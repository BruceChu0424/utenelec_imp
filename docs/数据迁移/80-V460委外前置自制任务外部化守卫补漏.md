# 80 - V460 委外前置自制任务外部化守卫补漏

## 一、背景

V458 真实岗位 UAT 首轮暴露一组「focused 单测不落库」盲区 bug，本迁移收口其中的
schema 侧两处；同批源码修复见 §三。

1. V458 给 `preplan_supply_actions` 新增外部单据类型 `SUBCONTRACT_MAKE_TASK`
   （指向原分析内 `SUBCONTRACT_MAKE` 前置自制任务行），但只重建了自己的
   `preplan_supply_action_external_chk`，**漏改了 V250 三道守卫**：
   - `preplan_supply_action_route_external_v250_chk`（route×type 组合 CHECK）
   - `fn_guard_preplan_supply_action_history` 的外部化握手白名单
   - `fn_guard_preplan_supply_allocation_history` 的外部化 CASE

   真库上「物料分析 → 有子层委外件 → 采用委外并确定」在
   `createSubcontractMakeTask → markCreated` 时被触发器拒绝：
   `preplan action externalization handshake is invalid`（23514）。

2. 同批发现的 `production_material_analysis_item_source_type_chk` 丢失
   `SUBCONTRACT_PREPARATION` 问题由 **[迁移 81 / V461]
   (81-V461恢复委外备料来源类型.md)** 单独收口（V460 已应用，
   两个缺陷分开落迁移保持各自幂等）。

## 二、变更

- 组合 CHECK 与握手白名单放行 `(route='SUBCONTRACT',
  external_document_type='SUBCONTRACT_MAKE_TASK')`；
- allocation 外部化 CASE 的 SUBCONTRACT 分支扩展：`SUBCONTRACT_MAKE_TASK` 要求
  allocation 指向**同分析内真实 `SUBCONTRACT_MAKE` 行**（与 MAKE 分支对
  `MAKE_COMPONENT` 的要求同构），`SUBCONTRACT_APPLICATION` 原语义不变；
- 其余守卫（身份不可变、append-only、取消/状态回退）语义不变；
- 不加表、不改表结构——**无表计数变化**，reset 仅目录版本对加 `(460, 422)`
  （V461 后为 `(461, 423)`）。

## 三、同批源码修复（无 schema 变更，随本批提交）

1. `SubcontractMakeTaskService.createApplicationBatch`：满批自动/手动分批通知
   复用任务 action 插 allocation，撞 `(action_id, analysis_material_id)` 唯一键
   ——改为每批建立独立 SUBCONTRACT action（predecessor=任务 action，锚申请行，
   CREATED+external 直接 INSERT 不经 UPDATE 握手）。
2. `PreplanAnalysisStockPegService`：`SUBCONTRACT_MAKE` 产出入仓被
   PREPLAN_ANALYSIS 通用预留与 SUBCONTRACT_PREPARE_TASK 任务预留**双重扣住**，
   出仓时「可动用 0」——把 SUBCONTRACT_MAKE 加入 V447 既有排除清单。
3. `SubcontractMaterialPlanService` 计划行 INSERT：VALUES 占位 22 个而 Java 传
   参 21 个且字面量错位（V447 时代遗留，mock 测试不校验占位数）——对齐 21 位。
