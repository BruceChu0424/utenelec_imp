## 二、范围与依据

### 2.1 本次审阅范围

- 生产边界：历史数据、来源系统、附件/证据、税务账、管理会计维度和终态更正。

### 2.2 控制原则

1. 固定资产、长期待摊、无形资产和供应商预付款按经济实质分开，不能因“先付款”混为待摊；
2. 达到预定可使用状态、受益期、残值、寿命和企业会计政策由财务负责人批准；
3. `CORPORATE` 与 `TAX` 账分开；税收优惠不能覆盖账面折旧政策；
4. 已过账事实不删除、不原地重建，错误通过可追溯反向事实纠正；
5. 制单、复核、过账和期间管理分权，且服务端执行权限和本人回避；
6. 任何生产结论必须区分“代码存在”“自动化通过”“真实 PostgreSQL 通过”“企业 UAT 签字”。

## 三、已交付能力

### 3.1 数据和审计骨架

- 类别、固定资产账簿、待摊计划版本/计划行、审批步骤、业务事件、会计期间、过账批次和批次明细；
- 原型主档追加类别、关键日期、来源行、科目快照、归属、责任、状态和乐观版本；
- 来源类型、来源单号与来源行规范化唯一性，避免同一来源行重复建固定资产或待摊；
- 审批步骤和业务事件只追加；已过账批次、日志和总账凭证保留原记录；
- 核心权限按查看、编辑、审批、过账、处置和期间管理拆分，并由服务端再次校验；本人审批/
  本人过账受限。独立导出仍需结合真实导出端点单独验收，不能仅凭权限代码宣称交付；
- 旧删除重建式计提入口被关闭，正式月度运行使用独立批次。

以上是“安全骨架已建立”的结论，不代表下文缺口已经实现。

### 3.2 制单与查询

- 资产/待摊类别和政策维护；
- 草稿创建、修改、带版本删除、提交、他人审批与驳回；
- 固定资产/待摊分页、筛选、详情、账簿/计划、审批、事件和凭证查询；
- 金额以 decimal 字符串输出，减少 Flutter `double` 精度风险；
- 工作台分别返回政策阻断和运行门禁阻断。

### 3.3 月度折旧与摊销

- `CORPORATE` 月度折旧/摊销预览和逐项输入快照；
- 连续期间、开放期间、输入指纹、唯一有效正常批次和并发锁；
- 制单、非本人审批、非本人最终过账；
- 正常批次、逐项日志和借贷平衡总账凭证同事务写入；
- 正常月度批次反冲：生成引用原批次的反向批次、反向日志和反向凭证，保留原历史；
- 折旧/摊销批次与子账合计对账后关账，受控原因重开。

“正常月度批次反冲”只覆盖月度折旧/摊销，不能用于反冲资本化、处置或终止业务事件。

### 3.4 Flutter 工作台

- 固定资产、长期待摊和月结三个工作区；
- 360/720/1280 等宽度的自适应表格/卡片和可滚动表单；
- 独立 loading/error/empty/retry，局部失败不绑死全部区域；
- 主档和月度批次动作都按权限与服务端 `allowedActions` 的交集控制；兼具权限的制单人不会
  看到服务端已因本人回避而禁止的审批/最终过账动作；
- `postedWorkflowsEnabled=false` 时展示“资产核心落账安全门禁已关闭”，并说明政策配置不能解除；
- 不提供虚假的附件上传、TAX 过账或总账深链。

## 四、生产安全门禁

### 4.1 配置契约

```yaml
uten:
  finance:
    asset:
      posted-workflows-enabled: ${UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED:false}
```

默认值为 `false`，生产、测试和开发环境在没有显式审批的情况下都应保持该值。门禁关闭时：

| 动作 | 结果 |
|---|---|
| 类别/政策、草稿 CRUD、提交、审批/驳回、查询 | 可继续，用于初始化与验证 |
| 固定资产/待摊激活 | 服务端拒绝，UI 不提供 |
| 固定资产处置申请/批准 | 服务端拒绝，UI 不提供 |
| 待摊提前终止申请/批准 | 服务端拒绝，UI 不提供 |
| 已存在处置/终止待审批记录的驳回 | 允许符合权限和本人回避的人员安全退回 |
| 月度折旧/摊销正常运行及正常批次反冲 | 能力已交付；仍受期间、权限、连续性和数据前置条件控制 |

### 4.2 为什么不能直接启用

激活、处置和终止会同时改变会计凭证、主档状态、账簿/计划、事件链和后续期间计算。当前没有专用
业务事件反冲来原子地恢复这些事实。仅把凭证反向，或仅把状态改回去，都会造成子账、总账和审计
链不一致。因此修改环境变量不是“开启功能”，而是绕过已知风险控制。

- 在门禁关闭的非生产/UAT 环境配置类别、科目和职责分离；
- 创建无真实财务影响的测试草稿，验证提交、他人审批/驳回、查询和权限；
- 使用隔离测试数据验证月度折旧/摊销及正常批次反冲；
- 建设 B01–B15，持续追加迁移和自动化。

不得在真实业务中激活资产/待摊、批准处置或终止，也不得通过数据库直改状态绕过门禁。

### 7.2 Flyway 与回滚

- 已应用的 V123、V140 不可修改；V183 一旦在任何环境应用，也必须冻结本次已验证字节，
  不可用 repair 掩盖校验和漂移；
- 结构修正使用后续版本迁移；
- 已过账业务事实不通过删除回滚，只能使用经过审批的业务反向事实；
- 发生发布异常时先恢复 `UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED=false` 并停止新落账，
  再按凭证、批次、事件和状态逐项评估；不能直接批量删表或删凭证。

## 八、从 NO-GO 改判为 GO 的条件

只有同时满足以下条件才可召开生产放行评审：

1. B01–B03 全部完成并通过正常、驳回、反冲、重复请求、并发和故障回滚；
2. B04–B15 按企业上线范围完成，任何排除项有财务、审计、技术共同签字；
3. 最终代码的真实 PostgreSQL、后端、Flutter、对账、UAT、备份恢复和回滚证据齐全；
4. 权限按个人分配，制单、复核、过账、处置和期间管理不存在同人越权；
5. 开关启用有变更单、审批人、时间窗、监控、回退阈值和演练记录；
6. 启用后先小范围试运行，首个期间逐项对账为零再扩大范围。

在上述条件满足前，配置必须保持：

```text
UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED=false
```
