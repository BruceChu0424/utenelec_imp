# 2026-10-20 基础资料与个人关联列核验

本记录覆盖本次基础资料问题的源码、组件回归和隔离数据库验证。代码验证不等于已安装客户端或线上数据库完成更新。

## 已核对的既有修复

- 模具列表、详情、编辑及导出使用相同的 `qty`（模数）、`tqty`（套数）、`place`（存放位置）、`manufacturer`（制造商）字段。`qty` 保持 `1+1` 等字符串；套数保持原数值，不由其它字段推算。
- 制造年月统一使用 `mstatus` 与 `UtenMonthField`；既有历史年月、旧 `mfgMonth` 草稿兼容保留，非法月份不能滚到另一月份。
- 货品资料已有默认的“模具编号”和“模具名称”列，服务端遵循既有 UUID 优先、明确旧系统主键兼容的关系解析。此次补回归确认，不重复制造另一套名称关联。
- 货品选择器的名称、系列、规格、主颜色和单位表头使用服务端筛选；候选值来自独立 `facet-values` 分页查询，并保留分类/组件范围，不能拿当前一页的颜色冒充全部匹配项。

## 本次修复

- 制造商改为可自由录入的历史建议输入框。空输入时显示已保存的制造商，输入后按精确、包含、相似程度及使用次数排序；建议请求防抖，旧结果不会覆盖新输入，加载失败仍能录入。
- 模具编辑曾遗漏未映射到部门/员工 UUID 的历史 `place`、`keeper` 文本。现在编辑时显示并提交这些值；后端区分字段缺省和显式清空，保存其它字段不会抹掉历史位置或保管人。
- 举一反三复查发现仓库详情有“备注”，新建/编辑却没有该字段，后端整表更新会将旧备注清空。现已补齐备注录入和回显；后端缺省保留旧值，显式 `null` 清空，并覆盖新建后详情读回。
- 收付款类别继续保留六个财务大类、系统科目保护、只停用不删除和部分更新语义。右侧标题复用 `MasterDetailCard` 且只展示摘要；新增子类、编辑、启停收敛到左树同行图标及右键菜单，两处调用同一实时权限/对象保护方法。搜索区与摘要间距对齐分类资料规范，专用财务字段弹窗改用共享 `UtenFormGrid`，窄屏大字可操作。

## 个人关联列

在货品表格“+ → 新建一列 → 关联资料”中，可以选择模具名称、编号、模数、套数、制造商、存放位置或制造年月。

- 复用现有平台列定义、个人表头偏好、加载和导出流程。`RELATED` 定义属于创建它的账号；其它账号看不到该个人定义，自己的表头操作不会改动全员表头。
- 关联内容由服务端白名单注册。源货品遵循既有查看范围，目标模具必须具有 `mould:view`；读取、恢复及导出均重新检查权限。前端失去目标权限后不继续展示缓存值；即使本地权限尚未刷新，服务器返回 401/403 也会立即清除旧投影并关闭编辑。
- 个人投影与标准列使用同一关系口径：优先 `goods.mould_id → moulds.id`；仅 UUID 缺失时按 `goods.mould_legacy_id → moulds.legacy_id` 唯一主键精确回落，一次批量查询，全部字段来自同一模具。显式 UUID 指向已删除模具时保持空，不跳到其它历史目标；没有关系时显示空，不依据相同名称、编号或备注猜测。
- 关联列只读，不持久化到业务记录、不修改货品/模具，不参与数值公式。模具编号等文本导出保留前导零。
- 现有全员“模具名称”标准列保留。其它领域关系不开放任意 SQL 或自定义匹配条件，后续须经过同样的明确关系及权限注册。
- 个人只读关联列独立使用 `goods:view` 与目标 `mould:view`，不要求货品编辑权限；普通文字、数字及共享计算列仍使用原页面编辑开关和 `goods:edit`。新增独立能力 `canDefineRelated`，不会借个人表头操作获得业务写权限。

## 历史制造商来源核验

本次主任务对旧库 `YTDQ_2023.dbo.B_Mould` 做了只读核对：1605 行、12 个字段（ID、MouldName、Number、QTY、MStatus、Remark、ParentID、Status、TQTY、Mnumber、Place、summary），没有制造商字段或可确定的制造商关系。Place 非空 1523 行，Remark 非空 458 行；包含“厂/公司/制造/模具”的备注是共模、改模、出售等信息，不能直接视为制造商。

因此不根据模具名称或备注编造历史制造商。新增字段在没有可靠来源时保持空，用户保存后进入历史候选。

补查 `Mnumber` 有93行非空，内容混有“已卖”“换后模”“新模”“博睿改”等，可能含改模方线索，但不构成可靠的制造商映射；原始文字继续保留，不自动提取为制造商。

## 本地实际 UAT 前的补查

进一步核对发现 c04 版本个人 RELATED 严格只读 UUID，而标准货品模具列还支持精确历史主键回落；旧资料因此可能出现标准名称有值、个人名称为空。已先用真实 PostgreSQL 复现失败，再将个人读取收敛到上述同一关系口径。回归包括 UUID 与 legacy 冲突时 UUID 优先、全部七个字段精确回落、无关系/未知主键不匹配、已删目标不回落、字段空值不跨模具拼接以及编号前导零保留。

组件测试和隔离 PostgreSQL 证据不替代实际 API/浏览器验收；实际本地 UAT 的覆盖与结果另存于 `.local-artifacts/platform-fluidity-audit/uat`。

## 实际滚动验收发现的选择注册生命周期

浏览器 final4 反复出现的 `owner == null` 已按正在使用的本机 Flutter 源码映射到 `RenderObject.getTransformTo`、`_SelectionContainerState` 和滚动选择委托的 `_flushAdditions/_compareScreenOrder`。原生选择容器在 State.dispose 注销，保留元素的渲染子树却可先脱离，后帧排序因此会读取失去 owner 的节点。组件回归显式保留500项滚动元素及其状态、脱离渲染子树、让兄弟滚动容器新增，并等待后帧排序，修复前得到相同位置的 `attached` 断言。此回归证明生命周期契约，不冒称同步 WidgetTester 完整复现浏览器 JS 事件竞态。

公用 `UtenSelectionLifecycleScope` 在 detach/deactivate 前从原父注册表注销，在重新附着且布局完成后一次恢复当前成员。注销同步释放原父的选择柄 LayerLink，避免保留已选文本重新附着时出现双 LeaderLayer；文本选择本身保留。正常新增仍交给 SDK 既有后帧合并，不额外改变复制拓扑，不加入新的行选择委托。接入标准页面内容容器、分类页、层级树及其懒建行、共用表格及其行、编辑网格正文，保持页面/表体独立局部选择区、输入原生选择与表头隔离。

表格换源清空文字选择另需等待 `endOfFrame` 之后的下一事件回合，先让多层原生滚动委托的注册微任务全部完成；否则清空空容器会在父委托 foreach 内同步移除自身。待清空期间原有版本及复制守卫继续拒绝旧内容；两个宿主销毁时取消定时回调并移除守卫。未修改 SDK、未捕获吞掉几何错误、未禁用用户复制。
