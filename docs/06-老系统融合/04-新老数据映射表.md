## 一、使用说明

- 每个新系统实体对应一张老表（或一段说明）
- 字段级映射记录"新字段 → 老字段"的转换规则
- 类型差异、枚举差异、编码差异必须显式记录
- 双写代码实现时，**严格按本表**，不在代码里隐式处理

## 三、字段级映射模板

> 每个实体填一张表。下面以 Employee 为例（待填）。

### Employee 字段映射

| 新字段 | 类型 | 老字段 | 老类型 | 转换规则 | 备注 |
|---|---|---|---|---|---|
| id | UUID | ⏳ | ⏳ | 新系统生成，老系统无对应 | — |
| code | String | ⏳ emp_no | VARCHAR | 直接映射 | 员工工号 |
| fullName | String | ⏳ name | VARCHAR | 直接映射 | — |
| gender | enum | ⏳ gender | CHAR(1) | `'M'→male, 'F'→female` | 枚举差异 |
| phone | String | ⏳ mobile | VARCHAR | 直接映射 | — |
| email | String | ⏳ 无 | — | 不双写 | 老系统无此字段 |
| departmentId | UUID | ⏳ dept_id | INT | 查部门映射表 | 见 Department 映射 |
| hireDate | DateTime(UTC) | ⏳ hire_date | DATETIME | 本地时区 → UTC | 时区差异 |
| status | enum | ⏳ status | TINYINT | `1→active, 2→inactive, 3→deleted` | 枚举差异 |
| createdAt | DateTime | ⏳ 无 | — | 不双写 | 老系统无 |
| ⏳ 无 | — | create_time | DATETIME | 不迁移 | 老系统独有，新系统用 createdAt |

## 五、ID 映射策略

新老系统的主键不一样（新系统用 UUID，老系统可能是自增 INT），需要一张**映射表**：

| 新 ID | 老 ID | 实体类型 | 备注 |
|---|---|---|---|
| ⏳ | ⏳ | Employee | 每条员工记录一行 |
| ⏳ | ⏳ | Department | 每个部门一行 |

实现方式（后端定）：
- 方案 1：新库内每张表保留一个 `legacy_id` 字段
- 方案 2：单独建一张 `legacy_id_mapping` 表
