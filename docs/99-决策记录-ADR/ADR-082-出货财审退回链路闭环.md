# ADR-082 出货财审退回链路闭环（撤回退回 + 原样重提 + 通知兜底）

- 状态：已接受（2026-09-14，V578）
- 关联：[ADR 客户零星发货与出货财务审核](../03-页面/客户零星发货与出货财务审核.md)、迁移 [170-V578](../数据迁移/170-V578出货财审撤回退回.md)

## 背景与问题

两审门禁（销售确认 → 财务放行 → 仓库作业）的「财务退回」支路在真实使用中出现两侧失联：

1. 财务「待审核」列表与徽章**排除** `finance_rejected=true` 的单据（设计使然，防混入待办计数），且没有「撤销退回」功能；
2. 销售侧「确认并提交财务」按钮在 `financeRejected` 时被隐藏，唯一回路是「编辑→保存」（保存自动清退回标记并重新通知财务）；
3. 退回通知要求归属人同时持有 `sales_shipment:view + sales_shipment:edit`，否则**静默不投递**；归属人为空的「公共单」同样无人收到。

三层叠加：财务以为单子消失、销售不知道被退回也找不到再提交入口、订单可发量又被退回草稿占住——等价于流程卡死。

## 决策

不重构状态机（后端回路本就完整），补齐三个出口：

1. **财务侧「撤回退回」**：新端点 `POST /sales/shipments/{id}/finance-reject-reverse`，清退回标记、追加 `REJECT_REVOKED` 审计事件、办结销售侧退回通知、单据恢复待财务审核（销售确认事实保留）。适用于退回原因与出货内容无关（如客户货款分类未维护、误退）的场景。
2. **销售侧「原样重新提交」**：`confirmSales` 放开 `financeRejected` 分支——修订号 +1 形成新一轮提交事实后重新进入财务队列；财务若坚持要求改单可再次退回。改单路径（编辑→保存→自动重提）保持不变。
3. **通知兜底**：退回通知投递门槛从 view+edit 放宽为 view；归属人不可达时回退投递给制单人。

配套可见性：出货列表新增 `financeRejected` 查询参数；财务工作台加「已退回」分段（红底「已退回销售」状态列）；销售出货详情在被退回状态显示「重新提交财务审核」按钮与双路径指引横幅。

## 权限与审计

- 撤回退回复用 `finance_shipment_audit`，零新权限码；
- `sales_shipment_finance_release_events` 的 CHECK 扩展 `REJECT_REVOKED`（V578），审计流完整可追溯；
- 不动两审门禁本身：`assertFinanceAudited`、认领租约、内容哈希校验全部保持。

## 后果

- 财务误退可自助恢复，不再需要销售「假改单」配合；
- 退回通知覆盖率从「归属人有 view+edit」提升到「归属人或制单人有 view」；
- 销售可原样重提意味着可能出现「退回↔重提」循环——由人工流程自行收敛，每次循环都有修订号与审计事件，无数据风险。
