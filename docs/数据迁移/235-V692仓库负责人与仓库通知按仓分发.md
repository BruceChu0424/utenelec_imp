# V692 仓库负责人与仓库类通知按仓分发（ADR-115）

## 背景

2026-09-24 用户反馈：多个仓库由不同人员负责，但仓库类通知（领料待出库、IQC 待入库、成品入库待审、销售待拣货、委外出仓、预计到货等）一律发给仓库部门里持对应权限的所有人；成品仓只关心产成品出入库，其它仓涉及领料、委外、采购、产成品，没有快速找到自己仓库单据的方法。此前平台没有「员工 × 仓库」的负责关系，单据所在仓只写进通知正文。

## 结构

- 新表 `warehouse_keepers(warehouse_id, employee_id, created_at, created_by)`，主键 `(warehouse_id, employee_id)`，`employee_id` 另建索引。负责人指向员工（与 `moulds.keeper_id` 同口径），账号停用或重建不丢负责关系。登记在主仓（有下级的仓）上 = 负责它下面全部子仓。
- `fn_warehouse_scope_ids(uuid[])`：给定仓库 + 全部未软删后代，与 `WarehouseScopeService.scopeOf` 同口径，给列表 SQL 做「指定仓库」筛选。
- `fn_warehouse_keeper_user_ids(uuid[])`：这些仓库（含各级上级仓）登记的负责人中，员工在职（未删除、非离职）且账号启用的 `users.id`。空数组 = 未指定有效负责人。
- `fn_user_warehouse_scope_ids(uuid)`：账号负责的仓库集合（「我的仓库」）= 自己是有效负责人的仓 + 还没有任何有效负责人的仓。

## 登记

- 审计三清单：`FULL / data_change`，归 master 组（`AuditTriggerCoverageMigrationContractTest`）。
- 清库策略：`PRESERVE`（仓库附属设置，随仓库/员工主档保留），ops 脚本与 `business_data_reset()` 孪生函数同时登记，孪生函数沿用 V686 的锚点补丁法，锚点缺失即失败。
- 主档引用目录：`warehouse_keepers.warehouse_id` 豁免为 `OWN_CONFIG`（删仓库后负责关系自然失效，不算「还在用」）。
- 迁移头 V692 / 621 张：README 头行、ops 白名单 `(692, 621)` 与异常文案、两个清库契约测试同步。

## 兼容与数据

- 只建表与函数，不回填、不改任何已有数据；已应用迁移不改字节。
- 没有登记任何负责人时，通知分发与所有列表的行为与 V691 完全一致（「我的仓库」等于全部仓库）。
- 旧应用连接 V692 库不受影响（新表只被新代码读写）。

## 验证

2026-09-24 云端会话：用项目自带 Flyway 11.7.2 在本机 PostgreSQL 16.13 空库上从 V1 迁到 V691（620 个，约 12 秒），再单独执行 V692 成功；在同库事务内造 5 个仓（主仓下挂成品/五金/塑胶，另一独立仓）与 5 个员工账号核对：

- 无负责人时任何账号范围 = 5 个仓，任何仓的有效负责人为空；
- 成品仓 → 员工 1、五金仓 → 员工 2 + 离职员工 5、主仓 → 主管员工 3 后：成品仓负责人 = {1, 3}，五金仓 = {2, 3}（离职员工排除），独立仓为空；员工 1 的范围 = 成品仓 + 独立仓，主管 = 全部，普通仓员 = 独立仓；员工 1 账号停用后成品仓负责人只剩 3；
- 审计触发器 2 个已挂，`business_data_reset()` 定义含 `('warehouse_keepers', 'PRESERVE')`。

真库全链与 Testcontainers 用例以 GitHub CI 为准。
