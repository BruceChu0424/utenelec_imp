## 一、定位

对标老系统「即时库存」窗口的**看盘视角**：按货品大类浏览当前库存，按仓库维度切换。
分类入口是**常驻左树 + 右侧库存表**（2026-09-26 起），复用货品资料的 `UtenCategoryTreeView`
与 `UtenSplitView`。任意层级都可点击，点击父类=后端按子树汇总（`categoryId` 递归 CTE），
切换分类后左树保持可见。单个包装根逐层提升，树使用无缩进层级色与选中高亮；「未分类」默认收起。
树由 `/tree?withGoodsCounts=true` 提供**子树货品数**（节点尾部显示），零货品分类整支不显示
（后端未给计数时不隐藏）。左侧统一搜索同时定位分类和货品，具体行为见「功能点」。
右侧 `UtenFilterToolbar` 显示当前分类、仓库字段、库存范围开关与结果数，不再重复放分类选择字段。
表格展示库存数量 /
库存重量 / 待检量 / 合格待入库 / 多排数量；仓库面板「全部」表示参与核算仓库聚合，
选**主仓库**表示该主仓子树聚合（两者在全部仓都挂主仓下时等价，但语义分开保留）。

与「库存查询（余额）」页的区别：余额页按仓+货+色逐行、供仓管对账；本页按货品+颜色聚合、
带分类筛选与多排视角，供 PMC/管理层看盘。

本页的聚合行只用于查询，点击后进入货品库存详情，不在跨仓聚合数量上修改库存。授权余额调整
只能从 [`/stock/balance` 的单一余额详情](库存列表页.md)发起，避免一次操作误改多个仓库维度。

## 二、入口与导航

- 进入：仓库管理 hub「即时库存」卡片。
- 离开：返回仓库管理 hub（`UtenBackButton` 指定 `/warehouse`）。

## 三、响应式布局

- **medium / expanded（宽度 ≥ 600dp）**：`UtenSplitView` 左侧常驻分类搜索与分类树，右侧为
  库存工具栏和表格。左栏初始宽度 300dp，使用组件统一的拖动、宽度约束、双击复位及键盘调整；
  本机宽度记忆 key 为 `stock.instantInventory`。右侧工具栏通过 `Wrap` 换行，支持拖窄右栏。
- **compact（宽度 < 600dp）**：页顶保留统一搜索；AppBar「分类树」按钮打开 `endDrawer`，
  抽屉复用同一分类面板。点分类或「全部分类」后关闭抽屉并重查；未进行搜索或选择时直接关闭
  抽屉不改筛选。库存表使用 `UtenContentContainer.wide`，页顶与抽屉搜索文本共享页面状态，
  抽屉关闭时尚未完成的搜索防抖由页面接续。
- 刷新库存列表时不以全屏加载页替换左树，保留用户已展开的分类路径。

**含内料仓开关（2026-09-16，V595 / ADR-089）**：内料仓是车间内部直送的料架，不是现实里的仓库，
默认**不计入**即时库存（`includeLineSide=false`）；要看车间料架上还有多少直送料时再打开。与「含不良品仓」
同样只在「全部 / 父仓聚合」口径下生效，显式选中某个内料仓仍按单仓精确显示。本开关仅页面会话内生效，不持久化。仓库筛选字段仍是
`UtenFilterPickerField`：圆角 `UtenRadius.control`（10）、高度按同一口径对齐搜索框（≈44）、
未筛选显占位「全部」、已筛选时边框与值文字走 primary。

**2026-09-28 ([ADR-131](../99-决策记录-ADR/ADR-131-车间整批领料与盘点计耗.md))**: 开关文字改为「含内料仓」, 旁边提示"内料仓是车间的料架, 默认不计入即时库存"。开启整批领料的车间, 内料仓里还会有仓库整袋发进来的颗粒等料, 同样默认不计入; 要看每种料在车间还有多少、估计还剩多少, 到[车间内料仓页](车间内料仓页.md)。库存详情里新增两种流水"内料仓盘点耗用""内料仓盘盈" (来自盘点, 没有单据可跳, 显示"盘点")。

## 四、数据链路

```
左侧分类树：/api/master/material-categories/tree?withGoodsCounts=true
      （节点尾部显子树货品数；零货品分类整支剪掉；单包装根提升）
统一搜索：本地 categoryHits 匹配分类名称/编号
      + GET /api/stock/instant-inventory/search-category-ids?keyword=&categoryRootIds=
        （货品 name/code/model/c_number 模糊；每批 1-32 个树根，只返回分类 id）
      → resolveHierarchySearch 合并命中分类与祖先链，展开左树并定位右表范围
右表：GET /api/stock/instant-inventory?categoryId=&warehouseId=&includeDefective=&includeLineSide=&keyword=&page=&size=&sort=&order=
      └ goods 货品驱动 LEFT JOIN stock_balances 聚合
        —— warehouseId=叶子仓：精确单仓；=主仓库：自身+全部子仓（服务端
           WarehouseScopeService 展开，is_accountable 与不良仓开关口径同「全部」）；
           null=全部（仅 is_accountable 仓库）
        —— 无余额货品也列出（库存 0），与老系统「分类下全是内容」一致
        × material_categories（所属类型）× colors / units（名称解析）
        × production_plan_items 可排余量预聚合（多排数量）
```

- 数量/重量：余额表当前值（历史=StockGoods 最新年 FactQTY/FactWeight 迁移，V80；
  增量=单据审核同事务联动，仓库单据含重量，盘点不联动重量）。
- **库位号列**：读货品主档 `goods.stock_place`，V451 起由实际入库学习回写保持最新
- **所属仓库列(2026-09-15, V587)**：读货品主档 `goods.owning_warehouse_id` 的仓库名，即「这批货平时归哪个仓管」。**与页面顶部的仓库筛选不是一回事**——那个筛的是本次要看哪个仓的库存, 这一列说的是货品归属, 所以列 key 用 `owningWarehouse` 而不是 `warehouse`。即时库存接口目前不下发该字段, 由页面按货品字典(`GoodsDictItem.owningWarehouseName`)批量回落取名, 打印预览走同一口径；要省掉这次字典请求, 正解是后端在库存行里直接带上这两个字段
- **「所属仓库」列表头筛选(2026-09-15)**：服务端过滤+服务端聚合 facet 桶（在未应用本筛选的同一口径上聚合，翻页不变；含「(空)」桶筛未登记），参数 owningWarehouse/owningWarehouseNull。
- **V590 单一事实源(2026-09-15)**：归属仓改由任何入库自动回写为最新入库仓(StockService 过账内核收口, 采购/委外/完工/调拨/退料/盘盈/手工单全路径)。本页与物料分析/货品资料展示的是同一个 `goods.owning_warehouse_id`, 入库一变各处打开即最新; 按仓真实库存仍以 stock_balances/本页为准。
  （到货登记 / IQC 合格品入库确认 / 产成品登记「记住库位」，见
  [迁移说明 66](../数据迁移/71-IQC入库库位学习.md)）；同一货品多仓不同库位时，
  待入库预填仍优先按仓库×货品偏好，主档值只是全局回退建议。
- **库存台账金额（V421 口径，页面已不展示）**：`stock_balances.amount_local` 按
  货品+颜色聚合，来自已审核库存流水及其红冲/调账事实。本页 2026-09-01 起不再渲染
  该列（持 `goods:cost:view` 亦然），排序候选同样移除；后端字段与导出能力保留。
- 排序白名单：qty / weight / moreQty / pendingQty / name（默认数量降序）；
  `costAmount` 排序键已不随本页发送。
- 仓库面板「全部」= 6 个真实仓（IsCal=0 参与核算，2026-07-28 修反转 bug）；幻影仓可单选。
- **主/子层级（V476）**：面板按「顶层仓在前、子仓缩进」一次铺开；主仓库（父仓）
  可选=子树聚合；叶子仓=精确单仓。同一面板的运营口径（单据登记）里父仓只钻层不可选
  ——本页是唯一允许父仓聚合的库存查询入口之一（余额/流水查询同口径）。
- 「含不良品仓」开关（V81 `warehouses.is_defective`，按名称识别）：默认开=老系统口径
  （不良仓计入全部）；关掉即剔除 成品不良品仓/原材料不良仓；**仓库=全部或主仓聚合时
  生效**，选定叶子仓时置灰。**选择按账号服务端持久化**（`user_preferences` key
  `stock.instantInventory`，模式同工作台布局：本地缓存即时渲染 + 登录后服务端同步 +
  防抖 800ms 推送，provider：`lib/features/stock/providers/instant_inventory_prefs_provider.dart`）。
- **加密 Excel 导出**：`UtenExportButton` → `POST /stock/reports/export`（report=`instant-inventory`，
  后端 `StockReportService.export` 独立分支复用同款查询全量分页拉取，父仓聚合口径同步生效）；
  五道防线齐备：`stock_report:export` 独立权限（V71 已种子）+ 限流拦截器 + Agile AES-256 密码
  + 10 万行上限 + 审计（`export_stock_report`）。导出再次检查 `goods:cost:view`；无权时
  **整列移除**库存台账金额，而不是输出空白表头——导出口径独立于页面展示。

## 六、功能点

1. **货品分类筛选**：medium / expanded 常驻左树，点击行选择分类并展开/收起该行；父类 = 子树汇总。
   compact 抽屉点击分类后关闭。节点尾部显子树货品数；零货品分类整支隐藏，计数缺失则保留。
   「全部分类」同时清除分类与搜索，保留仓库范围及表头筛选。进页默认全部分类并直接加载第一页。
   分类树加载失败在分类面板显示错误与重试，不阻塞默认库存列表。
2. **统一搜索定位**：300ms 防抖，回车可立即发起；分类名称/编号在本地匹配，货品名称/编号/型号/
   客户型号使用库存专属轻量端点定位，合并后显示命中分类、祖先路径和分类自身命中的整支子树。
   - 命中货品时优先定位所属分类，右表带同一 `keyword`；点击包含命中货品的祖先分类时保留关键词。
   - 只有分类命中时，右表显示该分类全部库存，不把分类名称误当作货品关键词。
   - 没有命中时，右表仍发送关键词查询，不能退回全库数据；左树显示无结果反馈。
   - 清空搜索恢复全树并清除货品关键词；当前分类保留，点「全部分类」才回到全部范围。
   - 输入新词或手动选分类立即使旧定位请求失效；库存列表也校验请求代际，避免慢响应覆盖新结果。
   - 搜索失败显示错误与「重试搜索」；导出/打印始终使用当前已应用的库存筛选与关键词。
3. **仓库筛选**（同款字段 + `showUtenWarehousePickerPanel` 查询口径）：面板顶部「全部」行
   （= 参与核算仓库聚合）+ 整棵层级缩进一次铺开，主仓一点即选 = 自身 + 全部子仓聚合，
   选中即关并重查。刷新按钮重载字典、分类树与当前查询并回第 1 页；搜索中刷新保留仍有效的
   当前分类，刷新期间的新输入或手动选择优先。从库存详情返回则重查原页。
4. 表头设置列多时显示明确的竖向滚动条，库存数量、库存重量、待检量、合格待入库、
   多排数量均可独立显示/隐藏；每个选项至少 44dp 高。
5. 数量/重量/多排数量/名称支持表头排序（回第 1 页）。
5a. **列头筛选**（2026-09-16 补齐）：归属仓库列之外，**颜色 / 系列 / 单位**三列也可从列头
   下拉筛选（桶由列表响应 facets 下发：颜色 UUID / 系列文本 / 单位 UUID；空值走「其他」桶），
   与搜索/分类/仓库筛选叠加生效、翻页保持。
6. 数字列格式化：最多 2 位小数去尾零；null 显示「—」。
7. **行点击 → 库存详情页**（`RouteName.stockItemDetail(goodsId)`，push 保活本页筛选）：
   单货品各仓余额 + 出入库流水。
8. 加密 Excel 导出（report=`instant-inventory`，导出参数与当前筛选/排序/不良仓开关/
   搜索关键词同步）。
9. **表格下方合计条**（2026-09-11，`MasterDataTableView.summaryBar` + `reportTotalsBar`）：
   合计库存重量 / 合计库存数量 / 合计待检量 / 合计合格待入库。
   - **值全部来自服务端**：本页服务端分页，前端对当前页求和会得出一个看着像总计、其实只
     覆盖一页的数，比不显示更糟。后端把列表查询本体（core）原样包成派生表再 `SUM`，
     派生表内不带 LIMIT/OFFSET，所以合计覆盖整个结果集。
   - **和表格显示的是同一批行**：分类子树、仓库范围（含父仓子树聚合 / 仅参与核算仓）、
     「含不良品仓」开关、关键字这四个筛选全在 core 里，改任何一个都同时改变列表与合计，
     不可能对不上——这是本页最容易踩的坑（一行 = 一个货品×颜色的跨仓聚合）。
   - **数量按单位分组**，多单位显示「12 个 · 3 箱」，绝不跨单位相加；重量只有一个口径不分组。
   - 刻意**没有合计**的两列：**多排数量**来自生产计划行的 qty/oqty/iqty，是计划行单位的量，
     与本行「单位」列（货品主档单位）不是同一口径，按单位分组会贴错标签；**库存台账金额**
     受 `goods:cost:view` 脱敏，合计一旦下发就绕过了列脱敏，等于把成本总额漏给没权限的人。
   - 响应形状：`/api/stock/instant-inventory` 返回 `TotaledPageResponse`
     = 原 `{items,page,size,total,totalPages}` + `totals`；老客户端读不到 `totals` 时
     整条合计条不渲染（不伪造 0）。

## 七、权限与边界

- 页面、聚合查询及库存搜索定位使用 `stock:view`；分类树仍由 `material_category:view` 控制树端点。
  加密导出另需 `stock_report:export`。
- `goods:cost:view` 不再改变本页任何可见内容（2026-09-01 起页面与预览打印均无
  库存台账金额列）；该权限仍决定导出 Excel 是否含金额列。**合计条同样不含金额**：
  金额列不声明合计，所以无权限者拿不到成本总额，有权限者也不会在页面上多出一个
  绕过列脱敏的口子。
- 本页不显示 `stock:balance:adjust` 操作，不能在聚合行直接修正库存。
- 数量、重量与金额是三类独立库存事实。数量调整不得伪造标准成本估算；只有携带金额的
  已审核库存流水才改变 `stock_balances.amount_local`。数量与金额不匹配时必须走库存
  价值核对。详细调整、审计和历史订单规则见
  [仓库盘点修正与历史单据处理](../数据迁移/50-仓库盘点修正与历史单据处理.md)。
