# 06 - 货品资料分类树 · 老库溯源

> 本档记录"基础资料 → 货品资料"分类树在**老库 `YTDQ_2023`** 中的存储结构、字段映射、数据质量风险。
> 新库表设计与迁移代码见后续 ADR / `server/legacy_migration/`。
> **溯源时间**：2026-07-24 · **数据源**：老库已还原至 LocalDB（见 [01-YTDQ老库总览.md](01-YTDQ老库总览.md)）

---

## 一、结论（一句话）

**货品资料分类树 = 老库 `SystemItem` 表中 `ItemclassID = 1` 的那些节点**，靠 `ParentID` 自引用成树；货品主档 `B_Goods` 通过 `B_Goods.ParentID → SystemItem.ItemID` 把每条货品挂到分类树的某个叶子下。

> ⚠️ `SystemItem` 是一张**万能分类树表**，混存了多种基础分类，**迁移时必须用 `ItemclassID` 过滤**，否则会把部门/车间/模具系列等无关数据一起迁过来。

## 二、老库表结构

### 2.1 `SystemItem`（分类树主表，1067 行）

| 字段 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `ItemID` | int | **主键** | 被 `B_Goods.ParentID` 引用 |
| `ItemclassID` | int | **分类类型** | 见下表，决定是哪棵树 |
| `Number` | varchar | 分类编码 | 如 A / BCP / BC / BT / OEM；**有重复**（WJ/SJ 等多处复用） |
| `Name` | varchar | 中文名称 | 如 原材料 / 包装材料 / 标贴 |
| `ParentID` | int | 父节点 ItemID | 根节点 = 0；构成树 |
| `Level` | int | ❌ **不可靠** | 并非真实深度（Level=1 的节点大多有父），**迁移时丢弃，用 ParentID 递归重算真实 depth** |

### 2.2 `ItemclassID` 区分的各棵树（关键！）

| ItemclassID | 树的含义 | 根节点数 | 备注 |
|---|---|---|---|
| **1** | **货品资料分类**（本次目标） | 9 | 原材料/半成品/成品/轨道/辅料/广告展板/OEM×3 |
| 2 | 业务/外贸区域分组 | — | 外贸钟/外贸苏/南区/北区 |
| 3 | 按材质的另一套分类 | — | 五金类/塑胶原料/包装类/标贴类 |
| 5 | **部门** | — | 总经办/销售部/工程部…（对应新系统 Department） |
| 10 | 财务 | — | 现金/开户行 |
| 12 | 车间/工序 | — | 安装车间/注塑车间 |
| **18** | **模具系列分类**（65） | — | 下一步"模具资料"的来源 |

### 2.3 `B_Goods`（货品主档，35750 行）与分类的关联

- `B_Goods.ID`：3697~68242（大数），`ParentID`：2000~3500（小数）→ **`ParentID` 指向 `SystemItem.ItemID`，不是自引用**。
- 全部 34814 条有效货品都挂在 `ItemclassID = 1` 的分类叶子上。
- `B_Goods` 关键字段（迁移货品主档时用，本档备查）：`ANumber`(编号)、`Goods_Name`(名称)、`Standard`(规格)、`UnitID`(单位→B_Unit)、`MColorID`(颜色→B_Color)、`MouldID`(模具→B_Mould)、`Price`/`APrice`(单价)、`Status`(状态)。

## 四、数据质量风险（迁移必须处理）

| 风险 | 数量/说明 | 处理策略 |
|---|---|---|
| **孤儿节点**（父被删，连不到主树） | 15 个。父 ItemID 2339/2342/2343/2624/2636 已不存在，残留华泰F26/欧悦/五光十色/宝迪V6·Z6/东联系列等 | 迁移时挂到虚拟"未分类(legacy)"节点，或人工归位后迁移；**逐条记入校验清单** |
| `Level` 字段非真实深度 | 全表 | 迁移时丢弃，用 `ParentID` 递归重算 `depth` |
| `Number` 编码重复 | WJ（五金原料/五金件）、SJ（塑胶类/塑胶原料）、OEM（三类共用）、LVT/Boade 等 | 新库 `code` **不设全局唯一**，改用 `path` 唯一或 `(parent_id, code)` 唯一 |
| `SystemItem` 混存多类 | 7 种 ItemclassID | 迁移严格 `WHERE ItemclassID = 1`（货品）；模具=18；部门=5 |
| `B_Goods` 也可能指向已删分类 | 需校验 | 迁移货品主档时校验 `ParentID` 在新库的存在性，悬挂的归"未分类" |
| 文本 GBK 编码 | 老库 `Chinese_PRC_CI_AS`，varchar 按 GBK 存 | 读取/导出时转 UTF-8（已用 `iconv -f gbk -t utf-8`） |

## 五、字段映射初稿（SystemItem → 新库 material_category）

| 老库（SystemItem, ItemclassID=1） | 新库 material_category | 转换 |
|---|---|---|
| `ItemID` | `legacy_itemid` (int) | 保留，迁移校验/回溯用 |
| `Number` | `code` | 直接映射；不全局唯一 |
| `Name` | `name` | 直接映射 |
| `ParentID` (=0) | `parent_id = NULL` | 根节点父为空 |
| `ParentID` (>0) | `parent_id` | 映射到对应新库节点的 UUID（按 legacy_itemid 反查） |
| （递归重算） | `depth` | 根=0，子=父+1 |
| （触发器维护） | `path` | `父path ‖ code ‖ '/'`，参照 departments 触发器 |
| `ItemclassID`=1 | `kind = 'goods'` | 货品；模具=18→`kind='mould'`（后续） |
| （新增） | `sort_order` | 默认 0，按 Number/Name 排序 |
| （新增） | `is_active` / `is_deleted` | 默认启用、未删 |

## 七、迁移要点（给迁移代码的输入约束）

1. **只读 `SystemItem WHERE ItemclassID = 1`**，按 `ParentID` 递归构建树。
2. **先迁父、后迁子**（拓扑序），保证写子节点时父节点 UUID 已存在。
3. **重算 depth**，不信老库 `Level`。
4. **path 交给新库触发器**自动生成（同 departments），代码不手填。
5. **孤儿 15 个**：单独标记 `legacy_orphan = true` 或挂虚拟根，输出校验报告。
6. **保留 `legacy_itemid`**，便于迁移后双向核对与增量同步（老库以后还会加类别）。
