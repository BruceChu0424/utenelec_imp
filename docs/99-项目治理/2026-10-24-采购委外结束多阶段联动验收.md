# 采购委外取消/结束：多阶段与部门联动验收

日期：2026-10-24。规则入口：[ADR-193](../99-决策记录-ADR/ADR-193-采购委外提前结束与余量重建财审.md)。界面按 `frontend-design` 和 Uten 组件规范实现。

本轮扩大前一轮 14 个数据库场景，核对采购、委外、仓库、品质、财务及生产需求。以下矩阵区分尚未发生的履约与已经发生的实物事实；不通过删除质检、清零在外材料或修改原订货量伪造取消成功。

## 右下角入口与批量选择

- 采购、委外任务中心的表格多选不再依赖导出或生成订货单资格；右下悬浮区有明确的取消/结束入口。
- 按钮后面的 `(N)` 只计当前服务端核验可办理的整单数量。同一订单的多条货品行只计一次，不把行数当订单数。
- 未选择、只选择不可办理项或资格核验中，按钮灰色禁用。选择变化后防抖读取新资格，迟到回执及账号、服务器或权限变更不能覆盖当前选择。
- 混合选择时逐单说明不可办理原因，须确认仅提交可办理订单；不可办理项不会送审。每批最多 50 张，后台对最终提交集合执行全批预锁和原子提交。
- 选中一条货品行也会影响该整张订单；对话框展示完整明细和数量，明确整单影响，不悄悄取消同单其它明细。
- 375px 和大字号下优先保留首业务动作在初始可见行，避免“已选”胶囊挤掉取消按钮；其它页面的共享表格顺序保持原默认行为。

## 阶段矩阵

| 阶段或情况 | 取消/结束口径 | 必须核验的部门结果 |
|---|---|---|
| 草稿、原商业财审待审或退回且尚未生效 | 不得绕过原生命周期直接提前结束 | 原单、来源、财审及仓库零副作用；普通取消/反审继续遵守权限和认领 |
| 商业已批准，尚未收货或发料 | 可以申请直接结束或余量重建 | 财务批准前原单继续；批准后旧仓库预期关闭，来源精确释放或由新草稿承接 |
| 收货草稿尚未审核 | 先完成或删除该草稿 | 原草稿保留，阻挡目标指向准确收货单；处理完成后重新核对申请 |
| 退货草稿尚未审核 | 先完成或删除该草稿 | 不跳过真实退货，不提前释放不确定余量 |
| 品质尚未检验、部分检验 | 先完成品质和不合格实物处置 | 品质任务保留；有权限者可进入准确质检单，无权限者显示联系品质部 |
| 检验失败，未实物退回 | 先处理不合格实物退回 | 指向对应仓库品质结果，不把 FAIL 当已退或可重建数量 |
| 已实物退回，财务贷项仍在办理 | 按真实净实收核定余量 | 实物与贷项分开；结束不抹除原应付、贷项或责任，既有财务处置可继续 |
| 撤销 IQC 实退后重新实退 | 每轮独立保留事件，原命令重放保持幂等 | 不因重复事件键拒绝合法第二轮实退，不重复立账或发布同一命令 |
| 已合格，尚未入库 | 可结束剩余承诺，原实物继续入库 | 品质合格待入库卡保留，不因原订单结束而显示实物已取消 |
| 部分已入库且已有应付、核销付款 | 可以结束剩余承诺 | 原收货、库存、AP、付款、银行流水和 GL 保留，不自动核销欠款 |
| 委外 OPEN 计划，尚未领料 | 结束未来领料 | 原计划及预留按既有取消路径撤销，不制造发料或损耗 |
| 委外已提交领料草稿，仓库尚未发 | 先由业务人员撤回或完成真实发料 | 原仓库待发卡与库存占用在真实撤回后消除，不能只隐藏任务 |
| 委外部分或全部已发，没有回厂 | 可结束后续承诺 | 旧供应商处真实 WIP 保留；可继续真实退料及独立材料损耗处理，不虚转新厂 |
| 委外部分回厂，短交或等待下一批 | 品质判定完整后可以申请结束 | 办结旧短交案件和提醒，不伪造成接受损耗；合格暂挂实物由本次批准放行 |
| 委外已有独立接受的成品损耗 | 原实收加结清损耗保持不变 | 不重开需求；已计入财务结束基数的关联损耗不得直接红冲 |
| 委外独立材料损耗或材料退回 | 原真实材料责任继续办理 | 区分成品履约结清与组件材料事实，独立材料损耗仍可按原守卫审核及红冲 |
| 生产尚在 WAITING | 结束旧未来供给，不取消真实需求 | 需求数量、行数和等待状态保持，新订单须重新备齐真实物料，不能冒用旧厂 WIP |
| 现代物料分析与旧计划先行供给 | 遵守各自实际供给合同 | 现代 preplan 不另造旧 generic peg；旧计划先行 transfer 则精确释放，不双算需求 |
| 财审结束申请期间发生新收货、质检或实退变化 | 拒绝旧指纹，重新核对 | 不沿用旧余量批准；财务退回后原部门可继续办理 |
| 批量中存在过期或无权项 | 最终提交集合整批回滚 | 无半批 case、事件、来源释放或新草稿；不得泄露无权行的商业快照 |
| 同时批准、驳回、收货或重复点击 | 只允许一个一致结果提交 | case、版本、认领和有序事务锁共同防重复、新旧容量双占及重复新单 |
| 结束已批准后旧页面继续操作 | 拦截改变已核定实收的命令 | API 和数据库均保护终态；新到货、新退货或原收退红冲不能悄悄改变来源基数 |

## 本轮确认修复

1. 任务中心的选择及悬浮组曾依赖导出或下单入口，委外进行中缺少该组；新增明确入口、资格数量和批量流程。
2. 375px 下“已选”胶囊可能把长业务按钮挤到初始视口之外；仅这三处任务表启用首动作优先，并验证真实边界和可点击性。
3. 财审列表真实返回曾只在本人作出决定后刷新；改为返回服务端重核并清除过期选择。
4. 工作台打开的结束对话框需在账号、服务器或权限变化后清除旧私有预览，不能只拦截提交。
5. IQC 实退撤销后再实退，旧发布键未包含版本而与新 payload 冲突；事件键纳入实际版本，原命令重放仍不重复。
6. 已接受的委外成品损耗在结束后仍能被红冲，可能抹去冻结的结清数量；前向 V924 同时保护 API、资格投影、案件 hook 和数据库，独立材料损耗继续可办。
