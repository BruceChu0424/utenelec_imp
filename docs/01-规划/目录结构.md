# 目录结构

> 本档定义 Uten IMP 项目的完整目录结构、每一层每一文件夹的职责。
> 任何新增文件必须放到正确的位置，禁止随意创建顶层目录。

---

## 一、顶层结构

```
uten_imp/
├─ README.md                       项目总览，第一链指向 00-项目准则
├─ pubspec.yaml                    Flutter 项目配置 + 依赖
├─ analysis_options.yaml           lint 规则（very_good_analysis）
├─ .gitignore
├─ .metadata                       Flutter 自动生成
├─ docs/                           ★ 所有设计文档
├─ lib/                            ★ Flutter 前端源代码
├─ server/                         ★ Spring Boot 后端（Java 21，独立 Maven 工程，见 ADR-006）
│  ├─ pom.xml · docker-compose.yml · .env.example
│  ├─ src/main/java/com/uten/imp/  config/ security/ common/ features/(auth|org|rbac) audit/
│  └─ src/main/resources/db/migration/  Flyway 迁移（建表 + 组织树/RBAC/admin 种子）
├─ test/                           单元测试 + Widget 测试
├─ integration_test/               集成测试
└─ assets/                         字体、图标、图片、lottie
```

## 四、Feature 内部结构（统一约定）

每个 `features/<name>/` 内部都遵循同样的子目录：

```
features/<name>/
├─ pages/                          页面（带 Scaffold 的顶层 Widget）
│  └─ <name>_page.dart
├─ widgets/                        该 feature 私有的子组件（不进 Uten 组件库）
├─ providers/                      该 feature 的 Riverpod Provider
├─ repositories/                   数据访问（前端 Mock / 后端 dio）
├─ models/                         该 feature 的数据模型
└─ <name>.dart                     barrel file（可选）
```

**何时建子目录**：只有该 feature 真的需要时才建，不预创建空目录。比如一个只有 1 个页面的 feature，就只建 `pages/` 即可。

## 五、命名细节

详见 [../00-项目准则/01-命名规范.md](../00-项目准则/01-命名规范.md)。这里补充几个易混淆点：

- 组件文件名：`uten_<name>.dart`（如 `uten_button.dart`）
- 页面文件名：`<feature>_page.dart`（如 `login_page.dart`）
- 私有子组件：`_<name>.dart`（如 `_stat_tile.dart`，仅 feature 内用）
- 测试文件：与源文件同路径 + `_test.dart` 后缀（如 `test/components/buttons/uten_button_test.dart`）

## 六、禁止事项

- ❌ 在 `core/` 里放业务逻辑
- ❌ 在 `components/` 里放业务相关组件（业务相关放 feature 的 widgets/）
- ❌ 跨 feature 直接 import 对方的内部文件（必须通过 shared/）
- ❌ 在 `lib/` 根目录散落 .dart 文件（除 main.dart / app.dart）
- ❌ 随意新建顶层目录（任何新目录必须先更新本档）
- ❌ 在 features 里直接堆 Material 组件（必须用 components/）
