# ADR-076：生产成品品质检查单聚合层与送检登记撤回

- 日期：2026-09-10
- 状态：已接受；V547/V548 源码候选，本地 FullChain/契约/Widget 回归通过；公司服务器尚未升级
- 相关：ADR-054（FQC 数量守恒）、ADR-058（仓库送检登记与库位快照）、ADR-075（合格来源跟随实际入库仓）、V430、V469、V542、V547、V548
- 后置关系：本 ADR **不改变** ADR-054 §2.2/§2.3 的「一条报工明细一个待检事实、数量与决定只在 inspection」，也不改变 ADR-058 §2.5.4 的「FINISHED_IN 按登记批次继承仓库与库位」；只在其上增加一层展示/办理聚合，并兑现 ADR-058 §4.5 承诺的受控撤回

## 一、问题

用户口径：「登记成品」（产成品送检登记）要对照采购到货登记——逐行选实际成品仓、可批量填库位、带备注，
「批量送检」把同一成品仓的行合并成**一张品质检查单**由品质部按单处置。实现前的差距：

1. 单张登记页只有表头级仓库；V469 允许同一报工多个登记批次，但页面无法把不同行送到不同仓；
2. 品质待检队列一行一条 inspection（ADR-054 §2.2），仓库一次送 20 行品质就看到 20 行，没有「一次送检」的单据身份，
   批量审批也只能逐条勾；
3. V542 的登记备注只存不显示，品质看不到仓库写了什么；
4. ADR-058 §4.5 承诺的登记撤回从未实现：仓库选错仓只能等品质处理或红冲报工。

## 二、决策

### 2.1 检查单是聚合层，不是数量权威

```text
仓库登记命令（单张页每个仓一次 / 批量页一次）
  └─ 每个成品仓一个登记批次（V469：一批一仓）
       ├─ 逐行 FQC PENDING（V410/V430：数量、PASS/PARTIAL/FAIL、放行都在这里）
       └─ 一张品质检查单 production_fqc_inspection_sheets（V547）
            └─ sheet_items：一条 inspection 终身只属一张单，并锚定登记批次/登记行
```

- 检查单只有：单号（`FQC` + YYYYMMDD + 6 位日流水，V279 DocNumberService 口径）、仓库/收货人/备注快照、来源类型
  （单张 / 批量）、生成它的登记命令幂等键；**没有数量列**。
- 待检数量、决定、放行、恢复链、FINISHED_IN 全部仍按 inspection（ADR-054 §2.3）；检查单状态是投影：
  仍有 PENDING/PARTIAL 行 = ACTIVE，否则 CLOSED。
- 同一操作者、同一登记命令键、同一仓库只允许一张检查单（部分唯一索引）；登记命令幂等重放不再建单。
- 不回填历史：V547 前的 inspection 没有检查单，待检处置按「无检查单」逐条显示（`sheet=NONE`）。

### 2.2 行级成品仓与按仓拆批

- 单张登记页明细行增加「实际成品仓」列；工具区「默认成品仓」只落到未手工改过仓的行；逐行预填优先级：
  同货品同颜色最近一次**有效**登记仓（`lastWarehouseId`，已撤回不算）> 当前用户上次登记仓（last-warehouse）。
  预填一律黄框待核对。
- 提交按行仓分组，每个仓 `POST /arrival-registrations/{reportId}` 一次，幂等键 = 页面键 + `:` + 仓库 UUID；
  部分仓失败停在原页，已成功仓的行锁定只读，重试只补失败仓；每个批次按响应 registrationId 记忆库位。
- 批量登记页保留「同一报工单本批所选行必须同仓」（服务端合同一报工一仓一批次）；同仓的多张报工合并成一张检查单，
  不同仓分单。两页共用 `showUtenWarehousePickerPanel`、「统一设置成品仓(n)」「统一填写库位(n)」批量动作
  （计数订阅表格 controller）。

### 2.3 登记撤回（V548）

- 前提（服务端 + 数据库 BEFORE 守卫 + 提交前延迟守卫三重）：来源日报仍已审核未红冲；该批次每条 FQC 仍 PENDING、
  合格/不合格为 0，且无决定事件、放行命令、恢复授权。任一不满足 → 409，不做部分撤回。
- 事务：追加 `production_finished_arrival_registration_reversals`（原因 2–500 字、幂等键、请求哈希）→ 该批次登记行
  标记 `reversal_id` → 逐条 FQC 追加 `REGISTRATION_REVERSED` 取消事件（状态 CANCELLED）。登记头、登记行、
  inspection、检查单及其明细都保留为历史；指向该登记的库位偏好保留。
- 撤回后报工行重新出现在仓库待登记，可再次登记到任意仓：V430「报工行终身唯一」前向放宽为
  「同时只有一条有效登记行 / 一条未取消 inspection」（部分唯一索引）。
- 「未登记」谓词收口到视图 `v_production_report_items_pending_registration`：仓库待办、登记详情、库位建议、
  通知投递、链路健康、数据库登记行守卫统一引用，不再各自拼三个 NOT EXISTS。
- 端点 `POST /api/warehouse/production-finished-in/arrival-registrations/{registrationId}/reverse`，
  权限与登记相同（`stock_doc:view + stock_doc:approve` + `SUB_WH` 仓储对象范围）。

### 2.4 品质侧口径

- `InspectionView` 增加 sheetId/sheetNo/warehouseName/place/registrationRemark/receiverName（登记事实只读回看）。
- 待检处置「自制产成品」一行一张检查单（`GET /api/production/quality-inspections/sheets?status=ACTIVE`）+ 无检查单历史
  任务逐条；双击检查单进办理弹窗，逐条 PASS/FAIL 复用既有弹窗，「全部合格(n)」= 本单待检行原子 pass-all。
- 批量审批页按检查单分组（组头三态复选，镜像 IQC 收货单组）；独立 FQC 页与检测记录保持 inspection 粒度并加
  「检查单号」列。
- **角标口径改为待检处置队列行数**：`GET /count` = `COUNT(DISTINCT COALESCE(sheet_id, inspection.id))`
  （一张检查单计 1，无检查单历史任务逐条计 1），与 IQC 按收货单计数一致；Flutter provider 不变。

## 三、权限与边界

- 不新增权限码。检查单读取沿用 `production_quality_inspection:view`（品质池全量；非品质池按 inspection 的
  报工 maker 对象范围裁剪，整单无可见行返回 404）；撤回沿用登记权限。
- 检查单不参与库存、成本、完成率；不能作为放行或点收依据；FINISHED_IN 继续按登记批次仓/库位生成。
- 采购 IQC 收货单不受影响。

## 四、验收（本地已过）

- FullChain：(a) 同报工两行分别登记 A/B 仓 → 2 批次、2 张单、inspection 仓正确、PASS 后 FINISHED_IN 各自继承仓与库位、
  同键重放不建单；(b) 批量 3 张报工（2×A 共 5 行 + 1×B）→ 2 张单、A 单 5 行、重放不建单、单内一条 FAIL 不影响同单其它行、
  其余全合格后整单 CLOSED、来源报工红冲后 inspection CANCELLED 而检查单保留；(c) 登记 → 撤回 → 待办重现 → 改登另一仓
  → 新批次/新单，PASS 一行后再撤回 409，绕过服务直插撤回记录被数据库守卫拒绝。
- 服务单测：备注 trim/空归 NULL/501 字拒绝/不同备注不同哈希；撤回原因 trim/长度/哈希含登记身份。
- 迁移契约：V547/V548 静态契约；审计覆盖登记（547/547/548）；清空策略同步（ops 脚本 + 孪生函数补丁 + 契约测试计数）。
- Widget：单张页两行分别选仓 → 两次 POST（不同幂等键）并逐批记忆、部分仓失败停页重试只补失败仓、
  「统一填写库位(n)」计数即时刷新并应用、已登记批次撤回；批量页备注 trim 与统一填写库位；待检处置检查单行
  双击办理与全部合格。

公司服务器未升级、真实岗位 UAT 未做前，本决策与相关迁移保持 **NO-GO**。
