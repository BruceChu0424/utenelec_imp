# ADR-040：销售开单体验与财务审核中心（订货精简、地址簿学习、财务驳回、审核专用页）

- **状态**：已接受（源码候选；V300 已应用本地开发库，目标库迁移与岗位 UAT 未完成）
- **日期**：2026-08-18
- **影响**：销售（订货/出货开单）、财务（销售订单确认）、客户主档（地址簿）、计划部（进度可见性呈现）
- **依赖**：V294 财务确认闸门、ADR-027（审核组资格模型）、[SOP](../07-业务链路/01-销售订货到发货全链路-SOP.md)

## 一、背景

销售开单与财务确认链路存在四类体验/职责问题：

1. 新建销售订货单要求填写联系电话/收货地址，但这两个事实属于**发货环节**而非订货商业承诺，销售被迫提前填写或留空后再补，口径混乱；
2. 出货开单每次手填收货地址/电话，客户主档没有就永远空白，系统没有"记住上次填写"的学习能力；一个客户多个收货地址也无承载；
3. 发运策略可留空，空策略订单流入审核后才暴露歧义；单据号/制单时间等系统字段看起来可填，用户点击无反应误以为故障；
4. 财务确认页只有"确认"一个按钮、没有驳回，且点详情直接跳销售端订单详情——财务能看到改量/排产进度/取消订单/红冲等不属于自己职责的操作，也看不到决策所需的客户欠款。

## 二、决策

### 2.1 订货单精简：联系信息回归发货环节

- 新建/编辑销售订货单**不再采集**联系电话、收货地址或定金/预收；合同信息段只保留合同号与签约地点。
  老库 sales_orders.deposit 仅作历史只读快照，不能证明到账，新流程不读写。客户真实到账由财务登记
  CUSTOMER_PREPAYMENT，详见 [ADR-048](ADR-048-客户预收与销售订单资金事实分层.md)。
- 出货/其它出货单保留收货地址+联系电话，并在选客户（含从订货单引入回填客户）后自动带出。

### 2.2 客户收货地址簿（学习能力）

- 新表 `client_ship_addresses`（V300）：客户维度地址簿，`usage_count` + `last_used_at` 驱动"最近使用优先"默认带出；同客户规范化地址唯一（`md5(lower(btrim(address)))` 部分唯一索引，软删行不占位）。
- **学习钩子**：出货/其它出货保存的同事务 upsert 本次地址+电话——同地址已存在则次数+1、刷新使用时间；用户改过电话则写回该行（记住修改）；无记录则新建。学习失败（空/超长地址）静默跳过，绝不影响单据落库；插入用原生 `ON CONFLICT DO NOTHING` 保证并发重复保存不产生唯一冲突。
- **多地址弹窗**：出货编辑页收货地址字段内嵌地址簿入口，弹窗支持查看/点选/新增；**删除须独立权限点 `client_address:delete`**（默认授 DEPT_SALES + GM，超管恒有），软删保留审计事实。
- 地址簿为空的客户回退既有主档带出（收货地址→地址；电话→手机→备用电话），主档也没有则留空待手填——"没有就不加载"。
- 不回写客户主档：主档维护是 `client:edit` 职责，开单学习不越权改主档。

### 2.3 发运策略必选 + 系统字段标注

- 新单保存必须显式选择 `ALLOW_PARTIAL / REQUIRE_COMPLETE`（服务端 create 落点校验）；编辑保存与审核同口径拦截"未选/历史未指定"草稿（`CUSTOMER_CONFIRM` 历史值只读保留，不允许改回）。
- 报价转订货草稿由服务端直接落库，不在创建点卡策略；销售打开草稿编辑/审核时被同一规则拦截并引导补选。
- 所有"系统自动生成、不可填写"的字段统一在 label 后缀「（系统自动生成）」：单据号、制单员、制单时间（`utenMakerAuditCells` 共享组件，全部单据编辑页一次生效）、件数（自动汇总）。

### 2.4 财务审核中心：双决策 + 专用审核页

- 财务确认补充**驳回**决策（沿用 `sales_order_finance:confirm` 决策权限 + 财务部门树资格复核）：驳回必填原因、不改订单状态与库存预留、只记事实列（`finance_rejected` 族）并通知归属销售；确认自动清除驳回标记，形成"驳回→修正→确认"闭环。
- 列表页重设计为审批收件箱：待确认/已驳回分段 Tab、顶部摘要条、卡片带金额/客户应收余额/交货紧迫度/驳回原因；徽标只数未驳回可办件。
- 新增**财务审核专用详情页**（`/finance/sales-order-confirmations/:id`）：客户财务快照（应收余额/信用额度/铺底额/超信用告警 + 本单金额）、订单信息（币种加粗红色）、产品明细（保持全局 `MasterDataTableView`）、双决策底栏。财务不再进入销售端订单详情，不见销售运营按钮。
- 金额可见性沿用 V294 待确认列表口径：`sales_order_finance:view` 持有者可见订单原币金额（确认必须核对金额）；本视图不授予任何销售写操作。

### 2.5 排产进度的财务闸门呈现

- 销售订货单详情：财务确认通过前不显示「排产进度」入口（待财务审核阶段无排产事实，表头已有"待财务确认"行说明）。
- 订单进度看板：`OrderProgressRow` 下发 `financeConfirmed`；未确认订单卡片显示「等待财务审核」徽章、进度环归零、数量区替换为等待说明，点按提示"审核通过后显示排产进度"。
- 现货预留不受闸门影响（V294 既定口径：审核落点预留照旧），未确认订单的「去发货」保持可用。

### 2.6 审核引导文案

- 销售订货单点审核的确认弹窗明示后续流转：「审核通过后订单将生效并形成库存预留，随后自动转发财务审核；财务确认通过后计划部才可见并排产。」成功回执为「已审核，已转发财务审核」。

## 三、后果

- 正向：订货开单字段更少、职责更清；出货地址一次填写终身记忆且可多址管理；财务决策有完整风险视图与驳回回路；系统字段不再被误认为故障。
- 代价：客户联系事实新增一处存储（地址簿），与主档并存——主档仍是"客户档案"，地址簿是"开单学习"，两者语义不同不回填同步；历史已审订单的财务确认不受影响（V294 已回填）。
- 边界：`LEGACY_UNSPECIFIED` 策略仅可能存在于 V187 迁移的已审历史单（草稿不会产生该值），若异常出现草稿态该值，删除重建即可，不做自动改写。
- 验证：`flutter analyze` 0 issue；后端 test-compile 通过；通知 outbox/进度阶段/发运策略契约定向测试全绿。目标库迁移、真实岗位 UAT 未完成前生产 **NO-GO**。
