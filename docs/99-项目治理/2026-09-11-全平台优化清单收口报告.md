## 二、修掉的真实缺陷（不是重构，是线上会出事的）

1. **部分排产后整单从「待排产」消失**（用户首报）。`chain_status` 的派生规则散在 12 个写点，
   任何未完工计划量都把整行标成已排产；剩余未排量从未参与判定。收敛为一处共享 CASE
   「剩余未排优先」，V545 一次性回填，销售进度/单据大类/调度台三处同步显示「部分已排 x/y」。
2. **车间负责人开不了工**。V543 收回 `production_plan:view:all` 后，执行段写侧仍要求
   「能读计划制单人」，车间账号连自己车间的工单都无法开工/报工。写侧改为与读侧同口径的
   车间归属判定（主职 ∪ 兼职 ∪ 车间子树负责人 ∪ 段负责人本人），抽成
   `ProductionWorkshopMembership` 供执行段与日报守卫共用。
3. **生产链领料单写不进出库备注**。V164/V232 把 `remark` 列入「身份不可变」集合，
   出库备注（单张/批量）在生产链单据上一律 23514 拒绝。V550 前向替换函数移除该列，
   其余身份列原样锁死。
4. **批量出库对草稿领料单必然整批回滚**。生产链生成的领料单全是草稿，批量端点却只走
   「已审核单」内核。改为同事务内「审核即出库」，并按固定锁序一次性预锁整批
   （`FulfillmentMutationLocks` 同事务语义：首次 acquire 冻结集合，逐单首锁会让第二张单越界）。
5. **表头筛选值不随数据集失效**。行集/列集变化后旧筛选值仍在过滤，表现为「表头看着没筛选、
   表体却是空的」。组件层增加失效值剪除，并让无桶列退回纯标签（不再有点开只有「所有」的死箭头）。
6. **服务端分页表格的「合计」会说谎**。92 张表里 91 张服务端分页，客户端把当页一加就是错数。
   建立服务端合计机制（派生表复用同一 WHERE 含对象范围谓词、不带 LIMIT），前端只渲染不相加。
7. **徽章外层小于内层**。工作台「采购/委外」卡漏算「待退回供应商」、「钱流」卡漏算 IQC 驳回。
   收敛到 `todo_badge_registry` 唯一累加实现：入口 → 模块 → Tab 总数。
8. 其余：通知弹窗「稍后再看」并发竞态、访客接待卡不办结、报销自审收到无法操作的卡、
   信息变更撤销不撤 HR 卡、附件分类与上传耦合、`fn_business_attachment_reset_blockers`
   漏保护货品主档附件（V549）、待交货视图把草稿计入（V551）。

## 三、确立的平台口径（新增/修订的"铁律"）

- **计数两形态**（`docs/00-项目准则/14-徽章与计数口径.md`）：红徽章＝待办且逐级累加；
  中性 `(N)` ＝浏览型且永不累加。主档/报表/权限/审计入口恒不挂计数。
- **表格合计**（`docs/02-组件库/UtenTotalsSummaryBar.md`）：服务端分页必须用服务端合计；
  数量按单位、金额按币别分组；明确列出**拒绝求和**的列型（表头总额逐行重复、单价、
  按货品重复的快照、费率、无单位数量、脱敏成本）。
- **列表页布局**：`UtenListTwoPane` 全断点「筛选在上 / 表格在下」，左右分栏只留给分类树主档页；
  筛选区封顶 45% 且内部可滚，极矮视口整体可滚并保表格最小高度。
- **页面级层级筛选**：`UtenFilterPickerField` + 侧滑面板（分类树 / 仓库层级），
  表单内的一格仍用下拉——判定标准是角色不是控件。
- **附件**：分类是上传之后、文件旁边的**可选**标注（新增 `PUT /attachments/{id}/category`，
  授权与删除同一条对象策略）；预览能力矩阵单一真源，上传白名单 ⊇ 预览 ⊇ 服务端转换。
- **跨 feature 调用只经 `application.port`**（ADR-017）：本轮新增 `HrNoticePort`、
  `BusinessAttachmentResetPreparationPort.drainNextDeletion`，共享 SQL 口径放 `common/`。
- **返回键**：`backTo` 先 `pop`，栈空才 `?returnTo` / `defaultPath`；详情页「返回列表」按列表
  路由守卫显隐（财务审核员从任务中心进来不再被自己的按钮送去 /access-denied）。

### 7.2 表格交互（`UtenTableColumnKit` / `MasterDataTableView` / `UtenEditableGrid`）

- **列换位改「按下即拖」**：不再需要长按 500ms。横/竖两个 drag 识别器同挂，方向消歧交给竞技场——横拖换位、竖拖移除。代价明说：表头本身不再能横拖滚动表格（表体横拖与底部横滚条仍在）。
- **行首多选列横滚冻结**（`UtenFrozenLeadingColumn`）。踩到三个坑，都写进组件文档了：
  1. 未横滚时那份副本必须 `IgnorePointer`——48×行高的定位块即使内容为空也会吃掉首列点击（实测把 BOM 树展开箭头点不动）；
  2. **不能靠 setState 增删这份挂载**——滚动回调里重建整行会让 `ensureVisible` 之后的点击落空；
  3. `Transform.translate` 只搬绘制，**命中测试仍被父级 `Positioned` 的盒子挡住**——定位块必须是整行大小 + 内部 48 宽对齐，否则副本「画得出来点不动」（这正是用户反馈的「拖动后表头多选框失灵」）。
- **行内勾选格不自带底色**：自带会盖掉行底分隔线、且与行底色（斑马纹/选中深绿）对不上；只有浮上来的副本才带不透明底 + 右线 + 行底线。
- **表头最小可读宽**：量宽不再只看单元内容，所有列都按「标签（含必填 *）+ 内边距 + 筛选箭头 + 列头 ⓘ」抬一次地板——下达采购的「缺口」列不再一进页面就只剩一个图标。
- **`rowMenuExtraBuilder`**：给行右键菜单追加作用于当前选择集的条目；非空时纯勾选办理表也挂菜单。
