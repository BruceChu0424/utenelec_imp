# 仓库业务人员引用与选择器修复

本次修复基于生产 2.5.43 的 `bd7e8525be1ef52db2a6cfb10268fdbd8310844c`。仓管已具备实际到货登记资格，但收货人选择器使用员工档案列表，默认本人回显还逐个读取完整员工档案并忽略失败，因此没有 `employee:view` 的正常仓管会遇到 403。这不是缺少收货动作权限，也不通过追加人事权限解决。

## 唯一公共入口和保留的差异

`EmployeeReferenceRepository` 读取 `/org/employee-references`、`/by-ids` 和 `/departments`，服务端按业务目的核验原有动作资格。人员只返回标识、工号、姓名、部门、职位及原有两类状态；不读取员工详情、联系方式、证件、薪资或任职资料。默认候选、分页搜索与已存 UUID 的标签回显分别处理，不把 byIds 结果合并成候选目录。

`BusinessEmployeePicker` 复用 Uten 员工选择器和主题；业务侧栏仅显示工号、姓名、部门、职位，没有员工档案跳转。真正人事场景保留标准选择器。原状态标签不冒充操作资格：已有物理业务命令只要求该员工存在且未删除，不能擅自把账号停用、锁定、没有账号或非删除的离职身份排除在合法引用之外。服务端命令仍是最终权威；特定生产调用方原本明确的在职状态筛选通过 `statuses` 保留。

完整分页沿用 `loadCompletePagedSnapshot`，不会只展示首批或把异常分页当成功。身份、服务器、权限 ABA 变化沿用 `EmployeePickerAccess` 和 `AuthenticatedRequestScope`，过期结果不能回写。相同目的和相同人员的并发标签请求在当前读取边界内单飞，完成后不保留永久标签缓存。只读详情保留原单据姓名和 UUID，不为补显示索要写动作权限。错误显示原业务消息，没有全员工或完整人事接口兜底。

## Web 和现有 Flutter 桌面调用方

| 页面 | 目的 | 默认范围与回显 |
| --- | --- | --- |
| `inbound_arrival_registration_page.dart` | `WAREHOUSE_ARRIVAL_RECEIVER` | 默认本人；空搜索为仓储部子树；输入关键字按业务引用搜索；默认与草稿回显不再读员工档案 |
| `warehouse_subcontract_outbound_edit_page.dart` | `WAREHOUSE_SUBCONTRACT_OPERATOR` | 原经办人或本人；仓储部默认范围；原单据 UUID 和标签保留 |
| `warehouse_subcontract_outbound_batch_page.dart` | `WAREHOUSE_SUBCONTRACT_OPERATOR` | 各单经办人独立；并发相同标签只读一次；不阻塞出仓明细和原 UUID |
| `workshop_material_issue_page.dart` | `WORKSHOP_MATERIAL_ISSUER` | 直接发料按所选车间；改车间清除旧选择；原仓库任务围栏和真实发料命令保留 |

仓库调拨、盘点和产成品登记当前没有同类 HR 人员选择器调用，不虚列迁移。所有上述页面由 Web 和现有 Flutter 桌面共享 Dart 实现。登记、领料、出仓的数量、来源、原请求号、幂等和未知提交恢复合同均未改变。

默认部门定位和树也走相同业务目的的最小组织元数据，不再使用 `departmentCodeIdMapProvider` 的完整组织树与失败回退全公司。页面共用的名称服务另经原字典缓存键映射到 `/business-references/departments`；账户与仓库也读取对应最小业务字典，仍保留原缓存键及写后失效。

## Win7 候选边界

`W7-BIZ-176`、`W7-BIZ-178`、`W7-BIZ-207`、`W7-BIZ-208` 当前均为 TODO，以上业务未完成原生 WPF 迁移。本次没有开放 Win7 写入口，也没有修改共享进度、历史或任务状态。后续原生迁移必须使用同一业务引用合同和四列展示，保留原命令、身份隔离与未知提交保护，不能调用完整员工档案接口来替代。

## 验证

真实生产只读有效权限回执提取出普通仓管的 52 项代码集合，测试不复制账号身份、令牌或其他个人资料。组合验证共 204 个唯一用例通过，包括仅到货查看加登记两项权限的最小组件、实际 52 项权限的完整登记交互、搜索与末页、四列展示、错误保真、原经办人延迟回显、三种 ABA、命令身份、数量和未知提交恢复。原失败过程日志保留在 `output/warehouse-receiver-picker-20261101/frontend`，不以测试模拟代替真实后端授权验收；后端真实数据库回归由独立后端任务提供。

另有 8 项最小字典缓存与纯读 POST 修订号回归通过：账户、仓库、部门保留原字典键和失效语义，只改变最小读取来源；新的客户/供应商 search-context 只对精确 POST 判为读取，不改变写操作或自动重试合同。
