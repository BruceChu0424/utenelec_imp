## 入口与任务形成

物料分析创建自制备料任务，不等于已经下达车间。审核后的正式生产计划形成执行工单，继承合法车间和负责人，WAITING 工单即可在对应车间看到。不得为了任务可见自动批准计划、猜负责人或生成领料。

物料分析追加自制时，尚未提交领料、没有后续执行事实的原任务直接加量，保留原任务 UUID 和 ZX 工单号：3000 追加 1000 后原行变成 4000，任务数不增加([ADR-104](../99-决策记录-ADR/ADR-104-追加自制并入未开工的生产计划.md)、V647)。原物料需求按冻结规则对累计总量重算，已准备的物料与未提交领料草稿保留，只补新增缺口；原量齐套不代表追加后的总量也齐套。未确认路线仍须先选择。已提交领料申请，即使仓库尚未发料，也进入执行边界，后续追加另建工单；已发料、开工、报工或拆批同样不能改原工单数量。追加使任务版本变化，已打开的领料汇总或开工选择须以最新任务事实重核。

顶部保留「等待物料 / 生产中 / 草稿 / 历史任务」。默认未选分类不请求列表，只读取活动任务计数；历史任务须选时间范围或明确「全部」后查询。「草稿」段同时显示本机表单草稿与**我的未审核报工草稿**(服务端 status=0 日报行，双击进报工详情继续审核)，计数按草稿 ID 去重合计(2026-09-27)。搜索、车间、备料状态和分页由服务端处理，列表和徽章使用同一员工范围。行 UUID 是唯一动作身份，货品名称和编号只用于展示。

表格按分类展示：等待物料依次为状态、下一步、来源计划、物料、产品、编号、颜色、产品数量、订单、工单、车间；生产中依次为状态、生产路线（只读徽章）、来源计划、物料、产品、编号、颜色、产品数量、订单、工单、车间、进度（2026-09-23 用户口径「产品数量放到颜色列后面」——看完哪个产品什么颜色就看做多少，再往右才是订单 / 工单 / 车间；2026-09-25 起紧随「下一步 / 生产路线」之后显示「来源计划」列——物料分析编号 WL+日期+日流水，历史计划根显示 —，[V719](../数据迁移/244-V719物料分析编号.md)；列位置为用户当日口径「显示在下一步的后面，不要放在最后面」）——**「生产中」不显示「下一步」列**，报工由勾选后的批量报工入口办理。行右键菜单提供开工、领料、分批领料、查看用料、核对备料与查看计划等动作。双击打开本任务详情（含每种物料的数量表），不要求普通车间员工取得全计划权限。

「下一步」表头可按路线筛选：待选生产路线 / 齐套生产 / 持续生产 / 分批生产（服务端 `routeFilter` 在分页前生效）。

「等待物料」段默认排序(2026-09-27 用户口径「越接近可以开工的越在上面，物料齐的最上面」)：就绪度降序——物料已领齐/无需领料可开工 > 部分物料已投可开工 > 物料已备齐去领料 > 部分物料可领 > 已提交待仓库发料 > 等待到货/等待物料到齐 > 等计划下单 > 待选生产路线；同档内按工单号+执行段保持稳定次序。用户点表头显式排序时该默认排序让位。

状态颜色(2026-09-27 用户口径「物料齐的和部分齐的颜色现在是一样的，改下，色差大点，直接整个状态的表格背景变色」)：等待物料段状态列**整格背景变色**(表格按深底白字/浅底黑字双向约定自动保证对比度)，八档互不相同——物料已领齐/无需领料可开工=绿、部分物料已投可开工=琥珀、物料已备齐去领料=蓝、部分物料可领=紫、已提交领料待仓库发料=亮青、等待到货/等待物料到齐(缺料)=灰、等计划下单=品红、待选生产路线=红。「生产中 / 历史」两段状态仍用只读徽章，不铺整格底色。路线徽章沿用齐套=绿、分批=蓝、持续=品红。

## 先确认路线，再办理

尚未确认路线时，「下一步」格就是生产路线下拉框：点开显示当前可用选项（齐套生产 / 持续生产 / 分批生产），**选中即携带执行段版本提交**——没有草稿、没有确认按钮、没有弹窗，提交期间显示居中加载遮罩。未确认的行预填**路线记忆**(V602 恢复，ADR-096 加操作者档)：先按同产品最近一次有效确认的开工路线，本产品没有历史时按你自己最近一次确认的路线；仅在该路线仍是当前可选项时预填，旁挂黄标「已按本产品上次选择的路线预填，请核对」或「已按你上次选择的路线预填，请核对」——预填只是展示，不写任何事实，选中或批量确认才提交(ADR-093 明确确认口径不变)。无记忆或记忆不在选项内时显示「选择生产路线」空占位。无需物料的任务同样可选齐套 / 持续 / 分批(ADR-096)：持续=随时可开工，分批=按数量拆成两个生来可开工的零料子任务。

| 路线 | 开工前提 | 后续到料 | 适用情况 |
| --- | --- | --- | --- |
| 齐套生产 | 所有必需物料按计划需求到齐，仓库料实际领齐，直送料完成交接 | 同任务办理剩余领料；未齐套不提前开工 | 一次备齐再生产 |
| 持续生产 | 每种必需物料共同支持正产量，仓库料已实际发出、直送料已真实交接 | 在原工单继续领料或接收直送，工单只开一次工，按实际报工推进 | 采购或生产分批到货、边补料边生产 |
| 分批生产 | 明确本批产量并按该批完整齐套、领齐 | 剩余数量保留，后续显式再拆批；各批独立开工/报工 | 各批必须独立管理 |

持续生产不要求先填开工数量，不要求一定存在直送子件，也不把仅一项物料到货当成支持生产。BATCH 不作为普通分次领料的默认办法。路线确认、领料、开工是不同事实，确认路线不代替开工。

**开工前路线随时可换**（ADR-095）：只要任务未开工且没有报工，下拉一直开放，选中即提交；已备料、已领料、同车间直送已投入的事实一件不动。三条路线只在**开工门槛**上不同：

- 改齐套：已备物料保留、继续补齐，每种物料实领到位后才可开工（曾按持续生产备过部分料的任务状态不回退，标签「等待物料到齐 · 已备 a/n 种」）。
- 改持续：开工门放宽为每种必需物料共同支持正产出；WAITING 的任务立即按增量备料补跑一次。
- 改分批：要拆出独立子任务，仍只在尚未备料、领料或绑定供给时可选(无需物料的任务生来 READY，同样可拆)；不可选时下拉不出现该项，悬停说明「已备部分物料，不能再拆分批」。

已开工或已有报工后冻结，格退化为只读徽章回显，悬停说明冻结原因(红冲报工方可解锁)，不通过更改路线删除历史。路线可逐行选定，也可勾选多行后批量提交(ADR-096)，批量有两个入口：**在任一勾选行的「下一步」下拉直接选**——被改的行已勾选且勾选集里还有别的可设路线行时，一次下拉就对全部勾选行提交，悬停说明先讲清「本行已勾选：会一并确认全部 N 个勾选行」(2026-09-21 用户口径「我明明多选了，选中一个，为什么批量设路线还要重新选」；此前下拉只改本行，其余行只是被路线记忆预填成同样的字)；或用「批量设路线(N)」菜单按路线提交：菜单项「齐套生产(n) / 持续生产(n) / 分批生产(n)」括号里是勾选行中支持该路线且当前不是该路线的行数，「按预填默认值确认(m)」把带记忆预填的行各按自己的预填一次确认。两个入口同一套筛选(不支持该路线或已是该路线的行自动跳过)，没勾选的行在下拉里照旧只改自己；每行携带各自版本，不适用、版本冲突和部分失败按行提示并刷新。等待物料分类里不能开工的行(未选路线、物料未齐、待仓库发料)在首列勾选框角上压一把锁并悬停说明，勾选仍可用于批量设路线，批量开工计数不含它。提交中显示居中加载遮罩，防止重复点击。

### 跑批期间的加载反馈（2026-09-26 当前规则）

本页的全屏居中加载遮罩([UtenBusyOverlay](../02-组件库/UtenBusyOverlay.md))收成**一条通道**，同一时刻只有一块，按动作换文案：

| 动作 | 遮罩 | 文案与语义 key |
|---|---|---|
| 批量设路线 / 行内「下一步」下拉选中即提交 | 有 | `正在确认生产路线`，`workshop-route-confirm-busy` |
| 批量开工(含行右键菜单、任务详情弹窗里的单行开工，同一个方法) | 有 | `正在开工`，`workshop-batch-start-busy` |
| 重新核对备料 | 有 | `正在重新核对备料`，`workshop-recheck-busy` |
| 普通领料汇总页加载 / 提交 | 目标页持有统一模态遮罩 | `production-draw-request-loading` / `production-draw-request-saving` |
| 缺料申请页加载 / 提交 | 目标页持有统一模态遮罩 | `discovery-request-loading` / `discovery-request-saving` |
| 领料核对页返回后的任务刷新 | 本页持有统一模态遮罩 | `正在刷新任务列表`，`workshop-draw-review-refresh-busy` |
| 导航到分批领料、批量报工、生产计划或用料记录 | 来源页不跨导航挂遮罩 | 实际加载由目标页负责；导航防重复和网络加载分别管理 |

三条纪律：

- **遮罩盖住网络段与随后的整页重拉两段**，中途只换文案成「正在刷新任务列表」，不撤不闪。表格组件在已有数据时刷新是零画面的，遮罩撤早了就是「成功提示已经弹出、表格还停在旧行」的裸奔窗口，用户会对着没变的旧行再点一次。结果提示一律在遮罩撤下之后才发；刷新段的文案不说「已提交」「已完成」——整批全失败时这一段照样要跑，成了几条要等提示才知道。
- **来源页不把遮罩挂在整个导航 Future 上**。点击「批量领料」后，普通领料汇总和缺料申请均在目标页实际加载/提交期间显示同一 `UtenBusyOverlay`，网络阶段阻止重复操作；加载成功或失败都在 `finally` 撤下，不再使用旧首屏卡片。回到任务页后，只有实际重拉列表与徽章时显示本页刷新遮罩，刷新完成即撤下。这样既有统一的居中加载反馈，也不会让来源页的 root Overlay 盖住已加载好的确认页。
- **遮罩带不可关闭的 `ModalBarrier`，一旦卡住就是整屏死锁**：它自己盖住了右上角「刷新」，那条人工自愈路径够不着。所以真正的保证是每条链路的 `finally` 无条件复位；「返回即刷新」`onPageResume` 与刷新按钮里的复位只是第二、第三层兜底(日报页保存后 `context.replace` 会吃掉 push 的 completer，`finally` 走不到——本页的跑批动作都不走那条路，但兜底照留)。

## 物料来源与数量

路线决定生产节奏，来源决定物料如何交接，两者分开。一个任务可同时包含普通仓库领料和本车间上下层直送料：

- 普通仓库料在「去领料 / 继续领料」汇总中按真实仓库、货品、颜色和单位 UUID 聚合，保留每条 DRAW 明细及原任务 UUID；本次可选择物料和数量，剩余量保留待领。
- 车间直送料按服务端真实来源与交接投入，不在仓库领料汇总重复申请。不把车间流转身份解释为货品默认存放仓。

当前车间未用完的直送料可以送正常仓库，无需送回上游生产车间。余料申请区显示“来源位置”用于追溯；仓库在“确认余料收仓”中选择实际正常收料仓库。尚未领用的直送来源显示“车间直送（未投用）”，不要求先虚构领料或开工。收仓前数量仍处于待交接冻结状态，正常库存只在仓库确认后增加；后续生产从真实收仓位置续领，保留同一任务及来源关系。
- 待检、拒收、预计在途、待仓库发料不等于实际投料；页面采用后端 `canStart` 与 `canRequestDraw`，不自行拿 READY、库存行数或全量 issued 标志猜开工资格。
- **逐种物料事实**（ADR-095，2026-09-20 用户口径「物料没有齐不能显示齐，车间内流转的要流转了才算；车间内流转的数量怎么统计、显示在哪里」）：服务端把每种正式物料需求归入且只归入一个桶——已领到车间(含同车间直送已投入)/ 缺·等采购到货或委外回厂 / 缺·等自制子件完成(子件工单产出可能线边直送也可能入库后领料，交接方式在子件报工时才决定，未流转到本任务不算到料；ADR-096 起不再写成「直送」)/ 已备好可领 / 已申请待仓库发料 / 直送料待开工自动投入 / 备料中。「物料」列显示 `已领 a/n 种 · 缺 k 种(自制子件 j) · 可领 m 种 · 待发 p 种`，其中「缺 k 种」红色、「可领 m 种」绿色、「待发」次要灰(2026-09-20 用户口径)，悬停逐桶解释并给出已投料可产量；详情弹窗逐种列出需求 / 仓库已到(齐套到齐前不预留，按齐套提升同口径的仓库可用量显示)/ 直送已交接 / 已领 / 缺口 / 状态 / 承担的子件工单，来源写「自制子件 · 直送或入库领料」。
- 状态文案只按这些事实生成：可开工时每种物料都实领才说「物料已领齐 · 可开工」，否则「部分物料已投 · 可开工」；可领料时缺料说「部分物料可领 · 去领料」，全备说「物料已备齐 · 去领料」；已提交待仓库发料；缺料按持续生产说「等待到货 · 缺 k 种」/「等自制子件完成 · 缺 k 种」，按齐套说「等待物料到齐 · 已备 a/n 种」。表头「去领料」筛选桶名为「物料可领 · 去领料」，不宣称齐套。生产中明确按实际投料报工；「待报数量（含品质恢复）」来自计划剩余及有效恢复授权，不能冒充物料支持量。本次可报上限由报工来源接口精确计算，并分别保留品质恢复授权。

领料提交沿用已审预览指纹、执行段版本、明细 UUID 与幂等键。请求结果不明确时重试原意图，不能刷新生成第二次领料。聚合提交可以跨任务但必须同一车间，一次最多 50 个任务。

### 底层材料尚未确定时的领料申请

最底层自制件没有正式材料明细时，先确认齐套或持续生产路线，再从「批量领料」进入「确认领料申请」。一次仍限同一车间、最多 50 个工单；混选此类任务与普通可领任务时，先办理材料申请，成功返回并刷新后再核对其余普通领料，不能把未成功申请的任务当成已提交。

页面采用项目自有 `MasterDataTableView`。顶部只保留一条醒目的红框红字提醒：「下方工单尚缺领料信息。材料和数量可选填；不清楚可直接提交，由仓库补充。」原多段静态帮助与 BOM 说明已移除，动态错误和权限提示仍显示。车间任务（ZX 工单号）、生产计划、领料车间、提交状态各占独立紧凑列；提交状态按事实显示「待提交 / 已提交 / 待核对」，不再把多行身份与状态挤在同一格，也不强制固定行高裁掉大字体。

每个工单可以全部留空、只选材料或填写材料与数量，也可添加多种材料；空白材料行不提交。选料后自动带出名称、编号、规格、颜色、基本单位和参考库位，资料只读，缺少值显示「—」，颜色无需另选。父件产品与计划产量用于说明生产用途，不能充当原料或代入领料数量；参考库位也不代替仓库确认的实际发料仓。已填写的数量须为正数、最多 4 位小数；同一工单的同材料同颜色不能重复，每工单最多 100 行。换了材料或单位要重新核对数量，重选同材料保留已带入的颜色身份。

申请按各自执行段 UUID 和版本逐工单提交，材料不会跨工单合并。幂等键绑定该工单、版本和材料快照。多工单提交中已成功的工单保留「已提交」，重试不再发送；超时或结果不明确时冻结原提交参数与键，保留草稿，只能原样重试确认。明确业务拒绝会显示原因；权限、任务版本或草稿来源已变化时须重新核对，不能用恢复草稿覆盖已成功或尚未确认的提交。

成功创建的材料发现申请取得独立、不可变的 **LQ 申请号**。同一请求同键重放返回原申请；该工单已有未撤回申请时，换新键重复提交会被受控拒绝，不新建第二份申请、不改变原号或材料事实。待仓库处理的 `PENDING` 申请可在行菜单「撤回领料申请」撤回：先读取最新版本再提交撤回，仓库已处理或版本变化时拒绝。撤回保留原申请和永久占号；确需重提时按最新工单状态创建新申请，不复用旧 LQ，也不复活旧申请。

车间建议自动带到[生产领料任务中心](生产领料任务中心页.md)。未知材料由仓库选择；已知材料可与普通 DRAW 同表补齐数量和实际叶仓后原子出库。一个 LQ 按实际发料仓可形成多张独立 **SL 正式领料单**，仓库列表及申请详情按真实 UUID、单号和仓库逐张追溯；LQ 不作为 SL 临时号，ZX 也不代替申请号。申请、预留和建议本身不扣库存、不增加开工资格，也不直接学习 BOM；后续沿实际出库、确认退料与审核实际产量累计学习，保留人工 BOM。已开工历史不补造领料。

## 车间内料仓: 开工确认表、待认料与换料 (2026-09-28)

依据 [ADR-131 车间整批领料与盘点计耗](../99-决策记录-ADR/ADR-131-车间整批领料与盘点计耗.md) §5.4、§5.5。只对"开启了整批领料"的车间生效; 没开启的车间本页一切照旧。颗粒这类整批领料的料由仓库整袋发到车间内料仓 (原名线边仓), 工单不再为它领料, 用量由盘点算出、按报工量分摊。

**顶栏「车间内料仓」按钮**: 打开[车间内料仓页](车间内料仓页.md)并带上当前车间, 看现存、估计还剩, 办申请领料、退回、试模清机等用料和盘点。

**待认料**: 产品既没有 BOM 单个重量、也还没选过用哪种料时, 任务状态显示"待认料 · 开工时选用料", 归在「开工准备」的等待物料筛选中, 排在"去领料"之前。首次也不要求工单领料，点击状态或勾选开工进入认料确认表；待认料与内料仓待启用任务不计入批量领料，不提供按单领料入口。产品有期间料但车间没开启整批领料时，显示未开启原因，排除在「可开工」筛选之外。

**2026-09-30 开工与补料分开**：顶层未开工汇总改称「开工准备」，数量仍为全部未开工任务，不表示仓库要发多少张单。使用内料仓的进行中任务详情显示当前有效材料的「本任务预计需量／内料仓估计余量／预计缺口」，有申请权限的人始终可点「新建补料申请」，足料也能提前整批申请。申请只通知仓库，不挂工单，不锁定或限制本次生产数量，也不是开工前置条件。嵌件等按单物料仍使用原领料流程。

预计量由 `GET /api/workshop-material/segments/{segmentId}/stock-readiness` 服务端统一换算：剩余生产量转换到产品基本单位，再乘材料基本单位单重；返工不重复计新料，报废补产计入。只使用今天有效的期间材料，并精确匹配内料仓、材料与颜色。缺单重、缺余量事实或存在未审核报工时标为暂不能判断，不能当零用量或实物齐套保证。此接口只读，不是领料预留或开工守卫。

**开工确认表**: 勾选任务点「开工」, 其中有需要确认的行 (待认料, 或生产路线还没确认) 时弹出一张表, 按产品一行:

| 列 | 说明 |
|---|---|
| 产品名称、编号、本次任务数 | 同一产品多张工单合成一行 |
| 用料 | 选这个产品用车间内料仓里的哪种料, 每个产品只选一次, 以后开工自动带出。老库材质或上次选过的已预填 (标"请核对")。同时用两种料 (双色 / 双料) 就都勾上; 不用内料仓的料选最下面一项"本产品不用车间内料仓的料 (按工单领料)"。产品已有 BOM 单个重量或已选过料的显示"用料已定", 这次只需确认路线 |
| 还要按工单领别的料 (例如嵌件) | 只对没有 BOM 的产品出现, 默认不勾。嵌件注塑件勾上: 塑料从内料仓用, 嵌件照常按工单领料, 领完再开工 |
| 生产路线 | 按路线记忆预填; 已经选过路线的只显示 |
| 单个重量 | 只读, 来自 BOM; 没填显示"待补, 不影响开工" (结算前补上即可) |

底部按钮: 「确认并开工 (N)」依次记下全部用料 → 对路线没确认的工单逐个确认路线 → 批量开工, 办完自动关闭; 「先按工单领料, 暂不开工」只记用料和路线, 然后转去领料。勾了"还要按工单领别的料"的产品、以及选了"不用内料仓的料"且没有 BOM 的产品, 记下用料后不开工, 转到原来的领料申请去领按工单的料。三步各自防重复, 中途失败再点一次不会重复记录; 已记下的用料和路线都是有效的。勾选多行后在任一勾选行里选, 会对全部勾选行一起生效。

**换料** (少用): 生产中的行右键菜单「这张工单改用别的料」: 选原来用的料 (或「加一种料」, 例如双色件)、改用的料、从哪天起改用 (不能早于内料仓已结算的日期)、单个重量按哪个算 (默认沿用原来那种料的单个重量, 也可按新料在 BOM 里填的)、原因 (选填)。只改这一张工单, 从选定那天起报工的产量按新料算用量; 以后新开工的工单不受影响 (要一直换, 请改产品的用料)。菜单项只在服务端说这张工单可以换料时出现。

**报工日期与结算**: 工单接上内料仓后, 如果报工日期落在内料仓已经结算的那一期, 新建、审核、红冲都会被拒绝, 并提示报工日期请填下一期起始日或以后; 要改已结算期的报工, 请找有撤销结算权限的人撤销后再改。

测试: `test/features/production/start_confirmation_sheet_test.dart`、`test/features/production/workshop_tasks_bin_state_test.dart`; 服务端 `WorkshopMaterialStartGatePostgresTest`。

## 进行中与异常后续

只有显式开工后的 IN_PROGRESS 工单可以报工。生产中主链为「继续领料 / 分次报工 / 查看用料记录」：报工仍由勾选后的批量报工入口办理，一次同车间，申请权限不等于允许跨车间写入。无报工权限但有任务查看和开工权限的员工仍可办理本任务的后续领料。

「生产中」段按未审核报工草稿扣减(2026-09-27 用户口径「填写保存了，进行中就不应该再显示」)：待报数量先扣 status=0 日报草稿已承接的完工量(与报工读侧同口径，不含实际超产行)；被草稿**全量承接**的任务不再出现在「生产中」正文与分段计数，去「草稿」段继续处理；部分承接的保留并显示扣减后的待报数量，分批报工不受影响。审核或删除草稿后整页重拉即恢复/结案；草稿读取失败回退服务端口径(fail-open)，不因草稿接口异常挡住生产中列表。

实耗在生产日报随报工登记，车间任务页保留只读材料台账和退料进度；共享批次台账必须返回真正原领料任务 UUID，不把余料、损耗或在制自动当实耗。退料发起与仓库实收、品质通过与产成品实收入库各自是独立事实。返工再检、拒收重新交付、报废补产沿既有同源授权办理，不重复普通报工，不自动抹掉原失败或少收记录。超计划产出和领料仍由服务端明确校验。

原料退回或发生品质失败后，不使用旧页面能力快照继续提交；版本冲突返回刷新提示。持续补料使用原任务；只有选定分批路线才形成批次谱系。

## 到料通知

`PRODUCTION_WORKSHOP_TASK_ACTION_REQUIRED` 已进入统一居中待办弹窗 `ReviewPendingDialog`，登录和在线到达共用。卡片完整显示服务端计算的到料、缺口与下一步文案，单条和多条聚合均不截断车间物料正文；弹窗内部滚动。点击进入我的车间任务。通知中的到料不等于已领料，也不代替路线确认或开工；实际资格始终重新读取任务。到料事件携带 IQC 入库批次、产成品入库单或直送日报 UUID；消费前复核来源仍有效，已反向或旧事件缺少证据时只能重建中性当前状态提示。采购、委外、产成品和直送反向同时撤回旧卡并按当前事实重建，避免异步晚到重弹旧数量。

本次某一种必需物料已归本任务即可提示，不要求整单已经齐套；他单纯专属来源不弹，公共切片按本主仓实际可用量与安全量判断。卡片缺口清单按「仓库已到 X，还缺 Y」表述（齐套生产到齐前不做段级预留，缺口扣掉齐套口径的仓库可用量，不再把「到了 100 还缺 900」说成「还缺 1000」），自制子件供应的缺口标注「(自制子件在产)」，不预言直送还是入库。暂停、关闭、取消计划不产生开工行动卡，旧卡办结。卡片确认、已读、稍后和业务办结沿统一通知协议。开工前到料通知与持续生产后续补料进展以当前任务事实刷新，禁止仅按前端文字猜是否办结。

超级管理员可替车间办理，但仍受版本、物料、路线和来源守恒约束。普通负责人、计划编制人都必须是当前有效员工；拥有相应动作权限的编制人可沿管理范围办理，所有人身份不能绕过动作授权。暂停/关闭计划不再暴露领料、开工等执行能力。页面启动、返回、操作成功和共享执行刷新信号均读取服务端事实；迟到请求通过 generation 丢弃，账号切换/注销清空旧计数。分页和搜索不在客户端先下载全部工单再筛选。

任务改派以实物为界：未实发且没有共享物料批次依赖时可以换车间，已有未发领料草稿同事务同步收料车间和人员；已经发料或直送后不能靠改派转移实物。同车间换有效负责人不重写历史发料人。报工页面按整个执行任务剩余目标判断最后一批，按本次实际投料计算可报上限，两者分别显示和校验；整包/固定批次的实际耗用由人员确认，不按平均数自动填写。

再次编辑日报会恢复精确计划身份、排除本草稿后的任务余量及已填用料。材料读取失败时保留原已存用料，不能在普通保存时悄悄删除；成功更换来源后才按新来源清理原用料。已选择的直送去向也不会因为候选失效或网络失败自动变成送仓库/另一个任务，须重新核对接收工单。2026-09-27 起批量报工的每一行都可在下面逐条分配产出去向(ADR-127 §7)：系统按先急后缓把产量分给同车间还缺料的上层工单、余量送入仓库并自动补行，员工可改任一条；2026-10-01 起，一个可送的都没有时默认只读显示「送入仓库」及对应数量，鼠标悬停查看无法车间内流转的具体原因(例如委外件要先送入仓库)。详见[生产执行分段与报工页](生产执行分段与报工页.md)。
