## 二、页面结构

对齐品质部检查结果页范式：**进页面不预选大类**（内容区显示「在上方选择分类后
开始办理」引导空态，不加载任何分段数据）；各分段的小类行只随选中的大类出现
（结构上等价于大类未选时小类锁定）。

1. **页级工具条**：大类分段 = 待领任务 / 领料单 / 生产退料 + 胶囊搜索（关键字
   下发当前分段）。徽章只挂真实待办（**草稿不计入待办数**）：待领任务 =
   已提交且仍有申请未发量的正式 DRAW，加上有效 `PENDING` 材料申请；生产退料另有正式待收申请徽章，领料单和普通草稿/历史不冒充待办。
2. **待领任务段**（`WarehouseDrawTaskSegment`）：与 `/operations/workbench/warehouse`
   履约工作台同源，正式行由需求投影 `v_fulfillment_workbench` 经
   `production_planning_package_document_items` 的真实 DRAW 映射连接到单据和明细，**按正式 DRAW UUID 归组**。
   同一需求跨两个实际仓产生两张 SL 时，两行都显示，各自使用本单仓库、已申请量和实发量；
   不再从 `v_fulfillment_workbench_actions` 每需求只取一个动作，也不以 `LIMIT 1` 省略第二张单。
   尚未配置的底层材料申请作为独立分支，按真实 requestId/LQ 一行归组，不能当作已生成的 DRAW。
   多物料正式单货品列显示「N 种物料 · N 行待领」、待领数量列显示行数，
   并新增领料单号列；单货品单据照旧逐列显示货品与数量。小类分段 =
   待完成(默认) / 已领取；待完成包含未领、部分领取及待补材料申请。正式单无剩余申请量为 DONE，
   仍待发且已有实发为 PARTIAL，其余已申请待发为 READY_TO_PICK。
   `MATERIALS_TO_DEFINE` 行未选料时红底显示“需要填写”，已选料时显示“待核对领料”；
   单材料未填数量显示“需要填写数量”，不以父件计划量代入。材料列显示真实领料材料，父件只放“用于生产”。
   双击普通正式行打开 `/warehouse/DRAW/:id` 办理分批出库；双击已知材料申请进入同一批量详情页，
   未知材料申请进入“填写实际领料”。草稿首次实际出库完成审核，无对象权限的行只读（服务端裁剪）。
   - **批量出库**：表头复选框多选 + 右下角悬浮「批量出库」，有 `stock_doc:issue` 才渲染操作。
     勾选跨页保留；切换子分类、关键字或单号筛选时清空，排序不清空。刷新会剔除本页已领完或失效的选择，
     结果只有一页时也剔除已不在结果中的选择，多页时不凭当前页推断其它页。
     选择中含未知材料或失效任务时明确提示先填写/刷新，不能静默丢弃后只提交其余行。
     一次选择 **1 至 50 项任务**，包括正式单与已知材料申请；导航分别携带去重 UUID 列表
     `documentIds`、`discoveryRequestIds`，允许其中一组为空。
   - **同表补信息**：批量页进入时只读取最新详情。普通 DRAW 行保持整张当前已申请未发量；申请行自动带入
     已选材料及其编号、规格、颜色、单位、参考库位和生产用途，资料只读，无值显示“—”，只补实际数量与叶仓。
     缺项红框、表头星号和逐行错误提示并用；数量必须为正数、最多 4 位小数，参考库位不替代实际仓。
     同一材料可「拆分发料仓」增加一行，新行数量和仓库留空待核对；至少保留该材料一行、同申请最多 100 行，
     同材料同颜色同单位同实际仓的重复行须合并，不能借拆行改掉材料身份。
   - **确认与原子性**：统一备注选填、最多 200 字。仅普通 DRAW 调用 `POST /stock/docs/issue-batch`；
     包含申请时调用 `POST /stock/docs/issue-discovery-batch`，参数为 `docIds` 和
     `discoveries[{requestId,expectedVersion,items[{goodsId,colorId,unitId,warehouseId,qty}]}]`，另带同批幂等键与备注。
     服务端先锁定并核对全部任务，申请配置、按实际仓生成 SL、审核及整批实发在同一事务完成，任何失败整批回滚。
     普通单只发「累计有效申请量 − 已实际发出量」，不把尚未申请的需求余量带出；申请行采用本次核对的实际材料数量。
     含草稿或待配置申请时还须 `stock_doc:approve`，无权时前端给出原因，服务端同样拒绝。
     普通已出完单按服务端事实跳过或识别同键重放；失败保留输入，幂等与不确定结果处理见「四」。

- 待领任务徽章 = `GET /operations/workbench/warehouse/count`
  （`countPending('WAREHOUSE')` 复用 `WAREHOUSE_DOCUMENT_ROWS`，计 `open_line_count > 0` 的任务行）：
  正式 DRAW 每张单一项，未配置的有效 PENDING 申请每份一项。未知材料申请即使尚无数量也计待办；
  已配置申请退出该申请分支，转为真实正式单据行，跨仓形成两张 SL 时按两张待发单计数。
  不再用每需求单一动作投影或无正式申请的行级需求兜底冒充仓库待办。
- 领料单和普通草稿/历史不挂待办徽章；生产退料的正式待收申请单独计数。
- hub「生产领料任务中心」卡徽标 = 已提交待领任务数 + 正式待收退料数；
  工作台仓库卡 = 三张任务中心卡之和。
- **待领任务子分类计数**（当前为待完成 / 已领取）：
  「待完成」是已申请且待发的总量段 → 红徽章；旧“待备料/部分领取”不再作为并列分类
  （同一批活不在一行里红两遍，见 [徽章与计数口径](../00-项目准则/14-徽章与计数口径.md)）。计数口径 =
  `GET /operations/workbench/warehouse/status-breakdown`
  （`warehouseStatusBreakdown()`）。列表、汇总和子分类计数共用
  `FulfillmentWorkbenchQueryService.WAREHOUSE_DOCUMENT_ROWS` 的归组和状态规则，
  `OPEN_ANY = READY_TO_PICK + PARTIAL + MATERIALS_TO_DEFINE`；已领取 DONE 为终态，不计待办。
  子分类徽章请求携带当前仓库范围，不随表格关键字、单号筛选或分页缩小；列表及其 `summary.statusCounts`
  则遵循本次查询上下文，只有相同范围与筛选条件下才比较计数，不能把搜索结果条数与范围总徽章直接等同。
  正式单的判断保留已出完明细，避免剩余待发行把部分领取误判成未领取。
  计数端点失败时前端清空徽章并写日志（不再 `catch(_)` 静默留旧值）。

本轮申请量全部发出后可退出待发队列，原工单是否领齐仍按完整需求与累计实发判断；原需求还有未申请量时由车间再次提交。内部DRAW生成、打开页面和通知到达都不增加申请额度，详见[ADR-077](../99-决策记录-ADR/ADR-077-车间明确提交领料后进入仓库任务.md)。

## 四、业务口径与边界

- 生产链（物料分析/报工）生成的 DRAW/FINISHED_IN 单据禁止通用编辑/删除
  （`fn_is_production_linked_stock_document` 服务端守卫）。生产领料/退料域整体归
  生产链所有：领料单/生产退料不提供手工新建入口（2026-09-04 撤除）——手工单没有
  计划包与执行段映射，审核/出库会被台账守卫一致拒绝（「必须且只能关联一张有效生产
  计划」「没有且仅有一个有效生产计划包，禁止发料」）；临时性出入库请用其它入库/其它出库。
- 领料分批出库（issue）幂等；草稿首次出库的审核与扣账共用同一事务，响应丢失以同一
  幂等键重放不会重复扣库存。取消出库必须填写原因，以反向流水恢复库存和占用，不修改
  或抹除原出库历史；退料只退已领良品，数量 ≤ 来源行可退量。
- **批量出库幂等与草稿**：前端按所选正式单、申请 UUID/版本、每行材料与颜色/单位/数量/实际仓、统一备注
  形成完整提交指纹；同一内容复用原 UUID 批量键，不是每次点击都换新键。提交前保存草稿；超时、断网或结果不明确时
  冻结原参数和键，保留手填内容，只允许原样重试确认，不能改数量后沿旧键重放。明确业务拒绝后可按提示修改，
  内容改变才形成新意图与新键；成功后清理该草稿并刷新任务与徽章。
- **两类端点的重放**：普通 DRAW 沿 `StockDocService.batchChildIdempotencyKey` 按操作人、批量键与真实单据 UUID
  派生子键，并以实际 ISSUE 事件识别重放。包含材料申请的批次另用持久批次记录绑定操作人、整批键和规范化完整 payload，
  同键不同内容受控冲突，已完成同键返回原结果，不重复配置、不另造 SL、不重复扣库存。响应沿用
  `StockDocIssueBatchResponse{issuedCount, skippedCount, replayedCount, replayed, issuedDocNos}`；
  `replayed=true` 时提示“本批此前已完成”，已出完但不属于该键重放的普通单按实际结果计 skipped。
- **申请号与正式单关系**：待处理申请主单号显示“申请 LQ…”，正式行保持 SL，来源申请号独立展示。
  一个 LQ 可经真实需求/明细映射关联多张 SL，正式列表必须全部保留并按各单实际仓筛选；详情逐张用 UUID 打开。
  同一正式单真实承接多个申请时完整显示来源 LQ。重复材料申请不能生成另一份未撤回申请；撤回只允许尚未仓库处理的
  PENDING 状态并校验版本，旧 LQ 及永久占号保留。取消出库或红冲是正式单据的独立审计动作，不撤回/改号掩盖出库历史。
- **出库备注**（2026-09-12 起单张详情在表格上方「出库备注(选填)」+ 逐行「行备注」列编辑；批量出库仍走「统一备注」）：随正向出库 `reason` 追加到
  单据 `remark`，单条 ≤200 字（输入框同值）、多轮用「；」连接、总长 ≤500；判重按
  「；」拆条整条相同才跳过（此前 `contains` 判重会把「A」当成「AB」的重复丢掉）。
  草稿首轮「出库即审核」同样带备注（此前被静默丢弃）。取消出库的 reason 仍走取消原因
  审计，不落 remark。
- **出库凭证/照片**（附件 ownerType=`STOCK_DOCUMENT`）：常驻领料单详情页（不再只在出库
  弹窗内），可看/可管口径见[出入库记录页](出入库记录页.md)「十、仓库单据凭证附件」。

## 四·一、称重(2026-09-28，[ADR-135](../99-决策记录-ADR/ADR-135-仓库重量账与单重自学习.md) / V743)

数量仍是领料、占用与成本的唯一事实；重量只进仓库重量账，永不拦截出库。领料的数量来自计划(BOM × 产量)，
称出来的重量不参与单重均值，只用来测「实发比应发多了多少」。

- **单张领料出库**(`/warehouse/DRAW/:id`，`ProductionDrawDetailTable`)：
  - 「已出库」后加只读「已出库重量」(各轮实称 / 分摊重量合计，已扣取消出库；估算带「≈」)；「本次出库」后加可编辑「本次重量」
    (共享[出库重量列](../02-组件库/WeightGridColumn.md)：占位「应称 12.5」，WARN 琥珀 / ALERT 红框，⚖ 反推称重计数
    「需要 N 个 → 秤上应显示约 Y kg」只回填重量)，另有「称重核对」列(如「比应发多约 35 个 (+1.5%)」)。
  - 清空「本次出库」再填重量时，按单重反推数量(黄框待核对)，该行标记 `qtyFromWeight`。
  - 请求 `POST /api/stock/docs/{id}/issue` 与 `/approve-and-issue` 的 `lines[]` 增加 `weightKg`、`qtyFromWeight`(仅 true 时发)；
    同一明细多行时重量相加，同一明细既有称重行又有未称行返回 400。重量进入出库幂等哈希(不称重的请求哈希不变)，客户端幂等键同样带上。
  - 确认摘要列出「本次实称 X」与偏差行，只提示不拦截。每轮称重只记在出库流水上(MEASURED)，不写回生产链领料明细(守卫禁止)。
  - 旧「实际重量」列(领料明细 `weight`，生产领料恒为空)删除；手工领料单明细带重量时另显示「单据重量」。
  - 每条称过的出库流水记一条 DRAW 称重观测(核对证据，捕获键 `DRAW:<流水 id>`，往来方 = 领料部门)；取消出库按后进先出把观测标为已红冲。
- **取消出库**：弹窗改为只读退回重量(全退 = 原重量，部分退 = 已出库重量 × 取消数量 / 已出库数量，标「(按比例)」)；
  请求只带数量，`/issue/reverse` 带重量返回 400，重量由重量账镜像原流水。
- **批量出库**(`/warehouse/DRAW/batch-issue`)：每条待出库行在「待出库」后有重量格，材料申请行各有自己的重量格(换算率为 1 的申请行可按重量反推数量)。
  重量进入表单草稿与提交指纹，改重量即换新批量键。
  - `POST /stock/docs/issue-batch`：`weights: [{itemId, weightKg, qtyFromWeight}]`(明细必须属于所选单据，否则 400；已无可发量的明细忽略)。
  - `POST /stock/docs/issue-discovery-batch`：顶层 `weights`(已有 DRAW 明细，同上) + `discoveries[].weights: [{goodsId, colorId, warehouseId, weightKg, qtyFromWeight}]`
    (须恰好对上该申请的一条配置行)；两者都进批量请求哈希。没称重时两个键都不发。
- **生产退料收仓**(WDRAW，待仓库确认且有审核权时)：明细表「数量」后加实称重量格(登记数量只读)与核对标签「登记退 N个, 称重约 M个」；
  收仓确认弹窗显示重量汇总，`POST /stock/docs/{id}/material-return/confirm` 增加 `lines: [{itemId, weightKg}]`(没称时不发)，
  存入 `production_material_return_receiving_confirmations.line_weights`，进入确认哈希(同键不同重量 409)，客户端幂等键同样带重量。
  退料入库流水(以及车间直送退回时线边仓的出库腿)按实称记 MEASURED，收料仓的调入腿取对应出库腿的重量；
  并记一条 RETURN 称重观测(核对证据，捕获键 `RETURN:<流水 id>`，往来方 = 车间)。
- **明细重量字段**：`GET /api/stock/docs/{id}` 的 `items[]` 增加 `issuedWeightKg` / `issuedWeightEstimated`(DRAW = 出库减取消，WDRAW = 已收仓重量；
  任一相关流水重量未知或还没有流水时为 null)，以及 `qtyFromWeight`、`countWeight`、`bookWeight`。
- 已知限制：仓库报表按单据类型的 DRAW / WDRAW 明细表仍读明细 `weight`，生产链领料的每轮重量在流水上、退料重量在确认行上，这两类报表的重量列暂为空；
  看领料重量请用[库存详情页](库存详情页.md)出入库流水。
- 回归：`test/features/warehouse/stock_doc_detail_weight_test.dart`、`production_draw_batch_discovery_test.dart`、`warehouse_draw_task_segment_test.dart`；
  服务端 `StockDocWeightCaptureContractTest`、`StockDocWeightCapturePostgresTest`(门控)、`ProductionDrawDiscoveryBatchEndToEndTest`、`ProductionMaterialDiscoveryEndToEndTest`。
