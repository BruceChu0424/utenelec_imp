# V608 报销链路完整化

> 迁移：`server/src/main/resources/db/migration/V608__expense_claim_fullchain.sql`
> · 决策：[ADR-094](../99-决策记录-ADR/ADR-094-报销链路完整化.md) · 实体：[实体字典 §2.4](../04-数据模型/实体字典.md)

## 变更内容

1. **单号命名空间**：`business_identifier_namespaces` 注册 `EXPENSE_CLAIM / BX`
   (DocNumberPrefix 镜像)；`expense_claims` 补齐 `claim_no`(`BX + YYYYMMDD + 6 位日流水`，
   UNIQUE + `^BX[0-9]{14}$` CHECK)，并接入 V279 终身占号及单号不可变触发器。
2. **存量回填**：已有非空单号原样保留并登记原 UUID 的占号；按号码内日期、终身占号和
   `business_document_sequences` 的较大值推进流水。仅缺号单据按创建时间、UUID排序，
   使用创建时间的上海业务日接续取号；非法旧号或跨身份占号冲突导致整个迁移回滚。
3. **新表 `expense_claim_invoices`**(发票登记)：
   - 要素：`invoice_type`(六枚举 CHECK：GENERAL/SPECIAL/DIGITAL/PAPER_GENERAL/PAPER_SPECIAL/OTHER)、
     `invoice_code`、`invoice_no`、`issue_date`、购销双方名称/销售方税号、
     `amount_excl_tax` / `tax_amount` / `total_amount`、`check_state`
     (UNCHECKED/VERIFIED_MANUAL/MISMATCH)、`attachment_id`(FK→attachments，SET NULL)。
   - 形状约束(税务总局 2024 年第 11 号公告)：号码 `^[0-9]{8}$|^[0-9]{20}$`；
     代码 10/12 位；**20 位数电票必须无代码、8 位老票必须带代码**(CHECK)。
   - **防重复报销唯一索引**(财会〔2020〕6 号)：
     `UNIQUE (COALESCE(invoice_code,''), invoice_no)` —— 存活报销单间同一张票只能登记一次；
     草稿物理删除级联释放号码，驳回重提同单保留。
4. **新表 `expense_claim_events`**(流转留痕)：`event_type` 七枚举 CHECK
   (CREATED/SUBMITTED/WITHDRAWN/EDITED/APPROVED/REJECTED/PAID)+ 操作人
   (employee FK + 姓名快照 NOT NULL)+ 备注(存驳回原因/重提说明)+ 时间；索引 (claim_id, created_at, id)。
5. **存量事件回填**：五段 `INSERT ... SELECT` 按既有时间戳回填创建/提交/通过/驳回/打款
   (审批/驳回/打款操作人姓名 join employees 取全名，取不到回退申请人快照)；
   老单撤回在旧模型无痕迹，不回填。同单、同动作、同操作人和同时间的已有事件不重复插入。

## V607开发库部分结构的启动修复

2026-09-19启动日志在 V608 添加 `claim_no` 时报告 SQLSTATE 42701。只读核查本机开发库确认：
Flyway最后成功版本是607，尚无608历史记录；单号列、NOT NULL/唯一/格式约束、命名空间、
发票表及索引已存在，事件表、两表审计触发器及清库策略尚未完成；报销单和发票均为0行。
这是未登记迁移的部分结构，不能据此认定V608已成功应用。

本次修订尚未成功登记的V608候选，使其复用已有表、列、约束和索引，补齐触发器、事件表与
缺失清库项。无需删表、清库或 `flyway repair`。正式执行仍由Flyway在一个事务中完成；
保留已有数据，不以重新编号掩盖冲突。对已经成功登记旧V608校验值的其他环境，仍须保留
其已应用字节并另行制定前向升级，不直接套用本次未登记开发库的处理。
