# 生产链逐步守恒与压力测试矩阵

状态：测试与数据工厂建设中。此文件不表示压力测试已通过。只使用新建隔离 PostgreSQL，真实业务副本由本轮总负责人单独准备；不连接或写现有业务库。

| 边界 | 当前实现 | 验证方式 |

| 数量 | 14 位整数、4 位小数，正需求最小 0.0001 | 请求精度保护及 NUMERIC 账量 |

## 每一步都检查的事实

1. 全树身份使用 `(analysis_id, analysis_item_id, node_key)`，相同 nodeKey 在其他产品/分析不能互相覆盖。
2. 本批 BOM 需求不因下达计划消失；路线/下达/在途不增加合格库存、实领、实收或销售可发量。
3. 供应动作分配合计等于对应需求动作数量；公共超量独立记录，不能加入原来源专属权益。
4. 同仓/货品/颜色的预留有效量与实领量不超对应供给；WAITING 不抢占零散料，实际领齐才能开工。
5. 质检前、拒收、未确认实收数量不增加库存；入库基本量等于单据数量乘冻结换算率。
6. 库存余额与出入库流水净额一致；生产 `iqty`/已产量只认有效实收，分批及反向按精确来源对称处理。
7. 前置委外的已通知量等于原批次减追加冲销；PREP 与 OUTBOUND 共用同一成品实收容量，4/10 划出与反向必须是 6+4，不能出现 10+4。
8. 销售归属只接受真实完成/合格入库事实；重复请求不增加第二份计划、申请、预留、库存或销售数量。

## 小规模逐步链

| 编号 | 场景 | 业务步骤 | 关键负向/守恒 |
|---|---|---|---|
| P01 | 两产品共用自制/采购子件 | 多行销售下单、自审、财务确认、联合分析、逐路线下达、WAITING | 原料总需求准确，父件可先下达；未领料不能开工 |
| P02 | 同一 BOM 在两分析复用 nodeKey | 同产品不同销售来源分别分析；公共料不足；专属到货 | 仅按真实来源拿料，总分配不超库存；兄弟分析不能挪用 |
| P03 | 根与中层有子件委外 | 原树子件先分流；目标件前置自制；质检实收后委外申请/订单/出仓/回厂 | 不重复展开子件，不把未加工目标件当最终合格供给 |
| P04 | 无子件委外 | 申请、下单、财务、出仓、回厂、IQC、实收 | 无多余前置任务，沿独立委外量账闭环 |
| P05 | 采购少到与分批 | 原订单分两次到货、分批 IQC、分批实收 | 剩余量仍属同一在途责任，不重复补采，不提前 READY |
| P06 | 全部/部分不合格 | 到货隔离、拒收、退回、补货、复验、入库 | 未合格量不能入库，退回补货只有一条责任通道 |
| P07 | 超量到货 | 登记超到、财务决定、合格验收、仓库实收 | 未批准超量不进库存；获批公共余量与原分析量分开 |
| P08 | 原料分仓领用 | 同主仓两子仓入库、分仓 DRAW、实发、开工、报工、FQC、实收 | 每张 DRAW 只扣实际仓；部分发料不能开工；反向回原仓 |
| P09 | 委外批次取消/反向 | 前置实收10、订单占4、完整反向订单、通知冲销、前置入库反向 | 未解除下游拒绝；6+4 守恒；原批次和冲销均保留 |
| P10 | 旧取消同步 | 旧申请/行动已取消而通知累计未冲销；显式同步后再次通知 | 无自动改旧账；旧请求不能复活；新通知使用新代际 |
| P11 | 同时下达/重放 | 两连接同分析同键；同版本异键；不同分析抢同一供给 | 同键一份结果；异键冲突或精确串行，不超排/超占 |
| P12 | 输入边界 | 500/501 来源、500/501 路线、10/11 层与环 | 拒绝发生在写入前或整事务回滚，不关触发器、不改期望 |
| P13 | 非零生产成本和正毛利 | 每件 A 消耗 B×2/E×1，输入单价10，10件材料价值300，销售价100/件；分别验证在制、良品、不良、退料/冲销 | 实际库存价值→实发/WIP→产出价值守恒；不得用主档当前成本或全零金额替代历史事实 |

复杂例外复用现有 `FullChainEndToEndTest` 的真实业务步骤与原断言，新增数据工厂只复用其基础建档/身份切换能力；不把测试中的直接写业务终态当成“通过业务流程”。新多产品链另外增加独立逐阶段账表核对。

### 旧测试夹具真实性整改

已发现并移除 `startedSegmentFor` 在缺少执行段时自动把 BOM 的 `hard_gate` 改为 false 的隐式降级。该 helper 现只接受已真实下达的 READY/DISPATCHED 执行段，缺少执行段或物料会明确失败，已有完整车间/负责人也不再被覆盖。

13 个发货、库存、收款和权限测试使用显式 `produceFinishedFromOpeningInputs`：OTHER_IN 记录事先声明的 B×2/E×1 输入 → 兼容手工计划服务 → 实际计划包 → 实际 DRAW 发料 → START → 报工/FQC/成品实收。原业务金额/库存/状态断言保留。这些测试证明各自财务或反向行为，**不能替代**销售财审 → 物料分析 → 路线确认 → 下达车间的新主链验收。无料生产仅保留明确构造的无 BOM 自制/合法 ZERO_MATERIAL 专项（旧 `production_bom_policy` 已由 V423 删除）；不能因为流程走不通而临时改 BOM 门槛。

材料清账原入口缺口已整改：我的车间任务直达精确执行段材料台账，写 post/reverse 在幂等重放前逐需求校验。管理范围遵守 ADR-050，为计划 owner/正式交接/超管或显式 `production_plan:view:all`，再与 settle/reverse/close 各自专用动作求交；手工数据共享只扩大读。仅车间成员不能修改其他车间或关闭整计划。快捷填入补黄底与框内说明，保留已填写损耗/在制且必须人工提交。普通车间入口与能力交集、原车间页及repo共11测试通过，5文件analyze无问题。先前将“全量范围+专用动作”拒绝写的预期源于错误解释，现已按 ADR-050 纠正。修正版 PG 已通过：全量管理人真实post/reverse成功、无动作与手工共享拒绝、scoped worker跨段/混批拒绝、调离后旧key重放拒绝，以及具备close权仍拒绝成品未入库。V501/462，日志 `server/target/production-material-adr050-scope.log`，1例通过；原未清账拒绝close专项仍保留。上述证据不代替完整多角色浏览器 UAT。

## 计量与运行纪律

- 普通正确性与压力计量使用独立 Maven build 目录。压力入口默认关闭，不随全量 Maven 自动运行。
- 大规模计时必须等当前 Maven/Flutter 全量结束，独占运行；同时记录产品数、订单/来源数、BOM行数/深度、历史行数、JVM版本/堆上限、CPU数、PostgreSQL版本和迁移头。
- 每次真实业务服务调用记录方法、成功/拒绝、耗时、JDBC执行次数、批处理逻辑语句数、commit/rollback次数。只存 SQL 指纹和计数，不记录参数、凭证或业务正文。
- JDBC 次数是客户端向 PostgreSQL 发出的执行次数；数据库内部触发器中的语句不会虚报为独立客户端调用。触发器耗时包含在对应 JDBC 请求内。服务执行时延与响应体大小测量的序列化耗时分列，Mock HTTP 已包含真实控制器序列化。
- 服务调用和 Mock HTTP 分开标识。Mock HTTP 包含实际控制器、校验、权限与序列化，但不代表真实网络、JWT登录耗时或浏览器首屏时间。必须保留响应字节数。
- 初始化、历史压载、预热、断言查询不混进请求时延。并发分配的每条线程各自携带身份和测量上下文。
- P50/P95/P99 只在注明样本数时展示；少量 smoke 样本不称为稳定 P95。不能删除失败请求、改数量期望或禁触发器凑通过。
- 既有 SLO 来源为[生产链需求16.4](../07-业务链路/04-生产订单排产与执行全链路需求.md)：50行查询 P95 2秒、100订单/10,000展开节点预览 P95 10秒、20订单确认组无竞争 P95 5秒。没有覆盖的浏览器/目标库条件明确保留为未测。

## 可执行入口

`ProductionChainDataFactory` 只建立主档与通过真实销售自审/财务确认服务的订单，不伪造库存、预留或终态。每产品98个展开节点，含共享多层自制、采购、带子件及叶委外；物理 BOM 为 `13×产品数+86`，深度2。`ProductionMaterialAnalysisScalePostgresTest` 小规模方法覆盖两产品、重复路径跨分析隔离、采购和两类委外通知、两连接同键下达与 WAITING 数量事实；压力方法额外要求 `UTEN_RUN_PRODUCTION_STRESS=true`。

仅在总负责人确认独占计时后，于 `server` 运行：

```powershell
$env:UTEN_RUN_DB_TESTS='true'
$env:UTEN_RUN_PRODUCTION_STRESS='true'
$env:UTEN_PRODUCTION_STRESS_SIZES='100,500'
$env:UTEN_PRODUCTION_STRESS_SAMPLES='5'
$env:UTEN_PRODUCTION_STRESS_HISTORY_ROWS='100000'
mvn -q '-Duten.build.directory=target-production-scale' '-Duten.production.measurements=target/production-scale-measurements.jsonl' '-Dtest=ProductionMaterialAnalysisScalePostgresTest#hundredAndMaximumProductsWithHistoryRecordRealServiceAndMockHttpCosts' test
```

输出为追加式 JSONL：规模记录、真实服务调用及 Mock HTTP 请求各一行；包含失败请求，禁止删除失败样本。初次预览与20行下达每组仅一个样本，不宣称稳定P95；重复刷新/详情记录明确样本数。历史压载参数默认20,000，可显式设100,000或500,000，报告读取实际数据库总数；合成分布不等同真实业务历史，也不证明浏览器切页性能。
