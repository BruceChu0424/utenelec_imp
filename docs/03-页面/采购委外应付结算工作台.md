# 采购/委外应付结算工作台

- 路由：`/finance/payables`
- 基础查看：`ar_ap_ledger:view` + `finance:view:all`
- 付款：`finance_payment:create`
- 超耗责任：`subcontract_loss_claim:view/review/fulfill/reverse`
- 贷项应用：`supplier_open_item_offset:apply/reverse`
- 月结：`supplier_settlement:view/create/confirm/dispute/reverse`

## 页面目标

首屏回答：应付多少、账面已核销多少、实际现金付了多少、抵销多少、还欠多少、何时到期。
采购货款和委外加工费分列；委外自有材料不进入 AP。

## 主工作区

顶部 KPI 使用服务端本币字符串，不在 Flutter 用 `double` 汇总：
供应商流水、明细和年度往来与本页共用事件口径：按业务日展开 AP 立账/红冲、账面付款/反审、
贷项/索赔抵销与反转；外币付款用账面核销本币，不用现金本币误减 AP。


```text
应付 - 账面付款核销 - 已生效抵销 = 未付
实际现金 - 账面付款核销 = 汇兑差额
```
采购/委外订单由财务批准后冻结供应商、币种、汇率、结算方式和行单价；收货/进仓审核锁订单头行，
服务端重算原币、本币和尾差，客户端金额不参与立账。财务已批准超量纳入额度，未批准超量拒绝。


筛选：采购/委外、open/部分/结清/逾期/贷项/未定到期日、关键词、立账日期、到期日期。
表格显示来源类型/单号、供应商、结算方式、原币/本币、现金已付、账面核销、抵销、未付与逾期天数。

选中正 `PAYABLE` 可生成付款单；服务端付款预览与审核再次锁余额。同一供应商贷项/索赔可用
“应用贷项”逐笔选择同供应商、同币种、同开账汇率的正应付；发生日由服务端记账，不能倒填
已确认月结期间。`PREPAYMENT` 仅展示，独立预付款资产/总账链完成前不开放自动应用。

超耗必须能从发料明细取得正数账面成本，否则损耗审核在任何库存、责任单或总账写入前失败关闭。
正常允许损耗留在产出成本；超耗借记委外超耗异常损失、贷记库存资产，供应商赔偿另记索赔应收和
追回收入，不能把赔偿直接净掉材料损失。

## 委外超耗责任

同页切换“委外超耗责任”。列表显示实际/允许/超耗、账面损失、建议/确认索赔和状态；混合单位
只在逐行显示数量。

决定支持每条材料多方案；客户端先校验分配量，服务端按行重新校验并锁版本。现金赔偿必须选择
启用资金账户、到账日、金额和证据；补货/废料返还必须提供已审实物单头及明细 UUID；供应商处
补料走 `compensated_qty` 守恒。加工费折让等待红字发票/贷项，普通委外进仓不能冒充免费补货。

已履约方案使用专用“反转履约”；现金/补料对称反向，补货/废料先红冲实物单。责任决定整体
反转必须在所有履约和抵销已经反向后执行。

## 月结批次

月结以供应商+币种+自然月冻结：期初、本期立账/红冲、账面付款/反审、抵销/反转、期末；保存
逐笔行、哈希、供应商确认、内部确认、争议和反转事件。当前月份未结束不能冻结；到期日由服务端
结算规则计算，前端不编辑。冻结行和金额不可更新/删除。

冻结立即阻断截止日前新业务；未双方确认的批次可先反转再重开，双方确认过的月份永久关闭，争议或
反转也不允许改写旧期，修正进入下一开放期间。确认/反转与供应商写入使用 supplier-first 锁序。
显式 `CASH` 固定在收货/验收业务日到期，供应商 `tday` 不得把现金单改成账期单。当前 AUTO 总账
没有通用跨期反向凭证，跨月红冲在任何子账写入前失败关闭；事件日期按 `Asia/Shanghai` 归属。

## 响应式与状态

- compact：KPI 横向滚动；筛选/详情使用全屏或抽屉；核心列优先。
- medium/expanded：左筛选 + 主表/详情；金额使用等宽数字；状态不只依赖颜色。
- 具备加载、错误重试、空状态、刷新、分页、排序、防连点和顶部通知。

## 明确边界

工作台的业务 AP 不是“已开票应付”。供应商发票、暂估转正式、三/四单匹配、红字税额和价差
仍待独立模块；预付款资产应用、专用免费补货入库也保持失败关闭。依赖质检、发票或对账确认日期的
账期在专用事件处理器完成前保持未定到期日，并阻止月结冻结，不猜日期。源码、空库和 Widget 证据
不等于公司目标库迁移或岗位 UAT，生产继续 NO-GO。
