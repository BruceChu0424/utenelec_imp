## 一、结论（一句话）

**供应商分类 = 老库 `SystemItem` 表中 `ItemclassID = 3` 的 15 个节点（全是扁平根，无嵌套、无孤儿）；供应商主档 = `B_Provider`（386 行、29 字段），通过 `B_Provider.ParentID → SystemItem.ItemID`（ItemclassID=3）把每条供应商挂到分类树的某个根下。**

> ⚠️ `SystemItem` 是万能分类树表，迁移时必须用 `ItemclassID` 过滤（货品=1、客户=2、供应商=3、部门=5、模具=18…）。

## 二、老库表结构

### 2.1 `SystemItem`（ItemclassID=3，供应商/材质分类，15 行）

字段同货品分类（见 [02](02-货品分类-老库溯源.md) §2.1）。ItemclassID=3 的特点：

- **15 个节点全是 `ParentID=0` 的扁平根**（无父子嵌套、无孤儿），与模具分类（ItemclassID=18）形状一致。
- `Number` 有重复：`CL`（表面处理类 / 金属材料类）各一条。
- 一条 `Number` 为空（ItemID 2945「玻璃面板」）。
- `Level` 不可信，迁移按 parent 链重算（这里全是根 → level 0）。

## 三、数据质量风险（迁移已处理）

| 风险 | 数量/说明 | 处理策略（已落地） |
|---|---|---|
| 无未分组 | 386 条全部已分组（无 `ParentID=0`） | `category_id` 无 NULL |
| `Number` 编码重复 | `CL`（表面处理类/金属材料类）两条 | 新库 `code` 不设 UNIQUE，定位用 `id`/`legacy_id` |
| `Number` 为空 | 玻璃面板（ItemID 2945） | `code` 允许空串（NOT NULL 但空串满足） |
| `Level` 不可靠 | 全树 | 迁移按 parent 链重算（全根 → level 0） |
| `SystemItem` 混存多类 | 7 种 ItemclassID | 迁移严格 `WHERE ItemclassID = 3` |
| 文本 GBK 编码 | 老库 `Chinese_PRC_CI_AS` | PowerShell + .NET SqlClient 原生解码 → UTF-8 CSV |
| 描述/地址含管道符 `\|` | 部分行 | `export_legacy.ps1` RFC4180 引号转义 |

## 五、字段映射（SystemItem → supplier_categories / B_Provider → suppliers）

### 5.1 分类（SystemItem ItemclassID=3 → supplier_categories）

| 老库 | 新库 | 转换 |
|---|---|---|
| `ItemID` | `legacy_id` (UNIQUE INT) | 保留，溯源+重跑幂等 |
| `Number` | `code` | 直接映射；不唯一（CL 重复、玻璃面板空） |
| `Name` | `name` | 直接映射 |
| `ParentID`(=0) | `parent_id = NULL` | 15 个全是根 |
| （递归重算） | `level` | 全 0（扁平根） |
| （触发器维护） | `path` | `/code/` |

### 5.2 主档（B_Provider → suppliers）

见 §2.3 表格「新库列」一栏。`category_id` 由 `ParentID` 反查 `supplier_categories.legacy_id` 得到；386 条全部命中。
