# 委外回厂短交判定页

> **2026-09-20 新增（V636 / [ADR-098](../99-决策记录-ADR/ADR-098-委外允许损耗与回厂短交判定.md)）**：仓库登记委外回厂时累计数量少于订货量，系统按订货行开「回厂短交案件」，
> 本页让委外跟单员判定是「分批到货，继续等」还是「接受损耗，结案」，并把每一次的损耗率记进委外商汇总。
> **2026-09-22 追加(ADR-098 §2.8；锁的粒度 2026-09-21 按 ADR-101 §2.5 收到「行」)**：案件待判定期间
> **出案件的那一行**是锁着的——这一行的货先不入库、这一行也不改量，同一张单上其它已经足额到齐的货照常入库，
> 所以本页的判定不是「事后登记」，而是仓库那批货能不能上架的闸门。判定成「分批到货」或「接受损耗」即自动解锁；
> 分批到货过了预计到齐日、且累计回厂仍未进入允许损耗范围时，会重新锁上并回到待判定。订货单详情页有同一口径的锁定横幅，点「去判定」直达本页只看那张单。
> **2026-09-22 [ADR-103](../99-决策记录-ADR/ADR-103-委外两条路线同位锁定与单一子件按到货解锁.md) §2.5**：判定成「分批到货」之后，
> 后续批次把**累计**送进允许损耗范围时，仓库确认入库那一刻同样自动按接受损耗结案(`WAITING_MORE` 案件也结，不再等逾期催人)；
> **2026-09-24 结清口径修订**：接受损耗独立核销履约余量，保留订货数量和来源申请占用，不再通过改量结案，也不生成改量复核；
> 允许损耗范围内正常结清，不通知财务。超出约定损耗仍须委外人工判定，异常损耗财务责任流程保持。
> 仓库点「不再出仓」关掉余量后系统对涉及的订货明细自动重评一次。
> 入库放行闸按**收货单**：一张收货单里任一行待判定整张先不入库，同一订货单的其它收货单不受影响。

## 一、页面与权限

- 路由 `/subcontract/short-deliveries`；`?caseId=` 通知卡片深链(进页直接打开该案件详情)、`?orderId=` 任务中心状态列深链(只看这张订货单)、`?supplierId=` 供应商详情深链(只看这个委外商)。
- 看页面：`subcontract_order:view`；对象级读范围与委外订货单一致(本人负责的订货单，或 `subcontract:view:all`)。
- 判定：`subcontract_short_delivery:decide`(委外管理 / 委外订货，V636 默认授予持 `subcontract_order:submit_finance` 的部门) + 对象级本人订货单；没权限的人能看不能判(操作列显示「无判定权限」)。
- 入口：委外 Hub「回厂短交判定」卡片(徽章 = 待判定案件数)、委外任务中心「进行中」状态列的「回厂短交待判定 / 分批等待中」(点击直达)、通知卡片、供应商详情「委外损耗」段的「短交记录」。

## 二、页面结构

- 分段(UtenFilterToolbar)：`待判定`(红徽章：低于允许下限的待判定 + 分批等待已过预计到齐日) / `容差内待结案`(中性括号：没有约定可依、或自动结案被拦下的行，见下) / `分批等待中`(中性括号) / `历史记录`(时间门控，ADR-066)。任务型页面进页默认落在「待判定」。搜索：订货单号 / 委外商 / 货品 / 收货单号。
- **料没发完不开案件(2026-09-21，[ADR-101](../99-决策记录-ADR/ADR-101-委外单一子层级按到货解锁与容差自动结案.md) §2.5)**：
  委外是先发料后回厂，供应商手上只有我方已经发过去的那部分，回厂少是分批发料的常态，不是短交。
  只有**这一行的料已经全部发给委外商**(含仓库点了「不再出仓」关掉余量)之后才开始判短交；
  前置生产分批备齐时，已发量必须达到完整计划量，不能用「本批已备齐量」替代整笔承诺。
  料是在最后一批货到齐之后才发完的，案件由系统在仓库确认入库那一刻补开。
- **「容差内待结案」这一段现在剩什么(ADR-101 §2.6)**：料已经发完、累计回厂又落在这张单约定的
  允许损耗范围之内的行，**仓库确认入库的那一刻系统已经自动按「接受损耗」结案**——自动开损耗单、
  案件记损耗量与损耗率、保留订货量并核销履约余量，不再挂在这里等人点一次。允许损耗本来就是双方事先
  谈好的「交到这个数就算交完」，不需要再要一次人工确认。所以这一段包括三种行：
  一是累计已达到允许下限、正在等质检与仓库入库的行；
  二是**订货时没填允许损耗**的行，没有事先约定可依，多少算交完只能由人来定；
  三是自动结案时被「发出去的料对不上账」拦下来的行(例如供应商手上还剩没退回来的料)，
  要先按提示补登退料单或损耗单，再由人结案。低于允许下限与严重短交两档一律保持人工判定。
- **分批等待中也会自动结(2026-09-22 ADR-103 §2.5)**：判定成「分批到货」的案件(`WAITING_MORE`)，后续批次让累计回厂
  进入允许损耗范围时，仓库确认入库那一刻按接受损耗结清(损耗单 → 案件 `ACCEPTED_LOSS` 记损耗率 → 独立核销履约余量)，
  后续登记进入「容差内待结案」、入库后进入「历史记录」，不再等预计到齐日逾期再催人点一次；仍低于下限的批次在预计日内可入库、案件留在分批等待。
  以 1000 / 10% 为例：800 → 分批 → 再到 150(累计 950)即自动结案，损耗 50；再到 90(累计 890)不结。
  **2026-09-23 边界修正**：后续登记已达到允许下限时，原预计日即使已经过期，也立即解除旧逾期入库锁和催货提醒，
  案件转入「容差内待结案」中性段等待质检/入库；原 `WAITING_MORE` 状态、决定与日期保留到实际结案，审计不断链。
  入库时仍按实时净回厂量重核：补足批次若在上架前被红冲或退回，不能凭旧容差快照继续放行。
  恰好达到下限同样适用：发 100、允许损耗 5%，回 95 件即可在合格入库后核销 5 件损耗并关单，不再等 5 件。
  **先入库后质检的仓库追货口径(2026-09-24)**：例如发 6000、允许损耗 5%、已登记回厂 5800，
  即使仍待检，仓库预计到货列表也不再催补 200；待检任务继续在品质流程中处理，合格入库后再正式核销损耗。
  预计到货列表、计数和登记默认量共用实时净回厂/全发判断，不按旧 severity 快照隐藏数量。
  红冲或实际退回导致净回厂跌破下限时恢复应到量；已结清案件不重复享受容差，后续反向操作沿原事实链处理。
  **接受损耗始终保留订货数量**：例如订货 2000、实际回厂 1900、核销损耗 100，结清后仍显示这三个独立事实，
  不能把订货量改成 1900，也不能把已占用的申请 100 件重新放回待下单。
  系统自动结清和人工接受损耗都不生成改量复核；允许损耗范围内不通知财务，超耗部分仍按原异常损耗责任流程处理。
- **「不再出仓」触发重评(ADR-103 §2.5)**：料只发了一部分就被仓库关掉余量时，`closePlan` 末尾对涉及的订货明细跑一次与
  入库同款的评估——累计回厂已在容差内的直接自动结案，低于下限的补开案件通知委外，一件都没回厂的行不开案件(没有回厂
  就没有可判的事，留给下一次登记评估)；此前关余量后无人重评，案件永远不开。
- 表格列：订货单号、委外商、货品名称 / 编号 / 颜色(各一列)、原订货量、允许损耗、最少应到、累计回厂、短交量、短交率、程度(严重短交 / 低于允许下限 / 容差内未到齐 / 未设允许损耗)、最近收货单、到货次数、发现时间、(分批段/历史)预计到齐、(历史)核销损耗量 / 损耗率 / 损耗单 / 结案时间、状态、负责人、操作。
- 待判定段：低于允许下限的行整行红底，严重短交置顶并带红色「严重短交」标签；「严重」= 短交率 ≥ max(2 × 允许损耗, 20)%。
- 双击行 = 案件详情弹窗：数字摘要 + 过程记录(仓库登记发现 / 再次到货 / 判定 / 自然到齐 / 作废)，开放案件且有权限时底部给两个判定按钮。

## 三、两种判定

| 判定 | 弹窗 | 服务端做什么 |
| --- | --- | --- |
| 分批到货，继续等 | 预计到齐日期(必填，不早于今天) + 说明(选填) | 案件 → 分批等待中；仓库的预计到货任务本来就开着，什么都不动；到齐自动完成；过了预计到齐日回到「待判定」并每天早上提醒一次(重要通知) |
| 接受损耗，结案 | 列出三件后果；低于允许下限时说明必填 | ① 按发料时冻结的用量把短交折算成材料损耗，自动登记并审核委外损耗单(超出部分仍转 ADR-047 财务责任判定)；② 保留订货数量和来源申请占用，实收如实记录、剩余按损耗核销并结清，不重新下单；③ 案件记损耗量/率并撤回通知卡，不生成改量复核，正常允许损耗不通知财务 |

供应商处剩料多于本次短交折算量(多发的料、允许补料没用完)时，剩料仍需真实退料或损耗事实交代，不能靠修改订货量抹平。累计回厂为 0 的行不能按接受损耗结案(红冲订货单或用受控改量处理)。

## 四、徽章与计数口径

- 页内「待判定」红徽章 = `/subcontract/short-deliveries/count.pending`；委外 Hub 卡片同数展示，不登记进服务端徽章目录的入口(页内数字读汇总事实数 `subcontractShortDelivery.*`, ADR-108)——委外模块红数由任务中心 `/count` 承担(已把有待判定案件的订货单算进去)，同一件事只数一次(准则 14 §四之二)。
- 供应商列表「损耗率(%)」列与详情页「委外损耗」段读 `v_subcontract_supplier_loss_summary`：只算已结清订货行，接受损耗行保留原订货量，加权损耗率 = 累计损耗 / 累计订货。
