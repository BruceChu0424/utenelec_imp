# 云端 Claude 逐项续做指引(额度有限, 一次一个任务)

> 适用: 用户在 claude.ai 网页版(Claude Code 云端会话)里继续第二阶段, 额度约 250 美元, 要求**做完一个任务就停下汇报, 由用户看余额决定是否做下一个**。
> 先读本目录 `01-交接总览.md`(背景、已完成、部署记录), 再读本文件; 做具体任务时读 `03-后续工作流任务书.md` 对应小节和 `02-审计发现全集.md` 里对应的发现 ID(用 ID 搜索, 不要整份读)。
> 状态日期 2026-09-24。

## 一、云端环境和本机不一样的地方(开工前必须知道)

| 事项 | 云端会话的情况 | 怎么办 |
|---|---|---|

| Flutter / Docker | 沙箱里不一定有 | 不要花额度在沙箱里装全套; 前端与真库测试以 CI 为准, 沙箱只做后端编译与定向单测(有 JDK/Maven 时) |

## 二、每个任务的固定流程

1. **开工**: `git pull`; 读本文件第四节该任务的说明, 以及 03 文档对应小节、02 文档对应发现 ID。
2. **查号**: `ls server/src/main/resources/db/migration | sed 's/__.*//' | sort -t V -k2 -n | tail -3` 与 `ls docs/99-决策记录-ADR | tail -3`。当前迁移头 **V693**(仓库负责人, ADR-115), 下一个可用 **V694**; ADR 下一个 **ADR-116**。已执行过的迁移一个字节都不能改。
3. **开分支** `claude/<任务编号>-<key>`, 实现 + 测试 + 文档一起改(页面说明、ADR、迁移说明、实体字典)。新增迁移要同步迁移头五处(见 04 文档第三节: 清库脚本版本对与目录文本、两个清库契约测试、数据迁移 README 头行); 新增表要登记审计三清单、清库表分类、主档引用目录。
4. **推分支并开 PR**, 等 GitHub CI(`quality.yml`): 快道约 6 分钟, 全量真库约 1.5-2 小时。红了就修, 直到全绿。等待期间不要反复轮询, 隔 20 分钟看一次即可。
5. **合并**: CI 全绿后合并进 main(squash 或快进均可)。
6. **汇报并停下**, 固定格式:
   - 做了什么(一句话) / PR 与 CI 链接 / 用户能感知到的变化;
   - 是否含迁移(含迁移就需要本机发版才会到服务器);
   - 下一个任务是什么、第四节的预估花费;
   - 然后**停下等用户说"继续"**, 不要自己开下一个。

## 三、额度规则(省钱优先)

- Claude 看不到账户余额。**由用户在 claude.ai 的设置里看用量/余额**, 再对照第四节预估决定是否继续。建议: 余额 < 下一个任务预估上限 × 1.5 就不开新任务。
- 第一个任务做完后, 用户记下它实际花了多少, 按"实际 ÷ 预估"的比例校准后面所有预估。
- 省额度的做法:
  - 不开多代理并行(Workflow/子代理群), 单个会话直接做;
  - 只读需要的文件, 大文件先 grep 定位行号再读片段;
  - 不在沙箱里装 Flutter 跑全量, 交给 CI;
  - 不做与当前任务无关的"顺手重构"。
- **任务做到一半额度快没了**: 立刻停手, 把当前分支推上去, 在 PR 描述里写清楚"做到第几步、下一步是什么、哪些测试还没过", 再汇报。下次从 PR 接着做。

## 六、发版到公司服务器(只能在本机做)

当前服务器是 **v2.0.1(库 V688)**; main 已到 V693(V689-V693 未发版), 下一版为 **v2.0.2**。步骤(详见 `deploy/simple/RUNBOOK.zh-CN.md` 与 05 文档第七节):

1. 本机 `git pull` 到要发的 main 提交, 确认该提交 CI 全绿。
2. 迁移演练只在本机: `pg_dump` 服务器库 → 本机 docker 恢复 → 用待发布 JAR 起一个实例指向副本库(Flyway 随启动迁移) → 冒烟。**不要在服务器上直接跑 migrator**(它写死连正式库)。
3. `gh workflow run simple-release.yml --ref main -f version=v2.0.2`(没等 CI 跑完可加 `-f allow_running_checks=true`, 但已失败的作业会被门禁拒绝)。
4. 服务器: `sudo uten-imp-updater check` → 把 `/etc/uten-imp/server.env` 的 `UTEN_SERVER_STATUS_APPLICATION_VERSION` 改成新版本 → `sudo uten-imp-updater activate v2.0.2`(自动备份 → 迁移 → 切换 → 健康检查)。
5. 冒烟: 服务器上用自签临时会话跑只读接口检查(做法见 01 文档第四节部署记录), 看 `/version.json` 与状态页。
