# V864 生产调度按实际供给与履约聚合

日期：2026-10-14。

V719 的生产调度根视图沿用 V470 的 `requested_qty - approved_qty` 待排计算，遗漏了已提交计划和 V478 起的 `root_fulfilled_qty`。库存覆盖后无需工单、采购或委外已经合格入库的产品因此仍被记为待排；产品完成数量又只数工单，出现“已完成 8、未完成 0，但仍有待排数量”或无工单采购完成后停在“分析处理中”。

本迁移新增只读视图 `v_production_analysis_workbench_item_progress`，分别给出尚未安排数量和尚未履约数量：

- 尚未安排扣已提交/已审核计划、实际顶层供给交接，以及本来源已落实的精确在途份额。自制行动对应的计划不重复扣除。
- 尚未履约只扣实际顶层供给交接、来源专属实收入库，以及自制子件原需求已经获得的正式现货覆盖。来源实收沿用 V694/V722 与备料预算的口径：已审核 `FINISHED_IN` 非公共实收基本量，按每计划私有预算封顶，再以冻结换算率转回来源单位；公共计划产出与实际超产不冒充来源履约，冲回按实收来源重新计算。仅下单、到货未验收、公共现货模拟分配或未认领公共在途均不算完成。
- 已有 `MAKE_COMPONENT` 锚点的库存覆盖读取父物料的合格精确权益及正式生产物料预留，保留正式投入后已履约事实；排除本锚点自己的产出权益，避免与计划 `iqty` 重复计入。无须生产的足库存 BOM 组件不会被新建为待排子件。
- 调度根视图、`fn_material_analysis_fulfillment_status` 和 API 产品完成数量共用这些来源事实。产品按货品/颜色/单位聚合；实际缺口、追加、权益释放或冲回会重新显示未完成。
- 全部实际履约后退出“进行中”；计划尚未自动关闭但已全量实收，不保留空待办。采购/委外在途仍显示备料中，部分下达后的真实未安排量仍显示部分已排。

仅新增/更新投影和函数定义，不改历史分析行、计划、报工、收货、预留、权益或库存流水，不改已应用迁移。没有新增业务表、列或索引，因此不增加业务数据重置 table 分类；视图随既有表事实清空，无须独立重置。

验证覆盖：八个生产产品完成加一个库存覆盖产品；无工单采购/委外在途、实际履约、单据完成但未履约和履约冲回；部分供应与提交计划的真实缺口；既有自制子件的模拟分配与正式现货覆盖、实收、投入和释放；同一正式预留混合自产精确份额与公共现货；专属公共自制在途认领与取消；公共 2 先入库、私有 4 后入库及冲回，冻结换算率 2 下不重复履约；API 按产品身份聚合且无工单供给可完成。另以真实业务链核对足库存 BOM 组件下达时不生成重复子件工单。测试数据库均为隔离 Testcontainers，本地验证不代表已部署或已修改业务库。
