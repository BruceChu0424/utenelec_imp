# B0：前端数据加载解耦与响应性

日期：2026-10-23。承接旧数据长期运行方案复核；用户随后授权分阶段实施，第一阶段优先消除加载与大数据处理导致的页面卡顿。遵循 `frontend-design`，复用现有 Uten 控件、主题与业务身份，不重做视觉。

**当前状态：B0 已完成，已合入本地 main 工作树，安装后源码检查通过。** 最终 stage17 的物料六切换最大帧 193.9ms、千行表 89.5ms、搜索滚动 84.699ms，均 0 次 ≥200ms；真实销售/财务千行准备最大帧 22.6ms。原始失败全部保留，不把后续定向通过改写成早先整批全绿。本任务没有导入或修改业务数据库；测试明细均为内存合成模型，草稿存储只使用并清理隔离测试命名空间。安装及安装后检查以文末回执为准，不提交、不推送、不进入 B1。

## 验收口径

网络等待、解析、业务投影、Widget 构建/布局、附件与 PDF 是不同阶段。`async`、`Future.microtask` 或多一个 spinner 均不能证明计算离开了 UI 线程。

- 原生平台：大 JSON 使用 isolate；`UtenPrintPreview` 公共 PDF 的完整布局与保存均在可终止 isolate 中。
- Web：大 JSON 与公共打印 PDF 使用同源 Worker；需要 Dart 对象的物化与其他不能移交的纯展示工作按实际耗时切片，让出真实事件循环。
- 查询只允许当前身份、权限、服务器和请求代次发布。取消读取不表示业务写入没有发生，禁止自动重放已发送命令。
- 后端等待时局部显示进度，保留可用内容与独立输入、导航；数据尚未准备完毕不能发布半份统计或启用错误的业务操作。
- 性能记录包含数据规模、构建标识、帧间隔与构建/光栅阶段。200ms 是本轮排除明显冻结的底线，不能当成流畅目标。目标是普通操作及时反馈、长计算不连续占用主线程、旧结果不覆盖新结果。

## 本包实现范围

| 共享链路 | 实施内容 | 保护的语义 |
|---|---|---|
| API JSON | 大响应原生 isolate / Web Worker；Web 物化按耗时切片；取消向物化传播 | Unicode、空值、精确数字字符串、非 JSON/stream/bytes、自定义 decoder |
| 分页仓库与报表 | 46 仓库的 76 个通用分页解析入口；10 报表文件的 11 个读取入口；服务器 totals/facets 保持原值 | 分页、总计、精确金额、服务端权威统计 |
| 读取归属 | 单调 epoch 围栏覆盖账号、权限和服务器切换及 A→B→A；旧 data/error/loading 均不回写 | 不显示旧身份数据，不清除新请求等待状态 |
| 物料分析 | 模型、共享仓库维度、展示投影、展开和模式切换切片；按精确 UUID 复用索引；只发布完整投影 | 原始来源、操作组与物理行身份、数量、路线、草稿、并发数量变化 |
| 树结构 | 共享 subtree 计算由逐行前扫改深度栈；缓存可见投影与排序 | 断层深度、祖先续线、折叠、顺序 |
| 公共表格 | 显示/筛选/排序缓存，排序键每行提取一次；Master 列宽按实际 2ms 预算逐格推进；EditableGrid 首帧仅标题与地板，原 200 行样本按 2ms / 最多 32 格逐帧完整量宽 | 用户列宽、原有采样尾部内容、字号变化、筛选与选中 |
| 大单据编辑表 | 大表按祖先真实滚动位置与测量高度挂载；保留焦点、IME、最近交互锚点及原生文本选区；业务校验先展开并挂载错误行再定位 | 完整行模型、原始输入、总计、草稿、跨行复制、业务选中与提交数量 |
| 真实明细行准备 | 销售与财务 6 条加载/恢复/引入路径按 4ms 预算创建及初始化临时控制器，全部完成后只发布一次；过期或失败按独立预算清理未发布行，包含初始化失败的最后一行 | sticky 身份、独立初始化代次、行修订、新输入快照、原文、金额、选中与未知提交 |
| 仓库批量预读 | 4-worker 有界读取，稳定顺序；过期/失败停止新增读取；按收货单一次分组草稿 | 提交事务、未知提交状态、仓库及来源规则 |
| 采购价格分析 | 300ms 防抖后才创建完整快照；捕获切片；旧证据立即失效 | 精确数量/价格/汇率、原有请求分批与权限 |
| 附件预览 | 原生大文件后台解析；Web 文本/CSV/ZIP 真切片；有限展示但保留真实总数 | 多字节边界、带换行引号 CSV、GB18030、ZIP64、原件字节 |
| 草稿与大附件 | 输入当下只冻结容器和不可变字节句柄；后台编解码；保存、恢复和原文件指纹核验让出界面线程 | 未完成文本、原始字节、串行写入、未知提交、每条原文 CAS 与历史版本 |
| 本机草稿存储 | 原生 JSON/UTF8 与不可变历史校验响应式执行；IndexedDB 在事务外准备、事务内比较原文并原子写入；迁移竞争有界重试 | 原有锁、日志恢复、reset 归属、历史原文与没有半份升级 |
| 公共打印预览 | 屏幕纸页懒挂载；PDF 完整生成移出 UI；取消/权限变化终止 Worker/isolate；已编译 Worker 随资产发布 | 全文复制、自然纸张分页、标题、原文、字体与数量字符串 |

公共入口调用审计：`lib/features/**/pages/*.dart` 共 234 个页面文件（不是独立路由数），15 类工作流；MasterDataTableView 在 180 个 features 文件中引用、EditableGrid 47 个。方法为共享入口深查与代表页面验证，**这些数字不能写成全部页面逐一完成 UI 或性能验收**。

大表挂载与数据分页分别处理。Master 的本地窗口要求稳定且唯一的行身份、主虚拟列表，并且没有服务器自动追加分页或行拖拽；只有内容高于视口时才需要窗口。中等规模编辑表和服务器分页表同样受新行挂载预算保护，不用 200 行阈值把相同卡顿遗留给较短表格。服务器追加分页与行拖拽保留原构建器、滚动位置和身份映射，仅延后真实业务子树的首次挂载。窗口沿用原 `ScrollPosition`，不叠加第二个纵向滚动容器。编辑表的全部控制器和数据仍由业务层保存，窗口只管理 Widget。100% / 200% 文本缩放、变高行、末端定位、真实选择复制、弹窗及焦点变更均有回归。

最终每个真实帧，全局最多准入 **1 个**新行 Element 子树（多个表格合计）。启用分批挂载的新窗口/新 shell 先完成一帧轻量壳布局，再开始真实业务行挂载，避免 header/platform 冷布局与首次输入控件叠在同帧；已有行 State 不重挂，非延迟小表与 `deferNewMounts=false` 保持原语义。曾使用的 2/1 自适应方案保留在历史记录，最终不再因上一轻行恢复到 2 行。纯计算仍按原 4ms 预算让出真实事件循环，量宽按 2ms；单个原生输入子树无法被强行切开，不承诺其布局总小于 4ms。占位不可输入/选择，独立搜索和导航可用。`isMounting` / `settled` 包含真实业务行布局、测高和锚点校正；不能以壳完成代替就绪。隐藏/离页结束等待并停止继续排帧。

草稿比较不再反复 JSON 编码大附件。同步输入检查保留不可变字符串/字节句柄，异步保存解析完整快照后才交给原串行 writer。恢复附件时同时检查身份与控制器变更代次，不能覆盖等待期间的新文件；恢复遮罩也需阻止旧输入焦点继续编辑。文件来源及上传回执的 SHA256 保留原算法和全部字节核验，分块执行，不能因性能优化跳过证明。

读取围栏覆盖通用分页控制器的已接入列表族、报表读取、物料分析及汇总单、库存/仓库洞察、货架标签、FQC 和称重取样等实际核查入口。仓库解析入口数不等于全部消费者逐个验收；独立 `pw.MultiPage` 打印路径（例如生产备料汇总单、执行卡、采购和报销专用打印）未因公共 Worker 自动完成后台化，需另按各自结构复核，不能宣称全部 PDF 已迁移。

首错定位覆盖销售、采购、外协、财务、生产计划、生产日报、开工确认、车间领料、退料/结算、仓库到货/入库等使用同类编辑表的入口。不得通过截掉模型、只验证已挂载行或只提交可见行取得性能改善。

## 可复现验证

正式本地工具：`tool/b0_responsiveness_harness.dart`、`tool/serve_b0_harness.py`。仅合成数据，不连接业务数据库；假 API 拒绝非 GET。真实物料页面用 500 产品 / 2,000 物料及固定两秒延迟。PDF 用 2,800 行；CSV 用 100,000 数据行和一个标题行；JSON 用约 3.9MB / 30,000 行。

```powershell
$env:CI='true'
$env:DART_SUPPRESS_ANALYTICS='true'
$env:PUB_HOSTED_URL='https://pub.dev'
flutter build web --profile --no-pub --no-web-resources-cdn --no-wasm-dry-run --dart-define=B0_BUILD_ID=<reviewed-build> -t tool/b0_responsiveness_harness.dart
python tool/serve_b0_harness.py --root build/web --evidence-dir <outside-git-evidence> --port 53871
```

浏览器打开 `http://127.0.0.1:53871/?auto=material&run=<run-id>`，也可选择 `grid`、`material-actions`、`json`、`pdf`、`csv`。大附件草稿及 IndexedDB 检查使用本轮已构建 harness 的对应入口，具体构建与 run 标识随最终证据清单记录。`view=grid` 提供手工输入入口。自动物料场景调用真实模式控件回调，记录六次切换；搜索场景等待真实防抖及投影完成标记，再校验高亮文本、空结果并快速跨区滚动。不把这些回调描述为真实指针输入延迟。采样期间不要读取 accessibility tree、截图或运行构建/测试；另做实际输入验证。记录视口、DPR、文本缩放和实际表体高度。结果写到本地证据目录，不提交业务数据或机器临时日志。

PDF Worker 的可重现生成和源哈希检查见 [PDF_WORKER.md](../../../tool/PDF_WORKER.md)。修改对应输入后必须更新资产和 receipt；`flutter run/build` 无需用户手工执行预处理。
