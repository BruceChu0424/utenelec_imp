# V617 报销凭证核验与财务设置

迁移：[V617__expense_claim_evidence_and_settings.sql](../../server/src/main/resources/db/migration/V617__expense_claim_evidence_and_settings.sql)。
决策：[ADR-094](../99-决策记录-ADR/ADR-094-报销链路完整化.md)；操作：[员工报销 SOP](../07-业务链路/员工报销全链路-SOP.md)。
本页描述源码候选与前向迁移，不表示目标数据库已安装。

## 数据变更

1. `expense_claim_invoices` 增加购买方税号 `buyer_tax_no`、人工核验依据 `verification_remark`、核验时间 `verified_at`、人员 UUID `verified_by` 和姓名 `verified_by_name`。
2. 把旧 `VERIFIED_MANUAL` 转为 `AMOUNTS_MATCH`。V608 旧值曾由金额计算产生，没有独立人工核验事实，不能补造历史核验人员。迁移不回退已付款单状态，也不重复过账。
3. 新 CHECK 区分 `UNCHECKED / AMOUNTS_MATCH / MISMATCH / VERIFIED_MANUAL`；人工通过必须同时有核验人员、时间和非空依据。算术一致不能自动写成人工通过。
4. 普通发票继续使用20位无代码或8位加10/12位代码规则；`OTHER` 使用1至60位字母、数字、斜杠或连字符号码，必须填写开具单位，代码可空或1至20位同类字符。不得为了登记财政票据等非发票凭证编造增值税发票号码。
   标准增值税号码形状统一按代码与号码查重，即使改选OTHER也不能绕过；其他OTHER自编号按规范化开具单位、代码与号码，避免不同单位自编号互相误冲突。
   身份约束以 `NOT VALID` 加入，保留可能缺开具单位的历史OTHER记录，后续新写/更新仍受约束；不伪造历史开具方。历史缺字段须先人工补正，再考虑验证全部存量。
5. 新增单行 `expense_claim_settings`，主键固定为1，保存公司抬头、税号、提交说明、是否必须登记票据、版本及审计字段。`require_invoice` 默认 false，表示允许有附件和依据的未登记票据申请进入审核，不是免除法定凭证要求。
6. 注册 `expense:settings` 业务配置权限并关联 `hr.expense` 权限面，不默认扩大所有财务人员的配置权。修改由服务端鉴权并使用 `version` 防止覆盖。
7. 配置表启用审计触发器并列入业务清空 `PRESERVE`，报销单、明细、发票与事件仍为 `CLEAR`。运维脚本和清库契约与数据库策略同步，禁止只改一处。
   审计解释器为凭证、流转事件和报销设置表提供中文名称，便于财务追踪修改。

## 应用行为配套

- `GET /api/expense-claims/settings` 向报销相关岗位提供只读公司资料和制度提示；`PUT` 仅 `expense:settings` 可维护。
- `/history` 与 `facets?queue=history` 增加已处理查询：当前批准/驳回人员可查自己处理记录，付款权限可查PAID；不扩大到其他员工私有草稿。
- 报销 DTO 返回 `version`；修改、提交、撤回、审核、付款及票据维护携带预期版本。过期请求拒绝，用户刷新后重新核对。
- 人工核验使用 `POST /api/expense-claims/{id}/invoices/{invoiceId}/verify`，提交 `expectedVersion`、`result` 和 `remark`。结果为 `VERIFIED_MANUAL` 或 `MISMATCH`；需 `expense:approve`、`attachment:view`、`attachment:download` 且非申请人才可执行，批准同样要求原件访问权限。
- 提交前校验费用日期与用途、扫描通过附件、已登记票据关联及开票日期；未登记票据时按设置和说明规则校验。批准前所有登记票据须人工核验通过。
- 申请、核验、审核、付款保持可追溯，修改业务或票据后重新核验。付款继续沿原 `finance_expense_id` 关联且幂等。
- 付款证明复用附件表的新owner `EXPENSE_PAYMENT_PROOF`，不是新业务表；APPROVED由符合回避的出纳维护，PAID冻结。付款前至少一份CLEAN回单或现金签收凭据，原申请凭证不解冻。
- 公司抬头当前为实时设置，未增加单据级公司资料快照。打印只能称为公司内部展示件，归档版本另由财务留存。
