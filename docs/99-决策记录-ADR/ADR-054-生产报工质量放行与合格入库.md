# ADR-054：生产报工质量放行与合格入库

- 日期：2026-08-28
- 状态：已决策并形成 V409–V415 全链源码候选；V418 前向补齐仓库整单零实收后的同源重新交付余量。后端、Flutter、V329→V338→V418 谱系及 V1→V419 空库 PostgreSQL 已验证；目标库迁移和真实岗位 UAT 尚未完成
- 相关：ADR-029、ADR-033、ADR-046、V156、V157、V249、V337、V338、V409–V415、V418
- 版本边界：生产核心迁移为 V409–V415，后置仓库拒收修复为 V418；当前共享全局目录为 V419/381。V416/V417 属财务，V419 属仓库到货创建幂等，不改变本 ADR 的质量数量权威

## 一、问题

ADR-046/V338 已经把“主管审核报工”和“仓库实际点收入库”拆成两层，但本 ADR 决策前的代码仍会在日报审核后直接按日报 `qty` 生成等量 `FINISHED_IN` 草稿。当时系统因此只能证明：

1. 车间/主管申报了多少；
2. 仓库最终实收了多少；

它不能证明实收数量经过生产末检（FQC），也不能分开记录合格、不合格、返工、报废和拒收处置。若仓库直接点收，未经质量放行的半成品/成品会进入库存、`iqty` 和父 MAKE 就绪链。

## 二、决策

### 2.1 权威顺序

```text
采购/委外收货 → IQC PASS → 合格库存进入目标仓并刷新物料分析
  → 计划草稿审批下达 → CONFIRMED 执行包/执行段 + reservation + DRAW
  → 仓库真实发料 → 派工/开工 → IN_PROGRESS 执行段
  → 生产日报提交/主管审核（只增加 fqty）
  → 每条日报明细显式登记一条 FQC PENDING
  → 品质按 inspection UUID 作 PASS / PARTIAL / FAIL
      ├─ PASS 数量 → 追加质量放行事件，可请求 FINISHED_IN
      └─ FAIL 数量 → 回退有效贡献并生成恢复授权
           ├─ REWORK：复用原在制，补报后重新 FQC
           └─ SCRAP / REJECT：按冻结 BOM 重新齐套、真实 DRAW 实发后补报并重新 FQC
  → FINISHED_IN 生成器在同一事务把库存行登记到 FQC release ledger
  → 仓库按 V338 逐行点收
  → 只有仓库实收增加库存和 iqty
  → MAKE 父需求只读取该合格入库事实
```

采购/委外的在途、待检和 IQC FAIL 不能冒充立即可用库存；`READY`/齐套 100% 只表示可以继续派工、发料和开工，不表示已生产完成。FQC PASS 不直接写 `fqty`；FAIL/PARTIAL 的 `fail_qty` 通过 append-only contribution adjustment 同事务回退当前有效 `fqty` 与精确销售 produced 投影，原日报 gross 永不改。FQC 始终不写库存或 `iqty`，父 MAKE 只读取最终合格入库；通知和 Outbox 也不是质量或库存事实。生产完成率统一为 `iqty / 计划量`：计划 10,000、仓库累计实收 1,000 即 10%，不得用 `fqty`、FQC PASS 或 FINISHED_IN 草稿替代。

### 2.2 一条日报明细一个待检事实

`production_fqc_inspections.source_report_item_id` 唯一。创建时冻结：

- 日报头/明细 UUID；
- 计划行、执行段和销售分摊 UUID；
- 目标仓、货品、颜色、单位、换算率；
- 日报申报数量和日报制单人。

登记只接受：日报已审核、未删除、带目标仓；日报行精确关联 `IN_PROGRESS` 执行段；执行段属于有效 `CONFIRMED` 计划包；身份和数量维度完全一致。登记后身份不可修改或删除。

### 2.3 决定与数量守恒

品质决定写 `production_fqc_decision_events`，只追加、不更新、不删除：

| 决定 | 数量形状 | 不合格处置 |
|---|---|---|
| `PASS` | `pass_qty > 0`、`fail_qty = 0` | 无 |
| `FAIL` | `pass_qty = 0`、`fail_qty > 0` | `REWORK/SCRAP/REJECT` 必填 |
| `PARTIAL` | `pass_qty > 0`、`fail_qty > 0` | `REWORK/SCRAP/REJECT` 必填 |

`PARTIAL` 表示一次抽检决定同时含合格和不合格数量；若只放行剩余量中的一部分，仍可使用 `PASS` 并填写本次数量，inspection 投影自然为 `PARTIAL`。

必须始终满足：

```text
0 <= Σpass_qty + Σfail_qty <= reported_qty
remaining_qty = reported_qty - Σpass_qty - Σfail_qty

PENDING  : resolved = 0
PARTIAL  : 0 < resolved < reported_qty
RESOLVED : resolved = reported_qty
```

同一 inspection 的决定先锁 inspection 行再累计，避免两个品质人员并发超量。品质决定与日报红冲统一为 `inspection → execution segment → plan item → sales order/header → plan link` 的行锁顺序；红冲在锁日报头后按 inspection UUID 排序预锁，避免 decide/reverse 形成环。同一幂等键、相同请求哈希返回原决定；同键不同请求返回冲突。

### 2.4 PASS 到 FINISHED_IN 的显式桥

V410 不让质量服务直接创建库存单。`ProductionQualityInspectionPort.allocateReleasedQuantity(...)` 由真正的 FINISHED_IN 生成器在同一事务调用：

1. 锁定 inspection；
2. 校验库存行是草稿 `FINISHED_IN`，并精确引用同一日报头/行、计划行、执行段、销售分摊和货品维度；
3. 按决定时间从尚未使用的 PASS lot 分配数量；
4. 写 append-only `production_fqc_release_commands/allocations`；
5. 分配不足则整个 FINISHED_IN 创建事务回滚。

约束为：

```text
每条 release command 的 allocation 合计 = requested_qty
每个 PASS decision 的累计 release allocation <= pass_qty
FAIL/PARTIAL 中的 fail_qty 永远没有可消费 release lot
```

V338 后续短收生成的 residual 草稿、已点收红冲生成的 replacement 草稿，继承原始 FQC 放行来源，不重复消费 PASS；V410 的 release command 只绑定首次生成的 `FINISHED_IN` 草稿行。仓库的申报/实收/余量和专用红冲仍由 V338 守恒。

### 2.5 历史兼容

V410 **不回填**任何历史已审核日报，不根据既有 `fqty`、`iqty`、FINISHED_IN、货号、单号或同数量伪造 FQC：

- `ProductionQualityInspectionPort.managesReportItem(...) = true` 才表示该日报行进入新 FQC 链；
- V414 迁移切点把当时已存在且没有 inspection 的日报行登记到只读 `production_fqc_legacy_exemptions`；此后缺 inspection 且无该精确日报行豁免 UUID 的请求一律失败关闭；
- 历史豁免只表示允许按 ADR-046 的 legacy 事实继续处理，不表示“FQC 已通过”，也没有运行时新增豁免入口；
- 接线启用后，新审批日报必须先 `registerApprovedReport`，并停止原“审核即直接生成 FINISHED_IN”路径；
- 历史数据治理若需补证，只能另建人工核验/迁移 ADR，不能修改 V410 或批量猜测 PASS。

## 三、权限与对象范围

新增：

- `production_quality_inspection:view`：品质任务池可看全部；生产人员只能按既有 `production_plan` owner/data-scope 看与自己日报有关的质量结果；不可达 UUID 返回 404。
- `production_quality_inspection:approve`：品质决定动作；默认只授 `DEPT_QA`。

即使账号持 `approve`，运行时仍必须位于有效 `DEPT_QA` 组织树；离职、访客、未绑定员工或其它部门失败关闭。超级管理员只保留恢复路径。V410 没有员工到实验室/检验线的更细主档，因此不能宣称已实现检验线级对象范围。

## 四、Outbox 与已完成接线

FQC 事务写三个幂等事件：

- `PRODUCTION_FQC_PENDING`：某张已审日报的待检行已登记；
- `PRODUCTION_FQC_RELEASED`：一个决定产生正数 PASS，可由入库生成器消费；
- `PRODUCTION_FQC_RESOLVED`：该 inspection 的全部申报量已有质量结论。

当前源码候选已经完成：

1. `ProductionDailyReportService.approve` 在日报状态落为审核后调用 `registerApprovedReport(reportId)`；新 UI 只允许选择 `IN_PROGRESS` 精确执行段。
2. 新执行段报工不再“审核即入库”；仅无执行段的历史计划行走明确隔离的 legacy 兼容服务，且不会显示或伪造 FQC。
3. PASS/PARTIAL 的正数 `pass_qty` 由同步应用端口在同一事务创建一张精确 FINISHED_IN 草稿，并立即调用 `allocateReleasedQuantity`；失败整事务回滚。
4. `StockDocService.confirmFinishedInbound` 在库存/`iqty` 写入前，强制沿首次入库行、V338 短收余量或专用红冲 replacement 谱系找到足额 PASS release。
5. V338 点收、短收、拒收和专用红冲保持原职责；计划 10、首轮实收 1 已验证为 `iqty=1`（10%），余量 4 可继续点收且不重复消费 PASS。
   V418 将整单零实收定义为“保留 REJECTED 决定 + 全量同源 residual FINISHED_IN”：不入库存、不增 `iqty`、不改写 FQC PASS，但仓库仍有一张可恢复的重新交付待点收单；同一确认幂等重放不重复建单。
6. V412 以 append-only cancellation event 处理来源报工红冲；活动 FINISHED_IN 未反向前禁止取消，取消后禁止再放行。V413 前向修复 V410 延迟守恒函数的 PL/pgSQL 同名变量歧义，不修改 V410 字节。
7. 品质任务中心已提供 IQC/FQC 双入口、待办角标、PASS/PARTIAL/FAIL 表单；仓库首页以真实 FINISHED_IN 草稿提供可恢复待点收队列，通知不是事实源。
8. V414 把 FAIL 从当前有效贡献扣回并生成 append-only recovery authorization；REWORK replacement 重新报工、重新 FQC，全量 FAIL 的零有效贡献仍可完整红冲。
9. V415 为 SCRAP/REJECT 建立独立补产物料 cycle：按当前冻结 BOM 和 authorization 数量生成 exact demand、库存 reservation 和单一 DRAW；只有仓库真实 issue、全部需求 `FULFILLED` 后追加 READY，才允许 replacement 报工。

## 五、验收与 NO-GO

最低自动化和岗位验收必须覆盖：

- 一条日报明细只生成一个 inspection，重放不重复；
- 非审核日报、非 IN_PROGRESS 执行段、缺 UUID 或维度不一致拒绝；
- PASS、分次数 PASS、混合 PARTIAL、全 FAIL；
- FAIL 缺原因/处置码拒绝；
- 同键同请求重放、同键异请求冲突；
- 两个并发决定不能超过 `reported_qty`；
- PASS release FIFO 分配、多 FINISHED_IN 分批、超 PASS 回滚；
- FAIL/REWORK/SCRAP/REJECT 在 replacement 再检 PASS 且仓库实收前无库存、无 `iqty`、无父 MAKE 唤醒；
- 计划 10、报工 10、FAIL 1 后 `fqty=9`；REWORK 补报 1、再检 PASS 后恢复 `fqty=10`，二次全 FAIL/红冲不重复扣量；
- SCRAP/REJECT 缺料为持久 `BLOCKED` gap；未全量 reservation、未真实 DRAW issue 或任一 demand 未 `FULFILLED` 时禁止补报；
- V338/V418 全收、短收、整单拒收后同源重新交付、专用红冲保持数量守恒；
- 品质任务池、生产 owner 范围、无权 UUID 404、非 QA approve 403；
- 迁移空库、非空克隆、历史零回填、审计触发器、Outbox 重放。

主源码和测试源码编译通过。最终稳定工作树完整 Maven 2,511 项为 0 failure/0 error（338 项环境门禁跳过，关键数据库类另行显式执行），完整 Flutter 1,137/1,137。专项组合契约 73/73；`ProductionFinishedInWarehouseConfirmationPostgresTest` 8/8 覆盖 V338/V418 点收重交谱系，空库 2/2 应用全部 381 个迁移到 V419，部分 IQC 正式供给/反向 4/4、V419 到货命令账 1/1，PostgreSQL 合计 15/15、无跳过；Flutter 生产执行/待点收/丢响应重试聚焦 26/26。以上仍不代表公司目标库或现场实物验收。

以下任一未完成均为生产 **NO-GO**：目标非空库迁移与历史核对、真实车间/品质/仓库多岗位 UAT、备份恢复、签名构建和部署回读。

## 六、V414–V415：失败贡献回退、返工再检、补料与显式历史切点

V410–V413 后置审查确认两个 P0：无 inspection 以“可能是历史”为由直接放行属于开放式绕检；FQC 失败数量虽然不入库，却仍占用 `fqty`、销售报工分摊和执行段报工上限，导致部分失败后原段永久无法补足。

V414 采用以下前向策略：

1. 迁移时把切点前已经存在、但没有 inspection 的日报明细写入只读 `production_fqc_legacy_exemptions`。运行时没有新增豁免入口；切点后同时缺 inspection 和 exemption 必须失败关闭。
2. 每个 FQC `fail_qty` 同事务追加 `production_fqc_contribution_adjustments`，从当前 `production_plan_items.fqty` 与精确 `plan_order_item_links.produced_qty` 投影扣回，但原日报行和 FQC 决定永久不改。
3. 同一 fail decision 生成唯一 `production_fqc_recovery_authorizations`。后续 replacement 报工必须携带 `fqcRecoveryAuthorizationId`，审批时追加 ALLOCATE 事件；再次 FQC PASS 后恢复有效贡献并入库，若再次 FAIL 则递归产生下一 recovery lot。
4. 来源/replacement 报告红冲按 `declared_qty - contribution_adjustments` 回退有效贡献；全量 FAIL 的零有效贡献是合法反向。红冲追加 RELEASE、取消其派生 child authorization，再取消 inspection；已分配 child 未自下而上反向时整笔红冲失败关闭。
5. `REWORK` 表示原在制实物返工，可复用原执行段并重新 FQC，不自动追加主料。它只能消费对应 authorization 的开放量，不能占用普通执行段额度。
6. `SCRAP/REJECT` 不得直接补报。系统先建 `production_fqc_replenishment_tasks`；计划员创建 recovery-only 物料分析并确认物料方案。普通物料分析 notify/generate 明确拒绝这类工作区，防止同一 authorization 同时生成顶层普通计划和补产 demand。
7. V415 以 `production_fqc_replenishment_cycles` 冻结 `authorization → analysis/item → 原 package/plan/plan item/segment → 当前 BOM fingerprint`，按授权成品数量生成 `EXACT_SNAPSHOT` demand；这些 demand 的 `execution_segment_id=NULL`，但携带 cycle、authorization 和原计划行 UUID，不篡改已开工原段的首次齐套事实。
8. 计划员确认时复用库存分配器：足额则创建 reservation 和一张精确 DRAW；不足则追加 `BLOCKED` attempt/gap，新幂等键只补差。BUY 缺口须先补采购，MAKE/SUBCONTRACT 缺口须先通过独立上游流程形成合格库存；V415 不自动伪造子计划、采购单或委外单。
9. DRAW 草稿/审核不等于可补报。只有仓库真实 issue 后，全部 recovery demand 为 `FULFILLED` 且 DRAW 达到已审/已实发状态，数据库才追加 READY。READY 前服务和数据库都拒绝 SCRAP/REJECT recovery ALLOCATE；READY 后 replacement 仍须再次 FQC，只有 PASS 才能形成 FINISHED_IN。
10. 反向从下游向上：活动 replacement report 会阻断 READY 反向；无使用事实时 DRAW issue 反向会撤 READY。来源 authorization 取消先释放未领 reservation、反向未发 DRAW；已经实发则必须先反出库/退料，禁止把在途实物静默取消。

报工来源 DTO 新增：`fqcRecoveryAuthorizationId`、`fqcRecoveryDispositionCode`、`fqcRecoveryAvailableQty`、`fqcSourceInspectionId`、`fqcSourceReportItemId`、`fqcSourceReportNo`、`fqcRecoveryRequiresMaterial`。普通 gross 尚未达到执行段计划量时先显示普通剩余；普通量报满后再显示 recovery lot。REWORK 最大报工量取开放 lot；SCRAP/REJECT 在 READY 前 `requiresMaterial=true/maxReportQty=0`，READY 后才按授权开放量报工。
