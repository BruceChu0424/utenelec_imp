# ADR-008：后端代码结构重构（死代码清理 + 包结构 + 大文件拆分 + 行为修复）

> 日期：2026-07-23 · 状态：已实施（javac 21 + Lombok 全量编译零错误；运行时行为待冒烟验证）
> 审计存根：[server/server-audit-report.md](../../server/server-audit-report.md)（136 文件逐行审计，重构前快照）

## 背景

后端随 Phase 2/访客系统/权限管理快速生长到 136 个文件，出现明显腐化：camelCase 包名（`profileChange`）、`rbac` 包混入三种职责、五个 250–590 行的大 Service、约 30 处死代码、大量复制粘贴的私有工具方法。全面审计（报告存根：`server-audit-report.md`，136 文件逐行通读）后按风险分三波重构。

## 决策与执行

### Wave 1 · A 级（安全机械操作）

- **删除死代码约 30 处**：无调用的私有方法/构造器/Repository 派生方法/死枚举值（`ErrorCode.QR_*` 与 `VisitorVerifyResponse.reason` 双轨，保留后者）/ `@EnableScheduling`（无 `@Scheduled`）等，逐条删前 grep 复核。
- **抽公共件**：`HashUtil`（sha256，**保留原 Base64 语义**——改 hex 会使在途刷新令牌/验证码全部失效）、`Strings`（isBlank/maskPhone/last4）、`Pageables`（分页构造）、`AdminGrantGuard`（「仅 admin 可授 admin 角色」，原复制 3 份）。
- **包名规范**：`features.profileChange` → `features.profilechange`。
- **配置去重**：CORS 默认值三处归一到 `SecurityProperties`；dev/prod yml 清理重复/无效行。

### Wave 2 · B 级（结构与拆分）

- **rbac 包三分**：`features.rbac`（纯 RBAC 模型）/ `features.auth.model`（UserAccount 等认证实体）/ `features.admin`（`/api/admin` 后台管理 API，`UserController` → `AdminUserController`，**映射路径不变**）。
- **五大 Service 拆分**（只搬代码不改逻辑）：
  - `EmployeeService` 590 → Query / Onboarding / Command 三件套
  - `ProfileChangeService` 507 → Submit / Query / Review + `ProfileFieldApplier`（三个 switch 收敛为 fieldCode→reader/writer 映射表）+ 批量姓名回填（**修掉 N+1**）
  - `AuthService` 365 → LoginService / PasswordService / TokenIssuer / PermissionResolver（Controller 直注，不留 facade）
  - `VisitorApprovalService` 310 → HrApproval / HostConfirm / Gate + `VisitorApplicationMapper`（消除两 Service 逐字节重复）
  - `AdminUserService` 257 → UserAccountAdmin / RoleAdmin / PermissionOverrideAdmin
- Controller 不再直接注入 Repository（5.6）。

### Wave 3 · C 级（行为修复，均为审计确证 bug）

| 修复 | 内容 |
|---|---|
| **管理员锁定失效** | 登录与 **refresh** 均拒绝手动锁（`locked` + `lockedUntil=null`），专属文案区分暴力临时锁；登录成功不再回写 status 冲掉人工状态；lock 写入时清 `lockedUntil` 防绕过 |
| **车牌读错列** | 列表/核验响应从遗留明文列改读 `plate_no_enc` + 解密（V14 起明文列已不写） |
| **审计 actor 为 NULL** | `tx.bind()` 前置到方法首行；changePassword / 访客登录 / 员工登录成功路径补 bind（失败路径刻意不 bind） |
| **软删部门泄露** | 访客目录接口过滤 `deleted=false` |
| **杂项** | EmployeeController.update 补 `@Valid`；访客刷新令牌撤销改批量 UPDATE（原全表 findAll 内存过滤） |

## 明确不做的（留待决策）

- `Employee.version` 乐观锁补递增（会使在途 pending 申请 409，需知会 HR 流程）
- `EmployeeCredential`/`EmployeeEducation` 实体（建表未建功能，删留待产品确认）
- 生产环境关闭 swagger（`permitAll` 现状需安全确认）
- `department_roles`/`user_permission_overrides`/`emergency_contacts` 补审计触发器（需新迁移）
- `ProfileChangeDto.Page` 合并进 `PageResponse`（JSON 字段名 `totalElements` vs `total` 不同，前端已对接，保持契约）

## 影响与验证

- 文件数 136 → 157（拆分所致），无 API 路径/请求响应形状变化，迁移文件零改动。
- 验证：每批次 javac（JDK 21 + .m2 缓存 + Lombok）全量编译零错误；**未跑 Flyway/Spring 启动/Testcontainers**，运行时行为需下次 `mvn spring-boot:run` + 关键链路冒烟（登录/锁定/解锁/访客核验/权限分配）确认。
- 已知残留小缺口：被锁用户已签发的 access token 在 15min TTL 内仍有效（JwtAuthFilter 不逐请求查 status）；访客账号首次 INSERT 的审计行无 actor。
