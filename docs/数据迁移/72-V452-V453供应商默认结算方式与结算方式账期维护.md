# V452/V453 供应商默认结算方式与结算方式账期维护

## 目标

V443 把销售货款链路（客户标签、出货财审、铺底口径）收口后，采购/委外侧的
「结账方式」仍有两个不对称缺口：

1. 客户主档有 `default_settlement_method_id`（V285），供应商主档没有——采购/委外
   订货每次开单都要手选结账方式，与销售链路能力不对称。
2. `settlement_methods` 的账期策略列（`terms_base/due_rule/default_due_days/
   fixed_day_of_month/months_ahead`，V330/ADR-047）没有任何在线维护入口：在线新建的
   结算方式一律落库默认「收货日当天到期」，无法表达 月结60 / 月末+15天 / 次月固定10日
   等账期，只能 DBA 手改 SQL。

V452/V453 补齐这两块，并保持既有权威不变：订货单的结账方式仍是必填、财务批准时
快照冻结的唯一事实；供应商默认只是开单预填；AP 到期日仍由
`SupplierPaymentTermService` 在收货/进仓审核时按 UUID 结算方式计算。

## V452：供应商默认结算方式（镜像 V285 客户契约）

- `suppliers.default_settlement_method_id UUID`（FK RESTRICT + 部分索引）；
  `price_style` 降级为同步的旧库 `B_Provider.PStyle` 快照。
- 回填只接受「恰好一个启用中的 legacy 字典匹配」：`supplier.price_style =
  method.legacy_id` 且该方法唯一启用、未软删。缺配/歧义保持 NULL，由人工维护；
  活视图 `v_supplier_default_settlement_migration_issues` 常驻核对（活证据，
  非闸门——供应商默认不驱动任何运行时放行，区别于客户 V285 的问题表）。
- 触发器 `fn_sync_supplier_default_settlement_method_reference`：UUID 写入必须指向
  启用中的方式并同步 `price_style`；与既有快照冲突、或单写 legacy（非显式旧库
  导入事务）都失败关闭。显式传 null 清空时两者同清。
- 触发器 `fn_guard_supplier_default_settlement_method_target`：被启用中供应商引用的
  结算方式不得改名映射/停用/删除（镜像客户守卫；系统角色行仍受 V285 不变量约束）。
- 服务端 `SupplierService.applyDefaultSettlementMethod` 走
  `SettlementMethodReferenceResolver` UUID 权威解析；字典项
  `SupplierDictItem.defaultSettlementMethodId` 供前端开单预填。
- **不自动放行、不猜值**：供应商默认只用于采购/委外订货开单时的下拉预填
  （预填仍存在的启用方式；必填校验与订单快照校验原样生效），不影响既有单据、
  应付立账与到期日计算。

## V453：结算方式账期策略在线维护

- 权限：`settlement_method:view`（查看全量含禁用行与账期）、`settlement_method:edit`
  （维护账期与可选改名）。权限面 `basic.settlement-method` 关联
  view/create/edit 三个码；零默认 grant，须权限管理员显式授权（V437 范式）。
- 实体补齐账期列映射；`ReferenceMethodService`：
  - `settlementAdminList()`（含禁用行）；
  - `updateTerms(id, req)`：枚举/范围/固定日形态校验镜像 V330 CHECK
    （基准 5 值、规则 3 值、天数 0-3650、固定日仅 FIXED_DAY_OF_MONTH 1-31、
    跨月 0-120）；改名查重排除自身（引用一律 UUID，改名安全）；
  - `create(req)` 可随带账期（内联新增不传时仍落库默认）。
- **系统角色锁定**：`system_role` 非空（CASH/MONTHLY）的行在线改账期直接 409——
  「现金=收货当天到期、月结=月末+30天」是 V285/V330 锁定的文档化不变量
  （显式 CASH 不被供应商 tday 改成账期单）。
- 前端新页 `/basicinfo/settlement-methods`（基础资料 hub 第 11 个入口）：
  列表卡片展示名称/编号、系统角色锁定徽标、停用态和一句话账期口径
  （与 `SupplierPaymentTermService` 推导同口径）；点击进入维护弹窗；
  质检验收/对账确认/发票基准标注「事件处理器开放前到期日保持未定并阻断月结冻结」。
  停用/删除不在此页开放（活动客户/供应商默认受 DB 守卫保护）。

## 订货/收货开单预填（前端）

- 采购/委外订货与收货/进仓编辑页：供应商确定（表头选择、统一设供应商、行级选择、
  上游引入）且结账方式未选时，用「上游单据结账方式（收货/退货沿用来源快照，经
  `UtenDocLinkDetail.settlementMethodId` 透传）→ 供应商主档默认」的顺序预填；
  只预填启用中的方式，不覆盖用户已选值，必填校验原样兜底。
- 供应商资料表单与详情新增「默认结算方式」；编辑时当前默认已停用则阻断编辑
  （与客户页同款 fail-closed 提示）。

## 迁移前后只读核对

```sql
-- 未匹配 legacy 的供应商（活证据，人工维护后自动消失）
SELECT count(*) FROM v_supplier_default_settlement_migration_issues;

-- 回填后默认方式必须全部启用且未软删
SELECT count(*) AS invalid_defaults
FROM suppliers supplier
JOIN settlement_methods method ON method.id = supplier.default_settlement_method_id
WHERE method.status <> '使用' OR COALESCE(method.is_deleted, FALSE);

-- 系统角色行的账期口径未被改写
SELECT system_role, terms_base, due_rule, default_due_days
FROM settlement_methods WHERE system_role IN ('CASH', 'MONTHLY');

-- 新权限/权限面登记完整
SELECT count(*) FROM permission_surfaces WHERE surface_key = 'basic.settlement-method';
```
