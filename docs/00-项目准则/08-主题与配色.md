### 2.5 状态色体系（ADR-169，2026-10-08）

状态列与状态徽章统一走 `UtenStatusBadgeType` 十档 + `resolveStatusBadgeColors`：
**深色实底 + 成套前景字，明暗两主题同一实底**（自带对比度；琥珀档是唯一亮底，
配深棕字 `onWarningStrong`）。色板常量在 `UtenColors.status*`，色相刻拉开 +
明度分层，白字对比度全部 ≥4.5:1（WCAG AA）：

| 档位 | 色值 | 色名 | 语义家族 |
|---|---|---|---|
| `danger` | `#991B1B` | 红 | 硬阻断/锁定不能往下、驳回、失败、异常、不合格、逾期、红冲 |
| `success` | `#15803D` | 绿 | 完成/通过/已审，及「就绪可动手」（可开工/可领/可下单） |
| `warning` | `#F5B301` 亮底深棕字 | 黄 | 等待外部且无异常：等财务/等仓库/在途/等检查 |
| `info` | `#1D4ED8` | 蓝 | 正在执行/加工中/已提交流转中 |
| `sky` | `#0369A1` | 青 | 第二等待档：同页区分两种「等别人」（如等财务 vs 等仓库发料） |
| `orange` | `#C2410C` | 橙 | 风险中间态：部分异常/短交待判定/临期，未死锁但需注意 |
| `violet` | `#6D28D9` | 紫 | 部分就绪：可部分下单/部分可领/部分齐套 |
| `fuchsia` | `#A21CAF` | 品红 | 分类强调（非语义状态：分批等待、持续生产路线） |
| `accent` | `#0F766E` | 青绿 | 他方执行中（委外商加工中）/品牌特殊档 |
| `neutral` | `#475569` | 灰 | 草稿/未提交/已取消/已中止等中性终态 |

三条硬规矩：

1. **映射逐页显式，不许猜色**：状态→档位由各页自己的映射函数（如
   `purchaseOrderDisplayBadgeType`）显式决定；`utenStatusLabelType` 按文案关键字
   猜色的兜底已删除（它正是「委外锁死等物料齐套显示黄色」这类语义错误的根源），
   未显式映射的状态列保持无色纯文本。
2. **逐页/逐段独立**：只要求「同页同现的状态互可区分（色相+明度差）」且不违背
   锚定语义；不同分段（草稿/进行中/历史）互不联动，「开工准备里可开工=绿」与
   「历史段完工=绿」并存是正确用法。同页状态建议 ≤7 个，超出先归并灰档。
3. **底色与字色成套**：换实底必须同步换前景（琥珀档尤其）；红绿是色盲最易混对
   （红 800 暗档/绿 700 亮档靠明度拉开），状态永远带文字标签。

2026-10-08 追加三条（用户口径）：

4. **格内不许写死颜色**：状态列底色与前景由表格统一配对（深底白字/亮底黑字，
   `utenSemanticCellForeground` 自动判定），格内自定义 cellBuilder 的文字/图标
   一律继承 DefaultTextStyle/IconTheme——写死颜色会出现「红底黑字看不清」。
5. **状态/进度列文字统一加粗**（w700；胶囊 `UtenStatusBadge` 同步 w700），
   判定用 `utenIsStatusOrProgressColumn`（状态列口径 + key 含 progress / 标签含
   「进度」）；列宽测量同步用加粗样式防截字。
6. **状态/进度列默认最前**：所有表格的状态列、进度列（含无状态字样但实质是
   行级结论的状态渲染列，如「判定结果/处理结果」）默认排列表格第一位，多状态
   列全部前置保持相对序；纯数值分档列（可靠度）与工序列（当前步骤）不在此列
   （2026-10-06 批次的相应豁免由本条推翻）。

红/黄**计数徽章**与三形态计数口径（`dangerStrong`/`warningStrong`）见
[14-徽章与计数口径](14-徽章与计数口径.md)，与本节互不影响。完整决策依据与
业界调研见 [ADR-169](../99-决策记录-ADR/ADR-169-状态色深色实底与逐页独立配色.md)。

### 2.6 物料分析按产品视图·层级连线轮换色（2026-10-10）

`UtenColors.bomProductGuide*` 四常量：物料分析准备页「按产品看」的树形层级
**连线**（祖先竖线/肘线/父行引出段）按产品渲染序奇偶轮换，同一产品整棵子树
同色、相邻产品换色。只染连线——箭头、徽章、行底色一概不动。

| Token | 色值 | 主题 | 轮换位 |
|---|---|---|---|
| `bomProductGuideEven` | `#0D9488`（teal-600） | 浅色 | 偶数序产品 |
| `bomProductGuideOdd` | `#7C3AED`（紫） | 浅色 | 奇数序产品 |
| `bomProductGuideEvenDark` | `#5EEAD4`（亮青绿） | 深色 | 偶数序产品 |
| `bomProductGuideOddDark` | `#A78BFA`（亮紫） | 深色 | 奇数序产品 |

选色（用户口径「找两个色差大的」）：青绿 174° 对紫 262°，色相错开近 90° 且
明度不同；避开红/黄/绿（进度列状态扫视色）与品红（路线徽章委外色）。浅色用
深档（1px 细线白底上要压得住），深色用亮档（深底上要跳得出）。经
`UtenTreeTableCell.guideColor` 传入，汇总视图与未归属孤儿行不参与轮换
（默认灰连线）。

同日追加（用户口径「箭头还有箭头的背景也统一」「下面的箭头跟线挨在一起」）：

- **展开箭头圆底同色轮换**：有下级行的箭头圆底经 `UtenTreeTableCell.toggleColor`
  与连线同一对色相轮换，但实底**明暗两主题统一用深档**（`bomProductGuideEven`/
  `Odd` 即 teal600/紫，不随主题换亮档）——白箭头自带对比度，与 ADR-169
  「实底不吃表面色」同路数；无下级的灰色占位图标不参与。汇总视图维持
  depth%4 层级轮换色。
- **每级缩进 16→24**（`UtenTreeTableCell.indent`，物料分析主表两视图一致；
  同日扩到货品资料-组装信息，配色不变）：同色后祖先竖线离圆底只剩 2px 会
  看着粘成一块，放大到 10px（间隙 = indent − 14）。

## 三、使用规则

### 3.1 业务页面

优先读主题：

```dart
final theme = Theme.of(context);
final colors = theme.colorScheme;

Text('标题', style: theme.textTheme.titleMedium);
Icon(Icons.check, color: colors.primary);
```

只有主题未暴露、且确属全局语义 token 时才直接引用 `UtenColors`：

```dart
const UtenStatusBadge(
  label: '已完成',
  type: UtenStatusBadgeType.success,
);
```

禁止：

```dart
// 禁止在业务代码新增裸色值，也禁止只适配浅色模式。
Container(color: const Color(0xFF14B8A6));
Text('说明', style: const TextStyle(color: Colors.grey));
```

`Colors.transparent`、`Colors.white`/`black` 只在透明或明确反相前景等框架语义中使用；业务状态仍必须走主题或 `UtenColors`。

### 3.2 间距、圆角与阴影

- 间距使用 `UtenSpacing.s4`～`s48`。
- 圆角使用 `UtenRadius`；主题控件已有默认 shape 时不要重复覆盖。
- **控件圆角唯一值**：按钮、输入框、Chip 等表单级控件一律 `UtenRadius.control`（10）。
  2026-09-01 全平台统一：浅/深主题的 elevated/filled/outlined/text/icon/FAB/输入框/Chip
  与 `UtenButton`、`ClickGuard`、导入按钮全部调用该 token，业务代码不得再散落
  8/10/12/14 等控件级硬编码。卡片（14）、对话框（18）等容器圆角不在其列。
- **搜索框唯一组件**：`UtenSearchBar`（胶囊圆角 + 清除 + 300ms 防抖，高度内容
  驱动），页面不得手写搜索 `TextField`；与分段导航条并排时的严格同高由
  `UtenFilterToolbar` 的 IntrinsicHeight+stretch 结构保证，勿各自设高度。
- **分类筛选统一范式**：「分类/状态分段 + 搜索」用 `UtenFilterToolbar`
  （48 高胶囊分段、选中只变背景色不出 ✓、可挂红色圆计数徽章
  `UtenSegmentBadgeLabel`），不再各自手写 Chip 行/筛选按钮/自成一套分段样式。
- 阴影使用 `UtenElevation.low/mid/high(isDark: ...)`，不得在页面复制 `BoxShadow` 数组。
- 玻璃、模糊和高成本阴影还须服从性能档，详见[性能自适应](07-性能自适应.md)。

### 3.3 字体与缩放

- 全局字体为 `NotoSansSC`。
- 页面使用 `Theme.of(context).textTheme` 的 Material type role，不硬编码常规字号。
- 用户字号通过 `fontScaleProvider` 统一作用于 `MediaQuery.textScaler`；组件不得再次手动乘倍率。
- 图标不要跟随字体无限放大，必要时在组件内部设置合理边界。

## 四、主题模式

应用向 `MaterialApp.router` 同时提供 `buildLightTheme()`、`buildDarkTheme()` 和 `themeMode`。`ThemeNotifier` 支持：

- `ThemeMode.light`
- `ThemeMode.dark`
- `ThemeMode.system`

选择值保存到本地 `SharedPreferences` 的 `themeMode`。这只是界面偏好，不包含密钥或业务数据；不要把敏感信息放进同一偏好机制。

## 五、组件主题覆盖范围

浅色和深色主题均集中配置：

- typography、AppBar、Card、Divider；
- Filled/Elevated/Outlined/Text/Icon Button；
- InputDecoration；
- NavigationBar/NavigationRail；
- Chip、Dialog、SnackBar、ListTile；
- ProgressIndicator、FloatingActionButton；
- Switch、Checkbox、Radio、TabBar。

因此页面应先使用 Material 主题默认值或 Uten 公共组件。只有明确的新全局设计规则才允许修改 `light_theme.dart` 和 `dark_theme.dart`，并且两份主题必须同步评估。

## 六、变更检查

主题或公共组件变更至少完成：

1. 浅色、深色各检查窄屏和桌面宽屏。
2. 检查默认、hover、focus、pressed、disabled、loading、error 状态。
3. 检查文字对比度、键盘焦点和语义标签。
4. 运行 `flutter analyze` 和相关 widget 测试。
5. 搜索业务层新增裸色：

```powershell
rg -n "Color\\(0x|Colors\\." lib/features lib/shared
```

命中不等于必然违规，但每一处都要说明为什么不能使用主题或语义 token。
