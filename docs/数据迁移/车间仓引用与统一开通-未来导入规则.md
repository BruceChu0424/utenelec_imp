# 车间仓引用与统一开通：未来导入规则

本规则纠正无旧仓身份的XW03“五金车间”普通仓解释。原Excel/旧清洗文档/旧已封输入和历史单据原文保留，不通过改原件、重新审批、伪造出入库或GL消除差异。本轮用户已在统一页面开通五金铜铸车间内料仓；当前三余额承接、WH9退役与4货品修正由独立受审数据计划执行，**不是再次运行全量stock loader**。

## 身份与编码

- 普通源仓只按真实旧仓或明确普通TARGET解释，WH1–8的现有UUID/代码不重建；真实KEEP134轨道仓保留，不能按“名字含车间”一刀切。
- 删除XW03的活动TARGET声明，WH000009历史仓/终身登记保留不重用；清洗固定现有WH1–8映射，新普通编号从未占用的后续号开始，late allocator至少推进到9。原late代码本来只推进分配器，不重排仓库码；它继续不UPDATE仓库，且不得把正规LS仓改成WH数字码。
- “生产车间”仍独立映WS_WJTZ。“所属仓库=五金车间”若没有真实普通仓身份，只生成 `goods_workshop_stock_location_review.csv`，保存原值、源文件行号、legacy/code/name及车间码，不填普通owner。完整80列仍在原始Excel行档案中。未知普通仓标签仍失败关闭；不得为消除错误把XW03再补回来。
- 4个受审身份为65919/GD2056、65920/GD2057、65921/GD2058、65923/GD2060，且各自完整产品名必须一致。最近源如ID/名称/编码改变或出现其他车间引用，不能按旧GD序号或名字相似猜，须另审新映射。

## 必须分阶段的流程

1. 在独立受限目标完成普通主档/编码阶段，保留已有主档UUID和终身编码原像。普通warehouse crosswalk仅8目标，旧warehouse.csv带旧身份的对账仍为6，不能把它改成8或9。已退役WH9和实际开通LS另列，不能硬断言数据库总仓恒为9。
2. 使用现有统一开通页面/正常服务打开WS_WJTZ内料仓。必须有真实 `workshop_bins` 唯一开通行、真实opened_by/at与对应line-side仓/部门/主树；不由ETL插入开通行或改periodic设置。本受审历史承接要求periodic未开启，若已开启则停下另审，不能替人关闭。
3. 对目标执行实际RRRO开通snapshot。`prepare_workshop_stock_location_policy.py --emit-opening-sql <私有SQL路径>` 只产读取SQL，不连接数据库；Root执行后保存原JSON。目标SID/OID、实际UUID、row_version和PG直接计算的整row SHA来自该目标。不能把本机bin UUID/快照复制冒成公司开通事实，未来任务也不硬写本轮UUID。
4. Root对同4个legacy+code+完整name、原“所属=五金车间”及上述真实snapshot写明确批准文件。`format=REVIEWED_OPEN_BIN_STOCK_LOCATION_APPROVAL_V1`、purpose=`FOUR_EXACT_HISTORICAL_GOODS_LOCATION_ONLY`；绑定review和snapshot SHA，`quantity_policy=SOURCE_VALUES_UNCHANGED`、`change_periodic_settings=false`。未批准模板不可执行。
5. 用下列**纯文件**命令生成全新的策略目录，原Excel/overlay/snapshot不改：

```text
python prepare_workshop_stock_location_policy.py \
 --review <overlay/goods_workshop_stock_location_review.csv> \
 --opening-snapshot <actual-target-opening.json> \
 --approval <Root-reviewed-approval.json> --out-dir <新的私有policy目录>
```

目录包括2份COPY CSV、原review、真实snapshot/批准原件及 `LOCATION_POLICY_MANIFEST.json`。所有文件SHA、4项精确身份、批准和开通事实再次核验；CSV只描述位置，不含被改写的数量、金额、单位或权重。
6. 实际封包入口 `rehearse_local_import.py prepare` 在既有完整参数外传 `--workshop-stock-location-policy <policy目录>`。原overlay仍保默认空授权CSV；封包从另行受审policy取2份授权COPY CSV，review SHA必须与overlay完全一致，输入、生成器与额外文件全部登记。没给策略不会静默归主仓/WH4或排除4行：消费时因缺实际批准而在任何业务DELETE前失败。旧shell的stock入口同样要求准备后的3CSV并经同一consumer，不能直跑单份stock SQL跳过前置。
7. 两入口均经 `compose_bootstrap.reviewed_loader_content()` 把 `reviewed_workshop_stock_location.sql` 与真实stock模块组成一个受外层事务保护的模块。运行时再核actual bin/line_side/部门/普通主树、整row SHA、目标SID/OID、真实维护会话、4项唯一身份、owner普通仓NULL及明确单位；持共享锁防检查后漂移。普通crosswalk禁止指任何LS；只有受审4项item-location优先分支可以用本已开通bin，不扩大 `good_stock_leaf` 的定义。新的未知引用或NULL单位一律拒绝，不猜条/1/零。
8. 同一位置解析用于历史明细、流水及余额。源ID、数量、价/金额、颜色、单位、冻结率和状态不变；独立movement检查从原crosswalk和真实opening另算，不信任loader已解析结果。来源4项8/15/8/0中零量映射和raw/latest stage也保留；原0量0金额不伪造active balance，不拿零值当删除授权。零量非零金额等既有源金额治理仍按其独立已审流程，本包不改数值算法。

## 当前运行与验收边界

上述是未来导入源码/流程补丁，不是对现有库执行指令。当前用户库和公司候选的承接必须使用独立数据delta，核旧仓全引用、3余额、4goods、原历史/流水/财务、bin/periodic与终身编码，再独立RRO；当前不能运行会清重建stock表的历史导入模块。Root/owner负责review、正式合并/CI和执行，不能把源码候选或模型PASS冒成已部署。
