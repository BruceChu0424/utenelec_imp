# 仓库委外出仓工作台页

> **2026-10-20 待发料徽章按明细统一**：`tasks/count` 和徽章事实 `subcontractOutbound.count` 通过 `WarehouseTaskRowCountPort.subcontractOutbound` 复用统一任务中心实物行，同一已提交领料单的两条待发货品明细计 2；当前仓库授权范围、已提交且未发出/未撤回条件继续生效。批量办理按原领料单分组并携带精确明细 UUID；[批量出仓页](委外领料批量出仓页.md) 使用 `selected-outbound` 原子命令和原请求回执，只办理所选明细，未选行和预留留在原单。原单页整单保存／审核入口继续使用原业务规则。

- **业务依据**：[ADR-143 委外按工序领直属物料、齐套通知、分批回厂](../99-决策记录-ADR/ADR-143-委外按工序领直属物料与分批回厂.md) §4.3；链路见[委外全链路 SOP](../07-业务链路/08-委外全链路-订货出仓回仓重设计.md)。
- **迁移**：[275-V798](../数据迁移/275-V798委外按工序领直属物料与分批回厂.md)、[V900 所选明细原子出仓](../数据迁移/V900-委外所选明细原子出仓.md)。

本页是仓库执行委外领料的专属页面：列表一行 = 一条原货品明细，来源为委外人员在委外任务中心「待处理·领料」提交、仓库还没发出的
**领料草稿**(委外材料出仓单草稿)。仓库发出去的是委外件的**直属物料**(一张草稿可以有多种物料)，
委外商加工后交回委外件。全页无价格/金额/币种字段；直属物料仍是公司自有存货，本次出仓是转为
委外商处保管，不立采购或加工费应付。

仓库不决定发什么、发多少：发哪几种物料、每种的领料数量都由委外人员提交时服务端算好(按冻结单耗与
联合分配后的可领套数)。仓库只核对实物，可以把某行**改少**；任务所选明细入口只办理勾选且数量大于 0 的原行，
未选行和**填 0** 的行继续留在原领料草稿，其数量及预留不变。不能改多、不能加行；原单整单入口仍有下文单独说明的保存删行规则。整张都发不出时点
**「退回委外(不发)」**把这张领料退回委外人员。

## 入口与权限

- 仓库 Hub → 出库任务中心「委外出库」分段(小类「待发料」)，红角标 = 待发领料货品明细行数
  (`GET /api/warehouse/subcontract-outbound/tasks/count` 的 `count`，服务端徽章事实 `subcontractOutbound.count`)；
  计数与待发料列表同一条查询(同样只认绑定冻结计划行的领料草稿)，也接受列表的
  可选参数 `scopeWarehouseId`(仓库数据范围由服务端按本人强制, [ADR-149](../99-决策记录-ADR/ADR-149-仓库数据范围服务端强制.md)；所选仓越界 403)，红数与列表总行数均按待发货品明细计数；徽章汇总与列表使用同一业务资格及仓库范围(不选仓 = 本人全部可见范围)；
  只挂红数，没有黄数。**无 `subcontract_outbound:view` 时卡片与角标整组不显**。
- 路由：`/warehouse/subcontract-outbound`(待发料列表)、`/warehouse/subcontract-outbound/:issueId`(拣货出仓页)；
  静态段先于 `/warehouse/:code`。
- 权限：`subcontract_outbound:view` 看列表/详情；`subcontract_outbound:execute` 执行拣货出仓与「退回委外(不发)」(服务端要求 view + execute)；
  草稿保存/审核/红冲还叠加对应 `subcontract_material_issue:edit/approve/reverse`，这些动作精确列入
  `warehouse.subcontract-outbound` 权限设置 surface。已停用的 `subcontract_outbound:handle` 不能代替任一现行权限。未授权深链同样 403。

## 待发料列表

- 一行一条原领料货品明细，同单同货品的不同明细也不合并。旧独立入口复用仓库任务中心的委外出库列表，按调用者仓库数据范围(ADR-149，服务端强制，可选 `scopeWarehouseId` 在本人范围内挑一个仓)，按单据号筛选后可查看该单全部授权明细。
- 默认列序以状态、领料单号在前，随后核对委外商、货品名称 / 编码 / 颜色、数量与领料仓等业务信息；数量内联单位。选择同单多条明细时按原领料单分组，所选原行 UUID 保持独立，不按货品名称合并。用户已保存的列设置继续保留。
- 搜索：领料单号 / 委外订货单号 / 委外商(防抖，只让最新 GET 回写)；下拉刷新与分页。
- 单张与批量拣货的本机输入留在「待发料」原行，状态为「草稿」；已发起但回执不明为「提交待核对」，不移去单独草稿分类。双击任一未完成成员恢复原整批，已确认出仓的成员不重复标草稿。任务批量地址为 `/warehouse/subcontract-outbound/batch?issueIds=…&itemIds=…`，本机草稿还保留原行到来源的映射、数量、称重、备注、仓库、经办人及日期。原子命令发送前冻结并持久化原请求体、服务器指纹与幂等键；恢复先查该来源的 `selected-outbound/receipt`，不能因 GET 仍显示草稿就断言未发送。空回执保持待核对，且须当前可读原来源，用户明确「按原内容重试」才发送同一键及原请求体；成功回执只确认原命令的精确行集，已确认来源不重复出仓。
- 任务中心双击货品行或多选后进入保留 `itemIds` 的核对页，只显示所选货品，以 `selected-outbound` 原子命令执行正数行，无须选齐同单所有行。未选行和填 0 的行及其预留仍留原单。独立原单详情及未携带明细身份的旧入口保持明确的整单办理语义，不用整单保存／审核去代办子集。批量页顶部单据卡
  直接铺开(2026-10-10 起「单据信息 (N)」折叠标题退役，卡片里的出库单号/来源订单等信息保留)，
  填 0 的行不进入本次命令，也不因省略而从原单删除；
  一张单的物料全部填 0 会被拦下，提示整张不发请到单张拣货页「退回委外(不发)」。
- 委外人员撤回领料后，这张草稿从列表消失，仓管收到「委外领料已撤回」通知(整张撤回时通知直达本列表，部分撤回时直达这张拣货页)；
  部分撤回时待发料通知按剩余内容刷新。
- 接口：`GET /api/warehouse/subcontract-outbound/tasks?page&size&keyword` → 分页
  `{issueId, issueBillNo, planId, orderId, orderBillNo, supplierName, warehouseId, warehouseName, lineCount, materialKindCount, submittedAt, submittedByName}`。

## 任务所选明细出仓与原单拣货

- 表头：领料单号 / 委外订货单号 / 委外商只读；出仓日期(默认今天)、发出仓、经办人(默认当前登录人，
  默认部门 SUB_WH 子树)、交货日期、备注。改发出仓时服务端按新仓重新占用库存，新仓不够即 409。
- 明细列(2026-10-10 数量+单位口径：独立「单位」列删除，单位内联在领料数量 / 仓内可动用与
  本次出库输入框后缀)：物料名称 / 编号 / 颜色、发出仓、领料数量、仓内可动用、库位号、本次出仓、
  实称重量、回厂交回的委外件、委外件编号、行备注。批量出库页在此基础上还带处理结果(首列)、
  出库单号、委外商及来源订单；货品名称 / 编号 / 颜色相邻，数量和仓位之后再放父件来源信息。
  - **领料数量**：委外人员提交的数量，本次出仓的上限。
  - **本次出仓**：默认 = 领料数量；只能改小(0 到领料数量之间)。任务原子入口在确认前不保存业务单据，正数 A 少发时只按实发量核销 A。其未发数量由原领料计划保留，委外下一次新提交领料时按权威已发量与仍在途的待发量重算、补齐落后物料；不会自动回填旧单，也不重复生成仍由 B 草稿预留覆盖的物料。原单整单入口的 PUT 保存仍会即时重算所列行的预留，不能把这条旧保存效果套到任务原子入口。
  - **填 0 = 本次不发**：任务原子入口的该行不进入命令、不做重量核对，仍留原单待发，原数量与预留不写；与未选行一样可稍后直接继续办理。原单整单入口仍明确提示保存删行：PUT 省略的 0 行由服务端软删并记 `warehouse_dropped_at`，释放其预留，原提交数量保留供差异追溯，后续新领料再按原计划补齐。两种入口均至少有一行正数，全部填 0 时页面提示
    「整单不发请点「退回委外(不发)」或联系委外人员撤回领料」，不调服务端。
  - **仓内可动用**：这个仓、这个物料和颜色此刻能动用的合格量(含本张草稿自己占住的量)。
  - **回厂交回的委外件**(带名称与编号)：发出去的是物料，收回来的是委外件，拣货、点数、核对一律以本行物料为准。
- **实称重量**：单张拣货页与批量出库页每行在「本次出库」后有可编辑实称重量格(共享[重量格](../02-组件库/WeightGridColumn.md)，
  占位「应称 X」，可输 850g、1.2t、3斤；WARN / ALERT 框与件数说明；只提示不拦截)，工具条「称重单位」切换录入单位，
  表尾显示「实称 X (未称 N 行)」。「本次出仓」为空时填重量会按单重反推数量(黄框待核对)，该行标记 `qtyFromWeight`；
  重新打开草稿时按保存的标记恢复黄框。保存的 `items[]` 带 `weight`(千克，4 位)与 `qtyFromWeight`；看不懂的重量在保存前拦下。
  审核出仓时实称流水记 MEASURED，并记一条 ISSUE 称重观测(往来方 = 委外商，捕获键 `ISSUE:<出仓明细 id>`)；
  红冲出仓把观测标为已红冲([ADR-135](../99-决策记录-ADR/ADR-135-仓库重量账与单重自学习.md))。
- 操作：
  - **任务所选明细确认**：先 `GET /api/subcontract/material-issues/{sourceId}/selected-outbound/review` 核对指纹，再单次 `POST .../selected-outbound`，请求中的 `itemIds` 与 `document.items` 必须是同一组原正数行 ID。全部当前行都选且为正数时可直接执行原单 D；只选部分时原子形成执行子单 S，把所选 A 复制为新 A2，并记录原 A → A2 的不可变谱系。原 A 身份与原父单保留为 `warehouse_split` 历史，不记仓库删行、不修改未选 B。只移交所选计划行的预留，再通过原审核内核出仓；B 和 0 行的行事实、预留与待办保持原样。客户端不先 PUT 整单，也不将未选行填 0。
  - **原单整单入口·保存拣货**(PUT `/api/subcontract/material-issues/{id}`)：带回本次要发(数量大于 0)的原有明细(原 id、来源链 UUID 不变)，只改数量、重量和备注；
    填 0 的行不带回，由服务端删行；
  - **原单整单入口·审核出仓**(先保存再 POST `/api/subcontract/material-issues/{id}/approve`)，确认弹窗明示三效果：
    ① 所列直属物料从所选仓库实际出库，交委外商加工；② 改少或填 0 不发的物料不会丢：委外下次领料时系统自动补齐；
    ③ 委外商加工完交回的是委外件，回厂后仍需登记和品质检查，合格后才正式入仓。
  - **退回委外(不发)**(浮动操作组，只对持 `subcontract_outbound:execute` 的人显示；
    POST `/api/warehouse/subcontract-outbound/tasks/{issueId}/return-to-draw`，body `{reason}`)：整张领料实物发不出(缺货、料损等)时使用。
    先弹出原因框(必填，最多 200 字)，确认后才上忙碌遮罩提交。不论仓库是否改过拣货数量，服务端按撤回领料的锁顺序作废这张草稿的
    全部领料行与草稿头、释放全部占用(专属批次退回原分析)、重算可领，并通知提交领料的委外人员「仓库退回了领料：{订货单号}」(含原因)；
    只动这一张草稿，同一任务在别的仓的待发领料和领料计划不受影响。成功后提示「已退回委外：这张领料单不发了，占用的库存已退回，
    并通知了委外人员」，刷新任务计数并回到出库任务中心；404 / 409 / 服务器错误 / 网络不明时要求刷新核对，不重复提交。
    这是仓库已改过的草稿唯一的出口：委外人员撤不回它，仓库也不能删单或删光物料行(服务端提示「整张都不发请在拣货页把这张领料退回委外人员」)。
- 草稿已审核、已撤回或明细与服务端拣货视图对不上时，页面按冲突处理并提示刷新，不在过期草稿上继续操作。
- **无需拣货**：打开拣货页时领料单已被委外撤回、已退回委外或已发出(详情接口 404)，整页换成空态「这张领料单已被委外撤回或已处理，无需拣货」
  和「返回待发料」按钮，不显示操作按钮、不给重试(通知深链点进已撤回的领料就是这个状态)。
- 仓库不能手工新建领料草稿：通常由委外人员提交领料产生；任务部分出仓的执行子单、公开撤销审核的替代草稿由服务端沿原来源生成，不另立领料需求。不想再发外由委外人员在任务详情「结束领料」。
- 详情接口：`GET /api/warehouse/subcontract-outbound/tasks/{issueId}` →
  `{issueId, issueBillNo, planId, orderId, orderBillNo, supplierName, warehouseId, warehouseName, version, lines:[{issueItemId, planItemId, lineNo, parentGoodsName, parentGoodsCode, goodsId, goodsCode, goodsName, colorName, unitName, requestedQty, qty, stockAvailableQty, locationHint}]}`；只有未审、未删除的草稿可读(否则 404，页面显示「无需拣货」)。
- 退回委外接口：`POST /api/warehouse/subcontract-outbound/tasks/{issueId}/return-to-draw`，body `{reason}`(必填，去空格后不超过 200 字)，
  权限 `subcontract_outbound:view + execute`，只认仓库待发池里的领料草稿 → `{withdrawnIssueIds, removedLineCount}`；
  草稿已不存在 404，已发出 / 已撤回 / 已退回或明细刚被改过 409。

> **加载与完成返回**：只加载需要的仓库字典，并与任务/草稿读取并行；批量读取最多四路。当前选中单据全成功后
> 自动回 `/warehouse/tasks/outbound?section=subcontract&view=tasks`；部分失败或结果不明保留原操作。显式恢复中，相邻未提交来源已取消或不可读时仅以来源 ID 脱敏占位，不能挡住当前可读原请求的回执核对；也不会把相邻来源派发或把未完成整批当成功删除。确认结果在本机草稿初始化后保存，原完整范围及未提交填写继续保留。
> 任务中心首次返回即刷新，父层已刷新时避免子页返回再拉一次。

## 服务端联动(审核同事务)

1. 消费实际执行单的正数行预留(专属批次优先)，形成真实出库流水和委外商处保管台账。部分所选入口只移交原 D 的所选 A 预留到 S；原 D 未选 B 与填 0 行不写。原单整单保存／审核入口继续按整草稿的当前行与历史仓库删行规则核对，不能借此扩大任务所选集合。
2. 领料计划行的已发净量 += 本次(CAS 不超过计划量，并发冲突 409)。
3. 按实际执行单发布既有发料完成通知；旧整单入口的仓库删行差异仍按其历史提交量计算。任务部分出仓后依据不可变 S → D 回执刷新原 D 的剩余待发通知，B 或 0 行仍有待发时不得撤掉 D 的提醒；最后剩余行完成才撤回。通知重放不重复发布。
4. 不自动续开下一张草稿：之后能领多少由委外任务中心按实时库存重算并提醒委外人员。

公开撤销审核：对实际执行单反向入库并回减已发净量，原已审单转为反向历史，并复制为新表头／新行 UUID 的待发草稿；新草稿在预留成功后发布其自身待发通知。执行子单 S 的反向不写原 D 未选 B，后续从新草稿继续出仓，不让已反向旧身份直接变回草稿。已有下游回厂核销、材料退或损耗时先按既有守卫反向下游。订货红冲：撤回全部未发领料、
释放预留、领料计划 CANCELED。

## 与其它页面的分工

| 页面 | 归属 | 职责 |
|---|---|---|
| 本页(待发料 + 拣货) | 仓库 | 核对委外人员提交的领料、只能改少(填 0 = 本次不发)、整张发不出时退回委外、审核出仓与反向 |
| 委外任务中心「待处理·领料」 | 委外 | 看可领套数、提交领料、撤回未发领料、结束领料 |
| 预计到货任务中心 / 独立登记实际到货页 | 仓库 | 委外件加工回厂；通用 `/subcontract/receipts/new` 不受理新回厂 |
| 委外订货单详情「全链路进度」 | 委外 | 只读跟踪领料发外/回厂/来料质检/应付，单号点进只读详情 |
| 原物料分析供给进度 | 计划/销售 | 只有委外回厂来料质检合格并入库才成为合格供给 |

## 页面状态、响应式与并发

- compact：保持可触达的任务表/卡与至少 48dp 操作区；核心数量与阻断原因不依赖悬停。
- expanded：高密度任务表；单击选择、双击打开，右键/长按菜单仍须按权限生成。
