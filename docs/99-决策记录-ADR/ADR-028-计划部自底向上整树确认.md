# ADR-028：计划部「自底向上、最深层优先」整树确认

- 状态：已实施（feature flag 默认关，候选）
- 日期：2026-08-07
- 相关：ADR-019（计划需求分解）、[04-生产单排产与执行全链路需求](../07-业务链路/04-生产订单排产与执行全链路需求.md)、V230；承接被回退的流程重构教训（整包确认 + 逐段下发唯一可行）

## 背景（为什么）

现状确认生产计划只展开 **一层 BOM**（`ProductionExecutionPlanningService.snapshot()` 单 join；`generateSelfMadeSubplansForPackage` 只建一张草稿子计划、显式禁止递归）。多层 BOM 必须计划员**逐层手动**：确认 A → 手动打开/审核/确认 B → 再确认 C。与业务要的「自底向上、最深层优先、下层完成自动释放上层、傻瓜式」相反。

## 关键发现（决定方案）

侦察实证后，大半基础设施已存在、无需重建：

1. **全树 BOM 递归已存在**：`MrpService.buildMrpSql` 的 `exp` CTE（≤10 层、path 防环），但 `lvl` 被聚合丢掉未投影。
2. **自底向上自动释放已工作**：`ProductionExecutionReadinessService.onFinishedInboundApproved`（FINISHED_IN 审核 → V194 `PRODUCTION_PLAN_ITEM` peg + `production_material_make_receipt_allocations`）已把父 WAITING 段在子件入库后升 READY，且**天然链式**（C 完工→B 就绪→B 完工→A 就绪）。
3. `subplan_links`（V126+V176）支持 N 层；V194 MAKE-peg 不变量已强制溯源。

**唯一缺口**：confirm 只展一层；子计划建为草稿（`status=0`），而 confirm 要求 `status=1`，故无法自动递归；无持久化深度。

## 决策

采用 **Option B：新增递归 orchestrator 复用逐层 confirm**（**不改** `confirm`、`snapshot`、`generateSelfMadeSubplansForPackage`、V194，仅组合）：

- 新增 `BottomUpPlanOrchestrator.confirmFullTree(planId, req)`：preview 校验 BOM 图 → 顶层 confirm → 递归下行（自动审核子计划 + 逐层 confirm），直到自制叶子件。**建造自顶向下；就绪/执行自底向上**（由既有 V194 钩子驱动）。
- 自制叶子件（无 BOM，如 C）**不**调 confirm（confirm 的 snapshot 内联 goods_bom_items，无 BOM 会得空产品行）；只自动审核使其可报工/成品入库——与当前人工流程一致。
- V230 给 `production_plans` 加 `bom_depth`（MAKE 树距根深度）+ `auto_generated`（orchestrator 标记），驱动傻瓜式 UI「最深层可开工优先」排序，并使级联回退只作用于自动子。
- **级联回退**（同发布必修）：`closeSubplans` 对 `auto_generated` 且自带 CONFIRMED 包的子计划，先递归 cancel/reverse 其包（下到叶）再关本子。仅自动子级联；人造嵌套包绝不静默反转。整树取消用 **reverse**（status→−1），非 cancel（cancel 要求子为草稿，但 orchestrator 自动审核了子）。
- 新端点 `POST /api/production/plans/{id}/mrp/generate-planning-package-full-tree`，`production_plan:edit` + 能力开关 `production.bottom-up-orchestrator.enabled`（**默认关**）。

## 后果

- **正向**：一次确认建出整棵 MAKE 子计划树，最深叶先就绪，下层完工自动释放上层；傻瓜式。既有逐层 confirm 与 25 段全链路测试不受影响（confirm 不变）。
- **可逆**：flag 默认关；出问题关 flag（无需重部署）+ 用新级联回退清掉 orchestrator 建的包，即回退到今日逐层手动流。不重蹈上次整流被回退的覆辙（本次是新增组合方法、不改 confirm、逐段执行语义不变）。
- **权衡/已知边界**：单仓跨层假设；不做跨层 MRP 合并（既有局限）；自动审核绕过子计划人工复核（子内容由父 BOM+MAKE 短缺完全决定，无人决策内容）；深树单事务（≤10×宽1，可监控切 `REQUIRES_NEW`）。
