# V592 客户「默认销售条款」落客户表（单一事实源）

> 2026-09-15 · 用户口径：与货品「归属仓库/归属车间」同一思路——客户资料表上的字段是唯一事实源，基础资料能直接维护，其他地方（新建销售订货单）直接预填最新值，每次下单自动写回。

## 做了什么

**此前**：新建销售订货单选客户后的结账方式/货运策略/币种预填，是实时查该客户**最近一张未删订单**推导（`SalesOrderRepository.findLastTermsByClientId`，无表、不可在基础资料维护）。

**现在**（clients 表三列）：

| 列 | 说明 |
|---|---|
| `default_settlement_method_id`（复用既有列） | 默认结账方式 |
| `default_shipment_policy`（新增 TEXT） | 默认货运策略（单头同款自由文本） |
| `default_currency_id`（新增 UUID → currencies） | 默认币种 |

- **存量回填**：每客户最近一张未删订单的单头条款（与旧学习口径一致：不限审核状态，红冲/取消单也如实记录）；`IS DISTINCT FROM` 守卫只搬有差异的行，人工已维护的值不覆盖，重放幂等。
- **下单写回**：`SalesOrderService` 保存/修改订单时 `syncClientDefaultTerms`——单头三项写回客户行（空项保持原值；值没变不落盘，goods 归属仓同款幂等守卫）。
- **预填**：`/sales/orders/last-terms` 优先读客户行三项；客户行全空回落最近订单（回填前老数据兜底）。
- **基础资料**：`ClientSaveRequest`/`ClientDetail` 开放三字段（币种走结账方式同款 presence 语义：不带键=不动；校验币种存在且未软删；详情下发币种名）。

## 顺序与触发器

clients 带审计/行触发器：先加列/索引/FK，再 UPDATE 回填，之后不再 ALTER clients（V259/V587/V590/V591 同款规矩）。
