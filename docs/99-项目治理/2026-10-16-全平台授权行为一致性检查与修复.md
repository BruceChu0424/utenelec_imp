# 2026-10-16 全平台授权行为一致性检查与修复

## 结论与交付边界

本次源码候选把功能授权统一回到权限设置：全员基础、部门配置、个人覆盖、有效负责人委派经统一解析后，产生相同操作能力。财务、品质、AI、工作台及行动待办不再额外按所属部门或个人授权来源限制功能。

检查同时覆盖了配置保存、实际权限、路由、按钮、服务端能力、待办候选和会话刷新，修复了其中可复现的冲突。普通授权变更允许有效会话刷新取得新权限；旧访问凭证仍立即失效。单据对象范围、敏感字段、实物责任、有效占用、版本与业务状态仍按各自规则执行。

交付位于隔离分支 `uimp/permission-only-operations`，未改动主工作区的并行修改，未部署、未写生产数据库。以下源码与自动化验证，不等同于已部署系统的全部真实账号验收。

统一规则见 [ADR-181](../99-决策记录-ADR/ADR-181-操作资格统一使用有效权限与准确失败提示.md)。

## 检查与修复矩阵

| 范围 | 发现或反查的冲突 | 最终处理与验证重点 |
| --- | --- | --- |
| 销售订单财务确认、报价核价、订货审批、超量到货审批 | 部门授权或有效委派已给动作，仍要求财务部门或额外个人 grant | 只按在职启用账号与实际查看/动作授权判断；真实 PostgreSQL/HTTP 验证跨部门授权、认领、确认和撤权 |
| 品质 FQC | 非品质部门持审核权限仍进不了审核池；打开页面后能力未跟随撤权 | 审核池按查看与审核授权；列表和办理页共享能力源，刷新不丢输入、不重放未知结果 |
| AI 与工作台 | 已授权业务仍被部门域或部门概览挡住 | 部门只用于分类偏好；入口、徽章和工具按实际业务授权及原对象范围查询 |
| 行动待办及弹卡 | 通知接收池额外按部门筛人，或只给查看者也收到动手待办 | 收件及弹卡沿用实际页面/动作授权；超级管理员固有全权限不自动订阅所有提醒 |
| 部门组织页 | 只有部门查看仍被员工查看权限挡住 | 部门树和搜索独立可用；没有员工查看时不请求员工接口 |
| 货品、客户、供应商、模具 | 有实体查看，却被分类树权限挡住整个列表/详情 | 无分类读取时使用全局主档列表，保留搜索、筛选、分页、详情及原数据范围；不发分类请求 |
| 主档写动作和 BOM | 按模块推导分类依赖会误挡全局编辑、删除、状态、导出、货品导入、客户交接和 BOM 修改 | 仅实际使用分类/组件选择器的新建入口补分类读取；现有记录及 BOM 行的其他动作独立核验 |
| 功能组合与独立命令 | 从权限码前缀推导查看，会破坏附件、证件、入职、字段授权、研发任务等独立行为 | 页面入口补读与原服务端明确的同时授权分别登记；只有后者影响最终操作能力，禁止猜测新门槛 |
| 个人、部门、基础包与页面保存 | 新开动作缺必要读取；单纯撤权被旧动作配置拒绝或重新加回；页面导航补齐反而强迫扩读或阻断独立动作 | 硬性组合只补允许自动授予的普通读取；导航读取无法合法补齐时只提示缺入口，保留独立授权。明确收回优先，敏感读取须独立确认，多路径择合法路径 |
| 负责人委派 | 旧委派仍有配置但已失效，却显示开启；中央收回后仍显示重新授权；清理按钮可能指向非经理来源 | 区分已配置/已生效及可开启/可关闭；只能清理时不提供开启；派生读取使用真实所属权限面、上限和版本 |
| 批量批准/驳回 | 只读用户可选择审批行；单一动作权误获得另一批量动作入口 | 各按钮分别分权，执行前复核当前能力；授权变化时更新已打开页面 |
| 登录与授权刷新 | 普通权限变更撤销 refresh，造成强制退出；同次 `/me` 的新权限未更新界面 | 保留有效会话，旧 access 拒绝后刷新为当前权限；同响应同步权限和会话，隔离旧账号/旧服务器/晚到响应 |
| 到货资料学习 | 查看入口可独立写任意货品；收货重放可能再次覆盖后来主档维护 | 去除无来源独立写入口，把学习绑定真实成功登记行及原事务；保留旧草稿请求形状、命令键和重放语义 |
| 保存与失败输出 | 已成功却显示失败；无回执却断言未提交；已知原因被“网络或权限”覆盖；输出内部权限/状态码 | 区分成功后刷新失败、未知写结果和明确拒绝；保留可读业务原因，提示用权限设置中的名称，三语共享文案同步 |
