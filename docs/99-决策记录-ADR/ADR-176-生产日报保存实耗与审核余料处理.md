# ADR-176 生产日报保存实耗与审核余料处理

- 日期：2026-10-11
- 状态：本地源码候选；部署与实际岗位验收另行记录。
- 修订：[ADR-086](ADR-086-报工同页登记实际用料与收尾余料退仓.md) §2.3、[ADR-129](ADR-129-BOM设计使用数量与真实使用数量.md) §2.7 的新日报操作时序与实耗覆盖规则。
- 不改变材料守恒、原领料来源、单位换算、待退冻结、仓库实收记账、红冲和权限边界。

## 保存与审核职责

新建和编辑日报直接保存表格里的「本次实际用料」，保存时不再弹「清点剩余物料」，不按剩余数反算或改写实耗。保存仍只产生草稿；附件完成及原创建结果确认后进入该日报详情／待审核页面，不自动审核。保存失败或结果未知时保留原输入及原请求，先核对原提交。

审核页使用现有共享表格、按钮与主题。产出去向、子件用料独立展开收起，每条明细只有一行，字段横向分列；长名称单行省略并可查看全文。折叠仅影响显示，隐藏行继续参与数量校验与提交。有错误的分组自动展开。相同来源的复制主行各有独立折叠状态。

## 余料数量与处理

审核页读取服务端材料审核快照，按物料需求与真实原领料来源去重显示：来源工单、物料名称、编号／颜色、基本单位、审核前可用、本次实际用料、预计已领余料、未领直送料、本次可申请退料、处理方式。不得把多个单位的数量加成一个总数。

- 审核前可用量来自原 ISSUE 的当前未清账且未在退料途中的可结算余额，已经扣除历史结算、已退和待退冻结。
- 预计已领余料＝审核前可用－本单已保存实耗。负数是需要重新核对的冲突，不截成 0，也不修改实耗。
- 可申请退料按结耗后的实际 FIFO 来源和退料限制计算。后续批次承接、继续生产或状态不允许退料的余额留在车间，不能直接把预计余料全部视为可退。
- 未领直送料不属于已领余额，单独显示；可退的直送来源依其原来源及单位生成申请，不能重复计入已领余料。

可处理余料逐需求选择「留在车间」或「申请退回仓库」，默认需要明确选择，提供「全部可退余料退仓」与「全部留在车间」快捷操作。零余料无需选择；受限制的料只读显示留用原因。无审核权限的用户只能查看。损耗与在制仍走原有管理入口，不能为了配平自动当作消耗或退料。

## 审核、恢复与兼容

新版审核绑定日报所见版本、材料余额及退料来源指纹、逐需求处理选择。确认之前冻结完整意图，发送前持久化；请求结果未知时保持原幂等键和原决定，只读查询原回执，不能刷新余额后替换原决定重发。同键不同决定必须冲突，身份或服务器切换不得把旧快照用于新提交。

服务端在相关物料来源锁内重新核验快照，再同事务先登记实耗，后按明确选择申请退料。余额、来源或可退限制变化时拒绝并要求重新读取审核信息。审核成功不等于物料已回仓：申请只冻结额度，仓库实际接收后才记录退料并恢复库存。审核页保留审核当时材料快照与处理决定，已审后只读。

V1/V2 历史审核与回执继续兼容；旧 `countedLeftoverQty` 保存事实不做历史改写。使用新版审核时直接使用保存的实耗，不受旧头部退仓意愿或清点数覆盖。已有迁移字节不变，协议扩展使用前向迁移 V840。

## 精确计量与报工详情

报工主表继续保持原列顺序。产品下面为上下两张独立详情卡片，从货品名称列起点缩进；去向淡青、用料淡蓝灰，使用有主题色背景的展开／收起按钮。共享需求只有一份可写实耗，其他产品读取同一输入，折叠与布局不改变提交。

名称列按内容自然宽，后续字段紧邻，标题旁放条数、状态及展开按钮；空输入格以灰色字段名提示。手动添加先选择合法接收工单并填写数量，确认后保留手定去向，余量派生为唯一仓库份；取消不改变原建议，不保存未完成的空新增行。手动模式和精确请求量随草稿保存，未勾选行不占本次额度。FQC恢复仍整行一个去向，不能添加部分分拆。

来源额度、已保存实耗、单耗依据、产出批次及分组使用服务端原始精确文本；数量按万分之一整数校验，换算率按六位小数读取。大型旧数缺少精确原文时要求重核。普通多行同源累计跨过有效额度的行需填写原因；品质恢复与固定追加仍守原授权，不借普通公共额度扩量。

现有数量存储为 `NUMERIC(18,4)`，换算率为 `NUMERIC(18,6)`。正名义量按原四位 `HALF_UP` 换算后必须得到正基本量，名义量和基本量都须在原存储范围内。保存输入、正式拆份、旧稿审核和直送执行共用服务端规则；客户端提前提示、保留原数，不丢弃过小切片、不改写计量事实。实耗、不良数与旧清点量遵守原存储范围且允许 0。

`.5` 和 `1.` 这类输入可规范化为相同数值后提交，单独 `.` 无效；审核详情显示四位小数原文，`0.0001` 不显示成 0。

## 验证范围

须覆盖：有余料／余料零的直接保存与审核导航；分批报工、共享需求去重、后续承接；待退冻结与未领直送料；不足余额、版本／来源变化；逐料混合 KEEP／RETURN；同键重放与同键改决定；无权限、身份变化、网络结果未知；历史 V1/V2 兼容；审核先结耗后退料、仓库实收才恢复库存。
