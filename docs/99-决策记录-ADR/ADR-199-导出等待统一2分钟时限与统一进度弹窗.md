# ADR-199 导出 2 分钟时限与「导出/下载/批量操作统一进度弹窗」

- 日期：2026-11-08（2026-11-09 批量与下载收尾）。
- 状态：已接受；服务端与 Flutter 端实现随下一版本发布；WPF 端同步件已就位（W7-FLOW-019）。
- 关联：ADR-198（生成进度协议与 204）、[通用进度弹窗](../02-组件库/通用进度弹窗.md)、
  [组件库使用规范「界面提示与按钮加载」](../00-项目准则/09-组件库使用规范.md)。

## 问题与核查

1. 同步导出事务时限 40 秒，3 万行级导出超时；HTTP 请求截止（`FulfillmentHttpDeadlineFilter`）
   40 秒又压在事务时限之上，双重掐断。
2. 全项目导出/下载只有转圈遮罩：无进度、不可取消（2026-11-08 用户口径「弹窗可点取消，显示
   进度百分比 + 进度条，不要转圈，全项目所有导出、下载都这样」）；批量下单/批量审批同样要进度条；
   进度/加载动画做成**一个公共组件**，以后换样式只改一处。

## 决策

1. **事务时限单一常量** `ExportTransactions.TIMEOUT_SECONDS = 120`：28 处同步导出
   `@Transactional(timeout=...)` 引用它；`LegacyExportBudget` 检查点同源。HTTP 截止过滤器豁免
   导出与单据下载端点。
2. **统一进度弹窗** `lib/components/feedback/uten_progress_dialog.dart`：
   - 样式只在该文件维护（`UtenProgressBar` 条形 / `UtenProgressRing` 圆环 / 弹窗布局）；总量
     未知显示扫动条，**不伪造百分比**；弹窗内不出现转圈（契约测试钉死）。
   - 读取/下载类取消 = `immediate`（关弹窗返回 null，结果/异常吞掉）；**写入类批量取消 =
     `afterCurrent`**：当前项办完即停，不中断进行中的写请求（否则结果变「未知提交」），已办
     结果照常呈现并提示「已停止，其余 N 项未处理」，不重放、不当作全部失败。
   - **单请求型批量写入 `cancellable: false`**：一次已提交的事务无法真正取消，不提供误导性的
     「取消」（2026-11-08 用户建议先做不可取消，要改只动一个参数）。
   - 身份/服务器切换：`invalidation` + `isCurrent` 按取消收尾；`onRouteOpened` 登记弹窗路由供
     `route.isCurrent` 守卫排除自家弹窗；action 在调用方 Zone 执行（scope 传递不丢）。
3. **覆盖范围**：导出按钮（`UtenExportButton` 35 处共用）、后台导出任务弹窗、草稿批量删除
   （10 页 mixin）、循环型批量（物料分析批量下单、生产退料收料、库存出入库、销售出库核对、
   委外领料出库、车间料仓领退料、访客、员工资料修改、采购退回确认、车间批量开工/设路线、
   主档批量、HR 登记转正与送祝福、权限批量、BOM/通知批量等）、单请求型批量（各审批中心）、
   下载（批量单据 PDF/ZIP、附件字节进度、工资条、财务四对话框、安装包页、更新页圆环）。
4. **多端**：Win7 WPF `UtenBusyDialog` 增加确定进度模式（`ShowProgress`/`Report`/`Stage`），
   单位导出与更新下载接入；台账 `clients/windows_legacy/progress/work-items.json` W7-FLOW-019
   登记已迁移与未迁移项（服务端进度端点轮询、圆环组件未迁移）。

## 边界保留

- 一般保存、命令、读取等待仍用 `UtenBusyOverlay`；同一动作只用一个等待件。
- 取消是「用户不再等」，不是「服务端回滚」；后台导出任务的服务端取消走既有任务取消接口。
- 未知提交、幂等键、防连点、草稿与版本核对等既有写保护全部原样保留。
