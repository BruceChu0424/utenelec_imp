# ADR-043 合格到货精确归属与跨分析借料边界

- 日期：2026-08-21
- 状态：已采纳（源码候选；V314/#23d 未获本轮动态验收许可，目标库迁移和真实多岗位 UAT 未完成，发布 **NO-GO**）

> **2026-08-22 V337/V338 后置边界**：V307/V309 的 IQC/MAKE origin exact 继续不可变；当同一分析内 MAKE 节点幂等创建 `MAKE_COMPONENT` child 时，V337 不改 origin，而以 append-only MAKE entitlement delegation 把 current beneficiary 从父树旧后代节点交接到 child 对应直接层。旧节点可因 ownership 转移显示 `required=0`，但其合格权益不得继续从共享池扣除后又让 child 缺料。该交接与跨分析让料是两类不同命令，也不形成债务、计件或工资。child 后续完工入库仍须经 V338 仓库逐行实收，只有实收增加库存和 `iqty`。V337/V338 尚未部署和真实 UAT，详见 [ADR-046](ADR-046-生产领料仓库点收报工归属与未来计件边界.md)。

## 背景

V298 已能把采购/委外 IQC 合格库存隔离给来源
`material_analysis_id`，防止其它分析抢占。但同一联合分析内若多个产品使用
相同仓库/货品/颜色/单位，V298 没有保留原始 `analysis_material_id`，重算可把
针对 A 产品的到货分配给 B 产品。同时，页面把单项合格到货、当前分析占用和
整套齐套量混为一个「到货/可生产」概念，容易出现「质检通过但仍显示 0」。

## 决策

1. **仓库收货不等于合格入库**：收货审核只生成 IQC 待检事实；每次 `PASS`
   才写 `DIR_IN`，并在同一事务内建立分析归属和刷新。
2. **V307 精确子账**：保留 `stock_reservations` 作为唯一物理预留真相，新建
   `preplan_analysis_stock_exact_pegs`，以一对一子账保留
   `IQC PASS event -> receipt -> external request/application item -> action allocation
   -> origin analysis material UUID -> beneficiary material UUID`。新行受益方必须从原始行开始，
   原始谱系和数量不可改，数据库同时校验仓库/货品/颜色/单位、供应分摊容量和
   单次 PASS 数量守恒。V307 的 origin 与初始 `beneficiary_*` 均保持不可变，
   `UPDATE/DELETE` 继续由数据库拒绝；V309 起当前受益方改由 append-only
   entitlement 事件派生，部分让料和正式转移都不篡改原始收货/MAKE 谱系。
3. **先精确保障，再分共享池**：重算先扣安全库存，再把生效 exact peg 作为
   原物料节点的 secured coverage；同分析兄弟产品只能消费剩余共享量。超出
   action allocation 的特批超收仍进公共池，不伪造归属。
4. **安全库存口径唯一**：主重算、分仓展示和正式计划预览统一使用
   `max(publicAvailable + eligibleOwnPeg - safetyStock, 0)`，exact 身份不得
   绕过安全库存。
5. **展示分层**：服务端返回节点级 `exactPeggedQty`和分析仓维度
   `ownPeggedQty`；前端分开展示「本节点合格入库绑定」与「整套物料最多可生产」，
   并通过 45 秒只读 GET 和 CAS 冲突回读消除长期旧快照。
6. **反向可追溯且失败关闭**：V309–V314 的 `FORMALIZE/RESTORE` 事件保存
   entitlement 到正式 demand/reservation 的桥。未领料取消可恢复；已领料、已开工、
   未撤销跨分析让料或未恢复正式桥时，采购/委外/MAKE 红冲继续返回冲突。
7. **库存锁必须最先**：涉及分析归属的 IQC、任务取消和分析来源计划审核，先按
   货品/颜色稳定取得全部 `inventory dimension` 锁，再进入各自固定的单据、分析、
   action/allocation/reservation 锁序；任何分支不得持有业务行锁后再补取库存锁。

## 跨分析让料的后续决策

V288/V289 继续表示同一分析内跨产品软分配。跨分析业务不采用债务/还款模型，而是
“A 显式让料给 B，A 形成高优先级未满足需求；A 自身或 B 的下一批合格供给优先补 A”。
V309–V314 已建立权益事件、优先补齐、正式转移桥和最终审计 sweep，完整语义、状态机、权限与反向规则见
[ADR-044 跨物料分析让料与后续供给优先补齐](ADR-044-跨物料分析让料与后续供给优先补齐.md)。

## 影响与验收边界

- 新迁移：V307（exact peg 子账、容量/身份/审计守卫；不回填历史 V298 行）。
- 后续迁移：V309–V314（跨分析让料头、append-only entitlement、MAKE 精确来源、
  权限/生命周期、正式桥和延迟数量守恒）。
- 后端：采购/委外 PASS 精确归属、节点优先保障、合单明细隔离、计划预览精确加回、
  双分析让料/优先补齐、正式需求恢复、红冲门禁和库存优先锁序。
- 前端：节点 exact 数、分析聚合数、整套齐套分层展示；旧 CAS 自动回读；空闲页
  45 秒读取最新快照；跨计划候选、双方影响、优先待补和补齐来源分层展示。
- 详细审计与发布边界见
