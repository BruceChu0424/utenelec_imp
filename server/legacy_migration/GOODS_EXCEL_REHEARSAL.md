# 货品 Excel 彩排与复导

本说明是完整重建流程的货品步骤。先运行 `prepare_clean_master_data.py`，再运行
`prepare_goods_excel.py`；不要把 `import_product_lists.py --apply` 的旧补空模式
当作全量货品导入。旧工具不会新建 Excel 独有的货品。

## 顺序与命令

1. 验证并保留本次老数据库原始导出、原始 manifest 和三份 Excel 的 SHA-256。
2. 先清洗单位、颜色及所有历史引用，生成独立的 `clean` 数据集。
3. 生成货品覆盖层，不修改任何原始文件：

```powershell
python server/legacy_migration/prepare_goods_excel.py `
  --source-dir D:/uten_legacy_rehearsal/20261022/clean `
  --dictionary-dir D:/uten_legacy_rehearsal/20261022/clean `
  --excel-dir "D:/uten_legacy_inputs/product lists" `
  --crosswalk D:/uten_legacy_rehearsal/20261022/clean/warehouse_crosswalk.csv `
  --output-dir D:/uten_legacy_rehearsal/20261022/goods-overlay
```

4. 核对覆盖层 manifest、逐字段差异、异常清单和新货品分类；将其 `goods.csv`
   和 `goods_owning_warehouse.csv` 放入最终派生导入目录，保留各层 manifest。
5. 按正常工具导入单位/颜色/供应商/模具/客户/货品分类及 `goods.csv`。
6. **紧接货品主档、且必须在 BOM 和任何交易之前**，在同一事务执行
   `goods_excel_attributes.sql`，再写货品所属仓库。来源/基本单位在数量引用建立前定稿。
7. 继续导 BOM 和交易，执行完整身份、引用、库存数量及金额对账。

`goods_excel_attributes.sql` 不自带 COMMIT，依赖调用方的事务；它使用临时表并验证
每个货品身份存在、车间名称唯一。脚本本身不连接数据库。

## 身份与覆盖规则

- 货品编码是来源身份。已有编码沿用旧 `legacy_id` 和分类，Excel 非空的新名称、
  型号、材质、系列、规格、客户型号、供应商型号、状态、折扣和正常售价覆盖旧值。
  Excel 空值保留老库信息。
- 编码不在老库的 Excel 货品建立新身份，保留 Excel 原码。新身份是由编码 SHA-256
  派生的稳定负整数，与老库正整数分开。相同名称不同编码仍是不同货品，避免串色、
  串规格。重复编码报错，不能最后一行覆盖前一行。
- 新货品分类优先使用旧树中最长的准确路径后缀、唯一同名叶子或最近的唯一祖先；
  不重挂已有货品、不批量建立新的 Excel 分类树。原始完整分类路径同时进入备注。
  未能定位时挂历史未分类根，并在身份报告明确列出，供针对性修订。
- 颜色、空缺基本单位按清洗后的唯一名称映射，包含同一清洗函数的单位/颜色别名；
  目标找不到即拒绝生成。**已有非空基本单位不同于 Excel 时保留原单位**，不在导入前
  擅自重解释旧数量。单位与颜色 UUID 随正常主档导入解析，不再只写 legacy 快照。
- 模具编号、供应商及客户仅做唯一准确主档匹配，可消费引用主档层提供的
  `excel_reference_mapping.csv` 显式证据别名；别名必须指向存在的目标身份，且不能与
  另一准确旧键冲突。引用主档层的模具 code 已重新生成，只能作为显示编号；存在别名
  对照时不拿新 display code 匹配 Excel 原编号，而使用已审别名及保留的 mnumber。
  不明确的外键保持旧值，同时将
  Excel 名称、编号保留在可搜索的货品备注及原始档案，禁止猜关系。
- 当前默认供应商遵守货品来源：采购优先主采购供应商、委外优先主委外供应商，各自再
  回退通用供应商；自制仅消费通用供应商。没有对应字段时保留老值，未采用的其他路线
  供应商保留备注。另一条路线不能被伪造成备用供应商，老备用关系保持原身份。
- 来源按产品角色明确映射：自制件→自制、外购件→采购、委外件→委外。车间使用
  已有明确的车间部门映射；未知角色或车间会中止。
- 所属仓库直接按编码身份映射清洗后的良品子仓。对 Excel 没有编码对应的其他老货品，
  只有精确同名的所有 Excel 行对仓库完全一致时才补归属，不按模糊名称猜仓库。
- Excel 建议售价只有正数、基本单位与报价单位一致且比例为 1 时写货品售价；零价
  视为未配置，不覆盖老价格。折扣要求在 0–1。异常值保留证据，不强制数值转换。
- Excel 的采购超收比例、起订量和正数包装倍数进入已有主档字段；旧安全库存不自动
  激活新系统的常备补库机制。提前期、含税/票据、库存上下限等未有对应主档字段的
  有意义信息进入备注。完整 80 列始终保留在原始 JSONL。
- `【价格策略】` 无编号子行与前一货品关联存档，保留替代单位及换算率，不创建商品，
  不把替代单位的价格误当基本单位价格。其他无编号非空行会报错。

## 可核对产物

| --- | --- |
| `goods.csv` | 保持输入列顺序/结构的派生货品全量 |

| `goods_excel_issues.csv` | 类型污染、不明确外键及异常数值 |
| `goods_source_engineering_review.csv` | 没有 Excel 来源的旧货品，保持空来源，供工程核定 |
| `goods_quantity_unit_review.csv` | 旧/新基本单位冲突、有效单位与处理决定 |
| `goods_quantity_unit_history_evidence.csv` | 每种货品各历史来源的单位/换算率及引用数 |
| `goods_quantity_unit_excel_evidence.csv` | 主行及价格策略的单位、比例、售价原文 |
| `goods_quantity_unit_stock_evidence.csv` | 受影响余额逐键保留的数量、金额和重量 |
| `goods_quantity_unit_review_summary.json` | 单位冲突及受影响库存键的总数 |
| `goods_excel_field_coverage.csv` | 全部 80 列的非空数与落地策略 |
| `goods_excel_raw.jsonl` | 所有产品行及价格策略子行，附文件/工作表/行号 |
| `goods_excel_manifest.json` | 输入/工作簿及派生输出的哈希、大小和数量 |

没有 Excel 来源的旧货品不默认采购、自制或委外。`g_style` 和老装配班组 ID 仅作为
复核线索列入报告；现有迁移脚本没有可证明其等同于采购/自制/委外来源的映射，因此
本步骤不据此编造路线。报告也保留两份生成器代码的 SHA-256。

## 当前输入已确认的问题

三份工作簿共 23,104 条非空行：22,488 个唯一货品编码和 616 条价格策略子行。
其中自制 13,768、外购 4,569、委外 4,151。此为工作簿现状，不代表最终数据库验收。

- 单重列有 27 个非空值，全部是 `F812-40` 等型号文本，不能作为重量导入。
- 折扣 `D1181052=500`、`280118019=2.5`、`280118020=2.5` 超出合法值域，
  不覆盖原折扣；需要业务核对实际含义。
- 供应商和模具大量使用新 ERP 的简称/编码，不能靠相似名称自动关联老主档。
  待用户确认后应在准确匹配规则处修订并重新生成整个覆盖层。
- 历史说明声称建议售价基本全零不准确；本批有 4,045 条正数售价，必须逐单位判断。

## 历史计量保护

本次实际新包有 82 个已有非空基本单位与 Excel 不同：套→个 33、kg→个 17、块→个 13、
卷→个 10、本→个 4、包→个 2、包→kg 1、把→个 1、张→个 1。共涉及 3,593 个历史引用
出现和 93 个库存余额键，其中主仓 51 键、主仓非零 26 键。复导后以当次报告重新核对。

82 项均保留旧基本单位，Excel 新单位写入可搜索的待核备注及专门清单。售价、单重、
起订量、包装倍数按单位计量；存在单位冲突时同样不能直接覆盖这些字段。百分比来源
属性可以正常补充。历史交易和 BOM 的数量、换算率、单价、金额、重量均不改变。

只有 `280501087` 的 Excel 价格策略明确写出 1 包=25 kg，但历史购申请、订单和收货
同时出现 kg 与包且换算率都为 1，余额没有单位快照，不能据此宣布历史数量闭合。
因此继续保留旧“包”，待工程与库存共同核对全部受影响数量及反向单价后再受控转换。
不能把一个换算因子当作已经验证完整历史账的证明，亦不能从品名里的 PCS 数推断包装。

11 个离线回归测试覆盖来源覆盖层、空值保留、原始文件不变、新编码同名分身份、稳定
新增 ID、单位别名、重量污染、价格策略子行、缺失字典和重复编码。数据库执行及完整
导入验收由整体协调器的实际运行结果确认，不能用这组测试代替。新增回归还验证不同
基本单位保留历史单位/售价/单重、MOQ 待核、显式包重换算仅作证据，以及别名目标存在。
