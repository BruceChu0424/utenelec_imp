# UtenTableSurface

页面交互表格不画最外圈描边，保留圆角裁切、内部行列分隔、选中状态和输入焦点反馈。`MasterDataTableView` 和 `UtenEditableGrid` 共用 `UtenTableSurface`；`UtenRevisionTable` 委托前者，平台列功能不另绘表格外框。

表格父容器也须遵守同一规则。仅表格或标题与表格组成的 `UtenCard` 使用 `showBorder: false`；对应 `Card` 使用 `utenTableCardShape(context)`，从当前主题的 `OutlinedBorder` 复制形状并去掉 `side`，保留原有圆角。已有显式形状的表格卡片仅去掉外侧描边。普通表单、摘要、提示、空状态卡片以及打印纸面与 PDF 模板继续使用各自的边框规范，不修改全局 `CardTheme` 或 `UtenCard` 默认值。

列边界按实际可见列顺序决定：末列后没有列设置、删除或移除动作列时，不画其右外缘；后面还有真实列时，右侧分隔线属于内部网格，继续保留。表头、数据格、语义底色格与冻结副本使用同一判断，隐藏列不计入末列位置。冻结列只占可见序列的前缀，不按视口当前裁切位置去掉仍有后续列的分隔。末列的列宽拖拽手柄始终保留。

本次核查包括 AI 用量与记录、服务器任务、采购财审明细、生产用料审核、订单带入、手工需求、日报产品明细、电子执行卡预览、品质办理与详情、资产过账预览、报价修订比较及委外进度的表格父容器。品质详情分区和日报产品分组通过子组件或参数提供表格，须检查其父外壳，不能仅检查表格组件自身。

回归覆盖表格有无动作列、隐藏末列、横滚、语义格上下分隔、主题圆角保持，以及现有冻结选择、列固定、列宽拖拽、行菜单、过滤和表格父页面的交互。源码审查和组件测试不代替真实账户与业务数据的页面验收。
