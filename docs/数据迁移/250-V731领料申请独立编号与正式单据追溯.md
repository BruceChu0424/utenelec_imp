## 编号与业务身份

待仓库补料的申请原先只有执行工单号，尚未分配实际仓，也没有真实 DRAW 单据。V731 在提交申请的事务内生成 `LQ + 上海日期 YYYYMMDD + 六位日流水`，存入不可变的 `production_material_discovery_requests.request_no`。使用原 `DocNumberService`、全局编号命名空间和永久占号登记，不以 ZX 工单号或 UUID 代替领料编号。

仓库配置物料及实际仓后，原领料链按实际仓生成真实 DRAW，继续使用 `SL` 正式领料单号。一张申请可对应多张正式领料单；申请号与正式单号分别属于自己的 UUID，不转移或复用身份。仓库列表、详情和批量出库表展示实际编号，正式单保留来源申请号，申请详情按正式单号及实际仓提供入口。筛选、排序和搜索沿原单据可见性规则处理。

同键、相同意图重复提交返回原申请号；已有待处理申请时，换新键再提交返回受控 `409`，原申请号、版本、日流水及材料事实不变。服务在取号前用存在性查询判断待处理申请，不能把单列 UUID 结果当作数组解析。取消保留原号，后续新申请生成新号。仅申请编号不会创建空领料单、改库存或触发 BOM 学习。学习仍以实际发料、确认退料及审核真实产出为依据。

正式仓库任务按 `production_planning_package_document_items` 的真实需求与 DRAW 明细映射汇总，使用每张单自己的实际仓、有效数量、申请量及实发量，不能再取每笔需求的第一张动作单。一笔需求分两仓领 `2 + 3` 时，列表必须显示两张 SL，各显示本单数量，合计仍为 `5`。申请详情返回 `requestNo` 和 `drawDocuments`（正式单 UUID、单号及实际仓），兼容保留 `drawDocIds`；正式单详情的 `materialRequestNo` 按真实映射显示来源申请号，多个来源完整列出，不假设存在单一申请外键。

## 历史兼容与部署边界

迁移按历史创建时间的上海日期补号，同时避开永久占号登记里的既有编号。历史守卫仅在迁移事务内允许原号为空且其它字段完全相同的编号回填，完成后恢复业务历史守卫并加编号不可变约束。编号命名空间或前缀冲突直接中止迁移；不关闭触发器、不改库存与历史业务数量。

回填会排队执行延迟来源约束。迁移在后续 `ALTER TABLE` 前执行 `SET CONSTRAINTS trg_material_discovery_request_source IMMEDIATE`，先完成原来源校验并排空事件，避免存量库报“存在待处理触发器事件”。这不是跳过约束；约束定义仍为 `DEFERRABLE INITIALLY DEFERRED`，后续业务事务的默认延迟语义不变。共享历史守卫通过 JSON 读取编号，避免对没有 `request_no` 列的明细记录读取不存在字段。

不新增表，申请仍沿既有 CLEAR 和审计策略；永久编号保留策略不变。前向迁移前按现役发布流程备份，旧迁移字节保持不变。回退应用时保留新列和已经使用的编号，不能删除申请或领料历史。源码验证不代表业务库已安装或服务已部署。

V731 落地时(2026-09-26)验证覆盖 PENDING、CANCELLED、CONFIGURED 三种历史状态回填，逐字段比较申请及需求、预留、正式单和事件事实不变；迁移重放、同键与不同申请并发、取消重建、全局号禁止复用、日流水溢出回滚及不同键重复申请拒绝均有真实数据库回归。按实际仓生成多张正式领料单的关联展示另有列表/详情验证。完整回执及尚未完成的全量边界统一见[收尾记录](../99-项目治理/2026-09-26-领料申请批量出库与编号收尾.md)。

历史回填测试已于 2026-10-06 退役: 原 `ProductionMaterialRequestNumberMigrationPostgresTest` 把当前 Java 钉在 V730 库上启动、再手工推进 V731 验证三种历史状态补号。V731 已在所有真实库执行 (测试服务器在 V797 之后, 本地开发库在 V808), 新建空库没有 V731 之前的申请可补, 迁移字节又不可变, 回填逻辑不会再对任何真实数据运行; 而钉旧版启动当前 Java 要为每个后续迁移不断加桥 (屏蔽启动任务、逐个执行或截取后续迁移、内联补列), 故删除历史回填部分。当前行为 (同键在线重试与并发得到同一永久编号; 不同执行段并发各得独立编号并登记在全局占号表; 编号不可改、不能被其它单据类型占用, LQ 前缀不能被其它命名空间注册; 日流水溢出整笔回滚; 取消保留原号、新申请换新号; 不同键重复申请受控 409 且不消耗流水、不改材料事实; 申请编号从不创建空领料单) 由 `ProductionMaterialRequestNumberPostgresTest` 在当前完整 schema 上守护, 单笔同键重放与取消保号另见 `ProductionMaterialDiscoveryEndToEndTest`。
