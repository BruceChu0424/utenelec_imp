# ADR-038：来源单号可读化与订货仓库后移

- **状态**：已接受（源码候选；开发原库已应用 V292 数据清洗）
- **日期**：2026-08-16
- **影响**：采购、委外、生产（物料分析/计划下达）、仓库（预计到货/收货/进仓）、通知、数据迁移
- **依赖**：ADR-019（部分反转：§2.3 同仓库成单约束、订单仓库快照）、ADR-029/ADR-033（物料分析与计划前供给）、ADR-036（单据号命名空间）

## 一、背景

两个业务口径问题在 2026-08-16 复核中被提出：

1. **来源单据展示 UUID**。计划前物料分析生成的采购申请/委外申请把 `物料分析-<36位UUID>` 整串写进 `source_doc_no`（表头+明细）、`production_plan_no`、`remark`，并沿申请→订货谱系继承；自制子需求行的 `source_ref` 存 `MAKE-<UUID>`；物料分析「剩余物料已可下达」通知文案直接拼 `sourceDocumentId`。业务人员在单据页/通知里看到的是一大串不可读的 ID。
2. **订货单不该选仓库**。订货只表达「向谁买/委外、价格、结算」；「入到哪个仓库、多少数量」是到货事实。旧实现把仓库放在订货单表头，导致任务中心要求「同仓库明细才能生成一张订货」，且预计到货任务把订货时的仓库快照锁死，仓库登记实到时不能改仓。

## 二、决策

### 2.1 来源单号一律可读，UUID 只做关联键

- 物料分析路径生成的申请：来源单据 = `计划前物料分析 <分析日期>`（上海业务日）；备注 = `计划前物料分析 <日期> 备料任务自动生成`（采购）/`… 委外备料任务自动生成`（委外）。销售谱系回溯改为按 `materialAnalysisId` 精确关联（`resolveSalesOrderNos` 拆分计划/分析两路），不再字符串匹配 UUID。
- 生产计划路径生成的申请维持 `plan.billNo()`（SJ…）；MRP 明细备注「执行分段 <UUID>」「执行分段需求 <UUID>」改为分段编号（ZX…）。
- 自制子需求 `source_ref` = `自制备料 <日期> <4位尾码>`：尾码仅作同日去重，满足 `(source_type, source_ref)` 全局唯一索引；插入前查重，撞码换码重试。
- 「剩余物料已可下达」通知：事件新增 `sourceDocumentNo`（按来源类型解析 CJ/EJ/CR 单号），文案只展示单号；`sourceDocumentId` 仅作幂等/关联键。
- 历史数据由 **V292** 一次性改写（含订货/收货明细的继承行）；`preplan_supply_actions.external_document_no` 受 append-only 触发器保护不可改写，其 MAKE 短码不出现在任何界面，保留原值。
- 系统性核查口径：全库文本列按完整 UUID 正则扫描，唯一允许存 UUID 的是身份/技术键（`*_id`、审计 `target_id`、BOM `node_key`、并发锁、幂等键），任何「单号/来源/备注」展示字段不得出现 UUID。

### 2.2 订货不携带仓库，入库仓库后移到收货/进仓登记

- `purchase_orders` / `subcontract_orders` 的 `warehouse_id` 对订货**留空**（列保留，兼容历史单据）：编辑页不再显示仓库下拉（配置 `hasWarehouse: false`），列表/详情页隐藏仓库列，保存不提交仓库；编辑历史订货单会把旧值清空（订货语义上仓库不再是其事实）。
- 撤销 ADR-019「同仓库明细才能成单」约束：任务中心可跨仓库选行分解，一张订货单仍只按供应商/委外商约束拆单。申请单保留仓库（计划侧库存分配、齐套投影与领料继续使用）。
- 预计到货：`inbound_expectations.warehouse_id` 允许为空；`canCreateReceipt` 不再把仓库当登记门槛；任务卡片仓库行显示「登记到货时选择」。
- 收货/进仓：仓库必填（前端 `warehouseRequired`，后端「收货单/进仓单需指定仓库」兜底），到货登记模式不再锁仓；到货提示条明确「请选择本次入库仓库」。委外发料/材料退/损耗/退货等以仓库为物理事实的单据不受影响。

## 三、迁移

| 迁移 | 作用 |
|---|---|
| V292 | 存量「物料分析-UUID」来源标签/备注改写为「计划前物料分析 <日期>」；订货/收货明细继承行同步改写；`MAKE_COMPONENT.source_ref` 改写为「自制备料 <创建日> <id前4位>」 |

## 四、后果

- 好处：所有单据的来源/备注对业务人员可读；通知不再暴露 UUID；订货职责边界更清楚（订货=商业行为，入库=仓库事实）；跨仓申请可合并分解，减少无谓分单。
- 代价：历史订货单上的仓库值在下次编辑保存后清空（详情页订货不再展示仓库）；`preplan_supply_actions` 历史 MAKE 短码永久留存（不可改、不可见）；依赖字符串 `物料分析-` 前缀做谱系匹配的旧逻辑必须走 id（本 ADR 一并改掉）。
- 2026-08-16 全链路核查补记：当日发现后端分解预览仍残留「不同仓库请分别生成订货单」409（`PurchaseRequestService` / `SubcontractApplicationService`），与本 ADR §2.2 矛盾——已移除该约束并同步改写采购/委外 `DecompositionPreviewTest` 为断言跨仓行同批返回（行上 `warehouse_id` 仅作申请侧展示原样透传）；至此 §2.2 前后端口径一致。
- 待续：公司目标库 V292 复核；物料分析若无日期冲突可考虑后续铸造正式 WLFX 单号（当前以可读标签替代，不做命名空间注册）。
