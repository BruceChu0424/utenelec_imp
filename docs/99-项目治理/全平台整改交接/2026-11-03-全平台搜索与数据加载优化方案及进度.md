### 4.2 发现清册与闭环

既有 [875 条/30 模块查询入口清单](B1-2026-10-25-查询入口覆盖清单.csv)、[公共能力差异清单](B1-2026-10-25-查询公共能力调用与差异.csv)、[报表清单](11-B1报表入口与差异清单.csv)、[NativeFacets 清册](B1-2026-10-26-NativeFacets17调用清册.csv)及 [offset 清单](B1-2026-10-26-分页offset迁移清单.csv)作为发现起点。875 是历史清单行数，不是当前已实测数量；本次搜索/分页模式扫描命中 140 个 Dart 候选文件，也不等于完整入口数或已验收数量。

批准实施后，在本专项下建立并维护逐入口附表，至少包含：

```text
入口ID / 模块 / 平台与runtimeFamily / 实际路由 / 页面或弹窗入口
入口类型（主搜索、表头、树、选择器、列表、统计、历史、导出等）
调用组件 / repository / API / 服务 / SQL或表与索引
主体、对象范围、数据来源和权限版本 / 状态、日期、搜索与排序合同
列表、总数、徽章、分面各自范围 / 依赖的公共任务ID / 同类根因ID
待迁移与保留差异 / 前后测量 / 实际交互证据 / 状态与剩余项
```

双向核对“路由/菜单/页面/弹窗 → API”和“GET/经确认的纯读POST/查询服务/后台读取 → 调用方”，包含类级与方法级路由组合、别名和动态调用；不能漏掉只读POST，也不能仅凭名称把未知POST当作无副作用查询执行。官网另核对其公开与管理路由。搜索扫描用于发现，人工沿实际可达链及真实运行请求确认。无入口、已退役、不适用的条目要有依据，不通过排除旧记录缩小分母。

同页的不同动作、候选框、详情子区块、Shell保活、多窗口、宽窄布局与平台条件分支按需拆成子记录。排序、自动刷新、返回和窗口恢复也能触发加载，不能因没有搜索框就遗漏。现行入口、历史清单差异、未识别调用及未说明平台分支全部有归属后，才可结束发现阶段。

同一根因修到公共维护入口，并列出全部调用方；逐一迁移和验证后才关闭根因项。公共组件通过但调用方未接、漏接弹窗、只查主列表或仅测管理员，都属于未完成。后续发现新入口补入清册并重开相应覆盖项，不用旧清单封闭范围。

WPF 以当前唯一台账为准。权限页、销售/采购/财务列表及多类任务包仍有未迁移项，不用共享后端推定原生端已经完成；也不因候选身份跳过已实现同责入口。

## 五 搜索与普通加载的优化方案

### 5.1 先建立分段耗时

对每类入口区分输入防抖、客户端等待/优先级排队、传输、鉴权、连接池与锁等待、SQL执行、行映射/序列化、JSON解析、模型投影、状态发布及首屏绘制。用请求关联标识、路由模板、计数和耗时追踪，不记录搜索词、请求/响应正文、凭据和业务输入。

服务端核对实际表/索引体积、活动与历史分布、统计信息、失效索引、死元组与 autovacuum、长事务/锁、连接等待和后台作业竞争。先读既有受控指标；如尚未启用 `pg_stat_statements`，记录条件及启用影响，不为调查擅自重启服务。不能把连接池调大、延长超时或更换硬件当作已定位根因。

共享环境只做有界、带超时的只读观察，不运行重压或长时间全库扫描。真实量级执行计划、`EXPLAIN (ANALYZE, BUFFERS)`、夹具和故障试验在明确隔离环境执行；`ANALYZE` 形式会实际执行查询，不能当作无成本观察。

### 5.2 修查询与索引

权限员工列表优先返回只需的账号、员工、部门、岗位摘要，避免逐条实体加载及无关敏感字段读取。对所选账号使用精确身份读取或按 ID 补全，避免为恢复选择再次模糊搜索完整列表。保留已离职账号支持、当前能力判定及草稿。

按最终 SQL 验证组合索引、部分索引、排序、OR 条件和精确总数成本。数据库/API内部分批有界，稳定排序加唯一身份；游标用于完整读取，不重新提供用户页码、滚动补页或邻页预测。排序和总数合同不能无说明改变。新增索引核算写放大、构建锁、WAL、空间和失败残留；迁移编号以实施时目录为准，已应用 SQL 保持原字节。

单字/两字中文包含搜索单列测试。`pg_trgm` 没有可提取 trigram 时可能退化为全索引扫描，不承诺加 GIN 即解决；不能改成只允许前缀或至少两个字来换取速度。小目录可用有界候选与低成本投影；大目录依据分布比较适合的检索方案，复杂索引仅在实测需要时引入。禁止静默改变包含、相关性、多词、空格和特殊字符语义。

### 5.3 完整摘要与首屏依赖

2026-11-04追加要求覆盖早期按用户页码的方案：在当前授权、来源、搜索、筛选与排序范围内，公共 `loadCompletePagedResult` / `loadCompleteCursorSnapshot` 以100条（已有明确200条协议保留）有界内部批次收齐当前列表摘要，首续批一致；向界面交付一个完整本地结果。去掉邻页、五页窗口、滚动补几页和私有本地切片，滚动只做虚拟绘制。完整摘要内存随结果数增长，不宣称常数内存或数据库全表一次返回。

货品多授权根继续由服务端形成完整受控范围，再按同一稳定顺序读取；不回到客户端分根拉全和重排。树定位、名称、分类计数及非必要表头候选不阻塞已经具备完整资格的行；必要权限、价格、可办资格及版本未齐时不开放动作。详情/编辑仍按原入口读取全部原单，不把列表摘要当作可保存的完整编辑模型。

本机草稿、正式单据与恢复票据按原owner完整合并；未完成正式单据读取前不能选删尚未排除的本机checkpoint。失败、0条、未就绪和已退休明确区分。导出、纸面PDF页、受控文件分块、原写批上限与公开访客隐私查询保留其原合同。

### 5.4 公共读取生命周期

在现有 `UtenSearchBar`、读取身份、分页缓存和优先级预算上补齐调用方：输入改变即退休旧读，保留 IME/防抖；适合的只读请求取消或合并，未能取消的旧传输继续受物理预算约束。离页、隐藏、切账号/权限/服务器、A→B→A、写后刷新和库实例替换均不能复活旧结果。

缓存键包含完整查询、主体/代理身份、权限与读范围版本、来源、仓库/部门、日期、排序、列筛选、页大小及必要写修订；禁止跨范围复用。复用 count/facets 时必须明确各自保留的筛选条件与一致性时点。若总数需独立加载或改为 hasMore，先列所有调用方并审查合同，不直接删除精确总数。

只保留既有显式分类首批准备及共享物理预算；它只准备一个有界首批，不是滚动邻页缓存。显式刷新、真实返回和写后刷新取得最新事实。列表不等待无关计数/表头读取，但不能以空值冒充0或悄悄修改统计新鲜度。网络慢和解析/渲染卡顿分别修复，复用 Web Worker、原生 isolate 与 `UiWorkBudget`，不再制造一套缓存或网络层。

界面相关实施默认使用 `frontend-design`，保留 Uten 主题和组件。无独立副标题/提示句，必要说明贴近字段或标题提示 icon。等待按钮接 `UtenBusyOverlay`、防连点和完整收尾；自动输入搜索保持输入、取消和导航可用，不以按钮规范阻塞整页。具体遵守[组件规范](../../00-项目准则/09-组件库使用规范.md)和[性能规范](../../00-项目准则/07-性能自适应.md)。只读取消不推定业务写入未提交，不自动重放未知命令。

## 六 任务中心与活动数据方案

### 6.1 保持原统计口径再减少工作量

逐中心登记列表、当前分类总数、其他分类徽章、状态分面、列头候选各自的筛选合同。列表可以按当前状态缩小，其他分类计数可能需要更广范围；日期与搜索是否影响各统计逐项核实。

采购/委外比较“窄列表候选 + 原口径轻量汇总”与现实现；只把可证明等价的谓词提前，避免为广汇总先富化所有列表字段。无搜索 overview 已有免富化分支，委外齐套已有批量共享，继续复用。不能简单删除 `MATERIALIZED` 或让所有统计只剩当前分类。

仓库逐来源检查四次查询重复的 UNION、聚合和来源判定。可选同一一致性快照复用候选、合并必要元数据或延迟非必要分面；活动/历史、仓库范围、实物行、空单、草稿归属及反冲历史保持原合同。生产/品质/财审/HR/研发按实际模型处理，已有“先分页身份再批量细节”的路径保留，不重做整个任务系统。

### 6.2 历史来源判定保持唯一语义

测量函数调用次数、不同单据数、单据明细数与来源图深度，找出跨明细和跨查询重复工作。探索在保留完整来源字段时使用现有 row 入口减少原行重读；按单据身份去重，批量或在同一读取阶段复用判定。授权、来源与业务筛选必须在分页之前完成，不能拿回一页后再排除历史。

`legacy_id IS NULL` 不能代替完整来源判断；CURRENT/LEGACY/ALL、父单/FK/类型化来源、列表/徽章/导出/来源选择与写入拒绝均需对照。保留数据库写 guard，不能让历史 `0/-1` 状态重新进入可办理草稿队列。该判定依赖其他表，不能强标 `IMMUTABLE` 后硬建表达式索引。持久化来源闭包需维护所有来源变化，作为有独立证明的条件性方案。

### 6.3 活动索引与读取投影的选择

| 方案 | 采用条件 | 边界与回退 |
|---|---|---|
| 原主表 + 组合/活动部分索引 | 优先选择；当前筛选、排序和谓词能受益 | 保留主单及来源；验证实际参数化计划能使用索引，不能只看索引存在 |
| 活动任务读取投影 | 查询优化后仍有明确跨表聚合热点，读收益足以覆盖维护成本 | 按域保存最小任务身份、阶段、排序和必要展示；可重建、可对账，切回原查询可回退 |
| 时间分区/独立历史层 | 大表规模、裁剪/维护收益和恢复方案均有证据 | 检查唯一键/外键、跨年未完单、规划成本和峰值空间，不按日期隐藏待办 |
| 全业务活动/历史双主表 | 暂不作为默认方案；需证明前三种不足且整体迁移可控 | 涉及单头明细、来源、原件、反审/售后和对账，必须另有具体设计与授权 |

活动投影需覆盖新建、草稿修改、提交、审核、驳回、撤回、完成、关闭、重开、红冲和迟到事实。选择同事务维护或带版本/幂等的可靠事件更新，并验证重建、乱序、重复、中断、积压和恢复。异步方案必须约定新建/撤回/重开等变化的最大可见延迟、监测水位及超限回退原查询的条件；写后读取和新出现待办不得在未说明的延迟中失踪。撤权与对象授权依当前权威实时复核，不等待投影追平。原单据继续承担金额、数量、库存、权限与写命令权威；旧投影不能授权写入。先影子比对，充分验证后切读，保留回退与差异告警。

## 七 历史分层与长期增长

“活动/历史业务分类”“具备归档资格”“物理冷热层”分别判断。创建很早但未闭环的单据仍是活动；已进历史列表不自动具备物理归档资格；复制校验成功不代表允许退出热层。

承接现有 B3，核实审计/Outbox 分层、调度运行、跨层读取、永久防重身份与生命周期登记的实际状态。先治理确实影响在线查询的大载荷和重复计算，再按业务族评估完整单据分层。原件和业务证据永久保留，缓存/凭据/未提交临时片段按各自合同处理；不恢复按年龄全库清空或业务清空能力。

归档资格至少核查：最晚结清证据、未清应收应付、品质/售后、库存/在途/预占与来源权益、成本层、公共余量、委外责任、活跃引用、反审代际与冻结。24个月是既有候选建议，不能作为自动执行授权；缺结清证据不能用创建日替代。

完整对象族按“候选 → 即时资格/版本/引用复核 → 无损复制 → 行数、数量、金额、原文、哈希和附件核验 → 历史读取/恢复验证 → 受控切换 → 观察及回退”推进。支持暂停、租约、断点、重放、复制期间新增引用与修改检测；数据库和文件跨存储一致性要有明确协议。冷层不可用、撤权、缺件、损坏、原单号精确查询和来源追溯均须实测。

本轮方案不直接搬移、删除业务历史或原件。数据表分区、实际热层退出和线上配置变更在具体收益、完整对象清单、恢复与回退证据具备后提交审阅；已授权范围内的小步骤持续完成，不逐个停问。冷热治理无需作为当前几十条待办提速的前置条件。

### 8.1 计时口径与目标

沿用 [07 方案性能预算](07-整体优化统一方案-2026-09-30.md#101-性能目标)，固定硬件、运行配置、源码、数据规模、权限账号、并发、网络和后台负载后冻结本轮具体预算。下表均为建议目标，尚未测得达标；不能事后降低标准凑通过。

| 场景 | 拟定常规局域网目标 | 计时口径 |
|---|---|---|
| 员工搜索及普通列表有界 API | p95 ≤ 500ms；约定繁忙档 ≤ 1s | 请求发出至完整响应，不含输入防抖；SQL、排队与序列化另拆分 |
| 员工搜索首批结果 | p95 ≤ 800ms 为本轮建议预算 | 最后一次有效输入变化至首批正确可见，包含既有300ms防抖；IME组合单列 |
| 普通任务中心首屏 | p95 ≤ 1s 为本轮建议预算 | 分类/导航动作至当前正确行可见；其他可操作完成另受普通页面预算约束 |
| 普通页面可操作 | p95 ≤ 2s；约定繁忙档 ≤ 3s | 从触发动作到所需信息和合法操作就绪，不能只算出现骨架 |
| 在线历史首屏 | p95 ≤ 3s | 全条件生效后的正确首屏；冷层取回按对象/包大小单列 |
| 输入、取消和导航 | 记录事件延迟、长帧与最长停顿，按 B0 设备预算验收 | 后端慢、大返回和后台任务竞争时仍响应；不以动画转动或进程存活代替验收 |

首屏绘制、合法操作就绪、当前查询完整收集、服务端SQL执行、序列化和传输各有独立时钟。记录请求起止与行数/字节，标明第一次可见行和完整结果接受时点；数据库SQL样本与真实客户端端到端样本分别标识。滚动零数据请求记录在渲染证据列，打开耗时另给前后同源、同数据、同权限和可比负载证据。开发机还有并行构建或其它测试时记录当轮负载；只清理本任务owned进程，不停止用户或其它任务进程。

记录 p50/p95/p99、最长停顿、样本数、系统错误/超时率、取消率、SQL次数、扫描/返回行、函数调用、响应字节、连接/锁等待、CPU/I/O/内存/GC/WAL和队列。业务校验失败单列；计数减少但实耗变慢不算通过。云端/远程网络、冷/热缓存和不同客户端分别测量，不把局域网预算直接当 WAN 承诺。
