# 物料反查与追溯中心

> 路由保持 `/production/where-used`。本设计在现有 BOM 反查和共用实际用料追溯之上扩展，读侧查询不修改库存、成本、领料、报工或历史批次数据。

## 用户需要解决的问题

入口围绕“我要查什么”组织，结果围绕“从哪里来、用到哪里去、凭什么确认”组织。

| 查询入口 | 主要问题 | 必须保留的限定 |
| --- | --- | --- |
| 货品 | 塑料颗粒用在哪些产品；某产品用了哪些物料 | 编号/名称只用于选对象，查询绑定货品 UUID；原料、半成品、产品和历史停用身份都可作为起点 |
| 单据 | 这张采购单到货、入库及后续分配到哪里；委外单发了什么、回了什么 | 先选择单据类型和真实单据，不按编号前缀或名称猜归属；同号跨类型必须可区分 |
| 生产批次 | 这批产品何时报工、产出多少、有哪些用料依据及相关凭证 | 入口使用真实报工输出批次；不把工单、质检入库批次或供应商原料批号混为同一种身份 |

货品与生产批次支持“用到哪些产品”“用了哪些物料”两个方向。具体单据直接显示该单据已有的来源和关联，不提供没有业务意义的方向切换。不能以查询方向改变实际凭证的数量含义。

## 参考与取舍

- [Microsoft Dynamics 365 物料追溯](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/trace-items-raw-materials-inventory-production-sales)以货品、跟踪维度、时间范围和方向定位，结果按实际单据/交易串联，并允许从节点继续查询。采用其“起点明确、凭证下钻”的思路，不照搬复杂操作栏。
- [Odoo 批次追溯](https://www.odoo.com/documentation/19.0/applications/inventory_and_mrp/inventory/product_management/product_tracking/lots.html)通过批次查看库存移动及相关收发货记录。借鉴其“货品与批次分开、同一批次由真实移动记录连接”的原则。
- [GS1 Global Traceability Standard](https://www.gs1.org/sites/default/files/docs/traceability/GS1_Global_Traceability_Standard_i2.pdf)将追溯建立在收货、转化、发运等关键事件，以及对象、人员、地点、时间、原因等要素之上。对应本系统优先使用已过账领退、核销、入库及报工外键，不用当前 BOM 补造实际历史。

界面沿用 ERP 现有主题、字体、间距、表格和自适应面板；不引入另一套视觉系统或图表组件。关系多时以可筛选明细表和按需展开凭证为主，避免默认显示一张拥挤的大关系网。

## 页面结构

1. 顶部使用同一个查询区域：查询卡内摆放货品/单据/批次入口、共用对象选择字段、查询与筛选；结果模式及实际追溯方向独立放在卡片下方，与结果正文共左缘，不叠加查询卡的内边距。单据入口不显示无意义的 BOM 与方向控件；小屏筛选使用有文字提示的图标入口，控件自然重排。依据说明位于标题栏，日期等次要条件按需展开。
2. 结果查看方式：实际追溯、BOM 与历史关系。保留现有独立反查权限、五种来源范围、历史日期、分页排序和关系详情。
3. 主结果使用共用业务表格，优先显示关联货品、证据类型、工单/批次、时间与对应数量。数量未知显示未知，不显示假零；不同单位、不同证据层级不相加。
4. 行详情使用同一自适应面板，查看来源凭证、领退/核销、报工/回货、批次、参与人和数据依据。详细口径放在相关记录处，不常驻多段提示。
5. 无生产使用记录时，仍应区分“单据存在但尚无后续使用”“当前范围没有结果”“没有查看权限”“查询失败”。已知来源记录不能因无生产行而消失。

货品选择复用销售的右侧分类选择器；关系详情复用与实际追溯一致的自适应侧栏。2026-10-20 起，BOM 与历史关系结果默认将产品名称、编号、颜色分列，单格不再重复拼接三类信息；领、退、核销与期间分摊仍各保留自己的数量和单位。表格键及列键保持，个人列布局继续使用原有存储。

关系结果支持多选，右下显示已选数量。有 `goods:bom:edit` 的员工可通过「一键替换」选择新组件，弹窗上方展示当前组件，下方选择替换成的组件。只有含当前有效 BOM 关系的产品可以选择替换；历史证据不能修改。服务端先预览实际承载关系与全部受影响产品，二次确认后原子替换；共享子组件对未选产品的影响必须显示。基本单位或领料方式不同不直接沿用用量。具体事务和共享结构规则见 [ADR-185](../99-决策记录-ADR/ADR-185-组装编辑草稿与共享组件同步.md)。

「导出筛选结果」要求独立 `production_where_used:export` 权限，可选 Excel 或 PDF 及密码保护，包含所查组件名称、编号和 UUID、来源及历史日期条件、排序、操作员、导出时间和完整筛选结果。导出所有匹配页，最多 50000 行；超过限制须缩小筛选。当前 BOM 与历史证据分列保留原口径，不能汇总冒充实际耗用。

2026-10-17 起，查询入口按 `frontend-design` 复用添加货品中模具字段的 `UtenReferencePickerField`：左侧可直接输入，300ms 防抖显示最多 8 个匹配候选，右侧“选择”携带当前查找文字打开原有滑入选择框。点选候选或在滑窗确认后才绑定真实 UUID；取消恢复此前选择，清除同时清空结果。货品联想与完整窗口共用反查专用材料接口，保留历史停用、软删除和占位候选；单据/批次共用追溯对象接口。账号、权限、服务器或入口变化立即使旧候选失效。

工具栏继续使用 Uten 主题与字体，货品类型入口桌面最小宽 112，随选值及字体适配；输入和选择按钮整体最大宽 360。下拉、输入、查询和筛选的桌面高度统一为 40，触控最小高度为 48；窄屏和大字体下换行，保留完整输入与选择入口。

## 员工使用示例

以下名称仅说明操作方式，不表示系统已有这些业务记录。

- **查塑料用在什么产品上**：入口选“货品”，按名称或编号选择具体塑料，进入“实际追溯 → 用到哪些产品”。表格先显示关联产品、编号和生产批次；双击一行查看车间、领退料、耗用依据、报工日期、全单参与人和来源分配。点击关联产品可继续查询后续产品，逐段追踪半成品到成品。
- **从成品倒查用料**：选择该成品，在“实际追溯”中切换“用了哪些物料”，查看已记录的生产用料与来源凭证。委外成品只有在冻结明细归属、真实发料关系和对象权限均成立时，才显示对应原料及估算核销；有权查看的成品收货记录不因此被隐藏。可继续选择原料，查询其余使用去向。
- **按采购单或委外单查**：入口选“单据”，输入单号；同号不同类型分别列出，选择明确的业务类型。采购单显示已授权的订货、收货和已有后续生产分配；没有下游记录时仍保留来源。委外单显示已有的订货、回货、发料及冻结 BOM 估算核销。凭证能否打开继续遵循该单据的权限。
- **查某一生产批次**：入口选“生产批次”，用批号或报工单号定位真实输出批次。查看本批产量及对应报工；没有逐批原料分摊时，不把整项任务的累计领料和耗用填成本批数值。未编批号的输出以“报工单号 · 第 N 行产出批次”区分。
- **只想知道理论上哪些产品会用这种料**：切换“BOM 与历史关系”，沿用原有多层 BOM、当前/历史来源和日期筛选。理论关系和已发生的实际领耗分别查看，避免将 BOM 配方误当成真实消耗记录。
## 当前系统的证据层级

| 证据 | 可证明 | 不能据此声称 |
| --- | --- | --- |
| 采购订单行 → 收货行 → IQC 放行 → 库存移动 | 订货、到货、放行及实际入库 | 收货审批就等于入库；IQC 批次就是供应商批号 |
| 入库来源分配 → 需求/预留/领料行 | 已确定的来源分配关系 | 该采购批次已经被某产品逐批消耗 |
| 实际领退料过账与核销；`issue_posting_id` | 实际领、退及可核对的原 ISSUE 核销 | 没有该外键的老数据也有精确批次来源 |
| 日报用料 `(report_id, demand_id)` 与输出批次 | 报工、用料及批次之间已有的关联 | 同日报多个产品/批次各自都消耗了完整一份用料 |
| 自制件直送来源事件 → 分配 → 来源报工行/输出批次 | 有明确来源份额的内部实物流转 | 这条强证据可以推广到所有采购原料混仓流转 |
| 委外回货核销 → 原发料行 | 按冻结 BOM 核销对应发料 | `FROZEN_BOM_ESTIMATE` 就是供应商实测耗用 |
| 期间盘点结算分摊 | 期间实际耗用及产品分摊依据 | 每个产品或批次的逐件实测用量 |
| 当前 BOM、计划需求、物料登记记忆 | 理论、计划或已登记身份 | 实际领料、消耗或确切历史原料批次 |

普通跨仓调拨和混仓没有贯穿的采购原批次外键时，不按日期 FIFO、库存均价池或当前 BOM 反推。查到来源分配或估算依据时明确显示；未留存的信息保持未知。历史缺口不以数据回填掩盖。

## 权限与精度

- `production_where_used:view` 保留原有关系报表和货品选择能力，不自动升级为查看全域单据、人员、供应商和批次明细。
- 新单据搜索与实际明细使用对应业务查看权限、对象 owner 范围和真实仓库授权谓词；计数与分页采用相同谓词。仓库参与者身份或“选择了某个仓”都不等于被授权查看所有仓。
- 供应商名称单独按原权限遮蔽；未授权对象不能通过候选、计数、单号或详情存在性泄露。
- 账号、代操作、服务器及真实权限变化使旧响应和详情失效；相同权限内容的普通资料刷新不清空合法查询。
- 数量使用精确十进制文本。生产产量不跨不同物料行重复求和；日报参与人不解释为逐产品操作人；批次筛选不把任务累计数量冒充该批数量。

## 已接入的查询契约

`GET /api/production/reports/where-used/subjects` 使用 `kind=goods|document|batch`、`keyword`、`exact`、`page`、`size`。空输入不请求；同号不同类型保留为不同候选；选中后以 `type + UUID` 固定身份。

当前支持 `GOODS`、`PURCHASE_ORDER`、`SUBCONTRACT_ORDER`、`PRODUCTION_PLAN`、`PRODUCTION_REPORT`、`STOCK_DOC`、`PRODUCTION_OUTPUT_LOT`。界面把单据明确命名为采购订货、委外订货等，不把本阶段入口声称为任意 ERP 单据搜索。

`GET /api/production/reports/where-used/trace` 使用 `subjectType`、`subjectId`、`direction`、可选 `dateFrom/dateTo` 和分页。`items` 复用共用实际追溯行；`sources` 保留订货、收货、委外发料/估算核销、报工和库存等可读凭证；`sourcesTruncated` 明示超过有界来源窗口；`coverageNotes` 说明缺失或不能逐批分摊的事实。

- 日报产出附带真实输出批次 UUID、产出明细行号和本批产量；没有已编批号时，用“报工单号 · 第 N 行产出批次”作为定位说明，不伪造供应商批号。
- 订单、日报、日期或批次筛选不会把任务累计领退和核销量冒充该对象用量；没有逐批分摊时数量保持未知。
- 委外物料凭证在授权且冻结归属可靠时附带关联委外产品和订货单。缺失、父单键不一致或无对象权限时不补猜。
- 来源日期为对应业务单据日期。冻结 BOM 核销量是发料行累计估算核销，不解释为该日实测用量。库存来源附带真实 `docType`，详情按实际业务类型导航，不由单号猜测。
- 实际表、行详情和继续追溯共用 `GoodsProductionTraceView`。可以从产品或输出批次继续查询，逐段查看半成品和后续产品关系。

## 验收范围

覆盖货品双向查询、单号同名候选、无下游来源记录、生产/入库批次区分、多来源共用领料、部分退料与反审、多产品多批次不重复用量、委外估算标签、期间分摊、精确数量、权限撤销与跨 owner/仓拒绝、页码越界、乱序响应、小屏/两倍字号和深浅主题。

本页不承诺历史原料批次记录绝对完整；原关系报表的旧数据治理边界仍见[物料反查产成品页](物料反查产成品页.md)。
