# 部门默认权限矩阵（V212 基线 + 后续增量）

> 权威来源：V212 基线及后续只追加迁移；生产物料分析增量见 `V234__production_material_analysis.sql`
> 配套文档：[权限管理页.md](../03-页面/权限管理页.md)、[ADR-011](../99-决策记录-ADR/ADR-011-工作台部门分区与动态权限配置.md)
> 日期：2026-08-05

## 背景

部门默认权限此前由 V29/V31-57/V99/V130/V183/V196/V198/V200/V204 等迁移零散累加。2026-08-03 dev 库
TRUNCATE 业务表后这些种子不再重跑，部门权限页全空。V212 把 15 个业务部门的默认权限收敛为**单一权威
来源**：对每个配置部门做受控重置（先 `DELETE` 全部权限，再 `INSERT` 矩阵集，`ON CONFLICT DO NOTHING`）。

## 模型与原则

- 有效权限 = 全员基础（employee 角色包）∪ 部门配置（本部门 + **所有上级**，递归向上取并集）∪ 个人加授 − 个人收回；超管恒全量。
- **向上递归继承**：挂在父部门的权限自动对子部门员工生效 → 写权限**下沉到叶子部门**，避免父级堆权限导致越权下传。
- **3 个管理中心与公司节点保持空白**，不在父级配权限。
- **高危个人-only 权限任何部门都不授予**：`audit_log:view/export`（V173 触发器硬拒绝部门级）、
  `authorization:manage`、`user:manage`、`stock:balance:adjust`、`finance_asset:approve/post/dispose/export`、
  `finance_asset_period:manage`、`production_material_analysis:bom_override`。需逐条个人点名；V234 不向任何部门默认插入 `bom_override`。
- 全员基础（不在本矩阵）：`profile:edit:self`、`expense:apply`、`notice:read`、`suggestion:submit`、
  `visitor:apply`、`visitor:host-confirm`、`payroll:view:self`。

## V233 增量：对象级授权 `*:view:all`（2026-08-08）

V212 是受控重置的权威源、已应用不可改。V233（`V233__object_level_auth_view_all.sql`）在其之上**追加**
4 个「查看全部」权限点（采购/委外/生产/库存单据按制单人 `maker_id` 隔离后的全量旁路）+ 对应部门授权
（`ON CONFLICT DO NOTHING`，可在授权页调整）：

| 权限点 | 默认授予部门 | 说明 |
|---|---|---|
| `purchase:view:all` | GM, DEPT_FIN, DEPT_QA | 严格：采购员 own 自己的单 |
| `subcontract:view:all` | GM, DEPT_FIN, DEPT_QA | 严格：委外员 own 自己的单 |
| `production_plan:view:all` | GM, DEPT_PROD, DEPT_ENG, SUB_PLAN | 计划 maker=计划员，车间须全见 |
| `stock_doc:view:all` | GM, DEPT_FIN, SUB_WH | 仓库须看全部流水（含生产自动生成） |

其余角色默认按 `maker_id` 只看自己制单的；个人/部门可在授权页额外加授 `*:view:all` 或用
`user_data_scopes`（scope=purchase/subcontract/production_plan/stock_doc）委托「看+改某归属人的单」。
详见 [对象级授权统一实施报告](../99-项目治理/2026-08-08-对象级授权统一实施报告.md)。

## V234 增量：生产物料分析与生产计划审批（2026-08-08）

V212 是已应用历史基线，不再改写。V234 在其上追加 8 个权限及以下默认部门授权；该表是源码候选口径，目标库是否存在必须以现场 `flyway_schema_history` 和授权对账为准：

| 权限点 | V234 默认授予部门 | 边界 |
|---|---|---|
| `production_material_analysis:view` | `GM`, `DEPT_PROD`, `DEPT_ENG`, `DEPT_PMC`, `SUB_PLAN` | 查看 analysis/item/material、立即/预计量和历史 |
| `production_material_analysis:manage` | `GM`, `DEPT_PMC`, `SUB_PLAN` | 新建和刷新分析；不能批准计划 |
| `production_material_analysis:route` | `GM`, `DEPT_PMC`, `SUB_PLAN` | 确认 BUY/MAKE/SUBCONTRACT；覆盖建议须原因和审计 |
| `production_material_analysis:notify` | `GM`, `DEPT_PMC`, `SUB_PLAN` | 下达 `preplan_supply_actions`，不是普通消息 |
| `production_material_analysis:generate` | `GM`, `DEPT_PMC`, `SUB_PLAN` | 只生成计划草稿、ACTIVE planning draft、SUBMITTED plan link；零预留 |
| `production_material_analysis:reallocate` | `GM`, `DEPT_PMC`, `SUB_PLAN` | 调整跨产品分析分配；已预留 READY 必须先反向 |
| `production_plan:approve` | `GM`, `SUB_PLAN` | 原子重算并形成 READY、完整预留、DRAW 和销售分摊；门控 `approveNow` |
| `production_material_analysis:bom_override` | **无部门默认授权** | 高风险单次例外；仅超级管理员固有能力或逐人加授，不进入部门默认/批量全部授权 |

V234 的 `bom_override` 不得因 `manage/generate/approve` 被隐含获得。功能权限仍叠加 maker、组织、销售来源和仓库对象范围；`view` 也不自动授予写操作。

## 待业务确认的判断点

以下在矩阵中已按业务推断落实，提请复核：

1. **委外 8 类 edit 归 `DEPT_SALES`/`DEPT_RAIL`**：依 V53（销售跟单员驱动委外）。若实际由 PMC 负责，需迁移到 SUB_PURCHASE。
2. **`goods:edit` 同时给 `DEPT_PMC` 与 `DEPT_ENG`**：PMC 维护货品主档（V41），工程维护 BOM/结构。若货品主档只归一方，删另一处。
3. ~~`sales_order:change_planned` 归 `DEPT_PROD`~~ → **已按用户决定收窄到 `SUB_PLAN` + `GM`**（2026-08-05）：原挂 `DEPT_PROD` 会下传 6 车间，导致车间工人可改已排产订单；现归计划部（日常改量）与管理层（审批），不挂生产部。该码不在「全部授权」排除清单内（仅 `sales_order:priority`/`reallocate` 被「全部授权」排除）。
4. **`GM` 是否需要 `*_report:export`**：当前只给 report:view，未给 export（数据出境保守）。如需高管导出报表，个人点名或矩阵补。

## 维护方式

- **调整业务部门默认权限**：V212 已应用后只能追加新迁移，禁止直接修改。页面手工配置在运行库上即时生效，但不等于新环境默认矩阵已同步。
- **新增权限点**：仍遵循「功能落地时随版本化迁移登记 `permissions` 行 + 按归属 `INSERT INTO department_permissions`」，V212 是这些授予的收敛归宿。

### V226 —— 货品售价/折扣编辑 + 成本可见（2026-08-07）

`V226__goods_price_cost_permissions.sql` 新增两个「主数据」权限点并授予 `DEPT_FIN`：

| 权限码 | 名称 | 含义 | 默认授予 |
|---|---|---|---|
| `goods:price:edit` | 编辑货品售价/折扣 | 写侧字段级权限（仿 V141 `employee:pii:edit`）：在 `GoodsService.create/update` 中，未持权而改 `price`/`discount` → 403；未触碰（原样回传）放行。前端对无权者把售价/折扣锁定只读。 | `DEPT_FIN` |
| `goods:cost:view` | 查看货品成本 | 读侧脱敏（仿 V90 `sales_order:price:view` + `SalesPriceMasker`）：`GoodsCostMasker.canView()` 为假时，货品详情把 18 个成本字段置 null 并标 `costMasked=true`，前端隐藏「成本预算」Tab。 | `DEPT_FIN` |

同时给 `DEPT_FIN` **补授 `goods:edit`**：改售价要走 `PUT /master/goods/{id}`（控制器 `@PreAuthorize("goods:edit")`），而 V212 只给了财务 `goods:view`，故 V226 补 `goods:edit` 让财务能通过编辑表单维护售价/折扣（其它字段同样可改）。

- 超管恒有全量；其他部门/个人可在「权限管理」页用**个人权限覆盖**（grants/revokes）增授/回收这两个码——例如把改价权精确到某位「财务负责人」而非整部门。
- 折扣字段复用老库 `goods.zk`（详见 [31-货品组装BOM与成本预算](31-货品组装BOM与成本预算.md)）。

### V227 —— 货品折扣可见（2026-08-07）

`V227__goods_discount_view_permission.sql` 新增读侧字段级脱敏权限点 `goods:discount:view`（「主数据」，sort_order 25），并默认授予销售两条线 + 财务部：

| 权限码 | 名称 | 含义 | 默认授予 |
|---|---|---|---|
| `goods:discount:view` | 查看货品折扣 | 读侧脱敏（仿 V226 `goods:cost:view`）：`GoodsService.canViewDiscount()` 为假时，货品详情把 `discount` 置 null 并标 `discountMasked=true`、列表项 `discount` 置 null，前端隐藏详情折扣字段/查看行/列表折扣列。写侧配套：`ensurePriceEditIfTouched` 对不可查看者跳过折扣触碰判定（否则他们改品名等正常编辑会被折扣 403 误伤）、`apply` 仅可查看者折扣落库（顺带修复 V226 遗漏的 `setDiscount`，使「财务改折扣」真正生效）。 | `DEPT_SALES` / `DEPT_RAIL` / `DEPT_FIN` |

- 授权集对齐既有的「销售价可见」`sales_order:price:view`（恰好授予 `DEPT_SALES`+`DEPT_RAIL`），再加维护折扣的 `DEPT_FIN`：销售需带价/折扣谈单、财务维护价折扣；生产/仓库/PMC 等其余部门看不到折扣。
- 折扣的**编辑**仍由 V226 的 `goods:price:edit`（默认仅 `DEPT_FIN`）控制；本权限只管**查看**。即：销售能看不能改、财务能看能改、其它部门既看不到也改不了。
- 超管恒有全量；其他部门/个人可在「权限管理」页按需增授/回收。

### V228 —— 权限目录两级分类（module 一级 + category 二级）（2026-08-07）

`V228__permission_module_taxonomy.sql` **不改任何授权**，只重组权限目录的分类结构，解决权限页
"约 30 个扁平分组、同域被拆散、找权限找不到"的问题：

- 新增 `permissions.module` 列（一级功能模块），`category` 规范为二级子类。目录由后端按
  `(module, category)` 两级分组下发，前端「功能模块 → 子类 → 权限项」两级折叠展示。
- 11 个一级模块（顺序由后端固定）：基础资料 / 销售管理 / 采购管理 / 委外管理 / 生产管理 / 仓库管理 /
  财税管理 / 工程研发 / 人事行政 / 品质检测 / 系统管理。权威归类表见 [55-权限模块分类](55-权限模块分类.md)。
- 合并被历史种子拆散的同域分组：库存（旧「库存」+「库存管理」）、生产（旧「生产」+「生产管理」+
  「生产计划」+「生产报表」）、报销（旧「报销」+「员工报销」）；退货质检 / 收货待检从「库存管理」
  归回各自单据模块（销售 / 采购）。
- 覆盖目录内全部权限点（含 V227 的 `goods:discount:view`，一并从「主数据」归入「基础资料·货品资料」）；
  任何未覆盖者兜底为「其他」模块，便于发现后补归类。不影响有效权限计算（不增删权限点、不动
  `department_permissions`），仅改变目录在权限页的呈现分组。
- 配套前端：权限行不再显示原始权限代码（仅中文名 + 来源标签），避免暴露后端/库结构标识。
