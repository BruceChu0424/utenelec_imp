让计划员（含年纪较大的员工）能勾选多个产品一起做物料分析：默认看产品结论（能生产几个、还缺几种料），逐层展开 BOM 树看每个组件的备料进度，按物料汇总缺口给采购/委外下单，并支持把某条路径的现货"先调给更急的产品用"，全程留痕、可撤销。

### 二期 · 现货层借用（调货，全链路源码候选）

1. **服务端**（`MaterialAnalysisService` / `MaterialAnalysisController` / `MaterialAnalysisContracts`）：
   - `POST /api/production/material-analyses/{id}/borrows`、`POST /{id}/borrows/{borrowId}/revoke`，权限 `production_material_analysis:reallocate`，版本+指纹 CAS + 幂等键（复用 `production_material_analysis_commands`）。
   - **精确投影数学**：存在 ACTIVE 借用时，先跑无借用基线投影 → 每笔生效量 m = min（申请量，借出方基线剩余可借出，借入方基线剩余缺口），按创建顺序扣减两侧容量（多笔不超借）→ 以 `cap`（借出节点覆盖上限 = 基线 − Σm出）+ `secured`（借入节点池外锁定 Σm入）+ 维度 earmark 重跑主投影。**不变量：借出方精确 −m、借入方精确 +m、第三方路径分配完全不变、池守恒（pool′ + Σsecured = pool）**；产品级「最多可生产」同步变化。

2. **Flutter**：节点行双向徽标（「已被调走 N 件 · 调给 X」/「已调入 N 件 · 来自 Y」/生效 0 显示「暂未生效」）；节点详情区逐笔明细 +「撤销」（原因必填）；「调给其它产品」对话框——候选只列其它产品缺同种料的直接组件路径、数量默认=min(已分配, 对方缺口)、超上限红字、确认前大白话影响预览（"A 会重新缺 N 件；B 缺口减少 N 件"）；服务端 allowedActions 不含 REALLOCATE 时入口全部隐藏（本地权限不能绕过）。
3. **数据库（并发会话主导，已合流）**：V288 `production_material_analysis_borrows`（含复合外键 (analysis_id, from/to_material_id) 防跨分析端点）；V289 守卫（INSERT 必须 ACTIVE 且 last_effective_qty=0、身份与申请量不可变、仅 ACTIVE→REVOKED、禁物理删除、审计触发器覆盖刷新）。

## 四、必须遵守的规范（改这块代码前重读）

- **ADR-033**：每条 `analysisItemId + path/nodeKey` 是独立节点任务；同货多路径不得合并任务身份；共享库存池只在仓货色维度分配且回写各路径；采购/委外可在下游合单但保留逐路径 allocation。
- **ADR-029 不变量**：分析软分配不写 `stock_reservations`、不扣在手；在途/待检/冻结/不合格不计入齐套；generate 不预留，approve 才原子建 READY+预留+DRAW+销售分摊；追加式反向，不物理删除业务事实。
- **Flyway 纪律**：已进任一共享环境 `flyway_schema_history` 的迁移不得修改/改名/重排，修正只能新增更高版本。V288/V289 目前**未提交未应用**，仍可改；一旦合入主干即冻结。
- **权限模型**：页面权限点 `production_material_analysis:view/manage/route/notify/generate/reallocate/bom_override` + `production_plan:approve`；按钮 = 客户端权限 ∩ 服务端 `allowedActions`；前端隐藏不能代替服务端校验。
- **写操作纪律**：版本 + 指纹 CAS；幂等键（同一键不同请求体必须 409）；>500 条按稳定任务身份排序后分块、续批用最新 version+fingerprint、幂等键绑定请求前事实而非批次序号。
- **适老化基线**（`docs/03-页面/三架构缺口-适老化UX规范.md`）：正文 ≥18px、数字 ≥24px、按钮 ≥48–56dp、一页一事、大白话、默认值先行、危险二次确认写清影响、错误给"下一步"不给错误码、状态不靠单一颜色。
- **进度口径**：IQC PASS 才算合格入库；生产进度 = 审核报工 fqty；成品 = 审核入库 iqty。三者永不混用。

## 六、关键设计决策（改之前先理解为什么）

1. **生产顺序 = 依赖门禁 + 自由调度**：父件只在直接下层齐套后才能安排（硬约束）；同层不同分支可任意并行（无编排顺序）。不要做"严格自底向上排队"。
2. **借用只动软分配层**：正式预留（READY 计划）不可抢。借用生效量按基线投影精确计算，避免 SAP 式"动态 peg 说不清谁少了"——本实现借出方精确 −m、第三方零漂移。
3. **按物料汇总是投影不是任务**：聚合键 = 货品+颜色+单位；任何写入都落到逐路径节点。
4. **进度条单一口径**：节点进度 = 备料覆盖（合格现货÷需求）；排产后的生产进度用文字状态与子计划承担，不要塞进同一条进度条。
5. **撤销只许 ACTIVE→REVOKED**：追加式留痕，审计靠 V289 守卫 + 审计触发器，不靠人工自觉。
