# V506 受控库存开账与历史余额待核对

日期：2026-09-07。属于[存货价值与成本闭环方案](../01-规划/2026-09-07-存货价值与成本闭环重构方案.md)的独立内部能力；没有自动修改旧GL，也没有把开账端口当作完整财务审批页面。

## 正数量开账

[InventoryOpeningPort](../../server/src/main/java/com/uten/imp/application/port/InventoryOpeningPort.java) 与 [InventoryOpeningService](../../server/src/main/java/com/uten/imp/features/stock/valuation/InventoryOpeningService.java) 独立负责开账。普通价值出入库及后补仍由 `InventoryValuationPort/Service` 负责；只在 `stock/valuation` 包内共享事实写入与校验辅助，不建立第二个数量管理器。

`open(Opening)` 要求外层已经持有共享库存键锁和业务事务，独立核对实际数量与原记录金额（NULL也精确比较）。只对尚无价值头的历史池执行一次；前后数量完全相同，**不生成库存movement**。原余额整行JSON、原数量、原金额、开账原因和操作者通过不可变记录保留。

- 明确核定金额：可建立已核定的价值来源；金额必须由有权应用入口确认，不能从旧余额自动采纳。
- 尚未核定：记录已知组成部分或NULL，并保持PENDING；写入当前价值投影的0只代表目前已确认组成部分为0，不代表真实总成本为0。
- 后续核定：对返回的原 `sourceCostNodeId` 调用已有来源调整。已出库部分按原关系追加到COGS/在制等去向，在库部分追加到库存；原movement和旧账不改。
- 数量或旧金额已变化、缺金额却要求最终确认、无锁、同键异体、重复建立新基准均拒绝。原请求重放只返回原结果。

真实回归：数量7、旧记录999，待证开账后数量仍7，没有新movement。发出2后核定总成本70，得到COGS20、在库5/价值50；旧999证据仍在。该结果没有说明旧GL需要调整929；GL差额必须另按其原来源核对。

## 零数量旧额与新周期分开

`startEmptyCycle(EmptyCycle)` 只处理实际数量为0、但旧金额非零/缺失或仍有未证历史状态的池。它建立**当前空库存**的0价值基准，同时创建独立OPEN历史核对案件。旧金额、原余额整行、原价值池快照、时间与责任人都留在案件和追加事件中。

旧金额不进入新周期的价值分配边，不自动变成损失，也不表示财务差额已经结清。之后的新到货按新批准来源正常计价，不会分到旧残值；空周期开账SOURCE禁止普通 `adjustSource`，防止后来把旧金额塞回新货成本。`EmptyCycleValue` 分别返回当前开账结果与历史案件状态，两种状态不得混为一谈。

真实回归：数量0、旧记录−2000，独立立案后新到10/价值100，再发6，剩余4/价值40、COGS60；旧−2000仍为OPEN待核对，没有加到新货里。旧金额NULL同样保留未知，不伪装成已核定零历史成本。

## 核对事实与关闭闸门

新增三张业务表，均为CLEAR：

| 表 | 责任 |
|---|---|
| stock_value_openings | 一池一次的受控基准、原余额完整证据、原/新价值与开账模式。 |
| stock_value_legacy_balance_cases | 与新价值链隔离的原金额待核对事项；原证据不改，状态由办结事实推进。 |
| stock_value_legacy_balance_case_events | OPENED、NOTE、RESOLVED追加事件，保留责任人、幂等键、请求hash及批准依据快照。 |

核对说明可以追加；不能改删原记录。关闭只接受 [InventoryLegacyResolutionEvidencePort](../../server/src/main/java/com/uten/imp/application/port/InventoryLegacyResolutionEvidencePort.java) 返回的、本案有效的独立财务审批证据：已完成的前向调整，或明确批准的不需调整决定。core不按旧金额自行计算损失，不生成凭证，也不把 `gl_vouchers.status=1` 当作审批。

该证据port当前没有生产实现，因此普通调用不能关闭案件。未来财务工作包应在持有审批/来源锁的事务内提供只读证据，不得在案件锁之后再补取上游锁。接口和UI需继续落实独立库存历史差额审批、前向GL、期间与反向约束；本包没有把这些未交付能力标为已完成。

## 数据库保护与兼容

V500、V503、V504、V505原字节不改。V506前向增加开账事件形状，保留数量/来源/节点/物理配对守卫；仅在同事务已存在完整开账依据时允许LEGACY_UNVERIFIED池建立ACTIVE价值头。

V500价值事实、投影、节点/边和managed stock balance约束，以及本包开账/历史案件保护，统一 `ENABLE ALWAYS`。复制模式不能改历史金额、原事件或破坏物理/价值配对。新增三表在V506内通过既有唯一锚点加入runtime清空策略，不修改已冻结V504；原业务清空仍保留主档、权限和审计策略。

迁移本身不自动开账、不改任何旧数量/金额/GL、不关闭历史事项。未使用开账端口的非空旧池继续保持未证；不能靠当前标准成本、售价或默认零值修平。原库的完整源数据备份与受控切换仍是部署前提。
