# ADR-078 完整子批生产与实际用料余料退仓

- 状态：已接受（2026-09-12）；V560/V561/V562定义本轮基础事实。本文记录源码规则，实际迁移、运行服务及岗位验收状态另记。
- 关联：[ADR-046](ADR-046-生产领料仓库点收报工归属与未来计件边界.md)、[ADR-073](ADR-073-本批物料履约与同主仓分仓领料.md)、[ADR-075](ADR-075-合格来源跟随实际入库仓与车间通知.md)、[ADR-077](ADR-077-车间明确提交领料后进入仓库任务.md)。

## 分批安排

部分到料可支持的是“现有合格实物能配齐的完整子批”。例如原任务 1,000 件，全部所需材料能配成 300 套时，本次可安排最多 300 件，剩余 700 件继续等待。某种必需材料完全没有、整套数量为零时仍不能开工。在途、待检、未正式入库量不能用来计算可生产量。

同理，销售和计划都是1000部手机，而各项必需物料只能配10套时，可先建立并办理10部的执行子批，保留其余990。下达量、当前完整可生产量、本次核对量、安排后余量分别显示；员工主动少安排时，余量不一律表示缺料。

我的车间任务中，适用的 WAITING 行提供“分批领料”。进入独立页面只读取当前可齐套量，显示原待生产量、本次数量、剩余量和本批实际仓物料汇总。修改数量后必须重新核对，明确“确认本批领料”才在一个事务内拆批并提交本批仓库任务；仓库实际发齐后仍须车间开工。剩余到料后可继续分批，不重复建立采购、委外或自制供给责任。

接口为 `POST /api/production/execution-batches/preview` 与 `/submit`，共同要求 `production_execution:view`、`production_execution:start` 和任务对象范围；预览不写业务。提交绑定审阅版本、数量、物料快照与幂等身份，未知回执保留原意图重试。沿用前批已领物料而没有新增领料的续批使用“确认本批生产”，不能显示成另一张空领料申请。页面操作见[我的车间任务](../03-页面/我的车间任务页.md)。

原执行段的计划数量、物料需求和销售来源属于历史事实，不能直接改小。新增 `production_execution_segment_splits` 记录原段、本批、余批及数量关系；原段以 CANCELLED 退出活动容量，并由谱系显示为“已拆分为生产批次”。新段保留同计划、产品、来源计划行及初次车间/负责人安排，物料和销售分摊数量守恒。后续正式车间分配仍按原权限和状态办理。

线性、整包、固定批量物料都按冻结 BOM 的精确规则计算。后续子批用累计需求函数之差 `F(此前批量 + 本次数量) - F(此前批量)`，不能用原总需求除以数量得到平均单耗。BOM 指纹变化时拒绝改算原任务。整包/固定物料已经分配到前批的部分，须有前批实际领取证明；后续零增量是有分批来源证明的特殊情况，不能伪装成无 BOM 的 ZERO_MATERIAL。

入口面向物料分析来源、自动等料且没有正式供给 peg、预留、领料或报工事实的任务。人工暂缓须先解除；已有领料或报工的任务保留原事实并继续按本次实际数量分次报工、登记用料，不通用重写历史数量。存在旧正式供给绑定或 BOM 变更时给明确原因，禁止通过拆批脱开来源链。

需要依赖缺少来源事件的历史预留才能供给本批时，明确提示先核对历史占用，不把旧安全库存政策中的不可兑现量显示为可生产量。现代合格来源与普通公共库存沿当前实际预算处理；历史无事件池不在本轮未经对账重写。

## 实际用料与剩余物料

登记页、材料台账、登记记录和冲销输入均显示需求基础单位。实物领退料仍保留原 DRAW 的单位与换算率，后台按基础单位守恒；货品、颜色、单位和仓库均按系统 UUID 关联。

后续批次没有新增领料，但继续使用前批材料时，通过 `material-usage-sources` 只读取得有分批证明的真实原领料任务。员工选择该来源后，登记仍提交原执行段、原需求和原 ISSUE，不另造耗用来源；原任务的读取和写入权限分别复核。不能把被替换的 WAITING 父段 ID 当作实际领料来源。

每次“本次登记”使用独立意图 UUID。连续两批各消耗 10 千克应各记 10 千克，不能因为同数量、同原因生成相同幂等键而吞掉第二次。网络回执不确定时锁定原数量和键，仅允许同意图重试；面板不得通过拖拽、遮罩或返回丢失未确认意图。

成功登记后若仍有可处理余额，自动提示“本次剩余物料”：

- 留待后续生产：只保留现有已领未登记余额，不伪造耗用、损耗或 LEGAL_WIP。
- 核对退仓：查看精确原 ISSUE 来源、原领料单、实际仓库、单位及可退量，可填写部分退仓数量。确认后建立正式待收退料申请，其余余额仍可留用。

## 仓库退料闭环

V560 使用三张追加式事实表记录请求、原 ISSUE 切片及取消；按实际原仓生成 WDRAW。车间沿 `production_material:settle` 和精确执行段对象范围提交、查看、撤回，无需授予仓库单据创建或审批权限。

待仓库收料量冻结原 ISSUE 的可用额度，不能重复退料、登记耗用或反向绕过。车间撤回尚未收到的申请后释放额度，并保留取消记录。仓库在生产领料任务中心的“生产退料 → 待收料”核对实物，明确确认后沿既有 WDRAW 审核、GOOD_RETURN 与库存入账事务处理，才增加库存并减少车间持有量。每个实际仓独立一单、独立确认；实物数量与申请不同则暂不确认，由车间撤回后按实际数量重提。

新余料申请限已开工任务；未开工领错料沿仓库“取消出库”恢复原可领量。整包、固定批量或精确舍入产生的共享物料仍被后续非终态批次承接时，显示留用原因并从可退量中扣除，不能先退回再让后续批次永久缺少原领料证明。全部可登记余额都已提交退仓时，车间显示“待仓库收退料 / 查看退料进度”，不再催重复登记耗用。

正式待收申请计入仓库待办及父级计数，普通草稿统计排除这类已提交请求，避免重复计数。确认实收、撤回、登记用料后均刷新车间余额和仓库待办。已实收后的修正继续走原正式反向链，不修改原收料历史。

## 验证

同一拆批家族的物料成本和产出继续使用原执行任务成本池，并按原批准产量分配；每次子批的报工、实际入库仓与物理流水保持独立 UUID。固定材料跨 40/60 两批时，不得把全部成本提前压到首批，后批也不得无来源零成本。V562 只接入原库存价值算法的权威来源范围，成本修订、提前发货和反向仍由原账本处理。

分批报工继续保留原批准总量，不能借旧 `isFinal` 提前完结路径把原分析计划数量改小或自动另建补产。成本分母按同家族当前有效末端批准量取值；正常 40/60 两批仍为 100，不能把已退役的父段重复算入。

必须验证完整子批上限、重复拆余批、跨仓精确数量、原段/物料/销售分摊守恒、过期预览整批拒绝、人工暂缓与越权拒绝；以及连续同量耗用、未知回执同键重试、部分余料留用、请求冻结、取消释放、真实收料加库存和重复收料幂等。正式 Flyway 空库重放、真实服务与 PostgreSQL 组合测试和 Flutter 交互验证分别记录，不以源码或预览截图替代运行系统验收。
