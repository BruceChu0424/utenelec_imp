# ADR-185 组装编辑草稿与共享组件同步

状态：已接受，2026-10-20。

## 问题

组装树中每个组件都是独立货品。组件的子层来自该组件自身的组装清单，多处引用共享同一份结构。在产品内修改嵌套组件，应当同步该组件自身及所有引用位置。先逐条修改正式清单、退出时才询问同步，会使取消确认失去意义。

## 决定

界面按 `frontend-design` 复用现有 Uten 主题、树表、选择器、对话框和权限，不建立另一套组件或颜色体系。

组装信息默认只读。右下显示已选数量、编辑模式与有权限的审计模式；进入编辑需要 `goods:bom:edit`。添加、粘贴另需 `goods:bom:create`，删除另需 `goods:bom:delete`，审计标记仍独立使用 `goods:bom:audit`。编辑与审计互斥，激活模式通过按钮颜色和退出文案表明。刷新移到详情页右上，位于价格分析左侧。

进入编辑模式后，添加组件、删除、右键编辑/新增/复制/粘贴和拖拽才能执行。右键未选中的行先单选该行；右键已在多选集合中的行保留多选。复制保存所选关系的设计参数及货品引用，孙层仍由引用组件自身提供。无选中时粘贴至本货品顶层；选中一行时粘贴为该行组件的子层；多选时要求先明确唯一目标。剪贴板不写系统剪贴板，账号、权限或服务地址变化后清空。

每次动作自动暂存当前页面编辑会话的内存草稿，显示暂存反馈；这些动作不提前修改正式清单。草稿不承诺应用关闭或浏览器刷新后恢复。退出并保存时先由服务端验证完整操作序列，列出实际修改父件及其他引用范围，再二次确认。取消确认继续保留草稿。确认后一个事务提交全部操作，更新组件自身，所有引用随共享关系读取最新结构。没有仅覆盖单个引用实例的分叉配方。

返回、审计切换和价格分析等离开入口先完成保存流程。导入和重新学习沿用各自专用确认流程，执行前先处理当前编辑草稿。账号、权限或服务器边界变化使旧草稿与旧回调失效，禁止沿用旧身份提交。

## 服务端约束

| 接口 | 用途 |
| --- | --- |
| `GET /master/goods/{parent}/bom/edit/snapshot` | 读取组件行与原始内容指纹 |
| `POST /master/goods/{root}/bom/edit/preview` | 验证草稿操作、原始快照、归属与同步影响，返回限时预览凭证 |
| `POST /master/goods/{root}/bom/edit/commit` | 复核身份、权限、快照、影响范围和确认意图后原子提交 |

预览在独立事务内重放原有权威组装命令，并强制回滚实体、触发器和事务 outbox 写入。不得产生外发通知或正式货品编辑历史。提交绑定原操作者、登录会话、根货品、操作内容和预览时的结构；成功响应丢失时同一凭证不重复修改。

按既有 V739 顺序先锁父件，再取得共享组装图锁，等待后重新读取。继续使用既有循环、重复关系、颜色、数量精度、期间领料、学习接管、审计清除及成本重算规则。新行临时身份映射为正式关系身份，后续编辑、删除与移动不能串行。

单重与父件资料偏差等非阻断提醒随预览返回，保存确认展示最终草稿仍然存在的提醒。快照指纹使用服务端 HMAC，原始单价等敏感字段不出服务端。

V883 将正式提交纳入货品编辑历史，并记录原命令实际要求的权限集合。跨层移动虽然用软删旧关系、新建关系保留来源谱系，但只要求原有编辑权限；真实新增、删除在撤回及重做时仍复核对应细分权限，不能按数据库行形状猜测原操作。

## 货品列表顶层批量维护

2026-10-20 根据用户确认，货品资料列表的多选右键菜单提供批量添加组件、批量移除指定组件。复用现有 Uten 货品选择器、数量输入、期间料确认与组装权威服务，不在页头重复堆放批量按钮。指定旧组件换新组件继续由物料反查承担。

| 动作 | 范围与行为 | 权限 |
| --- | --- | --- |
| 批量添加组件 | 1 至 50 个所选货品的顶层；同一组件 UUID 已存在则跳过，保留原用量、审计及学习身份；只追加缺少的组件 | `goods:bom:edit` + `goods:bom:create` |
| 批量移除指定组件 | 只移除所选货品直接挂接的指定组件关系；未命中跳过，不删除组件货品主档，不深入修改共用半成品内部 | `goods:bom:edit` + `goods:bom:delete` |
| 覆盖整份组装清单 | 保留为单个货品的明确操作，使用已复制组件形成完整目标清单；清单外的顶层关系被移除，同组件继续按既有 REPLACE 对齐规则维护 | `goods:bom:edit` + `goods:bom:create` + `goods:bom:delete` |

添加默认且本批处理固定为所选货品顶层。若所选货品自身是共用半成品，修改其顶层也会影响引用该货品的其他产品，确认前仍展示这些真实影响，不因“只处理顶层”隐藏共享关系。

批量操作先调用 `POST /master/goods/bom/batch-maintenance/preview`，展示每个目标的新增、更新、移除及跳过数量、共享影响与现有业务提醒；再次确认才调用 `/commit`。覆盖动作明确命名为“覆盖整份组装清单”，与指定组件替换分开；原清空入口若使用，则明确为“清空顶层组装清单”，同样经过移除预览。

预览重放原有 APPEND/REPLACE 或批量删除服务并回滚；正式提交在一个事务内重新核对完整指纹、权限、身份与影响范围。添加/覆盖每次最多选择 200 个组件，移除最多 500 个组件，与原批量删除上限一致；实际新增、更新、移除合计不超过 2000 条。重复目标或重复组件请求拒绝，不按名字猜身份。零变化可返回明确回执，不产生正式业务修改。提交结果未知时保留原凭证重试，不能重新预览后重复添加。

V884 将新提交路径登记为货品编辑历史，并记录实际动作权限。原“复制货品后新建副本并附带组件”仍走新建货品流程，不被已有货品的编辑、删除门槛误拦。

## 物料反查批量替换与导出

关系结果默认将产品名称、编号、颜色分列。多选只能选择含当前有效 BOM 的产品；仅历史证据的行不可替换。拥有反查查看及组装编辑权限的员工可选择替换组件，先预览实际承载关系和所有受影响父件，再二次确认整批替换。共享子组件可能影响未勾选的其他产品，必须在确认清单中明确列出。替换保留原关系的设计用量与管控参数，基本单位或领料方式不同则拒绝批量沿用。

历史生产快照、已冻结需求、实际领退耗用、报工和追溯凭证不被当前配方修改重写。

导出要求独立 `production_where_used:export` 权限，仍需要反查查看权。格式选择 Excel 或 PDF，并可选择密码保护；导出全部筛选结果，记录所查组件身份、来源及日期条件、排序、操作员、服务器生成的导出时间和证据口径。继续经过统一下载保护、导出频率/并发限制与审计。

## 验证范围

必须覆盖只读与动态撤权、跨产品复制粘贴、嵌套共享组件、取消确认零正式写入、事务回滚、循环/重复/单位错误、快照冲突、预览过期、同一成功请求重放、历史行保护和受控导出。定向源码与隔离数据库验证不等同于业务库迁移、部署或真实岗位验收。
