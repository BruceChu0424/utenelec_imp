## 批量办理与数量核对

批量详情采用上方关键信息卡片、下方统一明细表。顶部按单据展示单号、日期、经办人及来源/状态；只展示接口实际提供的人员与时间。单据信息区域默认展开并可整体收起，多张单据的全部明细汇总在同一张表中。发出仓默认带出原单实际仓库，放在明细表内；同一 EC 在表内改仓时同步该单全部行，服务端仍按一张单据一个实际仓库校验。单据备注与明细备注分别放在表内，沿用各自原值和保存字段。右下角批量办理/确认出库等主操作统一 `UtenButtonType.danger` 红色大按钮；返回、刷新和核实结果保留次级样式。

| 分类 | 核对与执行 |
|---|---|
| 销售出库 | 只有「确认出库」一个动作（V582 一步式）。货品、数量、单位、实际仓库、建议库位、实际库位及来源订单逐行展示；无仓提交的单在此选实际叶仓。 |
| 委外出库 | 按计划及其已有 EC 草稿载入，表内核对目标件、本次量、重量和实际仓库。同计划多实际仓草稿分别办理，不互借预留。保存与审核沿用现有权限、来源 UUID 和数量校验。 |
| 其它 / 产成品出库 | 只勾选未关闭草稿，按整单数量出库。同单明细一起选中；需改量时先编辑草稿。明细展示实际库位与当前建议库位，避免把主档建议冒充出库事实。 |

四类批量均沿用逐单事务，首个异常停止后续请求，并区分成功、失败/待核实和未处理；不得声称整批原子回滚。已成功单据不重复提交。不确定回执先只读核实，再由用户重新确认后续操作；业务写请求不随网络恢复自动重放。

其它与产成品出库使用 `GET /api/stock/docs/{id}/outbound-review` 取得明细和 `reviewToken`，确认提交 `POST /api/stock/docs/{id}/approve-reviewed`，请求体为 `{expectedReviewToken}`。服务端持单据锁校验核对快照后再进入原有审批/库存事务；货品、数量、换算率、仓库、来源或明细集合变化返回冲突。快照不是授权或幂等凭据，仍执行原权限和对象范围校验；旧单笔 `/approve` 入口保持兼容。

委外 `PREPARED_OUTBOUND` 是有效目标件出仓类型。`readyOutboundQty` 扣除了所有未审草稿占用，只表示还能新分配给草稿的量；办理已有草稿时，本次上限为 `readyOutboundQty + 本张草稿原数量`，不能把同计划其他草稿的数量加进来。即使 `ready=0`，已有 10000 数量的草稿仍可办理 10000；真正未知路线继续禁止执行。数据库实收、备齐量和预留不因显示修复而改写。

## 一、页面与权限

- 路由：`/warehouse/tasks/outbound`（路由名 `warehouse-outbound-tasks`；
  静态段 tasks 须先于 `/warehouse/:code` 单据路由声明）。
- **进入权限（任一满足）**：`sales_shipment:warehouse-work`（销售出库段）、
  `subcontract_outbound:view`（委外出库段）、`stock_doc:view`（其它/产成品出库段）。
  页内分段按各自权限显隐；出仓历史另需 `warehouse_subcontract_outbound_history:view`。
- 新建按钮按 `stock_doc:create` 门控（`DocumentPermissionCatalog.stockDocument`）；
  服务端 `@PreAuthorize` 独立兜底。
- 页面权限面：`warehouse.outbound-tasks`（V450），精确关联上述权限码及
  `subcontract_outbound:` / `stock_doc:` 动作前缀。

## 二、页面结构

对齐品质部检查结果页范式：**进页面不预选大类**（内容区显示「在上方选择分类后
开始办理」引导空态，不加载任何分段数据）；各分段的小类行只随选中的大类出现
（结构上等价于大类未选时小类锁定）。

1. **页级工具条**（`UtenFilterToolbar` 大类分段 + 胶囊搜索）：
   - 分段与徽章（只挂真实待办；**草稿不计入待办数**）：销售出库
     （徽章 = 销售待出库数）/ 委外出库（徽章 = 待出仓任务数）/ 其它出库 /
     产成品出库（两类通用单据分段只有草稿与历史，不挂徽章）。
   - 搜索关键字 300ms 防抖后统一下发给当前分段。
2. **销售出库段**（embedded `WarehouseSalesOutboundWorkbench`）：
   小类分段 = **待出库**（挂待办徽章）/ **已出库(历史)**；
   双击进 `/warehouse/sales-outbound/:id` 详情办理。仓库不能自建销售出库单——
   任务全部来自财务已放行的销售出货（边界提示见独立页）。
3. **委外出库段**：小类分段 = 待出仓任务（挂待办徽章，与父分类徽章同数）|
   出仓历史（终态不挂）。
   - 待出仓任务 = embedded `WarehouseSubcontractOutboundWorkbench`，
     双击进 `/warehouse/subcontract-outbound/:planId` 拣货出仓（草稿即"新建"）。
   - 出仓历史 = embedded `WarehouseDocumentHistoryView(subcontractMaterialIssue)`
     （仓库实物视图，只读）。
4. **其它出库 / 产成品出库段**（`WarehouseStockDocSegment`）：
   不渲染 icon+标题分段头（分类语境由上方大类分段表达）；状态小类 =
   全部/草稿/已审(历史)/红冲，**进页面不预选**（空集 = 不过滤），各段不挂徽章
   （草稿不计入待办数，已审/红冲是历史）；全部分类栏最下方为总结行
   （左「共 N 条 · 双击办理」、右新建按钮按 `stock_doc:create` 门控）；
   双击进 `/warehouse/OTHER_OUT|FINISHED_OUT/:id` 详情。

## 三、角标口径

- 分段徽章（只挂真实待办，草稿不计入）：销售出库 =
  `GET /warehouse/sales-outbound/count`（财务已放行且尚未确认出库的单，V450 新增、V582 收窄口径，
  与列表同一读范围 Specification）；委外出库 =
  `GET /warehouse/subcontract-outbound/tasks/count`；
  其它出库 / 产成品出库不挂（只有草稿与历史）。
- hub「出库任务中心」卡徽标 = 两段之和（`WarehouseOutboundTaskBadge`）；
  工作台仓库卡 = 三张任务中心卡之和（见[页面总览](页面总览.md)工作台区）。
- 任一来源加载中不显示半程合计；任一失败显示异常图标（不把未知伪装成 0）。

## 四、业务口径与边界

- 销售出库只在财务放行（financeAudit=1 且未驳回）后出现；已出库(SHIPPED)、
  取消、红冲不计入待办角标。本页不含商业/财务字段。
- 委外出仓只显示服务端已备齐放行的目标件（无子层级预留合格库存；有子层级须完成
  物料分析、领料、自制报工、FQC 与成品入仓）；历史 BOM 子件发料只读兼容。
- 其它出库/产成品出库为仓库原生单据（stock_documents），草稿 → 审核写库存；
  生产链生成的单据禁止通用编辑/删除（服务端守卫）。
