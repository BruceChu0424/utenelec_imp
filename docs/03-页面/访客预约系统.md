# 访客预约管理系统

> 外部访客来访的完整闭环：**入口选择 → 访客手机验证码预约 → HR 审批 → 签名二维码凭证 → 保安扫码核验**。
> 前后端打通（Flutter + Spring Boot），双主体 JWT 鉴权，pgcrypto 加密 PII，HMAC 签名二维码防伪造。

---

## 1. 角色与入口

| 角色 | 入口 | 能力 |
|---|---|---|
| 访客（外部） | 入口页「访客登录」 | 手机号验证码注册/登录、提交来访申请、查看申请状态、查看已批准二维码 |
| HR / admin | 工作台「访客审批」 | 审批申请（批准/拒绝/转接待人确认） |
| 被访人（普通员工） | 工作台「我的访客」 | 确认/拒绝转给自己的访客（可选两级环节） |
| 保安（security）/ admin | 工作台「安保」 | 扫码核验（绿放行/红禁止）、签到 |

**入口选择页**（`/entry`，登录前默认页）：两个按钮分流——
- 「内部人员登录」→ 现有员工登录页（账号密码）
- 「访客登录」→ 访客手机验证码登录页

---

## 2. 访客端流程

1. **注册/登录**：手机号 → 获取验证码（后端生成 6 位，开发期 log 网关打印 + 接口返回 `devCode` 前端显示）→ 输入验证码 → 后端校验并签发访客 JWT。
   - **员工检测**：登录时后端查 `employee_sensitive.phone_hash`，命中则拦截 → 提示「该手机号为优腾员工账号，请走员工通道」。
   - 注册即创建访客账号，自动生成 `visitor_no`（V + 手机尾4 + 随机2位）。
2. **提交来访申请**：姓名 / 身份证（选填）/ 来访单位 / 来访事由 / 是否开车 + 车牌 / 接待部门 + 接待人（从员工目录选）/ 计划到访时间。
   - **被访人目录**自动排除离职员工（`status != resigned`）。
3. **查看状态**：申请中 / 待接待人确认 / 已批准 / 已拒绝 / 已签到。
4. **已批准** → 显示**入厂二维码凭证**（后端 HMAC 签名）+ 下方**6位通行码**（二维码扫不了/电脑无摄像头时，保安可手动输入该数字核验）。

## 3. 审批与核验流程

- **HR 审批**：列表（待审批/已批准/已拒绝）→ 详情 → 批准 / 拒绝（填原因）/ **转接待人确认**（可选两级）。
- **被访人确认**：员工在「我的访客」看到转给自己的申请 → 同意接待 / 拒绝。同意后回 HR 最终批准。
- **保安核验**：`mobile_scanner` 扫二维码，或手动**输入6位通行码**（二维码扫不了时）→ 后端验签/查码 + 查状态 → **绿（放行，可签到）/ 红（禁止 + 原因）** → 签到后状态变 `checkedIn`，再核验变红「已使用」。

---

## 4. 状态机

```
pending ──forward──> hostReviewing ──hostConfirm──> pending(hostConfirmed=true)
   │                       └──hostReject──> rejected
   ├──approve──> approved ──checkIn──> checkedIn
   └──reject────> rejected
```
（`cancelled` 预留）

## 5. 数据模型（后端，V12__visitor.sql）

| 表 | 说明 |
|---|---|
| `visitor_accounts` | 访客账号：phone_enc/phone_hash(HMAC)/name/visitor_no/status |
| `visitor_sms_codes` | 短信验证码（sha256 入库，短期，限流） |
| `visitor_refresh_tokens` | 访客刷新令牌（独立于员工，轮换+重用检测） |
| `visitor_applications` | 来访申请：访客/事由/车牌/接待人/状态/qr_token/审批信息 |
| `visitor_approval_steps` | 审批轨迹（submit/forward/hostConfirm/approve/reject/checkIn） |

PII（手机/身份证）走 pgcrypto 加密 + HMAC 查重，与员工 `employee_sensitive` 范式一致。

---

## 6. 安全设计

- **双主体 JWT**：员工 `typ=staff`、访客 `typ=visitor`；`JwtAuthFilter` 按 typ 分支复查账号状态；权限点天然隔离（访客 JWT 只含 `visitor:*`）。
- **签名二维码 + 通行码**：二维码 `base64({aid,exp}).HMAC`（扫码，防伪造/截图转借）+ 6位 `passcode`（手动输入，降级方案）；均 7 天有效，签到后失效。passcode 生成时尽量全局唯一（冲突重生成）。
- **员工检测**：手机号命中员工 → 拦截（防员工绕过内部登录）。
- **脱敏**：身份证/手机按角色脱敏；访客只看自己申请；HR/保安按权限点。
- **审计**：visitor 表挂 `fn_audit` 触发器；登录/员工检测走 `AuditService.logExplicit`。
- **限流**：短信码 60s/条 + 每日上限 + 尝试 5 次失效；登录限流继承现有。

## 7. 路由

| 路径 | 页面 | 守卫 |
|---|---|---|
| `/entry` | 入口选择 | 两端未登录 |
| `/visitor/login` `/home` `/apply` `/apply/:id` | 访客自助 | 访客 session |
| `/visitor-approval` `/:id` | HR 审批 | `visitor:approve` |
| `/my-visitors` | 被访人确认 | `visitor:approve` |
| `/security/scan` | 保安扫码 | `visitor:check-in` |

访客流程独立于 ShellRoute（有自己的 session）；审批/被访人/保安在 ShellRoute 内（员工登录后）。

---

## 8. 后端接口（`/api`）

- 访客鉴权（permitAll）：`POST /visitor/auth/send-code|login|refresh|logout`
- 访客自助（visitor 主体）：`GET /visitor/applications/mine` `/{id}`、`POST /visitor/applications`
- 被访人目录（authenticated）：`GET /visitor/directory/departments|employees`
- 审批（`visitor:approve`）：`GET /visitor-approval` `/{id}` `POST /{id}/action|host-confirm` `GET /as-host`
- 保安核验（`visitor:check-in`）：`POST /security/verify` `/check-in/{appId}`

## 9. 短信验证码

开发期 `uten.sms.provider=log`（后端日志打印 + send-code 返回 `devCode` 便于联调，不真实发送）；生产改 `aliyun` 并配 AccessKey/签名/模板（`AliyunSmsGateway` 已留 stub）。
