# 流水线看板页（未实施提案）

> 计划路由 `/production/line` 当前没有注册，计划文件
> `production_line_board_page.dart` 也不存在。本页保留为产品候选需求，不计入当前生产能力。
> 现有生产排程/进度入口使用 `ProductionBoardPage`，见 `/production/schedule` 和
> `/production/progress`；当前真实页面契约见[生产调度工作台](生产调度工作台.md)和
> [生产主管看板页](生产主管看板页.md)。

## 一、候选目标

面向车间大屏/平板，按产线展示当前工单、进度、节拍、当班产量和异常。若现有生产排程/进度页
已满足现场需求，应关闭本提案，避免第二套看板和口径。

## 二、实施前置

1. 明确产线、班次、实时节拍和异常的权威数据源；当前没有该实时后端契约。
2. 决定轮询、SSE 或消息推送及断线/过期标识，不能用前端随机刷新模拟生产数据。
3. 新增专用查看/异常处置权限和后端对象范围；不能只复用粗粒度旧 `production:view`。
4. 明确与生产计划、日报的数量口径和时区，建立对账。
5. 以实际车间设备验证刷新频率、内存、防烧屏和断网表现。

## 三、目标布局

- 大屏：每条产线一张卡，状态、当前工单、进度、节拍、产量、异常数。
- 窄屏：卡片单列，保留数据更新时间和过期警告。
- 异常必须同时使用文本/图标，不只靠颜色。

目标组件优先使用 `UtenAppBar`、`UtenResponsiveGrid`、`UtenCard`、
`UtenStatusBadge`、主题化 `LinearProgressIndicator` 和 `UtenEmpty`。项目没有
`UtenStatCard`；KPI 用业务卡组合（原 `DocKpiBar` 已删）。

## 四、验收

- [ ] 路由、页面、后端接口和权限均真实存在。
- [ ] 数据更新时间、断线和陈旧状态清楚可见。
- [ ] 用户看不到无权产线，直接请求详情也被后端拒绝。
- [ ] 与日报/计划数量对账通过，并有跨日、跨班次边界测试。
- [ ] 持续运行、低性能档和大屏内存测试通过。
