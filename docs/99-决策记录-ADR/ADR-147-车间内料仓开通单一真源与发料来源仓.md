# ADR-147 车间内料仓开通单一真源与发料来源仓

- 日期：2026-10-04。
- 状态：已接受(本地源码实现，V800；8085 克隆库真实接口切非超管账号、Testcontainers 迁移/守卫测试、端到端测试与 Flutter 页面测试验证)。
- 取代：[ADR-089](ADR-089-车间直送v2持续生产与线边仓自动配置.md) 的「第一次车间直送时按『车间 x 收料主仓』自动配置线边仓」(V595 `LineSideWarehousePort.ensure`)；[ADR-087](ADR-087-车间内部直送与线边仓.md) 遗留的「仓库资料里手工把仓勾成线边仓」入口。
- 修订：[ADR-131](ADR-131-车间整批领料与盘点计耗.md) §3.6(内料仓不再按「(主仓名)」区分多个、一车间一个)与 §5.1 第 3 步(开启整批领料不再选「放在哪个主仓下」，改为先开通、可选发料来源仓、开启整批领料是开通后的子能力)；[ADR-151](ADR-151-表单草稿回到初始值单重参数结构化契约与入库登记单批合一.md) §4 数据库错误映射补「行版本守卫回 409」。
- 相关：[ADR-145](ADR-145-仓库主档单主仓与禁用不可选.md)(单主仓，内料仓挂主仓 001 下)、[ADR-146](ADR-146-不良品仓业务规则与可用量单一口径.md)(发料来源只能是良品子仓)、[ADR-127](ADR-127-直送资格单一事实源、不可转原因与报工自动分流.md)(直送资格唯一判定 `fn_workshop_direct_targets`)。
- 用户问题(2026-10-04)：「开启整批领料时选的仓库里没有塑胶仓库」「仓库资料里有装配第一车间内料仓，内料仓页却说装配第一车间没开启」「选仓要和别的地方一样右边滑出来、先点主仓再点子仓」「车间开启那张表行太高」「开通要能多选、右下角批量开通」。

## 1. 事实(调查与复现，服务器只读 + 克隆库 + 8085)

- 「开通」有两个真源而且互不同步：内料仓这个仓库行(`warehouses.is_line_side`)有三条建法——车间内部直送第一次时自动建(V595)、开启整批领料时建、仓库资料手工勾「内料仓」；而内料仓总览、「车间开启」表、内料仓页判断「开通」只看整批领料设置 `workshop_material_settings.periodic_enabled`。服务器上装配第一车间的内料仓 10-02 被直送自动建出、10-04 仍在收直送，页面却显示「未启用」、内料仓列为空。业务清空只清设置不清仓，每次清空都重新造成这种不一致。数据库也不拦：在用的内料仓能在仓库资料里停用，能手工新建一个没有设置的内料仓。
- 「放在哪个主仓下」下拉只列顶层仓(`parent_id IS NULL`)，子仓(塑胶仓库是 001 的子仓)永远进不来，却混着两个不良品仓与轨道车间；用户把它理解成「内料仓的料从哪个仓来」。发料页「出库仓库」候选只有「货品所属仓 + 有货叶仓」，PC 颗粒的所属仓被 V591 回填成五金/包材仓库，塑胶仓库在这一侧也出不来。
- 「默认出库仓」被算了三次口径各不相同：内料仓页 `materials()` 不校验所属仓是否启用/不良(克隆库里停用的五金仓库照样是默认且唯一候选)、申请候选 `requestMaterials()` 校验、申请行 `suggested_leaf_warehouse_id` 又取未校验的所属仓。
- 行高：「车间开启」表格单元格里放 `UtenButton`(最小 44)、总览表放两个 `TextButton`(最小 40/48)，行被撑到 48~64px，平台普通文字行约 35px。没有多选与批量命令，「去开通」要跳三次(总览 -> 设置页只剩一行 -> 行内按钮 -> 对话框)。

## 2. 决定

### 2.1 开通记录是唯一真源，内料仓只能由开通命令建出

- 新表 `workshop_bins`：每个车间一行 = 这个车间的内料仓已开通(可收车间直送)。`bin_warehouse_id` 唯一非空 = 内料仓；`source_warehouse_id` 可空 = 默认发料来源仓；`opened_by/opened_at/updated_by/updated_at`；`row_version` 是「开通状态版本」(改来源仓、开启/撤销整批领料都加一，页面据此判断有没有被别人改过)。
- 内料仓仓库行只能由开通命令(`WorkshopBinService`，materialbin 模块里唯一能建 `is_line_side` 仓的地方)建出：名称「{车间名}内料仓」，编号 LS-{车间编码}(编号终身占用，撤销时软删的内料仓再开通时原行复用、原编号不变)，挂在发料来源仓的主仓下，没选来源仓时挂唯一主仓(单主仓下两者都是 001)。
- 数据库兜底：
  - 每个未删除的内料仓恰有一条本车间的开通行(延迟约束，提交时校验；开通命令先建仓再写开通行，撤销时先删开通行再软删仓)；
  - 一个车间最多一个未删除的内料仓(部分唯一索引 `ux_warehouses_line_side_workshop`)；
  - 开通行守卫：车间必须是生产部下的车间、内料仓必须是本车间未删除的记账内料仓、来源仓写入或变化时必须是启用中的良品子仓(`fn_warehouse_is_good_stock_leaf`)、车间与内料仓不可改、版本逐一递增；
  - 仓库退出新选的前置条件 `fn_warehouse_selection_exit_blockers`(停用、删除、改不核算、改成不良品仓四条路共用，ADR-145 §2.3) 改读开通行：已开通的内料仓、仍是某个内料仓发料来源仓的仓都不能停用、删除、改不核算或改成不良品仓(原「已开启整批领料的内料仓」条件随之取代)。要停用一个来源仓，先在「车间内料仓」改来源仓或恢复按货品所属仓库发料。
- 仓库资料里内料仓只读：服务层拒绝修改、停用、删除内料仓(「车间内料仓由「车间内料仓」页开通和管理, 仓库资料里只读」)，页面详情不给编辑/停用/删除，内料仓一栏写「是, 由「车间内料仓」开通和管理 (这里只读)」。

### 2.2 三态与撤销

| 状态码 | 含义 | 表格底色 | 能做的(有设置权限时) |
|---|---|---|---|
| NOT_OPEN | 未开通 | 灰 | 开通、开通并开启整批领料 |
| OPEN | 已开通，收车间直送 | 蓝 | 开启整批领料、改发料来源仓、撤销开通 |
| OPEN_PERIODIC | 已开通且整批领料中 | 绿 | 改发料来源仓、撤销整批领料 |

- 三态只由服务端给出(`SettingsView.status`)，同时下发 `allowedActions` 与 `revokeBlockers`(撤销这一步现在做不了的原因)，页面不自己推算。
- 整批领料是开通后的子能力：`workshop_material_settings` 用复合外键 `(车间, periodic_bin_warehouse_id)` 引用开通行，设置守卫要求先开通(「这个车间还没开通内料仓, 请先在「车间内料仓」开通」)。整批领料的段状态、期间链、30 多处读设置的函数语义都不变。
- 撤销一次退一步：整批领料中 -> 已开通(原规则：内料仓没有整批领料的进出、没有段接上、没有待办领料单、没盘点过)；已开通 -> 未开通，只撤销设错的开通(`fn_workshop_bin_revoke_blockers`：没开整批领料、没有任何进出、没有余额、没收过直送、没有库存单据/预留/领料单引用)，删开通行并软删仓库行。

### 2.3 车间直送不再自动建仓

- `LineSideWarehousePort.ensure` 删除，改为只读 `openedBinOf(车间)`；`LineSideWarehouseService` 删除。
- 直送资格唯一判定 `fn_workshop_direct_targets` 新增原因码 `WORKSHOP_BIN_NOT_OPEN`：收料车间没开通内料仓时上层工单都不能收，大白话「{车间}还没开通内料仓，请仓库在「车间内料仓」开通后再直送，这次先送入仓库」。它排在接收方状态类原因之前(接近程度 25)，一个都不能送时报工页优先说它；报工分配按这条把这部分送入仓库，并把原因码记进送仓原因 `output_route_reason`。
- 直送明细守卫要求内料仓就是出料车间在 `workshop_bins` 里开通的那一个。审核时开通被并发撤销(资格判定已放行)，服务端同样拒绝并说明，一笔直送都不写。

### 2.4 默认发料来源仓只算一次

- `fn_workshop_bin_default_source(内料仓, 货品, 颜色)`：来源仓有可发量 -> 货品所属仓库(必须是可选良品子仓) -> 可发量最大的良品子仓；可发量 = `v_stock_usable` 的按仓可用量(ADR-146 单一口径)，不良品仓、内料仓永远不选；车间还没开通(申请先于开通)时从第二步起算。
- 内料仓页可发的料 `materials()`、申请候选 `requestMaterials()`、申请行建议仓、直接发料没选仓时的默认值只调它。
- 发料来源仓滑窗的仓库层级单独给一份只有元数据的接口 `GET /settings/source-warehouses`(编号、名称、上级、状态、是不是不良品仓、能不能选)，开通设置或发料权限都能读，不需要仓库资料或库存查看权限；提交时服务端用同一规则再校验。

### 2.5 批量命令(全成全败)

- `POST /settings/batch-enable`：每个车间按当前状态往前走一步——未开通 -> 开通(`periodic` 为真时同时开启整批领料)；已开通 -> 开启整批领料、只改来源仓，或「恢复按货品所属仓库发料」(`clearSource=true`，来源仓置空；不能与 `sourceWarehouseId` 同时给，已经是按货品所属仓库时 422「没有要改的」)。来源仓因此是三态：不变 / 改成某仓 / 清空——此前一旦设过来源仓就回不到「按货品所属仓库」，要停用那个仓只能被迫另选一个不想要的仓(2026-10-05 审查发现；W3 实施时只能用 SQL 置空)。`POST /settings/batch-disable`：撤销一步。单车间 `PUT /settings/{workshopId}` 是只有一个车间的批量，走同一条代码路径。
- 一个原子请求：最多 50 个车间、带请求号(同号同内容回放原结果，同号不同内容 409)；车间去重后按 UUID 排序逐个取建议锁，避免两批交叉选车间互相死锁；先把每个车间的问题全部查出来(状态/版本不一致是冲突 409，其余是规则不满足 422，`fieldErrors` 按车间列出)，一个都不写；全部通过才写。
- 开启整批领料的在产认料按产品去重：`GET /settings/in-progress-pending?workshopIds=a,b`，一个产品只认一次(认料本来就是产品级事实)，每个产品带「在产车间」。

### 2.6 界面

- 内料仓总览成为唯一的车间清单(设置页「车间开启」页签删除)：三态状态列(灰/蓝/绿)、内料仓、发料来源仓(没选显示「按货品所属仓库」)、本期；**行里不放按钮**，行高回到平台普通表格；单击选中、双击打开(已开通进内料仓，未开通打开开通面板)、右键/长按菜单放开通、开启整批领料、改来源仓、撤销。
- 有设置权限时表头三态多选，右下悬浮「开通(N)」「开启整批领料(N)」「撤销(N)」(N 只数勾选里这一步适用的车间，没勾选时灰显)；没有设置权限不显示勾选列。撤销确认框逐个车间说要退的那一步，现在不能撤销的列出服务端原因。
- 开通面板是全站右侧滑窗(`showUtenAdaptivePanel`)，支持多个车间：发料来源仓走全站仓库滑窗(`showUtenWarehousePickerPanel`, 用途 `goodOut`：先主仓再子仓，只能选启用中的良品子仓，不良品仓带标签置灰)；「改来源仓」模式另有开关「不指定来源仓, 按货品所属仓库发料」(打开后来源仓选择置灰，提交 `clearSource`)；「同时开启整批领料」打开后才出现启用日与在产认料，在产认料用平台可编辑表格(按产品一行，勾选多行后改任一勾选行的用料 = 全部勾选行生效)。失败时保留全部输入并复用同一个请求号。
- 只开通、没开整批领料的内料仓也能「进内料仓」：只列现有的料和数量(车间直送进来、等上层工单领用的料)，没有发料/申请/盘点动作，有设置权限时右下有「开启整批领料」。
- 设置页只剩「机台与容器」「上线准备」两个页签；车间切换用与总览同一份清单；两个页签的动作挪进右下悬浮按钮组。
- 发料页「出库仓库」(收退回时是「退到哪个仓库」)改用全站仓库滑窗，有货的仓在副行写「可发 N 单位」(数字来自服务端)，默认值是服务端默认发料来源仓。

### 2.7 存量与业务清空

- V800 回填：有任何引用(余额、流水、直送、整批领料设置、库存单据等全部外键列，外加物料分析参与仓)的内料仓 -> 已开通(来源仓为空；有整批领料设置的仍是整批领料中，开通人取开启人)；一次都没用过的内料仓 -> 软删除(NOTICE 列出，需要时重新开通)；同一车间还剩多个在用的内料仓 -> 迁移中止交人工合并。测试服务器只读核对：装配第一车间内料仓(有 2 条流水、1 次直送) -> 已开通；注塑车间内料仓(整批领料中) -> 已开通·整批领料。
- 业务清空：`workshop_bins` 随仓库主档保留(PRESERVE)，整批领料设置、期间等仍清空；清空后已开通的车间仍是已开通、整批领料要重新开启。

### 2.8 数据库错误映射：版本守卫回 409

- ADR-131 的内料仓服务层曾用 `WorkshopMaterialGuards` 把自己的约束名守卫一律翻成 409，与 ADR-151 §4 的全局口径(业务守卫 422)不一致，而且只在包过的调用里生效。本次删除这层包装，统一交全局映射，并在全局映射里补一条：约束名以 `_version_guard` 结尾的行版本守卫(V409/V740/V800)是别人刚改过、属于并发冲突，回 409(有中文原因原样回显，否则「该记录已被他人修改，请刷新后重试」)，页面据此重读；其余业务守卫仍回 422 并原样回显中文原因。

## 3. 同行做法

- SAP PP/EWM 的生产供应区(Production Supply Area)：线边位置显式建立，并为它配置补货的来源库存地点(控制循环)，不由业务单据随手建出。
- 金蝶 K/3 Cloud 的车间线边仓需在仓库/车间设置中启用后才能被生产领料、投料使用，物料另有「默认发料仓」作为领料的默认出库仓。
- Odoo MRP 的工作中心/生产库位：备料(pre-production picking)按路线从配置的来源库位取料，生产库位与来源库位都是显式配置。
- 共识：线边位置显式开通(不在业务流程中途自动建出) + 补料来源仓可配置 + 默认出库仓由系统按规则给出。本 ADR 按此收敛：开通是唯一入口，来源仓可选，默认出库仓只由一个函数给出。

## 4. 验证补充(2026-10-05 审查修复)

- `WorkshopBinBatchCommandPostgresTest`(真实服务、真实 PG、只有设置权限的非超管账号)：一次开通两个车间；同键重放不多建仓、同键不同内容 409；一个车间版本过期整批 409 并逐车间列原因、另一个车间也不写；规则不满足整批 422；改来源仓后原来源仓被「发料来源仓」挡住停用，恢复按货品所属仓库后不再挡；来源仓与恢复同时给 422；内料仓有没结束的预留时撤销 422 并列出原因；撤销 = 开通行删除 + 内料仓软删，再开通复用同一行(同 id、同编号、同上级，过 V798 两层树守卫与 V800 同生共死断言)；名字被别的仓占用时整批拒绝。
- 8085 实测：装配第一车间(来源塑胶仓库)恢复按货品所属仓库 -> 200、来源仓为空，塑胶仓库的停用前置条件里「还是 1 个车间内料仓的发料来源仓」消失；来源仓与恢复同时给 -> 422；再改回塑胶仓库 -> 200。
- 设置页「机台与容器」「上线准备」悬浮按钮文案改走多语言(批量新增机台、保存修改、保存)；两个页签里早于本 ADR 的其它中文硬编码(机台批量新增对话框、上线准备表格列等)保持原样，记为界面多语言整体补齐时一起处理。

## 5. 不做

- 不把内料仓挂到子仓下面(三级仓)：内料仓仍是主仓 001 的直属子仓，「来源仓」只是默认从哪里发料，不改变叶仓判定、同主仓规则与命名。
- 不改委外出仓/委外领料/采购超收容差(另一会话负责)。
- 内料仓任务的仓库数据范围(申请按建议仓分给哪个仓库负责人、徽章与列表同一谓词)由 ADR-149 统一处理；本 ADR 只保证建议仓来自同一个默认来源函数。
