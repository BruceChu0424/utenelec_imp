# 库存实际成本接线与验收

本页维护实际成本的实现入口、守恒合同和专项证据，合并原 V509 计划、成本引擎、V521 接线及委外自有材料四份交接。当前任务顺序与整体验收只看[统一验收记录](2026-09-07-全平台本地审计与整改验收.md)和[串行收口要求](2026-09-07-执行纠偏与串行收口.md)。源码存在、专项测试通过和目标环境安装是不同事实。

## 业务事实与金额权威

库存数量、供应商价款、公司持有价值分别留证。IQC PASS 只放行待入库量，仓库实际接收才形成可用库存。免费补回可以没有新 AP，但必须沿原资金和实物来源承接已有价值；销售价格也不能成为出库成本。

- 实际输入 A 保留最多 24 位有效小数，派生账面 B 保留最多 30 位；验证范围而不改值。参见[原始金额与分摊口径](../07-业务链路/2026-09-07-财务原始金额与精确分摊口径.md)。
- `InventoryValueLedger`、`ValueAuthorityStore` 保存 SOURCE 实际值及 node/edge/revision 谱系。四位 `knownValueLocal` 是兼容投影，不能替代完整金额或精确份额。
- 非有限份额保留来源与有理数量，不能制造零金额、自动 FX 或 `LOCAL_RESIDUAL` 损失。末项领取同一来源全部余额；原始、已分、未分严格守恒。
- `ValueBounds` 使用有方向的上下界，有限展开最多 128 位；`InventoryValueAuthorityService.refine` 在库存锁外单步处理依赖，禁止递归展开。最多 10,000 项进程缓存可丢弃；深层精化的持久化续作仍需独立验收。
- 未知来源、未核历史或未确定实耗保持 PENDING/LEGACY_UNVERIFIED，不成为零成本 FINAL。正数旧库存保留原数量/价值快照；零数量残值单独诊断，不能挪给新批次。

精度设计、曾发现的截断点及能力边界保留在[库存成本账内精度与精确份额复核](2026-09-07-库存成本账内精度与精确份额复核.md)，不在本页重复推导。

## 从业务动作查实现

路径根为 `server/src/main/java/com/uten/imp/`。以下是实际源码入口，不表示每个分支已完成全链验收。

| 业务动作 | 实现入口与结果 |
|---|---|
| 库存实收/实发 | [StockService](../../server/src/main/java/com/uten/imp/features/stock/StockService.java) 调用 [StockValuationCoordinator.value](../../server/src/main/java/com/uten/imp/features/stock/valuation/StockValuationCoordinator.java)。OUT 按实际仓库/货品/颜色池移动平均取值；流水与余额采用返回成本。OTHER_IN 读取真实单据金额；未确定 FINISHED_IN 成本保留待分配。 |
| 历史池首次启用 | [InventoryBusinessValueSupport.ensureActive](../../server/src/main/java/com/uten/imp/features/stock/valuation/InventoryBusinessValueSupport.java) 在库存锁内建立可追溯期初。`StockBalanceRepository.readPhysicalSnapshot` 直接读取锁内实际数量/重量，避免同事务多次收货复用陈旧 JPA 值。 |
| 采购/委外收货及品质 | [ProcurementInventoryValueService](../../server/src/main/java/com/uten/imp/features/stock/valuation/ProcurementInventoryValueService.java) 的 receiptApproved、qualityRecorded、store 及对应反向；[来源证据适配器](../../server/src/main/java/com/uten/imp/features/stock/valuation/ProcurementCostSourceEvidenceService.java) 核实已审收货/AP/不可变收费份额。 |
| IQC 实退、贷项与补回 | returnedToSupplier/returnReversed、creditConfirmed/creditReversed 只接真实事件或凭证 UUID，再沿 case/funding/FAIL 数量定位旧费用。合同与 API 见[到货退换货实现](采购与委外到货退换货实现与验收.md)。 |
| 生产领料、实际材料结清 | [ProductionInventoryValueService.bound/settled/refresh](../../server/src/main/java/com/uten/imp/features/stock/valuation/ProductionInventoryValueService.java) 把 ISSUE 实际成本绑定到具体 posting；CONSUMED 转入生产成本对象。DRAW 审核、实发和实际消耗分别留证。 |
| 成品实收与后补成本 | Coordinator 在原实物事务 registerOutput；[InventoryProductionCostService](../../server/src/main/java/com/uten/imp/features/stock/valuation/InventoryProductionCostService.java) 维护版本和分配任务；[InventoryValueWorkService.runBatch](../../server/src/main/java/com/uten/imp/features/stock/valuation/InventoryValueWorkService.java) 每任务短事务续作，业务刷新待办可持久保留。 |
| 委外自有材料 | [SubcontractOwnMaterialCostService](../../server/src/main/java/com/uten/imp/features/stock/valuation/SubcontractOwnMaterialCostService.java) 沿真实材料 ISSUE 和回厂 consumption UUID 转移 SUBCONTRACT_WIP；首次实际入库才汇入成本对象。 |
| 委外正常/超额损耗 | [SubcontractLossValueService](../../server/src/main/java/com/uten/imp/features/stock/valuation/SubcontractLossValueService.java) 的 validateWaste/registerOutput/refresh 按实际来源分离 NORMAL 与 EXCESS；[SubcontractLossClaimService](../../server/src/main/java/com/uten/imp/features/finance/payables/SubcontractLossClaimService.java) 单独记录实际赔偿。赔偿不能自动冲掉实物损失。 |

移动引用由 `InventoryMovementCostReference` 的 ProcurementStockIn、ProductionMaterialEvent、FinishedProduction、SalesReturnQuality、OriginalIssueMovement 表达，禁止调用方传任意金额冒充来源。采购品质来源须同时核对 failureCaseId、qualityPartId、fundingSliceId、sourceApLedgerId 四个 UUID；不按单号、日期、货号或当前价格猜节点。

## 待检、在制与反向守恒

`InventoryPositionService.acquire/move/store` 以原根累计数量区间分配，每次最多 100 个来源。QUALITY_PASSED、WIP、SUBCONTRACT_WIP、IN_TRANSIT、EXTERNAL 是明确保管位置；COST_WIP 表达成本归集，不能增加仓库物理数量。收货费用证据只在 quote/AP/header 已落后建立；品质事件与价款切片同事务冻结。

生产分配以当前批准目标量形成暂估分母。实际领用不等于实际耗用，必须由现有责任人明确结清 CONSUMED；不能增加一层与业务无关的审批，也不能自动使用“实发减退料”替代消耗证据。FINAL 还要求完工、正常/异常损耗、在制和费用均已确认。

| 守恒例 | 应保留的事实 |
|---|---|
| 来源 600，目标 20，成品实收 5 | 成品 150、在制 450；目标改 10 后通过新修订变成 300/300。 |
| 上例已售 3，后补来源 100 | 归入销售成本 210、库存 140、在制 350，不能只调剩余库存。 |
| 来源减少 200，而成品仍暂记 600 | 独立待分配调整 -200，物理 WIP 为 0，总值 400；后续任务完成后成品 400、调整 0。不能删除负债、制造负实物或跨批挪值。 |
| 撤销实际耗用 | CONSUMPTION_RETURN 沿原数量区间恢复原 ISSUE WIP，原输入/节点/任务不删除。COST_RETURN_CURSOR 自有量 0、最多 2 条后继边；剩余比例冻结在后续任务中。 |
| 撤回完工 | REOPEN_COMPLETION 必须有同计划/操作者/版本的真实结清 REVERSE；恢复 IN_PROGRESS，不伪造 FQC 或已入库反向。 |

分配任务冻结 input×output 对，每页最多 100；一事务处理一输入/输出配对，CAS 校验版本。只有捕获的来源修订已传播并 APPLIED，才可清除对应 dirty。APPLYING 期间新增实收保留业务刷新指针，不能永远阻断真实收货。

委外 DIRECT_TARGET 只接受同货品/颜色、冻结基本量 1:1；旧 FROZEN_BOM_ESTIMATE 不能成为 FINAL 实耗。材料实际退回扣原 ISSUE 尚未耗用部分，反向按实际库存均价回原 owner。普通委外成品退回的反向关联原实物退回流水，不使用加工费单价重算。

SC FAIL 只把失败加工费保留在外部位置，自有材料仍沿供应商/成本在制承接。免费补回沿 `funding.root_receipt_item_id`，不新增自有料耗用。一批 PASS 如含多个原批次，内部按来源边界生成实际库存明细与流水，UI 仍一次确认；stock_sequence、逐项 expectedRemaining、数量/金额/重量/操作者守卫保持。

销售退货顺序为业务校验/幂等/库存门槛 → 更新品质 → 追加事件 → 带类型来源的实际流水 → qualityEventRecorded。RECEIVED/RECEIPT_REVERSED 只走专用收货 hook，避免重复。GOOD 撤销使用当前混合库存实际均价回待检位置，历史原事件不改写。

## 仍需单独收口的范围

多代来源、分配超过 100 项的续作、任务中断恢复、极小后补值与原生 SQL 越权边界须依[逐步守恒与压力矩阵](2026-09-07-生产链逐步守恒与压力测试矩阵.md)逐项给证据。经济循环不能通过同执行段产出反喂自己确认成本，返工需独立实际范围；不得为过测试伪造来源。

实际加工费后补的审批来源、历史资金核对、普通退货共同账面分配、客户现金退款、供应商索赔现金兑现及最终 GL/账户完整联动依统一计划推进。完整同版本 Maven/Flutter、全部岗位浏览器 UAT、最终规模压力、服务器副本升级与对账、上传部署仍需各自证据。本页已有专项不能替代这些工作。
