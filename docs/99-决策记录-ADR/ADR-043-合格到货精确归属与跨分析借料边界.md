# ADR-043 合格到货精确归属与跨分析借料边界

- 日期：2026-08-21
- 状态：已采纳（源码候选；目标库迁移、Flutter 全量/真机验收、真实多岗位 UAT 未完成，发布 **NO-GO**）

## 背景

V298 已能把采购/委外 IQC 合格库存隔离给来源
`material_analysis_id`，防止其它分析抢占。但同一联合分析内若多个产品使用
相同仓库/货品/颜色/单位，V298 没有保留原始 `analysis_material_id`，重算可把
针对 A 产品的到货分配给 B 产品。同时，页面把单项合格到货、当前分析占用和
整套齐套量混为一个「到货/可生产」概念，容易出现「质检通过但仍显示 0」。

## 决策

1. **仓库收货不等于合格入库**：收货审核只生成 IQC 待检事实；每次 `PASS`
   才写 `DIR_IN`，并在同一事务内建立分析归属和刷新。
2. **V307 精确子账**：保留 `stock_reservations` 作为唯一物理预留真相，新建
   `preplan_analysis_stock_exact_pegs`，以一对一子账保留
   `IQC PASS event -> receipt -> external request/application item -> action allocation
   -> origin analysis material UUID -> beneficiary material UUID`。新行受益方必须从原始行开始，
   原始谱系和数量不可改，数据库同时校验仓库/货品/颜色/单位、收货行到
   request/application item 的 UUID 链、供应分摊容量和单次 PASS 数量守恒。
   被 exact 引用的 material 行不得改身份/维度，有效端点在刷新终态必须仍 active。
   `beneficiary_*` 在 V307 只是未来 schema 扩展点；由于本期尚无 entitlement/loan/
   可逆转移桥，数据库守卫禁止 exact 子账任何 `UPDATE/DELETE`。以后必须由补齐
   完整业务账的前向迁移显式替换守卫，不能直接改受益方。
3. **先精确保障，再分共享池**：重算先扣安全库存，再把生效 exact peg 作为
   原物料节点的 secured coverage；同分析兄弟产品只能消费剩余共享量。超出
   action allocation 的特批超收仍进公共池，不伪造归属。
4. **安全库存口径唯一**：主重算、分仓展示和正式计划预览统一使用
   `max(publicAvailable + eligibleOwnPeg - safetyStock, 0)`，exact 身份不得
   绕过安全库存。
5. **展示分层**：服务端返回节点级 `exactPeggedQty`和分析仓维度
   `ownPeggedQty`；前端分开展示「本节点合格入库绑定」与「整套物料最多可生产」，
   并通过 45 秒只读 GET 和 CAS 冲突回读消除长期旧快照。所有携 version/fingerprint
   的写入口在 409 后只 GET 最新详情，绝不自动重试；只保留相对最新建议仍合法的草稿。
6. **反向 fail closed**：分析归属一旦已转正式生产需求，在 exact peg 到正式
   demand/reservation 的可逆转移子账完成前，采购/委外收货和 MAKE 成品入库红冲、
   action/analysis 取消及计划包 cancel/reverse 都必须返回冲突；计划确认只可把
   READY 段需求转正式占用，WAITING 段不得提前释放分析归属。
7. **库存锁必须最先**：涉及分析归属的 IQC、任务取消、计划审核、计划包 confirm
   与 lifecycle，先按货品/颜色稳定取得全部 `inventory dimension` 锁，再进入各自
   固定的单据、分析、action/allocation/reservation 锁序；PASS 必须 analysis→action，
   任何分支不得持有业务行锁后再补取库存锁。

## 跨分析借料边界

V288/V289 仅是同一分析内两个产品直接组件的软分配，不是跨分析债务账。
V307 的单一 `beneficiary_*` 只是不可写的谱系扩展点，无法表达部分借用、多来源还款或
MAKE 入库归还。因此本次不提供跨分析可写入口，也不得宣称「下一批自动优先归还」
已完成；数据库触发器同样拒绝直接修改受益方，防止绕过应用层。后续必须以独立前向迁移补齐：

- 可分片的 exact entitlement 账与 BUY/SUBCONTRACT/MAKE 统一供应来源；
- lender/borrower 双 UUID、outstanding/repaid 和追加式 LEND/REPAY/REVERSE 事件；
- exact entitlement 到正式 demand/reservation 的可逆转移桥；
- 双分析有序锁、双方权限/CAS、部分还款、红冲和已领料门禁。

在上述结构完成前，前端必须明示「仅限当前分析内调拨；跨分析借料及自动归还未启用」。

本候选明确不包含尚未满足上述不变量的 V309/V310 或任何“跨计划让料”运行时入口。

## 影响与验收边界

- 迁移 lineage：V304 恢复为最早已应用的 canonical 字节并冻结 checksum；V307
  新增 exact peg 子账、容量/身份/端点/审计守卫且不猜测回填历史 V298；V308 在
  V307 业务表之后重新执行 fail-closed 全 `public` audit sweep。
- 后端：采购/委外 PASS 精确归属、节点优先保障、合单明细隔离、计划预览精确加回、
  转正式需求后的红冲/取消/计划包门禁、READY-only 转移与 inventory-first 锁序。
- 前端：节点 exact 数、分析聚合数、整套齐套分层展示；全部 CAS 写冲突自动回读；
  空闲页 45 秒读取最新快照，未保存编辑不被静默覆盖。
