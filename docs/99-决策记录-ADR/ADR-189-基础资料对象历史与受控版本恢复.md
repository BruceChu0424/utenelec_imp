# ADR-189 基础资料对象历史与受控版本恢复

日期：2026-10-22

状态：实现完成，定向验证通过；尚未发布或部署。

基础资料详情、分类与总览需要回答“谁在何时修改了什么”，并能从误删或旧版本恢复。ADR-182 的个人最近十次撤回和取消撤回解决的是个人编辑序列，不能承担多人对象历史，也不能修改原始审计事实来伪造恢复后的过去。

## 决策

新增 `master_record_versions`，从主档、分类、BOM、联系方式、地址及专用责任、授权、计量和跟进附表的真实行变更捕获前后快照。原始图片不复制到列表，数据库仍保留原件与哈希证据。事实表禁止更新、删除和截断，业务清空目录必须将其列为 `PRESERVE`。导入已有个人历史的原始快照，不改写其原始人、时间、内容或个人撤回状态。不能从不存在的历史推造更早版本。

统一 `/api/master/record-history` 使用 `entityType` 加对象 UUID、分类 UUID 或空范围查询，返回游标分页、操作人、时间和动作。摘要页批量加载本页对象与权限范围，不逐条加载关联行或字段值；选中一条记录后再加载授权后的完整字段差异与恢复能力。同一事务中同一对象的多次行写入合并为一次操作；分类删除可查看并恢复原操作涉及的完整分类子树。浏览权限与恢复权限分离，只有查看权限的用户可以读历史。主档扩展信息沿用不可变列定义和原 `PlatformColumnService.write` 的字段权限、对象资格与版本校验；公式结果使用当前业务事实重新计算。

恢复方向必须明确为“恢复到此次修改前”或“恢复到此次修改后”。恢复包含该次操作中此对象一并改变的关联行；不会静默删除其他操作后来新增的独立关联行。分类删除恢复包含原删除操作中的下级分类、货品或客户等资料。提交必须携带当前对象历史事实集合的 `COUNT:MAX` 令牌；事实不可删，因此较早分配序号但较晚提交的并发事实也会使令牌变化，不能仅比较最大序号。后端在固定顺序的非等待锁下重新检查令牌、当前权限、归属、字段权限、现有引用、启用状态和图循环，冲突时整笔回滚。恢复成为一条新历史事实，保留原来的所有事实。

个人撤回和共享版本历史复用同一领域校验，不共享个人历史窗口或原操作者的旧授权。客户共享只允许查看，不因此取得恢复权限。售价、折扣、采购及委外学习成本分别遵守其当前查看权限，不能由售价权限取得成本或折扣；账户余额和客户访问授权也保留各自权限。模拟身份、锁定账号、访客和必须改密的账号不能恢复。前端登录主体、服务端地址或权限变化会立即清除旧内容和确认弹窗，迟到响应不得重新显示。

历史版本只覆盖当时记录且当前仍存在的字段，旧版本缺少后来新增列时保留当前值；物理地址与联系方式重建只列出旧版本实际提供的列，让新列使用数据库默认值，不能通过整行填充把新责任或保护列清空。旧快照未保存的内容不推造为历史事实。

编号恢复通过 `MasterIdentifierVersionRestorer` 重新调用当前编号分配与终身占用服务，保留当前序号，按当前分类重算托管标记，禁止复制旧分配元数据。预锁顺序与正常新建一致，主仓和车间内料仓仍保留专用编号规则。分类前缀及层级变更通过子树协调流程处理。库存、账户余额、责任交接、单位计量、成本计算及追加业务证据使用原领域维护流程，不能用旧快照任意回写；历史界面和接口说明具体阻止原因。

BOM 恢复重新校验组件有效状态、引用与循环。同次正常维护中父货品的 `source_e` 是派生结果，恢复先保留当前值，再根据恢复后的组件重新计算；不能拿过去的派生成本覆盖当前图。每个实际改变 BOM 内容的父件在同一事务追加一条 `GOODS_BOM_UPDATED` outbox 事件，继续触发既有物料分析刷新和研发任务通知链；纯核对标记不重算、不通知。事件追加失败则组件、成本和新版本一起回滚。其他主档逐类核对正常保存副作用：只恢复其允许的普通字段；账户余额来源、仓库车间关系、财务层级与单位计量规则仍交给专用流程，不能跳过其配套写入。

## 界面

前端设计默认使用 `frontend-design`，复用 Uten 主题、表格、筛选工具栏、确认对话框和加载状态。所有历史入口导航到同一个独立历史页，携带对象或分类范围；列表支持资料类型、含已删除节点的分类、操作、操作人、时间和身份关键字筛选，每次只取当前页。双击版本进入独立详情页，展示字段修改前后对照和恢复动作；不再保留抽屉时间线。恢复必须二次确认，取消不发请求。版本页恢复结果通过共享变更信号带回列表及原详情，浏览器和系统返回也不会留下旧详情快照。

差异投影将缺失、空值和空文本视为同样的“未设置”，不展示双方都为空的伪差异；隐藏内部版本、编号分配和迁移影子字段，业务字段使用中文名称。原始事实仍完整保留。恢复到新增前的能力与服务端校验一致：允许软删的主档要求当前编辑与删除权限、重验引用，并在确认中明确说明撤销新增会删除资料及原操作关联项。

即时库存与车间内料仓复用既有盘点历史和审核链，展示盘点前后、提交人及审核事实。库存恢复只能经过盘点或对应逆向业务流程，不能套用主档快照写回。

## 验证边界

验证应覆盖跨操作者读取与恢复、只读权限、失效会话和模拟身份、CAS 冲突、删除及地址完整恢复、后续主选或默认选择冲突、分类子树恢复、敏感字段过滤、历史不可变及游标分页。界面覆盖取消无请求、明确前后方向、身份切换、窄屏、大字体和深色。测试通过不表示已集成发布、激活或完成生产 UAT。

2026-10-22 的本轮后端定向验证使用隔离 PostgreSQL，从空库正常执行 825 个迁移至 V899；未修改业务库、未 repair 已应用迁移。对象历史 29 项真实数据库回归全部通过，包含 157 条货品和两层分类的原 UUID 整体恢复、BOM 派生成本与 outbox 原子性、前述权限及冲突边界，以及空值、中文标签、公开关联姓名与图片差异投影。原有货品个人历史 15 项和其他主档个人历史 18 项回归通过。

该样本中，157 条货品及两层分类的恢复事务两轮约耗时 3.7 秒和 5.4 秒；末轮 50 条摘要用一条 SQL、约 22 毫秒返回，引用写锁冲突约 13 毫秒拒绝且没有资料写入。这些是单机功能样本，不能当作容量压测。整批恢复是低频写操作，会持有范围表锁，页面保持恢复遮罩和退出保护；常规摘要查询没有这些写锁。

权限复核还修复了完整货品表单绕过专用委外损耗命令成本权限的问题。完整表单和版本恢复都按实际变化校验 `goods:cost:view`；省略或数值等值回传仍可编辑其他字段，显式清空属于受保护的修改，已有只读显示不新增遮挡。新增授权及既有折扣、订货口径、客户型号的 31 项单元回归通过；真实 Spring 与 PostgreSQL 的 3 项回归验证拒绝时业务资料、版本及两套历史均不变，授权后新建、修改、清空均成功。

随后收付款类别的表格编辑和批量启停通过 V902 纳入既有本人历史路径；该轮隔离数据库正常执行当前完整 828 个迁移至 V902。新增 9 项真实 Spring/HTTP/PostgreSQL 回归及原生服务 23 项回归通过，覆盖具体字段 CAS、分字段权限、双历史捕获、父子顺序、系统科目及账户引用；管理员也不能通过共享 CREATE 历史恢复到新增前来软删财务类别。新增可编辑的部门核算、收款标志、付款标志使用各自中文差异标签；原始标志不是业务授权的替代判断。
