# 仓库任务中心页

采购/委外的待登记实物行选择按原始预计到货明细保留；双击只打开该行，多选的两条入库路线只带入所选行。同单多行可以合并办理，但不得按单号去重后扩大到整张订货单。登记入口最多 50 个来源任务、100 行物料；显式空选择、失效或不可见明细须返回重选，不能自动改为整单登记，见[仓库到货登记页](仓库到货登记页.md)。

> **2026-10-20 明细徽章与顶栏仓库选择统一**：已按货品明细展示的实物任务，其红黄徽章与同范围、同作业状态的明细数量一致；同一采购单的两条待到货明细计 2。来源分段、大类、仓库模块和工作台复用服务端同一事实数，旧领料兼容入口不重复累计。办理仍按原单据去重进入原流程。顶栏顺序为「仓库选择 → 资料草稿 → 仓库草稿 → 刷新 → 权限设置」，仓库选择使用主题主色描边和统一控件圆角，深浅主题同步；窄屏沿用顶栏操作面板。删除分类上方的「任务筛选」及「清除筛选」整行；当前范围在顶栏选择器内显示，恢复全部范围从选择器选「全部仓库」并确定。默认设计技能为 `frontend-design`，沿用项目字体、组件和主题 token。

> **2026-10-20 仓库筛选与成品单选修正**：仓库筛选按本人可见仓提供同一个选择入口，普通仓管、单仓负责人也可打开；主仓包含可见下级仓，列表和数量同步收窄。范围读取失败可原位重试，刷新和返回页面重取负责范围。产成品待登记多选携带实际勾选的实物批 `lotIds`，登记页只加载这些批，同一报工的其它批不自动加入；本机填写草稿同样按实物批匹配。同一批的需求、公共、超产拆分仍整批办理，不增加操作步骤。默认设计技能为 `frontend-design`，复用现有 Uten 组件与主题。

> **2026-10-17 货品明细直接展示**：出库、入库及其历史列表统一为一条原货品明细一行，同单同货品的不同原始明细也不合并。采购、委外、产成品、其它出入库、生产领退料均保留单据号表头筛选；货品名称、编码、规格、颜色、数量和单位直接显示。服务端先形成授权范围内的明细，再做搜索、状态筛选、计数及分页，不能先分页单据再在客户端展开。列表数量为明细条数；实物任务徽章按 2026-10-20 修订同步采用同状态明细口径。办理仍进入原单据复核页面，同单多行只进入一次原单；不改变原审批、数量、来源、幂等和库存事务。无货品的空草稿仍保留可打开行。旧销售出库、委外出库、预计到货与成品任务独立链接复用同一任务中心，避免不同入口出现两种展示。

> 本次界面使用 `frontend-design`，沿用 Uten 的青绿交互色 `#0F766E`、浅灰背景 `#F5F7FA`、白色表面 `#FFFFFF`、深色正文 `#0F172A`、次级文字 `#475569` 与细边框 `#E2E8F0`，使用原 NotoSansSC 字体和紧凑表格。状态列固定靠左，货品信息紧随其后，单据与来源列保留筛选；窄屏沿用共享表格水平滚动，不改为折叠单据卡片。

> **2026-10-13 草稿数字与入口统一**：顶栏「仓库草稿」汇总本人全部可见仓库的独立库存单据草稿与本机填写，「资料草稿」单独承接仓库资料；两者不随任务页选仓收窄。任务页恢复了所选仓库时，在顶栏仓库选择器内显示当前范围，可从该选择器恢复本人全部可见仓库。各作业大类只计真实任务，不再把独立填写草稿手工加进出库或入库数字。正式单据与同类型、同 UUID 的本机 checkpoint 只显示一行，多份填写保留选择恢复，未处理前不参与正式单据批量删除。生产链自动生成的单据不进入独立草稿工作区；旧版仓库损耗草稿按只读兼容规则展示，保留既有权限下的草稿清理。

> **2026-10-11 任务填写草稿回到原行**：到货登记、产成品登记与最终点收、生产领料填写/批量出库、生产退料接收、委外拣货、销售出库核对、品质结果上架等既有任务的本机填写，留在原业务分类与原任务行，状态列显示「草稿」；提交结果不明时显示「提交待核对」。出库/入库/生产领料不再单列任务填写草稿分类。双击原行恢复原单或原整批；同一任务有多份填写时先选择续填哪份。确认成功的批量成员不重复显示草稿；来源 UUID、账号、服务器、权限和原提交标识保持绑定。本机状态不写入业务状态或库存。手工新建库存单据、新建盘点和仓库资料仍保留独立草稿入口。

> 服务端已办结但回执丢失、原行离开待办队列时，任务中心及独立任务页保留「核对原提交」提示，恢复同一份未知请求；不新造业务行、库存或单据，也不增加待办角标。普通已完成记录不显示该提示。

## 结构：业务大类 + 必要作业阶段

- **大类行**(正文第一行，带页级搜索；仓库范围选择器在顶栏资料草稿左侧)：出库 / 入库 / 生产领料 / 品质检查结果 / 委外成品退货 / 委外损耗 / 车间内料仓 (2026-09-28 新增)。进页面不预选大类（未选显示引导空态，不发请求）。
- **小类行**（选中大类后出现）= 原各任务中心页自己的分段，以嵌入态复用整页能力（小类行、表格、办理动作与独立页完全一致）：
  - 出库 → [出库任务中心](出库任务中心页.md)（销售出库/委外出库/其它出库/产成品出库）
  - 入库 → [入库任务中心](入库任务中心页.md)（采购入库/委外入库/产成品入库/其它入库）
  - 生产领料 → [生产领料任务中心](生产领料任务中心页.md)（待领任务/领料单/生产退料）
  - 品质检查结果 → [品质部检查结果](品质部检查结果页.md)（保留作业阶段；采购/委外来源改为表头筛选，状态文字同时说明来源）
  - 委外成品退货 / 委外损耗 → 时间门控的历史视图（只读，不挂数）
  - 车间内料仓（[ADR-131](../99-决策记录-ADR/ADR-131-车间整批领料与盘点计耗.md)）→ 按权限显示待发料 / 待收退回 / 盘点审核 / 周期盘点 / 记录。有发料权限时显示「直接发料」；仅持仓库盘点审核权限也能进入大类与审核队列。「盘点审核」内嵌[库存盘点审核页](库存盘点审核页.md)，点击申请进入真正审核明细并可原位返回队列，直接按整单审核，无用途卡片勾选；通过后自动刷新队列和待办。父分类与子分类共用同一左侧边界。顶栏同名按钮直接定位该子分类。「周期盘点」保留期间状态与[期间盘点页](车间内料仓盘点页.md)，仅对有查看及周期录入／审核权限的人显示；2026-10-01 起记录「状态」与「盘点」「结算」列按状态铺整格底色（开着绿／盘点中蓝／待结算琥珀／结算失败红等，见[车间内料仓页](车间内料仓页.md)）。

旧三路由 `/warehouse/tasks/{outbound|inbound|draw}` 与 `/warehouse/quality-results` 构建本页并预设对应大类（通知深链、收藏、`?section=/?view=` 参数原样透传），不再是独立页面。

## 徽章口径（准则 14 不变）

- 仓库出入库计数端点通过应用端口 `WarehouseTaskRowCountPort` 复用任务中心的实物明细 SQL 投影，原端点操作资格与服务端仓库范围继续生效；品质结果按原实物检验行分桶。不能回到旧单据计数服务，也不能在前端按当前页展开数量补差。
- 大类红数 = 原各卡同源入口：出库 `warehouseOutboundCenter`、入库 `warehouseInboundCenter`、生产领料 `warehouseDrawCenter`、品质检查结果 `warehouseQualityResult`（均随徽章汇总一次带回，ADR-108）。
- 品质检查结果大类另挂黄数（等待检查结果 = 货已收、等品质部出结论），与注册表黄链同源。
- 委外成品退货 / 委外损耗是历史只读大类，不挂数（准则 14 §二）。
- 车间内料仓大类：红数取 `warehouseWorkshopMaterial`（待发料＋待收退回）与 `warehouseStockCountReview`（库存盘点待审）的独立入口并集，各计一次；黄数仍只为真实周期 `COUNTING`。顶部快捷入口与审核子分类共用审核待办数，0 隐藏，不将每个 `OPEN` 期间算成待办。没选仓取统一徽章汇总(服务端已按本人仓库范围)；选了仓取同一汇总接口带 `scopeWarehouseId`(ADR-149，不再用 `PENDING` 列表 size=1 凑数)，列表和计数共用服务端条件，主仓包含子仓。页内多处显示不再累计进模块。
- hub「仓库任务中心」卡角标 = warehouse 有效待办累计（服务端目录加本机独立草稿，与顶栏红药丸、工作台仓库卡同源同数）；库存单据草稿合计已包含调拨和盘点切片，不重复相加。任务填写仍按原行与原提交核对，不混入独立草稿。
- 仓库范围（[ADR-149](../99-决策记录-ADR/ADR-149-仓库数据范围服务端强制.md)，V804，取代 ADR-115 的「我的仓库」）：服务端按本人范围强制过滤列表、大类与分段计数、徽章。主管顶栏是小标签，点开右侧滑窗(先主仓后子仓，首行「全部仓库」)可挑任一仓；负责多个仓的子仓负责人同样的滑窗(首行「我负责的全部仓库」，只列自己的仓)；单仓负责人同样可以打开选择；其他人可在本人可见仓内筛选。选了仓时大类数与分段数取 `/workbench/badges?scopeWarehouseId=`(只算仓库模块入口)，没选仓取全站徽章汇总(服务端已按本人范围)；库存单据各分段的「草稿」数同样带上所选仓(`/documents/status-counts?scopeWarehouseId=`)，与旁边列表同一范围；范围变化即重拉大类计数与分段列表。记忆的仓不在当前可选范围内时回到本人默认范围；返回本页或点「刷新」会重取本人可选范围(负责关系刚改过时不会一直拿旧范围请求、得到「所选仓库不在你可见的范围内」)。本人默认范围里自己还没提交的库存单据草稿不论在哪个仓都列出并计入草稿数(顶班在别的仓建的草稿不会从自己的列表和草稿箱里消失)，挑了某个仓就只看那个仓。
