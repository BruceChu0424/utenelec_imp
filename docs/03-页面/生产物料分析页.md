# 生产物料分析准备

> 路由：`/production/material-analysis`(物料分析准备)、`/production/material-analyses`(物料分析历史记录)

本文是准备页、下达车间、采购和委外三个入口的现行交互合同。历史验收记录只证明当时的代码和环境，不代替当前测试或部署状态。

准备页及三个桶的历史修复证据见[修复与验证记录](../99-项目治理/2026-09-26-物料准备统一流程修复.md)，本页只维护现行交互和业务规则。源码、测试结果和已安装版本分别核对，历史验收记录不代表当前版本已部署。

入口 `/production/material-analysis`，历史记录 `/production/material-analyses`。分析编号来自 `analysis_no`，不以短 UUID 或货品编号代替单号。

## 1. 员工流程

1. 在新建页勾选已审核销售订单行(表格行内填本次分析数量)，和/或录入手工需求单(一个需求编号下多行货品)，选择主仓库，点「联合分析所选 N 项」一起分析(2026-09-27 ADR-130，见 1.1)。
2. 已有供应方式自动带出并保存。未能确定的行保持空选红框，补选后即保存；没有独立“确认路线”步骤或按钮。自动保存只确认供应方式，不创建采购、委外、车间任务。2026-09-27 起自动保存由服务端在联合分析 / 刷新的同一次计算里完成 (ADR-102)，页面只轻提示「已按货品档案自动确认 N 条供应方式」，不再另发一次保存、不盖全屏遮罩。
3. 在原产品树核对需要数量、可用数量、还缺数量、下单数量和指派。每个真实子件都可以单独下单或追加。
4. 勾选后一次确认下单。相容的同料自动合单，员工无需进入“共享批次”办理页。
5. 回执更新原产品树和三个桶；失败保留未完成的输入与选择，已成功的部分如实保留。

三个桶用于按部门查看待处理、进行中和需处理。桶外层是只读清单，勾选后进入共用“核对并下单”页。核对页复用主表的列、输入控制器、路线、指派、数量预览及提交器，不另维护 notify/issue-plans 的私有编排。

### 1.1 新建分析：销售订单产品与手工需求单(2026-09-27 ADR-130)

新建页(尚未有分析时)与「销售下单 → 调度台多选 → 分析」同一流程：销售订单行和手工需求行放进同一个「本次分析」，一个按钮一起分析。

- **顶部**：一行引导文字 + 「主仓库」下拉。下面是分段切换「销售订单产品 (已选 a)」「手工需求 (b 行)」，计数为中性数字。桌面上分段条右侧放当前分段的操作：销售段是搜索框，手工需求段是「再建一张手工需求单」按钮；窗口较窄(约 600-900 宽)一行放不下时，右侧整体换到下一行，分段始终完整可见。
- **销售订单产品**：搜索框 + 候选表(服务端每页 100 行，表头三态多选，跨页保留选择)。表格行内有「本次分析数量」列：已选行显示输入框并预填剩余量，未选行显示「—」。已选行的数量框为空、不是数字或不大于 0 时显示必填红框，与提交校验同一口径：有红框就一定会被拦下。
- **手工需求**：一张或多张手工需求单卡片；「再建一张手工需求单」按钮在桌面端位于分段切换行右侧(销售段放搜索框的位置)，窄屏在卡片列表底部。新建的卡片追加在列表末尾，并自动滚进视野。每张卡表头为 来源类型(返工/试制/样品/备库/其他) | 需求编号(必填，最多 200 字；提示「同一需求请始终使用同一个编号，后续可凭它找回任务」) | 来源原因(必填，至少 2 个字) | 需求日期；多于一张时可「删除此单」，已有明细先确认。表头下是自研可编辑表格，列为 货品名称(必填) | 编号 | 颜色 | 规格 | 单位 | 数量(必填，大于 0) | 需求日(选填，空则用表头日期)；编号到单位只读，取自所选货品。
- **选货品**：点货品名称单元格打开多选货品选择器(范围「除未分类外的全部货品」)。第一个选中的货品填入所点的行，其余依次填入其后的空行，不够再追加新行；本单已有的货品跳过并提示。行可删、表尾可加行；表尾合计按单位分组，不同单位不相加。
- **同一编号下同一货品只能一行**；同一类型同一编号不能分开写在两张单里，页面提示合并成一张。一次分析可录多张单(例如一张返工、一张样品)，各有各的编号。
- **右下悬浮组**：「已选 N 项」胶囊 + 「联合分析所选 N 项」，N = 已选销售行 + 已选货品的手工行，合计最多 500 项；多选货品会超上限时只加入放得下的部分并提示。胶囊上的清除同时清空销售选择和手工行，有手工行时先确认。
- **提交前拦截(不发请求)**：未选来源类型、缺编号或超长、原因少于 2 个字、填了表头却没选货品、某行填了数量却没选货品、数量为空或不大于 0、同单货品重复、两张单同类型同编号、什么都没录。提示点名第几张单、第几行；只有空行(无货品也无数量)直接忽略。出错的是手工需求单时自动切到手工需求段，并把那张单滚进视野；有问题的行标红。每次点联合分析都重新判定标红，上次标红、这次已经没问题的行恢复正常。
- **分析进行中**：点联合分析后到服务端返回之前，已录内容只能看不能改：手工需求单的表头输入、「删除此单」「再建一张手工需求单」置灰，明细表格整块锁住(行尾删除收起，「添加行」、右键粘贴和键盘操作都不响应)，销售段行内数量框也置灰，保证看到的明细就是提交的内容。
- **窄屏**：同样两段放在页面顶部，一行放不下(手机加大字号)时计数换到第二行，两段都完整可见；销售段仍是候选卡 + 「上一页/下一页」+ 底部数量编辑；手工段为全宽需求单卡片，卡片列表底部是全宽「再建一张手工需求单」，数据与桌面同一套。
- 手工需求在点联合分析、服务端预览成功之前只是页面输入，不是持久化单据，也不进调度台待排列表；离开页面不保留(不在表单草稿保护范围)。同编号同货品集合再次分析会恢复原分析；货品集合不同时，看得到原分析的人收到「需求编号 X 已在物料分析 WL… 中(N 个货品)；已建的分析不能增减货品，要增减货品请换一个需求编号(只改数量请打开原分析刷新)」，看不到原分析的人(可见范围与打开分析相同，按负责人隔离)只收到「需求编号 X 已被另一份物料分析使用，请换一个需求编号」，不透露分析号。已建分析不能在原编号下增减货品，取消原分析也不会释放这个编号。

分析建立后，顶部卡片在「关联销售订单」旁显示只读的手工需求标签，按类型和编号分组，例如「返工 · RW-001 · 3 个货品」，悬停显示来源原因。

### 进页与等待 (2026-09-27 用户口径「一进就弹窗加载，会卡一会」)

- 带着来源新建 (排产看板「联合分析所选」，进页即自动分析)：第一次分析期间页面显示进度卡「正在展开 N 个产品的 BOM 并核对库存…」(N = 本次来源行数)，不再先闪一张空的候选表，也不挂「联合分析」悬浮按钮；算完直接显示物料表。在新建页自己勾选 / 录入后点「联合分析所选 N 项」时，已填内容保持可见且只读 (见 1.1「分析进行中」)，只在按钮上转圈，不换成进度卡。
- 打开已有分析 (看板双击、分析记录、车间催办直链)：读取期间显示页头骨架 + 一行说明「正在读取这份物料分析的 BOM 与库存结果…」，不是整页正中一个转圈。
- 开页只加载主仓选择所需的仓库字典；颜色、单位和货品名称使用分析快照，货品选择器按自身需要加载可选数据。颜色、单位或币种字典的慢请求不再阻塞已完成的分析结果。
- 供应方式的自动确认没有任何全屏遮罩。打开已有分析时若服务端报还有能按货品档案确认的行 (`pendingAutoConfirmRouteCount` > 0，多半是到货 / 审核等别的单据顺带重算后新冒出来的)，且本人有刷新与确认路线能力、页面没有未提交的填数 / 勾选 / 在办操作，页面静默刷新一次分析 (同一张快照只试一次，刷新回包不再连环触发)；期间顶部只有一行小提示，失败只轻提示、不挂红色错误。人工改供应方式的保存仍有「正在确认物料路线」遮罩。
- 套用快照后的四项附带读取 (在途调拨、车间在催、可调拨量、生产车间 / 负责人默认值) 由一个公共装载器合成一批并发请求，全部回来后只整页重画一次；各读取自带会话作用域与代际守卫，迟到结果丢弃。账号 / 权限变化时按作用域补取。顶部「主仓库」字段与分析编号、更新时间事实框在宽屏同一行按行高拉伸等高，不再帧后量高度再重画；手机窄屏各占一行。
- 套用快照时只核对仍勾着的行能否继续勾选；进页勾选集为空，不再对整张表逐行跑下单判据。

## 2. 来源与树形

- 销售来源以订单行 UUID 为准；手工来源以(来源类型, 需求编号)为一张需求单，每行保存类型、编号、原因、货品、颜色、单位、数量和需求日期。同一编号下同一货品(货品 + 颜色 + 单位)至多一行，编号比对忽略大小写和首尾空格；一个编号只属于一份物料分析，每个货品行各自下达计划(ADR-130，数据库规则见 [V738](../数据迁移/257-V738手工需求单多货品.md))。
- 原产品及 BOM 路径是页面稳定身份。合单后不额外把制造锚点和子件提升为用户产品，也不把原子件变成不可办理的零需求行。
- 系统制造锚点、实际计划和原需求分摊仍在后台保留。读取和命令解析依赖精确 BOM 边、来源分摊及别名证明，禁止按货品名、同货品首行或树中首行猜写入目标。
- 顶层产品保留独立销售/手工来源。组件按货品、颜色、基本单位、供应方式及相容制造参数合单；BOM 或日期不相容时不能静默采用首个来源设置，由核对说明原因。
- 同一物料的来源生产车间、负责人或超产比例不同(比例按数值比，10 与 10.0 相同)时，下单自动分成几张工单同一次提交，不再要求先统一(ADR-120 §8)。汇总视图仍是一行，办理列写明「按车间/负责人/比例分成 N 张工单」，悬浮逐张列出车间、负责人、比例和本次数量；确认框按物料品种汇总并只确认一次。各行自带数量时每张就是它那几行的数；汇总行手输总量时先按两视图同一平分规则落到各来源行再按张相加，合计与总量一致。在汇总行把车间、负责人、比例改成一样即合成一张。供应方式不同仍须先选定一种，不自动拆。
- 父件不参与合并：上层工单是谁、在哪个车间都不影响合单与分单；下层按精确对应接到各自那张父单，做好后送给哪个上层工单在报工时再分(ADR-127)。
- 汇总视图是同一组事实的可选核对方式，不是追加或继续办理的必经步骤。原行和合计必须去重，不同时累计原需求、制造锚点和其转交份额。
- 按物料汇总视图的顶层产品行（2026-10-07）：固定排在所有聚合行之前，名称前带红色「顶层」徽章（与下达车间分桶同款），是一等可下单行——勾选只带根行自己、不联动聚合行，数量 / 车间 / 负责人 / 比例格照常编辑。与组件混批下单时共用按产品视图的一次确认编排：顶层经 issue-plans / notify 逐产品下达（保留销售来源，永不进 AGGREGATE_MAKE 共享批次，服务端对 level=0 的汇总拒绝继续成立），组件照旧走汇总通道。纯组件批次仍用汇总视图自己的开跑前确认与依赖分轮。「产品任务（按产品办理）」前缀与办理列「按产品办理」按钮退役，切换视图只走表头切换。

## 3. 数量口径

| 项目 | 含义 |
| --- | --- |
| 需要数量 | 原始来源数量沿保存的 BOM 逐边计算的 `sourceRequiredQty`；下单、超量和追加不改变它。每条边按本节点锁定采用的用量计算：有真实使用数量用真实值，否则用设计使用数量；整包/固定批次、父件单位变了、委外节点的全部直属物料 (按委外合同用量) 用设计值。单元格悬停说明本行按哪个用量算、依据几批、设计值多少；按真实使用数量算且采用时的报工不良率大于 0 时，括号里另列「不良率 X」(百分数，最多 2 位小数，例如「每件按真实使用数量 0.105 计算(12 批累计，设计 0.1，不良率 3.25%)」)，按设计使用数量算时从不列出；不良率只作说明，不参与计算 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.13)；表头仍只留字、不挂说明 |
| 实际备料需求 | 真实计划产出所需的材料；随父件计划量、包装及固定批次规则变化 |
| 下单数量 | 本行实际发出的有效下单量，包含超量；不能只显示分给本需求的数量。多来源合单保留每行输入意图，行合计等于真实单据量 |
| 追加下单 | 已下单行的本次新增量。成功后累计到下单数量，本次输入归零；不能把旧下单输入再加一遍 |
| 还需安排 | 扣除已落实责任后仍须办理的量。可采用供给尚未被占用时仍需办理，不能只因看到候选供给就当作已安排 |
| 还缺数量 | 核对可采用供给后仍需补下单的净缺口；不等于实际领料缺口 |
| 可用数量 | 可安排的仓库现货，加上在途及已下达但尚未办理的供给剩余量；扣除有效占用、认领与已实收部分，按真实供给来源去重 |
| 实物缺口 | 尚未到仓或没有合法精确权益的物料缺口；用于领料/开工门禁，不能由计划可用量替代 |

用量采用与锁定 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.5)：分析在新建和人工「刷新」时才采用最新的设计/真实使用数量 (`design_bom_qty / actual_bom_qty / usage_basis`，采用时的不良率 `usage_defect_rate` 跟真实使用数量一起采用和锁定)；保存路线、下达、审批、唤醒等内部重算沿用快照里的值，只按当前路线重新选用哪一个。例外：BOM 行被原地改了计量规则 (换了组件或单位，改了计量方式、计量基数或是否允许尾包) 时，锁定值只在原规则下有意义，这条边按现时值重新取。人工刷新时，父节点已有下达计划批次的子节点保持原值，与已冻结的车间需求一致；汇总下单的共享制造批次里，锚点与各成员子树在同一相对路径上保持同一个数 (锚点第一次展开时沿用第一个成员子树的锁定值)。同一次重算若改掉了父节点的有效路线 (例如主档建议变了、人工确认被清掉)，会按新路线再选一次用量，需求与分配看同一条路线。预览、下达、汇总下单和审批因此看到同一个数；用量变化不清人工确认的路线，也不让预览报「结构已变化」、下达/审批报「BOM 直接层已变更」，只有组件/颜色/单位/层级路径/控制段/计量规则/第一层单位换算率变了才要求刷新。汇总下单批次的配方键按设计使用数量，学习不会让后续追加找不到原批次。

例如实际下单 10000，本需求安排 1000，页面下单数量显示 10000；剩余 9000 可以成为其它订单的可采用供给。另一订单采用 4000 后，剩余可采用量为 5000。实际到货时，这 4000 按认领来源归接收订单，未认领的部分进入公共库存，不产生第二份库存或销售分摊。

下单/追加的余量使用选择（2026-09-30 补齐，[ADR-099](../99-决策记录-ADR/ADR-099-计划量单一入口与子层按计划产出展开.md) 修订二）：选中行本次输入大于 0、且编辑前有公共可用余量时，追加输入按回车或离开输入框即询问；未在编辑时选择的，提交前补问。判断使用服务端共享池余额，兼容旧响应的公共现货与公共在途，不再要求仍有需求缺口，也不排除自制子件；不能因输入已把页面余量预扣到 0 而不问。

- **优先使用可用余量**：默认方式，保持勾选、输入后预扣页面可用量的流程；下达时按真实需求与供给资格采用余量，不足部分再下单。
- **保留余量，额外下单**：本轮输入不预扣共享预算，服务端跳过自动认领公共未来供给，按填写数量新增下单；需求之外的数量记入公共备货。新公共供给按实际业务状态进入计划可用量，入库前不能当作可领现货。
- 选择应用于本次所选行及其车间、采购、委外、同料合并各段，表格上方显示当前方式并可切换。取消不下单；失败保留输入和方式；成功后下一轮重新选择。需求已经满足的追加不重复占用需求，仍按公共备货办理。

编辑中的共享预算：优先使用余量时，只有勾选且有效的本次下单量或追加量才预扣可用量，扣至 0；取消选择、清空或减少数量即释放差额。选择额外下单即释放本轮预扣，切回优先使用时恢复预扣。同货品、颜色、基本单位及供给范围使用同一预算，不把每条 BOM 行的重复仓库数据累加，不把历史下单量再次扣除。可用数量列只显示仍可安排的共同余量，本行已经占有的份额不再加回该列；本行私有预留与已领用覆盖仍用于扣减本行缺口。该扣减是页面本轮编辑预算，不写库存或认领；提交后以重新读取的正式供给事实重建预算。还缺数量同时按本行需求与剩余可用量重新计算。

各产品行的首次或追加输入相互独立。修改 A 的输入不会减少或覆盖 B/C 的默认量或手工量，只同步共同可用量和缺口；同一个产品的父件与其子件仍按 BOM 联动。三个产品各需 1000，三行分别输入 10000、1000、1000 时，实际提交总量是 12000，三份占用合计 3000 后共同可用为 9000；实际总下单 10000 且三份需求均已安排时共同可用才是 7000。确认下单显示本次实际合计。

同一合单中 A 填 10000、B 填 1000，应保留 10000/1000 的原行提交意图，不能因需求相同比例回显成 5500/5500。历史记录缺少逐行输入证据时，只能显示有依据的分配与单据总量，不能倒推成“当时输入”。

自制原工单增长按累计产量计算材料差额：`f(原量+追加)-f(原量)`。包装、固定批次按真实执行批次取整，不能对多个来源各取整一次再相加。

## 4. 父子联动与输入保护

- 父件修改首次下单或追加数量后，所有实际受影响的后代重新计算缺口和建议量。折叠、分页、尚未创建输入框的子件同样参与。
- 子件新增缺口默认勾选；不把“保护手工数量”当作跳过勾选同步的理由。用户明确取消的选择保留，显式重新选择父树可以重新选满。
- 手工数量不被后台刷新、迟到预览、系统建议或其它行编辑覆盖。首次下单与追加只读取当前有效的数量列，预览与提交一致。
- 首次和追加都可分批。采购起订量/倍数只作为有权限时的系统建议；没有需求不自动抬量，手工输入仍由用户决定。
- 汇总手输首次总量的下限按各来源当前未安排需求的四位定点原文精确求和；显示精度不能改变校验。单位“个”且三来源各需 0.5 时，1.5 可下单，1.4999 仍低于合计；真实 1000.0002 不能降为 1000。按产品逐行分批与追加额外量保留原规则。无效或缺失的精确事实明确阻止提交，不按 0 继续计算。
- 已下单数量、已有单据的供应方式和生产参数按真实单据锁定；新增量在追加格办理。原行和精确转交目标共同决定是否已下单，不能因单据挂在共享制造树就重新放开原行供应方式。汇总行只有全部来源可修改时才允许改供应方式，不能悄悄只改其中未锁的几行。补充指派在同一核对页完成，不因为缺少车间/负责人把复选框直接隐藏。
- 这种锁定也适用于 BOM 结构刷新、主档变化和其它单据触发的重算。同一实物身份已有真实计划或申请时，以原单据的唯一供应方式保护路线，不因重算清空后又按新主档自动换路线；未下单节点仍按原规则重新确认。来源缺失、实物身份矛盾或真实单据路线不相容时明确阻止写入，不按首行猜测。
- 需求已全部安排、当前缺口为零的已下单来源，满足既有下达权限、计划资格、BOM 与精确来源身份要求时仍可勾选并显式追加，默认追加量保持零；额外量沿既有公共备货规则办理。有效原单只恢复办理上下文，不绕过这些门禁。真正失效且没有有效办理责任或有效原单的来源保持只读，撤销的订单、他人公共供给认领和同货品的其它来源不能作为复活依据。最小有效数量 `0.0001` 同样视为已下单。
- 按物料汇总的超产比例同样遵守已下达冻结：任一来源已有下达记录时，汇总比例只读；尚未下达的独立来源可切到按产品设置。追加不能借汇总比例框修改已有工单，既有比例调整仍走计划审批及数据库版本保护。
- 允许超产比例列 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.10)：按货品默认预填——有记住的最近一次人确认比例用它，否则结构默认 (货品来源采购/委外 0%；制造底层 10%，上层 0%)。没被人改过的格子下达时提交空值，由服务端按默认填写、标 `DEFAULT`、不记住，新快照带来新默认值时跟着刷新；人改过的按所填值提交 (`EXPLICIT`) 并记成该货品下次默认，文字不再跟着刷新，但判断「是不是还等于默认」改按新默认比 (之后改回旧默认也算人填的)。汇总下单表的比例格在各来源都没人改过时跟着来源一起刷新到新默认；撤销草稿时，当时仍是系统预填的格子回到当前默认值，不把旧默认当成人填的放回去。本页、汇总下单表与计划编辑页判断「人改过没有」用同一个助手 (`SystemPrefilledRates`)。计划单带来的比例 (人改过才会带来) 同等明确提交。已下达的比例随工单锁定显示，修改仍须计划部审批。

## 5. 自动合单、追加和性能

组件共用汇总命令，单来源也经过相同的权限、数量、来源和幂等核对。顶层产品先办理，再按真实父子依赖执行组件；同一依赖层合批，父件落地后按权威快照核对下一层。不得把非重复子件先全部下掉，再提交重复父件。全选下单只确认一次(产品视图主确认、汇总视图开跑前确认；汇总视图勾了顶层产品行时同样共用产品视图主确认)，之后的依赖分轮静默办理，失败即停并保留输入与已成功回执 (ADR-120 §2.4；2026-10-07 起汇总视图不再逐轮弹确认框)。

未提交领料、未发生执行事实且参数相容的自制追加进入原计划及原 ZX 工单，保留 UUID 与单号；已提交领料、发料、开工、报工或拆批时新建任务，旧历史不改。采购/委外未被下游操作的申请追加到原明细，已操作后按现有规则新建责任。同一物料分析的采购申请/委外申请本身**滚动合单**（ADR-065 修订三，2026-10-08）：同一分析、同一路线至多一张「开口」申请，一次批量下达的多个组、多个依赖轮次、乃至与经典明细通道混用的下达，只要该申请还没被订货单引用（含待财务审核的草稿订货单）就并入同一张——不再出现同一 WL 单据号并排多张碎片申请；行数达 500 或已被下游动过才另开新单。滚动单的**撤回是整单连带**（ADR-065 §2.3 既定语义在滚动单上的自然扩大）：撤回共享这张申请的任一批次/任务，同单全部行动（含经典通道的顶层行任务）在同一事务一并撤回、单据只红冲一次；任一明细已订货（`ordered_qty>0`）则整批拒绝（fail-closed，先红冲下游订货单再撤）。

- 同一分析的写入具有共同版本、库存和来源锁，不能用客户端无界并发加速。
- 一次提交最多 500 组(一个物料分成几张工单就算几组)、10000 条来源路径；同料不因来源条数被误拆成多张单，只因做法不同而分开。同一次提交里同一物料的几张单逐张落账，后一张不会采用前一张新做出的公共备货份，各张数量与确认框一致。
- 上述是请求容量上限，不是响应时间承诺。原事务截止时间继续生效，超时的当轮整批回滚，不能向员工提示整批成功。分轮提交中已经成功的前轮保留真实回执，失败轮输入保留供核对。具体规模、硬件和耗时记录在专项验证中，不作为页面规则固化。
- 缓存每份快照的节点索引、精确来源图和行投影；两种视图共用来源图查找实际单据，切换快照后重新建立。服务端保留真实 BOM 边匹配、多目标与重复边歧义校验，将同一次读取中重复的来源预算计算合批。必要的父子刷新仍按依赖顺序保留。
- 独立制造组可分阶段建立锚点并集中刷新；共享原材料的实际审核仍逐计划读取最新库存。单个计划在完整锁内复用不可变的执行预览，正式库存/执行写入之前立即失效，不跨计划或事务复用。分析内部创建/审核读取轻量命令结果，普通计划详情和追溯接口保持完整。
- 已证明无祖先/输出/供给交叉的制造组，按阶段批量读取来源容量和精确 BOM 责任；每份读取按真实批次及父件分配隔离，不能按同货品推断归属。单计划完成后 flush 并清理 JPA 已完成实体，数据库事务及原锁仍保留。
- 数量预览只读，300ms 去抖、单飞并尾随最新输入。预览不建计划、不写库存、不通过真实下达再回滚模拟。
- 普通预览采用公共自制供给时，根行同步显示这份未来覆盖与采用量，不能继续把同一份数量显示成还需安排，也不能算成已经入库。选择「保留余量，额外下单」仍按填写量办理并保留公共供给；这是提交时的明确选择，允许与之前普通预览不同。默认选择继续按预览数量办理。
- 过时的编辑预览取消客户端请求，同签名有效预览继续复用；取消不代表服务端 SQL 一定已停止。一次整树下单完成或部分失败后统一刷新辅助数据及徽章，后继计划必须的指派读取仍先于提交。
- 命令使用版本、指纹和幂等键；网络失败不擅自重放不确定写入。409 更新事实后重新核对，未提交输入保留。
- 后台动态数量变化应刷新可用量、累计、缺口与流程阶段；服务端动态投影变化不以分析头版本未变为由忽略。
- 45 秒轮询与返回即刷新先比较版本、指纹和动态投影，三者都没变就不套用——有未提交输入时也一样 (2026-09-27 之前编辑中会不比较就整份重新套用，每 45 秒整页重画一次并补发一次汇总预览)。变了才按「保留未提交输入」的口径套用。

## 6. 三个桶与进度

主表、桶清单、核对页共用办理数量和权限。采购与委外用真实申请/订单链的 `flowStage`，车间用真实计划与执行事实；文案来自 `ProductionFlowStage`，颜色统一由 `MaterialPreparationStatusStyle` 按待处理、进行中、待收货、完成、阻塞、取消等语义映射。主表最后的待办列和三个桶使用相同整格背景、文字色，不因采购、委外或车间不同而换色；保留每种业务真实步骤名称。不再加“并入共享批次”等技术前缀。

进度不能把“已经下单”说成“已经入库”，也不能因需求已转交就说“未下达”。已有明确单据阶段时优先显示它，认领数量、缺料解释和来源分摊放在详情，不掩盖真实流程阶段。

桶左上角统一使用 `UtenFilterToolbar` / `UtenFilterSegment`，只保留待处理、进行中、需处理；已下达分类退役。待处理计数为红色，进行中黄色，需处理作为待处理的子集用中性计数，不重复累加。

三个入口继续使用工作台同款黄色进行中、红色未下达徽章，零数隐藏、超过 99 显示 `99+`。徽章与点击后的列表使用同一行投影。完成和取消只保留历史；部分下达可同时有待安排和进行中状态。

### 6.1 委外行：下达委外、缺 BOM 与自动刷新([ADR-143](../99-决策记录-ADR/ADR-143-委外按工序领直属物料与分批回厂.md))

- **只下达委外**：委外节点(任何层级，包括顶层产品、中间层、公共超量和按物料汇总下单)一律「下达委外」，生成委外申请并通知委外部。顶层产品经 `POST /{id}/notify` 下达，组件在两种视图中都经 `POST /{id}/aggregate-orders/preview` 核对、`submit` 提交；数量像采购一样可分批、可超量备货(需超量下达权限)、可自动认领别人的公共在途。不下达车间，不建任何「先在厂内做委外件」的任务；`issue-plans` 只处理自制行。汇总下单的委外批次永远是外部批次。
- **直属物料照常展开**：委外件的直属物料(可发外的直属边：按件用量、生产投入阶段、按单领料、用量大于 0)作为需求节点出现在树里，按各自路线下达(自制下达车间、采购下达采购、嵌套委外再下达委外)。委外申请在途时直属物料不会被委外件自己的在途抵掉；需求按委外件的计划产出展开(含公共超量)。领给委外商的物料按「待发 + 已发净量 − 按合格入库回厂量折算的耗用」覆盖需求。
- **缺 BOM**：委外件没有可发外的直属物料时，该行状态显示「缺 BOM·已通知研发(研发任务号)」，下达委外的勾选框不可勾；服务端下达同样拒绝「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善，研发保存后物料分析会自动更新」。分析新建或刷新发现缺 BOM 时，系统自动给工程研发部建一条「完善 BOM」研发任务(同一货品只建一条，分析制单人或当前操作人加入等待名单，来源记分析号)并通知研发，不重复打扰。
  - 「缺 BOM」标记与自动通知研发只挂在有需求的委外节点上：需要数量大于 0，或节点上挂着有效的委外供给分配(委外 SUPPLY 行动处于 OPEN / CREATED / IN_PROGRESS 且分配量大于 0)。需求为 0 的委外节点(例如上层改成采购后留下的子件)不标、不转研发。
  - 下达仍按货品拦：下达委外、汇总下单的预览(`blockedReason`)与提交用同一个按货品的判定，真要下达的委外件缺 BOM 一律 409 并转研发，不看那一行有没有标记。
- **研发完善后自动刷新**：研发在货品 BOM 里补好直属物料并保存后，研发任务自动完成；系统给每张含这个委外件、还没按新 BOM 展开、仍未结束的物料分析各排一条刷新事件(`MATERIAL_ANALYSIS_BOM_REFRESH`)。事件投递时以分析负责人身份、在独立事务里只刷新这一张(与人工「刷新」同一套锁，组件表按新 BOM 重新展开出直属物料节点)；刷新失败按事件队列退避自动重试，不影响其它分析。计划员不用手工刷新。等这张分析的人在它刷新完之后才收到「{货品} 的 BOM 已完善，物料分析已自动更新，可以下达」；分析已结束、负责人账号不可用等不能自动刷新时，改收「{货品} 的 BOM 已完善，打开物料分析刷新后即可下达」。自动刷新新展开出的行不自动确认路线，打开分析时按「进页与等待」的静默刷新补确认。
- **进度阶段**：委外行的待办列按领料读模型显示：等待下发委外 → 等待委外下单 → 已下单·待财务审批 → 已审批·等待物料 / 物料可领·待委外领料 / 已提交领料·等仓库发料 → 委外加工中·等待回厂 → 来料质检 → 待入库 → 已入库。步骤条第 3 步为「领料发外」，显示「已领 x/Q」，不把不同物料的数量相加。供给进度弹窗标题「委外领料与加工进度」，可点开委外申请、委外订货单、委外材料出仓单和回厂单。

## 7. 仓库、执行与反向

所属仓库、归属车间直接来自 `goods` 的归属字段，与货品资料、仓库及车间使用同一事实源。正常业务入库通过 `GoodsOwningWarehouseSyncService` 学习真实仓库；确认生产指派通过 `ProductionGoodsWorkshopPreferenceService` 学习默认车间及负责人。准备页重新读取时同步这些字段，即使分析版本没有变化也要更新。带未提交草稿时保留各行数量文本、选择和路线决定，同时刷新归属、供给数量和真实进度；核对下单页打开时仍沿同一读取通道刷新。结构变化只保留仍有精确原行对应的草稿并提示核对，迟到的旧请求不能覆盖较新的归属修改。2026-10-04 起([ADR-145](../99-决策记录-ADR/ADR-145-仓库主档单主仓与禁用不可选.md))所属仓库列点开的是运营口径面板：先加载完整仓库字典，只能选服务端标出的可选良品子仓(主仓、停用仓、不良品仓、车间内料仓都不列)，服务端只在值变化时按同一定义校验；入库学习也不会把所属仓库学成不良品仓或停用仓。

顶层产品已有本产品实际生产计划时，生产车间和负责人显示真实计划/执行任务的指派并锁住；不再显示可修改下拉框，也不由最新货品默认值替换历史指派。只有采用他人供给而没有本产品生产计划的情况不能借用来源计划的指派。货品默认归属更新与已下单任务指派是两种事实。

计划员选择主仓库。服务端展开合法子仓并保存真实库存归属；实际领料、送检与入库由对应仓库办理。公共计划可用量不能转成 READY、正式预留或已发料。

MAKE 缺料允许先下达 WAITING，实际领料和开工仍要求合法到货与本执行批所需材料。`SHIP/REFERENCE` 仅供参考，不生成正式物料需求。委外行不管有没有下层、有几种直属物料，一律「下达委外」，只需下达委外权限，不要求车间和负责人，详见 6.1。

自制公共供给以真实计划明细为来源，认领只是供给承诺。实际成品入库才建立原有库存预留、精确归属和权益事件；不能继承原计划的私有销售/用料身份。撤回只释放尚未实收的认领余量；已领用或已下游转移的实收按原反向顺序恢复后才能红冲。目标分析合法释放实收权益后，V723 关闭相应承诺，后续源入库红冲不得复活已取消目标。

取消分析成功后返回来源页并刷新计数。撤回某笔供给仍留在当前分析核对其它任务，不能通过原单一来源撤回入口取消其它来源的份额。

按产品与按物料汇总的撤回入口沿同一精确来源图寻找实际单据，不把“原行没有直接供给引用”解释成“已并入既有单据”。共享批次显示整批撤回，普通供给与认领分别走原撤回接口；同一批次只列一次。整批确认展示真实分配来源、需求份额、公共备货和安全补库，使用服务端四位精确数量核对，不把展示别名复制成第二份分配。任一关联原行仍有未提交汇总草稿时先处理草稿；来源不完整、权限已变或确认期间快照已更新时停止并要求重新核对。服务端继续校验当前权限、完整版本与真正执行事实，重复请求不新增或重复撤回任务。

## 8. 接口与验证

接口前缀 `/production/material-analyses`。读写表示协商见[响应协议](../05-架构/物料分析响应协议.md)。

| 动作 | 接口 | 权限/约束 |
| --- | --- | --- |
| 分析/授权刷新 | `POST /preview` | create/refresh, 持久化分析, 不下达任务; 同一次重算里按货品主档自动确认供应方式 (需 route 且可确认路线, ADR-102 2026-09-27), 响应 `autoConfirmedRouteCount` = 本次确认的组数 |
| 查看详情 | `GET /{id}` | view 与对象范围; `pendingAutoConfirmRouteCount` = 还能自动确认但尚未确认的组数 (通常是别的单据顺带重算后新冒出来的行; 无 CONFIRM_ROUTES 能力时恒为 0), 有刷新与确认能力时页面静默刷新一次 |
| 人工改供应方式 (直改即存) | `PUT /{id}/routes` | route, 已有单据的路线守卫照常执行; 自动确认不再走这里, 同一次重算里新冒出来的子件一并自动确认并计入 `autoConfirmedRouteCount` |
| 顶层产品下达 | `POST /{id}/issue-plans` | generate，立即审核另需 production_plan:approve；只处理自制行，委外候选行拒绝 |
| 下达采购 / 委外 | `POST /{id}/notify` | notify；委外行缺 BOM 时 409 并自动通知研发(研发任务在独立事务里保留) |
| 下达数量预览 | `POST /{id}/issue-plans/preview` | 只读投影，同一快照、结构与版本核对 |
| 组件核对/下单 | `POST /{id}/aggregate-orders/preview`、`submit` | 原行来源解析、兼容核对、完整锁内重算、幂等 |
| 公共供给认领、撤回、调拨 | 对应专用命令 | 来源容量、对象范围、独立权限与反向守卫 |

合单预览保留物理执行行 `materialLineId`，同时返回本次原产品树的 `originalMaterialLineIds`，并纳入预览指纹。客户端核对完整原行集合及同份分析的精确别名图；兼容无新字段的响应时只沿该图解析，禁止按同货品猜测。任何丢失或冲突都保留本轮输入并停止后续提交，不能把内部编号变化当作该层已完成。

验收同时覆盖正常/部分/超量、不同来源不等量、任意层级追加、包装阈值、多目标及嵌套合单、未渲染子件默认选择、手工输入保留、缺路线/权限、父成功子失败、重复和并发提交、供给采用后实收/撤回/红冲。源码测试、隔离数据库、当前运行进程和用户业务验收分别报告。
