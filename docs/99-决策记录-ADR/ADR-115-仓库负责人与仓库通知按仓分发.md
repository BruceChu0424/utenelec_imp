# ADR-115 仓库负责人(仓管员)与仓库类通知按仓分发、任务中心「我的仓库」

- 日期：2026-09-24
- 状态：已实现(源码)，迁移 V693；服务器仍在 V688，需本机发版。
- 相关：ADR-017(跨模块只经 application.port)、ADR-073(叶子仓记账)、ADR-105(审计三清单)、ADR-108(徽章汇总)。

## 背景(用户原话)

> 目前仓库未做细分，存在几点问题：多个仓库由多个人员负责，但仓库的通知是统一全部收到的。成品仓库比较简单只要注意产成品出入库就可以，但其他仓库比较麻烦，领料、委外、采购、产成品的出入库都有涉及到，没有一个快速找到自己仓库相关单据的方法。

此前所有仓库类通知都按「仓库部门(SUB_WH)子树 × 该通知所需权限」发给池里的每一个人，单据落在哪个仓只写进通知正文；平台没有「员工 × 仓库」的负责关系(`ProductionStockTaskAccessPolicy` 注释原文：no employee-to-warehouse assignment table)。

## 决定

### 1. 负责关系是仓库主档的附属设置

- 新表 `warehouse_keepers(warehouse_id, employee_id)`(V693)，在「仓库资料」详情里「设置负责人」整组替换，`warehouse:edit`。
- 指向员工而不是账号：负责是组织事实，账号停用/重建不应丢关系；读取时统一换成在职员工的启用账号。
- 登记在主仓(有下级的仓)上 = 负责它下面全部子仓：仓库主管登记在主仓上就能收到全部仓的通知。
- 候选人列出全部在职员工，仓库部门的人排前面，并标出「没有账号 / 不在仓库部门(收不到仓库类通知)」。

### 2. 通知按仓分发(`ChainNoticeService.warehouseRecipients`)

收件人 = 原通知池 ∩ 单据所在仓(含各级上级仓)的有效负责人(`fn_warehouse_keeper_user_ids`)。三个兜底都退回整个原通知池，宁可多发，不让任务掉进无人区：

1. 该仓没有登记有效负责人(未登记、负责人离职或账号停用)；
2. 单据还没定仓；
3. 登记的负责人都不在池里(不在仓库部门或缺这项通知要求的权限)。

「单据所在仓」逐类取：成品入库草稿 = 入库单仓；成品待登记送检 = 成品货品主档的所属仓库(V587，目标仓要到登记时才选)；生产领料 = 领料单发料仓；IQC 待入库 = 检验明细目标仓；IQC 结案 = 目标仓 + 先入库后检的上架仓；销售待拣货/撤回放行 = 出货单表头仓 + 逐行拣货仓(V631)；委外出仓 = 计划行备料仓 + 未审出仓草稿仓；委外预计回厂/撤回 = 委外订货单收货仓；采购预计到货 = 预计到货目标仓；到货异常定案 = 异常行的仓。12 处仓库通知池全部接入(`ChainNoticeWarehouseKeeperRoutingTest` 用源码计数钉住，新增仓库通知漏接会失败)。

权限与读侧资格(`ReviewNoticeAudience`)不变：分发只会把收件人变少，不会让没有权限的人收到。

### 3. 任务中心「仓库范围」

出库 / 入库 / 生产领料三个任务中心顶栏加「仓库范围」：

- **我的仓库**(`warehouseScope=MINE`) = 我是有效负责人的仓(含子仓) + 尚无有效负责人的仓 + 尚未定仓的任务(`fn_user_warehouse_scope_ids`)。与通知分发同一口径：我收得到通知的单据，列表里都看得到。
- **全部仓库**：不过滤。
- **某个仓**(`scopeWarehouseId`)：该仓 + 子仓(`fn_warehouse_scope_ids`)，不含未定仓的任务；用于替同事顶班。

接入的列表：生产领料待领任务(与子分类计数)、领料单/退料/产成品出入库/其它出入库(库存单据，发出仓或调入仓在范围内)、销售出库(表头仓或任一明细拣货仓)、委外出仓任务(备料仓或草稿仓)、采购/委外预计到货(与分来源计数)、到货异常、产成品待点收(待登记按成品所属仓库归属)。

选择按账号记忆(`user_preferences: warehouse.taskScope`)；从没选过时，登记为负责人的账号默认「我的仓库」，其余默认「全部仓库」。还没人登记负责人时「我的仓库」等于全部仓库，服务端直接不加条件。范围只决定列表显示哪些单据，不改权限：各端点照旧按原权限与对象范围校验。

跨模块实现：范围与负责人解析是 `application.port.WarehouseTaskScopePort`(实现 `WarehouseKeeperService` 在 master 模块)，各模块控制器只依赖端口；范围条件由 `WarehouseTaskScope.predicate` 生成、值一律参数绑定。

## 不做 / 后续

- 工作台与任务中心的红徽章仍是全公司口径(ADR-108 汇总)，没有按负责人拆分；分段里的列表与子分类计数(待领任务子分类、预计到货分来源)已按范围。按负责人拆徽章需要逐个来源改计数 SQL，另开任务。
- 不按负责人限制可见性或操作权限：负责人只是分发与筛选的依据，顶班、主管复核仍可切「全部仓库」。

## 验证

- 真库(本机 PostgreSQL 16.13 + Flyway 11.7.2)：V1→V693 全量迁移通过；三个函数的负责人继承、离职/停用排除、无负责人仓兜底逐条核对(见数据迁移说明 236)；各列表新增 SQL 条件在真库结构上执行通过。
- 单测：`ChainNoticeWarehouseKeeperRoutingTest`(分发与三种兜底、12 处接入计数)、`WarehouseTaskScopeTest`、`WarehouseKeeperControllerContractTest`、`FulfillmentWorkbenchQueryServiceTest`(排序与范围)；前端范围参数与选择器用例。
