## 一、已经批准进源码的架构边界

1. 公司本地 PostgreSQL 是日常唯一可写主库。本地 App 和云端 App 在链路正常时都把业务事务提交到该主库。
2. 阿里云 PostgreSQL 是异步物理热备，不是第二个日常写库；“近实时”不等于零延迟或零 RPO。
3. 公司到云端链路断开时，公司员工继续使用本地 App/主库；云端员工业务请求返回 503，不缓存、
   不排队、不断网后静默重放业务写入。恢复后通过复制槽保留的 WAL 自动追平，因此没有双库业务冲突合并。
4. 若业务要求断网期间本地与云端都继续写，必须停止本方案，逐业务域重新设计命令幂等、因果顺序、
   库存/金额守恒、补偿和人工冲突审批；不得把 PostgreSQL 改成两个可写节点后宣称完成。
5. 员工账号默认 `remote_access=FALSE`。公司内网使用本地入口；只有被显式授权的员工可从云端入口登录。
6. 本地入口同时受服务器端 CIDR 门禁保护；云端登录、refresh 和每个员工业务请求都受远程授权门禁保护。
7. 本地与云端使用同一个私有 OSS Bucket。附件确认后绑定服务器实际校验和哈希的精确 `versionId`；
   生产版本化存储遇到空 `storage_version` 必须失败关闭，不能回退读取 current 版本。
8. 热备不是备份。误删、勒索、错误更新和逻辑损坏会被复制，必须有独立加密备份、连续 WAL/PITR 和恢复演练。

## 五、需要配置的输入（不是上线证明）

真实值只进入服务器密钥管理、权限受控的 `/etc/uten-imp/server.env` 或等价设施，不进入 Git、聊天、日志或文档。

- 本地：`UTEN_PROFILE=prod`、数据库 URL/账号/密码、JWT issuer/密钥、CORS、可信代理、允许 CIDR、OSS 凭据。
- 云端：`UTEN_PROFILE=cloud,prod`、主库/副本 TLS JDBC URL、同一 JWT issuer/密钥、CORS、可信代理、
  OSS ECS RAM 角色、Bucket/endpoint/region。
- 复制：主/备 CIDR、管理员/复制/App 角色秘密文件、TLS CA/证书、PGDATA、槽名和有限 WAL 参数。
- 客户端：原生 Release 固定受控 `API_BASE_URL` + `CLOUD_API_BASE_URL`；Web Release 同源 `/api`。

填写这些变量只表示“配置输入齐全”。目标资源创建、迁移、故障、恢复、容量、权限和 UAT 没有证据时仍不能上线。
