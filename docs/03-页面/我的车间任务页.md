# 我的车间任务页 (/production/workshop-tasks)

## 2026-09-18 六轮 确认步骤删除：路线自动识别（V606 / ADR-091 批注）

用户口径：「不用确认路线这个操作了，这个确认路线的步骤删除吧，然后自动识别生产
路线就行。」——二~五轮围绕「确认」打磨的整套交互（下拉草稿、确认路线(N)、批量
设置路线、路线记忆、多选联动）随确认门一起退役。

- **自动识别规则（服务端创建事务内赋值，单一事实源 `fn_auto_execution_start_route`）**：
  有本车间直送供给的子件（V605 收紧后=自制口径直送资格）且在 WAITING → **持续
  生产**；其余（零料/下达即齐套/纯仓库供料）→ **齐套生产**。分批生产不由创建时
  识别——点「分批生产领料」本身就是选择分批（拆批后根段取消、批次段=齐套、剩余
  段继承分批）；「部分开工 · 持续生产」同理动作驱动：服务端对未动过的工单在同一
  事务把路线切到持续生产。冻结尺不动：动过（领料单/报工/预留/供给钉）即不能再改。
- **路线列 = 只读徽章**（四轮配色：齐套绿/分批蓝/持续品红 + 图标）：悬停说明识别
  规则；已冻结的行悬停说明冻结原因。下拉框、色标竖线、草稿全部删除。「生产中/
  历史任务」仍无此列。
- **入口全部动作驱动**（不再看「已确认哪条路线」）：开工/去领料按识别出的路线放行
  （持续生产未部分开工前不放行，原因点名持续序列）；「分批生产领料」看
  `canSplitBatch`（现有物料能配齐一部分就出现）；「部分开工 · 持续生产」看
  `canStartContinuousSupply`（每种直送子件已到一部分就出现）。点哪个动作=选哪条
  路线，服务端同事务切换，未动过的尺子不变。
- **确认按钮退役**：「确认路线(N)」「批量设置路线(N)」不再渲染（任何计数下）；
  首列勾选回到只服务批量领料/批量开工/批量报工。
- **人工纠偏保留**：行右键菜单/详情弹窗「重新确认生产路线」三选一弹窗（预选当前
  识别值；只有齐套可选时直确认不弹窗），提交走 confirm-route 端点（服务端**同值
  幂等**——重复确认成同一条不是新决定；改值仍要求 WAITING 且未动过）。提交期间
  全屏加载遮罩（五轮通道沿用）。
- 等待方式按路线区分（五轮词表扩展）原样保留：等待物料到齐·齐套生产 / 等到货·
  分批生产 / 等直送料·持续生产；到货进展卡的下一步提示按识别出的路线分流。
- 已知边界：直送资格在创建**之后**才出现（同车间后来才开工同货品工单）的段仍识别
  为齐套，自动提升可能先顶成 READY——覆盖路径是动作驱动的部分开工入口；不为该
  子集恢复人工确认。`suggestedStartRoute` 路线记忆（V602）失去前端消费方，服务端
  投影与索引保留待后续清理。
- 迁移：[V606](../数据迁移/195-V606开工路线自动识别.md)；测试：车间任务页 28 用例
  （只读徽章/确认 UI 缺席/配色与等待文案/入口动作驱动/纠偏遮罩）+ 服务端
  `ProductionExecutionRouteGateEndToEndTest` 重写为自动识别语义。

## 2026-09-18 五轮 确认路线反馈对齐物料分析：全屏加载遮罩 + 按钮按需显示 + 等待按路线区分

> **2026-09-18 六轮已取代**：确认路线的按钮/流程整体退役（自动识别），本节的
> 加载遮罩通道（沿用于纠偏提交）与等待文案词表扩展仍有效；「按钮按需显示」
> 随按钮一起消失。

用户口径：「点击确认路线后中间应该显示加载的弹窗」「没有需确认路线的这个按钮就不显示」
「批量设置路线的按钮只有多选才显示」「路线应该可以随时更改，即使确认了也可以更改——
你看看物料分析准备页面怎么实现的」「一旦确认了，等待物料的方式就应该不一样了」。

- **全屏加载遮罩**：「确认路线(N)」串行逐单提交与单行提交（右键菜单/详情弹窗/单选项
  直确认）共用 `_confirmingRoutes` 通道，挂 `UtenBusyOverlay`（root Overlay 全屏蒙版 +
  屏幕正中卡片「正在确认生产路线」）——物料分析 2026-09-15 起「确认物料路线也盖遮罩」
  同款（此前只有按钮转圈，大列表时用户误以为卡住）。完成即撤，结果提示期间不转圈。
- **按钮按需显示**：「确认路线(N)」计数为 0 时**整个不显示**（此前常驻置灰可点、点给
  「保留草稿」说明——该说明通道随按钮隐藏退役，纯等料草稿保留在行内下拉，到货卡按
  路线提示下一步）；「批量设置路线(N)」**多选（≥2 勾选）且有可设置行才显示**——只勾
  一行时改行内下拉就是批量设置（多选联动同款），按钮没有意义。
- **等待方式按路线区分（词表扩展）**：`ProductionFlowStage.forSegment` 新增可选
  `startRoute`，本页状态列传入——确认后 WAITING 的文案从通用「车间已收到 · 等待物料」
  分裂为 FULL_KIT「等待物料到齐 · 齐套生产」/ BATCH「等待到货 · 分批生产」/
  CONTINUOUS「等待直送料 · 持续生产」；色档仍为 waiting 琥珀（状态语义不变，路线颜色
  在路线列徽章/色点上）。未确认保持通用文案。见[物料分析 §3.7](生产物料分析页.md)。
- **「确认后也可更改」口径核实（对照物料分析）**：物料分析的路线在**没有下游行动**
  （已下达/供料行动/产出交接）前随时可改；本页同一把尺——**已确认且未动过**（无领料单、
  报工、正式预留、供给钉）的工单，下拉一直是可编辑的（改→自动勾上→确认路线提交，即
  「重新确认生产路线」）；一旦动过（如确认齐套后自动提升**建了领料单**）路线冻结，只读
  徽章悬停说明冻结原因（「已产生领料单、报工或预留（或已开工），不能再更改」）。这是
  V599/ADR-091 的守恒边界（对抗审计 M1：动过的工单改路线会把出口封死成永久 WAITING），
  与物料分析「已有计划/供料行动冻结」同构，不放开；表头 ⓘ 说明补了这半句。
- 测试：按钮显隐（单选/多选/无可确认）、忙遮罩（门控假仓库挂起提交断言遮罩挂载与完成
  撤下）、三条路线各自的等待文案与冻结徽章色。

## 2026-09-18 四轮 路线配色：齐套绿 / 分批蓝 / 持续青绿

用户口径：「每个工单能不能三条路线（齐套/持续/分批）都可选？不可以就算了」
「不同生产路线对应不同的颜色，不然不好区分」。

- **三选一收窄维持不变（评估后不放开）**：齐套恒可选；分批需有物料子件需求
  （零料段没有「按可配齐量拆批」的依据，分批=齐套，服务端同口径拒绝）；持续
  需至少一个子件可由本车间直送供给——直送子件「到一批投一批」是持续生产的
  引擎，全走仓库领料的工单选了持续 = 选了一条永远开不了工的路（部分开工要求
  每种直送子件已到一部分，没有直送子件就永远不满足）。收窄只发生在「选了也
  走不通」的工单上，是防呆不是限制（ADR-091 §2.1/§三）。
- **路线配色**（全站徽章六档里取三档，与同行状态徽章不撞色——分批/持续行必然
  还在 WAITING(琥珀)，齐套的绿与「齐套·待领料」青绿、「可开工」蓝分得开；
  绿色「已完工」只在历史任务出现，而历史任务没有路线列）：
  - 齐套生产 = 绿（success）· 图标 checklist；
  - 分批生产 = 蓝（info）· 图标 call_split；
  - 持续生产 = 品牌青绿（accent/teal）· 图标 all_inclusive。
- **落点**：路线列冻结/只读行 = 带图标与路线色的徽章（替换原纯文本）；可编辑
  行 = 下拉左侧 8px 色点，**跟随下拉当前值（草稿/路线记忆）实时变色**——确认
  前就看得见将选哪条；详情弹窗「生产路线」行 = 同款徽章（未确认仍灰字提示）；
  确认路线弹窗选项图标、批量设置路线面板说明行图标同套上色。色点深色模式用
  亮档（successOnDark/infoOnDark/teal300）。

## 2026-09-18 三轮 批量设置路线 + 路线记忆 + 确认只提交可开工行

用户口径：「多选后生产路线可以批量设置（新建采购统一设置条款同款）；生产路线要
带记忆，下次默认选择上次选择的；多选后确认路线——只有可开工的是走生产路线，
其他的还能修改」。

- **首列勾选门再放宽**：等待物料行 = 路线可设置（未确认，或 WAITING 未动过可
  重选——含已确认未改动的等料行）∪ 齐套链动作。此前门太窄：整页都是「已确认
  齐套路线、还在等料」的行时**表头三态全选框直接禁用**（就是「最顶上的那个
  不能选择」的来由）；放宽后这些行可勾、进批量设置路线。
- **「批量设置路线(N)」**（右下，新建采购「统一设置条款」同款底部面板）：
  勾选后一次选一条路线，写进所有**路线可设置且事实允许该路线**的行（写的是
  会话草稿，不是提交）；工单事实不允许该路线的行自动跳过并计数提示；设成
  已确认值的行脱脏脱选（与单行改回同口径）。之后仍由「确认路线(N)」统一提交。
- **多选联动**（新建采购行内条款同款）：勾选了多行时，直接改**其中一行**的
  路线下拉，一次写到全部勾选中「路线可设置」的行；事实不允许该路线的行跳过。
  触达多行就提示（改了几个 / 跳过几个）；改未勾选的行只写自己并自动勾上。
- **确认路线只提交可开工行**：提交范围 = 勾选中 ∩ 有路线决定 ∩
  （READY/DISPATCHED 可开工可领料，或 WAITING 且可齐套提升——确认齐套即补跑
  提升转 READY）。**纯等料的 WAITING 行不随批提交**：草稿保留、下拉继续可改
  （按钮计数不含它们，点按钮给「保留草稿、到货后再确认」的说明）——到货卡
  会按路线提示下一步。
- **路线记忆（V602）**：未确认工单的下拉预填**同产品最近一次确认的开工路线**
  （服务端 workshopTasks 投影尾列 `suggestedStartRoute`，按 `route_confirmed_at`
  倒序取最新；V602 建部分索引点查）。记忆不在当前收窄选项里（工单事实已变，
  如持续生产失去直送资格）回落默认齐套。确认/改选即刷新记忆，无需回写。
- **下拉样式**：`UtenDropdownField` dense 形态收窄内边距与同行文本格等高；
  弹层宽度与字段同宽（120~480 夹紧）——物料分析等表格内下拉同步受益。

## 2026-09-17 确认生产路线：先定路线，再卡流程(V599 / ADR-091)

用户口径：「应该先让车间的人先确定路线，只有把路线确定了先，才好去卡流程、解锁啥的」
「待领料那里的下一步改成路线确认」「物料分批到的，给对应的车间弹窗——某某物料到了 100 个，
还差什么物料，或者物料已支持开工，去领料开工啥的」。

- **三选一**：等待物料的工单「下一步」首条 = **「确认生产路线」**——齐套生产(默认，等全部子件
  到齐一次领料) / 分批生产(ADR-078，按可齐套上限拆批) / 持续生产(ADR-089，同车间直送到一批投一批)。
  选项按工单事实收窄：零料段只有齐套可选(弹窗只有一个选项时不再弹、直接确认)；持续生产需要有
  可由本车间直送供给的子件。已确认的工单在未领料/未报工时可「重新确认生产路线」，动过即冻结；
  详情弹窗常显「生产路线」一行。
- **服务端同口径门控**：未确认路线时 开工/批量开工/领料申请/分批提交/持续生产开工/重新核对备料
  全部 409「请先确认生产路线」；已确认「分批生产」的工单不再出现齐套链入口，反之亦然。
- **系统不替车间选路**：到货驱动的齐套自动提升被 `fn_execution_route_allows_auto_promote` 抑制
  (未确认/BATCH/未开工的 CONTINUOUS)；确认齐套路线那一刻若已可齐套，同事务补跑提升——行为与
  旧的「到货即提升」对齐。**下达时即齐套的段不受影响**(CompleteKitAllocator 在下达事务内直接
  建 READY 段)。这同时关闭了 V595 的竞态：仓库料先到齐不再把持续生产工单顶成 READY。
- **到货进展弹窗**：IQC 确认入库(含先入库后质检的自动转正)与非线边仓产成品入库这两类
  「真实写进库存」事件，按「仓×货品×颜色」命中仍在等待的工单，发**聚合卡**：「本次入库 N 件 +
  仍缺清单(名称 编号(颜色) 还缺 X 单位，封顶 6 行) + 按路线的下一步提示」；与既有车间行动卡
  同聚合 `(PRODUCTION_EXECUTION_SEGMENT, 段)`——一张工单同时最多一张活跃卡，开工/领料/分批/
  确认路线即办结。收货审核、红冲、IQC 拒收不触发(可用量没有真实增加)。
- 分批谱系落生即定路线：批次段 = 齐套(每一批就是一次小齐套，开工/领料不受新门影响)、
  剩余段继承分批。
- 权限零新增：确认路线与开工同门槛(`production_execution:view + start`)。

## 2026-09-16 部分开工 · 持续生产(V595 / ADR-089)

等待物料的工单若至少一个子件由**本车间直送**供给(同车间有在产该子件的工单，或已有直送指向它)，
**且每一种可直送的子件都已经送到了一部分**(2026-09-17 用户口径：「持续开工的前提是已经有一部分的
料，子层级每一种料都有一部分了，至少能开始生产了」)，且尚未领料/分批/预留，「下一步」列与行菜单、
详情弹窗多一个入口**「部分开工 · 持续生产」**(`canStartContinuous`；与「分批领料」并列，用户二选一)：

- 确认后同一张工单只开一次工：直送子件到一批就自动投一批，工单一直开着，直到最后一次报工按实际完工结账；
- 仓库供给的物料照旧一次领齐：全部子件都直送 → 一键即「持续生产中 · 可报工」；有仓库料 → 停在
  「物料齐套 · 去领料」，领齐后再点开工；仓库料缺时开不了工，提示直接列出缺什么；
- 状态列生产中显示「持续生产中 · 可报工」；报工量以已到直送料按单耗折算为上限；
- **一件料都没到不许开工**：入口本身不出现(`fn_can_start_continuous_supply` 同口径)，
  强行调接口会被拒并列出「哪些子件一件都还没到」。空料架开工等于零物料在产，
  接着还会去领仓库的料——该加没加、该不算的算进去，正是要堵死的那类账乱。

**只剩线边仓直送料没出库的工单**(`pendingLineSideOnly`，系统对账把父件提升齐套时留下的线边仓草稿)
不再显示「去领料」，直接按「物料齐套 · 可开工」呈现——点开工时就地自动出库，仓库不会收到替车间发线边仓料的任务。

## 2026-09-16 分批遇车间直送：线边仓自动投入(ADR-087 §六)

同车间直送(报工「转下一道工序」)到料的工单，走「分批领料」切批时**不再对线边仓
物料提交领料申请**：

- 线边仓(直送)明细行在核对页标「车间直送 · 自动投入」徽标；提交事务内自动审核
  并出库，不等仓库。
- 本批全部来自直送时按钮为「确认本批生产」(与沿用前批物料同口径)，成功提示
  「直送物料已自动投入，无需领料，可直接开工」——本批立即可开工。
- 混合批(直送子件 + 仓库子件)只有落在仓库的那部分进入领料申请/仓库待领；
  直送部分已自动投入，不再出现在领料汇总里。
- 全量直送且全部子件齐套的工单不点分批也自动解锁：报工直送审核同事务完成
  齐套提升与线边仓出库，徽章直接变「物料齐套 · 可开工」。

用户口径三条规则对应关系：子件还缺→等待物料(不变)；同车间直送全齐→可开工
不领料(直送自动链)；子件只到一部分→分批先产够的那部分，直送部分自动投入。
服务端资格按需求谱系匹配(分批子段挂 `split_root_demand_id`)，细则见
[ADR-087](../99-决策记录-ADR/ADR-087-车间内部直送与线边仓.md) §六。

## 2026-09-12 分批生产与实际用料退仓

适用的等待物料工单在“下一步”列提供“分批领料”：只读核对当前完整可生产量，选择本次数量并审阅材料汇总，确认后建立本批及余批谱系，只向仓库提交本批任务。剩余数量仍为待生产，可在后续到料后继续分批；历史原段显示“已拆分为生产批次”。已有领料/报工或正式供给绑定的任务不通用拆改，人工暂缓不能绕过解除动作。细则见 [ADR-078](../99-决策记录-ADR/ADR-078-完整子批生产与实际用料余料退仓.md)。

“分批生产领料”核对页采用产品/计划/工单信息卡、四项数量卡、本批数量填写区和实际仓领料明细表。任务待生产、当前可齐套上限、本批已核对量、安排后剩余分别展示；本批已核对量、输入值、明细领料数量及确认按钮以红色突出，可齐套上限使用绿色。剩余量是留待后续安排的产品数量，不是物料缺口；用户主动少安排时也不能一律称为等待到料。

修改本次数量后，旧核对量和明细保留但标明需要重新核对，确认入口暂不可用；非法数量和超出当前齐套上限在框内提示。明细只列接口提供的本批新增领料数量、单位和实际仓，不合计不同物料单位，也不虚构已领/缺口列。沿用前批实际已领物料时仍显示无需再次领料并使用“确认本批生产”。桌面保持右下红色大按钮，手机使用独立底部操作区，避免遮挡明细工具条；手机明细优先展示物料名称及带单位的本批数量，编码、实际仓等可横向查看。原同幂等键重试、权限和开工门禁保持不变。

实际用料的表格、台账、登记记录及冲销补齐单位。每次新登记独立幂等意图，允许两次同数量的合法分批耗用。登记成功仍有余额时提示留待后续生产或核对退仓；留用不造耗用账，退仓需明确填写并提交原领料来源。申请待仓库收料时冻结该部分额度，可在仓库确认前撤回；实收才记退料与恢复库存。

沿用前批已领物料的续批仍有用料入口：先选择有真实证明且有权限的原领料任务，再在原需求上登记。仍需留给后批的共享材料不可提前退仓；新余料申请只处理已开工任务，未开工领错料走仓库取消出库。全部余额已提交退仓后显示“待仓库收退料 / 查看退料进度”。

## 2026-09-12 车间手动提交领料

现行顺序以 [ADR-077](../99-决策记录-ADR/ADR-077-车间明确提交领料后进入仓库任务.md) 为准：齐套 → 车间勾选任务 → 右下“批量领料” → 独立领料汇总页核对并点击“领料” → 仓库任务出现 → 实际发完 → 车间开工。进入汇总页、刷新和返回不提交任务。

齐套待领料状态改为青绿色，与等待物料的琥珀色区分，可直接点击状态查看本工单汇总，也可勾选批量操作。已提交显示“已提交领料 · 待仓库发料”，领齐才可勾选开工。状态表头增加四类筛选，并由服务端在分页前处理。批量选择中领料与开工分别计数，只处理各自符合条件的工单。汇总页按实际仓库、物料、颜色、单位合并，展开来源可核对工单数量；同一批次只能属于同一车间。

双击工单详情也提供“去领料”入口。汇总表前的复选框选择本次物料，逐行填写本次应领数量；只提交所选数量，未选或未申请余量继续保留。数量变化按真实DRAW行分摊并重新核对，仓库只能发已申请未发量。该操作不缩小工单；要把原1000件中的10件先生产，应进入上节“分批领料”建立完整子批，而不是少申请后直接开工。数量合同见[V564](../数据迁移/160-V564逐行分批领料申请数量.md)。

接口为 `/production/workshop-tasks/draw-request/preview|submit`；仍用车间查看与开工权限及对象范围。下文旧版“自动进入仓库待领”“齐套未领料锁住”描述仅为历史记录，以本节及ADR-077/078为准。当前为源码候选，仓库后续动作见[生产领料任务中心](生产领料任务中心页.md)，迁移与运行环境状态以独立验收记录为准。

## 2026-09-12 报完后的下一步

生产中保留全部尚未完成的执行段，但不再统一显示“可报工”。可报量为零后，状态按真实待检、待点收入库和用料登记事实显示下一步；已足额入库但尚有已领未登记量时显示“已入库 · 待登记实际用料”。用料按钮放在状态旁的“下一步”列，避免员工必须横向滚到表尾或打开右键菜单寻找。无需再次报工的行使用说明图标，不再造成“任务被锁”的误解。

领料/开工仍归等待物料阶段。报工量、品质通过量、正式入库量与实际物料耗用是不同事实，不能因为成品已入库就自动补造耗用。执行段只有足额有效入库且原物料需求结清后才能转 COMPLETED。

日报明细来源单行显示执行工单号；来源读侧返回真实计划 UUID，有计划查看权限时按计划 UUID 和执行段 UUID 跳到聚焦详情。重新选来源与清除来源是独立操作。普通新报工隐藏“完结”勾选，历史 isFinal 字段和服务端不足封顶/品质恢复规则保留。

## 一、什么时候应出现车间任务

“创建自制子件”只建立 `MAKE_COMPONENT` 或 `SUBCONTRACT_MAKE` 备料任务，不自动创建正式车间执行段。创建成功后仍须核对数量、车间和负责人，提交生产计划并由有权人员审核；无审核权限时只生成草稿待审。

车间任务登录弹窗卡片的办结点是**开工**（ADR-063 2026-09-10 修订 §3）：车间负责人登录后按本人范围收到「物料已领齐·可以开工 / 等待物料」卡片（normal 优先级也弹），进入本页对应分类；点开工成功即按执行段撤回全体收件人的弹卡（`resolveProductionWorkshopTasks`，reason=STARTED）；完工入库（段 COMPLETED）由完工投递兜底办结（reason=COMPLETED）；**报工本身不办结**。卡片不另计徽章（后端接线由并行批次完成，本页只消费既有分类与计数）。

已审核且有合法安排的 WAITING 执行段应出现在对应车间，不要求先齐套。车间看到“备料中”，物料齐套后才产生完整预留和 DRAW；全部真实发料后才允许报工。不能为了让任务可见自动猜负责人、替员工批准计划，或绕过仓库发料门禁。

物料分析的车间详情在创建子件后提示“已创建备料子任务，尚未下达车间”。新子件优先进入首个100行可见窗口并保持选择，其它行的手填数量/车间/负责人草稿保留；较大分析不能把刚创建的任务放到尚未加载的窗口之后。页面已保存的组织安排继续优先，默认车间和负责人只作可核对预填。

## 三、列表与徽章

### 材料使用确认（2026-09-07）

任务行提供“确认用料”（无结清权限时为“查看用料”），右键菜单也可打开“物料使用情况”。直接进入既有材料台账，携带本工单 `executionSegmentId`，不要求车间员工先取得计划制单人的查看范围。页面只展示服务端筛选后的本段需求与结清来源记录。

实际提交需要 `production_material:settle`，冲销需要 `production_material:reverse`。普通车间员工只能办理主职、兼职、本人负责或管理车间范围的执行段；接口逐需求检查归属，跨计划、混合其他车间的批次整体拒绝，幂等重放也重新校验当前归属。管理范围遵守 ADR-050：计划 owner、正式交接的可写 owner、超管，或显式 `production_plan:view:all` 的全量范围，均须与对应清料动作权限求交。手工 `user_data_scopes` 共享只扩大读，不能与动作组合取得管理写权。

材料台账加载 `capabilities` 只读接口，分别下发 `canSettle/canReverse/canClose`，页面再与本地动作权限求交；因此原计划详情中的只读全量用户也不会看到假可用的提交、冲销和关闭按钮。未知或缺失能力默认false；每次真正POST仍独立鉴权，不信任先前的能力快照。

“未结清全部填入实耗”只给空白实耗格填建议，保留已填写的实耗、损耗和在制。建议量扣除本次已填写损耗/在制后标黄，框内图标说明需核对实际用量；仍须点击“提交本次材料结清”才产生事实。不能把损耗、余料或在制静默当实耗。

任务入口不显示全计划结案，也不跳转未按执行段过滤的全计划退料选择器。计划详情原管理入口继续承担整单材料台账及结案；整单结案要求管理写范围、足额成品实收和材料数量守恒同时成立。足额入库但未确认实耗/退料/损耗/在制时，执行段保持生产中，不能用简化操作绕过清账。

终态不挂徽章）。车间筛选在表格

## 四、2026-09-05 查询语法修复

现场日志只读确认了 `SQLState: 42601`、`syntax error at or near "BY"` 和 `TRUEORDER BY`。这是查询字符串连接缺分隔符导致的数据库语法错误，不是“车间没有任务”，不得用返回空列表掩盖。

`ProductionExecutionWorkbenchService` 的修复范围：

1. 执行段筛选与 ORDER BY 之间明确换行，防止 `task.reportable = TRUEORDER BY`。
2. 关联单据派生表与排序之间明确换行，防止同类 `candidateORDER BY`；派生表显式命名 route/document_type/document_id/document_no/status，不能依赖第一个UNION分支的偶然列名。
3. 根任务对象范围加括号及分隔后再接过滤AND，保持范围谓词与附加条件的组合语义。

后二项来自同类源码审查，不冒充现场日志已出现的报错。修复只改查询组装，无数据库结构或迁移变化，也不改变员工范围、状态或权限。

新增 `ProductionExecutionWorkbenchQueryPostgresTest` 在一次性PostgreSQL中通过真实Hibernate执行5项查询；排序/安全/关联文档旧契约另7项通过，0失败/错误/跳过。这5项采用查询投影fixtures，不等于完整Flyway视图升级测试。现场server进程尚未重启，没有取得使用修复版本后列表/徽章成功回读证据；本地源码和测试通过不等于已部署。
