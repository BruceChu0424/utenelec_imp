## 1. 问题与用户口径

### 1.1 现在为什么做不到 (代码事实)

1. **材料事实都挂在工单需求上。** 领料明细的 `demand_id`、`reservation_id` 都是 NOT NULL (`M/V152:36-38`); 单条需求超预留或超领料被数据库拒绝 (`M/V249:482-503`)。一次领一整批、多张工单共用, 在按单链路里做不出来。
2. **注塑件没有颗粒 BOM, 是零物料 DIRECT_MAKE, 被 V710 材料发现门拦住。** 插入时打标 (`M/V710:70-78`), 开工拦截 (`M/V710:94-107`), 服务端 `J/features/production/execution/ProductionExecutionSegmentService.java:787-795` 同样拦。结果是每张工单都要先领料才能开工。
3. **开工只能显式操作。** 报工只收生产中的段, 文案"请先在我的车间任务中开工" (`J/features/production/dailyreport/DailyReportExecutionSegmentGuard.java:297`); 自动开工已由 `M/V491__workbench_report_requires_explicit_start.sql:1-10` 下线。
4. **线边仓 (本 ADR 起叫内料仓) 只认车间直送。**
   - 普通调拨和其它出库不能从线边仓出 (`J/features/stock/StockDocService.java:955-960`); 调入仓必须是普通记账叶仓 (`:963-967`), 普通选仓函数排除线边仓 (`M/V613__operational_warehouse_leaf_identity.sql:14-31`)。
   - 线边仓里的料只算给直送指名的那条需求 (最新定义 `M/V615__workshop_direct_source_allocation.sql:717-723`), 所以天然退出公共可用量。
   - 线边仓上没有直送或生产领退料来源的流水, 提交时被延迟触发器拒绝 (视图 `M/V615:105-121`, `M/V619__workshop_material_normal_warehouse_custody.sql:1150-1156` 追加两类例外; 触发器 `M/V615:152-162`)。
5. **普通出库受可动用量约束:** 余额 − 有效预留 − 货品安全库存 (`J/features/stock/StockService.java:252-283`, `J/features/stock/StockBalanceRepository.java:51-78`)。已有"只扣预留"的查询 (`StockBalanceRepository.java:122-135`), 只给已分配的生产领料用。
6. **成本侧。** 盘亏价值进 LOSS (`J/features/stock/valuation/StockValuationCoordinator.java:64-74`); 生产成本对象的投入只从物料清账过账发现 (`J/features/stock/valuation/ProductionInventoryValueService.java:230-241`), 成本对象未建立时刷新直接返回 (`:228`); 刷新来源守卫只认产出、清账、完工报工和实产追加 (最新全文 `M/V525__subcontract_normal_and_excess_loss_value.sql:244`, 之后 `M/V562:82`、`M/V695:74`、`M/V701:250` 锚点追加)。
7. **期初导入不产生实物流水** (`J/features/stock/valuation/InventoryOpeningService.java:19`)。
8. **附件8 靠成品入库称重近似** (`J/features/finance/cost/FinanceCostService.java:32-35, 259-379`)。用户已确认成品入库不称重, 这个口径失效。
9. **没有机台和料桶主档** (老库 `B_Machine` 0 行, 新库无表)。
10. **老库做法** (调研 report-master-data §4-§7): 仓库按公斤整批发颗粒, 不挂工单; 水口料作为独立货品退仓; 7 年只有 6 行颗粒盘点; 有颗粒 BOM 的注塑件 0 个; "PC E-15" 被 759 个件用到。

### 1.3 同行做法与出处

标【官方】为厂商帮助文档, 【实施】为实施顾问文章。实现前逐条复核一次原文。

1. **金蝶云星空"调拨领料"**: 先把料整批调到车间仓, 只换位置不算耗用; 化工行业按桶调到车间仓, 余料调回。出处: [倒冲领料介绍](https://blog.csdn.net/xswl1/article/details/143208393)【实施】、[生产单据类型参数](https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%94%9F%E4%BA%A7%E5%8D%95%E6%8D%AE%E7%B1%BB%E5%9E%8B%E5%8F%82%E6%95%B0)【官方】。本 ADR 的"调拨进内料仓"照此设计。
2. **金蝶"倒冲差异分摊"**: 定期盘点产线, 实盘与账面的差异按期间内各生产订单用量比例摊回。出处: [倒冲差异分摊](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E5%80%92%E5%86%B2%E5%B7%AE%E5%BC%82%E5%88%86%E6%91%8A)【官方】。本 ADR 的"按理论比例摊回工单"照此设计。
3. **用友 U8 现场仓盘点**: 订单分到的盈亏 = 盘点盈亏 × 订单期间用量 ÷ 全部订单期间用量; 盘盈使订单已领量小于 0 时改记其它入库。出处: [U8 库存盘点及调整](https://www.szyonsuite.com/article-detail/166.html)【实施】。本 ADR 的"实盘比账上多时产品分 0" (§5.8) 照此设计。
4. **SAP**: 散装料 (Bulk) 直接记成本中心会让主料的产品成本失真 ([KBA 3577470](https://userapps.support.sap.com/sap/support/knowledge/en/3577470)【官方】); "冻结账面库存"在盘点开始时记下账面 ([Freezing the Book Inventory Balance](https://help.sap.com/docs/SAP_ERP/96bf9ad642cf4b26a29595e3d573fb8c/4561bd534f22b44ce10000000a174cb4.html)【官方】)。本 ADR 的"开始盘点即截止"照此设计。
5. **Dynamics 365 / Oracle EBS**: 精益倒冲按"期间 × 生产流"算差异 ([Backflush costing](https://learn.microsoft.com/en-us/dynamics365/supply-chain/cost-management/backflush-costing)【官方】); Bulk 供应类型不需要交易 ([WIP Supply Types](https://docs.oracle.com/cd/E18727-01/doc.121/e13678/T228107T228127.htm)【官方】)。
6. **定额耗用量比例法与以存计耗**: 共耗材料按定额比例分配、最后一个倒挤尾差 ([正保](https://www.chinaacc.com/new/201007/05su2994244780.shtml)); 以存计耗的缺点是损耗藏进耗用 ([MBA 智库](https://wiki.mbalib.com/wiki/%E5%AE%9E%E5%9C%B0%E7%9B%98%E5%AD%98%E5%88%B6))。本 ADR 用"其它耗用单列 + 浪费率标红"把损耗亮出来。

## 2. 决定摘要

**一句话**: 颗粒用调拨整批发进本车间内料仓, 只换位置、不算耗用。车间照常报工。什么时候需要就盘点: 开始盘点即定截止日, 提交时按"截至本期的账面 − 实盘"当场过出本期实际用量; 系统随即自动结算, 按"报工量 × BOM 单个重量"的理论比例把价值分进各工单成本。守恒、分摊合计、截止锁定都由数据库断言兜底; 只有三种会让数据算错的情况才拦结算, 并自动通知该补的人, 补完自动结算。

| 谁 | 做什么 | 多久一次 |
|---|---|---|
| 仓库 | 车间来人时直接发料 (选车间、料、袋数, 公斤自动算, 选领料人, 一次确认); 有申请时一键按申请发; 收退回 | 随时 |
| 车间 | 新产品第一次开工时认一次料 (多数只需点确认; 嵌件件多勾一个"还要按工单领别的料"); 照常报工; 可选: 申请领料、退回、登记试模清机用料、换料 | 随时 |
| 有盘点权限的人 | 开始盘点 → 手机逐台点满/半/空、数袋 → 提交 | 需要时 |
| BOM 维护人 | 在 BOM 里填颗粒行和单个重量 (克); 收到"缺单重"通知时补 | 随时 |
| 系统 | 提交盘点后立即自动结算; 被拦时通知责任人并每 10 分钟重试; 报表标红异常 | 自动 |

## 3. 判定口径

### 3.1 可配置属性 (不写死车间名)

| 属性 | 放在哪 | 含义 | 谁维护 |
|---|---|---|---|
| 发料方式 | `goods.issue_method`: `ORDER` 按工单领料 / `PERIODIC` 整批领到车间内料仓 | **唯一判定来源**。`PERIODIC` 的料不能再有新的按单需求、永远不能是直送的货品 (切换前留下的按单需求必须已核清, §3.4) | 基础资料 |
| 分摊方式 | `goods.periodic_cost_basis`: `OWN` 主料 / `SHARED` 辅料 / `EXPENSE` 记车间费用 | `PERIODIC` 必填, `ORDER` 必空。与发料方式同一道切换门 (§4.1) | 基础资料 |
| 每袋净重 | `goods.bulk_package_qty` | 盘点和发料"袋数 × 每袋"的默认值; 切换发料方式时默认取货品已有的"订货倍数 / 整包装量" (`goods.order_multiple_qty`, `M/V575__goods_order_policy.sql`) | 基础资料 |
| 回收料 | `goods.is_recycled_material` | 水口料、破碎料; 其它入库预填金额 0 | 基础资料 |
| 车间整批领料 | `workshop_material_settings` (每车间一行): 是否开启、指定内料仓、启用日 | 开启的车间 = "整批领料 + 盘点计耗"车间 | 有 `workshop_material:setup` 的人 |
| 机台与容器 | `workshop_machines`、`workshop_machine_containers` | 盘点卡片的来源 | 同上 |

`PERIODIC` 的料基本单位必须是质量单位 (`unit_measurement_profiles.measurement_dimension='MASS'`, 表见 `M/V442__measurement_capture_learning.sql:22-37`)。界面的"克"换算只对名称为千克/公斤/kg 的单位显示, 其它质量单位按原单位显示, 存值一律是基本单位。

### 3.2 期间边

- **定义**: BOM 行的组件是 `PERIODIC` 货品, 这一行就是期间边。不给 `goods_bom_items` 加列, 由组件的发料方式判定。
- **形状** (数据库触发器强制): `control_stage='START'`、`consumption_basis='PER_UNIT'`、`basis_output_qty=1`、`hard_gate=FALSE`、`qty>0`。组件分摊方式为 SHARED 或 EXPENSE 的 BOM 行一律拒绝, 提示"色母这类辅料不写进 BOM, 按当期主料用量分到各产品"。
- `hard_gate=FALSE` 是纵深防御: 全库 `hard_gate` 的含义是"按单齐套门槛" (`M/V247__bom_control_stage_and_packaging_measurement.sql:12-18, 34-35`), 漏网读者也会把期间边当非门槛跳过。"这是必需的主料"由组件发料方式表达。
- 同一父件同一组件只有一行 (`M/V79__goods_bom_items.sql:44-46`), 所以一个产品对一种颗粒只有一个单个重量。

### 3.3 什么时候冻结什么

| 冻结点 | 冻结什么 | 为什么 |
|---|---|---|
| 下达 (生成执行分段) | 按单需求 (只为非期间的生产硬门槛边建); 零料原因; 执行指纹对期间边只计"用哪种料" (只含 BOM、PERIODIC、组件、颜色、单位五段), **不计单个重量、BOM 行 id、BOM 行更新时间** | 期间边增删会改零料原因, 要让排产预览过期; 改单重不影响任何需求, 也不能让拆批报"BOM 已变化" (现指纹含 BOM 行 id 与 `b.updated_at`, `J/features/production/mrp/ProductionExecutionPlanningService.java:243-261, 392-406`; 比对在 `ProductionExecutionBatchService.java:180`, 只对按单需求的段比) |
| 开工 (变为生产中) | 本段绑定的内料仓; 本段的期间料行 (来自当时 BOM 的期间边、产品认料或源段); 生效起始日 = max(启用日, 已结算截止日 + 1), **不用开工那一刻的日期** (报工按表头日期归期, 夜班可能先报后点开工); BOM 单重快照 (只在 BOM 行以后被删时兜底) | 车间归属此前已在派工时冻结 (`M/V155__production_execution_segments.sql:221-236`) |
| 结算 | 每行报工用的单重、分摊比例、金额 | **单重只有一条规则**: 取结算时产品 BOM 上该料期间边的单个重量; 没有这一边取段快照; 再没有就是缺单重, 拦结算。每条理论明细记下所用单重和来源。撤销后重结按当时 BOM 重算, 这是有意的 |

### 3.4 下达时的判定

| 产品 BOM | 需求 | 零料原因 |
|---|---|---|
| 有非期间的生产硬门槛边, 也有期间边 | 只为非期间硬门槛边建 | 无 (DEMANDED) |
| 只有非期间硬门槛边 | 照旧 | 照旧 |
| 有期间边, 没有非期间硬门槛边 (可以另有包装边或参考边) | 无 | 新增 `PERIODIC_MATERIAL` |
| 没有任何边 | 无 | `DIRECT_MAKE` (V710 打标, 照旧) |
| 只有非期间的非硬门槛边、发货包装边、参考边 | 无 | `NO_PRODUCTION_HARD_GATE`, 照旧 |

**双账防护**: 发料方式只在货品上; 数据库另有两条全局守卫: `PERIODIC` 货品不能成为任何新的按单需求的货品, 也不能成为直送行的货品。货品改为 `PERIODIC` 的前提是这种料没有**未核清**的按单需求 (§5.1); "未核清"只有一个定义 `fn_material_demand_uncleared` (§4.7): 未删除、状态不是 `RELEASED`/`REVERSED`, 且 (状态不是 `FULFILLED`, 或 已发 − 已退 ≠ 已清账实耗 + 核定损耗, 或 仍有合法在制, 或 有待退料), 逐需求发退清账口径与 `M/V711:230-267` 相同 (`FULFILLED` 就是"料已备齐或已发出", `M/V150__production_material_fulfillment_ledger.sql:97-100`)。万一某段仍带未核清的整批领料货品按单需求, 该段状态为 `ORDER_ONLY`、不建期间料行 (§5.4), 所以同一种颗粒不可能在同一段里既按单清账又进期间理论。

### 3.5 "有没有 BOM"的两个口径

| 函数 | 含义 | 读者 |

| `fn_goods_has_bom(goods)` | 有任何有效边 (含期间边) | 编排是否确认展开 (`J/features/production/mrp/MrpService.java:98-104`); 执行分段零料原因 |
| `fn_goods_has_order_bom(goods)` | 只数非期间边 | 物料分析、MRP、委外、足迹 (§6 第 14-18 条); 零料证据守卫的 `DIRECT_MAKE` 分支 (§4.2) |

### 3.6 内料仓: 线边仓改名复用, 规则按货品分流

- **名字**: 线边仓面向用户一律叫"{车间名}内料仓" (界面、多语言文案、服务端提示、通知、页面文档)。内部列名 `warehouses.is_line_side`、函数名、类名不改 (牵动 31 个 Java 文件与 16 个迁移, 得不偿失)。自动配置 (`J/features/master/warehouse/LineSideWarehouseService.java:43-106`) 生成的仓名改为"{车间名}内料仓"; 名字已被占用时 (同车间在别的主仓下已有一个, 或别的仓恰好同名) 追加" ({主仓名})" (现有 `uniqueName` 的口径, `:124-131`, 括号改半角加空格)。V740 按同一规则改现有自动配置行: 每个车间按建立先后第一个且名字未被占用的叫"{车间名}内料仓", 其余追加" ({主仓名})", 即只给重名的加。
- **指定的那一个**: 每个开启整批领料的车间在 `workshop_material_settings.periodic_bin_warehouse_id` 指定一个内料仓 (没有就用现有自动配置入口在所选主仓下建出)。一个车间只有一个按盘点计耗的内料仓, 一张盘点单盘完。
- **公共可用量不用改**: 内料仓本来就退出公共可用量 (`M/V615:717-723`), 颗粒在里面没有任何直送指名的需求, 天然不会被别人预留。
- **规则按货品分流** (两类货品天然不相交: `PERIODIC` 是采购原料, 直送货品是自制子件):

| 内料仓里的货品 | 允许的动作 | 入口 |
|---|---|---|
| `PERIODIC` | 调入/调回 (TRANSFER)、其它耗用 (OTHER_OUT)、盘点过账 (新流水 21/22 型) | 只能经内料仓服务, 每笔带数据库核验的来源引用 |
| 非 `PERIODIC` | 现有直送规则一行不改 | 原直送与生产领退料链路 |

- 通用"仓库调拨 / 其它出库 / 其它入库"页面照旧选不到内料仓。`StockDocService` 对线边仓 TRANSFER/OTHER_OUT/WASTE/FINISHED_OUT 的拒绝保持, 只对"`PERIODIC` 货品且单据由内料仓服务登记"的放行。
- 数据库守卫: 内料仓流水视图与"每条流水恰好一行来源"断言只对 `PERIODIC` 货品生效; 线边仓来源异常视图 (`M/V615:105-121`) 豁免内料仓流水视图里的流水。

## 4. 数据模型 (全部在 V740)

通用约定: 全部表带 `created_at/created_by`; 可改的表带 `row_version`; 所有写命令的幂等由一张命令账本 `workshop_material_commands` (`created_by + idempotency_key` 唯一、`request_hash`、`target_id`、`result`) 承担, 命令行在业务写完后于同一事务最后插入一次, 只插不改; **业务表不带命令 id 列** (业务清空时保留的表不能引用被清空的表, `server/ops/reset_business_data.sql:1668-1677`); 金额只由 V500 价值核心写入; 业务日期一律存 DATE 列 (取自 BusinessTime), 不从流水时间戳截取; 内料仓的每笔进出另存所属期间 `period_id` (§4.3)。DDL 细节见实现规格。

### 4.1 配置

- **goods 新增** `issue_method` (默认 `ORDER`)、`periodic_cost_basis`、`bulk_package_qty`、`is_recycled_material`。触发器: `PERIODIC` 必须是质量单位; 发料方式**和分摊方式**都只能经基础资料的切换服务改 (会话标记 + 提交时延迟断言), 前置条件见 §5.1。分摊方式的断言: 改成辅料或记车间费用时, 这种料不得有未删除的 BOM 期间边、有效的 MATERIAL 认料、在生产中段上仍有效的期间料行; 任何改动都要求这种料在所有内料仓账面为 0 且没有未结算期间的期间行或流水 (结算按期间行上的分摊方式快照, 期中改了会让结算反复失败)。
- **workshop_material_settings** (主键 `workshop_department_id`): `periodic_enabled`、`periodic_bin_warehouse_id` (必须是本车间、未删除的内料仓, 开启时必填, 部分唯一)、`go_live_date`、`enabled_by/at`、`disabled_by/at`、`row_version`。内料仓和启用日在有流水后不可改。**停用只用来撤销设错的开启** (第一期): 本仓从未有过流水、从未有段绑定过本仓、没有待办领料单; 停用时删掉那张空的第 1 期, 之后可以像第一次一样重新开启。已经在用的车间不支持停用后再开启 (期间链只需管一段连续的开启)。
- **workshop_machines** (机台挂车间): `code`、`name`、`model`、`tonnage` (选填)、`enabled`、`sort_order`、`remark`、`is_deleted`; `(workshop_department_id, code)` 未删除唯一。
- **workshop_machine_containers**: `machine_id`、`name` (干燥机料斗、储料桶)、`capacity_qty` (千克, 大于 0)、`enabled`、`sort_order`、`is_deleted`; `(machine_id, name)` 未删除唯一; 被盘点行引用后只能停用不能删 (ADR-111)。
- **goods_bom_items**: 不加列; 期间边形状触发器见 §3.2。

### 4.2 执行、认料与换料

- **production_execution_periodic_materials** (段的期间料行, 开工时建, 建即绑定): `execution_segment_id`、`bin_warehouse_id`、`material_goods_id/color_id/unit_id`、`origin` (`BOM` / `CHOICE` / `CHANGE` / `INHERITED`) 及各自来源 id、`design_qty_snapshot` (只有 BOM 行有)、`effective_from` (BOM / CHOICE / INHERITED 行 = max(启用日, 已结算截止日 + 1); CHANGE 行 = 换料选定的起始日)、`effective_to` (换料时写一次)。除 `effective_to` 写一次外不可改; 同段同料有效区间不重叠; 段生产中或完工时必须有行 (对需要的段); 段上有未核清的整批领料货品按单需求时不许建行 (§3.4)。
- **goods_periodic_material_choices** (认料, 产品级): `kind` (`MATERIAL` 用内料仓里的某种料 / `NONE` 本产品不用内料仓的料, 按工单领料)、料与颜色、`also_order_materials` (只对 MATERIAL: "还要按工单领别的料", 例如嵌件; 默认否)、`chosen_by/at`、`chosen_workshop_department_id`、`prefill_source` (`LEGACY_MATERIAL_TEXT` 或空)、`superseded_at/by/reason` (`BOM_TAKEOVER` / `CHANGED` / `ISSUE_METHOD_SWITCH`)。有效选择唯一; MATERIAL 的料必须是 `PERIODIC` 且 `OWN`; NONE 与 MATERIAL 不能同时有效; 同一产品的有效 MATERIAL 行 `also_order_materials` 必须一致, 且只允许没有任何 BOM 的产品勾选 (有按单 BOM 的产品按 BOM 领)。**BOM 接管**: 产品第一次有了期间边, 同一事务里其全部有效认料作废, 以后开工一律按 BOM; 例外: 有效认料勾了"还要按工单领别的料"而产品还没有任何按单边时拒绝新增期间边, 提示"这个产品开工时选了'还要按工单领别的料', 请先在 BOM 里填上这些料 (例如嵌件), 再填塑料单个重量", 防止以后开工不再要求领嵌件。
- **production_execution_material_changes** (段级换料): `from_row_id` (空表示加一种料, 例如双料件)、新料、`effective_from`、`weight_basis` (`FROM_REPLACED` 沿用原料单重, 默认 / `OWN_BOM` 按新料 BOM 单重)、`reason`。同一事务给原行写 `effective_to = effective_from − 1` 并新增 `CHANGE` 行。
- **production_execution_segments**: 零料原因 CHECK 加 `PERIODIC_MATERIAL` (格式同 `NO_PRODUCTION_HARD_GATE`, `M/V249__execution_segment_material_requirement_shape.sql:8-51`); 零料证据守卫 (最新全文 `M/V426__strengthen_direct_make_analysis_lineage.sql:17-121`, 之后 `M/V479:8-16`、`M/V701:209-225`、`M/V710:109-130` 锚点修改) 只在 V426 正文里做两处锚点替换, 不在函数开头加任何早退 (V701/V710 的早退顺序不变, 非颗粒规则一行不变): (1) `DIRECT_MAKE` 分支的"产品没有任何 BOM 行"改为"产品没有按单 BOM" (`NOT fn_goods_has_order_bom`), 所以补填颗粒单重后, 原 `DIRECT_MAKE` 段拆批、追加照常通过; (2) 在 `NO_PRODUCTION_HARD_GATE` 分支后追加一支 `PERIODIC_MATERIAL`: 有期间边且没有非期间的生产硬门槛边。`NO_PRODUCTION_HARD_GATE` 本身不改 (期间边 `hard_gate=FALSE`, 不破坏它的证据; 新下达用哪个原因由下达服务决定)。

### 4.3 内料仓进出

- **workshop_material_requisitions** (领料单 / 退回单): `request_no` (领料 ZL、退回 ZT, 经 V279 全局编号永久占号: 取号触发器按 `kind` 分命名空间、只挂 BEFORE INSERT, 另挂一条改号拦截触发器, 写法同 `M/V674:219-220` 的库存单据与 `M/V734` 的 LQ 领料申请; 单号形状 `Z[LT]` + 14 位数字)、`kind` (`ISSUE`/`RETURN`)、`origin` (`WORKSHOP_REQUEST` / `WAREHOUSE_DIRECT`)、`bin_warehouse_id`、`workshop_department_id`、`receiver_employee_id` (直接发料必填)、`status` (`PENDING` → `DONE` 或 `CANCELLED`)、`done_by/at`、`remark`。
- **workshop_material_requisition_lines**: 料、颜色、单位、`requested_qty > 0`、`requested_bags`、`suggested_leaf_warehouse_id` (预填货品归属仓)、`fulfilled_qty` (投影, 断言等于调拨关联之和)。

- **workshop_material_other_issues** (其它耗用): 料、`qty`、`reason` (`TRIAL_MOULD` 试模 / `PURGE` 清机 / `SCRAP_MATERIAL` 报废料 / `OTHER` 须填说明)、`period_id`、`business_date`、`stock_document_item_id`、`movement_id` (唯一)。
- **workshop_material_count_postings** (盘点过账): `period_line_id`、`count_id`、`movement_id` (唯一)、`kind` (`CONSUME` 21 型出 / `CONSUME_REVERSE` 21 型原路入 / `GAIN` 22 型入 / `GAIN_REVERSE` 22 型原路出)、`reverses_posting_id` (两种冲回必填)、`qty`、`business_date` (= 期末日)、`reason` (`SUBMIT` / `CORRECTION` / `SUPPLEMENT`)。

### 4.4 期间与盘点

- **workshop_material_periods** (按内料仓): `period_no`、`start_date`、`end_date`、`status` (`OPEN` → `COUNTING` → `COUNTED` → `CLOSED`)、`counting_started_by/at`、自动结算状态 `close_state` (`NONE`/`QUEUED`/`BLOCKED`/`HELD`/`FAILED`)、`close_blockers` (JSON, 差什么、谁来补)、`close_attempted_at`、`close_attempts`、`close_failures` (连续失败次数)、`held_until`、`row_version`。第 1 期 `start_date = go_live_date`, 之后每期 `start_date = 上一期 end_date + 1`; `end_date` 非空当且仅当不是 OPEN; 状态沿期间链只能不升, 恰好一个 OPEN 且是最后一期 (不引入 btree_gist, 用逐期衔接断言; 因为不支持停用后再开启, 断言不处理断开的期间链)。**不设盘点周期**: 期间 = 相邻两次盘点之间。
- **workshop_material_counts**: `period_id`、`version`、`status` (`DRAFT`/`SUBMITTED`/`SUPERSEDED`)、`submitted_by/at`、`correction_reason`; 同一期最多一个 DRAFT 或 SUBMITTED。
- **workshop_material_count_lines** (逐行保存, 行级 `row_version`, 两人可同时录): `line_kind` 只有三种 (`FULL_BAGS` 整袋 / `CONTAINER` 机台容器 / `WEIGHED` 过秤公斤数, 开口袋、搅好未上机、散料或明确为 0 都是它; 界面照旧分组显示, 分组说明存 `weigh_note`)、料、`bag_count`、`bag_net_qty`、`weighed_qty`、`machine_id`、`container_id`、`capacity_qty_snapshot`、`fill_level` (`FULL`/`HALF`/`EMPTY`/`WEIGHED`); `qty_base` 生成列 (整袋 = 袋数 × 每袋; 容器 = 容量 × 1、0.5、0 或过秤数; 过秤 = 过秤数)。提交时断言: 本车间启用机台的每个启用容器都有一行; 截至本期账面不为 0 或本期有流水的每种料至少一行 (0 也要明确填)。
- **workshop_material_period_lines** (提交盘点时建, 更正或已盘点补录时改): `cost_basis` (提交时的分摊方式快照, 结算只认它)、`opening_qty`、`transfer_in_qty`、`return_qty`、`other_issue_qty`、`closing_qty`, 生成列 `actual_qty = 期初 + 领入 − 退回 − 其它耗用 − 期末`; 延迟断言: 期初 = 上一期期末 (第 1 期为 0); 领入/退回/其它耗用 = 流水视图中属于本期的合计; 盘点过账两条净额: 净 21 型 (`CONSUME − CONSUME_REVERSE`) = max(`actual_qty`, 0), 净 22 型 (`GAIN − GAIN_REVERSE`) = max(−`actual_qty`, 0); 截至本期的账面 = 期末。

### 4.5 结算结果 (按"次"存, 只追加)

- **workshop_material_period_closes**: `close_no`、`status` (`ACTIVE`/`REVERSED`)、`trigger_kind` (`AFTER_COUNT` / `SCHEDULED` / `MANUAL`)、`closed_by/at`、`reversal_event_id`、`reversed_by/at`、`reverse_reason` (手动重试、撤销的幂等由命令账本承担)。一期最多一次有效结算 (部分唯一)。
- **workshop_material_close_materials**: 每期每种料的 `cost_basis` (= 期间行快照)、`theory_qty` (只 OWN 有)、`allocation_basis_qty` (只 SHARED 有)、`outcome` (`ALLOCATED` / `UNALLOCATED_LOSS` / `GAIN` / `NOTHING` / `EXPENSED`)、`consumed_qty`、`loss_qty`、`waste_rate`、`flags` (`WASTE_OUT_OF_RANGE` / `OTHER_ISSUE_LARGE` / `ACTUAL_WITHOUT_THEORY` / `GAIN_PRICE_ZERO`)、`value_at_close`。
- **workshop_material_close_theory_lines** (可追到每行报工): 报工行、日期、段、成本范围、产品、期间料行、`output_qty_base`、`unit_weight`、`weight_source` (`BOM_AT_CLOSE` / `SEGMENT_SNAPSHOT` / `REPLACED_ROW_BOM`)、`theory_qty = round(产量 × 单重, 6)`; 覆盖断言两条: 本期每一条合格的已审报工行, 在它的每一条有效期间料行下都有理论明细; 反过来, 绑定本仓的段上表头日期落在本期的每一条已审报工行, 都落在该段某条期间料行的有效区间里 (§3.3 的起始日规则与 §5.6 的截止锁让它结构上成立, 断言兜底, 不另设拦截项)。
- **workshop_material_close_allocations**: 每 (料, 成本范围) 一行 `basis_qty`、`allocated_qty`、`is_tail`、`value_node_id`、`reversed_at`; 断言: 未反向行合计 = `consumed_qty`, `consumed_qty > 0` 时恰好一行承担尾差; 结算提交时, 在制名下属于该期间行的剩余数量为 0 (全部移到成本在制或 LOSS, 不留滞在制)。

### 4.6 流水类型、估价与成本投入

- **新增流水类型** 21 = 内料仓盘点耗用 (出; 更正时原路入)、22 = 内料仓盘盈 (入; 更正时原路出), `source_doc_type='WORKSHOP_MATERIAL_COUNT'`。不借 5 型: STOCK_DOC 的 5、6 型必须挂生产发料事件 (`M/V514__production_material_exact_movement_links.sql:86`)。台账标签、库存报表、附件8 同步登记。
- **估价** (`StockValuationCoordinator`): 21 出 → 在制 (`Destination.WIP`, 去向 = 期间料行), EXPENSE 料 → `EXTERNAL`; 21 入 → 原路退回原 21 流水的价值区间; 22 入 → 已知成本入库, 价格依次取内料仓池当时已知均价、最近一次调入该料的单价、再没有按 0 核定并在报表标红, 不留"成本未定"; 22 原路出 (更正时冲回盘盈) → 出到 `EXTERNAL` (与盘盈入库同一对手方), 按出库时池均价 (V500 平均池对普通入库没有"按原值撤回"的接口, `ReverseStore` 只适用于经 `store` 建立的入库, `J/application/port/InventoryPositionPort.java:37-39`; 盘盈价本就是核定价, 差异在报表可见)。调拨与其它出库沿用现有估价 (调出进在途, 调入按原出库成本恢复, `StockValuationCoordinator.java:97-105`; 其它出库进 EXTERNAL, `:71`)。
- **可动用量**: 新增来源引用 `InventoryMovementCostReference.WorkshopMaterialBin`, 由数据库函数核验来源单据确实是本事务里内料仓服务登记的。核验通过时: 内料仓作为出库方 (21 型出、22 型原路出、退回调出、其它耗用) 只守非负底线 (`StockService.java:227-240`); 仓库叶仓调入内料仓的调出一侧只扣有效预留、不扣安全库存 (复用 `StockBalanceRepository.java:122-135`)。没有这个引用的出库照旧守可动用量。
- **成本投入种类**: `stock_value_production_cost_inputs.input_kind` 加 `PERIODIC_MATERIAL` (原 CHECK 在 `M/V517__inventory_value_custody_positions.sql:222`), `InventoryProductionCostPort.InputKind` 同步加 (`J/application/port/InventoryProductionCostPort.java:18`); 仿 `M/V525:143-158` 加延迟触发器: 投入节点来自分摊事件、`approved_posting_id` = 分摊行、分摊行未反向且成本范围一致。
- **投入发现只有一个口径**: 新视图 `v_production_cost_input_candidates` = 清账过账投入 (现有 `ProductionInventoryValueService.java:230-241` 口径) 并上期间分摊投入; `refresh()` 与待刷新重算 (`:295-305`) 只读这个视图。成本对象不存在时仍直接返回, 由成品入库登记产出时一并发现 (`StockValuationCoordinator.java:123-127`)。
- **刷新来源守卫**: 锚点 `OR EXISTS(SELECT 1 FROM production_daily_reports report` (写法同 `M/V701:250-260`) 前追加一类合法来源: 结算批次或其撤销事件 (对本范围有分摊行、操作人一致)。报工审核不需要新来源: 产出入库本来就会刷新成本对象 (`StockValuationCoordinator.java:123-127`), 完整性门在那时重算。
- **成本完整性门** (`ProductionInventoryValueService.java:248-266`) 追加两条"不完整": (i) 成本范围里有绑定内料仓的段, 其已审报工日期晚于该仓已结算截止日; (ii) 有属于本范围、来源为期间分摊、尚未登记为投入的切片。所以结算前注塑件成本保持暂估, 不会"显示完整却缺塑料"。

## 5. 流程

### 5.1 上线 (一次性, 顺序固定)

0. **清旧账** (在标料之前): 在产注塑单已按工单领出、还没用掉的颗粒, 走现有退料流程退回叶仓并清账 (让这些按单需求"核清", §3.4); 车间手上从来没入过账的余料, 用现有"其它入库"按核定价入普通叶仓。**不用期初导入**: 期初导入只给已有数量开价值、不产生实物流水 (`J/features/stock/valuation/InventoryOpeningService.java:19`), 既增加不了叶仓数量, 又会与已发料重复。
1. **标料** (基础资料): 颗粒改为"整批领到车间内料仓"并选"主料", 色母选"辅料", 填每袋净重 (默认取货品已有的整包装量), 水口料标"回收料"。可以勾选多种料一次改。
   - 改为整批领料时服务端先列出、确认后同一事务处理: 先改货品, 再把用到这种料的 BOM 行改成期间边形状; 按包或按批计量的行必须先改, 否则拒绝。前提: 这种料没有未核清的按单需求 (含 `FULFILLED` 但已发未清账的, §3.4), 预览里逐条列出是哪张工单、差多少没清。改回按工单领的前提: 各内料仓里这种料账面为 0、没有未结算期间的期间行或流水、未结算期间里没有这种料的理论用量、没有生产中段上仍有效的期间料行、没有有效认料。
   - BOM 学习: 本 ADR 不改 V711。按 V711 现行规则, 转换 BOM 行形状 (以及以后新增、修改、删除期间边) 会把这些父件的学习改为人工所有 (`M/V711__production_bom_learning.sql:54-80`), 学习停用后也就不会去改期间边的单个重量; 期间边是否例外 (让父件的嵌件、包材继续学习) 由 ADR-129 会话决定 (§11)。
2. **填 BOM / 上线准备页** (内料仓设置里): 列出近 12 个月在该车间做过或归属车间为该车间的产品; 列: 产品 | 老库材质 | 预填颗粒 (材质文本与料名唯一命中) | 单个重量 (克) | 参考: 货品资料单重 | 状态。一键"勾选行用货品资料单重填入" (货品资料 `m_weight` 按质量单位换算成克), 再逐个核对标黄项; 勾选多行后改任一行即批量生效; 一次保存 = 批量写 BOM 期间边, 只知道料不知道单重的写认料。顶部进度"常做的 312 个产品, 已选料 300 个, 已填单重 280 个"。单个重量填**件重 (不含水口)**; 冷流道且水口不回掺的件可加每件水口重。小于 0.1 克或大于 5000 克二次确认; 与货品资料单重差 20% 以上标黄。
3. **开启车间整批领料** (内料仓设置): 选车间、主仓 (在该主仓下用现有自动配置入口取得或建出"{车间名}内料仓")、启用日。一个原子命令: 写设置、建第 1 期; 本车间正在生产的段中, 产品已有期间边或 MATERIAL 认料的当场绑定 (生效起始日 = 启用日); 还没认料的产品在同一对话框里一次选完 (MATERIAL 或 NONE), 所以开启后不存在"在产却没认料"的段。段上仍有未核清的整批领料货品按单需求的, 不绑定, 按工单做完为止 (`ORDER_ONLY`, §5.4)。
4. **机台**: 批量新增 (台数 21、编号前缀、每台容器: 干燥机料斗 50 公斤、储料桶 100 公斤), 个别机台单独改、停用、增删; 勾选多行后改一格即批量生效。
5. **空仓启用**: 内料仓开启时颗粒余额必须为 0; 启用日当天仓库把车间要用的料"直接发料到内料仓" (第 0 步退回和其它入库的料也经这一步进内料仓)。不新增估价通道。

### 5.2 发料 (仓库直接发料为主路径)

- **直接发料**: 仓库任务中心 → 车间内料仓 → 直接发料: 选车间、料、袋数 (公斤按每袋净重自动算, 可改)、领料人 (车间员工选择器, 默认该车间上一次的领料人), 出库叶仓默认货品归属仓; 一次确认。同一事务: 建"已完成"领料单、按叶仓逐张建并审核 TRANSFER (叶仓 → 内料仓)、写调拨关联。库存不足、版本冲突整笔回滚, 保留输入。
- **按申请发** (可选): 车间在内料仓页"申请领料"只列整批领料的料, 填公斤或袋数, 同时显示"仓库还有 X 公斤""内料仓估计还剩 Y 公斤"; 提交只生成申请。申请预填出库叶仓 = 货品归属仓, 按 ADR-115 只通知该仓仓管。仓库打开申请一键按申请发 (默认量可按整袋改)。
- **归期与业务日期**: 业务日期一律记真实日期; 所属期间由系统在确认那一刻定: 记进开着的那一期。内料仓正在盘点时, 发的料自动算下一期, 页面提示"已开始盘点, 这批料算到下一期"。
- **漏录补录**: 盘点开始前实际已发、当时忘了录的料, 可以勾选"这批料是上一期漏录的"补录到那一期 (填原因), 只能补到"盘点中"或"已盘点、还没结算"的那一期: 盘点中补录随提交一起算; 已盘点后补录, 服务端同一事务自动更正该期 (领入 + 补录量, 期末实盘不变, 实际用量随之增加并按 §5.7 第 4 条的规则追加过账), 然后立即尝试结算。那一期的盘点里没盘到这种料的, 先"更正盘点"补上实盘数再补录。已结算的期间不能补录。
- **为什么用 TRANSFER**: 这一步只换位置、不算耗用 (同行共识); 估价现成, 内料仓均价就是真实调入成本; 不碰生产发料链 (`M/V152:36-38`); 台账和报表天然认识调拨; "领料"的语义由领料单和数据库守卫保住。

### 5.3 退回、其它耗用、水口料

- **退回** (可选): 车间提交退回 (料、公斤), 提示"只退没拆袋、没掺色母的料"; 仓库按实收确认, 生成 TRANSFER (内料仓 → 指定叶仓), 记进开着的那一期, 不能退到已截止的上期。
- **其它耗用** (可选): 车间登记试模、清机、报废料、其它的公斤数和原因, 当场生成内料仓的 OTHER_OUT, 价值去 EXTERNAL, 不摊给产品, 报表单列。单笔超过设定公斤数或本期合计超过实际用量 5% 的在报表标红。不登记的话差额体现在浪费率里, 数据仍守恒。
- **水口料**: 第一期不进内料仓, 回掺不记。交回仓库走现有"其它入库": 回收料预填金额 0, 显式核定零成本 (留空会变成成本未知, `StockValuationCoordinator.java:119-123`)。卖出走现有出库单据。

### 5.4 开工与认料

服务端给出状态, 界面只按它分支。任务台 DTO 新增 `binMaterialState` (由 `fn_segment_bin_material_state` 给出) 和 `needsStartConfirmation`:

| 状态 | 条件 (按顺序判定) | 界面 | 开工门 |
|---|---|---|---|
| `KNOWN` | 段已有期间料行 | 正常 | 放行 |
| `ORDER_ONLY` | 段上有未核清的整批领料货品按单需求 (上线前按工单领过, 做完为止, §3.4) | 按单领料流程 | 走原按单门和 V710 门 |
| `NO_BIN` | 车间没开启整批领料, 产品也没有期间边 | 原样 | 原样 |
| `NEED_BIN` | 产品有期间边, 但车间没开启整批领料 | 红字 | 拒绝: "「{产品}」用的「{料名}」要从车间内料仓领, 但「{车间}」还没有开启整批领料。请找仓库开启, 或改派到已开启的车间" |
| `KNOWN` | 车间已开启; 产品有期间边, 或源段有有效期间料行, 或有 MATERIAL 认料 | 正常 | 放行; 认料没勾"还要按工单领别的料"时同时解除 V710 领料发现门, 勾了则领料发现门照旧 (只能登记非整批领料的料) |
| `ORDER_ONLY` | 车间已开启; 产品认料为"按工单领料" | 按单领料流程 | 走原按单门和 V710 门 |
| `NEED_CHOICE` | 车间已开启; 以上都不是 | "等待物料"分类, 状态"待认料", 行可勾选开工 | 拒绝 (开工确认表里认完即放行) |

- **开工就绪与开工确认表的衔接**: 开工就绪统一定义 (`fn_execution_start_material_ready`, 工作台 `canStart` 的来源, `J/features/production/execution/ProductionExecutionSegmentService.java:963-970`、`ProductionExecutionWorkbenchService.java:1007`) 只再排除 `NEED_BIN`, **不排除** `NEED_CHOICE`: 真正拦待认料开工的是服务端开工门和数据库开工触发器。另给 `needsStartConfirmation` = 通用开工前提 (状态待开工、计划有效、包已确认、车间与负责人已定) 且状态不是 `NEED_BIN` 且 (状态为 `NEED_CHOICE` 或路线未确认)。客户端现在只让 `canStart` 且路线为齐套或持续到料的行进入开工 (`L/features/production/pages/production_workshop_tasks_page.dart:864-870`), 改为 `needsStartConfirmation` 的行也放行, 进入开工确认表分支。
- **开工确认表** (合并 ADR-093/096 路线确认): 车间在"车间生产任务"勾选任务点"开工", 其中有 `needsStartConfirmation` 的行时弹一张表, 按产品一行: 产品 | 本次任务数 | 用料 (老库材质唯一命中预填) | 还要按工单领别的料 (例如嵌件) (勾选框, 默认不勾, 只对没有任何 BOM 的产品出现) | 路线 (按路线记忆预填) | 单个重量 (只读, 未填显示"待补, 不影响开工")。底部「确认并开工 (N)」与「这几个产品按工单领料 (暂不开工)」。勾了"还要按工单领别的料"的产品写认料后不开工, 转到现有领料申请 (ADR-119) 去领嵌件等按单料, 领料登记完再开工。
- 「确认并开工」依次: 一个原子请求写全部认料 → 对未确认路线的段逐个确认路线 (现有接口) → 按计划批量开工 (现有接口, `L/features/production/pages/production_workshop_tasks_page.dart:1436-1470`)。三步各自幂等, 中途失败留下的认料和路线都是有效事实, 重试不重复。
- 用料选"本产品不用车间内料仓的料"的行写 NONE 认料: 产品有按单 BOM 的照常一起开工 (走原按单领料门); 没有 BOM 的由「按工单领料 (暂不开工)」转到现有领料申请 (ADR-119), V710 材料发现门照常要求真实领料, 保证"材料不明确不等于不需要材料"。
- "用料"下拉只列本车间内料仓收的主料, 可多选 (双料件); 另有"本产品不用车间内料仓的料 (按工单领料)", 选项文案列出本内料仓收的全部料名。嵌件注塑件 (颗粒 + 嵌件, 没有 BOM) 选颗粒并勾"还要按工单领别的料": 颗粒走期间理论, 嵌件走按单领料并被 BOM 学习学到, 两边都不漏 (以后给该产品填颗粒单重时学习的去留按 V711 现行规则, 见 §11)。
- 开工触发器 (变为生产中时) 绑定内料仓并建期间料行 (状态为 `ORDER_ONLY` 的段不建): 源段 (拆批或追加的源) 有有效期间料行时复制为 `INHERITED`; 否则按当时 BOM 的期间边建 `BOM` 行 (带单重快照); 否则按 MATERIAL 认料建 `CHOICE` 行。起始日按 §3.3。同一产品下次开工自动带出。
- 服务端开工门 (`ProductionExecutionSegmentService.java:787-795`) 与数据库开工就绪函数读同一个状态函数, 前后自动一致。
- **改认料** (`workshop_material:choose`): 作废旧认料另选新料, 对以后开工的段生效; 已开工段要改的, 同一对话框选"从哪天起改用", 按 §5.5 逐段写换料; 已结算的期间不变。
- **BOM 接管**: 给产品新增第二条期间边时弹窗"这个产品要同时用两种料吗 (双色 / 双料)? 如果只是换料, 请改原来那一行"。

### 5.5 换料 (段级, 少用)

车间生产任务行菜单"这张工单改用别的料": 选新料和起始日, 可选"加一种料"。需要 `workshop_material:choose`; 起始日要晚于内料仓已结算的截止日。不登记的话, 原料和新料的差额分别体现为浪费和"有实际没理论"(记损失、报表标红), 数据仍守恒。

### 5.6 报工 (截止守卫)

- 报工页面不变; 报工"不良数"由 ADR-129 §2.13 加 (§11)。
- **截止守卫**: 段绑定了某内料仓, 报工日期落在该仓已结算期间的, 新建、审核、红冲一律拒绝 (只看段绑定的仓, 不看期间料行的有效区间, 早于起始日的补报工同样被锁)。新建时提示"这个日期所在的一期车间内料仓已经结算, 报工日期请填 {下一期起始日} 或以后"; 审核或红冲时提示"{起止日} 的车间内料仓已经结算, 不能再改这期的报工。需要改的话请找有撤销结算权限的人 ({姓名}) 撤销后再改"。
- 截止日及以前的报工在结算前仍可以新建、审核、红冲: 它们是盘点前已经发生的生产事实。截止日以后的报工照常进入下一期。夜班跨零点按日报表头业务日期归期 (现行口径), 不新增班次字段。

### 5.7 盘点 (开着 → 盘点中 → 已盘点 → 已结算)

1. **开始盘点** (`workshop_material:count`, 在实物清点开始那一刻按): 截止日默认今天, 一键可选"昨天" (交班时盘点)。当场写本期 `end_date`, 本期变"盘点中", 下一期同时开出。之后内料仓的领入、退回、其它耗用记进下一期 (按期间归属, §4.3)。与 SAP 冻结账面同理: 截止点对齐实物清点时刻。页面提示"想要按月对账, 请在月底盘一次", 不强制。
2. **录入** (逐行保存, 两人可同时录; 每行点完即落库, 断网只影响正在录的那一行, 不另做本机草稿): 手机优先, 每台机一张卡片"3 号机 | 在用料 (默认上次) | 干燥机料斗 [满|半|空] | 储料桶 [满|半|空]", 写明档位"超过四分之三算满, 四分之一到四分之三算半, 不到四分之一算空"; "本机停机、全空"一键; 用量很小的料可改"直接填公斤"。袋料每种料一行"整袋 __ 袋 × 每袋 __ 公斤", 开口袋可加多行过秤数; 搅好未上机的选主料、填公斤。"其余料都用完了, 记 0": 列出有账或有进出但还没填的料, 一次确认。"打印空白盘点表" (`L/components/print/uten_print_preview.dart` 的 `UtenPrintPreviewButton`)。估算: 21 台 × 2 下 ≈ 42 下, 袋料约 20 下, 8-10 分钟。
3. **提交盘点** (同步, 1-3 秒): 断言覆盖, 建或更新期间料行; 当场按净额过账: 实际用量 A > 0 写 21 型出库, A < 0 写 22 型盘盈入库; 状态改"已盘点", 截至本期账面 = 实盘; 同时排队自动结算 (§5.8)。21 型金额 = 提交那一刻内料仓池均价。
4. **更正盘点** (少用): 只在"已盘点"时 (含撤销结算之后)、且下一期还没提交盘点; 出新版本盘点单、写原因, 可以补上漏盘的料。**过账规则对称** (已盘点后补录也用同一规则): 新 A ≥ 0 时先把本期间行的 22 型全部原路冲回, 再把 21 型调到正好 A (多了追加 21 型, 少了原路冲回 21 型); 新 A < 0 时先把 21 型全部原路冲回, 再把 22 型调到正好 −A。所以任何时候净 21 型 = max(A, 0)、净 22 型 = max(−A, 0), 在制里挂在该期间行名下的价值正好等于结算要分的量, 不会有一部分永远留在在制 (例: 先盘成 A = −5 过了 5 公斤盘盈, 更正成 A = +10 时, 先冲回 5 公斤盘盈, 再出 10 公斤, 而不是出 15 公斤)。
5. **撤回盘点** (少用): 只在"盘点中"、且下一期没有任何流水和盘点单时; 删除自动开出的下一期, 本期回到"开着"。

### 5.8 自动结算

- **触发**: 提交盘点、更正盘点、已盘点后补录成功后立即在后台尝试结算 (提交后投递, 页面轮询进度, 避开 Flutter Web 无 body 写请求的 15 秒上限, ADR-089:125); 报工审核时若本单涉及的期间正被"未审报工"拦着, 审核提交后也立即尝试一次 (报工截止守卫本来就预读这些期间, 不加语句); 另有登记在 `ScheduledTaskCatalog` 的定时任务每 10 分钟重试所有"已盘点未结算"的期间 (补单重后由它接上); 有盘点权限的人可点"立即重试"。期间必须按顺序结算, 上一期未结算时本期显示"等上一期结算"。
- **失败退避**: 结算因程序或数据错误失败 (不是三种拦截) 连续 3 次后, 定时任务改为每天重试一次, 并通知持 `workshop_material:setup` 的人"车间内料仓结算连续失败, 请联系系统管理员", 页面显示最近一次失败原因的业务文案。
- **只有三种情况拦结算** (不拦会算错), 拦住时自动给责任人发通知, 内料仓页顶部显示"差什么、谁来补", 补完后自动结算:

| 情况 | 为什么会算错 | 通知谁 |
|---|---|---|
| (a) 截止日及以前、绑定该内料仓的段上还有未审报工 | 理论会漏掉这部分产量, 份额被别的产品吃掉 | 这些报工的审核人 (有 `production_daily_report:approve` 且能审这张单的人) 与报工制单人 (审核人删不了别人的草稿) |
| (b) 有产量但没填单重的产品 | 这个件的份额会被同料其它产品吃掉 | BOM 维护人 (有 `goods:bom:edit` 的人) |
| (c) 某种料有理论用量, 但本期期初 + 领入 = 0 (料从没进过内料仓) | 理论会从空池里"用掉", 通常是认错料或漏录发料 | 仓库发料人 (内料仓所在仓的仓管, ADR-115) 与本车间有认料权限的人; 通知写明两条出路: 仓库在"直接发料"里勾"这批料是上一期漏录的"补录, 或车间核对是不是认错了料 (改认料或换料后自动重算) |

- **其它异常不拦**, 系统按规则自动处理并在报表标红:

| 分摊方式 | 情况 | 处理 (outcome) | consumed / loss |
|---|---|---|---|
| 主料 | A > 0, T > 0 | `ALLOCATED` | consumed = A |
| 主料 | A > 0, T = 0 (有实际没理论) | `UNALLOCATED_LOSS`, 标红 | loss = A |
| 主料或辅料 | A < 0 (实盘比账上多) | `GAIN`, 产品分 0 | 都为 0 (盘盈已在盘点时过账) |
| 主料或辅料 | A = 0 | `NOTHING` | 都为 0 |
| 辅料 | A > 0, 本期主料理论 > 0 | `ALLOCATED`, 按主料理论比例 | consumed = A |
| 辅料 | A > 0, 本期主料理论 = 0 | `UNALLOCATED_LOSS`, 标红 | loss = A |
| 记车间费用 | 任何 | `EXPENSED` (盘点时已进 EXTERNAL) | 都为 0 |

  浪费率 (只算主料, = (实际 − 理论) / 理论) 超出 [-30%, +50%]、其它耗用超限, 都只在报表标红。
- **事务内容** (后台任务, 单事务): 期间行 FOR UPDATE, 复核状态、上一期、拦截项、`row_version` → 调理论函数写理论明细 → 定处理方式 → 按成本范围 (`fn_production_execution_cost_scope`) 汇总理论, `allocated = MoneyPolicy.quantityShare(consumed, T_s, T)` (数量 4 位, `J/common/finance/MoneyPolicy.java:201`; 不在业务包里自己写四舍五入, 金额口径锁边测试扫描 `features/warehouse`), 理论最大的一行 (并列取 id 最小) 承担尾差 (= consumed − 其余之和) → 一次锁定库存键 (本期全部料 + 所涉产品 + 这些成本范围清账会用到的料, `InventoryMutationLock.lockAll`) → 每行分摊按 V500 精确区间从在制 (期间料行) 移到成本在制 (成本范围), loss 移到 LOSS, 不产生实物流水 → 按成本范围 id 排序逐个 `refresh()` (刷新范围 = 本期所有有理论明细的成本范围) → 写结果, 期间改"已结算"。提交时延迟断言兜底: 分摊合计 = consumed; 理论覆盖 (两个方向, §4.5); 在制名下该期间行不留余量; 投入来源合法; 有成本对象的分摊都已登记为投入。结算只认期间行上的分摊方式快照。
- **操作人**: 自动结算记提交盘点的人, 定时重试记同一人, "立即重试"记点的人; `trigger_kind` 区分。

### 5.9 撤销结算 (只能撤最近一期)

- **权限**: `workshop_material:reopen`, 只能逐人授予; 需要 ADR-110 再认证; 必须填原因。
- **条件**: 该内料仓最近一个已结算的期间, 下一期仍是"开着"或"盘点中"。
- **一个事务, 只撤成本、不动数量**: 每行分摊用 `ReturnConsumed` 从成本在制退回在制 (`J/application/port/InventoryPositionPort.java:28-30`, 与清账反向同一手法 `ProductionInventoryValueService.java:196-205`); LOSS 移回在制; 按成本范围刷新; 本次结算标为已撤销; 期间回到"已盘点", 自动结算状态 `HELD`, `held_until = 撤销时刻 + 24 小时`。
- 之后可以更正盘点、补审或红冲报工、改单重; 改完点"重新结算", 或 24 小时后定时任务自动重结, 写新的一次结算结果。

### 5.10 报表 (U12)

1. **内料仓用量表** (每期 × 每种料): 期初、领入、退回、其它耗用、期末、实际、理论、差额、浪费率 (只算主料)、处理方式与标红原因; 金额和单价需 `goods:cost:view`; 辅料只给每期总用量 (U9)。
2. **产品用料表** (每期 × 产品 × 料): 完工、单重、理论、分摊实际、材料金额、单件材料成本 (= 金额 / 完工), 可展开到工单和每行报工。**独占期** (本期这种料只有这一个产品用) 标"真实单耗", 给出"实际 / 完工"并与单重对比; 其它行标"按理论比例分摊"。ADR-129 §2.13 上线后加"不良"列与"实际 / (完工 + 不良)"。
3. **浪费率趋势**: 按料、按期折线, 横轴是期间起止日。
4. **缺单重清单**: 跨期常驻, 可一键跳到 BOM。
5. **内料仓收发明细**: 流水视图, 带业务日期、来源单据、操作人。
6. **附件8**: 列名列序保留, 数据源换成结果表 (§7.5)。

报表按对象范围过滤: 车间成员只看本车间内料仓。金额读价值节点现值, 同时保留"结算时金额"。

## 7. 成本

### 7.1 期间分摊怎么进产品成本

分摊目标是**现有 PRODUCTION_EXECUTION 成本对象** (按成本根归集, 拆批和追加归同一个根), 只加投入种类 `PERIODIC_MATERIAL`, 不另立成本范围。手法同委外损耗: 原材料切片先移到成本在制, 再以投入身份修订成本对象, 来源由延迟触发器锁死。结算前注塑件成本对象保持暂估、不完整; 结算后转为完整。

### 7.2 已出库、已售、已被上级领用的产品

沿用 V500 后补传播 (`docs/数据迁移/116-V500实际平均库存价值核心.md`): 在库件增加库存价值; 已售进销售成本; 已被装配工单领用的沿价值边进上级工单; 空池价值保持 0。当前没有库存成本期间和总账过账, 会计月报前应先让当月内料仓盘点并结算: 这是操作顺序要求, 不是系统闸。

### 7.3 色母

分摊方式选"辅料" (SHARED): 期间实际用量按本期各工单全部主料理论重量的比例分进产品成本。理由: 色母是真实材料成本, 记费用会让产品成本偏低 (SAP Bulk 被批评的问题)。代价: 本色件也会分到少量色母成本。"记车间费用" (EXPENSE) 作为货品配置保留, 不改代码。容器里的色母随主料计, 期初期末口径相同, 误差大部分抵消。

### 7.4 水口料、盘盈与损失

- 水口料交回仓库按核定 0 成本入账, 卖出收入全额入账, 不冲减当期材料成本 (塑料成本已全额进产品, 再估价会算两次)。回掺不记账会让浪费率偏小, 报表加说明。第二期再考虑按参考价作副产品冲减。
- A < 0: 盘点时以 22 型按 §4.6 核定价格入库, 产品本期这种料分 0; 上期多承担的部分不追溯, 误差与容器档位同量级。
- `UNALLOCATED_LOSS`: 价值进 LOSS, 不摊给产品, 报表标红。

## 10. 性能与并发

- **报工审核不变慢**: 只加一步不加锁预读 (本单涉及的内料仓期间, 带索引) 和一步对这些期间行 FOR SHARE (复核未结算); 不算理论、不写内料仓表; 期间边不进足迹, 审核不锁颗粒库存键。用 ADR-089 常驻语句剖面用例锁住"语句增量不超过 3 条, 且不锁整批领料货品的库存维度"。
- **索引**: `production_daily_reports(bill_date) WHERE NOT is_deleted`; `production_execution_periodic_materials(bin_warehouse_id, execution_segment_id)`; 三张来源表 `(bin, goods, color, business_date)`; 每个新外键带领头索引 (`SchemaIndexHygieneContractTest`)。热表触发器按 ADR-106 拆 INSERT 与 `_upd` 列级 WHEN。
- **提交盘点**: 同步, 每种料 1-2 条流水, 30 种料以内不超过 3 秒。**结算**: 后台单事务, 验收基准 200 张工单 × 3 种料 10 秒内。
- **锁序** (全局一致、无环; 报工路径锁期间行而不是内料仓行, 下一期报工不被本期结算挡住):
  - 报工保存、审核、红冲: 幂等顾问锁 → 预读涉及的期间 → 按 id 排序对期间行 FOR SHARE → 原有足迹与库存键 (`J/features/production/dailyreport/ProductionDailyReportService.java:356-376` 的顺序只在最前面加一步) → 锁日报行, 复核期间集合没变。
  - 发料、退回、其它耗用: 领料单行 → 设置行 FOR SHARE (定归期: 记进开着的那一期; 开始盘点要拿设置行 FOR UPDATE, 所以两者不会交错) → 库存键一次 `lockAll`。
  - 开始盘点、撤回盘点: 设置行 FOR UPDATE → 当前期间行 FOR UPDATE。
  - 提交、更正盘点、补录 (补到盘点中或已盘点的那一期): 设置行 FOR UPDATE → 期间行 FOR UPDATE → 本仓各料库存键 `lockAll`。
  - 结算、撤销结算: 期间行 FOR UPDATE (后台任务用 SKIP LOCKED 防重跑) → 库存键一次 `lockAll` → 成本对象按成本范围 id 排序。不锁日报行, 只检查未审。
  - 开工、认料、换料: 段行 (按 id 排序) → 产品认料顾问锁 → 设置行 FOR SHARE → 期间料行。
- **幂等**: 所有命令带幂等键, 先按 (操作人, 幂等键) 取事务级顾问锁再查命令账本; 同键不同内容拒绝, 重放返回原结果; 命令行在业务写完后于同一事务最后插入。

  1. ADR-129 §2.13 加列 `production_daily_report_items.defect_qty` 后, CREATE OR REPLACE `fn_report_item_material_output_qty(p_report_item_id uuid) RETURNS numeric`, 改为"良品基本量 + 不良基本量" (FQC 补产的处置规则不变)。签名和其它对象都不用动: 期间理论、报表、附件8"安装挑选不良"列同时生效; 学习会话若让学习分母也读它, 所有车间的学习同时生效。
  2. **计划用量是否按不良率放大由 ADR-129 §2.13 决定。** 提醒: 学习分母含不良后, 学到的单耗变为"每做一件 (含做坏的) 用多少料" (与本 ADR 的单个重量同一口径); 若计划侧不放大, 物料分析、MRP、下达的计划用料会按不良率偏少。可参考的放大口径: 计划用量 = 计划良品数 × 单耗 ÷ (1 − 学到的不良率), 不良率 = Σ不良 ÷ Σ(良品 + 不良), 按同一批学习样本累计; 不良数上线前不良为 0, 数值不变。
  3. 不良数不进 fqty、入库、FQC、超产、直送分流; 良品为 0 的纯不良行是否开放由 ADR-129 §2.13 决定, 本 ADR 的理论函数两种情况都能算。
- 主线程已把用户原话转达给 BOM 学习会话并获对方接手; 另须把本节"期间边与 V711 学习的现行交互"与上面 ADR-129 §2.13 第 1、2 条原文发给 ADR-129 会话 (以 SendMessage 原文为准)。

## 12. 分期

**第一期** (做全才算根治):
1. 配置: 货品四个属性与切换服务; 车间开启整批领料 (内料仓指定、启用日、在产段认料); 机台与容器; 上线准备页; 线边仓改名。

5. 盘点: 开始、录入、漏录补录 (盘点中或已盘点未结算)、提交过账、更正 (对称冲回)、撤回; 手机卡片与打印。
6. 自动结算: 理论函数、三种拦截与通知、定时重试、分摊、价值移动、投入发现视图、完整性门、刷新守卫、撤销结算。
7. 物料分析、MRP、委外、有 BOM 判定、履约足迹: 期间边过滤。
8. 报表: 四张报表、收发明细、附件8 换源、内料仓页估计还剩。
9. BOM 学习: 本 ADR 不改 V711 (由 ADR-129 会话实现不良数进学习); 只提供报工耗料产量唯一函数 `fn_report_item_material_output_qty` 作为共用钩子 (§11)。
10. 收尾: 权限、菜单、文档、上线第 0 步清旧账的使用说明、真实 PostgreSQL 全链测试。

**第二期**: 独占期真实单耗在 BOM 页只读展示; 水口料按参考价作副产品冲减; 颗粒补货提醒 (仓库可用 + 各内料仓估计还剩低于补货点); 报工加啤数、模具主档加整啤重和每件腔数、按模具或机台出差异分析; 容器按"升 × 堆积密度"换算; 盘盈待抵扣结转 (如报表显示跨期误差明显); 我方供颗粒外发注塑; 修复通用调拨红冲计价缺陷。

**第三期 (可选)**: 各料浪费率连续 3 期稳定在 ±3% 以内后, 如确需实时账面, 在同一内料仓上叠加报工倒冲 (金蝶"调拨倒冲 + 差异分摊")。届时必须同时处理瞬时预留与 V249 上限、按理论账面审核盘点、锁序和审核耗时。

## 13. 验证计划

真实 PostgreSQL, 受 `UTEN_RUN_DB_TESTS` 门控; 全链测试切换真实账号走全栈, 禁止只用 mock。测试清单与断言见实现规格。

1. **配置守卫**: 一车间一内料仓; 内料仓必须是本车间线边仓; 有流水后内料仓与启用日不可改; 停用只在从未有流水、从未绑定时允许; `PERIODIC` 必须质量单位; 期间边形状; 辅料和记费用的料不能进 BOM; 发料方式与分摊方式切换前提与 BOM 行连带转换; 有 `FULFILLED` 但已发未清账的按单需求时切换被拒, 退料清账后放行; 线边仓改名 (只给重名的加括号)。
2. **公共可用量不含内料仓颗粒**: 齐套、预留、物料分析、MRP、委外可用量都看不到; 通用单据选不到内料仓。
3. **发料**: 直接发料与按申请发料; 两个叶仓拆两张调拨; 内料仓均价 = 调入成本; 安全库存不挡、预留挡; 库存不足整笔回滚; 通用调拨、其它入库进出内料仓被拒; 内料仓单据红冲被拒; 直送货品在内料仓的原规则不变。
4. **退回与其它耗用**: 内料仓一侧只守非负底线; 价值去向正确; 盘点开始后当天发的料记进下一期、业务日期仍是当天; 补录只能补到盘点中或已盘点未结算的那一期, 已盘点的自动更正; 没有来源引用的普通出库仍守可动用量。
5. **下达**: 只有期间边 → `PERIODIC_MATERIAL`、无需求; 按单边 + 期间边 → 只为按单边建需求; 按单边 + 期间边的段 (按单需求的段才比指纹) 改单重后拆批不报"BOM 已变化"; 补填单重后原 `DIRECT_MAKE` 段拆批、追加仍可建段。
6. **开工与认料**: 待认料的行能勾选并弹出开工确认表; 开工确认表一次开工多个计划; 同产品第二张工单自动带出; 按工单领料写 NONE 后仍要求真实领料; 嵌件注塑件勾"还要按工单领别的料"后领料发现门保留、嵌件按单领、颗粒进期间理论; BOM 接管 (勾了该项又没有按单边时拒绝); 未开启车间 `NEED_BIN` 被拒; 领料发现、新需求、直送登记 `PERIODIC` 货品被拒; 开启时在产段一次认完并绑定, 带未核清按单需求的段为 `ORDER_ONLY` 不绑定; 工作台状态与开工门一致。
7. **换料**: 生效日前后的报工分属两种料; 已结算日期不能换。
8. **盘点**: 满、半、空与直接填公斤的换算; 缺容器或缺料不能提交; 更正的对称冲回 (先盘盈 5 再更正为多用 10: 冲回盘盈 5、出 10, 结算后在制无余量); 撤回删除空的下一期; 两人并行录入; 机台满半空全链。
9. **自动结算**: 提交即排队、后台结算、页面轮询; 两个产品共用一种料按比例加尾差, 合计 = 实际; 价值切片合计 = 21 型价值; 两个方向的覆盖断言。
10. **拦结算三情况**: 未审报工 (审核人与制单人都收到通知)、缺单重、有理论没进过料 (仓库补录到已盘点那一期后自动更正并结算) → 各自通知责任人 → 补完自动结算; 其它异常 (有实际没理论、盘盈、浪费率超限、其它耗用超限) 不拦、标红; 连续失败 3 次改为每天重试并通知。
11. **跨期**: 9 月 30 日夜班报工 10 月 1 日审核计入 9 月; 10 月 1 日凌晨才点开工、表头 9 月 30 日的报工也计入 9 月; 结算后该期日期的报工新建、审核、红冲被拒 (含早于期间料行起始日的补报工), 提示正确。
12. **并发**: 结算与报工审核双向无死锁; 本期结算时下一期报工不等待; 结算与发料、提交盘点与发料并发; 同键重放不重复过账; 两个节点的定时任务不重复结算。
13. **撤销结算**: 只能最近一期; 成本完整撤回、数量不动; 24 小时内定时任务不重结, 点"重新结算"或满 24 小时后重结写新结果; 无权限或未再认证被拒。
14. **成本发现与传播**: 结算时没有成本对象的段, 成品入库后登记投入; 结算前成本对象不完整、结算后完整; 结算与撤销事件被刷新来源守卫接受; 在库件价值增加, 已售件进销售成本, 被装配工单领用的上级工单成本随之变化; FQC 补产 SCRAP 计理论、REWORK 不计。
15. **物料分析、MRP、委外、足迹**: 期间边不进快照、不预留、不下单、不让料; MRP 不展开; 单一子件判定不受影响; 报工审核不锁颗粒库存键。
16. **学习**: V740 不触碰学习对象 (迁移契约测试扫描 V740 文本, 剥注释后不出现学习函数、表、列名); 期间料段不产生学习分子 (整批领料货品不能有按单需求); 嵌件注塑件完工清账后嵌件边照 V711 发布, 之后填颗粒期间边成功、颗粒单重不被学习覆盖; 现有学习测试保持绿。
17. **性能**: 报工审核语句增量不超过 3 条; 结算 200 × 3 在 10 秒内; 提交盘点 30 种料在 3 秒内。
18. **权限负测**: 无权限 403; 车间只见本车间; 撤销结算要再认证; 逐人权限点不经部门下发。
19. **迁移**: 在本机克隆库上前向迁移 (禁止在服务器上演练); 迁移头同步; 业务清空分类; 审计登记。
20. **页面**: 窄屏、大字体; 失败保留输入; 文案无代号; 括号全为半角; "线边仓"字样面向用户全部消失。

## 14. 不做与没选的方案

- **报工时实时倒冲**: 放第三期。会撞 V249 超需求拒绝和默认超产; 单重不准时"欠扣"与盘点互相卡死; 报工审核已出现过 15.094 秒 (ADR-089:125)。
- **散装料直接记费用 (SAP Bulk)**: 主料的产品成本会失真, 也拿不到用户要的数据。
- **只出报表不进账**: 产品成本缺塑料, 而且成品入库已不称重。
- **按工单领颗粒、报工填用量**: 用户已否决。
- **新建独立的车间料仓**: 用户要求线边仓改名复用; 颗粒与直送货品天然不相交, 按货品分流即可, 不需要第二套私有保管口径。
- **固定盘点周期与周期提醒**: 用户要求需要时就盘。按月对账靠"月底盘一次"的页面提示。
- **计划员手工点结算**: 改为自动结算; 只有三种会算错的情况才拦, 其余自动处理并标红。
- **BOM 行上另设发料方式**: 同一车间同一种颗粒一旦既按单领又整批领, 两本账的实物都在车间、盘点无法区分; 发料方式只放货品上。
- **期间"代用" (按产品 + 产量换料)**: 落不到具体报工行, 重算不可复现; 改为带生效日的段级换料。
- **"按理论给产品、差额记盘盈"**: 产品会重复承担上期多摊的部分; 改为 A < 0 时产品分 0。
- **结算时才过数量账**: 盘点到结算之间账面虚高, 退回和其它耗用会按虚高账面放行; 改为提交盘点当场过净额。
- **盘点"提交"时才截止**: 与实物清点时刻脱节; 改为开始盘点即截止。
- **另立"期间差异"成本范围**: 一张工单两个成本对象、两次产出分配。
- **物料分析里显示期间边的参考量**: 第一期快照整体不读期间边, 避免十余处读 `hard_gate` 的代码逐一改写。
- **在 V740 里锚点替换 V711 学习函数 (学习分母读共用函数、期间边不改人工所有、发布不碰期间边)**: 上一轮修订曾这样定, 已撤回。用户要求的是让 BOM 学习会话把不良数算法覆盖到所有车间, 该会话已接手, 合并时会 DROP ... CASCADE 重建全部 V711 学习对象; V740 改其函数体既多余又增加碰撞风险。本 ADR 只提供共用函数 `fn_report_item_material_output_qty`, 期间边与学习的现行交互交该会话决定 (§11)。
- **给"报工日期落不进任何期间料行"单设第四种拦截**: 期间料行起始日规则与截止锁已让它结构上不会发生, 用结算断言兜底即可; 多一种拦截就多一种要人处理的通知。
- **自动结算改走业务事件派发 (`business_outbox`)**: 那是全厂唯一的一条派发线程, 结算单事务最长可到 10 秒会卡住全厂通知; 重启丢失由每 10 分钟的定时任务兜住。
- **新增班次字段、引入 btree_gist、期初导入进叶仓或内料仓**: 都不需要; 期初导入只给已有数量开价值、不产生实物流水, 余料改走其它入库核定价 + 启用日直接发料。
- **停用后再开启**: 第一期不支持, 停用只用来撤销设错的开启; 期间链因此只管一段连续的开启。

## 15. 评审处理 (简述)

L = 库存与成本守恒, U = 现场操作与界面, I = 与现有流程和在途工作衔接。

- **全部采纳并落到正文的致命项**: 可动用量拦内料仓出库 (L-F1, §4.6 来源引用授权); 分摊进不了成本、完整性误判 (L-F2 / I-F1, §4.6 投入发现视图、刷新守卫、完整性门); 反结与唯一键冲突 (L-F3, 数量在提交盘点时过账、结算只移价值、撤销只撤成本、结果按次存); 认料"按单领别的料"是死路 (U-F1, NONE 认料 + ORDER_ONLY); 认料与 BOM 双料 (U-F2, BOM 接管); 截止与实物脱节 (U-F3, 开始盘点即截止); 色母理论口径 (I-F2, 辅料单独处理方式); 足迹锁颗粒与结算成环 (I-F3, 期间边出足迹、报工锁期间行); `hard_gate` 挡不住物料分析 (I-F4, 快照整体不读期间边)。
- **严重项**: 盘盈重复承担 (A < 0 产品分 0); 同车间两本账 (发料方式只在货品上 + 全局守卫); 调拨红冲计价缺陷 (内料仓单据禁止红冲, 通用缺陷另跟踪); 期初不产生流水 (空仓启用); 盘盈计价停在未定 (22 型核定价格); 理论不可复现 (期间料行生效区间、单重唯一规则); 权限缺口与页面放置 (§8); 仓库直接发料为主路径; FQC 补产放行; 委外与有 BOM 判定 (§3.5); 拆批与改 BOM (第一轮定为派生段放行, 第三轮改为零料证据 `DIRECT_MAKE` 看按单 BOM; 指纹不计单重)。
- **第二轮用户拍板改变的处理**: 私有保管清单类意见 (L-S3、I-S8) 因复用线边仓而不再需要新口径; 学习衔接 (I-S6) 定为本 ADR 不改学习, 不良数进学习由 ADR-129 会话实现 (§11; 第三轮曾改为 V740 锚点替换学习函数, 已撤回); 纯不良报工与不良数分片 (I-S9) 移交 ADR-129 §2.13; 盘点周期意见 (U-m5、U-m6) 因不设周期而取消; 结算清单改为自动结算 + 三种拦截; 权限点由十二个收敛为七个。
- **第三轮: 实现规格对抗评审 (2026-09-28)**: 致命 3 条: 采纳 2 条: 上线时已按工单领出的颗粒不会计两次 (§3.4 未核清定义、§5.1 第 0 步、`ORDER_ONLY`); 嵌件注塑件的路径 (§4.2、§5.4); 不采纳 1 条: "BOM 学习把不良数算进去" 改由 ADR-129 会话实现 (该会话会 DROP ... CASCADE 重建学习对象, V740 改学习函数既多余又增加碰撞风险), 本 ADR 只提供共用函数 `fn_report_item_material_output_qty` (§11、§14)。严重 9 条全部采纳: 更正对称冲回与 22 型原路出 (§5.7, 估价按池均价出到 EXTERNAL); 期间料行起始日不用开工时钟、截止锁只看段绑定的仓 (§3.3、§5.6, 第四种拦截不设, 改为断言); 已盘点后可补录并自动更正 (§5.2); 待认料的行能进开工确认表 (§5.4); 零料证据守卫改两处锚点、不加早退 (§4.2); 期间边指纹去掉行 id 与更新时间 (§3.3); 业务表去掉命令 id (§4); 分摊方式同一道切换门 (§4.1); 工作包顺序与测试位置 (实现规格 §6)。小问题 19 条全部采纳 (取号触发器按 ADR-106 只挂插入 + 改号拦截, 改名只给重名的加括号)。简化建议 8 条: 采纳 6 条; 部分采纳 1 条 (立即重结只在更正、补录、报工审核后触发, 补单重由 10 分钟定时任务接上); 不采纳 1 条 ("结算走业务事件派发", §14)。逐条理由见实现规格末节"评审处理"。

## 17. 实现备注 (2026-09-28)

实现按本文与实现规格完成。下面是实现中与本文或规格不同的决定、本文没写到但实现时定下的口径, 以及文档同步时核对源码仍未补齐的缺口。以源码为准; 这里的缺口清单只反映 2026-09-28 的核对结果。

### 17.1 发料方式与分摊方式切换对 BOM 行的连带处理 (`J/features/master/goods/GoodsIssueMethodService.java`)

1. **改成"整批领料 + 辅料"或"整批领料 + 记车间费用"时, 同一事务软删除用到这种料的全部 BOM 行** (预览里这些行标"从 BOM 去掉", 说明"辅料不写进 BOM, 按当期主料用量分到各产品"), 并重算这些父件。§4.1 的数据库断言要求这种料不得有未删除的期间边, 二选一: 要么拒绝切换、等人一行行手删, 要么切换时一并去掉; 实现取后者, 员工少一步, 数据库断言照样兜底。
2. **改回"按工单领料"时, 同一事务把这种料在开工前、装配、完工三个阶段上"齐套门槛为否"的 BOM 行恢复为齐套门槛** (预览标"恢复为齐套门槛")。否则这些产品会悄悄变成"没有生产硬门槛", 开工不再要求领这种料。早先因改成辅料而被软删的行不恢复。
3. **改成"整批领料 + 主料"时**, 把 BOM 行转成期间边形状的那条 UPDATE 同时把组件列原值写回一次, 让 BOM 接管触发器照常作废这些产品的认料 (产品第一次有期间边), 与手工新增期间边的效果一致。
4. 切换与上线准备批量保存的幂等都进同一张命令账本 `workshop_material_commands`, 命令种类 `GOODS_ISSUE_METHOD` / `PERIODIC_BOM_PREPARATION`, 由基础资料包直接写参数化 SQL, 不引用内料仓包的代码 (ADR-017); 上线准备里"只知道料不知道单重"的行经 `WorkshopMaterialChoicePort.choose` 写认料, 幂等键由请求键派生。
5. 普通货品保存、新建、导入对四个新列只读 (实体列不可插入、不可更新); 四个属性只经 `PUT /api/master/goods/issue-method/batch` 改, 其中每袋净重、回收料传空表示保留原值。
6. 克的换算只按单位名称: 千克/公斤/kg/kgs = 1000 克, 克/g/公克 = 1 克; 不读计量档案的换算系数 (与 §3.1 一致), 其它质量单位按原单位录入。
7. BOM 行的两个确认 (单个重量小于 0.1 克或大于 5000 克、同一父件第二条期间边): 需要确认时服务端回 422, 字段错误名为 `confirmUnusualWeight` 或 `confirmSecondPeriodicMaterial`, 页面弹确认后带标记重发; BOM 粘贴同一约定; BOM 导入在检测报告里已列为警告, 提交时视为已确认。

### 17.2 自动结算的触发、开关与版本

1. **提交盘点后的后台自动结算**: 提交盘点、更正盘点提交、补录进"已盘点未结算"的那一期、报工审核时发现所涉期间正被"未审报工"拦住, 这四处在各自事务里登记一次结算尝试, **事务提交之后**才投递到单线程后台执行器 (`WorkshopMaterialCloseTrigger`, 队列 500); 同一事务同一期只投一次, 回滚不投递。请求线程不同步结算 (网页端无请求体的写请求有 15 秒上限)。
2. **定时重试**: `WorkshopMaterialCloseScheduler.retry` 每 10 分钟一轮 (启动后 3 分钟首轮, 云端副本不跑), 已登记 `ScheduledTaskCatalog` "车间内料仓自动结算"; 每轮最多 50 期, 按内料仓、期号顺序, 选"已盘点"且处于排队、被拦、失败 (连续失败不足 3 次, 或距上次尝试满 1 天) 或保留期已到的期间; 操作人记该期最新一版盘点的提交人; 单期失败不影响其它期。服务重启丢掉的投递由它接上, 补完单重后的结算也由它接上。
3. **开关**: 属性 `uten.workshop-material.auto-close.enabled` (默认 `true`)。设为 `false` 时停掉提交后的自动投递和 10 分钟定时补做; 员工点的"立即重试"与撤销后的"重新结算"照常。只用于测试: `WorkshopMaterialCountPostgresTest`、`WorkshopMaterialIssuePostgresTest` 设为 `false`, 否则后台结算会与测试里紧接着的更正盘点、补录争同一期。生产环境不要关。
4. **每次结算尝试都会提升期间版本**: 无论成功、被拦 (记"差什么、谁来补") 还是失败 (记失败次数), 都会写期间行, 数据库守卫让 `row_version` 每次 +1。所以提交盘点后页面手里的期间版本很快就过期: 页面要在提交后刷新或轮询期间状态, 再允许"更正盘点""撤回"等带版本的操作, 否则员工会看到"这一期已被别人改过"。
5. 一期结算成功后, 同一轮顺带结算已经盘点、正在排队或被拦的下一期。
6. 撤销结算后点"重新结算"记为手动 (`MANUAL`), 同时清掉 24 小时保留、把状态置为排队, 页面据此开始轮询; 报工审核触发的那次结算以审核人为操作人。
7. 后台执行器不经业务数据清空的排水闸 (排水闸在管理包, 仓库包不能引用); 只有定时补做经 `DrainAwareTaskScheduler`。清空期间恰好在跑的一次结算只会记为失败, 清空后没有可结算的期间。

### 17.3 结算细节

1. **刷新成本范围只刷本次有分摊行的范围** (规格原写"本期所有有理论明细的成本范围")。原因: V740 的刷新来源守卫只接受"本次结算对该范围有分摊行"的结算或撤销事件, 刷新一个只有理论、没有分摊行且已有成本对象的范围会被拒 (23514)。影响: 有理论但没分到料的范围 (例如这种料本期以盘盈收场), 成本完整性门等它下次产出入库时再重算。
2. **零理论边角**: 绑定本仓的段上某行已审报工用到一种理论为 0 的料 (产量为 0, 例如 FQC 返工补产), 而本期没有这种料的期间行时, 正向覆盖断言要求一条写不出来的理论明细; 结算以业务文案停下, 提示车间更正盘点把这种料补上 (记 0)。有理论才拦的"没进过料"拦截不覆盖这种情况; 更干净的修法 (理论为 0 时不要求覆盖) 留给后续迁移。
3. **标红口径** (本文 §5.8 只写了方向, 实现定的数): 浪费率超出 [-30%, +50%] 标红; 其它耗用超过本期 (期初 + 领入) 的 10% 标"试模清机等用料偏多"; 盘盈按 0 估价时标"盘盈没有参考价"。浪费率在 SQL 里算 (保留 6 位), 仓库业务包不写四舍五入 (金额口径锁边测试扫描)。记车间费用和盘盈两种处理方式的"结算时金额" = 这一期盘点过账的净值。
4. **拦截项的存储形状**: 期间行 `close_blockers` 为 `[{kind, count, responsible, samples}]`; `responsible` 直接存中文 (报工审核人或制单人 / BOM 维护人 / 仓库发料人或本车间认料的人), 报表页原样显示为"负责: ..."; 上一期未结算时为空; `samples` 是报工单号、产品名或料名。

### 17.4 附件8 列解释 (`J/features/finance/cost/FinanceCostService.java`)

1. 只列**已结算**、且**期末日落在查询日期范围内**的期间, 按内料仓、期末日、期号、材料编码排序; 末尾追加"其它耗用""期间""内料仓"三列 (§7.5)。
2. "产品入库数": 主料 = 理论用量 (良品 × 单个重量); 辅料 = 按主料理论分到产品的量 (计入量); 记车间费用的料 = 0。§7.5 原写"理论用量", 但辅料与记车间费用的料没有理论, 所以这样落。
3. "账面结存" = 期初 + 领入 − 退回 − 其它耗用 − 产品入库数; "差异" = 实际盘点数 − 账面结存 (负数表示多用); "成品占材料比例%" = 产品入库数 ÷ 实际用量 × 100 (实际用量大于 0 时才有值)。
4. "安装挑选不良"恒为 0。报表列定义没有备注字段, 表头直接写成"安装挑选不良(待不良数上线)"; ADR-129 §2.13 上线后改为 不良 × 单重。
5. 附件 8-1 (领料明细) 取内料仓发料流水: 原模板的"订单号"列改名"领料单号", 显示内料仓领料单号; 备注显示内料仓名, 补录的加"上一期漏录补录"。附件 8-2 (退料明细) 取内料仓退回流水。附件 8-3 (产品入库明细) 取有效结算的理论明细 (重量 = 理论用量, 数量 = 报工产量, 备注 = 内料仓与期间起止日)。

### 17.6 其它实现决定

1. **内料仓主仓的叶仓判定修复** (`J/features/production/fulfillment/ProductionMaterialDiscoveryService.java`): 领料发现校验来源仓时原来判"没有任何子仓", 某主仓下第一次建出内料仓 (线边仓子仓) 后, 这个主仓就被当成"不是叶仓"拒绝 ("实际仓库无效")。每个开启整批领料的车间都会在所选主仓下建一个内料仓, 上线必撞。改为调用 V613 的 `fn_warehouse_is_operational_leaf` (不把内料仓算作子仓), 与其它十处读者同一口径。
2. 领料发现拒绝整批领料货品放在 `validateMaterialIdentity`, 车间申请与仓库配置两条路都经过; FQC 补产确认的"只用整批料"短路放在对象范围检查之后、计划分析检查之前 (这类任务不需要计划分析)。
3. 生产侧新端口在 `ProductionExecutionSegmentService` (`WorkshopMaterialStatePort`) 与 `ProductionDailyReportService` (`WorkshopMaterialReportGuardPort`, `required=false`, 为空时跳过) 用字段注入, 不加构造参数, 让现有用 `@InjectMocks` 构造的单测照常编译。
4. 下达快照行的组件发料方式放在第 30 列 (下标 29), 读取前先判列数; 旧的 29 列模拟行按按单边处理。
5. 开工就绪: 待认料的段只有在没有领料发现门时"可开工"才为真 (例如 `NO_PRODUCTION_HARD_GATE` 或 `DEMANDED`); 没有 BOM 的零料直制产品在认料前"可开工"为假、"需要开工确认"为真, 客户端按后者把它放进开工确认表。新段插入时已带路线 (V699 默认持续生产), 所以"路线未确认"这一支只对旧行生效。
6. 工作台分桶: 待认料的待开工、已派工行归"车间已收到 · 等待物料", 并从去领料、已提交领料、可开工三桶排除, 一行只在一个桶里; 服务端排序排在"去领料"之前。
7. 段列表的"补产就绪数"改用 `fn_fqc_replenishment_material_ready`, 只用整批料的报废补产也算就绪, 与任务状态"就绪"一致。
8. 客户端: 开工确认表侧板宽度放宽到 min(1560, 0.94 × 窗口宽) (八列合计约 1450 像素); 内料仓相关的五条新路由在路由全覆盖测试里逐条登记, 原 206 条守卫数量单独锁定不变。
