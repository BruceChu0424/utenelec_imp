## 三、明细表字段语义（重点）

明细表是老库设计的「重灾区」，也是新库优化的主战场。

### 3.1 基本行字段（共性）

| 字段 | 含义 |
|---|---|
| `ID` | 明细主键 |
| `BillID` | → 主表 `ID` |
| `GoodsID` | 货品 → `B_Goods.ID`（新库 `goods.legacy_id`） |
| `ColorID` | 颜色 → `B_Color.ID`（可空，无色货品为 0/null） |
| `QTY` | 数量（float，主单位） |
| `Price` | 单价（decimal） |
| `Total` | 金额 = QTY×Price（订货/入库为 `Total`，退货为 `STotal`） |
| `UnitID` / `URate` | 单位 → `B_Unit` / 单位换算率（`QTY×URate` = 基本数量，用于库存） |
| `Weight` / `KQTY` | 重量 / 件数（辅助计量） |
| `Summary` | 摘要 |

### 3.2 数量字段族（语义由触发器反推，详见 §四）

| 字段 | 出现在 | 含义（反推） |
|---|---|---|
| `QTY` | 全部 | 单据数量（申请量/订货量/收货量/退货量） |
| `RQTY` | 申请/订货明细 | **已转量**：申请明细=已订数量，订货明细=已收数量（下游审核时回写累加） |
| `WQTY` | 订货/入库明细 | **已退数量**（退货单审核时回写累加） |
| `DQTY` | 申请/订货明细 | 已分配/已排产数量 |
| `BPQTY` | 入库明细 | 赠品/包装数量（入库时 `QTY+BPQTY` 一起入账） |
| `OrderQTY` | 入库/退货明细 | 关联订单数量 |
| `FlagQTY` | 订货明细 | 标记数量 |
| `SQTY` / `SOrQTY` / `UseQTY` / `RefQTY` | 申请明细 | 销售订单相关/已用/参考数量（语义模糊） |

### 3.3 溯源字段族（⚠️ 老库核心反模式）

明细行用**逗号分隔的 varchar 字符串**塞 1:N 上游关系，触发器用 `f_split` 拆分循环回写。这是新库必须改掉的重点：

| 字段 | 出现在 | 含义 | 老库实现 |
|---|---|---|---|
| `SOrderNo` / `SOrderID` | 申请/订货/入库/退货明细 | 销售订单号/ID | **varchar(8000)，多值逗号分隔** |
| `POrderNo` | 申请明细 | 订货单号 | varchar |
| `PInNo` | 订货明细 | 收货单号（被哪些入库单收货） | varchar(2500)，多值 |
| `InNo` / `InID` | 退货明细 | 入库单号/ID | varchar / int |
| `OrderNo` / `OrderID` | 入库/退货明细 | 订货单号 / **订货明细 ID** | OrderID 为单值 int |
| `FPlanNo` | 申请/订货/入库/退货明细 | 生产计划号 | varchar |
| `BomItemID` | 申请/订货/入库/退货明细 | BOM 明细 ID | **varchar(8000)，多值** |
| `LItemID` / `LStatus` | 申请/订货明细 | 工序明细 ID / 工序状态 | varchar(5000)，多值 |
| `ApplyID` | 订货明细 | → 申请明细 ID | 单值 int |
| `MGoodsID` | 申请/订货明细 | 替代货品 ID | int |

> 🔎 入库明细的 `OrderID`、订货明细的 `ApplyID`、退货明细的 `InID/OrderID` 是**单值 int**——这几条是真正的外键链路骨干。其余 `*No`/多值字段多是「软关联 + 报表展示用」。

## 四、触发器揭示的业务规则（设计金子）

老库把全部业务逻辑下沉到 91 个触发器。采购相关触发器揭示了以下规则，**新库必须保留语义、改用 Service 层实现**：

### 4.1 状态机驱动一切

所有库存/回写/成本联动，都由主表 `Status` 字段变化触发：

```sql
IF (@Status <> 0 AND @Status2 <> @Status)  -- 状态确实变了才触发
```

- `Status = 0`：草稿，**不产生任何业务影响**
- `Status = 1`：审核生效 → 入库增库存 / 回写上游 / 重算成本
- `Status = -1`（反审/红冲）：**反向冲销**（库存减、上游回减）
- `Status2` 记录「上一次状态」，用于判断状态迁移方向

> 新库语义保留：单据有「草稿 / 待审 / 已审 / 红冲」状态机，只有「已审」才驱动下游。

### 4.2 全链路回写（审核生效时）

```
P_Application（申请）  ──ApplyID──▶  P_OrderItem（订货）：RQTY += 订货量
P_Order（订货）        ──OrderID──▶  P_InItem（收货）：RQTY += 收货量，PInNo 追加
P_In（收货）           ──OrderID──▶  P_OrderItem：RQTY += 收货量，PInNo 追加
P_Withdraw（退货）     ──InID──▶    P_InItem：WQTY += 退货量，PWDrawNo 追加
P_Withdraw（退货）     ──OrderID──▶  P_OrderItem：WQTY += 退货量，PWDrawNo 追加
P_In/P_Withdraw        ──SOrderID──▶ S_OrderItem：PIQTY/PWQTY（销售单已采/已退）
P_Order                ──BomItemID─▶ F_PlanItem：POQTY（生产计划已采）
```

回写是**逐条 UPDATE WHERE ID=**，方向随 `Status` 正负。

### 4.3 结案标志（Fulfill）

`CheckFulfill*` 触发器：明细增删改后，若主表下所有明细的剩余量 ≤ 0，则主表 `Fulfill=1`（结案）：

- 申请单：`QTY - RQTY <= 0`（全部已订）
- 订货单：`QTY - RQTY + WQTY <= 0`（全部已收，扣除已退）

### 4.4 库存台账（StockGoods）—— 与采购强耦合

收货/退货审核直接写库存表 `StockGoods`：

- **台账粒度**：`StockID + GoodsID + ColorID + Year`
- **按月分列**：`INQTY01..INQTY12` / `INWeight01..12` / `INTotal01..12`（入），`OUT*`（出）——写死 12 个月列
- **当前余额**：`QTY` / `Total`（且影响 `Year > 当前年` 的期初行）
- 收货审核 → `INQTY<月> += 量`，`QTY += 量`
- 退货审核 → `OUTQTY<月> += 量`，`QTY -= 量`

> ⚠️ 这是采购与库存的强耦合点。新库若不同步做库存账，收货/退货的「库存效果」需先以流水事件形式留存，余额账后置。

### 4.5 采购价 → 货品成本联动

收货单审核（`Status=1`）会重算货品标准成本（`B_Goods`）：

```
SourceE = 入库价
GTotal  = SourceE + MachiningE + IncidentalE + LacquerE + PlatingE + CasingE + PolishE
LostE/RentE/WorkE = (SourceE+加工费) × 各自 Rate / 100
CTotal  = GTotal + WorkE + LostE + RentE
Total   = CTotal × (1 + MakeRate/100)        -- 货品标准成本
```

> 新库：采购入库价联动成本档案是可选高级特性，首版可只记录入库价、不自动改货品成本档案。

### 4.6 全局开关

所有触发器开头判断 `(SELECT ISplan FROM SystemAccinfo) = 1`——「是否启用生产计划/成本联动」全局开关。新库无需此开关，逻辑显式化。

## 七、老库设计的核心问题（新库要解决的）

1. **业务逻辑全埋在触发器**（合计、库存、成本、回写）→ 换库即丢失、不可测、不可审计。新库上移到 Service 层事务。
2. **多值字符串溯源**（`SOrderID`/`BomItemID` varchar(8000) + `f_split` 游标回写）→ 性能与正确性双输。新库用关联表/外键。
3. **按月分列库存台账**（`INQTY01..12` 写死）→ 跨年复杂、扩展僵化。新库用流水 + 余额模型。
4. **状态字段冗余混乱**（`Status/Status2` + `Fulfill/Stop/Cancel` + `LStatus`）→ 多套体系并存。新库用枚举 + 结案派生。
5. **十几个语义模糊的数量列**堆在一行 → 新库只留单据原生量，累计量（已收/已退）按需从下游聚合或专门回写表。
6. **`float` 存金额数量**（`QTY float`）→ 精度风险。新库用 `numeric`。
7. **主表挂 `GoodsID`**（`P_Order.GoodsID`）→ 一单一货遗留，与明细冲突。新库去除。
