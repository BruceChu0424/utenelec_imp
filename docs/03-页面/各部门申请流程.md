# 各部门申请流程

路由：`/finance/applications`、`/finance/applications/new`、`/finance/applications/settings`、`/finance/applications/:id`、`/finance/applications/:id/edit`、`/finance/applications/:id/continue`

## 页面定位

集中核对原表六类申请的进展、原始凭证和已经发生的付款。

页面名称沿用原始财务需求“各部门申请流程”，来源与岗位节点见[申请出货实施记录](../99-项目治理/2026-11-02-财务复刻-申请出货实施记录.md)。新建动作按当前所属业务入口办理，原申请编号、来源和响应未知的操作继续留在原记录中。

| 原表分类 | 新建入口 |
|---|---|
| 出差申请 | 我的申请中的出差申请 |
| 出差报销申请 | 原报销入口的出差报销 |
| 报销申请 | 原报销入口的普通报销 |
| 付款申请 | 我的申请中的付款申请 |
| 预付申请 | 我的申请中的供应商预付申请 |
| 工资付款申请 | 本财务入口的原工资批次申请 |

员工“我的申请”的种类不增加工资付款申请。财务入口既有工资申请仍须引用真实工资批次，保留薪资查看范围、原扣款和实发事实；不能据此新增员工自助工资付款能力。

## 读取与办理

列表使用现有 Uten 分类、表头筛选和分页表格。详情区分原始来源、提交时冻结内容、岗位签名和实际执行记录。只读查看不授予审核、付款、确认或反审能力；每个动作均与当前版本、认领和来源指纹一并由服务端核对。

报销、工资等申请只能引用当前身份有权读取的原单。原生单据后来不可读时，既有申请的只读参与者仍按原申请的冻结范围读取历史；不能借申请页面打开原单或读取其他申请的原始内容。本人可编辑草稿继续核对当前原始来源，来源不可用时保留输入并停止提交。

执行、财务确认和撤销执行分别记录真实资金及审计事实。撤销关联付款保留原付款及申请历史，不删除或改写旧审计事件。响应未知时先查询原操作回执，再恢复同一请求身份，避免重复写入或重复付款。

设置与岗位映射沿用 `expense:settings`；页面读取使用当前财务申请、报销或工资的相应入口权限。功能启用、岗位配置、实际对象范围和动作权限分别校验，不能以看到入口代替已经具备办理条件。

## 实现与验证边界

入口映射唯一维护于 `lib/features/finance/config/finance_application_routes.dart`，业务契约由 `FinanceApplicationController`、`FinanceApplicationService` 及各原生来源适配器维护。页面设计默认使用 `frontend-design`，复用 Uten 主题、提示 icon、公共等待弹窗和既有草稿保护。
