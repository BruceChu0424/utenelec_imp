# V579 基础资料子表与客户信誉分

## 背景

用户反馈（2026-09-14）：客户/供应商主档的联系方式与地址是平铺单值列（mobile/phone/phone2/fax/email/website/address/ship_address），无法登记多个联系人电话或多个地址；也没有客户行为记录与信誉分。同时手机是必填，录入负担重。

## 变化

1. **`party_contact_methods`**：多联系方式。`party_type`（CLIENT/SUPPLIER）+ `party_id` 多态归属；`kind` ∈ MOBILE/PHONE/FAX/EMAIL/WEBSITE/OTHER；`value` 非空 1–200；`is_primary` 主选；`remark`。索引 `(party_type, party_id, kind)`。
2. **`party_addresses`**：多地址。`kind` ∈ SHIPPING/BILLING/OTHER（默认 SHIPPING）；`address` 非空 2–500；`is_default`。索引 `(party_type, party_id, kind)`。
3. **`party_activity_records`**：跟进/行为记录。`kind` ∈ FOLLOW_UP/COMPLAINT/PENALTY/REWARD/OTHER；`content` 非空 2–2000；`score_delta` ∈ [-100,100]（默认 0）。索引 `(party_type, party_id, created_at DESC)`。
4. **`clients.credit_score INT NULL`**，CHECK 0–200。NULL=从未评估；首条带分数记录落地时按 `100±delta` 初始化，之后累计并夹在 [0,200]。仅客户有信誉分。
5. 三表全部挂 `trg_audit_*` 行级审计触发器（ALWAYS），与全库口径一致。

## 老数据适配（零丢失回填）

- 每条非空平铺列回填一条子表行：mobile→MOBILE(主选)、phone→PHONE(主选)、phone2→PHONE(非主选)、fax→FAX、email→EMAIL、website→WEBSITE；address→BILLING 地址、ship_address→SHIPPING(默认) 地址。客户与供应商分别回填。
- **平铺列保留不删**：单据、导出与老接口继续读它。服务端 `PartyDirectoryService` 在联系方式增删后把「每类第一条（主选优先，其次最早）」同步回平铺列，该类清空则置空串——两套口径不会漂移。

## API（复用既有权限码，零新码）

- `GET/POST/DELETE /api/master/clients/{id}/contact-methods[/{cmId}]`（client:view / client:edit）
- `GET/POST/DELETE /api/master/clients/{id}/addresses[/{addressId}]`
- `GET/POST /api/master/clients/{id}/activity-records`、`GET /api/master/clients/{id}/credit-score`
- 供应商同构（supplier:view / supplier:edit，无信誉分端点）。
