## 2026-10-05 委外申请物料齐套才解锁下单(ADR-156)

委外加工价每天不一样，财务批准订货单那天价格就定了，所以直属物料不齐时不让生成委外订货单，
现有物料够做几套才能下几套：

- 任务中心「待处理」申请行多两种状态：**等物料齐套**(一套都不够：不能勾选、不能生成订货单，
  但照样留在「待处理」、照样计红数)、**可部分下单·可下单 N {单位}**(够做一部分：可以勾选)。
  缺 BOM 优先显示「缺 BOM·已通知研发」。见 2.3。
- 行上「齐套情况」逐种直属物料列出每套用量、需要、专属库存、已被占用、现在能用、还缺、够做套数。
- 勾选申请生成订货单时，按需求日期先后共用公共库存，预填各自这次能下的数量。
- 生成、保存、提交财务、财务批准、批准后加量都由服务端核对齐套，不够 409 并点名缺哪种物料；
  减量、删除草稿不拦。手工直接新建的委外订货单只能用公共库存。
- 可下单量上升时，采购委外部门能生成订货单的人收到「委外可下单」行动卡(见第七节)。
- 可下单、够做套数和物料明细全部来自服务端，Flutter 不读 BOM、不算库存。

## 2026-10-01 编辑页货品多选

委外订货及通用单据编辑页的货品入口复用销售同款多选器：第一项填当前行，其余各建一行。
订货、询价等保持原成品范围，发料、材料退与损耗保持原材料范围；上游锁定行不能改换货品。
新建订货带入的行自动勾选，逐项带回颜色、基本单位和库位，并沿原主档条款预填单价。
编辑既有订货单时新增行沿用整单商业条款；重复货品仍在保存前统一复核，不自动合并数量或来源。

## 2026-09-24 接受损耗独立结清与数量展示

接受损耗保留原订货数量、实际回厂数量及来源申请占用，独立记录损耗并核销履约余量。
例如订货 2000、实际回厂 1900、结案损耗 100，订单详情仍显示订货 2000、已收 1900、
结案损耗 100，标题与状态显示「已结清」。结案损耗只读服务端 `settledLossQty`，单位为
订货行单位；直属物料的损耗台账与委外件订单量分别显示，不能用两者的数量差在前端推算。

全链路进度的「结案核销」读取订单详情的 `closed`，不靠缩小订货量或供应商结存归零推断。
短交历史与详情独立显示原订货量、累计回厂、核销损耗及已结清状态。
所有接受损耗都不重开来源申请、不重新下单、不生成改量复核；允许损耗范围内正常结清，
不通知财务。超出约定损耗仍须委外人工判定，原异常损耗财务责任流程保持。

## 任务进度窗口与返回刷新

任务中心只有一个正式入口。申请行双击打开产品进度窗口，直接使用工作台响应；动态详情在窗口内
加载，失败可重试，关闭后晚到的响应不重新打开窗口。进度窗、委外订货单详情与物料分析供给进度
统一为一条时间线：计划已下达申请 → 生成委外订货单 → 财务审批 → 领料发外(已领 x/Q) →
加工回厂 → 品质检验 → 仓库确认入仓 → 结案核销。物料段复用任务详情的物料表；订货单进度接口(`/api/subcontract/orders/{id}/progress`)的物料行 `supplySources` 与任务详情同一读口，只给还缺的开放行(已发齐、已结束领料或不缺的行为空列表)。

产品进度窗另显示「数量归属」：申请沿当前可见明细的真实供给分配追溯，逐项显示原产品、
销售单号/行号、委外件和归属数量。申请合并多个产品时保留多条来源，不取某一个代表产品；
公共超量单列「公共备货」。只对当前页有查看权的申请 UUID 做一次批量查询，脱敏行不展开来源。

从入库、订货、领料或其他页面返回任务中心时，保留当前分段并重新读取，旧请求不得覆盖更新后的
行状态；首次进入仍只有一次概览加载。委外任务中心入口角标红数 = 待处理 + 可领
(服务端徽章汇总 `subcontractTask.pending + subcontractDraw.drawable`)，黄数 = 进行中
(`subcontractTask.inProgress`)；一个 60 秒轮询，返回 Hub 或完成委外业务动作时一起刷新；
无权限不请求、会话变更清零重建、请求失败保留完整旧快照。

## 计划调配与补供衔接

委外仍按真实委外件、申请、订货、领料发外和回厂入库追踪，调配不改原商业单。计划员在
[物料分析](生产物料分析页.md)让出合格现货后，可为原计划明确补供：委外件沿原「下达委外」
流程补下委外申请，获授权时单列公共超量；直属物料需求随委外件的计划产出自动增加。旧 DONE
不一律阻止合法新补量，旧原料耗用不能遮住新批材料缺口。见
[V568补供责任](../数据迁移/164-V568让料后的自制补供责任.md)。

已批准的委外订货专属在途可以调整，公共余量可以认领；已领给委外商的直属物料不能冒充最终委外
在途。来源、目标、已调量、未实收、失败提醒与合法撤销均用真实 UUID 投影，待检和合格待入库
不是可生产库存。原供给失败不抹历史承诺，净补供与撤回入口按真实有效供给处理，详见
[在途归属专册](../数据迁移/165-V569在途供给归属调整.md)。

> **操作区去重**：任务中心宽屏与全屏只由 `MasterDataTableView` 渲染操作区——「待处理」是
> 「已选 N 项 + 生成委外订货单」，「领料」是表格自带的浮动按钮「批量领料(n)」；窄屏卡片列表
> 在同一内容宽度判断分支里渲染一组。页面 Scaffold 不再重复叠加操作区。历史记录未选择日期时
> 不挂操作区；切换宽窄屏保留选择，权限及下单行为不变。

> **分类范式(ADR-066)**：委外申请分解页用统一分段卡(分段行 + 异常小类行 + 末尾历史记录时间
> 门控段；历史记录默认不选不发请求)；委外申请详情页底部有「生成委外订货单」按钮(复用
> subcontract_order:view+create+decompose 权限，带全部明细 id 直达订货编辑页)。

## 一、页面目标与不可跨越的职责

委外页面必须让员工在一个稳定入口看清以下链路，但不能把不同岗位的执行动作揉成一张通用采购页：

```text
直接委外下单 ──────────────────────────────┐
                                            ├→ 委外订货 → 提交财务(必须有 BOM) → 财务批准
物料分析「下达委外」→ 只读委外申请 → 申请分解 ┘        │ 冻结领料计划(每种直属物料一行)
  (缺 BOM：不能下达，自动通知研发)                     ↓
直属物料按各自路线备齐(自制完工入库 / 采购到货入库 / 嵌套委外回厂入库)
                                                       ↓
委外任务中心「领料」：可领 N 套 → 领料页提交 → 按「订货单 × 仓库」生成出仓草稿
                                                       ↓
仓库委外出仓工作台：核对、只能改少、审核出仓 → 委外商加工
                                                       ↓
仓库登记回厂(按可回厂套数) → 来料质检 → 合格待仓库确认入库 / 不合格处置
                                                       ↓
退回、余料、损耗责任、加工费应付与对账；直属物料后续到货继续领、分批回厂
```

不可妥协的页面边界：

1. Flutter 不读取 BOM 来判断能领多少、该发什么；可领量、物料表、状态和动作全部来自服务端(`canDraw`、`capabilities.canSubmitDraw`、`allowedActions`)。
2. 计划申请是只读需求事实；委外人员不能在申请页新建、编辑、审核或红冲。
3. 财务通过订货只表示商业放行与冻结领料计划，不表示已领料、已发出、已回厂、来料质检合格或已结案。
4. 提交领料、仓库草稿和通知送达都不能代替仓库实际审核出仓；回厂、质检合格都不能代替仓库实收。
5. 回厂新建不进入通用 `/subcontract/receipts/new` 编辑器；必须从仓库预计到货进入独立登记页，按可回厂套数、数量和来源校验。
6. 通知是提醒；任务投影、单据状态、对象范围、库存预留、来料质检与财务台账才是权威事实。

## 二、入口与路由

### 2.1 委外 Hub

- 路由：`/subcontract`。
- 页面按真实 `view` 权限逐卡显隐，不因部门名称、旧默认授权或「超级管理员前端 fallback」恢复动作。
- 信息架构：任务中心、单据(订货/计划申请/回厂品质/成品退/余料退/损耗)、三类报表、出仓单据(「委外材料出仓单」：发给委外商的直属物料出仓单，查看、核对与红冲，按 `subcontract_material_issue:view` 单独显隐)。
- 「待退回供应商」卡使用 `supplier_return_task:view`，不能用 `subcontract_order:view` 代替。
- 「回厂短交判定」卡片徽章 = 待判定案件数，与任务中心 `/count` 同源同数。

### 2.2 两种业务来源

| 入口 | 路由 | 页面行为 | 写动作门禁 |
|---|---|---|---|
| 直接委外 | `/subcontract/orders/new` | 直接录入委外件、委外商、币种、税率、结算方式、数量和价格；没有「内部生产入库仓库」字段；缺 BOM 的明细显示红色提示 | `subcontract_order:view + create`；提交财务另需 `subcontract_order:submit_finance` |
| 物料分析委外 | `/operations/workbench/subcontract` | 委外任务中心：申请分解、领料、进行中跟踪 | 路由守卫为任一持有 `subcontract_application:view` 或 `subcontract_order:view`；各分段按服务端能力显示 |
| 委外领料页 | `/operations/workbench/subcontract/draw-request?orderItemIds=a,b` | 批量领料(见 4.3) | 路由守卫 `subcontract_order:view`；提交由服务端 `subcontract_order:draw` 与对象范围裁决 |

直接委外入口保留在「委外订货与全链路」列表页；物料分析委外入口保留在「委外任务中心」。委外材料出仓的执行入口只在仓库管理 Hub(`/warehouse/subcontract-outbound`)；`subcontract_outbound:view` 单独授权也能进入仓库根页。

订货编辑页对商业快照的要求：币种必填；税率必须明确填写 `0–100`，`0` 表示明确零税率/免税，
不能用 `null` 让财务或后端猜测；结算方式必填。保存成功后才提交财务，提交失败时保留草稿并明确反馈。
提交财务时每个委外件都必须有可发外的直属物料，否则 409「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」，
同时把提交人加入研发任务的等待名单。

**直属物料齐套守卫(ADR-156)**：订货单的数量必须是现有直属物料够做的(本单来源申请的专属批次 + 公共可用库存，
已扣掉其它还在办的委外单要领的量；没有来源申请的手工单只能用公共库存)。服务端在下面五个动作核对，
不够就 409，逐种列出不够的物料：

| 动作 | 409 文案开头 | 文案末尾的下一步 |
|---|---|---|
| 新建(含从任务中心带单) | 直属物料还没齐套，不能生成委外订货单：「物料」本单需要 x，现在能用的只有 y… | 请按委外任务中心显示的「可下单」数量下单，其余等物料到了再下 |
| 编辑保存草稿 | …不能保存委外订货单：… | 同上 |
| 提交财务 | …不能提交财务：… | 物料可能已被别的委外单或生产先用掉；请委外人员把数量改成委外任务中心显示的「可下单」数量，或等物料到了再提交 |
| 财务批准(财务任务页) | …不能批准：… | 同上 |
| 批准后改量加量 | …不能加量：… | 同新建 |

文案中间说明已经扣掉其它还在办的委外单要领的量，以及「委外价格每天不一样，物料齐了才解锁下单」。
被拒时整笔不保存。删除草稿、批准后减量、红冲不核对；草稿、在审、财务退回的订货单都占着物料，
放弃的单要删除才释放。编辑页把服务端原文显示给用户，不自己判断物料够不够。

### 2.3 委外任务中心分段

分段：**草稿 / 待处理 / 领料 / 进行中 / 历史记录**。默认不选分段(内容区引导占位、不发请求)；
用户主动选择后才收窄。通知深链 `?segment=draw&orderItemId=` 或 `&orderId=` 直接打开「领料」并按该明细/订货单筛选，页头显示可清除的范围标签。

**待处理**：一行 = 一条仍有未下单量的委外申请明细，可跨申请勾选「生成委外订货单」。
缺 BOM 的申请行状态为「缺 BOM·已通知研发」(黄，等研发)，不可勾选；研发任务被取消而 BOM 仍缺时，
行上提供「通知研发完善」(`POST /api/subcontract/applications/items/{applicationItemId}/forward-bom`，沿用申请分解的权限)。

**物料齐套锁(ADR-156)**：申请行的状态列(服务端 `displayStage`)按下面顺序取第一个命中，可下单数量读服务端 `orderableQty`：

| 状态 | 判定 | 页面行为 |
|---|---|---|
| 缺 BOM·已通知研发 `BOM_MISSING` | 申请里有委外件没有可发外直属物料 | 不可勾选；不计入红数(见上) |
| 等物料齐套 `WAITING_KIT` | 还有未下单量，但每条明细可下单都是 0 | 不可勾选、不能生成订货单(服务端 `canCreateOrder` 为假)；**照样留在「待处理」并计入红数**——与以前的锁一样，只在行上显示锁住 |
| 可部分下单 `KIT_PARTIAL` | 至少一条明细可下单 > 0，但可下单合计小于未下单合计 | 可勾选；状态写「可部分下单·可下单 N {单位}」(N = 各明细可下单之和) |
| 待下单 | 可下单 = 未下单 | 照旧 |

- 可下单 = MIN(剩余未下单, 现有直属物料够做的套数)。现有物料 = 物料分析分给这张申请的专属批次 + 公共可用库存，
  扣掉所有还在办的委外订货单(草稿、在审、财务退回、已批准未结案)还要领的量。各行各自按当时的公共库存算，不互相扣。
- 「齐套情况」：行上入口，按申请明细打开只读弹窗(`GET /api/subcontract/applications/items/{applicationItemId}/kit`，
  权限 `subcontract_application:view`)。头部写剩余未下单、够做套数、可下单；表格逐种直属物料：
  物料名称 / 编号 / 颜色 / 单位 / 每套用量 / 需要(剩余未下单要用的量) / 专属库存 / 已被占用(别的还在办委外单要领走的量) /
  现在能用 / 还缺 / 够做套数。够做套数最小的物料就是卡住的那一种。缺 BOM 时不列物料。
- 生成委外订货单：勾选后进订货编辑页，分解预览(`POST /api/subcontract/applications/decomposition-preview`)
  每条明细返回 `kitQty`(够做套数)与 `orderableQty`(这次能下的数量)。所选申请按需求日期先后共用公共库存，
  需求日期早的先分，各自的专属批次只给自己；编辑页按 `orderableQty` 预填数量，为 0 的明细不预填。
  预填值可以改，改大(包括超过申请剩余量)由保存时的守卫核对。

**领料**：见第四节。

## 四、领料(ADR-143)

### 4.1 「领料」分段

一行 = 一条已获财务批准、领料计划未关闭、订货明细未结清(合格入库 + 已结损耗 < 订货量)、还没领满的委外订货明细(委外任务)。版式照「我的车间任务」，表格为 `MasterDataTableView`：

| 列 | 内容 |
|---|---|
| 状态 | 可领 N {单位}·去领料(蓝：可领 = 剩余全部；紫：部分可领) / 已提交领料·待仓库发料(青) / 等计划安排·缺 k 种(品红：还缺的物料没有在途供应) / 等待物料·已备 a/n 种(灰蓝)。优先级：可领 > 已提交 > 等计划安排 > 等待物料；可领与待发同时存在时悬浮提示两者 |
| 委外订货单号、委外商 | |
| 委外件名称、编号、颜色 | 货品身份三列各占一列 |
| 订货数量、单位 | |
| 已领 / 待仓库发 / 可领 / 还缺 | 行级显示量(订货单位)，恒等式 已领 + 待仓库发 + 可领 + 还缺 = 我方供料套数(接口 `materialQty`；财务批准的委外商自带料那部分不用我方物料，没有自带料时 = 订货数量，ADR-143 §三.4a) |
| 交期 | |

- 默认排序：状态优先级、交期、订货单号、行号。状态列表头筛选：可领 / 已提交领料·待仓库发料 / 等计划安排 / 等待物料，数字来自服务端 `statusCounts`。
- 只有服务端标记 `canDraw` 的行可勾选；勾选后表格浮动按钮「批量领料(n)」(只在 `capabilities.canSubmitDraw` 为真时出现)进入领料页。点状态里的「可领」直达领料页(只带这一行)。
- 分段计数只挂红数 = 可领行数(轮到委外动手，按调用者权限与订货单可见范围)；不挂黄数(等待物料 / 待仓库发的订货单已计入「进行中」黄数)。没有 `subcontract_order:draw` 的人可领数恒为 0；`/count` 返回无权限时整个「领料」分段隐藏。

### 4.2 任务详情

双击行打开任务详情：

- 物料表：物料名称 / 编号 / 颜色 / 单位 / 每套用量 / 需求 / 已发外 / 待仓库发 / 仓库可用 / 本次可领 / 还缺 / 供应来源 / 状态。
- 物料状态：已发齐 / 待仓库发 / 可领 / 还缺 / 已结束领料；某种物料自己已备齐、只是被别的物料卡住时显示「已备」。
- 供应来源列出还缺物料的在途：采购在途 x(单号) / 车间生产 x(工单) / 委外在途 x(订货单) / 未安排。委外在途按已审未关闭的委外订货单未合格入库量算(嵌套委外的直属物料从它的订货单财务批准起就算在途，回厂待检、待入库期间仍算)，所以这种行显示「等待物料」而不是「等计划安排」。
- 待发领料列表：领料单号、仓库、行数、提交时间、提交人。仓库已改过的领料(仓库保存过、某行数量已不等于提交量，或某行被仓库填 0 删掉；服务端 `pendingDrafts[].edited`)在单号后标红色「· 仓库已改过」，列表下方提示：这些领料委外这边不能撤回，这批不发了请联系仓库在拣货页点「退回委外(不发)」。
- 底部动作只由服务端 `allowedActions` 决定：
  - **撤回未发领料**(至少有一张没被仓库改过的待发领料时才出现)：确认框只列能撤回的领料；确认后撤回该明细未发出的领料，预留与专属归属原样退回，并通知仓库已撤回。仓库已保存过拣货修改的领料不能撤回(409「领料出仓单 X 仓库已开始拣货并修改过，这边不能撤回；请联系仓库在拣货页把这张领料退回」)。
  - **结束领料(不再发外)**(还有物料没发齐时)：必须填写原因(不超过 200 字)；撤回未发领料(仓库已改过的也一并强制撤回，仓库照常收到「委外领料已撤回」)、释放预留、关闭该明细的领料计划行，并重新评估短交。
- 详情里的「去领料」按钮直达领料页。

### 4.3 委外领料页

路由 `/operations/workbench/subcontract/draw-request?orderItemIds=...`，版式照车间「领料汇总」页(收起式页头、忙碌遮罩、浮动操作组)：

- 头部：N 个委外任务 · M 种物料 · 预计 K 张出仓单。
- 任务表：委外订货单号 / 委外商 / 委外件名称 / 编号 / 颜色 / 单位 / 订货数量 / 已领 / 可领 / **本批可领**(按「交期、订货单号、行号」联合分配共享物料后) / **本次领料数量**(输入，默认 = 本批可领，0 < x ≤ 本批可领，4 位小数；填 0 表示本次不领)。
- 物料表(服务端预览，改数量后 300 毫秒去抖重算)：领料仓库 / 物料名称 / 编号 / 颜色 / 单位 / 本次领料数量 / 仓库可用。
- 提交：服务端在锁内按同一顺序重算，实时可领低于提交量才 409，页面显示服务端说明并按实时本批可领重新填写；成功后每次提交按「订货单 × 仓库」新建委外材料出仓草稿(永不并入已有草稿)，每张草稿通知所在仓库。幂等键在结果未确认(网络、超时、服务器错误)时冻结复用，重复提交返回同一结果；领料页每次打开或重新加载、每次得到明确结果后都换新键，所以撤回后重新进页再提交一定是新的领料，不会被当成旧批次的重放。旧键重放到已撤回、已被仓库退回或已变化的领料时返回 409「这批领料已撤回或已变化，请重新打开领料页后再提交」。
- 预览整批 409(所选任务已领满、已结束领料等)时，页面只给「返回委外任务中心」(回去后清空选择并刷新)，不给「重新加载」；其它读取错误仍给「重新加载」。
- 一次最多 50 个委外任务。

### 4.5 订货单批准后改量(对齐销售 V482)

本节只适用于真正修改订货数量；接受损耗使用独立结清路径，不属于本节改量或复核流程。

- 入口：订货单详情「改量」(权限 `subcontract_order:change_qty`，默认不授；采购同构 `purchase_order:change_qty`)。仅财务批准且无待复核 case 时可用。
- 语义：改量**立即生效**并自动创建财务复核 case 重回审批队列。每条领料计划行按新订货量重算计划量；新数量不得低于各物料已发外与待发量反算的最小订货量、委外商处结存反算量和已回厂净量；已提交未发的领料必须先撤回，否则 409 列出这些领料单。加量要直属物料齐套(不够 409「直属物料还没齐套，不能加量…」，ADR-156)，减量不核对物料。事实账 `procurement_order_qty_change_logs`(以前→现在)在审批任务列表标注「改后待复核 · 改量 N 处」，审核详情展示修改清单。
- 复核通过 = 确认(不重复生效副作用)；驳回保留新数量，制单人可再次改量。

## 五、仓库发料与回厂来料质检

### 5.1 仓库发料

- 任务中心：`/warehouse/subcontract-outbound`；拣货页：`/warehouse/subcontract-outbound/:issueId`。
- 一行 = 一张委外人员已提交、仓库未发出的领料草稿(按调用者仓库范围)。仓库只能把某行改少(不超过提交的领料数量；某种物料这次不发填 0，保存时这一行从领料单删掉、提交量保留并列进「少发」)，不能改多、不能加行、不能删光全部物料行；改少立即释放多出的预留。核对实际仓与库位后审核出仓。
- 整张发不出时仓库在拣货页「退回委外(不发)」(必填原因)：作废这张草稿、释放占用，提交领料的委外人员收到「仓库退回了领料」，物料备齐后重新领料。
- 草稿只能由委外人员提交领料产生；不想再发外由委外人员在任务详情「结束领料」。
- 详见[仓库委外出仓工作台页](仓库委外出仓工作台页.md)。

### 5.2 回厂与来料质检

- 仓库从预计到货进入独立到货登记页，不经委外通用新建页。登记的是委外件 P。
- 可回厂量按委外商处能做成 P 的完整套数(逐种物料取短板)；直属物料还没发给委外商时不能登记回厂。来源 UUID 不一致或仓库事实缺失均失败关闭。
- 回厂超过可回厂套数的部分是委外商自带料：登记照收，审核时多出部分不入库、不立应付，转财务审核组确认价格和归属。
- 回厂审核进入来料质检隔离，并按财务批准的加工费快照形成立账事实；质检合格只生成仓库合格待入库，不写库存、不推进原生产供给；仓库以独立人员确认实际量与实际库位后才入库并推进，不重复立账。
- 质检不合格不进入可用库存，后续正式退回/贷项负责反向；不得直接修改回厂累计或用备注抹平。

### 5.3 V440 来料质检不合格退回与贷项专页

- 稳定列表：`/procurement/iqc-rejections`；详情：`/procurement/iqc-rejections/:id`。
- 仓库 Hub 与财务 Hub 均只在 `procurement_iqc_rejection:view` 下显示入口和进行中角标；通知深链进入同一详情，不另造通用单据页。
- 质检结果事务只写质量事实和通用业务 Outbox；异步消费者按稳定业务键幂等建案。异步失败不得回滚质量结论，case 进入 `FINANCE_EXCEPTION` 并通过受控恢复继续。
- 公开业务状态严格为六个：`PENDING_RETURN`、`RETURN_RECORDED`、`CREDIT_CONFIRMED`、`CLOSED_NO_CREDIT`、`FINANCE_EXCEPTION`、`REVERSED`；贷项建立和专用抵销在单一事务内完成，不持久化或展示第七个过渡状态。
- 结构化动作：登记失败实物退回、确认供应商贷项、仅对冻结失败金额严格为 0 的 case 无贷项结案、按当前状态受控反向；`FINANCE_EXCEPTION` 可在服务端允许时重试财务投影。所有命令携带 `expectedVersion + commandId`。
- 登记实物退回必须提交退回单号、日期、经办人与事件 UUID；它不走合格普通退货、不增加普通 `returned_qty`、不直接生成贷项。返修/补做通过 replacement allocation 释放合法回厂容量，不重复领料发外，也不重复消耗委外直属物料。
- 确认贷项按冻结失败全量生成负应付；只抵销来源应付当前正余额与失败金额的较小值，剩余负应付作为开放供应商贷项保留。非零金额不能 `CLOSED_NO_CREDIT`，零金额不能生成 0 元应付。
- 待检/部分检验和未完成拒收闭环的来源应付必须暂停付款、普通抵销与月结，直到 `CREDIT_CONFIRMED` 或 `CLOSED_NO_CREDIT`；页面不得以可操作按钮暗示绕过后端 hold。
- view-only、record-return 与 `view_all` 都不自动获得金额；金额只认 `procurement_iqc_rejection:amount:view`，且服务端 `priceMasked=true` 时 Flutter 必须显示 `***`，财务动作权限也不能解密。
- 对象池：普通 `view` 只看本人归属；`view_all` 跨归属；`record_return` 是明确的跨归属实物退回执行池；confirm-credit、close-no-credit、reverse 是财务全局动作池，但所有页面/命令仍先要求 `view`。
- V440 是采购与委外共用的来料质检拒收闭环，不得拿材料超耗 `subcontract_loss_claim` 冒充。
- **列表表头筛选**：状态/单据类型(收货类型)两列可从列头下拉筛选，与工具条下拉同源同参数(`status` / `receiptType`)，选中后重拉回第 1 页。
- **金额币种(ADR-128)**：原币金额(不合格原币金额、贷项凭证原币、确认贷项弹窗的冻结金额与分项合计)写成「币种 金额」，币种用服务端随案件下发的 `currencyName`(主档名称，缺名称退回可读代码)；本币金额(列表「不合格金额(本币)」、紧凑卡片「本币金额」、替换收货分配)只写金额、不挂单据币种。金额显示统一用 `money_display.dart` 的共用函数。

`subcontract_outbound:handle`、`finance_order_approval:review` 和 `subcontract_application:edit` 是停用复合权限，不能恢复为替代门禁。

### 6.1 对象范围

- 普通委外单据默认按稳定 `maker_id`/服务端归属投影可见；跨制单人查看使用 `subcontract:view:all`。
- `subcontract:view:all` 只扩大委外对象阅读范围，不授价格、创建、审核、红冲、领料、出仓或财务决定。
- 财务审核员对关联订单只有审核任务所需的只读视角；`finance_order_approval:view` 不能授予委外编辑。
- 领料列表、任务详情、预览与提交按订货单经手人可见规则投影；知道 `orderItemId`、`issueId` 或订单 UUID 不构成授权。
- 超级管理员固有权限由服务端决定；前端不得通过「isSuperAdmin 就显示动作」绕过停用权限与 `allowedActions`。
- 价格字段服务端仍以 `priceMasked` 作最终权威。Flutter 本地 permission 只决定是否渲染，不能解密服务端已脱敏数据。
- V440 是明确例外：`record_return` 跨归属形成仓库/退回执行队列；`confirm_credit`、`close_no_credit`、`reverse` 跨归属形成财务动作池。它们扩大的是各自动作任务池，不授页面阅读或金额；访问页面仍先认 `view`，金额仍只认 `amount:view`。

## 七、通知页与顶部通知栈必须绑定

委外业务事务通过 Outbox 产生通知事实，`ChainNoticeService` 幂等写入通知页记录。凡是业务上
「有通知」，必须同时满足：

1. 有权接收且持 `notice:read` 的用户能在通知页看到记录；
2. 同一未读到达事件同时投影到顶部非阻塞通知栈；
3. 新通知在旧通知上方，支持叠放、展开和逐条关闭，不阻塞正在进行的仓库/生产操作；
4. 顶部关闭只表示本设备已展示，不等于通知已读、审批完成、库存过账或业务结案；
5. 点击主动作才按既有规则标记已读并进入稳定深链；深链再次执行页面权限与对象门禁。

主要通知与动作入口：

| 事件 | 收件人 | 稳定入口 |
|---|---|---|
| 委外可下单(`SUBCONTRACT_ORDER_KIT_READY`，委外申请可下单量增加，ADR-156) | 采购委外部门(`SUB_PURCHASE` 及下级)里同时持有 `notice:read`、`subcontract_application:view`、`subcontract_order:decompose` 的在职账号 | 任务中心「待处理」并按申请单号搜索 `/operations/workbench/subcontract?segment=pending&keyword={申请单号}`(重要级行动卡「委外可下单：{申请单号} {委外件} 可下单 N {单位}」；每个申请明细一张，可下单比上次提醒时多才重新提醒，变少不打扰，降到 0 撤卡；数字以任务中心实时计算为准) |
| 委外可领料(可领量增加) | 订货单可见范围内持有 `subcontract_order:draw` 的人 | 任务中心「领料」并按该明细筛选(行动卡；每个明细一张，按最新可领量更新；可领为 0、提交领料、结束领料、红冲时消除) |
| 委外领料待发料(提交领料) | 草稿所在仓库的仓管(持 `subcontract_outbound:view + execute`) | `/warehouse/subcontract-outbound/:issueId`(行动卡；撤回时改为「委外领料已撤回」，整张撤回时链接待发料列表 `/warehouse/subcontract-outbound`；点进已撤回的领料显示「无需拣货」) |
| 仓库退回了领料(`SUBCONTRACT_DRAW_RETURNED`，仓库「退回委外(不发)」) | 提交这张领料的委外人员 | 任务中心「领料」(只涉及一个订货明细时按它筛选)；正文写明仓库、领料出仓单号、物料没有发出、占用已释放和退回原因，请物料备齐后重新领料；同时撤掉仓库的待发料卡。进入委外任务中心即把这条通知置为已读 |
| 委外直属物料已发出(发料审核) | 订货单经手人 + 持领料权限的人 | 订货进度(「本次发出后累计已发齐 X {单位}，可通知委外商加工」；少发时追加「少发：B 20(下次领料自动补齐)」) |
| 撤销发出(发料红冲) | 同上(加急) | 订货进度(按物料列出撤销数量) |
| 委外件缺 BOM | 工程研发部持研发任务查看权的人 | `/rd-tasks`(「请完善 BOM：……是委外件，还没有维护直属物料，计划和委外都在等」) |
| BOM 已完善 | 研发任务等待名单里的计划员 / 委外人员 | 被挡住的物料分析 / 委外订货单 / 委外任务中心 / 生产计划(等物料分析的人在这张分析按新 BOM 自动刷新完后才收到「物料分析已自动更新，可以下达」，不能自动刷新时收到「打开物料分析刷新后即可下达」；其余人立即收到「可以继续下达 / 下委外单」) |
| 批准后改量 → 复核 case 开立 | 财务审核池(同订货审批) | `/finance/procurement-approvals`(行动卡) |
| 临近/超过交期且委外商处仍有未回厂套数 | 委外制单人；有来源时原分析制单人 | 订货全链进度 |
| 回厂登记 / 来料质检待检 | 品质、委外制单人 | 品质任务 / 订货进度 |
| 来料质检不合格形成退回/贷项任务 | 订单负责人、持 V440 对应权限的仓库/财务人员 | `/procurement/iqc-rejections/:id`(行动卡) |
| 来料质检拒收退回、贷项、零金额结案、财务异常或反向 | 按阶段责任人及订单归属人 | V440 详情页；通知不携带冻结金额 |
| 来料质检合格 / 其它品质结案 | 仓库、委外制单人、分析来源负责人 | 合格放行 / 订货结案 |
| 材料损耗产生超耗责任 case | 持 `subcontract_loss_claim:view/review` 的合格财务人员；订单归属人收业务回执 | 财务 `/finance/payables` / 订单 `/subcontract/orders/:id` |
| 超耗责任决定、履约、反向 | 按阶段持 `subcontract_loss_claim:view/fulfill/reverse` 的财务人员；订单归属人 | 财务 `/finance/payables` / 订单全链进度 |

超耗责任通知由业务事务写 Outbox 并使用稳定业务键幂等发布；通知标题/正文不携带建议索赔额、
实际索赔额、抵销额或到账金额。金额只能在通过对应商业/财务权限和对象门禁的页面读取。
V440 建案、实物退回、贷项确认、零金额结案、财务异常和反向同样遵守该规则：每条有权可见的
通知页记录必须绑定同一顶部到达事件，不能只写通知页或只弹顶部；`notice:read`、阶段动作权限与
来料质检拒收对象范围共同解析收件人，通知正文和顶部摘要均不得泄露冻结金额。

## 八、响应式、空错、刷新与并发

### 8.1 响应式与可访问性

- compact `<600dp`：申请分解与领料使用单列任务卡；核心事实优先，次要字段折叠；操作区域至少 48dp。
- medium `600–840dp`：筛选纵向收敛，列表/表格按可用父容器宽度布局。
- expanded `>840dp`：高密度业务表、服务端分页和按行上下文动作；禁止无对象的「开始第一条待办」。
- 图标不能单独承担状态含义；状态同时有文本。支持暗色主题、系统文字缩放、键盘焦点和语义标签。
- 每页只有一个主动作；无动作权限时整项不渲染，不能用 disabled 按钮泄露写能力。权限齐全但服务端状态/capability 阻断时，才显示禁用原因。
- 领料页弹出确认或错误提示前先收起忙碌遮罩，遮罩不能盖住后弹的对话框。

### 8.2 加载、空态与错误

| 状态 | 页面要求 |
|---|---|
| 首次加载 | 保留页面骨架并显示语义化进度，不显示空白成功页 |
| 刷新中 | 禁止重复写动作；旧数据可保留但必须显示刷新状态 |
| 空态 | 说明「当前筛选无数据」还是「业务尚未产生」，并给合法下一步；无权限不能伪装成空数据 |
| 读取错误 | 显示业务化错误和「重试」，不把 Dio/SQL/堆栈文本直接交给员工 |
| 权限不足 | 路由失败关闭；Hub 卡/写动作隐藏；受控说明页只提供合法替代入口 |
| 关联对象受限 | 显示「无权查看关联单据」，不泄露单号、价格、人员或 UUID |

### 8.3 刷新与并发

- 搜索、防抖和翻页使用请求序号，只允许最新响应回写；切换筛选时清理跨页选择。
- 分解提交前服务端重验申请状态、剩余量、来源 UUID、对象范围和 capability；待财务订单继续占用来源容量。
- 直属物料齐套守卫(ADR-156)按物料加事务级咨询锁，两人同时下单时串行判定，后到的按扣掉前一张后的物料核对；任务中心的「可下单」是打开时的实时值，提交时以服务端核对为准。
- 领料提交使用幂等键并在锁内重算可领量；撤回在锁内重验草稿是否已被仓库修改(改过的拒绝)，结束领料强制撤回；仓库「退回委外(不发)」按同一锁顺序再锁草稿头与计划行；仓库拣货保存、预留、审核和红冲均需 CAS/幂等与数量守恒。
- 列表返回、页面恢复和网络恢复需刷新当前页；通知不能代替刷新后的任务事实。
- 并发冲突显示明确恢复路径：刷新、重新预览或打开最新任务；不得静默覆盖他人操作。

## 十、计划委外申请页

- 生产侧生成的申请恒为已审(status=1)；申请页进入即默认「计划已下达」，没有「尚未下达」段。
- 委外件点「下达委外」后立即生成委外申请(缺 BOM 的委外件不能下达)；「计划已下达」计数 = 已审申请数。
- 后续：双击申请行进详情 →「生成委外订货单」→ 提交财务审核 → 财务任务中心通过 → 任务中心「领料」。生成订货单同样受直属物料齐套约束(ADR-156)，预填按这次能下的数量。
