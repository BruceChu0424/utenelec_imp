# 230 · V645 追加自制并入未开工的生产计划(ADR-104)

- 迁移：`V645__material_analysis_plan_growth_in_place.sql`
- 类型：前向，新增四个判定函数 + 一条提交时对账触发器，锚点补丁三个身份守卫。**不加表、不加列、不改历史行、不 DROP 任何触发器。**
- 口径来源：2026-09-22 用户口径「物料分析准备页面追加的自制件，生产车间没有去领料开工的前提下应该自动合并，不要每追加一次就单独列一张；采购那边已经会自动加到一个单子，因为之前的单子没有去执行；如果已经开始执行了就创建新的单据；生产件一样的就放到一起去、或者一个计划单」。
- 决策：[ADR-104 追加自制并入未开工的生产计划](../99-决策记录-ADR/ADR-104-追加自制并入未开工的生产计划.md)。
- 编号：V643 留给并行会话(未用)，本迁移 595→596。

## 为什么要有它

采购/委外自 V640 起「未订货的申请明细就地追加」；自制这边每追加一次都 `createDraftPlan` 新建一张生产计划，五道库侧守卫把已建计划的数量钉死：计划明细 qty 不可变(V234/V614)、计划关联行 submitted_qty / public_surplus_qty 不可变(V490/V577)、一张计划一条关联行(V234)、预排草案载荷不可变(V191)、执行段 planned_qty 不可变(V155/V524)。要让追加并进原计划，必须先在库侧定义「什么叫还没开工」，再只对这种计划放开只增不减的改量。

执行段本身**不改量**：追加量在同一个 CONFIRMED 计划包里另起一段(与拆批同形态)，原执行段、冻结的物料需求、预留与备料单一字不动——它们是已冻结的执行事实，与 V640 不碰「待财务审核的草稿订货单」同一条纪律。

## 改了什么

| 对象 | 变化 |
| --- | --- |
| `fn_material_analysis_plan_growable(plan)` | 新增。物料分析生成的计划是否仍未开工：未删除/未取消/未中止/未结案、草稿或已审核、恰一条计划明细且完工/入库/封顶累计全 0、没有报工、没有拆批、每一段仍是 WAITING/READY、每张备料单(DRAW)仍是未审核、未发料、未删除的草稿；已审核时必须有且只有一个 CONFIRMED(执行模型 1)计划包。判据与 `ProductionPlanningPackageService.closeExecutionSegments / closeDraw` 撤销计划包同源 |
| `fn_is_material_analysis_plan_item_growth(item, before, after, oldCap, newCap)` | 新增。计划明细的这次 UPDATE 是否就是并入追加：只增不减、封顶量不动、计划仍未开工 |
| `fn_is_material_analysis_plan_link_growth(plan, oldStatus, newStatus, oldSubmitted, newSubmitted, oldSurplus, newSurplus)` | 新增。关联行的这次 UPDATE 是否就是并入追加：状态不变(SUBMITTED/APPROVED)、归需求量与公共备货量都只增不减且至少一个真的变大、计划仍未开工、计划明细已先改到「归需求 + 公共」之和 |
| `fn_is_material_analysis_plan_item_supply_growth(table, old, new)` | 新增。被生产供给钉住(V162/V503)的计划明细只动 qty(与审计列)、只增不减、计划仍未开工 |
| `fn_guard_material_analysis_plan_item_identity()` | 锚点补丁(V614 版)：qty 改量除日报定稿封顶外，再放行「并入追加」 |
| `fn_sync_material_analysis_plan_link_qty()` | 锚点补丁(V577 版)：submitted_qty / public_surplus_qty 在「并入追加」时放行；UPDATE 分支原本就按 OLD/NEW 差额回写分析行的 submitted_qty / approved_qty 并推进分析版本与指纹，这里只放开身份断言 |
| `fn_guard_production_supply_source_item()` | 锚点补丁(V640 版)：被钉住的计划明细在「并入追加」时放行 qty 只增(与 V640 的 `fn_is_preplan_supply_line_growth` 并列) |
| `fn_check_material_analysis_plan_item_link_qty()` + `trg_check_material_analysis_plan_item_link_qty` | 新增 DEFERRABLE INITIALLY DEFERRED 对账：计划明细 qty 改量后，提交时核对 `qty + capped_qty = 关联行 submitted_qty + public_surplus_qty`(原本只在关联行 INSERT 时检查；日报定稿封顶 qty+capped 守恒、并入追加两边同增，两条路都满足) |

补丁方式沿用 V580/V588/V589/V640 纪律：`pg_get_functiondef` 取定义、行尾归一 LF、锚点必须恰好命中一处，否则 23514 失败宁可不迁。

## 应用侧(同批，非本迁移)

- `MaterialAnalysisCommandService.issueWorkshopPlansInternal`：每一行先查 `growablePlanFor`(同一分析行最近一张 `fn_material_analysis_plan_growable` 的计划；请求指定了生产车间时车间必须一致；没带「立即审核」的请求只并入草稿计划)，命中就 `growPlan`：计划明细与关联行只增不减地改大 → 草稿计划重排预排草案(带审核时整张审核)；已审核计划先 `ProductionPlanService.growAnalysisPlanSalesAllocation` 扩大订单侧分摊(只加归需求份)，再 `ProductionExecutionPackageCommandService.appendSegment` 在同一个计划包里另起一段(WAITING 或无料 READY，自带冻结需求与耗用规则，销售分摊只切归需求份)。没命中照旧新建。
- `GeneratedPlan` 新增 `mergedIntoExisting` / `appendedQty`；命令回放记录 `mergedPlanIds`。
- 客户端：结果弹层与提示区分「已并入原生产计划」与「已生成」；主表分段回报写明「其中 N 张并入原计划」。

## 兼容与影响

- 存量计划全部保持原样：只有此后发生的并入追加会改写这三类数量，且只增不减；开工了(有段离开 WAITING/READY、备料单已审核或发料、有报工、有拆批)的计划照旧另立新单。
- 关联行仍是一张计划一条(UNIQUE(plan_id))，`issuedPlanQty = submitted + approved + Σ public_surplus` 口径不变，主表与级联页读数不用改。
- CLEAR 目录不新增业务表，`reset_business_data.sql` 白名单登记 `(645, 596)`。
