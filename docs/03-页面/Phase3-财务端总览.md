## 三、销售出货、应收与收款联动

财务需要区分三个不同事实，不能把“订单待收”“出货放行”和“正式应收”混成一个状态：

| 节点 | 财务动作 | 金额与汇率 | 结果 |
|---|---|---|---|
| 销售订单审核 | 查看销售订单待收计划 | 只按订单币种看原币，不读取汇率 | 经营预测；不写 AR、不写总账 |
| 现金客户出货草稿 | 在仓库开始拣货前审核是否放行 | 不填汇率 | 只记录放行事实；不自动生成收款、库存或 AR |
| 仓库 `SHIPPED` | 无逐单手填动作；系统读取财务维护的有效开账汇率 | 本次发运原币 × 开账汇率 | 同事务扣库存、回写订单并建立正式 AR；失败全部回滚 |
| 销售收款草稿 | 引用同客户、同应收/核销原币的未结 AR；选择直收或外贸代理结汇 | 填原币毛额、汇率方向/来源/时间、银行入账、真实账户金额、扣费或另付；有费用明确本公司承担 | 服务端重算本位币毛额/账户入账/费用/账面冲减/汇兑；客户/代理承担须另立应收/索赔；V1 writeOff=0 |
| 销售收款审核 | 由非制单人复核 | 不接受客户端派生本位币结果 | 同事务核销 AR、更新真实账户、追加 POSTING 流水并生成该单 RECEIPT AUTO 凭证；deferred 终态守卫确认单头/流水一致，失败整笔回滚 |
| 总账 | 收款审核实时过不可变单张凭证；按期间作业不再删除/重建 V1 收款 | 读取已冻结的开账/到账金额与科目 UUID | 原 `RECEIPT` 保留，红冲在当前业务月追加 `RECEIPT_REV`；原凭证必须等于冻结期望分录多重集；销售立账和成本仍可重建 |

费用承担方稳定字段为 `feeBearer`：无费用传 `NONE`，有费用只允许 `COMPANY`。审核/红冲后页面与验收应同时以
`v_receipt_flow_integrity.is_consistent=true` 和 `v_receipt_gl_integrity.is_consistent=true` 为完整性证据；异常进入对账清单，不能自动补流水、凭证或改历史金额。

正式 AR 在 `SHIPPED` 立即形成，销售立账/成本仍按期间投影；V407 收款审核已实时生成该单收款凭证。同一 AR
可分批多次到账，每批原币毛额、实际汇率、费用、真实账户入账和前后余额独立冻结。外贸代理已结汇并进入
CNY 账户属于现有 V1 路径，代理在途/多客户结汇批次仍未交付。完整决策和数字公式见
[ADR-053](../99-决策记录-ADR/ADR-053-多币种收款毛额净额与追加式账户流水.md)及
[ADR-030](../99-决策记录-ADR/ADR-030-销售待收计划与正式应收分层.md)，销售/仓库岗位步骤见
[销售全链 SOP](../07-业务链路/01-销售订货到发货全链路-SOP.md)。

### 3.1 客户预收与预收转销

- 销售端不录入定金或预收；sales_orders.deposit 仅为老库历史快照。
- 财务收款单显式选择 AR_SETTLEMENT 或 CUSTOMER_PREPAYMENT。客户预收可选绑定活动已审订单且不允许普通
  AR 核销行；V0 预收不允许费用，V1 可按与普通收款相同的扣除/另付费用模型登记。
- 普通收款按不可变 SALES_ORDER 来源 FIFO 分配；预收转销精确绑定同客户、同币种、同订单正式 AR，
  保存双币和汇兑快照，反转遵循后进先出。
- 客户预收列表、订单资金汇总和转销详情要求 customer_prepayment:view + finance:view:all；应用/反转
  再分别要求 customer_prepayment:apply/reverse。退款仍为 **NO-GO**。
- 币种展示以主档名称为用户口径；旧 `001/002/003` 作为业务编号在 API/持久化中保留，但不面向用户
  展示，也不作为金额前缀。订单资金卡的币种在订单信息区独立显示，各资金指标只显示金额。
- 同一客户预收列表可能跨币种：逐行展示币种名称；检测到多个币种或分页结果未完整加载时，顶部累计
  统一切换为本币口径，禁止跨币种原币直接相加。

### 3.2 V408–V417 账户流水、付款并发与性能边界

- 流水显示 `POSTING/REVERSAL/ADJUSTMENT` 和原流水引用；红冲追加镜像行，不删除原记录。
- 账户流水列表/API 同时要求 `account:view + account:balance:view + account:flow:view`；旧广授的 `finance_reconciliation:view` 不能替代，金额保护由服务端完成。
- `v_account_balance_integrity` 对比账户缓存与原币流水重建余额；它不是银行对账单。
- 完整上海月份使用可重建 `account_flow_monthly_summaries`，起始月只扫原始尾段；`v_account_flow_monthly_integrity` 与原账逐月核对。
- V416 提供 V0 收款、V0 GL 和旧账户流水三类只读异常队列；新收款/流水还受外部证据、maker-checker、来源 UUID 和本位币快照数据库守卫。异常只显示并要求签收，不自动改历史。
- V417 付款新建使用制单人范围幂等键/哈希，草稿更新使用 `expectedVersion`；同键异内容和陈旧页面均 409。页面金额以四位、汇率以六位十进制字符串提交。
- 当前 V419/381 PostgreSQL 16.15 空库中，财务 25 万条、5 账户、50 年测试 6/6，两组 Index Only Scan、无原流水 Seq Scan，Execution Time 1.059 ms、Java/JDBC 墙钟 20 ms，三类规模样本差异/异常均为 0。它只证明财务对 V418/V419 结构兼容；当前仍为 OFFSET/窗口查询，目标库深页/大区间容量必须另测。
- V407/V408 财务 PostgreSQL 7/7 继续覆盖收款核心；本轮财务后端定向 74/74、付款 PostgreSQL 5/5、财务 Flutter 29/29、完整 analyze 0 issue。当前稳定工作树完整 Maven 2,511 项 0 failure/0 error、完整 Flutter 1,137/1,137；尚未形成受保护签名 lineage，目标库/UAT 仍独立验收。
- 银行转账页当前只应提交同一启用本位币账户；外币/跨币种审核应显示“需双边币种、汇率和本币快照”错误。付款单空明细审核应显示“供应商预付资产/应用/退款链未完成”，两类都不得改余额/流水/GL。
- V416 队列已交付但历史 V0 有费语义尚未签收；退款、超收/未分配、多客户代理在途、typed 折让/坏账、外币退货、通用关账、非收款 GL 追加反向、供应商预付链、外币/跨币转账双边快照、余额调整 maker-checker、银行对账导入/匹配和交易日开账率权威仍为 **NO-GO**。V417 空库通过不改变这些业务/上线门禁。

- 客户预收事件报表提供 /api/finance/reports/customer-prepayment/events 与
  /api/finance/reports/statement/customer-prepayments 两个同源端点，覆盖到账/红冲/转销/反转；
  AR 汇总不把预收到账当正式应收回款，只在预收转销时冲减 AR。

## 五、资产与待摊专业子账

- 页面不是旧的固定资产/待摊双 Tab CRUD，而是概览、固定资产、长期待摊、月结过账四区；
- 主档和月度批次动作取“本地权限 ∩ 服务端 `allowedActions`”，本人不得自审或执行本人发起的最终过账；
- 月度流程为预览 → 提交 → 他人审批 → 过账；错误创建正常反向批次，保留原批次、原日志和原凭证；
- `UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED=false` 时，激活/初始确认、处置批准和提前终止批准
  在服务端 fail-closed；补齐类别或科目不能解除该门禁；
- 当前允许在非生产/UAT 准备类别、草稿、提交和他人审批/驳回，并用隔离数据验证月度引擎；不得录入
  真实资产后绕过门禁，也不得把正常月度反冲描述成资本化/处置/终止事件反冲。

## 六、当前审批流

- 报销：`DRAFT → SUBMITTED → APPROVED/REJECTED → PAID`。当前是单阶段审批；付款在同一事务内扣减账户并生成费用、对账和总账记录。页面时间线由报销单时间字段合成，没有通用 `ApprovalRecord`。
- 工资：`DRAFT → SUBMITTED → APPROVED/REJECTED → PUBLISHED`。工资条在草稿创建时生成，发布后才对员工可见；驳回为终态。
- 两类状态变更均使用后端行锁，但仍须验证真实数据库并发和权限矩阵。详见 [全局机制 §3.3](../05-架构/全局机制.md#33-报销审批流expenseclaim) 与 [§3.4](../05-架构/全局机制.md#34-工资条审批流payrollslip--payrollbatch)。
