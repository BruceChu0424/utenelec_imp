# 三架构缺口功能 · 适老化（傻瓜式）UX 规范

> 适用：销售退货客户处置（V220）/ 委外发料审核解禁（V221）/ 采购委外收货待检 IQC（V222）
> 原则：操作人员年龄偏大、学习能力差——**字号大、按钮大、一页一事、大白话、默认值先行、危险二次确认、错误给"下一步"而非错误码**。
> 后端已就绪（本规范只约束前端，确保傻瓜式）。技术词（disposition / inspection_status / supplier_ending 等）一律不出现在界面。

---

## 通用适老化基线（所有页面遵守）

- **字号**：正文 ≥ 18px，标题 ≥ 22px，数字/金额 ≥ 24px。
- **按钮**：主操作按钮高 ≥ 56px、宽通栏或居中大色块；次操作 ≥ 48px。点按区不留小于 48×48 的死角。
- **一页一事**：每个页面只让老人做一个决定；不并排多个表单。
- **大白话**：用"退货怎么处理""这批货合格吗"，不用"处置""质检结论""放行"。
- **默认值先行**：能默认的绝不让人填（见 IQC 全量合格、发料自动带 BOM）。
- **危险/不可逆操作二次确认**：弹"确定吗？这一步做完不能直接撤回"，并写清影响。
- **错误信息给下一步**：例如"这张发料单还没选对应的委外订货单，请先点这里选择"，而非"VALIDATION_FAILED"。
- **状态永远可见**：用颜色徽标（黄=待处理、绿=已完成、灰=已关闭）+ 一句话状态。

## 一、销售退货客户处置（退款结案 / 换货 / 补发 / 维修返还）

**触发**：退货单已审核且未决定处理方式时，退货详情页顶部显示醒目黄条：「⚠ 这批退货还没决定怎么处理」，加一个通栏大按钮「👉 选择处理方式」。

**选择页（一页一事）**：四张大卡片纵向排列，每张 = 一个选项 + 一句白话影响：

| 卡片 | 一句话说明（直接写在卡片上） |
|---|---|
| 💰 退款结案 | 钱退给客户，**不再补货**。应收就此了结。 |
| 🔄 换货 | 给客户**重新发同款货**（按当前库存预留）。 |
| 📦 补发 | 货没收到/坏了，给客户**重新发一批**（按当前库存预留）。 |
| 🛠 维修后返还 | 把退回来的货**修好再寄回**给客户（不补新品）。 |

- 点一张卡片 → 卡片展开一个「原因（必填，≥5字）」+ 通栏「确定」按钮。
- 「确定」前弹二次确认：「确定选【补发】吗？选择后不能直接撤销，需要走审批更正。」
- 确认后结果页：「✅ 已记录：补发。仓库会重新发货给客户。」+「返回」。

**防错**：选项一旦确认不可在线改判（须走受控补偿）；二次确认 + 影响预览是关键防线。换货/补发若库存不足，提示「库存不够全部预留，已预留 X 件，剩余 Y 件需要排产，请告诉生产主管」。

## 二、采购 / 委外收货待检（IQC）

**入口**：仓库菜单新增「待检入库」，带红色数字徽标（= 待检条数）。

**列表页**：每条待检 = 一张大卡片：
```
【货品名 + 规格】            收货 100 件
来源：采购收货单 RC-20260806-001    仓库：主仓    2026-08-06
[ ✅ 全部合格 ]   [ ❌ 全部不合格 ]
```
- 「全部合格」：不要求填数量（后端 baseQty 可空=全量）→ 弹「确认这 100 件都合格？合格后进入可用库存并通知生产。」→ 确认即放行。
- 「全部不合格」：必填原因（坏在哪）→ 标记不合格，不入库，提示「请通知采购联系供应商退货/索赔」。
- **部分合格**（高级，可折叠）：点"部分合格"才出现数量输入，默认填=收货数，老人一般用不到。
- 已处理的卡片变灰 + 显示「✅ 已合格 100」或「❌ 不合格 20」。

**关键**：一键"全部合格/全部不合格"，不让人填数量；填数量的高级入口默认折叠。

## 三、委外发料审核（409 门禁已解除）

**编辑页**：发料明细**自动从委外订货单带入**（货品、数量、单位、父件、关联订货行），老人不手填 BOM、不手挑子件。
- 若没带出关联订货：顶部黄条「这批发料还没指定是给哪张委外订货单的，请先选择」+ 一个「选择委外订货单」大按钮（引导，不是报错）。

**审核**：底部通栏「审核出库」大按钮 → 系统自动冻结 BOM + 建台账 + 出库 → 成功提示「✅ 已出库 100 件给该委外商」。
- 出库时库存不足：提示「主仓这种料只剩 X 件，不够发 Y 件。请先补货或改数量。」（不报错码）

**回厂后的守恒**（对老人透明，但要让主管看得见）：发料单详情显示「供应商处结存：70 件」（=supplier_ending，白话化），回厂进仓时系统自动按 BOM 扣减；若回厂超过供应商处结存（超耗/错料），系统拒绝并提示「回厂数量超过供应商手里的料，可能超耗或发错料，请人工核对」。

---

## 给前端的一句话总结

> 三个功能都用「大卡片 + 一个主操作 + 白话影响 + 二次确认 + 默认值」的同一套模板；后端 API 已支持傻瓜式调用（IQC 合格/不合格可不传数量、发料自动带 BOM、退货处置四选一）。**任何界面文案都不要出现英文技术词。**
