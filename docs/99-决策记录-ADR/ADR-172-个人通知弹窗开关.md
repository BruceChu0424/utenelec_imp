# ADR-172：个人通知弹窗开关

- 日期：2026-10-09（原号 171——与并行会话的委外任务中心 ADR 撞号后改号）。
- 状态：用户授权实施；源码及本地回归不代表公司服务器已部署。
- 遵循 ADR-063（弹窗口径）与 ADR-052（三事实模型：关闭弹窗≠已读≠业务完成）。

## 1. 背景与需求

用户要求（2026-10-09）：工作台右上角加「通知设置」入口，点击弹出对话框，列出**本人当前
会收到的通知弹窗类别**，可逐类关闭；关闭后不再收到该类弹窗。

此前弹窗没有任何个人层面的静音手段：用户只能逐条 X 关闭（下次登录仍弹）或稍后 15 分钟。
对不负责某类任务却因职能权限在池内的人（如主管兜底接收），缺少「这活不归我盯」的个人开关。

## 2. 决策

**新增个人维度的弹窗开关表 `notice_popup_preferences(user_id, source_event)`（V833）：
存在行=已关闭该类弹窗。只抑制「弹窗」一层，不改任何业务与通知事实。**

1. **可见列表 = 全目录 + 适用标志**（2026-10-09 用户修订口径：设置放**通知页**，那里设置
   全部通知类型；「我会收到的弹窗」由资格决定，不由列表决定）：`GET /notices/popup-preferences`
   返回 `ReviewNoticeCatalog` 全部事件，每项带中文名（`ReviewNoticeCatalog.labelOf`，单一事实源，
   键集一致性由 `ReviewNoticeCatalogLabelContractTest` 锁定）、`applicable`（= 当前弹卡资格
   `eligibleEvents`，**超管按真实授出权限判定**——读侧与发送侧同口径，2026-10-09 读侧补齐：
   `ReviewNoticeAudience` 注入 `PermissionResolver.grantedPermsOf(userId)`，超管镜像不再放大
   资格面，否则超管会被列成全事件）与 `popupDisabled`。前端分「我会收到的弹窗」（可开关）与
   「其它类别（当前岗位不会收到）」（仅浏览不可关）两组；资格变化后条目自动挪组。
   入口在**通知页筛选行左侧**调节图标（工作台右上角入口按用户口径移除）。
2. **写入**：`POST /notices/popup-preferences/{sourceEvent}` `{disabled}`；只接受审核目录注册
   事件（未知事件 400）。关闭=存在行（幂等），开启=删行。均要求 `notice:read`。
3. **抑制点（读侧，两处）**：
   - `pendingReviews()`（登录检查门）：个人关闭的事件从查询事件集中剔除；
   - `arrivals()`（20 秒到达轮询 feed）：个人关闭的事件整条不出现在到达流——顶部条与
     居中弹卡都不再出现。
4. **明确不变的层**（个人静音≠业务事实消失，ADR-052 口径）：
   - 通知仍正常落库、通知中心列表与未读徽章照常；
   - 办结撤回、V825 补发、(订单,收件人,版本) 去重、已读/稍后语义全部不变；
   - 部门共享任务卡的**其他人照常收到**——这是个人偏好，不是任务改派；
   - 人事打卡（acknowledge，强制动作）与运维/账号安全告警（面向超管本身）**不开放关闭**。
5. 前端：工作台首页右上角图标入口（持有 `notice:read` 可见）→ 居中对话框
   （`notice_popup_settings_dialog.dart`）：类别行+开关即时保存（每行独立 busy、失败回滚
   并提示重试）、空态说明、关闭按钮；遵循既有组件与无障碍规范（开关带 Semantics、
   图标按钮带 tooltip、48dp 触达）。
6. 数据治理：`notice_popup_preferences` 为账号配置，清空业务数据时 PRESERVE
   （与 `user_preferences` 同款）；外键 `ON DELETE CASCADE` 随账号删除。

## 3. 边界与不做

- 不做「关闭=通知不落库」：通知是业务事实与审计线索，落库与可见性不因个人偏好改变。
- 不做全局/按部门的弹窗策略：那是权限与发卡池的职责（ADR-063 真实授权口径已覆盖）。
- 不开放关闭 URGENT 服务器告警与打卡类人工通知。

## 4. 影响面

- 迁移 `V833__notice_popup_preferences.sql`（建表 + 重置策略 PRESERVE）。
- 服务端：`NoticePopupPreference(Id)` 实体、`NoticePopupPreferenceRepository`、
  `NoticeService.popupPreferences/setPopupPreference` 与两处读侧抑制、
  `ReviewNoticeCatalog.EVENT_LABELS/labelOf`、`NoticeController` 两个端点。
- 前端：`NoticePopupPreference` 模型与仓储两方法、`ApiEndpoints` 两条、
  `notice_popup_settings_dialog.dart`、`dashboard_page.dart` 右上角入口。
- 契约锁定：`NoticeServiceTest`（关闭事件不进登录检查、列表只展示当前资格带中文名、
  未知事件拒绝、开关幂等行）、`ReviewNoticeCatalogLabelContractTest`（标签键集=目录键集）、
  `notice_popup_settings_dialog_test.dart`（列表渲染、即时保存与失败回滚、空态）。
- 验证（2026-10-09）：服务端 81/81、前端 widget 3/3、flutter analyze 零新增问题。
