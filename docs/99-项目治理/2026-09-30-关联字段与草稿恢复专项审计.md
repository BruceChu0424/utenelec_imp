### 3.2 推荐设计

1. 定义库存查询上下文值对象：goodsId + warehouseScope + colorScope(all / explicit / null) + includeDefective + includeLineSide；URL 解析/编码是可刷新协议。主目录现有 `InstantInventoryScope` 可组合，不能丢其新增筛选字段或另造冲突对象。分类/关键词/系列/所属仓是返回列表上下文，不再过滤已确定的单货品明细；返回时保留列表范围。
2. 后端共用 warehouse 解析器，严格保留现有特殊规则：选叶仓为精确仓；父仓/全部才应用核算仓和排除不良/线边。余额、流水、指标传同一值对象，但流水日期/类型过滤另标，不能拿有日期过滤的流水净额直接当当前总余额。
3. 余额行到弹层再到流水，是“具体 warehouseId + goodsId + colorId”维度；null 色显式传 colorNull。调整/核重始终保持这一精确维度、expectedQty、幂等、权限，不接收聚合查询范围作为写入维度。
4. 货品详情库存页与库存详情共用信息区/面板。直接从货品主档打开可采用明确“全部库存”默认，不能伪装从即时库存继承了筛选。
5. 只读身份投影可落在 stock:view 授权入口：复用相同 goods/master SELECT 字段及 StockQueryService，不从 UI 为每行追加 goods detail 请求。通用 /goods/lookup 目前要求 goods:view 且 goodsScope；若扩充字典须保留原权限，不为修 stock 页面随意扩权。替代方案是在已有授权库存读 API 返回货品说明。实现前确认用户可见范围，不能靠前端 DTO 拼接绕权。
6. KPI 调整为当前库存范围的事实摘要，并明确“计划多排”等独立口径；原 goodsInsight 默认范围不可直接换标题冒充同范围统计。布局复用主目录 PlatformTableBinding/registry/picker；显示配置、只读公式事实、可写扩展值各沿原机制。
7. 详情新建投影不生成交易快照。已审单历史展示仅可使用当时已存的字段/修订快照；当时未存型号/规格不可补写后宣称是历史事实，应明确“当前货品资料”。

验收夹具：同货品有普通子仓/兄弟仓/不良仓/线边仓/非核算仓，无色及两种颜色；有待检/合格待入库/计划多排、未知/估算/精确重量。列表→详情→余额→弹层→流水、URL刷新、返回列表逐项核对范围；仓库/颜色查询全量分页不能只比首100行。stock:view 但无 goods:view、无成本权限、无调整权限分别验证。一次批量主档读，无每行 N+1，无新余额写入。

### 6.1 源码可确定的机制

公共 Mixin :444 为每个 grid 的每一行导出 platformFields，即使 cells 空也写出 sourceRecordId/version/loaded/dirty/cells 等；:457 比较行数；:461 按下标还原。
日报 `_productRows` 排除派生子行，capture 只写这些业务产品；restore 先放产品，再 `_reloadMaterialRows()` 按当前实际领料/分配来源重建。 `_applyMaterialRows()` :1292 是 product → allocation rows → material rows 展开。
因此：
1. 旧 grid [A, A用料, B]，恢复 [A, A用料, A去向, B]：即使无扩展值也被行数校验阻止。
2. 旧 [A, A用料, B, C]，新 [A, B, C, C用料]：长度相同，旧 B 的扩展值会写到 C。
3. createdReportId 恢复 :357-363 早返回，只剩产品行；旧平台快照仍含派生子行，可能阻塞已接受单据的附件接续。

现有 `test/shared/drafts/form_draft_mixin_test.dart:363` 仅验证单行静态 grid，没有覆盖动态行身份。

### 6.3 后续实施

- Mixin 提供明确的可持久化行身份映射，默认静态表保持兼容；日报选择产品业务行，不把只读 material/allocation 行写成可写扩展对象。
- 未提交本地产品行用稳定 localRowId，存进业务行 codec；复制产生新localRowId，排序/插删不改变已有行ID。goodsId 不能当唯一身份，同货品不同执行段/来源/去向可多行。
- 已提交用真实服务端 item IDs 和创建回执建立关联；提交失败/结果未知不能提前声明本地行变成某个服务器行。服务器拆分日报产出时，必须明确扩展字段传播合同，不按响应序号猜映射。
- 旧 schema 无稳定身份：无扩展业务值时允许恢复其它业务输入；有值只在能证明身份时映射，不能以相同长度/相同货品推断。不能丢弃原草稿或自动写回“修好了”的新记录。
- 先保留当前 Mixin 未知提交/删除保护、route/account/server fence，等待并行包冻结，再小范围加身份扩展点。
- 最终验收：动态行增减/同长度移位/产品排序/复制/同goods不同来源/已提交checkpoint/旧schema无身份/无价权/账号服务器切换；逐产品 extension values 与真实ID一致且业务提交次数不增加。
