# 233 · V652 索引卫生：删冗余索引、补热点关联列领头索引(ADR-106)

- 迁移：`V652__index_hygiene_redundant_drop_hot_fk_leading.sql`
- 类型：前向。96 个 `DROP INDEX IF EXISTS`，74 个 `CREATE INDEX`；不动表、列、约束与数据。
- 决策：[ADR-106](../99-决策记录-ADR/ADR-106-热表触发器按相关列起跳与索引卫生.md) §2.5。

## 冗余判定

同表、同访问方法、同部分谓词、同表达式，键列(连同算子类、排序规则、排序选项)是另一索引的前缀，且 INCLUDE 列已被对方携带；
支撑主键/唯一/排他约束的索引永不删除，唯一索引只在对方是同列唯一索引、且对方的空值规则不比它宽(`NULLS NOT DISTINCT`
只被 `NULLS NOT DISTINCT` 覆盖)时才算重复；两条完全相同的留旧删新。本次删掉的 96 条全是普通(非唯一)索引。
与 `SchemaIndexHygieneContractTest` 用的是同一条 SQL。删掉的主要是：单号与旧库主键普通索引(与同列唯一约束重复)、
四棵分类树与部门/收付款类别的 `*_parent`(被 `*_parent_sort` 覆盖)、`idx_stock_movements_goods_date` 与
`idx_stock_documents_maker_id`(与另一条定义完全相同)、`idx_sb_goods`(被带 INCLUDE 的 `idx_stock_balances_goods_cover` 覆盖)、
三个物化视图的月份/类型索引(被各自唯一索引覆盖)。

暂不删两条(契约测试白名单写明原因)：`audit_log_archive_created_at_idx`(审计表由审计整改工作流统一处理)、
`idx_procurement_iqc_stock_in_item_batch`(`ops/reset_business_data.sql` 的 V448 读路径索引自检要求它存在)。

## 补的领头索引

- 43 个热点关联列：估值图(`stock_value_*` 的节点、事件、池、成本任务/分摊/产出、修订、作业)、物料需求、库存预留、计划明细、
  总账凭证的引用方——守恒触发器与服务查询正按这些列回查子表。
- 31 个货品数量来源列(V651 改单位时按需 EXISTS)。契约只要求等值探针用得上：不带条件、或只带「该列 IS NOT NULL」的部分索引都算。
- 不补 `*_by` 审计列和字典/人员父表；估值节点自引用游标列(每次移动都改写，建索引会让这些更新失去 HOT)、没有查询按其回查的列、
  已退役的 MAKE 委托表不补。

## 兼容与影响

- 索引总数净减 22 个；热表写入少维护冗余索引，反查不再全表扫描。
- 不涉及新表/删表，`reset_business_data.sql` 表清单不变。
