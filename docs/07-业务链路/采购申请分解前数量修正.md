# 采购申请分解前数量修正

采购申请与委外申请是计划下达的只读需求池，不存在人工草稿审核接口。部门独立下单从采购或委外订货单开始。采购申请的数量修正使用独立命令 `PUT /purchase/requests/{id}/items/{itemId}/qty`，权限为采购申请查看与采购订货分解。

V846 为每次实际修正追加 `purchase_request_qty_revisions`。同一事务冻结原明细、原数量、目标数量、明细版本、操作账号及员工、来源最低需求。准备触发器与提交完整性触发器验证该证明；生产来源守卫只接受同一事务、同一用户、同一明细、完整原快照和版本的精确更新，普通修改、删除、跨用户或旧证明仍拒绝。

合法修正保留所有来源身份和原历史。申请必须已下达且开着，不能是历史导入；收费和赠品已订量都为零，不能已有订货引用、已消费/释放供给份额、未来转移或公共认领。来源最低基本量取原供给 peg 与计划分摊、公共备货、安全补货的完整下达量。收费数量与赠品语义按原单计算实物基本量，修正结果不能小于该最低量。需要撤销原计划需求时仍回计划域处理，数量修正不能代替需求撤销。

相同值且相同版本没有新证明，不推进版本。过期版本、下游占用和缩破来源均拒绝并回滚；并发同版本只允许一个修正提交。数量从服务端 `qtyExact` 原文到输入、JSON 字符串及回执核对均不经过二进制浮点。输入上限为十四位整数、四位小数，错误或不明确回执保留本地输入，必须显式核对当前版本后再提交。

证明行是包含操作人、时间、完整原明细和新值的不可变事件，归入审计 NONE 的自审计流水；原申请明细仍保留正常变化审计与历史留存。系统测试清空登记为 CLEAR，不修改任何历史迁移字节。独立真实数据库验证不等于正式服务器安装与岗位验收。
