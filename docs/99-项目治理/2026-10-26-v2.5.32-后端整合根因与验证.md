# v2.5.32 后端整合根因与验证

本记录对应本次主链全量整合的本地修复。发布、数据库迁移和正式环境验收由发布回执另行证明。

## 公共导出入口与领域边界

完整验证发现新增导出适配器从 `reporting` 直接依赖 `master`、`operations`，违反已有模块边界。没有扩展允许依赖方向，改为由原业务领域拥有解码、权限、原始查询、数量及列投影，通过应用 Port 供持久导出编排调用。

| 能力 | 权威入口 | 完整迁移调用方 |
| --- | --- | --- |
| 基础资料导出 | `application.port.MasterReportExportPort`、`features.master.export.MasterReportExportSource` | `ReportExportSource`、`ReportExportService`、`ReportExportWorker`，基础资料各原服务继续执行其原始过滤和流式读取 |
| 采购工作台导出 | `application.port.WorkbenchReportExportPort`、`features.operations.workbench.WorkbenchReportExportSource` | 持久导出的提交校验、权限与读取编排；保留原工作台任务来源和日期/列筛选 |
| 已核验实际成本导出 | `application.port.GoodsActualCostSnapshotExportPort`、原 `GoodsActualCostSnapshotService.streamExport` | `ActualCostReportExportSource`，保留原结果摘要、精度、分节与发布检查 |
| 中立查询合同 | `application.port.ReportExportQuery` | 原 `ReportExportRequest` 实现该接口；序列化记录、任务标识、原始参数和外部请求合同保持 |

旧 `reporting/export` 下基础资料与工作台实现已移回所属领域，没有遗留第二份实现。实际成本适配只通过新的窄接口调用原权威服务，不复制计算。基础资料货品导入列仍由原 `GoodsExportProjection` 处理；跨域入口不新增第二套列算法。

## 本轮明确根因

- POI 弃用接口：使用正式线程隔离 `TempFile.withStrategy`；`SXSSFWorkbook.close` 负责其内置释放，保留私有目录、压缩、预算、异常清理与并发回归。JPA 改为 `select(cb.tuple(...))`，Jackson 改为 `properties()`，不压制警告。
- 测试编译中的原始泛型和多值泛型 varargs：改精确 matcher、类型化 mock 与串联 `thenReturn`。事务测试使用正式 setter 配置 `TransactionInterceptor`，不新增 `SuppressWarnings`。
- MVC 切片的全局发布校验缺少协作者：六个现有 MVC 测试统一使用 `WithReportReadScopeMvc` 提供 `ReadScopeVersionAuthority` 与 `ExportProjectionAccessGuard`，保留真实 advice 与原安全过滤/方法权限断言。
- 文档合同错误将 `server/docs` 当仓库文档根：按 `pubspec.yaml` 与 `server/pom.xml` 向上定位同一实际仓库，不复制文档或降低合同。
- 审计会话真库测试借用了开发机独立 migrator 凭据：显式将 Flyway URL、账号及口令绑定同一私有测试克隆，继续校验其真实迁移目录，不访问开发或正式业务库。

## 作业状态与业务详情审计差异

`GET /api/report-export-jobs/{id}` 是本人作业进度轮询，遵循现有 AI 作业轮询差异。架构测试精确检查此 Controller/method、`service.get` 的本人授权、跨用户 404，以及返回记录字段仅为进度与受控元信息，不能返回原筛选、请求体或私有文件路径。下载继续保留 `export_report_download` 审计；业务详情审计阈值没有降低。
