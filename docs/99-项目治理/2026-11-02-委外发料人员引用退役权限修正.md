# 委外发料人员引用的退役权限修正

## 根因与修正

完整权限目录回归发现 `BusinessEmployeeReferencePurpose.SUBCONTRACT_MATERIAL_ISSUE_PERSON` 引用了已经退役的 `subcontract_material_issue:create`。手工新建委外发料路由及权限已被 V677 / ADR-109 删除；委外发料由仓库任务生成。新增人员引用场景错误地套用了普通单据的“create 或 edit”模式。

公共场景现仅允许持有现役 `subcontract_material_issue:edit` 的身份列出候选人员。`view` 继续只用于已有人员回显；HR 查看权限和退役的新建权限均不能取得候选能力。Web 与 Flutter 共用人员引用 API，不新增权限、不恢复手工新建、不修改历史迁移。WPF 候选中未迁移该写入入口，不因这次修正开放。

## 覆盖与证据

沿用全目录双向合同扫描所有服务端权限字面量及 Flutter 权限常量，未添加忽略项。新增场景回归覆盖现役编辑、退役新建、只读与 HR 权限的区别，并保留手工新建路由不存在的回归。

本地隔离 PostgreSQL 实际应用全部 915 条迁移至 V989 后，上述 11 项测试全部通过，无跳过。日志保留在发布目录的 `retired-reference-permission-regression.log`；这不表示生产已升级，也不代替最终提交的完整 CI。
