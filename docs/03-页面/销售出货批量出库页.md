# 销售出货批量出库

> 路由：`/warehouse/sales-outbound/batch`
> 别名：整批销售出库、批量确认出库

## 页面定位

仓库集中核对已选销售出货单并逐张确认实物出库。

## 办理与边界

- 从销售出库任务勾选货品明细进入，地址以 `shipmentIds` 和 `itemIds` 保留原出货单、原明细与对应订货来源；只显示本次所选明细，不能按单号补入未选行。
- 销售出货在财务放行后按原单一次确认，不能在仓库侧拆改已批准金额或重复形成应收。所选行未覆盖某张原单全部明细时，提示「该出货单需整单确认，请返回任务中心选齐同单明细」，本次不出库。服务端 `warehouse-work.itemIds` 在持单据锁后再次要求集合完全一致；缺少、重复、外单或并发新增明细均拒绝。
- 查看需要 `warehouse_sales_outbound:view`，确认出库需要 `warehouse_sales_outbound:execute`。
- 核对原单货品、颜色、计量单位、拣货与实际出库数量；仓库办理不改写商业价格或财务审核结果。
- 服务端逐张验证财务放行、有效状态、当前版本、库存与本人仓库范围，列表查看权不替代实际作业权。
- 发送及异步续接使用当前身份；有回执不明的单先核对原操作，已成功单据不重复确认。
- 每张出货单是独立命令。原 A 已派发但结果未知时，即使后续未派发 B 取消、删除或当前不可读，也可单独读取 A 的当前状态核对；不把它改成覆盖剩余来源的新写请求。A 必须当前可读且原明细身份、货品与数量范围仍一致，已出库才登记为完成；A 不可读则保留原未知身份，不重放。受阻 B 只显示来源 ID，原批次、所选范围和未完成状态继续保留，不显示旧敏感快照。
- 返回原任务上下文，保留已经完成的成员与未完成成员各自的状态。
