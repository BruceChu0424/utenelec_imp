# V505：真实恢复库结构收敛

日期：2026-09-07。状态：已进入正式源码迁移目录的本地候选；已在真实服务器备份的独立副本验证，完整目录组合验证进行中，未发布、未修改服务器。

## 为什么需要前向迁移

公司服务器 V476/438 的迁移版本、脚本名及校验值全部匹配，但物理目录并不完全相同。不能用 `flyway repair` 或只改版本号解决，也不能认定空库回放一定比服务器的每个细节正确。

对比采用相同 PostgreSQL 16：新建空库执行438个迁移，导出、恢复结构后再与实际备份恢复库比较。排除备份恢复带来的等价表达式重写及函数换行差异后，逐项核对最新规则，做以下收敛。

| 项目 | 前向处理 | 依据 |
|---|---|---|
| 生产材料事件/分配/清料、销售发货状态/退货品质/退货处置、采购品质事件共8个追加账触发器 | 验证已有表、触发器形状、函数归属，再恢复 `ENABLE ALWAYS` | V161、V188、V189、V220、V222 明确禁止历史事实被复制会话绕过修改 |
| 审计归档的事件类别、风险等级、请求UUID索引 | 补齐明确索引并核验实际定义 | V171 的 `CREATE TABLE IF NOT EXISTS ... LIKE ... INCLUDING INDEXES` 只在新建时复制索引，已有归档表不会自动补齐 |
| 新库残留 `master_code_sequences` 行审计触发器 | 只移除已识别的旧 `fn_audit`/`fn_audit_redacted` 同形触发器 | V183 以后审计覆盖排除编号计数器，编号归属及实际业务操作审计继续保留 |
| 销售其它出货的材料/压铸/机加工成本分项 | 未来省略值统一为NULL，去掉默认0 | 未提供成本不是已确认零成本；不改任何存量NULL、0或非零金额 |

同名但不同定义的触发器或索引会令迁移回滚，不能静默覆盖未知手改。迁移不新增业务表，不调整清空分类，不重新计算数量、应收、应付或成本。

## 已有证据与后续验收

独立副本专项已通过：收敛后12,882个目录对象无缺失、额外或定义差异；321张父表完整行摘要不变；先以正常约束创建的生产材料事件，在复制会话尝试UPDATE仍被SQLSTATE55000拒绝。原始服务器恢复库继续保留V476，用于后续完整前向迁移演练。

本次结构对比不含原服务器角色所有者/授权、动态审计分区子表、序列当前位置或物化视图内容。对应项仍属于最终本地演练和服务器手动更新后的检查，不用该专项代替全量验收。详细记录见[本地审计验收](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)。
