# 资产及待摊重新提交对照

固定资产、待摊费用的入账申请被退回后可编辑同一张卡片并重新提交；固定资产处置、待摊终止申请被拒后也可调整原因、日期和凭据重新申请。详情接口新增 `reviewRevisions`，按 `RECOGNITION`、`DISPOSAL`、`TERMINATION` 分别返回最近两次真实业务提交。每项包含 `workflowType`、`resubmission`、`previousSnapshot`、`submissionSnapshot`。首次提交没有 previous；旧记录缺少可证明镜像时返回 NULL，不能从当前卡片回填旧金额或日期。

入账申请在原行锁、版本校验和同一事务内，将商业镜像追加到不可变 `finance_asset_events.SUBMITTED.payload.submissionSnapshot`。快照包括名称、类别、部门/责任人及当时名称、地点、来源证据、原值或总额、残值率、期限、启用/受益日期及备注。金额、比率使用精确十进制字符串。提交版本、审核人、提交时间、净值、累计计提等工作流或会计推进量不属于商业对照。业务事件按原发生时间排序，外层 `reviewRevision` 仅用于同刻排序，不下发为商业字段；后续旧写入方没有该元数据时，不能被错误排到旧镜像之前。

仍处于待入账审批的旧卡片在拒绝事务结束前保持冻结，可将其内容保存到此次 REJECTED 业务事件。下一次提交时只在此前 SUBMITTED 没有镜像的情况下使用这份冻结证据；绝不覆盖已经存在的提交镜像。已经退回可编辑、且没有这类冻结证据的旧卡片保持历史缺失。

处置和终止复核沿用现有 `DISPOSAL_REQUESTED` / `TERMINATION_REQUESTED` 的金额、凭据，以及事件原有原因、有效日期。缺必要历史要素时整份旧镜像标为不可用，不将缺失金额写成零。两种请求不与入账申请配对，拒绝事件本身也不会被误当成新申请。

本次不新增数据库迁移，不改既有事件、不改入账/计提/核算或处置过账计算。`postedWorkflowsEnabled`、申请人与审批人分离、版本冲突、科目配置、来源身份和状态前置条件保持原控制。真实 PostgreSQL 对照测试中，处置/终止的已生效状态以明确夹具给定；该测试验证请求、退回、重提和读取，不替代资产启用或 GL 过账全链验收。
