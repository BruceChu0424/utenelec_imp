# 称重偏差统计精度修复

`goods_weight_observations.deviation_pct` 是 `ApwPredictor.checkWeight` 的 `100 × (实称 / 应称 − 1)` 派生结果，不是称重请求输入。V1011 的字段名回退将它归为 actual，因而拒绝正常模型产生的 `-0.00000000000002220446049250313`。V1075 只修正该字段的分类，使用已有有限数值、40 位整数及 30 位小数的派生统计边界；实称重量、数量及其他字段保留原有校验。

唯一分类入口仍为 `fn_migrate_financial_amount_columns(jsonb)`。前向迁移结构化核对其现有定义，为该精确字段增加语义覆盖；后续调用即使传入旧的 actual 分类也不会恢复错误约束，非法 kind 仍被原检查拒绝。历史 V518、V1011 不变，不改数学、风险规则或业务数据，不新增精度用途及交互。

自动观测调用方包括普通仓库单据、到货登记、成品入库、委外发料、生产余料收货及销售发货；主动称样复用相同观测服务。`WeightSampleRequest`、`WeightProfileUpdateRequest` 均不接受偏差输入。重量原数及明确精度选择的证据继续由原有 WEIGHT_KG/TARE_KG 合同负责。

服务端 `WeightObservationRow` 已有 `deviationPctExact`；`WeightAlertRow` 补充同名只读字段。Web 与 Flutter 桌面共用的 `WeightObservation`、`InsightWeightAlertRow` 优先读取精确文本，学习记录及库存分析沿用公共 `formatSignedPct`，不经 double 重建展示值。瞬时 `WeightCheck`、预测算法及数值兼容字段不变。本次没有新界面入口、按钮或布局。

Win7 C# WPF 源码尚无这些观测/异常 DTO 或偏差消费入口，本次没有原生写入口可同步。候选身份及未迁移范围保持原台账，不代表 Win7 完整业务或真机验收完成。
