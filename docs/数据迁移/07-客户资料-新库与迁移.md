## 一、与货品/模具资料「同构但分表」

货品用 `material_categories` + `goods`；模具用 `mould_categories` + `moulds`；**客户用 `client_categories` + `clients`**，物理隔离、互不影响（与模具落地时选独立表的理由一致，见 [05](05-模具资料-新库与迁移.md) §一）。「货品/模具/客户/供应商资料同级」体现在前端「基础资料」hub（`/basicinfo`），不在 DB 层。

## 二、新库表设计

### 2.1 `client_categories`（分类树，Flyway `V35__client_category.sql`）

与 `material_categories`(V31) / `mould_categories`(V33) 字段逐一相同：`id(UUID PK) · legacy_id(INT UNIQUE) · code · name · parent_id(自引用 FK) · level(INT 真实深度) · sort_order · path(触发器维护) · 审计4列 · is_deleted · deleted_at`。

- `path` 由触发器 `trg_clientcat_path`（函数 `fn_clientcat_path`，逻辑同 `fn_matcat_path`）维护：`path = 父path || code || '/'`。
- `code` 无 UNIQUE（GD/CL 重复），定位用 `id`/`legacy_id`。
- 老库业务形状是 **10 根 / 40 节点 / 最大深 2**；V272 另加迁移种子为 `legacy_id=-1` 的系统“未分类”根，目标树为 11 根 / 41 节点。V275 候选把其实际 UUID 登记进固定注册表；普通在线逻辑不以旧整数、名称或内部 code 识别该根。

### 2.2 `clients`（主档，Flyway `V36__client.sql`）

逐字段照搬老库 `B_Client`（34 字段），起清晰列名（见 [06](06-客户资料-老库溯源.md) §2.4）：

```
id(UUID PK) · legacy_id(INT UNIQUE=B_Client.ID) · category_id(→client_categories)
name(Client_Name) · code(Number) · full_name(Full_Name) · client_rank(Client_Rank)
place_id(PlaceID 地区文本) · emp_id(Emp_ID 业务员) · legal_person(Juri_Per 法人) · linkman(Link_Man)
mobile · phone · phone2 · fax · postcode(Post) · address(Link_Addr) · email · website(Http)
ship_via(Shipvia) · ship_address(Ship_Addr) · bank(Client_Bank) · bank_account(Client_BankNo) · tax_id(Tax_ID)
credit(Credit numeric) · init_total/init_total2(期初应收) · exchange_rate(CRate) · tday(TDay) · price_style(PStyle) · zj_id(ZJID)
region(QYName 区域) · client_xz(ClientXZ 性质) · status(使用/禁用) · remark
审计4列 · is_deleted · deleted_at
```

- `category_id` 由 `B_Client.ParentID → SystemItem.ItemID`(ItemclassID=2) 反查得到；老库 **6 条 ParentID=0** 在 V272/现行离线脚本中挂系统“未分类”根，目标库 `category_id NOT NULL`。
- 索引：`category_id` / `legacy_id` / `code` / `status`。
- V285 增加 `default_settlement_method_id UUID → settlement_methods.id ON DELETE RESTRICT` 及部分索引。普通新增/编辑只收 UUID；数据库同步 `price_style` 并拒绝 UUID/快照冲突、legacy-only 在线写入、停用/删除仍被启用客户引用的结账方式。客户编辑页可显式选择或清空默认结账方式，列表/详情展示关联名称。

## 四、后端 API

### 4.1 客户分类 `/api/master/client-categories`（与 `/master/material-categories` 同构）

`GET /tree`、`GET /{id}/subtree`、`GET /{id}`、`POST`、`PUT /{id}`（防成环 + 子树 level 重算）、`DELETE /{id}`（校验无子）。
包 `com.uten.imp.features.master.clientcategory`（`ClientCategory` 实体 / `Repository` / `Service` / `Controller` + 4 DTO），逐方法镜像 `materialcategory`。

### 4.2 客户主档 `/api/master/clients`（与 `/master/moulds` 同构）

`GET /api/master/clients?categoryId=&page=1&size=20`（**categoryId 非空时返回该分类及所有后代分类下的客户——子树汇总**；为空返回全部）、`GET /{id}`（详情）、`POST`（新建）、`PUT /{id}`（编辑）、`DELETE /{id}`（软删）。后三者需 `client:edit`，请求体 `ClientSaveRequest`（categoryId/name/code/fullName/... 全业务字段）。

> **子树汇总**（与 mould/goods 的差异）：客户主档会**直接挂在有子分类的分组节点上**（如外贸(钟)既有子分类「内销轨道」又直接挂 17 个客户）。故 `list(categoryId)` 先 `ClientCategoryRepository.findSubtree(categoryId)` 取自身+所有后代分类 id，再 `findByCategoryIdIn`。点外贸(钟) → 20 条（17 + 内销轨道 3）；点外贸(苏) → 44；点南区 → 63（全省+分销商）。
包 `com.uten.imp.features.master.client`（`Client` / `Repository` / `Service` / `Controller` + `ClientListItem`/`ClientDetail`）。

## 五、正式离线导入与开发样例

| 路径 | 用途 | 文件 |
|---|---|---|
| **Shell（正式离线链）** | 分类 + 主档 | `migrate_client.sql`、`migrate_client_data.sql`；完整切换由 `migrate.sh --bootstrap-all` 编排 |
| **Java（仅 dev）** | classpath 分类样例 | `com.uten.imp.legacy.migration.ClientCategoryMigrator`（ItemclassID=2） |
| **数据导出** | 老库 → UTF-8 CSV | `export_legacy.ps1 ClientCategory/ClientData` |

### 5.1 设计要点

- **递归 depth**：客户业务分类有真实嵌套（最大深 2），`migrate_client.sql` 递归算 level；脚本无条件重建稳定的系统“未分类”根。
- **受控替换**：Shell 在单事务中先删客户主档，再删普通分类并保留 V275 系统根；任何未知下游 FK 会使事务回滚。它不使用 `TRUNCATE`、`CASCADE` 或禁用约束，也不是在线增量同步。
- **固定身份**：在线 API、官网询盘和页面只绑定注册表中的 `client_category_id`，不得按 `legacy_id=-1`、名称或 code 重新发现。
- **6 条未分组**：V272 前历史演练为 NULL；现行脚本用 `COALESCE` 挂系统“未分类”根，统一搜索可直接展开定位。
- **管道符转义**：`export_legacy.ps1` 对含 `\|`/`"`/换行的字段做 RFC4180 引号转义（实测王海东等行地址含 `\|`，未转义会 COPY 列错位）。
- **GBK**：老库 `Chinese_PRC_CI_AS`，导出走 PowerShell + .NET SqlClient 原生解码。
- **V285 客户默认结账方式**：`migrate_client_data.sql` 在受控 `uten.legacy_reference_import=on` 事务内同时写 UUID 与旧整数；重载时连同问题表一起清空，并重新生成无法唯一匹配的对账证据。上线前必须确认问题表未解决行，不能把“迁移脚本存在”当作目标库已完成回填。

### 5.2 运行时边界

ERP JAR 不包含 SQL Server 驱动或老库 DataSource。`app.legacy.enabled=false` 是退役通道的安全断言，不是可开启的迁移开关。

## 七、迁移校验（实测，2026-07-24）

```sql
-- V272 目标：40 个业务节点 + 1 个系统未分类根
SELECT count(*), count(*) FILTER (WHERE parent_id IS NULL), COALESCE(MAX(level),0)
FROM client_categories;

-- 主档对账
SELECT count(*) AS total,
       count(category_id) AS linked,                            -- 260（不含随后财务占位增量）
       count(*) FILTER (WHERE category_id IS NULL) AS ungrouped,-- 0
       count(*) FILTER (WHERE category_id =
         (SELECT client_category_id FROM system_master_category_registry)) AS uncategorized, -- 6
       count(*) FILTER (WHERE status = '使用') AS in_use,        -- 236
       count(*) FILTER (WHERE status = '禁用') AS disabled       -- 24
FROM clients;

-- 抽验挂载
SELECT c.code, c.name, COUNT(cl.id) FROM client_categories c
JOIN clients cl ON cl.category_id = c.id
WHERE c.legacy_id IN (2855,2214,2165) GROUP BY c.code,c.name;
-- 外贸（苏）=43 / OEM（苏）=18 / 外贸（钟）=17
```

**V272 前历史演练结果**：分类 40/根 10/深 2；客户 260（已挂 254 / NULL 6 / 在用 236 / 禁用 24）。现行候选目标是 41 节点/11 根、260 条源客户全挂载、系统根 6、NULL 0；`migrate_finance.sql` 还可能动态追加 `LEGACY-FIN-CL-*` 历史占位并同样挂系统根。

## 八、前端（与货品/模具资料同级）

- `/basicinfo` → 基础资料 hub：货品 / 模具 / **客户** / 供应商 卡片入口。
- `/basicinfo/client` → **客户资料页**（`ClientCategoryPage`）：左分类树 + 右分类详情 + 该分类下客户分页 + 客户详情弹框（编号/名称/全称/等级/区域/业务员/法人/联系人/手机/电话/地址/收货地址/银行/税号/信用额度/期初/状态/备注 等）。复用 `UtenCategoryTreeView` / `CategoryEditDialog` / `UtenLocationField` / `ProductCategoryNode` 模型。
- 列表项：title=客户名、subtitle=`code · 区域 · 联系人`、trailing=状态 chip（使用=绿/禁用=灰）。
- 工作台「基础资料」卡片仍指向 `/basicinfo`（hub）；财税部原客户/供应商占位卡片已移除（见 [09](09-供应商资料-新库与迁移.md)）。
- **主档维护（client:edit）**：详情弹框带编辑/删除；分类详情可添加客户。公共 `ClientSaveRequest.categoryId` 必填，官网询盘转客户由服务端显式绑定系统“未分类”根。
- **默认结账方式（V285 候选）**：新建/编辑从启用结账方式字典选择，提交 `defaultSettlementMethodId`；加载字典失败会明确提示并不打开不完整表单。空选项表示显式清空，旧客户端省略该字段则保留原值。
- **实现要点（四类一致）**：① 后端 `XxxSaveRequest` 强制 `name` 非空（`@NotBlank`）、`categoryId` 非空（`@NotNull`）；`requireCategory` 校验分类存在且未软删；审计字段（`created_at/by`、`updated_at/by`）由 Spring Data `AuditingEntityListener` 自动填，无需手设；删除为软删（置 `is_deleted=true` + `deleted_at`），不物理删除。② 删空当前页最后一条时自动回退上一页，避免列表空白。③ 货品/模具的分组分类（含子分类）不直接挂主档，「添加」按钮仅在叶子分类（`childCount=0`）出现；客户/供应商因 list 子树汇总，任意分类均可添加且立即可见。
- **子页返回**：返回键显式回基础资料 hub（非工作台）——hub 与子页都用 `context.go` 进入不压栈，默认 `UtenBackButton` 会因 `canPop()=false` 误兜底回工作台，故 AppBar 指定 `onPressed → context.go(basicinfo)`。
- **白屏修复**：详情弹窗与关闭动作使用同一 root navigator，避免误 pop 业务页面。
- **统一关联搜索（2026-08-14）**：左树顶部同搜分类名称/编号与客户名称/编号等字段，按当前客户可见范围逐页收集全部 `categoryId`、展开祖先并驱动右表同词结果；V272 后未分类客户也展开真实系统根。详见 [基础资料页](../03-页面/基础资料页.md) 与 [UtenHierarchySearch](../02-组件库/UtenHierarchySearch.md)。
- **分类驱动编号与 UUID 身份（V257–V279 候选）**：客户分类维护可编辑 `code_prefix`，客户编号为空时取最近祖先显式前缀、全空回退 `KH`；手工编号和自动编号都进入 V279 全局完整标识终身保留。前缀/父级变化须先预览确认再批量改号；官网询盘、财务、销售及普通 CRUD 绑定分类/客户时只提交 UUID，不按客户编号、名称或 `legacy_id` 生成关系。
