## 实际复现

## 故障链与修复入口

用同摘要 SDK Release DLL 的匹配 PDB 解析新 dump，可靠调用链为：

```text
UIAutomationCore / oleacc
  AXPlatformNodeWin::get_accValue
  AXPlatformNodeWin::GetValueAttributeAsBstr
  AXPlatformNodeBase::GetString16Attribute
  AXNodeData::GetString16Attribute / GetStringAttribute
  std::string::assign / memcpy -> C0000005
```

故障指令读取 `RDX=0x423a00004381c000`，复制长度 `R8=35`，是无效源内存；不是财务金额计算栈、单据保存栈或普通 Dart 异常。Release 优化使上层部分 `this` 不可直接恢复，因此不编造事故时的具体节点 ID 或原始业务文本。

源代码和已有原生红绿用例已证明公共缺陷：树重新挂载/重建节点后，保留的平台 delegate 可能继续引用旧 AXNode；原 `GetData()` 直接返回缓存节点数据，后续任何节点属性查询都可读失效字符串。公共修复需要事务预检、保全未重发子树、重建后重新绑定节点，并保护旧子索引。只对 `HitTestSync` 判空不覆盖这次 `get_accValue`，只给某个页面加 try/catch 也不能修复 native 内存生命周期。

统一入口继续使用已有 `flutter-3.44.2-safe-accessibility-tree.patch`，Windows 另加 `flutter-3.44.2-windows-hit-test-lifecycle.patch`。本轮增补 `flutter-3.44.2-retained-text-value-regression.patch`，只增强测试：35 字节堆分配文本、保留旧引用、重挂载后 UTF-16 属性读取。没有关闭辅助功能、隐藏异常、返回截断业务数据或逐页复制修复。

本次 UI Automation 查询参与了触发过程；这证明原版对该系统查询不安全，不能反推所有现场用户的辅助功能客户端、触发页面或全部退出都相同。此前另一台现场证据是 `HitTestSync+0xF5D3`，此次是不同入口的实机证据，二者都必须纳入公共稳定性门槛。
