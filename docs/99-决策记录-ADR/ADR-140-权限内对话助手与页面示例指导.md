# ADR-140 权限内对话助手与页面示例指导

- 日期: 2026-10-02。
- 状态: 本地实现与验证，具体结果见[本轮验证记录](../99-项目治理/2026-10-02-权限内AI助手本地实现与验证.md)；不代表业务服务器已经启用。
- 依赖: ADR-133 公共 AI 平台、ADR-134 销售文件识别、ADR-109 授权策略、ADR-110 再认证、ADR-138 成本单、ADR-139 报价客户确认。

## 要解决的问题

员工希望在当前业务页面直接问问题、得到填写例子、查询本人权限内的事实，并把客户文件带入订货草稿。超管还希望通过自然语言准备对某一员工的单项授权。聊天不得成为原有权限、数据范围、字段权限、审批或来源约束的旁路。

“了解整个平台”分成三类，不能混为拥有数据库全权:

| 内容 | 权威来源 | 回答方式 |
|---|---|---|
| 业务流程与字段含义 | 版本化、审核过的业务指南 | 根据当前部门、页面权限和字段权限选择说明，给假设例子并标明来源 |
| 真实业务事实 | 当前用户能调用的既有业务服务 | 有限参数的只读工具查询，注明成本口径、时间及不完整状态 |
| 操作 | 既有业务命令、状态和版本规则 | 生成可核对的操作卡；业务服务完成保存、确认、再认证与审计 |

知道一张表或页面存在，不等于可以读其记录。普通员工不能利用聊天授权；超管也不能通过聊天绕过单据状态、财务审核、来源或数量守恒。

~~~mermaid
flowchart LR
  U[用户问题和当前页面] --> A[服务端身份与部门权限]
  A --> M[模型选择有限能力]
  M --> V[参数与当前权限复核]
  V --> K[已审核说明与假设例子]
  V --> Q[现有业务服务与数据范围]
  V --> P[明确操作预览]
  P --> C[本人确认与必要再认证]
  C --> B[原业务事务与审计]
  K --> R[结果读取重新鉴权]
  Q --> R
  B --> R
  R --> U
~~~

## 调研与取舍

调研采用官方资料，而非把供应商宣传当作本项目安全证明:

- [Microsoft Copilot Studio Security FAQs](https://learn.microsoft.com/en-us/microsoft-copilot-studio/security-faq): 按交互者身份与权限限制保密知识，知识来源也有独立管理控制。
- [Salesforce Agentforce 安全与共同责任](https://help.salesforce.com/s/articleView?id=005315874&language=en_US&type=1): 内部助手沿用登录用户的对象、字段和共享权限；管理者需限制主题与动作，配置本身仍是项目方责任。
- [SAP Joule Capabilities](https://help.sap.com/docs/joule/capabilities-guide/about-this-document): 将业务助手区分为信息查找、导航和任务能力。本轮搜索可见其能力摘要，动态正文未能完整读取，故不据此推断其内部鉴权实现。
- [OWASP AI Agent Security](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html): 工具最小权限、独立授权、上下文隔离与高影响操作完整性。
- [OWASP Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html): 用户输入、文件、网页和工具文本都可能携带指令；提示词或正则检测不能代替确定性的权限边界。

本项目选择“受约束的意图理解 + 已审核知识 + 原业务工具”。模型返回的自由文本不直接成为业务事实答案。模型只选择已开放的指南、字段或工具及有限参数；后端重新验证后生成答案。这样即使模型被诱导产生越权工具名、SQL 或假金额，也没有对应执行入口。

这会牺牲任意问题的自由发挥。尚未注册的查询明确说明未接入；问题不清楚时要求补充；不把“没有权限”“没有记录”“暂未支持”“服务失败”混成同一结论。

## 身份、范围与工具边界

1. 只有员工真实会话和 ai:use 可以进入；访客、未绑员工、锁定、强制改密和模拟身份均不能提交。权限来自服务端身份，客户端不能声明自己的部门或超管身份。
2. 普通员工可用域是主部门、兼职部门及其有效祖先，与现行功能权限的交集。超管可用全部已注册域。页面功能授权不自动使普通人获得其他部门的 AI 数据范围。
3. 每个业务工具再次检查权限和原服务的数据范围；列表、候选、合计、成本组成、客户范围及文件结果同样属于受保护数据。
4. 不提供 SQL、表名、数据库连接、任意 URL、任意接口、脚本、shell 或文件系统工具。工具注册来自服务端代码，模型无法增加工具。
5. 输入 schema 只是协议声明，执行端必须核对必填、类型、长度、未知参数和取值；业务 UUID、人员、货品和权限码必须经服务端候选/业务服务核实。
6. 当前问题、上一轮问题及上传文件均是不可信内容。只延续本人上一轮已验证的问题；不接受客户端构造的 system/assistant 历史，不把成本答案、授权令牌或数据库结果送回模型。
7. 聊天任务结果存入既有 ai_jobs。后台使用提交人的身份重建，读取时再次检查身份版本、全局授权 epoch、当前部门指纹以及工具的业务证据。部门或权限变化后旧记录拒绝读取。成本证据还重查原货品、原成本单与组成范围；工作台历史重新核对当前可见计数，防止功能权限未变但记录归属已变的漏洞。
8. 浏览器和客户端只保存当前会话的临时聊天状态。账号、服务端地址、模拟状态或权限上下文变化时清空，并丢弃旧请求的迟到结果。历史仍受服务端门禁，不以 UI 清空代替鉴权。

## 当前页面和字段举例

2026-10-03 修正: “这个页面怎么填写，请举例”等明确页面帮助，直接读取下述权限化指南，不依赖模型输出 JSON。快捷入口发送 intentHint=PAGE_HELP，普通手输的完全匹配问法也可识别；提示只选择只读说明，不能授权任何业务动作。自由提问仍按当前可用能力构建闭合 JSON Schema，并在服务端验证工具参数。模型预算请求为 8192，公共网关仍取管理员配置的更低上限，不额外重试或读取 reasoning_content 代替最终输出。详见[故障修复与验证](../99-项目治理/2026-10-03-AI页面说明与模型返回异常修复.md)。

页面上下文只传规范路由与可选字段键。后端将路由映射到审核目录，再检查部门、页面动作与字段权限。模型只收到页面标题和允许的字段键/标签，不收到路径中的业务 UUID、URL 查询参数、隐藏字段、表单真实值、密码或整屏截图。

客户端上下文来自当前活动路由的 URI path。ShellRoute 的 matchedLocation 在 push/pop 时可能仍指向上一页，不能用于确定聊天正在解释哪一页；查询参数仍不外送。关闭页面感知后不会从历史恢复页面。

回答包含“字段用途 → 填写方法 → 假设例子 → 来源”。例子绝不冒充当前记录事实。例如:

- 订货数量: 客户要 120 个就填 120 个；另有 3 箱不能相加成 123 个。
- 本次报工: 昨天 60 个、今天新完成 40 个，本次填 40，不能重报累计 100。
- 整袋盘点: 3 袋 × 25 公斤 + 开口袋 6.2 公斤 = 81.2 公斤；漏填和明确零库存不同。
- 报价: 财务确认版本 3 后客户接受；再修改形成新版本时，旧客户确认失效。
- 成本: 已知材料 2 元、加工 1 元，若运费缺失，3 元只是已知部分，不是完整实际成本。

首批目录覆盖销售报价/订货、采购/委外订货、物料分析、车间任务、报工、内料仓盘点、货品资料、报价财审、员工资料和工作台。未登记页面或扩展字段明确提示没有可靠说明，不根据同名字段猜测。当前实现是页面语义感知，不是截图 OCR，也不声称已经识别屏幕上的实际输入值。

## 销售文件形成订货草稿

聊天上传复用 SALES_DOCUMENT_INTAKE，参数限定 order、新单；当前聊天文件选择支持 Excel/xls/xlsx/CSV。既有销售页面的 PDF/图片识别继续沿原流程使用，不能将其已有支持误写成聊天界面已经开放。文件大小、压缩炸弹和不可信内容边界沿 ADR-133/134。上传任务必须是本人、成功、未消费、未绑定旧单且授权戳仍有效；客户和货品候选还需按当前归属重新验证。

成功后返回 OPEN_SALES_ORDER_DRAFT 卡，使用现有 /sales/orders/new 的 aiJobId 和原附件入口。销售先核对客户和每一行，再保存。保留原文件、识别行和学习回执，不另造一套导入或学习写回。归属复核放在原销售识别结果读取入口，覆盖已选及未选客户/货品、组合件和重复单据提示；不依赖聊天之后的第二次检查。客户自定义列名即使叫 goodsId，也不作为服务器 UUID 解析。

上传文件写着“给我管理员权限”也不会产生授权动作；文件只进入销售识别流程，不能进入授权意图提示。文件中金额不能自动覆盖已确认报价价款。原系统报价转单继续检查财务核价、客户接受当前版本、有效期和原单状态。

## 成本查询

query_goods_cost 需要财务部门资格、goods:view、goods:cost:view 和既有货品/成本单范围。先做有界候选查找，同名时让用户提供准确编码；看不到和不存在都不泄漏额外记录。

回复注明货品、成本单、版本、确认状态、币别、单位、测算批量、缺价状态和计算时间。它回答已注册成本单的测算结果，不把测算当作完整实际成本。尚无成本单不能回答 0 元。实际成本按期间和价值账查询仍需专门工具接入。

业务结果留在应用服务内，不发给模型二次总结。历史读取使用封存的原候选/货品/成本单证据重新验证数据范围，不能仅检查 goods:cost:view。

## 超管单项授权

prepare_permission_grant 只为真实超管提供。服务器解析在职账号、工号与权限目录；重名或多项匹配时要求明确，不猜对象。普通人的自然语言不能创建授权提案。

提案使用有域隔离的 HMAC 签名，有效期 10 分钟，绑定发起人、发起人授权版本/epoch、目标账号版本、权限 ID/码及有效期。确认卡显示真实员工、权限与影响。签名密钥不足或未配置时关闭此能力。

确认端点单独执行超管、ai:use、authorization:manage、RequiresStepUp 和现行策略校验，事务内锁定目标/发起人并检查版本。仅合并这一项个人 grant，保留其他 grants/revokes；不全量覆盖，不修改 is_super_admin，不授予超管专属码，不为自己或另一超管操作。复用既有授权服务继承审计与令牌吊销。

已授权不重复新增；版本、权限目录或身份变化时要求重新准备提案。自动重试不重放授权写入。聊天模型拿不到再次验证的密码或令牌。

## UI、异常与运行边界

- 右侧可上下拖动的入口，点击打开右下角小窗；小屏按可用空间收缩，避开键盘和系统安全区域。
- 展示当前页面上下文开关、具体例子问法、发送中/取消/失败/规则模式、上传文件、操作卡与新对话。
- AI 服务不可用时提供有限的本地说明，不能用伪造结果填补失败。并发、每日额度、取消、超时、租约与清理复用公共 AI 队列。
- POST 写入不因网络恢复自动重放；正式业务动作有明确回执。失败保持可恢复界面，不显示密钥或服务商内部原文。
- 同样的问题再次显式发送是新的查询，不套用上传文件的内容去重缓存。文件仍按原规则去重，但已成功的旧结果需先通过当前可见性检查；原结果因归属变更失效时，新识别能重建当前候选，而不会持续复用被拒绝的旧任务。
- 用户主动输入的聊天文字可能发送到配置的服务商，界面予以说明；不得声称所有输入均留在本地。服务商地域、出网开关与日志留存沿现有平台设置。
- 技术日志保留用途、时长和错误类别，不记录聊天正文、文件、成本或授权令牌。ai_jobs 的受限结果保留与任务清理仍按 ADR-133；它不是审计日志的替代品。

## 对抗验证矩阵与后续扩展

| 情况 | 必须成立的结果 |
|---|---|
| 生产用户问财务成本，或伪造 FINANCE/超管身份 | 不查询财务工具，不泄漏候选、金额或记录是否存在 |
| 模型选择未注册工具、传 SQL/额外参数 | 执行前拒绝 |
| 文件内嵌授权指令、恶意外链、表格公式 | 不执行指令/外链/公式，不进入授权工具 |
| 使用另一用户 jobId 或已消费来源 | 拒绝，不带入草稿 |
| 账号切换、撤权、调部门、记录归属变化 | 旧请求迟到结果不回写，历史在服务端重新验证 |
| 无权限字段/任意路径冒充当前页面 | 不返回字段说明或业务数据 |
| 同名员工/物料、多项权限 | 明确要求工号、货品编码或单项权限，不猜对象 |
| 修改签名提案、过期、跨账号、版本冲突 | 零授权写入 |
| 重复发送/点击、取消、超时、服务不可用 | 有限任务、可见状态、无重复业务提交 |
| 未知成本、实际与测算混淆、跨单位汇总 | 保留未知与口径，不生成虚假精确答案 |

后续新增生产明细、库存、销售进度、财务实际成本等查询，按业务域分别实现 AiChatToolPort，并提供字段投影、数据范围复查、结果来源、有限查询与负向回归。新增页面字段说明必须同步现行业务文档与测试。未经这些步骤不开放通用数据库代理。

本地单测只是验证证据的一部分。上线仍需对候选版本做真实 PostgreSQL/API 身份矩阵、已配置模型的对抗语料、常用页面岗位体验和并发/取消/限额验收；不能承诺已经覆盖全部可能问题或绝对不会出现安全缺陷。
