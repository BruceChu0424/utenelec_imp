## 一、老系统「即时库存」窗口溯源

老系统（004.jpg 截图）：顶部「仓库」下拉（默认全部）+ 左侧「货品类型」树（全部/原材料/半成品/成品/轨道/辅料…）+ 右侧表格。列：

| 列 | 老库来源 | 新库对应 |
|---|---|---|
| 所属类型 | `SystemItem.Name`（货品分类，`B_Goods.ParentID`） | `material_categories.name`（货品直接分类） |
| 型号 | `B_Goods.Number` | `goods.model` |
| 客户型号 | `B_Goods.CNumber` | `goods.c_number` |
| 货品名称 | `B_Goods.Goods_Name` | `goods.name` |
| 规格 | `B_Goods.Standard` | `goods.spec` |
| 颜色 | `B_Color.ColorName` | `colors.name` |
| 单位 | `B_Unit.Unit_Name` | `units.name`（经 `goods.unit_legacy_id`） |
| 备注 | **`B_Goods.Paper`**（老库存「外购/外加工/客户货品系列编号」等自由文本） | `goods.paper` |
| 库存重量 | `StockGoods.FactWeight`（当年） | `stock_balances.weight`（**V80 新增列**） |
| 库存数量 | `StockGoods.FactQTY`（当年） | `stock_balances.qty` |
| 成本金额 | **`B_Goods.CTotal × FactQTY`**（不是台账 Total！） | `goods.c_total × qty` |
| 多排数量 | `View_ProductMore`：`F_PlanItem` 可排余量 | `production_plan_items` 同口径聚合 |

关键视图（`sys.sql_modules` dump 实证）：

```sql
-- View_StockGoods：当年 FactQTY/FactWeight，且只算 B_Storage.IsCal = 0（参与核算）的仓库
-- View_IOStockGoods：即时库存主视图，一行 = 仓+货+色+年，含 Paper(备注)/FactWeight(库存重量)
--                    /CTotal×FactQTY(成本金额)/VNumber(供应商型号)
-- View_ProductMore（多排数量）：
SELECT GoodsID, ColorID,
       SUM(CASE WHEN QTY - OQTY > IQTY THEN QTY - OQTY - IQTY ELSE 0 END) AS 多排数量
FROM F_PlanItem WHERE QTY > OQTY AND QTY - LQTY > IQTY
GROUP BY GoodsID, ColorID
```

实测（LocalDB，2026-07-28）：`B_Goods.KQTY/KQTY2` 全 0（不是多排数量）；`StockGoods.Weight` 全 0、
`FactWeight` 15,017 行非 0（重量口径只能用 FactWeight，与 FactQTY 同「最新年」语义）。

## 二、新库设计（不照搬视图，货品驱动查余额）

老库 = 12 张视图 JOIN 台账再前端过滤；新库 **货品驱动 LEFT JOIN `stock_balances`**：

- **粒度**：货品×（有余额的颜色）；**无余额货品也列一行（库存 0）**——老系统截图里
  电子件/辅料「全是内容」（含 0 行），balances 驱动会把零库存货品整条藏掉（初版踩坑，已修）。
- **仓库=全部**：跨「参与核算」仓库 `SUM`（`warehouses.is_accountable`，对应老库
  `B_Storage.IsCal=0` 口径）；指定仓库时该仓单行（含幻影仓，下拉可选）。
- **过滤**：货品分类**递归 CTE 子树**（点父类=看全部后代，与货品资料页一致）、仓库、关键字
  （名称/编号/型号/客户型号 ILIKE）。
- **多排数量**：`production_plan_items`（V55，`F_PlanItem` 已迁 7.3 万行）预聚合子查询
  `LEFT JOIN`，`color_id IS NOT DISTINCT FROM` 对齐无色行——与仓库单据/生产计划行为**联动**：
  审核任何出入库单据 → 余额即时变；生产计划量/完工量变化 → 多排数量即时变。
- **不良品仓开关（V81）**：老库 B_Storage 无不良仓字段，新增 `warehouses.is_defective`
  （按名称「不良」识别：成品不良品仓/原材料不良仓，迁移脚本与存量回填同规则）。
  「全部」默认**含**不良仓（=老系统口径）；前端 FilterChip 关掉即 `AND NOT w.is_defective`。
  指定仓库下拉时开关失效（单仓已锁定）。实测两种口径：含 8,392 项有库存 / 不含 8,283 项。
  开关选择**按账号持久化**：`user_preferences` key `stock.instantInventory`
  （复用 V27 偏好机制，前端 provider 缓存+防抖推送，换设备/重登自动带上）。
- **成本金额**：`goods.c_total × 数量`（老库口径；台账 `amount_local` 是采购成本累计，口径不同，不用）。
- **性能**：goods 3.5 万 LEFT JOIN 余额聚合（8.6k）+ 计划明细 7 万行预聚合，全链路一次 SQL，
  `LIMIT/OFFSET` 分页，排序白名单防注入。实测含子树+多排聚合 **~45ms**；全部 3.5 万货品分页浏览。
  未来数据再涨，可加 `goods(category_id)` 索引或把多排聚合物化（本版不需要）。

### ⚠ is_accountable 语义反转 bug（2026-07-28 修复）

老库 `B_Storage.IsCal=0` 表示**参与核算**（View_StockGoods `WHERE IsCal=0`），但
`migrate_warehouse.sql` 初版把 bit 直迁 boolean：6 个真实仓（IsCal=0）全落成 `is_accountable=false`，
而幻影仓 stub 默认 TRUE——**恰好整体反了**，导致「全部」模式只查到 100 多行幻影仓数据、
辅料等分类全空。修复：迁移脚本取反（`NOT COALESCE(...)`）+ stub 显式 FALSE +
存量数据 `UPDATE warehouses SET is_accountable = NOT is_accountable`（16 行两组恰反）。

## 三、V80 + 迁移代码（重量补齐）

| 文件 | 改动 |
|---|---|
| `V80__instant_inventory.sql` | `stock_balances ADD COLUMN weight NUMERIC(18,4)`（IF NOT EXISTS，幂等） |
| `export_legacy.ps1` | StockGoods 导出 SQL 增 `Weight AS weight, FactWeight AS fact_weight` |
| `migrate_stock_docs.sql` | `sg_stage` 增 weight/fact_weight；余额重建带 **最新年 `SUM(COALESCE(FactWeight, Weight))`**（与 FactQTY 完全同口径）；校验段增「余额含重量」计数 |
| `StockBalance.java` / `StockBalanceRepository.upsertBalance` | 实体/upsert 增 weight（增量带方向符号；**null=不动重量**，旧调用方兼容） |
| `StockService.MovementRequest` | 增可选 weight（基本重量=明细 weight×unit_rate）；保留 14 参旧构造器，采购/销售/委外 10 处调用零改动 |
| `StockDocService` | 仓库 8 类单据审核/红冲按明细 `weight×unit_rate×direction` 联动余额重量；**盘点 CHECK 传 null**（盘盈盘亏无单重口径，不动重量防错账） |

**执行（幂等可重跑）**：

```bash
powershell -File export_legacy.ps1 WarehouseDocs   # 重导（stock_goods.csv 现含 weight/fact_weight 两列）
bash server/legacy_migration/migrate.sh --stock-docs  # 重建余额（含重量）+ 流水，重跑安全
```

实测重跑：余额 8,638 行 / 含重量 1,288 行 / 流水 567,145，与老库最新年 FactQTY/FactWeight
逐行比对一致（样本：货品 7119 仓 132 qty 92,850 / weight −1,237.68 双边吻合；负数重量是老库
原始台账数据，如实迁移）。

## 四、后端接口

```
GET /api/stock/instant-inventory?categoryId=&warehouseId=&keyword=&page=&size=&sort=&order=
权限：stock:view（全员基础权限，V45 已种子）
```

- `categoryId` 货品分类（递归子树）；`warehouseId` 缺省=全部参与核算仓库聚合。
- 排序白名单：`qty/weight/costAmount/moreQty/name`（默认 `qty DESC, name ASC`）。
- 行字段：`goodsId/colorId/categoryName(所属类型)/model/cNumber/name/spec/colorName/
  unitName/remark(paper)/weight/qty/costAmount/moreQty`——名称后端一次 JOIN 出齐，
  前端免字典二次解析（与余额页按 id 解析的模式不同，本接口自带 JOIN 更省一次往返）。
