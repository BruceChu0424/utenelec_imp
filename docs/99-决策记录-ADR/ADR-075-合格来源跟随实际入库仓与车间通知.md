# ADR-075 合格来源跟随实际入库仓与车间通知

- 日期：2026-09-08。
- 状态：已接受；源码及数据库回归进行中，发布状态以全平台验收记录为准。
- 依据：用户明确要求采购批次绑定原单，最终在哪个仓库入库就跟随哪个实际仓；到料消息与弹窗发给对应车间负责人。
- 取代范围：[ADR-073](ADR-073-本批物料履约与同主仓分仓领料.md) 中“真实来源跨主仓一律转公共库存”的限制；公共库存的正常仓范围、实际领用和开工规则继续适用。

## 业务规则

计划部只选择主仓，查看该主仓的物料总数和缺口，不需要判断子仓的存放位置。合格库存分散在同一主仓的多个子仓也合并计算；仓库在实际领料时查看每项物料所在的子仓和领取数量。新分析选择真实主仓 UUID；历史分析的叶仓 UUID 保留，显示及预算按真实父子关系归入主仓。

同主仓、同货品、同颜色的公共安全库存只保留一次。初次下达就应根据这个总量判断是否齐料并生成实际分仓领料单，不依赖手动“重新核对备料”修正错误等待状态。实际领料使用本次真实事件及已消耗预留证明，仍保护实际子仓的实物量和其他任务硬预留，不再次扣除子仓安全数。跨其他主仓的公共库存不会因此开放；下列合格专属来源规则继续适用。

新单或修改选择仓库时，停用仓、停用祖先及不符合核算条件的位置不能再选入。但停用存放子仓里已经存在的实物不会消失：仍按原实际仓、货品、颜色和来源参加本任务的合法库存核对，并允许按真实预留清出。不得靠重新启用仓库、改仓 UUID 或补假入库解锁任务；删除仓、未知仓和其它任务专属库存仍不开放。

1. 采购或委外的登记到货、待检、只通过品质但尚未完成仓库入库，都不算可领物料。来源单、验收、实际入库、货品、颜色、原分析节点和数量必须相符。
2. 有上述完整证明的本批合格物料，跟随实际入库的叶仓；允许同批分仓、跨主仓。仓库名称或仓库“不良仓”标记不改变这张已通过验收的入库事实，也不让该仓其它公共或未检库存变成合格库存。
3. 备料、分析明细、入库去向、正式预留、领料单都保留实际仓 UUID。不能将实收记录改名成计划仓，不能串用其它产品、BOM 路径或订单的专属库存。
4. 车间只在本工单所需物料齐全后获得领料任务，各仓分别生成领料单；领齐后由有权限的人员明确开工，开工后才可报工。
5. 委外前置自制仍只生产该委外件本身，子件来自原分析树已有任务。前置自制入库属于该委外任务或原委外订货行的专属待加工库存，尚未完成外加工，不得用于解锁上层成品任务。
6. 取消、退回和撤回沿原单、原入库行和原仓反向办理；有已消费的下游事实时先撤回对应下游。不得靠删除占用、改写旧成本或重新建立另一套任务来绕过。

## 消息与操作

到料后自动刷新受影响分析及执行段。计划可以在物料未齐时下达，故不再给计划制单人发送旧“物料已可下达”提醒。

车间就绪消息按具体执行段发送给当前所属车间及其负责人，并检查当前办理权限。主部门、兼职部门、车间经理或明确负责人均按真实身份关系校验；其它车间、只有查看权、离职、停用及已撤权人员不获得该办理消息。列表、数量徽章、详情和中心弹窗采用同一范围，并在分页前过滤。

到货回调仍是即时主路径。非 cloud 后端启动约5秒后开始自动补偿，每轮结束60秒后继续，修复停机或旧版本漏回调留下的等待任务。每轮最多25个候选、按游标轮转，批内超过3秒不再启动下一项；每项使用独立事务及锁/语句超时，失败项留待后续轮次，清业务期间由现有排水门禁阻止进入。这些是调度上限，不承诺全部积压5秒内处理完。

补偿沿原批准工单的完整物料、原批来源和实际分仓预留规则生成 DRAW 草稿，仍由仓库实际领料、车间明确开工。系统不是虚拟员工：审计记录“系统自动核对备料”，仅受控 FORMALIZE 允许空真人编号并保存固定系统原因；来源原操作人、计划/工单负责人和全部数量事件继续可追溯。其它事件和人工入口仍要求真实登录。

“重新核对备料”保留为有权限人员检查历史等待任务的入口；正常启动和到料恢复不要求员工反复点击。“登记实际用料”只在已有实际物料活动且存在待登记量、有相应权限时可办理。只有历史记录时显示“查看用料记录”，没有物料活动时隐藏实际用料入口。

## 验证要求

真实 PostgreSQL 链覆盖两实仓分批到货（先缺料、后齐套）、其它任务及未检库存隔离、正式预留恢复原仓、直接自制合格入库、委外准备不得冒充最终成品、委外多仓发出与反向。成本另核对非零金额、分仓输出、后到费用和撤回守恒。

主仓汇总回归覆盖 A 仓 30、B 仓 70、安全数 20 的初次下达 80 件，两仓分别领出 30 与 50；单位成本分别为 2 与 3 时，已领未耗成本为 210、剩余库存成本为 60，完整撤回后恢复原仓数量和总成本 270。成本仍按原实际子仓处理，主仓汇总不合并成本池。

通知回归已通过 126 项，其中 6 项使用真实 PostgreSQL 验证接收范围、分页前过滤、各入口数量一致、多仓领料摘要及有界查询；此结果不代替最终提交的全量测试或公司服务器验收。

V540 专项还覆盖停用子仓原库存的真实领出、已启用仓但旧回调遗漏的当前用户副本自动恢复、重复核对不重复预留/审计/通知，以及无系统标记、冒用系统身份和错工单来源被数据库精确拒绝。最终组合验证及公司安装状态仍以统一验收记录为准。
