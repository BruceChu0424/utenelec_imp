# 工资条生成页

> 路由：`/payroll/generate` · 实现：`lib/features/payroll/pages/payroll_generate_page.dart` · Phase 2
> 上层：[页面总览](页面总览.md) · 状态机见 [全局机制 §3.4](../05-架构/全局机制.md#34-工资条审批流payrollslip--payrollbatch)

## 一、当前定位

有 `payroll:generate` 权限的用户按年月和部门范围创建服务器工资草稿、预览服务器返回的结果并提交审核。页面不在客户端计算或修正金额。

## 二、当前四步流程

| 步骤 | 当前实现 |
|---|---|
| ① 范围 | 年份、月份、全员或单个部门 |
| ② 项目 | 开关选择加班、奖金、社保/公积金、个税 |
| ③ 服务器预览 | `POST /api/payroll/batches` 创建 `DRAFT`，展示汇总和前 20 名员工 |
| ④ 提交 | 校验草稿非空后调用 `POST /api/payroll/batches/{id}/submit` |

草稿创建时即生成 `PayrollSlip` 和 `PayrollItem` 快照；提交、审核和发布只推进状态。发布后员工才可见工资条。

```mermaid
flowchart LR
    S1["选择期间与范围"] --> S2["选择薪酬项目"]
    S2 --> D["服务器创建 DRAFT 和工资条快照"]
    D --> V["预览前 20 人及汇总"]
    V --> S["提交为 SUBMITTED"]
```

## 三、金额来源

- 固定薪酬来自员工补偿快照并在服务端解密读取。
- 加班、奖金、社保、公积金、个税及其他增减项仅从对应期间的 `payroll_variable_inputs` 精确读取；开关只决定是否纳入已有输入。
- 当前没有录入或导入 `payroll_variable_inputs` 的 API/页面，也没有政策公式引擎。因而页面文案中的“服务器规则计算”不能理解为系统会自行推算加班、社保或个税。
- 当前页面没有全局调整系数、单元格微调、覆盖旧批次或工资批次导出功能。

## 四、数据与权限

- 实体：`PayrollBatch`、`PayrollSlip`、`PayrollItem`、`PayrollVariableInput`、员工补偿快照和部门。
- 生成/提交需要 `payroll:generate`；审核需要 `payroll:review`；发布需要 `payroll:publish`；读取全部工资需要 `payroll:view:all`。
- 权限由动态权限点决定，不再依据固定的 hr/finance/manager 角色名称。

## 五、边界和待验收项

- 空范围或服务器未生成任何工资条时阻断提交。
- 同期间、同范围只允许一个有效批次；被驳回批次停用后可重新生成，不提供“覆盖”操作。
- 草稿创建成功后页面会锁定范围和项目开关；提交失败可重试。
- 页面提交后跳转员工列表，不保留离线草稿；所有服务器动作都必须在线。
- 变量输入入口、工资政策计算口径、四眼分权、长周期容量压测以及真实 PostgreSQL/E2E 仍是生产验收项。
