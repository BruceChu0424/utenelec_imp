# 委外全链路 SOP：按工序领直属物料、发外加工、分批回厂与退换货

委外是一道放在厂外做的加工工序：委外件 P = 我们把 P 的直属物料发给委外商，委外商加工、组装后交回 P。回厂先来料质检，合格后由仓库实际入库，再按原来源供给上一层生产或销售。公司自有材料和供应商加工费分别留证；财务批准、品质合格、仓库实收不能互相替代。

本页规则以 [ADR-143](../99-决策记录-ADR/ADR-143-委外按工序领直属物料与分批回厂.md)(领直属物料、齐套通知、分批回厂)为准，下单前的物料齐套闸门按 [ADR-156](../99-决策记录-ADR/ADR-156-委外申请物料齐套才解锁下单.md)(迁移说明见 [V809](../数据迁移/V809-委外申请物料齐套才解锁下单.md))，损耗按 [ADR-114](../99-决策记录-ADR/ADR-114-委外损耗独立结清不改订货量.md)，超量到货按 [ADR-019](../99-决策记录-ADR/ADR-019-计划需求分解与采购委外财务审批.md)，改量按 [ADR-072](../99-决策记录-ADR/ADR-072-委外收敛与采购委外订货批准后改量.md) 的受控改量。委外订货不设「允许超收比例」(那是采购的规则，见 [ADR-144](../99-决策记录-ADR/ADR-144-采购允许超收比例与超出部分财务审批.md) §四)。迁移说明见 [275-V798](../数据迁移/275-V798委外按工序领直属物料与分批回厂.md)。

最新验证、未完成事项和发布状态只看[统一验收记录](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)。

## 二、需求来源与领料计划

### 2.1 物料分析下达委外

1. 计划按原订单/需求、货品/颜色、BOM 路径确认 SUBCONTRACT。根层、中层、叶层都按本节点路线处理；委外节点只下达为委外申请，不进车间、不建任何前置自制任务。
2. 委外节点的直属物料照常展开为需求节点，按各自路线下达：A 要自制就先用 A 自己的下层生产 A，B 要采购就采购 B，C 本身也是委外件就先走 C 自己的委外任务(层数不限)。A 完工质检后入库、B 到货质检合格入库、C 回厂合格入库之后，才计入 P 的齐套。
3. P 的未结委外申请对「有可发外直属物料」的 P 计为内部在途：直属物料的需求不会因为 P 已经在途而被抵掉。已批准订货的份额以冻结计划行的物料与单耗为准。
4. 直属物料需求按 P 的计划产出展开：计划产出 = 分摊/申请量 × (申请量 + 公共超量 − 合格入库回厂量)；顶层委外件的计划产出并入来源行的计划产出量。申请量 + 公共超量 ≤ 合格入库回厂量，或订单结清，申请即完成。
5. 物料覆盖逐种计：每种物料的覆盖量 = 待发草稿 + 已发净量 − 按合格入库回厂量折算的耗用(不小于 0)，以该物料的计划需求封顶。交接给委外领料的专属库存视同已收货，不再重复算该物料自己的在途。
6. 委外节点的所有直属物料都用 BOM 设计用量(合同用量)，不用真实使用数量。

### 2.2 缺 BOM 的委外件

委外件必须先有 BOM 才能往下走。「缺 BOM」= 委外件没有一条可发外的直属物料(没有 BOM，或直属边全部不符合 2.4)。

| 环节 | 处理 |
|---|---|
| 物料分析新建或刷新 | 发现缺 BOM 的委外节点，自动给工程研发部建一条「完善 BOM」研发任务并通知研发；同一货品只建一条，后来发现的计划员加入等待名单。该行显示「缺 BOM·已通知研发(研发任务号)」，下达委外的勾选框不可勾。只看有需求的委外节点(需要数量大于 0，或挂着有效的委外供给分配)；需求为 0 的委外节点不标「缺 BOM」，也不自动通知研发。 |
| 下达委外 / 汇总下单 | 服务端同样拒绝：「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善，研发保存后物料分析会自动更新」，并把当前用户加入等待名单。下达、汇总下单预览与提交按货品判定：真要下达的委外件缺 BOM 一律拦下，不看那一行有没有标记。 |
| 研发保存 BOM | 货品现在确有可发外的直属物料时：研发任务自动完成；系统给每张含这个委外件、还没按新 BOM 展开、仍未结束的物料分析各排一条「物料分析按新 BOM 刷新」事件(`MATERIAL_ANALYSIS_BOM_REFRESH`)。事件投递时以分析负责人身份、在独立事务里只刷新这一张(组件表按新 BOM 重新展开出直属物料)；刷新失败按事件队列退避自动重试，不影响其它分析，也不拖住 BOM 事件本身。等这张分析的计划员在它刷新完之后才收到「{货品} 的 BOM 已完善，物料分析已自动更新，可以下达」；分析已结束、负责人账号不可用等不能自动刷新时，改收「{货品} 的 BOM 已完善，打开物料分析刷新后即可下达」。等委外订货单、委外申请或生产计划的人立即收到「{货品} 的 BOM 已完善，可以继续下达 / 下委外单」。 |
| 委外任务中心申请行 | 显示「缺 BOM·已通知研发」(黄，等研发)，不能生成订货单。研发任务被取消而 BOM 仍缺时，行上提供「通知研发完善」重新提醒。 |
| 手工委外订货单 | 可以保存草稿；提交财务时拒绝并提示「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」，同时加入等待名单；编辑页在这些明细上显示红色提示。财务批准时再兜底检查一次。 |
| 旧/手工生产计划确认执行计划包 | 按缺口生成委外申请前检查，缺 BOM 时确认被拒(409 同上文案)，当前操作人加入等待名单，来源记生产计划单号；研发保存后通知直达该生产计划。 |

### 2.3 委外部门直接新建订货单

直接单(没有物料分析来源)只能领公共库存；下单本身也只能按公共库存够做的套数(2.5)。缺的物料在任务详情显示「还缺」与「供应来源：未安排」，状态为「等计划安排」，由计划另行安排。系统不再为直接单自动建任何前置分析，订货单也不再有「内部生产入库仓库」字段。

### 2.4 可发外的直属物料

只有「按件用量、生产投入阶段(开工 / 装配 / 完工)、按单领料(不是整批定期领料)、用量大于 0、不是系统占位货品」的直属边才发给委外商。按包装 / 固定批量、出货阶段、整批定期领料的边不发外。判定只有一个数据库函数 `fn_subcontract_draw_edges(goods)`：计划冻结、物料分析展开与内部在途判定、可用量与精确归属都只用它。

物料颜色 = BOM 边颜色，边上没填就取物料默认颜色；财务批准时与单耗一起冻结，分析节点、可用量、精确归属用同一口径。

### 2.5 下单前物料齐套才解锁(ADR-156)

委外加工价每天不一样，财务批准订货单那天价格就定了，所以直属物料不齐时不让生成委外订货单；现有物料够做几套才能下几套，没齐的部分继续锁着，物料再到再解锁。

1. **能用的物料**：每张委外申请明细 = 它自己的专属批次(物料分析分给这张申请的委外节点的直属子节点的库存权益，只算可用仓) + 公共可用库存。逐种物料计，A 的库存不能替 B 放行。
2. **已被占用**：还在办的委外订货单(草稿、在审、财务退回、已批准未结案)按每种直属物料「还要领的量」占物料——已批准的按领料计划行(需发 − 已发 − 已提交未发)，没批准的按 BOM 整单算。有来源申请的部分先占那张申请的专属批次，不够的部分和手工行、超出申请的部分占公共库存。占用只参与计算，不在仓库里预留。
3. **可下单** = MIN(剩余未下单数量, 现有物料扣掉占用后够做的套数)。剩余未下单 = 申请量 − 已下单 − 已送审订货单的来源份额。
4. **任务中心「待处理」**：可下单为 0 的申请行显示「等物料齐套」，不能勾选、不能生成订货单，但照样留在本段、照样计红数；能下一部分的显示「可部分下单·可下单 N」；缺 BOM(2.2)优先。行上「齐套情况」逐种物料列每套用量、需要、专属库存、已被占用、现在能用、还缺、够做套数。
5. **生成订货单**：勾选的申请按需求日期先后共用公共库存，预填各自这次能下的数量(为 0 的明细不预填)。可以改数量，改大(包括超过申请剩余量)要物料够。
6. **守卫**：生成委外订货单、保存草稿、提交财务、财务批准、批准后加量，都按同一口径核对，不够就 409「直属物料还没齐套，不能{动作}：「物料」本单需要 x，现在能用的只有 y…」；删除草稿、减量、红冲、结束领料不拦。两人同时下单按物料串行判定。
7. **提醒**：申请可下单量比上次提醒时多，采购委外部门能生成订货单的人收到「委外可下单」行动卡(见第七节通知表)。

所有数量只在服务端算一次(V809 的 SQL 函数)。下单之后照 2.6 起的流程走：财务批准冻结领料计划、领料、发料、分批回厂。

### 2.6 财务批准冻结领料计划

财务批准时，每个订货明细按当时的可发外直属边，每种物料冻结一条领料计划行：物料、解析后颜色、单位、冻结单耗 `b = ROUND(订货单位换算率 × BOM 边用量, 6)`、计划量 `f(Q)`。单耗为 0 时批准拒绝并提示。批准之后 BOM 再改不影响这张单：可用量、精确归属、锁维度全部按冻结计划行读取，不读现时 BOM。批准不建出仓草稿、不占库存，只触发一次「领料重算」。

## 三、商业审批与改量

一张订单一个委外商及一套兼容商业条件；批量录入不同条款时按明确条件拆成真实订单。财务冻结供应商、币种、有效汇率、税率、结算方式、单价、单位换算和来源，批准订单不产生应付。操作权、归属范围、认领和快照版本由服务端校验，不能用查看权限替代审核权。

建单、改单、送审、批准都要直属物料齐套(2.5，ADR-156)：批准即锁定当天委外价，物料必须仍然够做本单的数量；送审、批准时物料已被别的单或生产用掉的，409 并提示委外人员把数量改成任务中心的「可下单」数量或等物料到了再提交。批准之后物料够不够只影响能领多少(第四节)。

批准后修改走 `change-qty`，不是普通全量编辑：合法改量立即生效，同事务记录 old→new 和来源份额变更并创建复核 case。当前有待处理复核时不叠加另一份修改。复核通过不重复生成预计供给；驳回保留已生效数量和历史，制单人按原因处理，不能自动撤回已发生物流。

改量时每条领料计划行按新订货量重算 `计划量 = f(新订货量)`，不做增量累加。加量要直属物料齐套(不够 409「不能加量」)，减量不看物料。缩量下限 = MAX(各物料已发外与待发量反算的最小订货量、委外商处结存反算、已回厂下限)；已提交未发的领料必须先撤回，否则 409 并列出这些领料单。增量不超过原来源可订容量；按[来源份额对账](../数据迁移/119-V503批准后改量的来源份额与生产挂接对账.md)返还未履约份额，原 BOM/需求不随商业减量被抹掉。

## 四、领料与发料

### 4.1 数量口径(只在服务端算一次)

记订货明细的订货量 `Q`(订货单位)，第 i 种物料的冻结单耗 `b_i`：

- 套数 → 物料量 `f_i(S) = CEIL(S × b_i, 4)`；物料量 → 套数 `sets_i(x) = TRUNC(x / b_i, 4)`。所有套数结果再取不超过 Q。计划量 `planned_i = f_i(Q)`。
- 已发净量 `sent_i` = 已审核发出 − 材料退货；待仓库发 `pending_i` = 已提交、仓库未发出的领料量；已覆盖 `covered_i = sent_i + pending_i`；仓库可用 `avail_i` 见 4.2。
- 行级显示量(订货单位)：
  - 已领 = 不超过 Q 的 `MIN_i sets_i(sent_i)`
  - 待仓库发 = 不超过 Q 的 `MIN_i sets_i(covered_i)` − 已领
  - 可领 = 不超过 Q 的 `MIN_i sets_i(covered_i + avail_i)` − 不超过 Q 的 `MIN_i sets_i(covered_i)`(不小于 0)
  - 还缺 = Q − 已领 − 待仓库发 − 可领
  - 恒等式：已领 + 待仓库发 + 可领 + 还缺 = 我方供料套数 Qm(没有财务批准的委外商自带料时 = 订货数量；有自带料时 Qm = 订货量扣掉自带料、不低于已领套数，可领与「料已发完」都按 Qm，ADR-143 §三.4a)。
- 物料级：需求 `planned_i`、已发外 `sent_i`、待仓库发 `pending_i`、仓库可用 `avail_i`、本次可领、还缺 `MAX(0, planned_i − covered_i − avail_i)`；还缺为 0 的物料计为「已备」。
- 「领满」只按物料判断：每种物料 `covered_i ≥ planned_i`，从不用套数等于 Q 判断。

### 4.2 本任务能动用的库存

作业叶仓(未删除、非不良品仓、非线边/内料仓)里该物料、该冻结颜色的合格可用量 = 本订货明细来源分析的精确专属批次 + 公共可用量(已扣他人预留)。逐种物料计算，A 的库存永远不能放行 B。顶层委外件的直属物料，精确批次取来源行第一层节点；合并了多张申请的订货明细，精确批次按该物料下全部在途申请 / 订货明细分摊，不重复认领。

### 4.3 委外人员提交领料

1. 委外任务中心「待处理·领料」子分类一行 = 一条已获财务批准、领料计划未关闭、订货明细未结清、还没领满的订货明细。状态：可领 N {单位}·去领料 / 已提交领料·待仓库发料 / 等计划安排·缺 k 种 / 等待物料·已备 a/n 种。「等计划安排」= 还缺的物料里有一种没有任何在途供应；在途供应(任务详情「供应来源」)= 已审采购申请未下单量、已审未关闭的采购 / 委外订货单未合格入库量(加回已退货量，委外再扣已结损耗)、已审委外申请未下单量、有效生产计划未成品入库量。嵌套委外的直属物料 C 从 C 的委外订货单财务批准起就算「委外在途 x(订货单)」，C 回厂登记后待检、待入库期间仍算在途，所以 P 显示「等待物料」而不是「等计划安排」，直到 C 合格入库后计入 P 的齐套。
2. 勾选可领的行进「批量领料」，或点状态里的「可领」直达领料页。领料页按「交期、订货单号、行号」顺序联合分配共享物料，默认值 = 联合分配后的本批可领量；改数量后 300 毫秒去抖重新预览物料表与预计出仓单张数。
3. 提交时在锁内按同一顺序重算：实时可领低于提交量才 409，并逐行返回实时可领量，页面一键按实时值重新填写。成功后每次提交按「订货单 × 仓库」新建委外材料出仓草稿(永不并入已有草稿)，每行记下领料数量，占用库存并接收专属归属，每张草稿通知所在仓库。同一个幂等键重复提交返回同一结果。幂等键每次尝试一个：领料页每次打开或重新加载、每次得到明确结果(成功或明确拒绝)后都换新键，只有结果未确认(网络、超时、服务器错误)时才沿用同一键重试。撤回后再提交一定是新键；旧键重放时如果它对应的领料已撤回、已被仓库退回或已变化，返回 409「这批领料已撤回或已变化，请重新打开领料页后再提交」，不会复活已撤回的草稿。
4. 同一委外任务可以反复提交领料，直到领满订货量；后续物料再到货，可领量增加就再提醒。

### 4.4 仓库发料

- 仓库只能把某行改少(不超过委外人员提交的领料数量)，不能改多、不能加行；改少立即释放多出的预留。核对实际仓与库位后审核出仓，已发净量随之增加。
- 某种物料这次整行不发：拣货页本次数量填 0 = 本次不发。保存时这一行从草稿删掉(软删并记 `warehouse_dropped_at`，提交的领料数量原样保留)，它的预留随之释放；一张草稿至少要发一种物料。
- 仓库少发某一种时：本批应发 A 40、B 80，实际只发 B 60，之后的可领量按「已发齐的完整套数」重新算，下次领料先补齐落后的 B(再发 20)，不会多发领先的 A。发料通知写明「少发：B 20(下次领料自动补齐)」；填 0 不发的物料按它的整行提交量列进「少发」。
- **退回委外(不发)**：整张领料发不出(缺货、料损等)时，仓库在拣货页点「退回委外(不发)」并填写原因(必填，不超过 200 字)，权限与审核出仓同一道门(`subcontract_outbound:view + execute`)。不论仓库是否改过拣货数量，服务端按撤回领料的锁顺序作废这张草稿的全部领料行与草稿头、释放它的全部占用(专属批次退回原分析)、重算可领，并通知提交领料的委外人员(含原因)。只动这一张草稿：同一任务在别的仓的待发领料、领料计划都不受影响(它不是已删除的「不再出仓」)。仓库仍不能删单、不能删光物料行。
- 仓库不生成草稿；不想再发料由委外人员在任务详情「结束领料」。

### 4.5 撤回与结束领料

- **撤回领料**：仓库发出之前，委外人员可按订货明细撤回未发出的领料，预留与专属归属原样退回，并通知仓库已撤回(全部撤回时通知直达待发料列表 `/warehouse/subcontract-outbound`)。仓库已经保存过拣货修改的领料不能撤回(409，提示请仓库在拣货页退回)。
  - 「仓库已改过」= 草稿被仓库保存过，或本明细的某行数量已不等于提交量，或某行被仓库填 0 删掉。任务详情把这类领料标「仓库已改过」；只有至少一张待发领料没被仓库改过时才给「撤回」，确认框只列能撤回的。撤回仓库已改过的领料返回 409「领料出仓单 X 仓库已开始拣货并修改过，这边不能撤回；请联系仓库在拣货页把这张领料退回」，这类领料的出口是仓库的「退回委外(不发)」(见 4.4)。
- **结束领料(不再发外)**：委外商做不完或物料停用时，委外人员在任务详情填写原因结束领料：撤回未发领料(包括仓库已改过的：结束领料就是不再发，强制撤回，仓库照常收到「委外领料已撤回」)、释放预留、关闭该明细的领料计划行，并对该明细重新评估短交。

### 4.6 委外商退回我方材料

材料退货审核减少该物料的已发净量，退回的料重新入库后可再次领料；退料红冲把已发净量加回，若这些料已被重新领出导致超过计划量则 409「退回的料已重新领出，不能红冲退料」。订货明细已结清(合格入库 + 已结损耗 ≥ 订货量)或领料计划已关闭后，余料退回不会让任务重新出现在「待处理·领料」里。

### 4.7 唤醒与可领提醒

库存的每笔入库、预留释放(撤回、仓库改少或填 0、仓库退回委外、结束领料、订单红冲)、财务批准、改量之后，事务内只追加一条「领料重算」事件(按物料去重)，不读齐套、不加锁；事件投递时(事务已提交)才计算受影响订货明细的可领量并更新提醒卡。可领量比上次提醒时增加才重新提醒；可领为 0、提交领料、结束领料、红冲时消除提醒卡。委外订货单建单、保存、删除、红冲、改量后也按本单用到的直属物料追加这个事件；同一次投递顺带重算用到这些物料的委外申请可下单量，更新「委外可下单」提醒(2.5，ADR-156)。

## 五、回厂、品质与实际入库

**可回厂量**：委外商处能做成 P 的物料 `usable_i` = 已发出 + 补发 − 已退回 − 已记损耗(= 已核销 + 结存)；可回厂套数 = 不超过 Q 的 `MIN_i sets_i(usable_i)`。累计回厂(物料口径) ≤ 可回厂套数 + 财务批准的委外商自带料 + 已退回的质检不合格量。到货登记、回厂单保存与审核、发料红冲容量、到货任务可见、回厂提醒都用同一段服务端算法；直属物料还没发给委外商时不能登记回厂(「请先在委外任务中心领料并由仓库发出直属物料」)。

1. 仓库从订货单登记回厂，服务器继承商业字段和行 UUID。真实仓库在到货时确定，同主仓允许范围和跨主仓处理依原来源规则；不能把客户端供应商/价格替换为新来源。
2. 订单正常未回容量与已退未补容量分开。两者并存时明确 NORMAL 或 RETURN_REPLACEMENT；自动识别只适用于无歧义情况。正常超到按异常/批准量处理，未批量不写应付/可用库存；不能借补回额度掩盖正常超到。
3. 回厂审核核对实物容量和超量授权，冻结价款切片并建立待检。新增应付只取本次实际应付加工费；免费补回不生成零应付，已贷后重新计款只计对应份额。应付不是公司自有材料价值。
4. **回厂核销按目标跟踪**：回厂单审核时写入本行的物料口径回厂量 = 回厂量 − 本单质检补回分配 − 财务批准自带料(之后不随实时状态重算)。R = 有效(未红冲)回厂明细的物料口径回厂量之和；每种物料本次核销 = `MAX(0, f_i(R) − 当前有效核销量_i)`，按发料先进先出(发料日期、创建时间、行号)切片；红冲按记录的切片原样退回，下一次回厂自动纠正尾差。数据库守卫逐种物料校验：核销量 ≤ `usable_i`，且与 `f_i(R)` 的差 ≤ 已红冲回厂行数 × 0.0001。
5. 品质可以分批合格/不合格。每次合格只增加合格待仓库入库量；仓库按实际数量、重量和叶仓确认后才写库存、刷新原分析和供给，未检/不合格不进入可用库存。
6. 同单其它待检行不阻塞已合格实收切片；每个实际入库增量独立幂等。领出发外的直属物料实耗与加工费按真实来源合入委外件库存成本；免费补回沿原资金/原收货来源，不重复耗用原料。

**回厂超过我方供料能做成的套数(ADR-143 §二.12)**：多出来的那部分实物只可能是委外商贴了自己的材料，这是价格和归属问题。登记照收不拦；审核时多出来的部分不入库、不立应付，页面提示「回厂数量超过我方发给委外商的材料能做出来的数量，多出来的部分用的是委外商自己的材料；本次未入库、未立应付，已转交财务审核组确认价格和归属」，单子进到货异常等财务判定(ADR-019)。只有财务批准过的自带料份额才不计入物料守恒核销；财务批准的自带料入库时不消费我方物料。

**入库放行闸按收货单**：一张收货单里任一行待判定，整张先不入库；同一订货单的其它收货单不受影响。

公司材料发出后进入供应商保管/在制，仍属公司价值，不是销售或立即耗尽：

```text
每种物料：实际发出净量 = 合格回厂核销 + 明确损耗 + 供应商处结存
```

材料退回、回厂核销、损耗和各自反向使用同一发料来源；同货品其它批次不能掩盖超耗。领料、发料、回厂、品质和实收各有独立进度，不把其中一个「完成」标签当作整链结案。

一批免费补回含多个原失败批次时，可保持员工一次确认，内部按原材料/费用来源边界拆实际库存明细。不能把加工费为 0 误解释为免费库存，也不能将两个原批次的自有料合成一个猜测来源。

## 六、普通退货、来料质检拒收与实际贷项

| 情形 | 处理 |
|---|---|
| 合格且实际入库后的普通退货 | 表头商业身份从原收货行 UUID 派生；有来料质检的行按已解决品质及实际未退入库量校验，不能只看合格或同货品总库存。物理退回和金额追加记录，反向关联原流水。 |
| 来料质检不合格 | 先保留品质事实，再由可靠 Outbox 幂等建拒收 case。建案/财务投影失败不能回滚已成立品质；异常保留物流事实，按原来源恢复。 |
| 不合格实物退回 | 在实际退回动作记录日期、退回单号、经办及事件；不冒充合格普通退货，不直接生成贷项。再次失败必须本代再次实退才能再补。 |
| 未取得供应商贷项的补回 | 沿原订单、原资金和原价值免费履行，预占不等于结清；合格且仓库实收后才结清对应份额。 |
| 已取得贷项后再补 | 原贷项保留，新收货按已贷份额重新计款；不得又使用原免费权益。 |
| 部分/跨案实际贷项 | 选择同一个原应付，输入真实凭证 A 和明确 case/version/qty/A 分项，服务端预览共同 book B 与余额，确认必须携最新 hash。不是按全部失败数量自动生成全额负应付。 |
| 无贷项结案 | 只走明确合法的零金额/已证明履行语义；非零未结份额不能靠改状态消失，不能制造零应付或伪造免费来源。 |

当前案件会出现 PENDING_RETURN、RETURN_RECORDED、CREDIT_CONFIRMED、CLOSED_NO_CREDIT、FINANCE_EXCEPTION、REVERSED 等状态；结清还要看资金切片、实物补回、实际凭证和剩余量，不能只看一个状态名。反向一张实际凭证须反向全部关联 case 分项及其抵销，保留原凭证，并检查后续是否已使用对应来源。

原应付及负应付消费同一个冻结 BookAllocationPlan，先按可抵未付份额抵销，剩余供应商贷项继续开放；不能为了结清原单丢差额。待检/未解决的失败份额执行统一付款、普通抵销和月结 hold，专用合法同源动作使用其明确许可；不能因本次免费补回无新应付就丢掉原冻结。

完整请求/响应、共同 SQL 守卫和前端合同在[采购与委外到货退换货实现与验收](../99-项目治理/采购与委外到货退换货实现与验收.md)。

## 七、短交、损耗、成本、权限与通知

**短交与损耗(ADR-098 / ADR-114)**：

- 「料没发完不判短交」：每一种直属物料的已发净量都达到计划量，或该明细已结束领料，才算发完。料是在最后一批货到齐之后才发完的，在仓库确认入库那一刻补开案件。判定的锁只锁短交的那一行，同单其它已经足额到齐的货照常入库。
- 容差内自动结案：下单约定过允许损耗、本行的料已经全部发出、累计回厂落在允许损耗范围内时，仓库确认入库那一刻按接受损耗独立结清——开损耗单、案件记成接受损耗并留下实际损耗率；**订货量不改、来源申请余量不释放、不开财务复核**。低于下限的、以及没填允许损耗的，仍由委外人员判「再等一批」还是「接受损耗」。结案之后又来货算超收，走第五节财务那条路。
- 整单结损耗时，把委外商处每种物料的剩余结存全部记损耗，不按短交量 × 单耗重算(避免 0.0001 尾差)。
- 不做委外损耗后的补发料。

损耗确认供应商处公司材料的实际去向，不再扣一次公司仓。正常允许损耗进入合格产出成本，超额部分独立为异常损失；实际索赔/现金赔偿/合法抵销与物理损失分别留证，不能自动相互净额。价格折让需真实贷项/税额来源，普通进仓不能冒充免费实物赔偿。实际源材料/加工费、正常/超额与反向见[库存实际成本接线](../99-项目治理/库存实际成本接线与验收.md)。

**成本完整性**：回厂明细在每种冻结物料的核销都达到目标量时即为完整(计价 FINAL)。

**权限**：

- 新权限点 `subcontract_order:draw`「委外领料(提交、撤回、结束领料)」，授予已持有 `subcontract_order:submit_finance` 的部门与个人加授；查看「待处理·领料」子分类、任务详情、预览只要 `subcontract_order:view`。对象级范围沿用委外订货单的经手人可见规则。
- 页面查看、跨归属查看、金额查看及 record_return/confirm_credit/reverse 等动作分别授权；金额遮蔽时不能从精确值、预览或其它接口回读。服务端 `allowedActions`、版本和对象范围是最终门槛。
- 财审认领/续期失效则暂停决策，不能把旧页面按钮可用当审批有效。

**通知**(面向人的正文不出现代号)：

| 事件 | 收件人 | 内容与生命周期 |
|---|---|---|

## 九、不变量

1. 每条领料计划行 0 ≤ 已发净量 ≤ 计划量；每种物料已覆盖量 ≤ 计划量。
2. 领料只能在财务批准之后、计划未关闭、明细未结清时提交；本次数量 ≤ 锁内联合分配后的实时可领量。
3. 仓库实发 ≤ 委外人员提交的领料数量。
4. 可回厂量按「委外商处可做成 P 的完整套数」，不把各物料折算后相加。
5. 每种物料累计核销与 `f_i(R)` 的差 ≤ 已红冲回厂行数 × 0.0001，且 ≤ 委外商处可用量；委外商处结存 ≥ 0。
6. A 的库存、已发量、专属归属永远不能替 B 放行。
7. 下单要直属物料齐套：只能按现有物料(专属批次 + 公共可用库存，扣掉还在办的委外单要领的量)够做的套数下单，建单、保存、送审、批准、加量都核对，减量不拦(ADR-156)；所有数量只在服务端算。
8. 缺 BOM 的委外件不能下达委外、不能提交财务、不能被财务批准；已批准的委外订货明细一定有冻结计划行。
