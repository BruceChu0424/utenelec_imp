# ADR-165 车间到货通知产能水位与车间负责人受众

- 状态：已接受（2026-10-06，V815；修订 ADR-091 §2.3/§八 的到货进展闸门与受众条款）
- 关联：ADR-091（开工路线确认与到货进展通知）、ADR-095（车间路线随时可换）、
  ADR-096（三条路线通用）、ADR-149（仓库通知「负责人∩池, 为空发整个池」兜底形状）、

## 一、背景（用户口径）

「物料到货进展」行动卡（`PRODUCTION_WORKSHOP_TASK_ACTION_REQUIRED`，进中央弹窗）此前的
闸门（ADR-091 §八，2026-10-06 上午）是布尔值：分批/持续路线只要
`start_material_ready` 或 `prepared_capacity>0` 就发卡。布尔一旦为真，之后**每一次到货
事件**（每种料到齐各触发一次 IQC 入库/成品入库/直送）都会「撤旧卡 + 发新卡」再弹一次窗，
即使可生产件数根本没涨——「一种物料齐了就弹一次，太烦人了」。

用户给的正确口径：

1. **每种物料都有一部分了**（可支撑产量 > 0）才首次弹「可以生产 X 件」；
2. 之后又来物料但**不能支持生产更多**（可生产件数没涨）→ 不弹；
3. 又来物料**能支持生产更多**（例如扣掉之前已领料支持的 20 件后还能生产 100 件）→ 再弹；
4. 弹窗只给「**有权限 且 是该车间负责人**」的人——计划部有权限但不是车间负责人，不弹。

## 二、决策一：到货进展卡按「可支撑产能水位」弹（替换 §八 的布尔闸门）

`ChainNoticeService.publishWorkshopMaterialArrival` 的闸门
（`arrivalProgressWarrantsNotice`）改为**产能水位差**：

- **可支撑产能按路线取口径**（`workshopArrivalCapacity`）：
  - **BATCH**＝分批领料核对页的「当前可齐套生产量」，与页面**同一个数**——
    `ProductionExecutionBatchService.currentSplitCapacity`（由 `maximumReadyQty` 抽出，
    冻结耗用曲线二分 × 仓库可用量（专属权益 + 公共预算扣安全库存），剩余段自动扣前批）；
    不可计量（路线已改、前批固定料未领齐、尺子缺位等）返回 null，不发卡、水位不动。
  - **CONTINUOUS**＝已备预留产能 `fn_execution_material_output_capacity(segment, FALSE)`
    ——已领走的料不占这口径，「还能生产多少」只算没领的；领料后产能回落，水位跟着回落。
  - **FULL_KIT**＝齐套全有或全无：只在 WAITING 且仓库口径盖住全部缺口时为 `planned_qty`，
    否则 0（READY 及之后由齐套/可开工行动卡接管）。
- **水位列** `production_execution_segments.arrival_notice_capacity`（V815，NULL＝从未评估按 0）。
  每次到货事件评估后同步成当前值（`syncArrivalCapacityWatermark`，值不变不写，
  `IS DISTINCT FROM` 防抖）：上涨发卡时抬上去，回落时落下来——「涨了」永远相对最近一次，
  领料回落不会被旧水位压住（回落后再涨到新高就再通知）。
- **发卡条件**＝`当前产能 > 水位`；弹窗文案带「（现有物料可支撑生产 X 单位）」。
- 保持不变：路线未确认不发；会自动提升的段（WAITING ∧ `auto_promote_when_ready` ∧
  路线放行）不发——齐套/可开工行动卡由 `publishWorkshopTask` 体系负责，且
  ARRIVAL_PROGRESS 办结会把刚投递的 important 卡撤掉；到货撤销（`validArrival=false`
  的「物料状态更新」）不受闸门约束仍即时通知（并同步水位）。
- §八 的「部分到货撑不起部分生产→静默」语义由「产能 0 不涨不弹」自然涵盖；
  「IN_PROGRESS 不发」条款废止——分批/持续路线生产中产能回涨（补料解锁更多产量）
  现在会按水位差正常通知。

## 三、决策二：车间任务行动卡只发车间负责人（受众收窄，波及全部车间任务卡）

`ChainNoticeService.workshopRecipientUserIds` 收窄：

- **收件人＝（车间（含下级班组）各部门负责人 `departments.manager_id` ∪ 任务负责人
  `responsible_employee_id`）∩ 当前有效权限**（`notice:read` + `production_execution:view`
  + `production_execution:start`/报工，`ReviewNoticeAudience.canHandleWorkshop`，含个人回收）。
- 计划部等职能岗即使**个人加授**了车间任务权限，不是车间负责人也**不收卡**（此前可经
  个人加授/兼职混进收件人，是用户点名的口子）。
- **兜底**：车间一个负责人都没登记且任务无负责人时，退回旧的全成员池
  （主职/兼职/各级负责人）——与 ADR-149 仓库通知「负责人∩池, 为空发整个池」同一形状，
  任务不能无人感知。
- 波及面：`publishWorkshopTask`（备料中/齐套待领料/领齐可开工/持续生产进展）与
  `publishWorkshopMaterialArrival`（到货进展）共用该收件人，全部收窄；车间成员仍可在
  「我的车间任务」页看到任务（页面范围 `workshopScope` 不变），已收到的卡仍按车间范围可见。

## 四、验证

- `WorkshopArrivalNoticeRegressionTest`：产能涨才弹 / 不涨不弹 / 回落后再涨再弹 /
  齐套全齐只弹一次（多余到货静默）/ 尺子不可计量静默且水位不动 / 撤销仍即时重建并同步水位 /
  开工就绪信号不再触发到货卡。
- `ProductionWorkshopMaterialNoticeContractTest.arrivalProgressCardGatesOnProducibleCapacityWatermark`：
  源码契约（布尔闸门 `partialStartCapable` 退役、水位比较与同步存在）。
- `ChainNoticeProductionWorkshopScopeTest` / `WorkshopNoticeScopePostgresTest`：
  负责人优先（不含普通成员/兼职）+ 无负责人兜底全成员池。

## 五、迁移

V815 `workshop_arrival_notice_capacity_watermark`：`production_execution_segments` 加
`arrival_notice_capacity numeric(18,4)` 列（只由通知投递线程在段行锁内更新；表为 FULL
行级审计，水位变化自然留痕，无需登记）。
