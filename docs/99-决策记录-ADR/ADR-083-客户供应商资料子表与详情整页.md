# ADR-083 客户/供应商资料子表模型与详情整页

- 状态：已接受（2026-09-14，V579）
- 关联：迁移 [171-V579](../数据迁移/171-V579基础资料子表与客户信誉分.md)、页面 [基础资料页](../03-页面/基础资料页.md)

## 背景

1. 客户/供应商联系方式与地址全是平铺单值列（mobile/phone/phone2/fax/email/website/address/ship_address），无法登记多个联系人电话或多个地址；手机必填造成录入负担。
2. 「负责人」列显示数字：老库 `emp_id` 存 legacy 数字，仅 V261 对能唯一匹配 `employees.legacy_id` 的行回填了 `owner_employee_id`；供应商列表 DTO 干脆没有姓名字段。
3. 双击行弹出 560 宽固定两列的详情弹窗，大屏利用率低、需要上下滚动。
4. 没有客户行为记录与信誉分载体（`clients.credit` 是旧库只读快照）。

## 决策

### 1. 子表模型（V579）

三张 party_type 多态子表：`party_contact_methods`（多联系方式，含主选）、`party_addresses`（多地址，含默认）、`party_activity_records`（跟进/投诉/违约/奖励，可带 ±100 信誉分变动）；`clients.credit_score` 可空列（NULL=从未评估，首条评分按 100±delta 初始化，累计夹 0–200）。

**平铺列保留为兼容层**：单据、导出与老接口继续读平铺列；服务端在子表变化时把「每类第一条（主选优先）」同步回平铺列。两套口径由服务端单向收敛，不允许漂移。

### 2. API 与权限

`/api/master/clients/{id}/contact-methods|addresses|activity-records|credit-score` 与供应商同构；读写分别复用 `client:view/edit`、`supplier:view/edit`，**零新权限码**。

### 3. 详情整页替代弹窗

双击列表行进 `/basicinfo/client/:id`、`/basicinfo/supplier/:id`（对齐货品详情整页范式）：

- 基本信息用 `UtenFormGrid` 按容器宽自适应列数（大屏一行 4–5 列）；
- 联系方式/地址/跟进记录三个管理分区（添加/删除，客户另有信誉分展示）；
- 右下悬浮操作组：编辑、负责人和可见人（客户）、启停、删除；
- 编辑表单抽取为公共模块 `client_master_edit.dart` / `supplier_master_edit.dart`，分类页与详情页共用同一套字段与保存流程。

**口径修订**：联系人改必填（单据/物流找得到人），手机不再必填（多联系方式在详情页逐条登记）。

### 4. 其余主档弹窗响应式

`master_edit_dialog` / `master_detail_sheet` 宽度从固定 560 改为 `clamp(屏宽 92%, 560, 900/840)`，网格列数按容器宽 1–4 列自适应——其他仍在用弹窗的主档同步受益。

### 5. 负责人显示姓名

- 供应商列表 DTO 补 `ownerEmployeeName`（按 `owner_employee_id` 解析）；
- 客户/供应商列表列在 owner 为空时显示「未分配」而不是裸 legacy 数字（老库未匹配行无法解析出人名，如实展示）。

## 后果

- 新登记的联系方式以子表为准，老数据全量回填，单据侧零改动；
- 系统测试清空白名单新增三表 PRESERVE（372→375）；
- `clients.credit`（旧库快照）与 `credit_score`（新信誉分）并存：前者只读对照，后者由跟进记录驱动，不互相换算。
