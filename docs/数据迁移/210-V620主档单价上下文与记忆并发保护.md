# V620 主档单价上下文与记忆并发保护

## 业务规则

未来录单的共享默认值直接存放对应主档。货品保存供应方式、默认供应商、常用存放仓、生产车间与负责人；客户保存销售条款；供应商保存结账方式、币种、税率。个人表格列宽、筛选、页面选择属于用户偏好，继续留在用户偏好机制。已确认路线、订单金额、真实库存、执行车间属于历史交易事实，不由主档默认值反向改写。

供应方式在准备页修改后，经确认立即提交与分桶一致的路线命令。同一事务保存分析行确认及货品来源；取消不写入。新分析读取货品主档，已有分析的人工确认保持不变。无需恢复已退役的 `/last-routes` 和历史扫描。

## 价格为什么需要上下文

只保存一个数值不足以表达价格。78 元/箱不能被解释为 78 美元/个；同一供应商为另一件货更改默认币种，也不能改变此前价格的含义。采购、委外在 `goods` 分别新增五列：

| 后缀 | 含义 |
|---|---|
| `price_supplier_id` | 该价格的供应商 UUID |
| `price_color_id` | 该价格的颜色 UUID，可空表示无颜色 |
| `price_unit_id` | 原订单行单位 UUID |
| `price_currency_id` | 原订单币种 UUID |
| `price_tax_rate` | 原订单税率 |

列前缀分别是 `default_purchase_`、`default_subcontract_`，仍复用既有 `default_purchase_price` 和 `default_subcontract_price`。保存按货品去重，同单同货取最大 `line_no` 的有效明细，只有行号缺失或相同时才用创建时间与 UUID 保持确定顺序。不能把随机 UUID 的大小当成用户可见行顺序。空价保留此前整组价格与上下文。

两类单据共用 `ProcurementMasterDefaultsSyncService`。写入前按 goods UUID 统一锁序；供应商条款成对写 UUID 与结账方式 legacy 影子。软删/撤销/红冲单不学习。商品、客户、供应商、归属车间、入库归属仓的每次真实改动同时递增主档 `version`，陈旧主档编辑表单必须刷新；值不变不落盘。审计操作者使用外层事务的 `app.actor_id`。

预填接口仍为 `/last-terms`，主档价格额外返回 `priceContext`。普通 `view` 仅可获取默认供应商；价格及商业条款仍受各单据独立 `price:view` 或财务全域权限保护，与详情接口使用同一脱敏判断。供应商条款仅用于同一供应商，汇率也必须匹配币种。单价仅在供应商、颜色、单位、币种、税率全部匹配且必要上下文完整时预填。后续修改货品/颜色/单位/供应商/币种/税率，尚未被人工确认的系统预填价自动清空；复制行保留自动价来源并绑定新行监听，不能因复制变成人工价。异步预填以行级修改代际保护，即使用户输入后又清空也不能被迟到响应重新填上。用户输入或完成价格编辑即视为人工确认，即使数值与预填相同也保留。货品详情仅向 `goods:cost:view` 授权人展示两价及原计价上下文，旧数据缺维度明确提示核对。

## 存量迁移与导入

V620 只增加可空列和真实主档外键，不改任何既有价格、单据、库存、金额或历史来源。不推测旧价格对应的单位/币种：旧价格保留供查看，上下文为空时不自动预填，下一次正式保存订单时学习完整上下文。旧库导入脚本无需为这些列编造数据；其省略新列的 INSERT 自然留下 NULL，执行全部前向迁移即可兼容。

无新增业务表；货品现有审计触发器会记录列变更。清库仍保留货品及其默认值，无新的清空表策略。所有新增字段按货品主键读，不对历史订单实时扫描；无需为仅做预填投影的列增加低选择性索引。
