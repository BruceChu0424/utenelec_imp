# ADR-186 原材料行情手动关联与离线预测

- 日期：2026-10-20
- 状态：首版源码实施；真实行情回测、生产启用和采购岗位验收分别留证。
- 关联：[ADR-179](ADR-179-货品价格分析与可追溯建议.md)。
- 本地证据：[首版验证记录](../99-项目治理/2026-10-20-原材料行情手动关联与离线预测验证.md)。

## 业务决定

用户希望免费开源、可手动选择货品并关联原材料价格，辅助判断铜、铝、银和 PC 的采购价格走势。当前没有行情订阅。PC 按聚碳酸酯处理，必须明确牌号和地区，不能用 PP 或 PVC 期货替代。

沿用现有货品价格分析页，在采购价格池增加独立行情区域。用户进入所选货品的价格分析，选择已导入的行情基准，核对品种、现货或期货、牌号、地区、币种、单位和价格口径后确认关联。选择和取消只改变本地草稿；明确确认才保存。解除关联需要确认。绑定使用版本比较，避免另一窗口的修改被覆盖。

现有“今日参考价格”仍按授权历史采购事实计算。行情基准是独立市场口径，不自动当成该货品含税、含运费、含加工费的可成交价格。铜铝常见元/吨和白银常见元/千克的口径也不能直接比较。没有受控换算、材料含量、加工费与现货基差校准前，不自动替换历史参考、录单单价、主档记忆价或确认成本。

## 开源选型与免费使用边界

首版使用 [Nixtla StatsForecast](https://github.com/Nixtla/statsforecast)，Apache-2.0，CPU 即可运行统计候选模型和朴素基线。[官方滚动回测文档](https://nixtlaverse.nixtla.io/statsforecast/docs/tutorials/crossvalidation.html)支持按时间向前验证。复杂模型只有在同一品种、同一预测期限的样本外验证胜过简单基线后才适合启用；增加模型复杂度本身不证明更准确。

后续可加入 [MLForecast](https://github.com/Nixtla/mlforecast) 的树模型和协变量，或 [Chronos](https://github.com/amazon-science/chronos-forecasting) 作为候选。首版不增加 GPU、付费模型接口或外部大模型调用，也不安装自动追随未知许可证的模型权重。

开源代码与行情数据授权分开。当前不自动抓取网页，不把 [AKShare 官方说明](https://akshare.akfamily.xyz/introduction.html)中限定学术研究的数据接口当成商用免费行情源。可以使用公司有权使用的供应商报价、自有报价记录或明确允许该用途的数据文件。上期所的[日周数据](https://www.shfe.cn/reports/tradedata/dailyandweeklydata/)用于理解报价字段和单位；[PC 现货页面](https://pc.100ppi.com/)证明不同牌号和报价企业存在不同价格，不作为本功能已获得 API 或转载授权的证明。

## 数据与模型链路

独立 Python worker 读取操作人员提供的 manifest 和 CSV，生成有版本的行情预测快照。服务端只读配置目录里的快照，HTTP 请求不训练模型、不请求行情网站；公司采购、库存、供应商成交和个人信息都不发送到外部。技术合同见 [CONTRACT](../../services/material_forecast/CONTRACT.md)，操作见 worker 目录 README。

manifest 显式标识行情系列、品种、牌号、地区、价格口径、单位、来源及授权确认。期货需要换月或合约口径说明；PC 只接受有牌号和地区的现货。CSV 为 `date,price,available_at`，保留同一报价日的后来修订。`available_at` 是本系统或授权采购工作流首次真正可知该版本的时间。只有原始发布/接收档案能证明当时已有权取得该版本，才填写历史时间；未知则使用本次首次可知时间，不能仅凭旧报价日期回填。档案回放是离线回测，不是 ERP 当时实际运行模型或发出预测的记录。导入账本防止静默删除或篡改已接收的历史版本。

滚动回测按每个起点当时可知的版本重建训练集，早期窗口选模型，后期独立窗口验收。每个预测期限与“下一期仍为最新价格”的 Naive 基线比较，并检查区间实际覆盖。没有足够窗口、没有胜过基线或区间表现不足时，保留报价和朴素基线，状态为依据不足，不输出主动采购信号。报价缺失不补零，也不补成虚构成交。

输出后续 1、5、20 个有效报价期的点预测与区间。没有精确交易日历时，不虚构未来日期，也不把不规则现货报价期称为精确交易日。只有验证通过且区间与当前报价明确分离才输出偏强或偏弱，否则显示方向不明。回测 MAE 和区间覆盖率有各自含义，不包装成“预测准确率”。真实数据历史表现也不保证未来结果。

服务端独立检查来源、结构、价格、版本和时效；不信任快照自称 READY。行情过期、生成过期、数据不完整或绑定身份变化时，停止输出当前信号。界面显示行情截止时间、来源、单位、模型版本和验证状态；行情不可用不影响历史采购价格分析。

## 采购解释与权限

“市场偏强，可按需求分批询价”是价格倾向，不等于已经确认今天应下单。实际采购还需要库存覆盖、采购交期、需求日期、供应商报价及资金条件。首版不自动决定采购数量，不自动下单。下跌信号也不能阻止为交期或安全库存补货。

读取继续检查 `goods:view`、`goods:price_analysis:view`、采购来源和商业价格权限及货品可见范围。保存和解除绑定额外要求 `goods:edit`、真实货品可写范围和有效账号。控制器和服务都校验，不增加分类查看权限。账户、权限和货品变化后清除旧展示；旧异步回执不得回流。新增绑定表使用向前 Flyway 迁移，不修改已应用的价格视图迁移。

## 更新与发布

三种更新各自独立：

1. 行情更新：人员或后续已批准数据适配器向本地文件追加有时间戳的记录。
2. 预测更新：worker 对新数据重新计算并原子发布快照，ERP 读取最新完整快照；原始账本和前一版本留在运营备份中。
3. 框架更新：Dependabot 每周检查 pip 依赖并提交升级候选，新增 CI 安装明确版本并运行离线重放和真实库推理回归。生产仍走项目发布门禁，不在启动时 `pip install --upgrade`。

自动发现升级与自动上线不同。合成数据测试可证明接口和防泄漏逻辑可运行，不能证明铜、铝、银、PC 实际市场预测有效。真实品种的固定历史回测、许可证核对和生产运行环境验证通过后，才适合发布相应版本。当前没有承诺免费实时行情、商业预测准确率或自动生产升级。
