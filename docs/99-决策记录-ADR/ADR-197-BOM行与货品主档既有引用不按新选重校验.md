# ADR-197 BOM 行与货品主档既有引用不按新选重校验

- 日期：2026-10-31。
- 状态：已接受；服务端实现与测试，随下一版本发布。
- 关联：ADR-111（粘贴原子命令）、ADR-145（所属仓库「只在值变化时校验」先例）、
  ADR-188（复制与新选二分）、ADR-191（停用货品自动退出 BOM）。

## 问题与核查

2026-10-31 员工在货品资料页把含 V51025 的组装清单粘贴到「测试配件（FL000913）」被整单拒绝：
「粘贴没有生效…第 3 行 V51025 V5连体二三插保护门弹簧（新旧系统共用物料）：供应商已删除或停用」。
货品 V51025 状态是「使用」，员工把这条报错误读成「V51025 停用」。

根因单点（已排除第二道拦截：全部迁移与触发器不校验供应商，BOM 行供应商只有 Java 端一把尺子）：

1. 前端复制行（`bomComponentCopyBody`）与单行编辑保存体都把行上已有的
   `defaultSupplierId` 原样回传；货品主档保存体同样回传供应商/模具/颜色/单位/客户引用。
2. `GoodsBomService.apply()`（粘贴/导入/单行编辑共用）与 `GoodsService.apply()` 把回传引用
   一律当「新选」重新解析，`GoodsMasterRelationshipResolver` 的 `requireActive` 对
   已删除/禁用/报废一律 409。
3. 供应商停用**不清理** BOM 行/主档上的既有引用（与 ADR-191 停用货品自动清边不同：
   供应商不参与物料展开，保留历史引用是正确行为）。于是这些合法存在、展示正常的行，
   一走到写入路径就被自己身上的历史引用挡死。

生产库实测影响面：30 个停用供应商挂在 8,200+ 条生效 BOM 行（3,353+ 父件，利辉 GY000022 一家
3,786 行）；301 个货品的默认供应商停用；281 个停用模具挂在货品主档（每次保存回传 `mouldId`
同样被拦）；停用颜色 6 货品 + 2 BOM 行。这些父件/货品的组装信息与主档编辑被锁死。

用户拍板口径（2026-10-31）：**供应商状态不影响组件/BOM 写入**。行上引用是历史事实，
不是本次操作新选的。

## 决策

1. `GoodsMasterRelationshipResolver` 为供应商/颜色/模具/单位/客户增加「未变即保留」重载
   （如 `supplier(UUID, Supplier existing)`）：请求带回的 UUID 与行上/主档上当前引用一致时
   原样返回，不重校验状态、不查库；换成另一个对象才走原单参严格解析（新选口径不变：
   单据/选择器维度仍只允许「使用」）。
2. 接入全部写入调用点：BOM 行 `apply()` 的颜色与供应商；货品主档的颜色、厚度单位、
   重量单位、基本单位、模具、客户、默认/第二供应商。所属仓库沿 ADR-145 原逻辑不动。
3. 新选被拒时报错点名实体：「供应商「GY000022 利辉」已删除或停用，不能新选」，
   颜色/模具同构——消除「货品停用」的误读。既有引用保留不产生任何报错。
4. 前端无需改动：回传语义由服务端判定；粘贴结果弹窗逐行展示新文案。

## 边界

- 组件货品维度（ADR-191）不变：停用货品仍自动退出当前 BOM，粘贴/导入仍拒绝停用组件。
- BOM 文件导入按颜色**名称**解析（`applyImportedColor`）仍是新选口径，不受本决策影响。
- 既有引用即使在对象被删除（软删）后也原样保留：拒绝保存并不能移除引用本身，
  数据治理（如批量清理失效引用）另行决策，本次不做。
- 供应商停用/删除依旧不清理既有引用，`importStateSnapshot` 等对账口径不变。

## 验证

- `GoodsMasterRelationshipResolverTest`：未变引用直接返回且不查库；换引用仍走严格校验
  且报错点名（供应商、模具两型代表）。
- `GoodsBomSupplierReferenceTest`：带源边证明的粘贴保留停用供应商；无证明新选停用供应商
  整单拒绝且文案点名；行编辑回传保留；换供应商走严格校验。
- goods 包 669 例回归全绿；`GoodsUuidRelationshipServiceTest`/`GoodsCustomerModelServiceTest`
  桩随重载签名更新（原桩钉的是单参方法，语义不变）。
