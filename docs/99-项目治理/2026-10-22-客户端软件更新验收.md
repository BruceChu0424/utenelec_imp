# 2026-10-22 客户端软件更新验收

## 目标与范围

目标为非网页客户端提供更新入口；管理员上传并发布后，联网且已登录的客户端自动检查并提示，用户点击更新后完成包下载、校验和本机升级。客户端升级与后端服务器更新分开。

功能契约、平台边界、发布步骤及部署配置见[客户端软件更新](../03-页面/客户端软件更新.md)。界面沿用 `frontend-design` 和 Uten 组件；本记录不改变项目既有权限或业务数据规则。

## 服务端检查

- [ ] 真实超级管理员且具有 `authorization:manage` 能创建和上传私有草稿；发布、撤回需要再认证，草稿准备不能分发到员工。
- [ ] 普通员工、访客、模拟身份、必须改密会话无法发布；禁止仅靠隐藏前端按钮控制写入。
- [ ] 草稿创建请求 UUID 幂等；相同请求不同参数被拒绝；上传/发布/撤回结果不明时可读取原记录。
- [ ] 上传用原始流且最多 512 MiB；超限、截断、摘要不符、扩展名/包结构不符失败，不能发布半包。
- [ ] Windows ZIP 拒绝路径越界、绝对路径、重复/冲突路径、非法清单、缺核心文件、大小或哈希不符。
- [ ] 发布构建号比当前高；平台、架构独立选择，精确架构优先于可兼容 universal；未知平台/架构不误发。
- [ ] 慢上传不持有目录锁阻塞更新检查；最多两个上传；上传、发布、撤回并发不会暴露未校验的文件或错误元数据。
- [ ] 已知长度上传前预查磁盘余量，复制中每 8 MiB 复查；不足保留空间时拒绝并清理暂存。
- [ ] 仅已发布包可下载；草稿和撤回包被拒绝；下载元数据、文件内容和响应长度一致。
- [ ] iOS 只接受正确的官方 `apps.apple.com` HTTPS 链接，禁止任意 URL/重定向执行。
- [ ] 专用文件目录不跟随服务器发布被删除；备份可还原 `release.json`、包文件及其对应关系。
- [ ] 业务数据清空与普通附件清理不误删发布目录或发布元数据。

## 客户端检查

- [ ] Web 跳过本机更新桥、原生下载和安装操作，现有网页检查不受影响。
- [ ] Windows/Android 设置显示当前原生版本和构建号；版本比较按构建号。
- [ ] 登录、回到前台及检查间隔能发现更新；无更新不弹窗；错误不冒充最新；重复检查和更新有并发保护。
- [ ] 登录居中提示不直接展示更新说明；“查看详情”进入专页，专页提供完整内容、立即更新与进度，设置入口也进入同一专页。
- [ ] 手动检查能明确显示结果；同一提示不会不断打断；服务器/账号变化后旧请求不能改写新身份状态。
- [ ] 下载只接受可信接口返回的指定包，重新验证 SHA-256 与大小，失败不启动安装器。
- [ ] 断网、中断、摘要不符、包已撤回、权限不足能显示可操作的错误；重试不破坏当前安装。
- [ ] Windows 目录不可写时在退出前失败；其他程序占用文件、杀软阻断或启动失败有清楚回执。
- [ ] Windows 更新程序等待原进程退出，备份/替换/启动顺序正确，失败恢复旧文件，日志可查。
- [ ] Windows 包中的服务器命令或恶意脚本不会替代固定更新程序。
- [ ] Windows 更新保留语言、主题、服务器选择、设备标识、安全存储和已持久化草稿；未保存编辑需先保存。
- [ ] Android 未允许安装来源时能进入系统授权，返回后可重试；同签名、更高版本代码覆盖成功且数据保留。
- [ ] Android 错误包名、签名或旧版本被拒绝，取消系统安装不误报成功。
- [ ] iOS/macOS 打开指定 App Store 条目；Linux 不展示本轮未实现的覆盖安装承诺。
- [ ] 更新提示与发布表单在窄屏、大字体、深浅主题、中英韩下可操作，错误及进度完整可见。

## 上线前必验

1. 准备一次含更新器的新客户端首次安装；确认早期无更新器版本仍需先安装一次完整新客户端。
2. 在 HTTPS 部署设置持久包目录、服务账号权限、磁盘监控和备份。为原始包上传单独配置 512 MiB 反向代理例外，执行配置检查与受控重载。
3. 上传超过默认 2 MiB 的真实 Windows ZIP/正式签名 APK，核对专用目录元数据状态和文件摘要后发布。
4. 使用实际上一版本设备验证提示、下载、校验、覆盖安装、重启及本机设置保留；至少覆盖 Windows 与 Android 的目标使用系统。
5. 记录源代码提交、客户端显示版本/构建号/架构、包摘要、发布 ID、设备系统与更新回执。没有真机证据前不写“手机更新已验收”。
6. 发布出现问题时撤回，确认新检查不再返回该包；对已升级设备准备更高构建号修复版。

## 公开技术依据

- [Android PackageInstaller 安装确认要求](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int))：普通应用不能承诺跨 Android 版本无交互静默覆盖。
- [Apple App Review Guidelines 2.5.2](https://developer.apple.com/app-store/review/guidelines/#software-requirements)：iOS 不通过应用内自行替换可执行代码规避分发渠道。
- [Microsoft App Installer 更新配置](https://learn.microsoft.com/en-us/windows/msix/app-installer/update-settings)：MSIX 可做系统管理更新，但本次实现使用现有 Flutter 可执行目录的固定更新程序，不混称已接入 MSIX。
