# ADR-173：会话状态语义相等与身份栅栏去对象指纹

- 日期：2026-10-10。
- 状态：用户授权实施；本地回归全绿，不代表公司服务器已部署。
- 遵循 ADR-014（refresh 保持 lineage/intent）、ADR-023（任务认领租约）、ADR-027（财务审核组范式）；
  与 `docs/05-架构/网络层与拦截器.md` §6.1.1「token 刷新、同身份资料刷新不改变 intent」同源。

## 1. 背景与缺陷

用户报告（2026-10-10）：订货审批审核详情页停一两分钟就弹「登录身份已变化，请重新加载并认领
审核」，点重试立刻恢复，反复出现。

根因链（服务端 `refresh_tokens` 表证实：01:34 → 01:48 → 02:02，每 ~14 分钟一轮）：

1. access token TTL 15 分钟，`AuthInterceptor` 提前 60 秒单飞刷新（ADR-108）；后台轮询
   （通知 20 秒 / 徽章 60 秒 / 认领心跳 30 秒）保证闲置时刷新必然发生；
2. `/auth/refresh` 成功 → `SessionEventBus.publishProfile` →
   `SessionNotifier._applyRefreshedProfileIfCurrent` **无条件 `state = SessionState(...)`**，
   即使档案内容与当前完全一致，也会产生一个"内容相同的新对象"；
3. 全站九处栅栏用**对象同一性**（`identical`）比对 `SessionState`，把这次例行的令牌轮换
   误判为换号：
   - `financeReviewClaim`（七个财务审核页共用的认领工厂）：`isCurrentSession` 判死 → 认领
     `_fail('登录状态已变化')` → 决策按钮禁用；
   - 订货审批 / 销售订单 / 出货财务三个审核页 listener：清空页面 + 释放认领 + 报
     「登录身份已变化」（即用户所见）；
   - 报价核价页：`_invalidateAccess()` 强关对话框并隐藏报价；
   - 采购 / 委外 / 销售编辑页：条款预填、地址簿选择结果被静默丢弃；
   - 仓库预计到货视图：列表回包丢弃；物料分析页：scope 键掺 `identityHashCode` 被击穿；
   - `app_router`：每轮刷新全路由 `router.refresh()`；`currentPermissionsProvider` 全量重建。

服务端核实：任务认领租约按**人**（employeeId）走、不跟 token 走；刷新后原 claimId 决策仍可
提交——所谓"失效"纯属客户端对象同一性误判，服务端租约从未丢失。

## 2. 决策

**身份 = 语义字段（状态 + 用户 + 操作人 + 业务重置代次），不是状态对象实例。** 分三层修复：

1. **源头不换实例**：`_applyRefreshedProfileIfCurrent` 构造新档案后与当前值比较，
   相等直接返回（不赋值）。`AppUser` 实现值相等（权限点按集合比较——服务端合成顺序不稳定）。
2. **通知层深比较**：`SessionState` 实现值相等；`SessionNotifier.updateShouldNotify` 覆写为
   `previous != next`。任何路径的语义无变化赋值都不再惊动监听者（路由 refresh、权限集重建、
   伴随读重拉一并根治）。
3. **栅栏层语义身份**：`SessionState.isSameIdentity`（status + user.id + actor.id +
   businessResetGeneration，与 `authenticatedScopeProvider` 的会话身份键同口径）。全部
   `identical(SessionState)` 比对点改用它：
   - `financeReviewClaim` 的 `isCurrentSession`；
   - 三个财审页 listener 与 `_load` 守卫（权限滑动更新不清空——服务端在决策时点按
     `requireActiveClaimByMe` 重校验权限与审核人资格）；
   - 报价核价页 listener / `_captureContext` / `_load`；
   - 采购、委外、销售编辑页预填守卫；仓库预计到货视图 `current()`；
   - 物料分析页 `_sessionScopeKey` 去掉 `identityHashCode(user/actor)`、权限缓存比对改
     `setEquals`、键补业务重置代次。

**不变式**：换号、登出、模拟切换（目标↔管理员）、业务清空重登仍立即失效认领并清空页面；
`employee_reset_password_dialog` 等既有语义栅栏（比 userId/epoch）不受影响；
`visitorSessionProvider` 无此缺陷（访客刷新不换状态对象）。

## 3. 验证

- `session_impersonation_race_test`：新增"同内容刷新保持同一实例且零通知"、"权限变化发射新
  状态但 isSameIdentity 为真"两条回归；
- `finance_review_claim_notice_test`（新）：认领在同身份状态更替/权限滑动下存活、换号即失效；
- `finance_procurement_approval_review_page_test`：新增"token 静默刷新（同身份新状态对象/权限
  滑动）不清空页面与认领"；
- 存量断言（`replaceIdentity` 换不同 id → 页面清空报错）继续通过——语义比较只放过同身份更替。

## 4. 影响

- 受益页面：订货审批审核详情、销售订单财务审核、出货财务审核、报价核价、销售订单批量确认、
  出货审核工作台、订货审批批量、采购/委外/销售单据编辑、仓库预计到货、物料分析、全局路由。
- 性能附带收益：不再每 ~14 分钟全路由 refresh + 权限集全量重建一轮。
- 文档同步：ADR-014 §3 增补、`docs/05-架构/状态管理.md` §4.2、
  `docs/05-架构/网络层与拦截器.md` §6.1.1、三个审核页文档。
