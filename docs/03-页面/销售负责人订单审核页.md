# 销售负责人订单审核页

> 路由：`/sales/manager-review`

反审核请求先把 `decisionId`、原修订号、审核员工 ID 与原因保存到本机草稿，再发送请求。服务端以该 UUID 追加不可变决定，详情的 `managerDecisions` 返回原决定身份、动作、版本、员工与原因。响应丢失时只有五项证据及下一修订号全部相符才可收口；其他人决定、错版本、错原因或缺少事件继续保留原未知提交，不重放。WPF 仍未迁移，必须按同一合同实现后才能开放操作。

> V978 源码候选：本地功能已完成，尚未部署或正式打包，生产账号授权尚未执行。
> 工作台位置：综合营销部最前面，位于“销售管理”之前。

## 入口与流程

入口为 `/sales/manager-review`，名称“订单审核”。报价、订货分别使用 `?kind=quote` 和 `?kind=order`，各有待审核、已通过、已驳回分类。只显示当前账号有查看权限的单据类型。

报价：销售保存并提交 → 负责人审核 → 财务核价 → 销售登记客户同意当前版本 → 转订货草稿。

订货：销售保存并在详情审核提交、形成原有库存预留 → 负责人审核 → 财务确认 → 计划部及后续履约。报价转来的订货也须经过本级审核。

负责人通过仅交接财务。财务通过才放行后续业务；负责人审批不扣实物库存、不立应收，也不代替财务核价或客户确认。

## 页面与动作

设计使用 `frontend-design`，复用 Uten 主题、统一表格、表头设置、明细、附件、客户往来、修订对照、认领和草稿能力。桌面与窄屏使用同一张可横向滚动的表格。

| 场景 | 实现效果 |
|---|---|
| 报价审核 | 核对客户文件、数量、价格及条款；按授权调整折扣、成交单价、赠品/零价、最新标价、有效期、结账方式和审核备注 |
| 报价数量、货品身份、增删行需修改 | 驳回给销售处理；负责人和财务核价页均不提供这些改单写入 |
| 订货审核 | 核对原订单、来源报价、客户往来及修改前后内容；批准或填写原因驳回 |
| 批量订货审批 | 支持跨页选择、共同审核备注，最多 100 笔；按所见版本和本人认领一次原子提交，任一冲突整批回滚 |
| 负责人驳回 | 报价回草稿；订货先保留原订单和预留，销售按原受控修订规则修改、保存、重新提交 |
| 负责人反审核 | 撤销本级批准并回到负责人待审；财务已认领、已通过或其他业务守卫不允许时阻止，订货须填写原因 |
| 销售改量或修改已审订单 | 原负责人批准失效，修改后重新经过负责人和财务；原行身份、预留守恒及下游限制保留 |
| 撤回、取消或中止 | 退出有效待审范围，保留审批历史；详情说明当前只读或等待销售重新提交 |
| 回执不明 | 保留原版本、选择、备注和提交意图，通过原认领/版本及决定值核对；不自动再次审批 |

报价负责人定价来源为 `MANAGER`，财务定价仍为 `FINANCE`，都不回写货品主档价格。详情展示当前单据，审批原版本通过不可变记录和修订对照追溯。

## 权限与初始负责人

权限面为 `sales.manager-review`，管理端归在“综合营销部 / 订单审核”。两种单据独立授权：

| 单据 | 查看 | 批准 | 驳回 | 反审核 |
|---|---|---|---|---|
| 报价 | `sales_quote_manager:view` | `sales_quote_manager:confirm` | `sales_quote_manager:reject` | `sales_quote_manager:reverse` |
| 订货 | `sales_order_manager:view` | `sales_order_manager:confirm` | `sales_order_manager:reject` | `sales_order_manager:reverse` |

报价 `confirm` 同时包含本次报价的核价调整与批准，沿用原核价权限职责；修改货品主档仍需原来的独立权限。查看不包含决定；反审核也不包含待审批准或驳回。财务权限不会自动授予负责人权限，负责人权限也不会授予财务审批权。

首位指定人为朱舜炜，但业务代码不按姓名、工号或部门写死审核资格。上线时先用[只读授权核对脚本](../../server/maintenance/sales_manager_review_authorization_preflight.sql)核实唯一启用账号，再通过既有管理员权限设置加授对应权限。后续可按同一机制授权其他人；保留其他已有授权。本次没有更改生产账号。

## 居中提醒

拥有对应查看权及批准或驳回权的在职启用账号进入接收池。仅查看、仅反审核、已停用或已失效授权不产生待审弹窗；超管的隐含全量权限不自动订阅。

- 新提交同时产生通知中心记录、在线提醒和既有 `ReviewPendingDialog` 居中弹窗。
- “去工作台处理”进入对应报价/订货分类；两种任务混合时进入同一个订单审核工作台。
- 中途新授权的人，在登录或在线到达检查时补齐仍待审的提醒；每类每轮最多 20 张，只补缺失记录，不重复重建或置未读。
- 弹窗沿用“某人正在审核”心跳状态。办结、撤回、取消或权限变化后失效；重新提交按新轮次提醒。
- 已读、关闭及“稍后再看”不等于审批完成；沿用原个人弹窗偏好和安全弹窗调度。

## 技术合同与生效范围

负责人接口统一位于 `/api/sales/manager-review`。查看、保存、批准、驳回、反审核均有服务端权限和阶段校验；财务列表、计数、详情、认领、决定及数据库闸门也校验负责人阶段。

审核详情及动作响应标记 `reviewStage=SALES_MANAGER`、`reviewContractVersion=1`。报价用 `reviewStatus / reviewStatusBucket / reviewActions`，订货用 `reviewApproved / reviewRejected`，版本用 `reviewRevision`，不把负责人批准写成财务批准。队列与计数响应沿用各自分页/计数结构。金额和响应样例见[共享契约](../../contracts/sales-manager-review/v1.json)。

以下路径均相对 `/api/sales/manager-review`；根路径不附加尾部斜杠：

| 方法与路径 | 请求要点 |
|---|---|
| `GET` 根路径、`GET /count` | 队列按 kind、state、keyword、page、size 查询；计数只数本人可办理的待审 |
| `GET /quotes/{id}`、`GET /orders/{id}` | 对应类型查看权限，返回本级审核投影 |
| `PUT /quotes/{id}` | 共享 `QuoteFinanceEditRequest`：expectedRevision、expectedClaimId、validUntil、settlementMethodId、financeRemark、lines；兼容字段名 financeRemark 在本入口写负责人备注，保存空值才清空 |
| `POST /quotes/{id}/confirm`、`/reject` | expectedRevision、expectedClaimId；text 为本次说明，驳回必填；确认不带说明时保留已保存的负责人备注 |
| `POST /quotes/{id}/reverse` | expectedRevision，继续校验本级批准、财务及来源订单状态 |
| `POST /orders/{id}/confirm`、`/reject` | expectedRevision、expectedClaimId；确认 remark 选填，驳回 reason 必填 |
| `POST /orders/batch` | orderIds、expectedRevisions、expectedClaimIds、共同 remark；完整选择集一次提交 |
| `POST /orders/{id}/reverse` | expectedRevision、必填 reason；不能越过财务认领或已办结状态 |

请求 DTO 的兼容字段名不代表获得财务写权，最终阶段由受权限保护的端点和服务端状态决定。

Web 和现有 Flutter 桌面共用实现。Win7 WPF 对应审核及通知入口仍未迁移，详见[实施与验证记录](../99-项目治理/2026-10-31-销售负责人前置审核.md)和唯一进度台账；不能把后端支持视为 WPF 已支持。
