# 生产计量与来源守恒

本页承接[生产排产与执行主流程](04-生产订单排产与执行全链路需求.md)，集中维护基本单位、BOM、库存承诺、共享供给和来源约束。它不是另一份当前验收记录，也不新增数据表或API合同。

## 一、基本单位与BOM计量

业务数量使用十进制定点，先以冻结的正换算率转为基本量，再比较同货品/颜色/实际仓的容量。订单“箱”、目标件“件”、重量和金额必须分列，不能把不同单位的缺口相加为一个总数。BOM行用量表达组件基本量相对父件基本产出的消耗依据，不让员工再填写一套猜测的BOM单位。

当前[MaterialConsumptionMath.required](../../server/src/main/java/com/uten/imp/features/production/analysis/MaterialConsumptionMath.java)对父件产出 `q`、组件用量 `b`、包装/批次产出基数 `k` 使用以下计量：

| basis | 组件需求 |
|---|---|
| PER_UNIT | `q × b`。 |
| PER_PACKAGE，允许拆包 | `q × b / k`，按现有数量精度向上保足。 |
| PER_PACKAGE，不允许拆包 | `ceil(q / k) × b`。 |
| FIXED_BATCH | `ceil(q / k) × b`，不能将整批投入按连续比例无限拆分。 |

用量和包装/批次基数必须为正，非法basis拒绝；当前函数最终向上到4位数量精度。展示用的 `effectivePerProduct` 不能替代非线性整包/整批需求的容量复核。比如一包供10件、每包耗2，产11件须按2包耗4，不能按平均单耗0.2误判为2.2。部分生产、重算和剩余分配都必须保留实际批次口径。

数量按实际计量单位保足与金额精度是两种规则。实际金额不能借数量取整自动裁位、记FX或LOSS；[原始金额合同](2026-09-07-财务原始金额与精确分摊口径.md)和[实际成本专题](../99-项目治理/库存实际成本接线与验收.md)单独约束金额。

正常损耗若已含在BOM用量中不能再加一次。若将来引入独立损耗率、成材率或生效版本，必须保存“是否已含损耗”的明确依据，按发料精度计算；不能把旧规格中的通用 `q × 用量 × (1 + 损耗率)` 当作当前所有物料已有的字段合同。

## 二、BOM树与计划锚点

节点身份至少由 `analysisItemId + nodeKey`、父节点和路径构成；同货品在不同BOM路径不是同一份需求。保存完整树便于追溯，但每个执行层只领自己的直接子件。A→B→D中A领B，B领D，不能让A和B各再采购/消耗一份D。

- 当前层无直接BOM且有合法分析来源时，可以直接自制，不造假需求或空DRAW。缺来源、结构加载失败不能伪装为ZERO_MATERIAL，也不能从“需求表为空”推断零物料。
- 有BOM时继续核循环/深度、正用量、有效组件、颜色/单位UUID、计量方式、控制阶段和当前指纹。已删除或迁移stub货品不得作为新活动父件/组件。
- `SHIP/REFERENCE`是参考或发运用途，不作生产硬门槛；实际生产耗用包装必须配置到生产控制阶段，如FINISH。无生产硬门槛不等于没有成本或没有来源责任。
- 根产品、MAKE候选和有子层委外都可在路线及数量确认后下达车间。MAKE_COMPONENT/SUBCONTRACT_MAKE是计划锚点，原子件需求仍在原树，不搬一份再展开；旧委托数据按受控刷新收敛，不建立新的双份权益。
- 父件已有合格库存只按真实短缺展开子料。另一种直接材料短缺不能使已有父件的子料再产生需求。前置自制已实际领用的原材料持续覆盖本批，不能在等待委外回厂时重新变成缺口。
- 计划草稿/分析在来源或BOM改变后要重新校验；已批准执行使用冻结依据，不能随主档静默换料。旧PLAN_BOM_OVERRIDE只读，新流程没有BOM策略或越权按钮。

`subplan_links`连接另一张真实生产计划，执行分段只属于本计划明细；两者不能互换。当前分析行仍各自形成独立计划，批量同车间输入不等于合并计划头；跨分析物理合单需要专门来源桥及正反向设计，不能仅按同货品合成一行。

## 三、库存、权益和未来供给

| 事实 | 能否作为当前可领物料 | 约束 |
|---|---|---|
| 实际合格自由库存 | 可以，在事务内复核并正式预留 | 实际叶仓、货品、颜色、质量状态及权限一致。 |
| 本需求精确权益/exact | 按受益节点和来源使用 | 不是额外库存，不能在公共池与exact各算一次。 |
| 分析内优先分配意向 | 尚未正式预留 | 预览可变化；命令重新锁容量，不能越过已保护承诺。 |
| 批准采购/委外/生产未来供给 | 不可以 | 只减少尚待安排责任或支持预计日期；须沿明确来源承接。 |
| 已显式采用的公共在途 | 不可以 | claim保护未来容量，待合格实收入库才转可领。 |
| 到货、待检、PASS未入库 | 不可以 | 物流到达、品质许可、仓库实收分开。 |
| FAIL、冻结、已报废或他人专属权益 | 不可以 | 不能用零值、主仓汇总或同货品其它来源绕过。 |

销售与生产使用同一个 `stock_reservations` 聚合：有效量=原量−已消费−已释放，消费+释放不得超过原量。不能再建平行“物料锁表”或用is_locked布尔值替代数量。库存余额由实际流水更新，分析表不能直接加减仓库余额。

在聚合多仓时，仓级预留分别扣，全局预留只扣一次；统一可用查询已扣的预留不再重复扣。安全库存、质量/盘点冻结同样应明确是否已包含在输入中，不能重复减或重复加。当前查得到的自由量不是允许绕过其它订单承诺的授权。

同一主仓内可跨有效子仓齐套并分别生成DRAW；库存、实收、预留和流水保留真实叶仓UUID，主仓仅界定范围。真正跨主仓仍按原公共收货/调拨和明确来源规则处理，不能把实际仓重标为分析仓。没有分析来源的直接正式收货保留其实际单仓合同。

## 四、本批需求与排产额度

```text
可继续下达量 = 有效需求量 - 有效待批准提交量 - 有效已批准下达量
本批物理缺口 = 本批BOM实际需要 - 已由合格实物/有效实领覆盖的本批份额
待补责任 = 本批未覆盖需要 - 已有合法采购/委外/车间等供给责任
```

三者分别计算和显示，下达计划不能把物理缺口清零，公共备货也不能扩大本批BOM需要。已领用仍按精确节点覆盖本批；已下达量/尚未下达量、待料、在途、已领量和实际完成量不能混成一个百分比。

同一需求的SUBMITTED+APPROVED不得超过有效需求；SUBMITTED不增加正式已排量、执行段、预留或DRAW。批准后WAITING/READY和其它有效执行阶段按实际有效数量对齐计划明细，后续取消/反向保留原事实并追加变化，不能丢失所选批次。

齐套能力用于执行判断，不限制计划下达。需求10，A支持10、B支持6，可先下达10并整体WAITING，零散料不被预留；员工明确选择较小批次时按该批次实际齐套。不能后台未经选择把10拆成两份计划，也不能在收到部分料时将整批假提升。

对线性PER_UNIT物料，可用“可分配基本量/单台需要”的最小支持量判断瓶颈；包装/整批物料须用真实 `required(q)` 复核。齐套率应表达同一产品/批次可支持数量，不能按有库存的BOM行数平均，不能将不同单位产品的数量随意合并成整体齐套率。数据缺失显示不可计算，不自动当零库存/零在途去采购。

## 五、多产品、公共余量与供给分配

一次共享计算对每个兼容供给建立递减余额，按当前明确优先级和稳定来源顺序给各需求分配：`本次份额=min(本需求未满足量,供给剩余)`。后续需求只能看到扣减后的余额。两位用户的预览仍可能看到同一自由量，因此确认时必须锁定来源、重读有效容量和版本；不能直接把预览变成受保护份额。

直接层完整套料保护优先，深层诊断只用剩余公共库存；exact归原受益节点。不同分析、父子/兄弟节点、同物料不同路径必须同时测试，不能把父需求和子锚点各算一次。优先级修改不自动挪走已领或已保护库存，改派须有权限、影响和原因，并对称处理来源。

采购/无子层委外允许的公共超量单独确认并分账：A需要500、实际批准2000，A只归属500，公共1500；B明确采用1000后公共剩500。MAKE及有子层委外不得用公共超量制造额外子件任务；公共安全补库和公共超采也保持各自来源，不能加到本分析allocation/exact。

根产品BUY或委外回厂亦按ROOT_SUPPLY真实来源交接给销售/下游；不能另建虚构订单或绕过客户发货财审。同源交接失败保持可追溯未交接量，不以通知已发作为完成。

合法未来供给至少要求真实已批准且未停止/删除、尚有有效未收容量、兼容货品/颜色/单位与来源、有可靠正换算率。有关开放行单位无效应阻断并提示，不能当0继续重复下单；已完成/停止/删除的无关历史单位问题不应阻断本次计算。历史不会再到的尾数由业务明确停止/结案，不按单龄自动清掉。

预计齐套日可以按时间累加明确来源的可用供给并考虑品质/收货提前期，但只是预测；延期、部分到货、FAIL或优先级变化须重算。当前接口实际使用分析version/fingerprint、命令hash和真实来源锁；旧规格的nettingRunId、capacitySnapshotAt等示意字段没有构成一套已实现API，不能要求客户端拼造。

跨申请部分分解可按兼容供应商/商业条款归集为订单，订货不按收货仓拆单。MOQ/包装导致的额外量必须归公共供给，不虚挂具体需求；取消一个共享需求只释放它的份额，不能整单关闭别人仍需要的采购/委外。实际来源增加/减少和未履约返还按正式来源账处理，不用比例平均改旧事实。

## 六、关键不变量与实现入口

```text
0 <= 原量 - 消费量 - 释放量
Σ同一供给有效分配 <= 同一供给可分容量
Σ同一来源实收分配 <= 该来源实际合格入库
Σ执行段销售分摊 = 该段应归属的计划量
Σ各段使用某销售link的量 <= 该link有效容量
原始来源量 = 已履约/已分配量 + 未履约/未分配余额 + 明确取消/反向量
```

每条式子都要求同一计量维度和有效事件口径。不能用max(0)掩盖来源负余额或通过改预留清除异常；只有定义为“建议缺口”的展示量才可与独立超量分栏。重复和反向继续沿原UUID、原累计区间/切片，不按单号、日期或当前BOM猜回去。
