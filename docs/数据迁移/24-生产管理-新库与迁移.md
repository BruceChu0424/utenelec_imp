## 一、设计决策总览（含理由）

| # | 决策点 | 选型 | 理由 |
|---|---|---|---|
| 1 | 单据范围 | **本期只迁 3 张表**：F_Plan/F_PlanItem/F_PlanCostItem；F_DateReport(+Item) 建空结构；F_Arrange/F_Cost/F_Step/F_Producting 等全 0 表**不做** | 在用数据集中在生产计划与 BOM 展开；排产/成本/工序/在制从未启用，归未来车间/成本模块（同 [18] §1.3、[23] §一） |
| 2 | **F_PlanCostItem 136 万行** | **反冗余 `bill_date` + 按年 RANGE 分区（2018–2030 + DEFAULT）** | 全库最大表无原生日期列（41 字段全无 date/datetime），必须 JOIN `BillID→F_PlanItem→F_Plan.BillDate` 回填为分区键；136 万行单表+仅 PK 索引是老库性能重灾区，分区+索引双管齐下（[23] §七） |
| 3 | **成本重算/级联逻辑** | **本期不上移到 Service 层**：BOM 自动展开（TRI_F_PlanCostItem_Insert）、数量级联重算（TRI_F_PlanCostItem_Update `子.QTY=父.QTY×DQTY`）、MRP 需购量公式（View_F_PlanCostItem 三分支 CASE）**全部归未来成本/MRP 模块** | 这些触发器是 136 万行表的高频写入来源，迁移历史数据是**一次性快照**，不需要重算；本期"保数据完整 + 只读查询"（[23] §七 7.6、[18] §五） |
| 4 | BOM 树结构 | **原样保留**（`parent_id` 自引用 + `level` 层级 + 全数量族 + 溯源号） | BOM 是生产模块业务核心，未来 MRP 必须依赖；新库只读保数据，不做编辑（编辑归未来模块） |
| 5 | 真外键骨干 | **F_PlanItem.S_OrderID → sales_order_items.id**（销售订单驱动生产）+ **F_PlanCostItem.SOCItemID → sales_order_cost_items.id**（生产→销售成本溯源） | 取代老库逗号串 + 触发器游标回写；销售模块（V51）**本批同步新建**，迁移顺序：销售 → 生产（[18] §二、[23] §七 7.7） |
| 6 | 多值溯源降级文本 | POrderNo/PInNo/PWDrawNo/PDrawNo/OWDrawNo/EONo/EINo/EWNo/PAppNo + InNo/TranNo 共 11 个 varchar(250–5000) → **`source_doc_no TEXT` 合并占位** | 老库设计反模式：一个字段挂多张单号；新库真 FK 走单值（S_OrderID/SOCItemID），文本占位保留追溯线索（[23] §七 7.3） |
| 7 | 数量族全保留 | F_PlanItem **12 个数量族**（OQTY/QTY/LQTY/IQTY/FQTY/RQTY/BQTY/TQTY/PAQTY/ISRQTY/CPQTY/POQTY/PIQTY）+ F_PlanCostItem **16 个数量族** 原样落 `NUMERIC(18,4)` | 数量族是触发器游标回写的累计量，每个都有业务语义；本期不重算但必须保数据（区别于采购 [15] §四只保留 received/returned） |
| 8 | float→numeric | 老库 `QTY float`/`FWeight float` 等 → 新库 `NUMERIC(18,4)` | float 精度风险（同采购 [14] §七、[23] §七 7.5） |
| 9 | FK 陷阱防护 | **`F_PlanCostItem.BillID → F_PlanItem.ID`（不是 F_Plan.ID）** 在 DDL/迁移/注释多处显式标注 | 老库 fkeys.txt 揭示的"成本展开行挂在计划明细行下"，错关联会全表错位（[23] §3.2） |
| 10 | 人员/车间字段 | `WorkShop/WorkerID/Seller varchar` 装数字/名字 → `department_id UUID`（可空，能对齐才填）+ `workshop_name/worker_name/seller_name TEXT` 原样留底 | B_Worker↔employees 无 legacy_id 对齐（同采购 [15] §九），后续建 `worker_legacy_map` 回填；车间主档未建，文本留底不丢语义 |
| 11 | 物料/供应商/颜色主档 | 经 `legacy_id` JOIN 出 UUID；缺失时**自动补录**最小存根（同采购 [15] §3.3） | 只保历史快照引用；goods 存根标 `auto_created`，不得进入当前货品/BOM/MRP（V181/[31](31-货品组装BOM与成本预算.md)） |
| 12 | 状态机 | `status SMALLINT 0草稿/1已审/-1红冲` + `is_closed`（Fulfill 派生）+ `is_stopped`（Stop 手工） | 单枚举 + 派生标志，取代老库 Status/Status2/Fulfill/Stop/Cancel/ISR/CStatus/LStatus 八套并存（[23] §七 7.4）。F_ 触发器**不引用 ISplan 全局开关**（[23] §4.1），全凭状态驱动，新库沿用显式化 |
| 13 | 触发器逻辑去向 | 审核回写 S_OrderItem（PQTY/LQTY/PlanNo）+ 设首工序 StepID **本期不实现**（销售模块未上线前无目标表） | 这些是审核生效的副作用，归销售/车间模块同步实现；本期生产表是"已审快照"，迁移时不跑触发器 |

> **核心方针**：F_PlanCostItem 是"读多写少 + 重算昂贵"的快照表，**本期只迁不重算**；触发器揭示的业务规则作为**未来成本/MRP/车间模块的需求规格库**保留在 [23] §四与本文 §四。

```
    ├─ 成本核算（F_Cost / F_CostItem）

```

## 三、表设计（DDL · 落 V55）

### 3.0 统一约定（与 V44 采购 / V48 仓库一致）

- 主键 `id UUID DEFAULT gen_random_uuid()`；溯源 `legacy_id INT`（分区表 UNIQUE 需含分区键，见 §3.3/§五）。
- 单据号 `bill_no TEXT UNIQUE NOT NULL`（业务主键，老库前缀 `SJ`，如 `SJ26070068`）。
- 审计四件套 `created_at/updated_at/created_by/updated_by` + 软删 `is_deleted/deleted_at`。
- 金额/数量统一 `NUMERIC(18,4)`；汇率 `NUMERIC(18,6)`（本模块无币种，沿用默认本币）。
- 人员字段（maker/approver）→ UUID 留空，留 `*_legacy_id INT` 文本占位（B_Worker↔employees 无对齐，同采购）。

### 3.1 `production_plans`（生产计划单头 · 源 F_Plan，7,235 行）

## 四、状态机与触发器逻辑去向（明确"本期不做"清单）

### 4.1 状态机（生产计划审核）

```
录入 → status=0(草稿) 或 1(已审，贴老库"保存即生效"，老库历史无 0)
审核 status 0→1：同事务内
   · 重算 is_closed（所有明细 qty-iqty ≤ 0）
   · 【未来】回写 S_OrderItem.PQTY/LQTY/PlanNo（销售模块上线后）
   · 【未来】F_PlanItem.StepID 设首工序（车间模块上线后）
   · 【未来】F_ProductingItem 按日产能填充（排产模块上线后）
红冲 status 1→-1：同事务反向冲销（清排产、减上游回写），单据保留不可删
   · 守卫：F_StepItem 已 IQTY（已派工完工）禁止反审（未来车间模块负责）
```

> 与采购 [15] §4.4 一致：触发器派生量（iqty/rqty/bqty 等累计量）由 Service 在明细/下游变化时重算主表 `is_closed`。**本期迁移的是历史快照**，老库累计量原样保留，不重算。

### 4.2 **本期不做** 的触发器逻辑清单（归未来模块）

> 老库 11 个 F_ 触发器（[23] §四），本期只保留它们的**业务规则文档化**（作为未来模块需求规格），**新库不实现**：

| 触发器 | 老库副作用 | 归属未来模块 | 本期处理 |
|---|---|---|---|
| **TRI_F_PlanCostItem_Insert** ⭐ | 新增 F_PlanItem 时自动展开 BOM 写 F_PlanCostItem（双数据源：销售订单成本 BOM 优先 / 货品档案 BOM 兜底；多层递归） | 未来 BOM/MRP 模块 | 不实现。BOM 展开数据原样迁移保只读 |
| **TRI_F_PlanCostItem_Update** | F_PlanItem OQTY/QTY/LQTY/IQTY 变化时，全 BOM 子树数量按 `父×DQTY` 级联重算（136 万行表的高频写入） | 未来成本/MRP 模块 | 不实现。明细只读，重算归未来 |
| **TRI_F_PlanCostItem_Level** | 新增时上溯 ≤30 层算 Level（防 BOM 循环引用） | 未来 BOM 模块 | 迁移原样保 Level，新建走应用层校验 |
| **CheckChange_F** | Class<>0 时标记 F_PlanItem.CStatus=1（成本已变更） | 未来成本模块 | 不实现 |
| **TRI_Plan_Order** | F_Plan 审核回写 S_OrderItem + 设 F_PlanItem.StepID + 填充 F_ProductingItem 按日产能（机器负荷 PRatio ≤1） | 销售模块 + 车间/排产模块 | 不实现（前置模块未上线） |
| **CheckFulfill4** | F_PlanItem 增删改派生 F_Plan.Fulfill | 同采购范式 → Service 派生 is_closed | **Service 层实现 is_closed 派生**（同采购 [15] §4.4） |
| **ProductingItem_BQTY** | F_ProductingItem 回写 F_PlanItem.IQTY/IWeight + F_StepItem | 未来车间模块 | 不实现 |
| **ProductItem_BQTY** | F_ProductItem 派生 F_PlanItem.BQTY/FQTY | 未来车间模块 | 不实现 |
| **PStep_FQTY** | F_PStepItem 派生 F_ProductItem.FQTY（瓶颈工序决定） | 未来车间模块 | 不实现 |
| **CheckFulfill_StepItem** | F_StepItem 派生 F_PlanItem.FQTY/FWeight/TranNo | 未来车间模块 | 不实现 |
| **TRI_Transfer_Plan** | F_Transfer 回写 F_PlanItem.TQTY + **直接 UPDATE StockGoods OUTQTY<月>**（调拨即库存出库） | 未来工序调派模块（库存联动走 stock_movements） | 不实现 |

> **TRI_Transfer_Plan 直接动 StockGoods**（动态 SQL `UPDATE StockGoods SET OUTWeight<月>=...`）——老库在制工序调拨视为库存出库（同采购 [14] §4.4 按月分列台账模式）。新库未来用 `stock_movements` 流水表达（[17] §二决策3）。

### 4.3 F_ 触发器不引用 ISplan 开关（与采购的差别）

[23] §4.1 验证：`grep ISplan` 在 F_ 段无命中。生产模块全凭 `Status/Status2` 状态机驱动，**显式化程度高于采购**（采购 [14] §4.6 的 SystemAccinfo.ISplan 全局开关是 P_ 模块独有）。新库沿用：审核动作只看 `status` 字段，不依赖任何全局开关。

## 五、F_PlanCostItem 分区与索引专项（V55 重点）

### 5.1 反冗余 `bill_date`（分区键）的取值路径

F_PlanCostItem 41 字段**无任何日期列**（[23] §3.2 关键观察）。分区必须从 F_Plan 反冗余：

```
production_plan_costs.bill_date
  ← JOIN production_plan_items ppi ON ppi.id = bill_item_id   -- 经 BillID（陷阱：→F_PlanItem.ID）
  ← JOIN production_plans pp       ON pp.id = ppi.plan_id
  ← pp.bill_date                                              -- 取 F_Plan.BillDate
```

迁移 SQL 在 staging 载入后 JOIN 三级取 `bill_date`，回填到 `production_plan_costs.bill_date`（NOT NULL）。

### 5.4 估算行数 / 迁移时长

### 6.1 `production_monthly_mv`（月度上卷 · V56）

```sql
CREATE MATERIALIZED VIEW production_monthly_mv AS
SELECT 'PLAN'::text  AS doc_type,
       date_trunc('month', bill_date)::date AS ym,
       goods_id,
       COALESCE(NULL, '00000000-0000-0000-0000-000000000000'::uuid) AS client_id,  -- 生产计划无 client FK，留 nil-uuid
       SUM(qty)   AS plan_qty_sum,            -- 排产数量合计
       SUM(oqty)  AS order_qty_sum,           -- 销售订货量合计
       SUM(iqty)  AS finished_qty_sum,        -- 完工/进仓量合计
       SUM(rqty)  AS inbound_qty_sum,         -- 入库量合计
       COUNT(*)   AS line_cnt
FROM production_plan_items
WHERE is_deleted = false
GROUP BY 1, 2, 3, 4
UNION ALL
-- 日报（F_DateReport 空结构，预留结构，本期 0 行）
SELECT 'DAILY'::text,
       date_trunc('month', bill_date)::date,
       goods_id,
       '00000000-0000-0000-0000-000000000000'::uuid,
       SUM(qty), SUM(0), SUM(qty), SUM(0), COUNT(*)
FROM production_daily_report_items
WHERE is_deleted = false
GROUP BY 1, 2, 3;

CREATE UNIQUE INDEX mv_production_monthly_uidx
    ON production_monthly_mv (doc_type, ym, goods_id, client_id);
CREATE INDEX mv_production_monthly_goods ON production_monthly_mv (goods_id);
CREATE INDEX mv_production_monthly_ym    ON production_monthly_mv (ym);

CREATE OR REPLACE FUNCTION refresh_production_monthly_mv() RETURNS void AS $$
BEGIN
    REFRESH MATERIALIZED VIEW CONCURRENTLY production_monthly_mv;
END;
$$ LANGUAGE plpgsql;
```

```sql
-- 生产管理迁移：F_Plan/F_PlanItem/F_PlanCostItem → production_plans /
--   production_plan_items / production_plan_costs（136 万行分区表）
-- =====================================================================
-- 用法：bash server/legacy_migration/migrate.sh --production --confirm-destructive
-- 前提：V42-V49 + V51 sales_order_items/sales_order_cost_items（销售模块必须先迁）+ V55 已建表；
--   主档 goods/colors/units/suppliers 已迁。

       s.product_no,

       (SELECT id FROM colors WHERE legacy_id = s.color_legacy_id AND s.color_legacy_id <> 0),

       COALESCE(s.poqty,0), COALESCE(s.piqty,0),

       NULLIF(s.remark,'')
FROM item_stage s JOIN plan_stage p ON p.legacy_id = s.plan_legacy_id;

-- ======================== 3. production_plan_costs（按年分批） ========================
-- 反冗余 bill_date/bill_no：JOIN cost_stage → item_stage → plan_stage 三级链
-- parent_id 先留 NULL，全量 INSERT 后 UPDATE 回填（同 stock_document_items upstream 模式）

-- 3a. 主 INSERT（按年分批，每年一个 INSERT，单批失败可独立重跑）
--     使用 query 全量一次性 INSERT 亦可（PG 能处理 1.36M），分批是为了运维清晰
INSERT INTO production_plan_costs (
    legacy_id, bill_item_id, bill_no, bill_date,
    parent_legacy_id, level, node_class,
    goods_id, color_id, master_goods_id, master_color_id, sales_order_cost_item_id,
    qty, dqty, pqty, lqty, slqty, rqty, order_qty, in_qty,
    pdraw_qty, owdraw_qty, pwdraw_qty, eo_qty, ei_qty, ew_qty, mqty, pa_qty,
    price, total, supplier_id, ass_team_legacy_id,
    source_doc_no, lstatus, summary)
SELECT s.legacy_id,
       (SELECT id FROM production_plan_items WHERE legacy_id = s.bill_item_legacy_id),
       p.bill_no, p.bill_date,                                       -- ⭐ 反冗余分区键
       s.parent_legacy_id, s.level, s.node_class,
       (SELECT id FROM goods  WHERE legacy_id = s.goods_legacy_id),
       (SELECT id FROM colors WHERE legacy_id = s.color_legacy_id AND s.color_legacy_id <> 0),
       (SELECT id FROM goods  WHERE legacy_id = s.mgoods_legacy_id AND s.mgoods_legacy_id <> 0),
       (SELECT id FROM colors WHERE legacy_id = s.mcolor_legacy_id AND s.mcolor_legacy_id <> 0),
       (SELECT id FROM sales_order_cost_items WHERE legacy_id = s.soc_item_legacy_id AND s.soc_item_legacy_id <> 0),
       COALESCE(s.qty,0), COALESCE(s.dqty,0), COALESCE(s.pqty,0), COALESCE(s.lqty,0),
       COALESCE(s.slqty,0), COALESCE(s.rqty,0), COALESCE(s.order_qty,0), COALESCE(s.in_qty,0),
       COALESCE(s.pdraw_qty,0), COALESCE(s.owdraw_qty,0), COALESCE(s.pwdraw_qty,0),
       COALESCE(s.eo_qty,0), COALESCE(s.ei_qty,0), COALESCE(s.ew_qty,0),
       COALESCE(s.mqty,0), COALESCE(s.pa_qty,0),
       s.price, s.total,
       (SELECT id FROM suppliers WHERE legacy_id = s.supplier_legacy_id AND s.supplier_legacy_id <> 0),
       s.ass_team_legacy_id,
       CONCAT_WS(' | ',
                  CASE WHEN NULLIF(s.p_order_no,'') IS NULL THEN NULL ELSE 'PO:'  || s.p_order_no END,
                  CASE WHEN NULLIF(s.p_in_no,'')    IS NULL THEN NULL ELSE 'PI:'  || s.p_in_no END,
                  CASE WHEN NULLIF(s.p_wdraw_no,'') IS NULL THEN NULL ELSE 'PW:'  || s.p_wdraw_no END,
                  CASE WHEN NULLIF(s.p_draw_no,'')  IS NULL THEN NULL ELSE 'PD:'  || s.p_draw_no END,
                  CASE WHEN NULLIF(s.o_wdraw_no,'') IS NULL THEN NULL ELSE 'OW:'  || s.o_wdraw_no END,
                  CASE WHEN NULLIF(s.eo_no,'')      IS NULL THEN NULL ELSE 'EO:'  || s.eo_no END,
                  CASE WHEN NULLIF(s.ei_no,'')      IS NULL THEN NULL ELSE 'EI:'  || s.ei_no END,
                  CASE WHEN NULLIF(s.ew_no,'')      IS NULL THEN NULL ELSE 'EW:'  || s.ew_no END,
                  CASE WHEN NULLIF(s.p_app_no,'')   IS NULL THEN NULL ELSE 'PAPP:' || s.p_app_no END),
       s.lstatus, NULLIF(s.summary,'')
FROM cost_stage s
JOIN item_stage i ON i.legacy_id = s.bill_item_legacy_id
JOIN plan_stage p ON p.legacy_id = i.plan_legacy_id;
-- ⚠ 若单事务 OOM/超时，改为按年循环：WHERE EXTRACT(YEAR FROM p.bill_date) = 2022 等

-- 3b. BOM 自引用 parent_id 回填（parent_legacy_id → 新 UUID）
UPDATE production_plan_costs c SET parent_id = p.id
FROM cost_stage s, production_plan_costs p
WHERE c.parent_legacy_id = s.parent_legacy_id
  AND s.legacy_id = c.legacy_id            -- 当前子行
  AND s.parent_legacy_id <> 0              -- 顶层不回填
  AND p.legacy_id = s.parent_legacy_id     -- 父行新 UUID
  AND p.bill_date = c.bill_date;           -- 同年同分区（父子 bill_date 必一致）

COMMIT;

-- ======================== 校验 ========================
SELECT '✔ 计划单 '   || (SELECT count(*) FROM production_plans) AS r
UNION ALL SELECT '计划明细 ' || (SELECT count(*) FROM production_plan_items)
UNION ALL SELECT 'BOM 展开 ' || (SELECT count(*) FROM production_plan_costs) || '（应 = 1359875）'
UNION ALL SELECT 'BOM 顶层行（parent_id NULL） ' || (SELECT count(*) FROM production_plan_costs WHERE parent_legacy_id = 0)
UNION ALL SELECT 'BOM 父子挂接（parent_id NOT NULL） ' || (SELECT count(*) FROM production_plan_costs WHERE parent_id IS NOT NULL)
UNION ALL SELECT 'BOM 孤儿（bill_item_id 无对应） ' || (SELECT count(*) FROM production_plan_costs c WHERE NOT EXISTS (SELECT 1 FROM production_plan_items i WHERE i.id = c.bill_item_id))
UNION ALL SELECT 'BOM 孤儿（goods_id NULL） ' || (SELECT count(*) FROM production_plan_costs WHERE goods_id IS NULL)
UNION ALL SELECT 'BOM 反冗余 bill_date 覆盖 ' || (SELECT count(*) FROM production_plan_costs WHERE bill_date IS NOT NULL)
UNION ALL SELECT '计划明细挂销售订单（FK） ' || (SELECT count(*) FROM production_plan_items WHERE sales_order_item_id IS NOT NULL)
UNION ALL SELECT 'BOM 挂销售成本（SOCItemID FK） ' || (SELECT count(*) FROM production_plan_costs WHERE sales_order_cost_item_id IS NOT NULL)
UNION ALL SELECT '货品历史引用锚（全库） ' || (SELECT count(*) FROM goods WHERE auto_created = TRUE)
UNION ALL SELECT '分区分布：' || string_agg(yr || '=' || cnt, ', ')
  FROM (SELECT EXTRACT(YEAR FROM bill_date)::text AS yr, count(*) AS cnt
        FROM production_plan_costs GROUP BY 1 ORDER BY 1) z;
```

### 8.4 校验维度

- **总数一致**：`production_plans` = 7235 / `production_plan_items` = 73388 / `production_plan_costs` = 1359875
- **legacy_id 覆盖**：三表 legacy_id NOT NULL，`COUNT(*) = COUNT(legacy_id)`
- **bill_date 覆盖**：`production_plan_costs.bill_date IS NULL` = 0（分区键必须非空）
- **分区分布**：按 `EXTRACT(YEAR FROM bill_date)` 校验各年分布（预期集中在 2022–2026）
- **FK 链路**：`production_plan_costs.bill_item_id` 经 `production_plan_items.legacy_id` 映射成功率 = 100%（孤儿 = 0）
- **BOM 树完整性**：`parent_legacy_id <> 0` 的行 `parent_id` 必须非 NULL（除 legacy 父行不存在外，记录异常数）
- **销售骨干**：`sales_order_item_id` / `sales_order_cost_item_id` 非空数（取决于老库 JOIN 率，预期较低，样本 S_OrderID=0）

## 九、风险与待确认

| 风险 | 影响 | 对策 |
|---|---|---|
| **F_PlanCostItem 136 万行迁移时长** | 单事务 8–20 分钟，失败回滚代价大 | 按年分批 INSERT（`WHERE EXTRACT(YEAR FROM p.bill_date) = N`），单批 ~100k 行；失败可单批重跑；低峰期执行（[23] §八 4） |
| **BOM 自引用 parent_id 回填** | 子父行跨分区时 FK 映射失败 | 父子 `bill_date` 必一致（同 F_PlanItem 的 BOM），UPDATE 加 `AND p.bill_date = c.bill_date` 限制；校验 parent_id NULL 数 |
| **S_OrderID JOIN 率** | F_PlanItem.S_OrderID 样本全 0（直接计划生产）→ sales_order_item_id 非空率可能很低 | 抽样 `SELECT count(*) FROM F_PlanItem WHERE S_OrderID <> 0` 确认；销售模块未上线时，可先建 staging 不挂 FK，后续 UPDATE 回填 |
| **WorkShop varchar(250) 装数字** | 样本 `37`/`38` 是车间编号字符串还是 B_WorkShop.ID？无法精确落到 departments | 新库留 `department_id NULL` + `workshop_name` 原样文本；后续建 `workshop_legacy_map` 回填（[23] §八 2） |
| **F_PlanCostItem 反冗余 bill_date 失败行** | 若 BillID→F_PlanItem→F_Plan 链断裂，bill_date 为 NULL → 分区拒绝写入 | staging JOIN 时若 p.bill_date NULL，用 `'1970-01-01'` 兜底并记 warning count；校验段报告此类异常行 |
| **成本核算本期不做** | F_PlanCostItem 不能编辑、不能查"需购量"、不能重算 BOM | 明确"本期只读保数据"，UI 不暴露编辑入口；BOM 查询界面提供（read-only），MRP 公式归未来模块 |
| **多值溯源降级文本** | POrderNo/EONo/PDrawNo 等丢失多值结构，跨模块追溯减弱 | 用前缀化合并 `'PO:xxx | EO:yyy'` 保留类型可识别；四模块全部上线后补关联表回填（[18] §七） |
| **销售模块强依赖** | V51 sales_order_items/sales_order_cost_items 未建 → SOCItemID/S_OrderID 无法映射 | **迁移顺序硬约束**：先 V51 销售再 V55 生产；本期若销售滞后，可先迁 F_Plan/F_PlanItem，F_PlanCostItem 等 V51 完成再补 |
| **人员字段**（MakeID/ApproverID/WorkerID/Seller） | B_Worker↔employees 无 legacy_id 对齐 | 留 NULL + `*_legacy_id INT` 留底，后续 `worker_legacy_map` 回填（同采购 [15] §九） |
