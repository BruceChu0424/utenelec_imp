# V904 原料身份与单耗待核证据

用户已确认注塑件采用 PC 面板料 E-15，但当前没有可靠单耗，应先保存对应关系及待核项。
`goods_material_identity_evidence` 记录产品 UUID、原料 UUID、可空颜色、来源种类、非空
`provenance`、导入 run 与操作者，状态为 `PENDING_QUANTITY`。导入来源必须关联真实
`legacy_migration_runs.run_id`；同一有效产品、原料、颜色身份不能重复，禁止自环和占位端点。
同一产品可记录多种已经明确身份的原料，均保持待核用量；禁用原料不能新建或恢复当前
关系，原料后续禁用时退出当前材料证据投影，旧证据保留。禁用父件仍可保留自身资料。

关系中没有用量、金额或换算字段。它不写 `goods_bom_items`，不改变货品的
`ORDER/PERIODIC`，不启用车间整批领料，也不创建工单、物料需求、预留、库存、成本或
学习样本。未知单耗不能按 0、1、旧期初数量或无证据重量补齐。

组装页沿既有材料证据查询展示“原料身份核对”和“单耗待核，尚未加入 BOM”，保留材料
编号、名称、颜色、基本单位和来源记录数。父件仍由原入口核验可见性，材料继续按现有
归属范围过滤；来源 JSON 与导入细节不进入该读接口。已有正式 BOM 时，仅相同父件、
原料 UUID 及颜色身份的直接边显示“已在 BOM 中”，同名另一身份或跨层边不冒充直接边。

这不是已经确认的生产 BOM。工程日后核实设计用量或单重后，沿现有 BOM 维护与权限
流程生成正数量配方，继续执行重复组件、自环、循环、单位和停用检查；本迁移不提供
跳过这些校验的写入口。水口料及不良料属于已明确的产出/废料语义，不由此推导原料
消耗或自动回用循环。

新表登记 FULL 数据变更审计与业务清空 PRESERVE，原料及颜色的有效引用进入主档删除
保护目录，父件按自身附属主档配置处理。该迁移只建立模型，不自动插入任何业务关系。

验证包括真实 PostgreSQL 上的来源 FK、重复/自环约束、无业务副作用、准确 BOM 关联、
原读取范围过滤及业务清空保留，另有现有 Flutter 组装页的中文状态与打开证据回归。
源码与隔离测试不代表本地候选导入已完成或公司服务器已经部署。
