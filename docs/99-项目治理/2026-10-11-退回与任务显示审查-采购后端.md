## 根因与最终契约

财务驳回只结束本次 `procurement_order_approval_cases`，原订单继续为草稿并保留全部来源份额，供原单修订重提。原 `purchase_pending` / `subcontract_pending` 和 Java 分解算法仅扣除 PENDING case；case 变为 REJECTED 就不再扣除来源。原单仍进入 FINANCE_REJECTED 任务，两边由此分叉。委外 `fn_subcontract_application_open_qty` 也只扣 PENDING，因此齐料解锁读模型有同一问题。

本次采用下列契约，不把单据驳回当成取消需求：

| 订单事实 | 申请未分解量的口径 | 执行出口 |
|---|---|---|
| 普通未提交草稿，无财审 case | 保持现有规则，不作财务占用 | 订单草稿；未分解来源按现规则保留 |
| status=0，最新 case=PENDING | 当前来源份额持续占用 | 原订货单等待财务 |
| status=0，最新 case=REJECTED | 同一当前来源份额持续占用 | 原订货单修订重提 |
| 原退回订单减少/移除某条来源份额 | 只释放减少/移除的部分；未变化的行继续占用 | 原订单与来源实际剩余分别显示 |
| 原退回订单再次提交或再次驳回 | 仅当前来源份额一次，不累计历次审批 | 原单进入最新财审轮次 |
| 取消/删除原草稿订单 | 订单终态/删除事实排除全部未生效占用 | 申请实际剩余重新可分解 |
| 已批准订单 | `ordered_qty` / `gift_ordered_qty` 承担已生效份额；不再扣草稿占用 | 原已生效执行链 |
| 已批准订单改量复核，含实物已结案 | status=1、is_closed 和已生效数量保持；最新复核不再额外扣申请 | 最新待复核/退回映射在进行中，跨 30 天仍可见，明确显示“改量待财务复核/改量财务退回” |
| 已批准订单红冲 | 现有来源份额与生产挂接对称撤销；不受本次读模型补充改变 | 实际恢复的来源数量 |

实物未分解量 = MAX(申请实物需求 − 已批准收费/赠品份额 − 当前在审/退回待修订收费/赠品份额, 0)。保留明确超采许可；不把订单数量截断到申请剩余，也不新增“数量必须小于剩余”的错误限制。手工无来源订单不占用任何申请。现代合并来源和历史采购单锚点只计一次；V1 赠品参与实物需求，历史赠品备注仍不增加需求。

取消接口的现有能力有区别：采购草稿支持取消（status=2），含未被财务认领的在审单；委外服务没有同款取消接口，退回原草稿使用既有删除，已生效单使用受控红冲。本次没有新增委外取消端点或状态机。

## 实现与并发边界

- V854 新增普通 SQL STABLE 函数 `fn_procurement_order_latest_approval_status(text, uuid)`，读取最大 attempt。V196 已有 `(order_type, order_id, attempt)` 唯一约束和相同顺序的读取索引，最大 attempt 唯一；不新增索引或业务表。
- 采购 `PurchaseRequestQuantities.pendingJoin`、委外 `SubcontractApplicationService.decompositionPreview`、`SubcontractOrderService.planSourceSplits`、已审订单 `ProcurementOrderSourceRevisionService` 的其他草稿占用容量均按最新 PENDING/REJECTED。
- V854 只重建相关读函数/视图。`v_procurement_decomposition_tasks` 的申请占用、在审订单和退回订单统一读取最新财审状态，在审/退回行互斥；保留 V853 的收费/赠品实物、来源日期、供应商与 DRAW_OPEN 等既有投影。
- `is_closed` 表示实物/数量结案，不表示财务复核办结。已批准订单最新财审 PENDING/REJECTED 优先于 closed 判定，跨 30 天历史窗口仍可见；复核通过才恢复原实物执行状态或 COMPLETED。投影仅供任务列表与计数使用，已核对实际领料、收货、供给授权没有读取该工作台视图。财务退回红数包含实物 open_qty=0 的复核任务，未重开物理结案或释放来源。
- 采购/委外单据列表当前财审筛选明确限制 active status=0/1，排除已取消/反审记录的历史 case。单据 PENDING_FINANCE / FINANCE_REJECTED 桶包括 status=0/1；委外 EXECUTING 限已生效未实物结案且没有当前 PENDING/REJECTED，避免进行中合计重复。APPROVED 仍保留原有“已审总量”，不作为互斥阶段参与求和。
- 原单修订仍在现有来源/订单/库存锁范围内先移除旧草稿行，再重建当前来源份额，避免把自己的旧份额重复扣除。财务原有 case 身份、版本、认领、快照校验、审批事件和事务保持原契约。
- 该新增函数没有保存数据，不是 SECURITY DEFINER，也不是业务清空维护函数。已核对 reset/oracle 的业务表与索引集合及指定维护函数权限契约；没有需要同步的新增业务状态或索引。
