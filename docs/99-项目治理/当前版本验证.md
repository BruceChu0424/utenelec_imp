## 数据库升级演练

发布前只读核对公司服务器运行 v2.5.2，Flyway V811/737、readiness UP。将其 28,831,520 字节 custom dump 恢复到本机独立 PostgreSQL 16 容器，保留角色名、对象所有者及授权关系，使用迁移身份进行前向升级；没有把本机数据库覆盖公司库，也没有执行公司业务清空。

V812 至 V819 共八个迁移已在该副本通过，745 个历史/新增迁移校验通过。逐表行数及排序行摘要对比仅出现权限目录、授权纪元、迁移历史、相应追加审计及四张新增空表；业务数量、金额、人员及来源表摘要未变。原始备份和包含现场标识的摘要只存本机，不提交仓库。

副本中只剩一份已完成的测试产品分析，未见截图对应的旧分析及 600/400 重复单据。因此原截图的历史处置不能据此确认；新增隔离回归覆盖两来源各 100、先下 400 的 BUY 与 MAKE 供给路径。历史正式单据若已存在重复，必须核对审核、领用、入库后沿原撤回链处理，不能直接删行。

## 验证与发布口径

- 已完成的专项结果分别记录在本机测试日志；最后统一格式、Flutter analyze/全量测试、后端单元/架构/契约以及完整数据库分片，以同一冻结提交重新汇总。
- Windows 无法执行的 Linux 部署/进程锁场景在 Linux 容器和 GitHub Linux 作业验证。浏览器 IndexedDB 测试单列 Chrome 门，不能用原生存储测试代替。
- 官网静态来源及本机 SQLite 中共 75 个 raw 图片引用均存在；这证明清理未破坏这些已检查的引用，不替代独立网站运行环境的内容验收。
- 正常业务拒绝、对抗测试主动触发约束错误、首次测试库创建管理员提示与真实服务启动告警分开核验；不关闭警告、不删失败用例来制造通过。
- 发布按 [Git 规范](../00-项目准则/11-Git提交与合并规范.md)经 PR 合并，Quality Gate、CodeQL 和依赖扫描必须在最终 SHA 全部通过，再推送 v2.5.3 标签由 [Simple Release](../../.github/workflows/simple-release.yml)签名上传。
- 更新器先验证签名和清单，含迁移时先备份、停服并前向升级，之后切换并验证健康。迁移后若启动失败，保持应用停止，结合备份恢复或前向修复，不能让旧 JAR 直接运行于未核验的新结构。

日常运行步骤见[现役发布手册](../../deploy/simple/RUNBOOK.zh-CN.md)。旧候选的数字和未部署结论留在各自历史专项或 Git 历史，不再作为当前状态。
