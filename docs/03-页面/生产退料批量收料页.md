# 生产退料批量收料

> 路由：`/warehouse/material-returns/batch-receive`
> 别名：批量退料收料、整批生产退料

## 页面定位

仓库逐张核对已选生产退料单的实物数量并确认收料。

## 办理与边界

- 从入库任务中心的生产退料任务选择原始明细进入，整批保留每张单据的来源身份和所选明细 ID；核对和提交不能扩展到同单未选行。
- 普通 WDRAW 原退料单按同一库存事务完整收仓。只选择部分行时，仅显示所选行并提示返回选齐同单明细，不提交收料；服务端 `material-return/confirm.itemIds` 对原单明细做集合一致性校验。内料仓 RETURN 则沿用逐行命令，两种办理边界不因同一分类而混用。
- 查看需要 `stock_doc:view`，确认收料需要 `stock_doc:approve`；查看权限不包含确认权限。
- 按原单据核对货品、颜色、单位、仓库与原领料来源。数量带原计量单位，不能把不同物料合成一个收料数。
- 发送前重新核对当前身份与权限；每张单据的状态、版本、仓库范围及实际收料边界由服务端独立校验。
- 已成功的单据保持成功；回执未查明时先核对原结果，恢复原请求身份，不重新办理已成功成员。
- 每张退料单有独立命令。原 A 结果未知时只按已保存的来源、实际仓、原明细集合及同一幂等键核对；提交前重新读取 A 验证当前查看资格和原范围。后续未派发 B 取消、删除或不可读只阻止 B，不妨碍 A 核对；不可读来源只显示 ID，不回填旧单据快照。A 本身不可读时不重放，仍保留原命令与未知状态。A 核对成功后的草稿保存原批次全体来源，B 继续未派发，不宣称整批完成。
- 返回保留原入库任务上下文，单张失败不抹掉整批已经完成的记录。

内料仓 RETURN 与普通 WDRAW 在同一生产退料分类显示，命令仍各自独立。内料仓批量入口 `/workshop-material/issue/batch` 在同一张明细表核对和编辑实际仓库及数量，统一确认后内部逐申请提交，不增加逐单进入步骤；需 `workshop_material:view` 查看、`workshop_material:issue` 收料。办理所选行后，未选行仍待收；已办理行不会因同单再选其它货品重复入库。
