## 一、模块定位与表清单

老库 `O_` 前缀 = **仓库管理（库存出入库操作）** 单据集，与采购 `P_`、销售 `S_` 并列。9 类单据「主表 + 明细表」成对，全部经触发器写统一台账 `StockGoods`（454,104 行）。

> ⚠️ `M_`/`E_`/`T_` 前缀是**其他账套/模块**（M_In BillNo `XS…`=销售向、E_=另一账套、T_=未启用空账套），**不属于仓库管理**，本次不迁。`S_`=销售，独立模块。

## 二、主表共性字段（9 类高度同构）

| 字段 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `ID` | int IDENTITY | 主键 | |
| `BillNo` | varchar(50) | 单据号 | **唯一**，前缀编码单据类型（CB/QR/QC/SL/ST/CJ/CC/PQ） |
| `BillDate` | datetime | 单据日期 | |
| `StockID` | int | 仓库 → `B_Storage.ID` | 调拨单为 `OStockID`(调出)+`IStockID`(调入) 两个 |
| `WorkerID`/`MakeID`/`ApproverID` | int | 经手/制单/审批 → `B_Worker` | 人员类，迁移记 `*_legacy_id`（V67，见 [17] §六） |
| `Remark` | varchar(250) | 备注 | |
| `Status`/`Status2` | int | 状态 / 上一次状态 | 状态机核心（见 §五） |
| `Cancel` | bit | 取消 | |
| `Total`/`STotal` | decimal | 合计 | 部分单据有 |

**各单据特有：**
- `O_Transfer`：`OStockID`+`IStockID`（调出仓 + 调入仓，**双仓库**）。
- `O_In`（产成品进仓）：`VendID`、`WorkShop`、明细带 `OrderNo`/`PlanNo`/`OrderID`/`PlanID`（关联销售订单/生产计划）。
- `O_Out`（产成品出仓）：`ClientID`、明细带 `OutID`/`OutNo`（关联销售出库）。
- `O_PDraw`（领料）：大量**逗号分隔多值反范式字段**（`ContractNo` varchar(2550)、`GoodsName`/`LNo`/`CName`/`CNumber`/`CSerial`/`CAnumber`/`CColor` varchar(1500~2500)）+ `PlanID`/`GoodsID`/`ClientID`/`AssTeam`（班组）。
- `O_WDraw`（退料）：`ReturnID`、`Department`。
- `O_Check`（盘点）：`CheckID`（盘点人）。
- `O_OtherIn`/`O_OtherOut`/`O_Waste`：`BillType` varchar(50)（**二级类型区分**，如损耗可能挂在这里）、`bmid`。

## 三、明细共性字段

| 字段 | 含义 |
|---|---|
| `ID` | 明细主键 |
| `BillID` | → 主表 `ID` |
| `GoodsID` | 货品 → `B_Goods.ID`（新库 `goods.legacy_id`） |
| `ColorID` | 颜色 → `B_Color.ID`（可空） |
| `UnitID`/`URate` | 单位 / 换算率（`QTY×URate`=基本量，用于库存） |
| `QTY` | 数量（float，主单位） |
| `STotal`/`Total` | 金额 |
| `Weight` | 重量 |
| `Summary` | 摘要 |
| `StorgePlace` | 库位 → `B_StoragePlace.ID` |

**链路字段（单值 int 真外键骨干）：**
- `O_WDrawItem.PDrawID`/`PDrawNo` → 领料单 `O_PDraw`（退料↔领料）。
- `O_InItem.OrderID`/`OrderNo`、`PlanID`/`PlanNo` → 销售订单 / 生产计划。
- `O_OutItem.OutID`/`OutNo` → 销售出库。

**多值 varchar 软关联（反范式，降级为占位文本）：** `O_PDrawItem.SOrderNo`/`OWDrawNo`/`BomItemID`（varchar 2500，逗号分隔）——与采购明细同款老库反模式，新库不照搬。

**盘点特有：** `O_CheckItem.NowQTY`（实盘数）、`SurplusQTY`/`SurplusWeight`（盘盈盘亏量）、`Reason`（原因）—— 盘点单的库存效果 = `NowQTY − 账面` 的差额（盘盈 +/盘亏 −）。

## 四、StockGoods 台账（统一库存账 · 454,104 行 · 全链路核心）

所有 `O_` 单据审核（`Status=1`）经触发器写 `StockGoods`，与采购收货/退货同表。

**粒度：** `StockID + GoodsID + ColorID + Year + StorgePlace`（一行 = 某仓某货某色某年某库位的账）。

**按月分列（老库核心反模式）：** 每行硬编码 12 个月列：
- `INQTY1..12` / `INTotal1..12` / `INWeight1..12`（入）
- `OUTQTY1..12` / `OUTTotal1..12` / `OUTWeight1..12`（出）
- `QTY` / `Total`（当前余额）、`APrice`（均价）、`Fact*`/`All*`（累计）

> ⚠️ 这是采购溯源 [14] §4.4 已点名的反模式：跨年复杂、扩展僵化、写死 12 月。**新库用 `stock_movements`（流水）+ `stock_balances`（余额）取代**（V45 已建）。仓库管理模块迁完，`stock_balances` 的期初余额即从 `StockGoods.QTY` 反推（见 [17]）。

- **历史无草稿（0）态**——与采购一致：老库"保存即生效"，迁过来只有 1/-1。

- 新库保留语义，逻辑上移到 Service 层事务（去触发器）。

## 八、老库核心问题（新库要解决的）

1. **业务逻辑全埋触发器**（台账/回写/成本）→ 新库上移 Service 层事务。
2. **按月分列台账**（INQTY01..12 写死）→ 新库流水 + 余额模型（已建 `stock_movements`/`stock_balances`）。
3. **9 套同构单据表 + 18 张报表视图**重复 → 新库可用**统一单据表 + `doc_type` 判别**（见 [17] 决策），报表收敛为流水查询。
4. **多值 varchar 溯源**（领料 BOM/销售单号）→ 降级占位文本，待销售/生产模块补关联表。
5. **`float` 存数量金额** → 新库 `numeric(18,4)`。
6. **库位 `StorgePlace`** 老库独立表 → 新库首版简化（仓库内文本/后置建表）。
