# 85 · V466 IQC 退回补货单通道收口

> 状态：源码候选（本地实现，未推送 CI）｜日期：2026-09-03
> 关联：[ADR-024 采购/委外 IQC](../99-决策记录-ADR/ADR-024-三架构缺口闭合-退货处置-委外守恒-IQC.md)、[品质部检查结果页](../03-页面/品质部检查结果页.md)、[入库任务中心页](../03-页面/入库任务中心页.md)

## 问题（2026-09-03 内测服务器实证）

采购收货 200、IQC 合格 190 / 不合格 10、仓库登记实物退回供应商之后，系统同时打开了
**两条互不知晓的补货通道**：

1. **原订单通道**：`ProcurementArrivalControlService.refreshAfterReturn` 把预计到货
   重开为「应到 200 · 已收 190 · 待到 10」，原订货单等待供应商补 10（补货收货由
   `ProcurementIqcReplacementAllocationService` 的退回释放额度授权，本就支持走原订单）；
2. **重新下单通道**：`MaterialAnalysisService.reconcileSupplyActionStatuses` 因「原采购
   需求已无在途」把供给行动整个 CANCELLED，缺口 10 重新出现在物料分析，引导
   重新通知 → 新采购申请 → 新订货单 10。

两条通道叠加 = 同一批欠货可能被补两次（用户视角即「一张需求变成两张单、数量口径乱」）。

## 根因

「在途」口径只看 `qty − received + returned`，而 IQC 不合格实物退回**从不写**
`purchase_order_items.returned_qty`（那是采购退货单 `purchase_returns` 的语义），
退回事实只落在 `procurement_iqc_rejection_cases.return_recorded_at`。于是退回登记后
原订单事实上重新欠货，所有在途判断却读到 0 → 行动被取消 → 邀请重新下单。

## 决策（用户拍板：原订单继续补）

- 补货默认走**原订单**（预计到货重开 + 补货收货授权），退回登记后物料分析
  **不再邀请重复下单**——下达余量扣除「已取消 IQC 行动对应原订货单的当前欠货」；
- 重新通知通道保留给「退回尚未登记」的窗口与显式补采场景（全不合格 E2E 口径不变）；
- 行动本体按 V250 追加式契约**保持 CANCELLED 不复活**（触发器
  `trg_guard_preplan_supply_action_history` 显式禁止复活已取消行动，尊重既有架构）。

## 迁移内容（纯投影修正，不新增表、不动任何行动行）

`v_preplan_buy_action_slice_progress`（V463 sources 分摊版）：`item_receipts` CTE 新增
`returned_failure_base`（按订货行汇总已退回不合格基本量，案件 `return_recorded_at IS
NOT NULL` 且状态在 `RETURN_RECORDED / CREDIT_CONFIRMED / CLOSED_NO_CREDIT /
FINANCE_EXCEPTION` 内），`source_progress.open_order_qty` 的 FIFO 分摊总量随之加上该值
→ `demand/safety_future_qty` 反映原订单真实欠货（活跃行动的覆盖、buySplitDetail 在途
展示、safety 分支取消守卫同时受益）。

## 应用侧配套（同批代码）

- `MaterialAnalysisCommandService.notifySupply`：可下达余量 = 需求 − 活跃行动覆盖 −
  **`cancelledIqcReplacementInFlight`**（因「到货质检存在不合格…需重新通知」取消的
  行动，其锚定申请行对应订货行的当前欠货 = 未收 + 已退 + 已退回不合格）——退回登记后
  缺口被原订单在途覆盖，不再重复生成申请；
- `MaterialAnalysisService.reconcileSupplyActionStatuses`：采购/委外两处「已无在途」
  NOT EXISTS 守卫在 fn_share 份额里加上已退回不合格基本量（多批到货场景：第一批判定
  不合格并登记退回后，剩余未到货部分仍在途，行动不得被误取消）；
- 退回**反向**（`return_recorded_at` 清空）后 failedReturned 归零：在途覆盖随之消失，
  缺口重新可通知——自愈，无需任何反向动作。

## 已知边界

- 「先重新通知、后登记退回」的时序下，替代行动（新申请/新单）与原订单预计到货并存，
  覆盖合计会大于缺口（只压掉第三次通知）；仍需业务上二选一收口（罕见序列，UI 任务
  徽章先推动登记退回）。

## 验证

- `FullChainEndToEndTest.partiallyRejectedReturnKeepsOriginalOrderAsSingleReplacementChannel`：
  20 到货 → FAIL 8 / PASS 12 → 确认入库 → 登记退回 → 行动保持取消、视图在途 8、
  **追加通知不生成新申请**、预计到货 12/20 OPEN、订单未结案；反向后欠货退出在途、
  替代申请恢复可生成。
- 既有全不合格链路 `fullyRejectedReceiptReleasesPlanningCoverageAndAllowsReplacementNotification`
  行为不变（退回未登记时 failedReturned = 0，全部口径与旧一致）。
