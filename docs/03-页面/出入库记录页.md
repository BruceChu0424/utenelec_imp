# 出入库流水页

> **⚠️ 2026-09-01 已并入[库存详情页](库存详情页.md)**：本页源码下线，
> 路由 `/stock/movement?goodsId=X` 重定向到 `/stock/item/X`，无参旧链回即时库存；
> 按货品看流水与「双击回源单」全部迁入库存详情页的「出入库流水」分段
> （源单映射口径不变）。本文保留作历史口径档案。

> 路由：`/stock/movement`（`lib/features/stock/pages/stock_movement_page.dart`）
> 权限：`stock:view`
> 上层：[库存余额页](库存列表页.md)、[即时库存页](即时库存页.md)、货品资料详情或工作台 PMC 运营部

## 一、定位

只读查看真实库存增减流水。页面按时间展示由采购、销售、仓库和生产等业务单据形成的库存影响，
也是授权余额调整回查 `CHECK` 凭证的入口。本页不提供脱离业务单据的“新增出入库”。

## 二、入口与导航

- 工作台 PMC 运营部「出入库记录」可直接进入全部流水。
- 库存余额详情带入 `goodsId + warehouseId`，定位到单一仓库和货品。
- 即时库存或货品资料详情带入 `goodsId`，查看该货品跨仓流水。
- 预置货品显示为可清除的 chip；清除后恢复全部货品。
- 类型 9 盘盈或类型 10 盘亏且有 `sourceDocId` 时，点击行进入来源 `CHECK` 详情；
  查看凭证详情还需 `stock_doc:view`。

## 三、响应式布局

- 使用 `UtenListTwoPane`：筛选区在上（整宽，按可用高度 45% 封顶、内部可滚），`MasterDataTableView` 在下占满剩余高度（2026-09-10 起所有断点一致，不再左右分栏）；窄屏同样纵向排列。
- 当前页面过滤控件只有预置货品 chip 和仓库下拉，二者可以叠加。
- 列为日期、类型、货品、仓库、带正负号的数量。
- 日期和数量支持服务端排序；取消排序后恢复交易时间倒序。
- 列表使用服务端分页，不另维护手机卡片或离线缓存副本。

## 四、涉及的 Uten 组件

`UtenAppBar` / `UtenBackButton` / `UtenContentContainer.wide` / `UtenListTwoPane` /
`MasterDataTableView` / `InputChip`。

## 五、功能点

1. 按仓库筛选；支持路由传入货品过滤并随时清除。
2. 展示日期、库存动作类型、货品、仓库和带方向的数量。
3. 日期、数量排序与分页均由后端执行。
4. **全类型行点击跳转（2026-08-16 起）**：按 `sourceDocType`（服务端 SRC_* 常量）映射——
   采购收货/退货→采购单据详情、销售出库/退货/其它出库→销售单据详情、委外回厂/成品退/发料/
   材料退/损耗→委外单据详情；统一 `STOCK_DOC` 来源按 movement_type（V59 字典 1-20）推导
   仓库单据 code（5 DRAW/6 WDRAW/7,8 TRANSFER/9,10 CHECK/11 OTHER_IN/12 OTHER_OUT/
   13 FINISHED_IN/14 FINISHED_OUT）。普通盘点和授权余额调整共用同一条 CHECK 追溯链。

当前页面请求：

```http
GET /api/stock/movements?goodsId=&warehouseId=&page=&size=&sort=&order=
Authorization: stock:view
```

后端接口还接受 `movementType`、`dateFrom`、`dateTo`，但当前页面没有对应筛选控件，文档不得把它们写成已上线的页面能力。

## 六、授权调整追溯

授权余额调整由余额页发起后：

1. 自动生成并审核一张一行 `CHECK`；
2. 调增写类型 9 盘盈流水，调减写类型 10 盘亏流水；
3. 流水的 `sourceDocId` 指向该 `CHECK`；
4. 点击流水可在凭证详情查看单号、原因、账面数量、实盘/目标数量、差额、制单主体与审计时间链。

流水只记录结果，不承担授权入口。是否可以调整余额仍由独立的 `stock:balance:adjust` 控制，
与本页的 `stock:view` 无关。详见
[仓库盘点修正与历史单据处理](../数据迁移/50-仓库盘点修正与历史单据处理.md)。

## 七、涉及的数据实体

- `stock_movements`：库存增减流水；
- `stock_balances`：流水影响后的当前余额；
- `stock_documents` / `stock_document_items`：`CHECK` 等来源凭证；
- `goods` / `warehouses` / `colors`：名称解析所需主档。

## 八、权限要求

- 页面与流水查询：`stock:view`。
- 进入来源 `CHECK` 详情：`stock_doc:view`。
- 本页没有录入、调整、审核或红冲能力。
- 调整余额：`stock:balance:adjust`；授权调整单红冲还同时要求 `stock_doc:edit`。

## 九、边界情况

- 无记录：显示「暂无流水」。
- 从余额页带入货品和仓库时，两项同时生效；清除货品不会自动清除仓库。
- 无 `sourceDocId` 的历史盘盈/盘亏行保持只读，不能伪造详情链接。
- 未知 sourceDocType 且无法按 movement_type 推导的行不动作（不猜路由）；无 `sourceDocId` 的
  历史行保持只读，不能伪造详情链接。
- 后端或网络失败时显示错误并允许按当前页、当前筛选重试。

## 十、仓库单据凭证附件（2026-09-10）

流水回源的凭证详情（`/warehouse/:docType/:id`，`StockDocDetailPage`）对生产领料单
（DRAW）常驻「出库凭证/照片」文件区（`BusinessAttachmentSection`，ownerType
`STOCK_DOCUMENT`，ownerId=单据 UUID，分类：出库凭证/照片/其他），位于表头卡之后、明细
之前；出库弹窗内的同款区保留。此前该区只在出库弹窗里，出完或没有出库权限的人再也看不到
凭证。前端与服务端 `StockDocumentAttachmentAccessPolicy` 同口径：

- **可看**：`stock_doc:view` ∩ `attachment:view` ∩ 单据未删 ∩ 对象范围——与
  `StockDocService.detail` 一致：生产链单据按仓储组织对象范围
  （`ProductionStockTaskAccessPolicy.canAccessWarehouseTasks`）可跨制单人查看，手工单按
  制单人 maker/data-scope（`StockDocAccessPolicy.requireReadable`）隔离；不可达一律
  404「仓库单据不存在」，不泄露存在性（此前只查全局 `stock_doc:view`，其他部门持该权限
  即可读到生产领料凭证）。
- **可管（上传/删除）**：可看 ∩ 持 `stock_doc:approve` 或 `stock_doc:issue` ∩ **单据状态
  为草稿或已审**（已红冲 −1 的单据凭证冻结，409）∩ 对象范围可写（生产链单据要求仓库任务
  办理范围，手工单要求制单人可写范围）。前端 DRAW 的 `canManage` =
  `status != -1 && (status == 1 ? issue : approve ∩ issue)`（草稿=出库即审核）。
- 更新变体（上传确认/删除）在 `FOR UPDATE` 之后重读状态，并发红冲后不能再替换凭证。
