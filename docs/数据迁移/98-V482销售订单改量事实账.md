# 98 · V482 销售订单改量事实账

> 2026-09-05 · 前向迁移 · 新增一张 append-only 事实表，无存量改写

## 背景

用户口径（2026-09-05，当日二次修正）：销售订单在**财务确认后允许改量**，但改完
自动回到「待财务确认」；财务确认侧要能看到**修改清单——每行 以前多少 → 现在多少**。
（此前同日早些时候曾按「确认后禁改」实现，本迁移随之反转。）

## 迁移内容

- 新表 `sales_order_qty_change_logs`：
  - `order_id` / `order_item_id`（RESTRICT）、`old_qty` / `new_qty`（>0）、
    `changed_by_employee_id`（SET NULL）、`changed_at`；
  - 索引 `(order_id, changed_at DESC)`；
  - append-only 保留审计轨迹，无软删列。

## 行为链（同批代码）

1. `SalesOrderService.changeQty`：已审订单每次改量逐行写入本表；
   若改量前订单 `finance_confirmed = TRUE`，则改后置回 `FALSE` 重新进入财务
   确认队列，并投递「改量后待财务确认」通知（弹卡直达审核页）。
   `finance_confirmed_at` 保留为**上次确认时间**，作为修改清单的对照基线。
2. 财务队列（`SalesOrderFinancePendingDto`）新增 `changeCount`：
   上次确认之后的改量处数；>0 的行标注「改后待确认 · 改量 N 处」。
3. 财务审核详情（`SalesOrderFinanceReviewDto.qtyChanges`）新增修改清单：
   仅展示 `changed_at > finance_confirmed_at` 的行；重新确认后
   `finance_confirmed_at` 前进，旧清单自然归档隐藏。
4. 销售详情页改量弹窗：已确认订单显示红色警示「修改后将重新进入待财务确认」。

## reset 口径

`sales_order_qty_change_logs` = CLEAR（业务事实，系统测试清空）；
目录对注册 V482/444。
