# 远程身份验证页

> 路由：`/settings/remote-mfa`

所有已登录员工通过“设置 → 账号 → 远程身份验证”进入；仅管理本人验证器，代操作不可用。
实现：`lib/features/auth/pages/remote_mfa_page.dart`、`remote_mfa_repository.dart`、`widgets/remote_mfa_prompt.dart`。
设计使用 `frontend-design` 和现有 Uten 主题/设置行，中文、英文、韩文同源维护。

绑定流程：在公司内网开始绑定 → 统一密码再认证 → 当前页展示二维码和设置密钥 → 验证器输入六位动态码 → 服务端确认绑定。
二维码由现有 `qr_flutter` 在本机绘制，不调用外部二维码网站。密钥和 otpauth URI 仅保存在当前页内存，不写日志、草稿或偏好；
成功确认、到期、取消、离页、换账号及换服务器均清除展示。复制密钥是员工主动操作，应避免共享或留在共享剪贴板。
离页不自动撤销服务端pending记录；再次进入须重新发起，不能恢复读取旧密钥。

| 接口 | 用途 |
|---|---|
| `GET /api/auth/mfa` | 读取是否绑定、pending、当前会话验证期限、是否允许内网绑定和可信来源 |
| `POST /enrollment` | 本人公司内网、StepUp；返回本次密钥、otpauth URI、到期时间 |
| `POST /confirm` | 提交 `{otpCode}`，必须属于发起绑定的同一会话 |
| `POST /verify` | 本人当前会话提交 `{otpCode}`；不改变原业务命令，不重放业务请求 |
| `POST /disable` | 公司内网、StepUp及有效动态码；成功后撤销本人全部会话，客户端退出登录 |
| `POST /users/{id}/reset` | 公司内网超管、授权管理及StepUp，填写原因；重置目标并撤销其全部会话 |

表中 POST 路径均以 `/api/auth/mfa` 为前缀。服务端控制有效期、失败次数和重放拒绝，客户端不自行延长验证期限。
状态页面按需读取，不在每个普通请求前增加一次MFA查询。

统一网络门禁只对结构化 `403 MFA_REQUIRED` 提示验证，登录/刷新/验证接口自身不递归弹框。
同时发生的业务拒绝合并为一个验证框，旧账号/旧入口的迟到拒绝不能提示新账号；输入框和验证请求也保留会话边界。
已标为自动的后台请求不弹验证框；取消后同一会话三十秒内不再次自动弹框，员工仍可随时到个人页面主动验证。
成功后原请求返回 `MFA_RETRY_REQUIRED`，明确“核查原操作结果，再确认继续”，不会自动发送原来的读或写请求。
未来正常的后台读取仍可按现有调度重新读取；网络已连接不表示原写入失败。

access过期后，如果原业务请求已获401且refresh返回MFA拒绝，客户端核对会话后退出该登录，提示密码+OTP重新登录；
access仍有效时可直接验证当前会话。网络错误、限流或MFA服务暂不可用不应伪装成绑定成功。

已实现的是页面、令牌链路接入和仓库接口契约。实机TOTP时间同步、代理可信来源、独立网络、部署环境及管理员恢复流程仍须现场验收。
已有草稿仍受原服务器URL/账号命名空间保护；此功能没有实现跨域草稿迁移，也不保证断网设备上的已下载内容可远程收回。
