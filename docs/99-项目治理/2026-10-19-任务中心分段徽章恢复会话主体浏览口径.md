# 任务中心分段徽章恢复会话主体浏览口径

## 范围

任务中心/列表页的分类与子分类红黄徽章在超管会话下缺失（「销售任务中心『进行中』有一条但没有徽章」「人事任务卡红数没有了」）。根因与 v2.5.23 工作台徽章消失同源：[ADR-184](../99-决策记录-ADR/ADR-184-业务待办按真实操作资格与责任范围计算.md) 首版把**页面直连**的计数路径也包进了任务受众改写（`TaskAudiencePort.read` 用 `grantedPermsOf ∩ 会话权限` 重建主体、剥超管镜像），10-18 修订一只修了 `WorkbenchBadgeService` 聚合层，页面直连端点漏覆盖——同一入口在 hub 卡有数、进了页面没数。

本次修复（ADR-184 修订二）：分段徽章与聚合徽章同为展示层、同一口径。

| 受影响路径 | 修复 |
| --- | --- |
| 销售 `GET /sales/orders/progress/stage-counts` 的 `TASK_*` 桶 | `SalesOrderService.progressStageCounts` 内嵌 read → browsingRead |
| HR `GET /org/hr/tasks/summary` 的 `taskCounts`（工作台事务卡红数） | `HrTaskService.summary` 内嵌 read → browsingRead |
| 各单据列表 `GET /documents/status-counts` 的 `ACTIONABLE_*`/`RESPONSIBLE_*` 桶 | `DocumentStatusCountQueryService.counts` 内嵌 read → browsingRead |
| IQC 退回计数可办桶 | `ProcurementIqcRejectionService.counts` 内嵌 read → browsingRead |
| 运营工作台 `/warehouse/count`、`/warehouse/status-breakdown`、`/purchase/count`、`/subcontract/count` | 摘 `@BusinessTaskRead`（与同文件列表端点一致，仓库范围统一走浏览重载） |
| 委外领料 `/subcontract/draw-tasks/count`、短交 `/subcontract/short-deliveries/count` | 摘 `@BusinessTaskRead` |

行为矩阵不变：超管（目录镜像）恢复历史口径数字；仅查看账号分档计数仍恒 0（桶内动作资格按会话权限判定）；普通操作员数字不变。弹窗、行动通知、发卡池与命令层动作口径不动；`ReviewNoticeAudience` 通知受众（列表+计数同体）刻意保留剥镜像。

## 验证

`mvn -f server/pom.xml test -Dtest=FulfillmentWorkbenchTaskAudienceTest,BusinessTaskReadConfigurationTest,WorkbenchBadgeBrowsingAudienceTest,DocumentTaskAudienceCountTest,ProcurementIqcRejectionServiceContractTest,FulfillmentWorkbenchQueryServiceTest,WarehouseTaskEndpointScopeContractTest,HrTaskActionCountTest,SalesTaskAudienceCountTest,HrTaskServiceIdentityReviewTest,SubcontractDrawTaskAudienceTest,SubcontractShortDeliveryTaskAudienceTest` 全绿（59 例）。三个钉「计数端点挂任务改写」的断言改钉新口径。前端无改动（仍读同一批键，服务端恢复填数）。
