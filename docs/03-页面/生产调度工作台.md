## 2026-08-29 当前入口、V423 BOM 下线与执行质量边界

> 当前新建/分析入口是 `/production/material-analysis`，分析历史是 `/production/material-analyses`，生产计划历史是 `/production/plans`。生产核心迁移为 V409–V415、仓库拒收重交为 V418；V423/ADR-057 已下线货品「生产 BOM 策略」和计划级 BOM 例外放行，当前目录头以[迁移总索引](../数据迁移/README.md)为准。目标交互与岗位 SOP 以[生产物料分析页、节点任务与逐级计划](生产物料分析页.md)、[ADR-033](../99-决策记录-ADR/ADR-033-生产物料节点任务化与自底向上备料.md)、[ADR-054](../99-决策记录-ADR/ADR-054-生产报工质量放行与合格入库.md)和[ADR-057](../99-决策记录-ADR/ADR-057-下线生产BOM策略与计划级例外放行.md)为准。本节优先于下方历史调度链。

2026-08-29 起调度台只保留一个右下角悬浮主入口：未勾选时显示「新建物料分析」，勾选 N 行时显示「联合分析所选 N 项」，位置与采购任务工作台一致。原「物料分析」与「进入分析并生成计划」的并列入口目标页重合，已收敛；调度台入口只导航并带入 seed，真正持久化发生在物料页「联合分析所选产品」或「按最新库存刷新分析」，**任何进入动作都不代表已生成计划、采购单或委外单**。

待排区桌面表使用 `MasterDataTableView`：候选请求默认每页 100 行，表头复选框有空/全选/半选三态，行与表头都是真实多选；表格上方选择摘要显示「已选 N 项（最多 500 项，可跨页选择）」、48dp「清空已选」、本次数量与日期，真正进入分析的业务按钮只在右下悬浮。每行可调整「本次联合分析数量」，不得超过该行待排量，最终仍由服务端 preview 复核。「建议联合分析（本页 N 行）」只选当前页尚无活动分析的候选；已有活动 analysis 的产品只能单独继续，不能与新来源混选。关键词提示是「搜索订单号 / 客户 / 货品」，并支持交期起止、状态和排序筛选。

**响应式边界必须写准确**：当前调度台 compact 待排卡只渲染已请求的首批 100 行，没有「上一页/下一页」控件，因此不能宣称手机调度台已跨页选择。进入 `/production/material-analysis` 后的销售候选卡才具有每页 100、48dp「上一页/下一页」和跨页保留选择。两页都执行最多 500 来源的业务上限，但分页 UI 不是同一实现。

物料分析页保留完整 BOM 数据，但初始默认「只看缺料」，顶部可搜索产品/物料，并可切换「待确认路线」或「全部 BOM」。计数准确显示「筛选命中 X 条；保留上级后共 Y 条 / 全部 Z 条」，筛选命中时保留其祖先路径，不允许静默隐藏；当前视图内产品与分支默认展开，也可单独折叠。产品卡首次构建 60 项，通过「继续显示下一批（还有 N 个）」增量展示；BOM 首次构建筛选后前 30 个产品，通过「继续显示下一批产品（还有 N 个）」继续展示，不能一次铺满 500 个产品的深树。这一本轮现场易用性约定覆盖 ADR-033 旧文的「初始完整树全展开」展示默认，但不删除或丢失任何业务节点。卡片之间保留垂直间距，数量列在不同层级仍对齐。只有路线已确认且可执行的节点显示复选框；未确认、未保存、MAKE 下层未齐或只读节点直接显示 48dp「先确认路线/先保存路线/下层未齐/仅查看」。复选框只改变本地选中集，不隐式提交路线；路线必须用「采用采购/采用委外/采用自制」明确确认，选中后再用底部「提交采购需求（N）」「提交委外需求（N）」或「安排自制生产（N）」写入业务事实。BUY 和 SUBCONTRACT 节点可不受 BOM 深度限制直接选中，但仍必须满足当前路线、缺口、权限与版本门禁；超过 500 条的路线/下达动作由客户端使用最新版本与指纹安全分批并显示进度。联合排产、V192 默认车间和溯源边界见[生产计划单一键生成与全链路溯源设计](生产计划单一键生成与全链路溯源设计.md)。

Flutter 没有把“待分析/备料、可下达、生产中、已完成、历史待料”实现成一个五页签总表；员工从新建页勾选销售候选或录入合法手工来源，也可从独立历史页恢复原 analysis。生产进度页现已补 FQC/待点收/返工补产投影和 V415 补产物料待办，但这仍不能替代目标环境浏览器、岗位与实物验收。

页面目标合同如下：

- 完整 BOM 节点始终存在，初始「只看缺料」并可一键查看「全部 BOM」；当前视图的产品/分支默认展开，每个 `analysisItemId + path/nodeKey` 是独立节点任务；
- 缺料用红色 + 图标/文字 + 数量表达；`required=0` 只显示“本批无需补货”，不得显示“随上级件”；
- MAKE 和有供料 BOM 的 SUBCONTRACT 只按父件实际未覆盖短缺激活下一层，BUY 不激活后代；每个 MAKE 层只检查自己的直接子件，逐级自底向上，不把整棵树扁平为根计划领料；
- “可开工（分析参考）/可完工入库/预计可发货（参考）”分列；计划最大量只取可完工入库，兼容字段 `readyNowQty` 等于该量；
- `SHIP/REFERENCE` 不作硬门槛、不预留、不生成 DRAW；生产消耗包装必须配成 `FINISH`；
- BUY/委外是物料任务；MAKE 的直接下层实际齐套后才创建 `MAKE_COMPONENT`。当前候选以整节点 child ownership 停止父树后代激活；child 独立生成计划，合格点收入库后才提高父层齐套；只有 MAKE/root 可生成计划；
- 从当前节点进入既有计划向导填写数量、车间、负责人和日期；取消或生成后回到/留在分析任务流，显示真实计划状态，不直接 `approveNow`；
- 未排余量保留在原 analysis，待采购、委外或 MAKE 合格供给到位后继续分批安排，不创建新的 WAITING 正式计划。

必须区分两套页面：MAKE/root 点击计划动作后进入「填写生产计划单」向导，逐张补数量、车间、负责人和日期，最后在「确认提交 N 张生产计划单 · G 个车间组」中点「确认并提交审批」；它只提交 MAKE/root 独立计划草稿。AppBar「计划单预览」打开的则是只读「生产备料计划汇总单」，按自制/采购/委外分区核对，底部只有「打印 / 导出 PDF」，**不提交任何单据**。BUY 和 SUBCONTRACT 仍分别从 BOM 底部动作进入采购/委外申请链，不能把这三条链写成一个混合汇总提交。

两处纸面公司头当前都硬编码「中山市优腾电器有限公司」，多公司组织配置尚未接入。默认车间唯一来源是 V192 `production_goods_workshop_preferences`，仅在执行段正式确认或后续合法改派后学习；V253 是官网询盘迁移，当前 V419/381 也没有改变默认车间权威。

进度必须区分五种事实：采购/委外 IQC `PASS` 的合格可用库存与物料齐套、当前有效完工申报 `fqty`、FQC 待检/PASS/FAIL、FINISHED_IN 待点收、仓库实收 `iqty`。计划卡不得互相替代这些数量；FQC PASS 也不能计为已入库。正式计划物料状态只读取已确认 V1 计划包与实际 DRAW/issue；完成率只认 `iqty / 计划量`。部分 IQC PASS 会刷新分析库存，但在正式精确预留/领料形成前，计划仍保持「未锁定齐套」。

真实子计划入口显示「子计划 N 张（点开展示进度）」。展开行分别显示「已报工 X」「已入库 X / 排产 X」及物料齐套文案，并整行进入子计划；375px 窄屏用两行布局、行高至少 56dp，在 1.3 倍系统字体下仍可读、无溢出且可点击。

生产计划详情只承载已冻结的执行事实：执行分段、真实子计划、直接层正式需求、预留、DRAW/issue、报工、FQC 和 FINISHED_IN 点收。旧“物料需求只读估算（MRP）”“预排并保存草案”“补建正式计划包”不再作为新业务入口；分析来源计划的排产草案在物料分析生成事务中形成，批准入口应用该草案。`ZERO_MATERIAL / DIRECT_MAKE` 计划显示“无下层领料物料，可直接自制”，不得因物料表为空显示红色 BOM 异常，也不得生成空 DRAW。

V250 旧口径隔离链与 ADR-033/V409–V415/V418 当前工作树自动化都有局部证据；本轮空库已真实应用 381 个迁移到 V419，部分 IQC、拒收重交和到货幂等 PostgreSQL 聚焦 15/15。它仍不是公司数据克隆、目标库或完整真实岗位/实物 UAT，生产写链路继续 **NO-GO**。

## 2026-08-08 工作台目标设计（V234，历史参考）

> 本节保留 V234 的五视图目标设计，并不表示当前 Flutter 已实现该总工作台。若与上方目标冲突，以上方、[ADR-033](../99-决策记录-ADR/ADR-033-生产物料节点任务化与自底向上备料.md)和当前代码为准。完整树是逐路径节点任务视图，但不能自动递归创建正式计划；新正式计划只允许 READY。目标库和真实 UAT 未完成，生产写链路 **NO-GO**。

### 页面职责与一级动作

V234 曾提议将「物料分析」与「生成生产计划」放在同一动作区，该双入口设计已废止。当前只使用本文顶部定义的「新建物料分析/联合分析所选 N 项」单入口；生产计划、采购需求和委外需求均在分析结果内经显式选择与二次确认后提交。历史记录、刷新、筛选和列设置使用次要动作，不与主入口争抢视觉层级；移动端触控目标不小于 48dp。

### 待排需求列表

每行至少显示：需求号、来源单号/手工类型、产品、需求总量、已下达量、剩余量、**可立即生产量**、**预计可生产量**、齐套率、预计齐套日、最早短缺、交期风险、优先级、分析状态、数据更新时间和负责人。

“可立即生产量”只使用选定单目标仓的当前合格可用库存；“预计可生产量”可使用精确 peg 且日期可靠的采购、委外和 MAKE 未来供给。两列不得合并。其他仓只展示库存分布和调拨候选，不能跨仓相加成当前立即量。默认排序建议依次使用：已逾期/临期、可立即生产量大于零、优先级、需求日期；用户排序和筛选返回页面后保留。

列表由服务端分页和对象范围过滤，并覆盖销售来源、五类手工需求及系统 `MAKE_COMPONENT` 子需求。另有对象范围一致的“物料分析记录”分页视图，展示负责人、来源/需求编号、状态、齐套量、分析时间和最后更新时间；点击任一记录按 `analysisId` 恢复详情，不能让离页后的手工任务变成只有知道 UUID 才能找回的孤儿记录。50 行以上使用虚拟列表。恢复活动且可刷新的旧分析时，可用持久化完整来源自动重算一次库存/BOM 快照和分析版本；`VIEW`-only 记录不得写。任何自动刷新都不能提交路线、通知或计划生成。

### 物料分析页

点击后加载该计划前需求的全部组装层级。初始以「只看缺料」视图展示逐路径节点，保留命中节点的祖先上下文，并提供「待确认路线/全部 BOM」切换。页面顶部可按现场顺序展示只读摘要卡：

1. **自制 MAKE**；
2. **采购 BUY**；
3. **委外 SUBCONTRACT**；
4. 当前库存已覆盖；
5. 结构异常/待确认。

点击卡片只切换筛选，不改变路线或数量。表格每行显示层级缩进、BOM 路径、父件、组件、用量、本批激活需求、主档建议路线、人工确认路线、仓库库存、有效预留、冻结/安全库存、当前合格可用、未来供给、缺口、任务所有权、下游动作和更新时间。`required=0` 显示“本批无需补货”，但仍显示仓库现货。

缺料行使用深红背景/边线时还必须显示缺料图标、文字和数量，不能只靠颜色。重复物料可显示汇总数量，但展开后必须能查看每条 BOM 路径和 `analysis_item_id` 需求归属。

### 全树节点任务与自底向上备料

- 页面初始只显示缺料节点与必要祖先上下文，但必须显示 X/总数并可一键查看全部 BOM；每个 `analysis_item_id + path/node_key` 仍是独立节点任务，同货多路径不得压成一个任务或按货号开口供给去重。
- 目标仓合格自由库存可在仓货色维度共享分配，但分配结果、action allocation、委派和反向必须回到各自路径。
- 根产品激活直接组件；父件只按实际未覆盖短缺向下传播。BUY 截断后代；MAKE 激活下层；SUBCONTRACT 有我方供料 BOM 时激活供料后代，无 BOM 时不虚构需求。
- MAKE 节点下层实际齐套前不创建 child item。当前候选点击“安排生产”后幂等创建 `MAKE_COMPONENT`，以 child 存在性投影整节点 ownership，并让父树后代不再激活。目标合同要求未来若支持任意分批委派，须显式守住委派量和未委派余量；当前没有 `delegated_qty`，不得写成该能力已实现。
- child item 在同一工作台独立生成真正的子生产计划。最深层可齐套任务优先；子件合格入库后，父分析才增加当前可用量。
- 可从父节点定位 child item，也可从 child item 返回精确父路径；不得按 goodsId 猜父件。子需求的计划量、报工量和在途不能冒充父产品或销售完成量。
- ADR-028 的 full-tree orchestrator HTTP 写入口永久停用，新工作台不展示其入口；历史服务代码仅供兼容审计，不得借配置重新开放新写入。

### 路线确认与下游动作

主档来源只是建议；计划员只对本批已激活、未委派且仍有缺口的路径节点确认 BUY、SUBCONTRACT 或 MAKE。偏离建议时必须填写原因，服务端校验路径所有权、父路线、目标路线所需主数据和权限。分析输入变化后旧决定显示“已过期，需重新确认”。

「提交采购需求」「提交委外需求」和「安排自制生产」都不是发普通消息：

| 动作 | 首先落库 | 必须精确关联 |
|---|---|---|
| 提交采购需求 | BUY `preplan_supply_actions` | `PURCHASE_REQUEST` 真实采购申请行及原始节点分摊 |
| 提交委外需求 | SUBCONTRACT `preplan_supply_actions` | `SUBCONTRACT_APPLICATION` 真实委外申请行及逐路径分摊；供料后代另行备料 |
| 安排自制生产 | MAKE 计划前 action（当前复用 notify 的 MAKE 分支） | 下层实际齐套后创建 `PREPLAN_MAKE_TASK + MAKE_COMPONENT` 并投影整节点 child ownership；显式分批委派量未实现 |

按钮状态至少包括“未处理、生成中、已下达、履约中、已齐套、撤回中、已撤回、反向失败”。未生成真实下游且未被引用时可撤回；已有订单、委外发料、收货、正式计划或仓库发料后，必须显示对应反向入口和处理任务，不能直接删除或把通知标为已撤回。

### 共享物料调配

2026-08-14 起，分析详情节点详情区新增「调给其它产品」现货借用：把一条直接组件路径已分配的合格现货覆盖量调给同一分析内其它产品的同物料路径，服务端双趟精确投影（借出 −m / 借入 +m / 第三方不变、可生产量同步），逐笔留痕、双方行内可见、未下达前可撤销。入口、门槛与撤销规则以[生产物料分析页 §3.3](生产物料分析页.md)为准。

工作台允许多选需求查看共享短缺物料，并在自由库存范围内调整分析分配。分配面板必须同时展示总自由量、各需求建议量、人工分配量、交期和影响后的可立即生产量。

重排使用明确的上移/下移动作并在确认前预览影响；确认调用 `PUT /api/production/material-analyses/{id}/allocation-priorities`，提交全部有效需求的完整优先级排列、期望版本、指纹和幂等键。取消不写回。服务端以单一完整套料池重算并持久化快照，物料行缺口、通知数量、待排列表和销售进度不得各自按单行另算。

- 分析分配不写 `stock_reservations`；普通生成计划草稿时仍不生效，只有批准事务按目标仓原子创建物理预留时才生效；
- 分配总量不得超过未预留、未冻结并扣除安全库存后的自由量；
- 支持输入/步进器等非拖拽操作，拖拽只作大屏快捷方式；
- 已被 READY 计划预留的物料不能直接抢占。若账号有高风险改派权限，必须先进入原计划释放/反向向导，校验未发料/未开工并填写原因，再返回重新下达；
- 并发失败时点名物料、原可用量、当前可用量和受影响需求，由用户决定下一步，不自动循环重试。

### 分批生成草稿与批准生产计划

只有 MAKE child item 和根产品显示“安排生产”。先选择一个目标仓，再从当前节点进入既有计划向导逐行填写本次提交数量、车间、负责人和日期，默认值不得超过该行目标仓可完工量。BUY/委外节点没有生成计划动作。提交前摘要展示将创建的计划草稿、ACTIVE planning draft 和来源；用户明确确认后才写入，取消或成功后回到原分析任务流。

普通“生成生产计划”使用 `production_material_analysis:generate`：服务端校验 item 类型、委派所有权、分析版本、BOM 签名、单目标仓和数量后，只创建计划草稿、计划行、`ACTIVE production_planning_drafts` 和 `SUBMITTED production_material_analysis_plan_links`，同步 item 的 `submitted_qty`；不创建执行批次、物理预留、DRAW 或正式销售分摊。路线确认只在下达缺料任务时强制，已完整齐套的本批数量不因剩余缺口路线未确认而被阻断；只有正式物料路线连主档也无法解析时才 fail-closed。成功后留在当前分析页刷新计划号和状态，员工继续处理其他节点。分析头仍只使用 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`。

持 `production_plan:approve` 者随后批准时，服务端在一个事务按目标仓重新校验需求剩余、BOM/分析版本、路线、当前合格库存和职责分离，并原子批准计划、创建 READY 批次、完整套料预留、DRAW、销售分摊和审计/Outbox，将 plan link `SUBMITTED → APPROVED` 并同步 item 数量。任一行失败则整批失败，草稿/SUBMITTED link 保持可见且没有部分预留。持 generate + approve 权限者可显式选择 `approveNow`，生成和批准同事务；不得默认跳过确认。剩余数量继续留在待排需求；不创建 WAITING/AUTO_WAIT/DEFERRED 正式计划，也不把未来供给伪装为预留。

### 无 BOM、权限和异常

- 2026-08-29 起（ADR-057 / V423）不再有主档「生产 BOM 策略」与逐计划 BOM 例外放行：当前 MAKE 层没有直接 BOM 时按「直接自制」处理，剩余需求全额可安排且不生成物料需求、预留或空 DRAW；存在 BOM 时只以该层直接子件的生产硬门槛计算齐套，短缺 MAKE 子件再进入自己的下一层，逐级自底向上。`production_material_analysis:bom_override` 权限与「填写资料异常继续原因」对话框已删除；历史 `PLAN_BOM_OVERRIDE` 只读留证。
- 页面实际权限统一为 `production_material_analysis:view`、`production_material_analysis:manage`、`production_material_analysis:route`、`production_material_analysis:notify`、`production_material_analysis:generate`、`production_material_analysis:reallocate` 和 `production_plan:approve`，不得再使用设计期 `production_preplan:*` 名称或只复用宽泛 `production_plan:edit`。
- 列表、详情、批量动作、导出和深链统一执行对象范围；`view:all` 只放宽创建人范围。动作由服务端 `allowedActions` 最终决定。
- 分析加载失败显示错误卡和重试；部分节点失败不能把未知值当零。离线/超时显示数据是否陈旧，禁止继续下达。
- 深层结构用层级文本、路径和可展开详情表达，不依赖颜色或仅图标。键盘/读屏顺序与视觉顺序一致，错误聚焦到第一个问题字段。

### 历史 WAITING 视图

历史 V191–V195 `WAITING/AUTO_WAIT/DEFERRED` 计划单独进入“历史待料”页签，带“旧流程，只读兼容”标识。新工作台不允许对其执行共享调配、路线重选或新计划生成；完成/反向通过 feature flag 隔离的兼容入口处理，并记录调用量以便最终退役。

## 2026-08-02 历史调度链路（V191–V195，仅兼容）

> 本节只保留 2026-08-02 的历史兼容口径，旧目标库状态不得覆盖上方当前边界；若历史按钮、无 BOM 阻断或递归子计划描述与新入口冲突，以上方当前章节为准。该历史段中的计划详情 MRP、保存预排、补建计划包均已退役，只允许读取存量冻结结果和执行单据，不得重新暴露写入口。

调度工作台进入某张生产计划后，标准路径是：草稿物料评审→保存可恢复预排草案→审核原子下达→回查采购/委外/DRAW/真实子计划→在确认包上预览或打印生产执行工卡。审核前不得锁料或建正式下游单据。

物料评审的处置必须显示为 `READY`、`AUTO_WAIT`、`DEFERRED` 三态：整套齐料才是 `READY`；系统缺料为可自动齐套的 `AUTO_WAIT`；用户主动延期为禁止自动提升的 `DEFERRED`。审核后的 `DEFERRED` 只能通过 `release-defer` 单向人工放行并立即重做齐套，不能原地改写回延期。

车间必须是 `DEPT_PROD` 直属子部门，班组必须直属所选车间，负责人须为在职/试用且在所选组织路径内，开工日不得晚于完工日。V195 仅刷新 V194 新增业务表的未来写入审计覆盖，不补历史审计或业务数据；候选未完成目标库迁移及真实岗位 UAT，生产发布仍为 **NO-GO**。

MAKE 采用“直接层、逐级下钻”：父包只创建当前层自制缺口的子计划，禁止一次递归生成所有层。每张子计划可再次走同一评审与审核链。无 BOM 行可定位治理，但整方案不得保存或下达。

只读账号可查看已生成结果和工卡；编辑账号可预排、覆盖草案和补建尚不存在的正式计划包。系统不会对已有确认包执行“生成剩余”或原地重算，而是幂等回放原有结果。

## 一、页面职责

生产调度工作台承接计划需求池中已选择 `MAKE` 路线的销售缺口，负责排产与进度查看：

- “待排产”页按交期、紧急程度和 BOM 可用性展示可排销售需求；
- “生产进度”页展示父生产计划及其真实自制件子计划；
- 页面只负责导航、筛选和调度操作，不把展示状态当成库存、领料或完工事实；
- 计划详情、执行分段、领料、报工和入库仍由各自权威单据及服务端状态机决定。

## 二、必须区分的两个“子”概念

| 页面对象 | 数据来源 | 是否独立生产计划 | 点击结果 |
|---|---|---:|---|
| 自制件子计划 | `subplan_links` 指向子 `production_plans` | 是 | 打开子计划 `/production/plans/{childPlanId}` |
| 执行分段 | `production_execution_segments` | 否，是父计划明细的执行从属 | 在父计划详情打开执行分段详情 |

页面文案可以使用“子计划”帮助现场理解，但代码、接口、审计和文档必须保持以上语义，不能把执行分段误写为独立生产计划。

## 三、生产进度卡交互

一个父计划卡包含两个互不冲突的点击区：

1. 点击父计划表头，打开该父计划详情；
2. 点击“子计划 N 张”，只展开或收起子计划进度；
3. 展开后点击具体子计划行，打开该子计划详情；
4. 子计划可以继续展示自己的下级计划，形成逐层下钻；
5. 空计划 ID、自引用 ID 或路由异常必须显示明确错误，不允许静默无响应。

父计划表头与展开控件使用分离的 `InkWell`，避免点击子计划区域时误跳父计划。计划卡的置顶、重要标记菜单也保持独立点击语义。

子计划整行触控高度至少 56dp。宽屏可把计划身份、数量、状态放在同一行；375px 等窄屏必须改为两行：第一行显示进度环、单号/车间、状态和进入箭头，第二行使用可换行的「已报工 / 已入库 / 排产 / 物料齐套」信息。关键数量与齐套文字不小于 14px，并须在系统字体放大 1.3 倍时无溢出、仍可整行点击，不能靠 9–12px 小字把信息硬塞进一行。

## 四、权限、状态与异常

- 生产计划查看权限只决定能否进入计划详情；跳转本身不能绕过路由和服务端对象范围校验。
- 编辑、派工、报工等动作继续按各自权限点和服务端状态校验显示，不因能查看子计划而自动获得写权限。
- 车间、班组、负责人和日期必须由服务端再次校验组织层级与有效人员范围；前端联动筛选不是安全边界。
- 子计划列表加载失败时显示错误卡和“重试”，不影响父计划详情和 MRP 物料需求的独立展示。
- 没有子计划时不渲染空卡；红冲、草稿、进行中、已完成分别显示真实状态。
- 列表刷新后必须重新读取服务端数据，不能长期复用旧的展开内容作为业务事实。
