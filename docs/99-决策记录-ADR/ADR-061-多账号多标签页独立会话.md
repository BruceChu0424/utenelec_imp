# ADR-061：多账号多标签页独立会话（Web sessionStorage）

> 日期：2026-09-02 · 状态：**已接受（前端源码与测试已验证；后端零改动）**
> 前置：[ADR-014](ADR-014-会话超时与token刷新机制修复.md)（会话超时与 token 刷新）·
> 本 ADR 取代 ADR-014 §6 中「同源所有标签页共享单一会话记录并互相收敛」的设计；ADR-014 的
> CAS/latest-intent/撤销队列/精确拒绝等语义继续有效。

## 1. 背景

真实使用场景：同一台电脑、同一浏览器打开多个标签页，分别登录不同账号（对应不同公司的 ERP
数据入口）。旧设计下：

- 员工令牌记录 `auth.token_record.v1` 经 `flutter_secure_storage` 落在 Web 的 localStorage——
  同源所有标签页共享同一份；
- `AuthTokenChangeBus`（BroadcastChannel）主动通知其他标签页「权威记录已变」，
  `SessionNotifier._reconcileExternalTokenChange` 收到后重读共享记录并重建会话。

结果是后登录的账号顶掉所有先打开的标签页——全部页面都变成最后登录的账号。后端复核结论：
**服务端自始支持并发独立会话**（每次登录签发独立 `refresh_tokens` 行与新 `session_id`，登录
不踢旧会话，logout 只撤销单个 session；改密/撤权等安全事件才全量撤销该用户），问题纯在
前端存储与跨标签页协调设计。

## 2. 决策

1. **会话状态按标签页隔离**：员工令牌记录、模拟身份键（`auth.impersonation_*`）、登出栅栏
   （`auth.logout_fail_closed.v1`）迁移到「标签页级存储」——Web 用 `sessionStorage`（同源各
   标签页互不可见、随标签页关闭销毁）；原生平台没有标签页概念，回退为原有 `flutter_secure_storage`
   进程级共享，行为与改造前完全一致。
2. **删除跨标签页会话收敛**：移除 `AuthTokenChangeBus`/`AuthTokenChangeNotice` 与
   `_reconcileExternalTokenChange`。Web Locks/lease 保留，但只作互斥量（串行化本标签页的
   登录/登出/刷新提交），不再承担会话协调。
3. **保持共享的键**（设备级便利/安全设施，不随标签页隔离）：登录账号历史
   `auth.login_account(s)`、refresh 撤销队列 `auth.pending_refresh_revocations.v1`（登出后关
   标签页仍可由其他标签页/下次启动补撤销）、设备审计键、访客令牌。
4. **一次性收编迁移**：旧共享记录首次被某个标签页读到时，在专用锁内迁入该标签页独立存储并
   立刻删除共享副本；后续新开的标签页不再继承旧会话，必须各自显式登录。

## 3. 用户可见的行为变化

- 同一浏览器可同时开多个标签页登录**不同账号**，互不顶替、互不影响（本 ADR 的目标）。
- 新开标签页不再自动带入已有会话，需在该标签页显式登录。
- 关闭标签页 = 该标签页会话终结：客户端凭据随 sessionStorage 销毁；服务端 refresh token 遵循
  原 7 天 TTL，共享撤销队列仍尽力补撤销。
- 关闭整个浏览器后重新打开需重新登录（旧行为：localStorage 中的 refresh token 可跨浏览器
  重启恢复）。这是安全收益：凭据不再长期驻留磁盘。
- 空闲超时按标签页独立计时、独立登出：每个标签页只按自己的操作续期，超时只登出自己。
- 同一账号被管理员改密/撤权时，服务端全量撤销该账号 refresh——该账号的所有标签页都会回到
  登录页，这是安全语义，不受本 ADR 影响。

## 4. 实现要点

- `lib/core/security/tab_scoped_store{,_stub,_web}.dart`：`TabScopedStore` 接口 + 条件导出
  （沿用 `auth_refresh_lock.dart` 的 `if (dart.library.html)` 模式）。Web 实现为 sessionStorage；
  原生 `SecureStorageTabScopedStore` 适配原安全存储。
- `SecureStorage` 新增可选 `sessionScope` 注入（测试用内存实现模拟不同标签页）；员工记录与
  模拟身份的全部读写改走 `_sessionScope`；`_forceDeleteAllStaffTokenKeys` 同时清标签页记录与
  共享存储中的历史令牌键。
- 收编 `_adoptLegacySharedTokenRecord`：专用锁 `staff-token-record-adopt.v1` 内 double-check
  （scoped 有→用 scoped；否则读 legacy→写 scoped→best-effort 删 legacy），每实例只尝试一次。
  锁与记录锁 `staff-token-record.v2` 分离，避免嵌套死锁；全程保持「record→adopt」单向顺序。
- `authLogoutFenceProvider`：Web 返回 `TabScopedAuthLogoutFence`（栅栏只封闭本标签页——
  A 标签页登出失败不再把 B 标签页另一账号挡在自动恢复之外）；原生仍为 SharedPreferences 版。
- `AuthInterceptor` 会话边界文案从「账号已在其他窗口切换」改为「登录状态已切换」；
  `409 SESSION_CHANGED/SESSION_STATE_UNAVAILABLE` 语义不变，只在同标签页内触发。
- 后端零改动，无数据库迁移。

## 5. 安全权衡

- sessionStorage 与 localStorage 同为同源明文键值存储（均可被 XSS 读取），敏感度不变；改进在
  凭据生命周期——随标签页销毁，不再跨浏览器重启驻留磁盘。
- 浏览器「复制标签页」或页面内 `target=_blank`/`window.open` 会复制 sessionStorage 副本：两
  副本若先后用同一 refresh token 刷新，后到者触发服务端既有的**重用检测**，该账号全部会话被
  撤销并要求重新登录。安全性保持 fail-closed，仅影响该账号体验；多账号并行场景不涉及。
- 撤销队列仍共享且持久，「先入队、再删本地唯一 refresh 副本」的登出交付语义不变。
- 升级瞬间若有旧代码标签页仍在写共享记录，之后新开的标签页可能重复收编同一有效会话；该记录
  属于同一浏览器同一用户，且服务端刷新轮换/重用检测会使旧副本失效，无跨主体泄露。
- 共享存储中可能残留一个永不读取的旧 logout fence 布尔值（Web 不再读它），无害。

## 6. 测试

- 新增 `test/secure_storage_tab_scope_test.dart`：记录按 scope 隔离、后登录不顶替先登录、
  登出只 tombstone 本标签页、旧共享记录一次性收编并删除共享副本、scoped 记录优先于 stale
  副本、模拟身份键隔离、撤销队列/记住账号保持跨标签页共享、标签页栅栏激活/清除/异常值
  fail-closed。
- 重写 `test/session_mutation_race_test.dart` 的「外部登出/登录」用例为新语义：另一标签页
  （独立记录）登出再登录另一账号，本标签页会话与身份原样保持。
- 删除 `test/secure_storage_token_coordination_test.dart` 中已失效的「跨实例记录通知」用例，
  保留同标签页内 CAS/latest-intent 竞态用例。
- 全量 `flutter test`：除 5 个与本次无关的预存失败（已在干净 HEAD 复现）外全绿。

## 7. 不做 / 后续

- 不做「新标签页继承最近会话」或「标签页间会话切换」——与本决策目标相反。
- 会话列表、远程登出、异地登录告警仍按 安全策略 §3.5 保持未实施。
- 桌面端多进程多开沿用进程级共享（与现状一致），如需隔离另立决策。
- ADR-014 原文保留不改，其 §6 的跨标签页协调描述以本 ADR 为准。
