# 232 · V675 货品基本单位「已被数量引用则不能改」改为改单位时按需检查(ADR-106)

- 迁移：`V675__goods_quantity_unit_in_use_on_demand.sql`
- 类型：前向。删除 104 个语句级触发器、一个置位函数和 `goods.quantity_unit_locked` 列；新增 `fn_goods_quantity_unit_in_use`，替换 `fn_guard_goods_quantity_unit` 与其触发器。不改任何数量、换算率或来源关系。
- 前身：[114 · V498 货品数量单位生命周期守卫](114-V498货品数量单位生命周期守卫.md)。
- 决策：[ADR-106](../99-决策记录-ADR/ADR-106-热表触发器按相关列起跳与索引卫生.md) §2.3。

## 为什么要有它

V498 在 52 张数量来源表上各挂 INSERT / UPDATE 两个语句级触发器，每条写入语句都带过渡表跑一段动态 SQL，只为把
`goods.quantity_unit_locked` 置成 TRUE；UPDATE 版本受过渡表限制不能加列过滤，预留、余额、分析物料的每次数量更新都要白跑。
这个标志只在「改货品基本单位」这种罕见操作上才用得到。

## 改了什么

| 对象 | 变化 |
| --- | --- |
| `trg_lock_goods_quantity_unit_insert/_update`(52 张表各两个) | 删除 |
| `fn_lock_goods_quantity_unit_from_references()` | 删除 |
| `goods.quantity_unit_locked` | 删除 |
| `fn_goods_quantity_unit_in_use(uuid)` | 新增：按 `fn_goods_quantity_reference_sources()` 清单拼一条 UNION ALL 的 EXISTS，命中即止。清单仍是唯一事实源 |
| `fn_guard_goods_quantity_unit()` | 替换：单位真的变化时，先对本货品行 `FOR UPDATE` 等在途引用事务结束，再用新快照判定是否已被引用；已引用按 V498 同一文案拒绝(含「历史基本单位尚未核对」) |
| `trg_goods_quantity_unit_immutable` | 重建：`BEFORE UPDATE ... WHEN (单位 UUID 变化，或原单位为空时旧库单位编号变化)` |

## 应用侧(同批)

- `Goods` 实体删掉 `quantityUnitLocked`；`GoodsRepository.quantityUnitInUse` 调同一个数据库函数；`GoodsService` 编辑时现查一次，
  拦截(`GoodsQuantityUnitPolicy`)、是否写单位、详情回显共用；详情/状态变更各查一次。`GoodsDetail.quantityUnitLocked` 接口字段不变。
- `GoodsQuantityBasisLocks.lockUnused` 改名 `lockForQuantityUse`：对全部相关货品行取 `FOR KEY SHARE`(与外键检查同级，同货品并发写入互不排队；与改单位守卫的 `FOR UPDATE` 互斥)。

## 兼容与影响

- 「已被数量引用的货品不能改单位」正反用例全部保持(52 张来源全部列、BOM 两端、历史空单位、回滚不留痕迹、两个方向的真实锁等待)。
- 口径变化(推翻 V498「用过即终身锁定」，待业务确认)：「是否已使用」只看此刻还在的数量行。引用被硬删除(删掉的草稿明细、清空业务数据)、或草稿明细改指别的货品之后，原货品若已没有任何数量行就不再算已使用，可以改单位；软删、取消、红冲的历史行仍算使用，组装清单是主档仍锁定。
- 并发前提：60 个来源货品列都有指向货品的不可延迟外键，「变成引用」必经外键检查(对货品行取 `FOR KEY SHARE`)；唯一带行条件的来源 `legacy_measurement_profile_snapshots` 自 V442 起只追加，已有行不能被 UPDATE 成已使用。`SchemaIndexHygieneContractTest` 钉住这两条。
- 删除旧触发器按「挂的是置位函数」逐个删(只删父表上的，分区克隆随父表删)，不按来源清单拼名字；并行迁移重建过某张来源表时也不会因触发器不在而失败，漏删会让随后的 `DROP FUNCTION` 失败。
- 未使用货品改单位要查遍全部来源，V676 给 31 个缺领头索引的来源货品列补齐完整索引(契约要求等值探针用得上：不带条件、或只带「该列 IS NOT NULL」)。
- 前提是读已提交隔离级别(平台默认)。
