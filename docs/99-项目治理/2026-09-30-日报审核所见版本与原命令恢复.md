# 日报审核所见版本与原命令恢复

本记录承接 R1.01 和《2026-09-30-审核与批出库所见版本缺口复核》。范围为生产日报详情的审核命令与恢复，保留正常报工数量、耗料、去向、审核池权限及反向业务合同。普通批出库所见版本、最低客户端版本、附件和扩展列的总版本不属于本包。

当前状态：最终候选迁移号为 V768，隔离后端 69 项与前端 90 项组合通过，13 文件分析及 2 场景截图通过。包已具备整合条件；根完整目录的迁移/reset 接线与整合验证另行承接。尚未部署，不能据此宣称公司环境已启用 V2。

## 协议与事务

- `DailyReportApproveRequest` 新增可空 `commandVersion`、`expectedVersion`。两者都缺失或 V1 加空版本继续使用原 V1；V2 必须明确为 2 且所见版本非负。V2 缺版本不回退到 V1。
- 详情返回 `approvalCommandVersion=2` 表示该后端具备审核 V2 合同。前端另外核实原 JSON 中存在整数 `rowVersion >= 0`，旧模型的默认 0 不代表真实所见版本。未知协议和 V2 缺版本只允许重新读取。
- V1 指纹算法和历史命令完全保留。V2 指纹绑定协议标签、日报 ID、所见版本；相同 actor/key 换版本不能重放。成功回执在读取当前版本和状态前查找，因此本命令成功后版本前进或日报已红冲仍能返回原命令事实。
- 新 V2 按既有 actor/key 顾问锁、期间锁、业务关系锁、日报行锁顺序执行；锁后 refresh、权限和状态核对、CAS 通过后才记录命令并执行实际耗料/直送/到货任务。没有改业务数量合同。
- 回执携带日报 ID、原 key、真实协议、真实 reviewedVersion 和 replay 标记。历史 NULL 保持 NULL，绝不伪造版本 0。V2 遇到旧 V1 回执返回明确兼容错误，由查询接口展示旧版来源。
- 新 `GET /api/production/daily-reports/{id}/approval-receipt` 仍要求当前 view 权限和当前对象可读，只查当前 actor 的 key。`CONFIRMED` 才代表存在原命令；`PENDING` 表示同 actor/key 顾问锁占用；`UNCONFIRMED` 表示暂未找到，不能证明旧请求永远不会提交。
- 审计动作 `view_production_daily_report_approval_receipt` 登记到 `AuditEventInterpreter`；新增错误码 `DAILY_REPORT_REVIEW_VERSION_CONFLICT`、`DAILY_REPORT_LEGACY_APPROVAL_RECEIPT`。

## 前端确认与恢复

打开确认框前，从同一份详情冻结单据、所见版本、去向文案和 key。确认期间返回刷新信号即使更新详情，也不能替换这份提交。新版请求使用冻结 V2 版本，旧版请求保持空版本兼容，并在确认中说明限制。

本包复用既有 `FormDraftStorage` 的原子 CAS，使用日报专属、服务器/身份隔离的命名空间；没有修改通用草稿协议或 FQC。

1. `PREPARED` 完整落盘后才允许领取。
2. 每个发送者 CAS 领取为 `DISPATCHED` 并更新 attemptId，再调用网络；保存失败明确显示本次未发送。
3. 若同一页面确认从未调用网络，且 owner 未变，只能按自己的 CAS 值撤销 PREPARED 或刚领取记录。另一页面已领取时旧页面不能删除它。
4. 缺少 phase 的旧记录一律视为已发送未知，不能猜测成尚未发送。恢复 V1 未知只能查询；不能拿当前 GET 补历史版本、生成新键或再发送 V1。
5. V2 未知在用户明确选择按原内容重试时仍使用原 key、原版本；后续 400/422/500 不自动抹去此前未知结果。明确 V2 CAS 冲突由服务端同 key 串行及版本单调性保证原命令不能再成功。
6. 完整可核对回执先于本机清理/刷新/导航标记为已确认。本机收尾失败只开放清理，不把业务改回失败或再发写。旧版 2xx 却仍是 DRAFT 且无完整回执不能当成功。
7. 当前 GET 已审核或已红冲不代表本机原命令得到确认；页面保留原记录、核对入口，不报成功、不自动退出。未知记录期间审核/编辑/删除/红冲均不开放，读取与离开仍可用。
8. 账号、服务器、单据身份及当前路由均校验；身份/服务器改变时同时递增页面 generation，A→B→A 也不能复活旧响应。晚响应不能向新身份/新页面报成功或弹出新页面。真实路由 factory 以日报 ID 和来源构造 Key；确认 busy 在同 owner 的 finally 清理。

每张日报每个 owner 只保存一个当前待核对命令，不保存无限增长的本机成功历史。完成后的长期证据是服务器 append-only command ledger。
