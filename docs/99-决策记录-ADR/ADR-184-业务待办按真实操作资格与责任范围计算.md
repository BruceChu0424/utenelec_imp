# ADR-184：业务待办按真实操作资格与责任范围计算

- 状态：已接受，源码与本地验证；部署和真实账号验收单独记录。2026-10-18 修订：徽章展示层划出任务口径，按会话主体浏览口径读取（见文末修订记录）。
- 日期：2026-10-17
- 补充：ADR-181、ADR-063、ADR-108、ADR-149。

## 决策

工作台待办、模块和页面红黄徽章、系统行动通知共同使用真实授出的动作权限、当前单据责任范围和当前业务状态。只有查看权限不能产生运营任务；已授权的跨部门办理人可以正常收到任务，不增加部门硬门槛。

超管固有全目录权限继续用于主动管理。业务任务使用 `PermissionResolver.grantedPermsOf`，不因超管身份自动订阅所有业务工作。服务器健康和升级等平台职责沿用其独立权限规则。

## 实现边界

- `TaskAudiencePort.read` 在一次受控读取内选取真实授予与当前会话权限的交集，保留用户、员工、登录会话、模拟身份和 MFA 元数据，去掉超管目录扩张。嵌套读取复用一次快照，异常时恢复原安全上下文；普通单据浏览与命令不使用该上下文。
- `BusinessTaskRead` 在方法权限检查之前执行。徽章汇总对全部业务来源共用一次任务快照，再按入口和模块求和；平台来源显式登记。
- 归属任务复用原单据策略。改单、转单等可写任务使用本人和正式交接责任，手工只读数据范围不产生写任务；领料等明确的池化操作保留其既有“动作权加可见对象”规则。公共申请、财审和品质池继续使用其合法操作池。
- 仓库任务使用 `fn_user_warehouse_access(user, true)`，仅去掉隐式超管主管范围。指定主管、登记仓管、未分仓任务和无人负责仓的既有兜底保留。一参函数继续服务普通管理浏览，任务与浏览使用不同缓存键。
- 普通列表分布保持可浏览。红黄数读取服务端 `TASK_*`、`ACTIONABLE_*`、`RESPONSIBLE_*` 或已登记任务事实，缺字段按零处理，不回退成浏览总数。只读恢复和失去编辑权的本地填写快照可恢复，但不计红。
- 行动通知在发布时绑定真实业务对象；读取时在分页之前统一复核权限、责任和状态，列表、未读、到达流、弹窗、详情采用同一判据。普通行动目录不自动增加弹窗或认领。合法知会、办理结果与已办结历史继续保留。

## 模块核查范围

| 模块 | 任务资格与范围 |
| --- | --- |
| 采购、委外 | 下单、驳回修订、短交判定分别计算；订单修订和判定使用可写归属；缺 BOM 等既有状态判据保留 |
| 委外领料 | 真实领料动作、原订货单可见范围、实际可领量；不使用超管自动全见 |
| 销售、报价 | 退回修订、客户确认、转单、可发货分别授权；可发货复用现存实物预留与财务确认规则 |
| 财务、报销 | 批准、驳回、付款、核价、总账确认分别判断，保留制审和制付分离 |
| IQC 退回及贷项 | 登记退回、确认贷项、零额结案按案件阶段和精确动作分桶 |
| 生产、车间 | 计划可写责任与车间实际指派；开工、报工等不同操作分别决定对应桶 |
| 仓库、内料仓 | 实物仓责任及收发料、入库、退回、盘点的具体动作；只读查看不计任务 |
| 人事 | 转正、发布庆典、证件核对分别授权；认领、接管按钮与办理权限一致，本人释放保留 |
| 研发 | 手工完成与合法 BOM 维护两条办理路径；按任务类别、有效货品及 assignee 收敛 |
| 访客、资料变更、盘点 | 主办人或合法审批池、当前状态、对应确认或审核权限 |
| 本地和服务端草稿 | 真实创建或编辑资格及可写责任；只读恢复记录不冒红 |

## 验证要求

覆盖纯查看、单个动作、缺必要读取、跨部门同权限、超管仅目录权限、超管真实业务授权、本人、正式交接、手工只读范围、他人责任、撤权、源状态变化和缺字段清零。明确覆盖仅短交判定的有效 PostgreSQL 查询、仓库任务与浏览缓存隔离、旧会话迟到响应、只读草稿及页内二次冒红。

后端单元、真实 PostgreSQL 和 HTTP、Flutter 交互及静态检查分别记录。证据见对应[治理记录](../99-项目治理/2026-10-17-业务待办真实授权与责任范围修复.md)。界面检查和修改默认使用 `frontend-design`，复用 Uten 组件与主题，不改变业务数量和来源链路。

## 修订记录

### 2026-10-18：徽章展示层恢复会话主体浏览口径

- 现象：v2.5.23 上工作台各模块卡的红黄徽章整体消失。根因是本 ADR 把徽章聚合也包进 `TaskAudiencePort.read`（真实授出权限、去掉超管目录镜像），仅持目录镜像的超管与仅查看账号在 `GET /workbench/badges` 里入口缺席或数字恒 0，前端 `count<=0` 不渲染。个人弹窗开关（ADR-172）与徽章链路无关，保持不动。
- 修订：徽章是纯展示层，跟随用户能看到的范围。`WorkbenchBadgeService` 改用 `TaskAudiencePort.browsingRead` 聚合——会话主体原样读取（超管镜像生效），期间 `@BusinessTaskRead` 与服务内嵌的任务改写直通，仓库范围走浏览重载（`fn_user_warehouse_access(user, false)`，隐式超管主管范围恢复）。`WorkbenchBadgeSources` 的 `businessTask` 标志与 `platform()` 工厂随之删除。
- 不变：任务中心页面、弹窗、行动通知与发卡池仍按真实授出的动作权限与责任范围计算；仅查看权限账号的分档计数仍恒 0（准则 14 §四之二）；「只有查看权限不能产生运营任务」继续约束动作层。
- 验证：`WorkbenchBadgeBrowsingAudienceTest`（仅目录镜像、无真实授权的超管必须拿到入口与数字）、`BusinessTaskReadConfigurationTest.badgeBrowsingReadEvaluatesMethodSecurityAgainstTheSessionPrincipal`。
