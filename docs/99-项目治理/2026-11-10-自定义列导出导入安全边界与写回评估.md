# 自定义列导出、导入的安全边界与写回评估

本轮代码候选为 `c2271eb887566e347eab02bf2ccb035b043ce25e`、`7d6ef2caa641cf3387d95bf8e1a57be1dc36c06d`、`e49ce2bc930cd2eb36629d87320049796bec9332`，随后 `63ab1a38a`、`c56f8921f` 保守收紧旧预览恢复，基线为退货分类修复后的 `8645dbc14`。本轮实现安全防丢和防误写；完整自定义值写回仍是评估，没有自动创建列、扩大导入写入边界或开放新导入入口。

## 当前结论

不能把用户增加的列一律静默忽略，也不能看见 Excel 的“价格”“名称”就写入同名系统字段。修复前，公共 XLSX 只落盘显示表头和值，HTTP 投影里的 `platform:<列UUID>`、scope 没有进入文件。货品导入只按固定别名映射：未知列被跳过，除客户品名特例外的重复别名取第一列。自定义列与系统列同名时，重排顺序可能把自定义值当成真实业务字段；仅导出一个叫“价格”的自定义列时，重复检查也无法识别。

本轮采取以下明确行为：

- 已识别的同义或重复表头拒绝，提示具体列，不按位置选第一列。“客户货品名称”和“客户品名”仍各自是合法别名，同时出现则拒绝，没有可合并语义。
- 未知或自定义列有实际内容时，进入原检测问题列表或原校验错误，阻止写入；需要删除该列或使用明确支持的映射后重新检测。空表头下有值也检查，只有样式的空尾列及未知列全部为空时不会被误当作数据。公式缓存为空仍不是空单元格。
- 已知系统只读列保持非写入语义，例如货品库存/折扣、BOM真实使用数量和学习来源；实际设计数量仍取自己的字段。货品/BOM原有“不执行 Excel 公式”守卫保留，成本表原有只读取公式缓存、保留公式证据、逐行明确采用/跳过的流程保留。
- 新 XLSX 在最终投影含平台列时写入 Excel 自定义属性 `UTEN_PLATFORM_COLUMN_SCHEMA`。version 1 保存 scope、去重 `columnSets`（index、显示label、列UUID）和各 sheet 的 name/headerRow/columnSet 引用。相同投影的续表不重复保存列定义，预算为256Ki字符。正常文件、选中输出、续表及密码保护沿同一公共 writer。
- 当前导入识别到该属性就明确拒绝自定义列写回，要求重新导出仅含系统列的文件，不把平台列的显示名猜成系统字段。标记缺损、过大、未知版本或引用无效也拒绝，错误只给固定原因，不回显原JSON或单元格值。标记只是来源提示，不能赋予导入权限。

这没有把旧文件变成可信文件。旧的无标记文件、复制粘贴到新文件或手工删除标记的文件，只剩显示名称；单列自定义“价格”与真实价格列无法可靠区分。当前重复与未知列守卫只能识别有证据的冲突，不能声称已解决所有无标记冒名。需要保留明确预览并核对来源，完整回环应采用下面的稳定身份合同。

## 已有平台列的可写合同

| 种类或scope | 当前 owning 合同 | 完整导入时应怎样处理 |
|---|---|---|
| `TEXT` | `PlatformColumnService.prepareFields` 按列UUID、模块、记录权限与版本写入，文本最多2000字符 | 只映射到已存在且当前可写的同scope列；明确补齐、覆盖和清空的区别 |
| `NUMBER` | `ExtraColumnCalculator.decimal` + `FinancialExactAmount.book`，十进制原文、无损范围校验；不经double | 使用同一入口和精度规则，不另设数量/金额平均值或Excel显示精度；当前规则是绝对值小于10^40、有效小数最多30位，不误套所有业务列的4位数量规则 |
| `CALCULATED` | 数值由服务端定义的公式生成，不能提交非空输入值覆盖 | 预览列为系统计算、不能回写；Excel公式不作为可执行业务公式 |
| `RELATED` | 个人只读关联显示，依赖目标资料查看权限，不能写入业务记录 | 显式标注关联只读；修改显示值不改变真实关系UUID |
| `master_*` | `MasterPlatformColumnAdapter` 同时要求模块view/edit，排除模拟身份；逐记录锁定并复用owner、writable、系统锁定及价格权限 | 导入权限本身不能代替主档扩展字段编辑权；新建后只能使用实际生成的记录UUID |
| 已注册单据/明细scope | `DocumentPlatformColumnAdapter` 复用单据功能权限、真实父单据、生命周期与锁 | 只有允许的草稿/合法编辑状态可写；与原单据保存同事务，不另绕审核或来源限制 |
| `view_*`、个人展示、历史只读 | `DisplayPlatformColumnAdapter` 不支持实体值保存；`ReadOnlyPlatformColumnAdapter` 禁止业务字段写入 | 可导出显示结果，不能当作业务字段导入或自动生成可写列 |

定义UUID、scope、owner与依赖由 `PlatformColumnService.loadDefinitions` 验证；价格敏感性沿依赖传播。删除或跨scope定义、个人关联权限、对象可写性、`expectedVersion` 和掩码不能用列名或文件里的声明绕过。每次写最多32列等原边界保留。

还要注意：`PlatformColumnService.write` 接受的是整组 `cells`，不是“仅修改本次出现的几个字段”。完整导入若直接把所见列传进去，会遗漏已有未导出列，甚至触发删除敏感字段的拒绝。必须在原记录锁内读取完整旧组，合并明确选中的变更，保留未导入、隐藏、掩码及无权修改的字段，并校验旧版本。

## 完整写回的建议实施范围

第一步扩充可回环文件合同：除列UUID/scope之外，绑定真实记录UUID、字段版本与来源版本；保留表头改名、重排、续表和用户选择范围。文件标记仍不能替代服务端权限。旧无标记文件只能通过明确映射和差异预览接入，不按模糊名称自动猜测，也不自动创建同名平台列。

第二步在现有检测页表达逐列决定：可写列显示目标定义和类型；只读/计算/关联列显示不会回写；未知、重名、跨scope、已删除列必须先解决或明确跳过。逐行继续显示原值、新值与补齐/替换决定，空白不自动清空旧值。只把用户明确选择且有权写的差异送入被冻结的提交意图。

第三步由 owning 导入服务在同一事务中保存系统字段和扩展字段，复用平台列的定义、权限、精度、CAS、历史与审计；新建使用真实结果UUID，更新合并完整旧字段组。写入失败整笔回滚，未知提交保留原请求，不按新的映射或版本重发。主档、单据草稿和只读报告按各自能力迁移，不把一套写入口强塞给全部scope。

这属于中等到较高复杂度：难点主要在稳定身份和版本、部分列保全、原子写入、历史/敏感字段及旧文件歧义，不在Excel解析本身。建议先实现货品 `TEXT/NUMBER`，验证改名重排、缺列、超精度、并发、无权限、取消/未知提交和新建/修改模式；再按同一合同迁移其他已有导入业务。
