# 订货单公共表头规范

> 适用页面：销售订货单、采购订货单、委外订货单的新建/编辑页；
> 最后核对：2026-09-05(明细区表头体系与货品资料统一为共用组件 UtenTableColumnKit：表头设置
> 改按钮处锚定浮层勾选列表、表头纵向拖出隐藏改 root Overlay 跟手浮层(过阈值变红底红×)、
> 表头长按拎起横拖直接排序(与弹窗排序同一状态)；编辑模式操作条撤下「全选/复制选中/批量删除/
> 粘贴」常驻按钮——全选走表头复选框、复制/粘贴/删除走行级右键/长按菜单；此前 2026-09-04
> 口径：销售订货单价权威、可编辑折扣与明细表头设置、实际重量列下线、单位紧跟数量、必填列
> 锁定不可隐藏、折扣列 ⓘ 说明)。

## 一、适用边界

| 单据 | 结账/结算方式显示 | 必填 | 2026-09-03 起的位置 |
|---|---|---|---|
| 销售订货单 | 结账方式 | 是 | 单头（不变） |
| 采购订货单 | 结账方式 | 是（行级） | **明细行**（与供应商同格） |
| 委外订货单 | 结算方式 | 是（行级） | **明细行**（与委外商同格） |

采购/委外订货单的商业字段（结账/结算方式、币种、汇率、税率）自 2026-09-03 起全部
**下移明细行**（ADR-068）：单头不再展示；多选行可「统一设置条款」一次写全套；
保存按「供应商+条款组合」自动拆单，每组条款归集到该张单头（下游收货/退货/应付
仍读单头快照，完全兼容）。销售订货单维持单头口径，本规范的必填交互仍适用于销售。

下游收货/退货/进仓沿用来源快照与历史兼容（单头快照即行条款归集结果），不因本规范新增必填。

## 二、必填交互（销售单头 + 采购/委外行级）

1. 标签使用共享必填标识，显示红色 `*`，不再把 `(必选)` 硬编码进字段名。
2. 字段/单元格启用且为空时立即显示错误色边框（行级为列头红 `*` + 单元格红字提示）。
3. 必填不提供清空选项。
4. 保存前再次校验；失败时在字段/单元格附近显示明确错误，并阻止请求体省略该字段。
5. 字典加载中、加载失败、无可用项和历史已停用项必须分别展示，不能渲染成可保存的伪空值。
6. 红色不是唯一提示；红色 `*`、边框/红字和错误文案共同表达必填。

销售使用 `UtenDropdownField(required: true)`；采购/委外行级使用
`ProcurementTermDropdownCell`（弹菜单选择格，`procurement_commercial_grid.dart`）。

## 三、人员字段

- 业务员、采购员、经办人等员工字段遵守
  [UtenEmployeePicker](../02-组件库/UtenEmployeePicker.md)。
- 已选值和弹窗主行显示 `姓名(工号)`，部门显示在下一行。
- 员工 UUID 是提交与关联权威；姓名和工号只作展示。

## 四、服务端边界

| 链路 | 当前约束 |
|---|---|
| 销售订货 | Flutter 新建/编辑与保存校验已强制；销售订单服务仍保留 nullable/历史兼容 |
| 采购订货 | 行级必填（`groupByCommercial` 逐行校验组合完整性）；单张创建/编辑运行时校验结账方式（原 `@NotNull` 于 2026-09 移入 service，`requireHeaderSettlement`）；批量拆单请求头不携带商业字段，逐行校验后按组合归集到各张单头；提交财务时再次复核 |
| 委外订货 | 同采购（行级必填 + 组合拆单归集 + `applyHeader` 结算方式必填校验） |

## 五、默认值预填（V452 + 2026-09 学习模式）

必填是事实，预填是体验；预填不替换单据必填校验，也不覆盖用户已选值。采购/委外订货
（行级条款）的预填优先级：

1. **学习模式（/last-terms，2026-09）**：按货品记住上一次订货的整套条款
   （供应商/结账方式/币种/汇率/税率），选货品、任务中心带单、上游引入后自动带出——
   只填各行**为空**的字段；停用供应商跳过供应商回填但条款仍参考。
2. **回落默认**：币种人民币、汇率 1、税率 0（委外汇率历史固定 1，现随条款行级录入）。
3. **供应商主档默认结算（V452）**：确定供应商后行内仍未选结账方式时，取
   `suppliers.default_settlement_method_id`（仅启用中的方式）。
4. 收货/退货（单头快照沿用）：上游单据结账方式快照 → 供应商主档默认，逻辑不变。

## 六、批量设置（行级条款专属）

- 多选 N 行 → 操作条「统一设置条款 (N)」→ 底部面板一次写
  供应商+结账方式+币种+汇率+税率；**留空的项保持各行原值**。
- 行内点选供应商/结账方式/币种时，行处于多选选中态则联动填到所有选中行。
- 保存成功文案按拆单组合数提示（「已按供应商+条款组合拆分为 N 组…」）。

## 七、数量与备注

- **数量允许超过申请剩余量**（2026-09 超采/超委外放开）：分解预填默认剩余量，可改大；
  引入面板在订货模式下同样允许超量（收货/退货上限保留）。
- **实际重量列已下线**（2026-09-04：单位已表达重量，不再重复录入）：采购/销售/委外
  商业单据编辑网格与详情/审核列均不再展示；行模型 `weight` 字段保留，编辑既有单回填
  并随保存透传（>0 校验仅对回填值生效）。仓库过磅/生产日报等实物场景不受影响。
- **单位列紧跟数量之后**（2026-09-04 全站统一列序）。
- **每行末尾「备注」列**：随行提交 `remark`（数据库/DTO 全链路已有列），全部单据编辑页生效。

## 八、销售订货单价、折扣与明细表头

1. 销售订货行「单价」是只读商业快照，不能在开单表格修改：普通新行取货品主档售价；报价转单
   取已审核报价行售价；编辑既有草稿的同一行保留已冻结售价，新行/换货行才取当前主档售价。
2. 「折扣」允许持有销售订单新建/编辑动作权限的销售逐行修改。货品主档折扣只作初始建议；新写
   使用 `0 < 倍率 <= 1`、四位小数，`1=原价`、`0.9=9折`。旧数据 null/0 仍按原价读取，保存时
   归一为 1，不批量改写已审核历史。折扣列表头带 ⓘ 信息图标（`EditableGridColumn.headerInfo`），
   悬停/长按弹出「1 = 保持原价；0.9 = 9折；0.8 = 8折，以此类推」。
3. Flutter 即时预览 `数量 × 单价 × 折扣`；服务端不把请求单价作为写入来源，而是重新取得权威
   单价并用 `BigDecimal` 重算行金额/原币合计。请求省略单价仍可保存；提交非空单价与权威价不一致
   则冲突拒绝，客户端改 `price/amount*` 不得改变落库结果。
   4. **全部商业单据编辑页启用 `UtenEditableGrid.showColumnSettings`**（2026-09-04 起：
   销售/采购/委外的订货与申请编辑页）：深绿实心大按钮入口 → **按钮处锚定的浮层勾选列表**
   （2026-09-05 起与货品资料共用 `UtenColumnChooserButton`：全选行、勾选显隐、拖拽排序、
   恢复默认，点弹层外关闭）；表头纵向拖出隐藏 = **root Overlay 最顶层跟手浮层**（共用
   `UtenColumnHeaderDragHost`：原格变淡留原位、过阈值浮层红底红×、拖回取消；实现见
   [UtenTableColumnKit](../02-组件库/UtenTableColumnKit.md)）；**表头长按拎起横拖 =
   直接排序**（同日加入：按住不动拎起、横拖跟手浮层+插入位指示线、松手落位——与弹窗
   拖拽排序同一份顺序状态与持久化）。**必填列（列头红 *）锁定不可隐藏**（弹层勾选禁用
   并标注「必填列，不可隐藏」，拖出隐藏无效；排序不受限）；非必填列仍受
   「至少保留一列」兜底。隐藏只影响页面显示，行控制器和提交数据保持完整。
   **列显隐与排序按账号持久化**（2026-09-04 二刷）：宿主页经
   `EditableGridColumnPrefsNotifierBase`（`lib/shared/providers/editable_grid_column_prefs.dart`）
   接 `UtenPagePrefs`——同一编辑页的全部单据模式各占一桶（prefKey 如
   `sales.docEdit.gridColumns`、`purchase.order.gridColumns`），跨设备/重登自动带上；
   列集合演进时未知 key 忽略、新增列按默认序追加；用户本次会话手动改过列设置后，
   迟到的服务端偏好不再覆盖本地。
   **明细操作条精简（2026-09-05）**：编辑模式操作条只保留「表头设置」与宿主批量动作
   （采购/委外的「统一设置条款 (N)」等）；「全选/取消全选」「复制选中」「批量删除」
   「粘贴/粘贴多行」不再常驻——全选走表头复选框，复制/粘贴/批量粘贴/插入空行/删除选中
   走行级右键/长按菜单（同一套 controller 逻辑）。只选/任务模式（无编辑的勾选表）
   保留全选与移出常驻按钮。
5. 复制既有订货行产生的是新明细，不能沿用旧行冻结价冒充当前主档价。客户端清空复制行单价并
   提示重新选择货品；重选后取得当前主档价。若货品未维护售价则保持空值并阻止保存，不残留旧货品价格。

## 九、文案与括号

- 所有新增或修改文案统一使用 ASCII 半角 `()`。
- 员工格式写成 `姓名(工号)`，字典项写成 `名称(代码)`。
- 禁止新增 U+FF08/U+FF09；完整规则见
  [命名规范 §3.3](../00-项目准则/01-命名规范.md#33-文案与标点)。
