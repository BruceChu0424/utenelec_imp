# 领料申请、批量出库与编号收尾

日期：2026-09-26。修改位于本地工作区；本次没有提交、推送、部署、迁移业务库或清空业务数据。

## 本次行为

- 车间批量领料统一使用加载弹窗。确认申请页顶部只保留明显的红框红字选填提醒，工单、计划、车间和提交状态分列，减少堆叠行高。
- 底层自制件可先提交缺料申请，也可提前选填实际材料。选择后自动显示货品编码、规格、颜色、单位等资料，缺少资料显示横线；颜色保留显示并只读。
- 仓库列表展示实际领用材料，生产父件作为用途说明。未知材料显示红色待填写状态；已知材料可以与普通领料单一起进入原批量出库表，数量和实际仓缺项标红。
- 配料、按实际仓生成正式领料单及实发在同一事务完成；失败整批回滚，重试不重复出库。手填数量、草稿和未确认提交结果继续保留。
- 申请自动取得不可变的 `LQ` 编号，实际 DRAW 单继续取得 `SL` 编号。列表及详情显示真实单号并保留来源关系，一张申请跨仓可以生成多张正式单据。
- BOM 学习继续依据实际发料、确认退料和审核真实产出计算累计净耗量，不因选填申请或预留提前修改 BOM，也不覆盖人工维护的 BOM。

## 根因修复

1. 原仓库投影对每笔需求只取一个动作，跨仓时会漏掉第二张正式单据。现按真实 DRAW 与明细映射汇总，使用各单实际仓及自身数量；数据库回归验证了两仓 `2 + 3 = 5`，两单均可见且分别追溯到同一申请。
2. 原待补料申请只有工单身份，没有申请编号。V731 接入现有全局编号、上海日期日流水及永久占号机制，补齐历史申请；约束校验完成后才执行后续改表，不关闭历史守卫。
3. 已有待处理申请时，重复的新提交号触发单列 UUID 被当作数组解析。现使用真正的存在性查询，返回受控冲突，保留原申请号、版本、日流水及材料事实。
4. 公共备货展示错误地排除了本来源的整条记录。现仅限制精确自来源的认领量，保留批准在途、交期和记录；同分析其它需求仍可合法认领。
5. 采购/委外及制造公共供给先计算全库再筛选，导致合单超时。V729、V732 在来源读取阶段先按业务范围筛选，保留原数量与来源算法。没有放宽超时、数量或回滚门槛。

源码迁移目录为 **V732／661**。详细规则见 [ADR-119](../99-决策记录-ADR/ADR-119-底层自制实际领料与BOM累计学习.md)、[V731](../数据迁移/250-V731领料申请独立编号与正式单据追溯.md) 和 [V732](../数据迁移/251-V732制造公共供给按来源筛选后计算.md)。源码目录不代表业务数据库已经安装。
