# V590 货品归属「仓库 / 生产车间」单一事实源收敛

> 2026-09-15 · 用户拍板口径：货品资料表上的归属字段是唯一事实源，全站展示一律读它，不再有第二条「实时算一遍」的展示链路。

## 做了什么

1. **归属仓 `goods.owning_warehouse_id`（V587 列复用）任何入库自动回写**
   - 新增 `GoodsOwningWarehouseSyncService`：`UPDATE goods SET owning_warehouse_id=? WHERE id=? AND owning_warehouse_id IS DISTINCT FROM ?`（值没变不写，避免无谓审计行）。
   - 调用点收在 `StockService.recordMovement` 的 `DIR_IN` 分支——它是唯一库存过账内核，采购入库 / 委外回厂 / 完工入库 / 调拨入 / 退料 / 盘盈 / 手工其它入库**全路径无旁路**。
   - 出库与红冲（反方向流水）不翻转归属仓；红冲后再入库自然纠正。多仓并存时归属仓 = 最新入库仓，按仓真实库存仍以 `stock_balances` / 即时库存为准。
   - Excel「所属仓库」回填仍走 `import_product_lists.py` 第 3 段（**只填空**，不覆盖已有值；重跑幂等）。回填种子先落地，之后每次入库自动维持最新。

2. **归属生产车间搬进货品表**
   - `goods.owning_workshop_department_id`（归属车间）+ `goods.owning_responsible_employee_id`（归属车间负责人）两列，`production_goods_workshop_preferences`（V192 建、V488 补负责人）的学习语义**整表搬入后 DROP**。
   - `ProductionGoodsWorkshopPreferenceService` 改为读写货品表两列（学习写入语义不变：车间无歧义才学、车间换负责人整体跟随、同车间未选人保留旧记忆；预填读时仍校验车间是 DEPT_PROD 活跃子部门、负责人在职）。
   - 学习入口不变：排产确认 / 车间改派自动回写——即「哪次下达用的车间，货品就记住哪个车间」。

## 数据迁移口径

- **本迁移自足**：偏好表数据 `UPDATE ... FROM production_goods_workshop_preferences` 整行搬入（偏好表每货品唯一行，目标列新建为空）。无外部数据依赖、幂等重放安全。
- **顺序规矩（V259/V587 同款）**：goods 带审计/行触发器，UPDATE 排队触发器事件后 PostgreSQL 拒绝再 ALTER goods——列 / 索引 / FK 全部放在 UPDATE 之前。
- **清空函数孪生同步**：按 V474 的「读取已安装函数定义 + 锚点替换」失败关闭补丁，从 `business_data_reset()` 策略清单移除 `('production_goods_workshop_preferences', 'PRESERVE')`（PRESERVE 96→95；学习数据已随 goods 归 PRESERVE）。锚点单行无换行符，不受迁移文件 CRLF/LF 差异影响（V588 教训）。
- **三处同步**：`server/ops/reset_business_data.sql` 同步删行并登记版本对 `(590, 547)`；`BusinessDataResetSqlContractTest` 新增 `REMOVED_RESET_TABLES` 登记；`AuditTriggerCoverageMigrationContractTest` 移除该表（goods 本身已在清单）。
- **Excel 回填不受影响**：`import_product_lists.py` 的所属仓库段只写 `goods.owning_warehouse_id`，与本次新增两列正交；仓库对不上名会自动建 `auto_created=true` 存根的老逻辑不变。
