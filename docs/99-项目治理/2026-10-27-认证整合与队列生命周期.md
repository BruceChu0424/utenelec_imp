# 认证整合、连接准备与串行队列生命周期

## 源码边界与问题

本轮先保全并提交主目录已验证的修复，再依次合入桌面冻结提交
`1373871253cd94cb60f9f7b0207364497bbeabc7` 和员工账户完整检查点
`e44686be30f560242c3ed081fb9b1e857ae4f22d`。两个检查点的基线分别为
`3f153526f8271ba863120c528c81f4458b29391e`、
`a829bbcef678b9bf985979ee1a206e186af7e694`，不能整树覆盖较新的主线。
最终发布源码身份、CI 和服务器激活以对应发布回执为准。

整合确认三类真实生命周期问题：

1. 派生 endpoint 的 `ref.read` 会同步触发 Session listener；先预约或比较 epoch、
   后读 endpoint，可能使新 B 登录自我失效，或让 A→B→A 的旧响应通过旧检查。
   Session 没有页面消费者时，普通 `ref.listen` 还会随 provider 暂停，丢失中间 endpoint。
2. 桌面新鲜探针本来就可能在发密码前将缓存 cloud 切到 local。该合法准备改变了后台
   operation epoch，若页面要求探测前后该 epoch 相等，第一次点击会静默取消。
3. 共享串行队列保留已完成的 Future，会保留其原执行 zone。两个独立 FakeAsync zone
   的公开调用实际复现后续锁/CAS停滞；仅换 fixture 的 record lock 不能绕过
   SecureStorage 的全局 access queue。修复应释放空闲队列的完成信号。

## 唯一公共入口与调用清单

| 公共入口 | 责任及完整适用调用 |
|---|---|
| `SerialTaskQueue.run` | 唯一认证 FIFO 实现：native/web `AuthRefreshLock`、SecureStorage 全局 record access、Session commit queue 四处接入；空闲时无 tail，有等待者时保持队列次序，错误不污染后续调用，保留异步入场边界。 |
| `AuthRefreshLock.synchronized` | 保留同 scope 共享和 scope 隔离。Web 继续使用原 Web Locks/lease、租期、心跳、超时及 owner 检查；公共队列只维护本地串行边界。 |
| `SessionNotifier` operation owner | 先读取完整依赖，再预约 epoch；current 检查先读取 endpoint，再核 epoch/URL/configuration owner+revision。安全 endpoint 订阅由 container 持有并在 notifier dispose 时关闭，与页面是否监听无关。 |
| `SessionNotifier.userIntentEpoch` | 仅明确 login/changePassword/logout/impersonation 操作推进，用于尚未提交密码的准备归属。原 `requestIntentEpoch` 的后端失效语义保留给数据读取及权限边界。 |
| `writeServerMode` / `writeCloudUrl` | 同一 preferences 的显式配置 revision 在持久化 await 之前同步推进；应用、恢复默认和低层公开写调用均经过这些入口。健康探测不推进配置 revision。 |
| `loginServerPreparationProvider` | 等待同一在途真实探测，核 preferences、配置 revision、mode/local/cloud 及 probe owner；配置 A→B→A 即使最终字符串相等也退休旧准备。 |
| `LoginPage` → 同一 `SessionNotifier.login(isCurrent:)` | 准备期间核 user intent；准备结束再取最终 endpoint/OTP context，只提交一次密码。之后 caller+operation owner 共同保护预约、发送、串行提交、存储 await 前后及可见状态发布。 |

保留两个明确取消结果：`LoginServerPreparationCancelled` 和
`SessionMutationSuperseded`。页面安静结束 loading，不用旧结果记账号、导航或清除新赢家。
初始已退休的 caller 在推进 epoch/state/storage 之前被拒绝。

## 签发方与既有边界

令牌、CAS、refresh 和持久注销队列保留真实 issuer。迟到结果和旧 refresh 按原 repository、
backend、issuer 清理，不能用当前服务器替旧 token 重新贴标签。构建审过的公司 LAN/cloud
relay 可以共享一个会话；Debug/custom/loopback 保持独立，dataset UUID 相同不代表可投递凭据。
合法旧 v1/v2 无 issuer 记录仅在明确公司可信 realm 兼容；损坏 v3 不降级成 legacy。

ApiClient 保留一个 AuthInterceptor、原拦截器顺序及 readScope；refresh 的新 issuer/实际
dispatch 检查处于同一 `withOwnedDio` 生命周期内，完成后仍关闭 transport。数量、权限、
未知提交、幂等、B0预算、服务器计算权威及 Web/原生平台差异不交给连接准备层。
维护状态与 readiness 读取仍为独立匿名、禁重定向、可释放的 Dio，不带登录凭据。
