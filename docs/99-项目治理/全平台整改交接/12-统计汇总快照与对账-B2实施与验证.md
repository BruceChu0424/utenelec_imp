## 范围与同类入口清点

按统一实现要求先清点全部同类实现，形成一套公共方案后迁移全部适用入口：

| 能力 | 既有实现（勘查结论 2026-10-27） | B2 公共方案 | 保留差异 |
|---|---|---|---|
| 期间汇总（库存） | `stock_monthly_mv` 每 5 分钟全量 CONCURRENTLY 重算，**零应用读方**；对账另有全流水无窗 SUM | V949 `stock_monthly_summaries`：事件溯源账本 + AFTER INSERT 触发器同事务增量 + 排他锁重建函数 + 完整性视图/断言 | 流水 append-only、变更=新增反向行 → 直接增量（V408 范式），无需脏期间 |
| 期间汇总（客户/供应商） | 无投影：对账单期初=全历史 `UNBOUNDED PRECEDING` 窗口现场重放；年度=逐月相关子查询全量重扫 | V950 `party_monthly_summaries` + `party_month_dirty`：7 个源表触发器事务内登记（side, party, 业务月），按脏键从事件权威整格重算 | 事件流存在更新/状态翻转 → 用脏期间重算而非逐行增量 |
| 期初快照 | 资金账户已有月汇总+月内尾段（V408，唯一成型范式）；库存/往来缺失 | 三段式期初（已关月汇总 + 当月尾段 + 展示窗前缀）扩展到往来对账单/年度表 | 不新建冗余「期初快照表」：月度汇总本身就是可重建的期初锚点，保持单一真源 |
| 变化维度对账 | `StockReconciliationService` 对全 `stock_movements` 无窗 SUM，发现差异时 countRows+driftRows 连跑两遍 | 日常层：余额 ↔ Σ月度汇总小表聚合，单次查询同时取明细与总数；完整层：按货品区间分块核对汇总↔原始流水 | 两层都是只读告警，绝不自动调平；修复途径=重建函数或 CHECK 盘点/授权调整单 |
| 无读者 MV | `finance_ar_ap_mv`、`stock_monthly_mv` 零 Java 读方，仅调度器周期刷新 + 遗留导入/封存重置脚本自刷 | V951 退出周期刷新（调度器白名单 -2），对象保留为冻结诊断快照并加注释 | 有读者的销售/采购/生产/委外四张 MV 保留 5 分钟过渡刷新，待按成本逐张改造（研究报告明令「不一次性重写六张」） |

## 交付内容

### 迁移（前向新增，不改任何已应用文件字节）

- **V949__stock_monthly_summaries.sql**：库存月度汇总表（月×类型×货×仓×色，color_key 派生列入主键）、`fn_upsert_stock_monthly_summary` AFTER INSERT 触发器（共享 advisory 锁，与 V408 同构）、`fn_rebuild_stock_monthly_summaries`（排他锁全量重建，迁移时执行一次）、`v_stock_monthly_integrity` + `fn_assert_stock_monthly_integrity`（独立原始事实核对）、`stock_monthly_verification_state` 分块核对游程单行、审计登记（汇总表只审计重建戳，避免最高频写入路径每笔多一条审计）。
- **V950__party_monthly_summaries.sql**：往来月度汇总表（side×单位×币种×月；net_original/net_local 逐行 posted-settled 语义、posted/settled 本币分列、null_original_count 记「待核验」行数）、`party_month_dirty` 脏键表（`1900-01-01` 哨兵=整单位重建）、`fn_touch_party_month_summary` + 7 个源表触发器（ar_ap_ledger 按事件相关列；收款/付款头与行；预收转销/应付抵销），既有单位迁移种子哨兵，审计登记。
- **V951__retire_unused_report_views_from_refresh.sql**：两张无读者 MV 冻结注释；历史刷新状态行保留原事实。

### 服务端代码

- `features/stock/StockReconciliationService`：日常对账改读月度汇总（DRIFT 小表聚合 + `COUNT(*) OVER()` 单次取数）；新增 `verifyGoodsRange`（货品闭区间汇总↔流水逐格核对）与 `verificationState` 读取。
- `features/stock/StockMonthlyVerificationScheduler`：每天 03:41 低峰滚动核对一个货品区间（默认 250，`uten.stock.monthly-verification.chunk-size`），游程回绕计圈，漂移只告警。
- `features/finance/report/PartyMonthlySummaryService`：读路径同步自愈 `reconcileNow(side, party)`（读取永远精确，不存在读过期汇总）、后台 `drain(limit)` 按 (side,party,month) 全序排水、`seedFullRebuild` 全量重建入口、`pendingCount` 新鲜度。
- `features/finance/report/PartyMonthlySummaryScheduler`：每 5 秒排水（`uten.finance.party-summary.*` 配置），失败下一轮重试（脏键未删即未完成，天然可重放）。
- `features/finance/report/FinancePartyStatementSql`：`running` 重写为三段式（已关月汇总 + 当月尾段 + 展示窗前缀；NULL 行整行跳过、待核验 NULL 传播、:from 为空退化为全历史）；`annual` 改读汇总（调用方恒传整年，月界门槛语义不变）。**事件流 SQL（events）保持唯一权威定义**，投影重算与读取共用同一份。
- `features/finance/report/FinanceReportService`：对账单/年度表读取前自愈该单位脏键；`buildRunningBalance` 绑定 `:fromMonth`。
- `features/reporting/MaterializedViewRefreshScheduler`：`REPORT_VIEWS` 退役两张（4→6）；`ScheduledTaskCatalog` 新增 2 个任务条目并更新 2 个描述。
- `StockReconciliationController`：响应新增 `verification` 分块核对游程（附加字段，前端兼容）；一次查询替代原先 countDrift+driftRows 双跑。

### 迟到/乱序/旧单修改/跨月红冲/核销/重放语义

- 库存：新流水永远落进它自己的业务月（触发器按 `transaction_date` 上海月），迟到/乱序提交天然正确；**不用任何最大 ID / created_at 水位**。
- 往来：每类源变更把受影响（side, party, 业务月）登记进脏表——立账按账期月、遗留期初按快照日、红冲按 deleted_at 月、收款反审按 reverse_date 月、抵销按 effective_date/reversed_at 月、改期 UPDATE 同时触碰新旧月。消费=按脏键从事件权威整格重算并删脏键（同事务）：崩溃可重试、重复消费幂等、水位不存在。
- 读取永远精确：读路径先自愈本单位。对账层绝不自动调平——差异必须可见并追因（完整性断言/分块核对/日常对账三层都只告警）。

### 影子运行、重建、切换和回退

- 影子：`PartyMonthlySummaryPostgresTest` 冻结旧全历史窗口 SQL 为基准，多窗口（月初/月中/无起点/跨年）×双币×待核验×红冲×抵销场景下新旧输出逐行相等；汇总单元格与事件权威独立重算逐格相等；既有 `FinanceLegacyOpeningStatementPostgresTest` 五组场景（含遗留期初/截止日/反审日期）继续作为行为基准。
- 重建：库存 `fn_rebuild_stock_monthly_summaries()`；往来 `PartyMonthlySummaryService.seedFullRebuild()`（哨兵）+ 后台排水收敛；两者在测试中证明可精确复现增量状态。
- 切换：全部为前向新增（三张新表 + 注释 + 调度器白名单），无基表结构变更；读者切换与表启用同批发布。
- 回退：代码回退后 MV 调度器即恢复六张刷新、对账回到全流水 SUM、对账单回到全历史窗口——无破坏性变更，不需要 repair 或数据回滚；新表可留待下次重建或删除。
