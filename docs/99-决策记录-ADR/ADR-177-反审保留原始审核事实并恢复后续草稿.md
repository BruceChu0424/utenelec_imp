# ADR-177 反审保留原始审核事实并恢复后续草稿

状态：实施中，须以当前源码的真实数据库回归及界面验收作为完成证据。

日期：2026-10-11。

用户要求把员工操作的红冲改为反审：撤回已审核效果，回到可编辑草稿，修改后再次审核；库存、计划来源、应收应付、账户及业务历史必须数量与金额守恒。

## 决定

一个业务单据的已审核 UUID 是永久过账来源。现有反向流水、质检冻结、账户反向事实及 `reversed_at` 都以它为锚点。把其状态直接从 `-1` 改回 `0` 会复用已经使用的过账及反向幂等身份，因此不采用这种方式。

员工点击“反审”后，`DocumentUnapprovalService` 在同一事务内调用该业务原有的 `reverse`，保留原审核与全部反向事实，再按显式字段白名单创建新 UUID、明细 UUID 和单号的草稿。接口直接返回新草稿详情，界面替换当前路由到该草稿，可继续编辑和审核。`document_unapprovals` 永久记录原单、后续单、原因、执行人和逐行 UUID 映射。相同原单只有一个后续单；同请求键和重新生成请求键的重复点击都返回已有后续单。

事务失败时原反向动作、新草稿、来源复制、平台字段及关联记录一起回滚。每类业务仍使用原有权限和对象归属规则；统一入口要求该类单据的查看和反向权限，不额外要求反审者拥有编辑权限；后续草稿仍由原责任人按原编辑权限修订。新草稿保留原 `maker_id`、业务 owner 与 `created_by`，反审实际操作人写入审计及永久关联，不能把业务归属转给反审人。

白名单只复制业务输入与商业事实，审核人、批准/反向时间、历史导入 ID、过账状态、终态核销余额前后快照、业务累计量和旧创建请求键不复制。单价、总额输入、金额、汇率、单位换算、货品显示及来源 UUID 保留。货品快照的原审批锁时间必须清空，重新审核时由原审批流程重新冻结；保留旧锁会导致采购等单据无法再次审核。银行现金分配的前后基数、账面分配金额及 FX 是草稿也需要满足的权威输入，必须保留；再次审核重算终态核销余额，不能以“清累计”为由损坏银行/账面/FX 约束。新字段不会经运行时 schema 反射自动复制。

采购、委外订货的多来源申请分配保留原来源 UUID 和精确 `alloc_qty`，把所有来源行重映射到新订货明细。生产计划产品编号经原数据库分配器为新计划分配。生产日报按原批分组为新报告代际生成新输出批 UUID（旧批与原始缺陷首片历史永久保留，逐行映射可回查），原样复制服务器已经划分的需求/公共/实际超产/超限份额、缺陷一次归属、产出去向、人员顺序、实际用料及实盘余料；不把详情强行转换为新建请求重新拆分。再审核仍由原报工和物料/品质/来源守卫决定是否可生效。平台自定义字段按新记录 UUID 建立新的版本历史。

附件保留在原单。草稿与原单均展示前后关联，可打开原始附件；不复制同一个可删除的 storage key，避免删除草稿附件时损坏原始审核证据。

## 范围和门禁

标准入口注册 21 类：销售订货/退货/其它出货，采购订货/收货/退货，委外询价/订货/进仓/成品退货/发料/材料退/损耗，五类标准钱流单据，普通生产计划，生产日报及独立仓库单据。

原 `reverse` 方法作为内部补偿动作及专用工作流的账义务保留。员工标准详情入口只展示“反审”。出库发运事实通过原退货、财务更正流程处理；报价转入订单仍受客户接受报价和一次转换约束，需报价重新协商。分析、执行 V1 子计划、补产计划从来源计划包维护，不能通用复制丢失其来源责任。生产领退料、成品实收点收、盘点及不良品渠道使用原专用撤回流程；成品点收撤回按原实收批重建待点收任务。历史导入单据只读，不能通过此入口变成新业务。

存在已使用的下游、已核销款项、已消耗库存、期间关闭、无效来源或超出允许数量时，必须阻断整个操作。反审不会替员工猜测或级联改写这些事实。

## 验证

`AccountPostingReversalPostgresTest` 增加五类钱流及另付手续费分支：原审核→反审→返回归属不变的草稿→重复请求→重新审核，比较三个账户累计字段、正反流水及账户完整性。另测同请求键用于另一原单时整个反向与建草稿事务回滚。

`StandaloneDepartmentLifecycleConservationEndToEndTest` 增加采购订货反审后重新提交财务审核，申请来源与数量仍为原 UUID，原申请 `ordered_qty` 回退后仅累计新一轮审核一次。

`DailyReportDefectLearningEndToEndTest` 增加需求/公共拆分、实盘用料及超限实产三分支的原样草稿恢复与再次审核守恒。

所有注册 family 另在完整 Flyway schema 中核验复制列存在、无默认的必填列均提供、审核/过账/累计/锁时间不复制；这只是 schema 兼容证据，不能替代各类完整业务路径测试。最终测试结果由当前验收报告记录，本文不把尚未运行的测试宣称为已通过。
