# 平台设置页

> 路由：`/admin/platform-settings`。入口：工作台 → 系统管理 → 系统设置 → 平台设置。
> 日期：2026-10-10；决策：[ADR-175](../99-决策记录-ADR/ADR-175-公司平台品牌与配置中心.md)。

平台设置把当前公司使用的平台外观、服务器连接信息和配置去处分组呈现。配置属于当前连接的公司数据库；给另一家公司独立部署后，该公司可设置自己的品牌。此功能不建立共享数据库内的多租户隔离。

**2026-10-17 外网访问入口**：“平台配置导航 → 平台管理”新增[外网访问与连接](外网访问与连接页.md)，
沿用超级管理员及 `authorization:manage` 双重门禁。该页管理远程总开关、人数上限和人员撤权，
不是修改品牌表中的服务器地址，更不切换数据库。策略容量扩大不等于带宽或性能已经验收。

## 布局与信息层级

界面修改默认使用 `frontend-design`，复用 Uten 主题、字体和组件。页面全宽左对齐，顶部集中呈现当前连接状态、接口地址、连接方式及操作，三个标签页共享这一区域，不重复展示服务器地址和切换按钮。

“服务器与文件”在宽屏按 3:2 分栏呈现存储事实和维护入口，窄屏及大字号下改为全宽纵向排列。Logo 存储、附件位置和上传开关使用标签值行；存储位置显示可读名称，未知后端保留服务器返回值。连接重检期间或失败后统一显示等待验证，不把旧状态作为当前连接的依据。

更新说明分为公司设置和个人偏好两项摘要，额外部署及数据清除说明按需展开。品牌表单和预览、配置导航同样按实际可用宽度和字号重排，所有面板填满所属列。切换标签时回到页首，但保留尚未保存的品牌编辑；维护入口与配置导航共用忙碌禁用和未保存离开确认。

## 进入与连接核查

入口显隐和深链守卫均要求当前用户是超级管理员，且当前权限快照包含 `authorization:manage`。模拟员工视角不能使用管理员身份修改平台。

进入页面先请求当前生效服务器的 `GET /api/admin/platform-settings/status`。服务器返回有效状态且确认数据库已连接后，再读取管理配置。核查过程中以及核查失败时不开放品牌保存或 Logo 选择；页面提供重新检测和服务器设置入口。切换账号、模拟身份或服务器后，旧请求失效，不能把旧公司的设置写到新连接。

页面显示当前接口地址、连接模式、Logo 存储方式和业务附件存储配置。Logo 存储在当前公司的数据库中，和公司名称、颜色一起提交；不依赖通用附件存储是否启用。附件存储后端与上传开关只是部署配置事实，不等于对象存储、扫描器或全部业务上传链已经健康。

## 企业品牌

| 配置 | 用途与范围 |
|---|---|
| 公司名称 | 平台及生产打印件公司头显示的公司身份，必填，最多 120 个字符 |
| 公司其他名称 | 公司英文名、简称或历史名称；每行一个，最多 16 个不同名称，每个 2～120 个字符，总计最多 500 个字符；供客户文件识别排除我方卖方信息 |
| 平台名称 | 应用标题与平台展示名称，必填，最多 80 个字符 |
| 品牌标语 | 登录品牌区，最多 160 个字符 |
| Logo | 登录、侧栏与平台品牌预览；可替换或移除 |
| 主题色、副主题色 | 平台交互与品牌点缀，`#RRGGBB`；保留业务状态的语义色 |
| 登录提示 | 登录前可见的公司提示，最多 500 个字符 |
| 联系电话、邮箱、公司网站 | 平台联系信息；网站须为完整 HTTPS 地址 |

品牌信息和 Logo 可在登录前读取，只填写适合公开展示的内容。公司名称与平台名称是展示身份，不会变更库存、单据所属公司、账户、税务主体或权限。

公司其他名称只填写本公司的名称，不填写客户、供应商名称或通用词语。服务端去掉空行、修剪行首尾空白并忽略大小写去重。别名和公司名称同属公开品牌信息，也按同一版本保存。

销售客户文件识别在一次识别开始时取得公司名称、别名和品牌版本，并在卖方行排除、敏感信息遮蔽、AI 提示及结果核对各阶段使用同一份身份快照。识别过程中更换公司品牌不会改变已冻结的卖方判定。名称按字面匹配，作为身份数据传递，不作为 AI 指令；短英文简称有单词边界保护。优腾原有兼容名称只用于仍配置为优腾公司的实例，其他公司可把优腾识别为正常客户。

财务开票抬头、税号、报销说明和发票要求仍由[报销业务设置页](报销业务设置页.md)及其独立接口维护。更换平台品牌不会静默覆盖这些财务资料；可从配置入口直接前往核对。

生产执行工卡、生产备料计划汇总单的公司头与 PDF 作者信息使用打印动作发生时的当前公司名称，不再写死优腾名称；生产数量、计划包/分段身份、状态、查询和纸面布局保持原有规则。

### Logo 更换

支持 PNG、JPEG，每个文件最多 512 KiB，宽高各不超过 2048 像素。服务端验证真实图片格式、解码后重编码为 PNG，移除原图元信息。Logo 与其他品牌字段按同一版本原子保存，上传前的预览不代表已经生效。

Logo 二进制保存在 `platform_branding.logo_png`，随公司数据库备份；公开读取返回版本绑定的规范化 PNG。审计记录修改决策、版本与摘要，避免把原图或 Base64 内容写进日志。清空测试业务数据保留平台品牌。

表单统一保存本次修改，服务端要求再认证。若其他管理员已保存，新请求返回冲突并要求刷新核对，不覆盖他人的设置。服务器确认新版本后，当前客户端刷新公共品牌；其他客户端通过公共品牌刷新获取更新。

若保存命令发出后网络超时、服务器错误或响应无法确认，页面保留编辑并提示“保存结果尚未确认”。重新检测会读取服务器最新版本；发现版本变化时要求读取最新设置后核对，不能把重新连通当作保存已经失败或成功。版本未确认的写入也不能跳过 `expectedVersion` 再次覆盖；撤销涉及冲突或未确认保存时，要从服务器重新读取。

未保存编辑的离开保护同时接入 `PopScope` 和 `FormDraftNavigation` 的当前路由 `pageKey`，覆盖返回键、深链返回、侧栏/胶囊 `go`、路由替换和浏览器返回。重新读取、切换连接方式或进入配置入口会按现有交互提示丢弃编辑；保存、读取或选图进行中不允许通过导航离开。身份或服务器变化按权限栅栏立即作废旧编辑，不能借确认框继续写入旧来源。

## 服务器与部署边界

原生正式版只在安装包构建时批准的本地、云端 HTTPS 地址之间选择，可选择自动、仅本地、仅云端。Web 正式版固定使用当前访问入口同源 `/api`，服务器由部署入口和 DNS 决定。Debug 版本保留既有开发地址覆盖功能。

本机连接模式只影响当前设备；它不是给全公司改服务器的设置。页面复用现有服务器选择逻辑，并显示当前生效地址；服务器迁移、远程访问授权、网络入口和数据库迁移须各自按现有管理链路实施。

数据库连接、JWT 和加密密钥、CORS、存储凭据、部署站点等启动配置不通过品牌表单改写。平台页显示必要的非敏感状态并引导至相应配置去处；AI 服务商密钥沿用[AI 服务设置页](AI服务设置页.md)的受控只写机制。

运行时品牌设置不能更换原生安装包图标、Windows 静态版本资源或已经安装的 PWA 清单信息。这些外壳资源需要重新构建安装包或发布 Web 外壳；用于存储路径的技术安装身份字段仍保持既有值，不能随品牌更名。页面内标题、品牌和主题色由运行时设置管理。

## 更新版本保留公司设置

普通版本更新保留当前公司的品牌、Logo、公司别名、安全运行策略、业务配置与个人偏好。升级更新程序代码和静态资源；公司的数据库、环境配置及附件原件不作为发行包中的默认数据覆盖。新增配置只能补充缺失项，已保存配置的迁移规则由后端回归验证。

| 范围 | 保留规则 |
|---|---|
| 服务器与数据库 | Simple 更新器切换 `/opt/uten-imp/current` 指向的版本目录；运行环境继续读取 `/etc/uten-imp/server.env`、迁移读取 `/etc/uten-imp/migrator.env`，不在普通激活中重装环境文件 |
| 附件与备份 | 附件原件在独立 `/var/lib/uten-imp-media/attachments`；数据库及备份也在发行目录外。版本清理只处理历史发行目录，不清理公司原件 |
| 含迁移升级与回滚 | 迁移前先备份；代码失败回滚不静默恢复旧数据库。含迁移失败保留备份、停止应用，由维护人员核查后恢复，避免把升级后的公司设置和业务写入覆盖成旧值 |
| Windows | 稳定的技术存储身份保持 `CompanyName=Uten`、`ProductName=优腾综合管理平台`、可执行名 `uten_imp`。现有插件用这两个资源字段构造偏好和凭据目录，因此它们不能替换成平台公司显示名称。可见窗口标题另由运行时平台名更新，只改变窗口文字 |
| Android、iOS | 保持已安装应用的 package/bundle 身份：`com.uten.uten_imp`、`com.uten.utenImp`；更新继续使用同一发布签名身份，不能用卸载再装或清除应用数据代替升级 |
| macOS、Linux | 保持原 bundle/application 身份及既有本机数据路径；品牌显示变更不创建新的技术安装身份 |
| Web | 保持公司的 HTTPS origin 和同源 `/api`。刷新版本化静态资源及 Flutter 资产缓存，不清空 local/session storage、IndexedDB 中的用户数据，也不发送 `Clear-Site-Data` 清站点数据头 |

服务器版与 Web 的现有 Simple 发布链只发布程序和 Web 资源。仓库目前没有可验收的桌面/移动安装器升级链；以上客户端安装身份是源码保护规则，实际新安装包仍须核对签名、应用身份和原数据路径，不能由源码测试推断安装升级已经完成。

用户主动卸载、操作系统清除应用数据、浏览器清除站点数据，以及公司更换服务器、域名或数据库，属于单独的数据保留或迁移操作，不等同普通更新。原生客户端常规更新应继续使用该公司的已批准可信端点；换服务器须先核对数据及连接来源，不能以新安装包默认地址代替公司迁移。

客户端持久缓存最近两个可信接口确认过的公开品牌和 Logo，缓存键独立于应用版本，Web 同源接口同时绑定浏览器 origin。更新重启或暂时断网时可显示上次确认的公司品牌；管理页以只读方式展示，必须重新通过服务器状态及管理配置读取才开放修改。缓存不作为权限、连接和保存成功的依据，不将安装包默认值写回服务器或个人偏好。单个 Logo 的缓存绑定服务器、品牌版本和摘要，损坏条目只忽略该品牌缓存。

升级期间 Logo 接口的 404 可能来自旧版接口或旧品牌版本，不能据此删除已经确认的图片。客户端会核对最新品牌信息，只有服务器的新鲜品牌信息确认未设置 Logo，才清除旧图；新的品牌身份与旧图不能混用。

`PlatformSettingsUpgradePostgresTest` 在隔离数据库验证服务重建、重复迁移及临时追加兼容迁移后，公司品牌原列和完整 Logo 字节、25 项运行设置、用户主题和表格布局 JSON、通知弹窗偏好保持原值；历史种子被改动时拒绝升级并保留原设置。`PlatformSettingsUpgradeContractTest` 保护唯一授权写路、没有启动默认覆盖、旧设置名称/类型/有效范围兼容，以及后续迁移不得重置已有配置。客户端另有固定 v1 存储格式兼容回归，后续版本不能通过重建当前模型夹具掩盖旧缓存读取问题。

`deploy/updater/test_company_upgrade_preservation.py` 在 CI 的部署契约组自动执行，保护环境/原件与发行目录隔离、更新与回滚无隐式数据库恢复、客户端技术身份稳定、Web 同源且不清用户存储。该测试仅读源码及临时目录，不操作已安装主机。

## 配置入口

配置入口目录为 `lib/features/admin/models/platform_settings_catalog.dart`，通过路由的同一套 any/all 权限规则过滤。每个目标继续使用自己的权威接口、动作权限、版本校验和审计。

入口按平台管理、业务基础、运维与核查、我的偏好分组；平台页本身仅超级管理员可操作，品牌保存明确影响连接此服务器的全公司员工。

| 入口 | 配置内容 |
|---|---|
| 安全与运行设置 | 登录保护、业务提醒、审计留存、服务器更新计划 |
| AI 服务 | 服务商、模型、密钥、连接测试与使用限额 |
| 报销与开票信息 | 财务抬头、税号、报销说明与发票要求 |
| 账号与权限 | 账号、部门及个人权限、数据范围、远程访问 |
| 基础资料与业务字典 | 货品、客户、供应商、仓库、账户、币种、单位与结算方式 |
| 车间物料管理 | 各车间内料仓、来源仓与物料管理方式 |
| 服务器状态 | 服务器、数据库、备份、存储与定时任务状态 |
| 审计中心 | 平台配置和业务操作记录核查 |
| 我的偏好设置 | 当前设备的深浅主题、语言、字号、性能与时间显示 |

报价模板、货品/BOM、采购收货策略等依赖具体业务对象的配置，继续在相应业务页操作。个人通知弹窗开关继续在工作台通知设置中操作，不把某个人的偏好写成全公司策略。

## API 与验证

- `GET /api/platform/branding`、`GET /api/platform/branding/logo?v=版本`：匿名品牌展示，只返回公开白名单字段及规范化 Logo。
- `GET /api/admin/platform-settings/status`：管理员连接与存储配置核查。
- `GET /api/admin/platform-settings`：管理员读取品牌配置。
- `PUT /api/admin/platform-settings`：超级管理员、授权管理权限、再认证、`expectedVersion` 原子保存；Logo 可替换、保持或移除。
- `V839__company_platform_branding.sql`：独立公司品牌单例、约束、审计与测试重置保留策略。

匿名豁免只匹配上述两条精确 GET 路径；相似子路径、尾斜杠、其他方法及 `/api/admin/platform-settings/status` 不获得豁免。JWT、远程访问和首次改密过滤器共用同一精确匹配规则；公司内网的网络来源边界继续生效。

源码验证覆盖权限与深链、加载失败时的入口、配置入口权限过滤、连接前置条件、失效响应、保存冲突、图片边界、审计与公共读取。迁移及针对性测试通过不等于已发布，也不等于公司服务器和员工实际使用已验收。

## 官方参考与本平台采用方式

[SAP 主题设置](https://help.sap.com/docs/help/e37f3c54603c4647b0b5d73c870f6223/3a9285c4711841c9b612ff87c1d8d6ad.html)以统一主题管理公司 Logo 与颜色，[Dynamics 365 更换横幅或 Logo](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/get-started/tasks/change-banner-or-logo)由系统管理员为指定法律实体保存品牌，本平台对应采用超管专属公司品牌表单、全局主题应用和保存前的公司/服务器核对。

[Odoo 19 公司设置](https://www.odoo.com/documentation/19.0/applications/general/companies.html)将公司资料、用户权限及公司单据布局集中组织；本平台借鉴这一配置导航方式，将平台管理、业务基础、运维核查和个人偏好分组，并继续通过各业务权威入口维护财务抬头与权限。当前实施仍是每家公司独立部署、当前数据库一个品牌单例，不引入这些产品的共享数据库多公司模型。
