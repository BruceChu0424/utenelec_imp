# V631 出货明细按行记实际发出仓

- 迁移：`V631__sales_shipment_line_warehouse.sql`。
- 口径来源：2026-09-20 用户拍板「仓库确认出库不再选整单实际发货仓；发出仓在明细表按行选、预填建议仓，以后批量发货不用因为货分在不同仓而拆单」+「仓库只管仓库的，币种汇率没维护应在财务放行时提示」+「实际库位号预填建议库位」+「作业更新时间要可读」。
- 依赖：V188 出库事件账；V566/V582 一步式出库与实仓取证；V613 核算叶仓判定；V630。

| 对象 | 变化 |
| --- | --- |
| `sales_shipment_items.warehouse_id` | 新列(FK warehouses)：行的实际发出仓；`status=1` 的历史行回填为表头仓(此前整单只能从表头仓发)；部分索引 `idx_sales_shipment_items_warehouse` |
| `sales_shipment_warehouse_events.line_warehouses` | 新 jsonb 列(默认 `{}`)：确认出库事件冻结的 itemId→warehouseId |
| `fn_guard_sales_shipment_picking_evidence()` | `pg_get_functiondef` 锚点补丁：非 SHIPPED 事件不得带 `line_warehouses`；SHIPPED 事件每个键须是本单明细 UUID、值须是启用的核算叶仓(`fn_warehouse_is_active_accounting_leaf`) |

表头 `sales_shipments.warehouse_id` 的语义收窄为「默认/主发出仓」：推迟选仓的单据在确认出库时取第一行的发出仓落表头(V582 的 SHIPPED 事件仍按表头仓取证，`fn_assert_sales_shipment_picking_warehouse` 不变)；销售指定过仓的单据表头不动，行仍可各自选仓。

## 应用侧

- 后端：`WarehouseWorkTransitionRequest.StockPlace` 增 `warehouseId`；`transitionWarehouseWork` 按行解析发出仓(行指定 > 本次默认仓 > 行已落定 > 表头仓，缺一行即拒绝)并写回明细；可发量校验按仓分组；`approveLocked` 消预留、`applyMovement` 过账、红冲回库都按行仓；直发客户的 `CustomerShipmentInventoryPort.Line` 带 `warehouseId`，`reservePicking/consumeShipment` 不再收整单仓。
- 仓库视图：`WarehouseSalesOutboundDetail` 删 `canSelectWarehouse/warehouseOptions`；`WarehouseSalesOutboundLine` 增 `warehouseId/warehouseName/suggestedWarehouseId/warehouseChoices`(候选仓及各自可发量)。
- 财审：`financeAudit()` 放行前 `requireFinanceRateMaintained`——币种汇率未维护(≤0)直接 409 并指向基础资料→币种；`finance-audit-info` 增 `currencyName/financeRate/financeRateReady`，财审页放行前红条提示、放行按钮禁用。
- 前端仓库出库详情/批量核对：删「实际发货仓库」下拉，表格「发出仓」列改为按行下拉(预填建议仓，选项带可发量、不足的禁选)；「实际库位号」预填建议库位；「作业更新/出库时间」按北京时间显示。
