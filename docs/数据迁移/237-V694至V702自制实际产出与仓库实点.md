# V694–V702：实际产出分账、比例审批与追加计划

对应 [ADR-118](../99-决策记录-ADR/ADR-118-自制实际产出分账与公共超产.md)。本地源码候选，现场只读取证时为 V688；迁移目录与服务器安装状态分开记录。

| 迁移 | 职责 |
|---|---|
| V694 | 日报实际批次、数量和公共身份；需求／计划公共／实际超产分账；批次数量、来源与批准后身份不可变守卫 |
| V695 | 已审实际超产支持真实库存与成本目标；所有精确供给消费者共享公共来源判定；反向与草稿占用完成边界 |
| V696 | 开放已开工任务保留实际报工能力；实际超产与原计划完成进度分离；公共先入不填满原需求 |
| V697 | 仓库自动点收的逐行实点数证据；新增自动登记要求核对数量，历史未知点数不回填；无证据旧待检批次走人工点收 |

| V701 | 只有正式追加来源证明可共享材料、执行及成本谱系；不重复需求、领料、实耗或产出，固定追加量回原批次续报 |
| V702 | 普通任务与实际追加任务共用同料增量申请；计划部审批生成独立冻结增量需求，原用料定额和产成品目标不变；真实备料、实发和实耗沿原仓库流程 |

V694–V697 仅增加列、函数、视图、索引和守卫；V698 增加两张比例申请／决定表，V700 增加四张实际追加请求／证明／反向／占用表，V702 增加三张材料增量申请／决定／撤销表。九表均为 CLEAR 业务数据：请求为 FULL 审计，追加式决定／证明事实不重复做行审计。历史日报、原计划量、销售分摊、既有库存与质量事件不重写。原 V690 公共来源按可证明的旧身份兼容，普通内部无销售任务不能因此变成公共。

V693 为并行仓库负责人任务，必须先保留并正常前向应用；不得占用其编号。本阶段目录为 V702 / 631 个迁移文件，后续 V704–V707 见 [239](239-V704至V707计划超产比例与历史迁移恢复.md)。`server/ops/reset_business_data.sql` 仅更新支持的目录证明，不在公司服务器执行该脚本。同步补齐 V693 之后保留表数量100的校验，及新九张业务表的版本／完整性检查。

验收需要全新库完整回放、V693 后前向升级、再次迁移为零、历史非空数据保留，以及批次 NULL／数量／身份／并发对抗。业务验证必须包含实际超产、直送分流、公共先入、质检、少收余量、反向、成本和下游占用阻断。

回退不能编辑已应用迁移或执行 Flyway repair。发布失败先保留新数据和完整备份，依既有更新器流程选择兼容制品或前向修正；不可用旧库快照覆盖发布后新记录。
