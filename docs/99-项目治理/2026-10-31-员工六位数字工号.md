本次为独立本地实现；公司内部数据库尚未执行，未部署、未打包或上传。历史改号必须与新服务端在同一维护窗口落地，恢复员工写入前完成下述核对。

**执行次数：仅一次。** 首次发布此需求时，将历史改号列为独立的一次性部署步骤；它不是应用启动任务、定时任务或每次升级动作。成功后废弃现场执行入口，保留新旧工号对照和审计证据。后续服务器更新不加载或调用改号脚本，只保留普通新员工接续取号的长期功能。

## 已确认业务规则

- 工号是保留前导零的六位数字字符串，不带 UT。朱德洪固定 `000001`，王少春固定 `000002`。
- 首次对现存、未删除的保留员工档案按入厂日期从早到晚排序；同日按原档案创建时间、UUID稳定排序。包括离职保留档案，防止复职获得另一个身份/工号。已确认的重复档案别名不另外编号，保留原始历史。
- 登录账号 `17665410007` 通过 `users.employee_id` 定位，不按姓名猜测。对应档案原来的 `ADMIN` 改为本次最后一个数字工号，入职日期按本次用户所说的“今天”固定为 **2026-10-31**，不能用将来执行脚本当天替代。
- 编号后固定，改入职日期或补录老员工不重排。首次受审改号将新序列设为本次最后号，避免历史自定义高数字工号把新序列推远；此后只递增，不消费旧 UT 释放池，离职、合并及归档不会回收新数字号。已有全局历史占号时跳过，不承诺无间隙。超过 `999999` 拒绝取号，禁止截断。
- 其他独立 bootstrap `ADMIN`（如果存在）、已删除档案和已核实别名出现在预览的排除清单；不得隐瞒或误当作已编号员工。两位创始人存在同名保留档案时拒绝，先核对身份。
- 入职日期更正追加 `hire_date_correction`，保留原始任职事件。公司数据副本显示本人 `ADMIN` 的入职、转正均为2026-01-01，并有2026-10-31同日调岗记录；用户已明确确认两项日期均改为2026-10-31，保留调岗历史。维护计划允许该同日调岗，不允许更早的真实调岗或转正事实被覆盖。旧日期、新日期、版本和原始历史均进入受审对照。

3. V977只安装取号基础与回执表，不自动修改公司员工。使用遇错即停止的维护连接加载 `server/maintenance/employee_six_digit_numbering.sql`（psql须使用 `-X -v ON_ERROR_STOP=1`），按UUID核对两位创始人，查询：

   ```sql
   SELECT pg_temp.employee_numbering_plan(
       '<已核实朱德洪UUID>'::uuid,
       '<已核实王少春UUID>'::uuid
   );
   ```

   将返回JSON以受限权限保存，不粘贴到公开日志。逐项核对 `entries`、`excluded`、`accounts`、`ownerHistory`，`issues`必须为空。明确核对本人绑定、最后号、2026-10-31日期、两位创始人前两号和其他员工入厂次序。权限和密码不在预览中导出。
4. 保留已核对的**原样JSON**，用参数化查询在同一维护连接执行，先用ROLLBACK演练；正式实施时在核对返回回执后提交：

   ```sql
   BEGIN;
   -- $1是已审核JSON，不重新生成并静默接受一个新计划；$2是本次备份/审核证据引用。
   SELECT pg_temp.apply_employee_numbering($1::jsonb, $2::text);
   -- 核对前两号、本人最后号、人数、回执，以及员工/账号/业务UUID与账号安全属性未变。
   -- 与数据变更在同一事务内废弃执行入口；失败回滚则仍可更正后重试。
   DROP FUNCTION pg_temp.apply_employee_numbering(jsonb,text);
   DROP FUNCTION pg_temp.employee_numbering_plan(uuid,uuid,text,date);
   COMMIT;
   ```

   函数持有员工、账号、别名和任职历史表写锁；预览过期、身份/日期冲突、历史预约冲突均整体拒绝。不关闭审计、不启用legacy-import豁免、不删除或转让预约。如果连接断开，先只读查询完成回执，不重新运行脚本。临时入口尚未删除的同一连接重送相同计划时只返回已有回执，不更新员工、历史或序列。
5. 核对 `employees`、`employment_history_effective`、回执、序列及新旧全局预约。原单据/历史快照不改写；它们仍能按UUID查到当前员工。数字工号排序与按入职日期排序是两个字段，后续更正日期不改号。
6. 用本人原账号验证登录及权限，验证员工列表/详情/部门花名册/选人/打印导出保留前导零，新增一个隔离测试员工验证接续取号。正式环境避免为试号制造真实无用档案；现场验收结束再恢复业务。提交后不通过交换号码回退；需要恢复时按完整备份与同源服务端恢复方案处理，保留审计。
7. 完成后退出维护连接，将现场脚本临时副本从执行目录撤下；后续发布不再分发/装载该一次性入口。审核源文件保留在Git用于追溯；不得删除已应用的Flyway迁移文件、迁移历史或改号回执来“清理脚本”，也不得通过清除完成标记再次排序。
