# V597 自制产成品「先入库后质检」(合格自动点收)

> 2026-09-16 · 用户口径：「所有入库的行为都支持『先入库后质检』或者『直接登记并质检』这样才对。」
> V596 给采购/委外到货(IQC)做完之后，系统里另一条「必须先过品质才能入库」的链是自制产成品报工入库(FQC)，
> 本迁移把同一个选项补到那条链上。决策见 [ADR-090](../99-决策记录-ADR/ADR-090-到货先入库后质检.md) 第六节。

## 这条链原本长什么样

车间报工 → 仓库「登记成品仓与库位」(送检登记：**实物这时已经交到成品仓的库位上**) → 品质 FQC 判定 →
合格放行生成 FINISHED_IN 草稿(status=0) → 仓库「点收」确认实收 → 才写 `stock_movements` / `stock_balances`。

也就是说这条链上的实物**本来就已经在仓库的库位上**，品质部本来就是到库位去检验。
比 IQC 少的那半步是：品质合格之后，仓库还要再点一次「确认实收并入库」。

## 所以「先入库后质检」在这条链上 = 登记时就承诺「合格按这个位置全量入库」

- 仓库在送检登记页点「先入库后质检」(而不是「登记并送检」)：登记头记下这个决定(三列)；
- 品质部照常收到检查单，队列与办理页顶部标红「货品已入库，需到对应储放区域检查」，逐行给出「成品仓 / 库位」；
- 品质**合格**时，在判定的同一笔事务里由系统按登记的仓 + 库位自动完成点收(走 V338 同一套确认/守恒/价值/库存写入，
  批次来源记 `origin=PRE_STOCKED_AUTO`)，**仓库不再收到「待点收」任务**；
- 品质**不合格**时什么库存动作都没有(本来就没写过库存)，照常走 V410/V412 的恢复/补产链路。

**代价必须说清楚**：自动点收 = 实收恒等于报工量，放弃「短收改量 + 差异原因 + 余量单」那一步
(与 V584 车间直送入库同口径)。需要按实物改量的批次就走原「登记并送检」。

## 改了什么(不新增表、不改任何既有行)

| 对象 | 变化 | 为什么 |
| --- | --- | --- |
| `production_finished_arrival_registrations.stock_in_before_inspection` / `pre_stocked_at` / `pre_stocked_by_employee_id` | 三列 + `production_finished_arrival_pre_stocked_shape_chk`(同进同出) | 登记表是追加式的(守卫拒绝任何 UPDATE)，所以这个决定在登记那一刻做出、之后不可改——与「登记本身不可改」同口径 |
| `idx_production_finished_arrival_registrations_pre_stocked` | 部分索引 (仓, 时间) WHERE 已选先入库 | 品质队列按「已上架待检」标红分组 |
| `fn_guard_production_finished_arrival_registration` | 补两条：选了先入库的批次，目标仓必须是 `fn_warehouse_is_active_accounting_leaf`(V596 同一函数)且非线边仓 | 合格后系统会直接按这个仓自动入库，落仓口径要提高到与入库选仓一致；线边仓是车间料架 |
| `production_finished_in_confirmations.origin` | 新列 NOT NULL DEFAULT `WAREHOUSE_CONFIRM`，CHECK ∈ {WAREHOUSE_CONFIRM, PRE_STOCKED_AUTO} | 点收历史分得清「仓库确认实收」与「先入库后质检的合格自动点收」 |
| `trg_guard_production_finished_in_pre_stocked_confirmation` | BEFORE INSERT ON 点收确认 | 自动点收必须是全量接收(无余量单)，且该入库单每一行都要来自一个「先入库后质检」的未撤回登记行、落仓与库位与登记快照一致 |
| 权限码 `production_finished_in:before_inspection` | 新增；默认授 DEPT_PMC / SUB_WH / GM；登记到 `warehouse.inbound-tasks` 面 | 「合格就自动入库、不再人工点收」是一个独立的、可回收的决定，不靠 `stock_doc:approve` 顺带(它同时是登记与点收的按钮码) |

## 链路(每一种情况)

1. **进入方式**：产成品送检登记页(单张/批量)底部「登记并送检」左边的「先入库后质检」按钮；没有权限的账号看不到这个按钮，
   服务端也兜底 403。
2. **上架约束**：仓必须是启用中的记账叶仓且非线边仓；库位本来就逐行必填(原流程也必填)。
3. **品质合格(整行/部分/分批)**：每个 PASS 事件放行多少就自动点收多少——同事务 `confirmPreStockedFinishedInbound`，
   幂等键 `FQC-PRESTOCK:<PASS 事件 UUID>`，确认行 `origin=PRE_STOCKED_AUTO`、`decision=ACCEPTED`；
   点收人记为出结论的品质账号(单据授权走「证据即授权」：入库单每行都必须来自先入库登记行)。
   「待点收」通知因为单据在同一事务里已推到已审核而自动不投递(V338 的投递条件是 status=0)。
4. **品质不合格**：与原流程完全一样，不动库存，开恢复授权/补产任务。
5. **先入库的登记批次被撤回(V548)**：条件不变(该批每条 FQC 仍 PENDING 且无任何决定/放行/恢复授权)，
   撤回后登记行失效，自动点收的前提随之消失；实物要不要从库位搬走由仓库按撤回原因线下处理。
6. **上架仓后来被停用/改成父仓**：自动点收里的 `requireActiveLeafWarehouse` 会拒，整笔品质判定回滚；
   仓库改仓后重新登记(与 IQC 的「退回原流程」不同：FQC 的落仓是登记事实，不能在判定时换仓)。
7. **红冲**：`reverseFinishedInbound` 照旧(自动点收产生的入库单与手工点收的形状一模一样)。
8. **徽章与队列**：自动点收的单从来不进「产成品待点收任务」(那个队列只列 status=0 的 FINISHED_IN)，
   仓库待办自然少一项；品质待检徽章口径不变。

## 回填与兼容

- 老登记行 `stock_in_before_inspection = FALSE` = 原流程，行为一个字节不变；老点收行 `origin` 默认 `WAREHOUSE_CONFIRM`。
- 登记幂等哈希只在选了先入库时追加一段 `stockInBeforeInspection=1`：老键的哈希逐字不变，
  同键不同选择会 409(而不是静默按第一次的选择重放)。
- 清库策略：不新增业务表，`business_data_reset()` 目录对追加 (597, 554)。
