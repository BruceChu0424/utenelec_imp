# 采购委外导出、差异数同步及分析恢复检查

本记录对应 2026-10-27 本地工作区候选，保留了工作区已有的差异数及其他并行改动。未提交、未发布、未迁移生产数据库，不代表员工浏览器或生产业务验收。界面按 `frontend-design` 与现有 Uten 组件、主题、按钮位置实现。

## 行为与范围

- 采购与委外的进行中、历史记录表格可按当前搜索、表头筛选、排序、时间范围导出；历史列表与导出明确限定 `COMPLETED`，修正原先仅传日期导致混入其他阶段的问题。
- 两模块的进行中、历史记录支持勾选关联订单导出 PDF，多份打包 ZIP；同订单多行只输出一份。委外混合待处理表保持其原申请与领料来源，未用单一任务查询冒充整张混合表导出。
- 采购单打印与批量输出取消财务审核前提，委外使用相同读取、确认和输出机制。待审状态如实显示，财务未通过不生成审核人签名。此变更不提交、批准或下达业务单据，也不放开领料、库存、应付等业务动作。
- 委外差异数补齐领料中的父件订单行、材料出仓和材料退回的关联订货差异；详情、明细报表及其导出使用同源字段。保留已有申请、订货、回厂、成品退回等入口的差异数实现。
- 订单差异数为累计实到减退回减订货，负值表示欠到数；直接结束或损耗结案不会把实物差异清零。申请行仍表示有效已订减需求。材料单明确显示源订货单位，不与材料行数量混算；跨货品、单位的整单列表不叠加一个无意义的总数。

## 公共能力及迁移清单

| 公共入口 | 已迁移调用方 | 保留差异 |
|---|---|---|
| `lib/shared/export/order_document_selection.dart` | 采购工作台、委外任务中心 | 各自可查看订单类型及提示 |
| `lib/shared/export/order_documents_export.dart`、`order_document_bundle.dart` | 采购和委外批量订单 adapter、路由注入、Web PDF Worker | 接口、纸张标题、文件名；采购赠品与委外实际订货数量 |
| `lib/shared/print/procurement_order_print_document.dart`、`procurement_order_pdf.dart` | 采购详情预览、采购和委外 PDF/ZIP | 未审签名为空，状态/价格脱敏保留事实 |
| `ProcurementOrderPrintDocument`、`ProcurementOrderPrintSupport`、`ProcurementPrintSnapshotDigest`、`ProcurementPrintAuthorization` | 两模块 print-data 与 print-authorization | 各领域 detail 授权与快照行构造 |
| `FulfillmentWorkbenchQueryService.exportProcurement`、`WorkbenchReportExportSource` | 同步导出及后台任务 `workbench_purchase` / `workbench_subcontract` | 两张表的列配置、模块导出权限 |
| 既有 `ProcurementDeliveryDifferenceRead`、`procurementDifferenceColumn` | 委外领料 DTO/模型/待处理行，材料出仓/材料退详情、明细报表、导出 | 源订单查看范围与单位；缺权限或事实显示未知 |

采购旧打印、PDF bundle 与批量导出路径保留为薄 adapter 或兼容导出，原有通用流程已迁入公共入口，不保留第二套 PDF 打包/快照校验实现。原采购快照摘要类已由公共摘要实现替代。

输出仍保留 100 份、32 MiB 输入、100 MiB 产物预算，后台 Worker、文件名避碰、部分失败汇报、内容摘要、落盘前服务端重读授权，以及身份/权限/服务器/筛选/离页取消。筛选采用单调代次，切换后再切回同一条件不能恢复旧导出。委外列关键词筛选改走服务端，与导出使用同一条件，不再只过滤当前已加载行；重复来源展示列关闭无对应服务端字段的关键词入口。表格导出沿用既有后台任务、完整分页、投影及模块权限，不截取当前屏幕行。

同步表格导出、打印 JSON 及后台任务均使用对应 `native_purchase_owner` / `native_subcontract_owner` 范围；人员交接、归属或授权变化后，生成、读取和交付阶段重新校验。精确的打印重授权 POST 属于只读查询，客户端不误增业务写修订，模拟身份也不因此放行业务写入。各条原生范围路由由公共 `ProcurementReadRoutes` 统一维护。

## 第三张图仅核查

生产调度与进度双击进行中的 `ANALYSIS` 行，仍以原 `analysisId` 读取服务器分析快照；不跳草稿，不因打开自动重算。已保存的路线、优先级及成功提交的业务操作可恢复。

页面保持挂载时，从子页返回或只读轮询会保留有效临时编辑；彻底退出到列表再双击会创建新页面，未提交的数量、勾选、负责人等局部输入没有跨退出草稿持久化。本次未修改生产分析业务代码。
