# 表格读取异常恢复（2026-10-28）

本轮针对表格左上角反复出现“扩展字段未更新”，以及读取错误挤占表格的问题。基于当前本地工作区继续完善已有修复，保留其他并行改动；本记录不代表打包、发布或真实岗位验收。

## 根因与场景处理

| 场景 | 自动处理 / 明确处理办法 | 保全边界 |
|---|---|---|
| 表头缓存含已失效或其他模块的列 | 仅显示偏好解析使用服务端 `availableOnly`，按当前模块与账号返回可用定义；清理失效列对应的显隐、次序、冻结、宽度、筛选和排序偏好 | 不清理业务记录、历史快照和本地暂存值；写入与公式依赖仍严格校验 |
| 缓存列编号不是 UUID | 在显示偏好读取边界过滤，避免请求在服务端 UUID 参数绑定前整体失败；返回结果驱动同一布局修复 | 不修改模型、真实记录编号、保存及历史接口的校验 |
| 价格或关联权限使某些偏好暂时不可用 | 批量投影只发送本次元数据校验过的根列，保留权限隐藏的偏好供恢复权限后使用；服务端独立加载和遮蔽已保存字段 | 不把授权拒绝当作失效配置清理，不让未校验的隐藏列拖垮整批读取 |
| 元数据读取后目录列被删除 | 列定义不可变，目录删除使用墓碑；批量读取仍能解析已选投影 | 不重建业务字段，不重放写入 |
| 短暂连接或网关故障 | 沿用公共安全读取重试策略；扩展列只读批量接口最多自动重试两次，退避 400/1200ms | 保存、创建、删除及未知提交不重放；慢请求收发超时不盲目重试 |
| 服务端要求稍后重试 | `Retry-After` 秒数和 HTTP 日期共用解析；等待不短于既有退避及服务端要求；超过 10 秒的服务端冷却不进入自动循环 | 日期优先使用响应的服务器时间，避免设备时钟偏差；保留人工处理入口 |
| 权限或登录失效 | 保留明确说明，重新获取有效权限后再读取；新拒绝优先于旧缓存与迟到回执 | 遮蔽无权读取的值，保留待编辑原文，不绕过授权 |
| 批次缺失、重复或返回其他记录 | 整次读取不发布部分新结果；提示核对记录与范围后重试 | 保留上次完整快照及本地草稿，禁止混合新旧批次 |
| 首次列表、后台刷新、连续翻页或分组失败 | 共用紧凑摘要与可点击详情；按场景重试所属读取 | 刷新、翻页与分组保留已加载数据，首次读取不冒充已有结果 |
| 原因过长、多行、窄屏或大字体 | 公共状态组件限制摘要；窄宽使用图标，完整原因进入可滚动、可选择的详情 | 不截断诊断原文，不让错误正文撑大工具条 |
| 既有记录的补充列尚未读取成功 | 显示“同步中”或“暂不可用”，读取成功且实际为空才显示空值 | 不把未知值当空值、零或计算失败；已有快照、本地输入与价格遮罩继续保留 |
| 打开详情后更换账号、查询、表格，或后台恢复 | 立即废止旧详情动作，移除自身说明弹窗；同一所属对象重建继续使用最新回调 | 不执行旧分页闭包，不访问销毁后的上下文，不误关闭覆盖其上的其他弹窗 |

## 公共入口、调用清单与清理

- 显示：`UtenTableReadStatus`；扩展列适配：`PlatformTableStatus`；读取及布局恢复：`PlatformTableController` / `PlatformTableRepository`；服务端定义权威：`PlatformColumnService`。
- 两个扩展列公共宿主：`MasterDataTableView` 工具条、`UtenEditableGrid` 操作条。提示位于既有表头与操作之后，避免插入失败提示移动原有首要操作。普通视图与全屏使用相同实现。
- `MasterDataTableView` 首次读取、刷新失败、连续翻页和分组失败共用同一显示组件，移除无限长度分页原始错误及悬停才可获知完整原因的独立实现。
- 当前 AST 逐调用清单见 [本轮调用清单](表格读取异常恢复-20261028-调用清单.md)：`MasterDataTableView` 210 处、`UtenEditableGrid` 28 处，以及委托主表的修订表 10 处。调用点不等于页面数；公共接入和组件回归不冒充每个业务页面的真实账户验收。完整扫描快照保存在 `output/table-read-recovery-20261028/table-caller-inventory.json`。
- 保留差异：列权限、价格脱敏、公式依赖、历史冻结、首次读取与已有记录保留、分页方向及保存冲突。业务校验、审批阻断、附件原件和打印文档不统一成安全读取重试。
