# ADR-191 禁用货品自动退出当前组装清单

- 日期: 2026-10-22。
- 状态: 已接受；源码实现与隔离验证，服务器应用另行核验。
- 修订: ADR-188 中允许停用组件原样复制、覆盖导入保留的例外由本文取代。
- 关联: ADR-111 主档引用保护、ADR-129 设计与实际用量、ADR-143 BOM 更新、ADR-189 对象历史。

## 问题与核查

货品普通保存、状态命令、批量启停和历史恢复可以分别写入状态。原实现没有在禁用时清理
`goods_bom_items`，物料分析和 MRP 的展开以未软删组装边为依据，因此禁用原材料和半成品仍可
参与展开。原粘贴及导入还允许某些既有停用组件保留，单独限制选择器不能消除这些引用。

## 当前清单

1. 货品状态变为「禁用」时，同一事务软删所有以其为组件的当前组装边，不区分原材料、
   半成品、产品，也不局限于可见的一个父件。使用该组件的每个实际父件都更新。
2. 多层结构按共享的直接关系生效。例如 A 使用 B、B 使用 C，禁用 C 移除 B→C；禁用 B
   移除 A→B。无需删除 A→B 以外的正常组件，也不把 B 自己的配方一并清空。
3. 原行 UUID、设计数量、颜色、价格和来源保留，只设置软删、删除时间和学习释放标记。
   重新启用货品不自动恢复原边。重新使用须在启用后重新维护并核对配方；有权限的显式
   历史恢复仍受当前状态、引用、版本和权限校验。
4. 每个受影响父件重算材料合计并推进版本，即使移除的组件价格为零也推进，避免打开的
   编辑器和旧导入检测结果覆盖新结构。启停请求及关联组装变更沿既有审计和历史触发器捕获。
5. 数据库对所有新建、换件和恢复当前边统一拒绝禁用组件。粘贴和导入提前给出逐行错误；
   有效源边身份也不再豁免停用组件。自动学习排除禁用父件和组件，已退役边不会自动复活。

## 物料分析与历史

新分析从清理后的当前 BOM 展开。旧分析保留原材料行和来源以便核对，在任何深度仍引用
停用货品或失效组装边时给出需刷新诊断并阻止继续新增安排。根产品禁用后也不允许新增安排。
重新启用货品不会让失效组装边对应的旧分析恢复可下达状态。

未外部化的旧节点通过既有刷新流程失活。已经关联采购、委外、自制、专属库存或实物来源的
节点仍执行原有刷新兼容性校验；不能安全重算时拒绝并保留原事实，由原业务取消、释放或
更正流程处理。禁用不修改已有订单、领料、库存、生产冻结用量、报工、实际消耗或历史成本。
最后一个生产硬门禁组件因禁用而移除时，`retirement_reason=COMPONENT_DISABLED` 保留这个原因。
刷新后仍须先维护并核对可用组装信息，不能静默把原来需要材料的产品变成零料生产。
正常人工删料不使用这个标记；已经正常具备无料生产条件的其他产品保持原规则。
仍有有效生产物料或随后建立有效替代配方时记录 `retirement_resolved_at`，保留退役原因，
并避免多年后的正常人工删料又被旧停用记录错误拦截。参考边、出货边和期间料不能冒充替代配方。
V871 旧操作历史未包含这两个新字段。恢复时仅将缺失字段按 NULL 默认值规范化比较，
不重写保留的历史前后事实；非空退役原因或解决时间的后续变更仍须通过原版本冲突检查。

清理事件仍使用 `GOODS_BOM_UPDATED`，携带 `reason=COMPONENT_DISABLED`，不把移除组件当作
「BOM 已完善」来完成研发任务或通知可以下达。

## 事务与迁移

V903 在状态变更前取得货品引用互斥锁，按语句汇总所有禁用货品，在整条状态更新结束后清理。
同一批次禁用父子件不会在原 UPDATE 进行中反向更新同一行。组装写入锁与禁用互斥，遇到
并发锁冲突整笔回滚，保留正常重试入口，不允许留下禁用货品的当前组装边。

迁移同时清理已有禁用组件的当前引用；没有物理删除，不改写旧迁移。迁移只操作当前组装
结构、父件材料合计和版本、更新事件，不更改权限或既有业务单据。具体执行证据见专项记录。
