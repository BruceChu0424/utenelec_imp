# V632 出货放行记账汇率与标准收付款方式

- 迁移：`V632__sales_shipment_finance_release_rate.sql`。
- 口径来源：2026-09-21 用户原话「销售出货 财务那里不是应该审批嘛 然后 应该可以填写汇率 销售收款那里也可以」+「新建销售收款单 选择客户后 为什么收款方式没有自动弹出来 然后点击 下拉框也没有啥显示」；做法对齐金蝶云星空/用友 U8/SAP SD 的通行逻辑(见 [ADR-097](../99-决策记录-ADR/ADR-097-出货放行记账汇率由财务确认.md))。
- 依赖：V443 放行事件表；V511/V578 事件类型；V403 本位币 UUID 权威；V273 收付款方式字典；V631 财审汇率闸门。

| 对象 | 变化 |
| --- | --- |
| `sales_shipment_finance_release_events.exchange_rate` | 新列 NUMERIC(18,6)：本次放行冻结的记账汇率(本位币/1 原币)；CHECK 大于 0 |
| `sales_shipment_finance_release_events.exchange_rate_source` | 新列 VARCHAR(20)：`CURRENCY_MASTER`(币种主档参考汇率预填) / `FINANCE_MANUAL`(财务放行时手工填写)；与汇率列成对 CHECK(同空同有) |
| `sales_shipments.exchange_rate` | 只改注释：语义改为「财务放行时冻结的记账汇率」——草稿不带销售端汇率(应用侧置空)、放行写入、撤回放行清空、仓库确认出库按它折算本币立应收 |
| `finance_payment_methods` | 库里没有任何 `legacy_name_confirmed=true` 的方式时，播种 4 条标准方式：银行转账 `REC-BANK`、现金 `REC-CASH`、支票 `REC-CHEQUE`、承兑汇票 `REC-DRAFT`(固定 UUID `63200000-0000-4000-8200-00000000000N`、收付两用、启用、`ON CONFLICT (code) DO NOTHING`)；不改 V273 三条占位行 |

不加表、不回填历史放行事件(V632 之前放行的单据没有冻结汇率，仓库确认出库仍回落到币种主档参考汇率)、不改保留列数据；`reset_business_data.sql` 版本对 `(632, 588)`。

## 应用侧

- 后端 `SalesShipmentService.financeAudit()`：不再 `requireFinanceRateMaintained` 挡放行，改为 `resolveFinanceReleaseRate`——财务填了汇率以财务为准(大于 0、最多 6 位小数；本位币只能是 1；与主档相同记 `CURRENCY_MASTER`，否则 `FINANCE_MANUAL`)，没填就用币种主档参考汇率(本位币恒 1；主档也没有则 409「请在放行时填写记账汇率」)；放行把汇率写到 `sales_shipments.exchange_rate` 并连同来源写进放行事件；`financeAuditReverse` 与商业内容变更撤回放行时清空。
- `ShipmentFinanceDecisionRequest` 增 `exchangeRate`(可空；批量放行与既有测试走 4 参兼容构造)。
- `finance-audit-info` 增 `baseCurrency`、`shipmentExchangeRate`(已冻结值)、`suggestedExchangeRate`(预填值：已冻结的 > 本位币 1 > 主档参考汇率 > 空)；`financeRateReady` 对本位币恒 true。
- 仓库确认出库 `applyFinancePostingRate`：有放行事件且本单冻结汇率大于 0 时按冻结值立账，否则回落到币种主档(FOR SHARE)。
- 前端出货财务审核页：快照卡「主档参考汇率」只读展示；下方「记账汇率」输入框预填建议值、本位币锁 1、主档未维护时红条提示但不再禁用放行(空着放行会被拦下要求填写)；确认弹窗复述汇率与本单折合本币参考值；已决策单据只读展示冻结值。
- 前端销售收款单：引用应收或选定预收订单后按币种预填「本批汇率报价」(本位币锁 1，主档没有参考汇率时留空由财务按银行回单填)；「收款方式」字典为空时提示并允许先保存(服务端本就允许空)；「引用应收」空列表处一键「改为登记订单预收」并直接打开订单选择。

## 验证

- 单测 `SalesShipmentFinanceRatePolicyTest`：放行汇率规则 6 例(财务填写优先与来源标记、主档回落、主档缺失只在没填时报错、本位币恒 1、位数与正负、币种停用)。
- 契约 `SalesShipmentFinanceReleaseRateMigrationContractTest`(4 例)、`SalesShipmentFinanceRateSqlContractTest`(8 例不变)。
- 真库 `SalesShipmentFinanceReleaseRateEndToEndTest`(Testcontainers，`UTEN_RUN_DB_TESTS=true`)：美金主档汇率 0 时不填即 409、填 7.2 冻结并记事件、撤回清空、主档维护后预填与来源判定、放行 7.25 后主档改 8 不影响出库立账(应收 exchange_rate=7.25、本币 7250)；本位币填 7.2 被拒、不填恒 1；标准收付款方式播种。
- Flutter：`finance_sales_shipment_audit_review_page_test`(汇率框预填/空着放行被拦/填写后随请求提交/本位币锁定)、收款单预填与空字典用例。
