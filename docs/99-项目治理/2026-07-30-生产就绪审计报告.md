## 三、已验证

### 3.1 架构与安全基线

- 后端采用 Spring Security 无状态会话，JWT 仅从 `Authorization: Bearer` 读取，未使用认证 Cookie。当前关闭 CSRF 与该 bearer-only 模型一致，**不是已确认的 CSRF 漏洞**；若未来改用 Cookie 登录，必须重新启用 CSRF Token，并配置 `SameSite`、`Secure`、`HttpOnly`。
- Access Token 源码默认 TTL 为 15 分钟，运行值可被数据库系统设置或部署配置覆盖；V133 会把仍等于旧默认值 480 分钟的设置收敛为 15 分钟，但明确自定义值不会被擅自覆盖。V135 在 staff access JWT 写入用户 `auth_version` 与全局授权 `epoch`，`JwtAuthFilter` 每次请求用一次轻量投影同时复查账号状态和两个版本；直接用户授权、员工换部门、超管/员工绑定变化，以及共享角色、权限和部门层级定义变化会使旧 access token 立即 401。全量回归发现旧实现可能把拒绝响应序列化异常吞入宽泛 `catch` 后继续过滤链；源码已把拒绝分支移出捕获并改用稳定 JSON tree，`JwtAuthorizationVersionTest` 3/3 证明旧/缺版本及序列化路径 fail-closed。开发库已应用 V135且完整 Maven 已通过，但真实 HTTP 覆盖矩阵与性能测试仍未完成。
- `JwtService` 现在要求 secret/issuer 都非空，签发写 issuer、解析用 `requireIssuer` 强制校验；
  prod 必须显式提供环境唯一的 `UTEN_JWT_ISSUER`，dev 默认 `uten-imp-dev`。同一密钥、不同
  issuer 的跨环境 token 拒绝测试已加入；这降低误复用密钥时的环境串用风险，但不替代每环境独立
  密钥、轮换和真实登录/刷新验证。

  缺强一次性密码失败”。

## 六、已知限制与残余风险

- 6 个物化视图的定时刷新已经有源码实现，默认每 5 分钟运行一次；在 V131 应用、多实例锁、刷新耗时、失败恢复和告警通过前，报表新鲜度仍是发布风险。
- V132 只保护新写入或累计值增加，并刻意允许历史超量记录做纠偏减少；它不会自动修复既有异常。应用前后必须先盘点历史违反行，并验证业务层把 SQLSTATE `23514` 转换为可理解的冲突响应。
- V134 提供的是迁移证据和 checkpoint **表结构**，不代表所有模块已有增量 loader、自动对账、reject 回放或 checkpoint 推进；bootstrap 脚本也不得推进未来增量水位。
- V135 的权限版本校验是当前源码机制，不是生产验收结论；旧 token 缺少 `av`/`ae` 时会被拒绝，因此部署必须把数据库迁移、后端切换和会话重新登录纳入同一发布步骤。运行时 access TTL 仍应从目标库核验，不能只看源码默认值。
- 通知列表上限 500 与进程内导出并发上限 2 能控制单实例资源，但不等于 10–20 年规模已经通过容量验证；多实例部署时导出并发是“每实例”而非全平台总量。
- 工资和员工报销已移除固定 500 条截断并建立服务端分页/总数契约；这关闭了源码级静默遗漏，
  V138 与 30,000 报销/5,000 工资 smoke 也给出初步索引证据，但不证明深页性能、权限过滤 count、
  索引膨胀或 10–20 年容量已经达标。
- 访客三队列已分页并接 V139；员工目录虽仍返回 `List`，已限制 50 条且稳定排序。固定资产/
  长期待摊已分页并接 V140。全仓 47 个 List 端点已审计，剩余高风险集中在无界可发行行、
  client/supplier 全量 dict、data-scope owners 静默 LIMIT 200、top-N 无截断元数据，以及若干
  响应集合契约；请求集合已统一加上限但仍须完整 HTTP 回归，详见 P0-12。
- V147 全新库 128 个迁移链和现有开发库 V140→V144 升级都已通过；升级后开发库 835 个约束中
  834 validated、唯一 `NOT VALID` 为历史库存正数约束，1,031 个索引全部 valid/ready。
  长期开发库尚未应用 V145–V147；这些结果仍只证明审计环境的结构与当前快照健康，不能替代
  生产同构或生产发布演练。
  `OFFSET` 深页、索引写放大/膨胀、真实选择性和多租户并发仍需生产同构压测。
- 通用 HTTP 审计记录元数据而不记录请求正文，避免复制密码和 PII；这项安全取舍意味着关键财务/授权变更仍需结构化业务事件或表触发器补充 before/after。

  仅中文，必须把中文限定写入发布范围，并建立新增硬编码文案门禁，不能宣称本地化完成。

  前端常量删除。数据范围不是前端三级选择器，而是后端公共 + 本人 + 显式 owner 授权，
  `client:view:all`/超管全见；文档和新模块不得恢复幽灵权限。
- 销售 finance 专用报表以及生产计划/MRP 的跨 owner 可见性属于跨模块产品决策，不能自动套用销售
  页面 owner 规则；在产品确认、服务端策略和测试完成前保留为发布风险。
- 当前 bearer-only 鉴权下关闭 CSRF 合理；Web 侧更现实的风险是 XSS 后令牌窃取、CORS 误配和
  敏感数据渲染。入口已去内联资源，本地严格 CSP 桌面/移动浏览器验证为 0 错误，但 Nginx 模板

  依赖扫描和前端日志脱敏。
- forward headers 的安全改动不能替代网络隔离：若 8080 可被绕过代理直连，来源 IP、HTTPS
  判定和限流审计仍可能失真；部署门禁必须检查监听地址、防火墙和代理健康检查。
- 阿里云短信 SDK 已接入不等于短信通道可上线；验证码防刷、国内账号权限、模板审核、费用告警、

  “短信已接收、本地事务回滚”，但进程在本地提交后、调用供应商前崩溃仍有极小窗口；严格可靠投递
  需要 outbox worker 与供应商回执/查询。
- 登录主体/IP 桶目前是单 JVM 内存态，多实例生产必须用 Redis 或网关共享状态；V147 只提供独立
  IP 高阈值配置，不解决跨实例一致性。
- PWA 当前不提供离线壳、业务缓存或写入队列，通知也没有真正的 WebSocket/SSE 连接；文档不得把

- Web 原始 `main.dart.js` 为 6,810,382 B、`canvaskit.wasm` 为 7,229,467 B；Nginx 已启用 gzip，

- 旧库中的 `+86`、`0086`、空格或横线手机号必须在迁移时解密、规范化并重新加密/HMAC；仅修改新写

- V146 只保护后续审计写入，不在 Flyway 内无界重写已有 `audit_log`；上线前可清空测试审计，

- 代码未实现“所有审批/转账请求通用签名”，文档不得把它写成已落地安全能力。HTTPS、JWT、服务端授权、幂等键、版本/行锁和审计是当前可验证控制。
- 实验室、流水线/设备与空调控制需明确标识“演示/待接入”，不可进入生产验收清单的已完成功能。
- 六端名称和 Android manifest/signing 源码加固不等于安装包可发布。Android 当前在本机 SDK

  Apple/Linux Release 需对应 runner，详见[多端发布与签名](多端发布与签名.md)和 P0-14。

### 8.3 数据库状态

```sql
SELECT installed_rank, version, description, success, installed_on
FROM flyway_schema_history
ORDER BY installed_rank DESC
LIMIT 10;

SELECT conname, convalidated
FROM pg_constraint
WHERE conname IN (
  'ar_ap_ledger_party_shape_chk',
  'report_mv_refresh_status_chk',
  'report_mv_refresh_duration_chk',
  'accounts_balance_consistency_chk',
  'stock_movements_positive_qty_chk'
);

SELECT pg_database_size(current_database()) AS bytes,
       pg_size_pretty(pg_database_size(current_database())) AS pretty;

SELECT count(*) AS constraints_total,
       count(*) FILTER (WHERE convalidated) AS constraints_validated
FROM pg_constraint
WHERE connamespace = 'public'::regnamespace;

SELECT count(*) AS indexes_total,
       count(*) FILTER (WHERE indisvalid AND indisready) AS indexes_valid_ready
FROM pg_index
WHERE indrelid IN (
  SELECT oid FROM pg_class WHERE relnamespace = 'public'::regnamespace
);

SELECT count(*) AS non_positive_stock_movements
FROM stock_movements
WHERE qty <= 0;

SELECT count(*) FILTER (WHERE fqty > qty) AS finished_over_qty,
       count(*) FILTER (WHERE iqty > qty) AS inbound_over_qty
FROM production_plan_items
WHERE NOT is_deleted;

SELECT view_name, status, last_started_at, last_succeeded_at,
       last_failed_at, last_duration_ms, last_error, refreshed_by
FROM report_materialized_view_refresh_state
ORDER BY view_name;

SELECT target, status, started_at, finished_at, exit_code
FROM legacy_migration_runs
ORDER BY started_at DESC;

SELECT run_id, target, migration_mode, mapping_version,
       reconciliation_status, rejected_count,
       export_manifest_sha256, checksum_manifest_sha256,
       migration_repository_commit, migration_script_sha256
FROM legacy_migration_runs
ORDER BY started_at DESC;

SELECT tgname, tgrelid::regclass AS table_name
FROM pg_trigger
WHERE NOT tgisinternal
  AND (tgname LIKE 'trg_%_guard' OR tgname LIKE 'trg_%_disposition_guard')
ORDER BY table_name, tgname;

SELECT u.id, u.login_account, u.auth_version,
       s.epoch AS authorization_epoch
FROM users u
CROSS JOIN authorization_state s
WHERE s.singleton_id = 1
ORDER BY u.login_account;
```
