- 外贸系列(2682) 的 Number 无法对应到人（老库存疑乱码）→ 判为**公共**，全员可见。

## 二、新库设计

| 件 | 设计 |
|---|---|
| `goods.owner_employee_id`（V85） | 归属业务员；**NULL=公共货品全员可见**。FK employees |
| 权限点 `goods:view:all`（V85） | 「查看全部归属货品（外贸）」；默认不授任何部门（最小授权），超管恒有 |
| **数据范围授权 `user_data_scopes`（V89）** | **中间档**：权限管理页按人勾选「能看哪些业务员的货品」，可见规则 = 公共 ∪ 本人 ∪ 授权归属人；查询期实时生效（无需重登） |
| 可见性规则 | 服务端强制（`OwnerVisibility` 统一判定）；超管/持 `goods:view:all` 全见 |
| 生效面 | `GoodsService.list`（货品列表 + UtenGoodsPicker 选择器同源）+ `facets`（筛选下拉计数） |
| 归属迁移 | `migrate_goods_owner.sql`：6 个老库子树根→B_Worker→employees(legacy_id)，先清零再按分类闭包灌入 |

## 五、边界与后续

- ~~不在过滤范围：`/{id}` 详情与 `/lookup`~~ → 2026-07-28 已补齐：详情/编辑/删除/lookup 全部按归属守卫，
  越权返回 404（不透出存在性），名称解析静默过滤。
- **编辑权**：goods:edit 权限点本身不按归属限制（能否编辑由权限点决定；归属守卫只挡「看不到的不能碰」）；
  如需「能看全部但只能改自己的」再细分编辑范围权限点。
- **客户资料侧**：B_Client.Emp_ID 同构（客户已有归属人字段源），客户列表按人隔离可直接复用本模型
  （owner 列 + view:all 权限点 + Service 过滤三件套）→ 已落地（V86，见 36）。
- **HR 换人**：归属挂 employees.id，员工离职/接手只需改 goods.owner_employee_id（批量 UPDATE 即可）；
  HR 真员工替换 stub 后 legacy_id 不变，归属迁移重跑不断链。
