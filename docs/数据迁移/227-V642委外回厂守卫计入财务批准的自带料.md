# V642 委外回厂守恒守卫计入「财务已批准的委外商自带料」

- 日期：2026-09-21
- 决策：[ADR-101 委外单一子层级按到货解锁、分批发料与容差自动结案](../99-决策记录-ADR/ADR-101-委外单一子层级按到货解锁与容差自动结案.md)
- 目录变化：V640/592 → **V642/593**(V641 留给并行会话)。不加表、不加列、不动触发器。

## 一、为什么改

用户口径：**「超过就是得通知财务」**。

委外回厂原本有两道数量闸，顺序上先撞的是守恒那道：我方发了 1000 个子件，就只能交回
1000 个委外件；委外商送回 1050，服务端抛

> 委外目标件尚未足额出仓且无足够IQC失败返修额度，禁止超量回仓

并整笔回滚。仓库看不懂这句话，收货单建不出来也审不了；财务那边**完全不知情**，既没有
到货异常待办也没有通知卡。仓库只能少登记或改数，多出来的实物就落在账外——这恰恰是
「超收要通知财务」想避免的局面。

多交回的那部分在物理上只有一个解释：**委外商贴了自己的材料**。那是价格与归属问题，
该由财务定案，不该在仓库登记页面上被一句看不懂的话挡回去。

## 二、改了什么

**守恒本身不放开**，只是把「财务已经批准的那份自带料」从守恒台账里摘出去——它不是我方
发出去的料，本来就不该参与

```text
同源实际发出 = 合格产出对应实际耗用 + 实际材料退回 + 明确损耗 + 供应商剩余
```

这个等式。锚点补丁 `fn_assert_subcontract_target_outbound_receipt`，把

```sql
v_received := v_received - v_replacement;
```

换成再扣掉一份**自钳位**的财务批准额度(`procurement_arrival_exceptions` 里
`decision IN ('APPROVE_ALL','APPROVE_CUSTOM')` 的 `approved_excess_qty`，按订货换算率折成
目标件基本量)。状态取 `RECEIPT_ADJUSTED / RECEIPT_POSTED / CLOSED` 三种：本守卫是 DEFERRED，
在 COMMIT 时才跑，那时 `recordApproval` 已经把异常从「财务已调整」推进到「已入库」或「已结案」，
只认 `RECEIPT_ADJUSTED` 会在提交那一刻正好取不到额度。

- 取 `LEAST(额度, GREATEST(v_received - v_replacement, 0))`，所以它永远抵不过台账上
  真有的量，`v_received < 0` 那条兜底(红冲 / 错账)仍然有效；
- 没有财务批准时额度为 0，两道守卫(`subcontract_target_outbound_first_guard`、
  `subcontract_target_outbound_consumption_guard`)一个字节都不放松，所以不会出现
  「不知道料从哪来」的库存。

V638 补上的 `PREPARED_OUTBOUND` 合计与 V581 的激活条件必须原样留在补丁结果里，
迁移里各有一条断言钉死；对不上宁可失败(23514)，不猜形状。

## 三、配套的服务端改动(不在本迁移里)

| 落点 | 改动 |
| --- | --- |
| `ProcurementArrivalControlService.arrivalCapacity` | 委外行的到货上限再压一档「我方实际供料折算量」；被它压住时 `ArrivalCapacity.materialBound = true` |
| `ProcurementArrivalControlService.validateBeforeApproval` | 被供料量压住而超出时，拦截文案改成「回厂数量超过我方发给委外商的材料能做出来的数量，多出来的部分用的是委外商自己的材料；本次未入库、未立应付，已转交财务审核组确认价格和归属」 |
| `SubcontractReceiptService.approve` | **顺序反过来**：到货异常闸先跑(它抛的是不回滚的 `ProcurementArrivalBlockedException`，异常记录照常提交、财务照常收到通知)，守恒闸留在后面兜底 |
| `SubcontractReceiptService.requireTargetOutboundCapacity` | 额度里加上 `financeApprovedExcessBase`，否则财务批准完这张单仍然审不过去，等于把财务的批准作废 |
| `SubcontractReceiptService.lockAndRequireDraftOutboundCapacity` | 登记草稿时不再因「超过物理上限」拒收(实物已经到厂了，拦下来只会让它落在账外)；仍然拦的只有「物理上够、但额度被同明细另一张未审草稿占住」这种并发冲突 |

## 四、存量影响

- 已审核的回厂单、已结案的到货异常、历史 LEGACY 手工发料行：一个字节不动。没有新流
  发料计划的订货明细(`plan_item` 不存在)本来就不受这条物理上限约束，口径不变。
- 尚未批准的到货异常(`PENDING_FINANCE`)：`approved_excess_qty` 为空或 0，额度为 0，
  行为与迁移前一致。
- 已经因为这条守卫被拒过的收货单没有留下任何记录(整笔回滚)，需要仓库重新登记一次；
  这一次会正常建单并转财务。
