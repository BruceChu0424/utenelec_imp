## 一、与货品/模具/客户资料「同构但分表」

供应商用 **`supplier_categories` + `suppliers`**，独立成表，与 material/mould/client 物理隔离（理由同 [05](05-模具资料-新库与迁移.md) §一）。「同级」体现在前端 hub。

## 二、新库表设计

### 2.1 `supplier_categories`（分类树，Flyway `V37__supplier_category.sql`）

与 `material_categories`(V31) / `mould_categories`(V33) / `client_categories`(V35) 字段逐一相同。老库业务形状是 **15 个扁平根**；V272 另加迁移种子为 `legacy_id=-1` 的系统“未分类”根，目标为 16 根。V275 候选把其实际 UUID 登记进固定注册表；普通在线逻辑不以旧整数、名称或内部 code 识别该根。

### 2.2 `suppliers`（主档，Flyway `V38__supplier.sql`）

逐字段照搬老库 `B_Provider`（29 字段），起清晰列名（见 [08](08-供应商资料-老库溯源.md) §2.3）：

```
id(UUID PK) · legacy_id(INT UNIQUE=B_Provider.ID) · category_id(→supplier_categories)
name(Vend_Name) · code(Number) · description(Vend_Desc 避保留字) · place(Vend_Place)
emp_id(Emp_ID) · legal_person(Juri_Per) · linkman(Link_Man) · mobile · phone · phone2 · fax
postcode(Post) · address(Link_Addr) · email · website(Http) · ship_via(Shipvia) · ship_address(Ship_Addr)
bank(Vend_Bank) · bank_account(Vend_BankNo) · tax_id(Tax_ID)
init_total/init_total2(期初应付) · exchange_rate(CRate) · tday(TDay) · price_style(PStyle)
status(使用/禁用) · remark
审计4列 · is_deleted · deleted_at
```

- `category_id` 由 `B_Provider.ParentID → SystemItem.ItemID`(ItemclassID=3) 反查；源端 386 条全部命中。V272 仍设系统根承接财务迁移可能生成的 `LEGACY-FIN-SP-*` 占位，并将目标列收紧为 NOT NULL。
- 索引：`category_id` / `legacy_id` / `code` / `status`。

## 五、正式离线导入与开发样例

| 路径 | 用途 | 文件 |
|---|---|---|
| **Shell（正式离线链）** | 分类 + 主档 | `migrate_supplier.sql`、`migrate_supplier_data.sql`；完整切换由 `migrate.sh --bootstrap-all` 编排 |
| **Java（仅 dev）** | classpath 分类样例 | `com.uten.imp.legacy.migration.SupplierCategoryMigrator`（ItemclassID=3） |
| **导出** | 老库 → CSV | `export_legacy.ps1 SupplierCategory/SupplierData` |

### 5.1 设计要点

- **扁平根入库**：15 个 ItemclassID=3 全是 `ParentID=0`；脚本另无条件重建稳定的系统“未分类”根。
- **受控替换**：Shell 在单事务中先删供应商主档，再删普通分类并保留 V275 系统根；任何未知下游 FK 会使事务回滚。它不使用 `TRUNCATE`、`CASCADE` 或禁用约束，也不是在线增量同步。
- **全部分组**：源 386 条无悬空；受控财务旧库导入产生的历史占位绑定 V275 固定注册表中的 `supplier_category_id`，所有运行态供应商均要求非空分类；在线写入不得按 `legacy_id=-1`、名称或 code 猜根。
- **管道符转义 + GBK**：同客户（见 [07](07-客户资料-新库与迁移.md) §5.1）。

## 七、迁移校验（实测，2026-07-24）

```sql
-- V272 目标：15 个业务根 + 1 个系统未分类根
SELECT count(*), count(*) FILTER (WHERE parent_id IS NULL), COALESCE(MAX(level),0)
FROM supplier_categories;

-- 主档对账
SELECT count(*) AS total,
       count(category_id) AS linked,                            -- 386
       count(*) FILTER (WHERE category_id IS NULL) AS ungrouped,-- 0
       count(*) FILTER (WHERE status = '使用') AS in_use,        -- 237
       count(*) FILTER (WHERE status = '禁用') AS disabled       -- 149
FROM suppliers;

-- 抽验挂载
SELECT c.code, c.name, COUNT(s.id) FROM supplier_categories c
JOIN suppliers s ON s.category_id = c.id
WHERE c.legacy_id IN (2309,2301,2694,2945) GROUP BY c.code,c.name;
-- 表面处理类=55 / 五金类=48 / 塑胶件=5 / 玻璃面板=5
```

**V272 前历史演练结果**：分类 15/根 15/深 0；源供应商 386（已挂 386 / NULL 0 / 在用 237 / 禁用 149）。现行候选目标为 16 根、NULL 0；`migrate_finance.sql` 可能动态追加并挂载 `LEGACY-FIN-SP-*`，最终总数须按本次源库对账。

## 八、前端（与货品/模具/客户资料同级）

- `/basicinfo` → 基础资料 hub：货品 / 模具 / 客户 / **供应商** 卡片入口。
- `/basicinfo/supplier` → **供应商资料页**（`SupplierCategoryPage`）：左分类树 + 右分类详情 + 该分类下供应商分页 + 供应商详情弹框（编号/名称/描述/分类/地区/业务员/法人/联系人/手机/电话/地址/收货地址/银行/税号/期初应付/状态/备注 等）。复用 `UtenCategoryTreeView` / `CategoryEditDialog` / `UtenLocationField` / `ProductCategoryNode`。
- **统一关联搜索（2026-08-14）**：左树顶部同搜分类名称/编号与供应商编号、名称、描述、联系人、法人、地区、手机；前端逐页收集全部 `categoryId`、展开祖先并驱动右表同词结果，财务占位也可定位系统“未分类”根。详见 [基础资料页](../03-页面/基础资料页.md) 与 [UtenHierarchySearch](../02-组件库/UtenHierarchySearch.md)。
- **分类驱动编号与 UUID 身份（V257–V279 候选）**：供应商分类维护可编辑 `code_prefix`，供应商编号为空时取最近祖先显式前缀、全空回退 `GY`；手工编号和自动编号都进入 V279 全局完整标识终身保留。前缀/父级变化须先预览确认再批量改号；采购、委外、财务及普通 CRUD 绑定分类/供应商时只提交 UUID，不按供应商编号、名称或 `legacy_id` 生成关系。
- 列表项：title=供应商名、subtitle=`code · 地区 · 联系人`、trailing=状态 chip。
- 工作台「基础资料」卡片指向 `/basicinfo`（hub）；**财税部原「客户资料」「供应商资料」两张占位卡片已移除**（基础资料独占这两个入口，采购/账户占位保留）。
- **主档维护（supplier:edit）**：详情弹框带「编辑/删除」按钮；分类详情面板「新增子分类」旁有「添加供应商」按钮，弹出通用 `MasterEditDialog` 表单，提交后调 POST/PUT/DELETE 并刷新分页。
- **子页返回 / 白屏修复**：与客户页同——返回键显式回基础资料 hub（非工作台）；详情弹窗 `Navigator.of(context)` 漏 `rootNavigator:true` 致点行后白屏，已修（见 [07](07-客户资料-新库与迁移.md) §八）。
