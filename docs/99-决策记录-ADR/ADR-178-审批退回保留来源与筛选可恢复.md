# ADR-178：审批退回保留来源与筛选可恢复

- 日期：2026-10-11（客户端 America/Denver）
- 状态：本地源码候选；业务数据库仍为 V853，未部署或运行岗位验收。
- 关联：ADR-052、ADR-066、ADR-100、ADR-143、ADR-171；V854。

## 背景

采购原订货单财务退回后仍可以编辑、重提，但申请剩余量只扣除 PENDING 订单，
同一份来源需求重新回到申请待分解。本地只读样本 CD20261012000001 有两条退回明细，
实物合计 5002.5；CS20261012000001 与 CS20261012000004 分别重新显示 2.5、5000 待分解。
与此同时异常子分类依红数自动选择“财务已退回”，隐藏进行中的其它状态。

## 来源承诺

1. 未删除、status=0 的采购/委外订货单，最新财审轮次为 PENDING 或 REJECTED 时，
   来源份额继续占用申请。财务退回是原单修订任务，不创建第二份需求。
2. 原单修订使用保存后的有效来源份额；减量释放差额，重提不重复占用，重复退回也不翻倍。
   采购保持收费量、赠品量和实物合计的既有口径。未提交普通草稿延续原规则。
3. 明确撤回财审、取消或删除时，由既有状态机和有效来源事实决定释放；历史审批记录保留。
   已批准订单仍按原已分解计数与反审规则计算，不能同时再加草稿承诺。
4. Java 分解预览/FIFO/来源修订容量、SQL 待分解投影与委外齐套计算共享最新轮次函数。
   V854 只修复读取规则，不重写历史迁移、业务份额或库存余额。
5. 容许超采等既有业务规则保持；禁止以简单“订货量不得大于申请剩余”替代正确来源分配。

## 页面设计

| 页面/维度 | 决策 | 原因 |
| --- | --- | --- |
| 采购任务工作台、委外任务中心 | 删除财务已退回异常子分类；状态列继续显示与筛选退回 | 同一事实只提供一个筛选入口；进行中默认完整列表 |
| 委外订货列表 | 删除进行中的财审状态子分类，移至可清除的状态列 | 大类保持进行中，列头选择待财审/退回/执行中 |
| 逾期、短交等独立异常 | 保留手动选择和显式全部，autoSelectBadge=false | 逾期与审批状态正交；短交是有独立动作的处置案件 |
| 仓库领料单出库进度 | 删除重复子分类，移至可清除列头 | 等仓库/部分出库/全部出库已是行状态 |
| 品质检查结果来源+状态 | 保留来源与真实作业状态；默认全部状态，二级不自动选择 | 来源和作业阶段是两种信息，不能一刀删除 |
| 追加用料、超产比例申请 | 单层状态入口增加全部 | 已有服务端 ALL，用户可以从退回恢复完整查询 |
| 销售单据表头状态 | 清除必须实际取消状态限制；订货保留业务大类，其它类型显式全部 | 清除不能无效，也不能悄悄跳到历史视图 |
| 财务审批历史 | 保留各轮 case 与只读历史 | 审批轮次历史不等于原业务单的最新当前状态 |

本次覆盖 ADR-066 对上述筛选页“无全部”以及 ADR-100 对退回异常子分类的旧规则。
工作模块、来源、物理作业类别仍保留已有导航；不全局改变 UtenFilterToolbar 的默认定位。
待办红数继续来源于真实待修订任务，删除重复子分类不能让待办消失。

实物结案不等于财务复核办结。已批准改量的最新 PENDING/REJECTED 优先于实物 closed：
仍列进行中、显示明确复核阶段，财务退回仍计红数；既有实物结案/数量/库存保持，
批准后才回已结案历史。财审列表段及计数覆盖活动订单 status=0/1，排除取消/反审终态。

## 其它显示不变量

- 空筛选结果保留筛选/清除入口，不能误报没有任何业务数据。
- 分页列表不得用当页桶和当页数据伪装全量筛选；使用服务端已支持的筛选。
- 同仓库/同页面快速换筛选，也必须以请求代数判定响应；旧成功、旧失败不能覆盖新结果或加载态。
- API 返回数组时读取数组接口，不能经过 Map 解包丢失真实记录。

## 验证与边界

针对原单退回、部分量、多物料、赠品、重复重提、取消/删除、筛选恢复和迟到响应增加回归。
