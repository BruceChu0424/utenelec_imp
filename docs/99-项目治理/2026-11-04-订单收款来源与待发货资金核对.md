## 最终业务口径

| 入口或字段 | 权威与含义 |
| --- | --- |
| 出货收款 / 选出货单 | 每行明确选择实际出货批次的有效应收 UUID（`appliedLedgerId`），再填本次真实收到的金额。新行金额留空，不把还欠自动写成已收；同客户多批须分别选择并明确各批金额。 |
| 货款 / 已收 / 还欠 | 来自本批唯一有效正式应收；已收为已审核收款毛额加已实际抵到本批的定金，费用、减免、退货及其他抵款分别保留，不拿客户累计或订单计划款冒充本批实收。 |
| 部分收款 | 本批货款1000，本次实收400，审核后本批已收400、还欠600；后续只对该批收600才结清。未发生的尾款、到账约定和未抵的定金不减少本批还欠。 |
| 订单预收（定金/多付） | 人员明确选择订货单并填写真实金额；与出货收款是不同用途。已完成且已审核、未删除、未中止的订单允许记录真实多付，不恢复履约、不确认收入、不自动挪给别单。中止/撤销订单不接受新定金；其真实已出货AR尾款仍可按批收取。 |
| 用定金抵款 | 复用预收实际应用，明确抵到所选本批应收；不再记一次收款。预收1000实际抵本批735后，本批已收735、还欠0，剩265仍为原客户/原绑定订单预收。 |
| 银行净到账 / 费用 | 客户结算200、银行费10、实际净到账190分别记录；本批结算已收200，银行账户真实增加190，不能混成同一数。实际入账时间必须已经发生，未来草稿可以保留但不得实际审核入账。 |
| 订单资金辅助 | 订单汇总包含未发货计划，`未收计划（辅助）`不作本批催款依据。未分配客户预收单独受权限保护，既未抵本批就不算本批已收。 |
| 可选订单分配 | 只有人员明确选择辅助订单时才写 `requestedSalesOrderId`，且须与所选同一批AR的真实来源相符。普通批次收款保持NULL；绝不跨不同出货AR自动FIFO选款。 |
| 历史独立来源 | 受核直接出货AR及已核验独立期初AR继续按真实来源办理，原来源编号展示为原来源，不编造订货单或出货单。 |
| 即时库存 | 货品选择器复用服务端批量良品现存合计，含各颜色，不含不良品仓和车间内料仓，不扣订单预留；与可用量有明确区别，未下发不当零，新增列放原业务列之后。 |

没有新增「还欠即自动禁止发货」政策，仍由已有财审、授信及仓库闸门决定。逾期依据本批真实到期日和业务日；没有新增虚假的承诺付款或催收记录域。

## 权限与历史依据

- 出货来源准备是收款创建/编辑能力的有限只读范围，不开放全公司AR查询。全财务角色可按既有职责引用公司合法来源；普通人员只能引用销售对象范围内的真实出货。实际创建与更新仍各走原权限。
- 新建及新增/替换来源必须经同一服务端源权限；更新从服务端原始 `(订单,ledger)` 关系识别保留来源，财务交接编辑原绑定不强套新销售owner。审核/反向沿用原财务单据范围，不额外套审核员销售owner。
- 新客户预收继续要求原 `customer_prepayment:view` 和 `finance:view:all`，且真实绑定订单；普通收款不要求该全账权限。
- 现有订单/出货财审角色可读本对象有限资金；仓库作业不透传金融字段。客户累计到账仅在另有权限后折叠为辅助，不作为本批资金。
- 财审放行的资金依据保存于当时事件。刷新读原历史，不随后续收款改写；旧事件缺字段保持未知。普通出货详情不透传私有 `print_context`，仓库打印按明确字段清单生成且不含资金投影。
- 所有当前资金读取外层使用RR，批量自调用包装也覆盖；port检测实际隔离级不足时整批未知，不使用 `REQUIRES_NEW` 或新增反序锁。
