## 一、页面结构（2026-09-12 起自上而下：摘要 → 履约进度（折叠）→ 产品进度（沉底））

1. **订单摘要卡**：单号（titleLarge 放大）+ 单据状态徽标（草稿/已审核/已红冲）+
   开单日期/交货日期/制单员（bodyMedium 放大一档）+
   财务状态徽标（待财务确认/财务已确认·确认人/财务已驳回）+ 已结案/已中止徽标。
   当前财务驳回时显示原因、审核人和业务发生时间；处置双出口（2026-09-05 起）收敛到
   右下悬浮操作组：「修改订单」（修订重报，`sales_order:edit`）与「取消订单」（终止处置，
   `sales_order:cancel`，且无发货/无排产在产完工关联才开放——与订货单详情页
   「取消订单」同一后端 `POST /sales/orders/{id}/cancel`；取消即清驳回态并置中止，
   订单转入历史记录「已中止」）；入口仍受服务端对象归属与权限约束，不以按钮显隐替代授权。
2. **履约进度（默认折叠）**：[`UtenProgressTimeline`](../02-组件库/UtenProgressTimeline.md)
   快递式时间线，数据源 `GET /api/sales/orders/{id}/progress-timeline`。
   **最新进展永远在最上面**并高亮（描边卡 + 「最新」徽章），历史节点按时间倒序，
   灰色虚位的未来阶段（PENDING）垫底。2026-09-12 起整卡默认折叠（UtenCollapsibleSection），
   标题行常驻「最新：阶段 · 时间」状态胶囊（与最新节点同色系），点标题展开完整时间线。
3. **产品进度（页面底部）**：复用 [`SalesPlanProgressPanel`](../../lib/features/sales/widgets/sales_plan_progress_panel.dart)
   （2026-09-12 版式统一；2026-09-13 起不再提供「本次发货数量」输入列）：宽屏为可多选
   产品表，窄屏为逐产品卡片；展示订货、已排、已生产入库、已发、本次可发、办理中和
   生产入库进度，并可打开该行进度来源。
   同一面板也内嵌销售订货单详情（旧宿主保留自带工具条）。可发使用后端 `shippableQty`，
   扣除办理中的出货，不用预留量或报工量冒充可发实物。卡片继续显示未排和剩余量
   （未排 = 服务端 `unplannedQty`，2026-09-10 V545）+
   物料分析状态 + 生产计划溯源与执行子计划深链（`production_plan:view` 才可跳）。
   **V300 财务闸门不变**：`financeConfirmed=false` 时本区替换为「等待财务审核」提示，
   不展示任何排产事实。

**交互口径（2026-09-13 修订）**：
- **右下悬浮操作组**（UtenFloatingActionGroup，全站详情/批量页统一）：
  「已选 N 项」胶囊（一键清空勾选）+「修改订单」（可修订时）+「取消订单」（驳回单），
  红色大按钮「去发货(N)」放最右（2026-09-13 用户口径；多选批量发货，未选时灰显、
  点击提示先勾选）。面板经 `SalesShipmentActionScope` 上报勾选数/忙碌态，动作由面板执行。
- **刷新在 AppBar 右上**（UtenAppBarActionButton，整页口径：摘要+时间线+产品进度
  三段全部重读）；面板内不再有「刷新产品进度」按钮与「全选可发产品/已产口径」说明文字
  （全选走表头复选框）。下拉刷新保留。
- **「本次发货数量」输入列已下线**（2026-09-13）：表格只展示「本次可发」；去发货按
  各行可发量预填跳转出货页，实际发货数量在出货单明细里填写（出货页仍做 ≤可发 终校验）。
- **表格行单击只切换勾选**，不再弹进度弹窗；弹窗只由「查看进度」列按钮触发。
- 订单可写、已审且已获财务确认、未中止或结案，并拥有 `sales_shipment:view/create` 时
  可发货。新建出货页再次核对订单行 UUID 与当前可发量，预填所选产品和数量，允许减少本次
  数量；打开、选择和返回不创建单据。明确保存才创建出货草稿。产品来自多个实际库存来源时
  由服务端分成多张单据，回执仅列业务单号。销售不选择或查看内部仓库和库位；仓库执行仍
  核对实际仓与库位。所有出货仍须财务放行后才进入仓库办理。

三个数据源（detail / plan-progress / progress-timeline）并行加载、独立错误提示，
互不影响（速度优先，不串行等待）。产品表独立缓存本次读取，勾选不反复请求；
刷新、从出货页返回后重读并清除旧选择。
开单使用独立幂等键；网络回执不确定时保留并锁定原内容，仅可同键重试。
多单创建后的暂存附件按各真实出货 UUID 绑定，附件重试不重复建单。

## 二、履约进度时间线事件口径（服务端组装）

> 责任人统一显示实际姓名（`EmployeeNameResolver.nameOf`）；内部员工工号、账号代号不在
> 履约时间线中展示。

| 阶段 | 责任人来源 | 时间来源 | 状态规则 |
|---|---|---|---|
| 销售下单 | `sales_orders.maker_id` | `created_at` | 恒 DONE |
| 销售审核 | `approver_id` | audit_log 状态迁移（0→1），缺审计则只显示人 | status=1 DONE / 0 CURRENT / -1 REJECTED（红冲） |
| 财务审核通过 | `finance_confirmed_by` | `finance_confirmed_at` | DONE；最近一次驳回即使已经修订/确认，也保留一条历史 REJECTED 事件（含原因/人员/时间） |
| 计划单物料分析 | `production_material_analyses.maker_id` | `analyzed_at` | 每份分析一条 DONE；说明使用“进行中 / 部分已下达，剩余待料 / 已全部下达 / 已取消”等中文业务称谓，不直出内部枚举代号；无分析时按财务闸门给 CURRENT/PENDING |
| 物料准备-采购/委外订货 | 订货单 `maker_id` | 订货单 `created_at` | status=1 DONE（detail 带财务审批人）/ 0 CURRENT（审批中）/ -1 或审批驳回 REJECTED；可点单号跳订货单详情 |
| 生产计划下达 | 计划 `maker_id`（detail 带审核人） | 计划 `created_at`，已审改用 audit_log 0→1 时间 | status=1 DONE / 0 CURRENT / -1 REJECTED |
| 生产中 / 生产完工 | 派生聚合（无单一责任人） | 无 | 已产>0 → CURRENT/DONE；detail = 已产/订货 |
| 销售发货 | 出货单 `maker_id`（detail 带发货审核人、物流单号） | audit_log 0→1，缺则 `handed_over_at`/`created_at` | status=1 DONE / 0 CURRENT / -1 REJECTED；可点单号跳出货详情 |
| 订单中止 / 结案 | — | — | REJECTED / DONE |

排序由服务端完成：已发生事件（DONE/CURRENT/REJECTED）按时间倒序、无时间的当前阶段置顶；
PENDING 占位按业务顺序垫底。前端不重排。

时间线单号可点跳转（按权限点拦截，无权限顶部提示）：
`SALES_SHIPMENT→/sales/shipments/:id`、`PURCHASE_ORDER→/purchase/orders/:id`、
`SUBCONTRACT_ORDER→/subcontract/orders/:id`、`PRODUCTION_PLAN→/production/plans/:id`、
`MATERIAL_ANALYSIS→/production/material-analysis`。

## 三、阶段通知核对（既有链路，未改动）

订单每进入一个阶段的通知由 `ChainNoticeService`（business_outbox 可靠旁路）覆盖，与本页时间线同一事实源：

- 销售审核通过 → 通知财务确认（`notifyOrderPendingFinanceConfirmation`）
- 财务确认 → 通知计划员物料分析（`notifyOrderFinanceConfirmed→notifyOrderApproved`）；
  财务驳回 → 定向通知归属销售（`notifyOrderFinanceRejected`，urgent 强提醒，关闭回执与已读分离）
- 物料齐套/备料 → `notifyMaterialAnalysisReady`（采购/委外人员仍须从任务中心下单，通知不自动下商业订单）
- 排产 / 报工 / 完工入库 / 发货 / 出货驳回 / 取消 / 延期预警 → `notifyPlanScheduled` 等既有事件

财务驳回后的“修改订单”不是对已审核订单直接放开普通写入：保存落点锁定订单/明细，校验无下游
发货、排产或完工，释放预留并按 UUID 软版本修订后回草稿；重新销售审核才重建预留并回财务待确认。
