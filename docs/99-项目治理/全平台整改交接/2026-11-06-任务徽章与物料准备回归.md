# 任务徽章与物料准备回归

候选分支 `uimp/task-material-regressions-20261106` 从本地 `main` 的 `bad2ed660` 起步。历史对照为 10 月 7 日的 `4c9f8dc89`，公司测试候选对照为 `e157c9757`（v2.5.48）。公司截图用于定位业务入口，当前公司部署版本、权限及真实数据时延仍需现场核验。

## 多端与验收

Web 与现有 Flutter 桌面端共用以上界面和加载逻辑。Win7 WPF 的现有工作台读取 `/dashboard/overview`，本次涉及的任务中心、物料分析、委外领料及登记编辑入口按 [原生任务台账](../../../clients/windows_legacy/progress/work-items.json) 记录迁移状态。服务端的精确物料、来源和权限合同适用于后续原生接入。

本地委外单只读复核得到目标 10000、基础单耗 1、含损耗单耗 1.1、备料上限 11000 和库存 10000。旧算法先按 1.1 向下求得预算覆盖 9090.9090，再乘回并按领料精度取整为 9999.9999。基础产出覆盖、按预算覆盖和实际领料量分别验证。

真实 PostgreSQL 测试中，首单合格 800 个并认损后，全齐套父工单仍为等待，原来源缺口 200。追加委外件的合格 200 入库后原工单转可领，原预留合计 1000，公共可用未重复增加。原委外单仍有有效待交余量时，这 200 仍是原单供给承诺。跨仓补料以原分析来源权益、入库仓和操作权限决定归属。

锁定依赖下 Web release 构建通过。定向 Flutter 测试包括 129 项日报编辑及契约、独立实称重量回归、63 项读表与列布局及创建回执、5 项分桶与实际下单量。日报称重用例核对 0.005 kg/基本单位和报工换算率 2，确认 12.5 kg 得到 1250，取消确认后原数量仍可继续编辑。日报迁移 `V1113` 增加空值兼容的单重和称重口径字段，已有单据的历史重量保留原值。最终 Java 日报组 38 项通过，包含真实 PostgreSQL 的主档改重后保留历史称重依据和创建回执。BOM 复制 35 项定向测试及 1 项 PostgreSQL 链路通过。

本地定向验证包括首次直接进入采购和产成品入库、晚到权限、切范围时丢弃旧请求、分桶实际任务计数、500 个产品的响应性、取消/分段失败恢复、单重列旧布局迁移、委外原料 10000 的精确领料、1000→800→200 齐套链及日报称重保存。Windows Flutter Chrome 测试器在运行用例前遇到路径转义及本地 CanvasKit 加载问题。Win7 进度工具在本地 main 与候选分支均报告已有业务源清单漂移，本轮只记录对应原生条目的迁移边界。公司旧电脑上的操作时延、公司补单原单及 Win7 真机需分别验收。
