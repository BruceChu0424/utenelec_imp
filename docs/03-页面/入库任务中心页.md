## 一、页面与权限

- 路由：`/warehouse/tasks/inbound`（路由名 `warehouse-inbound-tasks`）。
- **进入权限（任一满足）**：`warehouse_inbound:view`（预计到货/到货异常）、
  `stock_doc:view`（产成品/其它入库）、
  `warehouse_purchase_receipt_history:view` / `warehouse_subcontract_receipt_history:view`
  （对应收货历史）。
- 动作权限沿用各业务域：到货登记在预计到货详情内执行（登记页要求
  `warehouse_inbound:stock_in`）；批量入库/点收要求 `stock_doc:approve`；
  一键入库要求 `warehouse_inbound:stock_in`。服务端独立兜底。
- 页面权限面：`warehouse.inbound-tasks`（V450）。

## 二、页面结构

对齐品质部检查结果页范式：**进页面不预选大类**（内容区显示「在上方选择分类后
开始办理」引导空态，不加载任何分段数据）；各分段的小类行只随选中的大类出现
（结构上等价于大类未选时小类锁定）。

1. **页级工具条**：大类分段 + 胶囊搜索（关键字下发当前分段）。徽章只挂
   真实待办（**草稿不计入待办数**）：
   - 采购入库徽章 = 采购来源预计到货数 + 到货异常数
     （`/warehouse/inbound/expectations/type-counts` 的 PURCHASE +
     `/warehouse/inbound/arrival-exceptions/count`）；
   - 委外入库徽章 = 委外来源预计到货数（SUBCONTRACT）；
   - 产成品入库徽章 = 待点收任务数（`/warehouse/production-finished-in/tasks/count`）；
   - 其它入库不挂（只有草稿与历史）。
2. **采购入库段**：小类分段 = 预计到货（挂采购来源待到货徽章）｜到货异常
   （挂待办徽章）｜收货历史（终态不挂）。
   - 预计到货：embedded `WarehouseInboundExpectationsView(fixedOrderType: PURCHASE)`
     ——2026-09-05 起双击按到货步骤直达办理页（待登记→登记实际到货页 /
     继续送检确认 / 到货异常 / 品质检查结果；原到货详情中间页已删除）；
     仓库不凭空
     新建采购收货单，一切登记都来自预计到货任务。**2026-09-03 支持多选批量送检**：
     「已登记 · 待送检」任务可勾选（采购/委外两段共用），一次把所选任务挂着的
     全部草稿收货单在一个事务逐张送品质部待检（单张超量隔离不回滚其他单；
     后端 `POST /api/warehouse/inbound/arrivals/batch-complete`，
     同幂等键重试时已完成单按既有事实安全重放）。
     **2026-09-17 多选「先入库后质检(N)」**：与「先质检后入库」(2026-09-20 前叫
     「批量登记送检」)并排的第二个
     批量动作（V596 独立权限），待登记行直达批量登记页并预置先入库后质检
     模式（`?preStock=1`，库位逐行必填），详见
     [仓库到货登记页](仓库到货登记页.md)。
   - 到货异常：embedded `WarehouseArrivalExceptionsView`——财务定案后按批准量
     一键入库（可多选批量，原子事务）。
   - 收货历史：embedded `WarehouseDocumentHistoryView(purchaseReceipt)`（只读实物视图）。
3. **委外入库段**：小类分段 = 预计到货(SUBCONTRACT，挂待到货徽章) |
   收货历史(subcontractReceipt)。
4. **产成品入库段**：小类分段 = 待点收任务（挂待办徽章）｜产成品进仓单
   （不挂——草稿不计入待办数）。
   - 待点收任务：embedded `ProductionFinishedInboundTasksView`（FQC 放行上限队列，
     可批量全量点收；短收/拒收逐单处理）。
   - 产成品进仓单：`WarehouseStockDocSegment(FINISHED_IN)`。
5. **其它入库段**：`WarehouseStockDocSegment(OTHER_IN)`。
6. **通用单据分段**（FINISHED_IN / OTHER_IN）：不渲染 icon+标题分段头；状态小类 =
   全部/草稿/已审(历史)/红冲，**进页面不预选**（空集 = 不过滤），各段不挂徽章
   （草稿不计入待办数）；全部分类栏最下方为总结行（左「共 N 条 · 双击办理」、
   右新建按钮按 `stock_doc:create` 门控）。

## 三、角标口径

hub「入库任务中心」卡徽标 = 预计到货(全部来源) + 到货异常 + 产成品待点收
（`WarehouseInboundTaskBadge`，草稿不计入）；工作台仓库卡 =
三张任务中心卡之和。分段徽章按来源拆分（见上），加载中不显示半程合计，
失败显示异常图标。

## 四、业务口径与边界

- 到货登记一步完成（登记+送检同事务）；超量自动隔离待财务定案，不入库、不生成应付。
- IQC 链路不变：合格切片进「品质部检查结果」页，仓库确认实物与库位后才增加库存
  （两阶段库存合同见[品质部检查结果页](品质部检查结果页.md)）。
- 不合格实物退回登记后，原订货单的预计到货按合格净量重开等待供应商补货
  （待收 = 应到 − 已收 − 已退回不合格；补货收货走原订单授权，V466 口径详见
  [品质部检查结果页 §六a](品质部检查结果页.md)）。
- 产成品入库先登记成品仓与库位并送检，品质放行后按实物最终点收；
  仓库实收前不增加 `iqty`。
- **各分段表头列筛选（2026-09-16）**：预计到货段「供应商/委外商」列（主档 dict 桶，
  回传 `supplierId`）；到货异常段「供应商/仓库/状态」三列（供应商/仓库=dict 桶、状态=固定枚举）；
  待点收任务段「任务步骤/仓库」两列（任务步骤=固定枚举、仓库=dict 桶）。桶值与各分段既有
  服务端筛选参数同型，选中即重拉回第 1 页。
