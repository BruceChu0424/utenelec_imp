# 品质逐行入库与委外出仓验收

本次处理委外品质合格后入库报“仓库 UUID 不能为空”、单详情与批量逐行核对供应商/委外商和实际仓库，以及委外出仓加载与成功返回任务中心。设计见 [ADR-079](../99-决策记录-ADR/ADR-079-品质放行逐行实际入库仓与委外成本来源.md)，数据库变化见 [V563](../数据迁移/159-V563品质逐行实际入库仓.md)。本记录表示本地源码和隔离测试结果；未更新现有业务数据库、重启业务服务或部署。

## 修复及行为

- 报错来自委外正常损耗成本用可空订单仓库构造成本池。首次真实产出确定稳定成本对象，后续跨仓收货复用原对象；早于产出的真实正常损耗保留原 COST_WIP 并在首次产出分配。历史订单和成本不回填、不改写。
- 单详情和批量页共用明细表，逐行显示来源单据、供应商/委外商、单位、合格待入量、本次实收、实际目标叶仓及库位。待检和不合格行只读。更换仓库清空旧库位并要求重新填写；同仓及普通刷新保留输入。
- 新请求显式传实际仓库，数量、来源、剩余量、权限和仓库状态统一校验。原收货及质检仓只作快照；真实库存、来源权益和库位学习均使用实际入库项。分仓入库后红冲扣回实际仓，价值退回原品质登记池。
- 委外出仓当前选择全部成功后返回出库任务中心“委外 / 待办”并刷新。部分失败或响应未确定时保留现场核对，已确认成功的单据不重复执行。
- 加载仅等待所需仓库字典，与任务/草稿并行读取；独立读取最多四路，同一计划/草稿去重，多草稿转批量页复用已读资料，员工姓名后台补充。后端相同草稿数量聚合只算一次；三条可见计划行的 PostgreSQL 实际执行聚合循环由 6 次降到 3 次，详情 SQL 请求总数仍为 3。本轮没有给出网络端到端耗时承诺。
