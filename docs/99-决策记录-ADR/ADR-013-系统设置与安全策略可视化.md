# ADR-013：系统设置（安全/业务策略可视化与动态生效）

> 日期：2026-07-27 · 状态：已实施（mvn compile/test BUILD SUCCESS + flutter analyze 0 error；运行时冒烟待重启后端）
> 前置：[ADR-012](ADR-012-报表加密导出与列排序与行跳源头.md)（导出限流/:export）· 原则：安全首位、最小权限、敏感操作二次确认

## 背景

安全/业务策略阈值（登录限流、账号锁定、密码历史、导出限流、令牌 TTL、短信验证、导出行数上限）原本硬编码在
`SecurityProperties` / `JwtProperties` / `SmsProperties` + 导出 `100_000`，管理员无法在线调整，需改 yml + 重启。
管理员要求在「系统管理」页可视化配置这些次数/时长，且**配置页本身要全方面安全**（普通用户不可见、不可访问、不可篡改）。

## 决策

### 1. system_settings 表（运行时可配项，V72）

- 只放**运行时可生效的策略阈值**（11 项：安全 5 / 令牌 2 / 短信 3 / 业务 1）。
- **排除密钥类**（jwt.secret / crypto / sms AK——涉密钥、轮换走 env/Vault）与**部署类**（CORS / swagger / DB / legacy——启动时定）。
- 字段含 `label/description/unit` 方便前端表单渲染；`updated_at`（触发器维护）+ `updated_by`（审计追溯）。

### 2. 动态读取（SystemSettingsService，不缓存）

- `readInt(key, def)` / `readLong(key, def)`：**每次 findById**（表仅 11 行 PK 查询亚毫秒），管理员改设置**立即生效**，无缓存一致性延迟。
- 各安全组件改读 settings 替代硬编码 Properties：LoginRateLimiter / ExportRateLimiter（令牌桶阈值动态，变更后下次 check 重建桶）、LoginService（lockout）、PasswordService（密码历史）、JwtService（access TTL）、RefreshToken×2（refresh TTL）、VisitorSmsService（短信 3 项）、6 处导出上限。

### 3. 全方面安全（配置页核心）

- **路由守卫**：`/admin/` 前缀统一要求 `user:manage`（`permission_by_path.dart`）→ `/admin/system-settings` 仅超管可达；工作台入口卡片按同权限显隐，**普通用户看不到入口**。
- **`@PreAuthorize('user:manage')`** Controller 级二次校验。
- **二次密码确认**（`SystemSettingsService.write` 验证当前账号密码）：即使 access token 被盗，改安全策略还需账号密码——防令牌泄露导致策略被恶意篡改。
- **审计**：每次改设置记 `update_system_setting`（谁/哪项/旧→新值），审计页可查。
- **类型/非负校验**：后端 + 前端双重，防恶意值。

### 4. 前端页（UI 精心）

`admin_system_settings_page`：按 4 类分组卡片（安全策略/登录令牌/短信验证/业务限制）+ 改动跟踪（dirty 高亮）+ 批量保存 + 二次密码弹框 + 危险操作警告横幅 + 上次修改时间。

## 验证与残留

- mvn compile + test（6 测试，含限流 3）BUILD SUCCESS；flutter analyze 0 error。
- 运行时冒烟（待用户重启后端跑 V72）：改 `lockout_minutes` → 登录失败用新阈值锁定；改设置在审计页查 `update_system_setting`；非超管访问 `/admin/system-settings` 403；输错二次密码 BAD_CREDENTIALS。
- 残留：prod HTTPS（反向代理）；导出限流单机内存桶（多实例换 Redis 共享）。
