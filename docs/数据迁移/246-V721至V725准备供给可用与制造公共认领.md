# V721–V725 准备供给可用与制造公共认领

## 原因

物料准备把可采用公共在途限定为已审核商业订单。实际已经下达的采购/委外申请尚未办理时，公共余量为 0，造成重复下单。自制计划公共产出没有跨分析认领证据，无法保证页面显示可用之后的真实交付归属。

用户口径：下多少显示多少；可用包括现货、在途和已下达但未办理的量，其它订单可以采用剩余供给。实际库存、领料和开工口径保持以实物为准。

## V721

新增 planning 容量/余量函数，使真实未办理采购和委外申请的公共份可认领，保留原 approved 商业在途口径。供给被认领后正常商业订货、财务批准和实收入库仍沿原来源办理；取消、减量及竞争认领均执行来源容量守卫。不加表，不迁移重写旧数量，不把申请量写成库存。

## V722

新增只追加的 `preplan_make_public_claims` 与 `preplan_make_public_claim_cancellations`。制造公共承诺以真实计划明细为来源，目标分析和目标物料均有外键/维度/仓库约束；撤回只能释放尚未实收的余额。

`preplan_analysis_stock_exact_pegs.make_public_claim_id` 是第三种来源锚点，与原供给分摊和自制锚点互斥。成品实收先按真实私有额度和公共额度分片；公共认领建立原库存预留、exact peg 和权益事件。原 PUBLIC 不能继承私有身份的限制继续成立，只为有独立 claim 证明的来源开放精确实收。

来源供给状态统一从真实计划公共份、实收、认领和撤回计算。来源取消或减量不得留下未履约认领；普通 UPDATE/DELETE 不能修改承诺历史。合法红冲重新恢复尚未实收的承诺，已转正式领料或耗用的实物仍需先恢复原权益。

两张表登记为业务 CLEAR、审计 NONE/ledger。操作人、时间、幂等键和只追加事实构成自身审计证据；没有新增平行库存台账。

## V723

在目标分析的精确实收权益经过原释放链合法释放且无下游耗用/剩余受益权益后，追加关闭认领承诺。源入库以后红冲不会重新恢复已取消目标的认领；仍有正式占用或已耗用时保留既有反向守卫。没有新增表，不修改已应用 V721/V722 的字节。

## V724

采购/委外公共认领原先整张分析排斥，导致联合分析中产品 A 的公共余量不能给 B 使用。改为按真实原受益人和向实际承载节点传递的别名方向识别自我认领；同分析的独立原需求可采用公共份，不因后来进入同一合单任务就把兄弟原行误作自身。普通源使用真实私有来源；新合单源使用 CREATE/APPEND 不可变事件里的逐原行/逐目标私有份额，校验原范围、维度、两份证明一致及私有总量。历史缺完整证据的合单继续采用保守边界。实际认领保留原受益人，实收沿既有 ORIGIN 与精确委托链交到当前承载节点。前向修改现役延迟校验，其仓库、货品、路线、单据、容量、并发及反向约束全部保留；不新增表、不改写旧供给数量。后来合单不能追溯取消此前合法认领；仅新建、改身份、增量或重启已取消认领重新证明来源。整体取消释放全部认领后允许源容量归零，仍保留对其他有效认领的总容量守卫。

## V725

V725 在 V724 已由其它运行流程安装到共享业务库后前向补强 CREATE/APPEND 的逐原行和逐目标私有份额证明，缺少完整历史证明时继续保守处理。另补齐未办理采购/委外申请在认领激活后的私有在途：公共份被其它产品采用，不能让来源产品已经下达的私有份消失。仅计划 pending 读取包含仍有效的未办理申请，商业审核和真实库存条件不放宽；不重算或改写旧单数量，不新增表。

同时修正普通自制计划的合单继承：`production_material_analysis_plan_links.submitted_qty` 已经是私有份额，不能再减 `public_surplus_qty`；继承读取按真实单位倍率转为基本量，原计划和单据数量不改。

计划读取使用单独的私有容量和来源余量函数，把有效未办理申请加入原已审核私有量；实际私有转让准入继续使用原已审核容量函数。真实委外申请即使货品含 BOM，也不能因原转让准入中的 BOM 限制而漏掉自己的私有在途。

## 安装与回退

只执行新迁移，所有已应用迁移字节不变，禁止 `flyway repair`。本模块新增至 V725，并行模块还会增加迁移；源码目录不代表现场库已安装。当前库版本须读实际 `flyway_schema_history`，其 baseline 行不计入 SQL 文件总数。

升级前保存可恢复的完整备份并停止业务写入；在隔离副本确认迁移、源码和数据契约后再安装。回退应恢复成套数据库与对应旧制品，不能在已经产生新认领/实收事实后直接删除新表或切回不能识别来源的旧程序。

## 验证

隔离业务链需要覆盖：采购/委外申请未办理余量、认领/撤回、超量及并发争抢、后续商业审核、实收按来源分账；普通及合单自制的公私混合产出、先公共后私有、分批与重复实收、下游正式预留、合法红冲、已耗用拒绝以及源取消/目标取消约束。

具体候选日志与通过结果记录在[准备模块修复记录](../99-项目治理/2026-09-26-物料准备统一流程修复.md)，不能以迁移成功代替业务链通过或用户验收。
