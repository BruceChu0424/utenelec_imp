# V738 手工需求单多货品

- 日期：2026-09-27；该迁移引入时本工作树源码目录为 V738/664(V735-V737 在其它会话在途，合并时按真实目录重算)，当前头以[迁移索引](README.md)为准。
- 迁移：`V738__manual_demand_multi_goods_lines.sql`。
- 设计：[ADR-130 手工需求单多货品与新建物料分析页表格化](../99-决策记录-ADR/ADR-130-手工需求单多货品与新建物料分析页表格化.md)；触发器拆分写法同 [ADR-106](../99-决策记录-ADR/ADR-106-热表触发器按相关列起跳与索引卫生.md) 与 V734。

## 改了什么

手工需求(返工、试制、样品、备库、其他)改成像一张小订单：一个需求编号下可以挂多个货品行，与所选销售订单行一起联合分析。V234 建、V529 重建的 `uq_production_material_analysis_manual_source_ref` 对全部非销售来源按 `(source_type, lower(btrim(source_ref)))` 全局唯一，一个编号在全库只能有一行，也就只能有一个货品，所以要拆。

| 对象 | 变化 |
|---|---|
| `uq_production_material_analysis_manual_source_ref` | 删除 |
| `uq_production_material_analysis_system_source_ref` | 新建。`(source_type, lower(btrim(source_ref)))` 唯一；未删除，来源类型不是销售行与五类手工类型，且排除 `SUBCONTRACT_PREPARATION` 的 `SC-ORDER:%`(同 V529)。所有系统来源编号仍全局唯一：自制备料 `MAKE_COMPONENT`、委外自制 `SUBCONTRACT_MAKE` 在生成编号前做「编号可用」探测并换码重试，依赖此索引；共享制造 `AGGREGATE_MAKE`(「共享制造 日期 批次号前 8 位」)与委外前置 SC-PREP(`SC-PREP:` + 订货行 id)靠构造保证唯一，没有探测，由此索引在数据库层兜底 |
| `uq_production_material_analysis_manual_source_line` | 新建。`(source_type, lower(btrim(source_ref)), goods_id, color_id, unit_id) NULLS NOT DISTINCT` 唯一；只覆盖未删除的 `REWORK/TRIAL/SAMPLE/STOCK/OTHER` 行。同一编号下同一货品(货品 + 颜色 + 单位)只占一行 |
| `fn_guard_manual_demand_single_analysis()` | 新建。先取事务咨询锁，键文本 `'MATERIAL-ANALYSIS-MANUAL-REF:' \|\| 类型 \|\| '\|' \|\| lower(btrim(编号))`，与服务端 `lockSourceIdentities` 逐字一致；再查同类型同编号(忽略大小写与首尾空格)的其它未删除手工行是否属于另一份分析，是则 SQLSTATE 23505 拒绝，提示「需求编号 X 已属于另一份物料分析, 同一需求编号只能在一份物料分析里; 请换一个需求编号」。查询条件写死五类手工类型，走上一行的部分索引 |
| `trg_guard_manual_demand_single_analysis` | BEFORE INSERT，WHEN 未删除的手工行；ENABLE ALWAYS |
| `trg_guard_manual_demand_single_analysis_upd` | BEFORE UPDATE，WHEN `(analysis_id, source_type, source_ref, is_deleted)` 有变化且为未删除的手工行；ENABLE ALWAYS，与 INSERT 条同一启用模式(热表卫生契约) |

不加表、不加列、不改存量数据。新规则严格宽于旧索引(旧规则下每个编号全库只有一行)，存量数据不可能违反，因此不回填。

## 为什么这样做

- 保留 ADR-029「一个(来源类型, 需求编号)只属于一份物料分析」：只把旧索引加宽成「编号 + 货品」会让同一编号的不同货品落进两份分析；并发的 {X:A} 与 {X:B} 两个请求也会各建一份。守卫触发器在数据库层兜底，服务端先按同一锁键加锁，同编号请求在两处都排队。
- 系统来源编号不能跟着放宽：自制备料与委外自制的编号可用探测只按类型 + 编号查，必须仍全局唯一；共享制造与 SC-PREP 编号没有探测，全靠构造唯一，这条索引是它们在数据库层唯一的兜底。
- 没用排他约束：库里没有 `btree_gist`。没用需求单表：ADR-130 决定手工需求保持页面本地输入，新表要连带审计登记、清库分类、主档引用登记与一套读写接口。
- FQC 品质恢复自动建的返工来源(`FQC-RECOVERY-` 编号，单货品)同样受新索引与触发器约束，行为不变。

## 核对 SQL

```sql
-- 1. 索引：旧索引已不存在，两条新索引存在(期望 2 行，没有 manual_source_ref)
SELECT indexname, indexdef
FROM pg_indexes
WHERE schemaname = 'public'
  AND tablename = 'production_material_analysis_items'
  AND indexname IN ('uq_production_material_analysis_manual_source_ref',
                    'uq_production_material_analysis_system_source_ref',
                    'uq_production_material_analysis_manual_source_line');

-- 2. 触发器：两条都在且为 ALWAYS(期望 2 行，tgenabled = 'A')
SELECT tgname, tgenabled
FROM pg_trigger
WHERE tgrelid = 'production_material_analysis_items'::regclass
  AND tgname IN ('trg_guard_manual_demand_single_analysis',
                 'trg_guard_manual_demand_single_analysis_upd');

-- 3. 一号一分析：期望 0 行
SELECT source_type, lower(btrim(source_ref)) AS demand_ref,
       count(DISTINCT analysis_id) AS analyses
FROM production_material_analysis_items
WHERE is_deleted = FALSE
  AND source_type IN ('REWORK','TRIAL','SAMPLE','STOCK','OTHER')
GROUP BY 1, 2
HAVING count(DISTINCT analysis_id) > 1;

-- 4. 同编号同货品重复：期望 0 行
SELECT source_type, lower(btrim(source_ref)) AS demand_ref,
       goods_id, color_id, unit_id, count(*) AS lines
FROM production_material_analysis_items
WHERE is_deleted = FALSE
  AND source_type IN ('REWORK','TRIAL','SAMPLE','STOCK','OTHER')
GROUP BY 1, 2, 3, 4, 5
HAVING count(*) > 1;

-- 5. 上线后观察：带多个货品的手工需求编号
SELECT source_type, lower(btrim(source_ref)) AS demand_ref, count(*) AS goods_lines
FROM production_material_analysis_items
WHERE is_deleted = FALSE
  AND source_type IN ('REWORK','TRIAL','SAMPLE','STOCK','OTHER')
GROUP BY 1, 2
HAVING count(*) > 1
ORDER BY goods_lines DESC
LIMIT 20;
```

## 回退与部署边界

- 迁移只能前向。`DROP INDEX` 不带 `IF EXISTS`：库不在 V529 之后的预期形状时直接失败，不静默跳过。
- 应用回退到 ADR-130 之前的版本可以直接跑在 V738 库上：旧页面一个编号只录一个货品，旧服务端写入同样满足两条新索引与守卫触发器，已存在的多货品编号仍可按分析行正常读取、下达和追溯。
- 若要恢复旧的全局索引，只能另写前向迁移，且前提是核对 SQL 第 5 条返回 0 行(没有任何多货品编号)；已有多货品编号时不能恢复，也不应为此拆改业务数据。
- 迁移头同步点：[迁移索引](README.md)头行与表格行、`server/ops/reset_business_data.sql` 的白名单对与上界文字、`BusinessDataResetSqlContractTest` 的硬编码对；引入时本工作树为 `(738, 664)`；与 V736 统一合并后为 `(738, 665)`(V735、V737 跳号)。
- 源码验证不代表业务库已安装；部署以服务器更新记录为准。
