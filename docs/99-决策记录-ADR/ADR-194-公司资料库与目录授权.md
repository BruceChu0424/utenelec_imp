# ADR-194：公司资料库与目录授权

- 状态：实现与本地验证中；不代表服务器已经部署或业务 UAT 通过。
- 需求：常用功能增加公司文件模板、制度及内部文档的集中入口；按文件夹授权、密码保护、可恢复管理，并复用私有原件存储。
- 依据：ADR-074 原件与存储、ADR-109 权限目录、ADR-045 页面内授权、ADR-110 敏感再认证、ADR-181 有效权限。

## 身份与存储

入口名称为“公司资料库”，常用功能默认顺序为基础资料、公司资料库、我的报销、工资条、意见箱。资料库目录与文件拥有不可变 UUID，显示名称不参与物理对象定位。目录树、说明、排序、权限、删除批次在 PostgreSQL；文件字节进入统一 `COMPANY_FILE` 附件 owner，复用隔离、扫描、摘要、大小校验和精确原件保留。

文件先预留资料库身份，再按统一 `presign -> raw PUT -> confirm` 完成附件扫描确认，最后关联已确认原件。预留失败不得伪装成上传成功；发布成功后禁止以同一身份覆盖原件，需要上传一个新文件。待确认项仅发起者可见，退出或失败时可保留原请求回执恢复，不能因重试重复建文件。

未完成占位不会因客户端关闭而自动证明失败。具有有效查看、目录权限管理和删除权限的普通资料管理员，可在目录 ACL 和密码均满足时查看并回收他人遗留占位，释放有效同名和目录数量；不要求超级管理员身份，也不赋予代他人上传、发布或下载能力。回收继续保留记录及已经扫描确认但尚未发布的原件。

实际部署使用现有独立 NVMe 媒体卷 `/var/lib/uten-imp-media/attachments`，不另写系统根盘、应用发行目录、Web 静态目录或旧 `/data/uten-imp/attachments`。磁盘保留、I/O 并发、待上传配额、ClamAV、备份继续使用统一附件合同。只读现场结果、配置差异和防止未挂载误写根盘的启动门禁见[资料库存储运行说明](../../deploy/company-files/README.zh-CN.md)。

## 两层授权

全局权限独立区分 `company_file:view/download/upload/create/edit/move/delete/restore/manage_permissions`。`view` 是入口和元信息权限，文件内容预览与下载另需 `download`。新建文件夹、上传、整理、回收、还原和授权均需各自动作；不能凭上传权删除或覆盖已有文件。

权限目录将这九项归入常用模块的公司资料库，并绑定同一个 `common.company-files` surface。总权限页面与模块内页面权限入口读取同一服务端目录；页面内授权只能委派当前制度允许委派的权限，不能造另一份独立开关。

目录 ACL 按用户或部门设置允许/拒绝，包含九个动作。生效条件为全局动作权限和目录 ACL 同时满足；禁止通过知道 UUID、搜索、面包屑、详情、回收站、预览或统一附件原件 URL 绕过。祖先拒绝持续生效，子目录允许不能冲破祖先拒绝；停止继承从显式允许开始。部门成员包含现有组织关系及上级部门关系。每次请求重新读取目录策略，不用短期前端缓存证明未撤权。

成功读取 `GET /api/company-files/{id}` 的资料元信息后，Controller 才通过统一 `AuditDetailViewRecorder` 记录 `view_company_file_detail`，对象类型为 `company_file_nodes`，对象 UUID 取实际返回结果。审计只保存“公司资料”类型标签，不复制文件名、说明、原件身份、目录权限或商业字段；鉴权、目录 ACL、受保护祖先或对象查找失败不能产生成功查看事件。仅查看元信息不要求下载权限，受锁目录自身可读标签的现有规则保留。真实操作者归属、会话去重和通用 GET 事件抑制沿用统一审计器，不额外写下载或编辑事件。

移动校验源对象及整棵子树、目标目录的动作权限，目标还需接收该类型的创建/上传权限。删除目录须对整棵活动子树逐一授权，任何一项拒绝则整次回滚。隐藏对象不能通过批量重排被修改。敏感目录授权和密码变更复用本人登录密码再认证；超级管理员恢复授权只解决自锁，不自动授予文件内容下载。

## 密码与会话

目录密码只存 BCrypt 哈希，审计快照不复制哈希。新密码至少 8 个 Unicode 字符且不能全为空白，超过 BCrypt 72 字节 UTF-8 上限明确拒绝，不静默截断；只有显式传入 null 才清除密码。散列并发有界，错误尝试按账号与目录限速。

解锁凭证在服务端内存保存，绑定账号、服务端会话、目录、密码 revision，十五分钟到期。切换账号/会话不能继承解锁，密码变更立即失效，重新锁定撤销本会话能力；重启后需重新解锁。解锁能力不替代当前 ACL。父目录未解锁时不能用已知子目录/文件身份泄露内部名称或原件。

## 并发、回收与边界

目录变更通过事务锁串行处理结构与 ACL，普通对象编辑使用版本回执防止覆盖他人的更新。数据库补充父目录合法性、循环、深度、有效同名、原件身份不变等约束，客户端输入校验只改善体验。

回收站逻辑删除目录和同批子项，不清除原件，使用删除批次避免还原父目录时复活此前独立删除的内容。还原重新检查父目录、目标权限与同名冲突；不得静默覆盖现有内容。没有永久清空入口。

单目录最多 500 项，目录最多 32 层，单次子树命令最多 5000 项，授权规则最多 100 项，列表按页返回；资源上限超出时明确说明。长按拖动有移动和手动排序替代菜单，所有交互仍由服务器验证，不依赖拖动本身证明授权。

## 界面原则与验证

前端默认应用 `frontend-design`，保留 Uten 深绿/青绿品牌、主题 token、字体、页面容器、顶部通知和轻量动画。资源管理器的重点是紧凑操作区、可扫描的文件区、明确当前位置及按需详情，不在文件区堆叠装饰统计卡。图标、平铺和详情视图为同一对象列表的呈现方式，授权结果保持一致。

完整布局与交互见[公司资料库页面](../03-页面/公司资料库.md)。验证应覆盖真实 PostgreSQL 约束与事务、上传下载字节一致、独立动作与目录 ACL、受密码保护的上层目录与跨会话绕过、失败队列恢复、并发冲突、回收批次、窄屏/深浅主题/大字号和服务挂载门禁。每次交付单独记录本地、CI、发布、服务器激活及业务验收状态。
