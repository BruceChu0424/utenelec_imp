# ADR-119 底层自制实际领料与 BOM 累计学习

- 日期：2026-09-24。
- 状态：本地实现与隔离测试；未部署到公司业务库。
- 初始迁移：V709 / V710 / V711；2026-09-26 追加 V726 支持车间选填材料申请快照、V727 支持已知材料申请与普通领料单原子批量出库、V731 支持独立 LQ 领料申请号。当前源码目录见迁移总索引，编号迁移尚需按上线流程安装。
- 更新 ADR-057/096 的无 BOM 自制开工规则，以及 ADR-118 的初始超产比例默认值。原审批、库存、品质、成本与产出归属规则继续适用。

## 1. 使用流程

物料分析准备、下单、下达仍按现有操作。没有有效底层 BOM 材料的 DIRECT_MAKE 自制任务需要领料，不能再把“材料尚不明确”解释成“不需要材料”。新任务及无报工事实的未开工原始旧任务进入材料发现门禁；已开工及已冻结拆批历史保留原证据，不追造领料或改写空批次快照。

1. 车间在“我的车间任务”点去领料，使用项目自有表格核对工单，可按工单选填一种或多种材料及申请数量，编号、规格、颜色、单位和参考库位自动带出。材料和数量均可不填；已选材料必须有基础单位，已填数量必须为正数且最多四位小数。只产生正式申请，不扣库存，也不自动开工。
2. 仓库现有“生产领料 / 待领任务”包含该申请。领料材料列只显示真实材料；没有材料时红底显示“需要填写”，已预填时显示材料名称及“待核对领料”。父件独立显示为“用于生产”，不能拿父件充当领料材料。同源列表、分页、待办数量和通知包含该申请。“我的仓库”包含尚未定仓的申请；指定某个实际仓的筛选仍只看已定仓任务。
3. 未知材料从“填写实际领料”登记；已知材料直接进入原批量出库详情，自动带入材料、颜色、基础单位和已填数量，不要求重复选料。仓管与领料人核对并补齐正数量、实际叶仓。批量页须保留申请中全部货品、颜色、基础单位，可调整数量或将同材料拆到多个实际叶仓；需要换料时回实际领料页办理。单位沿货品基本单位，千克和个使用相同的数量输入，不增加独立重量字段；每份申请正式配置最多 100 行。
4. 未知材料登记保存时，原子生成正式材料需求、精确预留、DRAW 和车间领料授权，随后沿原领料单审核并实际出库。已知材料的批量确认则把配置、审核及实际出库放在同一个事务内，也可与正常 DRAW 混选。任何材料不足、单位无效或版本冲突都回滚当前整笔或整批，保留输入；不能由前端逐笔配置成功后再另发批量出库请求。
5. 真正领料后才能开工，后续实际报工、用料、余料退仓、品质、成品入库及红冲沿已有链路。

尚未确定材料时不能证明分批齐套。原任务若选了分批，先选择持续或齐套生产来登记材料；有真实物料后再按原分批约束办理。错误提交但尚未配置的申请可取消并重提，已配置的真实库存事实不得通用删除。

首次材料发现沿用 `BUY` 的现货库存供给路径，不新增采购、自制或委外供给责任，也不改所领货品的 `source_type`；学习保留真实货品、颜色和单位，后续计划按货品自身的正常路线办理。

### 2026-09-26 车间预填与仓库接续

每个工单单独保存申请建议，不能把多个工单的同名材料合并后丢失归属。V726 的 `requested_materials JSONB NOT NULL DEFAULT '[]'` 保存最多 100 行不可变车间申请快照；未选材料保存空数组，已选材料保存货品、可空颜色、基础单位、可空数量及服务端读取的展示资料。相同货品和颜色在车间建议中只保留一行，申请不指定实际仓。详情通过 `suggestedItems` 返回，正式 `items` 继续只代表仓库已配置事实。预填不创建物料需求、预留、领料单、耗用或 BOM 边，仓库确认后才沿原配置事务办理。申请数量可空，仅选择材料也能提交，仓库的正式配置仍要求完整正数量和实际叶仓。

幂等意图包含工单、提交版本以及规范化后的材料身份和数量，保留旧空材料请求摘要兼容。相同行顺序变化或数量末尾零不构成新意图，同键改料、改量或改版本须拒绝。多工单按各自版本依次提交，已成功项不重复；响应不确定时保留原输入及同一请求键核对重试。同人同键返回原申请身份及编号；已有有效申请时换用新键提交，返回 `409 CONFLICT`，不另取号、不递增工单版本、不生成需求或改变数量。仓库首次加载待办时带入建议，重新核对待办结果不能覆盖仓管已修改的材料或数量；已完成时以正式配置结果为准。原申请快照与仓库实际配置分别留痕。

仓库材料详情与正常领料详情统一使用 `MasterDataTableView`。选择物料后自动带出名称、编号、规格、颜色、基本单位和参考库位；这些主档信息只读显示，未登记的显示“—”，不让操作人重复填写。颜色列保留，实际颜色身份随材料带入；重选同一材料不会悄悄改成默认颜色，换材料或单位后清空旧数量。领料数量、实际发料仓和用于生产的产品继续独立列出。材料、正数量和实际叶仓为正式配置必填项，用表头星号及行内错误明确提示；用于生产的产品由工单带入，不能由仓管随意改写。参考库位或货品归属仓不能代替本次实际发料仓。多种材料不跨单位或颜色合计数量，待办仍按申请计数。

### 2026-09-26 已知材料申请并入正常批量出库

已知材料但尚未填写数量或实际仓的申请可以多选，与正常 DRAW 一起进入原“批量出库详情”页，单独打开已知材料申请也进入此页。沿用 `ProductionDrawDetailTable` 的正常领料格式，在材料对应的数量及实际发料仓单元格补信息；缺项标红框，货品资料及用于生产的父件自动显示。申请号与正式领料单号分列：申请行显示真实 LQ 号，尚无正式 DRAW 时正式单号显示“—”。原普通领料单仍显示真实 SL 号，并按已申请未发量批量出库，不改其既有数量口径。

不知道材料的申请继续从“填写实际领料”选择材料。批量勾选包含未知材料时，明确提示先完成选料，不静默丢掉这些任务。已知材料数量可空的状态不影响选择，进入页面只读取，填完红框并确认后才写入。

混合批次由 `POST /api/stock/docs/issue-discovery-batch` 的一个后端事务完成：先校验整批权限、版本、材料和库存来源，预锁全部生产计划及库存范围，再为申请生成精确需求、预留和 DRAW，最后与已有 DRAW 一起审核并实际出库。普通单使用真实 DRAW UUID，材料发现使用真实申请 UUID 和申请版本，两种身份不能混用。缺库存、过期版本、取消、无权操作或任一明细失败时，整批回滚，不留下半笔配置或成功批次账。合计最多 50 个来源任务，按实际仓生成后的正式单据总数也不得超过 50；每份申请最多 100 行，同料同实际仓不得重复，跨叶仓拆行保留各自数量和仓身份。材料发现路径需要仓库查看、审核及出库权限。

V727 的 `production_draw_issue_batches` 在成功事务中保存操作人、完整规范化意图、原始成功结果和真实 DRAW UUID 集合。服务端独立生成批次 UUID 并据此派生内部实发命令，防止旧外部接口提前占用内部键；成功回执前核对整批已请求量均已实际发出。同人同键重复确认依据冻结成功结果返回重放回执，不再次出库；更改材料、数量、仓库、申请版本、来源成员或备注后复用旧键须拒绝。重放也先复核当前有效岗位及查看、审核、出库权限，不能借成功历史绕过权限入口。出库取消后再重放原键也不能再次发料；换新批次键提交已配置申请同样须拒绝。客户端响应不确定时冻结原参数，保留原键重试。批次账是命令证据，不是第二份库存或 BOM 数量账；进入页面、填写红框、预留和失败批次不产生学习贡献，成功实发仍须等待下文规定的真实耗用与产出闭合后才参与学习。

### 2026-09-26 申请号 LQ 与正式领料单号 SL（V731）

`production_material_discovery_requests.id/request_no` 标识车间领料申请；`stock_documents.id/bill_no` 标识实际仓的正式 DRAW。两者各自拥有 UUID 和业务编号，不复用、不改名，也不把 ZX 工单号当作任何一方的单号。

申请提交成功后取得 `LQ + 上海日期 YYYYMMDD + 六位日流水`，命名空间为 `PRODUCTION_MATERIAL_REQUEST`。号码沿 V279 全局业务编号命名空间、日流水与永久占号登记生成，申请号唯一且不可修改。同一申请与同键成功重放保留同一个 LQ；撤回申请及业务清空不释放号码。V731 为已有待处理、已撤回和已配置申请按创建时间的上海日期补号，只填写原先缺失的 `request_no`，不改申请 UUID、材料快照、正式 SL、库存或学习历史。回填通过狭窄的历史守卫例外，并在改表约束前实际校验待执行的延迟来源约束，不禁用触发器；号段冲突或日流水超过 999999 时拒绝并回滚，不截断或重用旧号。

一份申请可以先有零张、配置后按实际发料仓关联一张或多张 SL。关联沿 `production_material_discovery_lines.demand_id → production_planning_package_document_items(document_type='DRAW') → stock_documents` 查询，不以单号字符串或父件名称猜配。请求详情的 `requestNo` 显示 LQ，`drawDocuments` 逐张返回正式单据 UUID、SL 号、仓库 UUID 和仓名；原 `drawDocIds` 保留兼容。若正式单据映射到多份申请，来源申请号按真实映射完整去重列出，不取第一份冒充唯一来源。

待领列表以“申请 LQ…”明确标识尚未配置的申请，正式单保持 SL 为主单号，另列来源 LQ；详情与混合批量表将申请号和正式单号分开。详情可按每张 SL 及实际仓打开正式单据。旧接口未提供号码时显示“—”，不在客户端拼号；跳转仍使用各自真实 UUID。编号只增加识别与追溯，不触发出库、开工或 BOM 学习。

正式 DRAW 的列表、计数、状态、列筛选值及仓库筛选共用真实单据明细映射投影，按 `stock_document_items` 的有效申请量、实际已发量与未发量归组到该张单据及实际仓。不能从一笔需求只挑首张单，也不能把整笔需求量重复放进每张跨仓单：同一申请分两仓 2 和 3，应有两张 SL，各自显示 2 和 3，合计仍为 5。原单据权限、需求有效性和取消/退回量口径继续适用；尚未配置的 LQ 分支不虚构实际仓。搜索同时保留申请号、正式单号、ZX 工单号、实际材料及用于生产的产品。

车间确认页顶部只保留红框红字的选填提醒，材料、数量不清楚仍可提交给仓库补充；工单、计划、车间及提交状态独立成列。读取和提交使用统一 `UtenBusyOverlay`，由执行网络请求的目标页持有，完成或失败后撤除；入口页不跨导航保留遮罩。动态错误与权限提示继续保留。

## 2. 学习口径

每个实际生产族保留一份当前贡献。族沿既有成本来源关系包含拆批与实际追加计划，不能把同一笔领料在多个报工单、公共超产切片或追加工单中重复计算。

| 量 | 权威事实 |
|---|---|
| 分子 | 实际实发净量减已确认良品退料，包含实际生产损耗，不含取消的实发 |
| 分母 | 已审核的真实产出，包含实际超产；品质恢复报工不重复计原产量 |
| 累计单耗 | 某材料累计净耗料 / 父件全部有效样本累计实际产量 |
| 采样时机 | 生产族完成、无未审报工或待处理追加、无在制余额或待收退料，真实材料结耗平账 |

例如两批实产 100 和 300，净耗塑料 12 和 30，则平均每件 42/400=0.105；不平均两个批次的单耗。一个批次未用某种材料时，该批产量仍计入总分母，相当于该材料本批实际用量为零。不同材料是父件下的平级 BOM 子件。

进行中和未平账批次不贡献新的数据，避免先领后退、分次报工使单耗提前漂移。已有有效样本时，只要已审产出和现存真实耗用仍覆盖旧贡献，新增草稿、下一批新领未耗或待处理追加不会抹掉旧配方；待新批闭合再更新。实际红冲或确认退料使旧贡献失效时，按新贡献减旧贡献更新聚合。重放同一事实贡献不变，并发按货品与样本锁定。学出的 BOM 只影响以后的分析和下达，不改已有冻结需求、计划量、领料或成本。

原来学出原材料的底层自制件会保持学习身份，以后正常 BOM 工单也继续累计。BOM 页的“BOM 学习记录”显示累计产量、有效批次、各材料净用量及平均单耗。

## 3. 结构、身份与人工维护

- 精确区分货品、颜色、基础单位和实际仓；数量换算沿既有基础量，不靠名称合并。
- 只发布系统学习创建的 BOM 边。人工新增、修改或删除组件后，该父件停止自动发布，保护人工决定；真实累计仍保留。
- 自引用、结构循环、同材料的颜色/单位冲突、主档单位变化和无法表达的正单耗，保留阻塞原因并停止发布，不静默覆写。
- 后台聚合和人工 BOM 更新沿同一结构锁检查；纯数量增量不让所有生产任务串行等待全局结构锁。
- 使用 BOM 现有精度发布单耗，累计量保持更高精度；不能把精度过小的正耗用写成零材料。

## 4. 初始允许超产比例与记忆

只有制造最底层默认 10%，上层制造默认 0%。直接子层全部是采购原料，仍是制造最底层；因此学习出原料子层后不会突然把默认比例改成 0%。存在自制、委外或未确定来源子件时，保守按上层处理。

按货品持久保存最新确认比例，显式 0 与未填写不同。准备主表、各下达入口、级联下单和计划草稿使用同一服务端默认；刷新不能覆盖已输入的数字。保存/下达成功才记忆，已有执行任务改比例仍须计划部审批，待审和驳回不更新记忆。历史计划与工单已生效比例不批量改写。同品多行保留各行提交值，后续默认取最后成功保存的值。

## 5. 性能、权限与反向

列表先过滤分页。默认比例批量点查货品记忆；学习按当前生产族的索引范围读取报工/物料流水，事务末对同族去重刷新；读平均值只读货品聚合表，不扫描历史工单。

车间查看/提交仍要求车间岗位与 `production_execution:view/start`，仓库配置要求仓库岗位与 `stock_doc:view/approve/issue`，对象范围继续复核。新表写入绑定已有审计上下文；申请和物料来源追加留痕。取消申请不会删除已发生库存或报工。

业务数据清空保留货品和 BOM，也保留学习累计作为主档知识基线；清掉旧业务样本、刷新队列、材料发现申请/明细和批量出库命令账，永久业务编号占号继续保留。已清空源单不能再反向，新真实样本继续累积。此规则只是清空能力的兼容维护，本次不执行业务清空。

## 6. 验证与上线边界

需覆盖完整前向迁移/重放、无料禁止开工、车间提交/取消重提、仓库多材料与跨仓、库存不足原子回滚、实际出库后开工、分批/追加产量、净耗加权、重复/并发/退料/红冲、人工 BOM 保护、颜色/单位/环路、比例记忆及权限负测。页面验证数量加单位、失败保留输入、同键重试和窄屏大字体。

当前结果及完整验证边界统一见 [2026-09-26 领料申请、批量出库与编号收尾](../99-项目治理/2026-09-26-领料申请批量出库与编号收尾.md)，不在各设计文档重复累加测试数量。源码与隔离数据库通过不等于公司服务器已安装；上线必须另走备份、迁移、制品激活及真实岗位验收。已应用迁移字节保持不变。
