# V761 业务事件死信可见性索引

日期: 2026-09-30。状态: 本地实施候选，尚未安装到公司服务器。

业务事件第8次失败后转为status=2，原服务器状态采样只计算status=0，会把“已停止重试但尚未解决”的事件漏掉。应用指标现在分列待处理业务、附件清理和停止重试数，未解决总数包含三者；只要有停止重试事件即至少WARNING。没有可靠的停止时间列，因此不伪造死信等待时长。

本迁移仅增加 `business_outbox(id) WHERE status=2` 部分索引，让每分钟的死信计数读取尚未解决的索引集合，避免扫描多年成功载荷。不创建表、不改变状态、不重放、不删除任何事件，现有status=0处理队列索引继续保留。

这是普通`CREATE INDEX`，构建时仍要扫描原表并阻塞该表写入，不能因为索引只保存少量行就声称无锁上线。先在真实副本测构建耗时和空间，再纳入既有停写发布窗口。若实测窗口不可接受，应另设计并验证不在Flyway事务中执行的并发建索引方案，不能临时修改已应用文件。
