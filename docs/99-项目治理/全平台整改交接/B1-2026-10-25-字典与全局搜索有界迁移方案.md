# B1 字典与全局搜索有界迁移方案

日期：2026-10-25。此文是已核对源码的实施方案，不是字典迁移、界面或性能验收回执。遵循 `frontend-design`，继续使用 Uten 组件、主题、权限与 B0 输入保护。本文件不改变现有字典返回合同。

## 现有能力与实际缺口

| 现有入口 | 已有能力 | 本轮核实的限制 |
|---|---|---|
| `MasterDictionaryRepository.load` | 会话隔离、相同端点单飞、主档写后失效 | 客户/供应商仍一次加载完整精简字典 |
| `MasterDictionaryService` / `MasterLookupQueue` | 货品按 100 UUID 批读取、最多四路、失败可重试、4096 行 lookup 缓存 | 客户/供应商尚未接同类按 IDs 解析；员工按授权详情逐人读取，不能改成无权限批名接口 |
| `UtenMasterPicker` / `showUtenClientPicker` / `showUtenSupplierPicker` | 公共分类树、分类内服务器分页、selectableOnly、请求代次、返回页、确认栏 | `_reloadGlobalSearch` 逐页读完全部匹配并在 `_globalItems` 中累积，再本地分页；全局搜索仍无界 |
| `UtenPagedPickerList` | 公共表格的有界双向页窗口、rowsController、paginationScope/revision | 选中状态和输入由调用方负责；不能直接把可见页当提交全集 |

完整源码消费命中见[客户供应商字典消费者](B1-2026-10-25-客户供应商字典消费者.csv)。它记录名称显示、选项集合、状态/默认结算方式和写后失效各消费点，仍需逐调用方确认及回归。不能只迁移销售列表。

## 公共方案及边界

1. 增加客户、供应商的按 IDs 精简 lookup。沿用 `RequestLimits.LOOKUP_IDS` 硬边界，客户端每批使用既有 100 ID 队列；服务端按当前功能和对象权限筛选，不接收原始 SQL、字段名或客户端权限结论。返回当前接口确需的 `id/code/name/status/selectable`；供应商默认结算方式只供既有预填需求，不成为保存/审核权威。
2. 历史显示与新选择分别处理。显示允许当前授权的已禁用主档；已删身份沿历史授权合同处理。未知、不可达不返回私人明细，也不因为 lookup 为空而删除表单中的原 UUID、冻结名或历史原文。新选择继续使用服务端 `selectableOnly`，最终写入仍由原领域服务复核。
3. 页内名称显示从当前行、详情、草稿恢复和已选引用中收集 IDs，经公共 `MasterLookupQueue` 去重读取。结果只发布到当前用户/代操作/权限/服务器/请求代次。4096 行缓存上限与写后失效复用，当前视图和编辑中的名称快照由调用方持有，不能因缓存淘汰把正在显示的行变成未知。
4. 下拉搜索统一进入现有客户/供应商主档选择器，保持分类和真实字段；筛选器需要精简选项时接同一服务端分页谓词。客户现有搜索会匹配联系方式，继续通过 POST 请求体，不能把敏感搜索值移回 URL。
5. 迁移全部消费者后，再去除三套全量 `_clients/_suppliers` 构造和不再使用的完整字典加载。仓库树、币种、单位等其他字典按各自语义另审，不顺带截断。

## 全局搜索与分类定位分开

结果行应直接显示服务端当前页。全局匹配的分类位置不能再靠读完每一页明细推导。

新增独立、按需的分类元数据入口，例如客户/供应商 `POST /search-context`：请求携带与列表相同的关键词、分类/状态与 selectableOnly；复用同一权威 Specification 和对象范围，返回本次查询下的匹配分类、必要祖先路径及计数。只投影分类元数据，不取回业务明细或私人字段。元数据与取行分开调用，以查询条件及权限身份绑定；同条件翻页不反复计算整套分类。

现有完整分类树和权限规则继续成立；分类匹配量增长到需要分页时，应按分类节点/层级按需加载并明确加载进度，不能静默截掉匹配分类。无分类记录也要保留独立“未分类”事实。取消、失序、分类切换、A→B→A 和身份变化统一用现有代次保护。

公共 `UtenMasterPickerSpec` 增加分类查询上下文的可选端口，客户/供应商实现该端口；结果 `search(query,page)` 只读一页。全部接入后移除 `_globalItems` 全量集合、遍历 backendTotalPages 的 while 和本地结果分片。分类内浏览已有的服务器分页保持。

## 销售批量发货的有界合同

本轮已转入实施，最新代码/测试状态由根任务回填：

- `GET /sales/orders/shippable-lines/page`：标准 PageResponse、每页不超过 100，支持关键词及客户 UUID。
- `POST /sales/orders/shippable-lines/selection`：同一可发行查询基座，只选择当前可写候选；不超过合法单批 500 行时完整返回，超过则明确拒绝并要求收窄，不截取前 500。
- 旧 List 入口最多读取 501 行判定超限，超限明确指向分页接口；不静默少返回。
- 原全选仍表示完整合法候选。选中 IDs、数量/重量原文、已有确认结果与可见页分开；控制器只挂当前视口，翻页不丢输入。单批上限来自现有 `RequestLimits.DOCUMENT_LINES=500`，不能临时扩大服务器写入边界。
- 结果未知时继续使用原 `_retainedLines`、`_retainedDate` 和幂等键核对；翻页或重新搜索不替换已冻结的提交。新 selection POST 属纯读，网络修订号只按精确路径排除，不能泛化所有 selection 或 preview。

## 交互与设计约束

沿用现有 `ColorScheme` 和 `UtenColors`：交互深青绿 `#0F766E`、背景 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、边框 `#E2E8F0`、错误语义使用现有 error token。中文使用既有 NotoSansSC 字阶，正文/业务值沿 bodyLarge/bodyMedium；不新建另一套字号、圆角或颜色。

布局左对齐，保持现有“左分类、右结果、底部确认”的业务结构。窄屏沿用 UtenAdaptivePanel。加载反馈只占结果区域，搜索输入、已选摘要和安全导航保持响应；错误允许保留当前输入重试。没有新增自动动画。

```text
搜索输入                         已选数量 / 当前筛选范围
┌ 分类树 ┐┌ 当前服务器结果页 / 局部加载与错误恢复 ┐
│ 匹配位置││ 名称、编号、真实必要业务字段         │
└────────┘└─────────────────────────────────┘
分页与加载状态                   已选输入摘要 / 确认
```

方案审查结论：复用现有 Uten 视觉和公共分页入口；分类定位、全选和原文输入继续有各自明确的业务意义。实现前后须截图复核大字体、窄屏、键盘焦点及深浅主题，不能只检查加载动画。

## 验收出口

新增 lookup 必须覆盖允许/拒绝对象、空与未知/已删、去重和上限、100/200 边界、写后失效和不同身份响应；客户端用同一共享队列并验证全部消费者接入。

选择器必须覆盖多于一页的全局匹配、匹配分类位于末页、未分类、同名与同排序值、搜索失序/取消/失败、输入与选中跨页保全、撤权和服务器变化。名称显示、可选性与默认结算方式分别核对。

销售可发行另验证 100/500/501 边界、只读可见与可写候选不同、真实预留/草稿分配、原始数量重量、价格遮蔽和原未知请求。性能在固定规模与资源竞争下分别记录接口、SQL 工作量、内存、帧响应和 p95/p99。只有这些范围和实际交互完成，才能把相应入口标为完成。
