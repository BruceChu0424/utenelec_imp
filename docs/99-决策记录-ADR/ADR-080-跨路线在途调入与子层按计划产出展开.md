# ADR-080 跨路线在途调入与子层按计划产出展开

## 背景

生产物料分析准备页有三种把别人计划的供给调过来的方式：现货让料、专属在途调入、公共在途认领。落地后暴露出四个问题。

**一、跨路线调不进来。** 服务层已经把「专属在途调入」的目标放开到采购 / 委外 / 自制三条路线，但数据库守卫 `fn_guard_preplan_future_transfer` 仍然要求目标行的确认路线等于来源动作的路线，任何跨路线写入都以 `23514` 被打回，还因为被通用兜底翻译成「数据已被其他操作更新」，把人往并发方向误导。公共在途认领同样只在服务层放开，但候选仍按**目标**路线过滤，自制目标永远查不到来源，点了只看到「当前没有可采用的公共在途」——不报错，看起来像没数据。

**二、调进来了，下达余量不减。** 已下达覆盖量按「操作组 + 路线」二元键统计，而调入动作沿用来源路线落库。目标桶算「还能下达多少」时看不见这笔调入，会重复备料。

**三、子件不跟着父件的净产出走。** 第 2 层及以下的子件需求一直按父件的**物理缺口**展开，不扣任何在途。父件被在途覆盖一部分后，下层仍按整件全量备料，直接造成多采多产。

**四、混淆了「外部在途」与「内部制造承诺」。** 有效在途覆盖量里混进了委外件的前置自制任务未通知量（以及历史遗留的自制备料动作）。这部分的物理来源恰恰要靠下层原料去产出，一旦拿它去缩减子层需求，会把刚下达的车间计划的料抽空。

## 决策

### 1. 调入的目标边界改为白名单加形态不变量

数据库守卫不再要求「目标路线 = 来源路线」，改为：

- 来源仍限采购 / 委外的供给动作（外部最终件份额），自制在制品与委外前置自制半成品永不可作为来源；
- 目标行的确认路线必须是采购 / 委外 / 自制之一，控制段不是发货段或参考段，行仍生效；
- 单笔转入量不超过目标行毛需求（库侧宽松兜底）与来源未实收容量（原有闸门）；精确的待补量上限由服务层按权威快照把关；
- 同主仓（公共在途认领的仓库口径 V569 起即为同主仓，与专属调入、与让料一致）。

服务层用同一套判定过滤候选列表，杜绝「列得出来、存不进去」。

### 2. 调入动作沿用来源路线落库，分桶归属跟随目标行

调入动作确实是一张采购单或委外单的份额，路线与单据信息保持原样，进度链路仍显示真实的采购 / 委外单。但物料行的「已通知路线」按目标行的确认路线归位，因此：

- 自制物料上的一笔采购在途调入不会让该物料出现在采购桶；
- 已下达覆盖量按操作组补统计一次跨路线调入，目标桶的可下达余量随之减少，不再重复下达。

### 3. 子件毛需求跟随父件「计划产出量」

```
父件计划产出 = max(已承诺内部制造量, 物理缺口 − 外部最终件在途)
子件毛需求   = 父件计划产出 × 单耗
```

- **外部最终件在途**：已下单未实收的采购 / 委外份额、跨计划转入、公共认领、质检失败后重新欠货的切片。它们到货就能顶上，不必为其备下层料。
- **已承诺内部制造量**：该父件下已建的自制锚点与委外前置自制任务的**需求总量**，按物理缺口封顶。已下达即冻结，它的原料一件都不能少。
  - 这里取总量、**不扣已完工量**，是因为下层子件的正式计划覆盖对前置自制按「已产出未回厂」封顶：已为完工部分领掉的料，在委外件回厂之前一直挂在同一批子件行上当覆盖（ADR-062）。毛需求缩而覆盖不缩，缺口会被算小、车间反而少备料。
  - 锚点数量是累加的（重下达只增不减），因此托底值必须按物理缺口封顶，否则历史累加会把下层需求永久抬到缺口以上。这两条一起构成本决策的铁律。
- 任一层计划产出为 0，其整棵子树的未下达需求自动归零。

「有效在途覆盖」因此拆成外部与内部两类，两类之和等于原口径，所以「还需安排量」的计算完全不变，只有子层展开基准区分二者。

### 4. 只作用于计划口径，第 1 层与执行侧不动

第 1 层物料行的需求同时是实物执行层的基准（齐套、正式预留、领料、开工都读它），因此**不**用在途去缩减它。在途永远不生成正式预留、不把待料提升为可开工。子层展开是诊断投影，改动止于此。

### 5. 采购批量只做两个主档字段

货品主档新增最小起订量与订货倍数。采购桶的下达数量默认值 = `向上取整到倍数( max(还需安排量, 起订量) )`，超出需求的部分走既有公共备货通道。这是软约束，服务端不硬拦，计划员可以改小。没有超量下达权限的人不抬量，界面明确提示「低于起订量，需由有权限的人抬量」，不静默降级。委外与车间桶不按起订量**自动抬量**——它们会产生下层责任，默认值必须与需求一致。（2026-09-14 修订：车间桶的**本批生产量**允许计划员手工填成超量，超出部分按公共备货产出单独记账、不扩大下层责任，见 [V577](../数据迁移/169-V577下达车间超量与公共备货产出.md) 与 ADR-070 §2.7；这与"默认值不自动抬量"是两回事。）

### 6. 现货让料放开到所有 BOM 组件层

让出端与调入端都由「只限第 1 层」改为「第 1 层及以下」。第 0 层根供给行不参与，它有自己的根产出交付通道。既有护栏（数量不超过来源余额与目标缺口、一个节点一条未补齐关系、双端乐观锁、优先补齐按行匹配、同主仓）都不依赖层级，全部保留。

## 明确不做及理由

| 项 | 理由 |
|---|---|
| 有子层委外件当在途来源被调走 | 可转容量基数是订单已批准量，不区分目标件是否已出仓给委外商；在「已批准未出仓」阶段被转走会让源计划双重落空。且订货改量不回写前置自制账本，账本本身已有断链。放开前需先补「已出仓」档位与账本回写。 |
| 同一分析内兄弟节点互相认领公共在途 | 跨分析约束由服务层与数据库双重设防，放开会引入自引用；同货品的合并已在订货层按多来源锚定实现。 |
| 第 0 层根供给行按在途净算下层 | 会动到齐套、领料与开工门禁，违反「实物口径不认在途」。 |
| ~~父件行「一键办齐子层」批量编排~~（2026-09-14 已由 [ADR-081](ADR-081-下层一键办齐与物料表身份列统一.md) 接办） | 原理由：主表是树，子层行在各自的桶里已可逐行下达，数量口径本轮已纠正。把「确认路线 + 调入 + 三桶下达」压成一个事务要同时穿过三条各有校验的下达路径，任一行失败需整体回滚，与本轮正确性改动同批会放大回归面。单独排期。**ADR-081 的做法是不合并成一个事务**——改为有序编排 + 逐段如实回报（失败即停、已成功段保留、幂等可重试），所以上面这条「一个事务」的拒绝理由继续有效，被接办的只是「一键办齐」这个入口本身。 |
| 行动消息中心、时间相抵与齐套承诺 | 现有能力已保证「已下达不被自动改、风险能被看见」；这两项单独排期。 |

## 影响与验证

- 数据库：V574 只替换在途转拨守卫、新增两条索引、刷新两条权限目录文案；公共在途认领零迁移（守卫不动，服务层改取候选与落库路线）。V575 只给货品加两列。均不新增表，清库白名单与审计触发器覆盖不变。
- 老数据：新口径是重算投影，刷新即生效，不回写历史单据。已完结且无在跑计划的分析不会被重算，保持原样。
- 验证：子层展开的六个数值用例（含「已下达车间后再调入不减下层」「锚点量被物理缺口封顶」）、跨路线调入与跨路线公共认领的全链路真库用例、覆盖量读取的固定语句条数用例、起订量抬量的三个界面用例。
