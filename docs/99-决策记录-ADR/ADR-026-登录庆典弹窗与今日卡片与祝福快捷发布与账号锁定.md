## 背景

ADR-025 把通知做成了「HR 发、员工看」的单向广播。本轮把庆典升级为**员工本人可即时感知**的体验，并修掉几个 HR 工作流痛点：

- 登录后对自己的生日/周年/新婚/新生儿毫无即时反馈，也没有常驻提醒；HR 发布祝福后任务中心角标不减；祝福对象改选后标题残留旧名；员工账号开通埋在 ⋯ 菜单、且无锁定/解锁；工作台部门分区徽标展开时冗余、HR 统计卡过大过空、快捷发布祝福入口位置不合理。

## 决策

### 1. 工作台部门分区徽标「展开隐 / 收起显」
`WorkbenchModuleArea._buildSection` 的 `titleTrailing` 增加 `expanded` 守卫：仅收起时显示 `WorkbenchGroupBadge`。今日概览 / 待办任务 / 常用功能不受影响（前者无分区徽标，待办任务保持常显，常用功能无徽标）——满足「除这三者外」的排除要求。改动局限于 `workbench_module_area.dart`，复用既有受控折叠状态。

### 2. HR 工作台统计卡紧凑化 + 快捷祝福移入子页
- `_overview`/`_StatCard` 重构为 ≈72dp 紧凑磁贴（图标+数字同行、标签下行），用 `Row`+`Expanded` 固定高度、不随屏宽漂移；窄屏 2 列、中宽 4 列。
- `_quickNotice` 移除「生日 / 周年」瓦片（已迁入子页），仅保留「通用发布 / 新婚 / 新生儿」精简行。
- HR 子页 `/hr/tasks/:type`（birthday/anniversary）新增**一键批量送祝福**（`POST /notices/celebration/batch`，默认模板 + 服务端派生标题 + (subject,type,当年) 去重）+ **每行送祝福**（`/notice/publish?type=&subject=` 预填对象，复用发布页可人工调整）。

### 3. 祝福对象改选标题残留修复
`NoticePublishPage` 新增 `_titleAutoFilled` + `_autoFilledTitle` 追踪：标题由系统自动套入（用户未手改）时，改对象覆盖为最新建议标题、清空时一并清空；用户手改过则保留。修复「选 A→取消→选 B 标题仍为 A」。同时支持路由 `?subject=` 预填对象（`presetSubjectId`）。

### 4. 发布祝福后角标即减（HrTaskService 已祝福排除）
`HrTaskService.summary()` 查询本类型本年已发布庆典通知的员工集合（与 `CelebrationScheduler` 同口径 `published_at >= make_date(year,1,1)`），在 `birthdayToday`/`anniversaryToday` 条目标记 `blessed`，徽标按「未祝福」计数。子页批量/单个发布后 `reloadSilently()` 即时刷新徽标。

### 5. 登录庆典弹窗（每日一次）+ 今日概览常驻卡片
- 后端 `GET /api/notices/celebration/my-today`（`notice:read`）：当前用户今日庆典列表 `{type, subjectName, eventLabel, noticeId?}`。生日/周年服务端按 `birth_date`/`hire_date` 月日判定，新婚/新生儿按今日发布的庆典通知判定。**PII 安全**：日期仅服务端读，绝不外泄。
- 弹窗触发挂在 dashboard（登录后落地页，上下文稳定）`CelebrationPopupGate`：`SharedPreferences` 键 `celebration_popup_last_shown`（`yyyy-MM-dd`）做每日一次守卫；`showDialog` 弹 `CelebrationLoginDialog`（粒子场 + `CelebrationMascot` + 按类型文案 + 「谢谢小优」）。
- 今日概览置顶 `CelebrationTodayCard`：常驻轻量动画（粒子场，按性能档 lite 关闭），当日结束 `my-today` 返回空 → 自然消失；点击跳该通知祝福墙。
- 视觉：用户提供「小优」庆典美术（`assets/celebration/xiaoyou_{birthday,anniversary,wedding,newborn}.png`）；文件缺失时 `Image.errorBuilder` 回落 `UtenBrandMascot`（`logo_ip.png`），功能先上线。
- 动画规范：`CelebrationParticleField`（CustomPainter + AnimationController，`UtenAnim.slow * 8` 循环），lite 档渲染静态散点、控制器 dispose。

### 6. 员工详情开通/锁定/解锁账号外显
- 后端 `POST /org/employees/{id}/account/lock|unlock`（`account:support`，按 `employee_id` 解析 `users.id` 复用 `UserAccountAdminService`），与开通账号同权限级（非超管 HR 可用）。
- 前端 `_primaryActions` 顶卡：未开通→开通账号；active→锁定账号；locked→解锁账号（二次确认）。溢出菜单移除开通账号（避免重复）。

## 验证
- 后端单测：`NoticeServiceTest` +9 用例（my-today 五类 + batch 发布/去重/类型校验/空列表）共 32/32；主/测试源 `mvn compile`/`test-compile`/`package`（产 jar）通过；无新 Flyway 迁移。
- 前端：`flutter analyze` 0；`notice_interaction_repository_test` 13/13、employee 域测全过。（全量 `flutter test` 有 13 项失败，经 grep 确认均不引用本特性代码，源自并行 session 的 department/my_department 未提交改动，非本域。）
- **runtime 真实 E2E（后端从源码 spring-boot:run 起 8080，自签 JWT + 真数据）已全过**：
  - my-today 四类：临时设 ADMIN employee `birth_date=今天`→`birthday`(系统管理员/生日快乐/noticeId=null)；`hire_date=今天-5年`→`anniversary`(入职5周年)；插 wedding notice(subject=admin,今日)→`wedding` 返回正确 noticeId；无庆典 baseline=`[]`。日期 PII 不外泄。
  - celebration/preview：翁修和 → `祝 翁修和 生日快乐！` + 3 模板。
  - batch + 角标即减：summary 前 badgeCount=1（翁修和 blessed=false）→ POST batch → `{published:1,skipped:0}` → summary 后 badgeCount=0（翁修和 blessed=true）→ `/count`=0 → 再 batch 去重 `{published:0,skipped:1}`。
  - account lock/unlock：王少春 active → lock 200（status=locked, auth_version 2→3）→ unlock 200（status=active, av=4，会话吊销）；无账号员工 / 不存在 ID → lock 404。
  - 测试后 DB 已清理（翁修和 notice 删除、ADMIN birth/hire 复位、王少春恢复 active）。
- 未做：前端浏览器 UI 实跑（纯视觉未驱动，逻辑+数据已验）；用户后续提供「小优」美术 + 真实多账号 UAT。

## 影响与后续
- `my-today` 由 `notice:read` 保护、仅读本人档案，无越权面；批量发布 `notice:publish`，去重幂等。
- 庆典弹窗/卡片不影响主流程：所有失败静默，UI 不阻塞。
- 「小优」庆典美术到位前回落品牌 IP；后续美术替换零代码改动（仅放文件）。
- 账号锁定走 `account:support`，后端独立鉴权 + 数据范围校验；`UserAccountAdminService` 既有护栏（`requireAccountSupportTarget`）复用。
