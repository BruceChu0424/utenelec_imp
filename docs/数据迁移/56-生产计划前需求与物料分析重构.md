## 一、迁移原则

1. 已应用 Flyway 迁移不可修改；V150–V230 的历史生产事实、字段和约束保留。V234 若尚未在任何目标环境应用，可在合并前评审；一经应用，后续修复只能追加 V235+。
2. V191 草案强制绑定正式计划，不能改造成计划前分析。V234 新增独立分析聚合，普通生成时才创建正式计划草稿及其 `ACTIVE production_planning_drafts`。
3. 不创建平行库存、领料、报工或入库账。分析、路线、备料 action 和预计供给均不得写 `production_material_demands`、`stock_reservations`、supply peg、执行分段或 DRAW。（V298 起唯一例外：分析来源订货**真实 IQC PASS 入库**时，由入库链按来源分摊写 `PREPLAN_ANALYSIS` 归属预留——它是物理入库事实的归属锚点，不是分析/预览/action 自行占料；见 [ADR-039](../99-决策记录-ADR/ADR-039-计划前物料分析备料库存绑定.md)。）
4. 普通 generate 与 approve 必须分开：generate 只提交计划草稿；approve 才按一个目标仓原子重算并形成 READY、完整预留、DRAW 和正式销售分摊。
5. 所有写命令使用服务端幂等键和载荷哈希；物理表以数据库约束守住数量、来源和归属。
6. 历史 WAITING/AUTO_WAIT/DEFERRED 零回填、只读兼容。新链路不得再创建这些正式待料状态。
7. V237 在 V234 生产分析表和并行 V236 财务表之后重新执行 fail-closed 审计覆盖 sweep：只为迁移后的未来写入补齐/验证唯一有效 `trg_audit*`，不回填历史审计，也不修改 V234/V236。
8. V239 以新增迁移把 `production_material_analysis_materials.required_qty` 的终态合法范围从 `>0` 改为 `>=0`；全量批次 claim 后 required 恰为 0 是守恒结果，不得回改 V234 或以负数/删除行规避。
9. V247 为 BOM 和分析快照增加控制阶段、包装计量、三阶段齐套量、节点分阶段分配及历史计算模式；V248 为非线性正式物料需求增加不可变精确快照；V249 冻结执行段是 `DEMANDED` 还是有证据的 `ZERO_MATERIAL`。这三个迁移只追加结构和约束，不回写伪造的生产、预留、领料或入库事实。
10. V250 把 V162/V194 的来源防拆保护扩展到 `preplan_supply_actions/allocations` 及其采购、委外下游：冻结外部单据来源身份和路线匹配，阻断通过修改、脱钩或删除来源行绕过追溯；历史 `CANCELLED` action 仍受保护。V251–V287 的后续业务与治理迁移不反向改写本合同；V288/V289 只新增同一分析内的现货借用事实及其守卫；V298 新增 `PREPLAN_ANALYSIS` 备料库存绑定形态（ADR-039，不回填历史）。该段当时目录头为 V299；现行 V337/V338 后置合同见本页顶部，后续修复始终只能追加更高迁移。
11. ADR-033 是 V250 之后的业务合同，不反向改写旧迁移或旧证据。当前候选以稳定 path action key、现有 action/allocation、`parent_analysis_material_id` 和 child item 存在性投影委派所有权；V288 的 `qty/last_effective_qty` 仅表示分析内现货软分配，不是 MAKE 子计划的 `delegated_qty`。若既有事实不能无歧义恢复激活量、分批委派量和反向余量，只能追加 V300+ 表、列、约束或只读投影；在完整验收前继续 fail-closed。

## 二、V234 实际对象与职责

### 2.1 V234 产品生产结构策略（历史快照，V423 已取代）

> 下列三策略与保守回填只说明 V234 当时写入的迁移字节。V423 已删除该列；当前无直接 BOM
> 按分析事实直接自制，不存在主档策略或计划级越权。

`goods.production_bom_policy` 只允许：

- `BOM_REQUIRED`：必须有可用 BOM；无 BOM 时阻断，除非对本次需求使用独立越权；
- `DIRECT_MAKE`：产品主数据明确确认可无 BOM 直接自制；
- `NOT_PRODUCED`：不得进入生产分析或生成生产计划。

V234 的保守回填是：旧 `source_type` 为“采购/委外”的货品写 `NOT_PRODUCED`，其余写 `BOM_REQUIRED`；**绝不因无 BOM 自动写 `DIRECT_MAKE`**。该回填只保证 fail-closed，不代表业务认定正确；开放新写能力前仍须由工程、计划和生产逐项复核开放需求产品。

### 2.2 分析头、需求行与全树节点

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `production_material_analyses` | 一次持久化物料分析聚合，记录选定目标仓、版本、输入/预览指纹和分析时间 | `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`；该状态不是计划审批状态 |
| `production_material_analysis_items` | 分析中的顶层生产需求行；可来自销售、手工需求或系统 MAKE 子需求 | `SALES_ORDER_ITEM/REWORK/TRIAL/SAMPLE/STOCK/OTHER/MAKE_COMPONENT`；保存 `line_priority/ready_now_qty/ready_by_date_qty` 分配快照；`submitted_qty + approved_qty <= requested_qty` |
| `production_material_analysis_materials` | 完整 BOM 树的逐路径节点任务及本版本数量快照 | 每个 `analysis_item_id + path/node_key` 独立；V234 保存父节点、需求/覆盖/短缺、建议/人工路线和目标仓库存快照；当前候选从 child item 推导委派所有权，并未持久化显式委派数量；路线仅 `BUY/MAKE/SUBCONTRACT` |

销售来源必须指向真实 `sales_order_items`；手工 `REWORK/TRIAL/SAMPLE/STOCK/OTHER` 必须填写稳定业务需求编号与原因且不得伪造销售外键。数据库以 `source_type + lower(trim(source_ref))` 守住非销售来源唯一性；同一需求的活动分析应幂等恢复，终态记录从历史回查，不能靠新幂等键重复创建。`MAKE_COMPONENT` 必须由系统在父 MAKE 路径下层实际齐套并执行委派命令后创建，通过 `parent_analysis_material_id` 或未来 V254+ 等价关系精确关联父路径节点；数据库校验其货品、颜色、单位和委派量，用户不能手工选择。

完整 BOM 节点全部保存在分析快照中，每个路径节点是独立物料任务；页面初始“只看缺料”，搜索/筛选命中子节点时保留祖先上下文并分别显示直接命中/含祖先/全部数量，切到“全部 BOM”可查看所有节点。BOM 首次只构建筛选后前 30 个产品组，其余增量加载；这只是 UI 渲染分批，不删除节点或改变选择。所有节点在查看时都返回目标仓在手/合格可用量；`required_qty=0` 只表示“本批无需补货”，不能写成“齐套/随上级件”。只有路线已确认、当前可执行的节点显示真实复选框；未确认、未保存、MAKE 下层未齐或只读节点显示明确文字状态。任务是否可操作由“本批需求已激活、未委派、仍有缺口、路线/结构/权限有效”共同决定，不再由 `depth=1` 或 `shortage>0` 单独定义。

需求从根产品向下按实际未覆盖数量传播：BUY 父节点不激活后代；MAKE 父节点按短缺激活下层备料；SUBCONTRACT 父节点形成委外任务，且仅在有有效我方供料 BOM 时按短缺激活供料后代。MAKE 下层实际齐套后才创建 `MAKE_COMPONENT`，并把本批后代路径/数量 `DELEGATED` 给 child item；父树保留只读来源但不得再次下达或占用。

### 2.3 路线和共享调配

路线确认直接保存在 `production_material_analysis_materials.confirmed_route`，并记录 `route_reason/route_confirmed_by/route_confirmed_at`。主档建议为 `source_suggestion`；建议为 `REVIEW` 或人工偏离建议时原因必填。写入还必须校验路径任务当前激活量和委派所有权；刷新后以版本/指纹判定旧确认能否继续使用，不能把页面缓存当下达依据。

调度台只保留“新建物料分析 / 联合分析所选 N 项”一个主入口；进入页面不产生业务单据，真正的 preview/refresh 才持久化分析快照。单次联合分析的销售来源与手工来源合计最多 500。路线确认或任务下达超过单请求 500 条时，客户端按稳定任务身份排序并以最多 500 条分块；每块在服务端自身原子，后一块续用上一块返回的最新版本/指纹。幂等键绑定请求前 CAS 与块内排序后的精确任务集合，不包含重试时会变化的 batch index；服务端把 `actionGroupKeys` 和 `materialLineIds` 映射、合并、去重后，再对最终任务集合强制 1–500。

V234 不新增第二套物理库存分配账。共享物料调配在分析中按“选定目标仓 + 货品 + 颜色”共享自由量池，并按 `line_priority` 和稳定路径顺序执行完整套料分配；同仓的刷新/重排/预览/生成在仓维度事务锁内串行，锁后重读其他活动分析软分配与 `SUBMITTED` 草稿承诺，防止跨分析重复宣称同一库存。服务端把各 item 的立即/预计量和每条激活路径的已分配现货/缺口保存为同一次快照。

仓货色共享池只解决物理量不超分，不改变路径任务身份。同货多路径必须分别保存激活量、覆盖量、缺口、action allocation 和委派量；下游即使合单也不能仅按 `goods+color+unit` 去重。分批生成时，本分析的剩余软分配与新 `SUBMITTED` 承诺原子换账，总承诺不得从 100 错增为 110。`PUT /api/production/material-analyses/{id}/allocation-priorities` 必须提交全部有效 item 的完整排列、期望版本、指纹和幂等键，不能只传局部行。该操作不写 `stock_reservations`，也不能移动已批准计划的占用。已预留库存改派必须先对原计划走释放/反向，再重新批准目标计划。

### 2.4 计划前备料 action

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `preplan_supply_actions` | BUY/SUBCONTRACT 及 MAKE 委派命令的权威计划前动作 | `OPEN/CREATED/IN_PROGRESS/DONE/CANCELLED`；路线、目标仓、数量、需求日、业务键、代次、请求哈希和幂等键均落库；不得按货号开口量冒充路径幂等 |
| `preplan_supply_action_allocations` | 一个 action 到多个真实路径节点的精确数量分摊 | `Σ allocated_qty = action.requested_qty`；每条 allocation 保留 analysis item、path/node、父件和反向范围 |
| `production_material_analysis_commands` | PREVIEW/ROUTE/NOTIFY/GENERATE_PLAN 命令幂等账 | 同分析、操作和幂等键唯一；重放返回既有结果，不重复副作用 |

“提交采购需求 / 提交委外需求 / 安排自制生产”不是普通消息。服务端必须先落 `preplan_supply_actions` 和逐节点分摊，再创建并回写真实下游：

| 路线 | `external_document_type` | 真实下游 |
|---|---|---|
| BUY | `PURCHASE_REQUEST` | 采购申请及来源行 |
| SUBCONTRACT | `SUBCONTRACT_APPLICATION` | 委外申请及来源行；有供料 BOM 时，下层节点另按自身路径备料 |
| MAKE | `PREPLAN_MAKE_TASK` | 仅在下层实际齐套后创建 `MAKE_COMPONENT` child analysis item，并委派本批后代路径/数量 |

消息、角标、任务中心和 Outbox 只是上述事实的投影。BUY/委外是物料任务，不创建 `production_plans`；只有 MAKE child item 和根产品可以进入 generate。MAKE 委派必须保存来源父节点、目标 child item、本批数量、后代路径数量、操作者、时间和幂等命令；已委派数量在父树不可再次 route/notify/allocate。

action 尚未生成真实下游且未被引用时可以撤回并保留取消人、时间和原因；已有订单、委外发料、收货、正式计划或仓库发料后必须走对应取消/释放/红冲流程，禁止删除或把消息“已撤回”冒充业务反向完成。

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `production_plans.material_analysis_id/material_analysis_item_id` | 草稿计划精确回指分析需求行 | 两个字段必须同时为空或同时指向同一分析内有效 item |
| `production_material_analysis_plan_links` | 分批提交、批准、释放和反向的数量归属 | `SUBMITTED/APPROVED/RELEASED/REVERSED`；plan link 身份和数量不可改、不可删 |
| `production_material_analysis_items.submitted_qty/approved_qty` | 从 plan link 状态同步的提交量与批准量 | 合计不得超过 `requested_qty` |
| `production_planning_drafts` | 既有正式计划的审批前不可变预排载荷 | generate 创建 `ACTIVE`；approve 成功后按既有生命周期转 `APPLIED` |

分析头自身只使用 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`。`SUBMITTED/APPROVED` 是 plan link 的分摊状态，不能把它们写成分析头状态。

普通 generate 的事务边界：

1. 校验分析/item 版本、BOM 签名、销售剩余、单目标仓、本批数量和幂等键；只允许根产品 item 或已正确委派的 `MAKE_COMPONENT` item 进入 generate，BUY/SUBCONTRACT 节点任务必须拒绝；已齐套批次不要求为剩余缺口预先确认路线，但正式物料主档来源无法解析时仍 fail-closed；
2. 创建 `production_plans` 草稿、计划行和 `ACTIVE production_planning_drafts`；
3. 创建 `production_material_analysis_plan_links(allocation_status='SUBMITTED')`，由数据库同步 item 的 `submitted_qty`；
4. 不创建执行段、`stock_reservations`、DRAW、正式销售执行分摊或任何未来供给预留。

generate 返回结果必须足以让物料分析页原地刷新节点任务、计划号和审批状态；成功不要求前端跳离当前分析。该交互要求不改变 generate 的事务边界。

approve 的事务边界：

1. 要求 `production_plan:approve`，按稳定顺序锁定草稿、link/item、销售来源、BOM/分析版本和目标仓库存键；
2. 只按所选目标仓重新计算当前合格自由库存及完整套料量；其他仓只作调拨候选，调拨审核入目标仓前不得使用；
3. 同一事务批准计划、创建 READY 执行批次、全部直接领用物料预留、DRAW、正式销售分摊、语义审计与 Outbox，并将 plan link `SUBMITTED → APPROVED`；
4. 任一步失败全部回滚，原草稿和 `SUBMITTED` link 保持可见，不留下部分预留。

同时持 `production_material_analysis:generate` 与 `production_plan:approve` 的用户在独立汇总确认中默认勾选 `approveNow`，但仍须看到审核责任与副作用并显式点击「确认生成并审核下达」，且可取消勾选；生成和批准仍为一个全有或全无事务。无 approve 权限账号不得看到该选项或调用该参数，默认勾选不得演变为自动提交。

### 2.6 联合计划的默认车间只使用 V192

联合计划向导按 goodsId 批量读取 V192 `production_goods_workshop_preferences` 作为可修改预填；没有有效偏好的行进入“未分配车间”清单，员工补齐后才可提交。只有正式计划包确认成功且同货品本次车间无歧义，或执行段后续合法改派成功时才学习；打开/取消向导、保存草稿、拖动排序、失败事务和幂等回放不学习，也不回写历史执行段。

不得向 `goods` 增加 `default_workshop_department_id` 或保留第二份默认车间真相。V253 已被 `V253__website_inquiries.sql` 占用且与生产车间无关；若未来确需新增生产结构，只能从 V254+ 追加。

## 四、立即量、预计量与目标仓

`production_material_analysis_materials` 中的 `available_qty/reserved_qty/safety_stock_qty/inbound_qty/shortage_qty/expected_ready_date` 是带分析版本和时间的快照，不是批准时库存真相。

- **可立即生产量**只使用所选一个目标仓的当前合格在手，扣除有效预留、冻结和安全库存后，按该 MAKE/root 本批全部直接领用组件瓶颈向下取整；路径树中的参考现货不能越过激活和委派所有权进入上限；
- **预计可生产量/预计齐套日**只用于排序和风险提示，可读取精确来源且日期可靠的采购、委外和 MAKE 未来供给；
- 预计供给、待检库存、未完成调拨和其他仓库存都不能进入本次 generate 上限，也不能被写成物理预留；
- 其他仓库存只展示分布和调拨候选，调拨完成并审核入目标仓后重新分析。

### 4.1 三阶段与包装口径

`goods_bom_items` 及每次分析节点快照保存：

- `control_stage`：`START/ASSEMBLY/FINISH/SHIP/REFERENCE`；
- `consumption_basis`：`PER_UNIT/PER_PACKAGE/FIXED_BATCH`；
- `basis_output_qty`、`allow_partial_package`、`hard_gate`；
- 冻结的 `bom_qty/parent_per_product_qty/calculation_mode`。

只有 `START/ASSEMBLY/FINISH` 允许 `hard_gate=true`。`SHIP/REFERENCE` 由数据库、服务和 Flutter 三层禁止成为硬门槛；它们不参与正式需求、预留和 DRAW。生产包装确实要消耗的纸箱、胶袋、说明书等必须维护为 `FINISH + PER_PACKAGE/FIXED_BATCH`。

分析行保存 `ready_start_qty/ready_finish_qty/ready_ship_qty` 和节点的分阶段分配。`ready_start`、`ready_ship` 是分析参考，物料分析生成计划只允许使用 `ready_finish`。共享库存只走一次守恒分配：生产硬门槛优先、发货参考其次、一般提示最后；同一份物理库存不能被多路径重复消费，但每条路径任务及其 allocation 必须保留。

深层需求只按父节点真实短缺传播：BUY 截断后代，MAKE 展开下层备料，SUBCONTRACT 仅在有我方供料 BOM 时展开。MAKE child item 创建后，本批后代分配转为 `DELEGATED` 并由 child analysis 接管；不能把父件已有库存与子件原料同时算需求，也不能让父树和 child item 同时占用同一数量。

V247 对迁移前分析行使用 `LEGACY_CUMULATIVE_PER_UNIT`，继续依赖原行冻结的累计 `per_product_qty`；V247 后新建或刷新行使用 `EDGE_RULE`，按冻结的逐边 BOM 规则递归计算。不能用迁移执行时的当前 BOM 数量重写历史分析。

### 4.2 正式需求的精确快照

V248 保留线性 `LINEAR` 需求，同时新增 `EXACT_SNAPSHOT`：按包装/固定批次时，每个执行分段独立冻结产品数量、精确 `required_qty` 和 64 位规则指纹。库存预留、正式物料需求及 DRAW 都读取同一精确数量；六位 `per_product_qty` 只作为该分段或聚合后的展示平均值，不是重算权威。

例：10 件分成 3、3、4 三段，每 6 件耗 2 个整包且不拆包，三段正式需求为 2+2+2=6，不是聚合后的 4。草稿期软承诺也必须逐个 plan link 独立取整后求和；释放或红冲按原精确事实反向，不能用剩余数量乘平均率换账。

V249 历史迁移冻结执行段的 `material_requirement_mode`。`DEMANDED` 必须存在正式需求；`ZERO_MATERIAL` 没有需求、预留或 DRAW。V423 后新段只允许 `DIRECT_MAKE/NO_PRODUCTION_HARD_GATE`，`PLAN_BOM_OVERRIDE` 仅历史冻结段只读；V426 再要求 DIRECT_MAKE 精确匹配计划行、分析 item、goods/color/unit，并证明当前 BOM 与冻结分析快照均无物料行。已确认执行段不得因后改 BOM 改变历史物料形状；无法从历史事实安全判定时必须 fail-closed，先人工对账，不允许猜测回填。

### 4.3 IQC 合格量、红冲与全拒收替代需求

采购/委外收货只创建待检隔离事实，不得提前增加合格库存或立即量。同一收货可部分 `PASS/FAIL`；每次 `PASS` 只把本次合格量写入可用库存，V298 起在同一事务再按来源分摊写 `PREPLAN_ANALYSIS` 归属预留（ADR-039），并立即刷新相关物料分析，`FAIL` 不入库存或分析立即量。整张收货的全部明细终态后才执行一次正式供给 transition 与 WAITING→READY、reservation、DRAW 等推进；并发处置最后一行必须在收货范围内串行化，避免重复正式齐套。

收货红冲在原事务中只反向该收货已 `PASS` 的精确数量和分摊金额；IQC 明细转为 `REVERSED`，当前 `passed_base_qty/failed_base_qty` 归零，对称释放对应 `PREPLAN_ANALYSIS` 归属预留（V298），并刷新相关分析。可完工量下降只更新快照，不发布正向齐套通知。

整批 `FAIL` 后，已物理收完的原订单不再形成预计覆盖。系统保留原采购/委外申请、订单、收货、IQC 明细与事件，只将原 `preplan_supply_action` 置为 `CANCELLED` 以释放计划投影；再次通知生成 `generation + 1` 的 action，通过 `predecessor_action_id` 追溯失败动作，并按服务端重算的剩余缺口创建替代需求。不得删除原商业单据，也不得用新 action 覆盖原 action 身份。

## 七、上线与回退边界

1. **R0 只读分析**：单一页面入口、来源候选、初始只看缺料且可切全部 BOM、祖先上下文、前 30 产品组增量、所有路径仓库现货/需求/状态和历史兼容；不产生业务写事实。
2. **R1 节点任务与计划前写**：逐路径激活/所有权、路线和 supply action 真实落库；BUY/委外下游、MAKE 齐套后 child item/`DELEGATED` 与撤回/反向可追溯。
3. **R2 生成与批准**：generate 与 approve 分离且全量测试；approveNow 显式门控；READY、预留、DRAW 和销售分摊同事务。
4. **R3 生产放行**：完成目标库 `flyway_schema_history`/校验和预检，并在受审可恢复公司数据克隆上从现场实际版本演练至每个**已独立批准**版本；V425 未批准时不得为了取得 V426 而跨越、跳号、修改 history 或手工复制函数。完成历史数量、金额、权限和审计对账；治理有 BOM 产品的循环/深度/用量/UUID 单位颜色/控制阶段/包装计量及路线、仓库和责任主数据；验证无 BOM DIRECT_MAKE 的 V426 精确谱系负测、真实账号与实物流转 UAT、并发/压力、备份恢复/回滚及部署回读，经业务、技术、运维签字后才可开放写 feature flag。

回退只能关闭新写 feature flag；已经创建的分析、action、草稿或批准事实必须通过正常撤回/反向处理，不能靠回滚迁移、删表或删除消息恢复。源码候选、静态检查、单元测试或干净构建均不等于生产就绪；当前结论仍为 **NO-GO**。
