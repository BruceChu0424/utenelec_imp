# 物料分析撤回与调拨验证

本轮核对项目准则、ADR-043/049/102/120/143 后，按真实责任和库存来源区分命令。界面共用办理入口与确认规范，不把不同账务语义强行合并为一条取消接口。界面相关代码继续默认使用 `frontend-design`，保持 Uten 公共组件和主题约束。

## 场景与权威命令

| 功能 | 权威入口 | 必须保持的事实与负向场景 |
| --- | --- | --- |
| 普通计划整批撤回 | `/{analysis}/plans/{plan}/withdraw` | 草稿删除；已审计划在同事务反向有效执行包和计划责任；已取消旧包不冒充已撤回正式计划；独立子供给保留；实际领用、开工、报工、下游依赖时原子拒绝 |
| 共享制造整批撤回 | `/{analysis}/aggregate-orders/actions/{action}/cancel` | 按真实锚点核对全部来源；禁止从单路径绕过多来源；父批撤回保留独立子计划、采购和委外申请及其准确来源；请求重放不重复释放 |

| 跨分析现货让料 | `/{analysis}/cross-reallocations` 与 `/{relation}/revoke` | 同主仓且保留实际叶仓；只移动原始权益终点及其合法RESTORE；双方对象范围和CAS；禁止转手借入权益、正式占用及已执行事实；来源需求保留，后续供给优先补齐 |

## 本轮复现与修复

在途撤销确认打开后撤回宿主写权限，原确认窗仍可发送70件撤销请求。根因是弹窗只保留打开时的单据和可写状态，没有把宿主的账号、权限及分析快照作为命令条件。旧借用、跨分析撤销和调拨补供的回执也只有mounted检查，存在迟到回包覆盖后续上下文的同类缺口。

现由宿主向调拨、在途撤销及补供工作区传入实时命令条件。条件使用账号/模拟身份/权限集/业务重置代次和原分析对象快照；每次提交、多选调拨每一笔、冲突重读和回执应用前再次核对。旧上下文失效后不继续写、不自动重放、不回写新页面。成功一笔后的服务端快照用于有证据的逐笔重基；调拨已经完成的业务事实不会因关闭或切换账号而回滚。

普通借用与跨计划撤销也在确认后复核当前权限和原分析身份，迟到回包丢弃并释放忙碌态。权限作用域缓存必须保存Set快照，避免原地修改同一Set后误认为授权未变化。

未知回执继续冻结原来源、数量、原因和幂等键，只允许用户按同一意图确认；不自动重放POST。业务冲突读取最新状态、保留输入并重新确认，不能把已执行事实伪装成公共可用量。

## 数量协议与未来供给预算

调拨输入曾先经过double再发送，合法 `99999999999999.9999` 会成为 `100000000000000.0`。只保留POST原文仍不够：候选和撤销记录的容量也可能在JSON解析时已丢末位。现服务端候选、未来调拨记录及补供预览保留旧数字字段，同时增加只读 `quantityFactsExact` 十进制原文；物料行补齐 `allocatedAvailableQty` 和 `shortageQty` 原文。

客户端使用既有 `productionExactQuantity` 协议与BigInt万分位处理可调上限、手工数量、默认值、合计、撤销恢复量和公共释放量。五个调拨命令保留文本直到JSON边界，小数值兼容原数字格式，大数以字符串交给服务端BigDecimal；补供复用既有请求模型的 `qtyExact` 与 `safetyQtyExact`。已丢精度的大数字且缺少原文时失败关闭，要求重新读取；不根据double的toString猜原数量。

未来供给多选还存在独立口径缺陷：物理缺口1000、已有未来供给900、净待补100时，原合计校验按1000放行。现默认选择与总预算都按净待补100计算，来源60+60会在任何写入前拒绝；等量来源按稳定身份打破排序平局。现货调入继续按实际物理缺口，三类覆盖不混用。

## 按产品树的撤回入口

2026-10-21 用户补充要求后，按产品查看的「物料办理」列同时提供原计划/供给的撤回入口和原有调拨入口。根销售产品、普通自制子件、共享制造的原始来源行复用按物料汇总的同一个 `withdrawCell`；来源图只沿物料 UUID 找准确 action，再用 `action.documentId` 找对应锚点和计划，不按同货品猜测单据。

普通计划逐张调用既有 `/plans/{planId}/withdraw`；共享来源行点击后仍确认整批全部来源、公共数量，并调用 `/aggregate-orders/actions/{actionId}/cancel`。页面只读上下文、汇总草稿、来源关联不完整以及权限不符保持禁用；确认后继续复核会话、当前权限、分析版本和指纹，后端实际执行与下游依赖守卫没有新增绕行。

新入口最终8项widget通过，覆盖原销售根计划、普通子计划、共享整批来源/准确端点、权限禁用、关闭确认零写入、确认期间权限变化、来源链不完整及独立辅助语义。页面库与测试库2个入口静态分析无问题。最终日志为 `.local-artifacts/material-product-withdrawal-widget-final.log` 与 `.local-artifacts/material-product-withdrawal-analyze-final.log`。此轮没有重复完整261项旧主表族；新入口复用的后端流程已经由上述36项PG验证。最终Web重建、运行页面和截图由主任务记录。

真实浏览器最终核对发现：撤回本身可用，但并列的禁用调拨把 `enabled=false` 合并到撤回的语义祖先，浏览器辅助树继承禁用状态。新增 `ensureSemantics` 回归先复现这个祖先状态，再为动作容器提供明确子节点边界和调拨独立边界；现在撤回保有可用点击动作、调拨仍禁用，且通过语义点击能打开准确计划的确认，未发送写请求。最终主表文件 SHA256 为 `B53D8752DB366497DDCDFC9338C7CAB4AA2F4632236135BA79B2BD95CA80248D`。
