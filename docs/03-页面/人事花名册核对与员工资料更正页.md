# 人事花名册核对与员工资料更正页

> 别名：员工资料核对更正、批量核对、证件批量更正、花名册核对(文件名含「人事」「花名册」是为了让 AI 知识库把它归入 HR 族，完整方案 §十一)

> 路由：`/hr/tasks/reconcile`（声明在 `/hr/tasks/:type` 子路由之前，深链不可绕过守卫）
> 实现源：`lib/features/hr_task/`（`pages/hr_reconcile_page.dart` + widgets/models/repository，
> 列定义与差异格组件见方案 §3.5）；共用组件 `lib/components/data_display/uten_revision_cell.dart`
> 后端：`server/.../features/org/employee/reconcile/`（`ReconcilePlanStore` 四张表唯一存取、
> `ReconcilePlanHousekeeping` 每 10 分钟清理过期计划；计划生成/打分/执行服务同包，Pattern B 纯 JdbcTemplate）
> 入口：本期唯一入口 = 证件核对页(`/hr/tasks/identity`)多选 → 右下角「批量核对(N)」；
> 无参打开显示空态 + 「核对记录」
> 决策：[ADR-160](../99-决策记录-ADR/ADR-160-员工证件批量核对更正.md)；
> 方案：[人事花名册核对与证件批量更正方案](../01-规划/2026-10-05-人事花名册核对与证件批量更正方案.md)

## 一、定位

把「员工资料对不对」先算清楚、经人确认再改的服务端核对台：人事在证件核对页勾选问题员工进来，
服务端为每人生成一份**加密保存的核对计划**（旧证件号、修复建议、依据、把握，先展示后执行，
生成计划不改任何业务数据）；人事逐行确认/采用/手输后「确认更正 N 人 M 处」，输登录密码再认证，
服务端逐人调用既有「修改证件信息」(`changeIdentity`) 落库——每人一个独立事务，一人失败不连累他人。
计划连同每处改动的旧值/新值/依据/结果本身就是操作记录（§七、§九）。

本期只做**证件核对入口全链**（证件号一处差异）。花名册上传（表头识别、人员匹配、多字段差异、
新增员工）与 AI 确认卡是同一方案的后续包，届时本页增加上传态；表结构已按方案预留扩展。

## 二、入口与导航

| 入口 | 行为 |
|---|---|
| 证件核对页多选 →「批量核对(N)」 | 本期唯一入口。带着勾选的员工 id 进本页，页面调服务端生成核对计划，拿到计划后把地址替换成 `?planId=…`（刷新读同一份计划，不重算）；被他人认领的行在证件核对页就不可勾选（勾选位换锁「某某处理中」） |
| 无参打开 `/hr/tasks/reconcile` | 空态：说明从证件核对页进入，附「核对记录」链接（后续包在此放花名册上传区） |
| 返回 | 更正执行成功后 `pop(true)`，证件核对页清空勾选并静默刷新（任务与徽标同步减） |

查询参数只放员工 UUID 或计划 UUID，**绝不放证件号**。

## 三、路由与守卫

- 路由 `RouteName.hrReconcile = '/hr/tasks/reconcile'`，注册在 `/hr/tasks/:type` 之前。
- 页面守卫：`employee:view` 且（`employee:edit` 或 `employee:pii:edit` 任一）；生成计划另需
  `employee:pii:edit`（服务端 403 并说明缺哪个）；明文/打码由服务端按 `employee:pii:view` 决定。
- 证件核对页「批量核对(N)」按钮的可见性与本路由守卫同源（`locationAllowedFor`），页内不新增 `Perm.` 字面量。

## 四、响应式布局

- **宽屏**：`MasterDataTableView` 表格，一人一行。列：勾选（横向滚动时冻结，表头三态全选只选可勾选行）/
  工号 / 姓名 / 部门 / 证件号码（旧新对照格）/ 依据 / 把握 / 说明·结果。证件号列 `aiSensitive: true`
  （AI 页面快照只发列名，HR 页面内容本就不发给 AI）。
- **窄屏（<600 宽）**：`MasterDataTableView(compactCards: true)` 一人一张卡：标题 = 姓名，
  副标题 = 工号·部门，右上把握徽标；证件号旧新对照逐行展示，号码只露改动附近；逐项确认在底部弹层完成；
  分段收成「分类」下拉，批量条避开胶囊导航遮挡（`bottomContentPadding = max(32, 胶囊遮挡)`）。
- 右下角悬浮批量条与平台一致：`UtenSelectionSummaryPill`（已选 N 人）+ 主按钮
  「确认更正 N 人 M 处」（danger 大按钮）。

## 六、功能点

1. **计划生成**：进入即生成核对计划（每人一行）。行类型：修改（有修复建议）、仅提示（无候选/守卫命中）、
   一致（进来后已无问题）。顶部显示统计与有效期（24 小时内有效），说明「只改你勾选、采用的格子」。
2. **逐行确认 / 采用 / 手输**：把握**四档**——高（绿，新值默认采用并勾选行）、中（黄，显示建议不预选，
   点「采用」计入）、需人工（红描边：候选 ≤3 个胶囊带差异位高亮点选；>3 只给「可能出错的位置：第 2-6、
   15-18 位」）、无候选（灰，红字原因 + 输入框，请人对照证件）。手输证件号边输边校验
   （`IdCardUtils.problemOf`，不合格红字、该格自动取消采用、批量条数量随之减少）。
3. **依据**：行级「证件核对」，格级依据小字（去分隔符 / 字符纠正 / 15 位升 18 位 / 生日对齐 /
   删除重复数字 / 相邻对调 / 校验码推算 / 补末位 X）。
4. **确认更正弹窗**：列出「更正 N 人 M 处」与提示（会留操作记录、需输密码、按人独立事务）；
   确认后触发再认证，执行期间忙碌遮罩。
5. **执行与结果列**：每人独立事务调 `changeIdentity`；结果列逐行显示「已更正 1 处」（成功色）、
   「跳过：计划生成后此项已被他人修改」（警示色）、「失败：该证件号码已被其他员工使用…」（错误色，
   服务端原话）。执行成功自动释放操作人自己的证件核对认领，返回列表任务消失、徽标同步。
6. **409 / 过期态**：计划已在别处改过或执行过 → 409 `RECONCILE_PLAN_CHANGED`「这份核对已在别的窗口
   改过/执行过」，自动重读并保留未提交编辑；正在执行 → 409 `RECONCILE_PLAN_BUSY`「请稍候刷新」；
   超过 24 小时 → 「这次核对已超过 24 小时，未执行的内容已清除」，按钮「重新核对」。
7. **核对记录**：右上「核对记录」打开面板，按时间倒序列出历史计划（谁、何时、人数统计、轮次、状态），
   点开进入只读视图回看每人每处的旧新值与结果；`employee:view` + `employee:edit` 可见。

## 七、数据实体（V810，ADR-160）

| 表 | 一句话 |
|---|---|
| `employee_reconcile_plans` | 一张核对计划：来源、创建人、统计（不含个人信息）、状态 OPEN/APPLYING/CLOSED、版本、24 小时有效期 |
| `employee_reconcile_plan_rows` | 逐人行：一人一行，记生成时的员工版本（执行时比对）与行类型、执行结果 |
| `employee_reconcile_plan_items` | 每处修复建议：证件号旧值/新值/候选（pgp 密文）、差异位、依据码、把握、置信度与执行回写 |
| `employee_reconcile_applies` | 一轮更正回执：`(plan_id, request_id)` 与 `(plan_id, round_no)` 唯一（幂等），统计不含 6 位以上连续数字 |

值列全密文或统计数字；4 张表登记审计 NONE，操作记录走显式业务审计事件
（`employee_reconcile.plan_created / apply / discarded`，证件号只记「已修改」+ 依据码）；
清空业务数据时与员工档案一并保留（PRESERVE）。

## 八、权限要求

| 动作 | 权限 |
|---|---|
| 打开本页（路由） | `employee:view` +（`employee:edit` 或 `employee:pii:edit` 任一） |
| 生成计划 | `employee:view` + `employee:pii:edit` |
| 执行「确认更正」 | 创建人 + 再认证（`@RequiresStepUp`）+ `changeIdentity` 自带 `employee:pii:edit` |
| 核对记录 | `employee:view` + `employee:edit`（非创建人只读） |
| 看证件号明文 | `employee:pii:view`；无则 `****` 尾 4，且无差异位与候选 |

零新增权限码；超管照常放行。

## 九、边界情况

| 情况 | 行为 |
|---|---|
| 他人认领中的行 | 证件核对页不可勾选（锁 +「某某处理中」）；认领与接管 `identity` 仍按 ADR-154 另需超管或 `employee:pii:edit` |
| 员工绑定超级管理员账号 | 不出修复建议，行仅提示；`changeIdentity` 本身对超管账号员工 403 |
| 档案证件密文解不开（`unreadable`） | 无候选，提示「档案里的证件号码读取不出来……请人事对照证件重新登记」；手输新号仍可执行 |
| 计划生成后被他人改过 | 员工版本 / 逐项旧值守卫：该处跳过（STALE）并说明，其余人照常 |
| 新号码与别的员工重复 | 生成时候选哈希已被占用的直接剔除；手输或剩余候选执行时被 `changeIdentity` 409「该证件号码已被其他员工使用，请核对是否录错或与其他员工档案重复」，显示在该行结果列 |
| 同 `requestId` 重放（网络重试） | `(plan_id, request_id)` 唯一约束，重放返回上次结果，不重复写 |
| 两处同时执行 / 执行中进程中断 | 第二处 409 `RECONCILE_PLAN_BUSY`；中断由清理任务 5 分钟后收回租约，计划回 OPEN、已完成项保留结果 |
| 非创建人打开别人的计划 | 404（不暴露存在性）；持 `employee:edit` 的人从核对记录只读查看 |
| 计划过期 / 放弃 | 未执行项密文清空只留统计；**已执行项的旧值/新值与结果永久保留**，核对记录可回看 |
