# Windows / macOS 登录窗口与主窗口切换

## 需求与设计

用户要求 Windows、macOS 客户端采用类似 QQ 的两段窗口体验：登录时是隐藏系统标题栏的小窗口，
使用自绘关闭按钮；登录完成后进入普通系统窗口。

按默认 `frontend-design` 技能保留 Uten 既有视觉与业务约束：背景 `#F5F7FA`、表面 `#FFFFFF`、
正文 `#0F172A`、次要文字 `#475569`、交互青绿 `#14B8A6`、错误 `#EF4444`，实际颜色由当前
主题及平台品牌配置提供；继续使用现有 NotoSansSC、吉祥物、字标及表单组件。

用户随后提供左右分栏参考图，明确左侧品牌文案与主视觉、右侧负责登录。最终常规窗口为
55/45 双栏，无叠加卡片。左侧使用原创青绿色金属/玻璃 U 形流转插画，右侧复用同一份表单。
Windows 顶部布局为
`[拖动空白区][最小化][关闭]`，macOS 为 `[关闭][最小化][拖动空白区]`。
新设计仅调整窗口容器；登录按钮、账号历史、服务器恢复和 MFA 保持现有职责。

## 公共入口、合同与完整调用清单

| 入口 | 职责与接入 |
|---|---|
| `lib/core/platform/desktop_window.dart` | Windows/macOS 共用控制器；`com.uten.imp/desktop_window` 通道；模式 `login` / `main`，动作 `beginDrag` / `minimize` / `close` |
| `lib/shared/widgets/desktop_window_host.dart` | 两平台共用登录窗控件；位于整体界面缩放之外；路由内容固定槽位，切换保留输入与焦点 |
| `lib/app.dart` | 完整认证使用 main；未登录与首次强制改密使用 login；独立灾备路由使用正常窗口尺寸，原访问校验独立执行 |
| `lib/features/auth/pages/login_page.dart` | 原生 Windows/macOS 始终复用现有无卡片表单；错误、验证码、大字号继续滚动 |
| `lib/features/auth/widgets/desktop_login_layout.dart` | 两平台共用双栏布局、品牌图及三语文案；画布不足 820×520（含系统文字缩放）时回退单列；滚动视口预留控件安全区 |
| `windows/runner/main.cpp`、`win32_window.*`、`flutter_window.*` | 首次显示前完成小窗样式；原生窗口样式、工作区约束、拖动、异步关闭及主窗口状态恢复 |
| `macos/Runner/MainFlutterWindow.swift`、`Base.lproj/MainMenu.xib` | AppKit 小窗、正常标题栏、键盘输入、原始拖动事件、最小化/关闭及主窗口位置与全屏恢复；增加 Command+W |

两个阶段复用同一个原生窗口和 Flutter 引擎，避免建立第二份业务会话。登录窗口目标为 1000×680
逻辑像素，首次主窗口内容目标为 1280×800；实际尺寸受屏幕工作区限制。退出账号后恢复小窗，
下次登录恢复本次进程内记住的主窗口位置、大小、最大化或全屏状态，不新增跨进程偏好。

插画使用内置 `image_gen`，未使用 CLI/API fallback；最终 PNG 1138×1382、1,638,757 字节。
资源与完整提示词分别为 `assets/images/desktop_login_flow_v1.png`、
`build/desktop-window-20261026/imagegen-prompt.txt`。PNG 保持原始生成结果，无文字、Logo、水印。

模式请求合并过时的排队状态，重复认证刷新不重新定位窗口；迟到的原生回复不能恢复旧模式。
原生关闭延迟到通道回复之后执行。兼容旧 runner 缺少通道时不阻断应用，旧 runner 保留系统控件。

## 重复实现比较、清理与保留差异

此前只有 Windows 普通启动窗口、Windows 窗口标题通道及两平台更新通道，没有独立登录窗控件。
新增的 Dart 控件与模式控制器是两平台唯一入口，没有分别复制两份登录表单或认证流程。
Windows 启动时强制最大化的原逻辑被模式化窗口展示替代；原窗口标题和客户端更新通道保留其独立职责。

保留 Win32/AppKit 原生适配、左右按钮位置、系统主窗口行为及最大化/全屏语义差异。
Web、移动端和 Linux 不启用该通道。业务权限、登录、MFA、令牌、草稿、数量和服务端计算权威不交给窗口层。

## 验收边界

Windows 本机可编译与交互检查；macOS 已完成源码适配和 XIB XML 检查，本机为 Windows，
无法运行 AppKit 编译或 Mac 实机验收。Mac 上仍需检查输入、最小化、Command+W、全屏进出及多屏。
多显示器实际 DPI 组合与真实员工账号的业务登录验收未由原生合同用例代替。
