## 一、一张图：权限从哪来，到哪用

```
权限来源（服务端合成，PermissionResolver）
  有效权限 = 全员基础（employee 包）
           ∪ 部门配置（department_permissions，本部门 + 所有上级部门递归并集
              + V459 起各兼职部门同样含祖先递归并入）
           ∪ 个人加授 − 个人收回（user_permission_overrides，收回恒优先）
           （超级管理员 = 全部 active 权限码）
        │  写库即吊销 refresh；V135 用户 auth_version / 全局 epoch 变化
        │  让旧 staff access token 下一请求立即 401
        ▼
前端会话（currentPermissionsProvider；超管 = Perm 全量常量 ∪ 后端下发集合）
        ├── 路由守卫（app_router redirect → permission_by_path 的 any/all 双契约）
        ├── 工作台/Hub 卡片显隐（同一份 permission_by_path，单一数据源）
        └── 页面内按钮/入口（hasPerm 过滤，hide 而非 disable）
        ▼
后端（每个端点 @PreAuthorize("hasAuthority('code')")，独立于前端；
      数据范围按模块过滤：owner / user_data_scopes / *:view:all）
```

## 二、每个页面的权限（路由守卫）

- **唯一数据源**：`lib/core/router/permission_by_path.dart`。
  - `requiredAnyPermFor(location)`：返回 `null` = 登录即可；`[]` = 已知前缀下的未知单据段 → 404；非空 = **任一满足**即放行。
  - `requiredAllPermsFor(location)`：组合门槛（如入职页要求 `employee:create + employee:pii:edit` 同时具备）。
  - 单据类页面按 URL 段经 `DocumentPermissionCatalog`（`lib/shared/auth/document_permission_set.dart`）派生 view/create/edit/delete/approve/reverse 六类动作权限。
- **拒绝行为**：any/all 任一不满足 → 重定向 `/access-denied`（明确说明 + 返回工作台）；未知动态段 → `/not-found`。守卫在 `route_access_policy.dart` 的 `employeePermissionRedirect`，由 `app_router.dart` 全局 redirect 调用。
- **深链不可绕过**：菜单里看不见的页面，手输 URL 同样被守卫拦下；后端仍独立 403/404。
- **审核详情子路由与列表同码（2026-09-03）**：财务「订货审批任务中心」新增专用审核详情页
  `/finance/procurement-approvals/:caseId`（双击落点，底部通过/驳回/返回）——守卫用
  `startsWith` 覆盖子路由，与列表同用 `finance_order_approval:view`（同销售确认页范式）；
  批准/驳回是**服务端动作级** `finance_order_approval:approve/reject` + 实时审核资格，
  前端按钮只按服务端 `allowedActions` 渲染。零新增权限码，surface 复用 `finance.order-approval`。
- **明确不设权限的页面（登录即可，设计如此）**：`/dashboard`（工作台首页本身全员可达，内部卡片逐个按权限过滤）、`/profile` 系列（本人资料，字段策略由后端 ProfileFieldPolicy 管）、`/settings`（仅 `/settings/device-receipts` 要求 `audit_log:view`）、登录/改密/拒绝页等基础设施路由、访客门户（独立访客会话）、`/page-permissions/:surfaceKey`（页面内「本页权限」工作台——安全性由服务端 surface 能力与负责人子树把关，见权限管理页.md §四-A）。

## 三、工作台的权限（集散层与任务中心）

**设计原则（ADR-007）**：工作台是功能**集散入口**，不是独立权限域——卡片显隐直接复用路由守卫的
`permission_by_path` 映射（单一数据源），超管授了什么权限，工作台就出现什么模块。因此**没有泛化的
`workbench:*` 权限码**；各任务中心要么复用领域查看权限，要么拥有自己的专属码：

| 工作台/任务中心 | 路由 | 守卫权限 | 后端 |
|---|---|---|---|
| 统一履约·仓库工作台 | `/operations/workbench/warehouse` | `stock_doc:view` | 同码 @PreAuthorize |
| 统一履约·采购工作台 | `/operations/workbench/purchase` | 任一采购单据 `:view` | 同码 |
| 统一履约·委外工作台 | `/operations/workbench/subcontract` | `subcontract_application:view` | 同码 |
| 工程研发部任务中心 | `/rd/tasks` | `rd_task:view` | `rd_task:view/create/resolve/assign` |
| HR 任务中心 | `/hr/tasks` | `employee:view` | `employee:view`；接管需 `employee:task_takeover` |
| 品质任务中心 | `/quality/task-center` | 任一 `procurement_inspection:view` / `production_quality_inspection:view` | 同码 |
| 仓库任务中心（出/入/领料，2026-09-01） | `/warehouse/tasks/{outbound,inbound,draw}` | 按页 any-of 仓库/销售/委外出入视图权限 | 同码 |
| 生产补产物料待办（FQC） | 看板内嵌 `/production/schedule` 等 + 队列页 `/quality/production-inspections` | `production_plan:view` / `production_quality_inspection:view` | `production_fqc_replenishment:view/confirm` |
| 生产调度工作台（V470 起拆码） | `/production/schedule` | `production_plan:view` | 同码 |
| 生产进度总览（V470） | `/production/progress` | `production_execution:overview` | 同码；仍受生产计划 maker/部门对象范围约束 |
| 我的车间任务（V470） | `/production/workshop-tasks` | `production_execution:view` | 同码；服务端再按主职/兼职车间子树、负责人或车间经理过滤 |
| 旧待审收件台兼容路径(V493退役) | `/reviews/inbox` | 登录后重定向 `/dashboard`，不读取业务数据 | 原页面及聚合 API 删除；旧授权码 active/assignable=false，surface 停用 |
| 销售订单修改复审 | `/finance/sales-order-changes` | `sales_order_finance:view` | 审核动作仍需 `sales_order_finance:confirm` 及实时资格，共用 `finance.sales-order-confirmation` surface |
| 财务订货审批任务中心（2026-09-03 补录） | `/finance/procurement-approvals`（列表）+ `/:caseId`（专用审核详情，双击落点） | `finance_order_approval:view` | 同码；通过/驳回另需动作级 `finance_order_approval:approve/reject` + 实时审核资格（ADR-027 §八） |
| 采购/委外应付结算工作台（V475 挂面） | `/finance/payables` | 任一 `ar_ap_ledger:view` / `subcontract_loss_claim:view` / `supplier_settlement:view` | 页内结算/索赔/红冲/付款/抵扣动作码 + `finance:view:all`；挂 `finance.payables` 面（13 码） |
| 物料分析准备工作台（2026-09-05 收窄） | `/production/material-analysis` | `production_material_analysis:view`（动作另行授权） | 备料 notify / 路线 CONFIRM_ROUTES / 生成计划 generate+approve 逐动作 `@PreAuthorize`；组合口径见下方小节 |
| 委外准备中心（已退役） | `/subcontract/preparations`（兼容重定向到 `/subcontract`） | 无——2026-09-05 ADR-072 起页面与 `subcontract_preparation:view/start` 权限停用；有子层委外件由系统自动发单给计划（草稿期自动建前置生产分析），计划在物料分析工作台安排车间；分批通知仍需 `production_material_analysis:notify` |

**统一履约三页没有专属目录码，是设计决策而非遗漏**：能用工作台的人本来就需要对应单据的查看权限
（从工作台点进单据仍逐单校验）；管理端在对应业务模块（仓库/采购/委外）授权即可，无需重复建码。
带专属码的(`rd_task:*`、`production_fqc_replenishment:*`、V470 的
`production_execution:view/overview`)已登记进权限目录(工程研发·研发任务、生产管理·FQC 补产、
生产管理·我的车间任务与进度总览)，部门配置与个人覆盖均按
普通码操作。

### 部门提醒、操作授权与任务徽章的边界(2026-09-07)

- 页面查看、页面内操作、对象范围和弹窗接收是四道不同检查。中央明确个人加授的财务审核人仍可
  在权限及对象范围内审批；部门外个人加授不会自动产生财务部门弹窗，要接收需维护主职或兼职部门。
- `ReviewNoticeAudience` 在登录查询、到达 feed、详情 DTO 和弹窗心跳按当前部门祖先与有效权限复核。
  超管同样须命中部门；仅 view 不弹，须同时持通知读取、目标页 view 与相应确认/处理/开工/创建动作。
  财务初审/改量复审、IQC、计划分析、车间、仓库入库/发料及退回贷项统一走此规则。
- 登录待办先按有资格的事件集合在 SQL 内筛选再分页，避免旧部门任务占满 20 条上限；到达 feed
  过滤失去资格的任务仍推进原始 keyset 游标，避免永远重复扫描。部门查询每批一次，状态表批量读取。
- 历史未绑定 aggregate 的通知只作历史信息，不成为永远无法办结的弹窗。办结、稍后、删除、调岗或
  收权后心跳撤卡；切换账号/模拟身份取消旧检查与旧对话框，迟到响应不得跨身份展示。
- 常用功能不再提供待审收件台。实际任务页面的服务端 count 是徽章真源；已读/稍后不清业务任务，
  不叠加已退役收件台的通知计数。跨域弹窗回工作台，各条目直接进入其领域任务页面。
- 委外前置自制 GET `/production/material-analyses/subcontract-make-tasks` 使用
  `production_material_analysis:view` 或 `subcontract_application:view`。委外侧沿用共享申请任务池只读，
  纯计划侧的 count/list 同时应用生产 owner 范围；`NOTIFY_SUBCONTRACT` 只在 view+notify、对象可写及
  实际可通知量均满足时返回，不因委外查看权出现计划写按钮。

### 物料分析准备工作台的权限组合（2026-09-05）

- 页面、工作台卡片及只读供料进度统一要求 `production_material_analysis:view`。新建另需 `create`；
  `/production/plans/new` 在重定向前同时校验 create/view，生产 Hub 用同一路由规则决定新建入口，
  缺少分析 view 时保留仍有权访问的生产计划历史，不因孤立 create 授权让入口消失。
- 主表多选、下拉与“确认路线”使用route+CONFIRM_ROUTES。ROOT_SUPPLY与组件共享真实物料UUID；
  根行只选自身，缺根字段的旧响应不伪造写身份。历史确认/手动草稿优先，再使用货品、颜色、单位UUID
  的上次路线，最后回退主档/委外。读取记忆不提交、不授予任何额外能力。
- 「路线说明(选填)」入口已于 2026-09-05 下线（用户口径：准备页只保留确认路线），路线确认不再
  采集原因；服务端 API 仍接受可选 reason，V477 的「原因可空」约束宽松继续生效以支撑无原因确认，
  历史已存 route_reason 原样保留可查。
- 三类任务入口仍在同一权限面：普通备料action和根BUY/委外使用notify+NOTIFY_SUPPLY；
  自制下达车间走 ADR-71 原子端点 issue-plans（generate；同事务审核再叠加 production_plan:approve，
  权限码与旧 plan-preview/generate-plan 完全一致，零新码），不能用notify创建第二个根MAKE child。
  已计划、有效供料或产出交接会冻结根路线，服务端独立校验。
- V478追加根节点与产出FULFILL/REVERSE账本，V477/V478均不新增权限码/默认grant。
  production.material-analysis、中央revoke优先、负责人ceiling、不可转授view/跨分析让料和
  公司对象范围限制保持。迁移和最终验证见[本轮记录](../99-项目治理/2026-09-05-顶层路线记忆与确认修复验收记录.md)。

## 四、管理端总入口（`/admin/permissions`）

- **入口权限**：`account:support` 或 `authorization:manage` 任一可进；support-only 只渲染账号支持区
  （列表/补开/状态/重置密码），授权/部门/数据范围区必须 `authorization:manage` 且后端再校验超管。
- **目录浏览器**（`permission_catalog_browser.dart`）：功能模块 → 子类 → 权限项三级展示，数据来自
  `GET /api/admin/permission-catalog`（`DepartmentPermissionAdminService.catalog()`，固定 11 个模块排序：
  基础资料/销售/采购/委外/生产/仓库/财税/工程研发/人事行政/品质检测/系统管理，未登记归「其他」）。
  批量授权仅对 `bulk_assignable` 开放，且受 `authorize_all_excluded.dart` 排除清单约束（审计、授权、
  余额调整、资产生命周期、优先级/重分配、供应商退货等永不随「全部授权」发放）。
- **页面内权限（surface）**：`permission_surfaces` 是页面—权限精确关联的唯一来源；
  V328 建立 85 个，V437–V453 递增至 102 个，V455 补 10 个守卫页 surface 并退役
  `quality.lab-test` 空壳面后 111 个，V456 接线 5 个业务页入口并退役 `quality.inspection`
  旧面后 110 个，V459 新增 `reviews.inbox`（我的待审收件台，仅目录登记无委派入口）、
  V470 新增 `production.workshop-tasks`、V475 补 `finance.payables`（应付结算工作台
  13 码)与 `quality.inspection-records`(检测记录 2 码只读)后历史共114个；V486停用
  `subcontract.preparation`、V493停用 `reviews.inbox` 后活动面为 **112 个**。业务页 `/page-permissions/:surfaceKey`
  供负责人在页面内做人员授权（`ManagerPermissionDelegation`）。页面内授权**入口**由
  `lib/shared/auth/page_permission_scope.dart` 的唯一业务映射决定——V456 起业务守卫页
  均挂守卫同源的专属 surface（品质任务中心 4 码含 IQC/FQC 决定动作、生产成品质检、
  仓库质检结果、生产调度/进度 view-only；V475 补齐应付结算工作台与检测记录两个漏网），
  admin/自助页按设计无
  委派入口，生产链路健康在对象范围收口前保持 fail-closed。服务端启动时一次加载，
  不从前端路由补目录。V455 下线 15 个、V475 再下线 1 个（`viewcontext:scoped`）双端
  零引用孤儿码（lab:test:*、attachment:manage
  等，见 [迁移说明 75](../数据迁移/75-V455权限目录收口.md)、
  [迁移说明 76](../数据迁移/76-V456页面内授权入口接线.md)）。
- **动作分类**：`permissions.action_type` 仅允许
  VIEW/CREATE/EDIT/DELETE/APPROVE/IMPORT/EXPORT/EXECUTE/CONFIGURE/ASSIGN 十类。

## 五、新增一个页面/权限的操作清单

1. **后端**：新建前向 Flyway 迁移 `INSERT INTO permissions`（code/name/module/category/action_type/
   assignable），零默认 grant 或按部门 ID 显式 grant；**同步 `server/ops/reset_business_data.sql`
   白名单与 `docs/数据迁移/README.md` 头部计数**。已应用迁移与
   [55-权限模块分类](../数据迁移/55-权限模块分类.md) 是历史权威，**只读不改**，新码写进新迁移。
2. **前端**：`lib/shared/auth/permissions.dart` 加 `Perm` 常量（人工对齐，靠契约测试兜底）；
   `permission_by_path.dart` 注册 any/all 映射（新页面守卫 + 工作台显隐一次到位）。
3. **页面内**：按钮/入口 `hasPerm` 过滤（hide 不 disable）；后端每个端点补 `@PreAuthorize`。
4. **测试**：`router_access_policy_test` / `page_route_permission_dependency_test` /
   `document_route_segment_test` + 对应 feature 测试；后端 `DepartmentPermissionAdminServiceTest` 等。
5. **文档**：权限管理页.md 对应节登记新码与 surface；页面总览行同步路由与权限变化。
