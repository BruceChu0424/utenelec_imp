# 货品 BOM 并排对比与替换

分支：`uimp/goods-bom-comparison-20261101`；基线：`48ca76f73`。分类：前端交互及已有 BOM 编辑合同调用；不新增业务计算、数据库迁移或发布。

## 设计计划与复核

沿用 frontend-design 和 Uten 主题。浮窗外壳、标题栏、货品页头与内容统一使用当前主题 surface（浅色 `#FFFFFF`），不再混用灰色外壳与白色内容；主页面原有 `#F5F7FA` 背景保持独立。正文 slate `#0F172A`、操作 teal `#0F766E`、相同 success `#047857`、差异 error `#B91C1C`；深色使用现有主题及语义色。字体沿用应用中文字体及 textTheme，编号与精确数量保持原文。窗口内容统一左右 12px；窗口外沿 8px，中央保留可点击且可拖动的三点手柄。

```text
┌ 左货品 / 更换 / 上下 BOM ┐ ⋮ ┌ 右货品 / 更换 / 上下 BOM ┐
│ 名称、编号、组件表       │   │ 名称、编号、组件表       │
└─────────────────────────┘   └─────────────────────────┘
                 点击 ⋮ → BOM 对比 / 均分
┌ BOM 对比 · 相同 / 差异 / 左独有 / 右独有 · 重新分析 ───────┐
│ 左货品                   │ ⋮ │ 右货品                  │
│ 编码 → 名称 → 颜色 → 规格 → 设计使用数量                 │
│ ☑ Q70045 … 相同单元格绿 / 不同单元格红（不额外加行）     │
│ 自动编辑 / 分侧保存 / 选中或全部替换 / 服务端影响预览     │
└─────────────────────────────────────────────────────────┘
```

直接复用组装信息的 `MasterDataTableView`、`UtenTreeTableCell.compact` 及其列宽测量、表头设置、勾选、树形连线和横向滚动，不另画列表卡片。左右垂直滚动联动，根组件勾选共用一个集合。编码强制作为第一个数据列，后面默认是名称、颜色、规格、设计使用数量；独立的新版比较布局键防止旧名称/状态优先布局被重放。仅在实际不同的单元格标红，相同字段保持绿色；不产生差异字段子行，箭头只展开真实子装配。缺失组件的对应数据格标红；库存/学习等上下文不冒充可复制配方。内部真实关联仍以 UUID 为准，编码是优先核对入口，不按同名硬配对。

有权限的可写根货品进入后自动创建普通 `GoodsBomEditDraft`，单元格沿用组装页公共 `BomInlineEditCell`、输入主题及选择器。数量、备注、颜色、计量规则等修改先暂存，合法输入约 250ms 后重新比较；规格、型号等主档字段仍要求服务端货品可写能力和 `goods:edit`，并以共用属性预览同步两侧。编码、学习/真实用量和未获授权的字段只读。实际子组件仍可在其所属根的编辑会话内维护，保存预览继续披露共享影响。

左右根使用独立事务，不把两份无关 BOM 当作同一组装树提交。各侧保存复用 snapshot/preview/commit、版本、权限、期间料和未知回执合同；一侧保存不能清掉另一侧有效或无效的草稿。所有输入控制器由会话持有，过滤隐藏、滚动卸载、临时只读与延迟回执不会丢失输入；相同十进制值重新比较时不改写用户的尾零原文。编辑后可继续跨窗替换，来源使用当前合法草稿值；切换对象前处理未保存草稿。替换确认仅暂存，最终保存才写入。直接改单元格与选中/全部替换继续各自显示准确影响预览，未知保存结果仍只能核对原请求。身份/权限/请求代次变化后旧结果不发布，离开确认框随原窗口所有者关闭。窄窗口保留横向双栏滚动；三个及更多窗口可从标题栏选择具体比较对象。

整份替换针对当前货品直属组件清单（含对子装配的真实引用），不会递归覆盖共享子装配的配方或货品主档。共有 UUID 的子装配本来就引用同一份 BOM；左右独有装配展开读取真实子组件。目标独有组件仅在被勾选或明确整份替换时删除。数量、单价等按原始十进制文本比较，等值尾零不造成假差异；库存及真实用量不是配方冲突。

## 目标侧按钮、顶部通知与替换草稿补充（2026-11-01）

本轮仍默认使用 frontend-design，复用当前 Uten 主题和表格。四个替换动作分成两组，左表下方放两个“用右侧替换左侧”动作，右表下方放反方向两个动作；动作组、货品头、表格跟随同一比例及横向视口。保存动作归属对应侧，单个货品被两侧同时打开时只有一个保存入口。普通结果与保存成功统一通过 `context.appInfo/appSuccess` 的 `AppNotificationHost` 从顶部滑出，取消原蓝色内联占位；待恢复和失败提示保留可持续处理入口。

两表继续共用根组件选择集合。修改合法输入后可以继续替换，不必先保存。`GoodsBomEditDraft.fork()` 在相同身份下分支已有目标草稿，比较准备过程只更改候选；弹窗明确来源/目标编号、增删改/排列及共享影响。确认替换后才接入目标草稿，取消或红色×不影响先前编辑。未选中的修改、另一侧草稿和精确小数文本保留。已替换或新增的组件可继续编辑、重比和再次替换。替换阶段只请求服务端预览，不执行 commit。

最终点击对应侧“保存修改”再次弹窗核对，再按原 preview/commit 合同写入；每个根独立事务，不声称两个无关根原子提交。关闭/重新分析/切换时如有未保存内容，可继续编辑、放弃或先核对保存；选择保存时依次处理脏根，全部成功才离开，任一取消或失败保留剩余草稿。主动放弃某侧也需确认。保存结果未知时保留原请求、禁止丢弃/切换，并由同一请求核对回执；权限或所有者变化会移除所属确认框。

公共边界：新增 `copyBodyFor` 在原设计字段复制合同上解析已持久化来源，新增临时关系和换成其他组件的旧关系不得作为持久化来源 ID。`bindCopySource` 只绑定来源快照，不导入另一根写命令；最终保存仅刷新借用的只读来源证据，绝不重定目标版本或共用主档的乐观锁。源或目标真实冲突继续由服务端拒绝。普通组装/批量/分类等原复制调用保留原工作流，无需分支既有草稿；未复制新增来源算法。
