# ADR-167：实际超限报工与本批产出处置

- 日期：2026-10-07。
- 状态：用户授权实施；源码及本地回归不代表公司服务器已部署。
- 取代 ADR-118 中“新超限报工必须转追加生产计划”的规则；历史追加计划、证明与续报保留原合同。

## 1. 数量合同与车间入口

原需求及生产计划1000，允许超产10%，实际1200。旧流程在1100拦住报工，转追加计划又使整张实际报工等待审批。新规则一次录入1200，服务端锁定同一执行任务后拆为：需求1000、容差内公共超产100、超限待处置100。超需求为200，超授权为100，每份保持同一实际产出批次、真实材料及成本来源。

额度按执行任务累计，包含有效草稿占用、已审产出及历史未续报追加的保留额度，不能每次报工重新获得10%。精确销售/内部需求份仍各自受约束。新原始超产切片保存数据库生成的计划量、比例/版本、此前实际超产和可用额度快照，后续调整比例不会自动洗掉已登记的超限。

超限须填写原因，整单预览展示允许范围内及待处理数量，草稿恢复和幂等指纹保留输入。正式报工仍经车间主管审核。品质恢复沿原授权来源、固定追加批次沿原证明，不能借新入口扩大授权。

还没生产、预计超量时继续走比例申请；已经完成则走本批处置。批准本批不更新原计划、不提高任务比例、不改变货品比例记忆。

## 2. 本批处置

每个原始超限切片有唯一处置对象。草稿不推待办；日报审核后通知有审批权限且能读取该计划的计划人员。列表、徽章、详情及审批使用一致对象范围。

- 同意接收为公共备货（ACCEPT_PUBLIC）：本批数量获得放行授权。
- 继续待处理（HOLD）：保留实物和冻结状态。
- 要求核实（RETURN_FOR_REVIEW）：保留实际报工，记录核实原因，不自动反审核已有下游业务的日报。

本版本按精确切片整体处置，不在审批框改数量、直接变更订单归属。公共库存后续走正常预留/领用。数量更正、品质返工/报废和日报红冲走现有受控链；不同意超产不等于删除数量或报废实物。

决定保存操作者、时间、原因、版本、幂等键和请求指纹，只追加历史。待处理可继续决定，接收为终态；来源反向撤回则撤回处置并结束通知。同版本并发仅一次成功，同键同内容不重复执行决定或放行，并返回处置对象当前状态；旧 HOLD 键在后续接收后重放会看到当前 ACCEPTED，而不是恢复过去的 HELD。同键异内容拒绝。

处置列表、详情和确认框中的计划量、实际量、额度内量、超限量及比例由服务端 `ExactDecimalText` 输出为十进制字符串，前端原文解析、去尾零及百分比换算均不经过 `double`。例如 `9999999999999.9999` 和 `0.0001` 必须逐位保留。旧数字回包若已超出安全精度范围则标为未知并禁止确认，不能把舍入值当原始审批数量。处置请求仍只有动作、原因、版本和幂等键，不提交或改写业务数量。

同一精确显示合同覆盖本次新增的报工预览 `withinAuthorizationQty` / `overLimitQty`。既有预览 `actualQty` 和车间工作台 `overLimitPendingQty` 保留数字字段兼容旧调用，同时提供 `actualQtyExact` / `overLimitPendingQtyExact` 原文字段给新确认框和任务列表；已有数字只用于原有比较，不再用于重建新增显示值。报工预览数量与当前输入原文不一致、或新增数量缺少可信表示时停止确认并保留输入，不静默接受舍入结果。

报工写入沿用四位数量、六位单位率：完工量和不良数保留输入原文，大量通过 JSON 字符串绑定服务端 `BigDecimal`，安全范围内的小量保留原数字格式。详情、可报来源、固定追加与直送候选提供只读 `*Exact` 原文字段，编辑已有单、默认数量、追加申请及申请快照不得从已舍入的 `double` 播种。旧数字数量达到 `1e10`、六位单位率达到 `1e6` 时缺少原文即停止，不反推；旧本地高量草稿也须有数量原文确认标记，缺标记保留输入供用户核对重填。仅真实输入事件（含粘贴）清除待核对标志，程序回填和复制行不得冒充确认。

直送仍复用先固定条目、再按先急后缓补建议、共享接收量与同来源额度、最后核对固定条目的四阶段规则；所有数量刻度改为 `BigInt`，六位率换算在定点数上向下控制上限，原始固定份额、重排结果、草稿和请求均保留十进制原文。合法大数量可按原来源正常直送，例如 `9999999999999.9999` 分为直送 `9999999999999.9998` 与送仓 `0.0001`；旧候选高量缺少精确事实时保留输入并停止分配，不静默改为全送仓。物料实耗、重量、业务授权及迁移 SQL 不属于这次精度修复范围。

## 3. 品质、实物交接和库存

同一实际批仍一次登记实物位置、一次或分次质检。合格依次分需求、计划公共、容差内超产、超限；不良反向扣。全部1200合格时，未授权100保留PASS事实，暂不生成FINISHED_IN；1100正常办理。

批准只续放原合格事件尚未放行余额。先审批后质检，后续按当前授权放行；先质检后审批，生成待实际点收任务，不沿用过去登记时的自动点收承诺。恢复报工继承原超限来源授权，批准也可续放恢复链已合格未放行量。

计划授权、品质合格、仓库实收是三个独立条件。审批不直接加库存；待处置产出不能直送、领用、销售发出或算需求交付。数据库再次校验品质放行命令与成品入库来源，不能绕页面建单。

## 4. 实耗与成本

不新建成本池或生产任务，不因审批重复领料、耗料、记产出。全部实际超产200留在原成本范围，产出目标完整1200，不能只用已放行1100分摊全部投入。

例如已知成本120元、目标1200，1100真实入库对应110元，待处理100对应10元留在原在制成本。批准不产生第二份成本，后续点收沿原成本链结转。已知/未知成本继续沿既有完整性规则，超限待处置时不得标记成本最终完整。

申报、耗料、合格/不良/待检、放行、实收/未收分别守恒；核实、延期不抹除实际材料成本，反向沿同源追加式冲回。

## 5. 实施与验收范围

V822实现实际分片、冻结额度快照与累计守卫；V823实现本批处置、恢复来源授权和审计；V824实现品质排序、延迟放行、入库授权与成本完整性。旧迁移不改。

页面覆盖日报/草稿/详情、计划入口、处置列表/详情、权限路由、通知和徽章。重点回归1000/10%/1200、累计/草稿/并发额度、历史追加、恢复链、审批先后时序、不良/少收、权限/版本/幂等、完整成本与部分入库成本、来源反向。现场行为须另行按发布流程升级后生效。
