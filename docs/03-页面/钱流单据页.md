# 钱流单据页

更新：2026-09-21。销售收款、采购付款、一般费用、其它收入、银行存取款共用列表、详情和编辑页面，入口位于 `/finance/receipts`、`payments`、`expenses`、`incomes`、`bank-transfers`。

## 当前单据与历史原始记录

列表以独立的「来源」列区分当前单据和历史记录（只读），原来的草稿、已审、红冲状态照实显示。历史记录的「已审」是保留的旧系统状态，不表示可以重新审核或生成新的资金流水。

历史资金头的详情保留金额、原始明细和只读附件，显示常驻说明；编辑、删除、审核、红冲、费用财务确认均不提供。直接打开编辑地址也会先核对来源，再返回只读详情，不创建可编辑表单或上传入口。原始记录的更正须先核对原始凭证，不能通过重新执行当前业务动作消除历史差异。

旧系统收款无法证明属于货款核销或订单预收时，明确显示「历史收款类型待核实」，展示原始币种、汇率、收款金额和本币金额。不根据没有核销明细推断为客户预收，也不把原始金额显示为本次应收核销结果。此前已保存的历史类型仅作为「历史标记（待核实）」展示，不据此生成新的预收汇总或可用资金来源。

预收抵扣面板也不允许选择带历史标记的资金源；即使旧响应保留了余额，页面仍按只读处理。正常 `AR_SETTLEMENT` 与 `CUSTOMER_PREPAYMENT` 单据继续使用各自的权限、版本和金额守恒流程。

## 销售收款单：汇率预填、收款方式与「找不到销售单」(2026-09-21，V632/ADR-097)

- **本批汇率报价按币种预填**：引用应收或选定预收订单后，原币是本位币则锁定为 1；外币取币种主档参考汇率预填(主档没维护则留空)，财务按本批银行回单或代理结算单核对修改。只在汇率框为空或仍是默认 1 时预填，不覆盖财务已改的值。收款汇率与应收记账汇率(出货财审放行时冻结)的差额照旧进「收款汇兑损益」，不回调应收。
- **收款方式字典为空不拦保存**：V273 只带 3 条「待同步名称」占位行且不进选择器；V632 在库里没有任何已确认方式时补一套标准方式(银行转账/现金/支票/承兑汇票)。字典仍为空时下拉不再必填，服务端本就允许空方式。
- **订单没出货就没有应收**：「货款收款(核销已发货的应收)」的「引用应收」只列仓库确认出库后立的应收；客户只下了订单、货还没发时列表为空，收到的是定金/预付款要走「登记订单预收(订单未发货的定金/预付款)」。空列表处提供「改为登记订单预收并选择订单」一键切换(需 `finance:view:all` + `customer_prepayment:view` + `finance_receipt:create`)，切换后直接打开订单选择。

## 权限与数据合同

历史原始收付款只读，与可继续结算的历史往来余额分别处理。应收应付的「历史往来余额」仅在原币余额已知、币别已知且余额严格为正时，允许引入新收付款；零数、负数及币种未核实的金额不能推断为预收、预付或贷项。「财务收款」表示来源单据类型，不等同于客户预收。

原单来源无法唯一对应时，台账显示「历史期初（原单来源待核实）」和具体匹配状态，不虚构原单链接；这不否定独立核验的正往来余额。应付工作台以「其他往来」筛选这类记录。新核销按后端的快照业务截止日和金额守恒规则执行，页面不会把缺失金额或汇率补成 0 或 1。

历史余额作为结算目标，与历史资金作为来源分开控制。旧贷项即使保留 `CREDIT` 类型，也不显示应用入口；有完整证明的正历史应付可接受符合原供应商、币种、汇率规则的新贷项。客户预收仍须满足真实订单及来源关联要求，不能通过历史余额证明补造关联。贷项面板分页加载候选，第一页没有匹配项也能继续查看后续页，已选行与手工金额不丢失；金额共用 24 位精确十进制处理，不经过二进制浮点或局部四位截断。

总账自动生成仅处理当前可重建来源。历史原始资金头及其既有 AUTO 凭证不删除、不重建，也不因批量生成回写历史费用单的凭证 UUID。直接过账和反向入口执行相同边界。新收付款仍可按合法核销链结算旧往来余额并生成自己的凭证；不会因为期间内存在历史记录而整期跳过。这里限定的是生成作业的写入范围，历史凭证仍完整进入全账报表和平衡、关账核验，不能把历史不平差异从真实账里隐藏。

现金类 AUTO 凭证只有在来源 UUID 精确对应当前非历史资金头时，才属于可重建集合。旧凭证如果缺少可证明的来源 UUID，也保留原样，不能通过单号猜测归属后删除。来源未核实的「历史期初」往来余额不据此生成新的销售、采购或委外立账凭证。

受审历史往来的正余额可以成为后续新收付款或合法抵扣的目标，前提是原币、币种、本币和初始余额均有来源证明，动作发生日在历史快照截止日之后。资格按初始正余额判定；本次全部结清到零不应使刚完成的合法动作失去资格。容量仍按动作前的实际未结余额检查。

新收付款的反向只恢复本次动作。历史累计如果确认为负数，恢复下限取不可变证明中的初始累计，而不是擅自改成零；例如原额 0、历史已结 −8、未结 8，新收/付 8 结清后，反向应恢复未结 8、累计 −8。缺少可核验依据时拒绝猜测，当前非历史往来的累计下限仍为零。

抵扣的资金来源必须是当前有效的原生资金记录，历史负余额或旧收付款不会因此变成可用预收、贷项。供应商侧只开放现有采购退货贷项及已确认索赔，供应商预付款资产链仍未开放。客户预收仍必须满足真实销售订单、来源分摊及同客户同币种限制；无法证明订单归属、或仍有未归属历史到账时明确拒绝，不补造旧核销明细。后续抵扣记为独立事件，反向恢复该次抵扣；原始历史证明和已完成的新现金核销分别保留。

当前单据继续按单据类型权限、数据范围和状态决定动作；新建当前单据不受历史列表的只读标记影响。后端服务和数据库同时拒绝对历史原始资金头进行业务推进，页面禁用只是交互层的同一规则。

列表与详情统一消费 `legacyImported`。兼容旧响应时，非空 `legacyId` 同样表示历史来源，显式历史类型 `LEGACY_UNCLASSIFIED` 也保持只读；缺失新字段不使旧记录重新变为可写。预收来源行消费同一标记，旧响应的收款来源 legacy 身份也不能作为可操作资金。

## 金额提交口径(ADR-112, 2026-09-23)

费用、其它收入、银行存取款的明细只提交实际金额原文(`amountOriginal`), 本币由服务端按表头汇率精确派生(本位币单据汇率 1),
表头合计 = 明细合计; 请求再带 `amountLocal` 或表头金额会被拒为 400。收款/付款的本币同样只由服务端计算。
资金账户余额与对账流水统一由 `AccountFlowLedgerService` 过账, 红冲按原始流水冲回。
**红冲要求涉及的资金账户仍启用**(与审核同一口径): 账户已停用时提示「红冲涉及的资金账户不存在或已停用，请先启用账户后再红冲」。
这对银行存取款是一次收紧——以前红冲不校验转出/转入账户是否启用; 红冲本身是一笔新流水, 停用账户不应再有流水,
需要红冲时先启用、红冲后再停用, 过程留审计。付款/收款/费用/其它收入/委外现金赔偿的红冲原本就要求账户启用。
