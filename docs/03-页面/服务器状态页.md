# 服务器状态

> 2026-09-08 新增；2026-09-10 界面改仪表盘并新增线程/错误/会话/积压/附件/定时任务探针。
> 源码与自动化测试已通过，尚未部署到公司服务器（实机 8080 未起，实时 JSON 待补验）。

入口为工作台「系统管理 → 服务器状态」，地址 `/admin/server-status`。只读权限 `server_status:view` 独立于授权管理，只有获授该权限的员工可以查看；访客不能查看。页面不提供任意命令、重启、删目录或修改系统配置的按钮。

## 显示内容

| 项目 | 口径与预警 |
|---|---|
| 处理器占用 | 运行环境 CPU 采样；80% 黄、95% 红。短时升高可以观察，持续偏高需要检查 |
| 系统内存 | 显示占用比例与已用/总量；Linux 按 MemAvailable 计算，可回收文件缓存不误算为内存耗尽；80% 黄、90% 红 |
| 平台应用内存 | Java 堆占用与上限，与整台服务器内存分开；80% 黄、90% 红 |
| 数据库连接池 | 活跃连接占平台连接上限；80% 黄、95% 红 |
| 磁盘空间 | 系统、附件、数据和配置的备份目录；同一文件系统合并显示，80% 黄、90% 红。不把磁盘余量叫作内存 |
| 数据库 | 后台只读探测耗时与连接数量；探测200ms黄、1000ms红，连接80%黄、95%红；连接失败红色 |
| 最近备份 | 核验过的本地备份完成时间；30小时黄、48小时红。最近备份检查失败单独报红，不冒充“备份文件已损坏” |
| 平台线程数 | 平台 Java 进程当前线程数；400 黄、800 红（`UTEN_SERVER_STATUS_THREADS_WARNING/CRITICAL` 可调）。持续增长通常意味着连接或后台任务没有释放 |
| 最近错误日志 | 最近15分钟（按60次采样滚动）新增的 ERROR 日志条数；10 黄、100 红。计数自本次启动累计，**重启后重新计数**；读不到计数器时显示未知，不按“无错误”处理 |
| 在线会话 | 未撤销且未过期的员工+访客登录会话数（按 `session_id` 去重），每60秒更新；无阈值，只作参考不报警 |
| 待处理事件积压 | 业务通知 outbox + 附件清理 outbox 的待处理条数与最早一条等待时长；超过50条或等待超过5分钟黄，超过500条或30分钟红；每60秒更新 |
| 附件占用 | `attachments` 表登记的附件数量与实际存储字节合计，每5分钟统计一次；**不遍历文件系统**，统计超时显示未知而不是0 |
| 定时任务最近执行 | 每个 `@Scheduled` 任务的上次开始/结束/耗时/异常类名；超过2个周期未执行标黄，连续失败≥3次标红。按日程（cron）触发的任务没有周期，只显示最后一次，不判“超期”。记录在内存，**重启后清空**；只保留异常类名，不下发异常消息 |

读不到、未接入或过期的值显示灰色和具体原因，不用0填空，也不保留旧绿色状态误导用户。颜色同时配文字和图标，提示图标可悬浮、触控查看。版本标识未配置时如实说明，不拿开发版本号冒充服务器安装版本。

云端（cloud）档案下定时任务包装器不启用，「定时任务」区为空；数据库连接池当前把主库与只读副本两个连接池合并计算。

## 界面与动效

> 2026-09-10 由通用卡片改为仪表盘式布局，全部使用公共组件，页面不私造动画。

| 区块 | 呈现 |
|---|---|
| 运行总览 | 左侧大圆环 [`UtenGaugeRing`](../02-组件库/UtenGaugeRing.md)：值=**最差的百分比指标**（含磁盘），色=整体状态，环下小字「需要留意 N 项 / 暂无预警项」；右侧为状态徽章、说明、采集时间/运行环境/应用版本/已运行，以及「每15秒自动刷新，离开页面后暂停」。标题右侧 [`UtenLivePulseDot`](../02-组件库/UtenLivePulseDot.md) 每次采样成功闪一次 |
| 运行资源 | 处理器/系统内存/应用内存/数据库连接池 四个圆环，环外画黄红阈值刻度，内存类附已用/总量/可用 |
| 磁盘空间 | 每个文件系统一个圆环 + 已使用/可用空间/总容量 |
| 数据库与备份 | 数据库=连接数圆环（环下「当前/上限」）+ 响应耗时大数字（**按200ms/1000ms 单独着色**，不跟随连接数状态）；备份=已过小时数圆环，满量程取红色阈值 |
| 平台运行指标 | 带告警阈值的计数（线程数/最近错误/积压）画圆环，满量程取红色阈值；无阈值的计数（在线会话）与字节量（附件占用）用大数字卡，**不编造上限** |
| 定时任务 | `MasterDataTableView` 小表：任务/状态/上次开始/上次结束/上次错误/说明，黄红状态整行浅染 |

动效遵守 [06-动画规范](../00-项目准则/06-动画规范.md) §四与 [07-性能自适应](../00-项目准则/07-性能自适应.md) §五、§七：圆环弧线与数字都是**值变更时的一次性过渡**，没有常驻循环；lite 档、系统「减少动画」或页面离屏（`TickerMode` 关闭）时全部静态；数字滚动只在 rich 档启用。

采集数据过期（超过两个采样间隔）或刷新失败时：所有圆环变灰虚线、中心显示 `—`、脉冲点变灰、状态徽章全部中性，并显示「数据已过期，正在等待新的采集结果。」——**绝不保留上一次的绿色数字**。

## 性能与采样

后端使用独立单线程每15秒采集一次，页面 GET 只取缓存，不随页面人数重复扫描磁盘或访问数据库。连续请求不会触发新的采样。界面超过两个采样间隔（默认30秒）未更新先标灰，后端超过45秒也不再提供旧的正常状态；页面仅在可见时轮询，离开后停止。数据库探测只读 `pg_stat_activity` 的数量及连接上限，不读取业务明细或SQL文本。

采样分快慢两条车道，避免重探针每15秒打一次库：**快车道**（每次采样）=处理器、内存、堆、连接池、磁盘、数据库探测、备份文件、线程数、最近错误计数、定时任务注册表，全部为进程内读取或已有探测；**慢车道**（每4次采样=60秒）=在线会话、待处理事件积压；附件占用在慢车道基础上再加5分钟缓存。慢车道结果在两次统计之间沿用上一份，首次统计完成前显示「尚未完成首次统计」。所有附加探针都是只读参数化 SQL，带2秒语句超时，**超时或失败一律记为未知，不记为0**，也不下发SQL文本、目录路径或异常消息。

备份摘要由 `deploy/monitoring/server_status_export.py` 从既有本地备份检查报告生成，不运行备份、不连接云存储。输出仅保留检查时间、最后成功备份时间和检查状态，不暴露数据库标识、WAL名称、配置或原始错误。重新导出不会刷新原报告时间；超过15分钟未得到新检查报告显示未知。没有检查报告时保持未接入，不能根据目录存在或文件修改时间猜测成功。

配套systemd样例：`deploy/systemd/uten-imp-server-status.service.example` 与 `.timer.example`。服务每分钟导出一个小摘要，CPU限制10%、内存64MiB、禁止网络；应用只读 `/var/lib/uten-imp-server-status/backup.json`。源报告仍保持原来的私有权限，应用不获授root报告目录读取权。

配置项：`UTEN_SERVER_STATUS_DATA_PATH`、`UTEN_SERVER_STATUS_BACKUP_PATH`、`UTEN_SERVER_STATUS_BACKUP_STATUS_FILE`、`UTEN_SERVER_STATUS_APPLICATION_VERSION`。实际安装时按真实挂载目录和发布版本填写；权限迁移V534只新增查看权，不授予服务器维护命令能力。
