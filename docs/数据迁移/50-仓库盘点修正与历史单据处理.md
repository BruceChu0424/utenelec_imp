# 仓库盘点修正与历史单据处理

> 日期：2026-07-31
> 适用范围：仓库管理 `CHECK` 盘点单、即时库存、库存流水及订单预占
> 结论：盘点是有审计痕迹的库存差额调整，不直接改余额，也不回写历史订单。

## 1. 业务目标

仓库按周期清点货品后，以实盘数量修正系统账面数量。盘点审核完成以后，新的入库、出库、调拨、领料和退料继续在修正后的即时库存上增减。

修正必须同时满足：

- 能说明哪一天、哪个仓库、哪种货品和颜色，由谁盘点、谁审核；
- 保留盘点前的账面快照、实盘数量和盘盈盘亏；
- 不修改已经发生的历史库存流水和业务单据；
- 盘点期间如有其他出入库，不允许用过期快照覆盖正常库存变动；
- 同一货品维度的库存修正、流水和余额在一个事务内完成。

## 2. 当前模型与采用方案

现有系统已经具备 `CHECK` 盘点单：

- `stock_documents` / `stock_document_items` 保存盘点主单和明细；
- `stock_balances` 是即时库存余额；
- `stock_movements` 保存库存流水；
- 盘盈使用流水类型 9，盘亏使用流水类型 10；
- 审核后的库存联动和单据状态变更在本地事务内完成。

因此不新增“可以任意改库存”的入口，继续强化现有盘点单。每条盘点明细只修正以下唯一库存维度：

`仓库 + 货品 + 颜色`

计算口径：

```text
调整数量 = 实盘数量 - 账面快照数量
审核后余额 = 审核前余额 + 调整数量 = 实盘数量
```

- 调整数量大于 0：写盘盈入库流水；
- 调整数量小于 0：按绝对值写盘亏出库流水；
- 调整数量等于 0：保留盘点明细，不产生无意义的零流水。

以后发生的新库存业务仍统一写 `stock_movements` 并更新 `stock_balances`，自然从盘点后的余额继续加减。

## 3. 盘点流程

### 3.1 建立草稿

1. 先选择盘点仓库；
2. 添加货品，系统按仓库、货品、颜色读取即时库存；
3. 账面数量只读，由服务端保存时重新读取，不信任客户端传值；
4. 盘点人员填写实盘数量，`0` 是合法值，空值和负数不合法；
5. 服务端锁定本单涉及的库存维度，保存账面快照，并计算预览盘盈亏。

同一盘点单不允许出现重复的“货品 + 颜色”行，避免同一库存被重复修正。

### 3.2 审核修正

审核时按固定顺序锁定本单所有库存维度，然后再次读取即时库存：

- 当前余额等于草稿账面快照：由服务端重新计算差额，写盘盈/盘亏流水和余额；
- 当前余额不等于草稿账面快照：拒绝审核，提示刷新账面数量、重新核对实盘数。

该校验用于防止“盘点后尚未审核，期间又发生出入库”的旧快照覆盖合法流水。业务上仍建议盘点期间冻结对应库位或货品的收发，并尽快审核。

### 3.3 红冲

已审核盘点单如需撤销，应走现有红冲流程，生成反向库存影响，不删除或改写原流水。红冲后如仍需修正，应重新建立盘点单。

## 4. 历史订单和历史单据怎么处理

### 4.1 已完成、已审核的历史单据

保持原样，不回写数量，不重算为“好像当时库存就是实盘数”。

历史采购、销售、入库、出库、领料和退料记录表达的是当时真实发生的业务；盘点差异通常来自漏记、损耗、计量误差或历史迁移差异。盘点单作为一个新的、独立的调整事件承接差异，审计链才完整。

### 4.2 未完成订单和有效预占

不自动修改、不取消订单，也不偷偷减少预占。盘点修正的是在手库存，不是客户需求或供应承诺。

盘亏后可能出现：

```text
可用库存 = 在手库存 - 有效预占 < 0
```

此时应保留短缺事实，由业务人员重新排产、采购、调仓或与客户确认，而不是通过改历史订单掩盖短缺。盘盈则增加在手和可用库存，但也不改变订单数量。

### 4.3 退货、红冲和来源追溯

以后发生的退货或红冲仍关联原业务来源。盘点流水只关联盘点单本身，不能伪装成某张旧订单的补录出入库。

## 5. 明确边界

- 未列入盘点单的货品表示“本次未盘”，不能自动当作实盘为零；
- 大仓全盘可按区域、货类或货架拆成多张盘点单，当前单据明细上限保持 500 行；
- 盘点明细统一使用货品基本单位，避免换算率造成修正偏差；
- 当前盘点只修正数量，不推断和修改库存重量；重量盘点需要以后增加独立的账面重量、实盘重量和重量差额字段；
- 盘点不修改单价和历史成本；如需成本调整，应走独立财务规则；
- 不编辑已经执行过的 Flyway 迁移。本次强化沿用现有表结构，不需要数据库迁移。

## 7. 验收场景

1. 账面 100，实盘 96：审核生成盘亏 4，余额变为 96，之后入库 10 得 106；
2. 账面 100，实盘 105：审核生成盘盈 5，余额变为 105；
3. 账面 3，实盘 0：允许审核，生成盘亏 3；
4. 草稿快照 100，审核前正常出库 2：审核被拒绝，不把余额强制改成旧实盘数；
5. 同一货品和颜色重复两行：保存被拒绝；
6. 实盘为空或小于 0：保存被拒绝；
7. 盘亏后在手库存低于有效预占：订单和预占保持，系统呈现短缺；
8. 单据只盘了部分货品：未列货品余额不变。
