# 历史库存计量待核与受控恢复

本规范针对本轮旧账中无法证明基本单位的库存。原账保留，不把“操作资格冻结”解释成“库存为零”，也不按名称、倍率 1、常用单位或后来补齐的主档单位猜测旧数量的量纲。

## 已证事实及代码依据

完整来源调查见本轮交接证据 `DATA_QUALITY_STOCK_95.md` 和 `stock-95-source-evidence/assessment.json`。源账 8684 个余额维度中，95 个数量或金额非零的维度涉及 92 个货品，尚无可解析的原基本单位。81 维/79 个货品在原 `B_Goods` 已无主档，仅保留历史引用；14 维/13 个普通主档的原 `UnitID` 就为空。13 个普通主档中 9 个使用、4 个禁用。不能把 95 维写成 95 个货品，也不能全部解释为禁用货品。

原两个库存视图只连接 `StockGoods` 和 `B_Storage`，没有连接货品主档或过滤单位。因此，不能删除这些余额来模拟旧视图，更不能清零后声称库存核对通过。现有交易快照的单位 0、倍率 1 不能证明“个”“件”“千克”。

已有正式流程不能代替量纲核验：

- `GoodsQuantityUnitPolicy` 及 V675：已有数量引用的货品，普通编辑不能补选或修改历史未知基本单位。
- `StockCountRequestService` 和 `StockDocService.applyApprovedStockCount`：盘点要以当前单位和原余额快照核验，再以目标量减原量过账。原数量量纲未知时，这个差不能被当作有意义的盘盈盘亏。
- `InventoryOpeningService`：建立价值基准并保存原金额来源；它不证明原数量单位，部分开账会改变余额金额。不能为解除计量待核而调用价值开账。

## V928 的持久边界

`stock_measurement_holds` 按原余额 ID 和仓库×货品×颜色保存待核集合，以及发现时的数量、金额、重量和重量估算标记。原 `stock_balances` 的这些字段不因登记待核而变化。后补 `goods.unit_id` 不能解除记录。

`fn_stock_measurement_usable` 是统一计量准入。`v_stock_usable`、`v_stock_available` 和保留余额原列形状的 `v_stock_operable_balances` 共用它。MRP、物料分析、生产就绪、预留分配、销售选仓和委外领料的操作供给读此资格层。原库存总账、即时库存、货品分仓余额、财务/业务报表保留原账查询。

`StockService` 在出入库估值、余额更新之前拒绝待核维度。数据库对库存流水、余额和预留另有守卫，覆盖绕过服务的写入；释放/取消旧预留可以办理，新增、增加、重新启用、换仓及消耗不能使用未知计量。普通盘点候选不把持久待核量当作可直接求差的原量。

即时库存、分仓余额及货品库存详情提供：

| 字段 | 含义 |
|---|---|
| `measurementPending` | 当前主档单位缺失或原数量量纲仍待核 |
| `measurementHoldReason` | 持久原量纲待核为 `LEGACY_QUANTITY_BASIS_UNPROVEN`；单纯未维护单位为 `MISSING_BASE_UNIT` |
| `availableKnown` | 能否将该数量当作已证量纲的业务供给；待核时为 false |

复用关注项 `MISSING_UNIT` 和统计 `missing_unit_rows`，界面名称为“计量待核”。持久待核行即使主档后来有单位，即时库存的单位名称/单位分组 ID 仍为空，不能把原数合并进后来单位的数量小计。行上的原数量、原账面金额、原重量仍可核对；统计行数按页面真实货品×颜色及仓库范围粒度计算，不硬编码为 95。

## 导入及数据复制顺序

1. 保持候选库离线，业务账号不得 CONNECT。迁移身份按正式 Flyway 顺序执行 V925、V926、V927、V928；不要为了先试 V928 在正式候选制造缺号/乱序历史。
2. 如在已有数据上升级，V928 自动登记当时无单位且数量或金额非零的余额。
3. 如先建立空结构，再在受控恢复窗口复制业务数据，复制后、开放应用前由结构所有者执行 `SELECT fn_capture_stock_measurement_holds();`。受控复制时关闭触发器不会自动登记待核集合；不能省略此步骤。
4. 本轮应严格核对 95 维/92 货品及 source metadata 身份集合；核对捕获前后原数量、金额、重量逐维相同。函数可重复调用，重复执行新增数应为 0。
5. 核对原账余额全量仍可见，待核量不进入业务可用供给；完成数据库守卫、服务及页面验收后再开放 CONNECT。

## 已实现的恢复途径：有证据证明原基本单位不变

仅限人工已经取得可信原始单位证据，证明捕获的数量本来就在该基本单位下、无需数值换算的情况。数据库无法替人阅读外部文件；不得将该函数成功解释为外部文件内容已被系统自动核验。

1. 业务人员核实原货品身份、原基本单位、原仓色维度及捕获数量，形成受审修复单；记录来源文件/页/行或不可变文档定位及文件 SHA-256。历史引用技术锚必须先按真实身份完善为正式主档，不能只凭相似名称绑定。
2. 结构维护人按独立受审计划修复必要主档字段。已有 V675 单位不可变守卫保持生效；普通编辑、批量导入和客户端不得绕过。V928 的恢复函数不会自动修改货品单位，也没有新增客户端强制放行接口。
3. 结构维护人以独立维护 LOGIN 执行 `fn_verify_stock_original_measurement_basis(hold_id, verified_unit_id, reviewer_user_id, evidence_reference, evidence_sha256, resolution_note)`。参数必须绑定该修复单和明确的“原基本单位不变、无需换算”结论。
4. 函数核验正式主档、有效现单位、审核人及证据格式；并在锁下核对原仓/货/色、数量、金额、重量及估算标记与捕获时完全一致。任一变化、缺证据、重复核验都会拒绝。
5. 通过后只追加该待核记录的核验人、单位、证据及解除时间，不造库存流水、盘点、审批、成本、总账，也不改原余额。保存执行回执并复核供给资格。已经解除的证据不可再改、删除或清空。

应用运行身份 `uten` 即使意外获得额外表权限、通过 SECURITY DEFINER 或 SET ROLE，也不能通过上述维护入口采信旧数量。数据库入口检查原 LOGIN 的 `session_user`，不相信调用者自行设置的 GUC 或 current_user。

## 尚未实现：原量纲无法证明，只能真实盘点重建

这 95 维当前没有可自动补证的单位依据，不能执行上一节的采信动作。持久待核边界已经实现；“真实盘点重建未知数量基准”尚未实现，不能宣称这些物料已盘点或已经恢复可用。

下一项真实盘点任务必须先准备受审的数量基准重建计划，至少包含：

- 真实物料身份、正式基本单位、仓库与颜色；实盘原始记录、盘点人/复核人、时间和证据 SHA。
- 原未知量纲账作为独立历史证据完整封存；不能把新实盘数减旧未知数记成普通盘盈盘亏，不能先清零或伪造收货。
- 单独定义“量纲重建/新周期基准”事件及前后完整快照、权限、复核、幂等、并发库存锁和恢复方案；该事件与原账的关系须可追溯。
- 同时核对价值池原数量/原金额和待核成本。没有可信实际成本时保留价值待核，不能沿用旧未知单位单价、按零值冒充已核定成本或制造 GL。
- 为重建事件、单位、余额、价值链及原始证据做全关系校验；对普通已知单位库存做回归，完成真实页面流程后才开放该维度新业务。

在上述正式流程实现并经真实盘点复核之前，这些原账保持可见和不可操作。它们的账面数不是实物盘点结论。
