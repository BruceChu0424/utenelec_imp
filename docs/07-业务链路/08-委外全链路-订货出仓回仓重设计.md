## 一、采购与委外的共同点和差异

- 共同点：订货提交财务，批准才生效。批准冻结供应商、币种、正汇率、0–100 税率、
  结算方式、单价与双币金额；订货批准不立 AP。
- 采购：外部货品到厂，收货审核时立采购 AP；IQC PASS 只形成品质合格待入库量，
  仓库确认实际入库后才进入可用库存。
- 委外：公司先把订货目标件本身交给委外商。回厂审核按批准加工费立委外 AP；
  IQC PASS 只放行品质合格量，不重复立 AP；仓库确认实际入库后才写库存和生产供给。
- 公司自有目标件出仓只是库存位置/保管责任变化，不是销售，也不产生 AP。

## 二、两种业务来源、同一执行链

1. 委外部门直接新建委外订货单。
2. 物料分析选择 SUBCONTRACT 后：**无子层级**立即生成只读委外申请，由委外任务中心分解下单；
   **有子层级（V458）先在原分析内前置自制**，成品入库满批自动/手动分批生成委外申请后，
   委外部才开始参与。

委外 Hub 不再重复展示“两种下单入口”说明区，也不再放置“委外前置自制”任务卡。直接单在委外订货列表新建，无子层分析来源单在委外任务中心分解；有子层分析来源单由计划部自制完成后通知（账本见 `/subcontract/preparations` 分析来源页签）。委外任务中心“业务阶段”默认全部。

流程：

    草稿 -> 提交财务 -> 财务批准
      -> 无活动子层级：DIRECT_OUTBOUND / READY_OUTBOUND
      -> 有活动子层级（直下单）：MAKE_THEN_OUTBOUND / ACTION_REQUIRED
          -> V447 接管原分析精确子树需求/供给权益
          -> 独立前置自制分析 -> 整树备料 -> DRAW 实发
          -> 生产/装配 -> 报工 -> FQC -> 仓库实收入库
          -> 转委外出仓专属预留（V458：分批实收分批可出）
      -> 有活动子层级（分析来源，V458）：下单前前置自制已完成
          -> SUBCONTRACT_MAKE 任务账本 produced/notified
          -> 满批自动/手动分批生成委外申请 -> 分解 -> 财务批准
          -> PREPARED_OUTBOUND / READY_OUTBOUND（预留自任务转入）
      -> EC 目标件出仓 -> 委外加工 -> 回厂审核/AP/IQC
      -> PASS：合格待仓库入库；仓库确认：正式库存与供给；FAIL：不入库存

有子层级行在 V458 后不再要求整批完成才可出仓：直下单行任一批次实收即释放
可出仓量（LEAST(planned, prepared) − issued）；分析来源行在通知/订货时即已产完。前置自制入库
不等于原生产需求满足，原需求只认委外回厂 IQC PASS 后经仓库确认的实际入库量。

## 三、仓库执行和数量守恒

- 系统释放行时生成 EC 草稿。仓库选发出仓、经办人和本批数量；保存建立
  SUBCONTRACT_OUTBOUND 专属预留，审核只能消耗本单预留。
- 新流目标件单耗为 1；出仓量、供应商处结存和回厂消费按 1:1 守恒。
- 可分批出仓、回厂和 PASS；未出仓不得回厂，累计回厂不得超过已审出仓净量。
- 财务批准只冻结订单和准备快照，不让委外行进入仓库预计到货任务中心；只有目标件真实审核出仓后才显示可登记回厂容量，红冲或收满后实时退出。
- 出仓红冲先反向下游；改仓、改量、删草稿和订货红冲对称释放预留。
- IQC FAIL 的返修/补做数量由拒收 case 的 replacement allocation 单独登记和释放回厂容量；
  同一失败切片不得再次建立目标件出仓，也不得再次消耗 `LEGACY_BOM_COMPONENT` 委外子件。
  replacement allocation 不是库存入仓，后续合法回厂、IQC PASS 后仍须仓库确认实际入库，
  才形成可用库存和正式供给。
- 存量 LEGACY_BOM_COMPONENT 继续按 V221/V304 冻结子件单耗核销，不猜改历史。

## 四、回厂、IQC、退货和完成

### 4.1 回厂与 AP

仓库到货登记从财务批准订单服务端继承供应商、币种、汇率、税率和结算方式；金额按
订单行和本批数量重算。回厂审核校验先出后进与超量授权，建立 IQC 隔离、回写实到量，
并按加工费形成 AP/SUBCONTRACT_RECEIPT。它不写可用库存。

订单新单完成口径为“IQC 合格基本量减已退基本量”；待检和 FAIL 均不能显示完成。
无 V222 IQC 侧账的历史单才兼容实到净量。

### 4.2 PASS 与普通退货

- PASS 按合格切片追加品质事实并生成仓库待入库任务，不写库存。
- 仓库核对实际入库量与实际库位，可分批确认；每次确认才写库存、刷新分析并按实际入库切片推进正式供给。
- 采购/委外退货表头商业字段全部由服务端从来源收货明细 UUID 派生，客户端不能改。
- 有 IQC 行时必须等该行 RESOLVED；普通退货累计基本量不得超过已实际入库且未退数量，
  不能只以 passed_base_qty 为上限；
  同货品其它批次库存不能掩盖超退。无 IQC 行的历史收货才回退到实到量。
- 负 AP 按来源冻结单价、汇率和合格可退切片重算；最后一片吸收四位小数尾差。

### 4.3 V440 FAIL 拒收、实物退回与财务闭环

failed_base_qty 是质量事实，不等于实物已退，也不等于供应商已认可贷项。旧文所称
“FAIL 自动进入既有 supplier_return_tasks”不成立：V201 任务强制绑定到货超量异常。

V440 候选把质量、实物和财务明确拆成三个事务边界：

1. 品质事务只提交 IQC 结果和通用业务 Outbox；异步消费者按稳定业务键幂等建拒收 case。
   建案或财务投影异常不能回滚已成立的质量结论，失败 case 进入 `FINANCE_EXCEPTION` 等待受控恢复。
2. `record_return` 执行队列在 IQC 行 `RESOLVED` 后记录退回单号、日期、经办人和事件 UUID。
   这是失败实物退回证据，不走 PASS 普通退货、不增加普通 `returned_qty`，也不直接生成贷项。
3. 财务核验供应商贷项/红字凭证后，按冻结价、币种、汇率和全部失败数量生成**全额负 AP**。
   只允许以 `min(来源 AP 当前正余额, 失败金额)` 抵销来源 AP；不能抵销的负 AP 余额继续作为
   供应商贷项开放项保留，不能为了“结清原单”丢失差额。

页面/接口公开状态只有六个：

```text
PENDING_RETURN → RETURN_RECORDED → CREDIT_CONFIRMED
                         └→ CLOSED_NO_CREDIT（仅冻结失败金额严格为 0）
以上可反向阶段按下游事实受控退回前一状态；来源收货整体红冲才形成 REVERSED 终态。
FINANCE_EXCEPTION 可在建案或财务投影异常时出现；它可保留已登记的实物退回证据，
修复后分别回到 PENDING_RETURN 或 RETURN_RECORDED，不能清空物流事实假装重来。
```

贷项建立、专用抵销与 case 终态在单一事务内提交，不持久化或暴露第七个过渡状态。
非零金额不得走 `CLOSED_NO_CREDIT`；零金额不得制造 0 元 AP。来源 AP 从待检/部分检验开始暂停付款、
普通抵销和月结，存在 FAIL 时继续暂停，直到 case 达到 `CREDIT_CONFIRMED` 或
`CLOSED_NO_CREDIT`；批量付款、批量抵销和月结都必须一次性预取并执行同一守卫，不能以 N+1
遗漏部分来源。

V440 已获源码授权，但迁移未应用、功能未部署。任何历史 `PARTIAL/RESOLVED` 且
`failed_base_qty > 0` 的 IQC 行都会让迁移在创建 case/hold 结构前 fail-fast 整体回滚；系统不会
猜测它已退回、已获贷项或仍待处理。完成逐行治理/对账、真实岗位 UAT 和恢复演练前，FAIL 到退回到贷项链继续 **NO-GO**。不得把质量
结论直接写成供应商贷项，也不得让待检/失败 AP 绕过付款、抵销或月结守卫。

## 五、损耗、超耗责任与财务

- 损耗单只确认供应商处公司自有材料损耗并回写 wasted_qty；不得再次扣公司仓。
- deduct_amount 自 V330 起只保留为历史/建议索赔金额。新损耗审核不直接立
  AP/SUBCONTRACT_WASTE；deduct_posted 只供 V304 历史负 AP 查询和受控反向。
- 超出允许量才创建财务责任单。正常损耗留在产出成本；超耗先确认异常损失，再分别决定
  公司承担、豁免、索赔应收、合法 AP 抵销、现金赔偿或精确实物补偿。
- 服务价格折让必须等待红字发票/贷项及税额链；普通进仓不能冒充免费补货。
- 责任开案、决定、履约和反向写业务 Outbox；通知页和顶部非阻塞通知同时到达。

## 六、页面、权限和通知

- 委外详情显示财务审批、前置自制、目标件出仓、回厂、IQC、退货/损耗和应付摘要。
- 仓库使用独立委外出仓工作台，不进入含加工价的委外订单编辑页。
- 各动作使用独立权限；服务端对象范围和 allowedActions 是权威。
- IQC 拒收页面必须先有 `procurement_iqc_rejection:view`；跨归属读取另需
  `procurement_iqc_rejection:view_all`，金额另需 `procurement_iqc_rejection:amount:view`。
  `procurement_iqc_rejection:record_return`、`procurement_iqc_rejection:confirm_credit`、
  `procurement_iqc_rejection:close_no_credit`、`procurement_iqc_rejection:reverse` 只授各自动作，
  不能替代页面阅读或金额权限；确认贷项、重试财务投影以及反向已确认贷项时还必须叠加
  `procurement_iqc_rejection:amount:view`。服务端 `priceMasked` 是最终兜底。
- 财务批准通知制单人时跳订单详情；委外文案明确目标件准备/出仓和预计回厂。
- 委外供应商退回广播按有效 supplier_return_task:view 加 notice:read 解析，不硬编码采购部。
- 任务、预留、IQC、AP/offset 是事实源；通知仅提醒。凡通知页新增一条有权可见的业务通知，
  同一到达事件必须同时投影到顶部非阻塞通知栈；新通知叠在旧通知上方，可展开、逐条关闭，
  顶部关闭不等于已读或业务完成。

## 七、验收与发布边界

至少验证：两种业务来源、无/有子层级、完整前置自制、V447 权益接管/仓库入库自动交接/无执行取消恢复、分批出/进/PASS/仓库确认、先出后进、专属预留、
退货仅限 PASS、拒收异步建案、六状态与反向、实物退回独立、全额负 AP 与有限抵销、零金额
结案、payment/offset/month hold、replacement allocation、返修不重复出仓/消耗子件、双币/税率/
结算快照、损耗责任、并发、对象权限/金额脱敏、Outbox 幂等和通知深链。

源码、空库迁移和定向测试不等于上线。目标非空库迁移、历史 BOM/负 AP 对账、真实实物 UAT、
银行/供应商对账、恢复演练和部署回读完成前继续 NO-GO。

当前目录口径：全局源码候选头为 V447/409；V440 是采购/委外共用的 IQC 拒收与财务闭环候选，V441 是旧委外发料手工 POST 退役候选，V446/V447 是本文现行两阶段入库和跨分析权益交接。本文不预填尚未完成的目标环境验证数字；以实际测试报告、目标非空库迁移记录、迁移前后
对账和真实岗位 UAT 为准。
