# 车间直接申请原料与内料仓切换

## 用户口径与原问题

用户反馈申请面板要求先去基础资料把原材料改为整批领料，实际无法选择材料；申请应直接选料、填量、提交。另要求在车间内料仓页面切换其它已启用的仓。

原实现候选、申请服务、数据库明细守卫三层都只允许 PERIODIC，因此仅换文案或放开下拉框不能生效。上轮禁止默认切到别的车间后，空态提前返回又隐藏了主动切仓入口。

## 本次修改

1. 新增申请候选分页接口，允许有效质量单位的 ORDER/PERIODIC 材料；保持颜色、实际基本单位、仓库可发量和当前内仓归属。原共享材料接口不放宽。
2. 申请页改为搜索选料与数量表，支持超过 500 种材料的完整分页，不再提示去设置发料方式。申请不改变主档或库存，失败保留输入和同次幂等键。
3. V765 放宽未办理的车间领入申请。仓库按申请发料可在同页显式确认首次用途及全部 BOM 影响；权限、版本、单位与旧需求检查保留，与实际发料同事务提交。无需员工前置配置，也不把申请权限变成全局货品编辑权限。
4. 数量列与参考量按各行基本单位显示，不把克等单位错称公斤。
5. 内料仓切换器移到空态外，列出有权限的已启用仓。默认保持任务目标，主动切换才读取新仓，切换期间清空旧仓数量、权限与盘点状态。
6. 首次用途设置与最终物料身份锁在完整库存锁之后获取；直接发料也在新建明细前按顺序锁定库存和货品，避免并发共享锁升级。旧四字段履行命令维持原 JSON 指纹，旧回执缺少新字段仍可读取。

## 验证与运行边界

真实 PostgreSQL 回归覆盖无预配置候选、508种物料分页、单位与颜色、仓库范围、申请不改主档或库存、首次用途与实发原子回滚、权限、幂等、单位变更及旧流程。Flutter 覆盖直接搜索首次物料、克数量原样提交、搜索晚返回隔离、失败重试、仓库同页首次用途和主动切仓。

最终测试与本地运行状态以本次交付记录为准；数据库变更通过正式前向迁移，不直接改旧迁移字节或业务库存。
