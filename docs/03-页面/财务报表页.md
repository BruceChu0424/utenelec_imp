# 钱流报表页

> 路由根：`/finance/report`。真实页面与后端已接通，不是 KPI/图表占位页。
> 源码入口：[`finance_hub_page.dart`](../../lib/features/finance/pages/finance_hub_page.dart)、
> [`finance_report_table_page.dart`](../../lib/features/finance/pages/finance_report_table_page.dart)、
> [`finance_ar_ap_overview_page.dart`](../../lib/features/finance/pages/finance_ar_ap_overview_page.dart)。

## 一、入口与报表组

钱流 hub 提供：

- 应收应付总览；
- 明细报表、汇总报表；
- 往来对账单；
- 账户流水；
- 月结对账；
- 成本核算；
- 总账报表。

`/finance/report` 默认打开明细报表；具体子路由见
[`route_names.dart`](../../lib/core/router/route_names.dart)。路由门槛为 `finance_report:view`。

## 二、明细/汇总表格交互

`FinanceReportTablePage` 按 `cardId` 选择报表组，在组内切换具体变体。页面包含：

- 日期范围（默认从上月同日至今天）；
- 关键字、服务端 facet 筛选；
- 服务端列排序和 1-based 分页，页面大小 50；
- `MasterDataTableView` 表格、横向滚动和列头筛选；
- 行携带合法 `__srcId` 时跳转源钱流单据；
- 加密导出和打印预览；
- 报表类型、日期、facet、排序按账号保存；关键字不持久化。

后端返回标准报表结构 `{columns, rows, facets, page, totalPages, total, totals}`。前端不复制每张报表的解析、
排序和格式化逻辑，统一使用 `features/report/shared/`。

### 2.2 表格下方合计：只认服务端合计（2026-09-11）

报表一律服务端分页（页大小 50），所以合计**必须**由服务端在整个结果集上算：前端对当前页
求和会得出一个看着像总计、其实只覆盖一页的数，比不显示合计更糟。

- 响应新增 `totals`（`common/report/ReportTotal`）：服务端把列表查询原样包成派生表再 `SUM`，
  用的是与列表**同一份** where（日期/facet/关键字 + 对象级授权谓词），派生表内不带
  LIMIT/OFFSET，因此与翻到第几页无关；一个分组维度一条聚合查询，不存在 N+1。
- **绝不跨币种/跨单位相加**：按币种名/单位名 `GROUP BY` 后分组下发，前端只拼成
  「1,234.50 CNY · 200.00 USD」，前端侧不做任何加法。
- 合计**按列显式声明**（`ReportColumn.money(...).totaled("合计金额","currencyCode")`），
  默认不合计：单价、库存快照、以及**明细行上逐行重复的单据表头总额**（相加会按行数翻倍）
  这类列必须保持不声明。
- 未声明合计列的报表整条合计条不渲染（不伪造 0）。

页面接入见 `MasterDataTableView.summaryBar` + `reportTotalsBar(data.totals)`，
合计条挂在表体与翻页条之间（表体内滚时常驻）。

#### 钱流各报表的声明口径（2026-09-11 补齐）

| 报表 | 出合计的列 | 刻意**不**出合计的列与原因 |
|---|---|---|
| Z 应收应付总览 | 应收金额 / 应付金额（均为人民币口径，无币种维度） | — |
| A·C 应收应付明细 | 五个原币列**按币别分组** + 五个人民币列 | 汇率（比率） |
| 销售订单待收计划 | 订单原币 / 已发运立账原币 / 未发运待收原币（按币别） | — |
| B 应收款汇总 | 上月余额 / 发货 / 回款 / 退货 / 货款冲销 / 汇兑差额 / 本期冲减应收 / 应收余额（合计行上恒等式成立） | **铺底额**＝客户主档授信上限（政策属性，不是发生额）；**超出铺底额**可正可负，相加会让超限客户被未用满额度的客户抵销成「看着没风险」；**物料金额**投影为字面量 NULL |
| D 应付款汇总 | 期初 / 采购入库 / 委外入库 / 两类退货 / 损耗扣款 / 索赔贷项 / 红冲净额 / 实际付款 / 账面核销 / 付款汇兑差额 / 应付被抵销 / 贷项已使用 / 期末应付 | **应付合计**与期末应付是同一 SQL 表达式的重复列，合计会把同一个数显示两遍 |
| E 销售收款明细 | 本次收款(原币/人民币) / 本次冲销(原币/人民币) / 本次冲减应收 / 汇兑差额 / 手续费 / 其它费用 | **应收款金额**是被引用立账台账的头金额，一张立账被多次收款就会重复计数；**收款前/后未收**是时点快照 |
| F 销售收款汇总 | 收款单数 + 实际到账原币(按币别) + 各人民币列 | — |
| G 采购付款明细 | 实付金额(外)（靠**隐藏列** `__currencyCode` 分组）/ 实付金额 | **付款总额**与实付金额(外)是同一 SQL 表达式的重复列 |
| H 采购付款汇总 | 付款总额(按币别) / 实付金额 | 汇率；**已付/未付/本次余额**是立账台账的累计快照而非本单发生额；**本次付款**与实付金额重复 |
| M·N 一般费用明细/汇总 | 支出金额（行级人民币） | **付款总额/实付金额**是费用单单头金额、一单多行逐行重复；**数量**没有随行的单位列；**单价**是比率；**序号**是行号 |
| O 其它收入明细 | （无）——整张表只有重复的单头金额，没有行级金额列，合计条不渲染 | 收款总额（单头重复） |
| P 其它收入汇总 | 收入金额（行级人民币） | 收款总额 / 实付金额（单头重复） |
| V 费用冲销明细 | 本次收款(原币/人民币) / 本次冲销(原币/人民币) / 本次冲减应收 / 手续费 / 其它费用 | 冲销前/后未收（时点快照） |
| I·J·K·L 往来对帐流水/明细 | 立账金额(外/本) / 收付款金额(外/本) | **余额三列是逐行滚动值**，一行行相加毫无意义；三个汇率列 |
| X 年度对帐单 | 发货(收货)金额 / 回款(付款)金额（12 个月加总＝全年） | 期初/期末是每月滚动余额；**退货金额**当前恒投影 0 |
| S 帐户进出流水 | 收款金额 / 支出金额（单账户单币种，窗口聚合顺带算出，**零额外查询**） | **余额**是窗口滚动值 |
| 客户预收台账 | 预收现金(原币按币别/本币) / 转销应收(原币按币别) / 预收账面本币 / 应收账面本币 / 汇兑差额 | — |
| Q·R 银行存取 | （空表，无行） | — |

> 手续费/其它费用挂在收款单单头，明细里用 `ROW_NUMBER() OVER (PARTITION BY 单据)` 只落在
> 每张单的首行、其余行给 0——所以整集求和恰好「每单计一次」，是可加的；窗口函数在 WHERE
> 之后、LIMIT 之前求值，派生表里覆盖的正是整个筛选后结果集。

### 2.1 审核状态默认口径：草稿不进报表（2026-09-11）

报表过去把审核状态当纯可选筛选：不传 `status` 就是「时间范围内全部」，未审核草稿
（`status = 0`）因此默认进明细与汇总——未过账的单据不是收付事实，不应计入业绩。

现在的默认口径（`FinanceReportService.addApprovedByDefault`，销售/采购/委外/仓库报表同款）：

- **调用方未显式传 `status`** → 自动加 `status <> 0`，草稿排除；
- **显式传 `status`**（含 `status = 0` 专门查草稿、或表头「未审」facet）→ 按调用方口径走，
  不叠加默认值。查草稿的能力完整保留。

口径变化：历史报表数字会变小，减少的正是原先混进来的草稿行；单据审核后自动重新出现。
月度物化视图（`finance_ar_ap_mv` 等）本来就带 `status = 1`，不受影响。同轮迁移
[V551](../数据迁移/149-V551待交货视图排除草稿.md) 给 `sales_order_pending_v` 加了同款过滤。

## 三、数据与导出

- 页面请求 `/api/finance/reports/{group}/{view}`，筛选和排序均透传后端。
- 导出走 `/api/finance/reports/export`，使用页面同一报表 key 与查询参数，受独立权限、限流、
  最大行数、并发和审计约束。
- 打印预览按当前筛选重新请求，当前客户端上限为 2,000 行；它不是无上限全量打印。
- 聚合/台账行没有源单 ID 时不允许伪造下钻。

## 四、销售订单待收计划与正式应收

- 已审核销售订单进入“销售订单待收计划”，只按订单币种展示原币订单额、已发运立账原币和未发运预计原币。它是经营预测，不读取汇率、不换算人民币，也不写 `ar_ap_ledger` 或总账。
- 仓库完成 `SHIPPED` 后，每个发运批次才形成正式 AR；分批发运形成多笔 AR，合并发运通过不可变来源关系关联多张订单。
- 正式应收页面以币种、原币应收、原币已收/冲销/未收为主要核销口径，并保留财务开账汇率及本币拆分用于
  会计。销售收款引用 AR 后，应收/核销原币只读，由财务填写本批原币金额和实际到账汇率，服务端重算本币与
  汇兑差额。USD AR 可进入 CNY 账户；CNY 账户记到账本币，真实 USD 账户记到账原币。
- 跨币种订单必须按币种分组或分列，禁止把 USD、CNY 等订单待收或账户原币余额直接相加。同一 AR 分批
  到账时按收款批次逐行展示日期、汇率、费用、本币、汇兑差及前后余额，不以后批覆盖前批。当前失败关闭的是
  核销原币与 AR 不一致、HKD/EUR 等第三币种账户，以及尚未交付的外贸公司代收在途/多客户结汇批次。

详细边界见 [ADR-030](../99-决策记录-ADR/ADR-030-销售待收计划与正式应收分层.md)。

### 4.1 订单资金汇总与客户预收

订单资金汇总以服务端 SalesOrderMoneySummary 为唯一口径：订单金额、正式 AR、实际现金、费用冲销、
客户预收累计到账/转销/可用余额、AR 未收、未发运金额、计划尚需收款和超收分列。cashReceived
只含实际现金，不含 writeOff；销售订单历史 deposit 不参与计算。

订单币种以主档名称在订单信息或专门币别列独立展示，资金指标只显示金额数值；旧币种编号
`001/002/003` 不得作为金额前缀。客户预收列表跨币种或分页未完整时，累计区只显示可加总的本币金额；
完整单币种结果才可显示原币累计。

普通 AR 收款按不可变 SALES_ORDER source_sequence FIFO 写逐订单来源。预收转销只可冲减同客户、
同币种且有唯一订单来源的正式 AR。历史多订单 AR 若无法证明完整来源，返回 hasUnallocated 和具体收款行
告警，不把不确定金额归入订单，也不按比例推断。

退款流程尚未交付；相关生产验收保持 **NO-GO**。完整公式见
[ADR-048](../99-决策记录-ADR/ADR-048-客户预收与销售订单资金事实分层.md)。

客户预收事件报表与对账别名使用同一个服务端事件源：

- GET /api/finance/reports/customer-prepayment/events
- GET /api/finance/reports/statement/customer-prepayments

两者要求 finance_report:view + customer_prepayment:view + finance:view:all，按日期展示预收到账、到账红冲、
预收转销和转销反转，返回 salesOrderNos、现金原币/本币、转销原币、来源/目标账面本币、汇兑差和中文
事件标签。AR 应收汇总排除客户预收到账，只有预收转销事件冲减正式 AR，禁止把预收到账重复当 AR 回款。

### 5.1 应收应付总览的统一关联搜索

`/finance/report/overview` 是“左客户/供应商分类森林 + 右应收应付表”的主从页面。左树顶部一个搜索框同时匹配：

- 客户、供应商分类名称与编号；
- 往来单位名称与编号。

往来单位定位分页调用 `GET /api/finance/reports/ar-ap/party-locations?keyword=&page=&size=100`，收集全部
`{partyType, categoryId}` 后分别展开客户/供应商祖先路径并默认定位首个有效分类。右表继续调用
`GET /api/finance/reports/ar-ap/overview`，把同一 `keyword` 与 `categoryType/categoryId` 组合查询；编号只参与
过滤，公开报表仍保持原 6 列。V272 候选之后，未分类客户/供应商绑定真实系统根，命中时正常展开并按
该根过滤；只有滚动升级或脏数据仍返回空/树外 `categoryId` 时，才安全退回公司级关键词结果，不能沿用
无效分类滤空。

搜索输入变化立即使旧定位和旧报表请求失效，300ms 后才发新定位；手动点树会取消待执行与在途搜索。
纯分类命中只浏览该分类全部单位，不把分类词误传给报表；相关内容分支保留关键词。加载、失败、无结果和
compact 抽屉/正文文本同步均为交互契约。详见 [UtenHierarchySearch](../02-组件库/UtenHierarchySearch.md)。

权限必须按公司级报表口径理解：Controller 要求 `finance_report:view`，Service 还要求超管或
`finance:view:all`；不得复用受客户 owner 范围裁剪的 `client:view:all`。客户/供应商分类树仍分别要求
`client_category:view`、`supplier_category:view`，定位端点不会绕过树权限。

资产工作台不是报表页的子权限：进入 `/finance/assets` 要求 `finance_asset:view`，其写动作使用
独立资产权限和服务端 `allowedActions`。核心落账门禁默认关闭，完整生命周期仍为 **NO-GO**；
`finance_report:view` 不能替代任何资产工作流权限。

总账、成本和月结对账中的具体报表变体由
[`finance_report_config.dart`](../../lib/features/finance/config/finance_report_config.dart) 集中配置。

## 六、组件

当前使用 `UtenAppBar`、`UtenContentContainer`、`UtenListTwoPane`、`UtenSearchBar`、

## 七、安全与正确性

- 前端路由显隐不替代后端 `finance_report:view`。
- 导出、打印、列表必须使用相同筛选和数据范围；下载事件进入审计。
- 金额使用数据库/后端 decimal 口径，不在前端用二进制浮点重新汇总。
- MV 报表须展示或监控刷新新鲜度；不能把旧快照当实时账。
- 总账迁移与期初/期间/期末平衡未完成结构化对账前，生产结论仍为 NO-GO。
- 本页只查看/筛选/导出报表；`finance_post:execute` 的单期/全量过账后端端点没有 Flutter
  操作入口。若财务用户需自主执行，必须另行设计确认、进度、互斥、结果和失败恢复，不得把报表页
  写成过账控制台。
- 总账通用 `generate` 只能重建其明确拥有的通用 AUTO 来源，不能删除资产域凭证；资产月度错误
  必须在资产工作台创建关联原批次的正常反向批次。
