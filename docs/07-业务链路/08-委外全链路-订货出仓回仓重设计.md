# 委外全链路 SOP：目标件准备、出仓、回厂与退换货

委外处理公司目标件在外加工：目标件真实出仓，回厂先品质检查，合格后由仓库实际入库，再按原来源供给后续生产或销售。公司自有材料和供应商加工费分别留证；财务批准、品质PASS、仓库实收不能互相替代。

本页按[ADR-072](../99-决策记录-ADR/ADR-072-委外收敛与采购委外订货批准后改量.md)、[ADR-073](../99-决策记录-ADR/ADR-073-本批物料履约与同主仓分仓领料.md)及已确认业务规则组织。直接委外单的草稿自动准备、送审/批准前齐备校验已接线并通过本地专项，见第二节；内部生产准备在财务之前，仍待全项目组合验收。已有物料分析的前置自制与直接草稿准备是不同来源，不得混淆。

最新验证、未完成事项和发布状态只看[统一验收记录](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)。本页不重复旧版本目录头和阶段通过数字；运营业务链优先，深入财务最后，尚未完成全项目验收。

## 二、两条需求来源的准备时序

### 2.1 已有物料分析选择委外

1. 计划按原订单/需求UUID、货品/颜色、BOM路径确认SUBCONTRACT。根层、中层、叶层都按本节点路线处理，不能隐藏根委外或重复展开被其覆盖的子件。
2. 无子层的目标件可以直接下达委外申请/任务。有子层则先在**原分析**生成目标件前置自制计划锚点，子件责任和精确权益仍留原树；各层路线、数量确认后即可下达，不以当前物料齐套限制计划安排。
3. 执行段待子件合格实物齐套，按实际叶仓领料、显式开工、报工/FQC、仓库接收目标件。实领原材料继续覆盖原树，不因目标件产出而重新生成一遍采购需求。
4. 目标件实际入库后，`SubcontractMakeTaskService`按 `min(required, produced) - notified` 给出可通知量；自动或授权手工分批通知形成原来源的委外申请，委外部门再下商业订单。通知批次、申请及准备预留以UUID衔接。
5. 商业订单批准后，PREPARED_OUTBOUND沿已产目标件及其专属预留进入出仓。前置目标件入库只完成“交给委外加工前的准备”，原需求的最终成品供给仍等待加工后回厂、合格且实际入库。

整批或分批通知都不得超过实际产出，重复命令幂等返回原结果。撤销通知须先解除依赖商业订单/实物事实，追加批次反向并恢复同源准备预留，不能删旧批次或把下代重新生产与旧通知键混用。

### 2.2 委外部门直接新建商业单

直接单在草稿阶段按同货/颜色共享递减的目标件可用池计算缺口，并为每条真实直接订货行建立SC-ORDER准备分析，交计划部门安排内部生产。有子件但已有合格目标件现货的份额不重复制造；无子件或现货覆盖时可直接继续财务流程，不能拿原材料/在途冒充目标件实物。

1. 编辑页保存/回填 `warehouseId`，有准备需要时选择真实叶仓；父仓不是物理落点。相同原行和准备重复保存不会建第二份需求。
2. 新准备以 `SC-ORDER:{orderItemId}`、真实FK及冻结原订货基本量保留来源。它是直接单新增需求，不接管已有申请；旧SC-PREP及已批planItem的历史准备桥继续兼容。
3. 未排产的修改/删除先取消旧准备，原行UUID/历史保留后再建合法新份额；已有计划/生产的行不能通过改量、删行或改仓穿透。库存后来覆盖缺口时只取消可取消的空闲准备，已有生产事实不抹掉。
4. 计划部门在明确主/兼职组织和动作权限范围内处理这类真实SC-ORDER分析，内部生产先于商业财审；普通分析和其它销售财审门槛不因此放宽。
5. 目标件FQC合格并实际入库后，订单显示可送财务。`lockAndValidateFinanceSubmission`与`applyFinanceApproval`都重新调用 `requireNoMakeThenShortage`；送审后目标件被占用，批准仍明确拒绝。批准后建立真实出仓计划/专属预留，不用旧快照猜可用量。

## 三、商业审批、改量和目标件出仓

一张订单一个委外商及一套兼容商业条件；批量录入不同条款时按明确条件拆成真实订单。财务冻结供应商、币种、有效汇率、税率、结算方式、单价、单位换算和来源，批准订单不产生应付。操作权、归属范围、认领和快照版本由服务端校验，不能用查看权限替代审核权。

批准后修改走 `change-qty`，不是普通全量编辑：合法改量立即生效，同事务记录old→new和来源份额变更并创建复核case。当前有PENDING复核时不叠加另一份修改。复核通过不重复生成预计供给/出仓计划；驳回保留已生效数量和历史，制单人按原因处理，不能自动撤回已发生物流。

增量不超过原来源可订容量，减量不低于已登记回厂、已出仓/耗用和其它不可释放事实。按[来源份额对账](../数据迁移/119-V503批准后改量的来源份额与生产挂接对账.md)返还未履约份额，原BOM/需求不随商业减量被抹掉；不能平均回减但让来源表仍保留旧量。

仓库从出仓任务生成或恢复本单EC草稿，选实际叶仓、经办人及本批基本量。保存形成SUBCONTRACT_OUTBOUND专属预留，审核只能消费本来源允许份额；新流程发的是目标件本身，基本量按冻结单位换算1:1，不把其BOM子件再发一次。草稿改仓/改量/删除与订货受控反向对称释放预留。

目标件实际审核出仓后才出现可登记回厂容量；订单财审通过不是预计回厂实物。分批出仓/回厂各留UUID和基本量，未出不得收，正常有效回厂受同源实际出仓净容量约束。已证明的IQC/普通退货补回另沿原退回份额释放容量，不能用简单毛回厂量比较误拒合法补回，也不能重复发自有目标件。

公司材料发出后进入供应商保管/在制，仍属公司价值，不是销售或立即耗尽：

```text
同源实际发出 = 合格产出对应实际耗用 + 实际材料退回 + 明确损耗 + 供应商剩余
```

材料退回、回厂耗用、损耗和各自反向使用同一ISSUE来源；同货品其它批次不能掩盖超耗。准备、出仓、回厂、品质和实收各有独立进度，不将其中一个“完成”标签当作整链结案。

## 四、回厂、品质与实际入库

1. 仓库从真实出仓对应订单登记回厂，服务器继承商业字段和行UUID。真实仓库在到货时确定，同主仓允许范围和跨主仓处理依原来源规则；不能把客户端供应商/价格替换为新来源。
2. 订单正常未回容量与已退未补容量分开。两者并存时明确NORMAL或RETURN_REPLACEMENT；自动识别只适用于无歧义情况。正常超到按异常/批准量处理，未批量不写AP/可用库存；不能借补回额度掩盖正常超到。
3. 回厂审核核先出后进、实物容量和超量授权，冻结价款切片并建立待检。新增AP只取本次实际应付加工费；免费补回不生成零AP，已贷后重新计款只计对应份额。AP不是公司自有材料价值。
4. 品质可以分批PASS/FAIL。每次PASS只增加合格待仓库入库量；仓库按实际数量、重量和叶仓确认后才写库存、刷新原分析和供给，未检/FAIL不进入READY。
5. 同单其它待检行不阻塞已合格实收切片；每个实际入库增量独立幂等。前置目标件实耗与加工费按真实来源合入库存成本；免费补回沿原funding/root receipt，不重复耗用原料。

一批免费补回含多个原失败批次时，可保持员工一次确认，内部按原材料/费用来源边界拆实际库存明细。不能把加工费为0误解释为免费库存，也不能将两个原批次的自有料合成一个猜测来源。

## 五、普通退货、IQC拒收与实际贷项

| 情形 | 处理 |
|---|---|
| 合格且实际入库后的普通退货 | 表头商业身份从原收货行UUID派生；有IQC的行按已解决品质及实际未退入库量校验，不能只看PASS或同货品总库存。物理退回和金额追加记录，反向关联原流水。 |
| IQC FAIL | 先保留品质事实，再由可靠Outbox幂等建拒收case。建案/财务投影失败不能回滚已成立品质；异常保留物流事实，按原来源恢复。 |
| 不合格实物退回 | 在实际退回动作记录日期、退回单号、经办及事件；不冒充PASS普通退货，不直接生成贷项。再次失败必须本代再次实退才能再补。 |
| 未取得供应商贷项的补回 | 沿原订单、原资金和原价值免费履行，预占不等于结清；合格且仓库实收后才结清对应份额。 |
| 已取得贷项后再补 | 原贷项保留，新收货按已贷份额重新计款；不得又使用原免费权益。 |
| 部分/跨案实际贷项 | 选择同一个原AP，输入真实凭证A和明确case/version/qty/A分项，服务端预览共同book B与余额，确认必须携最新hash。不是按全部失败数量自动生成全额负AP。 |
| 无贷项结案 | 只走明确合法的零金额/已证明履行语义；非零未结份额不能靠改状态消失，不能制造零AP或伪造免费来源。 |

当前案件会出现PENDING_RETURN、RETURN_RECORDED、CREDIT_CONFIRMED、CLOSED_NO_CREDIT、FINANCE_EXCEPTION、REVERSED等状态；结清还要看资金切片、实物补回、实际凭证和剩余量，不能只看一个状态名。反向一张实际凭证须反向全部关联case分项及其抵销，保留原凭证，并检查后续是否已使用对应来源。

原AP及负AP消费同一个冻结BookAllocationPlan，先按可抵未付份额抵销，剩余供应商贷项继续开放；不能为了结清原单丢差额。待检/未解决的失败份额执行统一付款、普通抵销和月结hold，专用合法同源动作使用其明确许可；不能因本次免费补回无新AP就丢掉原冻结。

完整请求/响应、A24/B30、非有限份额、共同SQL守卫和前端合同在[采购与委外到货退换货实现与验收](../99-项目治理/采购与委外到货退换货实现与验收.md)。普通P/SC退货的共同历史book分配仍待财务收口，不能将旧“最后一片四位尾差”写成新实际金额规则。

## 六、损耗、成本、权限与通知

损耗确认供应商处公司材料的实际去向，不再扣一次公司仓。正常允许损耗进入合格产出成本，超额部分独立为异常损失；实际索赔/现金赔偿/合法抵销与物理损失分别留证，不能自动相互净额。价格折让需真实贷项/税额来源，普通进仓不能冒充免费实物赔偿。

`deduct_amount`只保留历史/建议索赔，`deduct_posted`用于旧负AP查询与受控反向；新损耗审核不按旧字段直接立负AP。实际源材料/加工费、NORMAL/EXCESS、后补与反向见[库存实际成本接线](../99-项目治理/库存实际成本接线与验收.md)。供应商现金索赔兑现和完整GL不能因成本专项存在就标完成。

- 页面查看、跨归属查看、金额查看及record_return/confirm_credit/reverse等动作分别授权；金额masked时不能从Exact、预览或其它接口回读。服务端allowedActions、版本和对象范围是最终门槛。
- 财审认领/续期失效则暂停决策，不能把旧页面按钮可用当审批有效。对同任务/跨任务的批量通知、反向和重复请求仍先鉴权。
- 通知通过Outbox进入真实任务深链，IQC拒收按资格投递到通知页/顶部/行动卡；完结或反向按实际任务状态撤回相关提醒。关闭顶部提示不等于业务完成，通知接收范围不能硬编码成采购部。
- 已有非零历史、LEGACY_BOM_COMPONENT、冻结单耗/单位和旧AP按原快照查询/对账/受控反向；不猜成新目标件1:1。V304旧“发BOM子件”、V330前旧“损耗直接负AP”不再用于新单。
