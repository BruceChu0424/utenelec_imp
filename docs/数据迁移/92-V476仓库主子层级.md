# 92 - V476 仓库主/子层级

> 迁移：`V476__warehouse_hierarchy.sql`（本地开发库已于 2026-09-04 应用并验证）
> 关联页面：[即时库存页](../03-页面/即时库存页.md) · [基础资料页](../03-页面/基础资料页.md)

## 一、背景与决策

用户要求：**一个主仓库（仓库（14年版），code=001）包含全部子仓库**——顶部仓库下拉
体现层级，选主仓=汇总全部子仓；仓库资料里主仓/子仓都能增改；**货品/物料流转必须
落到对应的子仓库**，主仓库只作汇总视角。

老库 `B_Storage` 是扁平表（ParentID 全 0），层级属于新库运营建模，不在老库迁移范围。
V476 只加列+一次性种子，不动历史单据。

## 二、数据库

- `warehouses.parent_id uuid REFERENCES warehouses(id) ON DELETE RESTRICT`（null=独立顶层）
  + 部分索引 `idx_warehouses_parent`。
- 种子：`code='001'`（仓库（14年版））设为主仓，其余未软删仓（成品仓库 / 成品不良品仓 /
  原材料不良仓（14年版）/ 五金仓库 / 轨道车间）挂为其子仓。今后新增仓库默认独立顶层。

## 三、语义（逐场景对症，非一刀切）

| 场景 | 主仓库（父仓） | 子仓库（叶子仓） |
| --- | --- | --- |
| 即时库存 / 余额 / 流水查询 | 可选 = 自身+全部子仓聚合（`WarehouseScopeService.scopeOf`），聚合口径下「含不良品仓」开关仍生效 | 精确单仓（旧行为不变） |
| 仓库单据 / 收货 / 出货 / 退退货 / 委外发料·退料·出仓 / 报工 / 产成品实收 | **禁止**（保存即拒：「必须选择具体子仓库」） | 唯一合法落点 |
| 采购·委外申请/询价/订货（预填链路源头） | 禁止（收货沿用同仓，源头就拦） | 合法 |
| 物料分析（主领料仓/参与仓） | 弹窗分组说明行不可勾选；存储偏好里的父仓自动剔除；兜底主仓取第一个叶子仓 | 合法（齐套/预留/DRAW 真值） |
| 货架标签「抬头仓库」 | 可选（纯打印标题文本，清单不按仓过滤） | 可选 |
| 仓库资料维护 | 「上级仓库」字段可选（两级模型：仅顶层仓可当上级；服务端防环） | 可改成挂到别的顶层仓下 |

前端统一呈现：`shared/widgets/warehouse_hierarchy_dropdown.dart`（Material 下拉，
即时库存/货架标签用）与 `warehouseHierarchyItems()`（UtenDropdownField 选项，
编辑/登记页用）——顶层仓在前、子仓缩进；父仓在运营口径下渲染为置灰分组标题，
历史已保存的父仓值仍能回显。

## 四、服务端落点

- `WarehouseScopeService`：`requireLeafWarehouse`（运营红线，13 个单据服务在
  applyHeader/保存路径调用；字段注入可空——单测手工构造缺省跳过，Spring 环境恒生效）
  与 `scopeOf`（查询范围展开的语义权威，含契约单测）。
- `StockQueryService`（即时库存/余额/流水）：范围展开用**内联递归 CTE**（与 scopeOf
  同语义）——stock→master 是 ADR-017 未放行的新依赖边，ArchitectureBoundary 闸门拦截，
  故不注入组件而是直查（锚点查不到=已软删/未知仓，退化为精确单仓旧行为）。
- `MaterialAnalysisService.requireWarehouse` / `normalizeParticipatingWarehouses`、
  `ProductionPlanningPackageService.requireWarehouse`、
  `ProductionFinishedArrivalRegistrationService` 的仓库 SQL 校验追加
  `NOT EXISTS (子仓)` 条件。
- `WarehouseService`：保存请求带 `parentId`（省略=保留，显式 null=清空回独立顶层；
  防环=不能是自己/不能落在自己后代链上）；列表项与字典带 `parentId/parentName`。
- 分类树 `/tree?withGoodsCounts=true`：节点附子树未软删货品数（即时库存页隐藏
  零货品分类分段用；不影响其余调用方）。
