## 口径核对

- 销售任务中心取完整销售模块；采购/委外任务中心取各自运营入口和相应草稿入口，供应商退回保持独立入口。
- 生产调度红数与批次黄数分别选取登记入口，生产草稿计入红数，车间任务仍属于独立 workshop 模块。保留逾期与催料提示。
- 财务审批入口取独立队列，五类钱流草稿只由模块汇总与草稿入口承接；财务 Hub 不新增黄数。
- 品质待检仍合并 IQC/FQC 红数，不新增在办黄数。新建单据、查询与报表入口保持无徽章。
- 公共徽章保持红黄 0/null 不显示、超过 99 显示 `99+`、浏览型 0 显示 `(0)`。布局修复没有将分段计数登记为新入口或重新求业务合计。
- 同一未结束且需要退回处理的单据可同时计红待办与黄进行中，遵循徽章准则四之七的重叠合同。黄色模块徽章提示改为仅说明进行中尚未结束，去掉无条件「暂不用动手」承诺；新增 zh/en/ko 数量文案并保留无 AppLocalizations 时的安全中文兜底，tooltip 覆盖、原语义和计数不变。
- 深浅主题沿用既有主题与语义色，没有重新设计状态配色或硬改业务状态映射。

## 独立复核追加闭环

同次审查的后续独立只读复核发现普通编辑路由的 GoRouter page key 只含路由模板，跨同模板单据会复用原 State。主业务分线以真实资源与有效预填/source 构造统一 key；本分线新增 `document_editor_resource_transition_test.dart`，从生产 `appRouterProvider` 抽取实际 builder/redirect，验证采购专属/普通、委外、销售、仓库、财务、生产计划和日报八族编辑路由。16 例证明旧 A 的迟到 GET 不进入 B、已接受 A 的表单在 B 加载期间移除、B 必须主动重读。委外原有 id key 已安全，没有将其误记为新增漏洞。新 key 重建同时暴露仓库编辑器旧 GET 在 State 销毁后落入 `_grid.addRow` 的生命周期错误；补 GET 后及补空白行前 mounted 守卫。

外部 controller 随 `showDialog` 结果立即释放仍可能被退场中的输入控件使用。仓库成品实收确认/取消两条在原实现复现提前释放。公共 `showAndWaitForExit` 等待实际路由 `completed`，当前七类外部 owner 消费者统一接入；业务输入在确认时冻结，采购/委外改量不再靠 300ms 延迟。两类原指定页面、追加的账户警戒线/让单/仓库销售出库备注都有实际确认/取消 Widget 生命周期回归。账户警戒线额外捕获旧 accountId、认证请求作用域和黏性身份纪元，A-B-A 旧确认不能写入。账户与仓库销售出库 detail 的资源 key 由统一路由分线处理。

本分线独立复核提出的 HR 混合直改/审核字段幂等内容检查与空值回放、旧审核确认跨身份/批次问题已交业务分线补入并验证；批次分页、全字段历史与 pending 优先聚合、员工先锁再复核批次等后端事实见对应业务分线记录。
