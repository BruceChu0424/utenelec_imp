# V596 到货「先入库后质检」(上架待检)

> 2026-09-16 · 用户口径：「入库必须先要品质部质检，一天来的货多了就堆在一起，或者质检没空；能不能先入库后质检：
> 原本的流程保留，但加个选项——入库任务中心那里直接入库，品质部照样发过去，但顶部标红提示『货品已入库，
> 需到对应储放区域检查』；品质部后面检查全部不合格，是要再出库？还是把之前的入库记录删除？」
> 决策见 [ADR-090](../99-决策记录-ADR/ADR-090-到货先入库后质检.md)。

## 结论先说：「先入库」= 实物先上架落位，不是先记一笔库存

- V446 起「品质放行」与「仓库入库」是两个独立事实：任何写 `stock_balances` 的采购/委外入库流水都必须挂在一个
  品质 PASS 事件与一条入库批次行上(`fn_validate_procurement_iqc_stock_in_item`、`fn_guard_legacy_procurement_iqc_auto_stock_in`)，
  价值账(V517)也要求先有品质切片。没有 PASS 就先写库存，等于回到 V222 之前「未检品当现货」的 P0 缺口，
  还要为不合格再造一种出库流水与红冲语义。
- 所以本迁移让待检明细行**记住实物的实际叶仓 + 库位**；品质部按这个位置到储放区域检验；合格时由系统按这个位置
  **自动完成正式入库**(走 V446 同一套批次/流水/价值/守卫，只是不再需要仓库再点一次确认)；不合格的从库位取出，
  走 V440 既有的退回/贷项链路——**既不需要出库单，也不删任何入库记录**。

## 链路(每一种情况)

1. **进入方式**：(a) 到货登记页点「先入库后质检」按钮(与「登记并送检」并排)→ 登记 + 送检 + 上架同事务(超量隔离的单不上架，等财务定案后走 b)；
   (b) 品质部检查结果页对「等待检查结果」的收货单点「先入库上架」→ 逐行选记账叶仓 + 填库位；也可只上架部分行。
2. **上架的约束**：只允许仍是 `PENDING` 且合格量 = 不合格量 = 0 的行；仓必须是记账叶仓且非线边仓；库位 1..100；
   同内容重放静默；位置改动追加 `PRE_STOCKED` 事件；出结论后服务端 409 + 触发器 23514。
3. **品质合格(整行或部分)**：每个 PASS 事件在同一事务里由系统按记录的位置完成正式入库——批次 `origin=PRE_STOCKED_AUTO`、
   幂等键 `prestock:<PASS 事件 UUID>`、金额/重量按放行切片全额、库位学习照旧、生产联动
   (`afterInspectionStockInConfirmed` + 整单结案唤醒)照旧；**不再**投递「待仓库确认入库」任务。
4. **品质不合格(整行或部分)**：与原流程完全一样只记事实并开 V440 拒收案件；实物从来不在 `stock_balances` 里，
   所以不需要出库单；退回任务与通知带上「实物位置：仓 / 库位」，仓库去库位取货登记退回。
5. **上架仓后来被停用/改成父仓**(极少数运维动作)：自动转正前再校验一次，不通过就退回原流程——放行进仓库
   「待确认入库」队列，由仓库另选实际仓；品质结论不会被挡住。
6. **收货红冲**：仍要求整单结案；红冲按批次行反向(含自动转正批次)；上架四列保留为历史。
7. **即时库存**：已上架待检品按实际上架仓计入「待检量」(`COALESCE(pre_stocked_warehouse_id, warehouse_id)`)，
   未上架的仍按收货参考仓；两者都不进可用量。
8. **通知**：上架后向品质部投递任务通知(含前 3 行「货品 → 仓 / 库位」)；整单结案通知按「先入库后检」措辞；
   拒收案件通知附实物位置。

## 回填与兼容

- 老待检行四列全空 = 原流程，行为一个字节不变；老入库批次 `origin` 默认 `WAREHOUSE_CONFIRM`。
- 事件 `PRE_STOCKED` 不在品质记录页的动作筛选里(只看 PASS/FAIL/RECEIPT_REVERSED)，不影响检测记录口径。
- 清库策略：不新增业务表，`business_data_reset()` 目录对追加 (596, 553)。
