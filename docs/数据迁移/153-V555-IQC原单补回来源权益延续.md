# V555：IQC 原单补回的来源权益延续

本迁移修复原供给行动因 IQC 终态不合格而取消后，供应商沿原订货行合法补回，实际入库却丢失原分析专属归属的问题。它承接 V554 的来源剩余区间；V466、V518 等既有迁移字节保持不变。

## 问题和边界

真实回归使用同一采购行的两个来源 A20/B30。原到货 50 中，12 件品质合格并实际入库，38 件不合格且实退。原行动已形成 `CANCELLED` 历史。供应商免费补回 38，经品质、仓库确认后，总库存 50、库存金额和 AP 均 2500，但旧代码因排除所有 `CANCELLED` claimant，未将新入库量继续归属 A/B。

`CANCELLED` 仍是终态。迁移不更新历史行动，不复活采购申请，不创建新订货单，不改金额或数量事实。普通到货、人工撤回、不同订单/案件、错误货品/颜色、已撤回实退和无法证明的旧记录均不能使用此延续入口。

## 权威证明与数量上限

`fn_iqc_replacement_origin_parts` 逐个追溯现有不可变事实：本次 PASS 品质分项 → 收货资金分项 → 有效补回分配 → 原 IQC 案件的实际退回 → 同一原订货行的来源申请/委外行。只认可 `NO_CHARGE` 或 `CREDIT_REPURCHASE`，并要求行动属于系统的 IQC 终态取消原因，原申请仍有效且没有该行动的人工 `CANCEL_ACTION` 凭证。

`fn_iqc_replacement_origin_capacity` 对本次实际入库使用上述证明集合中的 stock consideration 部件，不能因为一片有证明就把其它部件一起纳入。本次所有延续归属合计不得超过已证明的替补基本量。

同时，`fn_iqc_replacement_node_capacity` 限制：

- 原 allocation 尚未覆盖的数量；已转正式计划的 exact 仍计入原来源覆盖，不能因已经领用而重新补一遍。
- 当前物料节点的真实需求，或由 `fn_analysis_plan_material_matches` 证明的正式需求。V79 同父 BOM 组件唯一和 V495 直属锚点匹配继续生效，不猜测另一个父路径。
- 当前受益权益、正式预留/已领用覆盖及无法细分到节点的旧分析池。
- 其它活跃供给：采购使用当前剩余区间投影，显式公共在途采用使用其剩余 allocation 权益，委外申请与前置自制任务使用各自现役承诺。前置任务已通知部分由委外申请接管，不能重复扣除。
- 显式跨分析让料的接受节点，使用现役 `preplan_material_reallocations` 中精确 to 节点的 `OPEN/PARTIAL` 未补齐量增加必要预算，随后由原 `applyPriorityForOriginEvent` 优先补齐来源。不是新增借还账本；from 节点不另加量，已补齐或已撤销记录不计入，分批和重放仍受原账本约束。

框内预计去向由 `fn_iqc_replacement_preview_capacity` 读取同一资格/节点预算；只有品质分项已经提供补回证明时才显示该延续。实际归属仍由仓库确认事务决定，预览不写任何库存事实。

## 数据库保证

新增 `trg_guard_iqc_replacement_origin_continuation`，启用 `ALWAYS`，在插入 `ORIGIN_IQC` 权益前再次验证本次入库部件与容量。此时当前 origin 尚未进入受益余额；原 exact 行已存在，所以只从原 allocation 累计中排除本次 exact。既有品质、库存、资金、exact、权益守恒及不可变触发器全部保留。

迁移只新增函数和一个触发器，不新增业务表、不回填假凭证、不修改旧余额，也不改变业务清空目录。旧版本应用不能提供本次来源资格保证，回滚发布仍须遵守统一发布方案与数据库兼容要求。
