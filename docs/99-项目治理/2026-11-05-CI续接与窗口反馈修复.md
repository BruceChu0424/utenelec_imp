## 登录和主界面的窗口按钮

采用 `frontend-design`，复用 Uten 控件、颜色和布局。问题来自共享按钮只给图标增加顶部内边距，而悬停、按压和焦点边框仍以旧中心绘制。

公共入口是 `lib/components/buttons/uten_close_button.dart` 的 `UtenWindowControlButton`。原生反馈轮廓与 `_nativeGlyph` 共用 `nativeGlyphTopInset`，不移动已正确下移的图标；目标仍为 30×36，圆形图标 22，顶部间距 11。鼠标、键盘、重复激活保护、稳定的原生语义节点及不插入原生 Tooltip 的约束保留。

| 调用方 | 状态与边界 |
|---|---|
| `DesktopWindowHost` 登录模式 | 共用原生按钮；最小化、关闭，含全幅登录画面 |
| `DesktopWindowHost` 主界面模式 | 同一入口；最小化、还原/最大化、关闭 |
| Web、普通弹窗、悬浮窗口 | `native=false` 继续使用已有居中轮廓和各自业务回调 |
| WPF `UtenDialogWindow` | 独立 WPF CaptionButton/窗口框架，不使用 Dart 图标顶部偏移；不据此宣称 Win7 真机验收 |

实际像素回归在旧源码四个场景都测得反馈中心为 18、图标中心为 22，相差 4px。修复后的登录/主界面、深浅主题悬停及键盘焦点均围绕图标；五个完整窗口测试文件 73 项通过，另对四场景加载真实 MaterialIcons 再次逐像素验证通过。PNG、原失败和成功 native JSON 均保留在独立 Flutter 验证树 `build/window-control-hover/` 与 `build/integration-ci-20261105/`。
