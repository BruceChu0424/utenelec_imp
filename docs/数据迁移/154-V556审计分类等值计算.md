# V556 审计分类等值计算

迁移文件：`server/src/main/resources/db/migration/V556__audit_classification_shared_literal_matching.sql`。

物料分析会在一个事务内保存大量物料行，每条行审计均计算风险和类别。V169 两个存储生成表达式重复执行大小写转换、文本拼接及正则匹配；在保留 11 个索引和真实物料 JSON 形状的隔离 PostgreSQL 实验中，分类计算成为明显主成本。

V556 新增 `public.fn_audit_classify`，共用原始字段范围的规范化文本，把纯字面正则匹配改为子串匹配；`trg_audit_classify` 在每次 INSERT / UPDATE 前同时设置两项分类，并设为 ENABLE ALWAYS。API 仍将分类字段声明为 `insertable=false, updatable=false`。数据库会覆盖显式伪造的分类值，包括仅修改分类字段的 UPDATE 及复制模式写入。

## 规则与兼容

- 保留 V169 的 CASE 优先级、NULL/空值兜底、LOWER 拼接字段范围、大小写及无单词边界的子串语义。
- `data[-_]scopes?` / `system[-_]settings?` 仍分别匹配连字符或下划线的前缀，不额外增加单词边界。
- 风险中的 `^export_` 是字面下划线前缀；类别中的 `LIKE 'export_%'` 保留单字符通配符，因此 `exportX` 是导出类别但不因此升为中风险。
- 原认证/系统类别未读取 `target_id` 的分支继续不读取该字段。新增函数固定 `search_path=pg_catalog`；触发器显式调用 `public` 函数，防止会话搜索路径覆盖。
- `DROP EXPRESSION` 保留热表已有风险/类别值、列顺序、列类型、全部索引及数据。迁移不 UPDATE 历史，不重分类、不改归档表，也不改变 `fn_audit` 或 `fn_audit_redact_row`。归档工作器仍复制完整写入快照。

## 前置检查和失败处理

迁移在 public.audit_log 的 ACCESS EXCLUSIVE 锁内核验：目标为普通持久表；六个输入列类型及两个存储生成列符合已知结构；五个文本输入列使用同一排序规则，避免函数统一输入排序规则改变原独立 LOWER 语义；两个函数名未被已有重载占用；没有同名触发器或其他 BEFORE INSERT/UPDATE 触发器冲突。

为拒绝未评审的规则漂移，迁移通过 LIKE 复制热表实际输入类型和排序规则，在临时参考表上重新解析 V169 原生成表达式，再使用同一 PostgreSQL 服务器的 `pg_get_expr` 结果比较。没有硬编码来自另一 PostgreSQL 版本的反解析字节。发现未知结构、规则或对象冲突时整个迁移拒绝并回滚，不能跳过检查或伪造 Flyway history。

升级应使用现役签名制品与 migrator，并遵循停写、备份、验证和同版本切换流程。迁移成功后旧应用仍可按原 API 读写审计表；数据库回滚不能通过删除新函数、关闭触发器或重写历史实现。若需退回旧数据库状态，恢复经过验证的对应备份，或新增前向修复。
