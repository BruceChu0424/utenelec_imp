# V864 生产调度按实际供给与履约聚合

日期：2026-10-14。

V719 的生产调度根视图沿用 V470 的 `requested_qty - approved_qty` 待排计算，遗漏了已提交计划和 V478 起的 `root_fulfilled_qty`。库存覆盖后无需工单、采购或委外已经合格入库的产品因此仍被记为待排；产品完成数量又只数工单，出现“已完成 8、未完成 0，但仍有待排数量”或无工单采购完成后停在“分析处理中”。

本迁移新增只读视图 `v_production_analysis_workbench_item_progress`，分别给出尚未安排数量和尚未履约数量：

- 尚未安排扣已提交/已审核计划、实际顶层供给交接，以及本来源已落实的精确在途份额。自制行动对应的计划不重复扣除。
- 尚未履约只扣实际顶层供给交接、来源专属实收入库，以及自制子件原需求已经获得的正式现货覆盖。来源实收沿用 V694/V722 与备料预算的口径：已审核 `FINISHED_IN` 非公共实收基本量，按每计划私有预算封顶，再以冻结换算率转回来源单位；公共计划产出与实际超产不冒充来源履约，冲回按实收来源重新计算。仅下单、到货未验收、公共现货模拟分配或未认领公共在途均不算完成。
- `MAKE_COMPONENT` 锚点保存的是创建时已扣除现货及既有在途的净责任，不能再次从该净配额扣除父物料的全量库存或在途。投影核对同一来源的毛责任，只将超出非子件责任部分的他源覆盖用于该净配额；例如毛需求 10、原库存 8、子件净责任 2，正式预留原 8 件后子件仍需完成 2 件。
- 子件的毛责任沿原物料身份及有效父计划的冻结需求核对；已完成分批的冻结需求仍属于原责任，拆批释放的旧需求不重复计入。父件部分完工造成下层实时需求缩小，不能让已投入的旧库存再次履约尚未产出的子件。相同物料的多条 BOM 路径共享正式预留时，按实际作用域守恒分配，不能复制整份覆盖给每条路径。
- 库存覆盖保留实际投入后的履约事实，排除本锚点自己的产出权益，避免与专属实收入库重复计入；后续新增覆盖、释放和冲回仍按真实来源重新核对。无须生产的足库存 BOM 组件不会被新建为待排子件。
- 调度根视图、`fn_material_analysis_fulfillment_status` 和 API 产品完成数量共用这些来源事实。产品按货品/颜色/单位聚合；实际缺口、追加、权益释放或冲回会重新显示未完成。
- 全部实际履约后退出“进行中”；计划尚未自动关闭但已全量实收，不保留空待办。采购/委外在途仍显示备料中，部分下达后的真实未安排量仍显示部分已排。

仅新增/更新投影和函数定义，不改历史分析行、计划、报工、收货、预留、权益或库存流水，不改已应用迁移。没有新增业务表、列或索引，因此不增加业务数据重置 table 分类；视图随既有表事实清空，无须独立重置。

验证覆盖：八个生产产品完成加一个库存覆盖产品；无工单采购/委外在途、实际履约、单据完成但未履约和履约冲回；部分供应与提交计划的真实缺口；既有自制子件的模拟分配与正式现货覆盖、实收、投入和释放；同一正式预留混合自产精确份额与公共现货；专属公共自制在途认领与取消；公共 2 先入库、私有 4 后入库及冲回，冻结换算率 2 下不重复履约；API 按产品身份聚合且无工单供给可完成。另以真实业务链核对足库存 BOM 组件下达时不生成重复子件工单。测试数据库均为隔离 Testcontainers，本地验证不代表已部署或已修改业务库。

## 触发器路径的单遍求值（同日修订）

`fn_material_analysis_fulfillment_status` 在计划关联行级触发器内同步执行。最初实现让 `fn_production_workbench_component_credits` 在循环内按物料、按需求重复求值冻结范围与库存覆盖视图，每次重评又对每个（需求×物料）候选对调用 `fn_analysis_plan_material_matches`；单条 plan-link 插入即耗费数秒，多接收人报工链路超过 60 秒语句超时。同时状态函数经 `v_production_analysis_workbench_item_progress` 的 `DISTINCT + LATERAL` 形状无法收窄到单个分析，触发器要对全库分析计算 credits。

修订保持全部口径不变，仅改变求值策略：

- credits 函数把冻结范围、库存覆盖、在途供应三类事实各物化一次为 JSONB 快照，循环只读快照；状态函数改为直接以 `p_analysis_id` 参数调用 credits 并就地复算同一"尚未履约"公式。
- 库存覆盖与正式现货池从视图改为 `fn_production_workbench_material_owned_coverage(p_analysis)`、`fn_production_workbench_formal_stock_pools(p_analysis)` 参数化函数；冻结范围保留视图供断言查询，新增 `fn_production_workbench_frozen_material_scopes(p_analysis)` 孪生函数。三个函数把分析谓词折进基表扫描——窗口函数会挡住外部 `WHERE analysis_id` 的谓词下推，否则每次触发器执行都要先对全库所有分析算窗口再过滤，历史数据增长后计划审批会线性变慢。

本地以 `DailyReportComplexPerformancePostgresTest` 全类、聚合下单/直拨/车间流转/物料锚点等 CI 失败类与生产履约相关 Postgres 测试复核。
