## 价格精度保护

1. `export_legacy.ps1`：价格 Decimal 按 invariant 原数值输出；Double/Single 使用 `R` 格式保证数值反读一致，避免旧 .NET 默认格式丢失有效数字；其他字段保留既有导出语义。已经被历史导出丢掉的精度不能凭旧 CSV 补回，未来重导须重新从旧数据库导出。
2. Python 派生：不对旧价做数值格式化，直接保留原始文本；Excel补价用 `Decimal` 验证，不使用 `round`、`quantize`、固定小数位或折扣倒算。空旧价只有在计价单位与基本单位一致、比例精确为 1 且无单位冲突时才允许补入正建议售价。
3. `migrate_goods_data.sql`：三价 staging 使用无固定精度的 `numeric`，不经 `double precision` 或 `numeric(18,4)` staging 提前丢位。删除原主档前读取实际目标三列类型并检查精确可表示性；目标不是 exact numeric、非有限数或需要舍入时直接拒绝；越界由数据库报错拒绝，不改成别的数值。
4. 写入后再次逐货品检查三价与 staging 精确相等，触发器或其他处理改价也必须失败。历史 Flyway 文件不改写。本批旧库三价有效小数均不超过 4 位，可完整进入现役固定四位 numeric 列；未来更高精度输入如不能被实际目标列容纳则中止，不静默降低精度。
5. 货品列表的固定两位展示也同步移除，API 精确价格文字与 Web、Flutter、WPF 消费保持一致。展示值不能作为舍入后的业务价回写；金额合计、税额及其他交易规则不因本次单价修复改变。
