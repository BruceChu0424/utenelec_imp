## 3. 状态和持久化

编辑原输入 → 原owner加密草稿 → 显式冻结请求 → Sending先持久化 → 至多一次HTTP → Confirmed / Rejected / Unknown。发送门失败为NotSent，无活跃租约的Sending在恢复时成为Unknown，不自动重发。

- 目录为%LocalAppData%/Uten/UIMP-Win7-WPF/business-state/v1/下的owner hash；绑定issuer、user、dataset、reset generation。草稿/台账与认证文件不同entropy，不存密码、OTP、step-up、access或refresh。
- 草稿revision仅本机CAS。可保存缺名称/值尚不合法的编辑状态，显式业务提交时才校验required、权限和接口。
- UTF-8原文、presence、SHA冻结。Sending成功前禁发送，已记录requestId不重发；有活跃租约不误判崩溃。
- 同草稿有Sending/Unknown时，禁止覆盖、删除或换UUID重发。同revision已Confirmed也不可借清理失败重发；相同autosave不制造新revision。
- 服务器Confirmed而终态落盘失败时仍保留Confirmed，另记录PersistenceError及IsDurablyRecorded=false。原Sending留存，重启后的Unknown人工核对，不反报未发送。
- 恢复只载原namespace；重新提交须fresh owner授权和UUID详情复核。未编辑隐藏计量键时不将缺省改null，未编辑恢复内容时复用原文。

## 4. 退出和窗口生命周期

DraftWriteLease仅在原owner有效时签发，只授权原namespace本机保全，不授权网络、换目标或跨账号注入。退役先折叠旧内容，再保存；失败仍保留对象。

MainWindow.pendingEditors独立于Workspace，换登录页/工作台不移除未保全编辑器，Closed才移除。正常退出、离页、更新授权首尾共用保护。不能只靠子窗取消Closing；显式Shutdown会忽略它，见[微软说明](https://learn.microsoft.com/en-us/dotnet/api/system.windows.application.shutdown)。

保存并关闭时fields/status冻结，取得draftLock后才采集正文，防排队flush回写旧快照。完成后才Close。外部强杀、掉电或系统强制结束会话不是正常关闭，不扩大为已验。
