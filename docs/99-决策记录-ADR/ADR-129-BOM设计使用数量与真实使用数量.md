# ADR-129 BOM 设计使用数量与真实使用数量

- 日期：2026-09-27。
- 状态：已定稿，按本文实现；迁移 V737 (文档 256)。
- 修订 ADR-119 §2-§5 (学习口径、学习边所有权、超产默认与记忆)、ADR-118 §超产记忆、ADR-116 (预览守卫只比结构)、ADR-102/099 (物料分析用量锁定)、ADR-057/096 (执行分段指纹与拆批)、V583 (收尾余料退仓)。
- 设计评审：六个视角 (学习数学、分析与执行一致性、读者与委外、超产、性能与契约、需求与界面) 对照代码逐条攻击草稿后定稿，问题与取舍并入下文。

## 1. 问题

BOM 的 `goods_bom_items.qty` 是工程设计时估的「大概用量」。ADR-119 只给「底层自制件、仓库现场登记领料」的父件学习，并把学出的平均值直接改写进 BOM 的 `qty`；带人工 BOM 的父件被标成 `MANUAL_BOM` 后永久停学。结果：

1. 绝大多数父件的用量永远停在设计估算值，物料分析、车间领料都按估算算。
2. 学习的「真实」其实是账面回声：报工实耗按计划单耗自动预填，最后一次报工的余料按「账面还剩多少」退仓，不是按实物清点。学到的就是计划单耗本身；再把它喂回领料需求，只会单向上涨，另行确认损耗还会被重复计入。
3. 学习直接改写 `goods_bom_items.qty`：执行指纹含 `b.updated_at`，同品未开工任务从此不能拆批；物料分析的用量一变就清掉人工确认的路线、让下达/审批报「BOM 直接层已变更」。
4. 分母是整个父件的累计产量，后加入的组件被早期批次稀释；一个极小用量就让整张配方停发；一次真实编辑就让整个父件永久停学。

## 2. 决定

### 2.1 两个数，各有唯一来源

| 名称 | 存放 | 谁维护 | 用途 |
|---|---|---|---|
| 设计使用数量 | `goods_bom_items.qty` (原「数量」，只改显示名) | 工程人员；系统学出的边由系统同步 | 设计参考；成本预算 `source_e`；委外单一子件发料合同用量；没有真实数据时的计算回退 |
| 真实使用数量 | `goods_bom_actual_usages` (按 父件+组件+组件基本单位) | 学习引擎；人工只能「重新学习」 | 物料分析、车间领料需求、MRP 默认按它算 |

`goods_bom_actual_usages.actual_qty` 是生成列，唯一定义：`(净耗 − 重学基线净耗) / (暴露产量 − 重学基线暴露产量)`，分子分母都大于 0 才有值，否则为 NULL (=没有数据，绝不当 0)。累计值 `NUMERIC(30,10)`，结果不截断精度；只有同步到学习边的设计值按 BOM 精度 5 位小数 (最小 0.00001)。

### 2.2 用量规则只定义一次：两个视图

- `v_goods_bom_actual_usage` (一条真实使用数量)：`actual_status` (`NO_DATA` 没有有效样本 / `OUTPUT_UNIT_CHANGED` 父件基本单位在学习后变了 / `ACTUAL`)、`actual_qty` (每父件基本单位，只有 `ACTUAL` 才有值)、本轮窗口 `net_qty / exposure_output_qty / sample_count` (累计减重新学习基线，表约束保证不为负)。学习记录里 BOM 外用过的料、学习发布都读它。
- `v_goods_bom_item_usage` (一条 BOM 边) 建在它上面，只加边自己的规则：`linear` (`PER_UNIT`，或 `PER_PACKAGE` 且允许尾包)；不线性时状态为 `NOT_LINEAR` (整包或固定批次，平均单耗不能近似非线性规则，优先于其它原因)；线性边换算 `PER_UNIT` 直接用、`PER_PACKAGE` 用 `actual × basis_output_qty` (每包用量)；`actual_per_unit_qty` 只在该用量行可用时给出。
- `effective_qty = CEIL(COALESCE(actual, design) × 10^6) / 10^6`，与执行侧 6 位向上取整一致；`usage_basis = ACTUAL | DESIGN`。物料分析直接取视图的 `linear`、`actual_status` 与 `usage_basis=ACTUAL` 时的 `effective_qty`，Java 不再重算线性、状态和取整。
- 界面读者也不重算：组装信息页签 (`BomItemView`) 与「BOM 学习记录」的组件行经同一个映射 `BomItemUsage` 读视图列，JSON 里平铺成同名字段 (`actualQty / actualPerUnitQty / actualStatus / actualSampleCount / actualOutputQty / actualNetQty / actualUpdatedAt / relearnedAt`，加 `effectiveQty / usageBasis / systemLearned`，以及不良相关的 `actualDefectQty / actualPerProducedQty / actualDefectRate`，见 §2.13)。学习记录里 BOM 外用过的料没有边，按同序的列从 `v_goods_bom_actual_usage` 读：没有 `effectiveQty / usageBasis`，`systemLearned=false`，`actualQty / actualPerUnitQty` (每父件基本单位) 只在 `ACTUAL` 时有值。

视图只回答「本厂做这个父件时每件用多少」，不判断路线。

### 2.3 读者

| 读者 | 取值 |
|---|---|
| 物料分析快照 (`MaterialAnalysisBomSnapshotReader` → `MaterialAnalysisService`) | 视图的设计值与真实值都读；按节点决定用哪个 (§2.5)，并锁定在分析快照里 |
| 执行分段 (`ProductionExecutionPlanningService.snapshot`，车间领料需求/齐套/指纹) | 分析下达的计划用该分析锁定的节点用量；手工计划用视图 `effective_qty`；锁行别名仍是 `goods_bom_items b`，视图只做不加锁的 LEFT JOIN |
| MRP (`MrpService`) 与计划导入单台用量 (`ProductionScheduleService.orderLines`，一条 LATERAL 查询随订单行取回一层 BOM) | 视图 `effective_qty`，经共享的 `fn_material_analysis_edge_required` 按计量规则展开 (不再忽略整包/固定批次)；设计使用数量小于或等于 0 的存量 BOM 行 (V182 约束以 NOT VALID 放过的历史行) 只列出零件、不算用量，导入弹窗显示「待物料分析复核」，不再让整张订单带入失败；MRP 把这种行记为无效原因「BOM 用量小于或等于 0」 |
| 委外单一子件发料与交接守卫 (V581/V646、`SubcontractMaterialPlanService`) | 设计值 (合同用量，冻结在委外计划) |
| 成本预算 `source_e`、财务 BOM 份额、反查报表、BOM 复制/粘贴 | 设计值 |

`source_e` 公式收成一个 SQL 函数 `fn_goods_bom_material_cost`，Java `GoodsBomService.recalcSourceE` 与学习发布都调用它。Java 侧计量只有 `MaterialConsumptionMath.required` 一份公式，`CompleteKitAllocator.ConsumptionRule.required` 委托它。SQL 里有两个孪生：V247 `fn_material_analysis_edge_required` 算一条 BOM 边 (MRP、计划导入需求小计)；V609 `fn_material_snapshot_required` 按需求冻结的 `consumption_snapshot` 逐规则求和 (需求写入守卫、拆批/追加/预留断言)，Java 侧同一条曲线由 `CompleteKitAllocator.required` 逐规则委托共享公式后求和。`MaterialConsumptionMathSqlContractPostgresTest` 把两个函数装进真实 PostgreSQL 与 Java 逐例比对。

### 2.4 学习口径 (所有本厂生产的父件)

- **报名**：任何执行分段的生产事实都入学习队列；档案在第一次写出样本时创建。人工 BOM 不再阻止学习。
- **样本**：仍按生产族 (拆批、实产追加，`fn_production_execution_cost_members`) 一份当前贡献，差额更新，重放幂等。
- **族级条件**：已审产出 > 0、无未审报工、无待处理追加、产出达计划或已报完工 (`READY`)。
- **逐物料核清**：物料的每条需求都满足 `实发 − 良品退回 = 耗用 + 另行确认损耗`、在制占用为 0、没有待退料、身份没变，才算核清。
- **分子**：核清物料的 `实发 − 良品退回` (实物净耗，含正常损耗与确认报废)。
- **分母按暴露**：族对某物料有需求 (含 0 耗用的需求)，或族是现场登记领料族且该物料是父件已知材料，本族产量才计入该物料的分母。后加入的组件不被早期批次稀释。现场登记的父件第一次出现某物料时，该父件其它已完工的现场登记族一并补计这份暴露，所以结果与各族完工的先后无关：A、B 交替使用时各按全部批次平均，合计仍正确。不同颜色合并按 (组件, 单位) 计一次暴露。
- **保留**：族未完成或物料未核清时，旧贡献逐物料保留，除非被推翻 (产量减少、已证明耗用低于旧值、身份变化)。
- **早退**：族未完成且从未贡献过时，不读台账、不写任何行。

累计平均 = 所有有效样本净耗料之和 / 暴露产量之和。样本越多越稳定。

### 2.5 物料分析：按节点选用量，并锁定

- 快照多存 `design_bom_qty / actual_bom_qty / usage_basis / usage_reason / usage_sample_count / usage_defect_rate`，`bom_qty` 是本节点实际采用的量。`usage_defect_rate` 是与真实值同一份数据里的报工不良率，跟 `actual_bom_qty` 成对：一起采用、一起锁定、按同一条规则 (下文 (a)) 决定沿用还是重取，只作说明 (§2.13)。
- **按节点选**：父节点的有效路线是委外，且父件是单一子件委外 (我方把这一个子件发出去，`soleComponentSubcontractGoods`) → 设计值，原因 `SUBCONTRACT_OUTBOUND`，与委外发料计划一致；其余 (自制、委外前置自制、整件外发) 都是本厂消耗 → 有真实值用真实值，否则设计值并记原因。不看会被路线确认回写的 `goods.source_type`。
- **锁定**：分析在新建和人工「刷新」时才采用最新的设计/真实值；其余内部重算 (保存路线、下达、审批、唤醒) 沿用快照里的值，只重新按路线选择。人工刷新时，父节点已有下达计划批次的子节点也保持原值，与已冻结的车间需求一致。预览、下达、汇总下单、审批因此看到同一个数。锁定的细则：
  - (a) **规则不变才沿用**：同一节点键上，只有这条边的计量规则完全没变 (BOM 行 `bom_item_id`、组件货品、单位、计量方式、计量基数、是否允许尾包都相同) 才沿用锁定值；原地改了其中任一项的边按新节点取现时值，锁定值只在原规则下有意义。
  - (b) **共享制造锚点继承**：汇总下单的共享制造批次 (`AGGREGATE_MAKE`) 的锚点第一次展开时，还没有自己锁定值的节点按相对 BOM 路径继承批次第一个成员子树的锁定值 (成员行按 id 排序，与汇总预览同序)；锚点自己已锁定的节点不动。汇总预览、锚点和写进计划的是同一个数。
  - (c) **成员子树同步冻结**：人工刷新时，锚点上因已有下达计划批次而保持原值的父节点，同步冻结到每个批次成员子树的同一相对路径，成员树与锚点树始终是同一个数 (追加预览按成员子件算，追加计划按锚点子件长)。
  - (d) **路线被本次写入改掉时再选一次**：写快照可能改掉父节点的有效路线 (例如主档建议变了、事实变化清掉了人工确认、节点重新启用)，而子节点用量是按父节点路线选的。写入前后有子节点的节点路线不同时，同一次重算 (人工刷新或内部重算都一样) 按写入后的路线再选一次用量，需求与分配看同一条路线；第二遍只改用量列，不会再清确认。
- `per_product_qty` 在 Java 里按所选用量逐层计算，6 位向上取整后作为下一层的 `parent_per_product_qty`，不再每次刷新误判变化或触发 >0 约束。
- **守卫只比结构**：路线确认重置条件、预览「结构已变化」、下达/审批「BOM 直接层已变更」只比组件/颜色/单位/层级路径/控制段/计量规则/第一层单位换算率，不再比任何用量。设计值变化随下一次人工刷新生效。
- 汇总下单批次的配方键用设计用量，用量学习不会让后续追加找不到原批次。

### 2.6 执行分段与拆批

- 执行指纹去掉 `b.updated_at` (审核标记、备注不影响计量)，含实际采用的用量与 `usage_basis`。分析计划用锁定值，学习不会让已保存的草稿或排产预览失效；手工计划在真实值变化后需重新预览。
- 过期提示统一 (`ProductionExecutionPlanningService.stalePreview`，草案保存、正式确认与分段核对共用)：整份预览指纹不符为「排产预览已过期：目标仓库存、占用、计划行或 BOM 已变化，请重新预览」，分段 BOM 指纹不符为「执行分段 BOM 已变化，请重新预览」；手工计划 (没有来源物料分析) 两句都在「，请重新预览」前多一句「，或用量已按真实数据更新」。原来的「预排草案已过期…请重新计算」「请刷新排产预览」不再出现。
- 生产硬门槛 BOM 行 (发货包装、参考行与非硬门槛行不进领料需求，不查) 的设计或采用用量小于或等于 0 时拒绝生成执行分段，提示点名父件与组件 (编号 + 名称) 并给修法：「「父件」→ 组件「组件」：用量小于或等于 0，不能排产。请在父件的 BOM 里把这一行的用量改成大于 0。」(原为笼统的「BOM、颜色或基本单位数据不完整」)。
- 拆批不再拿现行 BOM 重算原冻结任务：用根需求冻结的 `consumption_snapshot` 曲线 (LINEAR 为 `{PER_UNIT, per_product_qty}`)，与 V561 数据库断言同一口径；没有曲线的非线性历史需求拒绝拆批。

### 2.7 实盘收尾 (真实数据从哪来)

最后一次报工的「还有料没用完」对话框改为逐物料填写**实际剩余** (实物清点，预填账面剩余，0 可填，不超过账面可用)，只要该工单还有账面可用的料就会出现。

**账面可用**只有一个定义：该需求各原领料过账 (`ISSUE`) 的 `fn_material_issue_available` 之和 (`ProductionMaterialSettlementService.issueAvailable`)，即未清账减退料途中。结算 FIFO、清账行的 `availableToSettleQty` 与 `maxReturnQty` (`readClearance`)、报工弹窗的上限与预填、审核时的实盘计算 (`bookAvailableByDemand`) 读的都是它；客户端不再有自己的回退公式。它只回答「账上还有多少」，不是可退量：被后续生产批次承接、或所在任务状态不许退料的料照样算在账上。

选「退回仓库」时：

- 本次用料 = 审核时的账面可用 − 实际剩余 (覆盖本单登记的用料)；审核时账上已没有这条料的，照登记的用料过账，交给结算按真实账面把关；
- 退仓数量 = 实际剩余 + 未领直送料。线边仓直送过来还没领用的余料 (`DIRECT_LOT`) 不在账面可用里、不计入实际剩余，收尾时另外整批退回；清点弹窗逐料提示「另有未领直送料 X <单位>，退回仓库时一并退回，不要计入实际剩余」(数量取自退料来源读取，读不到就只显示通用说明)；
- 被后续批次承接或任务状态不许退料的料，按实际剩余记账后，实际剩余留在车间，不退仓；
- 族的 `实发 − 良品退回` 就是实物净耗，学习不再是计划单耗的回声，损耗也不会重复计入。

中间报工的自动预填只是族内分摊，不影响学习结果。实际剩余超过账面可用 (之前报工多记了用料) 时拒绝并提示先核对用料；选「留在车间」照旧，该料未核清，不参与学习。

### 2.8 系统学出来的边 (底层自制件)

- **新建**：只在父件没有人工边、贡献的族全部物料核清时新建；一次性全部建或全部不建 (颜色不唯一、身份变化、成环、数值溢出时整张不建并记原因)，避免只建一半后父件不再走现场登记。
- **同步**：学习边的设计值由系统同步成真实值按 BOM 精度取 5 位的值 (最小 0.00001)，两列只差这次取位；真实值为「没有数据」(例如重新学习后) 时不同步，设计值保持最后一次同步值；父件当前来源为委外时暂停同步 (委外指纹与交接按设计值冻结)。同步保留审核标记，不发「BOM 已维护」通知；只有新建学习边才发。不写「按已完工实际净领用累计学习」备注，改由 `learning_profile_goods_id` 显示「系统学习」标记。
- **所有权按边**：人工改学习边的结构列 (组件、颜色、设计用量、计量方式/基数/尾包、控制段、硬门槛) → 这条边转为人工边，真实值照常学；人工删除任意边 → 记 `learning_released_at`，系统不再自动加回该组件；只改备注、价格、排序、审核标记不算接管。
- **不自动撤边**：学习边失去全部样本时真实值变为没数据，计算回退到设计值 (即最后一次同步值)，结构不变。

### 2.9 重新学习

工艺或材料变了，历史平均不再代表现在。「BOM 学习记录」里每个组件有「从现在起重新学习」(需 `goods:bom:edit`，服务端随记录返回 `canRelearn`)：把当前累计记为基线，之后只用新数据；新数据出来前按设计值计算。

- **学习轮次**：每次重新学习把该用量行的 `learning_generation` 加一。样本里的每个物料条目记下自己首次计入的轮次 (`production_bom_learning_samples.entry_generations` 只增不删，被撤回后再计入也认原轮次)。更早轮次的族以后再变动 (冲销、退料、补产、重新审核) 时，累计与基线同步移动，窗口只含本轮的族；基线永不超过累计，窗口的净耗、产量、批次都不会为负。

### 2.10 允许超产比例

- **结构默认**：货品来源为采购或委外 → 0%；否则 (自制或未定) 没有「制造阶段」子件时为制造底层 10%，有则上层 0%。制造阶段子件 = 来源为自制/委外，或自身有生产 BOM；来源未定的无 BOM 原料 (现场登记的材料都是这样) 算原料，不再把底层件变成上层。
- **只记人确认的值**：计划明细带 `allowed_overproduction_rate_source` (`DEFAULT` 系统按默认填 / `EXPLICIT` 人确认过)。界面上没被人改过的比例提交空值，由服务端按默认填并标 `DEFAULT`。MRP 子计划、报工补产、实产追加用默认值，不再把默认值钉成记忆。
- **草稿里的「同一行」**：编辑草稿时，服务端只凭页面带回的已存行 id (`PlanItemLine.sourceItemId`) 且货品没换认「同一行」：原行是 `DEFAULT` 而本次空着，或填的比例与原行相同，就沿用原行的比例与来源，不算新的确认。
- **什么时候记忆**：只有新的或改过的确认才记成货品下次的默认。规则只写一次，在 `fn_remember_plan_line_overproduction_rate(plan, goods, rate)`：记住这一行确认的比例，实产追加计划除外。两处调用它：计划服务保存明细时只对新增或改过的 `EXPLICIT` 行调用 `ProductionOverproductionAllowance.remember` (草稿重存会把没改的行删了重插，原样带过来的行不再记一次，免得盖掉之后审批通过的比例)；并入原计划时带明确比例也走它；已存明细原地改比例或来源由更新触发器 `fn_remember_plan_overproduction_rate` 调用 (只在比例、来源、删除标记变化且结果为 `EXPLICIT`、未删除时记)。V737 删掉了插入触发器：插入不代表新的确认。审批通过的比例调整另由审批记忆触发器更新。
- **客户端预填**：系统预填的比例格只由一个助手 `SystemPrefilledRates` (`lib/features/production/widgets/production_overproduction_rate_field.dart`) 判断，物料分析页、汇总下单表与计划编辑页共用：格子里仍是预填文本 = 没人改过，提交空值；人改过就按所填值明确提交。计划编辑页载入草稿时，来源为 `DEFAULT` 的行也算系统预填，没人动就一直提交空值 (挪动行也一样)，并随行带回 `sourceItemId`；复制行沿用原行的预填记录与 `sourceItemId`；给行换选货品即作废原预填记录并清掉 `sourceItemId`，再按新货品的默认重新预填。新快照带来新默认时，没人改过的格子连文本一起刷新；人改过的格子文本不动，只把预填记录换成新默认，之后改回旧默认或撤销都按当前默认比较，看到的比例就是提交后服务端填的比例。汇总下单表的比例格在各来源都没人改过时跟着来源刷新；撤销时，快照时仍是预填的格子回到当前默认值。
- V737 清掉 V709 以来被默认值钉住的记忆，只按最新一次审批通过的比例调整恢复。

### 2.11 界面

- 货品「组装信息」：「数量」改名「设计使用数量」，其后加只读「真实使用数量」(与设计值同一计量口径；没有数据或不适用显示「—」，悬停说明原因、有效批次和累计产量)；学习边带「系统学习」标记，标记槽宽按标记文字实测 (`UtenStatusBadge.measureWidth`，各语言、字号档都完整显示)，不写死像素；导出/预览/PDF 14 列；导入认「设计使用数量」与旧表头「数量」，忽略「真实使用数量」，设计使用数量为空报错不再静默按 1。
- 导出与导入的精度：导出的基准产量、设计使用数量、真实使用数量按完整精度写成数值 (数量列类型 `ExportColumn.QTY`，Excel「常规」格式，0.004 不再显示成 0.00)；导入按单元格存的值读数字 (不按显示格式)，含公式的文件整份拒收，所以导出再导入数量不变。已知限制 (另行跟踪)：导入不读「颜色」列，导入的行都不带单独指定的颜色 (按组件自己的颜色)；用替换模式导入时原有行的颜色被清掉，带颜色的系统学习边因此转为人工边。
- 悬停说明：在 BOM 内且有真实数据的边分两行，「按 N 批已完工生产累计：净耗 X / 产量 Y」和「物料分析和车间领料按真实使用数量计算」(计算采用真实值时)；格里显示的不是每件平均时 (按包装的边是每包用量，整包/固定批次没有真实值) 另加一行「实际平均每件用 X」；重新学习过的加一行「从 <日期> 起重新累计」。不用真实值时说明「<原因>，计算按设计使用数量」。真实值可用 (`ACTUAL`) 且这段累计登记过不良时，在批次行后另加一行「另有不良 X：按实产(良品+不良)算用量为 Y，不良率 Z」(§2.13)；实产单耗或不良率任一为空时不加。组装信息页签只知道父件 id，这一行的不良数不带父件单位；学习记录里带。
- 编辑学习边时提示「改设计使用数量后转为人工维护，真实使用数量照常累计」；只有改了数量才提交数量；删除确认说明学习组件删除后不会被自动加回。
- 「BOM 学习记录」头部显示累计实际产量、有效生产批次与累计不良，逐组件列出设计使用数量、真实使用数量、实产单耗、累计净耗料、累计产量 (用到该物料的族的良品产量，即暴露产量)、不良数、不良率、有效批次、计算采用，及 BOM 外实际用过的料、已删除不再自动加入的料。BOM 外的料不参与计算，「计算采用」显示「—」；真实使用数量只在有真实数据时显示每父件平均用量，否则显示「—」并悬停说明原因；实产单耗与不良率服务端给空时显示「—」，不良数没有时显示 0。累计产量与累计实际产量都只算良品，列名沿用；页面说明写明不良数只作记录、不计入产量。抽屉宽度 1700 (基准画布下一屏放下全部列；窗口更窄时按屏宽封顶，表格可横向滚动)。
- 学习记录接口 `GET /api/master/goods/{id}/bom-learning` 返回 `{profile, components, canRelearn}`：组件行 = 身份字段 (组件、单位、是否在 BOM 内、组装行 id、是否已删除、设计使用数量) + 与组装信息页签同名的 `actual*` 字段 (§2.2)。「从现在起重新学习」按钮只看服务端给的 `canRelearn` (与接口鉴权同一个 `goods:bom:edit`)，页面不另做权限判断，且只出现在已有累计记录的组件上；`POST .../bom-learning/relearn` 返回同一份记录，页面直接显示，不再多读一次，组装信息页签随后重读真实使用数量。
- 物料分析「需要数量」单元格悬停说明本行按哪个用量算、依据几批、设计值多少；按真实使用数量算且采用时的不良率大于 0 时，括号里另列「不良率 X」，按设计使用数量算时不列。不用真实值的原因只有一个多语言来源 `bomDesignReasonText` (`lib/features/basic_data/models/goods_bom_item.dart`)，组装信息页签、学习记录与物料分析都走它，物料分析不再另存一份。

### 2.12 性能与并发

- 学习触发器只在相关列真变化时起跳；需求表只看 `execution_segment_id/is_deleted/goods_id/unit_id` 的更新。
- 队列主键改为 `(transaction_id, execution_root_id)`，不再成为跨事务的族互斥锁；族在排空时用事务级 advisory 锁串行。
- 锁顺序固定：可能发布学习边的父件货品行 (按 id 排序，一次锁定) → 族 advisory 锁 → 父件学习 advisory 锁 (同一父件的样本、用量行、档案与重新学习都在它下面串行，样本在锁内重新读取) → 仅新建学习边时：候选组件 `FOR KEY SHARE` (与 `GoodsRepository.lockForReference` 同一道 ADR-111 栅栏，并发删除组件或改单位先完成) → BOM 图 advisory 锁。人工 BOM 写入先锁父件货品行再取图锁；一次写多个父件的导入先按 id 排序锁住全部父件。普通人工 BOM 父件的排空不锁货品行，队列/样本/用量表的外键检查不再等待别人的排空。
- 人工 BOM 触发器只改本行 (`NEW`)，不写档案/用量表。

### 2.13 报工不良数

所有车间的报工行都可以填「不良数」(`production_daily_report_items.defect_qty`，与数量同单位，默认 0)。它只记录：不进良品数、库存与入库、FQC、超产、分流，也不参与任何数量校验。

- **约束**：只能填在有车间任务、良品数大于 0 的行上 (不开纯不良行，CHECK `daily_report_defect_needs_good_output`)；服务端把一次录入的产出批拆成多段时，不良数整笔放在第一段 ((行号, id) 最小)，数据库延迟约束 `daily_report_defect_first_slice` (触发器 `trg_assert_daily_report_batch_defect`) 兜底，免得按分段重复计算。
- **录入 (报工编辑表)**：「完工申报量」后一列「不良数」，可选，空 = 0；表头说明「只记录，不影响良品数和库存；用来算实产单耗和不良率」(编辑表与详情表同一句)。只有已选报工工单的行能填，其它行显示「—」；输入框只接受数字、最多 4 位小数。表单草稿保存并恢复不良数；复制行带上不良数 (已批准追加批次的复制行不带来源，也不带不良数)；换选或清除来源时清空；已批准追加批次的行来源与总量固定，不良数仍可改。
- **校验文字**：客户端格内红框与保存校验共用一个口径 (`productionReportDefectIssue`)，保存时前面加「第 N 行」：「不良数请填写不小于 0、最多 4 位小数的数量」「不良数只能记在已选择报工工单的行上」「先填写大于 0 的完工申报量，才能记录不良数」。保存时它排在完工申报量与来源的原有检查之后，后两句因此很少弹出：没选工单的行本来就不能填 (换选或清除来源会清空)，填了不良数却没填完工申报量的行格子红框，保存先提示「第 N 行完工申报量必须大于 0」。服务端新建与修改草稿都经 `ProductionDailyReportService.requireValidDefect`，不良数为空或 0 不校验，否则：「不良数不能为负」「不良数最多 4 位小数」「不良数只能填在已选车间任务且良品数大于 0 的报工行上」。
- **拆段**：拆分只按良品数 (需求份额与公共产出、转下一道工序与送仓库、原工单与追加工单)，不良不占超产允许量，也不进直送数量。`DailyReportOutputAllocationService.keepDefectOnFirstSlice` 是唯一的放置规则：整笔不良放在拆出的第一段，其余段为 0；已批准追加批次先拆成原工单与追加工单两部分时也用它 (没有原工单部分时放在追加部分)，再拆段时仍只第一段带。页面打开草稿时按产出批把各段不良数加回一行；详情表一批拆成多条明细时不良数只在第一条显示，其余留空。
- **接口字段**：日报新建/修改请求 `items[].defectQty` 可选，缺省或 null 按 0，客户端只在大于 0 时发送；追加计划申请带的整单快照 (`reportContext`) 同一字段，从申请回到原表时一起恢复。日报详情返回 `items[].defectQty`，总是数字 (没有为 0)。组装信息页签行与学习记录组件行 (`BomItemUsage`，BOM 外的料按 `OFF_BOM_COLUMNS` 同序读) 返回 `actualDefectQty` (数字，没有为 0)、`actualPerProducedQty` (与 `actualQty` 同一计量口径，只有 `ACTUAL` 才有值，否则 null)、`actualDefectRate` (0..1，这段累计没有产出时为 null)；学习档案返回 `profile.totalDefectQty`；物料分析节点返回 `usageDefectRate` (0..1 或 null)。
- **幂等指纹**：`createRequestHash` 只在不良数不为 0 时把 `lines[i].defectQty` 放进指纹；不填与填 0 是同一份申报，指纹与加这一列之前相同。同一幂等键换了不良数再提交得到 409「同一幂等键已用于不同的生产日报创建请求」，不会被当成重放。追加计划申请的指纹嵌入整单快照的这份指纹，规则相同。
- **FQC 补产行**：这些行也有执行分段，页面同样给不良数输入，数据库接受并记录；但学习的良品产出与不良都不含 FQC 补产行，这些不良不进不良率。
- **学习口径不变**：真实使用数量仍是「每个良品」= 核清实物净耗 ÷ 良品产出。计划要的就是这个数：交付 N 个良品要备多少料，不良吃掉的料已经在净耗里。
- **不良只派生两个说明数**：族的已审不良 (不含 FQC 补产行) 与良品一起随暴露记入样本、用量行 (`exposure_defect_qty`，有自己的重新学习基线与轮次) 和档案 (`total_defect_qty`)。视图给出本轮窗口的不良数、实产单耗 = 净耗 ÷ (良品 + 不良) (可与设计使用数量的工程单耗对比) 和不良率 = 不良 ÷ (良品 + 不良)。只改不良数也会重算该族。
- **物料分析**：节点采用用量时一并锁定当时的不良率 (`usage_defect_rate`)，只用于说明，不参与计算。它与真实值成对 (§2.5)：只在视图采用真实值时取，按落库精度四舍五入到 6 位，只在 `MaterialAnalysisBomSnapshotReader.edgeUsageLateral` 这一处做 (快照读取与人工刷新采用共用，采用时比较有没有变化也就不会因 6 位以下的差别重写)；锁定、沿用与计量规则变了重取都跟着真实值走。按设计值算的节点里，单一子件委外发出的节点 (`SUBCONTRACT_OUTBOUND`) 保留真实值作路线改回自制时的依据，不良率随之保留；其它按设计值的节点 (没有数据、不线性、父件单位变了) 为空。它是用量列，不进结构守卫。
- **界面**：报工编辑表可填不良数，详情表在「完工申报量」后显示；组装信息页签「真实使用数量」悬停 (§2.11)、BOM 学习记录显示不良数、实产单耗与不良率 (头部显示累计不良)；物料分析「需要数量」悬停只在按真实使用数量算时列出采用时的不良率。不良率统一由 `formatBomDefectRate` 显示成百分数：最多 2 位小数并去尾零，有不良但小到四舍五入会成 0% 时显示「<0.01%」。
