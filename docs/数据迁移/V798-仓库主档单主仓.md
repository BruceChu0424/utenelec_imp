# V798 仓库主档单主仓与禁用不可选

- 迁移：`V798__warehouse_single_main_master_shape.sql`(本分支临时号，合并时由编排者重排)。
- 决策：[ADR-145 仓库主档单主仓与禁用不可选](../99-决策记录-ADR/ADR-145-仓库主档单主仓与禁用不可选.md)。
- 不加表、不加列、不加权限点；只装函数与守卫，并收敛仓库主档的层级/状态和不合规的货品所属仓库。不搬库存、不改任何单据。reset 分类不变。
- **发版约束：必须与 V799(不良品仓规则, ADR-146)同一次合并、同一次发版。** V798 把原来各自独立的两个不良品仓(002、C0401)挂到主仓 001 下，它们与良品子仓变成「同一主仓」；只靠同主仓判定的消费方(物料分析、齐套 `may_allocate`、预备料让料、预算读取等)要靠 V799 统一排除不良品仓，单独上线 V798 会让不良品仓里的货被当成同主仓可用。

## 为什么要改

测试服务器上五金仓库 C01、成品仓库 C04、两个不良品仓、轨道车间各自是独立顶层仓(每次老库重导 `migrate_warehouse.sql` 都先删光仓库再平铺插入)，以 001 为主仓的物料分析、主仓安全数预算、主仓负责人范围看不到五金和成品库存；C01 每次重导都被老库状态重新置成「禁用」，却是 5248 个货品的所属仓库。停用仓库从不检查库存和归属，所属仓库可以设成主仓、禁用仓、不良品仓。详见 ADR-145 §1。

## 迁移做了什么

1. `LOCK TABLE warehouses IN SHARE ROW EXCLUSIVE MODE`。
2. 共用函数(服务层与守卫同一定义)：
   - `fn_warehouse_name_key(name)`：名称比对键(去掉全部空白含全角空格、全角括号转半角、不分大小写)；
   - `fn_warehouse_root_id()`：唯一主仓 = 编号 001 的未删除仓；没有 001 时取唯一的未删除普通顶层仓；判断不了返回空；
   - `fn_warehouse_is_good_stock_leaf(id)`：新单可选良品子仓 = `fn_warehouse_is_active_accounting_leaf` 且不是不良品仓。仓库字典 `selectableForNew` 就是它；
   - `fn_warehouse_selection_exit_blockers(id)`：仓库退出新单可选(停用、删除、改不核算、改成不良品仓四条路共用)的前置条件，返回给人看的原因数组(还有库存、还是货品所属仓库、未结库存预留、已开启整批领料的内料仓；V800 把最后一条换成开通表的两条)。
   - `fn_warehouse_retirement_blockers(id)`：停用/删除前置条件 = 「它是主仓(全公司仓库的汇总), 不能停用或删除」(主仓无条件拒绝; 下面挂着子仓的其它仓「它是主仓, 下面还有 N 个子仓」) + 上面的退出新选前置条件。
3. 存量收敛(表里没有仓时跳过，只装函数)：
   - 没有 001 又有多个顶层仓 → 中止「请先确定主仓再升级」；主仓是不良品仓 → 中止；
   - 主仓置为顶层、状态「使用」；
   - 内料仓必须已在主仓下，否则中止并列出(有流水的内料仓不能改挂，只能人工处理)；
   - 其余未删除普通仓一律挂到主仓下；
   - 禁用但仍被货品归属或还有非零余额的仓 → 改「使用」；
   - 禁用且所有引用 `warehouses(id)` 的外键列(从 `pg_constraint` 动态枚举，发现多列外键直接中止)与物料分析参与仓 `participating_warehouse_ids` 都没有引用的仓 → 软删除；
   - 货品所属仓库指向主仓/不良品仓/停用仓/内料仓等不可选仓的 → 置空(不猜仓，由入库自动学习或人工重填)，条数用 NOTICE 报出；
   - 未删除仓规范化名称重名 → 中止并列出(不在 Flyway 里做通用合并：引用表有大量身份不可变守卫)。
4. 守卫：
   - `fn_guard_warehouse_master_lifecycle`，触发器 `trg_guard_warehouse_master_lifecycle` BEFORE UPDATE OF status, is_deleted, parent_id, is_defective, is_accountable：停用/删除时按停用前置条件拒绝；改成「不核算」或改成不良品仓时按退出新选前置条件拒绝(「仓库「五金仓库」现在不能改成不核算: 还是 5248 个货品的所属仓库」)；子仓不能改成顶层、只能挂在顶层仓下、有子仓的仓不能再挂到别人下面；有库存不能改仓库用途(两个方向)、有子仓的仓不能是不良品仓。
   - `fn_guard_goods_ordinary_owning_warehouse`(REPLACE)：新写入或值变化时要求所属仓库是可选良品子仓；值不变的普通改档不重新判定；仍对仓库行加共享锁，与停用/改用途互斥。
   - 报错都是 `RAISE '<中文>' USING ERRCODE='23514'`，接口原样回显 422(ADR-151 §4)。
5. 事后断言：恰好一个未删除顶层仓、其余未删除仓都直挂它、不存在「禁用却有库存或被归属」的仓。

## 对现有数据的影响

| 库 | 迁移前 | 迁移后 |
| --- | --- | --- |
| 克隆库 `uten_imp_who`(开发库同源) | 002/01/C01/C04/C0401 是顶层；C01 禁用且被 5248 个货品归属 | 10 个子仓全部直挂 001；C01 改「使用」；各仓货品归属数不变(C01 5248、C04 196、XW01 8214、XW02 1944、XW03 6)，没有被置空的所属仓库；执行 71 毫秒 |
| 测试服务器(只读核对) | 同上，C01 已由用户 10-04 手工启用 | 预计只改 5 个仓的上级；无软删除、无所属仓库置空 |
| 全新空库(CI) | 无仓 | 只装函数和守卫 |

升级后以 001 为主仓的物料分析、主仓安全数预算会开始计入五金、成品库存(期望行为，刷新分析即可)；不良品仓不进可用量由 V799/ADR-146 统一口径保证。

## 服务端与页面同步(同一步)

- `WarehouseService` 新建/编辑上级仓库补成主仓、拒绝挂到别的仓、拒绝第二个顶层与规范化重名；停用预检列出原因；仓库资料不能新建/改成内料仓；字典/列表/详情下发 `defective`、`selectableForNew`；列表主仓置顶；新增「仓库用途」列(可筛选、可导出)。
- `MasterLifecycleService` 批量启停/删除同一预检；`GoodsMasterRelationshipResolver`、`GoodsOwningWarehouseWriteService` 所属仓库只在值变化时校验可选良品子仓；`GoodsOwningWarehouseSyncService` 入库不学不良品仓/不可选仓；`LineSideWarehouseService` 不再生成「 (主仓名)」后缀。
- 前端 `WarehouseDictEntry` 带 `isDefective`/`selectableForNew`；`WarehouseSelection` 按用途(运营/查询)只认服务端标志；所属仓库两个入口改运营口径；查询面板默认不列停用仓；仓库资料页上级仓库只读固定主仓、仓库用途列与字段、内料仓字段只读、停用被拒原样提示原因。

## 老库迁移脚本(同一步)

见 ADR-145 §2.8 与 [legacy_migration/README](../../server/legacy_migration/README.md)：入库的 `warehouse_crosswalk.csv` 决定每个老库仓 id 的去向(SPLIT/KEEP/MERGE/DROP/TARGET)；`migrate_warehouse.sql` 不再 DELETE、上级固定主仓、状态取目标值、不良品仓按对照表；各单据脚本不再补建「(迁移自动补录)」仓库存根(委外脚本存根状态 `'in-use'` 一并修正)；老库主仓 132 的库存明细/流水/余额按货品所属子仓拆分；对不上的单据与余额写 `bootstrap_warehouse_exclusions`、对账扣减并导出 `data/import_report/warehouse_exclusions.csv`；新增 `--goods-owning-warehouse` 步骤；导入映射协议 `bootstrap-v13`。

## 验证

- `WarehouseSingleMainMasterMigrationPostgresTest`：多顶层无 001 中止、典型老库形态收敛、内料仓不在主仓下中止、规范化重名中止、停用/删除前置条件五类原因、两层树守卫、仓库用途守卫、所属仓库守卫、全新空库只装函数。
- `LegacyMigrationSafetyContractTest`、`LegacyBootstrapCoordinatorPostgresTest`、`legacy_migration/test_*.py`：对照表与脚本规则、真实 `migrate.sh --bootstrap-all` 的主仓收敛/拆分/不迁清单。
- 8085 + `uten_imp_who` 真实接口：先把克隆库恢复成迁移前形态(5 个扁平顶层仓、C01 禁用)再由后端启动执行 V798，结果见上表；之后用非超管账号(临时授予仓库新增/编辑/启停/删除与分析路线权限，测完撤回)逐条验证 ADR-145 §4 的接口行为。
- 性能：所属仓库置空按仓判定一次(逐货品调用函数在克隆库要 10 秒)，整条迁移 71 毫秒。
