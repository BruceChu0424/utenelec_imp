# 临时密码手动与随机统一入口

用户本轮要求：临时密码支持自己输入或随机生成，超级管理员可以为其他超级管理员设置临时密码。本轮使用 frontend-design，沿用 Uten 对话框、输入框、分段控件、主题和间距。

账号与权限管理、人事详情共用 `TemporaryPasswordInput` 与一次性 `TemporaryPasswordChoice`。随机模式仍由服务端生成；手动模式校验非空和两次输入一致，原文提交，不修剪空格。输入只保存在本次弹窗内，取消、切换随机、身份或目标失效时清空，不进入草稿、日志或持久存储。

两个原 reset-password 接口保留，省略请求体继续随机生成，可选 `temporaryPassword` 为手动输入。客户端仅在新摘要能力字段存在时开放手动模式；旧服务端继续使用随机模式。手动响应必须与输入一致，否则按结果不确定处理，不冒充已设置成功。

`passwordResetSupportAllowed` 只控制重置密码。账号锁定、停用等仍使用原 `accountSupportAllowed` 边界；本人通过既有修改密码入口处理，未绑定员工或不符合任职条件的账号继续受生命周期保护。有效期、首次改密、人工锁定、停用状态、会话撤销、再次认证及审计由同一服务端权威处理。

网络中断、超时或不完整回执不能证明未生效。两个入口共用结果分类，显示待核对提示，员工弹窗停止重复提交并提供关闭刷新；不自动重放凭据变更。明文凭据交付继续绑定原身份、请求代次和目标，账号切换或撤权后不展示迟到响应。

Web 与 Flutter 桌面共用上述入口。Win7 WPF 尚未迁入员工账号安全/管理写入口，保持未迁移，不因后端兼容合同开放写操作。最终回归、实际界面和发布证据随本次整合回执保存。

## 独立审查与补验

独立审查基于 `06e655c96`，修复三个已复现的边界：

- 员工详情 `_sameAccountAction` 已接收 `passwordReset`，但未传给 `_maySupportAccount`，使仅有重置能力、普通维护能力为false的目标在点击后被错误关闭。现按原参数透传；实际详情入口的手动/随机路径均覆盖点击、提交、一次性凭据交付和刷新，普通锁定/启停入口仍不开放。
- 旧端手动模式原来只在分段按钮禁用，未在提交点拒绝残留的手动状态。两个入口现共同调用 `TemporaryPasswordInputController.validate(allowManual: ...)`，并检查分段选择回调，旧端仍只允许缺省无请求体的随机模式。
