# 批领料未知提交与草稿证据保全

日期：2026-09-30。归属 R1.04 / R2 草稿共性交互。当前工作树为隔离候选；只改 Flutter，未改后端协议、业务量口径、库存、迁移或服务器。输入来自整合树 `platform-overhaul-20260930/uten_imp`，按文件 SHA 接收，不能用本树 d1 基线的全部 diff 覆盖整合树。

## 已实现的合同

- 普通批领料和材料明确批领料在发送前持久化原幂等键、单据集合、申请、重量、备注。发送前检查账号、服务器、路由当前性和选择身份；同一集合顺序变化保留页面，更换集合或草稿标识重建页面。
- 首次提交的明确业务拒绝允许纠正；一旦原提交结果未知，后续 400 / 403 / 422 等拒绝不能证明原请求未执行，原键和原体继续冻结。GET 已出完也不证明本批完成。批准过的普通领料原键重放只要求当前出库权限，最终由后端既有父回执核验。
- 可靠回执先转入已确认内存状态，再做本机检查点、清理与返回；后续本机失败不能重发。普通批回执必须覆盖全部所选单据；空回执不确认。恢复时统一未知标记、已知旧批领料/FQC 冻结体保守合并，显式 false 不能覆盖仍未知的冻结体；矛盾或不完整恢复不能触发成功清理。
- 在途请求禁止退出；未知结果允许“保存原提交后离开 / 继续核对”，不提供“不保存”，真实 discard 分支还要复验。FQC 单张和整单只增加必要未知状态 getter，保留原审核责任确认与既有恢复逻辑。
- `FormDraft` 统一提供 `hasUnknownSubmission`，本机快照保存 `_formDraftHasUnknownSubmission`。兼容旧通用 pending、旧 FQC、旧批领料；已确认检查点、明确拒绝、已确认后的未提交余量仍可正常处理。`FormDraftsNotifier.delete` 在读取最新磁盘内容后拒绝未知删除，并继续以 CAS 防陈旧修订；`complete` 是实际业务确认后的独立通道。
- 分类草稿表、旧草稿面板、任务中心表均保护未知记录。正式行覆盖本机未知时，禁用删除/选择并保留核对入口；等待服务端最新详情期间本机变未知或修订变化，正式 DELETE 不发送。
- 正式草稿与本机填写同删：先通过服务端最新详情/权限预检，再 CAS 删除用户已明确确认丢弃的本机修订，然后发正式 DELETE。预检失败本机输入保留。CAS 失败不发正式 DELETE；旧修订的其它页不能再保存 pending 命令。正式 DELETE 后续失败/未知时明确说明“本机填写已按确认清除，不会自动恢复”和正式结果，不宣称“没有任何变化”。不做自动跨页恢复，不创建无恢复入口的 claim。
- 生产板批删保持原服务端批量事务；收到正式成功后，本机清理若遇新未知记录则保留并报告“正式成功 + 原提交待核对”，不倒推正式失败。

## 关键边界与范围

本机 CAS 与正式 DELETE 不是跨系统原子事务。确认弹窗已明确上述先后顺序和本机丢弃代价；断电或网络中断后仍须核对正式列表。未新增服务端删除回执。分类表的观察状态保护不替代服务端权限/状态校验，也不宣称它单独解决所有其它页的并发编辑。真正关闭同一旧本机修订由任务中心删除流程的存储 CAS 完成。

本轮不把当前版本冒充用户所见版本，不调整普通领料锁后执行量，不改 FQC 写协议，也未处理全平台字段/表头完整性；后者按整合树 08/16/17 的后续任务继续。截图只验证所列分辨率、主题和字号的未知反馈及退出交互，不能代表整页密度、所有语言或全平台布局验收完成。
