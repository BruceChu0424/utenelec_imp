## 〇、V234 订单行—计划前分析—分批生产口径

本节依据 [ADR-029](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)，优先于后续只覆盖正式计划的旧投影说明。它是 V234 分批销售进度的验收合同，不表示当前销售进度 API/页面已经返回 analysis item、plan link 或全部阶段数量。

销售订单生产进度按以下层级展示：

```text
销售订单
  └─ 销售订单行（产品、订货量、交期）
      ├─ 待分析/备料的 material-analysis item
      ├─ SUBMITTED plan link（计划草稿待批准，不计已下达）
      ├─ 正式批次 1（已完成）
      ├─ 正式批次 2（生产中）
      └─ 正式批次 3（READY、待发料）
```

一条销售订单行可以分批关联多张正式计划和多个执行批次；一张合并生产计划也可以精确分摊到多条销售行。界面不得按货品名称临时 JOIN，也不得把第一张计划的状态覆盖整条订单行。

每条订单行至少显示：

- 订货有效量、已取消量；
- 已进入计划前需求量、待分析/待料量；
- 已提交待批准量、已批准正式下达量、READY 待发料量、生产中量；
- 合格入库量、可发货量、已发货量和剩余量；
- 当前最早预计齐套日、订单风险和投影更新时间。

展开正式批次显示计划号、本批分摊数量、车间、状态、计划/实际日期和深链。计划前需求仅显示销售可解释的“待分析、备料中、预计齐套日、结构待确认”等状态，不暴露采购价格、供应商谈判、内部绩效或敏感缺陷责任。

MAKE `MAKE_COMPONENT` child analysis item、正式子件计划、报工和子件入库作为父批次的物料依赖单独下钻。只有子件合格入库并最终推动父产品生产/入库后，才增加销售订单行的父成品阶段量；子件自身数量不能直接记入销售完成。

阶段状态由数量投影派生，不回写一个人工百分比真相：

| 阶段 | 判定重点 |
|---|---|
| 待分析 | 有有效剩余需求，但尚无当前有效物料分析 |
| 备料中 | 有 supply action 或预计供给，尚无正数 READY 下达覆盖 |
| 已提交待批准 | 存在 `production_material_analysis_plan_links=SUBMITTED` 及计划草稿/ACTIVE planning draft，但尚未批准；不得计 READY 或已预留 |
| 部分已下达 | 已批准下达量大于零且小于有效需求量 |
| 生产中 | 有已发料/开工/审核报工但未全部合格入库的批次 |
| 已完成生产 | 父成品合格入库量覆盖有效需求量；不等于已发货 |
| 部分/全部已发货 | 继续以仓库审核发货事实判定 |

订单改量或取消时，未转下游计划前需求可撤回；已有正式计划、库存预留、发料、报工或入库时显示“处理中/需反向”，直到对应事实完成反向后再降低阶段数量。读模型不得提前把业务事实抹掉。

销售用户默认只能查看自己及授权范围的订单。生产计划和计划前需求深链是否可点击由服务端对象范围和 `allowedActions` 决定；无权时保留销售可见阶段量并显示锁定说明，不借深链扩大生产、采购或员工信息权限。

移动端按订单行折叠批次，首屏优先展示数量和风险；批次列表支持分页/按需加载。状态使用文本、图标和语义色共同表达；数字使用稳定对齐，动态字体下不得截断关键数量。加载失败显示数据截止时间和重试，不把空响应当“没有生产”。

## 一、页面职责

销售订单生产进度把订单行对应的生产计划和执行分段按销售可见口径展示，回答：

- 已排产、已生产、已入库各有多少；
- 当前由哪些生产计划和执行分段承接；
- 分段处于待料、待派工、已派工、生产中、已完成、已取消或已红冲的哪一阶段；
- 哪些分段已延期，以及销售可以对客户说明的原因。

该弹层是履约读模型，不是生产写入口，也不能用一个百分比替代各阶段数量。

## 二、点击行为

- 点击生产计划编号，先关闭销售弹层，再打开该生产计划详情；
- 点击某个执行分段，打开同一父计划详情并携带 `executionSegmentId`；
- 计划详情在分段加载完成后自动打开对应分段详情；
- 计划 ID 缺失、当前账号无查看权限或路由失败时必须给出明确反馈，不能静默无响应。

销售侧把执行分段称为“执行子计划”仅是展示文案；它仍不是 `subplan_links` 中的独立自制件子计划。

## 三、权限与敏感信息

- 只有具备生产计划查看权限或被允许的跨部门查看范围，计划和分段才表现为可跳转；
- 无权时保留销售可见进度，但显示锁定状态，点击提示“当前账号没有生产计划查看权限”；
- 对象范围与敏感字段必须由服务端裁剪，前端不得仅靠隐藏控件保护成本、报价、内部不良责任和员工绩效；
- 从销售页跳入生产页不会授予任何编辑、派工或报工权限。

## 四、数量与异常口径

- 分摊量、报工量、入库量分别展示，不能相加成单一完成率；
- 部分生产、部分入库、部分发货必须保留各自余量；
- 自制件子计划只展示自身计划/报工/入库事实；V194 的 MAKE peg 只推动父物料需求齐套，子计划计划量/报工量/入库量不得直接冒充父成品或销售订单完成量；
- 执行分段不存在或已被合法反向时，刷新服务端投影后显示真实状态；
- 读模型更新时间和主单据事实冲突时，以服务端权威单据为准并允许刷新；
- 没有生产计划的现货订单不应伪造生产进度。

## 七、历史现有订单进度查询看板 + 完工徽章（2026-08-04）

本节记录 2026-08-04 已有看板实现，供 V234 兼容和回归。其单一生产百分比只能保留为次要摘要，不能取代〇节的阶段数量和一行多批结构。

### 入口与路由
- 销售管理 hub「销售管理」分组新增入口卡 **订单进度查询**（`/sales/progress`，权限 `sales_order:view`），右上角带 **完工提醒徽章**。
- 看板页 `sales_order_progress_page.dart` 列出当前归属销售的全部已审订单，每单一卡。

### 历史进度口径
- 当前外层圆环使用 `Σ已产 / Σ订货`（clamp ≤1）。V234 新投影验收后它只作摘要，且不能单独靠绿/橙/红表达状态；卡片必须同时展示文字阶段、精确阶段数量、待分析/备料量和更新时间。
- 每卡显示 Σ已产 / Σ订货 / Σ已发 / Σ可发；阶段 chip 派生自聚合：待排产 PENDING / 生产中 PRODUCING（含已排产·待物料·生产中·部分完工）/ 可发货 SHIPPABLE（已产齐套）/ 已发货 SHIPPED。
- 点卡片 → `showPlanProgressSheet(orderId)` 打开本文档一~五节所述**按单**进度弹层（各产品 订货/已排/已产/已发/剩余 + 计划溯源 + 执行分段）。
- 有可发货行（`reserved_qty>0`）时显「去发货」→ 复用 `showSalesBatchShipPanel` 批量发货面板（选可发行 + 改数量；审核后 `shipped_qty↑ / reserved_qty↓ / chain_status→8·9`，分批发货原生支持）。

### 后端
- 新端点 `GET /api/sales/orders/progress?page=&size=`（权限 `sales_order:view`）：原生 SQL 聚合 `sales_order_items`（qty/produced_qty/shipped_qty/reserved_qty/planned_qty）by order，派生 `productionPct` 与 `stage`，归属范围同 `/stats`（`accessPolicy.nativeReadScope`）。DTO `OrderProgressRow`。无新表。

### 完工徽章（复用通知系统）
- 完工（成品入库审核 / 报工审核）经 ChainNoticeService→business_outbox→Notice(type=workflow, audience=订单归属销售) 投递；V209 给 `notices` 加 `source_event` 列，完工通知带 `PRODUCTION_FINISHED_INBOUND` / `PRODUCTION_REPORTED`。
- 徽章 = 该销售未读的完工通知数（`GET /api/notices/unread-count-by-source?events=...`），60s 轮询，`sales_order:view` 自卫。
- 打开看板即调 `POST /api/notices/read-by-source` 标记该批完工通知已读 → 徽章归零（已读语义），联动工作台「销售管理」卡徽章与全局未读角标（`refreshGlobalBadges`）。
