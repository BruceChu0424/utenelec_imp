## 〇、文档定位与关键决策

### 0.1 状态标识

本文用以下标识区分事实与目标，禁止把目标态写成已实现：

| 标识 | 含义 |
|---|---|
| **现状** | 当前仓库已经存在，并已在 README、代码、迁移或测试中找到依据 |
| **本期** | 本需求要求实现并通过验收的范围 |
| **后续** | 明确不在本期承诺，需后续 ADR、主数据或基础设施支持 |
| **上线阻断** | 未满足即不得启用生产写操作或不得对外宣称全链路可用 |

### 0.2 v2.x 不可变决策

1. **不新造平行生产主链**：继续使用现有父计划 `production_plans`、计划明细 `production_plan_items`、销售关联 `plan_order_item_links`、自制件计划关联 `subplan_links`、既有报工和库存主链；本期新增的排程分段只能作为计划明细的执行从属记录。
2. **不重复建报工表**：`production_daily_reports` 及其明细已存在；本期只能向前扩展或增加从属明细，不能再创建同名或同义报工主表。
3. **库存占用只有一个权威口径**：V150 已把 `stock_reservations` 演进为支持 `owner_type/owner_id/purpose` 的统一物理占用账，并保留销售兼容语义。销售与生产占用必须继续进入同一聚合口径；允许精确 posting/需求映射，但禁止孤立平行的“物料锁表”和 `is_locked` 布尔真相。
4. **销售进度不冗余回写**：销售端进度由 `plan_order_item_links`、审核生效的报工/成品入库和发货数量构建 CQRS 读模型，不向 `sales_order_items` 新增由 Service 手工维护的百分比真相。
5. **一键生成是两阶段操作**：第一次点击只生成可编辑预览，不锁库存、不建正式采购申请；用户确认时必须重算并在一个事务内校验、占用和落单。
6. **在途不是现货**：在途采购只能参与预计齐套日和采购净需求计算，未实际收货且未转为合格可用库存前，不得作为“立即可生产”数量，也不得被物理占用。
7. **计划、物料、报工、入库、清料分维度表达**：不能用一个状态或几个布尔值掩盖部分领料、分批报工、多次退料和反审核。
8. **主事务同步，旁路异步**：订单剩余量、计划、库存占用、领退料、报工审核、成品入库等在本地事务内同步保持不变量；通知、看板和跨模块查询投影经 Outbox/CQRS 更新。
9. **不硬编码 UI 和组织模型**：展示表与编辑表按组件契约分开；面板宽度、动画、颜色使用项目 token；权限按“权限点 + 部门授权 + 个人覆盖 + 对象范围”，不写死角色。
10. **不承诺无基础设施支撑的 10 秒实时性**：本期保证业务事件与主事务同提交、投影可重放并可观测；具体延迟以部署后的 SLO 为准，不在需求中写死 10 秒。

### 1.1 当前事实

| 数据质量 | 审计报告仍有 BOM 缺失、数量异常、成本与审计门禁问题 | 列为上线阻断，不用新代码掩盖旧数据问题 |

### 1.2 业务问题

1. 生产调度进入订单后无法一次看到完整 BOM、实际可分配量、缺料和供给日期。
2. 原流程把车间选择放在生成前，无法先看到系统按物料和产能给出的整体建议。
3. 部分物料足够时，整单等待；若直接给待料计划锁住全部非短缺料，又会长期占用库存。
4. 同一物料被多个订单、计划或采购需求重复计算时，缺少统一优先级、并发占用和供给分配规则。
5. 领料、超领、补料、实际消耗、良品/不良品退料、报废和在制结转没有统一核销等式。
6. 报工、不良、返工、差额补产、成品入库和销售进度的数量含义容易混用。
7. 生产变更、取消、反审核和红冲未形成对称矩阵，容易留下占用、采购、库存或进度残量。
8. 销售、采购、仓库、车间看到的信息口径不同，系统管理日志又不足以解释一次数量变化的原因。

### 1.3 本期目标

1. 提供生产调度工作台和订单排产页，BOM 物料默认直接展示，不设置折叠入口。
2. 删除独立“选择车间”按钮；由“一键生成子计划”先生成建议，用户在编辑面板中检查和调整车间、数量、日期、负责人和班组。
3. 准确计算即时可生产数量、预测可生产数量、缺料数量和预计齐套日，支持“可执行批次 + 待料批次”。
4. 确认排产时原子校验订单剩余量、BOM 快照和库存版本，并为可执行批次占用全部必需材料。
5. 缺料形成可追溯的采购需求建议和供给分配关系，采购申请不得重复生成或重复占用同一在途供给。
6. 完成派工、备料、领料、超领/补料、分批报工、成品入库、清料退库和计划结案的线上闭环。
7. 销售从只读投影查看各订单行已排产、可开工、生产中、合格、入库、可发货和延期原因。
8. 所有关键变更有语义审计、幂等键、关联单据和对称反向操作。
9. 建立同源的仓库备料/交接、采购需求池和部门 SLA 工作台；委外先完成来源决策与只读履约投影，统一写闭环按后续阶段放行。

### 1.4 后续范围

以下能力不在本期承诺为“自动精确排程”，但本期数据结构和接口不得阻断后续演进：

- 设备级有限产能 APS、工序级排程、换线优化、技能矩阵和自动求解器；
- 完整 IQC/IPQC/OQC、供应商退货、返工路线和不合格品成本域；
- 全自动替代料优化和跨产品全局物料线性规划；
- 机器采集、工位扫码、工序级在制品和 OEE；
- 通知 WebSocket/移动推送及经容量验证后的严格秒级 SLO；
- 完整标准成本、实际成本和差异分摊闭环。

### 1.5 上线阻断

满足任一项即不得开启生产写入功能：

1. 关键在产/待排产品 BOM 完整率不是 100%，存在循环 BOM、无效单位换算或未确认版本。
2. 开放订单/计划仍存在无法解释的 `完工量 > 计划量`、`入库量 > 合格量`、负占用或领退耗不平。
3. 库存账面、库存流水和统一可用量视图无法按仓库、货品、颜色对账。
4. 生产原料占用未进入统一占用服务，或并发抢料测试仍可超占。
5. 领料/退料成本过账、反审核和红冲不能对称恢复。
6. 生产权限点、跨销售负责人数据范围、敏感字段遮蔽和对象级鉴权未完成。
7. 关键动作语义审计覆盖率不足，无法按订单、计划、物料和单据追溯数量变化。
8. Outbox 虽已有源码，但生产环境的积压监控、投影重放、失败告警或延迟 SLO 尚未验收，却对业务承诺可靠实时通知。
9. 端到端、并发、迁移回放、备份恢复和上线对账演练未通过。

## 二、术语、参与方与权限边界

### 2.1 核心术语

| 术语 | 定义 |
|---|---|
| 订单剩余未排量 | 审核有效订单量减取消量、已生效计划关联量；不得直接用页面缓存计算 |
| 父生产计划 | 顶层 `production_plans`，承接销售生产需求和整体计划头信息 |
| 计划明细 | `production_plan_items`，表达父计划中的产品/货品、数量和计划日期，不等同于子计划 |
| 自制件子计划 | 另一张 `production_plans`，用于多层 BOM 中需要自制的组件，通过 `subplan_links` 关联父计划；不是本页面的排程分段 |
| 排程分段/执行批次 | V155 新增的计划明细从属记录，表达同一计划明细按物料状态、车间和日期拆出的执行部分；UI 可显示“子计划”，接口、模型和审计统一使用执行分段语义 |
| 立即可生产量 | 仅使用当前合格物理库存，在扣除统一生效占用、安全库存和冻结量后，所有必需 BOM 物料都可覆盖的产品数量 |
| 预测可生产量 | 计入已确认且未被其他需求占用、预计在需求日前可用的采购供给后推算的数量；不能直接派工或领料 |
| 物料占用 | 对当前物理库存的软占用，影响 `v_stock_available`；只对可执行批次创建 |
| 需求挂接（demand peg） | 待料计划与当前/未来供给的计划性关联，用于净需求和到料跟踪；不等于物理库存占用 |
| 供给分配（supply allocation） | 某采购申请/采购订单/在途/收货可用数量分配给具体需求行的记录，累计不得超过供给未结量 |
| BOM 快照 | 确认排产时固化的 BOM 版本、组成、单位、损耗、替代选择和生效信息，后续主数据变化不静默改变已确认计划 |
| 清料 | 对子计划累计领用、消耗、退回、报废/损耗和在制结转进行数量核销 |
| 结案 | 成品数量已按规则入库或处置，物料已清料，所有未决变更关闭后的终态；不是单纯“报工数量达到计划量” |

### 2.2 权限与数据范围

权限沿用现有“权限点 + 部门授权 + 个人覆盖 + 对象范围”体系。下表的部门只是建议授权模板，不是硬编码角色：

| 权限点 | 能力 | 建议授权范围 | 对象级约束 |
|---|---|---|---|
| `production:plan:view` | 查看待排产、BOM 齐套和计划 | 生产/PMC、生产主管 | 按获授权组织和产品范围；敏感销售字段裁剪 |
| `production:plan:preview` | 生成/编辑排产预览 | 生产调度 | 只能处理审核有效且有可排剩余量的订单行 |
| `production:plan:confirm` | 确认正式计划 | 生产主管或获授权调度 | 服务端二次鉴权和版本校验 |
| `production:plan:priority` | 设置急单、插单和冻结期调整 | 生产主管 | 必填原因；写语义审计 |
| `production:plan:dispatch` | 派工、调整班组/负责人 | 生产调度、车间负责人 | 仅获授权车间；冻结计划需更高授权 |
| `production:material:prepare` | 查看备料和需求 | 仓库、车间物料员 | 仅获授权仓库/车间 |
| `production:material:issue` | 审核领料/补料/超领 | 仓库及审批人 | 数量、仓库、批次服务端校验 |
| `production:report:submit` | 提交报工 | 工人、班组/车间负责人 | 只能报本人或被委派的任务 |
| `production:report:approve` | 审核/反审核报工 | 车间主管 | 提交人与审核人分离按现有审批规则执行 |
| `production:material:clear` | 提交消耗、退料和在制结转 | 车间负责人/物料员 | 不得超过可核销数量 |
| `production:return:approve` | 点收/审核退料 | 仓库 | 必须确认实物、质量状态和目标库位 |
| `production:dashboard:view` | 查看生产读模型 | 生产主管 | 按组织范围过滤 |
| `sales:order:production:view` | 查看订单生产进度 | 销售及其主管 | 沿用 `owner_employee_id` 和下属范围；不显示成本、物料价格、内部责任人绩效 |

所有写接口必须在服务端再次做权限和对象归属校验；前端隐藏按钮不是授权控制。

## 三、数据权威源与不可破坏的不变量

### 3.1 数据权威源

| 业务事实 | 唯一权威源 | 禁止做法 |
|---|---|---|
| 销售需求与可排剩余量 | `sales_order_items` + 审核/取消状态 + `plan_order_item_links` 聚合 | 在生产页缓存一个“剩余量”长期回写 |
| 正式生产计划 | `production_plans`、`production_plan_items`、`plan_order_item_links` | 再建平行“生产任务”主表 |
| BOM 需求 | 产品 BOM 主数据；正式计划使用确认时快照 | 执行中直接跟随最新 BOM 静默变更 |
| 账面库存 | 已审核库存单据/流水聚合到库存余额 | 由生产表直接加减库存余额 |
| 当前占用 | V150 演进后的统一 `stock_reservations`，由 owner/purpose 与需求映射区分销售成品和生产原料；有效量为原量减消耗减释放 | 新建孤立 `production_material_locks` 后与销售预留各算一套，或用布尔值表示数量状态 |
| 可用库存 | V150 以后重建的 `v_stock_available` 与统一库存分配服务；排产另扣安全库存，V160 仅在采购工作台做不落占用的临时自由库存覆盖 | 页面、排产和仓库各自写减法，或把 WAITING 的临时覆盖误写成物理占用 |
| 采购供给 | 采购申请/订单/收货模块的审核有效未结数量 | 把草稿或已取消采购计入在途 |
| 报工事实 | 现有 `production_daily_reports` 及明细中审核生效、未红冲记录 | 新建第二张生产报工主表 |
| 成品入库 | 已审核生产入库单和库存流水 | 只凭报工把产品视为可发货库存 |
| 销售生产进度 | 由计划关联、审核报工、成品入库和发货构建的 CQRS 投影 | 新增 `production_progress` 百分比列手工同步 |
| 操作追溯 | 业务语义事件 + HTTP 审计 + 关键表审计 | 只记 URL 和状态码，无法解释数量变化 |

#### V90 可用量缺陷与 V150 修复状态

V90 原始 `v_stock_available` 在同一货品/颜色同时存在“具体仓预留”和“全局仓为空的预留”时，可能因重复 JOIN 放大余额。V150 已使用 LATERAL 分别聚合仓级与全局有效占用并重建该视图；源码级缺陷已处理，但现网迁移后的历史余额、全局/仓级占用和所有调用方仍须在发布前对账。

全仓口径必须显式计算：

```text
全仓可用量
= Σ各仓账面量
 - Σ各仓生效占用量
 - 全局生效占用量一次
```

自动化必须持续覆盖“仅仓级、仅全局、二者并存、多仓、空颜色”以及并发占用；现网数据对账和调用方排查完成前，生产发布仍属于上线阻断。

### 3.2 数量不变量

所有数量先转换为基本单位并按物料/产品精度处理。数据库约束和服务校验至少保证：

```text
订单有效计划关联量 = Σ(计划订单关联分配量 - 已取消/红冲量)
0 <= 订单有效计划关联量 <= 订单审核有效量

占用有效量 = 占用量 - 已消耗量 - 已释放量
占用量 > 0
已消耗量 >= 0
已释放量 >= 0
已消耗量 + 已释放量 <= 占用量

供给有效未结量 = 审核供给量 - 已收货量 - 已取消量
Σ(该供给的有效分配量) <= 供给有效未结量

报工处理量 = 合格量 + 返工量 + 报废量
审核累计合格量 <= 计划有效数量
成品审核入库量 <= 审核累计合格量

累计审核领用量
= 确认消耗量
+ 良品退库量
+ 不良品退库量
+ 审批损耗/报废量
+ 在制品结转量
```

最后一个等式允许配置物料精度容差，但禁止用百分比容差掩盖长期不平。任何反审核/红冲必须用相反方向恢复同一组累计量。

### 3.3 BOM 快照

确认排产必须为每条正式排程分段保存可追溯的 BOM 快照，至少包含：

- 产品、颜色/规格、BOM 版本、生效区间和快照时间；
- 每个组成物料、基本单位、单台基本用量、发料精度；
- 损耗率或已含损耗标识、成材率/换算率；
- 必选/可选标识、替代组、替代比例、替代优先级和审批依据；
- 生成预览时版本与确认时版本；
- 快照创建人、确认人和来源订单行。

BOM 缺失、循环、单位不可换算、关键字段为空或版本在计划日期无效时，系统必须硬拦确认，不得按零需求排产。BOM 主数据后续变更只影响未确认预览；已确认计划通过“计划变更”生成新版本和差异记录。

## 四、端到端业务流程

### 4.1 总体流程

```text
销售订单审核有效
  → 生产待排产队列
  → 查看订单、BOM、库存、供给和粗产能
  → 一键生成子计划预览
  → 用户调整数量、车间、班组、日期和替代选择
  → 确认时重新鉴权、重算和加锁
      ├─ 校验失败：返回逐项差异，回到预览
      └─ 校验通过：原子生成正式计划、订单关联、BOM 快照、物料占用和采购需求挂接
          ├─ 物料全部占用：可派工 → 备料/领料 → 生产/报工 → 成品入库 → 清料 → 结案
          └─ 物料未齐：待物料 → 采购/收货/质检可用 → 重新净算并尝试占用

每个关键提交
  → 同一主事务写 Outbox
  → 异步通知、销售进度投影和生产看板
```

### 4.2 阶段说明

1. **进入待排产**：销售订单审核有效后进入生产队列；取消、驳回或可排剩余量为零的订单行不得出现为可操作项。
2. **查看物料**：进入排产页即展示全部产品及其 BOM 行，不需要用户逐卡展开；系统同时显示数据时间、水位和不可计算原因。
3. **生成预览**：按订单行、当前库存、BOM、已分配供给、交期和粗产能生成建议，不写正式业务单据。
4. **用户校正**：用户可以调整车间、班组、负责人、计划数量和日期；涉及替代料时必须显式选择并满足审批策略。
5. **确认计划**：服务端重新读取权威数据，锁定订单行和库存维度，生成正式计划、订单关联、BOM 快照、可执行批次占用及待料批次需求挂接。
6. **待料跟踪**：采购模块拥有采购申请/订单状态；生产只持有需求和供给关联。收货并转为合格可用后触发重算，不直接把待料计划强制改成可生产。
7. **执行闭环**：派工后产生备料需求；库存实际变化只发生在仓库审核的领料、退料、报废或转移单据上。
8. **报工与入库**：审核生效的合格数量进入生产进度；成品只有审核入库后才成为库存和销售可发货依据。
9. **清料结案**：完成领退耗核销和未决异常处理后结案；报工达到计划量不等于自动完成。
10. **旁路同步**：每个关键提交在同一主事务写业务事件 Outbox；通知和读模型异步处理，失败可重试和重放。

## 五、物料、供给与产能算法

### 5.1 计算输入与快照版本

每次预览返回以下快照标识，确认请求必须原样带回：

- `orderVersion`：订单头、订单行审核状态和有效数量版本；
- `bomVersionSet`：每个产品采用的 BOM 版本集合；
- `inventorySnapshotAt`：库存/分配读取水位；
- `supplySnapshotAt`：采购供给读取水位；
- `capacitySnapshotAt`：车间日历和已承诺负荷读取水位；
- `proposalId`、`proposalHash`：预览内容和用户调整后的摘要；
- `expiresAt`：预览有效期，只用于提示，不能替代确认时重算。

页面必须显示数据更新时点。任何输入缺失时显示“不可计算”，禁止用零伪装。

### 5.2 基本单位与需求量

对产品数量 `q` 和 BOM 组成物料 `m`：

```text
基础理论需求_m(q) = q × BOM每台基本用量_m

若 BOM 用量未含损耗：
毛需求_m(q) = 按发料精度向上取整(基础理论需求_m(q) × (1 + 损耗率_m))

若 BOM 用量已含损耗：
毛需求_m(q) = 按发料精度向上取整(基础理论需求_m(q))
```

禁止重复叠加损耗。`goods_bom_items.qty` 没有独立单位字段，始终表示“每一产品基本量所需的组件基本量”，
因此不存在需要另行维护的“BOM 用量单位”。订单或计划数量若不是产品基本单位，参与计算前必须通过
可验证的正换算率转换为产品基本量；采购行可以使用非基本单位，但必须通过有效单位和可靠的正换算率
转换为组件基本量。当前系统不以一张独立的“权威已审核换算表”为前提，无法确定单位、换算率非正或
精度冲突时必须标记“不可计算”并硬拦确认，不能自行猜测。

### 5.3 当前可分配量

以下公式只能使用修复后的统一可用量查询。统一查询已经扣除销售与生产的生效分配，所以不得再减一次已分配量：

```text
当前可分配基本量
= max(
    0,
    统一可用量
    - 安全库存
    - 质量冻结量
    - 盘点/业务冻结量
  )
```

规则：

- 安全库存按货品、颜色、仓库和生效日期读取。默认排产不得使用；越限必须有专门权限、审批和原因。
- 销售成品预留与生产原料分配可在 UI 中分项展示，但二者都已进入统一可用量，不能再次参与减法。
- 不合格仓、待检库存、报废库存和冻结批次默认不可分配。
- 跨仓数量逐仓展示。跨仓调拨只有目标仓审核入库后才成为目标仓可分配量。
- 全仓聚合必须按 3.1 的公式处理全局占用一次，禁止对存在重复行风险的旧视图直接求和。

### 5.4 立即可生产量

对每个必需 BOM 物料计算：

```text
物料可支持产品数_m
= 向下取整到产品数量精度(
    当前可分配基本量_m / 每台毛需求基本量_m
  )

立即可生产量
= min(所有必需物料的物料可支持产品数_m, 订单剩余未排量)
```

若一个 BOM 行选择了经批准的替代料，以替代比例换算成主料等价量后参与该行计算。任何一份替代库存不能同时分配给多个 BOM 行或多个预览；确认时必须重新检查。

---

### 5.5 齐套率与状态

齐套率表示可生产产品数量，不按有库存的物料行数平均：

```text
产品即时齐套率 = 立即可生产量 / 产品订单剩余未排量

订单整体即时齐套率
= Σ(产品剩余量 × 产品即时齐套率) / Σ(产品剩余量)
```

| 状态 | 判断 | 含义 |
|---|---|---|
| 齐套 | 立即可生产量等于剩余未排量 | 可为全部数量建立可执行分段 |
| 部分齐套 | 立即可生产量大于零且小于剩余未排量 | 拆为可执行分段和待料分段 |
| 完全缺料/不可执行 | 立即可生产量为零 | 只生成待料分段；原因可能是缺料、BOM 无效或库存冻结 |
| 不可计算 | BOM、单位、库存或权限数据不完整 | 禁止确认，不能当作完全缺料自动采购 |

物料行的采购净缺口始终为非负数。供给大于需求时单独显示预计结余，不使用负净需求表达。

### 5.6 在途供给与预计齐套日

只有同时满足以下条件的采购订单行才是合法在途：

1. 采购订单已审核、未停止、未结案且未删除，订单明细也未删除；
2. `max(qty - received_qty, 0) > 0`，不得重复计算已收货部分；
3. 已通过供给分配关联到当前需求，或在本次全局净算中尚未分配；
4. 预计到货日加收货/质检提前期不晚于计划需求日；
5. 供应商、仓库、货品、颜色和质量要求兼容；
6. 采购单位有效且换算率为可验证的正数，在途基本量按
   `max(qty - received_qty, 0) × unit_rate` 计算。采购单位可以不是货品基本单位，但不能缺少可靠换算。

单位校验只覆盖与本次需求相关且满足上述开放状态的采购订单行：只要其中任一行的单位或换算率无效，
本次齐套与净需求计算就必须 **fail-closed** 并提示治理，不能把该行当作零在途后继续计算。没有相关
开放采购行时，不要求为了本次计算补录采购单位；已完成、已停止、已结案或已删除的历史行即使存在旧
单位问题，也不阻断本次计算。历史旧尾数若业务确认不会再到货，必须由采购按业务事实停止或结案，不得
由迁移按单据年龄自动关闭。

系统按时间顺序累加当前可分配量和各日预计转为合格可用的未占供给，找到所有必需物料同时覆盖计划数量的最早日期，作为预计齐套日。该日期是预测，不创建物理库存分配；采购延期、部分收货、检验不合格或更高优先级需求调整后必须重算。

### 5.7 替代料

替代料必须来自受控主数据，而不是用户任意选择同类货品。每个替代关系至少具有：

- 主料、替代料、替代组、替代比例和使用优先级；
- 产品/BOM 适用范围、颜色/规格/批次约束；
- 生效/失效时间、质量状态、是否需要技术或质量审批；
- 对成本、标签、客户要求和后续追溯的影响。

预览可以推荐替代方案，但默认不自动确认。确认后把实际选择、比例、审批人和理由固化到 BOM 快照、领料单和报工追溯中。改变已确认替代方案必须走计划变更，并释放旧分配、重新校验新分配。

### 5.8 部分齐套与待料策略

1. 先按 5.4 计算立即可生产量，只对这一执行分段的全部必需材料原子创建物理分配。
2. 剩余数量建立待料分段和需求挂接，不占用尚未形成完整套料的非瓶颈现货，避免长期囤料。
3. 待料需求可在 MRP 净算中与当前/未来供给做计划性挂接；页面必须标识“预测供给，未保护库存”。
4. 任一库存、采购、订单或优先级事件变化后重新净算。只有所有材料在同一事务中分配成功，待料数量才转为可派工数量。
5. 不允许出现“状态显示可生产，但某个必需物料没有有效分配”的执行分段。

示例：订单 10 台，A 料可做 10 台，B 料只能做 6 台。系统生成 6 台可执行分段并分配 A、B 各自对应的 6 台用量；剩余 4 台建立待料分段和 B 料缺口。A 料剩余 4 台用量不因待料分段被长期锁死。

---

### 5.9 采购需求与供给分配

采购需求按物料、颜色/规格、仓库、需求日和质量要求全局净算，并保留到每个待料分段/BOM 行的需求挂接：

```text
待采购净需求
= max(
    0,
    待料分段毛需求
    - 本次净算可分配的计划供给
    - 已审核未结采购供给的有效分配量
  )
```

每次全局净算生成唯一 `nettingRunId`，并冻结订单/BOM、库存、有效分配、采购供给和需求优先级的读取水位。净算在该快照内逐笔扣减供给余量：

```text
供给可分余量_s = 供给有效未结量_s - 快照前已生效分配量_s

按稳定优先级遍历需求 d、按稳定顺序遍历兼容供给 s：
本次计划分配量_d,s = min(需求未满足量_d, 供给可分余量_s)
需求未满足量_d -= 本次计划分配量_d,s
供给可分余量_s -= 本次计划分配量_d,s
```

同一个 `nettingRunId` 内，一份供给余量只能分给一个需求一次，任何后续需求只能看到扣减后的余量；结果必须保留需求行、供给行、分配顺序和数量。不同用户的只读预览仍可能基于相近快照看到同一份尚未正式占用的供给，因此预览分配只表示估算，不形成保护。

用户确认时，服务端必须在锁和版本校验下重新读取供给有效未结量，按 `nettingRunId + demandId + supplyId + demandVersion` 幂等地把仍有效的预览分配转换为正式供给分配。任一余量已被其他事务使用、供给状态变化或需求版本变化时，整体拒绝并返回差异，不得把预览数量直接写成正式分配。

规则：

- 预览阶段只显示采购建议，不落正式采购申请。
- 确认阶段按预览标识、需求版本、物料维度和需求日幂等创建或更新采购草稿/待审核申请；重复确认不得重复申请。
- 多个执行分段可汇总为一条采购建议，但必须保留各自需求分配量；采购收货也必须按需求优先级重新分配。
- 已审批或已下单的共享采购不能因一个订单取消而整单关闭；只能释放该需求挂接，再由采购模块判断是否减量、改配或关闭剩余供给。
- 建议供应商仅是建议，来源和评分必须可解释；未经采购审核不得自动下单。

### 5.10 粗产能与日期

本期产能用于提示和建议，不宣称设备级精确 APS。存在可靠工艺路线/标准工时时使用：

```text
计划标准工时 = 计划数量 × 单位标准工时 + 换线/准备工时
某日可用工时 = 班次工时 × 效率系数 - 维护停机 - 已冻结占用
负荷率 = (已承诺工时 + 本次建议工时) / 可用工时
```

若标准工时、班次日历或路线缺失：

- 显示产能数据不完整；
- 不生成虚假的精确完工日；
- 允许有权限用户手工填写日期并记录原因；
- 不得仅用 `goods.daily_capacity` 作为长期权威产能模型。

默认优先推荐产品适用路线对应的主车间；超负荷时推荐兼容车间。冻结窗口由系统参数配置，可提供 3 天默认值，但业务代码不得写死。强制超负荷、调整冻结计划或插单必须显示受影响计划、延期天数和原因，并二次确认。

### 5.11 执行分段、合并与优先级

1. 不同产品不合并为同一计划明细或执行分段。
2. 默认按销售订单行保留最清晰追溯；需要合并生产时复用现有合并能力，并为每个来源订单行保留 `plan_order_item_links` 分配量。
3. 物料状态不同的数量必须拆分为可执行分段和待料分段。
4. 跨多日生产通过日程桶/作业段表达，不仅因为跨天就复制父计划、计划明细或自制件子计划。
5. 同产品、BOM 快照、替代方案、车间、质量要求和物料状态均一致时才可建议合并；客户专用标签或配置不兼容时禁止合并。
6. 自制件子计划仍由 `subplan_links` 关联父计划，不能用执行分段关系替代，也不能把一次车间分配误建为自制件子计划。
7. 排序至少考虑人工优先级、交货期、等待时长和已冻结承诺。设置特急需要权限、原因和审计；不得仅因交期三天内就静默改变已承诺计划。

## 六、一键生成、并发与幂等协议

### 6.1 生成预览

点击“一键生成子计划”执行只读计算。UI 延续业务叫法，接口返回的是排程分段建议，至少包括：

- 每个订单行的剩余量、BOM 快照候选和不可计算原因；
- 可执行分段、待料分段、物料需求、库存分配建议和采购建议；
- 推荐车间、班组、负责人、开完工日期及产能风险；
- 使用替代料的候选方案和审批要求；
- 对现有计划的潜在延期影响；
- 5.1 中的快照版本和 `proposalHash`。

预览不得创建正式父计划、计划明细、执行分段、库存分配、采购申请、领料单或销售进度。允许保存草稿时，草稿不是库存权威数据，并有明确过期状态。

### 6.2 用户编辑规则

- 计划数量必须大于零；同一订单行所有预览分段合计不得超过当前剩余未排量。
- 完工日期不得早于开工日期；交期外日期显示风险，但不擅自修改客户交期。
- 车间必须支持该产品/路线；班组和负责人必须属于或获授权服务该车间。
- 改数量后重新计算 BOM、物料、供给和产能，不能只改表格显示值。
- 删除只对未确认预览行开放。正式数据只能变更、取消或红冲。
- 用户把待料分段改为可执行时，必须重新取得完整物料分配，不能只改状态。
- 调整同一计划明细下各分段数量时，其有效数量之和必须等于该明细本次排程数量；未排部分明确保留为待排，不得丢失。

### 6.3 确认事务

确认请求以一个 `confirmationGroupId` 为原子单位；失败时不得静默只提交其中一部分。服务端在一个事务内按以下顺序执行：

1. 校验幂等键；已成功请求直接返回原结果。
2. 重新鉴权并锁定所选销售订单行，按稳定 ID 顺序读取。
3. 校验订单审核状态、取消状态、数量版本和可排剩余量。
4. 校验 BOM 版本、替代审批和单位换算；生成正式 BOM 快照。
5. 按仓库、货品、颜色的稳定顺序获取库存维度锁或既有 advisory lock。
6. 重新读取修复后的统一可用量、安全库存和冻结量，重算立即可生产量。
7. 若结果与预览存在影响数量、供给或日期的差异，整体拒绝并返回逐行差异；不得按旧值继续。
8. 通过既有生产计划应用服务创建或更新父计划和计划明细；在计划明细下写执行分段。已有父计划时不得重复建单，自制件展开仍由既有 `subplan_links` 流程负责。
9. 写订单关联、可执行分段的统一库存分配、待料需求挂接和幂等采购草稿。
10. 写业务语义审计和 Outbox 事件。
11. 事务提交后再由旁路投递通知、刷新看板和销售进度。

事务内跨模块调用必须经过 Facade/Port 或应用服务，不允许调度 Controller 直接写销售、采购或库存 Repository。

---

### 6.4 锁、约束与精度

- 订单行锁顺序固定，库存维度锁顺序固定；任何服务不得反向加锁。
- 确认、改量、取消、领料、释放分配和采购收货触发再分配时复用同一库存协调服务。
- 数据库必须约束分配消耗/释放不超过原始数量、计划关联不重复、执行分段有效量不超计划明细量、供给分配不超供给未结量。
- 空颜色、全局仓和具体仓的比较规则必须统一；全局占用在多仓汇总时只扣一次。
- 数量全程使用 `NUMERIC`/十进制定点和主数据精度，禁止浮点比较。
- 预览读取可以走 CQRS 查询；确认重算必须读取事务内权威表/服务，不以可能滞后的看板投影作为写入依据。

### 6.5 幂等键

| 操作 | 建议幂等维度 |
|---|---|
| 确认排产 | `confirmationGroupId + proposalHash` |
| 采购草稿生成 | `需求版本 + 物料维度 + 需求日` |
| 库存分配 | `executionSegmentId + bomSnapshotLineId + allocationVersion` |
| 派工/领料申请 | `executionSegmentId + dispatchVersion` |
| 仓库领料审核 | `stockDocumentId + auditVersion` |
| 报工提交/审核 | `reportId + submitVersion/auditVersion` |
| 成品入库 | `reportItemId/executionSegmentId + inboundVersion` |
| 退料审核 | `returnDocumentId + auditVersion` |
| 取消/红冲 | `sourceDocumentId + reversalVersion` |

网络重试、双击和消息重复消费均不得产生重复计划、重复执行分段、重复库存流水、重复采购、重复进度或重复通知。

### 6.6 批量排产与冲突返回

- 用户可多选订单生成一个批量预览，系统按交期和人工优先级统一净算物料和粗产能。
- 单次确认组采用全有或全无语义。若批量过大，前端应在确认前明确拆为多个确认组，不得服务端暗中部分成功。
- 冲突响应必须包含订单行、物料/仓库、预览值、当前值、差异原因和建议动作，支持用户一键重新生成预览。
- 不把库存不足返回为通用 500；使用明确业务错误码。数据库唯一约束或锁冲突仍需转换为可理解提示。

## 七、状态模型

### 7.1 状态建模原则

计划生命周期、物料就绪、报工审核、成品入库和清料是相互关联但不同的维度。页面可汇总成用户易懂的标签，数据库和服务不得把它们压成一个含义不明的状态值或几个布尔字段。

既有父计划、计划明细和自制件子计划状态继续由生产模块拥有；V155/V156 已用向前迁移增加执行分段及其事件，不直接重写历史状态值。本节同时保留尚未实现的质量、冻结和清料扩展语义。

### 7.2 排程分段生命周期

| 状态 | 进入条件 | 允许动作 | 离开条件 |
|---|---|---|---|
| 待物料 | 已确认，但未能为全部必需物料建立有效分配 | 查看缺口、关联采购、变更、取消 | 全部物料原子分配成功后转可派工 |
| 可派工 | 已确认、BOM 有效、全部必需物料已分配 | 派工、调整未冻结日期、取消/变更 | 派工后转已派工 |
| 已派工 | 已分配到车间/班组/负责人，备料任务已创建 | 领料、撤回派工、暂停、报工 | 首次审核生效报工后转生产中；撤回需满足无不可逆库存动作 |
| 生产中 | 至少一笔审核报工生效，可能分批入库 | 继续报工、补料、成品入库、暂停 | 合格/处置达到计划要求且无待处理质量项后转待清料 |
| 待清料 | 生产数量已达到结案条件，但物料或成品单据尚未全部核销 | 消耗确认、退料、报废、在制结转、成品补入库 | 成品与物料均核销后转已结案 |
| 已结案 | 成品处置和领退耗核销完成，无未决变更 | 查看、受控反结案 | 仅有专门权限且下游未消费时可反结案 |
| 已暂停 | 因质量、设备、客户变更或人工原因暂停 | 恢复、变更、取消 | 原因解除并复核物料/日期后回到相应状态 |
| 已取消 | 未执行部分已取消，分配和需求挂接已释放 | 查看、必要时重新排产 | 终态；不物理删除 |
| 已红冲 | 已生效业务被反向单据完整冲销 | 查看 | 终态；重新执行必须生成新版本 |

冻结计划不是独立终态，而是由冻结窗口/人工锁定产生的调整限制。处于冻结期的分段仍有生命周期状态，但普通调度不能改车间、数量或日期。

### 7.3 物料就绪状态

物料状态优先由分配和库存流水数量派生：

| 状态 | 判定 |
|---|---|
| 未分配 | 必需物料无有效物理分配 |
| 部分分配 | 至少一项有分配，但未覆盖该分段全部 BOM 需求；该状态不可派工 |
| 已分配 | 每个必需 BOM 行有效分配量均覆盖需求 |
| 部分领用 | 已审核领用大于零，仍有有效未领分配 |
| 已领用 | 计划要求领用已完成；超领/补料单独累计 |
| 待核销 | 已进入生产/完工，但消耗、退料、损耗或在制尚未平衡 |
| 已核销 | 满足领退耗等式且所有仓库单据审核完成 |
| 已释放 | 取消、变更或红冲后未消耗分配已释放 |

不得用 `is_locked`、`is_returned` 表达上述多阶段数量事实。

### 7.4 报工与质量状态

报工沿用既有 `production_daily_reports` 主表和明细：

```text
草稿 → 已提交 → 已审核
             └→ 已驳回 → 修改后重新提交
已审核 → 已红冲
```

只有已审核且未红冲记录影响生产进度。每次报工至少区分：

- 本次处理量；
- 合格量；
- 返工量；
- 报废量；
- 实际开始/结束时间和工时；
- 参与人员；
- 不合格原因、责任分类和处置；
- 关联排程分段、父计划、计划明细和来源订单行；
- 附件和备注。

满足 `处理量 = 合格量 + 返工量 + 报废量`。返工量在返工完成并再次审核为合格前不计入合格进度；报废不自动等同于差额补产，系统先计算订单缺口和交期影响，由有权限人员确认补产/变更。

### 7.5 销售链路状态

销售订单的链路状态继续从数量派生，不由生产页面直接改状态：

- 已排产：有效计划关联量大于零；
- 可开工：关联执行分段中有完整物料分配；
- 生产中：存在审核生效报工且未全部入库；
- 部分完工：审核合格或成品入库大于零且未达订单有效量；
- 可发货：审核成品入库并完成相应库存预留后存在可发数量；
- 已发货：沿用现有发货审核数量；
- 延期/待料是附加风险标签，不替代数量状态。

## 八、生产执行、领退耗与报工

### 8.1 确认后的库存分配

- 只有可执行分段在确认事务中创建生产原料物理分配；待料分段只创建需求挂接。
- 每笔分配必须包含所有者类型、所有者 ID、用途、排程分段、BOM 快照行、仓库、货品、颜色、基本单位数量、已领用量、已释放量和版本。
- V150 已选择演进现有 `stock_reservations`：销售成品预留和生产原料占用由同一聚合口径计算，旧销售写法通过默认 owner/purpose 兼容；不得再并行维护第二套余额。
- 取消或改量只释放尚未领用的部分；已领用数量必须走退料、消耗、报废或在制转移，不能直接把分配记录改成已释放。

### 8.2 派工与备料

1. 可派工分段由调度选择班组、负责人和计划日期后提交派工。
2. 派工提交创建仓库备料/领料申请，而不是直接产生库存出库。
3. 备料单按 BOM 快照和当前未领分配量生成，标明原料/替代料、仓库、批次要求、目标车间和需求时间。
4. 仓库可分批备料和分批发料；部分发料不自动把剩余分配释放。
5. 撤回派工前必须检查是否已有审核领料、审核报工或冻结日程；存在不可逆动作时走计划变更。

### 8.3 领料

- 仓库实物确认并审核领料单后，库存流水才扣减账面量，同时把对应物料分配从未领转为已领。
- 普通领料上限是 BOM 快照毛需求减累计已领量；其中已包含配置的正常损耗，不能再额外放宽。
- 仓库发料必须匹配货品、颜色、单位、仓库和质量状态。启用批次管理时还要匹配批次/效期。
- 少领允许分批继续领；计划是否可开工由车间确认，但物料状态必须真实显示部分领用。
- 扫码是交互手段，不改变服务端数量、权限和幂等校验。

### 8.4 超领、补料和来料不良

超出 BOM 快照未领额度的数量不得在普通领料单直接发出：

1. 申请人选择超领或补料类型，填写物料、数量、原因、责任分类、现场说明和关联排程分段。
2. 服务端校验计划仍可执行、未重复申请、库存可用和权限范围。
3. 生产主管或配置的审批链审核；涉及来料质量时同步质量/采购，但不由生产模块直接改采购结论。
4. 仓库依据已批准额度创建发料单；审批本身不扣库存。
5. 审核发料后更新领料累计、实际成本事件和语义审计。

来料不良在领料或生产中发现时，先把实物转入待检/不良状态，再通过退供应商、报废、返工或良品退库流程处置；需要补料时另走补料申请，不能一笔单据同时隐式完成退料和补料。

### 8.5 分批报工

报工入口包括排程分段详情、我的生产任务和待报工列表，三处调用同一提交服务。表单至少包含：

- 排程分段、父计划、计划明细和产品信息；
- 本次处理量、合格量、返工量、报废量；
- 实际开工/完工时间、总工时；
- 负责人和参与人员；
- 不合格原因、处置建议、备注；
- 生产现场、成品或检验凭证附件。

校验规则：

- 合格量不得超过该分段剩余有效计划量；不存在计划量加 5% 的合格超报口径。
- 本次处理量必须等于合格、返工、报废之和；各数量非负。
- 实际完工时间不早于开工时间；人员工时不能为负，明显超出时间跨度时提示并要求说明。
- 只有提交状态可送审；重复提交和重复审核使用幂等版本防重。
- 审核前不更新正式生产进度；驳回只返回修改，不产生库存、进度或补产。
- 审核后首次有效报工使分段进入生产中；红冲审核报工按相反方向恢复累计量和投影事件。

不良率按业务定义选择分母并在看板明确标注，例如 `报废量 / 处理量`；不能把返工和报废混成一个不良数。预警阈值由参数配置，达到阈值只触发预警和调查，不自动认定责任。

---

### 8.6 差额补产与质量处置

报废或审核不合格后，系统计算：

```text
待满足数量 = 分段有效计划量 - 审核累计合格量 - 已确认取消量
```

系统展示继续在原分段生产、建立新执行分段、调整订单承诺或不再补产的方案和交期影响。只有有权限用户确认后才执行；不得每次出现不良就自动复制补产计划。返工仍归属原数量，返工成功报为合格时必须引用原返工记录，避免重复统计处理量。

### 8.7 成品入库

- 可入库上限是审核累计合格量减累计有效成品入库量。
- 成品可分批入库；入库单审核后才增加成品库存并更新计划订单关联数量。
- 入库必须携带排程分段、计划明细、父计划、来源报工和销售订单关联，合并生产时按 `plan_order_item_links` 的确定性规则分摊。
- 入库后复用现有成品库存预留/补预留逻辑，使授权销售看到可发货数量。
- 重复生成或审核入库单不得重复增加库存；入库反审核前必须确认下游尚未发货、调拨或被不可逆消费。
- 报工合格但尚未审核入库的数量显示为待入库，不得显示为可发货。

### 8.8 消耗申报与清料

进入生产后，车间可按物料申报实际消耗、正常损耗、报废和在制结转。系统用 BOM 快照与合格/报废产出给出理论值，但实际值必须由责任人确认；不能仅用 `领用 - 退回` 静默当作正常消耗。

对每个物料计算：

```text
可退上限
= 累计审核领用
 - 累计确认消耗
 - 累计已审核良品退库
 - 累计已审核不良品退库
 - 累计审批损耗/报废
 - 累计在制结转
```

结果小于零是数据异常，必须阻断并调查，不能取零后继续。

### 8.9 余料退库

1. 退料入口从生产中直至待清料均可使用；已结案后必须先受控反结案，避免原 v1.1 的循环状态。
2. 页面自动带出累计领用、已消耗、历史退料、损耗、在制和可退上限；用户只输入本次实退数量与质量状态。
3. 良品退回原材料可用库；待检/不良品进入对应质量状态或不良库，后续选择报废、退供应商或返工。
4. 车间提交只创建待点收单据。仓库实物点收并审核后，库存和核销累计才变化。
5. 多次部分退料被完整支持；任何一行不得超过实时可退上限。
6. 退料反审核必须检查该批库存未被再次分配或出库；已被下游使用时禁止直接反审核，改走反向库存单据。

### 8.10 在制结转与结案

未完成但需要换车间、换批次或跨期的物料不能伪装为已消耗或已退库。必须建立在制结转，明确来源分段、目标分段/在制位置、物料和数量；目标确认接收后才从来源核销。

排程分段结案必须同时满足：

- 审核累计合格量和经批准的取消/差额处置覆盖有效计划量；
- 合格品已按业务决定入库，或有经批准的其他处置；
- 领退耗等式在精度容差内平衡；
- 超领、补料、质量、退料、采购和变更单无未决状态；
- 未领库存分配已释放；
- 语义审计和 Outbox 事件已随事务写入。

父计划是否关闭从其所有计划明细、执行分段和自制件子计划的状态派生；不能因为一个分段结案就关闭整张父计划。

## 十、仓库、采购与委外履约工作台

### 10.1 现状与目标边界

**现状**：V153 以后，仓库、采购、委外 hub 已增加同源任务工作台入口，读取统一履约需求、执行段和真实来源单据；采购申请→订货→收货已由 V154 接入生产供给回写。工作台仍没有独立拣货/双方交接状态、跨请求自动采购合并、主动低库存补货和完整委外执行清账。

**本期 V1 已实现边界**：统一需求/履约查询、仓库领料任务、采购需求池和真实单据跳转已落源码；采购同一已审申请内支持多选明细转单。所有“待领取/已领取/已收货”仍必须来自审核单据，不能由卡片按钮直接改状态。

**委外边界**：V158 已把 SUBCONTRACT 缺口接到委外申请、订单和回厂收货的精确 supply peg，并在整套齐备时原子转 READY；工作台提供真实单据投影/跳转，但刻意不提供无安全后端支撑的批量写。委外原料发出、委外在制消耗、回厂质量隔离、余料退回/清账和成本仍属于后续阶段；历史数量和责任边界未修复前不得宣称完整委外闭环。

### 10.2 统一需求、分配与履约来源

部门卡片不是新业务台账。仓库、采购、委外、生产和销售都从同一组逻辑事实投影：

| 逻辑事实 | 核心字段 | 权威归属 |
|---|---|---|
| 履约需求 | `sourceType/sourceId/sourceLineId/sourceVersion`、法人/组织、物料、基本单位需求量、需求时间、优先级、目标仓/车间 | 发起业务模块 |
| 库存/供给分配 | demand ID、supply ID、分配量、已履约量、已释放量、版本 | 统一分配服务/供给所属模块 |
| 履约执行 | 关联的备料、领料、采购、收货、委外发料/回厂等单据行及审核数量 | 单据所属模块 |
| 部门待办 | 需求、分配和执行事件形成的 CQRS 投影，含 SLA、逾期和异常 | 可重建读模型 |

来源至少区分生产 BOM 缺料、生产备料、库存安全/最小量补货、质量补料、经批准的人工需求和委外需求。每个数量始终带来源行和版本；页面不得复制一个可手工修改的待办数量。

通用履约数量满足：

```text
需求有效量 = 原需求量 - 已取消量
已履约量 = Σ审核有效执行单据分摊量 - Σ红冲量
未履约量 = max(0, 需求有效量 - 已履约量)
Σ来源分摊量 <= 对应供给/执行单据有效量
```

部分履约是正常状态，不能用一个已完成布尔值代替数量。改单、取消和红冲都只调整当前来源分摊，并重新计算共享供给，不能误伤其他部门需求。

### 10.3 部门工作台统一交互

每个部门页面采用同一信息架构：

1. 顶部 KPI 卡片显示待处理、今日到期、已逾期、部分履约、异常和完成数量；每张卡可点击并立即成为下方列表筛选条件。
2. 下方使用项目统一只读表格，服务端分页、排序和筛选；点击一行打开处理侧滑面板。
3. 处理面板使用项目布局 token 和对应编辑组件，展示来源、当前数量、历史分批、关联单据和允许动作。
4. 任务中心显示负责人、创建时间、SLA 截止、备料/到货/回厂截止、剩余量、逾期时长和阻断原因。
5. 任何卡片数字都能下钻到组成行，并显示投影水位；卡片与列表不得各算一套。
6. 操作调用权威模块 Facade；工作台读模型不直接更新库存、采购或委外状态。

紧急程度同时展示文本、图标和颜色。部门 hub 原有单据/报表入口继续保留，但新增“我的待办/需求池/异常”入口，不能用静态入口卡片冒充动态 KPI。

### 10.4 仓库备料、拣配与交接工作台

顶部卡片至少包括：待备料、备料中、待交接/待领、部分交接/部分领、已领、退料待收、低库存/补货预警、逾期和异常。点击卡片过滤同一履约投影，不在仓库表另存手工状态。

#### 截止时间与优先级

```text
计划交接截止 = 计划开工时间 - 车间接料/转运提前量
拣配开始截止 = 计划交接截止 - 仓库备料提前量
```

提前量按仓库、物料类别、批次/称量要求、目标车间和班次配置。无可靠计划开工时间时显示未定 SLA，并要求调度补齐，不能默认当作不紧急。

任务排序依次考虑已逾期、特急审批、交接截止、物料齐套程度、等待时长和仓库波次。人工改优先级必须填写原因和审计；不得因列表排序改变库存分配所有权。

#### 低库存与补货预警

预警以“仓库 + 物料 + 颜色 + 基本单位”为唯一计算粒度；空颜色使用统一规范值比较，禁止把不同仓库、颜色或单位直接相加。计算从合格账面量开始，冻结和有效分配只扣减一次：

```text
当前可支配量
= 合格账面基本量
 - 质量冻结基本量
 - 盘点/业务冻结基本量
 - 统一分配账有效未履约基本量

补货库存位置
= 当前可支配量
 + 补货周期内已审核、未分配且预计合格可用的采购供给基本量

再订货点 = 补货提前期内预测需求基本量 + 安全库存基本量
建议补货量 = 按 MOQ/包装向上取整(max(0, 目标库存 - 补货库存位置))
```

`当前可支配量` 不得基于已经扣过分配的统一可用量再减一次分配。预测需求、补货提前期、安全库存、目标库存、MOQ 和包装换算必须有来源、生效时间和版本；数据缺失时显示“不可计算”，不能用零替代。

当补货库存位置小于等于再订货点时进入低库存；只有库存位置达到“再订货点 + 滞回量”并持续超过配置的稳定时窗后才恢复正常，避免收发料波动造成反复开关预警。状态可表达正常、低库存、已建议补货、补货中和异常。

通知只在预警状态发生变化时发送，使用“仓库 + 物料 + 颜色 + 预警状态版本”去重；同一状态下的重复净算只更新数量和时间，不重复轰炸仓库/采购。逾期未处理按 SLA 升级通知。

低库存产生独立的 `INVENTORY_REPLENISHMENT` 库存补货需求，不冒充生产缺料，也不直接生成采购单。进入采购需求池后可按严格合并键与其他需求合并采购，但必须保留独立来源分摊；MOQ/包装超采仍归公共补货供给。

#### 状态与动作

```text
待备料 → 备料中 → 待交接/待领 → 部分交接 → 已领
   └────────────→ 异常 ← 拣货短缺/质量冻结/盘点冻结/批次不符
生产退料申请 → 退料待收 → 已收良品/已收隔离品
```

- **待备料**：派工和有效物料分配已形成，尚未开始拣货。
- **备料中**：仓库创建拣货波次，按库位、批次和策略执行。
- **待交接/待领**：已拣到暂存区，等待仓库与车间交接确认。
- **部分交接**：部分数量已由双方确认，其余仍在仓库或异常处理中。
- **已领**：本次需求有效量全部交接；后续补料形成新的来源履约行。
- **退料待收**：车间已申请但仓库尚未验收，不增加任何可用库存。

#### 批量拣配与库存语义

1. 可按法人、仓库、目标车间/交接点、交接时间窗、货品、颜色/规格、单位、质量/批次要求和拣货策略组成拣货波次。
2. 波次可以合并实际拣货动作，但每个来源需求、分配量、已拣量和已交接量必须保留；不能把多计划数量覆盖成一行后失去追溯。
3. 库位和批次按物料策略执行 FIFO 或 FEFO；人工跳批次需权限、原因和质量/效期校验。
4. 盘点冻结、质量冻结、锁定库位和不合格批次不可拣。拣货时发现短缺，记录实拣量和短缺原因，进入异常并触发重新分配/补货，不得把系统数直接改成实物数。
5. 从存储库位移到仓库暂存区只是内部移库/拣货状态，仍属仓库保管，不等于生产消耗，也不把物料分配记为已领。
6. 仓库与车间按货品、批次、数量双向交接；双方确认后，审核领料单并把数量从仓库库存转入生产在制/车间占用。部分交接只转部分数量。
7. 交接差异记录短缺、多发、错料、破损和拒收，回到异常处理；不能用备注代替数量调整单据。

#### 退料验收

车间提交退料只形成待收任务。仓库点数、复核批次和质量后：良品审核入可用库；待检/不良品进入隔离库或质量状态。验收数量与申请不符时记录双方确认差异。仓库审核前，不增加账面可用量、不释放其他需求短缺，也不让待料计划转可派工。

仓库撤销拣货只恢复内部库位状态；已双方交接的数量必须走领料反审核或退料，不能仅把卡片拖回待备料。

### 10.5 采购需求池与采购履约

需求池顶部卡片至少包括生产缺料、库存补货、质量补料、待合并、待审批、待下单、在途、到货待检、部分可用、逾期和异常。每条需求显示来源、净需求、需求日、已分配供给、未履约量和预计可用日。

采购状态投影为：

```text
待净算 → 待合并 → 采购草稿/待审批 → 已审批待下单 → 已下单
→ 在途 → 部分到货/到货待检 → 部分可用 → 已履约
任一阶段可进入异常；取消/改单按来源分摊处理
```

多选需求生成采购草稿时必须自动拆分不兼容组合：

- 单据头合并键至少包含法人、采购组织、供应商、币种、税制/税率口径、结算/贸易条件、收货仓和审批路线；
- 明细合并键在单据头键基础上增加物料、颜色/规格、基本单位及换算、质量标准、需求日期桶、合同/价格来源和包装要求；
- 任一键不同就分单或分行，不允许用户强行合并后丢失质量、仓库或税务语义；
- 每条采购行必须有来源需求分摊，记录需求 ID、分配量、需求日和版本；采购行总分摊不超订货有效量。

MOQ 和包装取整：

```text
建议订货量 = 按包装倍数向上取整(max(采购净需求, MOQ))
超采量 = 建议订货量 - Σ具体需求分摊量
```

超采量进入公共库存补货/未分配供给，不得虚假挂给生产需求造成“已齐套”。采购员可调整建议，但系统展示 MOQ、包装、价格和交期影响并留审计。

分批到货按采购行的来源分摊和需求优先级分配，累计不超各自剩余量。到货只进入待检；质检合格并审核入库后才成为可分配库存，随后生产模块重新竞争/原子分配完整套料。发运、在途或到货未检均不能直接解锁待料计划。

共享采购改单/取消只释放受影响来源，重新净算其他需求。已下单减量、换供应商、改收货仓或需求日需要采购审批和影响清单；已收货部分必须先按收货/退货规则处理。

### 10.6 委外需求池与履约闭环

委外是 make-or-buy 决策的一种结果。对同一有效需求必须满足：

```text
自产有效量 + 委外有效量 <= 订单/计划有效需求量
```

从自产改委外前先检查自产排程、原料分配、领料、报工和入库；从委外改自产前检查委外订货、发料、在制和回厂。已执行部分通过变更/红冲处理，不能让同一数量同时占用自产和委外。

委外需求池目标状态：

```text
待 make-or-buy 评估 → 待审批 → 待委外下单 → 待发料
→ 部分发料/委外在制 → 部分回厂/回厂待检 → 部分入库
→ 待余料/损耗核销 → 已结案
任一阶段可进入异常、暂停或取消
```

目标闭环复用现有委外申请、订货、材料发出、回厂进仓、材料退回、损耗和成品退货单据：

1. 委外需求保留来源订单/计划、产品、数量、BOM/工艺快照、供应商、交期和质量要求。
2. 委外原料通过统一库存分配和仓库交接发出；交给委外商后转为委外在制/受托方保管，不立即视为生产消耗。
3. 支持分批发料、补料、委外进度和预计回厂日；供应商处数量必须可按物料对账。
4. 回厂先进入待检，质检合格后审核成品入库；不合格进入返工、拒收/退货或报废处置。只有合格入库参与销售可发货。
5. 余料由委外商分批退回，仓库验收后良品/隔离品分别入账；损耗必须审批并关联原因。
6. 委外结案满足：发出量等于合格成品对应消耗、良/不良退料、审批损耗和供应商在制之和，且成品回厂/质量/退货无未决单据。

当前委外发料历史数量和质量节点仍是上线阻断。本期只做来源决策与只读投影；完成数据修复、责任人确认和 E2E 后，后续阶段才启用上述统一写闭环。

### 10.7 部门权限、通知、审计与反向操作

- 仓库权限分为查看任务、开始/撤销拣货、确认交接、审核领料、验收退料和处理异常，并限制仓库/库位范围。
- 采购权限分为查看需求、净算/合并、编辑草稿、审核、下单、改配供给和处理异常；需求发起人不能越权审批采购单。
- 委外权限分为 make-or-buy 决策、需求审批、下单、发料、进度、回厂、质量、余料/损耗和结案，并沿用委外商数据范围。
- 权限按权限点、部门模板、个人覆盖和对象范围配置，不在代码写死仓管员、采购员或委外员角色。

任务创建、临近 SLA、逾期、拣货短缺、部分交接、采购延期、质检不合格、委外回厂延期、共享供给改配和异常关闭均写 Outbox。通知接收人由任务责任和组织范围解析，重复事件去重；关键逾期需升级给获授权主管。

语义审计必须记录来源需求、分配前后量、履约单据、批次/库位、双方交接人、合并/拆分键、MOQ 超采、供给改配、质检结论、委外损耗和撤销原因。部门页面只提交动作，状态和数量由审核单据/统一分配账派生。

撤销遵循下游优先：未拣可撤需求；已拣未交接可撤波次；已交接走领料反审核/退料；采购已共享不能整单取消；到货已被分配/领用先处理下游；委外已发料必须完成退料、在制或损耗处置。任何页面不得通过改卡片状态绕过这些规则。

## 十一、变更、取消、反审核与红冲矩阵

所有正式业务记录保留历史。未确认预览可删除；已确认数据只能变更、取消、反审核或红冲。每次反向操作与正向操作使用同一领域服务和锁顺序，并产生新的业务事件。

| 场景 | 前置校验 | 同步主事务动作 | 提交后旁路 |
|---|---|---|---|
| 放弃预览 | 无正式单据 | 删除/过期草稿，不释放库存，因为预览从未占用 | 可记普通操作日志，不发业务通知 |
| 取消待料分段 | 无已领料/报工 | 取消分段、释放需求挂接；共享采购只释放本需求分配 | 采购重算、销售风险投影更新 |
| 取消可派工分段 | 无已领料/报工/下游消费 | 取消分段、释放物理分配和需求挂接、回退订单有效计划量 | 通知调度/销售，重算其他需求 |
| 撤回派工 | 无审核领料和审核报工，未被冻结或有更高权限 | 撤销班组/人员和备料申请，回到可派工；保留物料分配 | 通知车间和仓库 |
| 计划减量 | 校验已合格、已入库、已发货和已领用下限 | 新版本减少未执行量，释放对应未领分配和需求挂接；已领部分进入清料 | 采购、产能和销售投影重算 |
| 计划增量 | 订单仍有剩余量，BOM/库存/产能有效 | 新增分段或新版本；新增部分重新净算和分配 | 采购建议和交期风险更新 |
| 改车间/班组/日期 | 冻结期、路线兼容、已领料位置 | 新建变更版本，调整日程；必要时创建物料/在制调拨，不能直接改历史 | 通知新旧车间并更新产能投影 |
| 改替代料 | 旧料未领或可合法退回，新替代审批有效 | 释放旧未领分配、创建新 BOM 快照版本和新分配 | 通知仓库/质量，更新成本投影 |
| 领料单驳回 | 尚未审核出库 | 单据驳回，不改变库存或分配消耗 | 通知申请人 |
| 领料反审核 | 物料未被确认消耗、退料、转移或下游使用 | 反向库存流水，恢复分配未领量 | 更新备料和执行投影 |
| 报工驳回 | 报工尚未审核 | 退回修改，不改变正式进度 | 通知报工人 |
| 报工红冲 | 对应合格量未被不可逆成品入库/发货消费，或先完成下游红冲 | 反向合格/返工/报废和工时累计，恢复分段状态 | 销售/看板投影重放，发更正通知 |
| 成品入库反审核（目标态） | 对应库存未发货、调拨或被其他单据消费，且原正向分摊可逐笔识别 | 按原入库分摊台账反向库存流水、计划明细和订单关联累计 | 可发货量和销售进度回退 |
| 退料驳回 | 尚未仓库审核 | 退回修改，不增加库存、不改变核销 | 通知车间 |
| 退料反审核 | 退回库存未再次分配/出库 | 反向库存流水和清料累计；否则禁止并要求反向单据 | 更新清料状态 |
| 采购提前/延期 | 采购模块状态有效 | 更新供给预计日/有效未结量，重算需求挂接；不直接改计划为可派工 | 通知调度和授权销售 |
| 采购收货反审核 | 该供给尚未被生产分配、领用 | 反向收货和供给可用量；若已被使用则禁止直接反审核 | 待料和交期投影重算 |
| 销售订单改量 | 沿用销售订单变更审批 | 未执行部分自动生成影响预览；生产主管确认后调整，已执行量不得被覆盖 | 通知生产、采购、仓库并更新投影 |
| 销售订单取消 | 检查计划、领料、报工、入库和发货阶段 | 未开始部分取消并释放；已领部分清料；已生产成品进入客户专用隔离、通用库存或其他处置需业务审批 | 各部门收到分阶段处理待办 |
| 急单插单/重排 | 具备优先级权限，给出影响清单 | 只调整获确认且未冻结/获特批的日程版本；不抢占已领物料 | 通知受影响负责人和销售 |
| 自制件子计划取消 | 校验 `subplan_links`、下层计划和执行状态 | 通过既有自制件子计划服务取消/红冲，不把排程分段当子计划删除 | 父计划进度和 MRP 重新投影 |
| 已结案反结案 | 下游未不可逆消费且有专门权限 | 新建反结案版本，恢复待清料或生产中；不原地篡改历史 | 发送高风险审计和通知 |
| 撤销仓库拣货波次 | 尚未双方交接 | 退回暂存库位/解除波次，不改变领用和消耗；保留来源分配 | 更新备料 SLA 和任务 |
| 撤销部分交接 | 交接库存未被消耗/转移 | 对指定来源和批次走领料反审核；其余已交接量不动 | 生产在制和仓库任务回退 |
| 采购合并单改量/取消 | 校验每个来源分摊、已收货和共享需求 | 只调整可撤来源；MOQ 超采回公共补货，不能挪成虚假来源 | 需求池和预计齐套日重算 |
| make-or-buy 改道 | 校验自产/委外所有下游 | 先释放或反向处理原路径，再对剩余量建立新路径；有效量不得重复 | 生产、采购/委外、销售投影更新 |
| 委外发料/回厂反审核 | 校验供应商在制、回厂质检、入库和下游消费 | 按材料发出→在制→回厂→质检→入库的反向顺序逐级处理 | 委外对账和订单进度回退 |

V157 已为 V1 执行段增加不可变 `execution_segment_sales_allocations`，并让报工/成品入库明细指向精确分摊；段分摊合计必须等于段计划量，同一计划销售 link 被各段使用的累计不得超过其容量。销售来源执行段缺少精确分摊、分摊与段/订单行不一致、冻结 link 被删除或缩量时一律 fail-closed。历史 V0 入库仍沿用明确 `upstream_item_id` 和单一有效销售 link 的兼容边界；历史来源迁移完成前不猜测多来源分摊。

共享采购、合并计划和合并入库的反向操作只回退当前来源分配量，不能误伤其他订单/分段。无法自动处理时进入异常工作台，由系统给出差异和待办，不允许静默忽略。

## 十二、Outbox、通知与 CQRS 读模型

### 12.1 架构规则

1. 生产主事务完成权威写入，并在同一数据库事务中插入业务事件 Outbox；Outbox 插入失败时主事务失败，避免业务成功但永久无事件。
2. 消费端按至少一次语义处理，用 `eventId + consumer` 唯一键去重；不得假设消息只到一次。
3. 通知、销售进度、生产看板、采购风险和审计展示是不同消费者，互不直接写彼此数据库表。
4. 读模型只读，可从权威表和事件重建；写接口不得读取滞后投影作为数量校验依据。
5. V151 生产 V1 事件已走持久化 Outbox；旧链仍存在的 `afterCommit + REQUIRES_NEW` 只作未迁移事件过渡。每个事件切换时必须对账并删除旧旁路，禁止长期双发。

### 12.2 关键业务事件

| 事件 | 主要数据 | 典型消费者 |
|---|---|---|
| `ProductionSchedulingConfirmed` | 订单、父计划、计划明细、执行分段、版本、预计日期 | 销售进度、生产看板、待办 |
| `MaterialAllocationChanged` | 分段、BOM 行、分配/释放/领用数量和原因 | 物料齐套投影、仓库备料 |
| `MaterialShortageChanged` | 缺口、需求日、供给挂接、预计齐套日 | 采购待办、生产/销售风险 |
| `ProductionDispatched` | 车间、班组、负责人、日期、派工版本 | 我的任务、仓库备料 |
| `MaterialIssueApproved` | 领料单、分段、物料和数量 | 执行详情、成本旁路 |
| `ProductionReportApproved` | 合格、返工、报废、工时、质量原因 | 销售进度、看板、质量待办 |
| `ProductionReportReversed` | 原报工和反向数量 | 投影回退、更正通知 |
| `FinishedGoodsInboundApproved` | 成品、数量、订单分配、仓库 | 销售可发货、库存投影 |
| `MaterialReturnApproved` | 良品/不良品、数量、仓库和处置 | 清料、采购/质量旁路 |
| `ProductionScheduleChanged` | 数量、车间、日期、优先级前后值 | 受影响人员、产能/销售投影 |
| `ProductionSegmentClosed` | 结案数量、清料结果、时间 | 父计划汇总、销售节点通知 |
| `WarehouseFulfillmentChanged` | 拣货、短缺、交接、退料验收、SLA | 仓库任务、生产物料状态 |
| `ProcurementSupplyChanged` | 需求分摊、下单、在途、到货、质检和可用量 | 采购池、待料和预计日期 |
| `SubcontractFulfillmentChanged` | make-or-buy、发料、在制、回厂、质量、余料和损耗 | 委外工作台、生产/销售投影 |

取消、反审核和红冲发布独立反向事件，并引用原事件/原单据，不通过修改旧事件表示。

### 12.3 通知规则

- 排产确认：通知获授权销售、生产调度、对应车间；仓库只有在有备料任务时接收待办。
- 缺料或预计齐套日变化：通知采购责任人、生产调度；只有影响客户承诺时通知销售，并使用公开延期原因。
- 派工：通知班组/负责人；撤回或改派同时通知新旧负责人。
- 首次审核报工、部分成品入库、全部可发货、延期和取消：通知对应销售及获授权主管。
- 超领/补料、退料、质量异常：发给审批人和对应仓库/质量待办。
- 通知内容只包含接收人有权查看的数据；点击后仍进行对象级鉴权。

### 12.4 延迟、重试与观测

v2.0 不写死报工审核后 10 秒内销售可见。上线前应通过压测确定投影 SLO，并在配置/运行手册中记录，例如 P95 延迟目标；需求验收关注：

- Outbox 与主事务同提交，无事件丢失；
- 消费失败指数退避重试，超过阈值进入失败队列并告警；
- 管理员可按事件查看待处理、重试、失败和投影水位；
- 页面显示最后更新时间，允许手动刷新；
- 重放不会重复通知或重复累计数量；
- 达不到 SLO 时显示数据延迟，不伪装实时。

### 12.5 销售与看板投影

销售进度以订单行作为粒度，保存可重建的阶段数量、预计日期、风险标签和最新事件水位。生产看板以组织、车间、日期和分段为粒度。投影可以存缓存/读库，但不得新增人工维护的销售进度真相列。

延期原因分为内部原因和销售可见原因；内部责任、供应商报价、成本和员工绩效不得投影到销售权限范围。投影重建完成前以水位标识不完整，不能将缺失行解释为零进度。

## 十三、语义审计、安全与附件

### 13.1 三层审计

1. **业务语义记录**：关键状态/数量变更在主事务内记录，保证成功业务一定有可解释事件；这是业务追溯的一部分。
2. **HTTP 审计**：沿用现有请求审计记录操作者、路径、结果、IP、耗时和 correlation ID；失败不回滚业务，但必须告警。
3. **关键表审计/约束**：对库存、分配、计划关联、报工和入库等关键表保留必要前后值或触发器证据，防止绕过服务写入。

不能只记录请求体全文；请求体可能包含凭证、个人信息和附件地址。审计使用结构化白名单字段和脱敏策略。

### 13.2 语义动作编码

至少覆盖：

| 动作编码 | 说明 |
|---|---|
| `PRODUCTION_PROPOSAL_CONFIRMED` | 排程预览确认 |
| `PRODUCTION_PRIORITY_CHANGED` | 急单/优先级变化 |
| `PRODUCTION_SEGMENT_CHANGED` | 数量、车间、日期、班组或负责人变化 |
| `PRODUCTION_SEGMENT_CANCELLED` | 执行分段取消 |
| `MATERIAL_ALLOCATED` | 原料物理分配成功 |
| `MATERIAL_ALLOCATION_RELEASED` | 未领分配释放 |
| `MATERIAL_SUPPLY_PEG_CHANGED` | 采购供给挂接变化 |
| `PRODUCTION_DISPATCHED` | 派工 |
| `MATERIAL_ISSUE_APPROVED` | 领料审核 |
| `MATERIAL_EXTRA_APPROVED` | 超领/补料审批 |
| `PRODUCTION_REPORT_APPROVED` | 报工审核 |
| `PRODUCTION_REPORT_REVERSED` | 报工红冲 |
| `FINISHED_INBOUND_APPROVED` | 成品入库审核 |
| `MATERIAL_RETURN_APPROVED` | 退料审核 |
| `MATERIAL_RECONCILED` | 清料核销 |
| `PRODUCTION_SEGMENT_CLOSED` | 执行分段结案 |
| `PRODUCTION_OPERATION_REVERSED` | 其他反审核/红冲，必须引用原动作 |

### 13.3 审计字段与查询

每条关键语义记录至少包含：

- action、结果、时间、actor user/employee/department；
- 父计划、计划明细、自制件子计划或执行分段 ID；
- 销售订单/订单行、库存/采购/报工/入库/退料单号；
- 货品、颜色、仓库、单位；
- 关键数量前值、变化量、后值；
- 原因、审批意见、来源动作；
- correlation ID、idempotency key、业务版本和原事件 ID；
- 客户端/IP 等现有 HTTP 元数据。

系统管理审计页现已支持从列表打开桌面侧滑/移动底部详情，查看脱敏后的请求元数据和格式化 before/after。按业务单号、计划、物料的完整语义检索、数量 delta 展示和字段级权限覆盖率仍须继续补齐并验收。

### 13.4 附件安全

- 报工附件数量上限通过配置管理，可提供 9 个默认值，但不在业务代码写死。
- 明确允许的图片/文档 MIME 和扩展名，校验实际文件签名；禁止可执行文件和双扩展名绕过。
- 配置单文件、单次请求和累计大小上限，使用流式上传，避免把大文件读入内存。
- 文件先进入隔离区，完成病毒/恶意内容扫描后才能被普通用户下载或用于审批证据。
- 对象存储使用不可猜测键、校验和和短期签名 URL；数据库保存元数据和对象键，不保存公开永久 URL。
- 下载时再次鉴权排程分段和订单范围；记录上传、替换、下载和删除审计。
- 规定保留期和依法删除策略。红冲报工的证据不物理删除，按审计保留策略冻结。

### 13.5 接口与数据安全

- 所有列表服务端分页并限制 page size；批量确认限制订单/物料行数，防止超大事务。
- 写请求校验 CSRF/认证、对象权限、版本、幂等键和内容长度；错误消息不暴露 SQL、路径或敏感字段。
- 跨模块 DTO 只传 ID 和不可变结果，禁止暴露 Repository/Entity 让外部模块直接修改。
- 销售端 API 单独裁剪字段；不能先返回全量成本/物料数据再依赖前端隐藏。

### 14.1 模块边界

- 销售模块拥有订单状态、有效量和对象权限，通过 Port 暴露可排需求与进度查询契约。
- 生产模块拥有父计划、计划明细、自制件子计划、排程分段、BOM 快照、派工和报工。
- 库存模块拥有账面量、统一分配、库存单据和流水；生产只能调用库存 Facade，不能直接更新余额。
- 采购模块拥有申请、订单、收货和供应商；生产只提交需求草稿/挂接并读取不可变供给结果。
- 通知和投影消费者只处理事件，不回写生产主状态。
- 跨模块数据库字段使用逻辑 ID 和索引，是否建 FK 遵循现有契约；不得为了本需求引入新的模块循环依赖。
- 增加架构测试：生产 Controller 不依赖 Repository，跨模块只能依赖 Facade/Port，CQRS 查询服务不得调用写服务。

## 十五、数据更新、迁移与上线门槛

### 15.1 平台数据更新原则

未来平台更新全量数据时禁止直接覆盖生产表。统一流程：

1. 导入隔离 staging，记录来源批次、文件哈希、行号和原始主键。
2. 校验组织、客户、货品、颜色、仓库、单位换算、BOM 版本和单据映射。
3. 对开放订单、计划、采购、库存和累计量生成逐笔转换结果；异常进入隔离清单，不以零或默认值吞掉。
4. 在生产数据副本执行 dry-run，输出新增、更新、拒绝、数量差异和孤儿关联统计。
5. 经业务签字后冻结旧系统写入，记录切点水位，再执行最终增量和向前迁移。
6. 按仓货色、订单行、计划明细和采购供给做期初/期末对账。
7. 重建销售进度和生产看板投影，并校验事件水位。
8. 完成备份恢复演练；失败时按批次回滚/停用新功能，不修改已发布 Flyway。

历史异常必须区分“已关闭历史只读”“开放业务待修复”和“无法识别隔离”三类。未经确认的历史超量不得自动生成库存、采购、分配或销售进度。

### 15.2 迁移约束

- 迁移版本从实施时仓库真实最高 Flyway 版本顺延，本文不再写基于 V90-V100 扩展。
- 已发布迁移只读；视图、约束和字段修复使用新迁移。
- 先修复 V90 全局/仓级预留重复 JOIN，再开发依赖统一可用量的排产确认。
- 统一分配账切换要有旧接口兼容期、双读对账，而不是长期双写；切换完成后删除旧写路径。
- 大表迁移评估锁表时间、索引并发创建、回填批次和回滚方案。
- 使用真实 PostgreSQL/Testcontainers 验证 NULL 颜色、NULL 仓、约束、锁顺序和视图，不以 H2 代替关键测试。

### 15.3 上线数据门槛

| 门槛 | 通过标准 |
|---|---|
| BOM | 所有开放生产需求和关键产品版本完整率 100%，无循环、无失效版本、单位全部可换算 |
| 库存 | 余额与审核流水按仓货色对平；旧视图重复 JOIN 修复并通过五类回归 |
| 占用 | 销售/生产进入统一分配口径；有效量非负且消耗加释放不超原量 |
| 订单/计划 | 开放业务中计划关联不超订单，执行分段不超计划明细，无孤儿关联 |
| 报工/入库 | 开放业务中合格不超计划、入库不超合格；历史异常已隔离并有处置人 |
| 领退耗 | 抽样和全量自动核销通过；成本过账与红冲对称 |
| 权限 | 权限矩阵、跨负责人对象范围和敏感字段测试全部通过 |
| 审计 | 关键动作覆盖率 100%，可从订单/计划/物料追到前后数量和原单 |
| Outbox/CQRS | 无不可解释积压，重试/去重/重放和投影重建演练通过 |
| 可靠性 | E2E、并发抢料、重复请求、迁移回放、备份恢复和故障演练通过 |

任一门槛未通过时，UI 只允许只读预览或通过功能开关关闭相关写操作。

## 十六、验收标准与场景

### 16.1 功能与 UI 验收

1. 进入订单排产页无需展开即可看到所有产品的 BOM 物料和不可计算原因；不存在物料折叠按钮。
2. 页面只有“一键生成子计划”入口，不再要求先点独立车间选择；车间在排程分段编辑区调整。
3. 物料只读表使用 `MasterDataTableView`；排程分段编辑使用 `UtenEditableGrid` 或紧凑端等价编辑表单。
4. 预览不产生正式计划、库存分配、采购、领料和进度；确认失败不留下部分数据。
5. 修改数量、替代料、车间或日期会重算依赖数据，并显示与原预览的差异。
6. 紧凑、中等、展开断点、深浅色和大字体通过；没有写死面板宽度、动画时长和颜色。
7. 风险状态同时有文字、图标和颜色；键盘、读屏、触控尺寸和焦点顺序通过。

### 16.2 数据与事务验收

1. 订单有效计划关联不超审核有效量，执行分段合计不超计划明细，数据库和服务双重校验。
2. 可执行分段的所有 BOM 行均有完整有效物理分配；待料分段不伪装为可派工。
3. 统一分配的原量、领用/消耗和释放满足不变量；销售与生产对可用量计算一致。
4. 同一采购供给的有效分配总量不超过未结量；共享采购取消一个需求不影响其他需求。
5. 审核累计合格不超计划，成品入库不超审核合格，红冲后全部按相反方向恢复。
6. 清料等式按每个物料成立；多次领料、退料、补料和在制结转后仍可对账。
7. 所有数量使用基本单位和十进制定点，边界精度、换算尾差和空颜色/空仓均有测试。
8. 重复请求不重复建单或累计；陈旧预览返回差异，不覆盖新数据。

### 16.3 通知、审计与安全验收

1. 主事务成功必有 Outbox 事件，回滚时无孤立事件；重复消费不重复累计或通知。
2. 消费失败可观测、可重试、可重放；页面显示投影水位，不承诺未验证的 10 秒实时性。
3. 每个关键动作可从系统管理审计页按订单、计划、分段、物料、操作者检索，并看到前值、变化量、后值和原因。
4. 销售只能查看获授权订单的公开进度，不能通过 API 获取成本、物料价格、内部质量责任和员工绩效。
5. 附件类型、大小、签名、病毒扫描、对象权限和保留策略通过；恶意文件不可下载。

### 16.4 性能与稳定性验收

以接近生产的 PostgreSQL 数据进行基准，至少覆盖 100 个订单、每单多产品、累计 10,000 条 BOM 行：

- 待排产列表 50 行分页查询 P95 不高于 2 秒；
- 单订单 1,000 条 BOM 行首次可用内容 P95 不高于 3 秒；
- 100 订单/10,000 BOM 行批量预览 P95 不高于 10 秒，并可取消；
- 20 订单确认组在无锁竞争时 P95 不高于 5 秒；有竞争时返回明确冲突，不无限等待；
- 查询无按行 N+1，批量接口和索引计划通过评审；
- 进程在 Outbox 积压、消费者重启和网络重试后可恢复且不重复数据。

若真实环境基线证明目标需调整，必须在上线评审记录新 SLO、容量和降级方案，不能直接删除性能验收。

| S11 | 预览后库存/BOM/订单改量 | 旧确认整体拒绝并返回差异，重新预览后才能提交 |
| S12 | 双击、超时重试、消息重复 | 计划、分段、分配、采购、库存和通知都不重复 |
| S13 | 多待料需求共享一笔采购 | 供给不超分；取消一个需求只释放对应挂接 |
| S14 | 采购部分到货、提前、延期、反审核 | 每次重算齐套和预计日；已被领用的收货不能直接反审核 |
| S15 | 产能缺数据/超负荷/冻结期插单 | 缺数据不报假日期；超负荷提示；冻结调整需特批和影响清单 |
| S16 | 分批报工、驳回、红冲 | 仅审核记录累计；红冲对称恢复；合格不超计划 |
| S17 | 合格、返工、报废同时存在 | 处理量等式成立；返工不提前计合格；报废不自动重复补产 |
| S18 | 分批领料、超领、补料 | 普通领料不超快照额度；审批不扣库存，仓库审核才扣 |
| S19 | 多次良品/不良品退料 | 每次不超实时可退上限，仓库点收后才入对应库存状态 |
| S20 | 消耗、损耗、退料、在制混合 | 领退耗等式成立后才结案，不能用复选框跳过差异 |
| S21 | 合并计划成品分批入库 | 先按计划明细容量，再按订单关联容量分配；超容量整单回滚 |
| S22 | 无销售关联的自制件子计划入库 | 正确回写计划明细，不伪造销售订单进度/预留 |
| S23 | 成品入库后尝试报工/入库反审核 | 有下游消费时阻断；按正确反向顺序恢复 |

| S25 | 销售本人、主管、无权人员访问进度 | 对象范围正确，敏感字段在 API 层裁剪 |

| S29 | 仓库分批拣货、双方部分交接、退料待验收 | 拣货不记消耗；仅交接量转生产在制；退料验收前不增加可用量 |

## 十七、实施分阶段与本轮交付边界

### 17.1 已实现并有代码/迁移/自动化证据的核心

下列结论只表示当前工作区已有实现与定向自动化证据，不表示已完成生产数据切换、岗位验收或上线放行：

1. **排产交互与完整套料拆分**：排产详情默认直接展示全部产品 BOM，不提供折叠入口；独立“先选车间”按钮已移除。“一键生成子计划”先得到不写库的预览，再在桌面右侧约 840px、移动端底部全屏的编辑面板内调整数量、车间、班组、负责人和日期。确认时使用稳定幂等键及预览指纹，按所有必需物料的最小完整套数拆成 `READY` 与 `WAITING`；待料段不占住零散现货，避免多个待料任务重复认为自己已有料。
2. **统一履约账（V150）**：`production_planning_packages` 保存一次确认身份；`production_material_demands` 保存逐需求快照；生产原料物理占用复用 `stock_reservations`；采购/委外未来供给通过 `production_material_supply_pegs` 显式挂接。约束和稳定锁序阻止需求、现货与供给超分。V150 同时修复 V90 `v_stock_available` 的重复 JOIN 放大问题。
3. **可靠旁路（V151）**：`business_outbox` 与主业务事务同提交，使用唯一 `dedupe_key`、重试退避、送达/人工处理状态和审计触发器；通知失败不再靠一次性调用猜测成功。
4. **领料、退料与清料（V152）**：DRAW/WDRAW 仍是物理库存单据，新增 posting 只记录每次领料/良品退料对需求和占用的精确分摊；重复请求幂等，红冲沿原 posting 对称恢复。执行段完成前校验“领用 = 消耗 + 已验收退料 + 合法损耗/在制”的物料结清状态。
5. **可操作工作台与审计（V153 + 应用层）**：仓库、采购、委外工作台读取同一履约视图并链接到真实来源单据；仓库的待领取/部分领取/已领取来自 DRAW 审核累计，不允许页面直接改状态。采购可勾选同一张已审申请的多个明细转订单；跨申请自动合并尚未实现。系统管理审计页可打开脱敏后的 before/after 详情。
6. **采购供给回写（V154）**：缺料确认可形成采购申请；采购订单、分批收货与反向动作逐笔迁移 supply peg。只有目标仓实际收货后才进入物理库存；WAITING 仅在全套物料可原子占用时转 READY 并生成精确 DRAW，部分到货不会假开工。
7. **正式执行分段（V155）**：`production_execution_segments` 是计划明细的执行从属，不是新的父计划，也不写 `subplan_links`。段保存产品、数量、车间/班组/负责人、日期、BOM 指纹、版本和状态；V1 段禁止再走旧 MRP 派生写入口，避免双轨重复领料或采购。
8. **执行、报工与入库（V156）**：支持分配、派工、开工、取消/反向；日报编辑可从执行段入口带入身份并多次分批报工，累计不得超过段计划量；成品入库明细必须关联同一执行段，完成数量和物料结清同时满足才可结案。
9. **销售精确分摊（V157）**：确认包按稳定顺序把每个执行段精确分配到 `plan_order_item_links`/销售订单行，段分摊之和必须等于段计划量且不得突破 link 容量；报工和成品入库必须携带该分摊并受各自累计上限约束。销售订单详情已按订单行显示对应执行段的数量、状态、日期、已报工和已入库。冻结 link 删除/缩量由数据库与销售变更服务共同拦截，相关场景已纳入组合回归证据。
10. **委外供给回写（V158）**：物料主数据明确为 SUBCONTRACT 时，缺口自动生成委外申请草稿和逐需求 peg；申请→订单等量迁移，回厂审核按明细分配，分批累计且回调幂等。只有 WAITING 的全部物料可覆盖时才整体转 READY 并生成精确 reservation/DRAW；未开工反向可整套撤回分配。委外发料、在制消耗和余料清账不在此范围。
11. **完成态原子红冲（V159）**：已完成执行段不能直接红冲报工。必须先对关联成品入库执行显式 `REOPEN_COMPLETION`，一次事务内锁定全部段并由 `COMPLETED` 重开到 `IN_PROGRESS`；任一段或下游校验失败则单据、事件和状态全部回滚，之后才允许反向报工。
12. **待料临时库存覆盖（V160）**：采购/委外工作台按仓库、货品、颜色、需求日和稳定优先级，把扣除安全库存后的自由库存作为“临时覆盖”抵减供给建议；它不写 `stock_reservations`，库存减少时缺口会重新出现，正式转 READY 时仍重新锁定整套物料。
13. **生产物料台账防篡改（V161）**：`production_material_stock_events`/`stock_postings` 与 `production_material_settlement_events`/`settlement_postings` 均为 append-only；已接受事实禁止更新、删除或级联消失，纠错必须追加 ISSUE/GOOD_RETURN/SETTLEMENT 的对应反向事实。
14. **采购/委外来源与守恒（V162）**：生产 peg 一旦引用采购申请/订单或委外申请/订单行，通用 CRUD 不得替换、删除或改写物料身份和数量；需求身份、peg 生命周期、委外转换、回厂分摊、占用、DRAW 与执行段容量由延迟约束共同校验，合法专用反向可在同一事务原子完成。
15. **采购收货来源追溯（V163）**：每条有效采购收货分摊必须同时证明收货头/行、采购订单行、生产需求、reservation、DRAW 头/行与执行段在物料、颜色、仓库和数量上同源；收货已促成领料消费时禁止直接红冲。
16. **生产关联库存单据锁定（V164）**：是否关联生产以计划包单据、`plan_draw_links` 和执行段/销售分摊外键判定，不按单号前缀猜测。通用库存编辑、删除、替换明细被数据库与服务/UI 能力共同阻断；审核、分批出库、完成重开和专用反向保留受控通道。
17. **齐套 READY 通知（应用层）**：采购或委外收货只有真实完成 WAITING→READY 后才写 `PRODUCTION_SEGMENT_READY`；去重维度包含执行段和触发收货，接收人按 `SUB_PLAN`/`DEPT_PROD` 部门及有效子部门权限解析，不依赖已下线角色。

最终组合回归：后端 343 tests、0 failure/error、48 skipped（PG 默认跳过）；真实 PostgreSQL 16 classes / 44 tests、0 failure/error/skip，空库 146 个迁移到 V165；V148 已锁定已部署校验和，后续修复由 V165 承载；Flutter 157/157，`flutter analyze --no-pub` 无问题，Web Release 构建成功。上述自动化仍不替代历史数据、权限、实物、性能和运维门禁。

### 17.2 仍未完成的上线门禁

- **数据切换**：历史 V90 预留、旧 MRP 派生单据、开放订单/计划、BOM/单位、库存余额和领退耗尚未形成可重复迁移、异常隔离和零差异对账报告。
- **业务验证**：仓库、采购、生产、销售、委外尚未完成带实物交接的人工 UAT；真实权限对象范围、职责分离、批量全有或全无仍需验收。
- **性能运维**：尚未完成生产规模压测、长事务/死锁压力、Outbox 积压与重放、备份恢复、告警、回滚和灰度演练。
- **排程与主数据**：有限产能 APS、冻结期插单影响计算、替代料版本/换算/审批、完整 BOM 生效版本仍未完成。
- **质量与执行细节**：来料/制程质量隔离、照片、完整人员工时、不良原因、返工/补产、超领补料审批和成本口径未闭环。
- **仓库任务状态**：当前工作台依据 DRAW 归纳“待备料/待领取”；尚无“备料中→双方交接→生产在制”的独立拣货和交接状态机。
- **采购效率**：当前安全支持同一已审申请内多选转单；跨请求按供应商/币种/税率/MOQ 自动合并，以及主动低库存补货、阈值回滞和补货上限尚未实现。
- **委外执行**：V158 的申请/订单/回厂供给回写已通过定向复核，但委外发料自动挂接/扣减、委外在制消耗、质量回厂隔离、余料退回/损耗和逐笔清账仍是独立上线阻断。

因此当前结论仍是：**核心链路源码从“只读安全骨架”推进到“可执行且 fail-closed 的 V1”，但生产发布保持 NO-GO**。

- `server/src/main/java/com/uten/imp/features/production/`：计划、排程、MRP 和报工服务；
