## 一、定位与合并动机

品质部对采购/委外收货的 IQC 结论，对仓库来说是同一批实物的不同处置去向：合格部分要入库、
不合格部分要退回。拆成两个页面后，仓库需要在两处核对同一张收货单，且旧列表页没有显式
「入库」入口（必须点进详情才能确认），容易找不到办理动作。

本页按**收货单**聚合全部检查相关事实，一个状态机走完：

- **等待检查结果**（蓝）：已送检、品质部尚未出结果（原预计到货任务中心的「已送检 · 待品质
  检验」步骤移交到此）；
- **全部合格 · 待入库**（绿）：检查全部通过，仍有品质放行待入库切片；
- **部分合格 · 部分待入库**（琥珀）：部分明细合格、部分不合格或仍在检，有待入库量或待退回；
- **全部不合格 · 需退回**（红）：全部明细不合格，实物退回凭证未登记；
- **已完结**（灰）：入库与退回办理完毕，仅历史可查。

状态推导在服务端单点完成（`WarehouseQualityResultService.STATUS_CASE`，列表 / 计数 / 状态
分组 / 详情共用同一表达式），列表行整行按状态填充颜色，且状态列始终带文字——颜色不是唯一
表达。分类层级（2026-09-01 全平台统一）：**来源类型（大类）+ 关键字搜索在上**，
**作业状态（小类）在下**；进页面两行均不预选（数据不过滤），选中来源后状态行才解锁。
徽章统一「未完结」口径（2026-09-01 定稿）；2026-09-04 修复：小类（状态）徽章进页面
即拉全来源计数、切换来源即重拉（此前被列表加载门控挡住，要点击小类才显示）：大类（来源）徽章 = 该来源未完结任务数，
小类（状态）徽章挂全部非已完结分段（等待结果保留数量供预判工作量；全部/已完结不挂），
卡片/工作台角标同口径。

## 三、批量入库的事务边界

- `POST /api/warehouse/iqc-stock-ins/batch-confirm`：1–20 张收货单、1–300 条明细；
- 整批同一事务：先按（类型, 收货单号）稳定顺序规范化并校验全部集合——重复幂等键、重复
  收货单、数量/库位/期望余量任一不合法直接整批拒绝；执行阶段任一行版本、状态、仓库或数量
  变化即抛冲突**整批回滚**，不允许客户端循环单张接口伪装批量成功；
- 每张收货单独立幂等键（按 用户+键 去重重放）；已完成的键安全重放并计入结果，不重复写库存；
- 单张 `confirm` 与批量 `batchConfirm` 复用同一 `confirmOne` 内核：锁序、库存维度锁定、
  金额/重量切片分摊、`warehouse_stocked_base_qty` 精确 CAS、分析归属与生产供给推进完全一致；
- `expectedAllocations` 只是确认前建议，前端按本次输入量依序截取，不保存第二套分配事实；
  `actualAllocations` 来自入库后追加式 reservation / exact-peg / entitlement / 正式需求账本重建，
  单张重放与批量结果必须返回同一真实去向。四类 allocation 数量之和必须等于对应入库切片数量；
- 生产联动按「收货单×批」执行一轮（2026-09-02 起，原为逐条明细触发）：明细全部落账后
  先推进正式履约（领取/预留/领料单按累计入库量一次推进，每「收货单×计划包×批」一张
  领料单），再对受影响物料分析整批去重刷新一轮——最终数据与逐条推进完全一致（分析刷新
  是当前库态的全量重算），齐套通知事件按批聚合、dedupe key 携带入库批次号；此改动同时
  消除了逐条触发时同一分析被整棵重建 O(明细数) 遍的批量入库慢根因；
- 冲突返回 `CONFLICT` 时前端保留全部输入并提示「整批已回滚」，刷新后重新核对。

## 四、权限边界

- 查看本页（路由与列表/详情接口）：`warehouse_iqc_stock_in:view` **或** `warehouse_iqc_return:view`
  任一满足（与待检处置合并 IQC/FQC 同款 any-of 口径）；复用既有权限，不新增权限点或迁移；
- 确认入库（单张/批量）：`warehouse_iqc_stock_in:view` + `warehouse_iqc_stock_in:confirm`；
- 「品质放行人本人不得确认」自 2026-09-01 起由硬性阻断降级为**复核提示**（单人维护场景
  需要同一账号完成放行与入库）：详情接口仍返回 `containsOwnRelease` 标记，详情页据此显示
  醒目黄色复核横幅并在确认弹窗里再次提醒，但不再拒绝提交；多人分工时该提示同样在场；
- 登记实物退回：`procurement_iqc_rejection:record_return`（V440 既有口径，按拒收案件校验

## 五a、大数据量下的读路径设计（V448 索引配套）

事实全部留在既有追加式账本，不建第二权威、不冗余存储状态列；快靠查询形状 + 索引：

- **筛选即收窄扫描面**：`receipt_scope` 先按类型收窄（采购/委外两段各自判定 `:type`），
  品质结论、放行切片、待退回、最近动态四个聚合 CTE 全部 JOIN scope 后再 GROUP BY——
  筛了采购或委外时只扫一类收货单的事实行，聚合规模随筛选收窄而不是恒定全库；
- **判定列 index-only**：V448 为聚合列建覆盖/部分索引
  （`procurement_inspection_items (receipt_type, receipt_id) INCLUDE (status, passed_base_qty, failed_base_qty) WHERE status <> 'REVERSED'`、
  PASS 放行事件部分索引、`stock_in_batch_items (pass_event_id) INCLUDE (base_qty)`、
  待退回案件部分索引等），聚合不吃回表；
- **角标不做全量聚合**：`count` 接口只数「存在待入库放行切片或待退回案件」的收货单
  （两条 UNION 的 DISTINCT），支撑 60 秒级轮询；
- **详情单据直查**：合并页详情不再跑全库聚合管线，按 `(receipt_type, receipt_id)`
  索引直查单张收货单的结论/退回计数，作业状态由 `deriveWorkStatus` 在 Java 侧推导——
  与列表 `STATUS_CASE` 分支同序，契约测试锁定两处口径不漂移；
- **单据读路径不做全表聚合**（2026-09-01 修复确认入库与详情随数据量变慢的根因）：详情的
  切片/明细/放行人判断与确认入库加锁查询（`passSlices`）原先对
  `procurement_iqc_stock_in_batch_items` 做**全表 GROUP BY** 求「已入库量」，数据量越大
  每次办理越慢；现改为按收货单事件 `LEFT JOIN LATERAL` 逐事件点查，命中 V448 覆盖索引
  `idx_procurement_iqc_stock_in_item_event_qty (pass_event_id) INCLUDE (base_qty)`
  （index-only，O(该单事件数) 次索引点查，与全库规模无关）。列表/角标的全量聚合管线
  维持原状（本就按 scope 收窄 + 覆盖索引）；
- **砍掉整库装饰性聚合**：列表不再计算「已入库条数」这类展示列（入库历史在详情按单
  读取），每次列表请求少一次全库 GROUP BY。

老数据适配：V446 之前的 PASS 事件 `requires_warehouse_stock_in = FALSE`，天然落在
部分索引之外、不形成待入库任务；`is_deleted` 为 NULL 的收货单继续命中既有
`COALESCE` 谓词（收货表不使用部分索引）。

## 六、预计到货任务中心的口径变化

- 送检即移交品质：`expectations` 列表 / 计数 / 类型计数不再因为「已收满但品质未放行」保留
  任务（原 `PENDING_INSPECTION_EXISTS` 口径下线，CLOSED 任务不再回流）；
- 本页只保留仓库仍有活干的任务：还有可登记容量、挂着草稿收货单（待继续送检）、或有未结
  到货异常（待财务定案）；
- 仍有剩余量可登记且部分已送检的任务继续显示「待登记到货」，详情里提示已送检张数并指向
  本页跟踪结果；登记保存成功后的提示语同样指向本页。

## 六a、不合格退回后的补货口径（V466，2026-09-03）

- 不合格实物退回登记后，这批欠货**默认由原订货单继续补**：预计到货按合格净量重开
  （应到 − 已收 − 已退回不合格 = 待收），供应商补货仍入原订单（补货收货由退回释放
  额度授权，不走到货异常）；
- 物料分析侧因「到货质检存在不合格」取消的供给行动保持取消（V250 追加式契约不复活），
  但其原订货单的当前欠货计入在途覆盖——**下达余量 = 需求 − 活跃行动覆盖 − 该欠货**，
  退回登记后缺口被原订单覆盖、不再邀请重复下单，避免同一批欠货两张单；
- 退回未登记（或退回反向）时欠货不计入在途，缺口恢复可通知——与全不合格后立即重新
  通知的既有口径一致；详见[迁移说明 85](../数据迁移/85-V466IQC退回补货单通道收口.md)。

## 八、验收门禁（在原 IQC 待入库门禁上追加）

至少验证：合并页五种状态的颜色/筛选/计数一致；四类预计/实际去向、部分数量顺序截取、跨仓
全量与跨仓部分、allocation 数量守恒警告、旧响应无 allocations 向后兼容；单张与批量成功结果弹窗；
批量全部入库与批量部分入库；整批冲突回滚
