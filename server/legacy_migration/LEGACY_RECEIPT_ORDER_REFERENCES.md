# V909 收货明细的原始上游编号与缺链保全

本协议用于保留有价值的历史收货明细及真实来源。V627 已应用 SQL 保持原字节，V909 前向补充原始上游编号，完整数量、金额、主档与业务守卫继续生效。

## 来源事实

本轮采购收货源有12373个表头、34885条明细。已有仓库对照表将旧仓130标为DROP，按原规则排除表头12877及2条明细，剩余12372个表头和34883条明细。保留明细中，19行引用15个在采购订单明细源中已经不存在的正ID。首例为收货明细30788、表头10498、原订单明细22652。

独立PostgreSQL以实际CSV和相同typed COPY精确复现：V627表头成功，明细注册来源证明时因缺上游报23514。此问题来自旧源断链，与员工离职或新员工编号无关。货品、颜色和单位的必需主档均存在。

本次委外收货39136条明细的原上游ID均为0或空；不按订单编号文本猜绑。采购和委外两类源均未发现负上游ID。下一轮必须从新来源重新统计，不能沿用19或39136作为固定预期。

## 保存位置和规则

`purchase_receipt_items`、`subcontract_receipt_items`各增加可空正整数`order_item_legacy_id`，保存来源的原始正ID。真实UUID外键`order_item_id`仍只按实际存在的上游legacy_id解析；缺失时保留NULL。原始编号快照不能作为业务外键、可用采购容量或审批。

新字段进入本次V627完整投影、`target_fields`及snapshot SHA，与原始行/文件SHA、run和目标UUID共同保全。新建非空快照要求当前受控BOOTSTRAP、同事务、正确proof种类、源文件及完整投影；存在实际目标时必须精确匹配其UUID，不能人为清空或换绑。货品、颜色、单位等必需主档的显式缺失仍拒绝。

新列不可在线补写、改值或清空；旧proof不含该列时仅兼容NULL，不回填旧行。未来合法退货更新不重新要求首导事务ID，由原数量守卫处理。迁移不新增库存、需求、财务审批或超量容量。

待核队列由同run中`order_item_legacy_id>0 AND order_item_id IS NULL`的行与既有不可变proof关联生成。原收货数量、单价、金额、赠品和累计退货数全部保留，不为通过迁移删除有效收货行。
