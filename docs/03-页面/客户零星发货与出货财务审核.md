# 客户零星发货与出货财务审核

本轮 V511 候选；本地专项结果见[迁移与验收记录](../数据迁移/125-V511客户零星发货统一流程.md)，最终平台验收及上线由统筹执行。

## 页面与操作

销售的 `/sales/customer-shipments` 使用统一销售表格和详情，新增入口为 `/sales/customer-shipments/new`。必须指定真实客户、仓库、用途，并人工选择“收费/不收费”。免费时不再要求填写单价、币种、汇率或结账方式，免费原因须交销售及财务核对。新建真实内部领用应使用仓库内部单据，不能客户留空伪装内部发货。

草稿保存后由“销售确认并提交财务”送审。财务仍在原“出货财务审核”办理，不增加收件台；卡片徽章和财务总徽章使用真实待审任务计数，已读通知不等于办结。财务选择“认领并审核”，认领成功后重新读取当前详情和审核快照，展示本次明细以及上次审核→本次修改。认领失败不会进入可提交审核，退出/重新认领可重试；续租失败或被接管后暂停决定，提交再校验本人 lease、同代 claim UUID 和原修订/哈希。

财务退回须填写原因。销售可以修改后再确认，或取消未出库单据。财审通过后、仓库尚未开始拣货时，修改会撤回原放行并重新确认；财审正在认领中时，包括同一账号另一窗口和超管都不能改。拣货开始后先由仓库完成退拣，才可修改。SHIPPED 后不能直接改数量、收费选择和价款；真实退货走退货检验，没有实物退回的价款更正应走财务追加调整，禁止虚做退货再发运。

仓库继续使用原销售出库任务。开始拣货才建立零星发货自己的库存预留；异常期间保留占用，明确退拣后释放，再拣产生新占用事实。最终 SHIPPED 消费该单预留并出库。收费仅此时立 AR，免费不立虚假 AR，但仍是实际库存出库。

`/sales/other-shipments` 为历史列表/详情；旧 `/new` 转到新客户零星发货，旧 `/edit` 回历史详情。历史数据、旧 UUID 和原库存事实不搬迁；原受控反向继续使用独立权限与真实来源校验。

## 权限和提醒

- 新客户零星发货继续使用 `sales_other_shipment:view/create/edit/delete/approve` 独立权限，`approve` 表示销售确认。共享 `sales_shipments` 表不会使其获得普通订货发货的操作权；服务端按 `shipment_kind` 和负责人范围复核。
- 财务池使用 `finance_shipment_audit`，仓库使用 `sales_shipment:warehouse-work`。审批授权与弹窗接收按 ADR-063 区分：弹窗须当前所属部门与实际动作权限同时满足，不因有查看权就全员弹窗。
- 新修订使用独立 outbox 去重身份；财审通过/退回、销售改动/取消和仓库开始作业撤回已办结提醒。旧通知的真假待办和认领姓名按一批 UUID 查，不逐通知反复访问数据库。
- 没有 `sales_order:price:view` 或财审操作权时，发货读 DTO 同时脱敏数值和 `*Exact` 文本。仓库专用投影不携带货款。

## 接口合同

统一 API 为 `/api/sales/shipments`；销售列表可传 `shipmentKind=DIRECT_CUSTOMER`，权限过滤在服务端执行。

| 操作 | 接口 | 关键输入 |
| --- | --- | --- |
| 新建/编辑 | POST / PUT `/{id}` | 明确类型/收费/用途；编辑 `expectedRevision`；既有明细 `id` |
| 销售确认 | POST `/{id}/confirm-sales` | query `expectedRevision` |
| 财审预览 | GET `/{id}/finance-audit-info` | 返回当前修订、哈希、当前和以前商业快照 |
| 财审通过/退回 | POST `/{id}/finance-audit` / `finance-audit-reject` | `expectedRevision`、`expectedContentHash`、`expectedClaimId`；退回必填 `reason` |
| 财审撤回 | POST `/{id}/finance-audit-reverse` | 仅未开始仓库作业 |
| 财审计数 | GET `/pending-finance-count` | 当前真实待审数，排除未销售确认和只读历史 |
| 仓库作业 | POST `/{id}/warehouse-work` | 既有状态机的 `targetStatus`、必要原因 |

财审 claim 类型为 `SALES_SHIPMENT_FINANCE_AUDIT`，键为规范发货 UUID。旧 `/{id}/approve` 不执行物理出库。

金额读取新增 `*Exact` 十进制文本，编辑优先原文，金额请求发十进制字符串，短显/自动预览不回写权威值。当前超出旧存储精度的直接发货金额或汇率乘积会明确拒绝、事务不写；平台实际单据金额与扩展精度仍需完成后续统一验收。已收后退货产生的待处理余额不是已经支付现金退款。
