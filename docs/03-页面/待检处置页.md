## 一、页面与权限

- 列表/处置：`/warehouse/inspections`（路由名 `warehouse-inspections`）
- 入口：**品质任务中心**（`/quality/task-center`）唯一任务卡「待检处置」，
  角标 = IQC 待检收货单张数 + FQC 待检任务数
  （`GET /api/procurement/inspection/pending-count` 与
  `GET /api/production/quality-inspections/count` 合计，红色圆数字徽章）。
- **进入权限（任一满足）**：`procurement_inspection:view`（IQC）或
  `production_quality_inspection:view`（FQC）。两域在页内分别门控：
  无 IQC view 不拉收货单、不显示「采购收货/委外回厂」分段与表头筛选桶；
  无 FQC view 不请求 FQC 接口、不显示「自制产成品」分段。
- 处置动作分域把关：IQC PASS/FAIL 另需 `procurement_inspection:handle`；
  FQC 登记决定另需 `production_quality_inspection:approve` 且服务端确认有效品质组织池
  （canDecide 失败关闭写按钮，不阻断任务查看）。无对应动作权限者只读。
- 处置返回、返回工作台，或客户端检测到新通知使未读数上升后，两个 pending count provider
  立即失效重拉，不再额外等待角标的 60s 轮询。通知条数/未读数只触发刷新，不是角标计数来源。
- 仓库侧「预计到货任务中心」不承担待检入口：只保留只读状态卡「待品质部批准」
  （无 `procurement_inspection:view` 时不拉取计数显示 '—'）。

## 二、页面结构（2026-09-01 起）

1. **工具条**：分段导航（四段）+ 胶囊圆角搜索框。
   - 每段右侧是红色圆数字徽章（工作台角标同款；0/加载中不显示）：
     「全部待检单」= 采购 + 委外 + 自制产成品三域之和，任一已授权域仍在加载时
     不显示半程合计，不把「未知」伪装成真实 0；各类型段 = 该域全量计数（非当前页推算）。
   - 搜索框 `UtenSearchBar(stadium: true)`：胶囊形边框与分段导航条（M3 StadiumBorder）同形；
     关键字跨域匹配收货单号/供应商（IQC）与报工单/生产计划/货品/颜色（FQC），300ms 防抖。
   - 分段与表头类型筛选共用同一口径（`docType`）。
2. **统一待检队列表格**（`MasterDataTableView`，列：单据类型/单号/供应商或生产计划/货品/
   状态/待检行数/待检数量/最近到检或进入质检）：
   - IQC 行来自 `GET /api/procurement/inspection/pending-receipts`
     （单据类型 = 采购收货/委外回厂），双击进本单处置页；
   - FQC 行来自 `GET /api/production/quality-inspections?status=ACTIVE`
     （单据类型 = 自制产成品），单次拉取上限 500 条，超出时计数仍用服务端 total
     并在工具条下方提示截断事实；双击详情 →（可决定账号）登记检验决定；
   - 持 FQC 决定能力的账号可勾选 FQC 行（IQC 行不出现勾选框，行稳定键独立于勾选键），
     右下角「批量全部合格(N)」走原子 pass-all；决定/批量成功先本地收敛行再刷新，
     刷新失败不回滚已决定事实。
3. **IQC 本单处置页**（`/warehouse/inspections/:receiptType/:receiptId`，不变）：
   - 明细多选表格固定显示货品、颜色、来源订货单、到检/已合格/不合格/剩余待检量和状态；
   - 右下角「批量合格放行(N)」仅处理当前收货单已选明细，最多 100 行；
     请求 `POST /api/procurement/inspection/{receiptType}/{receiptId}/pass-batch`，每行提交
     `inspectionItemId + expectedRemainingBaseQty + idempotencyKey`，服务端先校验全集再写品质结论
     和仓库待入库任务；不得在品质事务写库存；
   - 任一行状态或剩余量变化，整批事务回滚；客户端不得循环单行接口伪装批量成功；
   - 不提供"批量不合格"：不合格原因属于逐行质量证据；选中单行后登记原因；
   - 单行处置对话框：合格放行（PASS）数量可留空=全部剩余（部分 PASS 支持逐次放行），
     放行说明选填；不合格（FAIL）只记质量事实、原因必填；
     红色责任提示显示"审核员：姓名(工号)"（来自当前登录会话，客户端请求不提交审核员字段）；
     幂等键客户端 UUID v4，同键同命令静默重放、同键异命令冲突，提交错误留在对话框内。
   - 本单处理完显示完成态，返回任务中心继续下一单。

## 三、业务口径（与 V222/V335/V410+ 后端一致）

- 收货审核在同一事务内创建 PENDING 冻结行并追加 `PROCUREMENT_IQC_PENDING` 业务 Outbox，
  **不写 stock_balances**；三个可用量口径
  （warehouseAvailableBase/globalAvailableBase/v_stock_available）自然不含待检品。
- 待检 Outbox 按收货单 UUID `publishOnce`：同一收货单有多条明细只投递一次；收货审核事务
  回滚时待检行与 Outbox 一并回滚，不产生孤立通知。
- 待检通知只发给 `DEPT_QA` 子树内当前在职、账号启用，且最终有效权限仍包含
  `procurement_inspection:view` 的账号；PMC/生产默认查看权、跨部门个人加授和超管全集均不扩张
  品质通知池。接收通知不要求 `procurement_inspection:handle`，点击进入 `/quality/task-center`。
- Outbox 真正送达前重查本单是否仍有 `PENDING/PARTIAL` 明细；若已经极速处置结案，则跳过
  过期待检通知。待检角标仍以 `pending-count` 的实时聚合为唯一真相。
- 每次部分 PASS 只追加品质合格数量、事件和"合格待仓库入库"任务；`passed_base_qty`
  不是可用库存，不能直接生成库存流水、分析归属、reservation、DRAW 或 READY。
- PASS 无放行说明时，事件 `reason` 保存为 `NULL`；有说明时才追加说明文字。V335 只放宽
  PASS，FAIL 的非空原因数据库约束保持不变。
- 仓库可按合格待入库量分批填写实际库位并确认入库。只有仓库确认事务才写 `DIR_IN`、
  增加 `warehouse_stocked_base_qty`，并按该次实际入库切片刷新分析与推进正式供给。
- 整张 receipt 品质结案只表示 PASS/FAIL 数量已确定；全部 PASS 量都经仓库确认后，才是
  "仓库已入库"。通知、角标、生产齐套和报表不得把两个状态合并。
- FAIL 不入可用；处置（退/换/补/特采）走对应业务单据，本页只登记质量事实。
- 红冲收货前必须全部明细 RESOLVED；只按实际 `warehouse_stocked_base_qty` 反向库存，
  已 PASS 但未确认入库的数量只取消待入库任务。
- FQC 侧口径（并入后不变，详见[生产成品质检任务页](生产成品质检任务页.md)）：
  任务来自仓库已登记送检；PASS/PARTIAL 只形成 FINISHED_IN 待点收上限，不直接增加库存或
  `iqty`；FAIL 进入 REWORK 或 SCRAP/REJECT 补产链；来源红冲按顺序取消派生事实。

## 四、安全边界

- 处置按钮由前端按权限隐藏，服务端 `@PreAuthorize` 独立兜底（IQC view+handle；
  FQC approve + 品质组织池）。
- 审核员显示不是安全边界：服务端忽略客户端身份声明，并以
  `SecurityContextCurrentUser.requireEmployeeId()` 写入追加式事件表的 actor；
  全局 `fn_audit()` 继续记录事务审计事实。
- 数量校验双保险：前端对话框校验（正数且 ≤ 剩余），服务端按剩余待检量硬校验。
- 处置成功后先从本地表格移除已提交行，再刷新服务端投影；刷新失败也不恢复旧可操作行。
- 无对应 view 权限的域前端不渲染、不请求；服务端仍按各自权限与对象范围裁剪，
  前端显隐不是安全边界。

## 2026-09-07 验收数量与操作提示

IQC 输入和汇总使用已换算的验收数量，单位取服务端 `baseUnitId/baseUnitName`；`sourceUnitName/unitRate` 只用于框内换算说明。例如原单1箱=24个，到检48显示48个，填24合格+24不合格仍提交24+24，不再换算。明细与批量报告都把合格后的仓库确认、不合格后的后续处置写入框内图标。确认和回执按单位UUID分别汇总，未知单位提示待核对，不冒充来源包装单位。

详情可从精确链接打开，即使任务队列已无该单摘要也不崩溃。完整输入清单和代码证据见[主链通俗文案与框内提示清单](../99-项目治理/2026-09-07-主链通俗文案与框内提示清单.md)。
