# ADR-079 品质放行逐行实际入库仓与委外成本来源

- 状态：已接受（2026-09-12），源码候选，尚未更新现有业务库。
- 关联：[ADR-075](ADR-075-合格来源跟随实际入库仓与车间通知.md)、[品质部检查结果页](../03-页面/品质部检查结果页.md)。

## 报错根因

“仓库 UUID 不能为空”的实际失败点是 `InventoryValueLedger.key`：委外正常损耗成本在注册收货产出时，用可空的委外订货单仓库构造成本池。质检记录仓库受 NOT NULL 约束，不能把此报错简单归结为质检没有选仓，也不能通过回填订货仓掩盖错误。

委外正常损耗成本优先复用已有不可变成本对象的池。首次产出时，使用经库存价值引擎验证的真实产出池建立对象，后续不同实际仓收货沿同一对象归集；尚无产出时，已发生的真实损耗价值保留 COST_WIP，首产出再纳入。原订单商业字段、历史成本与 V525/V526 来源守卫不改写。

## 入库仓由明细确认

用户在每个品质放行切片上明确确认目标叶仓。原收货及质检的仓库继续保留到货/建议快照，不能据此重标实际库存。单详情与批量页共享明细表，连续展示来源单据、供应商/委外商、单位、合格待入量、本次数量、实际目标仓和库位；待检及不合格行只读。

请求逐项携带 `warehouseId`，进入幂等指纹与事务前置校验；每个实际入库项、库存流水、合格来源权益及库位学习记录其真实叶仓 UUID。一张收货单可将不同切片入不同仓，批量提交仍为一个受控操作批，无需虚构每仓新收货单号。切片剩余量和权限按原守卫验证，任一新写失败整批回滚。

旧客户端未携带仓字段时，仅兼容原放行切片已经记录的仓 UUID，并执行相同有效叶仓检查；若原切片也未记录仓则明确拒绝，绝不读订货或收货表头补猜。旧成功请求保留原指纹重放。新显式仓请求使用独立版本的结构化指纹，库位中的分隔符不能与仓字段拼接形成相同请求身份。更换目标仓会清空前仓库位并要求重新核对，普通刷新保留当前已编辑输入。

V563 前向替换原“质检仓必须等于入库仓”的等式，以实际入库项与库存流水同仓为权威，保留 PASS、原来源、货品颜色、数量和金额约束。新入库须为活动核算叶仓，祖先仓也必须有效；实际仓入库数量用于供给分配与生产唤醒。历史批次不改仓、不补造来源。

品质成本从登记池 A 入实际仓 B 时，反向必须扣回 B 的实物库存，并恢复 A 的原 QUALITY_PASSED 成本位置。校验原流水、原切片、金额、数量、未耗用与幂等，不强制把原登记池改成 B，也不改变商业费用来源签名。

## 出仓完成与加载

委外出仓的当前选中单据全部执行成功后，退出至出库任务中心的委外待办；部分失败或未确定结果仍留页核对。确认成功及核实已成功均刷新任务与角标。任务中心首次真正返回不得被二次“首次进入”判断吞掉；父页面已刷新时，子导航的返回处理不重复发起同一列表加载。

页面只等待需要的仓库字典，与任务/草稿读取并行；独立任务和草稿采用最多四路读取，保留顺序与精确原单身份。多草稿由单页转批量页时复用刚读取的资料，员工名称异步补充，不阻塞主明细。提交前的原单指纹、权限、就绪和数量校验保留。
