# ADR-171：委外任务中心「领料」并入「待处理」分类

- 日期：2026-10-09（修订二同日）。
- 状态：已接受(2026-10-09，前端源码 + 本地回归全绿；未发版，不代表公司服务器已部署)。
- 遵循 [ADR-066](ADR-066-分类分段统一与历史记录时间门控.md) 的统一分类范式(分类行 + 异常小类行)
  与 ADR-100「本人要动手的档不得被吞进『进行中』」的计数精神；修订
  [ADR-143](ADR-143-委外按工序领直属物料与分批回厂.md) §4.1 的分段结构(草稿 / 待处理 / **领料** /
  进行中 / 历史记录 → 草稿 / 待处理 / 进行中 / 历史记录)，领料行定义、数据源、权限与领料页全部不变。

> **修订二(2026-10-09，用户口径三连)**：
> 1. **领完料才算「进行中」**——领料没有结束的订货单不算「进行中」，只有领完料(或本就
>    无需领料)才进入。服务端权威投影 `v_procurement_decomposition_tasks` 新增 `DRAW_OPEN`
>    档(V834 迁移，谓词与 `SubcontractDrawSql.OPEN_ITEM_PREDICATE` 同口径)，整单从
>    IN_PROGRESS 三档剔除——进行中列表、`statusCounts.IN_PROGRESS`、黄徽章
>    `subcontractTask.inProgress` 一处改、处处一致。回厂短交待判定的红数分支保持挂在
>    FINANCE_APPROVED 上(领完料进入进行中后自然浮现)。
> 2. **子分类行退役，拍平成一张表**——「待处理」点进去就是表格，直接显示所有行：委外申请行
>    (工作台投影，服务端分页) + 领料行(钉在表格顶部、一次拉全 200 上限、翻页常驻，与草稿表
>    钉本地草稿同一范式)。「领料」只是一个状态，不再是子分类。状态红黄分色：可领/待下单/锁行
>    =红(等本部门动手)，已提交待仓库发=黄(在跑不用动手)，等计划/等物料沿用 ADR-169 十档。
> 3. **多选批量领料**——需要领料的行可勾选，右下角悬浮组「批量领料(n)」与「生成委外订货单(n)」
>    并存，各自按各自的选择集计启用，互不拦截。
>
> 计数口径随之修订：「待处理」红 = 申请待下单行数 + 可领行数(不变)；**黄 = 领料中行数**
> (`/api/subcontract/draw-tasks/count` 新增 `submitted`，与列表 `DRAW_SUBMITTED` 同判据)。
> hub 委外任务中心卡黄数 = `subcontractTask.inProgress` + `subcontractDraw.submitted`
> (徽章目录同步)；黄数恒等于任务中心两段黄行之和，不算双计。
> 「待处理」拍平表不做列头筛选(两类行的单据号/状态语义不同，服务端 facets 只覆盖申请行)；
> 筛选交给阶段搜索框与领料定位芯片；异常小类行只在申请行语义下生效，保留。
> 403 口径：无订货查看权限时领料行整体静默隐藏(计数与列表一致)，不向用户报错。

## 1. 背景

用户口径(2026-10-09)：委外任务中心分类行里的「领料」不该单独占一个分类——委外申请待下单与
领料可领都是「等委外本人动手」的活，应同归「待处理」。原五段分类把同一种紧迫度拆在两处，
红数也拆两枚，与 hub 入口角标(待处理 + 可领，一枚)口径不对应。

修订一(同日稍早)先做了「子分类行」方案(委外申请/领料两个子视图)；修订二按用户后续口径
再收敛为拍平一张表，并给出「领完料才算进行中」的服务端口径(V834)。

## 2. 决策

1. **分类行收敛为四段**：草稿 / 待处理 / 进行中 / 历史记录(修订二：无子分类行)。
   「待处理」= 申请行 + 领料行拍平的一张表。
2. **计数口径**(与[徽章与计数口径](../00-项目准则/14-徽章与计数口径.md)一致)：
   - 「待处理」红 = 申请待下单行数 `statusCounts.WAITING_ORDER` + 可领行数
     `subcontractDraw.drawable`——两类不同对象相加，与 hub 委外任务中心卡红数天然同数；
     黄 = 领料中行数 `subcontractDraw.submitted`。
   - 「进行中」红黄两枚不变(黄 = IN_PROGRESS 全量 = 领完料的单；红 = 其中财务驳回)，
     V834 后自动不含领料未结束的单。
   - autoSelectBadge(2026-10-04 口径)不变：进页面第一条红数分类自动选中。
3. **深链语义保真**：`?segment=draw(&orderItemId=/&orderId=)` 落「待处理」并按该
   明细/订货单定位领料行；`?segment=pending&keyword=申请号` 落「待处理」并按申请号搜索。
   `RouteName.operationsSubcontractDrawSegment/PendingSegment` 方法签名与参数零变化——
   在途通知 action_route、领料页返回、进行中「可领料」跳转全部不受影响。
4. **无订货查看权限(计数/列表 403)**：领料行整体静默隐藏，拍平表只剩申请行，
   红黄两枚领料计数一并消失。
5. **切换语义**：切走再切回「待处理」时领料定位芯片(只看某订货单/某明细)保留，
   靠芯片清除按钮回全部；异常小类行照常出现(作用于申请行的服务端过滤)。
6. **不动的东西**：领料任务行定义(ADR-143 §4.1 以下)、`/api/subcontract/draw-tasks*` 端点
   (仅 `/count` 增加 `submitted` 键)、`subcontract_order:view/draw` 权限、领料页与批量上限 50、
   仓库出仓链路——全部照旧。
