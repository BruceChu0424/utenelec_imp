## 一、目的与边界

V425 在 V424 完成审计降噪与中文化后，为新的审计口径建立空白起点。迁移只执行：

```sql
TRUNCATE TABLE audit_log, audit_log_archive RESTART IDENTITY;
```

这会永久删除在线审计表与冷归档表的全部历史，并重置自增 ID。它不修改业务表，但审计历史本身是
合规、调查和责任追溯证据，不能把“业务数据未变”解释为低风险迁移。`RESTART IDENTITY` 还会复用审计
ID：旧 Excel、截图、工单或调查记录里的日志 ID 以后可能指向另一条新日志，破坏引用唯一性。

## 三、AuditFreshStartGuardCallback 失败关闭边界

源码新增 `AuditFreshStartGuardCallback`，并接入正式 Spring Flyway 与独立 `UtenImpMigrator`：

- 每次 migrate 开始时读取本次连接的 Flyway history 行数；只有本次迁移从 **0 条已应用 history** 开始，
  才允许同一 fresh chain 继续经过 V425；
- 只要迁移开始时已有任意 Flyway history，回调会在 V425 前抛错并失败关闭。没有环境变量、运行参数或
  临时授权开关可以绕过；
- 该回调只是防止已使用数据库被普通正式入口意外清空，不是 V425 执行授权，也不证明 0-history 数据库
  可用于某个目标环境；fresh chain 仍须服从签名制品、目标身份、备份、恢复和发布审批；
- 直接运行未注册该 callback 的其它 Flyway CLI、测试 helper、旧 JAR 或自定义入口仍可能绕过保护，全部禁止。
  受控入口存在不等于所有入口都安全；
- 当前目标环境应用状态尚未核实，V425/V426 与发布仍是 NO-GO。回调不能恢复已经删除的历史，也不能解决
  `RESTART IDENTITY` 的 ID 复用问题。

## 四、当前处置分支

### A. 已知本机开发库已应用 V425

不得修改、删除、重命名 V425，不得 `flyway repair`。本机记录不等于其它环境状态，也不构成继续执行 V426
或发布的批准。被删除的审计事实不能由 V426+ 或当前业务行反向猜造；需要调查历史时，只能从执行前受控
备份恢复到隔离库核对，不能把旧 ID 直接灌回在线表。

### B. 已有 Flyway history、尚未应用 V425 的环境

正式 Spring 与独立 migrator 会由 callback 在 V425 前失败关闭；迁移必须停在 V424。该失败不是可忽略告警，
也不能改用未受控 Flyway CLI、旧 JAR 或自定义 helper 绕过。V426 在 V425 之后，因而同样不可达、NO-GO。

### C. 0-history fresh chain

callback 只在本次 migrate 从 0 条 history 开始时允许继续。此技术条件不等于目标环境清空授权；仍须确认它
确实是批准的新库/离线 fresh chain，并完成签名 lineage、目标身份、恢复和发布审批。不能把一个已有业务库
通过清 history 伪装成 fresh chain。

### D. 环境状态未知或入口未受控

保持 NO-GO。先盘点每个开发、测试、内测和目标环境的 history、V425 前后两表计数、加密备份 SHA-256 与
恢复位置；未注册 callback 的任何 Flyway 入口全部禁止。

## 五、若未来另行申请清空的前置门禁

V425 属于不可逆数据删除。任何目标环境执行前必须同时具备：

1. 负责人明确批准清空的环境、时间点和业务原因；
2. `audit_log` 与 `audit_log_archive` 的加密备份、SHA-256、行数和恢复位置；
3. 在隔离可恢复副本完成 V425 前后行数、序列、审计新写入和恢复演练；
4. 法务/合规/内部调查确认历史审计已满足留存或已完成受控归档；
5. 目标 `flyway_schema_history` 与冻结源码 checksum exact-set 一致；
6. 停写/排空旧实例，防止旧进程在迁移窗口继续写入；
7. 执行后回读 V425、两表为空、序列重置且新操作能产生 V424 新口径审计。

缺少任一项时，目标库应用 V425 为 **NO-GO**。上述清单只说明未来另行审批至少需要什么，不构成本次授权。

## 六、恢复与发布边界

V425 不能通过旧 JAR、修改迁移文件或 `flyway repair` 回滚。需要恢复历史时，只能从执行前受控备份
恢复到隔离库，经核对后制定新的前向恢复迁移或完整数据库恢复计划。

代码上传 GitHub、PR 合并、CI 通过、签名制品生成、目标库迁移和服务器激活必须分别报告。本文件只
说明源码候选契约，不授权数据库写入、部署或生产放行。
