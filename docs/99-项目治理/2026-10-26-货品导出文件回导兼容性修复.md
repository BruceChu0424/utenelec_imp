# 货品导出文件回导兼容性修复

用户反馈员工在货品资料中无法导入系统导出的文件，修改编号或清空编号后仍不能导入。尚未取得员工原文件和现场错误，本记录区分已复现的程序限制与现场验收。

## 已确认的问题与处理

1. 编号值可以为空，但解析器仍强制要求编号表头，删除编号整列会报缺少必填列。现将编号列设为可选，复用空编号规则；货品名称和类别仍为必填列。
2. 导出包含系统 UUID，旧文件的 UUID 在当前库不存在时被直接拒绝，修改或清空编号均无法通过。现仅将查无本地实体的 UUID 视为外来标识，进入既有无 UUID 的编号匹配或新建流程。新建使用系统分配的本地 UUID，绝不复用文件中的外来 UUID。
3. 读取或检测失败时，具体原因以前主要显示在短暂的顶部通知中。现将原因保留在弹窗可复制区域；读取成功的原文件可直接重新检测，读取失败可重新选择。
4. 混合文件既有恢复行又有差异行时，原交互会自动打开差异页，跳过报告中的恢复数量。现含恢复行的文件先显示报告，由用户继续核对或确认导入；取消仍不写入。

当前库已存在的 UUID 仍定位原货品。编号为空或缺列保留原号，新编号需经差异核对并选择替换才改号。已删除的本地 UUID 仍遵循原编号恢复规则；同文件重复编号、同一货品多行、不同 UUID 的编号占用、曾复用编号未提供当前 UUID 等仍拒绝。空号新行逐行自动编号，不按名称合并，不改变库存、BOM、订单或权限边界。

## 公共入口与调用范围

| 能力 | 现有入口与调用方 | 本次处理及保留差异 |
|---|---|---|
| 货品导出模板 | `GoodsExportProjection.forImportTemplate`；同步 `GoodsController` 与后台 `MasterReportExportSource` | 已共用列投影，继续补足系统标识、名称、编号、类别；不复制另一套导出算法 |
| 货品解析、身份匹配与检测计划 | `GoodsImportService`；`GoodsImportController` 的检测及原始字节/JSON 提交 | 在唯一领域入口修复两处限制；原文件 SHA、全局身份/资料指纹、权限与事务复核继续生效 |
| 文件读取 | `readGoodsImportFile`；货品、BOM、成本导入弹窗 | 保留共享大小/格式校验，不改变 BOM 与成本的各自业务身份规则 |
| 员工导入交互 | `product_category_page.dart` → `showGoodsImportDialog` → `DioGoodsImportRepository` | 原入口继续使用共享文件队列、差异页和 `humanErrorMessage`；补充持久错误提示及三语说明，沿用 `frontend-design`、Uten 主题与组件 |

没有新增平行解析器或编号分配器；没有失效实现需要迁移或删除。

## 验证与限制

- `GoodsExportImportTemplateTest` 使用真实系统导出响应字节，保留历史 UUID 后分别改号、清空编号、删除编号整列，再执行检测和提交。
- `GoodsImportMergeTest` 覆盖当前 UUID 缺编号列、未知 UUID 三种编号状态、已有编号冲突的忽略/替换、历史复用与重复行拦截。
- `GoodsImportHistoryPostgresTest` 在隔离 PostgreSQL 中核对本地身份保留、多行自动编号唯一、外来 UUID 不写入主键、同一计划不可重放、撤回与重做，以及恢复行与冲突行混合时只执行已确认的动作。
- 前端 4 个测试文件合计 **31 项通过**，覆盖错误持续显示、原文件重新检测、读取失败后重新选择、差异核对、恢复提示、取消、队列和未知提交重试。日志为 `output/goods-import-20261026-frontend-tests.log`；静态分析无问题，见 `output/goods-import-20261026-frontend-analyze.log`。
- 修复前版本的定向回归共 62 项，新增的 7 项分别因历史 UUID 不存在或缺少编号表头失败，原报告保留于 `server/target-import-file-audit-20261026/baseline-red/surefire-reports`，用于证明用例能复现修复前缺口。

- 后端最终 16 类合计 **117 项通过，失败/错误/跳过均为 0**，包括 18 项真实隔离 PostgreSQL 测试及 35 项合并/身份测试。隔离库通过真实迁移至 V946，没有访问业务库。主批日志为 `server/target-import-file-audit-20261026/final-run.log`，该次运行因两条 POI 文件编辑测试夹具和一条旧 owner 范围夹具失败；修正夹具后补跑两类 7 项全部通过，日志为同目录 `fixture-rerun.log`。最终 Surefire XML 为主批与补跑各类的最新结果；这是定向回归收口，不是单次全项目 CI 全绿。
- 导出回环测试在编辑后重新读取工作簿，确认改号、空号、历史 UUID 及删除编号列后的列位移，避免原始 inline string 残留使测试实际读取旧编号。owner 范围测试接入现用公共策略，原拒绝、允许及不落库断言均保留。
