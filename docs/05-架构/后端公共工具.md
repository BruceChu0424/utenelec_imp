## 一、`com.uten.imp.common.report.ReportQueryKit`（2026-09-16）

**位置**：`server/src/main/java/com/uten/imp/common/report/ReportQueryKit.java`（final 工具类，私有构造）。

**来源**：六个报表服务（finance / production / purchase / sales / stock / subcontract 的 `*ReportService`）里逐字重复的私有工具成员收敛而来；原各服务的本地拷贝已删，调用点改指本类。后续**新增报表必须复用本类，不得再拷贝私有副本**。

**成员**（只收完全一致的；有分歧的版本留在原服务，见类注释）：

| 成员 | 用途 | 收敛说明 |
|---|---|---|
| `FacetSpec`（record，5 参 + 兼容 6 参 `orderExpr`） | 列 facet 投影/分组/过滤/排序规格 | `orderExpr` 仅 purchase 的 execute 读取，其余服务固定 `cnt DESC` |
| `WhereBuilder` | base + 若干 AND 子句（带参数）构造 WHERE | finance 的空 fragment 变体留在原服务 |
| `addApprovedByDefault` | 默认口径：草稿（status=0）不进报表（单头别名 `o`） | finance 钱流别名 `t` 的本地拷贝保留 |
| `addCommonDocFilters` | 明细主过滤：单号/供应商/仓库/状态/日期/关键字 | 从 purchase/subcontract 收敛（逐字一致）；sales 取 clientId、production 取 goodsId 的分歧版本留在原服务 |
| `addSummaryKw` | 汇总关键字（单号模糊匹配） | sales 含客户名的版本留在原服务 |
| `facetsOf` | 从全部 query 参数抽取 `f.` 前缀列筛选 | 统一 LinkedHashMap 保插入序 |
| `parseUuid` / `parseShort` / `parseDate` | 导出参数解析（空/空白 → null） | — |
| `paginateAll<T>`（泛型） | 循环分页(size=500)累积全部行；硬上限 2000 页；超 `maxRows` 抛 409 | 各包 `ReportTableResponse` 是独立类型，经 total/exportColumns/rows 三个取数函数适配；`maxRows` 由调用方解析后传入（common 不依赖 SystemSettingsService） |

**范式**：原生 SQL + EntityManager + 各包自带的 `ReportTableResponse`（六包各自定义、结构同型）。排序白名单走同包 `common/report/ReportSort.java`（sort 必须命中列 key 白名单，防 SQL 注入）。

**当前调用方**：六包的 `*ReportService`（subcontract 全量接入）与 finance / production / purchase / sales / stock 五个 `*ReportController`（subcontract 的 controller 内联过滤 `f.` 前缀，未走本类）。

## 二、`com.uten.imp.common.finance.MoneyPolicy`(2026-09-23, ADR-112)

**位置**: `server/src/main/java/com/uten/imp/common/finance/MoneyPolicy.java`(final 工具类)。

**口径**(用户 2026-09-07 确认「财务不四舍五入, 分摊不丢余额」): 金额乘积保留全部位数; 按量分摊一律
「累计量份额 − 已分摊」, 末批取全部剩余; 累计份额整除取精确值, 除不尽取到来源金额自身小数位(至少 4 位)的最近值,
取舍差留在来源余额里由末批收回。**sales/purchase/subcontract/finance/warehouse/stock/production 与 common.finance 里,
除本类外不得出现 `HALF_UP`**(`ArchitectureBoundaryTest.moneyRoundingOnlyLivesInMoneyPolicy`, 豁免清单写明理由)。

| 成员 | 用途 |
|---|---|
| `exactProduct(qty, price[, discount])` / `local(original, rate)` | 完整乘积(实际 24 位 / 账面 30 位上限校验), 折扣空或 0 = 不打折 |
| `line(qty, price, discount, rate)` | 单据行金额: 单价空 → 金额空, 汇率空 → 本币空; 无币种单据传汇率 1 |
| `cumulativeShare` / `prorate` / `prorateBatch` / `amountSlice` | 累计份额(整除取精确值, 除不尽取到来源小数位的最近值)、本批 = 累计份额 − 已分摊、末批 = 总额 − 已分摊; 按事件切片 = 累计份额差 |
| `projectedSlice` | 4 位库存价值列(IQC 放行价值、分批入库价值)专用: `ROUND(来源 × 累计量 / 来源量, 4)` 的差, 与 V446/V449 库级守卫同式 |
| `sum` | 表头合计(空行不计) |
| `quantity` / `quantityFromBase` / `quantityShare` / `quantitySlice` | 数量列 4 位存储取整, 与金额分开命名 |
| `canonical` / `canonicalRate` / `unitValue` / `percentOf` | 只补显示位数不改数值 / 汇率 6 位 / 单位价值展示投影 / 报表占比 |

配套: `ServerDerivedAmounts`(标记接口) + `ServerDerivedAmountsModule`(全局 Jackson 模块)——标记的保存请求 DTO
出现 `amountOriginal/amountLocal/totalOriginal/totalLocal/costAmount/exchangeDiff/taxAmount/returnAmount` 直接 400;
`ExactDecimalText`(BigDecimal 以十进制原文字符串输出, 用在财务审核类 DTO 的金额/数量字段);
`ProcurementIqcAmountSplit`(同一条待检明细的 IQC 金额口径: 事件顺序切片、冻结品质分项优先的不合格金额、
退货可退额度 = 收货金额 − 不合格金额的已实收份额——仓库放行、财务不合格、退货额度三处同一口径)。

## 三、`com.uten.imp.features.finance.accountflow.AccountFlowLedgerService`(2026-09-23, ADR-112)

资金账户余额(`accounts.balance_current` 与 `receipts_total / payments_total / balance_adjustments_total`)和对账流水
(`finance_reconciliations`)的**唯一写入口**(`AccountFlowAppendOnlyContractTest.accountBalancesAndFlowsHaveOneWriter`)。

- `lockActive(accountIds, label)`: 按主键顺序 `FOR UPDATE`, 账户与币种都须启用;
- `post(AccountPosting)` / `post(LockedAccount, AccountPosting)`: `CurrencyRule` 决定账户记哪个金额
  (`BASE_ONLY` / `BASE_OR_DOCUMENT_CURRENCY` / `ACCOUNT_CURRENCY` / `ANY`), 改余额与累计列、写一条流水, 返回流水主键;
- `reverse(sourceType, sourceId, at, reason)`: 镜像反向流水并按原始流水冲回余额。

调用方负责先锁总账期间, 再调账本锁账户。新增资金单据只声明 `AccountPosting`, 不得再自写 `UPDATE accounts`。
