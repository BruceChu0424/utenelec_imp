# v2.5.21 统一授权与手动更新验收

版本：`2.5.21+2521`。本页随候选源码提交；完整 CI、签名上传、云端版本指针及公司安装分别核验，不提前宣称发布或安装完成。

2026-10-17 最新安排：用户要求先完成本地源码与 CI 报错修复，等其他并行任务完成后统一整合。本轮不打包、不发布、不合并主干；本页版本号和说明仅为候选，实际统一发布版本待后续确认。

## 员工可见变化

- 财务确认、报价核价、订货审批和 FQC 等功能使用实际有效授权，不再额外要求属于特定部门或必须另有个人点名。查看、批准、驳回和敏感字段仍按各自明确的权限设置办理。
- 权限开关、服务端能力、操作按钮、待办和会话刷新使用一致规则。普通授权变更后，有效登录会话可刷新取得新权限；撤权不会被旧界面、过期委派或晚到响应恢复。
- 独立动作不会因另一个页面的查看权限被误挡；只有允许自动授予的普通读取才辅助补齐，已收回、敏感或不在授权上限内的读取不会被偷偷加回。
- 审核失败保留实际原因，区分没有授权、占用、版本或状态变化、通信失败，以及操作结果尚未确认。操作已成功但页面刷新失败时，不再误报为提交失败，也不自动重复提交。
- 更新页面改进版本、阶段、原因及处理建议的显示。主机作业跨后端重启保存，结果未知时按原任务核对；旧主机助手没有详细原因时明确提示尚未确认原因。

权限规则见 [ADR-181](../99-决策记录-ADR/ADR-181-操作资格统一使用有效权限与准确失败提示.md)，检查范围与分组测试见 [授权行为一致性记录](2026-10-16-全平台授权行为一致性检查与修复.md)。

## 兼容与发布边界

本版没有新增或改写数据库迁移；迁移源与 v2.5.20 相同，头版本为 V870，共 796 条。保留已有账号、授权配置、业务数据、稳定身份和客户端偏好，不通过重建数据库或清空存储完成升级。

现役 `simple-release.yml` 从同一最终提交构建应用 JAR、独立 migrator 和完整 Web，核对迁移集合、生成 SHA256 清单并签名上传 OSS，最后更新云端版本指针。该流程不生成原生桌面安装包，也不会自动安装 Linux 主机助手或 systemd 单元。

服务器由用户在设置页手动检查并选择立即或预约更新。主机组件与应用版本分别验收；主机助手的独立安装、worker 身份与能力要求见 [服务器运维说明](../../deploy/simple/SERVER_OPERATIONS.zh-CN.md)。本次发布不代替用户执行公司服务器激活。

## 手动更新后核对

1. 在服务器设置点击“检查版本更新”，应发现 `v2.5.21`；仅检查不会下载、迁移或重启。
2. 选择更新后查看同一持久任务的阶段和结果；断开或重连后继续核对原任务，结果未确认时不重复提交。
3. 更新完成后核对实际运行版本、健康状态与页面版本；刷新 Web 后应显示本版说明，原设置和业务数据仍保留。
4. 用已授权的非财务部门账号核对对应审批；再核对撤权后的按钮与操作拒绝是否一致。出现失败时，保留具体提示和任务标识以便定位。

本地已完成跨模块权限、真实 PostgreSQL/HTTP、界面和版本说明的定向回归，以及更新检查与发布门禁合同检查。各分组有重叠，不汇总成全量用例数字。
