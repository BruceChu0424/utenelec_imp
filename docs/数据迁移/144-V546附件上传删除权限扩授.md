# V546 附件上传/删除权限扩授到单据归属部门 + 附件权限归类「通用」

2026-09-10。用户需求 G4：「新建销售订货单页在保存前就能上传附件；财务审核页可看；能预览 word/pdf/excel/图片；其他有上传处同样」。

## 根因

审计发现 `attachment:upload` / `attachment:delete` 自 V280（当时的复合码 `attachment:manage`）→ V328（拆成按钮级）起只授予 **DEPT_FIN / DEPT_HR**。销售、采购、委外、仓库、计划、生产、品检等单据页面早已接入共享附件区（`BusinessAttachmentSection` 叠加 `attachment:upload` 才显示「上传」按钮），但这些部门的员工永远看不到上传入口——不是页面漏接，而是通用功能门槛没给。

同时 V328 把 `attachment:*` 归类在「人事行政 → 附件」（当时只有员工档案入口）。现已是跨模块共用能力，继续挂在人事行政下误导管理员查找。

## 本版变化

1. **目录归类**：`attachment:%` 全部改为 `module='通用', category='附件'`（含已停用的历史复合码，保持同组）。后端 `DepartmentPermissionAdminService.MODULE_ORDER` 追加「通用」，排在「系统管理」之后；权限管理页两级目录相应显示第 12 个模块。
2. **扩授** `attachment:upload` + `attachment:delete`（`INSERT … SELECT … ON CONFLICT DO NOTHING`，未知部门编码由 JOIN 自然跳过）：

| 分组 | 部门编码 |
|---|---|
| 销售 | DEPT_SALES、DEPT_RAIL、DEPT_NEWMEDIA、SALE_G1..G4、RAIL_MUDUO、RAIL_ZHIQIAN |
| 供应链 | DEPT_PMC、SUB_PURCHASE、SUB_WH、SUB_PLAN |
| 生产与品检 | DEPT_PROD（6 个 WS_* 车间继承）、DEPT_QA、QA_OUT、QA_TEST |
| 管理层与中心 | GM、FIN_CENTER、MKT_CENTER、MFG_CENTER |

DEPT_FIN / DEPT_HR 原有授权不变。`attachment:view` / `attachment:download` 在 V280/V328 已授予全部在职部门，本版不动。

## 对象级边界不变

通用码只挡功能门槛；每个 ownerType 的 `AttachmentOwnerAccessPolicy` 仍按单据状态与归属终审：草稿 / 财务退回可管理，提交审核或生效后只读；财务审核页只读（`SalesOrderAttachmentAccessPolicy` 本版收紧：财务只对已进入财务流程的订单可读，草稿不可读）。新增 `PRODUCTION_PLAN`（草稿且未关闭/中止/取消可管理）与 `PRODUCTION_DAILY_REPORT`（草稿且未关闭/取消可管理，审核后只读）两个策略。

## 幂等与验证

- `UPDATE` 带条件、`INSERT … ON CONFLICT DO NOTHING`，可重放。
- 权限目录/部门权限写入由 V135 触发器推进 `authorization_state.epoch`，在线会话按版本机制即时生效，无需重登。
- 验证 SQL：

```sql
SELECT module, category, count(*) FROM permissions WHERE code LIKE 'attachment:%' GROUP BY 1,2;
SELECT d.code, string_agg(p.code, ',' ORDER BY p.code)
FROM department_permissions dp JOIN departments d ON d.id = dp.department_id
JOIN permissions p ON p.id = dp.permission_id
WHERE p.code IN ('attachment:upload','attachment:delete') GROUP BY d.code ORDER BY d.code;
```
