> **2026-09-23 ADR-110**：设置项只登记在服务端枚举 `SystemSettingKey`(键/类型/默认/范围/名称/说明/是否公开)，数据库只存值；页面的取值范围随列表接口下发，不再在前端另写一份。保存不再在页面里问密码，改由服务端要求再认证、网络层弹统一的「请确认是你本人」框。新增 7 项(切换人窗口、密码最短长度、临时密码有效期、三个业务预警天数、待办角标刷新间隔)。

## 入口

工作台 → 系统管理 →「系统设置」卡片。路由 `/admin/system-settings`，授权管理入口要求
`authorization:manage`；后端 Controller 与 Service 还必须确认当前主体仍是超级管理员——**普通用户连入口卡片都看不到**。

系统设置权限与审计核查权限彼此独立：超级管理员因固有全权限可查看审计；其他人只有个人点名获授
`audit_log:view` 才能查看在线审计和原设备本机回执，但该权限不允许进入本页或修改留存策略；
`authorization:manage` 也不能替代 `audit_log:view` 查看审计。

## 安全（六道防线，强制规范）

1. **路由守卫** `/admin/system-settings` 要求 `authorization:manage`；普通用户看不到本页入口。`/admin/` 下其它页面按各自权限判断，审计中心不复用本页权限。
2. **`@PreAuthorize("hasAuthority('authorization:manage') and principal.superAdmin")`** Controller/Service 双层校验。
3. **再认证**：唯一写路径 `PUT /api/admin/system-settings` 标 `@RequiresStepUp`，要一张 5 分钟、绑定当前会话、只能用一次的凭证——即使 access token 被盗，改策略还需密码。页面不自带密码框：服务端回 `403 REAUTH_REQUIRED` 时网络层弹统一密码框，换到凭证后自动重发。
4. **审计**：`update_system_setting`（谁/哪项/旧→新值），审计页可查。
5. **类型 + 范围校验**：服务端按 `SystemSettingKey` 登记权威校验；列表接口随项下发 `minValue/maxValue/defaultValue`，前端只用它提示。
6. **职责分离**：本页继续要求 `authorization:manage` + 超级管理员；审计查看要求 `audit_log:view`，
   审计导出再叠加 `audit_log:export`，三者不得相互代替。

## UI（精心设计）

按 5 类分组卡片（安全策略/登录令牌/短信验证/业务限制/审计与留存）+ 改动跟踪（与服务端原值比较后才标记 dirty，高亮 primaryContainer；改回原值自动清除）+ 右下角「保存 N 项改动」+ 顶部警告横幅（影响全员提示）+ 每项显示说明 + 上次修改时间。数值项越界时输入框标红并提示服务端给的范围「(最小–最大)」。

本次改动包含审计留存时，保存前先弹一次「确认审计留存修改」(缩短期限会在下一次 03:17 清理中永久删除历史日志)；其它改动直接保存。保存期间不挂整页遮罩——再认证密码框要能弹在最上层。

「审计与留存」卡片会把两个独立数值实时翻译成完整时间线，例如：前 6 个月在线可查，随后归档
30 个月，共 36 个月后永久删除。页面明确提示每日北京时间 03:17 执行以及永久删除不可恢复；缩短
期限前应先完成合规确认与必要备份。页面同时提示：客户端本机回执按两段期限之和自动清理，但还受
最近 300 条上限约束；产品不提供手动清空，本机数据仍可能因卸载、浏览器/系统清理或设备重置消失。

## 设置保存、并发与实际生效时机

唯一写入路径是 `PUT /api/admin/system-settings` 原子批量请求(单项 `PUT /{key}` 与庆典设置 `PUT /notices/celebration/settings` 已删除)：

```json
{"changes":[{"key":"lockout_minutes","value":"20","expectedValue":"15"}]}
```

一次请求最多 50 项；先按主键顺序锁定本批设置，检查全部原值和新值后才写入。
任何设置未登记、值非法或原值已变更，整批都失败，不能出现前几项已生效、后几项失败。逐项审计仍保留，
只有事务提交成功才发布显式成功记录。

表单按登记类型渲染数值、文本或布尔选项；只校验本次改动，不强迫无关旧配置被改写。保存期间冻结
输入和重复确认；下拉刷新不会覆盖未保存编辑。所有修改时间使用北京时间。保存完成再重新读取权威值。

`SystemSetting.updatedAt` 由既有数据库默认值/更新触发器生成，Hibernate 使用
`@Generated(event = {INSERT, UPDATE})` 在写语句回执中同步受管实体；批量保存返回的 DTO
直接使用该数据库时间，不用应用时钟或逐项 `refresh`。

运行时数值边界(登记在 `SystemSettingKey`；只在显式编辑对应键时校验)：

这些是安全/容量硬边界，不代表建议把实际配置调到最大值。密码历史允许 0，表示不回查旧密码，当前密码
始终禁止复用。庆典自动类型只允许 `birthday,anniversary` 的非空子集；停发通过布尔开关，署名为 1–100
字符。V659 把越界的令牌期限收进新范围(access 5–1440 分钟、登录保持 1–30 天)，其它存量值不动。

> access TTL 上限为何是 1440 而不是更短：服务端会话(ADR-110)让登出、空闲超时、账号变动都即时生效，
> access TTL 不再是安全边界，只决定「多久静默换一次令牌」。登录保持时长是会话从登录起算的绝对期限。

`SystemSettingsService.readInt/readLong/readBool/readString` 只接受 `SystemSettingKey`(按字符串读的 API 已删除)，**不缓存**，每次按主键读取；值缺失或不合法时回退登记默认值并记警告。各组件动态读取：
- `LoginRateLimiter`/`ExportRateLimiter`：令牌桶阈值动态，变更后下次 check 检测到新值重建桶。
- `LoginService`/`StepUpService`（锁定阈值/时长）、`PasswordPolicy`（最短长度）、`PasswordService`（密码历史）、`JwtService`（access TTL）、`AuthSessionService`（空闲超时、绝对期限）、`VisitorSmsService`（短信 3 项）、三个业务预警调度器、报表/基础资料/审计中心导出上限。
- `AuditRetentionScheduler` 每次运行重新读取在线与归档月份；保存后最迟在下一次 03:17 周期生效，
  不需要重启服务。任务分批先归档并确认，再删除在线行，最终才永久删除到总期限的冷归档。
- 客户端从公开运行时设置同步“在线期 + 追加归档期”的总月数，在后续本机回执读写时执行超期/超量
  自动清理；该公开数值不暴露任何审计内容，也不赋予审计查看权限。

新增设置项的步骤：在 `SystemSettingKey` 登记 → 迁移补一条数据行(值=登记默认) → 调用方按枚举读。`SystemSettingRegistryContractTest` 在全新迁移库上断言行集合、种子值与登记一致，漏一步即红。

详见 [ADR-013](../99-决策记录-ADR/ADR-013-系统设置与安全策略可视化.md)、[ADR-110](../99-决策记录-ADR/ADR-110-服务端会话与敏感操作再认证.md)。

## 会话空闲超时 vs 登录令牌有效期（两套独立机制，别混淆）

| | 登录令牌有效期（access TTL） | 自动退出登录（会话空闲超时） |
|---|---|---|
| 层 | 令牌本身 | 服务端会话 `auth_sessions`(权威) + 前端及时提示 |
| 计时对象 | 令牌多久换一次 | 用户多久没有「人为请求」(角标/计数类自动请求不算) |
| 默认 | 15 分(5–1440) | 30 分(可调) |
| 到期行为 | 前端用 refresh 静默换新令牌（**用户无感**）；会话到登录保持时长(默认 7 天，从登录起算)才需重输密码 | 服务端让会话失效，任何请求 401；前端到点弹窗「您已 N 分钟没有使用…」→ 回登录页 |
| 防的是 | 单个令牌的暴露窗口 | 用户离开但系统还开着，别人趁机操作；令牌被窃后的长期滥用 |

- **一直操作**：access 到期前端自动续期（无感），空闲因有操作不计时——**两层都不打扰**。
- **离开 30 分钟**：服务端会话空闲超时(即使令牌还没到期)，前端同时回登录页。页面开着只有角标在轮询也算离开。
- **登录满 7 天**：会话到绝对期限，需重新输密码(中途一直在用也一样)。
- **按标签页独立**（ADR-061）：Web 端每个标签页有自己的会话与计时——A 标签页操作不给 B 标签页续期，A 超时登出也不影响 B（B 可同时登录另一账号）。

> 关键修复（2026-07-27）：access 过期时后端必须返 **401**（`SecurityConfig` 配 `AuthenticationEntryPoint`），前端 `AuthInterceptor` 才会自动 refresh；若返 403 会被误判成「无权限」、需重登才恢复。详见 [ADR-014](../99-决策记录-ADR/ADR-014-会话超时与token刷新机制修复.md)。

### 改了阈值何时生效

- **「自动退出登录」**：服务端每个请求读当前值，保存即生效；前端 `IdleTimeoutGuard` 三管齐下同步本机提示——① 进系统拉一次；② 每 5 分钟轮询；③ 超管在本页保存后自增 `idleThresholdVersionProvider` 信号 → **立即重拉**。
- **「登录令牌有效期」**：只影响**之后签发**的令牌；用户下次 access 到期、前端自动 refresh 时拿到新 TTL。无需重登。
- **「登录保持时长」**：只影响之后登录建立的会话(已有会话的绝对期限在登录时已定)。
