## 问题与处理

资料库选择器虽然可以选取任意文件，但页面 MIME 白名单、服务端上传 MIME 白名单和内容检查限制了格式；发布阶段还拒绝了原件与资料名均无后缀的情况。本次统一修正选择/拖入/复制粘贴及后端全上传流程：

- 原有文档/图片按既有类型合同校验，媒体按媒体类型合同识别；未识别的媒体容器退为 `application/octet-stream` 原件，避免旧 MOV、少见 MP4 品牌被格式白名单拒收。签名授权和上传会话仍保持原声明，发布与下载使用核验后的有效 MIME；原件绑定、重试和摘要不变。未知后缀、CDR、设计与模型格式也以 `application/octet-stream` 保存原字节，不承诺预览。不透明 MIME 优先于后缀，重命名不能触发解析；服务端也在 Office 转换入口拒绝不透明原件。
- 放宽范围只限 `COMPANY_FILE`。其他业务附件保留白名单，继续走同一 `presign -> raw PUT -> confirm`，资料库仍以 `reserve -> ... -> complete` 发布。扫描、故障拒收、ACL、密码、owner、配额、原始大小、SHA-256、幂等与未知提交重试规则保留。
- 媒体播放器读取经过授权和完整性核验的原字节，以本地私有临时目录/浏览器 Blob 为源；不把 ERP 令牌或私有下载 URL 交给播放器。默认暂停，提供播放/暂停、进度和静音，公共预览弹窗提供全屏、关闭和重新授权下载原件。播放器释放后删除/撤销源；平台创建失败或挂起时限制清理等待，晚到资源也被退休。
- `UtenFileColors.folderOf` 统一资料库目录图标、三种视图、详情、拖动、导航、面包屑、移动目标和空态的黄色。主题浅色 `#E5AD32`，深色 `#FFCC57`。其他按钮保持原有主题色。
- 后续按用户要求，“已选文件”改为公共 `AttachmentKindIcon` 与文件名的紧凑列表，删除上传访问弹窗顶部整段提示并清理死翻译键；权限区原说明保留。覆盖桌面、360px/200% 和横屏/200% 场景。

单文件仍采用服务端配置，默认 25 MiB；完整原件读取后播放。未新增大文件分片上传、Range 流播放、服务端转码、CDR/CAD/模型渲染或在线 Office 编辑。应用异常退出可能留下操作系统临时副本，正常关闭/撤权/解析失败路径执行主动清理；本次不是操作系统加密缓存或崩溃清理的完整验收。

## 公共入口、完整调用清单与差异

| 既有入口与比较 | 公共入口及迁移调用方 | 清理与保留差异 |
| --- | --- | --- |
| 页面选择/拖入按普通附件白名单拒收，粘贴有另一份 MIME 兜底 | `companyFileUploadContentType`；`CompanyFilesPage._uploadFiles`（选择/拖入）、`_pasteFileCopy` | 删除页面私有类型拒绝和粘贴独立兜底；普通单据附件继续用 `guessAttachmentContentType` |
| 附件图标、预览资格和公共弹窗共用原能力表，未登记媒体 | `attachment_file_rules.dart` 的媒体能力表、`AttachmentMediaPreview`、`AttachmentMediaSource` | 资料库和 `AttachmentSection` 均经同一公共预览弹窗；无另一播放器；媒体上传仅资料库放行 |
| 上传、原始 PUT、确认及服务端内容检查 | `AttachmentService.validateUpload` / `AttachmentContentInspector.inspectForOwner` | 不透明资料只做有界读取/摘要与原有扫描，不调用格式解析；已知类型保留后缀/内容检查；普通业务原件不放宽 |
| 文件发布与重命名的后缀一致性 | `CompanyFileService.requireSameFileExtension` | 无后缀与无后缀允许；增删/改变格式后缀仍拒绝；不可变原件语义保留 |
| 文件夹图标在浏览器、导航和选择器使用主题主色 | `UtenFileColors.folderOf`；`CompanyFileIcon`、导航、面包屑、移动选择器与空文件夹提示 | 文件夹专色集中维护；`UtenEmpty.iconColor` 可选参数，其他模块默认行为不变 |
| 五份 Nginx 应用 CSP 缺少 Blob 媒体许可 | 三份 `deploy/nginx` 模板、cloud 模板、remote-access 公司模板均允许 `media-src 'self' blob:` | 不放宽脚本/对象/网络来源；未修改现役服务器配置 |

公共预览的原有两处生产调用方：公司资料库 `CompanyFilesPage._readFile`、普通业务 `AttachmentSection`。二者继续使用原下载授权和 `SensitiveContentBoundary`，媒体组件被边界移除时清理资源。业务附件无媒体上传入口，但历史媒体仍可复用预览。播放器全屏用稳定 GlobalKey 维护同一资源身份。

## 开源选择

采用 [Flutter video_player](https://pub.dev/packages/video_player) 与 [video_player_win](https://pub.dev/packages/video_player_win)，锁定 2.14.1 / 3.3.1，均 BSD-3-Clause。Windows 插件使用系统 Media Foundation，依赖设备自带解码器；不自动安装额外编码包。媒体登记覆盖 MP4/M4V、WebM、MOV、MP3、WAV、OGG/OGA；容器可上传不保证编码能播放。

Office 沿用现有隔离 [LibreOffice worker](../../deploy/company-files/PREVIEW_WORKER.zh-CN.md)。[ONLYOFFICE](https://www.onlyoffice.com/compare-editions) 和 [Collabora](https://www.collaboraonline.com/faqs/) 是额外文档服务，当前需求不必引入在线编辑服务。[kkFileView](https://github.com/kekingcn/kkFileView) 可作后续评估，但其 [CAD 依赖](https://github.com/kekingcn/kkFileView/blob/master/server/pom.xml) 含 Aspose，不能只据项目开源许可宣称所有底层格式开源。[libcdr](https://github.com/LibreOffice/libcdr/blob/master/README) 可解析部分 CDR，后续需用真实版本/字体/版式样本验证，不据此承诺通用 CDR 预览。
