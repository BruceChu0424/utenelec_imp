# V566 销售无仓提交与仓库实仓拣货

本迁移是共享工作树中的源码候选，尚未更新现有业务库。必须与本次销售/仓库前后端一起发布；隔离 PostgreSQL 的测试不能代替目标库安装回执。

## 业务边界

销售新建出货时可以只确认客户、产品、来源订单行、数量及商业信息。财务确认通过后，仓库在“开始拣货”时明确选择实际叶仓、核对各行实际库位。候选仓按现有库存、安全库存、其它硬预留及在拣任务扣减；订单出货还须有该订单行在所选仓可兑现的精确预留。库存不足的候选显示差额，但不能开始拣货。

全局预留以整个库存池的可兑现上限校验，不在每个叶仓重复扣一遍。实际拣货取全局预算与本仓预算的较小值，再逐个订单行验证来源额度；同货品的另一订单行有余量，也不能掩盖当前行的来源仓不符。销售安全库存继续沿原销售预留与出库规则按有货叶仓计算，未改变生产主仓汇总预算政策。库存 SQL 使用 `numeric` 计算，避免旧货品安全库存浮点字段将整个表达式转换成浮点数。

仓库岗位没有销售订单详情权限时，仍从已授权出货单的持久化行 UUID 计算真实可发量；不从已经屏蔽来源字段的销售显示 DTO 猜预算，也不向仓库响应暴露被屏蔽的订单身份。

从产品进度批量开单时，服务端可以按真实来源预留分仓形成多张单仓草稿，销售无需猜仓。每张单据仍独立经过财务放行、仓库拣货与最终交接。整单齐套发运策略、历史订单激活、实际成本、应收确认和退货反向沿既有流程处理。

## 数据与历史

- `sales_shipments.warehouse_chosen_at_pick` 默认为 `false`，已选仓旧单据保持原冻结快照合同。现行两审流程中尚未拣货且仓库本来为空的有效草稿可前向启用该模式，其已冻结仓字段本来也是 `null`，商业内容与哈希不变。新建未传仓库或内部精确分仓建议使用 `true`，该模式不可中途修改。
- 该模式的商业快照将仓库固定表示为 `null`，财务确认的是本次商业内容。仓库明确开始拣货时才写 `warehouse_id`；实际库存、订单预留消费、销售出库流水、成本和反向仍使用这个唯一真实仓字段。
- `sales_shipment_warehouse_events` 追加实际 `warehouse_id`、`review_revision` 和按精确出货行 UUID 键控的 `line_stock_places`。现有追加式事件保留原字节，不补造历史库位。
- 实际库位是仓库人员确认的文本；目前没有独立的库位 UUID 主档，不能以可变文本充当库存外键。允许空文本表达未设固定库位，货品当前 `stock_place` 仅作输入提示。
- 数据库约束要求新模式填仓发生在财务已放行的 `PENDING_PICK → PICKING`，并有同仓、同审核版本、同办理人和时间的不可变事件证明。开始拣货后不能直接换仓；异常须先退拣。已交接出库的仓库事实继续冻结。

`fn_customer_shipment_commercial_snapshot_before_v566` 保留原快照函数；新函数只对新模式固定商业仓字段，原模式输出完全沿用原函数。没有重写历史提交、财审决定、库存流水、成本或应收。

## 接口与验证

`POST /api/warehouse/sales-outbound/{id}/warehouse-work` 在 `targetStatus=PICKING` 时接受 `warehouseId` 和 `stockPlaces:[{shipmentItemId,stockPlace}]`。其它状态转换不能携带新仓或新库位。服务端再次验证实际库存、精确订单来源、状态、财务许可及行归属；预览不会锁库存、创建预留或自动出库。

仓库详情返回 `canSelectWarehouse`、`warehouseOptions`，每个候选含 `canFulfill` 及按行单位表示的 `requiredQty/availableQty`；行另含 `actualStockPlace`，与当前主档提示分开。(V631 起改为逐行 `warehouseChoices/suggestedWarehouseId/warehouseId`，整单级两字段退役，见 [221](221-V631出货明细按行记实际发出仓.md)。)

回归入口为 `SalesShipmentWarehouseAssignmentEndToEndTest`：验证千件订单只开十件无仓出货、财审前禁止拣货、错误实际仓事务回滚、实际仓与库位留痕、财审快照不漂移、交接后库存和订单量正确；另验客户免费发货无仓提交与空库位不产生应收。实际执行结果见测试报告，不以源码存在代替通过。

本地最终定向证据：`server/target-flex-warehouse-r3.log` 中 5 项通过，覆盖普通订单出货、免费发货、无仓编辑保留内部建议仓、旧财审仓保护、全局预留与小数量；`server/target-flex-warehouse-r4-exact-source.log` 中追加的同货品不同订单行实仓来源负例 1 项通过。两轮均以隔离 PostgreSQL 完整重放 525 项迁移至 V567，合计 6 个不同场景，不将重复启动或迁移次数当作额外业务场景。
