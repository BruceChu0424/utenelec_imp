# 235 - V692 热表延迟约束触发器按相关列起跳(补齐 V646/V690)

- SQL: `V692__hot_table_deferred_trigger_when_gates.sql`
- 决策: [ADR-106](../99-决策记录-ADR/ADR-106-热表触发器按相关列起跳与索引卫生.md)(热表延迟约束触发器的 UPDATE 路径必须带 WHEN)

## 为什么

ADR-106/V674 规定: 热表上的 DEFERRABLE 约束触发器对 UPDATE 起跳时必须带 WHEN, 只有相关列真的变了才排队到提交时校验。JPA 与整行更新会把所有列写进 SET, 只写 `UPDATE OF` 挡不住无关更新。V646(委外子件精确库存交接)和 V690(车间公共备货报工)各新增了不带 WHEN 的 UPDATE 路径, 被 `HotTableTriggerHygieneContractTest` 拒绝。V646 已发布到服务器, 不能改字节, 所以统一在 V692 重建。

## 改了什么(只重建触发器, 函数与校验语义不变)

| 表 | 触发器 | 改法 |
|---|---|---|
| stock_reservations | trg_component_handoff_target_balance | INSERT 保留原名; UPDATE 拆为 `_upd`, WHEN qty / released_qty / is_deleted 变化 |
| stock_document_items | trg_assert_finished_in_segment_public_fact | INSERT OR DELETE 保留原名; UPDATE 拆为 `_upd`, WHEN 执行段 / 销售分配 / qty / doc_id / is_deleted 变化 |
| stock_documents | trg_assert_stock_document_segment_public_status | 加 WHEN status / is_deleted / doc_type 变化 |
| production_execution_segments | trg_assert_execution_segment_public_capacity_change | 加 WHEN planned_qty 变化 |

四个触发器原本都不是 ENABLE ALWAYS, 重建后保持默认。不加表, 清库分类与审计三清单不变; 迁移头 V692 / 621。
