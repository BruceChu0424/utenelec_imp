# AI 上下文识别与使用审计

## 需求与实现边界

- 文件先看标题、表头、各工作表内容，再结合用户明确用途、当前授权页面和真实部门辅助路由。部门提示不是授权依据。
- 复现依据是仓库 `sales-intake/matching-fixture.json` 的 SUNAS 合成资料：`Commercial Invoice` 标题与正文 `Quotation base on EX-WORK` 条款会被旧全局关键词规则判成混合业务。本次未取得截图中的原始 Excel，不能宣称已用该原件验收。
- 当前页面问题由服务器授权目录产生，窗口打开或切页动态更新；保持历史，关闭页面关联则停止上下文建议。
- 图片或扫描件不能仅凭“合计金额”自动当报销发票。销售用途/偏好且未明确报销时跳过报销 OCR；缺乏可靠票据信息时供用户选择用途。明确要报销时可保留部分建议，但仍列缺项并由本人核对保存。
- 工作聊天不提供娱乐、个人闲聊和平台外通用问答；回复仍由本地授权知识/业务工具生成，模型只路由，不自由返回数据。
- 系统设置中的 AI 使用审计记录接受的提问、用途、使用人、状态和费用。原始系统提示词、原文件内容、API 密钥不进入问题预览；识别出的凭据脱敏。只有真实超管加系统授权管理权限可查看跨员工审计。
- 每次重试属于实际调用记录；纯本地页面帮助也有使用记录，但调用模型为零。缺失 token 或缺少价格显示未知，不能作为零费用。
- 费用按币种分别汇总。当前金额来自管理员设置的单价估算，调用起点冻结模型与价格，不等于供应商扣费账单，也不统计此平台之外的使用。

当前接入为普通 API Key 协议，并未接某家服务商的套餐额度接口。五小时与每周余额显示“暂未接入”，不根据本地 token 推算。后续需要服务商、套餐类型及其公开查询接口，不能把当前 Codex 账号的额度当成 ERP 服务账号额度。
