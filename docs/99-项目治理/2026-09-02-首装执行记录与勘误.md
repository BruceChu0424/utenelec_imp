## 二、文档/仓库勘误（现场踩坑实录，共 7 项）

1. **OSS 拉取 403（脚本 bug，已修）**：`uten-imp-updater.sh` 的 `oss_get()` 把 V1 签名放 URL
   查询参数；**开启版本控制的桶不支持这种方式**，一律 `SignatureDoesNotMatch`。改为
   `Authorization` 请求头携带签名后正常。修复已回带仓库脚本。
2. **server.env 模板正则未加引号（已修）**：`UTEN_TRUSTED_PROXY_REGEX=127[.].*|::1` 的 `|`
   被 shell 解析为管道，source 即报 `::1: command not found`。模板已改为整体单引号。
3. **releases 目录属主（已修）**：updater 解压后目录 root:700，服务账号 `uten-imp` 与
   nginx（www-data，已加入 uten-imp 组）都无法读取。updater 现在暂存完成后
   `chown root:uten-imp` + `chmod g+rX`。修复已回带。
4. **"internal-test" 安全闸与内网 HTTP 模板互相矛盾（部署侧绕过）**：
   `InternalTestRuntimeSafetyGate` 强制 CORS 必须是 HTTPS 源且 `require-https=true`；
   `prod/cloud` profile 又强制附件存储必须 OSS。内网本地磁盘 + 自签 HTTPS 的现实组合下，
   当前可用 profile 是 `dev`（env 已显式收紧：swagger off、sms disabled、require-https=true）。
   **根因是第 6 条**：前端登录必须 WebCrypto（安全上下文），因此 HTTPS 是硬需求——
   文档原来的"内网 HTTP"路线不可行。
5. **systemd 单元缺 ReadWritePaths（已修）**：`ProtectSystem=strict` 且无白名单，附件目录
   `/data/uten-imp/attachments` 与日志目录 `/var/log/uten-imp` 均不可写。已补
   `ReadWritePaths=` 并回带仓库 unit。
6. **CSP 拦 Flutter Web（已修）**：`style-src 'self'` 拦掉 Flutter 运行时内联样式，
   界面渲染异常。已加 `'unsafe-inline'`（仅样式）并回带 nginx 模板。
7. **Nginx CSP/HTTP 模板整体升级为"内部 CA + HTTPS"**：80 端口只保留根 CA 下载 + 301 跳转；
   443 提供全部服务；模板见 `deploy/nginx/uten-imp-http-lan.conf`。

### 其他现场修正（非 bug，属环境事实）

- 办公网段实测为 **192.168.0.0/23**（不是文档示例的 /24），Nginx allow 已按实际网段。
- 迁移专用账号：migrator 硬编码使用 `uten_migrator` + `UTEN_MIGRATOR_DB_PASSWORD`
  （纯字母数字 ≥20 位），与指引"复制 server.env 同账号即可"不符。
- `pgcrypto` 扩展需超级用户预建并 `ALTER EXTENSION ... OWNER` 交给 uten_migrator（V01）。
- 迁移刻意不加 GRANT：需手工授权（表/序列 SELECT/INSERT/UPDATE/DELETE 给 `uten`，
  并 `ALTER DEFAULT PRIVILEGES FOR ROLE uten_migrator`）；物化视图刷新还需
  `GRANT uten_migrator TO uten`（属主角色成员才可 REFRESH）。
- `mysql` 无关；`uten-app` 建库账号指引有误，实际应用账号 `uten`（8.11 旧装遗留角色已清理，
  旧库删除前 pg_dump 因目录权限失败未能留档——经维护者确认数据可弃）。

## 七、数据备份设计（2026-09-03 补充，已实施）

简化链原有备份仅"发版含迁移时自动 pg_dump"一种，已补齐周期备份：

| 层 | 机制 | 位置 | 保留 |
|---|---|---|---|
| 日常自动备份 | `uten-backup.timer` 每日 01:30 → `uten-backup-daily`（pg_dump -Fc 全量 + 附件 rsync） | `/data/uten-imp-backups/pg/`（RAID1，与系统盘物理分离） | **只留最新 1 份**（维护者要求，新备份成功后自动删旧；脚本 `KEEP=1` 可调） |
| 发版迁移备份 | updater activate 自动 pg_dump | `/var/backups/uten-imp/` | 随发版保留 |
| 恢复方式 | `pg_restore -d <库> --no-owner <dump>`（已实测：349 表+账号完整还原） | RUNBOOK 第五节 | — |
| 附带巡检 | 备份脚本内置 RAID1 双盘 UP 检查 + /data 水位 85% 告警（写入 journal） | `journalctl -t uten-backup` | — |

组件：`deploy/simple/uten-backup-daily.sh` + `units/uten-backup.{service,timer}`（服务器已装，
`systemctl is-enabled uten-backup.timer` = enabled）。

**边界说明**：备份与数据库同机（RAID1 双盘冗余），可防误删/坏文件/应用故障，防不了机房级灾难；
ERP 为内网测试服务器，暂不异地。将来要异地时：把 `/data/uten-imp-backups` 目录纳入任意
离线同步（U 盘/家用 NAS via Tailscale）即可，dump 为自包含文件。

## 九、PII 密钥交接（2026-09-03，已处理）

现象：点开人事任一老员工报"服务器内部错误"（`pgp_sym_decrypt: Wrong key or corrupt data`）。
根因：142 名员工敏感字段是 8 月开发环境录入的（dev 钥匙），首装时服务器新生成了随机钥匙。

处理（未动任何数据，走代码原生密钥轮换机制）：
- `/etc/uten-imp/server.env`：`UTEN_PGP_KEY_VERSION=2`（新随机钥匙升为当前版），
  `UTEN_CRYPTO_PGPLEGACYKEYS_1=<8月dev钥匙>`（登记为历史版本 1，解老数据）；
- 旧钥匙来源：维护者 8 月的 `server/.env`（dev 值，值本身不写入任何文档）；
- `UTEN_HMAC_KEY` 同步切回 8 月 dev 值（已验证与存量 phone_hash 完全吻合；切换前确认
  新库启用后无新写入，切换无损），保证新老员工身份证/手机号查重统一；
- 验证：解密与指纹比对均在 SQL 内完成、未回显明文；重启零报错。

**维护者备忘**：将来正式换强钥匙时，把当前 v2 随机钥匙降级登记进 legacy、新钥匙升版本即可，
老数据无需迁移；dev 钥匙虽为弱值，内网测试环境可接受，公网/生产前必须轮换。


## 八、故障速查补充（在 RUNBOOK 第五节之上）

| 症状 | 原因/处理 |
|---|---|
| 浏览器"登录失败，请稍后重试"且后端无任何请求 | 页面非安全上下文（http 或证书告警放行），WebCrypto 不可用。确认地址是 `https://` 且根 CA 已导入 |
| updater 拉取 `SignatureDoesNotMatch` | 确认服务器脚本为 Authorization 头签名版（勘误 #1） |
| migrator `dedicated database credential is missing` | migrator.env 缺 `UTEN_MIGRATOR_DB_PASSWORD`（20+ 位字母数字） |
| migrator 建表 `permission denied for schema public` | 需在 `uten_imp` 库内授权（不是 postgres 库）：`GRANT USAGE,CREATE ON SCHEMA public TO uten_migrator` |
| 物化视图刷新失败 | `GRANT uten_migrator TO uten` 未执行 |
| web 静态 403/500 | releases 属主非 `root:uten-imp` 或 www-data 不在 uten-imp 组 |
