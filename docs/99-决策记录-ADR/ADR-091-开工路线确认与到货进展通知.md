## 一、问题

用户口径(2026-09-17)：

1. 「应该先让车间的人先确定路线，只有把路线确定了先，才好去卡流程、解锁啥的。」
2. 「你可以把待领料那里的下一步改成路线确认。」
3. 「仓库那里对应的物料都是分批到的……如果是部分开工，就要给对应的车间弹窗——中间的信息弹窗，
   某某物料到了 100 个，还差什么物料，或者物料已支持开工，去领料开工啥的。」

复核既有实现的真实缺口：

- 三条开工链（齐套 / 分批 ADR-078 / 持续 ADR-089）彼此独立成入口，**没有一个显式的「先选路」动作**：
  车间是靠「点了哪个按钮」事后表达路线，流程闸门无法按路线收敛，「下一步」列三四个动作并列、
  语义靠用户自己分辨。
- **齐套自动提升会替车间做决定**：物料一到 `tryPromote` 就建领料单、升 READY。仓库料先到齐时，
  段被升成 READY，`fn_can_split_execution_batch`（要求 WAITING）与 `fn_can_start_continuous_supply`
  的入口同时消失——车间想分批或持续生产已经晚了，这正是 V595 遗留的竞态。
- 到货唤醒(`MaterialAnalysisSupplyWakeupService`)只重算物料分析，**不告诉车间**：哪张工单的哪种料
  到了多少、还差多少、现在能干什么。车间只能自己刷页面碰运气。

## 二、决策

### 2.1 段上的开工路线（V599 三列 + 事件）

`production_execution_segments` 增加 `start_route`(`FULL_KIT`/`BATCH`/`CONTINUOUS`)、
`route_confirmed_at`；操作人记在事件账 `ROUTE_CONFIRMED`（复用 `created_by`，不另设冗余列）。

| 路线 | 含义 | 对应既有链 |
| --- | --- | --- |
| FULL_KIT 齐套生产 | 全部子件按需求量到齐→一次领料→开工 | ADR-077 齐套链（默认） |
| BATCH 分批生产 | 按可齐套上限拆子批，批批领料、批批生产 | ADR-078 分批谱系 |
| CONTINUOUS 持续生产 | 同车间直送子件到一批投一批，开一次工，数量最后算 | ADR-089 V595 |

- 新段 `start_route IS NULL`：**所有开工侧动作被服务端拒绝**（`start`/`batch-start`/
  `start-continuous`/领料申请 `draw-request/submit`/分批 `execution-batches/submit`，
  统一 409「请先确认生产路线」），「下一步」列只给一条 primary——「确认生产路线」。
- 确认端点 `POST /production/plans/{planId}/execution-segments/{segmentId}/confirm-route`：
  权限 `production_execution:view + start`，幂等/版本/事件记账与 start 同款。可选路线按段事实下发
  （FULL_KIT 恒可；BATCH 需有物料需求；CONTINUOUS 需至少一个可直送子件），服务端同口径校验。
- **改路线**：`fn_can_change_execution_route`——仅 WAITING 且「未动过」（无领料单、报工、正式预留、
  供给钉）允许重确认；一旦动过/离开 WAITING，路线冻结。取消/红冲不受路线影响。
- 确认 FULL_KIT 时若本已可齐套，就地在同一事务里补跑提升（等价人工「重新核对备料」），
  行为与旧自动提升对齐；BATCH/CONTINUOUS 确认本身不动库存。

### 2.2 齐套自动提升按路线放行（同时关闭 V595 竞态）

`tryPromote` 的段查询追加 `fn_execution_route_allows_auto_promote(segment.id)`：

- `FULL_KIT` → 放行（旧行为）；
- `BATCH` → 抑制：根段等车间来拆批，拆出的批次段/剩余段各走各的提升；
- `CONTINUOUS` 且 `continuous_supply` 尚未置位 → 抑制：保住 WAITING，让「部分开工 · 持续生产」
  入口不被仓库料先到顶掉；`start-continuous` 置位后仓库需求恢复自动提升（混合链 ADR-089 §2.1）；
- `start_route IS NULL` → 抑制：**系统不替车间选路**。确认 FULL_KIT 的那一刻补跑提升。

批次段/剩余段由 `ProductionExecutionBatchService.createChild` 落生即定：批次段 `FULL_KIT`（每一批
就是一次小齐套），剩余段继承 `BATCH`（继续等下一批）。`recheck-material` 收敛为 FULL_KIT 专用
（其语义就是齐套提升；BATCH/CONTINUOUS 的缺料视图分别由分批核对页与持续生产拒绝原因承担）。

### 2.3 到货进展通知（只挂在真实的库存增加事件上）

触发点：`MaterialAnalysisSupplyWakeupService.afterInspectionStockInConfirmed`（采购/委外 IQC
确认入库，含先入库后质检的自动转正）与 `afterFinishedInboundApproved`（非线边仓产成品入库）。
收货审核、红冲不触发——那时实物还不能用，通知就是假的。

对事件维度（仓 × 货品 × 颜色）命中的 **WAITING** 段（含未确认路线的），每段发一张聚合卡：

- 明细行：命中的子件「本次入库 N 件」+ 全部子件的「还差 X 件」清单（封顶 6 行，多的折叠成
  「等 M 种」）；
- 下一步提示按路线分流：未确认 → 「请先确认生产路线」；FULL_KIT → 缺口清单/「已齐套可领料开工」；
  BATCH → 「部分物料已到，可分批领料」；CONTINUOUS → 满足 `fn_can_start_continuous_supply` 时
  「直送料已到一部分，可部分开工 · 持续生产」；
- 受众与既有车间行动卡同源（车间树在编∪兼职∪班组长∪段负责人，过滤通知权限）；聚合键同为
  `(PRODUCTION_EXECUTION_SEGMENT, segmentId)`——一张工单同时最多一张活跃卡，开工/领料/分批/
  确认路线即办结，状态卡重发也会顶掉旧的进展卡，不会堆积。

### 2.4 存量适配（V599 回填）

- `continuous_supply=TRUE` 的段回填 `CONTINUOUS`；其余全部段（含 WAITING、含已拆批次段）回填
  `FULL_KIT`，`route_confirmed_at=now()`——升级后没有任何在途单被新门锁住；
- 老 WAITING 单想改分批/持续：仍在 WAITING 且未动过，走「重新确认生产路线」即可；
- 事件动作白名单追加 `ROUTE_CONFIRMED`（重建 CHECK 约束，V595 同款做法）。

## 三、每一种情况怎么走

| 情况 | 结果 |
| --- | --- |
| 未确认路线就点开工/领料/分批/持续生产 | 409「请先确认生产路线」；「下一步」只有「确认生产路线」 |
| 确认 FULL_KIT 且已可齐套 | 同事务补跑提升：建领料单、升 READY（与旧自动提升一致） |
| 确认 FULL_KIT 但仍缺料 | 维持 WAITING 等到货；到货进展卡按 §2.3 推送 |
| 确认 BATCH | 根段不再被自动提升；到部分料后分批核对页拆批；批次段即 FULL_KIT |
| 确认 CONTINUOUS 但未开工 | 段保持 WAITING；直送子件到一部分后「部分开工 · 持续生产」可用 |
| 已有领料单/报工/预留后想改路线 | 409：路线已冻结（与 ADR-078「未动过才可拆」同一把尺） |
| 零物料段（无子件） | 只有 FULL_KIT 可选（BATCH/CONTINUOUS 无意义，入口与服务端同口径拒绝） |
| 分批拆出的批次段 | 落生即 FULL_KIT 已确认，开工/领料不受新门影响 |
| 仓库把料发完(issued)后 | 开工仍要求 FULL_KIT 已确认（issued 的段回填后本就 FULL_KIT） |
| 到货的是别的工单的料 | 不命中该段需求维度，不发卡 |
| IQC 拒收/红冲 | 不发通知（可用量没有真实增加）；已有缺口清单在下一次真实到货时更新 |
| 段取消/红冲/完工 | 路线随段终结；卡按既有办结点撤回 |

## 四、明确不做

| 不做 | 理由 |
| --- | --- |
| 仓库供给物料的部分到料直接开工（不拆批） | ADR-089 §三已有结论：那要把 V249 守恒守卫整体放宽，
  风险面扩到所有工单；分批谱系(ADR-078)已完整覆盖该诉求 |
| 路线确认做成独立页面 | 弹窗三选一足够（与持续生产确认同款）；不新增路由/权限面 |
| 新权限码 | 确认路线的人就是能开工/能提交领料的人，同门槛即可 |
| 到货预测/在途 ETA 提醒 | 本轮只做「事实发生」的通知；预测属采购跟单域 |

## 五、验证

- 服务端：`ProductionExecutionRouteGateEndToEndTest`(真实 PG)——未确认全动作 409、确认 FULL_KIT
  就地提升、BATCH 抑制自动提升、CONTINUOUS 竞态关闭（仓库料先到不再顶掉持续生产入口）、
  改路线守卫、零料段、批次段落生即 FULL_KIT；既有 start/draw/batch/continuous 全链测试补
  「先确认路线」步骤后全绿。
- 到货通知：`ProductionExecutionRouteGateEndToEndTest.arrivalProgressCardFollowsTheWaitingSegmentFacts`
  ——outbox 事件、按当时事实重组卡片、不在等待不重复发、人工 OTHER_IN 不误触发。
- Flutter：车间任务页「确认生产路线」下拉首条 + 三选一弹窗 + 路线过滤后的下一步清单。
- 迁移在开发库克隆上单独执行：回填断言、CHECK 约束、函数、事件白名单、既有段完整性。

## 六、2026-09-17 对抗式审计后的加固（同批落地）

- **outbox 去重键改指纹**：触发单据集合裸拼 UUID 在批量入库/批量质检处置 ≥5 单时超过
  `business_outbox.dedupe_key VARCHAR(240)`，会把整笔入库事务炸掉——改用 SHA-256 摘要前 32 位。
- **FIN 单张审核也发到货进展**：原先只挂批量点收，单张审核漏发；两入口统一。
- **两个索引**：`production_material_demands(goods_id)`（到货命中查询）与
  `production_planning_package_document_items(demand_id)`（缺口反查领料行）。
- **派工补路线门（防御性）**：dispatch 与开工同口径要求已确认路线——下达即齐套的段
  (CompleteKitAllocator 直建 READY)同样先确认再走开工侧动作；`canConfirmRoute` 相应放宽到
  WAITING/READY/DISPATCHED 的未确认段。
- 审计确认无缺口的面：IQC 拒收/部分合格/先入库后质检不进任何缺口与上限口径；路线门抑制期间
  分析权益滞留但不丢（三条路线解除后均可补跑）；收货红冲对 CONTINUOUS/BATCH 段 fail-closed；
  confirmRoute 幂等/版本/并发/事务性正确；多卡顶替与超管受众口径正确。

## 七、已知边界（后续单独排期，本轮不做）

| 边界 | 说明 |
| --- | --- |
| 直送撤回的补偿引导 | 父段已消耗时需按「父段领料退 → 入库红冲 → 报工红冲」顺序人工反向，系统只 fail-closed 拒绝、无引导清单 |
| 撤回后线边仓余料 | `fn_line_side_stock_targets_demand` 要求 reversal_id IS NULL，未投完的余料不指向任何需求也不进公共量，需人工调拨出线边仓 |
| 收货红冲不撤到货进展卡 | 旧卡内容过时但 normal 级，下一次到货/状态变化会全撤重发 |
