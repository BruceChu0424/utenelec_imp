# Legacy Series Content Repair

This document records how series names from old crawl artifacts are corrected without changing business ownership or source evidence.

## Why repair was needed

- Legacy list pages used shortened/truncated category labels.
- Detail pages contain a fuller breadcrumb (`div.rtop`) that is cleaner and more reliable.
- A direct migration from UI text caused title pollution in 50+ Chinese records and dozens of English typo variants.

## Repair principle

1. Keep source identity immutable (`ch-uten-v2:series:<legacyId>`).
2. Keep raw payload/hash/source trail untouched.
3. Repair only:
   - `Series.i18n` display labels
   - `Series.rowVersion` for conflict detection
4. Do not rewrite product ownership, media references, publication flags, or URLs.

## Detection evidence

The repair uses:

- `(locale, sortId)` paired from detail breadcrumb
- raw payload hash continuity
- explicit reviewed mapping file generated by repair command

If any identity/hash mismatch occurs, the record is blocked and reported.

## Commands

Dry run:

```bash
npm run catalog:repair-content -- --report D:\audit\legacy-series-content-plan.json
```

Apply:

```powershell
$env:UTEN_LEGACY_SERIES_CONTENT_CONFIRM='APPLY_REVIEWED_LEGACY_SERIES_CONTENT'
npm run catalog:repair-content:apply -- --report D:\audit\legacy-series-content-plan.json --backup-dir D:\backups\legacy-series-content
```

## Safety notes

- Always run on a copied DB for testing.
- Production apply is one transaction with row-version check.
- Re-applying after success should return `already-clean`.
- Never run before taking a full database/media backup.

## Rollback

Use the generated backup file. Restore according to your normal operation procedure.
Do not use in-place `VACUUM` on a live write database.
