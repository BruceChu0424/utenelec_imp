## 1. 业务定位

销售订单审核只形成订单有效预留，不等于仓库已备货。新流程按以下边界推进：

`订单财务确认 → 出货草稿 PENDING_PICK → 出货财务放行 →（仓库确认出库）→ SHIPPED`

- 出货草稿占用订单行可发额度，防止多人重复建立任务；不二次扣 ATP，不扣在手。
- 月结、现金、定金客户在仓库确认出库前都必须逐张由财务人工放行；三类标签只辅助判断，不能自动放行，标签为空时须先回客户资料分类。该财务审核只记录“允许发货”的人和时间，不填写汇率，也不生成收款、本币、库存、正式 AR 或总账。
- 确认出库是实物分配边界：同一事务里先证明所选仓真的发得出（扣安全库存与其它订单硬预留），再扣账。校验与扣账共用同一批 goods/color 互斥锁，并发的第二张单排队后按已扣减的余额重算，不存在「两边都校验通过再一起扣」的窗口。
- 确认出库落到 `SHIPPED` 才锁定财务开账汇率，并在同一事务消费预留、扣库存、回写销售订单、形成本次发运本币快照和唯一正式 AR；AR 立账日、账龄和到期日从该次上海业务日起算，不使用草稿 `bill_date`。部分交接只把本次消耗段绑定该仓，未发余量仍可由其他仓履约。汇率、库存、预留、来源或 AR 任一校验失败时全部回滚。
- 无订单的零星出库使用“其它出货”，销售出货不允许手工混入无来源行。
- 客户、币种、税率、付款方式、销售员和行价格/折扣/原币金额由服务端从来源订单重建；订单只保留币种与原币商业事实，`SHIPPED` 时再锁定财务有效汇率，按本次发运原币额计算本币并冻结为 AR 开账汇率。客户端汇率、金额或成本不是商业或会计权威。订单脱汇率源码已对齐且本地定向回归通过，仍须完成目标环境全链、数据与约束核验及岗位 UAT，不能把源码和本地测试视为生产已放行。
- V188 每次状态转换在同事务追加仓库事件；当前状态用于页面，事件账用于追溯，已接受事件不可修改或删除。

## 2. 页面显示

详情表头显示发运/仓库状态、最近作业时间与出库时间。状态文案必须来自服务端字段，不从按钮点击或本地缓存推断。

财务专页/受限详情本轮只显示打开页面时的**当前客户风险投影**，它会随 AR 收款、预收转销和客户主档变化。后台 `sales_shipment_finance_release_events` 的 `RELEASED/REVOKED` 快照冻结当时客户、币种、本次出货原币合计、结算 UUID、正式未收、铺底/超铺底和同币种可用预收，供审计中心/数据库对账；`SHIPPED` 前没有本次出货开账本币，不显示伪本币。本轮没有业务时间线查询端点或 UI，不能把后台事件表写成已交付页面功能。

| 状态 | 页面动作 | 服务端约束 |
|---|---|---|
| `PENDING_PICK` | 财务先审核；通过后仓库「确认出库」（选填出库备注） | 复核订单来源、发运策略、客户已分类、全客户财务审核与本仓可发量；确认须二次确认；库存、预留、订单、应收同事务 |
| `SHIPPED` | 只读；从来源关系走销售退货 | 无论是否有 `handedOverAt` 都隐藏并拒绝普通红冲；历史缺时间只表示证据未知，不表示未出库 |
| `LEGACY_PENDING` | 只读显示迁移异常与重建指引 | 不提供旧审核、财审、仓库动作或原位升级；对账后从当前已财务确认订单逐行重建版本 1 两审任务，原草稿留证 |
| `CANCELLED/REVERSED` | 只读 | 保留历史，不提供假动作 |

异步提交期间动作按钮禁用并显示进行中状态；成功后使用服务端返回详情刷新。409/403/400 必须显示具体冲突、无权或校验原因，不能静默返回列表或停留在假成功状态。

## 3. 权限与对象范围

### 销售选货与仓库确认实际位置

订单进度和订单详情的产品表支持多选、填写本次可发数量，去发货打开预填客户、订单行、产品和数量的新建页。销售出货的新建、编辑、引入和详情不要求选择或展示内部仓库/库位。服务端按精确订单行、有效预留及安全库存核对可发量，兼容同次请求的多个实际来源时返回全部真实草稿；重试同一意图不重复建单，附件按实际回执的出货UUID绑定。

财审放行后，仓库单张详情与批量核对页显示可选实际叶仓、逐产品可用量和实际库位。确认出库时提交所选仓及逐行位置，服务端在同一事务再次核对库存和来源；建议库位与已确认实际库位分开，切换仓库清空旧的未确认输入，没有固定库位时允许留空。仓库事件保留真实位置及复核版本，不能把销售未选仓解释成任意仓都可发。

新无仓出货的商业财审快照保留原无仓口径，仓库补仓不改写该快照；既有明确指定仓的旧单保留原约束。实际总重量和物流件数不能在自动多单时复制多份，按各单实际值补填。实现与历史兼容见[162](../数据迁移/162-V566销售无仓提交与仓库实仓拣货.md)、[163](../数据迁移/163-V567销售批量出货来源与幂等身份.md)。

| 能力 | 权限 | 额外范围 |
|---|---|---|
| 查看出货 | `sales_shipment:view` | 销售归属/委派范围；仓库、财务特殊动作权限仅扩大其必要读取范围 |
| 建立/编辑销售出货 | `sales_shipment:edit` | 必须能写来源订单归属；新流程逐行带订单行 |
| 仓库作业 | `sales_shipment:warehouse-work` | 进入 `/warehouse/sales-outbound` 专页，只能确认出库；不能财务审核。服务端仍校验出货归属对象范围；默认授仓储部 |
| 仓库驳回并释放订单预留 | `sales_shipment:reject` | 仅版本 1 `PENDING_PICK` 当前草稿；`LEGACY_PENDING` 只读，已出库不可驳回 |
| 财务审核/反审 | `finance_shipment_audit` | 进入 `/finance/sales-shipment-audits` 专页及受限共享详情并查看必要商业信息；不能新建、编辑、删除、驳回或推进仓库状态。财务已审单在反审前不可编辑、删除或驳回；仓库确认出库后反审被拒绝 |
| 客户分批确认 | `sales_order:confirm_partial_shipment` | 同时满足订单正常写范围；特殊动作权限不自动变成全销售跨归属权限 |
| 查看价格/商业条件 | `sales_order:price:view` 或财务授权 | 无权时服务端把表头金额/币税/付款条件及行价格/成本字段置空，不靠页面遮盖 |

两个精确 surface/动作权限须在权限设置页分别出现并独立授权：`finance.sales-shipment-audit` 只含 `finance_shipment_audit`，`warehouse.sales-outbound` 只含 `sales_shipment:warehouse-work`。V443 不新增任何默认 grant；财务审核不能推导仓库执行权，仓库执行权也不能推导财务审核。页面显隐只改善体验，服务端 `@PreAuthorize`、对象范围和状态机才是权威。无权深链进入统一拒绝页，不得静默跳工作台首页。

财务审核弹窗中的“正式 AR 未收”只汇总正式应收；尚未转销的客户预收必须单列，不得用其负余额净掉正式 AR。铺底额不冲减 AR，`超出铺底额=正式 AR 未收-铺底额` 保留负数。

## 4. 接口

```text
POST /api/sales/orders/{id}/partial-shipment-confirmation
body: { confirmed: true|false, reason: "联系人/渠道/决定依据" }

POST /api/sales/shipments/{id}/warehouse-work
body: { targetStatus: "SHIPPED", reason: "出库备注(选填)",
        warehouseId: "实际发货仓(无仓提交时必填)",
        stockPlaces: [ { shipmentItemId, stockPlace } ] }

POST /api/sales/shipments/{id}/finance-audit
POST /api/sales/shipments/{id}/finance-audit-reverse
```

客户端不能传任意状态：`targetStatus` 只接受 `SHIPPED`，已退役的 `PICKING`/`PICKED`/`EXCEPTION` 一律 fail-closed 拒绝（不做静默兼容，否则老前端或重放脚本会绕过整套可发量与来源承诺校验）。重复提交、陈旧状态、仓库库存不足、预留错仓、客户未确认或财务未放行均返回失败且事务不产生部分副作用。

V90 历史 `chain_status=0` 且没有有效预留的旧未结订单，必须在**新建 V187 出货时**提前拒绝，不能拖到确认出库才报错。业务人员须按订单逐行对账库存、历史已发数量和旧排产后显式激活；当前没有自动批量激活，也不得用迁移脚本伪造历史预留。V187 迁移前已存在的 `LEGACY_PENDING` 出货草稿在 V443 起全部只读，不得走旧审核；需从当前订单来源重建新任务。

## 5. 明确未覆盖

- 库位、批次/序列号、效期、实拣数量、替代批次与分批出库（销售出货一次整单发运、一次立唯一正式 AR；需要分批时由销售拆成多张出货单）；
- 二人复核、装箱、箱码、称重、承运商/运单/多件交接；
- 一张出货单跨多仓与仓间调拨任务；
- V189 已提供销售退货最小冻结与 `GOOD_RELEASE/SCRAP/REWORK`；完整检验项目、批次、特采、召回、返工工单和报废财务仍未覆盖；
- 扫码设备、离线作业和仓库级对象范围。
- 正式价目、折扣/税额最终结算、多次分批舍入尾差归集和开票 condition engine。
- 财审风险事件的业务时间线查询 endpoint/UI；当前只在后台事件表、通用审计和数据库验收中核对。

这些能力落地前，本页只能称“单据级最小仓库状态”，不能称完整 WMS。

## 6. 人工验收清单

1. 同一订单行两账号并发建任务，总量不超过订单有效预留。
2. 月结、现金、定金各建一张出货：未财务审核时确认出库都失败，审核后成功；未分类客户财审失败；确认出库后财务反审失败。
3. 一个现货、一个长周期产品分别验证三种发运策略。
4. 指定仓不足、安全库存保护、其它订单预留和另一在拣任务均能阻断。
5. 已 `SHIPPED` 下编辑、删除、驳回、让单、订单改量/取消都失败；老客户端发 `PICKING`/`PICKED`/`EXCEPTION` 被明确拒绝而不是静默兼容。
6. 跳过状态、重复确认出库、以及确认失败后残留占用/半条事件均不允许（失败=整事务回滚，连拣货占用都不留）。
7. 确认出库失败时库存、预留、订单已发量、应收全部不变；成功时四者同事务变化，并以 `SHIPPED` 上海业务日立且只立一笔正式 AR、从该日计算到期日。
8. 所有 `SHIPPED`（含历史缺 `handedOverAt`）都没有普通红冲入口且接口拒绝；纠错走 V189 退货冻结。
9. 客户端伪造价格/金额/币税条件不生效；不同商业条件不能错误合单；财务已审单编辑、删除、驳回失败；无价格权账号响应不含商业字段。
10. 确认出库事件（含实际仓与逐行库位证据）可按时间线查询，数据库 UPDATE/DELETE V188 事件失败；历史 `PICKING/PICKED/EXCEPTION` 事件行原样保留。
11. V90 未激活订单新建出货提前失败；对账显式激活前不能生成作业；既有 `LEGACY_PENDING` 草稿没有旧审核/财审/仓库动作，只能留证并人工重建；活动 legacy `PENDING_PICK` 不允许以 gate v0 绕过财审。
12. 客户有未转销预收时，财务审核弹窗仍保持正式 AR 未收原值并另列同币种可用预收；预收转销审核后才冲减正式 AR，铺底差值全程不截零。
13. 通过数据库/审计证据验证：财审放行同事务新增一条 `RELEASED` 快照并冻结本次出货原币合计；反审保留原事件并新增 `REVOKED`。事件不出现伪造的出货本币；直接 UPDATE/DELETE 失败；事务末端失败时财审状态、事件和同事务 Outbox 通知命令均回滚，实际异步投递继续按 Outbox 重试；历史单不出现伪造事件。反审后改明细须能由通用审计重建，不把事件表误当行级快照。不得因页面尚无时间线就跳过该验收。
