# ADR-047：采购/委外应付、月结、付款与超耗责任分层

- 日期：2026-08-22
- 状态：已接受（共享工作树源码候选；目标库、岗位 UAT 与发布仍 NO-GO）
- 影响：采购、委外、IQC、应付台账、付款、对账、总账、权限、审计、Flutter 财务工作台
- 迁移：V330、V332–V334、V336、V339–V342、V360–V378（中间版本由并行生产链占用）

## 背景

系统已有“收货/回厂审核立 AP、付款单核销 AP、退货/损耗负 AP、总账和报表”的骨架，
但存在外币 AP 把本币当原币、到期日不计算、应付汇总把付款重复当冲销、未来付款污染历史
截止日、采购与委外混列、仓库损耗单直接决定扣款、贷项/预付无应用事实等缺口。

采购与委外不是同一实物流：

- 采购是外购物料/商品进入企业；
- 委外是企业自有材料移到加工商处保管并被加工，加工商只形成加工服务应付；
- 自有材料发给加工商不产生 AP，也不是销售出库。

## 决策

### 1. 四条账分开

1. 实物/在制账：采购收货、IQC、退货；委外发料、消费、余料退回、损耗、补料、供应商结存。
2. 成本账：采购存货成本；委外自有材料成本、加工费、正常损耗和异常损失。
3. 债务/索赔账：采购货款 AP、委外加工费 AP、贷项、索赔应收、争议与合法抵销。
4. 资金账：实际付款、供应商现金赔偿到账、账户流水和银行核对。

禁止用一个余额字段代替四条来源；禁止用名称/编号猜关联，跨链只认 UUID。

### 2. AP 立账与付款

- 财务批准采购/委外订单只是商业放行和未来到货事实，不立 AP。
- 财务批准订单冻结供应商、币种、正汇率、结算方式和行单价；委外历史空结算快照不得用当前主档猜补。
- 收货/进仓审核锁订单头行，服务端按批准数量、价格和汇率重算双币金额；客户端金额不参与立账。
- 财务批准的超量到货计入授权额度，未批准超量拒绝；分批收货/退货最后一片吸收四位小数尾差。

- 仓库审核采购收货或委外进仓时形成 AP；委外 AP 只含加工费，不含自有材料价值。
- AP 同时冻结原币、本币、开账汇率、供应商、业务类型、结算方式和到期日。
- 付款行保存现金汇率、开账汇率、现金本币、账面核销本币、汇兑差额与前后原币余额。
- 同币种、同供应商、正 open item 才能付款；服务端锁 AP 后重算，前端金额不是权威。
- 反立账使用红冲状态和软删除保留审计/FK，不物理抹除历史。

守恒：

```text
未付本币 = 立账本币 - 账面付款核销本币 - 已生效非现金抵销本币
现金已付本币 = 实际银行/账户流出；与账面核销的差额 = 汇兑损益
```

`CASH` 是例外：显式现金结算固定在收货/验收业务日到期，不允许供应商 `tday` 把现金单改成账期单。

### 3. 结构化账期与月结

结算方式保存：

- 基准：`RECEIPT_DATE | QC_ACCEPTANCE_DATE | STATEMENT_END | STATEMENT_CONFIRM_DATE | INVOICE_DATE`；
- 规则：`NET_DAYS | EOM_PLUS_DAYS | FIXED_DAY_OF_MONTH`；
- 默认天数、固定日、跨月数；供应商正数 `tday` 优先。

收货时只计算当时已发生的基准；依赖未来 IQC、发票或对账确认的规则返回空并等待对应事件，
不得猜日期。“月结”稳定角色按月末加天数计算。

月结批次按供应商、币种、自然月冻结逐笔快照：

```text
期末 = 期初 + 本期立账/红冲 - 本期账面付款/反审 - 本期抵销/反转
```

批次包含哈希、逐行前后余额、供应商确认、内部确认、争议和反转事件。财务快照与行只读；当前月份
未结束不能提前冻结。冻结即阻断该截止日前的新业务事件；未双方确认的批次可先反转后重开，一旦
双方确认过，即使后续争议或反转也不重开旧期，修正进入下一开放期间。确认/反转与供应商写入使用
同一 supplier-first 锁序，避免冻结快照在确认瞬间漂移。

### 4. 贷项、预付与抵销

- 采购退货/已确认索赔可作为贷项，必须用 `supplier_open_item_offsets` 显式逐笔应用到正 AP。
- 两边按稳定 UUID 加锁，保存业务批次号、行序、发生日、原币和两边账面本币、前后余额；
  反转严格 LIFO，记录保留为 `REVERSED`。
- 不同开账汇率会产生汇兑差额；专用汇兑投影开放前失败关闭。
- `PREPAYMENT` 明确作为供应商预付款资产展示；当前旧负 AP 兼容行不开放通用自动应用，
  直到独立预付款资产科目和总账迁移完成。
- 抵销日期由服务端记今天，不能倒填进已确认月结期间。

### 5. 委外正常损耗与超耗责任

损耗单只确认实物损耗并回写供应商处材料守恒。每条材料保存实际量、允许量、超耗量和
账面损失；混合 kg/件/米时头部不相加，只看逐行数量。

```text
供应商结存 = 发出 + 已确认补料 - 已消费 - 已退回 - 已损耗
超耗 = max(实际损耗 - 合同允许损耗, 0)
```

正常允许损耗留在合格产出的成本中；超耗必须有正数发料账面成本，否则审核在任何库存、责任单
或总账写入前失败关闭。超耗确认时借记委外超耗异常损失、贷记库存资产；后续索赔追回独立入账，
不得用赔偿净掉原损失。

有超耗才开财务责任单。原 `deduct_amount` 只是建议金额，不产生会计事实。财务可按每条材料
拆成多种方案：

- `COMPANY_BEAR`：正常/批准由公司承担；
- `WAIVER`：有权限、有原因的豁免；
- `AP_OFFSET`：已确认索赔应收与 AP 的书面抵销；
- `CASH_COMPENSATION`：独立供应商索赔应收，必须经启用账户实际到账；
- `MATERIAL_REPLACEMENT`：加工商处补回我方材料，增加 `compensated_qty`，不立 AP；
- `OUTPUT_REPLACEMENT`：待专用“零加工费且不重复耗用我方材料”的补偿入库；普通进仓不得冒充；
- `SCRAP_RETURN`：精确绑定已审核材料退回明细；
- `SERVICE_PRICE_REDUCTION`：必须等待红字发票/贷项和税额处理，不能冒充赔偿抵销。

实物履约必须绑定精确单据明细 UUID、订单/材料、数量且只能使用一次；供应商处补料使用专用
守恒事件。履约与责任决定均有专用反转路径。

### 6. 索赔应收与总账

无当前合法抵销权的赔偿不列负 AP。现金赔偿使用独立 `supplier_claim_receivables`：

```text
确认赔偿：借 供应商索赔应收 / 贷 委外异常损失追回
合法抵销：借 应付账款 / 贷 供应商索赔应收
现金到账：借 到账账户 / 贷 供应商索赔应收；差额进汇兑损益
```

系统角色使用稳定 UUID：`SUPPLIER_CLAIM_RECEIVABLE`、`SUBCONTRACT_LOSS_RECOVERY`。
资金到账同事务更新账户、写 `finance_reconciliations`、结清索赔应收；无账户到账不得完成。

## 不采用

- 仓库在损耗单填扣款、审核即冲 AP；职责和税务口径错误。
- 直接降低加工单价表达材料赔偿；会污染加工成本和税额。
- 用普通委外进仓表达免费补货；会重复消费我方材料。
- 用当前累计余额重跑历史报表；后续付款/反审会篡改过去。
- 把供应商预付款继续当负债净额自动抵销；资产负债分类不正确。

## 仍未交付 / NO-GO

- 供应商发票、暂估转正式、订单/收货/IQC/发票三或四单匹配、红字发票与税额价差仍无独立模块；
  当前“应付”表示收货/服务验收形成的业务 AP，不得称为“已开票应付”。
- `OUTPUT_REPLACEMENT` 专用补偿入库尚未开放；责任方案保持待履约。
- 供应商预付款独立资产/应用/总账链尚未开放；兼容行只展示并失败关闭。
- 依赖 `QC_ACCEPTANCE_DATE`、`INVOICE_DATE`、`STATEMENT_CONFIRM_DATE` 的账期仍缺专用事件处理器；
  相关 AP 保持未定到期日并阻止月结冻结，不猜日期。
- 当前 AUTO 总账缺少通用会计期间和跨期反向凭证模型；跨月红冲在任何业务写入前失败关闭。
  同月反转以及报表/月结反转日期统一按 `Asia/Shanghai` 业务日归属。
- 目标库 Flyway/history/金额对账、真实多岗位 UAT、银行核对、总账重生成、备份恢复与发布签字未完成。

因此本 ADR 只说明源码候选设计和本地证据，不代表公司目标库已经迁移或功能已上线。
