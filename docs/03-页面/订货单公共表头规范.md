# 订货单公共表头规范

> 适用页面：销售订货单、采购订货单、委外订货单的新建/编辑页；
> 最后核对：2026-08-27。

## 一、适用边界

| 单据 | 结账/结算方式显示 | 订货时必填 | 下游兼容 |
|---|---|---|---|
| 销售订货单 | 结账方式 | 是 | 出货、其它出货、退货不因本规范新增必填 |
| 采购订货单 | 结账方式 | 是 | 收货、退货沿用来源快照和历史兼容 |
| 委外订货单 | 结算方式 | 是 | 进仓、退货沿用来源快照和历史兼容 |

本规范只把三类商业订货单设为必填，不能机械扩张到所有带 `settlementMethodId` 的下游单据。

## 二、必填交互

1. 标签使用共享必填标识，显示红色 `*`，不再把 `(必选)` 硬编码进字段名。
2. 字段启用且为空时立即显示错误色边框。
3. 必填订货单不提供清空选项。
4. 保存前再次校验；失败时字段附近显示明确错误，并阻止请求体省略 `settlementMethodId`。
5. 字典加载中、加载失败、无可用项和历史已停用项必须分别展示，不能渲染成可保存的伪空值。
6. 红色不是唯一提示；红色 `*`、边框和错误文案共同表达必填。

销售、采购使用 `UtenDropdownField(required: true)`；委外保留异步字典状态，并复用
`requiredLabel` 与 `applyRequiredEmpty`。

## 三、人员字段

- 业务员、采购员、经办人等员工字段遵守
  [UtenEmployeePicker](../02-组件库/UtenEmployeePicker.md)。
- 已选值和弹窗主行显示 `姓名(工号)`，部门显示在下一行。
- 员工 UUID 是提交与关联权威；姓名和工号只作展示。

## 四、服务端边界

| 链路 | 当前约束 |
|---|---|
| 销售订货 | Flutter 新建/编辑与保存校验已强制；销售订单服务仍保留 nullable/历史兼容，不能把 UI 门禁描述成直接 API 硬约束 |
| 采购订货 | Flutter 保存前强制；保存请求以 `@NotNull` 和 UUID resolver 校验有效结算方式，提交财务时再次复核 |
| 委外订货 | Flutter 校验字典状态和有效选择；服务端保存强制有效 UUID，提交财务时再次复核 |

如果以后把三类订货统一提升为服务端硬不变量，必须先核对历史空值、迁移兼容和直接 API 调用，
再补服务校验/约束与负向测试；不得只改数据库 nullability。

## 五、文案与括号

- 所有新增或修改文案统一使用 ASCII 半角 `()`。
- 员工格式写成 `姓名(工号)`，字典项写成 `名称(代码)`。
- 禁止新增 U+FF08/U+FF09；完整规则见
  [命名规范 §3.3](../00-项目准则/01-命名规范.md#33-文案与标点)。
