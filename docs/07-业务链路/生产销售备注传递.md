# 生产侧销售备注与来源关系

2026-10-21，按业务要求将销售订单统一备注和订单行单独备注作为生产要求传递到物料分析、生产计划、车间任务和工单打印。

## 数据来源

`ProductionSalesRequirements` 从 `sales_orders.remark` 与 `sales_order_items.remark` 读取当前值，两个字段分开返回和显示，不拼接覆盖生产计划自己的备注。只投影订单行标识、订单号、产品名称和这两类备注，不增加金额、价格、折扣字段。

- 普通分析来源按订单行 UUID 取值；自制/委外子件按 `parent_analysis_material_id` 逐级追溯到来源。
- 汇总生产子件按仍有效的供给动作及其准确分摊回溯各来源。相同货品的不同订单保留独立记录；互相冲突的备注不能按货品名去重。
- 父汇总批撤回但独立子工单保留时，读取 V895 的不可变原始私有来源证明，按其准确来源 UUID 继续展示备注。要求完整份额与冻结结构相符；此历史证明只用于备注溯源，不作为当前供给容量，也不恢复已撤父批的活动需求。
- 追溯从已授权条目开始递归，按当前条目的唯一批次调用 `fn_preplan_aggregate_recorded_private_sources_scoped(analysis,NULL,batch)`；不会为查一条工单展开整个分析的历史批次。具有逐来源证明的子批次用该证明替代宽泛父级继承；一份只分摊订单 A 的子工单不能因为父批也含订单 B 而混入 B 的备注。
- 车间拆批工单优先读取自己的 `execution_segment_sales_allocations`，不能带入同计划行其他执行段的订单要求；没有执行段分摊的历史工单才回落到准确计划行及分析谱系。
- 只读查询按已获准查看的分析行、计划明细或当前页执行段批量执行，空集合不查询，不增加独立销售单据浏览入口。调用点必须先通过现有分析/计划/车间的对象范围守卫。
- 读侧不改来源、数量、计划状态或销售备注。历史来源软删除后仍可按保留的准确 UUID 回溯；不按货品、名称或相似单号猜测。

## 展示

界面继续默认应用 `frontend-design`，复用 Uten 主题与组件。分析表和车间任务表增加“销售生产要求”入口；产品与部件都可查看完整内容。计划摘要下与车间任务详情中直接显示，订单统一备注和产品单独备注有独立标签，多来源逐项列出。文本可选择复制，长备注换行并在既有容器内滚动；不截断为不可访问内容。

销售备注是当前权威读侧事实。分析轮询的动态比较包含备注内容，备注修改即使没有改变物料数量指纹，也会更新页面。工单打印预览与 PDF 同步携带自己的销售来源要求。

## 回归入口

- `ProductionSalesRequirementsPostgresTest`：使用当前迁移的真实列形状验证多级子件、相同货品不同要求、汇总批次、多来源取消、循环脏谱系、手工计划、拆批准确分摊及空来源。
- `ProductionExecutionWorkbenchQueryPostgresTest`：原有车间范围与 SQL 查询用例继续覆盖新增查询依赖。
- `production_sales_requirements_test.dart`：分析/计划/车间解析、两类备注分别显示、重复来源去重、360/1280 宽度、200% 字号与明暗主题。

这些是本地源码及测试约束；公司运行服务升级与岗位验收另行记录，不能从构建通过推断已部署。
