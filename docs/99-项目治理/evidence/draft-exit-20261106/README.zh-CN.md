# 显式草稿退出的公共等待阶段

`saveFormDraftBeforeExit` 统一管理明确退出时的草稿持久化和一个 `UtenBusyOverlay`。同步占用退出许可，重复关闭/返回不会共享一个成功结果后再次导航。普通自动保存、后台切走、提交前检查点和恢复检查点继续使用原 `saveFormDraftNow`；确认框不被遮罩，错误处理发生在遮罩收尾后。存储异常保持抛出，由原调用方保留输入并完整提示；原来两个未处理错误的退出调用方补齐失败收尾。

已迁移设置、科目名称、财务单据审阅、既有财务单据编辑、科目导入和通用财务原请求六个实际直接退出调用方。已有业务 busy、确认/菜单、原返回值与原请求不重放规则继续由调用方控制；原本两个本地等待实现改用同一公共入口。

新增原失败证明保存/丢弃确认后的实际存储阶段缺少公共等待。首修完整70案中69通过，剩余案揭示丢弃的临时 `_draftFinished` 阻止自动保存重建草稿，却被后续关闭误当成业务已完成。公共入口明确区分丢弃阶段与已确认业务完成，等待CAS期间阻止第二个退出，保留业务成功原先可越过业务busy导航的合同。未知提交的禁止丢弃、原草稿CAS与其他页面修订保护均保留。

最终公共完整70案、六caller恢复/公共关闭/源码审计组合9完整文件197案、独立硬关闭中断完整1案通过。中断案在存储尚未结束时移除整棵窗口：等待正确退役、不给失效页面导航许可、原始输入仍可重新打开恢复。真实Chrome新增7案全部通过，覆盖确认/取消、自动保存无遮罩、重复退出、存储失败重试、身份退休和保存/丢弃的等待阶段；不是把筛选7案写成整个公共文件的Chrome结果。

Web与现有Flutter桌面/移动共用此入口。WPF未迁移的这些财务/草稿UI仍未迁移，本批不构成Win7真机验收。没有读取或纳入可视化分支的同名草稿WIP。
