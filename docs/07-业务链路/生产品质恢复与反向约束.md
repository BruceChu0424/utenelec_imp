# 生产品质恢复与反向约束

本页从[生产主流程](04-生产订单排产与执行全链路需求.md)展开报工、FQC、仓库点收、材料结清和正反向来源约束。来源计量见[生产计量与来源守恒](生产计量与来源守恒.md)。这里描述合同和实际入口，方法存在不等于全部场景已验收。

## 一、报工、品质和实收三个数量

新日报必须引用已显式开工的IN_PROGRESS执行段。READY只证明齐套/预留，实际必需领料完成后仍由负责人开工；首笔日报不能替代开工。日报只申报本次完工量，不让生产人员填写最终品质PASS/FAIL。

| 数量 | 权威来源 | 不能替代什么 |
|---|---|---|
| gross完工申报 | 当前有效已审日报行及其恢复来源 | 不等于品质许可或库存。 |
| 当前有效fqty | 日报贡献减实际FAIL adjustment及对应反向 | 不等于仓库实收完成率。 |
| pass/fail/pending | 每条日报行的唯一FQC inspection及品质决定 | PASS只形成未用完的入库许可。 |
| iqty | 仓库实际接受切片减实际反向 | 才是库存、成品履约和完成率依据。 |

```text
本inspection：已PASS + 已FAIL + 仍待决定 = 有效申报量
0 <= PASS + FAIL <= inspection容量
当前有效fqty = 有效日报gross - 有效FAIL贡献调整
有效仓库iqty <= 有效PASS放行 <= 当前有效fqty
完成率 = 实际iqty / 对应有效计划量
```

必须对同一来源、代际和有效事件比较，不能把多次恢复的毛报工量当计划净完成量。计划10、原报10、FAIL1后有效fqty为9，恢复授权为精确1；原日报与品质决定均保留。计划10000实收1000只完成10%，不会因已报10000而显示完成。

日报创建同键同体重放，同键异体拒绝，草稿编辑/审核用版本保护。本次量须为正且不超过锁内可报余额，没有额外5%超报宽限。审核后才登记贡献和唯一FQC；驳回不增加库存、iqty或放行。人员、工时和时间如有输入须符合实际，不能用日报负责人/worker或fqty推算计件工资；人员工时、附件与计件是独立待验收/扩展范围。

## 二、FQC和失败恢复

品质按inspection UUID决定PASS/PARTIAL/FAIL并保留实际原因、处置及操作者。PASS冻结release并生成相应FINISHED_IN待点收；FAIL追加贡献回退和recovery authorization，不能修改旧日报让不良看起来从未发生。

| 处置 | 物料与后续 |
|---|---|
| REWORK | 沿原在制恢复，不自动新增主料；引用开放authorization补报，审核消费该恢复份额，再建新的FQC。 |
| SCRAP/REJECT | 建recovery-only工作区与冻结BOM的EXACT_SNAPSHOT需求；完整物料预留后形成补料DRAW，实际发料且全部需求FULFILLED后才可补报；仍需再次FQC和点收。 |
| 缺料 | 持久保留BLOCKED attempt/gap，由既有采购/自制/委外取得合格物料；不伪造上游单据，不把0投影当完成。 |
| 再次FAIL | 新品质代际生成下一份恢复授权，原授权的分配/释放沿真实父子来源；不能重复扣原fqty或重复领同一补料。 |

恢复工作区不能走普通notify/issue-plans创建顶层生产计划，避免一份失败量同时进入普通生产和恢复补料。允许量来自FQC失败份额，不来自手填数量或通知。需要额外补料也必须单独有实际来源和允许额度，不能在普通领料里静默超发。

原计划普通剩余优先展示：计划10先报5并FAIL1，仍有正常可报5，不应被等待补料的恢复1遮住。取消恢复须先解除活动replacement、FQC和FINISHED_IN；全FAIL的恢复报工有效贡献为0时也按原分配释放，不能为取消再扣一次数量。

历史无inspection豁免只接受迁移已冻结的具体日报行UUID，不凭日期、“看起来旧”或缺执行段绕过品质门。新无段日报不得进入可报列表或保存。

## 三、仓库点收、短收和反向

可点收额度只来自尚未分配的PASS release，不能按当前fqty、日报量或手填入库量补造。仓库逐行输入acceptedQty，满足 `0 <= acceptedQty <= 本行当前待点收量`，短收需原因。

- 正数实际接受量才增加库存、iqty和对应计划/销售来源分摊。
- 短收余量在同事务生成同计划/日报/FQC来源的新待点收草稿；零收行也保留余量。
- 整单全部0可按原因拒收为REJECTED；未消费的PASS余量仍可重新点收，不改FQC或fqty、不增库存。
- 待点收、已接受和余量必须守恒；重复确认或网络重试返回原事实，不重复入库/分摊。
- 批量确认在公开合同内全有或全无，逐行实际库位、来源和库存容量不能由同货品其它批次掩盖。

已点收生产FINISHED_IN禁止通用编辑、删除或通用红冲，使用 `POST /api/stock/docs/{id}/finished-in/reverse` 对应专用命令。按原accepted slice反库存/iqty并追加反向头/行，恢复同来源待点收额度，入口见[StockDocController](../../server/src/main/java/com/uten/imp/features/stock/StockDocController.java)。下游已发货、调拨、领用或关联证据不可恢复时拒绝，先处理下游。

销售多来源、合并计划和分批实收都按原allocation回写。V1精确执行段销售分摊总量对齐段计划量，使用同一销售link不超过容量；缺少分摊或来源漂移不能猜。历史V0只在明确upstream_item_id及允许的单一销售link范围内兼容，不能猜多来源分配。真实子件无销售来源时只回本计划/父需求，不造销售预留。

## 四、领、退、耗、损耗和在制

DRAW审核是需求确认，仓库实际issue才扣库存、消费对应预留并把价值移入实际在制。一个执行段可有多个叶仓DRAW，部分实发保留剩余需求；未完整实领不能开工。普通领料不超过冻结需求/允许补料额度，正常损耗已经含在需求时不能再放宽一次。

材料实际消耗由责任人明确确认，不自动用“领用减退回”代表CONSUMED。每份ISSUE来源保持：

```text
实际领用 = 确认消耗 + 已收良品退料 + 已收待检/不良退料
         + 明确损耗/报废 + 有证据的在制结转 + 尚未结清
可退上限 = 同来源实际领用 - 已确认消耗 - 已退 - 损耗/报废 - 在制结转
```

负可退上限是异常，不能取0后继续。车间提交退料尚未增加可用库存，仓库实际接收后才记对应实物/结清；待检或不良不能入可用料池。已消耗材料若要退回，先按实际结清反向恢复同源可退量，不允许既算已耗又再次实退。

`production_material_stock_postings`记录实际领退料事件与库存流水桥；结清posting通过issue_posting_id定位原实领。旧NULL不猜来源。多次部分退料、消费、损耗和在制须逐源核对，不能用整单总量或后进先出替代原来源。

实际CONSUMED成本进入生产成本对象，成品实收在原事务注册输出，后补或反向沿未售库存、已售COGS及在制归集。CONSUMPTION_RETURN恢复原数量区间/ISSUE WIP，原输入/事件不删除；REOPEN_COMPLETION要有真实同计划结清反向依据，不伪造品质或成品反向。金额与任务分配细节集中在[成本专题](../99-项目治理/库存实际成本接线与验收.md)。

未完生产换车间、跨批或跨期不等于已消耗/已退。需要明确来源段、目标段/在制位置、物料、数量和接收依据；通用跨段在制调拨和完整成本GL不可因存在WIP枚举就宣称已交付。

## 五、来源反向矩阵

| 动作 | 必须保留/恢复的事实 |
|---|---|
| 放弃分析或未下游action | 只有无依赖或已解除来源才取消，保留事件。分析从未占库时不能假释放库存。 |
| 取消待批准计划 | 释放对应submitted额度并终结草稿/链接，不写库存反向；不能物理删除被来源引用的行。 |
| 取消WAITING/未发READY | 按原计划/来源释放未执行责任及允许释放预留；共享供给只释放本需求份额。 |
| 改量、路线或优先级 | 已执行量和商业/品质快照不覆盖；获准的剩余量先解除原路径再建立新路径，MAKE/BUY/委外不能重复承接同一份额。 |
| 实发撤回或退料 | 核同源未耗/未退/未转移容量，追加真实库存/预留反向；已开工或有下游时走相应退料/结清通道，不能把卡片拖回待料。 |
| 报工驳回 | 未审核才可退改，正式fqty/FQC/库存不变。 |
| 报工或FQC反向 | 先处理入库、recovery/replacement和相关品质，再按原贡献/分配反向，不能删原决定。 |
| 成品点收反向 | 专用命令按原接受切片恢复库存/iqty/来源额度；下游消费先解除。 |
| 退料/耗用结清反向 | 原事件保留，恢复同一ISSUE数量和成本去向；检查退回库存或原来源是否已再被使用。 |
| 采购/委外收货反向 | 只反本来源实际入库、品质/费用/材料及未用供给；后续使用、再次补回和普通退货先解依赖，不能误伤同单其他来源。 |
| 委外通知或前置产出反向 | 批次、申请、商业单、实出、回厂和实收逐级处理，恢复原树准备/供应商责任；禁止删父件同时留下已用子件。 |
| 销售改单/取消 | 原已准入履约可继续，新安排仍过本次财审；实际已发、在产、预收/转销等按专用通道处理，不凭生产权限强行清链。 |
| 结案/反结案 | 实收、物料、品质/恢复和待点收全部核对，未决事实阻断；父计划不能因一段完成就整体关闭。反结案需要实际命令及来源，不是改状态字段。 |

变更、取消和红冲统一使用本次实际来源的锁计划及版本/幂等合同，见[履约事务锁序](2026-09-07-履约事务锁顺序与来源漂移处理.md)。不能把一个旧简写锁顺序应用到所有跨域事务。暂时不能自动反向时明确冲突和待处理来源，不能静默忽略或加no-op。
