# ADR-121：跨模块新建表单草稿恢复

- 日期：2026-09-26
- 状态：已接受；本地实现，未部署
- 范围：新建表单、任务中心、本机持久化与红色徽章；零数据库迁移

## 背景

用户要求所有模块的新建页在填写后退出时询问是否存草稿，异常关闭前自动保存，并在对应任务中心显示草稿及红色数量。现有业务草稿接口要求完整必填字段，部分创建接口还会占用来源数量或发起审批，不能当作逐键自动保存接口。

## 决定

建立独立的本机表单草稿，统一由 `FormDraftMixin` 管理。页面仅提供完整且保留原文的状态编码、恢复及可编辑监听集合。新建页、可重建的新建弹窗及填报页共用存储、退出确认、恢复、作用域和提交保护。

Web 使用 IndexedDB，原生端使用应用支持目录的逐记录文件；均采用原子比较版本后写入。服务器地址、用户和实际代操作人进入持久键；登录纪元只用于阻止迟到结果跨身份生效。当前权限、复合路由权限和业务来源在恢复/正式提交时重新检查。

表单草稿不成为库存、财务、配额或审批事实。正式提交前落盘原始请求的可恢复上下文；未知结果不得无证明地重新建单。服务端幂等键或已创建记录 ID 必须原样恢复。确认提交完成用墓碑替换有效负载，避免迟到写入或旧标签页复活已提交草稿。

## 对 ADR-108 徽章口径的限定扩展

服务端 `badgeSummaryProvider`、业务 `facts`、状态分段和黄色数量保持原契约。本机尚未成为业务单据的表单草稿，由一个 `effectiveBadgeSummaryProvider` 统一按 ID 去重后加到对应红色入口/模块/总数。所有相关显示读取该投影，禁止各页面自行累加。任务中心用同一 `formDraftsProvider` 列出可恢复对象，因此红色数量和用户能打开的草稿一致。

## 代价与边界

本机草稿不跨设备同步；清理站点存储/卸载会丢失本机草稿。突然断电只保证已提交到存储的事务，不能保证最后一个尚未落盘的输入。存储失败不显示成功，用户选择保存后离开时失败则留在页面。不能声称此方案自动保护所有既有记录编辑或现有物料分析工作台的未保存更改。

接入契约、覆盖清单和验证方式见 [表单草稿自动保护](../02-组件库/表单草稿自动保护.md)。
