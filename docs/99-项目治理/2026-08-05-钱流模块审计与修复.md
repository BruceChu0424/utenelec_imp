## 一、审计概览

8 路并行只读深审 + 1 路关联审计(采购财务审批),共 31 项 findings(M1–M31)。审计维度:文档规格 / 收付款转账 / 费用收入成本 / 对账报表 / 固定资产 / 跨切面(状态机·权限·竞态·审计) / 并发锁定调研 / 功能完整性。

最严重已亲验:**M1 银行转账汇率前端可控→可凭空造钱**(`FinanceBankTransferService` 原信任 `req.exchangeRate`,只校验 >0)。

## 二、用户拍板的 4 项方向

1. **增值税/价税分离**:**不在 ERP 做**。进项/销项税、发票管理、税务申报由外部金税/代账处理;ERP 只记含税总额。→ 本模块不引入税额字段,VAT 相关视为文档边界(见 §六)。
2. **并发占用**:复用既有软占用租约范式(原 HrTaskClaim),先覆盖钱流 5 单据 + 审批池。→ 后与并行会话对齐:**改用已建 `task_claims`**(见 §五),不另建 `entity_claims`。
3. **职责分离 + 审计**:拆 `:approve` 权限点 + maker≠approver + 金额变更全留审计。
4. **金额管控 + 手续费**:直接收/付款加上限/二次审批 + `bank_fee` 对称入账。

## 五、并发占用:与并行会话对齐(用 `task_claims`)

原计划新建 `entity_claims` 表 + `EntityClaimService`(复用 HrTaskClaim 范式)。同期并行会话已建更通用的 **`task_claims`(V215 `V215__task_claims_unified.sql`)+ `features/common/taskclaim/{TaskClaim,Repo,Policy,Service,Controller}`**,含 `target_type+target_key` 部分唯一索引、show-as-locked(不隐藏)、接管、maker-checker。**决策:撤销本域 `entity_claims`,钱流 5 单据将来直接集成进 `task_claims`**(并行会话路线图下一步即"逐面集成")。`@Version` 乐观锁作为占用机制的双保险,配套补(含给 GlobalExceptionHandler 加乐观锁兜底),不在 Phase 0 单独提前上(M28 已由 em.refresh 修复)。

## 六、VAT/价税分离边界声明

**本 ERP 钱流模块不做增值税价税分离、发票管理、税务申报。** 所有金额按**含税总额**记账;费用/收入全额进费用/收入科目,不拆"进项税额/销项税额"分录;无发票主表(仅 `invoice_no` 文本字段关联老库支票号)。进项/销项税抵扣、发票开具/认证、增值税/所得税申报由**外部金税系统/代账**完成。使用者不得据 ERP 总账/利润表直接报税。
