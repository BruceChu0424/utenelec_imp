# 车间任务路线与供料场景矩阵

2026-09-19，2026-09-20 按 ADR-095/ADR-096 更新。以当前代码和 ADR-093 为实施合同；旧 ADR 中“持续生产仅直送、仓库必须全齐”的限制由本次重构取代。

## 入口与选择

物料分析确认需求及采购/自制/委外责任 → 下达生产计划并继承车间负责人 → 我的车间任务确认执行路线 →
按实际供料办理 → 显式开工 → 持续报工 → 品质/交接 → 实收或同车间投入 → 用料结清/完工。
计划数量是总目标，持续路线不要求先填第一批开工数量。报工是实际完成量，不能把预计采购/已到待检量当成投入。

常用两条路线：**齐套生产**等待整单材料足量；**持续生产**在同一任务按每批实际到料补领和报工。
仅需要各批独立安排、独立追踪时选择**分批生产**。分批到货本身不要求拆任务。
路线和来源是两个维度：同一任务、同一物料都可能一部分由普通仓领出、一部分同车间下层直送。

## 场景与结果

| 场景 | 正确结果 |
|---|---|
| 新任务材料已经齐全 | 先确认路线，系统不提前生成领料单锁死选择；零料任务也先确认再开工 |
| 无需物料的任务(零料) | 三条路线都可选(ADR-096)：齐套=确认后开工；持续=随时可开工；分批=按数量拆成两个生来 READY 的零料子任务(快照空数组、无领料单)，批次段直接开工、剩余段可再拆或改齐套 |
| 新产品第一张任务，没有同产品历史 | 「下一步」预填当前登录人上次确认的路线并挂黄标「已按你上次选择的路线预填」；同产品有有效确认时按产品预填并优先；预填只展示，选中或批量确认才写事实 |
| 一次要给多张任务选路线 | 勾选后「批量设路线(N)」菜单：齐套/持续/分批各显示能改的行数，「按预填默认值确认」把带记忆的行各按自己的预填一次确认；逐行携带版本，部分失败按行提示 |
| 物料未齐 / 未选路线的行 | 首列勾选框角上压锁并悬停说明，勾选仍可用于批量设路线；批量开工计数不含它 |
| 持续生产已备/已领部分料（含直送已投入），车间想改齐套 | 允许（ADR-095）：状态不回退、已备物料一件不动，开工门改为每种物料实领到位；列表「等待物料到齐 · 已备 a/n 种」 |
| 已备料的任务想改分批 | 409 且无副作用：分批要拆独立子任务，只在未备料时可选；下拉不出现分批，悬停说明 |
| 已开工或已有报工后想改路线 | 409「开工后不能更改」；徽章悬停说明已有报工记录 |
| 采购/委外件未到而仓库已把能发的发完 | 「等待到货 · 缺 k 种」，不再误报「待仓库发料」；详情按种显示仓库已到与缺口 |
| 同车间子件工单未完成 | 「等自制子件完成 · 缺 k 种」(ADR-096 起不写「直送」：子件产出可能线边直送也可能入库后领料，交接方式在子件报工时才决定，`direct_supply` 只是分配偏好)；子件流转到本任务或入库后领到车间才算已领；详情列出承担的子件工单与状态，来源写「自制子件 · 直送或入库领料」 |
| 每种物料都已实领 | 「物料已领齐 · 可开工」；持续生产不再把领齐说成「部分产量」 |
| 计划1000，采购先合格实收100，再到900 | 持续路线首批领100并显式开工；后900仍在原任务继续领；不另拆生产计划 |
| A有100、B尚未到 | 可以准备已到的料；每种必需料共同支持正产出后才允许START，不能空开工 |
| A支持100、B支持60 | 实际投料最多共同支持60；报工累计不能因为A足量就超过瓶颈 |
| 每包供10件、用2单位，只有1单位材料 | 不足完整投入，不能据平均单耗虚算5件；2单位支持10件，11件需要4单位 |
| 同一物料仓库60+直送40，需求100 | 合计覆盖100；直送来源预留只计一次，不再接收额外40 |
| 日报使用箱，需求使用件 | 按来源冻结unitRate转基础量后检查容量；保留旧日报单位不改写 |
| 同车间子件报工合格直送 | 必须有真实上下层责任，按接收需求UUID点对点接续；同车间同货品本身不构成授权。内部位置只承接在制与成本，不污染货品正常存放仓 |
| 同一日报的产出进入不同主仓范围 | 按实际内部接收位置归集，不能把同车间不同主仓混成同一交接头 |
| 跨车间、无真实接收需求、颜色不符 | 不走车间直送；按普通仓库/品质链处理 |
| 后批到料，任务已经在生产中 | 中心弹窗仍提示到料和下一步；在原任务继续领，开工不重复 |
| 到货待检或不合格 | 不增加合格可领量和可报上限；走既有退货、返工、报废或补产授权 |
| 仓库少发 | 只计算实际已发；余量仍待发；齐套路线不开工，持续路线按实际共同能力开工 |
| 超发/超送/超报 | 命令事务和数据库容量校验拒绝；公共备货必须单独有合法归属 |
| 申请退料尚未实收 | 先扣报工可用能力，仓库实收后才恢复相应库存；不能一份料同时退和报 |
| 直送到当前车间后剩余材料送仓 | 由当前车间交仓库，仓库选择同主仓内有效正常叶仓收料；上游生产地点只保留来源追溯，不是实物返回目的地 |
| 直送料尚未领用、尚未确认路线 | 按精确直送来源申请送仓，真实执行技术位置出库及正常仓入库，不虚构领料或START；未确认路线的任务保留专属保管权益，不提前生成正式领料预留，也不释放为公共库存 |
| 已投入车间的直送料送正常仓 | 按原ISSUE余量做GOOD_RETURN，正常仓增加库存；不能再次扣技术位置库存。原成本及原任务来源权益随实际物料承接 |
| 送仓后继续生产 | 原任务从实际正常仓续领；原技术位置尚未实发指令按真实送仓事实撤减，原单据毛数量与已发历史保留，不能两处同时待领 |
| 仓库收料结果网络不明 | 保留原实际收料仓库与幂等键重试；已确认事实原样返回，不能改仓重复收料 |
| 品质FAIL后返工 | 保留原报工/FQC事实，按原恢复授权补报；报废/拒收补产先走明确补料来源 |
| 每批按实际量报工 | 累计按任务总目标判断完成，不能把本次材料可报上限当成整单目标；合并提交的同任务销售分摊行一起计算 |
| 同任务还有其他待审日报 | 草稿占用可报额度，但不算已完成产出；尾批/余料退回提示按已审普通量判断，不能因别人存了草稿就提前退料 |
| 旧接口提前完结 | 销售任务没有未来供给和未实发领料承诺时才允许短产完结；内部子件短产保留原任务继续，避免切断父层责任。拒绝时不改目标、不释放物料；新页面按实际量报工，不提供随意截断任务入口 |
| 材料实际耗用、正常损耗、额外损耗 | 工艺实耗包含BOM已计入的正常损耗；额外损坏/报废才登记另行确认损耗并扣减能力。整包/固定批次不按平均单耗自动填用量，实际耗用允许明确填0 |
| 已领10、申请退3；随后真实退回3 | 两阶段都只按剩余7核算普通报工；退回不能反向增加可报量。申请撤销与实收撤回分别恢复对应事实 |
| 未开工任务改派车间 | 尚未发生实物交接且没有共享物料批次依赖才可改车间，未发草稿同步收料车间和人员；已有实发/直送先走原来源反向，不能只改页面归属 |
| 同车间更换负责人 | 有效在职负责人可变更；已有库存/报工事实继续保留原操作人，不能重写历史 |
| 离职计划编制人、只读用户、暂停计划 | 操作人有效性、动作权限和业务状态分别核验，计划所有人身份不能绕过；仍按对象范围显示历史记录 |
| 撤回/红冲，下游已消费 | 按原来源反向并先处理下游，不能直接删除上游事实；普通与直送遵循同一守恒原则 |
| 网络重试/多人同时领料 | 命令幂等、版本与来源锁共同保护；返回原事实，不重复投料或重复分配 |
| 同货品不同BOM路径/不同任务 | 需求UUID及分批谱系不合并；可以汇总操作，不能混掉订单/成本归属 |
| 历史默认仓被线边入库覆盖 | 有普通仓证据则恢复；无证据留空待明确，不猜仓，不改旧库存流水 |

## 提醒与规模

到料通知按货品、颜色、实际仓范围匹配，区分“仓库本次实收量”和“本单可领量”。
每个任务维持一个活跃行动聚合；长正文完整显示；任务列表继续服务端分页。
到料命中使用200条游标分页，不再只处理前30个任务。正式预留、直送谱系和持续任务扫描使用对应索引。
这里说明算法边界，不代表已经证明任意数据规模的响应时间；真实性能验收须记录样本量、并发数和耗时。

## 调研取舍

[Odoo 的部分制造与欠单](https://www.odoo.com/documentation/18.0/applications/inventory_and_mrp/manufacturing/workflows/manufacturing_backorders.html)
表明拆余量是可采用的一条路线；本系统只在用户明确要求独立批次时采用，避免默认拆单。
[Dynamics 365 的完工申报](https://learn.microsoft.com/en-us/dynamics365/supply-chain/production-control/report-production-orders-as-finished)
区分实际完成、耗用和后续库存流程；本系统据此保留实际投入与实际报工证据，并沿已有FQC与成本账闭环。
这两项是设计参考，不表示复制其全部状态机。
