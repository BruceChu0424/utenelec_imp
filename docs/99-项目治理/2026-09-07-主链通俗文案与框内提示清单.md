# 主链通俗文案、验收单位与财务新建减负

本次以真实输入和提交链为依据，使用现有 Uten 输入、提示与折叠组件。没有增加一套表单组件、迁移或金额/库存写入逻辑。财务资金卡由资金事实专项维护，其指标与这里的输入指引分别对齐相同业务事实。

## 场景与操作清单

| 场景 / 入口 | 操作人 | 本步决定与下一步 | 框内提示 / 本次调整 |
|---|---|---|---|
| 销售订货明细 | 销售 | 填本行单位订购量，提交财务 | 数量说明审核期间不能改；已审核修改重新送审；锁定单价说明来源；折扣用 1、0.9 而非 9、90 |
| 销售退货明细 / 原因 | 销售 | 引用实际发运，填写实退量和原因 | 退货量不能超过尚可退量；原发运决定贷项，参考价不能提高退款；实物先待检，退货审核不等于已付退款 |
| 财审首次 / 修改审核 | 财务 | 核对修改前后，再确认或驳回 | 确认不等于收款、发运或开工；驳回原因说明怎么改；批量备注写入每张所选订单 |
| 多产品物料分析采购 / 委外桶 | 计划 | 选路线、决定本次安排量 | 下达量是本次安排，不是实收；在途不算库存，下达不代表能开工；保留选中深色行数量可读性 |
| 物料分析自制下达 | 计划 | 决定本批交给车间的量 | 可先下达，开工与领料仍按物料和执行状态门禁 |
| 车间报工 | 车间 | 按执行段产品单位填本次完工申报 | 不是累计量，不将报工审核标成可用库存；随后仓库登记、品质验收与入库 |
| 采购 / 委外订货明细 | 采购 / 委外 | 填单位数量、单价和行条款 | 单价不是整行总价；币种决定金额含义；汇率填 1 原币折合本币；税率填 13 而非 0.13 |
| 商业条款统一设置 | 采购 / 委外 | 批量选择需要替换的项 | 同样提供汇率、税率、币种、结算提示，留空仍保持原行；学习值黄标继续保留 |
| 单笔 / 批量仓库到货登记 | 仓库 | 按本行单位登记本次实到 | 少到、多到按实物；超批准部分进异常处理，不直接成为可用库存；库位/系列/编码已有学习来源黄标 |
| IQC 明细 / 批量报告 | 品质 | 填本次合格、不合格，提交报告 | 显示实际验收单位；例如“原单1箱 = 24个；这里按个验收”；合格后还须仓库确认，不合格另行处置 |
| IQC 提交确认 / 提交回执 | 品质 | 核对每项数量与单位后提交 | 按验收单位 UUID 分组合计，不直接加箱/个/千克；未知单位只报待核对行数；普通结论说明不再冒充学习黄标 |
| 应收收款分配 | 财务 | 把本次付款对应到来源应收 | “本次分配收款(原币)”“应收币种”；不能超过余额、不能重复分配，同笔费用另记 |
| 订单预收登记 | 财务 | 先选订单，再登记实际到账 | 客户/币种由订单确定；以后抵扣预收不再次产生现金收款 |
| 预收抵扣面板 | 财务 | 选同客户同币种欠款，写抵扣依据 | “抵扣说明”取代“应用原因”；消除员工界面的 UUID 术语；抵扣不是再收一次现金 |
| 我的报销新建 | 申请人 | 填标题、费用项目、票据金额 | 可选补充说明折叠；票据人民币金额不得重复记录，项目说明解释用途 |

## 财务新建字段分类与最终界面

| 单据 / 字段 | 用户真正需决定 | 来源带出 / 可推导 | 少见或选填项 | 实际调整 |
|---|---|---|---|---|
| 通用钱流单据 | 单据日期、业务对象、真实账户、方式、经办人、明细 | 单号、制单员、制单时间为系统事实 | 发票号、备注 | 系统事实改为紧凑只读文字；发票和备注放选填折叠区，编辑已有内容默认展开；经办人仍保留 |
| 应收收款 | 来源应收、分配金额、到账账户和时间、汇率、实到账、银行流水 | 原币随来源应收；汇率凭据类型随直接到账/外贸代理渠道 | 无费用为默认；有费用再展开 | 去掉互相矛盾的“汇率来源”重复选择；无费用隐藏银行费/其它费/费用项目，切回无费用同时清零；实际到账和凭据必填入口始终显示 |
| 收款分配表 | 本次收款，必要时填写行备注 | 可收金额、币种和收款后余额；历史收款/抵扣/来源/换算为只读 | 完整对账列通过“查看对账明细”展开 | 默认 6 列，不让十多列只读历史把本次输入挤出屏幕；展开再收起复用同一行控制器，已输入金额与来源 UUID 不改变 |
| 外贸代理代收 | 代理公司、结算单号、实际到账与银行流水 | 汇率来源固定为代理结算单 | 另付费用时才选择费用付款账户 | 对应渠道必填项条件显示；不把必填字段藏进选填区 |
| 订单预收 | 订单、预收原币金额与本批银行到账事实 | 客户与币种随订单，不提供第二个可编辑客户选择 | 与收款相同的费用/备注 | 先选订单，再填银行事实；客户和币种用紧凑来源摘要，不做重复输入框 |
| 应付付款 | 已入账应付、真实付款账户/方式、汇率、实际经办人 | 原币和本次金额随应付分配 | 通用发票、备注 | 共用紧凑审计与选填区；保留原先来源与币种锁定，不增加无来源付款通道 |
| 费用 / 其它收入 / 银行转账 | 对象、账户、明细金额和实际经办人 | 系统编号与审计信息 | 发票、备注 | 去掉误用于这些单据的“销售原币/到账”页首说明；共用分组，业务校验和金额来源不变 |
| 员工报销 | 标题、类别、发生日期、实际票据金额 | 申请人为当前会话，金额合计由明细汇总 | 总备注、行用途说明 | 备注折叠，金额与说明框内给出提示，保存草稿/提交动作不变 |

## 验收单位的代码证据

- `StockDocService.normalizeAndValidateSaveLine` 通过 `goods.unit_id` 找单位；缺少行单位时补为该单位、换算率为 1；显式使用该单位时强制换算率为 1，其他单位必须填写正换算率。`baseQtyOf` 使用 `qty × unitRate`。
- V182 对 `goods.unit_id` 的数据库注释为“当前基本单位”；V45 定义库存数量为已乘换算率的数量，V420/V422 安全补货触发器也把该 UUID 作为基本单位权威。计量采集的 `business_unit_id` 与独立实际重量单位不能替代它。
- `ProcurementInspectionService.receive` 将 `qty × unitRate` 写入 `received_base_qty`。本次详情原查询追加 `goods.unit_id`、验收单位名称、来源单位名称，采用现有批量 JOIN；没有再次乘除、修改历史数值或新增 N+1 请求。
- IQC 列表、批量表单、提交确认与成功回执使用同一数量体系，分组合计复用 `measurementTotalsText`。历史缺少单位时明确显示“验收单位待核对”，不回退成来源包装单位，不把未知数量相加。
- 精确详情不依赖待检队列是否仍含该单摘要；直接链接有明细但无队列摘要时保持可读，避免空摘要解引用导致页面崩溃。

## 基本单位生命周期后续闭环

V498补齐主档基准可变更边界：没有数量/BOM使用时可改；首次使用后由DB持久锁定，取消、删除和重置不自动解锁。归一化在读取单位前取得尚未使用货品的事务锁，单位编辑先赢时必须读取新单位，归一化先赢时单位编辑等待并被拒；从而避免后续主档编辑把已存在BaseQty重标成另一单位。历史空UUID保持原资料，普通编辑不猜测补选。实现、52表/60列覆盖与验证见[114-V498](../数据迁移/114-V498货品数量单位生命周期守卫.md)。
