# Windows / macOS 登录窗口与主窗口切换

## 需求与设计

用户要求 Windows、macOS 客户端采用类似 QQ 的两段窗口体验：登录时是隐藏系统标题栏的小窗口，
使用自绘关闭按钮；登录完成后进入普通系统窗口。

按默认 `frontend-design` 技能保留 Uten 既有视觉与业务约束：背景 `#F5F7FA`、表面 `#FFFFFF`、
正文 `#0F172A`、次要文字 `#475569`、交互青绿 `#14B8A6`、错误 `#EF4444`，实际颜色由当前
主题及平台品牌配置提供；继续使用现有 NotoSansSC、吉祥物、字标及表单组件。

用户随后提供左右分栏参考图，再明确要求左侧只保留现有 IP 和 Logo，删除生成插画与文案。
最终常规窗口为 55/45 双栏，左侧复用 `UtenBrandMascot` 和 `UtenWordmarkLogo`，右侧复用同一份表单。
Windows 顶部布局为
`[拖动空白区][最小化][关闭]`，macOS 为 `[关闭][最小化][拖动空白区]`。
按用户最终要求删除登录页的服务器恢复按钮和技术说明；连接失败、超时及账号密码错误直接显示结果。
MFA、账号历史、权限及令牌处理保留各自公共职责。

## 重复实现比较、清理与保留差异

此前只有 Windows 普通启动窗口、Windows 窗口标题通道及两平台更新通道，没有独立登录窗控件。
新增的 Dart 控件与模式控制器是两平台唯一入口，没有分别复制两份登录表单或认证流程。
Windows 启动时强制最大化的原逻辑被模式化窗口展示替代；原窗口标题和客户端更新通道保留其独立职责。

保留 Win32/AppKit 原生适配、左右按钮位置、系统主窗口行为及最大化/全屏语义差异。
Web、移动端和 Linux 不启用该通道。业务权限、登录、MFA、令牌、草稿、数量和服务端计算权威不交给窗口层。

登录前连接选择只调用公共预检，随后仍调用同一 `SessionNotifier.login`。界面保存独立账号输入代次，
等待预检后刷新派生端点，再捕获 MFA 上下文；账号或服务器 A→B→A 后的旧结果不得恢复当前挑战、记住旧账号或跳转。
公共会话入口在预约、请求及存储提交边界检查可选调用方围栏。签发服务器绑定、刷新和登出的公共维护由认证任务统一整合，
本任务没有重写仓库、刷新、吊销队列或令牌格式；整合时应语义并入该围栏，而不是覆盖对方公共实现。
