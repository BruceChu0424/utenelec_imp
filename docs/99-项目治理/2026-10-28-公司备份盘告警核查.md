## 具体生产扩容方案与执行步骤

将现有 `/dev/ubuntu-vg/uten-backup` 从 **60GiB 扩到 100GiB**，使用 VG 中未分配的 40GiB，
同时在线扩展已挂载的 ext4。不会格式化、卸载卷、重建数据库或主动停止 ERP。
下列步骤已在获得本次明确授权后执行，原方案保留以便审核，不应重复执行扩容。

1. 重新只读核对目标身份、空间与作业：

   ```sh
   findmnt -T /srv/uten-backup -o TARGET,SOURCE,FSTYPE,OPTIONS
   sudo lvs --units b --nosuffix -o lv_path,lv_size,lv_attr /dev/ubuntu-vg/uten-backup
   sudo vgs --units b --nosuffix -o vg_name,vg_size,vg_free ubuntu-vg
   df -B1 --output=target,size,used,avail,pcent,ipcent /srv/uten-backup
   systemctl is-active uten-imp postgresql@16-main
   systemctl is-active uten-pgbackup.service uten-paired-internal-backup.service
   ```

   确认仍为上述 LV、ext4、可读写挂载，VG 可用至少 40GiB，备份作业当前未在执行；
   若身份、容量或作业状态变化，则先评估新状态，不机械执行。

2. 已执行的唯一生产变更命令：

   ```sh
   sudo lvextend --resizefs --size 100G /dev/ubuntu-vg/uten-backup
   ```

3. 立即验证：

   ```sh
   sudo lvs --units b --nosuffix -o lv_path,lv_size,lv_attr /dev/ubuntu-vg/uten-backup
   sudo vgs --units b --nosuffix -o vg_name,vg_size,vg_free ubuntu-vg
   findmnt -T /srv/uten-backup -o TARGET,SOURCE,FSTYPE,OPTIONS
   df -B1 --output=target,size,used,avail,pcent,ipcent /srv/uten-backup
   systemctl is-active uten-imp postgresql@16-main
   sudo -u postgres pgbackrest --stanza=uten-imp --output=json --log-level-file=off info
   ```

   LV 目标应为 107,374,182,400 bytes，VG 余量预计为 79,335,260,160 bytes（约 73.89GiB）。
   ext4 容量预计从约 58.76GiB 增至约 98GiB，可用空间增加约 40GiB 至约 55GiB；
   文件系统元数据与期间新增 WAL 会影响精确值，以变更后 `df` 为准，必须明显高于 20GiB。
   随后核对下一轮主机巡检正常且不再生成新的低余量事件。原历史告警保留为事实记录，不通过删除告警掩盖问题。

风险与回退限制：扩容会改变生产 LVM 与文件系统元数据，存在短时 I/O 负载与系统/设备故障风险，
应避开正在运行的备份并保持运维连接。ext4 在线增长后不能安全地靠一条反向 `lvreduce` 回退；
不得尝试在线缩容。若 LV 已扩大但文件系统扩展失败，保留较大 LV，确认 ext4 状态后再补做扩展，
不缩小到旧边界；若文件系统异常，按维护与恢复流程处理。扩大备份卷也不替代后续容量趋势和恢复点保留检查。
