# 仓库盘点修正与历史单据处理

> 日期：2026-07-31
> 适用范围：库存余额页、仓库管理 `CHECK` 盘点单、库存流水及订单预占
> 页面说明：[库存余额页](../03-页面/库存列表页.md) · [出入库流水页](../03-页面/出入库记录页.md)
> 结论：允许被领导明确授权的人填写目标库存，但后端不执行裸余额更新；系统在同一事务内生成
> 可追溯的授权调整盘点单和差额流水。历史订单、预占和既有流水行保持原样，后续存取货从修正后的余额继续增减。

## 1. 业务目标

仓库按周期清点货品后，以实盘数量修正系统账面数量。盘点审核完成以后，新的入库、出库、调拨、
领料和退料继续在修正后的即时库存上增减。

修正必须同时满足：

- 明确哪一天、哪个仓库、哪种货品和颜色，由谁操作、按哪种流程审核；
- 保留盘点前的账面快照、实盘/目标数量和盘盈盘亏；
- 不删除或改写已经发生的业务单据和库存流水；
- 盘点期间如有其他出入库，不允许用过期快照覆盖正常库存变动；
- 同一货品维度的凭证、流水和余额在一个事务内完成；
- 高风险快捷入口使用独立权限、必填原因、幂等和可回查凭证。

## 2. 当前模型与采用方案

现有系统已经具备完整 `CHECK` 盘点链路：

- `stock_documents` / `stock_document_items` 保存盘点主单和明细；
- `stock_balances` 保存当前余额；
- `stock_movements` 保存不可由余额页直接编辑的库存流水；
- 盘盈使用流水类型 9，盘亏使用流水类型 10；
- 审核、流水和余额联动在本地事务内提交。

系统提供两条入口：

1. **普通周期盘点**：建草稿 → 复核 → 审核，适合多行盘点和职责分离；
2. **授权余额调整**：持有 `stock:balance:adjust` 的人员在已有余额详情中填写目标值和原因，
   服务端自动创建并审核一张一行 `CHECK`，适合盘点后立即修正单行余额。

两条路径都只修正唯一库存维度：

```text
仓库 + 货品 + 颜色
```

计算口径：

```text
调整数量 = 实盘/目标数量 - 审核前余额
审核后余额 = 审核前余额 + 调整数量 = 实盘/目标数量
```

- 调整数量大于 0：写盘盈入库流水；
- 调整数量小于 0：按绝对值写盘亏出库流水；
- 普通盘点差额为 0：可以保留盘点明细，不写零流水；
- 授权快捷调整目标等于当前余额：返回 422，不生成无意义的 `CHECK`。

## 3. 普通周期盘点

### 3.1 建立草稿

1. 选择盘点仓库；
2. 添加货品，系统按仓库、货品、颜色读取即时库存；
3. 账面数量只读，由服务端保存时重新读取，不信任客户端传值；
4. 盘点人员填写实盘数量，`0` 是合法值，空值和负数不合法；
5. 服务端锁定本单涉及的库存维度，保存账面快照并计算盘盈亏预览。

同一盘点单不允许出现重复的“货品 + 颜色”行，避免同一库存被重复修正。

### 3.2 审核修正

审核时按固定顺序锁定本单所有库存维度，然后再次读取即时库存：

- 当前余额等于草稿账面快照：由服务端重新计算差额，写盘盈/盘亏流水和余额；
- 当前余额不等于草稿账面快照：拒绝审核，提示刷新账面数量、重新核对实盘数。

该校验用于防止“盘点后尚未审核，期间又发生出入库”的旧快照覆盖合法流水。业务上仍建议盘点期间
冻结对应库位或货品的收发，并尽快审核。

## 4. 领导授权的余额快捷调整

### 4.1 授权语义与页面流程

1. V167 只把 `stock:balance:adjust` 加入权限目录，不向任何部门默认授权；权限管理员仍可按现有机制
   明确授予个人或部门。建议点名授予领导、仓库负责人等少数人员，并定期复核；
2. 余额行先打开只读详情：compact 使用底部面板，medium / expanded 使用右侧抽屉；只有持有独立权限时
   才显示高风险「调整余额」；
3. 操作者填写**调整后的最终数量**和必填原因，页面展示当前数量与本次差额；
4. 请求携带页面看到的 `expectedQty`。服务端先锁定“货品 + 颜色”，锁后再按仓库重读当前余额；
5. 当前值已被正常出入库改变时返回 409，保留表单输入并要求刷新，不允许旧页面覆盖新流水；
6. 服务端创建并审核一张一行 `CHECK`，保存账面数、目标数、差额、原因、制单主体和审核主体；
7. 调增继续用类型 9，调减继续用类型 10，不另造库存流水类型；
8. 成功后刷新余额页。另有 `stock_doc:view` 时可打开生成的 `CHECK`；盘盈/盘亏流水也可反查该凭证。

快捷调整是**预先授予操作能力**，不是逐笔双人审批。当前同一登录操作者同时写入 `maker_id` 和
`approver_id`，结果中的 `adjustedAt` 取单据 `created_at`；模型没有独立 `approved_at`。如果业务要求
“每一笔必须由另一位领导审批”，应使用普通草稿—审核流程或另建双人审批状态机，不能把当前快捷入口描述成双人复核。

### 4.2 幂等与审计来源

客户端为一次用户操作生成 `idempotencyKey`；它是去重键，不是鉴权令牌。服务端控制
`AUTHORIZED_BALANCE_ADJUSTMENT:` 保留前缀并写入 `source_doc_no`，V167 部分唯一索引保证同键同请求
只回放原结果、不重复记账；同键被用于不同请求时返回 409。

可靠的人员和时间来源是：

- `stock_documents.maker_id` / `approver_id` 与 `created_at` / `updated_at`；
- `stock_movements.created_by` 与 `created_at`；
- 单据明细的账面数量、目标数量和差额，以及单头/明细原因。

不能依赖余额表原生 upsert 未维护的 `updated_by` 来判断修改人，也不把客户端传入身份当作审计依据。

### 4.3 正式 API 契约

```http
POST /api/stock/balances/adjust
Authorization: stock:balance:adjust
Content-Type: application/json
```

请求：

| 字段 | 必填 | 规则 |
|---|---|---|
| `idempotencyKey` | 是 | 8–128 字符；仅 `[A-Za-z0-9._:-]` |
| `warehouseId` | 是 | 已有余额行的仓库 UUID |
| `goodsId` | 是 | 已有余额行的货品 UUID |
| `colorId` | 否 | 颜色 UUID；无色库存传 `null` |
| `expectedQty` | 是 | 页面读取的旧余额，最多 14 位整数、4 位小数 |
| `targetQty` | 是 | 调整后的最终数量，`>= 0`，最多 14 位整数、4 位小数 |
| `reason` | 是 | 去空白后非空，最长 500 字符 |

示例：

```json
{
  "idempotencyKey": "stock-balance-adjust:019fb5ad",
  "warehouseId": "00000000-0000-0000-0000-000000000001",
  "goodsId": "00000000-0000-0000-0000-000000000002",
  "colorId": null,
  "expectedQty": 10,
  "targetQty": 7,
  "reason": "周期抽盘，实物少 3 件"
}
```

成功响应字段：`documentId`、`billNo`、`beforeQty`、`afterQty`、`deltaQty`、
`adjustedByEmployeeId`、`adjustedByName`、`adjustedAt`。

错误语义：

- 422：字段校验失败、目标为负、原因为空、目标与当前相同；
- 403：未持有 `stock:balance:adjust`；
- 409：`expectedQty` 已过期，或同一幂等键对应另一笔请求。

### 4.4 权限矩阵

| 能力 | 权限 |
|---|---|
| 进入余额页、查看余额和流水 | `stock:view` |
| 执行授权余额调整 | `stock:balance:adjust` |
| 查看生成的 `CHECK` 凭证 | `stock_doc:view` |
| 红冲授权调整单 | 同时需要 `stock_doc:edit` 与 `stock:balance:adjust` |
| 编辑或删除授权调整记录 | 所有受支持业务接口均禁止 |

`stock:view`、`stock:edit` 或 `stock_doc:edit` 单独存在，都不等于拥有余额快捷调整权。

### 4.5 红冲

已审核盘点单如需撤销，应追加反向库存影响，不删除或改写原流水。授权直接调整单只能在同时满足
`stock_doc:edit` 和 `stock:balance:adjust` 时红冲；受支持业务接口禁止编辑或删除原调整记录。

当前实现还有两个必须知晓的边界：

- 反向流水沿用原单 `billDate` 当天零点作为 `transaction_date`。跨日或跨月红冲会把反向量计入原业务期间，
  从而改变历史月度汇总；这是待明确的会计期间规则，不能表述成“历史期间绝对不变”；
- 红冲原盘盈会减少当前库存，如当前余额不足，负库存保护会拒绝红冲。此时不得删记录或绕过校验，
  应先核对后续出库，再决定新的业务处理。

## 5. 历史订单和历史单据

### 5.1 已完成、已审核的历史单据

原单和原流水行保持原样，不回写数量，不重算为“好像当时库存就是实盘数”。历史采购、销售、
入库、出库、领料和退料表达当时发生的业务；盘点差异通常来自漏记、损耗、计量误差或历史迁移差异，
应由新的盘点调整事件承接。

“原行不改”不等于所有历史报表期间永远不变：后续红冲会追加反向流水，且当前反向流水日期规则见 §4.5。

### 5.2 未完成订单和有效预占

不自动修改、不取消订单，也不偷偷减少预占。盘点修正的是在手库存，不是客户需求或供应承诺。

盘亏后可能出现：

```text
可用库存 = 在手库存 - 有效预占 < 0
```

此时保留短缺事实，由业务人员重新排产、采购、调仓或与客户确认，而不是通过改历史订单掩盖短缺。
最终迁移链由 V150 聚合全局和指定仓预占；盘盈会增加在手和可用库存，但不会改变订单数量。

### 5.3 退货、红冲和来源追溯

以后发生的退货或业务红冲仍关联原业务来源。盘点流水只关联盘点单本身，不能伪装成某张旧订单的
补录出入库；授权调整也必须通过其 `CHECK` 和 9/10 流水追溯。

## 6. 数量、重量与成本口径

- 盘点和授权快捷调整只修正数量，不推断或修改库存重量；重量盘点以后需要独立的账面重量、实盘重量和差额字段；
- 不修改货品单位成本 `goods.c_total`，不为快捷 `CHECK` 补写差额金额，不回算历史成本；
- `stock_balances.amount_local` 在这次数量调整中不增加金额；
- 即时库存页面的展示成本按 `goods.c_total × qty` 派生，因此目标数量变化后，**展示总成本会随数量变化**；
- 不修改历史订单、预占、单价或既有业务单据金额。如需库存计价调整，应走独立财务规则。

因此文档不能笼统写成“调整后成本完全不变”，应区分单位成本、账面金额字段和数量派生展示金额。

## 7. 其它边界

- 未列入普通盘点单的货品表示“本次未盘”，不能自动当作实盘为零；
- 大仓全盘可按区域、货类或货架拆成多张盘点单，当前单据明细上限保持 500 行；
- 盘点明细使用货品基本单位，避免换算率造成修正偏差；
- 余额页只列已有 `stock_balances` 行，当前快捷入口不能把完全不存在的“仓库 + 货品 + 颜色”从 0 调成正数；
  此类首次建账应走普通 `CHECK` 选货盘点，或以后另建受控选择入口；
- V167 提供业务层权限与幂等唯一索引，但不是数据库级 WORM。准确表述是“所有受支持业务接口禁止编辑或删除”；
- 不编辑已经执行过的 Flyway 迁移；后续规则变化必须使用新的迁移。

## 9. 验收场景

1. 账面 100，实盘 96：审核生成盘亏 4，余额变为 96，之后入库 10 得 106；
2. 账面 100，实盘 105：审核生成盘盈 5，余额变为 105；
3. 账面 3，实盘 0：允许审核，生成盘亏 3；
4. 普通盘点草稿快照 100，审核前正常出库 2：审核被拒绝，不覆盖新余额；
5. 同一货品和颜色重复两行：保存被拒绝；
6. 实盘为空或小于 0：保存被拒绝；
7. 盘亏后在手低于有效预占：订单和预占保持，系统呈现短缺；
8. 单据只盘部分货品：未列货品余额不变；
9. 无 `stock:balance:adjust`：详情不显示按钮，直接调用接口返回 403；
10. 授权调整 10 → 7：余额变 7，记录原因、当前操作者和盘亏 3，之后入库 2 得 9；
11. 页面显示 10、提交前正常出库到 9：返回 409 且不产生调整单；
12. 同一幂等键、同一请求重试：返回原单号，不重复生成单据或流水；
13. 同一幂等键换参数：返回 409；
14. 授权快捷目标等于当前量：返回 422；普通盘点仍可保存零差额盘点明细；
15. 无 `stock_doc:view`：调整可以成功，但不能查看生成凭证；
16. 仅有 `stock_doc:edit` 或仅有 `stock:balance:adjust`：都不能红冲授权调整单；
17. 不存在余额行的库存维度：余额页不提供快捷入口，改走普通 `CHECK`；
18. 调整数量后：单位成本、余额金额字段、重量、历史订单和预占不变，派生展示总成本按新数量变化；
19. 跨月红冲：追加反向流水并按当前日期规则进入原业务期间，财务验收该口径或另立后续改造。
