  一、到底做了啥
  真后端、真数据库、真登录、真权限、机密数据真加密。目前人事模块（员工/部门/账号）和登录鉴权这条链路是真后端、已经从头到尾跑通验证过了；其他模块（工资/报销/通知/建议/生产）还是假数据，等你做到那个阶段再接。

  分三块：后端（Java Spring Boot）、数据库（PostgreSQL）、前端（Flutter）。

  ---
  二、怎么实现的（原理，大白话）

  1. 登录这件事，从头到尾发生了啥

  你说"现在不仅是前端，后端也要实现"——核心就是登录要"真"。

  以前的假登录：输啥都能进，密码根本没看。

  现在的真登录（员工）：
  1. 你输账号（工号）+ 密码，前端发给后端 /api/auth/login。
  2. 后端拿账号去数据库查这个人。密码不是明文存的——存的是用 Argon2id（一种单向哈希算法）算出来的一串乱码。后端把你输的密码也哈希一下，跟数据库里那串比对，一样才放行。就算数据库被偷，黑客也拿不到真密码。
  3. 登录成功，后端发两个"通行证"回来：
    - access token（JWT）：短期的，15 分钟过期，前端每次请求带它证明"我是谁"。
    - refresh token：长期的，7 天，access 过期了用它换新的（不用重新输密码）。
  4. 前端把这两个令牌存进 flutter_secure_storage（手机的安全区：苹果 Keychain / 安卓 Keystore），绝不存 shared_preferences（那是明文的）。

  默认密码：
  - admin（引导超管）：密码来自 .env 里的 BOOTSTRAP_ADMIN_PASSWORD。
  - HR 新建的员工：密码 = 身份证后六位。HR录入身份证时，后端在内存里取出后六位、立刻哈希、然后只把哈希存库——后六位明文绝不落库、不记日志、不返回给任何人。
  - 不管哪种，第一次登录都被强制改密码（改之前啥也干不了，只能停在改密页）。

  2. 权限：谁能看啥、谁能干啥

  不是"登录了就能看所有"。每个人有角色（员工/人事/财务/管理层/管理员…）和权限点（employee:view、payroll:generate这种）。

  - 三层卡：
    a. 路由级：前端路由守卫——你没 employee:view 权限，直接输 /employee 网址也进不去，被踢回工作台。
    b. 按钮级：没权限的按钮直接不显示（不是变灰——变灰反而暴露"这里有功能"）。
    c. 数据级（最关键）：后端才是真关卡。前端藏只是体验，黑客绕过前端直接打 API，后端照样拦。
  - 数据脱敏：身份证/手机/银行卡 → 只有 hr+管理员 能看全；薪资 → hr+财务+管理员 能看；管理层/普通员工永远看不到别人的薪资和身份证。这个是后端返回数据时就按你角色抹掉/打码的，前端拿到的已经是脱过敏的。

  3. 机密数据怎么加密（这是你最担心的）

  身份证、手机、银行卡、薪资这些，在数据库里不是明文。用的是 PostgreSQL 自带的 pgcrypto：
  - 存进去前，用主密钥（UTEN_PGP_MASTER_KEY）加密成乱码再存。
  - 密钥不在代码里、不在 SQL 里——放在 server/.env（这个文件不进 git），后端启动时读进来用。
  - 我还做了密钥版本化：每条密文前面带个版本号（1:xxxxx）。以后想换密钥，旧数据用旧密钥照样能解开，不会"一换密钥全变乱码"。
  - 身份证查重：身份证是加密存的，没法直接"查重"。我用 HMAC（另一种单向哈希，同样的输入永远得到同样的输出）单独存了一列id_card_hash，加唯一索引——同一个人想重复入职，第二次直接 409 拒绝。
  - 审计日志：谁、什么时候、改了啥，都记进audit_log。而且我专门处理过——密码哈希不会被复制进审计表（一开始审计会把整行原样记下来，包括密码哈希，我改掉了）。

  4. 前端怎么连后端

  前端用 dio（一个 HTTP 库）发请求。我做了个拦截器机制：
  - 每次请求自动把 access token 塞进请求头。
  - 如果后端回 401（令牌过期），拦截器自动用 refresh token 去换新令牌、然后重发刚才那个请求——你完全无感。换不到（refresh也过期了）就自动退出登录、跳回登录页。
  - 我修过一个坑：登录失败时本来也会误触发"换令牌"逻辑，把人莫名登出——已经改成登录/刷新接口的 401 不触发这个。

  5. 防爆破、防猜测

  - 限流：同一 IP 1 分钟最多试 5 次登录。
  - 锁定：连续错 5 次密码，锁 15 分钟，到点自动恢复。
  - 防"账号枚举"：猜账号时，"账号不存在"和"密码错"返回一模一样的提示（都只说"账号或密码错误"），黑客猜不出哪个账号是真的。而且为了防止通过"响应快慢"猜（存在的账号要算哈希、慢；不存在的快），不存在的账号我也故意跑一遍假哈希抹平时序。

  三、你以后要注意啥（重点）

  A. 怎么跑起来（依赖我装好的环境）

  我给你装了 JDK 21（winget）和 Maven 3.9.16（阿里云镜像）。以后跑后端：
  cd server
  docker compose up -d postgres     # 起数据库
  mvn spring-boot:run               # 起后端（会自动建表、建 admin）
  前端： flutter run --dart-define=API_BASE_URL=http://localhost:8080/api -d chrome

  ⚠️ 几个坑：
  - 数据库端口我改成了 5433（你 5432 被另一个项目 justplay 占了）。.env 里 UTEN_DB_URL 也是 5433，别改回 5432，会冲突。
  - server/.env 是真密钥（已 gitignore，不进库）。.env.example 是模板。生产环境密钥要从服务器环境变量或 Vault注入，别把开发 .env 带上线。
  - 当前跑着的库里，admin 密码被我测试时改成了 NewPass1234。你要想恢复默认，删库重建即可（admin 会回到 Admin@12345并要求首登改）。

  B. 安全红线（这几条别犯）

  1. 密钥/数据库密码/JWT 密钥/HMAC 密钥——永远在 .env，永远别写进代码、别提交 git。我已经设成"缺了就启动失败"（fail-fast），所以你忘配它会直接报错提醒你，不会悄悄用个弱默认值。
  2. 令牌只存 flutter_secure_storage，别图省事存 shared_preferences。
  3. 权限校验后端必须做，前端藏按钮只是体验。新加任何写接口，记得加 @PreAuthorize。
  4. 机密字段（身份证/薪资/银行）走加密 + 按角色脱敏，别图方便直接返回明文。

  C. 哪些还是"假的"（Mock），别以为是真功能

  现在真后端的只有：登录/改密/权限、员工档案、部门、账号管理。
  还是假数据的：工资条、报销、通知、建议箱、生产/实验室/库存。这些页面能看、能点，但数据是前端写死的，没走后端。等做到那个 Phase 再接（接的时候照着 HR 的 Repository 模式抄就行，业务代码基本不动）。

  D. 改东西"一处改全站变"——组件化

  你强调过要组件化、卡片化。我按这个做了：
  - 人物/实体展示统一用 UtenPersonCard；员工状态统一用 EmployeeStatusBadge；部门树统一用 DepartmentTree。
  - 以后想改"员工卡"长啥样，只改 UtenPersonCard 一个文件，全站员工卡一起变。 别在某个页面里手搓Card/ListTile——那就又散了。
  - 列表页统一用 UtenResponsiveGrid（卡片瀑布流），别用 ListView。

  E. 你正在加的"访客模块"——它是踩在我搭的地基上

  我看到你在并行做访客（手机验证码登录、二维码、保安扫码、访客审批）。它复用了我搭的鉴权地基：AuthUser 现在分staff/visitor 两类、JwtAuthFilter 按令牌里的 typ 区分、路由守卫也加了访客分支。
  注意：
  - 访客的权限点（visitor:view/visitor:approve/visitor:check-in）要在后端 permissions 表里建好、给对应角色配上，前端permission_by_path 我看到你也加上了——保持前后端权限码一字不差对齐。
  - 访客的手机号/身份信息如果敏感，照样要走 pgcrypto 加密（别明文存），别破坏了整套安全规范。

  F. 改完一定要验证（别只靠眼睛）

  - 前端：flutter analyze（我每次改完都跑，保证零错误）。
  - 后端：mvn compile（能编译）+ mvn spring-boot:run（能起来）+ 实际 curl 几个接口。Java 没法像 Flutter那样"保存就看出来错"，不跑 mvn 你不知道哪里写错了——我这次就靠真跑后端揪出了 4 个真实 bug（懒加载崩溃、表缺列、时间类型不兼容、入职对象冲突）。
  - 数据库：docker exec -it uten-imp-postgres psql -U uten -d uten_imp 进去看数据对不对；或 DBeaver 连 localhost:5433。
