## 一、迁移目的

V430 把新生产成品的目标仓与逐行库位从生产日报移到仓库送检登记：

1. 日报草稿保存不产生仓库任务、FQC 或入库单。
2. 日报审核只写有效 `fqty`，并使权威“待仓库送检登记”任务可被重建。
3. 仓库选择成品仓并逐行冻结 `place`；登记事务不录实际数量、不写库存、不增加 `iqty`。
4. 同一仓库登记事务逐行创建 FQC PENDING。
5. 品质 PASS 后才沿既有 release ledger 生成 FINISHED_IN；V338 最终点收的 `accepted_qty/iqty` 才是库存与完成率权威。

这不是 WMS 库位分账迁移。当前库存维度仍是 `warehouse + goods + color`；`place` 是交易快照，`goods.stock_place` 只是页面预填建议。

## 二、V430 数据职责

V430 的前向结构和数据库函数必须共同承担以下职责：

| 领域 | V430 职责 | 明确不做 |
|---|---|---|
| 待登记任务 | 以已审核、未红冲日报及“尚无成功仓库登记”的事实形成可恢复任务；通知不作为权威 | 不在普通草稿保存时建任务，不用通知未读数当任务数 |
| 幂等命令 | 绑定操作者、稳定幂等键、规范请求哈希和终态登记结果；同键同体回放、同键异体冲突 | 不允许客户端重试重复登记 FQC |
| 仓库登记 | 冻结来源日报、目标仓、操作者和逐行 `source_report_item_id + place` | 不允许增删行、换货品、改报工量或填写实收量 |
| FQC 接线 | 仓库登记与逐行 inspection 在同一事务完成；新 inspection 从登记读取仓库与库位来源 | 不再要求新 inspection 从日报头仓库猜测，不回填历史 PASS |
| FINISHED_IN | PASS 后创建草稿时继承 inspection/登记的 warehouse/place 与完整 UUID 来源 | 不在仓库送检登记时写库存、`iqty` 或生产完成 |
| 历史兼容 | 既有 inspection、FINISHED_IN、V338 confirmation、V418 residual/replacement 和 V414 exemption 原样保留 | 不改写历史日报仓库，不用当前货品主档猜历史库位 |

V430 可以前向替换 V410/V338 后由当前源码调用的校验函数或触发器定义，但不得修改、删除、重命名任何已应用迁移文件。已应用 checksum 不一致、源码缺失或版本集合不一致一律停止；禁止 `flyway repair`。

实际 V430 结构为：

- `production_finished_arrival_registrations`：一张日报唯一的登记头，冻结 `warehouse_id`、仓库编码/名称快照、当前收货员工 UUID/姓名快照、操作者、幂等键和请求哈希；`created_by + idempotency_key` 唯一。
- `production_finished_arrival_registration_items`：每条日报明细唯一的登记行，冻结 `place_snapshot`；库位 trim 后长度为 1–100。
- `fn_guard_production_finished_arrival_registration`：只接受已审核日报和有效、可核算、未禁用仓库；登记头只追加。
- `fn_guard_production_finished_arrival_item`：登记行必须属于同一日报、带 execution segment，且不存在 inspection 或 legacy exemption；登记行只追加。
- `fn_require_complete_production_finished_arrival`：可延迟约束在事务提交前确认登记逐行完整覆盖日报活动明细。
- `fn_guard_production_fqc_inspection`：前向替换 V410 新增 inspection 的来源校验，从登记头读取仓库并要求精确登记行；既有 inspection 的投影更新仍走历史兼容分支。
- 两张登记表均接 `fn_audit()`；迁移没有历史登记回填，也不更新日报、inspection、FINISHED_IN、库存或货品主档。

## 三、数据库守恒

### 3.1 登记来源与完整性

新在线登记必须同时满足：

- 日报已审核、未删除、未红冲；每个来源行未删除且精确关联允许报工的计划行和执行段。
- 请求逐行 UUID 集合与当前日报活动明细集合完全相等；不允许遗漏、重复或额外行。
- 目标仓存在、有效、可核算且未禁用；每行 `place` 是仓库本次确认的交易快照。
- 当前登录员工自动成为 `receiver_employee_id`，姓名以登记时快照冻结；请求不能指定或冒充收货人。
- 一个来源日报和每条日报行只有一个永久登记身份；并发请求不能生成两套登记或 inspection。
- 登记行与 inspection 的日报、计划行、执行段、销售分摊、货品、颜色、单位、换算率和申报数量完全一致。
- 登记、命令、逐行快照和后续 inspection 均接审计；业务身份不可普通更新或删除。

### 3.2 数量权威

```text
reported_qty / fqty = 生产已审核有效完工申报
passed_qty           = 品质合格放行额度
accepted_qty / iqty  = 仓库最终实收与库存权威
```

仓库送检登记不接受实际数量字段。登记前后必须满足：库存余额不变、库存流水行数不变、计划 `iqty` 不变、执行段完成状态不变。只有 V338 `finished-in/confirm` 的正数 `acceptedQty` 可以增加库存和 `iqty`。

### 3.3 仓库与库位谱系

- V430 后新 inspection 的仓库来源必须是成功的仓库登记，不是 `production_daily_reports.warehouse_id`。
- PASS 创建的首次 FINISHED_IN 明细必须继承对应登记行的 `place`；仓库头必须继承登记目标仓。
- V338 短收 residual、V418 整单拒收重交和专用红冲 replacement 继续继承原仓库与 `place`，不得从 `goods.stock_place` 或页面当前值重新计算。
- `goods.stock_place` 后续修改不得改变登记、inspection、FINISHED_IN 或历史 confirmation 的快照。

## 四、目标非空库迁移前只读盘点

先在只读目标身份和已经验证可恢复的副本执行。不得为让结果“好看”而直接修改目标数据。

### 4.1 Flyway exact-set

```sql
SELECT installed_rank, version, description, script, checksum, success
FROM flyway_schema_history
ORDER BY installed_rank;

SELECT max(version::int) FILTER (WHERE success AND version ~ '^[0-9]+$') AS head,
       count(*) FILTER (WHERE success AND version IS NOT NULL) AS versioned_count,
       count(*) FILTER (WHERE NOT success) AS failed_count
FROM flyway_schema_history;
```

发布时以同一受保护构建产出的 migration manifest、JAR 内资源和目标 `flyway_schema_history` 三方 exact-set 为准。本文不冻结并行开发中的全局迁移数量或头常量。

### 4.2 旧链完整性基线

```sql
SELECT count(*) AS approved_report_items,
       count(inspection.id) AS with_inspection,
       count(exemption.source_report_item_id) AS with_legacy_exemption,
       count(*) FILTER (
           WHERE inspection.id IS NULL
             AND exemption.source_report_item_id IS NULL
       ) AS unexplained_without_quality_identity
FROM production_daily_report_items item
JOIN production_daily_reports report
  ON report.id = item.report_id
 AND report.is_deleted = FALSE
LEFT JOIN production_fqc_inspections inspection
  ON inspection.source_report_item_id = item.id
LEFT JOIN production_fqc_legacy_exemptions exemption
  ON exemption.source_report_item_id = item.id
WHERE item.is_deleted = FALSE
  AND report.status = 1;
```

V430 切点前的已审核在线日报通常应已有 inspection 或精确 legacy exemption。存在无法解释的缺口时必须先形成业务核对清单，不能把它们批量伪造成仓库已登记或 FQC PASS。

同时冻结并保存：

- 已审核日报、日报明细、当前 `fqty/iqty` 汇总；
- PENDING/PARTIAL inspection 和 PASS release 余额；
- 活动 FINISHED_IN 草稿、V338 confirmation、V418 residual/replacement 数量；
- 库存余额/流水、计划完成状态和相关 Outbox 数量；
- `goods.stock_place` 非空量，仅作为建议字段基线，不作为交易快照回填源。

## 五、迁移后验收

### 5.1 新切点行为

必须用 V430 后新建的数据证明：

1. 日报草稿保存、修改和退出均无仓库待登记任务、inspection、FINISHED_IN 或库存变化。
2. 审核只增加一次有效 `fqty`，任务可从业务表重建；通知删除或投递失败不隐藏任务。
3. 仓库登记覆盖全部行，成功后每行恰有一个 inspection；登记前后库存、`iqty` 和完成率不变。
4. 相同幂等键同体安全回放，同键异仓/异库位冲突，并发双登记只有一个成功。
5. PASS 后首次 FINISHED_IN 的仓库与 `place` 精确等于登记快照；未 PASS 行没有可消费入库额度。
6. 最终全收、短收、整单零实收、重新交付和专用红冲继续满足 V338/V418 数量及 UUID 谱系守恒。

### 5.2 历史兼容

- V430 前已有 inspection 无需、也不得补仓库登记；原 inspection 仓库仍为历史权威。
- V414 exemption 不自动变成登记或 PASS。
- 既有活动 FINISHED_IN 可继续走 V338 点收；其仓库、来源和已存在 `place` 不被迁移重写。
- 迁移不得把 `goods.stock_place` 批量复制到旧单据行，也不得把日报仓库批量解释为仓库实际确认。

### 5.3 权限负向

岗位验收至少覆盖：

- `stock_doc:view` 仅允许读取有权任务；登记还需 `stock_doc:approve` 与有效 `SUB_WH` 组织范围。
- 计划/生产/品质账号即使知道日报 UUID，也不能提交仓库登记。
- QA 的 `production_quality_inspection:view/approve + DEPT_QA` 组织池规则不因 V430 放宽。
- 当前没有仓库到员工或库位到员工的细粒度分配，验收报告不得声称单仓/单库位授权已经完成。

## 六、自动化与发布边界

最低自动化应包括：V430 静态迁移合同、真实 PostgreSQL 空库迁移、V430 切点前后非空兼容、幂等/并发登记、数据库不可变守卫、审计覆盖、日报反向、FQC PASS/FAIL、V338/V418 点收重交和四岗位正负权限测试。

空库、合成非空或本地链通过仍不等于公司目标数据库迁移、历史数量对账、真实实物交接、多岗位 UAT、恢复或发布。正式窗口必须使用同一签名候选、已验证备份和 exact-set manifest；失败只能新增更高版本前向修复，或恢复到已演练且与旧版本完全一致的备份。

禁止修改已应用迁移、手工改 `flyway_schema_history`、删除约束/审计、使用 `flyway repair`、用旧 JAR 覆盖新 schema，或用页面状态/通知/`goods.stock_place` 冒充仓库登记、FQC 与库存事实。上述目标侧证据不全，生产继续 **NO-GO**。
