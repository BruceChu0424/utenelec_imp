# ADR-042 委外全链路重设计：订货→仓库出仓→加工→仓库回仓

- 日期：2026-08-20
- 状态：已采纳（源码候选；空库 287 迁移重放 + 全链路 HTTP 冒烟 30/30 通过；目标库迁移与岗位 UAT 未完成，生产 NO-GO 口径不变）

## 背景

委外是「公司的物料给委外商加工」：与采购（只进不出）的根本差异是**先出（材料）
后进（成品）**。旧链路里材料出仓单由委外模块手工新建、手工从订货引入，存在四个断点：

1. 委外订货只能由计划申请分解生成，委外部门不能自建订货单（业务上两条来源都存在）；
2. 财务批准订货后没有任何自动化的出仓依据，仓库不知道该发什么料、发多少；
3. 仓库没有自己的委外出仓页面（出仓在委外模块操作，职责错位）；
4. 订货单看不到出仓/回厂/IQC/应付的全链路进度；发 1 吨回来不足 1 吨的损耗差异没有
   结案核销与向委外商追偿的账务通道。

## 决策

1. **发料计划快照 + 自动出仓草稿（V304）**：财务批准委外订货的同事务，按批准时 BOM
   一级子件展开生成 `subcontract_material_plans/items`（`planned_qty = 订货量 × bom_unit_qty`
   冻结快照），并自动生成一张全量出仓单草稿（EC 单号、委外商随订货单、发出仓留空、
   maker 置空=系统生成）。订货货品无 BOM 子件时不建计划（委外商自备料）。
2. **出仓执行归仓库**：新仓库专属页面「委外出仓任务中心 + 拣货出仓页」
   （不复用委外单据页；全页无价格金额字段）。草稿的编辑/审核走既有
   `/api/subcontract/material-issues` 端点（数据通用）；maker 为空的系统草稿凭
   `subcontract_material_issue:edit` 权限放行（V304 授权 SUB_WH），自有手工单维持
   maker 归属隔离不变。
3. **分批出仓闭环**：草稿改量审核后按计划行 CAS 回写 `issued_qty`（防超计划 409），
   余量且无未审草稿时自动续生下一批草稿；红冲对称回减；「不再出仓」可手工关闭余量
   （必填原因）；订货红冲先被既有守卫拦截（有已审下游），通过后软删未审草稿 + 计划
   CANCELED。
4. **手工订货放行**：订货明细 `application_item_id` 允许为空（委外自建手工行），
   DTO `@NotNull` 与保存/提交财务的来源校验只作用于申请分解行；手工单批准后同样
   生成发料计划 + 预计回厂任务。
5. **全链路进度**：`GET /api/subcontract/orders/{id}/progress` 聚合 财务审批 →
   发料计划/出仓单 → 进仓单/IQC → 退货/损耗 → 供应商处材料台账（V221 守恒）→
   应付摘要；订货单详情新增「全链路进度」区，单号可点进只读详情。计划部物料分析
   供给进度链同步插入「材料出仓」步骤（委外路线独有，`MATERIAL_ISSUED`）。
6. **损耗结案与财务联动**：损耗单新增 `deduct_amount`（本币扣款，默认 0=公司承担），
   >0 审核立负应付（AP/SUBCONTRACT_WASTE，V304 扩 `ar_ap_ledger` 来源 CHECK），
   红冲先反立账；应付汇总/对账单按供应商口径自然体现（委外商共用 suppliers 主档，
   不新建财务卡片）。损耗/材料退的默认量改为供应商处结存（发出−回厂已消费−已退−已损耗）。
7. **委外 hub 瘦身**：只留 委外订货单 + 计划下达的申请（只读）+ 三张报表；
   询价/发料/进仓/退货/材料退/损耗六卡移除（路由与权限保留，历史链接不受影响）；
   仓库 hub 任务中心加「委外出仓」卡（角标=待出仓计划数），单据区补委外四执行单历史卡。
8. **独立权限点（V305，bruce 2026-08-20 口径「权限设置里授权才可见/可操作」）**：
   `subcontract_outbound:view/handle` 两个新权限点管辖出仓工作台（看任务 / 拣货审核关闭），
   权限管理页可对任意部门/个人授权或收回；默认只授仓库本职 SUB_WH（V196/V296 同先例），
   委外/财务/品质默认均不可见（UAT A7a–A7e 验证：未授权 403、授 view 可见、
   无 handle 不可操作）。单据本身仍受 `subcontract_material_issue:view/edit` 管辖，
   两层独立可收回。两个 hub 的全部卡片同步改为按权限点显隐，无权限整组隐藏。
9. **顺带修复（本链路暴露的既有 bug）**：预计到货列表在委外自建单（无分析来源、
   无建议仓）下 `ImmutableCollections$MapN.get(null)` NPE → 短路保护；
   到货异常一键入库的收货单审核改明细触发 receipt_item 守卫 →
   `stockInWithDecisionSession` 同事务打开决策会话开关。

- 新迁移：V304（计划两表 + plan_item_id + 损耗扣款两列 + ar_ap_ledger CHECK 扩 +
  SUB_WH 四单权限 seed + 新表审计触发器）+ V305（出仓工作台独立权限点 + SUB_WH 默认授权）+
  V306（V304 新业务表之后刷新并 fail-closed 校验全 `public` 审计触发器覆盖）。
- 新后端：`SubcontractMaterialPlanService`、`/api/warehouse/subcontract-outbound/*`、
  `GET /api/subcontract/orders/{id}/progress`、`LinkedOrderReadGate`（仓库执行的物流单
  对订货归属人只读放行）；改造 订货/发料/损耗 Service 与物料分析供给进度
  （委外插 MATERIAL_ISSUED 步）。
- 新前端：仓库出仓任务中心 + 拣货出仓页、订货单「全链路进度」区、损耗扣款字段、

## 备选方案

- **出仓任务用独立任务表（仿 inbound_expectations）而非自动草稿**：被否——自动草稿
  更贴「财务通过仓库自动开出仓单据」的业务表述，且复用发料单既有审核/库存/守恒链路，
  不引入第二套单据生命周期。
- **损耗扣款进一般费用单而非负应付**：被否——扣款对象是委外商（供应商），负应付直接
  冲减对该商的应付余额，对账口径与采购退货一致；费用单则丢失供应商维度。
