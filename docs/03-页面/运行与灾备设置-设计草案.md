# 运行与灾备设置 - 设计草案

日期：2026-10-23。状态：待评审，仅规定界面与交互，尚未实现或部署。

依据：[ADR-183](../99-决策记录-ADR/ADR-183-本地业务服务与受控远程入口.md)、现有 [设置页](../../lib/features/settings/pages/settings_page.dart)、[服务器状态页](../../lib/features/admin/pages/server_status_page.dart)、[服务器更新页](../../lib/features/admin/pages/server_operations_page.dart)。灾备服务、密钥托管和隔离机制以正式架构方案为准；本页不将现有客户端服务器选择器解释成灾备能力。

## 1. 页面任务与入口

正常情况下，公司本地承办业务；云端承担原有受控远程入口与加密备份。故障时，由超管选择恢复点和已登记的备用目标，在旧主可靠停止写入后启用备用服务。全程只有一个业务写主。

- 设置中的现有“服务器”行改为“运行与灾备”，只打开一个统一页面。普通员工只看到“本机连接”和当前服务说明；超管可经控制面验证后查看备份与灾备操作。
- 本机的“本地 / 云端 / 自动”连接偏好继续复用现有连接对话框，分组名为“本机连接”。旁注：“只影响这台设备的连接，不改变公司业务运行位置。”
- 服务器状态页仅显示运行摘要与指向统一页面的“查看运行与灾备”，放在状态请求的失败分支之外。服务器更新继续使用既有更新作业页，不混入接管按钮。
- 登录页与连接失败页保留“运行与灾备”直达同一路由。页面外壳、预登记的控制面地址和救援登录不依赖本地业务 API、当前业务会话或远程权限查询成功。
- 原生客户端和独立托管的救援 Web 页面均能打开同一控制面。仅从故障本地主机提供的 Web 资源不能充当救援入口；救援地址须在正常时期登记并提供可保存的直达链接。

本地业务不可达时，页面先显示：“本地业务服务暂不可达。可查询备用状态；不会自动改变业务运行位置。”控制面也不可达时显示：“暂时无法连接灾备控制服务，无法确认运行位置。请使用已登记的运维恢复方式。”不得显示缓存状态为实时状态，或提供绕过验证的“强制启用”。

## 2. 视觉与页面结构

使用 `frontend-design`，沿用 Uten 的青绿交互色、slate 中性文字、既有字体与间距，不重做监控图表。浅色参考值为背景 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、次级文字 `#475569`、交互 `#0D9488`；警告和错误使用现有语义 token，深色模式由主题映射，不能只凭颜色识别状态。

```text
运行与灾备                                      刷新
当前业务运行位置：公司本地   [正常运行]   核实于 …
本机连接：自动 / 当前连接 …                    调整连接
────────────────────────────────────────────────────
备份与恢复保障
云端加密备份：可恢复至 …      备用目标：…
最近恢复演练：… / 尚未验证                   管理备份
────────────────────────────────────────────────────
恢复与接管
当前：尚未开始恢复作业
                                               开始恢复
────────────────────────────────────────────────────
最近作业与操作记录                              查看记录
```

复用 `UtenAppBar`、`UtenContentContainer.narrow`、`UtenStatusBadge`、`UtenButton` / `UtenActionButton`、`UtenDialog` 与既有设置行。用分组和分隔线表达层级，当前业务运行位置始终位于页首；恢复期间将“恢复与接管”展开成作业进度，其他分组保留摘要。

所有内容左对齐。窄屏与 200% 界面大小下改为单列，字段名、值、按钮依次排列；恢复点详情和确认按钮不依赖横向滚动。宽屏最多两列详情，主操作保留一个。错误就地解释阻塞原因，操作反馈用 `AppNotification`；加载、未知、已核验必须有明确文字。

评审取舍：不以“云端开启”开关表示运行模式，不增加一排等权功能卡，也不把“备份成功”显示为“可接管”。本页面的视觉重点是当前写主和当前恢复作业，便于在事故中判断下一步。

## 3. 设置项目与最小按钮

| 区域 | 展示与可编辑内容 | 必要按钮与中文文案 |
|---|---|---|
| 当前运行 | 本地或具体备用站点、核实时间；配置和实测状态分开，运行代次只放在超管作业详情 | `刷新`；故障时出现 `开始恢复` |
| 本机连接 | 当前连接目标与连接偏好；Release 只允许可信已登记入口，普通用户不能输入任意主机 | `调整连接` |
| 备份策略 | 数据与附件的成套范围、备份频率、保留期限、已选择目标；保存前核验目标身份和恢复密钥可取回 | `编辑备份策略`、`保存设置` |
| 备份目标 | 云端密文存储、公司备用存档等已登记目标的多选列表；每项显示身份核验、可写、完整性与最近成功时间 | `管理目标`、`验证目标` |
| 恢复保障 | 最近一次隔离恢复演练、样本核验和测得耗时；没有证据就显示“尚未完成恢复验证” | `恢复演练`、`查看记录` |
| 恢复与接管 | 恢复点、接管目标、事故原因、当前作业；正常时期不常驻直接启用按钮 | `开始恢复`；后续按钮由作业状态决定 |

备份目标和业务接管目标是不同能力。可以同时选择多个备份目的地，但每次接管只选一个已通过运行验收的目标。例如 `192.168.1.253` 若只具备存档能力，则显示“备份存档，不能接管”，不出现在可启用列表中。目标无能力证明时不能凭地址或在线探测变成可选主站。

界面只显示密钥版本、凭据引用和托管状态，不回显数据库口令、私钥、解密密钥或恢复码。云端备份说明固定为：“正常备份仅保存密文；恢复时由受控流程为所选目标取用密钥。”目标不能自行得到启用权。

## 4. 恢复向导

每步都是同一个持久化恢复作业，不创建多个互相独立的弹窗命令。恢复时间使用完整日期、秒和明确时区，避免把备份完成时间误认为数据可恢复截止时间。

| 步骤 | 用户需看清的内容 | 操作及限制 |
|---|---|---|
| 选择恢复点 | 可恢复截止时间、成套数据库 / 附件、清单校验、需要的密钥版本、最近恢复验证；备份完成时间单独标注 | `下一步`。只允许完整且可解密的恢复点；显示“预计缺少此时间之后的数据”，未知时明确“尚无法确定” |
| 选择备用目标 | 已登记云端或其他合格站点、版本兼容、容量与运行验收；一次只选一个 | `检查恢复方案`。选择地址不等于启用，失败原因逐项列出 |
| 恢复并核验 | 向隔离环境恢复并检查业务库、附件、历史密钥、审计链和后台任务；不对员工开放写入 | `恢复并检查`。完成后显示“恢复完成，尚未启用” |
| 隔离旧主 | 明确将被隔离的旧主，以及数据库 / 主机 / 存储写入阻断的可信回执 | `隔离旧主`。旧主不可达不等于已隔离；不能用客户端勾选“我已停机”作为证明 |
| 启用备用 | 最终核实目标、恢复点、可能缺失数据、旧主隔离回执、将撤销旧会话及恢复后的权限复核 | `启用备用服务`。重新强认证后确认；后端再次检查方案版本与全部门禁 |

事故原因提供“设备故障 / 疑似入侵 / 计划维护”。疑似入侵时提示选择已知安全的恢复点，并显示其与事件时间的关系；时间未查明时不得默认声称最新备份安全，也不覆盖受影响主机或删除原始证据。

确认页只保留一条主按钮，文案例如“启用云端备用服务”，正文明确“公司业务将改由此站点承办；所有设备需重新登录”。要求用户核对目标和恢复时间，不以逐字输入文字替代服务端隔离证据。方案过期或证据变化时返回“恢复方案已变化，请重新检查”，不能沿用旧确认。

## 5. 状态与中断

| 状态 | 页面文案 | 当前可用操作 |
|---|---|---|
| 本地正常 | `公司本地正在承办业务` | 管理备份、恢复演练、开始恢复 |
| 本地不可达 | `本地暂不可达，运行位置尚待确认` | 查询控制面、救援登录；验证后才能开始恢复 |
| 恢复准备 / 核验中 | `正在恢复备用环境，尚未开放业务` | 查看进度；隔离旧主之前可 `取消准备` |
| 等待旧主隔离 | `旧主尚未确认停止写入，暂不能启用备用` | 隔离旧主、刷新证据 |
| 已隔离、待启用 | `旧主已隔离，备用服务等待启用` | 启用备用服务；不能自动重开旧主 |
| 备用启用中 | `正在启用备用服务，请勿重复提交` | 查询原作业 |
| 备用运行 | `当前由所选备用站点承办业务` | 查看接管记录、准备回切 |
| 结果未确认 / 作业失败 | `尚未确认原作业结果` / 明确失败阶段和影响 | `查询原作业`、`查看处理说明`；不把超时显示为已回滚 |
| 回切中 | `正在核验回切，当前写主见页首` | 查询原作业；旧站点不能自行恢复写入 |

进度依据服务器作业回执，不用倒计时推算成功。关闭页面、进程重启或更换设备后按原作业 ID 恢复查询；不重复发起启用或恢复。原作业未终结时，另一位超管只能接续查看与经授权处理，不能另开并行接管。只在执行方提供安全取消语义时显示取消按钮。

演练始终带“隔离演练，不改变当前业务服务”标识，禁用通知、外部回调和正式后台写出；演练成功只生成验证记录，不出现直接切换员工流量的确认。演练与正式接管不能共享可写业务库。

## 6. 回切与普通员工体验

备用运行后，`准备回切`建立独立作业：核实修复后的本地目标 → 将备用期间新增数据完整同步到本地候选 → 检查成套附件和权限 → 安排短暂停写 → 隔离当前备用写主 → 最终追平与核验 → `切回公司本地`。回切确认页必须显示“已包含备用运行期间新增数据”；不得用故障前旧库直接覆盖。

普通员工始终只看到一个已确认的业务运行位置。作业完成并校验入口之后才提示：“业务服务已恢复，请重新登录。”员工客户端接收可信运行代次与入口，清理旧会话并重新核对权限；不自动重放中断的业务提交。本机草稿继续按服务器 / 业务代次隔离，待确认提交显示“请先核对原提交结果”。

原有受控远程入口仍遵守 ADR-183。人数显示“远程已授权 X / 5 人”，不是在线窗口数；MFA、账号撤权和远程授权不随灾备自动放宽。接管计划须说明哪些员工能进入备用站点；如需全员临时在异地办公，应先完成明确的网络和授权方案，不能以“灾备模式”直接解除既有边界。

## 7. 权限与验收

业务设置入口可以展示连接帮助，灾备目标编辑、正式恢复、隔离旧主、启用和回切仅限超管本人，并要求独立控制面强认证、理由和审计。模拟身份、只读会话不能操作。现有 `authorization:manage`、业务会话和本机缓存的超管标记均不能自动获得灾备执行权；具体权限码按正式架构落实，不在设计稿中假装已经存在。

救援超管须在正常时期预先登记并具备独立因子与撤销机制。本地后端离线时依然由控制面核实该身份；未预置救援身份时给出运维恢复指引，不回退为旧备份角色或客户端缓存授权。密文备份回滚不能复活已撤销的会话、MFA 证明、超管或远程授权；权限状态不确定时先阻止放行业务并提示复核。

实现验收至少覆盖：本地主机彻底停止后仍能从登录页及独立救援页进入；单纯客户端切换不改变写主；缺密钥 / 缺附件 / 无隔离回执时不能启用；启用超时只查原作业；两名超管并发不能形成双主；疑似入侵不自动采用最新恢复点；演练没有正式写出；备用新增数据随回切保留；普通员工和模拟身份无执行权限；360px、深色、200% 界面大小下关键信息与确认操作可达。

本稿不代表独立控制面、云端加密备份、救援身份或任一备用目标已经具备上线能力；这些均须有实现和实机验收证据后才能在页面显示“已就绪”。
