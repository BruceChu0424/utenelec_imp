## UT0029 包材仓诊断与修复

公司服务器限定只读 SQL 核对（READ ONLY、15 秒语句超时，未改账号、权限、仓库、单据或服务器配置）：

- 员工 UT0029 的有效账号处于 active，仓储部门有效。
- 包材仓 WH000008 启用、参与核算、良品普通叶仓，`fn_warehouse_is_good_stock_leaf` 返回 true。
- 包材仓负责人包含 UT0029；`fn_user_warehouse_access` 返回 KEEPER 且负责/可见范围包含包材仓。
- 授权源包含 `warehouse:view`、`warehouse_inbound:view`、`warehouse_inbound:stock_in`，没有收回这三项的 active 个人覆盖。
- 2026-10-31 公司仓库字典访问日志可见 HTTP 200。日志不能关联截图那次浏览器的全部内存状态，未将成功状态码当作浏览器已正确呈现的证据。

已在实际 Provider 依赖链复现空白的形成路径：`exportContextEpochProvider` 更新 → `masterPartyLookupProvider` 重建 → `masterNameServiceProvider` 重建；新名称服务的仓库映射尚未解析。原页面初始化早已执行，行内选仓直接读取新服务的空映射，弹出“请先维护仓库”。即使字典原请求成功、同会话字典缓存仍在，也会出现该问题。另一个相同表象是可选名称加载吞掉请求/解析错误。

修复公共入口：

- `MasterDictionaryService.requireWarehouseHierarchy` 区分必需的选仓读取与可降级的名称补全；保留真实错误、重试、会话退役保护。仍只缓存成功结果、仍由服务端决定可选标记。
- `showUtenWarehouseDictionaryPickerPanel` 在当前会话中加载后呈现，明确显示加载/失败/重新加载。权限/会话重建后销毁旧层级和临时选择；空结果也能显式重新加载。
- 原 `showUtenWarehousePickerPanel` 继续服务调用方已限定的任务/物料仓库快照，避免拿全量字典覆盖业务可选范围。
- `warehouseSelectionProvider` 与货品所属仓库的通用资料读取也改用必需读取，失败不再伪装成空配置。

## 我的车间任务 Excel 导出

分类：前端与后端共享导出契约。

- 页面使用现有 `UtenExportButton`，入口 `/production/reports/export?report=workshop-tasks`；复用现有后台导出任务、进度/恢复、文件名/保存位置、可选密码、列投影、扩展列、下载及审计。
- `WorkshopTaskExportContract` 是权限与筛选白名单；需要同时持有 `production_execution:view`、`production_report:export`，后者沿用现有 `production_report:view` 前置依赖。不自动新增/扩大员工权限。
- `ProductionWorkshopTaskExportService` 调用原 `ProductionExecutionWorkbenchService.workshopTasks`，保留员工/车间归属、分类、搜索、来源计划/工单号、生产路线、开工状态筛选、排序和历史日期。页面没有分类时禁用导出；历史按页面现有近三个月/全部选择导出。
- `ReportQueryKit.paginateAll` 与 `ExportPageSink` 按批输出全部符合条件记录，不只导出当前已挂载的一页；同步旧入口仍沿用公共行数上限，后台任务沿用公共完整性、取消、快照、文件大小和存储限额。
- 后台任务授权范围明确使用 `native_workshop_tasks` 的真实人员/车间指纹，范围变化后不能下载旧范围文件。未借用生产计划 owner 范围，也未仅用宽泛 production 报表范围代替车间归属。
- 同步兼容下载在生成前与交付前核对同一车间范围，期间调岗或撤权时不返回文件；后台任务仍使用原公共 worker 与下载授权。
- 数量保留 BigDecimal 与单位，单号和文本沿用公共 Excel 字面量保护。导出只包含服务端事实；本地未提交的草稿提示不作为服务端事实导出。

## 主链整合复核：导出状态合同

复核确认了状态列的根因：`REPORT_INSPECTION` 读取的是底层 `IN_PROGRESS` 且待报数量已结清的执行段，原新增导出只映射底层状态，把待检验、点收入库和结清阶段写成“生产中”。同类问题还会把缺料、可领料和可开工都压成“待开工”。

- 同步 Excel 与后台导出共同改用 `ProductionWorkshopTaskStage.label`，完整保留物料、路线、报工、品质、仓库和终态事实。
- Web/Flutter 原车间页面的状态适配迁入 `workshopTaskFlowStage`，继续调用原公共 `ProductionFlowStage` 词表；删去页面内重复的私有适配，没有变更颜色、布局或动作权限。
- `server/src/test/resources/contracts/workshop-task-stage-v1.json` 的 45 份共享输入/预期输出同时被 Java 实际导出行与 Dart 实际页面适配验证，覆盖等待物料、计划催单、内料仓、领料发现、部分/全部齐套、报满后品质与入库、终态及数量边界。
- 本地尚未审核的报工草稿只在界面叠加提示，导出仍只采用服务端事实；单独回归确认草稿承接不会变成“已报完”。WPF `W7-BIZ-115` 保持 `todo`，唯一台账已补充同一合同接入要求。
