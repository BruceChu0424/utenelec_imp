# 2026-09-12 设置与审计日志核验

本记录仅覆盖系统设置、密码历史消费者、审计写入分类和在线审计查询/UI。全站验证及公司服务器部署结论由主任务统一记录。

## 根因与修复

| 问题 | 根因 | 当前实现 |
|---|---|---|
| 多项设置保存慢且可能只保存一部分 | 前端逐项HTTP，每项重复Argon2校密、各自提交 | 一次批量请求、一次校密、全部先验证、一个事务；每项成功审计与事务绑定 |
| 并发页面可能覆盖更新 | 没有原值校验 | 批量提交expectedValue，按key有序悲观锁，任一不符整批冲突；旧单项同锁读取但保留旧协议 |
| 设置显示可改却不生效 | bool/string也使用数字输入；庆典任意字符串保存成功后被扫描器过滤 | 按元数据类型渲染，自动庆典只允许受支持类型；V553仅改说明、不重写旧值 |
| 密码历史设0会导致改密500 | Pageable.ofSize(0)非法 | 0只关闭历史查询，负数明确拒绝，当前密码仍不可复用 |
| 极大策略值影响容量与稳定性 | 大部分只校验非负 | 15项数值配置均有明确上下界，限制短信TTL乘法与密码历史哈希工作量；见系统设置页完整表 |
| 设置页刷新覆盖编辑、保存回执异常 | dirty只增不减，无保存结果检查 | 改回原值自动清除dirty，保存冻结编辑，脏数据不被下拉覆盖；批量响应须完整匹配请求键和值 |
| 保存响应仍携带旧修改时间 | 数据库触发器更新时间，实体未声明生成值，findById只命中一级缓存 | Hibernate INSERT/UPDATE生成值映射，数据库回执同步实体/DTO，无额外逐项refresh查询 |
| 审计事件列表等待统计才显示 | 列表和统计串行后一起更新UI | 列表先展示，统计随后用同一snapshotId加载；统计失败可重试且不隐藏证据 |
| 审计会话分页仍聚合全部会话 | 完整设备/结果/令牌聚合发生在分页前 | 先按完整会话的登录/最早活动时间确定本页，再聚合本页证据；CTE只投影需要的列 |
| 狭窄窗口仍顺序扫描全部在线审计 | 起点GROUP BY JOIN被优化器改成全表扫描 | LATERAL按匹配session_id索引读取完整起点，再分页；实际公司副本逐行同值对照与EXPLAIN见审计页 |
| 批量业务落库的审计分类计算成本高 | 两个生成表达式重复执行文本转换和字面正则匹配 | V556共用原文本范围、以子串匹配保持原规则，ALWAYS触发器强制分类；保留11索引、脱敏和历史快照 |
| 审计首屏信息重复、大文件维护困难 | 重复步骤说明、约5800行主文件混合所有职责 | 紧凑调查工作区，保留独立范围和高级调查；按原私有边界拆为4个同库模块；小屏概览紧凑化、高级筛选默认收起且显示已选条件 |

## 现役入口与权限

- `lib/features/admin/pages/admin_system_settings_page.dart` / `features/admin/systemsetting/*`：工作台与路由继续要求`authorization:manage`；服务端Controller/Service再要求当前superAdmin，写入二次密码确认。未加入任何替代权限。
- `/admin/audit-logs`及会话子页、相关服务继续要求`audit_log:view`；导出另外要求`audit_log:export`。非超管只能通过个人点名授权；审计权限不授予系统设置能力。
- 审计详情共用`showAuditLogDetailViewer`及四页完整证据；设备本机信息仍必须先在线取得审计授权，不添加删除/修改接口。
- 审计分页先根据人员UUID和北京时间日期选择会话，完整会话统计跨午夜、跨选定日期，且受同一快照限制；没有把无会话ID旧记录猜测归组。

## 数据与兼容

V553仅更新两项说明元数据。所有设置值、审计历史、账号、单据和库存均无迁移重写。既有庆典不支持类型保持原样展示，扫描器继续保持原行为；只有显式修改对应键才执行新值校验。新增上限是容量硬边界，不是推荐运行值。部署前应只读核对现有策略，异常值按管理员明确决定处理。

V556仅转换审计热表分类的计算方式。迁移先核验已知V169生成规则及对象冲突，再DROP EXPRESSION并启用ALWAYS分类触发器；已有值、列顺序、索引及归档均保留。Java分类字段仍只读；伪造分类、单独修改分类字段及复制模式写入均由数据库重新计算。两个新函数固定搜索路径，不允许会话中的影子函数覆盖。

系统设置运行时读取仍无缓存，提交后不同实例的后续读取可取得新值。令牌TTL影响后续签发，前端空闲阈值按既有刷新信号/轮询更新，庆典在北京时间08:00:07扫描，审计留存在03:17批任务生效。

- Flutter范围：42项定向测试通过，涵盖原有设置留存、审计列表/完整详情/会话详情，加原子批量、脏值还原、非法值、响应一致性、慢统计/统计失败；小屏密度调整后审计组及4个额外截图用例共37项通过。
- UI：375/768/1440三档、浅深主题、1.3倍字、reduced-motion及既有1.5倍字/横屏检查。可用`flutter test --dart-define=UTEN_CAPTURE_UI=true test/features/admin/audit_center_layout_test.dart`复现截图，文件位于忽略目录`build/ui-audit/`；截图加载本地中文/图标字体，并仅替换widget test注入的Ahem测试字体。它不是浏览器或公司用户实测截图。加载后的会话/事件截图可对`admin_audit_log_detail_test.dart`使用同一开关生成，输出为`audit-loaded-{375|1440}-{sessions|events}.png`。
- PostgreSQL：`AuditSessionQueryPostgresTest`使用独立`postgres:16-alpine`容器完成全量Flyway，3项会话实测通过，覆盖跨午夜、分页登录排序、完整事件数量/退出证据、快照/游标及归档边界。后续设置上界与旧单项锁修订不改该会话SQL。
- 后端：最终34项单测/合同检查通过。`SystemSettingsBatchUpdateTest`验证一次校密/一次flush、后项非法不更改前项、旧值冲突、密码错误与重复项拒绝；`SystemSettingsServiceRetentionValidationTest`覆盖容量上界；`PasswordHistorySettingsTest`覆盖0、负数、当前密码复用拒绝；既有密码授权版本失效回归继续执行。
