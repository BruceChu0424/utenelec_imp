## 一、问题

用户 2026-09-20 原话(节选)：

> 委外 这个就是 我们仓库得先发货出去 然后再发货回来 因为 委外件是可能有损耗的 这个损耗是不一定的
> 所以我设想 就是 在委外下单那里 ... 每个货品 加个列 就是 允许损耗范围 然后这个页加个记忆 下次自动填写 ...
> 是直接放在货品资料的表还是咋 就是比如 这个货品 为外键 允许5%的损耗
> 然后仓库那里 收货 ... 如果是分批到的 就是你自己判断 就是 收到的货 数量少于5% 那么就显示弹窗 数量严重低于啥的 ... 然后通知委外人员
> 委外任务中心 ... 把 等待财务审核 财务已通过 财务驳回 三个合并 改成进行中 然后加个状态 每个状态一个颜色 颜色差距大点 ...
> 表头加个筛选 重要的通知 用红色通知徽章 普通 正在进行的 就用数字 ... 对应的那个委外单出问题了 就标红色 紧急
> 重新设计个页面 ... 把出问题的 数量严重低的重点显示 然后让委外自己判断 是属于分批入库的 还是 允许入库
> 分批入库 那么 剩下的 仓库就继续等 ... 允许入库 就直接入库 后续没有再来的
> 你要自己记录 这个订单 损耗比是多少 ... 这个供应商 每次的损耗比是多少 ... 可以总结 汇总

现状盘点(见文末参考)：

1. 委外链路里「损耗」只存在于材料侧：委外损耗单(`subcontract_wastes`)按发料明细记实际损耗、允许损耗、超耗，
   审核后走 ADR-047 的超耗责任(财务索赔/抵销/公司承担)。**目标件回厂数量少于订货量**这件事从未被定义：
   仓库照实登记，订货行一直挂着「待到货」，没人判定它是分批还是损耗，供应商也没有损耗统计。
2. 到货登记(`WarehouseArrivalRegistrationService.register`)只有「超量」闸门(ADR-019：超过财务批准量隔离待财务)；
   少量没有任何提示。
3. 委外任务中心(`/operations/workbench/subcontract`)分段是 待处理 / 等待财务审核 / 财务已通过 / 财务驳回 / 历史记录，
   订货单批准后到结案之间的过程(待发料、加工中、部分回厂、出了问题)全部叠在「财务已通过」一段里，看不出谁出了问题。
4. 供应商主档列表已经摆了一列「损耗率(%)」，但注释写着「无对应物理列，恒显示 —」。

「其他业务是不是也需要」：采购到货没有我方发料，供应商少到只是欠交，走既有的等待/改量即可；自制产成品的短收 V338 已有
「差异原因 + 余量新草稿」；所以本 ADR 只落在委外回厂这一条链路上，任务中心的分段合并也只改委外任务中心。

## 二、决策

### 2.1 允许损耗放在订货明细上，记忆落在货品主档

- `subcontract_order_items.allowed_loss_pct NUMERIC(5,2)`：本行允许损耗百分比，0 到 100，可空(空 = 未设)。保存即冻结到本行，
  后续改主档不影响已下的单。
- `goods.subcontract_allowed_loss_pct NUMERIC(5,2)`：货品主档默认值，就是用户说的「以货品为外键」的记忆。
  - 预填：委外订货编辑页新增行时经 `/subcontract/orders/last-terms` 一并带出(`allowedLossPct` + `allowedLossPctSource=GOODS_MASTER`)，
    黄框提示「已按本货品上次填写的允许损耗预填，请核对」，与 ADR-096 路线记忆、ADR-068 条款记忆同一套呈现。
  - 回写：保存/批量创建/更新委外订货单时，每一行非空的允许损耗写回该货品主档(值不同才写，审计触发器留痕)。
    「下次自动填写」= 下次带出的就是上次填的。
  - 主档货品编辑弹窗成本页也能直接改这个默认值(标签「委外允许损耗(%)」)。
- 不复用 `goods.lost_rate`(BOM 成本预算里的损耗比率)：它是成本口径，不是收货判定口径，两者混用会互相污染。
- 不做供应商维度的记忆：用户口径是按货品；供应商差异体现在事后汇总(2.6)，需要时再加一档。

### 2.2 到货登记时的判定：下限、弹窗、确认

定义(全部按订货行、订货单位)：

| 名称 | 计算 |
| --- | --- |
| 订货量 Q | `subcontract_order_items.qty` |
| 允许损耗 p | `allowed_loss_pct`，空表示未设 |
| 允许下限 F | `Q × (1 − p/100)`，4 位小数 |
| 累计回厂 D | 已审核委外进仓净量 = `received_qty − returned_qty − IQC 已退回不合格量`，与预计到货 `accepted_qty` 同一口径，不封顶；本次登记的行量加进去后再比 |
| 短交量 S / 短交率 | `Q − D`，`S / Q` |

严重程度：

| 程度 | 条件 | 表现 |
| --- | --- | --- |
| 严重短交 `SEVERE` | D < F 且短交率 ≥ max(2p, 20)% | 红色 + 「严重」标签，排最前 |
| 低于下限 `BELOW_FLOOR` | D < F | 红色 |
| 容差内 `WITHIN_TOLERANCE` | F ≤ D < Q | 中性 |
| 未设允许损耗 `UNSET_TOLERANCE` | p 为空且 D < Q | 中性，页面提示去订货页补设 |

流程(只对委外订货类型；采购登记不变)：

**前置条件**(2026-09-21 由 [ADR-101](ADR-101-委外单一子层级按到货解锁与容差自动结案.md) §2.5 补入)：
**本行的料还没有全部发给委外商之前，一律不判短交。** 委外是先发料、后回厂，委外商手上只有我们已经发过去的
那部分料，回厂比订货量少是分批发料的常态，不是供应商少交；这时候弹窗、开案件、发紧急通知，全是误报。
要等这一行的料发完才开始判——包括仓库点了「不再出仓」主动把余量关掉的情形，那也算发完。
如果料是在最后一批货到齐之后才发完的，就在仓库确认入库的那一刻补开案件，不会因为发料晚了就漏判。

1. `register` 在写任何东西之前评估本次登记涉及的每一订货行。只要有一行是 SEVERE / BELOW_FLOOR，而请求没带
   `shortDeliveryAcknowledged=true`，就以 409 `SUBCONTRACT_SHORT_DELIVERY_UNACKNOWLEDGED` 拒绝，`fieldErrors` 逐行给出
   「订 / 允许损耗 / 最少应到 / 此前已到 / 本次 / 累计 / 少多少」。此时未插入幂等命令、未建收货单，重试没有副作用。
2. 前端(单张登记页、批量登记页共用一个弹窗)把这些行列出来，标题「到货数量明显少于订货量」，正文用大白话说明
   登记后会通知委外跟单员判定，按钮「继续登记并通知委外」/「返回修改」。确认后带 `shortDeliveryAcknowledged=true` 原样重发。
   **弹窗前必须先撤「正在登记」全屏遮罩**：UtenBusyOverlay 把遮罩直接插进 root Overlay，而弹窗是随后才推上来的
   路由、排在那条 OverlayEntry 之下，不撤遮罩弹窗就被盖住、两个按钮都点不动(2026-09-21 批量登记页实测)。
   `registerArrivalConfirmingShortDelivery` 因此要求调用页传 `setBusy`：弹窗前置 false 并等这一帧画完，确认后
   置回 true 再重发；选「返回修改」则保持 false 由页面自己收尾。
3. 收货单建立并审核送检成功后(与登记同一事务)，按行开立或刷新「回厂短交案件」(2.3)。容差内 / 未设两档不弹窗、不通知，
   只开中性案件；累计到齐(D ≥ Q)时关闭该行仍开着的案件(自然到齐)。
4. 超量到货仍由 ADR-019 处理，与本判定互不影响(累计超过 Q 的行不会进入短交评估)。

### 2.3 案件：`subcontract_short_delivery_cases`

一行订货明细同一时刻最多一个开放案件(部分唯一索引)。字段：订货单/明细/供应商/货品/颜色/单位快照、触发的收货单、
Q / p / F / D / S / 短交率 / 程度、状态、判定、预计到齐日、判定说明、负责人(订货单制单人)、判定人与时间、结案时间、
损耗量 / 损耗率、生成的损耗单、改量记录、乐观锁版本、到货次数。事件表 `subcontract_short_delivery_case_events` 追加式记录
发现 / 再次到货 / 判定 / 逾期 / 完成 / 作废。

状态机：

```
登记短交(无开放案件) ──DETECTED──▶ PENDING_OWNER(待判定)
PENDING_OWNER ──判定「分批到货·继续等」(必填预计到齐日)──▶ WAITING_MORE
PENDING_OWNER / WAITING_MORE ──判定「接受损耗·结案」──▶ ACCEPTED_LOSS(终态，记损耗率)
PENDING_OWNER / WAITING_MORE ──登记后 D ≥ Q──▶ COMPLETED(自然到齐，终态)
WAITING_MORE ──再次登记仍短交且未过预计日──▶ WAITING_MORE(只刷新数字，不再通知)
WAITING_MORE ──预计到齐日已过──▶ PENDING_OWNER(逾期，重要通知，每日最多一次)
PENDING_OWNER / WAITING_MORE ──订货单红冲/作废──▶ CANCELED
```

「接受损耗·结案」在同一事务里做三件事，顺序不能反：

1. **损耗单**：按该订货行在供应商处仍未清的发料(发出 + 补料 − 已消费 − 已退 − 已损耗)，为短交量折算出材料损耗：
   发子件的流向按冻结单耗 `S × frozen_unit_qty`，发目标件的流向按订货换算率；允许量 = 允许损耗对应的那一份
   (`Q × p% × 同一换算`)，其余是超耗。自动生成并审核一张委外损耗单(制单人 = 判定人，来源仓 = 发料仓，原因写明案件号)。
   审核后走既有链路：正常损耗进合格产出成本，超耗自动开财务责任判定(ADR-047)——所以「允许 5% 的损耗」在财务侧也成立。
   供应商处没有发料记录的行(历史单/无料行)不生成损耗单。
2. **改量**：调用 ADR-072 的受控改量把本行订货量改为累计回厂量 D。改量本身负责：来源申请把 S 还回待下单(物料分析会重新看到缺口)、
   预计到货同步关闭、出仓计划收口(planned = 已出)、订货单结案、开财务改量复核 case。若供应商处仍有超出短交折算量的材料
   (多发的料、允许补料没用完)，改量下限会高于 D，此时结案被拦下并提示「请先登记退料单或损耗单」，案件保持待判定——
   这是守恒的要求，不吞差异(见 `business-chain-scenario-matrix.md` 对「百分比容差吞差异」的禁令)。
3. **记账**：案件写 `loss_qty = S`、`loss_pct = S / Q`、损耗单 id、改量记录 id，状态 ACCEPTED_LOSS；撤回该案件的所有通知卡。

三步的顺序不变，但有两个坑必须一起填上，否则这三步走不完([ADR-101](ADR-101-委外单一子层级按到货解锁与容差自动结案.md) §2.6 已一并修正)：

- **订货量能不能改下来，取决于「已核销损耗」也算进目标量**。第 1 步刚用损耗单把委外商手上那份料核销掉，
  第 2 步在算「这一行还该留多少计划量」时如果不认这份损耗，料已经全部发完的单子就一点量都收不回来，
  必定被「新数量仍低于已实发或进行中的前置生产量」拦死，并把第 1 步刚开出来的损耗单一起回滚，
  操作的人只看到一句看不懂的红字。
- **同一张订货单的第二行结案，不再被第一行自己开出来的财务复核挡住**。受控改量每次都会开一条待财务复核，
  而「有在办复核就不许再改量」那道闸防的是有人连着做两次自由改量；短交结案不是自由改量，它记的是
  「回厂多少、损耗多少」这个既成事实，每行又只有一个开放案件把关。不放开这一条，多货品委外单只要短交两行就永远结不掉。

「分批到货·继续等」只写判定与预计到齐日，不动任何单据；仓库那边的预计到货任务本来就还开着，继续等就是什么都不做。

### 2.4 通知

| 事件 | 收件人 | 优先级 | 文案 |
| --- | --- | --- | --- |
| `SUBCONTRACT_SHORT_DELIVERY_DETECTED` (SEVERE / BELOW_FLOOR) | 订货单制单人；委外部其他持判定权限的人广播知会 | 紧急(红) | 标题「委外回厂数量明显少于订货量：单号」；正文说货品、订了多少、最少应到多少、累计到了多少、少了多少，以及「去判定是分批到货还是接受损耗」 |

### 2.5 委外任务中心：待处理 / 进行中 / 历史记录 + 状态列

- 分段：`待处理`(WAITING_ORDER，红徽章) / `进行中`(IN_PROGRESS = 等待财务审核 + 财务已通过 + 财务已退回，中性数字) / `历史记录`。
  服务端 `status=IN_PROGRESS` 映射三种 task_status，`summary.statusCounts` 多给一个 `IN_PROGRESS` 合计。
- 状态列(表头可筛、可排序，颜色刻意拉开)：

| 状态 | 含义 | 颜色 |
| --- | --- | --- |
| 等待财务审核 | 已提交财务未决 | 蓝 info |
| 财务已退回 | 要改单重报 | 红 danger |
| 待发料出仓 | 财务已通过，还没有任何审核过的发料/出仓 | 紫 violet |
| 委外加工中 | 已发料/已出仓，尚未回厂 | 青 accent |
| 部分回厂 | 已有回厂但未到齐、无开放案件 | 橙 warning |
| 已回厂待入库 | 各行回厂净量(received − returned)都已 ≥ 订货量, 只差质检合格入库；结案不等于入库, 接受损耗改量后到入库前就停在这一档 | 绿 success(与历史段「已完成」同色, 不同段) |
| 分批等待中 | 有案件已判定分批到货且未过预计日 | 品红 fuchsia |
| 容差内待结案 | 有容差内 / 未设允许损耗的中性案件待结案 | 灰 neutral(不算异常、不计红) |
| 回厂短交待判定 | 有低于允许下限的待判定案件(含分批逾期) | 红 danger + 行底红 + 「紧急」标签，排最前 |

  委外订货单按单归组，一张单取最严重的行状态。前置自制合成行沿用原车间状态文案。
- 异常小类行(选中「进行中」后出现，全部红徽章)：新增 `回厂短交待判定`(exception_code=SHORT_DELIVERY)与 `财务已退回`
  (exception_code=FINANCE_REJECTED)，与逾期等并列，这样「重要的用红色徽章、正在进行的用数字」在同一页成立。
- 红徽章口径(准则 14 §四之二同步改)：hub 委外模块红数 = 任务中心 `/count` = 待处理 + 财务已退回 + 回厂短交待判定
  (按单去重)。判定页卡片上的徽章只是同数展示，不登记进 `todo_badge_registry`，同一件事只数一次。
- 采购任务中心不改：采购没有回厂短交这件事，五段维持。

### 2.6 判定页与供应商损耗汇总

- 新页 `/subcontract/short-deliveries`「委外回厂短交判定」：分段 `待判定`(红：低于允许下限的待判定 + 分批等待已过预计到齐日) /
  `容差内待结案`(中性：容差内或未设允许损耗的短交, 不急但要有人结案) / `分批等待中`(中性) / `历史记录`(时间门控)；
  搜索单号/供应商/货品；列：订货单号、委外商、货品名称、编号、颜色、订货量、允许损耗%、最少应到、累计回厂、短交量、短交率、
  程度、最近收货单、发现时间、预计到齐、状态、操作。严重短交置顶并加「严重」标签。两个操作各有确认弹窗：
  「分批到货·继续等」要预计到齐日；「接受损耗·结案」列出三件事的后果，低于下限时说明必填。
  入口：委外 hub 新卡片(红徽章同数展示)、任务中心状态列「回厂短交待判定」点击直达并按订货单过滤、通知卡片直达并定位案件。
- 供应商损耗汇总：视图 `v_subcontract_supplier_loss_summary` / `v_subcontract_supplier_goods_loss_summary`，口径 =
  已结案(自然到齐或接受损耗)的委外订货行：订货量取案件记录的原订货量(改量前)，损耗量取案件 `loss_qty`(自然到齐为 0)，
  加权平均损耗率 = Σ损耗 / Σ订货。落点：供应商主档列表「损耗率(%)」列不再恒显示「—」；供应商详情页概览新增「委外损耗」
  段(结案行数、累计订货、累计损耗、加权损耗率、最高一次、按货品明细、最近几次接受损耗的案件)；判定页历史记录可按供应商筛。

### 2.7 权限

- 新增 `subcontract_short_delivery:decide`「委外回厂短交判定」(模块 委外管理 / 分类 委外订货，面 `subcontract.order`)：
  判定分批到货或接受损耗结案。默认授予当前持有 `subcontract_order:submit_finance` 的部门(能提交委外订货的人才判定)。
  对象级仍按 ADR V233：本人负责的订货单，或持 `subcontract_order:view:all`。
- 查看判定页与供应商汇总：`subcontract_order:view`。仓库确认弹窗不需要新权限(它只是登记的一部分)。
- 结案内部调用的损耗单审核与订货改量不再各自要求 `subcontract_waste:*` / `subcontract_order:change_qty`：
  权限点是判定本身，服务端以专用入口绕过方法级注解但保留全部业务守卫(守恒 CAS、期间、乐观锁、来源一致)。

### 2.8 等待委外判定期间先锁住：先不入库，也不改量(2026-09-22 用户追加)

用户口径：「仓库那里通知，然后等待委外回复应该有这个状态，然后锁住先」「就是先锁住，先不入库先」。
理由很直白——到底是分批到货(剩下的还会来)还是接受损耗结案(就到这么多)，决定了这张单后面怎么算；
在委外给出结论之前把货入了库，等于替委外先替下了结论。

**锁的条件**：存在**待判定**的回厂短交(锁住的是哪一批货，按下面「锁的内容」里的粒度算)，即 §2.3 的红档谓词
`(status='PENDING_OWNER' AND severity IN ('SEVERE','BELOW_FLOOR')) OR (status='WAITING_MORE' AND expected_complete_by < CURRENT_DATE)`。
与判定页「待判定」段、任务中心红徽章同一口径，不另起第三套。
中性档(容差内 / 未设允许损耗)既不弹窗也不通知，**不锁**——没人被通知却被锁住是说不通的。

**锁的内容**：

| 被锁的动作 | 落点 | 拦截时的说法 |
| --- | --- | --- |
| 质检合格后确认入库(单张 / 跨单批量 / 先入库后质检的自动转正) | `ProcurementIqcStockInService.confirmOne` 单一漏斗，经 `SubcontractShortDeliveryPort.stockInHoldReason` 问委外要理由 | 「…已通知委外判定是分批到货还是接受损耗；判定完成前这批先不入库，货先留在待入库不要上架。」 |
| 人工改量(ADR-072) | `SubcontractOrderService.changeQty` 公开入口 | 「…判定完成前先锁住不改量。接受损耗结案时系统会自动把订货量改成实际回厂量。」 |

**关联粒度按行不按单**(2026-09-21 由 [ADR-101](ADR-101-委外单一子层级按到货解锁与容差自动结案.md) §2.5 修订)：
入库这一闸问的是「这批收的货里，**这一行**订的东西上有没有待判定的短交」，此前问的是「这张委外订货单上有没有」。
一张委外单常常同时订好几个货品，其中一个少到了，不该把同单另外那些已经足额到齐的货一起冻在待入库——
它们跟这次判定的结论没有关系，判定完了也不会改变它们的数量，仓库只会看到一批完全正常的货莫名其妙上不了架，
这与「分批发料、分批回厂」的日常节奏直接打架。改量那一闸与详情页那条红底横幅仍按整张单：
改量本来改的就是整单的事，横幅是告诉人「这张单现在被什么卡住」。

**不锁的动作**：继续到货登记(货是实物，拦不住也不该拦，登记只刷新案件数字)；红冲(它本身就是作废并撤销案件的
合法出口，锁住反而会把 `cancelOpenCasesForOrder` 的清理路径做成死代码)。

**解锁**：委外判定成「分批到货」或「接受损耗」即自动放行，不需要任何人手工解锁。分批到货过了预计到齐日会
**重新锁上**(案件按 §2.3 回到待判定)——这一点要在界面上讲清楚，否则像 bug。

**界面**：订货单详情页在财务审批横幅下方多一条红底横幅「等待委外判定回厂短交(本单已锁定)」，正文是那句大白话，
带一个「去判定 / 查看短交详情」按钮直达判定页并只看这张单；「改量」按钮留在原地变灰、点一下说明为什么。
服务端只读字段 `OrderDetail.shortDeliveryHold`(caseId / caseCount / summary / overdue)派生自案件，不落库。

**两条边界**(都有用例钉死)：
- `expected_complete_by` **就是今天**不算逾期、不锁，退到昨天才锁；比较一律交给库里的 `CURRENT_DATE`，
  免得 JVM 与容器时区不一致让临界日漂一天。
- 已经成功的入库按同一幂等键重放，即使此刻单子又被锁住也照常返回原批次，不会被改判成 409
  (幂等在 `confirmCommands` 里先短路，走不到挂闸的 `confirmOne`)。

## 三、每一种情况怎么走

| # | 情况 | 系统行为 |
| --- | --- | --- |
| 1 | 一次到齐 D ≥ Q | 不弹窗、无案件；若该行之前有等待中的案件 → COMPLETED，卡片撤回 |
| 2 | 分批到，首批低于下限 | **前提是这一行的料已经全部发完**(没发完不判、不弹窗，§2.2)；弹窗确认 → 登记 → 案件待判定 + 紧急通知 + **锁定这一行(该行不入库；本单不改量, §2.8)**；判定「分批到货」填预计到齐日即解锁 |
| 3 | 分批到，后续批次仍低于下限、未过预计日 | 同样只在料已发完后才有案件；弹窗(告知已判定分批、本批后累计多少)→ 登记 → 案件只刷新数字，不再通知 |
| 4 | 分批到，到齐 | 案件 COMPLETED，卡片撤回，任务中心回到「已回厂待入库 → 入库后已完成」口径 |
| 5 | 分批到，过了预计到齐日仍未到齐 | 案件本来就只在料发完后才开(§2.2)；案件回到待判定(逾期)，每日一次重要通知；任务中心该单变红；**该行重新锁定**，横幅改说「已过预计到齐日，等待重新判定」 |
| 6 | 末批后仍低于下限，判定接受损耗 | 损耗单(允许量按 p%)→ 改量到 D → 记损耗率；超耗进财务责任判定；来源申请余量回到待下单 |
| 7 | 累计在容差内未到齐 | 料已发完 → 仓库确认入库的那一刻**自动按接受损耗结案**(损耗单 → 记损耗率 → 改量到 D，三步同 §2.3，超耗为 0)，不弹窗、不通知、**不锁**，没人需要动手；料还没发完 → 不判、不开案件，等料发完再看 |
| 8 | 行未设允许损耗 | 判定口径同 7，但没有约定可依，**不自动结案**，仍由委外人工结；页面提示到订货页补设；主档记忆一旦有值，新行自动带出 |
| 9 | 超量到货 | ADR-019 隔离待财务，不进短交评估。委外还多一种超量：交回来的比我方发过去的料能做出来的还多，多出来的那部分用的是委外商自己的材料，按 ADR-101 §2.8 走财务隔离——货先不入库、不立应付，转财务审核组确认价格和归属 |
| 10 | IQC 不合格退回后补货 | 退回量不计入累计 D(与预计到货同口径)，补货登记走同一判定 |
| 11 | 收货单红冲 | D 回减；已终态案件不自动重开，下次登记重新评估 |
| 12 | 订货单红冲/作废 | 开放案件 CANCELED，通知撤回 |
| 13 | 手工改量(ADR-072)把 Q 改到 ≤ D | 改量后重评：开放案件 COMPLETED |
| 14 | 供应商处剩料多于短交折算量 | 结案被拦，提示先退料/损耗单；案件保持待判定 |
| 15 | 一张订货单多行/多货品 | 判定按行；任务中心按单显示最严重状态；弹窗逐行列出 |
| 16 | 同一行两张收货单同时在 IQC | 累计按已审核收货净量，与 accepted_qty 一致，不重复计 |
| 17 | 无权限的人打开判定页 | 能看(subcontract_order:view)不能判；无 view 权限卡片隐藏 |
| 18 | 通知点击 | 直达判定页并定位案件；案件已判定则卡片已撤回，页面按历史显示 |

## 四、明确不做

- 不做「登记时由仓库选分批/损耗」：仓库只登记事实并确认知情，判定权在委外。
- **「不做容差内自动结案」已被整条推翻**(2026-09-21，[ADR-101](ADR-101-委外单一子层级按到货解锁与容差自动结案.md) §2.6)：
  现在的口径是——仓库把货确认入库的那一刻，如果这一行的料已经全部发给委外商，而且累计回厂量落在本单约定的
  允许损耗范围内，系统直接按「接受损耗」结案，三步(损耗单 → 记损耗率 → 把订货量改成实际回厂量)与 §2.3 完全一样，
  只是不用人再去判定页点一次。原先的顾虑是「没有『供应商说交完了』的信号，自动结案会把还在路上的货变成超量」，
  它不再成立：允许损耗本身就是那个信号——下单时双方就约定了「交到这个数就算交完」，再要人确认一遍，
  只是把一件已经谈妥的事挂起来等人；何况容差内是中性档，既不弹窗也不通知，没有任何人被告知这张单在等自己，
  它就会一直挂着没人管。自动结案**只限「容差内」这一档**：「未设允许损耗」没有约定可依、「低于下限 / 严重短交」
  本来就要委外自己判是分批到货还是接受损耗，这两档仍然全部由人来点。结案之后真的又来货，那是超收，
  走 ADR-101 §2.8 转财务审核组，不会悄悄进库。
- 不做按供应商的允许损耗记忆、不做日期维度的允许损耗表；需要时在货品主档之上再加一档。
- 不改采购任务中心分段；不改产成品短收(V338)。
- 不把「允许损耗」用于任何账务自动抵消：损耗单、改量、财务复核、超耗责任全部是既有显式动作，本 ADR 只负责把它们串起来。
- 不做批量判定(先单条；用户要求「让委外自己判断」，批量容易误点)。
