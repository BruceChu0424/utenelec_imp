# 计量学习与旧库自动推断决策

> 日期：2026-08-31  
> 状态：源码候选；未部署、未对目标库执行、未获生产切流证据

## 1. 结论

系统不在货品主档增加一个全局“按数量/按重量”开关。最终模型是：

1. **业务事实**：qty + unit_id + unit_rate 始终保留；实际总重量及其单位是独立事实。
2. **采集偏好**：按 goods UUID + operation family 学习采购、仓库、销售、委外、生产各自的录入习惯。
3. **证据账**：只接收已审核、已过账及其红冲事件；草稿键入不参与学习。
4. **人工决定**：人工覆盖有原因、权限、版本和追加式审计；自动学习不覆盖人工决定。
5. **异常隔离**：有重量无数量、负数、单位缺失、换算率非法和来源能力漂移进入小范围例外队列。

这避免同一货品“采购称重、销售按件”被一个全局标签误伤，也避免把重量伪造成库存数量。

## 2. 为什么不能直接用“只有哪个字段就按哪个”

旧库通用 Weight 没有重量单位、净重/毛重/皮重类型。大量表虽然有该列，但所有行都是 0；因此：

- Weight = 0 表示未采集/未知，不证明真实重量为 0；
- 没有 Weight 不能作为“只按数量”的强证据；
- 单位名为 kg/g/斤，只能说明 QTY 的业务单位，不能说明通用 Weight 的单位；
- goods.MWeight 是单重参考，且当前快照 35,750 个货品仅 1 个正值，不能生成实称总重量；
- 有 Weight、没有 QTY 的旧行不是“重量货品”，而是待隔离的数据形状。

正式库存仍由业务基本量管理。系统不提供 WEIGHT_ONLY 正式账务模式；“重量为主”只能改变录入视觉主次，不能删除或伪造数量。

## 4. 已确认的旧库规则

### 4.1 数量

QTY × URate = 库存基本量。显式单据 UnitID 优先；不得用单位名称做关系键。

缺单据单位时，只有同时满足以下条件才可在画像临时层使用货品基本单位：

- 单据 UnitID 为 0/NULL；
- URate 为 NULL 或 1；
- goods.UnitID 是非零且能精确映射的 UUID；
- 不覆盖显式单据单位。

该规则只确定单位身份，不推断计量维度。

### 4.2 委外发料数量

当前 E_SOutItem 49,889 行的 STQTY 全为 0，但 QTY 正数有 49,882 行。
旧脚本 COALESCE(STQTY,QTY) 会因 0 非 NULL 而把发料量全部迁成 0。

确定性 resolver：

    STQTY > 0 且 QTY > 0 且相等 -> STQTY
    STQTY 为 NULL/0 且 QTY > 0  -> QTY
    STQTY、QTY 同为正且不相等  -> 拒绝并复核
    其余无正数量                 -> 拒绝并复核

源码候选已使用 COALESCE(NULLIF(STQTY,0),QTY)，并增加双正不一致失败门禁。

### 4.3 即时库存

StockGoods 必须按仓库、货品、颜色取最新年，同年汇总
FactQTY / FactWeight。QTY/Weight 是期初/旧口径，当前快照 Weight 全为 0。

当前诊断快照的 45,611 个最新维度中：空维度 35,193，数量非零但重量未知
9,016，数量/重量均为正 1,222；重量无数量 114、负数量 54、负重量 112、
数量重量异号 66，三类异常去重后需隔离 234 个维度。

    FactQTY=0 且 FactWeight=0       -> 空维度，不建余额
    FactQTY!=0 且 FactWeight=0      -> 保存数量，重量=NULL（未知）
    FactQTY=0 且 FactWeight!=0      -> 隔离 WEIGHT_WITHOUT_QUANTITY
    FactWeight<0                    -> 隔离 NEGATIVE_WEIGHT，余额重量=NULL
    FactQTY 与 FactWeight 异号      -> 隔离 SIGN_CONFLICT，余额重量=NULL
    其余                            -> 保存 FactQTY 和数值 FactWeight

只有 Fact 字段本身为 NULL 时才允许回退 QTY/Weight，并记录
FACT_NULL_FALLBACK，不能静默混用。

## 5. 自动学习状态机

| 状态 | 日常行为 | 是否改变库存/金额 |
|---|---|---|
| UNCLASSIFIED | 数量为主，提供“补充实际重量” | 否 |
| PROVISIONAL | 弱提示最近存在同时登记重量的依据 | 否 |
| CONFIRMED | 有显式重量单位 UUID 后，默认展开实际重量 | 否 |
| CONFLICT | 保存当前输入，提交前集中处理冲突 | 否 |
| 人工覆盖 | 使用人工偏好；自动证据继续累计但不覆盖 | 否 |

默认在线门槛是 3 张独立单据、2 个业务日。空重量且来源不具备称重能力时不计作
BUSINESS_QUANTITY 反证；两种显式偏好都达到门槛时进入冲突，不按多数票静默决定。

旧库正重量没有单位，只能形成 PROVISIONAL 建议。用户未来第一次补充重量时必须先选择
重量单位 UUID；之后已审核/已过账事实可学习该单位。无 UUID 的重量不得进入在线证据账。

红冲通过追加 REVERSED 事件抵销原证据，不删除、不更新原事件。重复幂等键同 payload
可安全重放；同键异 payload、重复来源和二次红冲必须拒绝。

## 6. 页面交互

- 采购、销售、仓库、委外通用列统一为“数量”；重量列统一为“实际重量”。
- 盘点的“账面数量/实盘数量”、BOM 需求量、预留量等专业字段保持原名。
- 未学习时不新增常驻窄列；桌面和 375px 紧凑布局都先显示数量。
- 点击“补充实际重量”：
  - 已有重量单位 UUID：展开重量输入；
  - 没有 UUID：先显示“选择重量单位”，数值框不出现。
- 状态使用文字和图标，不只靠颜色；操作目标至少 44dp。
- 后台 profile 更新不清空用户已输入数值，也不在当前编辑过程中突然切换布局。

## 7. 数据与审计结构

V442 源码候选新增：

- unit_measurement_profiles：显式单位维度/换算治理；当前不按名称自动播种。
- measurement_capture_profiles：货品×场景当前投影。
- measurement_capture_line_snapshots：跨业务页面的显式数量/重量/单位快照。
- measurement_capture_evidence：已审/过账/红冲 append-only 证据。
- measurement_capture_decision_events：人工覆盖/撤销 append-only 决定。
- legacy_measurement_source_registry：旧表级能力和 qty resolver。
- legacy_measurement_profile_snapshots：formatVersion 3 manifest 绑定聚合画像。
- legacy_measurement_exceptions：少量不安全数据的隔离与解决记录。

measurement_capture_profiles 有独立 version，避免学习更新与 Goods 主档编辑产生无关 CAS
冲突。批量解析 API 必须一次处理当前页面全部 goods UUID，禁止逐行 N+1。

## 8. GO / NO-GO

当前允许：

- 本地只读画像；
- 源码候选、静态契约、纯领域测试和共享组件测试；
- 在完整 manifest 绑定导入中生成 PROVISIONAL 建议和异常队列。

当前仍为 NO-GO：

- 把现有本地 CSV 数字当成正式迁移验收；
- 把通用 Weight 全局解释为 kg、净重或毛重；
- 从单位名称、类别、平均比例或 goods.MWeight 自动补重量；
- 自动创建 WEIGHT_ONLY 正式库存事实；
- 在全部业务审核/红冲入口尚未接入显式重量单位前启用 ENFORCE；
- 在未完成目标非空库迁移、真实岗位 UAT、恢复演练和 Flyway exact-set 校验前部署或切流。

紧急回退只关闭提示/强制，保留证据、决定和异常；不得删除历史或批量改写库存数量。
