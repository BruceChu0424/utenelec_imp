# 旧库字段与业务语义核定

本文件记录已经用源结构、字典、视图、触发器和全量数据等式证实的含义，配合 [执行手册](重建彩排与正式导入执行手册.md)。它不是按相似字段名猜出的映射表。后续新来源必须重新核元数据和数据，不能只复用此批数量。

## 1. 证据分级和处理方法

1. **源结构直接证明**：计算列定义、DEFAULT/CHECK、真实外键、字典、视图与触发器。用这些确定字段口径。
2. **全量数据证明**：逐行、逐维度和上下游勾稽。不能只用总数或几个示例证明所有记录。
3. **明确整理规则**：用户授权的多年无活动单归历史，是有输入/阈值/理由的业务治理，不冒称物理收发已完成。
4. **尚无证据**：保留原始来源和缺口；历史缺字段直接归历史，不为补资料恢复草稿。错误且无有效业务依据的记录从业务中删除并留审计。

## 3. 原始关系不能用相似信息代替

- 单据头/行原ID和真实上游FK是首要身份；同货品、日期、单号片段或姓名不能代替FK。
- 同一SKU不同颜色、单位或倍率不能直接加总；一个SKU超发不能抵掉另一SKU未发。
- 无FK委外收发保留历史可查，不自动挂到两张2014反审/未审委外单，不据此推断供应商余额为零。
- 产品与原料的身份关系不等于真实单耗。缺克重时保留待核关系，不能填1形成可执行BOM。
- 源“未审核”“已审核”“停止/取消”“履约数量完成”“历史关闭”是不同维度，不能压成一个状态码。
- Sys_Logs是历史业务审计，不应泛称历史配置。明确动作+类型+完整单号可作头活动线索，但没有typed行ID时，遇到先删除后修改/重建不能证明仍是当前同一物理头，更不能据此恢复草稿。查询、打印或登录也不证明执行。最终31近期候选已核完整生命周期117条，仅31次新增和86次修改；删除、取消、审核、重建、重复新增均0。
