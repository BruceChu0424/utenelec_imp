# V814 车间到货通知产能水位

> 2026-10-06 · [ADR-165](../99-决策记录-ADR/ADR-165-车间到货通知产能水位与车间负责人受众.md)（修订 ADR-091 §2.3/§八）

## 改动

- 新建 1:1 水位表 `production_execution_segment_notice_state`（`segment_id` PK 级联删除、
  `arrival_notice_capacity numeric(18,4)`、`updated_at`）：「物料到货进展」行动卡上次评估
  时的**可支撑产能水位**。无行＝从未评估，按 0 对待。
- 不放段表加列：段表的 BEFORE UPDATE 触发器会 bump `lock_version`/`updated_at` 并重验
  车间负责人，每次水位变化会把在途的领料核对 CAS（「车间任务已变化，请刷新」）顶失效。
- 审计归 notice/NONE（系统协调状态）、清空业务数据 CLEAR（`business_data_reset()` 锚点
  插入 + 自检，V798/V809 同款）；不改存量数据、不加权限码。

## 行为

- `ChainNoticeService.publishWorkshopMaterialArrival` 每次到货事件按路线评估「当前可支撑产量」：
  - BATCH＝分批领料核对页的「当前可齐套生产量」（`ProductionExecutionBatchService.currentSplitCapacity`，
    与页面同一个数，剩余段自动扣前批）；
  - CONTINUOUS＝已备预留产能 `fn_execution_material_output_capacity(segment, FALSE)`；
  - FULL_KIT＝齐套全有或全无（WAITING 且全部缺口被盖住＝`planned_qty`，否则 0）。
- **只有当前产能 > 水位才发卡**（分批/持续路线文案带「（现有物料可支撑生产 X 单位）」，
  齐套卡维持原文案；暂缓中的分批段指引先解除暂缓）；发卡或回落都把水位 UPSERT 成当前值
  （值不变不写）。会自动提升的段（WAITING ∧ auto_promote ∧ 路线放行）先返回且不抬水位。
  到货撤销（物料状态更新卡）不受闸门约束，仍即时通知并同步水位。
- 水位只在通知投递线程（outbox delivery，段行 `FOR UPDATE` 锁内）UPSERT；
  `currentSplitCapacity` 的「不可计量」在事务边界内吞掉返回 null——异常越过
  @Transactional 代理出口会把共享的 outbox 投递事务标记 rollback-only，事件重试到死信。

## 受众（同批 Java 改动，无迁移）

`workshopRecipientUserIds` 收窄为「车间子树各部门负责人 ∪ 任务负责人 ∩ 车间任务权限」；
计划部等职能岗个人加授权限也不收卡；车间无任何负责人时兜底回旧全成员池。
