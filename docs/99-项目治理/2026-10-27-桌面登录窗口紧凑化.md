# 桌面登录窗口紧凑化

用户反馈 Windows/macOS 登录窗口过大。按默认 `frontend-design` 技能复用当前 Uten 主题、
NotoSansSC、原有 IP/Logo、表单控件及 16px 原生圆角，未新增装饰或第二套登录流程。

## 统一尺寸与布局

- 两平台登录目标从 1000×680 调整为 800×540 个逻辑像素/点，面积减少约 36.5%，继续限制在屏幕工作区。
- Windows 启动入口及退出登录后的尺寸、macOS 的同一模式入口同时迁移；主窗口初始 1280×800
  及主窗口位置、尺寸、最大化/全屏恢复规则保持原样。
- `DesktopLoginLayout` 是两平台唯一布局入口：左右比例 45/55，IP 最大 220、Logo 宽 170、
  表单最大宽 340，左右使用主题间距 24；标题 26。输入框与按钮继续使用既有控件可操作尺寸。
- 画布达到 680×440 时使用双栏；更窄、更矮或无障碍文字要求更多空间时使用原单列滚动表单。
  始终只创建一份表单，验证码、错误和账号密码不因切换丢失，顶部窗口控件仍与滚动区域分开。

## 完整接入及验证边界

调用点为 `windows/runner/main.cpp`、`win32_window.cpp`、
`macos/Runner/MainFlutterWindow.swift` 和 `lib/features/auth/widgets/desktop_login_layout.dart`。
两种原生实现只保留平台窗口职责差异，未改变认证、内网信任、路由、权限、自动会话恢复或数据保存。

原生 Windows 回归 79/79 通过，覆盖 800×540 启动/退出登录、圆角、DPI、工作区及主窗口恢复；
120 次区域替换前后 GDI 对象保持 10。证据位于
`D:/Projects/uten_imp/build/desktop-window-compact-20261027/verification.json`。
Flutter 用例覆盖两平台、标准/窄屏/矮屏及 100%、115%、150%、200% 界面倍率，并检查 MFA、滚动、
输入保全和实际可点击性。该平台模拟不等同于 macOS 原生编译/实机验收。

保留当前所有运行库与公司 CA 交付门禁；任何安装包和 ZIP 应由同一源码、版本、构建号生成。
源码、构建、安装及公司实机验收分别记录，不以界面预览代替安装验证。
