# 2026-10-26 公司资料库安全与稳定性检查

本轮按上传、存储、预览、下载、权限、密码、身份切换、并发、回收站和部署边界检查并直接修复。范围为当前本地候选及公司服务器只读配置；不等于已经上线、完成员工 UAT 或证明系统不存在任何漏洞。工作区原有并行改动保留，没有修改历史 Flyway 迁移、部署、重启或开启现场转换。

## 结论与原件语义

原有统一附件方案可以继续使用，应该补强具体边界，无需另建公开文件目录或第二套上传链。公司资料库仍走 `reserve -> presign -> raw PUT -> confirm -> complete`，只有经内容校验和扫描确认的不可变原件可发布。系统操作资格与资料 ACL/密码保持分离，前端按钮不能替代服务端判断。

客户端上传原始字节，不对图片做有损压缩、缩图或重新编码。内部存储有透明无损 GZIP：默认至少 64 KiB，节省至少 4 KiB 且 10% 才采用；不值得压缩或已有压缩的格式保留原编码。原始大小/SHA 与实际存储大小分开记录，读取先还原并校验，用户下载得到原始文件。内部压缩、损坏拒绝、解压限额、冷启动恢复和文件系统同步已有本轮 Linux 实测。

## 权限与密码检查结果

真实 PostgreSQL 回归覆盖了系统资格+当前资料 ACL、祖先拒绝优先、停止继承、人员/部门及禁用主体、独立文件和文件夹密码、本人再认证、十五分钟会话解锁、错误尝试限速、密码 revision 失效、跨账号/会话、回收还原、同名冲突、并发版本、创建幂等及不可覆盖原件。普通附件元信息、预览、原件/历史直链与资料库使用同一 owner 策略；已撤权对象不能靠知道 UUID 或旧附件身份读取。

密码继续只保存 BCrypt 哈希，至少 8 个 Unicode 字符且非空白，UTF-8 不超过 72 字节；更改现有 ACL/密码仍走系统管理资格与本人登录密码再认证。新建时的阅读设置不产生系统权限。审计不记录明文密码、哈希、原件路径或私密资料名称。未发现需要放宽这些规则的理由。
