# 15 - 采购模块 · 新库设计与迁移方案

> 设计依据：[14-采购模块-老库溯源.md](14-采购模块-老库溯源.md)
> 设计原则（用户钦定）：**业务零割裂感**（沿用老流程与体验）+ **底层重新设计**（高效）+ **未来海量数据仍快** + **安全**。
> 模块归属：**PMC 运营部 → 采购**，分两块交付：**采购管理**（单据操作）+ **采购报表**（明细/汇总分析）。

---

## 一、设计决策总览（含理由）

| # | 决策点 | 选型 | 理由 |
|---|---|---|---|
| 1 | 库存关系 | **库存独立模块 + 审核同事务联动**（事件流水+余额） | 解耦（销售/领料/盘点共入口）但审核即动库存，零割裂；取代老库按月分列台账 |
| 2 | 单据骨架 | **4 套独立主从表**（申请/订货/收货/退货） | 各步语义不同（请购无供应商/币种、收货要仓库收货人…），独立表约束清晰 |
| 3 | 链路溯源 | **真外键骨干 + 文本占位**（去字符串化） | 收货→订货→申请用单值 FK；销售/计划留 `source_*` 占位（新库未做） |
| 4 | 汇总报表 | **物化视图（最细粒度）+ 查询上卷** | 十几年几百万明细→物化视图几十万行，CONCURRENTLY 刷新，查询毫秒级 |
| 5 | 多币种 | **保留**，迁 `currencies` 字典 | 确有美金/港币进出口采购；金额分原币/本币双口径 |
| 6 | 历史迁移 | **全量十几年** | 明细按 `bill_date` 年分区应对规模 |
| 7 | 状态机 | `0草稿/1已审/-1红冲` + `is_closed` 派生 | 贴老库"保存即生效"，已审只可红冲 |
| 8 | 数量回写 | 明细保留 `received_qty/returned_qty`，Service 回写 | 老库验证过的模式（RQTY/WQTY），触发器逻辑上移到 Service |
| 9 | 主键/审计 | UUID + `legacy_id` 溯源 + 审计软删 | 同 goods/suppliers 主档惯例 |
| 10 | 基础资料归属 | **币种/仓库归「基础资料」模块**（与颜色/单位同级），非采购私有字典 | 全公司共用，统一 CRUD/迁移，未来持续扩展（税率/付款方式…） |
| 11 | 迁移补录 | 单据引用的基础资料缺失时**自动补录**最小记录到主档 | 引用完整性优先，不因主档未迁全而丢关联 |

## 二、模块划分

```
PMC 运营部
├─ 采购管理（操作类 · 单据）
│   ├─ 采购申请单  purchase_requests / *_items
│   ├─ 采购订货单  purchase_orders   / *_items
│   ├─ 采购收货单  purchase_receipts / *_items   ──审核──▶ 库存 +入库
│   └─ 采购退货单  purchase_returns  / *_items   ──审核──▶ 库存 -出库
├─ 采购报表（分析类）
│   ├─ 明细报表 ×4（参数化：日期范围 + 供应商/货品/状态/单号 + 多选列）
│   ├─ 汇总报表 ×4（物化视图：货品×供应商×月，量/额/均价）
│   └─ 待交货订货汇总（取代 P_OrderMore / View_P_OrderNoRec）
└─ 库存联动（独立模块，采购为其出入口之一）
    ├─ stock_movements（流水，所有出入库统一入口）
    └─ stock_balances（当前余额，仓库+货品+颜色粒度）
```

## 三、基础资料补迁（币种 / 仓库 · 归「基础资料」模块）

> **归属**：币种 `currencies`、仓库 `warehouses` 是全公司共用的基础资料，与货品/模具/客户/供应商/颜色/单位**同级**，挂「基础资料」页面，有独立 CRUD（复用 `MasterDataTableView` 表格模式，见记忆 *basic-data-master-ui-pattern*）、独立迁移脚本、独立权限点。**不是采购模块私有字典。**
>
> 基础资料是**持续扩展的统一模块**：现有 货品/模具/客户/供应商/颜色/单位 + 本次 币种/仓库，未来还有 税率/付款方式/交货方式 等，一律在此模块统一管理。

### 3.1 `currencies`（币种 · 迁 B_Currency，3 条）

| 老库 | 新库字段 | 说明 |
|---|---|---|
| ID | `legacy_id` | 溯源 |
| CurName | `name` | 人民币/美金/港币 |
| Number | `code` | 001/002/003 |
| ExRate | `exchange_rate` | 老库为 0（实际汇率在单据上），保留字段 |
| Status | `status` | 使用/禁用 |

> 老库 3 条扁平（ParentID=0），不建树。

### 3.2 `warehouses`（仓库 · 迁 B_Storage，6 条）

| 老库 | 新库字段 | 说明 |
|---|---|---|
| ID | `legacy_id` | — |
| Storage_Name | `name` | 成品仓/五金仓… |
| Number | `code` | C01/C04… |
| Location | `location` | 总仓库/轨道仓… |
| IsCal | `is_accountable` | 是否参与核算 |
| Status | `status` | 使用/禁用 |
| WorkID/WorkID1 | `workshop_id_legacy` | 关联车间（int 暂留，不 FK） |

### 3.3 迁移时「基础资料缺失」自动补录（引用完整性优先）

迁移单据明细时，其引用的 单位/颜色/币种/仓库/货品 ID 若在主档表 JOIN 不到（老库主档未迁全 / 孤儿 / 后续新增），**自动补录一条最小记录到对应主档表**，保证外键不断、不丢关联：

```sql
-- 示例：迁采购明细前，反推补录缺失的单位（先补主档，再 JOIN 出 UUID）
INSERT INTO units (legacy_id, code, name, status, auto_created)
SELECT DISTINCT s.unit_legacy_id,
       'LEGACY-' || s.unit_legacy_id,
       '（迁移自动补录）', '使用', TRUE
FROM purchase_order_stage s
WHERE s.unit_legacy_id IS NOT NULL
  AND NOT EXISTS (SELECT 1 FROM units x WHERE x.legacy_id = s.unit_legacy_id)
ON CONFLICT (legacy_id) DO NOTHING;
-- 同策略用于 colors / currencies / warehouses / goods
```

- 新主档表（currencies/warehouses）加 `auto_created BOOLEAN DEFAULT FALSE`；现有主档表（colors/units）若不便加字段，用 `code` 前缀 `LEGACY-` + 固定名称标识即可，事后人工补全。
- **运行时（非迁移）同理**：录单据时若基础资料不存在，前端「快速新建」弹窗 → 存主档 → 自动选上，杜绝「选不到就硬填」。

## 四、采购管理 · 表设计

### 4.1 统一约定

- 主键 `id UUID DEFAULT gen_random_uuid()`，迁移溯源 `legacy_id INT UNIQUE`。
- 单据号 `bill_no TEXT UNIQUE NOT NULL`（业务主键，新库用独立序列生成器，防并发冲突）。
- 审计四件套 `created_at/updated_at/created_by/updated_by` + 软删 `is_deleted/deleted_at`（同主档）。
- 金额统一 `NUMERIC(18,4)`，数量 `NUMERIC(18,4)`，汇率 `NUMERIC(18,6)`，税率 `NUMERIC(18,4)`。
- 金额双口径：`*_original`（原币）+ `*_local`（本币 = 原币×汇率）。
- **明细表冗余 `bill_date`**：作为分区键 + 查询裁剪列（避免每次 JOIN 主表取日期，值得反范式）。

### 4.2 主表（以 `purchase_orders` 为例，其余三类同构增减）

```sql
CREATE TABLE purchase_orders (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    legacy_id       INT  UNIQUE,                         -- P_Order.ID
    bill_no         TEXT NOT NULL,
    bill_date       DATE NOT NULL,
    supplier_id     UUID REFERENCES suppliers(id),       -- VendID（申请单无）
    warehouse_id    UUID REFERENCES warehouses(id),      -- StockID
    currency_id     UUID REFERENCES currencies(id),      -- CurID（申请单无，默认本币）
    exchange_rate   NUMERIC(18,6) DEFAULT 1,             -- CRate
    tax_rate        NUMERIC(18,4) DEFAULT 0,             -- TRate
    purchaser_id    UUID,                                -- Purchaser → employees（订货单）
    maker_id        UUID,                                -- MakeID → employees
    approver_id     UUID,                                -- ApproverID → employees
    remark          TEXT,
    total_original  NUMERIC(18,4) DEFAULT 0,             -- 合计（原币）
    total_local     NUMERIC(18,4) DEFAULT 0,             -- 合计（本币）
    status          SMALLINT NOT NULL DEFAULT 0,         -- 0草稿/1已审/-1红冲
    is_closed       BOOLEAN NOT NULL DEFAULT FALSE,      -- 结案（Service 派生）
    source_doc_no   TEXT,                                -- 销售/计划溯源占位（新库未做）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID, updated_by UUID,
    is_deleted BOOLEAN NOT NULL DEFAULT FALSE, deleted_at TIMESTAMPTZ,
    UNIQUE (bill_no)
);
```

各单据差异：
- **申请单 `purchase_requests`**：无 `supplier_id`/`currency_id`/`exchange_rate`/`tax_rate`（请购本币、未定供应商）；增 `applicant_id`（Applier）、`need_date`（需求日）。
- **订货单 `purchase_orders`**：如上；增 `deliver_date`（交货日 SendDate）。
- **收货单 `purchase_receipts`**：增 `sender_id`（交货人 SenderID）、`receiver_id`（收货人 Receiver）；`supplier_id` 必填。
- **退货单 `purchase_returns`**：增 `receiver_id`；`supplier_id` 必填。

> ❌ **去除** 老库 `P_Order.GoodsID`（主表挂货品的一单一货遗留，与明细冲突）。

### 4.3 明细表（分区 · 以 `purchase_order_items` 为例）

```sql
CREATE TABLE purchase_order_items (
    id              UUID DEFAULT gen_random_uuid(),
    legacy_id       INT,
    bill_no         TEXT NOT NULL,            -- 冗余（分区友好 + 报表）
    bill_date       DATE NOT NULL,            -- 冗余（分区键）
    order_id        UUID NOT NULL REFERENCES purchase_orders(id) ON DELETE CASCADE,
    line_no         INT,
    goods_id        UUID NOT NULL REFERENCES goods(id),
    color_id        UUID REFERENCES colors(id),
    unit_id         UUID REFERENCES units(id),
    unit_rate       NUMERIC(18,6) DEFAULT 1,  -- URate（qty×unit_rate=基本量）
    qty             NUMERIC(18,4) NOT NULL,   -- QTY 订货量
    price           NUMERIC(18,4),            -- Price
    amount_original NUMERIC(18,4),            -- Total 原币
    amount_local    NUMERIC(18,4),            -- 本币
    received_qty    NUMERIC(18,4) DEFAULT 0,  -- RQTY 已收（Service 回写）
    returned_qty    NUMERIC(18,4) DEFAULT 0,  -- WQTY 已退（Service 回写）
    request_item_id UUID REFERENCES purchase_request_items(id),  -- ApplyID 真FK
    deliver_date    DATE,                     -- SendDate
    weight          NUMERIC(18,4),
    remark          TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    is_deleted BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (id, bill_date)
) PARTITION BY RANGE (bill_date);
-- 建初始分区：2020–2030 逐年（pg 14+ 支持后续自动分区 pg_partman 或月度 cron）
```

链路真外键骨干：
- 收货明细 `purchase_receipt_items.order_item_id` → `purchase_order_items(id)`（OrderID）
- 退货明细 `purchase_return_items.receipt_item_id` → `purchase_receipt_items(id)`（InID）
- 退货明细 `purchase_return_items.order_item_id` → `purchase_order_items(id)`（OrderID）
- 订货明细 `request_item_id` → `purchase_request_items(id)`（ApplyID）

> 明细原生量只留 `qty/price/amount` + `received_qty/returned_qty` 两个回写量。老库十几个模糊数量列（DQTY/SQTY/UseQTY/FlagQTY/BPQTY…）**不迁**，其中确有业务含义的（BPQTY 赠品）以独立列 `gift_qty` 保留，其余丢弃。

### 4.4 状态机与结案（Service 层实现，取代触发器）

```
录入 → status=0(草稿) 或 1(已审，贴老库"保存即生效")
审核 status 0→1：同事务内
   · 收货单：received_qty 回写订货明细 + 写 stock_movement(+入库) + upsert stock_balance
   · 退货单：returned_qty 回写订货/收货明细 + stock_movement(-出库) + stock_balance
   · 订货单：received_qty(已订) 回写申请明细
   · 重算相关单据 is_closed
红冲 status 1→-1：同事务反向冲销（库存反写、回写量倒回），单据保留不可删
```

结案派生：`is_closed = (所有明细 qty − received_qty + returned_qty ≤ 0)`，在明细/下游变化时由 Service 重算主表。

## 五、库存联动 · 表设计（独立模块）

> 库存是 PMC 下一个独立大模块，但采购是其第一个出入口。本期做**最小可用**：流水 + 当前余额，支撑采购审核的零割裂库存效果；完整台账报表（期初期末/月报表）后置到库存模块。

```sql
-- 出入库流水（所有单据统一入口：采购/销售/领料/盘点/调拨…）
CREATE TABLE stock_movements (
    id              UUID DEFAULT gen_random_uuid(),
    transaction_date TIMESTAMPTZ NOT NULL,
    movement_type   SMALLINT NOT NULL,        -- 1采购入库 2采购退货 3销售出库 ...
    source_doc_type TEXT NOT NULL,            -- 'PURCHASE_RECEIPT' / 'PURCHASE_RETURN'
    source_doc_id   UUID,
    source_item_id  UUID,
    goods_id        UUID NOT NULL REFERENCES goods(id),
    color_id        UUID REFERENCES colors(id),
    warehouse_id    UUID NOT NULL REFERENCES warehouses(id),
    direction       SMALLINT NOT NULL,        -- +1 入库 / -1 出库
    qty             NUMERIC(18,4) NOT NULL,   -- 基本单位量（已乘 unit_rate）
    unit_id         UUID, unit_rate NUMERIC(18,6),
    amount_local    NUMERIC(18,4),
    remark          TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (id, transaction_date)
) PARTITION BY RANGE (transaction_date);

-- 当前余额（仓库+货品+颜色 粒度）
CREATE TABLE stock_balances (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    warehouse_id    UUID NOT NULL REFERENCES warehouses(id),
    goods_id        UUID NOT NULL REFERENCES goods(id),
    color_id        UUID,                     -- null=无色
    qty             NUMERIC(18,4) NOT NULL DEFAULT 0,
    amount_local    NUMERIC(18,4) DEFAULT 0,
    last_movement_date TIMESTAMPTZ,
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (warehouse_id, goods_id, color_id)
);
```

采购审核事务内：
```
INSERT stock_movements(direction=+1/-1, qty=Δ基本量, ...)
ON CONFLICT (warehouse_id,goods_id,color_id) DO UPDATE SET qty = stock_balances.qty + Δ, ...
```

> 相比老库 `StockGoods` 按月分列（INQTY01..12）：流水模型天然支持任意时间范围、跨年、多种单据类型，余额实时，历史走流水聚合（可再建按月物化视图）。这是"底层重新设计、更高效"的核心体现。

## 六、采购报表 · 实现（2026-07-27 完成，镜像销售报表 [20] §六）

> 9 张报表（催料单 + 申请/订货/收货/退货 各明细/汇总），**服务端 JOIN 出名称 + 列 facet + 分页**，live 查询（不依赖物化视图）。老系统采购报表 1:1 复刻。

### 6.1 入口（hub 3 卡，前端镜像 sales）

hub「采购报表」分区（`lib/features/purchase/pages/purchase_hub_page.dart`）：
- **采购明细报表** `/purchase/report/detail` — 卡内 ChoiceChip 切 申请/订货/收货/退货
- **采购汇总报表** `/purchase/report/summary` — 卡内 ChoiceChip 切 申请/订货/收货/退货
- **采购催料单** `/purchase/report/expediting` — **独立**（不分明细/汇总，无类型切换）

页面 `purchase_report_table_page.dart`：左筛选栏（单据类型 chip[非催料] + 日期范围[默认 2018 至今] + 搜索 + 查询）+ 右 `MasterDataTableView`（动态列 + 表头每列 autofilter + 横滚 + 翻页）。配置 `purchase_report_config.dart` 双枚举 `PurchaseReportKind{detail/summary/expediting}` × `PurchaseReportDocType{request/order/receipt/return}`。

### 6.2 后端（`features/purchase/report/`）

- 端点（统一前缀 `/api/purchase/reports`，权限 `purchase_report:view`，返回 `ReportTableResponse{columns,rows,facets,page,totalPages,total}`）：
  - `GET /expediting`（催料单：订货明细未收 + 库存/安全库存）
  - `GET /{request|order|receipt|return}/detail`、`/{...}/summary`
- **服务端 JOIN 出名称**（供应商/仓库/货品/颜色/单位/类别/人员），前端按 columns 动态建列；列 facet（供应商/仓库/结帐方式/是否审核/完成/中止）供表头 autofilter；分页 + `CAST(:p AS 类型)` 防空参数坑（见 MEMORY *hibernate-native-query-null-param-type*）。
- **人员名解析**：`LEFT JOIN employees em ON em.legacy_id=o.*_legacy_id OR em.id=o.*_id` —— **OR 同时覆盖历史(legacy_id)与新单(UUID)**。`employees.legacy_id` 未填前历史人名显空白；新单 `create` 写 `maker_id`/`approve` 写 `approver_id`（=当前登录用户），故新单制单/审核员即时显示。

> **去/留决策**：「围数」老库全表无此字段 → 去列；「结帐方式」PStyle 无字典 → 存原值 + 留字典位（`PurchaseSettlementStyle`，待业务填）；「安全库存」= `goods.min_qty`（老库无独立字段）；「库存数量」= `SUM(stock_balances.qty)`；「人工费」= `goods.work_e`；「产成品名称」经 production_plan_no → 生产计划推导（常空）。

### 6.4 物化视图（保留，非 9 报表依赖）
