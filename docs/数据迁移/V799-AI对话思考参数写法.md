# V799 AI 服务商「思考参数写法」扩展(ADR-152)

> 编号说明: V799 是 AI 轨道 worktree 的临时号(与仓库整改轨道的 V799 并行); 集成时由编排者重排并同步迁移头五处(README 头行、reset 脚本版本对、两个 ops 契约测试、migrationsExecuted、MigrationRehearsalSupport)。本文件随改号一起改名。本文不代表业务数据库已经安装。

## 做了什么

- `ai_providers.thinking_control` 的 CHECK 从 `NONE/DEEPSEEK/DASHSCOPE/OPENAI_REASONING` 放宽为再加 `ZHIPU`、`ANTHROPIC_EFFORT`; 列注释改为「思考参数写法」。
  含义: AI 对话设置里的「思考程度」(快速/标准/深入)按这一写法映射成服务商参数(智谱: OpenAI 兼容端点 `thinking` + `reasoning_effort`, Anthropic 兼容端点 `output_config.effort`; Claude 4.6+: `output_config.effort`)。
- 已有的智谱配置(`preset = 'ZHIPU'` 且 `thinking_control = 'NONE'`)改为 `ZHIPU`, 同时 `version + 1`、`updated_at = now()`(行审计 COLUMN_SCOPED 照常记录这次变更)。其它服务商的配置不动: Claude 预设新建时默认 `ANTHROPIC_EFFORT`, 但不改存量(Haiku 4.5 等不认 effort 的模型由管理员自选)。
- 不加表、不加列、不加权限点; 业务数据清空分类不变(`ai_providers` 仍 PRESERVE)。

## 对现有用途的影响

识别类用途(销售文件识别、文件分类等)调用公共平台时不要求思考程度(`DEFAULT`), 映射结果与迁移前完全一样: DeepSeek/通义/OpenAI 写法照旧关思考, 智谱与 Anthropic 写法照旧不发参数。只有 AI 对话按账号设置发出明确档位。
