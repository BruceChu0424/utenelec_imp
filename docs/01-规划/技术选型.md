## 一、技术栈总览

| 层 | 选型 | 版本 | 选型理由 |
|---|---|---|---|
| 框架 | Flutter | `>=3.27.0`；CI 固定 3.44.2 | 一套代码六端（iOS/Android/Web/Windows/macOS/Linux），制造业 IT 团队维护成本低 |
| 语言 | Dart | SDK `^3.12.2` | 强类型、空安全、AOT 编译性能好 |
| 状态管理 | Riverpod | 2.x | 类型安全、可测试、无 BuildContext 依赖、社区主流 |
| 路由 | go_router | 最新 | 官方推荐、声明式、Web 深链友好、支持守卫 |
| 设计系统 | Material 3 | 内置 | Flutter 官方支持，主题 token 化好 |
| 国际化 | intl + gen_l10n | 官方 | 不引入额外依赖，arb 文件可协作 |
| 偏好存储 | shared_preferences | 最新 | 轻量偏好（主题/语言/字号/性能档/工作台布局缓存） |
| 敏感存储 | flutter_secure_storage | 最新 | token / refresh（iOS Keychain / Android Keystore，已启用） |
| 设备检测 | device_info_plus | 最新 | 用于性能分级和生成经清洗的审计设备声明；安装标识是应用随机 UUID，不采集 IMEI、MAC 或硬件序列号，也不构成可信设备认证 |
| 网络层 | dio | 最新 | 拦截器机制好；已接真实后端，AuthInterceptor 自动加 token + 401 静默刷新 |
| Lint | very_good_analysis | 最新 | 严格规则，团队风格统一 |
| 测试 | flutter_test；integration_test 依赖已声明 | 内置 | 当前有单元/Widget 测试，但尚无 `integration_test/` 用例，不能宣称集成测试已落地 |

## 二、为什么选 Flutter（而不是 React Native / 原生 / Web）

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Flutter** | 一套代码六端、UI 一致、性能好、Dart 强类型 | 桌面端生态不如原生（但企业后台够用） | ✅ 选定 |
| React Native | Web 生态成熟 | 桌面端支持差（RN 桌面不成熟）、双端 UI 不一致 | ❌ |
| 原生（各端分别做） | 体验最佳 | 5 端 × N 个模块开发量爆炸 | ❌ |
| 纯 Web | 桌面/移动浏览器都跑 | 移动端体验差、离线弱、无法上架 | ❌ |

详见 [../99-决策记录-ADR/ADR-001-技术栈选型.md](../99-决策记录-ADR/ADR-001-技术栈选型.md)。

## 三、为什么选 Riverpod（而不是 Provider / Bloc / GetX）

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Riverpod 2.x** | 类型安全、可测试、无 context 依赖、AutoDispose、AsyncNotifier 一站式 | 学习曲线略陡 | ✅ 选定 |
| Provider（官方旧） | 简单 | 无类型、依赖 BuildContext、复杂状态难管理 | ❌ 已被 Riverpod 超越 |
| Bloc | 强约束、事件流清晰 | 样板代码多、对中小项目过重 | ❌ |
| GetX | 简单 | 架构混乱、反模式多、社区争议大 | ❌ |

详见 [../99-决策记录-ADR/ADR-002-状态管理选Riverpod.md](../99-决策记录-ADR/ADR-002-状态管理选Riverpod.md)。

## 四、为什么选 go_router

- Flutter 官方 package（first-party）
- 声明式路由，配置集中
- 支持 Web 深链和浏览器地址栏
- 内置 redirect 钩子，做路由守卫（未登录跳登录页）简单
- 支持嵌套导航（ShellRoute 外壳 + 子页面）

---

## 五、为什么用 Material 3（而不是自建设计系统）

- Flutter 官方支持，ThemeData 直接配
- ColorScheme / TextTheme / ComponentTheme 全套 token
- 响应式断点有官方推荐（WindowSizeClass）
- 团队学习成本低（设计师也熟悉 Material）
- 不选自定义系统：避免重复造轮子，企业后台不需要"惊艳到独一无二"

在 Material 3 基础上用品牌色（深绿+青绿）覆盖默认蓝色。

> 销售/采购/委外/仓库/生产/钱流/基础资料/HR/鉴权/访客/通知/建议使用真实后端。
> 工资与员工报销前端已切 Dio，V133 表、后端 API 与固定状态机已有源码；是否完整仍以权限、
> 审批/薪酬口径、会计副作用和生产 E2E 为准。实验室检测 / 空调控制等设备能力待后续接入。

| 维度 | 实现 |
|---|---|
| 数据 | PostgreSQL 16 + Flyway；共享工作树最高 V392/354。版本化 pgcrypto 只覆盖既有及 V282/V284 指定 PII，V286/V287 只处理可选主身份行及其派生一致性，不是全库/TDE；V288/V289 建立现货借用结构、终态守卫与审计覆盖，在线链仅为未部署源码候选。金额、余额、汇率、税额、成本和数量保持精确 `NUMERIC`。公司现有 `uten_imp` 既有只读证据仍为 V238，隔离克隆 V244 只是历史证据；目标库必须备份、迁移、对账，不能把源码或克隆验证当生产迁移完成。公司主库是唯一日常写端，阿里云仅作未来异步物理热备 |
| 网络 | Dio + Repository；原生 Release 固化公司/云端两个批准的 HTTPS API，优先探测公司入口；Web Release 只用同源 `/api`。云端员工请求由 `remote_access` 服务端门禁，断开主库链路时返回 503，不缓存或重放业务写 |
| 认证 | Argon2id + JWT（access 源码默认 15min + refresh 7 天，TTL 可配 + 不透明轮换 + 重用检测）+ V135 授权版本逐请求校验 + 首登强制改密 |
| 存储 | 偏好 shared_preferences；令牌 flutter_secure_storage（禁止混用）；两端附件共用私有阿里云 OSS，已确认对象固定精确 `versionId` 和服务端 SHA-256。PostPolicy 大小门禁、staging/final、恶意内容扫描、删除 outbox 与真实 Bucket 恢复仍是上线阻断 |
| 加密 | 已纳入范围的身份证/手机/银行/薪资等 PII 使用版本化 pgcrypto 过渡密文 + DTO 按权限点脱敏 + 导出 Agile AES-256；磁盘/快照和备份分别依赖加密卷与加密仓库，远端数据库使用 TLS `verify-full`。外部 KMS/HSM/Vault envelope、目标主机 LUKS/云盘和目标库 V282/V284/V286/V287 回填/约束验收仍为 NO-GO（[ADR-037](../99-决策记录-ADR/ADR-037-数据库数据保护与分级加密.md)） |

| 数据导出 | 独立 `*:export` 权限 + Bucket4j 限流 + 可选 Agile AES-256（密码为空则普通 Excel，非空 1–128 位则加密，且只入 body）+ 行数上限 + 审计；审计导出必须同时持 `audit_log:view` 与 `audit_log:export`（[ADR-032](../99-决策记录-ADR/ADR-032-导出文件可选密码保护.md)） |
| 系统设置 | 运行时策略阈值可视化 + 二次密码确认 + 审计；审计在线期 1–120 月、追加归档期 0–240 月（默认 6+30 月）（[ADR-013](../99-决策记录-ADR/ADR-013-系统设置与安全策略可视化.md)） |
| 审计 | 请求、显式事件、公开业务表变化三层留痕；默认用户写操作、对象/Request ID 筛选、`snapshotId` 高水位、V184 触发器强校验、V185 软删除/脱敏加固、风险统计、四页详情、设备证据、本机在线授权核对、加密导出和自动留存见[审计中心](../03-页面/审计日志页.md) |
| 错误处理 | 统一错误码（ApiException），不泄露后端细节 |
| 架构 | Repository 接口模式，业务代码与数据实现解耦；报表统一走 `ReportTableResponse` 范式；部署拓扑由 [ADR-031](../99-决策记录-ADR/ADR-031-本地云端单主库部署架构.md) 固定为单主异步热备 |
| 交付门禁 | GitHub Actions：Gitleaks 全历史、Maven verify、Flutter format/analyze/test/Web build、CodeQL Java 安全与质量分析、OSV 周期扫描；生产还必须完成不可变制品、目标环境切流、回滚/恢复、多网络多账号 UAT，自动化全绿不等于可上线 |

> **CI 安全扫描产物口径（2026-08-01）**：当前私有仓库不接 GitHub Code Scanning，CodeQL 与 OSV
> 均不向 Security 页上传 SARIF，而是把 SARIF 保留为 GitHub Actions artifact。OSV 仍显式启用
> `fail-on-vuln`，发现依赖漏洞时任务失败；artifact 只改变结果存放位置，不放宽漏洞门禁。
