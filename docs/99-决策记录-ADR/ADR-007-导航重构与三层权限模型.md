# ADR-007：UI 导航体系重构（悬浮胶囊导航 + 工作台集散）与三层权限模型

> 日期：2026-07-23 · 状态：已实施（前端 + 后端均已落地）

## 背景

原导航为「桌面后台式」三档外壳：compact 底部 Tab / medium 折叠 Rail / expanded 左侧分组侧栏。问题：

1. 大屏下左侧栏（240/72dp）长期挤压内容区，业务页面可用宽度受限；
2. 角色分组入口藏在侧边栏，手机端（compact）根本看不到这些入口，人事/财务在手机上无处进入业务页；
3. 权限只有「用户 → 角色 → 权限点」一层，无法表达「某部门统一给什么权限」「给某个人单独加/减一个权限点」，也没有权限管理 UI（只有后端接口）。

## 决策

### 导航：全断点统一底部悬浮胶囊导航

- 取消侧边栏/Rail，全断点（含桌面/Web）统一为底部**悬浮胶囊导航**，仅 4 项：**工作台 · 通知 · 我的 · 设置**；overlay 悬浮不占布局，内容全屏宽。
- 四主 Tab 由外壳内部 `PageView` 承载，支持**左右跟手滑动**，胶囊滑块高亮随连续位置实时联动（交互参照 JustPlay 实现，技术栈适配 Riverpod + go_router，不引 GetX）。
- 路由双向同步：滑停 `context.go` 更新 URL；深链/点胶囊 `animateToPage` 切页；四页保活。
- 业务子页面照常走 go_router；因部分页面自带 `bottomNavigationBar`，业务页底部预留胶囊高度防遮挡，主 Tab 页则以底部留白让内容可滚过胶囊。

### 工作台：功能集散中心，按权限点显隐

- 原侧边栏的角色分组（人事/财务/生产/决策/保安）全部迁入**工作台功能模块区**；内容取消 `maxWidth` 收束，全屏宽。
- 显隐判定从「按角色硬编码清单」改为**按权限点**：直接复用路由守卫的 `requiredPermFor()` 映射（单一数据源）——超管给谁授了什么权限，工作台自动出现什么模块。
- 全部分区（今日概览/待办/每个功能分组）支持折叠（新组件 `UtenCollapsibleSection`）。

### 权限模型：三层合成 + 管理后台

- 权限来源 = **直接角色 ∪ 直属部门角色（`department_roles`，V21 迁移）→ 权限点并集 → ± 个人覆盖（`user_permission_overrides` grant/revoke）**；超管全量不变。部门角色仅对直属员工生效（不含子部门，避免递归带来的不可预期授权）。
- 新增[权限管理页](../03-页面/权限管理页.md)（`/admin/permissions`，`user:manage` 守卫）：按员工（角色分配 + 三态权限覆盖矩阵 + 账号操作）/ 按部门（默认角色）。
- 安全守卫：不能改超管账号的角色/覆盖；非管理员不能授 admin 角色；写操作走既有审计。
- 生效时机：JWT perms 在登录/刷新时由 `AuthService.permsOf` 合成，变更**下次登录或令牌刷新后生效**（页内有提示）。

## 备选方案（未采纳）

| 方案 | 不选原因 |
|---|---|
| 保留侧边栏、仅加胶囊导航为 compact 档 | 三档三套导航维护成本高；手机端角色入口问题依旧 |
| `StatefulShellRoute` 承载四 Tab | 无法提供跨分支连续跟手滑动 |
| 权限粒度只到角色（不做个人覆盖） | 无法满足「财务但额外能发通知」这类真实诉求 |
| 部门角色递归子部门生效 | 授权范围不直观，容易「不知不觉给了权限」；先仅直属，后续有需求再评估 |

## 影响

- 删除：三档外壳（约 550 行）与原 `_NavGroup` 角色硬编码清单。
- 新增组件：`FloatingCapsuleNavBar`、`UtenCollapsibleSection`；工作台 `WorkbenchModuleArea`。
- 后端：V21 迁移（2 张表）、`permsOf` 合成升级、`/api/admin` 六个新/改接口。
- 文档：App外壳 / 工作台首页 / 页面总览 / 全局机制 §一 / 权限管理页（新建）。
- 已知限制：后端用 javac（JDK 21 + .m2 缓存）编译验证，未跑 Flyway 迁移与 Spring 启动，需在下次 `mvn spring-boot:run` 时确认 V21 正常执行。
