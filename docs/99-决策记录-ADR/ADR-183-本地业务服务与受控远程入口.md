# ADR-183 本地业务服务与受控远程入口

日期：2026-10-17。状态：已合并本地主分支；须完成发布及现场接入验收后启用。用户已授权完成代码和文档，尚未购买云资源或变更正式服务器。

## 背景与决策

目前外部同时使用不超过5人，偶尔海外；公司外网断开时允许外部暂停正式办理。公司是日常生产、仓库和财务业务的主要操作地点。因此保持一个公司本地业务服务和一个本地 PostgreSQL 写主库，阿里云只提供受控传输入口。

本决策替代 ADR-031 中“云端业务 App 的普通请求通过 WAN 逐条访问公司主库”的日常路径；保留其唯一写主、显式远程授权、断链不双写、灾备接管必须隔离旧主的原则。旧 cloud profile 与退役 Runbook 不作为本方案安装入口。未来独立异地恢复继续按 ADR-157 和现役备份合同建设。

## 网络与身份边界

员工到公司业务域名的 TLS 在公司终止，正式证书私钥、DNS/ACME权限均不在云入口。云 Nginx stream 转发内层员工 TLS，并通过 WireGuard 上的独立机器 mTLS 连接公司传输入口；公司解开外层后才处理员工 HTTPS。云端不能读取员工密码、动态验证码、令牌或业务正文。

WireGuard只配置两端主机地址，不发布办公室或数据库子网。公司侧防火墙仅允许已登记云 peer 到专用传输端口，禁止该接口转发至 LAN，禁止 SSH、数据库、共享文件及其他端口。云入口不持有公司管理、数据库、备份或解密身份。公司接入进程以独立身份运行，出站和文件读取受限。

这些边界以公司侧强制策略为准。失陷云节点仍可能中断、延迟或主动向 ERP 发起请求，所以应用认证、MFA、授权、限流、漏洞修补与审计仍是必要边界；不能据加密隧道宣称零入侵风险。

## 后端入口分类

主 Tomcat connector保留内网行为；显式配置后新增仅绑定127.0.0.1的remote connector，默认8082。公司受控远程代理只连接此端口，入口类别取真实 connector端口。客户端可构造的Origin、X-Forwarded-For、X-Forwarded-Port或自定义头不能改变它。

本地入口继续检查精确办公CIDR，远程入口执行当前全局策略、员工remote_access及MFA。缺失或冲突来源不得回退成公司身份。来源在一次请求的过滤链绑定并在finally清理，避免线程复用污染。HTTP登录、刷新、每个已认证请求与附件均遵守此规则。新增员工远程入口默认不发布访客系统，模拟身份只允许内网。

## 运行策略与强认证

V874新增`remote_access_policy`单例，默认关闭、授权容量5人。人数是授权账号容量，不是同时打开窗口数；提高容量须先验证网络、业务负载和内部预留容量。授权与人数修改共用数据库锁，避免并发授予超过上限。全局策略修改与新增远程授权只允许公司内网超管并遵守原有再认证；撤销继续使旧会话失效。

V873新增员工TOTP凭据和会话MFA时间。密钥通过现有AES-GCM SecretCipher、环境/用户/列绑定AAD加密；注册仅内网且要求再认证，pending有时限并绑定发起会话。TOTP采用标准时间步、容差与原子单次消费，失败计数及锁定在拒绝响应前持久化。重置因子要求内网超管、再认证和理由，并撤销会话。

业务清空保留已绑定MFA因子和远程策略，但继续清除auth_sessions。pending_session_id仅保存软引用，确认时必须重新检查活会话、本人、同一sid和TTL；不能因外键依赖而阻止原有会话清空，也不能将旧pending身份当作凭证。清空后旧会话和证明失效，新登录需重新取得MFA证明。

外网登录必须先确认口令、账号状态及远程资格，再验证第二因子，之后才能签发带服务端MFA状态的会话。内网旧JWT进入远程入口不能绕过MFA；验证码验证绑定当前用户和当前sid。刷新不延长MFA窗口，改密不凭空延长远程验证资格。现有单设备会话规则继续适用。

每请求的外网总开关和MFA状态随现有账号/会话SQL一次读取，不增加一次跨网数据库查询或逐请求MFA状态接口。动态验证码和注册密钥不进入日志、审计内容、草稿或普通偏好。

刷新先以标量投影定位用户及会话，再按**用户 → 刷新令牌 → 会话**取锁；不能在等待用户锁之前把令牌实体加载到一级缓存。取得令牌锁后重新核对用户、sid及hash，再检查当前资格。实际Hibernate用户整实体flush可能升级用户行锁，因此不能只凭最初的`NO KEY UPDATE`判断外键插入安全。该定位仅使刷新增加一次标量查询，普通业务请求不增加查询。

MFA解除先非锁读取当前会话，消费验证码后取得刷新令牌锁，再锁定会话重验，最后清除因子及撤销会话；最终清理函数不得反向取得令牌锁。若登出抢先完成，晚会话检查必须使整个事务回滚，保留因子且不部分消费验证码或撤销令牌。账号改密、撤权、验证器重置与刷新必须维持同一锁序。真实PostgreSQL并发回归与合并证据见[安全性能复核记录](../99-项目治理/2026-10-17-远程接入安全性能复核与主分支合并.md)。

## 性能与故障语义

HTTP业务请求跨网一次，接口内SQL在公司完成。远程请求有独立并发预算，默认8；五人同时加载页面形成短突发时，最多等待100毫秒获取容量；持续饱和则在执行业务前拒绝，不排无限队列、不自动重放写。公开健康检查另限2并发，避免匿名HTTP/2探针绕过业务预算。启用connector时检查“业务预算+2≤连接池上限−4”；这只是名义容量校验，嵌套事务可能每请求占用多个连接，不能当成物理连接预留。提高预算前要核对Hikari等待、真实业务并发及内网P95。

远程服务端处理耗时与拒绝计数只用固定指标名，无用户、单据、URL或参数标签；它不包含员工网络、TLS握手和完整下载耗时。采购验收另从客户端记录5和10并发下各类关键接口端到端p50/p95/p99、错误和传输字节。额外connector显式开启JSON压缩，避免遗漏主connector的压缩配置；既有重查询需要单独定位，不能通过买大ECS掩盖。

链路中断时公司本地继续工作，远程正式办理暂停。MFA恢复成功不自动重放原业务写。客户端保留已支持并实际落盘成功的本机草稿；提交已发出却未收到结果时必须核对原命令，不能推断失败。已有业务命令回执按具体模块使用，全平台通用幂等不是本决策凭空建立的能力。

## 数据保护与扩容

数据库、附件、权限、配置和历史密钥依赖继续按成套恢复规则保护；异地副本与热备属于独立阶段。提升云副本前必须在数据库/主机/存储层可靠隔离旧主，不能只关HTTP入口。恢复之前就停用远程通道，之后持续隔离，撤销恢复出来的旧会话、刷新凭据及MFA证明，复核最近授权/撤权记录，再要求重新登录和验证；不能让历史备份复活已经撤销的远程资格。

扩容顺序是先测上行和慢接口，再调整授权容量、并发与带宽；入口故障影响超过维护成本时增加双WAN及两个可用区入口。若本地主机成为瓶颈，先优化查询、事务和任务，再评估冗余事务盘与应用资源。任何迁移主站或多实例业务运行均需单独评审后台任务、事件、原件与故障恢复。
