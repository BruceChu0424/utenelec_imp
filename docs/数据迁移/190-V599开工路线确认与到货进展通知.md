# V599 开工路线确认与到货进展通知

- 日期：2026-09-17
- ADR：[ADR-091](../99-决策记录-ADR/ADR-091-开工路线确认与到货进展通知.md)
- 关联：V561（分批谱系）、V595（持续生产/线边仓）、[V564](160-V564逐行分批领料申请数量.md)

## 改了什么

| 对象 | 变更 |
| --- | --- |
| `production_execution_segments.start_route` | 新列，TEXT NULL，CHECK 白名单 `FULL_KIT/BATCH/CONTINUOUS`；NULL=待车间确认 |
| `production_execution_segments.route_confirmed_at` | 新列，TIMESTAMPTZ NULL；操作人记在事件账 `ROUTE_CONFIRMED` 的 `created_by` |
| 存量回填 | `continuous_supply=TRUE` → `CONTINUOUS`；其余全部段（含 WAITING、含分批谱系段）→ `FULL_KIT`，`route_confirmed_at=now()`。**升级零摩擦：没有任何在途单被新门锁住**；WAITING 老单想改路线走「重新确认」 |
| `fn_execution_route_allows_auto_promote(UUID)` | 新函数（唯一口径）：FULL_KIT=放行齐套自动提升；BATCH/未确认=抑制；CONTINUOUS=持续生产开工置位后放行。`tryPromote` 的段查询追加此谓词 |
| `fn_can_change_execution_route(UUID)` | 新函数：仅 WAITING 且未动过（无领料单/报工/供给钉/预留）允许改路线——与 ADR-078「未动过才可拆」同源 |
| `production_execution_segment_events_action_check` | 白名单追加 `ROUTE_CONFIRMED`（V470/V595 同法整条重建 CHECK） |

## 行为变化（与 Java 同批生效）

1. **路线门**：`start_route IS NULL` 时 `start`/`batch-start`/`start-continuous`/领料申请
   `draw-request/submit`/分批 `execution-batches/submit`/`recheck-material` 全部被服务端拒绝
   （「请先确认生产路线」）；新端点
   `POST /production/plans/{planId}/execution-segments/{segmentId}/confirm-route`
   （权限 `production_execution:view + start`，幂等/版本/事件账与 start 同款）。
2. **系统不替车间选路**：到货驱动的齐套自动提升在路线未确认/分批/未开工的持续生产段上被抑制；
   确认 `FULL_KIT` 的那一刻同事务补跑提升（等价旧的「到货即提升」，`promoteAfterRouteConfirmation`
   尽力而为：缺料静默留在 WAITING）。**下达时即齐套的段不受影响**——CompleteKitAllocator 在下达
   事务内直接按 `requestedStatus='READY'` 建段，不走 `tryPromote`。
3. **分批谱系落生即定路线**：`ProductionExecutionBatchService.createChild` 批次段=`FULL_KIT`（每一批
   就是一次小齐套），剩余段继承 `BATCH`。
4. **到货进展通知**：IQC 确认入库（含先入库后质检自动转正）与非线边仓产成品入库这两类
   「真实写进库存」的事件，按「仓×货品×颜色」命中仍在 WAITING 的车间工单（单仓限 30 段），
   经 `business_outbox`（事件 `PRODUCTION_WORKSHOP_MATERIAL_ARRIVAL`，去重键含触发单据）投递
   「本次入库 + 仍缺清单 + 按路线的下一步」聚合卡；与既有车间行动卡同聚合
   `(PRODUCTION_EXECUTION_SEGMENT, segmentId)`，一张工单同时最多一张活跃卡。
   收货审核、红冲、IQC 拒收不触发（可用量没有真实增加）。

## 不变的东西

- V249 守恒链五道闸、V595 持续生产的补投/折算上限、V561 分批谱系与数量守恒、
  ADR-077 领料申请流程——全部一字不动；
- 事件账既有动作与行、全部既有段的状态与数量；
- 不新增表、不新增过账类型、不新增权限码。

## 清库策略

不新增业务表，`business_data_reset()` 的 (版本, 条数) 白名单已登记 `(599, 556)`；
清空口径无新增 CLEAR/PRESERVE 表。

## 升级路径

对 V594 之后的库按序执行 V595→V596→V597→V598→V599。V599 只加两列、回填、建两个只读判定函数、
重建一个 CHECK 约束——无锁表风险（`production_execution_segments` 行数在业务清空后的库上极小）。
