# 权限关系与统一工作台检查

本轮按 `frontend-design` 设计，沿用 Uten 组件、主题与服务端权限策略。工作基线为本地主树当前源码的隔离副本，发布、生产数据库迁移和业务验收分别记录。

## 设计与关系合同

- 色彩：白色 `#FFFFFF`、浅灰 `#F8FAFC`、正文 `#0F172A`、次级文字 `#475569`、品牌青绿 `#0F766E`、分隔线 `#E2E8F0`；运行时统一取主题 token，支持深色模式。
- 字体：沿用系统既有中文字体和正文尺度；模块 14px 半粗体、条目及资源列表 13–14px，说明优先提示气泡，避免每项重复堆叠说明。
- 布局：左侧紧凑员工/部门/模板目录，右侧统一权限树。模块与子类默认收起，以公共虚线连接呈现层级；批量操作常驻分组菜单，避免大色块卡片占满屏幕。
- 多选：明确显示已选对象数，支持已加载对象全选、清空及跨搜索保留；批量模板先预览目标与权限变化，再确认应用。敏感权限逐项确认。
- 有效权限由服务端统一计算：基础包、部门（含祖先）、模板、手工授权、负责人授权合并后，个人取消优先；权限依赖和敏感授权边界保持服务端权威。
- 员工和部门模板采用独立来源。模板修改影响关联对象，移除模板项不误删手工来源；部门绑定作用于所属及继承该部门的员工。个人取消继续生效。
- 旧模板快照来源无法可靠拆分，保留既有配置并标明旧关联；重新应用后建立独立来源。不猜测或重置服务器已有授权。
- 密码二次验证改为当前账号、当前会话内连续活动复用，空闲 5 分钟重新验证；只保存内存凭证，不缓存密码，后台轮询不能延长验证。

设计复核：以现有货品分类树为参照，删除权限模块大面积品牌底色与重复说明，采用紧凑目录行。保留来源、敏感标识、未生效依赖和草稿状态，避免为缩小高度隐藏关键授权信息。

## 检查与迁移清单

| 统一职责 | 公共入口与已迁移调用方 | 验证与必要差异 |
|---|---|---|
| 有效权限来源 | `PermissionResolver`、V960 两个来源视图；单人/批量、部门祖先、通知候选、访客接待、运维与车间高权 SQL | 基础包/主兼职部门/模板/手工/委派合并后个人取消优先；本人及超管不能作为普通目标；敏感策略继续后端裁决 |
| 批量权限与模板关系 | `PermissionTemplateAssignmentService`；单员工旧接口委托同核；员工/部门多选、模板关联/解绑与普通增量 | 1..500 个对象、原子提交、配置与模板版本指纹、敏感逐项确认；解绑校验所见五字段，拒绝旧窗口拆新关联 |
| 权限目录与分组 | `PermissionCatalogBrowser`、`PermCatalogGroupSection`、`PermissionTitleBlock`；员工、部门、基础包、模板及批量弹窗 | 全部/模块/子类菜单统一；模板与基础包仅按策略带普通项，基础包钉死项保留；页面抽屉复用分组与行标题，仍保留负责人可委派上限及锁定项 |
| 模板依赖草稿 | `PermissionTemplateSelectionPlan.select/selectMany`；逐项及模块批量同入口 | 服务端依赖元数据驱动普通查看闭包，敏感/未知依赖不自动带入；移除查看权限时从草稿级联移除相关动作；3001 项目录只枚举一次 |
| 关联与缓存刷新 | `refreshPermissionConfiguration`；模板保存/删除、导入/复制、基础包及部门保存、批量授权/应用/解绑 | 模板元数据刷新关联名称；基础包/父部门变化同步失效已打开部门的继承与依赖状态；个人草稿保留其所属边界 |
| 密码会话 | `StepUpCoordinator`、`StepUpInterceptor`、`StepUpPromptHost`、`StepUpService`、`AuthSessionService` | 同账号/会话/服务器复用，真实活动 30 秒节流，空闲 300 秒失效；改密原密码、模拟模式及 MFA 保留各自独立边界 |
| 目录层级 | `UtenHierarchyTreeView`；分类/部门 wrapper、CategoryPageShell、模具/仓库/收付款类别、各编辑和快捷选择器、我的部门、权限部门目录、生产车间树 | 默认展开深度 0；刷新保留手动状态，搜索临时展开匹配路径；公共虚线绘制仍为 `UtenTreeBranchGuide` |
| 业务数据树 | `UtenDefaultCollapsedTreeState`；货品成本、物料分析产品/分支、部门架构图 | 默认收起、新分支收起、换单据重置；展开/收起保持列宽、原值和 Ctrl 同级交互；不改变计算、SQL、分页与草稿 |
| 页面入口 | `page_permission_scope.dart` 与实际路由枚举契约；客户/供应商详情、主档历史及本地类型切换、资产新增、仓库批量办理、生产申请/补录等 | 267 条注册路由、347 个业务路径样例、45 条明确豁免；盘点审核反向登记补齐；全页/弹层复用入口分别处理 |

已删除旧模板差量重放、旧 transfer 模板计划/应用路径、旧单员工模板私有应用弹窗，统一到独立来源与公共批量审阅核。保留旧 HTTP 单员工接口作兼容委托，不再维护第二套计算。清理 V958 已退役且无调用的前端下载权限常量。为清除原脏基线的 `archive -> admin` 依赖，读取运维的同一授权表达式移至 `security.ServerOperationsReadAccess`，旧入口只委托，不放宽策略。

保留的展示差异：生产日报必填用料编辑组保留可见；搜索触发的相似员工建议按搜索展开；打印用 `GoodsBomPreview` 为完整清单，无展开控件。部门没有个人取消体系，外部来源须调整模板/祖先/基础包，或在员工层设置个人取消。模板/部门实际来源变化会依既有 epoch 机制使旧负责人委派失效，名称备注及无变化重复应用不推进授权版本。

V957 旧模板应用没有可证明的手工/模板来源分界，保留原配置并显式标记旧快照；新应用以 V960 独立来源联动。模板编辑不猜测或批量清除公司服务器既有授权。
