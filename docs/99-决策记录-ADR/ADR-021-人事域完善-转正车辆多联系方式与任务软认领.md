# ADR-021 人事域完善：转正口径 / 车辆与多联系方式 / 更换手机号 / HR 工作台与任务软认领

> 日期：2026-08-05 · 状态：已采纳（源码落地中）
> 关联：[ADR-011](ADR-011-工作台部门分区与动态权限配置.md)（权限模型）、[ADR-020](ADR-020-入职工号岗位与管理中心用人语义.md)、
> [53-人事正式名录迁移](../数据迁移/53-人事正式名录迁移.md)、[55-转正日期回填与员工车辆联系方式](../数据迁移/55-转正日期回填与员工车辆联系方式.md)

## 背景

正式名录 141 人导入后，人事日常使用暴露出一组相互关联的问题：

1. 名录只有 1 人登记了转正日期，HR 任务中心刷出「上百人未登记转正」的噪音；
2. 任务中心把转正/生日/周年/新入职四类提醒平铺在一页，内容过多、没有快捷操作，
   多人协同时还会出现「两个人同时办理同一名员工的转正」的重复操作风险；
3. 员工档案缺车辆信息——厂区/宿舍场景「谁的车挡道/有问题」找不到人；
4. 登录账号 = 手机号，但改手机号不同步登录账号，改完员工就登不上；
5. 员工详情页操作全部埋在 `⋯` 菜单里、信息无分组导航，「半天找不到想看的」；
6. 部门架构图只是缩进列表，高层领导悬空在总经办、不进其分管班组；
7. 花名册/架构图打印（即文档下载）此前只看 `employee:view`，没有独立导出权限。

## 决策

### 一、转正日期口径（老数据适配 + 新数据约束）

- **老数据**：`employees.confirmed_at IS NULL` 且状态非 `probation` 的存量员工，
  迁移回填 `confirmed_at = hire_date`（默认入职日期，视为已转正）。试用期员工不回填，
  继续走转正提醒与办理。名录迁移脚本同步改为
  `COALESCE(批注转正日期, hire_date)`，**以后重新迁移自带该口径**。
- **新数据**：入职页「用工状态 = 正式」时**转正日期必填**（服务端 fail closed 校验，
  不得晚于今天、不得早于入职日期）；「试用」不填转正日期，由合同试用期月数派生预计转正日，
  到期在 HR 工作台办理。
- **转正办理**：`POST /api/org/employees/{id}/confirm` 支持可选 `confirmedDate`（默认今天），
  并写入 `employment_history` 新事件类型 `confirm`（V210 扩展 CHECK），任职时间线可见。
- 已在册但缺转正日期的老员工，HR 可在编辑页/详情页「补登转正日期」
  （`employee:edit`，走既有 `UpdateEmployeeRequest.confirmedAt`）。

### 二、车辆与多联系方式

- 新表 `employee_vehicles`（1:N）：车牌号（规范化大写去空格，7–8 位含新能源）、
  车辆类型/品牌型号/颜色/备注，全部**非必填**。车牌明文存储并建索引——
  「按车牌找人」是门岗/行政高频刚需，且车牌本身属于半公开信息；查阅走 `employee:view`。
- 新表 `employee_phones`（1:N）：备用手机号，pgcrypto 加密 + HMAC（与主手机同口径），
  标签（本人/家属/备用…）。展示按 `employee:pii:view` 明文、否则掩码。
- 主手机号仍唯一存于 `employee_sensitive`（登录账号绑定），备用号不参与登录。
- 员工自助：「我的」页可直接维护本人车辆与备用手机号（直改字段，不需审核，
  与现住址/邮箱同级）；HR 侧在员工详情编辑（`employee:edit` / 备用号写需 `employee:pii:edit`）。
- **车牌搜索**：员工列表搜索框同时匹配工号/姓名/车牌；命中的车牌在列表项上以
  `matchedPlates` 返回并显示，实现「谁的车有问题 → 秒查到人」。

### 三、更换手机号 ⇒ 同步登录账号

- 新增 `POST /api/org/employees/{id}/change-phone`（`employee:pii:edit`）：
  校验 11 位中国大陆手机号、不与在职员工主手机号重复、不与其他账号登录名重复；
  单事务内重写加密手机号 + HMAC、把 `users.login_account` 改为新号、
  吊销该账号全部 refresh token（强制重新登录），审计留痕。
- HR 编辑页直接改手机号、员工自助改手机号经 HR 审批合并，**同一条同步链路**
  （`EmployeeLoginAccountSync` 组件，三个入口共用），杜绝「改了手机登不上」。

### 四、HR 任务中心 ⇒ HR 工作台 + 任务软认领

- 页面重构为工作台：顶部统计卡（今日待办）+ 功能入口（转正办理 / 生日关怀 /
  入职周年 / 新近入职）+「我处理中的事项」。每个入口是独立子页面（列表 + 行内快捷操作：
  办理转正、补登转正、查看档案），不再一页平铺所有内容。
- **任务软认领（Soft Claim）**：调研业界工单/审批系统后的结论——
  - Jira / 钉钉审批 / 飞书工单：**任务始终可见**，用「处理人」标记归属，不隐藏；
    客服系统（Zendesk）甚至只做「XX 正在查看」的碰撞提示。隐藏任务会导致工作不可见、
    被重复创建、卡住无人发现，弊大于利。
  - 因此本系统**不隐藏**他人任务：被认领的行显示「张三 处理中」徽标，
    他人的快捷操作禁用并提示原因；认领者本人可继续/释放；
    持 `employee:edit` 者可**接管**（防止认领人请假卡死）。
  - 认领有 **24 小时租约**，过期自动失效（读取时惰性判定，无需定时任务）；
    认领/释放/接管幂等且写审计。认领状态存 `hr_task_claims`，任务本体仍动态计算、不落库。

### 五、导出权限与授权入口

- 新权限点 `employee:export`（员工资料打印/导出），预配行政与人力资源部；
  花名册打印、架构图打印按钮按该点显隐（无权限 hide，不 disable）。
- 全局“按员工 / 按部门”授权区仍仅超级管理员且持 `authorization:manage` 可见可用；人事若持
  `account:support` 只能进入共享路由的账号支持区，不能读取或写入授权目录。
- 2026-08-22 后，合法组织负责人可从已登记业务页右上角进入本页权限工作台，但只管理组织范围内
  员工的当前页面权限，写独立 `manager_permission_delegations`；完整边界由
  [ADR-045](ADR-045-页面内权限委派与授权来源隔离.md) 取代本文早期“仅超管入口”的笼统表述。

### 六、员工详情页与「我的」页重构（大厂 People 范式）

- 详情页：头部身份卡 + **常用操作外显为按钮**（编辑/调岗/转正/离职，次要在 ⋯），
  内容改 **Tab 分组**（概览 / 组织与合同 / 联系与车辆 / 薪酬(按权限) / 任职记录），
  到期预警与待审区块保留在头部下方；全断点 `UtenContentContainer.narrow`。
- 「我的」页：保持身份组/档案组响应式骨架；2026-08-27 起以对象限定的
  `GET /api/profile/me` 为档案权威，补齐身份、组织用工、联系住址、紧急联系人、合同和任职记录，
  并标注“可直接修改 / 需 HR 审核 / 请联系人事修改”。左侧快捷卡为我的部门、修改申请、车辆与号码、
  我的文件；工资、报销、通知和建议从工作台/主导航进入，不再登记为“我的”页快捷网格。

### 七、部门架构图

- 节点卡片化：部门名 + 人数 + 负责人 chip 一体；**负责人即使档案挂在总经办，
  也在其负责的班组节点内以「负责人」虚拟首行呈现**（标注挂职部门），成员行带领导徽章；
  层级用引导线 + 色彩区分；PDF 打印同口径美化，打印入口按 `employee:export` 门控。

## 影响面

- 迁移：V210（confirmed_at 回填 + history CHECK + hr_task_claims + employee:export 种子）、
  V211（employee_vehicles / employee_phones + 审计触发器）。
- 名录迁移脚本 `migrate_hr_roster.sql` 口径更新（重跑幂等）。
- 权限目录新增 `employee:export`；其余复用现有点，未新增角色语义。
- 审计：新表挂 `fn_audit` 触发器；更换手机号/认领/接管为显式审计事件。
- 兼容：`/confirm` 无 body 调用保持原行为；`UpdateEmployeeRequest` 新增字段均可选。
