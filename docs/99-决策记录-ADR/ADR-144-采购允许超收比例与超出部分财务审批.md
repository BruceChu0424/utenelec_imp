# ADR-144 采购允许超收比例，超出部分走财务审批

- 日期：2026-10-04
- 状态：已接受(2026-10-04)
- 迁移：V799(本分支临时号；合并进 main 时按 main 头 +1 重编号)
- 修订：ADR-019 §三.1 财务已批准可收容量公式(采购加允许超收量)。
- 相关：ADR-098(委外允许损耗 + 货品记忆，本 ADR 的同构模板)、ADR-019(超量到货财务闭环)、ADR-027(财务审核组)、ADR-143。

## 一、用户口径(2026-10-04)

> 委外有个损耗比，比如 10%，回来入库数量少于 10% 是可以入库的。那么采购对应的下单那里，可以超出多少比例：超出的部分在这个比例内入库是没问题的；大于这个比例就需要通知财务，财务也是有对应权限的。

## 二、决策

### 2.1 事实与记忆(照 ADR-098 / V636 同构)

| 事实 | 说明 |
|---|---|
| `purchase_order_items.allowed_over_receipt_pct NUMERIC(5,2)` | 采购订货明细「允许超收%」，0 ≤ p ≤ 100；空 = 0(与今天的严格口径一致)。保存时冻结在明细上；财务审批后不可改(采购专用冻结触发器，照 V760 `fn_guard_procurement_total_input` 写法)。 |
| `goods.purchase_allowed_over_receipt_pct NUMERIC(5,2)` | 货品记忆值。保存采购订货单时，按每个货品最后一行非空值回写(空行不清空记忆)；只按货品记，不按供应商分(与委外损耗一致)。 |
| `/api/purchase/orders/last-terms` | 预填带 `allowedOverReceiptPct` 与来源 `GOODS_MASTER`(比例不受价格遮蔽)；前端黄色「自动带出」标记；已带齐其它商务条件的行也要补预填比例。 |
| `procurement_arrival_exceptions` 快照列 | `order_qty_snapshot`、`allowed_over_receipt_pct_snapshot`、`tolerance_qty_snapshot`、`prior_net_received_qty_snapshot`(采购才写；首次登记与重新检出都写)。 |

货品主档在「采购默认」区域(默认供应商 / 价格旁边)查看和修改采购允许超收%，接口 `PUT /api/master/goods/{id}/purchase-receipt-policy`，权限 `goods:edit`，不需要成本查看权限。

### 2.2 数量口径

允许超收量 `T(q, p) = ROUND(q × COALESCE(p,0) / 100, 4)`(订货单位，四舍五入)。各层只在既有容量项上加 `T(当前订货量, p)`，不改写各层既有的退货 / 质检口径：

```
最多可收(累计) = 订货量 + T + 已退货量 + 已过账的财务批准超量 + 质检退回补货额度
```

- **按累计净收货计**(与分几批无关，同 SAP 允许超交)：累计收货在最多可收以内，照常入库、立应付，不打扰财务。
- **预计到货仍在累计达到订货量时关闭**(不再催仓库)。关闭后供应商再送来容差以内的货，由采购员用手工采购收货单登记，审核走同一闸门(容差内直接入库立应付，超出走财务异常)。
- **超过最多可收**：整张收货单照 ADR-019 隔离待财务(不入库、不立应付)，财务以 `finance_order_approval:approve / :reject` 判定：全部接收 / 指定接收 / 拒收超量(收窄到最多可收量入库，超出部分生成退供应商任务)。
- **到货容量拆三份**：欠交 `owed`(原口径，不含 T)、容差 `tolerance`(T 的剩余)、质检补回 `replacement`。来源歧义只看 `owed > 0 且 replacement > 0`；自动来源下 owed = 0 且 replacement > 0 按补回；按 补回 → 欠交 → 容差 的顺序消耗。`ProcurementIqcReplacementAllocationService` 同口径(歧义判定用 owed，超量校验用 owed + tolerance)。
- **应付**：T 不并入订单分摊基数。授权数量 = 订货量 + 已过账超量 + 本单财务批准超量 + `T_used`，`T_used = clamp(本次后累计有效收货 − (订货量 + 已过账超量 + 本单批准超量), 0, T)`，超过订货量的容差部分按 `MoneyPolicy.orderOverageAmount` 计价。收满订货量时应付 = 订单金额(含扩展列)分毫不差。`ProcurementReceiptAmountPreview` 同口径。
- **批准后改量下限**：最小的 4 位小数订货量 N，使 `N + T(N, p) ≥ 净保留收货量 − 已过账超量`(先算 CEIL4(…/(1+p/100))，正向核验不足再加 0.0001)。仅采购；委外不变。
- **总金额输入的明细**：T 不能整除导致金额无法精确拆分时，保存订单即拒绝该比例并提示。

同一口径在以下每一层用同一个表达式：Java 到货容量(`ProcurementArrivalControlService.arrivalCapacity`，仅 PURCHASE)；数据库收货守卫 `fn_guard_procurement_received_with_arrival_allowance` 与退货红冲守卫 `fn_guard_return_allowance`(两者为采购 / 委外 / 销售共享，只能在采购分支里用 `to_jsonb(NEW)->>'allowed_over_receipt_pct'` 读比例，不能直接写 `NEW.allowed_over_receipt_pct`)；应付授权与预览；改量下限；质检补回分配。允许超收量永远不写进 `arrival_overage_posted_qty` 或预计到货 `ordered_qty`。

### 2.3 财务与仓库可见

- 进入审批快照哈希(`ProcurementApprovalSnapshot`，仅非空时出现，旧单哈希不变)与展示快照(按 V760 现时定义锚点补丁 `fn_procurement_approval_display_snapshot`)。
- 财务采购订货审核页、采购订货单详情页加「允许超收%」列；改单复审对比显示差异(键 `allowedOverReceiptPct`)。
- 到货异常通知与任务卡：「订 Q，允许超收 p%(最多 Q+T)，此前已收 R，本次实到 D，累计 R+D，需审批超量 X」。
- 仓库到货登记页(单张 / 批量)对采购明细显示「最多可收(含允许超收 p%)」，提示改为「超过最多可收的部分才转财务」；隔离提示写明允许超收比例。

### 2.4 权限

不新增权限点：下单编辑沿用 `purchase_order:edit`；财务判定沿用 `finance_order_approval:view/approve/reject` 与财务审核组(ADR-027)；货品记忆沿用 `goods:edit`。

## 三、不变量

1. p 为空等同 0；0 ≤ p ≤ 100。
2. 采购已收量 ≤ 订货量 + T(订货量, p) + 已退货量 + 已过账超量 + 质检退回补货额度(数据库守卫兜底)。
3. 超过最多可收的部分不会不经财务就入库或立应付。
4. 订单在财务批准后不能改 p。
5. 收满订货量时应付 = 订单金额。

## 四、明确不做

- 委外订货不加超收比例(委外回厂受我方供料约束，超出部分本来就是委外商自带料走财务，ADR-101 §2.8 / ADR-143 §二.12)。
- 不按供应商记忆。
- 不在比例内给财务发通知；不把超过最多可收的收货单自动拆成两张(整单隔离，财务判定后收窄入库)。

## 五、验证

- 真库 E2E：订 100、p=5%：一次到 103 直接入库立应付；分两批 60 + 45 第二批入库；到 110 整单隔离，财务拒收超量 → 收窄 105 入库并生成退 5 任务，财务全部接收 → 110 入库；收满 100 后手工收货 3 直接入库；扩展列(模具费)明细收满 100 应付 = 订单金额；收 100、质检退 10、自动来源登记 10 按补回入库；红冲退货守卫放行比例内收货；改量下限按比例算；已批准订单改比例被拒；委外回厂不受影响。
- 记忆：保存订单回写货品、`last-terms` 预填带来源、空行不清空。
- Flutter：采购下单表格「允许超收%」列与黄标、详情页列、财务审核页列、改单对比、到货登记「最多可收」、到货异常卡片文案、货品采购默认区编辑。
