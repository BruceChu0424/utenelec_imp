## 已确认的根因

本地业务库 V853 的 CD20261012000001，最新第二轮财务审批已退回，仍保留两条原订货明细。
同一份来源 CS20261012000001 的 2.5、CS20261012000004 的 5000，又全部回到待分解。
原算法仅扣 PENDING 草稿订单来源承诺，忽略 REJECTED 原单仍需修订这个事实。
这不是单纯隐藏重复行的问题，而是新下单与原单重提同时具有同一份需求的执行入口。

V854 与相关 Java 查询改为读取每单最新财审轮次；未删除 status=0 且最新 PENDING/REJECTED
均保留有效来源份额。原单修订减量只释放差额；重提不再重占；真正撤回、取消、删除沿既有规则释放。
已批准收费/赠品计数、库存、超采许可、审批权限和审计留痕保持既有权威。

批准后改量复核也必须展示最新审核事实：原单仍已生效、承接量仍有效，
工作台显示“改量待财务复核 / 改量财务退回”，而不是继续误显示财务已通过。
实物 `is_closed=true` 不等于财务复核办结，最新在审/退回仍进入进行中与待修订红数；
实物仍已结案时，复核批准后才回 COMPLETED 历史；未实物结案则恢复对应执行阶段。
不能为修显示重开实物结案或再次释放来源。
已取消采购单和已反审委外单不再拿历史驳回提示用户继续修改重提。

## 页面设计与修复

| 确认问题 | 最终行为 |
| --- | --- |
| 采购/委外进行中重复财务退回子分类自动收窄 | 删除退回子分类；进入进行中先看完整列表，状态列保留当前退回及可清除筛选；红数仍提醒原单修订 |
| 独立异常选后无法回全量 | 逾期、短交等保留真实业务入口，增加全部，关闭异常行按红数自动选中 |
| 委外订货列表进行中又放一排财审状态 | 移至可清除状态列；执行中与改量复核互斥，实物结案不屏蔽未办财审；清除恢复完整进行中 |
| 仓库 DRAW 在任务中心和直达列表都锁住出库进度 | 删除重复进度条，列头筛选下推 issueStatus，清除恢复所选单据状态的全部记录 |
| 品质来源下二级状态偷偷选退回、无全量入口 | 来源保留；默认全部状态，二级手动选择，全部随时恢复 |
| 追加用料、超产比例只有状态切片 | 补服务端已支持的 ALL；申请/审批状态机不变 |
| 销售状态表头清除无效 | 订货保留业务大类及币种等条件，真实清除状态；其它类型显式全部，不悄悄转历史；草稿固定状态不伪装可清除列 |
| 建议筛空后筛选入口也消失 | 保留空表表头及当前筛选，可直接清除；文案准确表示当前筛选无结果 |
| 研发用当前分页裁剪伪装全量筛选 | 使用已有服务端类别、关键词与阶段筛选后分页，移除当页桶/当页裁剪入口 |
| 盘点同仓、结算方式、稀缺货品旧响应覆盖新筛选 | 请求代数与业务身份共同拦截迟到成功/失败，不污染新结果和当前加载态 |
| 稀缺预留数组按 Map 读取 | 使用数组接口，保留真实来源 ID；失败可重试，不误显示暂无预留 |
| HR/接待人访客页漏掉已签到、已取消 | 补纯浏览终态入口，保留角色范围和历史，终态不提供审批/确认动作 |

来源类型、实物作业、物理拒收、审批历史轮次都有各自含义，保留这些维度。
财务审核历史按 case/attempt 留各轮记录；业务工作台按最新轮次显示当前待办，二者不能混为一谈。
销售/生产/品质等部分数量在两个阶段出现时，核对的是余量与已承接量，而不是按名称粗暴去重。
