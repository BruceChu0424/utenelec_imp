# 公共表格与完整读取：实施及验证

本轮按用户要求实施性能优化，保留全部真实结果连续展示，不推送、不部署、不发布正式安装包。用户明确优先网页端，其次Windows；Android由用户自行测试，本轮没有开始Android测试，也不将共享Flutter代码视为Android已验收。前端使用 `frontend-design`，沿用 Uten 主题和现有交互。研究范围及取舍见[大型 ERP 实践对照](2026-11-10-公共表格完整读取-大型ERP实践对照.md)。

## 1. 实际改动

| 公共入口 | 已完成的处理 | 保留的边界 |
|---|---|---|
| `loadCompletePagedResult` / `loadCompleteCursorSnapshot` | 每批仅封存新增行；持久追加树共享旧块；旧快照不受后续批次修改，也不持有未来 builder | 原始总数、顺序、来源、权限、版本、终帧/EOF、取消与错误校验继续执行；重叠替换保守回退 |
| `PagedResult` | 复用已证明不可变的数据块，仅建立独立响应包装；保留协变子类和空响应独立身份 | 不将可变 List 或深度可变业务对象擅自当作稳定事实 |
| `MasterDataTableView` | 新段身份校验、增量分面、平坦行计划、窗口槽复用；无选择的逐批阶段不再全表算选择资格 | 有选择/完整结果/真正点击时仍按原合同实时核对资格；编辑、树投影及未知可变来源保守处理 |
| `UtenAncestorRowWindow` | 新段及移动页尾增量索引；内部 Fenwick 高度索引，行高更新和定位为对数成本 | 估计/字体变化、重复对象及无不可变证明时回退；锚点、焦点、文本选区与迟到测量退休保留 |
| 列宽、列索引、展示计算 | 隐藏列不做无必要量宽；列索引复用；明确展示版本的只读数据不重复排序/筛选 | 保留全内容适配、手调宽度、首次精确排序和已有分面语义，不按样本伪造最大宽度 |
| 生命周期 | 同会话安全追加不清文字选区；撤权/编辑/模式变化释放旧数据缓存 | 保留仍显示的错误/空态 notice 身份，错误详情不会因无关重建立即关闭 |

直接接入的十个主列表：货品、客户、供应商、模具分类主档，即时库存，以及颜色、单位、币种、结算方式、账户。币种的基准币仍不可勾选；账户的动态权限/名称展示不启用不可靠的展示缓存。其他调用方仍共享读取器减负和公共重复实现清理，但不假称其复杂树/动态编辑投影全部已增量化。

完整 235 处调用清单、保留差异和清理说明见[表格调用清单与验证](2026-11-10-公共表格增量整理-调用清单与验证.md)。首次同步排序、二维列虚拟化、独立后端业务算法不是本轮已完成项目。

## 2. 结构性验证

- 35k / 100k 首次逐批读取：表格 collect、窗口数据槽和本地分面累计各处理 N 行；完整后分面只排序一次，不再为每个前缀重新生成整表行计划或文本行键。
- 行窗口 35k / 100k 的索引及位置处理分别为 35,070 / 100,200，额外部分是每批移动的 footer/summary，未重复扫描全部旧行。
- 新增数据块封存总量为 N；此外仍有入口批次防御冻结等必要复制，不能称为全链零复制。
- 100k 读取在已发布 99k 时取消，故意放行最后一批晚响应，验证不再发布旧结果；新查询随后恢复全部 100k。
- 24 个连续替换查询仅最终 owner 返回完整 100k。金额原文、共享 Dart/C# 流协议、总数、身份与版本契约单独回归。
- 百万行整数读取及万块元数据增长测试已通过。后者只验证数据结构增长，不等于千万行真实 ERP 页面已经支持。

## 3. 浏览器实际结果及正确解释

验证使用本地 Release 合成 fixture，未连接公司数据库或业务 API。正式计时对照使用同一内置 Chromium 标签页、1280×800、DPR=1、可见状态、100k 行、30 列与每批名义 1ms 延迟。开发机为 Core Ultra 9 185H、约64GiB内存，不能代表4GiB/8GiB员工电脑。

这是单轮合成对照，读取阶段观察约下降67.3%，不是全平台提速承诺、P95统计或公司容量认证。初轮自由视口的80.1s/50.8s等结果仅用于发现第二层重复索引，不能混入上述固定条件比较。原始回执及源码/产物摘要见[整合前原始验收记录](evidence/table-read-performance-20261110/acceptance-before-main-integration.json)。

计时口径必须保持：`firstBatchAcceptedMs` 不是首帧绘制时间；`completeReadMs` 到读取器返回为止；`layoutWaitReturnMs` 包含夹具逐行校验和有帧数上限的布局等待，不能当成完整布局稳定或实际业务可操作时间。自动量宽仍可能继续；fixture 的批次调用数不是真实 HTTP 次数。

项目“完整交互读取一秒以内”目标没有放宽，**本轮未证明达标**。另两次冷启动样本：1k读取1,782ms、10k读取1,066ms；不隐去较慢样本，不用首批达标替代完整交互。低配真机、真实网络/数据库、多人并发及千万行页面仍待独立验收。

浏览器功能检查全部通过：

- 24次快速查询，23个旧读取及23个故意晚回均退休，最后完整35k。
- 中途断流撤下临时数据，再读恢复35k。
- 同查询失败重读保留已接受完整结果和选择，成功重读继续保留选择；不会发布临时前缀替换已接受结果。
- 12次表格开关/取消后恢复35k。
- 手动在100k表格键入中文、勾选首行、拖动至第99,999索引行并返回，输入和勾选保留；再连续输入查询并立即取消，临时结果撤下，随后恢复100k。此输入是旁路输入框，不冒充持久业务草稿或真实OS输入法候选窗验收。

## 5. 并行工作与失败证据

主线的空/加载/错误态横向滚动条、notice末行定位、无权限删除文案、其它业务修复均保留。Dart两处重叠自动合并后又经独立审查与上述319项交互回归，未用一边整文件覆盖另一边。

WPF台账三方均为373同ID，保护字段完全一致。notes/evidence按双方增量并集保留，history保留497条已有/双方历史及1条合并审计；140公共/流程+230当前页+3历史页=373，仍10完成、363未完成。owning工具原来会丢掉catalog外FLOW019的缺陷已修，有17项回归；该治理修复不算新增业务迁移或性能改善。见[语义合并证明](../../clients/windows_legacy/progress/evidence/table-read-main-merge-20261110.json)。

保留的失败及处理包括：小数几何舍入；常量空列表的泛型协变；错误详情notice被提前释放；fake clock导致native JSON解析I/O饥饿；Windows测试输入未重新聚焦；临时原生测试入口被SDK误识别为普通widget test；真实字体/窗口尺寸不符合原pointer夹具的overflow前提。具体原始输出见证据目录及各专项回执，不删除原断言来换通过。

对每行 `await checkpoint` 也做了独立实验：Web100k仅约39ms差异，收益不足以解释大表瓶颈，故本轮没有改动其微任务退休语义或4ms/256预算。保留[实验取舍](evidence/table-read-performance-20261110/checkpoint-microbenchmark-decision.md)，避免为小收益增添不必要机制。

本轮未推送、部署、激活公司服务、制作/上传正式安装与更新包。后续发布仍需要按当次授权完成主线整合、适用CI与正式交付验证。
