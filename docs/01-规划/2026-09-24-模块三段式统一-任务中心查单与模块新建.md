> 销售报表就是汇总」「销售管理里面 点进去 都应该是新建的页面」「新建单据的入口 进去就默认新建
> 不要显示历史」「仓库管理 任务中心一堆 要不要汇总」「每个模块都应该有新建」

## 一、每个业务模块固定三段式

模块 hub（销售 / 采购 / 委外 / 仓库 / 钱流 / 生产，从工作台模块卡进入）内部固定三个分区，
顺序也固定：

| 分区 | 职责 | 内容 | 徽章 |
| --- | --- | --- | --- |
| ① 任务中心 | **查看**该模块所有单据与任务（自己建的 + 别人流转过来的），办理待办 | 一模块**一张卡、一个页面**；页内大类=任务/单据类型，小类=状态/阶段，历史段时间门控 | 卡面红/黄徽章照准则 14 |
| ② 新建单据 | **创建**该模块的各种单据 | 每张卡直达对应 `/xxx/new` 编辑页；只对持新建权限者显示；进去默认新建，不显示历史 | **一律不挂**（用户 2026-09-24 口径：新建入口不需要通知数量徽章） |
| ③ 报表 | **汇总** | 明细/汇总/专项报表入口 | 一律不挂（准则 14 §二） |

模块 hub 顶栏的「待办 N / 进行中 N」两枚药丸保留——它们指向任务中心的待办，是「该去
任务中心了」的信号，不属于新建卡。

### 与旧模式的差异

- 旧：hub 单据卡 = 列表页入口（能新建的人落到新建页 = `skipListOnCreate` 双落点），
  卡上挂草稿红徽章。
- 新：hub 单据卡 = **新建入口**（creator-only，直达 `/new`）；列表浏览全部收进任务中心；
  新建卡不挂数。草稿信号仍在三处可见：新建页顶栏「草稿(N)」红徽章、任务中心「草稿」
  分段红徽章、模块顶栏/工作台模块卡的待办累计（服务端红链照旧登记，不改）。
- 只读型单据（如「计划下达的采购申请」「历史其它出货单」）没有新建页，不放新建区；
  浏览入口收进任务中心分段。

## 二、任务中心的分类设计（回答「怎么分 / 要不要子分类 / 要不要类型列」）

**两级分段 + 时间门控历史**，沿用销售订单进度查询与仓库任务中心已验证的范式：

1. **大类行**（第一行）= 任务/单据类型，如仓库的「出库 / 入库 / 生产领料 / 品质检查结果」、
   销售的「订货进度 / 出货单 / 退货单 / 报价单 …」。每段挂徽章：红=本类等本人动手数、
   黄=本类还在别人手上跑的数（两枚都可能出现，黄左红右）；浏览型大类不挂。
2. **小类行**（第二行，选中大类后出现）= 状态/阶段细分，默认不选、未选不发请求；
   末尾「历史记录/历史单据」段时间门控（时间段/全部）。
3. **表头**：保留「状态」列（可筛选）。**不设「任务类型」列**——类型已由大类行承担，
   同一张表内不混装多种单据；确需跨类型混装的新页面才加类型列+表头筛选（目前无此场景）。

进页面不预选大类（不预加载）；搜索框在页级，关键字传给当前分段。

## 三、分模块落地

### 仓库（原「任务中心一堆」的汇总）

- 新页 `/warehouse/tasks`（仓库任务中心）合并原四张卡：
  大类 = 出库 / 入库 / 生产领料 / 品质检查结果 / 委外成品退货 / 委外损耗；
  每个大类的小类行 = 原任务中心页各自的分段（销售出库/委外出库/其它出库/产成品出库；
  采购入库/委外入库/产成品入库/其它入库；待领任务/领料单/生产退料；品质页的来源行+状态行）。
  旧三路由 `/warehouse/tasks/{outbound|inbound|draw}` 重定向到新页带 `?group=`，
  通知深链与 `?section=` 参数原样透传。
- hub 新建区六卡：新建其它出库 / 新建产成品出库 / 新建其它入库 / 新建产成品进仓 /
  新建调拨 / 新建盘点（`stock_doc:create` 门控）。
  **领料单 / 生产退料刻意不提供手工新建**：由生产链自动生成（齐套建 DRAW、报工/退料闭环），
  手工单没有计划包与执行段映射，出库链路会被台账守卫拒绝；临时性出入库用其它出入库。
- 委外成品退货单 / 委外损耗单两张历史只读卡从 hub 撤下，收进任务中心大类（路由保留）。

### 销售

- hub：任务中心卡 1 张（销售任务中心）+ 新建区 5 卡（报价/订货/出货/客户零星发货/退货，
  creator-only）+ 报表 + 稀缺仲裁。
- 新页 `/sales/tasks`（销售任务中心）：大类 = 订货进度（原订单进度查询整页能力，
  含财务驳回/可发货等两层分段）/ 出货单 / 客户零星发货 / 退货单 / 报价单 / 历史其它出货。
  非订货大类的红徽章 = 草稿 + 财务已退回（分段计数，不进注册表）；黄色只在订货进度
  （与注册表 `salesOrderInFlight` 同源，避免 §四之八的双计）。
  旧路由 `/sales/progress` 与 `/sales/:seg` 列表页全部保留（通知深链、草稿按钮、
  列表页自身的深链入口）。

### 采购 / 委外

- hub：任务中心卡（运营工作台）+ 待退回供应商卡保留；单据卡 creator-only 化（订货/
  收货/退货、委外七类直达 `/new`），去草稿徽章；「计划下达的申请」只读卡保留原样。
- 任务中心已按大类分段（申请待分解/进行中/异常），本轮不重构其内部，后续如需把
  单据列表也并入任务中心再单独立项。

### 生产

- hub：调度台/审批队列卡保留（含徽章）；「生产计划单」「生产日报表」两张卡
  creator-only 直达新建（计划单→物料分析，日报→`/production/daily-reports/new`），
  去草稿徽章。

### 钱流

- hub 已是「任务中心 + 单据卡直达 /new + 报表」的样板；本轮仅去掉五张单据卡的
  草稿徽章（新建卡不挂数口径）。

## 四、徽章口径（结合准则 14 的增量）

- 新建卡不挂数 = 新口径，准则 14 §草稿 的「hub 单据卡挂 UtenDraftBadge」一行作废，
  草稿红链的注册表入口**不变**（顶栏药丸/工作台卡照常累计）。
- 任务中心合并后：hub 一张卡的红/黄 = 原各卡徽章之和（同一批服务端入口，无新增登记）。
- 大类行红黄两枚、小类行每段有数、黄左红右、0/null 不渲染——照准则 14 §四之七。
- 新增浏览型大类（委外成品退货/委外损耗/历史其它出货）不挂数（准则 14 §二）。
