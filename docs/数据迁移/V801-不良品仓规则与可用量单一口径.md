# V801 不良品仓规则与可用量单一口径

- 迁移：`V801__defective_warehouse_business_rules.sql`(本分支临时号，合并时由编排者重排)。
- 决策：[ADR-146 不良品仓业务规则与可用量单一口径](../99-决策记录-ADR/ADR-146-不良品仓业务规则与可用量单一口径.md)。
- 前置：V800(仓库主档单主仓)。两步必须同批上线：仓库收敛成单主仓后 002/C0401 也挂到 001 下，只靠「同一主仓」隔离不良数量的地方会立刻漏，本迁移把隔离改成显式规则。
- 不加表；`stock_documents` 加 3 列(调拨类型、原因、专门通道提交键)；加 2 个权限点。不搬库存、不改历史流水；reset 分类不变(新列随 `stock_documents` 一起清)。

## 为什么要改

「不良品仓」只是 V81 按名称回填的标签，没有业务语义：其它入库能把良品直接入不良品仓，调拨能把不良品调回良品仓，销售可预留量、MRP、物料分析都把不良品仓的数量当可用量；入库自动学习还会把货品所属仓学成不良品仓。详见 ADR-146 §1。

## 迁移做了什么

1. 类别判定函数(服务层 `WarehouseUsePolicy` 同口径)：
   - `fn_warehouse_is_defective_leaf(id)`：新单可选不良品子仓 = 启用记账作业叶仓、祖先链全部启用、是不良品仓(仓库字典 `selectableDefective`)；
   - `fn_warehouse_counts_as_usable(id)`：计入可用量的仓 = 未删、记账、非不良品仓、非车间内料仓、作业叶仓。
2. 可用量单一口径：
   - 视图 `v_stock_usable`：按仓可用量，只含计入可用量的仓，每仓只扣指定本仓的预留；
   - `fn_stock_global_usable(goods, color, exclude_order_items uuid[])`：可用仓扣安全库存后的合计 - 全部生效预留(全局预留只扣一次，落在不计入可用量的仓上的预留不扣)，最小 0。
3. `stock_documents` 新列与约束：
   - `transfer_kind TEXT NOT NULL DEFAULT 'NORMAL'`(NORMAL / TO_DEFECTIVE / DEFECT_RELEASE，只有调拨单能是后两种)；
   - `defect_reason TEXT`(普通调拨必须为空；专门通道 1-500 字，审核后必填)；
   - `channel_request_key TEXT`(专门通道一次建单的客户端提交键，`(maker_id, channel_request_key)` 部分唯一索引，用于幂等回放)；
   - 守卫 `fn_guard_stock_document_transfer_kind`：已审核的调拨单不能再改调拨类型或原因。
4. 出入库类别矩阵 `fn_stock_movement_class_violation`(与 Java `WarehouseClassMovementRule` 同表) + 文案 `fn_stock_movement_class_message` / `fn_stock_movement_type_label`，`stock_movements` BEFORE INSERT 守卫 `fn_guard_stock_movement_warehouse_class`(23514，`app.legacy_import='on'` 的老库导入会话豁免)。
5. 预留：新守卫 `fn_guard_stock_reservation_warehouse_class`(INSERT + UPDATE OF warehouse_id/qty/released_qty/status/is_deleted)拒绝任何预留方在不良品仓上的正向预留；`fn_guard_qualified_origin_reservation_identity` 去掉 V535 的不良品仓分支，只保留身份不可变部分。
6. 7 个既有守卫函数把「启用记账叶仓」换成「良品子仓」(先断言锚点个数再整段替换)：`fn_guard_iqc_actual_warehouse_selection`、`fn_guard_material_return_receiving_confirmation`(与 V619 对齐)、`fn_guard_procurement_iqc_pre_stock_mutation`、`fn_guard_production_finished_arrival_registration`(先入库后质检分支)、`fn_guard_sales_shipment_picking_evidence`、`fn_guard_sales_shipment_picking_warehouse`、`fn_workshop_material_bin_position`(2 处)。
   - 2026-10-05 与 V798(ADR-143 委外按工序领料)合并：重定义 V798 的 `fn_subcontract_draw_line_stock(计划行)`，公共可用部分只认 `fn_warehouse_counts_as_usable` 的仓(原内联「未删、非不良、非内料仓、作业叶仓」，现多一个「记账」条件)，`v_stock_available` 扣他人预留不变；同时按锚点替换 V798 的 `fn_subcontract_component_entitled_lots(订货明细)`，精确专属批次所在仓的作业叶仓判定换成 `fn_warehouse_counts_as_usable`(锚点 `fn_warehouse_is_operational_leaf(warehouse.id)` 必须恰好一处，否则中止)；领料提交的锁发现(`SubcontractDrawCommandService`)与领料草稿占用前的 `reserveDraft` 发出仓校验用同一函数——候选仓 = 锁住的仓 = 允许占用的仓(停用叶仓的既有库存仍可领)。
7. 「仓库上还有没结束的库存预留时不能改成不良品仓」不再在本迁移里按锚点改写 V800 的守卫：V800 的退出新选前置条件 `fn_warehouse_selection_exit_blockers` 已包含未结预留，停用/删除/改不核算/改成不良品仓同一口径(2026-10-05 审查修复时收敛)；
   另列出本次之前已审核、跨良品/不良品的普通调拨(NOTICE；测试服务器没有)——它们以后不能直接红冲，要改走专门通道。
8. 权限：`stock:defective_transfer`「转不良品仓」(默认给持有 `stock_doc:approve` 的部门，即仓储部)、`stock:defective_release`「不良复判转回」(默认给品质管理部 DEPT_QA)，`NORMAL` 授权策略、非基线、非高危，挂在「库存单据」权限面。往 `department_permissions` 种默认授权时与 V798 同法：本节内暂停 V775 的留痕绑定与删除留档两个触发器(`trg_bind_business_record_parent` / `trg_retain_business_record`，结束后按 V775 原样 ENABLE ALWAYS 恢复)，种子授权不登记永久记录身份，全新库仍是「留痕身份为空」(2026-10-05 与 V798 合并时统一，`SubcontractStepDrawMigrationPostgresTest` 断言)。另外老库全量导入的目标库守卫(`server/legacy_migration/migrate_bootstrap_target_guard.sql`)改为按来源表判定留痕身份：只有来源表本身是要清空的业务表时才算「目标库已有业务数据」，部门默认授权这类配置行的身份不算(2026-10-05 审查修复，`LegacyBootstrapCoordinatorPostgresTest` 复现并验证；现作为兜底保留)。
9. 事后断言：不良品仓上没有生效的正向预留(有则中止，提示先释放或复判转回)；没有货品的所属仓库是不良品仓。

## 服务层与前端同步

- 选仓：`WarehouseScopeService.require(仓, 名称, WarehouseUse)` 取代三个旧入口，30 多个调用点逐个标用途；库存内核过账前按矩阵给出中文原因，从不良品仓出库只守非负底线。
- 专门通道：`POST /api/stock/docs/defective-moves`(一次建单并过账，只需通道独立权限，提交键幂等)、`GET /api/stock/docs/defective-moves/options`；通用仓库单据入口只建普通调拨(两端同类)。
- 可用量：销售下单占用与退货重预留、委外备料、销售出货闸门、仓库销售出库候选与预算、客户零星发货、批量出货分配、MRP、排产都改读 `v_stock_usable` / `fn_stock_global_usable`。
- 物料分析行选择与分仓明细排除不良品仓，齐套 `may_allocate`、预排专属来源、自动核对、预算读取补非不良条件，参与仓与主仓不能是不良品仓。
- 即时库存「含不良品仓」默认关，打开后每行 `defectiveQty`、合计「其中不良品数量」；货品列表与详情合计按良品口径，详情另列不良品数量。
- 前端选仓用途 `WarehouseUse` 必填，面板/下拉给不良品仓加「不良品」标签，良品用途下置灰；库存详情余额行提供「转不良品仓」「不良复判转回」入口。

## 测试服务器影响(只读估算)

不良品仓 002/C0401 在测试服务器上 0 流水、0 余额，也没有落在不良品仓上的预留，事后断言不会触发；规则变化只影响此后的新业务。
