# 审计中心

> 目标：获授权的核查人员不用理解数据库字段，也能快速回答：**谁、在什么时间、用哪台设备做了什么、结果如何、是否有风险，以及具体改了什么**。
>
> 页面：`lib/features/admin/pages/admin_audit_log_page.dart`
> 后端：`server/src/main/java/com/uten/imp/audit/`
> 数据库：`V169__audit_center_risk_and_full_operation_coverage.sql`、`V171__audit_export_and_configurable_retention.sql`、`V172__audit_device_evidence_and_local_correlation.sql`、`V173__audit_view_permission.sql`、`V183__professional_asset_and_deferral_subledger.sql`、`V184__refresh_audit_trigger_coverage.sql`、`V185__audit_soft_delete_and_redaction_hardening.sql`、`V424__audit_notice_and_system_noise_exclusion.sql`、`V425__audit_log_fresh_start.sql`、`V428__audit_login_session_correlation.sql`、`V429__audit_production_daily_report_workers.sql`、`V556__audit_classification_shared_literal_matching.sql`

## 入口与权限

工作台 → 系统管理 → 审计日志，路由 `/admin/audit-logs`。超级管理员因固有全权限可进入；所有非超管
都必须由超级管理员通过个人覆盖点名授予 `audit_log:view`，该权限不能配置给部门或随部门树继承。
页面、详情和本机回执均为只读，任何账号都没有修改或手工删除审计记录的接口。
导出属于数据外发，除查看权限外还需独立权限 `audit_log:export`；非超管同样只能个人点名授权。
V171/V173 会清理升级前已有的非超管审计导出/查看授权，发布时必须按批准的核查人员名单重新授予，
不能依赖旧部门配置继续生效。

## 当前实现与性能边界(2026-09-12)

- `admin_audit_log_page.dart` 负责查询范围、请求版本、分页和路由编排；`audit_overview_widgets.dart`
  负责总览、筛选、会话与事件列表；`audit_detail_panel.dart` 负责统一详情与变更；
  `audit_device_evidence.dart` 负责设备核查和技术证据。这些为同一个 Dart library 的 `part`，
  保持详情入口及私有模型一致，没有增加网络请求或加载时依赖。
- 初始工作区收敛为紧凑标题、状态、人员与时间两个配置区；保留首屏可见的选人入口、48dp操作目标、
  浅深主题及大字号适配。查询后仅显示一条可展开的人员/日期范围条和紧凑模式切换，不重复铺介绍卡；会话三项指标只显示事实，列表标题不重复人员日期。
- 小屏统计采用两列紧凑指标，会话概览改为紧凑计数，列表标题只显示数量/页码；小屏分页仅显示前后页与当前/总页，跳页输入保留在桌面。搜索始终可见，
  高级操作/对象/分类筛选默认折叠；当前非空筛选以徽标继续显示，避免隐性筛选。
- 事件列表收到回执即可显示，统计随后使用同一个 `snapshotId` 获取；统计失败只显示可重试提示，
  不会隐藏已经取得的操作证据。晚到响应仍受请求版本守卫约束。
- 会话查询先按所选日期匹配身份，再按完整在线会话的登录时间(缺失时最早活动)排序，选择本页会话，
  才聚合其设备、结果、退出和令牌证据。日期只是匹配条件，不截断跨午夜或选定日期外的完整摘要。
  CTE 明确只取摘要所需列，不把 before/after 大 JSON 搬入重复消费的临时结果。
- 起点定位采用 `matched_sessions CROSS JOIN LATERAL`：逐个已匹配会话按 `session_id` 查完整的最早
  登录/活动，再排序分页，避免优化器为这一步把无关在线审计全部顺序扫描。完整会话摘要与详情仍受
  相同 `snapshotAuditId` 限制，不用日期内第一条事件冒充真实登录时间。
- 继续使用 V428 的会话/时间/ID 索引。这里未重建审计表、改动历史记录或放宽权限；实际大库耗时须
  结合目标数据分布和 EXPLAIN 验证，不能从源码优化推断固定毫秒数。

实际公司副本已升级到V555，含61,793条在线审计(61,791条原记录与2条迁移元数据审计)。在只读
`REPEATABLE READ` 事务、15秒超时、候选应用默认的 `jit=off` 下，按同一真实员工UUID分别选择31天
和最繁忙单日，并先确认没有归档范围冲突。起点SQL修改前后逐行结果相同；各交替执行3次：

| 范围 | 范围内主活动 | 匹配/返回会话 | 原起点SQL中位 | LATERAL起点SQL中位 |
|---|---:|---:|---:|---:|
| 31天 | 13124 | 48 / 10 | 194.486ms | 111.588ms |
| 单日 | 2716 | 7 / 7 | 122.795ms | 58.074ms |

该对照中，起点定位不再顺序扫描整张 `audit_log`，使用 `idx_audit_session_created_id` 查询48/7个
匹配会话；详细聚合只处理本页10/7个会话，对应2870/3196条完整会话事件，无临时块读写。范围匹配
仍通过人员或日期索引过滤，不能把“起点阶段消除全表扫描”说成整次查询只读本页行。以上仅为当前副本
分布下的分页SQL测量，不含高水位、归档检查、计数、人员解释、网络与UI，也不代替HTTP授权测试或全站SLO。

## 页面信息架构

### 1. 先确定人员和时间

页面初次打开只展示查询范围编排器，**不会请求日志列表、统计或导出数据**。普通调查必须依次完成：

1. 选择员工/访客：候选以不可变的系统人员 UUID (`actorId`) 为查询权威，姓名、工号、账号、部门和职位只用于识别；
2. 选择北京时间：可选今天、昨天、近 7 天、近 30 天或自定义区间；支持单日，任一查询最多连续 31 天；
3. 点击「查看登录会话」后才取得审计高水位并加载会话摘要，每页 10 次登录；需要高级逐事件排查时再切换到
   「事件明细」，每页 20 条。

没有可确认人员的登录失败、非法令牌、访问拒绝等证据走独立「未识别访问」模式，同样必须先选择北京时间
单日或不超过 31 天的区间。调查已经取得完整 Request ID 时，可直接走「按操作关联编号精确排查」；该模式
不依赖人员选择，并显示这一次操作的请求、显式事件和数据库变化证据。

系统范围不提供成功任务/迁移的全量入口，只提供「系统异常」范围：必须选择北京时间区间，固定
`actorScope=system` + `activityOnly=true`，并由服务端强制只返回失败结果。系统成功轮询、维护汇总和派生写入
不会借此重新进入主活动。

页面不提供“所有人员 + 全部日期”的默认查询，也不把人员姓名或可变账号当关联键。列表、详情、趋势、
筛选摘要和导出中的时间统一显示为北京时间，不提供切换为设备当地时间的入口；设备声明时区只作为取证字段。

### 2. 登录会话与独立时间线

选择真实人员后默认进入登录会话视图，不在首页铺开每一条 GET/修改/下载/退出记录：

- V428 为员工刷新令牌、访客刷新令牌、在线审计和冷归档增加稳定 `session_id`。一次成功登录生成一个
  UUID，刷新轮换继续沿用；退出、修改密码后的新会话和模拟身份请求均按服务端已验证身份关联。历史无可靠
  会话证据的行保持空，前端不得按相邻时间猜测拼接；
- `GET /api/admin/audit-sessions` 按人员 UUID + 北京时间单日/区间选择会话，但一旦命中某次登录，会返回该
  会话跨午夜的完整在线摘要。卡片展示登录/退出、设备、凭证状态、人工操作数、失败数和退出后活动；
- 点击卡片通过 `push` 进入 `/admin/audit-logs/sessions/:sessionId` 独立页面。普通返回必须 `pop` 回原
  审计中心实例，保留人员、日期、页码和滚动位置；浏览器深链直达且没有返回栈时才回审计中心；
- 独立页先按 `sessionId` 读取权威摘要，再复用同一 `snapshotAuditId`。时间线按
  `createdAt DESC, id DESC` 最新在前，每次 20 条，使用 `cursorAt + cursorId` 复合游标手工加载更早记录；
  Flutter 使用 `SliverList` 懒构建，不因多次加载而一次重排全部节点；
- 时间线节点必须展示中文动作、业务对象类型、可读名称/业务编号、结果、风险和北京时间。点击节点与事件
  明细入口共用同一套四页审计详情，不允许另做缺少 before/after、关联变化或设备证据的精简详情；
- 会话不存在、晚于当前快照、已转入冷归档以及所选日期包含冷归档会话时，服务端返回明确错误。冷归档仍
  只能走受控恢复/隔离调查，不伪装成“该日期没有日志”。

没有人员 UUID 的未识别访问和系统失败范围继续直接使用事件明细模式；完整 Request ID 也直接进入同一操作
证据调查，不人为建立登录会话。

### 3. 总览卡片

| 卡片 | 含义 | 点击行为 |
|---|---|---|
| 全部操作 | 已选人员/未识别访问与北京时间范围内的主活动 | 清除风险、结果、分类下钻 |
| 风险行为 | 中、高、严重风险数量 | 仅看风险记录 |
| 严重风险 | 刷新令牌重用等需要立即核查的记录 | 仅看严重风险 |
| 失败操作 | HTTP 失败、认证失败或安全策略拒绝 | 仅看失败记录 |
| 变更操作 | 主活动中代表新增、修改或删除意图的操作 | 仅看写操作；底层字段证据在 Request ID 下钻中展示 |

卡片是筛选入口而非装饰。当前生效卡片有选中态，再次选择“全部操作”恢复总览。

### 4. 所选区间趋势

按所选北京时间区间逐日显示操作总量与风险行为量 (最多 31 天)。总量使用主题主色，风险量使用风险色；图形同时提供
`Semantics` 文本，不能只靠颜色理解。

### 5. 搜索与筛选

- 人员模式固定提交 `actorId` + `actorScope=user`；未识别访问模式提交 `actorScope=anonymous`，不会把系统维护
  账号混入匿名安全事件；系统异常模式提交 `actorScope=system` 且只允许失败结果。三种模式都必须带完整
  `dateFrom/dateTo`；
- 默认 `activityOnly=true`，只展示可读的请求/显式业务/安全主活动。数据库触发器行、派生 `*_events`、账本和
  其它字段级证据仍保存在 `audit_log`，在详情查看同一操作或按完整 Request ID 排查时以 `activityOnly=false` 下钻，不因
  主列表降噪而删除证据；
- 操作：全部、写操作、新增、修改、删除、读取；选择登录等原始动作或非数据变更分类时会清除不兼容的
  操作类型，避免互斥条件返回空结果；
- 关键字不区分大小写搜索 action、操作人账号、对象类型、对象 ID、HTTP 路径和 request ID；
- Flutter 对象快捷项当前只有货品 `goods`、货品分类 `material_categories`、客户 `clients`、供应商
  `suppliers`；在主活动模式下，它们匹配对应 `/api/master/**` 请求路由组或显式业务对象，不直接展开
  database 行。需要字段级变化时，从主活动进入同一 Request ID 下钻。其它对象 ID 可用通用关键字搜索；
- 来源：主活动默认只含 request、business、security；database 来源只在完整 Request ID 证据下钻中展示；
  Request ID 独立框只提交完整 UUID，部分值使用关键字；
- 日期范围只能在运行查询前选择，服务端再次校验起止完整、开始不晚于结束且最多连续 31 天；
- 分类：全部、业务操作、数据变更、登录会话、权限变更、安全事件、导出、系统设置；
- 动作、风险级别、成功/失败；
- 一键重置；后端分页，按 `createdAt DESC, id DESC` 稳定倒序。

### 6. 可读事件列表

每条记录优先展示自然语言摘要，而不是原始 action：

- 操作人账号；
- 动作摘要，例如「修改生产执行分段：状态：READY → DISPATCHED」「新增销售订单 SO-2026-001」
  「认领HR任务 confirm · 张三」——摘要由后端解释器拼装（动作 + 对象 + 单号 + 前两项关键变更），
  失败操作在句末附中文原因（如「（密码错误）」）；
- 操作对象按结构化字段分别展示：对象类型、对象名称/单据标签、业务编号/单号、旧系统编号；UUID 只放
  折叠的技术排查区，不进入人员主时间线；
- 精确时间；
- 风险等级和操作结果（结果码已翻译为中文，如 成功 / 尝试过于频繁（已限流））；
- 设备简称、平台、IP、HTTP 状态码等辅助信息。

解释器 `AuditEventInterpreter` 覆盖全部业务表名、常见列名、状态枚举值与结果码的中文映射。
业务详情查看会分别写入 `targetDisplayName/targetBusinessCode/targetLegacyCode`；旧日志仍保留
`targetName` 兼容，缺失字段明确提示需要补录，不显示“其他业务对象”或猜测英文内部码；
数据库变更行额外生成逐字段「具体变更」明细（changeSummary，最多 6 项）。未收录对象保留可读化
fallback，并在详情中继续显示原始 `targetType`，不能因缺标签隐藏记录。

窄屏采用单列卡片，宽屏把操作人、动作、时间、风险和结果排成易扫描行。点击任意记录打开自适应详情：
桌面端为右侧面板，移动端为底部抽屉。

### 7. 导出当前结果

AppBar 的「导出当前结果」直接复用 `UtenExportButton`。首次列表高水位尚未取得时按钮禁用，不弹密码框、
不发送导出请求；取得 `snapshotId` 后才开放。导出严格沿用页面当前的关键字、对象、来源、
Request ID、员工/访客 UUID 或未识别/系统失败范围、操作类型、北京时间、动作、风险、事件类型、
成功/失败与当前快照，
不另建一套口径。密码可留空直接下载普通 Excel，也可设置任意 1–128 位 Excel/WPS
文件打开密码；设置密码时服务端使用 Agile AES-256 加密，且始终受独立权限、每用户频率限制、并发闸门和
`export_max_rows` 保护。审计中心另有更严格的同步导出硬上限：即使系统设置更大，单次也最多 10,000 条；
超过时必须缩短人员/日期/筛选范围。

表格包含可读动作、对象类型、对象名称、业务编号、旧系统编号、结果、风险等级与原因、事件类型、来源、设备名称/厂商/型号/平台/系统、
App 版本与构建、设备形态/浏览器/语言/时区/真机声明、本机安装标识、本地操作 ID、本机发起时间、
设备采集状态与摘要、IP、HTTP 上下文、request ID 和审计日志 ID。批量文件刻意不含 before/after JSON、
任何 User-Agent 字段和原始设备 Header；需要核查字段变化时按日志 ID
回到详情，避免把大体积或更敏感的快照批量外发。成功导出另记 `export_audit_log`，限流或失败请求也由
提前进入拦截链的请求审计记录。

## 详情子页

事件明细列表与登录会话时间线只能调用同一个完整详情查看器；桌面端共用右侧面板，移动端共用底部抽屉。
任何入口都不得省略以下四页证据。

详情必须有以下四个可切换子页；窄屏 TabBar 可横向滚动：

### 概览

按「读故事」的顺序组织为**操作叙事卡**（2026-08-29 重构）：卡片标题「这次操作做了什么」与结果徽标；
操作人（头像、账号、部门/职位）；「何时/在哪个页面/记录来源」上下文标签；大字完整动作句
（带主题色竖线强调，含对象与单号）；操作对象行；「具体变更」升级为 字段名 + 灰色旧值胶囊 →
主题色新值胶囊。其后为风险说明卡与「排查线索」卡（IP、接口耗时、完整接口路径、事件类型、
可复制的对象数据库 ID）。展示风险等级与可解释原因；风险是规则命中结果，不是机器学习结论。

### 数据变更

将脱敏后的 `before` / `after` JSON 解析为字段级对比，逐项显示变更前和变更后；同时允许展开原始
脱敏 JSON，便于排障。V185 后新生成的通用触发器记录会继续剔除密码、令牌、身份证、手机号、地址、
银行账号、薪资、联系人、迁移列明的原因备注类敏感文本及大型嵌套 JSON 快照。业务名称、编号等调查必需
字段仍按最小必要原则保留。V185 不无界重写旧审计行；历史记录
按原事实保留，只能由受限详情权限、留存策略及经批准的分批调查/治理控制风险。

### 设备证据

展示服务器固化的客户端声明快照：设备名、厂商、型号、平台、系统、App 版本/构建、设备形态、浏览器、
语言、时区、真机/模拟器声明、客户端发起时间、随机本机安装 UUID、设备快照摘要、本地操作 ID 与服务器
Request ID。详情默认只显示服务器快照；核查人员点击“授权并核对本机回执”后，服务端先校验权限并记录本次核查，
成功后才读取当前设备的本机资料与回执。若当前设备恰是原操作设备，会按 Request ID 在多次请求尝试链中定位具体
尝试，并逐字段显示“服务器 / 本机回执 / 一致性”；401 自动刷新、503/504 重试不会因最终 Request ID 不同而误报。
无权限、离线或授权接口失败时不读取本机安装标识、设备资料或回执。

本机回执异步尽力写入，最多 300 条，并按系统公开的审计总留存月数清理；不保存 query、请求正文或令牌。
回执正文以明文 JSON 存在本地偏好存储，HMAC 密钥单独存入平台安全存储：完整性通过只能发现普通编辑、密钥变化或写入损坏，
不是服务器签名或硬件证明。核查人员在另一台设备不能远程读取原设备本地存储；持
`audit_log:view` 的核查人员可在原设备进入“设置 → 本机信息与操作回执”，联网完成后端授权后，按完整
操作 ID 精确查询。普通员工和访客没有入口，深链也会被拦截；查询动作本身另记审计。本机回执没有手工清除
或修改功能，只会按留存策略自动清理；卸载应用或操作系统清理站点/应用数据仍可能使其消失。
系统不采集 IMEI、MAC、硬盘序列号。产品权限只能控制 UI 与 API；已经取得设备管理员/root 权限、
浏览器开发工具权限或用户系统账号的人仍可能直接读取本地偏好数据，因此本机回执不能承载密码、令牌、
请求正文或直接 PII，也不能当成不可抵赖证据。

客户端回执使用独立 `audit.device.local_receipts.v3` 存储键，签名覆盖
`{format:3, receipts:[...]}` 与每条 `verifiedOrigin`。首次升级在独立作用域的
`AuthRefreshLock` 内重新加载偏好存储，只在没有v3存储和安全存储导入标记时读取旧v1键：
合法v2签名保留既有验证结果，无签名或坏HMAC历史保持未验证，后续重试也不能把旧历史重新变成可信。
先持久化v3快照，再持久化导入完成标记；任一步失败均不对外确认成功，后续可重试，不缓存失败结果。
一旦确认导入，v3缺失、空串、损坏或外层版本被改为2都不会回退旧键；把合法旧v2列表复制到新键也不会
作为兼容格式读取。旧客户端此后仍写旧键，但不能覆盖新版记录或改变其来源标记；这些后续旧版本机回执
不会再自动合并，服务器审计记录不受影响。

新版每批回执变更都在同一锁内基于最新持久化快照操作，保留同一批的合并写入与失败前的有效缓存；
只有签名快照成功存储后才发布新状态。Web优先复用Web Locks，未支持时沿用现有短租约机制，不新增鉴权
或凭据复制通道。格式升级是自动数据兼容操作，不增加本机回执的人工编辑/清除入口。

审计列表、统计、详情和本机核查调用本身会继续产生服务器审计；客户端故意不为 `/admin/audit-logs/**`
写本机回执，避免“观察审计又生成待观察回执”的递归和挤占本机 300 条容量。

### 高水位边界分页

审计查询本身也会新增审计行，若直接用无边界 offset 分页，新高 ID 行会把旧页向后推，造成翻页重复或漏行。
第一次列表请求不传 `snapshotId`，服务端读取当时的最大日志 ID（空表为 0）并在响应顶层返回；随后翻页、
统计和页面导出都复用该值并固定查询 `id <= snapshotId`。直接调用 summary/export API 且未提供快照时，
服务端也会在该请求开始时自行取得最大 ID 并固定边界。刷新、搜索、日期、任一基础筛选、统计卡下钻或
“查看同一操作”会清除旧快照并重新取得一个边界。在普通后续高 ID 写入场景中页集不会被这些新行推移；
边界之后的新操作仍然保留，只是在主动刷新前不混入当前结果。

该边界不是跨 HTTP 请求持有的 PostgreSQL MVCC 快照：ID 已分配但稍后才提交的旧 ID 行仍可能进入结果，
留存任务并发删除在线行也可能移动 offset。因此它保证的是普通“后续分配更高 ID”写入下的确定性分页，
并显著消除审计查询自身造成的漂移；晚提交、03:17 留存窗口及高并发场景仍须实库验证，不能宣称绝对零重复/零遗漏。

### 技术信息

供排障使用：事件来源、request ID、HTTP 方法和路径、状态码、耗时、IP、User-Agent。
同一个 request ID 可关联一次用户请求和它引起的多条数据库变更。

## 风险规则

| 等级 | 当前规则示例 | 页面说明 |
|---|---|---|
| 严重 | 刷新令牌重复使用 | 可能存在会话泄露，需要立即核查 |
| 高 | 删除、权限/数据范围、系统设置、重置密码、库存调整、红冲、离职、黑名单 | 可能产生不可逆或越权影响 |
| 中 | 登录/认证失败、访问拒绝、HTTP 4xx/5xx、改密、数据导出、工资条 PDF 下载、查看敏感审计证据 | 需要确认是否为误操作、异常外发或攻击尝试 |
| 低 | 未命中以上规则的普通查看和业务操作 | 正常留痕，不表示绝对安全 |

风险以数据库强制分类为基础；V556 通过公共分类函数与 ALWAYS 写入触发器保持原 V169 规则，旧行及归档不重分类。后端读模型会把 V185 前以 `update` 存储的软删除识别为“删除/高风险”，并把
“查看审计详情、核查本机回执、工资条 PDF 下载”等敏感证据访问提升为中风险，
并让列表、筛选、统计、趋势与导出保持同一有效口径。后续新增关键动作时必须同时补生成规则或读模型覆盖、
标签和测试。

## 操作记录覆盖

审计分三层，服务端 request ID 将请求和数据库变化串联；客户端本地操作 ID 串联自动刷新/重试尝试：

1. **请求覆盖层**：`AuditRequestContextFilter` 从安全过滤链前开始计时，MVC 内由
   `UserOperationAuditInterceptor` 落库；没有进入 MVC 或尚未落库时由 Filter 的 `finally` 兜底。这样
   `GET/POST/PUT/PATCH/DELETE/HEAD /api/**` 的普通业务请求、匿名认证请求、401、CORS 非法来源 403、404/405 与前置异常原则上都有一条
   请求记录；JWT 完整校验成功后会把用户 ID/账号快照绑定到本次 request，因此即使 404/405 返回时安全上下文已清理，
   仍能准确归属操作人，未认证请求则明确为空。记录包含方法、路径、状态码、耗时、IP 与 UA；不保存 query
   值和请求正文，避免复制搜索条件、密码、令牌或 PII。`OPTIONS`、静态资源和健康检查不是用户业务操作。
   经审查的成功角标/待办计数轮询、通知到达轮询、`/auth/me`、员工/访客正常 refresh、任务 heartbeat 以及
   审计中心自身读取不会写成主活动；同一路径只要返回 4xx/5xx 或抛异常仍必须保留，客户端不能凭任意 Header
   绕过普通业务写审计。
2. **显式安全/业务事件**：登录成功与失败、限流、账号锁定/停用、刷新失败、刷新令牌重用、
   访客验证码、登出、401/安全策略拒绝、导出、工资条 PDF 下载和其它必须单独命名的动作，由
   `AuditService` 显式记录。2026-08-29 起通知域的用户手工操作与 HR 任务中心按钮也走显式留痕：人工发布公告、
   查看通知、确认回执、关闭强提醒、全部标为已读、完成工作台待办、回复/撤回庆典祝福、批量发布庆典、
   从我的列表移除通知(`notice_*`)，以及 HR 任务认领/释放/接管
   (`hr_task_*`)。通用 `TaskClaimHandle/TaskClaimSession` 的 claim/release 则可能由页面挂载、选择变化和销毁
   自动触发，是并发协调证据，不得写成纯人工点击；安全审查没有授权把其成功记录从主活动移除。首次持有仍记
   `task_claim`，重复持有改记 `task_renew` 并显示「续租任务认领(自动协调)」，release/takeover/force-release
   继续保留显式证据。targetId 记录通知标题、「任务类型 · 员工姓名」或 targetKey。人工成功事件使用调用方业务事务，业务回滚时成功审计一同回滚；
   登录失败等独立失败尝试才使用独立事务。系统自动发布通知、按来源自动已读和正常 refresh 不写主活动；
   已读通知再次被明确打开仍记录一条 `view_notice`，回答“查看了什么”。
   heartbeat 每 30 秒可请求一次，但只有剩余租约进入续租阈值时才真正 UPDATE；未到阈值只读返回。成功 heartbeat
   请求不落主活动，实际续租产生的底层触发器证据由 `activityOnly` 默认隐藏，失败/冲突仍保留。
   是否进一步移除通用自动 claim/release 的成功主活动，必须取得用户对具体动作和页面的明确授权；当前是剩余缺口。
   审计详情、本机回执核查与敏感下载在显式审计失败时不会继续披露内容。
3. **数据库变化层**：V169 为当时所有尚未覆盖的公开业务表补齐 AFTER INSERT/UPDATE/DELETE 触发器；
   V183 最终为其 9 张资产/待摊新表显式创建 `trg_audit_*` 并在迁移尾部做一次只补缺 sweep；V184 再以
   独立后置迁移复核。每张业务表必须恰有一个前缀触发器，且已启用、为 AFTER ROW、覆盖 INSERT/UPDATE/DELETE，并调用
   `fn_audit`/`fn_audit_redacted`，否则迁移 fail closed；完全没有前缀触发器时才补挂 `fn_audit()`。
   V185 将之后的 `is_deleted`/`deleted_at` 软删除转换存为 `delete`，扩充行最小化字段且保留 V172 设备关联列。
   触发器保存脱敏 before/after。凭证、刷新令牌、短信码、Flyway、空间扩展、序号、
   物化视图刷新状态和迁移运行元数据表
   不复制行内容，只保留请求或显式安全事件。**V424（2026-08-29）再把纯系统行为移出触发器覆盖**：
   通知 4 表（`notices`/`notice_user_states`/`notice_acknowledgments`/`notice_blessings`）、
   业务/附件事件发件箱、账户月度流水汇总与 4 张幂等指令表——这些由后台任务/框架自动写入，
   不是人工操作；人工在通知/任务上的动作由第 2 层显式事件留痕。财务过账、红冲、审批、库存、权限、
   安全与追加式 `*_events` 等业务证据不属于噪声，继续保留数据库触发器，只是不在主活动列表逐行铺开。
   今后再写 refresh_audit_trigger_coverage 全表扫描迁移时必须把这 11 张表加入排除清单。

触发器只能记录迁移生效后的变化：V169 之前的历史操作，以及任何表在触发器真正生效前若已发生的操作，
都不能根据当前行反向伪造操作人、时间和原值。当前最终迁移链在 V183 创建新表的同一迁移内先挂触发器，
V184 随后复扫，V185 再加固语义与脱敏；这仍须在目标 PostgreSQL 验证，不能据源码推定已部署。静态迁移测试会扫描后续 `CREATE TABLE`，
新业务表若出现在最新 sweep 之后必须补后续 sweep；技术表只能带书面理由进入白名单。部署验收仍必须在
目标 PostgreSQL 查询 `pg_trigger`，静态测试不能替代运行态证据。

`DeviceAuditInterceptor` 为员工、访客及各自刷新 Dio 注入版本化设备上下文；服务端在 JWT 前的
`AuditRequestContextFilter` 生成权威 Request ID、清洗设备字段并回显关联头。客户端会把编码后设备上下文
控制在 4000 字符内；服务端拒绝整体超过 4096 字符、JSON/版本/枚举/时间非法的上下文并标记 `invalid`，
缺字段标记 `partial/missing`，单字段则按白名单清洗或截断。设备声明异常不能阻断业务；极端或漂移超过
允许窗口的客户端时间不会进入 PostgreSQL。

审计存储正常时，普通人工请求至少有一条可读请求或显式事件；产生数据变化时还有一条或多条字段级记录，
同一 Request ID 可把各层串联。上述批准的成功后台轮询/refresh/heartbeat 是窄范围例外，失败仍保留。
通用请求审计写入失败会告警，但不会改写已经完成的业务响应；
审计详情、本机回执授权和敏感下载等证据读取则在显式审计失败时 fail closed。数据库触发器与业务写入处于
同一事务。TLS、反向代理拒绝、网关 413 等没有进入应用进程的流量由边缘访问日志负责，不能伪造成数据库内
的用户操作。

## 留存与自动删除

- **V425 当前为未获执行授权的 NO-GO 候选**：源码提交已经包含
  `TRUNCATE audit_log, audit_log_archive RESTART IDENTITY`，但本次审计中心优化只授权降噪、查询与定期留存，
  不授权清空历史。该语句会永久删除热表和冷归档，并复用从 1 开始的审计 ID；旧导出、截图或调查记录中的
  ID 以后可能指向另一条日志。因此任何非空环境不得自动应用 V425。
- 迁移总索引已记录可丢弃本机开发库具有 V425 history，因此 V425 必须按已应用迁移保持字节、文件名和
  顺序不变，禁止 `flyway repair`。正式 Spring 与独立 migrator 的 `AuditFreshStartGuardCallback` 会在已有
  history 的环境于 V425 前失败关闭；只有 0-history fresh chain 技术上可继续，但这不是清空授权。其它未
  注册 callback 的 Flyway 入口全部禁止；每个目标环境仍须独立盘点，状态不明时一律 NO-GO。
- 在线 `audit_log` 默认保留 **6 个月**，可在系统设置调整为 1–120 个月；到期后先进入冷归档。
- 冷归档默认追加保留 **30 个月**，可调整为 0–240 个月；默认总留存为 36 个月。两个截止点都从记录
  原始 `created_at` 计算，不从归档当天重新计时；长期停机后特别旧的记录可能在同次任务先归档、随后达到永久删除条件。
- 页面 list/detail/export **只查询在线 `audit_log`**。进入 `audit_log_archive` 后虽然仍处于总保留期内，
  也不能在审计中心直接查询或导出；确需调查必须走受控归档恢复/隔离查询流程。因此“总保留 36 个月”
  不等于页面可查 36 个月，默认页面在线可查期仍是前 6 个月。
- 自动任务默认每天北京时间 **03:17** 运行，同一事务内确认归档成功后才删除在线记录；达到总期限后
  才永久删除冷归档。页面和业务 API 都没有编辑、单条删除或批量删除入口；V425 不得被描述成页面能力或
  正常留存机制。
- 列表底部展示保留策略提示（读 `/api/settings/public` 的总月数），解释"为什么查不到很早的日志"。
- 期限只能由有系统设置管理能力的超级管理员修改，并要求二次密码确认和记录设置变更审计。缩短期限前
  必须确认法规、合同、调查冻结与备份要求。当前没有逐条“法律保留/调查冻结”功能；需要冻结时必须走
  审批后的独立备份或后续专门能力，不能只依赖页面提示。
- 本机回执跟随在线期与追加归档期之和自动清理，同时最多 300 条；本机无手工清除入口，但卸载应用或
  操作系统清理应用数据仍可能使其消失。

完整批处理、锁和应急流程见[审计与日志保留策略](../数据迁移/38-运维-审计与日志保留.md)。

## 接口

- `GET /api/admin/audit-sessions`：按真实人员 UUID 与北京时间范围分页返回登录会话摘要；`page` 默认 1，
  页面使用 `size=10`，服务端最大 20；首次返回 `snapshotAuditId`。日期最多 31 天，若范围包含已进入
  冷归档的会话则明确提示当前页面只查在线日志。
- `GET /api/admin/audit-sessions/{sessionId}`：独立页按规范 UUID 读取完整会话摘要；可沿用列表
  `snapshotAuditId`，直接深链则由服务端取得最新高水位。不存在、晚于快照和已归档分别返回明确错误。
- `GET /api/admin/audit-sessions/{sessionId}/events`：每次默认 20、最多 100 条，使用
  `cursorAt + cursorId` 复合游标和同一 `snapshotAuditId`；两个游标必须同时提供，游标编号不得超过快照。
- 上述三个接口和查询服务均要求 `audit_log:view`。每次成功查看会用真实核查人员身份记录
  `view_audit_session_list/detail/events`，摘要包含被核查人员、北京时间范围、会话编号或加载批次；显式
  证据审计写入失败时读取失败关闭。

- `GET /api/admin/audit-logs/actors`：分页搜索可调查人员，返回 UUID 权威的 `actorId` 及账号、姓名、部门、
  职位；需 `audit_log:view`，成功的候选搜索本身不制造审计主活动。
- `GET /api/admin/audit-logs`：分页列表；保留 action、actorAccount、riskLevel、eventCategory、outcome、
  dateFrom、dateTo，并支持 `keyword`、`targetType`、`targetId`、`eventSource`、`requestId`、
  `operationKind`、`actorScope`、`actorId`、`activityOnly`、`snapshotId`；除完整 Request ID 调查外，人员模式
  必须同时提供 `actorId/dateFrom/dateTo`，未识别访问模式必须提供 `actorScope=anonymous` 与完整日期；
  系统异常模式必须提供 `actorScope=system`、`activityOnly=true` 与完整日期，并只返回失败结果；区间最多
  连续 31 天。`page` 默认 1，`size` 默认 20，服务端会归一到 1–100。响应顶层为
  `items/page/size/total/totalPages/snapshotId`。
- `GET /api/admin/audit-logs/summary`：总量、风险、严重、失败、变更操作与所选区间逐日趋势；接受 action、
  actorAccount、eventCategory 和全部新增筛选，但不接 riskLevel/outcome，故卡片统计保持在当前基础范围，
  不叠加卡片自身的风险/结果下钻。
- `GET /api/admin/audit-logs/{id}`：概览、字段变化、设备证据、技术上下文完整详情。
- `POST /api/admin/audit-logs/local-receipt-verifications/{clientEventId}`：核查人员在读取原设备本机回执前
  完成服务端授权并记录本次核查；`clientEventId` 必须是规范 UUID，无 `audit_log:view` 或离线时不读取本机数据。
- `POST /api/admin/audit-logs/export`：按列表全部业务筛选与同一 `snapshotId` 导出 Excel；需
  `audit_log:view` + `audit_log:export`。请求体密码为空时普通下载，非空时允许 1–128 位并加密；单次硬上限
  10,000 条，系统设置值更大也不会放宽审计导出上限。
- `GET /api/settings/public`：登录后返回会话阈值及审计在线期+追加归档期的总月数，供本机回执自动清理；
  不返回任何审计内容，也不赋予查看权限。

列表不返回 before/after 和 User-Agent，只在按 ID 打开详情时读取，降低普通浏览时的数据暴露和传输量。
`targetId`、`eventSource` 为忽略大小写的精确匹配；四个页面快捷 `targetType` 会额外匹配其 request 路由组，
其它 `targetType` 仍为忽略大小写的精确匹配；`requestId` 必须是规范 UUID；
`snapshotId=0` 合法、负数返回 400。`actorScope=user` 表示有已验证人员 UUID，`anonymous` 只收没有人员 UUID
且属于安全/认证/登录失败的未识别访问，`system` 表示其余系统维护证据；`operationKind` 支持
create/update/delete/write/read，非法枚举返回 400。create 对应
insert/http_post；update 对应 update/http_put/http_patch，但排除 V185 前可识别的软删除 UPDATE；delete 对应
delete/http_delete，并纳入 before/after 显示 `is_deleted false→true` 或 `deleted_at null→非空` 的历史 UPDATE；
write 是增删改并集，read 对应 http_get 与 `view_%` 显式查看事件。

## 验收重点

- 点击每张统计卡片后，列表条件和选中态同步；
- 选择真实人员与北京时间后默认只加载会话摘要；首页卡片不请求时间线，点击卡片才进入独立页并分别加载
  会话摘要和首批事件；
- 从会话列表进入后返回，人员、北京时间、页码和滚动位置不丢失；深链刷新没有路由 `extra` 时仍能仅凭
  `sessionId` 加载，深链返回有审计中心兜底；
- 同一时间戳的多条事件按 ID 倒序跨页无重复/遗漏；第二页继续复用第一页快照，第一页后新增事件不混入；
- 会话节点点击后能看到与事件列表完全相同的概览、数据变更、设备证据和排查信息四页；
- 页面初次打开、尚未选人/未识别访问与日期时，不调用列表、summary 或 export；人员查询始终提交 UUID；
- 今天、昨天、单日、近 7 天、近 30 天与自定义 31 天边界均按北京时间，直接调用超过 31 天返回 400；
- 未识别访问模式只能看到匿名安全/认证证据，不把 `system`、`ops` 等维护账号混入；
- 系统异常入口只能看到所选北京时间内的失败证据；成功系统任务、迁移和维护汇总没有全量页面入口；
- 登录失败、刷新失败、CORS 非法来源 403、无权限访问、普通 GET、写操作、删除、导出均能找到记录；
- 同一次写请求的请求记录与数据变更记录拥有相同 request ID；
- 默认 `activityOnly=true` 只展示人的主活动；按同一 Request ID 下钻后能看到关联 database 变化，财务、
  安全、权限与追加式事件证据没有因主列表降噪被删除；
- 成功角标/待办轮询、正常 refresh 与成功 heartbeat 不进入主活动；相同端点的 4xx/5xx、刷新重用、
  认领冲突仍可查询；heartbeat 未进入续租阈值时不产生数据库 UPDATE，进入阈值后的底层变化只在证据下钻展示；
- 摘要为中文完整句并内联前两项变更（如「修改销售订单 SO-xxx：状态：草稿 → 已审核；…」），
  失败操作句末带中文原因；结果徽标与详情「结果」显示中文结果码；
- 业务详情查看分别返回对象名称、业务编号和旧系统编号；例如销售历史单据必须显示
  「销售订单 · 销售订货单 · 业务编号 SO-2026-001 · 旧系统编号 86」，不能只给 UUID 或“其他业务对象”；
- 完成待办、HR 按钮认领/释放/接管、人工发布公告、移除通知均能找到带标题/员工名的记录；通用页面自动
  claim/release 仍保留并明确标成并发协调，重复持有显示 `task_renew(自动协调)`；系统自动发布通知与已读回执不再出现；
- 详情概览叙事卡：操作人、时间/页面标签、大字动作句、对象行、「具体变更」旧值→新值胶囊、
  排查线索卡在桌面和窄屏均无溢出；
- V425 未获明确执行授权时迁移门禁失败；不得通过“业务表未变”或空库测试放行非空环境的审计清空与 ID 复用；
- 翻页、统计和导出复用同一高水位，普通后续高 ID 审计不会推移当前 offset；刷新或改变筛选后取得新边界；
- 首次高水位取得前导出按钮不可用；绕过 UI 直接调用导出且未传边界时，服务端仍自行固定高水位；
- 按对象类型/ID、来源、完整 Request ID、关键字和操作类型的正向/非法参数用例均通过；
- 货品/分类等对象快捷筛选在主活动中返回对应人工请求/显式事件；字段级 database 变化只通过同一
  Request ID 下钻，历史软删除在证据视图中仍解释为删除/高风险；
- 迁移静态护栏能拒绝最新 sweep 之后未列白名单的新表；目标 PostgreSQL 的公开业务表均有有效
  `trg_audit%`，并验证启用状态、AFTER ROW、I/U/D 事件和函数；V184/V185 不补造任何迁移前历史；
- 详情四个子页在桌面和窄屏可滚动、可关闭，无布局溢出；
- 新版员工/访客请求、刷新请求、401 重放与安全 GET 重试均带同一逻辑操作 ID；本机尝试链可按每个 Request ID 分别匹配；
- 同机回执完整性通过/失败、其他设备、缺失、旧记录、设备上下文无效等状态不混淆；
- 设备详情和导出不包含 IMEI、MAC、硬件序列号、原始设备 Header、query、请求体或令牌；
- V185 后新写 before/after 不含迁移列明的凭证、PII、原因备注类敏感文本和大型嵌套快照字段；对 V185 前历史行执行专项扫描并按批准流程处置，不把“未回写”误报为已清除；
- 导出参数与当前人员 UUID/未识别范围、北京时间、筛选和高水位完全一致；超过 10,000 条会拒绝；设置密码时
  Excel 必须输入原密码才能打开；
- 导出文件不含 before/after 与 User-Agent，导出成功和 429/失败尝试均可在审计中心找到；
- 非超管且未获 `audit_log:view` 的普通员工、访客和管理员无法调用审计查询接口，也看不到本机回执入口；
- 除超管固有全权限外，`audit_log:view` / `audit_log:export` 只能个人点名授权；部门权限保存与数据库直接写入均拒绝这两个权限；
- 只有查看权限时可核查但不能导出；导出还需 `audit_log:export`；审计与本机回执均无编辑/手工删除入口；
- 每次本机回执核查先通过服务器授权，并能按核查人、时间、目标操作 ID 回溯。
