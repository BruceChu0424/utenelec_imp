## 一、为什么必须独立

仓库管理原先把“采购收货单、委外进仓、委外出仓记录、委外成品退货、委外材料退回、委外损耗”
直接链接到采购或委外业务页面。那些页面包含币种、汇率、税率、结算方式、单价、金额、应付或
索赔动作；即使普通仓库账号被掩码，超级管理员或兼有商业权限的账号从仓库入口进入时仍会看到
商业信息，页面职责也会混入采购/委外编辑、审核、删除和红冲。

现行边界是：**仓库入口不再复用采购/委外业务列表或详情**。六类历史统一使用仓库自己的
quantity-only read model；可复用仓库内部的表格、状态徽标和安全展示壳，但不复用跨部门业务页面、
DTO 或动作栏。

| 仓库历史页 | type | Surface | 查看权限 |
|---|---|---|---|
| 采购收货历史 | `purchase-receipts` | `warehouse.purchase-receipt-history` | `warehouse_purchase_receipt_history:view` |
| 委外进仓历史 | `subcontract-receipts` | `warehouse.subcontract-receipt-history` | `warehouse_subcontract_receipt_history:view` |
| 委外出仓历史 | `subcontract-material-issues` | `warehouse.subcontract-outbound-history` | `warehouse_subcontract_outbound_history:view` |
| 委外成品退货历史 | `subcontract-returns` | `warehouse.subcontract-finished-return-history` | `warehouse_subcontract_finished_return_history:view` |
| 委外材料退回历史 | `subcontract-material-returns` | `warehouse.subcontract-material-return-history` | `warehouse_subcontract_material_return_history:view` |
| 委外损耗历史 | `subcontract-wastes` | `warehouse.subcontract-waste-history` | `warehouse_subcontract_waste_history:view` |

V445 只把六个历史查看权限直接授予叶子部门 `SUB_WH`，不授给 `DEPT_PMC` 父节点。每个 Surface
只关联本页一个只读权限，因此页面右上角“权限设置”和全局“账号与权限管理”都能独立配置，不会
混入价格、编辑、删除、审核或红冲权限。

任务中心另外完成两个仓库专页：

| 仓库任务页 | 路由 / API | Surface 与权限 | 动作边界 |
|---|---|---|---|
| 销售出库 | `/warehouse/sales-outbound/:id` / `/api/warehouse/sales-outbound/**` | `warehouse.sales-outbound` / `sales_shipment:warehouse-work` | 只按服务端 `allowedWarehouseTargets` 开始/完成拣货、登记/恢复异常和交接出库 |

V445 默认只给 `SUB_WH` 增加 IQC 仓库查看，不默认增加实物登记动作；动作须在页面权限设置或全局
权限管理中明确授予。销售出库沿用既有精确仓库作业权限与 Surface。

## 三、仓库字段白名单

允许返回：

- 单号、日期、状态、来源号；
- 供应商/委外商交接名称、仓库名称；
- 制单人、审核人和时间；
- 货品历史编码/名称快照、颜色、单位；
- 业务数量、实际重量、退回量、损耗量、供应商在外量；
- IQC 合格/不合格基本量与状态；
- 损耗期末量、标准量、损耗率、原因；
- 货品主档的当前建议库位。

禁止返回或在仓库端推导：

- 单价、原币/本币金额、成本或金额排序；
- 币种、汇率、税率、结算方式；
- 应收、应付、客户预收、供应商贷项或索赔建议；
- 财务审批备注或采购/委外业务动作。

`goods.stock_place` 只是当前主档建议值，不是历史单据库位快照；页面固定标为“当前建议库位”。
列表只展示行数，不跨单位合计数量，也不把未明确重量单位的行汇总成“总重量”。

## 四、原生仓库单据

调拨、其它入库、其它出库、生产领料、生产退料、产成品进仓、产成品出仓和盘点仍属于同一
仓库领域，可继续复用仓库内部参数化组件。此次已删除列表“成本合计”和成本排序，并在
`StockDocListItem/StockDocDetail/StockDocItemDto` 的 JSON 边界禁止序列化
`totalOriginal/totalLocal/price/amount*`。内部实体仍保留过账成本，库存/财务价值查询应走
受控库存价值或财务报表，不从仓库单据页面读取。

## 五、收货业务接口的纵深保护

采购收货与委外进仓业务接口在 `priceMasked=true` 时，除行单价/金额和合计外，还会把币种、
汇率、税率、结算方式置空；金额排序同时关闭，避免用排序次序推断金额高低。到货登记和继续送检
要求 `warehouse_inbound:view + warehouse_inbound:stock_in`，仓库不再靠采购/委外页面动作完成。

V445 还给权限目录增加 `bulk_assignable` 与 `sensitivity` 元数据。商业敏感权限在全局权限页
显示“商业敏感数据 / 需单项授权”，不会被“本组、本模块、全部配置”批量带入；逐项新增必须二次确认。
