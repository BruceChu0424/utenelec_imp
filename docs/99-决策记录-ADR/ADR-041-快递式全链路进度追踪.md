# ADR-041 快递式全链路进度追踪

- 日期：2026-08-19
- 最近更新：2026-08-30（时间线仅展示实际姓名和中文业务称谓）
- 状态：已采纳（源码候选；目标库迁移与岗位 UAT 未完成，生产 NO-GO 口径不变）

## 背景

销售订单的排产进度原本是模态底表（`showPlanProgressSheet`）：只回答「排了多少、产了多少」，
回答不了「这单现在走到哪一步、这一步谁经手的、出了问题找谁」。业务要求像查快递一样看订单：
每个阶段一行，带责任人和时间，最新进展在最上面，历史可追溯、责任可归因。

## 决策

1. **弹窗改整页**：订单进度查询看板点订单卡、订货单详情「进度追踪」按钮，统一进入
   `/sales/progress/:orderId` 整页（[页面文档](../03-页面/销售订单进度详情页.md)）。
   原底表重构为内嵌面板 `SalesPlanProgressPanel` 复用，弹窗函数 `showPlanProgressSheet` 下线。
   财务确认前也可进入：产品进度区按 V300 闸门隐藏，时间线仍展示下单/审核/财务轨迹。
2. **通用组件**：新增 [`UtenProgressTimeline`](../02-组件库/UtenProgressTimeline.md)
   + `ProgressTimelineEvent` 模型。展示顺序由服务端排定（已发生事件时间倒序、无时间当前阶段
   置顶、PENDING 垫底），前端只渲染不重排，避免多端口径漂移。
3. **责任人取数**：优先用单据自身的 `maker_id/approver_id/finance_confirmed_by` 等列，
   统一经 `EmployeeNameResolver.nameOf` 解析为实际姓名；员工工号、账号代号不在履约
   时间线中展示。解析仍兼容 users.id 历史数据；单据没有审核时间列的
   （销售审核、计划下达、出货审核）从 `audit_log` 状态迁移记录补时间点，查不到就只显示人，
   不伪造时间。物料分析备料步骤（`SupplyProgressStep`）同步新增 `operatorName`，
   覆盖 提交人/采购人/委外人/财务审批人/收货人/生产计划下达人。
4. **不新增表**：时间线是既有业务表 + 审计日志的只读投影，无新迁移、无回写；
   权限沿用各单据既有 `*:view` 权限点与对象级归属守卫（不可见按不存在处理）。
5. **阶段事件复用、展示分级**：`ChainNoticeService`（business_outbox 可靠旁路）覆盖
   审核→财务确认→物料分析→排产→报工→完工→发货→驳回/取消/延期落点，不为时间线复制事件。
   ADR-052 在同一通知事实之上补 `source_event` 传播、priority 分级和每用户 popup ack：
   普通进度继续通知中心 + 顶部条，只有明确责任人的驳回/阻断事件增加持久居中强提醒。
   时间线与强提醒都不得用异步投递时间冒充业务发生时间。
6. **业务称谓展示**：时间线说明不得直出内部枚举代号。物料分析头状态统一展示为
   “进行中 / 部分已下达，剩余待料 / 已全部下达 / 已取消”；未知值显示“状态待确认”，
   原始状态仍保留在数据库和内部契约中供程序判断。

## 影响

- 新端点：`GET /api/sales/orders/{id}/progress-timeline`（`sales_order:view`）。
- 前端新增：`UtenProgressTimeline`、`ProgressTimelineEvent`、`SalesOrderProgressDetailPage`、
  `SalesPlanProgressPanel`；删除 `sales_plan_progress_sheet.dart`（测试同步迁移为面板测试 2/2）。
- ADR-052 增量：进度看板增加 `REJECTED` 阶段、驳回原因/人员/时间和“修改订单”入口；
  修订回草稿、重审与再次财务确认仍出现在同一订单时间线，最近一次驳回事实不因当前标志清除而消失。
- 物料分析供给进度对话框：步骤带责任人、最新在上（与订单时间线同一范式）。
- 采购/委外订货单、生产计划单等其它单据的同款进度区块可复用该组件与取数模式按需扩展。
