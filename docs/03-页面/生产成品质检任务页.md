## 一、职责

本页只处理仓库已登记送检后形成的生产 FQC inspection；V430 前既有 inspection 继续兼容。日报数量是“完工申报量”，不是合格量；FQC 决定合格放行与失败处置，但不直接增加库存或 `iqty`。每条新执行段日报明细最多生成一条 inspection，来源日报、计划行、执行段、销售分摊、仓库、逐行 `place`、货品、颜色、单位和换算率均按 UUID/交易快照冻结。

## 二、权限和对象范围

- 查看：`production_quality_inspection:view`。
- 登记决定：`production_quality_inspection:approve`，且服务端仍要求当前员工属于有效品质组织池；只有权限、不在品质池时按钮失败关闭。
- 品质池可看共享待检队列；生产岗位只可按生产计划 owner/data scope 查看与自己业务有关的质量结果。无权 UUID 返回不存在，不泄漏单号或数量。

## 三、状态和决定

| 状态 | 含义 | 下一步 |
|---|---|---|
| `PENDING` | 尚无质量决定 | 品质登记 PASS/PARTIAL/FAIL |
| `PARTIAL` | 只处理了部分申报量 | 继续决定剩余量 |
| `RESOLVED` | 全部申报量已有决定 | PASS 等仓库点收；FAIL 走恢复链 |
| `CANCELLED` | 来源日报已按顺序红冲 | 只保留历史，不得再次放行 |

```text
0 <= Σpass_qty + Σfail_qty <= reported_qty
remaining = reported_qty - Σpass_qty - Σfail_qty
```

## 四、下游与反向

- PASS/PARTIAL 的 `pass_qty` 在同一事务生成精确 FINISHED_IN 草稿并消耗 PASS release lot；仓库头与逐行 `place` 继承送检登记快照，失败则整笔回滚。
- REWORK 回退当前有效 `fqty` 贡献并生成 recovery authorization；原在制返工后按开放量补报并再次 FQC。
- SCRAP/REJECT 必须按 BOM 形成 recovery demand、reservation 和单一 DRAW，仓库实发且全部需求 `FULFILLED` 后才可补报。
- 仓库实收前，PASS、通知、角标和 FINISHED_IN 草稿均不能增加库存或 `iqty`。
- 来源日报红冲必须先处理活动入库，再释放 replacement allocation、取消派生 recovery 和 inspection；历史记录均 append-only。

## 五、幂等、分页和错误恢复

决定请求携带稳定幂等键与请求哈希：同键同体返回原决定，同键异体冲突。列表服务端分页，不得固定截断 200 条。当前页使用统一任务表、状态分段、搜索、双击详情与原子「批量全部合格」；批量任一任务状态、权限、品质组织或放行校验失败时整批回滚。决定成功后先用返回 inspection 收敛本地行，再后台刷新；刷新失败不能让旧 active 行继续可操作。页面提供加载、空态、错误重试、搜索防抖、返回即刷新，并覆盖窄屏/大字体。

本页是**办理面**，不是历史记录编辑器。PASS/PARTIAL/FAIL 及来源取消继续以追加事件保存；只读历史查询统一从品质任务中心「查询与记录 → 检测记录」进入 `/quality/inspection-records`。记录页无修改、删除或导出，不能反向绕过本页的动作权限、品质组织池、状态机和幂等校验。
