## 一、定位

给所有员工（全员可见）使用的登录后默认落地页，是 App 的"门面"，也是**全部业务功能的集散中心**。

- 解决的问题：一眼看到今日关键指标与待办；按权限聚合展示当前用户可用的全部业务模块入口。
- 产品位置：底部悬浮胶囊导航第一项，[登录页](登录页.md) 成功后默认重定向到此页。
- UI v4 变化：原「左侧边栏（expanded）/ 折叠 Rail（medium）」承载的角色分组导航全部迁入本页「功能模块区」，侧边栏取消，内容全屏宽。

### 工作台上的卡片和待办怎么筛选

工作台下面的功能卡片按部门分组摆放(行政与人力资源部、财税部、生产部、PMC运营部等)，但一张卡片显示不显示，不看你在哪个部门，只看你能不能打开它对应的页面：

- 能打开的卡片才显示；一个分组里一张你能打开的卡片都没有，整个分组就不显示。
- 你的权限由几部分合起来：人人都有的基础权限，你所在部门和兼职部门(连同它们的上级部门)配置的权限，再加上单独给你开通的权限，减去单独给你收回的权限。所以一般只看得到本部门的卡片；别的部门的卡片，你有对应权限也会出现在那个部门的分组里；本部门的卡片，权限被收回后也不显示。
- 超级管理员看得到全部分组；还没接入功能的空分组只对超级管理员显示「功能规划接入中」。

页面上方「今日概览」按当前授权的业务入口汇总指标与待办，不再额外按主部门或兼职部门隐藏。每项仍沿用对应模块的数据范围和办理条件；未读通知按发给你本人的显示。

需要某个功能却没有卡片时，见[我的权限与申请开通](我的权限与申请开通.md)。

## 五、功能点

1. 页面头：头像 + 「你好，{姓名}」+ 日期，右侧通知铃铛带未读数 Badge（`unreadNoticeCountProvider`）。**超级管理员**额外显示「切换人」chip（`isSuperAdminProvider` 且非模拟中）—— 进入限时模拟窗口后以任意员工真实视角核验权限配置；模拟中入口隐藏，改由顶部常驻横幅接管「切换/退出」。详见 [模拟身份(切换人).md](模拟身份(切换人).md)。
2. **今日概览**：首帧后请求 `GET /api/dashboard/overview`，按本人有效权限和原对象范围返回通知、生产、销售等真实非金额指标，部门名称只作展示。服务端不再查询或返回账户余额、未结应收、未结应付金额卡；财务金额分别在账户资料和钱流台账按各自权限查看。原 `dashboard:finance_sensitive:view` 已于 2026-09-27 退役(V741), 不恢复上述三张卡。指标从左向右横排展示，未读通知在最左，重要通知、执行中订单等依次排在右侧，空间不足自动换行；**重要通知**(人事序列部门发布且未读，有才出卡)点击直达 `/notice?filter=important`。
3. **待办任务**：同一聚合接口返回通知待办与已授权入口的计数卡(生产待排产、仓库领料与退料、采购任务、委外任务、访客审批、资料变更审核、报销待审批 / 待付款)；通知打开明细，其他卡片跳转真实处理页。**计数卡的数字就是对应模块卡的红徽章数**(permissions-08, ADR-108)：服务端经徽章只读端口 `WorkbenchBadgeReadPort` 查询已登记入口，入口目录、来源、有效权限及对象范围都与 `GET /api/workbench/badges` 同一套；不再额外按所属部门决定显示。某个来源出错时该卡本次不出(徽章侧保留上一次的数)，不丢弃其他首页内容，也不把加载失败伪装成零待办。工资批次待复核不再单列计数卡：提交时已给复核人推「待复核」行动通知，出现在通知待办里。待办区位于同一块合并面板内；有任务时仅展示浅底瓦片，隐藏小节头、排序说明和总数徽章，仍按紧急度和截止时间排序，各卡片保留自己的数量徽章；无任务时保留「待办任务」标题与空态提示。

     「基础资料」模块各主档查看码的并集控制）外，其余四张自助卡的权限码在权限管理页归
     「常用模块」分组（V831 起排目录最前，子类与卡片同名，见 [权限管理页.md](权限管理页.md) 与
     [ADR-168](../99-决策记录-ADR/ADR-168-常用模块权限分组.md)）：工资条 / 我的报销 / 意见箱
     默认随全员基础包发放（可在「全员基础包」页整体移出、或在「按员工」页逐人收回），
     我的访客 =「接待访客」码（V679 起部门白名单 + NON_DELEGABLE，只由超管按部门或逐人授予）。

5. **按权限点显隐**：每个模块的可见性 = 用户是否拥有 `requiredAnyPermFor(location)` 返回列表中的任一权限点（`core/router/permission_by_path.dart`，与路由守卫同一份映射，单一数据源）；映射为 null = 登录即可见；超管全量放行；整组不可见时组标题不渲染。
6. **功能分组可折叠**：每个功能分组点标题行收起/展开（`AnimatedCrossFade` + chevron 旋转），功能模块的排序和折叠状态由 `workbenchLayoutProvider` 持久化到服务端；部门分组展开时隐藏分组徽章、收起时显示，卡片徽章继续展示各任务实时数量（今日概览合并面板不参与折叠）。**2026-09-10**：组内卡片支持长按拖到另一张卡片上换位（`_ReorderableModuleGrid`，悬停即换位 + 原位半透明残影），顺序以 `itemOrders`（分组 key → 卡片 location 序列）同一 Provider 持久化；不可见卡片（权限过滤）保持原位不丢排，新卡片按代码默认顺序补尾。
7. **我的部门**：入口位于“我的”页，点进 `/profile/me/department` 查看架构树、花名册和负责人说明。该页不再配置成员权限；合法负责人到对应业务页右上角“权限设置”维护本页权限。详见 [我的页.md](我的页.md) 与 [ADR-045](../99-决策记录-ADR/ADR-045-页面内权限委派与授权来源隔离.md)。

本人生日、入职周年、新婚或新生儿庆典由 `CelebrationTodayCard` 展示，`CelebrationPopupGate` 控制每日一次的庆典弹窗；它与按有效办理权限及业务对象范围投递的审批弹窗分别处理。人力资源“任务中心”汇总转正、生日、入职周年等提醒，详见[HR任务中心](HR任务中心.md)。

- `User`：姓名、兼容 roles claim、后端合成的权限点集合（模块显隐只使用 permissions）

## 八、权限要求

- **全员可见**；功能模块区按权限点精确显隐（见第五节第 5 点）。
- 权限来源（详见 [全局机制.md §一](../05-架构/全局机制.md)）：全员基础 ∪ 部门直配权限（含上级及兼职部门）∪ 个人加授 ∪ 有效负责人委派 − 个人收回；超管全量。角色体系不再参与合成。授权版本变化使旧 access token 立即 401，普通授权变更保留有效会话并静默续期；`/auth/me` 同步后工作台按新权限重建，无需重新登录(ADR-181)。

## 九、边界情况

- 用户除全员基础外没有部门/个人权限：功能模块区只剩基础包覆盖的常用功能卡（工资条 / 我的报销 / 意见箱；基础包被整体移出时连这三张也不显示）。
- 性能档 = lite：关闭 stagger 进场动画；折叠动画仍可用（开销极小）。
- 未读通知接口失败：Badge 不显示（`valueOrNull ?? 0`），页面其余部分不受影响。
- IQC 待检通知和品质角标彼此独立：通知用于提醒并触发 `pending-count` 重拉；Outbox 送达前若
  收货单已无 `PENDING/PARTIAL` 明细则跳过过期通知，而工作台角标始终读取实时待检聚合。
- `/api/dashboard/overview` 的入口计数卡某个来源出错(非认证/授权异常)：徽章服务按 JDBC 保存点隔离该来源，
  入口标为本次没算出，概览**本次不出这张卡**, 其他指标与待办照常; 同一入口的模块卡红徽章保留上一次的数。
  下一次进工作台(或返回即刷新)自然重算，前端不再为此单独轮询。(2026-09-23 前的「正在自动恢复」占位卡、
  `dashboard_fulfillment_partition_degraded` 审计与 15 秒重试已随 permissions-08 删除。)
- 某来源对当前主体无权(其原计数端点的 `@PreAuthorize` 拒绝)：入口不出现、不出卡；与模块卡是否显示红徽章同一判定。
- 权限解析依赖故障返回的结构化 `503 SERVICE_UNAVAILABLE` 不能伪装成零待办；前端只对该安全读做有限重试，
  保留会话并显示明确的可重试错态，不显示“无权限”。
- 首页聚合故意不包裹一个共享数据库事务：徽章端口自己开只读事务，其余分区各自读取，避免已捕获的子事务异常把外层标记为 `rollback-only`。全库不可用仍走整体可重试错态；该边界不提供 Mock/旧数据兜底。

## 十、业务清空功能永久删除

工作台不再渲染系统测试区、清空卡片、确认弹窗或上次清空结果，超级管理员与本地 Debug 也没有此入口。相关仓库、待确认记录读写、API 端点和服务端清空实现全部删除。界面继续使用现有 Uten 组件和主题，相关维护默认使用 `frontend-design`。

数据库通过 V919 前向迁移删除清空函数、专用权限及历史保护中的测试清空绕过分支；既有业务数据、文件与审计不被清理。历史迁移和审计名称保留作校验与查账，旧 `business_reset_generation` 仅兼容已有草稿、会话和 AI 结果的代际隔离。登录后的通用会话重建与待办刷新继续生效。

所有服务器 Nginx 继续对旧 `/api/system-test/` 返回 404。服务器同步下架随正式发布及受控迁移执行，源码完成不代表已经更新服务器。决策与升级核验见 [ADR-192](../99-决策记录-ADR/ADR-192-业务数据清空功能永久删除.md)。
