## 已核实的关键差异

九类主档（货品、客户、供应商、账户、币种、颜色、单位、模具、仓库）仍调用 `ReportQueryKit.collectPages`。该方法每页 100，把所有 `Map` 留在列表，没有接 `ExportPageSink`；之后 `XlsxExportService.build` 仍创建完整 `ByteArrayOutputStream/toByteArray`，有密码时再走 byte[] 加密。系统设置默认且最高 100000 行，不等于内存预算或流式实现。100000 行约 1000 轮列表读取，JPA Page 的 count 和深 offset 工作量必须另验。

不能简单让 collectPages 在 sink 模式返回空 List：现有调用方用 `rows.size()` 作 payload.total，会错误变成 0。根任务/runtime_evidence 已分工统一有界 source、唯一 Specification 与原 row mapper；服务端主档任务还必须有各自真实权限域，货品归属配置开关不能强并 production，客户共享也不能套供应商。

采购任务工作台 `exportPurchase` 是单次 `maxRows+1` 的大页，随后再构造完整 Map。它不是采购报表另一个名称，必须保留 `FulfillmentWorkbenchAccessPolicy`、action 可见性及同源真实数量字段。适配公共持久任务时应复用它的筛选/投影基座，不能复制另一套 SQL 权威。

审计 activity/session 都有真实 10000 上限，仍是可增长集合。Activity 的 `AuditQueryService.export` 一次加载完整 AuditLog 实体；其 before/after JSON 和 userAgent 没有 lazy 投影，最终不导出这些列并不意味着没有从数据库取入内存。改进必须同时控制取列、实体驻留、解释器工作量和 writer，而非只改文件输出。若变化摘要确实需要少量原始差量，应明确最小字段需求，不能删除历史原文来提速。Session 以每页 20 拼全量 Map；其原 snapshotAuditId 只能保留为现有在线定位合同，不能拿最大 ID 冒充真实事务快照、忽略晚提交。

结算方式管理导出称“小字典”，但源码没有自然常量个数约束，先读取完整列表才检查配置上限。不能用今天目录小假设永久无增长，也不能 LIMIT 后丢系统角色或历史结算方式。

实际成本的单货品筛选不等于小对象：真实查询最多选择 500 个成本对象（501 检测后拒绝），但 INPUTS、OUTPUTS、REVISIONS 无子事实行查询边界。50k 的 ExportDocument 单 sheet 检查发生在全部读取、转换和摘要以后，不能防止 source 先耗尽内存。其 expectedDigest、所有输入货品读取范围、精确原始数量金额和历史 revision 必须保留；不能自动调平差异，不能仅设置“500 对象”就宣布流式。

## 自然有限对象与有限文件合同

- 完整 BOM 已有 2000 展开行、11 层的统一文件边界，超限明确拒绝。操作内父件 cache、逐对象可见性、环路和导回身份都应复用，不能换成普通平表口径。
- 冻结测算成本单的 calculator 限 3000 明细、3000 费用，paths 请求最多 5000；保留 snapshotId、sheetVersion、digest、多 sheet、部分明细和价格精度。它也不是端到端流式，仍需最坏字节/多 sheet 资源证据。
- 客户报价模板是单报价最多 500 行、最多 100 模板、原文件合计最多 100 MiB；有 RR、报价和模板版本验证，不能用通用单 sheet 重写客户版式。其有限范围不免除多副本 heap 验证。
- 采购工作台批量单据有真实 `_maxExportDocs=100`，并保持 FINANCE_APPROVED 任务阶段和服务器 print-data 再确认；前端函数仍把所有 PDF、Archive 与 ZIP 字节保存在内存。需补函数自身数目/总 bytes/历史旧单行数预算和切片/Worker，不能只靠工作台按钮。
- 工资条是单人单条加锁、本人已发布或有独立全员导出权限，保密密码、薪资密文和下载记录继续由原服务负责。当前未发现员工整表 CSV/XLSX 导出路由；不能把单工资条测试当成 HR 名册覆盖。
- 权限配置备份有 1000 用户/1000 部门/5000 归属人/16 MiB 等合法文件边界。当前先全量构造且逐用户、逐范围查询，有真实 N+1 和迟到的预算拒绝。应先做计数/字节资格和同源批读取，保留 inactive override、委派及完整配置，不截取前 1000。

## 前端打印与人事

部门花名册和架构图过去都在 500 人处直接 break，却仍显示包含下级全部人员。本轮已使用同一完整名册 source：页 100、同一部门/子树权限、ID 去重、错页/空续页/人数不符拒绝。响应转换使用 UiWorkBudget，架构图原 A4 竖版/负责人/挂职版式进入既有 PDF Worker 的独立 v2 协议，原表格 v1 兼容。没有凭空增加业务人数上限。

九类主档打印还有同类漏洞：五个独立页面（账户/币种/颜色/单位/仓库）和 MasterEntityDetailPane 的货品/客户/供应商/模具共用入口，曾只请求一次 `size:2000`，实际服务器最大 100，导致只印首 100。正迁移统一完整分页快照、冻结 query/forPrint 条件、切片格式化和读授权版本退休，实际调用方测试待回填，不能仅靠 helper 单测与搜索结论勾完。

库存全局与仓库内页另有明确前 2000 的预览路径，需与其显示合同一起核查；不能把单次 size=2000 当成服务器会返回 2000。全平台公共打印预览需监听 `readScopeRevision`，已有加载结果和 A→B→A 不得复活；未知/撤权不能只禁止按钮而保留可复制的旧纸面。

## 官网独立范围

本次全文检查官网 route/actions/components，没有发现集合 CSV/XLSX/ZIP 导出。公开资料是单件 PDF：发布资格同时检查资料及关联产品/系列，存储身份、20 MiB、300 页及 SHA 由 `document-storage` 管理。下载使用完整 readFile 和 Response Uint8Array，不能称流式；这是有限原件交付，不是 ERP 100k 任务导出的验证替代。并发原件资源仍须 B4 独立核验。

官网询盘 bridge 是签名授权的待投递批，默认 20、最高 50、稳定 createdAt/id 和独立 ACK，不是给用户的导出。禁止为了 B1 测试清询盘、重复导入或改变投递事实。官网 publication/document-storage/bridge 的现行真实 PostgreSQL 与运行证据必须单列。

## 验证出口与交接分工

100k 证据只能在明确隔离库/进程、限制 CPU/内存/并发、保存源码指纹后取得。九主档应观察 source heap 是否只保有界批次、count/facets 是否反复计算、offset 扫描量、名称与扩展列批读取，以及 writer/temp/下载的独立预算；审计和有限单据按其合法最大范围验证，100k 输入则应在昂贵取载荷前完整拒绝，不能暗中只给前 500 或 10000。

持久任务的行数、进度、取消、未知提交、恢复、实际 scope/定义 ACL 再授权、build pin、私有临时件和保存前 gate 复用根任务公共能力。旧同步路径必须在查询前持有共享有限槽直到密码处理结束；大型旧请求明确要求后台任务，小范围也要验证实际行数和失败资源释放。worker 输出不套同步 500 行合同，二者不能互相冒充。

当前 root/runtime_evidence 负责九主档服务、任务与新权限域；report agent 负责六报表/where-used 多 sheet 与共用 writer；本子任务负责 HR/打印完整 source 与公共旧同步资源保护。根任务再落实审计最小取列、实际成本 source 和单据 ZIP 的差量。所有未完成项均不得被“已经有 hard limit”覆盖。

已取得的 HR 定向证据（尚不代表最终整合）：6 文件 22 tests、共享打印 4 文件 23 tests 全过；601 原始姓名 PDF 为 12 页 A4 竖版，文本身份 0..600 各一次，首/中/末页 PNG 已查看；1800 人公共 org worker 29 页，原表格 2800 行仍为 81 页。该轮同时有根任务 IAB 活动，不是安静性能基线。后续公共完整分页提取/主档接入变更后仍需复验并锁定最终源码。
