## 一、结论（一句话）

**模具分类 = 老库 `SystemItem` 表中 `ItemclassID = 18` 的 65 个节点（全是扁平根，无嵌套）；模具主档 = `B_Mould`（1605 行，12 字段），通过 `B_Mould.ParentID → SystemItem.ItemID`（ItemclassID=18）把每条模具挂到某个系列下。**

> ⚠️ `SystemItem` 是一张**万能分类树表**，混存多种基础分类，迁移时必须用 `ItemclassID` 过滤（货品=1、模具=18、部门=5…），否则会把无关数据一起迁过来。

## 二、老库表结构

### 2.1 `SystemItem`（ItemclassID=18，模具系列分类，65 行）

字段同货品分类（见 [02](02-货品分类-老库溯源.md) §2.1）。ItemclassID=18 的特点：

- **65 个节点全是 `ParentID=0` 的扁平根**（无父子嵌套、无孤儿）。
- `Number`（编码）有重复：`118`（118系列模具 / 西力118系列模具）、`Q120`（Q120系列模具 / 某某模具）各两条。
- `Level` 不可信（同货品），迁移按 parent 链重算（这里全是根 → level 0）。

### 2.2 `B_Mould`（模具主档，1605 行，12 字段）

| 字段 | 类型 | 含义（实测） | 新库列 |
|---|---|---|---|
| `ID` | int | **主键** | `legacy_id` |
| `ParentID` | int | → `SystemItem.ItemID`（ItemclassID=18，所属系列） | `category_id` |
| `MouldName` | varchar(50) | 模具名称（如「C20一位支架面/二位支架面」） | `name` |
| `Number` | varchar(50) | 模具编号（如 `C20-001【B3-12】`） | `code` |
| `Mnumber` | varchar(250) | 备用编号 | `mnumber` |
| `QTY` | varchar(150) | 数量（字符串，如 `1+1`） | `qty` |
| `TQTY` | decimal(9) | 总数量 | `tqty` |
| `MStatus` | varchar(50) | ⚠️ **实为「制造年月」**（如 `2018年7月`，324 条为空） | `mstatus` |
| `Status` | varchar(10) | **生命周期**：`使用`(1246) / `禁用`(359) | `status` |
| `Place` | varchar(250) | 车间/位置（`注塑车间` 占 1523） | `place` |
| `summary` | varchar(250) | ⚠️ **实为「保管人」**人名（如 `李海湛`，304 条为空） | `keeper` |
| `Remark` | varchar(250) | 备注 | `remark` |

> ⚠️ **字段名误导**（老库起名随意，新库按真实语义重命名）：
> - `MStatus` 不是状态，是**制造年月**日期串；
> - `Status` 才是生命周期（**使用/禁用**，注意不是「报废」——早期调研因 sqlcmd GBK 乱码曾误读为「报废」，PowerShell 干净查询 + 迁移后对账均证实是「禁用」）；
> - `summary` 不是摘要，是**保管人**人名。

## 三、模具系列分类构成（ItemclassID = 18，对应业务描述）

65 个系列可归为三大类，与用户描述**逐一吻合**：

### 3.1 自有产品系列模具（主体）

| 命名方式 | 系列 |
|---|---|
| 数字编号 | `118`、`1M`、`5M`、`6M`、`7M`、`80`、`H50`、`C20`、`D86` |
| 字母系列 | `A5`、`A8`、`V1`~`V9`（V1/V3/V4/V5/V7.0/V8/V9.1）、`UA`~`UW`（UA/UB/UC118/UD118/UD120/UE/UF/UG/UJ/UK/UW）、`W118`/`W20`/`W50`/`W86`、`Z5`/`Z6`/`Z9` |
| 主流产品 | `Q3-K`、`Q7`、`Q7-BJ`、`Q9`、`Q120` |
| V5 细分 | `V5`、`V5.1/V6.1`（连体床头柜系列）、`V5微点`（V5 微点系列）、`V7微点` |

> 与用户描述完全一致：V5 系列下细分出「连体床头柜系列」「V5 微点系列」等专项模具——但老库里这些是**独立的扁平根**（V5、V5.1/V6.1、V5微点 各自一条），并非 V5 的子节点。迁移按老库结构忠实地平铺为 65 个根，不做人工嵌套（保证 legacy_id 可回溯）。

### 3.2 轨道产品线（与货品资料的轨道分类一一对应）

| 编码 | 名称 | 对应货品分类 |
|---|---|---|
| `GD` | 轨道 | 货品 `GD01` 轨道 |
| `GD1` | 轨道3.0 | （货品轨道分类下的 3.0 子类） |

### 3.3 其他（品牌/客户/配件系列）

`OEM`、`LWT`(立维腾)、`LYC`(雷士)、`品帅`、`通士达`、`金牌`、`业强`、`七彩灯`、`五角星`、`沙特盒`、`宇微点`、`45A`(开关)、`68`(欧式明装)、`DC`(地脚插)、`GQ`(钢琴开关)、`BJ小按钮`、`S1/S2`(开关) 等。

## 四、数据质量风险（迁移已处理）

| 风险 | 数量/说明 | 处理策略（已落地） |
|---|---|---|
| **19 条悬空模具** | `B_Mould.ParentID` 指向已删/不存在的 SystemItem（如 Q5 系列，老库无对应 ItemclassID=18 分类，多标注「封存」） | `category_id` 置 NULL；前端「全部模具」视图可见 |
| `Status` 非「报废」 | 实为 `使用`(1246) / `禁用`(359) | 按原值迁，新库列名 `status`，前端状态徽标 使用=绿/禁用=灰 |
| `MStatus`/`summary` 语义误导 | MStatus=制造年月、summary=保管人 | 新库列名按真实语义：`mstatus`/`keeper` |
| `Number` 编码重复 | 118、Q120 等多条 | 新库 `code` 不设 UNIQUE，定位用 `id`/`legacy_id` |
| `SystemItem` 混存多类 | 7 种 ItemclassID | 迁移严格 `WHERE ItemclassID = 18` |
| 文本 GBK 编码 | 老库 `Chinese_PRC_CI_AS` | 导出走 PowerShell + .NET SqlClient 原生解码 → UTF-8 CSV（见 [05](05-模具资料-新库与迁移.md) §导出） |

## 五、字段映射（SystemItem → mould_categories / B_Mould → moulds）

### 5.1 分类（SystemItem ItemclassID=18 → mould_categories）

| 老库 | 新库 | 转换 |
|---|---|---|
| `ItemID` | `legacy_id` (UNIQUE INT) | 保留，溯源+重跑幂等 |
| `Number` | `code` | 直接映射；不唯一 |
| `Name` | `name` | 直接映射 |
| `ParentID`(=0) | `parent_id = NULL` | 65 个全是根 |
| （递归重算） | `level` | 全 0（扁平根） |
| （触发器维护） | `path` | `/code/` |

### 5.2 主档（B_Mould → moulds）

见 §2.2 表格「新库列」一栏。`category_id` 由 `ParentID` 反查 `mould_categories.legacy_id` 得到；19 条悬空 → NULL。
