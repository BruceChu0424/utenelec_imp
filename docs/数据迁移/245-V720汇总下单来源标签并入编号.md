# V720 汇总下单来源标签并入编号口径

## 背景

2026-09-25 V719 上线后用户实机反馈：采购员/委外的「计划号」没变。排查发现其
开发库的采购/委外申请全部走**同料合并汇总通道**
（`AggregateMaterialOrderWriteService`，V712 起的「同料多来源汇总」），
该通道下单时写的来源标签是「物料分析汇总 <日期>」——V719 只回写了经典通道
的「计划前物料分析 <日期>」，两条通道漏了一条。

## 改动（不加表）

1. **服务端**：`AggregateMaterialOrderWriteService.createExternal` 的来源
   标签改为批次所属分析的 `analysis_no`（汇总批次锚定单一分析
   `preplan_aggregate_batches.analysis_id`，文档级映射无歧义）；无编号的
   夹具行回退旧「物料分析汇总 <日期>」。
2. **存量回写**：与 V719 ④ 同一条谱系链（`preplan_supply_actions`
   外部单据映射 + V463 订货行来源分配表），把能精确回溯的
   「物料分析汇总 <日期>」标签（申请头/明细、订货单头/明细、收货明细，
   采购与委外两侧）回写成 WL 编号；多来源合并且指向不同分析的行、
   无法回溯的行保留原日期标签。备注前缀同款回写。
