# 基础资料文件导入差异核对

日期：2026-10-22。设计技能使用 `frontend-design`，复用 Uten 主题、表格、返回按钮和悬浮操作组。工作目录原有大量并行修改，本次仅在导入链路上增量修改，未提交或部署。

## 规则

| 情况 | 处理 |
|---|---|
| 系统无对应货品 | 正常新增，沿用已有分类、颜色、单位创建与原子事务规则 |
| 编号或 UUID 唯一命中 | 比较文件实际提供的非空字段 |
| 无编号且同分类同名唯一 | 作为已有货品核对；名称不作为跨分类关系键 |
| 编号/UUID 矛盾，同名歧义，重复身份行 | 阻止提交，按行提示修改 |
| 原值为空、导入值有值 | 自动补齐，在核对页标明；取消时仍然零写 |
| 原值与导入值相同 | 保留，无重复新增或替换 |
| 原值与导入值不同且都非空 | 进入整页差异表，仅勾选行应用非空冲突 |
| 导入值为空或列未提供 | 保留原值 |
| 全部忽略 | 跳过冲突，继续新增与补齐 |
| 返回取消 | 不发送提交请求 |
| 检测后资料变化 | 服务端拒绝；保留文件，重新检测 |
| 大量选择 | 文件和选择放在有总量限制的 JSON body，保留旧 raw API |
| 多文件选择或拖入 | 排队处理；先完成当前文件，再按最新状态检测下一份 |
| 后续文件取消或失败 | 停在当前文件，保留成功文件结果；不重写成功文件 |

货品更新仍执行对象写范围、编辑/状态/售价权限、数量单位锁和分类编号领域规则；未导入的关系与其它页签字段保留。导入历史和批次撤回须同时保留原货品 UUID，不能把更新记录误当新增货品删除。

BOM 仅核对组件自身字段，不新增客户型号列、不更新货品客户型号。默认 MERGE 按真实父件和组件 UUID 合并，保留文件外边；新增组件必须已经存在于货品主档。原样重导或忽略全部冲突不应触发组件写入、学习转换或审计变化；真实使用数量、学习值、权限和期间料计量约束继续由原领域服务执行。完整替换和追加保留既有显式模式。

基础资料现有文件导入入口范围为货品、BOM 组件和成本工作簿。前两者使用共享全页差异表；成本工作簿的逐行审核映射移到完整页面，保留既有成本草稿业务语义。

多文件以单文件事务为边界，不能把成功多份与失败一份描述为整批回滚。货品/BOM 支持多选与多文件拖入，按序读取每文件最多 10 MiB；成本工作簿多选后按序流式读取每文件最多 15 MiB，保留 XLS 支持，服务器继续独立拒绝加密和异常文件。成本多文件依次采用至同一草稿，取消或后续出错时保留已采用内容，仍需按原业务保存成本单。

包含已删除货品恢复的后续文件，即使没有普通字段冲突，也保留该文件的独立确认，不因前一文件成功而自动恢复旧资料。

## 追加：货品编号与身份

用户确认允许复用从未被业务使用过的已删除货品编号。`goods.code` 是可显示和编辑的业务值，实际关系使用 `goods.id` UUID。新货品取得新 UUID 和新的内部身份序号，旧货品保留原 UUID、删除状态及历史证据；不能通过恢复旧 UUID 冒充新建，或清掉原预约记录来绕过全局唯一。

旧系统曾支持审计清理，缺少完整生命周期证据的旧货品不能仅凭“现在没有引用”判断从未使用。因此无完整证据的旧号继续保留，不保证截图中迁移前已删的 501–520 自动回收。可证明的未使用新货品删除后，才按当前分类选择首个可用编号；历史引用、BOM、库存、订单等使用证据必须跨删除、归档和业务清空保留。编号被新 UUID 使用后，旧货品恢复和旧文件按编号自动匹配均须阻止误关联。

已单独验证源分类前缀 `2008935` 的历史显示号排到 `…520`、内部身份序号为 520 时，在目标分类继承 `2881342` 前缀的新建显示号仍为 `288134201`、`288134202`，内部身份序号继续 521、522。该验证并未释放旧编号。
