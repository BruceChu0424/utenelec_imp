# V629 零料任务三路线与路线记忆

- 迁移：`V629__workshop_zero_material_routes_and_route_memory.sql`。
- 决策：[ADR-096](../99-决策记录-ADR/ADR-096-车间任务三条路线通用与路线记忆批量设路线.md)。
- 依赖：V249 零料任务生来 READY；V561 分批证明与 `execution_split_shape`；V618 `fn_can_split_execution_batch`；
  V628 逐种物料事实函数。

只换函数、约束与索引，不加表、不加列、不改任何数据行，重放由 Flyway 版本保证。

| 对象 | 变化 |
| --- | --- |
| `fn_can_split_execution_batch(uuid)` | 以 `pg_get_functiondef` 锚点替换：源状态条件 `WAITING` → `WAITING OR (READY AND material_requirement_mode='ZERO_MATERIAL')`；锚点不在则迁移失败 |
| `fn_guard_execution_split_history()` | 同一条件的锚点替换(`source.` 前缀)；其余守恒尺(无预留 / 无领料 / 无供给绑定 / 未拆过 / 分析来源 / 自动提升)不变 |
| `execution_split_shape` CHECK | 重建：子任务快照允许空数组，但只对 `material_requirement_mode='ZERO_MATERIAL'`；有料子任务仍要求非空 |
| `idx_execution_route_confirmed_by_actor` 新增 | `production_execution_segment_events(created_by, created_at DESC) WHERE action='ROUTE_CONFIRMED'`，操作者路线记忆每页一次点查 |
| `fn_execution_segment_material_summary(uuid)` | 重建(签名变化)：`short_direct_count` → `short_make_count`，按需求 `supply_route='MAKE'` 统计，不再看 `direct_supply` |
| `fn_execution_segment_material_facts(uuid)` | 重建：状态 `SHORT_DIRECT` → `SHORT_MAKE`，同口径 |

存量影响：既有分批子任务的快照全部非空，约束替换对现有行是纯放宽；既有零料 READY 任务升级后可拆批、可改持续，
其状态与事实不变；有料任务的可拆判定结论不变(WAITING 分支原样)。汇总函数签名变化由本批 Java 同步
(`ProductionExecutionWorkbenchService`、`ChainNoticeService`、`ProductionExecutionBatchService` 零料分批路径)。

发布前应在恢复副本验证：零料 READY 任务改分批得两个 ZERO_MATERIAL READY 子任务、快照 `[]`、无领料单；
有料任务已备料改分批仍 409；混合供料任务的 `short_make_count` 与自制子件需求数一致；
`EXPLAIN` 操作者记忆查询走部分索引。

本地开发库(uten_imp，V628 已应用)在回滚事务内完整试跑：两处锚点命中、约束重建、索引建立、两函数签名替换均成功，
回滚后库无变化。

回退：不能撤销迁移或改 Flyway 历史；若异常，前向再发一版把两处条件收回 `WAITING` 并恢复非空快照约束即可，
数据无需修补(本迁移未改任何行；零料子任务如已产生，收回前先处理完)。
