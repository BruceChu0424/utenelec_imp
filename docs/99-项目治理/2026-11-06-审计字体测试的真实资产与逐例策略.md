## 已证首因

Flutter `c9a6c484230f8b5e408ec57be1ef71dee1e77020` Web tester 环境有两项原合同：`ignorePlatformMessages=true` 时 engine 的 `_sendPlatformMessage` 直接返回而不回调，Web binding 的 `mockFlutterAssets` 又是 noop；因此原 helper 通过 `rootBundle.load` 等待 `flutter/assets` 会永久挂起。与此同时，`forceTestFonts=true` 会把所有非测试字体强制映射为 `FlutterTest`，即使原 `FontLoader` 已装入真实字体。

本机 Web test server 还没有 `unit_test_assets` HTTP 路由。旧 FontManifest/TTF请求404与原10min超时均保留；临时隔离v3工具已验证三个真实资源HTTP200且SHA256与当前bundle一致：FontManifest369字节、NotoSansSCFull17,772,300字节、MaterialIcons1,645,184字节。此工具/正式CI路由由独立受控bootstrap维护，不能以本机v3通过代替Linux CI。

## 唯一入口与平台差异

- Native 保留原 `rootBundle` 的真实测试bundle通道，不变更同步/异步错误或字体字节。
- Web 只按 `ui_web.assetManager.getAssetUrl` 的原URL读取实际HTTP字节，非成功状态明确失败；不造manifest、字体、空结果或兼容数据。
- 每次显式加载前，Web按该例当前 `TestEnvironment` 激活真实字体，仅关闭强制测试字体；原平台消息、禁fallback、semantics和URL策略全部保留。每例tearDown恢复原始环境对象，不全局开启平台消息。当前没有跨测试加载缓存，也不在环境激活前提前返回。
- 现有调用方继续经同一入口，无局部opt-out；完整调用方清单见 `evidence/2026-11-06-audit-font-callers.json`。增加或修改这里不代表所有历史截图已重跑或完成产品验收。Win7/WPF候选状态没有改变。
