# V623 仓库库位主档关系与精确货架维度

## 主档、关系与个人设置的边界

共享业务默认值需要绑定其实际业务身份，不应依赖某人上次打开或填过的单据。单一货品属性直接放货品主档；同一货品在不同仓、不同颜色有不同位置，必须保留 `warehouse_goods_place_preferences` 作为仓库×货品×颜色主档关系。该表不承载库存数量，也不取代历史登记快照。名称中的 preferences 是兼容名称，不代表另一套从旧单据实时推导的真值。

| 运行数据或接口 | 当前事实源与保留理由 |
|---|---|
| 供应方式 | `goods.source_type`；确认路线同事务回写，已确认分析独立保留 |
| 默认供应商、采购/委外价格 | `goods`；V620 价格保留供应商/颜色/单位/币种/税率，维度匹配才能预填 |
| 客户销售条款 | `clients` 默认结账方式、发运策略、币种；`last-terms` 只是兼容接口名 |
| 供应商条款 | `suppliers` 默认结账方式、币种、税率；不从历史订单回退 |
| 常用生产车间/负责人 | `goods.owning_workshop_department_id/owning_responsible_employee_id`；V192旧表已删除 |
| 任务开工策略 `FULL_KIT/BATCH/CONTINUOUS` | 属于当前执行任务，保留本任务已确认值；未确认时按当前资格给明确的整批齐料默认或由用户选择。删除跨任务历史预选，不写入货品属性，也不让撤销任务影响下一张单 |
| 常用存放仓 | `goods.owning_warehouse_id`；正常入库学习，采购到货/成品登记只读该值；DTO `lastReceiptWarehouseId/lastWarehouseId` 是兼容名，不再扫货品收货历史 |
| 仓库默认库位 | 仓库×货品×颜色关系优先，缺项才用 `goods.stock_place` 的一般建议；NULL色保持独立 |
| `measurement_capture_profiles` | 货品×业务操作类别的计量录入策略；证据与人工决定事件单独保留，不能塞成一个货品字段，也不是实际数量账 |
| `user_preferences` | 列宽、表头、报表筛选、看板排序、工作台布局、物料分析选仓范围和个人上次选仓；不保存跨货品通用库位 |
| 系统测试 `business-data/last-result` | 最近操作回执，不是录单默认值，保留审计结果语义 |
| 单据快照、登记/反向、计量证据/决定事件 | 交易与审计事实，保留来源、时间及反向关系；不因修改默认值覆盖 |

采购到货预填保留来源主仓/计划归属范围约束；所有默认落仓必须是未删、启用、参与核算的正常运营叶仓。失效或跨来源范围的主档值不回退旧货品收货历史。个人 `last-warehouse` 仅是当前用户最近成功登记的操作上下文，V623给 created_by/created_at/id 增加复合索引，不替代货品主档。

实际入库/出库仓、库存颜色及历史数量仍来自单据和事实账。个人选仓仅是尚未选择时的操作上下文，必须通过当前仓库可用性验证，不能覆盖单据明确指定的来源或用户值。

## V623 数据处理

1. 只从 `user_preferences` 的 `warehouse.arrivalFill` 对象中删除无业务身份的 `stockPlace` 键；保留 `warehouseId` 与其他设置。标量旧值保持，不做不安全类型推断。
2. 产成品库位建议删除逐行历史登记扫描，只读精确主档关系与货品一般建议；采购/委外到货与成品登记的默认仓也删除逐行收货历史推断，共用 `WarehouseMasterDefaultsSql` 当前主档资格规则。采购到货初值按已选默认仓匹配库位关系，换仓时清除仍未被人工修改的旧自动库位，避免带错位置。
3. 对缺少关系的旧数据，一次性按真实仓库/货品/颜色识别最近有效登记。先确定最近一批，再判断该批是否所有行都有且仅有一个库位；不能因最新一批存在歧义而回退到更旧批次。
4. 只有货品一般库位为空，且货品更新时间不晚于来源登记时才允许回填，保护明确主档值和较新清空。已存在关系一律 `ON CONFLICT DO NOTHING`，不覆盖任何现有设置。
5. 排除已撤回登记及撤回行。来源登记 UUID、时间、创建用户均保留；选择人取该创建用户关联员工，不能误用被指定的收货人，身份不足不推断。
6. 不改旧迁移、不改库存、单据金额和交易快照。关系仍带原有行审计与来源约束；业务清空时随其来源的既有清理策略不变。

## 货架清单、打印与导出

每条真实行对应仓库×货品×颜色。余额按该精确维度汇总，库位仅为主档存放建议，**不是库位层的实物盘点数量**。没有实际库存或关系维度的货品可保留一般建议行，仓库为 NULL、数量为 0。无色库存不继承货品主颜色。

页面、Excel 增加实际仓库；行身份包含仓库/货品/颜色。多仓不能拼成同一货架图；单仓图直接从当前精确行集推导，不再套全仓聚合的层数/位数。打印按实际仓库+库行分组，屏幕与纸面都明确数量口径。旧 layout 读取接口保留兼容，现役页面不再请求它，减少一次重复全范围聚合。

## 并发与验证入口

共享 `PostgresUuidOrder` 按 UUID 高低64位无符号比较，与 PostgreSQL `ORDER BY uuid` 一致。主档批量回写先按该顺序锁全批，不能按勾选顺序或 Java UUID 的有符号自然排序持锁。库存写入仍遵既有商业来源/库存/仓库/分析前缀，主档归属写锁放在该前缀之后；不得把新锁提前插入既有履约阶段。

- `WarehousePlaceMasterRelationsMigrationPostgresTest`：非空库、颜色/仓库独立、NULL色、歧义、撤回、较新主档/清空、已有关系、操作者/收货人分离、JSON偏好键退役和幂等。
- `ShelfLabelQueryPostgresTest`：真实 PostgreSQL 查询，同货多仓多色、NULL色、不同建议库位、精确数量、无库存关系行与过滤布局。
- `GoodsOwningWarehouseWritePostgresTest`、`ProcurementMasterDefaultsSyncPostgresTest`：PG UUID对照与逆序跨命令并发。
- Flutter 到货登记、货架清单与独立维度回归：旧全局库位不再带入，实际仓/颜色身份、货架图和打印范围一致。

测试结果及部署事实由整体验收记录维护；测试入口存在不等于目标库已迁移或岗位验收已完成。
