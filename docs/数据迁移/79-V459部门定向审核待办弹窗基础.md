# 迁移说明 79：V459 部门定向审核待办弹窗基础

> 状态：共享源码候选（2026-09-02）。方案权威 = [部门定向审核待办弹窗-方案与执行计划](../01-规划/部门定向审核待办弹窗-方案与执行计划.md)。

## 内容

V459 一次打包「部门定向审核待办弹窗」的数据层基础，四部分：

1. **兼职部门表 `employee_secondary_departments`**（PRESERVE）
   - `UNIQUE (employee_id, department_id)`，代理 id 主键；`started_on`/`note` 仅展示审计。
   - 触发器三件套：
     - `fn_validate_secondary_department_not_primary`：兼职≠主部门（应用层校验的库级兜底）；
     - `fn_bump_employee_secondary_departments_auth_version`（V135 机制）：兼职增删改即时 bump 该员工 `users.auth_version`，旧 staff access token 下一请求 401——兼职是单人粒度授权，走 per-user version 而非全局 epoch；
     - `fn_audit()`：审计中心可查。
   - 权限合成语义（应用层 `PermissionResolver` 实现，见 P2）：有效权限 = 全员基础 ∪ 主部门链 ∪ **各兼职部门链** ∪ 个人加授 − 个人收回。表默认空 = 零行为变化。
2. **notices 聚合定位与办结撤回**：新增 `aggregate_kind`/`aggregate_id`/`resolved_at`/`resolved_reason` 四列（全可空）+ `notices_aggregate_shape_chk`（kind/id 同空同非空）+ 部分索引 `idx_notices_pending_aggregate (aggregate_kind, aggregate_id) WHERE resolved_at IS NULL`。
   - **历史行为全 NULL = 永不撤回**，走既有已读流程——旧数据零行为变化，无需回填。
   - 审核完成落点按 (kind, id) 批量 `resolved_at = now()`：全部接收人的弹卡流停止展示，通知中心灰显「已办结」（保留审计价值）。
3. **`notice_user_states.snoozed_until`**：「稍后再看」的服务端语义——未到期不出弹卡流（通知中心仍可见），到点未办结下次到达重弹；跨设备一致。
4. **权限码 `review_inbox:view`**（人事行政/通知，sort_order 613，VIEW，零默认 grant）+ 权限面 `reviews.inbox`（surface 110→111）——「我的待审收件台」聚合页的守卫码；页面内容按各业务域「部门(主/兼职)×职责权限码」资格过滤，本码只控页面可达。

## 不变式

- 前向迁移，不改任何已应用字节；`notices`/`notice_user_states` 仅加列，无 UPDATE/DELETE 历史行。
- 零默认 grant：新码需按部门矩阵（`department_permissions`）或个人覆盖显式授予。
- reset 白名单：版本对增至 V459/421；`employee_secondary_departments` 入 PRESERVE（95→96 张），CLEAR 维持 222 张。
