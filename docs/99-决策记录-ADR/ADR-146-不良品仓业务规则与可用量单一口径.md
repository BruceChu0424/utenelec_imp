# ADR-146 不良品仓业务规则与可用量单一口径

> 2026-10-05 与 [ADR-143](ADR-143-委外按工序领直属物料与分批回厂.md) 合并注记：委外前置自制(含它的目标仓校验)与委外备料全局预留 `SubcontractMaterialPlanService.globalAvailableBase` 随 ADR-143 删除，下文提到它们的条目只代表合并前。委外按工序领料里同一口径落在：领料逐仓可动用量 `fn_subcontract_draw_line_stock` 的公共可用部分与精确专属批次 `fn_subcontract_component_entitled_lots` 的批次所在仓都只认 `fn_warehouse_counts_as_usable`(V801 重定义/锚点替换 V798 的两个函数)，领料提交的锁发现、领料草稿占用库存前的 `reserveDraft` 发出仓校验用同一个函数——候选仓 = 锁住的仓 = 允许占用的仓，系统分出来的仓提交时不会被 409(停用叶仓的既有库存按 V540 仍可动用)。「新选一个仓必须启用」只在有人换仓时判定：仓库拣货改发出仓走 `require(原仓, 新仓, "发出仓库", GOOD_OUT)`，沿用原仓不要求仍启用。委外单一子件 T4 改为「物料只在不良品仓时没有可领，普通调拨不能搬回，复判转回后才可领」。

- 日期：2026-10-04。
- 状态：已接受(本地源码实现，V801；8085 克隆库真实接口切非超管账号、Testcontainers 守卫与矩阵契约测试、端到端测试与 Flutter 组件测试验证)。
- 取代/废止：[ADR-075](ADR-075-合格来源跟随实际入库仓与车间通知.md) 第 2 条「仓库名称或仓库"不良仓"标记不改变已通过验收的入库事实」(合格来源在不良品仓也算可用)；V535 `fn_guard_qualified_origin_reservation_identity` 的「合格来源可在不良品仓预留」分支；[ADR-101](ADR-101-委外单一子层级按到货解锁与容差自动结案.md)/[ADR-103](ADR-103-委外两条路线同位锁定与单一子件按到货解锁.md) 里「子件在不良品仓时调拨进作业叶仓即放行」改为「经不良复判转回良品仓后放行」；即时库存「含不良品仓」默认开([32-即时库存](../数据迁移/32-即时库存.md))改为默认关。
- 相关：[ADR-145](ADR-145-仓库主档单主仓与禁用不可选.md)(单主仓形态，本 ADR 与它同批落地)、[ADR-090](ADR-090-到货先入库后质检.md)(IQC/FQC 判不合格不入账，本次不变)、[ADR-131](ADR-131-车间整批领料与盘点计耗.md)(内料仓发料来源)。
- 用户问题(2026-10-04)：「不良品仓平时不能当普通仓用：好的货不能放进去，领料、委外发料、出货都不能从里面拿，物料分析和各种可用量都不能算它；不良品只能判了不良才转进去，出去只能报废、退供应商、复判合格转回或者盘点。」

## 1. 事实(调查与复现，克隆库 + 8085)

- 「不良品仓」只是 V81 按名称一次性回填的布尔标签，仓库资料不能维护、字典不下发(ADR-145 已补上维护与下发)，没有任何业务语义。
- 复现：「其它入库」把良品直接入成品不良品仓 C0401(200)；调拨从 C0401 调回包材仓(200, 没有任何品质处置)；销售可预留量(`StockReservationRepository.globalAvailableBase`)与 MRP 账面都随不良品仓入库同步增加；入库自动学习把货品所属仓学成不良品仓，之后到货登记、产成品登记的默认仓都变成不良品仓。
- 全局可用量至少有 6 份拷贝(销售下单占用、委外备料、销售出货、仓库销售出库、客户零星发货、批量出货分配)，只有批量出货分配排除了不良品仓；它们同时还把车间内料仓、不记账仓、主仓的数量算了进去。
- 物料分析、齐套的「合格专属来源」按 ADR-075 第 2 条在不良品仓里也算可用——这是当年测试数据把合格料入进了「原材料不良仓」，设计为了迁就这条数据定下的例外。
- 仓库收敛成单主仓(ADR-145)后，002/C0401 也成了 001 的子仓：所有只靠「同一主仓」隔离不良数量的地方(物料分析行选择、齐套可分配、预排专属来源、自动齐套核对、预算读取)都会把不良数量漏进来，所以两件事必须同批落地。

## 2. 决定

### 2.1 仓库用途是一等属性，选仓只有一个判定点

- 仓库分良品仓 / 不良品仓(`warehouses.is_defective`，仓库资料维护，ADR-145 守住「有库存时不能改用途」；改成不良品仓与停用、改不核算是同一组「退出新选」前置条件 `fn_warehouse_selection_exit_blockers`：货品归属、没结束的预留、内料仓开通与来源仓)。
- 服务端选仓只有一个入口：`WarehouseScopeService.require(仓, 名称, 用途)`(编辑单据沿用原仓用 `require(原仓, 新仓, 名称, 用途)`，历史身份不要求仍启用但仓库用途照样核对)；规则只写在 `WarehouseUsePolicy` 一处。旧的 `requireActiveLeafWarehouse / requireNewLeafSelection / requireLeafWarehouse` 与无人调用的 `operationalLeafIds` 删除，30 多个调用点逐个标用途。
- 用途 `WarehouseUse`(放在 `application.port`，跨模块共用词汇)：

| 用途 | 场景 | 良品仓 | 不良品仓 |
|---|---|---|---|
| GOOD_IN | 采购/IQC 上架/先入库后质检/委外回厂/产成品登记与点收/报工入仓/其它入库/余料退库/委外材料退回/退货表头与良品释放/委外前置自制目标/货品所属仓库 | 可 | 拒 |
| GOOD_OUT | 生产领料/内料仓发料来源/委外发料/销售与客户发货/产成品出仓 | 可 | 拒 |
| DEFECTIVE_IN | 「转不良品仓」的调入仓 | 拒 | 可 |
| DEFECTIVE_OUT | 「不良复判转回」的调出仓 | 拒 | 可 |
| DISPOSAL_OUT | 报废/其它出库/采购退货/委外成品退回 | 可 | 可 |
| TRANSFER | 普通调拨两端(另要求两端同类) | 可 | 可 |
| COUNT | 盘点、授权余额调整 | 可 | 可 |

  查询(看库存/流水/货架)不做服务端选仓校验，只存在于前端用途枚举。
- 数据库同口径：`fn_warehouse_is_good_stock_leaf`(ADR-145 已有，新单可选良品子仓)、`fn_warehouse_is_defective_leaf`(新单可选不良品子仓)、`fn_warehouse_counts_as_usable`(计入可用量的仓)。到货上架、IQC 入库、先入库后质检、产成品先入库登记、销售出库拣货仓与行仓、余料收料确认、内料仓发料来源这 7 个既有数据库守卫里的「启用记账叶仓」统一换成良品子仓(V618 余料收料从此与 V619 的「只能良品仓」对齐，不会再前段通过、后段报英文 23514)。
- 仓库字典每行再下发 `selectableDefective`(= `fn_warehouse_is_defective_leaf`)，与 `selectableForNew` 一起成为前端唯一的可选依据。

### 2.2 出入库类别矩阵(库存内核 + 数据库守卫，同一张表)

每笔流水能落在哪类仓只看流水类型；方向不区分——红冲按原流水反向记同一类型，「允许落在哪类仓」对正向和红冲天然一致，红冲永远不会被卡住。

| 流水类型 | 良品仓 | 不良品仓 |
|---|---|---|
| 2 采购退货、9 盘盈、10 盘亏、12 其它出库/报废、18 委外成品退回 | 可 | 可 |
| 7/8 调拨(来自仓库调拨单) | 按调拨类型：普通调拨两端同类；转不良品仓 = 良品 -> 不良品；不良复判转回 = 不良品 -> 良品；流水的仓必须是单据上的两端之一 | 同左 |
| 7/8 其它来源(车间余料直送退回等) | 可 | 拒 |
| 其余一切(采购入库、销售出入、领退料、其它入库、产成品进出、委外发料/退回/进仓/损耗、销售其它出库、内料仓盘点) | 可 | 拒 |

- Java：`WarehouseClassMovementRule`，`StockService.recordMovementInternal` 过账前用它给出中文原因(「「成品不良品仓」是不良品仓, 其它入库不能进出不良品仓; 请改选良品仓, 判为不良的货请用「转不良品仓」」)。
- 数据库：`fn_stock_movement_class_violation` + `stock_movements` BEFORE INSERT 守卫 `fn_guard_stock_movement_warehouse_class`(23514，中文原样回显为 422)。契约测试逐格(25 种类型 x 仓类 x 调拨类型 x 两端 x 端点归属)比对两边结果与文案。
- 老库历史导入会话(`app.legacy_import = 'on'`，只有迁移脚本设置)照搬老系统已经发生的流水，不按新规则拦。
- 不良品仓不参与可用量：上面没有预留、安全库存只管良品，所以从不良品仓出库只守非负底线。
- 「转不良品仓」的调出一侧与盘亏一样是在记录事实(这些货已经判为不良，不再是良品)：只守非负底线，不被本仓预留、全局预留和安全库存挡住。2026-10-05 审查实测：本仓 100 件全被生产领料预留占着时，判出 3 件不良却转不出去(409「可动用库存不足」)，不良品只能继续算作可用——这比预留暂时缺实物更糟。转走后已经没有实物支撑的预留由办理接口逐条列出(见 §2.3)，与盘亏之后同一种处理：领料/出货时按实物缺口暴露，计划员重新备料。

### 2.3 两条专门通道

- 都是仓库调拨单的一种调拨类型(`stock_documents.transfer_kind`：NORMAL / TO_DEFECTIVE / DEFECT_RELEASE)，必须写原因(`defect_reason`，1-500 字)，审核后类型与原因不可改(数据库守卫)。
- 流水类型沿用调拨 7/8：估值(调出进在途、调入按原调出成本恢复)、重量账(调入沿用调出的重量与来历)、报表分类原样适用；用途由单据的调拨类型区分，守卫按单据判定。没有另开流水类型，免得估值、重量、报表三处各补一套映射。
- 独立权限：`stock:defective_transfer`「转不良品仓」默认给能审核仓库单据的部门(仓储部)；`stock:defective_release`「不良复判转回」默认给品质管理部(下级部门继承)。
- 办理方式：`POST /api/stock/docs/defective-moves` 一次建单并过账(判定与执行是同一个品质/仓库决定)，只需该通道的独立权限，不需要通用仓库单据新增/审核权限；返回 `{document, warnings}`：生成的调拨单 + 「转不良品仓」后已经没有实物支撑的预留提醒(本仓指定本仓的预留超过剩余实物，或这个货品全部生效预留超过全部良品实物；大白话，不阻断过账)。同一制单人同一提交键(`requestKey`)且内容相同(调拨类型、调出仓、调入仓、原因、按行序的货品/颜色/基本数量)才回放原单；同一个键换了任何内容回 409「同一个提交键对应了不同的处置内容」，不把改过数量的请求当成已办成。面板在发出后结果未知(超时/断网/5xx)时锁定全部内容、只许原样重试；服务端明确拒绝(4xx)什么都没办，可以改了再提交。`GET /api/stock/docs/defective-moves/options` 下发当前用户能办的通道，页面据此显隐入口，不在本地拼权限。
- 通用仓库单据入口只建普通调拨(两端必须同类，跨类直接 422 并指向两条通道)；红冲专门通道的单据除了 `stock_doc:reverse` 还要该通道的独立权限。
- 前端入口：库存详情「库存余额」每一仓行——良品仓行「转不良品仓」、不良品仓行「不良复判转回」，打开右侧面板，货品/颜色/来源仓带入，调出/调入仓都用全站仓库侧滑面板按用途选。仓库调拨单列表/编辑页只说明「良品转不良、不良复判转回请在库存详情的余额行办理」，不另开一套多行建单表单：通道单是「判定一批货」的动作，从看得到这批货余额的地方发起，一次一个货品×颜色(接口本身接受多行)。

### 2.4 可用量单一口径

- `v_stock_usable`：按仓可用量，只含计入可用量的仓(未删、记账、非不良品仓、非车间内料仓、作业叶仓；停用叶仓的既有库存按 V540 仍可动用)，每仓只扣指定本仓的预留。
- `fn_stock_global_usable(货品, 颜色, 排除的销售订单行[])`：可用仓扣安全库存后的合计 - 全部生效预留(全局预留只扣一次；落在不计入可用量的仓上的预留不扣)，最小 0。旧 `v_stock_available` 在每个仓的行上都扣一遍全局预留，按仓求和会重复扣，新口径不再这样定义。
- 替换：销售下单占用与退货重预留(`StockReservationRepository.globalAvailableBase`)、委外备料全局预留(`SubcontractMaterialPlanService.globalAvailableBase`，只换口径不改委外流程)、销售出货仓库闸门(`SalesShipmentService`)、仓库销售出库候选仓与全局预算(`WarehouseSalesOutboundProjectionService`)、客户零星发货(`CustomerShipmentInventoryService`)、批量出货分配(`SalesShipmentBatchAllocation`)、MRP 账面与预留(`MrpService`)、排产零件现存(`ProductionScheduleService`)；AI 库存问答对不良品仓行标「不良品仓, 不计入可用」，可用恒为 0。

### 2.5 物料分析、齐套、让料

- 物料分析可用量的行选择与分仓明细直接排除不良品仓；合格专属来源在不良品仓不再算可用(废止 ADR-075 第 2 条)。
- 齐套 `may_allocate`、预排专属来源两个分支、自动齐套核对、备料预算读取补「非不良品仓」。
- 不良品仓上不允许任何正向预留(新守卫 `fn_guard_stock_reservation_warehouse_class`，所有预留方；V535 合格来源守卫只保留身份不可变部分)。V801 事后断言存量不良品仓上没有生效预留。
- 物料分析参与仓与主仓必须非不良品仓(服务端 `normalizeParticipatingWarehouses` + 前端主仓下拉都排除)。

### 2.6 其它入口

- 内料仓请领候选与可发量、默认发料来源、可选发料叶仓、到货/产成品登记默认仓(货品所属仓)只取良品子仓。
- 销售退货表头仓与良品释放只允许良品仓；余料退库实际收料仓只允许良品仓；委外前置自制目标仓改用良品子仓函数校验(只修正校验口径，不动委外流程)。

### 2.7 即时库存与货品库存

- 即时库存「含不良品仓」默认关(服务端参数默认值与前端偏好默认值一起改)；打开时每行另带 `defectiveQty`(本行在不良品仓的部分，前端在数量后标「其中不良品 N」)，表尾合计多一项「其中不良品数量」。
- 货品列表「库存量」与货品详情合计按良品口径(不含内料仓、不良品仓)；详情按仓明细照常列出不良品仓行并标「不良品」，另列「另有不良品 N (不计入库存合计)」。

### 2.8 前端

- `WarehouseUse`(goodIn/goodOut/defectiveIn/defectiveOut/disposalOut/transfer/count/query)与服务端同名同义；`WarehouseSelection(层级, use:, sameClassAs:)` 是唯一过滤点，另有 `warehouseSelectionProvider(use)`；`showUtenWarehousePickerPanel`、`warehouseHierarchyItems`、`WarehouseHierarchyDropdown` 的 `use` 必填(取代 `allowParent`)，每个调用点按单据类型标用途(采购/销售/委外/仓库单据类型各自给出 `warehouseUse`)。
- 面板与下拉里不良品仓一律带「不良品」标签；良品用途下照常列出但置灰不可选(面板附一句「不良品仓, 这里不能选」)。
- 仓库调拨单的调入仓下拉收窄到与调出仓同类，调出仓换了类别时清空调入仓。

### 2.9 本次不做

- IQC/FQC 判不合格的实物是否记进不良品仓库存：不做，ADR-090 不变(判不合格仍只登记处置，不入账)。
- 销售退货质检「判不良入不良品仓」、车间余料「不良退料入不良品仓」两个新处置动作：不做；本次只把退货良品释放与余料收料收紧到良品仓。
- 不良品减值：不良品沿用原成本，是否减值不在本次范围。

## 3. 同行做法(出处)

- SAP(Inventory Management「Stock Types」、MRP「Storage Location MRP Indicator」)：不良品放在 blocked stock 或 MRP 标识为「不参与计划」的库存地点，MRP/ATP 默认不计；良品与冻结库存之间只用专门的转移过账(343/344 冻结与非限制之间互转)，并留原因。
- 金蝶云星空/K/3(计划方案「可用仓库」参数、库存状态「是否参与 MRP」)：不良仓、待处理仓在计划方案里不作可用仓，库存状态为冻结/不良的库存不计可用量；不良品通过形态/状态转换单在可用与不可用之间转换。
- 共识：不良品与良品在「可用量」上严格隔离、只经专门的转换单据互转、转换要留原因与权限；本 ADR 按此设计。

## 4. 后果与风险

- 规则变化不是回退：销售下单占用、仓库出库候选、MRP 结果都不再含不良品仓(以及车间内料仓、主仓、不记账仓)的数量。测试服务器不良品仓 0 流水 0 余额，存量数据影响为零。
- 本次之前已审核、跨良品/不良品的普通调拨(测试服务器没有)以后不能直接红冲(类别守卫不区分正向与红冲)，V801 用 NOTICE 列出，由人改走专门通道。
