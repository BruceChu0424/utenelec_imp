# 报销列表页

> 路由：`/expense` · 实现源：`lib/features/expense/pages/expense_list_page.dart`

## 一、定位

员工管理自己报销单的列表入口。

- 解决的问题：按全部、草稿、待修订、处理中、已完成查看本人报销，快速进入详情或新建。
- 产品位置：工作台"常用功能 → 我的报销"，是 [新建报销页](新建报销页.md) 和 [报销详情页](报销详情页.md) 的枢纽。

## 二、入口与导航

- 进入路径：工作台首页 → "我的报销"快捷操作；[新建报销页](新建报销页.md) 提交成功后回跳。
- 离开去向：双击行 → [报销详情页](报销详情页.md)；页面头「新建报销」按钮 → [新建报销页](新建报销页.md)。

## 三、页面形态(2026-09-19 V608 对齐 purchase_doc_list_page 范式)

- `UtenAppBar('我的报销')`：右上刷新按钮(重拉当前页)。
- `UtenContentContainer.wide` + `UtenCollapsingHeaderScrollView`：
  - 折叠头 = `UtenFilterToolbar<ExpenseFilter>` 分段(全部/草稿/待修订/处理中/已完成，进页面默认“全部”；
    处理中和已完成使用中性计数；草稿与驳回待补正属于本人待办，按[徽章规范](../00-项目准则/14-徽章与计数口径.md)使用红色徽章)。
  - 页面头行：Icon + `我的报销 (N)`(N=服务端 total)+ 右侧「新建报销」tonal 按钮(唯一新建入口)。
  - 主体 = `MasterDataTableView<ExpenseClaim>`(`Key('expense-list-table')`，`primary: true`
    参与分类条折叠联动)。

| 列 key | 列名 | 说明 |
|---|---|---|
| `claimNo` | 报销单号 | BX + 日期 + 6 位日流水(V608 创建即铸，打印/归档编号) |
| `title` | 标题 | 报销单标题 |
| `category` | 类别 | 明细项类别去重顿号连接；**表头筛选**(固定八类桶下推 `category`) |
| `totalAmount` | 金额 | money 两位小数 |
| `status` | 状态 | **表头筛选**(当前分段状态集，选中后下推 `status` 并同步顶部分段) |
| `submittedAt` | 提交时间 | date，无提交时间取创建时间 |
| `progress` | 审批/付款记录 | 操作人姓名与真实审批、驳回、付款登记时间；付款记录不表示银行到账确认 |

- 表头筛选两层口径与 2026-09-16 版一致：状态/类别下推后端参数回第 1 页，换分段清状态筛选。
- 分页：provider `goToPage` + 表格内置翻页条(含跳页)。

## 四、权限与守卫

- 路由守卫 `expense:apply`(`permission_by_path.dart`)；后端 `/mine` 同权限。
- 列表只看本人(applicantId 过滤)，无多选/批量。

## 五、计数与刷新

`GET /api/expense-claims/counts` 返回本人草稿、驳回待补正、本人可审核和可付款数量。
“我的报销”入口只累计本人草稿与待补正；财务队列另计，不能把同一张单又按通知未读重复累计。
入口登记为服务端徽章目录的 `expenseMine`，归属 `people` 容器；报销审批在钱流内登记为 `expenseFinance`(ADR-108: 数字随徽章汇总一次带回, 前端 `BadgeEntry` 只做显示位置映射)。
保存、提交、撤回、删除及补正重提成功后同时刷新详情、列表、计数与通知；阅读消息不改变业务状态。
刷新中保持上一有效计数，身份切换后清理前一身份的数据。
