# V605 直送资格收紧：只认自制子件

> 2026-09-18。用户报障：「有些任务一部分是直送料、一些是需要去领料的；不能把需要领料的也弄成直接直送——采购什么的要去仓库取货。现在领料领不了、开工开不了。」

## 变化

- `CREATE OR REPLACE FUNCTION fn_demand_direct_supply_eligible`：第一条判支（同车间有在产该货品的其它工单）额外要求 `demand.supply_route = 'MAKE'`；第二条判支（已有货品比对过的直送行指向它）原样保留。`COMMENT ON FUNCTION` 同步。
- 存量修正 UPDATE：`start_route='CONTINUOUS'` 且仍在 WAITING、未动过（`fn_can_change_execution_route`）、没有 `ROUTE_CONFIRMED` 事件（= V606 自动识别打上的，不是人工确认）的段，按同一尺子内联重算（`fn_auto_execution_start_route` V606 才创建，这里不能引用）——被打偏的纯采购/委外工单回到 FULL_KIT。

## 为什么

资格判定此前只看「同车间是否恰有在做同货品的工单」，不看这条需求本身的 sourcing。
采购/委外子件的货走主仓入库，线边仓等不来；V604 自动识别把这类工单打成 CONTINUOUS
后，持续生产在「部分开工」前领料/开工/分批/核对全被路线门抑制（V599），部分开工又
要求每条可直送子件都先到一部分（V595 / 2026-09-17 口径）——工单两头堵死。
ADR-089 §背景第 1 条用户原话「有子件在仓库(其他车间、采购、委外)才需要领料」本就
是这个口径，本迁移把它编码进判定函数。

## 影响

- 影响面全部随函数收紧自动生效：`fn_auto_execution_start_route`（创建事务识别）、
  confirm-route 的 CONTINUOUS 校验、部分开工的 `direct_supply` 冻结、
  `fn_can_start_continuous_supply` 的到料前提、车间任务页 `routeContinuousEligible` 下拉收窄。
- 人工确认过（有 ROUTE_CONFIRMED 事件）或已动过/已离开 WAITING 的段不动；纠偏走既有
  「重新确认生产路线」入口。
- 混合链（MAKE 直送子件 + 采购/委外子件）行为不变：仍按 ADR-089 序列——直送子件到
  一部分 → 部分开工 → 仓库料领料 → 开工。

## 清库策略

无 DDL 新表、无索引；函数替换 + 一次性 UPDATE，与 V604 同形状，不登记
`business_data_reset()` 白名单。
