## 第 1 步：生成发布签名密钥（在家，5 分钟）

在 Git Bash 里执行（Windows 下就是你的终端）：

```bash
cd ~
umask 077
ssh-keygen -t ed25519 -a 100 -C uten-imp-release -f ./uten-imp-release-ed25519
# 提示 passphrase：直接回车留空（CI 非交互使用，不能设密码）
# 提示再输一遍：再回车
```

生成两个文件（都在你的用户目录）：

```bash
cat ~/uten-imp-release-ed25519      # 私钥：第 4 步要整段粘贴到 GitHub secret
cat ~/uten-imp-release-ed25519.pub  # 公钥：第 6 步要装到服务器
ssh-keygen -lf ~/uten-imp-release-ed25519.pub   # 打印指纹，抄下来存好
```

**保管规则**：私钥全世界只允许存在两个地方——GitHub secret（第 4 步）+ 你的冷备份
（U 盘或密码管理器）。禁止发微信/网盘/邮件。丢失或泄露的处置：生成新密钥、
GitHub 换 secret、服务器换 allowed_signers 公钥、发一个新版本号，即完成轮换。

## 第 2 步：阿里云 OSS 建桶（在家，10 分钟）

没有阿里云账号就先注册个人账号并实名认证。费用：标准存储约 ¥0.12/GB/月，你的制品
每个约 150–200MB，保留若干版本 = 每月几毛钱。

1. 登录阿里云控制台 → 顶部搜索「**对象存储 OSS**」→ 左侧「Bucket 列表」→「**创建 Bucket**」；
2. 按下表填写：

   | 项 | 填什么 |
   |---|---|
   | Bucket 名称 | `uten-imp-release`（被占用就加后缀，如 `uten-imp-release-01`） |
   | 地域 | 离公司近的，如 华南1(深圳) 或 华东1(杭州) |
   | 存储类型 | 标准低冗余 |
   | 读写权限（ACL） | **私有** |
   | 版本控制 | **开通**（重要，防误覆盖） |
   | 其余选项 | 全部默认 |

3. 创建后进入 Bucket「概览」页，记下两个值：
   - **Bucket 名称**（第 4 步 `OSS_BUCKET`）
   - **Endpoint（外网访问）**，形如 `oss-cn-shenzhen.aliyuncs.com`（第 4 步 `OSS_ENDPOINT`）

## 第 3 步：RAM 两个子账号（在家，10 分钟）

控制台顶部搜索「**RAM 访问控制**」→ 左侧「用户」→「创建用户」，建两个：

| 登录名 | 用途 | 勾选 |
|---|---|---|
| `uten-imp-release-publisher` | 给 GitHub CI 上传制品 | 仅 **OpenAPI 调用访问** |
| `uten-imp-server-puller` | 给服务器下载制品 | 仅 **OpenAPI 调用访问** |

**新版控制台的 AccessKey 创建流程**（建用户时不再直接给 Key，要到用户详情页创建）：

1. 用户列表 → 点进刚建的用户（如 `uten-imp-server-puller`）→ 上方「**凭证管理**」页签；
2. 点蓝色「**创建 AccessKey**」→ 弹出用途单选窗：
   - `publisher`（GitHub CI 用）→ 选「**第三方访问**」；
   - `puller`（公司自建服务器用）→ 选「**其他**」；
   - 这些选项只是阿里云的用途登记/风险提示，**不影响 Key 权限**；
3. 勾选「**我确认必须创建 AccessKey**」→「继续创建」；
4. **Secret 只显示这一次**，立刻点「复制」存进记事本并标注属于哪个账号；丢了只能删 Key 重建。

然后「权限策略」→「创建策略」→「脚本编辑」，建两条（把 `uten-imp-release` 换成你的桶名）：

**策略一 `uten-imp-release-publisher`**（能写能读，仅限发布前缀）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:uten-imp-release",
        "acs:oss:*:*:uten-imp-release/*"
      ]
    }
  ]
}
```

**策略二 `uten-imp-server-puller`**（只能读）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:uten-imp-release",
        "acs:oss:*:*:uten-imp-release/*"
      ]
    }
  ]
}
```

回到「用户」页：给 publisher 绑策略一，给 puller 绑策略二。
这两把 key 即使泄露，也只能摸到这一个桶，动不了阿里云其他任何资源。

## 第 4 步：GitHub 填 Secrets 和 Variables（在家，5 分钟）

打开 `https://github.com/BruceChu0424/utenelec_imp/settings/secrets/actions`

**Secrets 标签页 → New repository secret**，加 3 个：

| Name | Secret 值 |
|---|---|
| `RELEASE_SIGNING_KEY` | 第 1 步 `cat` 出来的**私钥全文**（从 `-----BEGIN OPENSSH PRIVATE KEY-----` 到 `-----END ...-----`，整段含首尾行） |
| `OSS_ACCESS_KEY_ID` | **publisher** 的 AccessKey ID |
| `OSS_ACCESS_KEY_SECRET` | **publisher** 的 AccessKey Secret |

**Variables 标签页 → New repository variable**，加 2 个：

| Name | Value |
|---|---|
| `OSS_BUCKET` | `uten-imp-release` |
| `OSS_ENDPOINT` | `oss-cn-shenzhen.aliyuncs.com`（换成你第 2 步的地域） |

⚠️ 常见填错：把 puller 的 key 填给了 CI（CI 只下载不上传会报 403）、endpoint 带了桶名（不要带，
只填 `oss-cn-…aliyuncs.com`）、endpoint 写成了内网地址（要用"外网访问"那个）。

## 第 5 步：在家验证整条发布链（15 分钟）

前提：Actions 页里 main 最近一次 **Quality Gate 全绿**。

```bash
cd /d/Projects/uten_imp
git checkout main && git pull
git tag v2026.09.01-1
git push origin v2026.09.01-1
```

- 打开 `https://github.com/BruceChu0424/utenelec_imp/actions`，应出现「**Simple Release**」运行；
- 等 15–25 分钟（Maven + Flutter 构建是主要耗时）；
- **成功的标志**：
  1. Actions 运行绿勾，Summary 显示「发布完成：v2026.09.01-1」；
  2. 阿里云 OSS 控制台桶里出现 `releases/v2026.09.01-1/`（点开有 `SHA256SUMS`、
     `SHA256SUMS.sig`、`server/`、`web/`）和 `LATEST.txt`（内容就是版本号）；
- **失败了**：点进红叉步骤看日志最后几十行。常见原因及解法：
  - `403 AccessDenied` → RAM 授权没绑对/策略没生效（等 1 分钟重试）；
  - `invalid endpoint` → OSS_ENDPOINT 填错；
  - 签名步骤失败 → 私钥没粘全（少了首尾行）；
  - 修好后**不要删 tag 重推**，直接 `git tag v2026.09.01-2 && git push origin v2026.09.01-2`
    （版本号只能往前走，旧对象不可变是设计要求）。

**版本号规则**：`v年.月.日-当天序号`，如同日第二版 `v2026.09.01-2`。tag 即版本，永不复用。

```bash

# 终端打印一个 https://login.tailscale.com/... 链接，
```

### 6.3 首装（逐块执行，每块做完看一眼输出再下一块）

```bash
# ===== A. 拿到部署文件（在服务器上 clone 新库） =====
apt update && apt install -y git curl unzip
git clone https://github.com/BruceChu0424/utenelec_imp.git /root/setup
# 若服务器访问 GitHub 慢：在你笔记本上 git clone 后 scp 整个目录上去也一样

# ===== B. 系统包与账号 =====
apt install -y openjdk-21-jre-headless nginx postgresql-16 python3
useradd --system --home /opt/uten-imp --shell /usr/sbin/nologin uten-imp

# ===== C. 目录 =====
mkdir -p /opt/uten-imp/releases /etc/uten-imp /etc/uten-imp-updater /var/backups/uten-imp

# ===== D. 数据库（空库，schema 由首版 migrator 一次建到最新） =====
sudo -u postgres createuser uten-app
sudo -u postgres psql -c "ALTER USER uten-app PASSWORD '换成强密码A';"
sudo -u postgres createdb -O uten-app uten_imp      # 强密码A 记下来，E 步要用

# ===== E. 四个配置文件 =====
# E1. /etc/uten-imp/server.env —— 参照模板抄：
cp /root/setup/deploy/setup/server.env.internal-test.example /etc/uten-imp/server.env
nano /etc/uten-imp/server.env     # 把数据库密码/相关 REPLACE 逐个替换
# E2. /etc/uten-imp/migrator.env —— 同样数据源：
cp /etc/uten-imp/server.env /etc/uten-imp/migrator.env   # 简化链允许同账号
# E3. /etc/uten-imp-updater.env：
cp /root/setup/deploy/simple/updater.env.example /etc/uten-imp-updater.env
nano /etc/uten-imp-updater.env    # 桶名/endpoint/puller 的 key 四个 REPLACE 换掉
# E4. 公钥信任：
nano /etc/uten-imp-updater/allowed_signers   # 一行：uten-imp-release ssh-ed25519 <公钥全文>
chmod 600 /etc/uten-imp/server.env /etc/uten-imp/migrator.env /etc/uten-imp-updater.env
chmod 640 /etc/uten-imp-updater/allowed_signers

# ===== F. 更新器与 systemd =====
cp /root/setup/deploy/simple/uten-imp-updater.sh /usr/local/sbin/uten-imp-updater
chmod 755 /usr/local/sbin/uten-imp-updater
cp /root/setup/deploy/simple/units/uten-imp.service /etc/systemd/system/
cp /root/setup/deploy/simple/units/uten-imp-updater.service /etc/systemd/system/
cp /root/setup/deploy/simple/units/uten-imp-updater.timer /etc/systemd/system/
systemctl daemon-reload

# ===== G. Nginx =====
cp /root/setup/deploy/nginx/uten-imp-http-lan.conf /etc/nginx/sites-available/uten-imp
nano /etc/nginx/sites-available/uten-imp
#   __INTERNAL_DOMAIN__ → 服务器内网IP或域名；__EXACT_OFFICE_CIDR__ → 6.1 记下的网段
ln -sf /etc/nginx/sites-available/uten-imp /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl enable --now nginx

# ===== H. 拉首版并激活 =====
/usr/local/sbin/uten-imp-updater check
#    预期输出：下载暂存 v2026.09.01-1 完成 + 提示"首装状态：请人工执行 activate"

#    自动：pg_dump 备份 → migrator 建库(几分钟) → 切 current → 启动 → 健康检查
#    成功输出：激活成功：v2026.09.01-1（健康检查通过）

# ===== I. 开机自启 + 定时更新 =====
```


## 第 8 步：为什么不可能推错库

- 本地 `origin` = 新库，`git push` 默认只推它（`push.default=simple` 已固定）；
- 旧库改名为 `old-origin` 且其 **push 地址已置为无效值**，任何 `git push old-origin …` 会直接报错；
- 旧的 `uimp/…` 本地分支已删除，你现在只有 `main`；
- 极少数情况确要往旧库补备份：`git remote set-url --push old-origin https://github.com/UTEN-ELECTRICAL/uten_imp.git`
  推完后再禁回去（把 push URL 改回 `no-push://archived-backup-read-only`）。
