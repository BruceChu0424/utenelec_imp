# ADR-169：状态色深色实底与逐页独立配色

- 日期：2026-10-08。
- 状态：用户授权实施（全站清扫分模块并行执行中）；源码及本地回归不代表公司服务器已部署。
- 无迁移、零新增权限码，纯前端配色与映射口径。
- 修订 `docs/00-项目准则/08-主题与配色.md` §2.4（原「业务状态必须映射到语义，而不是按页面随意选色」的单一五档口径）。

## 1. 背景与需求

用户对全站状态色的反馈（2026-10-08 原话要点）：

1. 「以前每个模块都是固定的差不多这个颜色，这样不好」——共享解析器把所有状态压进
   五个浅底档（中性/蓝/绿/黄/红），加上按状态文案关键字猜色的正则兜底
   （`utenStatusLabelType`），同一页面里多个状态频繁撞色；
2. 「委外不能执行都是黄色，不对」「很多锁住啥的就是红色，完工了就是深绿色」——
   委外任务中心「等物料齐套」（ADR-156 硬阻断、锁死不能下单）走了 warning 黄，
   正是兜底与旧映射的语义错误；08 准则早已写明「硬阻断用 error」但实现没跟上；
3. 「进来都用深色的，色差大的，好区分」——旧渲染是 50 级浅底 tint + 深字，
   饱和度低，浅绿/浅青并排几乎分不出（2026-09-26 车间任务页已为此单独加深过一次）；
4. 「一个页面一个页面走，不要批量处理」「每个模块颜色自己弄，流程不一样」——
   车间「开工准备」里可开工可以是绿，与「历史任务」的完工绿互不冲突；各分段
   （草稿/进行中/历史）互相独立配色，不强求全流程一套色。

## 2. 决策

### 2.1 渲染：深色实底 + 成套前景，明暗同色

`resolveStatusBadgeColors` 不再区分明暗主题：每档返回一对（实底色，前景字色），
全部为深色实底白字（琥珀档是唯一亮底深棕字，沿用计数徽章 `warningStrong`/
`onWarningStrong` 已定稿的一对——「黄更黄」与「白字」不能同时成立）。实底自带
对比度不吃表面色，与红黄计数徽章同一路数。表格状态列继续走 `cellColor` 整格
铺底，文字由表格双向对比度约定自适应黑/白。

### 2.2 色板：10 档深色，色相刻拉开 + 明度分层

`UtenColors.status*` 常量组（白字对比度全部 ≥4.5:1，WCAG AA）：

| 档位 | 常量 | 色值 | 色名 | 白字对比 |
|---|---|---|---|---|
| danger | `statusDanger` | `#991B1B` red-800 | 红 | 8.3:1 |
| orange | `statusOrange` | `#C2410C` orange-700 | 橙 | 5.2:1 |
| warning | `warningStrong` | `#F5B301` 亮琥珀（配深棕字 `onWarningStrong`） | 黄 | 5.3:1 |
| success | `statusSuccess` | `#15803D` green-700 | 绿 | 5.0:1 |
| accent | `statusTeal` | `#0F766E` teal-700 | 青绿 | 5.5:1 |
| info | `statusInfo` | `#1D4ED8` blue-700 | 蓝 | 6.7:1 |
| sky | `statusSky` | `#0369A1` sky-700 | 青 | 5.9:1 |
| violet | `statusViolet` | `#6D28D9` violet-700 | 紫 | 7.1:1 |
| fuchsia | `statusFuchsia` | `#A21CAF` fuchsia-700 | 品红 | 6.3:1 |
| neutral | `statusNeutral` | `#475569` slate-600 | 灰 | 7.6:1 |

业界调研要点（Material 3 / Ant Design / SAP Fiori / GitHub / Jira，2026-10-08）：

- 红/绿是红绿色盲最易混的一对——红取 800 暗档、绿取 700 亮档拉开明度；状态永远
  带文字标签（信息不只靠颜色传递，WCAG 1.4.1）；
- 红(`4°`)/橙(`24°`)相邻靠明度区分，只给语义确实不同的档用，不用于微差两档；
- 蓝与紫色盲下偏近，同页尽量别同时用这对（可用青绿替换其一）；
- 同页并行状态建议 ≤7 个，超出应归并灰档或靠文字；
- GitHub 2021 年把「已关闭」从红改为中性/紫以区别于错误——本系统沿用灰档作
  取消/中止终态，红冲（负向财务事件）保留红。

### 2.3 语义锚定（全局一致的「色相 → 语义家族」）

| 档位 | 语义家族 |
|---|---|
| danger 深红 | 硬阻断/锁定不能往下、驳回、失败、异常、不合格、逾期、红冲 |
| success 深绿 | 完成、通过、已审，以及「就绪可动手」（可开工/可领/可下单）——绿灯 |
| warning 亮琥珀 | 等待外部处理且无异常：等财务/等仓库/在途/等检查。**不能执行不是等待** |
| info 深蓝 | 正在执行/加工中/已提交流转中 |
| sky 青 | 第二等待档：同页需区分两种「等别人」时（如等财务 vs 等仓库发料） |
| orange 深橙 | 风险中间态：部分异常/短交待判定/临期——未死锁但需注意 |
| violet 深紫 | 部分就绪：可部分下单/部分可领/部分齐套 |
| fuchsia 品红 | 分类强调（非语义状态：分批等待、持续生产路线等类别色） |
| accent 深青绿 | 他方执行中（委外商加工中）/品牌特殊档 |
| neutral 深灰 | 草稿/未提交/已取消/已中止等中性终态 |

### 2.4 逐页独立：映射显式化，删除猜色兜底

- **删除 `utenStatusLabelType`**（按「待/进行中/已审…」关键字猜色的正则兜底）。
  表格/网格/卡片的未显式映射状态列保持无色纯文本。状态→档位由各页自己的映射
  函数**显式**决定（`purchaseOrderDisplayBadgeType`、`salesProgressStageBadgeType`
  这类函数就是范本）。
- 每页/每分段（草稿段、进行中段、历史段）**各自独立**配色：只要求「同页同现的
  状态互可区分（色相+明度差）」与「锚定语义不违背」，不要求跨分段联动。「开工
  准备里可开工=绿」与「历史段完工=绿」并存是正确用法。
- 一个状态在不同视角页可以取不同档（例如同一张单在列表页按单据状态取灰、在任务
  中心按行动语义取红），以该页的业务动作为准。

### 2.5 不变的部分

- 红/黄**计数徽章**（`dangerStrong`/`warningStrong`）与 `docs/00-项目准则/14-徽章与计数口径.md`
  的三形态口径零改动——本 ADR 只管状态列/状态徽章；
- 选中行青绿高亮、行级标红（rowColor）、编辑网格红框必填/黄框待核对、内联提示
  （`infoContainer` 等）、危险按钮等既有语义色不动；
- 基础资料主档「使用/停用」保持文本不上色（DocStatusBadge 既有边界）。

## 4. 追加决策（2026-10-08 当日用户反馈三轮）

1. **格内不许写死颜色**：委外任务中心红底黑字的根因是状态格自定义 builder 里
   `theme.textTheme.bodySmall` 自带深色压过表格注入的对比度前景。表格对
   cellBuilder 已包 `DefaultTextStyle.merge` + `IconTheme.merge`（含按底色算出的
   前景），builder 内文字/图标一律继承，不许再写死颜色。
2. **状态/进度列文字统一加粗**（w700，胶囊同步）；判定 `utenIsStatusOrProgressColumn`，
   列宽测量同步加粗防首帧截字。
3. **状态/进度列默认最前**（含「判定结果/处理结果」等无状态字样的行级结论列；
   推翻 2026-10-06 批次对进度列/长文本进度列的豁免）；多状态列全部前置保持
   相对序，compactCards 页给原首列补 `cardRole: title`。
4. 物料分析三个「下达」子页（车间/委外/采购桶）与主表进度列按本 ADR 补齐：
   等待下达归**灰**（等自己动手非等外部）、在途归琥珀、执行归青绿、阻断归红。

## 5. 落地与验证

- 共享层：`UtenColors.status*` 十常量、`resolveStatusBadgeColors` 重写（去 isDark
  参数）、`UtenStatusBadgeType` 扩 `orange`/`sky`、`uten_color_name.dart` 色名表
  补「橙/青」、`utenStatusBadgeCellColor` 去 context 参数并修正命名、五个共享
  表格/网格/卡片组件删兜底。
- 各模块逐页清扫：状态映射函数逐页人工核对语义后重定档位；业务层遗留裸色
  （`Colors.green.shade700` 等）收编进共享档位。
- 验证：`flutter analyze` 全绿 + 各模块定向测试 + AI 色名反查测试扩展
  （`test/shared/ai/ai_page_context_test.dart`）。
