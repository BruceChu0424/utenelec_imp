# Phase 4 — 生产 / 品质记录 / 实验室现状

> 上层：[页面总览](页面总览.md)。本文只记录当前可运行范围，不把历史 Mock、保留权限码或源码候选误写成已部署能力。

## 当前边界

- **生产管理**：生产计划、生产日报、BOM 成本、排程/进度和生产报表使用 `/production` 真实模块。
- **库存与仓库**：即时库存、库存余额和出入库流水使用 `/stock/*`；仓库业务使用 `/warehouse`。
- **品质检测记录**：`/quality/inspection-records` 是真实只读源码候选，从品质任务中心「查询与记录 → 检测记录」进入；它读取既有 IQC/FQC 追加式质量决定与撤销事件，不新建或修改质检事实。
- **实验室检测**：旧 `/lab/test*` 当前仍没有可访问页面、注册路由或后端 API；原纯 Mock 实现已删除，`lab:test:view/upload` 只为未来兼容保留。
- **空调控制**：当前没有可访问页面、注册路由、设备通道或后端 API；原 `/hvac*` 纯 Mock 实现已删除。
- 工作台「品质管理部」顶层只保留「品质任务中心」，不再单列 `/lab/test` 占位。新的「检测记录」位于任务中心内部并直达 `/quality/inspection-records`，但名称相同不代表实验室能力已经恢复。

## 当前页面

| 功能 | 路由 | 现状 |
|---|---|---|
| 生产管理 | `/production` 及子路由 | 真实后端候选；发布仍需目标库、对账和岗位 UAT |
| 品质任务中心 | `/quality/task-center` | 工作台品质管理部唯一顶层入口；收口 IQC/FQC 待办与只读记录 |
| 品质检测记录 | `/quality/inspection-records` | 真实只读源码候选；按 IQC/FQC view 权限与对象范围查询追加决定/撤销事实，无修改、删除、导出 |
| 库存余额 | `/stock/balance` | 真实后端；调整动作需独立权限并产生审计单据 |
| 出入库流水 | `/stock/movement` | 真实后端；可回查来源单据 |
| 流水线看板旧提案 | 无 | 未实施；现有排程/进度页承担相关能力 |
| 产量录入/统计旧提案 | 无 | 未实施；优先使用生产日报与真实生产报表 |
| 实验室检测 | 无 | 未实施；不得把品质记录页当成样本/标准/设备/报告上传系统 |

## 权限与数据

- IQC 记录端点使用 `procurement_inspection:view`；FQC 记录端点使用 `production_quality_inspection:view`。记录路由接受任一 view，前端只请求有权域，服务端继续独立鉴权。
- FQC 保留原对象范围：有效品质组织池读取共享队列，非品质池账号按生产报工 maker/现有生产数据范围读取；详情已知 UUID 越权按 404。
- 记录事实来自 `procurement_inspection_events`、`production_fqc_decision_events` 与 `production_fqc_cancellation_events`；撤销事件以 `CANCELLED` 明示，先前 PASS/FAIL 在父检验已反向后标为 `effective=false`，历史事件不覆盖、不删除。
- `lab:test:view` 和 `lab:test:upload` 不授权新的品质记录页，也不对应任何 Flutter 路由或 API。
- `LabTest`、实验室样本/标准/设备/附件上传等历史概念没有可供本轮验收的权威业务链。

## 发布边界

品质检测记录页是源代码候选，不是目标环境已安装状态。目标非空库事件对账、双域权限与对象范围多账号 UAT、真实 IQC/FQC 反向链、部署/监控/回滚证据均未完成，继续 **NO-GO**。

实验室和空调仍不能计入功能数、UAT 通过数或生产能力。未来重新实施实验室时，必须从真实样本/项目/标准/设备数据模型、服务端授权、文件存储、审计和端到端验收开始；不得把 `/quality/inspection-records` 改名或复用后宣称实验室已交付。
