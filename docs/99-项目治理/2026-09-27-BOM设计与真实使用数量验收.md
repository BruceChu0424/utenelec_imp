设计见 [ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md)，迁移见 [V739](../数据迁移/256-V739BOM设计与真实使用数量.md)。本页是测试结果的唯一记录处，设计与页面文档不重复测试数量。

- ADR-129 §2.1-§2.13 的全部决定，修订 ADR-119 §2-§5、ADR-118 超产记忆、ADR-116 预览守卫、ADR-078/086 拆批与收尾退仓。
- 服务端：BOM 读写、导入导出、粘贴替换、学习记录与重新学习；物料分析快照用量采用、锁定与结构守卫；执行分段需求与指纹、拆批；MRP 与计划导入单台用量；日报实盘收尾；日报不良数的校验、拆段与创建指纹；计划明细超产比例来源与记忆。
- 客户端：货品组装信息页签、BOM 学习记录、导入与预览；物料分析「需要数量」悬停与超产比例提交；生产计划编辑页比例提交；报工「清点剩余物料」弹窗；报工编辑表与详情表「不良数」列；物料反查单套用量说明。

## 本次改变

- BOM「数量」改名「设计使用数量」(`goods_bom_items.qty`，列不变)；新增只读「真实使用数量」，所有本厂生产的父件都学习，按核清物料的实物净耗 ÷ 用到该物料的族产量累计 (`goods_bom_actual_usages`)，人工 BOM 不再停学。现场登记的父件新出现一种料时，其它已完工的现场登记族一并补计暴露，结果与各族完工先后无关。
- 每条 BOM 边的计算用量只由视图 `v_goods_bom_item_usage` 定义 (有真实值用真实值，否则设计值，6 位向上取整)；物料分析、车间领料需求、MRP、计划导入单台用量用它；委外单一子件发料、成本预算、反查报表、BOM 复制/粘贴仍用设计值。Java 计量只有 `MaterialConsumptionMath` 一份公式 (`CompleteKitAllocator` 委托它)，SQL 有两个孪生：V247 `fn_material_analysis_edge_required` (一条边，MRP 与计划导入需求小计) 和 V609 `fn_material_snapshot_required` (冻结耗用曲线逐规则求和，Java 侧为 `CompleteKitAllocator.required`)。
- 计划导入 (`ProductionScheduleService.orderLines`，一条查询随订单行取回一层 BOM)：设计使用数量小于或等于 0 的历史 BOM 行只列出零件、不算用量 (弹窗显示「待物料分析复核」)，不再让整张订单带入失败；MRP 的无效原因改为「BOM 用量小于或等于 0」。
- 物料分析节点保存采用的设计/真实值、依据与原因；只在新建和人工刷新时采用最新值，父节点已有下达批次的子节点刷新也不变；路线确认重置、预览与下达/审批守卫只比结构。锁定值只在这条边的计量规则 (BOM 行、组件、单位、计量方式、基数、尾包) 没变时沿用；共享制造锚点第一次展开时按相对 BOM 路径继承第一个成员子树的锁定值，人工刷新时成员子树与锚点在同一相对路径同步冻结；同一次重算若改掉父节点的有效路线，会按新路线再选一次用量。
- 执行指纹去掉 BOM 行 `updated_at`，含实际采用的用量与依据；拆批按根需求冻结的耗用曲线切分，BOM 变化不再挡拆批。排产预览过期提示统一为「排产预览已过期：目标仓库存、占用、计划行或 BOM 已变化，请重新预览」与「执行分段 BOM 已变化，请重新预览」，手工计划多一句「，或用量已按真实数据更新」。生产用料的 BOM 行用量小于或等于 0 时，生成执行分段的提示点名父件与组件并给修法。
- 最后一次报工逐物料清点实际剩余；选「退回仓库」时审核按 账面可用 − 实际剩余 记本次用料，退仓数量 = 实际剩余 + 未领直送料。账面可用只有一个定义 (各原领料过账 `fn_material_issue_available` 之和，与清账行 `availableToSettleQty`、`maxReturnQty` 同一个数)，客户端不再自己算；被后续批次承接或任务状态不许退料的料仍在账上，清点后的实际剩余留在车间。清点弹窗逐料提示未领直送料。
- 学习边按边所有权：人工改结构列只让该边转为人工边，人工删除后不再自动加回，学习边不自动撤；「BOM 学习记录」逐组件显示并可「从现在起重新学习」(`goods:bom:edit`，零新增权限码)。重新学习开启新的学习轮次，更早轮次的族以后再变动只同步移动累计与基线。学习记录接口返回 `{profile, components, canRelearn}`，组件行与组装信息页签用同一组 `actual*` 字段；按钮只看 `canRelearn`；重新学习后直接显示返回的记录，组装信息页签重读。不用真实值的原因文字只有一份 (`bomDesignReasonText`)。
- BOM 导出的基准产量、设计使用数量、真实使用数量按完整精度写成数字 (`ExportColumn.QTY`，Excel「常规」格式)；导入按单元格存的值读数字、拒收公式，导出再导入数量不变。历史验收时留有“导入忽略颜色、替换清掉行颜色”的限制；2026-10-02 已修复：相同有效颜色保留原 UUID，真实改色按唯一有效颜色解析，缺失/歧义逐行报错；未展示的控制规则、供应商、行价与旧文件缺列均保留已有值，原样导回不再因此使学习边转人工。
- 超产比例：结构默认 (采购/委外 0%；制造底层 10%，上层 0%)；计划明细记 `DEFAULT / EXPLICIT`，只记人确认的比例；V739 重置被默认值钉住的旧记忆。编辑草稿时「同一行」只认页面带回的已存行 id (`sourceItemId`) 且货品没换；记忆规则只在 `fn_remember_plan_line_overproduction_rate`，计划服务只对新增或改过的确认调用 (`ProductionOverproductionAllowance.remember`)，插入触发器已删除。客户端「是否人改过」只由 `SystemPrefilledRates` 判断，物料分析页、汇总下单表与计划编辑页共用。
- 报工不良数 (ADR-129 §2.13)：所有车间的报工行可填「不良数」(`production_daily_report_items.defect_qty`，接口 `items[].defectQty`)，只记录，不改良品数，不进库存、FQC、超产允许量与分流。只能填在已选工单、良品数大于 0 的行上，页面与服务端各有三句校验文字；服务端拆段时整笔不良放在第一段 (`keepDefectOnFirstSlice`，数据库约束 `daily_report_defect_first_slice` 兜底)；创建指纹只在不良数不为 0 时计入。真实使用数量仍按良品算，不良只派生实产单耗 (净耗 ÷ (良品 + 不良)) 与不良率 (不良 ÷ (良品 + 不良))，FQC 补产行的不良不计入。组装信息悬停与 BOM 学习记录显示不良数、实产单耗与不良率 (学习记录头部加累计不良，抽屉宽度改为 1700)；物料分析节点与真实使用数量一起锁定采用时的不良率 (`usage_defect_rate`，6 位)，「需要数量」悬停只在按真实使用数量算时列出。
- 审计：服务端摘要 (`AuditEventInterpreter`) 为新列加中文名 (含 `defect_qty`「不良数」、`usage_defect_rate`「采用时的不良率」)，按「表名.列名」限定的取值与客户端 `AuditFieldLabels` 逐字一致。
