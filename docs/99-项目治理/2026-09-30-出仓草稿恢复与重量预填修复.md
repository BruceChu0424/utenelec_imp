# 出仓草稿恢复与重量预填修复

## 现场只读证据

按用户提供的单号，在当前开发配置连接的数据库只读查询：`EC20261001000001` 为未审核状态 `0`，关联 `EO20261001000001`；有效明细数量 1,000，单位换算率 1，重量 20 kg；同仓、同货、无色的库存余额也为 1,000 / 20 kg。未执行审核、修改库存或更新数据库。

收尾再次只读确认当前库 `goods_weight_observations.counterpart_kind` 确为 `character varying(12)`，该出仓单仍为状态 `0`。因此字段扩容既是隔离库可复现的问题，也适用于用户当前数据库；本次没有执行迁移或替用户审核。

截图的“出仓来源或服务器草稿已变化”来自 `WarehouseSubcontractOutboundEditPage.restoreFormDraft`，随后由 `FormDraftMixin` 的恢复失败遮罩阻断操作。服务端原 `SubcontractMaterialIssueService.update` 删除重建全部明细；本地恢复原要求 `draftItemId` 一致，因此普通保存可造成身份冲突。用户无需退出登录即可遇到，因为本机填写草稿会持续保存。

## 修复边界

- 服务端计划行按当前单据的权威 `planItemId` 复用原明细身份；显式行 ID 与扩展字段来源须一致，禁止跨单、重复或替换来源。只删除真正移除的行，刷新后重算预留；审核仍走原权限、锁及数量校验。每次重新占用使用独立预留事件 ID，旧释放事件保留，避免稳定明细 ID 与预留唯一键冲突。
- 客户端旧稿恢复要求同一服务器单据、完整且唯一的计划来源集合；兼容旧版本重建导致的明细 ID 变化，提交始终使用最新服务器行 ID。新草稿另保存服务器单据指纹及货品、颜色、单位、父件等来源快照；同 ID 被他人改动或真正来源变化保持拦截。
- 通用恢复失败新增“保留本机草稿，加载最新单据”。保留旧稿，重新读服务端成功后换新本机草稿身份；不绕过身份/服务器隔离、请求结果不明保护，也不把部分恢复状态当成最新单据。
- 同类安全重读入口覆盖成品登记单/批、批量领料、仓库材料申请、生产退料。已审核报工来源、材料申请版本、退料来源键校验继续保留。
- 真实数据库回归发现称重观测 `counterpart_kind VARCHAR(12)` 无法保存合法的 `SUBCONTRACTOR`（13 字符），使带重量的委外审核回滚。追加前向字段扩容迁移，原 V743 字节保持不变；扩容不删除或重写已有业务数据，不修改类型语义。
- 表格提示及出入库重量预填规则见 ADR-135 §3.6；不改数量、财务、库存归属规则。数据库迁移只在隔离测试库验证，用户当前库未执行。

## 验证说明

测试覆盖原行 ID 保留、非法来源拒绝、旧本地行 ID 恢复与最新 ID 提交、恢复失败安全重读、重量预填与实称隔离、换仓/颜色缓存隔离、20 kg 与 1 kg 的黄色提醒、称重弹窗及窄屏布局。验证为本地源码与定向回归，不代表运行中的应用已经更新，也不代表 CI 或生产验收。

关键回归入口：

- `test/features/warehouse/warehouse_subcontract_outbound_draft_restore_test.dart`：旧 ID 恢复、最新 ID 保存/审核、完整来源集合与服务器指纹变化、保留旧稿后重读。
- `test/features/warehouse/outbound_weight_reference_test.dart`：基本单位换算、换仓/颜色隔离、无学习历史仍按库存核对、预估不进入实称指纹。
- `test/shared/measurement/weigh_count_dialog_test.dart`：简化交互、20 kg / 1 kg 提醒、包装与分次称重、非法读数、抽样及单位转换、375px 布局。
- `test/components/uten_table_cell_hints_test.dart` 与 `test/shared/drafts/form_draft_mixin_test.dart`：两类表格及窄屏卡片、表头提示保留、恢复错误安全重读和身份隔离。
- `server/src/test/java/com/uten/imp/businesschain/SubcontractDraftIdentityPostgresTest.java`：隔离真实 PostgreSQL 的完整迁移、库存参数读取、连续保存、预留历史、带实称审核与红冲。

全表格检查是共享组件与源码调用审计，并非逐页人工操作验收；81 处 info/help/question 图标候选区分字段说明、业务状态与操作按钮。原有四处输入组件 raw `errorText` 也已改用统一字段消息组件，相应源码契约、列选择器和金额输入回归通过。

最终结果：78 项后端定向回归通过，其中完整 PostgreSQL 链路 1 项实际执行、未跳过；另有 17 项委外草稿恢复页面、10 项称重弹窗及多组共享组件/入出库页面回归通过。最后隔离数据库因并行 V764 落盘实际执行 690 个迁移、到达 V764；本次重量字段扩容仍是 V763。验证包括 500 个 / 10 kg 审核后，再红冲恢复 1,000 个 / 20 kg，计划已出量归零、称重观测与预留分配反向正确。后端使用独立 `target-weight-intelligence`，相关静态分析及差异检查通过；未提交、发布或对用户业务库应用迁移。
