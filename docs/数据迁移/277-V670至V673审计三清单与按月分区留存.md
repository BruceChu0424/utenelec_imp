## V670 行级审计三清单

| 对象 | 变化 |
| --- | --- |
| 旧审计触发器 | 拆掉全部 `fn_audit` / `fn_audit_redacted` / `fn_audit_classify_row` 触发器，删除 `fn_audit_redacted`、`fn_audit_classify`、`fn_audit_classify_row` |
| `fn_audit()` | 重写：触发器参数 [事件类型, plain/redacted, 列级审计的列...]；INSERT/DELETE 存整行，UPDATE 只存变化键(外加非空定位键)，忽略易变列，忽略后无变化不写；敏感列变化只记列名 `_redacted_changes`；`app.legacy_import='on'` 直接返回；直接写 risk_level / event_category |
| `fn_audit_minimize` | 新增：`fn_audit_redact_row` + 工资报销类额外去金额/姓名快照(原 `fn_audit_redacted` 的清单) |
| `fn_audit_redact_row` | 在 V626 清单上加 `login_account` 脱敏；补上 FULL 表里仍会带出的联系方式与证照号：`mobile`、`fax`、`plate_no`、`plate_norm`、`cert_no`，`party_contact_methods.value`、`website_inquiries.name` |
| `fn_audit_mask_account` | 新增：号码类账号只留后 4 位 |
| `fn_audit_track_table` | 新增：清单登记入口。FULL = `AFTER INSERT OR DELETE` + `AFTER UPDATE WHEN (OLD.* IS DISTINCT FROM NEW.*)`；COLUMN_SCOPED = `AFTER UPDATE OF <列> WHEN (<任一列变化>)`(可选 INSERT/DELETE)；NONE = 不挂。只对迁移角色开放 |
| 施加清单 | FULL 180 张(权限 14 张记 authorization、系统配置 7 张记 system、工资报销 6 张额外脱敏)，COLUMN_SCOPED 4 张(物料分析表头/物料行/来源行、物料改挪记录的状态与关闭人/时间/原因)，其余 218 张 NONE(V646/V647 两张只追加账本 `subcontract_component_stock_handoffs`、`production_execution_segment_growth_events` 建表时按旧规则挂了 `fn_audit` 触发器, V670 拆旧触发器时一并拆除, 按清单归 NONE/ledger(行内带操作人与时间, 行本身就是留痕))；尾部失败关闭校验形态与数量(184 张挂审计) |

新表建表时必须登记到 `AuditTriggerCoverageMigrationContractTest` 的三张清单之一(带理由)，FULL/COLUMN_SCOPED 在建表迁移里调用
`SELECT fn_audit_track_table('<表>', 'FULL', 'data_change');`。不再写 refresh_audit_trigger_coverage 全表 sweep。
NONE 里「只追加事件/流水/批次账」一组由契约测试机器核对：主代码与 V670 之后的迁移里出现对它们的 `UPDATE` 即失败，
只有登记了理由的三处一次性完成回填例外(`employee_offboarding_events`、`production_material_settlement_events`、
`warehouse_arrival_exception_stock_in_batches`)；会被人工改状态的 `preplan_material_reallocations` 因此改归 COLUMN_SCOPED。

## V671 审计表按月分区、只追加、留存函数

| 对象 | 变化 |
| --- | --- |
| `audit_log` / `audit_log_archive` | 旧表改名后按原列/默认值/约束新建 `PARTITION BY RANGE(created_at)` 分区表，主键 `(id, created_at)`；risk_level / event_category 改 NOT NULL + CHECK；新增 `on_behalf_of`；历史行按月搬迁(旧任务把同一个月拆在两边时整月留在线上)，一次性脱敏 actor_account 与快照里的 login_account，未认证登录失败里不像号码的原始输入置空；搬迁行数失败关闭核对 |
| 索引 | 每个父表只留 `(created_at, id)`、`(target_type, target_id)`、`(request_id)`、`(session_id, created_at DESC, id DESC)`、`(actor_id, created_at DESC)` |
| 只追加守卫 | `fn_guard_audit_append_only`：父表行级 BEFORE UPDATE/DELETE、父表与每个月分区语句级 BEFORE TRUNCATE，全部 ENABLE ALWAYS |
| `fn_audit_seal_privileges(role)` | 新增：撤销运行账号对审计表的 UPDATE/DELETE/TRUNCATE、撤销对月分区的全部权限，授予留存/预建函数执行权；迁移末尾与生产加固脚本各调一次 |
| `fn_audit_ensure_partition(parent, month)` | 新增(SECURITY DEFINER，`lock_timeout=5s`)：建北京时间月分区 `<父表>_pYYYYMM`；在线最多预建一年，归档只收已过去的月份，同一月份不能两边都有 |
| `fn_audit_retention_run()` | 新增(SECURITY DEFINER，`lock_timeout=5s`)：读系统设置保留期，合计不足 6 个月按 6 个月算(法定下限，函数常量)；先扫描(计行数、给待移分区加月界 CHECK 并校验)，再整月 DETACH→改名→ATTACH(靠 CHECK 免扫描)到归档、整月 DROP 过期归档、预建之后 3 个月，同事务写 `audit_retention_completed` 事件(含设置值、生效值、是否触发下限)；不接受截止时间参数 |

## V672 单据业务时间列

`sales_orders` / `production_plans` 加 `approved_at`、`reversed_at`、`reversed_by`；`sales_shipments` 加 `approved_at`、`rejected_at`、`rejected_by`、
`reversed_at`、`reversed_by`。由审核、红冲、仓库驳回命令写入(计划包红冲子计划的原生 SQL 同步写)。未上线，不回填。
代码事实：三类单据状态 -1 是红冲，不是驳回。

旧分区表改名 → 同列新建普通表 → 原样搬数据 → 主键 (id)、legacy_id 唯一、5 条原外键 + parent_id 自引用外键 → 逐条照搬非审计触发器
