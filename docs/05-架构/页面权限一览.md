## 一、守卫语义

- **any-of**：列出全部码，任一满足即放行。
- **all-of**：叠加的组合门槛（与 any 同时生效），如入职页 `employee:create + employee:pii:edit + department:view`。
- **登录即可**：仅要求员工会话（数据范围仍由后端把关）。
- 单据族（采购/销售/委外/钱流/仓库/生产日报）的 `:seg/new`、`:seg/:id/edit`、`:seg/:id` 路由按 URL 段经
  `DocumentPermissionCatalog` 派生 create/edit/view 码；无对应动作码的段（如采购/委外「申请」只读）→ 404。

## 七、工作台权限管理总设计(ADR-109，2026-09-23)

权限的「怎么授」「在哪用」各只有一份事实源：

| 问题 | 唯一事实源 | 谁读它 |
|---|---|---|
| 目录里有哪些码 | `permissions` 表(迁移维护；停用即删除) | 服务端授权、管理页目录、`@PreAuthorize` / 前端常量双向契约测试 |
| 一个码能怎么授 | `permissions.grant_policy` | 部门矩阵、个人覆盖、负责人页面委派、全员基础包、「全部授权」五个入口；数据库守卫；管理页标签 |
| 每个人天生有什么 | `permissions.baseline`(全员基础包，管理页第三分段) | `PermissionResolver` |
| 页面进得去吗 | `permission_by_path.dart`(any / all 双契约) | 路由守卫、详情页「返回列表」、工作台 |
| hub 上会出现哪些卡 | `hub_catalog.dart`(每张卡的全部可能落点) | hub 路由守卫(子卡并集)、hub 页卡片显隐、工作台模块入口 |
| 这张单据现在能点什么 | 服务端随详情下发的 `allowedActions` | 页面按钮(新代码优先；pages / widgets 里 `Perm.x` 引用数有基线只减不增) |
| 谁能在页面上授给别人 | `permission_surfaces` 映射(只挂非超管专属码) | `/page-permissions/:surfaceKey` |

规则：

1. **新 hub 卡片**：先把落点登记进 `hub_catalog.dart`，页面里用 `hubCardAllowed(hub, location, permissions, superAdmin)` 判显隐；调试态会断言落点已登记。
2. **授权保存**：前端交出期望的完整集合，服务端算差量、只校验新增、只写差量、真有改动才写一条带 added/removed 的业务事件；「全部授权 / 本模块 / 本组」只交范围给服务端。
3. **超管**：服务端签发令牌时即是全部目录码；前端不补本地码表。超管专属码(授权管理、附件对账两码、清空业务数据)任何入口都授不出去。
