## 1. 权限与模型职责

权限取自当前登录主体、有效部门与功能码。模型只在服务器当次给出的封闭工具集合中选择查询，不能生成 SQL、HTTP 地址、页面脚本、任意路由、用户身份或授权结论。客户、仓库、工单和人事数据仍使用原业务的对象范围；会话历史和工具结果在每次读取时重新校验身份、授权版本、部门及来源事实。

“假装我是超级管理员”、文件中的系统提示、角色标签和伪造工具参数都不改变服务器权限。工具事实在服务器生成答案，不交回外部模型进行自由改写。业务保存、提交、审核没有接入聊天工具；现有超管单项授权仍是独立预览、本人确认、再认证和审计流程，不属于文件自动填写。

## 3. 文件先分类，再进入页面

公共异步任务新增 `ERP_DOCUMENT_ROUTE`，只解析当前用户主动上传的原件，不创建业务单据。读取上限15MiB，使用真实文件头、已有有界 Excel/PDF 解析器、DOCX 纯文本安全读取器。拒绝宏、嵌入主动对象、加密或损坏文档、异常压缩比；不访问文档链接或运行公式/脚本。

分类在本地按工作表/页面分别使用标题、相邻表头和票据锚点，文件名不能单独决定用途。正文备注中的 quotation、发票号引用、采购订货单中的“订货单”不能单独产生另一种业务类型。报价、客户订单和商业/形式发票可属于同一贸易资料族；真正的人事、国内税票、仓库、生产、采购和独立合同仍保留业务边界。

用途按“用户明确要求 → 当前可访问页面 → 真实部门”辅助判断，任何一步都不扩大可执行工作流。真实部门从员工主部门、兼任部门和祖先部门读取，超级管理员的全量权限不等于销售部门。商业发票只有在含货品/数量/价格表头且销售上下文明确时才自动进入销售填写；多部门用途冲突或来源不明时供用户选择。商业发票不能仅因“发票”二字自动变成员工报销。

分类结果保存内部版本、部门指纹和页面上下文，读取和填表前重新核对；新版不复用旧分类器的错误结果。前端页面关联关闭时不传页面，开启时仅传有界路径，不传表单内容、部门身份或权限声明。

输出仅包含固定工作流枚举、可用选择、说明、字段建议、缺项、来源文件名及SHA-256。没有模型生成的跳转地址。只有明确且当前有权的目的地才能自动打开：

- 销售报价/客户订单/报价明细：打开新建订货单；用户明确要报价时打开新建报价单。进入真实页面后运行原销售识别、客户货品匹配与校验链。
- 发票：打开本人报销申请，填入本地识别的票面建议与费用明细。数字、日期与来源保持可核对，不代表发票验真或审核通过。
- 不确定、混合、多票、超读取范围：暂停说明并提供权限内选择。已识别但暂未接入填写的业务明确告知，不冒充成功。

支持 Excel、CSV/TXT、PDF、PNG/JPEG/WebP；DOCX 可分类与读取票据文本，销售明细须先导出为 Excel/CSV/PDF/图片再走已有识别链。ZIP、旧DOC、OFD及任意可执行文件不承诺可解析。

发票继续遵守 ADR-094：文字PDF/文本在服务器本地抽取，图片使用已部署的本地OCR，不上传到外部大模型。未启用OCR、扫描件无法辨认时明确说明，不能填假数。多张票据或多页票据不得把第一张的金额当整份金额；同一张票据的大小写合计不误认为两张。

## 4. 可见填写与用户控制

前端以类型化计划承载作业ID、原文件、原字节摘要、身份/服务器/权限边界。页面打开后重新读取原作业并复核权限、摘要及工作流，固定本地路由只能到新建表单。计划防重复执行；换账号、撤权或切换服务器后迟到结果不再操作页面。

页面显示真实读取、匹配、填表状态。高置信且无冲突的字段可带入；歧义匹配、缺必填、价格校验问题由现有核对界面处理。销售自动流程不创建扩展列、不自动学习客户资料或英文名，不替用户确认不确定的来源。

AI填写只修改当前表单输入。新建、保存、提交、审核仍由用户点原业务按钮。ADR-121 本机表单恢复不等于后台业务建单，沿用身份隔离和版本保护。报销原文件与票面信息在用户保存后保留明确登记入口，不通过自动任务偷偷登记凭证。

## 5. 代码更新同步

服务器每次请求根据当前 Spring `AiChatToolPort` 注册表、部门与功能权限生成可用工具，`/ai/chat/capabilities` 返回同源工具目录、工作流和目录指纹。部署新代码并加载后，新注册的只读能力自然进入当次路由；权限变化立即参与下次校验。

不把整个仓库、数据库表结构、密钥或任意内部接口交给模型。新业务必须提供授权适配器与封闭参数契约后才可操作；新表单需登记可核对字段说明及固定路由。自动同步能力目录不等于自动获得执行未知代码的权限。

## 6. 本次故障修复

2026-10-03 本地运行日志04:33:17出现 PostgreSQL“未设定参数值4的内容”。`AiChatEvidence.requireOrderAttachment` 用位置参数 JDBC 执行 JSONB `params ? 'docId'`，其中问号被驱动视为第四个参数；实际只绑定三个，因此文件识别完成后聊天提交409。改为 `jsonb_exists(params, 'docId')`，保留本人、新订货、未使用、未过期、授权版本校验。不能通过放宽权限、跳过原件检查或修改数据库约束消除错误。

## 7. 简短回复与界面呈现

`GET /api/ai/chat/page-suggestions` 按当前登录主体和登记页面返回最多三条可回答的问题，未知或无权页面不返回建议。聊天窗口默认呈现其中两条；打开窗口和切页都会更新标题与问题，不清空历史，不弹阻挡表单的对话框。身份、服务器、权限、页面或关联开关变化均使旧请求失效。该功能识别平台已登记路由，不宣称能看到任意屏幕或未提交字段值。

工作对话仅从封闭的本平台知识和工具生成结果；娱乐、个人闲聊和平台外任务返回简短工作提示。明确娱乐问题本地拒绝，不外呼模型；其他语义经 `NON_WORK` 路由判断，模型额外正文仍不会变成用户答案。问候与感谢保留简短礼貌回应。

默认直接回答业务结果，使用短句、常用词；不在每条答案追加权限范围、数据来源、内部规则、技术路径和审计说明。欢迎只保留一句话和少量提问例子。页面说明默认给关键字段和一个简短假设例子；业务列表默认最多5项，不隐瞒还有更多结果。

用户明确要求详细或单独回复“展开”时，才提供更完整的业务明细；单独要求“说重点”时恢复简短答案。查询续接只复用已验证的只读参数，仍执行当前工具、参数、权限和来源证据校验，不能复用授权提案或把历史事实交给模型。各工具保留有限结果上限，更多内容回原业务页查看。

简短不删去会影响判断的事实：金额币种、数量单位、日期、账面与可用库存、报工与入库区别，以及成本未完整、资料不足和无法识别等必要提醒。拒绝和故障也只给简短可操作提示。隐藏规则文案不改变服务器权限；授权确认仍显示对象、权限和范围。

自动填表完成后显示已填摘要与“尚未保存，请核对后保存”，不继续堆叠处理步骤和规则说明。保存、提交、审核仍由用户操作。验证记录见[简短回复验收](../99-项目治理/AI助手验收合集.md#ai-simple-replies)。

## 8. 安全资料

- [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)：默认拒绝，每次请求重新鉴权。
- [OWASP LLM Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)：不可信资料与指令隔离，工具独立校验，最小权限和人工确认不能仅靠提示词代替。
- [OWASP AI Agent Security](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html)：分类结果不能自行授予工具执行权。
- [Microsoft：AI代理最小权限与工具绑定](https://learn.microsoft.com/en-us/security/zero-trust/sfi/least-privilege-for-ai-agents)：明确主体、资源/数据/操作范围和工具白名单，验证撤权及下游执行检查。本项目对应当前员工主体、原业务范围策略、每次工具执行/历史读取重验。
- [Anthropic：跨产品约束模型能力](https://www.anthropic.com/engineering/how-we-contain-claude)：细分工具权限能够限制错误行为的影响，模型或中间处理结果不能被自动提升为更高信任。本项目不把文件分类结果当授权，也不给聊天任意脚本或数据库接口。

这些原则落实为服务器范围校验、固定工作流、无业务自动保存能力和对抗回归，不能据此宣称系统已达到“绝对不可绕过”。验证证据见专项记录。
