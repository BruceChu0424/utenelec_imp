## 一、V471 参与仓范围

`production_material_analyses.warehouse_id` 继续是实际领料叶仓，也是齐套、正式预留、
`DRAW` 和物理权益的唯一仓库真值。V471 新增
`participating_warehouse_ids uuid[]`，保存库存参考叶仓范围；顶部主仓不是这个物理落点：

- 历史分析回填为 `ARRAY[warehouse_id]`，不猜第二仓；
- 数组必须 1–100 项、无空值、无重复并包含实际领料仓；
- 所有成员必须是未删除、未禁用、参与核算的仓库；
- 为兼容旧客户端、旧测试和旧写入口，迁移后的 `BEFORE` 触发器会把“只写
  `warehouse_id`、未写参与仓数组”的 INSERT/UPDATE 自动归一为单主仓；新服务仍显式写完整集合；
- 其它参与仓的合格可用量只形成“所选仓合计可用 / 其它仓可调拨”提示。未先完成受审计的
  仓间调拨进入实际领料仓，不得提高 `readyNow`、不得形成 reservation，也不得生成或扩大 DRAW。

前端默认组合复用账号级 `user_preferences` 键
`production.materialAnalysis.warehouses`，保存实际领料仓和参考叶仓集合。

2026-09-05现行界面只在顶部显示主仓库，选择后展开所属可用叶仓，最多100个，超过上限明确
阻止而不静默截断；“实际领料仓设置”仍指定范围内一个叶仓。历史分析保持原持久化仓和参与
集合，不因打开页面换仓；旧客户端只传warehouse_id的单仓兼容不变。其它仓库存仅为调拨参考，
未实际进入领料仓不计齐套。该界面改版无需新增迁移，不修改V471/V472已应用字节，见
[V476说明](92-V476仓库主子层级.md)与[生产物料分析页](../03-页面/生产物料分析页.md)。

## 二、V472 公共超量与显式采用

V472 把一次采购或无子层委外的“精确需求”与“计划员主动追加的公共备货”拆账：

- `requested_qty` 和 action allocations 仍只等于本分析需求；
- `public_surplus_qty` 是独立公共切片，绝不进入来源分析的精确 entitlement；
- 后续分析只能通过 `SHARED_FUTURE_CLAIM` 显式采用同实际领料仓、同货品/颜色/单位、同路线且
  到期可用的已批准公共在途；来源 action 按行锁和延迟约束守恒，累计采用不得超过实时批准容量；
- 部分到货先兑现已采用需求，未采用余量保持公共；取消、来源订单变更、来源行变更和并发采用
  由不可变身份、来源总量与活动 claim 触发器失败关闭；
- 历史超量只在“单一外部来源行、无共享歧义、批准数量可证明”时回填；其它情况进入
  `v_preplan_public_surplus_migration_issues` 人工队列，禁止猜测。

新增权限：

| 权限 | 默认部门 | 说明 |
|---|---|---|
| `production_material_analysis:over_supply` | `GM`、`SUB_PLAN` | 公共超量下达；不可批量授权 |
| `production_material_analysis:claim_shared_future` | `GM`、`DEPT_PMC`、`SUB_PLAN` | 采用公共在途 |

两者均登记到 `production.material-analysis` 权限面。公共在途响应还必须分别通过采购或委外
对象范围；仅持物料分析/模块查看权时不得泄露不在本人范围内的来源单号或 UUID。

## 三、升级前后校验

升级前：

1. 确认 `production_material_analyses.warehouse_id` 无空值；空值必须先形成业务对账单，禁止猜仓。
2. 保存 `flyway_schema_history`、V470–V472 文件校验和、活动分析/action 数量和数据库备份。
3. 检查 V472 历史回填候选是否存在多来源或共享来源歧义。

升级后至少执行：

```sql
SELECT count(*)
FROM production_material_analyses
WHERE cardinality(participating_warehouse_ids) < 1
   OR NOT warehouse_id = ANY(participating_warehouse_ids);

SELECT *
FROM v_preplan_public_surplus_migration_issues
ORDER BY analysis_id, action_id;

SELECT version, success, checksum
FROM flyway_schema_history
WHERE version IN ('470', '471', '472')
ORDER BY installed_rank;
```

第一条必须为 0；第二条允许有待人工处理项，但这些项不得自动成为公共在途；第三条必须三版
唯一且成功。再抽样核对“需求 500、正式采购 2000、公共 1500；新需求 1000 显式采用后公共余
500”，并确认分析 A entitlement 始终只有 500。

## 四、回退与恢复

这两版增加持久事实、约束和历史解释，禁止通过改旧迁移、`flyway repair` 或直接删列回退。
发布前失败可恢复升级前备份；升级后已经产生公共切片或 claim 时只能停写、导出对账、修复应用
并以前向迁移纠正。应用回滚到不知道 V471/V472 的版本前，必须先证明旧版本不会错误消费新
action 形状；无法证明即 **NO-GO**。
