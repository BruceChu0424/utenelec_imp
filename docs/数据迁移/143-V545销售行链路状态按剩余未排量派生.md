# V545 销售订单行链路状态按剩余未排量派生

2026-09-10。用户口径：「我的车间任务 部分排产后订单会从待排产区域消失直接转移到进行中，就是只排产部分」——订 10 排 4 审核后，订单在生产调度待排产段消失、销售进度显示生产中、订货列表大类落到生产中，调度工作台也看不到"已排 4/10"。

## 根因

`sales_order_items.chain_status` 是派生列，但派生规则内联在十余个写点（排产审核/红冲、报工审核/红冲、成品入库/红冲、出货驳回/红冲、退货、让单、改量、根供给、FQC 回退），且一致把「已排 − 已产 > 0」当作整行已排产（3/4/5/6）；剩余未排量（未交付 − 预留 − 未完工计划量）从不参与判定。销售进度阶段另按 `produced>0 OR planned>0 → PRODUCING` 聚合，订货列表大类按 `chain_status IN (2,3,4)` 精确匹配，三处各自漂移。

## 本版规则（唯一口径）

`server/src/main/java/com/uten/imp/common/saleschain/SalesOrderChainSql.java`（Java 镜像 `SalesChainStatus`）：

```
chain_status ≤ 0                                  → 原值不动（未上链 / 已取消）
未交付量（qty − shipped + returned − flag）≤ 0     → 9 已发货
预留 ≥ 未交付量                                   → 7 可发货
已发 > 0                                          → 8 部分发货
剩余未排量 = 未交付 − 预留 − max(已排 − 已产, 0) > 0 → 预留 > 0 ? 1 部分预留 : 2 待排产
已产（完工入库）> 0                               → 6 部分完工
原值 5                                            → 5 生产中（只由报工审核在未排量归零时推进）
未完工计划量 > 0                                  → 3/4（排产审核按物料判定；其余保留原值 3 否则 4）
```

- 全部写点共用该 CASE（同语句改数量列时以 delta 形式传入，PostgreSQL SET 读旧行值）；出货交接只推 8/9，是唯一例外。
- 报工审核 3/4→5 增加「剩余未排量 ≤ 0」门槛；报工红冲与 FQC 失败回退按"是否仍有有效报工量"决定留 5 或回 3/4，不再无条件 5→4。
- 调度工作台「缺口」= `unplannedQtySql`；销售进度 `PENDING` = Σ行剩余未排量 > 0（先于 PRODUCING）；订货列表待生产/生产中大类改 `chainGroup=pending|production` 数量派生，部分排产的单可同时命中两段；`GET /production/schedule/shortage-count` 无前端调用，已删除。
- 前端：进度页阶段列「待排产·部分已排 4/10」，进度详情/订货明细链路标签同款，产品进度面板加「未排」，调度待排产表加「已排」列、状态列标「部分已排 4/10」。

## 迁移内容

`V545__sales_order_item_chain_status_unplanned_backfill.sql` 只回填数据：`is_deleted=false` 且 `chain_status IN (3,4,5,6)` 且剩余未排量 > 0 的行，按同一 CASE 改回 8（已发>0）/ 1（有预留）/ 2；不改任何数量列，报工/入库事实仍在 `plan_order_item_links` / `produced_qty`。幂等，重跑无命中行。不新增表、列、索引。
