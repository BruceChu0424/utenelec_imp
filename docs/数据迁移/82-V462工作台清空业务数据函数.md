# 82 - V462 工作台「清空业务数据」函数

## 一、背景

`server/ops/reset_business_data.sql`（psql 停机版）要求停应用、零其它连接、
带外三重确认，只能在运维窗口执行。2026-09-03 用户决策（ADR-067）：工作台
最底部加「系统测试」区，超管在**运行中的应用内**一键完成同口径清空。
安全写入门实测禁止在 Java 内联 `TRUNCATE`/动态 SQL（变量、常量、文本块、
字面量拼接作 SQL 参数一律判注入），因此清空口径整体下沉为本迁移创建的
数据库函数。

## 二、变更

- 新增函数 `business_data_reset()`（`LANGUAGE plpgsql`，调用者事务内执行）：
  1. 建 318 表 CLEAR/PRESERVE 分类临时表（与 ops 脚本同一份清单，
     `BusinessDataResetSqlContractTest` 逐表锁定同步；CLEAR 222 / PRESERVE 96）；
  2. 前置拒绝（`SQLSTATE UT900` → 应用层 409）：outbox 有待处理/失败事件、
     附件/上传会话存在非人事 owner；
  3. 目录完整性失败关闭：分类重复 / 未分类 public 父表 / 白名单缺表 /
     保留表外键引用待清表；
  4. 统计待清行数 → `TRUNCATE ... RESTART IDENTITY`（业务表自增 ID 从 1 重新开始）；
  5. 主档金额/期初投影归零（账户五金额、客户/供应商期初往来、货品期初库存/
     安全库存/20 项成本金额费率、结算类别期初；@Version 与 updated_at 随真实
     变化推进，不停审计触发器）；
  6. 保留表行数基线采集 → 六物化视图刷新 → 终局校验（账户/期初/货品归零、
     CLEAR 逐表为零、PRESERVE 行数不变、物化视图为零，任一失败整体回滚）；
  7. 全员下线（应用内孪生独有）：`authorization_state.epoch + 1` +
     `TRUNCATE refresh_tokens`（断掉所有 staff 会话与续期）；
  8. 返回摘要（cleared_table_count / cleared_rows / preserved_table_count /
     authorization_epoch_after）。
- **不加表、不改列**：CLEAR 222 / PRESERVE 96 计数不变；reset 白名单版本门
  增至 **V462/424**。

## 三、调用方与门禁

- `features/admin/systemtest/BusinessDataResetService`（编排：运行开关 → 排水闸
  → 绑定审计 actor → 调函数 → 异常映射 → 显式审计事件）；
  `SystemTestController` `POST /api/system-test/business-data/reset`。
- 四重门禁：`uten.features.business-data-reset-enabled`（默认 false，仅
  dev / internal-test 开启，生产 403）→ `principal.superAdmin` →
  请求体口令逐字「清空业务数据」→ 排水闸（清空期间其它 `/api` 请求 503，
  在途清零后才执行）。

## 四、验证

- `BusinessDataResetSqlContractTest`：函数清单 == ops 脚本清单（318 项逐表相等）。
- `BusinessDataResetServicePostgresTest`（真实库全链路）：待处理 outbox → 409；
  执行后 222 张清空、账户五金额/结算类别期初归零且保留行数不变、
  `finance_reconciliations_posting_seq_seq` 重启（nextval=1）、epoch 递增、
  refresh_tokens 清空、审计行增长、二次执行幂等。
- `ResetBusinessDataScriptContractTest` 同步增至 V462/424；
  `MigrationRehearsalSupport` head/count 升至 462/424。

## 五、残留风险

- 每日 08:0x 的通知/对账调度器未接排水闸（撞窗概率≈0，后果=可重试回滚或
  残留一条派生通知，见 ADR-067 §5）。
- 内网服务器运行时 Flyway 关闭，函数随受控迁移进程（uten_migrator）落地。
- 新增迁移增删 public 表时仍需同步两份清单（ops 脚本 + 本函数），由
  两个契约测试双向锁定。
