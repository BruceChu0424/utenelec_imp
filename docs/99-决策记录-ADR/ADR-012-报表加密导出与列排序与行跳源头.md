# ADR-012：报表加密导出、列排序与行点击跳源头（统一表格升级）

> 日期：2026-07-27 · 状态：已实施（集中编译/分析待跑；运行时冒烟待用户重启后端后进行）
> 前置：[ADR-009](ADR-009-后端安全加固与功能补全.md)（安全首位）· 组件：`MasterDataTableView`（[文档](../02-组件库/MasterDataTableView.md)）
> 原则：数据展示全局唯一表格（一处改、全表生效）· 敏感操作独立权限点 · 输入当数据不当指令

## 背景

`MasterDataTableView` 是全项目「行×列数据展示」的唯一标准表格（6 报表族 + 6 主档 + 各单据列表共用）。
「统一表格升级」工程在此组件 + 共享层一次性叠加四项能力，所有页面自动获得，杜绝每页各画各的表格：

1. **Phase 1** 报表默认日期范围 = 上月今日..今日（`defaultReportFrom()`，收紧默认避免一进拉全量）。
2. **Phase 2** 列排序（日期/金额/数量列点表头排序）。
3. **Phase 3** 加密 Excel 导出（POI + Agile AES-256）。
4. **Phase 5** 行点击跳源头单据编辑页。

本 ADR 记录 Phase 2/3/5 的关键技术决策（Phase 1 为纯默认值调整，不单列）。

## 决策与执行

### 1. 列排序：共享白名单 ORDER BY（防 SQL 注入）

- 排序必须**回后端**（报表服务端分页，前端排序只用于极小结果集）。前端只发 `sort`（列 key）+ `order`（asc/desc）。
- 两套共享解析器，**sort 必须命中白名单**才生效，否则回落默认排序：
  - `common/report/ReportSort.java`：报表原生 SQL，白名单 = 投影别名（列 key），按别名 `ORDER BY`。
  - `common/web/TableSort.java`：JPA 单据/主档列表，白名单 = 前端列 key → 实体属性映射 `Map.of(key, property)`。
- 前端：`MasterColumnDef` 加 `type`/`sortable`；可排序列（date/money/number）表头出排序菜单；`sortQueryParams()` 生成 query。**日期列只走排序菜单、不列日期值 facet**（日期值各异，列筛选桶无意义）。

### 2. 加密 Excel 导出：POI SXSSF + Agile AES-256

- **SXSSF**（流式）防大表 OOM；服务端循环分页（size=500）累积，**硬上限 100k 行**防失控。
- **Agile AES-256**（OOXML 标准加密格式，Excel/WPS 原生支持）：`EncryptedWorkbookService` 经 BouncyCastle（`BouncyCastleRegistrar` `@PostConstruct` 注册）。
- **密码入 body**（`ExportPasswordRequest`，非 query/URL）+ HTTPS 传输；前端 `UtenExportButton` 弹密码框（≥6 位 + 确认）→ `downloadBytes`（`ResponseType.bytes`）→ 跨端保存（web Blob anchor / io path_provider）。
- **防公式注入**：单元格按文本写入（数值千分位由样式控制，非字符串拼接公式）。
- **审计**：`AuditService.logExplicit("export_<module>_report")` 记录 谁/什么报表/多少行；导出下载记录可在「系统管理 → 审计日志」查（`AuditController` + `admin_audit_log_page`，支持「仅导出」筛选）。
- 列定义复用 GET 路径的 columns（`ExportPayload`），剥离 width。

### 3. 行点击跳源头：`__srcId` 隐藏元数据列（命名约定）

- **约束发现**：`execute()` 按 `columns` 列表索引 `r[i]` 构建 row Map（`m.put(columns.get(i).key(), norm(r[i], ...))`），故 SQL 投影列数必须严格 == columns 列表列数。直接在 SQL 末尾加列不加 columns 会索引错位。
- **决策（命名约定，非 record 字段）**：列 key 以 `__` 开头 = 隐藏元数据列（如 `__srcId`）。`execute()` 末尾把 columns 过滤掉 `__` 前缀再返回（`visible = columns.stream().filter(c -> !c.key().startsWith("__"))`）：
  - 前端拿到的 `columns` 不含 `__srcId`（不渲染成列、不进排序菜单）；
  - 导出 Excel 不含 `__srcId`（复用 visible columns）；
  - 但 row Map 的 `items` 已 `put("__srcId", ...)`（`norm` 把 UUID 转 `toString()`），前端 `row['__srcId']` 可读。
- **前端**：报表页 `onRowTap(row)` 读 `row['__srcId']`，空则 return（汇总/对帐聚合行无单一源头）；非空 `context.push(RoutePath.<doc>Edit(seg, srcId))` → 单据编辑页，编辑页 `context.pop()` 回报表（保活筛选/分页状态）。
- **覆盖判断**：明细/汇总报表基于单据头表（别名 `o`/`t`/`p`）→ 加 `__srcId`；跨客户/供应商/货品/月度聚合（MV/视图/`executeGrouped`）→ 不加（行无单一源头）。各模块覆盖：采购 9、销售 8、委外 8、仓库 14、生产 2（plan；daily 为 0 行占位跳过）、钱流 8（receipt/payment/expense/income/fee-offset；ar-ap 台账、对帐、账户对帐聚合跳过）。

### 4. 独立导出权限（报表 `*_report:export` + 主档 `*:export`，V71）

- **原则**（ADR-009）：敏感操作用独立权限点，后端 `@PreAuthorize` 不信前端。「能查看」≠「能导出整表数据外发」。
- V71 新增 **11 个**导出权限：6 报表 `*_report:export`（purchase/sales/subcontract/stock/production/finance）+ 5 主档 `*:export`（goods/client/supplier/currency/account，主档含 PII 须同等独立）。各 `POST /export` 端点 `@PreAuthorize` 全改 `:export`。
- **回填**（导出跟随查看）：`INSERT ... SELECT` 把 `:export` 授予所有已持有对应 `:view` 的部门（`REPLACE(code, ':view', ':export')` 自连接 `department_permissions`），避免现有用户断权。
- **权限模型审视（对照大厂）**：导出=数据外发，大厂（Salesforce/钉钉/Workday）普遍比查看严、默认不给。本系统作为内部 ERP 取**平衡**——回填「跟随查看」保证业务可用（员工需导出报表工作）+ 独立 `:export` 让管理员可在「权限管理」页按部门/用户回收（最小权限可渐进收紧）+ 审计 + 限流（见 §5）多道防线。PII 主档（客户/供应商）导出已审计，不再叠加审批（过重）。
- **JWT claim 约束**：权限在登录时写入 token；V71 上线后用户须**重登**，新 token 才带 `:export`（旧 token 导出会 403）。超管恒有（`SecurityConfig` 硬编码放行）。
- 前端 `UtenExportButton` 不查权限（纯触发器，后端 403/429 时 appError）。

### 5. 导出限流（Bucket4j 令牌桶，per-userId）

- 导出是高成本数据外发，现有权限+审计+10 万行上限+前端防连点之外，补**频率维度**（防被盗账号/脚本短时大量拖库）——大厂数据导出标配。
- `ExportRateLimiter`（Bucket4j，仿 `LoginRateLimiter`，per-userId 而非 per-IP：导出需认证，按人限更精准）+ `ExportRateLimitInterceptor` 拦截 `POST /api/**/export`，超限抛 `RATE_LIMITED`（429）。
- 阈值可配 `uten.security.export-rate-limit-per-minute`（默认 10/分/用户）；内存桶上限 1 万防 OOM。单测覆盖：上限拦截、用户隔离、null 放行。

## 验证与残留

- 采购模板（execute 过滤 + 9 报表 `__srcId` + 前端 `_onRowTap`）`mvn compile` BUILD SUCCESS + `flutter analyze` 0 error。
- 其余模块由 5 个并行子代理落地（铁令禁 git/mvn/flutter，主线程集中验证）：执行 `mvn -f server/pom.xml compile` + `flutter analyze` 跑全量编译/分析，修任何编译错误。
- 运行时冒烟（待用户重启后端后）：① 报表点表头排序 ② 下载表格（设密码→Excel/WPS 输密码打开）③ 报表行点击跳单据编辑页 ④ 系统管理审计日志查「仅导出」⑤ `:export` 权限回收后某用户导出 403。
- 已知可接受残留：prod HTTPS（建议反向代理终结 TLS）为部署侧加固项；导出限流为单机内存桶（多实例部署需换 Redis 共享，当前单实例够用）。
