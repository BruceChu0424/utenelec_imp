# 2026-10-24 本地运行账号缺权修复

## 故障与根因

`mvn spring-boot:run` 已完成编译和 Flyway 校验，本地数据库版本为 920，随后加载
`PermissionSurfaceRegistry` 时出现 `permission denied for table permission_surfaces`，
导致 JWT 过滤器和 Tomcat 初始化失败。`BadSqlGrammarException` 是 Spring 的包装异常，
底层错误是数据库权限不足。

本次实际检查对象是仅发布在 `127.0.0.1:5434` 的本地开发库 `uten_imp`，
system identifier 为 `7700008130976600103`，database OID 为 `19699`。
业务角色为非超级用户 `uten`，迁移 owner 为非超级用户 `uten_migrator`。
迁移 owner 建好了对象，但没有完成运行账号授权及普通对象的默认授权：
586 个非分区表或视图缺少读取权限，28 个序列缺少使用权限。

旧业务清空函数、旧维护绕过函数和 `system:business_data_reset` 权限码在修复前已经不存在。
不能删除正常的权限目录表，也不需要重导业务数据来修复这个启动错误。

## 修复

- 新增 `LocalRuntimePrivilegesCallback`，仅在 `dev` 环境、回环地址、本库和指定分离角色组合下执行。
  Flyway 成功结束后统一核对运行授权，没有待执行迁移时同样执行。
- 授权策略保存在 `server/src/main/resources/db/local-runtime-privileges.sql`，位于迁移目录外。
  普通业务表、视图、序列和可调用函数获得必要权限，未来 owner 创建的对象也有对应默认授权。
- 保留迁移历史、审计父表/分区、不可变历史来源凭证、导入和维护专用函数的边界。
  不创建旧清空函数，不恢复旧权限，不授予超级用户、对象所有权或迁移角色成员资格。
- 删除开发配置中遗留的“测试数据清空”监听说明，回环监听本身继续保留。
- 不修改已应用的 Flyway SQL、数据库账号密码、对象 owner、管理员账号或业务授权数据。
