# 极端负载、中断与内置运行日志

用户最新要求：停止反复索取采集包，直接做大数据加载、快速连续操作、取消/中断等极端验证；各 Windows 安装版本内置可直接复制的 `.log`。本阶段继续独立分支实施，不修改业务库、不替换现用客户端、不推送/部署、不生成正式 Setup/更新 ZIP。

## 已找到并修复的资源风暴

新增 50,000 行、6,727,791 字节 JSON 的 24 次交叠读取/不断换代用例。旧实现对每个大响应直接启动 compute；过期读取虽不发布结果，仍全部解析，造成 isolate-group 分配和 GC 压力。首轮新增延迟断言失败，实测事件循环最长间隔 **15,492ms**，原失败日志保留。

新增唯一 CPU 数据工作准入入口 `DataWorkQueue`，默认最多 2 个有效工作并发；所有仍有效的工作保持 FIFO，不丢弃、不截断、不重放。只有调用方原有 `isCurrent` 围栏明确失效的读取才可淘汰。排队期间持续清理失效任务，每批最多 64 项后让出真实事件循环，避免取消风暴本身堵塞输入；不等慢任务结束才释放排队的过期数据。

同一规模后续样本完整保留最后一份 50,000 行、原文数量和金额字符串，23 次过期结果不发布；事件循环最大间隔分别为 10 / 14 / 15ms，样本总耗时约 277–310ms。不同轮次后台负载未严格隔离，不能据此声称固定速度提升比例；有界准入、原数据保全及过期结果隔离另有行为测试支持。

## 公共入口与完整迁移清单

| 调用方 | 旧机制/现机制 | 业务差异与验证保护 |
|---|---|---|
| `responsive_json_decoder_native.dart` | 大响应逐个 compute → 公共准入后 compute | 64KiB 以下原快速路径；保留完整 UTF8/JSON、身份/代次和 disposed 错误语义 |
| `responsive_json_decoder_web.dart` | Worker 消息直接并发 → 同一公共准入 | 继续同源 Worker 和分片物化；失败不偷偷回退主线程大解析 |
| `responsive_data_codec_native.dart` | 大数据直接 compute → 公共准入 | JSON/base64/UTF8 共用；公开入口仍在首次 await 前冻结容器及字节，原文/精度不变 |
| `responsive_data_codec_web.dart` | 多个 Worker 编码/物化任务并发 → 公共准入 | 保留 token 化、真实分片、同源 Worker、异常和取消合同 |
| `attachment_preview_parser.dart` | Native compute / Web 分片分别直接开始 → 都按公共准入 | 原件不改，预览关闭可退场，保留文本/CSV/ZIP 的完整解析合同 |
| `form_draft_storage_native.dart::_sameRaw` | 大字符串 CAS 比较直接 Isolate.run → 公共准入 | 输入字符串不可变；有效 CAS 前置工作必须完成，不能静默取消或重放写入 |
| `isolated_print_pdf_native.dart` | 保留既有每实例单飞、可立即终止的专属 Worker | 它拥有打印 worker/端口/退出生命周期和原请求快照时点，不改成无界排队；另跑打印/退出回归 |
| WPF 网络/读取 | 保留 ManagedTlsHttpHandler 的 8 槽网络限制与后台阻塞通信 | WPF 不使用 Dart isolate；未迁移的大表业务不虚称完成，不强并网络和 CPU 两类预算 |

扫描到的真正 Native compute / Isolate.run 数据入口均已按上述语义迁移。`uten_editable_grid.dart` 的局部 `compute()` 是同步局部函数名，非 isolate；不作机械替换。独立打印 worker 保留有理由的生命周期差异。

公共准入没有改变服务端计算权威、币种/单位、输入/草稿快照、CAS、权限、幂等、未知提交或写请求重试。相关完整数据、迟到/取消、草稿历史及附件回归继续保留。

## 自动 `.log` 的入口和使用

安装版默认记录，无需另外运行采集脚本。设置“运行日志”可直接导出 `.log`，桌面平台可打开日志目录；WPF 登录页“运行日志”与关于页也能打开目录。新 Setup 提供 Start Menu 的 Logs 目录快捷入口，ZIP 升级/便携运行仍可从应用内导出，不依赖快捷方式存在。

Windows 根目录：`%LOCALAPPDATA%\com.uten.uten_imp\client-logs\`。

| 组合 | 子目录与内容 |
|---|---|
| Win10/11 Flutter x64 | `flutter\x64\Release`；内部 Profile/Debug/Harness 分开。`app-*.log`、`native-*.log`、独立 `fatal-native-*.log` 及最近更新日志快照 |
| WPF 候选 x86/x64 | `wpf_legacy\<实际进程架构>\Debug或Release`；程序、独立 updater 都从同一 C# 源编译日志能力，updater 不增加外部 Core DLL 依赖 |
| macOS/Linux/Android/iOS Flutter | 同一 Dart 日志入口，写入各端应用私有目录；复用既有跨端保存入口导出 `.log`。本机未做这些原生系统的实机验收 |
| Web | 限量内存环与 `.log` 导出；网页不能按安装版目录自动写 Windows 文件，关闭/刷新后的留存不冒称已具备 |

日志 v1 为 UTF8 操作记录：版本/构建、运行时、异常类型/有限代码栈、脱敏请求路径/状态/耗时、更新按钮点击与阶段。Windows 原生层独立记录崩溃异常码、模块/RVA、PDB GUID、地址帧和访问地址；后台心跳记录无响应与恢复，不终止应用。原生 GUI 的引擎错误仅归类，原始输出不写入日志。

不记录账号、口令、token、请求/响应正文、业务输入或 widget 内容；不自动上传、不收集进程内存。URI 去 host/query 并模板化标识符。Dart/C# 共用 `test/fixtures/client_diagnostics_v1.json` 正反向样例。原有错误呈现/异常传播保持，不把崩溃吞成成功。

正常写入异步且有界；最多 256 条待写，溢出记录丢日志计数，不影响业务操作。单文件约 2MiB，默认保留最近 16 个本应用日志文件，活跃文件/文件锁无法删除时先保留，不触碰其他文件。原生紧急异常使用预先打开的独立文件，不等待正常 writer 锁；满盘/只读时 Dart 可从限量内存导出，不重试业务请求。只清理已证明位于日志目录、匹配本应用日志名的普通叶文件，不递归删目录、不跟随链接。

## 实际压力验证与当前边界

原始结果都在本工作树 `build/stability-native/`，不进入 Git。最终汇总回执与源码指纹在阶段证据中绑定。

- 50,000 行/24 次换代：保留原 15,492ms 失败，后续有界工作回归通过；完整行数、精确字符串、null、流中断后恢复、处理中 dispose 均验证。
- 10,000 个排队读取退场仍让出输入；两个有效任务被阻塞时，后续过期数据也可先退场；仍有效工作 FIFO、错误原样传播且只执行一次。
- 10,000 条日志突发、磁盘写失败、日志轮转、保留非日志文件、敏感内容剔除，以及设置导出/重复点击/离页晚回调通过。
- 原生子进程故意卡住消息线程、恢复并 RaiseException(C0000005)，无需采集工具即可在退出后读到 `.log`；32 项后台/生命周期/日志断言通过，包含原有更新 helper 的接受/取消隔离。
- Windows 混合实际样本：53/53 窗口动作、连续原生 MSAA `accHitTest`/树遍历 133 次、0 调用失败，1,764 次弹窗/节点切换、415 次读取退场、29 次完整读取、最终 50,000 行；UIA 计数与最终模型计数同为 1,764，事件循环最大间隔 141ms，原始输入保留、框架异常 0。该轮 `.log` 未见 bridge 错误、无响应或 native fatal。此连续观察纠正了首轮单次快照计数差可能被误读为冻结的问题。
- WPF 已在本机跑 x86/x64 编译和原生 runner；新增日志样例/隐私/保留断言纳入同一 runner。Win7 目标机、完整 ERP 迁移及真正安装/更新验收仍未完成。
- Web 使用本地合成 JSON 与生产同源 Worker/分片解析执行，避免把构造测试数据的 CPU 时间混入业务解码指标；最终实际浏览器结果见阶段汇总。原 Windows Flutter Chrome test loader 的 SDK 路径问题仍单独留作未通过，不能与实际构建浏览器验证混算。
