# 历史账户流水按批重建月汇总

旧库账户流水允许存在带负号的冲销事实。原始流水的来源校验已由 V626 提供；V408 月汇总的非负约束约束的是一个账户、币种和月份的最终合计。逐行执行 `INSERT ... ON CONFLICT` 时，PostgreSQL 会先检查待插入的负数增量，因此即使已有月合计及最终合计合法，也会提前拒绝原始流水。

V916 和 `bootstrap-v19` 保留流水原金额、账户对应关系、原始来源及现有月汇总约束。只有首次导入、完整通过 V626 证明的 `ACCOUNT_FLOW` 历史快照采用批量投影：先导入全部原始流水，再执行既有月汇总重建和完整性核对。普通业务的流水新增、更改、删除及冲销继续走原有规则。

该分支要求同一来源事务、冻结代码、输入清单和文件 SHA，以及包含 19 个业务字段的完整目标投影；首次使用的事务号、集群标识和数据库 OID 由数据库绑定并保持不可改。恢复到另一集群或数据库后，旧事务号不能单独充当新业务的导入授权或冻结条件。

收尾顺序为：所有导入模块及结构核对完成，在同一事务内标记本轮成功，立即验证全部延期约束，写入原有审计汇总，然后提交。任何检查失败都会回滚整个业务事务。数据库还会检查最终月汇总；同一导入事务成功后，不能再修改或清空已核对的月汇总，也不能降低完成状态。没有可靠用量的原料对应关系等其他待核数据，不会因资金模块通过而变成已确认业务数据。

独立验收另从冻结 CSV 推导原始流水、保留与归档范围，以及每个月的金额、行数和顺序边界，并与实际数据库比较。验收不得仅依赖导入程序调用的重建函数或完成标记。实际 schema 至少为 V916，或映射版本至少为 v19 时，必须通过 `finance_flow_monthly.verified`；省略预期 schema 不能关闭该检查。

本地冻结源码可以不含其他任务尚未集成的版本号；Flyway 允许版本缺号，迁移清单和数量必须以实际冻结源码及真实历史为准。服务器的角色、权限及额外迁移单独核对，不能复制本地超级用户权限、修改历史记录或使用 `repair` 冒充兼容。

本说明描述修复规则。整批导入、实际应用读取、本地切换、备份恢复和公司服务器更新，分别以对应实际收据为准；隔离测试不能替代这些步骤。
