# 浏览器草稿迁移自阻塞根因修复

本轮在发布整合中追查基线 `6ea02b292` 的 Flutter/Web CI 失败。公司数据库、服务端及业务草稿内容均未被本轮排查写入；复现使用独立测试 IndexedDB。

## 根因与修复

CI 中业务重置和缺失历史头的用例偶发报告“草稿存储被其他网页占用”。共同入口是 `BrowserFormDraftStorage._openDatabase → _readRawDrafts → _upgradePreparedDatabase`，并不是这两项业务规则本身失败。

旧准备读取只等待 `getAllKeys/getAll` 请求成功，没有等只读事务完成。随后 `database.close()` 仅设置待关闭标记，立即发起 v2 升级时，自己的旧事务仍可能占用连接，触发 `blocked` 并被误报成其他网页占用。[IndexedDB 关闭算法](https://w3c.github.io/IndexedDB/#close-a-database-connection)明确要求等连接的全部事务完成后才真正关闭；[升级算法](https://w3c.github.io/IndexedDB/#open-a-database)会在旧连接尚未关闭时发送 `blocked`。

真实 Chrome 独立 API 复现的 100 轮中有 1 轮出现自阻塞，完整事件顺序保留于 `output/idb-cdp-probe-result.json`。原实现浏览器套件还自然复现了“新服务端数据集”用例的相同错误，表明失败名称会随时序变化。

修复保留唯一准备读取入口，同时等待两个请求与事务 `complete`，监听请求、事务错误和中止，再继续关闭及升级。没有增加任意延时、忽略错误、降低旧断言或重复尝试来掩盖故障。原 v1 原文检查、三次有界迁移尝试、升级中止、未来版本拒绝、原始附件、CAS 与业务重置约束保持不变。

## 公共入口和平台复查

| 入口 | 结论 |
|---|---|
| Web 浏览器草稿及草稿历史 | 全部经同一 `BrowserFormDraftStorage` 处理；修复该准备事务边界。 |
| Web 设备审计回执 | 直接打开固定 v1，无“先读旧库再升级”的阶段，不存在相同自阻塞路径；纳入浏览器回归。 |
| Flutter 原生桌面草稿及历史 | 使用文件锁和历史日志的独立实现，没有 IndexedDB 连接升级；本轮未改变共享 API、原文、权限、版本或业务规则。 |
| Win7 WPF 候选 | 不执行 Dart 浏览器存储实现；不因本轮修复提升迁移或目标机验收状态。 |

仓库全部 `indexedDB.open` 调用均已核对：草稿的准备/升级两处和设备回执一处。没有创建平行存储实现。
