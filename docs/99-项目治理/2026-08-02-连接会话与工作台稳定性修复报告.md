## 一、执行结论

本次不是单一“admin 权限丢失”，而是多个独立故障在同一时间被用户看到：

1. 过大的 JWT 与设备审计请求头可在 Tomcat 解析鉴权过滤器之前被拒绝，前端又把部分异常误显示为无权限；
2. refresh、登录、退出和多标签页之间缺少足够强的代次边界，短暂网络故障可能错误破坏仍有效的本地会话；
3. `localhost 拒绝连接` 表示入口静态服务或代理端口没有监听，它与账号权限不是同一条故障链；
4. 生产履约工作台的原生时间列可能由 PostgreSQL/Hibernate 返回 `Instant`，旧映射只接受部分时间类型；
5. Dashboard 聚合曾让工作台一个分区故障放大为首页整体失败；
6. 旧健康探测路径和宽松响应判断可能把 SPA HTML 假 200 当成后端恢复。

源码候选已经把这些链路拆开处理：最小 JWT、服务端权限解析、原子会话记录、精确结构化拒绝、保守自动重连、只重试安全读、退出撤销持久队列、工作台 UTC 时间映射、Dashboard 局部降级、严格 health、Nginx/systemd/watchdog 模板。

用户侧原则是：正常使用过程中遇到短暂断网、后端 5xx、代理 HTML/空响应、权限服务短暂不可用时，不应被误踢下线；连接恢复后尽量自动继续。任何业务写请求都不静默重放，避免重复下单、重复审批或重复过账。

## 二、事故证据与故障链

### 2.1 已有证据

- 用户提供日志在 2026-08-02 09:35 出现 Tomcat `Request header is too large`；
- 同一进程的定时任务日志持续到约 09:55，说明请求头解析失败并没有直接杀死 JVM；
- 用户先看到“无权限”，刷新后看到“localhost 拒绝连接”；
- 同时反馈工作台“更新时间类型异常”。

因此，不得把三个现象都归因于“admin 权限被收回”。

### 2.2 独立故障链

| 故障链 | 技术含义 | 本次处理 |
| --- | --- | --- |
| 请求头超限 | 请求在进入 `JwtAuthFilter` 前被容器拒绝，不是业务权限判定 | staff JWT 缩为最小身份声明；设备审计头限长；Tomcat 采用有限 16 KiB 预算；网关做有限缓冲和真实 12/18 KiB 验收 |
| 权限解析暂时失败 | 服务可达，但数据库/权限依赖暂不可用 | 后端返回结构化 `503 SERVICE_UNAVAILABLE`；前端保留会话，不显示成账号无权限 |
| refresh/多标签竞态 | 旧请求可能覆盖新登录、退出或密码变更 | `generation + intentGeneration + sessionLineage`、跨标签锁、CAS、latest-intent-wins、旧响应隔离 |
| 代理/WAF 异常 401 | HTML、空体或未知 code 不能证明 refresh 已失效 | 仅精确的 HTTP 状态码与结构化 code 同时匹配才清会话 |
| localhost 连接拒绝 | TCP 目标端口没有监听；浏览器内代码本身已无法运行 | 生产入口必须是受监督的 Nginx/静态制品与 Spring 服务；提供 systemd 和 JVM 外 watchdog 模板 |
| 工作台时间异常 | 原生 SQL 时间类型随驱动/查询形态返回不同 Java 类型 | 接受 `OffsetDateTime`、`Instant`、`Timestamp` 并统一为 UTC |
| Dashboard 连锁失败 | 一个分区异常拖垮首页聚合 | 履约分区独立降级并返回 warning；仅降级期间每 15 秒重试 |
| 假健康 | SPA fallback 可把错误路径返回为 HTML 200 | 只认 `/actuator/health` 的 HTTP 200 且 JSON `status=UP`；其他 Actuator 路径固定拒绝 |

## 三、稳定性硬性不变量

以下规则是后续修改必须保持的验收边界：

1. 瞬态网络错误、超时、429、5xx、结构化 503、HTML/空体/未知 401 不得销毁有效会话；
2. 只有当前 session lineage 未变化，且 refresh 响应命中精确状态码与 code 合同时，才可结束会话；
3. 登录、refresh、logout 为公开鉴权交换，不读取权限后才放行，也不携带残留 `Authorization`；
4. 登录、退出、密码变更和 refresh 使用原子记录及 CAS，旧异步响应不得覆盖用户更新的意图；
5. token 和待撤销队列只保存在安全存储，不进入 `localStorage`、SharedPreferences 或跨标签广播正文；
6. 业务写请求不因连接失败自动重放；只允许 GET/HEAD/OPTIONS 做有限重试；
7. 连接恢复必须通过严格后端健康响应确认，不能仅凭浏览器 online 事件或任意 200；
8. 工作台一个分区失败不得伪装为权威零数据，也不得拖垮其他 Dashboard 分区；
9. 静态入口和后端进程必须由操作系统或编排器监督；浏览器无法在入口服务已停止时自救；
10. 源码验证、空库迁移或本机端口可用不等于公司环境已恢复。

## 四、已实现修复

### 4.1 后端鉴权与请求头

- staff access JWT 仅携带 `sub`、token 类型、授权版本和授权纪元等最小声明，不再携带完整角色/权限集合；
- 每次请求由 `StaffAuthorityResolver` 从服务端解析当前账号状态和权限；缓存按授权版本隔离、短 TTL、有界，账号停用、密码重置或管理员变更会通过版本变化失效；
- 权限解析或依赖故障返回结构化 `503 SERVICE_UNAVAILABLE`，不伪装为 401；
- 公开 login/refresh/logout 路径跳过残留 bearer 处理；
- Tomcat 请求头预算默认 16 KiB，设备审计上下文客户端编码上限 1536 字符；预算仍是有限防护，不允许以后用无限增大头部代替根因治理；
- 自动化覆盖约 12 KiB 请求头可达应用、约 18 KiB 请求头由容器以 400/431 拒绝。

### 4.2 会话与多标签页

- access/refresh、`generation`、`intentGeneration`、`sessionLineage` 写入同一个原子安全存储记录；
- 登录先预留新 intent/lineage，提交时使用 CAS；最新用户意图胜出；
- refresh 只能更新读取时同一代次的会话；退出、重新登录或密码变更后到达的旧响应被拒绝；
- 已带旧 lineage 的慢 GET/POST 响应不会交付给新账号，客户端返回本地 `409 SESSION_CHANGED`；写请求不会因此自动再发；
- 权威记录损坏时写入 fail-closed tombstone，旧双键 token 不会复活；
- Web Locks 有超时和租约回退；BroadcastChannel 只发送非敏感变更元数据；
- login/refresh/logout 在读取安全存储之前即作为公开交换处理，并主动移除残留 Authorization，避免存储故障阻断登录和退出。

### 4.3 精确 refresh 分类

只有以下组合是破坏性凭据拒绝：

| HTTP | code |
| --- | --- |
| 401 | `UNAUTHORIZED` |
| 401 | `ACCOUNT_LOCKED` |
| 401 | `ACCOUNT_DISABLED` |
| 422 | `VALIDATION_FAILED` |
| 403 | `VISITOR_BLOCKED` |

状态码与 code 必须同时匹配。HTML、空体、未知 code、状态不匹配、429、5xx、超时和断网都按“暂时不可用”处理并保留当前会话。

### 4.4 退出与最终撤销

- 用户操作后界面立即本地 fail-closed，后续页面不能继续使用旧会话；
- 非敏感 logout fence 先落盘，阻止应用重启时从旧凭据恢复；显式新登录可有序覆盖 fence；
- 普通 logout 撤销 refresh，不保证已经签发或泄露的 access 立即在服务端失效；access 最多存活到短 TTL（源码默认 15 分钟）。要求立即全局清退时必须另行递增 `auth_version`/授权 epoch 或轮换 issuer/签名密钥，并执行相应发布验收；
- 跨标签 token-record 锁先捕获旧 refresh，并在删除唯一副本前把它持久交接到加密待撤销队列；
  交接成功后才写 logout tombstone。交接失败按 0/30/120 ms 重试，fence 与原 token record 保留供
  再次操作；网络撤销异步执行，不让老人等待网络超时；
- 队列去重、最多 32 条、保留 30 天；损坏队列隔离删除，不影响当前认证记录；
- 应用启动、连接恢复和 5 秒/30 秒/2 分钟/10 分钟/30 分钟封顶退避会继续排空；同一时间只运行一个 drainer；
- 服务端 logout 为公开幂等：已撤销、未知或空 token 不泄露差异；匹配 token 的审计记录 owner 用户 ID 与 token UUID，不记录 token 原文/hash；after-commit 审计故障不回滚已经完成的撤销。

### 4.5 自动连接与简单交互

- 安全读 GET/HEAD/OPTIONS 遇瞬态连接错误时最多额外重试两次，间隔 400 ms、1200 ms；
- POST/PUT/PATCH/DELETE 等业务写请求绝不自动重放，用户看到明确结果后再决定是否重试；
- 断开后后台以 2/5/10/15 秒为上限探测，并在 0.85–1.0 范围抖动，避免同一办公室 NAT 下所有终端同一时刻冲击服务；
- 手动“重新连接”按钮立即探测，不等待退避；按钮触达高度不小于 48 dp；
- 严格恢复条件为根 `/actuator/health` 返回 HTTP 200 且 JSON `status=UP`；
- 提示使用普通中文：“网络连接异常，系统会自动重试”“网络已恢复，可以继续使用”；恢复状态通过语义 live region 告知辅助技术，并尊重 reduced-motion；
- 恢复后唤醒 Riverpod 网络状态图；生产履约工作台重新加载当前可见页；Dashboard 只在存在 `FULFILLMENT_UNAVAILABLE` 时每 15 秒重试，正常状态不持续轮询。

自动连接的边界：如果浏览器中的 App 仍在运行而 API 暂不可达，上述机制可工作；如果 Nginx/静态站点或用户打开的 `localhost` 入口本身已停止，页面代码无法执行，必须由 systemd/编排器/watchdog 恢复服务。

### 4.6 工作台与 Dashboard

- 原生查询时间列兼容 `OffsetDateTime`、`Instant`、`Timestamp`，统一为 UTC；
- 生产履约工作台连接恢复后自动刷新当前可见页，并保留当前筛选语义；
- Dashboard 履约分区故障时返回明确 warning 和不可用占位；`count=0` 仅是协议占位，不得解释为权威零待办；
- 认证/授权异常继续 fail-closed，不会被局部降级吞掉；普通分区故障不会拖垮整个首页。

### 4.7 部署与进程自愈模板

- Nginx 将根 health、liveness、readiness 明确代理到 Spring；其他 `/actuator/` 固定 404，并置于 SPA fallback 之前；
- health、auth、普通 API 使用分离且有限的 rate-limit 桶，降低同一 NAT 恢复风暴的相互干扰；
- Web 和 JAR 使用不可变版本目录、SHA256 校验和原子 symlink 切换，禁止通过 `current` 原地覆盖；
- systemd 模板提供启动前 symlink 校验、重启退避和资源边界；
- JVM 外后端 watchdog timer 开机宽限 120 秒后每 15 秒直连 liveness，5 秒超时，连续 4 次严格
  失败才重启 Spring；静态入口 watchdog 同频读取仅回环的 index.html 并校验制品标记，连续 4 次
  失败才重启 Nginx；Nginx master 异常退出另由 systemd `Restart=on-failure` 拉起；
- readiness 失败只摘流和告警，不触发无意义重启；外部域名、静态首页和真实业务可用性仍需独立监控。

当前源码没有旧/新 JWT 兼容 writer 开关，因此本候选不支持集群滚动混跑。目标环境只能在维护窗口全停、排空、清退会话后做单版本原子切换；若未来需要滚动发布，必须先实现并验证两阶段兼容 writer。

5. 当前无兼容 writer，必须安排全停维护窗口、排空流量、受控清退旧会话；禁止新旧 JAR 混跑。

### 7.2 切换与冒烟

1. 校验制品 SHA256，创建新版本目录；
2. 停入口、排空请求、停止旧服务并完成会话清退；
3. 原子切换 `current` symlink，启动 Spring 与静态入口；
4. 严格验证 health/liveness/readiness 均为 JSON `UP`，`/actuator/info` 为 404，后端停止时 health 不得由 SPA 返回 200；
5. 用真实 admin 做登录、权限接口、工作台非空查询、Dashboard 局部降级、refresh、logout 和再次登录；
6. 观察请求头拒绝率、401/403/503 分类、refresh 成功率、watchdog 重启、readiness、DB 连接池、前端恢复时间和待撤销队列排空。

### 7.3 回滚

1. 回滚前同样关闭入口、排空并清退会话；最小 JWT 新 token 不得直接交给旧 JAR；
2. 原子把 `current` 指回已校验的前一不可变版本，严禁原地覆盖；
3. 数据库迁移只按已审定恢复方案处理；已应用 Flyway 脚本不可改写或伪造 checksum；
4. 回滚后重复 strict health 与真实账号冒烟，并保存版本、SHA、会话清退和审计记录。

### 7.4 最低告警

- 外部静态首页或真实业务探针连续 60 秒失败；
- liveness 连续失败、watchdog 重启、systemd StartLimit 命中；
- readiness 失败或 DB 连接池耗尽；
- `Request header is too large`、431/400 请求头拒绝率异常；
- refresh 的结构化拒绝率、未知/HTML 401、503 和超时突增；
- 同一 NAT 大面积 429；
- logout 待撤销队列长期不下降；
- Dashboard `FULFILLMENT_UNAVAILABLE` 持续超过运维阈值；
- 工作台时间映射异常或查询失败。
