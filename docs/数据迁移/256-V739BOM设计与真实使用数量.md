# V739 BOM 设计使用数量与真实使用数量

> 本迁移在 feat/bom-actual-usage-20260927 分支上原号 V737；并入集成分支时目录已推进到 V738，为避免乱序改号 V739（登记序号保持 256），内容不变；258 已由 ADR-131(V740) 占用。

业务与边界见 [ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md)。目录从 V735/664 前向到 V739/665 (V736 由并行会话占用，本目录跳号)，不更改旧迁移；V711 的学习对象在本迁移里删除重建，V711 字节不变。

| 对象 | 变化 |
|---|---|
| `goods_bom_items` | `qty` 语义改名「设计使用数量」(列不变)；新增 `learning_released_at` (人工删除该组件边，学习不再自动加回)；V711 中被人工接管父件的学习边转为人工边、已删学习边补记释放时间；清除学习边上的固定备注 |
| `goods_bom_actual_usages` (新) | 按 (父件, 组件, 组件基本单位) 累计实物净耗、暴露产量、暴露族的报工不良数 `exposure_defect_qty`、样本数、重学基线与学习轮次 `learning_generation`；约束保证基线不超过累计；`actual_qty` 为生成列 (两者都大于 0 才有值)；业务清空保留；审计 NONE (派生投影) |
| `goods_bom_learning_material_totals` | 删除 (按颜色累计被上表取代) |
| `goods_bom_learning_profiles` | 删除 `enabled`；新增 `total_defect_qty` (累计不良)；计数清零后重放；审计 NONE |
| `production_bom_learning_samples` | 新增 `discovery`、`fully_cleared`、`entry_generations` (各物料首次计入的学习轮次，只增不删)、`defect_qty` (族的已审不良)；清空后重放；样本 JSON 改为 (组件, 单位) 的净耗、暴露产量、颜色明细与轮次；审计 NONE |
| `production_bom_learning_refresh_queue` | 主键改为 `(transaction_id, execution_root_id)`，外键改指 `goods` |
| `v_goods_bom_actual_usage` (新视图) | 每条真实使用数量的状态 (没有数据/父件单位变了/可用)、可用时的平均值与本轮窗口 (累计减基线)，以及不良数、实产单耗 (净耗 ÷ (良品 + 不良)) 与不良率 |
| `v_goods_bom_item_usage` (新视图) | 建在上一视图之上：每条 BOM 边是否线性、设计值、该边口径的真实值、状态 (不线性优先)、计算采用值 (6 位向上取整) 与依据，以及该边口径的实产单耗、不良数与不良率 |
| 函数 | 重建 `fn_enqueue_bom_learning / fn_refresh_bom_learning(uuid,boolean) / fn_publish_learned_bom(uuid,boolean) / fn_drain_bom_learning_queue / fn_touch_bom_learning / fn_bom_learning_manual_ownership`；新增 `fn_goods_bom_material_cost`、`fn_relearn_bom_actual_usage`、`fn_goods_structural_overproduction_rate`、`fn_remember_overproduction_rate`、`fn_remember_plan_line_overproduction_rate(plan, goods, rate)` (计划明细确认比例的唯一记忆规则，实产追加计划除外；计划服务 `ProductionOverproductionAllowance.remember` 与更新触发器共用)；替换 `fn_goods_default_overproduction_rate`、`fn_remember_plan_overproduction_rate`、`fn_remember_approved_overproduction_rate` |
| 触发器 | 学习触发器按相关列 `WHEN` 起跳 (需求表只看更新且不再监听插入)；计划明细的超产记忆删掉插入触发器、只留 `_upd` (原地改比例/来源/删除标记才起跳)，插入不再记忆 (草稿重存是删了重插，由计划服务只对新确认或改动的行记忆)；审批记忆加 `WHEN` |
| `production_material_analysis_materials` | 新增 `design_bom_qty / actual_bom_qty / usage_basis / usage_reason / usage_sample_count / usage_defect_rate`；现有 BOM 行回填设计值、`DESIGN` 与原因 `NO_DATA` (下一次人工刷新才采用真实值) |
| `production_plan_items` | 新增 `allowed_overproduction_rate_source` (`DEFAULT` / `EXPLICIT`) |
| `production_daily_report_material_usages` | 新增 `counted_leftover_qty` (最后一次报工实物清点剩余) |
| `production_daily_report_items` | 新增 `defect_qty` (报工不良数，默认 0，只记录)；约束：只能在有车间任务且良品数大于 0 的行上填；同一产出批只有第一段可带不良 (延迟约束触发器 `trg_assert_daily_report_batch_defect`)；学习触发器也随不良数变化起跳 |
| `goods.production_overproduction_rate` | 清空 V709 以来被默认值钉住的记忆，只按最新一次审批通过的比例调整恢复 |
| `business_data_reset()` | 按锚点把按颜色累计表替换为 `goods_bom_actual_usages` (PRESERVE，保留数不变) |

学习从台账事实重放：迁移清空旧样本与累计后，按每个生产族重算样本与真实使用数量，不发布、不改 BOM；现场登记的暴露产量与各族完工先后无关。业务清空前留下的旧累计基线不再保留。重放后全部累计记为基线 (学习轮次 1)：V739 之前按账面剩余退仓的净耗是计划单耗的回声，所以上线时真实使用数量全为「没有数据」，计算按设计值，与上线前相同；已存在的学习边保持原数值，实盘收尾的新数据出来后才转用真实值。

验证：完整空库迁移、校验与零重放；学习引擎真库测试覆盖暴露分母、现场登记暴露与完工先后无关、人工 BOM 父件只学真实值、不线性优先、良品退料与冲销撤回不撤边、按边接管、人工删除不再学回、重新学习及重新学习前的族以后变动只移动基线、并发删除组件时拒绝新建学习边、并发、同族两未提交事务不互等、业务清空保留；契约测试覆盖清空白名单、审计三名单、演练删除与计数豁免。测试数量与结果只记录在[治理收尾记录](../99-项目治理/2026-09-27-BOM设计与真实使用数量验收.md)。
