# 产成品待点收任务页

> **路由**：`/warehouse/production-finished-in/tasks`
> **页面**：`production_finished_inbound_tasks_page.dart`
> **后端**：`/api/warehouse/production-finished-in/tasks` 与 `/count`
> **迁移**：V338、V410–V415

## 一、职责

本页是生产 FINISHED_IN 草稿的仓库权威队列，不依赖通知。只有 FQC PASS release 足额的草稿才可进入；V338 residual/reversal replacement 沿原首次 release 谱系继承资格，不重复消费 PASS。

## 二、岗位和动作

- 查看队列需要 `stock_doc:view` 及生产库存任务对象范围；只读用户按钮文案为“查看待点收详情”。
- 逐行点收另需 `stock_doc:approve` 与 `SUB_WH` 仓储组织范围；页面不能仅因全局权限显示可点收承诺。
- 队列支持服务端分页、搜索、空态、错误重试和返回刷新；角标来自同一权威 count。

## 三、逐行实收

仓库对每个当前行填写 `acceptedQty`：

```text
0 <= acceptedQty <= reportedQty
residualQty = reportedQty - acceptedQty
```

短收必须填差异原因；当前单只按实收量入账，余量在同一事务生成同来源新草稿。整单所有行均为 0 时原单记录 `REJECTED`，不写库存、不增加 `iqty`；V418 同事务把全部未消费 PASS 额度生成同计划、同日报来源 residual 待点收单，供重新交付，不得要求车间重复报工或重做 FQC。正数实收才写库存、计划 `iqty`、销售预留/进度及不可变 confirmation。

生产完成率为：

```text
完成率 = production_plan_items.iqty / production_plan_items.qty
```

计划 10,000、仓库累计实收 1,000，显示 10%；日报申报、FQC PASS 或待点收草稿都不能提前显示为入库完成。

## 四、幂等和反向

点收请求使用稳定幂等键并锁定 inventory dimension→plan/package/segment→document/item；重复请求不能重复写库存或 `iqty`。已点收单禁止通用红冲，必须走 `/finished-in/reverse`：按原 accepted slice 反库存/`iqty` 并重建待点收 replacement，append-only 记录保留完整谱系。
