# 物料反查产成品页

> 路由：`/production/where-used` · 页面：`lib/features/production/pages/where_used_report_page.dart`
> 主查询：`GET /api/production/reports/where-used` · 专用材料候选：`GET /api/production/reports/where-used/materials`
> 基础权限：`production_where_used:view` · 初建：2026-07-28 · 本页状态：2026-08-01 实现完成，生产验收受第八节 NO-GO 约束

## 一、定位与用户目标

物料反查（where-used）用于回答：**选定一个可能被使用的货品，列出系统当前能够可靠识别的已知产成品关系，并说明每条关系来自哪里**。它不是“所有历史与理论关系绝对完整”的承诺。

典型场景包括物料替代评估、缺料影响分析、质量召回、BOM 变更评估和历史业务追溯。这里的“材料”不只限于原材料/辅料，也可能是半成品、委外件、已停用货品或仅为历史外键保留的占位货品。

页面有两处入口，均指向 `/production/where-used`：

- 工作台“工程研发部”分区卡片；
- 生产管理 hub 的“生产报表”卡片。

生产 hub 的路由准入把 `production_where_used:view` 纳入“任一生产 view”权限集，因此只拥有反查权限的用户也能进入 hub。hub 内部再按每张卡片的 `requiredAnyPermFor(location)` 过滤；未拥有 `production_where_used:view` 时不显示反查卡片，不得只依赖点击后的路由拦截。

## 二、连接与 API 契约

### 2.1 专用材料候选

```http
GET /api/production/reports/where-used/materials?keyword=&page=1&size=50
```

响应使用标准 `PageResponse`：`items`、`page`、`size`、`total`、`totalPages`。候选项字段为：

`id`、`code`、`name`、`model`、`spec`、`status`、`sourceType`、`categoryName`、`autoCreated`、`deleted`、`currentBom`、`bomIssue`、`productionHistory`、`subcontractHistory`。

专用候选搜索面向**全部匹配货品**，不再用分类或“已经存在反查关系”作为前置过滤。服务端在每个匹配项上快速标注四种证据：`currentBom`（至少一个当前有效直接父 BOM）、`bomIssue`（至少一个直接非正用量或自环）、`productionHistory`（新旧生产历史）和 `subcontractHistory`（委外历史）。多级祖先和上游异常由选中后的主查询递归计算，不在候选页对最多 50 项逐条递归。

因此候选搜索必须满足：

- 原料、辅料、半成品、委外件及其它名称/编号匹配的货品均可返回；
- 已停用、软删除、`auto_created=true` 的历史锚点不被静默排除，而是显示“已删除”“自动占位”“状态：X”等明确标签；
- 四个证据标志均为 `false` 的货品仍返回、可选择，并显示“暂无已知关系”；选择后由主查询给出可信空结果，而不是在入口阶段漏掉它；
- 初次打开和清空关键词时显示“输入编号/名称开始搜索”，前端不发请求；后端收到空白关键词也直接返回空 `PageResponse`；
- 仅对 trim 后非空关键词启动 250 ms 防抖；按搜索键可立即查询，清空会取消等待并使旧响应失效，迟到响应不得覆盖新关键词；
- 服务端将 `code`、`name`、`model`、`spec`、`series`、`c_number`、`material`、`require_remark` 小写拼接后执行包含匹配；V186 的同表达式 trigram GIN 索引支持 `%keyword%`；
- 搜索值先将反斜杠、`%`、`_` 依次转义，包含匹配和前缀匹配都使用 `LIKE ... ESCAPE '\'`；这三类用户输入是字面字符，不得扩展为 SQL 通配符，精确匹配排序仍使用未转义的小写关键词；
- 排序依次为编号/名称精确匹配、编号/名称前缀匹配、其它包含匹配，再按未删除、非占位、编号、名称和 UUID 稳定排序；不按“是否已有关系”改变匹配优先级；
- 每页最多 50 条。SQL 先在 `matched_goods AS MATERIALIZED` 中完成搜索、总数、排序和分页，再只对当前页最多 50 项计算 BOM/生产/委外 `EXISTS`，避免宽关键词对全量历史逐条探测；
- 非首页越界而返回空行时，服务端使用同一八字段表达式和同一字面转义 pattern 单独回查 `COUNT(*)`，正确返回 `total` / `totalPages`；该校正计数不执行逐项来源 `EXISTS`，也不能把真实总数伪装为 0；
- 候选接口只要求 `production_where_used:view`，不额外要求 `goods:view`，但服务端仍须执行与主查询一致的数据范围裁剪。

候选弹层在紧凑屏为约 92% 高底部抽屉，在中大屏为居中对话框。选择后保存稳定的 `goods.id` UUID，不得传 legacy ID、显示编号或名称。

### 2.2 主查询

```http
GET /api/production/reports/where-used
    ?materialGoodsId=<goods UUID>
    &source=all|current|history|production|subcontract
    &dateFrom=<YYYY-MM-DD，可选>
    &dateTo=<YYYY-MM-DD，可选>
    &page=1&size=50
    &sort=<白名单字段>&order=asc|desc
```

- `materialGoodsId` 必填，并与候选项 `id` 原样连接；
- `source` 可选且默认 `all`；白名单为 `all`（全部）、`current`（仅当前 BOM）、`history`（全部历史）、`production`（仅生产历史）、`subcontract`（仅委外历史），其它值返回 4xx；
- `dateFrom`、`dateTo` 均可空。两者都不传代表**全部历史**；仅传一端代表开区间，日期端点按自然日包含；
- 日期只约束生产历史和委外历史，**绝不约束当前 BOM**；
- 主结果统一使用 `goods.id <> :material` 排除所选物料自身；候选的生产/委外来源标记也排除产品与材料同 UUID 的自关联，BOM 自环只标记为 `bomIssue`，不得进入 `currentBom`；
- 服务端校验 `dateFrom <= dateTo`；非法 UUID、非法日期和非白名单 `source` 返回明确的 4xx，不得伪装成“0 条结果”。`page<1` 归一化为 1；候选 `size` 收敛到 1–50，主查询 `size` 收敛到 1–200；非白名单排序键回落默认排序，`order` 仅 `desc` 取降序、其它值按升序，用户原始串绝不进入 SQL；
- 200 且 `total=0` 才是可信空结果；401/403、连接失败、超时和 5xx 必须显示对应错误与重试入口。

候选和主查询的 Flutter 异常处理都保留 `ApiException.message`，只在非 API 异常时使用通用失败文案；不得把服务端验证、权限或业务错误统一吞成“搜索无结果”。

`source` 是查看范围而不是互斥的数据分类：`production` 包含 legacy 生产快照和全部已归属执行段需求；其中 `supply_route=SUBCONTRACT` 的执行段也会命中 `subcontract`。前端可分开展示两种视角，但不能假定两者相加等于去重后的 `all`。

响应 `meta` 必须回显归一化后的 `source`、`historyDateFiltered`，并通过 `unattributedDemandCount` / `unattributedDemandQty` 报告“存在材料需求但缺少执行段、无法稳定归属产成品”的记录。此类记录不能硬猜产品，也不能静默丢弃；页面应显示覆盖警示，并把它计入生产验收 NO-GO。

Flutter `ApiClient` 传相对路径 `/production/reports/...`，由统一 API base 拼接 `/api`。排查“始终为 0”时，依次核对候选 UUID、请求参数、HTTP 状态、响应 `total`、`meta` 和来源覆盖，不应把业务空结果简单归因于连接失败。

## 三、来源口径与数据可信度

页面固定告知：“当前可用的已知关系 = 当前 BOM + 新生产需求 + 旧生产快照 + 委外历史证据”。同一产成品可以命中多个分区，但指标必须分卡呈现，**不得跨来源相加为一个‘总用量’**。

| 弹窗分区 | 主要数据 | 日期作用 | 正确含义 | 可信度/限制 |
|---|---|---|---|---|
| 当前理论 BOM | `goods_bom_items` 且路径用量均 `> 0` | 不作用 | 查询时有效的直接或多级理论关系 | 是当前关系，不是历史版本 |
| BOM 用量异常 | `goods_bom_items` 中含 `qty <= 0` 的路径 | 不作用 | 已知异常关系，已从当前有效 BOM 排除 | 必须治理，不能进入当前用量 |
| 新生产履约需求 | V155 `production_material_demands` + 可归属执行段 | 作用 | 新系统冻结到具体产成品的需求 | 有效汇总只计已审核、未中止、未取消计划；终态只保留证据 |
| 旧生产排产快照 | legacy `production_plan_costs` | 作用 | 冻结的 BOM 展开、领料和退料字段 | 不是当前 BOM；展开需求不是实际消耗 |
| 委外历史证据 | `route=SUBCONTRACT` 需求、`subcontract_order_cost_items`、`subcontract_material_issue_items` | 作用 | 委外需求、成本快照和发料痕迹 | 发料/退料/损耗数量仍待复核 |

### 3.1 当前 BOM

- `qty > 0` 的路径进入当前理论 BOM；从材料端索引开始反向递归，使用 `UNION` 按“产成品 + 路径有效状态”去重并自然收敛成环数据，无固定深度上限；
- 同一材料经多条路径到达同一产成品时，主结果只保留一行；直接关系显示直接单套用量，间接关系不把多条路径用量强行相加；
- 含 `qty <= 0` 的路径通过候选 `bomIssue` 和结果 `__invalidBom` 标记为“BOM 用量异常”，不得进入当前有效关系；结果只在没有其它有效路径兜底该产品时单列异常区；
- 软删除关系、软删除/自动占位端点及无效 stub 按当前 BOM 有效性规则隔离，不得重新进入当前 MRP 口径；历史来源仍可保留这些身份用于只读溯源。

### 3.2 新生产需求与旧生产快照

新生产履约需求只把 `execution_segment_id` 能关联有效执行段的 `production_material_demands` 归属到 `segment.product_goods_id`。弹窗分别显示全部归属段证据、有效执行段数、需求量、单产品需求范围、首次/最近需求，以及其中委外段和委外需求量。有效数量汇总同时要求需求不是 `RELEASED` / `REVERSED`、执行段不是 `CANCELLED` / `REVERSED`，且生产计划 `status=1`、`is_stopped=false`、`is_canceled=false`。其它已归属的终态/无效记录只保留为关系证据，不进入段数、数量或日期汇总。

没有执行段的需求不能可靠归属产成品，只通过响应 `meta.unattributedDemandCount` / `unattributedDemandQty` 显示“系统未作猜配”，不生成虚假结果行。

旧生产快照中，`production_plan_costs.qty` 是历史 BOM 展开后的计划需求量，不能命名为“实际用量”“消耗量”或“实发量”。`bill_item_id` 是计划行标识；弹窗把全部快照证据、有效计划单数和计划明细数分开，不能把 `COUNT(DISTINCT bill_item_id)` 冒充计划单数。旧快照的有效计划、明细、展开需求、领退、单耗和发生日期也只计 `plan.status=1` 且未中止、未取消的计划；未审核、红冲、中止、取消或无法连回计划的快照只计入 `__legacyEvidenceCount`。

同一产成品历史上可能使用过多个 BOM 版本，`MAX(dqty)` 只能代表历史最大单耗，不能代表“当前单支用量”。详情至少要区分历史最小/最大单耗、首次/最近发生日期；如展示“最近单耗”，必须按确定的日期与主键稳定取最后一条，而不是用 `MAX` 代替。

产成品编号、名称、规格、分类来自查询时的当前 `goods` 主档，只是当前显示值，不是历史快照。主档变化不能反推当时采用的 BOM 版本。

### 3.3 委外计划与实发

- 委外分区同时容纳新生产需求中的 `supply_route=SUBCONTRACT` 子集、委外成本快照和委外发料痕迹，但三类指标分开；
- 委外成本快照只在 `order_item.id = cost.order_item_id` 且 `order_item.order_id = cost.order_id` 两把父单键同时一致时，才归属到该订单行产品，防止错单/脏数据串单；
- 委外发料以单行可验证的成品归属为准：优先使用有效订单行的 `goods_id`，该行无法连回订单行时才回退其冻结的 `parent_goods_id`；不凭单号、名称或编号模糊归属，也不跨单头拼接；
- 弹窗分别显示委外需求段证据、成本证据、订货单/明细、展开需求和单套用量范围，以及发料证据和发料单数；
- legacy 委外实发历史仍待重导、重迁和业务复核。运行时 UI 只显示“待迁移复核/仅作追溯”的品质警示，不硬编码审计行数；`__subcontractIssueQty`、`__subcontractReturnedQty`、`__subcontractWastedQty` 必须分别显示为“发料痕迹数量（待核）”“退料痕迹数量（待核）”“损耗痕迹数量（待核）”，只证明曾有关联，不得用于库存或财务结算。本文第八节仍保留截至 2026-08-01 的确切审计快照。

## 四、日期、搜索和空状态

页面默认不预填日期，首选口径为**全部历史**。日期属于可选的“历史范围”高级条件：

- 关闭/清空日期后恢复全部历史；
- 选择日期后，当前 BOM 命中仍保持不变，生产和委外历史按范围重算；
- 修改材料或日期会立即废弃旧结果，页码回到 1；迟到的旧请求不得覆盖新条件；
- 点击排序、翻页和打开详情都使用最后一次成功查询的条件快照；
- 空状态应说明当前覆盖来源和日期口径，例如“当前 BOM 与所选历史范围均未发现关系”，并提供“清除日期”“更换材料”操作；
- 若仅历史范围为空但当前 BOM 有结果，页面不得显示整页空状态。

## 五、结果模型与页面布局

### 5.1 主结果

主结果坚持“一种产成品一行”。合并的是产成品身份和来源标志，不合并各来源的业务指标。

桌面表格的首屏核心列建议为：产成品编号、产成品名称、规格、分类、来源、当前 BOM 关系、最近历史发生日。生产展开需求、委外计划、委外实发等高密度指标进入详情，避免横向无限扩列。隐藏关联键命名为 `__productId`；若兼容旧响应中的 `__srcId`，也只能解释为产成品 `goods.id`，不能解释为生产计划或来源单据 ID。

紧凑屏下筛选区限高为当前可用高度的 48%，并在区内独立滚动；结果区始终保留可见空间，不因材料卡、日期或大字溢出。展开屏仍使用左筛选/右结果双栏。

排序必须走服务端白名单，并在用户排序键之后固定追加产成品 UUID，保证翻页稳定、不重不漏。`count` 与数据页必须复用完全相同的数据范围、来源和日期过滤；非首页越界为空时使用同一 CTE 和 predicate 补查真实 `total` / `totalPages`。服务端限制页大小，前端不得拉全量后本地排序。

### 5.2 来源标识

每行使用带文本的来源标签：当前 BOM、新生产需求、旧生产快照、委外历史证据；`qty <= 0` 路径另标“BOM 异常”。不能只依赖颜色表达来源或质量。

顶部固定显示所选材料、来源过滤和全部历史/具体日期范围，并使用“当前可用的已知关系”口径。BOM reject、未归属需求或旧委外待核字段命中时显示非阻塞但醒目的覆盖警示，不能用“结果完整”掩盖数据边界。

### 5.3 行点击详情

整行可点击，结果区标题明确显示“关系结果 · 点击行查看详情”，不以一个无语义的箭头作为唯一提示；键盘 Enter/Space 也能打开。手机使用安全区内的高底部抽屉，平板/桌面使用居中对话框。弹窗打开后先立即展示结果行已有摘要，不等待二次网络请求；当前主档和后续证据按需加载，避免主列表 N+1。

详情按当前实现条件渲染以下分区：

1. 产成品与来源：关系来源、规格、分类及查询时主档状态；
2. 当前理论 BOM：直接/间接关系；仅直接关系显示单套用量，日期不影响本区；
3. BOM 用量异常：零数/负数路径、排除原因及“修正后才能作为当前关系”的处理状态；
4. 新生产履约需求：全部归属段证据、有效执行段数、需求量、单产品需求范围、首次/最近日期及委外子集；
5. 旧生产排产快照：全部证据、计划单/明细数、展开需求、历史单套范围、已领/已退/净领及首次/最近日期；
6. 委外历史证据：需求段、成本快照、订货单/明细、展开需求、发料证据/单数，以及发料、退料、损耗三个“待核”数量和首次/最近日期。

弹窗的字段接线保持明确：当前 BOM 使用 `__currentBom` / `__invalidBom` / `__currentDirect` / `__currentDirectQty`；新需求使用 `__executionEvidenceCount`、`executionSegmentCount` 及 `__execution*` 数量/日期字段；旧生产使用 `__legacyEvidenceCount`、`legacyPlanCount` 及 `__legacy*` 字段；委外使用 `__subcontractOrderEvidenceCount`、`__subcontractIssueEvidenceCount`、`subcontractOrderCount`、`subcontractIssueCount` 及 `__subcontract*` 字段。它们保留在行数据中但不作为普通可见列，前后端不得静默改名或串用。

来源分区之后再按 `goods:view` 懒加载“当前产成品资料”。某分区没有证据时不渲染；只有失效/红冲/取消证据时，仍说明“只作关系证据、不计入有效汇总”。

当前没有独立“where-used 详情”端点，文档不得虚构一个。现行弹窗以主结果行摘要为首屏，并按权限补取当前货品资料。未来若增加来源证据接口，应统一批量或按单个弹窗懒加载，且必须复用主查询的数据范围和权限过滤。

单个详情分区加载失败时，保留其它已加载摘要并在该分区提供重试；弹窗关闭、返回和深链返回均保留原材料、日期、排序、页码和滚动位置。异步期间防止重复打开弹窗；候选搜索和主查询都通过递增 generation 丢弃迟到响应，条件已变更的旧请求即使后返回也不得覆盖新状态。当前实现不承诺底层 HTTP 请求物理取消，加载中用已有进度态、操作禁用和失败重试表达状态。

## 六、链接与权限

`production_where_used:view` 同时保护页面、候选接口和主查询。生产 hub 准入权限集、hub 卡片过滤、路由守卫、工作台卡片显隐和后端 `@PreAuthorize` 必须一致；前端隐藏按钮不是安全边界。

| 详情动作 | 附加权限 | 链接规则 |
|---|---|---|
| 查看当前货品 | `goods:view`，并遵守货品 owner/data scope | 打开只读货品详情 |
| 查看当前 BOM | `goods:view` | 打开货品详情并定位“组装信息”页签 |
| 查看出入库流水 | `stock:view` | `/stock/movement?goodsId=<产成品 UUID>` |
| 查看生产计划 | `production_plan:view` | 仅当后端返回用户有权访问的稳定计划 ID 时显示 |
| 查看委外订单 | `subcontract_order:view` | 仅当后端返回用户有权访问的稳定订单 ID 时显示 |
| 查看委外实发单 | `subcontract_material_issue:view` | 仅当后端返回用户有权访问的稳定发料单 ID 时显示 |

后端必须在 SQL/服务层执行部门、owner 和单据数据范围裁剪，禁止把未授权产成品、材料、单据 ID、数量或来源元数据先返回再由 Flutter 隐藏。没有附加权限时，基础反查摘要仍可查看，但相关入口不渲染；详情加载 403 不能清掉已经有权看到的摘要。

跨 owner 的生产/BOM 反查范围若尚未完成产品决策和端到端授权测试，保持 **NO-GO**，不得默认放大到全公司数据。

## 七、性能设计与验收预算

### 7.1 查询设计

- 候选搜索先用 V186 combined trigram 表达式在 `matched_goods AS MATERIALIZED` 中完成全货品匹配、相关度排序、总数和稳定分页，再只对本页最多 50 项计算来源 `EXISTS`；
- 当前 BOM 反查从组件索引起步，用递归 `UNION` 去重和 cycle guard；主列表只求可达产成品，不展开全部路径；
- 生产和委外历史先按 `materialGoodsId`、可选日期和有效记录过滤，再按顶层产成品聚合；充分利用分区裁剪与材料/日期索引；
- 四来源先各自聚合为“一产品一行”后再合并，避免明细表直接 JOIN 造成笛卡尔乘积和虚增数量；
- 主列表一次返回当前页与必要摘要，详情证据懒加载；不得产生每行一次货品/BOM/权限请求的 N+1；
- 缓存或物化视图只有在明确刷新时机、失效策略、权限维度和可接受陈旧度后才能引入，不能用陈旧缓存换取表面速度。

### 7.2 V186 读侧索引

`V186__production_where_used_read_indexes.sql` 是本功能最终实现的一部分，创建 `pg_trgm` 并增加以下 partial/covering 索引：

| 查询面 | V186 索引 |
|---|---|
| 候选 combined search | `idx_goods_where_used_search_trgm`：八字段小写拼接表达式的 GIN `gin_trgm_ops` |
| 当前 BOM | `idx_gbi_where_used_active`：`component_goods_id, goods_id`，include `qty` |
| 旧生产快照 | `idx_ppc_where_used_active`：材料、日期、顶层产品和计划行，include 展开/领退字段 |
| 新生产需求 | `idx_pmd_where_used_all_evidence`、`idx_pmd_where_used_segment`、`idx_pmd_where_used_unattributed` |
| 委外历史 | `idx_scoci_where_used_active`、`idx_smisi_where_used_active`，后者 include 发料、退料和损耗字段 |

V186 最后对相关表执行 `ANALYZE`。验收必须证明候选 combined expression 命中 trigram 索引、材料条件命中各 partial 索引，并验证全历史和高扇出场景。V186 一旦应用即不可改字节；后续索引调整只能新增更高版本迁移，不得 repair 掩盖 checksum drift。

### 7.3 可量化门禁

在接近生产规模的数据集上，分别对高扇出材料的全部历史和近期范围运行 `EXPLAIN (ANALYZE, BUFFERS)`。暖缓存、服务端处理时间的目标为：候选首屏 P95 ≤ 300 ms，主查询首屏 P95 ≤ 1,000 ms、P99 ≤ 1,500 ms；冷启动单次查询应 ≤ 2,500 ms。若环境差异导致目标不适用，生产报告必须给出基线、样本量和批准后的替代预算，不能只写“感觉很快”。

前端还需满足：输入防抖 250 ms、触摸反馈 < 100 ms、长请求有进度和可重试反馈、generation 丢弃迟到响应、50 行以上列表不因一次性构建全部候选而卡顿。小屏筛选区限高且可独立滚动，页面不得横向溢出；操作目标至少 44×44 pt（Material 端优先 48×48 dp），深浅主题均满足正文 4.5:1 对比度；来源和质量状态不只靠颜色传达。

## 八、数据覆盖与 NO-GO 边界

截至 2026-08-01 的迁移审计：老库 BOM 源 218,820 行，有效迁移 198,022 行、reject 20,798 行；V181 后现库活动目标 198,025 行（含 3 条新系统手工行）、活动 stub 端点 0。20,798 条 reject 尚未完成业务闭环，因此只能声明“返回当前条件下可识别、可归属的已知关系”，不能声明“全部理论 BOM 或全部历史关系绝对完整”。

2026-08-01 本机只读复核时，后端健康为 `UP`、PostgreSQL 为 16.4，但目标库 Flyway 仍停在 V181，`idx_goods_where_used_search_trgm` 尚不存在；因此本轮只能确认连接和 SQL 契约，V186 部署后的生产规模性能仍未验收。

以下任一项未解决时均不得对该能力作生产级“结果绝对完整”承诺：

- 20,798 条 BOM reject 未分类、未闭环或未证明不影响当前反查；
- 49,889 条 legacy 委外实发数量未完成重迁/验收，仍为 `LEGACY_UNVERIFIED`；
- 跨 owner 的服务端数据范围规则未决或缺少正反向权限 E2E；
- 新增迁移尚未在目标环境从 V1 到仓库最高版本完整验证；
- `unattributedDemandCount > 0` 的需求没有完成产品归属，页面却未警示或生产报告未解释；
- 高扇出、全部历史查询未达到并记录 P95/P99 预算。
