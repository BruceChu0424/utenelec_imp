# V567 销售批量出货来源与幂等身份

日期：2026-09-12。状态：本地源码候选，未迁移现有业务库、未部署。

销售从产品进度选定本次数量，无需选择仓库。系统在原销售单与库存维度锁内复核精确预留，扣除待出货占用后，按真实叶仓拆分建议来源；现货只有10而订单1000时，本批仅开10。全局预留按实际可动库存预算找仓，不把无仓预留当成任意仓已有实物；公共池在同批多行间只使用一次。停用祖先、不参与核算或不良仓不参与新建议。

新批量请求携带本次操作的 `idempotencyKey`。V567 在现有、已审计的 `sales_shipments` 头表增加 `batch_request_key`、`batch_request_hash`、`batch_position`，不增加另一套业务表或清空分类。身份由批量入口通过不可由JSON填写的内部参数，在原创建事务的 INSERT 同时落下。数据库始终启用的不可变触发器禁止修改身份，也禁止为已有无身份历史单后补身份。创建人、键、批内序号唯一；任一分单失败时整个批次回滚。

相同人和键重放返回原有全部单号，内容变化返回冲突。软删除其中一张后，相同键不能新建替代单，原批次仍保留身份供追溯。再次发货是新的明确操作，使用新键，并重新核对数量。

商业头继续继承原订单币种、税率、业务员和结算方式；不一致的显式输入拒绝而非静默覆盖。地址、联系电话、物流号、发送人、备注及行备注原样保留。若拆成多单，物流总件数不能复制到每单；同一行拆成多单时，实际总重量也不能猜测分摊，明确提示先清空、生成后按各单实际填写。

建议仓使用V566的仓库确认模式。仓库还需明确确认实际叶仓和逐行库位，销售提交/财务商业快照的仓位含义不改变；创建草稿不扣实际库存、不增加已发，也不绕过财务或仓库实发。

`planProgress` 和原批量可发行都按真实有效订单预留、未交余量及已有待出货占用计算可开单量。进度新增 `shippableQty` 与 `pendingShipmentQty`，保留原订货、排产、生产入库、已发字段的含义。

新增 `SalesShipmentBatchPhysicalSourcesEndToEndTest` 验证1000订货、两仓3与7现货、全局与精确来源、拆单数量/头字段/仓库模式、重复请求、异内容冲突、待出货占用、软删重放与实物未出库。最终执行结果以本轮验收记录为准。
