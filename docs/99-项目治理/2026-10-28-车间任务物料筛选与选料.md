# 2026-10-28 车间任务物料筛选与选料

本记录对应本地候选工作区，范围为“我的车间任务”的可领料筛选、物料单元格入口和选料接续。沿用 `frontend-design`，保留工作区原有并行改动。本记录不代表已发布、生产验收或 Win7 业务迁移完成；实际回归结果在末尾更新。

## 需求口径与边界

- 将原“物料可领”拆为“齐套可领”和“部分可领”，筛选必须遵循同一服务端可申请事实、生产路线、认料及内料仓门禁。
- 单独识别“只缺 1 种本车间自产件”的任务，依据真实缺料需求及其供给工单所属车间，不以商品默认车间、名称或 `shortMakeKindCount` 单独猜测。
- 点击物料单元格查看当前工单的物料、供给状态和数量；可多选实际可领物料，接续既有领料核对页后提交。
- 提前领料只提前办理已有可申请量，不视为自制件已到、不自动开工、不改生产路线。WAITING 任务、未认料、未开启必要内料仓及批次专用流程继续遵守现有业务门禁。
- 领料只提交所选的准确 DRAW 来源行及其申请数量，继续采用服务端预览指纹、版本、幂等键及未知提交保护。货品同名、同码或显示单位相同不代表可以合并不同仓库、颜色、单位和来源。

## 设计方案

复用当前 Uten 主题、字形与字号，不新增业务专属字体或色板。基础角色来自 `lib/core/theme/uten_colors.dart` 与 `light_theme.dart`：品牌青绿 `#0F766E`，表面白 `#FFFFFF`，背景 `#F5F7FA`，正文 `#0F172A`，可领蓝 `#3B82F6`，缺料红 `#EF4444`；深色模式由原主题及语义前景色适配。保留原流程阶段“全部可领蓝、部分可领紫”的状态语义，不为新增弹窗改写公共流程配色。

主表物料摘要继续紧凑单行，增加清晰的可点击反馈。弹窗以物料事实和选择为中心：桌面用对齐明细，窄屏用可滚动列表；任务身份在顶部，所选数量与“去领料”动作靠近底部。物料名称、颜色、单位、缺口和可领量能直接读到，其余供给事实按需展开。只保留必要空态、错误重试和不可办理原因，不叠加说明段落。

```text
桌面：标题 / 工单身份
      物料与状态      需求 / 已领 / 缺口 / 可领      选择
      可滚动物料明细
      已选数量                                  去领料

窄屏：标题 / 工单身份
      物料名称、颜色、状态
      关键数量与选择
      可滚动物料列表
      已选数量 / 去领料
```

所有内容左对齐，数量按现有格式对齐。边框、圆角、间距、按钮及弹窗边界复用公共 token。避免以更多卡片、说明和装饰分散车间人员的选料操作；流程阶段颜色继续帮助区分任务就绪度。

真实身份及持久存储回归发现一个既有缺口：页面原快照虽包含 `uncertain=true`，公共草稿分类并未以该字段识别生产领料路由，因此原公共 unknown marker 可能为 false。已在领料页按既有可幂等重放语义覆写 `formDraftHasUnknownSubmission => _uncertain || _draftSubmissionPending`，明确把提交前的原命令快照标记为未知提交；不能仅凭保存了 `uncertain` 字段宣称恢复保护成立。

同时修复恢复链：持久化原 `submissionKey`，恢复时用原预览、任务版本、精确来源及数量重算核验；原完整命令恢复后才允许 `formDraftCanReplaySubmission`，避免公共 unknown 遮罩使原“重试领料”不可用。旧快照只有在冻结内容完整、可重建相同确定性 key 时恢复，缺项或标识不一致仍阻断。

身份/读范围失效后，迟到结果不会完成或删除原草稿；`finally` 清理页面自有 pending 状态时，mixin 的 sticky identity 栅栏停止后续自动保存，因此不会把原持久 unknown 快照改写为已确认。新测试使用真实 authenticated scope 与 `MemoryFormDraftStorage`，挂起提交后切换读范围，核对原快照包含准确来源行、持久记录逐字节不变、迟到成功不导航及不重复提交；再卸载旧页、以原 `saved.id` 重开，重试请求的 key、指纹、任务版本、来源行和数量与原请求完全相等，只重放一次。该场景已包含在最终 44 项通过回执。
