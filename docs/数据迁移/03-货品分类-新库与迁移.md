## 一、新库表设计(`material_categories`)

**范本**:`departments`(V02)——邻接表(parent_id)+ 物化路径(path,触发器维护)+ 软删除 + 审计。Flyway `V31__material_category.sql`。

### 与 departments 的差异(针对老库数据特点优化)

| 项 | departments | material_categories | 原因 |
|---|---|---|---|
| `code` | TEXT **UNIQUE** | TEXT(**无 UNIQUE**) | 老库编码大量重复("白色"×31),定位改用 `id`/`legacy_id` |
| `level` | TEXT 语义枚举 | **INT 真实深度**(根=0) | 老库 `SystemItem.Level` 不可靠,迁移按 parent 链重算 |
| `manager_id`/`headcount` | 有 | **去掉** | 物料分类无负责人/人数 |
| `legacy_id` | 无 | **INT UNIQUE** | 老库 `SystemItem.ItemID`，用于迁移溯源与重复数据识别 |
| path 触发器 | `fn_dept_path` | `fn_matcat_path`(逻辑同) | path 不要求 UNIQUE(排序用 `path, sort_order`) |

### 字段

```
id(UUID PK) · legacy_id(INT UNIQUE) · code · name · parent_id(自引用 FK)
level(INT 深度) · sort_order · path(触发器维护) · 审计4列 · is_deleted · deleted_at
```

### path 触发器逻辑

`path = 父path || code || '/'`（根节点 `/code/`），`BEFORE INSERT OR UPDATE OF parent_id, code` 触发器只重算当前节点。2026-08-02 起，真实换父由 Service 在事务级锁内防环，再以递归 CTE 按 parent 链原子重算完整子树的 `level/path`（含软删后代）；同父级请求不重算。

## 四、现役离线迁移链

现役路径为受审离线导出 → UTF-8 CSV → [migrate.sh](../../server/legacy_migration/migrate.sh) 编排 → 分类及主档 SQL → 结构对账。导出使用 [export_legacy.ps1](../../server/legacy_migration/export_legacy.ps1) 的 `GoodsCategory` / `GoodsData` 目标；分类导入是 [migrate_goods.sql](../../server/legacy_migration/migrate_goods.sql)，主档导入是 [migrate_goods_data.sql](../../server/legacy_migration/migrate_goods_data.sql)。执行前的源备份、目标库身份、批准引用、manifest 和同提交校验要求见[离线迁移运行说明](../../server/legacy_migration/README.md)。

### 设计要点

- **生产隔离**：ERP JAR 不包含 SQL Server 驱动或老库 DataSource；正式源读取只在受审导出会话中发生。
- **受控替换**：分类 SQL 在 Shell 的事务中重载主档和普通分类，保留未分类根；已使用库的下游 FK 会阻止替换，不使用 `TRUNCATE`、`CASCADE` 或关闭约束。
- **分层写入**：递归 CTE 计算父链深度，再按层 INSERT，让父行先于子行存在；源 `legacy_id` 保留用于映射和核对。
- **level 重算**：不信老库 `Level`。脚本建立 level 0 的“货品资料”分组，老库根挂在其下为 level 1，后代逐层加一。
- **孤儿处理**：缺失父节点的源分类挂到已有 `legacy_id=-1` / `LEGACY_ORPHAN` 根。V718 后货品分类注册列已置空，脚本先校验这一形态并保留该根本体；这些旧标识只用于离线适配与核验，不作为在线关系定位方式。未归位或成环来源仍须核对，不能把 SQL 执行成功当作完整对账通过。
- **GBK**：正式导出由 PowerShell/.NET SqlClient 从离线恢复库解码并生成 UTF-8 CSV；运行中 ERP 不负责源编码转换。

## 六、迁移校验

```sql
-- 按本次 CSV 行数核对导入分类，另列货品资料分组和未分类根。
-- 881 连通 / 15 孤儿是旧源快照统计，不是当前目标库的固定通过条件。
SELECT count(*) AS total,
       count(*) FILTER (WHERE legacy_id > 0) AS imported_categories,
       count(*) FILTER (WHERE legacy_id IS NULL AND legacy_code_snapshot = 'GOODS') AS goods_roots,
       count(*) FILTER (WHERE legacy_id = -1 AND legacy_code_snapshot = 'LEGACY_ORPHAN') AS orphan_roots
FROM material_categories;

-- 抽验路径与深度
SELECT legacy_id, code, legacy_code_snapshot, name, level, path FROM material_categories
WHERE legacy_id IN (2113,2283,2290) ORDER BY path;
-- 现役脚本:货品资料(level 0)→ 原材料(A,level 1)→ 包装材料(BC,level 2)→ 标贴(BT,level 3)。
-- A/BC/BT 对照 legacy_code_snapshot；内部 code/path 由当前编号规则产生。

-- 仅离线核验:V718 后注册列为空，按迁移根本体核对孤儿挂载。
SELECT * FROM material_categories
WHERE parent_id = (SELECT id FROM material_categories
                   WHERE legacy_id = -1 AND legacy_code_snapshot = 'LEGACY_ORPHAN'
                     AND is_deleted = FALSE);
```

## 八、货品主档（`goods`，V32）

货品主档表见 `server/.../db/migration/V32__goods.sql`（老库 `B_Goods` 全 78 字段迁移；图片列建 `bytea` 但本次不灌二进制）。API `/api/master/goods`：
`GET ?categoryId=&page=&size=`（分类下分页）、`GET /{id}`（详情）、`POST`（新建，`goods:edit`）、`PUT /{id}`（编辑）、`DELETE /{id}`（软删）。请求体 `GoodsSaveRequest`——只开放「标识/物理/价格」核心字段（name/code/shortName/model/spec/price/material/thickness/mWeight/pack/pieces/status）；78 字段里的成本项/图片/关联 legacy_id 暂不进表单。`goods:edit` 仅超管恒有（V32 未授部门）。

> **mWeight Jackson 坑（已修）**：实体字段 `mWeight`（getter `getMWeight()`）被 Jackson 默认序列化成 `MWeight`（连续大写不折半），前端 `fromJson` 取 `mWeight` 取不到 → 详情弹窗「单重」一直空。已在 `GoodsDetail` / `GoodsSaveRequest` 加 `@JsonProperty("mWeight")` 显式锁定键名（见 MEMORY: Jackson 连续大写字段坑）。

前端 `/basicinfo/goods`（`ProductCategoryPage`）与客户/供应商/模具页一致：详情弹框带「编辑/删除」、分类面板「添加货品」、返回键回 hub、通用 `MasterEditDialog` 表单。

> **2026-08-14 统一关联搜索**：左树顶部同时搜索分类名称/编号与货品字段，轻量定位返回全部匹配分类并展开祖先，右表承接同一关键词；管理搜索保留禁用品、排除历史 stub。根数超过 32 时分批取并集，树外 ID 失败关闭。详见 [基础资料页](../03-页面/基础资料页.md) 与 [UtenHierarchySearch](../02-组件库/UtenHierarchySearch.md)。

> **2026-08-14 分类驱动编号与 UUID 身份（V257–V279 候选）**：分类内部 `code` 作为稳定路径身份，不再让用户把它当业务前缀；旧可见编码迁到备注/只读快照，用户编辑 `code_prefix`。货品编号为空时取最近祖先显式前缀，整条路径均为空才用 `HP`，至少补六位数字；手工编号、复制/粘贴、Excel 导入和旧库重导走同一分配边界。分类前缀/父级变化先预览确认再批量改号，更深层显式覆盖子树不受影响。所有关系均以 UUID 为真源，改号不改关系；V279 将归一后的主档、单据和系统完整标识纳入全局终身保留，不再允许跨域把同一完整编号分给不同逻辑所有者。`GoodsListItem` 直接返回颜色/单位 UUID；Excel 检测逐行固化 UUID/new-token 并返回五分钟一次性 `planId`，提交时不按名称重新解析。详见 [ADR-034](../99-决策记录-ADR/ADR-034-分类驱动业务编号与UUID关联.md)与[ADR-036](../99-决策记录-ADR/ADR-036-全局业务标识与单据号命名空间.md)。

> **`auto_created` 历史引用锚（V177/V181，2026-08-01）**：迁移脚本为「老库单据明细引用了 `B_Goods` 不存在的货品号」建 stub（`migrate_subcontract`/`migrate_production`/`migrate_stock_docs`/`migrate_sales`），新库共 31 条（`category_id`/`status` 均空）。V177 加 `goods.auto_created BOOLEAN NOT NULL DEFAULT FALSE` 并回填；4 个迁移脚本的 stub INSERT 同步写 `auto_created=TRUE`。这些行只为历史单据/成本快照维持外键和原 legacy 身份，**不是待补全后继续使用的普通货品**：货品选择器隐藏，活动 BOM/MRP 拒绝。V181 软删 81 条误接入 BOM 的迁移行并加数据库守卫；历史引用锚本身不得强删（见 [31](31-货品组装BOM与成本预算.md)）。

> **`min_qty` 不迁（2026-09-29）**：新系统 `goods.min_qty` 是「安全库存（常备水位）」的**主动机制**输入——公共安全补库仅支持采购路线：非采购路线（自制/委外，即 BOM 树里全部父行）在缺口>0 时整行拦截不可下达，采购路线则每单强制按水位固定补库（消费点：`MaterialAnalysisWarehouseBreakdownReader`/`MaterialAnalysisBomSnapshotReader`/`PreplanAnalysisStockPegService` 等 7 处）。老库 `B_Goods.min_qty` 是库存报警水位（含 0.5 等非水位值），2026-09-28 全量重导把它直迁过来后，1313 条货品触发该闸，导致「物料分析父行勾选框整批消失」（自制/委外父行全部不可下达）。处置：`migrate_goods_data.sql` 与 `data/_migrate_3products.sql` 改为写 0 不迁（staging 列与 CSV 原值保留作证据）；已导库用 `UPDATE goods SET min_qty=0` 清 1313 条（重导后货品全为 legacy，无手工值受影响）。安全水位如需启用，必须在新系统由人显式逐货品配置。
