# 服务器存储管理

> 路由：`/admin/server-storage`
> 别名：服务器存储、存储管理、资源管理、受控清理

## 定位

查看服务器实际资源占用，核对保护原因后清理允许删除的资源。

从服务器状态页或服务器更新页进入。页面区分运行资源、业务原件和恢复资源，只对可信目录内符合保护规则的条目提供清理。

## 权限

超级管理员，或拥有 `server_status:view`、`server:update`、`server:cleanup` 中任一权限的员工可以查看。访客和必须先修改密码的账号不能进入。清理须超级管理员或独立的 `server:cleanup` 权限；代操作会话不能清理。清理预览和确认执行均须再认证，更新权限本身不赋予清理能力。

## 占用口径与明细

| 内容 | 口径 |
|---|---|
| 磁盘卷 | 显示总量、已用及系统保留、应用可用空间；共用同一卷的目录不重复累加卷容量 |
| 应用内存 | 进程常驻内存与 Java 堆内存分开；运行环境不支持的值显示尚未确认 |
| 数据库 | 当前数据库大小，与目录文件占用分开 |
| 上传登记 | 业务登记数量、逻辑大小和已登记存储大小；不冒充全部物理原件数量 |
| 资源分类 | 系统、安装版本、下载暂存、升级前备份、配套备份、数据库、当前上传目录、兼容旧上传目录、日志、缓存 |
| 分类与条目 | 分别显示逻辑大小、磁盘实占、估算可释放空间、修改时间、用途和保护原因 |

分类数量是目录直属条目数。兼容旧上传目录仅在部署确有配置时显示，和当前上传目录分别统计；同卷或重叠类别不能直接相加。读取失败、未接入或值未知时如实说明，不填零。资源明细按游标继续加载，当前页不足预设条数也不表示已全部显示。

逻辑大小是内容长度，磁盘实占来自分配块。估算释放量考虑硬链接与共同删除范围，不等于清理前后整卷余量之差。备份明细另说明实际隔离恢复已核对、仅留有历史恢复记录或尚未登记恢复证明，文件完整性检查不冒充恢复成功。

## 保护与清理

服务器返回的可删除性和保护原因决定是否可选，页面不能绕过保护：

- 系统目录、数据库、当前上传原件、兼容旧上传原件及私有文档不提供文件级删除；未有完整使用租约证据的缓存也受保护。
- 当前运行版本、回滚必需版本、最新至少三个版本和版本保留期内的资源受保护。旧版本即使满足至少十四天保留期，仍须通过其余保护检查。
- 下载暂存须经过至少二十四小时观察；日志只接受超过七天且已压缩闭合的受控轮转日志。
- 备份须有可信恢复证明并满足完整性、保留窗口和恢复保护清单。最新恢复点、成功指针、回滚所需和至少三套完整备份受保护；没有可信恢复证明时不提供备份清理。
- 正在执行或已预约的更新、仍被使用的文件、异常链接、所有者或文件身份变化等均会阻止相应清理。

操作顺序为“选择可清理条目 → 预览清理 → 核对条目、估算释放量、警告及有效期 → 确认清理”。预览最多五十项；预览不是删除授权的永久凭据。执行时服务器重新检查资源身份、引用和保护状态，过期或变化后需要重新预览。

## 回执与异常

页面显示清理进行中、清理完成、部分完成、未完成或需要恢复核查，并保留同一请求的已清理数量与估算释放量。结果未确认、连接中断或暂时查不到回执均不能解释为没有执行。

提交后只查询原请求回执，不自动重发删除或换新请求编号；重新进入后恢复本账号、本服务器的待核对请求。自动核对暂停时可手动核对或联系管理员，不能借刷新重复执行。需要恢复核查时以原回执和服务器实际状态为准。

## 相关实现

- 页面：`lib/features/admin/pages/server_storage_page.dart`；模型和仓储位于同功能目录。
- 接口：`GET /api/admin/server-storage`、`GET /resources`、`POST /cleanup/preview`、`POST /cleanup`、`GET /cleanup/{requestId}`，子路径均属于 `/api/admin/server-storage`。
- 权威：`ServerStorageController`、`ServerStorageService` 与本机 `operations_storage.py`；仅接受资源标识和有效预览，不接受任意文件路径或命令。
