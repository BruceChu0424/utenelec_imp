# V634 委外前置自制超量后的订货批准谱系守卫

- 迁移：`V634__subcontract_prepared_outbound_over_quantity_guard.sql`。
- 口径来源：2026-09-21 用户实测——物料分析下达车间时对委外前置自制候选行超量下达(归需求量 1000 + 公共备货 4000，台账 5000)，自制 5000 入库满批自动通知委外 5000，委外部按申请明细下单 5000 并提交财务，订货审批任务中心「批量通过」整批报「数据已被其他操作更新，或数量超出可处理范围」；把订货拆成几张小单也只有 <= 1000 的单能过。
- 决策：[ADR-062 2026-09-21 修订](../99-决策记录-ADR/ADR-062-委外先自制后通知与分批通知.md)。
- 依赖：V458 谱系守卫；V535 包装函数 `fn_assert_subcontract_preparation_source`(仍调用被替换的函数)；V589 前置自制跟量(台账 `required_qty` = 归需求量 + 公共备货产出)。

## 根因

Postgres 日志在 COMMIT 时报 `subcontract prepared-outbound lineage is inconsistent`(DEFERRED 触发器 `trg_subcontract_preparation_source_guard` → `fn_assert_subcontract_preparation_source_before_v535`)。V458 为 `PREPARED_OUTBOUND` 行写的守卫要求 `analysis_item.requested_qty >= plan_item.planned_qty`，其中 `analysis_item` 是原分析里的 `SUBCONTRACT_MAKE` 行，`requested_qty` 只记归需求量(1000)；V589 之后台账 `preplan_subcontract_make_tasks.required_qty` = 归需求量 + 公共备货产出(5000)，通知批次 `notify_qty`、委外申请与订货明细都按台账整批走，守卫仍拿 1000 卡 5000 的订货行，财务批准提交时必被拒。后端只把它当普通完整性冲突记一行 WARN(不打印约束名)，页面看不出原因。

| 对象 | 变化 |
| --- | --- |
| `fn_assert_subcontract_preparation_source_before_v535(uuid)` | `CREATE OR REPLACE`：`PREPARED_OUTBOUND` 分支的数量上限由 `analysis_item.requested_qty >= plan_item.planned_qty` 改为 `task.required_qty >= plan_item.planned_qty`(台账口径)；批次 `batch.notify_qty >= plan_item.planned_qty`、任务 ACTIVE/分析/准备行身份、货品/颜色/单位一致性与 `MAKE_THEN_OUTBOUND` 分支全部原样保留；函数注释同步 |

不加表、不加列、不改行、不动触发器；V535 包装函数与 `trg_guard_subcontract_preparation_reservation_identity`(预留改动时重跑同一断言)自动得到新口径。台账 `notified_qty <= required_qty` 由 V458 的 CHECK 与批次守恒守卫 `fn_assert_subcontract_make_task_batches` 继续兜底，所以放宽后订货行仍不可能超过前置自制真正承诺的产出。

## 影响范围

- 只放宽「同一前置自制任务、同一通知批次」下 `planned_qty` 落在 (归需求量, 台账 `required_qty`] 区间的订货行；超过台账或超过批次通知量的订货行仍被拒绝。
- 存量：没有能通过旧守卫落库的数据会因新口径变非法(新口径严格弱于旧口径)，无需回填。
- 应用侧不改代码；订货审批任务中心的批量通过/单笔通过、之后的出仓发料、回厂登记、IQC 与批量入库沿既有链路。

## 验证

- `SubcontractPreparedOutboundOverQuantityMigrationContractTest`：锁定 V634 只替换该函数、新口径用 `task.required_qty`、不再出现 `analysis_item.requested_qty >= plan_item.planned_qty`、不 DROP 触发器。
- `FullChainEndToEndTest#subcontractOverQuantityMakeTask_splitOrdersBatchApproveIssueArriveAndBatchStockIn`：真实服务跑通「超量下达 30(需求 10 + 公共 20) → 两次报工两张成品入库批量点收 → 满批自动通知 30 → 拆成两张订货单(20 + 10)一次批量批准 → 各自出仓发料 → 按单登记回厂 → IQC 合格 → 两张收货单一次批量入库」，库存回到 30。
- `BusinessDataResetSqlContractTest` / `ResetBusinessDataScriptContractTest`：白名单 (634, 589) 与目录对账。
