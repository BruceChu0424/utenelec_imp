# 委外回厂短交判定页

> **2026-09-20 新增（V636 / [ADR-098](../99-决策记录-ADR/ADR-098-委外允许损耗与回厂短交判定.md)）**：仓库登记委外回厂时累计数量少于订货量，系统按订货行开「回厂短交案件」，
> 本页让委外跟单员判定是「分批到货，继续等」还是「接受损耗，结案」，并把每一次的损耗率记进委外商汇总。

## 一、页面与权限

- 路由 `/subcontract/short-deliveries`；`?caseId=` 通知卡片深链(进页直接打开该案件详情)、`?orderId=` 任务中心状态列深链(只看这张订货单)、`?supplierId=` 供应商详情深链(只看这个委外商)。
- 看页面：`subcontract_order:view`；对象级读范围与委外订货单一致(本人负责的订货单，或 `subcontract:view:all`)。
- 判定：`subcontract_short_delivery:decide`(委外管理 / 委外订货，V636 默认授予持 `subcontract_order:submit_finance` 的部门) + 对象级本人订货单；没权限的人能看不能判(操作列显示「无判定权限」)。
- 入口：委外 Hub「回厂短交判定」卡片(徽章 = 待判定案件数)、委外任务中心「进行中」状态列的「回厂短交待判定 / 分批等待中」(点击直达)、通知卡片、供应商详情「委外损耗」段的「短交记录」。

## 二、页面结构

- 分段(UtenFilterToolbar)：`待判定`(红徽章：低于允许下限的待判定 + 分批等待已过预计到齐日) / `容差内待结案`(中性括号：容差内或未设允许损耗的短交) / `分批等待中`(中性括号) / `历史记录`(时间门控，ADR-066)。任务型页面进页默认落在「待判定」。搜索：订货单号 / 委外商 / 货品 / 收货单号。
- 表格列：订货单号、委外商、货品名称 / 编号 / 颜色(各一列)、订货量、允许损耗、最少应到、累计回厂、短交量、短交率、程度(严重短交 / 低于允许下限 / 容差内未到齐 / 未设允许损耗)、最近收货单、到货次数、发现时间、(分批段/历史)预计到齐、(历史)损耗率 / 损耗单 / 结案时间、状态、负责人、操作。
- 待判定段：低于允许下限的行整行红底，严重短交置顶并带红色「严重短交」标签；「严重」= 短交率 ≥ max(2 × 允许损耗, 20)%。
- 双击行 = 案件详情弹窗：数字摘要 + 过程记录(仓库登记发现 / 再次到货 / 判定 / 自然到齐 / 作废)，开放案件且有权限时底部给两个判定按钮。

## 三、两种判定

| 判定 | 弹窗 | 服务端做什么 |
| --- | --- | --- |
| 分批到货，继续等 | 预计到齐日期(必填，不早于今天) + 说明(选填) | 案件 → 分批等待中；仓库的预计到货任务本来就开着，什么都不动；到齐自动完成；过了预计到齐日回到「待判定」并每天早上提醒一次(重要通知) |
| 接受损耗，结案 | 列出三件后果；低于允许下限时说明必填 | ① 按发料时冻结的用量把短交折算成材料损耗，自动登记并审核一张委外损耗单(允许量 = 允许损耗对应份额，超出部分转 ADR-047 财务责任判定)；② 订货量改为累计回厂量(ADR-072 受控改量：来源申请余量回到「待处理」、预计到货关闭、财务收到改量复核)；③ 案件记损耗量/率，撤回通知卡 |

供应商处剩料多于短交折算量(多发的料、允许补料没用完)时改量下限高于累计回厂，结案被拦并提示「请先登记退料单或损耗单」，案件保持待判定。累计回厂为 0 的行不能按接受损耗结案(红冲订货单或用受控改量处理)。

## 四、徽章与计数口径

- 页内「待判定」红徽章 = `/subcontract/short-deliveries/count.pending`；委外 Hub 卡片同数展示，不登记进 `todo_badge_registry`——委外模块红数由任务中心 `/count` 承担(已把有待判定案件的订货单算进去)，同一件事只数一次(准则 14 §四之二)。
- 供应商列表「损耗率(%)」列与详情页「委外损耗」段读 `v_subcontract_supplier_loss_summary`：只算已结清订货行，接受损耗行按改量前原量，加权损耗率 = 累计损耗 / 累计订货。
