# V820 AI 未归属调用汇总与升级兼容

原 `ai_call_logs.user_id` 允许 NULL，系统调用和早期记录不一定对应员工。V815 把日汇总的该列设为非空主键，导致有这些日志的旧库在 V815 回填时失败，已升级库的定时汇总同样报错。

V820 保留 NULL 的真实含义，把日汇总的身份约束改为 `UNIQUE NULLS NOT DISTINCT (user_id, usage_date)`，因此每一天最多一行未归属汇总，后续 UPSERT 幂等。迁移从完整原始日志回填并逐桶核对次数、成功次数和已报告的 Token 数；不修改原始日志，不创建虚拟账号。全站 KPI 与时/日/月/年趋势包含这些调用，员工排行与活跃员工数只计算非空账号，个人趋势严格按本人 UUID 过滤。

V815 SQL 字节及已应用校验和保持不变。V814 或更早旧库须使用随发布包提供的迁移器，其 `AppliedMigrationCompatibilityCallback` 仅在 V815 事务中建立同连接 `TEMP VIEW ai_call_logs`，显式从 `public.ai_call_logs` 读取可归属账号的行，供旧的非空表回填；V815 结束立刻删除临时视图，失败随事务回滚。原表包含的未归属日志始终原样保留，紧随其后的 V820 把它们计入正确的 NULL 桶。已应用 V815 的库直接执行 V820，不重跑 V815、不 repair，也不能只停在中间版本作为本次升级完成证据。

回调在事务内保存原 `search_path` 并临时设为 `public`，保证新表仍建在 public，同时使 pg_temp 按 PostgreSQL 的隐式关系查找规则优先读取；V815 结束通过 `set_config` 原样恢复路径，不拼接路径值为 SQL。预设 `pg_catalog,public,pg_temp` 的连接同样经过升级回归，失败回滚也验证路径还原。

验证覆盖：V814 含 NULL 日志的原始失败与兼容升级、已安装 V815 后新增 NULL 日志再升级、临时视图回滚、两类原始日志逐行不变、日汇总重复运行和昨日迟到调用、四种窗口的全站/个人隔离，以及原 AI 队列 housekeeping 真库回归。
