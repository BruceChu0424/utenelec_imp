## 一、目的与边界

V430 已把本次成品送检的仓库和逐行 `place_snapshot` 冻结为交易事实。V431 只解决下一次打开登记页时“同一个仓库、货品、颜色通常放在哪里”的输入建议：

- 有精确偏好时自动填入，仓库人员仍可修改；
- 没有精确偏好时先只读采用同仓、同货品 UUID、同颜色的最近安全 V430 登记，再回退到全局 `goods.stock_place`；
- 用户显式保留默认开启的“记住”选择后，新增或更新该仓偏好；
- 任何偏好变化都不得改写 V430 登记、inspection、FINISHED_IN 或库存历史。

V431 不是库位主档，也不是 WMS 或库存分账迁移。库存余额和流水继续以 `warehouse + goods + color` 为权威维度；偏好表没有数量、库容、批次、序列号、移库或盘点含义。

## 二、数据模型

### 2.1 `warehouse_goods_place_preferences`

| 字段 | 约束 | 语义 |
|---|---|---|
| `id` | UUID PK | 偏好行身份 |
| `warehouse_id` | UUID NOT NULL, FK warehouses, RESTRICT | 实际成品仓 |
| `goods_id` | UUID NOT NULL, FK goods, RESTRICT | 系统货品身份，不用编码或名称关联 |
| `color_id` | UUID NULL, FK colors, RESTRICT | 精确颜色；NULL 是确定的“无颜色”键，不是任意颜色 |
| `place` | TEXT NOT NULL | trim 后 1–100 字符的默认文本库位 |
| `selection_count` | BIGINT > 0 | 成功且非重放的记忆次数 |
| `last_selected_by` | UUID NOT NULL, FK employees, RESTRICT | 最后确认该偏好的仓库员工 |
| `last_selected_at` | TIMESTAMPTZ NOT NULL | 最后确认时间 |
| `created_at / updated_at` | TIMESTAMPTZ NOT NULL | 生命周期时间 |
| `created_by / updated_by` | UUID | 操作用户审计字段 |

唯一约束必须采用：

```text
UNIQUE NULLS NOT DISTINCT (warehouse_id, goods_id, color_id)
```

多个货品可以共用同一 `place`，因此禁止对 place 单列建唯一约束。表须接 `fn_set_updated_at()` 和 `fn_audit()`；审计中心应把仓库、货品、颜色、旧/新库位、选择次数和最后选择人解释为可读字段。

偏好是可变投影，不得被 registration、inspection 或库存表外键引用为历史权威。交易链只保存其提交当时已经确认的 `place_snapshot` 文本。

## 三、建议解析与显式记忆

### 3.1 批量解析

选定仓库后，服务端按固定日报明细一次查询全部 warehouse/goods/color 键，禁止逐行 N+1。读取优先级为：

1. 已登记行的 `place_snapshot`，只读且不再解析当前建议；
2. V431 精确仓库偏好；
3. 其他日报中同仓、同 `goods_id`、同 `color_id` 的最近一笔 V430 登记，来源码为 `REGISTRATION_HISTORY`；
4. `goods.stock_place` 全局 fallback；
5. 空值，由用户填写。

历史回退必须按系统货品 UUID 关联，禁止按货品编码或名称匹配；颜色用 `IS NOT DISTINCT FROM` 精确比较，NULL 不是通配符。服务端先按 `created_at DESC, registration_id DESC` 选定最近登记，再判断该登记内相同 warehouse/goods/color 的 `place_snapshot` 是否只有一个不同值：同值多行可采用，不同值多行不得随机取值，也不得跳过该登记采用更老记录，只能继续回退 `goods.stock_place` 或空值。当前日报必须排除。该查询是只读建议，不插入或更新 V431。

接口须返回建议来源。未选实际成品仓时客户端禁用库位号并提示“请先选择成品仓”，选仓后才批量加载且开放编辑。切换仓库须清除原仓上下文的建议和手工库位，再用请求版本或等价取消机制丢弃旧响应、重新匹配新仓；同仓重取只把建议写入未被用户手工修改的行。

### 3.2 独立记忆动作

“记住为该成品仓默认库位”默认开启，但必须显示给用户并允许取消。服务端不能把字段缺失解释为同意；旧客户端省略记忆意图时不写偏好。取消只控制 V431 持久共享偏好的写入，不删除真实 V430 交易快照；该快照以后仍可以按上述规则作为可编辑的最近登记建议。

偏好动作只能在 V430 登记成功后执行，并绑定成功 registration、操作者和稳定幂等身份：

- 同一来源重试返回原偏好结果，不重复增加 `selection_count`；
- 相同 warehouse/goods/color 多行同值只 upsert 一次；
- 相同键出现不同库位时，该键返回歧义并拒绝学习，禁止最后一行覆盖；
- 新值不同则更新偏好并保留全行审计，相同则返回未变化；
- 偏好动作失败不撤销登记、不重建 FQC、不修改 `place_snapshot`，页面只重试偏好动作并准确展示部分成功或失败结果。

登记请求的幂等事实和偏好动作的幂等事实不得混为一个模糊成功状态。通知、角标或偏好保存结果都不能作为仓库已登记的权威。

## 四、权限与安全

- 读取建议必须先通过对应日报任务的 `stock_doc:view` 与生产库存任务对象范围，不能提供任意 goods UUID 批量枚举旁路。
- 写偏好沿用登记动作的 `stock_doc:approve`，并与有效 `SUB_WH` 仓储组织范围求交；仅有全局动作权限但不在仓储范围的账号失败关闭。
- 当前没有员工到具体仓库或库位的分配主档，因此不能宣称已实现单仓、单库位授权。
- 偏好端点不得复用或放宽为仅 `warehouse_inbound:view`，也不得直接更新 `goods.stock_place`、货品编码或系列。
- SQL 必须参数化；仓库、货品和颜色只能来自已登记固定来源及服务端回查，不能相信客户端提交的名称或可变编码。

## 五、前向迁移与历史兼容

V431 是纯新增表、约束、索引、触发器和审计解释的前向迁移。它不得修改已应用 V430 或更早迁移字节。

迁移明确不做：

- 不从 `goods.stock_place` 回填，因为一个全局值无法证明属于哪个仓库；
- 不从历史 `stock_document_items.place`、日报、registration、inspection 或 FINISHED_IN 批量写入或更新 V431“常用库位”；运行时对最近 V430 登记的精确 UUID 只读回退不属于迁移回填；
- 不更新、删除或重解释任何历史交易行；
- 不新增 warehouse + place 库存余额，不改变现有库存唯一维度；
- 不把现有货架挂牌、即时库存或七类仓库报表宣称为已经按仓库偏好改造。

旧客户端继续从 `goods.stock_place` 获得兼容建议，且因未显式同意记忆而不会产生偏好。新客户端在没有 V431 行时先尝试最近安全 V430 登记，再回退货品主档；两条读取路径均不产生偏好，因此无需数据回填即可渐进启用。

## 六、部署、失败与回退

发布前必须在只读目标身份确认 Flyway exact-set，并在可恢复的目标非空副本演练 V430 → V431。偏好表初始为空是正确结果，不是缺失迁移。

V431 应用后，功能回退采用：

1. 关闭偏好读取和记忆动作；
2. 页面恢复仅使用 `goods.stock_place` fallback；
3. 保留 V431 表、数据、审计和迁移资源，等待前向修复。

不得用缺少 V431 资源的旧 JAR 覆盖新 schema，因为 Flyway exact-set 会出现“已应用但本地未解析”的不兼容；不得删表、改 `flyway_schema_history`、执行 `flyway repair` 或修改 V431 已应用字节。若迁移自身失败，恢复到已演练且与旧候选完全一致的备份，或新增更高版本前向修复。

偏好保存是登记后的独立结果。运行时偏好失败不得把已成功登记提示成整体失败，也不得让用户重提登记造成幂等冲突；页面必须提供只重试偏好的入口和明确结果。

## 七、最低验收矩阵

- 迁移：空库、V430 非空升级、NULL 颜色唯一、FK/check、updated-at、全行审计、无历史回填、exact-set。
- 解析：同货品跨仓隔离、同仓跨颜色隔离、NULL 颜色、精确偏好优先、最近 V430 登记其次、全局 fallback、无建议、已登记快照最高优先；最近登记同维度同值多行可采用，异值多行回退主档/空值且不得采用更老登记。
- 记忆：创建、更新、未变化、取消、同源幂等重放、同键多行同值去重、同键异值拒绝、并发 upsert 和审计前后值。
- 失败：登记成功而偏好全部或部分失败时，registration/FQC/`place_snapshot` 不变；只重试偏好不会重复登记或增加错误次数。
- 权限：只读用户、非 `SUB_WH` 用户、越权 UUID 和任意 goods 枚举均失败关闭；合格仓库员工只可从有权登记来源记忆。
- Flutter：窄屏、来源标签、默认开启且可取消、选仓批量加载、A/B 仓乱序响应、手工值不被覆盖、加载中提交门禁、部分失败反馈与重试。
- 谱系：偏好和 `goods.stock_place` 后改均不改变 inspection、首次 FINISHED_IN、V338 短收、V418 重交、confirmation 或 reversal 的 warehouse/place。

文档、SQL 静态合同、空库测试或本地开发库通过均不代表目标库迁移、实物库位核对、多岗位 UAT、恢复或发布完成；上述目标侧证据任一缺失，生产继续 **NO-GO**。
