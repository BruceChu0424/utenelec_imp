# ADR-046：生产领料、仓库点收、报工归属与未来计件边界

- 日期：2026-08-22
- 状态：已决策（V337/V338 及关联服务/UI 为共享工作树源码候选；未部署、未完成目标库迁移和真实岗位 UAT，生产继续 **NO-GO**）
- 相关：ADR-028、ADR-029、ADR-033、ADR-043、V97、V150–V164、V337、V338
- 目录复扫：当前共享工作树最高 V375，共 337 个迁移文件、337 个唯一版本、无重号；V339–V375 并行候选不改写本 ADR 的 V337/V338 生产语义

## 一、问题

生产链中同时存在五类容易混淆的事实：物料已预留、仓库已发料、车间已报工、仓库已点收入库、未来计件工资。它们必须逐层推进，不能用一个数量或状态相互替代。

现场还暴露了两个具体缺口：

1. MAKE 节点创建 `MAKE_COMPONENT` child 后，原父树后代节点会变成只读、需求转到 child 直接层；已通过 IQC 或 MAKE 入库形成的 exact entitlement 若仍停在旧节点，就会出现“旧行 0/0、child 仍缺料”。
2. 生产日报申报量过去直接生成等量 FINISHED_IN 草稿；仓库缺少逐行实收权威，短收只能改源数据或整单退回，无法保留“申报、实收、余量”三者。

与此同时，历史日报行仍有 `price/total/stotal` 字段，计划/日报有单一 `worker_id`，执行段有车间、班组和负责人。这些字段都不足以证明实际作业人、工序、合格计件量或工资金额，禁止直接解释为计件工资。

## 二、决策

### 2.1 权威事实按顺序分层

```text
计划批准
  → READY + 完整预留 + DRAW
  → 仓库确认 DRAW（不动库存）
  → 仓库分轮实际发料 issue（扣库存、写不可变领料 posting）
  → 全部正式物料需求 FULFILLED 后才允许开工
  → IN_PROGRESS 执行段才允许报工
  → 主管审核日报，只增加 fqty，并生成 FINISHED_IN 待点收草稿
  → 仓库逐行确认实收，只有实收量增加库存和 iqty
  → 未来计件归属与工资结算（本 ADR 仅冻结边界，不实现）
```

- `READY` 只证明整套库存已预留且 DRAW 已生成，不证明仓库已经发料。
- DRAW 审核只确认领料需求；`issue` 才是物理交接。DEMANDED 执行段必须全部正式物料需求已履约才可 `START`；`ZERO_MATERIAL` 只沿既有冻结证据例外。
- 日报只允许引用 `IN_PROGRESS` 执行段。报工批准量累计到 `fqty`，不能增加库存、`iqty` 或工资。
- FINISHED_IN 仓库实收量累计到 `iqty` 并进入库存；`iqty` 不能反推具体工序、实际作业人或工资。

### 2.2 V337：MAKE entitlement 随 child 所有权交接

V337 新增 append-only `preplan_make_entitlement_delegations`，并使用成对的 `MAKE_DELEGATE_OUT/MAKE_DELEGATE_IN` entitlement 事件：

- IQC/MAKE 原始 exact peg、物理 `stock_reservation` 和来源单据永久不改；
- 只把当前 beneficiary 从父树中与 MAKE 直接子路径对应的旧物料节点，移到 `MAKE_COMPONENT` child 的同 BOM、同仓货色单位直接层节点；
- 来源节点、目标节点、MAKE action、child item、数量和幂等键逐项校验，目标累计不得超过 child 当前正需求；
- 同一物理量先 OUT 后 IN，不能同时被父树和 child 重复占用；刷新失败整事务回滚；
- 本迁移解决 exact 权益随节点所有权交接，不等于实现任意分批 `delegated_qty`、计件归属或工资。

### 2.3 DRAW 通知、角标与开工门禁

- 计划批准或待料段齐套生成真实 DRAW 后，Outbox 事件 `PRODUCTION_DRAW_PENDING` 投递仓库任务；仓库入口角标读取有权仓库履约待办，通知不是业务权威。
- DRAW 全部实际出库后发送 `PRODUCTION_DRAW_ISSUED` 给计划/生产岗位；反出库使其不再全部发料时发送 `PRODUCTION_DRAW_ISSUE_REVERSED`。
- 通知丢失不影响工作台发现真实 DRAW；重复消费按事件/出库幂等键去重。
- 页面必须同时显示“已预留”和“已发料 X/Y”。仅全部发料的 DEMANDED 段允许开工；部分发料仍保留出库进度，但不能借此报工。

### 2.4 V338：生产成品入库由仓库逐行点收

生产日报生成的 FINISHED_IN 不再允许走通用 `approve` 直接入账，必须调用：

`POST /api/stock/docs/{id}/finished-in/confirm`

请求须携带全部当前明细的 `itemId + acceptedQty`、幂等键；每行实收不得小于 0 或超过报工待入库量。多行单允许某行 0 实收、其它行正数接收：0 实收行全量进入余量草稿，正数行按实收入账；整单全部行均为 0 才表示仓库整单拒收，必须填写原因且不增加库存或 `iqty`。任何短收都必须填写差异原因。

V338 增加：

- `stock_document_items.reported_qty`：报工申报待入库量；
- `stock_document_items.source_daily_report_item_id`：FINISHED_IN 明细到日报明细的 UUID 真源；
- append-only `production_finished_in_confirmations/items`：逐单、逐行冻结申报、实收、余量和操作者；
- 短收时，当前单只按实收量审核入账，余量在同一事务生成新的、同计划同来源 FINISHED_IN 草稿，并再次投递仓库待点收任务。
- 整单零实收时，原单记为 `REJECTED`，确认记录保留申报量和拒收原因并通知生产/计划更正或红冲报工，不生成库存流水。拒收原因不写入单据备注——备注与总额是生产链身份守卫（V164/V232）的不可变列；详情接口以 `finishedInboundDecision/finishedInboundVarianceReason` 提供权威展示，生产 FINISHED_IN 为纯数量单据，总额保持 NULL。
- 已点收单禁止通用红冲，必须调用 `POST /api/stock/docs/{id}/finished-in/reverse`。专用命令追加 `production_finished_in_confirmation_reversals/items`，反向库存和 `iqty`，并把原 accepted slice 逐 UUID 重建成同计划、同日报来源的待点收草稿；不得让部分点收后的已收数量从待办中消失。

点收必须覆盖全部行；确认记录、实收缩量、余量草稿、计划链接、库存、`iqty`、执行段状态和通知全事务成功或全回滚。编号、同名货品或前端顺序均不得替代 UUID 来源。

### 2.5 报工人与未来计件边界

当前字段语义保持保守：

- `production_plans.worker_id`、`production_daily_reports.worker_id` 是单据上的计划/报工负责人；
- `production_execution_segments.team_department_id/responsible_employee_id` 是执行安排；
- `step_legacy_id` 只是尚未完成 UUID 工序主档迁移的历史影子；
- 上述任何字段都不证明一件产品由谁完成，也不能直接作为工资分配依据。

生产日报从本候选起只接收数量事实。客户端不再录入单价/金额；服务端对非空 `price/total/stotal` fail closed。历史列保留只为兼容，不回填、不计算、不展示为工资。

未来计件必须另行 ADR、迁移和业务确认，至少建立：

1. UUID 工序/工艺路线与生效版本；
2. 日报行级实际作业员工/班组贡献及数量或分配权重；
3. 日报行到仓库实收行的不可变数量分摊；
4. 经审批的工价版本、单位、有效期和舍入规则；
5. 计件结算批次、反向调整及到工资项的精确来源桥；
6. 薪资级权限、对象范围和金额审计脱敏。

第一阶段只允许把“主管已审报工 ∩ 仓库已审实收”作为未来可计件数量候选。未建立现代工序验收前，只能评估最终入库工序；中间工序计件继续 **NO-GO**。

不得从历史 `fqty/iqty/worker_id/responsible_employee_id/price/total` 或老库 `W_PATWork` 自动生成工资。不得把质量不良、返工或损耗直接扣给员工；相关政策须由业务、人事和合规另行批准。

## 三、反向与历史

- DRAW 反出库沿既有 posting 对称恢复；已开工、报工或下游消费时继续由正式反向门禁处理。
- 全部生产仓库动作统一使用 `inventory dimension → plan/package/segment → stock document/item` 锁序；收货回退同样先锁 package、segment 再锁 DRAW，禁止形成 `DRAW→plan`/`DRAW→inventory` 反向环。
- 日报红冲先处理其生成的未审 FINISHED_IN 草稿；已点收单须先走专用红冲，追加反向映射、执行段重开并重建 accepted slice 待点收草稿，不能改写历史点收记录。
- V338 只对能唯一匹配日报行的历史 FINISHED_IN 明细回填 `source_daily_report_item_id`；歧义行保持空值，禁止按货号猜测。
- 历史已审生产 FINISHED_IN 以 `LEGACY_APPROVED` 确认事实登记，不伪造当时不存在的逐行动作。

## 四、权限、审计与验收

- DRAW 审核/发料、执行段开工、日报创建/审核、FINISHED_IN 点收继续使用各自独立权限；生产仓库单的跨制单人处理还必须与 `SUB_WH` 仓储组织树对象范围求交，非仓储账号的工作台/角标返回安全空结果，直链写失败关闭。当前没有员工到具体仓库的分配主档，因此不能宣称已实现单仓级授权。
- V337/V338 点收、委派和红冲新表 append-only 并接数据库审计；工资金额若未来落地必须使用薪资脱敏审计，不能复用普通生产审计暴露金额。
- 最低组合测试必须覆盖：MAKE exact→child entitlement；DRAW pending/全发/反发通知与角标；部分发料禁止开工；仅 IN_PROGRESS 可报工；FINISHED_IN 全收/短收/幂等/余量草稿/红冲；客户端金额拒绝；权限和并发反向。

## 五、发布结论

V337、V338、关联 Java/Flutter 和测试均只是共享工作树源码候选。文档同步、静态检查或本地自动化不能替代公司目标非空库升级、历史对账、仓库/计划/车间真实账号 UAT、实物点收、并发恢复、签名发布和部署回读。上述证据完成前，生产写链和未来计件继续 **NO-GO**。
