# 货架目视化清单页

> 路由：`/warehouse/shelf-labels`（`lib/features/warehouse/pages/shelf_label_page.dart`）· 2026-08-17 源码候选
> 权限：页面与查询 `stock:view`（全员，与库存查询同权）；加密 Excel 导出另需 `stock_report:export`
> 上层：工作台 → PMC 运营部 → 仓库管理 hub → 「库存查询」分区 · 数据口径：货品主档 `goods.stock_place`（库位号）

## 一、定位

对标仓库现场挂牌「目视化管理清单 Visual Management List」：把**货品主档中已维护库位号**的货品
按 库行→层→位 列出，打印张贴到货架。**与库存数量无关**——货架固定摆放什么就列什么，
不查余额、不看流水。

主档库位号由三条学习路径保持最新（V451 起）：仓库到货登记回写、IQC 合格品入库确认回写、
产成品到货登记的「记住库位」（写入仓库×货品偏好，详情见
[迁移说明 66](../数据迁移/71-IQC入库库位学习.md)）。因此货架清单会随实际入库自动长出
新货位的行，不必等基础资料手工维护。

## 二、入口与导航

- 仓库管理 hub「库存查询」分区 →「货架目视化清单」卡片进入。
- AppBar 返回回仓库 hub（`backTo` 默认 `RouteName.warehouse`）；AppBar 另有手动刷新图标。

## 三、布局与功能点

1. **筛选行**：抬头仓库下拉（仅作打印标题「XX仓库物料库」，不过滤数据）+ 标题覆盖输入（可选）
   + 库行下拉（`stockShelfLabelRacks()` 喂选项，默认「全部」）+ 关键字搜索
   （名称/编码/系列/库位号模糊，300ms 防抖）+ 计数文案「共 N 项 · M 个库行」。
2. **分组卡片**：按库行分组，卡片头 = 抬头标题 + 库行徽章 + 项数；表体五列
   **库位号 / 物料编码 / 物料系列 / 物料名称 / 颜色**（与挂牌列一致，斑马纹）。
3. **预览打印**：弹窗灰底白纸分页预览；生成 PDF 走 `pdf/printing`（`NotoSansSCFull.ttf` 全量字体）。
   每个库行独立 **A4 横版**页，版式 = UTEN 头（左 logo 文案 / 中标题 / 右库行徽章）+ 五列斑马表；
   每页最多 16 数据行，每库行末尾留 6 行空白供现场手写补充。
4. **Excel 导出**：`UtenExportButton` → `POST /stock/reports/export report='shelf-labels'`
   （加密 xlsx，`stock_report:export` 持有者可见），查询参数（rack/keyword）与当前筛选同步。
5. **空态**：无已维护库位号的货品时显示引导文案「请先在货品资料中填写『库位号』（如 A31-3-1）」。
6. 库行下拉加载失败不阻塞主表（仍可全部查询）；主表失败显错误 + 重试。

当前页面请求：

```http
GET /api/stock/shelf-labels?rack=&keyword=    → 行（库行/库位号/物料编码/系列/名称/颜色）
GET /api/stock/shelf-labels/racks             → 全部库行（筛选下拉数据源）
Authorization: stock:view
```

## 四、涉及组件与实现

- 前端仓储：`StockQueryRepository.shelfLabels / shelfLabelRacks` + `ShelfLabelRow` 模型
  （`lib/features/stock/repositories/stock_query_repository.dart`）。
  2026-08-17 修复：该方法初稿曾被误粘贴进 `instantInventory()` 的 query map 字面量内部，
  导致仓储文件语法断裂、全项目编译不过；已按意图补全两个方法的边界。
- 服务端：`StockQueryController`（`/shelf-labels`、`/shelf-labels/racks`）；
  导出分支在 `StockReportService.exportShelfLabels`。
- 组件：`UtenAppBar` / `UtenBackButton` / `UtenContentContainer` / `UtenSearchBar` /
  `UtenButton` / `UtenExportButton`；仓库抬头名取自 `masterNameServiceProvider.warehouseEntries`。
