# 官网公开资料流与询盘确认的资源边界

公开 PDF 原先整份读入响应；并发相同询盘确认还可能在首次读取后等待另一个事务提交，把已经完成的同一回执误报为冲突。本次从 B1 历史候选按语义归集这些增量，保留当前官网的公开范围、私有资料目录、就绪检查及已有接口，不替换旧整文件或旧迁移。

## 唯一入口和完整调用方

- `lib/document-storage.ts::openVerifiedDocument`：最多两个物理下载名额，64 KiB 校验及传输块，同一文件描述符上的两遍 SHA-256、文件大小/身份/修改时间检查。旧 `readDocument` 通过这个入口兼容需要完整字节的调用方，不再维护另一套校验。
- `app/api/resources/[id]/download/route.ts::GET`：直接返回已核验的流，保留原始长度及附件响应头；满额返回 503 和 `Retry-After: 2`。路径格式、公开资源及产品/系列祖先范围仍由原有守卫决定。
- `lib/inquiry-delivery.ts::acknowledgeInquiries`：同一事务内按 `deliveryId` 统一顺序处理。更新等待后发现已提交时，只有来源 ID、ERP ID、ACK 状态完全一致才接受；冲突仍令整批回滚，不把受理、送达当成员工已读。

## 取消、超时及物理名额

120 秒总期限和外部 Abort 从取得名额时就生效，覆盖目录/文件打开、两遍读取及发布核验。请求可以先因取消或超时失败，物理名额仍等当前打开、读取或数据库回调真正结束后释放。迟到的文件描述符会关闭，迟到的拒绝有接收者，不能通过放弃等待后反复接收新工作制造无限后台任务。

公开资料数据库读取使用 1 秒事务排队上限、3 秒交互事务期限；PostgreSQL 事务内设置 2 秒 `statement_timeout`，让实际阻塞语句有服务器端边界。SQLite 开发入口不执行 PostgreSQL 语句。设置只在本次事务内生效，原公开条件与资源 `assetId` 绑定保持不变。

文件在响应前、传输中持续复核身份，并在初始、每秒及完成前复核公开状态；撤下会阻断后续校验/完整响应，已经发送的字节不能撤回。空读、篡改、取消和超时均通过同一生命周期收口；兼容入口、流式入口及 HTTP 路线共享该维护点。

## 回归与隔离

`tests/document-streaming.test.ts` 检查最大 20 MiB 原件按 64 KiB 精确传输、背压、取消/期限、篡改/撤下、预响应等待、迟到句柄只关一次、未开始读取及物理名额不提前释放。容量夹具跨两个块，防止把已预取到 EOF 的小文件误认为仍在下载。

`tests/b1-read-postgresql.test.ts` 使用现有 `createIsolatedPostgresqlDatabase` 唯一入口创建并核验临时库、迁移及清理；覆盖真实公开下载/撤下、PostgreSQL 表锁导致的实际语句取消和零残留等待、并发同回执、逆序请求、未知提交重试、后续项错误导致前项整批回滚。原件、原始来源和回执身份均保留。

验收环境仅使用合成数据：Linux Node 22.13.1 与 PostgreSQL 16.15，未发布主机端口，不挂载旧任务私密配置、上传物或业务数据库。容器采用 init 回收子进程、两核 affinity 和明确 PID 预算；不通过改产品 Webpack 配置、增加堆内存或跳过用例处理测试环境资源问题。

本次仅归集源码和验证，不代表官网已部署阿里云。正式云部署、真实资料上传及生产恢复仍按现行手册单独执行。
