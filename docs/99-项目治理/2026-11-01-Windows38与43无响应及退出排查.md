# Windows 2.5.38 / 2.5.43 无响应与退出排查

> 后续现场证据已补充：第一台实际为 2.5.37，匹配 Release 符号定位到 Windows `HitTestSync`，新增原生回归已复现；原 f109 公共树候选还缺此路径，现已拒绝出包。本文件保留首轮检查事实，当前结论与两台电脑差异见[现场核对与增量修复](2026-11-01-两台Windows日志与HitTestSync崩溃修复.md)。

用户反馈软件快速操作时发白、无响应，已两次退出；补充为 38 版，并要求同时检查 43 版及各平台。截图位置为钱流管理入口。任务基线为 `bd7e8525be1ef52db2a6cfb10268fdbd8310844c`，使用独立工作树和 `uimp/windows-stability-2538-2543-20261102` 分支，保留主工作区及其他任务改动。界面交互审查使用 `frontend-design`，沿用 Uten 主题、组件及业务边界。

## 结论与证据分级

1. **确定的原生线程阻塞缺陷**：38 与 43 的 `windows/runner/client_update_channel.cpp` 相同。`installUpdate` 原本在 Windows 消息线程上遍历路径、计算最多 512 MiB 文件的 SHA-256，并同步等待更新器就绪 15 秒，失败还可再等退出 5 秒。其间不能处理普通窗口消息，足以造成无响应。网络等待本身不等于此缺陷。尚无故障电脑记录证明用户当时正在执行更新，不能把此代码缺陷直接称作两次退出的唯一原因。
2. **两版正式包都暴露于已知引擎缺陷**：38 正式更新 ZIP、43 正式更新 ZIP、43 本机安装和对应 SDK Release DLL 的摘要均为 `011e87e890b7bfbac89f63c763341ffb8393d2b4a617dd836c471a0cdaa1346f`。SDK engine revision 为 `77e2e94772b6eb43759e34ed1ad7da4674e19cab`。该精确源码仍在 `FlutterPlatformNodeDelegate::ChildAtIndex` 对可能为空的子节点直接取 `id()`，`AccessibilityBridge::OnNodeReparented` 仍为空。
3. **历史现场与本次现场分开**：[10 月 28 日记录](2026-10-28-Windows窗口缩放闪退排查.md)已用 WER/dump 符号化确认 Profile 原引擎的空子节点崩溃，以及不完整保护下的 AXNodeData 生命周期失效。历史仅修空节点的引擎摘要不是最终补丁摘要。本次未取得故障电脑 38 版两次退出的事件或 dump，本开发机所见相关崩溃记录仍为旧本地测试版本，不能冒充本次现场。
4. **43 已含共享焦点修复，但未包含上述引擎修复**：`UtenViewFocusEvents` 已进入生产 `UtenWidgetsFlutterBinding`，处理退场渲染树期间的原生方向焦点事件；38 没有这项保护。详见[原始栈与修复记录](2026-11-01-Web原生焦点与渲染树退场边界.md)。该 Dart 修复不能修复 C++ AXNode/delegate 生命周期。

因此，**不能承诺原 43 安装包已经解决本次问题，也不能仅凭截图把两个现场退出定性为同一个崩溃**。本次修复源码和内部测试不等于现网或已安装包已经更新。
