# 直下单销售式供货流（先库存、缺口才生产）—— 方案与执行计划

> **已实施（2026-09-02 同日，ADR-064）**。落地与本方案的差异：原 D1/D2「批准时插
> SUBCONTRACT_OUTBOUND 软预留」改为**拆行**——现货部分拆为独立 `DIRECT_OUTBOUND`
> 行（bom_has_children_snapshot=true），走既有「无仓草稿→仓库选仓原子占用→实发」全链；
> 缺口部分为 `MAKE_THEN_OUTBOUND` 行，量=缺口，START_PREPARATION 建分析量自然=缺口。
> **零新表、零迁移、零新状态枚举**；取消/红冲/实发/出仓全部复用既有机制。
> 需求来源：用户口述「直下单有子层跟销售的流程差不多，能看到进度——直接下委外单→财务审批→
> 判断仓库有没有货，有货就通知仓库发货，没货或缺少就通知计划部生产；参照销售：成品仓足量
> 且未被其他订单锁定就通知仓库备货、销售去发货；你自己补充没想到的」。
> 基线：V457/V458 已落库（22ca1806/9fe3192e）；ADR-063 为弹窗会话（V459）；本方案=ADR-064，无迁移。

## 一、需求还原（口述 → 功能点）

| # | 用户原话（解码） | 功能点 |
|---|---|---|
| R1 | 「直下单有子层就是跟销售的流程差不多，能看到进度啥的」 | 直下单（不经物料分析手工下委外订货单）的目标件履约改成销售式三态，进度在订货单上可见 |
| R2 | 「财务审批，然后判断仓库有没有货，如果有货就通知仓库发货」 | 批准事务内查全局可用量；够 → 软预留 + 待出仓 + 通知仓库（复用 V458 的 OUTBOUND_READY 事件） |
| R3 | 「如果没货或是缺少，就通知计划部生产」 | 缺口（需求−可用）→ 新事件通知计划部（SUB_PLAN/DEPT_PROD 对应岗位）→ 前置自制载体按**缺口量**而非全单量建立 |
| R4 | 「参照销售：成品仓有足量的货且没有被其他订单锁定，就可以通知仓库备货」 | 可用量口径 = 账面 − 生效预留（`StockReservationService.globalAvailableBase`），天然排除被其他订单/需求锁定的量 |
| R5 | 「你大概理解下，然后自己补充下我没有想到的」 | §四补充清单（部分有货分批、同单共享池、撤单守卫等） |

## 二、现状盘点（带坐标）

### 已具备（直接复用）

1. **销售三态预留范式**：`SalesOrderService.reserveOnApprove`（`server/.../sales/order/SalesOrderService.java:1109`）——逐行 `globalAvailableBase`，够→全量预留进可发货；部分够→能留多少留多少、差额待排产；同货品多行共享递减池防重复占用。
2. **预留服务**：`StockReservationService`——`globalAvailableBase(goodsId,colorId)`、`reserve(...)`（可带仓）、`releaseBySourceDoc(sourceDocType, docId)` 按单整体释放。
3. **V458 分批出仓投影**：MAKE_THEN_OUTBOUND 已放宽为分批（首片实收即 READY_OUTBOUND、首片/整批两次通知、中间量靠投影，`SubcontractMaterialPlanService`）——「先发一部分、产出后补发」的骨架已在。
4. **V458 谱系分流**：`createPlanOnApproval` 里 `preparedLineage` 命中 → PREPARED_OUTBOUND（物料分析链下的单，本次不动）。
5. **V447 缺口生产载体**：SUBCONTRACT_PREPARATION 独立分析 + entitlement handoff（`SubcontractPreparationEntitlementHandoffService`）+ 准备中心「订货来源页签」一键 START_PREPARATION——保留，但触发条件从「一律」改为「仅缺口」，建分析的量=缺口。
6. **出仓就绪/完成事件**：`EVENT_SUBCONTRACT_OUTBOUND_READY/COMPLETED`（ChainNoticeService 已双登记）。
7. **进度展示位**：订货单详情 `subcontract_order_progress.dart` 已按 flowMode 分组渲染。

### 痛点（本方案要改的）

1. **批准不看库存**：`SubcontractMaterialPlanService.createPlanOnApproval` 中 `makeFirst = bom.hasChildren() && prepared == null`——有活动 BOM 子层且非 V458 谱系，一律 MAKE_THEN_OUTBOUND（整行 ACTION_REQUIRED、prepared=0），**哪怕仓库现货充足也要重新生产**。这是用户本次反馈的核心。
2. **无「部分有货」概念**：有子层行没有「现货部分先发、缺口部分再产」的组合态。
3. **计划部获知靠人盯**：批准后无缺口定向通知（现 EVENT_SUBCONTRACT_PREPARATION_REQUIRED 只覆盖「需要启动分析」的待办语义）。
4. **直下单批准后不支持改量**（销售有 changeQty，委外订货没有）——本方案不新增改量，列边界。

## 三、核心设计决策

### D1 批准三态判定（只动「有子层且非谱系」分支）
```
preparedLineage 命中            → PREPARED_OUTBOUND（V458 链，不动）
无活动 BOM 子层                 → DIRECT_OUTBOUND（现状不动；纯外发件无 BOM 无法自产补货，
                                   出仓任务等货属正常语义）
有子层 + 非谱系 → 查全局可用量 a（账面−生效预留，同单同货多行共享递减池）：
  a ≥ 需求 q   → 软预留 q；READY_OUTBOUND；发 OUTBOUND_READY（通知仓库发货）
  0 < a < q    → 软预留 a；缺口 d=q−a；行进「部分有货」态：可出仓量起步=a，
                 缺口 d 走 D3 缺口生产；产出回填后可出仓量增长（分批出仓）
  a = 0        → 不预留；全量缺口 d=q 走 D3
```
预留记录 sourceDocType=`SUBCONTRACT_ORDER` + 订单 id，支持按单整体释放。预留不带仓（全局，与销售一致）；出仓执行时仓库选仓实发、对称释放等量软预留。

### D2 可出仓量投影口径扩容（零/低迁移目标）
有子层行的「已备量」口径 = 软预留量 + 已产出回填量（V447 entitlement IN 回填）；可出仓量 = 已备量 − 已发。目标**不加新表**：预留表已存在（stock_reservations），状态/量全投影；仅当状态枚举需要新值（如 PARTIAL_READY）才做小迁移。缺口账本沿用 V447 既有结构（分析+handoff 即账本）。

### D3 缺口生产（通知计划部，量=缺口）
- 批准事务内：缺口 d>0 → 新事件 `EVENT_SUBCONTRACT_PREPARE_SHORTAGE`（ChainNoticeService EVENT 常量 + deliverOutboxEvent switch 双登记），收件=计划口径岗位（对齐 V458 SUBCONTRACT_MAKE_TASK_CREATED 的 SUB_PLAN/DEPT_PROD 寻址），内容带订单号/货品/缺口量。
- 计划部动作沿用准备中心「订货来源页签」START_PREPARATION 一键建分析（现有能力），但建分析量=d 而非 q；分析展开子层→领料→报工→FQC→入仓（自制全链）；产出经 entitlement handoff 回填订单可出仓量（V447 已有，产出订单专属不被抢）。
- 满/部分产出后的发货通知复用 V458 分批口径（首片+整批）。

### D4 取消 / 红冲 / 守卫（对齐 V458 范式）
- 订单取消/整单红冲：`releaseBySourceDoc` 释放软预留 + 撤缺口任务；已投产（分析已启动/produced>0）失败关闭，需先处理生产侧（同 V458 撤回守卫）。
- 订货红冲对已发部分：沿用现有出仓反向链；预留按剩余量对称调整。
- 出仓执行：实发量对称核减软预留（销售发货同款）。

### D5 在途兼容
已批准的 MAKE_THEN_OUTBOUND 老单照旧走完（不重算、不补预留）；LEGACY_BOM_COMPONENT 不动；V458 谱系链不动。新三态只对新批准生效。

### D6 进度可见
- 订货单详情（`subcontract_order_progress.dart`）：有子层行展示 需求/现货已备（预留）/缺口（在产）/已发；缺口在产点进去看准备中心任务。
- 准备中心订货页签：任务=缺口>0 的行，显示缺口量与启动状态。

## 四、补充清单（用户没提但必须定的边界）

1. **部分有货先发**：有 60 缺 40 → 先发 60，产出后补发 40（用户只说了「缺少就生产」，没说现货部分要不要等——按销售语义=先发）。
2. **同单同货多行共享池**：两行同货品不能重复占同一份可用量（销售 reserveOnApprove 同款递减池）。
3. **防抢**：批准即软预留，产出前不被其他订单/需求挪用（这正是 R4「未被其他订单锁定」的镜像义务）。
4. **撤单守卫**：已投产/已发不能无痕撤（避免生产白做）。
5. **无子层缺货不进生产**：纯外发件无 BOM，缺货只能外购补，不在本方案（可选后续：出仓任务缺货提示）。
6. **交期风险提示（可选增强）**：缺口大、交期近的行在进度卡标警（deliver_date vs 生产周期）。
7. **改量不支持**：直下单批准后改量现状不存在，本方案不做（若将来做，参照销售 changeQty 的增量重预留）。

## 六、验收清单

批准三态（足量/部分/零库存）、同货多行不超占、预留不被他单抢占、缺口事件到计划部、
缺口建分析量=缺口、产出回填可出仓量、部分先发+产出补发、出仓实发核减预留、
取消释放预留+投产守卫、在途老单不受影响、V458 谱系链不受影响、越权与对象范围、通知收件人。
