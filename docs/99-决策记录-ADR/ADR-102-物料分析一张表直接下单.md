# ADR-102 物料分析一张表直接下单

- 状态：已接受，按 2026-09-26 用户复核收敛主表与三个准备桶。
- 修订 ADR-033/081 的独立路线确认与桶内私有下单编排；数量预览以 [ADR-116](ADR-116-物料分析下达预览只读投影.md) 为准，原回滚式预览已经退役。
- 现行页面合同：[生产物料分析准备](../03-页面/生产物料分析页.md)。本文记录决策，不重复维护列宽、测试次数或部署状态。

## 背景

多次改动把准备页、三个桶、父子级联页及同料汇总页变成几套流程。原行需求转进制造锚点后，产品视图只读、显示 0 或要求跳到汇总视图，无法独立追加；父件改量又依赖子件输入框已经创建，分页和折叠状态影响自动勾选。数量预览曾把首次输入与追加输入同时累计，实际提交却只读一列。

用户要求的是稳定的原产品树、供应方式自动保存、同料自动合单以及每个子件可独立办理，不是新增需要学习的共享批次步骤。

## 决策

### 供应方式自动保存

已有主档供应方式直接带出并保存；主档未定但 BOM 能合法推导 MAKE 的情况继续按服务端建议处理。无法确定的行保持空值红框，不能下单。改选后立即保存，不再出现“确认路线”按钮或确认换桶弹窗。

自动保存走原 route 权限、对象范围、版本及幂等守卫，只确认供应方式，不创建任务或计划。人工修改失败保留草稿，自动失败只回滚该次自动产生的草稿，不能清掉人工输入；不进行无限自动重试。

### 一个办理入口

准备主表直接填写、勾选、确认下单。采购、委外、车间桶保持按岗位查看任务的作用，勾选后进入复用主表组件和状态的“核对并下单”页。旧级联页及其独立输入、预览和提交编排删除。

原行 UUID 和 BOM 路径贯穿展示、输入、选择及请求。服务端负责把原行解析到当前真实承载的需求，不能将名称匹配或首个同货品节点当作写入身份。

### 统一数量

- “需要数量”固定读取来源需求；实际备料按真实计划产出变化。
- “下单数量”显示本行实际下单量，包含超量，不能拿私有需求分配量冒充总下单量。
- “追加下单”只表示本次新增。预览与提交都只读当前有效列，旧控制器不得叠加。
- “可用数量”包含可安排的现货、在途和已下达但未办理供给的剩余量；扣除已占用/认领的量，不把在途当作可领实物。
- 各产品行的输入独立，一行手改不覆盖其它产品默认量或手工量。它们只同步共同可用和缺口，同产品父子仍按实际 BOM 联动；确认显示所有选中行的真实输入合计。可用列不加回本行已经占有的私有份额。
- 同货品编辑预算只预扣已选中且有效的本次下单/追加输入，取消勾选或减量立即释放，历史只读数量不再次扣除。它不写正式库存或认领，提交后按实际供给重建；真实办理资格与展示净缺口分别计算。
- 缺口为正的后代默认选中，与输入框是否渲染无关。手填数量和手动取消的选择分别保存。
- 首次、追加允许分批；缺少车间或负责人在同一页面补齐，不用隐藏复选框掩盖缺项。

### 同料自动合单

组件使用统一核对/提交管道，单来源和多来源遵守同一套规则；顶层产品保留销售来源的计划管道。同料只在颜色、单位、BOM、路线与制造参数相容时合并，数量相加，原来源分账仍完整保存。合单是内部单据组织方式，不再增加用户办理步骤。

预览返回真实执行目标以及完整原行集合证明，前端只沿同份分析的精确对应图验证，防止合单编号变化中断深层提交。

先顶层、再按真实父子依赖办理组件。任一步失败停止后续，不因为某条是采购或单来源就绕过依赖顺序。原工单追加条件遵循 [ADR-104](ADR-104-追加自制并入未开工的生产计划.md)，不以新建执行段冒充原工单增长。

### 同一进度

主表、三个桶和核对页使用相同的数量投影及 `ProductionFlowStage`。有真实单据阶段时显示该阶段；来源转交、库存覆盖和公共认领在详情解释，不以技术前缀替代进度。未下达、等待到货、已入库、可领料、已开工必须分别有事实证明。

三个桶统一使用平台筛选工具条，仅待处理、进行中、需处理；已下达分类退役。待处理为红色徽章，进行中为黄色，需处理是待处理的子集，用中性计数。计数与落地列表同源。完成/取消保留历史，不能回流为进行中。

表格待办状态以同一语义颜色函数映射，主表和三桶使用相同整格背景与文字色，真实业务步骤名称保留。

### 指派和货品归属

已下单顶层的生产车间和负责人取本产品真实计划/执行任务，并锁住显示；单纯采用他人供给不能借用对方指派。所属仓库、归属车间直接读取货品主档，正常入库和生产指派学习沿既有主档写入链更新。页面资料更新不能覆盖历史任务，也不能清空未提交数量和选择；旧 GET 不得回滚新归属。

## 性能与一致性

预览只读、去抖、单飞和尾随最新输入；提交期间不另发预览。页面按快照缓存索引、按页构建，父子默认选择作用于完整源数据。系统建议可变化，人工输入保持独立。

同一分析写入串行受版本、来源与库存锁保护；加速通过合批与删除重复全图读取实现，不用无界并发制造冲突。分段回执必须区分成功和未提交；网络不确定时用原幂等键核对，不能生成新键重复下单。

独立组可在同阶段合批读取来源和 BOM 责任，执行库存快照只在同一计划的锁内窗口复用，正式写入前失效，不跨计划共享。一次用户确认可包含多轮依赖提交，每轮事务原子，不能宣称后轮失败会回滚前轮已经成功的单据。分析头版本未变不代表库存、认领和主档归属未变；动态事实继续刷新，未提交输入保持独立。

本决策被接受不代表所有规模的性能已达标。实测结果及极大混合单的未完成边界见[本轮收尾记录](../99-项目治理/2026-09-26-物料准备统一流程修复.md)；验证批次与部署状态分别记录。

## 验证要求

正常/部分/超量下单、A/B 不等量合单、原位追加、开始执行后新单、多层与多路径 BOM、包装阈值、分页未渲染子件选择、父量回落、手填保留、三个桶与主表数字一致、缺路线/权限、失败保留与重试、实际供给采用和入库反向。测试记录与部署状态分别维护，历史通过结论不自动沿用。
