# V578 出货财务审核「撤回退回」

## 背景

用户实测（2026-09-14）：财务退回出货单后流程「消失」——财务「待审核」列表过滤掉已退回单、销售侧「确认并提交财务」按钮被隐藏（唯一回路是编辑→保存）、退回通知又要求归属人同时持有 `sales_shipment:view + sales_shipment:edit` 才投递（公共单/只读销售收不到任何提示）。三层叠加等价于流程卡死。

## 数据库变化（仅约束）

`sales_shipment_finance_release_events.event_type` CHECK 从 `('RELEASED','REVOKED','REJECTED')` 扩展为 `('RELEASED','REVOKED','REJECTED','REJECT_REVOKED')`。

- `REJECT_REVOKED`：财务撤回自己的退回决定，单据恢复「待财务审核」。不加表、不改历史行。

## 配套服务端行为（同批代码）

1. `POST /api/sales/shipments/{id}/finance-reject-reverse`（`finance_shipment_audit`）：仅作用于未放行、仓库未作业的退回单；清 `finance_rejected`/原因、追加 `REJECT_REVOKED` 事件、办结销售侧退回通知、重新进入财务待审队列（销售确认事实保留，无需销售重走确认）。
2. `confirmSales` 放开 `financeRejected` 分支：销售可**原样重新提交**（修订号 +1 形成新一轮提交事实，财务重新审核）；改单路径（编辑→保存→自动重提）保持不变——两条路都通。
3. 列表新增 `financeRejected` 查询参数：财务工作台「已退回」专段集中展示被退回单。
4. 退回通知投递门槛从 view+edit 放宽为 view；归属人不可达时回退投递给制单人。
5. `ShipmentWorkflowView` 新增 `canResubmitAfterFinanceReject` 供前端显示「重新提交财务审核」。

## 为什么不是状态机重构

后端回路本就完整（退回→销售编辑保存→自动重回财务队列），卡死是可见性/入口问题。本迁移只补财务侧「撤回退回」出口 + 放开销售原样重提 + 修通知投递，不动两审门禁与审计事实。
