# ADR-148 产成品实物交接批(同去向合单)

> **2026-10-07 [ADR-167](ADR-167-实际超限报工与本批产出处置.md) 补充**：同批超限份一起登记和质检，合格后暂缓放行，已授权份先办理。计划批准后续放原合格余额并生成待点收任务。分配顺序在实际超产之后增加超限份：合格最后分、不良最先扣。不同授权时点的放行不强行合入已有入库单。

- 日期：2026-10-05。
- 状态：已接受(本地源码实现，V803；Testcontainers 全链路 + 8085 克隆库真实接口验证)。
- 修订：[ADR-118](ADR-118-自制实际产出分账与公共超产.md) §4「不良/短收先扣哪一份」(见 §4、§6)；与 [ADR-151](ADR-151-表单草稿回到初始值单重参数结构化契约与入库登记单批合一.md) §5「入库登记单批合一」同批落地。
- 迁移：[V803 产成品实物交接批](../数据迁移/V803-产成品实物交接批.md)(本分支临时号，合并时由编排者重排)。
- 用户问题(2026-10-04)：「计划 1000，比例 10%，实际做了 1100，仓库登记一次，品质判一次，结果仓库收到两张入库单、两个点收任务、两条通知；点收少了 40 还先扣到了订单那份上。」

## 1. 事实

ADR-118 让一次报工按归属拆成几份报工明细：需求份(原订单/内部需求)、计划公共备货、实际超产，同一批次共用 `output_batch_id`。拆分是**归属账**，实物还是一堆货、一个去向。但下游把每一份当成一份独立实物：

| 环节 | 原来的做法 | 结果 |
| --- | --- | --- |
| 仓库登记 | 逐份一行，库位/实点/称重各填一次 | 同一堆货要登记两遍，库位可以填成两个 |
| 品质 | 逐份一条待检任务，逐份判合格/不良 | 能把不良判在需求份、超产份全合格，账实矛盾 |
| 放行建单 | 每个决定事件一张成品入库单(FINISHED_IN) | 一批货两张入库单、两条领料关联、两条通知 |
| 仓库点收 | 逐行填实收 | 少收的 40 可以先扣在需求份上，订单显示没完成而超产份却全收 |
| 车间详情/审核摘要 | 前端按 `output_batch_id` 自己拼组、拼文案 | 页面与服务端口径两套 |

## 2. 决定：实物交接批是登记、品质、点收的单位

**交接批** = 同一报工、同一产出批次(没拆分的行自成一批)、同一去向(送入仓库，或直送的同一接收需求)的各份。身份只在数据库算一次：

- `fn_daily_report_output_slice_rank(公共, 实际超产)`：归属优先级的唯一定义(需求 0 < 计划公共 1 < 实际超产 2)；
- `production_daily_report_items.output_lot_id`：生成列 = `fn_production_output_lot_id(报工, COALESCE(产出批次, 行), 去向, 直送需求)`；
- `v_production_output_handoff_lots`：交接批投影(批内各份、合计、份数、批内序号)，登记、品质、点收、车间详情共用。

页面上一行 = 一批实物；批内拆分(需求 / 计划公共 / 实际超产各多少)由服务端算好，以「其中」列和「需求 1000 · 实际超产 100」文案显示(`OutputLotText`)。

## 3. 登记：按批登记，服务端展开到各份

- 登记命令只收 `lots[{lotId, warehouseId, place, countedQty?, weight?}]`：库位、实点(先入库后质检)、称重都是整批一个，服务端按批展开到各份(称重按份数量用 `MoneyPolicy.quantitySlice` 分摊，整批只记一次称重观测)。
- 服务端按「报工 x 实际仓」分组成登记批次：**同一张报工的不同批可以进不同仓**(用户例：一张报工两批，一批进成品仓、一批进备用仓，一个命令一个事务)。
- 数据库整批守卫 `trg_assert_finished_arrival_whole_lot`(延迟)：同一批送入仓库的各份必须在同一次登记里、同一仓库同一库位一起登记，不允许部分登记(历史豁免照旧)。

## 4. 品质：整批判定，瀑布分配

- 新命令 `POST /production/quality-inspections/lots/{lotId}/decisions`：一次填整批的合格数与不良数(可只判一部分，剩下继续待检)，有不良须写处置方式与原因；幂等键 + 请求指纹，原样重放返回原结果，换内容 409。
- 服务端瀑布：**合格先满足需求份，再计划公共，最后实际超产；不良先扣实际超产，再计划公共，最后需求份**(修订 ADR-118 §4：原来没有规定先扣哪一份)。
- 命令表 `production_fqc_lot_decision_commands`(只追加)；决定事件带 `lot_command_id`。数据库守卫：
  - 分成多份的批不允许逐份判定(单份接口 `/{id}/decisions` 只用于单份批)；
  - 延迟约束按命令前各份的待判数量重算瀑布，必须与实际写下的逐份事件一致，合格 + 不良守恒；
  - 同一命令(同一登记、同一生产计划)放行出的合格行必须在同一张成品入库单里——**不跨生产计划合单**。
- 「全合格」批量(pass-all)：选中一份 = 选中它所在的整批，按批写整批命令；检查单办理页一批一行。
- 品质批量审批页(品质任务中心「批量审批」、待检处置勾选后进入的同一页)同样一批一行：检查单里的行来自检查单详情的 `lots`(批合计)，新增「本批拆分」列显示服务端拆分文案(「需求 1000 · 实际超产 100」)，本次报告列写「勾选即整批全部合格」；勾选提交时带上批内各份的检查任务(服务端仍按整批展开)，确认框逐批列出拆分，成功提示按批计数(「自制产成品全部合格 1 批」)。此前这页仍是一份一行，取消勾选超产那一行毫无作用(服务端照样整批放行)，提示还按勾选行数报数(2026-10-05 审查发现)。没有检查单的历史任务仍按份列出，属于多份批时标「整批 N 份一起判」。

## 5. 放行与点收：一批一张单、一个任务、一条通知

- 放行端口 `ProductionFinishedInboundReleasePort.createReleasedDrafts(List)` 一次处理一个命令的全部决定事件，按 `(报工, 登记批次, 仓库, 生产计划, 是否先入库自动点收)` 合单：一张 FINISHED_IN 多行(各份一行，行号按归属优先级)，领料关联与「待点收」通知每张单只写一次；任务队列一张单一个最终点收任务，「待处理数量」后显示「其中实际超产 N」，「实物批数」按批计。
- 仓库点收 `POST /stock/docs/{id}/finished-in/confirm` 只收 `lots[{lotId, acceptedQty}]`：一批只填一个实收数，**实收先满足需求份，少收先扣实际超产**；少收量留在余量单，余量单只含被扣的那几份。重放按「请求本身」认(单据 + 每批实收 + 差异原因的指纹)，锁住单据后先查确认记录再按当前明细展开：短收时收到 0 的份会被软删进余量单，响应丢了再按同一请求重试，按当前明细展开就和原来对不上——此前因此回 409「已按另一组实收数量确认」甚至 422「必须逐批覆盖全部实物批」(2026-10-05 审查发现)；现在同键同数回原结果，同键换数 409。单据详情带 `finishedLots`(批合计、拆分文案、少收规则说明、登记重量)。
- 用户例(计划 1000、比例 10%、实际 1100)：登记 1 批 → 整批合格 → 1 张入库单 2 行(需求 1000 + 实际超产 100)、1 个最终点收任务、1 条通知 → 点收 1060 → 需求 1000 + 实际超产 60 入库，余量单只有实际超产 40。
- 自制子件的需求份(直接来源)与被别的分析认领的计划公共份(公共认领来源)现在同一事务落进同一张入库单：直接来源容量守卫 `fn_assert_preplan_direct_make_exact_peg` 只数直接来源(`make_public_claim_id` 为空)，与服务端分配 `directMakeCapacity` 同一口径(V803 §7)。
- 多行成品入库单红冲按后进先出逐行撤回；同一成本池里每撤一行就当场核对该行「原样撤回」守卫(`trg_stock_value_reverse_store` / `trg_withdrawn_cost_output` 提前到本行撤回后执行一次)，口径不变——提交时再核对会因下一行把成本退回在制而误判。

## 6. 车间侧：分组与审核摘要服务端算一次

报工详情返回 `outputBatches[]`：一次录入的产出批次一行(`batchKey`、`itemIds`、`qty`、`summary`)，批内按交接批分去向组(`groups[]`：去向、接收方、合计、需求/计划公共/实际超产、拆分文案、原因、摘要)。审核确认逐批列 `summary`(例：「V51043 共 1100：送入仓库 1100(其中实际超产 100)」)；编辑草稿按 `itemIds` 把同批各份合回一行。前端删除 `routeSummary` 与 `productionDailyReportInputGroups`，不再自己按 `outputBatchId` 拼组和拼文案。

## 7. 不做的事

- 不跨报工、不跨生产计划合单；不改变直送(WORKSHOP 去向)的自检链。
- 不搬迁历史：已经逐份拆开的历史入库单、待检任务原样保留，历史登记的整批守卫豁免照旧。
- 不改 ADR-118 的分账规则本身(需求份、计划公共、实际超产怎么算)，只改「交接」时把它们当一批实物。

## 同行做法(出处为各家公开帮助文档的通行做法)

- **SAP S/4HANA(PP/QM)**：生产订单收货按物料凭证一次过账多行；质量管理按收货生成检验批(inspection lot)，使用决策(usage decision)对整批一次给出「非限制使用 / 报废 / 冻结」各多少，系统按数量过账，而不是逐个归属账去判。
- **金蝶云星空**：生产入库单可按生产订单行汇总多行；质检单按来源批次检验，合格/不合格数量回写后再入库，入库数量受「合格数」约束。
- **用友 U8/YonSuite**：产成品入库单按批次入库；来料/完工检验单按批判定后，合格数量生成入库，不合格走不良品处理。
- **Odoo**：一次收货(transfer)含多条移动行，质量检查(quality check)挂在收货或批次上；少收在收货时产生欠单(backorder)，按移动行的优先级处理剩余。

共识：**检验与实收按实物批一次做，归属/需求拆分是系统内部的分账，由系统按规则分配**；少收、不良的承担顺序由规则决定而不是由操作员逐份挑。本 ADR 的瀑布顺序(合格先满足需求、不良/少收先扣超产)让订单承诺优先兑现，超产只作公共库存补充。
