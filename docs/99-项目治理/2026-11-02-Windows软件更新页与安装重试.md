# Windows 软件更新页与安装重试

本次按用户要求重做 Windows「软件更新」页面，核对点击无反应、登录不提示及空闲自动更新。基线 `c75d6e1e3`，独立分支 `uimp/windows-update-page-20261102`。没有正式打包、上传、部署或替换现用客户端。

## 设计与范围

使用 `frontend-design`。沿用 Uten 主题：交互青绿 `#0F766E`、白色 `#FFFFFF`、背景 `#F5F7FA`、正文 `#0F172A`、次级文字 `#475569`、边框 `#E2E8F0`，全部从现有 ColorScheme 取得，深色模式由现有主题映射。字体沿用 Noto Sans SC，状态标题 24、版本 24、正文 14；使用既有圆角、间距和 UtenButton/UtenBackButton。

```text
平台名称 / 公司 / 当前设备
┌───────────────────────┐  更新内容
│ 状态与说明             │  完整说明，可选择复制
│ 当前版本 → 最新版本    │
│ 已下载 / 受阻原因 / 进度│  更新设置
│ 立即更新  检查更新     │  空闲更新与保存工作说明
└───────────────────────┘
```

工作区最大宽度 1200，宽度达到 1080 且文字倍率不大于 1.5 时双栏，其他情况纵向排列，整体左对齐并靠页面上方。比较旧方案后，去掉 156 像素的居中主视觉和高卡片，保留 80 像素设备标记；不用重复卡片、装饰渐变和新字体。版本信息及操作是主视觉。保留窄屏滚动、大字、键盘焦点、深色和减少动画支持。

## 原因与公共实现

截图里的 2.5.43 属于旧行为：更新页的命令式路由会拦住自身安全检查；后台下载又会跳过更新提示。主链已有 `5dac7bb4b` 修复这些条件，本次保留并以真实导航安全门回归，没有复制或恢复旧版方案。

本次额外修复：

- `ClientUpdateHost` 的弹窗状态仅覆盖新版提示弹窗，不能覆盖后续整个详情页访问。否则进入详情后始终不触发空闲倒计时。空闲安装同时复查可见性、本地测试限制、控制器忙碌和已交接状态。
- `installPrepared` 在第一次异步等待前占用安装状态，避免重复交接；开始重试时清除旧错误。
- `ClientStagedUpdateStore.apply` 校验缓存失败或原生报告包路径/长度/摘要无效时，丢弃损坏缓存，下次显式重试重新下载。权限或启动失败保留已校验包，不重复下载。
- 页面直接显示下载进度、已下载待安装、保存工作/操作未完成等原因；安装失败仍显示可用版本和重试按钮。已下载后的安装复用原包，检查时间显示实际时刻。
