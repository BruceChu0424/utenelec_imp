# ADR-029：生产计划前需求、全树物料分析与齐套后分批下达

- 状态：已决策；V234 业务迁移、V237 审计覆盖刷新及代码为源码候选，未部署、未完成真实 UAT，生产写链路仍为 **NO-GO**
- 日期：2026-08-08
- 决策人：业务负责人已确认本 ADR 全部业务选择
- 相关：ADR-017、ADR-019、ADR-028、生产履约 V1、V150–V195、V230
- 优先级：本 ADR 对“先建正式计划再分析”“自动递归创建正式计划”“新建 WAITING 正式计划”的描述具有替代效力；历史迁移和历史事实不改写

## 一、背景

现行候选链路以 `production_plans` 为入口：先有生产计划，再保存计划绑定的 V191 预排草案，审核时生成计划包、执行分段、物料需求和下游单据。现场实际需要反过来：先明确销售或手工生产需求，完成物料分析与备料；只有当前合格库存已经完整覆盖某个批次数量时，才生成正式生产计划。

V191 的 `production_planning_drafts.plan_id` 非空，V150 的需求/供给/预留也属于正式计划包，不能承载“尚未有正式生产计划”的分析。若页面先在后台创建空计划，只是隐藏旧流程，不是业务重构。

## 二、不可妥协的数据不变量

以下规则不因页面便利、急单或人员权限而放宽：

1. **计划前需求不是真实生产计划**：物料分析、来源判断、预计供给和备料动作不能增加正式计划量、销售已排量、报工量或入库量。
2. **在途不是现货**：采购在途、委外在途、未合格 IQC、未完工 MAKE 都只能影响预计量和预计齐套日，不能计入可立即生产量或物理预留。
3. **批准后的正式计划只接收完整套料批次**：新链路不得批准 `WAITING/AUTO_WAIT/DEFERRED` 正式计划。生成动作只创建计划草稿、`ACTIVE` planning draft 和 `SUBMITTED` plan link，不得预留；批准时才必须一次占用该批次全部直接领用物料。
4. **库存只有一个物理占用权威**：正式占用继续写统一 `stock_reservations`；分析阶段的分配是可失效的意向/模拟，不得伪装成库存预留。同一仓的全部活动分析必须在同一串行化分配口径中扣减彼此的软分配及尚未批准的 `SUBMITTED` 草稿，不能让两张分析重复宣称同一份自由库存。
5. **全树展示不能导致跨层重复需求**：树上每个节点必须保留路径、父节点和 `analysis_item_id` 需求归属。MAKE 节点的下层材料归属系统 `MAKE_COMPONENT` child item，不能同时记为父产品的直接领料需求。
6. **通知不是业务事实**：采购、委外、MAKE 备料必须先落幂等的 `preplan_supply_actions` 与逐节点 allocations，再精确关联真实采购申请、委外申请或 MAKE `PREPLAN_MAKE_TASK`/child item；消息/待办只是该事实的投影。
7. **已接受事实追加式纠错**：已生成申请、订单、库存预留、发料、报工和入库后，不能删除或原地改写；必须按来源追加取消、释放、红冲或反向记录。
8. **DRAW 不是实物发料**：生成领料需求和预留不改变在手；只有仓库审核并确认实物发出才减少物理库存。
9. **销售进度按来源和批次守恒**：一个销售订单行可以拆成多个正式计划/执行批次；每批精确分摊量之和不得超过销售行有效需求。MAKE 子需求完成不能冒充父产品完成。
10. **读模型不是写权威**：自动刷新、全树分析和预计量都是带版本的读结果；下达时必须重新锁定并重算，不能信任页面缓存。

## 三、决策后的领域流程

```text
已审核销售订单行 / 有权限的手工生产需求
  → 生产计划前需求（preplan demand）
  → 生成带版本的全树平铺物料分析
  → 逐节点人工确认 BUY / SUBCONTRACT / MAKE 路线
  → 缺口生成可追溯 preplan supply action
      ├─ BUY → 真实采购申请行
      ├─ SUBCONTRACT → 真实委外申请行
      └─ MAKE → PREPLAN_MAKE_TASK + MAKE_COMPONENT child item → 子件自身分析与备料
  → 到货、IQC 合格或 MAKE 完工合格入库
  → 重算可立即生产量
  → 选择一个或多个需求、一个目标仓并填写本次分批数量
  → 生成计划草稿 + ACTIVE planning draft + SUBMITTED plan link（不预留）
  → 有批准权人员批准并原子重算
      └─ READY 执行批次 + 完整套料预留 + DRAW + 销售分摊，plan link APPROVED
  → 仓库发料 → 报工 → 成品入库 → 销售分批进度
  → 剩余未排数量继续留在计划前需求池
```

“新建生产计划单”是业务入口名称，但进入后首先创建/选择的是计划前需求；物料分析之前不得创建 `production_plans`。齐套后“生成”才创建计划草稿和 `ACTIVE` planning draft，批准前不得产生 READY、预留、DRAW 或正式销售分摊。

手工需求必须显式选择 `REWORK`、`TRIAL`、`SAMPLE`、`STOCK` 或 `OTHER`，填写稳定且唯一的业务需求编号、原因、责任人、需求日期和产品；不得用自由文本重复创建同一需求，也不得伪造销售订单关联。同一来源类型与需求编号只能归属一份物料分析，历史记录完成或取消后仍须从记录中回查，不能换幂等键重新建单。`MAKE_COMPONENT` 只允许系统由 MAKE supply action 创建，不能由用户手工选择。所有来源都不能绕过齐套门禁。

## 四、全树平铺与 ADR-028 的边界

### 4.1 全树平铺是分析读模型

一次分析可以递归展开完整 BOM，用一个平铺列表展示所有层级。每行至少包含：

- `node_key`、`parent_node_key`、`path`、`depth`；
- `analysis_item_id` 所属顶层需求和父节点归属；
- 产品/组件、基本单位用量、累计需求量、损耗和精度；
- 主档建议路线、人工确认路线、覆盖原因；
- 当前自由库存、已预留、冻结、安全库存、合格可用量；
- 采购/委外/MAKE 在途和预计可用日；
- 当前缺口、依赖状态、阻断原因和下游动作状态。

同一物料在同一 `analysis_item_id`、同一路线、同一仓货色维度可作展示汇总，但必须保留原始 BOM 路径明细，不能丢失需求归属。

### 4.2 依赖必须保留

- 顶层产品只消耗其直接 BOM 层的物理组件。
- 对每个 `analysis_item_id`，只有 `depth=1` 的直接组件是当前需求的可操作节点，允许确认路线和创建 supply action；`depth>1` 只作依赖提示，不得进入当前需求的路线确认门禁、通知分组或下游数量合计。
- 路线确认是缺料通知和下游备料动作的门槛，不是已齐套批次的 blanket 生成门槛。需求 100、当前完整齐套 10 时，即使剩余 90 尚未确认 BUY/MAKE/SUBCONTRACT，也允许生成 10；只有正式 BOM 行既无人工确认路线、主数据来源也无法解析时才 fail-closed。
- 路线确认为 MAKE 的组件，若库存不足，生成 `PREPLAN_MAKE_TASK` 和系统 `MAKE_COMPONENT` child item；其下层材料由 child item 负责。
- child item 最终形成的子件计划完工并合格入库后，父需求才能把该组件计入当前可用量。
- 页面可一次看到整棵树，但不能一键把整树都变成正式计划，也不能把子层材料同时预留给父计划。

### 4.3 对 ADR-028 的替代

ADR-028/V230 的 full-tree orchestrator 会自动审核并递归创建正式 MAKE 子计划。新链路不再调用该写入口：

- `generate-planning-package-full-tree` HTTP 写入口永久返回冲突，不因配置重新开启；底层服务只保留作历史兼容审计，不得被新页面调用；
- 新页面不得显示“整树确认正式计划”动作；
- V230 字段和历史候选代码不删除，旧数据只读兼容；
- “最深层优先”保留为 `MAKE_COMPONENT` child 备料排序，不再等于自动创建正式计划；
- 只有 child item 自身完整套料后，才按本 ADR 生成其正式子件计划。

## 五、立即量、预计量与完整套料

### 5.1 可立即生产量

```text
当前自由量(仓、货、色)
= 当前合格在手
 - 有效统一预留
 - 冻结量
 - 安全库存

可立即生产量
= min(
    需求剩余未排量,
    floor(各直接领用组件当前自由量 / 每件基本单位用量)
  )
```

结果按产品基本单位精度向下取整，不允许四舍五入扩大。分析可展示多个有权仓库的库存分布和调拨候选，但每次生成必须选择**一个目标仓**；可立即生产量只按该目标仓当前合格自由库存计算。其他仓库存不得跨仓合并为立即量，只有调拨审核入目标仓后才可重算使用。

联合分析中的共享物料只能进入一个服务端完整套料池，并按持久化的 `line_priority` 稳定分配；不同分析之间也必须按目标仓串行刷新，先扣除其他活动分析的剩余软分配及 `SUBMITTED` 草稿用量，再计算本分析。产品的可立即量、直接层已分配现货、缺口、通知数量、调度列表和销售进度必须读取同一次分配快照，禁止各页面按单行重新计算而重复使用同一份自由库存。分批提交时，相应数量从分析软分配原子转换为 `SUBMITTED` 草稿软占用，总承诺量不能暂时或永久增加。调整优先级只是分析模拟，不等于物理预留；提交时仍须带版本、指纹和幂等键，批准时再次锁库重算。

### 5.2 预计可生产量与预计齐套日

预计量可计入已经审核、未取消、数量和预计日期明确并且精确 peg 到该需求的采购、委外和 MAKE 未来供给。它只用于排序和承诺风险提示，不得用于“生成正式计划”按钮的最大值。

页面必须同时显示“可立即生产量”“预计可生产量”“预计齐套日”和“数据更新时间”，禁止把两个数量合成一个模糊的“可生产量”。

### 5.3 生成草稿与批准下达

当目标仓 `可立即生产量 = 0` 时，“生成生产计划”必须禁用并显示具体短缺原因。当大于零时，本次数量必须满足：

```text
0 < 本次下达量 <= 服务端重算后的可立即生产量
```

普通“生成生产计划”执行提交阶段：

1. 校验计划前需求、销售来源、分析版本、路线、目标仓和提交数量；
2. 创建 `production_plans` 草稿、计划行和 `ACTIVE production_planning_drafts`；
3. 创建 `production_material_analysis_plan_links(allocation_status='SUBMITTED')`，同步该 item 的 `submitted_qty`；分析头仍使用 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED` 聚合状态；
4. 不创建执行批次、`stock_reservations`、DRAW、正式销售计划分摊或未来供给预留。

随后由持 `production_plan:approve` 的人员批准。批准事务必须按稳定顺序锁定计划前需求、草稿计划、销售来源、BOM/分析版本和目标仓货色库存键，然后：

1. 重算需求剩余量和完整套料数量；
2. 校验路线、BOM 结构策略、单目标仓、对象权限、职责分离及幂等键；
3. 审批草稿计划并创建 READY 执行批次；
4. 创建该批次全部直接领用物料的统一物理预留；
5. 创建精确销售订单行分摊；
6. 生成 DRAW 领料需求；
7. 将 plan link `SUBMITTED → APPROVED`，把 item 的数量从 `submitted_qty` 转入 `approved_qty`，再派生分析头 `PARTIALLY_PLANNED/COMPLETED`；
8. 写语义审计与 Outbox。

批准的任何一步失败全部回滚，草稿计划和 `SUBMITTED` plan link 保持可见并返回差异，不得留下部分预留。正式 READY 计划依赖的是已经在目标仓合格可用库中的物料，不得额外创建“未来供给预留”来伪装齐套。

若操作者同时持 `production_material_analysis:generate` 与 `production_plan:approve`，页面可显式提供“生成并批准（approveNow）”。该命令在同一事务完成草稿/ACTIVE planning draft 创建和上述批准步骤；任一步失败整体回滚。系统不得因账号有批准权而默认跳过确认，也不得让无批准权人员调用 `approveNow`。

多选生成默认整批原子成功或失败；若未来支持分组提交，必须由用户明确分组，并为每组使用独立幂等键和结果，不得静默部分成功。

## 六、路线确认与备料动作

### 6.1 路线是人工确认事实

主档 `source_type` 作为建议值，计划员只对当前 `analysis_item_id` 的 `depth=1` 可操作节点确认 `BUY`、`SUBCONTRACT` 或 `MAKE`。偏离建议值时必须填写原因；服务端校验节点层级、产品是否允许目标路线、供应/工艺必要主数据和操作者权限。深层依赖行必须显示“由上级自制子需求展开”等文字提示，服务端也必须拒绝对其保存路线或下达通知。

路线确认按分析版本/指纹保存。BOM、数量、目标仓或有效来源变化后必须刷新并使旧预览失效，不能直接用于下达；系统应保留确认人、时间和变更原因。

### 6.2 preplan supply action

缺口的“通知采购/委外/自制”必须先写 `preplan_supply_actions`，通过 `preplan_supply_action_allocations` 精确分摊到分析节点，并保存目标仓、路线、缺口数量、需求日期、幂等键、业务键、请求哈希、代次、状态和下游来源。action 状态使用 `OPEN/CREATED/IN_PROGRESS/DONE/CANCELLED`。

| 路线 | 权威下游 | 规则 |
|---|---|---|
| BUY | 采购申请行 | 申请保留 preplan action 和原始需求行关联；后续采购合单不丢来源 |
| SUBCONTRACT | 委外申请行 | 申请保留 action/需求来源；委外发料、回厂和 IQC 仍走各自权威链路 |
| MAKE | `PREPLAN_MAKE_TASK` + `MAKE_COMPONENT` child item | 先形成子件计划前需求和备料任务；子件齐套后才生成正式子计划 |

通知、任务角标、邮件或 Outbox 消费结果不能代替上述 action 与下游业务关联。

未生成真实下游单据且未被其他事实引用的 action 可以撤回并保留撤回事件。已经形成采购/委外订单、库存发出、正式计划或其他已接受事实后，必须调用对应取消/反向流程；不得直接删除 action 或下游单据。

## 七、无 BOM 与结构越权

无 BOM 不能自动等于“可以直接生产”。产品主数据必须显式维护生产结构策略：

- `BOM_REQUIRED`：应有有效 BOM；缺失、失效、循环或单位不可换算时阻断分析确认和下达；
- `DIRECT_MAKE`：业务确认无需 BOM 展开，可按直接自制处理并形成可生产数量；
- `NOT_PRODUCED`：不得走 MAKE 或生成生产计划。

迁移不得根据“当前无 BOM”自动批量猜测 `DIRECT_MAKE`。存量产品进入新链路前必须由业务逐项认定。

紧急情况下对 `BOM_REQUIRED` 缺失进行单次越权，必须使用独立高风险权限，填写原因，限定到某条分析 item/计划并记录越权人，写语义审计；它不修改产品主档，也不能绕过循环 BOM、单位不可换算或非法货品状态。若未来要求附件，须用 V235+ 追加不可变证据关联，不得把不存在的附件当成 V234 已实现。该权限默认不授任何部门，只允许超级管理员固有能力或逐人加授。

## 八、共享物料调配

分析页允许计划员在多个计划前需求之间模拟分配同一自由库存，帮助决定先生产哪个产品。分析分配必须：

- 只使用当前未预留、未冻结且扣除安全库存后的自由量；
- 保存版本和分配意向，但不写 `stock_reservations`；
- 在任一需求正式下达时重新锁定、重算，并以实际原子预留结果为准；
- 冲突失败时返回受影响物料和需求，不自动重试业务写操作。

已经被 READY 正式计划预留的库存不能在分析页直接“拖走”。确需改派时，必须校验原计划尚未发料/开工，使用独立高风险权限先执行原计划释放或反向，再给目标需求重新下达；原因、源计划、目标需求和数量均须审计。

## 九、历史 WAITING 兼容

- V234 新链路不再创建 `WAITING`、`AUTO_WAIT` 或 `DEFERRED` 正式计划/执行分段。
- 历史记录不回填、不伪造计划前需求，也不删除；新工作台只读显示“历史待料计划”标签和来源版本。
- 历史记录不得参与新计划前需求的可下达数量或共享调配。
- 处理历史待料计划只能走受控的旧兼容入口、完成既有链路或执行取消/反向；兼容入口必须 feature flag 隔离，并在存量清零后退役。

## 十、销售分批进度

销售页以“订单 → 订单行 → 正式生产批次”展开：

- 展示需求量、已下达量、待分析/待料量、生产中、合格入库、已发货和剩余量；
- 每个正式批次显示计划号、本批数量、状态、预计/实际日期；
- 同一订单行可对应多张计划和多个批次；同一生产批次也可按精确分摊承接多条销售行；
- MAKE `MAKE_COMPONENT` child item/正式子计划作为物料依赖单独下钻，不计入父成品或销售完成量；
- 进行中/已完成由阶段数量投影推导，不向销售订单行维护一个人工百分比真相。

## 十一、权限与对象范围

V234 源码候选必须在数据库权限目录、后端常量/鉴权、Flutter `Perm`、默认部门矩阵和权限管理页同步以下实际权限码；迁移落库和 UAT 前不得宣称目标环境已实现：

| 实际权限 | 能力 | V234 默认部门 |
|---|---|---|
| `production_material_analysis:view` | 查看计划前需求、分析、即时/预计量和历史 | `GM/DEPT_PROD/DEPT_ENG/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:manage` | 新建、编辑、保存或撤回未下游化需求/分析 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:route` | 确认或覆盖 BUY/委外/MAKE 路线 | `GM/DEPT_PMC/SUB_PLAN`；覆盖必填原因 |
| `production_material_analysis:notify` | 生成/撤回未下游化 supply action | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:generate` | 从齐套分析生成计划草稿和 ACTIVE planning draft | `GM/DEPT_PMC/SUB_PLAN`；本动作不预留 |
| `production_material_analysis:reallocate` | 共享自由库存分配及受控改派入口 | `GM/DEPT_PMC/SUB_PLAN`；已预留事实仍须先反向 |

## 十二、迁移、测试与发布边界

V234 源码候选只追加 `goods.production_bom_policy`、`production_material_analyses/items/materials`、`preplan_supply_actions/allocations`、`production_material_analysis_commands/plan_links`、计划来源字段、实际权限和审计，不修改已应用 V150–V230。V234 没有第二套库存账；共享调配是预览/决策，不是 `stock_reservations`。V234 一旦在任一目标库应用，任何修复只能追加 V235+。

发布按以下阶段控制：

1. **只读阶段**：入口改名、历史按钮、需求选择、全树平铺、立即/预计量和依赖提示；不得产生业务写事实。
2. **计划前写阶段**：需求、路线和 supply action 完整落库并可撤回/反向；采购、委外、MAKE 来源可追溯。
3. **生成与批准阶段**：齐套分析先生成计划草稿 + `ACTIVE` planning draft 且不预留；持 `production_plan:approve` 者批准时原子创建 READY、完整预留、DRAW 和销售分摊，或显式使用同事务 `approveNow`。阶段 2 与 3 必须一起达到生产可用标准。
4. **存量与上线阶段**：历史 WAITING 清理/兼容、真实多账号权限、目标库迁移、历史对账、仓库/IQC/采购/委外联调、压力和恢复演练、业务签字。

最低测试矩阵包括：无 BOM 三种策略、深层/循环 BOM、重复物料多路径、单位精度、单目标仓与跨仓调拨候选、库存同时抢占、普通生成不预留、批准重算失败、`approveNow` 原子回滚、职责分离、需求改量/取消、部分到货、IQC 隔离、超收/退货、路线变化、重复通知、MAKE 多层依赖、批量下达回滚、旧 WAITING 隔离、发料后反向、销售一行多批和多行合批、对象级越权及移动端操作可达性。

源码存在迁移或单测不等于目标库部署。未核验目标环境 `flyway_schema_history`、未完成真实岗位/实物 UAT、未通过反向与并发测试前，生产写链路保持 **NO-GO**。

## 十三、结果与取舍

本决策增加了计划前领域对象，但它不是平行生产主链：正式生产、库存、领料、报工和入库仍复用现有权威模型。新增对象只承载正式计划产生前原本缺失的需求、分析、路线和供给动作事实。

代价是需要 V234 迁移、权限拆分、历史兼容和跨模块联调；收益是现场不必先造一张错误的正式计划，分批生产、缺料备料、共享物料决策和销售进度都能保持可解释、可追溯及可反向。
