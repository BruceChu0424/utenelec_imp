## 批量办理与数量核对

所选明细直接进入办理页的统一表格，默认先状态、再单号，随后展示本业务需要的车间/往来、货品、数量及仓库。来源摘要只使用真实接口字段，不作为再进入逐单编辑的中间步骤；摘要、草稿和表格都不能扩展本次所选明细。单据备注与明细备注沿用各自原值和字段。右下显示「已选 X 项」及确认主操作；返回、刷新和核实结果保持次级样式。各业务原有单仓/分仓、数量和权限约束继续由原服务端契约决定。

| 分类 | 核对与执行 |
|---|---|
| 销售出库 | 只有「确认出库」一个动作（V582 一步式）。货品、数量(2026-10-10 起单位内联跟数字后，独立「单位」列删除)、实际仓库、建议库位、实际库位及来源订单逐行展示；无仓提交的单在此选实际叶仓。 |
| 委外出库 | 仅核对所选原始物料行；按正数行原子生成执行单及新明细 UUID，保存不可变原行谱系，再沿原审批/库存内核执行。本次数量不超过原申请量，不加行、不删原行、不互借预留；未选与填 0 的行仍在原待发草稿，预留不动。明确的原单详情保留其整单业务契约，不能冒充所选明细入口。 |
| 生产领料 | 普通 DRAW 保留原整批命令及精确 itemIds；内料仓 ISSUE 直接在同一张表填写本次数量/仓库，一次确认，按原申请分别执行，未选明细继续待办。 |
| 其它 / 产成品出库 | 只勾选未关闭草稿，按整单数量出库。选择不完整时明确阻止提交并提示补选；需改量时先编辑草稿，不把未选行静默加入本次办理。明细展示实际库位号与当前建议库位，避免把主档建议冒充出库事实。 |

命令按实际业务粒度执行，不把跨来源批次声称为一个原子事务；独立原单命令首个异常后停止新派发，保留成功与未处理记录。未知结果只按原命令和原范围核对，不随网络恢复自动发起新命令。恢复时未派发 B 取消、删除或不可读，只阻断 B；当前可读 A 的原未知命令仍可核对，不用 B 的旧敏感快照回填表格，也不把 B 算作完成。原本一条覆盖完整集合的命令不得拆成子集重放。

其它与产成品出库使用 `GET /api/stock/docs/{id}/outbound-review` 取得明细和 `reviewToken`，确认提交 `POST /api/stock/docs/{id}/approve-reviewed`，任务入口携带 `{expectedReviewToken, itemIds}` 的精确范围。服务端持单据锁校验核对快照与完整明细集合后进入原审批/库存事务；货品、数量、换算率、仓库、来源或明细集合变化返回冲突。快照不是授权或幂等凭据，仍执行原权限和对象范围校验；旧的明确整单 `/approve` 入口保持兼容。

原生其它/产成品出库没有持久命令键，未知结果只读核对原单的当前状态与原行集合，不伪造幂等协议或自动重发。邻居单不可读、取消、删除或原行集合变化时以来源 ID 占位隔离，不挡仍可读取的原单核对。

**实称重量**：委外出仓明细表(单张拣货出仓页与批量出库详情共用)在「单位」后有可编辑「实称重量」格([ADR-135](../99-决策记录-ADR/ADR-135-仓库重量账与单重自学习.md) / V743)，规则见[仓库委外出仓工作台页](仓库委外出仓工作台页.md)。

委外所选正数行的本次出仓上限为原申请量(`requestedQty`)，少发部分在该原子执行事务中释放对应未用预留，后续领料只补该物料的缺额；未选/0 行仍由原草稿及原预留覆盖。仅编辑数量不会提前释放预留，界面显示不会改写库存或谱系。

## 二、页面结构

仓库任务中心只保留方向与来源两行导航，阶段由表头筛选。默认不预选来源，任务深链可直接定位；未选来源时不请求列表。销售、委外、生产领料、其它出库和产成品出库共用 `WarehouseTaskRecordsView`，各行保留原单据及实物明细 UUID；授权、仓库范围、搜索、状态、单号及分页都在服务端形成同一完整结果集。

- 销售出库只显示财务放行后的仓库实物任务，不提供自建销售出库。委外出库只接委外人员已提交的直属物料领料草稿，仓库不自行生成来源。
- 生产领料同时包含普通 DRAW、待认料申请与内料仓 ISSUE，保留各自原始命令族和权限。内料仓直接发料入口放在本来源，退回已移至入库的生产退料。
- 其它出库、产成品出库沿原库存单据草稿与审核流程。只有审核权限时下发 `STOCK_REVIEW` 核对动作，不要求额外编辑权限；只读交接对象不会因能看见而获得审核能力。
- 「全部任务」汇总授权的进行中来源；「历史单据」查询同方向已办结或已撤回记录，通用草稿不计真实待办。历史详情同样保留点击的实物行范围。
- 右下悬浮组统一显示「已选 X 项」与批量动作。双击一行与多选都保留原始明细 ID；核对页及请求不能自动加入同单未选货品。不能安全分行办理的原单据在提交前明确要求选择完整范围，不静默扩大。不同命令族不能混成同一事务或静默过滤成员。

## 三、角标口径

- 销售待出库数来自 `warehouseSalesOutbound` 的 `PENDING_PICK` 原始实物行事实；历史迁移异常、已出库、取消及红冲不冒充待办。委外待发料来自 `subcontractOutbound.count`，只数已提交、未撤回且仓库未发的真实货品行，不按到货数触发。
- 生产领料合并 `productionDraw` 与 `workshopMaterial.pendingIssue`。内料仓退回计入入库方向，内料仓审核分类不再重复计发退料。其它与产成品出库只有通用草稿/历史，不挂待办红数。
- 来源、大类和工作台消费同一服务端仓库范围的徽章事实，不用列表首屏或 `size:1` 凑数。每个事实只参与模块合计一次，关键字、页码和历史浏览不缩小模块徽章。
- 数字未就绪不显示半程合计；失败保留异常状态，不能把未知当成零。选仓参数仍为 `scopeWarehouseId`，越界由服务端拒绝。

## 四、业务口径与边界

- 销售出库只在财务放行（financeAudit=1 且未驳回）后出现；已出库(SHIPPED)、
  取消、红冲不计入待办角标。列表不按单据 `status` 过滤(2026-09-20 修复：确认出库把
  `status` 翻成 1, 此前「已出库/历史单据」段永远为空)。本页不含商业/财务字段。
- 委外出库只显示委外人员在委外任务中心「待处理·领料」提交的领料草稿(委外件的直属物料，按冻结单耗算好的领料数量)；
  仓库不生成草稿，不想再发外由委外人员结束领料。委外人员撤回后草稿从列表消失并通知仓管。
  默认列：状态 / 领料单号 / 货品名称 / 编码 / 颜色 / 规格 / 数量及单位 / 来源单据 / 委外商 / 领料仓 / 业务日期 / 提交人；搜索单号、委外商或货品。
  详见[仓库委外出仓工作台页](仓库委外出仓工作台页.md)。
- **各分段表头列筛选**：统一任务表「状态」列使用服务端来源阶段桶，选中即重拉回第 1 页；
  委外出库段提供状态与单据号表头筛选，也可用搜索框查找。
- 其它出库/产成品出库为仓库原生单据（stock_documents），草稿 → 审核写库存；
  生产链生成的单据禁止通用编辑/删除（服务端守卫）。
