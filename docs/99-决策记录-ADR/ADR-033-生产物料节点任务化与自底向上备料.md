# ADR-033：生产物料节点任务化与自底向上备料

- 状态：业务设计已决策；当前并发工作树已有逐路径节点键、路线驱动下层需求、MAKE 下层门禁、child ownership 委派投影和同页任务交互的源码候选，后端定向 29/29、Flutter 页面/模型 25/25、目标 4 文件 analyze 无问题。当前没有 V251 显式 `delegated_qty` 表，分批委派量、完整反向及真实 PostgreSQL/HTTP/浏览器/岗位实物流转仍未闭环；未部署目标环境，生产写链路仍为 **NO-GO**
- 日期：2026-08-11
- 相关：ADR-019、ADR-024、ADR-028、ADR-029、V150–V250、生产履约 V1
- 优先级：本 ADR 部分取代 ADR-029 §4.2、§6.1、原 2026-08-10“深层缺料可直接下达”订正和相关页面口径；ADR-029 关于分析与正式计划分层、库存/质检/审批权威、追加式反向及历史兼容的规则继续有效

## 一、背景

ADR-029 已把“先造正式计划再看缺料”改为“先分析、齐套后生成计划”，也保存了完整 BOM 路径。但是后续页面仍把大部分深层节点解释为“随上级件”，只有直接层或碰巧计算出缺口的深层行可以操作。现场看到第二、三、四层货品，却看不到每条路径自己的现货、有效需求、任务状态和下一步，无法按真实备料顺序工作。

此前增补提出“`depth=1 或 shortage>0` 即可操作，并按 `goods+color+unit` 的开口供给去重”。该规则不成立：

- `shortage` 本身取决于需求是否已经沿父子路径激活，不能拿计算结果反过来定义任务身份；
- 同一货品出现在两条 BOM 路径时，责任上是两个节点任务，可能有不同父件、需求日、路线、批次和反向范围；
- 物理库存可以在仓货色维度共享分配，但业务任务不能仅凭货号合并或相互抵消；
- 按货品去重会让一条路径的 action 错误吞掉另一条路径的需求，失去来源、数量和反向证据。

因此需要把“树上的展示行”提升为有稳定身份的物料节点任务，并明确何时激活后代、何时把任务所有权委派给 MAKE 子分析。

## 二、术语与任务身份

### 2.1 每条 BOM 路径都是独立节点任务

完整 BOM 树中的每个 `analysis_item_id + path/node_key` 是一条独立的物料节点任务。至少保存或稳定投影：

- 所属分析需求、父节点、路径、深度和 BOM 快照；
- 本批激活需求量、已由现货覆盖量、真实短缺量和被委派量；
- 建议路线、人工确认路线、路线原因和版本；
- 目标仓在手、有效预留、冻结、安全库存、合格可用量及其他仓参考；
- 下游 action、采购/委外申请、MAKE 子分析、正式计划和执行状态的来源链接。

同一货品出现在不同路径时任务身份不得合并。服务端可把兼容的 BUY 或 SUBCONTRACT 需求合并到一张下游申请，但必须通过逐节点 allocation 保留每条路径的数量、父件和反向范围；不得用 `goods+color+unit` 的开口数量作为节点任务去重依据。

### 2.2 树默认完整展开

进入分析详情后，根产品和全部 BOM 层级默认展开。员工可以手工折叠分支，但刷新、生成计划或返回本页不得把未处理分支静默隐藏。

每一行无论本批需求是否激活，都显示目标仓现货与合格可用量。推荐的主列为：

| 物料与路径 | 路线 | 本批需求 | 合格可用 | 缺口 | 任务状态 | 操作 |
|---|---|---:|---:|---:|---|---|

`required_qty=0` 只表示当前批次不需要为该路径补货，文案统一为“本批无需补货”；不得显示“齐套”“有货”或“随上级件”来暗示已经形成独立需求。现货仍照常展示。

## 三、需求沿路径激活

### 3.1 只按父件实际未覆盖数量展开

根产品本批数量先激活其直接组件。任一父节点只把自身未被合格现货覆盖的实际短缺数量向下展开，不能按父件全部需求重复展开后代。

父节点路线决定后代是否激活：

| 父节点路线 | 父节点短缺的处理 | 后代任务 |
|---|---|---|
| BUY | 形成 BUY 物料任务与采购申请 | 不激活；各行仍显示仓库现货并标“本批无需补货” |
| MAKE | 先在当前树按父件实际短缺量展开其 BOM | 激活，用于判断该 MAKE 节点可生产批量 |
| SUBCONTRACT | 形成委外物料任务；若该委外件有有效供料 BOM，则按父件实际短缺量展开我方供料 | 激活我方供料节点；无供料 BOM 时不虚构后代需求 |
| 未确认/结构异常 | 保留路径和现货展示 | 不生成下游事实，显示待确认或结构阻断 |

SUBCONTRACT 在这里表示外部加工成品由委外供给；其已配置 BOM 的下层材料是我方需备齐并依法发给委外商的供料，不代表由供应商自行采购。委外发料、供应商处库存、耗用、退料、损耗和回厂 IQC 仍遵守既有权威链路；该链未验收前继续 fail-closed。

### 3.2 库存分配与任务身份分离

目标仓合格自由库存仍在仓货色维度进入一个服务端共享池，按稳定优先级分配，不能被多个路径重复宣称。分配结果必须回写到各自路径任务。

“共享库存池”不等于“共享任务身份”。同货不同路径即使最终被合并采购，仍须分别保存：

- 各路径激活需求、现货覆盖和缺口；
- 各路径 action allocation；
- 各路径被取消、改道、委派、收货兑现或反向的数量。

## 四、路线动作、MAKE 委派与计划生成

### 4.1 BUY 和 SUBCONTRACT 是物料任务

BUY 行可执行“通知采购”，形成幂等 supply action、逐路径 allocation 和真实采购申请。

SUBCONTRACT 行可执行“通知委外”，形成幂等 supply action、逐路径 allocation 和真实委外申请；若有我方供料 BOM，其后代物料任务继续按自身路线备料。采购/委外任务不是 `production_plans`，不得显示成生产子计划。

通知、消息和角标都不是完成事实。状态必须来自 action、申请、订货审批、预计到货/回厂、IQC 和合格入库。

### 4.2 MAKE 先齐下层，再创建子分析

MAKE 节点在下层实际齐套前只是当前父树中的自制物料任务，不立即创建 `MAKE_COMPONENT`，更不能直接生成正式子计划。

当服务端按目标仓、当前版本和 BOM 指纹重算，确认某个正数量批次的直接下层物料全部合格齐套后，员工才可在该 MAKE 行点击“安排生产”。该命令必须在一个事务中：

1. 锁定父节点任务、相关后代路径、共享库存软分配和幂等命令；
2. 计算本次可生产的正数量批次，不超过该 MAKE 节点真实短缺；
3. 幂等创建系统 `MAKE_COMPONENT` child analysis item，并精确回指父路径任务；
4. 把本批对应的后代路径和数量标记为 `DELEGATED`，由 child analysis 接管；父树保留可见和下钻，但不得再次确认路线、通知或占用同一数量；
5. 若仍有未安排数量，仅剩余数量继续在父树保持活动，不能把整条路径一次性委派而吞掉余量。

`DELEGATED` 是任务所有权转移，不是现货预留、领料、开工或完工。child analysis 仍须按 ADR-029 的齐套门禁生成正式计划草稿。

当前源码候选以“父路径已存在系统 `MAKE_COMPONENT` child item”推导 child ownership，并让父树后代不再形成可操作需求；尚无 V251 显式 `delegated_qty` 记录。因此当前证据只能证明节点级所有权投影，不能宣称“同一路径任意部分数量委派、剩余数量继续活动及其反向”已经持久化闭环。若一个节点允许分批委派，必须在上线前用现有事实证明数量可唯一恢复，或按 §7 追加 V251+。

### 4.3 只有 MAKE 与根产品生成生产计划

- BUY、SUBCONTRACT 只形成物料供应任务及其权威下游，不生成生产计划。
- MAKE child item 的本批直接材料齐套后可以生成真正的子生产计划。
- 根产品本批直接组件齐套后可以生成最终组装生产计划。
- 任一正式计划仍先生成草稿、`ACTIVE` planning draft 和 `SUBMITTED` plan link；批准后才原子形成 READY、完整物理预留、DRAW 和销售分摊。

生成计划后页面保持在当前物料分析，不强制跳转。对应 MAKE 或根产品行刷新为“草稿待审/已批准待领料/生产中/已完工入库”等服务端投影，并提供“查看计划”深链。员工可继续处理其他节点。

## 五、状态和操作必须来自权威事实

节点任务至少区分以下可解释状态，名称可由 UI 本地化，但不得由前端直接改写：

- 本批无需补货、路线待确认、缺料待处理；
- 已通知采购、采购处理中、等待合格入库；
- 已通知委外、委外处理中、等待供料/回厂/IQC；
- 自制下层备料中、下层已齐套、已委派子分析；
- 计划草稿待审、READY 待领料、已部分领料、生产中、已完工入库；
- 结构阻断、已取消或待反向。

“已领料”只来自仓库实际 `issue`；“生产中”只来自正式执行段/报工；“已完工入库”只来自审核合格的成品入库。页面按钮不能直接制造这些状态。

## 六、继续有效的权威边界

本 ADR 不改变以下 ADR-029 不变量：

1. 分析软分配不写 `stock_reservations`，也不扣在手。
2. 在途、待检、冻结和不合格数量不能计入当前齐套。
3. generate 不预留；approve 才原子创建 READY、完整预留、DRAW 和销售分摊。
4. DRAW 不是实物发料，仓库实际出库才扣库存。
5. MAKE 子件完工不能冒充父成品或销售订单完成。
6. 已接受的申请、订单、预留、发料、报工和入库只能追加式取消、释放、红冲或反向。
7. 所有写命令使用对象权限、版本、BOM 指纹、幂等键、稳定锁序和服务端数量重算。
8. 不恢复 ADR-028 的递归自动创建/自动批准整棵正式计划树。

## 七、数据与迁移要求

当前候选使用稳定 path action key、现有 action/allocation、`parent_analysis_material_id` 与 child item 存在性表达路径身份和 child ownership，没有新增 V251 委派数量表。若这些既有事实不能无歧义恢复“激活量、委派对象、委派数量和反向余量”，只能通过 V251+ 新增字段、表或只读投影实现；不得修改任何已应用 Flyway 文件，也不得借 `required_qty=0`、删除节点或按货品合并掩盖所有权。

建议的逻辑唯一维度为“分析需求 + 路径节点 + 代次”，委派还须记录来源节点、目标 child item、数量、时间、操作者和幂等命令。一个下游 action 可以承接多个兼容路径，但 allocation 总量必须等于 action 数量，每条路径累计 action/委派/现货覆盖均不得超过其激活需求。

## 八、最低验收

至少验证：

1. 进入页面默认展开完整树，所有层级都显示目标仓现货；`required=0` 只显示“本批无需补货”。
2. 同一货品位于两条路径时形成两个节点任务；共享库存不超分，下游即使合单也保留两条 allocation。
3. 父件部分有货时，MAKE/SUBCONTRACT 只按实际短缺展开后代。
4. BUY 父件不激活后代；改为 MAKE 或有供料 BOM 的 SUBCONTRACT 后按版本重算。
5. MAKE 下层未实际齐套时不能创建 `MAKE_COMPONENT` 或生产计划。
6. 创建 MAKE child item 后，已委派数量在父树只读，不能重复通知、重复软分配或重复生成计划；剩余数量仍可后续分批处理。
7. BUY/委外动作不生成 `production_plans`；只有 MAKE 与根产品能进入计划生成。
8. 生成后留在当前页面，刷新能看到真实计划、领料、生产、入库状态；无权或失败必须明确反馈。
9. 并发刷新、通知、委派、生成、取消和反向保持数量守恒、幂等与来源完整。

## 九、发布结论

本 ADR 是业务和验收合同，不是生产实现证明。当前并发工作树的源码候选和定向自动化已覆盖其中一部分，但既有 V250 隔离克隆与页面截图早于本 ADR；显式分批委派量、完整取消/反向、真实 PostgreSQL/HTTP/浏览器和多岗位实物流转仍未覆盖。

在 V251+（如需要）迁移、源码、数据库约束、自动化、目标库校验、历史对账、真实计划/采购/委外/仓库/质量/车间 UAT、并发与恢复演练及业务签字全部完成前，相关生产写能力继续 **NO-GO**。
