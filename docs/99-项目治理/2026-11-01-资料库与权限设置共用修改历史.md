# 资料库与权限设置共用修改历史

本轮从本地 `bd7e8525b` 隔离实施，分支 `uimp/history-company-permissions-20261101`。范围为前端呈现、后端历史记录与共享权限契约；不含发布、部署或客户端打包。默认按 `frontend-design`，沿用 Uten 主题和组件。

## 实现比较与公共入口

| 原入口 | 已有能力与必要差异 | 本轮处理 |
|---|---|---|
| 基础资料 `MasterRecordHistoryPage` / `MasterRecordRevisionPage` / `MasterRecordHistoryAction` / `MasterRecordRevisionBody` | 表头筛选、近三个月日期门、游标分页、来源/操作/人员筛选、前后对照、恢复前后版本；已有 B0 身份/权限/请求代次保护 | 展示、请求、导航和状态实现迁入 `lib/shared/history/`，旧路径保留薄入口或兼容导出，全部原调用方自动使用同一实现 |
| 公司资料库 `CompanyFilesPage` | 原有树、ACL、密码解锁、回收站；原先没有业务修改历史入口 | 顶栏查看可见资料历史；文件/文件夹右键可查看当前对象历史；两处都使用公共历史入口 |
| 权限设置 `AdminPermissionsPage` | 员工/部门/基础包/模板授权及语义审计；账号支持与授权管理权限有区别 | 授权管理顶栏接公共历史；账号支持用户不显示入口；个人、部门、基础包、模板、批量、导入和复制沿用同一历史列表/详情 |

公共 UI：`RecordHistoryArea` 配置模块名称、API、路由、类型/范围筛选和独立列布局；`RecordHistoryPage`、`RecordRevisionPage`、`RecordRevisionBody` 和 `RecordHistoryAction` 为唯一实现。基础资料旧构造入口保留，便于既有路由、业务来源盘点及外部调用兼容，没有保留第二套页面实现。表格继续复用现有 `MasterDataTableView` 与公共表格组件。

资料库跨域读取通过 `application/port/CompanyFileHistoryAccessPort` 复用拥有权限事实的资料库服务，不在历史查询维护另一套 ACL。

服务端公共 DTO：`common/history/RecordHistory`，基础资料和新历史返回完全一致的列表/前后值结构。新增 `ScopedRecordHistoryService` 负责公司资料与权限历史的授权投影，不把原始数据库快照直接发给客户端。

## UI 与业务流程

沿用主题基色 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、次级文字 `#475569` 和强调色 `#0D9488`；深色模式使用既有主题。字体沿用 NotoSansSC，字号、圆角和间距继续由 Uten token 管理，不另设视觉体系。

```text
公司资料库顶栏 / 文件或文件夹右键       权限设置顶栏
                  ↓                         ↓
             同一历史列表：名称、时间、类型、操作、人员、范围、摘要
                  ↓ 双击（沿用原表格交互）
             同一详情：修改前 → 修改后，支持字段搜索
                  ↓ 返回
             原页面与未提交草稿继续保留
```

三个模块独立保存列布局和筛选上下文。新模块不展示无意义的编号、基础资料分类和基础资料恢复按钮。窄屏/大字体将前后值改为上下对照，保留完整文本；列表继续使用现有水平滚动表格。加载、错误恢复、日期门、清除筛选及身份/权限变化后的清空均走公共实现。

基础资料恢复仍走原有业务校验。资料库还原继续通过回收站；权限调整继续通过当前授权流程及原有版本/再认证规则。历史详情明确说明用途，不新增绕过校验的旧权限重放操作。

## 权威权限及持久化

新接口为 `/api/company-files/record-history`、`/api/company-files/record-history/{id}` 和 `/api/admin/permission-history`、`/api/admin/permission-history/{id}`。详情使用面积/模块和记录 ID 双重限定，不能借另一模块历史 ID 绕过授权。

公司历史读取复用 `CompanyFileService.Scope` 的当前祖先链、继承切断、用户/部门/所有人规则、显式拒绝、上传中对象归属及会话密码状态。无权查看对象或祖先目录时，对应创建、修改、删除及文件夹记录均不可见；已知历史 ID 同样不能直读。移动历史还核对当时记录的旧/新父目录当前可见性，避免通过旧目录名称泄露信息。删除对象按现有回收站权限读取，物理缺失对象拒绝读取，不用历史名称重新构造访问能力。

ACL、权限继承和密码变更历史额外要求该对象当前 `manage_permissions` 能力；普通可见记录也逐字段剔除这些访问设置。超级管理员沿用资料库既有管理规则。过滤在服务端分页及摘要/关键字匹配之前执行；隐藏记录不占可见页容量，不返回隐藏总数，只有确实存在下一条可见记录才返回下一页游标。读取全过程持有与树写入配对的共享事务锁。

权限设置历史要求当前主体同时为超级管理员并持有 `authorization:manage`；账号支持、普通授权码和单独超管标记均不足以读取。控制器和服务分别验证，客户端失权后立即清除列表/详情，晚到响应不可重新填入旧数据。

`V988` 复用永久、只追加的 `master_record_versions`。公司节点/ACL由事务内数据库触发器捕获；密码仅记录保护状态及设置次数，不保存哈希、密码、存储地址或请求指纹。权限历史从已有事务内的 `PermissionChangeAudit` 语义事件保留新增/移除条目及白名单上下文，涵盖批量授权、模板关联/解绑、数据范围、导入、复制等差异；区分加授、禁止、重新确认、员工范围 UUID、模板 UUID 和导入对象，不把所有列表都当作权限码。

已存在公司资料在启用时登记明确的“历史启用时的资料快照”，不伪造以前的创建时间或修改前值；此前未保留的公司变更无法补造。已有在线/冷归档授权语义事件按原时间保留；事件未提供的前值明确为“未记录”，不推断成空配置。业务回滚时新历史同事务回滚，已有永久保留和不可改删规则不变。

## 本轮追加：货品字段权限与物料反查

用户追加要求：没有价格查看权限的人不能看到对应价格修改；确认从物料反查修改货品是否进入同一历史。

`MasterRecordHistoryService` 的字段遮罩原来只隐藏前后值，列表仍可能展示一条没有可读差异的价格变更。现将同一组 `HiddenKeyRule` 同时用于 Java 差异投影和 SQL 分页前的可见性判断；按同事务/同对象/同来源行合并最初修改前与最终修改后，再判定是否有任何可读变更。纯价格、成本、折扣、受保护扩展字段或不可见计算字段的历史不会向缺少对应查看权限的普通读者列出；混合修改只显示可读字段和可读记录数。没有价格查看权限时，价格编辑权限不替代历史查看权。已知历史ID直读和恢复也走同一可读性限制，混合版本需要恢复不可读字段时只给通用阻止说明，不泄露被隐藏的字段名称。超级管理员保留既有完整审阅能力，含无公开差异的内部证据。

列表在一条查询内按字段可见性过滤后才分页；不在返回50行后丢弃隐藏记录，不引入逐条详情查询。新资料库/权限历史不使用未校验的历史页缓存；翻页、从详情返回时重新读取当前权限，并清除加载中的旧记录。原基础资料的身份/权限/读范围变化仍由公共B0代次清空处理。

物料反查的产成品编辑导航位于 `lib/features/production/pages/where_used_report_page.dart::_openProductDetail`，使用 `RoutePath.basicinfoGoodsDetail(id, tab: 'bom')` 进入共用 `GoodsDetailPage/GoodsDetailBody`。主档保存通过 `goods_repository.dart::update` 调用原 `PUT /master/goods/{id}`，后端 `GoodsController/GoodsService.update` 写入同一 `goods`；组装维护写入同一 `goods_bom_items`。V898/V899 的 always-on 数据库触发器对这些实际变更记录永久历史，不依赖从哪个UI进入。成功保存且实际发生变更时归入对应货品的同一份历史；无变更保存、只读查看、失败或回滚不伪造修改记录。该结论依据真实路由/仓储/控制器/数据库触发器链路和实际数据库捕获回归，不宣称已对公司服务器执行过编辑。

物料反查页面及详情现有交互回归56项通过；3项需要显式截图模式的既有视觉用例未启用，单列保留。W7-BIZ-116仍todo/未迁移；候选端以后须沿用同一实际变更捕获和字段历史权限，不把Flutter结果当作Win7验收。

最终构建核对发现旧增量产物曾遗漏新增审计测试及资料库端口接口；已对本轮Java/SQL强制刷新并重新编译，实际类文件核对包含新接口、新审计测试与最新字段投影方法后再整轮复跑。早期失败与缓存混合结果不作为最终通过证据。字段过滤的列表摘要、修改范围和操作也按最新可读来源生成，不能用同次隐藏变更的来源标记替代可见修改；组装成本仍以成本查看权控制，保留销售价格与组件成本的业务差异。
