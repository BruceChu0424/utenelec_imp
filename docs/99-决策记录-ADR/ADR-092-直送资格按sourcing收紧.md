# ADR-092 直送资格按 sourcing 收紧：采购/委外子件不算直送候选

- 日期：2026-09-18
- 状态：已决策（用户报障当日收口）。
- 迁移：[V605](../数据迁移/194-V605直送资格收紧只认自制子件.md)。零新增权限码、零新增表。
- 取代范围：不取代任何 ADR；收紧 [ADR-089](ADR-089-车间直送v2持续生产与线边仓自动配置.md)
  的资格判定函数 `fn_demand_direct_supply_eligible` 一处口径，[ADR-091](ADR-091-开工路线确认与到货进展通知.md)
  的路线门与 V604 的自动识别机制原样保留。
- 相关：[我的车间任务页](../03-页面/我的车间任务页.md)

---

## 一、问题

用户报障(2026-09-18)：

1. 「有些任务是一部分直送料、一些是需要去领料的；你不能把需要领料的也弄成直接直送。」
2. 「采购什么的，需要去仓库取货的。」
3. 「现在领料都领不了、开工都开不了。」

复核既有实现的真实缺口：

- `fn_demand_direct_supply_eligible` 第一条判支只看「同车间是否有在做同货品的其它工单」，
  不看这条需求本身的 sourcing（`supply_route` = BUY/SUBCONTRACT/MAKE）。车间里同货品
  「又有自制工单、又另单采购」是常态，采购子件因此被算成「可直送」。
- V604 起路线在创建事务内自动识别：存在可直送子件且 WAITING → CONTINUOUS。带采购子件
  的工单被自动打成持续生产。
- 持续生产在「部分开工」之前，领料/开工/分批/核对全被路线门抑制（V599）；部分开工又要求
  **每一条**可直送子件都已经在线边仓到了一部分（V595 / 2026-09-17 口径）。采购子件的货
  走主仓入库，线边仓永远等不来——工单两头堵死，即用户报的「领料领不了、开工开不了」。

## 二、决策

1. 直送候选资格按需求自身的 sourcing 判定：第一条判支（同车间在做同货品）额外要求
   `demand.supply_route = 'MAKE'`；采购（BUY）/委外（SUBCONTRACT）子件永远走仓库领料。
   这就是 ADR-089 §背景第 1 条用户原话「有子件在仓库(其他车间、采购、委外)才需要领料」
   的编码化。
2. 第二条判支（已有货品比对过的直送行指名指向它）是既成事实，不受 sourcing 影响，
   原样保留。
3. 存量修正随迁移一次完成：自动识别打上（无 `ROUTE_CONFIRMED` 事件）且仍在 WAITING、
   未动过的 CONTINUOUS 段按收紧后的尺子重算；人工确认过或已动过的一概不动，纠偏走既有
   「重新确认生产路线」入口（V599 冻结尺不变）。

## 三、影响

- 纯采购/委外子件的 WAITING 工单不再自动落 CONTINUOUS，落 FULL_KIT，领料-开工通道
  随恢复；混合链（MAKE 直送子件 + 采购/委外子件）仍按 ADR-089 序列：直送子件到一部分 →
  部分开工 → 仓库料领料 → 开工。
- 影响面全部经 `fn_demand_direct_supply_eligible` 单点收敛：V604 创建事务识别、
  confirm-route 校验、部分开工的 `direct_supply` 冻结、`fn_can_start_continuous_supply`
  到料前提、车间任务页下拉收窄。
- 不改任何表结构、权限面与三条开工链的内部规则。

## 四、已知边界

- 自动识别前已被人工确认成 CONTINUOUS 的偏差单不会被迁移改动；车间在 WAITING 且未动过
  时仍可自行「重新确认生产路线」纠偏。
