# 财务业务审核中心

当前入口 `/finance/audits` 复用各链专用列表和审核详情，按查看权限显示大类；每个状态由对应业务事实决定。

| 大类 | 可达状态 | 历史与反向入口 |
| --- | --- | --- |
| 销售订单确认 | 待确认、已批准、已驳回；待确认表头区分首次与修改复核 | 已批准仍进入财审详情；持原订单 view + reverse 权限时显示共用反审预检与确认 |
| 出货审核 | 待审核、已退回、已审核、全部 | 既有已审核详情及独立出货财审反审能力 |
| 订货审批 | 待审批、已批准、已驳回、全部记录；采购/委外来源并入状态文字和状态表头筛选 | 按审批 case 留存各轮快照，历史不带批准/驳回动作；持原订货 view + reverse 时从详情反审 |
| 超量到货审批 | 以到货异常自己的办理状态和审核记录为准 | 已处理入口不另造绕开收货/退回守恒的通用撤销 |
| IQC 退回贷项 | 待退回、已退回待财务、财务异常、终态、全部 | 复用原贷项确认、零金额结案及反向能力 |

订单修改是原销售订单的复核状态，首次与修改合在「待确认」主队列；状态表头可分别查询。旧 `salesChanges` 分段及 `/finance/sales-order-changes` 深链进入待确认并保留修改筛选。首次与修改数量互斥，待确认显示两者合计；审核中心与工作台累计只使用服务端审核待办事实一次，已批准和历史计数不加入待办。

订货审批不再单列「全部待审／采购订货／委外订货」子分类，状态列显示「采购待审批／委外待审批」，用绿与青绿区别正常待办；修改及重提用橙，驳回用红，撤回及被替代用灰。IQC 退回贷项也由来源表头承接采购/委外，不重复提供来源和任务状态下拉。各页保留真实办理阶段；具体去留见[列表分类与状态呈现](列表分类与状态呈现.md)。

采购/委外历史经 `/api/finance/procurement-approvals/history?status=APPROVED|REJECTED|ALL` 读取；原 `/tasks`、`/count` 缺省仍为 PENDING，保持提醒与旧客户端兼容。列表、分页总数、单号 facets、类型计数使用同一状态。历史的汇率与本币金额优先读 case 上财务实际决定值。

反审复用 `DocumentUnapprovalAction` 与 `/documents/{family}/{id}/unapprove`。预检核对当前原单权限、对象范围、下游、事实快照，确认前重验；采购/委外只有最新有效已批准轮次可返回 `UNAPPROVE` 能力，旧轮次仅看历史，确认前后再核对 case 及版本。交易保留原审核代次、数量/库存/金额/来源并生成唯一后续草稿。历史财审查看权不扩大原单反审权；存在下游时显示实际阻止原因。审批 case 保持审核历史，不伪改为待审或抹去已批准事实。

销售详情的返回地址保留原筛选，旧首次/修改通知可继续进入；已批准列表不提供批量确认，采购/委外历史列表不提供批量通过或驳回。切状态、身份、服务器或权限时失效旧列表、筛选桶与选择，迟到响应不能恢复旧数据。

四条财审任务的填写保护复用本机 `FormDraftMixin`，不新增草稿分类：

| 任务 | 本机保留的输入 | 原任务与版本绑定 |
| --- | --- | --- |
| 销售订单确认 | 单价、折扣原始文本，确认备注、驳回原因 | 订单 UUID、financeReviewRevision、明细 UUID 集合 |
| 采购/委外订货审批 | 单价/总金额、汇率原始文本，审批备注、驳回原因 | case UUID、订单 UUID、attempt、version、明细 UUID 集合 |
| 报价核价 | 数量、单价、成交价、折扣原始文本，定价/删除/刷新选择，有效期、结算方式、备注、退回原因 | 报价 UUID、reviewRevision、明细 UUID 与所见主档价格 |
| 出货财审 | 记账汇率原始文本、退回原因 | 出货 UUID、reviewRevision、不可变商业内容 hash、明细 UUID 集合 |

输入即保存，原待处理行显示「草稿」并从同一行继续填写；筛选仍按服务端业务状态，任务不会因此移出待确认/待审批/待核价/待审核。草稿不进入独立钱流草稿分类，也不另外叠加待办数；带未完成财审输入的原行不参加批量审批，须先进入详情核对。

恢复前必须重新 GET 当前审核事实；再次办理审批、确认或保存修改时必须重新认领。认领令牌不持久化、不作为本机授权。对象、版本、明细或报价主档依据变化时保留旧输入并阻止重套；可以在保留旧快照后仅加载新事实。初始 GET、刷新和输入恢复都不会调用审批/确认接口。

本机财审任务记录以对应财审 `view` 权限读取本人价格/备注输入，与现有财审 GET 的值范围一致；动作权限被撤掉但查看权仍在时，也能仅 GET 核对原回执。保存业务修改、批准、确认或驳回仍要求当前动作权限、本人有效认领和服务端能力，不因读恢复获得写权限。此策略不泛化到会在普通查看接口打码的身份证等人事原文。

决定发出前先持久化原版本与命令意图；存盘完成后再检查同一对象、版本、当前动作权限及有效认领。丢失回执时显示「提交待核对」，禁止重复提交，审核中心和独立队列仍提供「核对原提交」，即使原待办已办结离队也可进入。阳性核对按实际协议：销售订单为同订单/财审版本的确认或驳回事实；订货为同不可变 case/订单/attempt 的 CAS 版本和对应审批历史；报价为同报价的精确 CONFIRM/RETURN 修订记录；出货为同 reviewRevision/商业 hash 的财审事实。还须匹配原命令的确认备注、驳回原因或记账汇率等实际决定值，不能只凭「已审」清理断点。商业 hash 不包含记账汇率或仓库后续进度。无法证明原保存/修订结果的场景继续保留原输入，仅展示 GET 事实，不猜测完成、不自动重放。
