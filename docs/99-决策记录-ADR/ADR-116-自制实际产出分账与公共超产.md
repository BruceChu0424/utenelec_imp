# ADR-116：自制实际产出分账与公共超产

- 日期：2026-09-24。
- 状态：已确认业务规则，正在实现和验收；不是公司服务器已安装证明。
- 适用：所有车间的自制工单，不以注塑、五金、装配分别写规则。
- 最新确认：任务显示“允许超产比例”，默认 10%；有权限的车间人员可提交调整，计划部审批通过才生效。超出有效比例时，整笔超出原计划的本次产量转入预填追加生产计划。早期讨论的“不设上限”已被本规则替代。
- 用户指定例：计划 100、比例 10%、实际 130，原工单报 100、追加计划 30；不是原工单 110、追加 20。
- 新任务默认已确定为持续生产，可按既有安全规则更改；默认路线不等于自动领料或开工。
- 编号：V693 / ADR-115 由仓库负责人任务使用；本次从 V694 开始，V695 为库存成本，V696 为任务与进度投影，V697 为仓库实点证据，V698 为比例申请审批，V699 为默认持续生产，V700–V701 为实际追加计划与材料／成本来源证明，V702 为普通任务及实际追加任务共用的材料增量审批。旧迁移字节不改。

## 1. 先区分五种数量

| 数量 | 谁确认 | 代表什么 |
|---|---|---|
| 计划数量 | 计划部批准 | 原生产承诺，不能为了容纳超产事后改大 |
| 实际完工申报量 | 车间填报、主管审核 | 本次实际产出，允许大于计划；不等于合格库存 |
| 实际用料 | 车间按合法领料、直送来源登记 | 真实耗用；理论 BOM 只提供建议，不能覆盖人工实填 |
| 合格放行量 | 品质，或现有受控直送自检链 | 本批可交接范围；不等于仓库已经实收 |
| 实际接收量 | 仓库或下工序接收方 | 真正库存／领用事实，不能自动复制计划或申报数量 |

所有页面必须说明自己显示哪一种量。“报工 1200”不能被写成“入库 1200”；“品质合格 1200”也不等于实收 1200。

## 2. 一个实际批次，服务端分账

### 2.1 有效比例、审批与追加计划

比例紧跟车间任务产品数量显示。提交 15% 申请后仍显示“有效 10%／申请 15% 待审”，计划部通过才生效。申请和审批分别保留版本、幂等键、操作人和不可变快照。审批页复用销售改后送财务审核的差异表：旧行红色删除线、新行绿色。退回不改有效比例，重提保留前次记录。

限额按本执行段的独立实际超产量核算，不能挪用同工单另一订单尚未完成的份额。已批准的计划公共备货属于原计划量；品质恢复不重复扩张原生超产额度。

- 计划 100、比例 10%、实产 108：原工单报 108，其中需求 100、容差内公共 8。
- 计划 100、比例 10%、实产 130：追加计划预填 30，原工单承接 100；追加计划经计划部审批后承接公共 30。
- 已合法报收 105，后来又实际生产 25：历史 105 不搬迁，只把本次尚未登记的 25 追加，不能再报 30 并重复计算历史 5。

追加计划的货品、颜色、单位、车间、负责人和冻结来源由服务端带入。两张计划的本次产出之和等于原实际输入；追加 30 已是新计划内公共量，不能又算成该计划的“计划外超产”扩大成本分母。

原材料及成本沿不可变追加来源证明共用，不能伪装为只允许同计划的拆批，不重复生成 DRAW、实发、耗料或库存。批准后通过真实来源校验和显式开工再续报，不直接伪造 READY 或消耗。固定实产追加任务不再调超产比例或裸报，原批次证明与唯一申报关联保持一致。

### 2.2 实际额外用料

超产批准和材料领用是两个事实。实际产出 130、原领料 100、实际耗料也是 100 时，共用一次真实耗用；实际耗料为 130 时，车间对同一原冻结材料申请新增 30，计划部核对原定额、已批增量和本次增量后批准。普通任务即使产出仍在容差内，也使用同一入口处理额外实耗。

批准形成独立、精确冻结的增量需求，原材料定额 100 和原产成品计划量都不改。新增 30 要经过实际备料、仓库实发和耗用，不能把“批准 30”当作“已领 30”。实际手填耗料不因追加计划、刷新来源或路由切换被自动改小。新材料或替代料不能借此改变原冻结物料身份。

计划内分批报工允许前批已登记真实耗用、后批新增耗用为 0；必须能证明同一任务的真实在制投入，且后批仍在原批准产量范围。实际超产或新追加批次不能仅凭任意旧领料记录和零耗用增加库存。

### 2.2 容差内的实际产出分账

员工只输入一次本次实际产量。服务端锁定执行任务、原需求和本次来源，形成同一批次下的分账明细：

1. **需求产出**：原销售／内部需求份，保留精确订单、分摊和工单身份，不超过原责任数量。
2. **计划公共备货**：原来已批准多做的备货份，仍受其独立额度约束。
3. **实际超产**：超出原计划范围的真实产出，明确为公共份，强制送仓。

日报行保存 `output_batch_id`、`output_batch_qty`、`is_public_output`、`is_actual_surplus`。同批各行数量之和等于员工输入的实际总量。服务端派生公共身份，不能信任客户端勾选一个“公共”就绕过订单或用料约束。

原有一条明细一个去向、一个品质来源的结构继续使用。拆成多行的是归属／交接事实，不是让员工重复录产量。编辑草稿按批次恢复原输入；审核后按分账展示真实去向。

同货品的不同工单、不同订单不能因名称相同被合并归属。销售订单关闭不会把其原分摊“释放”为公共额度。内部自制没有销售 UUID 也不代表它天然是公共库存。

草稿占用与实际完成分开：其他草稿占用了需求份时，应提示关联草稿及冲突，不能把这次输入静默转成公共超产。删除草稿释放占用，审核、重试及反向必须防重。

## 3. 直送与送仓

例如：本工单需求尚余 1000、有效比例 10%，本次实做 1100，下一工序真实未覆盖需求为 800：

| 分流 | 数量 | 后续 |
|---|---:|---|
| 交下一工序 | 800 | 原需求身份，走现有直送自检和精确领用链 |
| 送仓满足原需求 | 200 | 原需求身份，品质合格后按实收形成需求供给 |
| 送仓公共超产 | 100 | 公共身份，品质合格且实收后才可由其他计划使用 |

不能把未直送的所有数量都归公共。公共的判定依据是产出归属；暂时放在哪里是另一件事。

直送上限同时受“原来源供给责任”和“接收工单当前未覆盖需求”约束。已领料、已有直送及同计划拆段占用都要扣除。超产不得顺带进入下一工序，也不得自动扩大下一工序的生产计划。

所有车间适用同一规则，不等于取消交接边界：现有同车间、同货品颜色、真实父子责任的直送规则继续有效；跨车间沿正常仓库交接链办理。

提交时显示分流预览。保存／审核发现真实需求或目标状态已变化，应保留输入并说明具体变化；不能静默更换订单、数量或去向。

## 4. 品质与不按申报数入库

公共份和需求份都要保留日报来源。仓库登记成品仓、库位，品质可分次判定合格、不合格，尚未检验的继续待检。合格放行后按实际点收数量入库。

- 报 1200、合格 1180、实收 1150：库存只增加 1150；20 留在明确的不合格处置链，30 是已合格待交接量，不能消失。
- 同一合格批次先收 100 后收 80：使用同源余量，不能重新生成一份 180 的放行额度。
- 实物多于已报／已放行量：先核对并补报、送检，多出部分不能直接作为公共库存或盘盈入账。
- 实收为 0：区分暂未到货与明确拒收，不让一个数字隐式替代业务决定。
- 合格、失败、待检按同一来源守恒；实收、未收、退回也按同一来源守恒。

原“先入库后质检”入口改为“清点上架后送检”：逐行填写实际点数，输入不预填申报量，后台锁定来源后精确核对并持久化 `counted_qty`。只有点数与本批来源相符才能承诺品质合格后自动点收。数量不一致时使用“登记并送检”，品质放行后按实物人工点收；差异数不能在送检时就被当作已入账。历史未知点数保留 NULL，无证据的旧待检自动批次也转人工点收，已完成历史不改。

需求份发生不良时，不自动把已归公共的货改为需求份。需要补缺时，应通过真实公共库存的正常预留／领用追加分配，保留原公共产出历史，并防止与品质补产责任重复满足同一缺口。

## 5. 页面展示

### 车间任务

同一任务展示“计划量、累计实际报工、其中实际超产、计划合格实收、公共超产实收”。计划实收完成率最多 100%，只由属于原计划范围的实收推进；公共超产先入仓不得把尚未交付的原需求显示为完成。

已开工且仍开放的任务，即使报满计划，保留单任务实际报工入口；没有可自动建议数量时不做批量自动预填。停止、取消、未开工、无合法物料归属不因超产功能而放行。

### 新建与编辑日报

每行固定显示货品名称／编号／颜色、来源工单、本次实际完工量。选择接收工单后在本行展开“交下工序、送仓需求份、送仓公共份”，数量右对齐。用料保持原来源，手工修改后不得随产量变化被覆盖。

公共超产用文字标记。已有计划公共与临时超产在摘要中可合并显示公共总量，但详情仍区分来源，避免账目含义丢失。

### 审核与仓库

审核摘要同时给实际总量、需求份、公共份及去向。仓库列表按来源和归属展示待检、已合格可收、本次实收、未收。员工不需要看 UUID、数据库计数字段或技术线边仓实现。

### 错误与重试

真实冲突显示受影响工单及变化，输入保留；网络超时先读取原操作结果，已成功不重复执行。所有保存、审核、交接、质检和入库操作保留现有动作权限与对象范围。

## 6. 异常处理矩阵

| 情况 | 统一处理 |
|---|---|
| 少做、分多次报工 | 每次记录新增实际量；原工单余量继续，历史不改 |
| 超产在有效比例内 | 原任务记录真实产量，超产份经质检、实收成为公共库存 |
| 超过有效比例 | 整笔本次超出原计划量转预填追加计划，审批后按同一实际批次来源续报 |
| 调整比例待审／退回 | 原有效比例继续执行；红色删除线旧行、绿色新行供计划部复核，退回不改变事实 |
| 实际用料超出原定额 | 对原材料提交增量申请，审批后只新增真实所需供给，再由仓库实发；原定额不改 |
| 补料申请待审／退回 | 原有领用额度继续执行；不能用未批准数量结耗或登记虚假实发 |
| 草稿占额 | 显示关联草稿，防止重复申报；不计完成，不自动把冲突量改公共 |
| 同时保存／审核 | 锁定同一任务及精确来源，重新核对；真实冲突返回可解释结果 |
| 一张日报多计划同品 | 每条保留计划、执行段及销售分摊，不能按品名归并 |
| 下工序已有其他供给 | 只交当前真实缺口；剩余按原归属送仓 |
| 下工序停止或取消 | 未交接部分停止发送；已领用按下游反向链处理 |
| 部分合格、返工、报废 | 原批次质量处置；恢复报工保留归属，避免重复计普通产量和耗料 |
| 仓库少收 | 只记实收，余量可继续点收或明确退回；不能按报工数补齐 |
| 仓库多收 | 核对来源并补报送检，不能绕过品质直接增加库存 |
| 订单关闭但工单公共份未完 | 关闭订单不阻断独立公共份，也不改变原销售额度 |
| 工单已正式结束后发现漏报 | 需要可证明原批次的更正／补登记路径；不能静默重开订单或伪造新领料 |
| 公共货已经被别单领用 | 不能直接红冲原产出；先列出下游单据，按依赖顺序反向 |
| 下工序已耗用 | 同样按真实投入和成本依赖反向，不能抹掉来源 |
| 成本已经结算又出现有效超产 | 成本目标与分摊追加修订，真实总投入金额守恒，不只改数量分母 |
| 非整数单位、换算率不为 1 | 使用原单位快照与基础量精确换算；现有四位基础量精度不能精确承载时明确拒绝，不静默四舍五入改变库存 |

## 7. 权威实现与根因修复

`DailyReportOutputAllocationService` 统一承担实际批次分账。写入守卫检查分账后的事实，来源查询提供超产能力与建议量。后端、数据库及客户端不能各自计算一套互相矛盾的公共额度。

库存沿 `source_daily_report_item_id` 读取稳定公共身份；销售预留、物料分析专属绑定、MAKE 就绪以及委外前置供给必须共同遵守。混合单据按行判断，不能整单跳过需求供给。

原计划量不变。数据库只允许有确切已审超产事实支持的实际超计划累计；品质放行与最终点收仍是必经约束。库存成本目标包含实际超产，普通超产审批和红冲都触发成本修订。

第二张截图的审核失败来自 `lockPlanLinkGraph` 将 Java UUID 自然排序与 PostgreSQL UUID 排序结果直接比较。Java 使用有符号 long 顺序，PostgreSQL 使用字节顺序。修复按 ID 集合核对关联是否变化，按数据库锁定顺序刷新实体，继续检查真实增删、数量、删除态与销售来源。不能删除并发保护，也不能让员工反复刷新绕过。

## 8. 验收与发布边界

必须用真实 PostgreSQL 验证前向迁移、批次分账、草稿占用、混合来源、公共先入、部分品质／少收、重复与并发、成本修订、完整反向及下游占用阻断。前端验证实际数量超过建议量、手工实耗保留、拆分展示、不同入口和权限。

公司现场目前只读取证，未更改业务数据、执行迁移或重启服务。开发验证、远端 CI、服务器安装和岗位验收分别记录；不能互相替代。上线需按既有发布流程验证 V693 之后的前向迁移，保留备份和原制品，不能用旧库快照覆盖测试人员新记录。
