## 一、设计原则

| 原则 | 说明 |
|---|---|
| 纵深防御 | 前端校验只是体验，**后端才是真相**；前端永不信任输入 |
| 最小权限 | 默认拒绝，按需授予；导出/配置等敏感操作用**独立权限点** |
| 前端不可信 | 前端隐藏只是体验，绕过前端直调 API 必被后端拒 |
| 配置外置 | 密钥/URL 走 `.env` / 环境变量；运行时策略阈值走系统设置页 |
| 审计可追溯 | 关键操作（登录/改密/导出/配置变更/数据变更）全过审计 |
| OWASP 对齐 | 对 OWASP Top 10 每条有明确应对（§七） |

## 三、前端安全落地项

### 3.1 路由守卫 + 权限显隐

未登录跳登录页；受保护页按 `permission_by_path` 集中策略守卫：`requiredAnyPermFor` 至少命中
一个，`requiredAllPermsFor` 必须全部命中。入职路由同时要求 `employee:create` 与
`employee:pii:edit`。
菜单/卡片按权限点 `hide`（**不是 disable**——disable 反而暴露攻击面，吸引探测）。

### 3.2 输入校验（前端体验 + 后端权威）

所有表单 `UtenInput` 带 validator（必填/长度/格式/范围）。**前端校验只是体验，后端必须独立再校验**——攻击者绕过前端直打 API。

批量/嵌套请求必须复用后端 `RequestLimits`，不能只校验单个字段：事务单据/批量业务行当前上限
500，货品 lookup 1–200，数据范围 owner ≤1000，通知批删 ≤500/附件 ≤20，权限码 ≤500，
资料变更和员工嵌套集合 ≤100。动态 JSON 接口还须在 Controller 与 Service 双层检查数组形状、
对象类型、UUID、正数和日期；新增集合不得无上限接收。

所有 JSON Controller 请求体还受统一字节上限保护，默认 1 MiB，并按实际流读取，所以无
`Content-Length` 的 chunked 请求也不能绕过；超限返回稳定 413，畸形 JSON/类型返回稳定 400。
multipart/二进制上传不复用 JSON 缓冲策略，必须在各自端点配置流式上限、类型白名单和存储配额。
Nginx 2 MiB 是更外层门禁，不能替代应用层 1 MiB JSON 边界。

### 3.3 敏感数据存储分级

| 数据 | 存储 |
|---|---|
| 偏好（主题/语言/字号） | `shared_preferences` |
| **token / refresh / 密码** | **`flutter_secure_storage`**（iOS Keychain / Android Keystore） |

🚫 **禁止 token 存 `shared_preferences`**——Android 是明文 XML，可被备份/逆向。

### 3.4 配置外置

API base URL 是会暴露在客户端产物和网络请求中的公开部署配置，不是秘密。员工端与访客端必须
复用 `api_base_url.dart`：开发空值回退本地后端，Web Release 空值使用同源 `/api`，非 Web
Release 空值或 HTTP/回环/畸形地址必须 fail-fast。生产移动/桌面包用
`--dart-define=API_BASE_URL=https://...` 注入；`dart-define` **不能保存任何密钥**。

后端密钥、第三方 AK 和数据库凭据禁止硬编码，也禁止放入会随客户端发布的 `.env` 或
`dart-define`；开发使用不进 Git 的 `server/.env`，生产由服务器环境变量或 Vault/KMS 注入。
运行时策略阈值（限流/锁定/令牌 TTL/导出上限/会话空闲超时等）走**系统设置页**（见 §五）。
服务端未设置 `UTEN_PROFILE` 时默认按 `prod` fail-closed；本地开发必须显式设
`UTEN_PROFILE=dev`。base/prod 默认关闭 Swagger，只有 dev profile 默认开放。生产必须显式
提供环境唯一的 `UTEN_JWT_ISSUER`，不能依赖开发默认值。

### 3.5 密码框规范

`UtenInput(isPassword: true, autofillHints: const [AutofillHints.password])`：默认隐藏并提供可见切换；
登录表单使用 `AutofillGroup`，客户端校验只改善体验，密码策略与认证仍由后端强制。

### 3.6 错误处理（不暴露后端细节）

统一 `ApiException` → `context.appError(message)`。🚫 禁止把 status code / stack / SQL 报错直接吐给用户（OWASP 信息泄露）。批量/迁移任务失败只返回稳定错误码和随机 `referenceId`，完整异常只写受控服务端日志，供运维按编号关联。

## 四、后端安全实现（已落地）

| 项 | 实现 |
|---|---|
| 密码 | Argon2id（防 GPU 暴力）；改密禁止复用最近 N 个（`password_history_size` 可配）；入职/重置统一生成 20 位高熵一次性临时密码，禁止身份证后六位等可推测默认密码 |
| 登录 | 错误计数 + 锁定（`lockout_threshold`/`lockout_minutes` 可配）；登录限流采用“账号/规范手机号低阈值 + IP 高阈值”双桶并按员工登录/访客发码/访客登录隔离 namespace，避免园区 NAT/运营商 CGNAT 互相误伤；未知账号与错误密码返回相同错误并执行 dummy Argon2 匹配，dummy hash 在服务启动时预计算，避免首次未知账号请求额外编码形成时序差或初始化竞态 |
| 令牌 | JWT access（源码默认 15 分钟，运行值可由系统设置覆盖、最小 5；V133 仅把未修改的旧默认 480 收敛到 15）+ refresh（7 天可配）；签发与解析都绑定非空 issuer，生产显式配置环境唯一 `UTEN_JWT_ISSUER`，即使密钥误复用也拒绝跨环境 token；V135 staff JWT 携带用户 `auth_version`/共享授权 `epoch`，`JwtAuthFilter` 每请求一次投影复查账号与版本，不匹配立即 401。拒绝分支必须位于 token 解析的宽泛异常捕获之外，且响应序列化失败也不得继续过滤链；visitor JWT 的 `acc/vno` 使用 `visitorNo`、`avs` 只作头像 seed，禁止写入原手机号 |
| 字段加密 | pgcrypto（PII 如身份证/手机）+ HMAC（身份证查重）；密钥走 env/Vault，版本化支持轮换 |
| 审计 | `UserOperationAuditInterceptor` 覆盖认证后的 POST/PUT/PATCH/DELETE 元数据（账号/方法/路径/结果/状态码/耗时/IP/UA，不记 body）；关键表 AFTER 触发器提供 before/after，显式事件走 `AuditService`。通用请求审计不等于所有表都有 before/after，上线前仍须完成审计矩阵 |
| 权限 | 部门权限 + 个人覆盖 + 按权限点脱敏；V141 将员工 PII/薪酬写入从普通 create/edit 拆为独立权限（角色体系已下线，ADR-011） |
| 限流 | 鉴权入口主体低阈值 + IP 高阈值双桶、导出 per-user（Bucket4j，阈值可配）+ 导出进程内并发闸门（源码默认 2；多实例需共享状态/总量验证）；访客短信按手机号 HMAC 派生键取得 PostgreSQL transaction advisory lock 后复查发送间隔与日限，避免同号并发穿透 |
| 启动配置 | 未设置 `UTEN_PROFILE` 时默认 prod 并对生产数据库、issuer、CORS 等配置 fail-closed；本地必须显式 dev；base/prod 关闭 Swagger、INFO 日志，dev 才默认开放 Swagger/DEBUG |
| 引导超管 | 只在空库且 `admin` 不存在时用强一次性密码创建；账号已存在即严格跳过，启动不得重新提升已被人工撤销的 `is_super_admin` |
| prod | 关 swagger；HTTPS（反向代理终结 TLS）；默认环境 `forward-headers-strategy=none`，prod 才使用 `native` 且只信任 `UTEN_TRUSTED_PROXY_REGEX`；应用 8080 必须只允许受信代理访问；Web 入口使用同源 `/api`、HSTS、无 `unsafe-inline` 的 CSP、点击劫持/类型嗅探/权限策略头、请求体上限和入口共享限流；所有 Web Release/CI 构建必须带 `--no-web-resources-cdn`，Web 打印走同源 Blob，不得为第三方 CanvasKit/PDF.js CDN 放宽 CSP |

## 五、数据导出与高危配置（强制规范，2026-07-27）

详见 [../05-架构/安全策略.md §十](../05-架构/安全策略.md)。要点（新增导出/配置功能必须照此）：

- **数据导出五防线**：① 独立 `*:export` 权限（不复用 view）② Bucket4j 频率 + 进程内并发闸门 ③ Agile AES-256 加密（密码 body）④ 行数上限 ⑤ 审计。
- 导出密码 body 必须使用统一 `ExportPasswordRequest` 与
  `@Valid @NotBlank @Size(min=6,max=128)`；`EncryptedWorkbookService` 必须重复校验，
  不能只依赖前端提示，也不得提供明文导出降级分支。
- **客户端下载边界**：统一 `saveBytes` 清洗文件名为叶子名，移除路径分隔符/控制字符/平台非法字符；
  IO 端同名文件加序号，不覆盖已有文件。
- **系统设置（高危配置）五防线**：① 授权管理入口只限超管 `authorization:manage` ② `@PreAuthorize` + superAdmin ③ **二次密码确认**（防 token 被盗篡改策略）④ 审计 ⑤ 类型校验；HR 日常账号支持使用 `account:support`，密钥/部署类走 env。
- **隐藏元数据**：列 key 以 `__` 开头（如 `__srcId`）= 隐藏列，execute 过滤不渲染但 row 携带。

## 六、权限模型（现行：部门 + 个人覆盖）

> 2026-07-24 角色体系下线（ADR-011）。现行 = **全员基础（employee 包） ∪ 部门配置（含上级部门） ± 个人覆盖**，超管全量。

- **权限点**：按功能粒度，如 `employee:view` / `payroll:view` / `purchase_report:export`；授权管理使用 `authorization:manage`，账号日常支持使用 `account:support`。
- **部门 → 权限**：部门配置权限集（含继承上级部门）。
- **用户覆盖**：个人级增减（临时授权/回收）；V135 通过用户版本使既有 staff access token 立即失效。
- **共享定义变化**：部门树、部门权限、角色/权限目录等变化提升全局授权 epoch，使既有 staff access token 立即失效。
- **敏感读写分离**：读取按 `employee:pii:view` / `employee:compensation:view`；V141 起证件、
  联系方式和银行字段写入另需 `employee:pii:edit`，薪资、社保、公积金和补贴写入另需
  `employee:compensation:edit`。后端按请求字段校验，不能只靠前端隐藏。
- 前端：`sessionProvider.user.permissions` + `permission_by_path` 显隐；后端：每个 API `@PreAuthorize` 独立校验。

当前权限契约复核：143 个前端 `Perm` 常量全部进入超管 fallback，Java 活动引用的 138 个权限码
前端缺失为 0；路由、导出、敏感表单及业务按钮定向测试 20/20、全量 `flutter analyze` 0 issue。
上线前仍须真实 HTTP 的允许/拒绝矩阵和对象级越权测试。

> 即时失效是 V135 的源码设计，不是生产验收结论。上线前必须在目标 PostgreSQL 应用迁移，并覆盖
> 个人 grant/revoke、用户角色、员工换部门、部门树移动/软删、共享权限、超管和员工绑定变化；
> 同时验证逐请求投影的 P95/P99。

## 八、禁忌

🚫 硬编码密钥/URL/API key 到代码（走 `.env`）。
🚫 token/密码存 `shared_preferences`（必须 secure_storage）。
🚫 用 `disable` 代替 `hide` 表达无权限。
🚫 后端错误细节（stack/code/SQL）直接吐给用户。
🚫 数据导出复用 `:view` 权限（必须独立 `:export`）。
🚫 高危配置改设置无二次密码确认。
🚫 密钥/部署类配置进系统设置页（只放运行时阈值）。
🚫 明文 HTTP（必须 HTTPS）。
🚫 在公网或业务网直接暴露后端 8080，或把任意来源加入 `UTEN_TRUSTED_PROXY_REGEX`。
🚫 前端跳过后端校验允许写操作。
🚫 日志含 token、密码、短信验证码或完整手机号（即使开发期）；开发短信网关只记手机号尾四位，明文验证码只能通过显式 dev 响应短暂返回。
🚫 把手机号、身份证或其它原始 PII 放进 JWT claim；JWT 默认只是签名，不提供载荷机密性。
🚫 把服务端/用户提供的文件名直接拼到下载目录，或静默覆盖同名文件。
🚫 正式运行时依赖未登记的境外 CDN、字体、脚本、遥测、对象存储或地图服务。
🚫 用设备/服务器默认时区决定“今天、当月、账期、单号日期”等中国业务日界线。

## 九、提交前自检清单

- [ ] 受保护页有路由守卫；菜单/按钮按权限 `hide`（非 disable）
- [ ] 列表、详情、更新、删除、审核、红冲和批量入口都做同一对象级/数据范围授权；用已知 UUID 做越权负向测试
- [ ] 表单客户端校验 + 后端独立校验
- [ ] 数组/批量请求有集中上限、嵌套 `@Valid` 和边界+1/错误形状测试
- [ ] 密码框默认隐藏 + 可见切换；token 走 secure_storage
- [ ] 无硬编码密钥/URL；`.env` 不进 git
- [ ] 默认环境不处理 `Forwarded/X-Forwarded-*`；prod 代理白名单最小化，8080 仅代理可达，直连伪造头测试无效
- [ ] 访客短信在真实 PostgreSQL 多连接/多实例下验证同号锁后复查，验证码与完整手机号不进入应用、代理或审计日志
- [ ] 园区 NAT/运营商 CGNAT 下验证同 IP 多主体不互相限流；同主体爆破仍被拦截，多实例限流状态共享
- [ ] Web Release 使用 `--no-web-resources-cdn`，运行时无未批准第三方请求，Web 打印不加载公共 PDF.js
- [ ] 生产数据、备份、日志、监控与供应商处理地域已登记；任何数据出境先完成专项评估
- [ ] 解码 staff/visitor access JWT 检查最小 claim；部署后确认修复前含手机号的访客 access 已过期或清退
- [ ] 错误信息不暴露后端细节
