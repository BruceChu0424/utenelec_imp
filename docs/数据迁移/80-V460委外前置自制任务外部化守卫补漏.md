# 80 - V460 委外前置自制任务外部化守卫补漏

## 一、背景

V458 给 `preplan_supply_actions` 新增外部单据类型 `SUBCONTRACT_MAKE_TASK`
（指向原分析内 `SUBCONTRACT_MAKE` 前置自制任务行），但只重建了自己的
`preplan_supply_action_external_chk`，**漏改了 V250 三道守卫**：

1. `preplan_supply_action_route_external_v250_chk`（route×type 组合 CHECK）
2. `fn_guard_preplan_supply_action_history` 的外部化握手白名单
3. `fn_guard_preplan_supply_allocation_history` 的外部化 CASE

真库上「物料分析 → 有子层委外件 → 采用委外并确定」在
`createSubcontractMakeTask → markCreated`（OPEN→CREATED + 填 external 三字段 +
allocation external_item_id）时被触发器拒绝：

```
ERROR: preplan action externalization handshake is invalid
PL/pgSQL function fn_guard_preplan_supply_action_history() line 36 at RAISE
```

单元测试为 focused stub（不落库），未覆盖触发器路径，因此 V458 全量绿但真库炸。

## 二、变更

- 组合 CHECK 与握手白名单放行 `(route='SUBCONTRACT',
  external_document_type='SUBCONTRACT_MAKE_TASK')`；
- allocation 外部化 CASE 的 SUBCONTRACT 分支扩展：`SUBCONTRACT_MAKE_TASK` 要求
  allocation 指向**同分析内真实 `SUBCONTRACT_MAKE` 行**（与 MAKE 分支对
  `MAKE_COMPONENT` 的要求同构），`SUBCONTRACT_APPLICATION` 原语义不变；
- 其余守卫（身份不可变、append-only、取消/状态回退）语义不变；
- 不加表、不改表结构——**无表计数变化**，reset 仅目录版本对加 `(460, 422)`。

## 三、验证

- `SubcontractMakeBeforeOrderMigrationContractTest` 6/6（含 UTEN_RUN_DB_TESTS=true
  真库 Flyway 全量应用）；
- `ResetBusinessDataScriptContractTest` 5/5（目录对 (460,422) 登记）；
- 服务端全量 mvn 全绿。

## 四、关联

同日配套（同一次收口）：物料分析「有子层委外件」确认后进入与自制完全同构的
两段式候选卡（暂不可安排/可安排 → 勾选 → 下达委外 → 服务端建
SUBCONTRACT_MAKE），见 ADR-062 修订记录与「生产物料分析页」文档。
