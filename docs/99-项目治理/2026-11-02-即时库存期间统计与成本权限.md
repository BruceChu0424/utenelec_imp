# 即时库存期间统计与成本权限

本地分支 `uimp/instant-stock-period-20261102`，基线 `c75d6e1e3`。本轮为功能实现与本机验证，不包含整合发布、公司数据操作、正式客户端打包或部署。

## 用户要求与最终行为

- 删除左侧顶部「全部分类」按钮，保留默认全部范围；再次点当前选中分类清除分类条件。窄屏使用「分类目录」入口。
- 删除「多排数量」展示、打印和导出列；原 API 字段保留兼容既有调用方。
- 库存数量后新增成本价、成本金额、进仓数量、发货数量、结存数量。表格上方「选择日期」复用 `showUtenDateRangePicker`；取消不查询，清除回到未选状态。
- 未选日期时期间列显示「请选择时间范围」。当前库存数量、重量、待检量、合格待入库仍显示实时事实。
- 成本价、成本金额使用既有 `goods:cost:view` 独立权限。无权时表格、表头设置、打印、导出列选择不显示；后端成本值为空，导出列定义及行值均移除，手工/历史成本投影与成本排序均拒绝。普通导出仍独立要求 `stock_report:export`。
- V991 仅关联既有成本权限到即时库存与仓库资料权限面，方便配置；不给任何人员、角色或模板自动授权。

## 设计取舍

按默认 `frontend-design` 工作流保留既有 Uten 视觉和业务结构，不引入另一套组件。使用 `NotoSansSC` 与现有主题字号；底色 `#F5F7FA`、表面 `#FFFFFF`、主文字 `#0F172A`、次文字 `#475569`、交互 `#0F766E`、边线 `#E2E8F0` 均从已有主题解析，圆角和间距沿用 Uten token。

结构为「左分类树｜右查询工具栏、日期按钮、库存表」。货品识别列靠左，当前数量与重量紧邻，随后为期间进出结存、成本、待处理量与原主档属性；数字保留数量单位及本币金额语义。窄屏日期按钮显示「更改日期」，完整日期可长按查看或打开原选择弹窗，避免放大字号时长日期挤出界面。打印/导出继续使用 Uten 的操作菜单。

方案复核后保留一处日期入口，不添加独立日期文本框、统计卡或重复确认弹窗。响应式截图检查包括 390px / 2 倍字号，表格横向滚动沿用公共实现。

## 服务端权威与公共入口

`StockQueryService.InstantInventoryFilter` 增加可选 `dateFrom/dateTo`，必须成对且顺序有效。起止业务日均包含，按 `Asia/Shanghai` 转换为 `[起日零点, 终日次日零点)`。

共享 `StockMovementFlowSql` 为库存表与货品流水提供自然方向和内部调拨判定。进仓/发货按原业务方向汇总，红冲抵减原侧；发货含销售、领料等全部出仓净量，范围内部调拨不重复计算，跨范围调拨计入对应侧。

期末结存数量 = 当前范围余额 − 截止日之后已过账净变动；期末成本金额 = 当前范围库存台账本币金额 − 截止日之后本币净变动；成本价 = 期末成本金额 ÷ 期末结存数量，保留六位小数，零结存不计算单价。历史可查询事实以当前余额锚点及实际已迁移/已过账流水为准，不从货品标准成本估算历史价值。

日期统计在数据库按货品×颜色聚合后分页；分页、筛选、排序、全集统计和导出使用同一查询。即时库存入口使用只读可重复读事务，避免分页计数/汇总读取到不同版本。

`shared/stock_inventory` 是 Flutter 公共入口：行合同、仓储、列定义、日期按钮和日期序列化只有一份。独立即时库存和仓库资料内嵌库存同步迁移日期条件、分页缓存身份、迟到响应保护、打印与导出；切换日期立即清旧期间结果，失败不显示旧期间统计。

## 表头顺序追加调整

用户在本轮后续要求自行判断并落实最合理默认列序。本次按日常仓库查数的阅读顺序调整为：

货品名称、编号、颜色 → 库存数量、库存重量 → 进仓数量、发货数量、结存数量 → 成本价、成本金额 → 待检量、合格待入库 → 库位号、主档归属仓库 → 型号、规格、客户型号、物料系列、所属类型、备注。

数量和重量先展示当前库存事实；期间进出与期末结存连续；成本由结存推导，放在结存之后。成本授权变化不拆散数量流转组，分类和系列已有树/筛选入口，移到主档信息末段减少重复信息占用。

Flutter 共享列定义是两个库存宿主、表头设置和打印的入口。后端默认导出也采用同序，兼容文件额外的重量状态和单位，以及原始导出既有的“物料编码/归属仓库”列名；使用同一 `server/src/test/resources/contracts/instant-inventory-column-order.json` 合同样例验证 Java 与 Dart。日期、金额、权限和库存行排序业务未改变。

个人布局版本升至 2，仅已知旧默认布局自动采用新顺序，隐藏/宽度/附加列/行排序保留；拖动、固定列、部分/扩展布局继续保留。版本 1 中用户特意恢复的老分类优先顺序不重置。WPF 宿主仍未迁移，既有 todo 状态保持。
