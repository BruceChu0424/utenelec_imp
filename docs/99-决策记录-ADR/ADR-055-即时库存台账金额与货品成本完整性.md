# ADR-055 即时库存台账金额与货品成本完整性

- 日期：2026-08-29
- 状态：已采纳（V421 已应用当前开发库并完成恢复克隆/现场对账；目标库与真实岗位 UAT 未执行）
- 影响：货品成本预算、即时库存、库存报表、历史负成本治理

## 背景

即时库存原先沿用老系统 `goods.c_total × qty` 作为“成本金额”。该值是标准成本估算，
并非库存余额台账；当货品主档存在负成本或标准成本未及时维护时，会出现库存数量为正而
页面金额为负，且与 `stock_balances.amount_local` 不一致。当前开发库已出现
`UTZJ1001 qty=10000, c_total=-0.095`，页面显示 -950，但库存余额金额为正的实例。

同时，成本表单、服务和数据库没有统一的非负/精度边界，历史异常可继续传播到 BOM 成本。

## 决策

1. **库存价值只认台账**：即时库存页面、排序、打印和导出继续兼容 API key
   `costAmount`，语义改为当前筛选仓的
   `SUM(stock_balances.amount_local)`。标准成本 `goods.c_total` 不再参与库存金额查询。
2. **权限不变且失败关闭**：只有 `goods:cost:view` 可读取/排序/导出台账金额；无权响应为
   `null + costMasked=true`，服务端拒绝按成本排序，避免顺序侧信道。
3. **三层数值守卫**：
   - Flutter 表单只接受非负、最多 14 位整数/4 位小数；费率限 0%–100%，错误贴近字段并可读屏。
   - Bean Validation 与 `GoodsCostValuePolicy` 覆盖创建、更新、导入和完整实体。
   - V421 对金额、费率添加 `NOT VALID → VALIDATE` CHECK，数据库拒绝旁路写入。
4. **历史异常先留证再修复**：V421 先把异常行原 20 个成本字段、原因、确定性策略和恢复来源
   写入保留表 `audit_log`，再夹紧输入项并按现有成本公式重算派生值。原值从
   `audit_log.before.values` 可追溯；`risk_level/event_category` 由数据库强制分类（V556起由ALWAYS触发器实现），迁移不得伪造或改写历史分类快照。
   动作 `update` 自动归类为 `data_change`，业务严重性保存在审计 JSON。不新增永久修复表，
   也不修改既有迁移字节。
5. **数量与金额不互相伪造**：数量-only 调整不自动合成库存金额；如数量与台账价值不匹配，
   必须走库存价值核对/调整事实，页面不得用标准成本静默填平。

## 后果

- 好处：负标准成本不再制造“负库存”错觉；库存金额与流水/余额一致；新负成本在 UI、服务、
  数据库三层被阻断；历史修复可审计、可前向恢复。
- 代价：与老系统标准成本估算列不再同口径；数量-only 盘点后可能暴露金额差异，需要独立治理，
  不能靠乘法掩盖。
- 兼容：JSON 字段 `costAmount` 与权限码不变；仅显示名改为“库存台账金额”。

## 验证与发布边界

- 必须通过查询/报表权限测试、成本策略测试、迁移静态合同和 PostgreSQL 非空修复/约束测试。
- 当前开发库已从 V420 前向到 V421/V422：迁移前备份已真实恢复，负成本原值有审计、库存数量/金额
  守恒，后端 readiness 为 UP。目标库仍需历史异常清单、财务复核、独立恢复演练和真实岗位 UAT；
  本机完成不能外推为目标部署。
