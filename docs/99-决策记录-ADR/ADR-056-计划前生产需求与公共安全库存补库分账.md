# ADR-056 计划前生产需求与公共安全库存补库分账

- 日期：2026-08-29
- 状态：已采纳（BUY-only 机制已获业务显式授权；V420–V422 已应用当前开发库并启动验证）
- 影响：生产物料分析、采购申请、IQC、exact entitlement、安全库存、数量确认 UX

## 背景

物料分析当前遵守 ADR-043：

`可动用 = max(公共可用 + 本分析 exact 归属 - 安全库存, 0)`

因此 exact 身份不能越过安全库存。若测试库业务/库存归零但保留货品 `min_qty`，分析只按本批
`shortage` 下采购，合格到货即使全部绑定也可能仍处于安全库存以下；已完成动作不再算在途，
页面便再次提示相同生产需求，员工可被诱导重复采购。

把 exact 直接加到安全库存之后会破坏公司缓冲策略；把整笔“需求+安全”都绑定给一张分析又会
把公共安全库存私有化。两者都不可接受。

## 决策

1. **生产需求与安全库存补库分账**：
   - `demandSupplyGap = max(required - max(allocatedAvailable, exactPegged), 0)`，
     已合格 exact 即使暂被安全库存挡住，也不得再次形成需求采购。
   - `safetyGap = max(safetyStock - publicAvailable - openSafetySupply, 0)`，
     只看公共可用量，不把本分析 exact 当作公共缓冲。
2. **物理去重粒度**：公共补库按 `warehouse + goods + color`，统一使用货品基本单位和
   `unit_rate=1`；不能因同货多引用单位重复补库。库存维度锁下扣除全系统有效未结安全补库，
   并发分析只能有一份公共补库切片。
3. **必须提交前显式确认**：分析详情返回 `publicAvailableQty/openSafetySupplyQty/
   safetyReplenishmentGapQty/demandSupplyGapQty`。数量框分别显示可编辑“本批生产需求”和固定
   “公共安全库存补库”，并显示预计总量；请求必须精确回传当时的 `safetyReplenishmentQty`，
   版本或 gap 变化即冲突并要求刷新，服务端禁止静默加量。
4. **V420 仅启用 BUY**：同一采购申请创建两条明细：
   - DEMAND 明细继续进入 `preplan_supply_action_allocations`，IQC PASS 最多按需求切片 exact 绑定；
   - SAFETY 明细只由 action header 的 `safety_external_item_id` 追溯，IQC PASS 全部进入公共库存，
     不生成任何分析 entitlement。
5. **委外/自制失败关闭**：SUBCONTRACT/MAKE 若 `safetyGap>0`，本版本禁止继续通知并解释
   “仅采购路线支持公共安全补库”。委外需独立双明细与收货守恒；自制需公共产出执行量和入库 slice，
   均不得借 BUY 字段或把 extra 再绑定 parent/child 来伪装闭环。
6. **动作可审计且可解释**：`SupplyActionView` 分开返回需求量、安全补库量、合计及创建时
   safety/public/open 快照；旧 action 前向回填安全量 0，既有语义不变。

## 数据库约束

- `preplan_supply_actions` 新增安全补库量、三个快照与 safety item FK；旧
  `requested_qty` 继续只表示需求 exact 量，总量为两者相加。
- 约束保证安全量只能用于 BUY、使用基本单位、需求分摊合计等于需求量、safety item 与 action
  同采购申请/仓货色/单位/数量，外部握手后身份和数量不可改。
- 只读进度投影分别计算需求和安全切片的待检、合格、失败、在途，不能用整行收货量相互抵消。

## 授权与发布边界

创建公共安全库存明细会扩大未来采购义务。业务方已明确授权：仅允许员工在数量框知情确认后的新
BUY 申请创建独立公共补库明细；不自动修改既有申请、订单或库存，SUBCONTRACT/MAKE 不在授权内。

V422 作为已应用 V420 的前向修正：只在 action 创建/首次外部握手读取当前货品基本单位，后续状态使用
冻结单位快照；同时在 allocation 写侧拒绝把 safety item 反向指为 demand 来源。V420 字节保持不变，
禁止 repair。

当前开发库已完成 V420–V422、应用命令、Flutter、非空恢复克隆、并发与 IQC 分批测试，
且后端 liveness/readiness 为 UP。SUBCONTRACT/MAKE 公共补库仍为 NO-GO；公司目标库、
真实实物 UAT、独立恢复和签名发布继续是单独门禁。
