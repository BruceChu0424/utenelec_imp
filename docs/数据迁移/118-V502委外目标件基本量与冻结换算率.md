# V502 委外目标件基本量与冻结换算率

状态：V502当前字节的空库及非空501→502迁移专项已通过；本地候选尚未完成所有改单联合验收。已应用版本脚本保持原字节。

V436新委外路线的计划 `planned_qty/prepared_qty/issued_qty` 都是货品基本量，出仓单位率应为1，`bom_unit_qty` 应冻结“每个订单业务单位对应的目标件基本量”。旧INSERT把两个率对调，可能导致编辑草稿后二次换算出仓，并在回厂时少记供应商处材料消费。V502纠正该量纲，新建与扩量服务使用同一口径。

## 兼容处理

- 自动修复严格限于旧错写形状：非LEGACY路线，plan.unit_rate等于原订单率且不为1，bom_unit_qty=1，计划未实发，关联发料与回厂没有任何非草稿历史；货品基本单位必须明确。只改计划与草稿单位/率，不改数量、金额、库存、实发/消费记录。
- 已执行或无法证明的历史保持原值。`v_subcontract_quantity_basis_issues` 展示计划/订单明细UUID、实际与期望单位率，以及当前有效出仓行的冻结率差异，供按原单据与实物核对。历史合法LEGACY子料路线保持原冻结单耗。
- 新目标件计划INSERT有数据库量纲守卫。继续出仓/回厂遇到历史错换算时明确拒绝，不能继续累计错账；原红冲/退回历史路径不因为INSERT守卫而被强制改写。
- 不新增持久业务表；只新增诊断view和函数/触发器。业务清理目录无需新增CLEAR对象。

## 数量下限与计划调整（服务配套）

批准后改量时，共同收货下限按基本量计算：`max(0, 有效毛收货 − 有效普通退货 − IQC已实退不良量 − O_eff)`，最后向上取四位订单业务单位。`O_eff` 必须逐 `receipt_item_id` 取 `min(该行已入账批准超到量,该行扣实际普通/IQC退回后的净实收)` 后相加。每项以精确来源UUID和各自冻结率取得；OPEN/CLOSED只是预计到货状态，不能用来清零实物。替补收货已经进入毛收货，不能再减替补分配或剩余补货额度。只有累计记录的旧数据保持保守下限，不把缺少明细当零实收。

该超到来源限制是本轮前向补充，旧V440的全单累计容量没有这一精确限制，旧posted累计不重写。两例区别必须保留：正常收货行20与独立纯超到行4，后者实退2后只保留O_eff=2，最低订量20；同一收货行24中含超到4，实退2后净22仍可承载该行O_eff=4，最低订量18。没有更细分片事实时不能猜测“先退超到”或“先退正常”。

委外新路线再取“毛实发目标件基本量 − 精确材料实退基本量”的下限。LEGACY子件先按冻结单耗换算同一父件量，同子件分批累加、不同子件取最大值，禁止直接加总不同子料。未执行草稿和预留不是实发，可同步缩减或释放。毛计划保留实际发出历史：例如实发10、实退2、目标减至8时毛计划仍为10，不能把毛issued修改成8。PREPARED未消费权益退回原前置task，原制造产量不变；已有冻结分析的MAKE_THEN链仍须按正常反向处理后再改其需求。
