# V498 货品数量单位生命周期守卫

迁移文件：`server/src/main/resources/db/migration/V498__goods_quantity_unit_lifecycle_guard.sql`。

## 业务规则

`goods.unit_id` 是库存数量的基本单位 UUID。已有数量记录后改它，会把历史库存、待检量、计划数量重新标成另一种单位，而不是合法换算。本次固定其生命周期，不重算任何历史数量或换算率。

| 货品状态 | 普通编辑基本单位 | 其它资料编辑 |
|---|---|---|
| 无任何数量业务或 BOM 引用 | 可以，继续使用有效单位 UUID | 保持原规则 |
| 有库存、数量单据、生产或 BOM 引用 | 不可改成另一单位，也不可清空 | 可以，原单位按只读值保留 |
| 已有数量历史，但 `unit_id` 为空 | 不可在普通编辑猜选单位或清除 legacy 显示快照 | 可以，不提交单位关系字段 |
| 原引用取消、反向、软删或业务数据清空 | 不自动解锁 | 保持原规则 |
| 初次写数量来源的事务整体回滚 | 不遗留锁定标记 | 无数量使用时仍可改 |

历史空单位只能在独立的受控修复中，根据原单、原始单位关系与换算事实确定 UUID，并审查受影响数量链；本次不提供应用端绕过开关，不猜测回填、不修改已应用迁移、不使用 Flyway repair。

## 数据结构与覆盖范围

- 只新增 `goods.quantity_unit_locked BOOLEAN NOT NULL DEFAULT FALSE`，没有新增业务表。该标记由数据库拥有，JPA 映射 `insertable=false, updatable=false`，请求 DTO 不接受它。
- `fn_goods_quantity_reference_sources()` 明确登记 52 张数量源表、60 个货品 UUID 列。目录覆盖销售报价/订货/发运/退货、采购申请/订货/收退货、委外询价/申请/订货/发料/回厂/退料/损耗、库存流水/余额/预留、生产计划/执行段/报工/品质、预计划供给、物料分析以及计量数量证据。
- BOM 的父件 `goods_id` 和子件 `component_goods_id` 都固定单位；成本展开、替代料与委外父件等数量来源的不同货品列也分别覆盖。
- 历史回填不按余额正数或单据有效状态过滤：零库存、已取消、反向、软删的历史仍固定其数量含义。历史计量汇总只有 `distinct_document_count > 0` 才视为数量使用。
- 图片、备注、库位/车间偏好以及仅配置计量偏好的人工决定不属于数量来源，不会因此锁定未使用货品。
- 后续若增加数量来源表或货品引用列，必须通过新的前向迁移补充此目录与写入触发器，并加入来源覆盖测试；不能修改 V498 已应用字节。

## 并发与性能

1. 在读取基本单位并归一化之前，`GoodsQuantityBasisLocks.lockUnused` 按 UUID 排序，对尚未使用的货品取 `FOR NO KEY UPDATE`，保持到业务事务完成。现有共享销售/BOM验证口、采购行单位规则、仓库手工行、手工物料分析来源和三域主档快照入口复用该保护。
2. 数量来源 INSERT/UPDATE 的 statement transition table 提取本次涉及的全部货品，去重排序，再把首次使用的标记从 false 变为 true。标记与来源在同一事务提交或回滚。
3. 单位归一化先取得锁：单位编辑必须等待；业务来源提交使标记为 true，后续编辑被数据库拒绝。单位编辑先取得锁：归一化先等待，随后读取新提交的单位 UUID，再计算及写入，不能继续用之前读取的旧单位。
4. 已使用货品的基本单位永远固定，新的常规业务不再锁其 goods 行；引用触发器预先排除已锁货品，不执行重复 UPDATE。详情直接读取布尔能力，不逐次扫描历史表。
5. 数据库独立拒绝已锁货品修改 `unit_id`、解锁标记及未解析历史单位的 legacy 快照。服务端仍做提前冲突校验；前端显隐不是安全边界。

迁移时应沿项目既有维护窗口执行写入停顿和备份/回滚准备。回填只增加生命周期元数据，不改数量、unit rate 或来源关系；既有审计机制可能记录这些 goods 元数据更新。

## 页面

货品基本信息的“基本单位”在未使用时保留原选择器；使用后显示原单位和框内说明图标，支持悬停、点击、键盘。已停用或删除单位的已知名称仍用于历史只读展示；缺少可证明单位时提示核对。保存其它资料时不再把只读单位或 legacy 字段重新提交。

- 同一 PG 测试直接调用真实 `PurchaseLineUnitPolicy`，通过 `pg_stat_activity` 验证实际行锁等待；单位编辑先赢时最终源单位为新 UUID、`qty × unitRate` 仍为 24；归一化先赢时编辑返回 SQLSTATE 23514，原单位与数量保持。
- `GoodsQuantityUnitPolicyTest` 覆盖绕过 UI 的服务调用、当前单位不变、历史空 UUID 禁止猜测以及原数据不受失败请求修改。
- `goods_quantity_unit_lifecycle_test.dart` 使用真实表单交互验证原单位/历史单位只读说明、其它字段正常保存且不重新提交单位、未使用货品仍能实际选单位并保存。配套原货品页面/权限测试共 7 项通过，4 路径 analyze 无问题。
