# 报销详情页

> 路由：`/expense/:id` · 实现源：`lib/features/expense/pages/expense_detail_page.dart`

## 一、定位

申请人视角的报销单全貌：单据信息、明细、**发票登记、发票影像附件、审批轨迹、打款结果**，
并输出**可打印的《费用报销单》**。审批人视角见 [报销审批详情页](报销审批详情页.md)。

## 二、页面结构(2026-09-19 V608 改版：卡片序 + 内嵌表格，默认 1600 容器)

- `UtenAppBar('报销详情')` + actions「打印报销单」→ `showExpenseClaimPrintPreview`。
- **头卡**：标题 + 状态徽章 + 金额大字 + **人民币大写**；
  REJECTED 显示驳回横幅(驳回人/原因/修订指引)，PAID 显示打款横幅
  (付款账户 · 费用类别 · 付款日期 · 出纳 · 关联财务费用单已生成)。
- **信息卡**：报销单号(BX)/申请人/部门/创建时间/提交时间/审批通过(人+时间)。
- **报销明细**：`MasterDataTableView(embedded: true)`，列 = 费用科目/日期/说明/金额，
  表尾合计条(共 N 项 · 合计 ¥x.xx)。
- **发票登记**：`ExpenseInvoiceSection`——结构化票面要素表
  (#/类型/发票号码/发票代码/开票日期/销售方/金额/税额/价税合计/核对/备注)+
  「登记发票」按钮(本人且 DRAFT/REJECTED)：
  - 弹窗支持**图片识别回填**(`POST /invoices/recognize`；口径：不接外部付费
    AI API，识别服务使用本地开源 PaddleOCR 侧车，
    未部署时明确报「未配置」引导手工登记，全链路仍可用)；
  - **查重预检**(`GET /invoices/check`)：号码成形即查，重复时表单内红色提示；
    库级唯一索引只覆盖报销域已登记号码，不代表官方查验或跨账套入账去重；
  - 号码形状校验：数电票 20 位无代码 / 老票 8 位 + 10/12 位代码(税务总局 2024 年 11 号公告)；
  - `OTHER` 凭证可使用字母、数字、斜杠及连字符号码，并填写开具单位，不套用增值税发票号码格式；
  - 购销双方、购买方税号和金额按原件填写；金额勾稽一致显示 **AMOUNTS_MATCH**，不符显示 **MISMATCH**；
    **VERIFIED_MANUAL** 仅由审核人员显式记录核验结果产生；
  - 必须关联已上传的本单附件。OCR 后勾选已对照原件核对，识别接口本身不自动保存原件。
- **附件 / 发票影像**：`AttachmentSection`(本人且 DRAFT/REJECTED 可传删；
  财会〔2020〕6 号第四条：电子票打印件入账必须同时留存电子原件)。
- **审批轨迹**：`ExpenseClaimTimeline`——事件表真轨迹(提交/撤回/修改/通过/驳回/打款 +
  操作人姓名 + 备注)，显示当前阶段及真实流转；没有证据的旧操作不得补造姓名或核验结论。
- **备注卡**(有则显示)。
- **付款证明**：独立 `EXPENSE_PAYMENT_PROOF` 附件区，员工只读查看银行回单或现金签收凭据；不与申请凭证的上传、删除动作混用。

## 三、右下悬浮操作(本人按状态)

| 状态 | 操作 |
|---|---|
| DRAFT | 删除(danger，确认弹窗)/ 编辑 / 提交审批 |
| REJECTED | 编辑 / **重新提交**(清驳回痕迹并重新通知审批人) |
| SUBMITTED / REVIEWING | 撤回(回 DRAFT，办结审批卡) |
| APPROVED / PAID | 无(等待财务打款/已完成) |

提交前服务端校验版本、明细日期和用途、扫描通过的附件、逐票日期及本单附件关联。
财务启用“提交时必须登记票据”时至少有一张登记票据；关闭时无登记票据仍需附件及备注中的报销依据。
已提交后凭证只读；撤回或驳回修改后需重新核验。所有写操作携带 `expectedVersion`，旧页面不得覆盖新材料。

## 四、打印与原件

A4 打印包含公司抬头、单号、事由、明细、大小写合计、票据/电子文件份数、实际纸张待填写栏、
完整流转记录及付款信息。多行和长说明需正确换行分页。公司抬头读取当前财务设置，未冻结为历史快照。
展示件、签字空栏和系统姓名不等于税务发票、法定记账凭证或认证电子签名；原件与归档见[合规清单](../07-业务链路/员工报销合规依据与凭证清单.md)。

## 五、权限

路由守卫 `expense:apply`；后端 detail `assertCanRead`(本人 / 审批人 / 打款人按状态分权)，
附件渲染需 `attachment:view`。

## 六、测试

修订重提的旧、新费用明细和发票登记统一按[重新提交审批差异展示](重新提交审批差异展示.md)显示。
草稿或驳回后正在修订时显示当前可编辑资料；提交之后才使用冻结快照对比。旧历史未留存时明确提示，不补造旧值。
