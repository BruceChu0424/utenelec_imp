# 232 · V647 未领料车间工单原位追加(ADR-104)

- 迁移：`V647__material_analysis_execution_growth_in_place.sql`，前向追加；V645 与更早已应用文件保持原字节。
- 源码目录：V647/598。新增 `production_execution_segment_growth_events`，登记行级审计和业务清理 `CLEAR`；不新增权限码。
- 决策：[ADR-104](../99-决策记录-ADR/ADR-104-追加自制并入未开工的生产计划.md)。
- 编号：并行委外子件专属库存交接占用 V646，本迁移在应用到原库前顺延为 V647；最终验证必须包含该 V646 基线，不能将顺延前的隔离结果当作 V647 最终候选已通过。

## 原因与行为

V645 让追加量并入原生产计划，但已审核计划通过 `appendSegment` 新建执行段，车间列表仍多出一张 ZX 工单。V647 将合并继续落实到原车间工单：未提交领料且无后续执行事实时，原计划、计划包、执行段 UUID、ZX 工单号和物料需求身份保持不变，数量直接增加。已有领料申请，即使尚未发料，也应另建新单。

## 数据库合同

- `fn_material_analysis_plan_growable` 收紧到无领料申请及执行事实。内部未提交 DRAW 草稿与车间主动提交领料申请是不同事实，不以 `issued_qty = 0` 代替此边界。
- 受控入口 `fn_grow_material_analysis_execution_segment(segmentId, addedQty, salesAddedQty)` 同步增长原执行段与物料基准量；需求按原 `consumption_snapshot` 对累计产量计算。固定批次和整包的取整只针对累计总量，不把追加量独立向上取整后相加。
- `production_execution_segment_growth_events` 保存原位增长证据并禁止通用改删。身份与覆盖守卫只对有对应证据的变化放行；普通 UPDATE 不得改变段数量、需求数量、冻结规则或来源。
- 普通齐套准备的 READY 仍要求当前需求完整覆盖；持续准备保留已有增量准备规则，开工资格仍按当前路线和实领事实判断。原位增长后 WAITING 可以保留增长前的预留和未提交 DRAW；该例外不允许普通 WAITING 凭空占料，也不使未来供给变成库存。
- 原有销售排产容量先扩展，再增加原段归需求份；公共备货数量不计入销售订单。

## 应用接续与并发

Java 在同一事务完成计划及关联行加量、原段受控增长、齐套差额准备。差额为当前需求减去已有有效预留覆盖；同一实际叶仓复用未提交 DRAW，并新增来源明确的明细。新量不足时保留原准备事实，等待真实到料后补齐；未确认路线保持等待，追加不自动提交领料或开工。

共同履约来源/库存/主仓/分析锁先行，再按计划、计划包、执行段、DRAW 顺序锁定并重查合并条件。增长递增任务版本，旧领料预览和旧开工请求须重新核对；领料申请先完成的情况下追加不能再合并。

## 兼容与清理

迁移不自动折叠历史上已经拆出的多张工单，不更换旧工单号、不删除执行事实。需要处理已存在测试任务时必须核对全部关联、留恢复证据并单独记录结果，不能仅按同货品汇总数量。

### 本地历史 APPEND 两段的受控修复

操作入口为 [merge_unexecuted_analysis_append_tasks.sql](../../server/ops/merge_unexecuted_analysis_append_tasks.sql)。它仅处理人工复核过的同一分析范围内「原段 + V645 APPEND 段」两段组合，不是通用合单工具：计划、计划明细、计划包、产品/颜色/单位/换算率、车间/负责人/日期、需求仓库/日期/直送属性和冻结物料规则必须一致；双方未确认路线、没有领料/报工/拆批/直送等执行历史，也没有预留、供给承诺或备料单关联。脚本还枚举执行段及需求的入站外键，除本次明确保留的需求归属及销售分摊外，任何关联历史都拒绝。任一组合不符合即整事务失败。

原计划及分析关联量保持不变；追加源段改为取消并软删除，源需求释放并软删除，保留原 UUID、ZX、数量、冻结规则及历史关联；原段调用 V647 受控入口增长到合计数量。固定批次/整包按原冻结规则对合计重新计量，不把两段旧需求机械相加。源段退役审计与原段增长事件使用同一事务、请求 ID 和真实操作者关联。脚本不会禁用触发器或修改 Flyway 历史。

操作顺序：

1. 只读核对目标数据库、分析 UUID、预期组合数和逐对原/追加工单身份；生成完整可恢复备份并保留文件校验值。
2. 从备份恢复到独立克隆，安装 V647 后用 `psql -X -v ON_ERROR_STOP=1` 执行脚本。传入 `expected_database`、`analysis_id`、`actor_id`、`expected_pairs`，默认 `apply=false`；数据库名称不符会拒绝。脚本执行全部变更并运行 `SET CONSTRAINTS ALL IMMEDIATE` 后输出逐对结果，最后 `ROLLBACK`；必须保存完整输出和复核结果。
3. 此维护脚本不实现在线业务的完整履约锁前缀。正式执行前停止应用写入和后台执行任务，重新核对库身份、备份和同一组对象；只对已授权、已演练的本地目标显式传入 `apply=true`。候选或数量变化须停止，不能为凑足预期数扩大范围。
4. 提交后核对原计划量/关联量不变、活动任务数减少、原 ZX 和合计数量正确、追加源历史仍可查、增长事件与审计对应；再恢复服务并核对页面。失败保持回滚或沿完整备份恢复，不通过禁用约束强行完成。

克隆回滚演练、原库提交及页面验收必须分别记入[本轮验收记录](../99-项目治理/2026-09-23-自制追加原车间工单验收.md)。脚本存在或克隆成功不表示原库已经修复。
