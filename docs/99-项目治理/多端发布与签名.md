# 多端发布与签名

> 适用平台：Android、iOS、Web/PWA、Windows、macOS、Linux
> 当前结论：发布元数据与 Android 安全基线已加固，但六端可复现 Release 构建、签名、安装和
> 真实后端冒烟尚未全部完成；不得把“源码已配置”写成“安装包已验收”。
> 中国大陆是主要运行区域时，本文须与
> [中国大陆部署与兼容性](中国大陆部署与兼容性.md)同时执行。

## 一、统一产品信息

- 用户可见产品名统一为“优腾综合管理平台”；PWA short name 为“优腾 IMP”。
- Flutter 页面内产品名、版本和版权来自 `lib/core/constants/app_info.dart`。
- 应用版本用 `--dart-define=APP_VERSION=<version>` 注入；未注入时只回退到开发默认 `0.1.0`。
- Android label、iOS/macOS display name、Windows 产品/窗口名、Linux 窗口名和 Web/PWA manifest
  已同步。发布前仍须逐端截图/安装检查，防止商店、安装器或缓存沿用旧 `uten_imp`。
- PWA 已移除 `portrait-primary`，允许手机横屏、平板和桌面按响应式断点布局。

## 二、API 地址发布契约

员工端和访客端共用 `lib/core/network/api_base_url.dart`，构建矩阵如下：

| 构建 | 空 `API_BASE_URL` | 允许的显式值 |
|---|---|---|
| Debug/Profile | `http://localhost:8080/api` | 合法的绝对 HTTP(S) URL |
| Web Release | 同源 `/api` | `/api...` 相对路径或绝对 HTTPS URL |
| Android/iOS/Windows/macOS/Linux Release | fail-fast | 绝对 HTTPS URL，禁止回环地址 |

绝对地址带 userinfo、query 或 fragment 会被拒绝。`API_BASE_URL` 和 `APP_VERSION` 都会编译进
客户端产物，只能放公开配置；JWT/PGP/SMS/签名密码等秘密必须走后端环境、Vault/KMS 或 CI secret。

Web 与 API 由同一域名反向代理时推荐省略 API 参数：

```powershell
flutter build web --release --no-web-resources-cdn --dart-define=APP_VERSION=<release-version>
```

`--no-web-resources-cdn` 是发布安全契约，不得省略：Flutter 默认 Web Release 会从
`https://www.gstatic.com/flutter-canvaskit/...` 动态加载 CanvasKit，严格的同源
`script-src/connect-src` 会正确阻断该请求并导致白屏。同源打包运行时资源后，不需要为了兼容
Flutter 而放宽 CSP 到第三方 CDN。

Web 打印也必须使用项目的平台封装：IO 平台可调用系统打印，Web 使用同源 PDF Blob。业务代码
不得直接引入 `Printing`/`PdfPreview`，否则插件可能重新启用公共 PDF.js CDN 和动态脚本路径。
CI 中的 `test/mainland_runtime_guard_test.dart` 会检查这一约束及常见第三方运行域名。

移动/桌面 Release 必须显式给出生产 HTTPS API：

```powershell
flutter build windows --release `
  --dart-define=APP_VERSION=<release-version> `
  --dart-define=API_BASE_URL=https://<production-host>/api
```

### 2.1 Web/PWA 生产入口

`web/index.html` 已移除全部内联 style/script，加载动画拆为同源 `loading.css` 与 `loading.js`，
使生产 CSP 不需要 `unsafe-inline`。可审查的 Nginx 起点见
[`deploy/nginx/uten-imp.conf.example`](../../deploy/nginx/uten-imp.conf.example)，包含：

- HTTP 308 跳转 HTTPS、HSTS，以及 Web 静态站点与 `/api` 同源反向代理；
- 严格 CSP：默认/脚本/样式/连接/字体仅同源，禁 object 和 frame ancestor；仅 Flutter Wasm
  执行保留 `wasm-unsafe-eval`，不开放通用 `unsafe-eval` 或 `unsafe-inline`；
- X-Frame-Options、nosniff、Referrer-Policy、Permissions-Policy、COOP；
- `client_max_body_size 2m`，登录 5 次/分钟/IP 与 API 120 次/分钟/IP 的入口共享限流。
- `location ^~ /fallback_fonts/` 对版本钉死的字体分片设置一年缓存；缺文件明确 404，不得回落到
  SPA `index.html`。
- JavaScript/Wasm/JSON/CSS/SVG 开启 gzip，降低大陆移动网络首次传输量；是否启用 Brotli 必须
  在目标网关验证模块与缓存行为。
- 登录/发码入口的 IP 桶只做高阈值粗防洪，通用 API 也按园区 NAT/运营商 CGNAT 容量设置；
  细粒度账号/手机号限制由应用负责，真实共享出口压测后再冻结阈值。

Web 字体采用 4,092,516 B 主 UI Noto、515,100 B Roboto、仅打印按需加载的 17,772,300 B
Noto Full，以及与 Flutter 3.44.2 engine 对齐的 724 个同源懒加载 fallback WOFF2（144 family，
共 21,739,792 B）。PWA service worker 不预缓存 fallback 分片。CI 构建前运行
`.github/scripts/verify-font-assets.ps1`，校验 Flutter 版本及 729 个字体/许可资产的 size+SHA-256；
manifest 不得含本机绝对路径。

模板中的域名、证书路径、上游地址、可信网段和限流值必须按真实拓扑评审。当前主机未安装
Nginx，因此尚无本地 `nginx -t` 证据；上线前必须在目标环境完成：

```bash
nginx -t
curl -I https://<production-host>/
curl -I https://<production-host>/api/actuator/health
```

还要用目标浏览器验证 Flutter 启动、同源 CanvasKit/Wasm、字体、Web Worker、下载、相机、登录刷新、
前进后退和 PWA 更新；控制台不得有 CSP 违规，同源 API、429 与 413 负向行为必须符合契约。

## 三、Android 发布安全

### 3.1 网络权限与明文流量

- `android/app/src/main/AndroidManifest.xml` 必须声明 `INTERNET`；业务 Dio 请求在 Release 包同样
  需要该权限。旧配置只在 debug manifest 声明，会导致正式包无法访问后端。
- main manifest 设置 `android:usesCleartextTraffic="false"`，Release 只允许 HTTPS。
- debug/profile manifest 可覆盖为 `true`，仅供本地 HTTP 后端调试；不得把该覆盖并入 Release。
- CAMERA 权限用于保安访客扫码；发布隐私说明和商店权限声明必须说明用途。
- main manifest 设置 `android:allowBackup="false"`。同时保留 Android 11 及以下的
  `backup_rules.xml` 与 Android 12+ 的 `data_extraction_rules.xml`，对 root/file/database/
  sharedpref/external 全部排除，云备份和设备迁移都不得带出 token、数据库或应用状态。配置存在不
  等于设备行为已验收，发布包仍须做备份/恢复及设备迁移负向测试。

### 3.2 Release 签名

Android Release 禁止复用 Flutter debug key。当前 Gradle 从被 Git 忽略的
`android/key.properties` 读取：

```properties
storeFile=<keystore path>
storePassword=<secret>
keyAlias=<alias>
keyPassword=<secret>
```

仓库只提供不含秘密的 `android/key.properties.example`。任何 Release task 缺少上述配置时必须
fail-fast，不能自动退回 debug 签名。keystore 与密码进入组织密钥管理/受控 CI secret，备份、
轮换、责任人和恢复流程必须留档，禁止提交 Git、日志或构建产物附件。

推荐发布命令：

```powershell
flutter build appbundle --release `
  --dart-define=APP_VERSION=<release-version> `
  --dart-define=API_BASE_URL=https://<production-api>
```

构建后必须用 Android 官方签名工具核验 AAB/APK 证书指纹，并安装到真机验证 HTTPS API、登录、
安全存储、相机权限、扫码、下载和升级覆盖。

### 3.3 设备审计与本机回执发布边界

设备审计是跨端安全能力，不得把某个平台“碰巧能读到”的字段升级为强制硬件身份：

| 平台 | 可记录的设备证据 | 必须明确的缺失边界 |
|---|---|---|
| Android / iOS | 平台、系统版本、应用版本/构建、设备厂商/型号及物理设备标志（系统 API 可提供时） | 不申请或采集 IMEI、MAC、SIM、广告 ID、硬件序列号；设备显示名称可能为空 |
| Windows / macOS / Linux | 主机显示名称、平台/系统、应用版本/构建、设备形态（系统 API 可提供时） | 主机名可被用户修改，不等同硬件认证；不读取硬盘、主板或网卡序列号 |
| Web / PWA | 浏览器、平台、语言、时区、应用版本及随机安装标识 | 浏览器通常不提供真实设备名称、厂商和型号；不得通过 User-Agent 猜测并冒充确定值 |

每次安装首次运行生成随机 `device_installation_id`；每次逻辑操作生成 `client_event_id`，本机回执再保存
服务器返回的 `request_id`。设备快照随请求发送前必须限长、规范化并排除请求正文、查询值、令牌和业务
数据。服务器保存的是收到的客户端声明，不是平台远程证明；本机回执正文是偏好存储中的明文 JSON，
HMAC 完整性标记的密钥在平台安全存储，但仍位于本机，只能用于发现常见损坏或改写。产品权限无法阻止
已经取得设备管理员/root、浏览器开发工具或用户系统账号权限的人直接读取本地数据。产品文案统一使用
“交叉佐证一致/部分一致/无法核查”，禁止写成“绝对真实”。

本机回执最多 300 条，并按服务器在线期与追加归档期之和自动清理；产品不提供人工清除或修改入口。
但应用卸载、浏览器站点数据清除、系统存储清理、设备重置或安全存储损坏仍会让本机数据消失，发布说明
必须把它写成介质边界。Android 备份规则继续排除 shared preferences、安全存储和应用状态；其它平台也
不得把安装标识、完整性密钥或回执带入云备份/设备迁移，发布验收须做卸载、升级、恢复和迁移负向测试。

页面和深链同样属于发布门禁：审计中心与 `/settings/device-receipts` 仅向持 `audit_log:view` 的指定
核查人员开放；普通员工不显示入口，访客端不注册等价路由，直接输入深链也必须拒绝。任何审计或回执
导出还需 `audit_log:export`；任何端均不得提供编辑服务器审计、人工删除服务器记录或手动清空本机回执。
读取目标本机回执前必须按完整 `client_event_id` 在线请求服务端授权并记录核查，授权失败或离线时不得
因为“数据已经在本机”而降级读取。

## 六、发布验收清单

- [ ] 冻结唯一 commit、Flutter/Dart/Java/Gradle/Xcode 工具链与依赖锁文件。
- [ ] 六端产品名、版本、图标、版权、权限说明和商店元数据一致。
- [ ] Android Release 缺签名配置确定失败；有配置时签名证书不是 debug key。
- [ ] Android Release 有 INTERNET、禁止 cleartext；debug/profile 本地 HTTP 不影响 Release。
- [ ] Android Release 禁止系统备份；云备份、`adb`/设备迁移和恢复测试均不能带出 token、数据库、
      shared preferences 或其它应用状态。
- [ ] Web Release 空配置只请求同源 `/api`；所有非 Web Release 均请求显式 HTTPS 生产地址，
      且错误/回环地址构建或启动确定失败。
- [ ] Web/PWA 目标 Nginx `nginx -t` 通过；HTTP→HTTPS、HSTS、CSP、frame/nosniff/
      Permissions-Policy/COOP、2 MiB 请求体、登录/API 限流和同源 `/api` 均有正反向证据。
- [ ] Web/PWA 由 `--no-web-resources-cdn` 构建且产物不请求第三方运行时 CDN；可横竖屏，
      严格 CSP 下无控制台违规，CanvasKit/Wasm/Worker/字体/下载/相机可用，CORS/TLS、
      缓存更新和离线边界符合发布策略。
- [ ] 字体校验脚本验证 729 个版本钉死资产；`/fallback_fonts/` 缺文件返回 404、命中项长期缓存；

- [ ] 各平台安装、升级、回滚、登录/刷新、API、下载、安全存储、相机和退出完成冒烟。

- [ ] 普通员工、访客和无权限深链均不能进入审计中心或本机回执；`audit_log:view` 可核查但不可导出，

- [ ] 每次目标回执读取前均完成服务端授权并产生 `verify_local_audit_receipt`；无权限、令牌失效、断网、

- [ ] 卸载、清站点数据、系统清理、设备迁移和备份恢复不会把本机回执或完整性密钥带到另一安装实例，
      数据消失时页面明确显示“无法核查”而不是否定服务器审计。
- [ ] 产物生成 SBOM/校验和并经恶意软件/依赖扫描；签名、构建日志和产物受控归档。
- [ ] CI 对发布任务启用审批、最小权限 secret、不可变产物和可追溯版本号。
