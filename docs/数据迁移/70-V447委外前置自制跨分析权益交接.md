## 一、解决的问题

分析来源的委外行有子层级时，V436 会创建独立的 `SUBCONTRACT_PREPARATION` 物料分析。如果原分析已经下达采购、委外或 `MAKE_COMPONENT`，其现货与后续合格入库仍归原 `analysisId + materialLineId`，会造成原树看似齐套、前置分析仍缺料并再次下达。

V447 不复制库存、不猜货号，也不借用人工让料的“以后优先补齐”语义。它把本委外订货行接管的需求和供给所有权显式、定量、可审计地移到独立前置分析；原委外父件仍留在原分析，直到真实目标件出仓、回厂、IQC PASS 且仓库确认实际入库后才完成。

## 二、追加式事实

| 表/事件 | 权威含义 |
|---|---|
| `preplan_subcontract_requirement_handoffs` | 一个委外计划行、原分析父节点和目标前置分析之间的交接头；冻结双方版本、指纹、仓库和目标件 UUID |
| `preplan_subcontract_requirement_handoff_items` | 按相对 `bom_item_id UUID[]` 与 `goods/color/unit UUID` 映射的逐子件来源/目标行及容量快照 |
| `preplan_subcontract_requirement_supply_claims` | 对原供给 allocation 的未来容量认领；不得超过 allocation 数量，也不得被第二个活动交接重复认领 |
| `preplan_subcontract_entitlement_handoff_slices` | 已到库 exact lot 的逐切片交接证据，绑定物理预留、原 exact peg、OUT/IN 事件和可选 claim |
| `preplan_subcontract_requirement_handoff_events` | 父产出数量的 `TAKEOVER/RESTORE`；TAKEOVER 必须等于该委外行数量，RESTORE 只能全量且反指原 TAKEOVER |
| `SUBCONTRACT_HANDOFF_OUT/IN` | 同一物理库存上的成对权益事件；只变 current beneficiary，不改 origin、reservation 或库存流水 |

五张新表和事件账均 append-only。复合外键、延迟守恒触发器、来源 lineage、路径/维度、claim 容量、slice 容量及 OUT/IN 对称性任一不一致都在事务提交前失败关闭。活动交接所引用的原 action/allocation/物料身份不可改指或取消。

## 三、启动事务

`START_PREPARATION` 在一个事务内完成：

1. 解析唯一的原 `SUBCONTRACT` action、allocation、分析和父物料行；零条按直接委外处理，多条来源歧义直接阻断。
2. 按库存维度 → 原/目标分析 → 委外计划行的固定顺序加锁，并校验 CAS 版本、BOM 指纹、仓库和活动状态。
3. 创建独立前置分析，再以双方相对 BOM UUID 路径逐行建立不可变映射；名称、货号和展示层级不参与关联。
4. 追加父产出 `TAKEOVER`。刷新原分析时只从该 `SUBCONTRACT` 父节点的递归产出中扣除本行接管量；父件自身需求保留。
5. 对原子件供给 allocation 建立 claim；目标分析的未绑定缺口同时扣除 claim，避免重复采购/生产。
6. 将当时已有的可用 exact lot 以 OUT/IN 成对事件移到目标；刷新原分析和目标分析。

同一幂等键同一请求只返回原结果；缺少完整 V447 交接账的历史命令不得伪装成成功重放。

## 四、未来供给与仓库入库

- 未审批采购申请、委外申请或自制任务只代表被认领容量，显示为“委外前置自制已接管供给”，不计入 `inboundQty`。
- 采购/委外订货财务生效或生产计划正式批准后，尚未实收的有效数量才投影为目标分析确认在途；原分析先扣除活动 claim，避免一份供给在两边重复展示。
- IQC PASS 仍只创建 V446 仓库待入库。仓库人员确认实际量与实际库位后产生 exact origin；V447 的有序 hook 先按 claim 把可用切片交给目标分析，剩余量才允许进入普通人工让料优先链。
- 到货、红冲或分批只按实际 exact slice 推进。`future_qty = claimed_qty - arrived_qty`，不得把预计数直接变成库存或完成量。

## 五、取消与恢复

目标前置分析只有在没有领料、执行、产出、委外出仓、权益消费或其它不可逆事实时才能取消。受控取消依次：

1. 对目标当前 exact slice 追加 RELEASE/RESTORE 对称事件，恢复原 beneficiary；
2. 对父产出追加全量 `RESTORE`，使原分析重新展开被接管子树；
3. 刷新双方分析，并把尚未实际准备/发出的前置任务标为 `CANCELLED`。

若任一数量已消费或真实生产已开始，取消整体回滚并返回明确阻断原因。不得删表、改历史事件或把专属权益释放成公共库存作为“恢复”。

## 六、升级与发布边界

V447 前置检查会拒绝已经启动但没有 V447 账的分析来源 `MAKE_THEN_OUTBOUND` 任务，防止升级后出现无法证明所有权的半历史状态。V447 还以前向方式扩展 V337 entitlement 校验函数，使新 OUT/IN lot 可继续参与既有 FORMALIZE、MAKE、REALLOCATE、RELEASE 和 RESTORE 守恒；不修改任何已应用迁移字节。

发布顺序固定为：

```text
停止全部旧应用、worker 和写入口
  → 校验备份/checksum/目标非空克隆
  → 应用 V446
  → 应用 V447
  → 只启动新应用
  → 运行交接/仓库/库存后验收
  → 才允许恢复业务写流量
```

禁止新旧 JAR 滚动混跑；应用 V446/V447 后禁止用旧 JAR 回滚。失败时保持停写，使用已验证的整体恢复点或新增 V448+ 前向修复。
