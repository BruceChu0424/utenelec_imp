# 价格分析入口与商业价格权限收口

本轮承接 `392dd7b12` 的历史权限修复，在独立分支 `uimp/history-company-permissions-20261101` 继续实现。修改分类为前端、服务端与共享权限契约；界面按 `frontend-design`，沿用 Uten 的 NotoSansSC、主题、控件、布局及响应性规则。

## 根因与公共实现

用户要求：货品、采购、委外缺少对应价格权限时，不能从历史价格、价格分析、AI工具或直接链接取得价格；没有可查看的价格来源时，右上角入口也应隐藏。

排查发现：

| 原入口 | 已有正确能力 | 缺口与本轮处理 |
|---|---|---|
| `CommercialPriceVisibility`、采购/委外 `DocConfig.canViewCommercial` | 对应页面已有独立价格码，服务端 DTO、列表/筛选/报表及客户端列布局使用该公共能力 | 旧逻辑把 `finance:view:all` 也当作商业价格授权。当前 `permission-help.json` 明确该码只扩大财务数据范围，不自动开通敏感字段。现统一为对应价格码，不以范围、编辑或分析码替代 |
| 货品顶栏 `goods-price-analysis-entry`、价格分析路由及页面 | 已要求货品查看、分析权限，服务端仍控制来源与对象范围 | 原入口/页面只检查基础两码，所有价格池均显示。现至少具备一个可读来源才显示入口/放行路由；只显示获准的价格池，并重验异步离开编辑后的当前权限 |
| 图表、历史表头/分页/远程筛选、精确版本详情 | 已在服务端按来源、负责人、客户及版本过滤，保留原币精度与数据口径 | 页内详情和供应商详情以前只检查基础两码。现统一检查本价格池，失权立即清数据，晚到结果不得恢复 |
| 采购/委外编辑器价格核对、保存后提示 | 原有后台有界批量、取消、代次和保存结果语义 | 客户端基础两码不足以决定能否读该来源历史。现按页面的明确 `PURCHASE` / `SUBCONTRACT` 参数判断；七处保存提示调用同步接入，权限不足不查询或展示历史偏差 |
| 市场参考、市场目录及关联 | 已要求货品、分析与采购来源，保持只读建议和受控关联 | 公共门禁和控制器/服务原注解都移除财务范围替代价格码的旧分支 |
| `AiGoodsPriceTool`、AI页面指南 | 已限制AI领域、服务端价格证据和旧结果读取；业务价格不发给模型提供者 | 原工具只按基础两码登记，缺价格权限仍可看到工具。现工具只在有可分析来源时登记；参数只提供获准种类，执行前拒绝越种类，页面指南沿用入口判断 |

唯一公共价格字段判断：Java `CommercialPriceVisibility.canViewCommercial`，Dart `shared/auth/commercial_price_visibility.dart`。Java 原采购/委外重复判定合并为同一实例入口；客户端两套单据配置改为调用公共函数，所有使用这些配置的详情、列布局及草稿历史投影同步生效。财务自身文档/附件的财务权限继续由其原领域判断。

分析能力：Java `security/PriceAnalysisAccessPolicy` 和 Dart `shared/pricing/price_analysis_access.dart`。跨语言以 `contracts/price-analysis-access/v1.json` 同组正反例验证，涵盖无权限、只有分析、只有来源、只有价格、只有编辑、财务范围、独立采购/委外/销售、报价财务历史、超管、未知种类及多来源组合。

## 权限合同及必要差异

1. 普通分析入口先要求 `goods:view` + `goods:price_analysis:view`，再要求至少一个来源的价格读取能力。
2. 采购分析要求 `purchase_order:price:view`，同时具备采购订单查看或既有财务审批来源查看；委外对应 `subcontract_order:price:view`。销售分析要求销售订单查看与 `sales_order:price:view`，不沿用采购/委外码。
3. 采购收货/退货/报表、委外询价/收货/退货/报表及损耗建议仍按各自明确的字段码判断，不能用另一个单据的价格码互相替代。
4. `sales_quote_finance:view` 是原确认报价财务历史自己的授权，保留只读报价历史分支；它不会打开销售订单价格分析、均价或AI议价工具。
5. 旧材料出/退仓兼容成本不是当前页面商业价格列；服务端兼容字段需财务读取范围与明确 `goods:cost:view` 同时满足。仓储结构性无商业字段投影继续保留。
6. 主档价格、已学采购/委外成本、组件成本及确认成本测算仍是各自业务事实；本轮不合并币种、税率、单位、数量口径或计价规则。此前货品修改历史的纯受限修改隐藏、混合字段遮罩及恢复限制保留；当前主档字段维护继续走原字段写权限。

路由原 any/all 码映射不伪造为一个万能权限；`route_access_policy` 在该精确路由增加共用来源能力判断，入口和页内使用同一合同。无任何来源时普通链接转拒绝页；组件被直接挂载时也只显示权限提示，不发价格查询。

UI保持既有基色 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、次级文字 `#475569` 和强调色 `#0D9488` 及深色主题。唯一布局变化是按权限减去类型切换项，初始或权限变化时选择仍获准的类型。保留输入草稿与有权查看的业务流程；图表、筛选选项、表格、详情及供应商数据跟随身份/权限/请求代次退役。权限缺失不生成替代价格或自动补授权限。

## 完整适用调用方

| 层次 | 接入入口 |
|---|---|
| 价格字段公共能力 | Java采购订单/收货/退货/报表、委外询价/订单/收货/退货/损耗建议/报表及旧材料兼容成本；Dart `PurchaseDocConfig`、`SubcontractDocConfig` 的所有调用方，包括 `form_draft_history_projection` |
| 价格分析UI | `GoodsDetailBody` 顶栏、`GoodsPriceAnalysisPage`、`GoodsPriceObservationDetail`、`GoodsSubcontractSupplierDetail`、`GoodsMaterialMarketPanel`、直接路由 |
| 编辑与保存提示 | `ProcurementPriceCheckScope`；采购订单两处、采购通用单据一处、委外订单两处、委外通用单据两处 `notifySavedPriceAssessment`，共七处 |
| 服务端价格链 | `GoodsPriceAccess` → 价格分析/核对、游标历史、分页历史/远程 facets、精确版本详情、供应商价格/损耗能力、市场参考/目录/关联；原来源SQL的对象/负责人/客户过滤在 LIMIT 和聚合之前保留 |
| AI | 工具登记、工具参数、按种类执行、原有旧结果当前证据重验、页面指南；保留 `modelFacts` 不输出业务价格的合同 |
| 导出与历史 | 采购/委外公共报表及结构性历史/草稿投影消费同一价格公共入口；专用价格分析页面本身没有独立导出接口，不虚列不存在的导出能力 |

所有已支持 Web 与 Flutter 桌面入口共用上述 Dart 源码及服务端。Win7 已有货品列表/详情的售价列本来就按 `goods:price:view` 与 `priceMasked` 判断，本轮未改其读值合同；WPF价格分析、采购/委外完整业务入口仍未迁移，按唯一台账登记受影响合同，不以服务器同步代替原生UI完成。
