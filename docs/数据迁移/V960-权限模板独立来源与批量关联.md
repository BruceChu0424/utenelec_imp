# V960：权限模板独立来源与批量关联

本迁移是本地候选，须与本轮服务端及前端源码一并审核、验证和交付。本次未在公司服务器执行。

## 结构与权威入口

新增 `user_permission_template_bindings`、`department_permission_template_bindings`。每个员工账号/部门可关联当前一份模板，内容始终读取模板最新有效权限码。`authorization_user_template_permission_sources` 与 `authorization_department_permission_sources` 是稳定来源视图，分别过滤超级管理员专属或仅限逐人配置的策略。单人/批量解析、负责人委派上限、通知与访客候选及高权检查接入同一来源。

绑定变动使用既有授权版本/epoch触发机制；模板权限码或删除状态变化推进关联授权的epoch。两张绑定表登记 FULL 授权审计。没有修改或重置既有基础包、部门直接配置、个人加授/取消及数据范围。

## 旧数据和关系语义

V957仅记录旧应用目标，不能证明相同个人授权是手工还是模板写入。本迁移保留其原行及权限，不自动拆分或删除；读取时标记 `legacySnapshot`。重新应用模板后建立独立来源并删除该目标旧关联记录，原手工配置按合并/替换的预览处理。

模板编辑只改变模板来源；个人取消优先，手工授权不会因模板删除同码而丢失。部门模板按既有组织继承规则作用于当前和未来员工。合并保留直接设置；替换仅清空直接正向权限、换绑模板，保留个人取消及其他来源。删除模板/显式解绑将当前正向贡献固化为手工配置后清关系；失效任职不会因此重新激活旧授权。复制/导入整份配置解除相应对象动态关联后恢复已审阅快照。

## 接口与验证

`/api/admin/permission-templates/apply/preview`、`/apply`、`/bindings`、`/unbind`；普通增量 `/api/admin/permissions/batch/preview` 和 `/batch`。最多 500 个对象，服务端权限/目标资格校验、配置指纹、敏感新增逐项确认及同事务写入。只有数据库确认的超级管理员本人并持 `authorization:manage` 可操作，写入继续要求会话再认证。
