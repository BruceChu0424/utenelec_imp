# 服务器状态

> 2026-09-08 新增；源码与界面验证进行中，尚未部署到公司服务器。

入口为工作台「系统管理 → 服务器状态」，地址 `/admin/server-status`。只读权限 `server_status:view` 独立于授权管理，只有获授该权限的员工可以查看；访客不能查看。页面不提供任意命令、重启、删目录或修改系统配置的按钮。

## 显示内容

| 项目 | 口径与预警 |
|---|---|
| 处理器占用 | 运行环境 CPU 采样；80% 黄、95% 红。短时升高可以观察，持续偏高需要检查 |
| 系统内存 | 显示占用比例与已用/总量；Linux 按 MemAvailable 计算，可回收文件缓存不误算为内存耗尽；80% 黄、90% 红 |
| 平台应用内存 | Java 堆占用与上限，与整台服务器内存分开；80% 黄、90% 红 |
| 数据库连接池 | 活跃连接占平台连接上限；80% 黄、95% 红 |
| 磁盘空间 | 系统、附件、数据和配置的备份目录；同一文件系统合并显示，80% 黄、90% 红。不把磁盘余量叫作内存 |
| 数据库 | 后台只读探测耗时与连接数量；探测200ms黄、1000ms红，连接80%黄、95%红；连接失败红色 |
| 最近备份 | 核验过的本地备份完成时间；30小时黄、48小时红。最近备份检查失败单独报红，不冒充“备份文件已损坏” |

读不到、未接入或过期的值显示灰色和具体原因，不用0填空，也不保留旧绿色状态误导用户。颜色同时配文字和图标，提示图标可悬浮、触控查看。版本标识未配置时如实说明，不拿开发版本号冒充服务器安装版本。

## 性能与采样

后端使用独立单线程每15秒采集一次，页面 GET 只取缓存，不随页面人数重复扫描磁盘或访问数据库。连续请求不会触发新的采样。界面超过两个采样间隔（默认30秒）未更新先标灰，后端超过45秒也不再提供旧的正常状态；页面仅在可见时轮询，离开后停止。数据库探测只读 `pg_stat_activity` 的数量及连接上限，不读取业务明细或SQL文本。

备份摘要由 `deploy/monitoring/server_status_export.py` 从既有本地备份检查报告生成，不运行备份、不连接云存储。输出仅保留检查时间、最后成功备份时间和检查状态，不暴露数据库标识、WAL名称、配置或原始错误。重新导出不会刷新原报告时间；超过15分钟未得到新检查报告显示未知。没有检查报告时保持未接入，不能根据目录存在或文件修改时间猜测成功。

配套systemd样例：`deploy/systemd/uten-imp-server-status.service.example` 与 `.timer.example`。服务每分钟导出一个小摘要，CPU限制10%、内存64MiB、禁止网络；应用只读 `/var/lib/uten-imp-server-status/backup.json`。源报告仍保持原来的私有权限，应用不获授root报告目录读取权。

配置项：`UTEN_SERVER_STATUS_DATA_PATH`、`UTEN_SERVER_STATUS_BACKUP_PATH`、`UTEN_SERVER_STATUS_BACKUP_STATUS_FILE`、`UTEN_SERVER_STATUS_APPLICATION_VERSION`。实际安装时按真实挂载目录和发布版本填写；权限迁移V534只新增查看权，不授予服务器维护命令能力。
