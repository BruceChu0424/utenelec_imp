当前目录为 **V543 / 502 条迁移**；本篇为 2026-09-10 审计收口，承接 [139-V541](139-V541车间默认权限收紧.md)。只动部门授权行、页面权限面关联和权限目录的 `bulk_assignable` 标志；不改权限码集合、不碰个人加授（`user_permission_overrides`）、不写业务数据。

## 1. DEPT_PROD 残留收回（22 行）

V541 表头写明「车间只需 我的车间任务/日报报工/FQC送检」，但 dev 库核对仍留有：

| 类别 | 收回码 | 为什么不属于车间 |
|---|---|---|
| 对象范围 | `production_plan:view:all` | 范围码；任何人被个别加授 `production_plan:view` 即看到全部车间的计划 |
| 计划生命周期 | `production_plan:delete/batchDelete/reverse/flags` | 计划部（SUB_PLAN）职责，车间无对应页面入口 |
| 计划包 | `production_planning_package:cancel/draft_edit/generate/reverse` | 同上 |
| 执行调度 | `production_execution:overview/assign/dispatch` | 生产进度总览/改派/旧派工端点，计划部职责 |
| 模具主档 | `mould:create/delete/status`、`mould_category:create/delete/move/reorder` | V541 已收回 `mould:edit/mould_category:edit`，只留只读 |
| 僵尸码 | `production_execution:cancel/reverse`、`production_mrp:generate_purchase` | V455 起 `active=false`，挂着只误导目录审计 |

DELETE 同时覆盖 `MFG_CENTER` 与 `WS_*` 子树（当前只挂 `attachment:*`，列出保证任何环境幂等）。

**保留（车间本职，19 码）**：`production_execution:view/start/release_defer`、`production_daily_report:view/create/edit/approve/delete/reverse`（车间负责人审核/红冲本车间日报）、`production_material:settle/reverse/close`（确认用料）、`production_quality_inspection:view`（FQC 送检）、`goods:view`、`material_category:view`、`mould:view`、`mould_category:view`、`attachment:view/download`。完整岗位包见[权限体系总设计 §八](../05-架构/权限体系总设计.md)。

## 2. 页面权限面（permission_surfaces）对齐真实按钮

- **下架停用码**（仅 `production.*` 面）：`production.plan` 的 `production_execution:cancel/reverse`、`production_mrp:generate_purchase`、`production_material_analysis:manage`、`planning_supply_request:view`；`production.hub` / `production.material-analysis` 的 `production_material_analysis:manage`。`PermissionSurfaceRegistry` 本就按 `active=TRUE` 过滤，这些行只影响目录审计与 `PermissionSurfaceCatalogPostgresTest` 的面计数（`production.plan` 执行/包/材料码 12 → 9）。其他模块面上的历史停用码（如 `subcontract.preparation`）有独立契约锁定，不动。
- **补齐 `production.workshop-tasks`**：页面实际渲染「批量开工」与「确认用料/冲销」，V470 建面时只登记了 `production_execution:view` + 日报两码；补 `production_execution:start`、`production_material:settle`、`production_material:reverse`，页面内委派候选与按钮一致（委派仍受中央授权与对象范围约束）。

## 3. `*:view:all` 退出批量授权

9 个活动的 `*:view:all`（client/finance/goods/payroll/production_plan/purchase/sales/stock_doc/subcontract）置 `bulk_assignable=false`，前端 `lib/features/admin/authorize_all_excluded.dart` 同步登记——「全部授权 / 本模块 / 本组」三档不再顺带发放全量对象范围；仍可按部门或逐人显式授予。

## 4. 前端配套（同批次源码）

- 我的车间任务页：「查看生产计划」行菜单/双击只对持 `production_plan:view`（或超管）的人开放，其余人提示「无生产计划查看权限，请用「确认用料/物料使用情况」查看本工单」；历史任务段改为终态集（已完工/已取消/已红冲）+ 时间门控（ADR-066 §1.3），`READY_TO_REPORT` 兼容参数与 `readyToReport` 计数字段端到端删除。
- 生产计划/采购/委外/钱流/仓库/生产日报详情页「返回列表」：只对能进列表路由的人渲染（`route_access_policy.locationAllowedFor`，与守卫同源），并走返回键契约 `popOrBackTo`（路由设计 §十一），删除后同样 pop 回来源。
