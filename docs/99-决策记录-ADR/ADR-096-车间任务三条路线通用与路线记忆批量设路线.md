# ADR-096 车间任务三条路线通用、路线记忆两档、批量设路线与首列锁

- 日期：2026-09-20。
- 状态：已决策(源码候选，本地 PostgreSQL 回归见文末；不代表目标业务库已迁移或服务已部署)。
- 迁移：[V629](../数据迁移/219-V629零料任务三路线与路线记忆.md)。零新增权限码、零新增表、不改任何数据行。
- 关联：ADR-078(分批守恒)、ADR-089(直送在报工时决定)、ADR-091、ADR-093、ADR-095；
  [我的车间任务页](../03-页面/我的车间任务页.md)；[车间任务路线与供料场景矩阵](../07-业务链路/车间任务路线与供料场景矩阵.md)。
- 取代范围：ADR-095 §2.2 的 SHORT_DIRECT 桶与「等同车间直送」文案、§三「无物料子件的工单只有齐套可选」、
  §2.3「路线逐行选定，没有批量入口」；其余决策原样有效。

## 一、问题

用户口径(2026-09-20，ADR-095 交付后的追加)：

1. 「下一步可以有记忆：记住上次的选择，新的可以默认值。」
2. 「加个能够批量选择路线，现在必须得一个一个选。」
3. 「最前面可以锁住：物料不齐就是锁住。」
4. 「无需物料之类的，每种应该都支持三种生产模式。」
5. 「部分物料可领和物料已备齐的颜色还是一样的。」
6. 「物料里面把缺 X 种变红色、可领 X 种变绿色。」
7. 「不要显示直送：生产完可能直送、可能送去仓库，看看对应的业务策略是不是也要修改。」

复核后的事实：

- **零料任务被三处闸门挡在分批之外**：V249 让 ZERO_MATERIAL 任务生来就是 READY，而
  `fn_can_split_execution_batch`(V618)、`fn_guard_execution_split_history`(V561)只认 WAITING 源，
  `execution_split_shape` 约束又要求子任务物料快照非空——零料任务没有物料，快照只能是空数组。
  Java `validateRouteChoice` 因此干脆把零料任务锁在齐套一条路线上。
- **路线记忆只有产品档**：V602 恢复的记忆按同产品最近一次有效确认预填；新产品第一次下达时没有任何预填，
  用户要的是「我上次怎么选的，新的就默认那个」。
- **勾选与路线绑死**：未确认路线的行没有勾选框，批量条只有批量领料/开工，路线只能逐行下拉。
- **颜色**：`toDraw`(去领料·蓝)同时承担「部分物料可领」与「物料已备齐」；`ready`(绿)同时承担
  「部分物料已投·可开工」与「物料已领齐·可开工」。
- **「直送」说早了**：需求上的 `direct_supply` 标记只是持续生产分配时的偏好；开发库里没有任何函数读它决定交接，
  `continuousIncrement` 对每种需求都按仓库可用量分配。子件工单产出到底是线边直送还是入库后领料，
  是子件**报工那一刻**才决定的(ADR-089 直送在报工时勾选)。列表把它写成「等同车间直送」是对未来的承诺。

## 二、决策

### 2.1 每种任务都支持三条路线

零料任务(`material_requirement_mode='ZERO_MATERIAL'`)与有料任务一样可选齐套 / 持续 / 分批：

- `fn_can_split_execution_batch` 与 `fn_guard_execution_split_history` 的源状态条件从
  `status='WAITING'` 放宽为 `status='WAITING' OR (status='READY' AND material_requirement_mode='ZERO_MATERIAL')`
  (V629 以 `pg_get_functiondef` 锚点替换，锚点不在即迁移失败)。其它守恒尺(无预留、无领料、无供给绑定、
  未拆过、分析来源、自动提升)一条不放宽。
- `execution_split_shape`：子任务快照允许空数组，**只对** ZERO_MATERIAL 子任务；有料子任务仍必须非空。
- `ProductionExecutionBatchService`：零料源不做物料切片、不建领料单；子任务复制零料五列
  (`material_requirement_mode/zero_material_reason/zero_material_analysis_id/zero_material_exception_reason/zero_material_authorized_by`)，
  **生来 READY**，快照 `[]`；提交阶段不再对零料源做 READY 提升。
- `validateRouteChoice`：齐套、持续恒可；分批只看 `fn_can_split_execution_batch`。零料任务改持续=随时可开工；
  改分批=按数量拆成两个零料子任务，批次段直接开工，剩余段可继续拆或改齐套开工。

### 2.2 路线记忆两档：产品优先，其次操作者

`suggestedStartRoute` 的来源顺序：

| 档 | 来源 | `suggestedStartRouteSource` | 黄标文案 |
| --- | --- | --- | --- |
| 产品 | 同产品最近一次有效确认(非终态、`route_confirmed_at` 非空；V602) | `PRODUCT` | 已按本产品上次选择的路线预填，请核对 |
| 操作者 | 当前登录人最近一条 `ROUTE_CONFIRMED` 事件所在工单的当前路线 | `OPERATOR` | 已按你上次选择的路线预填，请核对 |
| 无 | — | `null` | 「选择生产路线」空占位 |

操作者档每次分页只点查一次(V629 部分索引 `idx_execution_route_confirmed_by_actor`)，不逐行查；
预填只是展示，**不写任何事实**，选中或批量确认才提交(ADR-093 明确确认口径不变)。记忆只在该路线仍是当前可选项时生效。

### 2.3 批量设路线

- 等待物料分类里，能改路线的行(`canConfirmRoute`)与能领料/开工的行都可勾选；批量条新增「批量设路线(N)」。
- 点开是菜单：`齐套生产(n) / 持续生产(n) / 分批生产(n)` + `按预填默认值确认(m)`。每项括号里是勾选行中
  **支持该路线且当前不是该路线**的行数，为 0 的项禁用；「按预填默认值确认」只算带记忆预填的行。
- 提交逐行携带各自执行段版本，顺序调用既有 `confirmRoute`(不新增端点、不新增权限)；部分失败按行报错并刷新一次。
- 批量开工 / 批量领料的计数与资格不变，仍只算真正可开工 / 可领的行。
- 2026-09-21 追加(用户口径「我明明多选了，选中一个，为什么批量设路线还要重新选」)：**勾选行的「下一步」下拉
  本身就是批量入口**——被改的行已勾选且勾选集里还有别的可设路线行时，一次下拉 = 对全部勾选行提交，筛选与菜单
  同一套(不支持该路线或已是该路线的行自动跳过，被改的行永远在内)；没勾选的行照旧只改自己。悬停说明先讲清
  「本行已勾选：会一并确认全部 N 个勾选行」。此前下拉永远只提交本行，而其余未确认行在刷新后被操作者档路线记忆
  预填成同样的字，看起来像已经批量选了，事实并没有写；「批量设路线(N)」菜单保留为不经过某一行、直接按路线提交
  的第二入口。

### 2.4 首列锁

`MasterDataTableView` 新增 `leadingOverlayBuilder`：可勾选但另有门槛的行，在勾选框右下角压一个小徽记。
车间任务页对「等待物料」分类里**不能开工**的行(未选路线、物料未到齐、已交仓库待发)显示锁，悬停说明原因；
勾选框仍可用(为了批量设路线)。已可开工 / 可领料的行不上锁。生产中与历史任务分类不上锁。

### 2.5 颜色与物料列

- 新增两档：`toDrawPartial`(部分物料可领 · 去领料)=紫(`UtenColors.violet`，新增 `UtenStatusBadgeType.violet`)，
  `readyPartial`(部分物料已投 · 可开工)=品牌青；`toDraw`(物料已备齐 · 去领料)仍蓝，`ready`(物料已领齐 · 可开工)仍绿。
  同一分类里同时出现的七档(待选红 / 等待琥珀 / 部分可领紫 / 已备齐蓝 / 部分已投青 / 领齐绿 / 待发灰)两两不同色相。
- 「物料」列分段着色：`缺 k 种` 红(`error`)、`可领 m 种` 绿(`success`)、`待发 p 种` 次要灰、`已领 a/n 种` 常规。

### 2.6 「自制子件」代替「直送」

- 汇总桶 `SHORT_DIRECT` → `SHORT_MAKE`：缺口且需求 `supply_route='MAKE'`(由自制子件工单供应)，不再看 `direct_supply`。
- 文案：「等自制子件完成 · 缺 k 种」、「缺 k 种(自制子件 j)」、详情来源「自制子件 · 直送或入库领料」，
  到货进展卡缺口标注「(自制子件在产)」。子件真正流转到本任务(直送已交接)或入库后领到车间，才转为已领。
- **业务策略不改**：`direct_supply` 继续只作持续生产分配偏好；交接方式仍在子件报工时决定(ADR-089)。
  本决策只纠正展示口径，不新增「必须直送」或「必须入库」的约束。

### 2.7 三条路线是什么(给车间的一句话)

| 路线 | 一句话 | 开工门槛 | 后续到料 |
| --- | --- | --- | --- |
| 齐套生产 | 料齐了再开工 | 每种物料实领到车间(仓库料领齐、自制子件交接完) | 同一任务继续领；未齐不开工 |
| 持续生产 | 先开工，边到边补 | 每种必需料共同支持正产出(各到一部分即可) | 在同一任务继续领料 / 接收子件，按实际报工推进 |
| 分批生产 | 先拆一批出来做 | 拆出的批次段自己齐套即可开工 | 剩余段继续拆或改齐套 / 持续 |

零料任务：齐套=确认后开工；持续=确认后随时开工；分批=按数量拆成两个零料子任务。

## 三、每一种情况怎么走

| 情况 | 结果 |
| --- | --- |
| 零料 READY 任务改持续 | 允许；`fn_execution_start_material_ready` 为真，立即可开工 |
| 零料 READY 任务改分批、拆 30/100 | 两个零料子任务生来 READY，快照 `[]`，无领料单；批次段齐套可开工；剩余段可再拆或改齐套开工；源任务 CANCELLED |
| 零料任务已开工 | 409「开工后不能更改生产路线」，与有料任务一致 |
| 新产品第一张任务，我上次选过持续 | 预填持续 + 黄标「已按你上次选择的路线预填」；来源 `OPERATOR` |
| 同产品有别的车间有效确认 | 预填按产品，来源 `PRODUCT`；操作者档被产品档覆盖 |
| 别人的确认 / 终态任务的确认 / 无登录身份 | 不构成操作者记忆 |
| 勾选 5 行点「持续生产(3)」 | 只对 3 行(支持持续且当前不是持续)逐行提交；其余 2 行原样；部分失败按行提示后刷新 |
| 勾选带预填的行点「按预填默认值确认(m)」 | 各按自己的预填路线提交；无预填的行不动 |
| 物料未齐 / 未选路线的行 | 首列勾选框角上有锁，悬停说明；仍可勾选批量设路线；批量开工计数不含它 |
| 一种自制子件未完成 | 「等自制子件完成 · 缺 1 种」；物料列「缺 1 种」红；详情来源「自制子件 · 直送或入库领料」 |
| 子件入库后由仓库发料领到车间 | 转为已领，与直送交接同口径 |

## 四、明确不做

| 不做 | 理由 |
| --- | --- |
| 记忆自动确认路线 | 确认是车间的明确决定(ADR-093)；预填只展示，选中/批量确认才写事实 |
| 有料任务已备料后仍允许拆分批 | ADR-078 守恒尺不放宽；本轮只放行**没有物料事实**的零料 READY 源 |
| 锁住的行禁止勾选 | 用户要的是「批量选路线」，锁只说明不能开工，不剥夺勾选 |
| 改 `direct_supply` 的分配语义或新增交接约束 | 交接方式在子件报工时决定，展示不应替业务下结论 |
| 新权限码 | 批量设路线复用逐行确认的端点与 `production_execution:start` |
