# 生产订单排产与执行全链路

本页是生产业务的串联入口，现行规则由分析、计划、执行、品质、仓库和结清各自的真实事实组成。**各层路线和责任数量确认后即可下达；车间必须等直接子件合格实物齐套、完成实际领料后显式开工。已下达不消除本批物理缺口。**

计量、共享供给和来源细节集中在[生产计量与来源守恒](生产计量与来源守恒.md)，报工、品质恢复、实收与反向集中在[生产品质恢复与反向约束](生产品质恢复与反向约束.md)。当前结果和未完成范围只看[统一验收记录](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)及[逐步守恒压力矩阵](../99-项目治理/2026-09-07-生产链逐步守恒与压力测试矩阵.md)，不累加历史专项为整体通过。运营链优先，深入财务最后；本页不表示全项目验收或部署完成。

## 一、主流程与岗位边界

```text
已财审准入销售需求 / 有权手工需求
  → 物料分析保存完整BOM与来源 → 本次确认各层路线
  ├─ MAKE：选择数量、车间、负责人 → 一次issue-plans原子下达
  ├─ BUY：真实来源申请 → 采购商业下单/财审 → 到货/品质/仓库实收
  └─ SUBCONTRACT：有子层先在原树前置自制 → 目标件实际入库后通知委外
                       → 商业财审 → 实际目标件出仓 → 加工回厂/品质/实收
  → 执行层按同主仓允许叶仓完整齐套，原子预留并生成各实际仓DRAW
  → 仓库实际领料 → 负责人显式开工 → 报工审核 → FQC
  → PASS放行待点收 → 仓库实际接受 → 原需求/销售实际完成投影
  → 同源领退耗、在制和成本结清
```

仓库、采购、委外和销售工作台读同一来源的需求、分配及执行事实；卡片不能手改一份待办量。销售拥有订单商业状态，计划拥有路线及生产安排，采购/委外拥有商业订单，财务拥有对应审核，品质拥有结论，仓库拥有实物确认；页面权限不互相代替。

订单修改待财审时，原已准入需求的采购/委外到货、品质、实收继续履约；新增路线/安排/公共在途采用仍核本次产品及父来源准入。不能用一个产品待审冻结另一产品，也不能用子锚点绕过其父订单财审。客户发货仍需财务放行→仓库SHIPPED，收费单随后立正式AR，见[销售SOP](01-销售订货到发货全链路-SOP.md)。

## 二、分析、路线与一次下达

分析可由已准入销售行或有权限的REWORK/TRIAL/SAMPLE/STOCK/OTHER手工需求形成；手工来源使用稳定业务编号和原因，同类型同编号恢复原任务，不重复建需求。MAKE_COMPONENT/SUBCONTRACT_MAKE由系统建立，员工不能手填系统来源冒充已批准链。进入、读取或刷新分析不是创建生产计划，更不是库存移动。

完整树保存analysis item、node、parent/path及BOM依据，主表搜索命中子节点时保留祖先。主档和学习路线只是建议，员工本次确认后才生效，不能因GET恢复记忆自动下达。根产品也需明确路线；路线原因按当前可选合同处理，不恢复旧强制说明门槛。已被委外父件覆盖的子树保留单份需求，不能再生成平行责任。

当前下达车间端点为 `POST /api/production/material-analyses/{id}/issue-plans`：

1. 检查权限、对象范围、分析version/fingerprint、本次真实来源和BOM，数量上限为尚未下达需求；库存齐套不作为计划创建门槛。
2. 同一事务解析根/候选/既有锚点，必要时建立计划锚点或有子层委外台账，再为每个独立分析行建立计划。
3. 未选择approveNow时保留草稿及待批准额度，不写正式执行/预留；具备独立 `production_plan:approve` 并明确选择时同事务审核下达。
4. 批准后根据执行批次实际物料情况形成READY或WAITING；READY才有完整预留和DRAW，WAITING零预留、无DRAW。任何一行失败，当前命令整笔回滚，不能留下只有子锚点没有计划的半套事实。
5. 同键同体回放原planIds，同键异体拒绝。旧失败已留锚点的合法重试按实时剩余增量识别，不再创建重复行。

`plan-preview/generate-plan`旧两段式HTTP合同和单独notify MAKE已退役；不让客户端先建子件再尝试生成计划。底层planning draft/package仍为实际实现构件或历史事实，不能据此恢复计划详情旧MRP“再生成剩余”入口。一个批次可以一次选多行，但当前分析行各自形成独立计划，不因同车间/同货品物理合并计划头。

销售与手工分析来源合计最多500；批量路线/下达按实际接口最终任务集合限额处理，去重后校验。超过上限应在确认前明确分块，每块原子、后块使用最新版本与稳定任务身份；前块已成功不是后块失败可以假装全回滚的理由。忙态、幂等和恢复选择依真实提交结果，不能用通知到达判定成功。

## 三、物料、仓库与执行状态

[计量专题](生产计量与来源守恒.md)定义基本单位、包装/整批、无BOM、父件现货、公共超量及exact的容量口径。关键分离为：可继续下达量、本批物理缺口、尚待安排的供给责任。采购/委外/车间计划减少重复安排责任，却不增加可领物料；待检、PASS未实收同样不增加。

同主仓不同有效叶仓可共同齐套，DRAW按实际叶仓分别生成；主仓不能成为虚构物理库，库存、预留和流水不重标。完整物料合计不足时不抢占零散库存。正式实领沿原树直接领料节点匹配，自制锚点不得借兄弟路径或别的分析专属权益。

| 阶段 | 可执行动作和门槛 |
|---|---|
| 草稿/待批准 | 可维护允许的安排，待批准额度不算正式已排或物理预留。 |
| WAITING | 计划已下达，跟进真实缺料；到料后按完整套料原子提升。人工暂缓须明确解除，不能被自动唤醒绕过。 |
| READY | 完整物料已预留并生成DRAW，仓库可分轮真实发料；不能直接当已开工或可报工。 |
| 可开工 | 全部必需需求实际FULFILLED，负责人明确点击开工。合法无物料层不造空DRAW，仍须显式开工。 |
| IN_PROGRESS | 允许本段报工及实际物料结清；物料、fqty、FQC与iqty分别展示。 |
| 实收达量/待清料 | 实收数量足够仍需处理品质/恢复、待点收、领退耗和其它未决事实。 |
| 完成/取消/反向 | 从实际来源及有效事件判定；不把全部转计划或单段完成当全分析/父计划完成。 |

车间和负责人继承计划明确安排，学习默认不覆盖人工值。组织资格和日期在服务端校验，班组/负责人不能跨不允许的组织路径；学习偏好只从成功且无歧义的实际确认/合法改派更新，失败、草稿、空选择和幂等回放不计。唯一默认车间源仍是 `production_goods_workshop_preferences`。

旧DISPATCHED及AUTO_START_ON_REPORT只解释历史事件。新操作不要求员工重复走旧派工表单，也不允许报工自动开工；未开工隐藏报工入口，服务端同样拒绝。历史WAITING可通过有权限的“重新检查物料”重查，列表GET保持只读，不静默补造旧来源。

## 四、品质、实收与结清

日报审核只增加有效完工贡献并登记每条明细的FQC；品质PASS放行待点收，仓库实际acceptedQty才增加库存和iqty。完成率使用实际iqty，不能用fqty、PASS或待点收草稿替代。短收/整单拒收保留同来源余量，重交不改变原品质；反向必须沿原接受切片。

FAIL使用不可变贡献调整和恢复授权：REWORK复用原在制并再检，SCRAP/REJECT先完成独立恢复补料与实发后再报工/再检。普通剩余不能被恢复待料遮住；多代FAIL、全FAIL反向、已售或已用来源不能通过删除旧记录解决。

材料领用、消耗、退料、损耗、在制分别留证，实际耗用由责任人确认。退料按同一ISSUE尚未结清容量，仓库实收后才改库存；成本由真实材料/加工费来源承接。完整公式、流程和逐项反向矩阵见[品质恢复与反向约束](生产品质恢复与反向约束.md)与[成本专题](../99-项目治理/库存实际成本接线与验收.md)。

有子层委外先自制的是目标件，子件不重复展开/出仓；原需求只在加工后回厂合格实收时取得最终供给。原分析任务与委外直接商业单是两条来源，后者SC-ORDER草稿自动准备、实际叶仓及送审/批准前齐备已接线并通过专项，见[128](../数据迁移/128-V529直接委外草稿准备.md)；采购/委外未用收货撤回的已过范围及限制见[127](../数据迁移/127-V527-V528采购委外收货撤回.md)、[委外SOP](08-委外全链路-订货出仓回仓重设计.md)和统一验收，不能沿用旧“新委外发料一律409”或“批准后才安排生产”的说明。

## 五、页面、权限与一致性

[物料分析页](../03-页面/生产物料分析页.md)承载路线/采购委外/车间安排，[履约工作台](../03-页面/生产履约任务工作台.md)和[我的车间任务](../03-页面/我的车间任务页.md)承载执行；[报工页](../03-页面/生产执行分段与报工页.md)、[FQC任务](../03-页面/生产成品质检任务页.md)、[仓库点收](../03-页面/产成品待点收任务页.md)各自确认真实事实。分析记录与生产计划历史是不同入口，不能混成一份“旧计划”。

页面必须分别显示未下达、已下达/待料、已领用、生产中、品质、待点收和实际实收；“暂不可安排”只读，不显示假勾选框。主表保留实际多选、祖先搜索和合法选择；大树/历史按服务端分页、批量查询和当前公共树表组件处理，不恢复首次全量铺开及按30组硬编码的旧交互。

真实子计划点击进入childPlanId；执行分段从父计划详情定位，跨模块可携 `executionSegmentId`，只打开一个详情。无权用户保留允许的公开进度，不能因深链得到操作权；空ID、失效来源和跳转失败明确反馈。筛选/身份/计划变化后丢弃旧异步响应，刷新保留仍合法的选择和位置。

读取、route、notify、generate、approve、over_supply、claim_shared_future、reallocate及执行/仓库动作分别校验；不硬编码职位或以view代替动作权。销售只看有权订单公开进度，金额/成本/内部质量责任/员工信息在API裁剪。字段校验沿公共框内提示，响应式、主题、键盘、大字和防重复提交遵循组件合同。

写命令使用[共同履约锁序与来源漂移合同](2026-09-07-履约事务锁顺序与来源漂移处理.md)：提前发现并锁本次真实来源、库存和公共在途，按稳定顺序重读版本；成功重放可回原结果，新的写入不能以旧CQRS缓存作为权威。空颜色、全局预留与叶仓比较规则统一，来源竞争返回可行动冲突，禁止用500/静默部分成功掩盖。

主事务保存不可变业务事实及对应Outbox，消费按至少一次幂等处理，反向引用原事件；通知和看板可重建，不能回写主数量。到货唤醒必须由实际实收产生，不因短信/通知送达提升READY。页面显示投影更新时间，缺数据不冒充0；未实测不能承诺固定10秒更新。

审计要解释动作、actor、来源UUID、量前后/变化、版本/幂等和原反向事件，HTTP审计和表级守卫补充而不替代业务证据。附件如接入需使用受控类型/大小、对象权限、扫描/隔离、短期下载和保留策略，不能因已有上传组件宣称生产证据链通过。

## 七、兼容、扩展和验收边界

旧分析/计划/日报/品质/入库按原UUID、快照和明确迁移规则留存。已下线的BOM三策略、bom_override、递归整树自动确认、老计划补建MRP包及自动报工开工不能借feature flag恢复。合法历史适配与无证据补造不同：不重算旧BOM，不给旧WAITING补猜来源，不批量激活旧订单或造预留，不把老多来源合并单任意分给一个订单。

正式迁移、旧数据分类、备份恢复和安装步骤见[迁移索引](../数据迁移/README.md)；已应用字节不改，修正向前新增。旧文的数据库计数、当前头、历史测试和“NO-GO门槛全部关闭写功能”等重复过程说明不再作为日常操作规则；实际未闭环场景仍需在统一验收明确阻断，不能用文档更新当代码修复。

以下保留为扩展约束，不能冒充现有完整能力：

- **替代料/完整BOM版本**：需主料/替代组/比例/优先级、产品颜色及质量范围、生效区间和必要批准依据，选择冻结后才影响领料；不能任意挑同类货品，也不能用改路线代替换料审批。
- **有限产能/冻结日程**：标准工时=`数量×单位工时+准备工时`，日可用工时=`班次×效率−停机−已冻结负荷`。没有可靠日历/工艺不显示假精确日期或负荷率，不把goods.daily_capacity当完整APS。跨日不复制计划，插单/冻结调整需受影响清单、原因和合法版本，不能抢已领料。
- **仓库波次/双方交接/批次扫码**：可按仓、车间、交接时间窗和兼容物料合并动作，但保留各来源的实拣/实交量。移到暂存区不等于实领或实耗；FIFO/FEFO、效期、跳批批准及双向差异须有实际台账。当前DRAW/issue不自动证明完整WMS已实现。
- **主动补货与SLA**：交接截止由计划开工减接料/转运提前量，拣配截止再减备料提前量；缺数据标未定，不自动当不紧急。补货库存位置=`当前可支配量+周期内未分配可信供给`，再订货点=`提前期预测需求+安全库存`；MOQ/包装超量归公共供给。阈值回滞/稳定时窗、状态变更去重和逾期升级需独立实现/验收，不把低库存提示直接变采购单。
- **工时、计件、OEE与质量附件**：无人员参与、时间、计件规则、扫描和证据生命周期就不计算工资/OEE或标完整质量管理；负责人、fqty和iqty都不是工资依据。额外领料/质量处置只能沿已有允许入口，不因规格提到审批链就虚构新层级。
