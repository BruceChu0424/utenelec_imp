> 路由：`/employee/:id`（计划：`lib/features/employee/pages/employee_detail_page.dart`）· Phase 2
> 上层：[Phase2-人事端总览](Phase2-人事端总览.md) · 前置：[员工列表页](员工列表页.md)
> 最后更新：2026-07-23 · v3 — Hero 后插入「待我审核的修改申请」区块

## 一、定位

hr 查看单个员工完整档案 + 发起调岗/离职，也是桌面 [员工列表页](员工列表页.md) master-detail 的右栏内容。

## 二、入口与导航

- 进入：员工列表点行；入职/调岗完成后跳入。
- 位置：业务详情子页。
- 离开：编辑 → [员工编辑页](员工编辑页.md)；发起离职 → [离职流程页](离职流程页.md)。

## 三、响应式布局

- compact（手机）：单列滚动，Hero 卡 + 信息分组卡 + 任职时间线 + 底部操作栏。
- medium / expanded：桌面作为 master-detail 右栏；独立打开时内容居中 ≤720dp。

## 四、涉及的 Uten 组件

`UtenAppBar`（操作菜单）/ `UtenCard` / `UtenInfoRow`（isImportant 高亮关键字段）/ `UtenStatusBadge`（状态）/ `UtenTimeline`（任职记录）/ `UtenSectionHeader` / `UtenBottomActionBar`（调岗/离职）/ `UtenEmpty` / `UtenSkeleton`。

## 五、功能点

1. **Hero 卡**：头像（无图用 `Icons.person`）+ 姓名 + 状态徽章 + 工号/部门/岗位 + 入职日期。
2. **信息分组**（`UtenSectionHeader` + `UtenInfoRow`）：基本信息 / 联系信息 / 组织信息 / 薪资信息。
3. **敏感字段脱敏 + 可见性**：手机 `138****1234`、身份证 `****`、银行账号 `****1234`；**薪资信息整组仅 `hr`+`admin` 可见**，`manager` 只读不渲染该组。
4. **任职记录**：`UtenTimeline` 展示 `EmploymentHistory`（入职/调岗/离职），按时间倒序。
5. **操作菜单**（AppBar ⋯，按权限点+状态条件显隐）：
   - `employee:edit`：编辑、调岗（对话框：调入部门/岗位+生效日期+备注）、转正（仅试用）、办理离职（非离职）、复职（仅离职）。
   - `employee:delete`：删除档案（二次确认，软删+停用账号+吊销令牌）。
   - 无权限：只读，无操作。
6. **账号状态行**：组织信息区显示登录账号状态（正常/锁定/停用/未开通），离职冻结后可直接确认。
7. **到期预警横幅**：试用期/劳动合同 30 天内到期或已过期时顶部橙色醒目提示（离职员工不提示）。
8. **任职记录**：含备注（离职原因/调岗说明/复职），按时间倒序。
9. `AsyncValue.when` 三态。

## 七、涉及的数据实体
`Employee`（全字段）/ `Department` / `Position` / `EmploymentHistory` / `Role`（控制薪资可见）。

## 八、权限要求
- 可见：hr / manager（只读，无薪资）/ admin。
- 数据范围：hr 看全员，manager 跟随视角只读；后端校验员工 ID 越权访问。
- 操作权限点：`employee:edit`（编辑/调岗）、`employee:delete`（标记离职）、`profile:review`（查看该员工的待审修改申请）。

## 八·附录：「待我审的修改申请」区块

**位置**：Hero 卡后、基本信息前。
**实现源**：[lib/features/employee/widgets/profile_change_pending_section.dart](../../lib/features/employee/widgets/profile_change_pending_section.dart)
**显示条件**（必须全部满足）：
1. 当前用户有 `profile:review` 权限
2. 该员工有至少 1 条 `pending` 状态的 `profile_change_request`

**布局**：
- 顶栏：⚠ 红图标 + 「待我审核的修改申请」标题 + 右上角红色徽章「N 项待审」
- 主体：最多展示 3 条 pending（提交时间 + 字段数 + 员工姓名 + 跳详情）
- 超出 3 条：底部「全部 →（N）」按钮跳 `/hr/profile-changes?employeeId=...`

**点击行**：跳 `/hr/profile-changes/:batchId`（HR 审批详情）

## 九、边界情况
- 无数据：`UtenEmpty`「员工不存在」。
- 加载失败：`UtenEmpty.error` + 重试。
- 性能档 lite：Hero 去 boxShadow，时间线去连线动画。
- 离职员工：状态徽章灰色，操作栏只留「重新入职」入口。
- 网络：详情缓存上次结果离线查看；调岗/离职需在线（排队，见全局机制 §4）。
