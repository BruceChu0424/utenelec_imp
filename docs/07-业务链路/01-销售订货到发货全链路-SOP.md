# 业务链 SOP：销售订货 → 生产 → 仓库发货 全链路

> **文档性质**：流程设计稿（待评审落地）
> **Owner**：综合营销部 + 生产部 + PMC 运营部 | **创建日期**：2026-07-28 | **评审节奏**：落地前每轮迭代评审
> **来源**：老板口述业务链原稿（2026-07-28），本文档在原稿基础上做了 **6 处纠正 + 9 处补充**，并对照现有系统能力给出落地映射。

## 一、原稿里设计得对、直接保留的部分

这些点和系统现有能力完全一致或方向正确，不用改：

1. **以销售订货单为唯一起点**，全链路状态自动流转、可追溯 —— 方向正确。
2. **库存不足不阻止下单**（缺货转生产）—— 正确，符合接单优先的制造业实际。
3. **可用库存 = 账面库存 − 已预留**，防超卖 —— 思路正确（但落地机制要新建，见纠正 4）。
4. **部分现货 + 部分生产**的混合拆行处理 —— 正确，不要整单二选一。
5. **多订单同产品合并生产**（100 + 50 = 150 一次投产）—— 正确，减少换线。
6. **分批报工、分批入库、分批发货** —— 正确。
7. **客户选择只能选自己名下客户 + 搜索框**（原稿第 2 条）—— 已实现：`clients.owner_employee_id` + `client:view:all` 权限点 + 服务端行级过滤（V86，见 [36-客户归属授权](../数据迁移/36-客户归属授权-按业务员.md)）。建单页直接复用该客户选择器，搜索走 facets 接口；持 `client:view:all` 的销售主管可选全部客户。
8. **出货数量不能超可发货数量**、同客户多订单合并一张出货单 —— 正确。
9. **导出沿用现有安全规范** —— 已实现：UtenExportButton（POI SXSSF + OOXML Agile AES-256 + 审计 + 频率限制）。
10. **操作留痕时间线** —— 复用 `audit_log`（在线默认 6 个月、可调 1–120 月；随后冷归档默认追加
    30 个月、可调 0–240 月），订单详情时间线直接读在线审计流，不需要另建表；超出在线期的调查走受控
    冷归档流程，不能让普通业务页直接查询归档表。
11. **权限隔离**（销售只看自己的单、生产看不到价格、仓库看不到订单金额）—— 沿用现有权限点体系即可。

## 二、需要纠正的 6 个点

### 纠正 1：订单生效必须挂到现有「审核状态机」上，不要另起"提交即自动校验"

原稿说"提交瞬间系统自动完成校验和初始化"。现有系统所有业务单据统一走 **草稿 → 提交 → 审核（approve/reverse + PESSIMISTIC_WRITE 行锁）**，红冲、驳回、并发拒绝（"状态已变"）全套机制都是现成的（见 [37 §三](../数据迁移/37-业务联动-MRP与并发加固.md)）。

**正确做法**：订货单保持 `草稿 → 已提交 → 已审核` 三态；**库存检查 + 软预留挂在"审核通过"这个动作上**。如果想体验上"提交即生效"，把订货单的审核配置成**自动审核**（提交后服务端同事务内完成审核+预留），而不是绕开状态机。否则这条业务链要单独造一套并发和回滚机制，必然后患无穷。

### 纠正 2：不要新造"生产任务单"，合并进已有「生产计划单 + MRP-lite」

现有 **生产计划单** 已支持一键生成采购申请 / 领料单 / 成品入库单（MRP-lite，V87/V88 联动表防重复）。原稿的"生产任务单"是同一个东西。

**正确做法**：生产计划单增加 `plan_order_links` 关联表（计划单 × 销售订单明细行，**多对多**）：
- 一张计划单可合并多个订单的同一产品（合并生产）；
- 一个订单行可拆到多张计划单（分批排产）；
- 排产量 / 报工量 / 入库量沿关联表回写到订单行，驱动订单行状态机。

### 纠正 3：原稿只算了成品库存，漏了原材料 —— 排产前必须过 BOM 物料检查

原稿通篇只考虑"成品够不够"，但制造业真正卡单的往往是**物料**。排产（审核生产计划单）时必须 BOM 展开（`goods_bom_items` 已有 19.8 万行 BOM 数据）：
- 物料够 → 自动生成**领料单**（MRP-lite 已具备）；
- 物料不够 → 按净需求（BOM 展开 − 库存 − 在途）自动生成**采购申请**；
- 订单行相应出现 **`待物料`** 状态，缺料未解决前不该显示"生产中"。

这是原稿最大的盲区：只打通"销售↔生产↔仓库"，没把**采购**拉进链里，缺料时照样卡单、照样要人去催。

### 纠正 4：库存"软预留"是全新机制，需要一张预留台账表

当前库存体系是**流水 + 余额**，没有预留概念（即时库存只有数量/重量/成本金额/多排余量）。原稿反复依赖"软预留"，必须新建：

`stock_reservations`（订单行 ID × 货品 × 仓库 × 预留数量 × 状态[生效/部分释放/已释放]），并定义：

- **可用库存 = 账面库存 − 生效中预留**，全系统统一这一个口径（下单校验、排产、出货校验都读它）；
- 预留的创建 / 部分释放 / 全量释放发生在：订货审核、报工入库、出库确认、出货驳回、订单改量、订单取消 —— 每个节点都必须对称维护，漏一个就会库存漂移；
- 并发占用同一批货：走现有行锁方案，后到者拿明确的"可用库存不足"拒绝，不做隐式排队。

### 纠正 5：不良品补产要走状态机，不能只发通知

原稿"差的 30 个自动生成补产任务单 + 通知销售"——通知只是旁路。**正确做法**：补产单就是一张新的生产计划单（`source = 补产`，关联原计划单和订单行），继续走排产→报工→入库→预留的同一套状态机，销售在订单行上能看到"已合格 120 / 补产中 30"的完整构成，而不是靠一条通知记住这件事。

### 纠正 6：取消流程的方向要分两种，原稿写反了一半

原稿只写了"调度发起生产取消申请 → 销售确认"。实际上有两类取消，发起方不同：

| 类型 | 发起方 | 确认方 | 说明 |
|---|---|---|---|
| **取消订单** | 销售（客户要取消） | 生产部（已排产/生产中时） | 原稿漏了这条主路径 |
| **取消生产计划** | 调度（生产不了/合并调整） | 销售 | 原稿写的这条 |

两类取消共用同一套"确认 + 库存/预留释放 + 已产成品入通用库存"逻辑，但入口和通知方向相反。

## 三、原稿漏掉的 9 个环节（补充）

1. **报价 → 订货**：报价单已有模块。订货单应支持"从报价单转入"，价格留痕可比对，避免报价一个价、下单另一个价。
2. **钱流闭环（应收）**：出货单审核 → `ar_ap_ledger` **应收立帐**（枢纽表已有）→ 销售收款 → 订单财务状态（未收/部分收/已收齐）。业务链不在"发货"结束，在"钱收回来"结束。订单上应能看发货金额 vs 已收金额。
3. **退货闭环**：客户收货后退货走已有**销售退货单** → 入库 → 红冲应收。注意：退货入库的货**不加回该订单的可发货数量**（订单已发完的部分是既成事实），入通用库存；只有"已发货数量 < 订货数量"的未发部分才允许取消。
4. **通知中心是前置依赖**：全链 8 类自动通知（排产/完工/部分完工/数量不足/发货/驳回/延期预警/取消确认）都依赖通知模块，但通知**后端还没接**（Phase 2+ 待开始）。这条业务链落地前必须先把通知发布的后端做了，否则所有"自动通知"都是空话。
5. **延期预警是定时任务，不是事件**：交货日期 −3 天且未发完的标红预警，需要一个每日扫描任务（对比当前日期与订单交货期），不是某个操作触发的。
6. **出货仓库的选择与多仓**：原稿说"填出货仓库"，预留就要**带仓库维度**（纠正 4 的表已含），否则 A 仓预留的货从 B 仓出，账就乱了。
7. **物流信息结构**：一张出货单一个物流单号够用，但**分多次部分发货**会产生多张出货单多个单号，订单详情要聚合展示全部物流单号，不能只存一个。
8. **价格对生产/仓库的脱敏**：原稿提了原则，落地时用现有"按权限点脱敏"机制（V30 已有先例 `employee:pii:view`），定义 `salesorder:price:view` 权限点，生产/仓库角色默认不授予。
9. **主管视角**：原稿只写了业务员视角。销售主管（持 `sales:view:all`，V91 已落地）需要全团队的订单看板 + 异常订单（延期/缺料/驳回）列表；生产主管需要跨调度的负荷视图。

## 四、完整流程（纠正合并后）

### Purpose
以销售订货单为唯一起点，打通销售、生产（含物料）、PMC 仓库、财税四个环节，状态自动流转、通知自动推送、数据自动同步，全链路可追溯，不超卖、不漏单、不卡单。

### Scope
- **含**：报价转入、订货、库存预留、排产（含合并）、物料检查与采购联动、报工入库、出货（单开/批量/部分发货）、出库、应收立帐、收款、退货、改量、取消、延期预警。
- **不含**：委外生产（已有独立委外模块，后续可作为生产的一种来源接入）、品质检验环节（建议后续在入库前加质检节点，本期可人工把控）。

### RACI 矩阵

| 环节 | Responsible（执行） | Accountable（负责） | Consulted（会商） | Informed（知会） |
|---|---|---|---|---|
| 报价 / 订货建单 | 业务员 | 销售主管 | 客户 | — |
| 订单审核（库存检查+预留） | 系统（自动审核） | 销售主管 | PMC | 生产调度 |
| 排产 / 合并生产 / 物料检查 | 生产调度 | 生产主管 | PMC（物料）、采购 | 业务员 |
| 领料 / 生产报工 | 车间生产负责人 | 生产主管 | — | 调度、业务员 |
| 出货开单 | 业务员 | 销售主管 | 客户 | 仓库管理员 |
| 备货 / 出库 / 驳回 | 仓库管理员 | PMC 主管 | — | 业务员 |
| 应收立帐 / 收款 | 财务（财税部） | 财务主管 | 业务员 | 销售主管 |
| 改量 / 取消 / 退货 | 业务员发起 | 销售主管 + 生产主管（分段确认） | 客户 | 全链相关人 |

### 流程图

```
[报价单] ──转入──▶ [订货单·草稿] ──提交──▶ [审核(可自动): 逐行查可用库存+软预留]
                                              │
                    ┌─── 现货够：行→可发货 ◀──┤
                    │                         └─── 不够：能留多少留多少，差额行→待排产
                    │                                       │
                    │                              [生产计划单(可多订单合并)]
                    │                                 │ BOM 物料检查
                    │                          ┌──────┴──────┐
                    │                       物料够          缺料
                    │                          │              │
                    │                       [领料单]      [采购申请]→等料(行:待物料)
                    │                          │              │
                    │                          ▼              ▼
                    │                       [报工(分批)] ◀──┘
                    │                          │ 合格数入库
                    │                          ▼
                    │              [成品入库单] → 库存↑ + 自动补预留
                    │                          │ (不良缺额→补产计划单, 同状态机)
                    └────────── 行数量齐了：行→可发货 ◀┘
                                   │
              [出货单: 单订单开 / 批量开(同客户合并, 可部分数量)]
                                   │
                    ┌── 驳回(货损/找不到): 释放预留 → 重走库存检查/生产
                    ▼
              [仓库确认出库+物流单号] → 销售出库单扣库存、释放预留
                                   │
                    ┌── 部分发货：行→部分发货，余量继续等
                    ▼
              全行发完：订单→已完成 ──▶ [应收立帐(ar_ap_ledger)] → [收款] → 财务闭环
                                   │
                                   └── 售后: [退货单]→入库+红冲应收(不入回可发货)
```

### 订单行状态机（全链最小粒度）

`待审核 → 部分预留/待排产 → 待物料(可选) → 已排产 → 生产中 → 部分完工 → 可发货 → 部分发货 → 已发货`
旁路：`已取消`（分段取消）、`已驳回重置`。

订单整单状态由行状态聚合：全行已发货 → `已完成`；任一行生产中 → `生产中`；以此类推。

## 五、异常与边界场景

| 场景 | 处理 |
|---|---|
| 改数量 · 未排产 | 直接改：增量重走库存检查+预留/生产，减量自动释放预留 |
| 改数量 · 已排产/生产中 | 需生产部确认（防止打乱在产计划），确认后同上 |
| 改数量 · 已部分发货 | 已发数量是下限，订货量不能改到比已发还少 |
| 取消 · 未排产 | 直接取消，释放预留，通知生产不用排 |
| 取消 · 生产中 | 销售发起 → 生产确认；已产成品释放入通用库存 |
| 取消 · 已部分发货 | 不能整单取消，只能取消未发货部分 |
| 生产取消（调度发起） | 调度发起 → 销售确认；订单行回到待排产 |
| 不良品缺额 | 自动生成补产计划单（关联原计划），销售与客户谈分批发还是等齐 |
| 仓库驳回出货单（货损/丢失/找不到） | 释放该批预留 → 差额重走库存检查/生产 → 通知销售 |
| 发货超量 | 服务端硬校验：本次数量 ≤ 可发货数量，超了直接拒绝（不靠前端提示） |
| 并发占库存 | 行锁 + 统一可用库存口径，后到者明确拒绝，不超卖 |
| 交货前 3 天未完 | 每日定时扫描 → 订单标红 + 通知生产负责人和业务员 |
| 客户退货 | 销售退货单 → 入库 → 红冲应收；不回加可发货数量 |

## 六、衡量指标

| 指标 | 目标 | 口径 |
|---|---|---|
| 超卖事故 | 0 | 发货数 > 实际可用 的次数 |
| 订单准交率 | ≥ 95% | 按交货日期发完的订单占比 |
| 接单 → 排产响应 | ≤ 1 个工作日 | 审核通过到首次排产 |
| 缺料卡单次数 | 逐月下降 | 进入"待物料"的行数 |
| 延期预警处理率 | 100% | 标红订单 24h 内有动作 |
| 下单 → 发货总时长 | 按产品线定基线 | 订单审核到全部出库 |
