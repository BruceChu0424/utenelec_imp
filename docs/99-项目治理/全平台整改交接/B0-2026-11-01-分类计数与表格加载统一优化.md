# 分类计数与表格加载统一优化

本轮从 `bd7e8525b` 开始，分支 `uimp/category-table-loading-20261101`。修改分类：前端读取编排、计数快照生命周期与跨语言传输资源调度。Web 与现有 Flutter 桌面沿用同一 Dart 实现；WPF 候选同步公共读取调度。采用 `frontend-design`，保留 Uten 主题、字号、布局、分类含义和未知计数显示规则。

## 原因及公共实现

| 既有路径 | 问题与正确能力 | 本轮处理 |
|---|---|---|
| 全站父级徽章汇总 | 登录后统一预读并保留；已有服务端权威事实与身份保护 | 保留，不把父级合计拆成不同业务/仓库口径的子计数 |
| 单据状态分类公共 Provider | 页面离开即释放；首帧订阅和 post-frame 作废可重复读取；分页/排序又作废同一聚合 | 共用短期保留入口，空闲 60 秒释放；15 秒内同范围分类切换复用；主动刷新强制重读，本端写修订和读取身份变化自动作废 |
| 仓库选定范围汇总 | 短期离开丢快照；同时监听全站值与成功读取修订，可额外重读 | 共用保留机制；只跟成功读取修订推进；保留精确仓库 family，给快照附身份/权限/API/读范围证明，旧证明与确认拒绝均不显示 |
| 运营/委外工作台 | 首次分类计数依赖列表/分页窗口一起返回；已有独立 overview API | 复用公共有界分类读取器，在允许的相同概览口径下独立预读；迟到概览不能覆盖更新的表格汇总；专属 exception 过滤仍取列表权威统计 |
| 表格、计数和辅助 GET | 同时发出的 facets/lookup/dict 可挤占前台连接 | 所有现行 Dart API 读取共用优先调度：最多 6 个普通读取，辅助最多占 2 个。认证先冻结身份；只有真正等待的读取才额外重验，即时读取不增加凭据存储往返；写入和流式/字节下载保留原路径 |
| WPF 托管 TLS | 已有 8 连接上限；辅助请求没有独立预算 | 保留既有 8 连接预算，辅助最多占 2 个；等待仍消费原取消/超时令牌，不绕过会话、来源、HTTP framing 或 read proof |
| 财务列表、生产领料计数 | 财务刷新 Future 等待辅助 facets；领料计数缺少精确迟到范围检查 | 财务列表独立完成；领料计数增加身份、仓库和请求代次围栏 |

公共入口和完整源码消费者清单见 [coverage.json](evidence/category-loading-20261101/coverage.json)，可用 `python tool/audit_category_loading.py --write` 重建。源码枚举是接入清单，运行验收以以下实际记录为准。

## 保留的业务差异

- 权威计算与 SQL 未改：`ACTIONABLE_*`、`RESPONSIBLE_*`、中性浏览数、独立填写草稿继续使用原投影。默认仓库、选择仓库、出货类型、库存单据类型等仍是不同范围。
- 表格始终使用原服务端列表查询、分页、排序、历史时间和筛选条件；没有把旧列表放入全局缓存，没有截断数据或改变 totals/facets。
- 已有全站事实型子分类继续复用原事实 Provider。独立 IQC、品质结果、短交等计数仍使用原独立请求及其代次保护，通过公共传输入口改善调度。主动刷新不能借用旧的在途读取。
- 工作台独立 overview 仅在当前统计不需要专属 exception 切片时使用；有差异时不强并统计。概览缓存按完整仓库包装仓库实例、部门、关键字及读取/写修订隔离，最多 64 份。
- WPF 业务页面尚未迁移的条目继续保持台账原状态。原生公共传输验证不能代表完整 ERP 或 Win7 真机业务验收。

## 测量与验证

| 安静环境的同基线对照 | 优化前 | 优化后 |
|---|---:|---:|
| 受控 HTTP：50 行表格完成时间中位数，4 对样本 | 176.817ms | 18.260ms |
| 同场景分类计数完成时间中位数 | 176.668ms | 18.205ms |
| 22 个真实列表测试的首次构造/数据呈现中位数 | 236.197ms | 211.938ms |
| 20 类使用公共单据分类计数的首次请求合计 | 40 次 | 20 次 |

22 页的非空首屏均在首个推进的测试帧呈现；其中销售订货统计、采购申请使用其原有专属入口，不计入 20 类状态计数。框架首次冷启动的最大值仍记录在原始 JSON 中，不把它或混合页面样本解释成每页固定提速比例。请求数减半不是耗时必然减半。

验证结果：333 项公共网络/徽章/分类/工作台/仓库/生产回归全过，22 项真实列表首屏对照全过，17 项服务端契约测试全过；私有 PostgreSQL fixture 记录了 233 次实际 Spring 查询/摘要请求。WPF x86/x64 公共门及既有完整 runner 全过，全部修改及新增 Dart 源静态分析零问题。

真实 Chrome 另以 `dart compile js tool/category_read_web_contract.dart -o build/category-web-contract/contract.js` 和 `node tool/run_category_read_web_contract.mjs` 执行同一生产调度器：辅助并发、精确仓库查询、前台优先、排队取消、身份退役五项通过，0 次公司业务请求。原 `flutter test --platform chrome` 在用例启动前被本机 CanvasKit 404 和模块初始化异常阻断；保留诊断与失败，没有修改共享 SDK，也没有把独立浏览器合同说成完整 Web 页面验收。

可审查结果：[最终摘要](evidence/category-loading-20261101/validation-summary.json)、[HTTP 对照原始值](evidence/category-loading-20261101/http-quiet.json)、[基线 22 页](evidence/category-loading-20261101/pages-before-quiet.json)、[候选 22 页](evidence/category-loading-20261101/pages-after-quiet.json)、[实际 PostgreSQL 查询](evidence/category-loading-20261101/postgres-real-query-timings.json)、[浏览器合同](evidence/category-loading-20261101/browser-contract.json)。

最终测量、回归摘要和源码摘要保存在本目录的 `evidence/category-loading-20261101/`。区分三类耗时：

1. 真实 loopback HTTP：6 条连接、8 个 150ms 的慢辅助接口、50 行 JSON，同一进程交替运行原调度与新调度。测量请求排队、传输、JSON 完成；属于受控争用场景，不是公司服务器延迟。辅助请求完成得更晚属于让出前台资源的取舍，原始 `allReadsMs` 一并保留。
2. 22 个真实 Flutter 单据列表构造与首屏：销售 5 类、采购 4 类、财务 5 类、仓库现行 8 类，使用隔离非空 DTO 与相同测试源，基线和候选分别运行。记录实际 Stopwatch 首屏、帧步数、分类请求次数。测试绑定不提供真实光栅/WAN 耗时；编译和首个框架冷启动不能外推日常体验。
3. 实际 PostgreSQL 服务端：既有完整迁移私有数据库、真实 security/controller/query/JSON 链，通过 `UTEN_RUN_DB_TESTS=true UTEN_MEASURE_CATEGORY_READS=true` 启用原徽章对账测试的可选耗时采集。MockMvc 不含 WAN/TLS/浏览器；只记路径、状态与耗时，不记身份、查询参数、响应内容或凭据。

333 项命令包括 `test/core/network`、`test/shared/badges`、公共分类缓存与状态计数、页面加载壳、仓库范围/草稿/盘点导航、采购/委外工作台范围与加载、生产计划/报表/看板辅助加载；精确 suite 源文件保存在测试与候选源码摘要中。原始运行日志在本工作树 `build/category-*.log`。

早先失败不改写成通过：最初漏声明 Riverpod scoped dependency、测试编译问题、短交重读语义回归、外部测试容器缓存计时器未在框架验收前回收、候选依赖未恢复及工作区库存漂移均保留原始日志；逐项修复或恢复原行为后重跑。Win7 清单的广泛源码指纹刷新包含原库存的 CRLF/LF 差异，未借此改变其他任务的 ID、状态、DoD 或业务源码。

本轮不推送、不部署、不激活、不生成正式客户端双包，不更改公司业务数据库或共享 SDK。现网效果仍需从同一审核源码部署后复测，不能将本机夹具数据表述为现网提速。
