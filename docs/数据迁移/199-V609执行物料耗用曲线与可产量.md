# V609 执行物料耗用曲线与可产量

日期：2026-09-19。此页描述源码迁移候选，是否安装以目标库 Flyway 历史为准。

原持续生产用 `实领量 / per_product_qty` 计算可报量。`per_product_qty` 对整包/固定批次可能只是整单平均值，
无法证明部分产量的实际耗用；原计算还只约束直送子件，漏掉分批仓库物料。

迁移增加 `production_material_demands.consumption_snapshot JSONB`，新原始执行需求在批准事务中冻结产品换算率
及各条 BOM 耗用规则，生成正式预留前验证整单需要与曲线完全一致。非空曲线不可改，已有领料/报工后禁止补造曲线。
不新增业务表，不删除和回填历史需求，不重写库存、成本和报工账。

共享函数：

| 函数 | 口径 |
|---|---|
| `fn_material_snapshot_required(snapshot, output)` | 逐条 PER_UNIT / PER_PACKAGE / FIXED_BATCH 算需要，各条向上保足4位后相加 |
| `fn_demand_material_output_capacity(demand, available)` | 在计划量内求满足冻结需要的最大4位产量；非线性使用单调二分，不遍历数量 |
| `fn_execution_material_output_capacity(segment, issuedOnly)` | 所有必需材料共同支持的最小产量；开工和报工只用实际投入模式 |

实际投入 = 已实发 − 已退 − 待退申请占用 − 已核定损耗 − 在制转出。已经确认的正常耗用仍属于累计产量的投入证据，
不再次扣掉。备料模式只计本需求有效正式预留（包含已消费部分），不把公共自由库存冒充本单权益。

净投入由 `fn_execution_material_net_issued_qty` 统一按需求UUID点查；新增领退料账 `demand_id,posting_type`
覆盖索引，开工与报工热路径不为每个任务重新聚合全历史领退料账。通知的本次实收权益点查索引在V611。

历史兼容：旧 LINEAR 按冻结单耗继续计算；旧 EXACT_SNAPSHOT 缺完整曲线时只有全部冻结需求足额才认可整单产量。
不能从现在的 BOM 猜回旧规则。V561 独立分批仍保留原累计区间/共享前批材料合同。

验证：`ExecutionMaterialCapacityPostgresTest` 使用真实 PostgreSQL，覆盖整包临界点、固定批次、单位换算、
重复物料路径合计、小数向上保足和非法规则拒绝；执行链以 `ProductionExecutionRouteGateEndToEndTest` 为准。
升级应先备份并在克隆库演练；不建议删除新列或回退已写曲线。回退应用前必须停止新增持续任务并评估已有部分实领任务。
