# 订单交付方式表头可见性修复

## 问题与根因

用户通过项目 `flutter run` 打开销售订单编辑页，表头显示 `10/15`，看不到交付配置入口。主线已有订单交付模型、交付列及配置浮窗，但 `platform_table_registry.dart` 的销售明细默认可见列清单没有 `deliveryPlan`。实际应用启用了 `PlatformTableCatalogScope`，公共表格因此再次隐藏该列；仅测试独立配置窗口不能发现这个组合问题。

同一表格注册覆盖新建、编辑、订单详情及经理/财务审单明细。修改历史使用独立表格，不存在这个隐藏问题。财务待确认订单任务列表虽复用表格 key，但使用独立类型及显示作用域，不应增加交付列。

## 实现

- 销售默认可见列由 `sales_document_layout.dart` 提供，订单在数量后加入交付方式；报价保持原有字段。
- `sales.docEdit.gridColumns` 的 `order` 桶及 `sales.order.items` 平台布局共同调用一次性版本迁移。v0 只将交付列放到数量之后并解除该列的错误隐藏，保留其他字段的相对顺序、隐藏、固定、宽度、自定义列及原有排序信息。空顺序仍使用完整默认清单。
- 首次设置和升级后的布局使用版本 1。用户此后主动隐藏或移动交付列，重开时保留其选择；不采用强制可见或全局清空表头设置。
- 迁移沿用当前偏好读取、保存、身份隔离和同步入口，不写销售订单、工程 BOM 或库存。

本次是前端呈现修复，Web 与 Flutter 桌面共用上述实现，没有后端、数据库或业务数量契约变更。WPF 尚未实现的交付业务入口仍属于未迁移范围，本次不改变支持状态。界面遵循 `frontend-design`，保留 Uten 表格、主题、交付浮窗及原有异步加载能力。
