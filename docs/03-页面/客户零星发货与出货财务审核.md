# 客户零星发货与出货财务审核

本轮 V511 候选；本地专项结果见[迁移与验收记录](../数据迁移/125-V511客户零星发货统一流程.md)，最终平台验收及上线由统筹执行。

## 页面与操作

销售的 `/sales/customer-shipments` 使用统一销售表格和详情，新增入口为 `/sales/customer-shipments/new`。必须指定真实客户、仓库、用途，并人工选择“收费/不收费”。免费时不再要求填写单价、币种、汇率或结账方式，免费原因须交销售及财务核对。新建真实内部领用应使用仓库内部单据，不能客户留空伪装内部发货。

草稿保存后由“销售确认并提交财务”送审。财务仍在原“出货财务审核”办理，不增加收件台；卡片徽章和财务总徽章使用真实待审任务计数，已读通知不等于办结。

2026-09-12 职责分离改版（对齐订货审批任务中心 / 销售订单财务审核页范式）：

- 财务工作台 `/finance/sales-shipment-audits` 支持多选 + 批量放行 / 批量退回（整批同事务，任一项 revision/哈希/认领失配或客户未分类即整体回滚），双击或行菜单“打开审核详情”进入专用审核页 `/finance/sales-shipment-audits/:id`；行菜单另有“查看销售出货单”跳共享只读详情。
- 审核详情页为财务专用视图：状态条 + 客户财务快照卡（货款类型/结账方式/应收未收/铺底额/超出铺底/可用预收；客户未分类阻断放行并可跳客户资料）+ 上次审核→本次修改清单 + 只读明细与附件；右下悬浮操作组：退回销售（必填原因，红）/ 确认放行 / 返回。认领（SALES_SHIPMENT_FINANCE_AUDIT）进入页面即建立，提交前复检 lease、修订与内容哈希。
- 销售端出货详情 `/sales/shipments/:id` 不再出现任何财审按钮：顶部状态横幅显示 正在等待财务审核 / 财务已退回（含原因）/ 财务已放行 / 仓库作业中；销售只看到 编辑 / 取消（原“删除”，仅措辞按用户口径调整，行为不变删除草稿）与 提交财务。仓库作业按钮仍按 `sales_shipment:warehouse-work` 在共享详情开放。

财务退回须填写原因。销售可以修改后再确认，或取消未出库单据。财审通过后、仓库尚未确认出库时，修改会撤回原放行并重新确认；财审正在认领中时，包括同一账号另一窗口和超管都不能改。已确认出库的单不可修改，纠错走销售退货。SHIPPED 后不能直接改数量、收费选择和价款；真实退货走退货检验，没有实物退回的价款更正应走财务追加调整，禁止虚做退货再发运。

仓库继续使用原销售出库任务。V582 起确认出库在同一事务里先建立本单归属的库存占用、再立即消费它并出库；失败则整事务回滚，不留任何占用。收费仅此时立 AR，免费不立虚假 AR，但仍是实际库存出库。

`/sales/other-shipments` 为历史列表/详情；旧 `/new` 转到新客户零星发货，旧 `/edit` 回历史详情。历史数据、旧 UUID 和原库存事实不搬迁；原受控反向继续使用独立权限与真实来源校验。

## 权限和提醒

- 新客户零星发货继续使用 `sales_other_shipment:view/create/edit/delete/approve` 独立权限，`approve` 表示销售确认。共享 `sales_shipments` 表不会使其获得普通订货发货的操作权；服务端按 `shipment_kind` 和负责人范围复核。
- 财务池使用 `finance_shipment_audit`，仓库使用 `sales_shipment:warehouse-work`。审批授权与弹窗接收按 ADR-063 区分：弹窗须当前所属部门与实际动作权限同时满足，不因有查看权就全员弹窗。
- 新修订使用独立 outbox 去重身份；财审通过/退回、销售改动/取消和仓库开始作业撤回已办结提醒。旧通知的真假待办和认领姓名按一批 UUID 查，不逐通知反复访问数据库。
- 没有 `sales_order:price:view` 或财审操作权时，发货读 DTO 同时脱敏数值和 `*Exact` 文本。仓库专用投影不携带货款。

## 接口合同

统一 API 为 `/api/sales/shipments`；销售列表可传 `shipmentKind=DIRECT_CUSTOMER`，权限过滤在服务端执行。

| 操作 | 接口 | 关键输入 |
| --- | --- | --- |
| 新建/编辑 | POST / PUT `/{id}` | 明确类型/收费/用途；编辑 `expectedRevision`；既有明细 `id` |
| 销售确认 | POST `/{id}/confirm-sales` | query `expectedRevision` |
| 财审预览 | GET `/{id}/finance-audit-info` | 返回当前修订、哈希、当前和以前商业快照 |
| 财审通过/退回 | POST `/{id}/finance-audit` / `finance-audit-reject` | `expectedRevision`、`expectedContentHash`、`expectedClaimId`；退回必填 `reason` |
| 财审批量（2026-09-12） | POST `/finance-audit-batch` / `/finance-audit-reject-batch` | `items[{id,expectedRevision,expectedContentHash,expectedClaimId}]`（≤100 笔）；退回批共用一个 `reason`；整批同事务，任一项失败全部回滚 |
| 财审撤回 | POST `/{id}/finance-audit-reverse` | 仅未开始仓库作业 |
| 撤回退回（2026-09-14 V578） | POST `/{id}/finance-reject-reverse` | 财务收回退回决定：清退回标记、追加 `REJECT_REVOKED` 事件、办结销售侧退回通知、恢复待财务审核（销售确认事实保留）；仅未放行且仓库未作业的退回单 |
| 列表按退回筛选（V578） | GET `/api/sales/shipments?financeRejected=true` | 财务工作台「已退回」专段；与 `financeAudit=0` 组合使用 |
| 财审计数 | GET `/pending-finance-count` | 当前真实待审数，排除未销售确认和只读历史 |
| 仓库作业 | POST `/{id}/warehouse-work` | `targetStatus="SHIPPED"`、实际发货仓、逐行库位、选填出库备注 |

财审 claim 类型为 `SALES_SHIPMENT_FINANCE_AUDIT`，键为规范发货 UUID。旧 `/{id}/approve` 不执行物理出库。

金额读取新增 `*Exact` 十进制文本，编辑优先原文，金额请求发十进制字符串，短显/自动预览不回写权威值。当前超出旧存储精度的直接发货金额或汇率乘积会明确拒绝、事务不写；平台实际单据金额与扩展精度仍需完成后续统一验收。已收后退货产生的待处理余额不是已经支付现金退款。


## 退回链路闭环（2026-09-14，V578/ADR-082）

财务退回后单据不再「消失」：

1. **财务工作台**新增「已退回」分段（待审核/已退回/已审核/全部），已退回行状态列红底「已退回销售」；双击进审核详情，右下出现「撤回退回」按钮——适用于退回原因与出货内容无关（客户货款分类未维护、误退）的场景，撤回后单据直接恢复待审，无需销售重走确认。
2. **销售端**：出货详情被退回时横幅指引双路径——「编辑」改单后重新提交，或原因与内容无关时直接点「重新提交财务审核」（原样重提，修订号 +1 形成新一轮提交事实；服务端 `confirmSales` 已放开 `financeRejected` 分支）。退回草稿仍占用订单可发量，改/取消原单即可释放。
3. **通知兜底**：退回通知只要求 `sales_shipment:view`（原 view+edit 双门槛导致只读销售/公共单收不到提示）；归属人不可达时回退投递给制单人。

审核详情简化（同日）：首审不再用文字逐行复述发货明细（下方出货明细表格即完整事实），仅保留「上次审核 → 本次修改」的差异对比；客户快照卡「销售货款类型」更名「客户货款类别」并注明来自客户资料主档。2026-09-15 审核详情整页（卡片区与明细表）收进 `UtenContentContainer.narrow`（1120 居中，对齐销售订货单详情页），滚动为折叠头+表内滚：上滑先收卡片区、明细标题吸顶后再在表格内部滚（销售订单财务审核详情同款）。
