先给结论：**字段是从老系统 B_Goods 原样迁来的，公式是 2026-08 按字段语义猜的（31 号文档原话「若有老系统 002.jpg 实际公式可对齐」），UI 是 18 个输入框一平铺。它既对不上公司真实的成本表，也没有任何分层与下钻。**

## 二、公司案例解析：《80N 玻璃系列实际成本（喷油）》

### 2.1 明细表（每产品一张平铺 BOM，1226 行 / 37 个产品）

每行零件的字段与算法（以 80N 单联单控开关第 1 行为例）：

| 列 | 算法 | 例 |
|---|---|---|
| 材料成本（自制塑件） | 产品净重 × 材料单价 × (1+损耗率) | 0.0146 kg × 16 元/kg × 1.03 = 0.240608 |
| 注塑制造费 | 塑件加工单价 0.28 元/啤 ÷ 出模数量（每模穴数） | 0.28 ÷ 2 = 0.14 |
| 喷油（外协，按个） | 喷油单价 × (1+损耗率)，单列一行 | 0.25 × 1.03 = 0.2575 |
| 采购件/五金 | 单价 × 用量（螺丝×2、铁耳×2…） | 0.054×2 = 0.108 |
| 包装（分摊用量） | BOM 小数用量：中盒 0.1/个、外箱 0.01/个 | 1.33×0.1 = 0.133 |
| 半成品 | 组件行无价，其子件平铺在同一层（功能件→滑杆/弹簧/触片…） | — |

### 2.2 汇总表（产品级公式链，以 80N 单联单控开关成品玻璃为例）

```text
小计(材料)       = Σ 明细行成本金额                        = 6.3373207
管理费           = 小计 × 12%                              = 0.760478484
生产成本         = 小计 + 管理费 + 安装人工(0.725) + 贴玻璃(0.16) = 7.982799184
销售费用         = 销售价 × 3%                             = 0.294
实际成本价       = 生产成本 + 销售费用                       = 8.276799184
利润 / 利润率     = 销售价 − 实际成本价（9.8）→ 1.5232 / 15.5%
```

37 个产品利润率区间约 8.5%~33%，全表平均 21.2%。表尾另有「成品价含高档小盒」列 = 销售价 ÷ 7（疑似出口报价按 7 汇率折外币，见 §八待拍板 7）。

### 2.3 与现行公式链的逐项对齐

| 公司口径 | 现行系统 | 差距 |
|---|---|---|
| 材料小计（含行级损耗 3%） | sourceE = Σ qty×单价（自制取 cTotal），2dp，无损耗 | 缺行级损耗 |
| 注塑/喷油/电镀/抛光/包装（行级工序费） | 产品级 6 个手填格子 | 无法分解到物料 |
| 安装人工/贴玻璃（固定额） | 人工 = 成品价×比率 | 形态不同 |
| 管理费 12%（材料基数） | **无**（manage_e 在库未接） | 缺 |
| 销售费用 3%（售价基数） | **无** | 缺 |
| 损耗 | 成品价×损耗率（计提式） | 口径不同（应移到行级） |
| 厂租 | 厂租比率×成品价 | Excel 无此项（并入管理费），保留为可选 |
| 利润 = 售价−成本（倒算） | 出厂价 = 成本×(1+利润率)（顺加） | 方向反 |

## 三、业界调研结论（SAP / 金蝶 / 用友 / 鼎捷 / D365 / Odoo / ERPNext）

跨产品高度一致的五条共识，直接引用为本方案的设计依据：

1. **两套成本分开**：报价/标准成本（事前模拟，BOM 卷算+费率+加成，不回写存货）与财务实际成本（事后归集核算）是两个对象。SAP 用 EK02 统计条件、D365 order-specific 计算明确「不生成 item cost」、金蝶「模拟报价」独立于标准成本模块。**本系统对应关系：goods 成本预算线（本方案）+ V500 实际成本线（已另行推进）——二元结构本身是对的，问题是预算线做得太糙。**
2. **主档少而稳，结构化成本放成本单**：主档只放「现行单位成本 + 只读参考价」（U8 计划价/最新成本/参考成本、金蝶 参考成本/最新入库价、ERPNext Last Purchase Rate）；成本构成明细放版本化的独立对象（D365 Costing Version Pending/Active、金蝶成本更新申请单）。
3. **损耗率放 BOM 行，不放主档**：所有系统一致（同一材料在不同成品/工序损耗不同）；金蝶公式「实际用量 = 标准用量×(1+损耗率)+固定损耗」与公司 Excel 做法完全相同。
4. **显示四层下钻**：汇总头（单位成本/来源/生效日期）→ 成本构成拆解（材料/人工/机器/制费/外协/包装，SAP cost component、D365 cost group）→ 逐项明细 itemization（可从构成下钻到 BOM+工序行）→ 对比与利润（标准 vs 实际、给定售价算毛利/给定利润反算售价）。
5. **会计口径与报价口径显式分离**：管理费用/销售费用是期间费用不进存货成本（吸收成本法），但报价成本单必须叠加管理费率+销售费率+目标利润（cost-plus）。公司 Excel「生产成本（会计）→ 实际成本价（报价）」的两段式正是这个结构。

## 四、目标口径定版（本方案的核心决策）

### 4.1 两层成本 + 双口径

```text
                 ┌─ 行级工序费（注塑 0.28/啤÷穴数、喷油/个、电镀、抛光）─┐
材料成本 = Σ BOM行 [ 用量 ×(1+行损耗率)× 单价（自制件取其 c_total）] + ┘
制造成本 c_total = 材料成本 + 其他加工费(杂费等) + 组装人工(固定额) + 制造费用(厂租率,可选)
──── 会计口径到此为止（与 GL/V500 的边界）────
报价成本        = 制造成本 + 管理费(管理费率×材料成本) + 销售费用(销售费率×售价)
利润 / 利润率    = 售价 − 报价成本（倒算，对齐 Excel）
建议出厂价 g_total = 报价成本 ×(1+目标利润率)（顺加，cost-plus 反推工具，重新定位）
```

- `c_total` 语义收紧为**制造成本**（现行公式它不含利润，方向本来就对），继续服务 BOM 卷算与 GL 过渡期结转；报价口径全部是**新增字段**，不动 c_total 的既有消费方。
- **损耗费（lostRate/lostE 计提式）退役**，损耗进入 BOM 行（§5.1）。这是唯一的破坏性口径变更，须与财务确认重算时点（§七）。
- 比率与固定额并存：管理费率/销售费率/厂租率按率，组装人工按额——对齐 Excel 形态。

### 4.2 参数的落位（回答「每个产品不一样、OEM 有管理费」）

- **行级**：损耗率、工序费单价——天然每个物料不同。
- **产品级**：管理费率、销售费率、目标利润率、组装人工额、各杂费——落在 goods（现行模式，每货品可独立覆盖）。
- **全局默认**：新建货品预填默认费率组（如 管理 12% / 销售 3%），存系统设置；OEM 类目可设不同默认（如需按客户系列区分，用 `goods.series` 或分类挂默认组，见待拍板 3）。

## 五、方案设计

### 5.1 数据模型（新增列，零新表）

```sql
-- goods_bom_items：行级成本参数
ALTER TABLE goods_bom_items
  ADD COLUMN loss_rate NUMERIC(5,2) NOT NULL DEFAULT 0,      -- 行损耗率%（0~100）
  ADD COLUMN process_type VARCHAR(20),                        -- 工序类型：注塑/喷油/电镀/抛光/其他（空=无工序费）
  ADD COLUMN process_price NUMERIC(18,4);                     -- 工序单价（元/啤 或 元/个，按类型约定）

-- goods：报价口径参数（复用已迁未接的 manage_e）
ALTER TABLE goods
  ADD COLUMN manage_rate NUMERIC(5,2),        -- 管理费率%（基数=材料成本，Excel 12%）
  ADD COLUMN sale_rate NUMERIC(5,2),          -- 销售费率%（基数=售价，Excel 3%）
  ADD COLUMN sale_e NUMERIC(18,4),            -- 销售费用金额（派生）
  ADD COLUMN assemble_e NUMERIC(18,4);        -- 组装人工（固定额，Excel 安装人工+贴玻璃合并口径可拆两列，待拍板2）
-- manage_e 已存在（V32），直接启用为派生金额；electric_e 继续保留不用或并入杂费（待拍板2）
-- lost_rate/lost_e：保留列、停止派生写入（兼容历史读数），新公式不消费
```

- 精度统一 NUMERIC(18,4)；`recalcSourceE` 求和去 `setScale(2)` 改 4 位落库（显示层自定）。
- CHECK 守卫沿用 V421 模式：`loss_rate/manage_rate/sale_rate ∈ 0..100`。

### 5.2 计算引擎（后端唯一真源）

`GoodsBomService.recalcSourceE` 升级为**分项卷算**，一次写回 goods 的分项与合计：

```text
每行：行成本 = qty ×(1+loss_rate/100)× unit_price（自制/半成品 unit = 其 c_total）
     + 工序费（注塑: process_price×qty÷出模数?——见下注）
按 process_type 分组汇总 → 注塑费/喷油费/电镀费/抛光费 各自写入对应 goods 列
材料合计 source_e = Σ 行材料部分；六费列中对应的分项被行级汇总覆盖，杂费仍手填
```

- 注塑「每啤÷穴数」的穴数不在 BOM 行上：**process_price 直接按「摊到单个零件的工序价」存**（0.14 而非 0.28/2），÷穴数留在 Excel 维护习惯里，系统不建模具/穴数模型（避免过度工程；若要留痕可写行备注）。
- 触发点不变（BOM create/update/delete 后重算父件）；多层 BOM 仍靠「子件 c_total 已含其下级」逐层摊平，与现行一致。
- 派生链（manage_e/sale_e/c_total/g_total）从「前端 _recompute」上收为**后端计算+DB 触发器守卫**（V421 已有 SQL 版公式先例，改公式即改 V421 同族迁移）；前端只做即时预览，不再拥有公式。

### 5.3 UI 信息架构：成本页签重做（四层，对齐 §三共识 4）

替换现行 18 格平铺表单。沿用项目三段式与既有组件（MasterDataTableView/ⓘ/悬浮保存组），无说明性副标题：

```
┌ 成本页签 ────────────────────────────────────────────┐
│ ① 汇总条（5 张 KPI 卡，大字）：                        │
│    制造成本 · 报价成本 · 建议出厂价 · 实际售价 · 利润率   │
│    （无 goods:price:view 者隐藏售价/利润率卡）           │
│ ② 成本构成表（行=构成项，列=金额/占比/参数）：           │
│    材料（→下钻③）│注塑│喷油│电镀│抛光│包装│杂费│        │
│    组装人工│厂租(率)│管理费(率)│销售费(率)               │
│    参数列就地编辑（率或额），金额列派生只读               │
│ ③ BOM 材料明细（MasterDataTableView，每物料的成本）：    │
│    组件/用量/损耗率%/工序/工序单价/单价/行成本/小计       │
│    自制件行成本取其 c_total 并标识「自制」；             │
│    损耗率/工序列在权限内就地编辑（保存即触发重算）         │
│ ④ 利润分析（联动）：                                    │
│    拖动/输入售价 → 利润、利润率即时重算；                 │
│    反向：输入目标利润率 → 建议出厂价                     │
└──────────────────────────────────────────────────┘
```

- ①的五个数字就是 Excel 汇总表的列，用户口径零翻译成本。
- ③直接回答「每个物料的成本」：BOM 页签本体**不**恢复单价/金额列（尊重 2026-09-25 退役决策，那里服务排产/计划用户）；成本明细长在成本页签内、受 `goods:cost:view` 门控，复用 `BomItemView` 已有的 viewPrice/viewTotal 脱敏通道。
- 文案：错别字「喷漆、朔费」→「喷油费」；「材料合计」→「材料成本」。

### 5.4 权限

| 内容 | 权限 | 行为 |
|---|---|---|
| 成本页签整页 | `goods:cost:view`（既有） | 无权隐藏页签（现状不变） |
| BOM 行单价/行成本（成本页签内③） | `goods:cost:view` | 无权整段③隐藏 |
| 汇总条售价/利润率卡 | `goods:price:view` + `goods:cost:view` | 缺一即隐藏对应卡 |
| 费率/损耗率/工序价编辑 | `goods:cost:view` + 货品编辑权 | 保存走货品 PUT/BOM PUT 既有链路 |

### 5.5 兼容与迁移

1. **增量列、零新表**；所有新增列 NULL/DEFAULT 0，老数据公式不变即不变。
2. **行损耗率回填**：默认 0；一次性批量工具「按分类设默认损耗率」（如原材料/辅料 3%，五金 0%），逐货品可改——对齐 Excel 习惯又不出错。
3. **公式切换**：新派生公式上线时，全量重算 goods 成本列；重算前把 20 字段原值写 `audit_log`（照抄 V421 治理模式：不静默抹除、可前向恢复）。
4. **GL 影响**：损耗退役后 c_total 数值会小幅变化，而 GL COGS 仍按 c_total×数量结转（V500 未落地前的过渡）。切换时点须财务确认，建议与一次月结对齐；重算前后各出一份 `FinanceCostService` 产品成本汇总对差异。
5. **导出**：成本页签加「导出成本单」——按 Excel 汇总表同构（构成项+公式列），受 `goods:cost:view`；货品列表导出不加成本列（维持现状）。
6. **成本历史（低成本高价值）**：利用既有 audit_log 整行 before/after，成本页签加「变更历史」侧滑：时间/人/逐字段 旧值→新值。不建成本版本表（SAP 式多方案对比属过度工程，真需要时再立项）。

## 七、风险

1. **c_total 语义变化波及 GL/财务报表**（§5.5-4）——最大风险，必须财务拍板切换时点。
2. 全量覆盖式保存契约（PUT 缺字段清 null，31 号文档 §四）下新增字段必须全链路回传，漏传即清空——复制货品、基本信息编辑、成本页保存三处都要带上（现行 `fixedValues` 机制的既有坑，加字段时放大）。
3. BOM 行级损耗/工序价的多层摊平：子件 c_total 变化会级联父件，深链 BOM 重算的批量性能需按现行 `treeGoodsIds` 模式做一次评估（现有 MAX_DEPTH=10 环检测可复用）。
4. 权限交叉（价格+成本双权才见利润）在 UI 上要给出明确隐藏而非空白，避免「数字没了」误报 bug。
