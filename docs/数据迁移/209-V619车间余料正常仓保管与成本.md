# V619 车间余料正常仓保管与成本

## 业务边界

当前车间不再使用的直送料应送正常仓库。来源追溯和实际存放是不同的事实：仍能追到原直送、原报工和原ISSUE，但库存必须记到本次真实接收的普通叶仓，不回记上道生产车间或技术线边位。

V618记录仓库确认的实际接收位置，V619接续数量、私有保管权益及成本。接收仓须为同主仓内活动普通叶仓；跨主仓不在本次流程内。普通仓库存调拨和已审核历史单据的实际仓身份不改。

这里的“同主仓”以原实际来源仓为准。当前采购/IQC合格来源可能实际存放在与计划逻辑主仓不同的位置，原精确私有权益仍有效。出库统一使用`fn_production_material_actual_warehouse_allows`：同计划主仓，或该实际仓内此需求所有有效正式持有均有数据库验证的合格来源。余料接续沿唯一MOVE/HANDOFF继承原资格和实际范围，不复制FORMALIZE，也不把逻辑计划仓当作物理仓。

## 三种来源

| 来源 | 真实库存变化 | 责任接续 |
|---|---|---|
| 已实际ISSUE，包括原技术位领入 | 在制材料减少，正常仓一次入库(type6)；原技术位不再扣第二次 | 原R同步净投入减少、释放增加；新实际仓R保留原需求和原ISSUE证明 |
| 未ISSUE、已正式备料的直送片 | 技术位type8出、正常仓type7入 | 撤减原实际技术位未发DRAW指令，原正式R释放，正常仓正式R继承精确片 |
| 路线尚未确认的未ISSUE直送片 | 同样两腿真实移位，不伪造ISSUE或START | 正常仓建立WORKSHOP_CUSTODY私有保管；任务保持WAITING，确认路线或显式核料时正式化 |

每条申请固定一种来源：原ISSUE posting UUID或direct transfer item UUID。按基本单位核算，保留冻结换算率。不能用同SKU、同主仓的另一笔货替换来源；数量来自实际来源片，受待退申请、已领、已耗及已有迁出事实共同限制。

实耗、报损和合法在制在发生时即冻结对应原ISSUE的来源片，而不是等下一次退料再按当前余额猜。比如当时仅有A3/B2在制，登记耗用5后，之后撤回另一张退料单补回A2/B3，新增可退量只能是A2/B3，不能把已经耗掉的A3改标为余料。正反结算保持同一原片和counter，物理净投入与不可退的净结算量分别核对。

接收动作不自动制造新的普通仓领料指令。车间确需再使用时显式“继续领料/重核”，正式化原私有保管或复用正常仓原R的未耗用余额，再提交普通仓领料。同一任务继续记录，保留全部真实领退事件。

## 申请冻结与仓库确认

`production_workshop_material_return_slices`在申请时固定未领直送的精确片，分别标识已经预留和仍未正式预留的数量。已冻结片不能同时投入、普通释放或被另一份申请重复占用；持续生产只可投入未冻结的剩余片。取消申请恢复该片可用量，不改历史DRAW总量。

库管确认后，在同一事务中完成：既有履约足迹和实际库存维度预锁、精确权益准备、真实物理入出库、实际仓私有R与来源片继承、成本携转、单据审核。prepare不能单独提交。旧技术位DRAW的未发指令以V618追加事件撤减/恢复，不篡改gross数量和已实发事实；通知根据最新有效指令办结或更新旧待领卡。

已发来源原R使用`consumed−q / released+q`同一更新，不能先打开技术位可用预留再迁出。反向用`consumed+q / released−q`，与真实GOOD_RETURN_REVERSE相互核验。

## 私有保管与来源守恒

WORKSHOP_CUSTODY的owner固定原需求，consumed必须为0。所有迁入R使用`source_doc_type=WORKSHOP_RETURN_CUSTODY`，保持原申请UUID和原数量不可变；公共分配器不得extend该R。每个MOVE/HANDOFF只能建立唯一专属target R，裸调用建R helper而没有完整MOVE/HANDOFF证明会在提交时拒绝。

正式化只由明确车间命令发起，沿原来源迁交到同任务正式R，不能把系统后台补料当作领料授权。绑定的私有保管也属于已有供料事实，不能选择独立拆批来绕过责任。正常仓释放私有R并不让原技术位来源“重新到货”；技术位可用量始终扣除真实净迁出。

已经属于本任务的余料移到正常仓，不会再次占用公共安全库存预算。专属数量由唯一MOVE/HANDOFF、实际入库movement及未反向事实计算，不能仅设置一个标记就绕过公共库存限制。

对分析前置权益，`production_workshop_return_preplan_events`连接精确原PREPLAN reservation、原正权益及本次RELEASE/RESTORE。只释放本需求有权承接的原report/receipt来源，不能拿另一受益人的预留。原料进入正常仓后由保管R阻止公共库存重复分配，不再伪造一次receipt或ORIGIN。

## 成本与反向

已领退料从原ISSUE的未耗用WIP切片携带价值，未领直送料按技术位真实账面出库生成IN_TRANSIT切片，再转入正常仓。目的仓已有库存均价不能用于重估来料。例如原料3件成本30、目的仓10件成本990，接收后应为13件、1020；不能按目的仓99元单价把3件记成297。

反向必须指向原实际收仓movement和对应MOVE，逐原切片恢复。未领直送还须正常仓反向出库与原技术位反向入库，已领退料只恢复原WIP，不伪造技术位补货。目标已经实际再领、耗用或继续迁库时，须先处理该真实后继，不能用另一笔新库存冒充原片。同一个普通仓内真实退回不需要跨仓MOVE，仍须有本次收仓确认及原GOOD_RETURN、movement link完整证明。缺少真实来源的旧数据由迁移诊断处理，不在正常写入路径猜测来源。

物理数量和成本各有独立延迟守卫。价值反向保留原切片范围及依赖节点，不以目的仓混合均价计算。正常仓之后仅增加其他真实入库时，保留后来每笔完整成本贡献节点，只撤原余料。例如上例再入2件、价值14后，撤回原3件余料，仍留下12件、1004。后续已经发生实际出库时，其混合成本存在真实后继，须先处理后继；不能拿后来同SKU库存凑数，也不能撤掉本来无关的纯入库来规避实现限制。

多张余料单先后反向时，保留价值通过无资产归属的`VALUE_REFERENCE`引用节点逐次接续。`reference_root_id`固定原完整成本来源，每个来源或引用节点仍最多有两个后继，保留成本传播的有界结构。它不增加库存、不持有金额，不按混合均价截取份额；后续源成本确定时仍可沿同一原来源传播。零金额和待价材料同样保留数量、来源及反向证明，不伪造零金额记账行。

## 旧数据、校验和性能

本迁移不重写旧流水、receipt、库存或财务历史。MAKE/BUY/委外receipt兑现容量按原R数量验证，历史合法退休与当前新资金注入分开；新兑现仍要求活动未耗用正式R。历史同单位且冻结换算率为1的MAKE来源不依赖后来是否补填货品基本单位。

迁移第一步在锁定事实表后核对全部生产R的`consumed`与四类领退posting净量；差异直接报告原R UUID及两侧数量，事务拒绝，不补造ISSUE或留下运行时差额。生产R随后增加数据库管理的事务基线字段；每个事务`consumed`增量必须等于同事务真实posting净量，调用方不能裸改consumed制造DONE。完整已证起点与持续事务增量共同守恒，posting按reservation与事务索引点查，支持同事务多次操作和savepoint，不在热路径反复扫描全历史。

结算来源也在DDL前核对：缺少`issue_posting_id`时拒绝；已有直送来源的ISSUE缺少来源片，或多来源ISSUE存在部分历史结算/部分结算反向时拒绝。单来源、整笔多来源结算及整笔counter可唯一回填；没有旧来源证明的部分多来源记录不按FIFO猜测。新增事实仅复用source_events的两个FK字段和定点索引，不新建平行结算账。

以下只读查询列出需要核对的结算来源：

```sql
SELECT settlement.id, settlement.issue_posting_id, settlement.settlement_type,
       settlement.qty_base, issued.qty_base AS original_issue_qty,
       settlement.source_posting_id, source_count.qty AS issue_source_count
FROM production_material_settlement_postings settlement
LEFT JOIN production_material_stock_postings issued ON issued.id=settlement.issue_posting_id
LEFT JOIN LATERAL (
  SELECT COUNT(*) AS qty FROM production_workshop_direct_source_events source
  WHERE source.stock_posting_id=issued.id AND source.event_type='ISSUE'
) source_count ON TRUE
WHERE settlement.issue_posting_id IS NULL OR (
  EXISTS(SELECT 1 FROM production_workshop_direct_source_allocations allocation
         WHERE allocation.stock_reservation_id=issued.reservation_id)
  AND (source_count.qty=0 OR source_count.qty>1 AND settlement.qty_base<>issued.qty_base))
ORDER BY settlement.id;
```

升级前只读定位数量投影差异；查出的行必须凭真实原单据核对，不得只为通过校验修改数量或造领料：

```sql
-- Read-only V619 preflight. Run against the source database before migration.
-- Every result requires evidence-based reconciliation; do not manufacture ISSUE
-- postings or change consumed_qty merely to make this query return no rows.
WITH posted AS (
    SELECT reservation_id,
           SUM(CASE posting_type
               WHEN 'ISSUE' THEN qty_base
               WHEN 'GOOD_RETURN_REVERSE' THEN qty_base
               WHEN 'ISSUE_REVERSE' THEN -qty_base
               WHEN 'GOOD_RETURN' THEN -qty_base
           END) AS net_issued_qty
    FROM production_material_stock_postings
    GROUP BY reservation_id
)
SELECT reservation.id AS reservation_id,
       demand.plan_id, demand.execution_segment_id,
       reservation.goods_id, reservation.warehouse_id,
       reservation.qty, reservation.released_qty,
       reservation.consumed_qty AS projected_consumed_qty,
       COALESCE(posted.net_issued_qty, 0) AS actual_net_issued_qty,
       reservation.consumed_qty-COALESCE(posted.net_issued_qty, 0) AS difference_qty,
       reservation.status, reservation.is_deleted
FROM stock_reservations reservation
LEFT JOIN production_material_demands demand ON demand.id=reservation.demand_id
LEFT JOIN posted ON posted.reservation_id=reservation.id
WHERE reservation.owner_type='PRODUCTION_MATERIAL_DEMAND'
  AND reservation.consumed_qty IS DISTINCT FROM COALESCE(posted.net_issued_qty, 0)
ORDER BY demand.plan_id, reservation.id;
```

所有来源预锁按UUID顺序，分配顺序另行使用到货序。迁移新增八张来源/保管事实表，全部ALWAYS审计、不可变证明，并登记业务重置CLEAR和运行时`business_data_reset()`。申请片、MOVE、反向、HANDOFF和原posting均有定点索引，不在每次领料时遍历所有历史库存流水。

针对一张退仓单的只读追溯：

```sql
SELECT item.id AS request_item_id, item.issue_posting_id, item.direct_transfer_item_id,
       confirmation.source_warehouse_id, confirmation.received_warehouse_id,
       move.source_reservation_id, move.target_reservation_id, move.qty_base,
       move.source_out_movement_id, move.received_movement_id,
       held.owner_type, held.qty-held.consumed_qty-held.released_qty AS private_open_qty,
       reversed.received_reverse_movement_id, reversed.source_reverse_movement_id
FROM production_material_return_request_items item
JOIN production_material_return_receiving_confirmations confirmation
  ON confirmation.stock_document_id=item.request_id
LEFT JOIN production_workshop_material_custody_moves move ON move.request_item_id=item.id
LEFT JOIN stock_reservations held ON held.id=move.target_reservation_id
LEFT JOIN production_workshop_material_custody_reversals reversed ON reversed.move_id=move.id
WHERE item.request_id=:return_document_id
ORDER BY item.id,move.id;
```

已领余料跨仓时`source_out_movement_id`必须为空；未领DIRECT_LOT必须有两腿。正常仓同仓退回沿既有R处理，可能没有跨仓MOVE，应同时读取原material posting及movement link，不能将缺少跨仓记录误判为丢失数量。

## 验证入口

- `WorkshopSupplyAdversarialEndToEndTest`：源权益、并发、实际仓映射和非零混价收仓/反向。
- `WorkshopMaterialReturnValueDagEndToEndTest`：同池两张余料单、后续真实入库、两种反向顺序及零/非零来源价值；每种情况下再通过内部估值port将后来真实入库的来源价值增加10并完成传播，正常仓保持10件、价值990→1000，所有节点后继数仍≤2、引用资产归属为0。该步骤验证成本依赖传播，不代替采购变价审批验收。
- `WorkshopMaterialReturnSourceConservationEndToEndTest`：分片实耗登记后乱序反向，已耗来源不能重新变为可退余料。
- `ProductionExecutionRouteGateEndToEndTest`：未开工退料、DIRECT_LOT冻结与解冻、正常仓接收、显式再领与改派。
- `WorkshopMaterialCustodyPostgresTest`：精确源片迁移、释放后技术位不复活、伪恢复拒绝。
- `ProductionMaterialConsumptionProjectionEndToEndTest`：裸消费拒绝、真实posting增量与事务边界。
- `ProductionQuantityAdversarialEndToEndTest`：FULL_KIT真实退3后按7完成及正式反向、另正常叶仓接收。

每轮证据须标识当次源码及迁移快照；安装成功、专项通过和全项目验收分别记录，不以旧绿灯替代新增正常仓流程验证。
