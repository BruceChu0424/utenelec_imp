# 组件库使用规范

> 本规范面向当前 Flutter 源码。真实组件清单见[组件总览](../02-组件库/组件总览.md)；最后核对：2026-08-27。

组件新增、修改、重构与相关设计文档默认使用 `frontend-design`，技能选择见[项目准则](00-准则索引与开发清单.md#设计技能选择)；实现继续复用 Uten 组件及主题 token。

---

## 一、目标

- 同类交互使用同一套视觉、状态与错误反馈。
- 响应式、主题、字体缩放、性能降级和可访问性在公共层统一处理。
- 页面保留业务编排，公共组件不直接调用模块 API 或读取模块权限。
- 抽象以真实复用为依据，避免复制粘贴，也避免没有调用方的“万能组件”。

---

## 二、放置层级

| 类型 | 目录 | 约束 |
|---|---|---|
| 纯 UI 基础能力 | `lib/components/` | 不依赖 feature、业务模型或业务 Provider |
| 跨模块业务组合 | `lib/shared/widgets/` | 可以表达稳定的跨模块业务展示，但不依赖页面 |
| 模块组件 | `lib/features/<module>/widgets/` | 可以依赖本模块模型和 Provider |
| 一次性页面组合 | 页面私有 Widget | 只有一个调用方时不强行公共化 |

项目当前没有组件 barrel。业务文件直接导入所需源码：

```dart
import 'package:uten_imp/components/buttons/uten_button.dart';
import 'package:uten_imp/components/feedback/uten_empty.dart';
```

不要引用不存在的 `components/index.dart`、`uten_components.dart` 或已删除组件。

## 三、优先复用规则

已有同类能力时必须复用：

发现多套同责实现时，先比较各自正确能力和业务差异，再形成公共方案并迁移全部适用调用方，见[统一实现与公共能力](16-统一实现与公共能力.md)。组件层级及业务边界继续遵守本规范，不以统一为由强并不同业务语义。

| 场景 | 当前入口 |
|---|---|
| 普通按钮 | `UtenButton` |
| 关闭弹窗、侧栏、预览或通知 | `UtenCloseButton`，红色圆形白色 ×，放在标题栏最右侧，不能占用左侧返回槽位；详见[窗口控件](../02-组件库/UtenCloseButton.md) |
| 最小化、全屏与还原 | `UtenWindowControlButton.minimize/expand`，黄色/绿色圆形；所有平台共用 |
| 多个窗口控件并存 | `UtenWindowControls`，各平台从左到右为最小化、展开/还原、关闭；整组在右侧，关闭在最右端，下载等业务工具放组外；窄屏也不将窗口控件折入“更多操作” |
| 原有底部文字关闭、失效提示退出 | 迁入标题右侧 `UtenCloseButton` 或公共标题关闭；移除重复页脚关闭，保留 busy、返回值及草稿/未知提交守卫 |
| 异步提交、防连点 | `UtenActionButton` |
| 按钮触发加载等待 | `UtenBusyOverlay`，与按钮置忙、防连点配合；按钮内 spinner 不能代替加载弹窗 |
| 标题、字段和列头旁的说明 | `UtenFieldHintIcon`；列头复用 `UtenColumnHeaderInfo` / `UtenColumnHintIcon` 或已有 `info` / `headerInfo` 入口 |
| 通用卡片 | `UtenCard` |
| 文本/密码输入 | `UtenInput` |
| 搜索 | `UtenSearchBar` |
| 下拉、日期、员工选择 | `UtenDropdownField` / `UtenDateField` / `UtenEmployeePicker` |
| 空、加载 | `UtenEmpty` / `UtenSkeleton` |
| 用户操作反馈 | `UtenNotify` 或 `context.appSuccess/Error/...` |
| 确认弹窗 | `UtenDialog` |
| 卡片集合 | `UtenResponsiveGrid`；完整连续列表复用 `UtenResponsiveGrid` / 虚拟窗口，内部分批使用完整读取公共入口 |
| 列表筛选 + 表格（上下） | `UtenListTwoPane` |
| 顶部折叠 + 正文内滚 | [`UtenCollapsingHeaderScrollView`](../02-组件库/UtenCollapsingHeaderScrollView.md)：所有尺寸保留同一 outer/inner viewport 和 primary 控制器；需外层回顶时走 `outerControllerOf(context)`，不按 `NestedScrollView` 类型猜宿主 |
| 可编辑明细 | `UtenEditableGrid` |
| 主数据/报表式表格 | `MasterDataTableView` |
| **既是树、又要行内编辑、还要多选** | `MasterDataTableView` + `cellBuilder` 内放输入控件, 控制器存宿主 State |

二次确认用 `UtenConfirmationSummary` 呈现本次操作的单据数、类型、数量及关键后果。数量按单位分组，金额按币种分组。关键数值和需要特别注意的后果使用主题错误色及粗体。逐行明细、可修改的参数和必核证据留在确认前的办理界面。

最后一行是 2026-09-22 补的分界(ADR-102)。以前这里只有「可编辑明细用 A、主数据表用 B」两条,
遇到「树形 + 行内编辑 + 多选 + 表头筛选」这种表没有答案。结论是**不要为此换表格组件**:
物料分析的分桶详情页与主表都已经用 `MasterDataTableView` 跑着「多行行内编辑 + 跨分页 + 抗轮询回填」,
换成 `UtenEditableGrid` 会丢掉列显隐/列序/列宽与 facets 表头筛选。做法有三条硬要求:

1. 控制器由宿主 State 持有(`Map<提交单元身份, TextEditingController>`), **不要挂在行对象上**——
   表格的行每次投影都会重建, 且带客户端分页, 挂在行上翻一页就丢一次用户填的数;
2. 宿主 `dispose` 里统一释放, 换数据源时整体作废;
3. **输入保全**: 后台轮询或 409 恢复换快照后, 只回填「仍等于旧系统预填值」的格子,
   用户改过的一律保留。少了这一条, 用户填了一屏的数会被后台刷新静默吃掉。

员工选择统一复用 `UtenEmployeePicker` / `UtenEmployeeMultiPicker` 或
`showUtenDepartmentEmployeePicker`：候选主行、确认栏和已选值均显示 `姓名(工号)`，
部门放在下一行；调用方必须传真实 `employeeCode`，历史接口确实没有工号时才回退为姓名。

分类、部门及员工选择中的组织树，无论在主页面、抽屉、侧滑窗、底部面板还是表单内的选择弹层，都通过 `UtenCategoryTreeView` / `UtenDepartmentTreeView` 或直接调用 `UtenHierarchyTreeView` 使用同一公共树入口；名称按层级缩进，并显示父子连接线及小号加减展开按钮，保持既有行高与独立点击区域。`flatLevelColors` 只选择紧凑层级配色，不取消缩进和连接线。不得另写无缩进列表或复制树行、连线、展开逻辑；单多选、可选节点、隐藏包装根、业务排序和确认/取消语义由调用方配置。连线几何与表格树共用 `lib/components/data_display/uten_tree_branch_guide.dart`，结构投影共用 `utenTreeProjection`；BOM 等表格仍经 `UtenTreeTableCell` 保留其原有表格外观。覆盖范围和验证边界见[分类树连接线与滑窗统一](../99-项目治理/2026-10-26-分类树连接线与滑窗统一.md)。

必填选择字段统一复用 `requiredLabel` + `applyRequiredEmpty` 或组件的 `required: true`：
空值时显示红色 `*` 和错误色边框，提交后显示字段就地错误；不能只用颜色表达必填。

字段说明、校验错误和自动带出提醒统一收进框内图标（2026-09-07 用户口径）：
公共输入组件传 `info:`；裸 `TextField` / `InputDecorator` 用
`UtenInputDecoration(InputDecoration(...), info: ...)`。图标支持悬停、点击与键盘打开，
标签保持短句，复杂条件与操作后果放进图标。**表格列的说明位置（2026-09-10 口径）**：列级通用说明（数量/单价/币种/税率/结账等对所有行相同的口径）放 `EditableGridColumn.headerInfo` / `MasterColumnDef.info` 的列头 ⓘ（共用 `UtenColumnHeaderInfo`，悬停/点按/键盘，吞长按不与列排序打架）；只有**行特有**的说明（学习预填来源、本行上限、必填空）才留在格内 `info`/`autofilled`/红框；列头 ⓘ 不能替代行特有提示，格内 ⓘ 也不再承载通用说明。凡单元可能出现预填黄标图标的列，`chromeWidth` 须计入 `UtenEditableGridCellSpec.hintIconWidth`（0——2026-10-08 起格内图标零尺寸、不占宽），默认列宽也要装下常见值。
错误仍保留红框、无障碍反馈和原提交校验；自动带出值通过 `applyAutofillHint` 保留黄框、
淡黄底和来源图标，不再占用框下空间。不要把必填说明误写成自动带出状态，已保存快照
也不是学习值。只在用户修改文本内容或重新选择时清除黄标，移动光标和聚焦不算修改。
同一字段避免嵌套多个 `UtenInputDecoration`；先包装说明，再应用必填和自动带出状态。

Material 原语并非一律禁止。以下情况可以直接使用：

- 公共库尚无对应能力，例如 `Switch`、`Checkbox`、`Slider`；
- 页面私有、没有稳定复用价值的 `Row`、`Column`、`Padding`、`SizedBox`；
- 公共组件内部实现。

即使直接使用 Material，也必须走主题、token、权限和状态约束；不得复制一套已有 Uten 组件。

## 界面提示与按钮加载

以下规则每次任务均须核对，界面新增、修改、重构和审查时执行，覆盖本次涉及的页面、卡片、区块、表单、表格及弹窗；同一业务的多端入口按根目录 [AGENTS.md](../../AGENTS.md) 同步核查。

- 不写副标题或独立成行的说明、提示句。无必要的直接删除；必要说明收进项目自有提示 icon，在鼠标悬停时显示对应说明弹层。
- icon 紧邻其说明对象的标题、字段标签或列头，与文字同排；不能单独成行，也不在下方重复显示同一段说明。复用 `UtenFieldHintIcon` 和现有标题/列头提示入口，保留点按、键盘及无障碍访问，窄屏或字体放大时仍随对应对象布局。
- 日期范围按钮按 2026-11-03 后续用户要求使用纯文字：移除日历、提示及清除图标，清除保留为同高文字按钮；复用 `UtenButton` 的上下文高度与触控目标。选中后显示“近90天”“近1个月”等短文案，历史或未来范围显示“共N天”，不冒称近期。整个日期按钮鼠标悬停立即显示 `yyyy.MM.dd-yyyy.MM.dd`，键盘聚焦及触摸长按也能查看；业务字段标签、开放端含义、必填和错误说明保留在原字段与公共提示中。此日期按钮规则优先于上一条的一般提示 icon 规则，公共入口为 `UtenDateRangeSelectionButton`、`UtenHistoryTimeFilter` 和 `UtenDateRangeTooltip`。**2026-11-04 修订：清除入口不再并排“清除”文字按钮，改为已选范围框内最右侧的红色圆形关闭按钮（`UtenCloseButton` 红底白 ×，紧凑窗口跟随行高），单按钮弹窗选择起止日期的口径不变；即时库存入口带“筛选范围”业务标签。**
- 所有需要加载等待的按钮都必须显示项目自有 `UtenBusyOverlay`，包括文字按钮、图标按钮、菜单动作及弹窗按钮。网络请求、数据加载、保存、提交、删除、审批、导入导出、异步计算等均适用，不设“只有长任务才显示”的门槛。
- **2026-11-08 修订：导出、下载、批量下单/批量审批等可感知进度的长等待改用 `UtenProgressDialog`（`showUtenProgress` + `UtenProgressSession`，组件文档见[通用进度弹窗](../02-组件库/通用进度弹窗.md)）**：弹窗显示大号百分比、圆角进度条、已用时间与「取消」，总量未知时显示扫动条、不伪造百分比，**弹窗内不出现转圈**；点取消立即关闭弹窗，调用方把 CancelToken 挂到请求上让传输真正停下。进度条与百分比的全部样式只在 `lib/components/feedback/uten_progress_dialog.dart`（`UtenProgressBar`）一处维护，整体换风格只改该文件，调用方不得自绘进度条。计数型批量操作（逐单提交）用 `session.count(done, total)` 汇报。一般保存、命令、读取等待仍用 `UtenBusyOverlay`；同一动作只用一个等待件，不叠遮罩。
- **2026-11-09 修订（取消语义与批量接法，ADR-199）**：写入类循环批量取消＝`cancelMode: UtenProgressCancel.afterCurrent`——当前项办完即停、不中断进行中的写请求（避免「未知提交」），已办结果照常呈现并提示「已停止，其余 N 项未处理」，不重放、不当作全部失败；**单请求型批量写入 `cancellable: false`**（一次已提交的事务无法真正取消，不提供误导性的「取消」）。身份/服务器切换用 `invalidation` + `isCurrent` 按取消收尾；有 `route.isCurrent` 守卫的页面用 `onRouteOpened` 登记弹窗路由；action 自动在调用方 Zone 执行（scope 传递不丢）。下载类字节进度用 `session.receiving(...)`（总量未知保持扫动条）；圆环进度统一用同文件 `UtenProgressRing`。Win7 WPF 端同步件见 `UtenBusyDialog.ShowProgress`（台账 W7-FLOW-019）。
- `UtenActionButton` 只负责自身 busy、防重入和按钮内 loading，不会自动创建加载弹窗；调用方必须配合公共加载弹窗。同一动作已有公共入口显示弹窗时复用该入口，不重复叠加；按钮禁用、转圈、改文案或单独进度条均不能替代弹窗。
- 遮罩跟随实际异步执行阶段，成功、失败、取消和中断均正确收尾；等待用户确认、再认证或展示结果弹层时先撤下或让位，避免遮住需操作的弹层。保留防连点、输入/草稿、未知提交和服务端权威，取消等待不代表服务端写入已取消，也不得据此重放写入。

本节规定后续执行方式，存量入口的完成情况仍须按实际迁移及交互证据记录。

## 四、正确 API 示例

### 4.1 普通按钮

```dart
UtenButton(
  type: UtenButtonType.primary,
  size: UtenButtonSize.medium,
  isLoading: saving,
  isExpanded: true,
  icon: Icons.save_outlined,
  onPressed: saving ? null : save,
  child: const Text('保存'),
);
```

`UtenButton` 的参数名是 `type`、`isLoading`、`isExpanded`；不要使用旧文档中的 `variant`、`loading`。

### 4.2 异步动作按钮

```dart
UtenActionButton(
  type: UtenActionButtonType.primary,
  label: const Text('提交'),
  loadingLabel: const Text('提交中'),
  onAction: () async {
    await repository.submit();
    if (context.mounted) context.appSuccess('提交成功');
  },
);
```

异步回调由组件锁定状态。同步抛错也必须恢复按钮；错误展示应走统一反馈入口。上例只展示按钮 API，实际接入还须按[界面提示与按钮加载](#界面提示与按钮加载)配合 `UtenBusyOverlay`，不能只保留按钮内 loading。

### 4.3 卡片网格

```dart
UtenResponsiveGrid(
  itemCount: items.length,
  itemBuilder: (context, index, itemWidth) {
    return UtenCard(child: ItemSummary(item: items[index]));
  },
);
```

`itemWidth` 表示当前格宽，卡片可据此适配。`UtenResponsiveGrid` 默认按父容器宽度形成 1～6 列，不要再按屏幕宽度重复算列数。

2026-11-04用户要求业务列表统一单页连续展示：按当前权限/来源/搜索/筛选/排序读取完整列表摘要，前端只虚拟绘制可见行；上下滚动不触发分页、刷新或逐行占位。后端继续稳定排序、有界内部分批（2026-11-08 起首批 50、之后对齐增长；单次页上限 2026-11-09 经用户确认由 200 上调至 1000，仍是有界上限），不放开为无界请求。共用 `loadCompletePagedResult` / `loadCompleteCursorSnapshot`，失败/漂移不伪造完整或0条；详情仍按原入口读取。

### 4.4 空状态

```dart
UtenEmpty(
  icon: Icons.inbox_outlined,
  title: '暂无数据',
  action: UtenButton(
    onPressed: reload,
    child: const Text('重试'),
  ),
);
```

## 五、表格、列表与分页

**2026-11-04现行规则：业务表格、主档、任务中心、滑窗/弹窗均一个连续结果，不显示页码/上一页/下一页，也不按滚动猜测加载邻页。** 已加载数据可往返滚动而不请求或重播行/列入场；渲染保持虚拟化。原构造参数若为源码兼容保留，不作为新页面实现入口。首响应权威总计/资格及每行原版本必须保留；内部后续批可明确不含重复元数据，不能以空/0冒充已统计。

**2026-11-08 用户口径：全部带表格的页面逐批追加显示（替代 11-07 只发首批 provisional）。** 完整读取按共享批次计划 `CompleteReadBatchPlan`（Dart `lib/shared/paging/complete_paged_snapshot.dart`，Java `com.uten.imp.common.web.CompleteReadBatchPlan`，共享向量 `contracts/complete-read-batch-plan-v1.json`）首批 50 行、之后对齐增长（50→50→100→200→200…→1000…，每批是自身页大小下的真实页，offset=(页码-1)×页大小，不重复读、不漏读；总量 ≤1000 的请求序列与旧 200 上限一致，2026-11-09 经用户确认上限 200→1000）；服务端单次页上限统一 1000（`Pageables.MAX_PAGE_SIZE`）。读取方用 `fetchPageSized` 把批大小透传到接口，`onProgressiveBatch` 接收每批校验通过后的累积前缀（首批立即、之后至多每 200ms 合并一次），完整结果到达后原位替换。逐批期间：不是滚动触发；列表加载状态不清除；`MasterDataTableView` 只追加行，不重建列、不跳滚动、列宽与文字选择按追加续算，禁用勾选/全选/行右键菜单并在表尾显示加载；合计/统计卡、导出、打印、批量与写入仍等完整结果；失败或被退休的读取把逐批行整体撤下（读取会话失效，表格自行隐藏），不显示半份冒充完整；同一查询已接受完整结果的重读保留原结果直至新结果完整。服务端缩小页上限或旧加载器自带页大小时，读取方按服务端页大小继续，至多浪费一次请求。主档 NDJSON 流请求 `size=1000`（2026-11-09 前为 200）时按同一计划分帧（`size=100` 仍是旧客户端固定帧）。2026-11-09 起即时库存主页面完整读取改走同款单扫描 NDJSON 完整流（POST `/api/stock/instant-inventory/summaries?complete=true`，`InstantInventoryCompleteStreamService`）：服务端在一个只读 RR 快照内经 `ReportExportCursor` 单次有序扫描供完全部批次，首批帧带合计与表头桶（与 GET 首批同口径）、续批帧只取行并沿用快照内一次算出的精确 total，每帧三凭据与读后提交栅栏复用 `VersionedSummaryPages`（修订域复用 `native-facet-instant-stock` 的新鲜度触发器集合）；客户端复用 `postSummaryStream` + `CompleteSummaryStream` + `readVersionedSummarySnapshot`（`InstantInventoryRepository.completeStream`）。真库 3.5 万行实测：逐批 OFFSET 请求约 80 秒 → 单扫描流秒级。GET `/instant-inventory` 的 `includeTotals=false&includeFacets=false` 续批仍是其他分页调用方的兜底路径（仓库面板、明细弹窗等），页上限随共享计划升至 1000。帧校验（页码/大小/proof 三字段/身份去重）与 readScopeVersion 退休机制对逐批行全部生效。

**2026-11-09 全站单扫描流迁移定论（先测后改，探针门槛 >3 秒）。** 对其余「逐批 OFFSET 阶梯」候选逐个做了真库（5434，35,805 货品、交易类源表 0~25 行）服务级探针（`*LadderProbeTest`，`UTEN_LADDER_PROBE=true` + `UTEN_DB_URL/USER/PASSWORD`，按共享批次计划首批 ALL/续批 rows-only 驱动真实服务）：IQC 8 行 114ms、FQC 12 行 168ms、仓库收/发任务中心 302/172ms、履约工作台采购/委外/仓库 133/618/139ms、生产待排产 47ms、研发任务 19ms、库存流水 148ms、销售/采购/生产/委外明细报表 796/450/84/61ms、仓库单据报表明细/汇总 104/61ms、财务应收应付明细 826ms——**全部远低于 3 秒，本批不迁单扫描流**（真库数据量不足以体现 OFFSET 重扫；生产库数据长大后按同款探针复测再迁，迁移范式=照抄 `InstantInventoryCompleteStreamService`）。六大报表页的真实读取形状同步查清：全部是客户端驱动的逐批 GET OFFSET 连续读完（`ReportPagedRead`→内层 `loadCompletePagedResult`，`PagedListController.load(fetchComplete:)` 的 requestedPage 不起作用），无翻页、无流；财务每批对全集重算 `ROW_NUMBER()`；批间无共享快照、行无身份去重（代码推定：完整读取超过 30 秒后续批不再带 metadataReuse，服务端重算统计并返回新的 `statisticsGeneratedAt`，首批 revision 比对将报 SNAPSHOT_CHANGED）——这些结构性风险记录在案，待生产数据量证实超过门槛后按同一范式迁移。
  - **本次连带修复（客户端批次上限 200→1000 的漏网页帽）**：任何在 `fetchPageSized`/`loadCompletePagedResult` 阶梯路径上的服务端页帽 <1000 都会在结果 >1000 行时被客户端的 size=1000 请求打穿（offset 语义错位 → 「分页信息异常」或恰 1500 行时静默重读）。2026-11-09 晚补抬 11 处：`FinanceProjectedReportTable`、`FinanceReportService`（往来对账单 buildRunningBalance、账户流水）、`FinanceAuxiliaryService.list`、`FinanceStatementDocumentService.originalTable`、`NativeFinancialPostingAccountService.configurations`、`CustomerPrepaymentQueryService.list`、`ProcurementPayablesService`、`ProcurementIqcRejectionService`、`SubcontractLossClaimService`、`SupplierSettlementService`，统一取 `CompleteReadBatchPlan.MAX_BATCH_SIZE`。刻意保留的 <1000 页帽（不在客户端阶梯路径）：货架标签导出的服务端自循环 500、仓库出库行内明细 500、GL 经营损益 `ReportRowWindow` 500（模板行数有界）、GL 期初/物料来源内部读取 200、应收应付往来定位 100（客户端自驱固定页大小并跟随 totalPages）。
  - 单扫描流迁移登记（唯一维护台账）：已迁=8 个主档+business-references summaries、即时库存主页面（2026-11-09）；本批测后不迁=上表全部候选（数字为准）；待生产数据复测=六大报表页、任务中心全家（探针类随 `*LadderProbeTest` 常驻可复跑）。

**2026-11-09 补充：分批渐进读取统一挂顶部加载进度通知（[TableLoadProgressNotice](../02-组件库/TableLoadProgressNotice.md)）。** 整张通知卡背景即进度条：已加载区从最左向右铺满全高，文字「正在加载数据：NN%」（NN% 加粗）恒居中浮在进度背景上，左侧细线旋转环完成后换对勾，右侧保留红色圆形关闭按钮（只隐藏本轮提示，读取继续）。进度 = 已验证累计行数 ÷ 服务端 total（同一查询口径），总量未知显示不定进度扫动光带，加载中封顶 99%、只有完整结果返回才 100%；失败/退休立即退场。加载开始即出现（150ms 消抖只吞秒失败/缓存命中的闪现）。接入零成本：`loadCompletePagedResult` 对带渐进槽的主表读取自动上报（`CompleteReadProgressReporter`），货品资料/即时库存/财务表格/各任务中心等全部覆盖；按钮等待仍用 `UtenBusyOverlay`、导出等长等待仍用 `UtenProgressDialog`，互不替代。


不要用一个组件强行覆盖所有数据形态：

- 卡片摘要：`UtenResponsiveGrid`。
- 完整卡片列表：`UtenResponsiveGrid`；大量已加载项使用现有虚拟窗口。`UtenPagedGrid`保留兼容构造但不再切页，`UtenPagination` / `UtenGridPager` / Picker页码控制不显示业务分页。
- 主数据、报表式行列展示：`MasterDataTableView`。
- 单据编辑明细：`UtenEditableGrid`。
- 简短设置项、菜单、时间记录：Material 列表或模块私有组件均可。

两个表格组件的列宽契约：都可拖表头列右边界调宽窄，手动宽度优先。默认宽度取表头和单元内容中较宽的一侧，分别计入内边距及其图标、间距和控件占宽。`MasterDataTableView` 直接量纯文本，复合单元可提供 `measureValueOf` 和 `measureWidthOf`。`UtenEditableGrid` 分批量取 `textOf` 并加入 `chromeWidth`，在首次有内容时一次发布默认宽度，后续输入只增长。缺少可测内容的复合控件使用声明宽度，`minimumWidthOf` 声明必要操作下限。双击列边界恢复自动适配。自动宽度通常封顶 480，超长值仍可通过单元内滚动或提示查看。详情见 [UtenTableColumnKit.md](../02-组件库/UtenTableColumnKit.md)。2026-09-04 起，业务页可显式开启 `UtenEditableGrid.showColumnSettings`；**2026-09-05 起两个表格组件的表头体系收敛为同一份实现 `UtenTableColumnKit`**（见 [UtenTableColumnKit.md](../02-组件库/UtenTableColumnKit.md)：「表头设置 x/y」深绿实心大按钮 → 按钮处锚定的浮层勾选列表——全选行/勾选显隐/(编辑表)拖拽排序与恢复默认；表头纵向拖出隐藏 = root Overlay 最顶层跟手浮层——原格变淡、过阈值红底红×、拖回取消；**表头横拖 = 直接换位（2026-09-11 起按下即拖，不再需要长按）**——跟手浮层+插入位指示线+松手落位，与弹窗排序同一份顺序状态；方向消歧交给竞技场（横拖换位 / 竖拖移除），代价是表头本身不再能横拖滚动表格，表体横拖与底部横滚条仍在）。**必填列（`required: true`）锁定不可隐藏**（弹层勾选禁用、拖出无效；排序不受限），非必填列仍受「至少保留一列」兜底；列定义可带 `headerInfo` 在表头渲染 ⓘ 信息图标（悬停/长按弹说明，如销售折扣列「1 = 保持原价；0.9 = 9折」）。至少保留一列，隐藏列不销毁控制器或提交数据。嵌入式/任务表默认关闭，避免无授权的布局变化。任务表必须让 `canSelectRow` 同时约束复选和右键动作资格；保存/提交期间传 `selectionEnabled:false`，统一冻结选择、批量动作与行菜单。编辑模式（`showAddRow`）操作条只保留「表头设置」与宿主批量动作——全选走表头复选框、复制/粘贴/批量删除走行级右键/长按菜单（2026-09-05 与货品资料统一，任务/只选模式不变）；**纯勾选模式（`selectable` 且非编辑）点行身非输入区 = 切换选中**（与 `MasterDataTableView`「单击行选中」契约统一；输入/按钮格自己消费点按，不会误触）。**2026-09-21 起多选的适用范围写明包含「详情页里的树表」**：货品详情「组装信息」页签的 BOM 树按 `MasterDataTableView.selectable` 开勾选列，**批量删除的 danger「删除」按钮挂在表头工具条 `toolbarActions` 里(与添加组件/导出组件/编辑/审计模式同排，全屏表格路由同位置也渲染)，不走右下悬浮组** ——该页不传 `batchActionsBuilder`，「已选 N 项 + 清除」胶囊因此留在表头上方工具条(`showSelectionSummary` 默认 true)；按钮勾 0 条灰、勾 1 条起可用，单条与多条共用同一条批量路径，全页只有一个「删除」。树表接入的三条口径(`idOf` 取行自己的业务 id 而非货品 id、表头三态只覆盖当前可见行、选中集跨父实体时按父分组调批量端点)见 [MasterDataTableView §七](../02-组件库/MasterDataTableView.md)；同时立一条通用规矩——**宿主页面自己存在「单击行 = 执行某个动作」的模式时(如 BOM 审计模式点行打「已核对无误」)，该模式期间必须关掉 `selectable`，切换模式时连勾选集一起清空**：同一个单击不能既是打标又是勾选，留着看不见的勾会让下一次批量动作多删几行。**另一种该关的情形：勾选在该页接不上任何动作(权限全无)时整列不渲染**——BOM 树的门控是 `!审计模式 && (删除 || 编辑 || 新增)` 三权限任一，一个都没有的只读账号看到一整列勾选框却没有任何按钮可接，按「隐藏而非禁用」整列不给。

**状态列与状态胶囊必须走共享色调(2026-10-04, ADR-150)**：表格状态列的底色只能来自 `UtenStatusBadgeType` 共享色调的显式映射(`utenStatusBadgeCellColor`, ADR-169 起 `utenStatusLabelType` 猜色兜底已删除)或 `UtenColors` 语义令牌(如车间任务的 `productionReadinessCellColor`)；独立胶囊用 `UtenStatusBadge` / `UtenDocStatusPill` / `UtenSegmentBadgeLabel`，不再手写 `UtenRadius.pill` 胶囊或自绘状态格。原因：AI 助手按单元格最终底色和状态组件反查颜色中文名(`utenColorName`)生成「颜色 = 状态 = 含义」图例，手写色值只能按色相猜，自绘格根本读不到。状态值有业务含义时在列定义上给 `legendOf`(值 -> 含义，走 l10n)，不在注释里写颜色说明。详见 [AiPageContext](../02-组件库/AiPageContext.md)。

**单元格内容一律左对齐(2026-10-10 全站口径)**：所有自制表格（`MasterDataTableView` / `UtenEditableGrid` / 修订表 / 自绘 `Table`/`DataTable`）的表头与数据格统一左对齐，金额、数量、汇率等数字列也不例外——`EditableGridColumn.numeric` / 业务列的 numeric 只再保留 tabular 等宽数字与数值键盘语义，不再驱动右对齐；页面 cellBuilder 与输入格不再写 `textAlign: TextAlign.right/end`。表格外的信息行（`UtenInfoRow` 的「标签: 值」）、Dialog 按钮区与合计条 `UtenTotalsSummaryBar` 的右端「标签: 值」序列不属此列。

十几年数据量场景必须服务端筛选、排序、分页；前端本地排序只允许用于明确受限的小结果集。排序应包含唯一键作为最后一项，防止翻页重复或漏项。

**多值单元格统一走 `UtenMultiValueCell`（2026-10-29 全站口径，源自仓库任务中心「生产工单」列）**：一格聚合多个单号/名称（销售订单号列表、申请来源、报销类别、变更字段、负责人等）时不得把全量顿号串塞进格内——格内最多显示首个值 +「等 N 个」（`utenMultiValueSummaryOf`），Tooltip 悬停见全量，点击格子弹窗列出全部；能按值跳详情的场景在弹窗内逐条提供「查看详情」（`onDetail`/`detailAvailableOf`），无落点的只列全部。`MasterDataTableView` 用列 `cellBuilder`、`UtenEditableGrid` 用 `EditableGridColumn.cellBuilder` 接入；`value`/`textOf`（导出、打印、复制、列筛选）仍由调用方提供全量串，不经过组件。已迁移：仓库任务中心生产工单（弹窗跳生产计划详情）、财务应收应付编辑网格/台账/选择器的销售订单号、委外与采购申请来源（采购保留整格外链跳转、仅显示截断）、报销类别、HR 与个人档案变更字段、仓库资料负责人列、生产调度与进度「进行中」产品名称/货品编码/颜色（V969 全量载荷，名称与编码弹窗按条跳货品详情；「编号」表头同步改名「货品编码」）。

### 修改后重新提交的审核对照

此规则适用于所有业务模块和所有同类审核入口，不以销售单据为限。退回后修改重提、已审批后修改复核，以及处置/终止申请被拒后重新申请，都应核查是否需要展示真实前后内容。

- 明细对照复用 `UtenRevisionTable`：修改或删除的旧整行红色并用横线贯穿；修改后的完整行在下方绿色展示，`changedKeys` 指定的实际改动单元格红字加粗；纯新增行保持绿色，未改行保持中性。
- 只有表头或申请字段变化时复用 `UtenRevisionFields`，不复制“以前/现在”长段落；顶部保留审核重点。
- 修改审核页顶部用醒目的业务名称，例如“销售订单修改”“采购订单修改”“报销单修改”；单号、轮次和当前审核状态放在次级信息。不能只写“待复审”而看不出修改对象，首次提交也不能误标为修改。
- 前后版本取业务提交/决策快照，不从通用审计或当前主档反推历史事实。未保存的旧值明确提示；金额、币种、数量、单位和来源身份必须对应各自版本。
- 行号重排、数值末尾零和核验状态不应制造假修改。明细 UUID 会重建时先按完整内容保留重复次数，再在身份唯一时配对；不猜测歧义行。
- 列表、详情、审批弹窗和业务状态机需逐入口核查。取消后另建新单、红冲终态、同一请求网络重试，不冒充同单修改重审。

当前接入与逐页证据见[重新提交审批差异展示](../03-页面/重新提交审批差异展示.md)。

## 六、主题、响应式与可访问性

公共组件和页面都必须：

1. 颜色走 `Theme.of(context).colorScheme` 或 `UtenColors` 语义 token。
2. 文字走 `textTheme`，并允许全局 `textScaler` 生效。
3. 间距、圆角、阴影和动画使用 `UtenSpacing`、`UtenRadius`、`UtenElevation`、`UtenAnim`。
4. 用 `LayoutBuilder` 依据实际父容器宽度适配，不只看屏幕宽度。
5. 点击目标、焦点、tooltip/semantics、键盘操作和对比度满足可访问性要求。
6. loading、disabled、empty、error、hover、focus 和 pressed 状态完整。
7. 在低性能档关闭非必要模糊和重动画。
8. 所有用户可见括号使用 ASCII 半角 `()`，禁止新增 U+FF08/U+FF09。

## 七、状态、权限与安全边界

- 组件内部瞬时 UI 状态可以用 `StatefulWidget`；跨组件业务状态和请求状态使用 Riverpod。
- 页面控制“是否展示/是否可编辑”只是用户体验，后端仍必须独立鉴权和校验数据范围。
- 未拿到权限或权限加载失败时 fail closed：隐藏或禁用高风险动作。
- 不把 token、密钥、完整隐私数据写入 Widget、路由参数、日志或错误提示。
- 导出、下载、支付、审批、删除等动作必须防连点；后端同时保证事务、幂等和审计。

## 八、新增组件流程

1. `rg` 搜索现有能力和全部适用调用点，登记优势、缺陷、边界及业务差异。
2. 比较现有方案，保留正确能力，确定基础、共享业务或模块私有层级。
3. 设计最小 API，写明状态、响应式、主题和错误行为。
4. 实现并增加必要的 widget 测试。
5. 迁移全部适用页面、弹窗、详情、历史、报表和导出；完成公共及调用方回归和实际交互验证，保留 B0 响应性保护。
6. 确认旧实现无有效调用、兼容需求和回归问题后清理，并记录必要的保留差异。
7. 更新[组件总览](../02-组件库/组件总览.md)、相关页面文档及完整调用方迁移清单。
8. 运行 `dart format`、`flutter analyze` 与相关测试，按[公共能力规范](16-统一实现与公共能力.md#七用证据验收统一成果)汇报证据。

没有硬性“必须先建空文档”或“必须更新 barrel”的流程；文档必须和真实 API 同步，测试必须覆盖高风险交互。

---

## 九、禁止事项

- 禁止引用 `UtenStatCard`、`UtenAnimatedNumber`、`UtenListItem`、`UtenSelect` 等已删除名称。
- 禁止复制公共组件到业务页面再局部修改。
- 禁止在业务文件新增裸 `Color(0x...)` 或复制阴影/圆角色板。
- 禁止用前端隐藏代替后端权限校验。
- 禁止大结果集全量拉取后在客户端分页、筛选或排序。
- 禁止异步按钮在异常后永久 busy，或允许重复提交高风险动作。
- 禁止公共组件直接发业务 API 请求。
- 禁止提交调试 `print`、样例数据和无调用的占位组件。

## 十、提交前检查

- [ ] 新 UI 已复用现有组件，或有明确理由留在模块/页面私有层。
- [ ] 公共能力的全部适用调用方已有迁移及回归清单，旧实现清理或保留理由明确；未仅凭组件单测或搜索结果宣告完成。
- [ ] 没有引用不存在、已删除或仅在规划中的组件。
- [ ] 权限失败时 fail closed，后端仍有相同权限与数据范围校验。
- [ ] loading/disabled/error/empty 和同步异常路径完整。
- [ ] 副标题和独立提示句已删除，或收进紧邻对应标题/字段标签/列头的行内提示 icon；悬停、点按和键盘均能查看说明。
- [ ] 所有需加载等待的按钮均已配合项目自有加载弹窗，防连点与成功/失败/取消/中断收尾完整，未仅用按钮内 loading 代替。
- [ ] 长列表使用服务端分页与稳定排序。
- [ ] 浅色、深色、窄屏、桌面和字体放大已检查。
- [ ] 无新增业务裸色、重复 UI、调试输出或敏感数据泄露。
- [ ] 员工选择主行/已选值为 `姓名(工号)`，部门位于副行。
- [ ] 新增或修改文案只使用 ASCII 半角 `()`。
- [ ] 状态列/状态胶囊走共享色调，有业务含义的状态列给了 `legendOf`(ADR-150)。
- [ ] 成本、工资、信用额度、个人信息(证件号/银行账号/手机等)列与字段写了 `aiSensitive: true`，尤其是列名只是「单价」「金额」这类通用词时(AI 助手的敏感词表管不到)(ADR-150)。
- [ ] `flutter analyze` 和相关测试通过，文档已同步。

## 悬浮操作区的正文留白（2026-09-12）

右下角动作统一 `UtenFloatingActionGroup`，主操作采用 `UtenButtonType.danger`。独立滚动正文底部使用 `UtenFloatingActionGroup.scrollClearance`（200dp）；共享表格带 `batchActionsBuilder` 时自动留白，页面外置悬浮按钮的表格传 `bottomContentPadding`。这是可滚动内容的一部分，末行应能移到按钮上方；横滚条仍贴近数据，不能随空白一起沉到页面底部。避免表格与页面分别重复绘制“已选 N 项”。

## 2026-10-13 全平台界面统一

新增/修改业务弹窗只用 `UtenAlertDialog` / `UtenDialogFrame`；简单确认走 `UtenDialog.show`。`Dialog.fullscreen`只用于明确全屏场景。复杂可滚表体显式保留自己的有界滚动，不重复套正文滚动。

尺寸与字体从 `UtenControlMetrics`、`buildUtenTextTheme`和 `UtenRadius`取值；分类用同一实际宽度适配策略，不能新增横滚分类或缩字替代。单元格输入主题统一密集字号与最小高，宽度测量使用实际TextScaler，缓存不能仅比较scale(1)。

页面清单同时覆盖widgets目录业务弹窗、选择器及material_analysis等part子页面，不能只数 `*page.dart`。已确认退役的实现可删除；同文件内部使用、导出或测试使用的类不能仅因外部引用少而删除。详见[全平台覆盖与验收](../99-项目治理/2026-10-13-全平台界面整改覆盖与验收.md)。
