1两份方案各看到一半（仲裁）

不矛盾、互补，但各有盲点；融合后才完整。

甲 · 净需求模型（对、乙漏）

  • 子件应按父件净产出（扣已确认在途）展开，现状只扣现货 → 在途抵了父件，下层仍多备
  • 双口径分离：计划口径减在途、实物开工只认合格入库
  • 在途失败/撤销要回补被净掉的下层未下达需求
+

乙 · WIP 落地修复（对、甲漏）

  • Java 已放开跨路线在途调入，DB 触发器还锁着 → 现在落库必报错
  • 现货让料被 depth=1 锁死，深层父件让不了料
  • 有子层委外当来源被容量函数清零；MOQ/子层处置链其实早已设计

为什么必须同批（强耦合链）

放开在途调入到自制/有子层委外（乙）→ 父件缺口被未入库在途部分覆盖→ 下层必须按父净产出 N 展开（甲）→ 在途黄了回补未下达下层（甲）→ 现货让料放开全深度才能同样净抵（乙）
只上乙：下层多备料（数据错） 只上甲：在途调不进、深层让不了（空转） 同批：既不积压也不断料

3统一模型：双口径 + 五个量

计划口径（备多少 / 还要不要下单）

计入合格现货 + 已确认在途；驱动净需求、子件展开。

实物口径（能不能领料/开工）

只认合格入库；在途不算，不提前 READY/开工（现状门禁不动）。

G
毛需求
父净产出×单耗
S
现货
合格库存+精确+现货调入
F
已确认在途
批准在外单+转入+认领
N
计划净需求
下层按它展开
P
物理缺口
开工只认它
N = max(0, G − S − F)　·　P = max(0, G − S)　·　子件毛需求 = 父 N × 单耗
铁律：① 父 N=0 → 整枝未下达需求归零；② 只缩"未下达量"，已下达单冻结不回流；③ 在途未入库不提前开工

4P0 一个不可拆变更集（同批开发、同批测试、同批上线）

P0.1 解锁
跨路线在途调入

V574 触发器目标改白名单 BUY/SUBCONTRACT/MAKE；Java 排除锚点/前置自制行、SHIP 段

P0.2 净算
子树按父 N 展开

投影加 F/N；父产出由 shortageQty 改为净产出（复用 activeFuture）；执行门禁仍用 P

P0.3 回补
在途失败/撤销

按谱系恢复父 N 与下层未下达需求；已下达部分只提示不改

P0.4 全深度
现货让料删 depth=1

删 SQL 两处 + Java 一处；borrow 维持 depth=1；守恒测试锁定

P0.5 委外来源
容量改外部未回厂

去子层清零；前置自制不计入；拿不稳先只开"订单批准后"

⚠ P0.1 与 P0.2 强绑定：放开调入入口的同一批，必须把子树净算与回补一起上，否则要么报错、要么下层需求数字错。

5三种调入 × 对子树影响（定稿）

调入减 N减 P下层未下达需求失败/边界
现货让料（全深度）是是立即按 N 缩减原计划优先待补
专属在途转入firm 是否按 N 缩减（新增）入库才减 P；失败回补
公共在途认领firm 是否按 N 缩减（新增）带 BOM 委外不吃公共超量
硬边界：只能调入"最终件"。锚点/前置自制行（MAKE_COMPONENT、SUBCONTRACT_MAKE）、自制在制、委外前置半成品、委外商处的料，一律不能当调入目标或来源；跨主仓走真实调拨单。

6有子层委外当"在途来源"的容量三阶段（最难项）

① 通知委外前

无外部订单 → 容量 = 0，不可转出（自制半成品绝不能算可转量）

② 订单批准后·回厂前

容量 = 外部订单批准量 − 已回厂 − 已转出（可转）

③ 回厂合格后

转为现货权益走现货让料，在途容量递减到 0

灰度兜底：若"仅外部未回厂"容量口径真库测不稳，本期先只开放阶段②，①与自制中一律不可转。
