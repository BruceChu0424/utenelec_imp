# 通知详情页

> 路由：`/notice/:id` · 实现源：`lib/features/notice/pages/notice_detail_page.dart`

## 一、定位

员工阅读公司通知正文的详情页。

- 解决的问题：展示通知标题、发布人、发布时间、正文（可选中复制）、附件、阅读时间。
- 产品位置：从 [通知列表页](通知列表页.md) 点入，单向只读页。

## 二、入口与导航

- 进入路径：
  - [通知列表页](通知列表页.md) → 点击列表项（同时标记已读）
  - 推送通知深链（Phase 2+）
- 在导航中的位置：业务详情子页。
- 离开去向：返回 [通知列表页](通知列表页.md)。

## 三、响应式布局

- compact（手机，< 600dp）：

  │                        │
  │ ┌────────────────────┐ │

  │ │ 国庆假期为 10.1-10.7 │ │

  │ └────────────────────┘ │
  │                        │
  │ 附件                    │

- medium（平板，600-840dp）：内容居中约 600dp 宽。

## 四、涉及的 Uten 组件

- `UtenAppBar`（带返回按钮）
- `UtenCard`（正文卡）
- `UtenStatusBadge`（类型徽章 + 置顶徽章）
- `UtenEmpty`（数据 null / error）
- `UtenColors`（附件图标 teal 色）
- Flutter 原生：`SelectableText`、`CircleAvatar`

## 五、功能点

1. **顶部徽章行**：
   - `UtenStatusBadge` 显示通知类型（8 种 `NoticeType` 对应 badge type + 类型 icon）。
   - 工作类（`type.isWork`：task/approval/workflow）追加 accent 色「工作」徽章。
   - 若 `priority.showBadge`（important/urgent），追加「重要」（warning 橙）/「紧急」（danger 红）徽章。
   - 若 `topPriority`，追加一个 warning 色"置顶"徽章。
2. **标题**：`headlineSmall` 粗体，与正文明显区分。
3. **发布人信息行**：CircleAvatar（类型色背景 + account_circle 图标）+ 发布人名 + 发布时间（"yyyy-MM-dd HH:mm"）。
4. **正文卡** `UtenCard` 内 `SelectableText`，`bodyLarge` + 1.7 行高，便于阅读和复制。
5. **附件区**（若 `attachments.isNotEmpty`）：
   - 标题"附件"。
   - 每个附件一个 `Container`：左侧 teal 色文件图标，中部文件名，右侧下载图标。
6. **阅读信息**（若 `readAt != null`）：底部 surfaceContainerLow 容器 + check_circle 图标 + "已于 yyyy-MM-dd HH:mm 阅读"。
7. `AsyncValue.when` 三态：loading 用 `CircularProgressIndicator`、error 用 `UtenEmpty.error`、null 用 `UtenEmpty`"通知不存在"。

## 六、功能链路图

```mermaid
flowchart TD
    A[列表点入] --> MR[markNoticeRead 若未读]
    MR --> G[/notice/:id]
    G --> W[watch noticeDetailProvider]
    W --> S{状态}
    S -->|loading| SK[spinner]
    S -->|error| ER[UtenEmpty.error]
    S -->|null| EM[通知不存在]
    S -->|data| R[渲染徽章+标题+正文+附件]
    R --> ATT{点击附件}
    ATT --> DL[下载（Phase 2）]
```

## 七、涉及的数据实体

→ 见 [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `Notice`：详情主实体（title / content / type / publisher / publishedAt / topPriority / attachments / readAt）
- `NoticeType`：5 种枚举
- `NoticeReadRecord`：阅读时间 readAt 来自该实体的首次阅读记录
- `Attachment`：附件（Phase 1 仅用文件名表示，后端接入后落地为完整 Attachment 实体）

## 八、权限要求

- **全员可见**。
- 数据范围：员工只能看到发布范围包含自己的通知（按部门/工种/全员）；后端必须校验。
- 关键操作权限点：本页只读 + 触发本人 markRead。

## 九、边界情况

- 无数据时：`notice == null` → `UtenEmpty`"通知不存在"。
- 加载失败时：`UtenEmpty.error` + 重试（`ref.invalidate(noticeDetailProvider(noticeId))`）。
- 性能档 = lite 下：正文区去掉卡阴影，附件图标用纯色矩形代替圆角图标容器。
- 网络断开时：Phase 1 Mock 无影响；后端接入后：
  - 通知正文应离线缓存（重要公告支持离线阅读）。
  - 附件下载必须在线，断网时点击 Toast 提示"请检查网络后重试"，并支持后台下载队列。
  - 长正文应做分页或折叠展开（避免一屏渲染过万字符）。
