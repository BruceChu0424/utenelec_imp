## 已核实可复用的能力

基线为本轮隔离工作区继承的 `35b705f5d`，不把旧文档测试当作现证。

- `Pageables.of` 将常规 JPA 每页限制在 1..100；`TableSort.resolve` 为非自定义排序补充标量 `id` 尾序；`NameRefKeyword.page` 保留搜索相关性并补稳定排序。不是所有自定义原生 SQL 都因此自动受保护。
- 销售订单页已有页内 seller 批名称；采购/委外订单已有 `latestForOrders` 审批投影；生产进度已有子计划和物料进度批读取。没有重新实现这些能力。

- 商业单据的大多数 `toList` 已是纯投影；搜索到的许多 `nameOf` 位于单据详情，不能把它们误报为列表 N+1。

## 本轮已写代码及必要差异

1. 客户/供应商页、六种仓库历史列表与详情、短交案件及事件姓名复用 `EmployeeNameResolver.namesOf`。仓库历史缺失身份保持每行自己的冻结名，避免某行回退名污染另一行。
2. 主档历史差异的 15 类主档引用仅批读标签字段；员工使用已有 `namesWithCodeOf`，部门新增 `DepartmentNameResolver.namesOf`。只为实际可显示的变更字段读取标签；客户保留功能权限、对象与共享授权，货品保留原 owner 规则，账户自身币种/类型例外单独保存。未知、已删、格式无效、无权保持不同提示。恢复预览、业务锁、审计与原始快照不改变。
3. 原生筛选桶统一走 `NativeFacets.rowsOf`，默认沿用 `TableFacets.DEFAULT_LIMIT=500`，保留更小的既有上限和显式 0。17 个执行调用经同一公共入口，旧的无界 `rows` 入口降为私有。桶限制不截断业务 count、totals 或状态统计。
4. 可发订单行补齐服务端价格遮蔽，沿用 `SalesPriceMasker`；增加 `i.id` 尾序。新增共享 SQL 的 page/selection API 和旧 List 兼容边界；完整前后端与实际交互验证仍待根任务回填，不能因代码存在勾完。

名称结果只在当前操作内存在，不建立跨用户、跨服务器缓存。现有字典的 session 隔离和写后失效继续保留。不同币种、单位、来源、库存归属和生命周期未强行合并。
