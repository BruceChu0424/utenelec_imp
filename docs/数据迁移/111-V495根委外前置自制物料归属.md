# V495 根委外前置自制物料归属

日期：2026-09-06。状态：本地源码候选，未更新现有业务数据库。

迁移：[V495__subcontract_root_preparation_material_identity.sql](../../server/src/main/resources/db/migration/V495__subcontract_root_preparation_material_identity.sql)。决策依据：[ADR-071](../99-决策记录-ADR/ADR-071-下达车间原子化与计划侧齐套判断下线.md)、[ADR-073](../99-决策记录-ADR/ADR-073-本批物料履约与同主仓分仓领料.md)。

## 根因

计划锚点简化后，`SUBCONTRACT_MAKE` 不再展开第二份 BOM。但根产品选择委外仍沿用旧规则，隐藏原产品 BOM，造成原树与锚点两处都没有子件。即使补回子件，V489 的原树匹配函数仍要求 `material.parent_node_key = parent.node_key`；根供料锚点是 `ROOT_SUPPLY`，其真正直属子件的 `parent_node_key` 为空，因此精确到货权益仍无法用于前置生产。

## 最终口径

- 顶层和中层有子件委外都保留原树唯一的一份子件需求。路线确认后可下达委外前置任务，子件不齐不拦截计划下达；车间仍需全部所需物料合格入库并实际领用后开工。
- `SUBCONTRACT_MAKE` 仅作为委外目标件的生产计划锚点，不再次创建或下达子件。无子件委外沿现有申请、订货及财务路径。
- 根产品直接采购保持不展开自制 BOM 的规则。
- V495 只调整 `fn_analysis_plan_material_matches`：根锚点匹配同分析、同原需求行、深度 1 且父路径为空的真实子件；中层仍按准确父节点路径匹配。另一分析、兄弟路径、已失效节点和已删除来源仍不能取用。
- 正式物料预留、齐套提升和权益事件继续共用此函数，实仓 UUID、来源物料 UUID、数量与换算率约束保持不变。
- 根锚点的分批数量映射到原树直属边，整包和固定批次按每个实际批次计量。委外前置自制已经领用的原材料，在目标件等待外协、尚未回厂时继续覆盖本批需求，避免生成第二遍采购缺口。

## 存量与验证

迁移不改任何业务数据。更新后，授权刷新会恢复原有物料节点并保持 UUID 和已确认路线；已有 WAITING 任务通过合格入库触发或“重新检查物料”继续判断。不能复制历史供料申请来补齐旧页面的空树。

`FullChainEndToEndTest` 分别验证根层和中层委外先下达 WAITING、原树采购料在兄弟子仓品质合格入库后转 READY，及前置生产、实收入库、自动申请、财务、委外出仓、回厂验收和销售归属。断言包含原子件 UUID 保留、锚点无重复 BOM 和前置入库后不重复补料。叶节点委外沿既有直接申请用例回归。实际测试结果记录在本轮平台验收文件。

目标非空库、真实计划/车间/品质/仓库/委外岗位与实物验收仍需独立完成；本文件不是部署完成证明。
