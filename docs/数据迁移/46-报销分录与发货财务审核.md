## 一、报销（一般费用单）支付完自动生成总账分录 + 财务确认

- **V124**：`finance_expenses.gl_status`（0 未过账 / 1 已过账待确认 / 2 财务已确认）+ `gl_voucher_id`。
- **审核钩子**（`FinanceExpenseService.approve` → `GlPostingService.postExpenseDoc`）：
  借 费用科目（按行 expense_style_id）/ 贷 付款账户科目（account_style_id 解析：挂接科目→CASH/101→102），
  单号即凭证号（AUTO/EXPENSE，与月度 generate 幂等兼容——generate 按期间全删重建）。审核后 gl_status=1。
- **红冲钩子**：删该单 AUTO 凭证（级联分录），gl_status 回 0。
- **财务确认**：`POST /api/finance/expenses/{id}/gl-confirm`（仅已审核且已过账），gl_status→2；
  详情 DTO 已含 glStatus 供前端展示。

## 二、客户发货财务审核（现金客户仓库放行，不是汇率或收款审批）

> **现行覆盖规则**：V124 财务审核字段仍有效，但 V187–V189 已把它收口为现金客户开始拣货前的人工放行事实。该动作不填开账/到账汇率，不生成销售收款、本币金额、库存、AR 或通用总账；月结/账期客户没有这一现金放行硬门禁。进入 `SHIPPED` 后，普通出货红冲和财务反审均拒绝，纠错走销售退货质量冻结。

- **V124**：`sales_shipments.finance_audit`（0 未审 / 1 已审发货）+ 审核人/时间；`ShipmentDetail` 已暴露。
- **财务审核**：`POST /api/sales/shipments/{id}/finance-audit`（独立权限 `finance_shipment_audit`，不得复用只读报表权限），
  响应带结算方式 `priceStyle`、`cashClient` 和未收余额 `outstanding`，只供财务人工判断是否放行，不代表系统已自动匹配某笔到账；
  `/finance-audit-reverse` 仅在出货仍为草稿且仓库未开始作业（`PENDING_PICK` 或历史 `LEGACY_PENDING`）时允许。财务已审出货在反审前不能编辑、删除或驳回；进入 `PICKING/PICKED/SHIPPED` 后反审被拒绝。
- **新仓库闸门**：`SalesShipmentService.startPicking` 在 `PENDING_PICK → PICKING` 前校验现金客户 `finance_audit=1`；未放行则拒绝开始拣货。V187 前旧 `approve` 闸门只属于 `LEGACY_PENDING` 历史兼容链，不得写成新流程的正式出货节点。
- 月结/账期客户可按结算政策进入仓库作业，不需要财务“直接审出货”；其正式 AR 同样只在仓库 `SHIPPED` 时形成。
