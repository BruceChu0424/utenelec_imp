# IQC与收货金额精度断点审计

状态: 只读审计，金额方案未冻结。用户最新要求财务金额不能擅自四舍五入；本报告不把软件精度差额认作汇兑收益、损失或库存损失。

## 权威金额与计算边界

采购/委外收货当前由已财审订单行的数量、单价、原币总额、本币总额、汇率以及单独批准的超到份额派生。仓库到货登记不接受重新输入价格和币种。实际付款/收款、供应商真实贷项各自是独立已确认事实，不能用重新计算的派生数覆盖。

V510拟分开正常/补回的名义金额、实际新增应付、原失败资金来源。免费补回新增应付为0，但原费用和自有材料价值必须沿实际来源承接。当前候选仍有将原失败金额与新收货名义金额等同的断点，`source_amount`独立轴尚未落库，不能描述为已完成。

## 已定位的舍入与截点

| 位置 | 当前处理 | 原先意图 | 新要求下的限制 |
|---|---|---|---|
| `PurchaseReceiptAmountAuthority.authorizedSource` / 委外同名方法 | 超到原币 `money(qty*price)`；本币 `money(已round原币*rate)`；money固定4位HALF_UP | 与已财审金额和额外授权额度同一口径 | 乘积的有效位会在派生金额形成时丢失，未获用户授权 |
| 两个 `sourceAmounts` | 中间收货先按数量×单价round4，再换算本币round4；最后一批使用原总额减历史累计 | 最后一批保全整单原币/本币总额 | 整单加总守恒不代表每次金额精确；中间账量已受取整影响 |
| `ProcurementIqcReplacementAllocationService` | 每份实际退回的数量/原币/本币按比例divide12 HALF_UP，再金额或数量setScale4 HALF_UP；最后一片取源剩余 | 不超过单个原失败份额，并吸收尾差 | 两次精度截断；数量规则与资金规则混在相同辅助函数，不能直接推广为财务规则 |
| `ProcurementReceiptConsiderationService.portion` | `amount*qty/total`固定4位HALF_UP，整份取原值 | 名义/免费/已贷项、品质、仓库、信用份额复用 | 同一辅助函数同时处理数量和金额，财务不能继续直接采用 |
| 同服务 `cumulativeSlice` | 累进两个round4结果相减 | 最后一片回到原总額，避免加总超额 | 只能保证总和，不能证明每片都是实际权威金额 |
| `ProcurementInspectionService.proratedIncrement` | IQC PASS/FAIL实际放行金额按累计基本量分摊到4位 | 品质分批放行与最终金额守恒 | 不应将分配精度当作真实费用变动；仓库再次复用此方法进行分批入库 |
| `ProcurementIqcRejectionService.failedAmounts` | 历史路径按品质事件累计量分别round4原币/本币；新路径拟读冻结切片，但切片本身仍round4 | 冻结拒收索赔份额 | 换读新表不能消除上游舍入，需统一金额权威 |
| 同服务 `money/moneyValue/quantity` | 三者都setScale4 HALF_UP，其中moneyValue还用于接口金额格式化 | 固定输出格式及旧数据契约 | 格式化不应修改金额，展示规则应独立于存储/记账 |
| 同服务失败业务量换算 | `failedBase/receivedBase`先divide12 HALF_UP，再乘receiptQty后round4 | 从基本量回到原单单位 | 这是数量换算截点，不应混作财务金额舍入依据 |
| V510 SQL候选 | nominal/payable、quality/funding/credit/stock/settlement/review金额均NUMERIC(18,4)；两处SQL用round4复核累进分摊 | 数据库与Java一致 | 删除Java的setScale仍不够，数据库列也会在保存超精度输入时改变值 |
| 原有收货实体/表 | qty/price/amount_original/amount_local均18,4，unit_rate为18,6 | 旧库标准尺度 | 单价、数量乘积可能多于4位，需要分开输入精度、计算精度和最终权威金额 |
| 原有IQC表V440/V446 | 失败/替补、放行、实际入库金额均18,4，部分函数变量也18,4 | 旧批量来源守恒 | 新模型若只扩一张表，经过旧函数变量/字段仍可能再次丢精度 |
| `ArApLedger` | 原币、本币原额/累计/抵销/余额均18,4；汇率18,6 | 对应旧统一台账 | AP/收付/抵销和GL须同步方案，不能由V510局部决定新的货币金额尺度 |

其中 `setScale(4, UNNECESSARY)` 是输入超精度拒绝而不是四舍五入，例如IQC基本量和仓库数量校验。是否继续4位数量是另外的计量约束，不能与金额规则混淆。

## 可从合法输入重现的例子

订单业务数量0.0002、单价0.5、单位换算率10000、汇率7，整行基本量2、原币0.0001、本币0.0007。全部输入满足当前数量/单价4位、换算率/汇率6位定义。

若两次品质FAIL各基本量1，数学上的同比分配是每片原币0.00005、本币0.00035。当前累进4位处理变成第一片(0.0001,0.0004)、第二片(0,0.0003)。这个“第二片原币0、本币非0”是软件分配精度生成的现象，不能因此自动建立汇兑/成本损益。

在原币/本币被人工改变以前，还必须区分供应商实际确认的贷项凭证金额与上述内部成本份额。若真实贷项只有第一片，系统不得自行声称第二片的外币金额为0；若实际凭证明确覆盖整行，必须保存其真实原额并保持后续内部份额与该原额精确关联。
