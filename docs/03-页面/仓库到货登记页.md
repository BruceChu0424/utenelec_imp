## 2026-08-31 IQC 两阶段后置覆盖

本页“登记并送检”只完成到货登记、收货审核和 IQC 隔离，不等于正式库存入账。后续固定分两步：

1. 品质部在待检处置页登记 PASS/FAIL；PASS 只增加 `passed_base_qty` 并形成仓库待入库任务；
2. 仓库在待入库任务中核对本次实际入库量和实际库位，可分批确认；只有确认事务才写
   `stock_movements(DIR_IN)`、增加 `warehouse_stocked_base_qty`，并按实际入库量刷新物料分析与生产齐套。

货品主档 `stock_place` 只是当前建议库位，不是历史入库库位；实际库位必须随仓库确认事件保存。
红冲只反向已实际入库量，已 PASS 但尚未确认的数量只取消待入库任务。完整规范见
[采购 / 委外 IQC 合格待入库任务页](采购委外IQC合格待入库任务页.md)。本节覆盖下文所有
“PASS 自动入库 / 合格放行即库存 / 仓库无需操作”的旧页面演进描述。

## 一、定位

仓库登记实际到货的**独立页面**（此前复用采购/委外收货单编辑页的到货模式）。
分立的原因：收货单编辑页包含币种/汇率/结帐方式/单价金额等采购视角字段，
仓库不该看到价格；保存后跳收货单详情同样会露出金额。本页登记带单位的业务实收量、可选实际
总重量与库位，
不涉及任何价格与金额。

- 本页创建的仍是 `purchase_receipts` / `subcontract_receipts` 草稿（走各收货单
  Service 的 create 链路）：**审核通过后采购/委外侧自动有这张收货单**，无需重复录入。
- 审核时服务端 `recomputeReceiptAmount` 从订货明细权威回填单价金额——客户端不带价格
  也不影响立应付；超量到货仍走进货异常隔离链（PENDING_FINANCE → 财务定案）。

## 二、页面结构

1. **提示横幅**：来源订货单号（只读文本）+「请按实际到货数量、单位和实际重量登记」说明
   （超量如实填写不会入库/立应付，自动隔离转财务审批）。
2. **表头**：单据日期（必填，默认今天）、供应商（只读）、**入库仓库**（必填）、
   **采购员**（仅采购收货；必选，预填订货负责人，选择器默认收敛采购部 `SUB_PURCHASE`）、
   **收货人**（必选，默认当前登录人，默认收敛仓储部 `SUB_WH`——收货人是仓库收货人，
   不是采购员）、备注。**不出现**币种/汇率/结帐方式/交货人。
   - 入库仓库**建议仓预填可更换**：预计到货任务带 `suggestedWarehouseId`（服务端沿
     订货明细→申请明细→计划前供给行动→物料分析目标仓回溯，全任务唯一有效分析仓才给出）时
     预填该仓并提示「已按物料分析目标仓预填」，仓库可按实际到货情况更换；
     改离建议仓时给出醒目提示（后续仓库待入库任务以所选仓为目标仓；只有实际确认入库后，
     分析齐套/供给进度才按该仓刷新）。
     无建议时自由选仓（多分析不同仓等合法场景）。
     （2026-08-19 起由「锁定」放宽为「预填+可更换」，按仓库实际操作要求调整。）
3. **到货明细表格**（仅任务内可收明细）：列为货品、颜色、业务单位、批准剩余、
   **本次实收**（必填 >0，默认=批准剩余量）、**实际总重量**（可空）、**库位号、物料系列、
   物料编码**。来源行由订货单固定带入，隐藏新增/删除；数量格有实时必填提示，实际重量必须由
   仓库按本次实物填写，不能从 `mWeight` 自动生成；库位/系列/编码仍走成功后的 best-effort
   学习回写。手机与桌面使用同一表格，紧凑屏左右滑动。
4. **底栏**：「明细 N 行」+ 按 `unitId` 分组的实收小计 + 取消/登记并送检；同一单位可合计，
   不同单位和「单位未维护」不得出现跨单位统一总计。窄屏汇总与按钮分两行，
   **没有金额合计**（仓库看不到金额）。

## 三、保存体与货品资料「学习」（审核流已由后文一步送检覆盖）

- 保存 body：表头 `billDate/warehouseId/supplierId/remark` + 采购 `purchaserId/receiverId`
  （委外进仓单主档仅 `senderId` 一个人员列，服务端按「收货人」语义解析，故委外侧提交
  `senderId`=收货人）；明细 `goodsId/qty/orderItemId/colorId/unitId/unitRate/weight/sourceDocNo`。
  `weight` 可空但若填写必须原样进入收货行；**不带 price/amount**。
- 保存成功后调用学习端点 `POST /api/warehouse/inbound/goods-profile-hints`
  （best-effort，失败不阻断主流程）把库位号/系列/编码回写货品主档，下次登记自动带出：
  - trim 后空值跳过；单次 ≤200 条；仅未删除货品；
  - `code` 仅在主档为空**且**不与他货重复时回填（编码是业务主键，仓库误输不得覆盖）；
  - `series`/`stock_place` 与主档不同才更新；带 `updated_at/updated_by`。
- 完成后提示「到货已登记，待审核」并 `pop(true)` 回预计到货任务中心（不跳收货单详情），
  任务中心感知返回值后**立即重载列表**：该任务卡片随即显示「已登记待审核 N」在途量
  （服务端按草稿未审收货单汇总 `registeredQty`），可再登记量同步扣减，
  全部登记完后按钮变为「已登记待审核」禁用态——防止审核前同一批到货被重复登记。
  同时 bump 对应收货单列表刷新键与预计到货角标。

- 顶部指标卡精简为两张：「全部待到货」（计数走 `/expectations/count` 全量口径）+
  「待品质部批准」（只读状态卡，点击在下方提示条显示品质部口径说明，不筛列表）；
  原采购/委外类型筛选卡与卡片内说明文字已下线，口径提示统一放卡片下方整行提示条
  （与财务审批任务中心同款 `_ScopeHintBanner` 布局）。
- 2026-08-31 委外释放时点修正：财务批准仍创建 `inbound_expectations` 审批快照，但不立即成为仓库任务。`DIRECT_OUTBOUND` 与 `MAKE_THEN_OUTBOUND` 都必须先有 `status=1` 的真实目标件出仓单；前置自制、FQC、成品实收入仓、`READY_OUTBOUND` 和出仓草稿均不显示。首次分批真实出仓后只开放本批回厂容量；该批收满且 IQC 结案后暂时退出，下一批出仓再自动出现。IQC 失败实物退回量可恢复补货容量，补货进仓由全部已审核回厂统一扣减，不能再按 replacement allocation 重复扣一次。采购仍在财务批准后显示；没有 V436 新流计划行的历史委外保留旧口径兼容。
- 委外当前可登记量由服务端统一投影：审核目标件出仓 + 已实物退回的合法 IQC 返修额度 − 已审核回厂，再受订货净未收量限制；混合单只返回已释放或正在草稿/待检/异常阶段的行。列表、总数、类型计数和角标使用同一谓词。
- 委外财务批准不再向仓库发送“预计到货”通知；每张目标件真实出仓单审核后，才按出仓单 UUID 幂等提醒仓库“可能回厂”。通知仍不是到货事实。
- `registeredQty`（已登记待审核在途量）= 关联订货明细的草稿（status=0、未删除）
  收货单数量合计；审核(1)后转入 `acceptedQty`，红冲(-1)/作废(删)后不再计入。
- 口径提醒：登记保存只建**草稿收货单**，`received_qty` 与任务结案仍以**收货审核**为准；
  审核通过即入 IQC 待检隔离。品质部在「品质任务中心 → 待检处置」PASS 后形成合格待入库量；
  仓库核对实际库位并确认入库后，才进入可用库存。

## 三·补、登记并送检一步完成 + 断点恢复（2026-08-27）

**背景（本轮修复的三个生产体感问题）**：

1. **保存后审核必报错**——登记页保存的草稿不带币种/汇率/结算方式，而收货审核的
   `requireHeaderMatches`（PurchaseReceiptAmountAuthority / Subcontract 版）要求表头与
   财务批准订货单一致 → 仓库点「审核」报「供应商、币种、汇率或结算方式与财务批准订单
   不一致」，被迫进采购收货单编辑页补币族/价格等采购字段。
2. **保存后慢 + 闪跳**——保存链路为 `create → await 学习回写 → pop 回任务中心 →
   await 整页重载 → push 采购/委外收货单详情页（又整页加载）`，约 7 个串行请求，
   视觉上「退出到仓库再进审核、闪一下卡一下」。
3. **中途退出死按钮**——登记保存后退出，任务卡变灰「已登记待审核」，无任何入口回到
   草稿审核页（expectations 接口不带回草稿单 id）。

**一步登记端点** `POST /api/warehouse/inbound/arrivals`（`WarehouseArrivalRegistrationService`）：

- 请求体 = 稳定客户端 `idempotencyKey` + 登记页字段（`qty/unitId/unitRate/weight`、库位、收货人、
  仓库、日期），其中 `weight` 为可选实际总重量，**不含价格与币族**；
- V419 先按当前登录制单人锁定 `maker + idempotencyKey`，服务端对除 key 外的规范请求计算 SHA-256：同 key + 同 body 返回原 `outcome/receiptId/receiptBillNo/exceptionId`，不再创建收货单；同 key + 不同 body 返回 409。命令账先写 `PENDING`，只允许一次转 `COMPLETED/QUARANTINED`，身份与终态结果均不可改删；
- 服务端按明细 `orderItemId` 回查来源订货单表头，权威回填
  `supplierId/currencyId/exchangeRate/settlementMethodId`（多单来源 fail-closed）；
- 委外登记和草稿续办在创建/审核前先确认每条来源已有真实审核目标件出仓；无出仓直接返回 409，不生成回厂草稿，也不进入“到货超量待财务”链；最终数量守恒仍由 V436 数据库门禁兜底；
- 新流委外回厂草稿创建/编辑与目标件出仓红冲按订货明细 UUID 顺序共用行锁：活动草稿先占交互容量，红冲后的剩余出仓 + 合法返修容量必须继续覆盖全部已审核回厂和活动草稿；有其它批次足额覆盖时不做无条件阻断；
- 同事务复用各收货单 Service 的 `create + approve`（IQC 隔离/订货回写/立应付/recordApproval
  全链路不变；权限仍由两段 Service 自身 `@PreAuthorize` 收口）；
- 正常 → `{outcome: SUBMITTED_FOR_INSPECTION, receiptId, receiptBillNo}`（已转品质待检）；
  实到超量 → approve 抛 `ProcurementArrivalBlockedException`（noRollbackFor，草稿 +
  PENDING_FINANCE 异常已提交），接口正常返回 `{outcome: EXCESS_QUARANTINED, ...,
  exceptionId}`，前端提示后由「到货异常任务中心」接管（财务定案 → 按批准量继续送检；
  品质 PASS 后仍须仓库确认实际入库）。

**前端流转**：登记页底栏按钮 =「登记并送检」，点按先出统一审核责任确认框
（`showUtenReviewerConfirmDialog`，一次确认同时覆盖登记与审核责任）。页面实例从首次提交到网络重试始终复用同一 key；即使服务端已提交但响应丢失，重试也只回放原结果。成功后
`pop(结果)` 回任务中心**就地刷新一次**并按 outcome 提示下一步——不再自动跳
采购/委外收货单详情页（仓库流程全程留在仓储模块）；学习回写改 `unawaited`
不阻塞返回。

**断点恢复与流水线步骤（2026-08-27 二轮，任务卡即流水线）**：

- `expectations` 接口每任务新增三个流水线要素：`draftReceiptIds`（挂着的草稿收货单）、
  `pendingInspectionReceipts`（待品质放行的收货单张数）、`openArrivalExceptions`
  （未结到货异常数）。任务卡据此显示当前步骤徽章，**断在哪一步，按钮就停在哪一步**：
  1. `待登记到货` → 「登记实际到货」（进本页）；
  2. `已登记 · 待送检` → 「继续送检」（新端点一键完成，见下）；
  3. `超量 · 待财务审批` → 「去处理」直达「到货异常任务中心」；
  4. `已送检 · 待品质检验` → 只读跟进；品质 PASS 后转“合格待仓库入库”，仓库仍须核对
     本次实际入库量和实际库位，不得自动入库。
- 新端点 `POST /api/warehouse/inbound/arrivals/{receiptId}/complete`
  （`WarehouseArrivalRegistrationService.complete`）：草稿收货单一键继续送检——
  服务端先按来源订货单**权威修复表头币族**（供应商/币种/汇率/结算方式；老登记链路
  建的草稿缺这些字段、原审核必报错），再走同一审核链路（noRollbackFor 同口径，
  超量返回 EXCESS_QUARANTINED）。**仓库从此完全不进入采购/委外收货单页面**。
- 列表/计数口径扩展：`OPEN` 任务 + 「已收满但品质未放行」的 `CLOSED` 任务
  （`PENDING_INSPECTION_EXISTS`：已审核收货单仍有 PENDING/PARTIAL 待检明细）——
  品质结案后原到货任务转入独立“合格待入库”队列；全部合格量经仓库实际确认后，入库任务才消失，
  仓库全程可见每张单停在哪一步。

## 四、权限与价格脱敏边界

- 路由权限（任一即可）：`warehouse_inbound:view` / `purchase_receipt:edit` /
  `subcontract_receipt:edit`（`permission_by_path.dart`）；后端收货单 create 仍有各自
  `@PreAuthorize` + 对象级授权兜底。
- 价格脱敏（V302）：无 `purchase_receipt:price:view` / `subcontract_receipt:price:view`
  的角色（仓库/生产等）看收货单列表/详情时，单价/金额族与合计一律由服务端置 null +
  `priceMasked=true`，前端渲染 `***`；预计到货明细接口 2026-08-18 起也不再下发
  `unit_price`。种子授权：DEPT_PMC / SUB_PURCHASE / DEPT_FIN / GM。
- 仓库侧到货异常任务（`/api/warehouse/inbound/arrival-exceptions`）的金额快照同口径脱敏。
