# B1 报表、分页与特殊来源专项

日期：2026-10-25（America/Denver）。本文件是本轮 11 实施文档的专项证据索引，不改写旧台账批次。阶段状态仍以完整阶段验收为准，不能据此标记 B1 完成。

## 完整定位清单

相邻 `11-B1报表入口与差异清单.csv` 登记 81 个当前导出变体和 11 个 GET 保留/辅助逻辑入口，共 92 项。两个别名属于同一逻辑入口时在同一行列出，不把别名累加为独立能力。CSV 登记源码入口、分页方式、元数据合同、保留差异、真实测试入口与待验证状态。

六领域普通报表保留各自的业务 SQL、权限、生命周期、遮价和单位/币种身份。公共入口是：

- `ReportReadPlan`：独立选择 count/facets/totals，默认 ALL；可嵌套的线程作用域，退出后还原。ROWS_ONLY 用于导出。
- `ReportReadPlanInterceptor`：仅六领域 `/api/{domain}/reports/**` 的 GET 接受 `includeCount`、`includeFacets`、`includeTotals`。缺省 true，只接受单个 true/false。拒绝错误及重复值，不修改行筛选条件。
- `ReportSort`：白名单用户排序后保留领域稳定后缀。六领域明细补真实行 UUID；单头补单头 UUID；销售客户汇总补客户/币种身份；财务收款分组补客户/币种身份。
- `ReportQueryKit.paginateAll` 与 `ExportPageSink`：由主实施入口统一维护，调用原领域服务。任务工作线程逐批消费，不能累计全部输入行。

省略 count 的分页响应使用 `total=-1`、`totalPages=-1` 表示未知，不能使用 0。省略 facets/totals 返回 `{}`/`[]`；调用方根据本次请求计划复用同条件的元数据，改变身份/服务器/权限/条件或显式刷新必须重取。固定布局报表已完整计算出少量结果时可保留真实行数，避免导出重复读取同一份固定表。

## 同类执行器与特殊来源

六领域普通 execute 均按计划避免执行未请求的统计 SQL。财务额外覆盖 `executeOverview`、`executeRawPaged`、`executeRawGrouped`、`executeGrouped`、`buildRunningBalance`、账户流水、预收事件，以及 FinanceStatementService/FinanceCostService 的 count。委外 inOutStatus 也接入 count 门控。

账户流水中的滚动余额是每一行的业务事实，不属于可省略 totals。无论计划如何，先按完整期间事实计算余额，再按展示搜索/精确单号筛选及分页；只有 count、整集收支合计窗口可以省略。越界空页仍需返回准确元数据时，从同一 filtered 关系补读请求的聚合；首页空结果不再多发补读。原先未被调用的私有全量账户滚动、解析日期及内存分页副本已删除。

预收事件原先先取全部事件再内存切页，现在由 PostgreSQL 有界返回。count/totals 仍按完整同一事件关系计算。到账、核销、红冲日期、原币/本币、销售单 UUID 与历史原文保持原权威。

货架标签原先导出复用了交互查询的 5,000 行上限，可能生成无提示的截断结果。现在共享 `ShelfLabelSql.rowsPage`、`StockQueryService.shelfLabelRowsPage` 与同一 DTO 映射，导出走逐页 sink。旧交互入口仍保留其既有有界展示合同。排序最后补货品 UUID，仓库×货品×颜色身份不合并。

固定资产、待摊清单现在先分页主档，再用一次 LATERAL 聚合读取该页各对象的有效 NORMAL/ACTIVE 日志；原来每个对象重复三次的日志聚合收敛。GET 与导出 loader 使用同一分页重载。日志反转、已冲销与软删除谓词、精度、月额舍入和历史保留均保持。GL trialBalance 在完整科目期初/期间聚合之后 SQL 分页，不以当前页明细重新计算余额。

GL 固定表普通 GET/同步导出保留原 REQUIRES_NEW 快照。后台导出使用显式 `exportInCurrentSnapshot` 桥，要求 sink、active/readOnly/REPEATABLE_READ 事务，以及报表查看/导出、完整财务授权；在该桥内自调用已有业务实现，避免新开事务偏离任务记录的读取快照。销售费用按科目出行，其绑定维护入口上限为 200 个目标。

随后补齐 `operatingPl` 动态分类段：保留同一业务 body，COGS 分类按批 500 读取，完整精确累加 matTotal，再输出原固定尾部。后台通过公共 ExportRowBatches 输出批次且使用同一行上限守卫；普通 GET 接可选 page/size 并通过 ReportRowWindow 仅保留请求窗口。未以 LIMIT 静默裁掉分类，也未把该表假称为固定行模板。单独新增 5,001 分类的真实 SQL/只读 RR 连接回归。代码存在不代替最终同树验收。

ORDER 报表另补价格权限排序边界：ORDER_PRICE_KEYS 同时约束无价权限下的可排序列、facets 和 totals；汇总默认使用公开客户名及客户/币种身份。原先金额默认排序和请求价格排序不再形成未授权相对序。必要客户/币种/单位分组和 count 保留，原后置 price/Exact 遮蔽仍是兜底；其它销售单据沿原权限合同。

| 保护项 | 当前合同 |
|---|---|
| 活动任务 | 每用户最多 2、全队列最多 40；持久身份防重复受理 |
| worker | 全局实际 1；数据库物理 session 锁与认领事务锁共同约束，多实例不能凭过期租约重叠 |
| 下载 | 每实例最多 1；下载前与下载中复核当前授权，内容先核大小和 SHA256 |
| 文件/临时盘 | 最终 XLSX 256 MiB；专用 SXSSF 压缩临时量 512 MiB；目录保留 2 GiB 可用空间 |
| 时间 | 读取事务/任务预算 10 分钟，单条 SQL 60 秒；每批检查取消/授权/租约/空间 |
| 行数 | 遵守当前系统设置 export_max_rows（默认 100,000，上限 100,000），分批和计算型输出共用守卫 |
| 发布 | 完整文件经原子移动和数据库认领围栏成功后才可下载，失败/取消不发布半截文件 |

运行中的取消先保留 worker 槽，待其确认停止再进入 CANCELLED。JVM 崩溃后的原 PostgreSQL 快照无法继续恢复；任务保留明确 FAILED 及原因，创建新任务使用新的读取时点，不在原任务上悄悄重跑。读取合同/应用指纹变化也显式拒绝旧候选。临时片清理只针对该专用导出目录中可证明属于再生任务的命名；不能混放正式原件。

回退先停用新任务入口/目录配置，等待或取消活动任务，保留任务表、请求、哈希及审计，再回切已验证的应用读取路径。不得 DROP 永久任务历史、改旧迁移或反向修改业务事实。新版本至旧代码的实际服务器回退和岗位 UAT 本轮未执行，发布前仍需独立演练；用户保留提交和更新权限。
