# ADR-175：公司平台品牌与配置中心

> 日期：2026-10-10；状态：已接受。
> 关联：ADR-004（默认品牌色）、ADR-013/110（系统设置与再认证）、ADR-031（可信服务器与单主库）、ADR-133（AI 服务配置）。

## 背景

平台名称、Logo 与品牌色原先绑定优腾内置资源。平台未来独立部署给其他公司，以及本公司更换 Logo 时，需要管理员在工作台完成品牌变更，并确认修改发生在正确的服务器。已有安全、AI、财务、业务字典与个人偏好有各自权限和权威保存路径，不应因新增品牌页出现第二套互相覆盖的配置。

## 决策

1. 新增 `/admin/platform-settings`。工作台保留现有系统设置入口，在系统设置页顶部新增平台设置卡；平台页分为品牌、服务器与配置入口。既有系统设置页保留安全及运行策略，AI 仍在其原网格首格，同时可从平台配置中心进入。
2. 公司品牌是当前数据库中的独立单例聚合，迁移 V839 建立 `platform_branding`。公司显示名称、公司其他名称、平台名称、标语、主/副主题色、登录提示、联系方式与 Logo 按版本原子保存。公司其他名称按行填写，最多 16 个不同名称，每个 2～120 个字符、总计 500 个字符，修剪空白并忽略大小写去重。此设计面向每家公司独立部署，不把品牌单例当作共享数据库的多租户实现。
3. 路由、入口和页面都校验当前超级管理员及显式 `authorization:manage` 权限。后端写入同时排除访客、模拟身份和必须改密主体，使用现有再认证机制、事务锁、版本比较与审计。任何冲突整次失败。
4. 进入页面先读取当前生效服务器的管理员状态接口，确认数据库连接，再读取管理品牌。权限、账号、模拟身份或服务器变化使旧请求失效。连接缓存、默认 connected 状态和本地可达性探针不能替代当前服务器的管理员状态回执。
5. 小型 Logo 与品牌字段放在同一数据库事务中，随数据库备份。输入限制为 PNG/JPEG、512 KiB、2048×2048 以内；服务端实际解码并规范化 PNG，不保存原图元信息。Logo 不走通用业务附件权限、隔离与删除链，不依赖附件存储启用。
6. 登录前公共接口仅输出显式展示字段与规范化图片，不输出操作人、密钥或部署凭据。匿名、JWT、远程访问与首次改密豁免统一限定两条精确 GET 路径，管理状态接口和相似路径不在其中；本地网络来源边界仍生效。公共品牌客户端不携带员工令牌、不跟随跨站重定向；快照与 Logo 绑定当前服务器和品牌版本，服务器变化不能保留旧公司结果。
7. 全局品牌接入应用标题、登录页、侧栏、关于信息与 Material 主题；生产执行工卡和备料汇总单的公司头/PDF 作者使用打印时的当前公司名称。主/副主题色用于品牌和交互；危险、成功、警告等业务语义色保持既有含义。个人深浅主题模式继续由本人设置。
8. 平台配置中心只汇总现有权威入口，复用路由权限目录过滤；业务对象配置仍在业务上下文中编辑。平台公司名不会覆盖财务开票抬头/税号，也不会修改历史单据和数据归属。
9. 服务器部分复用原生可信端点选择和 Web 同源接口。任意 API host、数据库/JWT/加密/存储凭据不进入品牌设置。安装包图标、原生产品元数据和 PWA 静态清单仍须构建或发布外壳变更。
10. 销售客户文件识别通过 `CompanyBrandingReadPort` 取得不可变公司身份快照，规则抽取、卖方遮蔽、AI 提示与结果核对使用同一份版本，不在识别中途重新读取公司配置。配置名称按字面处理，正则字符被引用、短英文名有边界，不作为模型指令。优腾兼容名称仅为原优腾公司实例保留，其他部署不能把优腾客户一律当作我方卖方排除。
11. 未保存表单同时注册当前 `pageKey` 的路由退出保护和系统返回保护，覆盖 `go`、替换、深链返回及浏览器返回。发出保存后响应不确定时保留编辑，重新读取版本核查，不能由“连接恢复”推导保存成败；冲突/未确认保存的撤销也从服务器重读，所有后续保存继续进行期望版本检查。
12. 普通服务器/Web/客户端升级必须保留公司现有配置；程序发行目录与数据库、环境文件、附件原件、偏好和凭据存储分离。Simple 激活只切换代码版本，现有环境继续读取，回滚不自动恢复旧数据库。Web 保持原 HTTPS origin 与同源 `/api`，不清用户存储。Windows 的现有 VERSIONINFO `CompanyName=Uten`、`ProductName=优腾综合管理平台` 是插件数据路径身份，Android/iOS/macOS/Linux 的应用标识也保持固定，不能跟随品牌名称变更；原生更新须维持发布签名与数据路径。新增 CI 源码契约守护这些边界，不宣称尚未实现的安装器已经具备或验收保留能力。

## 结果与验证边界

管理员可在当前公司的平台内快速更换品牌，Logo、文字与颜色有一致的版本、备份与审计。安全策略、财务资料与个人偏好保留独立权威来源，平台页统一给出可达入口。

回归覆盖新页权限守卫、入口在加载与错误状态仍可达、配置目录的权限隔离、连接与身份栅栏、保存冲突及图片校验。源码和测试验证不宣称迁移已在公司数据库应用、服务器已发布或员工端验收完成。

## 官方参考与本平台采用方式

[SAP 主题设置](https://help.sap.com/docs/help/e37f3c54603c4647b0b5d73c870f6223/3a9285c4711841c9b612ff87c1d8d6ad.html)的集中品牌主题与 [Dynamics 365 按法律实体更换 Logo](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/get-started/tasks/change-banner-or-logo)的系统管理员职责，对应本平台超管专属品牌配置、统一应用 Logo/颜色、保存前核对当前公司服务器。

[Odoo 19 公司设置](https://www.odoo.com/documentation/19.0/applications/general/companies.html)将公司资料、用户和单据布局关联组织，对应本平台分组配置导航、财务抬头保留独立权威以及打印消费者统一读取公司名称。参考其管理交互与职责划分；当前品牌单例仍限每家公司独立部署，不以页面配置模拟共享数据库的多公司隔离。
