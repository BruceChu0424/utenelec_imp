# 30 - UI 屏幕利用率优化方案（Data-Dense Dashboard 应用）

> 销售委外生产钱流四模块前端已落地。本档基于 **Data-Dense Dashboard** 设计系统（ui-ux-pro-max 推荐：minimal padding / grid layout / space-efficient / maximum data visibility，WCAG AA），对现有 UI 做**屏幕利用率 + 内容分区**优化，重点解决桌面/平板宽屏留白、单列堆叠浪费横向空间的问题。
> 优化目标：**宽屏每一寸都用起来，内容按"什么区域放什么"分区**，手机端零退化。

---

## 一、现状审计

| 维度 | 现状 | 问题 |
|---|---|---|
| 导航外壳 | compact 底部悬浮胶囊 / medium+ 左 NavigationRail（≥1280 常驻标签）✅ | 桌面已有侧栏，OK |
| 内容宽度 | `UtenContentContainer` 默认 maxWidth=1600 居中；`.narrow`=1120 | **超宽屏（>1600）两侧大留白**；数据表本该顶满 |
| 列表页 | UtenAppBar + 标题行 + 状态 ChoiceChip Wrap + MasterDataTableView，**全垂直堆叠** | **桌面横向空间浪费**：筛选占顶部、表被挤；筛选滚走后不可见 |
| 编辑页 | 主表字段 + 明细行，**单列** | 桌面右侧大片空；字段本可 2-3 列 |
| 详情页 | 主信息 + 明细表，单列 | 桌面可"主信息左 / 明细右"或顶 KPI+下双栏 |
| 网格 | `UtenResponsiveGrid` 1/2/3/4/5/6 列自适应容器宽 ✅ | 已高效，OK |
| 工作台 | 分区可折叠 + 网格卡片 | 卡片密度可再压（padding/minimize） |

**核心结论**：响应式骨架（断点/网格/侧栏）已到位；**短板在"数据页（列表/编辑/详情）仍是手机式单列垂直堆叠"**，桌面宽屏利用率低。

---

## 二、优化总则（Data-Dense Dashboard）

1. **数据页顶满宽度**：列表/报表/表格页去掉 1600 居中钳制，顶到侧栏右沿（保留 gutter）。
2. **分区代替堆叠**：桌面（expanded）用 **Row 分栏**——左"筛选/操作区"固定宽，右"数据区"占满；手机回退垂直堆叠。
3. **多列代替单列**：编辑/详情表单桌面用 2-3 列字段网格。
4. **信息密度**：表格行高/内边距收紧、KPI 条常驻、次要操作进溢出菜单。
5. **手机零退化**：所有分栏/多列在 compact 自动回退单列堆叠（断点驱动，非两套代码）。

## 三、具体优化项（按收益排序）

### P1 列表页 → 桌面"左筛选区 + 右表区"分栏（最高收益）
- **现状**：标题/搜索/状态 Chip/表格 全垂直。
- **优化**：新建共享组件 `UtenListTwoPane`：
  - **expanded（≥840）**：`Row` → 左侧 `UtenFilterPane`（宽 260，含搜索+状态 Chip+其它过滤+操作按钮"新建"），右侧 MasterDataTableView 顶满剩余宽。
  - **compact/medium**：回退现有垂直堆叠（搜索+Chip 在上，表在下）。
- **收益**：桌面筛选常驻可见（滚表不动筛选）、表横向顶满、内容分区清晰。
- **应用**：5 个列表页（purchase + sales + subcontract + production + finance 的 doc_list_page），把现有 `_buildFilterBar`/搜索/Chip 包进 `UtenListTwoPane(filterPane:, tablePane:)`。
- **配套**：列表页 `UtenContentContainer` → `.wide`（去 1600 钳制）。

### P2 编辑/详情页 → 桌面多列字段网格
- **现状**：主表字段单列。
- **优化**：新建 `UtenFormGrid`（expanded 2-3 列、compact 1 列），主表字段（日期/供应商/仓库/币种/汇率/经办人…）按字段数分列；明细表仍占满宽（在下）。
- **详情页**：桌面可"左侧主信息卡 + 右侧明细表"双栏（expanded），或顶部 KPI 条 + 下方双栏（主信息/明细）。
- **应用**：5 个 doc_edit_page + doc_detail_page。

### P3 表格全宽 + 密度
- **现状**：表在 1600 居中容器内。
- **优化**：列表/报表页用 `UtenContentContainer.wide`（新建：maxWidth 极大/不钳制、center:false），表顶到侧栏右沿。
- **MasterDataTableView**：expanded 桌面行高收紧（dense 模式）、列宽优化、金额列右对齐+等宽数字（tabular figures，防跳动）。

### P4 工作台/卡片密度
- 模块卡片 padding 收紧、每卡信息密度提升（图标+标题+计数+状态 同行）。
- 超宽屏 `UtenResponsiveGrid` 已 5-6 列，OK。

### P5 KPI/统计条常驻
- 列表/报表页顶部 KPI 条（DocKpiBar）在 expanded 常驻 sticky，滚动不丢失总览。

## 六、断点回退（手机零退化）

所有分栏/多列在 compact 自动回退，由 `context.breakpoint` 驱动，单套代码：
- expanded（>840）：Row 分栏 / 2-3 列字段 / 全宽表。
- medium（600-840）：2 列字段 / 表全宽 / 筛选折叠为顶部抽屉。
- compact（<600）：全垂直堆叠 / 1 列字段 / 表横向滚动。

## 八、设计系统锚点（Data-Dense Dashboard）

> **2026-08-14 统一编号 UI 后置覆盖（V279 候选）**：本页底部 V76 描述是 2026-07 历史落地记录。当前新文档号由服务端按 `PREFIXYYYYMMDDNNNNNN` 分配；普通新建页的单据号为只读“保存后自动生成”，不预取下一号，不在 sales/purchase/subcontract/finance 配置或 stock model 保留 Flutter 前缀镜像表。分类编辑的显式前缀输入持久提示“全系统 token 专用、忽略大小写、终身保留、服务端事务权威”；409 冲突保留当前输入供修改。详见 [ADR-036](../99-决策记录-ADR/ADR-036-全局业务标识与单据号命名空间.md)。

- 配色：深绿青绿品牌色（既有 UtenColors，深色浅色双主题）。
- 字体：现有（中文优先）；数字/金额列用等宽（tabular）防跳动。
- 间距：4/8dp 节奏；dense 模式行高/内边距收紧。
- 交互：行 hover 高亮、点击详情、150-300ms 过渡。
