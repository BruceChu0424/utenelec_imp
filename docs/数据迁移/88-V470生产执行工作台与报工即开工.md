# 88 - V470 生产执行工作台与报工即开工

> 迁移：`V470__production_execution_root_workbenches.sql`  
> 状态：源码候选；目标非空库迁移、岗位 UAT、恢复与发布均未完成。

## 1. 决策

V470 建立两张只读投影：

- `v_production_execution_workbench_roots`：按最外层物料分析聚合进行中任务；历史无分析计划
  才按最外层计划聚合。已有执行段但仍有未排需求时显示 `PARTIALLY_SCHEDULED`。
- `v_production_execution_workbench_segments`：逐执行段给出订单、车间、产品、计划量、有效
  报工、FQC、待点收、实收及备料事实。

当前流程不再向页面和权限面暴露人工“派工/确认开工”。旧端点与 `DISPATCHED` 历史状态
保留兼容，不回填、不伪造旧时间。已指定车间/负责人且全部正式物料需求已经仓库实发
`FULFILLED` 的 READY/DISPATCHED，或有冻结证据的 `ZERO_MATERIAL`，直接成为可报工候选。
首次创建日报草稿时，通过事务级精确 marker 允许 READY 直接转 `IN_PROGRESS`，同时追加
`AUTO_START_ON_REPORT` 事件；日报后续任一步失败，状态和事件一起回滚。

## 2. 仓库与反向

生产链 DRAW 草稿禁止单独审核，`POST .../approve-and-issue` 在一个事务完成审核和首轮
实物出库，并要求每条生产领料明细具有精确 `execution_segment_id`。首次报工前可填写原因
取消错误出库；已存在草稿/已审报工，或执行段已经 IN_PROGRESS/COMPLETED 后，只能走生产
退料，不允许把原出库事实静默抹除。

## 3. 权限和通知

- `production_execution:overview`：进行中聚合总览，仍叠加生产计划 maker/部门对象范围；
  跨制单人读取需 `production_plan:view:all`。
- `production_execution:view`：我的车间任务。服务端只返回本人主职/兼职车间子树、本人
  负责或本人管理车间的执行段。
- 报工按钮采用三权限交集：`production_daily_report:view`、`production_daily_report:create`
  与 `production_execution:view` 缺一不可。
- 新执行段报工来源与保存守卫都以精确车间指派为对象范围；不再要求车间员工同时处于计划
  maker 的 owner visibility。旧无执行段日报仍保留计划 owner 范围。
- V470 把旧 `production_plan:view` 授权兼容到 overview，把旧 start 或日报 create 授权
  兼容到 workshop view；个人 revoke 优先。dispatch/start 权限码保留给历史端点，但从
  当前 permission surface 移除。

计划批准、WAITING→READY、DRAW 全量实发和取消出库按执行段车间定向通知。候选为对应车间
主职/兼职在职员工、明确负责人和车间经理，再与当前有效
`notice:read + production_execution:view` 求交。通知路由固定
`/production/workshop-tasks`；同一通知行进入普通顶部通知，同时因
`PRODUCTION_WORKSHOP_TASK_ACTION_REQUIRED` 目录绑定进入居中行动卡。状态变化先办结旧卡，
首次报工以 `REPORT_STARTED` 自动办结。

## 4. 兼容与验证边界

迁移不改历史执行段、报工、库存、`fqty` 或 `iqty`，只新增原因列、索引、视图、权限目录和
受控状态跃迁。`server/ops/reset_business_data.sql` 的版本守卫同步接受
V468/430、V469/431、V470/432、V471/433、V472/434 与当前候选 V473/435；清表策略本身不变。
进行中根列表继续服务端分页；关键词含客户/车间，排序只接受
`latestEndDate/status/rootLabel`，status 使用固定业务 CASE，不拼接客户端列名。

本地必须至少通过：Java 主源码编译；V470 SQL 合同；复数执行段 UUID 去重/100 条上限；
READY/DISPATCHED 首次报工自动开工与越权/跨车间负向；DRAW 单独审核失败关闭；取消出库
在首次报工前后边界；车间通知双权限求交、顶部+居中两形态及自动办结。PostgreSQL 行为测试、
目标数据迁移和真实车间/仓库岗位 UAT 未完成前继续 **NO-GO**。
