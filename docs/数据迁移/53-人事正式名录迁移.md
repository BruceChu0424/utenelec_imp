## 六、设计决策与边界

- **工号确定生成**：构建脚本按序号编 `UT0002..UT0142`（幂等键 = `employees.code`，ON CONFLICT upsert）；
  导入后 `master_code_sequences` UT/ZW 均同步到实际最大值，后续 UI 入职从 UT0143 起号。
- **重跑安全闸**：若现有 UT 工号员工姓名与名册冲突且非本迁移所建，SQL 立即中止
  （提示先 `--hr-cleanup`）；正常重跑为幂等 upsert。
- **onboard 轨迹**：名册是权威入职来源，按 `hire_date` 写 `employment_history(onboard)`，
  按 (员工, onboard, 日期) 去重——与 [34] 老库 stub「禁止伪造历史」不同，此处日期可验证。
- **不创建登录账号**：141 人只有档案，无 users 行；账号按既有权限流程逐人开通（同 [34] 原则）。
- **ADMIN 现状**：ADMIN 员工挂在 财务部、岗位「财务经理」（历史测试遗留），清理未改动；
  建议 HR 在员工页把 ADMIN 调回 行政与人力资源部（V08 原始设计）。
- **supervisor_id 未设置**：直属上级可由部门负责人推导，名录无此字段，留 HR 按需维护。
- **migrate.sh 预检调整**：`--hr-cleanup/--hr-roster` 不依赖老库导出快照
  （export_manifest.json 缺失时跳过老库交叉校验，csv 仍按 build 脚本登记的 sha256 逐文件校验，
  审计 run 记录以 `sha256('na-hr-roster-flow')` 占位 export hash）。其余老库目标行为不变。
