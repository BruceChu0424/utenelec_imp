# 计划部弹窗熄火根因修复与全员基础包护栏（2026-10-09）

用户反馈：销售下单 → 财务通过后，计划部（李桃秀）没有收到「新订单待物料分析」弹窗。

## 根因（开发库实证，非推测）

1. **全员基础包被管理页清空**：2026-10-09 01:29:25 超管在权限管理页一次保存
   （audit_log 89403-89408，同一 request_id 31013e47）把当时基础包里 6 个码全部移出，
   含 `notice:read`。保存契约是「期望的完整集合」，移出一律允许、无护栏、无告警。
2. **`notice:read` 缺位的爆炸半径**：全体非超管同时失去 ① 前端到达轮询/登录检查门挂载资格
   （`app.dart` 要求 `notice:read`）；② `/api/notices/**` 访问权；③ `ChainNoticeService`
   全部发卡池接收资格。计划接手卡发卡池 = `SUB_PLAN 子树 ∩ notice:read ∩ 物料分析 view+create`，
   李桃秀是计划部唯一账号且只缺 `notice:read` → 池为空。
3. **静默熄火**：订单 XD20261010000001 财务确认后，outbox 事件 `SALES_ORDER_FINANCE_CONFIRMED`
   处理"成功"（status=1）但生成 0 行通知；V825 补发用同一资格池同样无法补回；全链无任何报错。
   财务侧弹窗"看似正常"只是因为操作者是超管（有效权限恒为全量目录码）。
4. **修复偏差放大**：2026-10-09 05:52 一次手工 SQL 修复只恢复了 V831 断言卡住的 3 个自助码，
   漏掉 `notice:read` 与 `profile:edit:self`（前一日治理记录第 51 行已留痕该偏差）；06:05
   管理页又把那 3 个码关掉。

另注：该订单已有 3 条物料分析明细（超管测试时自行接手），按办结口径本就不应再补弹——
验收须用新订单走完整链路。

## 用户侧验证口径

用**新订单**完整走：销售开单并审核 → 财务确认 → 计划部账号（李桃秀 13432161255）登录或在线，
20 秒轮询/登录门应弹出「新订单待物料分析」`ReviewPendingDialog`。已在物料分析中被接手的
历史订单不补弹（办结口径）；订单被任何人创建过物料分析后该卡按聚合撤回。

## 追加确认：登录中间弹窗「未读弹、已读不弹」（2026-10-09 第二项要求）

用户要求：账号登录时，没读过的任务要弹中间弹窗（一登录就弹），读过的不要重复弹。
代码级核实结论：**现行实现已经是该口径，无需改代码**——

- 登录检查门 `ReviewPendingLoginGate` 每次登录会话触发一次，拉
  `GET /notices/pending-reviews`（`findVisiblePendingReviews`）；
- 弹与不弹的分界是 `popup_acknowledged_at`，而它只由 markRead 系列（读通知 /
  【去工作台处理】落点置读 / 办结置读 / 稍后）写入；**弹窗右上 X 只本地关闭、不写它**——
  所以未读且未办结的任务每次登录都会重新弹出；
- 读过（含去工作台处理后落点置读）即静默；「稍后再看」15 分钟内不弹、到期未办结恒弹；
  办结（如订单已被接手做物料分析）不弹。
