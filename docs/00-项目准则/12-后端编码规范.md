# 12 - 后端编码规范

> 服务端（`server/`，Spring Boot + Java 21）的强制性编码约定。
> 每条规则都源于真实事故或评审结论；新增规则时附出处。

## 1. 不可变集合禁止 null 键查询（2026-08-16，销售订货单 500 事故）

### 规则

`Map.of` / `Map.copyOf` / `Collectors.toUnmodifiableMap` / `Collections.unmodifiableMap`
返回的不可变 Map，以及 `Set.of` 返回的不可变 Set，对 **null 键/元素**调用
`get` / `getOrDefault` / `containsKey` / `contains` 会直接抛 `NullPointerException`
（`ImmutableCollections.MapN.get` 内部 `Objects.requireNonNull`），
而不是像 `HashMap` 那样返回 null / false。**空 `Map.of()` 也不例外**（JDK 21 实测）。

因此：

- **key 可能为 null 时，先判空再查**：

  ```java
  // ❌ workshopId 为 null 时直接 500
  workshopNames.get(workshopId)

  // ✅
  String name = workshopId == null ? null : workshopNames.get(workshopId);
  ```

- **以可空外键为键的查找 Map，优先用 `HashMap` / `Collectors.toMap`**（null 键安全），
  只有键域保证非空（主键、构造的 record 键、常量）才用 `Map.copyOf` 收尾。
- 「空集合快速返回」写 `return Map.of();` 时，必须确认**所有消费方**都不会以 null 为键查询；
  否则改用 `new HashMap<>()`。
- 同理，`Set.of(...)` 的 `contains(x)` 在 x 可能为 null 时也要先判空。

### 事故与隐患记录（2026-08-16 全量排查）

| # | 位置 | 触发条件 | 状态 |
|---|------|----------|------|
| 1 | `WarehouseService.toList()` | 仓库「所属车间」为空 → 字典接口 NPE，前端连带报「加载客户失败」 | 已修复 |
| 2 | `ClientService.list()` | 当页客户的默认结算方式全部为空 → 空 `Map.of()` 被 `get(null)` | 已修复 |
| 3 | `VisitorApplicationMapper.toListItems()` | 当页申请都没有接待人 → 空 `Map.of()` 被 `getOrDefault(null, …)` | 已修复 |

排查方法：枚举全部不可变集合产生点 → 逐个核对消费方键的可空性 →
JDK 21 实测边界行为。其余消费点安全的依据：HashMap/`toMap` 返回、已有 null 守卫、
键为主键或 record 对象、上游 `@NotBlank`/`@PathVariable`/DB `nullable=false` 拦截。

### 评审检查点

- [ ] 新增 `Map.of/copyOf/toUnmodifiableMap/unmodifiableMap` 返回点时，键域是否保证非空？
- [ ] 消费方 `.get(...)` 的键是否来自可空外键 / 可空请求字段 / 可空 DB 列？
- [ ] `Set.of(...).contains(x)` 的 x 是否可能为 null？
