## 一、问题

用户口径(2026-09-22，三条消息，节选)：

> 委外就是只有两条路线 一个是先本地加工好了 很多个子层级的 加工好了 就是走自制先 然后直接去委外
> 另一条就是 直接去加工 但是是两个东西 比如手机外壳 我们采购 或者自制出来了 但是颜色需要发出去委外
> 别人喷漆 就是 手机壳得先生产好 或者 采购好 有货了 再发出去委外 然后 回来就是委外件
>
> 如果子层级物料大于等于两个 就需要走自制路线 委外管理那里 任务中心要锁住 这个没问题
> 但是 委外只有一个子层物料 现在就没锁 …… 这个采购件入库了 不管数量多少 就可以解锁
> 可以分批发货那样 就是可发数量那里可以提示
>
> 你可以看看车间生产流程 就是 物料到了 才能开工 或者领料 然后去加工 对应的进度显示应该也是不一样

实机复盘(dev 库 `audit_log`，2026-09-22 16:41-16:57)：用户重置业务数据 → 销售订单 → 物料分析下达 →
系统自动生成委外申请 EB20260923000002(5000 x V51043「E极插套(酸洗)」，它的 BOM 只有一个子件
V51012「E极插套」，采购件，`fn_subcontract_sole_component_goods` 为真，子件库存 0)→ 打开委外任务中心。
该行显示「待处理」，「生成委外订货单」可点。用户没有建任何订货单——**他说的「没锁」就是这一行**。

两条路线在代码里的锁点根本不对称：

| | 路线 A(子层 >= 2，先自制) | 路线 B(单一子件，直发子件) |
| --- | --- | --- |
| 任务中心下单前行 | 合成行 `SUBCONTRACT_MAKE_TASK`，`can_create_order` 恒 FALSE，状态列「正在等待安排生产 / 正在生产中」 | 真实申请行，`can_create_order` 只看权限 + `WAITING_ORDER` + 有余量，**不看子件库存** |
| 建单 | 自动发单给计划部(前置生产分析) | 无守卫 |
| 送审 / 批准 | `requireNoMakeThenShortage` 409「前置生产缺口」 | 无守卫(`computeApprovalLines` 落 `COMPONENT_OUTBOUND`，建议仓刻意留空，注释原话「先下单、等子件到货再由仓库发料」) |
| 批准后 | 从专属预留发目标件 | ADR-101：有货才建草稿、才通知仓库 |

ADR-101 把锁放在了财务批准之后，与用户「像车间一样，料没到就不能开工」的心智模型差了整整三步。
此外审计还确认了 ADR-101 §五自认的三处未做，以及回厂段两处与用户口径正面冲突的地方：

1. 子件到货唤醒只挂在采购/委外 IQC 入库那一个漏斗；子件若是**自制件**(完工入库)、其它入库、调拨入、
   委外材料退回、发料红冲回仓，出仓段一律不会被唤醒。既有 E2E 用 OTHER_IN 造货后**手工**调唤醒，掩盖了这个缺口。
2. 委外判定「分批到货」之后，最后一批把累计送进允许损耗范围时，仓库能入库但**案件不自动结案**，
   订货量停在原数不关单，要等预计到齐日过期、调度器催人再点一次。用户口径是「最后入库大于 100 就可以直接入库，损耗 100」。
3. 超收转财务后，财务批准了委外商自带料，仓库一键入库仍在「消费我方发出的子件」这一步 409 整笔回滚。
4. 超收文案永远说「超过财务批准可收量」，财务看不出多出来的是委外商自己的料。
5. 通知「委外预计回厂」告诉仓库要回厂的是**子件**，与「发出去的是子件，回来的是委外件」相反。

## 二、决策

### 2.1 两条路线的锁落在同一位置：下单前

路线 B 的锁与路线 A 对称，四层同锁，判据只有一个：

> **子件在作业叶仓(排除已删除、不良品仓、线边仓、非作业叶仓)的合格可动用量合计 > 0 即解锁；否则锁。**
> 子件 = `fn_subcontract_sole_component_goods` 命中的那唯一一条 BOM 边的 `component_goods_id`，颜色取边上的 `color_id`
> (与 `soleOutboundComponent` / 批准计划行一致)。可动用量 = `v_stock_available`(已扣活动预留)，与
> `countTasks` / `draftLineCappedByStock` 逐字同口径，抽成一个常量三处共用。

| 层 | 落点 | 行为 |
| --- | --- | --- |
| 任务中心申请行 | `FulfillmentWorkbenchQueryService.enrichTableRows` 新增 LATERAL，按 `action_item_ids` 展开明细(归组行一张申请多明细时任一单一子件明细无货即整张锁) | `can_create_order` 追加 `AND NOT locked`；`display_stage` 落 `WAITING_COMPONENT_STOCK` / `COMPONENT_STOCK_READY`，行带 `componentAvailableQty` |
| 建单 / 改单 | `SubcontractOrderService.prepareDraft` → `materialPlanService.requireSoleComponentStockAvailable` | 409，逐行「委外件 X(编码) 要发给委外商加工的子件 Y(编码) 仓里还一件都没有；等子件采购或生产入库后再下委外订货，入库后任务中心会自动解锁」 |
| 送审 / 批准 | `requireNoMakeThenShortage` 内部调用同一方法(它已被送审与批准两处调用) | 同上 |
| 批准后 | ADR-101 不变 | 子件被别人用光时不建草稿、不通知；到货唤醒补草稿 |

守卫 SQL 只写在 `SubcontractMaterialPlanService`，`SubcontractOrderService` 只经端口方法调用——
`SubcontractOrderMergeGuardTest` 的 `EntityManager` 是 mock，任何写在订货服务里的 native query 都会 NPE。

「不管数量多少」照字面执行：子件到 1 件就解锁，订 1000 照下，仓库按 ADR-101 分批发。

任务中心只看仍有未下单量(`qty > ordered_qty`)的申请明细；已全部下成订货单的明细不参与锁判定，也不再显示锁行。

**子件是自制件**：完工入库必须**点收进作业叶仓**才算到货。车间直送落线边仓的产出物不算(线边仓从
ADR-087 起就退出公共可动用量)，任务中心行与出仓段都看不到它。

### 2.2 进度按路线显示：三形态徽章

任务中心状态列新增三个阶段码，客户端文案与颜色：

| 阶段码 | 行 | 文案 | 颜色 / 形态 |
| --- | --- | --- | --- |
| `WAITING_COMPONENT_STOCK` | 申请行(下单前)，锁 | 等子件到货 | 黄，在办；不可勾选，「生成委外订货单」禁用并说明原因 |
| `COMPONENT_STOCK_READY` | 申请行，解锁 | 子件已到货 可下单(仓内可动用 X 单位) | 红，轮到委外动手 |
| `OUTBOUND_WAITING_COMPONENT` | 财务已批准的订货单，`COMPONENT_OUTBOUND` 行有余量、无草稿、子件无可动用 | 等子件到货 | 黄；在 `AWAITING_OUTBOUND`(待发料出仓)之前判 |

计数按 [ADR-100](ADR-100-进行中黄色数量徽章与三形态计数口径.md) 三形态：锁行从红数(`countPending`)移到黄数
(`countInProgress`)；`statusCounts` 服务端出 `WAITING_COMPONENT_STOCK` 键，`WAITING_ORDER` 减去它，
「待处理」分段改成红黄两枚(范本是本页「进行中」段)。委外 hub 卡面红数因此会变小、黄数变大——这是期望效果，
锁行确实不是委外部门能动手的活。采购部门那一支的 SQL 一个字不动。

申请行进度弹窗按路线生成步骤：路线 B 没有「前置生产完成」这一步，「目标件出仓」改成「子件出仓」，锁行顶部
横幅「子件尚未入库，暂时不能下委外单」，账本多一行「子件仓内可动用」。

### 2.3 唤醒收口到库存内核

`SubcontractOutboundWakePort.wakeOutboundAfterStockIn` 从 `ProcurementIqcStockInService.confirmOne` 移到
`StockService.recordMovementInternal` 的入库方向分支(`upsertBalance` 与 V590 的 `syncOnInbound` 之后)，经
`ObjectProvider` 注入。V590 的归属仓回写就是在这里收口「采购入库 / 委外回厂 / 完工入库 / 调拨入 / 退料 /
盘盈 / 手工单全部入库路径」，唤醒沿同一口子走，此后新增任何入库类型都自动覆盖。

- 红冲方向的入库(发料红冲、出货红冲)也唤醒：货真的回到仓里，可以再发。
- 线边仓 / 不良品仓 / 非作业叶仓的入库在唤醒开头按仓短路，不建草稿也不多跑一次查询。
- 事务语义与今天 IQC 一致：同事务、fail-closed。唤醒命中的计划行 goods/color 与本次入库维度相同，
  落在入库事务已声明的库存范围内，不会撞 V590 的「入库货品在开始写入后发生变化」守卫。
- 任务中心的锁是**查询时**按库存实时算，不依赖唤醒；唤醒只服务批准后的出仓草稿与仓库通知。
  仓库打开拣货页时 `regenerateDraft` 仍会按此刻库存补草稿，作为漏网的兜底。

### 2.4 仓库侧：阶段、可发量、建议仓、分批

- 出仓任务列表新增状态桶 `WAITING_COMPONENT`「等子件到货」(全部待出行都在等子件、无草稿)，行带
  `issuableTotal`(可发合计)与 `waitingComponentLineCount`。此前列表对没货的计划显示「目标件已备齐，待出仓」，
  而红角标又不数它，两边口径分叉。
- 拣货页「本次出库」预填改为可发量(此前预填计划余量、上限 0、红框)；可发 0 的行显示「等子件到货(仓内可动用 0)」。
- 明细表新增「建议发料仓」列，无草稿时「发出仓」下拉预填服务端算好的 `stockWarehouseId`；ADR-101 §2.3 算了
  这个字段但界面从未显示。
- 批量出库页从整单阻断改为按行：可发 0 的行取消勾选并标「等子件到货」，其余行照常。
- 补齐草稿 409 文案区分三种原因：没货「子件还没到货，仓里一件都没有；子件入库后系统会自动补草稿并通知仓库」、
  已有草稿(原文案)、无余量。
- **出库任务中心「委外出库」分段红黄两枚**(用户 2026-09-22 晚实机：分段上「没有对应的通知数量徽章」)：
  `GET /warehouse/subcontract-outbound/tasks/count` 同一响应返回 `count`(红：有货或有草稿，轮到仓库)与
  `waitingComponent`(黄：有待出量但子件一件都没到)，两数按同一批 OPEN 计划互斥；大类行与「待出仓任务」小类行各挂
  红黄两枚，hub 卡红数口径不变(见 §四)。
- **「委外拣货出仓」页与「销售出库详情」同一副骨架**(用户口径「委外货出仓页面的 UI 应该设计得和其它的一样」)：
  顶栏(标题 + 「仓库作业视图」+ 刷新) → 折叠头(计划状态横幅：出仓中 / 草稿 X 待拣货审核 / 可发 X / 全部行等子件时
  黄色提示；事实卡三列：委外订货单、委外商、交货日期、计划状态、关闭原因、出仓草稿单号、最近出仓单；折叠的「出仓记录」；
  可编辑时表单卡) → 「出仓明细 (N)」吸顶 + 表格内滚 → 浮动动作组(保存草稿 / 审核出仓 / 不再出仓，按权限显隐)。
  保存、审核确认、不再出仓、批量入口、返回与忙遮罩规则一个不变。

### 2.5 回厂段：按用户第 4 条逐场景对齐

以 1000 / 10% / 子件:委外件 = 1:1、料已全部发出为例：

| 场景 | 行为 | 本决策改动 |
| --- | --- | --- |
| 一次到 950 / 900 | 容差内，仓库确认入库那一刻自动结案：损耗单 50 / 100 → 案件 `ACCEPTED_LOSS` → 受控改量到实收 → 关单 | 自动结案的受控改量**仍开一条财务复核 case**(V503 守卫 `fn_check_procurement_source_revision` 要求批准后改量同事务开出 PENDING 复核，缺了直接回滚；复核的是「按约定损耗改到实收」这笔既成事实) |
| 一次到 800 | 严重短交：登记时仓库确认弹窗、通知委外判定、判定前这批**先不入库**(ADR-098 §2.8，用户 2026-09-22 上午口径「先锁住 先不入库先」) | 不变 |
| 800 → 接受损耗 | 损耗单 200(允许 100 + 超耗 100 转财务责任) → 改量 800 → 入库 → 关单 | 不变 |
| 800 → 分批 → 再到 150(累计 950) | 此前：150 能入库但案件挂 `WAITING_MORE`、不关单、等逾期催人 | **累计进入容差即自动结案**：`settleAfterStockIn` 对 `PENDING_OWNER` 与 `WAITING_MORE` 两种开放案件都结，损耗 50 |
| 800 → 分批 → 再到 90(累计 890) | 仍低于下限，仓库确认后可入库，案件留在分批等待，逾期后每日催 | 不变 |
| 800 → 分批 → 再到 250(累计 1050) / 一次到 1100 | 登记不拒收，审核落 `PENDING_FINANCE` 到货异常通知财务 | 财务批准后一键入库**走得通**：回厂审核消费我方子件时扣除本明细已批准的自带料；文案与通知点明「多出来的部分用的是委外商自己的材料」 |
| 允许损耗未填 | 中性案件，零通知，人工结案 | 不变(下单页已按货品主档预填) |
| 料只发了 600 就回厂 550 | 不判短交，等料发完 | 不变(ADR-101 §2.5) |
| 仓库「不再出仓」关掉余量 | 此前：关余量后无人重评，案件永远不开 | `closePlan` 末尾对涉及订货明细跑一次与入库同款的评估 |

入库放行闸仍按**收货单**：一张收货单里任一行待判定，整张单先不入库；同一订货单的其它收货单不受影响。
ADR-101 §2.5 写的「按行」指的是案件与订货明细的关联粒度，闸的粒度以本条为准。

### 2.6 通知：发出去的是子件，回来的是委外件

- 「待发委外子件出仓」正文去掉 `allowedActions`、「(基本单位)」、「IQC」等代号(准则 14 §四之五「说人话」)。
- 「委外预计回厂」与「已完成出仓」对 `COMPONENT_OUTBOUND` / `LEGACY_BOM_COMPONENT` 行按流向分流：
  「发出去加工的子件 A 本批已实际出仓 N，加工完回厂要登记的是委外件 B」。
- 「到货超量待财务审核」对委外带上「委外商自带料」与子件 / 委外件身份。

## 三、不变量

1. 判据仍只有一个来源 `fn_subcontract_sole_component_goods`；可动用口径仍只有一个常量。
2. 路线 A 与路线 B 的锁在同一位置：任务中心下单前行 + 建单 + 送审 + 批准。路线 A 一个字节不变。
3. 任务中心的锁按查询时库存实时算；唤醒只补草稿与通知，漏了唤醒也只是晚一步，不会把单卡死。
4. 出仓草稿的数量永远 <= 该仓此刻的合格可动用量(ADR-101 §三.3 不变)。
5. 短交只在「本行的料已经全部发出去」之后判；自动结案只发生在 `WITHIN_TOLERANCE`，但对 `PENDING_OWNER` 与
   `WAITING_MORE` 两种开放案件一视同仁。
6. 超出我方供料的回厂量，没有财务批准就一个字节都进不了库；财务批准之后，那一份按「委外商自带料」入库，
   不消费我方发出的子件，守恒等式不放松。
7. 系统按约定允许损耗自动结案的受控改量与人为改量一样开财务复核 case(V503 守卫)；系统路径只跳过订货单属主守卫。

## 四、明确不做

- **不把「等子件到货」登记进仓库 hub 的黄色徽章链**：这批订货单已经在委外任务中心的「进行中」黄数里(同一条链内同一件活
  只计一次，准则 14 §四之八)。黄数只画在出库任务中心「委外出库」大类行与「待出仓任务」小类行(见 §2.4)，hub 卡与工作台
  仓库模块卡不带。
- **不做锁行的通知**：「子件已到货可下单」不发通知。行状态查询时实时翻转；发通知要覆盖全部入库路径且会与
  采购到货通知重复。
