# 财务模板与固定资产折旧检查

> 本文件记录最初检查阶段的源码基线。用户随后已授权实施，最新代码与验收状态见[财务报表与资产接续实现回执](2026-10-31-财务报表与资产接续实现回执.md)。下文“未修改”的表述仅指该检查阶段。

## 结论与范围

财务提供的利润表和资产负债表可以作为报表调整依据。现有系统已有月度利润表、资产负债表、资产台账和月末折旧处理，能够复用；完整满足“录入资产、正确计提折旧、按模板出报表”属于中等改造，涉及报表取数、资产初始化及总账衔接。仅修改项目名称和表格外观不能解决当前缺口。

本轮完成源码检查、模板对照和专项验证，不改变账务算法、历史数据、资产启用开关或公司服务器。该范围遵循用户“改动不大就直接改”的条件；完整改造超出小改范围，以下给出可审阅的实施方案。公司服务器当前版本、实际科目绑定、资产数据和运行开关未在本轮读取，源码默认值不代表现网配置。

界面审查采用 `frontend-design`，保留 Uten 主题、表格、权限与响应式约束。文档沿用项目治理目录格式。

### 红字口径需要核对

“加工人工”究竟是日常生产人工、委外加工费用还是另外的非日常业务，必须以财务所指业务和科目为准；“退税”也需区分具体税种与业务。财政部《小企业会计准则》第七十条将营业外支出界定为非日常生产经营活动形成的支出，第六十九条关于部分先征后返税款的处理明确区分出口退税。因此不能据截图把全部加工人工、退税或向客户收取的税额硬编码进营业外收支。[财政部原文，第六十九至七十条](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852319878.pdf)

建议由财务确认这些项目对应的真实科目、单据、含税/不含税口径，以及这两张表的正式使用范围，再配置映射。该确认只决定会计归类，不影响先补齐模板结构和公共计算入口的设计。

## 固定资产录入与折旧

| 能力 | 当前源码状态 | 对财务要求的影响 |
|---|---|---|
| 固定资产录入 | 有名称、分类、原值、使用月数、残值率、部门、责任人、采购/验收/可使用日期和来源引用，支持草稿、提交、他人审批 | 可以复用已有“资产与待摊”入口，无需另做录入模块 |
| 资产类别政策 | 有成本、累计折旧、费用及清理科目配置，审批时冻结科目快照 | 需配置真实科目，不能只输入原值就完成入账 |
| 新资产初始确认 | 有借成本科目、贷清理科目的自动凭证代码；`posted-workflows-enabled` 默认 false | 默认配置下能录入、审批，但不能直接启用进入正常新资产计提流程；现网值待核实 |
| 初始确认、处置、终止的业务撤销 | 当前没有相应完整业务事件反冲入口，服务门禁说明也明确指出这一点 | 不能通过直接打开环境变量代替补齐生命周期 |
| 旧资产接续 | 草稿 API 没有期初累计折旧、期初剩余期限和切换日；新建账簿净值初始化为原值 | 财务已有明细中的旧资产不能按“全新资产”直接重录并重计全部折旧 |
| 月度折旧 | 有直线法、可使用次月启折、残值、4 位小数计算与末期尾差处理 | 复用现有服务端算法，无需由前端或 Excel 再维护一套 |
| 月末过账 | 预览、提交、他人审核、过账；借费用科目、贷累计折旧，同时写子账日志和总账 | 可以实现财务要的折旧会计分录；当前形式为审核后自动生成，不是通用手工借贷凭证编辑器 |
| 防重复与更正 | 有期间连续性、输入指纹、并发锁、有效正常批次唯一性和月度批次红冲 | 应保留；同一折旧不能再由人工重复补一张凭证 |
| 折旧清单 | 原值、月折旧、已提月数、累计折旧、净值已有 | GET 与导出当前不接收期间截止参数，SQL 累计所有有效正常日志，不能直接作为历史月末明细 |
| 清单月折旧 | 由主档重新计算并显示 2 位小数 | 需要区分“常规月折旧测算”与“所选期间实际计提”，末期以权威计划/过账事实为准 |
| 总账报表衔接 | 折旧凭证进入总账，但资产负债表不含累计折旧分类；利润费用归集受科目范围/绑定影响 | 必须做台账—计提日志—凭证—两张报表勾稽，不能以“生成凭证成功”代替报表正确 |

在财务前端及财务 Controller 中未发现通用手工会计凭证录入入口。当前有业务自动过账和资产专属过账。财务“直接做分录”的意图可以优先通过已有月末处理完成，若她要求自行编辑借贷分录，则属于另一个明确功能范围。
