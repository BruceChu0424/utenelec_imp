### V76/2026-07-28 历史实现记录

> 此前为 P0 邻接的设计-only 待办（"单据号应当系统统一生成"），现已全链路实现并验证。涉及 21 个 create-单据 Service + DDL V76 + 新 Java 包 + 前端 5 编辑页。

- **DDL**：`V76__doc_number_sequences.sql` 建表 `doc_number_sequences(prefix TEXT, period CHAR(4), last_seq INT, UNIQUE(prefix, period))`。
- **Java**：`server/.../common/docnumber/DocNumberService.java`（`nextNumber` 用 `INSERT...ON CONFLICT...DO UPDATE SET last_seq=last_seq+1 RETURNING last_seq`，**原子**，无并发撞号）+ `DocNumberPrefix` 枚举（21 单据类型各一，2026-07-28 增至 25 个）+ `DocNumberController`（`/api/doc-number/peek` **2026-07-28 已删除**，连同 `peekNumber`/`fromCode`；见下方「✅ 已修」段）。
- **格式**：`[前缀][YYMM][4位月内顺序号]`，例 `CD26070001`。
- **接入规则**：所有 21 单据 Service 的 `create()` 在 billNo 为空时**自动生成**（**忽略客户端传入值**，防伪造/撞号）；`update()` **不重新生成**（保留原号）。`StockDocService` 走 doc_type→prefix 映射表。
- **CJ 撞号解决**：采购收货=CJ，仓库产成品进仓=CR（新分配，避让）。
- **历史 backfill**：迁移后扫描各表现有 `bill_no`，按 (prefix, period) 回填 `last_seq` 最大值，保证新号不撞老号。
- **前端决策**：单据号**保存后在详情页展示**（新建页 billNo 字段只读，占位"保存后自动生成"）；曾实现 peek 预览后**回退**（用户选 save-then-show 为最安全）；peek 端点**2026-07-28 已删除**（连同 `peekNumber`/`fromCode`），收敛攻击面，见下方「✅ 已修（2026-07-28）」段。
- **配套前端重构（同批落地）**：① 编辑页明细从纵向卡列表改为可编辑 Excel 表（新 `lib/components/layout/uten_editable_grid.dart` `UtenEditableGrid` + 每模块 `lib/features/{module}/widgets/{module}_grid_columns.dart`）；② 日期统一为新 `lib/components/inputs/uten_date_field.dart`（替换 ListTile 日期选择器）；③ 下拉统一为新 `lib/components/inputs/uten_dropdown_field.dart`（Overlay 弹层，替换 `DropdownButtonFormField`）；④ 7 个 create-中心单据类型配置 `skipListOnCreate`，管理卡直跳新建页（钱流 expense/otherIncome/bankTransfer、销售 quote、采购 request、委外 waste/materialReturn），编辑页 AppBar 加"查看历史"按钮进列表；⑤ `MasterDataTableView` 横向滚动条修复（少行贴末行/多行贴底）+ 表头竖分隔线；⑥ "存草稿"按钮文案改"保存"（草稿→审核→红冲流程与业务副作用位置不变）。

### ✅ 已修（2026-07-28，单据号自动生成落地后的安全/正确性修复）

> 上述单据号重构落地后，经实测验证追加下列修复（详见 [28] §九「2026-07-28 修订」）：

- **DTO `@NotBlank billNo` 全量移除**：25 个 `*SaveRequest*` DTO 不再校验 `billNo`（服务端生成；此前 `@NotBlank` 在到达 `DocNumberService` 前就 400 拒绝请求）。

- **`is_stopped` 潜在 bug 修复**（被 #1 修复暴露）：`PurchaseOrder.isStopped` / `PurchaseRequest.isStopped` 原为包装类型无默认（`private Boolean isStopped;` → null），DDL 列 `NOT NULL DEFAULT FALSE` → Hibernate insert 发 null 覆盖 DEFAULT → create 触发约束违反。改为 `private Boolean isStopped = false;`。**此 bug 此前被 `@NotBlank` 400 拦截挡在前面未到达 DB，#1 移除 `@NotBlank` 后才暴露**——典型「上游校验掩盖下游约束」连环。`SalesOrder` / `ProductionPlan` 用原始 `boolean` 不受影响。契约教训见 [27] §二「NOT NULL DEFAULT 列 ↔ Entity 字段默认值」。
