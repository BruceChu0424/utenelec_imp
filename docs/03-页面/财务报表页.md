# 钱流报表页

> 路由根：`/finance/report`。真实页面与后端已接通，不是 KPI/图表占位页。
> 源码入口：[`finance_hub_page.dart`](../../lib/features/finance/pages/finance_hub_page.dart)、
> [`finance_report_table_page.dart`](../../lib/features/finance/pages/finance_report_table_page.dart)、
> [`finance_ar_ap_overview_page.dart`](../../lib/features/finance/pages/finance_ar_ap_overview_page.dart)。

## 一、入口与报表组

钱流 hub 提供：

- 应收应付总览；
- 明细报表、汇总报表；
- 往来对账单；
- 账户流水；
- 月结对账；
- 成本核算；
- 总账报表。

`/finance/report` 默认打开明细报表；具体子路由见
[`route_names.dart`](../../lib/core/router/route_names.dart)。路由门槛为 `finance_report:view`。

## 二、明细/汇总表格交互

`FinanceReportTablePage` 按 `cardId` 选择报表组，在组内切换具体变体。页面包含：

- 日期范围（默认从上月同日至今天）；
- 关键字、服务端 facet 筛选；
- 服务端列排序和 1-based 分页，页面大小 50；
- `MasterDataTableView` 表格、横向滚动和列头筛选；
- 行携带合法 `__srcId` 时跳转源钱流单据；
- 加密导出和打印预览；
- 报表类型、日期、facet、排序按账号保存；关键字不持久化。

后端返回标准报表结构 `{columns, rows, facets, page, totalPages, total}`。前端不复制每张报表的解析、
排序和格式化逻辑，统一使用 `features/report/shared/`。

## 三、数据与导出

- 页面请求 `/api/finance/reports/{group}/{view}`，筛选和排序均透传后端。
- 导出走 `/api/finance/reports/export`，使用页面同一报表 key 与查询参数，受独立权限、限流、
  最大行数、并发和审计约束。
- 打印预览按当前筛选重新请求，当前客户端上限为 2,000 行；它不是无上限全量打印。
- 聚合/台账行没有源单 ID 时不允许伪造下钻。

## 四、销售订单待收计划与正式应收

- 已审核销售订单进入“销售订单待收计划”，只按订单币种展示原币订单额、已发运立账原币和未发运预计原币。它是经营预测，不读取汇率、不换算人民币，也不写 `ar_ap_ledger` 或总账。
- 仓库完成 `SHIPPED` 后，每个发运批次才形成正式 AR；分批发运形成多笔 AR，合并发运通过不可变来源关系关联多张订单。
- 正式应收页面以币种、原币应收、原币已收/冲销/未收为主要核销口径，并保留财务开账汇率及本币拆分用于会计。销售收款引用 AR 后，币种只读，由财务填写到账原币和到账汇率，服务端重算本币与汇兑差额。
- 跨币种订单必须按币种分组或分列，禁止把 USD、CNY 等订单待收直接相加。当前收款行只接受与 AR 相同币种；真正跨币种核销在双币金额/双汇率模型完成前失败关闭。

详细边界见 [ADR-030](../99-决策记录-ADR/ADR-030-销售待收计划与正式应收分层.md)。

应收应付总览、往来对账单、账户流水、应收应付台账、对账和资产/待摊分别由独立页面承载：

### 5.1 应收应付总览的统一关联搜索

`/finance/report/overview` 是“左客户/供应商分类森林 + 右应收应付表”的主从页面。左树顶部一个搜索框同时匹配：

- 客户、供应商分类名称与编号；
- 往来单位名称与编号。

往来单位定位分页调用 `GET /api/finance/reports/ar-ap/party-locations?keyword=&page=&size=100`，收集全部
`{partyType, categoryId}` 后分别展开客户/供应商祖先路径并默认定位首个有效分类。右表继续调用
`GET /api/finance/reports/ar-ap/overview`，把同一 `keyword` 与 `categoryType/categoryId` 组合查询；编号只参与
过滤，公开报表仍保持原 6 列。V272 候选之后，未分类客户/供应商绑定真实系统根，命中时正常展开并按
该根过滤；只有滚动升级或脏数据仍返回空/树外 `categoryId` 时，才安全退回公司级关键词结果，不能沿用
无效分类滤空。

搜索输入变化立即使旧定位和旧报表请求失效，300ms 后才发新定位；手动点树会取消待执行与在途搜索。
纯分类命中只浏览该分类全部单位，不把分类词误传给报表；相关内容分支保留关键词。加载、失败、无结果和
compact 抽屉/正文文本同步均为交互契约。详见 [UtenHierarchySearch](../02-组件库/UtenHierarchySearch.md)。

权限必须按公司级报表口径理解：Controller 要求 `finance_report:view`，Service 还要求超管或
`finance:view:all`；不得复用受客户 owner 范围裁剪的 `client:view:all`。客户/供应商分类树仍分别要求
`client_category:view`、`supplier_category:view`，定位端点不会绕过树权限。

资产工作台不是报表页的子权限：进入 `/finance/assets` 要求 `finance_asset:view`，其写动作使用
独立资产权限和服务端 `allowedActions`。核心落账门禁默认关闭，完整生命周期仍为 **NO-GO**；
`finance_report:view` 不能替代任何资产工作流权限。

总账、成本和月结对账中的具体报表变体由
[`finance_report_config.dart`](../../lib/features/finance/config/finance_report_config.dart) 集中配置。

## 六、组件

当前使用 `UtenAppBar`、`UtenContentContainer`、`UtenListTwoPane`、`UtenSearchBar`、
`MasterDataTableView`、`UtenExportButton` 和打印预览组件。项目没有
`UtenViewContextSelector`、`UtenStatCard`、`UtenChartPlaceholder` 或 `UtenDataTable`。

## 七、安全与正确性

- 前端路由显隐不替代后端 `finance_report:view`。
- 导出、打印、列表必须使用相同筛选和数据范围；下载事件进入审计。
- 金额使用数据库/后端 decimal 口径，不在前端用二进制浮点重新汇总。
- MV 报表须展示或监控刷新新鲜度；不能把旧快照当实时账。
- 总账迁移与期初/期间/期末平衡未完成结构化对账前，生产结论仍为 NO-GO。
- 本页只查看/筛选/导出报表；`finance_post:execute` 的单期/全量过账后端端点没有 Flutter
  操作入口。若财务用户需自主执行，必须另行设计确认、进度、互斥、结果和失败恢复，不得把报表页
  写成过账控制台。
- 总账通用 `generate` 只能重建其明确拥有的通用 AUTO 来源，不能删除资产域凭证；资产月度错误
  必须在资产工作台创建关联原批次的正常反向批次。

## 八、验收

- [ ] 各报表变体的列、金额、筛选、排序、分页与导出对账一致。
- [ ] 无权限、跨对象、超大页大小和非法 sort/facet 均被后端拒绝或安全归一。
- [ ] 2,000 行打印边界、导出限流/并发/加密和审计测试通过。
- [ ] 多年数据执行计划、P95/P99、MV 新鲜度及刷新失败告警通过生产同构验证。
- [ ] 总账和老库迁移结构化对账达到发布阈值。
- [ ] 应收应付总览分别以分类名、分类编号、往来单位名和单位编号搜索，跨页命中路径完整；手动点树与快速连续输入不被旧响应覆盖。
