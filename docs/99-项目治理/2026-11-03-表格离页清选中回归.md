## 分类、设计和原有实现比较

这是前端交互变更；Web 与现有 Flutter 桌面端共用 Dart 实现，WPF 候选端由本任务并行适配记录汇总。按 `frontend-design` 保留既有 Uten 表格、主题、字体与布局，只调整离页后的临时操作对象生命周期。

| 原有入口 | 原有能力及问题 | 本次处理 |
|---|---|---|
| `PageSearchLifecycle` | 已按 GoRouter 页面身份追踪 push/pop/go、参数化路径、保活 shell；过滤同页 query 和临时 Navigator 弹窗 | 直接复用，不新增第二套路由监听 |
| `MasterDataTableView` | 内部单选和外部 `selectedIds` 会跨真实页面访问保留；现有 onReturn 仅清表头搜索 | onReturn 统一清单选高亮、外部单选动作状态及多选；层级/过滤隐藏行使用宿主完整清空合同 |
| `UtenEditableGrid` | controller 自管操作选中与业务外部 selectedOf/onRowSelect 共存 | 返回时只清 controller 自管的复制、删除、批量操作目标；保留业务勾选和保存锁 |
| `FormDraftCategoryTable` | 自定义 onClearSelection 仅转发同名回调，普通 `onSelectedIdsChanged` 宿主不会收到空集合 | 提供普通空集合 fallback，同时清本地草稿行选中，不删草稿 |
| `ShelfLabelPage` | 表格外部 isSelected 由货架定位字段驱动，单清内部高亮无效 | onSelectionCleared 同步清库位/仓库定位与由该选择产生的局部过滤 |
| `showMasterDetailSheet` 的业务详情调用 | 单位、颜色、币种、模具详情用 PopupRoute 呈现；公共页面生命周期有意忽略临时弹窗，无法据此区分业务详情 | 调用方读取详情成功且身份/路由仍有效后，复用来源清选中合同，再打开详情；读取失败/取消不清原选择 |
| `AccountDetailPage` 流水详情 | 流水表只有浏览单选高亮，没有参与收支计算的业务多选 | 复用 isSelected/onSelectionChanged/onSelectionCleared 受控单选；打开流水详情清高亮，查询结果及原币金额不变 |

公共页面入口是两类现有表格的 onReturn；`MasterDataTableView._clearMultiSelection` 同时供返回、选择摘要清除和菜单动作后清除使用，清理重复分支，统一保留宿主 guard。业务详情弹窗在各自成功读取门后复用 onClearSelection、pane.clearSelection 或受控单选合同。没有新增页面逐个拼接的路由回调，也没有修改服务端业务/API/金额精度或权限。

## 行为合同和必要差异

- 从表格打开真实详情后返回、切到另一保活主标签再回来：取消上次访问的单选和多选，清除依赖单选的操作状态。
- 同页重新构建、刷新通知、搜索参数变化、列表分页与列筛选：维持本次访问内的选择语义。既有表头搜索的返回清除规则保持原合同。
- 临时菜单、选择器、确认框、表格全屏展示不视为离开业务页面，关闭后保留选择；菜单执行条目后的清理保持既有合同。业务详情虽然也使用弹窗容器，仍代表打开另一个业务对象，按下表在详情成功准备后清来源选择，返回不恢复。
- `MasterDataTableView` 对多选调用宿主 `onClearSelection`，没有该回调时交回新的空集合；不就地修改宿主集合。宿主的保存/提交锁仍有最终控制权，拒绝清除的进行中快照保持不动。
- `UtenEditableGrid` 的 `selectedOf/onRowSelect` 常直接决定委外出库、质检、先入库等明细是否参与提交，是业务输入。不能因浏览关联详情回来就改变单据的参与行；保留它们。controller 自管选择仅用于复制/删除/批量编辑，在 selectionEnabled=true 时清除。selectionEnabled=false 的提交锁保持快照。
- 不清除数据行、单元格原始输入、文本控制器值、草稿正文、未知提交状态、数量、库存归属、复制缓冲或服务端结果。不依靠删行、截断数据来完成清选中。
- 独立 Flutter Navigator/桌面资料对照窗口没有 GoRouter 页面会话身份时，沿用原窗口生命周期，不把窗口失焦视作离页。WPF 候选及实际运行时验收在整体记录中区分，不以本次 Flutter widget 回归代替。

## 业务详情弹窗调用覆盖

源码检索共六处 `showMasterDetailSheet(`：一处公共函数声明、五处真实调用。公共函数不自行猜测选择语义，也不建立跨页 registry。

| 来源及详情入口 | 采用的清理合同 | 保留差异及调用方验证 |
|---|---|---|
| `UnitPage._showDetail` | `_clearUnitSelection` 同时接表格 onClearSelection | 等待读取及读取失败保留两行选择；成功详情/关闭往返三轮后空选择，表格 State 与两行数据保留 |
| `ColorPage._showDetail` | `_clearColorSelection` 同时接表格 onClearSelection | 同上；不清行内编辑、草稿或写入中操作对象 |
| `CurrencyPage._showDetail` | `_clearCurrencySelection` 同时接表格 onClearSelection | 同上；本位币不可多选规则不变 |
| `MouldCategoryPage._showMouldDetail` | 现有 `MasterEntityPaneController.clearSelection` | 详情读取失败保留选择，成功打开及关闭后选择为空，模具行与未写入事实保留 |

这些入口均在业务详情已成功准备时清理；加载等待、失败、取消、失效身份及未能进入目的详情不提前清理。确认框、普通选择器和菜单不增加任何清选中动作。

平台范围：这五页由 Web/现有 Flutter 桌面共用。WPF 已迁移的单位详情调用已同步清来源选择并通过 x86/x64 实际原生窗口回归；账户详情 `W7-BIZ-018`、颜色 `W7-BIZ-023`、币种 `W7-BIZ-024`、模具分类 `W7-BIZ-031` 在唯一台账仍为 todo，未因 Dart 变更或本机 WPF 部分读取而视为已迁移。后续接入这些原生业务详情时沿用同一成功准备门与草稿/未知提交保护。
