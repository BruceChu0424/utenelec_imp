# V554 合并订货来源剩余供给区间

迁移文件：`server/src/main/resources/db/migration/V554__procurement_source_remaining_supply.sql`。

一条订货行合并多个申请来源时，不能把剩余量、待检量或待入库量重新从 FIFO 第一来源开始分配。来源 A 20、B 30，实收 50 中合格入库 12，剩余 38 待检时，待检覆盖应为 A 8、B 30。旧 `share(38)` 得到 A 20、B 18，会让 B 已在待检的 12 再次形成新通知。38 不合格实际退回后，原订单的待补覆盖仍应为 A 8、B 30，不能对两份分析各抵扣整单 38。

## 派生规则

- 统一使用来源区间 `max(share(区间末累计)-share(区间首累计),0)`，份额仍按原订货行、申请来源 UUID、稳定行序及有效分配数量计算。
- 净合格先分配；待检/待入库承接净合格之后的区间；当前未退回失败量承接两者之后的区间。已实退的历代失败量不再算当前失败池，原 IQC 历史记录不修改。
- 原订单待补区间为“净已覆盖累计”至“当前订货总量”。净已覆盖累计为 `(累计实收-普通退货)×冻结换算率-已实际登记退回的 IQC 不合格基本量`，最小为 0。补回再次到货会继续推进累计，不能把历代不合格重复当新缺口。
- 视图已经计算每个来源的 `alloc_base/prefix_base/末位`，通过 IMMUTABLE 的纯数值 helper 复用，避免每列再次查询全部来源。命令和其他消费者使用同语义的来源 UUID helper。
- 同一行动组经多条 allocation 或多个取消代际指向同一 `order_item/source_item` 时，补货覆盖先按真实来源去重后再汇总。

## 变更范围

新增 `fn_procurement_bounded_interval_qty`、`fn_procurement_source_interval_qty`、`fn_procurement_order_source_remaining_qty`，前向替换 `v_preplan_buy_action_slice_progress` 的派生数量。采购与委外命令的剩余覆盖及分析预计供给消费者同步使用相同区间规则。

没有改写订单、来源分配、收货、库存、IQC、让料权益、应付、贷项或既有审计事实；不需要猜配编码、手工改库存或 repair 旧迁移。现有数据在视图读取及下一次合法分析刷新时由原 UUID 事实重新投影。取消行动仍保持取消，不因回收在途而复活历史行动。

部署必须先成功应用 V554 再运行依赖新函数的服务。回滚应用时保留前向兼容的函数和视图，不删除已有业务事实；若需调整派生规则，使用新的前向迁移。
