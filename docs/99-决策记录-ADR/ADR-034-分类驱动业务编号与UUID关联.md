# ADR-034：分类驱动业务编号与 UUID 关联

- 状态：已接受；V257–V278 实现本 ADR 主体，V279 按 ADR-036 收口全局命名空间；均为源码候选，目标库迁移与岗位 UAT 待验收
- 日期：2026-08-14
- 范围：货品、模具、客户、供应商分类及其主档；相关销售报价/订单、采购、仓库、委外、生产、财务历史展示、来源单与过账关系

> **2026-08-14 局部取代**：[ADR-036](ADR-036-全局业务标识与单据号命名空间.md) 取代本 ADR 第 4 条“不要求跨域互斥”及第 11 条中将单号排除在统一业务标识保留之外的部分。现行候选要求固定前缀与分类显式前缀共用全局 token 终身保留，单据/系统/主档完整标识全局终身占用；本 ADR 的 UUID 关联、快照、分类最近前缀和批量改号边界继续有效。

## 决策

1. 所有运行时业务关联只使用系统生成的 UUID。可编辑的编号、名称、备注和旧库 `legacy_id` 均不得用于 JOIN、权限、幂等或外键身份。
2. 分类的内部 `code` 继续作为不可见的稳定路径段；原用户可见旧编码迁到 `remark`，并保留只读 `legacy_code_snapshot`。用户另行编辑 `code_prefix`。
3. 主档编号采用“最近祖先的显式前缀 + 主档域全局序号”。子分类显式前缀覆盖父分类；空前缀表示继承。默认前缀为货品 `HP`、模具 `MJ`、客户 `KH`、供应商 `GY`。
4. **历史决策，已由 ADR-036 取代**：V276 阶段曾把货品、模具、客户、供应商视为独立编号域。当前规则是自动编号至少补齐六位且不截断，同时由 V279 将归一后的主档、单据和系统完整标识纳入全局终身保留；不同业务域也不得把同一完整编号分配给不同逻辑所有者。
5. 用户可以输入手工编号；统一服务校验其唯一性。输入空值时使用分类规则自动分配。新建、编辑、复制、单条粘贴、批量粘贴、Excel 导入和旧库重导必须走同一分配边界。
6. 分类前缀或父级变化时，服务端先返回影响预览。确认后在序列锁内批量改号；更深层的显式覆盖子树不受影响。批改采用临时编号两阶段交换，并记录批次及逐行历史；任何 UUID 关系都不随编号变化。
7. 已审核业务单据必须读取保存/审核时冻结的货品编号、名称快照。草稿可刷新，审核前重新冻结。销售报价、订单、出退货以及采购、仓库、委外明细采用同一原则；历史回填必须注明来源，不得把当前主档值伪装成原始历史事实。
8. 报价转订单、订单转发货、发货转退货、报工生成库存/补产、总账凭证来源等跨单据关系以来源 UUID 为真源；单号只保留为展示快照。历史自由文本不能证明语义来源时不得猜绑。
9. 货品、客户、模具、供应商缺失分类的数据统一挂到各域受保护的“未分类”系统根；V275 以不可变 UUID 注册表声明四个根的系统身份。普通运行时不得靠 `legacy_id=-1`、名称或内部 code 重新发现；该根不可删除、移动、改前缀或改内部身份，避免活跃主档从分类树中消失。
10. **V276 历史阶段，现由 V279 扩展**：V276 先对货品、模具、客户、供应商、颜色、单位、币种、仓库、账户、结算方式、收付款方式、四类分类内部路径码、部门、员工、固定资产和待摊费用等主档按 `upper(btrim(code))` 建立保留成员。V279 复用并扩展这些证据，将主档、单据、系统号和计划行 `product_no` 的完整标识收口为全局终身占用；软删、硬删或改号都不释放旧值。岗位等确有父级语义的逻辑所有者规则保留，但不能据此让不同实体复用同一完整标识。
11. **V276 历史排除条款，单号/生产分段部分已由 ADR-036 取代**：权限码、角色码、工作流原因码和报表字段码仍是机器键/枚举/列定义，不作为业务编号；单据号和生产执行分段则已由 V279 进入各自不可变命名空间，并与主档完整标识共享全局终身保留。这里的“全局”是唯一性与占用证据，不会抹平各业务类型的语义和取号策略。
12. V277 将账户与会计科目、收付款类别与关联账户彻底收口为 UUID 真源。活动账户缺少 `style_id` 时，只在迁移事务中按已明确的现金 `/101/`、其它 `/102/` 规则一次性回填，且目标必须唯一、启用、属于 ACCOUNT 并为叶子；运行时函数、普通 API 和 Flutter 表单不再按路径或 legacy id 兜底。`*_legacy_id` 只由 UUID 派生，一致性冲突直接拒绝。
13. 货品列表直接返回 `colorId/unitId`，销售、采购、仓库、委外和生产编辑页直接透传这些 UUID。legacy-only 货品在编辑时保持未选择，不得由客户端通过旧整数或名称提升为新关系。
14. 货品 Excel `detect` 必须返回短期一次性 `planId`，逐行固化既有 UUID 或计划内 new-token。`commit` 只接受五分钟内同一操作者、同一 SHA-256 文件且主档指纹未漂移的计划；过期、重复消费、服务重启和任何漂移均要求重新检测，不再按名称二次查找。
15. V278 建立 `system_posting_style_roles` 的 7 个固定过账角色身份：`AR_CONTROL`、`SALES_REVENUE`、`INVENTORY_ASSET`、`AP_CONTROL`、`SALES_COST`、`BANK_FEE_EXPENSE`、`FX_GAIN_LOSS`。迁移期可按已审核路径/名称唯一定位一次，运行时 `GlPostingService` 只通过角色取得持久化 `payment_styles.id`；未映射、停用或类别不符时失败关闭。路径仍可用于报表分类汇总，但不再是过账关系身份。

## 已落地的前向迁移边界

| 迁移 | 已收口内容 | 不采用的猜测 |
|---|---|---|
| V257–V263 | 销售、采购、仓库、委外货品编号/名称历史快照；草稿可刷新，审核冻结，报表读快照 | 不用今天的货品名称伪装历史原值 |
| V264–V270 | 报价、销售头、总账、报工生成单、采购人员/部门等跨单据和人员关系改用 UUID | 不按 `bill_no/source_doc_no`、姓名或旧整数做运行时 JOIN |
| V271 | 销售报价明细货品快照 | 不让报价重打随货品改号漂移 |
| V272/V275 | 货品、客户、模具、供应商“未分类”系统根及固定 UUID 注册表 | 运行时不再用 `legacy_id=-1`、名称或内部 code 识别系统根 |
| V273 | `B_PStyle` 建 `settlement_methods`；独立 `RecStyle` 建 `finance_payment_methods`，销售/采购/委外/AR-AP/钱流引用 UUID | 不把两套旧字典强接到 `payment_styles`，不让未确认占位名称进入正常选择器 |
| V274 | 仓库所属车间写 `workshop_department_id -> departments.id`；旧 `WorkID` 明确保留为 `Sys_Operator.ID` 影子 | 不按仓库名、车间名或误命名的 `workshop_legacy_id` 猜车间 |
| V275 | 生产日报计划行/销售行 FK；授权库存调整改用 UUID 命令关系 | 不用计划号、销售单号或 `source_doc_no` 前缀做身份/授权/幂等 |
| V276 | 主档编号终身保留、历史重复成员登记、并发锁、审计和最新全表审计覆盖 | 不静默重写历史重复；不因删除或改号释放旧编号 |
| V277 | 活动账户科目和类别关联账户 UUID 强约束；迁移期一次性默认回填；前后端只提交 UUID | 不在运行时按 `/101/`、`/102/`、账户类型或 legacy id 推断关系 |
| V278 | 7 个系统过账角色持久化映射 `payment_styles.id`，角色键/类别不可改删，映射科目必须启用、类别匹配且不被两个角色共用 | 不在运行时按科目路径、名称或“第一条”选择过账科目 |

## 并发与审计

- 分配和批改在每个主档域的序列行锁内完成；应用检查之外仍保留数据库唯一约束。
- 分类使用乐观锁版本，避免两名用户同时编辑前缀或父级时静默覆盖。
- 批次、逐行新旧编号、操作者和时间进入审计。货品图片等大字段不得复制进批量改号审计 JSON。
- V276 的 `master_code_reservations` 与 `master_code_reservation_members` 只追加且逐行审计；迁移前已有的重复编号登记为多个历史成员，允许原记录保持和编辑，但禁止任何新身份继续占用。受控全量重导只有在旧 `legacy_id` 完全一致时才可恢复同一身份。
- 直接 SQL 绕过统一服务不属于受支持的新写路径，只允许受控迁移脚本；迁移脚本也必须预留序号并写明来源元数据。

## 兼容与上线边界

- `*_legacy_id` 只作为旧库兼容影子。普通在线新建/编辑必须直接提交 UUID，不允许以旧 ID、编号或名称反查后生成关系，也不允许在 UUID 缺失时静默回退；只有显式 legacy 导入/适配器或历史只读展示可按正确命名空间解析旧 ID，且未命中、多命中或 UUID/旧值冲突一律失败关闭。
- 既有 Flyway 文件不可修改；本方案只使用新的前向迁移。
- 本地空库/容器迁移和测试不是公司目标库验收；公司目标库仍保留 V238 既有只读证据。上线前仍须在可恢复的目标库副本执行迁移、冲突预览、历史快照与系统过账角色对账、并发验证、备份恢复演练和多角色 UAT。
- 已确认的账户款类、人员、采购部门/采购员采用 UUID 真源；普通在线写入不接受旧 ID/姓名兜底。旧 ID 唯一解析仅限受控迁移与历史只读兼容，UUID 与旧值冲突时拒绝写入。
- 老库语义已经核清：销售/采购/委外/AR-AP 的 `PStyle` 同属 `B_PStyle`；钱流收款/付款方式同属独立 `RecStyle`；仓库 `B_Storage.WorkID` 属于 `Sys_Operator`，不是车间。源码候选据此拆建 UUID 主档和关系。目标库执行 V273–V278 前仍须先在可恢复副本核对字典行数、历史未命中值、旧编号冲突、账户科目默认路径唯一性、7 个过账角色映射和仓库人工 crosswalk；任何未确认值保持空 UUID/阻断新写，不得恢复按名称或数字猜接。
