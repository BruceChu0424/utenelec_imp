# 我的车间任务页 (/production/workshop-tasks)

更新：2026-09-21([ADR-096](../99-决策记录-ADR/ADR-096-车间任务三条路线通用与路线记忆批量设路线.md)，V629；[ADR-095](../99-决策记录-ADR/ADR-095-车间路线开工前随时可换与逐种物料事实.md)，V628)。ADR-096 起：无需物料的任务同样可选三条路线；路线记忆两档(同产品上次确认优先，其次你上次的选择)；勾选未确认/物料不齐的行也可勾，首列压锁说明不能开工，「批量设路线」按路线逐行提交；缺口按「自制子件」归桶，不再承诺「直送」。本页描述当前有效交互；9 月 18 日自动识别并立即应用路线的旧交互已由明确路线确认取代，同日上午引入的「路线确认」底部面板（草稿+确认按钮两步流）当日下午按用户口径退役——「下一步」列内直接下拉、**选中即提交**。ADR-095 起：**开工前路线随时可换**（实际领料、直送投入不再冻结，只有开工或已有报工才冻结）；状态文案与新增的「物料」列只按服务端逐种物料事实生成，「齐」只在每种物料都实领到车间时才说，同车间子件未流转不算到料。历史已发生的领料、开工、报工、品质和入库事实继续保留，迁移规则见 [ADR-091](../99-决策记录-ADR/ADR-091-开工路线确认与到货进展通知.md) 与[迁移索引](../数据迁移/README.md)。

## 入口与任务形成

物料分析创建自制备料任务，不等于已经下达车间。审核后的正式生产计划形成执行工单，继承合法车间和负责人，WAITING 工单即可在对应车间看到。不得为了任务可见自动批准计划、猜负责人或生成领料。

顶部保留「等待物料 / 生产中 / 历史任务」。默认未选分类不请求列表，只读取活动任务计数；历史任务须选时间范围或明确「全部」后查询。搜索、车间、备料状态和分页由服务端处理，列表和徽章使用同一员工范围。行 UUID 是唯一动作身份，货品名称和编号只用于展示。

表格按分类展示：等待物料依次为状态、下一步、物料、产品、编号、颜色、订单、工单、车间、数量；生产中依次为状态、生产路线（只读徽章）、物料、产品、编号、颜色、订单、工单、车间、数量、进度——**「生产中」不显示「下一步」列**，报工由勾选后的批量报工入口办理。行右键菜单提供开工、领料、分批领料、查看用料、核对备料与查看计划等动作。双击打开本任务详情（含每种物料的数量表），不要求普通车间员工取得全计划权限。

「下一步」表头可按路线筛选：待选生产路线 / 齐套生产 / 持续生产 / 分批生产（服务端 `routeFilter` 在分页前生效）。

状态颜色(2026-09-20 用户口径「不同状态不同颜色、差别大点」「部分物料可领和物料已备齐的颜色还是一样的」)：待选生产路线=红(车间必须先做决定，其它动作全部锁着)、等待物料/等待到货/等自制子件完成=琥珀、部分物料可领=紫、物料已备齐去领料=蓝、部分物料已投可开工=品牌青、物料已领齐可开工=绿、已提交领料待仓库发料=灰、生产中=品牌青(与「部分已投」不在同一分类出现)。路线徽章沿用齐套=绿、分批=蓝、持续=品红。

## 先确认路线，再办理

尚未确认路线时，「下一步」格就是生产路线下拉框：点开显示当前可用选项（齐套生产 / 持续生产 / 分批生产），**选中即携带执行段版本提交**——没有草稿、没有确认按钮、没有弹窗，提交期间显示居中加载遮罩。未确认的行预填**路线记忆**(V602 恢复，ADR-096 加操作者档)：先按同产品最近一次有效确认的开工路线，本产品没有历史时按你自己最近一次确认的路线；仅在该路线仍是当前可选项时预填，旁挂黄标「已按本产品上次选择的路线预填，请核对」或「已按你上次选择的路线预填，请核对」——预填只是展示，不写任何事实，选中或批量确认才提交(ADR-093 明确确认口径不变)。无记忆或记忆不在选项内时显示「选择生产路线」空占位。无需物料的任务同样可选齐套 / 持续 / 分批(ADR-096)：持续=随时可开工，分批=按数量拆成两个生来可开工的零料子任务。

| 路线 | 开工前提 | 后续到料 | 适用情况 |
| --- | --- | --- | --- |
| 齐套生产 | 所有必需物料按计划需求到齐，仓库料实际领齐，直送料完成交接 | 同任务办理剩余领料；未齐套不提前开工 | 一次备齐再生产 |
| 持续生产 | 每种必需物料共同支持正产量，仓库料已实际发出、直送料已真实交接 | 在原工单继续领料或接收直送，工单只开一次工，按实际报工推进 | 采购或生产分批到货、边补料边生产 |
| 分批生产 | 明确本批产量并按该批完整齐套、领齐 | 剩余数量保留，后续显式再拆批；各批独立开工/报工 | 各批必须独立管理 |

持续生产不要求先填开工数量，不要求一定存在直送子件，也不把仅一项物料到货当成支持生产。BATCH 不作为普通分次领料的默认办法。路线确认、领料、开工是不同事实，确认路线不代替开工。

**开工前路线随时可换**（ADR-095）：只要任务未开工且没有报工，下拉一直开放，选中即提交；已备料、已领料、同车间直送已投入的事实一件不动。三条路线只在**开工门槛**上不同：

- 改齐套：已备物料保留、继续补齐，每种物料实领到位后才可开工（曾按持续生产备过部分料的任务状态不回退，标签「等待物料到齐 · 已备 a/n 种」）。
- 改持续：开工门放宽为每种必需物料共同支持正产出；WAITING 的任务立即按增量备料补跑一次。
- 改分批：要拆出独立子任务，仍只在尚未备料、领料或绑定供给时可选(无需物料的任务生来 READY，同样可拆)；不可选时下拉不出现该项，悬停说明「已备部分物料，不能再拆分批」。

已开工或已有报工后冻结，格退化为只读徽章回显，悬停说明冻结原因(红冲报工方可解锁)，不通过更改路线删除历史。路线可逐行选定，也可勾选多行后批量提交(ADR-096)，批量有两个入口：**在任一勾选行的「下一步」下拉直接选**——被改的行已勾选且勾选集里还有别的可设路线行时，一次下拉就对全部勾选行提交，悬停说明先讲清「本行已勾选：会一并确认全部 N 个勾选行」(2026-09-21 用户口径「我明明多选了，选中一个，为什么批量设路线还要重新选」；此前下拉只改本行，其余行只是被路线记忆预填成同样的字)；或用「批量设路线(N)」菜单按路线提交：菜单项「齐套生产(n) / 持续生产(n) / 分批生产(n)」括号里是勾选行中支持该路线且当前不是该路线的行数，「按预填默认值确认(m)」把带记忆预填的行各按自己的预填一次确认。两个入口同一套筛选(不支持该路线或已是该路线的行自动跳过)，没勾选的行在下拉里照旧只改自己；每行携带各自版本，不适用、版本冲突和部分失败按行提示并刷新。等待物料分类里不能开工的行(未选路线、物料未齐、待仓库发料)在首列勾选框角上压一把锁并悬停说明，勾选仍可用于批量设路线，批量开工计数不含它。提交中显示居中加载遮罩，防止重复点击。

## 物料来源与数量

路线决定生产节奏，来源决定物料如何交接，两者分开。一个任务可同时包含普通仓库领料和本车间上下层直送料：

- 普通仓库料在「去领料 / 继续领料」汇总中按真实仓库、货品、颜色和单位 UUID 聚合，保留每条 DRAW 明细及原任务 UUID；本次可选择物料和数量，剩余量保留待领。
- 车间直送料按服务端真实来源与交接投入，不在仓库领料汇总重复申请。不把车间流转身份解释为货品默认存放仓。

当前车间未用完的直送料可以送正常仓库，无需送回上游生产车间。余料申请区显示“来源位置”用于追溯；仓库在“确认余料收仓”中选择实际正常收料仓库。尚未领用的直送来源显示“车间直送（未投用）”，不要求先虚构领料或开工。收仓前数量仍处于待交接冻结状态，正常库存只在仓库确认后增加；后续生产从真实收仓位置续领，保留同一任务及来源关系。
- 待检、拒收、预计在途、待仓库发料不等于实际投料；页面采用后端 `canStart` 与 `canRequestDraw`，不自行拿 READY、库存行数或全量 issued 标志猜开工资格。
- **逐种物料事实**（ADR-095，2026-09-20 用户口径「物料没有齐不能显示齐，车间内流转的要流转了才算；车间内流转的数量怎么统计、显示在哪里」）：服务端把每种正式物料需求归入且只归入一个桶——已领到车间(含同车间直送已投入)/ 缺·等采购到货或委外回厂 / 缺·等自制子件完成(子件工单产出可能线边直送也可能入库后领料，交接方式在子件报工时才决定，未流转到本任务不算到料；ADR-096 起不再写成「直送」)/ 已备好可领 / 已申请待仓库发料 / 直送料待开工自动投入 / 备料中。「物料」列显示 `已领 a/n 种 · 缺 k 种(自制子件 j) · 可领 m 种 · 待发 p 种`，其中「缺 k 种」红色、「可领 m 种」绿色、「待发」次要灰(2026-09-20 用户口径)，悬停逐桶解释并给出已投料可产量；详情弹窗逐种列出需求 / 仓库已到(齐套到齐前不预留，按齐套提升同口径的仓库可用量显示)/ 直送已交接 / 已领 / 缺口 / 状态 / 承担的子件工单，来源写「自制子件 · 直送或入库领料」。
- 状态文案只按这些事实生成：可开工时每种物料都实领才说「物料已领齐 · 可开工」，否则「部分物料已投 · 可开工」；可领料时缺料说「部分物料可领 · 去领料」，全备说「物料已备齐 · 去领料」；已提交待仓库发料；缺料按持续生产说「等待到货 · 缺 k 种」/「等自制子件完成 · 缺 k 种」，按齐套说「等待物料到齐 · 已备 a/n 种」。表头「去领料」筛选桶名为「物料可领 · 去领料」，不宣称齐套。生产中明确按实际投料报工；「待报数量（含品质恢复）」来自计划剩余及有效恢复授权，不能冒充物料支持量。本次可报上限由报工来源接口精确计算，并分别保留品质恢复授权。

领料提交沿用已审预览指纹、执行段版本、明细 UUID 与幂等键。请求结果不明确时重试原意图，不能刷新生成第二次领料。聚合提交可以跨任务但必须同一车间，一次最多 50 个任务。

## 进行中与异常后续

只有显式开工后的 IN_PROGRESS 工单可以报工。生产中主链为「继续领料 / 分次报工 / 查看用料记录」：报工仍由勾选后的批量报工入口办理，一次同车间，申请权限不等于允许跨车间写入。无报工权限但有任务查看和开工权限的员工仍可办理本任务的后续领料。

实耗在生产日报随报工登记，车间任务页保留只读材料台账和退料进度；共享批次台账必须返回真正原领料任务 UUID，不把余料、损耗或在制自动当实耗。退料发起与仓库实收、品质通过与产成品实收入库各自是独立事实。返工再检、拒收重新交付、报废补产沿既有同源授权办理，不重复普通报工，不自动抹掉原失败或少收记录。超计划产出和领料仍由服务端明确校验。

原料退回或发生品质失败后，不使用旧页面能力快照继续提交；版本冲突返回刷新提示。持续补料使用原任务；只有选定分批路线才形成批次谱系。

## 到料通知

`PRODUCTION_WORKSHOP_TASK_ACTION_REQUIRED` 已进入统一居中待办弹窗 `ReviewPendingDialog`，登录和在线到达共用。卡片完整显示服务端计算的到料、缺口与下一步文案，单条和多条聚合均不截断车间物料正文；弹窗内部滚动。点击进入我的车间任务。通知中的到料不等于已领料，也不代替路线确认或开工；实际资格始终重新读取任务。到料事件携带 IQC 入库批次、产成品入库单或直送日报 UUID；消费前复核来源仍有效，已反向或旧事件缺少证据时只能重建中性当前状态提示。采购、委外、产成品和直送反向同时撤回旧卡并按当前事实重建，避免异步晚到重弹旧数量。

本次某一种必需物料已归本任务即可提示，不要求整单已经齐套；他单纯专属来源不弹，公共切片按本主仓实际可用量与安全量判断。卡片缺口清单按「仓库已到 X，还缺 Y」表述（齐套生产到齐前不做段级预留，缺口扣掉齐套口径的仓库可用量，不再把「到了 100 还缺 900」说成「还缺 1000」），自制子件供应的缺口标注「(自制子件在产)」，不预言直送还是入库。暂停、关闭、取消计划不产生开工行动卡，旧卡办结。卡片确认、已读、稍后和业务办结沿统一通知协议。开工前到料通知与持续生产后续补料进展以当前任务事实刷新，禁止仅按前端文字猜是否办结。

## 权限与刷新

| 操作 | 页面与动作权限 |
| --- | --- |
| 工作台卡片、列表、徽章、任务详情（含逐种物料端点 `GET /api/production/workshop-tasks/{segmentId}/materials`） | `production_execution:view`，后端本人车间/负责工单范围 |
| 路线确认、领料、继续领料、拆批、开工 | 查看权限 + `production_execution:start`，后端复核任务写范围和版本 |
| 批量报工 | 任务查看 + `production_daily_report:view` + `production_daily_report:create`，仅已开工来源 |
| 查看完整生产计划 | 独立 `production_plan:view`；普通车间默认权限不因此扩大 |
| 实耗、退料、反向、结案 | 既有材料/品质/仓库专用权限及真实来源范围 |

超级管理员可替车间办理，但仍受版本、物料、路线和来源守恒约束。普通负责人、计划编制人都必须是当前有效员工；拥有相应动作权限的编制人可沿管理范围办理，所有人身份不能绕过动作授权。暂停/关闭计划不再暴露领料、开工等执行能力。页面启动、返回、操作成功和共享执行刷新信号均读取服务端事实；迟到请求通过 generation 丢弃，账号切换/注销清空旧计数。分页和搜索不在客户端先下载全部工单再筛选。

任务改派以实物为界：未实发且没有共享物料批次依赖时可以换车间，已有未发领料草稿同事务同步收料车间和人员；已经发料或直送后不能靠改派转移实物。同车间换有效负责人不重写历史发料人。报工页面按整个执行任务剩余目标判断最后一批，按本次实际投料计算可报上限，两者分别显示和校验；整包/固定批次的实际耗用由人员确认，不按平均数自动填写。

再次编辑日报会恢复精确计划身份、排除本草稿后的任务余量及已填用料。材料读取失败时保留原已存用料，不能在普通保存时悄悄删除；成功更换来源后才按新来源清理原用料。已选择的直送去向也不会因为候选失效或网络失败自动变成送仓库/另一个任务，须重新核对接收工单。
