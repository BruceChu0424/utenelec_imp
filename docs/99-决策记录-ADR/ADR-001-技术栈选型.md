# ADR-001 - 技术栈选型：Flutter

- **状态**：已接受
- **日期**：2026-07-21
- **决策者**：项目 Owner + 架构
- **影响**：整个项目

---

## 上下文

Uten IMP 需要覆盖 手机 / 平板 / 桌面 / Web 多端，团队规模有限，不能为每个端单独开发。需要选定一套技术栈作为项目基础。

候选方案：
1. **Flutter**（Dart）
2. **React Native**（JS/TS）
3. **原生各端分别开发**（Swift/Kotlin/C#/Web 各一套）
4. **纯 Web**（响应式网页）

## 决策

**选定 Flutter 3.41+ / Dart 3.x**。

## 理由

| 维度 | Flutter | RN | 原生 | 纯 Web |
|---|---|---|---|---|
| 多端覆盖 | ✅ 六端一套 | ❌ 桌面弱 | ❌ 各做各 | ✅ 浏览器都跑 |
| UI 一致性 | ✅ 自绘 | ❌ 双端不一致 | ❌ 各端差异 | ✅ |
| 性能 | ✅ AOT 编译 | ⚠️ JS Bridge | ✅ 最佳 | ❌ 移动端弱 |
| 桌面支持 | ✅ Windows/macOS/Linux | ❌ 不成熟 | ✅ | ✅ |
| Web 支持 | ✅（虽不是最强） | ❌ | — | ✅ |
| 团队学习成本 | 中等（Dart 新语言） | 低（JS） | 高 | 低 |
| 制造业后台适配 | ✅ | ⚠️ | ✅ | ⚠️ 移动端体验差 |

关键决策点：
- **桌面端是人事/财务/管理层的主力设备**，RN 桌面生态差直接出局
- **手机端是员工的主力设备**，纯 Web 在手机上体验不够好
- Flutter 一套代码六端覆盖，**单团队可维护**

## 后果

### 正面
- 一套代码、一套状态管理、一套组件库
- UI 在所有端高度一致
- Dart 强类型 + 空安全，重构和可维护性好
- Flutter 生态成熟，企业场景有先例

### 负面
- Dart 对团队是新语言（但语法接近 Java/Kotlin/JS，学习曲线平缓）
- Flutter Web 性能不如纯 Web 框架（但对内部企业后台够用）
- 桌面端某些原生能力需要平台通道（本项目基本不需要）
