## 🚀 如何运行

> 本节 `flutter run` 仅用于开发调试。公司员工入口必须发布 Web Release 并由受监督的静态站点/后端服务提供；否则调试进程退出后刷新必然出现“localhost 拒绝连接”。稳定运行基线见 [deploy/README.md](deploy/README.md)。

```bash
# 1. 安装依赖
flutter pub get

# 2. 生成国际化文件（修改 arb 后需重新生成）
flutter gen-l10n

# 3. 运行（自动检测平台）
flutter run

# 4. 指定平台
flutter run -d chrome        # Web（推荐：浏览器拉宽即可看到响应式效果）
flutter run -d windows       # Windows 桌面
flutter run -d android       # Android（需模拟器或真机）

# Release：Web 默认同源 /api，并把 CanvasKit 等运行时资源打进同源产物
flutter build web --release --no-web-resources-cdn --dart-define=APP_VERSION=<version>
flutter build windows --release --dart-define=APP_VERSION=<version> \
  --dart-define=API_BASE_URL=https://<lan-host>/api \
  --dart-define=CLOUD_API_BASE_URL=https://<cloud-host>/api

# 代码检查
flutter analyze

# 只格式化本任务的明确文件；共享脏工作区禁止全库格式化
dart format path/to/file1.dart path/to/file2.dart
```

### 本地开发验收路径

> 前端使用真实后端认证与业务 API，仓库不提供“任意账号密码”或可提交的演示凭据。开发环境
> 未指定 `API_BASE_URL` 时连接 `http://localhost:8080/api`；Release 规则见
> [多端发布与签名](docs/99-项目治理/多端发布与签名.md)。

1. 启动 App → `/entry` 选择员工入口 → 使用后端有效账号登录。
2. 若账号标记 `mustChangePassword`，必须先完成强制改密，不能绕过进入业务页。
3. 工作台、导航、按钮与路由按服务端权限显示；Dashboard 的通知、生产、仓库/采购/委外履约、访客/档案审核、财务、销售与政策聚合是真实服务端能力。履约分区故障时应局部降级并提示不可用，不能把占位 `count=0` 当成权威零待办。
4. 设置页验证主题、语言、字号、性能档、版本信息、修改密码与二次确认退出。
5. 拉伸 Web/桌面窗口并在手机/平板验证响应式、文本缩放、键盘和滚动边界。
6. 切换 lite/standard/rich，确认动画与特效按性能策略降级且业务功能不受影响。
7. 退出后当前安装和所有标签应立即 fail-closed，旧 refresh 在加密队列中最终撤销。普通 logout 不保证已泄露的 access 立即在服务端失效；它最多存活到短 TTL（源码默认 15 分钟），需要立即全局清退时必须另用 `auth_version`/授权 epoch/issuer/签名密钥轮换等受控机制。
8. 验证短时断网、超时、HTML/空体/未知 401 和结构化 503 不清会话；恢复后横幅显示“网络已恢复，可以继续使用”，当前工作台自动重读。
9. 验证只对 GET/HEAD/OPTIONS 最多额外重试两次（400/1200 ms），创建、审批、过账等写请求不自动重放。
10. 用三标签、离线退出后重启、损坏安全记录、真实 12/18 KiB 请求头和严格 JSON health 完成稳定性验收；发布入口不得使用会随调试进程退出的 localhost。
