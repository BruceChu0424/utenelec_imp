# 付款与预收业务引用摘要 CI 同步

当前完整主档/业务引用读取已使用 `POST /business-references/{suppliers,clients}/summaries`，两份旧测试仍只拦截原 GET 路径，导致实际候选读取没有进入夹具，查询记录为空。这里只在两份测试补齐原纯读 POST 合同：从 `body.filter` 记录原选择资格，固定实际 100 条批次，复用公共 `versionedSummaryTestResponse`，提供 64 位十六进制快照与数据证明。不修改产品或默认业务权限。

付款仍仅列可新选供应商，保留历史原 UUID/名称；候选在打开后被隐藏时，实际确认重新 lookup 并拒绝替换，原付款内容不写入。摘要读取不计成命令写入，其他所有付款 POST 仍严格拒绝；新增零写断言。客户预收流水继续允许历史已隐藏客户，选择后按其原 UUID 查询，保留“客户预收流水”、原资金单号、金额、币种、日期与复合权限合同。

两份修改连同原预收空态完整文件，原 17 项通过、2 项失败，修复后 Native 19/19 通过；三文件严格分析无信息、警告或错误。实际 Chrome 为预收两个完整文件共 7 项，加付款原首个真实候选交互 1 项，共 8/8 通过，无新增 skip。付款文件的原生 File 源码契约及其余付款/AP/汇率/币种/银行实付/微小费用/固定精度/幂等断言仍由 Native 完整文件覆盖，不称付款整文件已完成 Chrome。
