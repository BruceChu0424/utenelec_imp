# V535：合格来源跟随实际入库仓库

计划仓库用于安排物料。采购、委外回厂或自制的本批合格品最终入在哪个实际仓库，后续专属备料、领料、委外出仓和原单撤回就沿用这个实际仓库。不能因为实际仓与计划仓不同，让已经到货的车间任务一直显示缺料。

这条规则只适用于能证明来源的本任务合格库存。普通公共库存仍遵守原来的仓库、状态和安全库存规则；未检验、不合格、其他订单的专属库存不能拿来填缺口。测试时选了带“不良”属性的仓库，也必须同时证明本批货本身已通过品质验收及真实入库，不能仅凭仓库里有数量就判断齐料。

## 来源与数量

迁移文件：`server/src/main/resources/db/migration/V535__qualified_origin_actual_warehouse_fulfillment.sql`。

- `preplan_analysis_stock_exact_pegs.make_source_analysis_item_id` 保留直接自制的真实子分析明细 UUID，与旧版下达动作来源互斥。没有旧动作的新自制链不再编造旧来源。
- `fn_preplan_reservation_has_qualified_origin` 核验原品质记录、实际入库明细、实物流水及来源归属。可证明的采购分批入库逐笔核验实际数量，不能把整张品质单的合格总数重复用于每个入库批次。
- `stock_reservations.requires_qualified_origin` 标明正式需求占用依赖的特殊来源。事务提交时，真实来源到实际仓的 `FORMALIZE` 减去 `RESTORE` 必须覆盖目标占用的 `qty - released_qty`。同一来源、货品、颜色、实际仓库和需求归属不能更改。
- 一个采购来源分批入两个实际仓时，只有部分到货仍等待；全部合格且足量后，生成各实际仓对应的领料单。撤回按原来源和原实际仓恢复，不增加公共可用数，也不重复下达。

## 委外前置自制

有子层级的委外件，内部组装完成仍属于待委外的专属半成品。它不会成为父层可直接使用的最终委外成品，也不会因为入库而重新创建原子层自制任务。

计划生成的前置自制库存由 `SUBCONTRACT_PREPARE_TASK` 持有；直接委外订货单生成的前置自制库存由 `SUBCONTRACT_ORDER_PREPARATION` 持有，后者的所有者就是原委外订货明细 UUID。两种方式都保留原 `FINISHED_IN` 单据、明细、实际仓和品质依据。

财务通过后，符合条件的专属库存交接给实际出仓计划 `SUBCONTRACT_OUTBOUND`。一项前置自制分批入不同实际仓时，出仓单也按真实仓分别生成。出仓撤回、订货撤回后，库存归还原持有者和原入库来源；不能释放给其他订单。原入库撤回还必须先完成其下游出仓和占用的反向处理。V536 另外负责相应成本的原来源归还，不能用普通出库代替。

数据库延迟约束检查原件持有量、活动出仓量和已发量之间的守恒；原件入库后不能直接修改前置自制身份、实际仓或释放专属量来绕过原订单。

## 历史与验证

迁移增加两个业务列及来源约束，不新增另一套库存账。既有来源和历史流水保留；无法证明的老库存不会自动变成某订单的专属合格来源。所有变更在 Flyway 事务内执行，禁止关闭触发器、改写已应用迁移或修补校验和继续运行。

`QualifiedSourceWarehouseEndToEndTest` 覆盖采购分批、跨仓齐料、其他来源不能补缺口、取消恢复及直接自制；`SubcontractPreparationActualWarehousePostgresTest` 覆盖标准/直接委外前置自制的实际仓、专属原件、财务、出仓和原来源反向；`ProductionMutationFootprintPostgresTest` 核验跨仓锁范围。验收必须运行到当前完整迁移版本并核对数量和来源，不能仅以编译或单项旧版本测试代替。

这是候选代码说明。公司服务器是否完成迁移，以正式发布记录、Flyway 历史和发布后业务验收为准。
