隔离 PostgreSQL 完整应用 765 个正式迁移至 V839。升级演练先保存自定义品牌和规范化 PNG、全部 25 项非默认运行策略、用户主题/表格布局 JSON 与通知静音记录，随后重建服务实例、重复执行正式迁移、追加仅存在于测试临时目录的 V840 新列迁移。原值、完整图片字节、版本、修改人和修改时间逐项相同，旧 API 实现仍可读回。临时修改历史 V839 副本会被 Flyway 拒绝，既有配置不变；实际源码历史文件没有被测试修改。

客户端以稳定偏好键和安装身份继续读取旧设置。仅成功的服务器响应能更新公开品牌缓存；缓存按可信接口/网页 origin 隔离，图片绑定品牌版本及摘要。断网与升级中旧接口 404 保留最后确认的品牌，默认值不写回服务器，管理页缓存只能只读展示。固定 v1 夹具不从当前模型/默认值生成，后续版本必须继续兼容旧字段及已接受的长度范围。

更新器把程序发行目录与数据库、环境文件和附件原件分离，代码回滚不自动恢复旧数据库。Windows 的技术 CompanyName/ProductName、各端应用标识、Android 正式签名要求与 Web 同源/不清用户存储均由 CI 源码契约保护。正常兼容升级之外的卸载清数据、变更公司域名/数据库及恢复旧备份，仍使用各自的数据保留与迁移流程。

此证据没有进行桌面/手机安装器的真实安装升级，也没有发布安装包或更新服务器；正式发布仍需按版本核对签名、应用标识、数据路径及实际升级前后配置。

Windows 可见窗口标题通过单独的 `com.uten.imp/window_title` 通道使用当前平台名称。原 Win32 初始标题、Runner.rc 的技术 CompanyName/ProductName、可执行名和安装身份保持原值；标题更新只调用 `SetWindowTextW`，不创建或迁移本机数据目录。原生严格校验有界 UTF-8/UTF-16 和控制字符，在销毁引擎前注销通道；旧运行器不具备该通道时客户端安全忽略。
