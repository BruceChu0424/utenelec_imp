# 目录结构与模块边界

> 本文描述当前仓库的稳定目录职责，不再维护容易过期的“逐文件手写清单”。真实文件以
> `rg --files` 和冻结提交为准；新增/删除模块时必须同步 README、架构、实体字典与对应页面文档。

## 一、顶层目录

```text
uten_imp/
├─ lib/                 Flutter 应用源码
├─ test/                Dart 单元、Widget 与架构边界测试
├─ server/              Spring Boot 后端、Flyway、迁移与运维脚本
├─ docs/                需求、架构、页面、数据模型、迁移、ADR 与治理报告
├─ assets/              字体、图标、图片、动画等运行资源
├─ android|ios|web|...  Flutter 各平台工程
├─ pubspec.yaml         Flutter 依赖与资源声明
└─ README.md            项目入口与当前生产结论
```

当前没有 `integration_test/`，也没有仓库内 CI workflow；因此不得宣称关键业务 E2E、
全新 PostgreSQL/Flyway、迁移或权限矩阵已经自动化。`build/`、`.dart_tool/`、IDE 文件、
本地日志、`_scratch/`、老库备份和原始产品资料均是本地产物/受控输入，已由 `.gitignore`
排除，不属于可发布源码。

## 二、Flutter 分层

```text
lib/
├─ app.dart / main.dart
├─ core/
│  ├─ constants/ io/ l10n/ network/ performance/
│  ├─ responsive/ router/ security/ theme/ ui/ utils/
├─ shared/
│  ├─ auth/ models/ providers/ repositories/ widgets/
├─ components/
│  ├─ brand/ buttons/ cards/ data_display/ feedback/
│  ├─ forms/ inputs/ layout/ print/ settings/
└─ features/
   └─ <feature>/
      ├─ models/ pages/ providers/ repositories/ widgets/  （按需创建）
      └─ 其它 feature 私有子目录
```

职责：

- `core/` 是框架级能力，不依赖具体业务 feature。
- `shared/` 是跨业务共享的认证、模型、Provider、Repository 和 Widget。
- `components/` 是可复用 Uten 设计系统组件；只服务单个 feature 的组件留在该 feature。
- `features/` 按业务域组织。页面不得直接访问数据库，网络调用统一经 Repository/API client。
- 空目录不预创建；只有一个调用点的私有实现不应为了“组件化”强行抽象。
- 跨 feature 依赖由 `test/architecture_boundaries_test.dart` 约束，新增例外必须有 ADR。

工资与员工报销的前端 Mock 文件已从当前工作树移除，页面改用 Dio Repository 契约；V133
领域表、真实 API 与固定状态机也已有源码。但在薪酬/审批口径、权限、审计、会计和生产 E2E
完成前，仍不能描述为功能验收完成。后端 `/api/finance/expenses` 是一般费用单，不能替代员工
`/api/expense-claims`。
员工域旧 `MockEmployeeRepository`、旧 employee model 和旧 Provider 也已删除，当前员工页面只走
统一的真实 Repository/API 模型；禁止新增旁路 Provider 或在请求失败时回退到本地假数据。

## 三、后端模块化单体

```text
server/
├─ pom.xml
├─ src/main/java/com/uten/imp/
│  ├─ config/          安全、MVC、属性与基础配置
│  ├─ security/        JWT、当前主体、限流等
│  ├─ audit/           请求/业务/表审计查询与写入
│  ├─ common/          跨域公共基座
│  ├─ features/        业务模块
│  └─ legacy/          Java 分类树迁移
├─ src/main/resources/
│  ├─ application*.yml
│  └─ db/migration/    Flyway 唯一 schema 演进源
├─ src/test/java/      后端单元/架构测试
├─ legacy_migration/   离线导出与破坏性首次引导
└─ ops/                运维 SQL/脚本
```

后端约束：

- Controller → Service → Repository；Controller 不直接注入 Repository。
- 跨 feature 只通过公开 Facade/Port；报表只读查询是受控例外。
- schema 只通过 Flyway 修改，`ddl-auto=validate`；当前源码最高版本必须从
  `server/src/main/resources/db/migration/` 实时确认，目标库以 `flyway_schema_history` 为准。
- SQL/JPA 查询参数化；动态排序、列和视图名必须白名单。
- 写操作的权限、对象级数据范围、状态机、幂等、并发和审计都在后端负责，前端隐藏按钮不是控制。

## 五、命名与清理规则

- Dart 文件、目录、变量使用 `snake_case`；类型使用 `UpperCamelCase`。
- Java 包小写，类名 `UpperCamelCase`；Flyway 使用 `V<version>__<description>.sql`。
- 一页一档、一共享组件一档；局部私有 Widget 不强制单独文档。
- 不提交生成目录、本地日志、数据库备份、CSV 迁移包、IDE 配置、临时密钥或 `_scratch/`。
- 删除代码前用 `rg` 验证无引用；删除数据库对象只能新增 Flyway，不能回改已发布迁移。
- 不保留“backup_old”“final2”类源码副本；历史由 Git 管理。
- 迁移 reject、对账和 manifest 属受控证据，不能当普通临时文件随意删除。
