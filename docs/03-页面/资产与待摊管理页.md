# 资产与待摊管理页

> 路由根：`/finance/assets`
> 设计依据：[ADR-018](../99-决策记录-ADR/ADR-018-资产与待摊专业子账及不可变过账.md)
> 本页是专业资产子账工作台，不是固定资产和待摊两个普通 CRUD Tab。
>
> **生产状态：NO-GO。** 页面已交付安全骨架和月度工作台，但
> `UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED=false` 为默认生产门禁；初始确认、处置和提前
> 终止在补齐专用业务事件反冲及状态恢复前不可用。

## 一、用户与权限

| 用户 | 主要任务 | 权限 |
|---|---|---|
| 财务只读/内审 | 查看台账、计划、审批、事件和凭证 | `finance_asset:view` |
| 资产会计 | 建草稿、补资料、提交、归属变更 | `finance_asset:edit` |
| 财务复核 | 审核资产、待摊和月度运行 | `finance_asset:approve` |
| 过账人员 | 月度过账和正常批次反冲；初始入账受默认门禁保护 | `finance_asset:post` |
| 处置负责人 | 处置/终止准备与安全驳回；最终批准还必须同时具备过账权限且受默认门禁保护 | `finance_asset:dispose`；批准另需 `finance_asset:post` |
| 期间管理员 | 关账和受控重开 | `finance_asset_period:manage` |

路由要求 `finance_asset:view`；既有 `finance_report:view` 只用于报表，不能自动获得资产工作流权限。页面按权限和服务端 `allowedActions` 的交集展示动作；服务端仍需独立校验。
主档和月度批次面板均消费服务端返回的 `allowedActions`，不只按本地权限和状态推导；本人制单
但同时有审批权限时，不显示服务端已经因本人回避而禁止的审批/最终过账动作。

## 二、信息架构

页面由四部分组成：

1. 概览卡：资产原值、账面净值、待摊余额、全局待办/阻断异常（当前不是“只属于我的审批队列”）；
2. 固定资产：搜索、类别/部门/状态筛选、台账、详情和业务动作；
3. 长期待摊：搜索、类别/状态筛选、余额、计划和业务动作；
4. 月结过账：期间状态、预检、折旧/摊销运行、反冲、对账和关账。

概览区必须把两类阻断分开显示：

- 会计政策阻断：来自 `policyReady/missingPolicyItems`，用于提示最低类别和科目准备状态；
- 运行安全门禁：来自 `postedWorkflowsEnabled/operationalBlockers`，用于明确核心落账动作被关闭。

政策配置完整不得让运行安全门禁消失；页面必须明确告知用户“不能通过配置政策解除门禁”。

空数据库不得生成样例假账。当前台账空态在有编辑权限时提供“新建固定资产/长期待摊”；类别与政策
通过页面顶部政策入口配置。独立“查看初始化清单”尚未实现，不得在验收脚本中把它当成现有动作。

如果类别或科目没有配置，页面明确显示阻断原因，允许建草稿但不显示为可提交/可过账。运行安全
门禁关闭时仍允许建草稿、修改、删除、提交以及他人审批/驳回，以便准备数据和做 UAT，但不显示
激活、处置、终止或其批准入口。

## 三、响应式布局

### expanded（> 840）

- 概览卡按 4 列展示；
- 台账使用 `UtenListTwoPane`：筛选在上、`MasterDataTableView` 在下（2026-09-10 起统一上下，不再左右分栏；「新建」操作随筛选区标题行右侧常驻，窄屏不再丢失）；
- 表格首列为编号/名称，金额右对齐，状态使用 `UtenStatusBadge`；
- 详情使用宽 1040px、高度约视窗 90% 的 Dialog；当前没有对象详情 URL 深链。

### medium（600–840）

- 概览卡 2×2；
- 筛选折叠为顶部区域；
- 表格保留关键列并可横向滚动，次要字段进入详情。

### compact（< 600）

- 概览卡纵向或 2 列；
- 台账为分页卡片，不把七列压成省略号；
- 卡片仅显示编号、名称、净值/余额、部门和状态；
- 详情使用高度 96%、新建和编辑使用高度 95% 的可滚动底部抽屉；
- 所有主要点击目标至少 48dp，键盘和大字号下不得溢出。

项目继续使用深绿/青绿主题 token。通用企业蓝、硬编码颜色和自造阴影不进入本页。

## 四、列表与错误态

- 关键字搜索防抖，切换筛选或排序回到第 1 页；
- 固定资产和待摊各自独立请求、独立 loading/error/empty，不使用一个 `Future.wait` 绑死；
- 旧响应晚到时由 `LatestRequestGuard` 丢弃；
- 首次失败显示错误说明和重试按钮，不能永久转圈；
- 金额完全使用后端 decimal 字符串，客户端只格式化展示，不用 `double` 重算月折旧或余额；
- 搜索与筛选是当前页面会话状态；排序、页大小和跨会话偏好保存尚未实现，不得宣称会随账号持久化。

建议列：

| 固定资产 | 长期待摊 |
|---|---|
| 编号/名称、类别、部门、原值、累计折旧、净值、会计状态、运行状态 | 编号/名称、类别、受益期间、总额、累计摊销、余额、会计状态 |

## 五、新建与编辑

使用 `Form + UtenFormGrid + UtenActionButton`。表单内容可滚动，失败时不关闭、不丢输入；关闭脏表单需要确认。

固定资产至少录入：

- 类别、名称、原值、残值率和期限；计提方法来自已启用类别，当前只支持 `STRAIGHT_LINE`，对象表单不单独选择；
- 购置日、验收日、达到预定可使用状态日、启折期间；
- 部门、地点、责任人、序列号；
- 通用来源类型、来源引用、来源行引用和来源单据日期；当前没有独立供应商/发票/验收字段；
- 备注。

待摊至少录入：

- 类别、名称、总额和期限；计划方法来自类别，当前只支持直线法；
- 确认日期、受益开始/结束日期；
- 部门、通用来源类型/引用/行引用和来源单据日期；当前没有独立合同/发票字段；
- 备注。

编号由服务端生成。金额输入保持十进制字符串；期间必须是真实的 `YYYY-MM`；期限为 1..1200；残值率为 0..1。会计状态不可在表单下拉框直接改，只能通过提交、审核、激活、处置或终止动作变化。

## 六、详情

详情按以下区域显示：

- 概要：业务身份、会计状态、运行状态和当前余额；
- 归属与来源：部门、责任人、地点及通用来源类型/引用/行引用/单据日期；
- 账簿/计划：当前显示 CORPORATE；TAX 只可显示明确标记为“尚未启用”的模式预留，不得出现
  虚假的 TAX 新建、计提、反冲、总账或差异报表动作；待摊展示版本和逐期计划；
- 审批：节点、动作、人员、意见和时间；
- 事件：展示实际已经发生的调拨、状态、价值、处置、终止和反冲时间线；不能为尚未发生或门禁阻断的动作生成伪事件；
- 凭证：凭证号及可用的真实深链。若没有总账凭证详情路由，只允许复制凭证号，不伪造跳转；
- 文档引用：通用 Attachment 已有源码候选，但资产 owner policy、逐码证据映射和上传 UI 尚未接入，且生产 OSS/AV/删除一致性/恢复门禁未闭环；本页仍只显示结构化引用和“附件服务未启用”，不提供虚假上传按钮。

## 七、动作与确认

| 状态 | 允许动作 |
|---|---|
| `DRAFT` | 编辑、删除、提交 |
| `PENDING_APPROVAL` | 非本人审核或驳回 |
| `APPROVED` | 具有过账权限者激活；默认门禁关闭时不提供 |
| `ACTIVE` 固定资产 | 调拨、运行状态、查看折旧；处置申请默认门禁关闭 |
| `DISPOSAL_PENDING` | 非发起人批准/驳回；默认门禁关闭时只保留安全驳回 |
| `ACTIVE` 待摊 | 查看计划；提前终止申请默认门禁关闭 |
| `TERMINATION_PENDING` | 非发起人批准/驳回；默认门禁关闭时只保留安全驳回 |
| `COMPLETED` 待摊 | 只读查看；若历史终止申请被驳回且余额已为零，可回到已完成 |
| `DISPOSED/TERMINATED` | 只读、查看凭证和历史 |

`DISPOSAL_PENDING/TERMINATION_PENDING` 的拒绝需要 `finance_asset:dispose`；最终批准同时要求
`finance_asset:dispose` + `finance_asset:post`，并且只有核心落账门禁开启时才会出现在
`allowedActions`。

驳回、处置、提前终止、反冲和重开期间必须输入原因。危险动作使用明确后果确认，不用“确定吗”这种无上下文文案。

### 7.1 安全门禁文案

当 `postedWorkflowsEnabled=false` 时，页面显示不可忽略的“资产核心落账安全门禁已关闭”横幅；
横幅说明至少包括：受阻断动作、业务事件反冲/状态恢复尚未验收、政策配置不能解除门禁。隐藏按钮
不能代替服务端控制；直接调用受保护 API 也必须返回冲突错误。

不得向用户展示“修改环境变量即可启用”的操作指引。启用属于发布变更，前提是缺口完成、自动化
与 UAT 通过、财务和技术负责人共同签字。

## 八、月结过账

月结不能再提供旧“一键计提”按钮。标准操作为：

1. 选择开放期间和折旧/摊销类型；
2. 点击预览，显示笔数、总额、警告、阻断异常和逐项明细；
3. 有阻断异常时禁用提交和过账，并提供到资产/待摊详情的处理入口；
4. 发起人提交；另一名复核人审批；过账人员执行；
5. 显示运行编号、状态、凭证号、子账与总账对账结果；
6. 错误通过“创建反向运行”纠正，原批次仍可查看；
7. 折旧与摊销均已完成且对账为零后，期间管理员可关账；
8. 重开必须填写原因并显示风险说明。

当前页面在失败后提供刷新/重试和批次历史查询，但尚未实现“超时后自动按运行 ID 轮询并消除歧义”。
用户不能因客户端未收到响应而盲目重复过账；自动歧义恢复是后续必须补齐的生产能力。

月度折旧/摊销的正常批次及正常批次反冲已经交付；这里的“反冲”只反向月度计提事实和总账凭证，
不恢复资本化、处置或终止业务状态。门禁关闭的新库不能激活新对象，所以不得把月度工作台可用
写成“新建到处置/终止全生命周期已生产可用”。

## 九、无障碍与文案

- 图标按钮有可读 `Semantics`/tooltip；
- 状态不只依赖颜色；
- 金额使用等宽数字特性、千分位和右对齐；
- 表单标签始终可见，错误显示在字段附近；
- 保存/提交/审批/过账中按钮防连点并反馈进度；
- 预付款文案使用“供应商预付款”，本页使用“长期待摊”，避免误导为付款即启摊；
- 当前不显示税务一次性扣除动作；未来 TAX 账交付后，优惠只显示在 TAX 账簿，并且不得出现
  “500 万以下不用建资产”的错误提示。

## 十、验收

以下勾选项仅代表 2026-08-01 实现冻结时点已经留存的工程证据，不代表当前分支或生产环境已经
放行。文档收口时三份定向测试文件已增至 27 个测试声明；本轮分别等待 120 秒和 300 秒均在测试
运行器输出用例结果前超时，因此没有把旧的 26/26 快照冒充为当前回归通过，仍须在干净环境复跑。

- [x] 自动化覆盖 360、720、1280 三档且无已知 overflow；
- [ ] 414×896、1920×1080 与真实设备完成视觉复核；
- [ ] 首次失败、局部失败、超时、离线和旧响应晚到均有正确恢复；
- [ ] view/edit/approve/post/dispose/period manage 分别验证路由、入口和动作；
- [x] 主档和月度批次均消费服务端 `allowedActions`，本人制单不显示审批/最终过账动作；
- [x] `postedWorkflowsEnabled=false` 时安全横幅可见，受保护动作在 UI 不可见且服务端调用失败；
- [x] 会计政策缺失与运行安全门禁分别展示，补齐政策不会误开放核心落账；
- [x] 金额全程保持 decimal 字符串，列表不自行计算权威余额；
- [ ] 草稿→提交→他人审核→激活→预览→审核→过账→凭证完整走通；
- [ ] 本人自审、阻断异常、关闭期间、重复/并发过账和非法状态均被服务端拒绝；
- [ ] 调拨、闲置都有事件追踪；处置、提前终止在专用业务事件反冲和状态恢复交付前保持门禁关闭；

- [ ] 页面不冒充完整处置清算、退款/贷项、逐码资料证据、来源 adapter、TAX API/GL、历史期初
  或 GL 部门/成本中心能力；
- [ ] 页面没有虚假的附件、导入、税务或总账深链能力。
