# 货品导入问题表格修复与正常行分批导入

本轮承接员工文件导入反馈及用户追加要求：编号为空或修改编号后可上传；问题行单独进入表格，直接修正对应单元格；正常行照常确认导入。前一轮旧 UUID 和缺编号列兼容修复保留，见[前一轮回导兼容性记录](2026-10-26-货品导出文件回导兼容性修复.md)。本记录覆盖当前追加实现，不以旧回执替代当前验证。

## 最终流程

1. 检测原始 Excel，将问题行和正常行分开。文件内重复编号、多行指向同一本地货品时，整组列入问题行，包括首次出现的行；被其他货品占用的编号继续拒绝，正常更新仍按原身份规则匹配。
2. 问题行自动打开“导入问题修复”页面，使用表格显示文件行号、原因和文件单元格。正常部分可以先确认导入，存在非空字段差异时仍走原有替换/忽略核对。待恢复的已删除货品在该页明确显示恢复数量。
3. 问题表格允许修改编号、货品名称、类别、客户货品名称、客户型号、系列、型号、规格、材质、后模镶件编号、备注、英文名称、主颜色、单位、来源、状态、价格、最小起订量、订货倍数。系统 UUID、文件表头和其他非导入字段不可通过修正请求改写。
4. 修改后重新检测，服务端用原有规范化、精度、权限和唯一性规则校验。原 Excel 字节不变；编号留空时，本地 UUID 对应货品保留原号，新货品按分类规则自动编号。
5. 正常部分成功后保存已处理行号，再检测剩余部分；修复后只补导余行。正常但数据相同的行也算已处理，不使文件卡住。每次成功提交独立成批，可独立撤回；不把最后一批撤回描述为整份文件撤回。

取消问题页保留当前文件内的修正草稿，未重新检测的草稿不参与提交。接口拒绝修正时，问题表格仍保持可编辑，旧检测计划禁止提交；取消文件选择也保留当前报告及草稿。网络超时不记为成功，重试冻结的文件、计划、选择、修正和排除集合；只有明确成功回执才推进已处理行。切换文件清空当前文件修正和行号，之前成功部分的结果继续显示。

## 公共实现与差异

| 职责 | 唯一入口 / 调用方 | 处理与保留差异 |
|---|---|---|
| 解析、业务校验、编号和事务 | `GoodsImportService`；所有 raw/JSON detect/commit | 复用同一解析与检测器，正常子集独立计划；错误行不会创建分类或写货品 |
| 问题上下文 | `GoodsImportReport.problemRows[].cells` | 只返回文件输入及其修正，不返回无权查看的系统存储值 |
| 请求与计划 | `GoodsImportController`、detect/commit 请求 records、`DioGoodsImportRepository` | `cellCorrections` 与 `excludedRowNums` 绑定原始文件和检测计划；原始 raw 接口及旧构造保留 |
| 问题表格 | `GoodsImportProblemsPage` → `MasterDataTableView`、`UtenInput`、`UtenReviewInputCell` | 沿用 `frontend-design`、Uten 主题和表格；编辑单元格保持同一输入状态，文本精确比较保留前导零和空格 |
| 原有差异核对 | `ImportReviewPage`，货品/BOM 共用 | 保留原值/导入值核对、替换与忽略的职责，不将普通差异视为可绕过的校验错误 |
| 文件队列 | `ImportFileQueue` / `ImportFileQueueSummary` | 新增部分成功记录；货品按行推进，BOM 等原有整文件业务语义不改变 |
| 共用输入原值展示 | `UtenReviewInputCell`；问题表格、收款表格、报价审核等 | 稳定根布局及输入槽，首字符/恢复原值不重建输入；`decimalValues` 默认保留原财务数值比较，问题表格显式使用文本比较 |

没有新增另一套工作簿解析器或编号算法。检测/提交使用深不可变的字段修正表，旧 `codeCorrections` 作为编号修正简写转换到同一合同；同格冲突拒绝。文件哈希、主档与身份指纹、当前权限、对象范围及事务锁继续保护提交。只读恢复权限预检采用窄范围 `noRollbackFor(ApiException.class)`，防止预期的单行拒绝污染外层检测事务；提交层未捕获的拒绝仍回滚当前批次。
