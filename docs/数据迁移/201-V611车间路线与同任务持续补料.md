# V611 车间路线与同任务持续补料

- 迁移：`V611__workshop_routes_and_continuous_replenishment.sql`。
- 决策：[ADR-093](../99-决策记录-ADR/ADR-093-车间先确认路线与同任务持续补料.md)。
- 依赖：V609 冻结物料消耗及产量容量函数；V610 正常存放仓和内部流转位置边界。

迁移不修改旧版本文件，不清空旧路线、不删除旧领料或报工。非终态旧 `CONTINUOUS` 路线接入统一持续备料模式；原实际数量、来源及状态保留。新根任务的路线确认入口由同批应用代码生效。

持续模式的 READY 备料允许所有供料需求按实际到料部分覆盖，仍保留超预留、超领料、等待段不得持有未晋级的部分库存、完成结清和反向守卫。数据库新增开工路线门及正产出容量门，防止仅客户端限制。领料申请事件允许持续任务在进行中追加，保持追加式历史和确切单据绑定。

系统备料转正 actor 守卫扩到已确认持续模式的活动任务；保留原来源权益、真实预留、计划有效性和系统会话约束。新增持续补料活动段索引，以及按本次实收 `event_group_id` 点查 ORIGIN_IQC/ORIGIN_MAKE 权益的部分索引，避免到料通知扫描全部历史事件。`production_execution:start` 更新为“确认路线、领料与开工”，没有新增授权或扩大到仓库发料。

物料需求状态统一由 `fn_production_material_demand_status` 计算，履约服务和库存领退料服务共用，防止持续完结的“已领加已释放”被另一套旧 CASE 改回未履约。`fn_execution_start_material_ready` 为界面提供开工能力：仅把开工同事务可以合法投入的指名直送料加入实际净持料，普通仓库未发料仍不计入；最终开工守卫保持实际已投入容量要求。

发布前应在恢复副本验证：旧已开工任务不降级；未实领的旧草稿改持续模式不丢预留；纯仓库分批收货和多叶仓领料保留原任务；未到齐任一必要材料不能开工；持续中补料不得把状态改回 READY；直送和仓库需求混合不重复占料；取消、收货红冲、余料退仓和最终结清继续受原守卫控制。

回退不能直接撤销迁移或改 Flyway 历史。若生产出现异常，先停止新路线确认/持续补料操作并保留事实，以前向修复恢复；应用旧版本不理解新持续仓库路线，不能单独回退旧应用。此次未执行任何目标业务数据库迁移或部署。
