# 财务原件打印源设置与完整性回执

本记录覆盖四类财务原对账表的源纸面设置、原生 Excel 对照、Flutter PDF 与服务端 XLSX。代码仍在整合工作树，不表示财务认可、已上线或公司资料已导入。Win7/WPF 本轮按用户要求排除；没有推送、部署或正式打包。

## 原始设置证据

只从原书 ZIP XML 读取打印与样式元数据，没有执行公式、宏或外链，没有修改原文件。`ERP财务部门需求汇总.xlsx` SHA256 为 `47e2a017451b2c25e3a5f75f7848eec7e1589975056baf4b08673b2fd2c44a4d`，与原合同相符。

委外附件位于 `xl/worksheets/sheet2.xml`，明确设置 `paperSize=9` 即 A4、`orientation=portrait`。没有 `scale`、`fitToWidth`、`fitToHeight` 或 `pageSetUpPr`；没有 Print_Area、Print_Titles 或手动行列分页。四表的原边距均为左右0.75英寸、上下1英寸、页眉页脚0.5英寸，分别为54、72及36点。供应商、其他应收及客户三表未显式保存纸张设置，合同继续区分 `EXCEL_DEFAULT` 与明确 A4，当前有效默认 A4 由本地匿名原生转换记录，不将它冒称为三张原书的显式属性。

原委外表头为12点，多数声明 `wrapText=1`。旧渲染器把全表缩入一张 A4 宽度，再对非数字使用 `FittedBox` 且不换行，实际正文约5.106点，个别表头低至2.222点。这些小字号是实现产生的结果，不是原稿的要求。旧固定28点页边距也与原54、72点不同。

微软将打印百分比与 Fit to Page 作为两种设置；Zoom 为 False 才由 FitToPagesWide、FitToPagesTall 控制，不应因为两个页数属性的缺省值为1就启用整页缩放。[PageSetup Zoom](https://learn.microsoft.com/en-us/office/vba/api/excel.pagesetup.zoom)、[FitToPagesWide](https://learn.microsoft.com/en-us/office/vba/api/excel.pagesetup.fittopageswide)、[Page Setup](https://support.microsoft.com/en-us/excel/page-setup)。

## 匿名原生 Excel 对照

只打开匿名工作簿，未打开用户原书。源 ZIP 的 cols、Normal 字体及主题元数据复制到匿名书，原数据没有复制。原生 Excel 16.0 只读导出 PDF 并读取实际物理宽度；没有使用用户安装的 LibreOffice。

首轮 oracle 错把 XML 的存储字符宽赋给 COM.ColumnWidth；两者单位不同，前者含 padding，后者是界面字符宽。该首轮54点等数据和由其推导的页界结论全部撤回。正确流程不调用宽度 setter，直接读取匿名书中原始 cols 的 native Width。例如原 XML 宽9对应 UI宽8.4、物理宽50.625点。Normal 样式用 Styles("Normal") 明确查找，不把集合 Item1 的其他 builtin 样式误称 Normal。

逐列对照还确认旧 canonical 将三处源窄列扩大为6：供应商D原5.2、其他应收C原4.875、客户D原4.5。本轮 V2 改回原值，V1 历史几何保留。正确原生列宽与实际 Java XlsxExportService 生成的四张匿名工作簿逐列比较，全部可见列物理点数相符；XLSX 的 Normal 已明确为宋体11，原字号、100%、54/72点边距和无重复标题均保留。

原生初始设置为 Zoom=100、FitToPagesWide/Tall=1、Order=1，未启用 fit。跨带合并是源全画布定位后按列界裁出视窗，不能在每带重新居中或复印标题，也不能把整表合计当成每带小计。完整普通单格与金融金额另受下述保全文保护。

证据为 tmp/finance-paper-native-oracle 下的 oracle-raw-columns.json、excel-native-oracle-receipt.json、actual-xlsx-native-receipt.json 和 actual-xlsx-geometry-comparison.json。原始 col.width 与 COM UI ColumnWidth 在记录中分开，旧 oracle-layout-summary.json 仅作失败历史，不能用作当前验证。原书字符宽为物理排版事实，不是业务金额取舍。

## 公共实现与保留差异

四表的新纸面合同为 version 2，集中记录源字号、原字符列宽、实测物理点数、边距、100%与未启用 fit、原 wrapText/shrinkToFit、无重复标题以及源文件与几何指纹。Java 原件元数据、服务端 XLSX 和 Flutter/worker PDF 共同读取这些事实。

PDF 按原 A4 竖向和物理列宽分列带，先下后右分页。原书未设置重复标题，因此不自动复印列头、识别列或合并标题。跨带合并标题按原生验证的源画布定位并裁出所属视窗。正文完整单格只放在其所属列带。

原生 Excel 会剪掉固定18点行中的新长金额和部分日期尾部。本会话明确以准确值和完整表格优先：普通正文单格中的数字、日期时间、货品名称及图号都按原字号和原宽换行并增高；不裁尾、不改短格式、不用 FittedBox。原 nowrap 仍留在 sourceStyles 作为来源事实，保全文保护是明确的应用输出规则。只有源明确声明 shrinkToFit 才可缩字。单格高于支持纸面或 Excel 行高时明确拒出，不能发出截断原件。

XLSX 保留原 raw 数值或完整文本、列序、币别格式；保全文只改变换行和必要行高。XLSX 用保守排版估算为原字体留足行高，PDF 用项目既有嵌入字体计算行内换行；因此不同运行时的具体行高与页界可能不同，不声称两者像素相同。财务计算、金额、单位及源归属没有在排版层重算。

保留 version 1 的独立几何资源与解释路径，旧冻结原件按其旧版读取，不在打印时静默换成新版。新旧纸面模板、版本及来源不匹配时拒绝重绘。旧记录若完全缺少纸面版本依据，不用当前 canonical 猜补。生成新结算原件仍沿该原件明示版本及冻结业务事实；不改基础原件 SHA，不写总账、现金、库存或应收应付。
