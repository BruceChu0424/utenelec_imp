# V618 车间余料实际收仓

迁移 `V618__production_material_return_receiving_warehouse.sql`；后续 V619 提供物料专属归属与价值两侧承接。两者必须作为同一候选运行完整迁移和真实链路验证，V618 的直送料函数在运行时依赖 V619。

## 业务边界

当前车间把不用的材料送到正常仓库。原领料、直送凭证和技术流转位置用于追溯材料来自哪里，不表示实物应退回上游生产处，也不是正常存放仓。

车间提交来源与数量，不选择仓库。普通仓领来的余料可默认原正常仓；直送料生成的 WDRAW 草稿实际仓为空，由仓库确认有效、参与记账的普通运营叶仓。当前仅允许原履约主仓内选择，跨主仓需要正式调配流程。技术位置、汇总主仓、停用或失效仓不能接收。

## 两种真实来源

- `ISSUE`：已实际领入当前任务的未耗用物料，保留原 `issuePostingId`。原发料已经扣过库存，退库只增加实际正常收仓，不再另造一次技术位出库。
- `DIRECT_LOT`：已实际直送到当前车间但尚未 ISSUE 的余料，保留 `directTransferItemId`。不要求先选择路线、假领料或假开工。待退数量冻结本任务尚未发出的专属片与未分配直送料，不能借兄弟批次的预留。实际收仓记录技术位置减少、正常仓增加的两腿事实。

请求每行恰好一种来源。已领物料提交 `issuePostingId + qty`；未领直送料提交 `directTransferItemId + qty`，两种身份不能混用。来源部门沿真实交接事实保存；同源仓不同真实部门自动分组。历史未知部门不猜填。

ISSUE 和 DIRECT_LOT 均使用冻结需求的基本单位，来源列表与提交数量保持同一基本量口径，新 WDRAW 的换算率恒为 1。来源包装不能限制零散余料，例如 12 件中耗用 7 件后直接退 5 件，不换算成 0.4167 箱。原 DRAW/FINISHED_IN 的单位、数量及来源 UUID 不重写。

未选择路线的正常仓专属物料由 `WORKSHOP_CUSTODY` 归属承接，仍属于原任务，不变公共库存。只有首次路线确认或明确核料/继续领料才承接为需求预留；普通到货回调与后台补偿不自动形成返回余料的新领用意图。原 MAKE 供给尚未兑现时，仅按精确原收货余量消费原 peg，再把原 receipt 份额关联到实际正常仓的预留，不重复兑现 receipt/ORIGIN。已有正式预留的返回材料仅恢复其余额，明确核料再准备领用。

## 仓库确认与重放

`POST /api/stock/docs/{id}/material-return/confirm` 接收 `{warehouseId,idempotencyKey}`，要求 `stock_doc:approve` 与既有仓库组织任务范围；车间成员身份不能替代仓库权限。已明确正常原仓的通用审核也使用同一真实收仓确认协议。仓库数量不符时沿撤回重提处理，本次不增加部分接收协议。

通用仓库 CRUD 不能新建或编辑 WDRAW，也不能通过把其他单据改成 WDRAW 绕过。没有正式材料申请的旧草稿禁止继续写入或审核，按历史只读核对并从车间任务重新提交；所有新的 GOOD_RETURN 必须有精确申请行及实际收仓确认。已经发生的凭据与物理流水保持原样。

新增 `production_material_return_receiving_confirmations` 保存真实请求/WDRAW、原来源仓、实际收仓、旧抬头仓、操作者和命令哈希。相同键相同请求只重放，换仓或换单使用同键拒绝。确认记录不可 UPDATE 或 DELETE，并且必须与真实收仓在同一事务完成。只有当前事务的精确证明能授权修改草稿的 `warehouse_id`；通用编辑仍不能改生产链凭据。

确认前一次合并来源单据履约足迹与实际收仓库存变化足迹，再按既有商业来源、库存维度、主仓/分析、计划、执行段、仓库单据顺序锁定并校验。不会先改目的仓、再补拿上游锁。

## 未发领料指令

技术位置的物料实际移入正常仓后，旧技术 DRAW 的未发指令不能残留。追加 `MATERIAL_RETURN_DRAW_REDUCE/RESTORE` 执行事件，关联精确 receiving confirmation；数量保留原 DRAW 单据单位，不改原 gross qty、issued qty 或已发生历史。

`fn_production_draw_item_effective_qty` 是当前有效指令数量。领料申请上限、仓库待发、开工准备和当前需求承诺读取同一数量。事件按原任务、需求、来源/实际仓、冻结来源片核验。反向只恢复其原事件；正常仓已有新但未实发的指令在同一反向中精确撤减，已实际再领的物料不能靠红冲收仓抹掉后续事实。

必须撤减的基本量为冻结待转片与该物料池实际未发指令的较小值。换算必须精确；先寻找能独立表达本次数量的行，再按有界的不同单位顺序分配，避免大单无限组合搜索。当前单位组合不能自动精确处理时整笔回滚并提示核对数量/换算，不能舍去零头留下无实物的待发指令；没有 DRAW 的未分配直送料不制造虚假指令。

同一技术 DRAW 支持多次真实投入。自动出库幂等键结合当前追加式出库事件序列和本次数量，避免部分投入、退库反向后再次投入被旧固定键误判为重放。

待退冻结只排除本次冻结片。持续生产可真实投入其他未冻结数量，齐套生产仍须满足整套。取消未收申请后，明确核料可在原技术 DRAW 继续投入。技术指令不进入普通仓库待发，普通仓库 `issue` 不得代替车间 START/核料专用通道。

全部实物已送正常仓、旧 DRAW 无有效未发指令且没有共享物料依赖时，任务可以合法改派。新正常仓 DRAW 使用新接收部门，旧直送/领料历史保留原部门。改派后若撤回旧收仓，必须先改回原实物车间，不能把原车间在制恢复成新车间材料。

## 页面与兼容

StockDocDetail 的 `productionMaterialReturn` 来自精确请求关联，`materialReturnSourceWarehouseId`/`materialReturnMainWarehouseId` 为只读来源范围；`warehouseId` 始终是实际接收仓，未知时为 null。退库 Document 另外返回 `sourceWarehouseId/sourceWarehouseName/sourceDepartmentId`。来源行只以 `sourceWarehouseId/sourceWarehouseName` 表示原位置，不再重复输出含混的warehouse别名；`sourceType`必须明确，DIRECT_LOT 的 `issuePostingId` 为空，数量使用冻结需求基本单位。

未领直送料也构成 `hasMaterialActivity`，可以从 WAITING 任务进入余料退库；不能因此把 `hasUnregisteredMaterial` 虚标为待登记实耗。退料能力由服务端真实来源和写权限决定，历史可读不授予写权。

不重写旧审核单据、来源 UUID 或历史库位。旧同仓记录及真实反向按原事实处理；新的直送料收仓必须确认正常目的仓。新表已经接入审计和受控业务数据清理。

开工统一使用 canonical START，删除 `start-continuous` 入口及 `canStartContinuous` 重复能力，不保留旧接口的第二套运行流程。
