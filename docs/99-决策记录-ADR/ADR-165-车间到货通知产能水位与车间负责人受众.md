# ADR-165 车间到货通知产能水位与车间负责人受众

- 状态：已接受（2026-10-06，V814；修订 ADR-091 §2.3/§八 的到货进展闸门与受众条款）
- 关联：ADR-091（开工路线确认与到货进展通知）、ADR-095（车间路线随时可换）、
  ADR-096（三条路线通用）。

## 一、背景（用户口径）

「物料到货进展」行动卡（`PRODUCTION_WORKSHOP_TASK_ACTION_REQUIRED`，进中央弹窗）此前的
闸门（ADR-091 §八，2026-10-06 上午）是布尔值：分批/持续路线只要
`start_material_ready` 或 `prepared_capacity>0` 就发卡。布尔一旦为真，之后**每一次到货
事件**（每种料到齐各触发一次 IQC 入库/成品入库/直送）都会「撤旧卡 + 发新卡」再弹一次窗，
即使可生产件数根本没涨——「一种物料齐了就弹一次，太烦人了」。

用户给的正确口径：

1. **每种物料都有一部分了**（可支撑产量 > 0）才首次弹「可以生产 X 件」；
2. 之后又来物料但**不能支持生产更多**（可生产件数没涨）→ 不弹；
3. 又来物料**能支持生产更多**（例如扣掉之前已领料支持的 20 件后还能生产 100 件）→ 再弹；
4. 弹窗只给「**有权限 且 是该车间负责人**」的人——计划部有权限但不是车间负责人，不弹。

## 二、决策一：到货进展卡按「可支撑产能水位」弹（替换 §八 的布尔闸门）

`ChainNoticeService.publishWorkshopMaterialArrival` 的闸门
（`arrivalProgressWarrantsNotice`）改为**产能水位差**：

- **可支撑产能按路线取口径**（`workshopArrivalCapacity`）：
  - **BATCH**＝分批领料核对页的「当前可齐套生产量」，与页面**同一个数**——
    `ProductionExecutionBatchService.currentSplitCapacity`（由 `maximumReadyQty` 抽出，
    冻结耗用曲线二分 × 仓库可用量（专属权益 + 公共预算扣安全库存），剩余段自动扣前批）；
    不可计量（路线已改、前批固定料未领齐、尺子缺位等）返回 null，不发卡、水位不动。
  - **CONTINUOUS**＝已备预留产能 `fn_execution_material_output_capacity(segment, FALSE)`
    ——已领走的料不占这口径，「还能生产多少」只算没领的；领料后产能回落，水位跟着回落。
  - **FULL_KIT**＝齐套全有或全无：只在 WAITING 且仓库口径盖住全部缺口时为 `planned_qty`，
    否则 0（READY 及之后由齐套/可开工行动卡接管）。
- **水位表** `production_execution_segment_notice_state`（V814，1:1 侧表，无行＝从未评估按 0；
  不挂行级审计、清空业务数据时清空，与 V798/V809 通知水位表同款）。故意不放段表加列：
  段表的 BEFORE UPDATE 触发器会 bump `lock_version`/`updated_at` 并重验车间负责人，
  每次水位变化会把在途的领料核对 CAS（「车间任务已变化，请刷新」）顶失效。
  每次到货事件评估后同步成当前值（`syncArrivalCapacityWatermark`，UPSERT + 值不变不写）：
  上涨发卡时抬上去，回落时落下来——「涨了」永远相对最近一次，领料回落不会被旧水位压住
  （回落后再涨到新高就再通知）。持续生产的实际领料在出库事务内、写入 outbox 前
  同步降低水位（只降不升），与出库一起回滚；因此已通知 100、领完 100 后新到 50
  会再次提醒，不需要先等一次到货事件“发现回落”，也不依赖 outbox 投递先后。
  仅按物料账本本事务的 `ISSUE` 流水确定实发段（`recorded_tx_id`），同张领料单尚未实发的
  其他执行段不加锁、不改水位，避免扩大并发锁范围。
- **发卡条件**＝`当前产能 > 水位`；分批/持续路线文案带「（现有物料可支撑生产 X 单位）」，
  齐套卡维持「物料已齐套，可提交领料」原文案。暂缓中的分批段指引先解除暂缓
  （拆批会被页面拒绝，不邀请会被拦下的动作）。
- 保持不变：路线未确认不发；会自动提升的段（WAITING ∧ `auto_promote_when_ready` ∧
  路线放行）先返回且**不评估不抬水位**——齐套/可开工行动卡由 `publishWorkshopTask` 体系
  负责，且 ARRIVAL_PROGRESS 办结会把刚投递的 important 卡撤掉；不抬水位是为了万一
  提升没成、任务随后被暂缓，全齐卡仍能弹出来。到货撤销（`validArrival=false` 的
  「物料状态更新」）不受闸门约束仍即时通知（并同步水位）。
- §八 的「部分到货撑不起部分生产→静默」语义由「产能 0 不涨不弹」自然涵盖；
  「IN_PROGRESS 不发」条款废止——分批/持续路线生产中产能回涨（补料解锁更多产量）
  现在会按水位差正常通知。

## 三、决策二：车间任务行动卡只发车间负责人（受众收窄，波及全部车间任务卡）

`ChainNoticeService.workshopRecipientUserIds` 收窄：

- **收件人＝（车间（含下级班组）各部门负责人 `departments.manager_id` ∪ 任务负责人
  `responsible_employee_id`）∩ 当前有效权限**（`notice:read` + `production_execution:view`
  + `production_execution:start`/报工，`ReviewNoticeAudience.canHandleWorkshop`，含个人回收）。
- 计划部等职能岗即使**个人加授**了车间任务权限，不是车间负责人也**不收卡**（此前可经
  个人加授/兼职混进收件人，是用户点名的口子）。
- **没有合格负责人时不发卡**：没有登记负责人、负责人停用或动作权限被收回，均不扩展
  为普通成员池；车间普通成员和兼职成员不会仅凭任务办理权限收到弹窗。
- 波及面：`publishWorkshopTask`（备料中/齐套待领料/领齐可开工/持续生产进展）与
  `publishWorkshopMaterialArrival`（到货进展）共用该收件人，全部收窄；车间成员仍可在
  「我的车间任务」页按原业务范围看到任务。通知读取侧 `ReviewNoticeAudience.workshopScope`
  同步按当前负责人身份过滤，覆盖列表、计数、登录弹窗、在线到达与状态心跳；旧卡接收人
  若已不是负责人，立即失去该卡的可见性，历史记录保留。

## 四、验证

- `WorkshopArrivalNoticeRegressionTest`：产能涨才弹 / 不涨不弹 / 回落后再涨再弹 /
  齐套全齐只弹一次（多余到货静默）/ 尺子不可计量静默且水位不动 / 撤销仍即时重建并同步水位 /
  开工就绪信号不再触发到货卡。
- `ProductionWorkshopMaterialNoticeContractTest.arrivalProgressCardGatesOnProducibleCapacityWatermark`：
  源码契约（布尔闸门 `partialStartCapable` 退役、水位比较与同步存在）。
- `ChainNoticeProductionWorkshopScopeTest` / `WorkshopNoticeScopePostgresTest`：
  只收负责人、无负责人/权限撤回不广播、普通/兼职成员旧卡隐藏、负责人调离即时隐藏。
- `WorkshopArrivalWatermarkPostgresTest`：实际 PostgreSQL 验证出库降低基线、下一批 50 不被
  旧 100 压住、仅命中关联持续生产段、重试不抬高水位、事务回滚不遗留通知状态。

## 五、事务边界与迁移

- `currentSplitCapacity` 的「不可计量」（路线已改、前批固定料未领齐等）是拆批流程的
  正常中间态，**在 @Transactional 边界内吞掉返回 null**——异常一旦越过代理出口，调用方
  共享的 outbox 投递事务会被标记 rollback-only，到货事件重试 8 次后死信、通知静默丢失
  （红队复审发现的 P1）。真故障（非 ApiException）不吞，走投递重试。
- V814 `workshop_arrival_notice_capacity_watermark`：建 1:1 水位表
  `production_execution_segment_notice_state(segment_id PK, arrival_notice_capacity, updated_at)`
  （审计 NONE、清空业务数据 CLEAR，锚点插入 `business_data_reset()` + 自检，V798/V809 同款）。


## 六、同族弹窗盘点（2026-10-06 用户追问「委外之类的也要只支持部分才弹」）

对委外/采购域全部「供给就绪」语义的行动卡做了同口径盘点，结论：**均已符合，无需改动**。

- 「委外可领料」卡（V798/ADR-143）：可领量 = `fn_subcontract_draw_summary` 的
  `LEAST(剩余, MIN(各直属物料够做套数))`——短板套数口径，凑不齐一套 drawable=0 只撤卡；
  水位 `subcontract_draw_notice_marks` 只在可领量**上涨**时发卡（回落降水位+epoch 不打扰），
  2026-10-06 起水位记卡片实际写的数（83b10bbd5）。
- 「委外可下单」卡（V809/ADR-156）：可下单 = `LEAST(剩余未下单, MIN(直属物料够做套数))`，
  同为短板套数；水位 `subcontract_application_kit_notice_marks` 只涨才弹、归零撤卡。
- 其余委外/采购弹窗（领料待发料/预计回厂/短交判定/回厂交期/预计到货/到货异常/IQC 族、
  新需求下达）均为单据、审批、质检或交期类：一次一卡（单据/案件级聚合），
  不存在「部分到货就弹」或「每次到货重复弹」的路径。采购到货对车间侧的感知走本 ADR 的
  到货进展卡（同一水位闸门管住）。
- 测试锚点：`SubcontractStepDrawEndToEndTest`（B 短板只到一半按 40 套弹）、
  `SubcontractChainNoticeTest.partialIssueWithoutACompleteSetDoesNotAnnounceExpectedReturn`
  （凑不齐一套不发）、`NoticeMarkFollowsShownCardTest`（水位记卡上的数）。
