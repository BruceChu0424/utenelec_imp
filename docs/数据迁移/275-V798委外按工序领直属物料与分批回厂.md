## 结构变化

**新列与新表**

- `subcontract_material_plan_items` 加 `draw_closed_at`、`draw_closed_by`(外键 users)、`draw_close_reason`: 「结束领料(不再发外)」。CHECK: 三列同空, 或时间与 1 到 200 字的原因同在。行开放 = 计划 OPEN 且未删且 `draw_closed_at` 为空。
- `subcontract_material_issue_items.requested_qty NUMERIC(18,4)`: 委外人员提交领料时的本行数量。CHECK `requested_qty IS NULL OR (requested_qty > 0 AND qty <= requested_qty)`; 守卫 `trg_guard_subcontract_draw_issue_item`(INSERT)与 `trg_guard_subcontract_draw_issue_item_upd`(列级 WHEN, 均 ENABLE ALWAYS): 绑定计划行的发料行必须带 `requested_qty`(只有领料提交能建), 物料、颜色、单位、换算率、订货明细与冻结计划行一致, 新建时计划行必须开放; `requested_qty` 与所属计划行写入后不可改。
- `subcontract_material_issue_items.warehouse_dropped_at TIMESTAMPTZ`: 仓库拣货时把一种物料整行删掉(本次不发)的时间。只在仓库保存拣货删行时写入, 该行同时软删, `qty` 与 `requested_qty` 原样保留; 委外人员撤回领料、结束领料的强制撤回与仓库「退回委外(不发)」整张作废的软删都不写。CHECK `warehouse_dropped_at IS NULL OR is_deleted`。软删行不进任何库存、预留、计划行与守卫口径(这些都只看未删行, `fn_subcontract_draw_facts` 的待仓库发也只算未删的草稿行); 发料回执的「少发」= 未删行与仓库删行的 `requested_qty` 之和 - 未删行实发 `qty`。

- 新表 `subcontract_draw_notice_marks(order_item_id PK → subcontract_order_items ON DELETE CASCADE, notified_drawable, epoch, updated_at)`: 「可领」通知高水位, 只由投递后的重算写入。清空策略 CLEAR; 审计 NONE(通知组, 系统协调状态)。

## 数量口径与读函数(唯一一处计算)

| 函数 | 作用 |
| --- | --- |
| `fn_subcontract_draw_f(sets, b)` IMMUTABLE | `CEIL(S x b, 4)`, 套数换物料量; 计划量 = f(订货量) |
| `fn_subcontract_draw_sets(qty, b)` IMMUTABLE | `TRUNC(x / b, 4)`, 物料量换套数; 用整数除法精确截断, 与 Java `divide(b, 4, DOWN)` 一致 |
| `fn_subcontract_draw_edges(goods)` | 可发外直属边唯一判据: PER_UNIT、START/ASSEMBLY/FINISH、用量 > 0、物料未删非系统占位、非整批领料; 颜色 = COALESCE(边颜色, 物料默认颜色) |
| `fn_subcontract_component_entitled_lots(order_item)` | 订货明细按冻结计划行可接管的精确专属批次(签名由 `(application_item, order_item)` 改为只收订货明细); 顶层委外件取来源行 depth=1 节点; 认领区间按该物料节点全部在途订货明细切分, 只认 SUPPLY 行动 |
| `fn_subcontract_draw_line_stock(plan_item)` | 计划行在各作业叶仓的 exact_qty(专属批次) + public_qty(`v_stock_available`) |
| `fn_subcontract_supplier_own_qty(order_item)` | 财务批准的委外商自带料 E(订货单位): 已定案接收(`RECEIPT_ADJUSTED` / `RECEIPT_POSTED` / `CLOSED`, `APPROVE_ALL` / `APPROVE_CUSTOM`)的到货异常 `approved_excess_qty` 之和; 收货单红冲后异常转 `RETURN_REQUIRED` / `CANCELED` 不再计入。回厂守恒的净额上限用同一个函数 |
| `fn_subcontract_material_qty(order_item)` | 我方供料套数 Qm(ADR-143 §三.4a) = `LEAST(Q, GREATEST(Q - E, MIN sets(已发外净量), 0))`; E = 0 时 Qm = Q; 已经发出去的完整套数不会因为后批准的自带料被「收回」; 订货明细不存在时为空 |
| `fn_subcontract_draw_needed_qty(order_item, planned, b)` | 计划行我方需发量 `LEAST(planned, f(Qm, b))`; 没有自带料时 = 计划量。「料已发完」「领满」「还缺」与领料任务是否还开着都按它 |
| `fn_subcontract_draw_facts(order_item)` | 每条计划行: 计划、已发外净量、已提交未发、可动用、委外商处可做成 P 的量、行是否开放、我方需发量 needed_qty(最后一列) |
| `fn_subcontract_draw_summary(order_item)` | 已领 / 待仓库发 / 可领 / 还缺 / 已覆盖 / 可达套数与 all_covered / all_sent / any_open, 最后一列 material_qty = Qm; 已领 + 待仓库发 + 可领 + 还缺 = Qm(没有自带料时 = 订货量), 所有套数取 `LEAST(Qm, …)`, ready / all_covered / all_sent 按 needed_qty。没有计划行(缺 BOM 的委外件不能批准, 不应出现)时 order_qty 仍为订货量, 其余各数为 0, all_* 为假(不放行) |
| `fn_subcontract_returnable_qty(order_item)` | 可回厂套数 `LEAST(Q, MIN sets(usable))`; 没有计划行(或订货明细不存在)返回 0, 不放行回厂 |
| `fn_subcontract_receipt_basis(order_item)` | R(有效回厂行 material_basis_qty 之和)与已红冲回厂行数 |
| `fn_subcontract_receipt_material_complete(receipt_item)` | 回厂行物料成本是否完整(计价 FINAL), 成本守卫与 Java 共用; 没有计划行一律不完整 |

**我方供料套数 Qm(2026-10-05 补, ADR-143 §三.4a)**: 财务批准的委外商自带料那部分不用我方物料。例: 订 100、已发 60 套、回厂 80 其中 20 是批准的自带料 → Qm = 80, 只能再领 20 套; 再发 20 套后「料已发完」。Java 读侧(领料任务列表 / 详情 / 批量领料联合分配 `SubcontractDrawAllocator` 按 Qm 封顶、订货进度物料表、短交「料已发完」、到货追踪容差判定、可领通知、任务中心「可领」)都只读上面三个函数, 不另算。冻结计划量 `planned_qty`、硬上限 `issued_qty <= planned_qty`、批准后改量按 f(新订货量) 重算、退料红冲上限都不变(Qm 只收窄可领与「发完」判定)。接口: 领料任务行新增 `materialQty`(= Qm, 恒等式按它; `orderQty` 仍是订货量), 物料行 `requiredQty` 改为我方需发量。

**本特性自有守卫整体重写(触发器不重建, 保留 ALWAYS 与延迟属性)**: 计划行插入守卫(必须对应 `fn_subcontract_draw_edges` 的一条边, 单耗、计划量 = f(Q)、未发、未结束); 发料分配守卫(去掉流向白名单); 委外出仓预留守卫(去掉前置自制成品来源判定); 接管精确批次(按计划行物料与冻结颜色过滤, 计划行必须开放); 交接血缘守卫(认冻结计划行、顶层 depth=1、只认 SUPPLY 行动); 回厂守恒(逐计划行: 核销量 <= 委外商处可用, 且 |核销量 - f(R)| <= 已红冲回厂行数 x 0.0001; 冻结口径相对回厂量的净额不能超过质检补回与财务批准自带料(`fn_subcontract_supplier_own_qty`); 已审核回厂行必须有 material_basis_qty, 老系统导入的回厂行除外(它们的口径为空, 本来就不进净额、R 与无计划行检查, 所以只在「缺口径」计数里豁免; 否则老系统委外导入在提交时整批回滚, 之后对导入回厂单做委外退货也会被拒); 没有计划行(缺 BOM 的委外件不能批准, 不应出现)时可回厂按 0, 物料口径回厂量 R 必须为 0, 否则拒绝); 核销切片守卫(只切同一订货明细冻结计划物料、口径 `FROZEN_BOM_ESTIMATE`); 成本完整性改用 `fn_subcontract_receipt_material_complete`。精确归属的分摊权重 `fn_subcontract_component_parent_capacity` 只认 SUPPLY 行动。

接口层(2026-10-05): 正常路径由 Java 先给逐行原因(「请先在委外任务中心领料」「仓库只能少发不能多发」、超出可回厂套数转到货异常等), 上述守卫只在并发或旁路写入时撞上; 这时 `GlobalExceptionHandler.subcontractDrawGuardMessage` 按约束名(`subcontract_target_outbound_first_guard` / `_consumption_guard`、`subcontract_receipt_material_basis_guard`、`subcontract_draw_issue_requested_guard` / `_identity_guard`、`subcontract_draw_plan_basis_guard`、`subcontract_material_issue_item_requested_qty_chk`、`subcontract_material_plan_items_check` / `_issued_qty_check`)与出仓占用闸的固定英文句首翻成大白话 409, 不再落成通用「数据已被其他操作更新」, 也不回显 SQL/DETAIL。
