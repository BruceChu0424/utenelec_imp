## 一、问题

V436 把「有子层级目标件先内部自制」落实为：物料分析一下达 SUBCONTRACT 路线就生成委外申请
（委外部立即开始分解订货、财务审批），前置自制却要等订货财务批准后才启动，且整批实收完成
前不允许出仓。业务上这顺序反了：

1. 委外部在生产还没开始时就被卷入，拿着一张长时间无法执行的订货单；
2. 公司无法按生产节奏分批把已完工的目标件送去加工；
3. 「前置自制」与「通知委外」两个独立里程碑被捆死在一张订货单上。

## 二、决策

### 2.1 有子层级委外件：下达即前置自制，完成才通知委外

物料分析准备对 SUBCONTRACT 路线下达时按目标件当前活动 BOM 分流（服务端判定，前端不参与）：

- **无子层级**：维持 V436 语义，立即生成只读委外申请并通知委外部（与采购一致）。
- **有子层级（新）**：不生成委外申请、不通知委外部。在**原分析内**创建
  `SUBCONTRACT_MAKE` 前置自制任务行（子树需求委托给该行，与 `MAKE_COMPONENT`
  同构：齐套检查、计划向导、DRAW 领料、报工、FQC、成品实收入仓），并建立
  `preplan_subcontract_make_tasks` 账本（required/produced/notified 守恒）。

不新建独立 SUBCONTRACT_PREPARATION 分析、不触发 V447 跨分析交接：子树本就在原分析中，
委托机制天然避免重复展开与重复备料。

### 2.2 自制成品入库：专属预留 + 满批自动通知 + 分批通知

FINISHED_IN 审核事务把产出量写入账本 `produced_qty`，并以
`SUBCONTRACT_PREPARE_TASK` 专属预留扣住公共可用库存（不提前满足原生产需求）：

- **满批**（produced ≥ required）：事务内自动按剩余可通知量生成委外申请并通知委外部；
- **未满批**：计划部可在物料分析准备页/委外准备中心按「已产未通知量」手动分批通知
  （`POST /api/production/material-analyses/subcontract-make-tasks/{taskId}/notify`），
  每批一条 `preplan_subcontract_make_task_batches` + 委外申请 + 通知。

可通知量 = LEAST(required, produced) − notified；账本触发器强制 notified = Σ批次。

### 2.3 订货批准：PREPARED_OUTBOUND 即时待出仓

来源为账本批次的订货行在财务批准时以 `flow_mode='PREPARED_OUTBOUND'` 落
`subcontract_material_plan_items`（prepared = planned、READY_OUTBOUND、冻结仓=账本仓），
任务持有的预留切片被**释放并等量重建**为该行专属 `SUBCONTRACT_OUTBOUND /
PRODUCTION_FINISHED_IN` 预留（同 supply 溯源，满足 V436 FINISHED_IN 血缘断言），
随后生成出仓草稿并通知仓库。订货红冲时对称转回任务持有。

### 2.4 直下单分批出仓（放宽整批门禁）

委外部直接新建订货单的有子层级行继续走 V436 的 MAKE_THEN_OUTBOUND（批准后启动独立
前置自制分析），但整批门禁放宽为**分批**：任一批次实收即转 READY_OUTBOUND
（可出仓量 = LEAST(planned, prepared) − issued），首片与整批完成两个节点通知仓库，
中间追加量由任务投影与续生草稿体现。数据库形状约束不变（V436 本就允许
MAKE_THEN_OUTBOUND 行 prepared < planned 处于 READY_OUTBOUND）。

## 三、不变量（继承并扩展 ADR-059）

1. 委外申请生成前委外部不参与：无申请、无订货、无财务事务。
2. 前置自制产出不能提前满足原分析需求：任务持有/行持有的专属预留始终从
   `v_stock_available` 扣除；原分析节点只认委外回厂 IQC PASS 后仓库确认的实际入库。
3. 每一通知量、每一出仓量都有精确预留与批次守恒（批次守卫触发器 + 既有分配账）。
4. 已产未通知量被通知（申请生成）后，红冲成品入库失败关闭；订货红冲先把未消费
   预留转回任务持有，再走既有反向链。
5. 取消/撤回：账本行有 produced 或 notified 即失败关闭；纯任务按自制备料同构口径回退。
6. 通知只提醒；账本、预留、单据、allowedActions 是权威。

## 四、兼容与迁移

- V458 只向前新增：新来源类型、两张账本表、新 flow_mode、预留 owner 分支与
  断言函数扩展（`fn_assert_subcontract_preparation_source` 增 PREPARED_OUTBOUND 分支、
  出仓分配/FINISHED_IN 血缘断言接受新流向）。历史字节与 LEGACY_BOM_COMPONENT 不动。
- 在途 V436 单（已生成申请/已订货）继续按原链执行，仅享受 2.4 的分批出仓放宽。
- audit 覆盖与 reset 白名单（CLEAR）已登记；reset 目录门扩至 V458/420。

## 五、验收要点

下达分流（有/无子层）、原分析内委托不重复备料、FINISHED_IN 预留+账本、满批自动通知、
手动分批上限、PREPARED_OUTBOUND 批准即时出仓与预留转换、直下单分批出/进/PASS、
红冲守卫（成品入库/订货/出仓三层）、越权与对象范围、并发 CAS、通知收件人。

## 六、修订二（2026-09-04）：委外委托的 exact 权益迁移缺口

**事故**：有子层级委外件「下达委外」后，委外前置自制（SUBCONTRACT_MAKE）子树库存
明明齐套，可生产区却恒显「还缺 X 种物料」，无法填写数量生成计划单。

**根因**：`notify` 通知链中，exact 到货/备料权益向子任务行的迁移
（`delegateMakeEntitlements`，MAKE_DELEGATE_OUT/IN 事件对）只在 `route == MAKE`
执行，SUBCONTRACT 被跳过。此前 MAKE 任务创建时产生的 ORIGIN_MAKE 预留权益
钉在原父树子件节点上；委托后这些节点有效需求归零，但 `planExactPegs` 按节点的
**毛需求快照**（loadBomTree gross first pass）把权益 secured 到旧节点并从共享池
earmark 扣除——旧节点有效需求为 0 永不消耗 secured，新子树面对被扣光的池子，
形成自锁（库存物理存在、v_stock_available 全被自身预留扣成 0）。

**修复**：`PreplanStockEntitlementService.delegateMakeEntitlements` 的配对查询
泛化为 `(route, 子行来源类型, 单据类型) IN ((MAKE, MAKE_COMPONENT,
PREPLAN_MAKE_TASK), (SUBCONTRACT, SUBCONTRACT_MAKE, SUBCONTRACT_MAKE_TASK))`，
父节点 `confirmed_route = action.route`；`notify` 循环对 MAKE 与 SUBCONTRACT
统一执行迁移并触发第二次 refresh。无子层委外（SUBCONTRACT_APPLICATION）无子
任务行，查询自然无匹配。撤回路径本就复用 `restoreMakeDelegationsForAction`，无需改。

**存量数据修复**：升级后对卡死分析，在物料分析页撤回该「委外自制」任务
（此时权益未被消费，撤回成功、需求回到原节点、齐套恢复），再重新「下达委外」
即可走通两段式。契约锁定见 `ProductionMaterialAnalysisWorkflowContractTest
.subcontractMakeNotificationAlsoDelegatesExactEntitlements`。

## 七、修订三（2026-09-04）：委托头触发器放开双路线（V467）

**事故**：修订二合入后，有子层级委外件下层齐套、点「下达委外」界面毫无反应——
后端三次 23514「invalid preplan MAKE entitlement delegation」，整个事务回滚。

**根因**：修订二只改了 Java 侧（迁移查询与 notify 循环），V337 的数据库头触发器
`fn_check_preplan_make_entitlement_delegation` 仍写死 MAKE 四项形状
（route / external_document_type / parent.confirmed_route / child.source_type），
SUBCONTRACT 委托 INSERT 即拒。合入时契约测试是源码文本断言、不跑真库；E2E 种子
无 ORIGIN 权益、`delegateMakeEntitlements` 返回 0，触发器从未被踩到——
「代码改了、守卫没跟」。

**修复（V467）**：头触发器配对放开为 `route → (document_type, child_source_type)`
双路线（MAKE 与 SUBCONTRACT 各自配对），`parent_material.confirmed_route = action.route`
与 Java 查询同口径；未知路线 CASE 映射 NULL 经 `IS DISTINCT FROM` 保持失败关闭。
事件侧触发器与总量校验器形状无关不动。行为锁定在真库测试
`SubcontractMakeDelegationRouteGuardPostgresTest`（SUBCONTRACT 插入+权益搬移、
MAKE 回归、形状不匹配仍拒）。三次失败点击均已整体回滚、无存量脏数据，
升级后直接重点即可。见[迁移说明 86](../数据迁移/86-V467委外权益委托触发器放开双路线.md)。

## 八、修订四（2026-09-05）：委外=自制同构直下——委外部从下达起参与跟踪 + 委托子树路线继承

**用户口径**：①「下达委外后就是给车间多个任务而已，委外完全走自制路线，不要给委外多写代码」；
②「下达委外后子层级全部自动重置、要重新设置路线，这是不对的」；③「同时通知委外部有新委外单，
表格形式、有进度（正在通知车间生产 / 车间正在等物料）」；④完成后通知委外取货。

**决策**：

1. **下达链路不动**（真正复用自制路线）：有子层委外件「下达委外」仍走 V458 的
   `SUBCONTRACT_MAKE` 委托行 + `preplan_subcontract_make_tasks` 账本 + exact 权益委托（V467），
   车间任务/计划/执行段全部复用自制链；成品入库 → 预留 + 满批自动/手动分批生成委外申请 →
   通知取货的闭环不变。**不给委外另写第二条下达代码路径**。
2. **委托子树路线继承**（修「重置」）：`refreshLocked` 在节点 upsert 后按
   「货品+颜色+单位+路径尾段」把原子树已确认的路线一次性回填到委托行（自制备料/委外自制）
   展开的新子树——只补空、不覆盖既有确认；BOM 真实变化时四元组对不上即不继承（不复活过期路线）；
   撤回委托后原子树路线从未被清除。自制与委外同享该继承（同构）。
3. **委外部即时可见**：下达事务内除既有 SUB_PLAN/DEPT_PROD 通知外，向持
   `subcontract_application:view` 的办理人池发「新委外单（车间先产）」提醒，直达
   `/subcontract/preparations`；委外准备中心·分析来源页签表格化并新增**车间进度**列
   （服务端按委托行执行段聚合：正在通知车间生产 → 车间正在等物料 → 车间生产中 →
   已完工入库·待通知委外 → 已通知委外）。读接口 GET `/subcontract-make-tasks` 放宽为
   anyOf(分析 view / 准备中心 view) 与页面守卫对齐；分批通知 POST 门槛不变。
4. **性能**：`production_plans(material_analysis_item_id)` 部分索引（V480）支撑进度聚合；
   LATERAL 只挂列表查询不挂计数。

**顶层（ROOT_SUPPLY）口径**：顶层路线门禁维持——根 BUY/SUBCONTRACT 不在下达前展开 BOM 子树
（根层现货交接与子层毛需求会重复计量，且委外件的子层在委托行下以正确数量展开）；
顶层诉求落为**显示同构**：状态统一「未下达/已下达」词汇、缺口列纯数字，不再有
「待料可下达/已齐套/待生产 X」特例。

## 九、修订五(2026-09-06)：原树唯一需求与通知事务

根层与中层有子件委外统一保留原树物料节点，路线确认后允许先下达 WAITING 前置自制。`SUBCONTRACT_MAKE` 仅是目标件计划锚点，不展开第二份 BOM，不重设子件路线，也不再次下达已有子件。根采购仍按外购整件处理。实际齐套、领料、开工、品质和入库守卫保持。

V495 使根锚点精确匹配同分析、同原需求行的真实直属子件；中层继续按父路径匹配。前置自制的正式领用覆盖保持到委外最终回厂，不因半成品已入库而重复补料。旧复制子树后继承路线的无效刷新查询已删除。

人工分批通知在对象鉴权及分析、任务锁后读取回执，相同请求只建一份申请；每批续用最新动作代际。满批自动通知在入库事务内按原分析制单人归属生成申请，仓库操作人只承担真实操作审计，不要求其拥有计划编辑权限。任一写步骤失败都回滚，不吞掉异常提交半条链。V494 将延迟守恒检查限定到本次 old/new 任务，保留全量对账函数和所有历史事实。

委外查看前置生产进度沿申请登记簿和任务中心，前置自制页面不复活。代码及验证范围见[V494](../数据迁移/110-V494委外分批通知守恒与并发.md)、[V495](../数据迁移/111-V495根委外前置自制物料归属.md)。

V496 补齐通知后的反向：已解除所有订货与实物占用的生成申请，可通过原供料撤回入口追加批次冲销，释放前置产出反向资格。原批次不删除；有效已通知量按原批次减冲销守恒。部分订货恢复的 6+4 预留按有效剩余扣回，不能按 10+4 重扣。未通知前置责任与已通知申请各计一份，取消不会再造一套任务。见[V496](../数据迁移/112-V496委外通知冲销与前置产出反向.md)。
