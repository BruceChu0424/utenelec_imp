# 历史估值精度夹具复验

本次仅修复 ValuationComponent 的历史数据夹具，生产成本、业务守卫、精度选择与客户端契约保持原样。

原 CI 有六个用例在 `ALTER TABLE ... ENABLE ALWAYS TRIGGER` 报 25P02。独立原单案保留失败结果，并在旧 finally 之前仅打印首错：实际首错是更新节点的两项历史精度元数据时，`fn_guard_inventory_value_precision` 抛 55000“Original inventory precision identity is immutable”。

V1063 已把原精度触发器拆为 INSERT 和 `_upd` UPDATE 两个入口；夹具只按旧 INSERT 名称选择元数据触发器，遗漏 UPDATE。现在按真实元数据函数身份选择两者，并保存、恢复每个原 trigger mode。原量、成本、单据、来源、事件和 GL 事实仍在修改前后逐项 JSON 比对，只有夹具明确声明的 value_precision_version/business_precision_policy 两项元数据允许改变。物理和来源的延迟守卫仍执行原 `SET CONSTRAINTS ALL IMMEDIATE` 验证。

成功时在同一事务恢复全部原模式；失败时让 PostgreSQL 回滚元数据与事务性 trigger DDL，保留原首错，不在已中止事务的 finally 再发 ALTER 覆盖为 25P02。
