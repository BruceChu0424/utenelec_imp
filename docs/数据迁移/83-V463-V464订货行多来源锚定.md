# 83. V463/V464 订货行多来源锚定（同货品合并生成订货单）

> 决策背景与全链设计见 [ADR-069](../99-决策记录-ADR/ADR-069-订货行多来源锚定与同货品合并.md)。

## V463__order_item_source_merge.sql

1. 新增两张业务表（均带行级审计触发器 + `UNIQUE(order_item_id, 来源明细)` + `CHECK(alloc_qty > 0)`）：
   - `purchase_order_item_sources(order_item_id, request_item_id, alloc_qty, line_no)`
   - `subcontract_order_item_sources(order_item_id, application_item_id, alloc_qty, line_no)`
   - `SUM(alloc_qty) = 订货行 qty`；`purchase_order_items.request_item_id` /
     `subcontract_order_items.application_item_id` 保留为首来源（主锚点）。
2. 历史行回填：有锚点且 qty>0 的订货行 → 单来源（alloc = 行数量，line_no=1），
   `ON CONFLICT DO NOTHING` 幂等，不区分 is_deleted（读取侧视图自带过滤）。
3. FIFO 分摊 SQL 函数 `fn_purchase_order_source_share` /
   `fn_subcontract_order_source_share(行 id, 来源明细 id, 总量 BASE)`：
   按 line_no 顺序先到先得，**末位来源吸收超额** ⇒ 单来源行份额 = 全量
   （与 V463 前单锚行为逐位一致）。Java 侧分析覆盖统计复用。
4. `CREATE OR REPLACE VIEW v_procurement_decomposition_tasks`（替换 V301 版）：
   待财务占用 pending 改按 `SUM(src.alloc_qty)` 汇总——合并行的占用不再串到
   首来源一张申请上。列名/类型/顺序与 V301 完全一致（mapRow 按固定列位读 31 列）。
5. `CREATE OR REPLACE VIEW v_preplan_buy_action_slice_progress`（替换 V446 版）：
   订货行经 sources 关联到申请行切片；到货/待检/未交量按窗口函数 FIFO（末位吸收）
   分摊；列契约与 V446 完全一致。

不新增索引以外的对象给历史消费方：`fn_check_preplan_analysis_stock_exact_peg`
（V312 现行版）本就不校验收货行→订货行的单一申请行等式，无需替换。

## V464__reset_twin_order_item_sources.sql
