> **2026-11-03 货品迁移规则修订：旧数据库优先，产品 Excel 辅助补缺。** 数据库已有非空同义字段（价格 `0` 也算已有值）全部保留；表格只补数据库真正缺失的属性、来源等信息，Excel 独有货品仍按准确编码建立独立身份。冲突保留双方原文和源行，不根据折扣、历史交易价或成本推算售价，单位冲突不换算、不覆盖。详见[货品价格溯源与数据库优先修复](2026-11-03-货品价格溯源与数据库优先修复.md)。旧派生层须按新规则重新生成和核对，本次改代码不等于已修正存量生产数据。 价格必须保留原始数值精度，禁止四舍五入、截断、固定小数位格式化或将页面显示值回写；导入前按实际目标列精度校验，不能精确表示时中止并报错，不静默改价。

这是整体彩排手册步骤4的补充。先完成人事、仓库单位清洗、供应商及模具引用主档、最新产品 Excel 的身份及数量单位审计，再执行本节。所有派生操作均在完整导入事务内，位于货品 Excel 属性之后、BOM及交易之前。未核对的自由文本不转成新的业务关系或数量。

## 先确认来源字段的真实含义

本轮只读源库 `YTDQ_rehearsal_20261022` 的 `B_Goods` schema 与受审 `export_legacy.ps1` 确认：

| 老库真列 → CSV | 实测非空数 | 已证实的落点或处置 |
|---|---:|---|
| `Paper → paper` | 10346 | 真正货品备注；旧库存视图以 Paper 显示“备注”，当前货品页面和导出也使用 `goods.paper` |
| `[Require] → require_remark` | 0 | 独立的旧要求列，不能当成 Paper 的别名。最新 Excel 的“原ERP备注”和补充 JSON 原先只写在此列，不能代表页面可见备注已经更新 |
| `Material → material` | 7603 | 直接材质字段；数据库非空值优先，Excel“材质”仅补空。配方、组件材质及材料报价不能覆盖为整个货品的材质 |
| `Pack/BPack → pack/b_pack` | 0 / 0 | 直接包装字段为空；不把混合品牌、喷码、螺丝、装盒、贴纸说明猜成包装数量或采购倍数 |
| `ChartID/Lights/LStyle` | 均0 | 对应原列为空，不从杂项备注拼造图纸号、灯型或工序 |
| `StockPlace → stock_place` | 151 | 实为 18/19/20/21/22/24 等旧 `B_StoragePlace` 身份残值，完整来源保留；不导成当前货品货架，货品库位仍须按已审现场来源维护 |
| `CNumber/VNumber → c_number/v_number` | 3154 / 27 | 分别是客户型号、供应商型号；数据库非空值优先，Excel相应字段仅补空，不能移作模号 |
| `MouldID → mould_legacy_id` | 按来源逐行核对 | 精确引用旧 `B_Mould.ID`；已有准确旧引用优先，Excel仅在缺引用时经唯一身份映射补充 |

`Summary` **不是 `B_Goods` 的列**。`B_BomItem.Summary` 是 BOM 行摘要，`B_Mould.summary` 实为模具保管人，当前分别按自身来源语义迁移，不能混作货品备注。此前最容易踩的坑是按英文列名或“都叫备注”直接塞进同一新字段。

## 模具、模芯、后模镶件各自核对

本批旧 Paper 中 52 行提到模具、16 行提到后模。大多数已有明确 `MouldID` 及 Excel 模号，重新解析备注不能覆盖这些权威关系。例如部分备注写“模具V7-001”，但旧 ID 与最新 Excel 均指向 Q120-M19 或 MC-28 等选定模具；它们可能描述母模、模芯或共用组合，不能截取第一个编号改成该货品唯一模具。

1. 主模具关系保留直接旧 ID，数据库缺少关系时才使用 Excel 模具编号/名称，按已审引用主档规则映射。备注只有明确“模具”标签、唯一完整旧模号/备用号、当前关系为空、最新 Excel 模具名称及编号也为空时，才允许补缺；不截断位置后缀、不模糊补零、不以同系列前缀合并。本批没有满足这些条件的新补挂，故补挂0条。
2. 后模镶件沿用已审 V457 两条规则：“换后模X镶件”“后模镶件用X”。旧数据库 Paper 非空时优先使用；仅在旧备注为空时使用 Excel 原备注补缺，后模镶件已有值也保留。本批明确解析1条，货品旧 ID 36364 对应 `V7-012`，新旧来源一致。`换后模`、`后模借用MA-62` 未指出镶件编号，不把整套后模身份塞进镶件字段。
3. 前模芯、未说明前后面的模芯另列证据。当前 schema 只有 `rear_insert_code`，没有独立前模芯字段；不能以“有个相近字段”就错塞后模。本批保留可搜索原文、来源位置及解析值；后续若扩展前模芯模型，按该账本补迁，不丢原文、不新建猜测的模具主档。

每条决定及冲突均在 `goods_semantic_decisions.csv`，包括原文、来源列、产品旧 ID、当前模具身份、原模号、最新 Excel 模号/名称、规则与结论。同一条业务信息可能同时有旧 Paper 和 Excel 两份证据，摘要另按去重货品计数，不能把证据条数当货品数。

## 原模号中的位置须进入模具位置字段

[04号模具溯源文档](04-模具资料-老库溯源.md)及本轮引用主档清洗已确认，原 `B_Mould.Number` 的 `【B3-12】` 等尾缀属于模具存放位置。显示码重排成 `MJ` 后，仅把原码塞进备注会让结构化位置遗漏。

本轮严格匹配完整尾缀 `【[A-H][1-9]-[0-9]{1,2}】`，共1008条：其中1007条原 `place` 仅“注塑车间”，1条为空。生成如下合并：

- 原位置“注塑车间”、原模号 `A8-01【A2-14】` → `moulds.place = 注塑车间 / A2-14`。
- 原位置空 → 只写已确证的 `A2-14`，不猜车间。
- `【封存】`、非结尾标记及其他未证实格式不解析为货架。

这是**模具位置**，不写 `goods.stock_place`，不创建仓库、不改变模具在用/禁用状态，也不改变已按数据库优先规则确定的模具关系。原模号、原位置及新位置逐条保存在 `mould_location_semantics.csv`。

## 备注按数据库优先补缺，同时保留双方证据

原批次产品 Excel 有7284条非空“原ERP备注”；当时按Excel优先生成144条Paper变化，其中52条覆盖旧非空文字。这些数字保留为历史审计事实，不能作为现行导入指令。2026-11-03起，数据库 `goods.paper` 非空时保持原文，Excel备注只补空；`require_remark` 按其独立列语义保留并只补缺，不混淆两列。页面、打印、导出使用保留后的Paper，未采用的Excel原文、文件和行号继续留档，后置语义模块不得重新覆盖。

不把“按客户产品系列号编”推成客户或系列身份，不把“外加工”自动当成已证实的新采购路线，不把材料配方中的 KG 或克改成货品基本单位；基本单位、数量、价格闭环仍由前一步专项审计控制。没有独立可信字段的包装、喷码、螺丝和商业约定保留为原文说明，避免把字面数字变成会触发下单的业务参数。

## 准备及执行

```powershell
$py = 'C:/Users/bruce/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
& $py server/legacy_migration/audit_legacy_goods_semantics.py `
  --raw-data '<本轮受审raw目录>' `
  --overlay 'D:/uten_legacy_rehearsal/20261022/goods-overlay-final' `
  --references 'D:/uten_legacy_rehearsal/20261022/reference-masters' `
  --out-dir 'D:/uten_legacy_rehearsal/20261022/goods-semantics'
```

程序不连接数据库。每次最新 Excel、引用主档或覆盖层变化后必须重跑，不能重用旧派生结果。`goods_semantics_manifest.json` 绑定 raw manifest、各输入 CSV/JSON、生成程序、V457规则及证据文档的哈希。

| 产物 | 用途 |
|---|---|
| `goods_legacy_semantics.sql` | 在协调器同事务中执行的结构化补充模块 |
| `goods_note_semantics.csv` | 最新显示备注及明确后模编号，带预期旧值和 Excel 行号 |
| `mould_location_semantics.csv` | 原模号尾缀所证实的模具位置 |
| `goods_mould_semantics.csv` | 仅证据充分的缺失模具关系，本批0行 |
| `goods_semantic_field_sources.csv` | 各相关真源列的全部非空原文及落点策略 |
| `goods_semantic_decisions.csv` | 每条模具、模芯、材质配方、包装等语义的来源和处理依据 |
| `goods_semantics_summary.json` | 不包含原文的数量与结论摘要 |

三份执行 CSV 均为 UTF-8 管道分隔，静态 COPY 路径支持现有组合器。SQL 执行前校验旧值或本轮预期新值，漂移即整事务回滚；完成后再逐项对账，允许按同一输入重跑。它只写 Paper、明确后模镶件、已确证模具位置及满足严格补缺条件的模具关系，其他结构化字段也遵守数据库优先、Excel补缺的现行来源规则。

历史7284条备注、1008条模具位置、1条明确后模编号及0条新补挂只作原批基线；新生成结果须逐项核对数据库原值、实际补缺数、保留冲突和模具关系，不能按旧计数硬验收。源值原文留在私有目录，不复制到普通执行日志。自动解析测试通过、SQL组合器通过、数据库事务通过、页面人工验收是不同证据状态，分别记录。
