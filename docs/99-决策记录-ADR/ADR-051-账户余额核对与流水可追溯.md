# ADR-051：账户余额核对与流水可追溯

> 日期：2026-08-27
> 状态：V400-V405 余额批次、V408 追加式流水与 V416 异常/新写守卫均为源码候选；V417/379 空库已重放，目标非空库对账、财务 UAT、恢复和发布未完成
> 关联：ADR-011、ADR-017、ADR-027、ADR-030、ADR-034、ADR-035、ADR-053、V142、V166、V267、V277、V279、V328、V400-V405、V408、V416

## 背景

`accounts` 同时承担账户主档和运营资金余额快照。既有守恒式为
`balance_current = init_balance + receipts_total - payments_total`，收款、付款、费用、收入和
银行存取款审核会在同一事务更新账户并写 `finance_reconciliations`。但旧账户资料页存在四个缺口：

1. 普通账户编辑表单暴露 `initBalance`，容易把余额修正误做成主档字段更新；
2. `account:view` 已广泛授予，却同时返回期初、累计收付和当前余额；
3. 缺少上线时“全部账户重新核对”的批次、差异、幂等、并发和审计证据；
4. 账户详情与流水分离，列表没有专业的下钻、日期区间和关键字检索体验。

企业财务迁移通常把开账余额作为有日期、有抵销科目、可对账的记账事实，而不是直接覆盖余额。
账户余额和流水始终使用该账户自身币种：美元账户记美元，人民币账户记人民币；页面按币种分组并可下钻到
组成余额的交易，不把不同币种折算后冒充账户余额，也不把不同币种直接相加。

## 决策

### 1. 主档修改与资金事实分离

- 名称、显示编号、账户类型、银行账号和状态属于主档；业务关联始终使用账户 UUID。
- 显示编号允许受控修改。新建留空时由服务端取号；自定义编号仍受 V276/V279 同域及全局终身保留约束，
  改号、停用或软删都不释放旧编号。
- 币种、会计科目 UUID 和期初余额一旦存在资金历史便冻结。否则重生成历史总账时会把旧事实投到新口径。
- 普通 `account:edit` 不等于余额修改权。非零期初创建、期初变更及任何余额校准都额外要求
  `account:balance:adjust`。

### 2. 余额复核采用不可变批次

- 新增全量/部分余额核对批次。请求包含幂等键、服务端业务日、原因以及逐账户
  `expectedBalance` / `targetBalance`；全量模式必须覆盖全部活动账户。
- 页面可以提供“全部使用中账户目标填 0”预设，但该动作只填充目标值，不直接提交。若已有目标余额或
  外币本位币调账额，必须先确认覆盖并提供可见撤销；正式提交仍要求原因、差额复核、二次确认和同一套
  幂等/并发门禁。禁用账户不参与 FULL，也不能借预设绕过活动账户守卫。
- 目标余额输入不从当前值自动确认。即使差额为零也保留“已核对”明细，以证明全量检查完成；
  零差额不制造空流水或空总账分录。
- 服务端按账户 UUID 排序并加写锁，精确校验预期余额；任一账户冲突则整批回滚。
- 同一幂等键、同一请求指纹返回原结果；同键异内容拒绝。批次和明细禁止更新、删除或软删，
  纠错只能提交带新原因的新批次。
- 每行冻结账户编号/名称、币种、账户原币口径的调整前后值、原币差额和操作者，不能回查当前主档改写历史。
  余额核对本身不读取 `currencies.exchange_rate`：人民币非零调整的 `localDelta` 由服务端固定等于原币差额；
  外币零差额核对冻结 `localDelta=0`；外币非零调整须由财务显式提交同号、非零的本位币调账额
  `localDelta`，作为总账投影依据。该值是本次调整的独立会计快照，不是账户余额折算，也不是币种主档参考汇率。
- V401 用不可变 `localAmountBasis` 说明 `localDelta` 的权威来源：零差额为 `NO_CHANGE`，人民币同值为
  `BASE_CURRENCY_IDENTITY`，外币财务显式本位币金额为 `FINANCE_EXPLICIT_LOCAL`。既有 V400 行只为保持
  历史可重放标记 `LEGACY_REFERENCE_RATE`；新批次不得继续使用该旧参考率路径。
- V402 用 `BEFORE INSERT` 守卫阻止新行伪装成 V400 历史依据；V403 把本位币身份绑定到唯一币种 UUID 的
  `is_base_currency` 标记，并在数据库层校验每个新行的 basis。币种编号、名称和参考汇率均可作为显示/
  默认资料，但不得充当本位币身份。
- V404 强制调账行 `currency_id` 等于该 `account_id` 当前币种 UUID，并共享锁定账户/币种防止并发
  改币种；V405 进一步禁止普通更新改变本位币主键 UUID。V400–V405 均只能通过后续前向迁移修正。

### 3. 本次调整差额在余额、流水与总账同源

- `accounts` 增加累计调整额，守恒式改为
  `balance_current = init_balance + receipts_total - payments_total + balance_adjustments_total`。
- 非零差额写入 `finance_reconciliations`，来源类型为 `BALANCE_ADJUSTMENT`；增加记入流入、减少记入流出。
  流水金额与账户余额使用同一账户原币。账户流水仍从期初开始按发生日顺序滚动，日期和关键字只裁剪
  返回行，不裁剪余额事实。
- 每个批次使用稳定的“账户余额调整清算”权益科目。总账投影按账户 `style_id` 与清算科目生成对称借贷；
  增加余额时借账户、贷清算，减少时方向相反。人民币使用与原币差额相同的 `localDelta`；外币非零调整
  使用批次行显式冻结的本位币 `localDelta`，不得回读当前币种主档汇率重算历史。
- 余额校准与总账月度重生成使用既有科目树锁和 AUTO 期间锁。缺币种、外币非零调整缺少合法
  `localDelta`、账户科目、清算科目或借贷不平时失败关闭；零差额核对不因汇率缺失而失败。
- V400 只投影本批 `target - current` 调整差额，不从 `init_balance` 或目标余额猜造历史总账开账。
  若既有账户期初尚无正式总账 opening 凭证，必须另走经财务批准的开账迁移/凭证并联合对账；FULL 余额核对
  成功只证明运营账户余额已逐项核对，不等于历史总账开账完成。
- 因此“全部目标填 0”只把使用中账户的当前余额通过新调整差额归零；`init_balance`、累计收付款、
  既有调整、账户流水和总账历史继续保留。它不是删除历史或重新初始化数据库。

### 3.1 V400 legacy 币种桥接与失败关闭

- V400 只对 `legacy_id IS NOT NULL AND currency_id IS NULL` 的旧账户应用既有且可证明的二分规则：
  `account_type='OFFSHORE'` 取唯一使用中、未删除的 `currencies.legacy_id=3` 美金 UUID，其余 legacy
  账户取唯一使用中、未删除的 `currencies.legacy_id=1` 人民币 UUID。已有显式 UUID 不重写，
  `legacy_id IS NULL` 的在线/手工账户不参与推断。
- 人民币或美金目标为 0 条或多条，或者桥接后仍有活动未删除账户的币种为空、悬空、禁用或删除，
  都以 SQLSTATE `23514` 回滚 V400；这是防猜填门禁，不是可用 `repair` 绕过的 checksum 故障。
- 当前本地候选库只读实测桥接集合为 27 行（人民币 26、境外美金 1）。该数字只证明本地数据形态，
  不外推为公司目标库事实；目标库须在可恢复非空副本重新生成清单并由财务逐账户确认。
- `legacy_id=3` 美金币种当前本地参考汇率为 0。币种身份桥接、账户原币余额与交易汇率是三类事实：
  该值不阻止 V400 的 UUID 桥接，也不阻止美元账户按美元展示、查流水或做零差额核对。销售发运开账、
  收款到账等业务另行冻结各自交易时点汇率；账户余额核对不得要求先把可变参考汇率写回币种主档。

### 3.2 V408/V416 追加式流水、迁移异常、缓存差异与查询边界

- `finance_reconciliations` 增加稳定 `posting_seq`、`entry_kind`、`reversal_of_id`、`account_currency_id` 和 `amount_local`。`in_amount/out_amount` 永远是账户自身币种；旧外币历史若无法证明本位币快照可为 NULL，V416 后新流水必须保存正快照，本位币账户 native/local 同值。
- 全表禁止 UPDATE/DELETE。红冲只能追加唯一的 `REVERSAL`，并镜像原 `POSTING/ADJUSTMENT` 的来源、账户、币种和流入/流出；普通收款、付款、费用、其它收入、账户转账和供应商索赔到账均已改用共享反向流水服务。
- 数据库在账户存在任一资金单据、流水或余额调整后冻结账户币种、GL 科目和期初余额，补上仅靠应用层守卫时的直接 SQL 缺口。
- V416 要求新流水有来源 UUID、启用账户/币种和合法本位币快照；`v_account_flow_migration_exceptions` 将旧行的原生余额阻断与外币快照未证明分开列示，不自动回填。
- `v_account_balance_integrity` 以 `init_balance + SUM(in_amount-out_amount)` 重建账户原币余额，分别返回缓存余额、流水余额和差异。余额调整发现任一待调账户既有差异非零时整批失败，不能用新调整掩盖旧漂移。
- 该视图是系统账缓存/流水完整性视图，不是银行对账单。真实银行期末余额、回单导入、逐笔匹配和未达账项仍未交付。
- 账户流水查询使用 PostgreSQL 窗口函数、数据库日期/关键字过滤和 `(account_id,bill_date,posting_seq)` 覆盖索引。期初余额不再每次从第一笔全历史 `SUM`：完整月份读 `account_flow_monthly_summaries`，只对起始月月初到 `dateFrom` 扫原始账本尾段。月汇总可全量/按账户重建，`v_account_flow_monthly_integrity` 与原账逐月核对。
- 当前 V419/381 PostgreSQL 16.15 空库以 250000 条、5 账户、50 年分布执行财务规模/异常守卫 6/6，`skipped=0`。两个 Index Only Scan、无原流水 Seq Scan，Execution Time 1.059 ms、Java/JDBC 墙钟 20 ms，缓存/原账、月汇总/原账和规模样本迁移异常均为 0。该结果不是 V418/V419 业务验收或目标库 P95/P99；OFFSET 深页仍须复测。
- V1 收款的账户反向与 GL 反向是同一事务的两套派生事实：账户层保留 `POSTING` 并追加 `REVERSAL`，deferred `receipt_flow_terminal_guard` 禁止只改单头不写流水；总账层保留 `RECEIPT` 并追加逐行镜像 `RECEIPT_REV`。`v_receipt_expected_gl_entries` 用冻结科目/金额校验原凭证公式，`v_receipt_gl_integrity` 发现缺凭证、错金额或未镜像；按期间作业不得删除重建 V1 收款去掩盖差异。

### 4. 权限按动作和敏感度拆分

- `account:view`：查看非敏感账户主档。
- `account:balance:view`：查看期初、累计调整、累计收付、当前余额、按币种汇总和警戒线。
- `account:flow:view`：下钻账户流水；同时要求账户查看和余额查看。
- `account:warning:manage`：维护账户币种口径下的余额警戒线。
- `account:balance:adjust`：执行全量/部分余额校准；它是高危个人权限，不允许部门授权、页面委派或
  “全选授权”，默认不授任何部门，只能由超管在统一权限页对具体员工点名。

金额裁剪必须由服务端完成。列表、详情、字典、汇总和导出不能依赖前端隐藏来保护余额。

### 5. 汇总、警戒与欠款边界

- 账户页顶部只按币种显示使用中账户余额；禁用账户不进入余额、预警或负余额汇总，也不做跨币种裸合计。
  若未来增加本位币折算，必须展示权威汇率和折算时点。
- 账户币种表示实际资金或清算余额的计量单位，不等于销售订单币种或代收渠道。外贸公司把美元自动结汇后
  实际进入人民币银行账户的，只增加该人民币账户余额；只有公司确实持有或可支配美元余额时，才增加美元账户。
- “负余额账户”只是账户异常，不等于客户欠款或供应商欠款。应收、应付仍由 `ar_ap_ledger` 独立授权和展示，
  不混入账户主档汇总。
- 每个账户可设置同币种余额下限；低于下限时同时显示文本、图标和颜色，不能只靠颜色表达。

### 6. 页面采用上推吸顶和详情下钻

- 账户列表复用 `UtenCollapsingHeaderScrollView`：顶部概览随上滑收起，搜索/添加/余额核对操作行置顶，
  `MasterDataTableView(primary: true)` 在剩余空间内滚动。
- 列表首屏只加载主列表、facets 和按权限裁剪的 summary；禁用账户首次展开才加载，币种/科目编辑字典
  仅在新增或编辑时加载。详情由列表 push 进入时使用 pop 返回并触发列表刷新，PUT 回包直接更新详情，
  禁止为一次返回重复请求静态字典或用 go 替换 push 栈。
- 余额核对页的“全部使用中账户目标填 0”与提交按钮分离；预设后明确提示尚未提交并提供撤销。归零确认
  必须说明禁用账户不参与、历史保留；外币非零差额仍由财务逐账户填写同号非零 `localDelta`。
- 单击账户进入独立详情页。顶部是账户信息卡和显式编辑/停启/余额核对入口；下面是账户流水，支持关键字、
  起止日期、清除条件、排序、分页、加载/空/错误态，并显示 `POSTING/REVERSAL/ADJUSTMENT` 与原流水引用。
- 行右键（桌面/Web）和长按（触屏）提供查看、编辑、余额校准、停启和删除快捷菜单，但关键操作必须另有
  可见按钮，不能只依赖右键或手势。
- 类型筛选的传输值保持 `BANK`、`THIRD_PARTY` 等稳定枚举，服务端另返回中文 label；币种筛选同样返回名称，
  不能向用户展示枚举码或 UUID。

### 7. 停用和删除保持财务历史安全

- 已有资金事实的账户不得物理删除；删除仍为受限软删，并由服务端检查全部引用。
- 停用不能破坏既有红冲或重生成路径。当前链路尚未完成“零余额历史账户可停用但仍可红冲”的完整区分前，
  服务端继续失败关闭，UI 展示具体拒绝原因，不承诺所有已用账户均可停用。

### 8. 工作台不展示金额卡

工作台顶部不再返回人民币账户余额、未结应收或未结应付金额卡。账户余额放回账户资料页，AR/AP 放在钱流台账；
工作台继续承担待办和入口，不成为第二套财务汇总口径。

## 验收与发布边界

源码、迁移和本地测试只形成候选。上线前至少完成：

本地/测试库若需要真正“清除历史后重新开始”，只能在停写、备份和三重目标核验后运行
`server/ops/reset_business_data.sql`：先清业务事实，再在同一事务把所有使用/禁用账户的期初、累计收款、
累计付款、累计调整和当前余额归零，并保留带专用 actor 的账户审计。该运维清库不属于账户页面能力，
不得用于目标库或生产，也不得与保留历史的余额核对混为一谈。

1. 目标库备份与摘要留证；`flyway_schema_history` 与 V400-V408 源文件/校验和核对；可恢复非空副本执行
   legacy 空币种清单、26+1 规则不可外推的目标库独立复核、迁移升级和回滚演练；失败后禁止 `flyway repair`；
2. 现有账户守恒式、活动账户币种 UUID、账户原币余额、会计科目 UUID、流水与总账按账户/期间联合对账；
   外币非零调整另核验显式 `localDelta` 的符号、金额和审批证据，并证明每个既有
   `init_balance` 已有对应正式总账 opening；缺失时先完成批准的开账凭证；
3. 普通员工、财务查看人、警戒线维护人、余额调整人和超管的允许/拒绝矩阵；
4. 全量核对的零差额证据、并发入账冲突、幂等重放、原币流水、追加式反向、缓存/流水差异、人民币/外币
   `localDelta` 规则、总账借贷平衡、流水跨期滚动和目标规模 EXPLAIN；
5. 财务负责人对实际上线余额逐账户签字，随后执行签名发布、监控和恢复演练。

V400 当前余额调整仍由一个持 `account:balance:adjust` 的操作者直接生效，尚无 maker-checker 审批状态；该缺口、通用会计期间和真实银行对账完成前，不能把 V408 的追加式流水等同于完整财务关账能力。

以上未完成前，不得把“能打开余额核对页面”表述为开账完成或生产可用。
