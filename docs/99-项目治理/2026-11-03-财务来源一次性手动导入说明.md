# 财务来源一次性手动导入

入口为 `tool/finance_seed_once.py`，使用 Python 3.10 及以上标准库。脚本由操作人员手动运行，不接入启动、Flyway、安装、普通更新或定时任务。本次没有运行公司环境的 apply，没有推送、部署或正式打包。

本阶段导入原来源和目录。它不会提交或批准凭证，不写总账、现金、库存、正式应收应付，不创建假凭证、假现金、假库存，不把需求样例变为实际业务。原账套接续、科目/币别/辅助映射、固定资产关联及双人审核仍须在现有业务入口完成。来源已保存、目录已保存与已过账、可生成完整实账是不同状态。

## 原件范围与实际落点

计划只接受本会话所给资料包的20份已知相对路径，不递归扫描其他 WeChat 或用户文件。白名单在脚本 `SOURCE_PATHS`。包括最初科目代码XLS、ERP需求总表、参照图、9月凭证、报表ZIP及其9份原书。每份原件记录SHA256、长度、2026-09期间、操作人员明确填写的原账套及用途；复制到指定私有 `state/source-archive`，不修改原文件、不将原件提交Git。

ZIP先完整检查路径、大小写重复、同名文件、加密、符号链接、总大小和压缩比例，再受控读取白名单成员。若提供现成解包文件，逐个核对它与ZIP原字节的SHA相同。不会执行公式、宏或文档指令。

| 步骤 | 业务权威入口 | 落点与后续处理 |
| --- | --- | --- |
| 原科目代码177行 | `/finance/chart/import-preview`、`import-apply` | 保存原代码目录；不猜科目UUID、币别UUID或辅助对应，不自动创建核算项目 |
| 9月凭证与科目余额表 | `/finance/accounting-imports/preview`、`/{id}/compare` | 两个真实来源批次与只读比对；保留原账套；不自动提交/审批/过账 |
| 应收/应付辅助原明细 | `/finance/auxiliary-imports/preview`、`directory-apply` | 固定请求号原件及辅助目录草稿；不生成应收应付金额。映射待核时目录保持待处理，其他来源仍可归档 |
| 实际资产原书3页 | `/finance/template-imports/assets/preview` | 按原名选“2026年固定资产清单”“费用摊销”“2025年前折旧完清单”；保留真实来源，未自动关联ERP资产 |

| 财务报表、费用、经营损益、经营指标、ZIP与图 | 私有来源归档与计划 | 对比与模板依据，不重复造账。尚无相同业务权威上传入口的原表不伪装成另一种导入 |

所有原数字、公式缓存和错误值随原字节保留。脚本不通过二进制浮点计算、补0、截断、舍入或重算公式；JSON小数读取为Decimal。遇到服务端精度取舍、除不尽或存储限额时停止该原请求，由财务在已有精度/核对流程明确决定。脚本不会选择位数。需保留的本次明确选择仅可经私有业务头JSON提供 `X-Uten-Precision-Choices`，其他头一律拒绝；不得在该文件放认证信息。

## 手动运行

先建立操作人员有权限的私有持久目录，放在应用版本目录、源码目录之外，保留到本次核验完成；使用Windows目录ACL限制到授权操作人员。计划、归档含私有资料，不放公共共享、Web静态目录或版本发布目录。示例中的UUID、服务器、原账套须由操作人员从真实环境核对后填写，不能照抄占位值。

```powershell
python tool/finance_seed_once.py plan `
  --state-dir "D:/UtenPrivate/finance-source-202609" `
  --source-dir "D:/AuthorizedFinanceSources" `
  --server "https://company.example/api" `
  --actor "真实当前账号UUID" `
  --source-system "财务确认的原账套标识" `
  --currency-id "财务明确选择的默认原币别UUID" `
  --period 2026-09
```

`plan`完全离线。检查私有 `plan.json` 的全部文件SHA、期间、原账套、模板/工作表、用途、目录动作与每步请求号，再运行。该版本只处理已给的2026年9月包，拒绝把它冒用为其他期间。计划一经写出不覆盖，不因中断删除计划换号重建。

```powershell
python tool/finance_seed_once.py apply `
  --state-dir "D:/UtenPrivate/finance-source-202609" `
  --server "https://company.example/api" `
  --actor "真实当前账号UUID"

python tool/finance_seed_once.py verify `
  --state-dir "D:/UtenPrivate/finance-source-202609" `
  --server "https://company.example/api" `
  --actor "真实当前账号UUID"
```

令牌默认从 `UTEN_FINANCE_SEED_TOKEN` 环境变量读取，未设置时安全交互输入，不显示、不写磁盘、不要求在聊天里提供。不要把令牌直接写命令行或说明文件。脚本GET `/auth/me` 验证当前真实账号、数据集UUID与业务重置代次；不同账号、主机、计划或数据集拒绝沿用日志。要求HTTPS；`--allow-http-loopback`只对显式本机HTTP隔离验证有效。

来源和目录动作要求现有真实权限：财务报表读取、公司级财务读取、核算项目编辑、财务过账执行（凭证来源入口原有要求），以及资产查看/编辑。无权限时不伪造账号、scope或审批。脚本没有自动凭证submit/approve选项；必须按原双人流程后续处理。

`verify`只GET，不初始化远端来源或目录。已完成后再次 `apply` 也只GET核对原资源SHA、身份及目录状态，新增目录/GL/现金/库存/应收应付均为0。待核目录以 `blocked-source-issues` 记录，打开原批次在业务页面核对；不得修改归档SHA、换请求号或自动重解析来绕过待核。

## 中断和未知结果

独立OS文件锁防止两个脚本并发使用同一state；进程被终止时由操作系统释放锁。每步发送前将状态、原请求号、路径、精确query/body身份、业务头及文件SHA写入原子替换且fsync的journal，发送后只保存最小批次UUID、SHA、状态和是否待核，不保存业务响应正文或金额。

- 辅助原件使用原固定 `requestId` 查询本人 `/operations/{requestId}`。回执存在时直接采用原批次，后来的科目/币别映射变化不会重解析它。404不能证明原POST永不执行；继续仍使用同一请求号、同一原bytes、原filename/Content-Type、query与业务头。
- 科目、凭证/TB、模板分别复用服务端既有actor+SHA、actor+原账套+SHA、actor+模板+期间+SHA+工作表去重。丢响应后同原输入重试；不换actor/文件/模板/工作表重造来源。
- 目录写入只按原批次幂等执行；失去响应先GET原批次的applied状态。完成资源404或身份/SHA改变时停止，不POST补建。
- 断网、强制终止、写盘失败后保留state目录并原命令继续；不输出响应正文或业务数字。服务端错误仅显示状态码及有限错误代码。拒绝所有HTTP重定向，认证信息不会转发到其他origin。
