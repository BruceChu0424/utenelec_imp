# V827–V829 安全维护

这三项是独立下一版本分支的前向迁移, 基线为 V826。合并前重新核对迁移号, 不改已应用迁移。
没有自动轮换生产密钥、删除业务原件或清空数据。

| 迁移 | 内容 | 业务数据边界 |
|---|---|---|
| V827 | PII 主钥轮换的批次检查点与专属权限 | 仅增加维护元数据; 轮换默认关闭, 必须由有效超管本人再认证后调用, 密钥只从环境注入 |
| V828 | 不可变文档病毒扫描证据 | 扫描结果独立追加保存, 不修改报价/AI/成本原件的历史版本; 业务清空保留证据 |
| V829 | 测试清空保留认证、授权、安全、系统四类审计; 登录失败时间窗部分索引 | 普通业务历史按原清空政策处理, 原清空回执继续保留; 不改变审计只追加守卫或清空函数权限 |

V829只替换 `business_data_reset()` 中两份明确的审计保留谓词, 分别覆盖在线表与归档表。
找不到恰好两处时直接中止; 前后核对函数 owner、ACL、SECURITY DEFINER 与配置完全一致。
保留策略在显式执行测试清空时才生效, 迁移本身不清空任何表。

运行前先验证可恢复的成套备份及密钥托管件, 用副本迁移和回归测试验收。上线激活仍使用正式
更新器; 回退应用版本不能逆向删除已经产生的轮换检查点或扫描证据。生产 Nginx 模板对
`/api/system-test` 及其子路径返回 404, 内测环境保留独立受控入口。

本地验证、CI 和服务器安装分别记录在本次治理文档, 不互相替代。
