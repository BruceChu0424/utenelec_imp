# ADR-084 出货仓库作业一步确认出库

- **状态**：已接受（2026-09-14，V582）
- **相关**：[ADR-030 销售待收计划与正式应收分层](ADR-030-销售待收计划与正式应收分层.md)、
  [ADR-082 出货财审退回链路闭环](ADR-082-出货财审退回链路闭环.md)、
  [174 V582 出货仓库一步确认出库](../数据迁移/174-V582出货仓库一步确认出库.md)、
  [销售出货仓库作业页](../03-页面/销售出货仓库作业页.md)

## 背景

V187 给销售出货建立了单据级仓库状态机
`PENDING_PICK → PICKING → PICKED → SHIPPED`，外加 `EXCEPTION ⇄ PENDING_PICK` 的退拣回路。
设计意图是让仓库的实物动作留痕。但运行一年后的事实是：

1. **三个中间态没有任何独立的业务事实**。`PICKING` 只写三列表头 + 给零星发货建一条库存占用；
   `PICKED` 只写两列时间戳；`EXCEPTION` 只写一条原因文本且**不释放**已建的占用。
   真正改变库存、预留、订单已发量和应收的，全部集中在 `SHIPPED` 那一跳。
2. **代价却是全局的**：可用量算式要在四个地方减去「其它在拣任务占用」（闸门与只读预览各一套，
   手写重复、极易漂移）；任务中心要维护五个分类页签；客户端要区分五种动作与两种必填原因；
   `EXCEPTION` 在直发与订单两条路上的计入口径还不一致。
3. 用户口径（2026-09-14）：仓库准备好了就应该直接出库，不要这么多步骤限制。
   同一个系统里，生产领料（DRAW）早已是「出库即审核」一步式，两边不该有两套心智模型。

## 决策

**删除 `PICKING` / `PICKED` / `EXCEPTION` 三个状态及其命令，仓库只保留一步「确认出库」。**

```
PENDING_PICK --（确认出库）--> SHIPPED
```

- 财务放行仍是硬前置，`PENDING_PICK` 仍只占订单行可发额度、不占库存。
- 确认出库在**同一个事务**里完成：选实际叶仓 → 逐行实际库位 → 证明本仓可发 →
  扣库存 → 消费预留 → 回写订单已发量与链上状态 → 立唯一正式 AR。任一步失败整事务回滚。
- 「异常」不再是一个状态。仓库发不出货时就是不点确认；需要把单据退回销售时走既有的
  `sales_shipment:reject`（仓库驳回，释放订单预留），它本来就存在且语义更清楚。
- 已 `SHIPPED` 的历史事实一律不改写；事件账里的历史 `PICKING/PICKED/EXCEPTION` 行只读保留。
  在途老单由 V582 统一拨回 `PENDING_PICK` 并释放其拣货占用。

## 为什么这样更安全，而不是更松

删掉中间态最容易被误读成「少了一道关卡」。实际相反：

- 原两阶段模型里，`PICKING` 的可拣量校验与 `SHIPPED` 的真实扣账**是两个事务**。
  中间那段窗口靠「其它单据停在 PICKING/PICKED」这种**状态推断**来占位——
  一个既不在 `stock_balances` 也不在 `stock_reservations` 里的隐形占用。
- 一步式把校验与扣账合进同一事务，共用同一批 goods/color 互斥锁。
  并发的第二张单会在锁上排队，然后按**已经扣减过的真实余额**重算，
  不存在「两边都校验通过再一起扣」的窗口。隐形占用这一整个概念随之消失。
- `FullChainEndToEndTest` 里两张直发单竞争同一有限池的用例因此变得更强：
  落败方不再留下半条占用，而是整事务回滚、什么都不留下。

## 明确不做

- **不做分批出库**。领料的「多轮分批出库」是按申请量逐次发，销售出货是整单发运、
  一次立唯一正式 AR；把它改成可分批会牵动 AR 立账口径、汇率锁定与退货来源，
  不在本次范围。需要分批时仍由销售拆成多张出货单。
- **不删 `picking_started_*` / `picked_*` 列**。它们是已出库历史单的证据，
  且重建后的实仓取证函数仍按这两列走历史兼容分支。新流程只写 `handed_over_*`。
- **不收窄 V188 事件账的 CHECK**。表是追加式不可改写，存量事件行就带着三个旧状态。
- **不改端点、方法名与权限码**。`POST /{id}/warehouse-work`、
  `transitionWarehouseWork`、`sales_shipment:warehouse-work` 全部保持原样，
  只是 `targetStatus` 收敛为单值。

## 影响

| 面 | 变化 |
|---|---|
| 仓库任务中心 · 销售出库 | 五个状态页签收敛为「待出库 / 已出库」；多选后右下角红色「确认出库」一次办完 |
| 销售出库详情 | 底部只剩一个「确认出库」按钮；事实卡去掉开始拣货/拣货完成/异常说明三行；出库备注选填 |
| 销售出货详情（销售视角） | 仓库动作只剩「确认出库」；「仓库作业中」这一档状态提示消失 |
| 待办与角标 | 口径不变（仍是「财务已放行且尚未出库」）；办结时机由开始拣货挪到确认出库 |
| 权限 | 零变化 |

## 取代的既有表述

- ADR-030 §「仓库开始作业后须先异常退拣才能财务反审」→ 财务反审的边界就是「仍是 `PENDING_PICK`」。
- ADR-082 §「仅未放行且仓库未作业的退回单」→ 等价于「仍是 `PENDING_PICK`」。
- V566 迁移说明里「填仓发生在 `PENDING_PICK → PICKING`」「`targetStatus=PICKING` 时接受
  `warehouseId`/`stockPlaces`」→ 两者都改到 `PENDING_PICK → SHIPPED` 这一跳。
