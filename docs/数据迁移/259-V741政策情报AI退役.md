## 背景

2026-09-27 用户要求: 以前写过的「相关新闻之类的 AI」(工作台政策情报: 定时抓取政府网站的政策摘要, 再用 DeepSeek 生成摘要)连同文件、代码、展示界面和 API 配置全部删除, 改为新的公共 AI 平台(V742, ADR-133)。

V166 建的 `official_policy_briefs` 只是外部网页的展示缓存, 不是业务事实, 没有任何表引用它; 权限码 `dashboard:finance_sensitive:view`(V166 建, V677 改名)唯一用途是让持有人在政策情报里看到财税类政策。

## 结构

- `DROP TABLE official_policy_briefs`(连同其审计触发器)。
- `business_data_reset()` 孪生函数移除 `('official_policy_briefs', 'PRESERVE'),` 一行: 沿用 V590/V677「读已安装定义 + 单行 needle 替换」失败关闭补丁, needle 必须恰好出现一次, 否则报 `V741 cannot drop retired official_policy_briefs from business_data_reset` 整体回滚。
- 退役 `dashboard:finance_sensitive:view`: 先删页面权限面映射(外键 RESTRICT; 该码是不可委派码, 实际没有映射), 再删目录行; 部门授权、个人覆盖与负责人委派随外键级联删除(V677 第 4 节同款)。

服务端政策情报服务/调度/配置键、工作台政策卡片与前端 `Perm.dashboardFinanceSensitiveView` 由同一轮代码改动删除, 不在本迁移里。

## 兼容与数据

- 删除的是外部网页展示缓存, 不影响任何单据、库存、金额或主档; 已应用迁移字节不变。
- 旧应用连接 V741 库时工作台政策情报查询会失败(表已删), 因此 V741 必须与删除政策情报代码的同一版应用一起发布, 不单独上线。
- 服务器上旧的环境变量 `UTEN_POLICY_INTELLIGENCE_ENABLED`、`DEEPSEEK_API_KEY` 属于主机侧配置, 本迁移不处理。内测服务器环境校验脚本(本轮部署改动同步修改)继续接受并忽略 `UTEN_POLICY_INTELLIGENCE_ENABLED`(避免旧 env 文件让服务起不来); 各服务器 `server.env` 中这两行的删除作为发布后的运维步骤单独执行并记录。

## 运维步骤(发布后, 主机侧)

迁移与新版应用都不修改服务器上的 `server.env`。旧的政策情报变量对新版应用已无作用, 内测环境校验脚本「接受并忽略」
`UTEN_POLICY_INTELLIGENCE_ENABLED`, 所以升级不会因为它启动失败; 但应在发布验证通过后逐台清理, 并在发布记录里写明每台的结果:

1. 备份: `cp /etc/uten-imp/server.env /etc/uten-imp/server.env.bak-$(date +%Y%m%d)`(路径以该服务器实际 env 文件为准, 本地生产、云端热备、内测各一份)。
2. 删除旧行: 删掉 `UTEN_POLICY_INTELLIGENCE_ENABLED=...`、`UTEN_POLICY_INTELLIGENCE_*` 其余各行与 `DEEPSEEK_API_KEY=...`(内测校验脚本对 `DEEPSEEK_API_KEY` 仍是「必须不存在」)。
   旧的 DeepSeek 密钥如果还要用于新平台, 不要写回 env: 由超管在「系统设置 → AI 服务」按 ADR-133 重新填写, 之后到服务商控制台轮换旧密钥。
3. 可选新增: 生产没有 `UTEN_SECRET_CIPHER_KEY` 时按 ADR-133 生成(至少 32 字节, 新装机模板已自动生成); **云端与本地必须相同**。
   internal-test 保持 `UTEN_AI_OUTBOUND_ENABLED=false`(或不写, profile 强制 false)。
4. 重启服务并确认日志有 `Started`、健康检查通过; 在发布记录里记下每台服务器已清理(日期、操作人)。
