## 一、项目目标

Uten IMP 面向 200–1000 人制造业企业，使用场景覆盖：

| 场景 | 设备 | 典型宽度 |
|---|---|---|
| 车间班长巡检 | 手机竖屏 | 360–420 dp |
| 厂长出差审批 | 手机横屏 / 小平板 | 600–840 dp |
| HR 办公桌前 | 平板 / 桌面 | 840–1280 dp |
| 财务月底结账 | 桌面 / 大屏 Web | 1440 dp+ |

**核心要求**：

1. 单一代码库（`lib/`），通过布局断点自动适配，**禁止** `if (Platform.isAndroid)` 这类分支写两套 UI。
2. 任意页面在 compact / medium / expanded 三档下都布局合理、不溢出、不空旷。
3. 导航形态：**compact 悬浮胶囊 / medium+ 左侧 Rail**（见 [App外壳](../03-页面/App外壳.md)）——窄屏底部胶囊 overlay，≥600dp 切左侧 Rail + 内容居中收敛。
4. 内容区全屏宽（UI v4 起取消左侧栏与 maxWidth 收束），网格列数按容器实际宽度自适应。

> 📌 **导航演进**：
> - 2026-07-23（UI v4）：废弃「底部 Tab ↔ 折叠 Rail ↔ 展开 Rail」三档切换，原侧边栏角色分组入口迁入工作台功能模块区。
> - 2026-07-27（现行）：导航回归断点分化——**compact（<600dp）底部悬浮胶囊 / medium+（≥600dp）左侧 Rail**（`UtenSideNavRail`，≥1280dp 常驻标签）。
>   四主 Tab 由 `UtenSlidingTabView` 承载：compact 播左右滑动转场（手机 PageView 直觉），medium+ 即时切换（不整页横移）。

## 二、三档断点定义

### 2.1 断点表

本项目采用与 Material 3 [WindowSizeClass](https://m3.material.io/foundations/layout/applying-layout/window-size-classes) 对齐的三档断点：

| 档位 | 枚举值 | 宽度范围（dp） | 典型设备 | 等价 Material 3 |
|---|---|---|---|---|
| 紧凑 | `Breakpoint.compact` | `< 600` | 手机竖屏 | compact |
| 中等 | `Breakpoint.medium` | `600 – 840` | 手机横屏、小平板 | medium |
| 展开 | `Breakpoint.expanded` | `> 840` | 平板、桌面、Web | expanded / large |

> 💡 为什么不用 4 档（Material 3 还有 large / extra-large）？
> 制造业后台的 UI 复杂度有限，三档足够覆盖；多一档意味着多一倍测试和视觉稿。expanded 档内部用"最大内容宽度限制"消化超宽屏，不靠额外断点。

### 2.2 与 Material 3 WindowSizeClass 的关系

Material 3 把窗口尺寸划分为 `compact / medium / expanded / large / extra-large` 五档，每档对应推荐布局。本项目**对齐其前 3 档定义**：

- `compact < 600 dp`：单栏、底部导航。
- `medium 600–840 dp`：开始出现双栏，导航形态过渡。
- `expanded > 840 dp`：多栏、侧边导航。

> ⚠️ Material 3 文档里的 medium 边界是 600，不是 720 或 840（早期 Material 2 文档）。本项目统一以 **600 / 840** 为切点。

## 三、每档断点下的策略

### 3.1 导航策略

> **现行（2026-07-27）：按断点分化**——compact 悬浮胶囊，medium+ 左侧 Rail。

| 档位 | 导航形态 | 组件 | 说明 |
|---|---|---|---|
| compact（<600dp） | 底部悬浮胶囊（overlay 不占布局） | `FloatingCapsuleNavBar` | 4 项（工作台/通知/我的/设置），胶囊滑块跟手高亮，四页左右滑动转场 + 触屏可横滑切相邻 Tab |
| medium / expanded（≥600dp） | 左侧 Rail（≥1280dp 常驻标签，否则纯图标 + Tooltip） | `UtenSideNavRail` | 同 4 项，点 Tab **即时切换**（不播整页横移）；内容区套 `UtenContentContainer` 居中收敛（maxWidth 1600） |

实现要点：外壳 `MainShellPage` 按 `context.breakpoint.isCompact` 分两支（`_buildCompactShell` / `_buildRailShell`），四主 Tab 共用 `UtenSlidingTabView` 承载、全部常驻保活（进业务子页面仅 Offstage 隐藏，切回不回顶）。历史方案见 [ADR-007](../99-决策记录-ADR/ADR-007-导航重构与三层权限模型.md)。

#### 3.1.1 主 Tab 转场策略（compact 横滑 / medium+ 即时）

| 断点 | `UtenSlidingTabView` 参数 | 行为 | 理由 |
|---|---|---|---|
| compact | `animated: true`、`swipeEnabled: true` | 新页从一侧滑入、当前页对侧滑出；触屏可横滑切相邻 Tab | 手机 PageView 直觉，窄屏横移幅度小 |
| medium+ | `animated: false`、`swipeEnabled: false` | 点 Tab **即时切换**，无转场动画；不开横滑手势 | 大屏整页横移幅度大、突兀（有"盖住导航"的错觉）；桌面用点击切 Tab，无需手势 |

> ⚠️ **不要在大屏给主 Tab 用左右整页滑动转场。** 它是手机 `PageView` 的隐喻，搬到桌面/web 体验割裂。新页用「即时切换」或至多短淡入淡出即可。
> 四主 Tab 之外的**业务子页面**（工资条/报销/单据详情…）照常走 go_router 的标准 push 转场，不在本节范畴。

### 3.2 内容布局策略

| 内容类型 | compact | medium | expanded |
|---|---|---|---|
| 列表页 | 单列 | 单列（加宽） | 双列（master-detail）或单列居中 |
| 详情/表单页 | 单列 | 单列或双列 | 双列（label-value 两栏） |
| 卡片网格 | 1 列 | 2 列 | 3–4 列 |
| 数据表格 | 卡片列表（横向滑动） | 简化表格 | 完整表格（锁定首列） |
| 工作台 Dashboard | 1 列卡片堆叠 | 2 列卡片 | 3–4 列 KPI + 主图表 |

> 📌 **卡片网格列数应交给 `UtenResponsiveGrid` 自动处理**，不要在页面里手写断点列数。组件内部按**容器宽度**算列数，规则见下方 3.2.1。

#### 3.2.1 卡片网格列数规则（基于容器宽度）

`UtenResponsiveGrid`（Wrap 瀑布流实现）的列数**完全基于 `LayoutBuilder` 的容器宽度**自动推导，规则如下：

| 容器宽度（dp） | 列数 | 典型场景 |
|---|---|---|
| `< 500` | 1 | 手机竖屏、被弹层/分栏大幅挤窄的区域 |
| `500 – 800` | 2 | 手机横屏、小平板、桌面窄内容区 |
| `800 – 1100` | 3 | 平板、桌面 |
| `1100 – 1500` | 4 | 桌面宽屏 |
| `> 1500` | 5 | 大屏 / 4K Web |

> ⚠️ **断点判断必须用容器宽度，不能用屏幕宽度。**
> `SplitView` / `Dialog` / 右侧抽屉等都会挤占内容区宽度。按屏幕宽度算会**高估列数**，导致卡片溢出或挤压（UI v4 取消左侧栏后内容区通常=屏宽，但该原则对嵌套容器依然成立）。
> 因此：
> - 卡片网格（`UtenResponsiveGrid`）列数 → 基于 `LayoutBuilder.constraints.maxWidth`
> - 根 Shell / 导航形态切换 → 用屏幕断点（`context.breakpoint`）
>
> 二者各司其职，不要混用。详见 [03-自适应布局组件.md](03-自适应布局组件.md) §3.2。

### 3.3 最大内容宽度限制

> 🚨 **expanded 档下，阅读型内容区不得超过 1600 dp，且必须居中。**

理由：

- 文字行宽超过 ~120 字符（约 1600 dp @ bodyMedium）阅读体验急剧下降。
- 4K 屏（3840×2160）下不限制会导致卡片被拉成"长条"，留白巨大。

实现方式：在最外层 `Scaffold` body 包一层 `Center` + `ConstrainedBox`：

```dart
ConstrainedBox(
  constraints: const BoxConstraints(maxWidth: 1600),
  child: content,
)
```

> 例外：表格、看板（Kanban）这类"信息密度型"页面可放宽到 1920 dp，但需在页面文档注明。

### 3.4 文字选择与复制（全端基线）

> 🚨 **关键文字必须可选中、可复制。** Flutter 的 `Text` 默认**不可选**（全平台都是，不是 Web 特例）——不处理的话，用户在任何页面都拖选不了文字、Ctrl+C 也没用。

> ⚠️ **不要在 ShellRoute 里全局包 `SelectionArea`。** 早期曾在 `ShellRoute.builder` 套全局 `SelectionArea(child: MainShellPage(...))`，但 Flutter 3.44.2 的 `SelectableRegionState._flushInactiveSelections` 在 **web 端动态内容重建（徽章/通知轮询、表格刷新）与拖选并发**时抛 `ConcurrentModificationError`，崩掉整个调度帧（表现为"点了没反应"）。已于 2026-07-30 下线全局包裹（`app_router.dart` 有注释存档）。**全局包 = 重蹈覆辙**。

**现行实现（局部 `SelectionArea`）**：在"需要复制的内容区"就地包一层局部 `SelectionArea`，每个 region 的 registrar 只持当前页内容的 selectable；外壳轮询（徽章/通知）在该 region 之外，其重建不触本 registrar，故不触发 CME。

落地位置：

1. **所有表格**：`MasterDataTableView` 的表体内部包 `SelectionArea`（`_buildTable` 把 `_BodyFlex` 的 `LayoutBuilder` 子树包住，**表头不进**——表头另有"按住拖拽隐藏列"手势，二者隔离）。一处改、54 张表（主档/报表/单据列表/明细只读表）全获跨格框选 + 复制。行加稳定 `ValueKey`（有 `idOf` 用 id）进一步降 Selectable 抖动。**例外**：`selectable:true` 的多选表（任务工作台）不包——勾选场景不需要文本复制，且规避勾选与拖选并发风险（`_maybeSelectionArea`）。
2. **静态详情页正文**：`notice_detail_page` / `employee_detail_page` / `suggestion_detail_page` 整正文包局部 `SelectionArea`；`sales/purchase/finance/subcontract/stock_doc_detail_page` 只包**表头信息卡**（内嵌明细表用其自身 region，不嵌套重叠）。
3. 登录/入口/访客等 ShellRoute 外路由若需要，各自 `GoRoute.builder` 里同样包局部 `SelectionArea`（**不要**为此新增顶层 `ShellRoute`）。

> 手势共存（已测）：
> - **点行导航不被抢**：`SelectionArea` 的 mouse `TapAndPanGestureRecognizer` 纯点按不主动赢竞技场，命中分发"最深优先"+ `InkWell` 更早 `resolve(accepted)` → 行 `onRowTap` 正常触发、`Checkbox` 正常勾选（`master_data_table_view_selection_test.dart` 锁定）。
> - 拖选（鼠标拖 / 手机长按）与点按（导航）天然区分，不互斥。
> - 表头"按住纵向拖→隐藏列"手势在表头（SelectionArea 之外），与表体选择无冲突。

> 已知限制：
> - `Text(overflow: ellipsis)` 截断的单元格，拖选只能复制**可见前缀**（不是完整值）。需要完整值时拖宽该列再选复制，或用导出。
> - 大表/自轮询表若实测仍触发 CME，给该表加 `enableTextSelection=false`（待增 opt-out）回退；届时可用"行长按→复制单元格"等替代入口。
> - 极少数自定义 `CustomPaint` / `TextSpan` 富文本 / 自定义手势控件选不动，**就地**用 `SelectableText` 或 `SelectionContainer` 单独处理，不要为此动局部 `SelectionArea`。

## 四、实现方式：LayoutBuilder + Breakpoint 枚举

### 4.1 ❌ 禁止：MediaQuery 散落判断

```dart
// ❌ 反例：到处散落 MediaQuery
final width = MediaQuery.of(context).size.width;
if (width < 600) {
  return const MobileLayout();
} else if (width < 840) {
  return const MediumLayout();
} else {
  return const WideLayout();
}
```

问题：

- `MediaQuery.of(context).size` 取的是**屏幕**尺寸，不是父容器；嵌套布局（SplitView、Dialog、多窗）里完全错位。
- 同一阈值 600 在多处硬编码，改一处忘一处。
- Web 上窗口缩放频繁，散落判断难以维护。

### 4.2 ✅ 正确：LayoutBuilder + Breakpoint 枚举

#### 4.2.1 Breakpoint 枚举定义

放在 `lib/core/responsive/breakpoint.dart`：

```dart
/// 响应式断点档位。
///
/// 与 Material 3 WindowSizeClass 对齐：
/// - compact  < 600 dp   手机竖屏
/// - medium   600–840 dp 手机横屏、小平板
/// - expanded > 840 dp   平板、桌面、Web
enum Breakpoint {
  compact,
  medium,
  expanded;

  /// 根据宽度推导档位。
  static Breakpoint ofWidth(double width) {
    if (width < 600) return Breakpoint.compact;
    if (width <= 840) return Breakpoint.medium;
    return Breakpoint.expanded;
  }

  /// 便捷判断。
  bool get isCompact => this == Breakpoint.compact;
  bool get isMedium => this == Breakpoint.medium;
  bool get isExpanded => this == Breakpoint.expanded;

  /// 是否进入"宽屏"区间（medium 及以上）。
  bool get isWide => this != Breakpoint.compact;
}
```

#### 4.2.2 扩展方法 `context.breakpoint`

放在 `lib/core/responsive/breakpoint_extension.dart`：

```dart
import 'package:flutter/material.dart';
import 'breakpoint.dart';

/// 响应式便捷扩展。
extension BreakpointContext on BuildContext {
  /// 当前屏幕宽度对应的断点。
  ///
  /// 仅在"屏幕级"布局（如根 Shell、导航容器）使用；
  /// 组件内部应根据父容器判断，见 [03-自适应布局组件.md]。
  Breakpoint get breakpoint {
    final width = MediaQuery.sizeOf(this).width;
    return Breakpoint.ofWidth(width);
  }
}
```

> ⚠️ 注意：`context.breakpoint` 取的是**屏幕**宽度，适合根布局用。**组件内部**应使用 `LayoutBuilder` 拿父容器约束，详见 [03-自适应布局组件.md](03-自适应布局组件.md)。

#### 4.2.3 用 LayoutBuilder 写页面级布局

```dart
class DashboardPage extends StatelessWidget {
  const DashboardPage({super.key});

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        final bp = Breakpoint.ofWidth(constraints.maxWidth);

        // 最大内容宽度限制 + 居中（expanded 档生效）
        return Center(
          child: ConstrainedBox(
            constraints: const BoxConstraints(maxWidth: 1600),
            child: switch (bp) {
              Breakpoint.compact => const _DashboardSingleColumn(),
              Breakpoint.medium => const _DashboardTwoColumn(),
              Breakpoint.expanded => const _DashboardFourColumn(),
            },
          ),
        );
      },
    );
  }
}
```

#### 4.2.4 导航外壳

> 现行实现：外壳 `MainShellPage` 按 `context.breakpoint.isCompact` 分两支，四主 Tab 共用
> `UtenSlidingTabView` 承载且**全部常驻保活**；进入业务子页面（路由不是任一主 Tab 根，
> 即 `tabIndex == null`）时，滑动容器仅以 `Offstage` 隐藏、子页面叠在上层，故从子页返回
> 各 Tab 的滚动位置/状态不丢。**以 `lib/features/shell/pages/main_shell_page.dart` 实际代码为准。**

**compact（<600dp）—— 底部悬浮胶囊 + 滑动容器：**

```dart
// 概念结构（以 main_shell_page.dart 实际代码为准）
Scaffold(
  resizeToAvoidBottomInset: false,          // 键盘不顶胶囊、不压缩页面
  body: Stack(
    children: [
      Positioned.fill(
        child: SafeArea(
          bottom: false,
          child: Stack(
            children: [
              // 四主 Tab：常驻保活；compact 播左右滑动转场 + 可横滑切相邻 Tab
              Positioned.fill(
                child: Offstage(
                  offstage: tabIndex == null,    // 业务子页面时隐藏，不移除（保活）
                  child: UtenSlidingTabView(
                    index: tabIndex,
                    animated: true,              // compact：横滑转场
                    swipeEnabled: true,          // compact：触屏横滑切页
                    children: const [Dashboard, Notice, Profile, Settings],
                  ),
                ),
              ),
              // 业务子页面叠上层（底部预留胶囊高度防遮挡底栏按钮）
              if (tabIndex == null)
                Positioned.fill(
                  child: Padding(
                    padding: EdgeInsets.only(bottom: navReserve),
                    child: child,
                  ),
                ),
            ],
          ),
        ),
      ),
      // 胶囊 overlay 悬浮，不占布局空间
      Positioned(
        left: 0, right: 0, bottom: 6,
        child: SafeArea(top: false, child: FloatingCapsuleNavBar(...)),
      ),
    ],
  ),
)
```

**medium+（≥600dp）—— 左侧 Rail + 内容居中收敛：**

```dart
// 概念结构（以 main_shell_page.dart 实际代码为准）
Scaffold(
  resizeToAvoidBottomInset: false,
  body: SafeArea(
    bottom: false,
    child: Row(
      children: [
        UtenSideNavRail(
          extended: screenWidth >= 1280,        // ≥1280dp 常驻标签，否则纯图标 + Tooltip
          selectedIndex: tabIndex ?? capsuleIndex(location),
          onTap: (i) => context.go(tabLocations[i]),
        ),
        Expanded(
          // 超宽屏内容居中收敛（maxWidth 1600 + 响应式 gutter）
          child: UtenContentContainer(
            child: Stack(
              children: [
                Positioned.fill(
                  child: Offstage(
                    offstage: tabIndex == null,
                    child: UtenSlidingTabView(
                      index: tabIndex,
                      animated: false,           // medium+：即时切换，不整页横移
                      swipeEnabled: false,       // medium+：不开横滑手势
                      children: const [Dashboard, Notice, Profile, Settings],
                    ),
                  ),
                ),
                if (tabIndex == null)
                  Positioned.fill(child: child),   // 业务子页面叠上层
              ],
            ),
          ),
        ),
      ],
    ),
  ),
)
```

要点：

- `tabIndex`：当前路由恰好等于某主 Tab 根 → 该页码；否则 `null`（业务子页面）。
- 两支共用同一个 `_slidingTabs(...)` 构造，仅 `animated` / `swipeEnabled` 随断点切换（见 §3.1.1）。
- 四页用 `_KeepAlivePage`（`AutomaticKeepAliveClientMixin`）保活，切回 Tab 不回顶。
- 最外层包 `IdleTimeoutGuard`（空闲超时登出），与布局无关。

## 五、禁忌清单

> ❌ 以下写法在 PR Review 中**直接打回**：

| 反例 | 问题 | 正确做法 |
|---|---|---|
| `MediaQuery.of(context).size.width < 600` 散落多处 | 取屏幕而非容器，难维护 | 用 `LayoutBuilder` 或 `context.breakpoint` |
| `SizedBox(width: 400)` 写死 | 窄屏溢出、宽屏空洞 | 用 `Expanded`/`Flexible`/`FractionallySizedBox` |
| `if (Platform.isAndroid) ...` 写两套 UI | 违背"一套代码多端"原则 | 用断点切布局，不按平台切 |
| 每个页面自己写一遍 600/840 阈值 | 数字四处分散 | 走 `Breakpoint` 枚举，单一数据源 |
| 长文本/表单在超宽屏拉伸到难读 | 阅读体验差 | 具体**内容**按需 `ConstrainedBox(maxWidth: …)`（UI v4 外壳全屏宽，收束由页面内容自定） |
| 用 `OrientationBuilder` 区分横竖屏做布局 | 横屏手机 ≠ 平板 | 用宽度断点，不用方向 |

## 六、测试要求

### 6.1 必测的三档尺寸

每个页面、每个组件必须在以下三档逻辑尺寸下截图自测：

| 档位 | 测试尺寸（dp） | 备注 |
|---|---|---|
| compact | 360 × 640 | 最小手机 |
| compact（大） | 414 × 896 | iPhone 标准 |
| medium | 720 × 1024 | 手机横屏 / 小平板 |
| expanded | 1280 × 800 | 平板 / 小桌面 |
| expanded（宽） | 1920 × 1080 | 桌面 / Web |

### 6.2 Flutter 测试中模拟不同尺寸

**旧 API（仍可用，兼容性好）**：

```dart
testWidgets('Dashboard 在 compact 下显示单列', (tester) async {
  // 设定逻辑尺寸 360×640
  tester.binding.window.physicalSizeTestValue = const Size(720, 1280);
  tester.binding.window.devicePixelRatioTestValue = 2.0;
  addTearDown(tester.binding.window.clearPhysicalSizeTestValue);

  await tester.pumpWidget(const MaterialApp(home: DashboardPage()));
  await tester.pumpAndSettle();

  expect(find.byType(_DashboardSingleColumn), findsOneWidget);
  expect(find.byType(_DashboardFourColumn), findsNothing);
});
```

**新 API（Flutter 3.10+，推荐，多 View 场景更准确）**：

```dart
testWidgets('Dashboard 在 expanded 下显示四列', (tester) async {
  // 通过 View.of 注入自定义 View
  final view = tester.platformDispatcher.views.first;
  view.physicalSize = const Size(2560, 1600); // 1280×800 @ DPR 2.0
  view.devicePixelRatio = 2.0;
  addTearDown(view.resetPhysicalSize);
  addTearDown(view.resetDevicePixelRatio);

  await tester.pumpWidget(const MaterialApp(home: DashboardPage()));
  await tester.pumpAndSettle();

  expect(find.byType(_DashboardFourColumn), findsOneWidget);
});
```

> 💡 提示：项目里建议封装一个 `pumpWidgetWithSize(tester, widget, size)` 工具，避免每个测试都重复设置与 teardown。

### 6.3 黄金图测试（Golden Test）

对核心页面（登录、工作台、列表、详情）的每个断点都生成 golden 图，CI 上回归。命令：

```bash
flutter test --update-goldens
```

## 七、对照清单（每次开发前自检）

- [ ] 在 **compact（< 600 dp）**、**medium（600–840 dp）**、**expanded（> 840 dp）** 三档下都测过布局
- [ ] 用 `LayoutBuilder` 或 Uten 响应式组件，**不写死** `width` / `height` 数字
- [ ] 用 `Breakpoint` 枚举，不在多处硬编码 `600` / `840`
- [ ] 导航按断点分化：compact 底部悬浮胶囊 / medium+ 左侧 Rail（见 [App外壳](../03-页面/App外壳.md)）
- [ ] 主 Tab 转场：compact 用左右滑动转场、medium+ 用即时切换（不在大屏整页横移，见 §3.1.1）
- [ ] 关键文字可选可复制：表格靠 `MasterDataTableView` 表体局部 `SelectionArea`（54 表全覆盖）、详情页正文就地包局部 `SelectionArea`；**勿在 ShellRoute 全局包**（CME 崩溃，见 §3.4）
- [ ] expanded 档内容区有 `ConstrainedBox(maxWidth: 1600)` + `Center`
- [ ] 列表/卡片列数由 `UtenResponsiveGrid` 按**容器宽度**自动算（compact 1 列、medium 2 列、expanded 3–5 列），桌面端注意用容器宽度而非屏幕宽度
- [ ] 没有用 `Platform.isXxx` 切 UI
- [ ] 没有用 `OrientationBuilder` 决定主布局
- [ ] 已为该页面在三档下生成截图 / golden test
- [ ] 组件内部布局用 `LayoutBuilder`（参考 [03-自适应布局组件.md](03-自适应布局组件.md)）
