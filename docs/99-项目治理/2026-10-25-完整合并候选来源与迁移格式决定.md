## 来源过滤必须保留并发事实与 SQL 分组语义

联合真实业务回归发现，静态来源子查询不导出 PostgreSQL 的 `xmin` 系统列，也不能继承基表主键的函数依赖。
因此并发依赖发现和指纹读取继续访问完整基表事实，不能因为记录归档而漏掉锁计划或行版本变化。
业务可写候选在基表别名的 WHERE 中保留完整来源谓词及原锁；已存在的历史报工仍然是阻止修改比例的真实事实。
采购需求的幂等摘要明确按 `id,bill_no` 分组，保持原主键粒度及历史过滤，不依赖派生表无法提供的主键推断。
保留失败 SQL 作为负控，并使用真实归档依赖变化和归档报工回归检验这两类边界；不关闭守卫或省略原断言。

来源守卫的参数必须是实际单条记录。委外明细集合与日报补充凭据 UUID 集合不能作为明细实体传入；
日报从已校验的真实明细推导凭据集合，保留既有凭据不可移除或替换的规则。
不良品移仓的 Optional 先按原幂等流程解包，实体保护继续保留；没有将反射 helper 改为静默接受任意容器。
这些原生业务路径以合法编辑、历史子行拒绝、原像保全和首次请求/幂等重放作真实回归。

归档提示还必须位于既有对象范围与父子身份核验之后。销售优先级/让单、其它收入红冲及采购申请明细改量
保留原锁前缀，先按原 scope 或父子归属拒绝外部标识，再判断来源；不能用不同错误提前泄露外部记录是否归档。
真实 public 方法体的 native/archived 外部标识对照共六项通过；相同断言在冻结的修复前类上，三个归档对照均复现失败。
这些是服务层顺序回归，不代替 HTTP/AOP 授权或真实数据库锁验收。
