# UtenHierarchySearch · 层级树与内容统一关联搜索

> 适用范围：页面或选择器同时包含“左侧分类/部门树 + 右侧具体内容”时，一个搜索入口同时查层级和内容。货品及往来主档搜索在右侧统一列出授权结果，左树只提示命中路径。
>
> 源码所有者：[`category_tree_search.dart`](../../lib/features/basic_data/widgets/category_tree_search.dart)、[`uten_category_tree_view.dart`](../../lib/features/basic_data/widgets/uten_category_tree_view.dart)、[`uten_department_tree_view.dart`](../../lib/features/department/widgets/uten_department_tree_view.dart)。最后核对：2026-10-16。

---

## 一、统一交互契约

1. **一个搜索框**：放在左树顶部；同时匹配层级名称/编号和右侧具体内容的业务搜索字段。不得再让用户猜“左框只搜分类、右框才搜内容”。
2. **完整定位集合**：内容命中必须收集全部结果页的 `categoryId` / `departmentId`，或调用只返回去重分类 ID 的轻量定位端点；不能只用当前 50/100 条推断分类。
3. **授权树内失败关闭**：服务端定位与右侧列表使用同一权限、scope 和状态口径；客户端仍丢弃空 ID、已删除节点和当前树之外的 ID。
4. **树提示与浏览位置**：合并“层级自身命中 + 内容所属节点”，补齐祖先路径并展开。货品、模具、客户、供应商、库存、应收应付的搜索不能自动选中一个分类并截断右表；保存原浏览分类，清空词后恢复。树提示失败不能阻断独立的全局结果请求。
5. **右侧语义**：
   - 货品、模具、客户、供应商、库存、应收应付：右侧使用同一关键词，不带浏览分类限制，按服务端相关性统一分页；不按分类分组。既定业务根、owner、仓库、状态、日期与财务权限继续约束结果。
   - 分类名称/编号命中：其子树内容与主档字段命中取并集，参与同一结果集和排序，不删除关键词后另发分类浏览请求。
   - 部门管理及员工层级工作流保留部门上下文，不能把全局主档搜索机械套用于只授权某部门分支的花名册。
   - 客户、模具、供应商在 V272 候选之后把未分类主档绑定到真实、受保护的系统根；命中时必须像普通分类一样补祖先、展开并选中该根。
   - 只有尚未建立真实节点的数据域，或滚动升级/脏数据仍返回空 ID、树外 ID 且右侧支持全局查询时，树才可以没有可展开节点，右侧保留同一授权范围内的全局关键词结果；不得伪造无效选中。
6. **搜索态导航**：主档/库存/应收应付搜索期间点左树不缩窄右侧搜索结果；清空词后恢复普通分类浏览。部门与结构化BOM按自身业务上下文保留祖先，不能把结构节点当普通平表重排。
7. **异步状态完整**：300ms 防抖；输入一变化即让旧请求失效；加载、失败、无结果都在树附近显式反馈，错误使用可访问 live region，禁止静默吞错或让旧响应覆盖新关键词。
8. **响应式不降级**：expanded 在固定左栏内显示统一搜索；compact/medium 的树进入抽屉或自适应面板时，仍必须提供同一搜索入口、相同字段与相同状态语义。
9. **分类名称展示**：分类树正文只显示业务名称；系统分类编号保留为排序、搜索和溯源字段，不拼进名称、不改分类 ID。
10. **多词检索**：分类树及货品、模具、客户、供应商主档、即时库存以空格（含全角空格）分词，每个词都必须命中，但可分别命中不同字段。例如“螺丝 M3”可分别命中名称与型号。`%`、`_` 和反斜杠按普通字符搜索，不作为 SQL 通配符。即时库存继续使用其既有的名称/编号/型号/客户型号字段，列表、计数、合计、表头 facet 与轻量分类定位复用同一检索条件。
11. **定位未完成时的选择**：货品、客户、供应商选择器的分类定位只作提示，不能把右侧请求改成某分类下的无关键词浏览。输入一变化即让旧防抖与旧响应失效。
12. **分类与货品联合查询**：四类主档与即时库存的服务端关键词条件同时包含分类名称/编号及其完整子树。即使其他货品的备注也命中，分类下名称、编号不含关键词的货品仍须参与同一结果集、总数和分页，禁止只在货品结果完全为空时才补分类货品。
13. **名称优先，相关性先于分页**：主档名称的精确、前缀、短语包含、多词匹配依次在前；其次为编号，再次为型号/规格等主要资料，分类关联、备注/包装等间接命中在后。同档使用原排序及稳定 ID。服务端先排序再分页；客户端不拿当前页重排冒充全结果相关性。仓库/研发任务也优先其真实货品名称，不把拼接后的多个明细名称误认成一个名称精确命中。
14. **跨分类根与特殊候选**：货品超过32个分类根时，服务端返回的 `searchRank` 随各批完整结果一起保留，合并去重后按相关性、原排序、ID再分页。盘点候选使用独立的仓库/颜色/单位/占位过滤，分类联合只能与这些限制取交集；盘点列表仍搜索不可变的明细快照。
15. **定位接口同一排名**：轻量分类定位按分类分组，再按命中内容的 `MIN(rank)` 与稳定分类 ID 排序；客户端保留顺序作树提示，不据此改写右侧全局搜索范围。
16. **全局表头筛选**：四类主档的 `/facets` 省略 `categoryId` 时返回同一授权范围的全域桶；指定分类时仍限定其子树。全局搜索不能复用上一分类的桶，也不能只从当前页凑桶；客户桶和空值计数继续使用同一 owner/共享权限和历史 stub 排除规则。

界面修改默认使用 `frontend-design`，沿用项目现有组件、主题、紧凑表格与正常表单尺寸约束；不引入另一套视觉体系。

## 二、共享实现

| 能力 | 实现 |
|---|---|
| 层级名称/编号匹配 | `categoryHits`、`matchesKeywordSearch`，统一多词 AND 与小写匹配，命中节点包含祖先；层级自身命中时保留其子树 |
| 内容分类解析 | `resolveHierarchySearch`，过滤树外/空 ID、补祖先、选择首个有效内容分类 |
| 完整分页定位 | `collectPagedHierarchyCategoryIds`，复用首屏、逐页收集、每页前后检查请求代次 |
| 搜索态点树分支 | `hierarchyBranchContainsAny`，判断该分支是否包含内容命中并决定是否保留关键词 |
| 分类树受控状态 | `visibleFilterIds + externalSearchQuery + externalSearchLoading + externalSearchError` |
| 部门树受控状态 | 与分类树同名参数；内部纯节点搜索也匹配部门名称/编号且忽略大小写 |

树组件只负责渲染受控状态，不调用业务 API。页面/选择器负责选择正确的数据源、权限与业务字段；不得把货品、客户或员工仓库直接塞入共享树组件。

## 三、已接入场景与搜索口径

| 场景 | 层级字段 | 内容字段与定位方式 | 右侧结果 |
|---|---|---|---|
| 货品资料 `/basicinfo/goods` | 分类名称/编号 | 货品名称、编号、型号、规格、系列、客户型号、材质、备注；`GET /api/master/goods/search-category-ids` | 授权范围跨分类统一分页；包含禁用品、排除历史 stub |
| 模具资料 `/basicinfo/mould` | 分类名称/编号 | 模具名称、编号、制造商、存放位置、备注；分页完整收集 `categoryId` | 授权范围跨分类统一分页 |
| 客户资料 `/basicinfo/client` | 分类名称/编号 | 客户名称、编号、全称、联系人、手机；分页完整收集 `categoryId` | owner/共享可见范围内跨分类统一分页 |
| 供应商资料 `/basicinfo/supplier` | 分类名称/编号 | 供应商编号、名称、描述、联系人、法人、地区、手机；分页完整收集 `categoryId` | 授权范围跨分类统一分页 |
| 部门管理 `/department` | 部门名称/编号 | 员工姓名、工号（员工接口还支持车牌）；分页完整收集 `departmentId` | 当前部门子树 + 同一员工关键词 |
| 我的部门 `/profile/me/department` | 授权分支内部门名称/编号 | 安全花名册姓名、工号；只读取分支根花名册一次并本地定位 | 当前部门子树 + 同一员工关键词；绝不调用全员员工接口 |
| 应收应付总览 `/finance/report/overview` | 客户/供应商分类名称、编号 | 往来单位名称、编号；分页读取 `GET /api/finance/reports/ar-ap/party-locations` | 搜索不带浏览分类/type限制，保留日期、显示模式及公司级财务权限 |
| `UtenGoodsPicker` | 当前 scope 内分类名称/编号 | scope 内货品字段；受限分页 + 轻量分类 ID 定位 | 业务允许的根内跨分类统一分页，树点击不截断搜索 |
| `UtenClientPicker` | 客户分类名称/编号 | 客户字段；分页完整收集 `categoryId` | owner/共享范围内跨分类统一分页 |
| `DepartmentEmployeePicker` | 部门名称/编号 | 员工姓名/工号；分页完整定位 | 跨部门分页结果，或相关部门子树 + 同词过滤 |

即时库存搜索同样跨浏览分类统一分页，保留仓库/颜色/单位/库存口径等业务限制。

货品定位端点每次最多接受 32 个 `categoryRootIds`；页面根数超过上限时按 32 个一组取并集。无效根必须零命中，不能退化成全库。`UtenGoodsPicker` 还会校验右侧每条结果的 `categoryId` 属于当前可见树，避免旧服务端忽略 scope 时越界展示。

## 四、权限与数据范围

- 货品定位要求 `goods:view`；`GoodsService` 的 owner 隔离仅在 `UTEN_GOODS_OWNER_SCOPE_ENABLED=true` 时启用，默认关闭。货品资料页仅排除 stub，选择器同时排除禁用和 stub；货品/库存分类树还分别需要页面组合中的 `material_category:view`。
- 模具、客户、供应商资料沿用各自主档查看权限；客户结果继续受 owner 可见范围约束。
- 部门管理的树/员工列表分别使用 `department:view`、`employee:view`；没有 `employee:view` 时统一框只搜部门节点，不发员工请求。员工选择器专用最小树 `GET /api/org/departments/employee-picker-tree` 只要求 `employee:view`，仅返回定位字段，不扩大部门管理权限。
- “我的部门”只使用 `/api/my-department/tree` 与 `/api/my-department/roster`，服务端限制在本人所在大部门分支，并只返回安全花名册字段。
- 应收应付分类定位要求 `finance_report:view`，服务层与公司级总览一致继续要求 `finance:view:all`；不能借用受客户 owner 范围裁剪的主档搜索。

## 五、明确不适用的页面

- 收付款类别：纯类别目录 + 类别属性检查器，没有“分类下具体主档列表”。
- 分类/部门编辑弹窗、`UtenDepartmentPicker`：只选择层级节点，名称/编号节点搜索即可。
- 权限管理：左侧是账号结果列表、右侧是单账号详情，不存在分类反向定位；未保存权限还要求独立离开保护。

不能因为页面也有左右栏，就机械套用本契约。判定标准是“左侧为层级树，右侧为归属于该层级的具体内容”。

## 六、回归验收

- 用层级名称、层级编号、内容名称、内容编号分别搜索；英文编号大小写混输。
- 构造同词命中多个深层分类且超过一页内容，确认全部祖先路径可见，翻右侧页不丢已定位分类。
- 搜索后点击不同树分支，确认右表不被某分类截断；清空后恢复搜索前浏览位置。
- 人为延迟旧请求，确认新关键词结果不被覆盖；模拟定位接口失败，确认错误可见且右侧不偷偷切全量。
- 在 300ms 防抖期间及分类定位请求返回前点分类，确认列表仍带当前词、跨分类查询，旧防抖/响应不会覆盖新词或浏览恢复点。
- 用名称与型号/编号的组合词检索，确认少一个词的无关条目被排除；包含 `%`、`_` 的编号按字面匹配。
- 分别验证 expanded 与 compact/medium；树空、无结果、未分类内容、树外 ID、禁用/stub 与权限不足。
