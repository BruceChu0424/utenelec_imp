# 重新提交审批的差异展示

更新时间：2026-09-23

## 统一显示规则

- 修改场景顶部醒目标明具体业务，例如“销售订单修改”“采购订单修改”“报销单修改”，单号、状态、金额作为次级审核重点；首次提交不误标为修改。表头字段有修改时显示紧凑的旧值/新值。
- 商品或费用明细沿原顺序展示。未修改行保持普通样式；修改前的完整行用红底、红字与贯穿整行的横线；下一行完整展示绿色的新内容，即使只修改数量或金额也如此。
- 删除行只保留红色划线行；新增行绿色显示。每行另有“未修改 / 修改前 / 修改后 / 已删除 / 新增”及正负标记，不能仅靠颜色区分。
- 成对修改的新行保持绿色背景和普通字段绿字，实际改变的单元格用红色加粗文字；仅数量变化时突出新数量及随之变化的金额，复制过来的名称、编号等保持绿色。纯新增行没有旧值，不把所有字段误标为修改。
- 修改比较使用历史快照的真实值；不能用当前资料拼造旧数量、金额或旧票面要素。合计只计算本次明细，不能把旧行与新行相加。
- 自动重排行号不属于业务修改。精确十进制只统一多余末尾零，不经 double 比较；客户单号、票号等标识保留前导零。
- 共用 `UtenRevisionTable` 与 `UtenRevisionFields`；保留普通表格的横向滚动、整屏查看、复制与吸顶能力。

| 财务销售订单审核 `finance_sales_order_review_page.dart` | 审批通过后修订或改量产生待复审内容；旧、新订单明细在主表逐行对比。 |
| 财务采购 / 委外审批 `finance_procurement_approval_review_page.dart` | 采购与委外各自提交及修订审批，逐一使用对应业务快照，在原表内显示旧、新完整行。 |
| 出货财务审核 `finance_sales_shipment_audit_review_page.dart` | `previousCommercialSnapshot` 与 `commercialSnapshot` 按稳定出货行 UUID 比对。顶部不再逐字段复述商品变化，主表展示完整旧、新行。非关键收货及制单资料收进展开区。 |
| 人事信息变更详情 `hr_profile_change_detail_page.dart` | 每个申请字段本身已有冻结的 `oldValue/newValue`；共用 `ProfileChangeDiffRow` 改成上红划线、下绿，并完整换行显示长地址。 |

| 报销审批详情 `expense_approval_detail_page.dart` | 拒绝或撤回修订后重新提交时，对比上次提交与本次提交的费用明细和发票登记。核验按钮仍针对本次发票，旧票面记录不接受操作。 |

| 仓库到货异常财务处理与仓库复审 | 财务调整实收数量后，原收货草稿回仓库重审；`finance_arrival_exception_pages.dart` 财务详情和决定确认、`warehouse_arrival_exceptions_view.dart` 仓库异常详情共用 `ArrivalQtyRevisionTable`。详见[逐页验收](../99-项目治理/2026-09-23-到货异常改量复审逐页验收.md)。 |

| 访客审批 `visitor_approval_detail_page.dart` | `VisitorApplicationService.submit` 新建申请；拒绝后的下一次申请是新记录，不把新申请与旧申请随意配对。 |
| 生产日报详情 `production_daily_report_detail_page.dart` | 已审只允许红冲 1→-1，旧日报不可回到草稿修改；不套用订单修订显示。 |
| 通用仓库单据 `stock_doc_detail_page.dart` | `StockDocService.update` 仅允许 STATUS_DRAFT；审批及红冲保留原单业务事实。 |
| 生产余料退仓 `production_material_settlement_sheet.dart` | `ProductionMaterialReturnRequestService` 撤回写独立取消记录，再提交创建新的 StockDocument；保留原申请，不伪装为同一单据新版本。 |
| 品质批量审批 `quality_batch_approval_page.dart` | 提交之前是本地录入；提交之后固定 `QualityBatchSubmission` 做幂等重试。后续检验是新事实，不把网络重试或新检验当成修改复审。 |
| 销售报价、退货详情 `sales_doc_detail_page.dart` | 分别核对 `SalesQuoteService` 与 `SalesReturnService`：update 仅草稿，approve 后只能 reverse 到终态，无退回原单修改重审。历史其它出货的 create/update/approve 已停用，客户零星发货走已覆盖的统一出货财审。 |
| 研发任务 `rd_task_page.dart` | 核对仓库接口与 `RdTaskService.resolve`：OPEN/IN_PROGRESS 标记 DONE，关联货品 BOM 维护不产生研发任务的审批重提版本。 |
| 建议箱 `suggestion_detail_page.dart` | `SuggestionService.submit` 新建建议，reply 追加回复并推进处理状态，无原建议编辑后再提交审批接口。 |
| 官网询盘 `website_inquiry_detail_page.dart` | `WebsiteInquiryService` 只跟进状态、指派及转客户，不存在询盘修改后再审批的前后版本。 |
| 附件对账清理 | `AttachmentReconciliationApprovalTransaction` 只对 OBSERVED 发现审批进入 QUEUED；没有修改发现内容后重提的单据流程。 |

## 财务、人事及其它入口的补充逐页核查

| 页面 / 业务类型 | 页面动作与服务端实际状态机 | 本次处理 |
|---|---|---|
| `FinanceDocDetailPage` 销售收款（含客户预收） | `FinanceReceiptService.update` 只接受草稿；审核 0→1，红冲 1→-1，原单不回草稿。 | 保留审核/红冲事实，不将不同收款拼成修订对比。 |
| 同页采购付款 | `FinancePaymentService.update` 只接受草稿并校验版本；已审只能红冲终态。 | 无修改后重提入口。 |
| 同页一般费用 | `FinanceExpenseService.update` 只接受草稿；已审写资金流水后只允许追加红冲事实。 | 与员工报销重提区分；普通费用单无同单复审。 |
| 同页其它收入 | `FinanceOtherIncomeService.update/approve/reverse` 分别限草稿/草稿/已审，红冲置 -1。 | 无同单重提入口。 |
| 同页银行存取款 | `FinanceBankTransferService` 同样限草稿编辑，审核后只可红冲。 | 无同单重提入口。 |
| 固定资产工作台详情 `FinanceAssetDetailSurface` | `FinanceAssetWorkflowService.reject` 待审批→草稿，`updateFixed` 后可 `submit` 同一资产。 | 补初始确认审批的真实提交旧、新对比，金额/月数等修改值粗红。 |
| 待摊费用工作台详情（同组件独立账簿） | `updateDeferred/reject/submit` 允许同一待摊项目退回后修改重提。 | 同规则对比；“摊销月数”“负责人”等标签按账簿显示。 |
| 固定资产处置申请 | `requestDisposal` 将 ACTIVE→DISPOSAL_PENDING；`rejectDisposal` 回 ACTIVE 后可再次申请。 | 单独按 DISPOSAL 请求事件配对日期、收入、凭证依据、原因，不混到初始确认快照。 |
| 待摊费用终止申请 | `requestTermination`→TERMINATION_PENDING，驳回后恢复原有效状态，可再次申请。 | 单独按 TERMINATION 请求事件对比；不与处置或初始确认交叉配对。 |
| 折旧 / 摊销过账 `FinanceAssetPostingPanel` | `FinanceAssetPostingService.preview` 每次创建不可变新 run；状态 PREVIEWED→SUBMITTED→APPROVED→POSTED，反转创建独立反向 run。 | 没有修改已审 run 后重提，保留批次与反向历史。 |
| 客户预收抵扣面板 | `CustomerPrepaymentApplyPanel` 执行 apply，完成后只能 reverse；未提供修改已完成抵扣再审批。 | 保留原核销与反向事实。 |
| 供应商贷项抵销 | `SupplierOffsetCommandService.apply` 创建新 offset batch；reverse 为独立反向处理。 | 不把两笔独立抵销当旧、新版本。 |
| 应收应付 / 对账单 / 账户流水 / 财务报表 | 各页为读取、筛选、穿透及打印；`FinanceReconciliationController` 仅 GET，流水由已审钱流单写入。 | 报表金额差异不是修订审批，不机械套用红绿删除行。 |
| 账户余额调整 | `AccountBalanceAdjustmentService.adjust` 直接登记有原因的调整事实，不是退回修改审批工作流。 | 保留调整流水审计。 |
| HR 任务中心与转正/生日/周年任务 | `HrTaskService` 按员工档案动态计算待办；页面操作是认领、接管和进入实际员工办理页。 | 无另一份修改后重提详情；档案变更审批已由共用差异行覆盖。 |
| 意见建议详情 | `SuggestionService` 与页面均为 submitted→reviewing→resolved/rejected，未采纳为终态；可追加回复，不回退编辑原建议。 | 不把处理回复当重新提交。 |
| 研发任务中心 | `RdTaskService.resolve` 只将 OPEN/IN_PROGRESS→DONE；已完成/取消终态不编辑重新提交。 | 保留任务完成记录。 |
| 官网询盘详情 | 跟进、关闭、转客户是原询盘的处理状态；转客户后锁定，无审批退回修改原留言入口。 | 保留跟进记录，不伪造审批差异。 |

资产详情使用 `reviewRevisions`，每个工作流仅比较最近两次真实提交业务事件。初始确认快照新增写入既有 append-only `finance_asset_events.payload`，处置/终止沿用原请求 payload 与生效日期/原因，不需要新表。首提不显示旧行；草稿修订阶段不把上次提交数据当当前资料；旧事件未冻结的内容明确提示缺失。资产名称、类别、部门、人员优先使用提交时冻结名称，不从当前主档补造过去。

## 出货快照边界

旧商业快照只有货品 UUID，未冻结货品名称和编号。对比页优先使用快照中存在的名称/编号，否则按当前档案显示并明确提示；数量、单价、金额、备注等仍严格使用提交时的快照。删除货品也会预加载名称，避免只显示无法识别的编号。

货品相同的多行不合并；订单来源发生变化但旧快照缺少可读来源单号时，明确显示原来源与“来源订单已更换”，不能展示两条看似完全一样的行。

## 报销快照与配对

V689 增加上次/本次提交快照，DTO 字段为 `previousSubmissionSnapshot`、`submissionSnapshot`、`resubmission`。快照冻结标题、备注、合计、完整费用明细及完整票面登记要素，金额保留精确字符串。

费用明细在保存时会重建 UUID，因此前端先按完整商业内容做多重集匹配，保持未变化的重复行中性；只有“科目、日期、说明”在剩余两侧都唯一时，才把金额修改配成旧、新行。无法唯一判断的重复行显示删除和新增，不猜测对应关系。发票行使用稳定 UUID；查验状态与核验人是本次审核结果，不混入历史票面差异。

旧报销单没有历史快照时，显示“上次提交内容未留存或暂不可读，以下显示当前内容”。不从事件类型或当前项目倒推旧内容。首次提交没有上版快照时继续普通明细表，不将所有行标为新增。
