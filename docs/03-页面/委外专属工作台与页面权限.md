## 一、页面目标与不可跨越的职责

委外页面必须让员工在一个稳定入口看清以下链路，但不能把不同岗位的执行动作揉成一张通用采购页：

```text
直接委外下单 ───────────────────────────────┐
                                             ├→ 委外订货 → 财务审核
物料分析 SUBCONTRACT（无子层）→ 只读申请 → 申请分解 ┘    │
                                                    ├─ 无子层级：目标件待出仓
                                                    └─ 有子层级（直下单，ADR-064）：
                                                       按全局可用量拆行——现货直发
                                                       （DIRECT 行，通知仓库出仓）
                                                       + 缺口前置自制（SHORTAGE 通知计划部）
                                                           ↓
物料分析 SUBCONTRACT（有子层，V458）：先在原分析内前置自制
    → 成品入库账本 → 满批自动/手动分批通知 → 委外申请 → 分解 → 订货 → 财务批准
    → PREPARED_OUTBOUND 目标件待出仓（预留自任务转入）
                                                           ↓
物料分析 → DRAW 领料 → 生产/报工 → FQC → 仓库实收入仓（直下单缺口行，量=缺口）
                                                           ↓
仓库专属预留 → 目标件出仓 → 加工商加工 → 仓库登记回厂 → IQC
                                                           ↓
PASS 放行库存 / FAIL 处置 → 退回、余料、损耗责任、加工费应付与对账
```

不可妥协的页面边界：

1. Flutter 不读取 BOM 名称、层级显示或本地缓存来判断 `DIRECT_OUTBOUND` / `MAKE_THEN_OUTBOUND`；只展示服务端任务状态、阻断原因和 `allowedActions`。
2. 计划申请是只读需求事实；委外人员不能在申请页新建、编辑、审核或红冲。
3. 财务通过订货只表示商业放行，不表示已出仓、已回厂、IQC 合格或已结案。
4. 前置自制完成、FQC PASS、成品入仓草稿和通知送达都不能代替仓库实收与真实目标件出仓。
5. 回厂新建不再进入通用 `/subcontract/receipts/new` 编辑器；必须从仓库预计到货进入独立登记页，执行先出后进、数量和来源校验。
6. 通知是提醒；任务投影、单据状态、对象范围、库存预留、IQC 与财务台账才是权威事实。

## 二、入口与路由

### 2.1 委外 Hub

- 路由：`/subcontract`。
- 页面按真实 `view` 权限逐卡显隐，不因部门名称、旧默认授权或“超级管理员前端 fallback”恢复动作。
- 信息架构（V458 对齐采购 hub）：任务中心、单据（订货/计划申请/回厂品质/成品退/余料退/损耗）、三类报表、历史兼容（历史 BOM 子件发料，按 `subcontract_material_issue:view` 单独显隐）。全链路教学概览区与流程说教文案已移除；分组语义见各列表页标题与单据详情。
- “待退回供应商”卡使用 `supplier_return_task:view`，不能用 `subcontract_order:view` 代替。

### 2.2 两种业务来源（Hub 不单列入口区）

| 入口 | 路由 | 页面行为 | 写动作门禁 |
|---|---|---|---|
| 直接委外 | `/subcontract/orders/new` | 直接录入待加工目标件、委外商、币种、税率、结算方式、数量和价格 | `subcontract_order:view + create`；提交财务另需 `subcontract_order:submit_finance` |
| 物料分析委外 | `/operations/workbench/subcontract` | 只显示服务端投影的已下达、仍有未下单量的委外申请明细；可跨申请选择、部分分解 | 页面准入 `subcontract_application:view`；选择与“生成委外订货单”同时要求 `subcontract_order:view + create + decompose` 和服务端 capability |

直接委外入口保留在“委外订货与全链路”列表页；物料分析委外入口保留在“委外任务中心”。前置自制专页继续由物料分析节点、通知和稳定深链进入。目标件出仓只在仓库管理 Hub 保留权威入口；`subcontract_outbound:view` 单独授权也能进入仓库根页。删除委外 Hub 重复卡片不删除路由、权限或业务能力。

委外任务中心的“业务阶段”初始值固定为“全部”；用户主动选择后才收窄，不用页面默认阶段隐藏其它待办。

订货编辑页对商业快照的要求：币种必填；税率必须明确填写 `0–100`，`0` 表示明确零税率/免税，
不能用 `null` 让财务或后端猜测；结算方式必填。保存成功后才提交财务，提交失败时保留草稿并明确反馈。

## 三、八类显式业务页面

`SubcontractPageFactory` 按 `SubcontractDocType` 分派到显式 public 页面。各页可共享主数据选择器、
分页表格和底层 DTO，但责任头、动作集合、空态和商业字段权限必须独立。

| 类型 | 路由 | 专属页面定位 | 新建/动作边界 |
|---|---|---|---|
| 询价 `inquiries` | `/subcontract/inquiries` | 未启用的历史询价档案；列表与详情只读 | `/new`、`/:id/edit` 显示受控说明，不恢复旧询价动作 |
| 申请 `applications` | `/subcontract/applications` | 计划/物料分析下达事实登记簿，只读核对来源、数量、日期和状态 | 不能新建/编辑；尚未分解数量去申请分解页处理 |
| 订货 `orders` | `/subcontract/orders` | 两种来源汇合后的商业订货与全链进度 | 可直接新建或从申请分解；详情跟踪财务、准备、目标件出仓、回厂 IQC、退回/损耗和应付 |
| 回厂 `receipts` | `/subcontract/receipts` | 已有回厂单与 IQC 状态的跟踪页 | `/subcontract/receipts/new` 始终失败关闭并引导仓库预计到货；既有草稿按精确权限编辑 |
| 出仓记录 `material-issues` | `/subcontract/material-issues` | V436 目标件出仓执行记录与 `LEGACY_BOM_COMPONENT` 历史兼容 | 现行 Flutter 路由禁止空白新建；V441 候选停用并禁止分配 `subcontract_material_issue:create`，普通调用无权限返回 403，仍携旧权限的过渡调用由旧 POST 返回 409 并引导仓库任务；计划草稿执行在仓库专页，既有合法审核/反向能力不因 create 退役而抹除 |
| 成品退回 `returns` | `/subcontract/returns` | 绑定回厂/IQC 来源的成品退回与应付反向 | 有精确 create 权限时从回厂来源登记；无来源不得保存/审核 |
| 余料退回 `material-returns` | `/subcontract/material-returns` | 按委外商处净结存登记仓库实收并对称核减台账 | 有精确 create 权限时从在外结存登记；不得手输创造结存 |
| 损耗责任 `wastes` | `/subcontract/wastes` | 实物损耗、允许量/超耗量和后续责任入口 | 有精确 create 权限时从在外结存登记；建议索赔金额不是扣款、负应付或会计凭证 |

询价、申请、回厂、历史出仓、成品退回、余料退回和损耗不再通过“同一通用页换标题”表达。
深链仍要经过路由权限与服务端对象门禁；从 Hub 隐藏卡片不等于安全控制。

## 四、前置生产（2026-09-05 ADR-072 收敛：准备中心已退役）

委外不再有「自己分析产品」的入口。有子层目标件统一**先发单给计划**：

- **计划下达委外（物料分析 SUBCONTRACT）**：下达即建前置自制任务（V458 账本），
  车间生产完成自动生成委外申请并通知取货——链路不变。
- **委外直接下单**：草稿保存期系统按全局可用量自动为缺口创建前置生产分析
  （无页面操作），计划部收到居中行动卡（直达物料分析）后在自己的物料分析
  工作台安排车间；草稿编辑按「货品+颜色+数量」迁移既有分析，已排产行改动
  fail-closed；草稿删除随单取消未排产分析。
- **提交财务闸门**：有子层行库存未备齐即拒绝提交（提示等待生产入库）；
  财务批准通过即全部行 READY_OUTBOUND，仓库可立即目标件出仓。
- **进度与通知**：前置生产产出完工入库自动通知委外制单人「可提交财务审核」；
  车间进度权威视图=委外申请登记簿合成行 + 订货单详情全链路进度；
  `/subcontract/preparations` 仅作兼容重定向，`subcontract_preparation:view/start`
  已停用（V486）。
- 存量在批单的 MAKE_THEN 行由系统补偿器自动启动（每 10 分钟），无需人工干预。

## 4.5 订货单批准后改量（对齐销售 V482）

- 入口：订货单详情「改量」（权限 `subcontract_order:change_qty`，默认不授；
  采购同构 `purchase_order:change_qty`）。仅财务批准且无待复核 case 时可用。
- 语义：改量**立即生效**并自动创建财务复核 case 重回审批队列；新数量不得低于
  已回厂净量/已出仓目标件；委外减量另受「未出仓未草稿剩余」约束，有子层增量
  自动再发单给计划。事实账 `procurement_order_qty_change_logs`（以前→现在）
  在审批任务列表标注「改后待复核 · 改量 N 处」，审核详情展示修改清单。
- 复核通过=确认（不重复生效副作用）；驳回保留新数量，制单人可再次改量。

## 五、仓库目标件出仓与回厂 IQC

### 5.1 目标件出仓

- 任务中心：`/warehouse/subcontract-outbound`。
- 拣货页：`/warehouse/subcontract-outbound/:planId`。
- 页面只返回已备齐并由服务端释放的目标件行；`ACTION_REQUIRED/IN_PREPARATION` 不得成为仓库假任务。
- 新流冻结单耗为 `1`；历史 `LEGACY_BOM_COMPONENT` 才继续展示父件、冻结 BOM 单耗和历史子件守恒。
- 保存草稿建立本计划行专属库存预留；审核只能消费自己的预留并产生真实出库流水。

### 5.2 回厂与 IQC

- 仓库从预计到货进入独立到货登记页，不经委外通用新建页。
- 未审核出仓先进、回厂量超过合法出仓剩余、来源 UUID 不一致或仓库事实缺失均 fail-closed。
- 回厂审核进入 IQC 隔离，并按财务批准的加工费快照形成立账事实；IQC PASS 只生成仓库合格待入库，不写库存、不推进原生产供给；仓库以独立人员确认实际量与实际库位后才入库并推进，不重复立账。
- IQC FAIL 不进入可用库存，后续正式退回/贷项负责反向；不得直接修改回厂累计或用备注抹平。

### 5.3 V440 IQC 不合格退回与贷项专页

- 稳定列表：`/procurement/iqc-rejections`；详情：`/procurement/iqc-rejections/:id`。
- 仓库 Hub 与财务 Hub 均只在 `procurement_iqc_rejection:view` 下显示入口和进行中角标；通知深链进入同一详情，不另造通用单据页。
- IQC 结果事务只写质量事实和通用业务 Outbox；异步消费者按稳定业务键幂等建案。异步失败不得回滚质量结论，case 进入 `FINANCE_EXCEPTION` 并通过受控恢复继续。
- 公开业务状态严格为六个：`PENDING_RETURN`、`RETURN_RECORDED`、`CREDIT_CONFIRMED`、`CLOSED_NO_CREDIT`、`FINANCE_EXCEPTION`、`REVERSED`；贷项建立和专用抵销在单一事务内完成，不持久化或展示第七个过渡状态。
- 结构化动作：登记失败实物退回、确认供应商贷项、仅对冻结失败金额严格为 0 的 case 无贷项结案、按当前状态受控反向；`FINANCE_EXCEPTION` 可在服务端允许时重试财务投影。所有命令携带 `expectedVersion + commandId`。
- 登记实物退回必须提交退回单号、日期、经办人与事件 UUID；它不走 PASS 普通退货、不增加普通 `returned_qty`、不直接生成贷项。返修/补做通过 replacement allocation 释放合法回厂容量，不重复目标件出仓，也不重复消耗委外子件。
- 确认贷项按冻结失败全量生成负 AP；只抵销来源 AP 当前正余额与失败金额的较小值，剩余负 AP 作为开放供应商贷项保留。非零金额不能 `CLOSED_NO_CREDIT`，零金额不能生成 0 元 AP。
- 待检/部分检验和未完成拒收闭环的来源 AP 必须暂停付款、普通抵销与月结，直到 `CREDIT_CONFIRMED` 或 `CLOSED_NO_CREDIT`；页面不得以可操作按钮暗示绕过后端 hold。
- view-only、record-return 与 `view_all` 都不自动获得金额；金额只认 `procurement_iqc_rejection:amount:view`，且服务端 `priceMasked=true` 时 Flutter 必须显示 `***`，财务动作权限也不能解密。
- 对象池：普通 `view` 只看本人归属；`view_all` 跨归属；`record_return` 是明确的跨归属实物退回执行池；confirm-credit、close-no-credit、reverse 是财务全局动作池，但所有页面/命令仍先要求 `view`。
- V440 是采购与委外共用的 IQC 拒收闭环，不得拿材料超耗 `subcontract_loss_claim` 冒充。

## 六、页面权限与商业字段矩阵

V437 只登记权限码、动作类型与 `permission_surface_permissions`，**不向部门、角色或个人默认授权**。
权限管理员必须在权限设置页按真实岗位显式授权。`subcontract_outbound:handle`、
`finance_order_approval:review` 和 `subcontract_application:edit` 是停用复合权限，不能恢复为替代门禁。

| Surface | 页面阅读 | 业务动作 | 商业字段 |
|---|---|---|---|
| `subcontract.inquiry` | `subcontract_inquiry:view` | 当前 UI 只读历史；目录中的 `subcontract_inquiry:create/edit/delete/approve/reverse` 不在现行页面开放，也不能从深链恢复 | `subcontract_inquiry:price:view` |
| `subcontract.application` | `subcontract_application:view` | 申请只读；分解使用 order create/decompose 四权限交集 | 无商业字段 |
| `subcontract.order` | `subcontract_order:view` | `subcontract_order:create/edit/delete/submit_finance/reverse/decompose` 各自独立；财务决定只在财务任务页 | `subcontract_order:price:view` |
| `subcontract.receipt` | `subcontract_receipt:view` | 既有草稿使用 `subcontract_receipt:edit/delete/approve/reverse`；新回厂由仓库独立登记页创建，通用 create 路由关闭 | `subcontract_receipt:price:view` |

### 6.1 对象范围

- 普通委外单据默认按稳定 `maker_id`/服务端归属投影可见；跨制单人查看使用 `subcontract:view:all`。
- `subcontract:view:all` 只扩大委外对象阅读范围，不授价格、创建、审核、红冲、出仓或财务决定。
- 财务审核员对关联订单只有审核任务所需的只读视角；`finance_order_approval:view` 不能授予委外编辑。
- 前置自制队列由服务端按对象和岗位投影；知道 `planItemId`、`analysisId` 或订单 UUID 不构成授权。
- 超级管理员固有权限由服务端决定；前端不得通过“isSuperAdmin 就显示旧 handle 动作”绕过停用权限与 `allowedActions`。
- 价格字段服务端仍以 `priceMasked` 作最终权威。Flutter 本地 permission 只决定是否渲染，不能解密服务端已脱敏数据。
- V440 是明确例外：`record_return` 跨归属形成仓库/退回执行队列；`confirm_credit`、`close_no_credit`、`reverse` 跨归属形成财务动作池。它们扩大的是各自动作任务池，不授页面阅读或金额；访问页面仍先认 `view`，金额仍只认 `amount:view`。

## 七、通知页与顶部通知栈必须绑定

委外业务事务通过 Outbox 产生通知事实，`ChainNoticeService` 幂等写入通知页记录。凡是业务上
“有通知”，必须同时满足：

1. 有权接收且持 `notice:read` 的用户能在通知页看到记录；
2. 同一未读到达事件同时投影到顶部非阻塞通知栈；
3. 新通知在旧通知上方，支持叠放、展开和逐条关闭，不阻塞正在进行的仓库/生产操作；
4. 顶部关闭只表示本设备已展示，不等于通知已读、审批完成、库存过账或业务结案；
5. 点击主动作才按既有规则标记已读并进入稳定深链；深链再次执行页面权限与对象门禁。

主要通知与动作入口：

| 事件 | 收件人 | 稳定入口 |
|---|---|---|
| 有子层直接下单缺口→前置生产分析已建（草稿期） | 计划/生产（持 `production_material_analysis:view`） | 物料分析 summary（行动卡） |
| 前置生产产出完工入库 | 委外订货制单人 | `/subcontract/orders/:id` |
| 批准后改量→复核 case 开立 | 财务审核池（同订货审批） | `/finance/procurement-approvals`（行动卡） |
| IQC 不合格建案/实物退回登记 | 仓库/财务动作池 + 订单归属人 | `/procurement/iqc-rejections/:id`（行动卡） |
| 有子层级订货行财务通过 | 有 preparation view/start 且有通知阅读权的计划/生产人员；委外制单人收回执 | `/subcontract/preparations?planItemId=...` |
| 前置 DRAW/FQC/仓库实收推进 | 仓库、计划/生产、品质按事件职责 | 既有领料、FQC、成品待点收页面 |
| 目标件整批可出仓 | 仓库与委外制单人 | `/warehouse/subcontract-outbound` / 订货进度 |
| 目标件出仓审核 | 委外制单人；有原分析时通知来源负责人 | `/subcontract/orders/:id` |
| 临近/超过交期且加工商处仍有净结存 | 委外制单人；有来源时原分析制单人 | 订货全链进度 |
| 回厂登记 / IQC 待检 | 品质、委外制单人 | 品质任务 / 订货进度 |
| IQC FAIL 形成退回/贷项任务 | 订单负责人、持 V440 对应权限的仓库/财务人员 | `/procurement/iqc-rejections/:id` |
| IQC 拒收退回、贷项、零金额结案、财务异常或反向 | 按阶段责任人及订单归属人 | V440 详情页；通知不携带冻结金额 |
| IQC PASS / 其它品质结案 | 仓库、委外制单人、分析来源负责人 | 合格放行 / 订货结案 |
| 材料损耗产生超耗责任 case | 持 `subcontract_loss_claim:view/review` 的合格财务人员；订单归属人收业务回执 | 财务 `/finance/payables` / 订单 `/subcontract/orders/:id` |
| 超耗责任决定、履约、反向 | 按阶段持 `subcontract_loss_claim:view/fulfill/reverse` 的财务人员；订单归属人 | 财务 `/finance/payables` / 订单全链进度 |

超耗责任通知由业务事务写 Outbox 并使用稳定业务键幂等发布；通知标题/正文不携带建议索赔额、
实际索赔额、抵销额或到账金额。金额只能在通过对应商业/财务权限和对象门禁的页面读取。
V440 建案、实物退回、贷项确认、零金额结案、财务异常和反向同样遵守该规则：每条有权可见的
通知页记录必须绑定同一顶部到达事件，不能只写通知页或只弹顶部；`notice:read`、阶段动作权限与
IQC 拒收对象范围共同解析收件人，通知正文和顶部摘要均不得泄露冻结金额。

## 八、响应式、空错、刷新与并发

### 8.1 响应式与可访问性

- compact `<600dp`：申请分解和前置自制使用单列任务卡；核心事实优先，次要字段折叠；操作区域至少 48dp。
- medium `600–840dp`：筛选纵向收敛，列表/表格按可用父容器宽度布局。
- expanded `>840dp`：高密度业务表、服务端分页和按行上下文动作；禁止无对象的“开始第一条待办”。
- 图标不能单独承担状态含义；状态同时有文本。支持暗色主题、系统文字缩放、键盘焦点和语义标签。
- 每页只有一个主动作；无动作权限时整项不渲染，不能用 disabled 按钮泄露写能力。权限齐全但服务端状态/capability 阻断时，才显示禁用原因。

### 8.2 加载、空态与错误

| 状态 | 页面要求 |
|---|---|
| 首次加载 | 保留页面骨架并显示语义化进度，不显示空白成功页 |
| 刷新中 | 禁止重复写动作；旧数据可保留但必须显示刷新状态 |
| 空态 | 说明“当前筛选无数据”还是“业务尚未产生”，并给合法下一步；无权限不能伪装成空数据 |
| 读取错误 | 显示业务化错误和“重试”，不把 Dio/SQL/堆栈文本直接交给员工 |
| 权限不足 | 路由 fail-closed；Hub 卡/写动作隐藏；受控说明页只提供合法替代入口 |
| 关联对象受限 | 显示“无权查看关联单据”，不泄露单号、价格、人员或 UUID |

### 8.3 刷新与并发

- 搜索、防抖和翻页使用请求序号，只允许最新响应回写；切换筛选时清理跨页选择。
- 分解提交前服务端重验申请状态、剩余量、来源 UUID、对象范围和 capability；待财务订单继续占用来源容量。
- 前置自制启动使用 `expectedVersion + idempotencyKey`；仓库草稿保存、预留、审核、关闭和红冲均需 CAS/幂等与数量守恒。
- 列表返回、页面恢复和网络恢复需刷新当前页；通知不能代替刷新后的任务事实。
- 并发冲突显示明确恢复路径：刷新、重新选择或打开最新任务；不得静默覆盖他人操作。
