## 公共入口、调用方与必要差异

- 登录页、桌面可信候选和改密页继续调用唯一 `SessionNotifier`，保留 `Future<void>` 接口、显式失效异常、一次性凭据、MFA、未知提交和模拟只读边界。
- access 注入、显式 Bearer、proactive refresh、401 refresh/replay、登录/OTP/改密/me、注销及 pending logout 使用同一 issuer 与实际 HTTP 目标规则。编译明确配置的 LAN/cloud 可以显式选择切换；独立 Debug 不因相同 uid/dataset 变可信。队列仍只重试注销。
- Web 请求保留 Dio 编码后的 JSON/form/multipart 原字节、取消、响应流 receiveTimeout 和下载小请求体上限。Fetch 无网络逐字节上传事件，Web 上传进度只报告开始和收到响应头后的确认完成；原生保留原进度。Web 等响应头采用已配置 connect/send/receive 中最短非零期限并返回对应超时类型，较 XHR 更保守；未承诺浏览器能区分 TCP 建连和实际上传完成。
- 员工 7 个确认式写入口共用 owner；各自保留 PII、普通编辑、转正、返聘及合同权限。转岗已有独立完整流程，不复制其事务或迁移为通用写入器。账号开户/重置继续用现有公共凭据 flow，不并入普通资料修改。
- 后端当前资格、锁定/停用/reset/返聘、最后可用超管并发、旧密码代际及旧 refresh 所属 SID 的机制已在集成树，采用真实 PG/HTTP 复验，没有重复重写正确实现。

## 纯 alias 维护边界

`prepare_employee_alias_only.py` 仅离线生成受审 SQL，默认单个 repeatable-read 事务并 `ROLLBACK`；显式 `--commit` 才生成提交版，工具不自动连接或执行。前提包含新鲜的物理集群/数据库 OID、dataset/代际、完整 Flyway 指纹、V947 关键迁移、原员工/用户 UUID 和版本、启用永久凭据事实、归档 alias 及明确身份来源。锁内重读，错误或漂移拒绝；相同证据重入零插入，冲突证据拒绝。

事务内仅在数据库私有上下文逐行比较原账号、授权/拒绝、消息/已读、会话及原 actor/target 审计和员工历史；不输出密码、hash、密钥或 PII。允许现有 alias 触发器增加审计及 authorization epoch，使旧查询缓存失效，不改账号 auth_version、不撤销登录 SID。已有全局 epoch 可能要求访问令牌刷新，不能宣称完全无会话可见影响。

备份 reference/hash/verified 是外部人工独立验证的回执，工具不读取备份，也不自行证明可恢复。正式维护仍须统一版本部署、既有明确授权、配对备份验证、精确前提、预演及独立连接回读；提交未知先回读，不自动重放业务写入。没有准备可直接运行的旧公司账号修复计划，也没有执行旧停用/回绑执行器。
