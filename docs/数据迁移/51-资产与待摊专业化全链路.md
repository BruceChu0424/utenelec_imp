# 51 · 资产与待摊专业化全链路

> 日期：2026-08-01
> 设计依据：[ADR-018](../99-决策记录-ADR/ADR-018-资产与待摊专业子账及不可变过账.md)
> 本文取代文档 45 中“删除当期日志和凭证后重建即为幂等”的口径；V123/V140 已应用迁移保持不变。
>
> **当前生产判定：NO-GO。** `UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED` 默认且必须保持
> `false`。当前交付的是可继续验收的安全骨架、月度折旧/摊销正常批次和正常批次反冲，
> 不是可通过修改开关直接上线的完整资产生命周期。

## 一、目标与非目标

本轮把 V123 技术原型升级为可审计的固定资产与长期待摊安全骨架，已经交付：

- 类别与会计政策初始化；
- 草稿、提交、他人审批与驳回；
- 固定资产会计账簿的结构和税务账簿的数据库隔离预留；
- 待摊计划版本与逐期计划行；
- `CORPORATE` 月度折旧/摊销预览、提交、审批、正常过账和正常批次反冲；
- 归属/运行状态变更及处置/提前终止的受门禁工作流骨架；
- 子账期间关闭与受控重开；
- 审批、业务事件、逐项计算快照和总账凭证追溯；
- 列表、详情、权限动作和响应式月结工作台。

本轮不伪装交付以下基础设施：

- 真实附件上传、对象存储、下载鉴权、哈希、病毒扫描；
- 从 PO/AP/收货/CIP 自动抓取资本化候选；来源先采用结构化引用；
- 无形资产、在建工程、使用权资产和投资性房地产的专门核算；
- 条码盘点、资产组减值估值、批量文件导入和税务申报自动化。

本轮也明确没有完成以下生产必需能力：

- 资本化/初始确认、处置、提前终止各自的业务事件反冲、状态恢复和后续期间重算；
- 完整处置清算：处置收入、税费、清理成本、应收/收款、清理损益及差额审批；
- 退款、供应商贷项或合同变更驱动的待摊冲减；
- 必备资料代码到逐份证据的结构化映射与逐码校验；
- PO/AP/收货/CIP 的来源 adapter，以及源单金额、币种、行号、过账状态校验；
- TAX 账的 CRUD、独立计提/反冲 API、税务差异报表和 TAX 总账；
- 历史期初原值、累计折旧/摊销、剩余期限、追溯/不追溯切换；
- 将子账部门/成本中心快照写入总账分录的权威维度。

## 二、旧原型审计结果

| 风险 | 原型行为 | 新行为 |
|---|---|---|
| 历史可改 | 计提后仍可修改原值/期限/残值，重跑按新主档覆盖历史 | 提交后冻结会计字段；V183 已有事件/版本结构，但计划修订 API 尚未交付 |
| “幂等”破坏历史 | 删除同期间日志和凭证再生成 | 唯一批次 + 输入指纹；错误用反向批次和反向凭证 |
| 总账互相删除 | 总账 `generate` 删除期间全部 AUTO 凭证 | 总账只删除自己明确重建的来源，资产凭证不在其所有权范围 |
| 无初始入账 | 建卡不生成资本化/初始确认凭证 | 已有目标实现，但默认安全门禁关闭；业务事件反冲与状态恢复完成前不得生产启用 |
| 无期间控制 | 可跳月、倒序或随时重跑 | 有效日历月、连续期间、唯一有效批次、关账阻断 |
| 无职责分离 | 编辑权限可建档、计提、删除 | view/edit/approve/post/dispose/export/period manage 分权 |
| 税会混淆 | 单一原值/年限/残值 | 数据库隔离 `CORPORATE` 与 `TAX`；当前 API/过账只交付 `CORPORATE`，税务选择尚不能上线 |
| 待摊与预付混淆 | 手工输入即开始摊销 | 受益已经开始且会计审核后生成 v1 计划；激活/初始确认仍由默认门禁阻断 |

## 三、数据模型

### 3.1 类别和政策

`finance_asset_categories` 同时服务固定资产和待摊，但通过 `object_type` 严格区分。类别包含：

- 编码、名称、生效日期、启停和版本；
- 成本科目、累计折旧科目、费用科目、清理/来源过渡科目；
- 默认直线法、期限、残值率；
- 必备资料代码列表。

系统不种子化资本化金额门槛、资产寿命、残值或税务选择。正式提交前由企业财务负责人配置并批准。
`required_document_codes` 当前只是政策代码清单；尚无每个代码对应的证据类型、来源、哈希、
验真状态、审核人和审核时间，因此不能据此宣称“必备资料已逐码验证”。

### 3.2 主档与账簿

V123 的 `fixed_assets`、`deferred_expenses` 通过后续迁移追加：

- `category_id` 和四类科目快照；
- 来源类型、来源 ID 或通用来源引用、来源行引用和来源单据日期；当前没有独立供应商/合同/发票/验收字段；
- 购置、验收、可使用、资本化、受益开始/结束等不同日期；
- 部门、地点、责任人和序列号；
- 标准会计状态、运行状态、审批人/时间及乐观版本。

`finance_asset_books` 为固定资产账簿提供 `CORPORATE/TAX` 数据隔离。当前激活目标流程会建立
`CORPORATE` 账簿，但受生产安全门禁保护；`TAX` 仅为模式预留，当前没有可用的建账、计提、
反冲、过账或差异查询 API。账簿冻结金额、残值、期限、方法、起始期间、科目和政策快照。

`finance_deferral_schedule_versions` 与 `finance_deferral_schedule_lines` 保存待摊版本。审批时创建并
批准 v1 计划；每个版本的计划行合计必须等于版本金额，最后一期吸收舍入尾差，已过账计划行只允许
反向。数据库结构允许未来版本，但当前没有计划修订/未来生效版本 API，不能写成已交付能力。

### 3.3 审批、事件和批次

- `finance_asset_approval_steps`：对象类型、对象 ID、节点、动作、意见、操作者和时间；只追加。
- `finance_asset_events`：转移、状态、政策变化、处置、终止和反冲等业务事实；只追加。
- `finance_asset_posting_runs`：运行类型、期间、输入指纹、算法版本、状态、总额、异常、制单/审批/过账人、凭证和反冲引用。
- `finance_asset_posting_lines`：每一资产账簿或待摊计划的期初、当期、期末、月份序号、科目和 `department_id_snapshot` 计算快照；没有成本中心快照列。
- `finance_asset_accounting_periods`：资产子账开放/关闭、关闭人与原因、重开人与原因。

V123 的 `fa_depreciation_log` 和 `da_amortization_log` 继续作为报表兼容事实表，但关联正式批次并改用“未反冲有效行”部分唯一约束，不能再通过删除重建。

### 3.4 总账维度边界

过账明细只保存 `department_id_snapshot`；成本中心代码停留在主档，未冻结到过账行。现有
`gl_entries` 也没有部门/成本中心权威列，月度凭证因此不能形成按部门或成本中心可核验的总账维度闭环。需要管理会计分摊
或部门损益时，此项是明确的生产阻断，而不是报表层补字段即可解决的问题。

## 四、目标业务流程与当前可达范围

### 4.1 政策初始化

1. 财务负责人确认采用的会计准则；
2. 配置资产/待摊类别及四类科目；
3. 配置期限、残值、方法、必备资料和生效日期；
4. 权限管理员将审核、过账、处置和关账权限按个人分配；
5. 至少两名不同人员可完成制单与复核，否则保持 fail-closed。

### 4.2 固定资产

1. 建立草稿，服务端生成资产编号，录入结构化来源和各关键日期；
2. 补齐类别、金额、归属、地点、责任人、来源引用和验收资料；
3. 提交时服务端复核日期顺序、科目完整性、金额/期限/残值和来源唯一性；
4. 非发起人审批，冻结企业会计政策到 `CORPORATE` 账簿；
5. 过账人激活，生成借资产成本科目/贷清理或来源科目的总账凭证（当前默认门禁关闭）；
6. 下一个符合规则的连续期间进入折旧预览；
7. 调拨、闲置、维修等写业务事件；闲置不会自动停折；
8. 处置目标应使用专用申请、审批、清算、凭证、反冲和归档链；当前只有转入清理过渡的骨架，
   未覆盖处置收入、税费、清理成本、应收/收款和清理损益，且默认门禁关闭；
9. 提足折旧但仍使用的资产继续保留地点、责任人和盘点能力。

### 4.3 长期待摊

1. 供应商预付款仍留在往来；确认商品/服务已取得且未来受益期成立后才建待摊草稿；
2. 录入合同/发票/来源引用、受益起止、金额、费用科目、部门及计划方法；
3. 非发起人审核后生成版本化计划，检查所有计划行合计与总额完全一致；
4. 过账人激活，生成借待摊成本科目/贷清理或来源科目的凭证（当前默认门禁关闭）；
5. 逐期预览与过账；已确认历史行不可改；
6. 仅“未来受益已经终止”的余额费用化可以进入终止目标流程。退款、供应商贷项、合同变更必须
   与应付/往来和来源单据联动，不能用费用化终止冒充；该退款/贷项链当前未交付。

### 4.4 月度运行

1. 选择有效开放期间和运行类型；
2. 预览落库并冻结逐项输入，显示笔数、总额、尾差、缺科目、非连续期间等异常；
3. 阻断异常未清零时不得提交；
4. 发起人提交，另一人审批，具有过账权限且不是发起人的人员执行过账；
5. 过账事务取得期间互斥、重验输入指纹并同时落运行、明细、日志和总账；
6. 总账借方合计、贷方合计、批次明细合计和子账变动必须一致；
7. 需要更正时创建反向运行；原凭证、原日志和原计算快照保留；
8. 折旧与摊销两种运行都完成（包括合法零项证明）且无异常后才允许关账。

月度运行及其正常批次反冲已经交付，不依赖业务事件开关；但新库在门禁关闭时无法激活新资产/
待摊，因此可验证的是月度引擎和不可变反冲能力，不代表从新建到终态的生产全链路已经开放。

### 4.5 生产安全门禁

应用属性 `uten.finance.asset.posted-workflows-enabled` 由环境变量
`UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED` 提供，缺省为 `false`。门禁关闭时服务端拒绝：

- 固定资产与待摊的激活/初始确认；
- 固定资产处置申请与处置批准；
- 待摊提前终止申请与终止批准。

工作台的 `overview` 同时返回 `postedWorkflowsEnabled=false` 和
`operationalBlockers`，Flutter 显示独立安全门禁横幅并隐藏相关动作。该阻断与
`policyReady/missingPolicyItems` 分开；`policyReady` 当前只是最低类别存在性/完整性提示，
不是企业政策签字或逐码证据验真。补齐政策、科目或资料代码不能解除门禁。仅修改环境变量不构成
生产变更依据。

### 5.2 运行和期间

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/finance/asset-posting-runs/preview` | 创建逐项快照预览 |

## 六、错误与并发语义

- `400`：畸形 JSON、无法解析的请求体或显式 `MALFORMED_REQUEST`；
- `403`：缺少权限、发起人自审或本人过账；
- `404`：对象不存在；当前资产查询没有行级/部门数据范围过滤，持 view 权限可看全量；
- `409`：版本冲突、状态不允许、期间已关闭、输入指纹变化、重复有效批次、非连续期间或并发运行；
- `422`：Bean Validation、字段/期间/金额/日期/必备资料及会计政策完整性校验失败。

当前 API 没有客户端幂等键：每次 preview 创建新的 run ID，后续重复动作依赖状态和
`expectedVersion` 冲突；页面也没有超时后的自动按 run ID 轮询。内部 idempotency 字段不能冒充
客户端重试契约。任何总账写入失败仍应回滚业务批次、逐项日志和状态变化。

## 八、生产判断

当前完整生产结论为 **NO-GO**。源码、静态测试、本地 Mock，甚至数据库迁移回放通过都只表示局部
工程证据成立。默认关闭的门禁使未完成终态能力保持不可达，但门禁本身不把模块变成可生产。
以下任一项未完成时不得改判：

- 企业政策和科目映射未批准；
- 职责分离个人授权未完成；
- 真实 PostgreSQL 全新库 SQL 回放已通过，但 Flyway 元数据、代表性升级库、双连接并发、端到端
  反冲和子账—总账—报表对账尚未通过；
- 初始确认、处置和提前终止没有专用业务事件反冲及状态恢复；
- 处置清算、退款/贷项、逐码资料证据或来源 adapter 仍由人工备注替代；
- TAX 账 API/GL、历史期初追溯或 GL 部门/成本中心属于上线范围但尚未交付；
- 人工 UAT、备份恢复、容量和回滚未演练；
- 附件仍被业务流程列为强制证据，但真实附件基础设施尚未交付。
