## 一、员工看到的主流程

```text
已审核销售订单行 / 合法手工需求
  → 选择本次要分析的产品与数量
  → 选择一个目标仓并开始物料分析
  → 系统按完整 BOM 树检查目标仓合格可用库存、在途和缺口
  → 计划员逐直接需求节点确认 BUY / SUBCONTRACT / MAKE
  → 多选采购缺口并提交采购需求
  → 多选委外缺口并提交委外需求
  → 自制件形成 MAKE 备料任务和系统子需求
  → 选择当前可完工的产品/自制备料项
  → 逐张填写 A4 生产计划单
  → 服务端重新预览并批量生成计划草稿，提交审批
  → 计划批准后才形成 READY、正式预留、DRAW 和销售已排量
  → 剩余未排数量继续保留在原物料分析，待物料后续到齐再分批安排
```

销售订单有 10,000 件需求而当前生产硬门槛物料只完整支持 1,000 件时，员工可以先为 1,000 件填写并提交计划单；剩余 9,000 件不复制成一张“待料正式计划”，而是继续留在原分析。采购、委外或 MAKE 合格供给到位后，重新打开同一分析继续安排。

自制件按自底向上推进：先排产并完工入库最底层、当前可齐套的自制件（叶子件），其入库由服务端自动上调父级可完工量；父级变为可排产后再排产，层层上推至顶级产品。产品区把可排产项置顶、并在不可排产卡上标明被哪类缺口挡住，帮助计划员按此顺序操作，无需手工计算层层库存。

## 二、历史记录与来源选择

### 2.1 物料分析记录

历史页只读取服务端按负责人、部门和对象范围裁剪的记录，支持：

- 搜索需求编号、销售单号或产品；
- 按 `ACTIVE / PARTIALLY_PLANNED / COMPLETED / CANCELLED` 筛选；
- 按销售、返工、试制、样品、备库、其他或系统自制子需求筛选；
- 查看需求、已提交、已批准、待处理、可立即/按期数量；
- “继续处理”回到原分析 ID，不能用重新创建代替恢复。恢复后点“按最新库存刷新分析”时，前端自动用该分析已持久化的来源重算（从产品行重建销售/手工来源、跳过系统 `MAKE_COMPONENT`，与服务端 `requireSameSources` 排除 MAKE_COMPONENT 一致），无需重新选产品。

宽屏使用 `MasterDataTableView`，窄屏改为带状态、数量和明确“继续处理/查看”文案的卡片。搜索、筛选、分页、刷新和打开记录都是安全读操作，不改变业务状态。

### 2.2 新分析来源

- 销售来源只列已审核且仍有可排剩余量的销售订单行；支持勾选多行联合分析，不显示价格。
- 手工来源只允许 `REWORK / TRIAL / SAMPLE / STOCK / OTHER`；必须填写稳定需求编号、原因、产品、数量和日期。
- `MAKE_COMPONENT` 只能由系统根据 MAKE 备料动作创建，员工不能手工伪造。
- 点“联合分析所选产品”或“加入分析”前的勾选、搜索和本地表单编辑尚未写业务事实；真正点击“开始/刷新分析”会调用写接口并持久化分析、来源和 BOM 快照。

## 三、分析详情的傻瓜式交互

### 3.1 产品与自制备料项

- 区域表头有三态复选框：空框表示全未选，勾选表示当前可选项全选，半选表示只选了部分；再次点已全选表头即取消当前可选项。
- 每张产品卡也有复选框；选中后整卡使用深绿色底和白色文字，不只靠小勾表示状态。
- 缺少必需 BOM、无可完工量或无权限的行不能勾选，按钮附近必须显示原因；不能给一个看似可点但无响应的按钮。
- “调整物料优先顺序”只改变共享自由库存的分析模拟顺序，不创建正式库存预留；点击“确认优先顺序”才写入服务端并重算。
- 每张卡显示就绪状态：`可排产`（`readyNowQty>0`）或 `等待：自制子件 N · 采购 M · 委外 K`，并给出一行下一步提示（如“先排产并入库下级自制件，本件可完工会自动上调”）。状态由该产品 depth-1 短缺物料的路线统计得出，纯前端读已有字段，不另查库存。
- 产品区按“可排产置顶”做稳定排序（保留分配优先级与父先于子序），让计划员一眼看到现在能做谁；不可排产的卡在其可完工量标题下说明被什么挡住。
- `MAKE_COMPONENT`（自制备料）卡显示 `自制备料任务 · 用于组装 {父件}`，标明它喂哪个上级组装件；父件名由服务端经 `parent_analysis_material_id` 透传，为空时前端按 goodsId 兜底匹配 depth-1 MAKE 节点所属产品。
- 自制件完工入库后，上级可完工量由服务端 `MaterialAnalysisSupplyWakeupService` 自动 `refreshLocked` 上调，无需人工计算；本页只展示结果。

### 3.2 三个数量不能混用

| 页面名称 | 权威含义 | 能否作为本批计划上限 |
|---|---|---:|
| 可开工（分析参考） | `START` 阶段物料当前可支持的数量，只用于看准备进度 | 否 |
| 可完工入库 | `START + ASSEMBLY + FINISH` 生产硬门槛完整齐套后的数量 | **是** |
| 预计可发货（参考） | 加上 `SHIP` 参考物料后可支持的提示量 | 否 |

`readyNowQty` 是兼容 API 字段，服务端与当前页面把它写成、读取为“可完工入库量”。逐张计划单中的最大数量和最终 `plan-preview` 都按该量校验，不按“可开工”或“预计可发货”放大。

`SHIP/REFERENCE` 永远只是参考：不写正式生产物料需求、不占库存、不生成 DRAW，也不阻止生产计划或销售实际发货。生产过程确实消耗的纸箱、胶袋、说明书等必须在 BOM 中配置为 `FINISH`，并按 `PER_UNIT / PER_PACKAGE / FIXED_BATCH` 计算；不能把纸箱放在 `SHIP` 后再假装已经为生产预留。

### 3.3 BOM 父子树与红色缺料

- 页面按 BOM `level/path/parentNodeKey` 展示父子层级和路径，不把深层子件摊平为父产品的直接领料。
- 缺口大于零时同时显示红色、缺料图标/文字和缺口数量；不能只用颜色传达状态。
- 同一物料经多条 BOM 路径出现时可以展开路径，但同一个 `actionGroupKey` 只下达一次，不重复采购或委外。
- 只有当前需求的直接层、可执行节点可以确认路线和下达需求；深层行只解释“由上级自制子需求展开”，不能直接操作。
- MAKE 父件库存不足时，其子层材料属于系统 `MAKE_COMPONENT` 子需求；父件现货和子件原料不能在同一父产品中被重复消耗。
- BOM 树每个节点按真实缺口诚实标注，不把“需求为 0”误标成“库存充足”：`缺 X`（红，缺口>0）/ `已齐套 · 需求 X`（该路径有需求且现货够）/ `本路径无独立需求`（父件走采购/委外，子件不单独展开）。子件是否缺料以父件路线为准：只有父件路线为 MAKE 时才展开子件需求，否则子件 `required=0`、不单独缺料。

### 3.4 BUY / SUBCONTRACT / MAKE 分区

1. 计划员先按节点确认采购、委外或自制路线；偏离主档建议时填写原因。
2. 当 depth-1 节点很多且建议明确时，可用底部“采纳建议路线（N）”一键把所有 BUY/委外/自制建议确认为正式路线（route==suggestion 无需原因；REVIEW/空建议的跳过并提示需人工判断），避免逐行下拉。该按钮仅在存在未确认且建议非空的节点时出现。
3. 路线确认是缺料通知与备料动作的**硬门槛**：未确认路线的节点勾选框不可用；服务端 `notify` 也要求所选操作组全部 `routeConfirmed()`，否则拒绝（`通知前必须确认操作组内全部物料路线`）。
4. 每个分区表头提供三态全选，行可单选或多选；选中行深绿色高亮并显示“已选 N 项”。
5. BUY 点“提交采购需求（N）”；SUBCONTRACT 点“提交委外需求（N）”；未勾选的控制组保持不下达。
6. MAKE 点“创建自制备料任务”只形成 `PREPLAN_MAKE_TASK` 和系统 `MAKE_COMPONENT` 子分析来源，不自动递归创建整棵正式计划树。生成的 `MAKE_COMPONENT` 项作为同一分析里的产品行出现（带独立 `readyNowQty` 与自身 BOM），可被独立排产；其完工入库后自动上调父级可完工量。

这里的“通知”不是普通消息：服务端先写幂等 `preplan_supply_actions` 和逐节点 allocations，再创建真实采购申请、委外申请或 MAKE 子需求。消息、角标和岗位队列只是这些事实的提醒投影。重复点击使用幂等键；服务端按当前剩余缺口只补差额，不能重复生成同量需求。

## 四、逐张 A4 生产计划单

勾选至少一个当前可完工的产品或自制备料项后，点击“填写生产计划单（N）”进入独立向导：

- 一种自制件/一个执行批次对应一张 A4 纸面，桌面最大宽度约 794px；
- 左侧步骤栏和顶部进度显示“第 N / 总数 张”，移动端使用底部张数提示；
- 每张显示产品、编码、规格、来源和当前可完工量；
- 必填本批计划数量、生产车间、负责人、计划开始和计划结束；结束日期不得早于开始日期；
- “保存并下一张”“上一张”逐张处理；“应用到剩余”只复制车间、负责人和日期等安排，不改变各产品及其数量身份；
- 最后一张进入汇总确认，逐行复核产品、数量、车间和日期；“返回修改”不写库，“确认并提交审批”才返回分析页继续服务端预览与生成。

当前 Flutter 向导固定以 `approveNow=false` 调用生成接口：批量生成计划草稿、ACTIVE planning draft 和 `SUBMITTED` 关联并提交审批，不直接批准。具有计划审核权限的人在计划详情走独立审核；只有审核成功后才形成 READY、完整库存预留、DRAW 和销售已排量。多选生成默认整批原子成功或失败，任一产品的库存、版本、指纹、BOM、组织或数量变化都使整批失败并要求刷新，不能静默部分成功。

## 五、按钮与接口安全清单

| 页面动作 | 接口 | 是否写业务事实 | 操作说明 |
|---|---|---:|---|
| 查历史、筛选、分页 | `GET /api/production/material-analyses` | 否 | 安全读取对象范围内记录 |
| 查销售候选 | `GET /api/production/material-analyses/sales-candidates` | 否 | 不返回价格 |
| 打开分析 | `GET /api/production/material-analyses/{id}` | 否 | 只读当前持久化快照 |
| 本地勾选/取消/全选、展开 BOM、打开后返回 A4 向导 | 无 | 否 | 可用于浏览器视觉验收 |
| 开始或刷新分析 | `POST .../preview` | **是** | 持久化/刷新分析、来源和节点快照；使用版本、指纹和幂等键 |
| 确认路线 | `PUT .../{id}/routes` | **是** | 保存人工路线与原因并重算；“采纳建议路线（N）”是前端对该接口的批量封装，`route==suggestion` 无需原因 |
| 确认优先顺序 | `PUT .../{id}/allocation-priorities` | **是** | 改分析分配顺序，不是正式预留 |
| 提交采购/委外/自制需求 | `POST .../{id}/notify` | **是** | 创建权威 action、分摊及真实下游需求，不是单纯发消息 |
| 计划预览 | `POST .../{id}/plan-preview` | 不创建正式计划 | 服务端按当前库存/BOM/指纹做最终校验，返回一次性预览指纹 |
| 确认并提交审批 | `POST .../{id}/generate-plan` | **是** | 原子生成选中批次的计划草稿与提交关联 |

写按钮同时要求客户端有效权限与服务端 `allowedActions`；前端隐藏按钮不能代替服务端对象范围、状态、版本、指纹、数量和幂等校验。请求中按钮必须显示加载态并防连点；409 表示分析、库存或来源已变化，应刷新并重新确认，不自动重放写操作。

## 六、岗位交接 SOP

| 交接 | 上一岗位必须完成 | 下一岗位看到的权威任务 | 禁止误解 |
|---|---|---|---|
| 生产 → 采购 | 勾选 BUY 缺口并提交 | 计划来源采购申请/分解任务 | 通知消息不等于已经下采购订单 |
| 采购 → 财务 | 从任务中心选择申请行、填写部分数量，按单供应商/单仓生成订货并提交财务 | 订货审批任务 | 保存草稿不等于正式订单；业务人员不能自批 |
| 财务 → 仓库 | 合格财务审核组成员批准订单 | `inbound_expectations` 预计到货 | 预计到货不是现货、不是 IQC 合格、不能使生产 READY |
| 仓库/质量 → 生产 | 实际收货/回厂并完成 IQC，只有 PASS 数量转入目标仓合格可用库存 | 原分析重算后的可完工量/齐套任务 | 待检、FAIL、未入目标仓和仅有在途不得计入可完工量 |
| 生产 → 委外 | 勾选 SUBCONTRACT 缺口并提交 | 计划来源委外申请/分解任务 | 委外申请不等于已经发料或已经回厂 |
| 生产 → 自制子件 | 提交 MAKE 备料动作 | `MAKE_COMPONENT` 子分析任务 | 子需求不是正式子计划；须子件自身齐套、选择并生成计划 |
| 生产计划 → 车间 | A4 向导提交后由有权人员审核计划 | READY 执行段、DRAW 和计划详情 | 草稿/SUBMITTED 不得开工；DRAW 已审也不等于仓库已实际发料 |

## 七、当前验证与 NO_COVERAGE

当前证据见 [ADR-029 §12](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)和[迁移验收说明 §6](../数据迁移/56-生产计划前需求与物料分析重构.md)。隔离真实 HTTP 链已覆盖 BUY 2 组、委外 2 组、MAKE 1 组、3 个未选控制组、采购/委外正式订单和财务批准，以及 61,000/122,000 的分批计划；桌面浏览器覆盖三态选择、高亮、BOM 红色缺料和 A4 向导。

**2026-08-10 可见性增强（源码级，待重建前端 + 重启后端）**：①底部“采纳建议路线（N）”一键批量确认 BUY/委外/自制建议路线；②产品卡就绪状态徽标（`可排产` / `等待：自制子件 N · 采购 M · 委外 K`）+ 下一步提示；③`MAKE_COMPONENT` 卡“用于组装 {父件}”父件链（后端 `ProductView` 经 `parent_analysis_material_id` 透传 `parentAnalysisLineId`/`parentGoodsName`）；④产品区“可排产置顶”稳定排序；⑤BOM 树诚实标签（`缺 X` / `已齐套 · 需求 X` / `本路径无独立需求`）。已 `flutter analyze` 0 + widget 16/16 + 后端 behavior 单测全过 + dev 库 JOIN SQL 验证；**仍待**：重建前端 + 重启后端，在真实 `MAKE_COMPONENT` 上验证 `parentGoodsName` 填充，并跑 FullChain 回归。该增强不改 ADR-029 任何不变量（逐级确认、stock-gated `ready_now_qty`、wakeup 机制均未动）。

仍未覆盖且不得写成“已全链上线”的部分：

- 销售审核后自动创建分析尚未进入该 HTTP 链；
- 实际采购/委外到货、IQC、分析唤醒和整批拒收替代需求未跑 HTTP 实物流转；
- MAKE 子需求到正式子件计划未跑 HTTP 端到端；
- HTTP 样本未覆盖 `EXACT_SNAPSHOT / ZERO_MATERIAL`，仅自动化覆盖；
- 车间报工、完工、组装、成品入库和销售分批出库未完成本轮端到端验证；
- 浏览器人工验收仅为桌面视口；移动端、平板、键盘与读屏仍需真实设备/岗位 UAT；
- 公司目标库 V250 迁移与校验和、历史数量/权限/审计对账、主数据治理、并发压力、备份恢复、回滚和业务签字均未完成。

因此页面和接口即使已存在，也不能据此开放公司生产写权限或宣布生产就绪。
