# 技术选型

> 本档记录 Uten IMP 的核心技术选型及理由。详细决策过程见 [99-决策记录-ADR/](../99-决策记录-ADR/)。

---

## 一、技术栈总览

| 层 | 选型 | 版本 | 选型理由 |
|---|---|---|---|
| 框架 | Flutter | 3.41+ | 一套代码六端（iOS/Android/Web/Windows/macOS/Linux），制造业 IT 团队维护成本低 |
| 语言 | Dart | 3.x | 强类型、空安全、AOT 编译性能好 |
| 状态管理 | Riverpod | 2.x | 类型安全、可测试、无 BuildContext 依赖、社区主流 |
| 路由 | go_router | 最新 | 官方推荐、声明式、Web 深链友好、支持守卫 |
| 设计系统 | Material 3 | 内置 | Flutter 官方支持，主题 token 化好 |
| 国际化 | intl + gen_l10n | 官方 | 不引入额外依赖，arb 文件可协作 |
| 偏好存储 | shared_preferences | 最新 | 轻量偏好（主题/语言/字号/性能档） |
| 敏感存储 | flutter_secure_storage | 最新 | token/密码（后端接入后用） |
| 设备检测 | device_info_plus | 最新 | 喂给性能分级自动检测 |
| Mock 持久化 | hive | 可选 | 本地 Mock 数据，前端阶段用 |
| 网络层 | dio | 最新 | 拦截器机制好，将来加 token/签名 |
| Lint | very_good_analysis | 最新 | 严格规则，团队风格统一 |
| 测试 | flutter_test + integration_test | 内置 | 单元 + Widget + 集成 |

## 二、为什么选 Flutter（而不是 React Native / 原生 / Web）

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Flutter** | 一套代码六端、UI 一致、性能好、Dart 强类型 | 桌面端生态不如原生（但企业后台够用） | ✅ 选定 |
| React Native | Web 生态成熟 | 桌面端支持差（RN 桌面不成熟）、双端 UI 不一致 | ❌ |
| 原生（各端分别做） | 体验最佳 | 5 端 × N 个模块开发量爆炸 | ❌ |
| 纯 Web | 桌面/移动浏览器都跑 | 移动端体验差、离线弱、无法上架 | ❌ |

详见 [../99-决策记录-ADR/ADR-001-技术栈选型.md](../99-决策记录-ADR/ADR-001-技术栈选型.md)。

## 三、为什么选 Riverpod（而不是 Provider / Bloc / GetX）

| 候选 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **Riverpod 2.x** | 类型安全、可测试、无 context 依赖、AutoDispose、AsyncNotifier 一站式 | 学习曲线略陡 | ✅ 选定 |
| Provider（官方旧） | 简单 | 无类型、依赖 BuildContext、复杂状态难管理 | ❌ 已被 Riverpod 超越 |
| Bloc | 强约束、事件流清晰 | 样板代码多、对中小项目过重 | ❌ |
| GetX | 简单 | 架构混乱、反模式多、社区争议大 | ❌ |

详见 [../99-决策记录-ADR/ADR-002-状态管理选Riverpod.md](../99-决策记录-ADR/ADR-002-状态管理选Riverpod.md)。

## 四、为什么选 go_router

- Flutter 官方 package（first-party）
- 声明式路由，配置集中
- 支持 Web 深链和浏览器地址栏
- 内置 redirect 钩子，做路由守卫（未登录跳登录页）简单
- 支持嵌套导航（NavigationRail + 子页面）

---

## 五、为什么用 Material 3（而不是自建设计系统）

- Flutter 官方支持，ThemeData 直接配
- ColorScheme / TextTheme / ComponentTheme 全套 token
- 响应式断点有官方推荐（WindowSizeClass）
- 团队学习成本低（设计师也熟悉 Material）
- 不选自定义系统：避免重复造轮子，企业后台不需要"惊艳到独一无二"

在 Material 3 基础上用品牌色（深绿+青绿）覆盖默认蓝色。

## 六、现状：前后端均已实现（全栈）

> 后端已落地（Spring Boot 3 + PostgreSQL，见 [ADR-006](../99-决策记录-ADR/ADR-006-后端栈选型SpringBoot+Postgres.md)）。
> HR（员工/部门/账号）与鉴权（登录/改密/权限）走**真实后端**并已端到端验证；
> 其余模块（工资/报销/通知/建议/生产等）仍为前端 Mock，待对应 Phase 接入。

| 维度 | 实现 |
|---|---|
| 数据 | HR/鉴权 = 真实 PostgreSQL（pgcrypto 字段加密）；其余 = 内存 Mock |
| 网络 | dio + Repository 接口（Auth/Employee/Department 为 Dio 实现，其余 Mock） |
| 认证 | Argon2id + JWT（access 15min + 不透明轮换 refresh + 重用检测）+ 路由守卫 + 首登强制改密 |
| 存储 | 偏好 shared_preferences；令牌 flutter_secure_storage |
| 加密 | 身份证/手机/银行/薪资 pgcrypto 字段级加密（密钥版本化 `v<version>:`）+ DTO 按角色脱敏 |
| 错误处理 | 统一错误码（ApiException），不泄露后端细节 |
| 架构 | Repository 接口模式，业务代码与数据实现解耦 |

## 八、版本与升级策略

- **Flutter SDK**：跟随 stable 频道，不追 beta
- **依赖**：每季度 review 一次，major 升级单独安排
- **Dart**：随 Flutter，不单独升级
- **lint 规则**：升级 very_good_analysis 后统一修复
