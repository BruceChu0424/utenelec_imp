# 2026-10-22 禁用货品与 BOM 联动验证

## 调研结论

原实现不满足禁用自动退出组装信息的要求。货品普通编辑、启停、批量启停和历史恢复
分别存在状态写入入口；物料分析和 MRP 依据未软删 BOM 行展开，不统一过滤禁用状态。
粘贴和导入还允许原清单已有停用组件保留。只修改选择器或单个状态服务会留下旁路。

实现决策见 [ADR-191](../99-决策记录-ADR/ADR-191-禁用货品自动退出当前组装清单.md)。
主工作区原有并行修改保留，没有整体 reset/clean、暂存、提交或发布。

## 实现范围

- V903 对状态变为禁用的货品统一清理所有当前 incoming BOM 引用，并一次性补清已有禁用引用。
  采用软删，保留原行、组件 UUID、数量、颜色和来源；不删除停用货品自己的 outgoing 配方。
- 按状态 UPDATE 语句汇总处理，同批禁用父子件也能原子完成。父件材料合计重新计算，版本始终推进；
  锁与事务回滚覆盖并发组装写入，任何失败不会留下半套结构。
- 新增、换件、恢复、粘贴和文件导入都不能重新引入禁用组件。学习候选和同步也尊重禁用状态；
  释放标记阻止重新启用时自动恢复原边，物理消耗和学习样本仍保留。
- 旧分析任意层级的失效组装引用、停用根产品、失效子来源锚点会显示明确原因并阻止新增安排。
  原材料行、采购/委外/领料/生产来源仍可核对；刷新继续经过原有已下达和专属库存兼容性保护。
- 最后一项生产物料因禁用而退出时，保留未解决的退役原因，防止变成零料生产。有有效生产配方
  保留或随后建立有效替代配方时记录解决时间，后续正常人工删料不再被陈旧事件误拦。
- 新承诺事务对分析源货品及所有层级的当前材料货品取得共享锁，与禁用互斥；只读详情不加锁。
- 移除组件的事件不会完成「BOM 已完善」任务。历史撤回重做也携带同样原因。
- V871 旧 BOM 历史 JSON 在运行时按新增列的 NULL 默认值规范化，不回写原始 before/after 证据。
  历史界面隐藏内部退役字段；真实的状态和组装变化仍沿既有历史显示。
