# 通用进度弹窗(导出 / 下载 / 批量等待)

> 2026-11-08 新增。代码在 `lib/components/feedback/uten_progress_dialog.dart`(基础组件层, 不依赖业务模块)。
> 背景: 货品资料全量导出等长等待原先只有转圈遮罩, 用户看不到进展也无法取消(2026-11-08 全量导出超时排查后立项)。
> 适用范围: **全项目所有导出、下载、批量下单 / 批量审批等长等待**; 一般保存、提交、读取等待仍用 [UtenBusyOverlay](UtenBusyOverlay.md)。

## 一句话

把「等一个可感知进度的长任务」做成公共件: 调用方只汇报**进度**(百分比 / 计数 / 未知总量), 弹窗统一渲染**大号百分比 + 圆角进度条 + 已用时间 + 取消**; 以后换进度样式只改这一个文件。

## 文件与公开 API

| 名称 | 作用 |
|---|---|
| `UtenProgressState{status, detail, fraction, done, total}` | 一次汇报的不可变快照; `fraction == null` 表示总量未知(扫动条, 不显示百分比) |
| `UtenProgressSession` | 运行中的工作向弹窗汇报进度的会话: `stage(status)` 未知总量 / `percent(0..1)` 比例 / `count(done, total)` 计数(自动派生百分比与「done / total」详情行) / `detail(text)` 只改详情行; `isCancelled` / `whenCancelled` 供调用方把网络 CancelToken 挂上 |
| `UtenProgressCancel.immediate / afterCurrent` | 取消语义: `immediate`=读取/下载类, 立即关弹窗返回 null, action 后续结果/异常都被吞掉; `afterCurrent`=写入类批量, **当前这一项办完再停**(不中断进行中的写请求, 避免结果变「未知提交」), 弹窗改「正在停止」并禁用按钮, action 看到 `isCancelled` 后不再开始下一项, 结束后**照常返回真实结果**(含已办成的部分), 调用方照常刷新与汇报, 不重放、不当作全部失败 |
| `showUtenProgress<T>(context, title:, action:)` | 弹窗入口。参数: `icon` / `initialStatus` / `initialDetail` / `cancellable`(默认 true) / `cancelMode`(默认 immediate) / `showElapsed` / `slowHintAfter` / `isCurrent` / `invalidation` / `onRouteOpened`。成功返回 action 结果; immediate 模式下用户取消返回 null(取消后的任何结果 / 异常都被吞掉); afterCurrent 取消后仍返回真实结果; 失败关闭弹窗并把异常原样抛给调用方 |
| `UtenProgressSession.bytes(received, total, status:)` | 字节传输汇报: 总量已知显示百分比与「12.4 MB / 38.1 MB」详情; 总量 ≤ 0(服务端没给 Content-Length)保持扫动条只显示已收大小 |
| `UtenProgressSession.receiving(status)` | Dio `onReceiveProgress` 的现成适配: 第一字节到达前保持当前阶段(服务端还在生成), 之后切到下载百分比 |
| `formatUtenBytes(int)` | 进度详情里的文件大小文案(B / KB / MB / GB, 一位小数), 全项目共用 |
| `UtenProgressBar(value:)` | 全项目唯一的**条形**进度样式: 有值时填充, `value == null` 时缓慢扫动; 弹窗与内嵌(下载页等)共用, **换进度条外观只改这里** |
| `UtenProgressRing(progress:, accent:, track:)` | 全项目唯一的**圆环**进度样式(2026-11-09 新增, 自绘圆环按 0..1 画弧, 圆头收笔); 更新页等待图标等圆环场景共用, 换圆环外观只改这里 |

## 弹窗行为

- 模态卡片, 圆角沿用主题对话框, 最宽 440; 点空白不关闭; 系统返回键 = 取消。
- 确定进度: 大号青绿百分比(等宽数字, 允许动画时平滑跳动)+ 阶段一句话 + 详情行(如「3,200 / 35,763 行」「12.4 MB / 38.1 MB」)。
- 不确定进度(服务端还没给出总量): 扫动短条 + 阶段标题顶住版面, **绝不显示伪造的百分比**; 靠扫动与已用时间表达「在动」。
- 已用时间「已进行 m:ss」每秒走字; 超过 30 秒显示「数据量大时需要一两分钟, 请耐心等待, 不用重复点」。
- 底部「取消」(ghost 按钮, 高 48 适老化触控基线): 点了**立即关闭弹窗**并返回 null; 调用方应监听 `whenCancelled` 把 CancelToken 挂到网络请求上让传输真正停下。
- 只关自己: 结束时上面压着别的根导航弹窗(如重新登录框)按路由精确移除, 不误关。
- 无障碍: 阶段与百分比作为 liveRegion 播报; 数字用等宽字不抖宽。
- **弹窗内不出现转圈**(契约测试钉死); 循环动画只有扫动条一处, 服从性能档(省电档静止)、系统「减少动画」和 `TickerMode`。
- 挂在根导航上, 不要与 `UtenBusyOverlay` 同时显示(遮罩会盖住它)。

## 用法

```dart
final file = await showUtenProgress<List<int>>(
  context,
  title: '正在导出货品资料',
  initialStatus: '正在生成文件',
  action: (progress) async {
    final cancelToken = CancelToken();
    final whenCancelled = progress.whenCancelled.then((_) => cancelToken.cancel());
    // 生成阶段: 总量未知, 扫动条。
    progress.stage('正在生成文件');
    final bytes = await api.downloadBytes(
      '/master/goods/export',
      cancelToken: cancelToken,
      onReceiveProgress: (received, total) => progress.percent(
        total > 0 ? received / total : 0,
        status: '正在下载文件',
        detail: '${(received / 1e6).toStringAsFixed(1)} MB'
            ' / ${(total / 1e6).toStringAsFixed(1)} MB',
      ),
    );
    return bytes;
  },
);
if (file == null) return; // 用户取消, 不提示
```

计数型(批量审批逐单提交): 每完成一项调 `progress.count(done, selected.length, status: '正在提交审批')`。

## 身份失效与页面守卫(2026-11-08/09 增补)

- `invalidation` + `isCurrent`: 与 `runUtenBlockingTask` 同口径。身份、账号或服务器切换使 `invalidation` 发出通知且 `isCurrent()` 为 false 时, 弹窗按取消收尾(会话 `whenCancelled` 完成, 网络请求随之停下), 不再呈现旧身份的结果。
- 常用失效源: `FormDraftMixin.formDraftIdentityInvalidation`(草稿页身份/服务器切换时自增的惰性 ValueNotifier, 随 mixin dispose 释放); 仓库任务守卫页自建 `ValueNotifier<int>` 并在守卫回调里自增; 数据属主 epoch(如 `exportContextEpochProvider`)用 `ref.listenManual` 接一只 ValueNotifier。
- `onRouteOpened(route)`: 弹窗路由推入后回调(重建时回调最新路由)。用 `route.isCurrent` 之类「页面在顶才有效」响应守卫的页面, 用它登记弹窗路由——**自己推起的进度弹窗压顶不算「其他页面」**, 别的页面推到弹窗之上时路由不再是 current, 守卫照常拦截(同 account 工作台 `_batchDialogs` 口径)。
- **action 在调用方 Zone 里执行**(组件内 `callerZone.run`): `AuthenticatedRequestScope.run` / `BusinessPrecisionTransport` 靠 `Zone.current` 传递, 弹窗的 post-frame 启动不会把它们丢掉。曾因此修掉一个真 bug: 弹窗脱离 scope zone 后 same-login 换凭证的写请求不被身份栅栏拦住(多发了 1 条写)。在 `scope.run` 内打开弹窗自动受益, 调用方无需额外处理。

## 批量操作的两种接法(2026-11-08/09 定稿)

- **单请求型**(一次 POST 带全部选中项, 如各审批中心批量通过): `cancellable: false`, 扫动条 + 已用时间。一次已提交的事务无法真正取消, 不提供误导性的「取消」。
- **循环型**(逐单/逐份/逐人往返, 能显示真实百分比): `cancelMode: UtenProgressCancel.afterCurrent` + `progress.count(done, total)`, 循环顶部检查 `progress.isCancelled` 后 break。做法示范: `currency_page._runCurrencyBatch`(带 owner 失效源 + onRouteOpened)、`hr_task_list_page._batchConfirm`(无守卫页)、A 组各仓库批量页(2026-11-09 迁完: 生产退料收料/库存出入库/销售出库核对/委外领料出库/车间料仓领退料/访客/员工资料修改/采购退回确认/车间批量开工与设路线)。
- 主档批量启停/删除走共享入口 `lib/features/basic_data/widgets/master_batch_progress.dart`(`invalidation: owner` + `onRouteOpened: owner.trackRoute`), 不在页面里各写一份。
- 取消/部分完成的收尾口径: 照常呈现已办结果并提示「已按要求停止, 其余 N 项未处理」; 已成功的写入不回滚、不重放; 未知提交保护(幂等键、`runFormDraftSubmission` 等)原样保留。

## 注意

- 取消是「用户不再等」, 不是「服务端回滚」: 同步导出在服务端可能已经生成, 调用方取消后不得把任何结果再弹给用户; 后台任务(如导出任务)另有服务端取消接口, 由调用方在 `whenCancelled` 里调用。
- 未知总量时不编造进度, 也不用 0.04 之类的假下限充数。
- 与 `UtenBusyOverlay` 的分工: 可感知进度的长等待(导出 / 下载 / 批量操作)用本弹窗; 普通保存、命令、读取等待继续用 UtenBusyOverlay。同一动作只用一个等待件, 不叠遮罩。
- 文案走 `progressCancel` / `progressElapsed` / `progressSlowHint`(zh / en / ko 同步登记)。

## 同步导出的服务端进度协议(2026-11-08)

- 请求头 `X-Uten-Export-Operation`(UUID): `ExportRateLimitInterceptor` 见头登记, `afterCompletion` 注销。
- 端点 `GET /api/exports/progress/{operation}` → `{rows, total, phase}`; 只能读本人的; **未开始或已结束返回 204**(不是 404——404 会被审计记成失败操作), 客户端 `_SyncExportCurve` 对空快照保持当前进度。
- 汇报点: `MasterExportSource` / `ReportQueryKit.paginateAll` / `AuditQueryService.export` 等汇报 `announceTotal` 与 `rows`; `XlsxExportService` 汇报 `PACKAGING`; `WorkbookDownloadService.protect` 汇报 `ENCRYPTING`。
- 后台导出任务带 `totalRows`(迁移 V1125), 任务弹窗总数已知时显示百分比与「已处理 N / 总 行」。
- 事务时限统一 `ExportTransactions.TIMEOUT_SECONDS = 120`(2 分钟); `FulfillmentHttpDeadlineFilter` 豁免导出与下载端点。详见 ADR-198/199。
