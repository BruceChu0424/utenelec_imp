# ADR-180：进行中与历史单据按真实业务生命周期分流

- 日期：2026-10-15
- 状态：已接受；本轮为源码修复，发布和服务器安装另行验收。
- 修订：ADR-066 的旧完成态分类；保留 ADR-178 的可清除筛选与父类恢复规则。

## 决策

正常任务分类仅展示尚需处理、正在履约或等待后续办理的记录。已完成、已办结、已过账且无剩余作业、撤销及取消等终态进入明确的“历史单据”入口。保留原单、来源、审计及合法反向操作，不删除库存流水，不伪造办结或重新打开业务。

审批状态与业务生命周期分别判定：已审但未履约的订单、待付款的已批准报销、待发布的已通过工资、部分领料及待实收继续属于活动业务。退回后尚需更正或重新审批的业务保留可到达的入口；审核记录的历史不能掩盖独立后续任务。

分流在服务端授权查询及分页之前实施，同一谓词约束结果、总数和筛选桶。不得先取一页再由客户端删除完成行，不以 `canHandle` 代替生命周期：只读员工仍能看到有权读取的未来任务。

历史入口不挂待办红数。正常分类清除筛选后恢复活动父类；历史清除筛选后保持历史父类及日期、仓库、本人和部门范围。切换范围使旧请求及跨页选择失效。既有全状态审计浏览可在明确的历史入口保留，不能作为正常分类的无约束“全部”。

## 逐业务链边界

| 页面与业务链 | 正常分类 | 历史及保留事项 |
|---|---|---|
| 仓库入库/出库 | 等登记、待检、部分检查、待实收、部分领料、待退回和异常后续作业 | 已入/出库、登记办结、取消和撤回；车间内料仓实物凭证保留，已完成凭证不冒充普通仓库待办 |
| 仓库品质结果 | 非 COMPLETED，等待结论也是进行中 | COMPLETED；采购/委外、责任仓范围不变 |
| 内料仓领退料与盘点 | PENDING；内料仓页面增设待处理入口 | DONE/CANCELLED；历史可分别查看领退料与盘点单据 |
| 原生仓库单据与旧领退料入口 | 草稿、真正未发完未关闭的已审 DRAW；WDRAW 草稿仍待仓库实收 | 普通库存单过账、WDRAW 实收、DRAW 完成及撤回；不自动放开软删除可见性 |
| 盘点审核 | 审核队列只保留 PENDING，本人待更正仍可达 | 审核通过、驳回决定、撤回；审核归属和所选仓范围不变 |
| 品质待检/FQC | PENDING/PARTIAL，部分决定仍未完 | RESOLVED/CANCELLED；检测记录是独立事实查询 |
| 采购/委外 | 尚未分解完的申请、未履约订单和分批作业；最新待财审/退回优先保留 | 完全分解、真正结束/停止/撤回；不能仅凭物理关闭隐藏财审待办 |
| 销售报价/订单/出货 | 待核价、待客户、待转单、未完成订单、待财审和待仓库 | 已转单、已出库、完成、停止和撤回；订单进度按真实未排/未产/未发数量判断 |
| 生产计划/日报/车间任务 | 草稿、未结束正式计划、在制及待报工/待确认 | 计划关闭、中止、取消、反审及已正式完成日报；不能把中止伪装完成 |
| 财务凭证/审核/报销 | 草稿凭证、待审/退回需办、已批准未付款报销 | 已过账凭证、已完成审核记录、已付款报销；独立后续履约仍保留 |
| 工资批次 | DRAFT/SUBMITTED/REJECTED/APPROVED | PUBLISHED；翻页、刷新和迟到响应保留当前范围 |
| 访客三个列表 | 申请、接待人确认、批准待到访 | checkedIn/rejected/cancelled；本人、接待人、HR 部门及筛选桶同源 |
| 本人资料变更/HR 审核 | 整批仍有 pending 即保留待办，不因部分字段已结束隐藏整批 | 整批已生效/拒绝/撤销；本人、员工、部门范围及批次分页同源 |
| 人事生日/周年关怀 | 未发布祝福的当前及即将到来名单；已祝福不再可认领、释放或批量发送 | 从真实通知与主角快照查询跨日、跨年发布历史，按发布时间分页；原通知可见性与生日 PII 权限不变，不用当前生日或发布时间冒充未留存的纪念日期 |
| 研发任务 | OPEN/IN_PROGRESS | DONE/CANCELED；沿用正确分流，统一历史文案 |
| 官网询盘工作台 | new/following；普通全部仅聚合进行中 | converted/closed；在分页及总数前分流，保持原共享收件箱权限和跟进人 |

报表、主档、库存现存、原单详情、审计及明确历史查询不是待办队列，不因本决策隐藏合法事实。已有正确边界的任务入口保留原业务协议，不另造通用状态机。

## 查询与验证

仓库任务、品质结果、内料仓领退料和原生库存单据使用 `view=ACTIVE/HISTORY`；公开查询拒绝 `ALL`，内部详情仍经原权限读取记录。库存模块不反向依赖仓库模块。FQC/盘点旧接口新增 `status=HISTORY` 聚合，工资新增 `status=ACTIVE/HISTORY`；访客集合与采购/销售/生产权威履约规则在分页前处理。共享展示组件只统一分类，不定义业务状态。

本轮不新增数据库结构，不改已应用 Flyway、权限目录或公司业务数据。按链路运行 Flutter 行为/分页/筛选恢复回归、后端权限及隔离 PostgreSQL 回归。滑窗用实际 Flutter 渲染验证桌面、窄屏、数字与按钮对齐、36px 桌面分类行和至少 48px 触屏命中区。
