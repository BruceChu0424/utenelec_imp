# ADR-139：销售报价议价、客户确认与货品报价历史

- 日期：2026-10-02
- 状态：本地实现；上线前须执行候选版本检查、迁移与真实岗位验收。
- 依据：用户本次明确要求销售可以修改报价单的价格与折扣，不修改货品资料；财务核价后仍须征得客户同意。
- 替代：ADR-134 中“销售报价永不改价”和“财务确认后即可转订货”约定；订货单锁价、AI 基础资料学习与公共权限约定继续有效。
- 迁移：V788，仅前向新增；不改已应用迁移字节。

## 业务流程

新建报价 → 保存 → 提交财务核价 → 财务认领、修改或退回 → 财务确认 → 销售与客户沟通 → 登记客户同意当前版本 → 生成订货草稿 → 检查并保存 → 沿用订货审查、提交和财务审核。

客户未接受时，销售可重新修改报价再提交，或填写取消原因结束本次报价。财务也可在未转单前撤销核价重新处理。任何重新修改、提交或财务撤销确认都会使旧客户确认失效。

报价与订货使用同一套表头信息和公共明细表格。报价阶段可以提出单据价格、折扣和数量；订货单继承双方确认的价款并锁价。生成订货草稿不等于订单已审核，更不会跳过信用、条款、库存或履约检查。

2026-10-03 表头对齐补充：报价与新建订货的共同字段顺序一致，报价有效期放在共同信息之后。选择客户自动带入客户主档默认结账方式，业务员默认当前登录员工，报价币种自动显示本位币；未核对默认值随客户更新，人工值和已保存单据快照不被覆盖。默认条款读取不再依赖订货查看权限，同时复核客户可读范围及启用状态。

## 状态与动作

保留原状态码：0 草稿／财务退回，2 待财务核价，1 已核价，-1 取消／旧作废。以附加事实区分已核价报价的下一步，不重写历史状态码。

| 阶段 | 下一步 | 约束 |
|---|---|---|
| 未提交草稿 | 销售编辑、删除、提交或取消 | 编辑、删除、提交绑定当前修订号 |
| 待财务核价 | 财务认领后修改、退回或确认 | 本人有效认领 + 当前版本；销售不能并发覆盖 |
| 财务退回 | 销售修改、重新提交或取消 | 退回原因和历史保留，不再允许当作新草稿删除 |
| 待客户同意 | 销售登记客户接受、重新修改或取消 | 财务已确认；报价未过期且未转单 |
| 待生成订货单 | 生成订货草稿 | 客户确认版本等于当前版本；仍检查有效期 |
| 已转订货 | 查看关联订单 | 任意来源订单引用都冻结原报价，含已删或红冲订单 |
| 已取消 | 只读查阅 | 原因、操作人、时间和修订快照保留 |

“登记客户同意”是销售记录客户反馈，并非系统代客户作决定。既有已核价但未转单的报价不会凭迁移补造客户同意，须由销售实际确认。

若已生成订单后财务不接受，销售先按订单原有规则处理订单。订单未安全终止时禁止重新报价；原订单已红冲或删除后，可复制为关联新报价重新议价。新报价保留来源 UUID／可读单号，原报价、订单、财务及履约历史不覆盖。重复点击复用同一有效重议价单。

## 定价、修订与权限

- 报价行价格来源增加 `SALES`，与 `MASTER`、`FINANCE` 区分。销售手工提出的价款只写报价明细；不更新 `goods.price`。金额继续由服务端精确派生。
- 无价格查看权限者不能通过直接 API 写入价格、折扣或价款扩展列；读取报价版本快照也要脱敏。
- 财务可以修改单价、折扣和数量或删除货品行；删除不能使报价变成空单，错误请求整笔回滚。修改须保存后才可确认。
- 每次销售编辑、提交、财务修改、退回、确认、重开、客户同意、取消、转单追加不可变快照。
- 报价销售详情与财务核价详情共用逐格修订表：相同行以稳定明细 ID 匹配；只有变化格显示红色旧值删除线，表尾增加对应字段的新值红字列；整行删除才整行划去。换货不以显示行号冒充同一货品。
- 服务端 `allowedActions`／`financeActions` 决定可办动作，权限码、对象写范围、修订号和认领在写事务内再次核对。
- 报价批量删除保留用户选中时的版本；删除前重读状态，但不能用新读出的版本替换原选择版本来绕过冲突。

## 货品资料中的报价记录

货品详情新增“报价记录”页签，需要 `goods:view` 与 `sales_quote_finance:view`。仅能查看货品售价的普通人员不因此获得客户商业历史。

分页读取不可变 `SUBMIT / FINANCE_EDIT / CONFIRM` 快照，显示时间、业务员、客户、报价单号、版本／环节、数量、单价、折扣、金额与当前关联订货单。已从当前报价删除的货品行仍可查到旧记录，客户与销售人员使用当时快照。老快照未保存身份的字段明确显示“历史未记录”，不得用报价目前的客户或人员回填。订单关联必须与快照客户一致，避免换客户后把旧价格关联到新客户订单。

双击或“查看单据”打开有权限的关联订货单；没有可访问订单时打开本次不可变报价快照，不借此让财务读取销售尚未重新提交的当前草稿。当前界面不提供修改货品售价的旁路。查询使用快照 GIN 索引预筛货品，之后展开匹配行并按时间分页。

## 任务中心与通知

销售任务中心保留报价大类，新增“待客户同意”“待生成订货单”分段。两个红色徽章分别来自 `salesQuote.awaitingCustomerConfirmation`、`salesQuote.awaitingConversion`，互斥且只计算可办范围；财务待核价继续使用既有 `financeQuoteReview`，在销售端显示黄色进行中。模块容器只汇总注册入口，不重复累加页内分段。

财务确认通知改为“待客户确认”，不再引导跳过客户确认直接转单。提交、取消、撤回和核价办结继续沿用事务内通知及待办撤回机制。

## 客户模板

下载发现客户没有模板时，引导上传 Excel 学习模板，也保留标准格式下载。复用公共 AI 后台作业、文件解析、认列、工作表选择和进度／取消能力；模板模式允许空白明细模板，不需要先导入货品。

用户核对工作表与字段映射后采用模板。采用接口核对上传人、原报价、原客户、任务用途和当前访问权限，锁定报价防止上传过程中客户变化。学习沿用私有模板存储、版本与证据幂等规则，并把确认映射记入既有版式学习机制，不学习价格、不写货品和客户主档。

客户模板下载保持客户列顺序；标准格式下载继续遵守全平台列投影。模板不直接执行来源文件公式、宏或外部链接。相似版式更新版本，不同版式可并存选择，继续上传可持续修正版式。

上传支持 15 MiB 以内的 xlsx／xls，保留清洁版式的列宽、样式、合并等信息，不承诺源文件图片、宏或任意公式逐像素重现。未配置 AI 或没有 AI 权限时，常见表头仍可通过规则识别；规则不能确定的陌生表头明确报错，不猜测填入。多模板可选择并打包 ZIP 下载。

## 验证范围

以相应代码测试报告为准：报价真实 PostgreSQL 状态流与锁、字段修订与整行删除、客户确认失效、未确认／过期禁止转单、重复生成与重议价、取消及删除、遮罩越权、客户模板绑定／幂等／失败重试、货品快照历史、徽章、大小屏界面与异步旧响应。

本地自动化通过不等于 CI、安装包或服务器已经升级。真实销售／财务两个岗位、实际客户样本文件与实际 AI 服务商仍需在目标环境验收。
