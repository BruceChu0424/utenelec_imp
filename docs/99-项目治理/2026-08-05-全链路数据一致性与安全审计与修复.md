## 一、总体结论

链路**比文档"NO-GO"框架在数据完整性轴上更稳健**：多处被标 🔴/未闭合的能力，逐行读码后确认**已正确实现**。本轮修复了 3 个 P0 与若干 P1，并落地了统一任务并发控制后端基础设施。剩余项为已记架构缺口（委外守恒/IQC/WMS）与本轮识别的 P1/P2 路线图。

## 二、正面修正（审计确认"其实是对的"）

1. **MAKE 父需求回供 peg 数学正确无泄漏**（文档称"未闭环"）：`createMakeSupplyPegs` 严格 + `unwindPromotedSegment` 对称反 `consumed_qty`。
2. **库存台账 `balance=Σmovements` 由构造保证成立**：单一写入瓶颈 `StockService.recordMovement→upsertBalance`，`stock_movements` 应用层 append-only，`InventoryMutationLock` 稳定锁序，多仓键正确——**无重复计数**。
3. **四数量系统(reserved/planned/produced/shipped)端到端一致**：iqty≤fqty≤qty、produced≤allocated、inbound≤produced、shipped≤reserved 均强制。
4. **采购腿基本健康**：超收不双重入库、超收双层守卫(应用+DB触发器)、AP 一次且服务端重算、sibling 收货挡、红冲对称。
5. **AR/AP 金额服务端权威重算**（代理一度报"客户端可控"，经复核推翻）：出货 `normalizeCommercialLine→authoritativeShipmentAmount` 按来源订单比例重算并清注入字段；采购 PO 侧重算 qty×price×rate。
6. **SQL 注入全扫零风险**；审计完整性范例；鉴权/模拟身份/导出防御稳健；自制叶子件无 BOM 正确不拦截。

## 六、安全结论

安全地基**扎实**：SQL 注入全扫零风险（参数化+白名单）、审计完整性范例（触发器写+REQUIRES_NEW insert-only+V190 fail-closed sweep）、鉴权稳健（Argon2id+JWT 最小化+每请求重读+refresh 轮换重用检测）、模拟身份写守卫 robust、导出五道防线齐（本轮补齐第六道：公式注入防御）、对象级授权在 Sales/Payroll/ExpenseClaim 等已正确强制。剩余：TOCTOU（本轮修了 3 处，5 处已有 M28）、HrTask PII（本轮修）、财务对象范围（路线图）。

## 七、任务并发控制（详见 ADR-023）

用户问题"一人处理待办时他人该不可见还是标注处理中"——调研结论：**show-as-locked（显示"XX 处理中"且他人禁用），不隐藏**。理由：可审计性/接管/maker-checker/问责。已落地统一 `task_claims` 后端（V215 + 服务/控制器/策略），复用已验证的 `HrTaskClaim` 范式。下一步：逐面集成（T1 费用审批+采购分解）+ Flutter"处理中"徽标组件。

## 八、跨腿主题（数据正确性最集中的薄弱面）

1. **红冲对称性**是最大张力点：movable 闸挡红冲(KS-P1-1)、锁序倒置(KS-P1-2)、损耗负数(已修)、财务 TOCTOU(已修) 都在红冲/审核路径。
2. **财务过账结构性洞**：GL 非实时+银行转账不入 GL+无平衡 CHECK+postArAp 汇率——报表准确性依赖手动批且银行漂移。
3. **委外是数据完整性最弱腿**：守恒结构性不可强制 + 多处无上限（本轮修了上限）+ 回厂不消费发料——属已知大建设。
4. **任务并发控制全链缺失**（本轮落地基础设施）：除 HR 外无通用认领/可见性/防重复。
5. **安全地基扎实**：唯公式注入(已修)+TOCTOU(部分修)+PII(已修)/对象范围(路线图)三处需补。
