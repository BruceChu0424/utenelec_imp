# 候选库运行权限对齐契约

完整执行迁移不等于运行账号已经获得正常业务权限。正式迁移器只负责迁移及属主保护；
`LocalRuntimePrivilegesCallback` 仅在 dev、回环地址、固定 `uten_imp` 和分离角色组合下运行。
候选库不得通过启用 dev、改数据库名称判断或搬入其它数据库 ACL 来绕过这个边界。

唯一授权规则仍是 `server/src/main/resources/db/local-runtime-privileges.sql`。固定本地 dev
继续由原回调读取它；非标准名称的受审候选只能通过
`server/ops/reconcile-runtime-privileges.sql` 在一个事务中绑定身份后相对引用同一文件。
没有第二份可执行的保护名单，没有新增 Flyway 迁移或运行时数据库函数。

执行身份必须是直接登录的非超级用户 `uten_migrator`，`session_user=current_user`。
实际数据库 owner 必须是这个角色；public schema 可由它直接拥有，也可由
`pg_database_owner` 拥有，但后者仅在当前数据库实际 owner 同为 `uten_migrator` 时接受。
这是 PostgreSQL 16 的标准 template0/public 所有权模型，未变更 schema 或对象 owner。
参见 [PostgreSQL 16 predefined roles](https://www.postgresql.org/docs/16/predefined-roles.html)。

授权规则保留正常业务表 SIUD、只读业务视图、审计父表 SELECT/INSERT、历史来源凭据
SELECT、Flyway/私有关系和分区禁止直接访问等已有区分。不能因为某表有 immutable trigger
便一律改成 SELECT-only：原生台账仍需合法 INSERT，后续不可改行为由既有触发器继续约束。
V928 的 `stock_measurement_holds` 明确为 SELECT-only；其捕获和原计量依据核验函数不向
运行账号开放。已有导入、审计治理、维护和退役入口例外全部保留。

运行代码使用的序列仅需 nextval/default；授予 USAGE，不授予可重置序列的 UPDATE、
直接序列读取或授予选项。普通函数只处理实际由迁移 owner 拥有的对象。postgres/可信扩展
所属函数已有的 PUBLIC EXECUTE 保留，不为消除无权 GRANT 警告而开放管理员对象。
不具备授权权力的私有入口若仍向 app 暴露，整次对齐失败并回滚。

对齐只重建 PUBLIC 与 `uten` 在受管理对象上的权限；其它显式角色授权保留。
所有撤销使用 RESTRICT，拒绝级联删除其它主体的授权依赖。当前数据库内该 owner 的默认
授权同步为普通业务权限；数据库和 public 的 CREATE、表 TRUNCATE/REFERENCES/TRIGGER、
列级绕过与授予选项均作有效权限核验。数据库 CONNECT/TEMP 与 schema USAGE 若已有
未审查的授予选项，入口在任何 GRANT 之前拒绝，不自动改写未知委托关系。
没有全局角色属性、成员关系、密码或所有权修改。

## 受审执行步骤

本步骤由维护人针对准确候选执行；本文件本身不授权修改现役库。先独立核对并记录候选的
数据库名称、OID、集群 system identifier、实际数据库 owner，以及已验证的完整迁移目录。
不要由脚本连接后自动发现参数并当作独立批准。候选入口拒绝 `uten_imp`、postgres 和模板库。
维护连接须已能读取 `pg_control_system()`；此工具不替管理员补这个 catalog 函数权限，也不把
该信息函数视作 app 必须不可执行的私有入口。它的既有 ACL 保持不变。

保留并核对授权方提供的以下两个文件 SHA256，以及当前候选的全量业务数据指纹、角色属性、
成员关系、对象 owner、函数/触发器定义与 Flyway 历史快照：

- `server/ops/reconcile-runtime-privileges.sql`
- `server/src/main/resources/db/local-runtime-privileges.sql`

从完整、已验摘要的源码目录运行；凭据沿用维护人的受保护 PGPASSFILE，不放入参数或日志：

```sh
PGPASSFILE=/path/to/existing-private-owner.pgpass \
psql -X -v ON_ERROR_STOP=1 -h /approved/postgresql/socket -p 5432 \
  -U uten_migrator -d EXACT_CANDIDATE_DATABASE \
  -v expected_database=EXACT_CANDIDATE_DATABASE \
  -v expected_database_oid=INDEPENDENTLY_VERIFIED_OID \
  -v expected_system_identifier=INDEPENDENTLY_VERIFIED_CLUSTER_ID \
  -v expected_owner=uten_migrator \
  -v runtime_acl_confirm='RECONCILE CANDIDATE RUNTIME ACL EXACT_CANDIDATE_DATABASE' \
  -f server/ops/reconcile-runtime-privileges.sql
```

入口要求每个参数；任何名称/OID/集群/owner/确认语不符、角色危险权限、未完成退役、保护
无法封闭或授权依赖不能安全撤销，都以非零状态退出。该事务失败不会留下部分业务授权。
固定 dev 的 `uten_imp` 沿原规则保留 CONNECT/TEMP。候选入口则在同一事务 COMMIT 前
明确撤销 PUBLIC 与 `uten` 的 CONNECT，并核验 app 有效 CONNECT 为 false；中间的授权
不会对外提交，因此结束后自然保持离线，新 app LOGIN 被拒绝。不要把对齐成功误报为
激活或业务验收完成；最终切换另需受审的开放 CONNECT 步骤。

独立使用真实 `uten` LOGIN 验证 `session_user=current_user=uten`；不能用管理员 `SET ROLE`
冒充 app，因为 V926/V928 等守卫检查 session_user。可以在仅自有隔离测试库中先建立一个
真实 app 连接，立即撤销新 CONNECT，再在这个连接中做回滚式正反检查。候选入口继续
保持新 CONNECT 关闭，既有验证 session 仍能验证已对齐的对象权限。

正向核验包括正常 goods 新建/读取/修改/软删除、普通来源凭据读取、serial nextval、审计追加、
既有受审报表函数。负向核验包括来源证明和计量凭据写入、Flyway/审计历史修改、维护函数、
DDL、TRUNCATE/TRIGGER 与授予选项。goods 的删除按现有软删除业务生命周期核验，
不把物理删除原始证据当作权限成功条件。所有原始业务行、用户和角色指纹应保持不变。

## 验证边界

`server/ops/test_local_runtime_privileges.py` 覆盖独立 PostgreSQL 16、身份错配回滚、标准
`pg_database_owner`、受保护表/列/PUBLIC 权限、未来普通对象、序列最小权限及外部 owner 函数。
`ScopedRuntimePrivilegesPostgresTest` 使用完整当前迁移目录创建新的私有模板和独立候选，
通过真实密码认证的 `uten` 会话验证权限，并比较全量业务表行指纹、角色/成员关系、owner
和函数定义。原 dev 回调及实际 HTTP 启动测试仍单独保留。

这些测试不会连接或更改公司库、旧本地库或服务器；真实数据候选仍须由交接方独立核对其
精确身份和前后全量指纹。此处没有修改任何已应用迁移，也没有执行角色 bootstrap/hardener。
