# 09 - 组件库使用规范

> 🧩 **本规范全局强制。** 所有业务页面的 UI 必须用 `Uten` 组件库，
> **禁止业务代码直接堆 `Container/SizedBox/Padding/Card/Button/TextField`**（除非是组件库内部实现）。
>
> 配套准则：
> [08-主题与配色.md](08-主题与配色.md)（颜色由主题驱动，组件内部不硬编码）、
> [02-响应式与多端适配.md](02-响应式与多端适配.md)、
> [03-自适应布局组件.md](03-自适应布局组件.md)、
> [07-性能自适应.md](07-性能自适应.md)（性能档统一在组件层处理）。

---

## 一、设计目标

| 目标 | 说明 |
|---|---|
| 视觉统一 | 一套组件库 = 一套视觉语言，避免每个页面各画各的 |
| 改一处全屏生效 | 调字号、调颜色、调间距，只改组件库，所有页面自动跟随 |
| 响应式统一处理 | 断点（compact/medium/expanded）的判断收敛到组件内部 |
| 性能档统一处理 | lite/standard/rich 的降级（模糊、动画）收敛到组件内部 |
| 主题统一处理 | 浅色/深色切换、颜色取色统一在组件内部用 `colorScheme` |
| i18n 友好 | 长文本不被截断，组件预留 ellipsis / 多行 |

---

## 二、为什么必须用组件库

| 不用组件库的痛点 | 用组件库的收益 |
|---|---|
| 同一个按钮，10 个页面 10 种圆角 10 种颜色 | `UtenButton` 一处定义，所有页面一致 |
| 性能档切换要改业务代码 | 组件内部判断 `PerfTier`，业务无感 |
| 主题切换后某些页面颜色不对 | 组件统一走 `colorScheme`，主题切换全屏生效 |
| 响应式布局靠散落的 `if/else` | 组件内部用 `LayoutBuilder`，业务只传语义参数 |
| 改设计要全局搜索替换 | 改组件库一处，全局自动跟随 |
| 新人不知道间距该写多少 | 组件约束了 padding/间距 token |

> 一句话：**组件库是项目视觉与交互的"宪法"**，业务代码只是"用法"。

```dart

UtenStatCard(title: '本月产量', value: '12,580', trend: 0.12);
```

## 四、Phase 0 核心组件清单（必须先实现）

> Phase 0 = 在写任何业务页面之前必须先做完的组件，共 **12 个**。

| # | 组件 | 一句话用途 |
|---|---|---|
| 1 | **UtenButton** | 主按钮/次按钮/幽灵/危险四种风格，支持 loading、small/medium/large 三尺寸 |
| 2 | **UtenCard** | 通用卡片，支持实心/轮廓/玻璃拟态，玻璃模糊由性能档决定 |
| 3 | **UtenInput** | 文本/密码/搜索输入框，内置客户端校验（必填、长度、正则） |
| 4 | **UtenStatCard** | 数据卡片：数值 + 趋势 + 图标，Dashboard 万金油 |
| 5 | **UtenScaffold** | 响应式外壳：compact 走底部 Tab，medium/expanded 走侧边 NavigationRail |
| 6 | **UtenAppBar** | 自适应顶栏：compact 单行，expanded 可放大标题/操作区 |
| 7 | **UtenEmpty** | 空状态：可配图标 + 文案 + 主操作按钮 |
| 8 | **UtenSkeleton** | 骨架屏：性能档 lite 关闭闪烁，standard/rich 启用 shimmer |
| 9 | **UtenAnimatedNumber** | 数字滚动动画（rich 档才动，standard 直接 fade，lite 直接显示） |
| 10 | **UtenThemeSwitcher** | 主题切换 UI（浅色/深色/跟随系统三选） |
| 11 | **UtenLocaleSwitcher** | 语言切换 UI（中文/English） |
| 12 | **UtenFontScaler** | 字号档位调节 UI（小/中/大/超大） |

每个组件对应一份文档，放在 [../02-组件库/](../02-组件库/) 下，命名 `UtenXxx.md`。

## 五、何时应该新增组件

满足以下**任一**条件，就该抽象成 `UtenXxx` 组件：

| 条件 | 例子 |
|---|---|
| 同一段 UI 在 **3 处以上**重复 | "员工头像 + 姓名 + 工号"卡片 |
| 有**响应式/性能档**需求 | 列表项需根据断点切布局 |
| 有**复杂交互** | 多步骤上传、可拖拽排序 |
| 有**统一视觉规则** | 所有"危险删除确认"对话框 |
| 是业务**原子单元** | "金额展示"、"日期范围选择" |

不满足上述条件的，先用 `Container + Uten 组件` 组合，重复出现后再抽象。

---

## 六、新增组件的流程

```
1. 先写文档       → 02-组件库/UtenXxx.md（按第八节模板）
2. 评审通过        → 确认 API、响应式、性能档行为
3. 实现           → lib/components/<分类>/uten_xxx.dart
4. 加到 barrel     → lib/components/uten_components.dart export
5. 加到组件总览    → 02-组件库/组件总览.md
6. 写示例         → 02-组件库/UtenXxx.md 的"示例代码"小节
7. 写测试         → test/components/uten_xxx_test.dart
```

> ⚠️ **顺序不能颠倒**：先写文档再写代码，避免"先实现再补文档"导致 API 难用。
> 文档是组件的契约，实现必须服从文档。

---

## 七、何时不用组件库

| 场景 | 做法 |
|---|---|
| 业务特定的页面级布局 | 页面级可以用 `Container/Column/Row` 组合，但**嵌入的原子单元仍要用 Uten 组件** |
| 一次性 Demo / 原型 | 同上，原子单元仍走 Uten |
| 组件库内部实现 | 自由使用 `Container/Padding` 等 |

> 判定原则：**"这一块会不会在别的页面再次出现？"** 会 → 抽组件；不会 → 直接写。

## 九、核心组件用法速查

### 9.0 UtenActionButton（异步动作按钮，**首选**）

```dart
UtenActionButton(
  type: UtenActionButtonType.primary,
  isExpanded: true,
  icon: Icons.check_rounded,
  label: Text(l10n.submit),
  loadingLabel: Text(l10n.submitting),
  onAction: () async {
    await api.submit();
    if (context.mounted) {
      context.appSuccess(l10n.submitSuccess);
      context.pop();
    }
  },
)
```

按钮自带 loading 状态 + 防连点——按"等待回执"模式自动锁。

### 9.1 UtenButton

```dart
// 主按钮
UtenButton(
  variant: UtenButtonVariant.primary,
  size: UtenButtonSize.medium,
  loading: _saving,
  onPressed: _save,
  child: Text(l10n.save),
);

// 危险按钮
UtenButton(
  variant: UtenButtonVariant.danger,
  icon: Icons.delete_outline,
  onPressed: _confirmDelete,
  child: Text(l10n.delete),
);

// 幽灵按钮（无边框）
UtenButton(
  variant: UtenButtonVariant.ghost,
  onPressed: () => Navigator.pop(context),
  child: Text(l10n.cancel),
);
```

### 9.2 UtenCard / UtenStatCard

```dart
// 实心卡片
UtenCard(
  child: Padding(
    padding: const EdgeInsets.all(16),
    child: Text('内容'),
  ),
);

// 玻璃拟态卡片（深色 + standard 以上档自动启用 blur）
UtenCard(glass: true, child: ...);

// 数据卡片
UtenStatCard(
  title: l10n.monthlyOutput,
  value: '12,580',
  unit: l10n.units,
  trend: 0.12,            // +12% 显示绿色↑
  icon: Icons.trending_up,
);
```

### 9.3 UtenInput（带校验）

```dart
UtenInput(
  label: l10n.username,
  type: UtenInputType.text,
  validator: (v) {
    if (v == null || v.isEmpty) return l10n.required;
    if (v.length < 3) return l10n.tooShort;
    return null;
  },
  onSaved: (v) => _username = v,
);

UtenInput(
  label: l10n.password,
  type: UtenInputType.password, // 默认隐藏 + 可见切换
  validator: (v) => (v == null || v.length < 8) ? l10n.pwdTooShort : null,
);
```

### 9.4 UtenScaffold（响应式外壳）

```dart
UtenScaffold(
  currentRoute: '/dashboard',
  items: [
    UtenNavItem(route: '/dashboard', icon: Icons.home, label: l10n.dashboard),
    UtenNavItem(route: '/employee', icon: Icons.people, label: l10n.employee),
    UtenNavItem(route: '/payroll', icon: Icons.receipt, label: l10n.payroll),
  ],
  child: ...,
);
// compact：底部 NavigationBar；expanded：左侧 NavigationRail（自动切换，业务无感）
```

### 9.5 UtenEmpty / UtenSkeleton

```dart
if (list.isEmpty)
  UtenEmpty(
    icon: Icons.inbox_outlined,
    title: l10n.noData,
    action: UtenButton(
      onPressed: _reload,
      child: Text(l10n.retry),
    ),
  );

if (loading)
  UtenSkeleton.lines(count: 6); // lite 档不闪烁，仅灰块
```

### 9.6 UtenAnimatedNumber

```dart
UtenAnimatedNumber(
  value: 12580,
  format: (n) => n.format('#,###'),
); // rich 档滚动；standard 档 fade-in；lite 档直接显示终值
```

### 9.7 UtenThemeSwitcher / UtenLocaleSwitcher / UtenFontScaler

```dart
// 设置页一行三项
ListView(
  children: const [
    UtenThemeSwitcher(),
    UtenLocaleSwitcher(),
    UtenFontScaler(),
  ],
)
```

### 9.8 UtenResponsiveGrid（卡片瀑布流）

```dart
UtenResponsiveGrid(
  itemCount: notifications.length,
  spacing: 14,
  // itemBuilder 第三参 itemWidth 是当前单格宽度，卡片内部可据此自适应排版
  itemBuilder: (context, index, itemWidth) {
    final n = notifications[index];
    return UtenNotificationCard(data: n, width: itemWidth);
  },
)
// 列数基于 LayoutBuilder 容器宽度自动算：<500=1 / 500-800=2 / 800-1100=3 /
// 1100-1500=4 / >1500=5。禁止用 ListView 显示数据卡片。
```

## 十、列表页瀑布流强制规则

> 🚨 **本节为全局强制规则。**

所有**列表页**（工资条 / 报销 / 通知 / 建议等数据卡片列表）**必须**用 `UtenResponsiveGrid` 实现卡片瀑布流布局，**禁止**用 `ListView` 直接渲染数据项。

- 列表页主数据展示一律 `UtenResponsiveGrid` + 卡片组件（`UtenCard` / `UtenStatCard` / 业务卡片）。
- **详情页的明细项**（如工资条明细、报销明细列表）也**优先**用 `UtenResponsiveGrid`，让多条目在不同容器宽度下自动排布。
- `itemBuilder` 必须接收并使用第三参 `itemWidth`，使卡片内部布局随单格宽度自适应（窄列竖排、宽列横排）。
- 列数由组件按 LayoutBuilder 容器宽度自动算，**不在业务代码里硬编码列数或写 `context.breakpoint` 切列数**。
- `ListView` 仅允许用于：纯文本行（设置项列表、纯菜单）等无卡片视觉、无网格语义的场景。

理由：业务卡片高度随内容变化，强制等高的 `ListView`/`GridView` 会裁剪内容或留大片空白；`UtenResponsiveGrid` 基于 `Wrap` 是真瀑布流，且列数随容器宽度变化（桌面端侧边栏挤窄时仍正确），见 [03-自适应布局组件.md](03-自适应布局组件.md) §3.2。

## 十一、组件实现通用规范

| 规范 | 要求 |
|---|---|
| 取色 | 一律 `Theme.of(context).colorScheme`，不硬编码（见 [08-主题与配色.md](08-主题与配色.md)） |
| 字号 | 一律 `Theme.of(context).textTheme`，不硬编码 `fontSize: 14`（见 [04-字体与字号可调.md](04-字体与字号可调.md)） |
| 文案 | 一律走 `AppLocalizations.of(context).xxx`，不硬编码中英文（见 [05-国际化与多语言.md](05-国际化与多语言.md)） |
| 动画 | 走 Uten 动画 token，不在 lite 档跑重动画（见 [06-动画规范.md](06-动画规范.md)） |
| 性能档 | 通过 `PerfTierScope.of(context)` 读取档位（见 [07-性能自适应.md](07-性能自适应.md)） |
| 响应式 | 用 `LayoutBuilder`，不写死宽度 |
| 命名 | 文件 `uten_<name>.dart`，类 `UtenXxx`（见 [01-命名规范.md](01-命名规范.md)） |
| 状态 | 用 Riverpod，不用 `setState` 跨组件共享 |
| 命名参数 | 构造函数全部命名参数 + `required` 标注必填 |
| const | 能 `const` 尽量 `const` |

## 十二、禁忌

🚫 禁止业务代码直接用 Material 的 `Card` / `ElevatedButton` / `TextButton` / `TextField` 而不用 `UtenCard` / `UtenButton` / `UtenInput`。
🚫 禁止业务代码直接堆 `Container + SizedBox + Padding` 实现已有 Uten 组件的能力（复制粘贴而不抽象）。
🚫 禁止复制粘贴组件代码到业务页面后再改——必须改组件本体或新建组件。
🚫 禁止在业务代码里硬编码颜色/字号/动画时长（应该走主题与 token）。
🚫 禁止跳过文档直接实现组件（先文档后代码）。
🚫 禁止组件不处理性能档与响应式（必须按模板写明行为）。
🚫 禁止组件库内 `print` 调试代码混入。
🚫 禁止把业务逻辑（如 API 调用）写进组件——组件只负责展示与交互回调。
🚫 禁止用 `ListView` 直接渲染数据卡片列表（工资条/报销/通知/建议等）——必须用 `UtenResponsiveGrid`。
🚫 禁止在业务代码里写死卡片网格列数或用 `context.breakpoint` 切列数——交给 `UtenResponsiveGrid` 按容器宽度算。

## 十三、对照清单（每次提交前自检）

### 基础
- [ ] 所有按钮都是 `UtenButton` / `UtenActionButton`，没有 `ElevatedButton` / `TextButton` / `FilledButton` 等裸按钮
- [ ] 所有输入框都是 `UtenInput`，没有 `TextField` / `TextFormField`
- [ ] 所有卡片都是 `UtenCard` / `UtenStatCard`，没有 `Card`
- [ ] 列表页（工资条/报销/通知/建议等）数据卡片用 `UtenResponsiveGrid`，没有用 `ListView` 渲染数据项；详情页明细项也优先用 `UtenResponsiveGrid`
- [ ] 卡片网格没有写死列数，也没用 `context.breakpoint` 切列数（交给 `UtenResponsiveGrid` 按容器宽度自动算，`itemBuilder` 用 `itemWidth` 第三参自适应）
- [ ] 业务代码里没有出现"3 处以上重复"的 UI 没抽象成组件
- [ ] 新增的组件已经按流程：先文档 → 实现 → barrel → 总览 → 示例 → 测试
- [ ] 组件内部取色走 `colorScheme`，没有硬编码颜色
- [ ] 组件内部字号走 `textTheme`，没有硬编码 `fontSize`
- [ ] 组件所有可见文案走 i18n
- [ ] 组件处理了响应式（compact/medium/expanded）
- [ ] 组件处理了性能档（lite/standard/rich）
- [ ] 没有把业务逻辑（API 调用、状态变更）写进组件
- [ ] barrel 文件 `uten_components.dart` 已 export 新增组件

### 顶部通知
- [ ] 用户反馈一律 `context.appSuccess/Error/Warning/Info`，**禁止** `ScaffoldMessenger.showSnackBar`
- [ ] API 错误用 `context.appApiError(e)` 自动提取 `fieldErrors`
- [ ] 通知全部顶部（status bar 下方），无底部 SnackBar

### 防连点
- [ ] 异步动作按钮用 `UtenActionButton`（首选）或 `UtenButton(isLoading: ...)`
- [ ] `onAction` 内用 `context` 前都有 `context.mounted` 守卫
- [ ] 联动控件（Switch/Slider/SegmentedButton）共享一个 `ClickGuard`，按 `isBusy` 统一 disable
- [ ] `onAction` 没有同步抛错；catch 后转 `appApiError`
- [ ] **已存在 `_submitting/_acting/_saving` 状态 + `UtenButton(isLoading: state)` 的旧页面**：迁移时优先改用 `UtenActionButton`，删除手动 flag；不允许在 PR 里继续保留这种双份样板
