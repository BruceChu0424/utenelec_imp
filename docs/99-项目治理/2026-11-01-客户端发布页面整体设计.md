# 客户端发布页面整体设计

本轮目标是“发布新客户端”的管理工作台。基线 `bd7e8525b`，独立分支 `uimp/client-publish-page-redesign-20261101`。前端呈现及响应式调整使用 `frontend-design`，沿用 Uten 组件、主题和原发布业务合同。

## 设计方向与复核

页面为发布管理员完成版本配置、文件核对与结果确认服务。原布局把全部字段横铺在顶部，文件队列占满剩余区域，交付要求和草稿入口藏在折叠区；当前版本、适用设备、单文件状态缺少清楚的阅读顺序。

主色沿用 `teal700 #0F766E`，表面为 `#FFFFFF`，浅层表面 `#F8FAFC`，正文 `#0F172A`，次级文字 `#475569`，待核对提示使用 `warningText #B45309`。实际实现读取 ColorScheme 和 UtenColors，不另维护数值。Noto Sans SC 继续使用项目的标题、正文与说明字号，按钮、圆角和间距沿用 Uten token。

宽屏采用“左侧配置、右侧执行”的工作布局，配置区独立滚动，文件队列内的发布操作固定在底部；窄屏按配置、文件、交付核对的顺序纵向排列。两种布局共用控制器、完整队列及发布状态，切换布局保留当前队列/记录页签。流程文字对应真实的操作顺序，不增加强制向导。

```text
发布新客户端                         草稿状态 / 保存发布草稿
┌ 版本与适用设备 ┐     ┌ 发布队列 / 发布记录 ─────────┐
│ 系统 / 架构    │     │ 添加文件 / 批量添加          │
│ 客户端类型     │     │ 文件名、适用设备、版本、状态 │
│ 版本 / 构建号  │     │ 编辑目标 / 重选 / 核对原状态 │
│ 发布说明       │     │                              │
├ Windows 双包 ─┤     ├──────────────────────────────┤
│ 交付与结果摘要 │     │ 结果说明          上传并发布 │
└────────────────┘     └──────────────────────────────┘
```

设计复核后，使用少量有明确职责的表面区分配置、队列和交付核对；队列仍是完整文件列表。状态标签只表达发布生命周期，不用通用指标卡代替文件结果。删除底部重复的保存入口，将保存草稿移到页顶；长规则保留于说明和帮助入口，主流程使用管理员能直接理解的文字。

## 公共入口与适用调用方

| 入口 | 改动及保留事项 |
|---|---|
| `client_release_publish_page.dart`：设置页入口与软件下载页入口 | 两个入口继续指向同一完整页面；新增宽屏侧栏、窄屏纵排、可见草稿入口和队列底部发布操作 |
| `_TargetFields`：批量配置与单行编辑 | 共享平台、客户端类型和架构联动；批量区采用紧凑分组布局，单行编辑保留原行为；不复制第二套校验 |
| `client_release_publish_widgets.dart` | 队列与发布记录共用状态标签；配置与交付区共用标题层级，读取同一 Uten 主题 |
| Web / 现有 Flutter 桌面 | 共用上述页面和队列模型；保留平台文件选择器及既有上传能力差异 |
| WPF `ClientReleasePublishView` | 同步配置侧栏、窄屏纵排、顶部草稿入口、双包说明与队列底部操作；继续调用原生发布队列和服务 |
| WPF `ClientReleaseTargetEditor` | 同一目标编辑器通过 compact 参数表达批量区布局；平台切换时整体隐藏不适用字段及其标签，保留原数据和联动规则 |

旧的横铺批量表单、重复底部保存入口和队列/记录中的无层级状态文本已替换。必要差异：Flutter 对窄屏及 200% 字号回退到纵排，WPF 继续使用原生窗口尺寸和系统 DPI；两端保留各自原有文件选择、再认证、草稿与退出流程。

没有修改服务端 API、上传/发布队列状态机、权限、请求编号、哈希、文件字节、重试策略或版本号。成功项目不重传，未知结果先按原编号核对，已冻结项目不随批量配置改写。窗口缩放与列表滚动不截断底层队列，不以可见行代替全部项目。

- 宽屏、深色、平板、手机和大字号预览保存在本工作树 `output/ui/client-publish-page-20261101/`；该目录是本地截图产物，不随正式客户端分发。
