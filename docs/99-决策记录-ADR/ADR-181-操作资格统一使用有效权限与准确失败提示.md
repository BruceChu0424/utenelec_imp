# ADR-181: 操作资格统一使用有效权限与准确失败提示

- 状态: 已接受(源码候选，部署和真实账号验收分别记录)
- 日期: 2026-10-16
- 范围: 全平台功能准入、财务审核、品质审核、工作台、AI、行动待办及共享失败提示
- 修订: ADR-027 的财务部门/跨部门个人点名资格，以及工作台、AI、品质等功能的额外部门准入条件

## 统一授权规则

权限设置是功能授权入口。账号处于正常启用、员工在职状态时，相同有效权限产生相同操作能力，不因主部门、兼职部门或授权来源而不同。全员基础、部门配置、个人覆盖和有效负责人委派继续由 `PermissionResolver` 合成；个人收回仍优先，失效委派不产生权限。

财务确认、核价、订货及超量到货审批不再要求 `DEPT_FIN`，也不再要求跨部门员工必须额外存在个人 `grant`。查看、批准、驳回、核价等动作仍分别核对对应权限。超级管理员使用现行固有有效权限，不额外补造个人授权。

FQC 审核池使用查看与审核权限判断，只有查看权限的员工继续按原单据数据范围阅读。AI 可用业务域由业务权限判断；部门只可用于分类偏好，不得拒绝显式选择的已授权流程。工作台按已授权入口读取徽章及指标，不再把“本人部门”当作入口显示条件。

## 任务、对象与业务边界

行动待办的候选按在职启用账号、真实授出的页面/动作权限以及既有对象范围选取，弹卡读侧沿用相同规则。超管固有全部目录权限允许操作，但不自动订阅全部业务提醒。撤权、离职、停用或委派失效后重新核验。

功能授权不改变单据 owner/交接数据范围、敏感字段权限、仓库实物责任、车间任务责任、管理组织子树、账户状态、模拟身份只读、制审分离、有效审核占用、版本/状态、来源数量或事务规则。纯信息通知仍按已登记对象和业务跟进关系投递。权限目录中明确的 `INDIVIDUAL_ONLY`、`NON_DELEGABLE`、`SUPERADMIN_ONLY` 策略继续在权限设置内执行；平台/公司设置的超级管理员边界保留。

## 配置、实际能力与权限变更一致

`PermissionDependencyCatalog` 统一登记已核对的两类组合：页面入口/表单所需读取用于授权时补齐和管理页提示；该动作所有合法入口本来均明确要求同时具备的读取，才参与最终操作能力和批量待办解析。不能把“从某页面进入需要查看”扩大成所有独立命令的后端门槛，也不能因权限码前缀相同推导新依赖。动作的新授权只补齐实际必需且允许自动授权的普通查看权限；价格、金额、全部负责人范围等敏感读取和其他写动作仍须独立明确授权。对存在多个合法入口的动作，保留已持有的读取路径，不同时打开无关业务页。

账号支持与财务账户查看是两个业务功能。入职、专用证件/手机号修改、薪酬字段授权、附件各动作、研发任务办理等继续使用各自原有的独立能力和对象边界，不因缺少一般列表查看而被剔除。入职页面的部门选择读取只属于入口组合；不得顺带扩权为查看所有员工。读取货品售价仍按查看售价或售价字段编辑授权判断，不把字段授权误当为完整货品编辑权限。

同一动作可能被多个入口复用：采购/委外申请预览的来源查看，不能废掉已知合法来源行的订货创建；批量账户调账的账户与余额查看，不能废掉账户新建/编辑中合法的期初余额维护；正式成本导入的货品查看，不能废掉仅持成本查看与编辑时合法的导入预览。各入口保留原有精确校验，通用解析不得把某个入口的条件扩大到整项授权。

这一边界同样适用于保存授权：页面导航读取只能在未被明确收回、属于允许自动授予的普通查看且管理员确有授权上限时辅助补齐。不能补齐时保留入口缺项提示，仍允许授予在其他入口合法使用的独立动作；不得强迫扩大读取范围，或把导航缺项变成新的授予门槛。只有所有合法入口均需要的硬性组合缺项才阻止开启。多条读取路径择一即可的动作，应保留已有路径，或选择当前确可合法补齐的路径，不能只因默认路径被收回而忽略另一个合法入口。

货品、客户、供应商、模具的主档查看可独立使用全局列表，不依赖分类树。已有主档的编辑、删除、状态、导出，以及货品导入和客户交接不额外要求分类查看；只有实际需要分类或组件选择器的主档新建、BOM 新增组件才补齐分类读取。不能用整个模块前缀推导分类依赖。

个人明确收回始终优先。单纯撤销读取必须允许，原动作配置可以保留；确实缺少原有后端必要条件的动作不显示为可用，只有页面入口缺读则提示对应页面尚不可进入，不擅自撤销其他合法入口中的独立动作。管理页区分“已配置”与“已生效”，显示缺项并提供明确补齐入口。部门/个人全量保存只为本次新开或重新开启的动作补依赖；页面增量保存只处理明确 `enabled=true` 的动作；本组批量开启可修复已配置但不完整的动作。不得因为另一个动作仍有旧配置而拒绝单纯撤权或偷偷重新授予被收回的权限。

页面内派生的普通读取仍校验负责人授权上限、可委派策略、中央收回与真实所属权限面，保存和后续解析使用相同归属。失效委派不能显示为已开启；是否可重新授权与是否可清理旧委派分别返回和显示。中央已收回、失去转授上限等情况只能清理，不能展示重新开启入口；普通过期但仍有授权资格时才允许重新授权。“整组授权”只包含目录允许批量的项，敏感权限继续逐项明确授权；“全部收回”也清除仍配置但已失效的委派，避免未来意外恢复。

`/auth/me` 同一响应的权限与会话快照由会话 owner 同步，旧账号、旧服务器、同账号重新登录前的晚到响应不得回灌。FQC 与财审详情监听实际权限变化更新能力，保留原输入、命令键和未知结果阻断；不自动重复提交。只读账户不显示可执行的批量批准/驳回按钮，两个动作分别分权。

普通部门授权、个人覆盖和有效负责人委派变更不强制退出登录：授权版本变化使旧 access token 下一请求立即失效，仍有效的同一登录会话可通过 refresh 取得按当前授权重新合成的权限；保存后或手动刷新再经 `/auth/me` 同步界面。停用、删除、离职、改密、重置凭据、主动退出及远程入口变更等安全事件继续执行各自的 token/会话撤销规则，不因普通权限续期而恢复失效会话。

到货资料学习必须绑定本次成功登记的真实收货行，在原登记事务内完成；退役无来源的独立货品资料写入口。查看权限不能借“学习”修改任意货品。新请求指纹包含学习值，旧无学习请求与中断草稿继续保留原请求形状和幂等键，原命令重放不覆盖后来维护的主档。

## 面向员工的输出

- 优先显示服务端已提供的业务原因，区分没有权限、账号状态、他人占用、版本变化、业务条件和通信失败。
- 已知原因不能被“检查网络或权限”覆盖，也不能在后续检查时丢掉原始失败信息。
- 收不到写操作回执时只说明结果尚未确认，提示先刷新核对；不得推断“整批未提交”或要求直接重复提交。
- 文案使用页面上可找到的业务名称和下一步操作；不用部门名称替代实际授权动作，不输出权限码或内部状态码作为员工操作说明。
- 中文、英文、韩文共享提示同步维护。界面相关实现默认使用 `frontend-design`，复用 Uten 组件与主题。

## 验证要求

覆盖不同部门下的部门授权、个人授权、有效委派、撤权、停用、离职；同时验证无动作权限不能审批、有动作权限不能越过原对象/实物责任范围。测试将纯单元、真实 PostgreSQL、真实 HTTP 和界面交互分开记录，不把源码检查写成部署或所有真实账号 UAT 已完成。
