# 01 - 老系统现状调研

> ✅ **调研已启动（2026-07-24）**：老系统数据库 `YTDQ_2023`（SQL Server 2008 R2 备份，2.6 GB）已还原至本机 LocalDB 2022，首轮概览完成。
> **完整结构、大表、触发器风险、模块对应见 [../数据迁移/01-YTDQ老库总览.md](../数据迁移/01-YTDQ老库总览.md)**；本档保留通用调研框架与问题清单，供后续模块继续填充。
>
> 一句话结论：老系统是**国产中小型制造业 ERP**（SQL Server 2008 R2，196 表 / 168 视图 / 91 触发器，进销存 + 生产 + 财务 + 工资 + 质检），内部代号疑似"科宇(KYRJ)"。

---

## 一、调研目标

为 `00-融合总策略.md` 中的"单向影子双写"提供事实依据，回答三个问题：

1. 老系统有哪些功能？（决定哪些要双写）
2. 老系统用什么技术？（决定双写的可行性和方式）
3. 老系统的数据长什么样？（决定字段映射规则）

---

## 二、调研方法（建议）

| 方法 | 产出 | 适用场景 |
|---|---|---|
| 走一遍老系统 | 功能清单、操作流程 | 必做，最直观 |
| 老系统代码 / 文档 | 技术栈、架构、API 列表 | 有源码/文档时 |
| 老库表结构导出 | 字段、关系、索引 | 直连数据库读 schema |
| 访谈老系统维护者 | 历史包袱、坑、禁忌 | 找到原开发/运维 |
| 看老系统日志 | 访问量、用户分布 | 决定退役节奏 |

## 三、待回答的问题清单

### 3.1 技术栈

- [ ] 前端是什么？（Web？桌面？移动？技术栈？）
- [ ] 后端是什么语言 / 框架？
- [ ] 数据库是什么？（MySQL / SQL Server / Oracle / 其他？）
- [ ] 版本号？
- [ ] 是否有缓存（Redis 等）？
- [ ] 是否有消息队列？
- [ ] 是否有对外 API？

### 3.2 功能清单

- [ ] 列出所有老系统模块（每个模块对应新系统的哪个功能）
- [ ] 每个模块的核心操作（增删改查 + 业务流程）
- [ ] 哪些功能用户量最大？（决定迁移优先级）
- [ ] 哪些功能几乎没人用？（可能直接退役不双写）

### 3.3 数据库表结构

- [ ] 导出全部表（只读 schema，不动数据）
- [ ] 标注每张表对应新系统的哪个实体
- [ ] 标注关键字段（主键、外键、唯一索引、枚举字段）
- [ ] 哪些表是大表？（决定迁移方式）
- [ ] 是否有视图 / 存储过程 / 触发器？（特别注意触发器，写入老表可能触发副作用）

### 3.4 部署与运行

- [ ] 老系统部署在哪里？（本地服务器 / 云 / 容器）
- [ ] 网络可达性？（新系统后端能否直连老库？）
- [ ] 高峰期是何时？（迁移和双写测试要避开）
- [ ] 备份策略？

### 3.5 历史与禁忌

- [ ] 谁是老系统的原开发者 / 现维护者？
- [ ] 有什么"绝对不能动"的地方？
- [ ] 有什么已知 bug 但大家绕着走的？
- [ ] 老系统的认证体系是什么？（将来双写是否要复用老系统会话？）
