# ADR-053：多币种收款毛额净额与追加式账户流水

> 日期：2026-08-28
> 状态：V407/V408 业务口径已接受，V416/V417 以前向迁移补异常队列、新写守卫和付款命令并发；财务冻结集合 V417/379 已在 PostgreSQL 16.15 空库重放。共享目录随后由并发生产/仓库候选推进到 V419/381，不属于财务证据字节且全量回归尚未通过。目标非空库迁移、历史签收、多岗位 UAT、恢复和发布未完成
> 后置覆盖：ADR-030 中 V236-V238 收款金额/费用口径，ADR-051 中可删流水口径
> 关联：ADR-030、ADR-047、ADR-048、ADR-051、V236-V238、V379-V389、V400-V405、V407、V408、V416、V417

## 一、问题

销售订单和正式应收必须保留 USD 等原币商业事实，但公司实际资金路径不只一种：

- 客户或合作外贸公司将 USD 结汇后，人民币进入本公司真实 CNY 账户；
- 少数资金会真正保留为本公司可支配 USD，进入真实 USD 账户；
- 外贸代理费、银行费可从到账款中扣除，也可从另一真实账户另行支付；
- 同一 AR 可分批、跨期收款，每批汇率、费用和银行入账不同。

V236-V238 把 `amount_original`、`amount_local`、`write_off` 和单头费用绑在一起。该模型可以做到借贷数学平衡，却无法同时准确表达“客户结算原币毛额”、“按汇率得到的本位币毛额”、“费用”和“真实账户实际入账”。用应收冲销金额代替手续费会错报实际收到原币，也会污染折让/坏账语义。

旧 `finance_reconciliations` 红冲路径还会删除原流水，`accounts.balance_current` 是可变累计投影，缺少可以独立重建和暴露差异的账本事实。

## 二、不变的业务边界

1. 销售人员只负责客户、货品、数量、价格、折扣和订单原币，不录入、决定或修改到账汇率。
2. 已审订单只进入原币待收计划，不写 AR 和 GL。
3. 仓库 `SHIPPED` 是当前正式 AR 边界。它是现行系统规则，仍须由公司根据合同、交接和控制权转移证据完成业务签字。
4. 收款明细的 `currency_id` 是 AR 应收/核销原币，不是实际入账账户币种。
5. 每一个不同银行入账时间或实际结算汇率是独立收款批次，后批不得覆盖前批。

## 三、V0 与 V1 严格分层

- `settlement_authority_version=0` 是历史口径。V407 不根据新规则改写任何 V0 金额或手续费含义。
- `settlement_authority_version=1` 是新收款口径。新收款必须带制单人范围内唯一的创建幂等键和请求哈希；草稿编辑带 `expectedVersion`，陈旧版本返回 409。
- V1 普通 AR 收款行要求单一核销原币、单一批次汇率、`amount_local = amount_original × exchange_rate` 四位半入，且 `write_off_amount/write_off_local=0`。
- V416 在数据库层要求 V1 maker 非空、终态 approver 非空且与 maker 不同、银行流水号必填、代理渠道另有代理结算单号；V1 预收头也必须满足同一毛额公式。
- 折让、坏账和其它商业冲销必须使用未来 typed adjustment 流程，不得将其伪装成银行费、外贸代理费或 V1 `write_off`。

## 四、V1 金额字典

| 字段 | 币种/单位 | 权威含义 |
|---|---|---|
| `amount_original` | AR 原币 | 本批客户/代理结算毛额，不减手续费 |
| `exchange_rate` | `BASE_PER_SETTLEMENT` | 一单位结算原币兑换的本位币数量 |
| `amount_local` | 本位币 | 本批结算毛额，等于收款行本位币毛额合计 |
| `account_currency_id` | 账户币种 UUID | 审核时冻结的真实收款账户币种 |
| `account_amount` | 账户原币 | 真实收款账户的银行入账金额 |
| `account_amount_local` | 本位币 | 该真实账户入账的本位币快照 |
| `bank_fee_account_amount` | 费用账户币种 | 银行手续费原币金额 |
| `other_fee_account_amount` | 费用账户币种 | 外贸代理费或其它结算费原币金额 |
| `bank_fee/other_fee` | 本位币 | 上述两类费用的冻结本位币快照 |
| `fee_bearer` | 枚举 | `NONE` 或 `COMPANY`；客户/代理承担必须另立应收/索赔，不能记本公司费用 |

全部金额使用 `NUMERIC(18,4)`/`BigDecimal`，汇率使用 `NUMERIC(18,6)`/`BigDecimal`，派生金额按行使用四位 `HALF_UP`。前端向新收款提交十进制字符串，服务端和数据库重算与守卫；二进制浮点不是入账权威。

## 五、渠道、汇率和外部证据

### 5.1 `DIRECT_ACCOUNT`

- 必须使用 `BANK_STATEMENT` 作为汇率来源，并冻结汇率生效时间、银行入账时间和银行流水号。
- 可进入本位币账户，或与 AR 原币相同的真实外币账户。
- 第三币种账户失败关闭，不用单一汇率猜测两次兑换。

### 5.2 `TRADE_AGENT_CONVERSION`

- 必须选择启用的合作外贸公司 supplier UUID，并冻结名称快照。
- 必须使用 `TRADE_AGENT_STATEMENT` 汇率来源和代理结算单号。
- 只允许进入本位币真实账户。外贸公司是代收/结汇渠道，不因客户以 USD 付款而虚构本公司 USD 账户入账。
- 当代理收款日与本公司银行入账日分离，且业务需要表达代理在途余额时，V407 不能以相同日直收替代该子账。

## 六、费用结算模式

V1 将“费用由谁承担”和“从哪个真实账户出钱”分开。当前只接受无费用 `NONE` 或本公司承担
`COMPANY`。若合同约定客户或外贸公司承担，而对方实际少付/扣款，该差额是新的客户应收或代理索赔，
不能选择本公司费用科目让 AR 看似结清；在 typed claim/adjustment 流程交付前失败关闭。

### 6.1 `NONE`

银行费和其它费均为零，不产生费用账户流水。

### 6.2 `DEDUCTED_FROM_PROCEEDS`

- 费用从本批款项中扣除；
- `account_amount_local + bank_fee + other_fee = amount_local`；
- 收款账户只增加 `account_amount`，不增加毛额；
- 费用进银行手续费角色或财务选择的其它费用叶子，不冲减 AR 原币实收。

### 6.3 `PAID_SEPARATELY`

- 收款账户按毛额入账，`account_amount_local = amount_local`；
- 必须选择真实费用付款账户；
- 同一收款审核事务增加收款账户，扣减费用付款账户，分别追加 `RECEIPT` 和 `RECEIPT_FEE` 流水。

## 七、应收、账户和 GL

V1 审核在一个服务端事务内完成：

1. 锁定收款单、被核销 AR 和所有真实资金账户；
2. 复核制单人与审核人分离、客户/原币/余额/渠道/费用/账户币种；
3. 更新 AR 原币实收和本位币账面核销；
4. 更新真实账户原币缓存，追加账户流水；
5. 冻结费用和汇兑差额。

审核在推进单头状态前先 flush 行级原币、本位币、账面冲减、汇兑和前后余额快照，使数据库 V1 行/头守卫在同一事务读取完整事实；随后保存已审单头并调用实时收款 GL。任何一步失败均回滚。

V407 当前候选由 `FinanceReceiptService.approve` 在保存已审核收款、AR、账户和追加式流水后，同一服务端事务调用 `GlPostingService.postReceiptDoc` 生成该单 `RECEIPT` AUTO 凭证。科目缺失、凭证少于两行或借贷不平会抛错并使整笔审核回滚。单张凭证和以后按期间重建使用相同金额含义：

- 借收款账户 `account_amount_local`；
- 借银行手续费和外贸代理/其它费用本位币快照；
- 贷 AR 账面冲减；
- 毛额结算与 AR 账面冲减的差额进汇兑损益；
- `PAID_SEPARATELY` 另贷费用付款账户。

为避免 V278 历史名称匹配歧义使实时收款 GL 无法启动，V407 使用固定 UUID 创建“收款银行手续费”“收款汇兑损益”“应收账款控制”叶子，并且只在 `BANK_FEE_EXPENSE/FX_GAIN_LOSS/AR_CONTROL.style_id IS NULL` 时绑定；已经财务复核的既有 UUID 映射绝不覆盖。审核还会把收款账户、AR/客户预收、银行费、汇兑损益、其它费用和另付费用账户的科目 UUID 冻结到单头。`v_receipt_expected_gl_entries` 只用这些冻结科目和金额生成期望分录多重集，原凭证实际分录须与期望结果双向 `EXCEPT ALL`；“借银行 1/贷 AR 1”这类形式平衡但金额错误的凭证不能终态化。

V1 收款 `RECEIPT` 已移出按期间物理删除/重建集合。红冲保留原凭证和分录，在中国业务当前月追加
逐行反向的 `RECEIPT_REV`，通过 `reversal_of_voucher_id/reversed_by_voucher_id` 双向关联；因此原单在
以前月份时也不改写旧期间。`v_receipt_gl_integrity` 暴露已审/已红冲收款缺原凭证、缺反向凭证、缺行或
不镜像的异常，批量生成遇到异常失败关闭，不自动猜修。通用会计期间主档和正式关账仍未交付；当前月
只能作为临时开放期间，不能冒充正式关闭期间控制。

## 八、追加式账户流水

V408 把 `finance_reconciliations` 收口为账户自身币种的追加式事实：

- `posting_seq` 是稳定时序；
- `entry_kind` 区分 `POSTING`、`REVERSAL`和 `ADJUSTMENT`；
- `account_currency_id` 冻结账户原币，`in_amount/out_amount` 只使用该币种；
- `amount_local` 不参与账户原币余额求和；V408 以前无法证明的外币历史可为 NULL，V416 后所有新流水必须保存正的本位币快照，本位币账户须与 native 金额同值；
- `REVERSAL` 必须通过 `reversal_of_id` 唯一指向原 `POSTING/ADJUSTMENT`，同账户、同币种且流入/流出完全镜像；
- 全表拒绝 UPDATE/DELETE。普通收款、付款、费用、其它收入、账户转账和供应商索赔收款红冲都追加反向流水，不删原行。

V408 还在数据库层冻结已有资金历史账户的币种、GL 科目和期初余额。`v_account_balance_integrity` 按原币重建流水余额并暴露 `cached_balance-flow_balance` 差异；该视图不是银行对账单。余额调整在既有差异非零时失败关闭，不允许用新调整掩盖旧漂移。V1 收款单头与 `RECEIPT/RECEIPT_FEE` 流水还通过 deferred constraint trigger 在事务末强制 `v_receipt_flow_integrity.is_consistent=true`，直接 SQL 只把草稿改为已审但不写真实账户流水时不能提交；V0 历史明确豁免该新规则。

V416 以前向方式增加 `v_receipt_v0_settlement_exceptions` 和 `v_account_flow_migration_exceptions`。前者分类 V0 缺银行/渠道、费用语义、原币、AR 分配或 GL 证据；后者分类旧流水的账户/币种/符号/来源和本位币快照问题。两者只读、不自动改金额。V407 已有的 `v_receipt_v0_gl_reconciliation` 只核对 V0 原凭证缺失/歧义/不平，不能替代结算证据队列。

V417 为付款单增加 maker 范围的 `create_idempotency_key/create_request_hash` 和 JPA `version`：同键同内容返回原草稿，同键异内容或已删除原单拒绝，编辑必须带 `expectedVersion`；它防止网络重试造双单，但不把未交付的供应商预付变成可用能力。

一般费用、其它收入和供应商索赔现金到账目前只有本位币金额权威，尚无与 V407 同等的外币原币/本位币双金额模型；相关服务因此只允许本位币真实账户。它们选择 USD 等外币账户必须失败关闭，不能把 CNY `amountLocal` 写成外币账户余额。

## 九、数字验收例

### 9.1 费用从到账扣除

- AR：USD 100000，开账率 7.000000，账面 CNY 700000；
- 本批结算：USD 1000，实际结汇率 7.200000 CNY/USD；
- 本位币毛额：CNY 7200；
- 外贸代理费：CNY 72，`DEDUCTED_FROM_PROCEEDS`；
- 真实 CNY 账户净入：CNY 7128；
- AR 原币余额：USD 99000；AR 账面余额：CNY 693000；
- 汇兑收益：CNY 200。

GL 平衡式：

`Dr 银行 7128 + Dr 外贸代理费 72 = Cr AR 7000 + Cr 汇兑收益 200`

### 9.2 费用另付

相同的 USD 1000 批次中，收款账户毛入 CNY 7200，费用付款账户另行流出 CNY 72。

`Dr 银行 7200 + Dr 外贸代理费 72 = Cr AR 7000 + Cr 汇兑收益 200 + Cr 费用付款账户 72`

### 9.3 真实 USD 账户直收

账户原币流水和余额增加 USD 1000，本位币快照是 CNY 7200。只有这种情况可以增加公司 USD 账户；已结汇进入 CNY 账户的同一笔款不得再写 USD 流入。

## 十、历史迁移与异常队列

- V407 不把 V0 有费收款自动升级为 V1。旧 `write_off` 无法证明是银行费、外贸代理费、客户少付、销售折让或坏账，禁止猜填。
- 历史 V0 只能保留原字节和原语义；`v_receipt_v0_settlement_exceptions` 列出必须由财务依据银行回单/代理结算单确认的原因。
- V408 为存量流水补充当前账户币种快照，但外币历史行的 `amount_local` 不可从当前汇率猜算，保留为 NULL。
- V1 收款 GL 不参与批量删除重建；`v_receipt_gl_integrity.is_consistent=false` 的记录进入异常清单，禁止自动补凭证或改历史分录。
- 目标库必须分别签收 `v_receipt_v0_settlement_exceptions`、`v_receipt_v0_gl_reconciliation`、`v_account_flow_migration_exceptions`、账户币种/缓存差异、AR/AP 与 GL，不得用 `flyway repair` 或直接改余额消除差异。

## 十一、查询与几十年数据性能

V408 候选已完成四个必要基础：

1. `(account_id,bill_date,posting_seq)` 部分覆盖索引；
2. 账户流水由 PostgreSQL 窗口函数计算跨期滚动余额，日期/关键字在数据库过滤，不再把截止日前全部流水加载到 JVM 后内存分页。
3. `account_flow_monthly_summaries` 按账户+币种+上海月份保存完整月流入/流出和首尾 `posting_seq`，新流水只增量 upsert 所属月；
4. `fn_rebuild_account_flow_monthly_summaries` 可全量或按账户重建，`v_account_flow_monthly_integrity` 与原始不可变账本逐月双向核对。查询期初=账户期初+起始月之前完整月汇总+起始月月初至 `dateFrom` 的原始尾段，不再每次从第一笔全历史 `SUM`。
