# 成本预算读取范围误报修复

## 原因与公共入口

截图中的“数据访问范围已变化，请重新打开页面后核对”可以在权限不变时稳定复现：先读取货品，再读取成本单。服务端 `MasterReadScopeInterceptor` 对货品发布 `master_goods` 证明，对预算成本单发布 `master_goods_cost` 证明。后者还包含成本单冻结客户的可见范围，两份证明按合同必然不同。Dart 和 C# 的公共读取层此前均按 `/master/goods` 前缀归到同一键，交替请求时反复把正常响应判为范围变更；单纯点击重试不能消除冲突。

本次为客户端共享权限合同适配修复。业务计算和权限权威继续在服务端；不更改权限、不忽略 403、不自动重放写入。按 `frontend-design` 保留既有 Uten 主题、布局、错误和重试交互。

唯一维护入口沿用：

- Web / Flutter 桌面：`lib/core/network/interceptors/read_scope_revision_interceptor.dart`。
- WPF 候选公共层：`clients/windows_legacy/Uten.Legacy.Core/ReadScopeRevisionState.cs`，由 `SessionCoordinator.ObserveReadReply` 调用。
- 服务端 owning 合同：`MasterReadScopeInterceptor`、`LegacyExportReadScopeInterceptor`、`ReadScopeVersionAuthority`，本次仅增加验证，无生产后端逻辑变更。
- 三端同组样例：`contracts/read-scope-domains/goods-cost-v1.json`，直接由 Dart、C# 和 Java 测试消费，不另建页面局部绕过或第二套读取能力。

## 调用方与保留差异

| 业务入口 | owning 读取域 | 适配结果 |
|---|---|---|
| 货品列表、详情、BOM 导出 | `master_goods` | 保留 |
| 成本单最新列表、历史版本、详情 | `master_goods_cost` | 在宽泛货品规则前精确识别 |
| 成本单快照列表、快照详情、模板 | `master_goods_cost` | 同一公共入口修复 |
| 预算成本单导出 | `master_goods_cost` | 同一公共入口修复 |
| 实际成本、实际成本导出 | `master_goods` | 保留实际成本自身的服务端合同 |

全部 12 个有效路由见共享 JSON。Dart 回归覆盖有/无 `/api` 前缀，连续 25 轮共 300 次交替读取；C# 公共适配器同样消费 12 条路径做 25 轮读取。原生测试使用 GET fixture 验证公共路径归类，POST 导出的方法归属由 Java owning 拦截器和 Dart 请求层另行验证，不宣称 WPF 已实现成本导出。

Web 和现有 Flutter 桌面共用 `DioGoodsCostRepository` 全部读取入口，页面启动链为货品详情 → 成本最新列表 → 成本详情/首次 bootstrap → 预览。实际成本入口保持独立权限语义；导出仍沿用现有导出任务/下载机制。没有可清理的重复实现；跨语言只保留必要运行时适配，并用同组样例防止漂移。

WPF 公共范围层已同步；WPF 成本预算工作台、历史/快照/模板/实际成本和成本导出仍未迁移，不据此开放写入口或认定 Win7 ERP 已完成。唯一台账 `W7-CORE-008` 维持原有 `implemented` 状态，仅补充本项证据，不扩大整项 DoD/Win7 真机验收范围。

## 边界

本项不等于截图中已安装程序已经更新。尚未正式打包、上传、部署；没有连接现网账户验收，也没有 Win7 真机验收。真实权限变化仍需重新进入并核对，不能为消除提示而接受旧范围数据。
