## 一、结论

本轮把当前共享工作树的生产候选事实收敛为一条可审计顺序：

```text
V337 MAKE exact entitlement 随 child 所有权交接
→ 计划批准形成 READY/DRAW
→ DRAW 通知与仓库待办角标
→ 仓库全部实际发料后才可开工
→ 仅 IN_PROGRESS 执行段可报工
→ 日报审核只累计 fqty 并生成 FINISHED_IN 待点收草稿
→ V338 仓库逐行实收；短收/零收行余量另建草稿，整单零收才拒收
→ 实收审核才增加库存与 iqty
→ 已点收红冲追加反向映射并重建 accepted slice 待点收草稿
```

未来计件只冻结边界，没有实现。日报 `price/total/stotal` 已从写入口停用，既有列不是工价或工资；单一 `worker_id`、执行负责人、班组、`fqty`、`iqty` 也不能单独证明计件归属。

## 二、本轮治理判断

| 主题 | 当前源码候选 | 明确边界 |
|---|---|---|
| MAKE 权益交接 | V337 以 append-only OUT/IN 事件把 current beneficiary 从父树旧节点移到 child 直接层 | 不改 origin/物理库存；不等于任意分批委派量 |
| DRAW 交接 | 真实 DRAW 投递仓库；全发、反发分别通知计划/生产 | 通知和角标只是发现入口；`issue` 才是物理出库 |
| 开工 | DEMANDED 段全部需求 `FULFILLED` 才能 START；ZERO_MATERIAL 例外 | READY 只表示预留和 DRAW 完整 |
| 报工 | 仅 IN_PROGRESS 可报；审核累计 `fqty` | 不增加库存、`iqty` 或工资 |
| 仓库点收 | V338 全行实收确认；短收/零收行进入余量草稿，整单零实收按原因拒收 | 通用 approve 对生产来源 FINISHED_IN fail closed；只有实收量入库存与 `iqty` |
| 点收红冲 | 专用入口追加反向头/行并重建 accepted slice 待点收草稿 | 禁止通用红冲直接把已收数量从待办链抹掉 |
| 锁序与对象范围 | inventory→plan/package/segment→stock；动作权限∩`SUB_WH` | 尚无员工到具体仓库主档，单仓级授权仍是后续治理项 |
| 计件 | 仅未来设计 | 无工序 UUID、多人贡献、工价版本和工资来源桥，继续 NO-GO |
