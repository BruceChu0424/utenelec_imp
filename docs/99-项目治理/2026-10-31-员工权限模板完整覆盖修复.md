## 公共实现与全部调用方

| 入口 | 实现及处理 |
|---|---|
| 单员工应用 / 预览 | `PermissionTemplateService` 委托 `PermissionTemplateAssignmentService`，不再独立计算 |
| 批量员工 / 员工与部门混合应用 | 同一 `templatePlan` / `write`；员工覆盖结果逐人验证，不一致整笔回滚 |
| Web / Flutter Windows | 共用 `PermissionBatchDialog`，员工单人及批量均只提供“按模板覆盖权限”；明确显示预期数量及差量。仅部门入口保留直接配置的覆盖/追加选择 |
| 当前权限 / 登录 / 页面和业务鉴权 | `PermissionResolver` 的逐人合成与批量 SQL 同时处理覆盖绑定，排除基础包和部门继承额外能力；应用事务会停用原负责人委派，之后明确新增的授权仍可生效 |
| 负责人可转授上限 / 通知与接待人终判 | 仍经过同一 resolver；候选查询只取超集，不作为最终授权。模板覆盖不能通过批量或候选终判绕回旧继承 |
| 后台无人值守运维 / 车间撤销人 | 已有 SQL 只认可明确个人加授或实时模板，不从基础包/部门推断，继续遵循个人收回 |
| 模板后续增减 | 实时来源解析，不为遮蔽继承制造个人收回行，防止以后新增的模板权限被旧遮蔽阻断 |
| 解除关联 / 删除模板 | 覆盖绑定先固化当时实际有效集合，再解除关联，使用既有精确快照写入及最终结果验证；不复活被屏蔽的继承 |
| 权限复制 / 配置恢复 | 保留既有精确快照合同，恢复时解除绑定；原始数据范围、来源和审计规则不变 |
| WPF `wpf_legacy` | `W7-BIZ-007` 系统权限页仍未迁移，无原生模板应用调用方，不能标为已支持；后续须消费同一 `REPLACE` 和覆盖绑定契约 |

服务端对员工的 `MERGE` 旧请求也按完整覆盖执行，避免旧版 Flutter 桌面端继续保留原权限；新界面只发送 `REPLACE`。部门配置本身是组织授权来源，部门 `REPLACE` 仍替换本部门直接配置，`MERGE` 仍追加部门直接配置；不会替某部门的所有员工删除个人设置或其他部门来源，界面明确说明此必要差异。

## 数据兼容、事务与安全边界

- V971 为员工绑定增加 `exact_permissions`，默认 `false`，已有绑定保持原状。必须由管理员重新预览并覆盖应用，才改为完整覆盖；不自动提升现有员工权限。
- 绑定模式参与状态指纹和解除关联并发比较；同一模板同一版本切换模式也构成配置变化。
- 模板应用指纹加入 `employee-template-exact-v1` 策略标记；升级前按旧合并规则生成的预览不能在升级后直接提交，必须重新预览覆盖差量。
- 超管身份限制、敏感权限逐项确认、版本与全量状态指纹检查、事务原子性、未知提交禁止重放、会话/连接代次隔离继续有效。
- 有硬依赖缺失的模板拒绝应用，不偷偷减少模板权限或扩大模板权限。
- 使用实时覆盖来源，沿用现有认证版本和授权 epoch 失效机制；不修改其他员工、部门权限表或超级管理员默认权限。
