# V511 客户零星发货统一流程

## 业务变化

新客户零星发货存入既有 `sales_shipments` / `sales_shipment_items`，明确 `shipment_kind=DIRECT_CUSTOMER` 与 `billing_mode=CHARGED/FREE`。所有新客户发货都经销售确认、本人有效财务认领与财务确认、仓库拣货和最终 `SHIPPED`。普通订货发货保留已确认订单来源和创建时的销售提交基础。

收费发货仅在实际出库时形成一次 AR；免费发货货款为零，仍产生真实物理出库。免费标志不能用于猜测零成本。成本及历史价值整改属于 V509/后续价值接线验收，不因本包数量与收款通过而宣称成本闭环。

## 表、身份和防护

- 新建 `sales_shipment_submission_events`：发货 UUID、商业修订、十进制文本商业快照、SHA-256、实际用户/员工和时间。它是业务审计表，须纳入业务清理集合；有完整 `fn_audit` 触发器和 ALWAYS 只追加守卫，不能列为技术排除表。
- 发货表新增类型、收费选择、用途/免费原因、销售确认修订/员工/时间、财审修订及当前放行事件 UUID。既有财审事件表追加同修订快照、claim UUID、撤回原事件和退回原因；旧事件不回填、不改写。
- 财务认领类型为 `SALES_SHIPMENT_FINANCE_AUDIT`。成功取得本人当前 claim 后，提交需携带 `expectedClaimId`、`expectedRevision`、`expectedContentHash`。认领/续租只锁发货头→claim；实际编辑/决定在共同商业来源及库存前缀之后锁发货头→claim。
- 当前确认必须有对应不可变提交和财务事件；有效认领期间同本人/兼岗/超管也不能改商业内容。编辑保留原明细 UUID，移除明细软标记并保留旧审核快照；未开始仓库作业时改动撤回原放行并重新确认。已 SHIPPED 商业事实不能直接改写。
- `stock_reservations` 新增 `CUSTOMER_SHIPMENT_ITEM` 归属和用途，以实际发货明细 UUID 及本仓 `STOCK_BALANCE` 为来源。拣货同时检查全局及本仓可用量，扣除销售、生产、委外等已有预留；退拣释放，重新拣货产生新预留，出库精确消费。
- 新直发没有销售订单 UUID。`fn_is_direct_customer_shipment_ar` 严格核对当前收费发货、实发状态、有效财审事件、客户/币种/冻结双币原额及无伪造订单引用。收款仍沿实际 receipt line→AR、账户、GL；仅此类来源不生成 SO 补充分配。V379 原 SO 分配守恒完整保留，直发分支改查真实收款累计与 AR 原币、商业冲销和 `amount_settled` 账面本币守恒。实际到账本币不能替代债权账面本币。

## 历史兼容

原 `sales_other_shipments` 和库存/财务事实原样保留，不搬库、不补造销售/财审/仓库事件。新建、编辑、删除、审核入口退役；真正内部领用改从仓库内部单据建立。历史仅可查阅和通过原数量/来源保护的受控反向，正式负责人交接和幂等无变化更新仍可进行。

既有常规发货缺少完整订单行来源的记录标记 `LEGACY`，表示来源尚不能证明，绝不反推为新 DIRECT 或 FREE。其商业事实只读；合法历史退货累计仍可写回。已确认普通订单发货不重造历史审批，之后受控编辑才升级当前流程。

## 金额精度边界

用户已确认以实际单据和银行金额为准、分摊不丢余额。销售可编辑读 DTO 新增 `*Exact` 十进制文本，旧数值字段仅保留兼容显示；编辑原文和金额请求采用字符串，预览不回写为权威金额。新直发不再自动 HALF_UP 裁剪输入或数量×单价×折扣：当前旧金额列能无损表达的业务正常办理，暂不能表达的输入明确拒绝并不落库。平台最终实际金额确认及扩展精度方案由统筹继续完成，不能把临时无损拒绝当成所有合法精度场景已经支持。

已收后的退货贷项不是已批准或已支付现金退款。没有真实退货时不能虚做退货再发运纠正价款；需要独立财务追加调整。
