# 我的申请与审批权限配置指南

适用于本次“我的申请、分级审批、负责人回避”功能。请按公司确认的岗位分工逐人授权；以下字母账号仅为测试分工示例，不对应任何真实员工。实际入口以公司启用版本及账号授权为准，本指南不表示已部署。

**本地测试先核对服务端：**从最新 `main` 启动配套本地服务端，确认使用启用了 Flyway 的本地开发配置，等待自动迁移至 **V1002 成功**，再用配套客户端登录。只更新客户端、仍连接旧服务端，不会得到新的权限目录和审批流程。`prod` 配置关闭启动自动迁移，应走既有受控迁移流程，不能以重启公司服务器代替迁移。迁移异常按日志交维护者处理，不手工改 SQL、补权限表或修改 migration。合入 main 本身不改变数据库或运行服务；本轮未启动本地业务服务、改实际数据库或账号，以下授权操作由管理员在确认的测试环境执行。

## 1. 从哪里给员工开权限

首次配置建议由有授权管理能力的超级管理员集中操作：

1. 工作台进入 **系统管理 → 权限管理**，页面标题为“账号与权限管理”。只有账号支持权限时只能处理账号，不能配置功能权限。
2. 选择 **按员工**，搜索姓名、工号或登录账号，选中正确员工。
3. 在 **操作权限** 搜索下文的中文名称或权限码，逐项开启；如弹出单项授权确认，核对后确认。
4. 点击 **保存更改**，等待保存成功。不要把“待保存”当作已经授权。
5. 让该员工刷新工作台或重新进入相应页面，核对实际入口和本人可处理的待办。

业务页面右上角 **权限设置** 是便捷入口：选择可管理部门、员工，调整该页面列出的权限，再点 **保存更改**。负责人只能转授自己可转授、且在管辖范围内的权限；没有该按钮或目录缺项时，由超级管理员在上述完整目录处理。

审批和付款应逐人配置，不把这些权限放入“全员基础包”，也不要为省事给整个部门全部开启。“本组全部授权”不能代替敏感权限的逐项确认。**操作权限、可查看数据、组织负责人、审批设置是不同事项**，只增加查看范围不会获得审批权。

本次新行政财务申请权限及“配置负责人回避审批人”默认关闭，**只允许超级管理员逐人授予**，不能由部门矩阵、负责人转授或全选自动带出。报销四个新审核节点须逐项开启，不随批量全选带入；它们与新申请权限的授权策略不同。

## 2. 先核对部门与负责人，再配置审批权

1. 工作台进入 **行政与人力资源部 → 部门管理**，选中业务部门，点 **编辑部门**。
2. 在 **部门负责人** 选择该部门直属在岗员工，点 **保存**。维护者需要“查看部门”及“设置部门负责人”（`department:view`、`department:manager_assign`）；普通“编辑部门”不能代替负责人设置权。公司/决策层组织骨架不设置负责人，应选择下级业务部门。
3. 再到“权限管理 → 按员工 → 操作权限”，为实际审核人员开启对应的“审核本部门报销”“审核本部门申请”及原件权限。

普通部门首审范围取审核人的真实组织关系：其担任负责人的部门、主部门、兼职部门及各自下属部门。只给审批权限不能任意选择另一部门，更不能通过“可查看全部数据”扩大首审管辖。

设置负责人不会自动取得审核权；反过来，明确获得节点权限的同部门审核员工也可处理范围内其他普通员工的申请。请只给公司实际指定的审核人员开启，不以职务名称推定权限。负责人字段还用于识别其本人申请，决定是否必须走预配置回避人。

主部门不正确时，由有权人事人员在员工详情使用 **调岗**；真实兼职关系在编辑员工档案的 **兼职部门** 维护。不要为了临时审批改员工组织关系；负责人本人的申请应使用下一节的回避配置。财务、采购、副总和总经办节点按各自权限办理，不要求把每位申请人都调到财务或总经办。

## 3. 按岗位逐项开启

### 申请人

| 页面里的中文名称 | 权限码 | 开启后用途 |
| --- | --- | --- |
| 提交报销申请 | `expense:apply` | 我的申请中的费用报销、出差报销；本人保存、修订和提交 |
| 填写出差申请 | `application:apply:travel` | 仅出差申请 |
| 填写付款申请 | `application:apply:payment` | 仅普通付款申请 |
| 填写预付申请 | `application:apply:prepayment` | 仅供应商预付，供应商必填，不用于员工个人借款或预支 |
| 填写供应商付款申请 | `application:apply:supplier_payment` | 仅供应商付款申请 |

“填写行政财务申请”（`application:apply`）会同时开放上述四种非报销申请。只需要其中一种时，选对应单项，不必给通用权限；本次不含工资申请。供应商选择器已按申请用途提供候选，不需要因此另开“查看供应商”全表权限。

### 审核及办理人员

| 岗位 | 报销权限名称与码 | 其他申请权限名称与码 |
| --- | --- | --- |
| 部门首审 | 审核本部门报销 `expense:approve:department` | 审核本部门申请 `application:approve:department` |
| 财务初核 | 报销财务初核 `expense:approve:finance_initial` | 财务初核申请 `application:approve:finance_initial` |
| 财务复核 | 报销财务复核 `expense:approve:finance_review` | 财务复核申请 `application:approve:finance_review` |
| 总经办终批 | 总经办批准报销 `expense:approve:executive` | 总经办批准申请 `application:approve:executive` |
| 采购意见 | — | 采购部审核供应商付款申请 `application:approve:procurement` |
| 副总审批 | — | 副总审批供应商付款申请 `application:approve:vice_executive` |
| 财务接收保管 | — | 接收出差申请归档 `application:receive` |
| 实际付款登记 | 报销打款 `expense:pay` | 登记申请付款 `application:pay` |
| 预付账务关联 | — | 关联供应商预付财务入账 `application:prepayment:link_finance` |

旧“审批报销”（`expense:approve`）不能代替新的四级节点。只需要查看时用“查看报销单”（`expense:view`）或“查看申请记录”（`application:view`），并核对实际数据范围；查看权不产生审批待办。营销的订单审批继续使用原订单审核权限，不因开通报销或申请审批而自动获得。

报销票据的查验登记由财务初核或财务复核人员办理；部门首审、总经办终批不因此自动获得查验操作。

### 原件、附件与付款来源

| 人员/动作 | 一并核对的权限和前提 |
| --- | --- |
| 审核人员、负责人本人申请的替补 | 标准建议配“查看附件列表” `attachment:view` + “下载附件” `attachment:download`。报销审核、回避候选必须具备；有原件的通用申请批准及其候选也须具备。无附件出差申请的审核、接收保管不把这两项作为硬前置，可按实际需要配置。 |
| 申请人补原始凭证 | “上传附件” `attachment:upload`；为实际查看与核对原件，同时配查看、下载。报销、付款、预付、供应商付款提交前须有本单扫描检查通过的原始附件；出差申请不强制上传附件。 |
| 出纳/付款登记人 | 相应付款权限 + 附件查看、下载；首次上传付款证明还需上传权限。须有扫描检查通过的银行回单或现金签收证明。申请人和本轮已审核人员不能付款。 |
| 报销出纳的账户选择 | 另需“查看收付款账户” `account:view`，否则报销付款面板的账户选项无法读取。费用类别已按报销付款上下文提供，不必因此额外授予整个费用类别管理权限；其他申请出纳不据此一律加账户查看权。 |
| 普通付款申请的财务来源 | “查看采购付款” `finance_payment:view` 或“查看一般费用” `finance_expense:view`，按实际选择的财务单类型配置，并具备该财务行的数据范围。 |
| 供应商付款申请的财务来源 | “查看采购付款” `finance_payment:view` 及相应财务行数据范围；不能用一般费用替代。 |
| 供应商预付的实付登记 | 有“登记申请付款”和付款凭据权限即可按真实付款登记；此阶段不需要为了找财务单而开放全财务数据。 |
| 供应商预付的独立入账关联 | `application:prepayment:link_finance` + `finance_payment:view` + 附件查看、下载，并能访问对应合法预付财务行；不能是本申请人。 |

供应商预付先登记实际付款，显示“已付款 待财务入账”，不会新建费用或扣减系统账户。之后只有同供应商、同金额、同实付日的合法已审核 PREPAYMENT 财务付款记录可关联；没有合法候选就继续跟进。不能通过增加权限启用被限制的新预付会计算法，也不能用普通费用/非预付付款记录替代。**不需要给所有审核人员“查看全部报销数据”或全财务数据。**

预付“独立关联”指独立权限和独立动作，不强制再增加一名人员。只要不是申请人、具有完整关联权限与财务行范围，原审核人或原付款登记人也可关联；它不是再次审批或再次付款。

## 4. 配置负责人本人申请的回避审批人

这一步由另一名配置管理员完成；申请人不在单据中挑选审批人。

1. 为实际配置人员逐项开启 **配置负责人回避审批人**（`approval_policy:manage`）。这项只管理配置，不授予业务审核权。
2. 先给拟任替补开通其要处理的“审核本部门报销”和/或“审核本部门申请”，以及附件查看、下载。两类业务都需要代审时两项都开；只具一类权限即使能被选中，也不能处理另一类。
3. 确认替补在职、登录账号已启用且未锁定，已完成首次改密；不能选择该部门负责人本人。
4. 由另一名配置管理员进入 **系统管理 → 审批设置**，也可从审批中心顶栏进入。
5. 找到目标部门，核对 **部门负责人**，点击 **配置**，在“负责人本人申请时的审批人”选择已授权替补，点击 **保存设置**。

负责人即使有配置权，本部门这一行也不能自行改选或清除回避人，应交另一配置管理员处理。跨部门替补只获得所配置负责人本人申请的首审范围，不因此获得该部门所有普通申请，也不需要虚构兼职关系。

负责人或回避配置改变后，相关首审单据可能显示“待重新提交”。先完成配置，由申请人撤回重提；不能靠删掉再加回相同人员恢复旧单授权。提交和每级通过前都会检查后续合格人员，整条链应先配置齐全。

## 5. 用精简测试分工核对一遍

普通报销先准备 **6 名不同的在职员工，各自使用启用且有效的普通账号**，避免用超级管理员兼办所有环节。分权按员工身份判断，同一员工的不同账号不能算成两名审核人。下表六名业务人员可覆盖主要链路；另用 G 测负责人本人回避，配置操作沿用现有授权管理员。测试财务人员、负责人或终批人自己的申请时，还须为各受影响节点准备额外合格备选，不能让其本人继续审核，也不能把同轮其他节点人员临时挪来兼审。

| 示例账号 | 业务分工 | 可合并但不能在同一单重复办理的职责 |
| --- | --- | --- |
| A | 申请人 | 只开所需申请权和原始附件能力 |
| B | 部门负责人首审 | 可同时负责供应商付款的采购意见；该供应商链不经过部门首审 |
| C | 财务初核 | 可在供应商付款链担任副总节点；该链没有财务初核节点 |
| D | 财务复核 | 供应商付款的财务意见亦使用此岗位权限 |
| E | 总经办终批 | 对应总经理最终批准 |
| F | 付款登记/出差财务保管 | 未参加该张单前面的审批时才可办理；预付关联仍须另开独立权限 |
| G（回避专项） | B 本人申请的预配置首审人 | 有部门首审及原件权限，在该张单不再兼任初核、复核、终批或付款 |

按以下顺序测试，凭证用隔离测试资料：

1. A 建报销或普通付款/预付，按 **B → C → D → E → F** 办理；报销及普通付款/预付都是四审加付款，申请人另算一人。
2. A 建供应商付款，按 **B（采购）→ D（财务）→ C（副总）→ E（总经理）→ F** 办理。
3. A 建出差申请，按 **B → E → F（接收保管）** 办理；不出现付款步骤。
4. B 自己申请报销，由 **G → C → D → E → F** 办理，B 不能审自己的单，也不能自己更换 G。
5. 选一单驳回，确认申请人待修订红数出现，原单修订重提后旧轮审批不能接着用；再核对一名无权限或不在管辖范围的账号看不到对应待办。

同一人可以在不同单据、不同业务承担不同岗位；**同一张单同一轮不能兼审多个节点，审核人员不能再付款**。TRAVEL 的接收人可来自其他流程的财务初核/复核岗位，前提没有办理这张出差申请的前序审批。

## 6. 常见情况怎么查

| 现象 | 按顺序检查 |
| --- | --- |
| 我的申请里缺一个新建卡片 | 是否给了对应类型申请权并保存；是否只开了报销权或查看权；刷新工作台。四种非报销类型各自授权，不互相推定。 |
| 部门审批中心不出现 | 节点权限是否保存有效；主/兼职部门或负责人管辖是否真实匹配；是否当前在职有效账号。零待办不应通过放宽全公司查看范围解决。 |
| 有中心但没有当前单 | 是否轮到该节点；是否申请人本人、已在本轮审过、已撤回/驳回；是否属于另一部门；是否应去财务或总经办的节点中心。 |
| 无法选择部门负责人 | 必须是该部门直属在岗员工；先核对真实员工归属。公司/决策层骨架节点不设负责人。 |
| 回避候选列表为空 | 部门审核权限、附件查看/下载是否都有效；员工是否在职、账号启用且未锁定、首次改密完成；是否误选该部门负责人本人。配置管理员不必另获全员员工档案查看权。 |
| 替补能选中但某类申请仍不能审 | 是否只给了报销部门审核而缺申请部门审核，或反之；配置不自动补另一业务权限。 |
| 自己或同一财务人无法继续通过/付款 | 属于本人回避、同轮兼审或审批付款分权；换已经配置的合格人员，不能通过增加全量权限绕开。 |
| 提示后续没有合格人员 | 后续节点是否有与申请人、本轮已审人分离的在职有效账号；节点权、原件权限及付款证明能力是否齐全。 |
| 预付已付款但没有可关联候选 | 属正常待入账跟进；核对独立关联权、财务行查看范围及供应商/金额/实付日/预付类型/已审核状态。没有合法记录不能改选普通费用来办结。 |
| 已读通知但红数还在 | 通知已读不等于业务办结；红数随实际提交、审批、修订或其他动作变化。黄数表示等待其他环节或待入账跟进。 |
| 保存或办理结果不明确 | 先刷新/核对原状态；保留输入和保护草稿，不连续重放、不换付款/关联动作试探，也不删掉未知操作保护。 |
