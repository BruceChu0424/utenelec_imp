# 81 - V461 恢复委外备料来源类型

## 一、背景

V436 为「委外目标出仓备料」在 `production_material_analysis_items` 增补了
来源类型 `SUBCONTRACT_PREPARATION`（目标备料行）。V458 重写
`production_material_analysis_item_source_type_chk` 时基于 V234 基线清单，
**漏带了 V436 的增补值**，清单退化为：

```
'SALES_ORDER_ITEM','REWORK','TRIAL','SAMPLE','STOCK','OTHER',
'MAKE_COMPONENT','SUBCONTRACT_MAKE'
```

而委外备料链路全部主代码仍在写该类型（SubcontractPreparationCoordinator、
SubcontractPreparationEntitlementHandoffService、PreplanAnalysisStockPegService、
MaterialAnalysisService、MaterialAnalysisContracts、ChainNoticeService、
SubcontractPreparationTaskAdapter）。V458+ 真库上任何备料目标行 INSERT
都被该 CHECK 以 23514 拒绝；`SubcontractPreparationEntitlementHandoffMigrationPostgresTest`
的 `seedHandoffFixture` 播种即在 CI 全量套件中先行触发（focused stub 不落库，
与 V460 同一暴露模式）。

## 二、变更

- 仅恢复 `source_type` 清单中的 `'SUBCONTRACT_PREPARATION'`，其余枚举值与
  V458 完全一致；
- 不加表（表计数不变）、不动 `parent_shape_chk`（该类型不带
  `parent_analysis_material_id`，V436 以来语义不变）。

## 三、验证

- `SubcontractPreparationEntitlementHandoffMigrationPostgresTest`（fixture
  播种 + 精确交接 + 旧版释放回滚接受新批次）恢复通过；
- `LegacyBootstrapSchemaCompatibilityPostgresTest` 等四个迁移彩排随
  `MigrationRehearsalSupport` 常量升至 V461/423 同步通过；
- reset 白名单（`server/ops/reset_business_data.sql`）与契约测试
  `ResetBusinessDataScriptContractTest` 增至 V461/423。

## 四、影响

零行为变化（恢复 V436→V458 期间的合法状态），不重写历史行，无数据回填。
