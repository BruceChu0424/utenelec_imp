# 仓库管理枢纽页

路由 `/warehouse`。实现为 [WarehouseHubPage](../../lib/features/warehouse/pages/warehouse_hub_page.dart)，徽章数字来自服务端徽章汇总(入口口径登记在 `WorkbenchBadgeCatalog`, 前端映射 [badge_registry.dart](../../lib/shared/badges/badge_registry.dart), ADR-108)。页面按当前权限显示卡片，不以页面显隐替代服务端对象范围校验。

## 岗位入口（2026-09-24 模块三段式统一）

hub 固定三段式：任务中心（查看/办理）→ 新建单据（creator-only 直达新建页，一律不挂徽章）→ 库存查询/报表（浏览型，不挂数）。总设计见[模块三段式统一](../01-规划/2026-09-24-模块三段式统一-任务中心查单与模块新建.md)。

| 入口 | 分区 | 办理内容 | 待办来源 |
|---|---|---|---|
| [仓库任务中心](仓库任务中心页.md)（`/warehouse/tasks`） | 任务中心 | 出库 / 入库 / 生产领料 / 品质检查结果 / 委外成品退货 / 委外损耗 六大类一站式查看与办理 | 卡角标 = warehouse 容器待办累计（与顶栏药丸、工作台仓库卡同源）；各大类红/黄徽章见任务中心页文档 |
| 新建其它出库 / 新建产成品出库 / 新建其它入库 / 新建产成品进仓 / 新建调拨 / 新建盘点 | 新建单据 | 直达对应 `/warehouse/:code/new` 编辑页（进卡即新建态，不显示历史） | 不挂数（2026-09-24 用户口径：新建入口不需要通知数量徽章；草稿在新页「草稿(N)」按钮与任务中心草稿分段可见） |
| 即时库存 / 货架目视化清单 | 库存查询 | 库存查询与挂牌 | 不挂数 |
| 仓库报表（明细/汇总） | 报表 | 汇总 | 不挂数 |

领料单 / 生产退料刻意不在新建区：由生产链自动生成（齐套建 DRAW、报工/退料闭环），手工单没有计划包与执行段映射，出库链路会被台账守卫拒绝；临时性出入库用「其它入库/其它出库」。原出入库单据区（调拨/盘点列表卡）与委外成品退货/损耗两张历史只读卡已于 2026-09-24 撤下（浏览并入任务中心对应大类，路由保留）。销售开出货单只选择产品和数量，仓库在[销售出货作业](销售出货仓库作业页.md)中确认实际仓库和库位。

## 徽章、退料与刷新

- 顶栏红药丸读 `badgeModuleTodoProvider(BadgeModule.warehouse)`(徽章汇总里 warehouse 容器的红数, 服务端求和, ADR-108)，工作台仓库卡同源，不在枢纽再手写另一套加法。2026-09-21(ADR-100)起顶栏左边多一枚黄色「进行中」药丸 `badgeModuleInProgressProvider(BadgeModule.warehouse)`，是另一条链的另一次求和，红黄互不相加。
- `warehouseProductionDraw` 与 `warehouseProductionReturn` 分别登记一次。领料卡已合计两者，不能再把该卡总数登记到模块形成双计。
- `warehouseProductionReturnPendingCountProvider` 只在已登录且有仓库单据查看权限时请求正式待实收数。申请不直接加库存；仓库真实确认后才入账并减少待办。取消、完成的历史不计入。
- 计数按登录身份、代操作身份及只读代操作状态隔离，切换身份后不展示前一人员的成功缓存。首次读取失败保持未知；同一身份轮询失败保留上次成功值，后续继续恢复。
- 仓库写成功和返回枢纽通过 `invalidateWarehouseTaskCounts` 统一刷新，包含生产退料；仅刷新当前列表而遗漏模块/导航计数不算完整接线。

## 测试宿主合同

应用启动会注入 `sharedPreferencesProvider`。新增生产退料徽章后，枢纽顶栏即使某张卡不可见，也可能经注册表读取计数。实际红测链为 `productionReturn → stockDocRepositoryProvider(wdraw) → apiClientProvider → connectionRecoveryProvider → apiBaseUrlProvider → sharedPreferencesProvider`，会话身份也是同图依赖。只覆盖权限或旧的待办provider，不能完整模拟应用宿主。

枢纽Widget测试使用独立mock SharedPreferences并在ProviderScope注入，保持真实会话/权限读取链能够构建。依赖就绪后的初始异步读取须等待稳定，不能仅pump一次就在仍有计时器时销毁宿主。本次修复只补5个测试宿主的prefs及其中两个的`pumpAndSettle`，没有移除生产退料、放宽权限、替换业务provider或把异常伪装成0。退料身份隔离、失败恢复和仓库任务计数另由对应provider及任务中心测试覆盖。
