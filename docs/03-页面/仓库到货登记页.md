> **采购允许超收与最多可收([ADR-144](../99-决策记录-ADR/ADR-144-采购允许超收比例与超出部分财务审批.md) / V799)**：
> 采购订货明细可以约定「允许超收%」p(空 = 0)。单张与批量登记页对采购明细显示「最多可收(含允许超收 p%)」：
> 这一行此刻最多还能收多少 = 订货量 + 允许超收量(订货量 × p%，4 位小数四舍五入) − 此前净已收(已收 − 已退)，只作显示；
> 判定以服务端到货容量为准：累计可收 = 订货量 + 允许超收量 + 已退货量 + 已过账的财务批准超量 + 质检退回补货额度，
> 按累计净收货计，与分几批无关。累计收货在最多可收以内照常入库、立应付，不打扰财务；**超过最多可收的部分才转财务**：
> 整张收货单隔离(不入库、不立应付)，提示「实际到货超过最多可收数量(订货量加允许超收比例)；本次未入库、未立应付，
> 已转交财务审核组共享待审」，到货异常卡片写明「订 Q，允许超收 p%(最多 Q+T)，此前已收 R，本次实到 D，累计 R+D，需审批超量 X」。
> 预计到货仍在累计收到订货量时关闭；关闭后供应商再送来允许超收以内的货，由采购员用手工采购收货单登记，走同一闸门。
> 允许超收量不写进预计到货的订货量，也不写进已过账超量。委外订货不设允许超收比例。
>

> **委外回厂短交确认(V636 / [ADR-098](../99-决策记录-ADR/ADR-098-委外允许损耗与回厂短交判定.md))**：

> 本次登记后累计回厂(已审核回厂净量 + 本次)低于 `订货量 × (1 − 允许损耗)` 的行，

> 批量登记页共用同一个弹窗「到货数量明显少于订货量」——「继续登记并通知委外」= 原请求体加 `shortDeliveryAcknowledged=true`

> 弹窗期间「正在登记」全屏遮罩先撤下(它在 root Overlay 里会盖住后推的弹窗路由，不撤就点不动按钮)，确认后再盖回去。

> 货先留在待入库不要上架」。委外一给出结论(分批到货 / 接受损耗)就自动放行，仓库不用找人解锁。单张确认、跨单批量确认两条路都拦。

> 委外判定(分批到货 / 接受损耗)或后续到货让累计回厂到齐 / 进入允许损耗范围时，系统在同一事务里按上架位置自动转正，仓库不用点任何按钮。
> 等判定期间这批货也会列在「品质合格待入库」里，手工点「确认入库」会说明「货已上架，等委外判定短交后才能转为可用库存；判定完成系统自动转入，
> 仓库不用再点确认入库」。入库放行闸按**收货单**：一张收货单任一行待判定整张先不入库，同一订货单的其它收货单不受影响。
> 容差内未到齐 / 行未设允许损耗 不弹窗(只开中性案件)；**料还没全部发给委外商的行也不弹窗**——委外商手上只有我方已经发过去的
> 那部分，回厂少是分批发料的常态，不判短交、不开案件。仓库只登记事实并确认知情，是分批到货还是接受损耗由委外在
> [委外回厂短交判定页](委外回厂短交判定页.md) 判定。中断草稿「继续送检」按已知情记案件。

>
> **委外回厂超过可回厂套数走财务隔离**：委外回厂数量超过「我方发给委外商的材料能做出来的数量」时，登记**照常建单**——
> 实物已经到厂了，拦下来只会让它落在账外。登记时仍然拦的只有一种：数量物理上够、但额度被同一明细另一张还没审核的
> 登记单占住，这是并发撞单，刷新后重来即可。审核时这一批**不入库、不立应付**，转成到货异常交给财务审核组确认价格和归属，
> 仓库看到的原话是「回厂数量超过我方发给委外商的材料能做出来的数量，多出来的部分用的是委外商自己的材料；本次未入库、
> 未立应付，已转交财务审核组确认价格和归属」。财务批准的自带料入库时不消费我方直属物料，一键入库走得通；

> 没有财务批准，这部分一件都进不了库存。

## 入口和职责

预计到货任务中心 `/warehouse/inbound/expectations` 中，单张任务进入 `/warehouse/inbound/receipts/new`；多选任务进入批量登记页。来源由 `ProcurementReceiptPrefill` 带入，不能无来源编造订货行。

仓库填写实际到货量、单位、每行实际仓库、收货人和库位等信息。2026-09-12 起底部
「取消 / 先质检后入库」(2026-09-20 前叫「登记并送检」)改为右下角悬浮操作组（与品质批量审批页同款），吸底操作条退役。页面不录入价格、金额、币种、汇率和结算方式；服务端按已获财务批准的原订货单读取这些信息。创建的就是采购收货单或委外进仓单，无需其它部门重复录入。

## 业务步骤和数量

1. 采购订货财务批准后形成预计到货。委外还须已有仓库真实审核发出的直属物料，且委外商手里能做成的委外件套数大于已回厂量；已提交未发的领料草稿不能冒充已发出。
2. 仓库按本行单位填写本次实到数量。少到、多到都据实登记，不把不同单位的数量直接相加。数量乘原换算率才是库存基本量。
   2026-09-28 起每行可选填「实称重量」(千克口径，见下节)；货品基本单位或本行单位登记了「等于哪种重量单位」时，重量由数量精确换算，格子只读「=25 kg」、不提交重量。
   称出来的重量只作为仓库重量账与单重学习的事实，默认不改数量；「按称重改数量」必须人点确认。
3. 点击“先质检后入库”(原“登记并送检”)，服务端在一次事务中创建、审核收货并进入品质待检。采购超过最多可收(含允许超收)、委外超过可回厂套数的部分先隔离，财务决定接受量或退回；隔离部分不能直接增加库存或应付。
4. 品质 PASS 只形成合格待入库量。仓库核对本次实际入库量和库位后，才增加库存、推进物料齐套。支持分批确认，不能把已登记或已检验量当成已入库量。
5. FAIL 走实际退货和补回处理，沿原订货行保留数量及来源。撤回只反向已经实际发生的记录；存在不可撤回的下游使用时拒绝整次动作，不能留下半笔撤回。

采购可收量 = 订货量 + 允许超收量 + 已退货量 + 已过账的财务批准超量 + 质检退回补货额度 − 已收；页面「最多可收」只作显示，以服务端到货容量与数据库收货守卫为准。委外可回厂量同时受「委外商手里能做成的委外件完整套数」、财务批准的自带料、已审核回厂、合法实物退回补货额度和订货净未收量约束，到货登记、回厂审核、发料红冲容量与回厂提醒用同一段服务端算法。免费补回不再次消耗原自有材料；补货分配不能在“已审核回厂”之外又重复扣除一次。

## 批量登记表的表头快速筛选（2026-09-11）

## 到货来源

单张、批量登记的每行均提供“到货来源”，使用同一个控件：

| 选择 | 处理方式 |
|---|---|
| 自动识别 | 只有一种可收来源时由服务端识别；正常到货和已退未补同时存在时，要求员工明确选择 |
| 正常到货 | 使用正常未收额度，不占用已退未补额度 |
| 先补退货 | 先补回已退数量，超出部分按正常到货处理；是否免费或重新计款以原退货处理结果为准 |

框内图标支持鼠标悬停、点击和键盘阅读说明。这个选择属于本批实物事实，不学习为该货品以后所有到货的默认值。`replacementIntent` 使用 `NORMAL` / `RETURN_REPLACEMENT`；自动模式不发送该字段，保留旧调用的单一来源兼容。

## 仓库、去向和记忆提示

每行必选真实入库仓库，主/子仓级联选择，支持统一设置全部行。优先带出货品/颜色在本主仓范围内最近一次成功审核收货的有效子仓，没有记录才回退分析建议仓或原来源仓。临时下拉选择、失败、草稿、隔离和已撤回收货不作为成功仓库记忆。

原物料 UUID、来源切片和实际叶仓共同决定预定归属。按 ADR-075，有完整来源证明的合格专属物料跟随实际叶仓，不因换到另一主仓就自动变成公共库存；其它分析的专属物料和未检库存仍隔离。页面显示每条原预定的预计去向、基本量、产品、分析、计划/工单和负责人，变更实际仓须核对。登记阶段不产生合格库存；最终归属以合格后的仓库实际入库事务及 `actualAllocations` 为准。

自动带出的库位、系列、编码和仓库显示黄框、淡黄底色、框内来源图标。手动修改后清除黄标；只聚焦、移动光标或输入法组合状态变化不算修改，表格滚出再滚入也不恢复已确认的黄标。文本状态由 `UtenAutofillTextController` 持有。

登记成功后异步调用 `goods-profile-hints`，不阻塞返回任务中心。空值跳过，编码只在主档为空且全局不重复时回填；系列、库位实际改变才更新，并记录负责人。货品UUID始终是引用身份，编码和名称只是业务标识；主档建议库位不能覆盖历史入库实际库位。

## 提交、重试和任务跟进

单张页按实际仓库分组，批量页按订货单和实际仓库分组，每组一张收货单顺序提交。每次新打开的登记页持有独立登记批次标识，参与请求身份计算，避免两次真实到货数量相同却回放上一张单。来源、数量或实际仓改变会改变该组请求身份；原页相同内容丢响应重试保持相同 key。已成功组在原内容重试时回放原结果，不重复登记；失败组保留内容供处理。

失败提示只有一个口径(`arrival_registration_failure.dart`，2026-10-05 委外批量登记实测后收口)：服务端明确拒绝(有 HTTP 状态且 < 500：校验、业务冲突、数据库守卫，事务已整体回滚)原样显示服务端原因；只有结果不确定(断网、超时、5xx)才显示「登记结果未确认…请保持当前内容直接重试，同一内容重试不会重复登记」；本机草稿保护的异常(草稿在别处被改、登录身份变化)显示其自带的下一步。服务端明确拒绝后的本机草稿检查点写入失败不得顶替服务端原因(`runFormDraftSubmission`)。委外回厂/领料的数据库守卫(V798)由 `GlobalExceptionHandler` 按约束名翻成大白话 409，不再落成通用「数据已被其他操作更新」。

服务端按当前制单人和 `idempotencyKey` 锁定命令，并比较规范请求哈希：同 key 同请求返回原结果；同 key 改内容返回冲突，不能覆盖原事实。到货来源进入哈希。制单人、命令终态及结果不可变。

成功后返回任务中心就地刷新列表和徽章，不自动跳进采购/委外金额详情。任务步骤明确显示：待登记、草稿待继续送检、超量待财务、待品质、合格待仓库入库。旧草稿可通过 `arrivals/{receiptId}/complete` 续办，由服务端修复缺失的来源表头再走同一审核链。已登记草稿量计入 `registeredQty`，避免未送检期间重复登记。

预计到货搜索匹配订货单号、供应商、货品编码和名称，分页与计数使用一致的任务可见条件，输入防抖且仅最新请求回写。委外直属物料实际发出、可回厂套数大于已回厂量时，按出仓单 UUID 幂等通知仓库「委外预计回厂」，通知不构成到货事实。

2026-09-12：采购和委外仓库审核网关共用各自的 `approveReceipt` 事务内核，仅执行权威校验与送检，不再额外加载仓库不消费的商业详情。普通采购/委外审核接口仍返回原详情合同。批量继续送检仍使用整批来源预锁和原审核链，不把超量隔离或品质待检改成可用库存。

## 称重(实称重量)与称重计数(2026-09-28，ADR-135)

- **格子**(共享 [weightGridColumn](../02-组件库/WeightGridColumn.md))：填净重(扣除箱/袋)，可直接输 850g、1.2t、3斤、2lb，失焦后换成列单位；
  0 或空 = 没称。学到单重时占位「约 12.5」，单重未学准时「可选」。录入单位是账号级偏好(工具条「称重单位: 千克▾」)。
  **重量格永不批量生效**：勾选多行后改一行的重量只改这一行(一次称重是一个物理事实)。
- **称重核对列**：按学到的单重(货品 × 本行订货单供应商)核对实称与本次实收，超出容差且统计显著才出标签，如「偏少约 238个 (-4.8%)」
  (琥珀 = 有偏差，红 = 偏差较大)；单重未学准、按称重改过数量或没称的行留空。只提示，不拦截登记。
- **格内 ⚖ 称重计数**(到货场景，见[称重计数弹窗](../02-组件库/WeighCountDialog.md))：毛重(可「再称一次」累加) − 皮重 × 件数 = 净重，
  按单重折算件数(95% 区间 + 可靠度)。主按钮「只记重量」；次按钮「按称重改数量」并提示「将按估算数量入账, 影响对账」——
  点了之后「本次实收」黄框待核对(ⓘ 写推算区间)，该行标记 `qtyFromWeight`，不参与单重学习。弹窗里可顺手录「本批抽样」，
  保存为一条带本单供应商的称样记录。
- **表尾**：「明细 N 行 · 本次实收 … · 实称 125.3 kg (未称 3 行) · 称重偏差 2 行」。表单草稿保存重量、`qtyFromWeight` 与黄框状态。
- **提交**：`POST /api/warehouse/inbound/arrivals` 每行 `weight`(千克，HALF_UP 4 位；没称或按重量计的行不发)与 `qtyFromWeight`(仅为 true 时发送)。
  客户端内容派生的幂等键对称过或按称重改数量的行追加重量片段(千克 + 0/1)；服务端请求哈希同样覆盖重量与 `qtyFromWeight`
  (后者只在 true 时加入，未称重的老请求哈希不变)。服务端对按重量计的货品 / 行单位丢弃客户端重量，由重量账按数量精确换算。
- **单重学习**：登记事务内对每条称过的收货行记一条 RECEIPT 称重观测(数量 = 收货数量 × 换算率，供应商 = 订货单供应商，
  捕获键 `RECEIPT:<收货明细 id>`)；按称重改数量的行、按重量计的行不记。观测在审核送检之前写入，超量隔离的到货也保留；
  撤回收货把这些观测标为已红冲；断点草稿续办(`complete`)不记观测。
- **往下游**：收货重量 → 品质检验 → 合格放行按比例切片 → 仓库确认入库记为 SLICE 重量(见[合格待入库任务页](采购委外IQC合格待入库任务页.md)
  「放行重量」列)。V743 起 IQC 入库校验只在流水重量来源为 MEASURED / SLICE 时核对切片重量，未称的入库由重量账推导，不再在提交时报错。
