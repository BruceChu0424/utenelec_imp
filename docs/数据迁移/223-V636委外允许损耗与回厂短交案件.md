# V636 委外允许损耗与回厂短交案件

- 迁移：`V636__subcontract_loss_tolerance_and_short_delivery_cases.sql`。
- 口径来源：2026-09-20 用户原话「委外件是可能有损耗的...在委外下单那里每个货品加个列允许损耗范围, 加个记忆下次自动填写...仓库收货数量少于允许范围就弹窗并通知委外人员...让委外自己判断是分批入库还是允许入库...记录这个订单的损耗比, 以后按供应商汇总」；设计见 [ADR-098](../99-决策记录-ADR/ADR-098-委外允许损耗与回厂短交判定.md)。
- 依赖：V201 到货异常案件(案件模型原型)；V221 供应商处材料守恒(损耗单核销余量)；V330 委外损耗单与超耗责任(结案自动损耗单走它)；V486 批准后受控改量(结案改量走它)；V593 主档默认值预填(允许损耗记忆同一条路)；V572 审计全表 sweep 之后新表须自带审计触发器。

## 应用侧

- 后端 `WarehouseArrivalRegistrationService.register()`：委外登记前经 `SubcontractShortDeliveryPort.evaluateArrival` 只读评估，低于下限且未带 `shortDeliveryAcknowledged=true` 时 409 `SUBCONTRACT_SHORT_DELIVERY_UNACKNOWLEDGED`(fieldErrors 逐行大白话)；收货单审核送检成功后 `recordArrival` 同事务开立/刷新案件、完成自然到齐、发 Outbox 通知。
- `SubcontractShortDeliveryService.decide()`：`WAIT_MORE` 写判定与预计到齐日；`ACCEPT_LOSS` 顺序固定为 损耗单(`SubcontractWasteService.recordShortDeliveryLoss`) → 案件记损耗 → 受控改量(`SubcontractOrderService.changeQtyForShortDelivery`) → 记改量 id；供应商处剩料多于短交折算量时改量下限高于累计回厂, 结案被拦并提示先退料/损耗单。
- `FulfillmentWorkbenchQueryService`：委外任务中心 `status=IN_PROGRESS` 映射三档、`statusCounts.IN_PROGRESS` 合计、委外订货单 `display_stage` 细分执行状态、`exception_code` 补 `SHORT_DELIVERY/FINANCE_REJECTED`、`/count` 红徽章加短交待判定的订货单。
- 通知 `SUBCONTRACT_SHORT_DELIVERY_DETECTED`(紧急) / `SUBCONTRACT_SHORT_DELIVERY_WAIT_OVERDUE`(重要, 调度器每日一次) / `SUBCONTRACT_SHORT_DELIVERY_RESOLVED`(只撤卡)，聚合 `SUBCONTRACT_SHORT_DELIVERY_CASE`。
- 前端：订货编辑页「允许损耗%」列(主档记忆预填黄标)、到货登记/批量登记页 409 确认弹窗、委外任务中心三段 + 状态列 + 异常小类行、新页 `/subcontract/short-deliveries`、供应商列表「损耗率(%)」列与详情页「委外损耗」段。
- 验证：`SubcontractShortDeliveryPolicyTest`、`SubcontractShortDeliveryMigrationContractTest`、`SubcontractShortDeliveryEndToEndTest`(UTEN_RUN_DB_TESTS)，Flutter 对应页测试；隔离 worktree `sc-loss` + 克隆库 `uten_imp_scloss` 实机。
