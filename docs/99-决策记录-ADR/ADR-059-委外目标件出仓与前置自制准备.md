## 一、问题与根因

委外不是“只进不出”的采购。公司必须先把待加工的委外目标件交给委外商，委外商加工后回厂，经 IQC 合格放行后进入仓库待入库，再由仓库确认实际量与实际库位。

ADR-042/V304 的候选实现把这一前提写反了：

- 订货货品有 BOM 时，把一级 BOM 子件直接发给委外商；
- 订货货品无 BOM 时，认定“委外商自备料”，不生成任何出仓任务。

这导致委外订货仍像采购到货，且会绕过公司内部的领料、装配、报工、质量放行和仓库实收。

## 二、不可妥协的业务不变量

1. **委外出仓永远是订货目标件本身**，货品/ 颜色/ 单位/ 数量与委外订货行一对一对应；不再把 BOM 子件当作新单的委外出仓目标。
2. **有子层级的目标件必须先内部自制**：独立物料分析 → 按整树自底向上备料 → 生产计划审批 → DRAW 仓库真实发料 → 开工/装配 → 报工 → FQC → 仓库实收入库。仅当该订货行的整批前置数量完成，才释放委外出仓。
3. **无子层级的目标件直接进入待出仓**；仓库选定发出仓并保存拣货草稿时，为该订货行建立专属库存预留。库存不足时必须显式阻断，不得负库存或占用其他单据的预留。
4. **前置自制入库不能提前满足原生产需求**。该批库存必须在同一事务转为 `SUBCONTRACT_OUTBOUND` 专属预留，继续从 `v_stock_available` 扣除；委外回仓必须先有 IQC PASS，再由仓库确认实际入库，只有仓库已确认量才能作为原物料分析的合格供给。
5. **先出后进**：新语义订货行的委外回厂数量不得超过已审核出仓的目标件数量扣除已回厂/已反向的剩余。未出仓先进仓必须 fail-closed。
6. 任务投影、单据状态、库存预留、供应商处保管台账和质检记录是权威事实；通知只是可靠提醒，不能代替 `allowedActions` 和服务端门禁。

## 三、两种业务来源、同一条执行链

### 3.1 直接委外

委外部门在委外订货列表下单，不再在委外管理首页重复展示“两种下单入口”说明卡。商业字段仍经“保存并提交财务 → 财务批准”生效；批准事务内逐订货行判断活动 BOM 是否存在。

- 无 BOM：`DIRECT_OUTBOUND/READY_OUTBOUND`，生成 EC 出仓草稿和仓库待办。
- 有 BOM：`MAKE_THEN_OUTBOUND/ACTION_REQUIRED`，通知计划/生产。持 `subcontract_preparation:view + subcontract_preparation:start` 者在独立 `/subcontract/preparations` 待办选择仓库，并以实时 `allowedActions=START_PREPARATION` 显式启动。已建分析的打开动作另需 `production_material_analysis:view`；前置自制权限不反向授予生产分析阅读。

### 3.2 物料分析委外

原生产物料分析确认 `SUBCONTRACT` 路线后，仍先生成只读委外申请，由委外任务中心分解成一个委外商的订货单。订货财务批准后与直接委外使用同一分支判断；不在 Flutter 页面用名称或层级显示做决策。

有 BOM 时启动的是一个独立的“委外前置自制”分析，其产出只能交给该委外订货行。原分析仍等待委外回厂 IQC PASS 后的仓库实际确认入库，不得因前置自制成品入库或只有 PASS 事实而提前变为齐套。

> **2026-08-31 V447 后置实现**：V447 已建立独立的 append-only 跨分析权益交接账。启动前置自制时，服务端按相对 `bom_item_id UUID[] + goods/color/unit UUID` 将原分析子树与 `SUBCONTRACT_PREPARATION` 子树逐行精确映射，追加父产出 `TAKEOVER`、未来供给 claim，并以 `SUBCONTRACT_HANDOFF_OUT/IN` 成对事件移动已有及后续 exact entitlement；不改物理预留、不释放公共库存，也不复用人工让料优先补齐。原树只扣减本委外行接管的递归子件需求，委外父件需求仍等待真实回厂。未审批申请只作为被接管容量，不伪装成确认在途；采购/委外订货或生产计划正式生效后才投影目标分析在途，仓库实际确认入库后再移动 exact 权益。目标分析尚无领料、产出或消费时允许受控取消，按相反事件恢复 exact 与父需求；已有真实执行事实则失败关闭。完整结构、约束、升级与验收见 [V447 委外前置自制跨分析权益交接](../数据迁移/70-V447委外前置自制跨分析权益交接.md)。

委外工作台任务中心不再放置“委外前置自制”重复入口卡；来源分析节点、委外订货进度和通知动作仍可进入精确任务。委外任务中心的业务阶段默认“全部”，由人员主动收窄。

## 四、行级状态与混合单据

同一订货单可同时有无 BOM 行和有 BOM 行，因此准备状态必须落到订货行/出仓计划行，不能只放在订货单头：

```text
ACTION_REQUIRED
  → IN_PREPARATION
    → WAITING_FQC
      → WAITING_FINISHED_INBOUND
        → READY_OUTBOUND
          → PARTIALLY_OUTBOUND / OUTBOUND_COMPLETE
            → PROCESSING
              → RETURNED_PENDING_IQC
                → PARTIALLY_QUALIFIED / COMPLETED
```

无 BOM 行从 `READY_OUTBOUND` 开始。仓库出仓任务中心只返回已释放的行；`ACTION_REQUIRED/IN_PREPARATION` 只在生产域待办和委外订货进度中展示，不给仓库一个无法执行的假出仓单。

## 五、仓库、回厂和质量链

1. 系统释放出仓行时生成 EC 单号；仓库选发出仓、经办人和本次数量，保存时建专属预留，审核时只能消耗自己的预留并产生出库流水。
2. 目标件转为委外商处保管台账；新语义冻结单耗为 1，回厂数量按 1:1 消费该目标件台账。历史 `LEGACY_BOM_COMPONENT` 行继续按 V221 冻结 BOM 单耗核销。
3. 委外商回厂先登记实际到货/进仓草稿，审核后只建 IQC 待检隔离；PASS 只形成品质合格待入库量，仓库确认实际量与实际库位后才进合格库存并推进原生产供给；FAIL 不进可用库存并进入退回/处置。
4. 可分批出仓、分批回厂和分批 IQC PASS，但有 BOM 的前置自制必须整个订货行批量完成后才首次释放出仓，防止一边拼装一边把不完整批次交给委外商。
5. 财务批准时创建的 `inbound_expectations` 只保留审批快照，不等于仓库已可能收货。新流委外行只有真实目标件出仓审核后才进入预计到货；部分出仓只开放本批容量，收满/IQC 结案后在下一批出仓前退出。财务批准不得提前通知仓库预计到货。
6. 回厂草稿与出仓红冲必须按订货明细共用事务行锁。IQC 失败实物退回的总量只加回一次，全部已审核回厂统一扣减；replacement allocation 只证明补货归属，不能在读取容量中再次扣减。出仓红冲后发布补偿通知，最终以实时预计到货投影为准。

## 六、通知与稳定待办入口

| 事件 | 主要收件人 | 稳定动作入口 |
|---|---|---|
| 有 BOM 订货行财务批准 | 同时有 `notice:read + subcontract_preparation:view + start` 的计划/生产人员；委外制单人收进度回执 | `/subcontract/preparations`：开始/打开物料分析 |
| DRAW 待发/已发 | 仓库；计划/生产 | 既有生产领料待办/执行进度 |
| FQC 待检/放行 | 品质；仓库 | 既有 FQC 任务/生产成品待点收 |
| 目标件整批可出仓 | 仓库；委外制单人 | 仓库委外出仓任务/订货进度 |
| 委外出仓审核 | 仓库预计回厂岗位；委外制单人；有分析来源时回执来源负责人 | 预计到货/订货全链进度 |
| 委外出仓红冲 | 仓库预计回厂岗位；委外制单人 | 撤回本批预计回厂提醒；以实时任务投影为准 |
| 已出仓且供应商处净结存临近/超过交期 | 委外制单人；有分析来源时原分析制单人 | 订货全链进度 |
| 回厂已登记/IQC 待检 | 品质；委外制单人 | IQC 任务/订货进度 |
| IQC 部分/全部 PASS | 持 `warehouse_iqc_stock_in:view` 的仓库人员 | `/warehouse/iqc-stock-ins`；PASS 只生成待入库，不增加库存 |
| IQC 结案 | 仓库；委外制单人；分析来源负责人 | PASS 转仓库待入库；FAIL 转退回/处置；仓库确认后才可推进原分析与订货结案 |

`SUBCONTRACT_RETURN_DUE` 使用 `BusinessTime` 每日扫描，并以
`orderId + businessDate` 幂等发布。新流只认 V221 供应商保管台账的净结存；全量物理回厂、
材料退回或损耗核销后不再发送，即使 IQC 仍待检也不得误报为委外加工逾期。IQC 滞留继续由
品质任务投影负责，不与供应商回厂交期混为同一事件。

通知由业务事务写 Outbox，由 `ChainNoticeService` 幂等生成通知页记录。所有未读通知由 Flutter 统一到达协调器同时投影到顶部非阻塞通知栈；新通知在最上层，多条可叠放/展开/逐条关闭，不再弹居中阻塞对话框。顶部关闭仅表示本设备已展示；点击主动作才按现有规则标记已读/跳转。

本节是 ADR-052 通知到达展示策略的后置决策：取代其“`important/urgent` 默认进入居中持久窗”和“任意时刻只派发一个活动项”的 Flutter 默认行为。优先级继续决定语义颜色、标题前缀、停留时间和栈内排序，但不能把业务通知升级为阻塞当前仓库/生产操作的模态窗口。既有 `notice_user_states.popup_acknowledged_at` 字段与 popup-ack API 保留给历史记录和兼容调用；默认 Flutter 到达链不再写 popup ack，也不得把 popup ack 当作顶部通知已展示、通知已读或业务完成的权威事实。

### 6.1 V437 页面与动作权限矩阵

V437 只登记活动权限码、`action_type`、文案与精确 `permission_surface_permissions`；**不给部门、角色或个人默认授权**，也不把旧 `subcontract_receipt:price:view` 克隆到其它页面。升级后需权限管理员按真实岗位显式授权；未授权即 fail-closed。

| 页面/事实 | 阅读 | 写动作与附加门禁 |
|---|---|---|
| 计划下达的委外申请 | `subcontract_application:view` | 申请只读；分解同时要求 `subcontract_order:create + subcontract_order:decompose`，并在保存事务内重验剩余量/归属 |
| 委外订货 | `subcontract_order:view` | create/edit/delete/submit_finance/reverse 均是独立权限；财务批准/驳回用 `finance_order_approval:approve/reject` 并叠加实时财务资格 |
| 前置自制 | `subcontract_preparation:view` | 启动另需 `subcontract_preparation:start`；打开已建分析另需 `production_material_analysis:view` |
| 仓库目标件出仓 | `subcontract_outbound:view` | 补单/执行 `subcontract_outbound:execute`，关闭 `:close`；计划生成的 EC 编辑/删除/审核/红冲仍叠加对应 material-issue 动作，并统一展示在 `warehouse.subcontract-outbound` surface |
| IQC 合格待仓库入库 | `warehouse_iqc_stock_in:view` | 确认另需 `warehouse_iqc_stock_in:confirm`；品质 PASS 权不得推导仓库确认权；同一员工不得对同一 PASS 兼任放行与确认，超级管理员也无同人例外 |
| 历史发料页 | `subcontract_material_issue:view` | 不提供空白新建；已审历史保留受控查看/红冲，不抹除反向能力 |
| 回仓、成品退、材料退、损耗 | 各自 `:view` | 各自 create/edit/delete/approve/reverse；IQC 继续由品质查看/处置权限决策，不由委外页面授权 |
| 委外报表 | `subcontract_report:view` | 导出另需 `:export`；商业金额另需 `subcontract_report:price:view` |
| 应付/损耗索赔 | `ar_ap_ledger:view + finance:view:all` / `subcontract_loss_claim:view` | 付款预览另需 `finance_payment:create`；索赔 review/fulfill/reverse 分开，不以损耗建议金额代替财务决定 |

商业字段服务端按真实页面分开脱敏：询价、订货、进仓、成品退货、损耗建议额和报表互不代替。材料出仓/材料退当前页面无商业单价事实，不伪造价格权限；其历史成本形字段仅 `finance:view:all` 可解密。列表归属继续按 `maker_id`，跨负责人需 `subcontract:view:all`；通知、页面按钮和超管前端 fallback 均不得恢复已停用的 `subcontract_outbound:handle`。

## 七、异常、反向与并发

- BOM 必须在准备任务创建时冻结指纹；循环、禁用子件、单位缺失或自动补位 stub 均 fail-closed。后续修改 BOM 不静默改已开始的准备批次。
- 出仓草稿改仓/改量使用 CAS：同事务释放旧预留并建新预留；删草稿、关闭余量、订货红冲对称释放。已出库必须先自下游回厂/退料/损耗反向，不得直接抹掉。
- 前置自制实收仓与冻结准备仓不同时必须阻断或经显式改派，不得静默跨仓扣减。
- 仓库确认每个 PASS 切片必须提交并锁内复核 `expectedRemainingBaseQty`；同键同体只重放原结果，
  同键异体、余量变化、跨仓或同一员工先 PASS 后确认均失败关闭，不提供单维护人或超管同人绕过。
- V447 活动交接期间禁止取消/改指原供给 action、allocation 或原分析；目标分析取消必须先证明无已领料、已生产、已出仓或已消费权益，再按 exact slice 全量恢复。交接表及事件表禁止 UPDATE/DELETE。
- 并发锁顺序继续遵守 inventory dimension → analysis/plan/package/segment → subcontract plan/order → stock document/item；预留、准备分配、出仓、回厂和反向命令均需幂等键与数量守恒约束。

## 八、明确不支持的边界

1. 本链假设“出仓待加工件”与“回厂委外成品”使用同一货品身份且数量 1:1。若加工前后是不同货号、有收得率、一出多进或多出一进，必须在主数据建立不同 SKU/转换关系后另立迁移，不得用备注或人工改数绕过 1:1 守恒。
2. 前置自制完成不等于委外完成；FQC PASS、FINISHED_IN 草稿、通知送达都不能替代仓库实收和目标件真出库。
3. 加工费应付仍由委外回厂合格链投影；目标件出仓只是公司自有存货转为委外商处保管，不立采购应付。差异、余料、损耗与扣款继续按 V221/V304 及后续损耗守恒处理。

## 九、迁移、兼容与发布结论

- V304/V305/V221 是不可改写的历史迁移。V436 只向前增加新语义字段、行级准备事实、专属预留/实收分配、新流守恒和审计覆盖。
- 存量 V304 计划行标记为 `LEGACY_BOM_COMPONENT`，继续按冻结 BOM 子件解释；不猜测它们其实是目标件，也不批量改为 1:1。
- V447 在 V446 后增加跨分析需求/权益所有权，并要求新应用识别新的 entitlement 事件。部署必须严格执行“停止全部旧实例 → 迁移 V446 → 迁移 V447 → 只启动新应用 → 后验收”的停机切换；禁止新旧 JAR 滚动混跑，也禁止应用 V446/V447 后用旧 JAR 回滚。失败时保持停写并走备份恢复或新的前向修复。
- 新单候选验收至少覆盖：两种业务来源、无 BOM 直接出仓、有 BOM 完整前置自制、混合行、分批出/进/IQC、未出先进阻断、专属预留不泄露、反向、并发、对象权限、Outbox 幂等和 Flutter 顶部叠放。
- 分析来源前置自制另须覆盖：部分接管、同货品多路径不串线、未审批供给不冒充在途、正式在途只投影一次、仓库入库自动交接、取消全量恢复，以及源/目标并发取消失败关闭。
- 源码/空库/定向测试不等于生产上线。目标非空库迁移、旧 `LEGACY_BOM_COMPONENT` 对账、真实计划/生产/仓库/委外/品质多岗位 UAT、备份恢复、签名构建与部署回读未完成前，该链继续 **NO-GO**。
