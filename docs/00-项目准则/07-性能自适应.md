# 07 - 性能自适应

> 本项目跑在 200–1000 人企业的各种设备上：从车间主管手里三年前的低端安卓，到 IT 部门崭新的 iPad Pro，到行政办公的桌面 Web。**一套代码必须让所有设备都用得舒服**——性能好的设备更炫，性能差的设备自动降级，绝不能因为档位低反而卡。
> 本准则是 [00-准则索引与开发清单.md](00-准则索引与开发清单.md) 第 6 条"性能自适应"的展开，是动画规范 [06-动画规范.md](06-动画规范.md) 的基础。

---

## 一、设计目标

| 目标 | 说明 |
|---|---|
| 自动适配 | 启动时探测设备，自动落到合适档位，零用户干预 |
| 高端更炫 | rich 档放玻璃模糊、3D 卡片、粒子、完整 stagger |
| 低端够用 | lite 档砍掉一切 GPU 重活，保证 60fps 流畅 |
| 手动覆盖 | 用户可在设置页强制选档位（自动 / 省电 / 标准 / 极致） |
| 运行时降级 | 检测到发热、低电量时，rich 自动回退 standard |
| 统一接口 | 所有组件只读 `performanceTierProvider`，不自己探测 |

## 二、三档定义表（详细）

### 2.1 总览

| 档位 | 中文名 | 英文名 | 目标设备 | 目标体验 |
|---|---|---|---|---|
| `lite` | 省电 | lite | 低端安卓、老旧平板、Web 弱机 | 流畅但不炫，60fps 必须达成 |
| `standard` | 标准 | standard | 主流中端机、默认 Web | 标准动画 + 轻度模糊 |
| `rich` | 极致 | rich | 旗舰机、iPad Pro、桌面 | 玻璃模糊 + 粒子 + 3D |

### 2.2 功能差异矩阵

| 功能 / 效果 | lite | standard | rich |
|---|---|---|---|
| BackdropFilter / ImageFilter.blur | ❌ 禁用 | ✅ 轻度（σ≤5） | ✅ 玻璃模糊（σ≤15） |
| ShaderMask 自定义着色器 | ❌ 禁用 | ⚠️ 仅简单渐变 | ✅ 允许 |
| 骨架屏 Shimmer | 静态灰色 | ✅ 闪烁 | ✅ 闪烁 |
| 动画时长 | ×0.5（压缩 50%） | ×1.0 | ×1.0 |
| 数字滚动（AnimatedNumber） | ❌ 直接显示终值 | ✅ 开启 | ✅ 开启 |
| Hero 动画 | ❌ 禁用 | ❌ 禁用 | ✅ 开启 |
| 列表 stagger 进场 | ❌ 禁用，直接渲染 | ✅ 前 6 项 | ✅ 前 6 项 |
| 列表项进场方式 | 无动画（或极短 fade） | fade + slide | fade + slide |
| 页面转场 | 纯 fade，时长砍半 | fade + slight slide | fade + slight slide |
| 3D 卡片倾斜（基于陀螺仪/指针） | ❌ 禁用 | ❌ 禁用 | ✅ 开启 |
| Dashboard 粒子背景 | ❌ 禁用 | ❌ 禁用 | ✅ 开启 |
| 卡片按下 scale 反馈 | ✅ 仅 ripple | ✅ ripple + scale | ✅ ripple + scale |
| Lottie 动画 | ❌ 改静态图 | ✅ 关键反馈 | ✅ 关键反馈 |
| 主题切换 fade | ❌ 直接切 | ✅ fade | ✅ fade |
| 图片缓存质量 | 缩略图优先 | 标准 | 原图 |
| 列表图片懒加载 | ✅ 必须懒加载 | ✅ 必须懒加载 | ✅ 必须懒加载 |

### 2.3 lite 档铁律

> lite 档的核心是**砍 GPU 重活**。下列任意一条违反，PR 直接打回。

1. **禁用** `BackdropFilter` / `ImageFilter.blur`，全部退化为纯色背景
2. **禁用** 复杂 `ShaderMask`，仅允许简单线性渐变
3. **禁用** Hero 动画
4. **禁用** 数字滚动、stagger、3D 倾斜、粒子
5. 动画时长统一 ×0.5（包括转场）
6. 骨架屏不闪烁，用静态 `Color(0xFFE0E0E0)` 占位
7. 大列表必须 `ListView.builder` + 图片懒加载，**禁止** `Column(children: List<Widget>)`

## 三、自动检测机制

### 3.1 检测维度

| 维度 | 数据源 | 用途 |
|---|---|---|
| 平台 | `Platform.isAndroid/iOS/...` | Web/桌面走默认档 |
| 内存 | `device_info_plus` 设备信息 | 主判断依据 |
| CPU 核数 | `device_info_plus` | 辅助 |
| Android API level | `device_info_plus` | API<24 直接 lite |
| 屏幕分辨率 | `MediaQuery` / `display` | 高分屏才考虑 rich |
| 像素密度 | `MediaQuery.devicePixelRatio | dpi≥3 才考虑 rich |
| iOS 设备型号 | `device_info_plus.utsname.machine` | 老机型识别 |

### 3.2 评分规则（默认）

| 条件 | 落档 |
|---|---|
| Web 端 | **standard**（无法可靠检测硬件） |
| Windows / macOS / Linux 桌面 | **rich**（桌面算力充足） |
| Android API < 24（< Android 7.0） | **lite** |
| 物理内存 < 3GB | **lite** |
| 物理内存 3–6GB | **standard** |
| 物理内存 > 6GB **且** 分辨率 ≥ 1080p **且** devicePixelRatio ≥ 2.5 | **rich** |
| iOS device model 命中"老机型清单"（iPhone X 以前、iPad 2017 以前） | **lite** |
| 其余 iOS | **standard** |
| 任何探测失败 | **standard**（保守兜底） |

> iOS 老机型清单维护在 `lib/core/performance/legacy_ios_devices.dart`，每年新机发布后更新。

### 3.3 用户覆盖优先级

最终档位 = 用户手选 > 自动降级（发热/低电） > 自动检测。

```
auto（用户选了"自动"）
  └─ 从硬件探测得到基础档（lite/standard/rich）
       └─ 运行时检测发热/低电量
            └─ rich → 降为 standard（不降 lite）
standard（用户选了"标准"）
  └─ 固定 standard，运行时不再升/降
省电（用户选了"省电"）
  └─ 固定 lite，运行时不再升/降
极致（用户选了"极致"）
  └─ 固定 rich，但**发热/低电时强制降到 standard**（保护设备）
```

## 四、代码实现

### 4.1 `PerformanceTier` 枚举

```dart
// lib/core/performance/performance_tier.dart

/// 性能档位。三档自动降级，用户可手动覆盖。
enum PerformanceTier {
  /// 省电：禁用一切 GPU 重活，动画时长压缩 50%
  lite,

  /// 标准：默认档，标准动画 + 轻度模糊
  standard,

  /// 极致：玻璃模糊、粒子、3D 倾斜、Hero 全开
  rich,
}

/// 用户在设置页里的选择。
enum PerformancePreference {
  /// 跟随自动检测
  auto,
  /// 强制省电
  lite,
  /// 强制标准
  standard,
  /// 强制极致
  rich,
}
```

### 4.2 设备探测（device_info_plus）

```dart
// lib/core/performance/device_probe.dart

class DeviceProbe {
  /// 探测设备能力，返回建议档位。
  static Future<PerformanceTier> detect() async {
    // Web：无法可靠检测，默认 standard
    if (kIsWeb) return PerformanceTier.standard;

    // 桌面：算力充足，默认 rich
    if (Platform.isWindows || Platform.isMacOS || Platform.isLinux) {
      return PerformanceTier.rich;
    }

    // 移动端按内存 + API 判断
    if (Platform.isAndroid) {
      final info = await DeviceInfoPlugin().androidInfo;
      if (info.version.sdkInt < 24) return PerformanceTier.lite;
      // 物理内存（KB 转 GB 估算），很多设备不报告则兜底 standard
      final memMb = (info.systemFeatures.contains('android.software.leanback'))
          ? 0
          : _estimateAndroidMemory(info);
      if (memMb > 0 && memMb < 3072) return PerformanceTier.lite;
      if (memMb > 6144) return PerformanceTier.rich;
      return PerformanceTier.standard;
    }

    if (Platform.isIOS) {
      final info = await DeviceInfoPlugin().iosInfo;
      if (LegacyIosDevices.isLegacy(info.utsname.machine)) {
        return PerformanceTier.lite;
      }
      // iPhone 13 Pro 及以上、iPad Pro 视为 rich
      if (_isHighEndIos(info.utsname.machine)) return PerformanceTier.rich;
      return PerformanceTier.standard;
    }

    return PerformanceTier.standard;
  }

  static int _estimateAndroidMemory(AndroidDeviceInfo info) {
    // 项目里如果有原生 channel 报 /proc/meminfo，则用真实值；
    // 否则按机型/CPU 核数粗估，保守偏 standard。
    // 详见 lib/core/performance/memory_probe.dart（如有）
    return 0;
  }

  static bool _isHighEndIos(String machine) {
    return const ['iPhone14,2', 'iPhone14,3', 'iPhone15,', 'iPad13,', 'iPad14,']
        .any((p) => machine.startsWith(p));
  }
}
```

### 4.3 `PerformanceProvider`（Riverpod）

```dart
// lib/core/performance/performance_provider.dart

const _kPrefKey = 'perf_preference';

/// 当前生效的性能档。所有 UI 都读这个。
final performanceTierProvider = Provider<PerformanceTier>((ref) {
  return ref.watch(performanceControllerProvider).effectiveTier;
});

/// 用户的偏好选择（设置页用）。
final performancePreferenceProvider
    = Provider<PerformancePreference>((ref) {
  return ref.watch(performanceControllerProvider).preference;
});

/// Controller：合并 [用户偏好] + [自动探测] + [运行时降级]。
final performanceControllerProvider =
    NotifierProvider<PerformanceController, _PerfState>(
  PerformanceController.new,
);

class _PerfState {
  final PerformancePreference preference;
  final PerformanceTier detected;
  final PerformanceTier effectiveTier;
  final bool thermalThrottling;
  final bool lowBattery;

  const _PerfState({
    required this.preference,
    required this.detected,
    required this.effectiveTier,
    required this.thermalThrottling,
    required this.lowBattery,
  });

  _PerfState copyWith({
    PerformancePreference? preference,
    PerformanceTier? detected,
    PerformanceTier? effectiveTier,
    bool? thermalThrottling,
    bool? lowBattery,
  }) =>
      _PerfState(
        preference: preference ?? this.preference,
        detected: detected ?? this.detected,
        effectiveTier: effectiveTier ?? this.effectiveTier,
        thermalThrottling: thermalThrottling ?? this.thermalThrottling,
        lowBattery: lowBattery ?? this.lowBattery,
      );
}

class PerformanceController extends Notifier<_PerfState> {
  late SharedPreferences _prefs;

  @override
  _PerfState build() {
    _prefs = ref.read(sharedPreferencesProvider);
    final prefStr = _prefs.getString(_kPrefKey);
    final pref = PerformancePreference.values.firstWhere(
      (e) => e.name == prefStr,
      orElse: () => PerformancePreference.auto,
    );

    final initial = _PerfState(
      preference: pref,
      detected: PerformanceTier.standard, // 探测完成前保守用 standard
      effectiveTier: PerformanceTier.standard,
      thermalThrottling: false,
      lowBattery: false,
    );

    // 异步探测硬件，完成后更新
    Future.microtask(() async {
      final detected = await DeviceProbe.detect();
      state = state.copyWith(
        detected: detected,
        effectiveTier: _resolve(pref, detected, false, false),
      );
    });

    // 监听电量 / 发热（见 4.5）
    _listenRuntimeSignals();

    return initial;
  }

  /// 用户在设置页切换偏好。
  Future<void> setPreference(PerformancePreference pref) async {
    await _prefs.setString(_kPrefKey, pref.name);
    state = state.copyWith(
      preference: pref,
      effectiveTier: _resolve(
        pref, state.detected, state.thermalThrottling, state.lowBattery,
      ),
    );
  }

  /// 运行时降级回调。
  void _onRuntimeSignals({required bool thermal, required bool lowBattery}) {
    final t = thermal || state.thermalThrottling;
    final b = lowBattery || state.lowBattery;
    state = state.copyWith(
      thermalThrottling: t,
      lowBattery: b,
      effectiveTier: _resolve(state.preference, state.detected, t, b),
    );
  }

  /// 合并所有输入得到最终档。
  PerformanceTier _resolve(
    PerformancePreference pref,
    PerformanceTier detected,
    bool thermal,
    bool lowBattery,
  ) {
    PerformanceTier base;
    switch (pref) {
      case PerformancePreference.auto:
        base = detected;
        break;
      case PerformancePreference.lite:
        base = PerformanceTier.lite;
        break;
      case PerformancePreference.standard:
        base = PerformanceTier.standard;
        break;
      case PerformancePreference.rich:
        base = PerformanceTier.rich;
        break;
    }
    // 发热或低电（<20%）：rich 降为 standard；不动 lite/standard
    if ((thermal || lowBattery) && base == PerformanceTier.rich) {
      return PerformanceTier.standard;
    }
    return base;
  }

  void _listenRuntimeSignals() {
    // 见 4.5：BatteryPlus + 监听发热（实现细节略）
  }
}
```

### 4.4 组件读取档位

```dart
// 示例：UtenCard 在 lite 下不渲染 BackdropFilter

class UtenGlassCard extends ConsumerWidget {
  final Widget child;
  final double blurSigma;
  const UtenGlassCard({super.key, required this.child, this.blurSigma = 12});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final tier = ref.watch(performanceTierProvider);

    // lite 档：退化为纯色卡片，零 GPU 开销
    if (tier == PerformanceTier.lite) {
      return Container(
        decoration: BoxDecoration(
          color: Theme.of(context).colorScheme.surface,
          borderRadius: BorderRadius.circular(16),
        ),
        padding: const EdgeInsets.all(16),
        child: child,
      );
    }

    // standard：轻度模糊；rich：完整玻璃模糊
    final sigma = tier == PerformanceTier.standard
        ? blurSigma * 0.4   // standard 压低 σ
        : blurSigma;        // rich 用完整值

    return ClipRRect(
      borderRadius: BorderRadius.circular(16),
      child: BackdropFilter(
        filter: ImageFilter.blur(sigmaX: sigma, sigmaY: sigma),
        child: Container(
          decoration: BoxDecoration(
            color: Theme.of(context).colorScheme.surface.withValues(alpha: 0.6),
            borderRadius: BorderRadius.circular(16),
          ),
          padding: const EdgeInsets.all(16),
          child: child,
        ),
      ),
    );
  }
}
```

### 4.5 运行时降级（电量 / 发热）

```dart
// 用 battery_plus 监听电量
final battery = Battery();

StreamSubscription<BatteryState>? _sub;
int _level = 100;

void startMonitoring() {
  battery.onBatteryStateChanged.listen((state) async {
    _level = await battery.batteryLevel;
    // 电量 < 20 且未充电 → 触发降级
    final charging = state == BatteryState.charging ||
                     state == BatteryState.full;
    final lowBattery = _level < 20 && !charging;
    // 通知 PerformanceController（略，用 ProviderContainer.read 触发方法）
  });
}
```

> 发热检测：Flutter 没有官方 API，推荐两种来源——
> 1. Android 原生 channel 报 `PowerManager.THERMAL_STATUS_*`
> 2. 监听帧率：连续 N 帧 > 35ms 视为压力，临时降一档（5 分钟内无再降则升回）

## 七、测试要求

### 7.1 三档必跑

每个 PR 涉及 UI/动画的，**三档都要手动跑一遍**：

| 步骤 | 操作 |
|---|---|
| 1 | 设置页 → 性能模式 → 极致，跑一遍主流程 |
| 2 | 切到标准，再跑一遍 |
| 3 | 切到省电，再跑一遍 |
| 4 | 任一档有明显卡顿、错位、白屏 → 修 |

### 7.2 帧率检查

```dart
// 调试时打开 PerformanceOverlay（MaterialApp.showPerformanceOverlay: true）
MaterialApp.router(
  showPerformanceOverlay: kDebugMode,
  ...
);
```

- 目标帧率：**三档都要达成 60fps**（lite 档绝不能因为档位低反而卡）
- rich 档允许瞬间掉到 45fps（粒子进场），1 秒内恢复
- standard 档滑动列表帧时间应 < 16ms
- lite 档任何场景都不应超过 16ms

### 7.3 真机覆盖矩阵

每发版前至少在以下设备上跑过：

| 设备类型 | 代表机型 | 期望档 |
|---|---|---|
| 低端 Android | 红米 / 荣耀 3 年前机型，3GB 内存 | lite |
| 中端 Android | 主流国产中端，6GB 内存 | standard |
| 旗舰 Android | Pixel / 三星旗舰，8GB+ | rich |
| 老 iOS | iPhone 8 / iPad 2018 | lite |
| 新 iOS | iPhone 14+ / iPad Pro | rich |
| 桌面 Web | Chrome on 笔记本 | standard |
| 桌面原生 | Windows / macOS | rich |

## 八、性能监控（线上）

### 8.1 自建监控指标

| 指标 | 采集 | 上报 |
|---|---|---|
| 平均 FPS | 自建 `FrameCallback` 计时 | 每 30s 上报一次 |
| 卡顿帧率（< 45fps 比例） | 同上 | 同上 |
| 内存占用（峰值） | `SystemChannels.system` / `ProcessInfo` | 同上 |
| 当前性能档 | `performanceTierProvider` | 同上 |
| 设备型号 / 平台 | `device_info_plus` | 一次性上报 |

### 8.2 阈值告警

| 指标 | 阈值 | 动作 |
|---|---|---|
| rich 档平均 FPS < 50 持续 30s | — | 自动降为 standard，记录到 ADR |
| 任意档内存峰值 > 设备内存 80% | — | 上报 OOM 风险 |
| lite 档平均 FPS < 55 | — | 提交高优先级 bug |

> 监控代码放 `lib/core/performance/perf_monitor.dart`，开关由远程配置控制（默认关闭，灰度时打开）。

## 九、运行时降级触发条件

| 触发条件 | 动作 | 说明 |
|---|---|---|
| 电量 < 20% 且未充电 | rich → standard | 保护续航 |
| 设备发热（ThermalStatus ≥ Moderate） | rich → standard | 保护硬件 |
| 连续 60 帧 > 35ms | rich → standard（5 分钟冷静期） | 自动止损 |
| 用户选 `auto` 后硬件探测迟到 | 临时 standard，探测完成切真实档 | 兜底 |
| 用户手选 `lite` 或 `standard` | **不降级**，尊重用户选择 | 用户优先 |
| 用户手选 `rich` 但发热 | 强制 rich → standard | 唯一覆盖用户的情况 |

---

## 十、禁忌（PR 直接打回）

| ❌ 禁止 | ✅ 应该 |
|---|---|
| 业务里直接用 `BackdropFilter` 不读档位 | 包一层 `UtenGlassCard` 或自己读 `performanceTierProvider` |
| 业务里直接用 `ShaderMask` 自定义着色器 | 同上，lite 档退化为纯色 |
| 无视档位跑 Hero / 粒子 / 3D | 读档位，lite/standard 跳过 |
| lite 档跑 BackdropFilter / Hero / 数字滚动 | 全部禁用 |
| 用 `Column(children: list.map(...))` 渲染长列表 | 用 `ListView.builder` |
| 不开图片懒加载 | 图片用 `cacheWidth` / `precacheImage` 按需 |
| 业务里自己探测设备信息 | 全部走 `DeviceProbe` |
| 业务里自己定义 PerformanceTier 枚举 | 复用 `core/performance/` 的枚举 |
| 动画时长不随 lite 档 ×0.5 | 用 `UtenAnim`，时长感知档位 |
| 用户选了 lite 还强行炫 | 尊重用户，档位是契约 |
| 设置页改了档位 UI 不刷新 | `performanceTierProvider` 是响应式的 |

---

## 十一、对照清单（每次提交前自检）

- [ ] 用了 `BackdropFilter` / `ShaderMask` / 粒子 / Hero / 3D 的，都包了 `performanceTierProvider` 判断

- [ ] lite 档场景在高端机上跑过（验证不因为档位低反而卡）
