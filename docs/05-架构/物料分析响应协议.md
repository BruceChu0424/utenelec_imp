# 物料分析响应协议

物料分析服务保持一套权限、版本、数量和来源快照。读取和命令回执可显式选择传输表示，投影不改变域对象、指纹、命令幂等记录或库存事实。

| 协议 | 协商值 | 内容 |
|---|---|---|
| 原始表示 | 不传或未知版本 | 每条 `flatMaterials` 完整，包含自己的 `warehouseBreakdown` |
| 共享仓库 v1 | `shared-warehouses-v1` | 仓库事实按 `materialKey` 放入 `warehouseBreakdownsByMaterialKey`，节点保留其余完整字段 |
| 稀疏节点 v2 | `shared-material-defaults-v2` | 保留 v1 仓库字典，新增完整的 `materialDefaults`，节点只写与默认字典不同的字段 |

优先读取 URL 参数 `projection`；没有参数时才读取 `X-Material-Analysis-Projection` 请求头。响应带相应 `Vary`。生成计划回执在 `analysis` 中使用同一协议，`replayed` 和 `plans` 保持原值。旧客户端不协商时继续得到原始表示。

## v2 的恢复规则

`materialDefaults` 来源于本次授权快照首节点的实际字段值，包含所有节点字段及 `nodeRole`，仅不含已共享的 `warehouseBreakdown`。它可以包含货品、节点和来源身份，客户端必须先恢复完整行再解释任何身份。空材料列表使用空字典。

恢复每行时先取默认字典，再按稀疏行的实际存在字段覆盖，最后按恢复后的 `materialKey` 接回仓库字典。覆盖条件是键存在；不能使用非空判断。显式 `null`、`false`、`0` 和空数组均能覆盖非空默认值。

后端只有在原始类型值完全相等时才省略字段，`BigDecimal` 比较同时保留数值和 scale。不会把不同精度的小数、未知值、空值与零互相替代。协议本身不做业务计算。

## 内存与验证

`MaterialAnalysisSparseProjection` 每个响应只建立一份默认值数组和仓库字典，材料列表直接复用原快照。序列化逐行比较并写出，不为每个节点构造 Map、JSON 树或第二份完整材料对象。记录字段读取器在类级缓存；增加或改变序列化字段时，完整恢复合同必须继续通过。

`MaterialAnalysisResponseProjectionTest` 验证恢复后的 v1/v2 与原始快照全字段相等，覆盖空材料、千节点、混合默认值、显式空值/零/布尔/数组、小数 scale，以及 query/header 协商和旧协议兼容。

真实规模测量使用 `ProductionMaterialAnalysisScalePostgresTest`。HTTP 测量必须通过 `queryParam` 把协商参数写入实际 URI，并检查响应的 `projection`，不能仅向 MockMvc 参数表放值后把原始响应误记为压缩协议。JSON 字节数是未压缩体积；代理 gzip、客户端解码和实际网络时延应分别核实。
