## 背景

V224 的庆典通知是「一人一卡」：5 位同事同一天生日，调度器和 HR 任务中心「一键全部送祝福」
会发 5 张独立祝福卡——通知列表被刷屏、祝福互动分散在 5 面墙上。
诉求：**今天一共就一张卡**，卡里写明「今天有张三、李四……5 位同事生日」；
入职周年同理，且**各人年数不同**（张三 入职5周年、李四 入职10周年），要逐人标注。

## 结构（V454__notice_celebration_group_cards.sql）

- 新表 `notice_celebration_subjects`：庆典卡主角名单快照。
  - 列：`id` PK、`notice_id` FK notices CASCADE、`employee_id` FK employees SET NULL（可空，
    员工物理删除后姓名快照仍可展示）、`employee_name`、`event_label`（**逐人**标签）+ 审计列。
  - 索引：`(notice_id, employee_id)` 局部唯一（一张卡同一员工只出现一次）+
    `(notice_id)`、`(employee_id)` 查询索引。
- 存量回填：已有单人卡（`subject_employee_id IS NOT NULL` 且 type ∈ 4 类庆典）各补一行主角快照。
- 删除 `idx_notices_subject_type`（V224 去重索引）：去重口径迁到主角表后不再命中任何查询。
- `notices.subject_employee_id/subject_name/event_label` 列保留：单人卡继续写；
  聚合卡 `subject_employee_id=NULL`、`subject_name`=「张三、李四等 N 人」摘要。

## 语义

| 口径 | 行为 |
|---|---|
| 聚合发布 | `CelebrationScheduler`（每日 08:00）与 `POST /notices/celebration/batch` 对当天同类型全部未覆盖主角发**一张**卡；单人主角保持单人卡样式（`祝 张三 生日快乐！`） |
| 周年逐人标签 | 年数按 `EXTRACT(YEAR FROM age(hire_date))` 逐人派生 `event_label`，存主角行；卡标题用类型级标签（`入职周年快乐`），正文逐人点名「张三（入职5周年）、李四（入职10周年）」 |
| 幂等去重 | `(员工, 类型, 当年)` 在 `notice_celebration_subjects` 判定（聚合/单人统一）；已发过不进卡。当天已发卡后又出现新的未覆盖主角（数据补录/当日入职）时，下一轮只为其另发一张补充卡 |
| 我的今日庆典 | 跳转目标按主角表查（老单人卡因回填同样命中） |
| HR 已祝福徽标 | `HrTaskService` blessed 集合改按主角表 join，发布后角标即减（口径不变） |
| 批量接口返回 | `CelebrationBatchResult(published 覆盖人数, skipped 跳过人数, notices 卡数 0|1)` |
| 聚合模板 | 服务端预置面向「各位」的模板（不含 `{name}` 占位符）；前端单人卡 `{name}`→姓名、聚合卡去「{name}，」前缀兜底 |
