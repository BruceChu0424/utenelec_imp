# V816 AI 助手个人操作记忆(ADR-163)

> 编号说明: 本迁移开工时取临时号 V812, 并入 main 时与并行分支 `feat/permission-drawer-rework`(ADR-162, `V812__permission_surface_hierarchy_and_gaps.sql`)撞号, 先改号为 V814, 合并时又与 `V814__workshop_arrival_notice_capacity_watermark.sql` 撞号, 终号为 **V816**, 本文件与 ADR-163 §十 的引用已同步。本文不代表业务数据库已经安装。

## 做了什么

- 新表 `ai_chat_operation_memory`: AI 助手记住的「本人近期问题与当时的解法」, 只属于本人。列:
  - `id` uuid 主键;
  - `user_id` uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE(账号删除连行删);
  - `question_key` varchar(160) NOT NULL CHECK(btrim <> '' AND length <= 160)——规范化后的问题原文(NFKC + 小写 + 去空白标点后截 160, Java 侧 `AiChatDialogueSupport.normalized(message)` 生成并清洗控制字符, DB 不猜);
  - `resolution` jsonb NOT NULL CHECK(jsonb_typeof = 'object' AND octet_length <= 512 AND (resolution ->> 'kind') IN ('OPEN_FORM', 'TOOL'))——OPEN_FORM = 对话里点名开表单并成功出卡(值为 workflow), TOOL = 工具调用成功(值为工具名);
  - `hit_count` int NOT NULL DEFAULT 1 CHECK(>= 1);
  - `last_used_at` / `created_at` timestamptz NOT NULL DEFAULT now()。
  - `UNIQUE(user_id, question_key)`(同 key UPSERT); 索引 `(user_id, last_used_at DESC)`(LRU 收整与建议列表)。
- 表注释写明: ADR-163; 仅本人可见, 不进业务审计; business_data_reset 按 CLEAR 清空。
- 审计分类 NONE(`fn_audit_track_table('ai_chat_operation_memory', 'NONE', 'data_change', false)`): 个人偏好/个人操作痕迹不是业务事实, 行不进通用行审计, 也不另写显式审计事件(口径同 ADR-152 的对话设置)。
- `business_data_reset()` 登记 `('ai_chat_operation_memory', 'CLEAR')`: 以 V805 登记的 `('ai_chat_action_proposals', 'CLEAR')` 为锚点用 DO 块扩展, 末尾自检 DO 块核对登记条目与表存在。
- 不加权限点(只用 `ai:use`), 不改存量数据, 不回填(新表从空开始)。

## 口径

- **仅本人**: 服务端所有读写都带 `user_id = 当前账号`(照 ADR-152 会话隔离口径), 跨账号查不到任何行。
- **UPSERT 语义**: 同 key 同 resolution 只累计 `hit_count + 1` 并刷新 `last_used_at`; 同 key 不同 resolution 覆盖 resolution、`hit_count` 归 1(用户改了主意, 以最新为准)。
- **两个记忆点**: `requestedForm` 命中并成功出卡记 OPEN_FORM; `runTool` 成功返回记 TOOL。recall 命中只 touch(刷计数, 不改 resolution)。
- **保留**: 写入后 LRU 收整保留本人最近 50 行; `last_used_at` 超过保留期(默认 90 天, `AiProperties.operationMemoryRetentionDays`)由 AI 清理任务删除。
- **开关**: 账号设置 `operationMemory` 关闭时不写、不读、不注入, 建议端点回空; 开关与「清除记录」是个人偏好, 不写业务审计。

## 清理与保留

- AI 数据清理任务(`AiJobHousekeeping.purge()`)末尾调用 `purgeUnused(max(1, operationMemoryRetentionDays))` 删超期未用行。
- 清空业务数据(`business_data_reset`)把本表按 CLEAR 全清: 个人操作痕迹随测试数据一起清掉, 不留残余。
- 用户可在对话设置里「清除记录」(`DELETE /api/ai/chat/memory`), 只删本人全部行。

## 回滚注意

- 表里只有个人操作痕迹(规范化问题文本 + 解法枚举 + 计数), 没有业务数据, 丢失无对账意义; 单向 Flyway 无下行迁移, 手工恢复演练时 DROP TABLE 即可, 但要先移除 `business_data_reset()` 里本表的 CLEAR 登记条目, 否则函数引用不存在的表。
- 后续迁移若改列(如 resolution 结构), 注意 CHECK 里的 `resolution ->> 'kind'` 枚举与 Java 侧 `AiChatOperationMemoryService` 的写入形状一致; 超过 512 字节的 resolution 会被 CHECK 拒绝(写入方应保证)。
