# 货品表格保存后退出编辑

## 范围与结果

基线 `c75d6e1e3480057f4bec1a930475b402129f5a90`，独立分支 `uimp/goods-save-exit-20261102`。

修改属于前端交互。货品资料分类/搜索列表点击“保存 N 行修改”，全部保存成功后直接恢复只读表格，保留当前页面、分类及已保存记录，不再需要点击“不保存并退出”。普通视图与全屏共用该行为，新增行也遵守同一批次完成条件。

按 `frontend-design` 复用现有 Uten 主题、表格与按钮；本次只调整保存完成后的状态转换，无新增视觉系统。

## 既有实现比较与调用方

| 入口 | 既有能力及问题 | 本次处理 |
|---|---|---|

| `pages/product_category_page.dart` | 货品分类/全局搜索、普通/全屏共用 `_paneConfig` | 开启 `inlineExitOnSave: true`；既有修改与新增行统一接入 |
| 客户、供应商、模具分类页 | 同一公共 pane，业务继续编辑策略独立 | 保留默认 false；公共实现未复制，未扩展本次货品交互要求到其他业务 |
| 账户、颜色、货币、结算方式、付款方式、单位、仓库和 `MasterInlinePageMixin` 的公共 actions 调用方 | 原本允许保存后继续编辑 | 保留默认 false；既有公共 controller 回归覆盖兼容性 |
| Win7 WPF `Features/Goods/GoodsWorkspaceView.cs` | 明确为只读实现，DataGrid.IsReadOnly=true，无货品编辑/保存入口 | **未迁移**；后续 W7-BIZ-034 接入真实编辑时须遵守整批确认成功再退出、失败/未知保留及旧回执隔离合同，不新增占位写入口 |

Web 与现有 Flutter 桌面端使用同一 Dart 入口；无后端/API/权限或计算契约变更。货品详情单据编辑、BOM 编辑有独立草稿与提交生命周期，不属于本次分类表格保存按钮。

公共能力由参数表达是否退出，保留各业务差异。本轮没有新增平行实现，也没有可移除的重复实现。

## 失败与并发合同

- 保存失败、部分失败、校验失败或未知新增结果时保留编辑会话及尚未确认的输入；已成功行不重放。
- 保存中重复点击不能触发第二次提交；最后一项确认前不退出。
- 过期保存回执不能关闭新身份/新会话中的编辑状态或清除新草稿。
- 新增已确认而刷新失败时继续显示“资料已保存”的核对提示，不通过退出隐藏该错误，也不重复新增。
- 无修改退出继续使用既有离开协议；成功退出后可重新进入编辑。
