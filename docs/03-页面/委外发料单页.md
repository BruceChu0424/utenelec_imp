## 一、页面与权限

- 列表：`/subcontract/material-issues`
- 新建：`/subcontract/material-issues/new`
- 详情：`/subcontract/material-issues/{id}`
- 编辑：`/subcontract/material-issues/{id}/edit`
- 查看权限：`subcontract_material_issue:view`
- 维护、审核与红冲权限：`subcontract_material_issue:edit`，服务端仍按动作和单据状态复核。

## 二、当前安全边界（V304 后）

- 新出仓单由发料计划自动生成（订货财务批准 → BOM 展开快照 → 全量草稿），仓库在
  拣货页改量（≤ 计划余量）、选发出仓后审核；审核=材料出库 + 供应商台账 +
  计划回写（CAS 防超）。
- 手工新建仍可行（历史老单无计划）：明细须挂已财务批准的订货明细，审核冻结
  当前 BOM 首条活动边单耗；服务端 fail-closed 校验不变。
- 草稿的 maker 为空（系统生成）时凭 `subcontract_material_issue:edit` 权限执行；
  自有手工单维持 maker 归属隔离。

## 三、历史单据兼容

| 单据状态 | 页面行为 | 业务含义 |
|---|---|---|
| 草稿 | 可查看、编辑、删除；审核禁用 | 不是已发料事实，不得影响库存或下游可用量 |
| 已审核历史单 | 只读查看；有权限时可红冲 | 保留历史真实发料与库存流水，不回填或重算旧 BOM |
| 已红冲 | 只读 | 保留正反向审计链 |

历史已审核发料仍可作为材料退、损耗的来源。下游可处理量只从具体
`subcontract_material_issue_items` 计算：
`qty - returned_qty - wasted_qty`，并由服务端锁定来源行、防并发超退或超损耗。

## 四、库存与累计量口径

- 历史发料：原审核库存出库事实继续保留；红冲只反向冲销实际存在的历史流水。
- 材料退审核：公司仓入库，并增加来源发料子件 `returned_qty`；不再回写
  `subcontract_order_items.material_returned_qty`。
- 损耗审核：增加来源发料子件 `wasted_qty`。材料发出时已经离开公司仓，
  新损耗不得再次扣公司库存；只有红冲历史上真实存在的损耗出库流水时才做对称补偿。
- `subcontract_order_items.issued_qty/material_returned_qty` 仅保留迁移、历史查询兼容，
  新业务不写、前端不据此计算。
- 所有数量均以货品当前基本单位校验；来源与明细 `unitRate` 不一致时服务端拒绝审核。

## 五、解除门禁的必要条件

解除前必须同时具备并通过迁移、并发和红冲测试：

1. 委外订货由财务审核组批准并转为 `status=1` 时冻结带版本的 BOM 子件快照，后续 ECN 不改写历史；不得再另设委外部门的订单审核绕过财务。
2. 子件需求、累计发出、退回、损耗、合格产出耗用及供应商期末结存有追加式台账。
3. 审核按来源行和子件行加锁，支持幂等，且正向与红冲逐项守恒。
4. 历史单据不重算、不批量回填伪造来源；异常数据先对账、隔离、人工处置。
5. 前后端定向测试、真实岗位权限负向测试和生产迁移演练全部通过。
