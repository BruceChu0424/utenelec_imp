# V622 执行段物料覆盖集合校验

对应迁移：`V622__execution_segment_material_coverage_batch.sql`。

## 根因与边界

真实 PostgreSQL 的 100 来源、20 计划下达诊断中，执行段完整性检查被调用 1660 次；覆盖 CTE 内的单需求 DRAW 计算又被多个判定重复求值，累计调用 43160 次。开启单笔事务的 `SET LOCAL track_functions='all'` 后，单需求函数自耗约 16.51 秒，事务提交约 24.26 秒。这里只记录隔离测试容器证据，不作为公司服务器时延承诺。

迁移新增 `fn_execution_segment_material_coverage(segment)`，按执行段一次聚合需求、预留、历史 DRAW、有效未发指令及净实发/退料。段完整性函数通过 `MATERIALIZED` 覆盖集检查所有需求，避免重复执行相同标量子查询。约束仍在每次触发时检查当前完整段，没有关闭触发器、按状态跳过核对或使用事务缓存绕过检查。

## 保持的数量与身份语义

- 库存覆盖继续按需求 UUID 汇总 `qty-released_qty`，保留实际预留的来源与叶仓事实。
- 历史 DRAW 继续使用原单据基本量，仅匹配原有计划包/执行段映射和原有删除、状态条件。
- 有效未发量采用 V618 的有效指令业务量乘冻结换算率，再扣该 stock item 的全部净 ISSUE。先对 item ID 去重汇总 postings，再回接原映射；同 item 多需求不能把实发重复累计。
- 需求实物净量仍是 ISSUE 加 GOOD_RETURN_REVERSE、减 ISSUE_REVERSE 与 GOOD_RETURN。两部分覆盖的符号和取零边界保持原口径。
- 需求快照、零物料证据、超预留/超领料、完整与持续生产、WAITING、完工清料和跨段映射约束全部保留。

## 迁移与验证

本迁移提供完整、可复核的 helper 和守卫定义，不在运行时读取函数定义做字符串补丁。守卫来自 V621 实际定义，除覆盖查询块外保留原定义；旧单需求函数保留用于兼容和差分核对。没有业务数据修改、历史账重算或旧迁移 checksum 改写。

验证包含 `ExecutionMaterialCoverageEquivalencePostgresTest` 的真实 SQL 差分与变异测试、`ExecutionMaterialCoverageMigrationContractPostgresTest` 的正式 Flyway 621→622 函数体等价合同、`ProductionExecutionSegmentPostgresTest` 的提交期拒绝约束、持续补料/实物退料/独立批次完整服务链，以及同一 100 来源、20 计划函数统计前后对照。统计开关仅在该隔离测试事务生效，提交后恢复；所有量、来源与实际库存结论由测试断言核对，不能用减少 SQL 次数替代正确性验证。

同环境同规模测量中，提交时间从约 24.26 秒降至 7.24 秒；守卫仍调用 1660 次，标量函数重复调用被消除。500 来源仍需同时治理应用层大快照和重复发现成本，不能把 100 来源结果当作最大规模验收。环境及后续优化证据见[数量与规模验证](../99-项目治理/2026-09-20-物料分析数量与规模验证.md)。
