# ADR-039：计划前物料分析备料库存绑定（PREPLAN_ANALYSIS pegging）

> **2026-08-31 IQC 两阶段更新**：V298 的 PASS 同事务绑定保留为历史实现，不改迁移字节。
> 新 exact 归属必须由仓库实际入库确认事件建立，并同时引用对应 quality PASS event；
> PASS 未确认不得建立物理 `stock_reservations`。历史已 PASS/已入库数据须由前向迁移按库存流水
> 建显式基线，不得生成人工确认假历史。见
> [采购 / 委外 IQC 合格待入库任务页](../03-页面/采购委外IQC合格待入库任务页.md)。

- **状态**：已接受（源码候选；V298 已应用本地开发库）
- **日期**：2026-08-18
- **影响**：生产（物料分析/计划下达）、采购、委外、仓库（IQC 处置/收货红冲/自制完工入库）、库存可用量统一口径
- **依赖**：ADR-029 / ADR-033（计划前物料分析与备料 action）、[V90 预留台账](../07-业务链路/02-数据库设计-V90-预留台账与计划订单联动.md)、V298

## 一、背景

计划前物料分析下达的采购/委外订货，到货 IQC 合格入库后没有任何预留锚点，直接成为全系统公共现货（`v_stock_available`）。后果是跨分析重复计库存：旧分析已经买好入库的料，会被新建分析的备料缺口算成自己的可用量，新分析据此少下采购/委外申请。

既有跨分析软承诺（`softCommittedStock`）只覆盖其它分析 depth=1 快照行，深层物料与「已收货但尚未下达正式计划」的在库量完全漏出，无法在计算层修复。

业务语义要求整条链绑定：计划/分析 ↔ 备料物料 ↔ 采购/委外/自制 ↔ 仓库入库一一对应；旧分析备好的料保持归属旧分析，新分析的缺口保持是新缺口。

## 二、决策

### 2.1 入库即绑定（pegging）

- 采购/委外收货 IQC `PASS` 写入合格库存的**同一事务**（`ProcurementInspectionService.dispose`），按「订货明细 → 采购申请/委外申请明细 → 分析供应行动分摊（`preplan_supply_action_allocations`）」溯源到来源分析，写 `stock_reservations` 归属预留行：`owner_type='PREPLAN_ANALYSIS'`、`purpose='PREPLAN_MATERIAL'`、`owner_id=<分析ID>`，仓+货+色粒度，带幂等键。
- 无法溯源到分析供应行动的入库（历史链、无 allocation 的行）保持公共现货，不伪造绑定。
- 自制备料完工入库（`StockDocService.applyFinishedInChain`）对无销售链接的计划行产出，同样补写来源分析的归属预留（`pegFinishedInbound`）。

### 2.2 统一可用量口径不改视图

- `v_stock_available` 定义不变：归属预留本身就是生效预留，自动从公共现货中剔除——销售 ATP、MRP、其它分析、仓库可用量对它一律不可见，无需各消费方分别改造。
- 归属分析自己的可用量 = `v_stock_available` + 本分析生效归属预留：`MaterialAnalysisService.availability()` 与 `warehouseBreakdown()` 加回本分析绑定量（breakdown 新增 `ownPeggedQty` 展示分量）；跨分析软承诺按绑定量净额扣除，防止与 V234 软分配双重扣减。
- 生产执行计划的 `warehouseAvailability()`（预览与下达共用）对分析来源计划行同样加回绑定量，保证预览与正式下达同口径。

### 2.3 生命周期对称，库存事实不重复

- **下达计划包 confirm**（`ProductionExecutionPackageCommandService.confirm`）：同事务先释放分析归属预留，需求分配器再从池中为正式 demand 建 `PRODUCTION_MATERIAL_DEMAND` 预留行——同一物理库存只被一种身份占用，不重复、不漂移。
- **收货红冲**（`PurchaseReceiptService.reverse` / `SubcontractReceiptService.reverse`）：精确反向释放本次入库对应的归属预留。
- **分析取消 / 供应行动撤回**（`MaterialAnalysisCommandService.cancelAnalysis` / `cancelActionLocked`）：对称释放该分析/行动的全部归属预留。
- 任何遗漏释放都会让库存在所有口径中「隐身」，因此释放点必须与绑定点一一对应，由同一端口（`PreplanAnalysisPegPort` / `PreplanAnalysisStockPegService`）集中实现。

### 2.4 历史不回填

V298 只在既有 CHECK 中新增一种归属形态，不回填历史已入库库存；迁移前已入库的分析来源现货仍属公共池，可能被新分析看见。是否回填须经业务对账后单独决定并留证（fail-closed，不用脚本猜测归属）。

## 三、迁移

| 迁移 | 作用 |
|---|---|
| V298 | `stock_reservations` 的 `owner_type`/`purpose`/形态 CHECK 扩展 `PREPLAN_ANALYSIS` + `PREPLAN_MATERIAL` 组合；纯约束加法，无数据回填 |

## 四、后果

- 好处：新分析不再吞掉旧分析已备好的料；计划 ↔ 订货 ↔ 入库全链按来源可追溯；销售/MRP 等外部口径零改动（统一走 `v_stock_available`）。
- 代价：IQC PASS 后的仓库确认入库链多一次来源解析与预留写；红冲、取消、撤回、下达转移都必须对称释放；历史已入库量不回填，旧现货在首次业务对账前仍可能被新分析计入。
- 待续：历史已入库库存是否回填归属绑定（2026-08-18 时点仍开放，待业务决策）；公司目标库迁移与多岗位实物 UAT。
