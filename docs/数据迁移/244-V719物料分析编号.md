# V719 物料分析编号

## 背景

2026-09-25 用户口径：各页面当「计划单号」用的物料分析标签（`物料分析 4f7efc45`
这类 id 前 8 位短号）改成数字；同一天的不同分析显示不同数字；采购/委外的
「来源计划」列也显示同一个数，便于排序。此前采购/委外单据上落的是
`计划前物料分析 2026-09-24` 这种日期字符串——同日多张分析无法区分，也和
计划侧看到的短号对不上。

## 改动（不加表）

1. **编号列与命名空间**：`production_material_analyses` 增加 `analysis_no`，
   格式 `WL+YYYYMMDD+6位日流水`（V279 DocNumberService 口径，前缀 `WL`
   注册进 `business_identifier_namespaces`，终身占号）。`preview` 是唯一
   生产写入方，取号走 `DocNumberPrefix.MATERIAL_ANALYSIS`。
2. **存量回填**：按上海日期分区、`analyzed_at, id` 升序逐日 1..n 回填；
   同时把每个日期的 n 播种进 `business_document_sequences`（GREATEST 合并），
   新分配从存量之后继续。UNIQUE + `^WL[0-9]{14}$` CHECK。
   列允许 NULL：测试夹具直接 INSERT 最小列集，展示处用旧短号回退；
   不挂 V279 逐表占号触发器（该表 24 个测试文件直接插行，编号分配
   唯一入口在 DocNumberService + UNIQUE 兜底）。
3. **谱系标签回写**（只改展示字符串，不动任何数量/关联）：
   - 采购申请头/明细（`source_doc_no`/`production_plan_no`/备注前缀）、
     委外申请头/明细（`source_doc_no`/备注前缀）：经
     `preplan_supply_actions(external_document_type/id → analysis)` 精确回溯；
   - 采购/委外订货单头与明细、收货明细：经 V463
     `purchase_order_item_sources` / `subcontract_order_item_sources`
     回到申请行再回分析，**多来源合并且指向不同分析的行保留原日期标签**。
4. **执行工作台根视图**：`v_production_execution_workbench_roots` 的
   `root_label` 改为 `COALESCE(analysis_no, 旧短号)`（V696 全量重建，
   仅此一处表达式变化）。

## 之后的行为

- 新建分析即铸号；物料分析历史页有「编号」列，详情页顶部事实卡显示编号，
  列表关键字可直接搜编号。
- 下达采购/委外申请时 `sourceLabel` 就是编号本身（不再拼日期），采购任务
  工作台「计划号」与委外任务中心「来源计划」显示同一编号且可排序；
  委外前置自制任务的来源标签、跨计划让料候选/来源标签、让料记录对端标签
  同步改为编号（夹具行回退旧短号）。
- 我的车间任务新增「来源计划」列（ANALYSIS 根显示编号，历史计划根为 —）。
