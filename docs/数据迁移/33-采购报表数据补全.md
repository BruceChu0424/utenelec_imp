## 二、关键取证结论（老库视图定义级）

1. **编号-N = 货品编号 + "-" + 颜色编号**（`B_Color.Number`），不是单据分支。
   老库 `View_P_InItem` / `View_P_WithDrawItem` 原文：
   `B_Goods.ANumber + CASE WHEN isnull(B_Color.Number,'') != '' THEN '-' + B_Color.Number ELSE '' END AS 编号`。
   样例：白色 Number=3 → `280501084-3`；深灰色 Number=15 → `280501067-15`/`280501093-15`。
   注意口径差异：**收货/退货明细**用带后缀编号；**申请/订货明细**（View_P_ApplicationItem / View_P_OrderItem）
   走 `View_Goods.编号` = 纯 ANumber，**不带后缀**。新库报表已按此区分实现。
2. **制单员/审核员 = `Sys_Operator.fname`**（登录账号表，与 B_Worker 是两套 ID 空间，会撞号，
   如 B_Worker.509=李桃秀 而 Sys_Operator.194=李桃秀）。老视图 `View_P_Application/Order/In/WithDraw`
   全部 JOIN `Sys_Operator`。处理：与委外/钱流同模式——迁移时冻结为 `maker_name/approver_name` 文本列，
   不入 employees；报表 `COALESCE(employees 真名, 冻结名)`。
3. **申请单部门 = `P_Application.StepID` → `SystemItem(ItemclassID=5)`**（不是员工 ParentID，
   虽然本例两者都指向 2147 计划部）。老视图原文 `LEFT JOIN SystemItem ON StepID = ItemID`。
   StepID 名字有误导性，实为部门外键。
4. **结帐方式字典 = `B_PStyle`**（14 号文档"无字典表"判断有误）：
   `1现金 / 2提货 / 3代付 / 4支票 / 6月结 / 7垫付(托运部垫付) / 8汇款 / 10代收`（有跳号）。
   常量固化在 `PurchaseSettlementStyle`。
5. **收货"采购员" = `P_In.sman`（业务员）**，老视图不走订货单反查。已迁 `purchaser_legacy_id`；
   实测十几年数据 sman 全空（0 行），报表 COALESCE 回落订货单采购员。

## 五、遗留与后续

- **人事正式录入后**：HR 在员工档案为真员工补 `legacy_id`（= B_Worker.ID）即自动顶替 resigned stub，
  报表人名实时升级；Sys_Operator 冻结名作为历史兜底长期保留。
- **申请明细的"生产计划单号/生产单号"**：老库 `P_ApplicationItem.FPlanNo/ProduceNo` 十几年全空（0 行），
  属老系统未启用字段，列保留不删（复刻口径），非迁移遗漏。
- **收货 sman 全空**：同上，老系统未用；列与回落逻辑已就位，未来启用即有值。
- 同样式「编号-颜色编号」规则可能也适用于销售/仓库/委外报表（各老库 *Item 视图自查），
  用户未反馈前不动，避免过度复刻偏差。
