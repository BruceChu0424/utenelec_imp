## 一、`com.uten.imp.common.report.ReportQueryKit`（2026-09-16）

**位置**：`server/src/main/java/com/uten/imp/common/report/ReportQueryKit.java`（final 工具类，私有构造）。

**来源**：六个报表服务（finance / production / purchase / sales / stock / subcontract 的 `*ReportService`）里逐字重复的私有工具成员收敛而来；原各服务的本地拷贝已删，调用点改指本类。后续**新增报表必须复用本类，不得再拷贝私有副本**。

**成员**（只收完全一致的；有分歧的版本留在原服务，见类注释）：

| 成员 | 用途 | 收敛说明 |
|---|---|---|
| `FacetSpec`（record，5 参 + 兼容 6 参 `orderExpr`） | 列 facet 投影/分组/过滤/排序规格 | `orderExpr` 仅 purchase 的 execute 读取，其余服务固定 `cnt DESC` |
| `WhereBuilder` | base + 若干 AND 子句（带参数）构造 WHERE | finance 的空 fragment 变体留在原服务 |
| `addApprovedByDefault` | 默认口径：草稿（status=0）不进报表（单头别名 `o`） | finance 钱流别名 `t` 的本地拷贝保留 |
| `addCommonDocFilters` | 明细主过滤：单号/供应商/仓库/状态/日期/关键字 | 从 purchase/subcontract 收敛（逐字一致）；sales 取 clientId、production 取 goodsId 的分歧版本留在原服务 |
| `addSummaryKw` | 汇总关键字（单号模糊匹配） | sales 含客户名的版本留在原服务 |
| `facetsOf` | 从全部 query 参数抽取 `f.` 前缀列筛选 | 统一 LinkedHashMap 保插入序 |
| `parseUuid` / `parseShort` / `parseDate` | 导出参数解析（空/空白 → null） | — |
| `paginateAll<T>`（泛型） | 循环分页(size=500)累积全部行；硬上限 2000 页；超 `maxRows` 抛 409 | 各包 `ReportTableResponse` 是独立类型，经 total/exportColumns/rows 三个取数函数适配；`maxRows` 由调用方解析后传入（common 不依赖 SystemSettingsService） |

**范式**：原生 SQL + EntityManager + 各包自带的 `ReportTableResponse`（六包各自定义、结构同型）。排序白名单走同包 `common/report/ReportSort.java`（sort 必须命中列 key 白名单，防 SQL 注入）。

**当前调用方**：六包的 `*ReportService`（subcontract 全量接入）与 finance / production / purchase / sales / stock 五个 `*ReportController`（subcontract 的 controller 内联过滤 `f.` 前缀，未走本类）。

## 二、`com.uten.imp.common.finance.MoneyPolicy`(2026-09-23, ADR-112)

**位置**: `server/src/main/java/com/uten/imp/common/finance/MoneyPolicy.java`(final 工具类)。

**口径**(用户 2026-09-07 确认「财务不四舍五入, 分摊不丢余额」): 金额乘积保留全部位数; 按量分摊一律
「累计量份额 − 已分摊」, 末批取全部剩余; 累计份额整除取精确值, 除不尽取到来源金额自身小数位(至少 4 位)的最近值,
取舍差留在来源余额里由末批收回。**sales/purchase/subcontract/finance/warehouse/stock/production 与 common.finance 里,
除本类外不得出现 `HALF_UP`**(`ArchitectureBoundaryTest.moneyRoundingOnlyLivesInMoneyPolicy`, 豁免清单写明理由)。

| 成员 | 用途 |
|---|---|
| `exactProduct(qty, price[, discount])` / `local(original, rate)` | 完整乘积(实际 24 位 / 账面 30 位上限校验), 折扣空或 0 = 不打折 |
| `line(qty, price, discount, rate)` | 单据行金额: 单价空 → 金额空, 汇率空 → 本币空; 无币种单据传汇率 1 |
| `cumulativeShare` / `prorate` / `prorateBatch` / `amountSlice` | 累计份额(整除取精确值, 除不尽取到来源小数位的最近值)、本批 = 累计份额 − 已分摊、末批 = 总额 − 已分摊; 按事件切片 = 累计份额差 |
| `projectedSlice` | 4 位库存价值列(IQC 放行价值、分批入库价值)专用: `ROUND(来源 × 累计量 / 来源量, 4)` 的差, 与 V446/V449 库级守卫同式 |
| `sum` | 表头合计(空行不计) |
| `quantity` / `quantityFromBase` / `quantityShare` / `quantitySlice` | 数量列 4 位存储取整, 与金额分开命名 |
| `canonical` / `canonicalRate` / `unitValue` / `percentOf` | 只补显示位数不改数值 / 汇率 6 位 / 单位价值展示投影 / 报表占比 |
| `discountFromUnitPrice(对方单价, 汇率, 标价)` → `DiscountQuote{discount, flag, unitGap}`(2026-09-27 ADR-134) | 由客户文件单价(或财务成交单价, 汇率传 1)反推折扣倍率 = 对方单价 × 汇率 ÷ 标价, 按折扣列 4 位四舍五入; 从不改写单价。`flag`: `OK` / `ROUNDED`(有取位差, `unitGap` 为单件差额) / `ABOVE_LIST`(大于 1, 折扣为空, 绝不截成 1) / `NO_LIST_PRICE`(标价空或 <= 0, 需财务定价) / `INVALID`。合理区间 (0.3, 1] 与双汇率取舍由调用方判断(`SalesPriceAuthority.deriveDiscountFromClientPrice`), 不在本方法里 |

配套: `ServerDerivedAmounts`(标记接口) + `ServerDerivedAmountsModule`(全局 Jackson 模块)——标记的保存请求 DTO
出现 `amountOriginal/amountLocal/totalOriginal/totalLocal/costAmount/exchangeDiff/taxAmount/returnAmount` 直接 400;
`ExactDecimalText`(BigDecimal 以十进制原文字符串输出, 用在财务审核类 DTO 的金额/数量字段);
`ProcurementIqcAmountSplit`(同一条待检明细的 IQC 金额口径: 事件顺序切片、冻结品质分项优先的不合格金额、
退货可退额度 = 收货金额 − 不合格金额的已实收份额——仓库放行、财务不合格、退货额度三处同一口径)。

## 三、`com.uten.imp.features.finance.accountflow.AccountFlowLedgerService`(2026-09-23, ADR-112)

资金账户余额(`accounts.balance_current` 与 `receipts_total / payments_total / balance_adjustments_total`)和对账流水
(`finance_reconciliations`)的**唯一写入口**(`AccountFlowAppendOnlyContractTest.accountBalancesAndFlowsHaveOneWriter`)。

- `lockActive(accountIds, label)`: 按主键顺序 `FOR UPDATE`, 账户与币种都须启用;
- `post(AccountPosting)` / `post(LockedAccount, AccountPosting)`: `CurrencyRule` 决定账户记哪个金额
  (`BASE_ONLY` / `BASE_OR_DOCUMENT_CURRENCY` / `ACCOUNT_CURRENCY` / `ANY`), 改余额与累计列、写一条流水, 返回流水主键;
- `reverse(sourceType, sourceId, at, reason)`: 镜像反向流水并按原始流水冲回余额。

调用方负责先锁总账期间, 再调账本锁账户。新增资金单据只声明 `AccountPosting`, 不得再自写 `UPDATE accounts`。

## 四、表头排序与值筛选公共件（2026-09-25 单号列统一）

全站「单号类」列表列的排序与按值筛选统一走三个公共件，**服务端分页列表禁止在前端本地过滤**（只筛当页=误导）：

### 1. `com.uten.imp.common.web.TableSort`（既有）
JPA `Specification`+`Pageable` 列表的列排序白名单解析：前端列 key → 实体属性名，`order` 只认 asc/desc，未命中回落调用方默认排序。单据列表新增可排序列 = 在该服务的 `ALLOWED_SORT`/resolve map 里加一行 `"billNo","billNo"`。

### 2. `com.uten.imp.common.web.TableFacets`（新）
JPA 列表的列值筛选桶：`TableFacets.groupCount(em, Entity.class, spec, "billNo"[, limit])` —— 与列表**同一份 `Specification`** 按属性分组计数，返回 `[{value,count,label}]`（value 升序，默认上限 500 桶，下拉≥6 项前端自动出搜索框）。约定：列表谓词抽成私有 `xxxSpec(f)` 供 list 与 facets 共用；facets 不吃该列自身的值筛选。

### 3. `com.uten.imp.common.web.NativeFacets`（新）
原生 SQL 服务的桶构造助手：`NativeFacets.bucket(value,count)` / `rows(List<Object[]>)` / `rowsOf(query)`，把手写 `{value,count,label}` Map 循环收成一处。配合各服务「谓词/WHERE 抽出为列表-计数-facets 共用基座 + ORDER BY 白名单 switch」的模式二（样板：`ProductionScheduleService.pending/pendingFacets`、`ProductionExecutionWorkbenchService.workshopTasks/workshopTaskFacets`）。

### 通用铁律
- ORDER BY / WHERE 只拼白名单表达式，值一律命名参数绑定；Hibernate 6 校验未出现的命名参数（条件没进 SQL 就不 bind）。
- 精确值筛选参数（billNo/orderBillNo/segmentCode 等）在分页前服务端生效；facets 端点与列表同权限注解、同过滤参数（去掉单号列自身）。
- 报表侧：服务端 `ReportSort` 本就按全部列 key 白名单排序；前端 `isSortableReportType` 已放开 text。报表值筛选走 `ReportQueryKit.FacetSpec`（key=列 key，等值绑定）。

## 五、往来单位未结余额: `PartyOpenBalancePort` + `PartyOpenBalanceQuery` + `PartyOpenBalances`(2026-09-27, ADR-128)

单据旁边显示的「客户应收 / 供应商应付」和信用额度、铺底额比较的**唯一取数与唯一口径**。审核页、放行事件不得再自写
`ar_ap_ledger` 按往来单位汇总的 SQL。

| 位置 | 作用 |
|---|---|
| `application/port/PartyOpenBalancePort.java` | 跨模块读口(ADR-017): `clients(ids)` / `suppliers(ids)`, 一次传入一页用到的全部往来单位 |
| `features/finance/arap/PartyOpenBalanceQuery.java` | 实现: AR、AP 各一份常量 SQL(方向、往来列写成字面量, 能用上部分索引), 一页一条语句按「往来单位 × 币种」汇总, 不 N+1; 只读, 随调用方事务 |
| `common/finance/PartyOpenBalances.java` | 查询结果(账面事实): 各币种原币合计、全币种正式应收(应付)账面本币毛额、原币未核实部分; `forDocument(往来单位, 单据币种, 本币额度)` 派生视图并和额度比一次 |
| `common/finance/PartyOpenBalanceView.java` | 下发给页面的视图(金额按十进制原文, ADR-112): 单据币种一档 `openOriginal / creditOriginal / netOriginal / creditBookLocal`、`otherCurrencies`(各用自己的币种, 不换算不相加)、`openBookLocal`(信用口径)、`unverifiedLocal / unverifiedCount`、`creditLimitLocal / overLimitLocal / overCredit` |

口径要点:

- 单据币种一档是 `amount_balance_original` 的精确求和, 不用任何汇率; 本位币行缺原币时按账面本币。
- `netOriginal` = 应收(应付)未结 − 可用预收(预付 / 贷项 / 索赔贷项): 正数 = 对方还欠, 负数 = 预收(预付)有余。
- 信用额度、铺底额只和 `openBookLocal` 比: 全部币种正式应收(应付)行的账面本币毛额, 不扣预收。额度传空 = 未设置, 不判超额。
- 旧系统迁入行(`LEGACY_UNVERIFIED`)与缺币种 / 缺原币的外币行只进 `unverifiedLocal`(条件复用 `LegacyOpeningBalanceSql.unverifiedOriginalCondition()`), 不并入任何币种, 也不悄悄漏掉。

当前调用方: 销售订单财务确认列表与审核详情(`SalesOrderFinanceConfirmService`, 额度 = 信用额度)、出货财审与放行事件快照
(`SalesShipmentService.financeAuditInfo`, 额度 = 铺底额)、订货审批详情(`ProcurementFinanceApprovalService.review`, 无额度)。
公司级合计(应收应付总览、应收款汇总、应付工作台 KPI)跨往来单位、跨币种, 保持本币, 不走本件。
测试: `PartyOpenBalancesTest`(派生与比较)、`PartyOpenBalanceQueryPostgresTest`(真 PostgreSQL 口径)。

## 五、客户文件读取、文本归一与第三方凭据加密(2026-09-27, ADR-133 / ADR-134)

### 1. `com.uten.imp.common.files.document`(客户文件读取地基)

只读值、不执行任何内容、所有读取都有上限, 不依赖任何业务 feature(与货品导入的检查同思路但单独实现, common 不引用 features)。
拒绝时抛 `ApiException`, 消息是给用户看的中文。任何需要读上传文件的功能都应复用, 不要再在业务模块里写解析器。

| 类 | 用途 |
| --- | --- |

| `BoundedBodyReader` | 有硬上限的请求体读取: 声明长度超限立即拒绝, 流式读取中超限也立即拒绝 |
| `ZipSafety` | xlsx 压缩包检查: 条目 <= 1024、路径、解压大小与压缩比; 拒绝宏(vbaProject.bin)、外部链接、ActiveX、OLE 嵌入、自定义 XML、数据连接; 图片与绘图允许但不读 |
| `SpreadsheetGridReader` → `DocumentGrid(sheets[Sheet(name, index, rows[Row(index0, cells[Cell(col0, text, kind, number)])], merges, ...)])` | xlsx(SAX 流式)/ xls(HSSF, 记录长度上限)读成表格: 公式只取缓存结果、从不计算; 隐藏的表/行/列与批注跳过; 合并区域只在左上角有值; 最多 8 个可见工作表、每表 5000 行、每格 8192 字; 数字为精确 `BigDecimal`, 日期转 ISO |

### 2. `com.uten.imp.common.text.IntakeTextNormalizer`

客户文件识别(`features/sales/intake`)与客户货品对照学习(`features/master/learning`)共用的文本归一, 纯函数:
`normalizePart`(NFKC → 大写 → 去全部空白(含 U+1680/U+2028/U+2029) → 全角斜杠与各种横线统一 → 去掉末尾一个句点)、
`normalizeDescription`、`normalizeCn`(去客户/国别前缀与中文序号、系列号与「NN型」)、`partVariants`(剥 `Q120-` / `F-` / `V6` / `G-` 前缀, 从不剥 `-0N` 后缀)、
`splitByScript`、`bigramDice`(中文字二元组相似度, 不用 pg_trgm)等。`normalizePart` 与 V742 种子 SQL、`idx_goods_model_norm`
与服务端查询表达式逐字等价, 由 `IntakeModelNormExpressionContractTest` 与真库 `IntakeNormalizerSqlParityPostgresTest` 锁住;
改归一规则必须同步改迁移表达式与索引(新迁移), 并跑两边的对拍测试。

### 3. `com.uten.imp.security.SecretCipher`

**只用于运行期配置的第三方凭据**(目前只有 AI 服务商密钥, `ai_providers.secret`); 员工 PII 仍走 `TxSessionVars`/pgcrypto, 在 ADR-037 的 KMS 决定前不得改用。
AES-256-GCM, 每次随机 12 字节 IV、128 位标签, 格式 `g<版本>:base64url(iv||密文+标签)`, AAD `uten|<JWT 签发者>|<调用方上下文>|v<版本>`(调用方把表/列/行 id 放进上下文)。
密钥: `UTEN_SECRET_CIPHER_KEY`(>= 32 字节, 版本 `UTEN_SECRET_CIPHER_KEY_VERSION`, 旧版本放 `uten.crypto.secret-cipher-legacy-keys`), 未配置时由
`UTEN_HMAC_KEY` 经 HKDF-SHA256 派生(版本 `h1`)。API: `encrypt(plaintext, aadContext)`、`decrypt(stored, aadContext)`(失败一律抛
`SecretUnreadableException`, 不区分原因)、`currentVersion()`、`needsRewrap(stored)`、`available()`。密钥与明文从不写日志。
设计与核查见 [ADR-133 §2](../99-决策记录-ADR/ADR-133-公共AI平台与服务商可配置.md)。

### 4. 同批的应用端口(`com.uten.imp.application.port`)

`AiCompletionPort`、`AiJobHandler`、`AiJobUsagePort`(公共 AI 平台, 用法见 [AI 平台接入指南](AI平台接入指南.md))、`BusinessDataResetGatePort`(清库排水闸)、

## 六、`com.uten.imp.security.TxSessionVars`(事务内加解密, 2026-10-06 登记)

员工 PII 的版本化 pgp 加解密与域隔离 HMAC 公共件(ADR-037 过渡路径): `encrypt/decrypt`(单个)、
`decryptAll`(批量解密, 失败时调用方再逐个 `tryDecrypt` 兜底)、`hmac`(查重/匹配派生值)、`tryDecrypt`

| 成员 | 用途 |
| --- | --- |
| `encryptAll(Collection<String>)` → `Map<明文, 密文>` | 一条参数化 SQL(`unnest` + `pgp_sym_encrypt`)批量加密一组明文(跳过 null/空白与重复), 返回 明文 → `"<keyVersion>:<base64>"`, 与单个 `encrypt` 同一格式、可被 `decrypt/decryptAll` 读回; 首个调用方是员工资料核对计划(`ReconcilePlanStore` 落一份计划的全部证件号旧值/新值/候选, 避免每个值一次往返) |

新表批量落密文应复用本方法, 不要在业务模块里循环单条 `encrypt`, 也不要自写 `pgp_sym_encrypt` SQL。

## 七、`com.uten.imp.common.util.NativeValueConverters`（原生 SQL 行映射助手，2026-10-06 扩充公共化）

**位置**：`server/src/main/java/com/uten/imp/common/util/NativeValueConverters.java`（final 工具类，私有构造）。

**来源**：JPA 原生查询 / JDBC 结果集逐列取值时，驱动与 Hibernate 版本不同会让同一列返回不同 Java 类型（DATE 可能是 `LocalDate` 或 `java.sql.Date`，TIMESTAMPTZ 可能是 `OffsetDateTime`/`Instant`/`Timestamp`，NUMERIC 聚合列可能退化为其它 `Number`），直接强转会抛 `ClassCastException`。该类原已提供日期/时间/数值转换并被 36 个文件采用；2026-10-06 批次把全仓 ~96 个文件各自 private static 重复实现里的主流语义收进本类（新增 `uuid`/`text`/`booleanValue`/`trimToNull`），并完成 features/finance 与 features/warehouse 两域的去重迁移（16 + 8 个文件）。**新代码必须用本类，不得再写 private 转换副本**。

**可用方法与 null 语义**（分歧点已在类 javadoc 标明）：

| 方法 | 语义 |
| --- | --- |
| `toLocalDate(Object)` | DATE 列 → `LocalDate`；null → null；`LocalDate`/`java.sql.Date`/`Timestamp`/`util.Date` 按各自转换；其余 toString 解析，仍失败返回 null |
| `toOffsetDateTime(Object)` | TIMESTAMPTZ → `OffsetDateTime`（Timestamp/Instant 路径归一 UTC；已是 `OffsetDateTime` 则原样返回）；null → null；解析失败返回 null |
| `toInstant(Object)` | TIMESTAMPTZ → `Instant`；null → null；`Instant`/`OffsetDateTime`/`util.Date`/`LocalDateTime`(UTC) 分支 + 解析兜底 |
| `toBigDecimal(Object)` | NUMERIC → `BigDecimal`；**null 归一为 `BigDecimal.ZERO`**；BigDecimal 原样；其它 `Number`/`CharSequence` 走 toString 解析；再不行抛 `IllegalArgumentException` |
| `uuid(Object)`（新） | UUID 列 → `UUID`；null → null；UUID 实例原样；其余 `UUID.fromString(toString())`。个别旧副本只做强转不接受字符形式——本方法是超集 |
| `text(Object)`（新） | 文本列 → `String`；null → null；其余 `toString()`。注意：个别旧副本 null 时返回 `""`，语义不同，不得混用 |
| `booleanValue(Object)`（新） | 布尔列 → boolean；`Boolean` 原样；其余（含 null）`Boolean.parseBoolean(String.valueOf(v))`，即 null/无法识别统一 false |
| `trimToNull(String)`（新） | null/空白 → null；其余去首尾空白 |
