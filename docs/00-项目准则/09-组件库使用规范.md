# 组件库使用规范

> 本规范面向当前 Flutter 源码。真实组件清单见[组件总览](../02-组件库/组件总览.md)；最后核对：2026-08-27。

---

## 一、目标

- 同类交互使用同一套视觉、状态与错误反馈。
- 响应式、主题、字体缩放、性能降级和可访问性在公共层统一处理。
- 页面保留业务编排，公共组件不直接调用模块 API 或读取模块权限。
- 抽象以真实复用为依据，避免复制粘贴，也避免没有调用方的“万能组件”。

---

## 二、放置层级

| 类型 | 目录 | 约束 |
|---|---|---|
| 纯 UI 基础能力 | `lib/components/` | 不依赖 feature、业务模型或业务 Provider |
| 跨模块业务组合 | `lib/shared/widgets/` | 可以表达稳定的跨模块业务展示，但不依赖页面 |
| 模块组件 | `lib/features/<module>/widgets/` | 可以依赖本模块模型和 Provider |
| 一次性页面组合 | 页面私有 Widget | 只有一个调用方时不强行公共化 |

项目当前没有组件 barrel。业务文件直接导入所需源码：

```dart
import 'package:uten_imp/components/buttons/uten_button.dart';
import 'package:uten_imp/components/feedback/uten_empty.dart';
```

不要引用不存在的 `components/index.dart`、`uten_components.dart` 或已删除组件。

## 三、优先复用规则

已有同类能力时必须复用：

| 场景 | 当前入口 |
|---|---|
| 普通按钮 | `UtenButton` |
| 异步提交、防连点 | `UtenActionButton` |
| 通用卡片 | `UtenCard` |
| 文本/密码输入 | `UtenInput` |
| 搜索 | `UtenSearchBar` |
| 下拉、日期、员工选择 | `UtenDropdownField` / `UtenDateField` / `UtenEmployeePicker` |
| 空、加载 | `UtenEmpty` / `UtenSkeleton` |
| 用户操作反馈 | `UtenNotify` 或 `context.appSuccess/Error/...` |
| 确认弹窗 | `UtenDialog` |
| 卡片集合 | `UtenResponsiveGrid`；服务端分页时优先 `UtenPagedGrid` |
| 列表筛选 + 表格（上下） | `UtenListTwoPane` |
| 可编辑明细 | `UtenEditableGrid` |
| 主数据/报表式表格 | `MasterDataTableView` |

员工选择统一复用 `UtenEmployeePicker` / `UtenEmployeeMultiPicker` 或
`showUtenDepartmentEmployeePicker`：候选主行、确认栏和已选值均显示 `姓名(工号)`，
部门放在下一行；调用方必须传真实 `employeeCode`，历史接口确实没有工号时才回退为姓名。

必填选择字段统一复用 `requiredLabel` + `applyRequiredEmpty` 或组件的 `required: true`：
空值时显示红色 `*` 和错误色边框，提交后显示字段就地错误；不能只用颜色表达必填。

字段说明、校验错误和自动带出提醒统一收进框内图标（2026-09-07 用户口径）：
公共输入组件传 `info:`；裸 `TextField` / `InputDecorator` 用
`UtenInputDecoration(InputDecoration(...), info: ...)`。图标支持悬停、点击与键盘打开，
标签保持短句，复杂条件与操作后果放进图标。**表格列的说明位置（2026-09-10 口径）**：列级通用说明（数量/单价/币种/税率/结账等对所有行相同的口径）放 `EditableGridColumn.headerInfo` / `MasterColumnDef.info` 的列头 ⓘ（共用 `UtenColumnHeaderInfo`，悬停/点按/键盘，吞长按不与列排序打架）；只有**行特有**的说明（学习预填来源、本行上限、必填空）才留在格内 `info`/`autofilled`/红框；列头 ⓘ 不能替代行特有提示，格内 ⓘ 也不再承载通用说明。凡单元可能出现预填黄标图标的列，`chromeWidth` 须计入 `UtenEditableGridCellSpec.hintIconWidth`（44），默认列宽也要装下常见值。
错误仍保留红框、无障碍反馈和原提交校验；自动带出值通过 `applyAutofillHint` 保留黄框、
淡黄底和来源图标，不再占用框下空间。不要把必填说明误写成自动带出状态，已保存快照
也不是学习值。只在用户修改文本内容或重新选择时清除黄标，移动光标和聚焦不算修改。
同一字段避免嵌套多个 `UtenInputDecoration`；先包装说明，再应用必填和自动带出状态。

Material 原语并非一律禁止。以下情况可以直接使用：

- 公共库尚无对应能力，例如 `Switch`、`Checkbox`、`Slider`；
- 页面私有、没有稳定复用价值的 `Row`、`Column`、`Padding`、`SizedBox`；
- 公共组件内部实现。

即使直接使用 Material，也必须走主题、token、权限和状态约束；不得复制一套已有 Uten 组件。

## 四、正确 API 示例

### 4.1 普通按钮

```dart
UtenButton(
  type: UtenButtonType.primary,
  size: UtenButtonSize.medium,
  isLoading: saving,
  isExpanded: true,
  icon: Icons.save_outlined,
  onPressed: saving ? null : save,
  child: const Text('保存'),
);
```

`UtenButton` 的参数名是 `type`、`isLoading`、`isExpanded`；不要使用旧文档中的 `variant`、`loading`。

### 4.2 异步动作按钮

```dart
UtenActionButton(
  type: UtenActionButtonType.primary,
  label: const Text('提交'),
  loadingLabel: const Text('提交中'),
  onAction: () async {
    await repository.submit();
    if (context.mounted) context.appSuccess('提交成功');
  },
);
```

异步回调由组件锁定状态。同步抛错也必须恢复按钮；错误展示应走统一反馈入口。

### 4.3 卡片网格

```dart
UtenResponsiveGrid(
  itemCount: items.length,
  itemBuilder: (context, index, itemWidth) {
    return UtenCard(child: ItemSummary(item: items[index]));
  },
);
```

`itemWidth` 表示当前格宽，卡片可据此适配。`UtenResponsiveGrid` 默认按父容器宽度形成 1～6 列，不要再按屏幕宽度重复算列数。

长列表不能把全部历史一次加载到前端：后端使用稳定排序的服务端分页，前端使用 `UtenPagedGrid`、分页表格或等价的分页状态；分页从 1 开始，页大小必须有上限。

### 4.4 空状态

```dart
UtenEmpty(
  icon: Icons.inbox_outlined,
  title: '暂无数据',
  action: UtenButton(
    onPressed: reload,
    child: const Text('重试'),
  ),
);
```

## 五、表格、列表与分页

不要用一个组件强行覆盖所有数据形态：

- 卡片摘要：`UtenResponsiveGrid`。
- 服务端分页卡片：`UtenPagedGrid`。
- 主数据、报表式行列展示：`MasterDataTableView`。
- 单据编辑明细：`UtenEditableGrid`。
- 简短设置项、菜单、时间记录：Material 列表或模块私有组件均可。

两个表格组件的列宽契约(2026-08-27 起)：都可拖表头列右边界竖线调宽窄(下限 48 防拖没)，**用户手动拖过的列锁定用户宽度**，数据/内容变化不再覆盖它；`MasterDataTableView` 默认按列内容自动适配(封顶 480，详见其组件文档)；`UtenEditableGrid` 列默认取列定义 `width`，列定义提供 `textOf`(可选再加 `listenableOf`)后**随内容自动加宽**——输入/换值变长时列跟着变长，只增不减、封顶 480(超出后单元内横向滚动)，初始行与整批换行时整体量宽兜底。数值/日期等短内容列与 `maxLines: 2` 换行列不接 `textOf`，保持固定宽/换行语义。2026-09-04 起，业务页可显式开启 `UtenEditableGrid.showColumnSettings`；**2026-09-05 起两个表格组件的表头体系收敛为同一份实现 `UtenTableColumnKit`**（见 [UtenTableColumnKit.md](../02-组件库/UtenTableColumnKit.md)：「表头设置 x/y」深绿实心大按钮 → 按钮处锚定的浮层勾选列表——全选行/勾选显隐/(编辑表)拖拽排序与恢复默认；表头纵向拖出隐藏 = root Overlay 最顶层跟手浮层——原格变淡、过阈值红底红×、拖回取消；**表头横拖 = 直接换位（2026-09-11 起按下即拖，不再需要长按）**——跟手浮层+插入位指示线+松手落位，与弹窗排序同一份顺序状态；方向消歧交给竞技场（横拖换位 / 竖拖移除），代价是表头本身不再能横拖滚动表格，表体横拖与底部横滚条仍在）。**必填列（`required: true`）锁定不可隐藏**（弹层勾选禁用、拖出无效；排序不受限），非必填列仍受「至少保留一列」兜底；列定义可带 `headerInfo` 在表头渲染 ⓘ 信息图标（悬停/长按弹说明，如销售折扣列「1 = 保持原价；0.9 = 9折」）。至少保留一列，隐藏列不销毁控制器或提交数据。嵌入式/任务表默认关闭，避免无授权的布局变化。任务表必须让 `canSelectRow` 同时约束复选和右键动作资格；保存/提交期间传 `selectionEnabled:false`，统一冻结选择、批量动作与行菜单。编辑模式（`showAddRow`）操作条只保留「表头设置」与宿主批量动作——全选走表头复选框、复制/粘贴/批量删除走行级右键/长按菜单（2026-09-05 与货品资料统一，任务/只选模式不变）；**纯勾选模式（`selectable` 且非编辑）点行身非输入区 = 切换选中**（与 `MasterDataTableView`「单击行选中」契约统一；输入/按钮格自己消费点按，不会误触）。

十几年数据量场景必须服务端筛选、排序、分页；前端本地排序只允许用于明确受限的小结果集。排序应包含唯一键作为最后一项，防止翻页重复或漏项。

## 六、主题、响应式与可访问性

公共组件和页面都必须：

1. 颜色走 `Theme.of(context).colorScheme` 或 `UtenColors` 语义 token。
2. 文字走 `textTheme`，并允许全局 `textScaler` 生效。
3. 间距、圆角、阴影和动画使用 `UtenSpacing`、`UtenRadius`、`UtenElevation`、`UtenAnim`。
4. 用 `LayoutBuilder` 依据实际父容器宽度适配，不只看屏幕宽度。
5. 点击目标、焦点、tooltip/semantics、键盘操作和对比度满足可访问性要求。
6. loading、disabled、empty、error、hover、focus 和 pressed 状态完整。
7. 在低性能档关闭非必要模糊和重动画。
8. 所有用户可见括号使用 ASCII 半角 `()`，禁止新增 U+FF08/U+FF09。

## 七、状态、权限与安全边界

- 组件内部瞬时 UI 状态可以用 `StatefulWidget`；跨组件业务状态和请求状态使用 Riverpod。
- 页面控制“是否展示/是否可编辑”只是用户体验，后端仍必须独立鉴权和校验数据范围。
- 未拿到权限或权限加载失败时 fail closed：隐藏或禁用高风险动作。
- 不把 token、密钥、完整隐私数据写入 Widget、路由参数、日志或错误提示。
- 导出、下载、支付、审批、删除等动作必须防连点；后端同时保证事务、幂等和审计。

## 八、新增组件流程

1. `rg` 搜索现有能力和重复调用点。
2. 确定基础、共享业务或模块私有层级。
3. 设计最小 API，写明状态、响应式、主题和错误行为。
4. 实现并增加必要的 widget 测试。
5. 更新[组件总览](../02-组件库/组件总览.md)和相关页面文档。
6. 运行 `dart format`、`flutter analyze` 与相关测试。

没有硬性“必须先建空文档”或“必须更新 barrel”的流程；文档必须和真实 API 同步，测试必须覆盖高风险交互。

---

## 九、禁止事项

- 禁止引用 `UtenStatCard`、`UtenAnimatedNumber`、`UtenListItem`、`UtenSelect` 等已删除名称。
- 禁止复制公共组件到业务页面再局部修改。
- 禁止在业务文件新增裸 `Color(0x...)` 或复制阴影/圆角色板。
- 禁止用前端隐藏代替后端权限校验。
- 禁止大结果集全量拉取后在客户端分页、筛选或排序。
- 禁止异步按钮在异常后永久 busy，或允许重复提交高风险动作。
- 禁止公共组件直接发业务 API 请求。
- 禁止提交调试 `print`、样例数据和无调用的占位组件。

---

## 十、提交前检查

- [ ] 新 UI 已复用现有组件，或有明确理由留在模块/页面私有层。
- [ ] 没有引用不存在、已删除或仅在规划中的组件。
- [ ] 权限失败时 fail closed，后端仍有相同权限与数据范围校验。
- [ ] loading/disabled/error/empty 和同步异常路径完整。
- [ ] 长列表使用服务端分页与稳定排序。
- [ ] 浅色、深色、窄屏、桌面和字体放大已检查。
- [ ] 无新增业务裸色、重复 UI、调试输出或敏感数据泄露。
- [ ] 员工选择主行/已选值为 `姓名(工号)`，部门位于副行。
- [ ] 新增或修改文案只使用 ASCII 半角 `()`。
- [ ] `flutter analyze` 和相关测试通过，文档已同步。
