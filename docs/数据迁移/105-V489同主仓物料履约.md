# V489 同主仓物料履约

迁移：`V489__same_main_warehouse_material_fulfillment.sql`。本轮为本地源码候选，
未连接或修改已有业务数据库，未部署。V476/V474/V337 等已应用迁移保持原字节。

原实现将分析的实际参考叶仓、供应行动仓和收货仓 UUID 必须相等误当成“同主仓”。
同一个主仓下的塑料仓和五金仓因此会被当成跨仓，合格入库丢失原分析预定归属。

新增 `fn_warehouse_main_id` 和 `fn_warehouse_same_main` 按 UUID 父链识别主仓；
独立仓以自身为主仓，丢失/循环父链不把不同仓合并。exact mismatch view 改为主仓边界。
PREPLAN 正式需求和源权益允许同主仓，目标物理预留与来源权益的实际叶仓继续严格相等。
`fn_analysis_plan_material_matches` 保留原根物料链，并允许 MAKE_COMPONENT /
SUBCONTRACT_MAKE 锚点沿父物料定位原树直接组件；不把其它产品的同名物料视为来源。
守卫通过核验当前已安装函数定义后定向替换，找不到原比较式立即失败。
`production_material_stock_postings` 新增物理仓守卫，逐条领料/取消出库/退料事件的
库存单实际仓必须等于所消费或恢复的预留实际仓。同一需求分两个子仓领料时不能串用预留。
执行事件枚举新增 `RECHECK_MATERIAL`，供已收到的 WAITING 车间任务显式重查物料；
重查仍经过真实齐套与创建领料单的原子事务，不直接伪造开工状态。

不新增事实表，不回填或改写历史单据/库存/权益。成功收货仓默认直接读取货品/颜色在
本主仓范围内最近一次已审核且未红冲收货事实；每行独立，采购/委外共享历史。
已有 V431/V451 仍只记忆子仓内库位；子仓选择不混入库位偏好表。
仓库选择只有成功保存的业务单据及其原有行级审计才是历史，未提交选择不形成记录。

验证包括同主仓兄弟叶仓、独立仓隔离、异常父链、单位换算后数量守恒、每物料默认仓传递、
原登记拆单/幂等重试回归，以及隔离 PostgreSQL 的 V488→V489 升级和物理来源守卫保留。
FullChain 新增真实部分到货的同主仓精确绑定与跨主仓公共库存、先下达锚点后兄弟仓到货
自动解除 WAITING、同一物料分仓领料及幂等取消出库，并尝试串仓记账验证数据库拒绝。
实际执行结果由本轮汇总报告记录，不把测试定义视为通过证据。

回退应使用测试过的数据库恢复或新的前向迁移，禁止改旧迁移、Flyway repair 或
在新数据库约束上直接换回旧 JAR。历史错仓入库需独立核对原单、实物和权益后受控处理。
