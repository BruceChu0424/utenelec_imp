## 为什么要有它

「自动退出登录」只在浏览器计时，登出不作废 access token，refresh 滑动续期没有上限；二次密码确认是一个无限次可试、不和任何操作绑定的「对/错」接口；设置项的定义在迁移、服务、调用方和前端四处各写一份。三件事的共同根子是**权威状态不在服务端的一个地方**，本组迁移给它们各落一个服务端的家。

## 改了什么

### V658 服务端会话 + 再认证

| 对象 | 变化 |
| --- | --- |
| `auth_sessions` | 新表。每次登录(员工或访客二选一，`num_nonnulls(user_id, visitor_id) = 1`)一行：`created_at` / `last_seen_at` / `absolute_expires_at` / `revoked_at` + `revoked_reason`(枚举 9 种，含改登录手机号 `login_account_changed`) / `step_up_token_hash` + `step_up_expires_at`(成对)。两条部分索引按「未吊销」查员工/访客会话。 |
| `auth_step_up_states` | 新表。按员工账号累计再认证(含改密旧密码、进入切换人)的连续失败次数与暂停截止。 |
| `refresh_tokens` / `visitor_refresh_tokens` | 存量未吊销的一律置 `revoked_at = now()`：旧令牌没有会话行，发版后所有人重新登录一次。 |
| `business_data_reset()` | 锚点补丁(读已安装定义，锚点 `('stock_movements', 'CLEAR')` 恰好一处，否则失败关闭)：两张新表登记为 CLEAR。 |

两张表都是凭证/会话机制数据，与 `refresh_tokens` 同口径不挂行级审计(`AuditTriggerCoverageMigrationContractTest` 技术表白名单逐条写明原因)；登录、登出、再认证成功/失败、会话吊销另有显式安全事件。

### V659 系统设置单一登记

| 对象 | 变化 |
| --- | --- |
| `system_settings` | 删除 `value_type/category/label/description/unit/sort_order` 六列：这些改由 Java 枚举 `SystemSettingKey` 登记，表里只存当前值与最后修改人/时间。 |
| 新登记行 | `impersonation_window_minutes=15`、`password_min_length=8`、`temp_password_ttl_hours=72`、`delivery_due_warning_days=3`、`reservation_hold_grace_days=7`、`subcontract_return_due_days=3`、`badge_poll_seconds=60`(`ON CONFLICT DO NOTHING`)。 |
| 越界值收口 | `jwt_access_ttl_minutes` 收进 5–1440，`jwt_refresh_ttl_days` 收进 1–30，越界按最近边界落库。 |

`SystemSettingRegistryContractTest` 在全新迁移库上断言：表的行集合 = 枚举登记集合，每行种子值 = 登记默认值，且值都在登记范围内。

### V660 账号支持个人点名 + 存量临时密码过期 + 临时凭据约束 + 高危标记

| 对象 | 变化 |
| --- | --- |
| `department_permissions` / `manager_permission_delegations` | 删除 `account:support` 的全部部门级授予(原为行政与人力资源部)与负责人委派(V655 起已不可委派，正常为空，显式清一次)。 |
| `permissions` | `account:support` 的授权策略 `grant_policy` 改为 `{INDIVIDUAL_ONLY}`(ADR-109 权限目录单一事实源；合并权限工作流后不再用已被 V655 删除的 `assignable` 列)：不进部门矩阵、不可委派、不随批量，只能由超管在个人授权里点名配置；说明改为「只能个人点名授权」。部门级写入由 V655 的通用守卫 `fn_guard_permission_grant_policy` 拒绝(文案「该权限只能逐人授予，不能配置给整个部门」)，不再单独维护按码写死的守卫函数；迁移末尾断言策略已落库，失败关闭。 |
| `users` | 「必须改密但没有过期时间」的非超管账号 `temp_password_expires_at = now()`：过去由身份证后 6 位推导的初始密码立即失效，需重新发放随机临时密码。超管除外(引导管理员的初始密码来自部署密钥)。随后加 `BEFORE INSERT OR UPDATE` 触发器 `trg_users_temp_password_expiry`(函数 `fn_users_temp_password_expiry`)：必须改密的非超管账号没有过期时间时一律按已过期(`now()`)落库，离职冻结、交接加固、复职、超管降级等任何写路径都不能再造出永不过期的临时凭据(代码里离职/复职也显式把旧密码置为已过期)。不用 CHECK：该列默认值是 TRUE，大量只为占位建号的原生 INSERT 不写这两列，CHECK 会全部报错。 |
| `permissions` | 新列 `high_risk BOOLEAN NOT NULL DEFAULT FALSE`：持有者的登录凭据(重置临时密码、补开账号)只能由超管发放。本迁移置 TRUE：V212 高危清单(审计查看/导出、授权管理、用户管理、流程指派、库存余额调整、固定资产审批/过账/处置/导出/期间)、账号支持、账户余额调整、报销审批与付款、工资生成/审核/发布/查看全员工资，以及财税模块全部 `APPROVE`/`EXECUTE` 类权限。 |

## 应用侧(同批，非本迁移)

- `JwtAuthFilter` 在查账号状态的同一条 SQL 里连带查会话与空闲阈值；客户端声明为自动请求(`X-Uten-Automatic: 1`，用户 30 秒内没有输入时发出的请求)不续期。
- `POST /auth/step-up` 签发会话绑定的一次性凭证；`@RequiresStepUp` + `StepUpInterceptor`(方法拦截器，排在权限判定与参数校验之后)拦截敏感写接口(含补开账号)，缺凭证回 403 `REAUTH_REQUIRED`；删除 `/auth/verify-password`。
- 重置密码与补开账号按 `permissions.high_risk` 判定目标是否高危(`CredentialIssuancePolicy`)，高危只有超管能发放。
- 删除系统设置单项 PUT 与庆典设置 PUT，只留批量 PUT；公共设置接口新增 `passwordMinLength`、`attachmentMaxBytes`、`badgePollSeconds`。
- 前端：统一再认证弹窗 + 网络层自动重发；系统设置页、重置密码、进入切换人、个人资料提交都不再自带密码框。

## 兼容与影响

- 平台未上线，不做存量兼容：发版后所有人重新登录一次；未完成首登改密的非超管账号需要管理员重新发放临时密码。
- CLEAR 目录新增两张表(`reset_business_data.sql` 表分类清单同步登记)：清空业务数据后全员重新登录本就是既有行为，`BusinessDataResetServicePostgresTest` 清空表数 298→300。
- 系统设置读取只能按枚举：新增设置项必须同时改枚举和补一条迁移数据行，否则契约测试红。
