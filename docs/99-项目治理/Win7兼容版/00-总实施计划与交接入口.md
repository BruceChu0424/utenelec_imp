# Win7 原生兼容版：总实施计划与交接入口

本文件是本次迁移的接手起点。目标是把现有 UTEN 的全部适用业务迁到 C# / WPF / .NET Framework 4.8，保持现有 UI、圆角、权限和业务流程，共用现有后端；同时完成 Win7 SP1 x86/x64 的安装、原生更新、打包、Windows 下载和验收。**登录窗口或只读页面完成，不等于兼容版完成。**

截至本计划建立时，WPF 只具备原生基础、工作台/货品部分读取和正在集成的下载更新能力；完整业务闭环尚未验收。历史测试、已有代码、当前编译、Win7 真机及正式交付是不同状态，进度不得混算。

## 3. 完整范围与计数口径

## 6. 每个业务工作包的完成定义

每项至少核对：现有 Flutter 页面/公共组件及 owning 后端；所有可见动作/状态/来源；真实 DTO、权限/范围、版本和幂等键；数字/币种/单位/归属不丢失；UI、圆角、字体、布局、键盘与缩放；正常、空值、拒绝、并发、取消、断网、重启与未知提交；附件/批量/导出/打印/历史等适用动作；当前源码合同测试、x86/x64 及其目标机证据；对现有 Win10 的影响与回归。

若原页面已退役或仅为别名，要记录实际 redirect/调用证据及替代入口，不能复制一个无业务页面再算一次完成。若一个页面只实现读取，工作包状态必须保持部分实施，写操作、业务闭环和目标机验收不能自动勾选。

## 7. 换人接手的执行顺序

1. 阅读本文件、当前接手记录、工作包清单与最近变更；核对分支、HEAD 和 dirty 状态，保留并行改动。
2. 检查 source inventory、token 和依赖锁的离线 drift；确认不存在“之前报告通过但当前源码已变化”的误标。
3. 从 `04` 指定的最前未完成依赖继续，不重新猜方案，也不从“代码存在”推导功能完成。
4. 只在本独立工作区实施；复用公共入口，按业务矩阵做当前工作包，记录保留的平台差异和替换/清理清单。
5. 达到 DoD 后登记证据并更新状态/变更记录，重新生成进度摘要与复选框。未完成则写清还差什么、失败命令及下一步。
6. 定期提交可构建且可审查的阶段快照，保留准确 commit。**任务完成后也不合主链，不自动上传或部署。**

## 8. 环境与发布边界

现有本机 MSBuild、.NET Framework 4.8 引用程序集和共享 Flutter SDK 可以只读/按项目使用；不得通过降级它们兼容旧系统。新 C# 依赖只放私有 `build/windows-wpf/dependencies`，锁定版本与摘要，不修改全局包缓存或系统信任。正式配置不得混入 localhost/Debug/Profile/LocalTest。

候选 ZIP、源码校验、版本资源与包 inspector 不代表完整 ERP 或 Win7 现场验收。正式发布以平台+运行时+架构分组的 Setup/ZIP 及验收回执为准。现役 flat catalog 一旦含 WPF 记录，未识别运行时的旧 JAR 不得继续执行客户端发布/清理；这一真实回滚边界必须进入部署验收，不能用文档中“已支持新字段”推定现场安全。

需要外部条件的部分单独记录：可用 Win7 SP1 x86/x64 测试机、隔离业务测试身份/数据、真实打印机及正式代码签名/发布条件。缺条件时记录未验收并继续其余可独立工作，不伪造完成，不把该项目缩成登录演示。
