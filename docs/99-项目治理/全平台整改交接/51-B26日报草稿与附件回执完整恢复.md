# B26 日报草稿与附件回执完整恢复

本批收尾已确定的日报创建、草稿保前像及附件晚到回执问题，并带入同树验证的Jackson补丁。既有15父项不因小批数量增加而自动完成；本批后产品26，父项仍4/15。其它22模块字段/历史页面、旧parent权限读侧、资源压力和未验证行级仓候选继续按实际进度保留。

日报先冻结实际API请求体及原actor/server/key/nativeV3/fullV1双证明。首次CREATE收到2xx后也必须用原体只读核对create-receipt，双hash/version/key及双方单据id相符才CAS采用正式id和继续附件；UNKNOWN、LEGACY、回执查询错误不自动再POST。后端原先只核nativeV3，真实2个反例（改成后来的当前cells、完全省略原扩展字段）均错误200；现有完整proof时同时核version1和原完整体hash，不从当前字段猜证明。两proof列都NULL的旧合法nativeV3合同保留，当前权限与原桥接合同保持。

本机普通写入经同一CAS在成功前保存前像，失败CAS不制造历史。Native按scope锁/WAL与不可变payload/索引管理，Web同一IndexedDB事务；完成、删除及历史只读对象不能重新成为活动草稿。历史列表使用有界元数据游标，原内容在当前权限下按需读取，公共provider隐藏原协议body。只读恢复允许原请求查询和狭窄确认元数据，不能随意编辑或伪装用户。通用ACTIVE草稿price/PII仍受各编辑器恢复接口约束，不将此批说成所有模块敏感字段/窄屏问题都完成。

附件在presign之后、bytes之前CAS保存每文件稳定localId和原actor/server/父证明/storageKey/fileHash；已有attempt或legacy不明不能盲目重传。确认ACK丢失或重启后只调用原scope的native history GET，按唯一key、父单、上传人和真实服务端sha256正向核对；缺失/NULL/不匹配仍UNKNOWN。文件名/类型后续变化不猜身份；已删除原件只确认历史，不继续上传。DTO只加可空sha256，旧20/12参数构造兼容且不伪造legacy摘要，读权限/历史范围/下载门禁不放宽。回执不能覆盖另一页面已改变的原文件，已采用父单也不能绕过未完成附件的退出保护。
