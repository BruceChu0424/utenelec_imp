## 车间、产线、设备对照

4 个车间的旧 ID 与现有部门对应：

| 老 ID / 名称 | 新系统部门 |
|---|---|
| 37 安装车间 | `WS_ZHUANG` 装配第一车间 |
| 38 注塑车间 | `WS_ZHUSU` 注塑车间 |

20 条安装线为“安装1线”至“安装20线”。旧 ID 40–58 覆盖其中 19 条，**ID 59 才是安装13线**，不能直接用 `ID-39` 推断线号。现有数据库没有独立产线主档，不能为了导入而把它们做成部门。保留逐行旧 ID、名称及 `WS_ZHUANG` 归属对照。

10 个注塑机台为 ID 60–69 的“注塑1号机”至“注塑10号机”。本轮已准备 `migrate_legacy_injection_machines.sql`，从 `legacy_injection_machines.csv` 导入现有 `workshop_machines`，部门为注塑车间。编号遵循当前 `WorkshopMachineService.createBatch` 的空前缀加整数规则，重新从 `1` 到 `10`；名称保留来源，停用并标记待现场核验，创建人为保留的超级管理员。SQL 不创建新账号。

老表没有型号、吨位、容器及容量，不编造这些字段，不创建虚构容器。CSV 为管道分隔，满足整体静态 `\copy` 组合约束。仓库 `B_Storage.WorkID` 的关系需经现有仓库与车间 UUID 对照规则映射，不能把机台或产线旧 ID 直接当部门 ID。

本轮全部 196 张表的精确计数与逐表分组见 [20261022-来源全表精确计数与处置](20261022-来源全表精确计数与处置.md)。最初 8 张未知非空表均已完成上述溯源并给出处置，未来新表仍会保持“未知待核验”闸口。

## 可重复复核语句

以下均为来源库只读查询；工资表只查日期、行数、引用覆盖，不输出金额或员工姓名。

```sql
SELECT COUNT(*) FROM W_Formula;
SELECT COUNT(*) FROM W_Project;
SELECT COUNT(*) FROM W_PATWork;
SELECT COUNT(*) FROM W_Laborage;
SELECT COUNT(*) FROM B_WorkShop;
SELECT COUNT(*) FROM SystemPart;
SELECT COUNT(*) FROM ProductMore;
SELECT COUNT(*) FROM StockLabel;
SELECT COUNT(*) FROM StockSLabel;
SELECT COUNT(*) FROM dbom;

SELECT COUNT(*) AS row_count,
       SUM(CASE WHEN w.ID IS NOT NULL THEN 1 ELSE 0 END) AS employee_reference_found,
       SUM(CASE WHEN g.ID IS NOT NULL THEN 1 ELSE 0 END) AS goods_reference_found
FROM W_PATWork p
LEFT JOIN B_Worker w ON w.ID=p.EmpID
LEFT JOIN B_Goods g ON g.ID=p.GoodsID;

SELECT o.name,m.definition
FROM sys.sql_modules m JOIN sys.objects o ON o.object_id=m.object_id
WHERE o.name IN ('View_ProductMore','View_StockLabel','View_StockSLabel');
```

处置清单必须区分“导入当前业务”“按来源业务重算”“历史或配置归档”“来源为空”。保留完整旧备份和原始归档可保证来源不丢失，但不等于所有历史表已被当前业务页面直接使用。
