# 销售报价财务核价页(核价队列 + 核价详情)

> **2026-09-27 新增(ADR-134, V742)**：报价不再由销售自审。销售「提交财务核价」后报价进入本页，财务逐行定成交单价/折扣(没有标价的货品由财务直接定价)，确认后销售才能「转订货单」；订货单沿用报价核定的单价与折扣且锁定不可改——落实用户口径「价格销售没有权限改；报价单财务会不断地修改，确定后才会到订货那里；订货单一定是最终的」。
>
> **页面状态**：🟡 前端源码候选(fl-quote)，服务端契约见 SPEC §6.2；目标库迁移、真实岗位(销售/财务两个账号)UAT 未完成前生产 NO-GO。
> **入口**：钱流管理 hub「任务中心」分组「报价核价」卡(红徽章 = 待核价张数，徽章入口 `financeQuoteReview`)；报价被销售提交后财务收到通知直达详情；销售报价详情对持核价查看权的人显示「去核价」。
> **路由**：队列 `/finance/quote-review`(`?state=pending|confirmed|returned` 深链分段)；核价详情 `/finance/quote-review/:id`。
> **实现**：[FinanceQuoteReviewListPage](../../lib/features/finance/pages/finance_quote_review_list_page.dart)、[FinanceQuoteReviewPage](../../lib/features/finance/pages/finance_quote_review_page.dart)；模型 [sales_quote_finance_review.dart](../../lib/features/finance/models/sales_quote_finance_review.dart)、行编辑 [quote_finance_line_draft.dart](../../lib/features/finance/models/quote_finance_line_draft.dart)、换算 [quote_finance_pricing.dart](../../lib/features/finance/models/quote_finance_pricing.dart)；仓库 [sales_quote_finance_review_repository.dart](../../lib/features/finance/repositories/sales_quote_finance_review_repository.dart)。

## 一、定位

- 财务的「报价定价工作台」，不是审批放行：财务在这里**改**价格和折扣，确认后报价才算定稿。
- 「销售不能改价」的落地：报价行单价只来自货品资料标价(MASTER)；只有财务能直接定成交单价(FINANCE，含赠品/0价)；销售提交时只能提出折扣，财务确认后才生效；转订货单后单价与折扣锁定。
- 订单财务确认(V294)仍保留——它放行的是信用、条款与排产；报价转入且与报价一致的订单在订单财务审核页显示「报价已核价 · 一致」，财务只需核对信用与条款(可批量确认)。

## 二、状态机与动作

报价状态：`0` 草稿(带退回原因时即「财务退回」) / `2` 待财务核价 / `1` 已核价 / `-1` 作废。分桶键与分段计数同一套：`DRAFT / FINANCE_REJECTED / PENDING_FINANCE / APPROVED / REVERSED`。

| 从 | 动作 | 谁(销售端 `allowedActions` / 财务端 `financeActions`) | 到 | 说明 |
|---|---|---|---|---|
| 0 | 提交财务核价 `submit` | 报价负责人 | 2 | 带 `expectedRevision`；通知全部有资格的财务核价人 |
| 2 | 撤回 `withdraw` | 报价负责人，且财务没有认领 | 0 | 回草稿继续改 |
| 2 | 保存修改 `edit` | 有资格的财务 + 本人有效认领 | 2 | 逐行折扣/成交单价/赠品/按最新标价刷新；表头有效期/结账方式/财务备注；版本 +1 |
| 2 | 退回销售 `return` | 同上 | 0 | 原因必填(快捷选项 + 自由填写)，通知销售 |
| 2 | 确认报价 `confirm` | 同上 | 1 | 有未定价行时被挡；通知销售「可以转订货单了」 |
| 1 | 撤销确认再修改 `reopen`(财务端) | 有资格的财务，未转订货单；**不认领** | 2 | 回到待核价；页面随即重载并认领后继续改 |
| 1 | 重新修改 `reopen` | 报价负责人，未转订货单 | 0 | 回草稿，改完须重新提交 |
| 1 | 转订货单 `convert` | `sales_quote:convert` + `sales_order:create` | 订货草稿 | 单价与核定折扣锁定带入 |
| 1 | 作废 `reverse` | `sales_quote:reverse` | -1 | 不可恢复 |

财务资格 = 财务部门树在职 + `sales_quote_finance:confirm`(复用订单财务确认的资格判定)。所有财务动作与撤回/重新修改都带 `expectedRevision`；改价、退回、确认另带 `expectedClaimId`。撤销确认(SPEC §6.2「eligible reviewer, not converted」)不认领——服务端认领只接受待核价(status 2)的报价，已核价的报价认领会被 409 拒绝。

## 三、核价队列(`/finance/quote-review`)

- **三个分段**(统一筛选工具条)：
  - 待核价 —— 等财务动手 → **红徽章**(读徽章入口 `financeQuoteReview`，与 hub 卡同源)；
  - 已核价 —— 已结束 → 不挂数；
  - 已退回 —— 球在销售手上、改好还会回来 → **黄色进行中**(页内分段，不进徽章入口，ADR-100)。
- 服务端搜索(单号/客户/业务员)与分页；桌面端统一表格(单击选中、双击或工具条「核价」打开，右键菜单也可打开)，紧凑端卡片列表 + 显式「核价」按钮。
- 列：报价单号 / 客户 / 业务员 / 提交时间 / 明细行 / 报价金额(本币，服务端原文) / 状态·说明。待核价行的说明：「待核价 · 有 N 行没有标价」「销售改后重新提交」(浅黄底提醒)，有人正在核价时再加「张三 正在核价」/「你正在核价」；已核价行：「已核价 · 核价人」或「已转订货单 XD…」；已退回行：「已退回: 原因」。
- 从详情办结(确认/退回)返回时带 `true`，队列立即重拉并刷新徽章；详情页也 bump `finance:quote-review` 刷新信号。

## 四、核价详情(`/finance/quote-review/:id`)

### 4.1 认领

- 先读详情；服务端 `financeActions` 里有改价/退回/确认才认领 `SALES_QUOTE_FINANCE_REVIEW`，认领成功后**再读一次**，页面展示的是占用生效后的内容。只有「撤销确认」(已核价)时不认领，也不显示认领失败提示；撤销成功后整页重载，报价回到待核价，按上面的规则认领。
- 认领失败/被他人占用：顶部红卡「重新认领并刷新」，页面只读，悬浮按钮置灰并说明原因。
- 心跳每 30 秒续租；失效立即暂停；每个动作提交前再续租核对同一 claimId。离开页面、办结后释放；登录身份变化立即作废本页状态。

### 4.2 页面结构

1. **状态条**：单号 + 待财务核价 / 已核价(核价人·时间) / 已退回销售(原因) / 已转订货单，右侧「第 N 版」。
2. **提醒**：无动作时「只能查看」；再次提交时黄色提醒「标黄的行折扣和你上次确认的不同」；有未定价行时红色提醒 + 「去货品资料维护标价」(只在服务端能力位 `canMaintainGoodsPrice` 为真时出现，不在页面拼权限；窄屏时这个动作放在提醒下方，不把提醒文字挤成一条窄列)。从货品资料页返回后页面**重读**本报价：没改的行按最新内容重建，改过的行与表头保留页面上的修改(版本变了才整页重建)，最新标价随即可用「按最新标价刷新」。
3. **报价信息卡**：客户(编号)、业务员、制单员、单据日期、提交时间、交货日、合同号、币种、客户文件币种(「文件币种 USD, 按财务参考汇率 7.1 折算成本币」；外币没有参考汇率时说明「折合本币先空着」)、销售备注；可改：有效期、结账方式、财务备注(写给销售看)。
4. **客户文件和附件**：销售随报价上传的报价单/形式发票，只读预览(服务端按财务读范围放行)。
5. **核价记录**：提交 / 撤回 / 财务修改 / 退回 / 确认 / 重新修改 / 撤销确认，快递式时间线，最新在上，退回标红。
6. **货品明细**(统一表格，勾选列 = 批量设折扣)：

| 列 | 说明 |
|---|---|
| 货品名称 / 编号 / 颜色 / 数量 / 单位 | 快照优先；名称用全站货品身份格(正文色)，编号/颜色/单位用货品属性格 |
| 标价 | 按标价打折的行 = 提交时冻结的货品标价；财务定价/还没单价的行 = 货品资料当前标价；空或 0 显示红底「未定价」；货品资料已改价时显示「100, 资料已改为 120」 |
| 文件单价(原币) / 折合本币 | 客户文件里的单价与按财务参考汇率折合的本币价(有文件信息时才出现) |
| **成交单价**(可改) | 客户最终每件付多少；改它自动反推折扣 |
| **折扣**(可改) | = 成交单价 ÷ 标价，4 位小数，1 = 按标价；改它自动算成交单价 |
| 金额 | 未保存时为预览(数量 × 单价 × 折扣，精确十进制) |
| 与文件差额 | 本行金额 − 文件金额(折合本币)；0 显示「一致」，非 0 浅黄底 |
| 上次确认折扣 | 再次提交时出现；与现值不同的行整行标黄 |
| 销售提交折扣 | 销售最近一次提交时的折扣(对照) |
| 文件型号 / 文件品名 / 备注 | 有文件信息时出现 |

### 4.3 改价规则(与服务端 `MoneyPolicy.discountFromUnitPrice` / `applyDealPrice` 同一口径，SPEC §6.2)

- 折扣 = 成交单价 ÷ 标价：先按 12 位小数四舍五入，再按 4 位四舍五入；全程十进制整数运算，不经过 double(判断正负/为 0 也用精确十进制)。
- 定价来源由成交单价**自动**决定，页面预览与服务端保存结果一致：
  - 有标价且成交单价不高于标价 → 按标价打折，折成 4 位折扣(折扣列、报表、转单锁定的折扣都看得见)；**低于标价永远不会变成财务定价**；
  - 成交单价高于标价 → 自动改为财务定价(单价 = 成交单价，折扣 1)，成交单价旁出现「高于标价, 按财务定价保存」标记，不是报错；再改回不高于标价会自动回到按标价打折；
  - 没有标价(空或 0) → 只能财务直接定价(折扣固定 1)；填 0 或行菜单「设为赠品/0价」= 财务定价 0。
- 有标价的行填 0：提示「0 价请在行菜单选设为赠品/0价」(赠品须显式选择)。
- 行菜单：按标价打折(财务定价行且有标价时) / 按最新标价刷新(货品资料标价已变时；本行单价换成最新标价、折扣不变，保存前本行不可再改价) / 设为赠品/0价 / 撤销本行修改 / 去货品资料维护标价(能力位为真时)。没有「财务直接定成交单价」——SPEC 只允许没有标价或高于标价时财务定价，这两种情况填成交单价即自动转为财务定价。
- **批量设折扣**：勾选多行 → 表格工具条「批量设折扣(N)」→ 输入折扣 → 应用到勾选行中可按标价打折的行，没有标价、财务定价或刚刷新标价的行跳过并提示。另按全站口径「勾选多行后改任一勾选行单元格 = 批量生效」：在已勾选的行里改折扣，会一起改全部勾选行(悬停提示说明)。
- 保存只提交改过的行，每行四选一：冻结标价在用的按标价打折行提交 4 位小数 `discount`；没单价或原为财务定价、现改按标价打折的行提交 `dealPrice`(服务端按同一标价反推出同一折扣)；财务定价行提交 `dealPrice`；赠品提交 `giftZeroPrice: true`；按最新标价刷新提交 `useMasterPrice: true`。**表头是整体状态**：有效期/结账方式/财务备注总是带页面当前值(空 = 清空)，只改行时也不会冲掉它们。
- 填错的行(折扣越界、成交单价不是数字等)算作「有修改」：保存和确认都会先挡住并提示「有 N 行填写不对」/「请先保存修改」，不会悄悄丢掉。

### 4.4 决定

- **保存修改**：有填写错误的行先挡住并提示「有 N 行填写不对」；成功后以服务端返回的新版本重建页面。
- **确认报价**：有未保存修改先提示「请先保存修改」；有未定价行(没有价格，或标价 0 而客户文件有单价且未设为赠品)挡住并提示；确认弹窗显示审核责任人与报价金额。成功后通知销售可以转订货单，页面带 `true` 返回队列。
- **退回销售**：弹窗快捷选项「客户要改数量 / 缺货品需补充 / 价格需销售与客户确认」点一下填入原因，可再补充；原因必填。
- **撤销确认再修改**：已核价且未转订货单时出现(服务端 `financeActions` 含 `reopen`)，不认领、只带版本号；成功后整页重载，报价回到待核价并按常规认领后继续改。
- 处理中屏幕中央 `UtenBusyOverlay`(「正在保存修改」/「正在处理」)；有未保存修改时返回会先确认「有修改还没保存」。

## 五、销售端配合

- 报价详情：顶部状态横幅(草稿 / 待财务核价 / 财务退回(原因) / 已核价(核价人·时间) / 已转订货单 / 作废) + 核价记录；按钮只按服务端 `allowedActions`：编辑 / 删除 / 提交财务核价 / 撤回 / 重新修改 / 转订货单 / 作废 / 去核价 / 查看订货单；**不再有「审核」**。
- 报价列表(含销售任务中心报价大类)：分段 草稿(红) / 财务退回(红) / 待财务核价(黄) / 已核价(红数 = 已核价待转订货单，徽章入口 `salesQuoteAwaitingConversion`，事实 `salesQuote.awaitingConversion`) / 作废 / 历史记录；列表查询参数 `bucket` = 分桶键(服务端 `QuoteQueryFilter.bucket`)。
- 订货单列表「从报价引入」：弹窗「选择已核价的报价单」按 `bucket=AWAITING_CONVERSION`(已核价、还没转订货单，与徽章同一口径)在服务端筛，再按行上 `allowedActions` 只列本人能转的，已转单的报价不占分页。
- 订货单详情：来源报价旁显示「报价已核价」。

## 七、服务端契约(前端按此解析；与服务端 record 逐字一致，2026-09-27 冻结)

字段名以服务端 record 为准，前端不猜别名；`test/features/finance/quote_finance_contract_fixture_test.dart` 既有照 record 抄写的 JSON 夹具，也直接读服务端 record 源码核对组件名(任一侧改名就红)。金额/价格/折扣为十进制字符串(`ExactDecimalText`)，财务端点不做价格脱敏。

- `GET /api/sales/quotes/finance-review?state=pending|confirmed|returned&keyword=&page=&size=` → `PageResponse<QuoteFinanceListItem>`：`{id, billNo, billDate, clientName, sellerName, makerName, submittedAt, lineCount, pricePendingCount, totalOriginal, clientFileCurrency, statusBucket, reviewRevision, resubmitted, financeReturnReason, financeReturnedAt, financeConfirmedAt, financeConfirmedByName, convertedOrderNo, claimedByName, claimedByMe}`。
- `GET /api/sales/quotes/{id}/finance-review` → `QuoteFinanceReviewDto`：表头 `id, billNo, billDate, clientId, clientName, clientCode, makerName, sellerName, currencyName, baseCurrency, settlementMethodId, settlementMethodName, validUntil, deliverDate, contractNo, remark, clientFileCurrency, financeRate, financeRateMissing, status, statusBucket, reviewRevision, submittedAt, submittedByName, financeRemark, financeReturnReason/At/ByName, financeConfirmedAt/ByName, totalOriginal, fileTotalLocal, pricePendingCount, blockingLineCount, resubmitted, convertedOrderNo, canMaintainGoodsPrice, financeActions[edit|return|confirm|reopen], claimType` + `lines[{itemId, lineNo, goodsId, goodsCode, goodsName, colorName, unitId(2026-09-27 集成补上, 数量合计按单位分组), unitName, qty, listPrice(= 本行已存单价: 按标价打折时是冻结标价, 财务定价时是财务价, 空 = 没单价), priceSource(MASTER|FINANCE), financePriceByName, financePriceAt, currentMasterPrice, clientPrice, clientPriceLocal, dealPrice, discount, amount, fileAmountLocal, diffToFile, salesProposedDiscount, lastFinanceConfirmedDiscount, changedSinceLastConfirm, clientModel, clientGoodsName, remark, blockingReason}]` + `revisions[{revision, action, actionLabel, actorName, reason, createdAt}]`。页面的「标价」= 冻结标价在用时取 `listPrice`，否则取 `currentMasterPrice`(与服务端 `applyDealPrice` 取同一个)。
- `PUT /api/sales/quotes/{id}/finance` body `QuoteFinanceEditRequest{expectedRevision, expectedClaimId, validUntil, settlementMethodId, financeRemark, lines[{itemId, discount} | {itemId, dealPrice} | {itemId, giftZeroPrice: true} | {itemId, useMasterPrice: true}]}` → 最新 `QuoteFinanceReviewDto`。表头三项是整体状态(总是带当前值，`null` = 清空)。
- `POST /api/sales/quotes/{id}/finance-return` 与 `/finance-confirm` body `QuoteFinanceDecisionRequest{expectedRevision, expectedClaimId, text}`(退回原因写在 `text`，必填；确认时 `text` 为可选财务备注，页面不传)；`POST /{id}/finance-reopen` body `QuoteActionRequest{expectedRevision}`(不认领) → 最新 `QuoteFinanceReviewDto`。
- 认领：通用任务认领接口 `/api/task-claims/SALES_QUOTE_FINANCE_REVIEW/{报价id}/claim`，服务端只接受 status 2 的报价。
