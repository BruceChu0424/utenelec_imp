# AI 页面说明与模型返回异常修复

日期: 2026-10-03。关联 [ADR-140](../99-决策记录-ADR/ADR-140-权限内对话助手与页面示例指导.md)。

## 现象与定位

用户在新建销售报价单点击“这个页面怎么填写？请举个例子。”，收到“AI 没有返回可处理的对话结果，请换一种说法或稍后重试”。

这句提示来自 AiChatJobHandler 的 INVALID_RESPONSE 分支。已从代码和可重复测试确认:

1. 启用模型时，旧代码把明确页面帮助也先交给模型选择；本地已有经过权限校验的指南，却会被空回复、截断或非 JSON 阻断。仅模型不可用时的规则模式才绕开此依赖。
2. 路由调用传 jsonSchema=null，因此 JSON_SCHEMA 配置没有获得完整结构约束。提示词给的是伪 JSON 形状，输出预算又被固定压到 1200。
3. 真实 ShellRoute.push/pop 中，matchedLocation 可以保留旧页，而 uri.path 已跟随活动页面。旧聊天上下文可能解释错页面。原测试直接注入路由字符串，没有覆盖真实 Shell 导航。

截图不能区分实际服务商当次是空回复、截断还是协议内容不符；本轮未读取真实模型响应或密钥，不把其中一种推断写成已证实事实。

官方 [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 明确要求合法 JSON 示例及合理输出长度，并说明 JSON 模式仍可能出现空内容。该资料用于确定兼容性测试场景，不表示用户配置的服务商一定是 DeepSeek。

## 修复

- 新增只读 intentHint=PAGE_HELP。客户端仅在当前页快捷入口和页面感知启用时发送；后端校验提示值、当前页面、部门、页面动作及字段权限。
- 常见完整页面问法、明确可见字段问法可以读取本地指南，输出规则、具体假设例子和来源。混合越权请求不凭关键词当作成功的页面帮助。
- 未知页面或关闭页面上下文时明确提示，不恢复历史页面，不猜字段含义。
- 自由提问采用当前权限生成的闭合 schema。工具名、知识项、字段键及意图是有限枚举；参数保留各工具的严格校验。补合法 JSON 示例。
- 请求输出预算改为 8192，但公共网关仍按管理员配置取小。未增加原有重试次数，未变更服务商设置或公共网关行为。
- 保持最终 content 与 reasoning_content 的边界，不用思考文本中的 JSON 冒充最终路由结果。
- 聊天页面上下文改为活动 URI path，外壳原有导航定位逻辑保持原用途。仍不发送 URL 查询值和真实表单内容。
- 格式错误提示明确归因于服务返回，不再把预设问法的失败归咎于用户不会提问。

## 验证方法

前端使用真实 GoRouter + MainShellPage 进行列表 → push 报价新建 → push 订货新建 → pop → pop 回归，检查每次实际发送路径和上下文开关。不是只向组件注入固定字符串。

后端同时验证三层:

1. 处理器与目录: 已启用但返回异常的模型不能阻断明确页面帮助；无权页面/字段、未知提示和关闭上下文仍受门禁保护。
2. 真实 loopback HTTP 协议: OpenAI 严格 schema、Anthropic output_config、管理员较低 token 上限，以及空最终文本、截断、普通文本非 JSON 和仅有 reasoning JSON 的响应。
3. 一次性 PostgreSQL + 完整 JWT/后台队列 + 已启用 Fake AI 服务商: 复现截图问法直接成功且提供商调用为零；自由问法实际走 gateway；伪造跨部门页面在入队前拒绝；格式异常不能导致授权写入；关闭上下文不恢复旧页。

本轮最终验证全部通过:

## 运行边界

本轮修改源代码，测试仅使用本机 loopback 假服务商和临时 PostgreSQL，没有调整真实服务商配置、发送真实业务数据、修改业务数据库或重启当前运行的 8080 服务。代码修复需要运行中的前后端加载新版本后才能生效。真实服务商当次响应的具体异常原因仍需其技术日志确认。
