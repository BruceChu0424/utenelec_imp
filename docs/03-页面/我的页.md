# 我的页

> 路由：`/profile` · 实现源：`lib/features/profile/pages/profile_page.dart`
> 关联：`/profile/edit` · `/profile/me/changes` · `/hr/profile-changes` · `/hr/profile-changes/:id`
> 最后更新：2026-07-23 · 状态：v3 — 丰满字段 + 删除「账号与设置」卡 + 接入修改申请闭环

## 一、定位

给所有员工使用的个人资料中心 + 业务快捷入口。同时承载**个人信息修改闭环**的员工侧入口。

- 解决的问题：
  - 查看自己的姓名 / 工号 / 部门 / 岗位 / 联系 / 组织 / 紧急联系人等完整字段
  - 跳到本人相关业务（工资 / 报销 / 通知 / 建议）
  - **自助修改个人信息**（直改字段即时生效；需审核字段提交后走 HR 审批）
- 产品位置：底部 / 侧边导航"我的"项。

## 二、入口与导航

- 进入路径：
  - 底部 / 侧边导航"我的"项
  - 工作台首页（如有相关入口）
- 离开去向：
  - 快捷入口 → 工资条列表 / 我的报销 / 公司通知 / 建议箱
  - 「修改我的信息」→ `/profile/edit`
  - 「修改密码」→ `/change-password`（Phase 1 已有路由）
  - 「我的修改申请」→ `/profile/me/changes`

## 三、字段展示（v3 重写）

按角色脱敏：薪资 / 银行仅 HR/admin 可见；手机本人看全量，他人看脱敏；身份证 / 银行卡仅本人与 HR/admin 可见。

| 分组 | 字段 | 来源 | 备注 |
|---|---|---|---|
| 个人信息 | 工号 / 姓名 / 部门 / 岗位 / 邮箱 / 办公电话 / 工位 / 现住址 / 户籍地址 / 民族 / 政治面貌 / 婚姻状况 | session.user + EmployeeDetail | 后端按角色脱敏 |
| 我的修改申请 | 卡片 | `myProfileChangesProvider('pending').total` | pending > 0 时显示数字 + 高亮 |
| 快捷入口 | 工资条 / 我的报销 / 公司通知 / 建议箱 | — | 与原版一致 |

**已删除**：原"账号与设置"卡（含"应用设置 / 修改密码 / 帮助与反馈" ListTile）。
- 「应用设置」入口已迁移到设置项菜单
- 「修改密码」现在升级为 Hero 卡下方的 CTA 按钮
- 「帮助与反馈」暂留 Phase 3

## 四、Hero 用户卡 + 两个 CTA

```
┌───────────────────────────────┐
│ 👤  张三                       │
│     生产部 · 操作工            │
│     [员工]  [HR]  …           │  ← 角色 chip
├───────────────────────────────┤
│ [修改我的信息]  [修改密码]     │  ← 两个 CTA；canEdit=false 时仅显示「修改密码」

```

- 「修改我的信息」——按 `Perm.profileEditSelf` 控制可见性
- 「修改密码」——任何登录员工可见，路由 `/change-password`

## 五、响应式布局

- compact（手机）：单列纵向滚动（Hero + 快捷入口 + 信息详情 + 我的修改申请）
- medium（平板）：内容居中 ≤720dp
- expanded（桌面）：左 360dp 固定栏（Hero）+ 右剩余栏（详情 + 我的修改申请）

## 六、涉及的 Uten 组件

- `UtenAppBar` / `UtenCard` / `UtenUserAvatar` / `UtenInfoRow`
- `UtenButton`（CTA 两个按钮）
- `UtenResponsiveGrid`（快捷入口 4 等宽瓦片，沿用旧版结构）
- `AppNotification`（失败 / 成功通知）

## 七、涉及的 Uten 服务

- `currentPermissionsProvider`——判断是否渲染「修改我的信息」按钮
- `myProfileChangesProvider('pending')`——「我的修改申请」入口的计数

## 九、涉及的数据实体

→ [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `User`：姓名 / 工号 / 部门 / 岗位 / 角色
- `Employee`：手机 / 邮箱 / 户籍 / 现住址 / 工位 / 紧急联系人 等
- `ProfileChangeRequest`：本批次内 pending 数（驱动"我的修改申请"快捷入口）

## 十、权限要求

- **全员可见**
- 数据范围：仅本人；他人看不到自己的页面
- 操作权限点：
  - `profile:edit:self`（控制「修改我的信息」CTA 是否可见）

## 十一、边界情况

- 无 `profile:edit:self` 权限时：「修改我的信息」按钮 hide；「修改密码」仍可见
- `EmployeeDetail` 加载失败：右栏降级显示「—」占位（保持 UI 骨架）
- 我的修改申请网络异常：占位「—」+ 顶部 appError 提示
- 性能档 = lite：Hero 卡 boxShadow 关闭、CTA 动画简化
- 网络断开：基本只读信息可用；CTA 按钮点击走 onPressed null 兜底

## 附录 A：修改闭环（端到端）

详见 [员工详情页.md](员工详情页.md)（HR 端嵌入区块）和 [/profile/edit 实现](lib/features/profile/pages/profile_edit_page.dart)。

```
员工             前端               后端                 DB
─────────────────────────────────────────────────────────────
点"修改我的信息"
            → /profile/edit
              字段分组
              直改/需审核 badge
点提交
            → 收集 dirty 字段
              若含需审核 → 弹密码框
                verify-password
            → POST /api/profile/me/changes
                                → ProfileChangeService.submit
                                  直改：立即 UPDATE employees/sensitive
                                  需审核：INSERT profile_change_requests(pending)
                                  employee.version + 1
                                  audit_log
            ← 成功通知 + 跳回 /profile
                                                  … 时间过去 …
                                                  HR 端：
                                                  /employee/:id 详情页
                                                  Hero 后看到「待我审 (N)」
                                                  点进 /hr/profile-changes/:id
                                                  diff 视图
                                                  批准 → 事务内校验 version + UPDATE
                                                       → status=applied
                                                       → employee.version + 1
                                                       → audit_log
                                                  驳回 → 填原因 → status=rejected
```
