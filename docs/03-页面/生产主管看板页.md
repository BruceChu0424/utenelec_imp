# 生产主管看板页

> **当前实现**：`/production/progress` 生产进度工作台；完整产能/OEE 管理看板尚未实现
> **页面状态**：计划与真实子计划导航已实现；生产发布仍为 **NO-GO**
> **更新日期**：2026-08-28

## 2026-08-28 V415 生产、质量与仓库投影

生产主管看板现在必须按执行段分别展示：普通剩余可报量、FQC 待检/PASS/FAIL、REWORK 待报量、SCRAP/REJECT 补产物料状态、FINISHED_IN 待点收量和仓库已实收入库量。`fqty` 只表示当前有效完工申报贡献；生产完成率只认 `iqty / 计划量`。

看板内嵌 FQC 补产物料待办：`AWAITING_ANALYSIS → AWAITING_CONFIRMATION → AWAITING_STOCK/BLOCKED → AWAITING_WAREHOUSE → READY`。计划员确认时按当前 BOM 冻结 exact demand；库存不足只保留缺口并允许用新幂等键补差，不能重复生成 DRAW。`READY` 只有在仓库实发且全部 recovery demand `FULFILLED` 后成立；recovery-only 分析不能从普通分析命令再生成一张顶层计划。

较早 BLOCKED lot 不得遮住同段后续 REWORK 或 material-ready lot；普通 gross 尚未达到计划量时，正常生产剩余优先。以上状态均来自服务端查询，页面不根据通知、角标或货品名称自行推断。

## 一、当前页面边界

当前“生产主管看板”落在生产调度工作台的生产进度页，重点是计划追踪、筛选、置顶和下钻，不应宣称已有有限产能负荷、OEE、质量成本或实时车间大屏。

父计划卡展示单号、状态、车间、工期、计划量、当前有效报工贡献与仓库实收入库量；存在 `subplan_links` 时显示「子计划 N 张（点开展示进度）」并可展开真实自制件子计划。每条子计划分开显示计划/排产、`fqty`、`iqty`、FQC/待点收和物料状态，例如「待品质判定 2」「待点收 1」「已入库 1 / 排产 5」。采购/委外 IQC PASS 只形成合格待入库；仓库确认实际入库后才推动合格库存与齐套，二者都不直接增加生产报工或父成品入库。

## 二、独立点击域

| 点击区域 | 行为 |
|---|---|
| 父计划表头 | 打开父计划详情 |
| 「子计划 N 张（点开展示进度）」 | 仅展开/收起 |
| 具体子计划行 | 打开该子计划详情 |
| 置顶/重要菜单 | 只修改相应标记 |

以上点击域必须互不吞事件。子计划 ID 为空、路由失败或无权访问时显示明确反馈，不允许出现“点了没反应”。

子计划整行触控高度至少 56dp。375px 等窄屏使用两行布局：第一行放身份、状态和进入箭头，第二行可换行展示「已报工 / 已入库 / 排产 / 物料齐套」；关键文字不小于 14px，在系统字体放大 1.3 倍时仍须无溢出、可读并可整行点击。不能用压小字号或只靠颜色维持单行。

## 三、状态与权限

- 查看计划不等于可编辑、派工或报工；
- 卡片状态来自服务端计划与入库事实，页面不直接改生产状态；
- 草稿、已审核、红冲、已完成和延期必须分别显示；
- 子计划展开后仍按自身状态和数量展示，不继承父计划完成状态；V194 只把合法 FINISHED_IN 的精确回供计入父物料齐套，不把子计划计划量或报工量直接算成父计划/销售完成；
- 服务端对象范围与权限校验是最终边界。

## 四、后续完整看板

未来完整生产主管看板可增加备料中、备料完毕可报工、生产中、待审核报工、待清料、延期、待料、粗产能和 Outbox 水位，但只有在标准工时、产能日历、质量与投影 SLO 有可靠数据后才能展示。当前不得用伪精确百分比代替缺失主数据。
