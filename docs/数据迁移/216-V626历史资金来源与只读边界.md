# V626 历史资金与期初余额来源证明

迁移文件：`V626__legacy_finance_source_provenance.sql`。既有资金单、流水和应收应付业务值不改写；新增来源元数据默认 NULL。

## 旧资金事实的边界

`M_Get` 没有逐笔核销分配证据。导入原收款时使用 `LEGACY_UNCLASSIFIED`、金额权威版本 0，保留原客户、账户、金额、币种、汇率、状态和操作人快照，不能据其金额推断预收款、销售单归属或补造核销明细。付款、费用、其它收入及其真实原明细遵循相同原始事实原则。

`M_AllCheck` 使用 `LEGACY_SNAPSHOT` 保留逐行真实账户和原进出金额；NULL 仍表示未知，0 仍为 0。非本位币缺少本币快照时留 NULL，不从当前汇率反算。不生成新的 POSTING、反向流水或会计凭证，原历史资金不会重新影响当前账户余额。

这些历史头、原明细和原资金流水只读。数据库同时覆盖旧版本已经导入、仅有 `legacy_id` 的行：不能改金额、重新审批、删除、清除或重绑来源，也不能借旧资金生成新的可用预收、冲抵或来源分配。普通原生资金单的审批、反审和真实现金记账规则继续执行。

## 未结余额与新业务

`M_In` / `M_Out` 的本币原额、截止时点已结额和剩余额分别来自原行，必须满足原额减已结等于余额。仅当源币种明确为本位币且源汇率明确为 1 时，原币维度与本币等值；其余原币总额和原币余额保持未知，不把 NULL 或 0 汇率改为 1。

源 BillID、单号、往来单位和实际允许单据族共同确定来源。旧应付 BStyle=1 同时用于采购与委外，不能依前缀或首个命中随意绑定。唯一匹配才保留实际来源 ID；缺失、多重或未证明来源保留 `LEGACY_OPENING` 和明确的待核验原因。所有本次历史余额使用 `LEGACY_UNVERIFIED`，避免从正负号自动派生成 CREDIT 或 PREPAYMENT。

历史原额、原币事实、来源、截止时点和初始已结额不可改；账户当前余额、应收应付当前已结和剩余额仍由后续合法业务推进。例如原额 20、历史已结 8、剩余 12，在截止之后新增真实收款 3，可变为已结 11、剩余 9，原 8 的事实不变，也不会伪造一笔历史 8 元收款或凭证。

资格取决于已证明的初始正余额，不额外猜测原额必须为正。例如源原额 0、历史已结 −8、余额 +8 仍保留该原始等式；新收付结清后可回到余额 0，合法反向应恢复原历史基线。付款终局守卫对来源证明行将当前累计减去不可变初始累计，再与真正新增的有效付款精确核对；普通原生应付保持既有规则。

原币已明确且严格为正的当前历史余额可以用于新收付。数据库的应收身份资格依据不可变的初始正余额，因此全部结清后仍保留可校验来源；新的核销明细必须晚于受验快照的上海业务日期。历史负余额不自动成为可用预收、预付或退款。月结报表以受验 `sourceSnapshotAsOfUtc` 为基线，不能将截止前累计已结额当成旧单据日期发生的现金事件；覆盖截止之前或跨越截止的区间明确为无法完整重建。

已证明的正余额也可在原有身份和来源限制内成为新原生抵扣的目标：应付只接受现役 CREDIT / CLAIM_CREDIT，客户预收抵扣仍要求真实订单来源明细和原有可用额度，不借历史证明虚构订单分摊。历史余额始终不能成为新的抵扣资金来源。初始抵扣额为 0；之后的可变抵扣总额必须在事务结束时等于实际有效抵扣事件之和，孤立修改投影、改写事件金额或重复反向均被拒绝。正常反向按原事件恢复余额，不改变历史原额与截止已结基线。

## 来源证明与权限

唯一写入入口为 `public.fn_import_legacy_finance_source(uuid,text,jsonb,integer)`，固定支持四类资金头、两类真实明细、账户原流水及 AR/AP 期初余额。入口只接受完整原始 typed 行，数据库集中构造目标字段，不接受调用方提供的任意目标表、目标金额哈希或 SQL。证明存原文件 SHA、原行 SHA、目标 UUID、目标字段 SHA 和必要原始金额基线，不存源个人原文。

入口要求实际迁移登录身份、同库 bootstrap 排他锁、同运行事务、完整 `--bootstrap-all` RUNNING 回执、受审文件清单、候选提交和 manifest，以及真实集群 system identifier。四项会话设置只是与持久证据的比对值，本身不是授权。应用角色即使误获函数执行权，也不能靠设置 GUC、临时伪造 catalog 或复用另一事务的证明导入。

迁移账号必须能读取实际 `pg_catalog.pg_control_system()` 的 system identifier。若缺少权限，由 DBA 精确授予该零参函数 EXECUTE 给真实迁移执行角色；不向应用授权，不加入 `pg_monitor`，也不降低集群身份校验。V626 不擅自改变系统函数 ACL 或角色成员关系。

新表 `legacy_finance_import_sources` 为 PRESERVE，应用只读，写入注册函数不向 PUBLIC 或应用开放。重置清业务数据保留证明，证明没有反向外键阻碍受控 TRUNCATE。审计保留 ID、哈希和变更事实，使用 `fn_audit_redacted` 明确排除 `initial_state`，防止通用审计将嵌套财务金额越权显示。

V624 委外证明入口仅前向复用共同 bootstrap 身份校验，原迁移文件不变。旧委外结算 NULL 的查看与专项核验要求不变，新收货仍不能凭历史未知条款自动继续。
