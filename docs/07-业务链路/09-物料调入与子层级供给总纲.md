# 物料调入与子层级供给总纲

- 生效日期：2026-09-13
- 适用范围：生产物料分析准备页（`/production/material-analysis`）的三个下达桶（下达采购 / 下达委外 / 下达车间）里的「物料 / 调拨」模块，以及它对下层子件需求的影响。
- 相关：[委外全链路 SOP](08-委外全链路-订货出仓回仓重设计.md)、[生产物料分析页](../03-页面/生产物料分析页.md)、[ADR-049](../99-决策记录-ADR/ADR-049-跨物料分析让料与后续供给优先补齐.md)、[ADR-062](../99-决策记录-ADR/ADR-062-委外先自制后通知与分批通知.md)、[ADR-071](../99-决策记录-ADR/ADR-071-下达车间原子化与计划侧齐套判断下线.md)、[ADR-080](../99-决策记录-ADR/ADR-080-跨路线在途调入与子层按计划产出展开.md)

## 一、一页结论

1. **调入的东西永远是「最终件」**：同主仓、同货品 / 颜色 / 单位的成品或外购件。别人计划里的在制品、委外前置自制的半成品、正在委外商手上的料，都不是最终件，永远不能被调走。

2. **调入只减数量，不改归属**。调进一个车间自制的物料行，它还是车间的活；只是「还要自己做多少」变少了。不会因为调入了一笔采购在途，这个物料就跑到采购桶里去。

3. **子件要备多少料，跟着父件「还要自己产出多少」走**，公式只有一句：

   ```
   父件计划产出 = max(已承诺自己做的量, 物理缺口 − 外部最终件在途)
   子件毛需求   = 父件计划产出 × 单耗
   ```

   - 外部在途到货就能顶上，不必为它备下层料 → 不积压。
   - 已经下达车间 / 已经建了前置自制任务的那部分是冻结承诺，它的料一件都不能少 → 不断料。
   - 任何一层计划产出为 0，它整棵子树的未下达需求自动归零，不需要人一层层去删。

4. **计划口径与实物口径严格分开**。在途只影响「还要不要再安排」；能不能领料、能不能开工、齐没齐套，永远只认真正合格入库的货。在途没到就不会提前 READY，也不会提前开工。

5. **「只需 100 却要买 10000」不需要每层各买一遍**：一次下单，100 进本需求的精确账，9900 进公共备货池；别的计划缺同一个料时从公共在途里认领，不再重复采购。

## 二、三种调入的定义与边界

| 调入方式 | 调的是什么 | 减「还需安排」 | 减「物理缺口」 | 对下层未下达需求 |
|---|---|---|---|---|
| 现货让料 | 另一份计划已入库的合格库存权益 | 是 | 是 | 立即按父件计划产出缩减 |
| 专属在途调入 | 另一份计划已下单、未实收的采购 / 委外份额 | 是 | 否 | 立即按父件计划产出缩减 |
| 公共在途认领 | 公共备货池里已批准、未实收的份额 | 是 | 否 | 立即按父件计划产出缩减 |

**三条共同边界**

- **同主仓**。跨主仓不做账面调入，走真实仓库调拨单。
- **目标必须是生效的需求行**：路线已确认为采购 / 委外 / 自制之一，控制段不是「发货」或「参考」。
- **来源必须是外部份额**：只有路线为采购或委外的供给动作可以当来源。自制在制品与委外前置自制半成品不在其列。

**分别的限制**

- 现货让料：一个物料节点同时只保留一条未补齐关系；让出方自动挂「优先补齐」，它下一批合格供给先补自己。可让出 / 可调入的层级为第 1 层及以下的所有 BOM 组件层；第 0 层根供给行走它自己的根产出交付通道。
- 专属在途调入：调入动作沿用**来源路线**落库（它确实是一张采购单或委外单的份额），但分桶归属跟着**目标行**走。撤销时必须显式拆分「退回原计划」与「释放到公共池」两部分。
- 公共在途认领：必须跨分析（同一份分析里的兄弟节点不能互相认领，同货品的合并发生在订货层）；我方供料 BOM 的委外件不吃公共超量。

## 三、委外与自制的子层级处置链

### 3.1 委外的两种形态

- **无子层委外（纯外协）**：行为与采购完全一致。调入成品现货或在途即可抵掉需求，没有下层问题。
- **有子层委外（我方供料）**：先在本分析内按「净发外量」做前置自制，目标件完工后进委外准备专属预留，再通知委外 → 委外申请 → 商业订单 → 财审批准 → 出仓给委外商 → 回厂 → IQC → 仓库实收，这时才成为本需求的最终供给。

有子层委外的前置自制段与自制件完全同构，因此下面的规则对「自制件」和「有子层委外件」一视同同。

### 3.2 调入之后怎么走（用户最关心的那条链）

设父件需求 100，现货 0。

| 情形 | 父件计划产出 | 下一步 |
|---|---|---|
| 什么都没调入 | 100 | 自制：下达车间做 100；有子层委外：前置自制 100 再发外。下层按 100 套展开。 |
| 调入在途 60，尚未下达 | 40 | 只需为 40 件备料。剩下 60 等在途到货。下层毛需求从 300（按单耗 3）降到 120。 |
| 调入在途 60，其中 40 已下达车间 | 40 | 与上一行一致：已下达的 40 恰好等于净做量。 |
| 100 已全部下达车间，事后才调入 60 | 100 | **下层仍按 100 备料**。已下达是冻结承诺，系统不会偷偷把车间的料抽走。要少做，得由人去减量或撤回那张计划。 |
| 全部 100 被调入覆盖 | 0 | 不下达、不前置自制、不发外，整棵子树的未下达需求归零。 |

### 3.3 下层再缺料怎么办（递归，不需要新流程）

子件不满足时，**走和父件完全一样的一套解题顺序**，一层层往下递归，直到叶子都是采购件为止：

1. 本批已锁定的精确权益（最高保护，任何调入都挤不掉）
2. 同主仓公共现货
3. 其他计划的现货（让料调入）
4. 其他计划的专属在途（调入）
5. 公共在途（认领）
6. 新下达：采购件进采购桶、自制件进车间桶、委外件进委外桶

**三条既有规则保证这条链不打结**：

- **缺料不卡上层下达**。缺料的批次先进「待料」，车间侧齐套后自动转「可开工」，计划侧不做齐套拦截。所以父件该下达就下达，不必等下层齐了。
- **子件各走各的桶**。采购子件进采购桶、自制子件进车间桶、委外子件进委外桶，逐行下达，互不阻塞。
- **已下达量永不回流成待下达**。需求变小时「还需安排」被钳到 0，已经下出去的单不会被系统自动改写；要减量得走撤回或订货改量，由人决定。

### 3.4 混着采购、自制、再委外的多层树

每一层只认自己父层的计划产出，逐层套用 3.2 的公式即可。任何一层算出 0，它整枝的未下达需求都为 0。同一个货品出现在多条 BOM 路径上时，需求按路径分别保留用于追溯，公共库存在一次投影里只被扣一次。

### 3.5 分批前置自制与公共超量

委外前置任务已经接管的需求不能在第二次排产时重新记作公共超量。需求 10000、首批排 6000 后，第二批排 4000 不新增供给承诺；第二批排 6000 仅新增公共量 2000。候选物料入口和已有任务入口共用这一口径。公共量通过准备任务身份归集，不要求存在只用于精确需求的 allocation。

撤回前置行动同时减去需求份额与公共份额；剩余承诺必须覆盖尚未撤销的生产计划，已有实际产出或已通知委外时先完成下游反向。[V621](../数据迁移/211-V621委外前置生产承诺守恒.md) 对旧任务只修复能够由行动与计划共同证明的投影，矛盾历史拒绝自动猜测。

级联预览读取服务端 `externalFutureCoverageQty` 与 `internalCommittedOutputQty`，区分无需我方生产的最终件在途与必须消耗子件的内部生产承诺。中层现货或外部最终件覆盖后不得继续按原毛需求放大孙层；内部承诺不能当作外部成品扣掉。包装和固定批次逐 BOM 边向上取整，不能用累计平均单耗相除替代。

### 3.6 多节点路线与货品默认

同一货品在不同 BOM 路径可以分别选采购、自制或委外。一次确认中，同货品各节点路线一致时更新货品默认；路线混合时只保存各节点决定，保留货品原默认，不能按请求的最后一行覆盖主档。混合节点的主档建议与各自确认路线分别保存，刷新不能因为二者不同就清掉本次决定。

路线命令先完整检查版本、来源范围、重复选择、合法路线/原因及已有下游，随后在同一事务中批量保存。货品按统一 UUID 顺序锁定，节点和货品的审计触发器保持逐行生效；内容没有变化的节点不重写确认人/时间。任一节点不合法、已有不兼容下游或版本过期时，整批不落地。路线保存后仍只重算一次完整分析，不改变数量和库存裁决。

## 四、采购批量与在途

### 4.1 「只需 100 却要买 10000」

- 下达采购时可以把数量填到 10000：超过本需求的部分需要「超量下达」权限，单独记为**公共备货**，不占本分析的精确账。
- 公共备货在采购订单财务审核通过后成为**公共在途**，其他计划缺同一个料时直接认领，不必重复采购。
- 采购员在订货环节直接超订的部分，订单批准后同样自动进入公共池，不需要计划员额外授权。
- 货品主档上的**最小起订量**与**订货倍数**只影响下达数量的默认值（向上取整到倍数的 `max(净需求, 起订量)`），是软约束，计划员可以改。

### 4.2 在途的生命周期怎么算

| 阶段 | 计入「有效在途」 | 说明 |
|---|---|---|
| 申请已下达、订单未批准 | 是 | 已形成本计划的承诺，不该重复下单 |
| 订单已批准、未到货 | 是 | 可被调入 / 认领的正是这部分 |
| 已到货待检 / 合格待入库 | 是 | 仍算未来供给，但不是实物供给，不能据此开工 |
| 合格入库 | 转为现货 | 在途减少、物理缺口同步归零 |
| IQC 判废且已按失败切片重新欠货 | 是 | 补采承诺仍在，不必再下一单 |
| 订单取消 / 关闭且无补采 | 否 | 下次刷新时「还需安排」自动回升，下层需求同步回补 |

**晚到或交期未明的份额**：候选列表里会标出预计到货日期，调入时按当前口径默认接受，界面明示。真正决定能不能开工的仍然是实物入库。

## 五、不变量（落地时必须锁死）

1. 实物口径不认在途：在途未合格入库，不生成正式预留、不发领料、不把待料提升为可开工。
2. 子件毛需求只跟随父件计划产出；父件计划产出为 0 则子树未下达需求为 0。2026-09-21 起（[ADR-099](../99-决策记录-ADR/ADR-099-计划量单一入口与子层按计划产出展开.md)）「父件计划产出」是服务端事实：`max(需求量, 已下达计划量含公共备货产出)`——顶层按 1500 下达则第一层子件需求就是 1500，既有自制锚点配额自动跟到 1500；客户端不再自算。
3. 只能调入最终件；自制在制品、委外前置自制半成品、委外商处的料不得作为来源。
4. 数量守恒：让料 OUT = IN；在途调入量 ≤ 来源未实收容量且 ≤ 目标待补量；撤销拆分的「退回原计划 + 释放公共」之和等于撤销量。
5. 精确账与公共账分开：公共备货不绑定具体需求；自制与有子层委外不开放公共超量**子件任务**（多做的量不产生额外的下层采购/委外责任）。2026-09-14 起车间的**本批生产量**可超出需求，超出部分按公共备货产出单独记账（[V577](../数据迁移/169-V577下达车间超量与公共备货产出.md)），仍不绑定具体需求；销售订单来源的顶层行按订单未满足量封顶。2026-09-21 起（ADR-099）公共备货产出同样驱动下层需求（多做 500 个成品就要多备 500 套料），只是产出本身仍不绑定具体需求。
6. 已下达单据不被静默改写：需求变化只影响未下达部分。
7. 跨主仓不做账面调入。
8. 调入只减数量，不改目标行的路线与车间归属。

## 六、本期明确不做（留白与理由）

| 项 | 理由 |
|---|---|
| 有子层委外件当「在途来源」被别的计划调走 | 可转容量的基数是「订单已批准量」，不区分目标件是否已出仓给委外商。在「已批准未出仓」阶段被转走，源计划会同时失去容量又没有实物在路上，形成双重落空；且订货改量不回写前置自制账本，账本本身已有断链。放开前需要先补「已出仓」这一档与账本回写。 |
| 同一分析内兄弟节点互相认领公共在途 | 认领的跨分析约束由服务层与数据库双重设防，放开会引入自引用。同货品的合并已经在订货层按多来源锚定实现。 |
| 第 0 层根供给行按在途净算下层 | 第 1 层需求同时是实物执行层的基准，用在途去缩减它会动到齐套、领料与开工门禁，违反不变量 1。根供给行的现货交付已有专门通道。 |
| 父件行「一键办齐子层」批量编排 | （2026-09-14 [ADR-081](../99-决策记录-ADR/ADR-081-下层一键办齐与物料表身份列统一.md) 已接办为有序编排；2026-09-21 ADR-099 把整页的下层数字改由服务端 issue-plans/preview 算）主表本身就是树，子层行在各自的桶里已经可以逐行下达，数量口径本轮也已纠正。把「确认路线 + 调入 + 三桶下达」压成一个事务是纯体验增强，但要同时穿过三条各有校验的下达路径，任一行失败要整体回滚；与本轮的正确性改动放在同一批次会放大回归面，单独排期。 |
| 行动消息中心（新建 / 取消建议 / 提前延后 / 改量 / 失败回补的显性化） | 现有能力已保证「已下达不被自动改、风险能被看见」；消息中心是体验增强，单独排期。 |
| 时间相抵与齐套承诺（最早可齐套 / 可发货日期） | 依赖提前期与交期建模，复杂度与性能风险最高，单独排期。 |

## 七、性能与十年数据

- 在途与内部承诺量都按分析一次批量取回，不引入逐行查询；子层展开仍是一次自顶向下的单趟遍历。
- 跨分析的两条热路径（让料软占用、入库唤醒候选）按货品维度扫全库物料行，本期补了 `(goods_id, color_id, unit_id, analysis_id) WHERE active` 索引。
- 专属在途调拨表被 8 个采购 / 委外改单守卫按外部明细反查，本期补了 `external_item_id` 索引。
- 分析刷新是整份分析重算，由入库、质检确认、让料、调入、认领等事件在同一事务内触发；订单取消这类外部事件不触发刷新，数字在下次刷新时自动纠正。
