## 一、页面职责

销售订货单经销售审核后进入本页等待财务确认（V294 闸门）；**确认后订单才对计划部可见并排产**。本页是财务的审批收件箱与决策面，与销售端订单详情彻底分离——财务在此**不**看到改量/排产进度/取消订单/红冲等销售运营操作。

## 二、列表页（响应式审批工作台，2026-08-28）

对齐大公司审批中心（SAP/Oracle 审批收件箱）范式：

- **顶部摘要条**：当前视图笔数 + 财务控制边界；明确“确认只放行计划部可见与排产，不代表收款或正式应收”。
- **分段 Tab**：`待确认`（默认，财务当前可办件）/ `已驳回`（当前已转销售修正的订单）。徽标只数财务可办件；驳回后任务和角标转到订单归属销售，销售重审后才转回财务。
- **服务端搜索**：按单号、客户、业务员搜索整个待办集合，不做仅当前页的前端过滤；输入防抖并取消陈旧请求。
- **桌面/平板（≥840dp）**：使用系统自研 `MasterDataTableView`。列含单号、客户、业务员、订单原币金额、客户应收（本币）、交货日期、紧迫度、明细行、开单日期、审核状态/驳回原因；支持列宽、列显隐、全屏和分页。
- **桌面行交互**：单击行或复选框切换选择；350ms 内同行双击进入专用审核详情；右键/长按与无障碍“打开详情”动作作为替代入口。
- **紧凑端（<840dp）**：改为可勾选的密集列表；单击选择并保留显式「详情」按钮，绝不把双击作为唯一入口。
- **选择范围**：仅 `待确认` 且持有 `sales_order_finance:confirm` 时显示复选框与批量操作；`已驳回` 始终只读。切 Tab、搜索、手动刷新会清空选择；跨页选择最多 100 笔。
- **原子批量确认**：弹窗逐笔列出单号、客户、币种与金额，显示当前审核员和共同备注；服务端对 UUID 去重排序、固定顺序加锁、先全量校验再统一写入。任一订单已驳回/失效/越权则整批回滚，不允许前端循环单笔接口产生“半批成功”。批量驳回不在本期范围，驳回原因仍须逐单填写。
- **风险呈现**：逾期/临近交货行使用低强度语义底色并保留文字紧迫度；驳回件显示红色语义和原因，不能只靠颜色区分。
- 排序：未驳回在前，交货日升序（近交期优先）。

## 三、审核详情页（专用视图）

点列表卡片进入。与销售端订单详情完全不同，面向"该不该放行"决策：

1. **状态条**：单号 + 待确认/已驳回状态与下一步说明。
2. **客户财务快照卡**（本页核心增量）：
   - 应收余额（本币，`ar_ap_ledger` direction=AR 未结 `amount_balance` 合计，与应收汇总报表同口径）；
   - 信用额度 / 铺底额（客户主档）；
   - 应收余额 > 信用额度（且已配置额度）→ 红色告警「该客户应收余额已超信用额度，请谨慎确认」；
   - 本单金额（可读币种名称 + 原币合计）。
3. **订单信息卡**：单据日期/业务员/制单员/制单时间/交货日/**币种（加粗红色）**/发运策略/结帐方式/合同号/备注。销售端不录入定金或预收；历史订金快照不能证明到账。
4. **订单资金汇总卡**（只读）：订单金额、正式 AR、现金累计已收、费用冲销、预收累计到账/已转销/可用、
   正式 AR 未收、未发运金额、计划尚需收款与超收。cashReceived 不含 writeOff；有
   hasUnallocated 时显示历史多订单 AR 来源未分配告警，不把不确定金额计入本单。币种已在订单信息卡独立
   展示，因此十个资金指标只显示金额数值，不重复拼接 `001/002/003` 等内部编号。
5. **产品明细**：保持全局统一表格——货品（快照优先 + 颜色·单位 + 客户型号）/数量/单价/折扣/金额（可读订单币种名称）/备注。
6. **驳回记录卡**（仅已驳回）：原因 + 驳回人 + 时间。
7. **底栏双决策**：
   - **驳回**（danger）：原因必填（≤500 字），弹窗内联校验；决策落点保持已审核与现有预留并把任务转给归属销售，订单进入「已驳回」Tab。创建新出货随即被禁止。
   - **确认通过**（primary）：备注选填；确认后放行计划部并通知计划员接手物料分析。服务端不允许对“仍处于本次驳回、尚未修订”的订单直接确认，必须先由销售完成受控修订并重新审核，避免财务绕过整改闭环。
   - 处理中底栏常驻进度条（防连点），成功/失败走顶部通知；完成后返回列表并刷新。

## 3.1 销售侧驳回修订闭环

1. 驳回事务悲观锁定订单，保存审核人、业务发生时间和原因；并发确认/异原因重复驳回不能互相覆盖。
2. 归属销售在工作台“销售管理”和 Sales Hub“订单进度查询”看到同一未解决角标；看板行显示红色「财务已驳回」及原因。
3. 通知中心保留记录，顶部提示仍会滑入；同时出现无计时的居中强提醒。遮罩和系统返回键不能关闭，员工必须点“关闭”或“查看订单并修改”。关闭只确认已看到，不清业务角标。
4. 详情页和进度详情页均提供“修改订单”。保存前服务端确认无发货/退货/核销、排产/完工、活动计划分摊或仓库作业；随后释放预留、按订单行 UUID 原位/软版本修订并回草稿。
5. 草稿重新销售审核后重建预留、清当前驳回标志并重新投递财务待确认；最后由财务确认。最近一次驳回原因/人员/时间仍保留在进度时间线，不能因当前状态清除而伪造“从未驳回”。

### 币种展示规则

- `currencyId` UUID 用于接口关联、同币种校验和审计；`code` 只作旧业务编号、兼容和检索，
  不是关系键。`001/002/003` 不是金额序号。
- 任务卡、订单信息卡和专门的币别列优先显示主档名称；缺名称时只允许回退可读标准代码。
- 金额字段与币种语义分层：资金汇总格只显示数值，币种名称在订单信息或专门币别列显示，不把内部编号
  紧贴在每一个金额前。

## 四、后端端点（`SalesOrderFinanceConfirmController`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sales/orders/finance-confirmation/pending?rejected=&keyword=` | 待确认列表；`rejected` 缺省=仅未驳回，`true`=仅已驳回，`all`=全部；`keyword` 搜单号/客户/业务员 |
| GET | `/api/sales/orders/finance-confirmation/count` | 徽标计数（只含未驳回可办件） |
| GET | `/api/sales/orders/{id}/finance-confirmation/review` | 审核详情（订单 + 明细 + 客户财务快照） |
| PUT | `/api/sales/orders/{id}` | 普通草稿更新；若为当前财务驳回的已审核订单，则进入受控修订并安全回草稿 |
| POST | `/api/sales/orders/{id}/approve` | 草稿销售审核；驳回修订稿重建预留并重新进入财务待确认 |
| POST | `/api/sales/orders/{id}/finance-confirmation` | 确认（remark 选填；幂等；未修订驳回单禁止直接确认） |
| POST | `/api/sales/orders/finance-confirmation/batch` | 原子批量确认（1–100 个 orderId，共同 remark；任一失败整批回滚） |
| POST | `/api/sales/orders/{id}/finance-confirmation/reject` | 驳回（reason 必填；通知归属销售） |

金额口径：`sales_order_finance:view` 持有者可见订单原币金额与明细价格——与 V294 待确认列表下发 `totalOriginal` 同口径（财务确认必须核对金额）。该视图不授予销售端写操作。

## 五、通知链

- 销售审核 → `SALES_ORDER_PENDING_FINANCE_CONFIRM` → 财务确认人池（直达列表页）。
- 财务确认 → `SALES_ORDER_FINANCE_CONFIRMED` → 计划员接手物料分析。
- 财务驳回 → `SALES_ORDER_FINANCE_REJECTED` → 归属销售（`source_event`、审核人、业务时间、原因与订单深链齐全，priority=urgent）。
- 销售修订回草稿 → 业务角标仍保留；重新销售审核 → 新一轮 `SALES_ORDER_PENDING_FINANCE_CONFIRM`，财务角标重新出现。
- 均走 business_outbox 旁路（提交后投递，不阻断业务事务）。

强提醒的每用户 `popup_acknowledged_at` 与 `read_at` 分开：员工离线时事件仍可靠落库，登录后补弹；关闭居中窗不自动把通知标成已读，也不改变订单状态。
