# 新建报销页(V608 起与编辑合并)

> 路由：`/expense/new`(新建)、`/expense/:id/edit`(编辑 DRAFT/REJECTED)
> · 实现源：`lib/features/expense/pages/expense_claim_edit_page.dart`(旧 `expense_new_page.dart` 已退役)

## 一、定位

员工先保存申请，再到详情补齐原件和票据，最后提交。`claimId` 为空为新建；非空为编辑，
仅本人 DRAFT / REJECTED 可操作。完整操作见[报销 SOP](../07-业务链路/员工报销全链路-SOP.md)。

## 二、表单结构(表单页口径：UtenContentContainer.narrow)

1. **驳回横幅**：编辑 REJECTED 时显示驳回人、原因及修订指引，保存后仍需在详情重新提交。
2. **身份与制度**：当前员工、部门、业务日期预填，展示财务配置的公司抬头、税号和提交说明。
   **表头卡**填写报销标题和事由说明；无登记票据时说明凭证类型及报销依据。
3. **明细区**：`添加`按钮弹 `ExpenseItemDialog`(类别 ChoiceChip/金额/日期/说明)；
   用途说明必填且最多500字，行卡点击可改、右侧 ✕ 删除。
4. **合计卡**：小写(tabular)+ **人民币大写**(`rmbCapital`，银发〔1997〕393 号口径，
   与打印报销单同款)。
5. **发票提示卡**：引导「保存草稿 → 详情页上传发票影像并登记票面要素(支持图片识别)→ 提交」。

右下使用 `UtenFloatingActionGroup`：新建只有“保存并补充凭证”，编辑为“保存”。
新建页不直接调用提交接口，避免先提交后补材料。空明细不可保存；网络动作置忙并防连点。

## 三、保存与提交语义(V608)

- 新建：`POST /expense-claims` 创建 DRAFT，成功进入详情上传凭证；此时尚未进入审核队列。
- 编辑：`PUT /expense-claims/{id}` 携带 `expectedVersion`，明细整组替换、合计服务端重算，成功回详情。
  REJECTED 编辑保存后**仍是 REJECTED**，由详情页「重新提交」清驳回痕迹并重新通知审批人。
- 校验覆盖类别白名单、金额两位小数且 >0、合计 >0、标题长度；提交时另校验明细日期、用途和凭证。
  冲突时提示刷新后重新核对，不能自动重放写请求。
- UI金额及合计上限为9,999,999,999.99元，按整数分解析与汇总，避免极大浮点数丢失分位。

## 四、权限

`expense:apply` 保护两个路由。创建从当前有效员工生成身份；编辑必须是本人且状态可编辑，
不能由客户端指定任意申请人。附件能力还受独立附件权限保护。
