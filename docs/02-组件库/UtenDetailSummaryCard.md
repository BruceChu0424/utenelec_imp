# UtenDetailSummaryCard

单据详情的只读摘要容器。调用页面提供真实的单号、状态、金额、按单位分组数量、来源和审计字段；组件只组织呈现，不计算或合并业务数据。

- `heading`与`status`常显；窄栏和大字时上下排列，完整换行。
- `primary`保留办理前必须核对的主要事实；`facts`保留常用字段。
- `details`为次要信息，默认折叠。`expanded`可由页面控制；`onExpandedChanged`沿用页面回调。
- `notices`始终显示，承载风险提示、失败恢复和仍需操作的控件。需要一直保留的输入或动作应放在此处，而不是折叠区域。

卡片圆角和字形使用主题角色，间距取`UtenSpacing`。展开按钮桌面采用紧凑36角色，触控宽高至少48窗口像素；缩小档按`UtenControlMetrics`补偿。标签可以自然换行，按钮没有固定最大高度。

`UtenSummaryFacts`按实际可用宽度和系统字形比例排列。`UtenSummaryField`在窄于默认事实宽度角色220（随系统字形比例调整）时采用标签在上、值在下，避免160逻辑宽画布把原始金额挤成两字一行。正常宽度可采用标签和值同行；值保持全文、等宽数字，不缩字或省略。`selectable`保留文本选择。

空或未知值显示`—`，权限遮罩`***`原样显示；金额精度、币种、单位、数量分组和来源版本由调用页面或原有格式化器负责。组件不会把缺失值改为0，不跨单位相加，也不增加权限或命令。

`FinancePartySnapshotCard`的嵌入呈现复用上述字段网格：服务端余额、可用预收/贷项、正负净额、其它币种、原币未核实和超额警示保留原规则；`footer`不随次要额度信息折叠而消失。

不同单据应采用基于真实单据身份的key，或由页面显式维护展开状态，避免把上一张单据的展开状态当作当前数据。

相关测试：`test/components/uten_detail_summary_card_test.dart`、`test/features/finance/finance_party_snapshot_card_test.dart`。除原有折叠、身份、金额和余额用例，压力场景包含整体200%叠加系统200%、320小屏、640短窗和85%触控；通过真实点击验证展开/折叠、48目标及警示/底部动作回调，保留原始精确字符串与数量单位。
