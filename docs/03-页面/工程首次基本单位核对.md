# 工程首次基本单位核对

物料分析发现缺基本单位、颜色或 BOM 结构问题时，一次返回完整问题清单。普通错误提示只显示摘要，问题清单使用有界列表承载全部问题，可多选或全选转工程任务。同一修复目标的重复转发复用未完成任务，保留需求 UUID、BOM 父件和组件、原因、来源及等待人；批量转发在同一事务提交，任一目标失败整批回滚。

问题需求留在原页，其它需求可单独分析。手工需求同一编号属于同一分析，因此同编号各行一起等待修复，其它编号及销售需求仍可继续。原页可见且仍有问题时，每 45 秒重新读取真实问题；从工程或其它子页返回时也重新检查。隐藏页不轮询问题，重复请求合并，旧身份响应不回写。正式分析、确认和下达继续由服务端校验，界面筛选不能绕过资料问题。

## 工程办理

工程任务区分 BOM 结构问题与货品资料问题。点击结构任务打开对应货品 BOM；点击缺基本单位的资料任务，在具有有效 `rd_task:view`、`goods:view`、`goods:edit`、`unit:view` 权限及任务、货品对象写范围时，可进入首次基本单位核对。没有额外的部门门槛，也不自动增加权限。

核对框先对当前任务预检，已有数量事实或原历史单位已停用、删除时显示原因并禁用确认。预检只在打开单任务时检查数量来源，不对列表逐行扫描。单位和核对依据由办理人对照原始资料明确填写，不预选单位；加载失败可原位重试。

首次核对只允许原 `unit_id` 为空且除了 BOM 外不存在任何数量来源记录的货品。来源清单复用 `fn_goods_quantity_reference_sources()`，包含取消、红冲、软删及零数量的历史行；不存在自行过滤历史记录的旁路。原历史单位编号保留；已有 UUID 桥接(包括软删单位)时必须一致，未桥接时仍须明确人工证据。已有非空单位及任何 BOM 外数量事实不能借此更换或猜补单位，需按原始单据受控核对或纠正 BOM 货品映射。

服务端按任务、货品顺序取锁，复核任务归属与原货品领域写范围；单位及旧桥接行取共享锁，防止核对时被停用或删除。首次赋单位同时增加货品 `version`，旧详情编辑必须重新读取。单位决定写入任务的不可变结构回执及既有审计链；相同请求丢回执后可重放，不受字典改名、后续停用或其它转发人修改任务影响。

单位核对后仍有颜色等独立资料问题时，任务保持进行中，不发完整办结事件；全部主档问题清除后才完成。普通“标记完成”也会在锁后重新核对资料，不能仅改状态掩盖问题。核对、任务状态、版本和审计同事务提交，失败或回滚不留下部分决定，不改写任何历史数量、换算率、库存或供需来源。

源码迁移为 V881，基于 V675/ADR-106 的按需数量引用守卫扩展专用核对入口；未恢复 V498 已退役的粘性列和引用写入触发器。源码与隔离测试不代表公司数据库已升级。
