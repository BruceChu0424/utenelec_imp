## 一、当前员工主流程

```text
任务中心选择销售订单产品（可跨页，合计最多 500 项）
  → 新建物料分析 / 联合分析所选 N 项
  → 初始只看缺料，搜索或切换待确认路线 / 全部 BOM
  → 逐路径明确采用采购 / 委外 / 自制路线
  → 只勾选当前可执行节点
      ├─ 提交采购需求
      ├─ 提交委外需求
      └─ 下层齐套后安排自制生产
  → 对 MAKE / 根产品逐张填写生产计划
  → 汇总核对并提交审批
  → 批准后才形成 READY、完整预留、DRAW 和销售分摊
  → 仓库发料 → 报工 → 成品入库 → 分批发运
```

任务中心不再并列显示“物料分析”和“进入分析并生成计划”。进入分析只持久化或刷新分析上下文，不代表已经生成生产计划、采购单或委外单。

## 二、多产品 BOM 与适老化合同

- 完整 BOM 数据始终可达，初始默认“只看缺料”；搜索命中子节点时保留祖先上下文。
- 页面分别显示“筛选命中 X / 保留上级后 Y / 全部 Z”，不把祖先误算成命中，也不静默丢节点。
- 当前视图的产品和分支默认展开且可分别折叠；产品结论先构建 60 项，BOM 产品组先构建 30 组，再由“继续显示下一批”增量加载。
- 只有路线已保存且当前可执行的节点显示真实复选框；未确认、未保存、MAKE 下层未齐、只读等情况显示至少 48dp 的文字状态控件。
- BUY 与 SUBCONTRACT 不以 BOM 深度作为禁用条件，但仍必须满足激活需求、真实缺口、版本、路线、权限和节点所有权门禁。
- 移动端主页面保持单一滚动区；大量已选数量在独立 bottom sheet 中惰性编辑。调度台 compact 待排列表当前一次加载 100 条，不能写成已有完整移动端分页。
- 子计划窄屏使用两行布局，整行至少 56dp；在 375px 宽度和系统字体 1.3 倍下仍须显示已报工、已入库、排产和物料齐套并可整行进入。

## 三、500 项、分批和原子性

- 分析来源的销售订单产品与手工来源合并计数，单次最多 500 项；新增、表头全选和提交使用同一上限。
- 路线确认和供给下达在客户端按稳定任务身份排序，每 500 条一批；后一批使用前一批返回的最新 `version + fingerprint`。
- 幂等键由请求前 CAS 与该批精确任务集合生成，不包含重试时可能变化的批次序号；客户端丢失成功响应后，原批重试必须命中同一结果。
- 服务端将 `actionGroupKeys` 与 `materialLineIds` 解析、合并、去重后再校验总任务数 1–500，不能分别接收 500 后组合成 1000。
- 每个 HTTP 写请求在自身事务内原子；超过 500 的多个请求是逐批提交、逐批回显，不是跨全部批次的一个数据库事务。文档不得写成“500 以上仍整批原子”。

## 四、计划向导与只读汇总单必须分开

### 4.1 生产计划向导

向导只处理可生产的 MAKE / 根产品。每个节点形成一张独立生产计划草稿，必填数量、生产部直属车间、负责人和起止日期，班组可选。批量应用默认只复制日期，不默认覆盖车间、负责人或班组，并默认只填空白项。

向导最终按车间汇总核对，确认后提交审批；普通生成不直接批准，不创建 READY、预留或 DRAW。

### 4.2 生产备料计划汇总单

“计划单预览”是只读打印/导出页面，不是向导提交页。它按自制、采购、委外三分区展示分析结果和异常，只提供打印、导出 PDF，不承担采购/委外下达或生产计划提交。

当前公司名称仍硬编码为“中山市优腾电器有限公司”，仅满足单公司候选。组织配置化、多公司抬头、编号规则和印章策略未实现，开放多公司前必须修复并 UAT。

## 五、默认车间唯一真相

- V192 `production_goods_workshop_preferences` 是默认车间建议的唯一权威；不得给 `goods` 新增 `default_workshop_department_id` 形成第二份真相。
- 向导按货品批量读取 V192 偏好；显式传入车间优先，没有偏好时进入“未分配车间”清单并由计划员补齐。
- 打开向导、拖动、取消或仅保存草稿不学习。正式计划包确认或执行段后续合法改派成功后才学习，且不回写历史执行段。
- V253 已被网站询盘迁移占用。若未来需要生产节点显式委派量或其他新结构，只能从 V254+ 追加，不得修改 V192、V234–V253 已应用迁移。

## 六、IQC、库存与计划进度

- 采购/委外收货先形成待检事实，不直接增加合格可用库存。
- 每次部分 IQC `PASS` 都只按本次合格量写入库存并立即刷新命中的活动物料分析；`FAIL` 不入可用库存。
- 只有整张 receipt 的全部明细终态后，才一次推进正式供给、reservation/DRAW 与 `WAITING → READY` 等正式计划状态，防止重复推进。
- 红冲精确反向已放行的 PASS 数量、金额和分析可用量，不删除原订单、收货或 IQC 事实。
- 生产进度分别显示：审核报工累计 `fqty`、审核成品入库累计 `iqty`、正式 V1 执行分段物料齐套。无正式包、legacy V0 和数据异常必须分别显示，不能统一当作 0%。

## 七、当前溯源能力与安全边界

计划详情当前是**部分溯源投影**：已覆盖销售订单、DRAW/FINISHED_IN、采购申请和委外申请；尚未把申请→订单→分批收货→IQC→库存批次，以及报工→成品入库→发运完整串在同一详情中。

链路健康检查当前只覆盖四类异常：销售缺口无分析、分析未排完、计划无 DRAW、DRAW 无计划。它还没有覆盖采购/委外订单-IQC、精确供给、报工、FINISHED_IN 和发运；并且当前原生查询尚未套用统一对象级读取范围。修复权限范围、补负向测试和多角色 UAT 前，只能作为治理候选，不能对普通账号开放或作为“全链路安全”证明。
