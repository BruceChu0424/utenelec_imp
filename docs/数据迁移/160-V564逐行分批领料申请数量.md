# V564 逐行分批领料申请数量

V564 在执行段已有追加事件账中增加 `draw_item_quantities`，以原 DRAW 明细 UUID 保存本次申请的单据单位数量，不改原计划、物料需求、库存预留或 DRAW 应领数量。不新增平行库存表。

车间在领料汇总勾选物料、填写本次数量，提交后仅开放这些实际仓和数量；未选行及未申请余额留待下次申请。同一汇总行可合并多个任务，提交仍保留逐任务、逐原单行分摊。旧客户端未传 lines 时沿整批申请；新请求始终写逐行数量。前端仅展示和编辑，服务端重新核对版本、汇总指纹、归属、数量及权限。

`fn_production_draw_item_requested_qty` 返回累计已申请量，`fn_production_draw_fully_requested` 用于车间判断是否还可申请，`fn_production_draw_pending` 判断仓库本轮尚未发完的申请。仓库明细与单张/批量出库共用累计申请量减实际已发量，原应领数量仍独立保留。实际发完本次申请后退出仓库待办；再次申请会再次进入待办并触发独立可靠通知。实际物料未达到整个执行批次要求时仍不能开工；部分齐套先生产沿 ADR-078 拆出完整子批。

数据库守卫要求每个请求切片属于该执行段精确 demand/document-item 来源，数量正数、最多四位小数、累计不超过原应领量；请求事件不可改删。实际 `issued_qty` 增量不得超过累计申请量。提交不扣库存、不生成实际 ISSUE、不自动开工，未申请明细不能借同单已申请行越权出库。

历史 `draw_item_quantities IS NULL` 的整单申请按原数量解释；没有执行段关联的独立单据及已有真实出库的旧单保留原规则，不补造历史请求。该兼容不使新部分申请自动扩成全量。已出库后的反向、退料及成本仍沿既有链路。

迁移仅向前追加，不能修改 V559。升级需要同版后端与前端；回退代码前必须核对是否已经存在部分数量事件，旧版整单门禁不能安全解释新事件。已产生部分申请后采用前向修复，不能删除事件恢复旧行为。本地自动化证据记录于车间分批领退料验收页，业务库与服务升级另行验证。
