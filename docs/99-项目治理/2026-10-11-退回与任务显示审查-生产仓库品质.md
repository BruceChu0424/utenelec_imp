# 退回与任务显示审查：生产、仓库、品质及关联入口

日期：2026-10-11（用户客户端 America/Denver）。

本记录针对“单据被退回后，待办与进行中重复呈现；自动选中子分类后无法恢复全量；还有未测试出的显示问题”开展人工源码审查。先从实际路由与任务入口逐页辨别业务对象，再读页面筛选、任务模型、列表查询和徽章来源；`rg` 只用于定位，未通过批量扫描脚本自动判定页面设计。源文件快照来自当时存在大量并行修改的工作区，修复在独立 `task-return-display-audit` 工作树进行。每个已有文件的原字节另存 `baseline-files`，不覆盖其他工作的修改。

## 业务判断

1. 审批驳回、实物拒收、退料与反向冲销是不同事实。审批被退回的原订单可保留审批历史，但不应重新成为第二份可重复下单需求；仓库物理拒收或生产短收的剩余量仍应有明确处理入口。
2. 来源/作业类别决定谁办理、办理哪种实物，不因“已有状态列”全部删除。采购/委外/产成品、领料/退料、IQC/FQC、待检/待收仓等不同动作继续区分。
3. 同一列表的重复状态或进度导航不得形成不可清除的第二层筛选。能从列头清除的条件交给列头；保留状态导航时提供“全部”，徽章不能在第二层替用户默默缩小结果集。
4. 页码、关键字、类别和仓库是同一查询身份。服务端分页只拿到当页样本，不能在前端裁剪这份样本后宣称全平台没有匹配任务；旧请求也不能覆盖更新的筛选。
5. 待办、在办、历史分别表示下一步工作归属、尚未结束的作业和事实留痕。同一来源在不同角色的页面可同时成为“品质待检”和“仓库等待品质”，但红黄含义应准确；不能据此简单删除原有作业任务。

## 确定问题与实施契约

### DRAW 两个入口的不可恢复进度筛选

原 `warehouse_stock_doc_segment.dart` 和 `stock_doc_list_page.dart` 都以单选分段显示未出库/部分出库/已出完，没有“全部”；统一分段组件不允许点击已选项取消。选定后只有切换父状态才能清空。列表本身已有出库进度列，因此两个入口都删除这条重复进度导航，将进度桶移至该列头，通过现有 `StockDocFilter.issueStatus` 下推服务器；清除列头回到所选单据状态完整列表。未改变单据状态、数量、出库权限或命令。

### 仓库品质结果的隐式二级收窄

`warehouse_quality_results_page.dart` 现在用 `_QStatusSeg.all()` 表示“全部”，`_selectType` 选择来源时进入全量状态并加载；二级状态行设 `autoSelectBadge: false`。显式点不合格退回、等待结果等状态仍有效，再点全部可恢复全部来源内状态。红黄来源徽章继续报告工作量，来源仍可按既有入口偏好定位；不会再代替用户选某一品质状态。

后台 `WarehouseQualityResultService` 的统一 CASE 与详情推导按待入库切片、待登记实物退回、待检余量导出一份状态；本次未改这些权威数量。注意既有“历史记录”查询传空状态，实际是不限状态的日期查询，“全部”也不限状态；没有擅自将原历史查询改成仅终态，以免破坏存量书签/查询契约。

### 两类生产申请缺全量入口

追加用料和允许超产比例的列表现在各增加 `ALL`。后端 `ProductionMaterialIncrementService.list`、`ProductionOverproductionRateService.list` 原已支持该值，未新增状态机或变更审批逻辑；退回、批准、授权撤销的历史仍保持原状态。

### 研发分页被当作全量过滤

原研发状态/类别列桶取自当前服务端页，随后 `_applyFilters` 再裁剪当前页，却继续显示服务器总页数与“没有研发任务”。现在移除这套局部列桶/裁剪，阶段、类别、关键词统一经服务器过滤再分页。回归以第一页仅 BOM、第二页有 SAMPLE 的数据说明：选择 SAMPLE 必须直接查询服务器并从第一页取得匹配任务，而不被第一页样本限制。

### 盘点同仓旧响应覆盖新结果

`stock_count_session_page.dart` 的 `_load` 原只有仓库 ID 检查；相同仓库下旧类别、库存条件、关键词或页码可覆盖更新结果。现在每个加载请求捕获代数，并同时要求 mounted、请求代数、仓库身份当前有效后才写入行缓冲、页数据、错误或加载状态。输入缓冲和各仓草稿机制沿用原行为。
