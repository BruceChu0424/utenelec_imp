# V801 产成品实物交接批与到货登记批量命令

- 迁移：`V801__production_output_handoff_lots.sql`(本分支临时号，合并时由编排者重排；迁移头五处同步由编排者统一做)。
- 决策：[ADR-148 产成品实物交接批(同去向合单)](../99-决策记录-ADR/ADR-148-产成品实物交接批同去向合单.md)、[ADR-151 §5 入库登记单批合一](../99-决策记录-ADR/ADR-151-表单草稿回到初始值单重参数结构化契约与入库登记单批合一.md)。
- 前置：V694–V702(ADR-118 报工分账：`output_batch_id`、`is_public_output`、`is_actual_surplus`)、V547/V548(品质检查单与登记批次)、V597(先入库后质检)。
- 加 1 张表 `production_fqc_lot_decision_commands`(业务清空 CLEAR；不进审计账本，命令本身只追加)；报工明细加 1 个生成列；不加权限点；不搬迁历史单据。

## 为什么要改

一次报工按归属拆成「需求份 + 计划公共 + 实际超产」几份(ADR-118)，但仓库登记、品质、放行建单、点收、通知都把每一份当成独立实物：同一批货进同一个仓，却生成两张入库单、两个点收任务、两条通知；品质和仓库还要逐份判定/逐份点数，可以把不良记在需求份、超产份全合格，少收也可能先扣在订单那份上。采购/委外到货与产成品登记的单张页、批量页各自一套提交，批量页循环调单张命令，部分成功部分失败。详见 ADR-148 §1、ADR-151 §5。

## 迁移做了什么

1. **归属优先级唯一定义** `fn_daily_report_output_slice_rank(公共, 实际超产)`：需求 0 < 计划公共 1 < 实际超产 2(IMMUTABLE)。合格/实收按它升序分配，不良/少收按它降序扣。
2. **实物交接批身份**：
   - `fn_production_output_lot_id(报工, 产出批次, 去向, 直送需求)` = `md5('PRODUCTION-OUTPUT-LOT:'...)::uuid`(IMMUTABLE)；
   - `production_daily_report_items.output_lot_id` 生成列(STORED) = 上式(产出批次为空的行自成一批)，索引 `idx_daily_report_output_lot`；
   - 视图 `v_production_output_handoff_lots`：未删除且数量大于 0 的报工明细按 `(报工, output_lot_id)` 开窗，给出批内各份、`slice_rank`、批合计 `lot_qty`、份数 `lot_slice_count`、批内序号 `lot_position`；登记、品质、点收、车间详情共用(按报工过滤可下推)。
3. **登记整批守卫** `fn_assert_finished_arrival_whole_lot` + 延迟约束触发器 `trg_assert_finished_arrival_whole_lot`(登记明细 AFTER INSERT)：同一批送入仓库的各份(历史豁免除外)不能还有待登记的，且本事务登记的各份必须在同一个登记批次、同一个库位；否则 23514「同一批实物(同一报工、同一产出批次、送入仓库)的各份必须在同一次登记里一起登记到同一个仓库和库位, 请刷新后整批登记」。
4. **品质整批判定**：
   - 新表 `production_fqc_lot_decision_commands`(id、lot_id、来源报工、合格数、不良数、处置方式、原因、幂等键、请求指纹、所属全合格批次、创建人、时间；`(created_by, idempotency_key)` 唯一；数量/处置/原因/键/指纹检查约束)；只追加守卫 `fn_guard_production_fqc_append_only`；
   - `production_fqc_decision_events.lot_command_id` 外键 + 索引；
   - BEFORE INSERT 守卫 `fn_guard_production_fqc_lot_decision_event`：整批命令的事件必须落在本批自己的各份上；不带命令的逐份决定，若该批还有多于一份未取消的待检任务则拒绝(「这批实物分成了需求、计划公共备货或实际超产几份, 请按整批判定合格与不良数量, 不要逐份判定」)；
   - 延迟约束 `fn_assert_production_fqc_lot_decision`：按命令前各份待判数量重算瀑布(合格升序、不良降序)，必须与写下的逐份事件一致，合格 + 不良守恒；同一命令放行的合格行按「登记批次 x 生产计划」必须在同一张成品入库单里(不跨计划合单)。
5. **到货登记批量命令**：`warehouse_arrival_registration_commands` 加 `batch_idempotency_key varchar(128)`、`batch_request_hash char(64)`(成对出现的检查约束 + 索引)；按锚点修补 `fn_guard_warehouse_arrival_registration_command`，批量键与批量指纹和命令身份一样不可改。
6. **业务清空**：`business_data_reset()` 按锚点在 `('stock_movements','CLEAR')` 之后补 `('production_fqc_lot_decision_commands','CLEAR')`，与 `server/ops/reset_business_data.sql`、`BusinessDataResetSqlContractTest` 运行期扩展清单同步。
7. **自制子件直接来源容量只数直接来源**：按锚点修补 `fn_assert_preplan_direct_make_exact_peg`，「直接 MAKE 来源不超过子件与父物料数量」的合计加 `peg.make_public_claim_id IS NULL`。一批一张单后，自制子件的需求份(直接来源)与被别的分析认领的计划公共份(公共认领来源)在同一事务落进同一张入库单；守卫原来把同计划的公共认领也算成直接来源，以前两份分两张单、两个事务才没暴露。服务端分配 `directMakeCapacity` 一直只数直接来源，守卫与它同一口径(`MakePublicSupplyEndToEndTest` 两条用例覆盖)。

## 服务层与前端同步

- 产成品登记：`ProductionFinishedArrivalRegistrationService.batchRegister` 只收 `lots[]`，按「报工 x 实际仓」分组展开到各份；单张 `GET/POST /arrival-registrations/{reportId}` 删除。
- 品质：`POST /production/quality-inspections/lots/{lotId}/decisions`、`GET /lots/{lotId}`；检查单详情带 `lots[]`；全合格按批展开；单份接口只用于单份批。
- 放行：`ProductionFinishedInboundReleasePort.createReleasedDrafts(List)` 一次合单，领料关联与通知每张单一次。
- 点收：`FinishedInboundConfirmRequest.lots[{lotId, acceptedQty}]`；单据详情 `finishedLots[]`；多行成品入库单红冲后进先出逐行撤回并逐行核对成本撤回守卫。
- 报工详情：`outputBatches[]`(批次、去向组、拆分、摘要)；前端删 `routeSummary`、`productionDailyReportInputGroups`。
- 到货：`POST /warehouse/inbound/arrivals/batch`、`GET /warehouse/inbound/expectations/by-ids`；单张 `POST /warehouse/inbound/arrivals` 删除。
- 前端页面合并见 ADR-151 §5。
