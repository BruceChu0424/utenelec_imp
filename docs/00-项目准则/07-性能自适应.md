# 性能自适应规范

> 当前实现采用 lite / standard / rich 三档，并允许用户手动覆盖。本文只描述已经落地的探测和降级；最后核对：2026-07-30。

---

## 一、源码入口

| 职责 | 源码 |
|---|---|
| 档位与能力扩展 | [`performance_tier.dart`](../../lib/core/performance/performance_tier.dart) |
| 设备能力探测和评分 | [`device_scorer.dart`](../../lib/core/performance/device_scorer.dart) |
| 推荐档位 Provider | [`shared_providers.dart`](../../lib/shared/providers/shared_providers.dart) |
| 当前有效档位和偏好持久化 | [`performance_provider.dart`](../../lib/shared/providers/performance_provider.dart) |
| 设置 UI | [`uten_performance_switcher.dart`](../../lib/components/settings/uten_performance_switcher.dart) |

组件统一读取 `performanceProvider`。不存在旧名称 `performanceTierProvider` 或 `PerfTierScope`。

---

## 二、档位

| 档位 | 目的 | 能力开关 |
|---|---|---|
| `lite` | 旧移动设备、省电偏好 | blur 关、stagger 关、skeleton shimmer 关、Hero 关、时长因子 0.5 |
| `standard` | 默认移动端与 Web | stagger/skeleton/Hero 可开，blur 关 |
| `rich` | 桌面或用户强制 | 上述能力开启，blur 开 |

`PerformanceTierValue` 提供 `enableBlur`、`enableStagger`、`enableSkeletonShimmer`、`enableNumberAnimation`、`enableHero`、`durationFactor`。这些是能力策略，不代表每项都有现成公共组件；例如当前没有数字滚动组件。

---

## 三、自动评分的真实边界

启动时 `DeviceProbe` 只采集平台、Android SDK、iOS 系统版本和桌面/Web 分类。当前评分：

| 平台 | 推荐档 |
|---|---|
| Windows/macOS/Linux | rich |
| Web | standard |
| Android API < 26 | lite |
| Android API ≥ 26 | standard |
| iOS < 14 | lite |
| iOS ≥ 14 | standard |
| 未识别平台 | standard |

当前没有可靠读取 Android 内存，也没有实现温度、电量、实时帧率或运行期自动升降档。文档、测试和产品说明不得声称这些能力已存在。

探测结果在 `deviceCapabilityProvider` 中异步产生；完成前 `performanceProvider` 保守使用 standard，完成后因 Riverpod 依赖自动重算。

---

## 四、用户覆盖

`PerformancePreference` 支持：

- `auto`：采用设备推荐；
- `lite`：强制省电；
- `standard`：强制标准；
- `rich`：强制极致。

偏好保存到本地 `SharedPreferences` 的 `performancePreference`。用户强制选择优先于自动推荐。该偏好不应承载业务数据或敏感信息。

## 五、已经落地的降级

| 组件 | lite | standard | rich |
|---|---|---|---|
| `UtenCard(variant: glass)` | solid | solid | `BackdropFilter` blur |
| `UtenSkeleton` | 静态表面块，controller 停止 | 明暗循环 | 明暗循环 |
| `UtenCenterAlert` | 使用压缩/简化时序 | 标准 | 标准 |

其余动画是否降级由调用方显式读取 `performanceProvider`。不能仅在文档中列出能力而没有源码或测试。

## 六、大数据性能不由 UI 档位解决

性能档只能降低渲染成本，不能弥补错误的数据访问。十几年数据场景仍必须：

1. 后端稳定排序、过滤和分页，页大小有上限。
2. 高频查询有匹配索引，并用真实量级 `EXPLAIN (ANALYZE, BUFFERS)` 验证。
3. 避免 N+1、超大 JSON、前端全量排序和一次性渲染全部记录。
4. 导出、汇总、物化视图刷新等重任务与交互请求分离，并有超时/并发边界。
5. 图片、PDF 和附件按需加载，不把二进制塞进列表接口。

`UtenPagedGrid`、`MasterDataTableView` 等只是前端承载方式；接口是否真正分页仍以网络请求和后端查询为准。

## 七、新增高成本效果

新增 `BackdropFilter`、shader、大面积透明叠层、无限循环动画或复杂图表前必须：

- 说明业务价值和降级表现；
- 在父容器约束下测量，而不是只看高端开发机；
- 读取 `performanceProvider`，至少为 lite 提供无动画/无 blur 路径；
- 页面离开后停止 ticker、Timer、订阅和后台计算；
- `Offstage` 只隐藏并保活子树，不会自动停止 ticker 或排除焦点；保活页必须用有效祖先值合并后的 `TickerMode` 停止隐藏动画，并用 `ExcludeFocus` 阻止隐藏页继续获取键盘焦点；
- `UtenSkeleton` 的 shimmer 必须同时服从 `TickerMode`、系统 `MediaQuery.disableAnimations` 与 `performanceProvider` lite 档。任一禁用时停止 `AnimationController.repeat`，恢复允许后可从原位置继续；
- 增加必要测试并在 DevTools 检查帧耗时与内存。

如果没有显著价值，优先使用静态颜色、边框和即时状态变化。

## 八、提交前检查

- [ ] 使用真实 `performanceProvider`，没有旧 Provider 名称。
- [ ] lite 路径无 blur 和不必要循环动画。
- [ ] 用户手动覆盖后组件立即响应。
- [ ] 控制器、Timer、订阅和图片资源按生命周期释放。
- [ ] 长列表由服务端分页，前端没有全量拉取。
- [ ] 性能声明有源码、测试或量化证据，不把规划写成现状。
