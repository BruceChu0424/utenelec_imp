# V742 公共 AI 平台与销售客户文件识别、主档学习、报价财务核价(ADR-133 / ADR-134)

- 日期: 2026-09-27; 迁移 `V742__ai_platform_sales_intake_learning.sql`; 设计见 ADR-133(公共 AI 平台)与 ADR-134(销售客户文件识别、主档学习与报价财务核价)。
- 版本号是临时号: Flyway 不允许乱序(outOfOrder=false), 本分支目录跳过 V736、V737、V739、V740(并行会话在途号), 那些号先落地时本迁移顺延为「磁盘最大号 + 2」(V741 的下一个)。改号清单: 迁移文件名与头注释、孪生补丁失败文案 `V742 cannot extend ...`、ops 脚本 `(742, N)` 白名单/PRESERVE 计数闸 `>= 742 → 104`/`required` 六行的版本号/头行、`BusinessDataResetSqlContractTest` 的 CLEAR/PRESERVE 扩展版本与两个清库契约测试的字面版本对、`AuditTriggerCoverageMigrationContractTest` 与迁移演练里写死的版本、本页与迁移索引的编号和头行; 已按临时号迁移过的克隆库须重新克隆。当前头以[迁移索引](README.md)为准。

## 背景

2026-09-27 用户要求: 新建报价单/订货单时上传客户自己的报价单或形式发票(格式各不相同, 货品多为英文, 也有其他语言), 由系统对应到我们的货品资料; 价格不能改, 按文件单价算折扣, 自动填表头与货品明细; 用户确认保存后学习客户的叫法(货品英文名、客户资料), 上传越多资料越完整; AI 先调用第三方接口、以后换本机部署, 服务商在系统设置里填写、能测试连接、密钥加密显示, 其他功能以后也能接入; 报价单不是最终的, 财务核价确认后才转订货单, 订货单才是最终的。

本迁移只建结构、播种与登记; 识别、匹配、学习与核价流程在服务端代码里。

## 结构

新表六张:

| 表 | 用途 | 清库 | 审计 |
| --- | --- | --- | --- |
| `ai_providers` | AI 服务商配置: 预设(DeepSeek/通义/Kimi/智谱/豆包/硅基流动/OpenAI/Claude/Gemini/Ollama/vLLM/自定义)、区域(境内/境外/本机)、协议、接口地址、模型、JSON 输出方式、关闭深度思考、图片识别、输出上限、超时、启用、默认、境外数据出境确认、最近一次测试结果 | PRESERVE | COLUMN_SCOPED(system) |
| `ai_jobs` | AI 识别任务队列: 状态/阶段/进度/取消、参数、上传文件与指纹、结果、错误、提交人与提交时的授权戳、调用次数、租约、使用去向 | CLEAR | NONE(queue) |
| `ai_call_logs` | 每次 AI 调用一行技术记录: 用途、服务商、模型、成败、HTTP 状态、token、耗时 | CLEAR | NONE(technical) |
| `client_goods_aliases` | 客户货品对照: 客户(空 = 全局)的型号/品名 → 我们的货品, 带上下文、确认次数与明确选择次数 | PRESERVE | NONE(preference) |
| `sales_intake_layouts` | 客户文件版式: 表头指纹(+客户) → 列角色 | PRESERVE | NONE(preference) |
| `sales_quote_revision_logs` | 报价核价修订记录: 提交/撤回/财务修改/退回/确认/重新打开, 带明细快照, 只追加 | CLEAR | NONE(ledger) |

要点:

- `ai_providers.secret` 只存 SecretCipher 密文(AES-256-GCM, AAD 绑定服务商 id), 接口从不返回明文; `api_key_last4` 只在密钥长度 >= 20 时保存且必须伴随密文。名称大小写不敏感唯一; 至多一个默认服务商(部分唯一索引)。境外服务商必须带数据出境确认时间(`ck_ai_providers_overseas_ack`)。
- `ai_jobs` 进入成功/失败/取消的同一条更新必须清空上传文件(`ck_ai_jobs_terminal_input_released`); `input_sha256` 为 64 位小写十六进制; `submitted_auth_version`/`submitted_auth_epoch` 与 JWT 过滤器比较的 `users.auth_version`、`authorization_state.epoch` 同口径。索引: (状态, 创建时间)、(提交人, 创建时间倒序)、文件指纹。
- `ai_call_logs.provider_id` 指向服务商, 删除服务商时置空; 不存提示词、回复与密钥。
- 货品 `goods.name_en`(英文名称)+`name_en_source`(MANUAL 人工维护 / LEARNED 从客户文件学习), 客户 `clients.name_en`(外文名称)。新增两个货品索引: `idx_goods_name_en_trgm`(英文名三元组相似召回)与 `idx_goods_model_norm`(型号 NFKC、去空白、大写后的精确匹配)。中文名称候选沿用既有 `idx_goods_where_used_search_trgm`, 中文相似度在 Java 里按字二元组计算。
- `client_goods_aliases` 唯一键 `(client_id, alias_kind, alias_norm, context_norm, goods_id)` 为 NULLS NOT DISTINCT(全局对照 client_id 为空也只一行), 这把唯一索引同时服务前缀查询, 不另建重复索引; 全局对照按「不同客户数」重算可信度时要按 (种类, 叫法, 货品) 查客户对照行, 以 `client_id` 打头的唯一索引服务不了, 另建部分索引 `idx_client_goods_aliases_global_evidence (alias_kind, alias_norm, goods_id) WHERE client_id IS NOT NULL`(前缀不同, 不是重复索引); 来源单据只记 id 不建外键(单据属清空数据, 保留表不能引用清空表)。
- 报价明细 `sales_quote_items` 增加折扣(0 < 折扣 <= 1, 默认 1)、单价来源(MASTER 货品售价 / FINANCE 财务核价设定, 后者必须带设定时间)、设定人与时间、文件型号、文件品名、文件单价; 订货明细 `sales_order_items` 增加文件品名与文件单价(文件型号沿用既有 `client_model`)。文件单价只作参考, 从不参与金额计算。
- 报价表头 `sales_quotes` 增加币种、业务员、交期、结算方式(与订货同一外键目标与 RESTRICT 规则)、合同号、客户文件币种、提交与财务确认/退回的人和时间、退回原因、财务备注、核价修订号; 报价与订货表头都增加客户文件币种 `client_file_currency`。
- 报价状态新增 `2 待财务核价`, 并首次加状态 CHECK(-1/0/1/2)。`0` 为草稿(退回原因非空即「财务退回待修改」), `1` 为财务已确认(可转订货单), `-1` 作废; 存量状态 1 的报价视为已确认。

播种: 历史订货明细上非空的客户型号(`sales_order_items.client_model`)按「客户 + 规范化型号 + 货品」合并为该客户的 PART_NO 对照, 确认次数 = 订单数, 明确选择次数 0, 上下文为空串, 首末确认时间取订单日期(上海时区零点), 原文取最近一张订单的写法, 来源记为最近一张订单。只取未删除、未作废的订单与明细, 未删除的客户与非占位货品; 不播种全局对照。规范化表达式与 Java normalizePart 同口径(NFKC、全角斜杠与各种横线统一、去全部空白、大写、去掉末尾一个句点), 由单元测试对拍; 重跑按唯一键跳过。

权限:

- 新增 `sales_quote_finance:view`(查看销售报价核价任务, 财税管理/报价核价)与 `sales_quote_finance:confirm`(销售报价财务核价, 审批类, 高危), 回填给当前持有 `sales_order_finance:confirm` 的部门; 新增页面权限面 `finance.sales-quote-review`(销售报价核价)挂这两个码, 钱流首页面 `finance.hub` 挂查看码。
- 新增 `ai:use`(使用 AI 识别客户文件, 销售管理/AI 识别, 执行类)与 `goods:name_en:edit`(维护货品英文名称, 基础资料/货品资料), 回填给持有 `sales_order:create` 或 `sales_quote:create` 的部门; 两码挂在销售报价、销售订货页面权限面上, 英文名称码另挂货品资料面。没有 `ai:use` 时识别只走固定规则, 不调用 AI。
- 退役 `sales_quote:approve`: 报价不再由销售审核, 改为提交财务核价、财务确认。先删页面权限面映射, 部门授权/个人覆盖/委派随外键级联删除。
- AI 服务设置不新增权限码, 沿用 `authorization:manage` + 超级管理员。

- 清库策略: 孪生函数 `business_data_reset()` 用 V686/V693 锚点补丁一次插入六行, 锚点缺失或不唯一报 `V742 cannot extend business-data reset policy safely`; ops 脚本新增按存在性登记的六行(V741 目录上六张表都不存在)、`required` 版本登记六行(三张清空表同时进入清空计数恒等式)、PRESERVE 计数闸 `>= 742 → 104`; `BusinessDataResetSqlContractTest` 的 CLEAR/PRESERVE 扩展登记各三张。

- 迁移头: README 头行 V742/667、ops 白名单 `(741, 666)`、`(742, 667)` 与异常文案上界(V736、V737、V739、V740 跳号)、两个清库契约测试的字面版本对(2026-09-27 合并 main 后按磁盘 667 个迁移文件核对更正)。

## 兼容与数据

- 只加表、加列(全部可空或带默认)、加索引、加 CHECK 与播种; 不改任何既有数据。报价明细折扣默认 1、单价来源默认 MASTER, 存量报价金额不变。
- 状态 CHECK 只允许 -1/0/1/2: 老库报价为 0 行, 新系统只写这四个值。
- `sales_monthly_mv` 的报价分支(V137)按 `status = 1` 汇总本币金额, 状态 1 的含义(已确认)不变, 本迁移不重建物化视图。
- 旧应用连接 V742 库: 新列可空或有默认, 旧代码读写不受影响; 但 `sales_quote:approve` 已删除, 旧应用的报价审核按钮会因无权限而不可用, 因此 V742 与新版应用一起发布。
- 主机侧: 新的可选环境变量 `UTEN_SECRET_CIPHER_KEY`(未配置时由现有 HMAC 密钥派生; 云端与本地必须相同)与 `UTEN_AI_*` 开关随应用配置发布; 各服务器 `server.env` 里旧的政策情报变量的清理作为发布后的运维步骤单独执行并记录(步骤见 [V741 说明「运维步骤」](259-V741政策情报AI退役.md#运维步骤发布后-主机侧))。
- 业务上线前提(ADR-134): 客户资料必须已分配负责人, 否则业务员看不到任何客户, 识别只会提示「你名下还没有客户资料」。
- 客户货品对照的两个计数列按行的范围有两种口径(列注释已写明): 客户行按保存的单据累计, 全局行(`client_id` 为空)由服务端按「不同客户数」重算(见 ADR-134 §五、[实体字典](../04-数据模型/实体字典.md))。
