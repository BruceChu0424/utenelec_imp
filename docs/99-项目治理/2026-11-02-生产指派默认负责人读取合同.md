# 生产指派默认负责人读取合同

## 根因与业务权威

人员引用迁移后，通用部门树只返回 `id/code/name/level/parentId/children` 六个字段。物料主表和补供弹窗仍从该树读取 `managerId/managerName`，导致没有有效货品负责人学习记忆时丢失原车间负责人预填。原 `/production/material-analyses/default-workshops` 只返回有有效货品归属的学习记录，不能覆盖没有学习记录后手选车间的情况。

保留六字段部门树和原五字段货品学习接口；不恢复 HR/部门管理读取权限。新增的生产业务读取由服务端提供当前可指派的负责人，最终提交仍由原生产指派校验器复核，不把预填当作已派工事实。

## 专用读取

`GET /api/production/workshop-assignment-defaults?purpose=PRODUCTION_MATERIAL_OWNER&ids=<车间UUID列表>`。

- 仅接受 `PRODUCTION_MATERIAL_OWNER`、`PRODUCTION_PLAN_OWNER`、`PRODUCTION_SEGMENT_OWNER`；复用 `BusinessEmployeeReferenceAuthorizationPort` 对应原 purpose 的 AND/OR 权限与最新在岗账号校验，不新增权限码，不接受访客、首登待改密或失效员工身份。
- 每次服务端请求限制 1–200 个真实 UUID；客户端稳定排序、100 个分批，最多四个并发、每块一次、10 秒截止，共用取消令牌。旧货品学习读取与新读取复用同一有界调度入口。
- 每行只有 `departmentId/departmentName/responsibleEmployeeId/responsibleEmployeeName`。只返回请求中的未删除生产部直属车间；负责人须未删除、在职或试用且属于该车间组织范围。负责人没有登录账号不影响其业务身份；不合格时两项负责人字段均为空。
- 默认读取和实际保存共用 `ProductionAssignmentValidator` 的员工状态与组织范围判定。旧货品学习接口的响应、条件和既有客户端保持原样。
- 新读取使用 `native_workshop_tasks` 发布围栏，部门负责人、员工生命周期/归属以及调用人授权变化都会使旧结果失效；GET 不推进业务写修订号。

## 完整调用方核对

| 入口 | 实际变化与保留语义 |
| --- | --- |
| 物料主表 `_fetchTableAssignmentDefaults` / `_tableWorkerFor` | 最小部门字典、货品学习记录和专用负责人默认值合批发布；已下达事实、手选草稿、与本次车间一致的学习负责人优先，之后才用服务端当前合格负责人；都没有则手选。 |
| 原计划补供 `MaterialPriorityReplenishmentDialog._pickWorkshop` | 选定车间后按物料指派 purpose 读取默认负责人；新增请求代次与原 owner 校验，旧车间/旧身份返回不能改写新选择。 |
| `productionWorkshopTreeProvider` | 改为会话共享最小部门字典，保留原逻辑缓存键和写后失效；计划编辑、执行段改派、车间任务筛选和补供调用同一入口。计划与执行段原先没有经理自动预填，不额外增加该行为。 |
| `productionWorkforceTreeProvider` | 日报的生产层级也从同一最小字典构造；不复制或携带部门管理字段，人员选择仍使用对应的原业务 purpose。 |
| `ProductionPlanSummarySheetPage.defaultWorkshops` | 只消费旧货品学习的车间名称，保持不变。 |
| 部门管理页/部门编辑弹窗 | `managerId/name` 来自其本身受权的部门详情，不来自人员引用最小树；保留原管理权限和流程，不混入本专用接口。 |

Web 与 Flutter 桌面共用上述 Dart 入口。WPF 的完整生产指派仍未迁移，不开放写入口或更新其任务为已完成；未来接入须按同一 purpose、四字段响应和发布围栏实现，不把部门管理字段塞入通用树。

## 验证边界

本候选的本地仓库合同用例验证稳定排序、100 个分批、四并发、单次读取、旧货品响应兼容、无额外部门结果以及拒绝无关 purpose；Java 用例验证默认人与实际保存共用员工状态/组织规则和精确读范围路由。新增真实 PostgreSQL/HTTP 用例覆盖无货品记忆时的经理预填、六字段树、无 HR 读取、各 purpose 权限、首登生命周期和发布前撤权/经理离职围栏。

实际执行结果以本次发布证据和最终提交 CI 为准；新增 HTTP 源码、局部编译和前一轮已有测试通过，不代表新增 HTTP 用例、公司部署或 Win7 UAT 已通过。
