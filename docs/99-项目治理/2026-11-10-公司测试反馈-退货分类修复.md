# 公司测试反馈：退货选择器分类完整性

源码提交：`19c2be5c8643e6929fa2deec563390155b119ebb`；基线 `86dffb9db`。本项只在独立本地工作树实施，交给主任务审查并合入本地 main；没有推送、连接公司业务库、部署或正式打包。

## 根因与同类筛查

截图中的委外退货不是分类读取不完整：`SubcontractDocEditPage._pickerScope` 的默认分支误用了 `sellable`，公共选择器按设计整树排除原材料、辅料和历史未分类。修复前真实页面回归得到 `Expected all / Actual sellable`，原始输出见 [before-fix](evidence/company-return-picker-20261110/before-fix.txt)。

同类采购退货固定使用 `material`，又会隐藏来源收货中的成品、OEM 等货品。退货的目录范围不应重解释历史收货的货品分类；两类退货现均使用公共选择器 `all`，包括自定义及历史未分类。停用货品、虚拟货品、当前读取身份与权限仍由原选择器/API 合同处理。

上游明细引入通过 `subcontract_link_picker.dart` / `purchase_link_picker.dart` 读取真实单据来源，没有这类目录过滤，不重写其额度和归属。销售、BOM、仓库成品/材料等选择器有不同业务用途，本项未把它们全改成退货范围。

| 入口 | 新公共入口及范围 | 验证 |
|---|---|---|

删除了委外编辑页私有默认分支，独立订货页也改从同一场景策略取值。采购 provider 从无类型固定范围改为按单据类型的 family，全部两个产品调用及三个测试替换点已迁移；新增单据必须明确其范围。两个通用编辑页补齐与独立订货页相同的 `formDraftIdentityIsCurrent` 返回检查，身份退休或原行消失后的晚返回不能写回。

界面修改类型为前端选择行为，Web、Flutter Windows/桌面/移动共用这些 Dart 页面。按 `frontend-design` 保留 Uten 现有字体、主题 token、布局及公共等待/选择面板，没有新增独立说明、等待件或第二套 picker。

## 来源与业务保护

可浏览全部目录不代表可以无来源退货。`ProcurementReturnHeaderAuthority` 仍强制每一行唯一关联已审核收货明细，并由真实来源派生同一供应商、币种、汇率、税率及结算方式。退货库存、品质、可退额度、价款和锁内核对的产品代码全部保留。

既有 `ProcurementReturnHeaderAuthorityTest.absentReceiptIdentityListFailsBeforeAnyDatabaseAccess` 扩展到 PURCHASE/SUBCONTRACT 两类的 null/空/含 null 来源，均须在数据库访问前拒绝。该 Java 回归由主任务在最终集成源码执行，本分支没有把未跑 Java 写成通过。来源锁定行不能打开 picker；新增额外行不制造 upstream 身份。金额、数量原文、单位、颜色、库位和未知提交机制保持原合同。
