> 适用页面：销售订货单、采购订货单、委外订货单的新建/编辑页；
> 2026-09-27 ADR-134 增 §八之二(报价/订货「识别客户文件」)，销售报价单改为与订货同一套只读单价 + 可编辑折扣，
> 报价转入订货的折扣锁定，重复货品复核按折扣与文件单价区分(七之三)；
> 2026-09-25 增保存前重复货品复核弹窗(七之三) + 详情/审核页明细列对齐编辑页(七之四)
> + 编辑保存落点改 pop 回宿主(见 docs/05-架构/路由设计.md「返回键契约」)；
> 最后核对：2026-09-05(明细区表头体系与货品资料统一为共用组件 UtenTableColumnKit：表头设置
> 改按钮处锚定浮层勾选列表、表头纵向拖出隐藏改 root Overlay 跟手浮层(过阈值变红底红×)、
> 表头长按拎起横拖直接排序(与弹窗排序同一状态)；编辑模式操作条撤下「全选/复制选中/批量删除/
> 粘贴」常驻按钮——全选走表头复选框、复制/粘贴/删除走行级右键/长按菜单；此前 2026-09-04
> 口径：销售订货单价权威、可编辑折扣与明细表头设置、实际重量列下线、单位紧跟数量、必填列
> 锁定不可隐藏、折扣列 ⓘ 说明)。

## 一、适用边界

| 单据 | 结账/结算方式显示 | 必填 | 2026-09-03 起的位置 |
|---|---|---|---|
| 销售订货单 | 结账方式 | 是 | 单头（不变） |
| 采购订货单 | 结账方式 | 是（行级） | **明细行**（与供应商同格） |
| 委外订货单 | 结算方式 | 是（行级） | **明细行**（与委外商同格） |

采购/委外订货单的商业字段（结账/结算方式、币种、汇率、税率）自 2026-09-03 起全部
**下移明细行**（ADR-068）：单头不再展示；多选行可「统一设置条款」一次写全套；
保存按「供应商+条款组合」自动拆单，每组条款归集到该张单头（下游收货/退货/应付
仍读单头快照，完全兼容）。销售订货单维持单头口径，本规范的必填交互仍适用于销售。

下游收货/退货/进仓沿用来源快照与历史兼容（单头快照即行条款归集结果），不因本规范新增必填。

2026-09-27 ADR-134：销售报价单表头新增币种、业务员、交期、结账方式(报价上选填，财务核价时可改)、合同号，按客户切换预填的口径与订货单一致；报价与订货都新增只读参考字段「客户文件币种」(`clientFileCurrency`)。

## 二、必填交互（销售单头 + 采购/委外行级）

1. 标签使用共享必填标识，显示红色 `*`，不再把 `(必选)` 硬编码进字段名。
2. 字段/单元格启用且为空时立即显示错误色边框（行级为列头红 `*` + 单元格红字提示）。
3. 必填不提供清空选项。
4. 保存前再次校验；失败时在字段/单元格附近显示明确错误，并阻止请求体省略该字段。
5. 字典加载中、加载失败、无可用项和历史已停用项必须分别展示，不能渲染成可保存的伪空值。
6. 红色不是唯一提示；红色 `*`、边框/红字和错误文案共同表达必填。

销售使用 `UtenDropdownField(required: true)`；采购/委外行级使用
`ProcurementTermDropdownCell`（弹菜单选择格，`procurement_commercial_grid.dart`）。

## 三、人员字段

- 业务员、采购员、经办人等员工字段遵守
  [UtenEmployeePicker](../02-组件库/UtenEmployeePicker.md)。
- 已选值和弹窗主行显示 `姓名(工号)`，部门显示在下一行。
- 员工 UUID 是提交与关联权威；姓名和工号只作展示。

## 四、服务端边界

| 链路 | 当前约束 |
|---|---|
| 销售订货 | Flutter 新建/编辑与保存校验已强制；销售订单服务仍保留 nullable/历史兼容 |
| 采购订货 | 行级必填（`groupByCommercial` 逐行校验组合完整性）；单张创建/编辑运行时校验结账方式（原 `@NotNull` 于 2026-09 移入 service，`requireHeaderSettlement`）；批量拆单请求头不携带商业字段，逐行校验后按组合归集到各张单头；提交财务时再次复核 |
| 委外订货 | 同采购（行级必填 + 组合拆单归集 + `applyHeader` 结算方式必填校验） |
| 采购/委外行金额 | ADR-112(2026-09-23)起请求体**不带金额**(带 `amountOriginal/amountLocal` 直接 400)，行金额只由服务端 `MoneyPolicy.line` 按「数量×单价」「原币金额×表头汇率」精确派生，单价缺省则金额为空、汇率缺省则本币为空；背景是 2026-09-21 客户端用 double 相乘(3×0.10 = 0.30000000000000004)原样落库、送审精确比对被拒。编辑页行金额与合计条改为十进制精确乘法预览(单价未填显示「—」)，与服务端值逐位一致 |

## 五、主档默认值预填

预填不替换单据必填校验，也不覆盖用户已确认值；个人列宽/筛选仍是用户偏好，历史订单条款仍是交易快照。

1. 采购/委外 `/last-terms` 批量读 V593 货品默认供应商与供应商条款，**不再回落扫描最近订单**。客户销售条款同样只读 V592 客户主档。
2. 供应商默认结账方式必须仍启用；币种、税率仅在当前行供应商一致时参考，汇率也必须对应当前币种。主档没给才沿人民币/汇率 1/税率 0 的现行初值，用户须核对。
3. 采购价和委外加工价各自保存 V620 供应商、颜色、单位、币种、税率上下文；全部匹配且证据完整时才向空价预填。旧数值缺上下文不猜测，保留空价供人工输入。系统预填价在换货品/颜色/单位/供应商/币种/税率后重新校验，用户明确确认过的价格保持原值。
4. 普通页面查看权限不泄露商业条款或单价；读取仍要求对应单据 `price:view` 或财务全域权限。真实学习改变 goods/clients/suppliers 时同步递增主档版本，陈旧主档编辑表单须刷新。
5. 收货/退货沿上游商业快照，不用当前主档重写历史单。完整字段与迁移规则见 [V620说明](../数据迁移/210-V620主档单价上下文与记忆并发保护.md)。

## 六、批量设置（行级条款专属）

- 多选 N 行 → 操作条「统一设置条款 (N)」→ 底部面板一次写
  供应商+结账方式+币种+汇率+税率；**留空的项保持各行原值**。
- 行内点选供应商/结账方式/币种时，行处于多选选中态则联动填到所有选中行。
- 保存成功文案按拆单组合数提示（「已按供应商+条款组合拆分为 N 组…」）。

## 七、数量与备注

- **数量允许超过申请剩余量**（2026-09 超采/超委外放开）：分解预填默认剩余量，可改大；
  引入面板在订货模式下同样允许超量（收货/退货上限保留）。
- **实际重量列已下线**（2026-09-04：单位已表达重量，不再重复录入）：采购/销售/委外
  商业单据编辑网格与详情/审核列均不再展示；行模型 `weight` 字段保留，编辑既有单回填
  并随保存透传（>0 校验仅对回填值生效）。仓库过磅/生产日报等实物场景不受影响。
  **2026-09-21 补充**：委外出仓明细表(单张拣货出仓页与批量出库详情共用)按用户口径同样
  撤出实际重量录入列，原单 `weight` 降为只读透传字段，保存原样回传、不做 >0 校验；
  仓库过磅(stock)仍保留重量录入。判定钉在
  `test/features/measurement/transaction_weight_contract_test.dart`。
- **单位列紧跟数量之后**（2026-09-04 全站统一列序）。
- **每行末尾「备注」列**：随行提交 `remark`（数据库/DTO 全链路已有列），全部单据编辑页生效。

## 七之二、明细下方合计条（2026-09-11）

全部商业单据的**编辑页与详情页**明细表下方统一使用
[UtenTotalsSummaryBar](../02-组件库/UtenTotalsSummaryBar.md)，取代各页手写的
「合计 ¥…」文本：

| 合计项 | 口径 |
|---|---|
| 合计数量 | 按 `unitId` 分组，**不同单位绝不相加**（多单位显示「12 个 · 3 箱」，缺单位行落「单位未维护」桶）；实现见 `utenQuantityTotalEntry` + `groupMeasurementTotals` |
| 合计金额(币种) | 单据原币总额，**error 色标红**；币种名取自表头/行级条款（`financeCurrencyDisplayLabel`），**不硬编码 ¥**；采购/委外订货的行级条款在全单币种唯一时才标注币种 |
| 合计(本币) | 服务端 `totalLocal`；销售订单阶段按设计不落本币事实，故订单详情不出该项；值为空时整项隐藏 |

- 金额项受各页既有商务金额门控：采购/委外 `canViewCommercialAmounts`（含服务端
  `priceMasked`）、销售 `priceMasked`、申请单无金额口径 → 只剩「合计数量」。
- 编辑页合计条一律挂在 `UtenEditableGrid.footer`（网格表尾，紧跟明细内容下方——
  2026-09-14 口径：底部操作条已退役改右下悬浮组，合计不进悬浮组），数量刷新由
  `EditableGridTotalsBar`（`lib/shared/widgets/editable_grid_totals_bar.dart`）
  监听逐行数量控制器驱动——单价为 0 时金额不变，只跟金额合计会漏刷。
- 详情页合计条统一挂 `MasterDataTableView.summaryBar` 槽位（表体下方、翻页条上方，
  `compact: true`），不再悬在区块底部；销售订货编辑页同口径出 currency-aware 的
  「合计(币种)」总计文本。

## 七之三、保存前重复货品复核（2026-09-25）

销售/采购/委外订货编辑页保存时（必填校验通过后）先按各页拆单口径聚合明细查重，
发现重复货品先弹「发现( N 组)重复货品」复核弹窗，确认后才继续保存：

| 单据 | 重复判定键 |
|---|---|
| 销售订货单 | 货品+颜色+单位+换算率(2026-09-27 起再加折扣与文件单价：折扣或文件单价不同的行分开保留，不算重复，合并会丢掉其中一行的折扣/文件单价) |
| 采购订货单 | 供应商+条款组合+货品+颜色+单位+换算率 |
| 委外订货单 | 委外商+条款组合+货品+颜色+单位+换算率 |

采购/委外按「供应商+条款」拆单——不同供应商/条款的同货品行会落进不同订货单，不算重复；
销售出货/退货等带上游行引用(orderItemId)的单据不查重，合并会断上游链。

弹窗三选一（`lib/shared/widgets/order_duplicate_goods_review.dart`，三页共用）：

- **汇总合并**：同组数量相加合并为一行（`financeExactSumTexts` 十进制精确求和，不经
  double），单价等其余内容沿用组内第一行；采购/委外同时聚合来源申请明细
  （upstreamItemIds/sourceDocs/maxQty，与 V463「从上游引入」合并同口径）。
- **删除重复行**：仅当全部组各行内容完全一致（数量/单价/备注等逐项相等）时提供——
  此时删行是无损的；每组只保留第一行。数量或单价不同则不提供（删行=丢数据）。
- **返回修改**：不保存，重复行整行标红（`EditableGridRow.flagged`：errorContainer 42%
  红底，按行通知器局部重绘，宿主无需 setState；用户改动该行货品/数量/单价/供应商等
  即自动消红），下次保存重新判定。

ESC/点蒙层关闭弹窗按「返回修改」处理，绝不静默保存。采购/委外新建态只对勾选行查重
（未勾选行不进本次提交集，也不参与查重）；销售仅订货单类型触发。

## 七之四、详情/审核页明细列对齐编辑页（2026-09-25）

用户口径：单据列表点击进入的详情/审核页，其明细表的列集合与列序应与编辑页对齐，
不再多出编辑页没有的列：

- **销售订货单详情页**（即销售侧审核页面，带审核/编辑按钮）：补齐编辑页列
  （折扣/机加价/围数/进仓数量），数量后紧跟单位；履约进度列（业务链/已发/已退/
  可发/已排/已产/优先级）退役——进度看「订单进度」专页，已发/已退只保留给
  出货/退货等实物单据。
- **销售财审页**：数量后紧跟单位；客型列退役（开单不录入，审单恒为空列）；
  改量复核对比表同款列序，旧标签 加工费/周长 对齐为 机加价/围数。
- **采购/委外财审页**（共用页）：数量后紧跟单位；实际重量列退役（全站 2026-09-04
  已下线，本表是最后一处残留）。
- 单价列的「(报价 x)」后缀、金额列的动态币种名等**信息增强**保留，不算多出列。

## 八、销售订货单价、折扣与明细表头

1. 销售订货行「单价」是只读商业快照，不能在开单表格修改：普通新行取货品主档售价；报价转单
   取财务已核价报价行的单价与折扣(2026-09-27 ADR-134：这些行的折扣只读并提示「(报价核定)」，改动服务端回 409
   「该行折扣已由财务在报价核定」；数量与新增行仍可改)；编辑既有草稿的同一行保留已冻结售价，新行/换货行才取当前主档售价。
   销售报价单自 2026-09-27 起同一口径：单价只读(来自货品资料，服务端锁定)，草稿折扣可改，没有标价或文件单价高于标价的行
   折扣留空、显示「待财务定价」，财务在[销售报价财务核价页](销售报价财务核价页.md)定成交单价后显示「财务定价」。
2. 「折扣」允许持有销售订单新建/编辑动作权限的销售逐行修改。货品主档折扣只作初始建议；新写
   使用 `0 < 倍率 <= 1`、四位小数，`1=原价`、`0.9=9折`。旧数据 null/0 仍按原价读取，保存时
   归一为 1，不批量改写已审核历史。折扣列表头带 ⓘ 信息图标（`EditableGridColumn.headerInfo`；2026-09-10 起数量/单价/币种/汇率/税率/结账/供应商等**所有列级通用说明都走列头 ⓘ**，格内不再放通用 ⓘ，只保留学习预填黄标等行特有提示，见 [09-组件库使用规范](../00-项目准则/09-组件库使用规范.md)），
   悬停/长按弹出「1 = 保持原价；0.9 = 9折；0.8 = 8折，以此类推」。
3. Flutter 即时预览 `数量 × 单价 × 折扣`；服务端不把请求单价作为写入来源，而是重新取得权威
   单价并用 `BigDecimal` 重算行金额/原币合计。请求省略单价仍可保存；提交非空单价与权威价不一致
   则冲突拒绝，客户端改 `price/amount*` 不得改变落库结果。
   4. **全部商业单据编辑页启用 `UtenEditableGrid.showColumnSettings`**（2026-09-04 起：
   销售/采购/委外的订货与申请编辑页）：深绿实心大按钮入口 → **按钮处锚定的浮层勾选列表**
   （2026-09-05 起与货品资料共用 `UtenColumnChooserButton`：全选行、勾选显隐、拖拽排序、
   恢复默认，点弹层外关闭）；表头纵向拖出隐藏 = **root Overlay 最顶层跟手浮层**（共用
   `UtenColumnHeaderDragHost`：原格变淡留原位、过阈值浮层红底红×、拖回取消；实现见
   [UtenTableColumnKit](../02-组件库/UtenTableColumnKit.md)）；**表头长按拎起横拖 =
   直接排序**（同日加入：按住不动拎起、横拖跟手浮层+插入位指示线、松手落位——与弹窗
   拖拽排序同一份顺序状态与持久化）。**必填列（列头红 *）锁定不可隐藏**（弹层勾选禁用
   并标注「必填列，不可隐藏」，拖出隐藏无效；排序不受限）；非必填列仍受
   「至少保留一列」兜底。隐藏只影响页面显示，行控制器和提交数据保持完整。
   **列显隐与排序按账号持久化**（2026-09-04 二刷）：宿主页经
   `EditableGridColumnPrefsNotifierBase`（`lib/shared/providers/editable_grid_column_prefs.dart`）
   接 `UtenPagePrefs`——同一编辑页的全部单据模式各占一桶（prefKey 如
   `sales.docEdit.gridColumns`、`purchase.order.gridColumns`），跨设备/重登自动带上；
   列集合演进时未知 key 忽略、新增列按默认序追加；用户本次会话手动改过列设置后，
   迟到的服务端偏好不再覆盖本地。
   **明细操作条精简（2026-09-05）**：编辑模式操作条只保留「表头设置」与宿主批量动作
   （采购/委外的「统一设置条款 (N)」等）；「全选/取消全选」「复制选中」「批量删除」
   「粘贴/粘贴多行」不再常驻——全选走表头复选框，复制/粘贴/批量粘贴/插入空行/删除选中
   走行级右键/长按菜单（同一套 controller 逻辑）。只选/任务模式（无编辑的勾选表）
   保留全选与移出常驻按钮。
5. 复制既有订货行产生的是新明细，不能沿用旧行冻结价冒充当前主档价。客户端清空复制行单价并
   提示重新选择货品；重选后取得当前主档价。若货品未维护售价则保持空值并阻止保存，不残留旧货品价格。

## 八之二、AI 识别客户文件(报价/订货，2026-09-27 ADR-134)

1. 入口：新建报价单/订货单与草稿(含财务退回)，表头上方「识别客户文件」卡片 + 明细工具条同名按钮；已审核的订单不提供(显示「已审核的订单请用改量或修改, 不能整单重新识别」)，模拟身份时隐藏；AI 未开启只加一句「AI 未开启, 只能识别常见格式的 Excel」。
2. 流程：选文件(xlsx/xls/csv/pdf/png/jpg/jpeg/webp，文件 ≤ 15MB，图片 ≤ 8MB) → PDF/图片先确认「整份文件会发送给 AI 服务识别」(AI 未开启或模型不支持图片时直接提示，不上传) → 公共 AI 进度弹窗(上传文件/读取表格/识别表头与列/匹配货品/匹配客户/计算折扣) → 核对面板 → 套用。
3. 核对面板两步：客户(自动对上只显示「客户: X ✓ [换一个]」；否则给建议、「选其它客户…」、「用文件信息新建客户」；文件上没有任何买方线索时，只凭「文件里的货品该客户买过(已审核订货)」给出的建议最多是待核对预选，必须人确认，见 ADR-134 §三；可补客户资料的信息一句话 + 一个勾，空白字段默认勾、值不同默认不勾)；货品(默认只看「需要核对 (N)」，已对应收起；每行大白话原因 + 候选「名称(编号) · 颜色 · 系列」+ 理由，「就是它」「从货品资料选择…」「拆成 N 行」「设为货品英文名」(只对会导入的整行给出: 没勾上、订货单不能导入、没找到货品、拆开的组合件都不给, 也不会随保存带 setNameEn)；底部固定汇总 + 「全部导入 (N 行)」)。文件里别的工作表也像明细表时, 顶部写明「这次识别的是工作表「X」」并给小标签「另有工作表 Y 也像明细表 (N 行)」: 点了用同一个文件加参数 `sheet`(工作表序号)重新识别(同一套进度弹窗), 新结果整个替换面板(新作业 id, 之后导入/「改为新建报价单」都用新作业), 从不把几张表合在一起; 从订货单转来(手里没有原文件)时只提示, 不能点选。不出现置信度数字、识别方式、服务商/模型。
4. 价格：单价只来自货品资料标价(只读，服务端锁定)，文件单价只用来反推折扣(4 位小数，与服务端 `MoneyPolicy.discountFromUnitPrice` 同规则)。标价为 0/空或文件单价高于标价：报价单照常导入、折扣留空待财务定价；订货单不能导入，提示先做报价单并提供「改为新建报价单」(同一次识别，`/sales/quotes/new?aiJobId=…`)。「不能导入」的判定：看得到价格时按候选的定价标记(没有标价/高于标价)或 `orderBlocked`；看不到价格(`summary.priceMasked = true`，标价与定价标记已被服务端去掉)时只看候选上服务端保留的 `orderBlocked`(没有标价或文件单价高于标价；它不是价格字段，不透露任何价格)，订货页据此不勾选该行并引导改做报价单(2026-09-28 集成补上)。看不到价格的账号折扣留空、提交 null，由服务端按文件单价计算，绝不默认 1。
5. 套用：明细已有内容时问「替换/追加」；客户 → 按客户条款预填；币种 = 本位币、合同号 = 客户单号、备注追加贸易条款与没导入的行原文(均黄框)；只有需要核对的行在货品格黄框(原因在格内 ⓘ)，改货品/数量/折扣即清除；原文件存进附件「客户确认」。
6. 明细列：报价/订货增加「文件型号」「文件品名」(可改；手工选货品时文件品名带出货品英文名称，没改过不当客户叫法学习)与「文件单价(币种)」(只读，有值才显示)；报价单价同订货只读，折扣可空，财务定价行显示「财务定价」；报价转入的订货行折扣只读「(报价核定)」。
7. 保存：行提交 discount(空/看不到价格 → null)、clientModel/clientGoodsName/clientPrice/clientNo 与学习用 intakeLineKey/userConfirmed/setNameEn(只在请求中，不落库)；表头提交 clientFileCurrency 与 aiIntake{jobId, clientFields}；新建单草稿保存识别状态。重复货品复核：折扣或文件单价不同的行分开保留(见七之三)。保存成功后服务端另起事务学习客户叫法、货品英文名与客户资料(见 [ADR-134 §五](../99-决策记录-ADR/ADR-134-销售客户文件AI识别导入与主档学习及报价财务核价.md))。
8. 验证：`test/features/sales/intake/**`、`pages/sales_doc_edit_intake_test.dart`、`pages/sales_doc_edit_intake_draft_test.dart`、`widgets/sales_grid_intake_columns_test.dart`。
