# 客户端发布权限与服务器手动更新验证

日期：2026-10-26。状态：本地实现及隔离回归完成，未提交、未部署、未向员工发布测试版本。保留工作树原有并行改动，修改前快照与本任务机器回执位于 `build/client-release-permission-20261026/`。

## 最终行为

- 客户端发布管理统一使用 `client_release:publish`（发布客户端版本）。权限目录迁移为 V946，采用现有 `INDIVIDUAL_ONLY` 策略，由超管逐人授权，普通员工默认关闭，不能通过部门、负责人委派、批量或全员基础包发放。超管的有效权限仍由服务端目录下发。
- 持权员工可查看发布记录、创建草稿、上传、发布和撤回；无权限者入口隐藏，直接访问接口同样拒绝。访客、代操作及须改密会话继续禁止，正式发布与撤回保留密码再认证。
- 上传不等于发布。只有校验完成并正式发布的匹配平台、架构和更高构建号才提供给员工；撤回停止后续检查和下载，不降级已经更新的设备。
- Windows 员工客户端保留登录、回到前台和默认五分钟检查公司服务器的机制。检查只读公司服务器的发布目录，不请求 OSS。提示后由员工打开详情、确认立即更新，才下载并校验、交给固定更新器。
- 服务器页面进入、刷新、通知和进度轮询只读取本机状态。只有手动“检查版本更新”或明确确认的更新作业访问发布源；明确授权的预约仍按原作业执行。
- 两套历史更新 timer 模板使用 `ConditionPathExists=!/` 阻止启动；安装器仍禁用 timer，拒绝自动暂存参数，清理不可达的自动启动分支。不改变备份和 watchdog 的定时任务。
- 公司内网版本目录读取本身不产生 OSS 请求；手动检查和下载服务器版本仍会访问 OSS。外网客户端流量也可能经过云入口，不能概括为所有更新网络使用均免费。

## 公共入口与调用方

| 能力 | 公共入口 | 完整适用调用方及迁移 | 保留差异 |
| --- | --- | --- | --- |
| 客户端发布权限与所有者 | `client_release_access.dart` 的 `clientReleasePublisherProvider` | 设置发布行、发布对话框加载、选包、创建、上传、发布、撤回；统一替换旧超管和 `authorization:manage` 条件 | 普通员工更新本机不要求此发布权限；Web 可发布但不显示本机安装 |
| 服务端发布授权 | `ClientReleaseService.PUBLISH_PERMISSION/PUBLISH_EXPRESSION` 与 `publisher()` | 管理控制器和五个服务入口统一同一码，删除旧身份/授权管理绕过条件 | 对外检查/下载沿用员工身份，发布与撤回继续敏感操作再认证 |
| 发布目录与授予策略 | V946、既有权限目录和权限面查询 | 新增 `admin.client-releases`，复用现有逐人授权及权限解析，无第二套名单 | 高风险、显式授权；不迁移旧授权管理或服务器更新权限 |
| 服务器版本检查 | 既有 `ServerOperationsService` 和本机运维助手 | 页面、工作台提醒、后台通知和作业进度均读取本机缓存；只由显式作业访问发布源 | 已确认预约和进度轮询保留，不能把本机轮询误判为 OSS 查询 |
| 短窗弹窗居中 | 既有 `UtenAlertDialog` 整体滚动分支 | 在唯一公共实现中平衡右侧滚动条预留宽度，所有该分支调用方自然接入 | 复用 Uten 主题、滚动条及布局，不单独重做发布源表单 |

身份、业务数据集、服务器或权限变化会使发布操作永久失效，关闭所持有的发布对话框；重新授权不能续接旧请求。原始发布请求 UUID、未知回执恢复、完整包上传及校验继续保留。另将撤回流程的作用域捕获与确认纳入异常处理，准备期间撤权不再产生未捕获 Future，也不能重复发起撤回或与发布并发。

## 证据边界与发布验收

测试没有请求生产服务或 OSS，没有修改生产 timer 状态，也没有给真实员工分发软件。HTTP 发布链使用真实业务实现，审计服务和登录主体为 fixture，未执行完整 JWT/MFA/密码再认证交互。前端交接验证使用真实 Dart 更新流程，网络传输与原生安装调用由测试端提供；Windows 进程测试运行固定更新器，但可执行程序为隔离 C# fixture。

正式 ERP Release 到 Release 的员工设备升级、原有设置与业务草稿重新打开、实际公司网及外网分发，以及生产主机 timer disabled/inactive 状态仍需部署阶段验收。V946 和新模板需随受控发布安装后生效，不因本地测试通过而视为已上线。首次没有更新器的旧客户端仍需先安装完整新版；专用更新 ZIP 不能替代首装包。
