# 新建单据草稿数据集隔离修复

日期按用户所在地 America/Denver 记为 2026-10-25。本记录区分源码、隔离测试与正在运行的版本；不作为部署或真实业务建单验收凭据。

## 问题与实际证据

新建销售订货单保存提示“业务数据已清空，请重新登录后使用草稿”。其他新建入口也失败。

公共调用链为 `FormDraftMixin.runFormDraftSubmission → saveFormDraftNow → FormDraftsNotifier.ready → synchronizeBusinessReset`。提交前必须先持久化待确认标记；同步草稿失败时，业务 create 尚未发送。初始化失败仍允许填写，故用户直到保存时才看到错误。

本机只读核验：运行中的后端连接 `127.0.0.1:5434/uten_imp`，Flyway V934，`business_reset_generation=0`。当前 Chrome 的 localhost:53764 IndexedDB，同一管理员及 `http://localhost:8080/api` 的草稿 owner 前十二位为 `8c0a0129d0b9`，持久化代次为 **45**。只读解析 SST 和 WAL，没有更新草稿。45 > 0 足以确定触发公共围栏；普通重新登录仍会取得 0。

原有 owner 只包含服务器地址、用户及代操作人，无法识别同地址下重建前后的数据库。不能据此推断刚发生了业务清空，也不能降低本机围栏或绕过提交前保存。

## 统一实现和兼容合同

| 原有入口 | 优势与边界 | 本次处理 |
|---|---|---|
| `formDraftStorageOwnerPrefix` | 所有普通草稿及日报审核意图共用；旧 hash 没有数据集身份 | 纳入服务端持久 UUID；缺字段的旧服务端保持原 hash 字节 |
| Web IndexedDB / Native 文件存储 | 持久化 CAS、原件历史、旧代次围栏及响应性让帧 | 保留事务和围栏算法；共用类型化代次冲突错误，避免误报已清空 |
| `UserProfile → AppUser → SessionState → AuthenticatedScope` | 同一身份语义相等，账号、服务器及登录 ABA 隔离 | 透传并比较数据集 UUID；已绑定 UUID 的会话不接受缺字段响应退回旧空间 |
| `runFormDraftSubmission` | 提交前保存 pending，未知结果不自动重发 | 保持原协议；没有逐页面吞异常或跳过草稿的实现 |

V935 为 `authorization_state` 生成一次 `business_dataset_id`，数据库内持久不变。登录、刷新、`/auth/me`、代操作通过同一工厂返回 canonical UUID `businessDatasetId`，与权限快照一起核验。普通登录、令牌刷新和应用重启不生成新 UUID。

新数据集拥有独立 owner，原来的草稿、历史、附件及未知提交记录不复制、不重挂、不删除。首次获得 UUID 后，无 UUID 的历史记录保持在旧空间，不自动恢复为当前单据；不能只凭代次相等推断它属于当前数据库。

若备份恢复保留同一个 UUID，仍按原数据集处理，原代次围栏继续有效。本次不提供任意改 UUID 或自动接管旧草稿的入口。新建数据库、整库恢复、身份覆盖导入都须保留其受控数据迁移边界，不得把该 UUID 当作用户资料覆盖项。
