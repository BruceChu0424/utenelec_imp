# 车间内料仓发料页 (仓库)

> 2026-10-04 出库仓库只算一次([ADR-147](../99-决策记录-ADR/ADR-147-车间内料仓开通单一真源与发料来源仓.md), [V802](../数据迁移/V802-车间内料仓开通单一真源.md))：每行「出库仓库」的默认值统一由服务端 `fn_workshop_bin_default_source` 给出——这个车间内料仓的发料来源仓有可发量就用它, 否则用货品所属仓库, 再否则用可发量最大的良品子仓 (都不选不良品仓和内料仓; 都没有时留空要人选); 内料仓页、申请候选、申请行建议仓与本页同一口径。「出库仓库」列点开全站仓库滑窗 (先点主仓再点子仓), 每个仓下面显示「可发 N 单位」; 收退回时「退到哪个仓库」同样用滑窗, 只能选启用中的良品子仓。发料来源仓在[车间内料仓页](车间内料仓页.md)的车间总览里设置。

> 2026-09-28 新增, 设计依据 [ADR-131 车间整批领料与盘点计耗](../99-决策记录-ADR/ADR-131-车间整批领料与盘点计耗.md) §5.2、§5.3。

仓库把颗粒这类"整批领料"的料整袋发到车间内料仓 (原名线边仓), 车间也可以先申请, 用不完的料可以退回。发料在系统里是一张调拨 (仓库叶仓到车间内料仓), 只换位置、不算耗用; 用了多少由车间盘点算出来。

## 入口

- [仓库任务中心](仓库任务中心页.md)「出库 → 生产领料」办理内料仓待发料，并提供原权限下的「直接发料」；「入库 → 生产退料」办理内料仓待收退回。「车间内料仓」保留盘点审核、周期盘点和审核记录。
- 领料、退料通知分别进入对应出库、入库分类；旧深链按原业务种类兼容到新位置。

## 三种办理方式

### 直接发料 (主路径, 车间来人就发)

1. 选发到哪个车间 (只列已开启整批领料的车间)。
2. 选领料人: 车间员工选择器, 默认这个车间上一次的领料人。
3. 逐行填料、袋数 (公斤按每袋净重自动算, 可改)、出库仓库 (默认值见页首: 来源仓有货 -> 货品所属仓库 -> 可发量最大的良品子仓)。同一种料要从两个仓出, 点"从另一个仓库再发一部分"拆成两行; 同一种料同一个仓只能一行。
4. 点「确认发料」: 同一笔里建一张"已完成"的领料单, 按出库仓逐张建并审核调拨单, 料记进车间内料仓。库存不足或别人刚改过时整笔不发, 填写的内容保留。

发完提示单号、调拨单号和"记进第 N 期 (起止日)"。车间内料仓正在盘点时, 发的料自动算到下一期, 页面提示"已开始盘点, 这批料算到下一期"。

### 按申请发 (车间先申请)

「待发料」逐条列出原始申请货品明细 (单号、车间、货品名称、编号、颜色、带单位的本行数量、申请人、申请时间)，同单各行不合并。按单据号搜索可找齐同单明细；服务端在分页前按明细筛选，行身份包含原申请 ID 与明细 ID。打开或多选时精确保留本次明细 ID，详情仅核对所选行，不自动扩展同单其它货品。默认数量就是申请量, 可按整袋改; 出库仓默认值同直接发料 (申请时已算好的建议仓)。确认后同直接发料。申请只通知这批料所在仓的仓管 (没有仓管时通知全部有发料权限的人)。整单入口可取消未办申请并写原因；从部分明细进入时不显示整单取消，避免影响未选行。

多选进入同一张领料出库表，货品、本次数量和出库仓优先显示，其后保留申请单号、车间与办理状态；退料使用同一表格，显示入库仓与本次入库量。只核对这一张表并统一确认，不再进入额外预览页或逐申请打开编辑器。主任务列表继续支持多选，右下「已选 X 项」指最初选中的原明细数量。核对表没有第二套决定提交范围的局部勾选，所有展示的未办原明细均属于本次确认范围。

一条原明细需要从不同叶仓办理时，行菜单「分到另一个仓库」增加一个分仓行，保留同一原明细 UUID；各分仓数量合计仍受该原申请额度约束。同一原行同一叶仓不能重复，不能删除最后一个代表该原明细的核对行。分仓行数不增加右下原选择项数。

2026-09-30：车间可直接申请使用中的重量原料，无需提前修改发料方式。尚未确认用途的原料在仓库办理页显示首次用途卡，可选主料／辅料／车间费用，预览全部受影响 BOM 与旧需求，确认后随实际发料同一事务提交。仅现有货品编辑与 BOM 编辑权限持有人能确认首次用途；申请和发料权限不会因此升级。没有权限或有冲突时保留申请和输入，不扣库存、不留半次配置；已配置材料仍直接办理。

### 收退回

「待收退回」及领退料历史同样一行一条原始货品明细，按单号搜索；办理和取消沿用原申请身份、版本与权限，不因显示多行重复执行。打开后按实收填公斤数, 选退到哪个仓库 (同一种料可以分到两个仓收); 确认后生成调拨单 (车间内料仓到所选仓库), 记进车间内料仓开着的那一期。不能退到已经截止的上一期。

## 漏录补录

盘点开始前实际已经发了、当时忘了录的料, 直接发料时勾选"这批料是上一期漏录的":

- 出现"补到哪一期"下拉, 只列"盘点中"或"已盘点、还没结算"的那一期; 必须写漏录原因 (至少 2 个字)。
- 补到盘点中的那一期: 随盘点提交一起算。
- 补到已盘点的那一期: 系统在同一笔里自动更正那一期 (领入加上补录量, 期末实盘不变, 实际用量随之增加), 然后立即尝试结算。
- 那一期的盘点里没盘到这种料的, 系统提示"这种料在这一期的盘点里没有盘到, 请先更正盘点补上实盘数", 先更正盘点再补录。
- 已经结算的期间不能补录; 没有可补的期间时提示"不用补录"。

## 规则与提示

- 直接发料仍选已配置的期间材料；按申请发料读取该申请的精确材料与颜色，可在同页处理首次用途。数量一律按所选物料基本单位显示，克、公斤等不混算。申请后单位变化必须重新核对，不能沿用原数值。
- 发料的调出一侧只扣已被别的单子预留的量, 不受货品安全库存限制; 其它普通出库照旧。
- 系统建的这些调拨单不能红冲; 发错了请车间走退回。
- 通用的"仓库调拨 / 其它出库 / 其它入库"页面照旧选不到车间内料仓。
- 水口料不进车间内料仓: 交回仓库走"其它入库", 回收料金额预填 0 (提示"水口料按 0 成本进仓")。

## 给开发看的对照

- 已办历史以不可变过账记录的实际叶仓、数量和过账身份为准；同一申请行从多个叶仓办理时拆为多条历史，不重复申请量。仓库专用详情继续逐条校验当前仓范围，旧申请行深链只展开当前可见过账。待办、徽章与待办通知只使用剩余未办行的建议叶仓。
- 幂等回执只保存原结果，不保存原车间授权。机台、容器、换料、周期盘点、盘点提交／更正、结算重试／撤销及批量设置在读取旧回执前重新检查当前对象所属车间；版本和状态仍在首次执行的事务内检查，不阻断仍有权人员的原请求重试。

- 列表 `GET /api/workshop-material/requisitions` 每条返回原申请头与单条 `lines`；原详情 API 返回原单明细，办理页按 `lineIds` 严格过滤，空或失效集合不得回退整单。页总数和待办徽章均按待办货品明细计数。通知保持原申请身份。料仓期间状态及盘点审核仍各按其原业务对象显示。前端遵循 `frontend-design`，复用现有 Uten 表格和主题。

- 路由 `/workshop-material/issue` (`?mode=direct` 直接发料, `?requisitionId=` 按申请发或收退回), 页面 [workshop_material_issue_page.dart](../../lib/features/warehouse/materialbin/pages/workshop_material_issue_page.dart)。多申请入口 `/workshop-material/issue/batch` 使用申请 ID 到原明细 ID 的精确集合，由 [workshop_material_issue_batch_page.dart](../../lib/features/warehouse/materialbin/pages/workshop_material_issue_batch_page.dart) 统一单表核对和一次确认；确认内部按原申请事务办理，某申请失败即暂停，已完成申请不会重复执行。前期补录按各申请选择原期间和原因；首次用途按货品核对全局 BOM 影响，均保留在同一页面与本机草稿。
- 批量冻结命令保存原明细、数量、实际叶仓、版本、补录、首次用途、请求号与首次读取时已实办的 `priorHandledLineIds`。恢复时冻结未办原行与原已办集合必须互斥，合并后精确覆盖原选择，已办集合还须有当前实办事实；同一原行的多叶仓分仓可重复出现于命令行。没有该新字段的旧草稿只允许冻结命令自身覆盖完整原选择。本机 `confirmed` 不单独证明完成，须有当前本次范围的实办事实，否则保留原命令为待核对；未知结果只允许原 body 和请求号核对重试。
- 路由守卫 `workshop_material:issue`; 取消申请 `workshop_material:request` 或 `workshop_material:issue`。按钮只看 `allowedActions`。
- 接口: `POST /api/workshop-material/direct-issues`、`GET /api/workshop-material/direct-issues/defaults`、`GET /api/workshop-material/materials` (料与默认出库仓 `defaultLeafWarehouseId`)、`GET /api/workshop-material/settings/source-warehouses` (仓库滑窗的全站仓库树, 发料权限可读)、`GET /api/workshop-material/requisitions`、`GET /api/workshop-material/requisitions/{id}`、`POST /api/workshop-material/requisitions/{id}/fulfil`、`POST /api/workshop-material/requisitions/{id}/cancel`。建单只经 `WorkshopMaterialStockGateway` 到 `StockDocService.createAndApproveWorkshopMaterialDocument`, 单号领料 ZL、退回 ZT。
- 「出库 → 生产领料」红数合并普通生产领料和 `workshopMaterial.pendingIssue`；「入库 → 生产退料」合并普通退料和 `workshopMaterial.pendingReturn`；内料仓审核红数只取 `warehouseStockCountReview`，周期进行中数仍取 `COUNTING`。各事实只计一次，列表和徽章复用原仓库与车间范围。
- 单次 fulfil 只完成传入的原始明细，未选行仍待办。已存在过账、`fulfilled_qty > 0` 的行不再接受新办理；最后一条待办明细成功后原申请才转 DONE。实际数量仍允许沿原规则调整，不把申请数量当成强制发料量。右下悬浮统一显示「已选 X 项」和确认操作。
- 测试: `test/features/warehouse/workshop_material_issue_page_test.dart`; 服务端 `WorkshopMaterialIssuePostgresTest`、`WorkshopMaterialStockAuthorizationPostgresTest`。
