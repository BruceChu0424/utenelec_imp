# ADR-070：物料分析分桶详情页 + 三处学习记忆 + 采购委外超量下单

- 日期：2026-09-04
- 状态：已决策；后端/Flutter 为源码候选，真实岗位 UAT 未完成
- 相关：ADR-065（备料下达同批合并）、ADR-068（订货单行级条款与学习模式——本决策把
  「学习预填 + 黄框核对」推广到销售/路线/车间三处）、ADR-062/V458（委外前置自制）
- 迁移：V468（仅一条部分索引，服务路线学习预填查询；业务行为与表结构零变更，
  历史数据自动兼容——三处学习全部直接读既有历史表）

## 一、问题

1. 物料分析页顶部「大卡片套小卡片」瀑布流在物料多时被撑爆、顺序混乱；BOM 树头另有
   「批量选择(整次分析)」三枚全选勾，两套批量入口并存。
2. 销售/物料分析多处重复选择成本高：新建销售订货单每次手填结账方式/发运策略/币种；
   物料分析里无建议路线或上次改过路线的物料每次重选；计划向导逐页选车间。
3. 采购/委外备料数量被「本批缺口−在途」封顶：想一次多采给后面批次用做不到。

## 二、决策

### 2.1 物料分析分桶详情页（UI 改版，动作口径不变）

- 主页面只留一行六个入口卡：**可安排生产 / 暂不可安排 / 已转生产 / 可采购 / 可委外 /
  待自制**（计数徽标）；点击 Navigator.push 全屏详情页。
- 可安排生产桶 = 可编辑计划表（本批数量默认最多可生产、生产车间列、负责人列、
  必选校验）；两类批量动作：生成生产计划（产品行）、创建子件任务（自制候选行）。
- 采购/委外/自制桶 = 多选表 + 批量下达；原 BOM 树头三枚全选勾并入；树行首勾选框
  退役为入口指引图标（门禁图标保留）。
- **详情页动作 pop 回宿主页统一执行**（数量弹窗/分批/幂等/409 恢复/计划向导仍在
  宿主页上下文），两处实现不会漂移；详情页无独立路由（随宿主页权限）。

### 2.2 计划单保持「一产品一单」（不合并为同车间一张单）

用户提出「同车间汇总到同一张计划单」。经查 `production_plans.material_analysis_item_id`
单指针被库存 peg/供应进度/委外任务/执行就绪/MRP 五处当作 1:1 追溯锚点（领料/派工/
报工/入库按计划行回写）。**决策：不物理合并单据**——同车间同负责人的一次性批量下达
由分桶详情页承担（车间/负责人列选一次，计划向导按组预填确认），每张计划单仍对应
一个分析行。物理合单需要独立一轮执行链改造，不在本决策内。

### 2.3 三处学习记忆 + 黄框核对统一

统一约定（挂载点 `required_field_decoration.dart`）：**必填空 = 红框；系统学习/主档
带入的默认值 = 黄框 + 「请核对」提示；用户改值即消黄框**；优先级 错误 > 必填空 > 预填。

1. **销售客户条款**：`GET /api/sales/orders/last-terms?clientId=` 取该客户最近一张
   未删订货单的 结账方式/发运策略/币种；只回填「空或仍带黄框（未核对）」字段。
2. **物料分析路线记忆**：`GET /api/production/material-analyses/last-routes?goodsIds=`
   按货品+颜色+单位维度取最近一次 `confirmed_route`；对未确认路线且（无建议 或
   记忆≠建议）的组写路线草稿（脏态，须「确认路线」保存）；记忆=建议时不打扰。
   修改过路线的物料天然被记住（记忆存的就是确认结果）。
3. **车间默认**：沿用正式排产确认学习（`/default-workshops`），分桶详情页表格
   列直接展示并黄框；**负责人默认统一带出该车间在组织树上维护的负责人**
   （`departments.manager_id`，黄框提醒核对，可改；未维护负责人的车间留空手选；
   换车间时负责人跟着换新车间负责人），排产下钻 seed 显式指定优先。

采购/委外 `/last-terms` 行级条款（ADR-068）同步接入黄框（`CommercialTermsRowMixin.
termsAutofilledNotifier`）；销售地址簿带入、出库默认仓（D1）同口径。

### 2.4 采购/委外超量下单

- 数量确认弹窗与 `notifySupply` 对 **BUY/SUBCONTRACT 放开上限**：默认仍为缺口全量、
  允许改小分批，**也允许超过缺口**；超量部分入库后转为公共可用库存，供后续物料分析
  直接使用（在途与可用投影既有口径自然覆盖，无需新账本）。
- **MAKE 不放开**：自制任务仍必须按全部剩余需求精确创建（本批数量在子件任务的
  计划向导里填）。
- 负数一律拒绝；原有「真实未绑定需求扣除在途」的余量复核、安全库存补库校验不变。

## 三、后果

- 物料分析页净删约 900 行卡片 UI（瀑布流/状态面板/批量勾选），新增分桶详情页
  （`material_analysis_bucket_detail.dart`）；87 个页面测试按新 UI 移植。
- 销售订货明细仅「单价」锁定为 readOnly 正文字色，并提示由货品主档或来源报价带入；
  「折扣」由销售在订单行内调整，金额按数量 × 权威单价 × 折扣即时预览并由服务端重算。
- 权限零新增（详情页随宿主页；销售 last-terms = `sales_order:view`；
  路线记忆 = `production_material_analysis:view`）。
- 后续若确认物理合单需求，另立 ADR 评审执行链（`material_analysis_item_id` 指针模型）。

## 四、大数据量性能口径（2026-09-04 补，几百产品量级）

真实环境点「暂不可安排」整页卡死触发的一轮专项：

1. **分桶投影 O(物料²) → O(n) 索引化**：`_MaterialAnalysisIndexes` 增加
   `(analysisLineId, parentNodeKey)` 复合父子索引（与 V234
   `analysis_item_id + node_key` 唯一身份一致，不能假设 nodeKey 跨订单行全局唯一）；
   `_pendingMakeCandidates`（直接子层缺料）、
   `_hasProductionBomChildren`、`_analysisMaterialHasChildren`、`_depth1MaterialsFor`、
   `_delegatedChildProductOf` 全部从全表扫描改为索引取。
2. **分析快照级缓存**：`_bucketRows` 按分析对象身份 putIfAbsent 缓存（空桶也缓存），
   入口徽标×6/详情页标题每次 build 不再重算；同一快照上的路线草稿、学习预填或
   优先级变化须主动失效缓存，避免入口计数/顺序停留在旧状态。
3. **只读桶分页**：详情页 MasterDataTableView 200 行/页（只构建当页），并显式关闭
   表体 `SelectionArea`（Flutter Web 转场/横纵滚动不维护大选择注册树）；跨页批量
   用「全选全部 N 条」按钮（勾选按业务 id 跨页保留）。可安排桶网格首屏 100 行
   +「继续显示」增量装载。
4. **请求侧**：`/last-routes` 按 100 货品/块并行分块（URL 长度防 8KB 代理上限，
   与 default-workshops 同款）。
5. **看门狗**：页面测试「big analysis opens waiting bucket fast (perf canary)」
   ——1500 产品/3000 物料（多订单复用同款 BOM nodeKey）首屏冷投影与点暂不可安排
   均须 <10s，并验证 200 行/页形成 15 页；不能只从缓存命中后开始计时。
6. **服务端方向（未实施，后续专项）**：几百~几千产品时后端每次刷新全量重算
   分配投影才是最终瓶颈。演进方向 = 按产品粒度缓存 **BOM 展开结果**
   （键=货品 BOM 内容摘要；组件未变直接复用展开，库存/在途变化只重跑分配
   与齐套投影），分析刷新从 O(全部产品×全树) 降为 O(变化产品)。需要独立
   设计评审（涉及 V234 节点快照重建路径），不在本 ADR 落地范围。

## 五、2026-09-04 V471/V472 与统一物料表后置修订

本节覆盖 §2.1、§2.4 和 §三“权限零新增”；§三“销售单价锁定、折扣可调并按数量 × 权威
单价 × 折扣重算”保持不变。

1. 主页面六个分桶入口保留用于快速聚焦，但具体物料明细改成共享 MasterDataTable。默认按
   产品/BOM 展示，支持切换物料/路径汇总；层级缩进和连线必须可辨，搜索保留祖先上下文。
   统一表直接支持多选、列显隐/拖动、双击详情和右键“详情 / 采用建议或更换路线 / 采用公共
   在途 / 当前可执行任务”，菜单动作结束清除上下文选择。
2. §2.4 的“超量入库后自然成为公共库存、无需新账本”被 V472 替换。现在下达时即把精确需求
   与 public surplus 分开持久化；来源分析只拥有 requested_qty，后续分析只能显式 claim
   已批准公共在途。这样在到货前也能准确显示“公共可采用 1500”，并发采用由数据库容量守恒。
3. V471 新增仓库多选记忆：一个明确主领料仓 + 至少一个参与仓。其它参与仓只产生可调拨提示；
   未做仓间调拨前不提高齐套、预留或 DRAW。
4. MAKE 和有子层 SUBCONTRACT 不再被 lowerLevelPending 禁止创建 child，但仍禁止自动创建和
   部分 ownership。员工显式全量创建 child 后可先排车间；批准时物料不足进入 WAITING、零
   reservation、无 DRAW。
5. 新增 production_material_analysis:over_supply 与
   production_material_analysis:claim_shared_future 两个权限并登记页面权限面；取消 claim 的
   前后端权限统一为 claim_shared_future + 服务端 CANCEL_ACTION。公共来源的单号与 UUID 还要
   经过采购/委外对象范围，不能只凭模块 view 泄露。

例：A 需求 500、采购批准 2000，A 的精确归属仍是 500，公共在途 1500；B 需求 1000 时显示
可采用 1000、采用后公共余 500，也允许 B 另行采购。批量同 SKU 的确认文案只显示一个共享池，
并按稳定顺序扣减，避免每条 BOM 路径都展示 1500 造成重复可用错觉。迁移与恢复见
[迁移说明 89](../数据迁移/89-V471-V472物料分析参与仓与公共在途认领.md)。
