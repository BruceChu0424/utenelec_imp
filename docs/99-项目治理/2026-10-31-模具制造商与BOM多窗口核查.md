# 模具制造商与 BOM 多窗口核查

## 数据核查结论

2026-10-31 通过既有 SSH 管理入口，对公司服务器 `uten_imp` 执行了只读事务；旧数据来自本机已还原的 `YTDQ_2023` 备份，**不是正在运行的旧服务器的实时库**。本轮没有修改公司数据库、部署或打包。

| 核对项目 | 旧备份 | 公司库 |
|---|---:|---:|
| 模具 | 1,605 | 1,626 |
| 供应商主档 | 386 | 399 |
| 旧 `B_Mould.summary` 非空 | 1,300 | 1,300 条原文逐条保留于 `moulds.keeper` |
| 有制造商文本的模具 | 没有独立制造商列 | 0 |

旧备份 1,605 个模具 `legacy_id` 在公司库全部存在，`summary → keeper` 逐条原文一致，没有缺失或文本漂移。公司库比旧备份多 21 条模具，不能用旧备份覆盖这些增量。

截图中的 `2022-11-168【A1-04】`、`2022-11-170【D3-03】`、`2022-11-168-A【A1-04】` 在旧备份的 `summary` 都是“双惠”，公司库对应记录的 `keeper` 也仍是“双惠”。旧列还大量保存“博睿、天升、佳博、汇锋”等名称，不能把这一列统一解释成保管人员工。原迁移按 `summary → keeper` 保存，V869 又独立增加了空的 `manufacturer`，没有回填，因此制造商界面显示“待补充”。

用户随后明确确认：旧界面的这一列叫“制造商或模具供应商”，因此本轮恢复保留全部 1,300 条原文，包括以个人名字登记的制造商，不再把人名自动排除。**供应商主档与制造商文本仍是不同事实。** 旧供应商中可找到“晨欣模具厂、汇锋模具厂”等名称，但“双惠”没有名称包含匹配；不存在已证实的 `B_Mould → B_Provider` 制造商外键。`summary` 中的人名和简称按已确认的制造商原文保留，不自动绑定供应商 UUID。现有独立保管人关系、后来修改的保管人和人工填写的制造商均不覆盖。

公共复查入口为 `server/legacy_migration/audit_mould_manufacturers.ps1`：只读 SQL Server 和公司 PostgreSQL，输出 `audit.json`，含逐 UUID/旧 ID/原文的候选清单、文本漂移及供应商名称候选。默认输出 `output/mould-manufacturer-audit/`，本轮证据在 `output/mould-bom-20261031/audit.json`。此脚本没有写入模式。用户确认列义后，新增 V972 前向恢复：固定旧备份中的 1,300 个旧 ID 和逐条原文，仅在制造商为空、保管人无员工关系且仍等于原文、模具未删除时恢复制造商并清掉错误归列的保管人文本；原文移入制造商，不丢弃、不合并别名。已修改或较新的记录保持原样，历史/读取范围触发器不禁用。离线导入也修正为 `summary → manufacturer`、保管人保持独立，避免以后重新导入又出错。未运行公司库写入或全库重导。

## 设计及公共实现

本轮按 `frontend-design` 复用现有 Uten 主题：主色 `#0F766E`、强调 `#14B8A6`、页面 `#F5F7FA`、表面 `#FFFFFF`、正文 `#0F172A`、边框 `#E2E8F0`。字体沿用 NotoSansSC 和现有字号、圆角、间距 token。保留高密度工作表；编号紧随名称，按用户后续要求把上/下一个导航并入表格底部悬浮操作组，保留表格完整高度。

```text
反查结果主表                 可拖动比较窗口（可并排、缩放、收起）
  双击产品 ────────────────> 产品名称 / 产品编号
  右键：关系依据              原货品详情页签
                             原 GoodsBomTab（新增、编辑、替换、审计）
                             底部悬浮：上一个 BOM / 位置 / 下一个 BOM / 编辑
```

| 职责 / 已有实现 | 本轮处理 / 调用方 |
|---|---|
| `GoodsDetailPage → GoodsDetailBody → GoodsBomTab`，货品完整详情及 BOM 新增、编辑、替换、审计 | 物料反查双击在有 `goods:view` 时直接打开这一入口，默认 `tab=bom`；保留各动作的原权限和服务端事务。没有货品查看权限仍只显示反查授权范围内的关系面板。没有复制 BOM 编辑器。 |
| `where_used_product_detail_dialog`，历史关系、证据及库存跳转 | 保留，并增加行右键/长按“关系依据”；不会因改成完整货品详情而丢失历史数量说明。历史关系仍不能参加“当前 BOM”批量替换。 |
| 原整页详情标题 | 同一 `GoodsDetailBody` 显示产品编号，Web/Flutter 桌面和比较窗口共同生效。 |
| 来源表顺序 | `GoodsDetailSequence` 固定真实 UUID 顺序，去重、可序列化；货品列表为当前页，反查为已加载结果，界面注明范围。无来源序列的深链按当前分类读取完整顺序，不声称来源于原筛选。 |
| 完整分页读取 | 复用 `loadCompletePagedSnapshot`，保留分页完整性、身份隔离、总数变化拒绝及让帧；没有第二套截断读取。 |
| BOM 上/下一个 | `GoodsBomNavigation` 使用同一详情路由并保持 BOM 页签；首尾禁用，读取失败可重试。编辑时先经过 `finishEditing` 的继续/放弃/保存决策；保存失败或未知提交不越过旧编辑器。 |
| 所有基础资料及物料反查的顶部入口 | `UtenPageWindowScope → UtenAppBar` 统一贡献“新窗口”，覆盖 `/basicinfo` 全部页及 `/production/where-used`；不在每个业务页面复制按钮。新窗口打开当前路由，原窗口保留筛选和草稿，未序列化的查询条件在新窗口重新选择。 |
| `UtenFloatingWindow`，已有无蒙版、拖动、缩放、缩起能力 | 增加可复用 `arrange`，窗口排列不卸载编辑器。`BusinessWindowHost` 提供并排排列；窄窗口按局部 MediaQuery 自适应。 |
| 路由和权限 | 主窗/子窗调用同一 `_createAppRouter`，不复制路由表或身份；子窗单独导航、返回刷新信号、Navigator 与浏览器路由适配，子窗导航不改主窗 URL/历史。 |
| 离开和关闭保护 | `FormDraftNavigation` 按 router 隔离，全部六处注册入口同步迁移：草稿 mixin、货品 BOM、主档 inline、客户端发布、车间物料仓、平台设置。关闭一个窗口检查其全部编辑器；同路径另一窗口的草稿不会误阻拦或被放弃。身份/服务器/权限边界变化时撤销旧窗口。 |

复查中发现 BOM 确认对话框关闭动画可能晚于来源页替换；已把本地化解析固定在来源仍有效时，防止“下一个 BOM”在放弃/保存后触发失效 context 查询。该修复位于原公共 `GoodsBomTab`，保留服务端预览、原始精度、共享组件影响提示及未知提交恢复。
