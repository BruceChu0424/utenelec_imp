# 销售报价财务核价页（核价队列与核价详情）

2026-10-02 按 [ADR-139](../99-决策记录-ADR/ADR-139-销售报价议价客户确认与货品报价历史.md) 更新。取代本页原先“销售不能改报价单价”和“财务确认后直接转单”的描述。客户文件识别仍沿用 ADR-134，客户模板沿用 ADR-136 与 ADR-139。

## 入口与公共布局

- 财务任务中心“报价核价”：`/finance/quote-review`；详情 `/finance/quote-review/:id`。支持 `?state=pending|confirmed|returned`。
- 销售任务中心“报价单”：共用销售单据列表、详情和编辑页；新建报价与订货共用表头、客户选择、货品表、金额和附件组件。
- 报价有有效期，订货有发运策略；两者保留自己的业务字段。报价允许提出单据价格，订货继续锁定来源报价核定价款。
- 财务页面复用统一表格、公共认领、忙碌遮罩、精确金额和字段修订对照组件。桌面双击或“核价”进入；紧凑屏由公共表格的卡片布局承接。

## 完整流程

销售新建并保存 → 提交财务核价 → 财务认领、修改、退回或确认 → 销售联系客户 → 登记客户同意当前版本 → 生成订货草稿 → 检查保存 → 沿用订货审查、提交、财务审核与履约链路。

客户不同意时可以重新修改再提交，也可以填写原因取消报价。财务确认不代表客户已经接受。任何重新修改或撤销核价都使原客户确认失效。

| 阶段 | 可办事项 | 关键守卫 |
|---|---|---|
| 草稿 | 编辑、提交、取消；从未提交的草稿可删除 | 对象写范围、当前修订号 |
| 财务退回 | 修改后重新提交或取消 | 原因与历史保留，不能删除沟通历史 |
| 待财务核价 | 财务保存修改、退回、确认 | 合格核价人、本人有效认领、当前版本 |
| 待财务核价 | 销售撤回或取消 | 财务正在认领时不能抢走单据 |
| 待客户同意 | 登记客户同意、重新修改或取消 | 财务已确认、未过期、未转单 |
| 待生成订货单 | 生成唯一关联订货草稿 | 客户同意版本等于当前版本、未过期 |
| 已转订货单 | 查看订单；订单安全终止后重新报价 | 不修改旧报价及旧订单的价款来源 |
| 已取消 | 查阅历史 | 原因、责任人、时间保留 |

原状态码继续为 0 草稿／退回、2 待核价、1 已核价、-1 取消／旧作废；客户确认记录进一步区分 status=1 的下一步。

## 财务认领与页面结构

先读取详情；只有服务端 `financeActions` 含编辑、退回或确认时才认领 `SALES_QUOTE_FINANCE_REVIEW`。认领后再读一次详情，心跳续租，动作前核对 claimId。只查看或撤销确认无需预先认领；撤销后重新读取并认领待核价报价。认领失效立即暂停操作，支持重新认领刷新；离开或办结释放。

页面包括：状态与版本、报价信息、客户原文件附件、历次核价记录与逐格差异、货品明细、金额合计及操作按钮。可修改表头为有效期、结账方式与财务备注；保存始终提交当前表头状态，空值表示清空。

货品明细包括货品身份、数量、报价单价、成交单价、折扣、金额、价格来源；有客户文件时展示文件型号／品名、原币单价及折合本币参考。没有确定价格、无效输入和未保存修改均明确提示，不允许直接确认。

## 改价、改量和删除

- 销售报价价款仅保存到报价行，来源 `SALES`；不更新货品资料标价。无价格查看权限者不显示、不发送隐藏价格，并由后端拒绝越权改价。
- 财务可修改报价单价、折扣、数量，也可以删除行。单价与折扣组合修改按服务端精确金额计算，保留冻结单据基价。
- “成交单价”联动工具继续存在：基于冻结报价基价反推四位折扣；没有基价或成交价高于基价时采用财务直接定价。财务赠品／零价为显式操作。
- “按最新标价刷新”是用户主动选择，不因主档后来改价自动覆盖已报价条款。
- 明细请求只发送修改行。每行可包含 `qty`、`price` 与 `discount`，或既有 `dealPrice / giftZeroPrice / useMasterPrice` 定价指令；删除为 `removed=true`。服务端拒绝冲突指令、非法金额、重复或跨单行 ID，以及删除全部明细。
- 财务确认或退回前必须先保存修改。错误请求回滚整笔事务，不留下部分改量或部分删除；续租期间即禁止重复点击，旧身份或服务器的迟到响应不能重建页面。

## 修订对照

销售详情和财务详情共用 `SalesQuoteRevisionComparison` 与 `UtenCellRevisionTable`。按稳定明细 ID 比较两个版本，原有货品身份、数量、价格、折扣、金额、备注和扩展列留痕。

仅修改价格时：原价格格红色删除线，表尾“新单价”列红字；未变化格保持正常。修改多个字段时仅追加对应新值列。真正删除整行时整行划去，新增行单独标明。重排行号不被误判为删除后新增。

每次销售编辑、提交、财务修改、退回、确认、撤销确认、客户同意、取消和转单追加不可变快照。价格受限读者的历史快照也脱敏。

## 销售任务与通知

销售报价分段为草稿、财务退回、待财务核价、待客户同意、待生成订货单、已核价浏览、取消／作废及历史。草稿与退回红数来自既有状态计数；两个新待办入口为：

- `salesQuoteAwaitingCustomerConfirmation` → `salesQuote.awaitingCustomerConfirmation`。
- `salesQuoteAwaitingConversion` → `salesQuote.awaitingConversion`。

两者互斥，只数可办范围，已存在任何来源订单引用的报价都不再计入。销售大类汇总这些入口，模块徽章不重复累加页内分段。待财务核价在销售端显示黄数；财务核价入口 `financeQuoteReview` 为红数。

财务确认通知为“报价已核价，待客户确认”。重新提交按实际 SUBMIT 历史次数判断，不把草稿多次保存误报为重新提交。取消、撤回、退回和核价办结撤回相应审核待办。

## 关联订货与重新议价

生成订单只创建草稿，继续遵守订货的保存、审查、财务和履约闸门。报价价格与折扣带入后锁定，不能通过订货编辑绕过重新核价。

已转单后原报价被冻结，包含来源订单已软删或红冲的情况。若原订单不能继续，应先按现有取消／红冲守卫处理订单；已经发生发货、生产、预留等业务时不能强行跳过。安全终止后“重新报价”复制新单并保留来源关系，再走财务和客户确认；V792 同时永久封存旧订单，新报价后来取消或删除也不能使旧单复活。重复点击复用同一有效重议价单。“查看首次重新报价”使用历史只读入口，已删除的首次草稿仍能追溯。

## 货品历史与客户模板

货品详情“报价记录”需要 `goods:view` 和 `sales_quote_finance:view`，显示每次提交／财务修改／财务确认的不可变快照，可打开客户一致且有权限的关联订货单；无可访问订单则显示本次快照。旧快照未保存客户／人员身份时显示“历史未记录”，不能用当前报价客户或最终货品售价反推历史。

下载报价时没有客户模板，会提示上传 Excel；支持空白模板、字段对应核对与人工修正、全部可见工作表选择和保存客户模板。采用时服务端核对任务上传人、客户和报价身份，首次确认映射与模板版本固定留证。持续采用的映射进入已有版式学习机制，不学习价格、不改主档。下载绑定报价修订号和选定模板版本；身份变化后的旧文件不能落盘。客户模板保留列顺序；标准格式继续全平台投影。

## 主要接口

- `GET /api/sales/quotes/finance-review`、`/{id}/finance-review`：队列与核价详情。
- `PUT /api/sales/quotes/{id}/finance`：`expectedRevision`、`expectedClaimId`、当前表头与修改行。
- `POST /{id}/finance-return|finance-confirm`：当前版本、认领；退回原因为 `text`。
- `POST /{id}/finance-reopen|submit|withdraw|reopen|customer-confirm|convert|requote`：当前 `expectedRevision`，依动作核验身份与状态。
- `POST /{id}/cancel`：当前版本与必填 `reason`。
- `DELETE /{id}?expectedRevision=N`：仅从未提交的草稿。
- `GET /api/sales/quotes/goods/{goodsId}/history?page&size`：授权财务查看货品报价快照历史。

字段名以服务端 DTO 和前端契约测试为准。部署与真实岗位、实际模板、实际 AI 服务商验收状态单独记录，不能用本地回归代替。
