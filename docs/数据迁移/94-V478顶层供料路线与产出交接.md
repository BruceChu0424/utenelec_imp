## 一、需求与真实身份

P1根产品也应能选择采购、自制、委外。仅给产品标题画一个下拉框会缺失可审计的供料对象，因此使用真实ROOT_SUPPLY物料行，与组件复用同一 `materialLineId/actionGroupKey`、route/notify权限和数量链。

新建或授权刷新时，服务为SALES_ORDER_ITEM、REWORK、TRIAL、SAMPLE、STOCK、OTHER来源补一次根UUID；不为系统MAKE_COMPONENT/SUBCONTRACT_MAKE再造外层根。产品DTO以 `rootMaterialLineId` 指向根行，P1只选择自身，不能递归把子BOM全部确认。

迁移本身不批量确认历史根路线。原分析根指针起始为空；旧响应缺根字段时，前端根路线区域只读，不伪造UUID，既有子BOM/历史计划依原合同兼容。

## 三、路线和数量

根MAKE直接以原分析行生成正式计划，不通过notify重复生成MAKE child。根BUY/委外进入对应供料桶，不作为未下达自制计划；前端与服务端仍按既有供料、前置委外和审批合同办理。

根物料用货品基本单位，per_product_qty保存来源单位换算；销售来源取其冻结unit_rate，其它来源为1。例如10箱、每箱20件，根供给是200件，生产计划仍输入10箱。根库存分配在普通BOM分配后运行，先扣除已保护的组件公共库存，不能把同一余额花两次。

`submitted_qty + approved_qty + root_fulfilled_qty <= requested_qty`。root_fulfilled_qty由累计事件净基本数量除冻结换算率并截取四位小数；超过来源余量会被约束拒绝，不能通过截断超量或直接修改完成量掩盖不守恒。根已被SUBMITTED/APPROVED计划、任何有效供料行动或产出交接占用时，数据库冻结其路线；外购/委外根不能再写制造计划。

## 四、交接与反向

1. 销售根显式下达时，可在锁内将已分配的合格存量转为销售预留，再只对外部缺口下达供料；无命令不得自动消耗现货。
2. 采购/委外合格实收入库形成精确origin后，在同一事务核对受益根、仓库、货品、颜色和余量，追加exact RELEASE，释放原PREPLAN预留，再建立销售预留及FULFILL事件。手工来源的新外部入库可登记完成，但不能凭无收货来源的公共现货造完成。
3. 事件触发器核对来源身份、转换容量、exact释放与销售预留形状；随后投影root_fulfilled_qty和剩余状态。幂等重放不重复交接。
4. 收货反向只对未反向FULFILL追加一条等量REVERSE，完整匹配原预留、release事件和收货来源。销售已拣货、发货或预留已消耗时拒绝直接红冲，必须先走合法下游反向。

交接和销售预留不是销售发货或应收确认，不绕过既有财务放行、仓库出库及正式SHIPPED门禁。

### 4.1 交接引用、零追加量与人工撤回入口

分析详情将产出事件作为只读引用展示：`ROOT_STOCK_ALLOCATION`表示既有现货交接，`ROOT_OUTPUT_FULFILLMENT`表示合格收货交接；状态为COMPLETED或REVERSED，documentId是事件UUID，actionId为空，不能冒充普通preplan行动。

两类产出引用均不计入“已提交在途”。例如已经交接3件、根节点现在还需7件，追加供料上限仍为7，不能再次减3变成4。已REVERSED的产出引用不继续冻结根路线；其它活动供料/计划/交接仍可依法冻结。

已分配现货足以覆盖销售根时，数量确认单单独说明将交接的现货，追加采购/委外数量可为0。客户端不得自动把0改成1或伪造正数采购；服务端在锁内办理现货交接，并负责不生成0数量外部申请。此例外仅给ROOT_SUPPLY；普通不活跃BOM不能借此获得下达能力。

根详情的“撤回现货交接”只对COMPLETED的ROOT_STOCK_ALLOCATION显示，需view+notify及服务端 `ROOT_OUTPUT_REVOKE`。请求为 `POST /api/production/material-analyses/{analysisId}/root-outputs/{eventId}/revoke`，复用CancelRequest的version、fingerprint、idempotencyKey和**必填**reason(2..1000字符)；路线原因选填不放宽本项反向审计要求。成功回执刷新原分析，已撤回事件仍在历史里。

ROOT_OUTPUT_FULFILLMENT必须走来源采购/委外入库的合法红冲，不提供现货撤回按钮，服务端也拒绝把有收货来源事件经此接口撤回。任何已有拣货、发货或被消耗预留仍不能直接撤回。
