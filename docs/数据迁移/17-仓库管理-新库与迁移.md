# 17 - 仓库管理模块 · 新库设计与迁移方案

> 设计依据：[16-仓库管理-老库溯源.md](16-仓库管理-老库溯源.md)
> 设计原则（用户钦定并再次强调）：**比老系统更优秀、更高效、海量数据处理更快** · **适配老数据** · **底层数据库重新设计**（不照搬）。
> 模块归属：**PMC 运营部 → 仓库管理**（9 单据）+ **仓库管理报表**（9×2）。
> 复用：迁移代码**幂等 + 重度注释**，未来新数据可直接重跑（见 §八）。

---

## 一、关键洞察（决定全局设计）

1. **库存流水骨架已就绪**：V45 `stock_movements.movement_type` 当初就为仓库管理预留了 5–12 号位（5生产领料 6生产退料 7调拨入 8调拨出 9盘盈入 10盘亏出 11其它入 12其它出）。采购已用 1/2。**9 类仓库单据的"库存效果"全部能由流水表达**，无需新账本。
2. **9 类单据高度同构**：主表（BillNo/BillDate/StockID/MakeID/ApproverID/Status/Cancel）+ 明细（GoodsID/ColorID/UnitID/URate/QTY/STotal/Weight）几乎一致，差异只在少数列（调拨双仓、盘点盘盈亏、领料挂BOM/计划）。
3. **老库的臃肿**：9 套同构表（18 张）+ 18 张报表视图 + 按月分列台账（StockGoods 88 列）—— 重复、僵化、慢。

**结论**：新库**不照搬 9 套表**，采用「**统一单据表 + `doc_type` 判别 + 流水驱动库存**」的重新设计。9 张表 → 2 张表，18 张报表视图 → 2 个参数化查询。

## 二、设计决策总览

| # | 决策点 | 选型 | 理由（更优秀/更快） |
|---|---|---|---|
| 1 | 单据存储 | **统一 `stock_documents` + `stock_document_items` + `doc_type`** | 9 类同构，合并省 16 张表；单一索引/计划/审核路径；维护与扩展（未来加单据类型=加枚举值）零成本 |
| 2 | 库存驱动 | **审核同事务写 `stock_movements` + upsert `stock_balances`**（V45 已建） | 流水+余额模型，取代老库按月分列台账；任意时间范围/跨年/多类型，余额实时 O(1) |
| 3 | 调拨特殊 | **一笔调拨 = 两条流水**（调出仓 direction=-1 type8 / 调入仓 direction=+1 type7） | 调拨是"双仓双动"，流水天然表达；余额两仓一减一增 |
| 4 | 盘点特殊 | **按行算 `surplus = NowQTY − 账面`**：>0 写盘盈入(+1 type9)，<0 写盘亏出(-1 type10) | 盘点是差额调整，非全量出入；金额按均价 |
| 5 | 报表 | **全在 `stock_movements` 上查询**（明细=过滤流水 / 汇总=上卷），物化视图加速 | 9×2 报表 → 2 个参数化查询；分区裁剪毫秒级 |
| 6 | 分区 | `stock_document_items` 与 `stock_movements` 均**按日期 RANGE 分区** | 十几年 62 万+明细，命中单年/月分区，IO 大降 |
| 7 | 主键/审计 | UUID + `legacy_id` 溯源 + 审计软删 | 同采购/主档惯例 |
| 8 | 人员字段 | 留 NULL（B_Worker↔employees 无对齐，同采购） | 已知缺口，后续建 `worker_legacy_map` 回填 |
| 9 | 库位 | 首版 `place TEXT`（仓内文本），不建独立库位表 | `B_StoragePlace` 仅 7 行，独立表过重；后置按需 |
| 10 | 金额双口径 | `*_original`/`*_local`（仓库单据多为本币，双口径留位与采购一致） | 统一范式 |

> 与采购的关系：采购用 4 套独立表（4 类单据差异大：申请无供应商、收货有交货人…），仓库用统一表（9 类同构）。**两者共享同一 `stock_movements` 骨架**——这是全链路打通的枢纽。

## 三、表设计（重新设计 · 具体 DDL）

### 3.1 统一单据头 `stock_documents`

```sql
CREATE TABLE stock_documents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    legacy_id       INT  UNIQUE,                         -- 老库 O_*.ID 溯源
    doc_type        TEXT NOT NULL,                       -- TRANSFER/OTHER_IN/OTHER_OUT/DRAW/WDRAW/
                                                         -- WASTE/FINISHED_IN/FINISHED_OUT/CHECK
    bill_no         TEXT NOT NULL,
    bill_date       DATE NOT NULL,
    warehouse_id    UUID REFERENCES warehouses(id),      -- 主仓库（调拨=调出仓）
    to_warehouse_id UUID REFERENCES warehouses(id),      -- 调拨调入仓（仅 TRANSFER）
    supplier_id     UUID,                                -- 产成品进仓等可选供应商
    client_id       UUID,                                -- 产成品出仓/领料可选客户
    worker_id       UUID,                                -- 经手人 → employees（迁移留空）
    maker_id        UUID,                                -- 制单 → employees
    approver_id     UUID,                                -- 审批 → employees
    plan_no         TEXT,                                -- 关联生产计划号（领料/进仓，占位文本）
    remark          TEXT,
    total_original  NUMERIC(18,4) DEFAULT 0,
    total_local     NUMERIC(18,4) DEFAULT 0,
    status          SMALLINT NOT NULL DEFAULT 0,         -- 0草稿/1已审/-1红冲
    is_closed       BOOLEAN NOT NULL DEFAULT FALSE,
    source_doc_no   TEXT,                                -- 软关联占位（销售单号等）
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_by UUID, updated_by UUID,
    is_deleted BOOLEAN NOT NULL DEFAULT FALSE, deleted_at TIMESTAMPTZ,
    UNIQUE (doc_type, bill_no)
);
CREATE INDEX idx_sd_type_date ON stock_documents(doc_type, bill_date DESC);
CREATE INDEX idx_sd_wh        ON stock_documents(warehouse_id);
CREATE INDEX idx_sd_status    ON stock_documents(status);
```

### 3.2 统一明细 `stock_document_items`（按年分区）

```sql
CREATE TABLE stock_document_items (
    id              UUID DEFAULT gen_random_uuid(),
    legacy_id       INT,
    doc_id          UUID NOT NULL REFERENCES stock_documents(id) ON DELETE CASCADE,
    bill_type       TEXT NOT NULL,                       -- 冗余 doc_type（分区友好+报表免 JOIN 主表）
    bill_no         TEXT NOT NULL,
    bill_date       DATE NOT NULL,                       -- 分区键
    line_no         INT,
    goods_id        UUID NOT NULL REFERENCES goods(id),
    color_id        UUID REFERENCES colors(id),
    unit_id         UUID REFERENCES units(id),
    unit_rate       NUMERIC(18,6) DEFAULT 1,
    qty             NUMERIC(18,4) NOT NULL,              -- 单据数量（主单位）
    base_qty        NUMERIC(18,4),                       -- 基本量 = qty×unit_rate（库存用，迁移算好）
    price           NUMERIC(18,4),
    amount_original NUMERIC(18,4),
    amount_local    NUMERIC(18,4),
    weight          NUMERIC(18,4),
    gift_qty        NUMERIC(18,4) DEFAULT 0,
    surplus_qty     NUMERIC(18,4),                       -- 盘点盘盈(+)盘亏(-)（仅 CHECK）
    count_qty       NUMERIC(18,4),                       -- 盘点实盘数 NowQTY（仅 CHECK）
    place           TEXT,                                -- 库位（文本，首版）
    upstream_item_id UUID,                               -- 链路：退料→领料明细 等
    source_doc_no   TEXT,
    remark          TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    is_deleted BOOLEAN NOT NULL DEFAULT FALSE,
    PRIMARY KEY (id, bill_date)
) PARTITION BY RANGE (bill_date);
-- 建初始分区 2018–2030 逐年（同采购明细）
```

### 3.3 流水 `stock_movements` + 余额 `stock_balances`（V45 已建，复用）

`movement_type` 扩展约定（SMALLINT，无需改列，仅注释）：
```
1采购入库 2采购退货 3销售出库 4销售退货
5生产领料 6生产退料 7调拨入 8调拨出
9盘盈入 10盘亏出 11其它入 12其它出
13产成品进仓 14产成品出仓          ← 本模块新增（V45 仅到 12）
```
`source_doc_type` = `STOCK_DOC`，`source_doc_id`→`stock_documents.id`，`source_item_id`→明细 id。

> ⚠️ V45 建表时 `stock_movements` **未分区**。为"海量仍快"，建议补一个迁移把它改为按 `transaction_date` RANGE 分区（或上 pg_partman）。首版可不分区（62 万行 PG 扛得住+索引命中），分区作为性能优化项列入。

### 3.4 报表物化视图 `stock_monthly_mv`（月度上卷，加速汇总报表）

```sql
CREATE MATERIALIZED VIEW stock_monthly_mv AS
SELECT date_trunc('month', transaction_date) AS ym,
       movement_type, goods_id, warehouse_id, color_id,
       SUM(qty) AS qty_sum, SUM(amount_local) AS amt_local, COUNT(*) AS line_cnt
FROM stock_movements
GROUP BY 1,2,3,4,5;
CREATE UNIQUE INDEX ON stock_monthly_mv (ym, movement_type, goods_id, warehouse_id, color_id);
-- REFRESH MATERIALIZED VIEW CONCURRENTLY stock_monthly_mv; （每日 cron + 审核触发）
```

## 四、状态机与库存联动（Service 层，去触发器）

```
录入 status=0(草稿) / 1(已审，贴老库"保存即生效")
审核 0→1：同事务内，按 doc_type 生成 stock_movements（direction/type 见 §二决策3/4）+ upsert stock_balances
红冲 1→-1：同事务反向冲销（删/反向流水、余额倒回），单据保留不可删
```

**doc_type → 流水规则（单一参数化 Service 路径）：**

| doc_type | movement_type | direction | 说明 |
|---|---|---|---|
| OTHER_IN | 11 | +1 | 其它入 |
| OTHER_OUT | 12 | -1 | 其它出 |
| DRAW（领料）| 5 | -1 | 生产领料出 |
| WDRAW（退料）| 6 | +1 | 生产退料入 |
| FINISHED_IN | 13 | +1 | 产成品进仓 |
| FINISHED_OUT | 14 | -1 | 产成品出仓 |
| TRANSFER（调拨）| 8 调出仓 -1 **&** 7 调入仓 +1 | 双流水 | 双仓双动 |
| CHECK（盘点）| 每行 surplus>0→9(+1) / <0→10(-1) | 差额 | 盘盈/盘亏 |
| WASTE（损耗）| 12 | -1 | 表空，结构留位 |

> 一个 `applyStockEffect(doc)` 方法覆盖全部 9 类——这正是统一表 vs 9 套表的效率差。

## 五、报表设计（9×2 → 2 个参数化查询）

老库 18 张 `View_O_*` 视图 → 新库全查 `stock_movements`：

- **明细报表**：`WHERE movement_type IN (...) AND transaction_date BETWEEN ? AND ? [+仓库/货品/颜色]`，JOIN 主档带名，分页。分区裁剪命中单年/月，毫秒级。
- **汇总报表**：查 `stock_monthly_mv`，按用户维度（货品/仓库/月/类型）`GROUP BY` 上卷。
- **库存查询/余额**：直接查 `stock_balances`（实时，O(1) 唯一索引）。

> 9 族报表 = movement_type 过滤值不同，**一套报表组件 + 类型参数**即可，UI 上仍是 9 个入口（业务零割裂）。

## 六、老库 → 新库 字段映射（迁移口径）

### 主表（以 `O_OtherOut` → `stock_documents(doc_type='OTHER_OUT')` 为例）

| 老库 | 新库 | 映射 |
|---|---|---|
| ID | legacy_id | 直填 |
| BillNo | bill_no | 直填 |
| BillDate | bill_date | cast date |
| StockID | warehouse_id | `warehouses.legacy_id` 映射 |
| OStockID/IStockID (Transfer) | warehouse_id / to_warehouse_id | 双仓 |
| WorkerID/MakeID/ApproverID | *_id | ⚠️ 留空（人员未对齐） |
| Status | status | 1→1, -1→-1 |
| Total | total_original/local | 直填 |

### 明细（→ `stock_document_items`）

| 老库 | 新库 |
|---|---|
| GoodsID/ColorID/UnitID | 经主档 legacy_id 映射 |
| URate | unit_rate |
| QTY | qty；base_qty = qty×unit_rate |
| STotal/Total | amount_original/local |
| Weight | weight |
| StorgePlace | place（文本，存库位 legacy id 或名） |
| NowQTY/SurplusQTY（盘点）| count_qty / surplus_qty |
| PDrawID（退料→领料）| upstream_item_id |
| SOrderNo/BomItemID/...（多值）| source_doc_no（合并占位文本） |

## 八、复用性设计（未来直接迁新数据）

- **幂等三件套**：`legacy_id UNIQUE`（重跑去重）+ 开头 `TRUNCATE` 同链表 + `ON CONFLICT DO NOTHING` 补录。新账套/新年度数据 → 重跑导出+灌数即迁入，不改代码。
- **统一表的红利**：新增单据类型（如未来"组装单"）= 加 `doc_type` 枚举值 + 一段导出/灌数 + Service 的 `doc_type→流水规则` 映射加一行，**不改表结构、不改报表**。
- **注释规范**：每段 SQL 标注「老库源表 → 新库目标 + 字段映射 + 重跑注意」，未来维护者/我自己直接照搬。
- **校验段**固定输出：各类单据主/明细数、链路挂接数、孤儿数——迁完一眼验完整性。

## 九、风险与待确认

| 风险 | 影响 | 对策 |
|---|---|---|
| **统一表 vs 9 套表**（本设计选统一） | 影响整个模块范式 | ✅ 已决策：统一（更优秀/更快/更易扩展）；与采购"独立表"不冲突，共库存骨架 |
| 人员字段 B_Worker↔employees | 制单/审批/经手人无法落人 | 留 NULL，后续 `worker_legacy_map` 回填（同采购） |
| `stock_movements` 未分区（V45） | 海量后流水查询变慢 | 首版可不分区（索引够用）；列入性能优化：改 RANGE 分区或 pg_partman |
| 调拨双仓 | 流水/余额两仓联动 | 一笔调拨双流水（§二决策3），Service 保证两仓一减一增同事务 |
| 盘点金额 | 盘盈盘亏无单价 | 按 `stock_balances` 均价 `amount_local/qty` 算差额金额 |
| `O_Waste` 空 | 损耗单无数据 | 跳过灌数，结构/枚举留位 |
| 库位 `StorgePlace` | 新库无库位主档 | `place TEXT` 存名/id，后置按需建表 |
