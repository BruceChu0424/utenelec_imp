# 表单草稿自动保护

新建表单填写后，返回、切换模块或替换路由会询问“是否保存为草稿”，提供继续填写、不保存、保存草稿三个选择。编辑过程中持续写入本机存储，页面隐藏时补存。浏览器被关闭、应用被结束后，同一服务器、账号、代操作身份可以从任务中心继续填写。

## 与业务草稿的关系

表单草稿允许缺客户、缺数量、只填备注、无效的半截数字等未完成状态。它保存输入原文、选择、来源 UUID、日期、明细和待上传附件，**不调用业务建单、提交、审批接口**，不占用库存、报工配额或财务额度。继续填写后仍走原来的服务端权限、来源、数量和业务校验。

原有服务端 `status=0` 单据草稿保持原口径。2026-10-11 起区分两种填写：尚未形成任务的新建单据继续使用独立草稿；绑定已有任务的填写快照留在原任务行，状态显示“草稿”，业务分类、任务数量和原始业务状态仍由服务端决定。例如生产中的报工草稿仍属于“生产中”，不移入另一类，也不扣减分类中的任务数。

`effectiveBadgeSummaryProvider` 只将独立新建表单草稿按草稿 ID 去重补入红色数量和总数；任务填写已属于原任务，不另加一张待办。正式单据草稿仍按服务端事实统计。报工单已经保存到服务端时，其占用的可报额度仍须扣减以防重复报工，这与保留任务分类、任务行是两个不同口径。

2026-09-30 展示口径：采购、委外、生产调度任务中心保留一级“草稿”状态，状态内所有单据草稿合并为一张表，不再嵌套单据子分类或“全部／草稿／已审”状态栏。第一业务列为“类别”，通过表头筛选查看某一类；父级搜索和草稿表共用关键词。销售任务中心、钱流管理和仓库资料草稿入口放在右上角，与基础资料、HR、品质、建议箱既有入口统一，使用红色数量徽章。

钱流草稿页合并五类钱流单据与资料草稿；资产/待摊/政策草稿保留在资产工作台。销售草稿页合并订货、出货、退货、报价与资料草稿；原有各业务列表的草稿深链仍可用。仓库资料与手工库存单据保留独立草稿入口；到货登记、质检、拣货、点收、退料收仓等现有任务填写从原任务行恢复。车间“新建草稿”入口只保留未绑定执行段的独立新建填写，不收集报工、领料等已有任务快照。

## 任务填写的恢复

- 原任务 UUID 与批量成员身份决定匹配，不以货品、仓库或同名单位关联。批量快照从任一成员行打开时恢复整份原选择、原输入和已完成进度。
- 已发出但结果未知的请求显示“提交待核对”，保留原幂等键、原命令及已确认结果；不把超时视为失败而重新生成请求。没有安全重放协议的流程只读核对业务结果。
- 服务端任务已完成、取消或离开当前列表时，原工作台仍提供 `TaskDraftRecoveryNotice` 的恢复入口，普通旧填写也不会失去访问路径。未确认请求只能核对；普通未提交填写可继续或按原版本丢弃本机记录，不调用业务删除接口。不生成虚假的库存或业务任务行，也不另建草稿分类。
- 刷新只恢复输入到相同来源身份，仍使用服务端最新数量、库存、权限与版本。来源已变化时保留旧快照；“保留本机草稿，加载最新单据”读取最新来源、建立新的填写身份，不能带着未核对的原命令重开。
- 首次读取来源前即绑定账号与服务器栅栏；账号、代操作身份、服务器改变后的迟到读取和业务回执不更新新身份页面。

无服务端单据的本机草稿列表也使用“类别”首列与表头筛选，不再生成上方的类型胶囊。类别变化、搜索和身份切换都应清理选择；批量删除沿用身份、权限、状态、版本复核。生产计划保留原有批量审核和单事务批量删除；请求期间锁定勾选，完成后再刷新。草稿页和列表草稿状态不提供新建入口，只处理已有草稿。新建单据仍从对应业务入口进入。本机草稿不得调用正式单据删除 API，已创建单据的恢复检查点按业务类型与 ID 合并，避免重复展示或计数。

## 公共实现

- `lib/shared/drafts/form_draft_catalog.dart`：将编辑器类型、标题、模块、恢复地址和创建权限一起登记；页面使用目录描述，弹窗重建复用同一描述，避免各页面重复拼权限。
- `lib/shared/drafts/form_draft_mixin.dart`：初始基线、输入监听、连续快照、恢复、退出确认、身份变化保护、业务提交不确定性保护。
- `form_draft_category.dart` / `form_draft_category_table.dart`：业务分类范围、原始字段筛选、草稿行与业务行合并、恢复与删除。本机行不会伪造业务 DTO 或进入业务删除接口；服务端列表加载失败时仍保留本机草稿入口，不隐藏已保存内容。无已有单据表的分类用同一列表，以首列类别提供表头筛选。
- `draft_workspace_table.dart`：异类业务草稿的公共单表，统一类别筛选、关键词搜索、恢复和批量操作；每种来源独立读取，读取失败保留其他来源与本机草稿。
- `form_drafts_page.dart`：右上角草稿入口和落点注册；业务计数已含本机草稿，仅补入未归入这些业务类型的资料草稿。
- `lib/shared/drafts/form_draft_navigation.dart`：`DraftAwareGoRoute` 将路由离开保护接到公共守卫。按页面实例 key 注册，同一路径多层编辑互不串扰。
- `lib/shared/drafts/form_draft_store.dart`：服务器、用户、实际代操作人隔离；登录纪元仅作异步操作栅栏，不进入持久键，以便重新登录恢复。只读模拟身份不读写草稿；恢复同时检查创建权限和路由权限。
- `form_draft_storage_web.dart`：IndexedDB 事务保存，支持大于 localStorage 限制的原始附件；比较版本和写入在同一事务完成。
- `form_draft_storage_native.dart`：应用支持目录，逐记录文件锁、临时文件落盘与替换；不使用业务数据库。
- `form_draft_dialog_resume.dart`：基础资料弹窗通过宿主页 query 重建，保留分类和父级身份。
- `PendingAttachmentController.exportDraft/restoreDraft`：保留附件原始字节、分类和已确认上传的目标，拆单上传重试只补缺失目标。

两个网页同时编辑同一草稿时，过期版本写入和删除会报冲突，不覆盖较新的内容。正式保存成功后用完成标记替换草稿数据，避免迟到的自动保存重新生成已提交草稿。

2026-10-04([ADR-151](../99-决策记录-ADR/ADR-151-表单草稿回到初始值单重参数结构化契约与入库登记单批合一.md) §1)：编辑回到页面初始值(例如多行表格取消勾选再勾回)时，自动保存调用 `FormDraftsNotifier.discardClean`，只把活动记录换成不含输入的「已丢弃干净」标记(`lifecycle=DISCARDED_CLEAN`)，不写「已删除」墓碑；同一页面之后的自动保存和提交前检查点照常写入同一草稿编号，仍拿着旧版本号的其它标签页依旧判冲突。只有用户选「不保存」或在草稿列表删除(`delete`)、以及确认提交完成(`complete`)才是终态；「上次提交结果未知」的草稿既不能删也不能丢弃。提交失败时用 `describeSubmitError(error, fallback:)` 显示真实原因，提交路径不许 `catch (_)` 吞成通用句。

## 新页面接入契约

1. State 混入 `FormDraftMixin`；从 `FormDraftCatalog` 或已有单据领域配置取得 `FormDraftSpec`，提供 `captureFormDraft`、`restoreFormDraft` 和所有可编辑控制器/行的 `formDraftListenables`。不要在页面重新声明草稿权限。新建单据与已有任务的填写态可以启用，纯查看/终态不能产生新的填写快照；不得把密码、令牌或临时登录凭据放入快照。
2. 初始化默认值及来源后调用 `initializeFormDraft()`。动态增加行后要让监听集合包含新行所有可编辑控制器。`setState` 和声明的监听会统一触发保存。
3. 快照保留原文，不通过 `double.tryParse`、提交 body 或 `validate` 转换；UUID、上游分配、冻结版本、手动覆盖标记和显式取消勾选均不能丢。
4. 新建业务写用 `runFormDraftSubmission` 先落盘提交意图。只有持久化的服务端幂等键或已经创建的记录 ID 能证明安全重放时才允许 `formDraftCanReplaySubmission`。超时不自动换键、不重新建单；无法证明时保留原始输入并提示核对已有单据。
5. 已取得业务 ID、拆单 ID 和附件重试上下文后，用 `checkpointFormDraftAfterCreation()` 保存确认创建的检查点。业务操作成功且附件处理完成后调用 `completeFormDraft()`，再导航。成功的业务写不能因为本机暂存或清理失败被当成建单失败重试。
6. 页面返回 `withFormDraft(child)`。普通 Navigator 弹层需禁用无保护的遮罩关闭，取消按钮调用 `confirmFormDraftExit`，并传宿主路由的 pageKey。弹层草稿必须有可重建的持久路由，不能只靠内存 `extra`。
7. 同页继续登记下一批时，在服务端刷新后调用 `resetFormDraftAfterSubmission()` 建立新身份和基线；仍未提交的手动输入另行保留并再次快照。

保存修复：正式创建前的检查点仍使用会抛出失败的 `saveFormDraftNow()`；取得真实业务 ID 后改用 `checkpointFormDraftAfterCreation()`，本机暂存失败不能误报建单或附件上传失败。公共写入器先注册唯一 Future，再合并自动保存与显式保存；等待者不能重新启动第二个写入器。`completeFormDraft()` 完成后的导航先于忙碌状态判定放行，避免页面在 `finally` 尚未清 `_saving` 时被自己的退出守卫挡住。已创建单据锁定原表头和明细，附件只在实际失败时显示重试提示；继续办理复用已创建 ID。

## 持久性边界

### 2026-10-11 逐模块呈现核查

| 页面或流程 | 判断及呈现 |
| --- | --- |
| 销售报价、订货、出货、客户零星发货、退货新建 | 新建独立单据，保留销售草稿页及对应列表草稿状态 |
| 采购订单、申请、收货、退货新建；委外订单、询价、申请、收退货、余料退料、报废新建 | 新建单据仍保留独立草稿；已有来源引用不等同于已经存在的办理任务 |
| 钱流收款、付款、费用、其它收入、转账；报销；资产、待摊、资产政策 | 保留原有独立单据草稿及各工作台入口 |
| 生产计划、独立新建日报 | 保留原有单据草稿列表与服务端草稿，不将独立新建日报误判为车间任务填写 |
| 我的车间任务中的报工、领料、材料发现、追加用料、比例调整、执行段余料退仓 | 原执行段行标草稿并恢复，仍留在开工准备或生产中的真实业务分类；正式未审核日报继续占报工额度 |
| 未绑定执行段的全计划退料或独立新建车间单据 | 无安全的单一任务锚点，保留“新建草稿”兜底入口 |
| 采购/委外预计到货登记、产成品送检登记、批量领料发出、材料发现配置 | 按预计到货、日报、领料单或材料申请 UUID 留在原任务行；批量入口恢复完整原成员 |
| 委外拣货单张/批量、销售出库核对单张/批量 | 原待发料/待出库行标草稿；补本机保存，保留实际仓库、库位、重量、数量原文及逐张已完成结果 |
| 合格来料入库单张/批量、待检来料上架 | 原检查结果任务行标草稿；补本机保存，未知结果冻结原入库/上架命令并提供原请求核对 |
| 成品批量点收、生产退料批量接收 | 原点收/收料任务行标草稿；保存原选择、幂等键、实际收料仓与已确认项，不重发已完成项 |
| IQC 单张/批量、FQC 检查单/单任务/批量 | 原待检任务行标草稿，品质任务中心取消独立草稿分类/按钮；同货品不同来源、不同检验任务仍分开 |
| 财务销售订单确认、采购/委外订货审批、报价核价、出货财审 | 既有审核任务输入在原单/审批轮次行恢复；价格、折扣、汇率原文与审核版本绑定；恢复重新核对当前权限与认领 |
| 员工离职办理 | 员工原行提示离职办理草稿，原详情操作续填；人员在职状态仍是真实业务状态，不提前改为离职 |
| 人事证件资料核对更正 | 原人员待办行恢复整份计划填写；绑定原计划及冻结人员版本，密码和二次验证凭据不进草稿；丢回执只读核对原请求结果，过期或已关闭计划只能查看历史 |
| 入职、工资生成、建议、通知、基础资料、字典、分类、部门、岗位、客户地址 | 不是已有业务任务的填报，保留各自新建草稿模式；不将普通资料编辑伪装为任务状态 |
| 只读报表、历史记录、权限与敏感设置 | 不产生办理输入草稿；不添加没有业务意义的草稿分类 |

财务业务审核中心另见[财务业务审核中心](../03-页面/财务业务审核中心.md)：销售首次确认与订单修改确认合为同一大类的不同状态，批准后仍可回到详情；反审复用原单权限与下游预检，不以列表状态代替反向交易。

同类审核与历史入口还核对了库存盘点、工资条、报销、超产比例、追加用料、超限处置、访客审批与人事资料申请。已有终态和反向能力的继续复用；没有独立反审协议的通过原业务更正、撤回或重新盘点办理，不增加只改状态的按钮。修复报销待付款链接误入待审批队列、人事申请撤回记录缺入口、资料核对记录入口/分页与过期后只读回看问题。生日和周年已经送出祝福的人员仍保留原行，但不继续计入待办红数。

草稿保存在当前设备/浏览器，不是跨设备云草稿。清理浏览器站点数据或卸载应用会删除本机草稿。突然断电只能恢复已经完成持久事务的内容，不能保证断电瞬间尚未落盘的最后输入。自动保存静默进行，不占页面空间（2026-10-24 起不再显示底部状态条）；退出时选择“保存草稿”若落盘失败，页面留在原地并弹瞬时错误提示，不会直接离开。

验证包含公共生命周期、原始字段/附件恢复、登录作用域、版本竞争、退出三种选择、存储失败、提交完成标记、真实销售/财务/仓库页面恢复、徽章去重和任务中心导航。此功能为客户端改动，不需要数据库迁移，也不表示已部署到服务器。
