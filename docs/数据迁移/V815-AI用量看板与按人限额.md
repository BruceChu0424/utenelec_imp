# V815 AI 用量看板与按人限额(ADR-164)

> 编号说明: 本迁移开工时取临时号 V814, 并入 main 时同分支任务A的操作记忆迁移已改号为 V814、main 又有 `V812__permission_surface_hierarchy_and_gaps.sql` 与 `V813__ai_use_baseline_for_everyone.sql`, 故重排为 **V815**, 本文件与 ADR-164 §十 的引用已同步。本文不代表业务数据库已经安装。

## 做了什么

- **新表 `ai_user_limits`**: AI 助手按人限额与停用, 一人最多一行(无行=默认: 不停用、无限额)。列:
  - `user_id` uuid PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE(账号删除连行删);
  - `disabled` boolean NOT NULL DEFAULT false——管理员设置的停用开关, AI 任务提交(`AiJobService.submit/submitStructured` 的 `requireEnabled`)与模型调用前强制;
  - `daily_token_limit` bigint CHECK(IS NULL OR > 0)——NULL=跟随全局每日 token 预算, 由 `AiGateway.attempt` 在全局预算检查之后比对 `todayTokens(userId)`;
  - `daily_job_limit` int CHECK(IS NULL OR > 0)——NULL=跟随全局每人每日 60 任务, 由 `AiJobService.requireWithinLimits` 覆盖;
  - `row_version` bigint NOT NULL DEFAULT 0——乐观锁(管理保存 CAS, 首建传 `expected<0`, 冲突 409);
  - `updated_by` uuid / `updated_at` timestamptz NOT NULL DEFAULT now()。
  - 表注释写明: ADR-164; 空限额=跟随全局默认; disabled 由管理员设置, 提交与调用前强制; 乐观锁 row_version。
- **新表 `ai_usage_daily`**: 用量按人按日汇总(rollup)。列: `user_id` uuid NOT NULL、`usage_date` date NOT NULL、`calls/ok_calls` int NOT NULL DEFAULT 0、`input_tokens/output_tokens` bigint NOT NULL DEFAULT 0; PRIMARY KEY (user_id, usage_date); CHECK 四列非负; 索引 `idx_ai_usage_daily_date(usage_date)`(月/年窗口按日期段扫)。
  - **无 FK 到 users**: 用户删除后统计行保留(年视图要完整), 看板展示名回退「已删除员工」; 表注释写明由定时任务从 `ai_call_logs` 归档汇总、支撑日/月/年视图。
- **审计登记**: `ai_user_limits` → `fn_audit_track_table('ai_user_limits', 'FULL', 'authorization', false)`(照 V670 给 `user_permission_overrides` 的先例, 授权类配置表整行进审计); `ai_usage_daily` → `fn_audit_track_table('ai_usage_daily', 'NONE', 'data_change', false)`(纯计数, 行由汇总任务写)。
- **`business_data_reset()` 登记**:
  - `('ai_user_limits', 'PRESERVE')`——管理员给账号做的配置(谁被停用/谁被限额)随账号存在, 照 `user_preferences` PRESERVE 口径; 以 V462 登记的 `('user_preferences', 'PRESERVE')` 为锚点用 DO 块扩展(执行前 grep 确认该锚点在现存函数定义中唯一);
  - `('ai_usage_daily', 'CLEAR')`——用量统计是测试会产生的流水, 照 `ai_call_logs` CLEAR 口径随测试数据清掉; 以 V742 登记的 `('ai_call_logs', 'CLEAR')` 为锚点(同样验证唯一——任务A的 V814 锚点是 `('ai_chat_action_proposals', 'CLEAR')`, 不冲突)。
  - 两个扩展 DO 块都带「锚点计数==1 且本表尚未登记」双重守卫, 末尾自检 DO 块核对两表存在与两条登记在位(照 V814 写法, `chr(13)` 剥离后再比对)。
- **存量回填**(同迁移内): `INSERT INTO ai_usage_daily(user_id, usage_date, calls, ok_calls, input_tokens, output_tokens) SELECT user_id, (created_at AT TIME ZONE 'Asia/Shanghai')::date, count(*), count(*) FILTER (WHERE ok), coalesce(sum(input_tokens), 0), coalesce(sum(output_tokens), 0) FROM ai_call_logs GROUP BY 1, 2 ON CONFLICT DO NOTHING`——`ai_call_logs` 现存的 180 天历史一次进汇总, 看板上线第一天就有趋势。
- 不加权限点(管理面复用超管 + `authorization:manage` + step-up), 不改存量数据。

## 口径

- **限额空=跟随全局**: 两个限额列 NULL 都表示「跟随全局默认」(全局每日 token 预算 / 每人每日 60 任务), CHECK 拒绝 0 与负数——「跟随全局」是空值不是 0。
- **停用是账号级开关**: `disabled` 只由管理员经 `PUT /admin/ai/usage-people/{userId}/limits` 设置(step-up + row_version CAS); 拦在全部 AI 任务的公共提交闸, 运行中任务不追溯。
- **今日实时、历史汇总**: 限额判断与看板「今日消耗」实时查 `ai_call_logs`(有 `idx_ai_call_logs_user_created`), 不读本表; 本表只服务 >1 天的窗口(日=近 30 天、月=近 12 自然月、年=近 5 自然年)。时/日/月/年与 `todayTokens()` 统一按 `Asia/Shanghai` 定日界。
- **rollup 幂等**: 定时任务(`AiJobHousekeeping.purge()` 追加一步)终日回填 `generate_series(表内最大已完成日+1, current_date-1)`, 今日整日重算 `ON CONFLICT (user_id, usage_date) DO UPDATE` 覆盖——重复执行计数不变。
- **用户删除后行保留**: `ai_usage_daily` 不随 users 级联删, 展示名回退「已删除员工」; `ai_user_limits` 随账号级联删除(配置没有离开账号的意义)。

## 清理与保留

- 清空业务数据(`business_data_reset`): `ai_user_limits` PRESERVE——测试清空不把「谁被停用/谁被限额」清掉(否则被停用的测试账号恢复使用); `ai_usage_daily` CLEAR——测试产生的假用量随测试数据清掉, 不留假账。
- `ai_call_logs` 自身的 180 天分区留存(ADR-105)不变; 更早的 `ai_usage_daily` 行长期保留(年视图的数据来源), 由本表自身承担长周期, 不受明细归档影响。

## 回滚注意

- 单向 Flyway 无下行迁移; 手工恢复演练时 **先移除 `business_data_reset()` 里本表的两条登记(`('ai_user_limits', 'PRESERVE')` 与 `('ai_usage_daily', 'CLEAR')`), 再 DROP TABLE**——顺序不能反, 否则函数引用不存在的表(PRESERVE/CLEAR 两段都要清, 只清一条剩下的那条同样悬空)。
- `ai_user_limits` 里是管理员配置, DROP 前如有生产数据先导出; `ai_usage_daily` 可由回填语句从 `ai_call_logs` 重建, 但只能重建 180 天留存以内的部分, 更早的历史行丢了不可再生。
- 回滚应用前先停用对应的限额/停用检查(`AiJobService.requireEnabled`、`AiGateway` 个人限额段)与 rollup 步骤, 否则服务在缺表状态下每次 AI 提交/调用都会报错。

## 验证(随实现收口)

- 迁移自检: 全量迁移链在真实 Postgres 上通过(两个扩展 DO 块的锚点守卫与末尾自检), `business_data_reset()` 执行后 `ai_user_limits` 行数不变、`ai_usage_daily` 清空。
- 回填对账: 抽样几个用户/日期, `ai_usage_daily` 与 `ai_call_logs` 同日聚合逐列相等(Asia/Shanghai 日界)。
- rollup 幂等: 连续执行两次计数不变; 空表首跑从 `ai_call_logs` 最早日开始。
- `BusinessDataResetSqlContractTest` 运行时扩展登记 814(迁移头版本对由编排者统一登记); `AuditTriggerCoverageMigrationContractTest`、`SchemaIndexHygieneContractTest`、`ForwardMigrationSequenceContractTest` 照常通过。
