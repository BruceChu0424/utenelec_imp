| ADR-101 | [委外单一子层级：按到货解锁、分批发料与容差自动结案](ADR-101-委外单一子层级按到货解锁与容差自动结案.md) | 已决策(2026-09-21，V642，零新增权限码)；接办 ADR-085「活动 BOM 恰好只有一个叶子子件的委外件直接发那颗子件」这一形态——它此前在两个方向上同时是坏的：财务一批准就无条件给仓库派活(全链没有一处查过那颗子件的库存，只有仓库最后保存草稿那一下被拒)，而仓库出仓页没登记这种流向，于是「已备齐 1000」与「本次最多 0」并排显示、有货也发不出去。解锁点改成**有货才派活**：一件都没有就不建出仓草稿、不发通知、不进红徽章(按 ADR-100 属「在办但还不用我动手」的黄色档)；那颗子件采购入库的那一刻自动叫醒等料的出仓行，补草稿并通知「现在可发 N」。草稿数量按「计划余量与该仓此刻合格可动用量的小者」截断、并替仓库选一个真有货的作业叶仓，子件陆续到货就分批发、同一张草稿直接改大；明细表新增「仓内可动用」列排在「本次最多」前面，出仓单列出「回厂交回的委外件」。回厂侧两条口径修正：料没全部发给委外商时一律不判短交、短交的入库锁从整张订货单收到单行；料发完且累计回厂落在本单约定的允许损耗范围内时，仓库确认入库当场按接受损耗结案(损耗单 → 案件 → 受控改量)，推翻 ADR-098「不做容差内自动结案」——允许损耗本身就是双方事先谈好的「交到这个数就算交完」。多交回的部分不再被守恒闸整笔拒收，改判为「委外商贴了自己的材料」，走 ADR-019 的到货异常转财务审核组定案价格与归属，只把财务已批准的那份自带料从守恒台账里摘出去(V642)，没有财务批准一个字节都进不了库。需求侧按用户口径「需要的也要减去公共的」：委外件可以**吃**别人计划里的公共在途(下达那一刻自动认领)，仍不可以**造**自己的公共超量备货；认领候选口径收成同路线，与界面提示对齐。「还需安排」要不要直接显示净数由物料分析主表那一路落成独立字段，本决策不动该字段(它同时是两处数量上限)。不做跨路线认领、不放开委外件的公共超量备货、不做 BOM 深度 ≥ 2 的多层直接外发；这一形态自身的出仓 → 回厂 → IQC → 入库全链 E2E 与 Flutter 用例仍缺，发布 **NO-GO** |
