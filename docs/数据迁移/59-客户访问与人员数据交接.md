## 数据语义

- `clients.owner_employee_id`：当前负责人，可转移；新客户不得为空。
- `client_visibility_grants`：单客户额外只读查看，不授编辑/删除/状态/指派。
- `user_data_scopes`：按 raw 负责人整批额外查看，只读；每行由数据库写 owner 当前 rehire 计数。同任职期有效，owner 复职后旧行仍留审计但读取/CAS/client scope 转换均忽略；管理员 replace 先删该 recipient+scope 的所有旧代际再插当前代际。
- 客户交接例外：客户 owner 会从 A 变 B，因此 client scope A 的有效接收人仅对本批转出客户生成逐客户 grant，然后删除 client scope A；不得改成 B。
- `client:view:all` 是显式全量数据范围；与功能 edit/delete/status 同时存在时可操作全量对象。普通销售默认不持有。
- `employee_data_handovers.requested_scopes`：人工命令明确选择的 1–8 个范围，用于 payload 幂等与回执；空集合 fail-closed，不解释成全部。
- `employee_data_handover_scopes`：只有存在真实业务责任或历史访问的 effective graph scopes；认领释放、直属下级改接、client scope 授权转换等非业务 owner 影响不得凭空生成八条未来路由边。
- `employee_offboarding_events`：独立 `id` 供通用审计 target，`request_id` 唯一；保存来源与默认接手人任职代际、日期、稳定离职类型、原因、四项确认、结果摘要和 `EXECUTING→COMPLETED` 状态。审计中心 before/after 不重复保存 HR reason，源表仍保留。
- `employee_data_handovers` + effective scopes：每条边保存 source/target 双端任职代际。先在 source 当前代际内取该 scope 最大 sequence 的唯一边，再校验该边 target 当前代际；失败即无边，不回退旧 target。
- `employment_history`：只允许 INSERT；UPDATE/DELETE（包括旧 employee FK cascade）由 V398 拒绝，是任职代际的追加式权威。
- `maker_id / approver_id / created_by / audit actor`：历史事实，永不因交接改写。

历史客户 owner 为空不在迁移中猜测归属。迁移后它们进入“待分配”，由持 `client:assign` 的人员逐项确认；不得按分类名、地区、姓名或当前登录人自动回填。

## 目标库迁移前盘点

```sql
SELECT count(*) AS unassigned_clients
FROM clients
WHERE is_deleted = FALSE AND owner_employee_id IS NULL;

SELECT employee.id, employee.code, employee.full_name, employee.status,
       count(client.id) AS client_count
FROM employees employee
JOIN clients client ON client.owner_employee_id = employee.id
WHERE client.is_deleted = FALSE
GROUP BY employee.id, employee.code, employee.full_name, employee.status
ORDER BY employee.status, client_count DESC;

SELECT department.code, permission.code
FROM department_permissions assignment
JOIN departments department ON department.id = assignment.department_id
JOIN permissions permission ON permission.id = assignment.permission_id
WHERE permission.code IN ('client:view:all', 'sales:view:all')
ORDER BY department.code, permission.code;
```

结果属于权限/客户证据，不得复制真实姓名、客户清单或业务 UUID 到源码、普通日志或聊天。

## 验收矩阵

1. 销售 A 看不到销售 B 的内销、外贸、OEM 客户；列表、搜索、dict、facets、详情、导出和 picker 一致。
2. 单客户 viewer 能读该客户，不能读同 owner 其它客户，也不能编辑、状态、删除、改负责人或地址。
3. `client:assign` 仅超管/显式个人 grant 可用，能处理待分配客户；普通 client editor 无该权限且不能在通用表单改 owner。
4. 手工 raw owner scope 只读并允许离职历史 owner；正式 handover scope 可在功能权限允许时处理来源员工历史单据。
5. 离职有阻塞项时整批 409，账号和业务数据不变；成功时客户等责任转移、maker/审批/审计不变。
6. 同一 scope 两名管理员并发保存时，后提交者 expected-set 冲突并刷新，不静默覆盖。
7. 离职与新 owner/share/data-scope 并发时，责任指派等待 employee 行并在 resigned 后失败。
8. client scope A 交接只展开到 A 实际转出的客户，接收人看不到 B 原有客户；每个客户版本只推进一次且事件保存最终 viewer 集合。
9. `LEGACY-FIN-CL-*`、软删除行和不可见 owner 不进入默认 total/facets/dict/候选数量。
10. claims-only、supervisor-only 或仅 client scope 授权的人工全量命令保留 requested scopes，但不生成无数据 effective graph 边；零影响 execute 返回 409。
11. requested scopes 重复/越白名单、effective child 不在 requested、父批次已完成后补 child、任职历史改删均由数据库拒绝。
12. A 已 sales→B、production→C 后离职默认选 D，B/C 仍分别接手已有范围，D 只接剩余/失效范围；source/target 任一复职使旧边失效，且最新 target 失效不得回退更旧 target。
13. 离职成功停用个人 override、作为接收人/授权人的经理委派和 remote access，清临时凭据及未完成上传会话并强制改密；复职不自动恢复这些授权。
14. 同 requestId+同 payload 仅在 source/default-target 任职代际仍匹配时幂等；任一端复职、异 payload 或旧任职 requestId 返回 409。
15. `employee_offboarding_events` 的 audit target_id 等于事件 id，before/after 不含 reason/handover_reason；源事件表原因仍可按HR权限审计。

## 发布边界

空库执行 V1→V399、JPA validate 和本地测试只是候选证据。公司目标库必须先核对 live `flyway_schema_history` 和精确迁移字节，在恢复副本做非空升级和权限前后对账；禁止 `flyway repair`、手工改 history、旧 JAR 回滚或在目标库直接补 owner。
