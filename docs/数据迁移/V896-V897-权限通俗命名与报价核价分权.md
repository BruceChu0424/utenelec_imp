# V896 / V897：权限通俗命名与报价核价分权

V896 保留 `sales_quote_finance:confirm`，将其职责收窄为修改财务核价和确认报价；新增 `sales_quote_finance:reject`（退回销售报价）和 `sales_quote_finance:reverse`（重新核价销售报价）。三者都要求查看报价核价任务。只有确认或退回资格能认领待核价任务、接收待核价通知，重新核价资格只负责打开已确认且未转订货的报价。

同时将资产和长期待摊的撤销计提入账拆为 `finance_asset:reverse`，原 `finance_asset:post` 保留启用、计提预览及提交和正常入账。撤销批次的发起及最终入账均须撤销权限，审批仍需独立审核权限和不同经办人；撤销权限沿用原只能逐人授权的高风险策略。

迁移在同一事务中锁住授权目录和来源，复制原确认权限对应的部门配置、个人加授和收回、中性失效记录、页面映射及负责人委派。既有模板同步补齐拆出的权限并推进版本，已删除模板保留原历史。原授权策略、敏感级别和基础包配置跟随源权限，不给原来没有权限的人新增能力。

目录新增和授权复制会推进全局权限版本及部分账号版本和委派代次。迁移先保存版本快照，仅对迁移前匹配的委派快照逐项跟进；原本不匹配的纪元、账号版本或委派代次保持失效，关闭的委派保持关闭。组织、员工和委派范围代次不变。迁移中只暂缓负责人委派表自身的账号版本触发器，避免重定位时级联变更，事务内恢复；全局纪元仍使旧权限令牌失效，审计触发器不暂停。

V896 同时扩展 V875 的展示字段排除规则，修改 `name` / `description` 与原有模块、分组、顺序一样不再推进权限纪元。动作分类、授权策略、敏感级别、基础包和未来新增的授权字段默认仍触发失效。V897 只改名称和说明，不改权限码或 UUID。业务单据叫反审，报价叫取消，真实财务反向处理按动作叫撤销入账、撤销抵扣等，不删除原账务记录。

真实 PostgreSQL 升级回归入口为 `PermissionCatalogPlainNamesPostgresTest`：从 V895 的非空授权配置升级，使用 `PermissionResolver` 比较升级前后真实有效权限，覆盖个人收回优先、失效委派不恢复、双方账号代次更新、模板版本、原权限身份和安全字段不变、纯文案修改保留委派、真正授权变化仍失效。报价分权流程、任务认领、通知和页面行为由独立后端及 Flutter 回归验证。
