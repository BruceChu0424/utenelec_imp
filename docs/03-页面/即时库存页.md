## 一、定位

对标老系统「即时库存」窗口的**看盘视角**：按货品大类浏览当前库存，按仓库维度切换。
分类用 `UtenFilterToolbar` 分段胶囊，点选大类=后端按子树汇总；分段由
`/tree?withGoodsCounts=true` 提供**子树货品数**，零货品的一级分类不显示
（后端未给计数时不隐藏，向后兼容）。页级搜索框按**货品名称/编号/型号/客户型号**
模糊检索（后端 keyword 同口径，300ms 防抖）。表格展示库存数量 /
库存重量 / 待检量 / 合格待入库 / 多排数量；仓库下拉「全部」表示参与核算仓库聚合，
选**主仓库**表示该主仓子树聚合（两者在全部仓都挂主仓下时等价，但语义分开保留）。

与「库存查询（余额）」页的区别：余额页按仓+货+色逐行、供仓管对账；本页按货品+颜色聚合、
带分类分段与多排视角，供 PMC/管理层看盘。

本页的聚合行只用于查询，点击后进入货品库存详情，不在跨仓聚合数量上修改库存。授权余额调整
只能从 [`/stock/balance` 的单一余额详情](库存列表页.md)发起，避免一次操作误改多个仓库维度。

## 二、入口与导航
- 进入：仓库管理 hub「即时库存」卡片。
- 离开：返回仓库管理 hub（`UtenBackButton` 指定 `/warehouse`）。

## 四、数据链路

```
分段：/api/master/material-categories/tree?withGoodsCounts=true
      （同一端点，只取一级分类；无子级根自成一段；零货品分类隐藏）
搜索：GET /api/stock/instant-inventory?keyword=（name/code/model/c_number 模糊）
右表：GET /api/stock/instant-inventory?categoryId=&warehouseId=&includeDefective=&keyword=&page=&size=&sort=&order=
      └ goods 货品驱动 LEFT JOIN stock_balances 聚合
        —— warehouseId=叶子仓：精确单仓；=主仓库：自身+全部子仓（服务端
           WarehouseScopeService 展开，is_accountable 与不良仓开关口径同「全部」）；
           null=全部（仅 is_accountable 仓库）
        —— 无余额货品也列出（库存 0），与老系统「分类下全是内容」一致
        × material_categories（所属类型）× colors / units（名称解析）
        × production_plan_items 可排余量预聚合（多排数量）
```

- 数量/重量：余额表当前值（历史=StockGoods 最新年 FactQTY/FactWeight 迁移，V80；
  增量=单据审核同事务联动，仓库单据含重量，盘点不联动重量）。
- **库位号列**：读货品主档 `goods.stock_place`，V451 起由实际入库学习回写保持最新
  （到货登记 / IQC 合格品入库确认 / 产成品登记「记住库位」，见
  [迁移说明 66](../数据迁移/71-IQC入库库位学习.md)）；同一货品多仓不同库位时，
  待入库预填仍优先按仓库×货品偏好，主档值只是全局回退建议。
- **库存台账金额（V421 口径，页面已不展示）**：`stock_balances.amount_local` 按
  货品+颜色聚合，来自已审核库存流水及其红冲/调账事实。本页 2026-09-01 起不再渲染
  该列（持 `goods:cost:view` 亦然），排序候选同样移除；后端字段与导出能力保留。
- 排序白名单：qty / weight / moreQty / pendingQty / name（默认数量降序）；
  `costAmount` 排序键已不随本页发送。
- 仓库下拉「全部」= 6 个真实仓（IsCal=0 参与核算，2026-07-28 修反转 bug）；幻影仓可单选。
- **主/子层级（V476）**：下拉按「顶层仓在前、子仓缩进」分组展示；主仓库（父仓）
  可选=子树聚合；叶子仓=精确单仓。单据页同款下拉里父仓置灰不可选——本页是唯一
  允许父仓聚合的库存查询入口之一（余额/流水查询同口径）。
- 「含不良品仓」开关（V81 `warehouses.is_defective`，按名称识别）：默认开=老系统口径
  （不良仓计入全部）；关掉即剔除 成品不良品仓/原材料不良仓；**仓库=全部或主仓聚合时
  生效**，选定叶子仓时置灰。**选择按账号服务端持久化**（`user_preferences` key
  `stock.instantInventory`，模式同工作台布局：本地缓存即时渲染 + 登录后服务端同步 +
  防抖 800ms 推送，provider：`lib/features/stock/providers/instant_inventory_prefs_provider.dart`）。
- **加密 Excel 导出**：`UtenExportButton` → `POST /stock/reports/export`（report=`instant-inventory`，
  后端 `StockReportService.export` 独立分支复用同款查询全量分页拉取，父仓聚合口径同步生效）；
  五道防线齐备：`stock_report:export` 独立权限（V71 已种子）+ 限流拦截器 + Agile AES-256 密码
  + 10 万行上限 + 审计（`export_stock_report`）。导出再次检查 `goods:cost:view`；无权时
  **整列移除**库存台账金额，而不是输出空白表头——导出口径独立于页面展示。

## 六、功能点
1. **分类分段**（`UtenFilterToolbar<String?>`）：「全部」+ 一级分类 + 无子级根；
   父类分段 = 子树汇总；**零货品分类不显示**（计数来自 withGoodsCounts；计数缺失
   时不隐藏）。进页面默认不选（数据等价于不过滤）并直接加载第一页；
   点「全部」段回到全量。分类树加载失败只降级为「全部」一段并在工具栏下给
   行内错误 + 重试，不阻塞库存表。
2. **页级搜索**：名称/编号/型号/客户型号模糊（300ms 防抖），与导出/打印口径同步。
3. 仓库下拉切换即重查（主仓=子树聚合）；刷新按钮重查当前页。
4. 表头设置列多时显示明确的竖向滚动条，库存数量、库存重量、待检量、合格待入库、
   多排数量均可独立显示/隐藏；每个选项至少 44dp 高。
5. 数量/重量/多排数量/名称支持表头排序（回第 1 页）。
6. 数字列格式化：最多 2 位小数去尾零；null 显示「—」。
7. **行点击 → 库存详情页**（`RouteName.stockItemDetail(goodsId)`，push 保活本页筛选）：
   单货品各仓余额 + 出入库流水。
8. 加密 Excel 导出（report=`instant-inventory`，导出参数与当前筛选/排序/不良仓开关/
   搜索关键词同步）。

## 七、权限与边界

- 页面与聚合查询使用 `stock:view`；分类分段仍由 `material_category:view` 控制树端点。
  加密导出另需 `stock_report:export`。
- `goods:cost:view` 不再改变本页任何可见内容（2026-09-01 起页面与预览打印均无
  库存台账金额列）；该权限仍决定导出 Excel 是否含金额列。
- 本页不显示 `stock:balance:adjust` 操作，不能在聚合行直接修正库存。
- 数量、重量与金额是三类独立库存事实。数量调整不得伪造标准成本估算；只有携带金额的
  已审核库存流水才改变 `stock_balances.amount_local`。数量与金额不匹配时必须走库存
  价值核对。详细调整、审计和历史订单规则见
  [仓库盘点修正与历史单据处理](../数据迁移/50-仓库盘点修正与历史单据处理.md)。
