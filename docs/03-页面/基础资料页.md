# 基础资料页（货品 / 模具 / 客户 / 供应商 / 颜色 / 基本单位）

> 基础资料管理页：货品/模具/客户/供应商为**分类树 + 主档**双表页（四页同构）；**颜色/单位为扁平主档页**（无分类树，仅 编号/名称/状态 3 字段）。
> 全部共用同一套模块组件（`MasterDataTableView` / `showMasterEditDialog` / `showMasterDetailSheet`），仅字段集 / 文案 / 图标不同。

---

## 一、定位

- **给谁用**：全员可查看；编辑按权限点。
- **解决什么**：制造业核心主数据（物料/模具/客户/供应商）的分类归档与主档维护，承接老库（YTDQ）迁移过来的存量数据。
- **在产品中的位置**：工作台「常用功能」分区，跨部门基础数据底座。

---

## 二、入口与导航

- **进入**：工作台 →「基础资料」卡片 → 基础资料入口页（hub，6 个资料类型卡片）→ 选具体资料类型。
- **返回**：各资料页 AppBar 返回 → 基础资料 hub（`context.go(RouteName.basicinfo)`，不压栈）。
- **路由**（以 `lib/core/router/route_names.dart` 为准）：hub `basicinfo`；货品 `basicinfoGoods`、模具 `basicinfoMould`、客户 `basicinfoClient`、供应商 `basicinfoSupplier`、颜色 `basicinfoColor`、基本单位 `basicinfoUnit`。

> 这些是**四页共用的模块级组件**——改样式只改组件一处，四页同步生效。**不要在页面里复制它们的逻辑。**

| 组件 | 用途 |
|---|---|
| **`MasterDataTableView<T>`** | 主档**通用 Excel 表格**（四页共用）：标题由调用方放标题行；组件内含「横排 autofilter 列头（表头跟随表体横滚、无滚动条）+ 逐行数据（列对齐、底部横向滚动条）+ 分页」。列头下拉锚定列头**下方原位展开、限高 360、竖向滚动**（不全屏）。**翻页（上一页/下一页）后表体竖向回到顶部**。 |

## 五、按钮规范（四页统一）

| 场景 | 组件 | 类型 |
|---|---|---|
| 提交（保存 / 创建分类 / 创建主档） | `UtenActionButton` | primary（自带 loading + 防连点） |
| 新增子分类 / 编辑 / 添加主档 | `UtenButton` | **tonal** |
| 删除 | `UtenButton` | danger |
| 取消 / 关闭 | `UtenButton` | secondary |

约定：
- 操作按钮尺寸 `medium`。
- 分类操作三按钮（新增子分类/编辑/删除）由 `CategoryDetailCard` 渲染。
- **标题行一行三件套**：`Icon + Text（X (N)）| UtenSearchBar（搜索，Expanded 撑满中段）| UtenButton.tonal（添加 X）`。标题用 inline `Icon + Text`（**不用 `UtenSectionHeader`**——其内部 `Flexible(Text)` 在标题行 `Row` 的 unbounded 宽度下会崩）；「添加 X」仅 `_canEditMaster` 时出现。
- AppBar **不再有「+」**；空分类树用 `UtenEmpty(actionLabel:'新建分类')` 兜住顶级新建入口。

## 六、功能点

1. **分类树**：`expandOnRowTap`——点一个**有子类的分类行既展开又选中**（不必只点 chevron 图标）；搜索（命中节点 + 祖先路径自动展开）；按编码排序；CRUD 受分类编辑权限控制。
2. **分类详情卡**（`CategoryDetailCard`）：分类名/编码/层级/子分类数/父级/旧编码/路径 + 新增子分类/编辑/删除。
3. **主档表格**（`MasterDataTableView`）：点任一分类（含父分类）即按**子树范围**加载该分类及其所有后代分类下的主档；横排列头 + 逐行（列对齐）；点行 → `showMasterDetailSheet` 双列详情。
4. **字段 autofilter 筛选**：每个列头是下拉，点开在**列头下方原位**展开（限高 360、可竖向滚动，不全屏）；选项来自 `GET /master/{module}/facets?categoryId=`（子树范围内该字段的 distinct 值 + 计数），含「所有 / 空值(N) / 各具体值(N)」；多列叠加。无对应数据列的下拉只显「所有」。
5. **搜索**：标题行 `UtenSearchBar`，子树范围内模糊匹配（货品匹配名称/编号/型号/规格/系列等），300ms 防抖；与筛选叠加生效。
6. **翻页回顶**：上一页/下一页切换后，表体竖向自动回到顶部（从第一条开始）。
7. **横向滚动**：列总宽超视口时左右滚动看更多列；**底部有滚动条**（表头无滚动条但跟随表体横滚，列始终对齐）。
8. **主档新建/编辑**：`showMasterEditDialog` 双列分组表单。
9. **分类名称建议**：新建分类时常用 `ActionChip` 一键填入。
10. **主档详情**：双列卡片网格；底部编辑/删除/关闭居中。
11. **货品行状态着色**（2026-07-30，仅货品资料）：详情列表按 `status` 着行底色——
    使用=浅蓝、禁用=浅红、其他=白；单击选中把当前色**加深加亮**（`MasterDataTableView.rowColor`）。
12. **货品「来源」属性**（2026-07-30，V128）：基本信息新增来源（自制/采购/委外，
    `goods.source_type`），编辑表单下拉选择；列表有「来源」列可 autofilter；
    详情页有「来源」行。批量回填见 [数据迁移/49](../数据迁移/49-产品列表Excel移植.md)。
13. **「未分类」默认收起**（2026-07-30）：大屏左树「未分类（历史孤儿）」默认不展开
    （`UtenCategoryTreeView.initiallyCollapsedNames`），可手动点开；搜索命中路径不受影响。
14. **默认不预加载**（2026-07-31）：进入页面不再自动选第一个分类、不拉货品列表，右侧空态
    「请选择左侧分类」；点了分类才加载货品/facets/detail（省资源）。`UtenCategoryTreeView`
    新增可选 `visibleFilterIds`（外部受控可见集合），供搜索定位用，其他 9 个复用方零影响。
15. **顶部搜索能搜货品定位分类**（2026-07-31）：左树内置分类名搜索改为页面顶部统一搜索框
    （树设 `showSearch:false` + `header` 自绘搜索框），输入既匹配分类名（命中分类 + 祖先 + 子树），
    又异步全库搜货品（`GET /master/goods?keyword=`，后端归属授权已过滤），命中后自动展开并定位
    到该货品所在分类、右侧打开该分类。依赖后端 `GoodsListItem` 新增的 `categoryId` 字段。
16. **管理页主表只显示正常在用货品**（2026-07-31，V177 更新 2026-08-01）：货品资料管理页主表
    传 `excludeDisabled + excludeStub`，禁用货品与迁移兜底 stub 收拢到顶部集合行（见 18），不混入主表；
    **选货品滑窗**（单据/报表）默认隐藏禁用 + stub（见 [UtenGoodsPicker](../02-组件库/UtenGoodsPicker.md)）。
17. **懒载 + 搜索定位推广到模具/客户/供应商 + 即时库存**（2026-07-31）：三个资料页（与货品资料页
    同构）同样「默认不预载 + 顶部统一搜索搜主档定位分类」——后端 `MouldListItem`/`ClientListItem`/
    `SupplierListItem` 加 `categoryId`，前端各 repository 加 `search()`。即时库存页同样懒载 + 左树搜货品
    定位分类（借 `goodsRepository.search` 拿 categoryId）。树搜索辅助抽到共享 `category_tree_search.dart`
    （泛型 `<T extends UtenTreeNode>`，`DepartmentNode` 亦 implements 复用）。收付款类别页是纯分类树
    （无主档），不适用。
18. **特殊货品集合区 + `auto_created` 标记**（2026-08-01，V177）：迁移脚本为「老库明细引用了
    `B_Goods` 不存在的货品号」建的兜底占位 stub（新库 31 条，`category_id`/`status` 均空），由
    `goods.auto_created` 列标记（范式同 `warehouses`/`currencies`，V177 回填）。货品资料页主表排除
    禁用 + stub，二者归标题行下 `SpecialGoodsCollections` 的两个**默认折叠**集合行：**禁用货品(N)**=
    当前分类子树 `status='禁用'`；**不明货品(N)**= 仅选中「未分类(历史孤儿)」节点时出现（stub 无分类，
    查询强制 `categoryId=null` 走 `stubOnly`，否则 `category_id IN (子树)` 与 `IS NULL` 矛盾返回 0）。
    展开见首页 20 条（定高 `ListView`，避免挤压主表），点条目复用 `_showGoodsDetail`。导出/打印与主表
    同口径（正常品）。后端 `excludeStub` 参数镜像 `excludeDisabled`（`GoodsQueryFilter`/`GoodsService`/`GoodsController`）。
19. **新增货品 = 三 Tab 详情弹窗 + 颜色/单位内联新建**（2026-08-01）：货品「添加」从通用 `showMasterEditDialog`
    改为 mode 感知 `showGoodsDetailDialog`（基本信息/组装信息/成本预算 三 Tab，与查看同款）。基本信息页签可编辑，
    含**颜色/单位下拉内联新建**（下拉浮层搜索下方浅绿「添加」按钮 → 输入名称 → 查重 → 存颜色/单位主档 → 自动选中）；
    组装/成本页签需先保存基本信息拿到货品 id 后激活（两阶段，[31](../数据迁移/31-货品组装BOM与成本预算.md) §七）。
    组件右滑窗选择（`showUtenGoodsPicker(scope: component)`，6 分类白名单）+ 层级添加（选中默认子组件）+ 组件信息只读；
    成本材料合计由 BOM 自动聚合（后端 `recalcSourceE`）+ 下游级联。颜色/单位选项改走 `colorDictProvider`/`unitDictProvider`
    （新建后全局刷新）；**新建颜色/单位后端补合成 `legacy_id`(max+1)** 解开「新颜色无 legacy_id 存不进货品」鸿沟 + 名称查重 409。

## 九、涉及的数据实体

→ 见 [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)

- `UtenTreeNode<T>`（`models/uten_tree_node.dart`）：分类树节点最小契约（`id`/`name`/`code`/`children`/`hasChildren`），`UtenCategoryTreeView<T>` 泛化复用的基础（F-bounded）。
- `ProductCategoryNode` / `ProductCategoryDetail`：分类树节点 / 详情（**四页共用同一套分类模型**，`implements UtenTreeNode<ProductCategoryNode>`）。
- `PaymentStyleNode`（收付款类别，`models/payment_style_node.dart`）：`implements UtenTreeNode<PaymentStyleNode>`，**复用 `UtenCategoryTreeView` 渲染**（左树外观与货品资料一致；顶部 6 大类 ACCOUNT/LIABILITY/EQUITY/EXPENSE/INCOME/METHOD 切换条为页面级过滤，非树组件职责）。
- `MasterFacetBucket`（`models/master_facet.dart`）：通用 facet 桶（四页共用）。
- `GoodsListItem`/`GoodsFacets`、`MouldListItem`/`MouldFacets`、`ClientListItem`/`ClientFacets`、`SupplierListItem`/`SupplierFacets`：各主档列表项 + facet（字段集不同，Facets 用 `Map<String, List<MasterFacetBucket>>`）。
- `GoodsDetail` / `MouldDetail` / `ClientDetail` / `SupplierDetail`：各主档详情。
- 老库迁移溯源见 [数据迁移/](../数据迁移/)（03 货品 / 05 模具 / 07 客户 / 09 供应商）。

## 十、后端接口（主档列表 + facets，四模块同构）

- `GET /api/master/{goods|moulds|clients|suppliers}?categoryId=&keyword=&nullFields=&<字段>=&page=1&size=20` —— **子树范围**（categoryId 含其所有后代分类，复用 `findSubtree` 递归 CTE）+ keyword 模糊 + 字段精确筛选（值或 `__null__`→`nullFields`）+ 分页。
- `GET /api/master/{...}/facets?categoryId=` —— 子树范围内各字段 distinct 值（带 count，limit 50）+ 各字段空值计数（`nullCounts`）。供列头 autofilter 下拉。
- 列表 `Repository` 均 `extends JpaSpecificationExecutor`，`Service.list` 复刻 `EmployeeQueryService` 的 Specification 范式；`facets` 用原生 SQL + 字段→列名硬编码白名单（防注入）。
- 权限：查看 `goods:view`/`mould:view`/`client:view`/`supplier:view`（已授全部门）。

## 十二、边界情况

- **空分类树**：`UtenEmpty` + 「新建分类」按钮。
- **父分类（childCount > 0）**：**不再提示"选具体子分类"**——按子树汇总加载所有后代分类下的主档，筛选/搜索同样在子树范围内生效。
- **横向滚动**：列头用 `SingleChildScrollView(horizontal)` 跟随表体（双向 listener 同步，非 `LinkedScrollControllerGroup`——该类在 Flutter 3.44 已移除）；表头无滚动条、表体底部有。
- **筛选下拉不全屏**：`_FilterCell` 用自定义 `Overlay` + `CompositedTransformFollower`（锚定列头下方）+ `ListView`（限高 360 竖向滚动）+ `TapRegion`（点外部关闭）；替代了默认 `PopupMenu`（项多不滚动、会撑满）。
- **翻页回顶**：`MasterDataTableView` 持竖向 `ScrollController`，`didUpdateWidget` 检测 `currentPage` 变化 → `jumpTo(0)`。
- **无数据列**：表无对应列的字段，单元格显"—"，不进 facets/`nullFields` 白名单（避免原生 SQL 查不存在列报错）。
- **缺失字段（表已迁）**：颜色/单位已迁（`colors`/`units`，V39/V40），货品表「主颜色/单位」列由后端 `GoodsService` 按 `colorLegacyId/unitLegacyId → colors/units.name` 解析显示名称；解析不到（孤儿引用 / `0` 哨兵）回落 `#id`。
- **详情/编辑容器**：自适应——compact 底部抽屉 / medium+ 居中面板（max 宽 560）。
- **闭包 null 提升避坑**：`_showXxxDetail` 里 `XxxDetail? d` 跨闭包边界退回 nullable → 闭包前 `final detail = d;` 捕获 non-null。
- **Jackson 连续大写坑**：`cNumber`/`mWeight`/`fullName`/`legalPerson` 等用 `@JsonProperty` 显式钉死，前端 `fromJson` 兼容大小写两种 key。

## 十三、编号自动生成 + 唯一 + 状态下拉（V77，2026-07-28）

10 个主档（货品/模具/客户/供应商/颜色/单位/币种/仓库/账户/收付款类别）的 **编号(code)** 与 **状态(status)** 统一重构：

- **编号 = 服务端自动生成**：`MasterCodeService`（`common/mastercode/`）原子取号，格式 `[2位拼音前缀][6位]`，如货品 `HP000001`。10 前缀：货品HP/模具MJ/客户KH/供应商GY/颜色YS/单位DW/币种BZ/仓库WH/账户ZH/收付款SK（已验证与遗留 code 零碰撞）。前端新建弹窗编号框**只读**显「保存后自动生成」，不上送；编辑弹窗编号**只读不可改**（业务单据明细靠 code 关联，改不得）。
- **编号全局唯一**：每表全表唯一索引 `<t>_code_uq ON (code) WHERE is_deleted=false`（PG 允许多 NULL）。历史遗留真实重复 code（颜色22/收付款95/账户15/模具1/客户1）在 V77 内**就地 renumber**——每 code 保留首条，其余改 `[前缀][6位]`；货品本就无非空重复。**引用安全**：所有跨表引用走 UUID `id` 或整型 `legacy_id`（如 `goods.color_legacy_id`、`*_items.color_id`），无表按 code 引用，renumber 只改显示编号，引用恒正确（code '01' 下挂 18 个不同颜色名 → renumber 而非 merge）。
- **状态 = 下拉 + CHECK**：保留 `varchar` + `CHECK(status IN ('使用','禁用'))`（不改 boolean，零 API/实体改动）；前端 `master_edit_dialog` 的 select 统一换 `UtenDropdownField`（Overlay 弹层，根治单位/颜色下拉溢出、对齐全站），状态字段 `kMasterStatusOptions`（使用/禁用），新建预填「使用」。`payment_styles` 老库英文 `In Use` 在 V77 归一为「使用」。
- **分类树（materialcategory 等）不在内**：其 code「允许重复」、层级自由命名。

详见 `plans/cuddly-booping-prism.md`；颜色 renumber 细节见 [数据迁移/11](../数据迁移/11-颜色资料-新库与迁移.md)。
