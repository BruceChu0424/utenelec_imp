# 品质任务中心

> 路由：`/quality/task-center`（`RouteName.qualityTaskCenter`）· 实现源：`lib/features/quality/pages/quality_task_center_page.dart` + `warehouse/providers/procurement_inbound_count_providers.dart`（`procurementInspectionPendingCountProvider`）+ `dashboard/widgets/module_badge_sum.dart`
> 上层：[工作台首页.md](工作台首页.md) 的「品质管理部」分区「品质任务中心」卡片
> 数据源：IQC 待检 sidecar（V222）+ 生产 FQC inspection/decision（V410–V415）
> 最近更新：2026-08-28（品质中心同时承接 IQC 与生产 FQC；生产完成仍以仓库实收为准）

## 一、定位

品质管理部任务的统一收口（hub 风格：`UtenAppBar` + `UtenHubCard` 网格）。
首张卡「待检处置」承接采购/委外收货单的 IQC；第二张卡「生产成品质检」承接审核完工申报形成的 FQC inspection。IQC 入口此前挂在仓库
「预计到货任务中心」，2026-08-19 起移交品质部：检验是品质职责，仓库只负责登记到货，
检验通过后自动入库。

- 解决的问题：待检处置入口曾藏在仓库到货任务中心，品质人员要进仓库菜单才能放行；
  移交后品质部有自己的任务中心，仓库侧只读看到「待品质部批准」状态。
- 产品位置：工作台「品质管理部」分区「品质任务中心」卡片；`WorkbenchCardBadge(
  WorkbenchBadgeKind.qualityInspection)` 统一红色数字角标，数据来自
  `procurementInspectionPendingCountProvider`。

## 二、入口与导航

- 进入路径：工作台「品质管理部」分区 → 「品质任务中心」卡片 → `/quality/task-center`。
- IQC 查看/处置：`procurement_inspection:view/handle`，进入 `/warehouse/inspections`。
- FQC 查看/决定：`production_quality_inspection:view/approve`，进入 `/quality/production-inspections`；即使有 approve，服务端仍要求有效品质组织池，失败关闭。

## 三、卡片与角标

| 卡片 | 角标语义 | 点击去向 | 可见条件 |
|---|---|---|---|
| 待检处置 | 仍有 PENDING/PARTIAL 明细的收货单张数（`GET /api/procurement/inspection/pending-count`，60s 轮询） | `/warehouse/inspections` | `procurement_inspection:view` |
| 生产成品质检 | FQC `PENDING/PARTIAL` inspection 数量（`GET /api/production/quality-inspections/pending-count`） | `/quality/production-inspections` | `production_quality_inspection:view` |

- **角标权威口径**是 IQC 与 FQC 两个 `pending-count` 的有权合计；任一请求未知/失败不得伪装成真实 0；
  `PROCUREMENT_IQC_PENDING` 站内通知只负责提示和触发重拉，通知条数/未读数均不参与角标计算。
- 无查看权限者不渲染卡片，页内给出「暂无检验任务权限」提示；服务端接口独立鉴权兜底。
- 即时刷新有两个入口：从待检处置页返回本中心时，`ref.onPageResume` 立即使角标失效重拉；
  返回工作台，或客户端检测到新通知使未读数上升时，外壳的全局角标刷新同样使
  `procurementInspectionPendingCountProvider` 失效并重读 `pending-count`。两者都不等待该角标
  自己的下一轮 60s 轮询；新通知检测本身仍服从当前通知轮询/到达机制，不宣称服务端推送。
- 无查看权限时 provider 直接归 0 且不请求接口；计数请求失败时显示可辨识的同步异常图标与
  “进入待检处置后重试”提示，不把未知状态伪装成真实 0。待检处置页的处置动作仍需
  `procurement_inspection:handle`，本中心只看不处置。

## 四、与仓库侧的分工

- 仓库审核采购收货单/委外进仓单时，在创建 IQC `PENDING` 隔离行的同一事务内追加
  `PROCUREMENT_IQC_PENDING` 业务 Outbox；事件按收货单 UUID 使用 `publishOnce` 幂等，
  同一收货单有多条明细也只产生一个待检通知事件。事务回滚时待检行与 Outbox 一并回滚。
- Outbox 送达只面向 `DEPT_QA` 子树内当前在职、账号启用，且服务端最终有效权限仍包含
  `procurement_inspection:view` 的用户；PMC/生产部门的默认查看权、跨部门个人加授或超管全集
  不扩张品质通知池。仅查看权限即可接收，`handle` 不是接收通知的必要条件；点击进入
  `/quality/task-center`。
- 送达前再次查询该收货单是否仍有 `PENDING/PARTIAL` 明细；若品质人员已在 Outbox 处理前极速
  完成整单处置，则不发布已经过期的待检任务通知。
- 仓库「预计到货任务中心」原「待检处置」卡改为**只读状态卡**「待品质部批准」
  （不筛列表；点击切换卡片下方提示条的品质部口径说明，再点或点「全部待到货」收回；
  角标同口径保留，无 `procurement_inspection:view` 的仓库账号不拉取计数、显示 '—'）。
  同日类型筛选卡（采购到货/委外到货）下线，该页仅保留「全部待到货」+
  「待品质部批准」两张指标卡，卡片内不放说明文字（口径提示统一在下方整行提示条）。
- 检验通过（IQC PASS）后：合格量即时 DIR_IN 入可用库存并刷新命中的活动物料分析；
  每次 PASS 按合格差量推进正式供给齐套，整单终态只最终对账（详见待检处置页文档 §三）。
- 生产 FQC PASS/PARTIAL 的 `pass_qty` 只生成 FINISHED_IN 待点收上限，不直接增加库存或 `iqty`；仓库实收才是生产完成事实。FAIL 进入 REWORK 或 SCRAP/REJECT 补产链，详见[生产成品质检任务页](生产成品质检任务页.md)。
