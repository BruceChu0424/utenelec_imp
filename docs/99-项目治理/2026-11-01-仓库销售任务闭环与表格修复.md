## 已证实的问题与修复

1. 本地两张新订货单中，一张仍为 `NOT_REQUIRED`，另一张为 `PENDING`。旧进程可以在 V978 已应用后继续按旧提交路径写入前一状态。V987 将符合条件的未办结、非导入、未财审新单回到待负责人审核，并在草稿提交的数据库触发器中补齐负责人阶段；不伪造批准、不改变已经完成的财务事实。同步释放已回退单据的财审占用、撤下旧财审提醒。
2. 原订货列表按可用库存将待审核订单归入 SHIPPABLE，任务徽章却单独将未财审 SHIPPABLE 归回 PENDING。统一到 `progressStageExpr` 后，列表、阶段筛选、任务数量和行映射均把尚未审完的活跃单归入进行中/PENDING；状态显示“等待销售负责人审核”。
3. 原负责人队列只有独立单据类型和三组 Chip，列筛选回调为空。现在仅保留待审核/历史记录两个公共分类；报价/订货在同一授权队列中展示，状态在首列，类型进入列头筛选。所有列条件先在服务端生效，再计数与分页，金额保留精确文本和数值条件。只允许查看的单据类型才参与 UNION；批量仍只选择有批准权限的待审订货单。订单缓存不被同 UUID 的报价覆盖。
4. 仓库等待检查黄数原先错误依赖最终入库或退回权限；只有先上架权限的负责人会得到 0。现在先上架权限，或真实仓库负责人拥有查看权限时，均可跟踪本人仓库的待检黄数。非负责人只有跨仓查看时仍不扩大个人待办范围，红数仍取实际可办理动作。来源计数和页内状态计数共用这一判断。
5. 仓库 hub 的任务卡原先只渲染红数，现迁至 `UtenScopedBadges`，与工作台/导航沿用同一模块汇总，黄左红右，不相加、不新增第二套计数。
6. “生产工单”多值弹窗用页面 navigator 执行 pop，在嵌套路由中可能关闭页面而留下根弹窗。公共组件现在从弹窗 navigator 返回所选值，等待弹窗结束后再调用详情导航；相同组件的全部入口一起覆盖。
7. 车间任务“销售要求”使用普通按钮的主题最小高度，导致有备注的行被撑高。改用 `UtenTableCellAction`；完整的订单/产品备注仍在原详情弹窗中展示，未固定整行高度或裁掉正文。
8. 无指定材料的领料申请原本货品和数量全部为空。保留其真实未指定事实，货品格提供“待仓库填写材料”入口及说明；不从产品名称或 BOM 猜测实际领料。
9. 八个销售负责人权限保留原 ID/授权/敏感策略，按报价、订货归入“销售管理 / 销售报价、销售订货”。六个权限浏览/批量/委派/模板入口共同显示“销售负责人权限”与既有商业敏感标记。维护预检脚本改为按八个权限码列出增量，不再通过已不存在的独立分组授出整个业务分类。

原截图中的加载失败未留下可归因的 HTTP 错误明细；本轮以实际服务查询、真实 PostgreSQL 流程和页面渲染验证新的队列能够加载，未将推测写成旧故障的已证实根因。
