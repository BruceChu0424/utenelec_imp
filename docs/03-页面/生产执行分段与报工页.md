# 生产执行分段与报工页

> **页面状态**：执行分段查看与状态动作已实现；生产发布仍为 **NO-GO**
> **主路由**：`/production/plans/:id`
> **执行分段深链**：`/production/plans/:id?executionSegmentId=:segmentId`
> **更新日期**：2026-08-01

---

## 一、页面职责

生产计划详情统一展示父计划事实、BOM/MRP 预览、执行分段和真实自制件子计划。页面不得把不同层级揉成一个列表：

- `production_plans` 通常是可独立审核和下钻的计划；但 `EXECUTION_V1` 派生子计划禁止通用删除/红冲，必须从父计划包走受控反向，不能拆断谱系；
- `subplan_links` 表达父计划与自制件子计划的谱系；
- `production_execution_segments` 表达同一计划明细按齐套状态、车间和日期拆出的执行部分；
- 执行分段的报工、领料、成品入库和结案都必须回到同一父计划及其数量权威。

## 二、加载与失败隔离

计划详情、MRP 物料需求、执行分段和子计划列表分别加载。MRP 预览失败不能吞掉子计划列表；子计划列表失败显示独立错误卡和重试；执行分段加载失败显示明确错误和重试。

当路由携带 `executionSegmentId` 时：

1. 先打开对应父计划；
2. 执行分段数据加载完成后定位目标分段；
3. 自动打开一次分段详情；
4. 目标不存在时停止重复尝试，不叠加多个对话框。

## 三、执行分段交互

点击任一执行分段必须打开自适应详情：

- 紧凑屏使用底部弹层；
- 中等和展开屏使用对话框；
- 查看者可看到分段编号、状态、计划/已报工/剩余数量、物料齐套、车间、班组、负责人和计划日期；
- `WAITING` 明确显示待料，不能伪装为可派工；
- `COMPLETED` 明确显示已完成，不能继续展示非法动作。

动作按“权限 + 当前状态”共同决定：

| 状态 | 允许动作示例 | 约束 |
|---|---|---|
| `READY` | 调整、派工 | 派工前需物料齐套及必要分配信息 |
| `WAITING` | 调整 | 不允许派工或开工 |
| `DISPATCHED` | 开工 | 仍由服务端校验版本和状态 |
| `IN_PROGRESS` | 报工 | 跳转日报新建并携带 `executionSegmentId` |
| `COMPLETED/CANCELLED/REVERSED` | 查看 | 反向须走专用状态机，不在详情里直接改值 |

只读账号点击行也必须得到详情或明确无权提示，不能出现可点击样式却没有反馈。

## 四、真实子计划交互

详情底部“子任务 · 子计划”来自 `subplan_links`，每行显示子计划单号、交货日、入库/计划数量和状态。点击后打开子计划自己的详情页；空 ID、自引用或路由失败显示强提示。这里展示的是子计划自身事实，不证明其入库已按 supply peg 回供父需求；未闭环前不得把子计划入库直接计为父计划或销售履约完成。

执行分段的“详情”与真实子计划的“跳转”是两套行为。任何后续改版都必须用独立组件和测试守住该边界。

## 五、权限与数据安全

- 查看权限不能推导出编辑、派工或报工权限；
- 前端隐藏按钮只改善体验，服务端仍须校验权限、对象范围、锁版本和状态；
- 销售深链只能定位被授权查看的计划和分段，不得把成本、供应商报价、员工绩效或内部质量责任带回销售端；
- 日期字段兼容后端返回的日期对象或文本格式，但兼容转换不改变业务日期语义。
