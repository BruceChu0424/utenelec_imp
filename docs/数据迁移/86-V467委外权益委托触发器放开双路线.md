# 86 · V467 委外权益委托触发器放开双路线

> 状态：源码候选（本地实现，未推送 CI）｜日期：2026-09-04
> 关联：[ADR-062 委外先自制后通知与分批通知](../99-决策记录-ADR/ADR-062-委外先自制后通知与分批通知.md)、[迁移说明 80 V460 委外前置自制任务外部化守卫补漏](80-V460委外前置自制任务外部化守卫补漏.md)

## 问题（2026-09-04 本地真库实证）

物料分析准备页，有子层级的委外件下层已齐套（`lower_level_pending=false`、路线已确认
SUBCONTRACT），点击「下达委外」界面毫无反应。后端日志同时间段三次 23514：

```
ERROR: invalid preplan MAKE entitlement delegation
GlobalExceptionHandler : Database integrity conflict: ConstraintViolationException
```

整个下达事务回滚，前端只有一闪而过的完整性冲突提示，用户感知即「没反应」。

## 根因

b0a62cd1 的委外权益迁移自锁修复让 `MaterialAnalysisCommandService.notify` 循环对
`route==SUBCONTRACT` 也调 `PreplanStockEntitlementService.delegateMakeEntitlements`
（Java 配对查询泛化为 `(route, 子行类型, 单据类型) IN (('MAKE',…),('SUBCONTRACT',…))`），
但 V337 建的头触发器 `fn_check_preplan_make_entitlement_delegation` 仍写死四项 MAKE 形状：

- `action.route = 'MAKE'`
- `action.external_document_type = 'PREPLAN_MAKE_TASK'`
- `parent_material.confirmed_route = 'MAKE'`
- `child_item.source_type = 'MAKE_COMPONENT'`

SUBCONTRACT 委托（route='SUBCONTRACT' / SUBCONTRACT_MAKE_TASK / SUBCONTRACT_MAKE）一插入
即被拒。为什么合入时没发现：当时的契约测试是**源码文本断言**（grep Java 源码字符串），
不跑真库；两个 E2E 的种子数据没有可迁移的 ORIGIN 权益，`delegateMakeEntitlements`
返回 0、一条没插，触发器从未被踩到。

## 决策

- 头触发器配对放开为 `route → (document_type, child_source_type)` 双路线：
  MAKE→(PREPLAN_MAKE_TASK, MAKE_COMPONENT)、SUBCONTRACT→(SUBCONTRACT_MAKE_TASK,
  SUBCONTRACT_MAKE)；`parent_material.confirmed_route = action.route`（与 Java 查询同口径）。
- 未知路线经 CASE 映射为 NULL，配合 `IS DISTINCT FROM` 保持 V337 的 NULL 严格
  失败关闭语义（`NOT IN` 对 NULL 返回 NULL 会放过非法行，不可用）。
- 事件侧触发器 `fn_check_preplan_stock_entitlement_event`（MAKE_DELEGATE_OUT/IN 分支按
  委托头对账）与延迟总量校验器 `fn_validate_preplan_make_delegation_totals`（只对账
  OUT/IN 数量相等）形状无关，不动。
- 修复是纯函数替换（`CREATE OR REPLACE FUNCTION`）：三次失败的点击都已整体回滚、
  没有半成品数据，替换后**直接重点「下达委外」即可**，无需数据修复。
- 不加表、表计数不变（429 个迁移、重置白名单版本门增至 V467/429）。

## 行为锁定

- `SubcontractMakeDelegationRouteGuardPostgresTest`（真库 testcontainers，V1→head）：
  SUBCONTRACT 形状插入成功且权益搬移（源 6 / 目标 4 / 总量守恒 10）、MAKE 形状回归
  仍可插入、父路线与 action 路线不一致仍 23514 拒绝。
- `ProductionMaterialAnalysisWorkflowContractTest.subcontractMakeNotificationAlsoDelegatesExactEntitlements`
  增补迁移文件断言：Java 配对与 V467 SQL 配对必须同时存在，防止再出现「代码改了、
  守卫没跟」。

## 影响面

- 服务器 v2026.09.03-2 同样是「新代码 + 旧触发器」组合，有子层委外下达会同样失败，
  本迁移需随下一版发布。
- 本地 dev 库直接 `CREATE OR REPLACE` 即时生效（幂等），后端下次重启 Flyway 正常补记
  V467 历史行。
