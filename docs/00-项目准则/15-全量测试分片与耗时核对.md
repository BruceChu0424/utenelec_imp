# 全量测试分片与耗时核对

后端全量验证保留全部 Surefire 测试、PostgreSQL 业务链、迁移演练和 Failsafe 打包集成测试。
分片只改变测试的分配与执行位置，不减少测试或放宽断言。

## GitHub 完整门禁

`Quality Gate` 先使用 JUnit Platform 发现编译后的测试，再按照历史耗时分成四组。
每组在独立 GitHub runner、JVM、PostgreSQL 容器和构建目录中运行；组内保持串行。
所有分片运行完后，原有 `Backend / Java 21 (full: DB full-chain)` 检查汇总真实测试报告。
发现清单、计划指纹、片数、测试方法、失败和跳过原因必须核对；缺少分片或报告不能通过。
新增测试自动进入发现清单，不依赖人工维护排除表。
静态测试要求恰好执行一次；参数化和动态测试要求每个发现的方法产生实例且实际实例不重复。
首次引入或修改分片机制时，还必须执行下文的原始全量对照，证明参数化/动态测试的全部实例一致。

保留原快速检查提供早期反馈，保留 Flutter、官网、部署合同、密钥扫描、CodeQL 和漏洞扫描。
任一分片失败仍收集其他分片结果，便于一轮定位所有问题。失败不能通过自动重试后被静默掩盖。

`.github/test-timings/backend.json` 仅提供调度权重，来源运行可能失败；它不是验收证据。
全量结果必须来自当前源码产生的新报告。实际耗时受 runner 并发额度、冷启动、资源和用例分布影响。
四组并行主要缩短墙钟等待时间，不意味着计算费用也降低四倍。

修改分片机制时，可手动触发 `Quality Gate` 并勾选 `compare_reference`，在同次运行、同一提交、
同类 Linux runner 上额外执行原始串行全量并逐实例对照。此模式仍运行所有普通门禁，且串行对照
失败会阻断完整后端门禁。普通 PR/push 和未勾选该选项的手动运行保持四组并行，不额外跑串行。
涉及墙钟性能预算时，以相同环境作对照；本机超时仍记录为失败，不放宽原性能阈值。

条件跳过必须有发现清单中的原始声明与实际执行证据。公司工作簿专项只接受
`CostCompanyWorkbookReviewTest` 明确声明的 `uten.cost.companyWorkbook`（匹配 `.+`）未提供这一种原因；
其他系统属性条件、提供了路径却跳过、模糊原因均拒绝。私有工作簿另以真实本地输入验收，不随源码或 CI 上传。
`@EnabledOnOs` 按声明、Surefire XML 的 `os.name` 和运行报告的真实平台核对；Linux 不能接受 Linux 专项跳过。
Windows 产生的平台跳过保留完整理由和计数，相关 Linux 专项须另在真实本地 Linux JVM 补验，不能当作已经执行。
Docker 不可用产生的跳过仍阻断完整门禁；上述支持不放宽数据库测试要求。

## 本地运行

需要 Java 21、Maven、Python 3.11 或更新版本，以及运行中的 Docker。以下命令在仓库根目录执行。
使用独立、冻结的工作树；不要一边修改测试或迁移，一边把正在运行的报告当成最终证据。

```powershell
$env:UTEN_RUN_DB_TESTS = 'true'
python .github/scripts/backend_test_shards.py plan --output server/target-ci-plan --shards 4
python .github/scripts/backend_test_shards.py run --plan server/target-ci-plan/plan.json --all --workers 2 --output server/target-ci-reports
python .github/scripts/backend_test_shards.py verify --plan server/target-ci-plan/plan.json --reports server/target-ci-reports
```

可用 `--maven <mvn可执行文件路径>` 指定 Maven。先从两个并行进程开始，按内存、CPU 和 Docker
资源调整；不要在同一小型 runner 上直接堆叠大量数据库测试线程。
每片结果保存在输出目录的 `shard-N` 子目录，包含 Maven 日志、Surefire/Failsafe XML 和结构化报告。
控制台实时输出 Maven 阶段、当前测试类及结果摘要；完整迁移和诊断输出保留在日志中。

`run`、`baseline` 和 `focus` 都接受两个可选内存参数：`--jvm-max-heap` 限制每片的测试 JVM，
`--maven-max-heap` 限制每片的 Maven 父进程。不传时保持现有 JVM 默认值与已有环境配置。
参数只接受正整数字节数及可选的 `K`、`M`、`G` 后缀（大小写均可），例如 `4g`、`1536m`；
空白、小数、额外 JVM 参数或 shell 片段均拒绝。

```powershell
python .github/scripts/backend_test_shards.py plan --output server/target-local3-plan --shards 3
python .github/scripts/backend_test_shards.py run --plan server/target-local3-plan/plan.json --all --workers 3 --jvm-max-heap 3g --maven-max-heap 1536m --output server/target-local3-reports
python .github/scripts/backend_test_shards.py verify --plan server/target-local3-plan/plan.json --reports server/target-local3-reports
```

本机只有三个并行位时，四个等重分片会留下第二波；可像上例生成三个分片，仍执行所有发现的测试。
GitHub 的四个独立运行器继续使用四片。`plan --history <JSON路径>` 可采用本机已完成测试类的耗时
重新平衡；未执行类的估值应注明来源，不能把失败或中断运行的耗时提示当成通过证明。更换源码后
必须重新发现、生成绑定新源码的计划，并完整执行及核对新报告，不能拼接旧 XML 充当新版本全量。

这些参数仅设置资源上限，不改变测试分配、组内串行、失败处理、跳过规则或性能断言。
普通 CI 不额外传参。测试堆上限通过独立 POM 属性追加到 Surefire/Failsafe `argLine`，
保留原 Mockito agent 和 `uten.test.jvm.args` 中的隔离临时目录。Maven 上限仅在显式指定时
追加到 `MAVEN_OPTS`；报告的 `heap_limits` 记录这两个显式值，`null` 表示该项未由工具指定。
不输出其他环境变量。Java 堆以外的内存、PostgreSQL 和其他本机进程仍需计入并行运行预算。

每片的 Maven 父 JVM 通过独立参数文件在启动时设置临时目录，测试 JVM 继续使用原 `argLine`；
不把 `java.io.tmpdir` 重复作为 Maven 用户属性传入。`maven-parent-jvm.args` 随每片报告归档，
报告记录其路径、启动器平台编码和 SHA-256，启动失败时也保留；文件只包含本片生成的临时目录，
不记录已有 `MAVEN_OPTS`。带空格或中文的路径由 Java 参数文件解析；无法用启动器编码表示的路径会明确失败，
不会替换为乱码。其他 Maven 用户属性仍照常传入测试。

需要顺序执行分片时，可生成 `--shards 1` 计划，再以 `--workers 1` 运行。
改造验收还需要独立的原始入口对照，不能只用分片工具验证自身：

```powershell
python .github/scripts/backend_test_shards.py baseline --plan server/target-ci-plan/plan.json --output server/target-ci-baseline
python .github/scripts/backend_test_shards.py compare --plan server/target-ci-plan/plan.json --reports server/target-ci-reports --reference server/target-ci-baseline
```

`baseline` 不传测试 includes/filter，执行原始 `mvn clean verify` 并保留源码身份及实际报告。
`compare` 对比全部实际测试实例、状态和跳过原因。两个入口必须使用同一源码和提交。
PR 默认测试合并提交，拿远端计划在本地对照时也必须检出该合并提交，不能拿分支 HEAD 冒充。
原命令 `UTEN_RUN_DB_TESTS=true mvn verify` 继续可用；速度比较还需要相同资源和不受其他任务干扰的运行环境。
使用可选堆上限作对照时，`baseline` 与 `run` 传相同的两项值，例如
`baseline --plan server/target-ci-plan/plan.json --jvm-max-heap 4g --maven-max-heap 1536m --output server/target-ci-capped-baseline`。

## 快速修复循环

先运行上次失败的测试类及改动涉及的业务链，再提交完整验证。工具的 `focus` 入口生成的结果
明确属于定向检查，不可作为完整门禁通过的依据。合并与发布始终检查最终提交的完整 CI。

## 数据库初始化

只需要当前完整结构的普通业务测试可以复用本次 JVM 内由真实迁移构造的干净模板，
每个测试租用独立克隆库；关闭租约只清理该克隆，不停止其他测试使用的模板。
模板不会跨 CI 运行持久化。真实业务数据不进入模板。

验证空库创建、旧版本升级、部分状态恢复、重放和迁移失败的专项继续使用其原始迁移路径。
不以复制当前结构替代升级验证，不修改已应用的 Flyway 文件，不调用 `flyway repair`。

## 回退

可暂时用单片计划执行相同全量清单，保留报告核对；原始 `mvn verify` 入口也保持可用。
回退执行策略不删除测试、不关闭数据库测试，不放宽发布门禁。
