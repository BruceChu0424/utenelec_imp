# 销售订货到发货全链路 SOP

本页描述现行岗位流程、业务门槛和异常处理。销售订单来源与无订单的客户零星发货都必须经过财务放行、仓库确认实际出库；收费发货在 SHIPPED 时立正式应收。数量不足可以接单和下达计划，只有执行领料/开工需要实际合格物料齐套。

当前实现差距见本文末节；测试与运行结果集中在[统一验收记录](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)。本页不维护迁移头、旧测试计数或服务器安装状态。运营业务链优先，深入财务最后，完整项目验收尚未完成。

## 二、销售开单、审核与修改

1. 业务员选择有权访问的客户，可从已审核报价转入；主管跨归属读取和操作需对应权限。销售只录商业事实，不在订单录入客户预收到账或要求回填记账汇率。
2. 原有草稿行保留已冻结的单价依据，报价转入沿报价快照；新增/换货行按当前允许的价格来源取值。折扣可按授权调整，新倍率必须大于0且不大于1；历史null/0按原解释留存。客户端单价/金额不能覆盖服务端权威来源，生产/仓库无价格权限时服务端脱敏。
3. 新单必须选择 `ALLOW_PARTIAL` 或 `REQUIRE_COMPLETE`。`CUSTOMER_CONFIRM` 只保留历史值，不再新增一层客户确认审批。收货地址/电话在发货时选择或填写，可复用客户地址簿，不能回写为客户主档或当订单资金事实。
4. 销售订单状态为草稿0、已审1、红冲-1，没有独立销售提交态。草稿不占库存承诺；销售审核使用 `sales_order:approve` 和对象范围校验，同事务形成有效预留并送订单财审。销售审核不是财务审核，也不扣实物或立正式AR。
5. 财务在对应队列认领。认领失败/续期失败时页面只读，确认/驳回必须持本人的有效claim和当前业务版本；单笔及批量都校验。失效或版本冲突不能写部分决策，需刷新后重新认领。

| 修改时点 | 合法动作与后续 |
|---|---|
| 财务尚未认领 | 销售可按权限修改；服务端仍检查现有下游事实和来源容量。 |
| 有有效财审认领 | 禁止修改、删除及改量，包含认领人自己和其它账号，避免审核中的快照漂移。 |
| 已财审通过，尚无下游事实 | 完整修改保留原行UUID/软版本与商业快照，重建允许释放的预留，自动重新送财务。 |
| 已有分析、采购、排产、发运或资金事实 | 使用专用改量/反向通道；不得整单覆盖历史或删除已有来源。合法改量立即更新当前商业事实并形成修改复核，不自动回滚已完成下游。 |
| 财务驳回 | 销售查看原因后受控修订回草稿再自审，或走合法改量重报/取消；复核保留前后内容，驳回不抹旧事实。 |

已准入分析遇销售改单待财审，原采购/委外到货、品质和实际入库继续更新原需求履约；新的路线、追加安排、公共在途采用和采购/车间下达仍校验本次所选产品及来源父链。一个产品待审不冻结无关产品，也不能借子锚点绕过父订单财审。

## 三、库存承诺与计划下达

销售有效预留减少可承诺量，不减少 `stock_balances`。按各实际仓保护安全库存后再扣有效承诺；一份库存不能同时承诺给多个订单。全局预留可暂不指定发货仓，本批出库只消费对应份额，未发余量继续保留。数量锁保证不超卖，不能替代交期、优先级和授权让单的业务决定。

计划员选择已财审准入的订单需求和目标主仓，分析冻结来源和完整BOM。缺货不阻止下单，也不强迫整单在现货/生产间二选一；同产品多订单可明确合并，单订单可分批下达，关联由 `plan_order_links` 等UUID来源事实保留。

1. 在各层确认 MAKE、BUY、SUBCONTRACT 等合法路线。**确认路线和责任数量后即可下达任务，不能用子件当前齐套量限制计划下达。** 未确认路线、过期来源、重复下达或已被父委外覆盖的子件须拒绝。
2. MAKE 下达车间任务/计划锚点；子件需求仍在原树，只产生一份责任。未齐套的执行段 WAITING，不提前抢占零散通用材料。
3. BUY 生成采购来源任务，采购人员可跨申请选择、部分分解。一个商业订单按同供应商及兼容条款归集，订货不按收货仓拆单；真实收货时选实际仓。
4. SUBCONTRACT 有子层时先在原分析内完成目标件前置自制/拼装，实际成品入库后按可通知量分批交委外下单；无子层可直接形成委外任务。子件不能又按原树重复下达。直接委外单的草稿自动准备及专项边界见[委外SOP](08-委外全链路-订货出仓回仓重设计.md)。
5. 已有采购、委外、车间计划及显式采用的公共在途只代表未来供给责任，用于防重复下达。下达不能使原需求或实物缺口立即归零；公共超量也不能冒充本批合格权益。

分析分别保留本批需求、已下达、待补、在途、待检、合格待入库、实际齐套与已领用覆盖。原物料已实际领用仍覆盖本批，不得再次产生采购缺口。分析全部转计划只表示已下达，不表示生产完成。`SHIP/REFERENCE`不作生产硬门槛；实际生产耗用的包装按相应生产控制阶段如`FINISH`配置。

## 四、到货、齐套、领料和实际完工

采购收货/委外回厂先登记真实到货并形成待检；IQC PASS只给合格待入库量。仓库逐次核对数量和实际叶仓确认后，才写实物流水、增加可用库存并推进原来源履约。同单其它待检行不能阻塞已合格实收切片；FAIL、在途或PASS未实收不能用于领料开工。

同一主仓内的有效子仓可分别存放和发出塑料、五金等材料，预留/流水始终保留实际叶仓UUID。齐套分配可跨同主仓多个子仓，完整套料不足整笔回滚；跨主仓必须按原规则明确处理，不能悄悄重标仓库或挪用另一分析的专属权益。

执行顺序为：

```text
路线与数量确认 → 下达计划/车间任务
  → WAITING等待合格实物齐套
  → READY并按实际叶仓生成DRAW
  → 仓库分批实际领料 → 负责人显式开工(IN_PROGRESS)
  → 报工/完工申报 → FQC → 合格待点收 → 仓库实际点收
```

- DRAW审核只确认领料需求，仓库实际issue才扣库存；完成必需实领后才能开工。负责人/车间继承计划安排，学习默认不能覆盖人工选择。
- WAITING历史任务可用有权限的“重新检查物料”；列表GET不写入，人工暂缓不被自动绕过。未开工不显示报工入口，创建报工也不能自动开工。
- `fqty`表示当前有效完工贡献，FQC PASS是点收上限，`iqty`才是仓库实际成品入库和完成率依据；不能用报工或PASS伪造库存。
- 补产、返工、拒收和报废需真实处置/来源，通知或自动建议不能代替授权决定。领用、退料、实耗、在制与损耗分别结清；生产成本沿真实材料来源进入成品/已售成本，不取销售价。详见[库存实际成本](../99-项目治理/库存实际成本接线与验收.md)。

## 五、发货与正式应收

销售从订单可发来源开单，兼容客户、币种及商业条件的订单可合并分批发货。样品、赠送及其它无订单客户发货走“客户零星发货”，明确收费/不收费，使用同一客户发货事实和仓库链；旧“其它出货”只保留历史读取，不能作为绕过财务的新写入口。

1. 开单冻结本次来源和商业内容。订单来源保存后按当前流程送发货财审；零星发货先由销售明确确认。原币商业金额不代表本次银行到账，草稿不立AR或扣库存。
2. 所有客户发货逐张财审，月结/现金/定金标签不能自动放行；收费单客户付款类别未明确时须先处理。财务核对发货、订单资金及当前版本后人工放行；免费也必须审核和实际出库。
3. 财审认领期间禁止商业修改。尚未开始仓库作业的合法修改撤回旧放行并重新走审核，旧快照保留。仓库作业已开始，不能直接改商品/数量、删除或反审，须先走允许的异常退拣和恢复。
4. 仓库只处理已财务放行任务，依次 `PENDING_PICK → PICKING → PICKED → SHIPPED`。开始拣货校验指定仓可用量、本单来源承诺、其它预留/在拣份额和发运策略；异常/恢复需原因，并追加状态事件。
5. `ALLOW_PARTIAL`按可发量分批；`REQUIRE_COMPLETE`要求本次覆盖订单当前需共同交付的全部剩余行。草稿占用本次可发额度不能重复扣ATP，任何并发超额都必须拒绝。
6. 仓库确认真实交接后，SHIPPED同事务扣库存、消费本批预留、回写已发量；收费单锁财务开账汇率并立正式AR，立账/账期起日使用上海业务日。任一步失败整笔回滚。免费不立货款AR，但成本仍按真实库存来源转移。

一张发货单对应一次实际交接；订单可关联多个发货批次，不能以一张物流信息覆盖全部批次。当前状态机不等于完整WMS的实拣数量、复核、装箱、批次/序列号和物流件级管理，扩展范围不能由`PICKED`推断已实现。

## 六、退货、取消和异常

| 情形 | 处理规则 |
|---|---|
| 改量低于已履约/已占用下限 | 服务端按实际发运、生产及来源账拒绝；已排产还须相应权限与来源对账。不能只检查“新数量≥已发”就强行通过。 |
| 整单取消 | 有已发、绑定预收/转销、活动生产/完工来源或仓库作业时，先沿合法下游反向与资金处理；不能凭一个生产确认绕过门禁。已部分发货只处理允许减少的未发余量。 |
| 仓库找不到货/货损 | 登记异常，按允许状态退拣/恢复并重新核验来源容量；不能靠改实物余额或静默释放其它订单承诺解决。 |
| SHIPPED后发现错误 | 普通红冲不得直接加回库存，必须走销售退货与品质处置；旧行缺交接时间只表示证据未知，不表示未发。 |
| 销售退货 | 先待检冻结，再按真实GOOD/SCRAP/REWORK及追加纠错处理。客户处置REFUND_CLOSED/EXCHANGE/RESHIP/REPAIR_RETURN分别决定是否重开履约；不能一退货就自动补产或加可售预留。详见[退货SOP](06-销售退货质检冻结与处置.md)。 |
| 稀缺让单/远期承诺 | 默认不自动抢占；按交期、受影响订单、替代供给和权限人工决定，留原因/审计/通知。已拣、已交接、已出库份额不能让单。逾期预留只提醒，不自动释放。 |
| 延期、批次异常或来源漂移 | 按任务/通知回到真实单据；来源变化返回冲突并刷新，不能用忽略版本、重复下达或单号匹配消除错误。 |
| 历史开放订单/旧草稿 | 未激活订单先核库存、已发和排产，再显式处理；LEGACY_PENDING发货只读重建，不能批量造历史预留或客户确认。 |

通知是可靠Outbox旁路，不代替状态。到达提示、稍后提醒、关闭、已读和办结各自处理；收权/换身份后重新核操作资格，不向无权岗位展示金额。业务页时间线读受控在线审计，归档调查沿专门权限；导出继续使用公共加密/审计/限频机制。

## 七、资金边界和已知实现差距

客户预收必须来自真实财务收款，销售历史deposit不是银行到账。正式AR后按明确原订单/发货来源应用预收或登记收款，每批保留原币、实际账户额、费用、账面分配和前后余额。实际现金、转销、贷项及汇兑分别展示；负AR或REFUND_CLOSED不等于已向客户付款。详细合同见[实际金额口径](2026-09-07-财务原始金额与精确分摊口径.md)与[财务专项](../99-项目治理/2026-09-07-V519-V520-V523财务实际金额与银行链验收交接.md)。

- **直接委外准备已接线，待全项目整合**。既有分析委外任务与直接商业单保留两条来源；SC-ORDER草稿期先交计划、目标件实收后送财务，专项见[128](../数据迁移/128-V529直接委外草稿准备.md)。两条来源都不退回“齐套才下达计划”的旧规则。
- **财务后续：订单来源发货本币截断**。`SalesShipmentService.applyPostingRateSnapshot` 的订单来源分支仍 `setScale(MONEY_SCALE, HALF_UP)`，零星发货走精确分支。该差异不符合统一完整金额目标，不能写成新实际金额允许四舍五入；依任务顺序留待财务收口，不在本SOP改业务数据。
- 历史资金/成本核对、客户现金退款、普通退货共同账面分配、完整质量/WMS、后补成本GL、最终压力/岗位/目标环境验收仍需独立完成，不能用固定运营链通过替代。
