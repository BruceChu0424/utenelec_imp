# V855 根供给按真实合格入库仓交接

分析仓表示计划范围；已合格入库的采购或委外根产品，权益、交接事件及销售预留必须保留同一条原来源的实际核算叶仓。旧代码按分析仓精确查询权益，旧 V478 又同时要求交接仓等于分析仓和原释放权益的仓，因此“主仓分析、子仓上架”在品质合格自动入库时回滚，报根产品权益不存在。

[V855 SQL](../../server/src/main/resources/db/migration/V855__root_supply_actual_qualified_warehouse.sql) 只替换 `fn_guard_root_output_event`，不改表、索引、旧事件或已应用迁移字节。原分析、产品、颜色、根节点、外部路线和剩余数量校验继续有效。采购或委外交接必须有完整的品质放行、原入库批次与流水证明，精确释放权益和销售预留均须匹配实际仓。反向事件还必须逐项镜像原仓、数量、释放权益、销售预留及来源单据，不重新推测历史仓库。

配套后端统一根供给投影、财务未确认时保留的合格来源、恢复交接和现货交接。公共库存只在原主仓范围的良品核算叶仓内汇总，全局预留只扣一次，跨叶仓交接分别保留实际预留及事件。已上架待检量仍不算可用库存；财务未确认期间已取得的真实合格权益不会变成新缺口；被下游消费的来源仍须先处理下游，不能直接反审。

隔离 PostgreSQL 回归覆盖两行各 500 的自动入库、同体重放、销售分批合格、财务待确认及恢复、发货后阻断、分仓现货和其它所有者预留守恒、原切片反向及伪造仓/数量/释放身份拒绝。非空 V854 升级还校验原业务事实与已应用历史逐行不变、Flyway 验证和重复执行为零迁移。源码、GitHub CI、正式库迁移与公司运行版本分别验收；本记录不代表已发布。

没有新增表、列、索引或需要清理的业务对象，原业务清空目录及索引集合保持原映射。部署按既有升级器完成备份、前向迁移、激活与健康验收；不使用 Flyway repair。
