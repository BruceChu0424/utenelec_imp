## 一、员工看到的主流程

```text
已审核销售订单行 / 合法手工需求
  → 选择本次要分析的产品与数量
  → 选择一个目标仓并开始物料分析
  → 系统默认展开完整 BOM；每条 path 显示目标仓现货、本批需求、缺口和任务状态
  → 按父件实际短缺与路线激活后代：BUY 停止、MAKE 展开、供料委外展开
  → 计划员逐路径节点确认 BUY / SUBCONTRACT / MAKE 并处理真实缺口
      ├─ BUY → 通知采购
      ├─ SUBCONTRACT → 通知委外；有供料 BOM 时继续备齐我方供料
      └─ MAKE → 下层实际齐套后创建 MAKE_COMPONENT 并安排生产
  → MAKE 子件与根产品在本页填写本批车间、负责人和日期
  → 服务端重新预览并生成计划草稿，提交审批；页面不跳走
  → 计划批准后才形成 READY、正式预留、DRAW 和销售已排量
  → 剩余未排数量继续保留在原物料分析，待物料后续到齐再分批安排
```

销售订单有 10,000 件需求而当前生产硬门槛物料只完整支持 1,000 件时，员工可以先为 1,000 件填写并提交计划单；剩余 9,000 件不复制成一张“待料正式计划”，而是继续留在原分析。采购、委外或 MAKE 合格供给到位后，重新打开同一分析继续安排。

自制件按自底向上推进。目标合同是：MAKE 节点先在父树把本批下层物料实际备齐，再创建系统 `MAKE_COMPONENT` 子分析并把对应路径/数量委派给 child；子件正式计划完工合格入库后，父级可完工量才上调。当前候选通过 child 存在性推导**整节点 ownership** 并让父树后代不再激活，没有显式 `delegated_qty`，不得据此宣称任意分批委派余量已实现。员工仍从同一分析任务流处理下一层。

## 二、历史记录与来源选择

### 2.1 物料分析记录

历史页只读取服务端按负责人、部门和对象范围裁剪的记录，支持：

- 搜索需求编号、销售单号或产品；
- 按 `ACTIVE / PARTIALLY_PLANNED / COMPLETED / CANCELLED` 筛选；
- 按销售、返工、试制、样品、备库、其他或系统自制子需求筛选；
- 查看需求、已提交、已批准、待处理、可立即/按期数量；
- “继续处理”回到原分析 ID，不能用重新创建代替恢复。恢复后点“按最新库存刷新分析”时，前端自动用该分析已持久化的来源重算（从产品行重建销售/手工来源、跳过系统 `MAKE_COMPONENT`，与服务端 `requireSameSources` 排除 MAKE_COMPONENT 一致），无需重新选产品。

宽屏使用 `MasterDataTableView`，窄屏改为带状态、数量和明确“继续处理/查看”文案的卡片。搜索、筛选、分页、刷新和打开记录都是安全读操作，不改变业务状态。

### 2.2 新分析来源

- 销售来源只列已审核且仍有可排剩余量的销售订单行；支持勾选多行联合分析，不显示价格。
- 手工来源只允许 `REWORK / TRIAL / SAMPLE / STOCK / OTHER`；必须填写稳定需求编号、原因、产品、数量和日期。
- `MAKE_COMPONENT` 只能由系统在 MAKE 节点下层实际齐套并完成幂等委派后创建，员工不能手工伪造。
- 点“联合分析所选产品”或“加入分析”前的勾选、搜索和本地表单编辑尚未写业务事实；真正点击“开始/刷新分析”会调用写接口并持久化分析、来源和 BOM 快照。

## 三、分析详情的傻瓜式交互

### 3.1 产品与自制备料项

- 区域表头有三态复选框：空框表示全未选，勾选表示当前可选项全选，半选表示只选了部分；再次点已全选表头即取消当前可选项。
- 每张产品卡也有复选框。未选中时保持紧凑，只显示产品身份、剩余/就绪状态、阻断原因和下一步，不展开阶段参考量或本批输入；选中后整卡使用深绿色底和白色文字，并展开三阶段数量明细和批次输入，不只靠小勾表示状态。
- 缺少必需 BOM、无可完工量或无权限的行不能勾选，按钮附近必须显示原因；不能给一个看似可点但无响应的按钮。
- “调整物料优先顺序”只改变共享自由库存的分析模拟顺序，不创建正式库存预留；点击“确认优先顺序”才写入服务端并重算。
- 每张卡显示服务端汇总的就绪状态：`可安排生产`、`下层备料中`、`草稿待审`、`待领料`、`生产中` 或 `已完工入库`，并给出下一步提示。状态必须由逐路径任务及真实计划/领料/执行/入库事实投影，不能只在前端统计 depth-1 行。
- 产品区按“可排产置顶”做稳定排序（保留分配优先级与父先于子序），让计划员一眼看到现在能做谁；不可排产的卡在其可完工量标题下说明被什么挡住。
- `MAKE_COMPONENT` 卡显示 `自制任务 · 用于组装 {父件}`，并精确回指创建它的父路径节点。前端不得按 goodsId 猜父件；同货多路径时必须使用服务端父节点/委派关系。
- 自制件完工入库后，上级可完工量由服务端 `MaterialAnalysisSupplyWakeupService` 自动 `refreshLocked` 上调，无需人工计算；本页只展示结果。

### 3.2 三个数量不能混用

| 页面名称 | 权威含义 | 能否作为本批计划上限 |
|---|---|---:|
| 可开工（分析参考） | `START` 阶段物料当前可支持的数量，只用于看准备进度 | 否 |
| 可完工入库 | `START + ASSEMBLY + FINISH` 生产硬门槛完整齐套后的数量 | **是** |
| 预计可发货（参考） | 加上 `SHIP` 参考物料后可支持的提示量 | 否 |

`可开工/可完工入库/预计可发货` 的语义和服务端计算始终保留，但产品卡未选中时不展示三阶段明细和批次输入；只有员工选中该产品准备安排计划时才展开。折叠只是减少现场噪音，不能改变 `ready_finish` 的计划上限或隐藏阻断原因。

`readyNowQty` 是兼容 API 字段，服务端与当前页面把它写成、读取为“可完工入库量”。逐张计划单中的最大数量和最终 `plan-preview` 都按该量校验，不按“可开工”或“预计可发货”放大。

`SHIP/REFERENCE` 永远只是参考：不写正式生产物料需求、不占库存、不生成 DRAW，也不阻止生产计划或销售实际发货。生产过程确实消耗的纸箱、胶袋、说明书等必须在 BOM 中配置为 `FINISH`，并按 `PER_UNIT / PER_PACKAGE / FIXED_BATCH` 计算；不能把纸箱放在 `SHIP` 后再假装已经为生产预留。

### 3.3 BOM 父子树与红色缺料

- 进入分析结果后，根产品和所有 BOM 分支直接完整显示；系统不得隐藏未处理的第二、三、四层。完整树与节点“详情”是两层概念：树始终显示，次要详情默认收起。
- 每个 `analysisItemId + path/nodeKey` 是独立节点任务。主行只保留现场作决定需要的物料/路线、本批需求、本层分配、目标仓现货、缺口、权威状态和**唯一主动作**；不能只给顶层显示库存，也不能在一行堆多个同级按钮。
- 阶段、单位、有效预留、安全库存、未来在途/预计日期、完整 BOM 路径、路线建议与下拉、下游来源和计算说明进入该节点的“详情”。打开/关闭详情是只读交互，不改变勾选、路线、数量、分析版本或任务状态；缺口、禁用原因和目标仓现货不得藏进详情。
- `requiredQty=0` 统一显示“本批无需补货”，但仓库现货仍照常显示。它不等于“已齐套”，也不得再显示“随上级件”。
- 缺口大于零时同时显示红色、缺料图标/文字和缺口数量；不能只用颜色传达状态。
- 同一货品出现在多条 BOM 路径时是多个独立任务。物理库存仍由服务端共享池防超分；采购/委外可在下游合单，但必须保留逐路径 allocation。不得用 `goods+color+unit` 或一个 `actionGroupKey` 吞并路径身份。
- 根产品本批数量先激活直接组件；父件只有未被合格现货覆盖的实际短缺才向下展开：
  - BUY：后代不激活，显示现货和“本批无需补货”；
  - MAKE：按实际短缺激活下层备料；
  - SUBCONTRACT：父件形成委外任务；有有效供料 BOM 时按实际短缺激活我方供料节点，无供料 BOM 时不虚构后代需求；
  - 路线未确认或结构异常：保留树和现货，禁用写动作并显示原因。
- 目标合同要求 MAKE 创建 child item 前下层任务属于父树，创建后对应后代由 child 接管并在父树只读。当前候选只投影整节点 child ownership；显式委派数量、部分余量和反向仍是 NO_COVERAGE。

### 3.4 统一 BOM 树的路线确认与下达（不再按类型分区）

1. 所有层级件在同一棵树按路径缩进；主行显示采购/委外/自制/待定角标、服务端任务状态和当前唯一主动作，完整路径与高级字段从“详情”查看。
2. 计划员只对“本批需求已激活、未委派、仍有缺口”的路径节点确认路线；路线建议、下拉和偏离原因放在详情内。“采纳建议路线（N）”只能提交当前版本中符合这些条件的节点。
3. 路线确认是下游动作硬门槛。未确认、`required=0`、已由 MAKE child ownership 接管、结构异常或无权限的行不可勾选，并明确显示原因。
4. 可以按路线批量选择，但批量只是操作便利；请求仍携带每个路径任务及数量。选中行深绿色，并显示“已选 N 个节点任务”。
5. BUY 点击“通知采购”，生成可追溯 action、逐路径 allocation 和真实采购申请；SUBCONTRACT 点击“通知委外”，生成真实委外申请。二者都是物料任务，不创建 `production_plans`。
6. MAKE 行先显示“下层备料中”。只有服务端重算确认直接下层实际齐套后，才启用“安排生产”：当前候选幂等创建 `MAKE_COMPONENT` child item，以 child ownership 让父树后代不再激活，再进入既有计划向导。目标合同中的显式分批 `delegated_qty` 尚未落地。
7. 无“标记已领料/生产中/完工”按钮。领料来自仓库实际 `issue`，生产中来自执行段/审核报工，完工来自审核成品入库；树通过服务端刷新自动更新。
8. 重新进入仍为活动态且服务端明确允许 `REFRESH` 的旧分析时，前端必须从已持久化 item 重建完整用户来源（排除系统 `MAKE_COMPONENT`），自动执行一次 preview 重算，以便旧的深层零需求快照立即按新规则升级；不得使用路由 seed 中可能残缺的销售选择。`VIEW`-only 记录只读展示，绝不自动写分析版本。

这里的“通知”不是普通消息：服务端先写幂等 `preplan_supply_actions` 和逐节点 allocations，再创建真实采购/委外下游。消息、角标和岗位队列只是这些事实的提醒投影。重复点击必须按路径任务、代次、当前剩余缺口和请求哈希幂等；不能靠货号级开口供给量替代路径守恒。

### 3.5 按需出现的底部动作区

底部动作区不常驻，只在至少满足一项时出现：

- 有尚未提交的脏路线；
- 有可直接采纳、尚未确认的服务端路线建议；
- 已选择至少一个可下达的补货节点；
- 已选择至少一个可生成计划的 MAKE/root 产品项。

没有待提交内容时整个动作区隐藏，不显示“通知采购（0）”“通知委外（0）”“安排生产（0）”“生成计划（0）”等零计数按钮，也不常驻计划日期。路线保存、补货下达和计划生成只显示与当前选择相关的动作；计划日期、车间和负责人只在进入既有 `ProductionPlanWizardPage` 后填写。

动作区按需隐藏不改变权限和服务端门禁：按钮仍取“客户端有效权限 ∩ 服务端 `allowedActions`”，提交仍校验对象范围、状态、版本、指纹、数量和幂等键。

## 四、在本页安排 MAKE 与根产品计划

只有两类行显示“安排生产”：

- 下层实际齐套并已经创建/定位 `MAKE_COMPONENT` child item 的 MAKE 行；
- 本批直接组件实际齐套的根产品行。

BUY 与 SUBCONTRACT 行永远不显示生产计划按钮。点击“安排生产”后，从当前节点进入既有 `ProductionPlanWizardPage` 填写计划；这是同一任务流的继续处理，不要求员工先去计划历史重新找单：

- 显示产品、编码、规格、来源路径和服务端重算的本批可完工上限；
- 必填本批数量、生产车间、负责人、计划开始和结束日期；
- 结束日期不得早于开始日期，数量不得超过该节点尚未安排且实际齐套的数量；
- 多行批量安排可以逐张填写并汇总确认，但每张保持自己的 MAKE/root 身份和路径来源；
- 向导取消时返回原分析，已经幂等创建的 MAKE child 继续留作“待安排生产”任务；A4 版式沿用现有向导/打印能力。

提交仍固定走普通 generate：创建计划草稿、`ACTIVE` planning draft 和 `SUBMITTED` plan link，不直接批准。生成成功后回到/留在当前分析页，行状态刷新为“计划草稿待审”，显示计划号和“查看计划”；员工可以继续处理其他节点。

具有 `production_plan:approve` 的人员仍从权威审批入口批准。只有批准成功后才原子形成 READY、完整库存预留、DRAW 和销售已排量。多选生成默认整批原子成功或失败；任一库存、版本、指纹、BOM、组织或数量变化都使整批失败并要求刷新，不能静默部分成功。

## 五、按钮与接口安全清单

| 页面动作 | 接口 | 是否写业务事实 | 操作说明 |
|---|---|---:|---|
| 查历史、筛选、分页 | `GET /api/production/material-analyses` | 否 | 安全读取对象范围内记录 |
| 查销售候选 | `GET /api/production/material-analyses/sales-candidates` | 否 | 不返回价格 |
| 打开分析 | `GET /api/production/material-analyses/{id}` | 否 | 只读当前持久化快照 |
| 本地勾选/取消/全选、打开/关闭节点详情、取消计划向导 | 无 | 否 | 完整树始终显示；节点详情开关不写业务事实 |
| 开始或刷新分析 | `POST .../preview` | **是** | 持久化/刷新分析、来源和节点快照；使用版本、指纹和幂等键 |
| 确认路线 | `PUT .../{id}/routes` | **是** | 保存人工路线与原因并重算；“采纳建议路线（N）”是前端对该接口的批量封装，`route==suggestion` 无需原因 |
| 确认优先顺序 | `PUT .../{id}/allocation-priorities` | **是** | 改分析分配顺序，不是正式预留 |
| 通知采购/委外 | `POST .../{id}/notify` | **是** | 按路径任务创建权威 action、分摊及真实下游申请；不得生成生产计划 |
| MAKE 下层齐套后安排生产 | 当前复用 `POST .../{id}/notify` 的 MAKE 分支并提交精确 path action key | **是** | 重算下层门禁，幂等创建 `MAKE_COMPONENT` 并投影整节点 child ownership；当前无显式分批委派量 |
| 计划预览 | `POST .../{id}/plan-preview` | 不创建正式计划 | 服务端按当前库存/BOM/指纹做最终校验，返回一次性预览指纹 |
| 确认并提交审批 | `POST .../{id}/generate-plan` | **是** | 仅 MAKE/root 原子生成选中批次的计划草稿与提交关联；成功后留在本页 |

写按钮同时要求客户端有效权限与服务端 `allowedActions`；前端隐藏按钮不能代替服务端对象范围、状态、版本、指纹、数量和幂等校验。请求中按钮必须显示加载态并防连点；409 表示分析、库存或来源已变化，应刷新并重新确认，不自动重放写操作。

## 六、岗位交接 SOP

| 交接 | 上一岗位必须完成 | 下一岗位看到的权威任务 | 禁止误解 |
|---|---|---|---|
| 生产 → 采购 | 勾选 BUY 缺口并提交 | 计划来源采购申请/分解任务 | 通知消息不等于已经下采购订单 |
| 采购 → 财务 | 从任务中心选择申请行、填写部分数量，按单供应商/单仓生成订货并提交财务 | 订货审批任务 | 保存草稿不等于正式订单；业务人员不能自批 |
| 财务 → 仓库 | 合格财务审核组成员批准订单 | `inbound_expectations` 预计到货 | 预计到货不是现货、不是 IQC 合格、不能使生产 READY |
| 仓库/质量 → 生产 | 实际收货/回厂并完成 IQC，只有 PASS 数量转入目标仓合格可用库存 | 原分析重算后的可完工量/齐套任务 | 待检、FAIL、未入目标仓和仅有在途不得计入可完工量 |
| 生产 → 委外 | 勾选 SUBCONTRACT 缺口并提交；有供料 BOM 时继续备齐我方供料 | 计划来源委外申请/分解任务及供料节点任务 | 委外申请不等于已经发料或已经回厂 |
| 生产 → 自制子件 | 先把 MAKE 节点下层实际备齐，再点“安排生产” | `MAKE_COMPONENT` 子分析任务；父树投影为 child-owned、后代不再激活 | 子需求不是正式子计划；当前为整节点 ownership，不代表任意分批委派；须从 child item 生成草稿并批准 |
| 生产计划 → 车间 | 本页提交 MAKE/root 计划后由有权人员审核 | READY 执行段、DRAW 和计划详情 | 草稿/SUBMITTED 不得开工；DRAW 已审也不等于仓库已实际发料 |

## 七、当前验证与 NO_COVERAGE

旧口径证据见 [ADR-029 §12](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)和[迁移验收说明 §6](../数据迁移/56-生产计划前需求与物料分析重构.md)。隔离真实 HTTP 链曾覆盖 BUY 2 组、委外 2 组、MAKE 1 组、3 个未选控制组、采购/委外正式订单和财务批准，以及 61,000/122,000 的分批计划；桌面浏览器覆盖旧分区选择、高亮、BOM 红色缺料和 A4 向导。这些证据不能证明 ADR-033 已实现。
