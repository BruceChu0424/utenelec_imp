# V837 车间内流转免预开通内料仓

- 迁移：`V837__workshop_direct_transfer_no_preopen.sql`。
- 决策：[ADR-174 车间内流转免预开通内料仓](../99-决策记录-ADR/ADR-174-车间内流转免预开通内料仓.md)。
- 前置：V802(车间内料仓开通单一真源 `workshop_bins` 与直送资格门槛 `WORKSHOP_BIN_NOT_OPEN`)。
- 不加表、不加列、不回填数据；只重定义一个库函数。

## 为什么要改

用户口径(2026-10-10)：想要车间内流转(报工转下一道工序)必须先开通（例如）装配第一车间内料仓，
这不该是必须的——车间内流转像直接领料一样，上层工单直接领用，承接直送的内料仓始终是空的。
V802/ADR-147 的「必须预先人工开通」是开通真源的治理决策，不是直送本身的需要；数据形状上
「预先建好的内料仓」与「审核直送时系统建出的内料仓」完全相同。

## 迁移做了什么

1. 重定义 `fn_workshop_direct_targets`：删除 `stated` CTE 里「收料车间没有 `workshop_bins`
   开通行 → `WORKSHOP_BIN_NOT_OPEN`」的分支，其余逐字不变(diff 只含这一处与注释)。效果：
   候选列表、报工保存草稿校验(`requireEligible`)、单条断言 `fn_assert_workshop_direct_target`
   全部不再因未开通而拦。
2. 函数 COMMENT 更新为 V837 口径。
3. **不动**的(有意保留)：
   - `fn_workshop_direct_reason_text` / `fn_workshop_direct_reason_rank` 里
     `WORKSHOP_BIN_NOT_OPEN` 的文案与 rank——V837 之前的历史报工行送仓原因仍能回看；
   - `production_daily_report_items_output_route_reason_chk` check 约束里的历史枚举值；
   - 行级守卫 `fn_guard_workshop_direct_transfer_item`——直送明细的内料仓仍必须是收料车间
     开通行指的那一个、与收料需求同主仓，手工 SQL 依然绕不过。

## 配套(同事务生效，不在本迁移文件里)

- 服务层：`LineSideWarehousePort.ensureOpenedBinOf`(`WorkshopBinService` 实现)——审核直送读不到
  已开通内料仓时按需建仓并写开通行：与批量开通命令共用 `WORKSHOP-BIN:{车间}` 事务级建议锁；
  挂靠主仓优先取收料需求所在仓的主仓(守卫「与收料需求同主仓」因此恒满足)；发料来源仓置空
  (=按货品所属仓库)；`auto_created=TRUE`；名字被占/判断不出主仓时 409 拒绝并点名。
- 整批领料门槛(`fn_guard_workshop_material_settings`、复合外键)不变，不受波及。
