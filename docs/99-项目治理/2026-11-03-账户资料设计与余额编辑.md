# 账户资料设计与余额编辑

日期：2026-11-03。候选分支：`uimp/account-page-balance-20261103`；基线：`dfe3f3b67`。本记录对应用户提供的账户资料页截图及“进入编辑模式后，具备对应权限可填写盘点真实当前余额”的请求。

当前结果：账户页设计、有权限的单账户当前余额编辑、提示 icon 整理、Web 窗口切换草稿保护和公共保存焦点保护已完成源码及本机实际交互验证。以下早期失败为诊断审计事实，最终接收方案见末节；未上线、未正式打包、未修改生产余额。Win7 账户入口保持未迁移。

## 范围与权威入口

修改分类为前端呈现、交互及既有共享余额调整合同的调用。Web 与现有 Flutter 桌面端使用同一套 `AccountPage`，没有第二套客户端余额计算或保存方式。默认设计技能为 `frontend-design`，复用 Uten 组件、主题、精确金额和表格交互约束。

当前余额属于资金事实。填写盘点余额仍由 `POST /api/finance/account-balance-adjustments/batch` 创建不可变核对批次，不能通过普通账户主档更新覆盖 `balance_current` 或修改历史期初。`account:edit` 只授权主档编辑；余额调整继续要求 `account:view`、`account:balance:view`、`account:balance:adjust`（或服务端认可的超管身份）。不改变既有高危个人权限的授权渠道。

## 设计方案与自审

本页承担账户盘点和日常资金查看，以清楚阅读账户和余额为主。沿用 Uten 的 NotoSansSC 字体及现有主题，金额使用等宽数字。设计角色如下；实现继续引用已有 token，不另造一套主题数值。

| 角色 | 参考色值 | 本页用途 |
|---|---|---|
| 主色 | `#0F766E` | 主操作与关键交互 |
| 页面底色 | `#F5F7FA` | 工作区背景 |
| 表面 | `#FFFFFF` | 概览与表格阅读区 |
| 主文字 | `#0F172A` | 账户名称和余额 |
| 次文字 | `#475569` | 币种、数量与辅助说明 |
| 分隔 | `#E2E8F0` | 币种区隔和表格层次 |

布局采用左对齐通栏概览，独立显示每个币种的账户余额；账户数量和低余额预警收小，不与大额资金数字争夺视觉重点。币种之间用分隔线表达各自独立、不可合计。列表改为白底中性表格，使用和禁用通过状态文字区分。搜索与次要操作同排；主操作继续复用浮动操作组，窄屏操作收进 Uten 溢出面板。

```text
账户概览   账户数量 / 预警   │ 人民币余额 │ 美金余额
搜索账户                                  次要操作
账户表格：账户名称 / 类型 / 币种 / 当前余额
                                          编辑 / 添加
```

方案自审已放弃每个指标重复一张小卡片的排列，改用一条共享概览和币种分栏，让资金口径本身形成视觉秩序。不添加插图或装饰。编辑状态下可从当前余额进入单账户填写；仅具有余额调整权限的人员也可进入适用编辑状态，但主档字段仍服从各自权限。共享余额写 API 不变，单账户编辑组合既有批次弹窗状态机及确认/重试保护。

## 公共修复最终接收与实际 Web 回执

`UtenCollapsingHeaderScrollView` 的保留根现在有稳定的显式语义边界和独立子节点；重新附着后由公开 `markNeedsSemanticsUpdate()` 递归失效几何与拓扑，不销毁输入及其语义父节点身份。原 `clearSemantics()` 会让 Web 创建空 DOM 输入，而 Dart 保留旧输入连接及相同值，从而把空串回写草稿。仅删除清理会遗留旧 viewport sibling-merge 节点，递归 dirty 但没有独立边界也不能解决；这两个失败候选均保留实际错误证据，均不进入最终实现。

全部 6 份 `test/uten_collapsing_header_*test.dart` 共 25/25 通过，覆盖 touch、滚轮/重排、primary 隔离、全屏、宽窄/挤扁/2x 字号、原文/选区/composition/焦点及语义节点和父节点 ID。新增回归在独立旧实现中验证会失败：原清理版输入 ID `7→30`；无边界第二候选父 ID `6→35`。临时对照源码已清理，不修改全局 Flutter SDK。

实际 Web 又发现普通名称保存也会触发 `TextInput.updateConfig` 的 inactive DOM 断言。最终 `MasterInlineEditActions` 统一在 UI 保存前先 `unfocus`、等待一帧，并核对编辑代次和 context，然后进入原有 controller 保存流程；事务、验证、权限、未知提交及原文不变。新增 2 项回归先在旧代码跑红，候选与原 controller/reload 套件共 28/28 通过，覆盖 IME 原文/选区、失焦早于 busy、快速连点仅一写、等待期间取消再开始不能替新会话保存。余额外层弹窗同时复用已有 `UtenDialog.showAndWaitForExit`，不在退场动画中刷新保留编辑器；列表/详情回执均核对原读归属。
