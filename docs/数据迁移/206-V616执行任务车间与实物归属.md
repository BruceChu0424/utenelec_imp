# V616 执行任务车间与实物归属

迁移：`V616__execution_workshop_material_custody.sql`。依赖 V615 的直送来源批次投影；新增函数、触发器和退料来源部门列，不改写历史数量、单据、默认存放仓或员工归属。

## 修复的问题

`WAITING`、`READY` 只说明任务尚未开工，不表示材料还在仓库。旧分配接口仅按这两个状态允许换车间，因此已经实领、已经直送但尚未确认路线的任务也可能把原车间材料一起带入新任务归属。固定批量或整包用料的后批还可能在前批收料前先换车间，随后直接承接前批在原车间领取的材料。

## 统一判据

服务端分配预检与数据库 `workshop_department_id` 更新守卫共同调用 `fn_can_reassign_execution_workshop`：

- 未开工、未发生实物交接的任务仍可正常改派到有效新车间，普通仓库的未发料预留和领料单保持原实际仓库、数量和 UUID；专属于本任务且从未实发的 DRAW 同步当前收料车间与负责人。已有待发单时不能清空收料车间。
- 已提交领料申请但尚未实发，也按上项同步交付安排，保留原申请事件、行数量和单据身份；以本次改派版本刷新仓库待发任务。无需撤回不存在的申请动作。含多个任务的历史共用领料单不能只改其中一个任务到其他车间，须整体重新安排。
- 原车间真实净领料未归零、有效线边预留或当前需求及其根需求仍有未分配直送料时，先按原链真实退回/撤回，再更换车间。待退申请不等于仓库已收回，不能解除实物归属限制。
- 有固定批量或整包共用物料关系的执行批，必须先撤回关联批次并重新安排，不能把一份共用物料变成没有交接凭证的跨车间用料。不存在共用物料关系的独立批不受此项限制。
- 同车间调整负责人、班组或日期继续沿既有分配校验；不因为实领而关闭这些正常安排。

数据库守卫保留原有版本、派工后分配冻结、员工在职和组织范围等规则。迁移不会自动搬运库存、重新归属已领物料或把技术线边位置改成货品正常存放仓。

分配命令先沿 `ProductionPlanMutationFootprintService` 锁定正式计划履约范围，再锁任务与领料单，并复核足迹。只有当前事务中新产生、版本匹配且操作者一致的 `ASSIGNMENT` 事件，才允许领料单把 `department_id/worker_id` 精确同步为本任务当前分配；其余字段仍不可变。曾经实发的单据即使后来反向也不重写原交付身份。已提交的改派事件不能成为下一次通用 SQL/CRUD 改单的授权。

`ASSIGNMENT` 事件追加式保存，UPDATE（即使值不变）与 DELETE 均拒绝，防止改写旧事件刷新事务标识来冒充新改派证明。开发环境的受控整库清理仍沿原 `TRUNCATE` 规则，不靠删除单个历史事件绕过。

## 存量错配

`fn_execution_material_custody_valid` 统一核对当前任务及共用前批的真实未退回领料、未释放线边预留和未分配直送料。已知原领料车间或线边位置与任务车间不一致时，普通物料产能为零，START 和正向报工（包括恢复报工候选）关闭，并明确提示原车间冲突；原来源退仓、取消出库和日报反向仍可办理。待退申请不解除冲突，真实收回后才重新核对。

普通库存的实际叶仓 UUID 不等于生产车间 UUID，主仓下的正常叶仓领料不受误拦。历史普通 DRAW 未记录部门时不猜造冲突；已存在的部门和技术线边车间身份则必须尊重。未实发的旧收料快照，可由有权限人员显式保存当前分配修复，即使车间、负责人值未改；已实发凭证始终不重写。

## 未开工退料与原任务再领

`READY`、`DISPATCHED` 已经真实领到物料时，可以沿原 ISSUE 来源申请余料退库；无需先开工。是否可退由 `fn_execution_material_return_allowed` 及每份 ISSUE 的净可退数量共同确定，待退申请冻结对应来源数量，仓库实际收回才减少车间持料。没有实领的待料任务和终态任务不提供新退料动作。共用后批已占用的来源仍不能提前退回。

V616 保存原实际 DRAW 的来源仓和部门。当前操作人负责提交与审计，但当前任务的新部门不能冒充原交接部门。同一来源仓存在不同原部门时，一次申请自动分组，保留每行 ISSUE UUID；`source_department_id` 与扩展的幂等唯一键支持此分组。历史已发生单据及部门未知的记录保持原样，不回填猜测。后续 [V618 余料实际收仓](208-V618车间余料实际收仓.md) 将来源仓与实际收仓明确分开：当前车间把余料送正常仓库，原技术流转位置只保留来源证明，不能作为默认接收仓。

普通同仓实退恢复原需求的正式预留余额；跨实际叶仓的余料沿 V618/V619 精确来源移交承接，不把原技术位置的可用量重新凭空恢复。员工显式“重新核对物料”时，按当前实际存放仓的专属余额减去尚未实发的有效 DRAW 承诺准备补领草稿，再走原领料申请和仓库实发；不会在退料瞬间自动新增承诺，也不会借用公共库存或重复 CLAIM。齐套生产与持续生产均可在同一任务内再领，仍实际留在车间的材料走既有显式命令自动投入路径。

`fn_execution_demand_draw_commitment_qty` 将当前承诺统一为“未实发 DRAW 基本量 + 净实际 ISSUE”。执行段超配守卫使用此净值；历史 DRAW 仅保留曾经备齐的证明。实领 10、实退 3、再领 3 时，历史 ISSUE 共 13、GOOD_RETURN 共 3，而当前承诺、原预留和净投入仍为 10；不会改写原 DRAW 的数量或用逆退冒充再次领料。重复核对和相同幂等键均不重复生成补领承诺。

材料写命令和 capability 与执行任务统一调用在职操作者判据。离职的历史计划 maker 保留既定历史只读范围，不能经 owner 范围回退重新取得退料、材料结算或结案写权限；有相应权限的在职 maker 继续拥有既定计划管理范围。
