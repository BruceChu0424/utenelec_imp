# 87 - V469 生产成品按明细分批登记送检

## 一、问题与决策

V430 要求一张已审核生产日报一次覆盖全部活动行，并限制 `source_report_id` 唯一。仓库在同一日报
只有部分成品实际可送检时，无法先办理已到行；把一行从页面移出会导致整单校验失败。

V469 只放宽“日报必须一次办完”，不放宽来源事实：同一日报允许多个追加式登记批次，每批至少
一行；`source_report_item_id` 继续全局唯一并由 ENABLE ALWAYS 触发器校验日报归属、execution
segment、inspection 与 legacy exemption。登记头/行继续不可更新或删除并接 `fn_audit()`。

## 二、迁移行为与旧数据兼容

- 删除 V430 自动生成的 `production_finished_arrival_registrations_source_report_id_key`；
- 新增 `(source_report_id, created_at DESC, id DESC)` 索引，支持大数据下待办详情、幂等回放和最近
  登记查询，不按可变单号/货品编码关联；
- 重建同名延迟约束触发器：事务提交前每个登记头必须至少有一条登记行，跨日报行继续拒绝；
- 不 INSERT/UPDATE/DELETE 任何历史登记、FQC、日报、库存、`fqty/iqty` 或库位偏好；旧 V430
  “一日报一批且全覆盖”记录天然满足新约束；
- 已应用 V430/V431 字节保持不变。发现 checksum、缺迁移或目标版本集合漂移时停止，禁止
  `flyway repair`。

## 三、应用事务

服务端先锁日报，再按 UUID 顺序锁出仍未登记、未 FQC、非 legacy exemption 的活动行；请求 UUID
必须是该集合的非空子集。不同操作者/幂等键争抢同一行时，后到事务返回 409；不同行可以顺序形成
不同批次。登记头、所选 `place_snapshot`、逐行 FQC PENDING 和 Outbox 在同一事务提交或回滚。
幂等回放按 `created_by + idempotency_key + request_hash` 返回原 registration UUID 和原批次明细，
不会误返回同日报的后续批次。

登记后的“同时记住库位”必须把响应中的 registration UUID 原样带回：单张使用可选
`registrationId` 参数，批量使用 registration UUID 清单端点。服务端按该批次读取快照，并由
`source_registered_at + source_registration_id` 顺序守卫拒绝较旧批次覆盖较新偏好；不能只传
report UUID 后再猜“最新一批”，否则同日报并发办理会串批学习。兼容旧端点仅在该日报恰有
一个登记批次时工作；发现多个批次即 409 失败关闭并要求刷新，绝不猜最新。

待办、详情和通知投影按行判断：只要日报仍有一条符合条件且不存在登记行/inspection/exemption 的
明细，日报继续显示；行数与数量只汇总未登记行。页面“移出本次登记”仅修改本地请求，不调用删除
API；采购、委外同样只把所选订货行从当前收货请求排除，来源剩余量保持待登记。

批量页面上限 50 张，但正常读取不是 50 次循环：待登记表头/明细合并为两次有界 SQL，库位建议
按所选 report UUID 清单一次查询；只有并发后已完成的少量陈旧选择回退到单册历史/404 判定。
关键谓词使用 `production_daily_report_items(report_id)` 与三个来源行唯一索引，任务列表继续服务端
分页，避免数据增长后把全量行搬到 Flutter 过滤。

## 四、权限、审计与库存边界

- 自制读取：`stock_doc:view`；提交：`stock_doc:view + stock_doc:approve`，且服务层继续要求有效
  `SUB_WH` 仓储对象范围；
- 采购/委外读取/提交：`warehouse_inbound:view + warehouse_inbound:stock_in`，来源订单、真实委外
  出仓、超量财务隔离和价格脱敏门禁不变；
- “移出”不是持久化删除，无删除 API、无库存或历史副作用；真正提交仍由登记表审计、请求审计、
  FQC 事件和后续库存账形成证据；
- 送检登记仍不写库存、不增加 `iqty`。品质 PASS 只形成合格待点收，最终仓库确认才写库存。
