# 货架目视化清单页

> 路由：`/warehouse/shelf-labels`（`lib/features/warehouse/pages/shelf_label_page.dart`）· 2026-09-10 信息架构重做
> 权限：页面与查询 `stock:view`（全员，与库存查询同权）；加密 Excel 导出另需 `stock_report:export`
> 上层：工作台 → PMC 运营部 → 仓库管理 hub → 「库存查询」分区 · 数据口径：货品主档 `goods.stock_place`（库位号）

## 一、定位

**现场找货的工具**（2026-09-10 起），不再是「纸质挂牌的屏幕镜像」：

- 上半屏「货架图」按 库行 × 层 × 位 摆格子，一眼看出这排货架第几层第几位放什么；
- 下半屏统一表格可筛可排可导出，点格定位、点行反查，两边双向联动；
- 打印张贴仍在（预览打印 → A4 横版挂牌版式），只是从「页面主体」降级为一个出口。

口径五条（分支行为，见 §五）：

1. **禁用货品默认不列**——`includeDisabled=false`；工具条开「显示已禁用货品」才出现，状态列标「已禁用」；
2. **删除（软删）货品不列**——`goods.is_deleted = true` 一律排除；
3. **库位号清空即下架**——主档 `stock_place` 置空后该行自然消失（学习回写只在非空且不同时更新）；
4. **选仓 = 本仓偏好优先**——选了仓库时库位号取 `COALESCE(warehouse_goods_place_preferences.place, goods.stock_place)`，
   同一货品在不同仓可显示不同库位（列头 ⓘ 已写明）；
5. **多色同货品一行**——主档一个货品一行，颜色取 `goods.color_id`。

**即时库存是参考列**（不再声称「与库存数量无关」）：未选仓 = 全部参与核算仓库汇总，
选仓 = 该仓及其子仓汇总；货架摆放仍以库位号为准，库存为 0 的货位照样列出。

主档库位号由三条学习路径保持最新（V451 起）：仓库到货登记回写、IQC 合格品入库确认回写、
产成品到货登记的「记住库位」（写入仓库×货品偏好，详情见
[迁移说明 71](../数据迁移/71-IQC入库库位学习.md)）。因此货架清单会随实际入库自动长出新货位的行。
列头 ⓘ 也据此提示「库位号由入库登记自动学习，可在货品资料改正」。

## 二、入口与导航

- 仓库管理 hub「库存查询」分区 →「货架目视化清单」卡片进入。
- AppBar 返回回仓库 hub（`backTo` 默认 `RouteName.warehouse`）；AppBar 另有手动刷新图标
  （字典 + 库行/布局 + 清单三者同口径整页刷新）。

## 三、布局

自上而下四段（`UtenContentContainer.wide` 全宽数据页）：

1. **筛选工具条**（`UtenFilterToolbar<String>`）
   - 分段 = 库行：`[全部] + /shelf-labels/racks`（**只含已分层库行**，残值不进分段）；
     进页面默认不选 = 全量，「全部」是显式段；切换分段清空定位态并带 `rack` 重查；
   - 搜索：名称 / 编号 / 系列 / 库位号模糊，300ms 防抖后下传后端；
   - 行尾 `Wrap`：仓库筛选字段 [`UtenFilterPickerField`](../02-组件库/UtenFilterPickerField.md)
     （2026-09-11 起全站统一，与即时库存同款：点开 `showUtenWarehousePickerPanel` 侧滑面板，
     `includeAll`+`allowParent` 查询口径——顶部「全部」行 + 整棵层级缩进一次铺开、
     主仓一点即选 = 自身 + 全部子仓聚合；**真过滤**，字段与搜索框等高、圆角 `UtenRadius.control`）、
     「显示已禁用货品」`FilterChip`、
     「未分层 N」`FilterChip`（残值计数；点选即把表格收敛到未分层行）、「共 N 项」。
2. **货架图**（[`UtenRackGrid`](../02-组件库/UtenRackGrid.md)，限高 320 + 竖向滚动）
   一库行一张卡：卡头「A31 库行 · N 项」，行 = 层（高层在上）、列 = 位、格 = 库位号；
   同库位多货品聚合成一格并显 `+n`；空位弱化「—」不可点；
   「未分层（N）」单独一段平铺 + 指路「请在货品资料改正（如 A31-3-1）」。
3. **定位提示条**：点格后出现 `InputChip`「已定位库位 A31-3-1」，✕ 一键取消收敛。
4. **统一表格**（`MasterDataTableView<ShelfLabelRow>`）
   列：**货架 / 层 / 位 / 库位号 / 货品编码 / 货品名称 / 颜色 / 单位 / 即时库存 / 状态**；
   - 列头筛选（客户端聚合 facets）：货架、层、状态三列；
   - 列头 ⓘ：「库位号」= 学习来源 + 格式说明（选仓时追加「本仓偏好优先」）；
     「即时库存」= 全部核算仓 / 本仓树汇总口径；
   - 状态列走 `UtenStatusBadge`（启用绿 / 已禁用中性）；
   - 表头工具条右侧：「预览打印」+「下载 Excel」（`UtenExportButton`）。

## 四、功能点

1. **点格定位（图 → 表）**：点货架图某格 → 表格收敛到该库位（同格多货品全部保留）
   并出定位 chip；再点同一格取消。
2. **点行反查（表 → 图）**：单击表格行 → 货架图高亮该格并自动滚入视口；**不收敛表格**，
   方便连着点下一行继续对位。
3. **仓库切换**：清单 / 库行分段 / 货架图布局三个查询一起带 `warehouseId` 重查，
   并清空定位态（换了仓，原来的格不一定还在）。
4. **显示已禁用货品**：开关同时作用于清单、库行分段与布局三个查询。
5. **未分层 chip**：老库残值（`'19'`/`'Y12'` 之类）不冒充库行，只在货架图末段与工具条 chip 出现；
   批量治理见 §六。
6. **预览打印**：弹窗内可改抬头标题（`UtenInput`，默认 = 所选仓库名 +「物料库」）；
   灰底白纸分页预览，PDF 走 `pdf/printing`（`NotoSansSCFull.ttf` 全量字体）。
   每个库行独立 **A4 横版**页，版式 = UTEN 头（左 logo 文案 / 中标题 / 右库行徽章）+ 五列斑马表；
   每页最多 16 数据行，每库行末尾留 6 行空白供现场手写补充。打印分组用**列头筛选后**的行
   （与屏上所见一致），点格定位那种临时收敛不影响打印件。
7. **Excel 导出**：`POST /stock/reports/export report='shelf-labels'`（加密 xlsx），
   查询参数 = `rack/keyword/warehouseId/includeDisabled`（服务端筛选口径）；
   列头筛选是客户端视图态，不下传导出。
8. **空态 / 容错**：无已维护库位号的货品 → 货架图空态 + 表格引导文案；
   库行/布局加载失败不阻塞主表；清单失败显错误 + 重试。

## 五、数据链路

```http
GET /api/stock/shelf-labels?rack=&keyword=&warehouseId=&includeDisabled=false
    → [{goodsId, rack, place, goodsCode, series, goodsName, colorName,
        unitName, qty, disabled, level, slot, parsed}]
GET /api/stock/shelf-labels/racks?warehouseId=&includeDisabled=       → ["A31","B02"]（只含已分层库行）
GET /api/stock/shelf-labels/layout?warehouseId=&includeDisabled=      → [{rack, maxLevel, maxSlot, count}]
                                                                        （rack='' 的末条 = 未分层桶，残值数>0 才出现）
POST /api/stock/reports/export  report='shelf-labels'                  → 加密 xlsx（含 层/位/即时库存/单位 列）
Authorization: stock:view（导出另需 stock_report:export）
```

服务端（`StockQueryService.shelfLabelRows / shelfLabelRacks / shelfLabelLayout`，
SQL 在 `ShelfLabelSql`，解析在 `ShelfPlaceParser`）：

- `stock_place` 先 `BTRIM`，匹配 `^[A-Za-z]*[0-9]+-[0-9]+-[0-9]+$` 且层/位段 ≤6 位才算已分层
  （`parsed=true`，`rack`/`level`/`slot` 下发）；其余一律 `parsed=false`、`rack=''`、层位 null；
  Java 侧 `ShelfPlaceParser` 是 DTO 真值，SQL 侧同口径只用于筛选/排序/布局；
- 即时库存 `LEFT JOIN` `stock_balances` 按货品汇总（选仓时按仓树递归 CTE 限定），单位 `LEFT JOIN units`；
- 选仓时库位号 `COALESCE(warehouse_goods_place_preferences.place, goods.stock_place)`
  （与产成品到货登记 `ProductionFinishedArrivalRegistrationService` 同口径）；
- `includeDisabled=false` 时追加 `g.status IS DISTINCT FROM '禁用'`；软删货品恒排除。

前端仓储：`StockQueryRepository.shelfLabels / shelfLabelRacks / shelfLabelLayout`
+ `ShelfLabelRow` / `ShelfLayoutRack` 模型（`lib/features/stock/repositories/stock_query_repository.dart`）。

## 六、残值治理

老库 `B_Goods.StockPlace` 的历史内部代码（`'19'`/`'Y12'` 等）会原样迁进 `goods.stock_place`。
页面已把它们收进「未分层」桶（不再冒充库行进分段），但主档里仍应清掉，否则货品资料/报表
「库位号」列继续误导。治理脚本：

`server/legacy_migration/clean_shelf_place_residue.sql`（**人工确认脚本，不是 Flyway 迁移**）
——先跑演练输出残值明细/汇总/前后计数对账，仓库确认没有真实非标库位混在里面后，
带 `-v confirm=1` 再执行置空。详见 [数据迁移 17 §十二](../数据迁移/17-仓库管理-新库与迁移.md)。
