# 登录历史与客户资料权限及多人负责人

## 范围与交付状态

本次对应三张反馈图：登录历史手机号直接点选、销售维护本人客户的普通资料与财务字段分权、财务维护多个客户负责人。前端默认使用 `frontend-design`，复用 Uten 主题、表格、表单和员工多选器；本次为本地源码修改与回归，不代表公司服务器已更新或真实岗位验收完成。

登录历史点选的业务修复已存在于本轮起点源码（`6d5c2e516`）。本轮保留输入框和浮层共享 `TapRegion`、延后失焦检查的实现，增加截图尺寸、缩放、鼠标跨帧按下、卡片外浮层滚动与行空白选择的调用方回归，避免把已有修复重复记为本轮新增。

## 交互与字段规则

保持现有紧凑 ERP 信息密度，内容左对齐，沿用 `NotoSansSC` 和当前文字层级。颜色使用主题 token：主色 `#14B8A6`、操作深色 `#0F766E`、背景 `#F5F7FA`、卡片 `#FFFFFF`、正文 `#0F172A`、边框 `#E2E8F0`，随现有明暗主题切换，不另建页面配色。修改围绕角色可执行的动作展开，客户详情直接提供「负责人和可见人」入口，列表负责人单元格在授权且对象可管理时显示可点击的管理入口，未授权时保留纯文本。单元格、右键和批量设置共用同一维护合同，负责人设置不再经过普通资料编辑权限的只读拦截。

客户普通字段由 `client:edit` 与对象写范围共同控制。本人及合法共同负责人可维护普通资料；额外可见人、手工增加的整人查看范围继续只读。既有查看全部与正式交接范围遵循原对象策略，新增共同负责人不扩大为其他客户的整人写权限。

`client:finance` 独立控制开户行、银行账号、税号、信用额度、期初应收、结算天数、默认结账方式、默认币种及铺底额；历史 `price_style`、`init_total2`、`exchange_rate` 受同一财务限制。普通编辑、详情就地编辑、行内编辑和版本恢复均使用该边界。非财务表单将相应字段显示为只读，保存时排除；后端仍检查伪造请求。具有财务权限且对象范围可写、没有普通编辑权限的账号仅维护财务字段；额外可见人或整人只读范围不因具备财务权限自动变为可写，跨客户财务维护须有合法的全部客户范围。旧库 Credit 快照继续只读并从请求剔除，避免客户端数值转换回写。

默认货运策略属于销售条款，保留普通销售维护能力。销售订货单原有的结账方式、币种自动记忆由专用订单事实同步流程维护，不以此开放客户主档的财务直接修改。历史销售单据的制单人、负责人、审批人、数量和金额不随客户负责人设置改写；报表仍按原有主负责人分组，不能把一笔金额按共同负责人数重复累计。

客户文件识别同样遵守税号财务边界：无财务权限时不提供税号补全候选，恢复旧识别结果时客户端也排除该候选与提交字段。从文件新建客户保留名称和联系信息，去除无权维护的税号；伪造请求仍由服务端拒绝。既有普通客户信息学习和货品对照不因新增财务权限整体失效。

多个负责人通过独立客户访问设置接口维护，要求现行 `client:assign` 权限、对象可管理范围、有效员工账号、版本和变更原因。主负责人保留在 `clients.owner_employee_id`，其他负责人存于关联表；读取返回完整负责人集合。原有单负责人 API 字段保留兼容。负责人和只读可见人的身份互斥；移出的在职原负责人按既有在途处理规则保留只读查看，不因此保留普通资料写权。正式离职交接也必须处理共同负责人关系。

## 公共入口及调用方清单

| 职责 | 公共入口 | 适用调用方与保留差异 |
|---|---|---|
| 登录账号历史 | `AccountField` | `LoginPage`；删除按钮独立命中，行文字和空白均可选择，外部点击可继续到达登录按钮。 |
| 客户字段及提交过滤 | `buildClientFields` / `MasterEditFormController.buildBody` | 分类页新建、列表行内编辑、共用编辑弹窗、详情就地编辑；财务权限与普通写范围分别计算，只读字段不构造进请求。 |
| 客户财务字段边界 | `ClientFinancialPolicy` | 普通保存、行内编辑、操作撤回/重做及对象版本恢复；旧 Credit 只读和订单自动同步保留专用规则。 |
| 客户对象范围 | `ClientAccessPolicy` | 列表、计数、筛选、字典、导出、详情、联系及地址、文件学习、生命周期和修改历史；共同负责人按客户身份判定，额外查看不变成写范围。 |
| 管理员查看范围候选 | `DataScopeAdminService.ownerCandidates` | 主/共同负责人均进入客户归属候选，按客户与员工去重计数；软删除、未分配客户与旧财务桩继续排除，不扩大写权限。 |
| 多人负责人及可见人 | `ClientAccessService` / `ClientAccessPanel` / 批量设置 | 详情、列表菜单、列表批量设置；单条版本冲突、批量原子性、变更原因及审计统一维护。 |

本轮扩展已有入口，未建立第二套客户编辑器或另一个负责人写接口。供应商、货品等主档保留各自权限与归属语义。

新权限沿用 V936 默认关闭政策，不由数据库迁移猜测人员身份、伪造操作人或覆盖现有显式收回。部署后，管理员须通过现有权限管理为需要办理的财务人员显式开通「客户财务维护」；维护多人负责人还需「负责人和可见人」权限及相应客户范围。销售仍使用其现有「维护客户」权限与本人客户范围。
