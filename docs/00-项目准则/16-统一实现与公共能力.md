# 统一实现与公共能力

本规范承接用户追加的“八、统一实现与公共能力，避免重复维护”，适用于整个项目中的 UI、交互、算法和业务处理。相同职责且业务语义相同的能力统一为公共实现，由各模块调用，使一处修复覆盖全部相关入口。

涉及 UI 和交互时默认使用 `frontend-design`，沿用 Uten 组件、主题 token 和交互协议，见[设计技能选择](00-准则索引与开发清单.md#设计技能选择)及[组件库使用规范](09-组件库使用规范.md)。纯后端、数据库、部署和非界面文档按对应规范实施。

## 一、先排查重复实现

每次涉及一项功能，先检查同类页面、组件、服务和算法，不能只看当前修改的一个页面。范围包括主页面、弹窗、详情、历史、报表和导出，以及对应的前后端入口。

在所属阶段台账中记录已有实现及其完整调用位置，比较正确性、性能、交互、边界处理、维护成本和业务差异。搜索用于发现候选；职责和语义是否相同，还须结合合同、源码及实际调用确认。

| 已有实现入口 | 完整调用位置 | 优势与已验证能力 | 缺陷和边界风险 | 业务语义及必要差异 | 处理结论 |
|---|---|---|---|---|---|
| 填实际文件及符号 | 按模块和入口逐项列出或链接清单 | 附证据 | 附证据或标待验证 | 币种、单位、精度、权限、生命周期等 | 复用、改进、替换或保留及理由 |

## 二、合并优势，形成一套方案

存在多套同责实现时，先确认各自正确能力和约束，再确定公共合同与替换方案。比较应覆盖正常、空值、错误、取消、并发、历史兼容和大数据等适用边界，并明确如何保留已有正确能力。

不能简单拼接两套代码，也不能为统一而删去其中已正确处理的场景。先锁定行为和数据合同，再以测试及实际调用验证公共方案；有缺陷的旧行为不自动成为统一后的规则。

## 三、公共实现作为唯一维护入口

通用 UI 通过共享组件、主题和交互协议维护；通用计算、查询及处理逻辑通过共享服务或算法维护。按现有职责边界放置，不另建重复的公共层：

| 能力 | 职责边界 |
|---|---|
| 纯 UI 基础能力 | 使用 `lib/components/`，不依赖 feature、业务模型或业务 Provider |
| 跨模块 UI 组合 | 使用 `lib/shared/widgets/` 表达稳定的跨模块展示，不依赖具体页面 |
| 通用客户端算法与服务 | 在现有 `lib/core/` 或 `lib/shared/` 对应职责下维护，调用方只编排业务差异 |
| 服务端业务计算与处理 | 在拥有业务事实及事务的领域服务维护，经现有 application port 提供跨域能力；不为抽公共层打断事务 |

业务差异通过清晰的参数、配置、组合或策略表达，调用方只保留必要差异。禁止复制公共实现后局部修改，禁止以大量无关分支堆出万能组件或万能服务。只适用于单一页面、没有稳定复用职责的组合可保持私有，并说明边界。

## 四、迁移全部相关调用方

公共能力完成后，实际替换全部适用入口，包括同类页面、弹窗、详情、历史、报表和导出。不得只迁移示范页面后宣布统一完成。

维护逐入口迁移清单，记录旧实现、新公共入口、保留的业务配置、接入状态及验证证据。尚未验证的入口保留待验证状态；代码命中、编译通过或公共组件单测不能代替调用方接入回归。

确认没有有效调用、兼容需求和回归问题后，再清理旧实现及失效引用。过渡期间必须写清保留原因、剩余调用方、移除条件和所属阶段待办，不能让新旧两套长期并存。

## 五、统一不能改变业务事实

先确认职责和业务语义相同。不同币种、单位、计价规则、库存归属、权限和生命周期不得为共用而强行合成一个口径；应共用稳定机制，并将必要差异留在明确策略或领域边界中。

统一过程必须保留原始输入、精度、来源、历史、幂等和未知提交语义，不能用格式化后的展示值覆盖原文，不能因取消等待而重放业务写入。保留 B0 的身份与请求代次隔离、输入与草稿保全、后台计算或分片让帧、完整模型及响应性保护，不能以截断数据或只提交可见行换取性能。

B0 合同和历史验证见[前端数据加载解耦实施与验证](../99-项目治理/全平台整改交接/10-前端数据加载解耦-B0实施与验证.md)；该记录不能代替本次改动后的回归证据。

## 六、跨前后端统一规则与权威来源

业务权威计算集中在正确的服务端入口，前端预览只提供即时反馈，最终结果以服务端校验和计算为准。列表、详情、历史、报表和导出必须遵循各自业务语义下的同一权威规则，不能各自维护第二套金额、数量或权限口径。

跨语言无法直接共用代码时，统一输入输出契约、精度与舍入、规则版本、错误语义及测试样例；由同一组样例分别验证两端。适合时采用同源规则或生成代码，避免手写两份后各自演变。历史结果仍按原始事实及适用版本解释，不静默用新规则重算覆盖历史。

前端预览保留本地即时输入、防抖、有界计算及异步响应性，不得为共用而让每次输入等待后端，也不得重新引入主线程长时间计算。只发布完整且属于当前身份和请求代次的结果。

## 七、用证据验收统一成果

每个大阶段的回执必须包含以下五类内容，并与实际候选源码或提交对应：

1. 公共组件、服务或算法入口，以及其合同和权威来源。
2. 已迁移的完整调用清单，逐项覆盖模块、页面、弹窗、详情、历史、报表和导出等适用入口。
3. 已清理的重复实现、失效引用，以及旧实现无有效调用和兼容需求的核对结果。
4. 尚保留的差异及必要原因；过渡实现另列剩余调用方和移除条件。
5. 公共能力测试、调用方回归和实际交互结果，包含性能、边界及业务事实保护的适用证据。

既要证明公共实现正确，也要证明所有调用方接入正确。UI 记录真实入口的输入、加载、错误恢复及必要的多端/字体/主题交互；计算和处理记录适用的精度、权限、并发、反向与历史回归。仅凭代码搜索或公共组件单测不得宣布全阶段完成。

可在现有阶段回执中使用以下字段，不另建脱离阶段的第二套完成状态：

```text
大阶段 / 候选源码或提交：
重复实现比较表及完整调用清单：
公共入口 / 合同 / 权威来源 / 规则版本：
逐调用方迁移状态 / 保留配置 / 回归证据：
删除的旧实现 / 无调用及兼容核对证据：
保留差异及原因 / 过渡移除条件：
公共能力测试 / 调用方回归 / 实际交互结果：
精度、来源、历史、幂等、未知提交与 B0 回归：
失败、跳过、未覆盖项及剩余待办：
```

## 八、贯穿各阶段与执行节奏

各阶段边实施边统一，当阶段涉及某项功能时就完成其公共方案及全部适用调用方迁移，不能将已发现的重复实现全部拖到 B4。B4 再做全项目覆盖复核，核对遗漏入口、残留重复实现、必要差异及完整回归证据。

小阶段之间不停下来逐项询问，按本会话已明确的额度规则持续完成整个大阶段；进度说明和回执同步不构成暂停点。本规范不重设额度阈值，也不从历史云端任务指引推定本次额度、阶段范围或停止条件。旧台账的 B04、B27 等批次号不能直接视为这里的 B4。

本规范记录执行要求，不代表任何阶段或全项目统一已经完成。完成状态仍以所属阶段实际迁移清单及验证证据为准。
