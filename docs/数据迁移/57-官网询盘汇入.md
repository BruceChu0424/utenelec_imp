## 一、迁移对象

`website_inquiries` 表（官网询盘快照 + 处理状态机）：

- `source_id TEXT UNIQUE`：官网 `inquiries.id`，推送重试/重放的**幂等键**；重复推送返回 `created:false`，不重复建行。
- 联系与需求快照：name/phone/email/company/market/customer_type/required_standard/product_interest/request_type/estimated_quantity/target_schedule/preferred_contact/message/source/locale，与官网表单字段一一对应。
- 状态机：`new → following → converted / closed`；`converted` 只能由转客户动作到达（必须已成功关联 `client_id`），不可手工选；终态（converted）拒绝再改状态（409）。
- `assignee_employee_id` 跟进人、`client_id → clients` 转客户关联、`note` 最近跟进备注、`received_at` 接收时间。
- 审计列一次带全（created_at/updated_at/created_by/updated_by，实体继承 `BaseEntity`），并在本迁移内直接创建 `trg_audit_website_inquiries`（V252 全量 sweep 只覆盖当时已有表，晚于它的新表须自行登记）。

## 二、权限

新增两个权限点，`module='销售管理'`、`category='官网询盘'`（遵守 V228 就地写 module/规范 category 的约定，不落入兜底「其他」）：

| code | 名称 | 用途 |
|---|---|---|
| `webinquiry:view` | 官网询盘-查看 | 列表 / 详情 / 未处理数 |
| `webinquiry:manage` | 官网询盘-跟进与转客户 | 跟进状态推进、关闭、一键转客户 |

**不回填任何部门**（最小授权，与 V86 同原则）；上线后由超管在权限管理页授给综合营销部。超管恒有全部权限。

## 三、接口边界

- `POST /api/website-inquiries/ingest`：官网服务端单向推送入口。permitAll 但由 `WebsiteInquiryIngestGuard` 收口——共享密钥常量时间比较（`uten.website.inquiry-ingest-token` / `UTEN_WEBSITE_INQUIRY_INGEST_TOKEN`，**未配置时 fail closed 拒绝全部**）+ 每分钟 60 次固定窗口限流。该路径同时受 `LocalNetworkGuardFilter` 内网边界覆盖：本地部署（site=local）下官网服务器必须在 `UTEN_LOCAL_ALLOWED_CIDRS` 网段内；云端部署须单独评估该边界。
- 管理接口（均要求员工 JWT + 对应权限点）：分页列表（状态/关键词）、`new-count`、详情、`/{id}/status`、`/{id}/convert`。转客户按询盘快照创建**最小客户主档**（名称=公司或联系人、归属当前员工、备注留 `来源：官网询盘 <source_id>` 溯源），重复执行幂等。V272 候选下，`WebsiteInquiryClientAdapter` 查询 `client_categories.legacy_id=-1` 的受保护系统根并显式写入 `categoryId`；根缺失时失败关闭，不绕过公共 `ClientSaveRequest.categoryId` 必填契约。
- 异常一律走 `ApiException + ErrorCode`（401/404/409/422/429），不抛 `ResponseStatusException`（全局处理器不识别，会变 500）。

## 四、官网侧契约

`submitInquiry` 先落官网 SQLite（唯一事实写入），随后 fire-and-forget 推送（4 秒超时）：推送失败只记服务端日志，**不影响客户提交**，官网 `/admin/inquiries` 保留全部留言作兜底副本。配置见 `website/.env.example`（`IMP_INGEST_URL` / `IMP_INGEST_TOKEN`，与 IMP 密钥成对）与 `website/docs/cloud-server-deployment.md`。
