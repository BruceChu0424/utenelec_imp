# 报销审批详情页

> 路由：`/expense/approval/:id` · 实现：`lib/features/expense/pages/expense_approval_detail_page.dart`
> · 上层：[页面总览](页面总览.md) · 状态机见 [全局机制 §3.3](../05-架构/全局机制.md#33-报销审批流expenseclaim)

## 一、定位

审批人/财务视角的单据审核工作台：**核对票据(发票登记要素 + 影像附件)→ 通过/驳回 → 打款**。
2026-09-19 V608 补齐了审批人看发票的核心场景，并修复金额抹零
(原 `toStringAsFixed(0)` → 两位小数)。

## 二、页面结构(对齐财审页 finance_procurement_approval_review_page 范式，默认 1600 容器)

- `UtenAppBar` + actions「打印报销单」(同详情页打印件)。
- **Hero**：申请人 · 标题 + 状态徽章 + 报销总额 + 大写；PAID 附打款信息行；
  REJECTED 附驳回行(人+原因)。
- **申请信息卡**：报销单号/申请人/部门/标题/备注/提交时间。
- **报销明细**：embedded 表格 + 合计条(两位小数)。
- **票据与核验**：票面字段对审核人员只读，金额勾稽与人工核验分开。
  待审且有权的非申请人可通过行菜单“登记查验结果”打开核验弹窗：官方查验平台入口、
  通过/不符结果及必填渠道/依据。保存核验人、时间和说明；所有登记票据人工通过后才可批准。
- **附件 / 发票影像**(只读 `AttachmentSection canManage:false`)：审批人核对票据影像。
- **付款证明**：独立 `AttachmentSection(ownerType: 'EXPENSE_PAYMENT_PROOF')`；
  APPROVED时符合付款岗位回避的财务可上传/删除，登记付款至少需一份扫描通过的银行回单或现金签收凭据；PAID后只读。
- **审批轨迹**：事件表真轨迹(操作人姓名快照)。
- **审批意见**(审批态)：驳回原因必填(驳回后申请人可修订重提，提示写明修改要求)。
- **认领横幅**：`TaskClaimHandle(EXPENSE_APPROVE)` 他人持锁时禁用操作。

## 三、右下悬浮操作

| 态 | 操作 |
|---|---|
| SUBMITTED/REVIEWING(有 expense:approve) | 返回 secondary · 驳回 danger(原因必填)· 通过 success |
| APPROVED(有 expense:pay 且岗位回避满足) | 返回 · “登记付款”(账户/EXPENSE 费别/实际付款日期弹窗) |
| PAID / 其他 | 只读 |

- 打款走 `EmployeeClaimPostingPort` → 生成 YF 财务费用单(自动审核 + 扣账户余额 +
  总账分录)，幂等由 `finance_expense_id` 唯一约束保证。
- 操作成功回 `/expense/approval`，列表/汇总/筛选桶联动刷新。

付款弹窗明确提示先完成线下实际付款并上传付款证明，按钮为“确认已付款”。本系统登记系统账户和账务，
未接银企直连，不向银行发起转账。申请人不可自审、自付，审核人不可支付自己批准的单据。
所有决定和核验携带预期版本，材料变更或他人先处理时拒绝旧请求。

原票据号码查重、算术相符、人工记录通过和官方税务查验是不同事实；凭证适用性、扣除/抵扣及归档要求见
[合规依据](../07-业务链路/员工报销合规依据与凭证清单.md)。附件查看不足时不能靠纯文本猜测材料通过审核。

## 四、权限

路由守卫 any(`expense:approve`, `expense:pay`)；后端 detail `assertCanRead`。
人工核验和批准同时要求 `attachment:view` 与 `attachment:download`，保证审核人可查看附件清单并打开原件。
核验权限不足时隐藏相应动作并提示授权缺口；驳回仍按审核权限处理，不强迫先作凭证通过结论。

付款账户和费用类别沿用基础资料字典，付款岗位同时需要 `account:view` 与 `payment_style:view`。
付款证明读取需要附件查看/下载权限，上传需要 `attachment:upload`，付款前纠正错误附件还需
`attachment:delete`；已付款后不再允许修改。配置岗位授权时一并检查这些依赖，不以按钮可见代替接口授权。
