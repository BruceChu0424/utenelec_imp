# ADR-162 页面权限抽屉与权限面层级

- 日期：2026-10-06。
- 状态：已接受(2026-10-06；前端 + 服务端 + V812 迁移 + 测试 + 文档)。分支 feat/permission-drawer-rework，本地未 commit、未并 main。
- 编号：开工时 main 最大 ADR-161，取 ADR-162。
- 关联：ADR-109(权限目录单一事实源与授权策略，surface 目录的奠基)、ADR-045(页面内权限委派与授权来源隔离)、ADR-108(服务端会话快照的可委派页面)、ADR-151 §5(入库登记单批合一，路由计数口径)。

## 一、背景与用户要求

用户提出页面内权限设置的三个体验问题(2026-10-06)：

1. 各页面右上角「权限设置」跳独立页 `/page-permissions/:surfaceKey`，只有平铺开关列表；
2. 从模块 hub(如销售管理)进入时**看不到子页面的权限**——想给某人开「新建报价」得逐页跑；
3. 权限项太碎：新增/修改应合并展示为「编辑」，删除独立(风险高)，最好还能批量授权；
4. 有些页面根本没有权限入口(后有核对：任务中心合并页、财务审核中心、生产两审批队列、短交判定、车间内料仓 5 路由)。

## 二、根因(全部实测)

- `permission_surfaces` 118 个活动面**全部平级**：`sales.hub` 与 `sales.quote` 互不包含，hub 面只挂了子页面 view 码的并集(9 码)，hub 页面的授权面天然看不到子页面的编辑/删除/审核码。
- 旧设置页(983 行)是主从整页，无分组折叠、无族归并、无族级批量。
- `page_permission_scope_test` 的 `_businessPaths()` 是手维路径清单：没登记的路由(上述 9 条缺口)静默漏网——V437/V475 的历史「漏网补挂」注释说明这是重复发生的事故模式。
- 审核权限专项核对(逐单据)结论：48 个 APPROVE 码全部有真实校验、暴露端点零裸奔；真缺口只有 `purchase.request` 面缺 `purchase_order:decompose/create`(申请详情页「生成订货单」按钮无法从本页委派)。

## 三、决策

### 1. 权限面单层层级(V812 `parent_surface_key`)

- `permission_surfaces` 新增 `parent_surface_key`(FK 自引用 + CHECK 防自父)；**只允许一层**(hub → 卡片面)，注册表启动快照遇父缺面/二层/环直接 `IllegalStateException` 拒绝启动。
- 层级种子 = `hub_catalog.dart` 逐卡核对后写入迁移：7 张 hub 共 58 个子面。跨 hub 复用的卡片单父归属(「待退回供应商」归 purchase.hub、「内料仓用量报表」归 production.hub)，另一张 hub 的抽屉不重复显示该组。
- **码归属规则**：树内一个码只出现在「目录序第一个含它的子面」组里；根面组只保留没被任何子面认领的码(空组不返回)。负责人委派行的 `surface_key` 同规则写「码归属面」——子页面抽屉与 hub 抽屉对同一码写出同一张面，幂等口径一致，解析器「面含该码」校验天然成立。
- 写路径的树校验：`PUT /employees/{id}/permissions` 接受整棵树内的码，树外码仍 fail-closed 403。

### 2. 右上角原地抽屉替代独立设置页

- `PagePermissionAction` 点击改为 `showGeneralDialog` 右侧滑入 `PagePermissionDrawer`(宽 min(680, 96vw))，不再跳路由；`/page-permissions/:surfaceKey` 路由、`RouteName.pagePermissions` 与整页 `PagePermissionSettingsPage`(983 行)删除，豁免清单 18→17。
- 抽屉结构：选人视图(部门树+搜索+分页人员列表，无账号可走开通流程)→ 权限视图(员工卡+分组树+底部「已修改 N 项·撤销·保存」)；保存仍走 CAS 批量端点(`expectedVersion` 冲突刷新重试)，敏感码开启确认、未保存关闭/换人拦截等口径全部保留。
- hub 抽屉的分组条复用系统权限目录浏览器同款组件(`PermCatalogGroupSection`)；普通页面(单根组)不重复分组头。

### 3. 动作族归并与批量授权

- 新增展示层枚举 `PermissionActionFamily`：**「编辑」族合并 CREATE+EDIT**(用户口径「新增/修改统一为编辑」)，删除/审核/查看/执行·办理/导入/导出/分配/配置独立成族；服务端 `action_type` 仍是唯一事实源，族只是展示归并。
- 族行 = 图标 + 计数 + **三态复选**(未全开→一键补齐全部可编辑码，已全开→一键全收；锁定项不参与) + 展开箭头；展开后逐码开关仍可细调(原生动作徽标、授权策略标签、不可转授原因照旧)。
- 分组头菜单提供「本组全部授权/全部收回(不含锁定项)」；批量和保存共用 100 条上限的 CAS 端点。

### 4. 面目录收口(V812)

- **三任务面合一**：`warehouse.outbound-tasks/inbound-tasks/draw-tasks` 是同一张合并页(2026-09-24 四卡合并)的三个入口，删旧三面建 `warehouse.tasks`(19 码并集)，既有委派行 `surface_key` 原地重写，杜绝解析器 fail-closed 静默失效。
- **孤儿面清理**：`production.workshop-material` 无任何路由(车间侧内料仓动作发生在 `/production/workshop-tasks` 内嵌面板)，其码并入 `production.workshop-tasks` 后删面。
- **新面补缺口**：`sales.tasks`(5 单据 view 并集)、`warehouse.tasks`、`finance.audit-center`(4 审核 view 并集)；`purchase.request` 面补 `purchase_order:decompose/create`。
- 死代码清理：单码 PUT 端点(`PUT /employees/{id}/delegations/{code}`)与 DTO 前端零调用，删除；`PurchaseRequestService.reverse`/`SubcontractApplicationService.approve/reverse` 零调用删除；`PurchaseRequestService.approve` 为链路 e2e 测试夹具保留，补 `@PreAuthorize('purchase_order:decompose')` 守卫防未来无守卫接线。

### 5. 前端 scope 映射补 9 处缺口

`/sales/tasks`、`/warehouse/tasks`(合并页)、`/finance/audits`、`/production/overproduction-rate-requests*`、`/production/material-increment-requests*`、`/subcontract/short-deliveries`(→`subcontract.order`，ADR-098)、`/warehouse/workshop-material/setup`、`/workshop-material/{bin,issue,count}`、`/reports/workshop-material`——全部进 `_businessPaths()` 契约，防再次静默漏网。

## 四、不做的事(边界)

- **不改权限码本体**：479 个码的执行链(`@PreAuthorize`/对象范围/SQL 条件)零改动；「编辑合并」只是展示与批量口径。
- **系统权限总入口(`/admin/permissions`)不改**：抽屉的分组视觉向它对齐，它的三段式与批量通道保持原样。
- **超产/追加用料审批不拆独立码**：继续复用 `production_plan:approve`(核对结论：校验在、语义同域)。
- `production.chain-health` 维持无面 fail-closed(对象级授权未收口前不开放委派，V455 口径不变)。

## 五、验证

- 迁移：V812 在 BEGIN/ROLLBACK 无损自测 + `PermissionSurfaceCatalogPostgresTest` 全迁移链重放绿(新增 7 hub/58 子面/单层/合并重写断言)。
- 后端：`PermissionSurfaceRegistryTest`(树遍历/归属/单层校验)、`PagePermissionWorkspaceServiceTest`(hub 分组读 + 委派 owner 面写 + 树外码 fail-closed)绿；全量 test-compile 绿。
- 前端：`flutter analyze` 零问题；scope/action/route 覆盖/AI 特征目录四件套 45 测绿(含族归并、族级批量、脏态拦截、开通账号全流程)。
- 顺手修复主干两处存量红：`/hr/tasks/reconcile` 漏登记守卫清单(ADR-160 遗留，守卫计数 203→204 红)、AI 特征目录未再生成。
