# V802 车间内料仓开通单一真源与发料来源仓

- 迁移：`V802__workshop_bin_opening_single_source.sql`(本分支临时号，合并时由编排者重排)。
- 决策：[ADR-147 车间内料仓开通单一真源与发料来源仓](../99-决策记录-ADR/ADR-147-车间内料仓开通单一真源与发料来源仓.md)。
- 前置：V800(仓库主档单主仓：一个车间一个内料仓、挂在唯一主仓下)、V801(可用量单一口径 `v_stock_usable`，默认发料来源仓按它算可发量)。
- 加 1 张表 `workshop_bins`(PRESERVE，随仓库主档保留；审计 FULL)；不加权限点；不搬库存、不改历史流水。

## 为什么要改

「仓库资料」里有「装配第一车间内料仓」，内料仓总览却说装配第一车间「未启用」、内料仓列为空。内料仓这个仓库行原来有三条建法：车间直送第一次时自动建(V595/ADR-089)、开启整批领料时建、仓库资料里手工勾「内料仓」；而页面判断「开通」只看整批领料设置，业务清空又只清设置不清仓，两处永远对不上。开启时选的「放在哪个主仓下」只列顶层仓(还混着不良品仓)，塑胶仓库是子仓永远选不到；发料的「出库仓库」默认值在内料仓页、申请候选、申请行建议仓三处各算一遍，口径各不相同。详见 ADR-147 §1。

## 迁移做了什么

1. 新表 `workshop_bins`(主键 = 车间)：每个车间一行 = 这个车间的内料仓已开通(唯一真源)。
   - `bin_warehouse_id` 内料仓(唯一)，`source_warehouse_id` 默认发料来源仓(可空 = 按货品所属仓库；不能是内料仓自己)，`opened_by/opened_at/updated_by/updated_at/row_version`；
   - 守卫 `fn_guard_workshop_bin`：车间必须是未删除的部门、内料仓必须是本车间未删除的内料仓、来源仓必须是启用中的良品子仓(`fn_warehouse_is_good_stock_leaf`)、开通行身份(车间与内料仓)不能改、每次改动 `row_version` 恰好加一(约束名 `workshop_bins_version_guard`，回 409)。
2. 存量回填(一个 DO 块)：
   - 内料仓「用过」= 任一指向它的外键列有行(流水、余额、直送、整批领料设置、单据等全部外键列，除仓库自身与开通表) 或 余额非零 或 某张物料分析把它列为参与仓；
   - 用过的内料仓 -> 已开通(来源仓为空；有整批领料设置的仍是整批领料中；开通人取整批领料开启人或建仓人，且须是现存用户)；
   - 一次都没用过的内料仓 -> 软删除(NOTICE 列出编号与名字)；
   - 同一车间还剩多个用过的内料仓 -> 中止，交人工合并。
3. 一个车间最多一个未删除的内料仓：`ux_warehouses_line_side_workshop` 部分唯一索引取代 V584 的同名普通索引。
4. 内料仓仓库行与开通行同生共死(延迟约束触发器，提交时校验)：
   - `fn_require_warehouse_line_side_opened(仓)`：未删除的内料仓必须恰有本车间的开通行；
   - `trg_assert_warehouse_line_side_opened_ins/_upd`：新建内料仓、或把仓改成内料仓/恢复/换车间时校验；
   - `trg_assert_workshop_bin_withdrawn`：删除开通行时内料仓必须同一事务里软删。
   开通命令先建仓再写开通行，撤销时先删开通行再软删仓；仓库资料、SQL 手工勾「内料仓」都过不了提交。
5. 整批领料只是开通后的子能力：`workshop_material_settings` 加复合外键 `workshop_material_settings_opened_bin_fk (workshop_department_id, periodic_bin_warehouse_id) -> workshop_bins`；`fn_guard_workshop_material_settings` 的内料仓校验改为「这个车间还没开通内料仓, 请先在「车间内料仓」开通」。字段与其余 30 多处引用不变。
6. 仓库退出新选前置条件 `fn_warehouse_selection_exit_blockers`(停用、删除、改不核算、改成不良品仓共用；停用/删除的 `fn_warehouse_retirement_blockers` 自动带上)把 V800 的「已开启整批领料的内料仓」换成两条：「是已开通的车间内料仓, 请在「车间内料仓」里撤销开通」「还是 N 个车间内料仓的发料来源仓, 请先在「车间内料仓」改来源仓或恢复按货品所属仓库发料」。新增 `fn_workshop_bin_revoke_blockers(内料仓)`：撤销开通前的阻塞原因(整批领料还开着、有进出流水、有余额、有直送、有单据引用、有预留、有领料申请)。
7. 车间直送不再自动建仓：
   - `fn_workshop_direct_targets` 的第一道状态判断改为收料车间有没有开通行，没有时给原因码 `WORKSHOP_BIN_NOT_OPEN`(排序位 25)；
   - `fn_workshop_direct_reason_text`：「{车间}还没开通内料仓，请仓库在「车间内料仓」开通后再直送，这次先送入仓库」(没有车间名时说「收料车间」)；
   - `production_daily_report_items.output_route_reason` 检查约束加入该原因码；
   - 直送明细守卫 `fn_guard_workshop_direct_transfer_item` 要求内料仓就是直送单头车间(出料与收料同车间)在 `workshop_bins` 里开通的那个，且与收料需求同主仓。
8. 默认发料来源仓只算一次：`fn_workshop_bin_default_source(内料仓, 货品, 颜色)` = 来源仓有可发量 -> 货品所属仓库(可选良品子仓) -> 可发量最大的良品子仓；都排除不良品仓与内料仓，可发量按 `v_stock_usable`；都不满足返回空(页面要人选)。内料仓页、申请候选、申请行建议仓三处都改读它。
9. 审计与业务清空：`workshop_bins` 审计 FULL；`business_data_reset()` 按锚点补 `('workshop_bins','PRESERVE')`(与 `server/ops/reset_business_data.sql` 同步)。
10. 事后断言：每个未删除的内料仓都有开通行、开通行都指向本车间未删除的内料仓、整批领料设置都引用开通行。

## 服务层与前端同步

- 开通命令单一入口 `WorkshopBinService`(实现端口 `LineSideWarehousePort.openedBinOf`)，取代 `LineSideWarehouseService` 的自动配置；车间直送只读开通行，没开通时拒绝并说清楚怎么办。
- 新接口：`GET /api/workshop-material/settings/source-warehouses`(全站仓库、可选/不良品标记)、`GET .../settings/in-progress-pending?workshopIds=`(按产品合并)、`POST .../settings/batch-enable`、`POST .../settings/batch-disable`(全成全败，幂等键回放，状态/版本不符 409、规则不符 422 并逐车间列原因，一次最多 50 个)；`PUT .../settings/{workshopId}` 改为批量的单车间形态；旧的「放在哪个主仓下」接口删除。
- `WorkshopMaterialGuards`(把内料仓守卫一律翻成 409)删除：约束名以 `_version_guard` 结尾的回 409，其余业务守卫回 422(`GlobalExceptionHandler`，ADR-151 §4 补充)。
- 仓库资料：内料仓只读(不能改、停用、删除)，提示到「车间内料仓」里管理。
- 前端：内料仓总览三态分段 + 勾选批量开通/开启整批领料/撤销 + 行菜单 + 双击打开；开通面板(来源仓走全站仓库滑窗、只能选良品子仓)取代开启弹窗；设置页只剩「机台」「备料」两个页签；发料页的「出库仓库」列点开仓库滑窗，副标题显示可发量。

## 测试服务器影响(只读估算)

- 注塑车间内料仓 LS-WS_ZHUSU 有整批领料设置 -> 已开通·整批领料中(来源仓为空)；
- 装配第一车间内料仓 LS-WS_ZHUANG 有 2 条流水、1 条直送 -> 已开通(来源仓为空)；
- 没有被软删除的内料仓，也没有同车间多个在用内料仓，回填不会中止。
