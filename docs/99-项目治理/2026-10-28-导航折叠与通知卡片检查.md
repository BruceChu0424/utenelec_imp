# 导航、折叠与通知卡片检查

## 本次范围与设计

按 `frontend-design` 执行。保留现有 Uten 主题、NotoSansSC 字体、权限、通知来源、已读/回执/业务办结语义。检查入职返回、资料库侧栏、全系统同类导航与折叠入口；公司备份告警单独核对生产事实。

通知中心采用“业务消息叠卡”：同一业务对象共享一叠，不按标题或类型把不同订单混合。公告、制度、福利、系统、紧急、任务、审批、流程和庆典分别以类型图标及文字标识，类型色用于上沿及图标块；重要和紧急另有明确文字。来源发布人始终展示，人事消息沿用服务端重要筛选，不猜测发布人身份。

- 配色：沿用主题 surface / onSurface；品牌青 `#14B8A6`、制度紫 `#8B5CF6`、福利粉 `#EC4899`、系统蓝 `#3B82F6`、紧急红 `#EF4444`，其余类型从现有 NoticeType 取得。
- 字体：NotoSansSC；类型 12–14、正文 14、标题 16–18，按主题字号和系统缩放响应。
- 排列：左对齐，卡片上部为大图标、类型和状态，标题/摘要居中段，来源/时间在底部；堆叠数量徽章位于顶卡上部，背后露出两张完整卡面边缘。
- 动画：点击叠卡后背景渐暗，叠卡向屏幕中央过渡，再逐张展开成有间距的独立卡片。关闭反向收拢；键盘 Escape、遮罩和关闭按钮可退出。减少动画/低性能模式遵守公共 UtenMotion 门控。

```text
收拢                         展开（暗色背景中央）
┌ 类型图标  流程     [共3条] ┐   相关通知  共3条/未读2条  [关闭]
│ 订单当前进展              │   ┌ 流程  当前进展              ┐
│ 摘要                      │   └ 来源/时间                  ┘
│ 来源/时间  2未读           │   ┌ 审批  上一个审核结果         ┐
└──────────────────────────┘   └ 来源/时间                  ┘
  └──────────────────────┘     ┌ 任务  更早的任务              ┐
    └──────────────────┘       └ 来源/时间                  ┘
```

设计复核：避免所有类型只在小标签里换颜色，也避免满卡强色和无关装饰。鲜明处理集中在类型标识与叠卡展开；其余沿用工作平台克制的白色表面、主题圆角和边框。重要性不由颜色单独传达，移动端与大字号保持内容可滚动。

## 实施与验证

### 通知公共入口与迁移

| 原实现 | 当前入口 | 覆盖位置与保留差异 |
|---|---|---|
| 列表私有 `_NoticeCard`、类型/优先级/分组小签、选择遮盖 | `widgets/notice_card.dart` 的 `NoticeCard` | 通知列表单条、组顶卡、展开后的每条卡片；复用 UtenCard、主题、庆典主角和互动组件。原约 600 行列表私有呈现已移除 |
| 列表私有 `_NoticeGroupCard` | 同文件 `NoticeStackCard` | 全部多条业务组；顶卡显示数量，保留最高未办结重要度，防止最新普通回执遮蔽紧急通知 |
| 紧凑 ListTile 组弹窗/窄屏底部页 | `showNoticeGroupDialog` | 各屏幕统一居中可滚动舞台；只构建 ListView 可视附近的组卡，不一次性展开全部历史 |
| 裸回执按钮 | `NoticeInteractionFooter` + `UtenActionButton` | 全部列表回执；错误提示、防连点、等待反馈。组中保留详情入口，不把缺失回执操作误写成“已收到” |
| 通知发布取消的 canPop/go 分支 | 公共 `backTo` | 与已有发布成功回退保持同源，继续支持 returnTo |

分组继续使用原 `notice_group.dart`；只合并同一业务对象，不合并不同订单、同类型广播或无锚点通知，不改变服务端 aggregate/办结规则。来源姓名不被前端猜测成人事身份，重要筛选继续以服务端发布者部门规则为准。全部/未读/重要、管理删除、原权限、来源和业务待办完成规则保持原合同。

### 已修复的相关交互缺陷

- `Notice.copyWith` 原先更新已读/回执时丢失 aggregate、interactive、resolved 和祝福模板；现在完整保留，避免叠组拆散或已办结重新显为有效。
- 单卡慢网络下重复点击可能重复置读并叠两层详情；列表与组内都有防重入。
- 原组弹窗先乐观清空未读，失败后仍表现成功且卡在忙状态；现在逐条成功后才更新，失败保留并能重试。
- 组舞台挂根 Navigator，而手机详情底部页原挂 shell Navigator，会被舞台遮住；详情底部页改挂根，业务跳转关闭详情及舞台，恢复可交互页面。
- 所有类型小字使用根据当前表面计算的可读前景色，类型标签在亮/暗主题的对比度至少 4.5；类型仍同时以文字和图标区分。
