## 实现缺陷与落后测试的区分

### 真实身份和强类型摘要

`UtenGoodsPicker` 和 `UtenMasterPicker` 的分类与全局读取都已调用公共完整读取入口，但没有传入已知主档身份，导致完整读取无法拒绝跨内部批次重复的实体。现分别传入 `GoodsListItem.id` 和既有 spec 的 `idOf`，不按显示名称去重。

盘点适配器把 `PagedResult<CountStockRow>` 转为可绘制的 `GoodsListItem` 时曾丢掉原响应 `readScopeVersion`、`totals`、`facets` 和 `facetNullCounts`。现原样传递这些权威元数据；确认返回仍来自原 `CountStockRow` 对象的快照映射，不从显示模型重新拼数量、重量、单位、版本或资格。盘点没有新增币种推断；原始有币种分组的报表合计继续按原服务端合同保留。

新增的真实两批盘点负例分别制造授权版本漂移和重复 goods+color 身份。修复前两项均错误发布候选，修复后均拒绝发布、禁止确认，重试取得一致完整数据后恢复。匿名报表行与主档不同：打印的三个相同 `repeated-head` 行身份仍全部保留，未套用主档唯一身份规则。

### 完整读取 fixture

- 报表默认响应修为真实 51 行、两批；大列表修为 4000 行、80 批。后批按原省略元数据协议返回，不伪造总数。保留服务端来源 facet、原 `1000.00000001` 合计精度和单位、账户流水时间顺序；双向滚动零读取，排序/重试建立新读取。原普通财务打印已能返回 2501 行，但文案仍称“最多前 2000 行”，现同步真实完整打印范围及相关页面注释。
- 供应商保持 80 个真实身份、四个内部批次，以及 selectable-only 权限范围。完整首读失败不发布前缀；整范围重试从第一批开始。原选择在同条件刷新等待时保留，确认被禁用；窄屏切分类退休旧批次，迟到旧批次不请求后续批次、不发布旧候选。全部已接收数据只在本地滚动，不更换行集/列定义或发请求。
- 盘点旧 fixture 把禁选行在两批中重复返回，且测试仍操作已退役页码。现在每个真实候选只出现一次、全部批次先接收；全选覆盖两项可编辑颜色并排除禁选行，跨搜索增加第三项。旧搜索晚返回、选择快照、输入、重复添加和盘点会话退休仍受原断言约束。

### 候选 HTTP 404 与等待生命周期

原报表测试只伪造 `get/post`，漏接真实候选入口 `postForm`。Web 实际向测试服务发送 `/finance/reports/column-candidates`，得到 404；`pumpAndSettle` 的假时间循环饿死了真实 XHR 完成。保留原整组失败、浏览器控制台 404 和逐阶段诊断日志。仅本任务临时诊断把同一个原生 XHR 的启动与等待放进 `tester.runAsync`，实际收到 `ApiException(httpStatus=404)` 后，原筛选、打印和导出用例完整执行通过，证明原挂起属于未隔离的测试 I/O。

正式 fixture 迁入既有 `NativeFacetFakeTransport`，用实际电话和行数提供候选桶，同时核对真实 POST 路径、report/column 和内部大小 100。HTTP 边界用普通异步测试调用真实 `ApiClient.postForm`、Dio 和可控 HTTP adapter，分别覆盖 404 与 200、私密 form 不进 URL 和读取不触发写版本；界面边界用相同 `ApiException(httpStatus=404)` 及完整候选响应驱动失败、重试和退休。两层测试均实际执行，不以成功 fixture 代替失败路径。

中间版把 Dio 请求与整个界面点击一起移出假时间，导致成功后的公共完整读取 `UiWorkBudget` 也进入真实 zone，其零时长工作切片又被后续假时间 settle 饿死。该版本 VM 重试和 Chrome 三个负例原日志、浏览器异常及源码快照一并保留；最终明确分离 HTTP 与 widget 时钟边界，没有添加 sleep、延长超时或跳过浏览器负例。

该负例还发现实际产品问题：手动重试挂上 root `UtenBusyOverlay` 后，菜单的 `TapRegion` 把遮罩点击当作外部点击，关闭菜单并销毁草稿。共享 `UtenTableHeaderMenu` 现有明确的 `dismissOnOutsideTap` 合同；远程手动等待期间关闭外点退场，未等待的本地 Grid 调用方沿用原行为。路由、失焦和 Escape 继续通过原生命周期退休。

三个 HTTP 负例覆盖失败后关闭、成功重试、等待时 Escape 后迟到成功：404 必须撤掉 busy；已有私密主条件及新输入草稿保留；等待期间连续八次点击不重复读取、不销毁输入；Escape 仍立即关闭且迟到结果不复活；URL 无私密条件、原导出/打印请求体不变，101 行滚动零读取且读取不触发写版本变更。
