# 委外领料批量出仓

> 路由：`/warehouse/subcontract-outbound/batch`
> 别名：整批委外发料、批量委外出仓

## 页面定位

仓库集中核对委外人员已提交的领料单并逐张办理实际出仓。

## 办理与边界

- 从委外待发料任务勾选原货品明细进入，以 `issueIds` 和 `itemIds` 恢复原来源、所选范围与本机拣货输入；表格只显示所选行，未选行仍保留在原草稿与预留中。
- 任务中心明确所选明细的入口使用 `GET /subcontract/material-issues/{sourceId}/selected-outbound/review` 取得原单和服务器指纹；统一确认后一次 `POST .../selected-outbound` 原子办理所选的正数行。`itemIds` 必须与 `document.items` 正数行的原 ID 精确相同；部分选择时原 A 身份留在原单历史，以 `warehouse_split` 退休，执行子单 S 的新 A2 经不可变谱系对应原 A，回执仍使用原 A ID。原单未选行、填 0 的行及其预留保持原样。每张原单一次最多出库 500 条明细，至少一条正数。
- 查看需要 `subcontract_outbound:view`；执行还需 `subcontract_outbound:execute`，保存与确认分别叠加 `subcontract_material_issue:edit`、`subcontract_material_issue:approve`。
- 按冻结的直属物料和原计量单位核对数量、称重、仓库、经办人及行备注，不以整批显示总数替代每源预算。
- 未人工指定的交货日期在草稿中保持为空，页面随当天显示；只有服务端确认出仓事务成功时才冻结当天日期。保存拣货或确认失败不得提前冻结，人工日期及已审单据日期原样保留。
- 服务端逐张检查原委外订货来源、可领额度、版本、状态、库存和本人仓库范围。
- 未确认成员继续留在原任务；回执未查明时核对原出仓操作，已确认成员不再次保存或出仓。
- 发出命令前，本机草稿持久化冻结的 `idempotencyKey`、服务器 `fingerprint`、本次正数行 `itemIds` 与原 `document` 请求体，并单独保留原页面明细到来源的映射。重新打开先调用 `GET .../selected-outbound/receipt?idempotencyKey=` 核对原来源与本次精确明细集合，再读取其它未执行来源；不能用已移走明细后的源单余行替代原选择，也不把原页面中填 0 的行补入冻结命令。回执为空继续保持待核对；只读核对不重发，明确「按原内容重试」才以同一编号和原请求体重试。成功按原 `sourceIssueId` 标记，不把执行子单 ID 当作下一次来源。
- 显式打开含已冻结原子命令的本机草稿时，相邻未提交来源被取消、删除或当前不可读，不得阻断原操作核对。页面仅显示来源 ID 和处理状态，不以本机快照回填货品、供应商、数量等业务内容；原完整来源、明细范围与未提交填写仍保留。此恢复状态只能核对、重试原冻结命令，不派发未提交来源。空回执另需当前可读原来源，重试前再次核验；原来源不可读时继续冻结且不发送。成功回执须在草稿初始化完成后保存确认结果，退出、再次打开仍保持已确认，不误删含未完成来源的整批草稿。
- 表格默认依次展示状态、出库单号、委外商、来源订单、货品、数量和仓位，实称重量紧跟本次出库。既有用户列设置继续保留。
- 未携带明细身份的旧整单入口与没有原子命令的旧草稿保留原核对行为。原业务单页保存、审核的整单边界仍由服务端校验；新任务入口不再用两次保存／审核拼接部分出仓。确认、草稿保存与网络发送共用原账号／服务器请求范围；身份或权限变化后旧页面不能转用新身份发出旧请求。
- 返回原委外任务上下文，成功与未完成成员分别保留，整批恢复不复制领料单。
