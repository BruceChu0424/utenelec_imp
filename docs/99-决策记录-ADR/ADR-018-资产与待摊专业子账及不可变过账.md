# ADR-018：资产与待摊专业子账、职责分离与不可变过账

- **状态**：已接受（架构方向）；生产启用仍为 **NO-GO**
- **日期**：2026-08-01
- **影响**：资产分类、固定资产、长期待摊、会计期间、总账凭证、权限、审计、Flutter 财务工作台
- **依赖**：ADR-017（模块化单体 + CQRS 读侧 + Outbox 异步旁路）

## 一、背景

V123/V140 已提供固定资产和长期待摊的 CRUD、直线法计算及总账凭证样板，但其设计是技术原型，
不能作为正式财务子账继续扩展：

- 创建主档不产生资本化或待摊初始确认凭证；
- 原值、期限、残值和状态可在计提后直接修改或软删；
- 重跑期间会删除原计提日志和总账凭证，再按当前主档重建历史；
- 总账全量生成会删除同期间全部自动凭证，却不会重建资产凭证；
- 没有模拟、审批、过账批次、反冲、连续期间、关账和子账总账对账；
- `finance_asset:edit` 同时代表建档、审核与计提，无法形成职责分离。

本次功能尚无需要兼容的业务数据，适合以追加迁移的方式建立正式写模型；已经应用的 V123/V140
仍保持字节不变，只作为旧字段和报表的兼容层。

## 二、外部依据

本决策采用以下官方规则与成熟产品实践：

- 财政部《[企业会计准则第4号——固定资产](https://kjs.mof.gov.cn/zt/kjzzss/kuaijizhunzeshishi/200806/t20080618_46213.htm)》：重要组成部分分别确认；达到预定可使用状态前的必要支出进入成本；除已提足折旧仍使用的资产和单独计价土地外按月计提；寿命、残值和方法至少每年复核。
- 财政部《[企业会计准则第6号——无形资产](https://kjs.mof.gov.cn/zt/kjzzss/kuaijizhunzeshishi/200806/t20080618_46242.htm)》与《[企业会计准则应用指南](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=13655)》：预付账款、长期待摊、无形资产具有不同确认条件，不能因“先付款”而混为待摊。
- 《[企业所得税法实施条例](https://www.chinatax.gov.cn/n810341/n810765/n812176/n812748/c1193046/content.html)》和《[财政部、税务总局公告2023年第37号](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5212306/content.html)》：计税基础、最低折旧年限与特定设备器具税前一次性扣除属于税务账选择，不能覆盖账面折旧。
- [SAP Asset Accounting](https://help.sap.com/docs/SAP_S4HANA_CLOUD/3e5fcf2c768746049b5627bd5a42f720/592b3250326543f7bbceba6ae91fc061.html)、[Oracle Mass Additions](https://docs.oracle.com/en/cloud/saas/financials/25d/faalm/mass-additions.html) 和 [Microsoft Dynamics 365 Fixed Assets](https://learn.microsoft.com/en-us/dynamics365/finance/fixed-assets/set-up-fixed-assets)：来源数据先进入候选/复核链；资产使用独立账簿；折旧先生成建议或模拟，再审核、过账、对账和关账。

这些资料用于建立产品控制原则，企业具体会计政策仍须由其财务负责人批准，系统和开发人员不得代替企业作会计判断。

## 三、决策

### 3.1 分开四种经济事项

本模块正式管理两种对象：

1. 固定资产：有形资产卡片、会计账簿、折旧、归属变更、盘点、减值和处置事件；
2. 长期待摊：已发生且未来受益期成立的费用、版本化计划、逐期确认和提前终止事件。

以下对象不得伪装为本模块记录：

- 尚未交付的供应商预付款继续留在应付/往来；
- 满足可辨认与控制条件的软件、专利等进入无形资产能力（未实现时分类为待专业处理）；
- 在建工程、使用权资产、投资性房地产和生物资产在专门模块完成前不得塞进普通固定资产；
- 日常维修和不满足资本化条件的支出直接进入当期费用。

### 3.2 来源、主档、账簿和事实分层

正式模型分为四层：

```text
来源引用/候选
    → 资产或待摊主档（业务身份、归属、运行状态）
        → CORPORATE / TAX 独立账簿或版本化待摊计划
            → 审批、业务事件、过账批次、逐项快照、总账凭证
```

- 主档不再保存可随意覆盖的“权威累计额”；余额由不可变事实汇总。
- 资产类别只提供默认政策。正式批准时，将方法、期限、残值和科目冻结到 `CORPORATE` 账簿；以后修改类别不追溯覆盖旧资产。
- 税务账独立于会计账，默认不自动创建。500 万元税前一次性扣除只能作为带生效期和证据的税务账选择，不得作为账面资本化门槛。
- 待摊计划按版本保存；当前审批生成 v1 且已确认计划行不可修改。未来版本/当前期调整是目标模型，
  计划修订 API 尚未交付。

### 3.3 状态分离

审批状态、会计状态和实物运行状态不得混用一个自由文本字段。

固定资产会计状态：

```text
DRAFT → PENDING_APPROVAL → APPROVED → ACTIVE
  ↑           └ reject ─────┘             → DISPOSAL_PENDING → DISPOSED
```

长期待摊状态：

```text
DRAFT → PENDING_APPROVAL → APPROVED → ACTIVE → COMPLETED
  ↑           └ reject ─────┘          └ termination → TERMINATION_PENDING
                                                     ├ reject → ACTIVE / COMPLETED
                                                     └ approve → TERMINATED
```

固定资产运行状态另存为 `PENDING_ACCEPTANCE / IN_USE / IDLE / UNDER_REPAIR / LOANED / LOST_PENDING / DISPOSED`。
`FULLY_DEPRECIATED` 是账簿余额推导结果，不是资产退出状态；闲置或维修也不得自动停止账面折旧。

### 3.4 制单、复核、过账分离

权限至少拆分为：

| 权限 | 用途 |
|---|---|
| `finance_asset:view` | 查看台账、详情、计划、事件和过账结果 |
| `finance_asset:edit` | 维护草稿、提交、业务归属变更 |
| `finance_asset:approve` | 审核资本化/待摊政策和计提批次 |
| `finance_asset:post` | 激活入账、批次过账与受控反冲 |
| `finance_asset:dispose` | 资产处置或待摊提前终止 |
| `finance_asset:export` | 独立加密导出权限预留；当前没有资产导出 endpoint，不得宣称功能已交付 |
| `finance_asset_period:manage` | 关账和受控重开 |

服务端必须再次校验；Flutter 隐藏按钮不是授权控制。发起人不得审批自己的单据或批次，发起人不得为自己的批次执行最终过账。处置/终止最终批准同时要求 dispose+post；安全驳回只要求 dispose。高风险权限不按财税部门默认全授，由超级管理员按个人授权。

### 3.5 过账采用不可变批次

折旧与摊销统一使用：

```text
PREVIEWED → SUBMITTED → APPROVED → POSTED → REVERSED
```

每次预览保存：

- 账簿/计划版本、历史累计、当前金额、科目、部门及算法版本快照；
- 输入指纹、内部运行标识、警告和阻断异常；当前没有客户端幂等键；
- 逐项期初、当期、期末以及最后一期尾差。

过账前在同一事务内重新校验指纹，取得期间 advisory lock 和必要的行锁，并同时写入批次、逐项日志和借贷平衡的总账凭证。原批次、原日志和原凭证永不删除；已经交付的正常月度折旧/摊销错误，只能生成引用原批次的反向批次与反向凭证。

这里的“反向批次”只适用于月度折旧/摊销，不代表资本化/初始确认、处置或提前终止已经具备业务事件反冲。后三者还必须同时恢复业务状态、账簿/计划有效性、事件链、审批链和后续期间约束；该专用制单—复核—反冲—状态恢复链当前尚未交付。

同一 `run_type + book_type + period` 只能存在一个有效正常 `POSTED` 批次。允许零项批次完成审核和关账证明，但不得生成空凭证。

### 3.6 期间与连续性

- 所有期间必须是有效日历月，不只检查字符串形状；
- 首次计提从账簿开始期间进入，之后必须连续，不允许静默跳月或倒序；
- 关闭期间禁止新增、修改、过账或反冲；
- 重开必须具备独立权限、填写原因并保留操作者与时间；
- 关账前必须确认折旧和摊销都有有效批次、无阻断异常，并完成逐项快照合计与总账金额对账。

### 3.7 资本化与初始确认（目标流程与当前门禁）

草稿提交前必须具备资产类别、成本/累计折旧/费用/清理过渡四类科目、来源引用、关键日期和政策字段。批准只冻结政策，不等于过账；具有过账权限的人员执行激活时，在单一数据库事务内完成：

- 固定资产：借资产成本科目、贷来源或清理过渡科目；
- 长期待摊：借待摊成本科目、贷来源或清理过渡科目；
- 建立 `CORPORATE` 账簿或版本化计划；
- 写入业务事件、总账凭证和审计身份。

若来源单据本身已经过账到资产清理科目，激活只完成清理科目到正式资产/待摊科目的重分类，避免重复确认银行或应付。

上述是最终目标流程，不是当前生产承诺。系统以配置
`uten.finance.asset.posted-workflows-enabled` 控制会产生不可逆业务事实的工作流，对应环境变量为
`UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED`，默认值必须保持 `false`。门禁关闭时：

- 允许类别/政策维护、草稿 CRUD、提交、他人审批/驳回、查询和审计准备；
- 隐藏并由服务端拒绝固定资产/待摊激活、处置发起、终止发起以及处置/终止批准；
- 已经存在的处置/终止待审批记录仅允许具备权限的非发起人驳回，使状态回到安全状态；
- 会计政策配置完整也不能解除安全门禁。

任何环境均不得仅通过把该变量改为 `true` 宣布上线。必须先交付并验收初始确认、处置和终止的专用业务事件反冲与状态恢复，再由变更审批决定是否启用。

### 3.8 不可变和审计防线

- 已过账批次、逐项快照、审批步骤和业务事件只追加，不允许原地删除；
- 活跃资产和待摊不得再走普通删除；处置、终止、价值变化走专用事件；
- 新表逐表创建 `fn_audit()` 触发器；V169 只覆盖当时已有表，不能自动覆盖后续迁移；
- 写事务在首条数据库写入前绑定 `TxSessionVars`，同时写 `created_by/updated_by`；
- 来源类型、来源单号、合同/发票/验收资料继续使用结构化引用。2026-08-09 已有通用 Attachment 源码候选（对象级授权、服务端哈希、精确 OSS 版本、短时下载授权和生产启动门禁），但资产域尚未接入 owner policy、逐码证据映射和上传 UI；PostPolicy、staging/final、AV 隔离、删除 outbox、孤儿治理及真实 OSS/恢复验收也未完成，因此本 ADR 仍不能宣称资产证据附件可生产使用。

### 3.9 架构边界

- 资产审批、总账凭证、批次和日志属于同步写主链，使用模块化单体本地事务；
- 通知、报表刷新和异步导出才允许通过 Outbox；
- 复杂台账、概览和滚动表属于 CQRS 读侧，可使用受控原生 SQL；
- 总账重生成只拥有它明确列出的来源类型，禁止删除 `FA_DEP`、`DA_AMT`、资本化、处置和反冲凭证。

### 3.10 当前交付边界

截至 2026-08-01，当前实现的准确口径如下：

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 专业表结构、权限、审批/事件审计、乐观锁、来源行防重 | 已交付安全骨架 | 固定资产/待摊各表内由唯一索引保护，跨两表由服务校验 + advisory lock；可用于无历史数据初始化，但不等于生产放行 |
| 类别/政策、草稿、提交、他人审批与驳回、查询工作台 | 已交付 | 仍需企业政策、科目和岗位授权 |
| 月度折旧/摊销预览、提交、审批、正常过账 | 已交付 | 仅 `CORPORATE` 账的月度运行 |
| 正常月度批次反冲、原批次/日志/凭证保留 | 已交付 | 不覆盖业务事件反冲 |
| 资本化/初始确认、处置、提前终止 | 代码存在但默认门禁关闭 | 不可作为生产可用能力宣传 |
| 初始确认/处置/终止的专用反冲与状态恢复 | 未交付 | 生产阻断项 |
| 完整处置清算（收入、税费、清理成本、损益、应收/收款衔接） | 未交付 | 当前不能用“处置完成”替代完整清算 |
| 退款/供应商贷项驱动的待摊冲减 | 未交付 | 当前终止不得冒充退款或贷项 |
| 必备资料逐码证据与真实附件 | 未交付（通用底座仅源码候选） | 仅有资料代码/引用字段；资产域缺逐码证据映射和接入，通用底座虽已有对象级鉴权、服务端哈希和精确版本，仍缺生产 AV/staging、删除 outbox、孤儿治理及真实 OSS/恢复验收 |
| PO/AP/收货/CIP 来源 adapter | 未交付 | 当前只有结构化来源引用；不能证明源单金额、行号或过账状态 |
| TAX 账 CRUD、税务计提/反冲及 TAX 总账 | 未交付 | 数据库预留账簿类型不等于税务子账已上线 |
| 历史期初余额、累计折旧/摊销和追溯切换 | 未交付 | 当前只适合无数据、当前期间启用 |
| 部门/成本中心写入总账分录 | 未交付 | 过账行只冻结部门；成本中心停留主档，现有 `gl_entries` 没有对应权威维度 |

因此本 ADR 的架构方向已接受，但完整生产结论明确为 **NO-GO**。默认关闭的门禁是保护措施，不是对缺失能力的替代。

## 四、企业上线前必须批准的政策

系统不得替企业预设以下结论：

1. 适用企业会计准则还是小企业会计准则；
2. 账面资本化重要性门槛和低值资产管理办法；
3. 每类资产寿命、净残值、折旧方法和启折规则；
4. 重要组成部分拆分标准；
5. 允许进入长期待摊的业务类型、证据和受益期算法；
6. 总账科目与成本中心映射；
7. 金额审批阈值、重大事项联签和代理审批规则；
8. 税务优惠选择与证据留存政策；
9. 盘点频率、标签、责任人和处置规则；
10. 关账、重开和历史更正政策。

配置缺失时允许保存草稿，但必须阻止提交、激活、计提和关账；配置全部完成也不能绕过 3.7 的生产安全门禁。

## 五、后果

### 正面

- 已交付的月度折旧/摊销、总账和期间具备可验证闭环骨架；
- 重跑、并发和总账全量生成不再破坏历史；
- 模型先隔离税会账，避免把税收优惠错误写入会计账；TAX API/GL 交付前不宣称已能管理税会差异；
- 权限和审计能够回答“谁建、谁审、谁过账、按什么政策、影响哪张凭证”。

### 代价

- 相比简单 CRUD 增加类别初始化、审批、预览、过账和关账步骤；
- 必须建设企业会计政策并完成岗位授权；
- 资产域真实附件/逐码证据接入、批量导入、无形资产、在建工程、减值估值和盘点扫描仍需后续专门能力，不能用通用 Attachment 源码候选或备注字段冒充已交付。

## 六、验收门禁

- [x] 默认 `UTEN_FINANCE_ASSET_POSTED_WORKFLOWS_ENABLED=false`，服务端和页面均不能执行受门禁保护的动作；
- [ ] 初始确认、处置、终止各自具备独立申请、他人审批、反冲、原状态恢复和后续期间一致性验证；
- [ ] 从草稿、提交、他人审批、激活、计提预览、批次审批、过账到总账下钻完整通过；
- [ ] 本人自审、自过账、关闭期间过账、跳月、重复/并发提交全部失败；
- [ ] 末月尾差、零残值、长期期限、零项批次和反冲后的余额正确；
- [x] 总账重生成不删除任何资产域凭证；
- [ ] 固定资产/待摊逐项合计与总账借贷合计一致后才可关账；
- [ ] 360/720/1280/1920 页面无溢出，读权限不显示写动作，错误态可重试；
- [ ] 全新库 Flyway 回放、升级库回放、后端/Flutter 自动化、真实 PostgreSQL 并发测试通过；
- [ ] 企业政策、权限矩阵、人工 UAT、备份恢复和回滚演练完成签字。

在全部勾选并形成可审计证据之前，本模块不得从 **NO-GO** 改判为生产 **GO**。
