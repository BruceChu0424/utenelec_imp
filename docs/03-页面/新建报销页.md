# 新建报销页(V608 起与编辑合并)

> 路由：`/expense/new?kind=GENERAL|TRAVEL`(新建费用/出差报销)、`/expense/:id/edit`(编辑 DRAFT/REJECTED)
> · 实现源：`lib/features/expense/pages/expense_claim_edit_page.dart`(旧 `expense_new_page.dart` 已退役)

## 一、定位

员工先保存申请，再到详情补齐原件和票据，最后提交。`claimId` 为空为新建；非空为编辑，
仅本人 DRAFT / REJECTED 可操作。完整操作见[报销 SOP](../07-业务链路/员工报销全链路-SOP.md)。

## 二、表单结构（2026-11-03 重构）

1. **驳回横幅**：编辑 REJECTED 时显示驳回人、原因及修订指引，保存后仍需在详情重新提交。
2. **身份与表头**：当前员工、部门、业务日期以紧凑事实行展示；表头字段按可用宽度使用公共 `UtenFormGrid` 自动分列，窄屏转单列；统一表单内填写报销类别、标题和事由说明。
   新建页不常驻展示制度说明或流程教学卡；无登记票据时仍须说明凭证类型及报销依据，提交材料要求由原业务规则校验。
3. **明细区**：使用与采购编辑一致的公共 `UtenEditableGrid`，费用科目、日期、说明和金额直接逐行编辑，可添加多条费用；宽屏底部全宽表格，窄屏保持表格与字段可访问。用途说明必填且最多500字；未完成金额（如 `12.`）、行标识与扩展字段随本机草稿保留，不能被转换为合法金额后静默提交。旧未完成明细弹窗仅作为历史草稿恢复兼容入口。扩展列维护仅在当前可保存且非忙碌时开放。
4. **合计区**：与明细相邻，小写(tabular)+ **人民币大写**(`rmbCapital`，银发〔1997〕393 号口径，
   与打印报销单同款)。
5. **审批路线**：宽屏在右侧显示窄路线栏，窄屏折叠为同一表单内的流程区。顺序为部门负责人审核、财务初核、财务复核、总经办批准、财务付款；提示使用标题旁 `UtenFieldHintIcon`，不常驻副标题或独立说明。
6. **文件引导**：从 AI 助手识别发票进入时，展示真实解析/预填进度及票面核对预览；直接新建不显示空的 AI 流程卡。计划复核当前身份、权限、服务器、作业和原件摘要后才应用，迟到结果不能覆盖切换身份后的页面。

右下使用 `UtenFloatingActionGroup`：新建只有“保存并补充凭证”，编辑为“保存”。
新建页不直接调用提交接口，避免先提交后补材料。空明细不可保存；网络动作接 `UtenBusyOverlay` 并防连点，成功、失败、取消和中断均收尾；原输入、文件引导来源及未知提交恢复身份继续保留。

有发票引导计划时，用户保存后保留“登记票据”入口：复核原件归属并上传/复用当前报销单附件，再打开票面核对登记。AI 仅提供输入建议，不代替用户保存、提交、票据验真或财务审核；来源失效或上传结果不明时保留明确恢复状态，不盲目重复上传。发票图片继续走本地 OCR，文字 PDF/文本在服务器本地解析，遵守 ADR-094 与 ADR-141。

## 三、保存与提交语义(V608)

- 新建：`POST /expense-claims` 创建 DRAFT，成功进入详情上传凭证；此时尚未进入审核队列。
- 编辑：`PUT /expense-claims/{id}` 携带 `expectedVersion`，明细整组替换、合计服务端重算，成功回详情。
  REJECTED 编辑保存后**仍是 REJECTED**，由详情页「重新提交」清驳回痕迹并重新通知审批人。
- 校验覆盖类别白名单、金额两位小数且 >0、合计 >0、标题长度；提交时另校验明细日期、用途和凭证。
  冲突时提示刷新后重新核对，不能自动重放写请求。
- UI金额及合计上限为9,999,999,999.99元，按整数分解析与汇总，避免极大浮点数丢失分位。

## 四、权限

`expense:apply` 保护两个路由。创建从当前有效员工生成身份；编辑必须是本人且状态可编辑，
不能由客户端指定任意申请人。附件能力还受独立附件权限保护。
