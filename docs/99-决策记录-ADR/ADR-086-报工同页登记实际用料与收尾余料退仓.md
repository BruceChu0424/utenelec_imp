## 一、问题

用户口径(2026-09-15)：

> 我的车间生产任务里面，报工和实际用料/退料是两个区域工作，现在我想集中起来，
> 把实际用料放到报工里面一起填写，不要弄得这么复杂。
>
> ……就写本次实际用料吧。最后一次报工，如果本次实际用料填写了，自动检测，
> 如果数值对不上，就提示是否余料退回。

原来的办法：车间在「我的车间任务」右侧滑窗单独「登记实际用料」，填完再点「余料退库」
开第二个滑窗核对退料。报工在另一个页面。同一批人、同一个工单、同一件事，分三处操作。

## 二、决策

### 2.1 实耗填在报工明细表里，挂在成品行下面

生产日报明细表从单层变成两层：成品报工行 + 它所属工单**已领用的物料子行**。
子行只有一个可填列「本次实际用料」，旁边只读显示领料量。

- 必填、红框、拒负数、不得超过「本次还能登记多少」；
- **允许填 0**——「这批料一点没用」是合法事实。逼车间为没用的料编一个正数就是在造假账。
  这与成品行「完工量必须大于 0」是两种口径，不要合并。
- 物料子行由来源工单派生，不能单独勾选、复制或删除；删成品行时连带删掉。
- 同一个执行工单挂在多个成品行下时，它的物料只有一份额度：第一处可填，其余是只读镜像。

物料子行的来源不是报工行的执行段，而是先问 `material-usage-sources`：分批生产时本批段
可能一条需求都没有，料挂在**前批原领料段**上(ADR-078)。直接拿报工段查台账会查出零条，
提交时还会被服务端按段归属判 403。

### 2.2 记账时点跟着审核走，不跟着保存走

日报 `create` 只产出草稿，要主管审核才增加完工量；材料消耗是立即生效的实账。
保存即记账会让「草稿被删/日报红冲」之后实耗留在账上，两套事实长期对不上。

所以：草稿只承载数字(V583 新表)，**审核同事务**转成 `CONSUMED` 结算，
**红冲同事务**按 `production_material_settlement_events.daily_report_id` 反查整单冲销。

### 2.3 收尾才问「要不要退回仓库」，不是每次都问

「最后一次报工」= 本行勾了完结，或本次把可报量报满。此时如果还有料没登记成消耗，
弹一次窗逐项列出剩余量，两个出口：

- **退回仓库**：意愿随日报保存，审核时先结实耗、再按**当时**的剩余可退量开退料单；
- **留在车间**：不发任何请求。弹窗必须写明「本工单会一直处于未完工状态」——
  `can_close` 要求「已领 = 实耗 + 已退 + 损耗 + 在制」，留在车间的料会让这条等式永远不成立。

填 0、或没有差额 → **不弹窗、不建单、不打扰仓库**。

### 2.4 顺序不可颠倒：先结实耗，再发退仓

退仓申请一提交就冻结领料过账额度，而实耗的上限已经扣掉了待收料量。先冻后结会让审核时的
实耗登记撞「本次清账超过准确原领料未耗用数量」。

同理，退料单走**原领料单位**、台账是**基本量**，换算率不为 1 时两者不等。
所以差额一律由服务端在审核时按 `return-requests/sources` 现算，前端只用本地快照判断
「要不要问用户」，绝不自己换算退多少。

### 2.5 车间任务页只剩只读台账

「登记实际用料」「余料退库」的**填写**入口从车间任务页下线，点进去只剩材料台账与退料进度。
但**撤回退仓申请**保留——退料单填错了数量仓库改不了，只能撤回重提，把它和登记入口一起
关掉等于把人锁死。为此把滑窗的 `canRequestReturn` 从 `canSettle` 里拆出来。

生产计划详情页的管理侧入口(冲销、损耗/在制、整单结案)**完整保留**：报工页只提供
`CONSUMED` 一种结算，`APPROVED_LOSS` / `LEGAL_WIP` 的入口必须继续存在，否则材料守恒
等式的另外两项就没有录入口了。

## 三、明确不做

| 不做 | 理由 |
|---|---|
| 保存草稿就记实耗 | 见 §2.2 |
| 编辑页改已审日报的实耗 | 已审后要改只能走材料台账冲销；编辑页只对草稿开放 |
| 自动把待登记量预填进实耗 | ADR-078 的护栏：不能把损耗、余料或在制静默当实耗。默认空、必填、逼用户自己填 |
| 给不同单位的剩余量算合计 | 把千克和个加起来是假数(全站既有口径) |
| 批量报工超过 20 个工单时逐单拉台账 | 几十次台账请求会把页面拖到不可用。明说「本单只报工」，不静默少挂几行——静默会让车间以为料已经登记过了 |
