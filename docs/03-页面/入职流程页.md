# 入职流程页

> 路由：`/employee/onboarding`（计划：`lib/features/employee/pages/employee_onboarding_page.dart`）· Phase 2
> 上层：[Phase2-人事端总览](Phase2-人事端总览.md)

## 一、定位

hr 通过**多步向导**完成一名新员工从建档到开通账号的完整入职，比直接「新增员工」更规范，确保不漏环节。

## 二、入口与导航
- 进入：员工列表 FAB「+入职」。
- 离开：完成 → 跳员工详情；中途取消 → 回列表（已存草稿保留）。

## 三、响应式布局

`UtenWizard` 顶部进度条 + 单步表单区。

```
┌────────────────────────────────────────┐
│ ← 新员工入职                            │
│ ①档案 ─ ②组织 ─ ③薪资 ─ ④合同 ─ ⑤账号  │  ← UtenWizard 步骤条
├────────────────────────────────────────┤
│  当前步骤表单内容                       │
│  （复用员工编辑页的分组表单片段）        │
├────────────────────────────────────────┤
│  [上一步]            [下一步/完成]       │
└────────────────────────────────────────┘
```
- compact：步骤条横向滚动；medium/expanded：步骤条居中铺开。

## 四、涉及的 Uten 组件
`UtenAppBar` / `UtenWizard`（步骤容器）/ `UtenForm` / `UtenInput` / `UtenDropdown` / `UtenDatePicker` / `UtenButton` / `UtenToast` / `UtenConfirmDialog`。

## 五、功能点（5 步）

| 步骤 | 内容 | 必填校验 |
|---|---|---|
| ① 档案 | 姓名/工号/性别/出生/身份证/手机（复用员工编辑基本信息+联系） | 工号+身份证唯一 |
| ② 组织 | 部门/岗位/直属主管/用工性质/入职日期 | 部门+入职日期 |
| ③ 薪资 | 基本工资/银行开户行/账号 | 金额>0（仅 hr/admin） |
| ④ 合同 | 合同类型/起止日期/试用期 | 起止日期 |
| ⑤ 账号 | 开通系统账号：用户名/初始密码/角色 | 用户名唯一 |

1. **步骤校验**：每步「下一步」前校验当前步，失败停留 + 红字。
2. **草稿**：随时可退出，进度 + 已填存本地草稿，重进恢复。
3. **完成**：一次性提交创建 `Employee` + `User`（账号）+ `EmploymentHistory`（入职记录）。
4. **角色分配**：默认 `employee`，可多选（见全局机制权限并集）。
5. 成功 → Toast「入职办理完成」→ 跳员工详情。

## 六、功能链路图
```mermaid
flowchart LR
    S1[①档案] --> S2[②组织] --> S3[③薪资] --> S4[④合同] --> S5[⑤账号]
    S5 --> SUB[提交]
    SUB --> W[写 Employee+User+EmploymentHistory]
    W --> D[员工详情]
```

## 七、涉及的数据实体
`Employee`（新建）/ `User`（开通账号）/ `Department`/`Position`（下拉）/ `EmploymentHistory`（入职事件）/ `Role`（角色分配）。

## 八、权限要求
- 仅 `hr` / `admin`。
- 权限点：`employee:create`。

## 九、边界情况
- 工号/身份证/用户名重复：对应步骤就地报错。
- 中途取消：`UtenConfirmDialog`「已填内容将保存为草稿」。
- 网络：每步可本地暂存；提交失败保留草稿重试。
- 性能档 lite：步骤切换去滑动动画，直切。
