# 生产计划前需求与物料分析重构（V234/V237/V239 + V247–V250 源码候选）

> **状态**：V234/V237/V239 基础链与 V247–V250 阶段、包装、精确正式需求、执行段形状及计划前外部来源保护已形成源码候选；当前仅完成本地与一次性隔离克隆验证，未核验目标库 `flyway_schema_history`、真实岗位 UAT 和实物流转，不得宣称已部署或生产可用
> **日期**：2026-08-08
> **决策依据**：[ADR-029](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)
> **发布边界**：任何生产写能力在迁移、权限、反向、并发和真实 UAT 完成前均为 **NO-GO**

## 一、迁移原则

1. 已应用 Flyway 迁移不可修改；V150–V230 的历史生产事实、字段和约束保留。V234 若尚未在任何目标环境应用，可在合并前评审；一经应用，后续修复只能追加 V235+。
2. V191 草案强制绑定正式计划，不能改造成计划前分析。V234 新增独立分析聚合，普通生成时才创建正式计划草稿及其 `ACTIVE production_planning_drafts`。
3. 不创建平行库存、领料、报工或入库账。分析、路线、备料 action 和预计供给均不得写 `production_material_demands`、`stock_reservations`、supply peg、执行分段或 DRAW。
4. 普通 generate 与 approve 必须分开：generate 只提交计划草稿；approve 才按一个目标仓原子重算并形成 READY、完整预留、DRAW 和正式销售分摊。
5. 所有写命令使用服务端幂等键和载荷哈希；物理表以数据库约束守住数量、来源和归属。
6. 历史 WAITING/AUTO_WAIT/DEFERRED 零回填、只读兼容。新链路不得再创建这些正式待料状态。
7. V237 在 V234 生产分析表和并行 V236 财务表之后重新执行 fail-closed 审计覆盖 sweep：只为迁移后的未来写入补齐/验证唯一有效 `trg_audit*`，不回填历史审计，也不修改 V234/V236。
8. V239 以新增迁移把 `production_material_analysis_materials.required_qty` 的终态合法范围从 `>0` 改为 `>=0`；全量批次 claim 后 required 恰为 0 是守恒结果，不得回改 V234 或以负数/删除行规避。
9. V247 为 BOM 和分析快照增加控制阶段、包装计量、三阶段齐套量、节点分阶段分配及历史计算模式；V248 为非线性正式物料需求增加不可变精确快照；V249 冻结执行段是 `DEMANDED` 还是有证据的 `ZERO_MATERIAL`。这三个迁移只追加结构和约束，不回写伪造的生产、预留、领料或入库事实。
10. V250 把 V162/V194 的来源防拆保护扩展到 `preplan_supply_actions/allocations` 及其采购、委外下游：冻结外部单据来源身份和路线匹配，阻断通过修改、脱钩或删除来源行绕过追溯；历史 `CANCELLED` action 仍受保护。当前版本序列已到 V250，后续修复只能新增 V251+，不得回改已形成的 V234/V237/V239/V247–V250。

## 二、V234 实际对象与职责

### 2.1 产品生产结构策略

`goods.production_bom_policy` 只允许：

- `BOM_REQUIRED`：必须有可用 BOM；无 BOM 时阻断，除非对本次需求使用独立越权；
- `DIRECT_MAKE`：产品主数据明确确认可无 BOM 直接自制；
- `NOT_PRODUCED`：不得进入生产分析或生成生产计划。

V234 的保守回填是：旧 `source_type` 为“采购/委外”的货品写 `NOT_PRODUCED`，其余写 `BOM_REQUIRED`；**绝不因无 BOM 自动写 `DIRECT_MAKE`**。该回填只保证 fail-closed，不代表业务认定正确；开放新写能力前仍须由工程、计划和生产逐项复核开放需求产品。

### 2.2 分析头、需求行与全树节点

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `production_material_analyses` | 一次持久化物料分析聚合，记录选定目标仓、版本、输入/预览指纹和分析时间 | `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`；该状态不是计划审批状态 |
| `production_material_analysis_items` | 分析中的顶层生产需求行；可来自销售、手工需求或系统 MAKE 子需求 | `SALES_ORDER_ITEM/REWORK/TRIAL/SAMPLE/STOCK/OTHER/MAKE_COMPONENT`；保存 `line_priority/ready_now_qty/ready_by_date_qty` 分配快照；`submitted_qty + approved_qty <= requested_qty` |
| `production_material_analysis_materials` | 完整 BOM 树的平铺节点及本版本数量快照 | 保存 `node_key/parent_node_key/depth/path`、需求归属、建议路线、人工路线、立即/预计字段和下层依赖；路线仅 `BUY/MAKE/SUBCONTRACT` |

销售来源必须指向真实 `sales_order_items`；手工 `REWORK/TRIAL/SAMPLE/STOCK/OTHER` 必须填写稳定业务需求编号与原因且不得伪造销售外键。数据库以 `source_type + lower(trim(source_ref))` 守住非销售来源唯一性；同一需求的活动分析应幂等恢复，终态记录从历史回查，不能靠新幂等键重复创建。`MAKE_COMPONENT` 必须由系统创建，并通过 `parent_analysis_material_id` 精确关联父分析节点；数据库校验其货品、颜色和单位与父节点一致，用户不能手工选择。

全树平铺只提高可见性，不合并依赖。每个节点保留父节点和路径；对每个 `analysis_item_id` 只有 `depth=1` 是可操作节点，`depth>1` 不得保存路线、进入 notify 分组或创建下游动作。MAKE 节点的子需求由 `MAKE_COMPONENT` 行承接，其下层材料不能再次算成顶层产品的直接领料需求。

### 2.3 路线和共享调配

路线确认直接保存在 `production_material_analysis_materials.confirmed_route`，并记录 `route_reason/route_confirmed_by/route_confirmed_at`。主档建议为 `source_suggestion`；建议为 `REVIEW` 或人工偏离建议时原因必填。刷新后必须以版本/指纹判定旧确认能否继续使用，不能把页面缓存当下达依据。

V234 不新增第二套物理库存分配账。共享物料调配在分析中按“选定目标仓 + 货品 + 颜色”共享自由量池，并按 `line_priority` 稳定执行完整套料分配；同仓的刷新/重排/预览/生成在仓维度事务锁内串行，锁后重读其他活动分析软分配与 `SUBMITTED` 草稿承诺，防止跨分析重复宣称同一库存。服务端把各 item 的立即/预计量和直接层节点的已分配现货/缺口保存为同一次快照。分批生成时，本分析的剩余软分配与新 `SUBMITTED` 承诺原子换账，总承诺不得从 100 错增为 110。`PUT /api/production/material-analyses/{id}/allocation-priorities` 必须提交全部有效 item 的完整排列、期望版本、指纹和幂等键，不能只传局部行。该操作不写 `stock_reservations`，也不能移动已批准计划的占用。已预留库存改派必须先对原计划走释放/反向，再重新批准目标计划。

### 2.4 计划前备料 action

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `preplan_supply_actions` | BUY/SUBCONTRACT/MAKE 缺口的权威计划前动作 | `OPEN/CREATED/IN_PROGRESS/DONE/CANCELLED`；路线、目标仓、数量、需求日、业务键、代次、请求哈希和幂等键均落库 |
| `preplan_supply_action_allocations` | 一个 action 到多个真实分析节点的精确数量分摊 | `Σ allocated_qty = action.requested_qty`，事务结束时由延迟约束校验 |
| `production_material_analysis_commands` | PREVIEW/ROUTE/NOTIFY/GENERATE_PLAN 命令幂等账 | 同分析、操作和幂等键唯一；重放返回既有结果，不重复副作用 |

“通知采购/委外/自制”不是普通消息。服务端必须先落 `preplan_supply_actions` 和逐节点分摊，再创建并回写真实下游：

| 路线 | `external_document_type` | 真实下游 |
|---|---|---|
| BUY | `PURCHASE_REQUEST` | 采购申请及来源行 |
| SUBCONTRACT | `SUBCONTRACT_APPLICATION` | 委外申请及来源行 |
| MAKE | `PREPLAN_MAKE_TASK` | `MAKE_COMPONENT` child analysis item / 计划前备料任务 |

消息、角标、任务中心和 Outbox 只是上述事实的投影。action 尚未生成真实下游且未被引用时可以撤回并保留取消人、时间和原因；已有订单、委外发料、收货、正式计划或仓库发料后必须走对应取消/释放/红冲流程，禁止删除或把消息“已撤回”冒充业务反向完成。

### 2.5 计划提交与审批守恒

| 物理对象 | 权威职责 | 关键约束/状态 |
|---|---|---|
| `production_plans.material_analysis_id/material_analysis_item_id` | 草稿计划精确回指分析需求行 | 两个字段必须同时为空或同时指向同一分析内有效 item |
| `production_material_analysis_plan_links` | 分批提交、批准、释放和反向的数量归属 | `SUBMITTED/APPROVED/RELEASED/REVERSED`；plan link 身份和数量不可改、不可删 |
| `production_material_analysis_items.submitted_qty/approved_qty` | 从 plan link 状态同步的提交量与批准量 | 合计不得超过 `requested_qty` |
| `production_planning_drafts` | 既有正式计划的审批前不可变预排载荷 | generate 创建 `ACTIVE`；approve 成功后按既有生命周期转 `APPLIED` |

分析头自身只使用 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`。`SUBMITTED/APPROVED` 是 plan link 的分摊状态，不能把它们写成分析头状态。

普通 generate 的事务边界：

1. 校验分析/item 版本、BOM 签名、销售剩余、单目标仓、本批数量和幂等键；已齐套批次不要求为剩余缺口预先确认路线，但正式物料主档来源无法解析时仍 fail-closed；
2. 创建 `production_plans` 草稿、计划行和 `ACTIVE production_planning_drafts`；
3. 创建 `production_material_analysis_plan_links(allocation_status='SUBMITTED')`，由数据库同步 item 的 `submitted_qty`；
4. 不创建执行段、`stock_reservations`、DRAW、正式销售执行分摊或任何未来供给预留。

approve 的事务边界：

1. 要求 `production_plan:approve`，按稳定顺序锁定草稿、link/item、销售来源、BOM/分析版本和目标仓库存键；
2. 只按所选目标仓重新计算当前合格自由库存及完整套料量；其他仓只作调拨候选，调拨审核入目标仓前不得使用；
3. 同一事务批准计划、创建 READY 执行批次、全部直接领用物料预留、DRAW、正式销售分摊、语义审计与 Outbox，并将 plan link `SUBMITTED → APPROVED`；
4. 任一步失败全部回滚，原草稿和 `SUBMITTED` link 保持可见，不留下部分预留。

同时持 `production_material_analysis:generate` 与 `production_plan:approve` 的用户可在独立确认中显式选择 `approveNow`，生成和批准仍为一个全有或全无事务；不得默认开启，也不得允许无 approve 权限账号调用。

## 三、权限目录与默认部门

V234 实际权限必须在数据库、后端鉴权、Flutter `Perm`、默认部门矩阵和权限管理页保持完全一致：

| 权限码 | 能力 | V234 默认部门 |
|---|---|---|
| `production_material_analysis:view` | 查看生产物料分析 | `GM/DEPT_PROD/DEPT_ENG/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:manage` | 新建和刷新分析 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:route` | 确认物料供应路线 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:notify` | 下达计划前备料任务 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:generate` | 从分析生成生产计划草稿 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:reallocate` | 调整跨产品物料分配 | `GM/DEPT_PMC/SUB_PLAN` |
| `production_material_analysis:bom_override` | 单次无 BOM 例外放行 | 不授任何部门；仅超级管理员固有能力或逐人加授 |

## 四、立即量、预计量与目标仓

`production_material_analysis_materials` 中的 `available_qty/reserved_qty/safety_stock_qty/inbound_qty/shortage_qty/expected_ready_date` 是带分析版本和时间的快照，不是批准时库存真相。

- **可立即生产量**只使用所选一个目标仓的当前合格在手，扣除有效预留、冻结和安全库存后，按全部直接领用组件瓶颈向下取整；
- **预计可生产量/预计齐套日**只用于排序和风险提示，可读取精确来源且日期可靠的采购、委外和 MAKE 未来供给；
- 预计供给、待检库存、未完成调拨和其他仓库存都不能进入本次 generate 上限，也不能被写成物理预留；
- 其他仓库存只展示分布和调拨候选，调拨完成并审核入目标仓后重新分析。

### 4.1 三阶段与包装口径

`goods_bom_items` 及每次分析节点快照保存：

- `control_stage`：`START/ASSEMBLY/FINISH/SHIP/REFERENCE`；
- `consumption_basis`：`PER_UNIT/PER_PACKAGE/FIXED_BATCH`；
- `basis_output_qty`、`allow_partial_package`、`hard_gate`；
- 冻结的 `bom_qty/parent_per_product_qty/calculation_mode`。

只有 `START/ASSEMBLY/FINISH` 允许 `hard_gate=true`。`SHIP/REFERENCE` 由数据库、服务和 Flutter 三层禁止成为硬门槛；它们不参与正式需求、预留和 DRAW。生产包装确实要消耗的纸箱、胶袋、说明书等必须维护为 `FINISH + PER_PACKAGE/FIXED_BATCH`。

分析行保存 `ready_start_qty/ready_finish_qty/ready_ship_qty` 和节点的分阶段分配。`ready_start`、`ready_ship` 是分析参考，物料分析生成计划只允许使用 `ready_finish`。共享库存只走一次守恒分配：生产硬门槛优先、发货参考其次、一般提示最后；同一维度多路径只消费一次。深层诊断仅在有效路线为 MAKE 且父节点真实短缺时继续展开，不能把父件已有库存和子件原料同时算作需求。

V247 对迁移前分析行使用 `LEGACY_CUMULATIVE_PER_UNIT`，继续依赖原行冻结的累计 `per_product_qty`；V247 后新建或刷新行使用 `EDGE_RULE`，按冻结的逐边 BOM 规则递归计算。不能用迁移执行时的当前 BOM 数量重写历史分析。

### 4.2 正式需求的精确快照

V248 保留线性 `LINEAR` 需求，同时新增 `EXACT_SNAPSHOT`：按包装/固定批次时，每个执行分段独立冻结产品数量、精确 `required_qty` 和 64 位规则指纹。库存预留、正式物料需求及 DRAW 都读取同一精确数量；六位 `per_product_qty` 只作为该分段或聚合后的展示平均值，不是重算权威。

例：10 件分成 3、3、4 三段，每 6 件耗 2 个整包且不拆包，三段正式需求为 2+2+2=6，不是聚合后的 4。草稿期软承诺也必须逐个 plan link 独立取整后求和；释放或红冲按原精确事实反向，不能用剩余数量乘平均率换账。

V249 冻结执行段的 `material_requirement_mode`。`DEMANDED` 必须存在正式需求；`ZERO_MATERIAL` 必须冻结 `DIRECT_MAKE/PLAN_BOM_OVERRIDE/NO_PRODUCTION_HARD_GATE` 原因及相应证据，并且没有需求、预留或 DRAW。已确认执行段不得因后改 BOM 改变历史物料形状；若目标库存在无法从历史事实安全判定的零需求执行段，迁移必须 fail-closed，先人工对账，不允许猜测回填。

### 4.3 IQC 合格量、红冲与全拒收替代需求

采购/委外收货只创建待检隔离事实，不得提前增加合格库存或立即量。同一收货可部分 `PASS/FAIL`；只有累计 `PASS` 量进入库存、生产供给 transition 和物料分析唤醒。整张收货的全部明细结案后只唤醒一次，并发处置最后一行必须在收货范围内串行化。

收货红冲在原事务中只反向该收货已 `PASS` 的精确数量和分摊金额；IQC 明细转为 `REVERSED`，当前 `passed_base_qty/failed_base_qty` 归零，并刷新相关分析。可完工量下降只更新快照，不发布正向齐套通知。

整批 `FAIL` 后，已物理收完的原订单不再形成预计覆盖。系统保留原采购/委外申请、订单、收货、IQC 明细与事件，只将原 `preplan_supply_action` 置为 `CANCELLED` 以释放计划投影；再次通知生成 `generation + 1` 的 action，通过 `predecessor_action_id` 追溯失败动作，并按服务端重算的剩余缺口创建替代需求。不得删除原商业单据，也不得用新 action 覆盖原 action 身份。

## 五、历史兼容与后续迁移

- 不给历史生产计划、WAITING/AUTO_WAIT/DEFERRED 伪造 V234 分析、item、action 或 plan link；
- 新工作台对旧待料记录只读标识，处理只能走隔离的旧兼容入口或正常取消/反向；
- V234 不因“当前无 BOM”写 `DIRECT_MAKE`；业务认定和例外证据不得靠历史回填伪造；
- 若评审发现 V234 已部署后的约束、审计或数据修复需求，只能新增 V235+，不得编辑 V234；
- 后续若需要持久化人工共享分配意向、独立审批事件或兼容投影，应以新增表/列承载，不得复用 `stock_reservations` 或改写 plan link 历史。

## 六、最低测试矩阵

### 6.1 数据库与服务端

- 三种 BOM policy、保守回填、循环/失效 BOM、单位不可换算和越权审计；

## 七、上线与回退边界

1. **R0 只读分析**：页面入口、来源候选、全树、目标仓立即/预计量和历史兼容；不产生业务写事实。
2. **R1 计划前写**：分析、路线和 supply action 真实落库，三条下游来源与撤回/反向可追溯。
3. **R2 生成与批准**：generate 与 approve 分离且全量测试；approveNow 显式门控；READY、预留、DRAW 和销售分摊同事务。
4. **R3 生产放行**：完成目标库 `flyway_schema_history`/校验和预检及 V244–V246 非空数据演练；完成历史数量、权限和审计对账；修复 `BOM_REQUIRED` 无有效 BOM、来源路线不可解析、控制阶段/包装计量、单位/货色/仓库及采购/委外/车间责任主数据；完成真实账号与实物流转 UAT、并发/压力证据、备份恢复/回滚演练，并取得业务、技术、运维签字后才开放写 feature flag。

回退只能关闭新写 feature flag；已经创建的分析、action、草稿或批准事实必须通过正常撤回/反向处理，不能靠回滚迁移、删表或删除消息恢复。源码候选、静态检查、单元测试或干净构建均不等于生产就绪；当前结论仍为 **NO-GO**。
