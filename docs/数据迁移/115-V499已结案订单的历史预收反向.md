# V499 已结案订单的历史预收反向

源码：`V499__customer_prepayment_historical_order_reversal.sql`。本地候选，未升级现有业务库。

原规则在绑定订单的预收单发生任意相关更新时，都重新要求销售订单未结案。这会让合法历史预收在订单完成后无法红冲，即使先前抵扣已全部撤回、来源关系与金额从未改变。

新规则保留新登记、重新绑定和新审批的全部门禁：订单必须已审核、未停止、未结案，客户和币种一致。已有预收保持原订单、客户、币种和业务类型，且本次不是进入已审核状态时，不再重新要求历史订单仍然开放。

本迁移只替换原函数并将审批状态纳入触发列，不改历史单据、金额、分配、账户流水和 GL。红冲仍须满足服务端操作权限、未抵扣余额、版本、期间、账户及原/反向凭证约束。它不新增退款能力，也不允许把已抵扣预收直接冲掉。

验证证据包括：人民币预收/分次抵扣/收款/退货及完整反向，双币两批发货与不同到账汇率的正反向，以及 V406 原 GL→V498 非空数据→V499 的真实 PostgreSQL 升级。历史快照保持，新建/改绑定/新审批已关闭订单仍被拒绝；原、反向凭证双向关系保留。见[销售资金场景矩阵](../07-业务链路/2026-09-07-销售资金库存场景矩阵与压力验收.md)。

目录头 V499，共 461 个迁移文件；没有新增业务表。清空脚本的已审目录白名单同步支持 V499/461，不改变 326 张业务表的 CLEAR 230 / PRESERVE 96 分类。历史已应用 Flyway 字节不变，不使用 repair。
