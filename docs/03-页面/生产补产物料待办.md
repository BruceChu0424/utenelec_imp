# 生产补产物料待办

> **位置**：生产进度工作台 `/production/progress` 内嵌待办
> **组件**：`production_fqc_replenishment_banner.dart`
> **后端**：`/api/production/quality-replenishments`、`/material-tasks`
> **迁移**：V414/V415

## 一、适用范围

本待办只处理 FQC `SCRAP/REJECT` 的失败数量。REWORK 复用原失败在制，不进入新增主料待办。每个失败决定生成唯一 recovery authorization；计划员不能手工输入一个无来源的补产数量。

## 二、状态机

```text
AWAITING_ANALYSIS
  → AWAITING_CONFIRMATION
  → AWAITING_STOCK / BLOCKED
  → AWAITING_WAREHOUSE
  → READY
  → 补产完工申报 → 再次 FQC → 仓库点收
```

计划员先建立 recovery-only 物料分析，再确认物料方案。系统按 authorization 数量和当前 BOM 冻结 exact demand；普通物料分析 generate/approve 必须隐藏且服务端拒绝，防止同一失败量同时生成顶层普通计划。

库存不足时保留持久 gap；新幂等键只补未占用差额，不能重复占用或重复生成 DRAW。BUY、MAKE、SUBCONTRACT 缺口都必须先通过对应上游流程形成合格库存，系统不伪造采购单、委外单或子计划。

## 三、READY 门禁

只有 authorization/cycle/原计划身份一致、recovery demands 全部 `FULFILLED`、单一 DRAW 已审核且 `issue_status=2`、仓库已经实际发料、authorization 未取消且 READY 未反向，数据库才允许 READY。页面不能靠按钮点击后本地改状态；READY 后只开放对应 authorization 的可报数量，仍须再次 FQC。

## 四、权限、分页与刷新

- 查看：`production_fqc_replenishment:view`。
- 确认：`production_fqc_replenishment:confirm`，并与计划对象范围求交。
- 待办、物料任务和计数均来自分页/计数 API；未知状态不当作 0。
- BLOCKED 重试在网络响应不确定时沿用原幂等键；明确成功并仍缺料后，下一次人工重试使用新键。
- DRAW 生成后可跳到具体领料单；返回工作台立即刷新。

## 五、反向

来源取消前先反向 replacement 日报/FQC/入库。未领预留可释放、未发 DRAW 可受控反向；已经实发则必须先反出库或按原领料行退料。任何活动 replacement allocation 都阻止静默撤销 READY。
