# V804 仓库数据范围服务端强制(主管 / 子仓负责人 / 其他人)

- 迁移：`V804__warehouse_data_scope_enforcement.sql`(本分支临时号，合并时由编排者重排)。
- 决策：[ADR-149 仓库数据范围服务端强制](../99-决策记录-ADR/ADR-149-仓库数据范围服务端强制.md)。
- 依赖：V800(`fn_warehouse_root_id` 唯一主仓)、V693(`warehouse_keepers`、`fn_warehouse_scope_ids`)、V796(被重写的函数)。
- 不加表、不加列、不加权限点、不改任何数据；只定义函数。reset 分类不变。

## 为什么要改

「我的仓库」只是前端可选的筛选：不带参数 = 全部仓，指定仓不校验是不是本人负责的仓；「我的仓库」= 我负责的仓 + 所有没负责人的仓，覆盖全部在用仓时直接退回全部；徽章与各级计数从不按仓算；预计到货按恒为空的 `inbound_expectations.warehouse_id` 判仓。详见 ADR-149 §1。

## 迁移做了什么

1. `fn_warehouse_keeper_user_ids(ids)` REPLACE：这些仓的**子仓负责人**——登记在本仓或主仓以下各级上级仓、员工在职且账号启用；登记在主仓(`fn_warehouse_root_id()`)上的人是主管，不在此列。
2. `fn_warehouse_designated_supervisor_user_ids()` 新增：指定的主管 = 仓储部(SUB_WH 子树)各部门负责人 `manager_id` 对应员工的账号 + 登记在主仓上的负责人(员工在职、账号启用；不含只因超管身份成为主管的账号)。`fn_warehouse_supervisor_user_ids()` REPLACE：主管(列表范围) = 超管 + 指定的主管。
3. `fn_warehouse_responsible_user_ids()` 新增：任一在用仓登记的有效负责人 + 仓储部门负责人 = 仓库任务参与者，通知弹卡资格把他们当作仓储部门成员。`fn_warehouse_notice_candidate_user_ids(warehouses)` 新增：这张单涉及的仓(含上级链)的子仓负责人 + 指定的主管，仓库类通知池只按它纳入部门外的人。
4. `fn_user_warehouse_access(user)` 新增：唯一判定，返回 `role`(SUPERVISOR/KEEPER/OTHER)、`keeper_warehouse_ids`、`scope_warehouse_ids`(NULL = 不限)、`includes_unassigned`、`warehouse_member`。其他人的默认可见仓 = 没有有效子仓负责人的仓(含已删除的历史仓)；全公司没有任何有效子仓负责人时为 NULL(不限)。
5. `fn_warehouse_notice_recipients(warehouses, pool)` 新增：仓库类通知唯一规则——该仓链上子仓负责人 ∩ 池；没有则指定的主管 ∩ 池(超管不因超管身份算在这一级，否则「整个池」那一级永远到不了)；再没有才是整个池。
6. 预计到货所在仓：
   - `fn_procurement_item_inbound_warehouse_id(order_type, order_item, goods)`：订货表头子仓 -> 采购/委外申请表头子仓 -> 货品所属仓 -> 表头写的主仓。表头写主仓 001 只说明「进仓库」，先按货品所属子仓落到具体的仓(测试服务器上采购/委外申请表头全是 001)。
   - `fn_inbound_expectation_warehouse_ids(expectation)`：预计到货任务逐行到货仓去重；空数组 = 未定仓。
   - `fn_procurement_order_inbound_warehouse_ids(order_type, order)`：订货单逐行到货仓去重(委外回厂通知用)。
7. `fn_stock_document_matches_warehouse_scope(document, ids, unassigned, own_draft_maker)`：DROP V796 的三参数版，新建四参数版——发出仓或调入仓在范围内；两个都没有时按范围是否含未定仓；第四个参数(制单人员工 id 文本，空串 = 不用)给出时，这个人自己还没提交的草稿不论仓都算(只在本人默认范围传)。
8. DROP `fn_user_warehouse_scope_ids(uuid)`(V693「我的仓库」) 与 `fn_notice_warehouse_visible(...)`(V796 读侧通知过滤，从未接入；V798 曾把其中委外出仓分支改为按领料草稿解析仓库，随整个函数一起删除，委外领料待发料通知在发送时按草稿发出仓经 `fn_warehouse_notice_recipients` 分发)。

## 服务端与前端(同一步落地)

- `WarehouseDataScopeService` 实现 `WarehouseTaskScopePort` v2：`access()` 调 `fn_user_warehouse_access` 并按请求缓存；`current(scopeWarehouseId)` 校验所选仓(越界 403「所选仓库不在你负责的范围内」)；`withRequestedWarehouse` 供 `/workbench/badges?scopeWarehouseId=` 汇总；`noticeRecipients` 调第 5 条函数。
- 所有仓库任务端点只认 `scopeWarehouseId`(删 `warehouseScope=MINE`)；计数端点与列表同一谓词；`/expectations/type-counts` 删除，分来源并入 `/expectations/count`；品质检查结果全部端点接入范围；`/documents/status-counts` 与 `drafts.stockDocument` 的仓库单据按范围计数。
- `GET /master/warehouses/my-scope` 返回 `{role, canSelectAll, selectable, keeperWarehouses, defaultWarehouseId}`；负责人候选返回 `duplicateName`。
- 前端仓库选择器重写(主管/多仓负责人右侧滑窗，单仓负责人只读标签，其他人不显示)；任务中心计数全部来自同一份汇总；偏好只存 `warehouseId`。

## 克隆库与服务器

- 克隆库 `uten_imp_who`：8085 启动时执行 74 ms。之后改写了第 6 条函数(表头主仓落到货品所属子仓)，克隆库上已手工 `CREATE OR REPLACE` 并把 Flyway 校验值改为最终文件的值(1935633521)。
- 测试服务器只读核对(未建函数，按同一规则内联 SELECT)：最近 12 张预计到货全部由申请表头 001 推出，按新规则会落到货品所属子仓；`warehouse_keepers` 只有 1 行(系统管理员 -> C01)；仓储部负责人 庞宗荣 还没有账号。上线后在开账号、登记负责人之前，仓库部门成员(其他人)看到的就是全部(只有 C01 由超管负责，C01 的任务其他人看不到、主管能看到)，通知照旧发给池。
