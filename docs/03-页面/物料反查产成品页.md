# 物料反查产成品页

> 路由：`/production/where-used` · 实现源：`lib/features/production/pages/where_used_report_page.dart`
> 后端：`GET /api/production/reports/where-used`（`ProductionReportService.whereUsed`）· 权限：`production_where_used:view`
> 新增：2026-07-28（工程研发部需求：查一个材料用在哪些产成品上）

## 一、定位

BOM 反查（where-used）报表：**输入一个原材料（如"A螺丝"），查出它被用在了哪些产成品上**。
用于物料溯源、替代料评估、缺料影响分析。工程研发部为主使用者，生产部亦常用。

## 二、入口

- 工作台「工程研发部」分区卡片（见 [工作台首页](工作台首页.md)，工程研发部分区由此告别空分组）
- 生产部 hub「生产报表」分区卡片（[生产管理](Phase4-生产实验室总览.md)）

两处入口指向同一页面 `/production/where-used`。

## 三、数据源

`production_plan_costs`（源老库 `F_PlanCostItem`，136 万行 BOM 展开快照，按 `bill_date` 年分区）。
每行带 `goods_id`（材料节点）+ `master_goods_id`（顶层产成品）。按 `master_goods_id` 汇总：

| 列 | 口径 |
|---|---|
| 涉及计划数 | COUNT(DISTINCT bill_item_id) |
| 单支用量 | MAX(dqty)（BOM 单耗） |
| 历史总用量 | SUM(qty) |
| 最近使用 | MAX(bill_date) |

过滤：`goods_id = 输入材料` AND `node_class = 0`（仅物料节点，排除工序/费用）AND `master_goods_id IS NOT NULL`。
走索引 `idx_ppc_goods` + 分区裁剪（bill_date 范围）。

## 四、布局

左右分栏（`UtenListTwoPane`）：

- 左栏：材料选择器（**必选**，复用 `showUtenGoodsPicker`）+ 日期范围（默认上月今日..今日）+ 查询按钮
- 右栏：Excel 风格表格（`MasterDataTableView`，服务端排序 + 翻页）
- 顶部：**只读告示条**——"只读历史数据 · 仅含曾经排产过的自制产成品（未含委外与未投产新品）"

列：产成品编号 / 名称 / 规格 / 分类 / 单支用量 / 涉及计划数 / 历史总用量 / 最近使用。默认按"涉及计划数"降序。
行点击下钻到 BOM 成本展开页（查该产成品完整 BOM）。

## 五、语义边界（重要）

返回的是**历史上被排产展开过的自制产成品**，不是权威 BOM 主档：

- 未投产的新品组合查不到（老库 `B_BomItem` 21.8 万行理论 BOM 本期未迁，归未来 `bom_items`）
- 委外路径不覆盖（委外 BOM 展开 `subcontract_order_cost_items` / 实发料 `subcontract_material_issue_items` 本期不并入）

若工程部发现"理论上该用此料"的产品没查出来，多半是它从没排过生产计划或走委外——属范围限制，非 bug。
后续要全覆盖可 UNION 委外两表 + 补迁理论 BOM 主档（各约半天）。

## 六、技术注

通用执行器 `ProductionReportService.execute()` 的 SQL 拼装顺序无 GROUP BY 位（只适合一行一记录的明细报表），
故本报表自建聚合查询（样板 `ProductionPlanCostService.aggregateByMaster`，含 `CAST(:p AS uuid) IS NULL OR ...` 空安全模式），
但仍返回 `ReportTableResponse` 以复用前端 `MasterDataTableView` 动态列。排序走 `ReportSort` 白名单防注入。

## 七、权限

`production_where_used:view`（V78 seed，默认授权所有部门——反查能力通用）。路由守卫与工作台卡片显隐共用
`permission_by_path.dart` 的 `requiredAnyPermFor('/production/where-used')`。
