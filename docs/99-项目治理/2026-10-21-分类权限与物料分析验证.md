## 扩展核验的守恒规则

| 场景 | 必须保留的事实 |
|---|---|
| 父子与多级 BOM | 来源需求、当前动态备料需求和已下达总量分别计算；按冻结逐边曲线展开，不用平均单耗替代整包/固定批次。 |
| 首次下达与追加 | 私人来源份额和公共备货分开，原行 UUID/工单是否复用由真实执行事实决定。失败事务不留半张单，幂等重放不重复创建，不同请求键并发仍要守住版本和唯一承接。 |
| 损耗与收货 | 订 110、收 100、容损 10 时真实实收仍为 100；订 100、只收 90、损耗 10 时不能把缺少的 10 个实物当作已有库存。 |
| 普通及合并撤回 | 使用统一文字入口、确认、当前权限、来源完整性、版本和幂等协议；普通计划、共享供给动作、采购/委外申请保留各自权威反向路径。已经领用、开工、报工或存在下游责任时按事实阻止，不能释放成公共库存。 |
| 撤父但保留独立子工单 | 子工单的 CREATE/APPEND 逐来源凭证是历史归属证据；原父批取消不能使该子工单丢掉原始责任，也不能恢复已取消父批的需求。重建父批时同一责任只转接一次；真实实收和未完工在途分开计算。 |
| 共享批次的不同订单 | 共享节点的总实收不能逐份复制成每个原始来源的覆盖量。来源 100/200 分批实收 120、60 时，应分别累计 60/120；不能因新父批的共享池总额把 A 的供给误扣给 B。 |
| 现货、在途与公共认领 | 软份额、真实物理库存和正式预留不混算；双端版本、准确来源和撤回恢复守恒，已实际执行的部分不能被旧确认回收。 |
| 多来源在途调拨 | 多个供给方共享扣除既有在途后的净缺口预算，不分别重复使用物理缺口；数据库 NUMERIC(18,4) 通过原始十进制凭证及整数刻度传输、求和和撤回，避免 JavaScript double 丢失尾数。 |
| 会话与迟到回执 | 弹窗打开后切账号、撤权、分析变化或多笔中途失效时，停止剩余提交并丢弃旧回执。权限集合保存不可变快照，防止同一可变 Set 被原地修改后误复用旧确认。 |

## 已确认的并发与资源问题

公开详情原为 READ COMMITTED，跨多条 SQL 组装时可以读到旧 header 版本和另一事务的新来源数量。真实 PostgreSQL 两事务红测已复现，详情改为 REPEATABLE READ，与既有命令读回使用相同快照口径，不增加行锁或长期缓存。

同一详情原重复读取委外物料占用，现局部复用同一只读快照；备料预算按准确物理池复用不变的摘要与切片。显式刷新仍更新 header 版本和命令回执，但来源数量、根数量、齐套投影在所有字段相同的情况下不再重复更新。

V894 性能改造稳定快照中，30 个来源、2970 个节点的服务阶段数据如下；新增 V895 守卫后的复测另外记录，不将旧快照当最终量值：

| 指标 | 修改前 | 已测修改后 |
|---|---:|---:|
| 单次详情 SQL | 43 | 42 |
| 单次详情线程分配 | 79.34 MiB | 71.68 MiB |
| 缺省交期的 30 来源初建 SQL | 344 | 228 |
| 同轮初建销售主档查询 | 30 | 1 |
| 三个发现/复核阶段来源探测 | 90 | 3(三个阶段仍分别执行) |
| 无变化刷新 SQL | 199 | 168 |
| 无变化刷新实际改动行 | 94 | 2(header 与命令回执) |
| 独立销售生产要求读取 | 1 SQL | 1 SQL，约 112 KB 分配 |

上述是带测量工具的本机服务阶段样本。同期有其他编译和测试进程，读详情墙钟样本有重叠，不能据此宣称生产延迟或并发容量，也不能把线程分配当成 RSS。真实数量改变、30 计划只读预览与正式下达的数量一致性另有回归；资源优化不放宽事务、权限、来源或数量限制。

性能最终稳定快照 110 项全部通过，详见[读侧性能与快照一致性核验](2026-10-21-物料分析读侧性能与快照一致性核验.md)。后续 V895 子工单责任桥按另一组真实业务链独立核验，不能拿前述时间样本冒充其验收结果。

V895 当前源码再以同一个真实 Spring/PostgreSQL 方法复测 198/2970 节点：30 来源详情三次均为 43 SQL、零 DML，线程分配 72.53/72.16/72.00 MiB；无变化刷新为 169 SQL、仅改 header 与回执两行。新增责任检查使旧 42/168 预算各增加一条只读 SQL，没有把旧快照的数值当成最终数值。备注仍单次批量 SQL。此处线程分配不是 RSS 或并发容量，测试 JVM 限 2 个处理器与 1.5 GiB 堆。

规模复测首轮将 Maven 堆限为 512 MiB，编译全部 2025 个测试文件时内存不足，尚未执行测试，不能算业务失败。随后仅编译该方法及其真实依赖，通过直接 JUnit 启动完整 Spring/PostgreSQL：1 项成功、0 跳过、0 失败。主 Java/资源与 15 个被选测试依赖的前后哈希无变化，实际编译 V895 与源码均为 `FC19890EA87A240F77338436926AFDFE719D4D7DFBC485AC84CDB8C8585271B5`。原始日志、测量及独立哈希复核见 `server/target-v895-read-parity/minimal-test.log`、`minimal-read-v895.jsonl` 与 `final-selected-verification.json`；工具生成的 `.mimosa` 状态不作为生产源码。

销售备注追溯另发现历史批次扩大查询：只查一个子件时，旧候选 SQL 会为整个分析展开历史私有来源证明。改为从已授权的当前条目递归，仅展开沿途准确批次；具有逐来源证明的子工单以该证明替代宽泛父级继承，避免一部分只属于订单 A 的工单混入共享父批订单 B 的要求。单次批量 SQL 的接口保持不变。

该查询另对单条和整页同时测量，避免单条加速反而整页变慢。最终形状先物化廉价结构边的候选上界，再按相关批次一次校验准确凭证；候选边本身不授予任何销售备注来源。隔离 1000 批夹具的单子件仅展开一份证明，整页 1001 个上下文共展开 1000 份；没有在递归内重复展开 JSON 证明。
