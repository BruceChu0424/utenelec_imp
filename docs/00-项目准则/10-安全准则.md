## 一、设计原则

| 原则 | 说明 |
|---|---|
| 纵深防御 | 前端校验只是体验，**后端才是真相**；前端永不信任输入 |
| 最小权限 | 默认拒绝，按需授予；导出/配置等敏感操作用**独立权限点** |
| 前端不可信 | 前端隐藏只是体验，绕过前端直调 API 必被后端拒 |
| 配置外置 | 密钥/URL 走 `.env` / 环境变量；运行时策略阈值走系统设置页 |
| 审计可追溯 | 关键操作（登录/改密/导出/配置变更/数据变更）全过审计 |
| OWASP 对齐 | 对 OWASP Top 10 每条有明确应对（§七） |

- **后端**：Spring Boot 3.5.16 + PostgreSQL + Flyway。Argon2id 密码哈希、JWT（access 源码当前

## 三、前端安全落地项

### 3.1 路由守卫 + 权限显隐

未登录跳登录页；受保护页按 `permission_by_path` 集中策略守卫：`requiredAnyPermFor` 至少命中
一个，`requiredAllPermsFor` 必须全部命中。入职路由同时要求 `employee:create` 与
`employee:pii:edit`。
菜单/卡片按权限点 `hide`（**不是 disable**——disable 反而暴露攻击面，吸引探测）。

### 3.2 输入校验（前端体验 + 后端权威）

所有表单 `UtenInput` 带 validator（必填/长度/格式/范围）。**前端校验只是体验，后端必须独立再校验**——攻击者绕过前端直打 API。

批量/嵌套请求必须复用后端 `RequestLimits`，不能只校验单个字段：事务单据/批量业务行当前上限
500，货品 lookup 1–200，数据范围 owner ≤1000，通知批删 ≤500/附件 ≤20，权限码 ≤500，
资料变更和员工嵌套集合 ≤100。动态 JSON 接口还须在 Controller 与 Service 双层检查数组形状、
对象类型、UUID、正数和日期；新增集合不得无上限接收。

所有 JSON Controller 请求体还受统一字节上限保护，默认 1 MiB，并按实际流读取，所以无
`Content-Length` 的 chunked 请求也不能绕过；超限返回稳定 413，畸形 JSON/类型返回稳定 400。
multipart/二进制上传不复用 JSON 缓冲策略，必须在各自端点配置流式上限、类型白名单和存储配额。
Nginx 2 MiB 是更外层门禁，不能替代应用层 1 MiB JSON 边界。

### 3.3 敏感数据存储分级

| 数据 | 存储 |
|---|---|
| 偏好（主题/语言/字号） | `shared_preferences` |
| **员工 token record** | **`flutter_secure_storage`**；access/refresh + generation/intentGeneration/sessionLineage 单记录 |
| **待撤销 refresh** | **`flutter_secure_storage`**；最多 32 项/30 天，仅供幂等 logout drainer |
| logout fence | `shared_preferences`；仅非敏感布尔标记，存在/损坏/不可读均阻止自动恢复 |
| 访客 token / 登录账号预填 | `flutter_secure_storage` 独立 key |

🚫 **禁止 token 存 `shared_preferences`**——Android 是明文 XML，可被备份/逆向。

权威 token record 键存在但内容损坏时必须写无令牌 tombstone，禁止从残留旧双键复活。旧双键只在
权威记录不存在时迁移，顺序必须是“新记录写成功 → best-effort 删除旧键”。跨标签页锁、lease 和
BroadcastChannel 只能携带不敏感的 owner/到期时间/代次/lineage/hasTokens，禁止复制凭据。

### 3.4 配置外置

API base URL 是会暴露在客户端产物和网络请求中的公开部署配置，不是秘密。员工端与访客端必须
复用 `api_base_url.dart`。原生 Release 同时固化公司入口
`--dart-define=API_BASE_URL=https://<lan-host>/api` 与云端入口
`--dart-define=CLOUD_API_BASE_URL=https://<cloud-host>/api`；两者均须为批准的 HTTPS host，禁止
回环、userinfo、query、fragment 和运行时任意改写。客户端优先探测公司入口，探测失败才允许已获
远程权限的员工走云端；是否有权远程使用仍由服务端判定，端点切换不是授权。

Web Release 只允许同源 `/api`，不做浏览器内“局域网探针”，也不接受绝对
`API_BASE_URL`/`CLOUD_API_BASE_URL`。Release 不读取 SharedPreferences 中历史或用户手填的服务端
地址，避免把 Bearer token、refresh token 或密码发送到任意主机。`dart-define` **不能保存任何密钥**。

后端密钥、第三方 AK 和数据库凭据禁止硬编码，也禁止放入会随客户端发布的 `.env` 或
`dart-define`；开发使用不进 Git 的 `server/.env`，生产由服务器环境变量或 Vault/KMS 注入。
运行时策略阈值（限流/锁定/令牌 TTL/导出上限/会话空闲超时等）走**系统设置页**（见 §五）。
服务端未设置 `UTEN_PROFILE` 时默认按 `prod` fail-closed；本地开发必须显式设
`UTEN_PROFILE=dev`。base/prod 默认关闭 Swagger，只有 dev profile 默认开放。生产必须显式
提供环境唯一的 `UTEN_JWT_ISSUER`，不能依赖开发默认值。

### 3.5 密码框规范

`UtenInput(isPassword: true, autofillHints: const [AutofillHints.password])`：默认隐藏并提供可见切换；
登录表单使用 `AutofillGroup`，客户端校验只改善体验，密码策略与认证仍由后端强制。

### 3.6 错误处理（不暴露后端细节）

统一 `ApiException` → `context.appError(message)`。🚫 禁止把 status code / stack / SQL 报错直接吐给用户（OWASP 信息泄露）。批量/迁移任务失败只返回稳定错误码和随机 `referenceId`，完整异常只写受控服务端日志，供运维按编号关联。

### 3.7 会话拒绝与弱网恢复

- 清本地会话必须匹配精确结构化响应：`401 UNAUTHORIZED/ACCOUNT_LOCKED/ACCOUNT_DISABLED`、
  `422 VALIDATION_FAILED`；员工另含 `403 REMOTE_ACCESS_DENIED`，访客另含
  `403 VISITOR_BLOCKED`。还必须对提交的完整 token record
  CAS 成功。HTML/空体/未知 code 401、status/code 错配、任意 503、429、网络/超时和畸形 2xx 保留 token。
- 登录/改密先预留全局 intent，提交比较 `intentGeneration + sessionLineage`；refresh 写回/清理比较
  完整快照；退出先切可见状态、激活 logout fence，再在跨标签 token 锁内把旧 refresh 持久交接到加密
  撤销队列，交接成功后才写 logout tombstone。交接失败时 fence 与原 token record 必须保留供重试，
  禁止先删唯一 refresh 副本。旧响应不能复活或误清新会话，跨账号迟到响应必须丢弃。
- `SafeRequestRetryInterceptor` 仅为 GET/HEAD/OPTIONS 重试两次，400ms/1200ms；连接恢复不重放业务写。
  健康探测只认同源 `/actuator/health` 的 `HTTP 200 + JSON status=UP`，2/5/10/15 秒档位带
  85%–100% jitter；HTML、空体、空对象或 DOWN 不能标记恢复。
- refresh 撤销队列是安全子系统的单用途例外，只允许幂等 `/auth/logout`。严禁据此添加或宣称通用
  业务离线重放能力。

## 四、后端安全实现（已落地）

| 项 | 实现 |

| 密码 | Argon2id（防 GPU 暴力）；改密禁止复用最近 N 个（`password_history_size` 可配）；**入职**一次性临时密码=证件号后 6 位（业务决定恢复，弱口令，靠首登强制改密 + 新密码走 `PasswordPolicy` 复杂度兜底），**账号重置**等仍由 `TemporaryPasswordGenerator` 生成 20 位高熵随机密码；明文只在本次响应返回、服务端不持久化且不得记日志 |

| 首登门禁 | `PasswordChangeRequiredFilter` 根据每次请求从数据库重建的 `AuthUser.mustChangePassword` fail-closed；只允许 `POST /api/auth/change-password`、`POST /api/auth/logout` 和冷启动恢复所需的 `GET /api/auth/me`。`/me` 同步返回该标志，Flutter 重启后仍进入强制改密路由 |
| 登录 | 错误计数 + 锁定（`lockout_threshold`/`lockout_minutes` 可配）；登录限流采用“账号/规范手机号低阈值 + IP 高阈值”双桶并按员工登录/访客发码/访客登录隔离 namespace，避免园区 NAT/运营商 CGNAT 互相误伤；未知账号与错误密码返回相同错误并执行 dummy Argon2 匹配，dummy hash 在服务启动时预计算，避免首次未知账号请求额外编码形成时序差或初始化竞态 |

## 五、数据导出与高危配置（强制规范，2026-07-27）

详见 [../05-架构/安全策略.md §十](../05-架构/安全策略.md)。要点（新增导出/配置功能必须照此）：

- **数据导出五防线**：① 独立 `*:export` 权限（不复用 view）② Bucket4j 频率 + 进程内并发闸门 ③ 可选 Agile AES-256 文件密码（密码只走 body）④ 行数上限 ⑤ 审计。
- 导出请求统一使用 `ExportPasswordRequest` 与 `@Valid @Size(max=128)`；`WorkbookDownloadService`
  负责唯一的下载保护规则：密码为空时下载普通 `.xlsx`，任意非空 1–128 位密码均进行 Agile
  AES-256 加密。弱密码只对导出文件开放，不得放宽登录、改密或高危操作二次确认的密码策略。
- **客户端下载边界**：统一 `saveBytes` 清洗文件名为叶子名，移除路径分隔符/控制字符/平台非法字符；
  IO 端同名文件加序号，不覆盖已有文件。
- **系统设置（高危配置）六道防线**：① 授权管理入口只限超管 `authorization:manage` ② `@PreAuthorize` + superAdmin ③ **二次密码确认**（防 token 被盗篡改策略）④ 审计 ⑤ 类型校验 ⑥ 职责分离（`authorization:manage` 不替代 `audit_log:view`）；HR 日常账号支持使用 `account:support`，密钥/部署类走 env。
- **隐藏元数据**：列 key 以 `__` 开头（如 `__srcId`）= 隐藏列，execute 过滤不渲染但 row 携带。

## 六、权限模型（现行：部门 + 个人覆盖）

> 2026-07-24 角色体系下线（ADR-011）。现行 = **全员基础（employee 包） ∪ 部门配置（含上级部门） ± 个人覆盖**，超管全量。

- **权限点**：按功能粒度，如 `employee:view` / `payroll:view` / `purchase_report:export`；授权管理使用 `authorization:manage`，账号日常支持使用 `account:support`。组织负责人身份、职位名称和 `authorization:manage` 均不能推导开户能力。
- **部门 → 权限**：部门配置权限集（含继承上级部门）。
- **用户覆盖**：个人级增减（临时授权/回收）；V135 通过用户版本使既有 staff access token 立即失效。
- **共享定义变化**：部门树、部门权限、角色/权限目录等变化提升全局授权 epoch，使既有 staff access token 立即失效。
- **敏感读写分离**：读取按 `employee:pii:view` / `employee:compensation:view`；V141 起证件、
  联系方式和银行字段写入另需 `employee:pii:edit`，薪资、社保、公积金和补贴写入另需
  `employee:compensation:edit`。后端按请求字段校验，不能只靠前端隐藏。
- **self API 对象绑定**：本人端点必须从认证主体解析对象，不得接受客户端目标 UUID。当前
  `GET /api/profile/me` 只取 `AuthUser.employeeId`；本人个人 PII 例外不产生查看他人的权限，
  银行/薪酬仍按独立读取权限。未绑定账号返回明确 `NOT_FOUND`，前端不得回退到全员详情接口。
- 前端：`sessionProvider.user.permissions` + `permission_by_path` 显隐；后端：每个 API `@PreAuthorize` 独立校验。

当前权限契约复核：146 个前端 `Perm` 常量全部进入超管 fallback，Java 活动引用的 138 个权限码
前端缺失为 0；路由、导出、敏感表单及业务按钮定向测试 20/20、全量 `flutter analyze` 0 issue。
上线前仍须真实 HTTP 的允许/拒绝矩阵和对象级越权测试。

> 即时失效是 V135 的源码设计，不是生产验收结论。上线前必须在目标 PostgreSQL 应用迁移，并覆盖
> 个人 grant/revoke、用户角色、员工换部门、部门树移动/软删、共享权限、超管和员工绑定变化；
> 同时验证逐请求投影的 P95/P99。

## 八、禁忌

🚫 硬编码密钥/URL/API key 到代码（走 `.env`）。
🚫 token 存 `shared_preferences`（必须 secure_storage）；密码禁止任何本地持久化，只进入当次 HTTPS body。
🚫 用 `disable` 代替 `hide` 表达无权限。
🚫 后端错误细节（stack/code/SQL）直接吐给用户。
🚫 数据导出复用 `:view` 权限（必须独立 `:export`）。
🚫 高危配置改设置无二次密码确认。
🚫 密钥/部署类配置进系统设置页（只放运行时阈值）。
🚫 明文 HTTP（必须 HTTPS）。
🚫 在公网或业务网直接暴露后端 8080，或把任意来源加入 `UTEN_TRUSTED_PROXY_REGEX`。
🚫 前端跳过后端校验允许写操作。
🚫 日志含 token、密码、短信验证码或完整手机号（即使开发期）；开发短信网关只记手机号尾四位，明文验证码只能通过显式 dev 响应短暂返回。
🚫 把手机号、身份证或其它原始 PII 放进 JWT claim；JWT 默认只是签名，不提供载荷机密性。
🚫 把服务端/用户提供的文件名直接拼到下载目录，或静默覆盖同名文件。
🚫 正式运行时依赖未登记的境外 CDN、字体、脚本、遥测、对象存储或地图服务。
🚫 用设备/服务器默认时区决定“今天、当月、账期、单号日期”等中国业务日界线。
