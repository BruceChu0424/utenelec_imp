# V712–V715 物料汇总、共享制造与精确交接

本轮业务设计见 [ADR-120](../99-决策记录-ADR/ADR-120-物料汇总办理与共享制造来源.md)。当前源码目录预期为 V715 / 644 条迁移，执行结果以专项验收记录为准；本文件不代表业务库已安装。

| 版本 | 变化 |
| --- | --- |
| V712 | 共享下单批次、不可变创建/追加事件、原来源与共享子料的完整 BOM 路径关联；一张实际单据保留多来源私有份额和独立公共量 |
| V713 | 精确覆盖、冻结来源容量及已有供给的责任转交；保留旧任务未转交部分和反向边界 |
| V714 | 并行权限修复：登记 `production_plan:create`，与汇总数量无关 |
| V715 | 共享生产和原产品之间的直送份额证明；沿用实际直送、质检、出入库和反向规则 |

V712 增加 `preplan_aggregate_batches`、`preplan_aggregate_batch_events`、`preplan_aggregate_material_aliases`，V715 增加 `preplan_aggregate_direct_transfer_slices`。四张表都是 CLEAR 业务事实；汇总批次为 FULL 审计，其余三张只追加表归 NONE/ledger，行内保存操作者、时间与确切来源。清库目录共 422 张：CLEAR 320、PRESERVE 102。

V712另加共享行动的约束排队计数列`aggregate_allocation_check_revision`：批量分摊按语句去重排核，最终始终SUM真实份额；具名IMMEDIATE及保存点语义保持。该列不是金额、数量或校验缓存，不改变清库分类。共享委外单父字段只在准确批次证明成立时允许为空，来源份额从供给行动读取。

历史按产品建立的单据、订单数量和已冻结用料保持原身份。新汇总命令才创建共享批次；已有子件供给仅凭原始来源和完整 BOM 边路径转交，不凭同货品名称或行位置推断。已应用的 V709–V711 字节不需要改动。

上线采用正常 Flyway 前向迁移，先备份并完成相同目录的隔离 PostgreSQL 全链验证。回滚应用前必须确认是否已有新共享批次；已有新业务事实时不得直接删除新表或恢复不认识 `AGGREGATE_MAKE` 的旧运行时。业务库安装需要单独安排。
