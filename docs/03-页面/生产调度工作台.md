## 2026-08-11 当前入口与 ADR-033 目标边界

> 当前新建/分析入口是 `/production/material-analysis`，分析历史是 `/production/material-analyses`，生产计划历史是 `/production/plans`。目标交互与岗位 SOP 以[生产物料分析页、节点任务与逐级计划](生产物料分析页.md)和 [ADR-033](../99-决策记录-ADR/ADR-033-生产物料节点任务化与自底向上备料.md)为准。本节优先于下方 V234 工作台目标设计和 V191–V195 历史调度链。

Flutter 没有把“待分析/备料、可下达、生产中、已完成、历史待料”实现成一个五页签总表；员工从新建页勾选销售候选或录入合法手工来源，也可从独立历史页恢复原 analysis。当前工作树已形成 ADR-033 的逐路径备料和同任务流计划生成源码候选，Flutter 页面/模型 25/25、目标 analyze 无问题；这仍不能替代真实浏览器/岗位验收。

页面目标合同如下：

- 完整 BOM 默认展开，每个 `analysisItemId + path/nodeKey` 是独立节点任务；所有行显示目标仓现货、本批需求、缺口、状态和操作；
- 缺料用红色 + 图标/文字 + 数量表达；`required=0` 只显示“本批无需补货”，不得显示“随上级件”；
- MAKE 和有供料 BOM 的 SUBCONTRACT 按父件实际短缺激活下层，BUY 不激活后代；
- “可开工（分析参考）/可完工入库/预计可发货（参考）”分列；计划最大量只取可完工入库，兼容字段 `readyNowQty` 等于该量；
- `SHIP/REFERENCE` 不作硬门槛、不预留、不生成 DRAW；生产消耗包装必须配成 `FINISH`；
- BUY/委外是物料任务；MAKE 下层实际齐套后才创建 `MAKE_COMPONENT`。当前候选以整节点 child ownership 停止父树后代激活；只有 MAKE/root 可生成计划；
- 从当前节点进入既有计划向导填写数量、车间、负责人和日期；取消或生成后回到/留在分析任务流，显示真实计划状态，不直接 `approveNow`；
- 未排余量保留在原 analysis，待采购、委外或 MAKE 合格供给到位后继续分批安排，不创建新的 WAITING 正式计划。

V250 旧口径隔离链与 ADR-033 当前工作树定向自动化都有局部证据，但真实 PostgreSQL/HTTP/浏览器仍须单独核验；目标库、实际到货/IQC/MAKE 正式子件、车间至分批发货实物流转和真实岗位 UAT 未完成，生产写链路仍为 **NO-GO**。

## 2026-08-08 工作台目标设计（V234，历史参考）

> 本节保留 V234 的五视图目标设计，并不表示当前 Flutter 已实现该总工作台。若与上方目标冲突，以上方、[ADR-033](../99-决策记录-ADR/ADR-033-生产物料节点任务化与自底向上备料.md)和当前代码为准。完整树是逐路径节点任务视图，但不能自动递归创建正式计划；新正式计划只允许 READY。目标库和真实 UAT 未完成，生产写链路 **NO-GO**。

### 页面职责与一级动作

工作台承接计划前生产需求，分为“待分析/备料”“可下达”“生产中”“已完成”“历史待料”五个视图。列表上方把 **“物料分析”** 与 **“生成生产计划”** 放在同一动作区：

- “物料分析”始终是当前主要工作入口；选中一条需求时打开该需求，未选时提示先选择；
- “生成生产计划”只在至少一条选中需求的可立即生产量大于零且账号有权限时启用；
- 两个动作必须有文字标签、图标、加载与禁用原因；移动端放入固定底部动作条，保持至少 48dp 触控目标；
- 历史记录、刷新、筛选和列设置使用次要动作，不能与主操作争抢视觉层级。

### 待排需求列表

每行至少显示：需求号、来源单号/手工类型、产品、需求总量、已下达量、剩余量、**可立即生产量**、**预计可生产量**、齐套率、预计齐套日、最早短缺、交期风险、优先级、分析状态、数据更新时间和负责人。

“可立即生产量”只使用选定单目标仓的当前合格可用库存；“预计可生产量”可使用精确 peg 且日期可靠的采购、委外和 MAKE 未来供给。两列不得合并。其他仓只展示库存分布和调拨候选，不能跨仓相加成当前立即量。默认排序建议依次使用：已逾期/临期、可立即生产量大于零、优先级、需求日期；用户排序和筛选返回页面后保留。

列表由服务端分页和对象范围过滤，并覆盖销售来源、五类手工需求及系统 `MAKE_COMPONENT` 子需求。另有对象范围一致的“物料分析记录”分页视图，展示负责人、来源/需求编号、状态、齐套量、分析时间和最后更新时间；点击任一记录按 `analysisId` 恢复详情，不能让离页后的手工任务变成只有知道 UUID 才能找回的孤儿记录。50 行以上使用虚拟列表。恢复活动且可刷新的旧分析时，可用持久化完整来源自动重算一次库存/BOM 快照和分析版本；`VIEW`-only 记录不得写。任何自动刷新都不能提交路线、通知或计划生成。

### 物料分析页

点击后加载该计划前需求的全部组装层级，并默认展开成逐路径节点任务树。页面顶部可按现场顺序展示只读摘要卡：

1. **自制 MAKE**；
2. **采购 BUY**；
3. **委外 SUBCONTRACT**；
4. 当前库存已覆盖；
5. 结构异常/待确认。

点击卡片只切换筛选，不改变路线或数量。表格每行显示层级缩进、BOM 路径、父件、组件、用量、本批激活需求、主档建议路线、人工确认路线、仓库库存、有效预留、冻结/安全库存、当前合格可用、未来供给、缺口、任务所有权、下游动作和更新时间。`required=0` 显示“本批无需补货”，但仍显示仓库现货。

缺料行使用深红背景/边线时还必须显示缺料图标、文字和数量，不能只靠颜色。重复物料可显示汇总数量，但展开后必须能查看每条 BOM 路径和 `analysis_item_id` 需求归属。

### 全树节点任务与自底向上备料

- 页面默认展开整棵 BOM，每个 `analysis_item_id + path/node_key` 是独立节点任务；同货多路径不得压成一个任务或按货号开口供给去重。
- 目标仓合格自由库存可在仓货色维度共享分配，但分配结果、action allocation、委派和反向必须回到各自路径。
- 根产品激活直接组件；父件只按实际未覆盖短缺向下传播。BUY 截断后代；MAKE 激活下层；SUBCONTRACT 有我方供料 BOM 时激活供料后代，无 BOM 时不虚构需求。
- MAKE 节点下层实际齐套前不创建 child item。当前候选点击“安排生产”后幂等创建 `MAKE_COMPONENT`，以 child 存在性投影整节点 ownership，并让父树后代不再激活。目标合同要求未来若支持任意分批委派，须显式守住委派量和未委派余量；当前没有 `delegated_qty`，不得写成该能力已实现。
- child item 在同一工作台独立生成真正的子生产计划。最深层可齐套任务优先；子件合格入库后，父分析才增加当前可用量。
- 可从父节点定位 child item，也可从 child item 返回精确父路径；不得按 goodsId 猜父件。子需求的计划量、报工量和在途不能冒充父产品或销售完成量。
- ADR-028 的 full-tree orchestrator HTTP 写入口永久停用，新工作台不展示其入口；历史服务代码仅供兼容审计，不得借配置重新开放新写入。

### 路线确认与下游动作

主档来源只是建议；计划员只对本批已激活、未委派且仍有缺口的路径节点确认 BUY、SUBCONTRACT 或 MAKE。偏离建议时必须填写原因，服务端校验路径所有权、父路线、目标路线所需主数据和权限。分析输入变化后旧决定显示“已过期，需重新确认”。

“通知采购”“通知委外”和“安排自制”都不是发普通消息：

| 动作 | 首先落库 | 必须精确关联 |
|---|---|---|
| 通知采购 | BUY `preplan_supply_actions` | `PURCHASE_REQUEST` 真实采购申请行及原始节点分摊 |
| 通知委外 | SUBCONTRACT `preplan_supply_actions` | `SUBCONTRACT_APPLICATION` 真实委外申请行及逐路径分摊；供料后代另行备料 |
| 安排自制 | MAKE 计划前 action（当前复用 notify 的 MAKE 分支） | 下层实际齐套后创建 `PREPLAN_MAKE_TASK + MAKE_COMPONENT` 并投影整节点 child ownership；显式分批委派量未实现 |

按钮状态至少包括“未处理、生成中、已下达、履约中、已齐套、撤回中、已撤回、反向失败”。未生成真实下游且未被引用时可撤回；已有订单、委外发料、收货、正式计划或仓库发料后，必须显示对应反向入口和处理任务，不能直接删除或把通知标为已撤回。

### 共享物料调配

工作台允许多选需求查看共享短缺物料，并在自由库存范围内调整分析分配。分配面板必须同时展示总自由量、各需求建议量、人工分配量、交期和影响后的可立即生产量。

重排使用明确的上移/下移动作并在确认前预览影响；确认调用 `PUT /api/production/material-analyses/{id}/allocation-priorities`，提交全部有效需求的完整优先级排列、期望版本、指纹和幂等键。取消不写回。服务端以单一完整套料池重算并持久化快照，物料行缺口、通知数量、待排列表和销售进度不得各自按单行另算。

- 分析分配不写 `stock_reservations`；普通生成计划草稿时仍不生效，只有批准事务按目标仓原子创建物理预留时才生效；
- 分配总量不得超过未预留、未冻结并扣除安全库存后的自由量；
- 支持输入/步进器等非拖拽操作，拖拽只作大屏快捷方式；
- 已被 READY 计划预留的物料不能直接抢占。若账号有高风险改派权限，必须先进入原计划释放/反向向导，校验未发料/未开工并填写原因，再返回重新下达；
- 并发失败时点名物料、原可用量、当前可用量和受影响需求，由用户决定下一步，不自动循环重试。

### 分批生成草稿与批准生产计划

只有 MAKE child item 和根产品显示“安排生产”。先选择一个目标仓，再从当前节点进入既有计划向导逐行填写本次提交数量、车间、负责人和日期，默认值不得超过该行目标仓可完工量。BUY/委外节点没有生成计划动作。提交前摘要展示将创建的计划草稿、ACTIVE planning draft 和来源；用户明确确认后才写入，取消或成功后回到原分析任务流。

普通“生成生产计划”使用 `production_material_analysis:generate`：服务端校验 item 类型、委派所有权、分析版本、BOM 签名、单目标仓和数量后，只创建计划草稿、计划行、`ACTIVE production_planning_drafts` 和 `SUBMITTED production_material_analysis_plan_links`，同步 item 的 `submitted_qty`；不创建执行批次、物理预留、DRAW 或正式销售分摊。路线确认只在下达缺料任务时强制，已完整齐套的本批数量不因剩余缺口路线未确认而被阻断；只有正式物料路线连主档也无法解析时才 fail-closed。成功后留在当前分析页刷新计划号和状态，员工继续处理其他节点。分析头仍只使用 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED`。

持 `production_plan:approve` 者随后批准时，服务端在一个事务按目标仓重新校验需求剩余、BOM/分析版本、路线、当前合格库存和职责分离，并原子批准计划、创建 READY 批次、完整套料预留、DRAW、销售分摊和审计/Outbox，将 plan link `SUBMITTED → APPROVED` 并同步 item 数量。任一行失败则整批失败，草稿/SUBMITTED link 保持可见且没有部分预留。持 generate + approve 权限者可显式选择 `approveNow`，生成和批准同事务；不得默认跳过确认。剩余数量继续留在待排需求；不创建 WAITING/AUTO_WAIT/DEFERRED 正式计划，也不把未来供给伪装为预留。

### 无 BOM、权限和异常

- `DIRECT_MAKE` 可无 BOM 直接自制；`BOM_REQUIRED` 无有效 BOM 显示结构阻断；`NOT_PRODUCED` 不得确认 MAKE。单次越权只对特定分析 item/计划生效，需要 `production_material_analysis:bom_override`、原因、越权人和审计；V234 未实现附件字段，不得在 UI 冒充已留附件。该权限默认不授任何部门，只允许超级管理员固有能力或逐人加授。
- 页面实际权限统一为 `production_material_analysis:view`、`production_material_analysis:manage`、`production_material_analysis:route`、`production_material_analysis:notify`、`production_material_analysis:generate`、`production_material_analysis:reallocate`、`production_material_analysis:bom_override` 和 `production_plan:approve`，不得再使用设计期 `production_preplan:*` 名称或只复用宽泛 `production_plan:edit`。
- 列表、详情、批量动作、导出和深链统一执行对象范围；`view:all` 只放宽创建人范围。动作由服务端 `allowedActions` 最终决定。
- 分析加载失败显示错误卡和重试；部分节点失败不能把未知值当零。离线/超时显示数据是否陈旧，禁止继续下达。
- 深层结构用层级文本、路径和可展开详情表达，不依赖颜色或仅图标。键盘/读屏顺序与视觉顺序一致，错误聚焦到第一个问题字段。

### 历史 WAITING 视图

历史 V191–V195 `WAITING/AUTO_WAIT/DEFERRED` 计划单独进入“历史待料”页签，带“旧流程，只读兼容”标识。新工作台不允许对其执行共享调配、路线重选或新计划生成；完成/反向通过 feature flag 隔离的兼容入口处理，并记录调用量以便最终退役。

## 2026-08-02 历史调度链路（V191–V195，仅兼容）

> 本节只保留 2026-08-02 的历史兼容口径，旧目标库状态不得覆盖上方 2026-08-10 当前边界；若历史按钮或递归子计划描述与新入口冲突，以上方当前章节为准。

调度工作台进入某张生产计划后，标准路径是：草稿物料评审→保存可恢复预排草案→审核原子下达→回查采购/委外/DRAW/真实子计划→在确认包上预览或打印生产执行工卡。审核前不得锁料或建正式下游单据。

物料评审的处置必须显示为 `READY`、`AUTO_WAIT`、`DEFERRED` 三态：整套齐料才是 `READY`；系统缺料为可自动齐套的 `AUTO_WAIT`；用户主动延期为禁止自动提升的 `DEFERRED`。审核后的 `DEFERRED` 只能通过 `release-defer` 单向人工放行并立即重做齐套，不能原地改写回延期。

车间必须是 `DEPT_PROD` 直属子部门，班组必须直属所选车间，负责人须为在职/试用且在所选组织路径内，开工日不得晚于完工日。V195 仅刷新 V194 新增业务表的未来写入审计覆盖，不补历史审计或业务数据；候选未完成目标库迁移及真实岗位 UAT，生产发布仍为 **NO-GO**。

MAKE 采用“直接层、逐级下钻”：父包只创建当前层自制缺口的子计划，禁止一次递归生成所有层。每张子计划可再次走同一评审与审核链。无 BOM 行可定位治理，但整方案不得保存或下达。

只读账号可查看已生成结果和工卡；编辑账号可预排、覆盖草案和补建尚不存在的正式计划包。系统不会对已有确认包执行“生成剩余”或原地重算，而是幂等回放原有结果。

## 一、页面职责

生产调度工作台承接计划需求池中已选择 `MAKE` 路线的销售缺口，负责排产与进度查看：

- “待排产”页按交期、紧急程度和 BOM 可用性展示可排销售需求；
- “生产进度”页展示父生产计划及其真实自制件子计划；
- 页面只负责导航、筛选和调度操作，不把展示状态当成库存、领料或完工事实；
- 计划详情、执行分段、领料、报工和入库仍由各自权威单据及服务端状态机决定。

## 二、必须区分的两个“子”概念

| 页面对象 | 数据来源 | 是否独立生产计划 | 点击结果 |
|---|---|---:|---|
| 自制件子计划 | `subplan_links` 指向子 `production_plans` | 是 | 打开子计划 `/production/plans/{childPlanId}` |
| 执行分段 | `production_execution_segments` | 否，是父计划明细的执行从属 | 在父计划详情打开执行分段详情 |

页面文案可以使用“子计划”帮助现场理解，但代码、接口、审计和文档必须保持以上语义，不能把执行分段误写为独立生产计划。

## 三、生产进度卡交互

一个父计划卡包含两个互不冲突的点击区：

1. 点击父计划表头，打开该父计划详情；
2. 点击“子计划 N 张”，只展开或收起子计划进度；
3. 展开后点击具体子计划行，打开该子计划详情；
4. 子计划可以继续展示自己的下级计划，形成逐层下钻；
5. 空计划 ID、自引用 ID 或路由异常必须显示明确错误，不允许静默无响应。

父计划表头与展开控件使用分离的 `InkWell`，避免点击子计划区域时误跳父计划。计划卡的置顶、重要标记菜单也保持独立点击语义。

## 四、权限、状态与异常

- 生产计划查看权限只决定能否进入计划详情；跳转本身不能绕过路由和服务端对象范围校验。
- 编辑、派工、报工等动作继续按各自权限点和服务端状态校验显示，不因能查看子计划而自动获得写权限。
- 车间、班组、负责人和日期必须由服务端再次校验组织层级与有效人员范围；前端联动筛选不是安全边界。
- 子计划列表加载失败时显示错误卡和“重试”，不影响父计划详情和 MRP 物料需求的独立展示。
- 没有子计划时不渲染空卡；红冲、草稿、进行中、已完成分别显示真实状态。
- 列表刷新后必须重新读取服务端数据，不能长期复用旧的展开内容作为业务事实。
