# ADR-105 审计白名单行级审计、只记变化、按月分区留存与全写操作语义事件

- 状态：已接受(2026-09-23)
- 迁移：V670(三清单 + fn_audit 只记变化 + 遗留导入旁路 + 分类只算一次)、V671(审计表按月分区 + 只追加 + 留存函数)、
  V672(销售订单/出货单/生产计划的审核、红冲、驳回时间落单据列)、V673(production_plan_costs 改普通单表)
- 权限：零新增权限码
- 取代：V169 起「除技术白名单外全表必审、审计触发器不许带 WHEN/列清单」的规则(V184/V530/V572 全表 sweep 不再有后继)；
  V424 手工登记的请求降噪路径清单(`AuditNoisePolicy`)；V556 写入期分类触发器；V171 起逐行两阶段归档；人工应急归档 SQL 脚本
- 关联：[数据迁移说明 38](../数据迁移/38-运维-审计与日志保留.md)、[62](../数据迁移/62-V424审计日志降噪与中文化.md)、
  [ADR-017 模块化单体与异步旁路](ADR-017-模块化单体与异步旁路.md)

## 一、问题(审计发现 db-schema-01/02/03/04/09/11、audit-retention-settings-01/03/04/05/06/07/13、perf-warehouse-quality-08、perf-production-exec-11、perf-material-analysis-14、security-10/11/12)

1. **审计量与人的操作无关，与系统重算次数成正比**。行级审计挂在 404/434 张表上，派生快照(物料分析物料行、估值图)、
   队列、编号预留、只追加流水每次重算都被整行复制；21.6% 的 UPDATE 前后完全相同；一次 7 行 IQC 入库写 199 行业务数据
   就写 199 行审计。25 天 18 万行 294MB，数据库来源里七成以上是噪声。
2. **请求审计默认全记**。成功 GET 占请求事件 93%，靠一份手写路径清单排除轮询，每加一个角标端点就漏登一次；
   每个 401 写两行；例行过期令牌的 401 占中风险的绝大多数；45 秒静默刷新被记成人工「查看详情」。
3. **风险等级三处各算一遍**(写入触发器子串匹配、查询期补丁、显示期抬升)，口径漂移：显示「中风险」的行按中风险筛不出来。
4. **关键动作没有语义事件**：约 500 个写端点里只有少数服务手写了业务事件，审核/红冲/授权只能靠 HTTP 路径猜。
5. **业务逻辑读审计**：销售订单时间线从审计反查审核/红冲时间，在线审计只保留 6 个月，之后时间点消失。
6. **留存不可证、不可控**：逐批 INSERT+DELETE，成功不留痕、没有真库测试；运行账号对审计表有 UPDATE/DELETE/TRUNCATE；
   另有一份按 180 天归档、不读系统设置的人工脚本。
7. **审计里的完整手机号**：九成行的操作人账号是 11 位手机号，登录失败把原始输入(常是误输的密码)原样落库；
   模拟身份期间附件下载记在被模拟员工名下。
8. **遗留导入**会把约 250 万行历史连同行审计写一遍；production_plan_costs 为只读快照却按年分 34 个区。

## 二、同行做法(归纳共识)

- SAP 的变更凭证(CDHDR/CDPOS)只对登记了「变更凭证对象」的业务对象、且只对勾了「更改凭证」标志的字段记录，
  存的是字段级旧值/新值；派生表、内部队列不记。Odoo 的 mail tracking 同样只追踪声明了 `tracking=True` 的字段，
  并只写变化的字段。金蝶/用友的「上机日志」记的是业务操作(单据审核、反审核、删除)，而不是整行镜像。
- 共识：**白名单 + 字段级变化 + 语义操作日志**，保留期按时间分区整体归档/删除，审计存储对应用账号只追加。

## 三、决策

### 3.1 行级审计三清单(V670)

每张 public 表必须且只能归入一类，每条带理由，唯一登记处是 `AuditTriggerCoverageMigrationContractTest`：

| 清单 | 触发器形态 | 典型表 |
| --- | --- | --- |
| FULL | `AFTER INSERT OR DELETE` + `AFTER UPDATE ... WHEN (OLD.* IS DISTINCT FROM NEW.*)` | 主档、分类树、账号权限、系统设置、人事(脱敏)、工资报销(额外脱敏金额)、各单据头行、财务单据与凭证 |
| COLUMN_SCOPED | `AFTER UPDATE OF <列> WHEN (<任一列变化>)`(物料分析表头另加 INSERT/DELETE) | 物料分析表头(状态/取消/仓库/制单人)、物料行(确认路线/理由/确认人)、来源行(需求数量/交期/优先级/原因/删除)、物料改挪记录(状态/关闭人/关闭时间/关闭原因) |
| NONE | 无 | 派生投影与估值图、队列/认领/幂等命令、编号预留、偏好学习、单据关联、只追加事件/流水/批次账(行内带操作人，子行经父行追溯)、遗留只读数据、技术表 |

当前 400 张表：FULL 180、COLUMN_SCOPED 4、NONE 216。

「只追加事件/流水/批次账」一组靠机器核对而不是靠理由文字：契约测试扫描主代码与 V670 之后的迁移，这组表
一出现 `UPDATE` 就失败，只有逐条登记理由的三处一次性完成回填例外(离职交接执行完成回填结果、日报审核回填
所属日报、到货异常入库命令回填结果，均带状态/空值守卫只发生一次)。会被人工改状态的表不能放进这一组：
物料改挪记录(`preplan_material_reallocations`)会被人工撤回/取消、随优先履约推进状态，因此归 COLUMN_SCOPED。新表建表迁移必须登记，FULL/COLUMN_SCOPED 调用
`fn_audit_track_table(表, 清单, 事件类型[, 脱敏, 列, 含新增删除])`，不许手写 `CREATE TRIGGER trg_audit_*`。
静态契约测试核对：迁移链回放后的每张表都已归类、V670 施加的清单与登记一致、之后的建表都已登记；
真库测试逐表核对触发器形态。

说明：`FulfillmentMutationLocks.createdHere` 仍查 `production_material_analyses` 与五类商业来源单据头的新增审计行，
这些表都保留 INSERT 审计；该依赖由并发工作流改为只看 xmin 后删除(架构测试的临时例外同步删除)。

### 3.2 只记变化(V670 fn_audit)

- INSERT/DELETE 存整行(经 `fn_audit_minimize` 脱敏)；UPDATE 只存变化的键，外加单号/编码/名称/旧系统编号等
  非空定位键(两边相同，不算变化，只为列表摘要写得出「修改销售订单 SO-001」)。
- 忽略易变列：updated_at、updated_by、version、lock_version、row_version、last_login_at、last_used_at、last_seen_at、
  last_heartbeat、failed_attempts、quantity_unit_locked、last_selected_at/by；忽略后没有变化就不写。
- 敏感列变化只记列名(`_redacted_changes`)，不记内容；`login_account` 存脱敏值。脱敏函数去掉凭证、证件、
  电话/手机/传真/邮箱/地址、车牌、证照号、银行账户与自由文本，另按表去掉往来单位联系方式的值、官网询盘联系人
  姓名、员工姓名等；FULL 表的新增/删除整行与变化差异都经它，不会带出客户/供应商手机号或员工车牌、证照号。
- `app.legacy_import='on'` 的会话不写行审计。

### 3.3 分类只算一次

删除 `trg_audit_classify / fn_audit_classify / fn_audit_classify_row` 与查询期、显示期的补丁。
Java 侧 `AuditClassifier` 在 `AuditService` 写入前按明确目录给出 risk_level/event_category；数据库行事件由
`fn_audit` 按清单登记的事件类型直接赋值(删除与权限/系统类记高风险)。两列改为 NOT NULL + CHECK。
审计页显示与筛选只读存储列，「有风险」= 严重/高/中。

### 3.4 请求审计与语义事件

- 成功的 GET/HEAD 默认不记。敏感读取两类：业务服务显式写的详情查看/下载/审计查询事件，以及在控制器方法上
  声明 `@AuditedRead(理由)` 的读取(员工花名册与履历、工资条与批次列表、官网询价列表、人事资料变更列表)。
  是否留痕只由服务端声明决定，不看客户端请求头。
- 每个写请求(POST/PUT/PATCH/DELETE)由 `UserOperationAuditInterceptor` 从 HandlerMethod 推导一条语义业务事件：
  动作码「资源.方法」(控制器类名去 Controller、方法名，均转下划线)，目标取路径变量 id(其次唯一的 *Id 变量)，
  带请求方式、路径、状态码与耗时，取代通用 http 行；失败同样记录。业务服务已写显式业务事件的请求不再重复；
  页面自动发起的会话维护写入在方法上声明 `@AuditAutomaticWrite(理由)`(任务认领心跳、按来源/页面自动已读、
  工资条已查看、界面偏好)，成功时不记。审核/驳回/反审核/红冲/作废/过账/删除等关键动作的中文名集中在
  `AuditActionNames`，其余按请求方式给通用名称。不逐个控制器加注解，新增写端点自动有语义事件。
- 安全事件写了就不再写通用请求行；签名正确只是过期的访问令牌产生的 401 不记(签名或格式错误照记)。
  拒绝事件与匿名失败请求行经 `AuditEventThrottle` 按固定一分钟窗口节流：已登录会话同一路径每分钟一条；
  匿名来源的键只到「IP + 动作 + 状态码」，每次换路径换不出新键(第一条带当时的路径作样本)；每个来源每分钟
  另有条数上限(会话 20 条、匿名 IP 5 条)，全部匿名来源合计每分钟最多 120 条，挡住换 IP 的分布式刷写。
  窗口到点整体换新，刷键不会把常用键的窗口提前清掉。已登录用户的业务失败照常逐条记录。
- 失败的写请求：只有已经独立提交了失败类显式事件(如登录失败)才不再补一条；先写了成功类事件(如导出开始前的
  导出记录)随后失败的，照样补一条失败的语义事件。
- 详情查看按(操作人, 对象, 会话)30 分钟去重，页面静默刷新不再被记成人工查看。
- 删除 `AuditNoisePolicy` 手工路径清单。

### 3.5 业务事实不读审计(V672)

销售订单、出货单、生产计划加 `approved_at`、`reversed_at`、`reversed_by`，出货单另加仓库驳回的
`rejected_at`、`rejected_by`，由审核/红冲/驳回命令在同一事务写入；`SalesOrderTimelineService` 改读列。
代码事实：三类单据的状态 -1 是红冲(STATUS_REVERSED)，不是驳回，所以列名用 reversed_*；「驳回」只在出货单的
仓库驳回上存在。`ArchitectureBoundaryTest` 新规则：除审计包与清空业务数据回执外禁止 `FROM/JOIN audit_log`。

### 3.6 按月分区、只追加、留存可证(V671)

- `audit_log`、`audit_log_archive` 为按北京时间月 `RANGE(created_at)` 分区的同形表，主键 `(id, created_at)`；
  索引只留 `(created_at, id)`、`(target_type, target_id)`、`(request_id)`、`(session_id, created_at, id)`、`(actor_id, created_at)`。
- 行级守卫拒绝 UPDATE/DELETE，语句级守卫拒绝 TRUNCATE(父表与每个月分区)；运行账号只有 SELECT/INSERT，
  月分区对运行账号不授权(只经父表访问)；生产加固脚本在通用授权后调用 `fn_audit_seal_privileges('uten')`。
- 留存由 `fn_audit_retention_run()`(SECURITY DEFINER，表所有者)执行：保留期直接读系统设置
  audit_hot_retention_months / audit_archive_retention_months(默认 6/30 个月，范围 1-120 / 0-240)；整月早于在线截止点的
  分区 DETACH 后改名 ATTACH 到归档，整月早于最终截止点的归档分区 DROP；预建之后 3 个月的在线分区；同一事务写一条
  `event_source='system'、action='audit_retention_completed'` 事件(截止点、分区名、行数、设置值与实际生效值)。
  按整月处理，实际最多多留不到一个月。
- 法定下限：运行账号对系统设置有写权限，被攻破的应用可以先把两项设置改小再调用留存函数。函数因此自带常量下限
  「在线 + 归档合计不少于 6 个月」(《网络安全法》第二十一条：网络日志留存不少于六个月)，设置合计不足 6 个月时按
  6 个月删除，完成事件记 `floor_applied=true`；下限只有表所有者改函数才能动。运行账号最多能让 6 个月以前的记录
  按设置提前清理，6 个月内的审计动不了；设置本身的改动由系统设置的行级审计留痕。
- 锁：留存先做全部整表扫描(计行数；给待移分区补上与月界一致的 CHECK 并校验，只占旧月分区上的共享类锁)，再集中做
  DETACH/改名/ATTACH/DROP，ATTACH 靠已校验的 CHECK 免扫描，独占在线父表期间只剩元数据操作。留存函数与建分区函数
  都带 `lock_timeout = 5s`：有长事务占着审计表时最多等 5 秒就整次放弃(事务回滚、次日重试)，业务写入不会排在它后面
  长时间等待。
- `AuditPartitionMaintainer` 在启动时和每天预建当月及之后 3 个月的在线分区，不跟留存开关走(不设兜底分区，
  写到没有分区的月份会让整条业务事务失败)。与其他调度任务一样只在本地主实例运行，云端实例不跑(ADR-031)。
- 留存失败写 `audit_retention_failed` 事件并把异常抛给调度器；服务器状态页「审计日志归档」行显示最近一次成功时间。
  告警只看审计表里的持久成功记录，不看本次启动后内存里有没有跑过：最近一次成功超过 26 小时，或从没成功过而服务已
  运行超过 26 小时，都告警；本机没有排上这个任务(被关闭或配置有误)时补一行说明照样告警。云端实例不负责归档，不告警。
- 删除人工应急归档 SQL 脚本；确需立即执行由维护人员以表所有者身份调用同一个函数。

### 3.7 账号脱敏与模拟身份(security-10/12)

- `actor_account` 只存保留后 4 位的脱敏值(`AuditAccountMask` 与 `fn_audit_mask_account` 同一口径)；未认证的输入
  不像号码时不落库；V671 迁表时一次性脱敏历史行。
- 读取侧同一口径：审计页按 actor_id 解析人员档案时，`AuditActorDirectory.ActorProfile` 在构造时就把登录账号脱敏，
  列表、详情、导出文件的「操作人」列与人员选择器都只显示「姓名(*******1111)」；按完整号码或后 4 位搜索人员仍在库里
  匹配原值。
- 请求内的所有审计事件一律取已通过认证的真实操作人；模拟身份期间记在发起模拟的管理员名下，新列 `on_behalf_of`
  标注被模拟的账号(`JwtAuthFilter` 绑定)。调用方传入的操作人只用于认证前的登录类事件，存量调用点不需要逐个改。

### 3.8 遗留导入与 production_plan_costs(V673)

- `migrate.sh` 的导入事务都 `SET LOCAL app.legacy_import='on'`，每次运行(成功或失败)只写一条 `legacy_migration_run`
  汇总事件(运行号、映射版本、最终状态、退出码、对账状态、各表行数)，结果取运行的最终状态：全量导入在同一事务里
  标成功之后写；单模块导入与失败的运行由收尾的 `finish_run` 在状态定下来之后写；同一运行号只写一条。
  正确性由对账脚本负责。
- `production_plan_costs` 改普通单表：主键 `(id)`、老系统编号唯一、父子自引用外键；索引只留反查用的部分覆盖索引
  `(goods_id, bill_date, master_goods_id, bill_item_id) INCLUDE (dqty, qty, pdraw_qty, owdraw_qty) WHERE is_deleted=false AND node_class=0 AND master_goods_id IS NOT NULL`
  (比审计建议的 `(goods_id, node_class, bill_date)` 更贴查询：node_class 已在部分条件里)与外键检查所需的几条；
  语句级守卫只允许遗留导入会话写入，清空业务数据走 TRUNCATE 不受影响。

## 四、不做什么

- 不为缺操作人列的只追加子行补 created_by：这些行都经父行(事件/批次/修订头)追溯到操作人。
- 不做匿名 401/403/429 的内存聚合计数行：匿名按「IP + 动作 + 状态码」每分钟一条、来源与全局每分钟上限 + 过期令牌
  不记 + 不再双写，已把写放大压到有上限(1000 次换路径的匿名请求只落 1 行)；聚合计数行要额外的定时落库，
  重启会丢计数，且会丢掉「第一次出现」的时间与请求号。
- 不改权限变更差异事件(授予/收回清单)与账号锁定/停用事件：分别归权限工作流与安全工作流。
- 不回填历史审计格式：未上线，历史行照原样搬进分区表(只脱敏账号)。
