# V504：价值与来源改量事实清空策略

日期：2026-09-07。状态：本地源码候选，等待完整真实数据库清空回归；未清空服务器。

V500 新增8张存货价值表，V503 新增3张来源改量事实表，都属于业务事实。清空测试业务时必须与物理库存、原订单及来源分配一起清空，不能留下无来源价值或改量残账。

本迁移只前向扩展既有 `business_data_reset()` 的表分类：通过已知的库存流水分类锚点一次插入11行 `CLEAR`，校验各来源表存在且尚未分类。找不到唯一锚点、表缺失或已有冲突分类时回滚，不改已应用 V500 或 V464 的字节。

停机脚本 `server/ops/reset_business_data.sql` 同步这11张表；旧版库按实际版本判断表族应为0/8和0/3，缺一张、提前出现或未知表均拒绝。V505目录的总分类为337张父表，业务清空241张，保留96张。基础资料、组织权限、审计记录、迁移证据继续保留；应用内清空成功后的全员重新登录机制继续有效。

新增价值表：`stock_value_pools`、`stock_value_events`、`stock_value_nodes`、`stock_value_edges`、`stock_value_jobs`、`stock_value_tasks`、`stock_value_node_revisions`、`stock_value_postings`。

新增改量表：`procurement_order_source_revisions`、`procurement_order_source_revision_allocations`、`procurement_order_source_revision_peg_changes`。

源码契约逐表比较应用函数与停机脚本；真实PG回归还保留待核旧价值池和对应非零物理库存，验证一起清空而货品、仓库主档保留。执行结果记录在[本地审计验收](../99-项目治理/2026-09-07-全平台本地审计与整改验收.md)，不能把源码清单当作服务器已清空。
