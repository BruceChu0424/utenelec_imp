## 一、设计原则

| 原则 | 说明 |
|---|---|
| 纵深防御 | 前端校验只是体验，**后端才是真相**；前端永不信任输入 |
| 最小权限 | 默认拒绝，按需授予；导出/配置等敏感操作用**独立权限点** |
| 前端不可信 | 前端隐藏只是体验，绕过前端直调 API 必被后端拒 |
| 配置外置 | 密钥/URL 走 `.env` / 环境变量；运行时策略阈值走系统设置页 |
| 审计可追溯 | 关键操作（登录/改密/导出/配置变更/数据变更）全过审计 |
| OWASP 对齐 | 对 OWASP Top 10 每条有明确应对（§七） |

## 二、当前实现状态（真实，非 Mock）

- **后端**：Spring Boot 3 + PostgreSQL + Flyway。Argon2id 密码哈希、JWT（access 15 分 + refresh 7 天，TTL 可配）、pgcrypto 字段加密（PII）、AFTER 触发器审计、部门权限 + 个人覆盖 + 按权限点脱敏。
- **前端**：Riverpod + go_router + Dio。`sessionProvider` 管登录态、`AuthInterceptor` 自动加 token + 401 静默刷新、`flutter_secure_storage` 存 token、路由守卫 `permission_by_path` 按权限点显隐。
- **业务模块**（工资/报销/通知/建议/生产/采购/销售/委外/仓库/钱流/基础资料）均已接真实后端，不再 Mock。

## 三、前端安全落地项

### 3.1 路由守卫 + 权限显隐

未登录跳登录页；受保护页按 `permission_by_path.requiredAnyPermFor(location)` 守卫。
菜单/卡片按权限点 `hide`（**不是 disable**——disable 反而暴露攻击面，吸引探测）。

### 3.2 输入校验（前端体验 + 后端权威）

所有表单 `UtenInput` 带 validator（必填/长度/格式/范围）。**前端校验只是体验，后端必须独立再校验**——攻击者绕过前端直打 API。

### 3.3 敏感数据存储分级

| 数据 | 存储 |
|---|---|
| 偏好（主题/语言/字号） | `shared_preferences` |
| **token / refresh / 密码** | **`flutter_secure_storage`**（iOS Keychain / Android Keystore） |

🚫 **禁止 token 存 `shared_preferences`**——Android 是明文 XML，可被备份/逆向。

### 3.4 配置外置

API base URL / 密钥 / 第三方 AK **禁止硬编码**，走 `.env`（且 `.env` 不进 git）。
运行时策略阈值（限流/锁定/令牌 TTL/导出上限/会话空闲超时等）走**系统设置页**（见 §五）。

### 3.5 密码框规范

`UtenInput(type: UtenInputType.password)`：默认 `obscureText: true` + 小眼睛切换；登录页 `autofillHints: [AutofillHints.password]`；validator 校验长度/强度。

### 3.6 错误处理（不暴露后端细节）

统一 `ApiException` → `context.appError(message)`。🚫 禁止把 status code / stack / SQL 报错直接吐给用户（OWASP 信息泄露）。

## 四、后端安全实现（已落地）

| 项 | 实现 |
|---|---|
| 密码 | Argon2id（防 GPU 暴力）；改密禁止复用最近 N 个（`password_history_size` 可配） |
| 登录 | 错误计数 + 锁定（`lockout_threshold`/`lockout_minutes` 可配）；登录限流 per-IP（Bucket4j） |
| 令牌 | JWT access（15 分可配）+ refresh（7 天可配）；`JwtAuthFilter` 逐请求查用户状态（锁定/停用立即 401，关闭残留 token 窗口） |
| 字段加密 | pgcrypto（PII 如身份证/手机）+ HMAC（身份证查重）；密钥走 env/Vault，版本化支持轮换 |
| 审计 | AFTER 触发器（数据变更，V22/V23）+ `AuditService.logExplicit`（导出/登录/改密/改配置）；超管审计页可查 |
| 权限 | 部门权限 + 个人覆盖 + 按权限点脱敏（角色体系已下线，ADR-011） |
| 限流 | 登录 per-IP + 导出 per-user（Bucket4j，阈值可配） |
| prod | 关 swagger；HTTPS（反向代理终结 TLS） |

## 五、数据导出与高危配置（强制规范，2026-07-27）

详见 [../05-架构/安全策略.md §十](../05-架构/安全策略.md)。要点（新增导出/配置功能必须照此）：

- **数据导出五防线**：① 独立 `*:export` 权限（不复用 view）② Bucket4j 限流 ③ Agile AES-256 加密（密码 body）④ 行数上限 ⑤ 审计。
- **系统设置（高危配置）五防线**：① 路由守卫 `/admin/`（user:manage）② `@PreAuthorize` ③ **二次密码确认**（防 token 被盗篡改策略）④ 审计 ⑤ 类型校验；只放运行时可配阈值，密钥/部署类走 env。
- **隐藏元数据**：列 key 以 `__` 开头（如 `__srcId`）= 隐藏列，execute 过滤不渲染但 row 携带。

## 六、权限模型（现行：部门 + 个人覆盖）

> 2026-07-24 角色体系下线（ADR-011）。现行 = **全员基础（employee 包） ∪ 部门配置（含上级部门） ± 个人覆盖**，超管全量。

- **权限点**：按功能粒度，如 `employee:view` / `payroll:view` / `purchase_report:export` / `user:manage`。
- **部门 → 权限**：部门配置权限集（含继承上级部门）。
- **用户覆盖**：个人级增减（临时授权/回收）。
- **脱敏**：按权限点（`employee:pii:view` / `employee:compensation:view`）。
- 前端：`sessionProvider.user.permissions` + `permission_by_path` 显隐；后端：每个 API `@PreAuthorize` 独立校验。

## 七、OWASP Top 10（2021）对照

| # | 类别 | 应对 |
|---|---|---|
| A01 | 访问控制失效 | 部门权限 + 个人覆盖 + 前端 hide + **后端每 API @PreAuthorize** |
| A02 | 加密失效 | HTTPS + token 走 secure_storage + pgcrypto 字段加密 + 导出 AES-256 |
| A03 | 注入 | JPA 参数化 + 报表 sort/facet **白名单**（防 SQL 注入）+ 前端输入校验 |
| A04 | 不安全设计 | 敏感操作独立权限 + 二次密码 + 审计 + 幂等 |
| A05 | 安全配置错误 | `.env` 不进 git；密钥外置；prod 关 swagger / 开 HTTPS |
| A06 | 脆弱组件 | 定期 review 依赖 + CVE 关注 |
| A07 | 认证失败 | Argon2id + 错误锁定 + 限流 + token 续期 + 会话空闲超时 |
| A08 | 完整性失效 | JWT 签名校验 + 后端不信任前端输入 |
| A09 | 日志监控不足 | 触发器审计 + 显式审计（导出/配置/登录） |
| A10 | SSRF | 后端 URL 白名单 |

## 八、禁忌

🚫 硬编码密钥/URL/API key 到代码（走 `.env`）。
🚫 token/密码存 `shared_preferences`（必须 secure_storage）。
🚫 用 `disable` 代替 `hide` 表达无权限。
🚫 后端错误细节（stack/code/SQL）直接吐给用户。
🚫 数据导出复用 `:view` 权限（必须独立 `:export`）。
🚫 高危配置改设置无二次密码确认。
🚫 密钥/部署类配置进系统设置页（只放运行时阈值）。
🚫 明文 HTTP（必须 HTTPS）。
🚫 前端跳过后端校验允许写操作。
🚫 日志含 token/密码（即使开发期）。
