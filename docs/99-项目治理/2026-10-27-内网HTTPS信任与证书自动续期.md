# 内网 HTTPS 信任与证书自动续期

> 后续兼容性修正：首次上线的签发者包含 IP nameConstraints，虽 Windows 原生链和 OpenSSL 通过，但已发布 Dart 桌面版不支持该类型，导致登录被 TLS 阻断。已保持同一根和密钥，改用 DNS-only 约束签发者并重签叶子；Windows 桌面用户已确认恢复登录。以下保留首轮实施事实，当前策略与最终证据以 [Windows 桌面证书兼容修复](2026-10-27-Windows桌面证书兼容修复.md)及 [LAN_TLS](../../deploy/simple/LAN_TLS.zh-CN.md) 为准。

## 结果与边界

已在公司内部服务器实际启用内网证书自动续期，并在当前运维电脑的当前 Windows 用户证书库安装公司公开根。新证书 Windows 原生 X509Chain 验证通过，真实服务端 TLS 指纹与本地验证证书一致；服务器首页、readiness 和证书安装包均为 HTTPS 200，普通 HTTP 业务请求 308 到 HTTPS。

本次是 TLS 运维变更，不是应用版本发布，也不是全系统安全审计。其他员工电脑或其他 Windows 用户的根信任不能由服务器替其安装，首次须通过可信渠道取得安装包并运行一次。没有绕过浏览器 TLS 警告、降低证书校验或发布本地测试客户端。业务进程未重启，数据库未修改；当前业务进程 PID 在验收前后保持 365596。

## 根因与变更

原叶子证书有效至 2028-12-05、SAN 包含内网地址且公司根签名验证正常，因此不是过期问题。当前电脑两处 Root 库最初没有公司根，安装后原生信任链完整通过。现场原 HTTP 入口全站跳转 HTTPS，同时 HTTPS 缺少根证书下载路径，导致旧员工初始化脚本无法完成安全引导。

1. 保留公司根及原叶子私钥，初始化五年受限 LAN 签发者，只允许审核的三个 DNS 与一个 IPv4 /32，critical CA TRUE、pathlen:0、critical nameConstraints。根私钥未导出；自动服务通过 InaccessiblePaths 隔离根私钥。
2. `host/uten-lan-tls-renew.py` 成为唯一内网续期入口。每日检查、30 天门限、365 天叶子、原子安装、Nginx 校验、平滑 reload、真实 TLS 检查及失败回滚；中止后普通检查可恢复已安装但未加载的证书，SIGTERM 进入回滚。根或签发者不足 400 天告警，需受控更新签发者。
3. 实际签发时间 UTC `2026-10-27T07:29:29Z`，新叶子到期 UTC `2027-10-27T07:29:29Z`，SHA-256 `F23852E6902EB719C64E1C39D64207B8FC4B13810E5FB73ECF2CA649884F9E85`。签发者到期 `2031-10-26T07:23:37Z`，公司根到期 `2036-08-30T03:36:36Z`。
4. 正式 timer 已 enabled/active，服务器当地时间 03:45 后随机最多 30 分钟执行，Persistent 补跑；首个预定时间为 `2026-10-28 03:52:21 +08:00`。正常 service 命令不带 force，Result success/ExecMainStatus 0；临时强制覆盖已删除。
5. 员工 BAT/PS1 默认当前用户信任、无需管理员、不改 hosts，先验证独立 DER SHA-256，再入库；同目录公有根优先。HTTP 只公开精确公有根路径，其他业务仍跳 HTTPS；HTTPS 另外提供精确根及 ZIP，保留原办公网段 ACL。

根私钥的离线托管沿用 RUNBOOK 9.3；本次发现原私钥仍在服务器 root0600，未验证离线托管前不作删除，自动续期服务不依赖该私钥。新增签发者密钥仍只留公司服务器 root-only 目录，受控恢复托管需包含新增材料。

## 实际验证

- 正式 systemd 沙箱实际强制签发、安装、Nginx 校验及 reload 成功；随后正常检查和 check-only 成功。
- 首次受限演练因 Nginx 配置校验需低端口 bind 权限失败，旧证书恢复且网站持续正常；补足 CAP_NET_BIND_SERVICE 后完整重跑成功。CAP_DAC_OVERRIDE 供现有 www-data:adm 0640 日志校验，其他隔离保持，未以普通跳过续签作为签发验收。
- 16 项真实 OpenSSL 隔离续期回归通过，覆盖约束/根/SAN/门限/私钥保留/回滚/中断恢复/只读检查/未渲染地址拒绝；21 项原 systemd/host 契约通过。
- Windows PowerShell 5.1 的 11 项员工根证书纯校验通过；当前用户实际安装及重复运行通过；真实新叶子经 Windows 原生信任链验证，无链错误。

- 根证书 HTTP 200、安装包 HTTPS 200、主页 HTTPS 200、普通 HTTP 308、readiness UP；Nginx 和业务服务均 active。
