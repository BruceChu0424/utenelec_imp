# 通知同类叠放与卡片重设计

## 范围与设计方案

使用 `frontend-design`。本次属于前端呈现及展示分组：Web、Flutter 桌面和移动端共用通知模型与卡片；服务端的投递、业务聚合、权限、收到、已读和办结规则保持各自权威。

配色从既有主题取得：底面 `surface`（默认 #FFFFFF）、页面 #F5F7FA、主文字 #0F172A、辅助文字 #475569、边框 #E2E8F0、交互青绿 #0F766E；通知类别和紧急程度沿用现有语义色。Noto Sans SC 不变，标题使用主题 titleMedium / 600–700，正文与来源使用 bodySmall，数量和动作使用 label。

布局左对齐：

```text
┌ 类型图标  类型／必要状态                  未读 ┐
│ 标题                                          │
│ 正文摘要                                      │
│ 发布者                    时间                │
├───────────────────────────────────────────────┤
│ 叠层图标  共 N 条 · N 未读              展开   │
└───────────────────────────────────────────────┘
  └───────────────────────────────────────────┘
    └───────────────────────────────────────┘
```

单卡底部按原业务显示收到／祝福；组卡只显示组数量，进入已有展开舞台后逐条查看。只有多条才画底卡，底卡不接收点击或读屏焦点。卡面、组顶卡、组内卡统一调用 `NoticeCard`，中性表面复用 `UtenCard`；保留 Uten 圆角、间距、减少动画与键盘能力。用户最后确认阴影可以保留但须美观：顶卡采用极轻的中性贴边阴影并跟随卡片圆角，去掉彩色光晕和大片散影；底卡只靠细边框与错位底边分层。

设计自检：原方案大面积粉蓝渐变、同色光晕、重复紧急标识及两处数量分散注意力。新方案把颜色集中于类型与必要状态，只在真实存在多条通知时使用错位底卡；不增加分类副标题或独立提示行。

## 调用与迁移清单

| 入口 | 本次处理 |
|---|---|
| `noticeGroupKeyOf` / `groupNotices` | 保留业务对象优先；无业务对象的系统／运维重复主题增加稳定分组，不混并告急／恢复或不同版本 |
| 通知列表单卡 / `NoticeStackCard` 顶卡 | 同一 `NoticeCard` 中性卡面；底卡与数量表示真实条数 |
| `showNoticeGroupDialog` 展开卡 | 共用新卡面；保持逐条详情、收到、已读与业务跳转语义 |
| `UtenCard` 公共阴影 | 原阴影装饰缺少圆角，圆卡四角出现方形灰影；阴影统一跟随既有卡片半径，不修改其他调用方的阴影级别 |
| Web / Flutter Windows、移动 | 共用上述 Dart 入口；响应式与暗色验证见验收记录 |
| Win7 WPF 通知列表／详情 | 当前尚未迁移；对应 W7-BIZ-084/085 保留 todo，不能据本次 Flutter 改版标完成 |
