# V580 销售订单来源顶层行超量：公共备货计划单的对账放宽

- 迁移：`V580__sales_top_public_surplus_plan_link.sql`
- 类型：前向，只替换触发器函数体。**不加表、不加列、不改历史行。**
- 相关：[V577 下达车间超量与公共备货产出](169-V577下达车间超量与公共备货产出.md)、
  [ADR-081 §7.3 / §八](../99-决策记录-ADR/ADR-081-下层一键办齐与物料表身份列统一.md)

## 为什么要有它

V577 让下达车间可以超出剩余需求，超出部分记 `public_surplus_qty`。对**销售订单来源的
顶层行**，ADR-081 §7.3 的记账方式是把一次下达拆成两张计划单：

| 单 | 数量 | link 记账 | 计划明细的销售来源 |
|---|---|---|---|
| A 订单行 | 订单未满足量 | `submitted_qty = N` / `public_surplus_qty = 0` | 带 `sales_order_item_id` |
| B 公共备货行 | 超出的量 | `submitted_qty = 0` / `public_surplus_qty = M` | **不带**（带了会破坏销售守恒） |

但 V577 当时只改了对账触发器里的数量那一项
（`pi.qty = NEW.submitted_qty` → `+ COALESCE(NEW.public_surplus_qty, 0)`），
**漏了同一个 `EXISTS` 里的销售关联等式**：

```sql
AND pi.sales_order_item_id IS NOT DISTINCT FROM ai.sales_order_item_id
```

单 B 的明细按设计不带销售来源，而它挂的 `analysis_item` 正是那条销售来源顶层行，
等式恒假 → `EXISTS` 落空 → `RAISE 'analysis demand, plan item and submitted quantity differ'`。

结果：**销售订单来源的产品填超量下达车间 100% 失败**。非销售来源不受影响——两侧的
`sales_order_item_id` 都是 NULL，等式自然成立，所以这个洞一直没被非销售路径暴露出来。

复现：`MaterialWorkshopAnchorEndToEndTest#salesTopOverQuantitySplitsIntoOrderPlanAndPublicSurplusPlan`
（该用例自 V577 合入起就是红的；它被 `UTEN_RUN_DB_TESTS` 门控，不设环境变量时整批 SKIP，
所以 CI 与本地常规 `mvn test` 都看不到，属「假绿」——见 [[local-cloud-single-primary-deployment]] 的同名坑）。

## 改了什么

只把那一项放宽，且范围收到最窄：

```sql
AND (pi.sales_order_item_id IS NOT DISTINCT FROM ai.sales_order_item_id
     OR (COALESCE(NEW.submitted_qty, 0) = 0
         AND COALESCE(NEW.public_surplus_qty, 0) > 0
         AND pi.sales_order_item_id IS NULL))
```

即：**只有纯公共备货的 link**（归本需求量为 0、公共备货量为正）才允许它的计划明细
不带销售来源。带需求的 link 一个字节不变；货品 / 颜色 / 单位 / 换算率 / 单行形状
四条对账全部原样保留。

写法沿用 V577 的「形状断言 + 字符串替换 + 失败即抛」：锚点不在、或 V577 的数量对账
没打过，直接 `RAISE` 关闭，绝不盲改函数体。

## 数据影响

无。历史 link 行既不重算也不回填；已有的销售分摊守恒
（`production_plan_sales_allocations` 的「分摊合计 = 计划数量」与「排产量 ≤ 订单未满足」）
不在本次改动范围内，V234/V478 两条需求守恒同样不碰。

## 2026-09-15 前向说明（V588）

V588 起销售顶层行超量不再拆两张计划（一张计划 + link 分账，销售分摊只认
`submitted_qty`），本迁移的放宽对**历史已拆的纯公共备货 link** 继续生效，不再有新行
走该形态。`ProductionPlanService.validateAnalysisLink` 的 `pureSurplusLink` 兼容分支为
历史行保留。
