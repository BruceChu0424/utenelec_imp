## 一、用户口径(2026-10-04)

> 委外的流程跟自制的流程一样，不去判断子层的数量多少去分类。委外也作为一道加工工序，只领自己的直属物料；下层按各自路线准备，能够配出一批就领一批，同一委外任务持续领料、分批回厂。

委外件 P = 我们把 P 的直属物料发给委外商，委外商加工、组装后交回 P。与车间自制同构：

| 车间自制 | 委外 |
|---|---|
| 车间任务只领本产品的直属子件 | 委外任务(委外订货单明细)只领 P 的直属物料 |
| 下层子件按各自路线先做好、入库 | 同左：A 要自制就先用 A 自己的下层生产 A，B 要采购就采购 B，C 是委外件就先走 C 自己的委外任务 |
| 齐套可生产 N 个 → 通知车间去领料 | 齐套可配 N 套 → 通知委外人员「可领 N 个(P 的订货单位)」 |
| 车间提交领料 → 仓库发料 | 委外人员核对本次数量、提交领料 → 仓库发出 A、B |
| 报工 → FQC → 成品入库 → 父层解锁 | 委外商交回 P → 回厂登记 → 来料质检 → 仓库实际入库 → P 的上层解锁 |
| 持续生产：后续到货继续领 | 同一委外任务后续 A、B 到货继续领，分批回厂 |

不用等整棵树全部做完，也不用先在厂内做出 P。下层每到一批，就按实际配套能力推进上一层。

## 二、所有情况

1. **直属物料有多种且同一层级(A、B、C)。** 每种物料一条领料计划行，按「短板」算齐套：只有每一种必需物料都能覆盖的套数才可领。
2. **直属物料只有一种。** 同一流程，计划行只有一条。不再有「唯一子件」特殊路线。
3. **没有可发外的直属物料(无 BOM，或直属边全部不属于 §二.19 的可发外边)。** 委外件必须先有 BOM 才能往下走(用户 2026-10-04 两次拍板：「提示他们去完善 BOM 表，通知研发的人去完善」「没有完善，计划那边就不能给这个物料下单；研发一弄完，计划部的物料分析就自动更新组件表」)：
   - **计划(物料分析)**：委外节点缺 BOM 时该行显示「缺 BOM·已通知研发」，不能下达(下达委外的勾选框不可勾，服务端下达同样拒绝并说明原因)。分析新建或刷新发现缺 BOM 时，系统自动给工程研发部建一条「完善 BOM」研发任务(同一货品只建一条，后来发现的计划员加入等待名单)并通知研发。
   - **研发完善后自动更新**：研发保存 BOM 后，研发任务自动完成；系统自动刷新所有含这个委外件、仍未结束的物料分析(组件表按新 BOM 重新展开出直属物料节点)，并通知等待名单里的计划员「BOM 已完善，物料分析已自动更新，可以下达」。
   - **每张分析一条刷新事件(2026-10-04 复核)**：BOM 更新事件投递时不直接刷新分析，只给每张含这个委外节点、还没按新 BOM 展开、仍未结束(负责人账号有效)的物料分析各排一条刷新事件 `MATERIAL_ANALYSIS_BOM_REFRESH`(载荷带等这张分析的人)。该事件投递时以分析负责人身份、在独立事务里只刷新这一张；刷新失败原样抛出，按事件队列退避重试，不影响其它分析与 BOM 事件本身(不再「失败只记日志」)。等这张分析的人在它刷新完之后才收到「物料分析已自动更新，可以下达」；不能自动刷新(分析已结束、已删除、不再含该节点、负责人账号不可用)时改收「打开物料分析刷新后即可下达」。等委外订货单、委外申请、生产计划的人立即收到「BOM 已完善，可以继续下达 / 下委外单」，文案不说物料分析已更新。
   - **委外订货兜底**：委外任务中心的申请行缺 BOM 时显示「缺 BOM·已通知研发」、不能生成订货单；手工委外订货单可以保存草稿，提交财务时拒绝并提示「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」(同时加入研发等待名单)；财务批准时再兜底检查一次。研发任务若被取消而 BOM 仍缺，行上提供「通知研发完善」重新提醒。
   - **旧/手工生产计划兜底(2026-10-04 复核)**：生产计划确认执行计划包按缺口生成委外申请前同样检查，缺 BOM 时确认被拒(409「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」)，确认人加入等待名单(来源 = 生产计划单号)。
4. **直属物料本身有下层(A 要自制)。** A 走自己的路线(物料分析把 A 作为需求节点下达车间)，A 完工 FQC 入库后才算 P 的可用物料。系统不再为 P 在厂内建「前置自制」任务。
5. **直属物料本身也是委外件(嵌套委外，C)。** C 有自己的委外任务，按本 ADR 领 C 的直属物料、回厂入库；C 合格入库后计入 P 的齐套。层数不限。
6. **直属物料要采购(B)。** 采购到货、来料质检合格、仓库实际入库后计入齐套。
7. **部分到货。** 能配多少套就通知多少套；后续再到货，可领量增加就再提醒。
8. **多次领料。** 同一委外任务可以反复提交领料，直到领满订货量。
9. **仓库少发某一种。** 本批应发 A 40、B 80，仓库实际只发 B 60：之后的可领量按「已发齐的完整套数」重新算，下次领料先补齐落后的 B(再发 20)，不会多发领先的 A。发料通知写明「少发：B 20，下次领料自动补齐」。
10. **撤回领料。** 仓库发出之前，委外人员可按订货明细撤回未发出的领料，预留与专属归属原样退回，并通知仓库。仓库已保存拣货修改的草稿不能撤回(409，提示先与仓库确认)。
11. **分批回厂。** 委外商分批交回 P，可回厂量按委外商手里「能做成 P 的完整套数」算(§三.6)，每批回厂按目标量逐种核销委外商处物料(§三.7)。
12. **回厂超过已发齐的套数。** 多出来的部分用的是委外商自己的材料，照 ADR-101 §2.8 进财务超量审批(ADR-019)，财务批准的自带料份额不计入物料守恒核销，并且这部分不再需要我方物料：可领、还缺与「料已发完」按我方供料套数 Qm(§三.4a)算，不再按订货量补发。
13. **短交与损耗。** ADR-098/114 不变：订货量不改，接受损耗独立结清。「料没发完不判短交」的「发完」= 每一种直属物料的已发净量达到我方需发量 `needed_i = LEAST(planned_i, f_i(Qm))`(§三.4a；没有自带料时就是计划量)，或该物料已结束领料。整单结损耗时把委外商处剩余结存全部记损耗，不按短交量×单耗重算(避免 0.0001 尾差)。
14. **订货改量(批准后)。** 每条物料计划行按新订货量重算：计划量 = f_i(新订货量)(§三.2)，不做增量累加。缩量下限 = MAX(各物料已覆盖量反算的最小订货量、委外商处结存反算、已回厂下限)；已提交未发的领料必须先撤回(409 列出这些领料)。
15. **结束领料。** 委外商做不完或物料停用，委外人员可在任务详情「结束领料(不再发外)」并填写原因：撤回未发领料、释放预留、关闭该明细的领料计划行，触发短交重评(ADR-101 §2.5)。仓库侧原「不再出仓」按钮删除。
16. **多个委外任务抢同一批公共物料。** 列表与通知各自按当时可用量计算；同一次批量领料在预览时按「交期、订货单号、行号」顺序联合分配共享物料，默认值就是联合分配后的本批可领量；提交时在锁内按同一顺序重算，实时结果低于提交量才 409，并逐行返回实时可领量供一键回填。
17. **物料分析的委外节点。** 委外节点(任何层级，包括顶层产品、中间层、公共超量、汇总下单)一律下达为委外申请，不再有「下达车间先做委外件」。委外节点的直属物料照常展开为需求节点，按各自路线下达。
18. **手工直接下的委外订货单(无分析来源)。** 只能领公共库存；缺的物料在任务详情显示「还缺」与「供应来源：未安排」，状态为「等计划安排」。系统不再自动建「委外前置自制」分析。(2026-10-05 修订，ADR-156：手工单下单本身也要公共库存够做才放行，建单、保存、送审、批准都核对直属物料齐套，见 ADR-156 §六.12。)
19. **可发外的直属边。** 只有「按件用量(PER_UNIT)、生产投入阶段(START/ASSEMBLY/FINISH)、按单领料(非 PERIODIC)、用量 > 0、非系统占位」的直属边才发给委外商。按包装 / 固定批量、出货阶段、整批领料(PERIODIC)的边不发外。2026-10-04 实库 4014 条委外直属边全部是 START/PER_UNIT/ORDER。判定只有一个 SQL 函数 `fn_subcontract_draw_edges(goods)`，计划冻结、分析展开与内部在途判定、可用量与精确归属都只用它。
20. **委外商退回我方材料(材料退货)。** 退料审核减少该物料「已发净量」，退回的料重新入库后可再次领料；退料红冲把已发净量加回(若这些料已被重新领出导致超计划量则 409)。订货明细已结清(合格入库 + 已结损耗 ≥ 订货量)或领料计划已关闭后，余料退回不会让任务重新出现在「领料」里。
21. **BOM 改动。** 领料计划在财务批准时按当时的可发外直属边冻结(物料、解析后颜色、冻结单耗)。批准后 BOM 改动不影响已批准的单：可用量、精确归属、锁维度都按冻结计划行读取，不读现时 BOM；改量只重算已冻结的物料行。
22. **直属物料颜色。** 物料颜色 = COALESCE(BOM 边颜色, 物料默认颜色)，财务批准时与单耗一起冻结；分析节点、可用量、精确归属用同一口径(实库 140 条委外直属边边颜色为空、物料有默认颜色)。

## 三、数量口径(只在服务端算一次)

记订货明细 P 的订货量 `Q`(订货单位)、我方供料套数 `Qm`(§三.4a，没有财务批准的委外商自带料时 `Qm = Q`)，第 i 种物料的冻结计划行：

1. **冻结单耗** `b_i = ROUND(订货单位换算率 × BOM 边用量, 6)`；为 0 时财务批准拒绝并提示。
2. **唯一一对正反函数**：`f_i(S) = CEIL(S × b_i, 4)`(套数 → 物料量)，`sets_i(x) = TRUNC(x / b_i, 4)`(物料量 → 套数)。在 0.0001 网格上 `f_i(S) ≤ x ⟺ S ≤ sets_i(x)`。所有套数结果再取 `LEAST(Q, …)`。计划量 `planned_i = f_i(Q)`。
3. **已发净量** `sent_i` = 已审核发出 − 材料退货(计划行 `issued_qty` 即保存净量，材料退货审核 CAS 扣减、退料红冲 CAS 加回)。**待发量** `pending_i` = 已提交、仓库未发出的领料草稿量。**已覆盖** `covered_i = sent_i + pending_i`。**可用** `avail_i` 见 §三.5。
4. **行级显示量(订货单位)**：
   - 已领 `drawn = LEAST(Qm, MIN_i sets_i(sent_i))`
   - 待仓库发 `pendingSets = LEAST(Qm, MIN_i sets_i(covered_i)) − drawn`
   - 可领 `drawable = MAX(0, LEAST(Qm, MIN_i sets_i(covered_i + avail_i)) − LEAST(Qm, MIN_i sets_i(covered_i)))`
   - 还缺 `Qm − drawn − pendingSets − drawable`
   - 恒等式：已领 + 待仓库发 + 可领 + 还缺 = 我方供料套数 Qm(测试断言；没有委外商自带料时 Qm = 订货数量)。接口同时给订货数量 `orderQty` 与 `materialQty`(= Qm)。
   - 物料级：需求 = 我方需发量 `needed_i = LEAST(planned_i, f_i(Qm))`；已发外 `sent_i`；待仓库发 `pending_i`；仓库可用 `avail_i`；本次可领 `MAX(0, f_i(complete + drawable) − covered_i)`，`complete = LEAST(Qm, MIN_i sets_i(covered_i))`；还缺 `MAX(0, needed_i − covered_i − avail_i)`。还缺 = 0 的物料计为「已备」。
   - 「领满」只按物料判断：每种物料 `covered_i ≥ needed_i`，从不用套数等于 Q 判断。
4a. **委外商自带料与我方供料套数 Qm(2026-10-05)**：回厂超过我方物料能做出来的套数、经财务批准按约定接收的那部分(§二.12，ADR-101 §2.8，V642)用的是委外商自己的材料，不需要我方再发料。记财务批准的自带料 `E` = 已定案接收(RECEIPT_ADJUSTED / RECEIPT_POSTED / CLOSED，APPROVE_ALL / APPROVE_CUSTOM)的到货异常 `approved_excess_qty` 之和(订货单位；收货单红冲后异常转 RETURN_REQUIRED / CANCELED 即不再计入)，则
   - `Qm = LEAST(Q, GREATEST(Q − E, MIN_i sets_i(sent_i), 0))`：扣掉自带料，但不低于已经发出去的完整套数(已发的料不因为后批准的自带料被「收回」)；`E = 0` 时 `Qm = Q`。
   - 可领 / 可达封顶、还缺、恒等式、批量领料联合分配都按 Qm；每种物料的需发量 `needed_i = LEAST(planned_i, f_i(Qm))`，「领满」「料已发完」(§二.13 短交判定、到货追踪容差判定)、领料任务是否还开着都按 needed_i。
   - 冻结计划量 `planned_i = f_i(Q)` 不变：`issued_qty ≤ planned_qty` 硬上限、批准后改量按 f_i(新订货量) 重算、退料红冲上限都照旧；Qm 只收窄「还要发多少」。
   - 例：订 100、已发 60 套，回厂 80 其中 20 为批准的自带料 → Qm = 80，只能再领 20 套；这 20 套发出后即「料已发完」，再到 20 件就到齐。若已发 100 套后回厂 110(自带料 10)，Qm 仍为 100。
   - 只在服务端算一次：`fn_subcontract_supplier_own_qty`(E)、`fn_subcontract_material_qty`(Qm)、`fn_subcontract_draw_needed_qty`(needed_i)，汇总函数与回厂守恒净额上限共用。
5. **本任务可动用量** `avail_i`：作业叶仓(未删、非不良仓、非线边/内料仓)里该物料、该冻结颜色的合格可用量 = 本订货明细来源分析的精确专属批次(ADR-113 交接；顶层委外件的直属物料是来源行 depth=1 节点) + 公共可用量(`v_stock_available`，已扣他人预留)。逐种物料计，A 的库存永远不能放行 B。合并了多张申请的订货明细，精确批次区间按该分析物料下全部在途申请 / 订货明细分摊，不重复认领。
6. **可回厂套数**：委外商处可做成 P 的物料 `usable_i = Σ(at_supplier + compensated − returned − wasted)`(= 已核销 + 结存)；`returnable = LEAST(Q, MIN_i sets_i(usable_i))`。回厂约束(订货单位)：累计物料口径回厂量 ≤ returnable + 财务批准自带料 + 已退回的质检不合格量。已批准的委外订货明细一定有冻结计划行(缺 BOM 的委外件不能下单，见 §二.3)。到货登记、回厂单保存与审核、发料红冲容量、到货任务可见、回厂提醒事实全部用同一段服务端 SQL(删除 `ISSUED_TARGET_BASE_SUM` 加总写法)。
7. **回厂核销(目标跟踪)**：回厂单审核时写入 `material_basis_qty` = 回厂量 − 本单质检补回分配 − 财务批准自带料(之后不随实时状态重算)。`R` = 有效(未红冲)回厂明细的 `material_basis_qty` 之和(订货单位)。每种物料本次核销 `GREATEST(0, f_i(R) − 当前有效核销量_i)`，按发料先进先出(发料日期、创建时间、行号)切片；红冲按记录的切片原样退回，下一次回厂自动纠正尾差。数据库守卫逐种物料校验：核销量 ≤ usable_i，且 `|核销量_i − f_i(R)| ≤ 已红冲回厂行数 × 0.0001`。
8. **成本完整性**：领料制回厂明细在每种冻结物料的核销都达到目标量时即为完整(计价 FINAL)。

### 4.3 仓库委外出仓工作台

一行 = 一张委外人员已提交、仓库未发出的领料草稿(按调用者仓库范围)。拣货页可把某行改少(`qty ≤ requested_qty`，不能改多、不能加行)，改少立即同步释放预留；核对实际仓与库位后审核出仓。删除「补齐出仓单」、「不再出仓」、「等子件到货」黄徽章与 `/tasks/count` 的 `waitingComponent`。出库任务中心「委外出库」红数 = 待发领料草稿张数。

- **填 0 = 本次不发(2026-10-04 复核)**：某种物料这次整行不发，仓库在拣货页把本次数量填 0；保存时该行软删并记 `warehouse_dropped_at`(`qty`、`requested_qty` 原样保留)，预留随之释放。发料回执的「少发」按物料 = (未删行 + 仓库删行)的提交量 − 未删行实发量，下次领料自动补齐(§二.9)。一张草稿至少要发一种物料。
- **「退回委外(不发)」(2026-10-04 复核)**：整张领料实物发不出时，仓库在拣货页填写原因(必填，≤ 200 字)把这张草稿退回委外人员：`POST /api/warehouse/subcontract-outbound/tasks/{issueId}/return-to-draw` `{reason}`，权限 `subcontract_outbound:view + execute`(与拣货审核同一道门)。不论仓库是否改过拣货数量，按撤回领料的锁顺序(§4.2)再锁草稿头与计划行，作废这张草稿的全部领料行与草稿头(不写 `warehouse_dropped_at`)、释放全部未消费占用(专属批次退回原分析)、重算可领，并通知提交领料的委外人员(事件 `SUBCONTRACT_DRAW_RETURNED`，含原因)。只动这一张草稿，同一任务在别的仓的待发领料与领料计划不受影响(不是已删除的「不再出仓」)。这是仓库已改过的草稿的出口：委外人员撤不回它(§二.10)，仓库也不能删单或删光物料行。

### 4.5 物料分析

- 委外节点(任何层级，含顶层与汇总下单)只下达为委外申请；汇总下单的委外批次永远是外部批次(无锚点)，成员 P 节点各自展开直属物料。删除「下达车间先做委外件」、`SUBCONTRACT_MAKE` 锚点与任务台账、委外前置自制分析与 V447 交接。
- P 的未结委外申请(SUPPLY 行动)对「有可发外直属边」的 P 计为内部在途，直属物料不被 P 的在途抵掉；已批准的订货份额以冻结计划行的物料与单耗为准。缺 BOM 的委外节点不能下达(§二.3)。SHARED_FUTURE_CLAIM / FUTURE_TRANSFER 仍为外部。
- 直属物料需求按 P 的计划产出展开：`U = 分摊/申请量 × (申请量 + 公共超量 − 合格入库回厂量)`；顶层委外件的计划产出并入来源行计划产出量。申请 DONE 判定改为 申请量 + 公共超量 ≤ 合格入库回厂量，或订单结清。
- 物料覆盖逐种计：`net_i = 草稿 + 已发净量 − f_i(合格入库回厂量)`(不小于 0)，以 U 对应的物料需求封顶；有精确交接的量归该物料节点本身，其余按来源申请分摊权重分给各 P 节点；超出申请的超额与手工明细不归任何分析。
- 交接给委外领料的专属批次视同已收货(与 `TRANSFERRED_TO_PLAN` 同口径)，避免物料自己的在途被重复计算。
- 物料分析委外行的阶段 / 进度按领料读模型计算：可领料 / 等仓库发料 / 等委外回厂 / 等待物料，质检、入库子状态随回厂单实时显示；进度步骤显示「已领 x/Q」，不再把不同物料的数量相加。
- 委外节点的所有直属物料都用设计用量(合同用量)。

### 4.6 进度展示

委外订货单详情、委外申请进度弹窗、物料分析供给进度统一为一条时间线：下单 → 财务审批 → 领料发外(已领 drawn/Q) → 加工回厂 → 品质检验 → 仓库确认入仓 → 结案核销。物料段复用任务详情的物料表。

**V798 对象清单原则**：PostgreSQL 不跟踪 plpgsql 函数体对列和表的依赖，删列删表会成功但在运行时报错。所以 V798 必须：① 前置检查(旧形态数据存在即拒绝，提示先用 V798 之前的版本做显式测试清空)；② 先删幸存表上读这些列 / 表的触发器(含 `_upd` / `_del` 变体)；③ 用整体重写替换本特性自有的函数，用现时定义锚点补丁(核对命中次数)修改共享函数；④ 删视图、删表、重建 CHECK、删索引、删列、删函数；⑤ 新对象与权限；⑥ 后置扫描：任何 `pg_proc.prosrc` / `pg_views` 仍引用被删对象或列即 RAISE。Java 侧再加一条源码扫描契约测试。

## 六、不变量

1. 每条计划行 `0 ≤ issued_qty(净) ≤ planned_qty`；每种物料 `covered_i ≤ planned_i`。
2. 领料只能在财务批准之后、计划 OPEN、明细未结清时提交；本次数量 ≤ 锁内联合分配后的实时可领量。
3. 仓库实发 ≤ 提交的领料量(`requested_qty`)。
4. 可回厂量按「委外商处可做成 P 的完整套数」，不把各物料折算后相加。
5. 每种物料累计核销与 `f_i(R)` 的差 ≤ 已红冲回厂行数 × 0.0001，且 ≤ usable_i；委外商处结存 ≥ 0。
6. A 的库存、已发量、专属归属永远不能替 B 放行。
7. 下单不受物料库存约束；所有数量只在服务端算。(2026-10-05 修订：前半句由 ADR-156 取代——下单要直属物料齐套，按现有物料够做的套数下单；「所有数量只在服务端算」不变。)

## 七、明确不做

- 不做按包装 / 固定批量的非线性用量发外。
- 不做委外损耗后的补发料(仍按 ADR-098/114 判定短交与独立结清)。
- 不做跨订货单自动分配同一批公共物料(先提交先得；同一次批量领料内按顺序联合分配)。
- 不兼容旧数据：平台未上架。**上线顺序**：先用当前已部署版本做显式测试清空，再激活含 V798 的版本；V798 前置检查发现旧形态数据即拒绝执行。

## 八、验证

- 真库全链 E2E：两种直属物料 A(自制)、B(采购) → A 完工入库、B 到货一半 → 通知可领 → 提交 → 仓库少发 B → 再到货 → 第二次领料自动补齐 B → 分批回厂两次(含红冲中间一批再回厂) → IQC → 入库 → 关单；成本 FINAL。另覆盖：单一物料；缺 BOM 委外件(物料分析不能下达、自动建研发任务、研发保存 BOM 后研发任务完成且物料分析自动刷新出直属物料、手工订货单提交财务被拒)；嵌套委外；顶层委外件含公共超量；两张分析合并成一个订货明细；同一批量领料两任务共享物料默认值成功；撤回；结束领料后短交重评；材料退货后再领；超过可回厂量走财务；改量扩缩(含先撤回)；边颜色为空；行级恒等式；B 部分采购到货后被领走时 B 的在途不虚增。
- 迁移契约：前置检查、被删对象不存在、后置扫描、守卫逐种物料、重置策略与审计清单同步。
- Flutter：「领料」分段、领料页、仓库拣货页只能改少、任务详情物料表、进行中新状态。
