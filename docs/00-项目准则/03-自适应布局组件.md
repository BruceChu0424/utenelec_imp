## 一、"响应式" vs "自适应"

两个词在中文里常混用，本项目严格区分：

| 维度 | 响应式（Responsive） | 自适应（Adaptive） |
|---|---|---|
| 关注点 | **屏幕**尺寸 | **父容器**尺寸 |
| 数据源 | `MediaQuery.sizeOf(context)` / `context.breakpoint` | `LayoutBuilder` 的 `constraints` |
| 适用层级 | 页面级、根 Shell、导航容器 | 组件内部、可复用卡片、嵌套布局 |
| 典型场景 | 切底部 Tab ↔ 侧边 Rail | 卡片网格自动算列数、master-detail 折叠 |
| 详细文档 | [02-响应式与多端适配.md](02-响应式与多端适配.md) | 本文档 |

**一句话记忆**：响应式问"屏幕多大"，自适应问"我爸给我留多大地方"。

## 二、为什么组件内部必须用 LayoutBuilder

### 2.1 ❌ 反例：用 MediaQuery 写组件

```dart
// ❌ 这是一段"看似正确、实则错误"的卡片网格
class BadGrid extends StatelessWidget {
  final List<Widget> children;
  const BadGrid({super.key, required this.children});

  @override
  Widget build(BuildContext context) {
    final width = MediaQuery.of(context).size.width;
    final columns = width < 600 ? 1 : (width < 840 ? 2 : 3);

    return GridView.count(
      crossAxisCount: columns,
      children: children,
    );
  }
}
```

**这个组件会在以下场景失效**：

| 场景 | 实际表现 |
|---|---|
| 放进展开的 `NavigationRail` 右侧 | 屏幕是 1400，但右侧只剩 1100，仍按 1400 算成 3 列 → 溢出 |
| 放进 SplitView 的右半 | 屏幕是 1920，但右侧 master 区只有 600，按 1920 算 3 列 → 挤变形 |
| 放进 Dialog / BottomSheet | 容器只有 320，但屏幕 1280，算成 3 列 → 极度拥挤 |
| Web 上多窗口 / 分屏 | 完全错乱 |

### 2.2 ✅ 正例：用 LayoutBuilder

```dart
// ✅ 根据父容器约束算列数，任何嵌套场景都对
class GoodGrid extends StatelessWidget {
  final List<Widget> children;
  final double minItemWidth;

  const GoodGrid({
    super.key,
    required this.children,
    this.minItemWidth = 180,
  });

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        // 父容器给的宽度
        final available = constraints.maxWidth;
        // 至少每个 item 多宽，再反推列数
        final columns = (available / minItemWidth).floor().clamp(1, 6);

        return GridView.builder(
          gridDelegate: SliverGridDelegateWithFixedCrossAxisCount(
            crossAxisCount: columns,
            crossAxisSpacing: 12,
            mainAxisSpacing: 12,
            childAspectRatio: 1.4,
          ),
          itemCount: children.length,
          itemBuilder: (context, i) => children[i],
        );
      },
    );
  }
}
```

**核心法则**：

> 🚨 **可复用组件内部一律用 `LayoutBuilder`，不读 `MediaQuery.size`。**
> `MediaQuery` 只在根布局（Shell、根 Scaffold）里用一次。

## 三、Uten 自适应布局组件清单

> 📌 以下组件位于 `lib/components/layout/`，实现要严格按本档约定。

| 组件 | 作用 | 何时用 |
|---|---|---|
| `UtenResponsiveContainer` | 按断点返回不同 child | 页面级一次性切布局 |
| `UtenResponsiveGrid` | 基于 `Wrap` 的真瀑布流，按父容器宽度自动算列数 | 卡片墙、工资条/报销/通知/建议卡片列表、相册、KPI 网格 |
| `UtenMasterDetail` | 手机端列表/详情切换，宽屏左右分栏 | 列表-详情类页面（员工、工资条、报销） |
| `UtenTwoPaneLayout` | 左右分栏，比例可配，窄屏折叠为单栏 | 设置页、过滤面板 + 内容 |

### 3.1 UtenResponsiveContainer

按 `Breakpoint` 返回不同的 widget，省去手写 `switch`。

**API 规范**：

```dart
UtenResponsiveContainer({
  required Widget compact,
  Widget? medium,   // 不传则退化到 compact
  Widget? expanded, // 不传则退化到 medium 或 compact
})
```

**实现思路**：

```dart
class UtenResponsiveContainer extends StatelessWidget {
  const UtenResponsiveContainer({
    super.key,
    required this.compact,
    this.medium,
    this.expanded,
  });

  final Widget compact;
  final Widget? medium;
  final Widget? expanded;

  @override
  Widget build(BuildContext context) {
    // 页面级用屏幕宽度；嵌套场景请直接用 LayoutBuilder
    final bp = context.breakpoint;
    final child = switch (bp) {
      Breakpoint.compact => compact,
      Breakpoint.medium => medium ?? compact,
      Breakpoint.expanded => expanded ?? medium ?? compact,
    };
    return child;
  }
}
```

**使用示例**：

```dart
UtenResponsiveContainer(
  compact: const _MobileLayout(),
  medium: const _TabletLayout(),
  expanded: const _DesktopLayout(),
)
```

### 3.2 UtenResponsiveGrid

**核心**：基于 `Wrap` 实现的**真瀑布流**卡片网格。每项高度由内容自定义（不再强制等高），列数完全由 **`LayoutBuilder` 父容器宽度**决定。

> 🔄 **v2 重写说明**：旧版 `UtenAdaptiveGrid` 用 `GridView`（强制 1:1 正方形 + `childAspectRatio`），不适合卡片类业务（卡片高度差异大、内容无法自适应）。v2 改名 `UtenResponsiveGrid`，底层换成 `Wrap`，支持真瀑布流。**新代码一律用 `UtenResponsiveGrid`，旧名 `UtenAdaptiveGrid` 已废弃。**

**API 规范（v2）**：

```dart
UtenResponsiveGrid({
  required int itemCount,
  required Widget Function(BuildContext, int index, double itemWidth) itemBuilder,
  double spacing = 14,             // 横向间距
  double? runSpacing,              // 纵向间距，缺省同 spacing
  EdgeInsets? padding,
  UtenResponsiveColumns? columns,  // 可选：强制列数配置，覆盖自动计算
  int maxColumns = 6,
  int minColumns = 1,
})
```

**三个关键变化（相对旧版）**：

1. **`itemBuilder` 第三参数 `itemWidth`**：签名从 `(context, index)` 改为 `(context, index, itemWidth)`。`itemWidth` 是当前单格的实际可用宽度，卡片内部布局（文字行数、图标尺寸、是否横排）应据此自适应。
2. **列数基于 `LayoutBuilder` 的 `constraints.maxWidth`**（父容器实际宽度），**不再用 `context.breakpoint`**（屏幕宽度）。桌面端内容区被侧边栏挤窄，屏幕宽度 ≠ 容器宽度。
3. **`Wrap` 实现**：每项高度由 `itemBuilder` 返回的 Widget 自决定，行与行之间是真正的瀑布流（不同行可不等高）。

**列数规则表**（按容器宽度自动推导）：

| 容器宽度（dp） | 列数 | 典型场景 |
|---|---|---|
| `< 500` | 1 | 手机竖屏、被 Rail 大幅挤窄的桌面窄区 |
| `500 – 800` | 2 | 手机横屏、小平板、桌面窄内容区 |
| `800 – 1100` | 3 | 平板、桌面（Rail 折叠） |
| `1100 – 1500` | 4 | 桌面（Rail 展开） |
| `> 1500` | 5 | 大屏 / 4K Web |

> 最终列数受 `minColumns` / `maxColumns` clamp 约束。
> 若传入 `columns`（`UtenResponsiveColumns`），则强制使用该配置，跳过自动计算。

**使用示例**：

```dart
UtenResponsiveGrid(
  itemCount: payslips.length,
  spacing: 14,
  itemBuilder: (context, index, itemWidth) {
    final item = payslips[index];
    // itemWidth 是当前单格宽度，卡片可据此决定内部排版
    return UtenPayrollCard(data: item, width: itemWidth);
  },
)
```

**完整实现（v2，Wrap 瀑布流）**：

```dart
class UtenResponsiveGrid extends StatelessWidget {
  const UtenResponsiveGrid({
    super.key,
    required this.itemCount,
    required this.itemBuilder,
    this.spacing = 14,
    this.runSpacing,
    this.padding,
    this.columns,
    this.maxColumns = 6,
    this.minColumns = 1,
  });

  final int itemCount;
  // 第三参 itemWidth = 当前单格宽度
  final Widget Function(BuildContext context, int index, double itemWidth)
      itemBuilder;
  final double spacing;
  final double? runSpacing;
  final EdgeInsets? padding;
  final UtenResponsiveColumns? columns; // 强制列数配置（可选）
  final int maxColumns;
  final int minColumns;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        // ⚠️ 父容器宽度，不是屏幕宽度
        final available = constraints.maxWidth;
        final cols = (columns?.resolve(available) ??
                _autoColumns(available))
            .clamp(minColumns, maxColumns);

        final rs = runSpacing ?? spacing;
        // 单格宽度 = (总宽 - 列间间距总和) / 列数
        final itemWidth = (available - spacing * (cols - 1)) / cols;

        return Padding(
          padding: padding ?? EdgeInsets.zero,
          child: Wrap(
            spacing: spacing,
            runSpacing: rs,
            children: [
              for (int i = 0; i < itemCount; i++)
                SizedBox(
                  width: itemWidth, // 撑开单格宽度，高度由内容决定
                  child: itemBuilder(context, i, itemWidth),
                ),
            ],
          ),
        );
      },
    );
  }

  /// 按容器宽度自动推导列数（v2 规则）。
  int _autoColumns(double w) {
    if (w < 500) return 1;
    if (w < 800) return 2;
    if (w < 1100) return 3;
    if (w < 1500) return 4;
    return 5;
  }
}
```

> 💡 **为什么列数基于容器宽度而不是屏幕宽度？**
> 桌面端 `NavigationRail`（展开约 240dp）/ `SplitView` / `Dialog` 都会挤占宽度。一个 1920 的屏幕在展开 Rail 右侧的内容区可能只剩约 1500，按屏幕宽度算会高估列数，导致卡片溢出或挤压。
> `LayoutBuilder.constraints.maxWidth` 永远是"父容器真正给到的宽度"，最准确。
> 页面级 Shell / 导航仍用屏幕断点（见 [02-响应式与多端适配.md](02-响应式与多端适配.md)），两者不冲突。

> 💡 **为什么改用 `Wrap` 而不是 `GridView`？**
> `GridView` 通过 `childAspectRatio` 强制所有格子同宽同高（旧版强制 1:1 正方形），卡片内容稍多就被裁剪、稍少就留大片空白。`Wrap` 让每个子项高度独立由内容决定，行与行之间天然错落，才是真正的瀑布流，适合工资条/报销/通知等高度不一的业务卡片。

### 3.3 UtenMasterDetail

列表-详情类页面的标准容器。三档行为差异显著：

**三档行为表**：

| 档位 | 行为 | 布局 | 选中详情时的交互 |
|---|---|---|---|
| compact | 单栏切换 | 只显示列表，或只显示详情 | push 一个新页面 / 全屏覆盖 |
| medium | 窄分栏 | 列表占 40%，详情占 60% | 详情在右侧原地刷新 |
| expanded | 宽分栏 | 列表占 35%（≤ 360 dp），详情占 65% | 详情在右侧原地刷新 |

**API 规范**：

```dart
UtenMasterDetail({
  required Widget Function(BuildContext, T selected) detailBuilder,
  required IndexedWidgetBuilder itemBuilder,
  required int itemCount,
  required ValueChanged<int>? onSelect,
  int? selectedIndex,        // 受控模式
  double masterWidthWide = 360,   // expanded 档 master 宽度
  double masterWidthMedium = 240, // medium 档 master 宽度
})
```

**实现骨架**：

```dart
class UtenMasterDetail<T> extends StatelessWidget {
  const UtenMasterDetail({
    super.key,
    required this.itemBuilder,
    required this.itemCount,
    required this.detailBuilder,
    this.selectedIndex,
    this.onSelect,
    this.masterWidthWide = 360,
    this.masterWidthMedium = 240,
  });

  final IndexedWidgetBuilder itemBuilder;
  final int itemCount;
  final Widget Function(BuildContext, int index) detailBuilder;
  final int? selectedIndex;
  final ValueChanged<int>? onSelect;
  final double masterWidthWide;
  final double masterWidthMedium;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        final bp = Breakpoint.ofWidth(constraints.maxWidth);

        switch (bp) {
          case Breakpoint.compact:
            // 单栏：列表 / 详情二选一
            if (selectedIndex == null) {
              return _MasterList(
                itemBuilder: itemBuilder,
                itemCount: itemCount,
                onSelect: onSelect,
              );
            }
            return detailBuilder(context, selectedIndex!);

          case Breakpoint.medium:
            return Row(
              children: [
                SizedBox(
                  width: masterWidthMedium,
                  child: _MasterList(
                    itemBuilder: itemBuilder,
                    itemCount: itemCount,
                    onSelect: onSelect,
                    selectedIndex: selectedIndex,
                  ),
                ),
                const VerticalDivider(width: 1),
                Expanded(child: _detailOrPlaceholder()),
              ],
            );

          case Breakpoint.expanded:
            return Row(
              children: [
                SizedBox(
                  width: masterWidthWide,
                  child: _MasterList(
                    itemBuilder: itemBuilder,
                    itemCount: itemCount,
                    onSelect: onSelect,
                    selectedIndex: selectedIndex,
                  ),
                ),
                const VerticalDivider(width: 1),
                Expanded(child: _detailOrPlaceholder()),
              ],
            );
        }
      },
    );
  }

  Widget _detailOrPlaceholder() {
    if (selectedIndex == null) {
      return const Center(child: Text('请选择左侧条目')); // 文案走 i18n
    }
    return Builder(builder: (ctx) => detailBuilder(ctx, selectedIndex!));
  }
}
```

### 3.4 UtenTwoPaneLayout

通用左右分栏：左侧"次要面板"（过滤条件、目录树），右侧"主要内容"。窄屏自动折叠为单栏，左面板通过抽屉或按钮唤出。

**API 规范**：

```dart
UtenTwoPaneLayout({
  required Widget primary,       // 主内容（始终可见）
  required Widget secondary,    // 次要面板（窄屏折叠）
  double secondaryRatio = 0.3,  // 宽屏下次要面板占比
  bool showSecondaryOnMedium = true,
})
```

**三档行为表**：

| 档位 | 行为 |
|---|---|
| compact | 只显示 `primary`；`secondary` 折叠为可滑出抽屉（`Drawer` 或 `NavigationDrawer`） |
| medium | 左右分栏，`secondary` 占 `secondaryRatio`（默认 30%） |
| expanded | 左右分栏，`secondary` 占 `secondaryRatio`，宽度有上下限（如 240–360 dp） |

> 💡 与 `UtenMasterDetail` 的区别：
> `MasterDetail` 是"列表 + 详情"，强语义、有选中态；
> `TwoPaneLayout` 是"通用双栏"，无选中态语义，适合"过滤 + 结果"、"目录 + 编辑器"等场景。

## 四、何时用响应式、何时用自适应

| 场景 | 选择 | 用什么 |
|---|---|---|
| 根 Shell 切底部 Tab ↔ 侧边 Rail | **响应式** | `context.breakpoint` / `LayoutBuilder`（屏幕级） |
| 整个页面在手机/平板换不同结构 | **响应式** | `UtenResponsiveContainer` |
| 卡片网格列数自动 | **自适应** | `UtenResponsiveGrid` |
| 列表-详情页 | **自适应** | `UtenMasterDetail`（内部已是自适应） |
| 过滤面板 + 结果列表 | **自适应** | `UtenTwoPaneLayout` |
| 单个卡片内部，宽了想横排、窄了想纵排 | **自适应** | `LayoutBuilder` |
| 放进 Dialog 的表单 | **自适应** | `LayoutBuilder`（屏幕宽度毫无意义） |

**判断口诀**：

> 这个组件会被**嵌套**到不同容器（Rail 右侧、SplitView、Dialog、Web 多窗口）里吗？
> - 会 → 用 `LayoutBuilder`（自适应）
> - 不会（就是根布局） → 用 `context.breakpoint`（响应式）

**默认选自适应**。99% 的可复用组件都该用自适应。

## 五、禁忌清单

| 反例 | 正确做法 |
|---|---|
| 组件内部 `MediaQuery.of(context).size.width` | 用 `LayoutBuilder` 的 `constraints.maxWidth` |
| 在 `UtenResponsiveGrid` 外手写 `Wrap`/`GridView` 并写死列数 | 列数交给组件按 LayoutBuilder 容器宽度自动算，需要时传 `columns` |
| 自己手写 master-detail 的 Row + IndexedStack | 用 `UtenMasterDetail` |
| 在每个列表页重新发明两栏切换逻辑 | 用 `UtenMasterDetail` 或 `UtenTwoPaneLayout` |
| 用 `Orientation.landscape` 决定是否分栏 | 用 `Breakpoint`（横屏手机不一定宽） |
| `UtenResponsiveContainer` 里嵌套 `LayoutBuilder` 再判断 | 选一个层级：页面级用屏幕断点，组件级用容器约束 |
| 用旧版 `UtenAdaptiveGrid`（GridView 正方形） | 改用 v2 `UtenResponsiveGrid`（Wrap 瀑布流） |

## 六、对照清单（每次开发前自检）

- [ ] 可复用组件内部用 `LayoutBuilder`，**不读** `MediaQuery.size`
- [ ] 卡片网格用 `UtenResponsiveGrid`，列数基于 LayoutBuilder 容器宽度自动算（非屏幕宽度）；`itemBuilder` 用第三参 `itemWidth` 自适应卡片内部布局
- [ ] 列表-详情页用 `UtenMasterDetail`，不自己手写 Row
- [ ] 双栏面板用 `UtenTwoPaneLayout`，不自己手写 Row
- [ ] 页面级整体切布局用 `UtenResponsiveContainer` 或 `context.breakpoint`
- [ ] 组件在 `Dialog` / `SplitView` / Web 多窗口里被复用时仍正确（自测过一次）
- [ ] 列数 / 分栏比例随容器宽度平滑变化，无写死数字
- [ ] 该组件已加入 [02-组件库/组件总览.md](../02-组件库/组件总览.md)（如新增）
