# 列表分类与状态呈现

本轮根据实际页面、查询、权限和办理动作逐页判断，手工调整，没有用批量替换脚本删除分类。

## 判断规则

- 同一集合、同一表格、同一办理动作下的来源、类型或细状态，放到行内文字和表头筛选，不另起子分类栏。
- 草稿续填、开放作业、执行与历史等主工作入口，如果决定操作能力、草稿恢复或查询范围，继续保留。
- 不同业务对象、权限、事务命令、报表粒度、批次身份或真实目录树，继续保留分类。
- 服务端分页列表的表头筛选必须在分页前生效；不能用当前页记录猜类别全集或裁剪当前页来伪装查询。
- 清除细筛选回当前主阶段；历史保留原时间范围。切范围清理勾选，旧请求不得恢复旧队列。
- 稳定表格键和已有个人布局保留；行身份包含来源类型和真实 UUID，不按名称拼接对象。

## 颜色和验证范围

复用平台的 UtenStatusBadgeType 与整格状态色：可办理/完成绿，第二类型待办青绿，执行蓝，等待外部黄，修改/部分/风险橙，驳回/阻断红，草稿/取消灰。文字同时表达类型和状态，颜色不作为唯一信息。采购/委外是来源，不能自动等同于警告或失败。

订货审批已检查真实主题下 1440 与 375 宽的浅/深色页面，并验证白字与所用实底色达到 4.5:1。截图由当前页面和模拟数据渲染，属于本地视觉证据；不代表真实账号 UAT 或服务器发布。

本轮验证表头条件、跨页范围、清除与阶段切换、旧响应、勾选清理、历史深链、混来源同 UUID、真实 FQC 页容量及上限。后端接口和业务数据库未修改。

验证结果：20 个相关测试文件共 149 条回归全部通过；回写后品质与研发 15 条回归再次通过。本轮 36 项源码/测试的静态分析为 0 问题，逐文件核对回写结果与验证候选一致。全量项目分析另有 3 条其它并行测试的类型/常量提示，分别位于 `sales_doc_status_clear_test.dart`、`suggestion_empty_filter_recovery_test.dart`、`visitor_terminal_history_visibility_test.dart`；没有修改这些并行测试。
