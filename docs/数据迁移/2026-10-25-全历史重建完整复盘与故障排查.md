## 4. 本轮业务判断为什么不能照抄成固定ID名单

全历史先保全，再从真实日期、逐行义务、原关闭/取消、最后有效已审下游及完整生命周期判历史、有效未完、真实未开始与无效。旧Status默认−1不等于现代反审；老单缺资料不自动变草稿。关闭剩余需求不补满received/shipped/iqty/fqty，不造到货、日报、IQC、审批、核销或GL。生产按QTY−LQTY净需求和精确已审O_In核历史完成/未满足，不把FQTY或296旧分类升级为逐头真实执行。

采购<=10%是用户授权的历史收尾策略，逐SKU/可证冻结单位/净有效收货扣退货并区分赠品；96不是下轮固定名单。委外E_OrderItem.WQTY混合成品退回与材料退料，两份旧订单不证明只有两笔委外业务或供应商余额0。财务历史兼容状态1仅解释旧archive，不造实际审批人/时刻/cash/GL；新近真实未审与已有真实分录要从新源重判，不能全部按旧三ID归档。

原价目/展开成本与实际成本账分开；零量非零金额、负库存和负往来有源事实时保留，负预收预付不能按年龄/负号清零。禁用组件不进活动BOM；3,129中性原料身份不补1单位用量/密度/成本。物理保留、当前活动、来源归档、业务剔除、零量不出流水、历史关闭分别计数。

## 5. 提交、恢复和重试状态表

| 观察到的状态 | 正确动作 | 禁止的推断 |
|---|---|---|
| 纯文件/RO规划失败 | 修规则或工具，保失败，不改库 | 已经半导入／需要重清 |
| PG启动FATAL、stdout0、0SQL | 修连接参数后核相同目标，再新计划 | 已写部分业务 |
| 写事务仍运行 | 核实际PGPID/目标/当前query，不并发写保护域 | 用工具session号当PGPID；kill抢救半库 |
| 事务取消且整库保护域RTO已证 | 新不可变修订、同完整条件、正确新输出后单次重试 | audit0一个数等于全回滚；setval抹序列gap |
| COMMIT已发生、独立核验未完成 | 保持已提交事实，完成独立读回；失败则明确不确定范围 | 自动重灌同plan或标无写 |
| COMMITTED_VERIFIED | 消费真实收据继续下一步 | 用旧全库FP否认后续合法已审差量 |
| 技术完成、业务待核 | 交付部门清单，真实盘点/财务/UAT按授权进行 | 将HTTP200或编译通过称业务验收 |

每步都需完整提交前保护和独立提交后读回：真实ordinary guards开启、合法角色、CID/SID/OID、源/目标精确身份、前值CAS、全部相关业务/seq/旧run/audit/proof/pool保护、终SET CONSTRAINTS ALL IMMEDIATE、精确marker与audit全集。只核postverify会出现“已提交后才发现标记缺失”的不可接受窗口。若真实COMMIT不明，先读回而非自动重试。
