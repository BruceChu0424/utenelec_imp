# B1 客户、供应商完整候选与按 ID 引用迁移

本文记录本轮本地候选源码，不代表提交、CI、制品、部署或真实业务使用验收完成。与 `B1-2026-10-25-客户供应商字典消费者.csv` 的 126 处基线及查询/报表专项清单配合阅读。旧分类是排查线索，不能直接作为已完成证据。

## 公共职责与权威

1. **完整候选**：新单和关联选择复用 `showUtenClientPicker` / `showUtenSupplierPicker` → `UtenMasterPicker` → Repository 分页/search-context。历史筛选传 `selectableOnly:false`，保留禁用历史；新供应商选择和默认条款只接受 fresh lookup 后确已解析且仍为使用状态的记录。客户原有 legacy finance stub 排除口径保持默认 true，不扩大权限。
2. **表头完整候选**：`master_party_options.dart` 的 client/supplier/combined loaders 只读每页 100 条，沿用 Repository 的 POST 关键词合同。`MasterDataTableView.facetPageLoaders` 按列接入，其他原有 local facets 和旧 `loadFacetPage` 不受影响。组合往来方只访问当前有客户/供应商查看权限的域，不在前端混并业务计算。
3. **所选 ID**：`resolvePickedParty` 在选择后 fresh 读取确切 ID，校验单调 owner epoch、表单身份和当前 positive known/selectable，再接受候选；失败或缺失不会把原 picker DTO 当作新授权。历史选择允许已知禁用记录。`selectedPartyFacet` 只保留当前精确 UUID 的可读名，绝不枚举引用缓存作为完整候选；`__null__` 独立处理。
4. **页面引用名**：三名称服务的显式 `load*Names` 按实际返回 ID fresh 授权读取；详情、恢复、列表、关联单据在发布新数据前预读，普通 getter 只补显示。客户授权变化可以不改变 authEpoch，因此已缓存 positive 不能证明新读权限。公共 fresh-read 序列及回执覆盖合同见 lookup 专项文档/测试。
5. **本地草稿引用**：`PartyReferenceReadController` 按 owner、读修订、实际草稿 ID 集创建读所有的不可变名称快照；同一读不因其他页面清缓存或缓存容量淘汰而改变，下一次显式刷新重新证明。恢复原件里的 clientName/supplierName 属于原始输入，继续保留；未核引用只显示“已选择”，不改 UUID。`FormDraftCategoryTable` 与 `DraftWorkspaceTable` 共用该实现。
6. **生命周期**：`UtenMasterPickerField.allowClear` 默认 true；必选月结与锁定关联筛选设 false。选择 await 后检查 mounted；关联单据 sheet 的 owner A→B→A 使旧读取失效并只关闭一次，不更改未知提交、来源、数量或单据匹配规则。
7. **面板结果**：`guardPartyPanelResult` 共用到月结建立和统一条款面板，持有单调 epoch 的观察订阅直到面板关闭，返回时再比较原 ProviderContainer。不能只在打开/关闭各 read 一次：懒 provider 无观察者时可能漏掉中间 B。月结 owner 变化后保留本地输入但禁用冻结，旧身份结果不能成为新身份命令。
