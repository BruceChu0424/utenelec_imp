调度台待排区和物料分析候选区的移动分页能力不同：物料分析候选手机卡已有「上一页/下一页」和跨页保留选择；当前调度台 compact 待排卡仅展示首批 100 行，没有分页控件。销售进度文档不得借用任一生产页面的分页说明来宣称本页投影已经实现，本文〇节仍是待实现/待验收合同。

## 〇、V234 订单行—计划前分析—分批生产口径

本节依据 [ADR-029](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)，优先于后续只覆盖正式计划的旧投影说明。它是计划前分批销售进度的验收合同，不表示当前销售进度 API/页面已经返回 analysis item、plan link 或全部阶段数量。生产端当前操作见[生产物料分析页](生产物料分析页.md)。

销售订单生产进度按以下层级展示：

```text
销售订单
  └─ 销售订单行（产品、订货量、交期）
      ├─ 待分析/备料的 material-analysis item
      ├─ SUBMITTED plan link（计划草稿待批准，不计已下达）
      ├─ 正式批次 1（已完成）
      ├─ 正式批次 2（生产中）
      └─ 正式批次 3（READY、待发料）
```

一条销售订单行可以分批关联多张正式计划和多个执行批次；一张合并生产计划也可以精确分摊到多条销售行。界面不得按货品名称临时 JOIN，也不得把第一张计划的状态覆盖整条订单行。

每条订单行至少显示：

- 订货有效量、已取消量；
- 已进入计划前需求量、待分析/待料量；
- 已提交待批准量、已批准正式下达量、READY 待发料量、生产中量；
- 合格入库量、可发货量、已发货量和剩余量；
- 当前最早预计齐套日、订单风险和投影更新时间。

展开正式批次显示计划号、本批分摊数量、车间、状态、计划/实际日期和深链。计划前需求仅显示销售可解释的“待分析、备料中、预计齐套日、结构待确认”等状态，不暴露采购价格、供应商谈判、内部绩效或敏感缺陷责任。

MAKE `MAKE_COMPONENT` child analysis item、正式子件计划、报工和子件入库作为父批次的物料依赖单独下钻。只有子件合格入库并最终推动父产品生产/入库后，才增加销售订单行的父成品阶段量；子件自身数量不能直接记入销售完成。

阶段状态由数量投影派生，不回写一个人工百分比真相：

| 阶段 | 判定重点 |
|---|---|
| 待分析 | 有有效剩余需求，但尚无当前有效物料分析 |
| 备料中 | 有 supply action 或预计供给，尚无正数 READY 下达覆盖 |
| 已提交待批准 | 存在 `production_material_analysis_plan_links=SUBMITTED` 及计划草稿/ACTIVE planning draft，但尚未批准；不得计 READY 或已预留 |
| 部分已下达 | 已批准下达量大于零且小于有效需求量（**2026-09-10 V545 已实现**：订单行按剩余未排量停在待排产，进度页阶段列显示「待排产·部分已排 已排/订货」，进度行与 plan-progress 行下发 `unplannedQty`） |
| 生产中 | 有已发料/开工/审核报工但未全部合格入库的批次 |
| 已完成生产 | 父成品合格入库量覆盖有效需求量；不等于已发货 |
| 部分/全部已发货 | 继续以仓库审核发货事实判定 |

订单改量或取消时，未转下游计划前需求可撤回；已有正式计划、库存预留、发料、报工或入库时显示“处理中/需反向”，直到对应事实完成反向后再降低阶段数量。读模型不得提前把业务事实抹掉。

销售用户默认只能查看自己及授权范围的订单。生产计划和计划前需求深链是否可点击由服务端对象范围和 `allowedActions` 决定；无权时保留销售可见阶段量并显示锁定说明，不借深链扩大生产、采购或员工信息权限。

移动端按订单行折叠批次，首屏优先展示数量和风险；批次列表支持分页/按需加载。状态使用文本、图标和语义色共同表达；数字使用稳定对齐，动态字体下不得截断关键数量。加载失败显示数据截止时间和重试，不把空响应当“没有生产”。

## 一、页面职责

销售订单生产进度把订单行对应的生产计划和执行分段按销售可见口径展示，回答：

- 已排产、已生产、已入库各有多少；
- 当前由哪些生产计划和执行分段承接；
- 分段处于物料不齐套备料中、物料齐套备料中、备料完毕、生产中、已完成、已取消或已红冲的哪一阶段；历史 `DISPATCHED` 只显示为兼容工单，不再代表一个待人工办理步骤；
- 哪些分段已延期，以及销售可以对客户说明的原因。

该弹层是履约读模型，不是生产写入口，也不能用一个百分比替代各阶段数量。

## 二、点击行为

- 点击生产计划编号，先关闭销售弹层，再打开该生产计划详情；
- 点击某个执行分段，打开同一父计划详情并携带 `executionSegmentId`；
- 计划详情在分段加载完成后自动打开对应分段详情；
- 计划 ID 缺失、当前账号无查看权限或路由失败时必须给出明确反馈，不能静默无响应。

销售侧把执行分段称为“执行子计划”仅是展示文案；它仍不是 `subplan_links` 中的独立自制件子计划。

## 三、权限与敏感信息

- 只有具备生产计划查看权限或被允许的跨部门查看范围，计划和分段才表现为可跳转；
- 无权时保留销售可见进度，但显示锁定状态，点击提示“当前账号没有生产计划查看权限”；
- 对象范围与敏感字段必须由服务端裁剪，前端不得仅靠隐藏控件保护成本、报价、内部不良责任和员工绩效；
- 从销售页跳入生产页不会授予任何编辑、派工或报工权限。

## 四、数量与异常口径

- 分摊量、报工量、入库量分别展示，不能相加成单一完成率；
- 部分生产、部分入库、部分发货必须保留各自余量；
- 自制件子计划只展示自身计划/报工/入库事实；V194 的 MAKE peg 只推动父物料需求齐套，子计划计划量/报工量/入库量不得直接冒充父成品或销售订单完成量；
- 执行分段不存在或已被合法反向时，刷新服务端投影后显示真实状态；
- 读模型更新时间和主单据事实冲突时，以服务端权威单据为准并允许刷新；
- 没有生产计划的现货订单不应伪造生产进度。

## 七、订单进度查询与待关注角标

本节描述当前实际入口。单一生产百分比只作摘要，不替代各产品的已排、实际入库、已发、办理中和本次可发数量；〇节更完整分析/计划链投影仍按其单独验收范围解释。

### 入口与路由
- 销售管理 hub「销售管理」分组入口卡 **订单进度查询**（`/sales/progress`，权限 `sales_order:view`），右上角带 **待关注角标**；工作台首页“销售管理”卡复用同一数据源。
- 看板页 `sales_order_progress_page.dart` 使用 `MasterDataTableView`，按当前归属、阶段、关键字和时间条件查询；双击精确订单行或使用行菜单进入详情。
- 顶部分段筛选与表格滚动保持统一布局。已发货、中止和结案沿历史口径查看；历史“全部”不是只查已发货，尚未选定查询条件时不假造空结果。

### 当前进度口径
- 生产摘要使用实际成品入库口径，不以报工或子件入库冒充父成品已可发；数量和文字阶段同时展示。
- 阶段由 `SalesOrderService.progressStageExpr` 统一派生。财务驳回、中止/结案及已发完成先按原规则处理；活跃订单存在当前可发量时进入SHIPPABLE，随后才按剩余未排量和已有生产量判断PENDING/PRODUCING。因此“部分可发、其余未排”的订单不会被未排余量遮住发货入口；没有可发量的订10排4仍保留待排产及部分已排事实。
- 详情 `/sales/progress/:orderId` 展示产品进度与履约时间线；驳回且可写时提供修改或合法取消订单入口。
- “去发货”先进入本订单的可发产品选择，按服务端 `shippableQty` 及扣除办理中的数量预填新建出货页，不能只检查原始 `reserved_qty`。保存不改已发量；财审放行、仓库真实交接后才更新库存和已发事实。

### 后端
- `GET /api/sales/orders/progress?page=&size=&stage=`（权限 `sales_order:view`）：原生 SQL 聚合有效 `sales_order_items`（qty/produced_qty/shipped_qty/reserved_qty/planned_qty）by order，派生 `productionPct` 与 `stage`，并下发 `financeRejected/reason/byName/at`；归属范围同 `/stats`（`accessPolicy.nativeReadScope`）。
