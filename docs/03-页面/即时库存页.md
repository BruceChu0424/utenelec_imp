## 一、定位

对标老系统「即时库存」窗口的看盘视角：按货品 × 颜色聚合当前库存，按仓库范围、分类和表头条件筛选。
正文使用货品资料同款左右分栏：左侧分类树直接点选，右侧库存表随所选范围更新。搜索直接查询货品名称、编号、型号等库存结果，
不为分类定位额外请求货品分类命中列表。父类代表整个子树，「全部分类」清除分类条件；不再通过右上分类按钮或确认面板切换。

「库位号」和「主档归属仓库」是货品资料字段，不代表这行跨仓聚合库存的实际位置。编辑模式修改同一货品的这两个
主档值，因此同货品的多个颜色行共用一份草稿并只保存一次。实际搬仓仍须通过调拨等库存单据过账，不能改主档代替。

## 二、入口与导航

- 进入：仓库管理 hub「即时库存」卡片。
- 离开：返回仓库管理 hub（`UtenBackButton` 指定 `/warehouse`）。
- 「查看详情」以 `context.push` 进入 `/stock/instant-inventory/overview`，返回时优先 pop，
  保留原库存表的分类、仓库、搜索、表头筛选、排序和页码；直达总览后无返回栈时回即时库存。
- 总览将当前查询范围写入 URL，可直接打开和刷新。查询参数包括 `categoryId`、`warehouseId`、
  `includeDefective`、`includeLineSide`、`keyword`、`owningWarehouse`、`owningWarehouseNull`、
  `colorId`、`series`、`unitId`，不传原表页码。范围说明是展示信息，不能代替真实筛选参数。

## 三、响应式布局

- 所有宽度统一使用 `UtenContentContainer.wide`，有分类查看权限时复用 `UtenSplitView` 与 `UtenCategoryTreeView`。
- 桌面左侧常驻分类树，右侧显示库存工具栏与表格；分隔线可拖动并记忆当前设备的宽度，默认按共享分类树布局显示层级与选中态。
- 窄屏或大字号下空间不足时，使用共享分类目录入口打开完整分类树。点分类后直接更新范围并返回库存正文，保留表格与树的状态；不另设一套分类确认交互。
- 右侧搜索、仓库字段、库存范围开关与结果计数按局部可用宽度换行；桌面不显示重复的分类筛选按钮。
- 无 `material_category:view` 权限时不加载分类树、不显示目录入口，库存查询与货品搜索仍按 `stock:view` 可用。
- 桌面右下显示编辑模式与盘点动作；窄屏盘点动作进入 AppBar，编辑保存和取消仍由共享浮动动作组承载。
- 编辑期间分类树、「全部分类」与查询工具栏停止接受输入，行点击与排序关闭；先保存或取消编辑，再切换分类和查询条件。
  翻页、表头筛选、刷新和离开先经过共享未保存修改确认，取消确认保留草稿；确认放弃后才切换。
  浮动动作区预留表格末尾空间，避免覆盖最后几行。
- 库存数量、重量和待处理量保持现有查询口径；不良品仓与内料仓默认不计入，指定叶仓仍精确查询。

## 四、数据链路

```
左侧分类树（需 material_category:view）：/api/master/material-categories/tree?withGoodsCounts=true
右表：GET /api/stock/instant-inventory?categoryId=&warehouseId=&includeDefective=&includeLineSide=&keyword=&page=&size=&sort=&order=
      └ goods 货品驱动 LEFT JOIN stock_balances 聚合
        —— warehouseId=叶子仓：精确单仓；=主仓库：自身+全部子仓（服务端
           WarehouseScopeService 展开，is_accountable 与不良仓开关口径同「全部」）；
           null=全部（仅 is_accountable 仓库）
        —— 无余额货品也列出（库存 0），与老系统「分类下全是内容」一致
        × material_categories（所属类型）× colors / units（名称解析）
        × production_plan_items 可排余量预聚合（多排数量）
```

- 数量/重量：余额表当前值。数量历史=StockGoods 最新年 FactQTY 迁移(V80)，增量=单据审核同事务联动。
  重量自 V743 起是千克口径的仓库重量账：旧库余额重量单位不可证明，迁移为未知(基本单位是重量单位的货品按数量精确换算)；
  此后每笔流水按「精确 / 调拨对应 / 红冲镜像 / 实称或分摊 / 库存均重 / 学习单重估算」确定重量并与数量同一语句写余额，
  盘点可录实盘重量定重、有权限的人可单独核重，规则见 [ADR-135](../99-决策记录-ADR/ADR-135-仓库重量账与单重自学习.md) §3.2。
  聚合口径：`bool_or(qty <> 0 AND weight IS NULL)` 为真则整行 NULL(未称)，否则求和；任一维度含估算则整行带「≈」。
- **库位号列**：读货品主档 `goods.stock_place`，V451 起由实际入库学习回写保持最新
- **所属仓库列(2026-09-15, V587)**：读货品主档 `goods.owning_warehouse_id` 的仓库名，即「这批货平时归哪个仓管」。**与页面顶部的仓库筛选不是一回事**：前者筛选实际库存仓范围，本列说明货品的主档归属。列 key 为 `owningWarehouse`，库存响应直接包含 UUID 与名称，不依赖货品字典。
- **「所属仓库」列表头筛选(2026-09-15)**：服务端过滤+服务端聚合 facet 桶（在未应用本筛选的同一口径上聚合，翻页不变；含「(空)」桶筛未登记），参数 owningWarehouse/owningWarehouseNull。
- **V590 单一事实源(2026-09-15)**：归属仓改由任何入库自动回写为最新入库仓(StockService 过账内核收口, 采购/委外/完工/调拨/退料/盘盈/手工单全路径)。本页与物料分析/货品资料展示的是同一个 `goods.owning_warehouse_id`, 入库一变各处打开即最新; 按仓真实库存仍以 stock_balances/本页为准。
  （到货登记 / IQC 合格品入库确认 / 产成品登记「记住库位」，见
  [迁移说明 66](../数据迁移/71-IQC入库库位学习.md)）；同一货品多仓不同库位时，
  待入库预填仍优先按仓库×货品偏好，主档值只是全局回退建议。
- **库存台账金额（V421 口径，页面已不展示）**：`stock_balances.amount_local` 按
  货品+颜色聚合，来自已审核库存流水及其红冲/调账事实。本页 2026-09-01 起不再渲染
  该列（持 `goods:cost:view` 亦然），排序候选同样移除；后端字段与导出能力保留。
- 排序白名单：qty / weight / moreQty / pendingQty / name（默认数量降序）；
  `costAmount` 排序键已不随本页发送。
- 仓库面板「全部」= 6 个真实仓（IsCal=0 参与核算，2026-07-28 修反转 bug）；幻影仓可单选。
- **主/子层级（V476）**：面板按「顶层仓在前、子仓缩进」一次铺开；主仓库（父仓）
  可选=子树聚合；叶子仓=精确单仓。同一面板的运营口径（单据登记）里父仓只钻层不可选
  ——本页是唯一允许父仓聚合的库存查询入口之一（余额/流水查询同口径）。
- 「含不良品仓」开关(仓库用途 `warehouses.is_defective`，仓库资料维护)：2026-10-04 起([ADR-146](../99-决策记录-ADR/ADR-146-不良品仓业务规则与可用量单一口径.md))
  **默认关**——即时库存默认只看可用的良品；打开后把成品不良品仓/原材料不良仓计入，每行数量后标
  「(其中不良品 N)」(`defectiveQty`)，表尾合计多一项「其中不良品数量」；**仓库=全部或主仓聚合时
  生效**，选定叶子仓时置灰。**选择按账号服务端持久化**（`user_preferences` key
  `stock.instantInventory`，模式同工作台布局：本地缓存即时渲染 + 登录后服务端同步 +
  防抖 800ms 推送，provider：`lib/features/stock/providers/instant_inventory_prefs_provider.dart`）。
- **加密 Excel 导出**：`UtenExportButton` → `POST /stock/reports/export`（report=`instant-inventory`，
  后端 `StockReportService.export` 独立分支复用同款查询全量分页拉取，父仓聚合口径同步生效）；
  五道防线齐备：`stock_report:export` 独立权限（V71 已种子）+ 限流拦截器 + Agile AES-256 密码
  + 10 万行上限 + 审计（`export_stock_report`）。导出再次检查 `goods:cost:view`；无权时
  **整列移除**库存台账金额，而不是输出空白表头——导出口径独立于页面展示。

## 六、功能点

1. **货品分类筛选**：左侧分类树直接点选，父类代表子树；零货品分类隐藏。默认不筛选分类并直接加载第一页。
   「全部分类」清除当前分类条件，保留搜索、仓库及表头筛选。分类加载失败在左栏提供重试，不阻塞默认库存列表。
   无分类查看权限时不请求分类树，页面保留库存列表。窄屏共用分类目录与相同的直接点选行为。
2. **货品搜索**：300ms 防抖，回车可立即查询；搜索默认跨原浏览分类。搜索时明确选分类只收窄本次搜索范围，
   清空关键词恢复进入搜索前的浏览分类。不发起分类定位请求，不以空结果回退全库数据。
   输入、查询与身份边界会使旧请求失效，慢响应不得覆盖新条件；导出和打印使用同一已应用条件。
3. **仓库筛选**（同款字段 + `showUtenWarehousePickerPanel` 查询口径）：面板顶部「全部」行
   （= 参与核算仓库聚合）+ 整棵层级缩进一次铺开，主仓选择 = 自身 + 全部子仓聚合，
   点行暂存，确定后关闭并重查；取消/关闭不改变筛选。刷新按钮重载字典、分类树与当前查询并回第 1 页；搜索中刷新保留仍有效的
   当前分类，刷新期间的新输入或手动选择优先。从库存详情返回则重查原页。
4. 表头设置列多时显示明确的竖向滚动条，库存数量、库存重量、待检量、合格待入库、
   多排数量均可独立显示/隐藏；每个选项至少 44dp 高。
   默认列顺序为：货品名称 → 编号 → 颜色 → 库存数量 → 库存重量 → 待检量 → 合格待入库 → 多排数量 →
   库位号 → 主档归属仓库 → 所属类型 → 型号 → 规格 → 客户型号 → 物料系列 → 备注。
   先辨认货品与颜色，再查看库存和待处理数量，位置与主档属性放在后面；仓库资料内共享库存表沿用同一顺序。
   旧完整默认列序且无固定列的库存表采用新版默认顺序，保留隐藏列、列宽与附加列；用户自行调整的列序或固定列继续保留。
5. 数量/重量/多排数量/名称支持表头排序（回第 1 页）。
5a. **列头筛选**（2026-09-16 补齐）：归属仓库列之外，**颜色 / 系列**两列也可从列头
   下拉筛选（桶由列表响应 facets 下发：颜色 UUID / 系列文本；空值走「其他」桶），
   与搜索/分类/仓库筛选叠加生效、翻页保持。原「单位」列头筛选随独立「单位」列退役
   （2026-10-10「数量+单位」全站口径：库存数量/待检量/合格待入库/多排数量单位内联在
   数字后，单位不再占列）。
6. 数字列复用统一数量格式，保留库存最小精度（如 0.0001）及单位；null 显示「—」。
7. **行点击 → 库存详情页**（`RouteName.stockItemDetail(goodsId)`，push 保活本页筛选）：
   单货品各仓余额 + 出入库流水 + 单重学习(2026-09-28 起三段面板，见[库存详情页](库存详情页.md))。
7a. **重量单位**(2026-09-28)：工具条「重量单位: 自动▾」只改显示单位(账号级偏好，即时库存 / 库存详情 / 库存分析 /
   仓库报表共用)，不改存储；重量列、合计条与预览打印按所选单位换算，导出按所选固定单位(自动 = 千克)。
8. 加密 Excel 导出（report=`instant-inventory`，导出参数与当前筛选/排序/不良仓开关/
   搜索关键词同步）。
9. **表格下方合计条与库存分析**（2026-09-30，`MasterDataTableView.summaryBar`）：
   表格下方仅显示合计库存重量与「查看详情」，点击后打开独立库存总览页。数量、待检量、
   合格待入库的单位明细与分析说明在新页面内展示，避免挤占库存表。
   - 详情标题为「库存总览与分析」：重量概览、智能摘要、库存分布、重量数据覆盖、按单位统计与
     可展开的计算口径。外壳沿用 `UtenAppBar` 和 `UtenContentContainer.wide`；
     桌面按分析内容分区，手机及较大字号下纵向排列，使用整页滚动。
   - 总览按 URL 范围独立查询，以 `size=1` 获取服务端全集 `totals`，不对这一行求和；
     页面可刷新，成功响应标明更新时间，旧请求不能覆盖新范围或新风险分类的结果。
     当前筛选没有货品时显示空范围和返回调整筛选入口，不把空结果解释成旧服务端缺少分析。
     列表刷新和搜索防抖期间显示「统计更新中…」，
     列表查询或搜索失败时显示「统计暂不可用」；这些状态均禁用详情入口，避免把上一次响应当作当前范围的结果。
   - **值全部来自服务端**：本页服务端分页，前端对当前页求和会得出一个看着像总计、其实只
     覆盖一页的数，比不显示更糟。后端把列表查询本体（core）原样包成派生表再 `SUM`，
     派生表内不带 LIMIT/OFFSET，所以合计覆盖整个结果集。
   - **和表格显示的是同一批行**：分类子树、仓库范围（含父仓子树聚合 / 仅参与核算仓）、
     「含不良品仓」开关、关键字这四个筛选全在 core 里，改任何一个都同时改变列表与合计，
     不可能对不上——这是本页最容易踩的坑（一行 = 一个货品×颜色的跨仓聚合）。
   - **数量按单位分组**：详情分别展示库存、待检、合格待入库，各单位独立统计，绝不把「个、箱、米」相加。
     三项都为零的单位不显示；单位缺失保留「单位未维护」并提示资料问题，不猜测单位。
     服务端分别返回的 null、空串或空白单位组各自保留，不覆盖丢量，也不当作同一物理单位合并。
     重量合计是已知重量的千克之和，按页面显示单位换算；含估算时加前缀「≈」。
     未称项不算作零重量，详情说明当前合计的覆盖范围。
   - 刻意**没有合计**的两列：**多排数量**来自生产计划行的 qty/oqty/iqty，是计划行单位的量，
     与本行「单位」列（货品主档单位）不是同一口径，按单位分组会贴错标签；**库存台账金额**
     受 `goods:cost:view` 脱敏，合计一旦下发就绕过了列脱敏，等于把成本总额漏给没权限的人。
   - 响应形状：`/api/stock/instant-inventory` 返回 `TotaledPageResponse`
     = 原 `{items,page,size,total,totalPages}` + `totals`；服务端未提供 `totals` 时
     整条合计条不渲染（不伪造 0）。

### 表内位置资料编辑

- 入口需同时具备 `stock:view`、`goods:view` 与 `goods:edit`；只读库存账号不请求货品详情，也不因查看库存获得货品编辑能力。
- 进入编辑模式后，按当前页去重的货品 UUID 懒加载权威 `GoodsDetail`，核对 `writable`、原 `version` 和当前显示的
  库位/归属仓快照。不可写、版本缺失、读取失败或位置快照已变化的货品保持只读，并提示刷新核对。
- 只开放 `stockPlace`、`owningWarehouseId`；仓库选择使用货品资料同一运营用途与服务端可选能力。归属仓只是主档关系，
  不改变顶部实际库存仓筛选，不调拨余额，不修改颜色、数量、重量或金额。
- 保存复用 `PATCH /api/master/inline-edit/goods/{id}`，请求为原 `expected.version` 加本次 `changes`。
  后端沿用 `GoodsInlineEditService` 的登录状态、权限、货品对象可见/可写、行锁、版本冲突、允许字段、仓库有效性与
  货品操作历史与审计。不会拿最新版本自动重试覆盖并发修改。
- 同货品多颜色共用同一草稿，按货品保存一次；已成功货品从待保存集合移除，失败货品保留草稿和错误提示。
- 保存成功重新读取当前库存投影与货品能力；取消是纯本地操作。身份、权限或可信服务器切换立即清除草稿与旧数据。
- 盘点仍走独立盘点会话和审核流程；位置资料编辑不会绕过盘点、调拨或库存价值过账。

### 库存分析的口径与边界

分析中的「项」沿用列表粒度，即货品 × 颜色在所选仓库范围内的一行，并非物理件数，
也不是去重后的货品数。所有计数均来自服务端未分页的同一查询结果，翻页不改变统计结果；
分类、仓库、库存范围、搜索及表头筛选变化时同步更新。

| 指标 | 计算与解释 |
| --- | --- |
| 库存状态 | 按聚合行 `qty > 0`、`qty = 0`、`qty < 0` 分别统计正库存、零库存、负库存项数。负库存需要核对单据和余额，但跨仓正负抵消后的行统计不代表每个仓库都没有负数。 |
| 仓库负余额 | 另计当前筛选内实际仓库余额为负的记录数，单位为「处」。即使跨仓相加后该货品的库存为正，也提示核查这些负余额；旧响应未提供此指标时才回退到聚合负库存项数。 |
| 待检 / 合格待入库 | 分别统计对应数量大于零的行；同一行可同时属于两组，不能相加当成不同货品数。这些数量不直接并入库存，也不能作为已可用的数量。 |
| 无正库存但有待处理量 | `qty <= 0` 且有待检量或合格待入库量的行，提示优先跟进检验或上架；两类可能重叠，不把它们累加成唯一风险项数。 |
| 重量覆盖 | 以数量不为零的行作为有余额项，已知重量项数 ÷ 有余额项数。零库存货品不稀释覆盖率，未知重量不按零处理；已知中含估算的项另行标明。 |
| 单位统计 | 库存、待检、合格待入库分别按单位汇总。只隐藏三项都为零的单位，保留负值与单位缺失，不生成跨单位总数量。 |

智能摘要采用可解释的规则，将负库存、待检/待入库跟进、重量缺失和单位资料缺失整理成建议。
界面展示依据和算法说明，不生成没有事实支持的缺货、周转天数、安全库存、补货量或健康评分。
当前版本没有调用外部 AI，也不因打开分析而修改业务单据或库存。

有库存分析权限时可通过「打开库存分析」进入独立分析页，进一步查看周转天数、ABC 分类、
FIFO 库龄和盘点建议。该进阶分析页使用自己的仓库范围，不继承总览的分类、搜索与表头筛选，入口旁明确说明范围差异。

### 风险明细与跟进

总览中的建议可下钻到同一查询范围内的具体货品。默认选择最高优先级的有效提示，
依次为仓库负余额、无正库存但有合格待入库、无正库存但有待检量、重量未知、单位未维护。
明细通过 `/api/stock/instant-inventory/attention` 传入 `attention` 查询，最多先展示 8 项，
全部数量以该筛选响应的 `total` 为准；旧服务端没有此端点时明确提示失败，不回退到未筛选的库存列表。
切换提示和刷新时清除旧提示下的明细，失败提供重试，不保留伪装成新分类的旧行。
窄屏点击处理建议后自动滚动到对应清单，避免用户在长页面里寻找结果。

| `attention` | 服务端筛选口径 |
| --- | --- |
| `NEGATIVE_BALANCE` | 所选仓库范围内至少有一处真实余额为负，即使跨仓相抵后的数量为正也应命中。 |
| `AWAITING_STOCK_IN` | 聚合库存不大于零且合格待入库量大于零。 |
| `AWAITING_INSPECTION` | 聚合库存不大于零且待检量大于零。 |
| `UNKNOWN_WEIGHT` | 非零库存的重量未知。 |
| `MISSING_UNIT` | 货品单位未维护。 |

点击货品进入已有库存详情核查各仓余额与流水，沿用现有页面的只读/授权动作边界。
负余额清单按真实负余额处数降序，其余清单按货品名称排序，并补充货品与颜色的稳定分页次序；
不跨不同计量单位比较数量大小来判断处理优先级。
没有分析指标的旧服务端仍展示数量汇总，但不显示零风险结论，也不按缺失指标发起风险明细查询。
风险规则依据当前余额和待处理事实，没有需求、占用与交期时不推断缺货时点或自动生成补货量。

后续若扩展真实缺货与补货预测，需要接入已确认需求、库存占用、可用量、可靠到货与生产完工日期、
需求/耗用历史和采购交期。需求净额、到期覆盖、安全库存等模型必须与这些来源对齐，
不能只根据零库存比例推断紧急缺货；规则结果可以再交由 AI 解释，但数量与风险依据应保留可追溯的确定性计算。

## 七、权限与边界

- 页面与聚合查询使用 `stock:view`；分类筛选由 `material_category:view` 控制树端点与页面分类入口。
  无分类权限时不发起树请求，库存列表与搜索继续可用；分类权限变化后清除旧树数据。
  加密导出另需 `stock_report:export`。
- 位置资料编辑另需 `goods:view` 与 `goods:edit`，并按货品对象的 `writable` 能力显示编辑器；服务端逐次重验原版本与权限。
- 总览路由、总览刷新和风险明细沿用 `stock:view`，复用 `warehouse.instant-inventory` 权限面；
  直接打开 URL 同样受路由守卫保护。「打开库存分析」仍单独要求 `stock_report:view`。
- `goods:cost:view` 不再改变本页任何可见内容（2026-09-01 起页面与预览打印均无
  库存台账金额列）；该权限仍决定导出 Excel 是否含金额列。**合计条同样不含金额**：
  金额列不声明合计，所以无权限者拿不到成本总额，有权限者也不会在页面上多出一个
  绕过列脱敏的口子。
- 本页不显示 `stock:balance:adjust` 操作，不能在聚合行直接修正库存。
- 数量、重量与金额是三类独立库存事实。数量调整不得伪造标准成本估算；只有携带金额的
  已审核库存流水才改变 `stock_balances.amount_local`。数量与金额不匹配时必须走库存
  价值核对。详细调整、审计和历史订单规则见
  [仓库盘点修正与历史单据处理](../数据迁移/50-仓库盘点修正与历史单据处理.md)。
