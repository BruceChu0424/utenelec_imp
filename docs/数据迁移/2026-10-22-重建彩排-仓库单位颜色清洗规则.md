# 重建彩排：仓库、单位、颜色清洗规则

本规则服务于本地重建彩排。原始备份、原始 CSV、清洗 CSV、Excel 覆盖层分别保存，不能改原导出清单或把派生文件冒充老库原件。正式换新备份后，重新完整导出并重跑本流程。标记“首版/旧快照”的数字是过程证据；文末 `sealed` 数字来自本次最终封存输入的独立复核，仍不代表业务导入或生产验收已完成。

## 运行顺序与产物

1. 协调器验证原始导出的完整性与 SHA-256。
2. 运行 `server/legacy_migration/prepare_clean_master_data.py --source-dir <原始CSV目录> --output-dir <新的清洗目录> --excel-dir "D:/uten_legacy_inputs/product lists"`。
3. 运行 `server/legacy_migration/prepare_excel_reference_masters.py --source-dir <清洗目录> --excel-dir "D:/uten_legacy_inputs/product lists" --output-dir <新的引用主档目录>`，补全 Excel 明确指向的供应商、模具主档及安全别名。
4. 运行产品 Excel 覆盖程序，优先消费引用主档目录的 `supplier.csv`、`mould.csv`、`excel_reference_mapping.csv`，其余字典回退到清洗目录的 `unit.csv`、`color.csv`、`warehouse_crosswalk.csv`；不能重新写回被归并的旧 ID，也不能把新模具显示号当成原模号匹配。
5. 运行 `server/legacy_migration/audit_unassigned_stock_warehouses.py --clean-dir <清洗目录> --overlay-dir <产品覆盖目录> --output-dir <新的归属复核目录>`。依据清单核对主仓待拆分余额，先保全事实，再决定运营归属。
6. 生成中性材料身份层及 BOM 拓扑证明；拓扑程序为 `validate_legacy_bom_topology.py --goods-csv <最终goods.csv> --bom-csv <清洗goods_bom.csv> --output-dir <新的拓扑目录>`，检查实际保留边、排除边、重复父子与全图环，不按分类树冒充组装层级。
7. 协调器将各层已验证的输入组成最终包，整事务导入并对账；导入执行、包级复核和用户验收分别留证据。

清洗目录包含完整派生 CSV、`master_mapping.json`、`master_reference_changes.csv`、`stock_balance_warehouse_audit.csv`、`stock_balance_negative_exceptions.csv`、`clean_master_manifest.json`。最后一份清单绑定原始清单摘要、原始每文件摘要、Excel 摘要、程序摘要和输出摘要；下游必须验证这些关联。

## 单位

- 编号采用系统前缀 `DW`，从 `DW000001` 起。旧整数 ID 仅作为引用溯源，不能用旧编号当新显示编号。
- 清除控制字符和首尾空白；`个` 与 `个\x01` 归并；两条 `套` 归并；Excel 的 `千克`、`公斤` 仅作为 `kg` 的名称别名。
- `0.1`、`0.12`、`0.01` 等数字不是单位，不把这些数字当成换算率；无引用的污染字典不导入。
- 有引用的污染单位：只有冻结换算率为空或等于 1 时，才按该交易对应货品的可靠基本单位更正关系，保留原始 `qty`、`unit_rate`、价格、金额、实际重量。非 1 换算率缺少可证明的原计量单位时程序中止；不能根据单位名称计算新的数量。
- 货品本身的基本单位为空名时，必须有 Excel 同名且基本单位唯一的证据，否则程序中止，不能统一猜成“个”。
- 本轮旧快照中，单位 283 对应的 4 个货品均有 Excel 明确“个”；单位 242“1”的 3 条交易和单位 249“3”的 1 条交易能按货品基本单位解决。最终字典从 66 条收敛到 22 条。
- 新 Excel 若出现超出现行有效单位清单的名称，需审阅扩充清洗规则，不能静默接收新污染。

## 颜色

- 编号使用 `YS000001` 起；移除尾部误录句点、逗号，处理清楚的名称别名：兰色→蓝色、透明色→透明、透明蓝色→透明蓝。
- 不合并不同材质、涂层、色号或触感的颜色，如“电镀铂金”与“铂金”、“肤感黑色”与“黑色”。历史 `ABS` 标记有真实引用，不能据名称直接删除或猜成某个颜色。
- 空名、“无颜色名称”、纯数字噪音没有可证明的具体颜色，统一保留“未注明颜色”维度及旧标签审计，不猜成白色或黑色。旧颜色 638 空名有 10,894 个引用；纯数字 692 仍被 BOM 明细 477733 引用一次，不能直接删引用。
- Excel 中的新有效名称补入派生字典。派生独有身份使用负整数命名空间，和 SQL Server 正整数原始身份分离；显示编号仍是正常 `YS` 流水号。
- 本轮旧快照规范颜色为 137 条。若新备份改变颜色及引用，以新清单为准。

## 仓库

- 仓库编号按源码 `MasterCodePrefix.WAREHOUSE` 使用 `WH`，主仓为 `WH000001`“主仓库”。原主仓的“14年版”属于旧称，不再作为运营名称。
- 继续执行唯一主仓、直属子仓的两层结构；主仓仅汇总，不承载库存余额和实物流转。
- 五金仓库只保留一个。Excel 同时存在“五金仓库”和“五金车间”两种所属仓，它们用途不同，不能仅因名称含“五金”合并。
- 老仓 123 禁用不代表没有真实历史，按审过的对照归并到在用的唯一五金仓；老仓 119/120/121/124/125/127/128/129/130/131 已删除，继续按 `DROP` 隔离并记录原始事实，不复活库存根。
- 不把 `B_Storage.WorkID` 当车间 ID；它属于 `Sys_Operator`。货品 `ck` 中既有老仓 ID、已删除仓，也有 0/16 等异常，不能直接全部当作可靠归属。
- 标准目标为 9 个仓库。现有 `expected_warehouses` 指保留旧身份的仓库数，本轮为 6，不能误改成 9；最终结构另外断言总仓 9、主仓 1、五金仓 1。

## Excel 供应商和模具引用完整性

不能把 Excel 已明确存在的供应商或模具一律只放备注。引用主档层先以原始主档身份匹配，再补来源确证的新档：供应商可用唯一旧名称或唯一完整 `description` 全称，明确的短名扩展不能与已有全称矛盾。同一短名指向多个旧身份时，不按“使用/禁用”状态擅自挑一个。原模号精确匹配可复用身份；旧模号去掉尾部 `【B3-07】` 这种库位标记时，必须同时有 Excel 模具名称与旧名称精确一致。只有单一明确编号和一致有效模具名称才能新增模具，数字 `1`、“外购”、混合编号和一号多名不造档。

新供应商联系人、地址、银行资料、结算资料为空；新模具的制造日期、保管人、穴数和存放位置为空；不从产品属性猜这些主档事实。名称明确标“封存/停用/报废”的新模具不设为在用。新身份使用稳定负整数，继续保留旧正整数身份；所有供应商、模具显示码分别从 `GY000001`、`MJ000001` 重排，原始代码及外部模号完整保存在 `original_master_codes.csv` 和备注中。这样不会与旧模具重复代码的 SQL 兜底派号发生碰撞。

`excel_reference_mapping.csv`、`ref_dictionary_aliases.json` 保存来源值→身份及命中依据；`excel_reference_conflicts.csv` 保存未能证明的身份冲突。`reference_masters_manifest.json` 绑定本程序、清洗层输入及其父清单、每份 Excel、每个输出，不能跳过这一层摘要校验。

本轮引用层实测：供应商 386→390，新增井源、旺国电器有限公司、正杰、海能；模具 1,605→1,609，新增 V9-001、W50-01、W50-02、W50-03，其中 W50-01/02 的来源名明确“封存”，保持禁用。131 个供应商来源名字、1,408 个模具来源编号匹配已有身份，解决 3,001/3,645 个字段引用。仍有 7 个供应商同短名多身份（51 个引用）、48 个模具噪音/码名冲突（238 个引用），保存待核清单，不制造新身份掩盖冲突。数字为原始字段引用次数，不等于最终新建主档或货品行数。

## 库存守恒与待核对归属

StockGoods 的年初 QTY 不可跨年相加当当前库存。先按原始仓+货品+颜色取最后年度；同年库位行按现有导入器求和；FactQTY 仅在 NULL 时才回退 QTY，真实的 0 必须保留。然后归并颜色、合并目标维度。颜色归并前若直接先改 ID 再取最后年度，会丢掉另一颜色别名在较早年度的最后余额。

旧快照验证：454,104 年行→45,611 个原维度最近余额→45,360 个规范维度。数量、有效 FactQTY、金额、原始重量与实称重量的 Decimal 数值校验和前后一致。这些跨单位数量校验和只证明转换守恒，不是业务上可相加的库存总量；旧 Weight/FactWeight 仍没有可证明的质量单位，现行库存导入器不得据此声称 kg。

源已删除仓 131 的最新 FactQTY 数值校验和为 -999,988,702.3000，是不应复活的历史污染。各仓排除数、金额和极值必须看 `stock_balance_warehouse_audit.csv`；所有负余额单列 `stock_balance_negative_exceptions.csv`。负数不归零、不取绝对值、不猜成盘点调整。

主仓需要按可证明的货品所属仓拆分。Excel 无证据时，复核程序比较旧 `ck` 的在用良品子仓、同一分类下 Excel 兄弟货品的一致归属、该货品其他在用良品子仓的最后非零库存。至少两个独立证据族一致且无冲突才列为“佐证充分的建议”；程序不会自动改动归属输入。无证据、单一证据或冲突的事实保存在逐维度 CSV，不可直接丢弃。

`migrate_stock_docs.sql` 支持 `uten.legacy_unassigned_warehouse_code`，但这个设置不代表可以绕开仓库规则。V800 禁止仓库有库存后再停用，不能用“先导入再禁用”制造规则例外；也不能把未知质量冒充不良品。不明库存应在可审计的隔离事实中保全，只有确定真实运营仓后才计入可用库存。当前导入器会持久保存 `UNASSIGNED_OWNING_WAREHOUSE` 的货品、原始颜色/年、数量、金额；具体隔离去向需在整体彩排中落实并验收。

## V903 禁用组件的历史 BOM 隔离
