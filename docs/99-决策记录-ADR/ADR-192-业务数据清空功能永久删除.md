# ADR-192：业务数据清空功能永久删除

- 日期：2026-10-23（America/Denver）
- 状态：源码实施；服务器随下一次正式发布执行受控迁移，现场升级另验。
- 替代范围：ADR-067、ADR-155 中业务清空入口、执行链、测试清空保护例外和重新启用步骤。历史文档及已存在迁移原字节保留，不再构成当前使用指引。

用户要求彻底下架工作台清空业务数据功能并删除相关代码。仅隐藏按钮、关闭环境变量或撤销应用账户权限仍会保留可恢复的破坏性执行链，不能满足这次要求。

客户端删除工作台系统测试区、清空弹窗、仓库、待确认记录读写、API 端点、专用权限及翻译文案。开发环境、回环地址和超级管理员都不例外。使用 `frontend-design`，保持现有 Uten 组件、主题和其他业务入口。

服务端删除清空 Controller、Service、附件物理清理实现、排水闸、过滤器、专用端口、开关和错误码。调度器保留服务器状态观测与正常关闭，AI 任务保留租约、取消和旧结果代际隔离，移除清空排水分支。旧接口即使由已认证超管调用也不再映射。历史清空审计名称继续可读。

V919 前向迁移删除数据库清空入口和专用 helper、权限目录及四类当前授权关联，清理活动权限模板 JSON 中的旧权限码；已删除模板的不可变历史保留。移除历史保留与审计触发器中的测试清空绕过分支。正常运行维护保留原 owner 成员边界，替换为独立刷新 helper。迁移不调用旧函数，不删除业务记录、主档、媒体或审计，不通过 CASCADE 隐藏未知函数依赖。历史 SQL 保持原字节，空库顺序迁移也必须最终移除清空能力；新表不再登记 CLEAR/PRESERVE 清空分类。

保留 `business_reset_generation` 的既有值及通用读取协议，防止升级后重新读出旧草稿或接收历史 AI 结果。这是历史数据兼容，不提供任何推进清空的入口。备份、恢复与配置迁移保持各自受控流程。

所有 Nginx 模板继续封闭旧 `/api/system-test/` 命名空间。正式更新必须把 V919 纳入完整签名发行 SQL 集，通过现有备份、独立 migrator、应用重启及健康核验完成；不能只更新客户端。回滚到含旧清空实现的版本或恢复旧备份时，先保持旧路径封闭并重新执行永久下架迁移。

验收分别记录前端入口回归、Java 编译、完整 Spring/MockMvc 请求链中的旧接口 404、隔离 PostgreSQL 旧库升级及空库迁移、业务与历史保护、部署模板验证。源码和隔离测试不代表已提交、CI 通过或公司服务器已升级。
