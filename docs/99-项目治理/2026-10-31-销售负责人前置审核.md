# 销售负责人前置审核

状态：本地代码已实现，尚未部署或正式打包。工作分支 `uimp/sales-manager-review-20261031`，基线 `1d693e8f1`；主体实现提交 `327d96846`；备注保留修正提交 `efd8ef9b0`。

用户要求：综合营销部工作台在销售管理前增加“订单审核”；报价单及订货单先由被授权的销售负责人审核，通过后再交财务。首位指定负责人为朱舜炜，后续能授权其他人。用户特别要求仔细验证完整流程。

界面按 `frontend-design` 复用现有 Uten 主题、字体尺度、圆角和间距。工作台沿用营销组青绿色；审核队列采用现有表格与分段，主信息左对齐。视觉重点放在明确的审核阶段和批准/驳回动作，批准提示说明下一站是财务。详情、附件、修订记录、认领失败、窄屏及深色主题均沿用公共组件。

## 状态与权限

新提交：销售提交 → 负责人待审核 → 负责人批准 → 财务审核 → 后续原业务链。

负责人驳回必须说明原因。报价回销售草稿；订货保留预留和原始事实，经销售受控修订回草稿后重提。销售修改已审核订单或改量后，原负责人批准失效。财务编辑报价是本级既有核价职责，不冒充销售修改。

负责人反审核只撤销本级批准，财务正在认领或已经通过时不允许。已进入下游的订单继续受原库存、计划、发货和反审守卫约束。两级批准、驳回、人员、时间与历史分别记录。

`sales_quote_manager` 和 `sales_order_manager` 各有 `view`、`confirm`、`reject`、`reverse`，权限面为 `sales.manager-review`。权限决定审核资格，不依赖姓名或部门硬编码。新权限遵守 V936，不能自动授给普通销售或财务。

首位负责人的只读授权核对脚本为 `server/maintenance/sales_manager_review_authorization_preflight.sql`，核实朱舜炜的唯一启用账号并输出既有管理员分组加授 API 请求（`综合营销部 / 订单审核`，恰好八项）。执行授权仍走已有超级管理员身份、一次性再认证、账号生命周期锁和审计流程，不直接改授权表；分组加授保留其他授权。后续授权继续使用权限设置。本次未执行公司环境授权，不表示现网账号已经获得权限。

V978 保留历史已办结的原审核事实，不补造负责人批准。尚未财务通过的有效待办进入负责人阶段，旧财务认领和提醒退役。现有业务原单与审计保留。

## 居中审核通知

提交报价或订货后，实际拥有对应 `view` 与 `confirm/reject` 权限的在职启用账号收到通知中心记录、在线提醒及既有 `ReviewPendingDialog` 居中弹窗。只有查看或反审核权限不加入待审接收池，超级管理员隐含全量目录权不自动订阅。

登录补查与在线到达轮询都按当前实际授权补齐仍待审任务，每类每轮最多 20 张，按原单表头锁 `SKIP LOCKED`，仅补缺少的当前用户通知；中途新授权及迁移时已有待办也可补提醒。已有提醒不被重建或反复置未读。两种任务合并到同一个“订单审核”工作台，单种直达对应报价/订货分类。

办结、驳回、撤回、反审核、取消及重新提交按本级事件办结旧提醒；权限撤销后实时可见性校验阻止继续弹出。租约状态仍由公共心跳显示“某人正在审核”，其他人办结后弹窗自动移除该项。用户原有弹窗偏好和稍后再看语义保留。

管理审核详情及动作响应使用 `reviewStage=SALES_MANAGER`、`reviewContractVersion=1` 和 `reviewApproved/reviewActions/reviewRevision` 等中性字段，不把负责人通过写成 `financeConfirmed`。两端共享样例见 `contracts/sales-manager-review/v1.json`；Dart 适配至现有审核展示模型，WPF 对应入口仍为未迁移。
