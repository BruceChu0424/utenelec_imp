# 业务辅助选择前端来源同步

本修复延续生产 2.5.43 `bd7e8525be1ef52db2a6cfb10268fdbd8310844c` 上的业务人员引用修复。已有新建、编辑、收货等动作包含该动作需要的辅助选择；不另授员工档案或主档查看权限，也不因此开放主档详情、财务资料和修改入口。本次不改变任何真实授权配置、产品版本或数据库迁移。

## 公共维护入口和适用调用方

| 公共入口 | 默认业务读取来源 | 保留的差异 |
| --- | --- | --- |
| `showUtenSupplierPicker` | `/business-references/suppliers`、供应商最小分类树、纯读搜索及分类位置 POST | 原可选状态、分类分页、确认后回写及单独的供应商新增权限保留；只显示编号、名称、状态 |
| `showUtenClientPicker` | `/business-references/clients`、客户最小分类树、纯读搜索及分类位置 POST | 原历史客户开关、迁移财务占位项排除和服务端候选范围保留；只显示编号、名称、状态 |
| `showUtenGoodsPicker`、多选及输入建议 | `/business-references/goods`、分类树、分类位置、物理字段 facets 和远程分桶 | 原分类根限制、超过32根分批、分页、去重、列条件、相关搜索、失败关闭和身份边界保留；默认仅名称、编号、系列、型号、规格、颜色、单位 |
| `MasterDictionaryRepository` 原账户、仓库和部门键 | 对应 `/business-references/accounts`、`/warehouses`、`/departments` | 原缓存键、单飞、身份隔离及写后失效不变；账户来源不含余额或银行账号，仓库保留原服务端选择标记 |
| 委外损耗现金赔偿 `_loadCashAccounts` | 独立 `businessAccountReferenceRepositoryProvider` 的最小账户字典 | 原 `subcontract_loss_claim:fulfill`、资金类型、使用状态、数量、金额、日期、证据、版本及提交命令不变；账户余额核对等原完整 `.dict()` 不改 |

`business_reference_repository.dart` 只配置业务选择所用的仓库实例。Dio 查询实现仍是现有唯一实现，使用可选 `queryBasePath`、分类 `treePath` 或账户 `dictPath`；原主档 provider 默认源、详情及全部 CRUD 端点保持原样。客户和供应商列表解析额外裁掉辅助选择不需要的字段。公司显示名称由服务端保留“简称为空则公司全称”规则，仍通过同一个 `name` 返回。

明确提供的货品 `dataSource` 继续沿用自己的库存或报表来源、列和业务资格，没有切成无范围的默认货品查询。主档页面和账户余额核对不使用上述业务最小读取来替代原权限入口。共享选择器内部未发现为回填而主动读取完整主档详情；邻近的采购、销售、委外来源单据详情属于原业务链，未改动。

## 隐私和生命周期合同

客户、供应商关键词继续放在 POST 请求体，避免用户粘贴的联系方式进入 URL。`search` 和 `search-context` 四个新精确 POST 标为纯读取，不推进业务写修订号；其他 POST、未知提交和自动重试规则不变。面板保留现有会话、权限、服务器和范围版本围栏，过期响应、跨身份结果和混合版本的分类元数据不能回写。

业务侧栏不显示联系人、电话、地区、银行账号、税号或财务余额，不增加主档跳转。只取得辅助引用，不会获得主档写权限或改变单据本身的数量、金额、归属和后端校验。

## 多端和验证边界

Web 与现有 Flutter 桌面共用这些 Dart 入口。Win7 原生仓库4个对应业务仍是 `W7-BIZ-176/178/207/208` TODO；现有 WPF `GoodsReadService` 是按原 `goods:view` 读取的货品主档页面，不是本次已迁移的业务选择侧栏，不改其来源来放开主档。本次没有实现完整原生 ERP、修改共享进度或标记 Win7 已支持。

本地回归88个唯一用例通过：最小引用字段、原主档详情和账户完整字典边界、原货品分批算法、分页、搜索、列条件、主题、放大、范围 ABA、纯读修订号，以及无账户主档权限的现金赔偿选户和原命令验证。旧的联系人/电话列断言按本次明确要求改为“不得显示”，其余安全和行为断言保留。另实际渲染并查看浅色、深色、390宽窄屏、1.6倍放大四种本机测试场景截图；它们是合成测试资料，不冒充现网截图。后端真实数据库和HTTP授权验收由对应后端任务单独提供。

## 2026-11-02 发布集成的后端边界修复

本次集成的架构回归实测发现 `master -> org` 新依赖：辅助主档权限直接调用人员引用服务，部门引用控制器直接使用组织部门服务及其私有 DTO。修复通过 `application.port.CurrentStaffAuthorityPort` 保留原 `BusinessEmployeeReferenceAccess` 的真实在岗、账号状态和最新授权快照校验；部门树沿用既有 `OrganizationReferencePort`，由组织适配器委托原 `DepartmentService.employeePickerTree`。唯一的六字段 `DepartmentPickerNode` 移入 application port，全部组织、人员和辅助主档调用方使用同一份投影，不复制树算法，不扩大允许的模块依赖表。

这是服务端代码边界修复：HTTP 字段、业务权限和候选范围不变，Web、Flutter 桌面及后续 WPF 调用的合同不变，原生未迁移状态不变。验证入口为 `ArchitectureBoundaryTest`、`OrganizationReferenceAdapterTest`、`DepartmentEmployeePickerSecurityContractTest`、`BusinessMasterReferenceHttpPostgresTest` 和 `BusinessEmployeeReferenceHttpPostgresTest`；本次集成的执行结果在发布回执中按实际源码单独记录，不能沿用上段的历史前端测试数。
