# 11 - 颜色资料 · 新库设计与老库迁移

> 本档记录新系统颜色资料（`colors` 主档，扁平）的表设计、迁移代码用法、校验结果。

## 一、为什么扁平（不分树）

老库 `B_Color` 实测 `ParentID` 全为 0（151 行无一嵌套），是**扁平字典**（见 [10](10-颜色资料-老库溯源.md) §一）。故新库颜色**不建分类树**，只有一张扁平主档表 `colors`，业务字段仅 `编号/名称/状态`。这与四主档「分类树 + 主档」双表结构不同，更简单。

> 早期 README 曾占位 `colour_categories`（仿模具走独立树），本次据实地探查**改为扁平 `colors`**，并统一命名美式 `color`（与既有 `goods.color_legacy_id` 一致）。

## 二、新库表设计

### `colors`（主档，Flyway `V39__color.sql`）

```
id(UUID PK, default gen_random_uuid()) · legacy_id(INT UNIQUE=B_Color.ID)
code(Number 编号，V77 起全局 UNIQUE) · name(ColorName) · status(使用/禁用，V77 起 CHECK)
审计4列(created_at/updated_at/created_by/updated_by) · is_deleted · deleted_at
```

- 索引：`legacy_id` / `code`（V77 加全表唯一 `colors_code_uq`，`WHERE is_deleted=false`）/ `status`。
- **编号唯一性（V77）**：老库 `code` 大量重复（如 `01` 挂 18 个不同颜色名）。V77 就地 renumber——每个 code 保留首条（MIN id），其余改为 `YS######` 唯一新号；新建由 `MasterCodeService` 自动生成。**引用安全**：所有跨表引用走 `id`/`legacy_id`（如 `goods.color_legacy_id`、各 `*_items.color_id`），无表按 code 引用，renumber 只改显示编号，引用恒正确。详见 [基础资料页](../03-页面/基础资料页.md)。
- 继承链：`Color extends SoftDeletableEntity`（id/审计/软删）。
- `updated_at` 由 JPA `@LastModifiedDate` 维护（与 goods 同，无 DB 触发器、无 `@Version` 乐观锁）。

## 四、后端 API

`/api/master/colors`（**扁平，无 categoryId**）：

- `GET /api/master/colors?keyword=&nullFields=&code=&name=&status=&page=1&size=20` → 分页（`PageResponse`）
- `GET /api/master/colors/facets` → 各字段（编号/名称/状态）可选值桶 + 空值计数
- `GET /api/master/colors/dict` → 全量字典（货品编辑表单选颜色用，按名排序）
- `GET /api/master/colors/{id}` → 详情
- `POST /api/master/colors`（`color:edit`）→ 新建
- `PUT /api/master/colors/{id}`（`color:edit`）→ 编辑
- `DELETE /api/master/colors/{id}`（`color:edit`）→ 软删

请求体 `ColorSaveRequest`：`name`(必填) / `code` / `status`。
包 `com.uten.imp.features.master.color`（`Color` / `ColorRepository` / `ColorService` / `ColorController` + 6 DTO）。范式同 `GoodsService`，去掉 `categoryId`/子树。

## 五、老库迁移代码（仅 Shell 一条路径）

| 路径 | 用途 | 文件 |
|---|---|---|
| **Shell** | 主档批量 | `migrate_color.sql`、`migrate.sh --color-data` |
| **导出** | 老库 → CSV | `export_legacy.ps1 ColorData`（→ `data/color.csv`） |

> **无 Java 迁移器**：Java 端 `legacy/` 只迁 `SystemItem` 分类树（按 `ItemclassID`）；颜色是独立扁平表（非 SystemItem），走 shell 批量即可。

### 5.1 设计要点

- **扁平入库**：无树/无 parent，仅 `legacy_id/code/name/status`。
- **trim + 空串→NULL**：`NULLIF(BTRIM(name, ' ' \|\| chr(12288)), '')`。
- **保留噪音**：尾点/逗号/重复名原样，保证货品引用不悬空。
- **幂等**：`TRUNCATE colors`（`session_replication_role=replica`）后 COPY+INSERT。

## 七、迁移校验（实测，2026-07-25）

```sql
SELECT count(*) AS total,
       count(*) FILTER (WHERE status = '使用') AS in_use,     -- 141
       count(*) FILTER (WHERE status = '禁用') AS disabled,   -- 10
       count(*) FILTER (WHERE name IS NULL) AS blank_name     -- 1
FROM colors;
-- ✔ 颜色 总 151，使用 141，禁用 10，空名 1
```

**结果**：151（使用 141 / 禁用 10 / 空名 1）——与老库 `B_Color` 完全对账。trim 生效（` 套` 类前导空白已清）。`--all` 幂等重跑通过。

## 八、前端（与货品/模具/客户/供应商同级）

- `/basicinfo` → 基础资料 hub：新增 **颜色资料** 卡片入口（`palette` 图标）。
- `/basicinfo/color` → **颜色资料页**（`ColorPage`）：**扁平列表**（无分类树），标题行 `[图标][颜色(N)][搜索框][添加]` + 全屏 `MasterDataTableView`（搜索/autofilter/分页）+ 点行详情弹框 + 新建/编辑/删除（复用 `showMasterEditDialog` / `showMasterDetailSheet`）。
- 列：编号 / 颜色名称 / 状态（与货品表格风格一致）；详情行加 `旧编码`(legacy_id) 便于溯源。
- **货品颜色名称解析（完整链路）**：① 货品表「主颜色」列 + 详情行按 `colorLegacyId` 解析显名称（`GoodsService` 批量查 `colors.name`，孤儿/`0` 哨兵回落 `#id`）；② **筛选下拉显名称**（货品 facets `colorLegacyId` 桶加 `label=名`，前端显 label、筛 value）；③ **货品编辑表单可选颜色**（`MasterEditDialog` 的 `select` 字段，选项来自 `/master/colors/dict`，提交 `colorLegacyId`）。单位同理（见 [13](13-基本单位-新库与迁移.md)）。
