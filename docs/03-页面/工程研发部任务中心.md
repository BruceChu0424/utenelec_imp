# 工程研发部任务中心

> 路由：`/rd/tasks`(`RouteName.rdTaskCenter`) · 实现源：`lib/features/rd_task/`(model/repository/count provider/page) + `dashboard/widgets/module_badge_sum.dart`
> 上层：[工作台首页.md](工作台首页.md) 的「工程研发部」分区「任务中心」卡片
> 数据源：`rd_tasks`(审计触发器 `fn_audit`) + `rd_task_forwarders`(「完善 BOM」任务的等待名单)
> 业务依据：[ADR-143 委外按工序领直属物料与分批回厂](../99-决策记录-ADR/ADR-143-委外按工序领直属物料与分批回厂.md) §二.3(委外件缺 BOM 转研发)
> 最近更新：2026-10-04(委外件缺 BOM 自动建「完善 BOM」任务、研发保存 BOM 自动完成并自动刷新物料分析；同日复核：来源加生产计划确认执行计划包，物料分析改为每张一条刷新事件、失败自动重试)

## 一、定位

工程研发部的统一任务队列。最主要的一类是系统自动建立的「完善 BOM」任务：**委外件必须先有 BOM(可发外的直属物料)才能下达委外、下委外订货单**，
计划或委外被挡住时系统自动通知研发，研发补好 BOM 后计划那边的物料分析自动更新组件表。另有设计、打样、试产、ECN 和其他工程任务。

- 解决的问题：缺 BOM 不再靠口头催；同一货品只建一条任务，所有被挡住的人进等待名单，研发一保存就逐个通知、计划不用手工刷新。
- 产品位置：工程研发部工作台分区「任务中心」卡片；`WorkbenchCardBadge` 统一红色数字角标，数据来自 `rdTaskCountProvider`。
- 与物料反查(`production_where_used:view`)解耦——后者是只读查询，本页是任务流。

## 二、入口与导航

- 进入路径：工作台「工程研发部」分区 → 「任务中心」卡片 → `/rd/tasks`；「请完善 BOM」通知卡片也直达本页。
- 路由权限点：`rd_task:view`(默认授工程研发部；超管经 `PermissionResolver` 全集自然可见)。
- 离开去向：点行打开关联货品的详情整页「组装信息」页签(`/basicinfo/goods/:id?tab=bom`)维护 BOM；货品详情的读取与编辑权限由货品页自己判断。

## 三、「完善 BOM」任务从哪里来

「缺 BOM」= 委外件没有一条可发外的直属物料(没有 BOM，或直属边全部是按包装/固定批次、出货阶段、整批定期领料、用量为 0 或系统占位)，
唯一判定是数据库函数 `fn_subcontract_draw_edges(goods)` 没有任何行。以下场景发现缺 BOM 时，系统自动登记(`RdBomGapPort.forwardBomGap`)：

| 来源 | 什么时候 | 等待人 | 任务来源单号 |
|---|---|---|---|
| 物料分析 | 新建或刷新分析发现有需求的委外节点缺 BOM(需要数量大于 0 或挂着有效的委外供给分配；需求为 0 的节点不登记；分析提交后再登记，不拖慢分析) | 分析制单人 / 当前操作人 | 分析编号 |
| 物料分析下达委外 / 汇总下单 | 下达被拒(409「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善，研发保存后物料分析会自动更新」) | 当前操作人 | 分析编号 |
| 委外任务中心申请行 | 研发任务被取消而 BOM 仍缺时，委外人员点「通知研发完善」 | 当前操作人 | 委外申请单号 |
| 委外订货单提交财务 | 提交被拒(409「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」) | 当前操作人 | 委外订货单号 |
| 委外订货单财务批准 | 兜底检查被拒 | 订货单制单人 | 委外订货单号 |
| 旧/手工生产计划确认执行计划包 | 按缺口生成委外申请前检查，确认被拒(409「委外件 X 还没有维护 BOM(直属物料)，已通知研发完善」) | 当前操作人 | 生产计划单号 |

- **同一货品只有一条未完成任务**(唯一索引 `uq_rd_tasks_open_bom`)。后来发现同一缺口的人只加进等待名单(`rd_task_forwarders`，同一人只记一次)；并发登记撞唯一索引时复用先建的那条。
- **只有新建任务时才通知研发**：工程研发部持 `rd_task:view` 与通知阅读权的人收到「请完善 BOM：{货品名称}({编号})」，正文「…是委外件，还没有维护直属物料，计划和委外都在等。来源 {单号}」，链接本页。
- 登记在独立的短事务里提交：调用方随后报 409 回滚自己的事务，研发任务与等待名单照样留下。

## 四、研发保存 BOM 之后(自动完成与自动刷新)

货品 BOM 每次新增、修改、删除组件都发一条 BOM 更新事件(每次独立事件，不用终生去重键)。事件投递时先确认货品现在确有可发外的直属物料；清空 BOM、或只剩不能发外的边时什么都不做，任务保持未完成。确有时依次：

1. **给物料分析排刷新**：找出所有含这个货品的委外节点、还没按新 BOM 展开出直属物料、仍未结束(负责人账号有效)的物料分析，每张排一条「物料分析按新 BOM 刷新」事件(`MATERIAL_ANALYSIS_BOM_REFRESH`，载荷带上等这张分析的人)。这里只排队不刷新：一张分析刷新要几秒，放在 BOM 事件里会拖住其它通知的投递，某一张失败也没人重试。
2. **自动完成任务**：把它未完成的「完善 BOM」任务标为已完成(备注「BOM 已完善，自动完成」)。
3. **通知不等分析刷新的人**：等委外订货单、委外申请、生产计划的人(以及所等分析不在第 1 步名单里的人)立即收到「BOM 已完善：{货品}」，正文不说物料分析已更新：等单据的是「{货品} 的 BOM 已完善，可以继续下达 / 下委外单」，等物料分析的是「{货品} 的 BOM 已完善，打开物料分析刷新后即可下达」。链接直达各自被挡住的物料分析、委外订货单、生产计划或委外任务中心。
4. **逐张刷新分析(刷新事件投递时)**：以分析负责人身份、在独立事务里只刷新这一张(与人工「刷新」同一套锁)，委外件的直属物料节点随之出现、可以下达。刷新失败原样抛出，这条事件按事件队列退避自动重试，不影响其它分析。刷新完(或这张分析已经按新 BOM 展开)才通知等它的人「{货品} 的 BOM 已完善，物料分析已自动更新，可以下达」，链接这张分析；分析已结束、已删除、不再含这个委外节点或负责人账号不可用而跳过时，改通知「{货品} 的 BOM 已完善，打开物料分析刷新后即可下达」。

研发也可以在本页手动「标记完成」(`rd_task:resolve`，确认后提交，带乐观锁版本)，系统通知任务制单人与等待名单。手动完成而 BOM 仍缺时，下一次分析刷新或下单仍会重新建任务。

## 五、数据与字段

| 字段 | 说明 |
|---|---|
| `task_no` | 系统生成单号 `RD + YYYYMMDD + 6 位日流水`(`DocNumberPrefix.RD_TASK`) |
| `title` | 任务标题 |
| `category` | `BOM`(页面显示「BOM维护」，即「完善 BOM」) / `DESIGN` / `SAMPLE` / `TRIAL` / `ECN` / `OTHER` |
| `status` | `OPEN` / `IN_PROGRESS` / `DONE` / `CANCELED` |
| `goods_id` | 关联货品；「完善 BOM」任务必有 |
| `source_doc_type / source_doc_id / source_doc_no` | 首次登记的来源(物料分析 / 委外申请 / 委外订货单 / 生产计划) |
| `reporter_employee_id` | 首次登记人 |
| `assignee_employee_id` | 责任工程师 |
| `completed_at` / `close_note` | 完成时间与备注 |
| `row_version` | 乐观锁(手动完成必须携带) |

`rd_task_forwarders(rd_task_id, reporter_employee_id, source_doc_*)`：等待名单，派生数据，不单挂审计(以 `rd_tasks` 主体为准)。

## 六、页面结构

1. 分段工具条「草稿 / 待处理 / 进行中 / 已完成」：待处理(`OPEN`)挂红徽章，进行中(`IN_PROGRESS`)挂黄徽章，已完成含已取消。
2. 关键词(任务号、标题、来源单号或货品)与类别筛选(全部类别 / BOM维护 / 设计 / 打样 / 试产 / ECN / 其他)。
3. 任务表格(`MasterDataTableView`，大小屏共用)：单号 / 标题 / 类别 / 货品 / 来源单据 / 责任人 / 创建时间 / 状态；「状态」「类别」两列可表头筛选。
4. 点行打开关联货品的组装信息页签维护 BOM；没有关联货品的任务提示「可直接「标记完成」」。
5. 行上「标记完成」只对未完成任务显示(服务端 `allowedActions`)。

`rd_task_count_provider` 60 秒轮询 `/api/rd-tasks/count`，徽标只反映服务端权威未完成数；轮询失败时保持上一次成功值，不冒充零任务。

## 七、端点与权限

| 端点 | 权限点 | 说明 |
|---|---|---|
| `GET /api/rd-tasks?status=&category=&keyword=&assignee=&page=&size=` | `rd_task:view` | 列表；`status` = open(待处理+进行中，默认) / pending / in_progress / done |
| `GET /api/rd-tasks/count` | `rd_task:view` | `{count, open, inProgress}`：count = 未完成合计，open 走红徽章，inProgress 走黄徽章 |
| `POST /api/rd-tasks/{id}/resolve` | `rd_task:resolve` | 手动标记完成(携带 `expectedVersion`) |

「完善 BOM」任务不能手工新建：只由系统在第三节的场景里登记。委外任务中心的「通知研发完善」是
`POST /api/subcontract/applications/items/{applicationItemId}/forward-bom`(沿用申请分解的权限)。
