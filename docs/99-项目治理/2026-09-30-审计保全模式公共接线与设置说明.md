## 问题与合同

旧页面把在线月数与冷归档月数相加，直接说明到期永久删除；审计概览又把设备回执期限称为中央证据最长保留期。V762 保全候选安装后，这些表述会继续误导使用者。反方向也不能只因客户端升级或配置值保存成功，就宣称数据库已停止销毁。

| 服务器实际结果 | 客户端含义 | 不允许的推断 |
| --- | --- | --- |
| `PRESERVE_UNCLASSIFIED` | 服务器已报告保全；在线转归档继续执行，超过实际总期仅登记保全候选，不自动销毁 | 不代表已经完成异机备份、恢复演练或恢复已删除的数据 |
| `LEGACY_PURGE` | 只有服务器明确返回此兼容值时，说明仍可能按旧规则永久清理 | 不能因函数缺失推断成旧清理模式 |
| `UNKNOWN`、字段缺失、未来枚举值或读取失败 | 尚未核实，不能确认停止销毁 | 不能保留前一次“已保护”的展示作为本次成功读取 |

数据库能力合同由主任务 V762 提供: `public.fn_audit_retention_purge_mode() RETURNS text`。它是无参数只读查询，安装时绑定 `fn_audit_retention_run` 的函数定义与安全配置摘要；定义漂移或缺失返回 `UNKNOWN`。公共 API 不执行留存任务，不通过保存的月数猜测数据库能力。此说明记录主任务交接合同，V762 的 PostgreSQL 验证由主任务独立留存，不计入本项 59 个 Flutter 用例。

## 实现

### 后端公开实际能力

- `AuditRetentionModeReader.java:14` 仅调用无敏感信息的能力函数。缺函数、数据库读取错误、空值和未知枚举回到 `UNKNOWN`，日志只记录异常类名。
- `PublicSettingsController.java:33` 在既有 4 个运行参数外增加只读 `auditArchivePurgeMode`。设备回执月数、附件上限、空闲阈值与角标间隔保留原合同。
- 当前公共设置入口没有外层数据库事务；该入口的缺函数错误被转换为 `UNKNOWN`，不会在同一已失败事务内继续执行其他业务写入。不得据此推广为任意事务上下文都安全。
- `SystemSettingKey.java:95` 将归档追加月数说明改为“超期处置以服务器实际审计保全模式为准”，不再承诺到期必删。
- `AuditRetentionModeReaderTest` 含 3 个纯测，`PublicSettingsControllerTest` 含 1 个纯测。它们的编译及执行由主集成窗口完成，本说明冻结时不声称已通过。

### 共用运行快照及失败处理

- `public_settings_repository.dart` 复用主任务已实现的 single-flight 请求与 `publicSettingsSnapshotProvider`，新增枚举和只读模式字段，没有第二个定时器。
- 新一次请求失败只撤下已核实的保全模式，其余最近已知数字阈值保留。旧账户、旧服务器或退出前的失败回调不能清空新主体的成功快照。
- 快照依赖尚未恢复或不可读取时，派生模式返回 `unknown`，说明区域可继续渲染。
- 系统设置加载审计组后复用公共设置读取；保存审计月数之前再次读取能力。确认框订阅当前模式，框打开期间若后续读取失败，会改为“尚未确认”。

### 使用者说明

页面使用“服务器历史日志保护已启用”“到期后继续保留”“暂时无法确认是否自动删除”等业务语言。函数摘要、能力枚举和数据库分区术语仅放在实现与交接说明中。

- `audit_retention_presentation.dart` 统一三种模式的设置说明、确认文案与审计概览提示，避免相同规则各说一套。
- 输入月数显示在线、追加冷归档与算术合计，同时说明中央规则仍受服务器下限约束。客户端不把输入合计冒充数据库实际执行阈值。
- 保存仅调整月数，不启停保全。旧服务器返回的过时字段说明在审计归档项中用当前中性解释覆盖。
- 本机设备回执属于独立副本，仍按同步到的设备期限和最多 300 条限制清理；清理副本不等于删除中央证据。
- 审计概览仍说明只查询在线记录，较早记录需走受控调查/恢复流程；不再用设备回执月数声明中央历史的最长保存期。
- 确认框允许滚动，在窄屏和放大字体下保持操作可达。
