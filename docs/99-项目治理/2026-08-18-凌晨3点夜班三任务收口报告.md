## 一、任务1：计划前物料分析备料库存绑定（V298）

### 1. 用户问题与模型

生产计划部反馈：旧计划单做过物料分析并下了采购/委外、货已收到入库；再建新计划单做
物料分析时，新计划的备料可用量把旧计划收到入库的货也算进去了。用户的模型：
**计划单与物料绑定**——采购/委外/自制单据关联计划（分析），仓库入库按来源单据归属
回计划；旧计划的物料留在旧计划，新分析只算自己的。

### 2. 根因（夜班在途批次已定性）

物料分析下达的采购/委外订货，到货 IQC 合格入库后**没有任何预留锚点**，直接成为
全系统公共现货（`v_stock_available`），后续新分析把这批「别的分析已经买好入库的料」
算成自己的可用量。既有跨分析软承诺（softCommittedStock）只覆盖其它分析 depth=1
快照行，深层物料与「已收货但尚未下达计划」的量完全漏出。

### 3. V298 方案（夜班在途实现，本轮核查）

- 收货 IQC PASS 入库即按「订货明细 → 申请/委外明细 → 分析供应行动分摊」溯源到来源
  分析，写 `owner_type='PREPLAN_ANALYSIS'` 的库存软预留（供应锚点=采购申请行/委外
  申请行/生产计划行）。
- `v_stock_available` 统一口径自动扣除（视图 LATERAL 聚合所有 status=0 预留、不区分
  owner——本轮核对 V150 定义即现行口径，无需改视图）：其它分析、销售、MRP 都看不到
  这批料。
- 归属分析自己的可用量 = 公共可用 + 本分析生效预留（MaterialAnalysisService 侧
  own LATERAL 加回；`WarehouseBreakdown` 新增 `ownPeggedQty` 供「其中本分析备料」展示）。
- 其它分析的软承诺快照按已绑定量**净额**扣除（防止双重扣减）。
- 对称反向：收货红冲 `releaseForReceipt`；整分析取消 `releaseForAnalysis`（含自制备料
  入库锚点兜底清扫）；单任务撤回 `releaseForSupplyItems`。
- 计划包正式确认（confirm）同事务 `transferToPlanDemands`：分析预留释放回池（留
  `TRANSFERRED_TO_PLAN` 痕迹），需求分配器再为 production_material_demands 建行——
  库存事实不重复、不漂移。
- 自制备料（成品入库）对无销售链接的计划行产出，`pegFinishedInbound` 补同一形态归属。

### 4. 本轮核查与补齐

- **核查设计前提**：确认 `v_stock_available`（V150 定义）对 owner_type 无关聚合，
  V298 预留自动进入扣减口径；V160/V222 仅引用未重建，无口径漂移。
- **核查接线完整性**：IQC PASS、红冲×2、分析取消、任务撤回、计划包转移、成品入库
  六个挂点全部就位。
- **补测试（关键缺口：原实现零测试覆盖）**：`FullChainEndToEndTest#23b
  preplanPegging_receivedStockStaysWithOriginAnalysis`——分析A（订单1→H缺20）BUY 下单
  →订货→财务审批→收货→IQC PASS，断言：①绑定预留写入（qty=20 生效中）且公共可用量=0；
  ②**新分析B（订单2）的 H 可用量=0、缺口仍=20**（跨分析重复计算回归锚）；③分析A自己
  `ownPeggedQty=20`、可用量=20、他人预留=0；④红冲收货后生效预留清零、库存归零。
  **一次通过**。

## 三、任务3：订货下单→委托财务审查流核查

### 1. 现象与定性

用户（admin）在采购/委外点「订货下单（委托财务审查）」后，订货详情页**直接出现
「财务通过/退回修改」按钮**，感觉流程越位。核查结论：

- 状态机**正确**：提交 → `procurement_order_approval_cases` PENDING → 列表「等待财务
  审核」、详情「等待财务审核组处理」；审核期间锁定改删。
- 按钮出现原因：**admin 的员工挂在财务部**（dev 库实测：`17665410007 系统管理员/财务部
  +is_super_admin`），命中 V229 审核组资格（财务部树 ∪ 个人加授，超管无豁免），故
  详情页按 `canApprove/canReject` 渲染了审批按钮。是「UI 操作位」问题，不是越权/状态
  跳错——服务端资格校验一直都在。

### 2. 修复（操作位收敛）

用户期望的分工：采购/委外提交后只看到「等待财务通过」；审批界面只属于财务。改动：

- **采购/委外订货详情页**：移除「财务通过/退回修改」按钮与处理函数（对**所有**账号，
  含有资格的财务）；提示条明确指引「财务部门持权人员可在『财务 → 订货审批任务中心』
  审核通过或退回；采购侧仅可查看」。
- **财务订货审批任务中心**：任务卡新增**页内审批操作行**（通过 / 退回修改，按服务端
  `allowedActions` 放行），通过带确认弹窗、退回带必填原因弹窗，走既有
  `approveFinance/rejectFinance` 端点（V229 资格校验兜底不变）；完成后刷新列表与角标。
- widget 测试：任务卡渲染操作、点通过恰好调用一次 `/purchase/orders/{id}/approve`、
  `allowedActions` 为空时不出现操作；委外详情页测试改为断言**不再出现**审批按钮。

### 3. 运行时验证（待重启后端后实测）

计划用普通采购账号提交订货（确认看不到任何审批按钮）→ 财务账号（或挂财务部的
admin）进任务中心页内通过 → 订货生效并生成预计到货任务。
