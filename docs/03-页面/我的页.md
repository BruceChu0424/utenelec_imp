# 我的页

> 路由：`/profile` · 实现源：`lib/features/profile/pages/profile_page.dart`
> 关联：`/profile/edit` · `/profile/me/changes` · `/profile/me/department` · `/profile/me/vehicles`（2026-08-05 新增，我的车辆与备用手机号自助）· `/hr/profile-changes` · `/hr/profile-changes/:id`
> 最后更新：2026-08-05 · 状态：v5 — 新增「我的车辆与号码」快捷卡（ADR-021：车辆 + 备用手机号员工自助，直改即时生效）；档案组改为 基本信息 / 联系方式 / 户籍与其他 三段分组，联系方式含备用手机号。

## 一、定位

给所有员工使用的个人资料中心 + 业务快捷入口。同时承载**个人信息修改闭环**的员工侧入口。

- 解决的问题：
  - 查看自己的姓名 / 工号 / 部门 / 岗位 / 联系 / 组织 / 紧急联系人等完整字段
  - 跳到本人相关业务（工资 / 报销 / 通知 / 建议）
  - **自助修改个人信息**（直改字段即时生效；需审核字段提交后走 HR 审批）
- 产品位置：底部 / 侧边导航"我的"项。

## 二、入口与导航

- 进入路径：
  - 底部 / 侧边导航"我的"项
  - 工作台首页（如有相关入口）
- 离开去向：
  - 快捷入口 → 工资条列表 / 我的报销 / 公司通知 / 建议箱
  - 「修改我的信息」→ `/profile/edit`
  - 「修改密码」→ `/change-password`（Phase 1 已有路由）
  - 「我的修改申请」→ `/profile/me/changes`
  - 「我的部门」→ `/profile/me/department`（2026-08-03 新增，由工作台移植）

## 三、字段展示（v3 重写）

按权限点和对象关系脱敏：薪酬要求 `employee:compensation:view`，其它 PII 要求
`employee:pii:view` 或本人范围；后端 DTO 是权威，前端不得按“HR/admin”角色名自行解密或补全。

| 分组 | 字段 | 来源 | 备注 |
|---|---|---|---|
| 基本信息 | 工号 / 姓名 / 部门 / 岗位 / 入职日期 | session.user + EmployeeDetail | 后端按权限点/本人范围脱敏 |
| 联系方式 | 手机 / 备用手机号（标签+号码）/ 邮箱 / 办公电话 / 工位 | EmployeeDetail（含 V211 phones） | 备用号本人明文 |
| 户籍与其他 | 现住址 / 户籍地址 / 民族 | EmployeeDetail | — |
| 我的部门 | 卡片（位于「我的修改申请」之上） | `myDepartmentTreeProvider`（分支根名） | 点进 `/profile/me/department` 全页面查看 |
| 我的车辆与号码 | 卡片（位于「我的修改申请」之下） | `myEmployeeProfileProvider`（车牌摘要） | 点进 `/profile/me/vehicles` 自助管理车辆 + 备用手机号（直改即时生效） |

### 四·甲、我的部门快捷卡（2026-08-03 由工作台移植）

```
┌───────────────────────────────┐
│ 🌳  我的部门             ›    │
│     生产管理中心              │  ← 副标题=所属大部门分支根名
└───────────────────────────────┘
```

- 位于 Hero 卡与「我的修改申请」快捷卡之间（身份组 / 左列），副标题取 `myDepartmentTreeProvider` 的分支根名；加载中 / 未分配时显示「查看本部门架构与花名册」。
- 点击 → `/profile/me/department`（全页面，`context.go`，主 Tab 前缀子路由须 go 不 push）。**布局复用「部门管理」页（`/department`）**：expanded 全高分栏（左组织树 `UtenDepartmentTreeView` 300px | 分隔线 | 右详情），compact/medium 组织树进 `endDrawer`。右侧详情 = `MasterDetailCard`（部门概况，只读：在册 / 子部门 / 负责人 / 编制 + 路径）+ 安全花名册（`UtenPersonCard`，**负责人 / 管理人排最前**，安全字段）+ 部门负责人权限转授面板（仅当当前部门正是本人管理的部门时显示）。
- **花名册按「所选节点子树」聚合**（2026-08-06 修复）：管理中心 / 一级部门等纯分组节点本身不挂人，旧实现只取直属成员导致分组节点显示「无员工」；现 `MyDepartmentService.roster` 用 `departmentService.subtree(departmentId)` 收集子树全员（`EmployeeRepository.findByDepartmentIdInAndDeletedFalseOrderByFullNameAsc`）。叶子节点子树=自身，行为不变。统计卡「在册」人数随之反映分支内全员。**部门负责人权限转授面板仍按直属汇报运作（`managedStaffPermissionsProvider` 独立接口），不受此改动影响。**
- **点击员工弹「只读联系卡」**（2026-08-06 修复）：`_staffRow` 的 `UtenPersonCard` 原先无 `onTap`（点了无反应）；现点击弹底部联系卡（compact）/ 居中弹窗（expanded），展示头像 + 姓名 + 负责人/本人徽标 + 岗位·部门 + 工号 + 办公电话（可拨号 `tel:`）+ 邮箱（可发件 `mailto:`）。**只走花名册安全字段，不进 `/employee/:id`**——普通员工无 `employee:view`，跳受限路由会被守卫拦下转 `/access-denied`。安全字段在原有基础上补了 `departmentName`（子树聚合后用于区分员工所属下级部门）。
- **数据走 `/api/my-department/**`**（任意员工可见，无需 `department:view` / `employee:view`）。部门管理页的 `DepartmentOverviewPane` 调的是 `department:view` / `employee:view` 受限接口，普通员工 403，故此处**复用部门管理的「布局与组件」但保留 my-department 安全花名册数据源**。

## 九、涉及的数据实体

→ [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `User`：姓名 / 工号 / 部门 / 岗位 / 角色
- `Employee`：手机 / 邮箱 / 户籍 / 现住址 / 工位 / 紧急联系人 等
- `ProfileChangeRequest`：本批次内 pending 数（驱动"我的修改申请"快捷入口）

## 十、权限要求

- **全员可见**——「修改我的信息」与「我的修改申请」入口对所有登录员工开放，不挂权限点路由守卫，也不按权限点控制按钮显隐
- 数据范围：仅本人；他人看不到自己的页面
- 字段级控制（在编辑页 + 后端 `ProfileFieldPolicy`，单一来源）：
  - 直改字段（民族 / 政治面貌 / 婚姻 / 现住址 / 办公电话 / 邮箱 / 工位）——提交即生效
  - 需审核字段（姓名 / 户籍 / 手机 / 紧急联系人）——提交后进 pending 批次，HR 审批通过才合并
  - HR 专属字段（性别 / 生日 / 工作地点）——员工页只读，提示「请联系人事」
- 后端 `profile:edit:self` 权限点保留（`employee` 角色全员基础包已覆盖），用于接口鉴权与未来「禁止某员工自助改」的兜底；**前端入口不再依赖它**

## 十一、边界情况

- 「修改我的信息」「我的修改申请」入口全员可见可点；若当前账号未绑定员工档案，编辑页 `_load()` 提示「当前账号未绑定员工档案」
- `EmployeeDetail` 加载失败：右栏降级显示「—」占位（保持 UI 骨架）
- 我的修改申请网络异常：占位「—」+ 顶部 appError 提示
- 性能档 = lite：Hero 卡 boxShadow 关闭、CTA 动画简化
- 网络断开：基本只读信息可用；CTA 按钮点击走 onPressed null 兜底
