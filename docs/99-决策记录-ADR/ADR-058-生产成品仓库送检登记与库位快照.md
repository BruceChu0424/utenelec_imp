# ADR-058：生产成品仓库送检登记与库位快照

- 日期：2026-08-30
- 状态：已决策；V430 冻结仓库送检登记和交易库位快照，V431 后置增加按仓库的库位建议偏好，V469 前向允许同日报按行分批登记。目标非空库迁移、真实车间/品质/仓库岗位 UAT、恢复和部署回读完成前，生产继续 **NO-GO**
- 相关：ADR-033、ADR-046、ADR-054、V338、V409–V415、V418、V427、V430、V431、V469
- 后置关系：本 ADR 只后置覆盖 ADR-046/ADR-054 中“生产日报选择目标仓、日报审核立即登记 FQC”的在线新单路径；报工、FQC、V338 点收、失败恢复、反向和历史兼容的其余守恒不变

## 2026-09-04 V469 后置修订

V430 的“每张日报一次完整登记”使仓库无法把暂未到手、暂不送检或需要后续处理的明细从本批
移出；前端若遗漏一行会被整单拒绝。V469 将办理粒度改为日报行：

- 页面行首复选，批量按钮与右键/长按共用“移出本批送检”确认；移出不产生任何服务端写入，
  操作完成后清空临时选中态，避免下一次误操作；
- 同一日报可以有多个追加式 registration header；每个 header 至少一行并冻结一个仓库、收货人、
  幂等键和请求哈希；旧 V430 登记保持原样；
- `production_finished_arrival_registration_items.source_report_item_id` 的全局唯一、V430 ENABLE
  ALWAYS 来源守卫、审计和只追加约束全部保留。同一来源行并发只允许一个登记/FQC 身份；
- 登记与本批所选行的 FQC PENDING 同事务提交；未选行继续从日报行和“不存在 registration item /
  inspection / legacy exemption”重建待办，不写库存、`iqty` 或完成率；
- 登记后的库位记忆绑定本次响应 registration UUID；同日报并发后续批次不能改变前一请求的
  学习来源，较旧登记也不能覆盖较新偏好；
- V430 下文第 2.3 节“明细不允许删除”和第 5.1 节“登记覆盖全部活动日报行”保留为历史设计，
  现行解释分别是“禁止持久化删除来源，可移出当前批次”和“每个提交批次精确覆盖请求所选行”。

权限不新增：读任务仍需 `stock_doc:view`，提交/移出可见性仍需 `stock_doc:approve`，服务端继续
与有效 `SUB_WH` 对象范围求交。目标库 V469 非空升级、真实部分到货/送检、并发、多岗位和恢复
验收完成前仍为 **NO-GO**。

## 一、问题

V409–V415 把完工申报、FQC 放行和仓库实收拆成了不同事实，但在线页面仍要求生产日报制单人在报工时选择成品仓库。这个字段把仓库的实物职责提前交给计划/生产岗位，也使 FQC inspection 和后续 `FINISHED_IN` 在仓库看到实物前已经冻结仓库。

现有仓库待点收入口又只允许填写最终实收数量和差异原因，不能在送检前登记实际成品仓与逐行库位。页面展示的 `goods.stock_place` 是货品主档建议，不是本次交接的交易快照；若把它直接当成实际库位，会把后续主档变更错误地投射到历史单据。

本 ADR 将“选择成品仓和登记库位”移到仓库送检登记，同时保留以下底线：日报审核不是入库，仓库送检登记不是实收，FQC PASS 也不是库存；只有 V338 最终点收的 `accepted_qty/iqty` 才增加库存和完成率。

## 二、决策

### 2.1 新单权威顺序

```text
IN_PROGRESS 执行段
  → 生产日报草稿保存
       └─ 只保存草稿；不建仓库任务、不建 FQC、不建 FINISHED_IN
  → 生产主管审核日报
       ├─ 记录当前有效完工申报贡献 fqty
       ├─ 形成可恢复的“待仓库送检登记”任务
       └─ 同事务 publishOnce PRODUCTION_FINISHED_ARRIVAL_PENDING
  → 仓库送检登记
       ├─ 选择本次成品目标仓
       ├─ 逐行登记 place 交易快照
       ├─ 不填写实际入库数量
       ├─ 不写库存、不增加 iqty、不改变完成率
       └─ 同一事务逐行登记 FQC PENDING
  → 品质按 inspection UUID 作 PASS / PARTIAL / FAIL
       ├─ PASS 数量按既有放行账生成 FINISHED_IN 待点收草稿
       └─ FAIL 数量继续进入 REWORK / SCRAP / REJECT 恢复链
  → 仓库按 V338 对 FINISHED_IN 逐行填写 acceptedQty 并最终点收
       └─ 只有 acceptedQty 增加库存和 iqty
```

“待仓库送检登记”必须从已审核日报及其未完成登记事实重建，通知或角标仅用于提醒。用户关闭页面、网络丢响应或通知被清理，任务都不能消失。

日报审核对全部带 execution segment 的新在线明细，以日报 UUID 为 aggregate 在同一业务事务追加一次 `PRODUCTION_FINISHED_ARRIVAL_PENDING`，去重键为事件类型加 `reportId`。Outbox delivery 必须再次确认日报仍已审、未红冲、有活动明细、全部属于新执行段，且尚无仓库登记、inspection 或 legacy exemption；任务已登记、已红冲或已进入其它质量谱系时静默跳过过期通知。通知类型是普通任务，路由固定为 `/warehouse/production-finished-in/tasks`，不得升级为强提醒。

### 2.2 日报职责

1. 新客户端的生产日报不显示、也不提交仓库选择；日报头的历史 `warehouse_id` 可继续保留用于旧数据兼容，但不再是 V430 后新 inspection 的仓库权威。
2. 普通草稿 `create/update` 只保存报工内容和并发版本，不产生仓库任务、inspection、FINISHED_IN、库存流水或 `iqty`。
3. 只有审核成功才增加当前有效 `fqty` 并使仓库任务可见。重复审核、丢响应重试和并发审核不得重复贡献 `fqty` 或重复产生任务。
4. 日报仍须精确引用 `IN_PROGRESS` execution segment、计划行和必要的销售分摊 UUID；移除仓库输入不放宽任何来源、数量、状态、人员或对象范围门禁。

### 2.3 仓库送检登记职责

仓库登记页按已审核日报的固定明细打开：

- 表头由仓库选择一个有效成品仓；计划部、生产部和品质部不能替仓库提交。
- 收货人由当前登录仓库员工确定并冻结 UUID/姓名快照，页面只读展示，不能由客户端冒充他人。
- 明细行由日报 UUID 固定带入，不允许新增、删除、换货品、换颜色、换单位、改报工量或按名称重新匹配。
- 每条行登记 `place`。`place` 是本次送检/后续入库的交易快照，提交后随 inspection 和 FINISHED_IN 来源链保持不变。
- 页面不录 `acceptedQty`，也不提供“实收”“入库完成”或库存过账动作；最终实收仍在 PASS 后的 V338 待点收页面填写。
- 页面不显示价格、金额、成本或工资字段。

登记请求必须带稳定幂等键与规范请求哈希。相同操作者、相同键和相同请求返回原结果；相同键不同仓库、库位或来源明细返回冲突。仓库登记、逐行快照、inspection 和待检 Outbox 在同一事务全部成功或全部回滚。

“记住为该仓默认库位”是登记后的独立偏好动作，不得混入上述登记事实或用偏好写入结果冒充登记结果。页面必须把该动作作为默认开启但始终可见、可取消的选择；旧客户端未显式表达记忆意图时不得由服务端推断为同意。登记成功而偏好动作失败时，登记、inspection 和 `place_snapshot` 继续有效，页面须准确提示“登记已成功、默认库位保存失败”并允许安全重试偏好动作，不能重提登记或回写历史。

### 2.4 库位语义

库位读取与写入必须区分“不可变交易事实”和“可变的下次输入建议”：

1. 已登记任务永远读取 `production_finished_arrival_registration_items.place_snapshot`；本次 `place` 随 registration、inspection 和 FINISHED_IN 来源链冻结，任何偏好或货品主档后改都不能改写历史。
2. V431 的 `warehouse_goods_place_preferences` 以 `warehouse_id + goods_id + color_id` 为一个共享业务建议；`color_id IS NULL` 也是确定键，不表示任意颜色。选定仓库后，精确偏好优先于最近登记和全局主档建议。
3. 没有精确 V431 偏好时，可以只读采用最近一笔其他 V430 登记中相同 `warehouse_id + goods_id + color_id` 的 `place_snapshot`。货品必须用系统 UUID 对齐，禁止按可变编码或名称关联；最近登记内同一维度只有一个不同库位值时才可建议。若该笔登记同维度存在多个库位，不得随机取值或跳过它采用更老登记，继续回退到货品主档或空值。该读取不得写入 V431，也不得改写任何历史事实。
4. `goods.stock_place` 只保留为没有精确 V431 偏好、也没有可安全采用的最近登记时的全局 fallback。它继续服务尚未按仓改造的货品主档、货架挂牌和兼容页面，但登记不得隐式覆盖它，也不得把它批量复制成仓库偏好或历史交易事实。
5. 页面未选择实际成品仓时须禁用库位号并提示“请先选择成品仓”；选仓后才一次批量解析固定明细的建议并允许修改，显示“该仓已记忆 / 最近登记 / 货品主档建议 / 暂无建议”来源。切换仓库须清除原仓上下文的建议和手工库位后重新匹配；较早仓库请求的迟到响应不得覆盖当前仓库，同一仓库的服务端结果不得覆盖用户已经手工修改的行。
6. 用户勾选“记住为该仓默认库位”后，独立偏好动作才可以新增或更新 V431 偏好；该动作必须有稳定幂等身份、完整审计和明确成功/失败反馈。相同 warehouse/goods/color 在同一登记出现多行时，同值只学习一次，异值必须拒绝歧义，禁止采用“最后一行覆盖”。取消记忆只表示不新增或更新持久共享偏好，不删除真实 V430 快照，也不阻止该最近事实以后作为可编辑的只读建议。
7. 偏好表可更新不等于交易快照可更新。偏好保存失败、重试、并发覆盖或以后主动修改都不得删除、更新或重新解释 registration、inspection、FINISHED_IN、confirmation、residual、replacement 或 reversal。
8. 当前库存余额和流水的权威维度仍是 `warehouse + goods + color`，不是 `warehouse + place + goods + color`。V431 只保存一个默认文本建议，不宣称实现货位级库存、移库、库容、批次、序列号或拣选策略。
9. 若未来要求同一货品在同仓多库位分账，必须另建库位主档、库存维度、移动流水和盘点/并发规则，不能继续复用文本 `place` 或偏好表冒充 WMS。

### 2.5 FQC 与 FINISHED_IN

1. V430 后的新 inspection 从仓库送检登记读取 `warehouse_id` 和逐行 `place`，不再从日报头猜测。
2. 仓库登记事务对每条日报明细最多登记一个 inspection；已有 inspection、已取消日报、未审核日报或身份/数量不一致均失败关闭。
3. 品质权限、PASS/PARTIAL/FAIL 数量守恒、FAIL contribution adjustment、恢复授权和 PASS release FIFO 不变。
4. PASS 创建的 FINISHED_IN 必须继承 inspection 对应的仓库与 `place` 快照，并继续精确引用日报行、计划行、执行段、销售分摊和 PASS release。创建草稿不写库存或 `iqty`。
5. V338 最终点收继续逐行覆盖全部当前明细；短收生成同来源 residual，整单零实收保留 REJECTED 并按 V418 形成同源重新交付任务，专用红冲沿 accepted slice 反向。余量和 replacement 必须继承原仓库与 `place` 快照，不能重新猜测。

## 三、权限与对象范围

- 仓库任务查看沿用 `stock_doc:view` 与生产库存任务对象范围；无权账号返回安全空结果或无权 UUID 的 404。
- 仓库送检登记沿用 `stock_doc:approve`，并必须与有效 `SUB_WH` 仓储组织树求交。仅持全局动作权限但不在仓储范围的账号失败关闭。
- 待登记通知只发给 `SUB_WH` 部门子树内未离职、账号 active，且当前有效权限同时包含 `stock_doc:view` 和 `stock_doc:approve` 的用户；个人 revoke 后不得继续收到业务详情。此时尚未选择目标仓，当前模型也没有员工到具体仓库的分配，因此不能按单仓猜测收件人。
- 当前没有员工到具体仓库/库位的分配主档，因此不能宣称已实现单仓或单库位授权；选择结果仍须是有效、未删除仓库。
- 品质查看/决定仍为 `production_quality_inspection:view/approve`，决定动作继续要求有效 `DEPT_QA` 组织池。
- 生产/计划人员可在自身对象范围查看“待仓库登记、待检、待点收、已入库”状态，但不能执行仓库登记、品质决定或最终点收。

## 四、历史、反向与兼容

1. V430 不回填、伪造或重解释历史 FQC。已有 inspection 继续以自身已冻结仓库为权威；已有 FINISHED_IN、V338 confirmation、V418 residual/replacement 和 reversal 谱系均原样保留。
2. V414 legacy exemption 继续只表示迁移切点前的历史兼容，不表示 FQC PASS，也不自动生成仓库登记。
3. 不得把历史日报 `warehouse_id` 或当前 `goods.stock_place` 批量复制成“仓库已登记”的证据。历史补证必须另有人工核验和迁移决策。
4. 日报在仓库登记前红冲时，待登记任务随权威日报状态消失；登记后必须先按现有顺序反向 FINISHED_IN/PASS release/FQC，再处理日报贡献。不得删除登记、inspection 或决定历史来“恢复”页面状态。
5. 已提交仓库登记的仓库和 `place` 不允许普通 CRUD 修改。错误更正只能走受控、幂等、追加式反向，并服从是否已有品质决定、放行、点收或下游消费的状态门禁。
6. V431 迁移和记忆写链不从历史日报、登记、inspection、FINISHED_IN、库存单据或 `goods.stock_place` 猜测回填仓库库位偏好；首次持久偏好只能来自切点后用户可见且未取消的记忆动作。运行时在 V431 为空时读取最近一笔精确 UUID 维度的 V430 快照，仅是可编辑建议，不是回填、偏好写入或历史重解释。

## 五、V430 / V431 前向迁移边界

### 5.1 V430 交易事实

V430 只向前建立仓库送检登记的权威事实、幂等命令和数据库守卫，并把新 inspection 的仓库来源从日报切换到仓库登记。它不得修改任何已应用的 V338、V409–V415、V418 或其它历史迁移字节，也不得使用 `flyway repair` 掩盖 checksum 差异。

迁移必须同时守住：

- 一个已审核日报和每条日报明细都只能形成一个永久仓库登记身份；
- 登记覆盖全部活动日报行，仓库非空，逐行 `place` 与来源 UUID 完整；
- inspection 与登记行一一对应，仓库、货品、颜色、单位、换算率、数量、计划行、执行段和销售分摊完全一致；
- PASS 生成的 FINISHED_IN 继承登记仓库与 `place`；
- 登记、命令和逐行快照不可删除、不可普通更新并接审计；
- 任何登记事务都不能写库存、`iqty` 或把执行段提前置为完成。

### 5.2 V431 建议偏好

V431 只能前向新增 `warehouse_goods_place_preferences`，不得修改已应用的 V430 字节。偏好表必须满足：

- 仓库、货品、颜色均使用系统 UUID；唯一维度为 `warehouse_id + goods_id + color_id`，其中 NULL 颜色按一个确定值参与唯一性；
- `place` trim 后长度为 1–100；多个货品允许共享同一文本库位，不对 `place` 建唯一约束；
- 保存最后选择人、最后选择时间和选择次数，并接 `updated_at` 维护与 `fn_audit()` 全行审计；
- 偏好写入只接受当前成功登记的固定来源行，沿用 `stock_doc:approve + SUB_WH` 仓储组织范围，不能成为任意修改货品主档的旁路；
- 迁移不回填偏好、不更新 `goods.stock_place`，也不更新任何 V430 登记或库存历史；
- 功能回退时保留 V431 表和迁移资源，关闭偏好读写并回到 `goods.stock_place` fallback。已应用 V431 后不得使用缺少该迁移资源的旧 JAR、删除表、修改 `flyway_schema_history` 或执行 `flyway repair`。

详细结构、部署和验收边界见 [迁移说明 65](../数据迁移/65-仓库货品库位偏好.md)。

## 六、最低验收与 NO-GO

最低自动化与岗位验收必须覆盖：

- 日报草稿新建、修改、自动保存和退出均不产生仓库任务或 FQC；
- 日报审核只增加一次 `fqty`，产生一个可恢复待登记任务；
- 日报审核同事务只追加一个 `PRODUCTION_FINISHED_ARRIVAL_PENDING`；Outbox 重放不为同一事件/接收人重复建通知；
- delivery 前任务已登记或日报已红冲时不发过期通知；通知丢失、清理或无合格收件人均不影响权威任务可发现；
- 非审核日报、已红冲日报、缺来源 UUID、重复/遗漏行和越权账号不能登记；
- 仓库登记同键同体重放、同键异体冲突，并发双登记只有一个成功；
- 登记前后库存、`iqty` 和完成率不变；登记成功后每行恰有一个 FQC PENDING；
