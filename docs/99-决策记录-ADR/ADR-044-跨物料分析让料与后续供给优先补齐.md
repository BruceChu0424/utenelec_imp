# ADR-044 跨物料分析让料与后续供给优先补齐

- 日期：2026-08-21
- 状态：已采纳（源码候选；隔离库动态执行尚未获明确许可，目标库/部署仍需独立批准）
- 取代：ADR-043 中“跨分析借料尚未实现”的边界；ADR-043 的 V307 精确来源结论继续有效

## 一、业务语义

本能力不是债务或还款：

1. 来源计划 A 已有一批合格库存权益；
2. 计划员显式把其中数量 `q` 让给紧急计划 B；
3. B 当下获得 `q`，A 的原需求不删除并形成“优先待补 `q`”；
4. A 自己的下一批合格供给先原地满足该优先量；若 B 的下一批同仓同维度
   BUY/SUBCONTRACT/MAKE 供给先到，则其中最多 `q` 重新挂给 A，余量仍归 B；
5. 无关计划 C 的硬绑定供给不得被暗中抢走。接受计划不承担“返还”义务。

该语义与主流 ERP 的 Backorder Processing / priority pegging 一致：撤回或重新
分配已经确认的数量后，原需求重新成为未满足需求，后续供应按优先级重新确认；
既有正式预留仍受保护。

## 二、唯一库存真相与权益事件

`stock_reservations` 继续是唯一物理库存预留账。跨分析让料不拆第二套库存余额，
也不改写 V307 的不可变来源谱系。

V309 新增：

- `preplan_material_reallocations`：A/B 双分析、双物料行 UUID、仓库/货品/颜色/
  单位、让料量、已优先补齐量、双端 CAS 快照、原因和生命周期；
- `preplan_stock_entitlement_events`：不可改删的权益事件账；正事件建立权益 lot，
  负事件只能引用并消费一个正 lot；
- `v_preplan_stock_entitlement_lot_balance`：逐 lot 剩余量；
- `v_preplan_stock_entitlement_beneficiary_balance`：逐物理 reservation、受益分析和
  物料行的当前权益。

V310 给两张 V309 业务账显式附加审计触发器；V311 固化权限、双端 CAS 和生命周期；
V312 校验 MAKE `FINISHED_IN -> plan item -> MAKE_COMPONENT -> parent allocation` 来源；
V313 建立 append-only、FORMALIZE/RESTORE 与物理有效量延迟守恒；V314 再执行一次
fail-closed 全 `public` 审计覆盖扫描。

事件对：

- 初始供应：`ORIGIN_IQC` / `ORIGIN_MAKE`；
- 人工让料：A `REALLOCATE_OUT` + B `REALLOCATE_IN`；
- B 后续供给优先补 A：B `PRIORITY_OUT` + A `PRIORITY_IN`；
- A 自身到货：`PRIORITY_SATISFIED_IN_PLACE`，不移动权益；
- 转正式需求：`FORMALIZE`；未领料取消恢复：`RESTORE`；
- 来源撤销/红冲：`RELEASE`。

V313 的延迟约束要求事务提交时：

`同一物理 reservation 的全部 entitlement 剩余量之和`
`=` `该 reservation 的物理有效量`。

任何 lot 负数、让料 OUT/IN 不相等、补齐量与头表不一致、正式桥超出正式预留量，
都由 PostgreSQL 拒绝。

## 三、优先补齐顺序

对新建的合格 origin lot，在同一库存事务内按以下顺序处理：

1. 该 lot 本来属于 A：按让料创建时间、UUID 稳定顺序原地关闭 A 的待补量；
2. 该 lot 属于接受计划 B：按相同顺序把待补量重新挂给 A；
3. 超出待补量的余量保留给原供应计划；
4. 非 A/B 的其它分析、正式需求 reservation 和已领料事实不参与自动重挂。

同一物料节点不能同时参加多条未补齐关系。人工让料只允许消费**谱系终点**为
`ORIGIN_IQC/ORIGIN_MAKE` 的 lot：原始 lot 经计划取消或让料撤销形成的 `RESTORE`
仍保持原始类别，可以再次让料；从 `REALLOCATE_IN/PRIORITY_IN` 正权益恢复出来的
`RESTORE` 仍属于接受/优先权益，不得转手。该递归谱系规则从结构上禁止 A→B→C
连环让料。

## 四、正式计划与反向流程

- 只有 READY 执行段在确认事务内把 beneficiary entitlement 转为正式 demand
  reservation；WAITING 不持有部分库存。
- `FORMALIZE` 保存来源 entitlement event、来源物理 reservation、package、demand
  和正式 reservation 的精确桥。一个正式 reservation 可由多个来源 lot 共同支持，
  也可以同时含公共库存，因此桥数量只要求不超过正式 reservation。
- WAITING re-kit 先按来源计划的 analysis/item 加回自身 beneficiary entitlement；
  整套可齐后才执行 `transfer → formal allocation → FORMALIZE → DRAW → READY`。
- 未领料的计划取消或 segment 降级：先释放正式 reservation，再写 `RESTORE` 并恢复
  来源 PREPLAN reservation；已领料、已派工或已开工继续返回 409。
- 来源采购/委外收货、MAKE 成品入库、供应行动或分析若仍有关联让料、他分析
  beneficiary 或未恢复正式桥，禁止红冲/取消并给出先撤销让料或先取消未领料计划的
  恢复路径，绝不静默夺回其它计划权益。
- 分析取消时，`OPEN/PARTIAL` 让料仍返回 409；`FULFILLED` 关系按当前 beneficiary
  lot 逐片写 `RELEASE`，物理 reservation 只增量增加相同 `released_qty`，并把关系
  受控关闭为 `CANCELLED`。取消 A 绝不能释放 B 的切片，取消 B 反之亦然；历史
  V298 无 event 的 reservation 才使用分析级整行释放。存在未 `RESTORE` 的
  `FORMALIZE` 时，即使计划关联状态漂移也必须失败关闭。

## 五、并发、权限与接口

- 锁序：`InventoryKey(goods,color)` → 两份 analysis header 按 UUID → 两端物料行 →
  reallocation → entitlement/source reservation → action/demand；
- 创建和撤销都带双方 version/fingerprint；任一旧快照返回 409；
- 新权限 `production_material_analysis:cross_reallocate` 默认只授 GM 与计划部；
- 超级管理员可在权限设置中按部门或个人逐项授权/收回；该高风险权限不进入个人“一键全部授权”，部门或个人显式配置仍允许；
- 部门变更递增全局 authorization epoch，个人覆盖递增 auth version，旧 access token 在下一请求失败关闭；
- 还必须同时通过两份分析的对象级可写范围，候选查询在服务端过滤，不能泄漏无权分析；
- 同一幂等键异 payload 返回冲突，不能静默复用。

接口：

- `GET /api/production/material-analyses/{sourceId}/materials/{lineId}/cross-reallocation-candidates`
- `POST /api/production/material-analyses/{sourceId}/cross-reallocations`
- `POST /api/production/material-analyses/{sourceId}/cross-reallocations/{id}/revoke`

## 六、界面

文案统一为“跨计划让料、已接受、优先待补、已优先补齐”，禁止使用欠款、代还、还款。
跨计划入口和撤销使用独立 `CROSS_REALLOCATE` 权限，不能复用同分析 `REALLOCATE`。
候选同时返回服务端权威 `sourceLendableQty`；终端仅以该值和接受计划缺口计算上限。
`REVERSED` 明示“已撤销、权益已恢复”；`CANCELLED` 使用“头表让料量减去目标
beneficiary 的累计 `RELEASE`”得到 `currentEffectiveQty`，分别显示“仍保留”或
“已释放”，`FORMALIZE/RESTORE` 不会被误判为权益消失。
弹层使用 `Form + LayoutBuilder + Semantics`，提供 375px Bottom Sheet、宽屏 Dialog、
候选搜索、加载/空/错误重试、双方影响预览、48dp 操作区和双 CAS 冲突后保留草稿。
`allowedActions` 缺失或为空时写操作 fail closed。

不得替代新增 #23d 让料优先补齐与 V314 的获许可动态验收；本轮这两项未取得可引用的
