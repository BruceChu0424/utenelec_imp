这里的读取快照只在当前命令或响应内存在，不是跨请求缓存。BOM 组件失效、基本单位/颜色异常、环、超过十层仍失败关闭。现货数量、精确权益、公共安全库存、在途及下达余量继续分账。MAKE_COMPONENT/SUBCONTRACT_MAKE 仍仅为计划锚点，不复制原树物料需求。

增量落库始终运行现行数量算法，不凭旧 fingerprint 跳过计算。结构阶段保留旧 required/allocated 等计算值，随后 5 个库存参考字段与 7 个最终计算字段一起更新，避免需求减少时出现 allocated 暂时大于 required 的立即约束错误。真正结构变化仍触发原身份/让料/权益校验，有数量变化的行仍正常审计；ROOT_SUPPLY 继续由根供料服务独立维护。

结构预筛与 ON CONFLICT 最终比较共享 `NODE_STRUCTURE_COLUMNS` 的 18 列定义。输入 CTE 的 UUID、日期、数量、布尔和文本均显式定型；仅完全相同的结构行在进入 INSERT 前排除。新行、失活行和任一结构变化仍进入原写入及守卫，最后的数值重算独立执行。每块 500 行使用 15,000 个实际 JDBC 绑定槽，不以删除校验换取吞吐。5 次交替的 1,000 节点无变化实测中，100/500/1,000 行块的绑定加执行中位分别为 189.39/110.50/135.35ms，三组均零插入、零冲突；该微对照只说明批量粒度，不代替整链响应验收。

批量计划的静态作用域只属于当前 JPA 事务和单份分析。进入时验证完整已有锁范围，不授予新锁；商业来源、分析头/来源行、计划/需求/预留每次仍实时读取，原 Guard 与 requireCovered 不减少。退出时完整读取材料整行、当前 BOM 整行及根 UUID 集合，不一致即标记实际事务 rollback-only。该作用域必须在最终 refresh 之前退出，禁止嵌套，REQUIRES_NEW 暂停和恢复互相隔离；任何未关闭作用域都会阻止提交。即使上层捕获退出冲突，也不能提交部分计划。

静态片段在创建时一次生成摘要及去重库存维度，避免嵌套计划把相同的全部行再次逐一编码；退出比较仍保留完整行。BOM 锁范围按 `(goods_id, depth)` 去重遍历共享子件，最后读实际边及整行 hash；真实数量与路径展开继续走原逐路径读取器。图等价用例覆盖环、长短重叠路径、根同时为中间件、删除/缺失根、颜色及第 10/11 层边界。大集合查询采用 `IN (SELECT unnest(...))` 单参数半连接，已用真实 SQL、1,000 个非空候选和 70,000 个引用验证 generic/auto 六次重用；旧 ANY 谓词同样本第六次出现超时，因此不能仅凭空权益样本判断优化有效。

供给批查只把实际合格入库计为到货覆盖；已退回不合格由原订单形成的待补量继续抵扣可重新下达量。审计进一步发现合并来源的剩余量重复从 FIFO 起点分配，已前向修正为来源累计区间差，详见[V554](../数据迁移/152-V554合并订货来源剩余供给区间.md)。旧 action_group_key 通过真实 allocation 的物料 UUID 找回，不凭货品名或编码猜配。批量读在新 action 写入前完成，幂等、版本、指纹、对象权限和全事务预锁没有删除。

入库后置联动仍在来源事务内执行。精确归属容量来自 action allocation、exact peg、legacy reservation 和实际订单来源预算，下一张收货单读取同事务已经写下的权益事实，不依赖上一张的 shortage 展示投影。任何归属、正式履约或分析刷新失败仍回滚整批。

仓库分解读取仍使用 V554 的权威来源进度。仅没有 `safety_external_item_id` 的行动可排除：该 view 不会为它建立 SAFETY 切片；不能按安全补货声明量为零排除旧来源。按货品／颜色聚合时使用存在性筛选，避免同货品的不同单位维度把安全数量重复相加。真实 SQL 对照覆盖全部 14 列、NULL 颜色、双单位、多主／叶／不良仓、历史与追踪专属量、停用／删除／取消请求，以及合并来源实退后的 8／30 区间。1,000 个需求行动与 8,000 节点的代表性数据中，行动表访问 89,300→5,050；三个计划模式执行约 106–158ms→16–20ms。该读取器接线后的 70 项回归通过，端到端收益仍须随后复测。

取消分析没有移除服务端已下达计划、根交接、跨分析权益和版本守卫。前端补齐原因 2–1000 字校验及框内错误反馈，业务冲突必须显示给用户，不能静默声称取消成功。

这些单轮定位值受缓存及并行任务影响，不作固定提速倍数。最终 5 样本及 on/off 同查询结果等价对照另行补录，所有运行时/数据规模和中央回归并行负载均保存在测量事件中。

R4 的 5 组列表读样本受到 MockMvc 清空线程身份影响，返回的是无身份过滤后的空页，不作为最终列表证明；R5 在 HTTP 样本后恢复同一测试身份，活跃/全状态列表分别真实返回 8,566B / 47,989B。R4 的其他服务样本及实际 JIT 配对证据不受这项夹具问题影响。

整行编码仅用于同一事务、连接和固定 schema 内的临时 Guard 比较，不用于持久分析 fingerprint 或 schema 签名。没有省略列或减少前后校验。真实 PostgreSQL 覆盖 null/空串、逗号/括号/引号/换行/中文、数量、状态、UUID、数组和时间变化；100 来源真实快照的五组交替对照中，材料 9,800 行编码中位由 JSON 302.74ms 降至 composite 93.39ms，BOM 1,384 个唯一边由 332.96ms 降至 208.47ms，其他输出列逐行等价。后续继续核对重复路径上的指纹计算与批量事务范围，微基准不代替端到端验收。

## 继续验收的边界

公司业务库当前数据规模及网络环境与隔离夹具不同；不得只凭空库响应、缓存命中或 SQL 次数减少宣称所有页面已达响应目标。批量计划创建仍逐份履行单据、分摊、审核和执行段事务规则。整树刷新仍须写审计和数量快照，优化目标是消除重复工作，不跳过事实落账。最终以完整回归、规模结果和公司目标版本验收共同确认。
