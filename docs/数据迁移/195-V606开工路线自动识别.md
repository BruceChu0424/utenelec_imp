# 195 - V606 开工路线自动识别（删除「确认生产路线」步骤）

- 日期：2026-09-18
- 关联：[ADR-091](../99-决策记录-ADR/ADR-091-开工路线确认与到货进展通知.md)（确认门退役批注）、
  [ADR-092](../99-决策记录-ADR/ADR-092-直送资格按sourcing收紧.md)（V605，本迁移排其后）、
  [我的车间任务页](../03-页面/我的车间任务页.md)
- 用户口径：「不用确认路线这个操作了，这个确认路线的步骤删除吧，然后自动识别生产
  路线就行」＋二改「生产路线可以选择，不用去确认路线」——自动识别只给**默认值**，
  车间在格内下拉**直接改选即生效**（无确认步骤）。

## 一、决策

V599 的「先定路线再卡流程」显式确认门退役。路线改为**创建事务内按工单事实自动识别**：

| 识别规则 | 路线 |
| --- | --- |
| WAITING 且存在可由本车间直送供给的子件（V605 收紧后=自制口径的直送资格） | CONTINUOUS |
| 其余（零料段 / 下达即齐套 / 纯仓库供料） | FULL_KIT |

分批生产**不由创建时识别**——点「分批生产领料」本身就是选择分批（拆批后根段
CANCELLED、批次段落生即 FULL_KIT、剩余段继承 BATCH，V599 谱系不变）；「部分开工 ·
持续生产」同为动作驱动：服务端对未动过的工单在同一事务里把路线切到 CONTINUOUS。

**保留不动的面**（V599/V595 的守恒边界一个不松）：

- 路线冻结尺：动过（领料单/报工/预留/供给钉）即不能改路线、不能切持续生产；
- `fn_execution_route_allows_auto_promote` 抑制矩阵：BATCH/未开工的 CONTINUOUS 不被
  齐套自动提升顶掉（V595 竞态口径不变——只是 CONTINUOUS 现在由系统识别而非人选）；
- `confirm-route` 端点保留为**人工纠偏通道**（自动识别错边时，WAITING 且未动过可改选），
  并改为**同值幂等**：路线已由系统赋好后再「确认成同一条」不是新决定，不要求
  WAITING/未动过（已提升的段重复确认是合法空操作）；改值仍走严格校验。

## 二、迁移内容（只回填，无结构变化）

1. `fn_auto_execution_start_route(p_segment)`：自动识别函数（单一事实源，创建事务与
   回填共用）——WAITING 且存在可直送子件 → `'CONTINUOUS'`，否则 `'FULL_KIT'`。
   排在 V605 之后，回填即用收紧后的直送资格口径。
2. 存量 `start_route IS NULL` 的段（V599 部署后创建、尚未人工确认的）按同一规则一次性
   回填并补 `route_confirmed_at`；终态段恒回填 FULL_KIT。升级后没有任何在途单被
   路线门锁住。
3. 自动识别不产生 `ROUTE_CONFIRMED` 事件（不是人的确认决定）；段的创建/拆批/持续
   开工事件本身已可追溯路线来源。零 DDL、零索引、不改既有非空行、重放幂等
   （回填条件 `start_route IS NULL`）。

## 三、应用层配套（同批）

- **创建赋值**：`ProductionExecutionPackageCommandService` 在 `createDemands` 后同事务
  `UPDATE ... SET start_route = fn_auto_execution_start_route(id)`（仅 `start_route IS NULL`
  的本次新建段）——需求先落库（资格判支要查 demands），且先于预留/领料单生成。
- **门控放宽**：开工/批量开工/领料申请/重核/派工的 NULL 路线分支退役（不再 409
  「请先确认生产路线」——自动赋值后 NULL 不复存在，历史脏数据按齐套放行）；
  分批提交删除「先确认 BATCH」前置（未动过的尺子仍由提交前 activity 检查把守）。
- **持续生产动作切换**：`startContinuousSupply` 对非 CONTINUOUS 的未动过工单，在同一条
  CAS UPDATE 里置 `continuous_supply=TRUE, start_route='CONTINUOUS'`（一次 UPDATE，
  不二次抬 lock_version）；动过的仍拒绝「不能切换」。
- **UI**：车间任务页「确认路线(N)」按钮与三选一弹窗退役；路线列 = 色标竖线 +
  **可编辑下拉，直接改选即提交**（默认值=自动识别结果；无草稿、无确认按钮，提交
  挂全屏加载遮罩；多选联动与「批量设置路线(N)」同样选中即逐单提交）；动过的行
  冻结为只读徽章；等待文案按当前路线区分（五轮词表扩展不变）。

## 四、验证

- 服务端：`ProductionExecutionRouteGateEndToEndTest` 重写为自动识别语义——纯仓库段
  创建即 FULL_KIT、到货即提升、开工零确认；直送段自动 CONTINUOUS、仓库料全到仍保
  WAITING、部分开工同事务切路线；分批零前置可拆、批次段/剩余段路线谱系、无
  ROUTE_CONFIRMED 事件；动过后不能改路线/切持续；人工纠偏保留且同值幂等；到货
  进展卡口径不变（CI 环境变量门控执行）。
- Flutter：车间任务页 28 用例全绿——只读徽章与确认 UI 缺席、三路线配色与等待文案、
  齐套链动作按路线放行、分批/持续入口动作驱动（不要求已确认对应路线）、纠偏弹窗
  提交挂全屏加载遮罩。

## 五、已知边界

- 直送资格在段创建**之后**才出现（同车间后来才开工同货品工单）的段，识别仍是
  FULL_KIT：自动提升可能先把它顶成 READY（V595 竞态的这一子集回归）。覆盖路径是
  动作驱动——部分开工入口按能力（`fn_can_start_continuous_supply`）出现、点击即切
  路线；不为了消灭该子集重新引入人工确认。
- `suggestedStartRoute` 路线记忆（V602 索引）随确认步骤退役而失去前端消费方，
  服务端投影与索引保留（无害），后续可单独清理。
