| 目标 | 说明 |

## 三、前端现在就要做的事

### 3.1 路由守卫（go_router redirect）

未登录访问受保护页 → 跳登录页；已登录访问登录页 → 跳工作台。

```dart
// lib/core/router/go_router.dart
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:go_router/go_router.dart';
import '../auth/auth_provider.dart';

final goRouterProvider = Provider<GoRouter>((ref) {
  return GoRouter(
    initialLocation: '/dashboard',
    refreshListenable: ref.read(authStateProvider.notifier),
    redirect: (context, state) {
      final loggedIn = ref.read(authStateProvider).maybeWhen(
            data: (user) => user != null,
            orElse: () => false,
          );
      final goingToLogin = state.matchedLocation == '/login';

      // 未登录 + 不是去登录页 → 强制登录
      if (!loggedIn && !goingToLogin) {
        final next = Uri.encodeComponent(state.uri.toString());
        return '/login?from=$next';
      }
      // 已登录 + 去登录页 → 跳工作台
      if (loggedIn && goingToLogin) {
        return '/dashboard';
      }
      return null; // 放行
    },
    routes: [
      GoRoute(path: '/login', builder: (_, __) => const LoginPage()),
      GoRoute(path: '/dashboard', builder: (_, __) => const DashboardPage()),
      // ...
    ],
  );
});
```

> 详细路由命名见 [01-命名规范.md 第 2.5 节](01-命名规范.md)。

### 3.2 输入校验（所有表单必做客户端校验）

校验维度：**必填、长度、格式、范围、防 XSS 模式前置过滤**。

```dart
// 用 UtenInput 的 validator
UtenInput(
  label: l10n.username,
  validator: (v) {
    if (v == null || v.trim().isEmpty) return l10n.required;
    if (v.length < 3 || v.length > 32) return l10n.usernameLen;
    // 仅允许字母数字下划线
    if (!RegExp(r'^[A-Za-z0-9_]+$').hasMatch(v)) return l10n.usernameFormat;
    return null;
  },
);

UtenInput(
  label: l10n.email,
  validator: (v) {
    if (v == null || v.isEmpty) return l10n.required;
    if (!RegExp(r'^[\w.+-]+@[\w-]+\.[\w.-]+$').hasMatch(v)) {
      return l10n.emailFormat;
    }
    return null;
  },
);

// 防 XSS 前置过滤：移除 < > " ' & 等危险字符（前端体验层）
String sanitize(String input) {
  return input
      .replaceAll('<', '')
      .replaceAll('>', '')
      .replaceAll('"', '')
      .replaceAll("'", '')
      .replaceAll('&', '');
}
```

> ⚠️ **前端校验只是体验**，攻击者绕过前端直接打 API，所以**后端必须再校验一次**（见第四节）。

### 3.3 敏感数据存储分级

| 数据 | 当前阶段存储 | 后端接入后存储 |
|---|---|---|
| 主题选择、语言、字号 | `shared_preferences` ✅ | 同 |
| 用户偏好（最近查看、布局） | `shared_preferences` ✅ | 同 |
| Mock 登录态（仅前端标识） | `shared_preferences`（带 `_mock_` 前缀） | — |
| **真实 token / refresh token** | — | **`flutter_secure_storage`**（见 5.4） |
| **密码、私钥** | — | **`flutter_secure_storage`**，绝不存任何持久层 |

> 🚫 **禁止把 token 存 `shared_preferences`**——它在 Android 是明文 XML，iOS 是 plist，可被备份/逆向读取。

### 3.4 不硬编码（配置外置）

以下内容**禁止**出现在代码里，必须走 `.env` 或运行时配置：

| 类型 | 例子 | 配置位置 |
|---|---|---|
| API base URL | `https://api.uten.com` | `.env` (`API_BASE_URL`) |
| Mock 账号 | `admin / 123456` | `.env` (`MOCK_USERNAME` / `MOCK_PASSWORD`) 或仅 README |
| API key / secret | 第三方服务密钥 | `.env`（**且 `.env` 不进 git**） |
| 环境标识 | `dev` / `staging` / `prod` | `--dart-define` 或 `.env` |

```dart

```


### 3.5 Mock 数据不含真实信息

- Mock 数据**禁止**包含真实员工姓名、工号、薪资、客户名、采购价
- 用形如 `员工001 / 张三（占位）/ ¥--,---` 的脱敏数据
- Mock 图片用 `https://picsum.photos` 或本地资源，不用真人头像

### 3.6 密码框规范

```dart
UtenInput(
  label: l10n.password,
  type: UtenInputType.password, // 默认 obscureText: true + 可见切换图标
  // 关键：
  // - 默认隐藏（obscureText: true）
  // - 末尾"小眼睛"图标切换可见
  // - autofillHints: [AutofillHints.password] 仅在登录页
  // - 不允许复制粘贴到无关字段（输入模式 password）
  validator: (v) => (v == null || v.length < 8) ? l10n.pwdTooShort : null,
);
```

### 3.7 错误处理（不向前端暴露后端细节）

```dart
// 统一错误转换
String userFacingError(Object error) {
  return error.when(
    network: () => l10n.errNetwork,
    timeout: () => l10n.errTimeout,
    unauthorized: () => l10n.errSession,
    server: (_) => l10n.errServer,   // 不暴露 status code / stack
    unknown: (_) => l10n.errUnknown,
  );
}
```

> 🚫 **禁止**把后端的 SQL 报错、堆栈、status code 直接吐给用户——这是 OWASP 信息泄露。
> 前端阶段统一 Mock 成"网络异常/服务器繁忙"，后端接入后由拦截器统一转译。

## 四、后端接入时要做的事（前端预留接口）

### 4.1 登录扩展

| 项 | 当前 | 后端接入后 |
|---|---|---|
| 凭证 | Mock 账号密码 | 真实账号密码 |
| 双因素（TOTP） | UI 预留"第二步验证"页（暂跳过） | 接入 Google Authenticator / 企业 TOTP |
| SSO / LDAP | 接口预留 `AuthProvider` 抽象 | 接入企业 AD / OAuth2 |

> 前端把登录抽象成 `AuthRepository` 接口，Mock 实现与真实实现可替换。

### 4.2 密码策略（UI 预留）

| 策略 | 前端 UI 预留 |
|---|---|
| 强度校验 | 注册/改密页展示"弱/中/强"指示器 |
| 至少 8 位 + 大小写 + 数字 + 符号 | `validator` 已就位 |
| 定期更换 | 设置页"密码最后修改时间 + 到期提醒"位 |
| 错误次数限制 | 登录页"剩余 N 次尝试"位（前端仅显示，后端权威） |

### 4.3 Token 机制

- 短期 access token（如 15 分钟）+ 长期 refresh token（如 7 天）
- access 过期 → 用 refresh 自动续期，对业务透明
- refresh 过期或被吊销 → 跳登录页

前端 Dio Interceptor 自动处理（见 5.2），业务代码无感。

### 4.4 网络层（统一拦截器）

所有请求过 Dio 拦截器，统一做：加 token、签名、加密、错误转译。

### 4.6 CSRF 防护（Web 端）

后端接入后，Web 端：

- 关键写操作（POST/PUT/DELETE）带 CSRF token（从 cookie 读，回写 header）
- 前端 Dio Interceptor 自动注入

### 4.7 会话超时

| 行为 | 实现 |
|---|---|
| 闲置 N 分钟自动登出 | 用 `Listener` 监听全局手势，重置计时器 |
| 后端 token 过期 | 401 拦截器统一处理 |
| 前端阶段 | UI 预留"自动登出时长"设置项 |

### 4.8 审计日志

关键操作（前端只负责上报，后端落库）：

| 操作 | 触发 |
|---|---|
| 登录 / 登出 | 成功/失败均记 |
| 修改权限 | 改部门权限配置、改个人权限覆盖 |
| 删除数据 | 删员工、删工资条、删检测记录 |
| 导出数据 | 导出工资单、报表 |
| 修改财务数据 | 改薪资、改报表 |

前端通过 `AuditInterceptor` 自动埋点，业务代码无需手写。

### 4.9 权限校验（前端隐藏 + 后端校验）

> **关键原则：前端隐藏只是体验，后端才是真相。**

| 层 | 做法 |
|---|---|
| 前端 | 根据权限**隐藏**菜单/按钮（`hide`），**不是 disable** |
| 后端 | 每个 API **独立**校验权限，前端绕过也拦得住 |

> 为什么不用 disable？disable 反而吸引攻击者（"这里有好东西"），且仍是可见的攻击面。**直接 hide**。

## 五、权限模型设计要点

> **⚠️ 2026-07-24 更新**：角色体系已下线（ADR-011/V29）。现行模型 =
> **全员基础（employee 包）∪ 部门配置（含上级部门）± 个人覆盖**，超管全量；

### 5.1 角色定义（历史参考，已下线）

| 角色 code | 名称 | 说明 |
|---|---|---|
| `employee` | 全员 | 普通员工：看自己工资条、自己的检测任务 |
| `hr` | 人事 | 员工档案、入离职、考勤 |
| `finance` | 财务 | 工资、报销、报表 |

### 5.2 权限点（按功能粒度）

```dart
// lib/core/auth/permissions.dart
abstract final class Perm {
  // 工资
  static const payrollView = 'payroll:view';        // 看工资条
  static const payrollGenerate = 'payroll:generate'; // 生成工资
  static const payrollExport = 'payroll:export';     // 导出

  // 员工
  static const employeeView = 'employee:view';
  static const employeeEdit = 'employee:edit';
  static const employeeDelete = 'employee:delete';

  // 检测
  static const labTestView = 'lab:test:view';
  static const labTestUpload = 'lab:test:upload';

  // ... 按功能模块逐步补
}

// 角色 → 权限点映射（前端仅用于 UI 显隐，后端权威）
const Map<String, Set<String>> rolePermissions = {
  'employee': {Perm.payrollView /* 仅看自己 */},
  'hr': {Perm.employeeView, Perm.employeeEdit},
  'finance': {Perm.payrollView, Perm.payrollGenerate, Perm.payrollExport},
  'lab': {Perm.labTestView, Perm.labTestUpload},
  'manager': {Perm.employeeView, Perm.payrollView},
  'admin': {Perm.payrollView, Perm.payrollGenerate, /* ...全部 */},
};
```

### 5.3 前端使用

```dart
// Provider：当前用户的权限集合
final currentPermissionsProvider = Provider<Set<String>>((ref) {
  final user = ref.watch(currentUserProvider);
  return user?.let((u) => rolePermissions[u.role] ?? const {}) ?? const {};

extension PermX on Set<String> {
  bool can(String perm) => contains(perm);
}

// 菜单项：根据权限隐藏（不是 disable）
final navItems = [
  NavItem(route: '/payroll', icon: Icons.receipt, label: l10n.payroll,

  NavItem(route: '/employee', icon: Icons.people, label: l10n.employee,
      perm: Perm.employeeView),
```

## 六、OWASP Top 10（2021）对照

| # | 类别 | 本项目应对 |
|---|---|---|
| A01 | 访问控制失效 | RBAC 权限点 + 前端 hide + **后端每 API 校验** |
| A02 | 加密机制失效 | HTTPS 强制 + token 走 SecureStorage + 敏感字段 AES |
| A03 | 注入 | 后端参数化查询（前端无关，但禁止拼字符串到 SQL）+ 前端输入校验 |
| A04 | 不安全设计 | 威胁建模：每个写操作过审计、有幂等键 |
| A05 | 安全配置错误 | `.env` 不进 git、不暴露 stack trace、CSP 配齐 |
| A06 | 脆弱与过时组件 | 定期 `flutter pub outdated`，关注 CVE |
| A07 | 认证与身份失败 | 双因素 UI 预留 + token 续期 + 错误次数限制 + 会话超时 |
| A08 | 软件与数据完整性失效 | 后端响应签名校验 + 不信任前端输入 |
| A09 | 安全日志与监控失败 | 审计拦截器记录关键操作 |
| A10 | 服务端请求伪造 SSRF | 后端校验 URL 白名单（前端无关） |

## 七、禁忌

🚫 禁止硬编码任何密钥、URL、Mock 账号、API key 到代码里（走 `.env`）。
🚫 禁止把 token / 密码 / 私钥存 `shared_preferences`（后端接入后必须 `flutter_secure_storage`）。
🚫 禁止用 `disable` 代替 `hide` 来表达"无权限"。
🚫 禁止把后端错误细节（status code、stack、SQL 报错）直接吐给用户。
🚫 禁止 Mock 数据含真实员工/财务/生产/客户信息。
🚫 禁止明文 HTTP（必须 HTTPS）。
🚫 禁止前端跳过后端校验就允许写操作（前端校验只是体验）。
🚫 禁止把日志打到 console 含 token / 密码（即使是开发期）。
🚫 禁止在 Web 端不注意 CSRF（后端接入后必须配齐）。
