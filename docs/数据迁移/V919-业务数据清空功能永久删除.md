# V919：业务数据清空功能永久删除

2026-10-23，当前源码 V919/845。对应 [ADR-192](../99-决策记录-ADR/ADR-192-业务数据清空功能永久删除.md)。本地隔离验证和公司服务器应用状态分别记录，不能以源码目录号代表服务器已升级。

迁移删除 `business_data_reset()` 及测试文件枚举、校验、元数据清理、调用者与清空分类等专用 helper；移除共享历史保留、附件、业务证据、审计及字段版本守卫中的测试清空绕过分支。旧 flag 不再具备清空历史或推进数据代际的能力。未知函数定义不匹配时迁移失败，不猜测补丁，也不通过 CASCADE 隐藏新依赖。

六个正常物化视图刷新入口改用专用的刷新授权 helper，保留既有调用边界、函数所有者和授权。角色准备与加固脚本同样保持新 helper 私有，普通运行账户通过受控刷新入口调用。

删除专用清空权限及权限面映射、部门授权、个人覆盖、负责人委派中的当前关联；活动权限模板 JSON 移除旧码并按既有版本守卫递增，已删除模板的不可变历史不改写。删除目录码造成的授权版本变化只重绑定迁移前仍有效的委派，陈旧委派继续无效。历史业务审计继续可读。数据库迁移不调用清空函数，不删除客户、货品、订单、账户余额、附件、历史记录或系统配置。历史代际字段仍保留，用于兼容旧草稿与 AI 结果隔离。

V915 与之前的已存在迁移保留原字节；新库完整迁移和已有 V918 库升级都最终删除清空能力。测试使用隔离 PostgreSQL 和合成数据，覆盖迁移前后数据快照、旧 flag 无法绕过保护、六个正常刷新入口与目录权限。正式更新须由完整签名 SQL 集经现有独立 migrator 执行，升级步骤见 [RUNBOOK](../../deploy/simple/RUNBOOK.zh-CN.md#业务清空功能永久删除)。
