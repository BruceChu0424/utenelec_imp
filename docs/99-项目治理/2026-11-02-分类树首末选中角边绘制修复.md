# 分类树首末选中角边绘制修复

用户实际测试截图指出分类列第一选中行左上角露出旧底色，正常页与滑窗均存在。本次保留 Uten 的主题色、8px 外角、滑入选择色块、文字/图标/多选与稳定节点 ID，不对截图加 padding 或叠遮挡。

## 公共根因与唯一修复入口

1. `UtenHierarchyTreeView` 的平铺行使用普通 Row 居中，标题槽及选择色块只按自身内容和最小高度布局；行尾 Checkbox 或业务控件更高时，真实行高由其决定，但色块仍较矮，留下上下旧底色。改为同一公共树内部的内容行：先用标准 Flex 量出自然行高，只将较矮的 flex 标题槽按真实行高布局，保留实际宽度及控件位置。不固定行高、不缩小命中区域，不向 LayoutBuilder 使用不支持的 IntrinsicHeight。
2. Material 原先先画深绿抗锯齿圆角背景，再对白色选择子层单独抗锯齿裁剪。曲线边界的覆盖率被应用两次，旧底色从白色选择边缘渗出。Flutter 固定 SDK 的 `RenderPhysicalShape.paint` 对 `Clip.antiAliasWithSaveLayer` 明确采用先合成背景/子层，再裁一次边的路径。本次仅对平铺树首/末具有外圆角的行使用该路径，最多两行；中间行及普通缩进树沿用现有裁剪，虚拟化范围保持。

唯一生产文件为 `lib/shared/widgets/uten_hierarchy_tree_view.dart`。`UtenCategoryTreeView/UtenDepartmentTreeView` 继续作为薄适配，不新增页面级重复处理。正常分类页、货品/模具/主档选择滑窗、客户/供应商/收付款类别、库存与往来查询中的分类树，以及直接复用公共层级树的仓库/组织架构/员工选择入口均自动沿公共入口生效；未改变各调用方的业务筛选、权限、来源与节点关系。

## 验证

- 新增测试调用真实 `UtenCategoryTreeView`，捕获 RenderRepaintBoundary 的2倍像素。浅/深主题的首末外角在白色选中层与中性承托之间只能产生中性覆盖像素；未修版本两例实际失败，最大旧色偏差77，保留 before 图像及失败日志。修复后通过；扩展到 none/single/multi 三种模式与56px高行尾控件，共6个真实像素边界用例，不镜像私有 widget 实现、不放宽失败阈值。
- 全部公共树套件，加分类/部门适配层共62/62通过，包含行菜单、选择/切换动画、减少动画、长标签与控件对齐、连接线、森林宽度、projection cache、3000节点虚拟化及400/900px视窗，完整运行未取消。两文件 delta analyze 无 issue，格式与 diff 检查通过。
- 可选图像输出在 `output/windows-localtest-pressure-20261102/tree-edge-before`、`tree-edge-after`，已有分类树 dark/light 真实字体预览同时复核，保留首末圆角及中间方角、连接线与选择前景。
- 未启动或替换用户桌面软件。本次源码进入最终完整包，由 root 统一整合；现有 LocalTest 目录和运行状态交 root 按用户要求检查日志后处理。

## 多端差异

Web、现有 Flutter Windows、Android 共用上述组件。WPF 候选货品页当前采用原生 TreeView/TreeViewItem 选择，外层为 RoundedSurface，不含该平铺深绿背景与滑入色块的双层裁剪实现；此次没有为其复制 Flutter 绘制补丁。完整分类 ERP 的呈现迁移与 Win7 真机验收仍未完成，不能据本次修复标为已迁移/已支持。
