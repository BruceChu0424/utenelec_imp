# V718 货品未分类根放开为普通分类

## 背景

2026-09-25 用户口径：货品资料左树的「未分类」根（`LEGACY_ORPHAN`，V275 起
系统保留——不可改名/软删/物理删，注册表 FK RESTRICT + 不可变触发器双保险）
应该就是普通分类：树上不带括号英文快照、有权限即可编辑/删除（删除仍走既有
引用保护：分类下还有货品时会被拦，须先挪走）。

## 改动（只放开货品根；客户/模具/供应商三根保护原样保留）

1. **退役触发器** `trg_material_categories_protect_uncategorized`
   （`fn_protect_uncategorized_master_category` 在注册列置空后会 RAISE
   'missing'，必须一并退役；其余三表的同名触发器不动）。
2. **注册表脱钩**：先撤 `trg_protect_system_master_category_registry`、
   `ALTER COLUMN material_category_id DROP NOT NULL`，置空后重建**窄守卫**——
   仍禁删、禁改其他列，`material_category_id` 只许单向从非空改为空，防回填。
3. **改名**「未分类（历史孤儿）」→「未分类」，`version + 1` 让持有旧版本
   编辑页的人乐观锁失败重开。code=`LEGACY_ORPHAN` 保留作身份。

## 代码侧配套（同批落地）

- `SystemMasterCategoryRegistryEntry.materialCategoryId` 允许为空；
  `SystemMasterCategoryRegistry.isMaterialCategory` 对空根恒 false。
- `MaterialCategoryService` 移除 `requireMutableCategory`（改名/删除守卫）；
  `systemManaged` 随注册表脱钩自然为 false，前端锁图标/保留提示自动消失
  （前端守卫纯按服务端 `systemManaged` 派生，无需改动）。
- `MaterialCategoryMigrator.ORPHAN_ROOT_NAME` 对齐为「未分类」。
- 前端分类树标签：`LEGACY_ORPHAN` / `SYS_UNCATEGORIZED_*` 不再拼
  「名称(编码)」后缀（`categoryNodeLabel`）。

## 注意

- goods 表自 V684 起只有 `fn_guard_goods_live_category` 触发器（不读注册表
  的 material 列），置空不影响货品写入；`fn_assign_uncategorized_master_
  category` 只挂在 clients/moulds/suppliers 三表上，其 'material_categories'
  分支从此无人调用。
- 幂等：IF EXISTS / 条件 UPDATE，重跑安全；不加表。
