# 初版两页演示设计记录

> 本文保留初版V2的设计与字段核对记录。用户已进一步要求从例子形成通用方案；当前交付规则、完整层级显示、四个功能件及多层样例以[通用交付方案](通用交付方案.md)为准。以下“仅三个功能件、只拆一层”描述属于初版范围，不再是新版能力限制。

当前范围：根据用户提供的微信聊天及九张截图制作独立、可转发的 HTML 演示。用户已明确要求忠实复刻公司现有平台的页面及流程，主要为销售订货单编辑、计划部物料分析两页。业务确认后再改正式系统；当前不接 API、不改基础 BOM、不改库存或正式业务，不部署、不打包客户端。本文记录设计与实现目标，最终浏览器验收由主任务另行执行，本文件不宣称已经完成。

## 视觉及交互设计

使用 `frontend-design`，以真实页面源码及 Uten 公共组件为复刻依据。延续现有 Uten：主色 #0F766E、浅选中 #CCFBF1、背景 #F5F7FA、面板 #FFFFFF、正文 #0F172A、次级文字 #475569、边框 #E2E8F0。字体优先 Noto Sans SC，离线使用 Microsoft YaHei 等系统回退。顶栏高 56px、标题 18px/w700、底部细线无阴影，正文 14/16px。表格单元格包括数字均靠左，保留独立名称、编号及颜色列。

页面外壳、表单、工具条、表格及右下操作沿用公司现有平台布局，不另造左右配置工作台或方案宣传页。新增交付配置必须发生在销售订货单原明细表中，物料分析按现有准备与分析流程显示对应结果。

```text
销售订货单编辑
现有顶栏 → 原主表单 → 原附件区 → 原明细表（数量后新增交付方式）→ 保存
计划部物料分析
准备：选择已审销售来源 → 联合分析 → 原 BOM 树 / 按物料汇总 → 核对来源
```

计划部页面先呈现已审销售来源的候选与选择，执行“联合分析”后再显示分析结果。结果复用原表格树、展开/收起、表头筛选及“按产品/按物料汇总”的信息组织，交付选择及数量来源在对应订单行和物料路径中披露。联合分析及保存均只在演示内模拟，不产生真实审批、排产或库存事实。

## 销售订货单页面规格

源码依据：`lib/features/sales/pages/sales_doc_edit_page.dart`、`lib/features/sales/widgets/sales_grid_columns.dart`、`lib/shared/widgets/sales_document_layout.dart` 以及 Uten 表单、网格和悬浮动作组件。

- 顶栏：左圆形返回按钮，桌面标题“新建销售订货单”或“编辑销售订货单”；小于600px时为“新建订货”或“编辑订货”。新建右侧为“草稿(N)”，编辑不显示该入口。
- 主表单：白色 Card 内边距12px；UtenFormGrid默认桌面3列、600–839px为2列、更窄1列，横纵间距12px，字段最小可读宽度240px。不得加上订单原本没有的仓库、汇率、发货人或收货地址字段。

| 桌面第一列 | 第二列 | 第三列 |
|---|---|---|
| 单据号(系统自动生成) | 制单员(系统自动生成) | 制单时间(系统自动生成) |
| 单据日期 * | 客户 * | 币种 * |
| 税率(%) | 结账方式 * | 业务员 * |
| 交货日期 * | 发运策略 * | 合同号 |
| 签约地点 | | |

主表单网格后间隔12px，追加全宽“备注”（2–5行）。发运策略保留现有原文“允许分批发货”“整单齐套后发货”，其发运节奏语义与新增交付方式分别表达。

附件区位于表单之后、明细之前，标题“附件（合同/客户确认/图片）”，分类为合同、客户确认、图片、其他；空区提示“拖入或点击添加客户文件，加入后可在文件卡上 AI 识别”。不恢复已退役的顶部独立“识别客户文件”横幅。

原明细默认顺序为：勾选框／货品名称 *／英文名称／编号／颜色／数量 *／单价 *／折扣 *／总金额(订单币种)／备注／行尾删除。本次仅在“数量”后新增“交付方式”，通过 Uten 风格下拉及相应配置弹层选择整装、半散装及功能件交付层级，不使用原生 select。数量的单位在数量格内联，例如“100 个”，不另加单位列。

文件型号、文件品名默认隐藏，有值时强制显；文件单价仅存在相应数据时出现；机加价、围数、进仓数量(历史参考)默认隐藏。列顺序按公共 `canonicalSalesColumns` 及个人列偏好解释，演示采用默认可见列。

网格工具条保留“表头设置 N/M”。订单编辑没有常驻“从上游引入”、全选、复制、粘贴或批量删除按钮；全选在表头，复制等在行菜单。表头默认40px，保留竖分隔及横向滚动。表尾同一条左“添加行”“添加多行”，右“总行数”“数量”“总金额(所选币种)”；金额为红色。右下仅“取消”和带保存图标的“保存”，当前公共最小高度48px；有货品内容时保存红底白字，无内容时灰色。合计不重复放进悬浮操作区。

## 业务方案

- 基础 BOM 是产品原始结构，不按客户重复建 BOM。
- 交付方式属于订单行；同货品同客户下次也可另选。
- 整装交付保持成品；半散装交付逐功能件选择整件或直属下级。
- 拆选中的功能件一层；下级带 BOM 的支架、静触片、滑杆等仍整件交付。
- 取消选中功能件该层组装/单独包装；必要加工仍保留，最后仓库按整批方案打包。
- 核对视图保留原分组和路径，发货汇总保留每条贡献来源。
- 订单行分别形成交付来源；视图可按交付身份、编码、规格、颜色、单位及加工要求汇总，但保留逐行分配与完整贡献路径。不合并整件与其子件，不把不同订单行的选择相互覆盖。

## 示例来源及限制

使用截图 8/9 的 280229009「巴基S1六开单+双二孔」，仅摘录三个开关功能件。截图 5 的编号是 280229166，不能宣称两者完整 BOM 一致。演示订单数量 100 个成品是示例输入，不是订单事实；原聊天所说的一套组合在本页按一个产品核对。

三个开关功能件分别 Q3KBG014（左）、Q3KBG009（中）、Q3KBG015（右），每套各 1。共用后座 Q7BJ0029、压板 Q7BJ0028 每功能件各 1；全部按下级交付时分别为 3 × 100 = 300 个。动触片 Q71007 和支架 Q71105、静触片 Q71106、滑杆 Q71108R 每功能件各 2，汇总各 6 × 100 = 600 个。左/中打子分别 Q7BJ0011/Q7BJ0010，每个功能件 2；右侧 Q70018 每个功能件 2，右侧数量参考截图 5/7，须正式核对。源图中 Q7BJ0028 名称出现 Q3-BJ 前缀，按图保留，不擅自修订。

插孔功能件、铁架、安装包、按钮、说明书及包装等未载入演示。尤其旧图插孔父数量 2、下级数量 4/2，可能已按产品折算，不能再乘父数量。页面任何完整性核对只针对已载入摘录，不作整产品齐套/库存可发承诺。

待确认：完整 BOM 和数量口径、插孔功能件适用范围、不同包装及附件处理、同一行混合整装散装、计价单据及分批/退货口径、必要加工来源。以上是正式实施前的确认项，不把演示中未覆盖的完整产品结构标为已经齐套。

## 交付与使用

交付为同目录的单文件「订单散件交付方案-demo.html」，双击由浏览器离线打开。全部演示数据、CSS、脚本及品牌图均内嵌，不使用外部字体/CDN、服务器、登录或后台接口。HTML 只模拟本地页面、保存、来源选择和联合分析；如有导出或反馈，也仅生成本地文件，不上传。

所有客户、联系人、电话/地址、价格、金额、库存、示例单据和人员均为虚构演示数据，不得载入真实敏感信息。用户给出的货品编码、名称及 BOM 摘录仅用于说明该业务场景；不内嵌带真实库存、价格或聊天头像的原截图。演示库存不能解释为真实可用库存，示例金额也不代表正式散件计价方案。

实际演示验证见同目录「验证记录.md」。该记录只针对独立 HTML，不代表正式 ERP、完整 BOM、库存或目标电脑业务验收。

业务确认后，按「实施范围与交接.md」核实完整 BOM、数量契约和多端调用方，再实施正式系统。
