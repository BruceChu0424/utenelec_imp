# 报销详情页

> 路由：`/expense/:id` · 实现源：`lib/features/expense/pages/expense_detail_page.dart`

## 一、定位

员工查看某一笔报销单的详情，并执行后续操作（提交/撤回/删除）。

- 解决的问题：透明展示报销总额、状态、明细、审批轨迹、驳回原因；并允许在合适状态下推进或回退流程。
- 产品位置：从 [报销列表页](报销列表页.md) 点入，是报销单的"控制中心"。

## 二、入口与导航

- 进入路径：
  - [报销列表页](报销列表页.md) → 点击列表项
  - [新建报销页](新建报销页.md) → "存草稿"后跳入
- 在导航中的位置：业务详情子页。
- 离开去向：
  - 删除后 → [报销列表页](报销列表页.md)
  - 提交/撤回后留在本页（状态更新）

## 四、涉及的 Uten 组件

- `UtenAppBar`（带返回按钮）
- `UtenCard`（多处使用）
- `UtenInfoRow`（标签值行）
- `UtenStatusBadge`（Hero 状态徽章）
- `UtenButton`（type=ghost 删除/撤回、type=primary 提交，isExpanded）
- `UtenEmpty`（数据 null / error）
- `UtenToast`（success 提示）
- `UtenColors`

## 五、功能点

1. **Hero 总额卡**：渐变背景，展示"报销总额" + 大金额 + 状态徽章（6 状态对应 6 种 badge type）。
2. **基本信息卡** `UtenInfoRow` 多行：
   - 标题（`isImportant` 高亮）
   - 申请人
   - 创建时间 / 提交时间 / 审批时间（如有）/ 打款时间（如有）
3. **备注区**：若 `claim.remark != null`，渲染 info 图标卡。
4. **驳回原因**：若 `claim.rejectReason != null`，渲染 warning 红色边框卡（含 warning_amber 图标）。
5. **报销明细**：每项一个 `Container`（类别彩色图标 + 类别名 + 说明 + 日期 + 金额）。
6. **合计卡**：`UtenInfoRow` 显示"共 N 项" + 总额（`isImportant`）。
7. **底部操作栏**（按状态条件渲染）：
   - **draft**（可提交/可删除）：[删除] + [提交审批]
   - **submitted / reviewing**（可撤回）：[撤回]（isExpanded）
   - 其他状态：无底部栏
8. **删除操作**：调 `deleteExpense(ref, claim.id)` → Toast"已删除" → 跳列表页。
9. **提交审批**：调 `submitExpense(ref, claim.id)` → Toast"已提交，等待审批"，状态变 submitted。
10. **撤回**：调 `withdrawExpense(ref, claim.id)` → Toast"已撤回"，状态回 draft。
11. `AsyncValue.when` 三态：loading 用 `CircularProgressIndicator`、error 用 `UtenEmpty.error`、null 用 `UtenEmpty`"报销单不存在"。

## 七、涉及的数据实体

→ 见 [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `ExpenseClaim`：详情主实体（title / applicant / items / totalAmount / status / createdAt / submittedAt / approvedAt / paidAt / remark / rejectReason）
- `ExpenseItem`：每项明细（category / amount / date / description）
- `ExpenseApproval`：Phase 3 财务审批时写入轨迹（approvedAt / rejectReason 来自此实体）

## 八、权限要求

- **全员可见自己的报销**（按 applicantId 校验）。
- 数据范围：员工只能看/操作自己提交的单据；财务角色在 Phase 3 [报销审批详情页](报销审批详情页.md) 处理。
- 关键操作权限点：
  - 提交审批（仅 applicant 自己 + draft 状态）
  - 撤回（仅 applicant 自己 + submitted/reviewing 状态）
  - 删除（仅 applicant 自己 + draft 状态）

## 九、边界情况

- 无数据时：`claim == null` → `UtenEmpty`"报销单不存在"。
- 加载失败时：`UtenEmpty.error` + 重试（`ref.invalidate(expenseDetailProvider(claimId))`）。
- 性能档 = lite 下：Hero 渐变保留，禁用阴影；按钮去掉 loading 转圈。
- 网络断开时：Phase 1 Mock 无影响；后端接入后：
  - 详情支持离线缓存查看。
  - 提交/撤回/删除需要在线，断网时操作应进入"待同步"队列，恢复后回放。
  - 防止并发：状态变更接口需用 `If-Match`/版本号避免覆盖（如财务正在审批时员工撤回）。
