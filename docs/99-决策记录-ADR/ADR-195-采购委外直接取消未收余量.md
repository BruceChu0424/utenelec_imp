# ADR-195 采购委外直接取消未收余量

- 日期：2026-10-26。
- 状态：按本次业务要求实现；本地验证与正式启用分别记录。
- 修订 ADR-193 中“结束必须财务批准”的规定，其历史记录保留。
- 前向迁移：V944/V945；历史迁移不改写。V945 退役旧结束申请的财务待办可办理性和提醒，保留历史内容。
- 界面使用 `frontend-design`，沿用 Uten 组件、主题 token 和数据范围。

采购或委外人员确认不再需要供应商补交时，可直接取消整张已生效订货单的未收余量。必须先核对服务端计算的逐行数量并填写原因，确认后同一事务立即生效，不产生新的财务审批任务，也不要求存在财务审批人。单条和批量操作共用同一业务服务。

办理权限沿用本部门既有订单办理权限 `purchase_order:submit_finance` / `subcontract_order:submit_finance`，同时检查原单查看权、制单/交接写入范围及当前身份。沿用权限码只为维持既有授权边界，不代表结束动作仍须财务同意。只有查看权不能办理。

| 情况 | 处理规则 |
|---|---|
| 未到货、部分到货 | 原订数量和金额保留，冻结实际已收及已退事实，只取消核定未收量；收费量与赠品分别计算。 |
| 已自然完成、全到齐或超收 | 没有未收余量时不可再增加提前结束标记，不能借此额外冻结正常退货链。 |
| 原商业条款正在财务审批 | 仍阻止结束；正常订单审批不是本次取消的结束审批。 |
| 收货/退货草稿、未决质检、不合格品未退回、未办结到货异常 | 提示原阻挡任务，先完成或撤回对应业务，再重新核对余量；不默默丢弃实物或草稿。 |
| 委外待仓库发料 | 先办清当前发料；尚未执行的后续任务在结束事务内撤回。 |
| 委外已发材料、退料、损耗、合格待入库 | 在外材料责任保留；已结清损耗只作为原计算依据，不把取消量记成新损耗；已检合格实物继续正常入库。 |
| 旧结束申请待财务审批、已被他人认领 | 业务人员重新核对当前事实后直接办理，旧申请取消、待办和认领撤回且保留审计；财务不得再批准旧结束申请。 |
| 重复请求、超时后同请求重试 | 相同指纹、方式和原因返回原完成结果，不重复释放来源、发通知或创建新草稿；不同命令及过期指纹拒绝。 |
| 批量中有不可办理项 | 预览明确列出，仅在用户确认略过不可办理项后提交可办理集合；提交集合要么全部完成，要么整体回滚。 |
| 结束并按剩余量重建 | 原单立即结束，同事务生成关联草稿；草稿须重新确认供应商和条款，仍走正常新订单财务审批。 |
| 历史导入只读或计量不可信 | 保留历史只读和计量守卫，未知量显示“—”，不以零或默认换算推算余量。 |

原商业审批和结束记录独立。兼容存储终态为 `APPROVED`，直接结束的快照明确携带 `executionMode=DIRECT`，审计事件为 `CLOSED`，界面和通知显示“已直接结束”，不显示成“财务批准”。财务原订单详情通过独立 `headerSnapshot.orderClosure` 读取最新结束事实，避免把原商业审批误判为结束申请；结束历史详情只读。

采购、委外和财务详情共用 `ProcurementOrderClosureStatus`，其逐行数量共用 `ProcurementOrderClosureQuantities`，展示原订、累计收货、退货/已结清损耗、取消未收量及赠品，并记录原因、办理人和北京时间。累计收货不等于净留存，取消量已反映品质实退及已结清损耗，界面明确说明该口径。单单与批量确认也复用该数量展示。数量来自服务端完整快照，前端不重算，不丢精度。

订单取消不删除历史收货、库存和应付，不自动核销预付款或应付余额，不抹去生产需求。未消费供给和来源释放、草稿重新占用、后续收货/发料禁入、终态实收基数保护继续复用 ADR-193 的领域实现。结束后的新增原单退货或红冲会改变已冻结基数，仍须另行核对，不能直接重开原订单。财务正常按实际业务办理结算。
