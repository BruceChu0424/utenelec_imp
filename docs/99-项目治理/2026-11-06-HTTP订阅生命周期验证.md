# HTTP 订阅生命周期验证

本记录区分测试契约和本地执行环境，不代表完整 CI 通过或正式发布完成。

`c418ce7cc` 的真实 HTTP 整类已生成 OpenAPI 文档并进入完整接口探测，唯一接口失败为 `GET /api/auth/session/watch`。该接口在没有会话变化时按原业务合同等待 25 秒，旧通用探测却要求每个请求在 15 秒内结束，也没有制造会话结束事件。不能通过修改服务端长轮询或放宽探测超时来解决这项测试缺口。

当前探测先以真实员工登录建立独立观察会话，发起真实 HTTP 订阅，确认观察者确实登记后，通过真实退出接口注销该会话，并调用现有协调阶段。继续在原 15 秒总期限内断言 HTTP 200、`expired`、`no-store` 和观察容量释放。该真实响应仍归入完整 OpenAPI 操作探测的数量和状态统计，并断言文档中保留对应操作。原账号开通、密码门、工作簿、主机桥接、读查询字段及全部非订阅接口断言保留。

主机桥接的员工令牌检查在独立订阅登录前完成，避免新登录按真实会话替换规则退休旧令牌；桥接故障负例结束后复位夹具，才进行后续边界探测。

本地原生 PostgreSQL/Tomcat 已实际通过上述订阅闭环，日志含 `HTTP session watch: real logout completed, status=expired, no-store, capacity released within original15s`。本机整类后续仍在原 45 秒 OpenAPI 冷生成期限超时，完整失败日志保留，不能记成整类通过。最终判定仍需同一发布源码的完整 Linux CI。
