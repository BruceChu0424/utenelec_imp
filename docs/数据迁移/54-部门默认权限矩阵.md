# 部门默认权限矩阵（V212）

> 权威来源：`server/src/main/resources/db/migration/V212__department_permission_matrix.sql`
> 配套文档：[权限管理页.md](../03-页面/权限管理页.md)、[ADR-011](../99-决策记录-ADR/ADR-011-工作台部门分区与动态权限配置.md)
> 日期：2026-08-05

## 背景

部门默认权限此前由 V29/V31-57/V99/V130/V183/V196/V198/V200/V204 等迁移零散累加。2026-08-03 dev 库
TRUNCATE 业务表后这些种子不再重跑，部门权限页全空。V212 把 15 个业务部门的默认权限收敛为**单一权威
来源**：对每个配置部门做受控重置（先 `DELETE` 全部权限，再 `INSERT` 矩阵集，`ON CONFLICT DO NOTHING`）。

## 模型与原则

- 有效权限 = 全员基础（employee 角色包）∪ 部门配置（本部门 + **所有上级**，递归向上取并集）∪ 个人加授 − 个人收回；超管恒全量。
- **向上递归继承**：挂在父部门的权限自动对子部门员工生效 → 写权限**下沉到叶子部门**，避免父级堆权限导致越权下传。
- **3 个管理中心与公司节点保持空白**，不在父级配权限。
- **高危个人-only 权限任何部门都不授予**：`audit_log:view/export`（V173 触发器硬拒绝部门级）、
  `authorization:manage`、`user:manage`、`stock:balance:adjust`、`finance_asset:approve/post/dispose/export`、
  `finance_asset_period:manage`、`workflow_assignment:manage`。需逐条个人点名。
- 全员基础（不在本矩阵）：`profile:edit:self`、`expense:apply`、`notice:read`、`suggestion:submit`、
  `visitor:apply`、`visitor:host-confirm`、`payroll:view:self`。

## 待业务确认的判断点

以下在矩阵中已按业务推断落实，提请复核：

1. **委外 8 类 edit 归 `DEPT_SALES`/`DEPT_RAIL`**：依 V53（销售跟单员驱动委外）。若实际由 PMC 负责，需迁移到 SUB_PURCHASE。
2. **`goods:edit` 同时给 `DEPT_PMC` 与 `DEPT_ENG`**：PMC 维护货品主档（V41），工程维护 BOM/结构。若货品主档只归一方，删另一处。
3. ~~`sales_order:change_planned` 归 `DEPT_PROD`~~ → **已按用户决定收窄到 `SUB_PLAN` + `GM`**（2026-08-05）：原挂 `DEPT_PROD` 会下传 6 车间，导致车间工人可改已排产订单；现归计划部（日常改量）与管理层（审批），不挂生产部。该码不在「全部授权」排除清单内（仅 `sales_order:priority`/`reallocate` 被「全部授权」排除）。
4. **`GM` 是否需要 `*_report:export`**：当前只给 report:view，未给 export（数据出境保守）。如需高管导出报表，个人点名或矩阵补。

## 维护方式

- **调整业务部门默认权限**：直接修改 V212 或追加新迁移（推荐追加，保留 V212 历史）。页面手工配置在运行库上即时生效，但 V212 只在全新 bootstrap 重跑。
- **新增权限点**：仍遵循「功能落地时随版本化迁移登记 `permissions` 行 + 按归属 `INSERT INTO department_permissions`」，V212 是这些授予的收敛归宿。
