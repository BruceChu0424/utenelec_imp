# V615 车间直送来源分配与事件账

## 适用范围与反例

技术线边位只承载同车间上下层任务之间的生产流转。库存的货品、颜色相同，不表示来源可以互换。旧实现以“本位置存在指名给此需求的直送”为布尔资格，再使用整个位置余额；同一位置给 A 到10、给 B 到90时，A 可能占用 B 的90。无物料分析的手工计划没有 PREPLAN 权益兜底，更容易触发。

V615把资格、来源数量、实际投入和反向归属分开记录。普通仓仍承担正常存放；主仓只定义履约范围，receipt、reservation、DRAW、material posting、stock movement都保留实际叶仓UUID。不能以主仓UUID替换物理仓，也不能仅凭同主仓放宽需求/工单/原供给映射。

## 责任关系和双重来源证明

- 有分析来源的任务须同分析、精确父物料路径、MAKE_COMPONENT与父计划匹配；同SKU不同BOM路径不是授权。
- 无分析的手工/历史计划须有真实 `subplan_links` 或有效 MAKE supply peg。需求已有有效特定供给挂接时，以该挂接为权威，旁支父子链接不能越过它。
- 新直送还要求当前同车间、双方任务可操作、来源权限、真实合格产出和未覆盖的责任数量。跨分析没有既存显式授权链的来源不列入候选。
- 同一生产计划行拆出的多个执行段共享该计划行的MAKE peg额度；尚未正式领用的直送承诺也按source plan item合计。不能靠换执行段重获一份额度。候选“最多可送”表示本来源上限，和接收需求总缺口分别显示。
- 历史回填验证不可变的责任与原来源，不因后来错误改了接收车间就重写旧事实。当前实物归属的正向守卫由V616另外控制。
- MAKE采购/委外receipt兑现须保持原供给peg、真实receipt item及实际叶仓。部分收货拆成多个不可变兑现片段，但继续归属同一任务；附近普通库存或另一人的合格来源不能替代原receipt。
- 直送数量先由日报单位按冻结换算率折算基本量，再与需求基本量比较。来源单位保持原生产计划行单位；需求与库存按货品基本单位核算。

## 来源持有与事件

`production_workshop_direct_source_allocations`把精确transfer item连接到正式生产物料reservation。它只追加，不能修改或删除已记录的来源。PREPLAN正式化与MAKE receipt兑现的来源偏好优先精确绑定，再分配剩余可用来源。

`production_workshop_direct_source_events`按原material posting记录ISSUE、ISSUE_REVERSE、GOOD_RETURN、GOOD_RETURN_REVERSE，并记录RELEASE、RESTORE。反向事件同时指向原source allocation、原source event和原material posting，不能只把总数量对平。

V619进一步按真实结算posting冻结CONSUMED、APPROVED_LOSS、LEGAL_WIP及其反向来源片。`settlement_posting_id`保留实际结算记录，`issue_source_event_id`保留原ISSUE来源片。退料只能取原片扣除净结算后真正未耗用的数量；之后撤回另一张退料单也不能重选此前已经耗掉的来源。物理净投入口径不变，结算反向逐原结算片恢复可退资格。

`effective_qty = allocation.qty_base − RELEASE + RESTORE`；`net_issued_qty = ISSUE − ISSUE_REVERSE − GOOD_RETURN + GOOD_RETURN_REVERSE`。每片来源必须满足 `0 ≤ net_issued_qty ≤ effective_qty ≤ allocation.qty_base`。同reservation所有片的持有量等于其未释放量，净投入量等于其consumed_qty；每笔material posting必须精确覆盖。

释放只取尚未投入的来源片；恢复按原RELEASE片反向恢复。原来源已被别的任务合法占用时，恢复事务失败，不换用新到货。A5/B5合在一个reservation、其中一片已消耗时，释放另一片不会把已消耗来源重分类为可用。

实际完工反例还发现，旧MAKE receipt守卫把历史兑现10与完成释放后的当前持有5比较，导致真实退料后无法完成入库。V615将历史兑现约束为不超过reservation原始累计qty，技术位另外按receipt的原report item→transfer item逐组验证不能超过该reservation同来源的原allocation.qty；当前持有和净投入继续由事件账单独约束。保留原receipt/DRAW/ISSUE，不削改历史数量来满足余额。

V615先建立原ISSUE和精确来源片的追溯。随后V618/V619将新退仓流程统一为“当前车间余料送正常仓库”：来源UUID保持不变，实物和私有保管预留按仓库确认的实际普通叶仓接续，不能在原技术位虚增可用量。已领物料直接从在制位置进入正常仓，未领直送料使用受控两腿移位；不开放技术位通用TRANSFER。详见[209-V619车间余料正常仓保管与成本](209-V619车间余料正常仓保管与成本.md)。历史已经审核的原仓退料仍按原真实流水反向。

未终结任务可显式重核/继续领料：按同需求、实际叶仓的原私有余额扣除未实发承诺，只补缺失DRAW，不重复兑现receipt。正常仓仍经申请、实发。齐套和持续路线均可复用同实际仓尚未申请的草稿，已实发历史不改。真实退料与“原登记错误而红冲”是两种业务事实，不以红冲真退料冒充再次领料。任务完成释放的额度不自动复活，恢复仍须核对原来源。

分批到料形成独立预留时，某一批完全退回并在完成时退休（软删除、全释放、净投入0），其原receipt兑现仍是历史事实。统一历史验证允许引用这种已退休记录；新receipt写入另有加锁守卫，必须面对活动、未删除且有未耗用额度的正式预留，不能用“兼容历史”向已退休预留注入新来源。

## 技术位物理边界与历史诊断

技术位库存流水须有真实直送来源的FINISHED_IN或精确material event/movement link证明的DRAW、WDRAW，包括各自正式反向。V619另外允许精确退仓申请与custody MOVE共同证明的技术位移出/反向移入，用于未领直送料送正常仓。普通TRANSFER、OTHER_OUT、WASTE、FINISHED_OUT不能搬走技术位直送料；新页面排除技术位还不够，旧草稿审核和数据库延迟约束同样拦截。普通仓调拨保持原流程。

旧技术位存在无法归入上述链路的库存流水时，不修改原流水、不把后续同SKU到货借来抹平。迁移仅扫描一次，写入只追加的 `production_workshop_direct_legacy_anomalies`，保存原movement UUID和原仓/货品/颜色；受影响维度暂停新的来源分配，重新核料会明确提示。`v_workshop_direct_stock_anomalies`提供当前原始明细诊断，新流水的延迟守卫只按NEW.id点查原始证明。正常来源计算只查询小型历史异常表，不能逐lot重新扫描所有历史库存流水。异常只能在核对原始凭据后通过专门前向迁移修复，不自动删除标记或猜测已解决。

只读核查：

```sql
SELECT a.*, w.code AS warehouse_code, w.name AS warehouse_name, g.code AS goods_code
FROM v_workshop_direct_stock_anomalies a
JOIN warehouses w ON w.id=a.warehouse_id
JOIN goods g ON g.id=a.goods_id
ORDER BY a.warehouse_id,a.goods_id,a.movement_id;

SELECT r.id,r.demand_id,r.qty,r.consumed_qty,r.released_qty,
       s.transfer_item_id,s.effective_qty,s.net_issued_qty
FROM stock_reservations r
JOIN v_workshop_direct_source_allocations s ON s.stock_reservation_id=r.id
WHERE r.id = :reservation_id
ORDER BY s.allocation_no;
```

## 旧数据和迁移边界

旧Flyway文件不改，V615在事务中增加新账并回填可证明的历史来源。单来源按真实material posting及counter依赖回放，不改原单、库存、posting或预留余额。原始生命周期分配量也不得超过真实来源曾收到的总量，不能用已释放量掩盖历史超分配。合并后的未动预留可由精确FORMALIZE/receipt证明使用后来到达的来源，不仅按reservation创建时间猜测。异常位置的确证旧持有仍可记录，历史回填和新料可用资格分开核算。

多来源且历史从未发生posting、释放、消耗时可完整绑定；唯一一次整笔ISSUE恰好吃满全部已证明来源且没有释放时也可证明。多来源曾发生部分ISSUE或退回，即使当前净消耗为0，也无法凭余额猜原来源；缺少精确历史证据会使迁移事务整体拒绝，不留下半套来源账。需要先只读核对原单据后制定具体修复，不使用关闭触发器、重写历史或自动FIFO猜测来强行通过。

三表已登记ALWAYS审计、业务重置CLEAR策略和运行时`business_data_reset()`；不新增业务权限。路线、领料、直送审核仍沿各自独立权限，不借新账扩大仓库或跨车间授权。

## 并发和查询

库存维度锁、需求/正式预留锁与原履约足迹保持一致；涉及多个直送来源时统一先按source UUID顺序锁定，再按到货顺序分配，不能把FIFO分配顺序当成加锁顺序。释放和恢复使用相同source UUID锁序。延迟守卫在提交时复核来源总量与原物理账。

来源查询先限制接收需求/拆批根需求和实际位置，再读取精确receipt及来源片。allocation按source/reservation建索引；事件按allocation、posting、counter索引，余额用逐allocation LATERAL聚合，避免全历史窗口聚合。技术位异常热查询只访问历史异常小表的实际仓/货品/颜色索引；无异常时不再随正常库存流水增长。V610禁止已有流水的普通仓改为技术位，也禁止已有直送历史或非零余额的技术位改变身份、车间或主仓，避免快照被仓库改名换身份绕过。

直送候选先用MATERIALIZED范围按同分析或手工任务原父子/MAKE peg收窄，再调用统一资格与数量函数；不靠截断候选条数掩盖成本或遗漏真实上层任务。真实隔离库点查记录中，9个来源lot匹配2个：来源查询0.425ms，历史异常走Index Only Scan且不扫描stock_movements；候选范围CTE先执行，权威资格只对范围内行复核。这是当次小样本执行计划证据，不宣称已完成大型业务量压测。

## 验证入口

`WorkshopSupplyAdversarialEndToEndTest`使用真实PostgreSQL和服务链检查无关同SKU拒绝、手工MAKE peg跨叶仓、A10/B90专属量、并发确认、暂停接收方、逐来源领退/释放/恢复及技术位普通调拨阻断。`WorkshopDirectSourceHistoryPostgresTest`负责带存量的升级与歧义回滚演练。通知单测检查旧outbox重新读取当前接收人、无效待领卡撤回和指名来源到货权益。最终通过数量及日志以当次冻结源码验收记录为准。
