## 本轮明确根因与回归

1. 财务期初约束直接乘原值与残值率，遗漏 Java 账簿使用的四位残值舍入。原值 `100.0001`、残值率 `5%`、累计 `95.0001` 在旧 SQL 中被拒绝。新增真实 PostgreSQL 回归先失败，修复后 35 项通过（含 16 项真实 PG），零失败、错误和跳过。V974 为本轮新增、公司尚未应用的迁移；未重写已部署迁移或使用 repair。
2. 车间导出只映射底层段状态，报完待检验等阶段会错误显示生产中。Dart 车间公共适配和 Java 导出使用同一组 45 个合同样例；Java 50 项、Flutter 135 项通过，保留本地草稿只属界面的差异。
3. 浏览器草稿准备读取只等待请求成功，未等待只读事务 complete，关闭后立即升级会被自身连接阻塞。真实 Chrome 新用例在旧实现确定性失败；修复等待事务完成后，四组浏览器用例 39 项全过，无跳过。没有增加猜测延时、放宽断言或修改公共 SDK。
4. 合并后的资产表头筛选、资料库权限弹窗、模板应用、仓库选择共 55 项界面回归通过。权限分支额外复跑 55 项通过，失败、错误和跳过均为零。后续主链总体验证以最终源码对应的 CI 及本地回执为准。
5. Win7 来源清单生成器在 Windows 默认写 CRLF，却记录原始字节摘要；Git 按已有 `.gitattributes` 转 LF 后摘要失效。两项新增回归在 Windows 旧实现明确失败。统一生成入口显式写 LF，保留任务状态与证据，避免跨平台检出后产生虚假漂移；进度工具 13 项回归通过后重新生成并核对实际 Git blob 摘要。重复同步还会反复追加相同退役提示，现已通过同一登记入口保持幂等；重复同步回归先失败后通过，既有任务和历史事实不删改。
6. CodeQL 命中资产来源查询的运行时 SQL 拼接。现有业务值已绑定，表名只有内部固定来源；没有据此认定可利用的外部注入。将三个私有自由表名入口收紧为两种明确对象选择，使用完整固定 SQL 和显式类型化的可空 UUID 参数；保留自排除、跨类别查重、UUID 优先、软删除、冲销和事务锁。33 项回归通过，其中 24 项真实 PG；未关闭门禁或抑制规则。
7. 两张新财务业务表缺少公共审计策略登记，手工触发器不符合统一入口。已应用的 V973/V974 不重写；V975 调用公共 `fn_audit_track_table` 登记 FULL/data_change，按函数 OID 替换审计触发器并保留业务守卫与历史。源码合同只对两个精确 SHA 的历史文件允许已知语句，强制 V975 存在并使用公共登记，后续手写禁令保留。非空 V974→V975 真实 PG 回归核对旧行、旧审计、业务守卫、新策略及真实写审计。
8. 导出权限 fixture 仍模拟旧的三参数折旧接口，实际入口已经传入截止日期，导致 mock 返回空值。同步四参数 fixture，并增加折旧、摊销截止日透传及每入口一次范围检查断言；未给业务代码增加空值兜底。审计合同、导出权限和前向 PG 合计 24 项通过，零失败、错误和跳过。迁移 README 的当前目录同步为 V975/901，保留历史记录和离线导入授权边界。

公司数据库以当轮一致性备份在独立、无外网及无宿主端口的 PostgreSQL 副本演练。首轮 V970→V974 已核对 23 张核心表、762,134 条旧审计及全部旧迁移不变，1,300 条模具变更严格符合预期；旧备份的员工绑定数量漂移被前置核验拦住并改取新备份。V975 和最终 JAR 继续在该受保护副本验证，回执与最终提交逐项绑定，不通过生产库试迁移或 repair 获得证据。
