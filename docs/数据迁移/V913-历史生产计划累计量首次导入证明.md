# V913：历史生产计划累计量首次导入证明

本轮发现旧生产进度与新执行规则的口径不同。原 `IQTY` 由仓库进仓流程回写，原 `FQTY` 由工序流程回写；旧完工报表主要使用 `IQTY`。它们不是新平台“审核日报后才能入库”的同一组执行事实。来源见[老库生产溯源](23-生产管理-老库溯源.md)和[生产迁移映射](24-生产管理-新库与迁移.md)。

本轮 73,491 条原计划明细中，25,934 条 `iqty > min(fqty, qty)`，1,343 条 `fqty > qty`。真实完整 V912 结构、正常 bootstrap 上下文及全部守卫下，已分别复现 `production_plan_actual_inbound_guard` 和 `production_plan_actual_finished_guard` 拒绝；另有原行通过对照。不能因此把累计数改小、互相补齐，或补造现代日报、超产审批及库存事件。下次以新来源重新统计，不能使用这些数量作为固定预期。

采用独立的生产历史来源证明，保留原计划及其 13 个原始累计字段。它只证明首次导入确实保存了封存来源，不证明这些数量已经过新平台报工、质检或超产审批，也不增加任何后续生产、领料或入库额度。

执行时须同时满足：

- 完整的原明细 45 列与原表头 15 列经过原类型解析，原行、文件、manifest、冻结代码和运行身份全部绑定。
- 新 UUID、原明细 ID、父计划、货品、颜色、主件、单位、销售上游、行序及全部业务字段按原映射核对；不能只核三个计数或总行数。
- 仅已授权的当前 bootstrap 事务可登记首次来源。没有来源证明的新业务仍执行原限制，原有负数限制保留。
- 初始事务中的业务字段修改、删除重放和来源重绑须拒绝。延期终验重新读取当前实际行，兼容协调器在提交前已标记 `SUCCESS/PASSED`，不能只信触发器排队时的旧值。
- 原运行身份另存不可变的小上下文，冻结运行元数据中的身份字段。延期逐行核对不能反复解压最后的大型库存、托管回执；上下文不能用调用方可伪造的 GUC 或临时“已通过”标记代替。
- 来源表与上下文保留为历史证据。合法清库后，新运行可使用新 UUID 重导同一旧 ID；不能重用旧证明授权新记录。提交后的正常增长、纠减和反向规则保持原样。

`production_plan_costs` 的约 136 万行仍按既有 V673 只读历史资料保存。该批源 `qty` 全为零，不能据此生成原料单耗、正式 BOM 或新的领料需求。PC 等单耗未知的材料对应仍按[执行手册步骤4.5](重建彩排与正式导入执行手册.md#45-注塑件原料关系与水口废料分开)处理。

全量验收还须独立复算完整 typed 来源行 SHA、全部业务字段及 13 个计数，双向核对证明与目标的覆盖、父子和主档身份，并确认没有补造现代执行事实。实现回归与实际整批成功分别记录；当前实际执行状态以[执行手册步骤8](重建彩排与正式导入执行手册.md)为准。
