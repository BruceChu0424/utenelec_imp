## 1. 本期采用的方案

**业务服务和 PostgreSQL 都留在公司，阿里云只做加密转发。** 一次业务接口穿过公网后，在公司完成数据库查询和事务；没有云端逐条 SQL 访问公司数据库，也没有两份可写库存或财务数据。

员工 HTTPS 的正式证书私钥只在公司。云只能传递加密字节，外加专用机器双向证书和 WireGuard。公司侧只允许云到专用传输端口，禁止经隧道进入公司 LAN、SSH、数据库、文件共享和原内网入口。即使云机器失陷，也不能凭云机器身份取得员工权限或内网网络通路；应用漏洞、员工终端失陷和入口拒绝服务仍须独立防护，不能承诺软件零风险。

完整边界见 [ADR-183](../99-决策记录-ADR/ADR-183-本地业务服务与受控远程入口.md)，现场步骤见 [部署与故障处理](../../deploy/remote-access/README.zh-CN.md)。

## 4. 分几步上线

1. **采购定案**：测公司到候选地域的RTT/丢包/上行，核查公司WAN与UPS实物或管理接口；完成企业实名、域名实名及所需备案，保存企业账号报价后采购。
2. **先安装隔离入口**：在受控运维机器填无私钥的配置并生成审核目录，分别安装云/公司侧配置、机器证书与公司证书；保留原内网入口，远程总开关保持关闭。
3. **发布同一套应用**：走现有签名发行与迁移流程，由Flyway顺序执行全部未应用迁移（含V873/V874），不能跳过中间版本或手工改历史校验；启用专用remote connector。Web与后端来自同一公司发行，保留数据库/环境回滚依据。
4. **先做安全负向验收**：总开关OFF时先确认关闭；受控验收窗口可为已绑定验证器的试点账号临时ON，验证成功访问与未授权、未MFA、撤权、旧会话的对照，结束后恢复OFF。错误机器证书、域名、转发头和编码路径不能绕过边界；云到公司数据库/SSH/LAN不通；确认云无DNS、业务或备份权限。
5. **再做速度和断网验收**：在同样的受控开通窗口测试5人及10并发、正常内网同时操作，覆盖冷启动/热缓存/附件；切断公司外网或云入口，验证内网继续、草稿边界、提交结果核对与恢复，结束后恢复OFF。
6. **最后开5人试点**：员工在内网绑定验证器，超管逐人授权，最后开启总开关；观察一周的高峰和实际海外地点。任何安全边界失败先关闭入口再修复。

普通列表初始目标P95≤1秒、简单保存确认P95≤2秒，复杂分析和报表按具体流程设预算；这些是现场验收目标，当前没有真实WAN达标证据。并发名额是准入控制；单请求嵌套事务可能占用多个连接，启动检查不构成物理连接预留，也不能证明CPU、磁盘、锁和全部后台任务完全隔离。须在真实业务压测中核对池等待及内网P95，再决定是否需要更强的资源隔离。

## 5. 故障与增长

公司断外网时内部继续，外部暂停正式办理；已落盘的本机草稿按现有页面能力保留。提交发出后断线，先查业务事实，不能把超时当成失败。云宕机不切换数据库，公司宕机走成套数据库/原件/配置/密钥恢复；恢复前就停用远程通道，之后持续隔离并撤销恢复出来的旧会话与证明。

扩容按瓶颈顺序进行：公司上行/第二运营商备线与UPS → 接口与数据库 → 云带宽 → 云计算 → 双可用区入口。提高授权人数和并发前复测内网体验。固定20Mbps的网络目录价为1325元/月，不能把10→20Mbps当成低成本升级。未来异地灾备是独立建设阶段，必须有原主隔离和恢复演练；现有本地备份不等于已具备异地持续服务。
