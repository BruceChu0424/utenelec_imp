## 一、新建预填（能预填的都预填）

统一边界：**只在新建时预填**（编辑以单据数据为准）；人员类只预填"我方经办"角色，
对方侧人员（采购交货人/委外交货人/生产工）不预填；预填值界面上均可改；查询失败静默降级。

| 模块 | 预填内容 |
|---|---|
| 销售·出货/其它出货 | 业务员+发货人默认当前登录人；选客户自动带出主档收货地址（shipAddress→address）与联系电话（phone→mobile→phone2，可改）；**件数只读 = 明细已选货品各行数量之和（取整）**，选品/改量/增删行即时刷新，保存按明细重算 |
| 销售·订货 | 业务员默认本人；选客户带出合同信息的联系电话/收货地址 |
| 销售·退货 | 业务员默认本人 |
| 采购·申请/订货/收货/退货 | 申请人/采购员/收货人默认本人（交货人=供应商侧不填）；仓库按「本类型最近一张单」预填（D1 规则推广） |
| 委外·8 类单据 | 采购员/经办人默认本人；仓库同上预填 |
| 仓库·5 类单据 | 仓库按「本类型最近一张单」预填 |
| 钱流·5 类单据 | 经办人默认本人 |
| 生产·计划单 | 跟单员默认本人（生产工不填） |

**客户/供应商/委外商双向同步**（销售/采购/委外「从上游引入」）：
- 表头已选 → 引入面板对应筛选**默认锁定**该客户/供应商（可改）；
- 表头未选 → 引入确认后**自动回填表头**为上游单据的客户/供应商（销售回填后联动地址/电话）；
- 返回模型：`SalesLinkPickResult` / `PurchaseLinkPickResult` / `SubcontractLinkPickResult`（items + clientId/supplierId）；
- 特例：采购订货上游=申请单（无供应商概念）自动跳过锁定与回填。

## 二、上游引入只显示"未完成"明细

三个引入面板（销售/采购/委外）Step2 统一改为**只列剩余可引量 > 0 的行**，「本次数量」默认=剩余量：

| 场景 | 剩余量口径 |
|---|---|
| 销售出货←订货 | 订货数 − 已发（shippedQty） |
| 销售退货←出货/订货 | 原单数 − 已退（returnedQty） |
| 采购收货←订货 | 订货数 − 已收（receivedQty） |
| 采购退货←收货/订货 | 原单数 − 已退 |
| 委外进仓←订货 | 订货数 − 已收 |
| 委外发料←订货 | **当前禁用**；不得由 legacy `issuedQty` 推导，缺冻结 BOM 快照与子件台账时审核返回 409 |
| 委外退货←进仓/订货 | 原单数 − 已退 |
| 委外材料退/损耗←发料 | 发出数 − 已退 − 已损耗 |

上游单据明细全部完成时，Step2 空态文案提示「该单据明细已全部完成，无剩余可引入」（区别于"无明细"）。

## 三、审核/财务审核"没反应"排查与加固

**排查结论（E2E 实测，链路是通的）**：本地起 8080 实测——未带令牌 401、权限不足 403、
单不存在/已软删 404「销售出货单不存在」、已财务审核重复审 400「已财务审核，请勿重复操作」、
审核 XC26070063 → 400「发货数量超过可发货数量（预留 0）」。
接口、权限、业务校验全部正常工作；错误信息后端都有明确文案，前端 `appError` 会弹顶部通知。

**用户当时"没反应"的两个前端原因（已修）**：
1. 处理中时底栏整体消失（`_busy ? null : _actions`）+ 无任何进度提示，网络慢/后端不在时像死屏
   → 改常驻 `_BusyBar`（进度条 + "正在处理，请稍候…"），完成/失败 toast 后恢复按钮。
2. `_busy` 期间再点其它动作（如财务审核）被静默 return，连弹窗都不出
   → 改 `appInfo('正在处理，请稍候…')` 明确提示（审核/红冲/删除/改量/取消/财务审核/反审/驳回/报价转入 全量）。

**业务前置提示**：V443 起出货单草稿且 `financeAudit != 1` 时，财务/仓库动作须明确提示
“所有客户出货均须先完成财务审核，再由仓库作业”。月结、现金、定金标签只辅助人工判断，
未分类客户先回客户资料分类；任何标签都不能绕过财审。详情页表头保留「财务审核」状态行。

**XC26070063 审核被拦的业务解释（不是 bug）**：该单两行关联订货行
`chain_status>0`（已上链路）但 `reserved_qty=0`——货还没入库预留。
正确流程：订货 → 排产/生产入库 → 系统为订单行预留（reserved>0）→ 出货审核消耗预留。
遇到该提示：先在订货工作台看订单行的 已排/已产/预留，等成品入库补预留后再审出货。
