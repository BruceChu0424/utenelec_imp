## 二、E2E 实测证据

- **首跑（修复前）**：`FullChainEndToEndTest` 54 项 → 1 失败 + 40 错误。根因单一：**夹具未跟上 V294**——`createApprovedOrder` 只做「创建+审核」，未做财务确认，导致计划侧全部被闸门拦截（`排产关联的销售订单未通过财务确认` / `销售订单未通过财务确认，暂不能纳入物料分析`）。**服务端闸门行为正确，是测试代码滞后**。
- **修复后复跑**：55 项全绿（54 原有 + 1 新增闸门回归），Testcontainers PostgreSQL 16 全量迁移 V1→V295（276 个迁移无重复）。覆盖：销售下单→排产→MRP 多级展开→计划包（非线性 BOM/多尾包/零料段）→物料分析（树/通知子件/READY 批/草稿重放/BUY+SUBCONTRACT 真实下游/对象范围/部分批/共享料让单）→采购订货+财务批准→IQC 隔离/部分 PASS 累计→完工入库（进度=入库非自报）→执行段分批入库边发边产→出货（全发/分批/REQUIRE_COMPLETE 拒部分）→库存=Σ流水→超发拒绝且原子→入库红冲精确回滚→AR=发运合计→收款核销（现金+冲销+汇兑差额+跨币种/超收/费不匹配拒绝）→GL 借贷平衡→peg 守恒→权限角色隔离/对象范围/反 ID 探测→并发（财务审批双批/IQC 幂等重放）→自底向上整树（建成/子件入库释放父段/级联红冲/幂等重放）。
- **新增闸门回归**：`financeConfirmGate_planningInvisibleUntilConfirmedAndEligibilityEnforced`——未确认订单在待排产列表与物料分析候选**均不可见**（订单侧 chain_status=2 回写照旧）；非财务部门账号经部门矩阵拿到 `sales_order_finance:confirm` 后 `@PreAuthorize` 通过但**确认人资格层仍拒 403**；合格确认人确认后计划侧立即可见。
- **配套套件**：CriticalHttpContract（账号开通真实 HTTP）、ProductionChainHealthContract（新增 V294 谓词契约断言）、采购/委外 DecompositionPreview（改为断言跨仓同批返回）、ProcurementInspectionIntegrity、SubcontractMaterialConservation、ProductionMakeSupplyLifecycle、ProductionMaterialAnalysisPersistence、InventoryTransactionalIntegrity、FinancePaymentSettlement 全部通过（结果见文末运行记录）。

## 四、已知非阻断缺口（本次核查发现，未修，待排期）

1. **前端可达性（后端端点在、Flutter 无入口）**：① 总账重生成 `POST /finance/gl/generate[-all]` 全 lib 无调用，财务无法从界面过账；② 物料分析作废 `/{id}/cancel`、`/{id}/actions/{actionId}/cancel` 无 repository 方法；③ 订单中止 `stopped`、客户分批确认 `partial-shipment-confirmation` 仓库方法无 UI 调用方；④ MRP `generate` 前端无对应、`generate-draw` 后端恒 409 属死端点且与 `generate-finished-in` 守卫行为不一致，建议下线对齐。
2. **V294 运营缺口**：无反确认（误确认不可逆）；确认无显式 audit_log（事实列已有确认人/时间/备注，对比 `setLinePriority`/`yieldReservation` 有显式审计）；确认人池为空时 outbox 事件零接收人仍标 delivered、无升级告警。
3. **口径观察（有意设计/低风险，记录在案）**：开始拣货容量校验不计他单**全局预留**与他单挂单在拣任务（冲突推迟到出库 `recordMovement` 非负校验拦截，fail-closed 不超卖但拣货可能白做）；AP 按收货全量立账、IQC FAIL 不自动红字（须采购退货对冲，与「FAIL 只记事实」一致）；收货回写 `received_qty` 含 FAIL 量（结案口径含待退量）；`SalesShipmentService.reverse()` 对已审单不可达但保留完整红冲代码（Javadoc 易误导）；`shippableLines` 未过滤 chain_status≤0 历史行（开单时 fail-closed 拒绝，体验落差）；`MaterialAnalysisService.list` JOIN sales_orders 不过滤 finance_confirmed（受 maker 隔离+创建准入约束，风险极低）；报工红冲 FIFO 反向归因靠 CAS 拦截（PROD-P1-2 已知限制）；完结封顶跨多执行段 fail-closed 拒绝须人工核对。
4. **发布阻断不变**：目标库迁移与历史对账、真实多岗位权限 UAT、仓库/生产/采购/委外实物演练、完整质量域、容量与恢复演练、发布签字——见 [2026-08-09 生产就绪清单](2026-08-09-本地云端部署与生产就绪清单.md)。本报告的服务级验证不替代上述任何一项。
