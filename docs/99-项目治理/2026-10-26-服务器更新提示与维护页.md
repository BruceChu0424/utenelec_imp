# 服务器更新提示与维护页

本轮按用户最新要求先完成更新提示；其他并行任务收尾后，再继续全量整合、CI 和正式发布。本记录描述本地实现，不代表已安装公司服务器或旧客户端已获得新能力。

## 统一入口与状态契约

所有 Flutter 页面、登录入口与 Windows 客户端统一由 `lib/core/maintenance/server_maintenance.dart` 读取 `GET /api/system/maintenance`，由 `lib/shared/widgets/server_maintenance_host.dart` 展示。`lib/app.dart` 是唯一应用接入点，不在各业务页面重复轮询或弹窗。

公开响应仅包含 `schemaVersion/state/noticeId/serverTime/startsAt/targetVersion/retryAfterSeconds`。状态为 `available`、`scheduled`、`updating`、`recovery_required`，不返回操作人、数据库、附件路径、发布凭据或主机诊断。Nginx 直接读取主机原子写入的固定公开文件；直接连接后端使用同契约的 `PublicMaintenanceController`。普通网络错误或未知响应不构成“正在更新”的证据。

| 入口 | 实现与验证范围 |
| --- | --- |
| 浏览器、Windows、登录前后与业务弹窗 | 应用根宿主；同一预告确认一次；520px 上限居中弹窗；窄屏、大字体、键盘与中英韩文本 |
| 新打开或刷新浏览器 | `web/maintenance.html/css/js`；同源外部资源，适配已有 CSP；静态页面自动检查恢复并保留原业务 URL |
| 内网 HTTPS、标准 HTTPS、内部测试、独立云端模板、远程公司入口 | 五份现有 Nginx 模板共用 `/var/lib/uten-imp-public/` 资产与状态；后端停止时仍可读，维护响应为 503、no-store，保留安全头 |
| 服务器更新作业 | `deploy/simple/host_operations.py`；立即更新在验签、暂存、备份核验后发布完整 600 秒预告；预约更新提前公布；停服前复核绑定 |
| 下层人工激活 | `deploy/simple/uten-imp-updater.sh` 的授权守卫；现有部署必须由正常运维作业完成预告后激活，防止 CLI 旁路；真正空白首装保留独立条件 |
| 失败后恢复确认 | `deploy/simple/maintenance_recovery.py`；root 本机入口、独立私有回执；原失败作业原字节保留 |

上述五份 Nginx 来源为 `deploy/nginx/uten-imp-http-lan.conf`、`uten-imp.conf.example`、`uten-imp-internal-test.conf.example`、`deploy/cloud/nginx-cloud.conf.example`、`deploy/remote-access/templates/company-nginx.conf.tmpl`。现有远程云端 TCP 转发继续透传公司入口，不新增第二份可变维护状态。

## 交互与业务事实保护

提前十分钟提示用户保存工作并等待当前提交完成，确认后保留倒计时入口。倒计时按服务器 HTTP Date 与单调计时校准，不依赖员工电脑时钟；到点仍等待服务器明确进入更新，不自行阻断业务。

维护覆盖层保持底层路由与编辑器挂载，不自动刷新已打开的业务页面、不清草稿、不注销会话、不重放写入。恢复必须同时获得 `available` 与真实 readiness `UP`；未知提交仍需核对结果。后台客户端暂停轮询，回到前台立即重新读取。

独立静态页面没有编辑器，只有在状态可用且 readiness 正常后才自动重新打开原 URL。更新取消或停服前失败撤销预告；进入恢复核验的失败保留维护页面，不自动再次激活。

人工恢复确认核验签名清单全部文件、签名版本与提交、实际 JVM 的物理 JAR 路径与进程身份、完整迁移目录、数据库/附件备份绑定及连续健康。通过后记录完成事件。后续正常修改发布来源或同版本重启不会复活已结束的旧维护。若 PostgreSQL 实例启动身份已改变，本入口严格拒绝，须先独立完成数据库实例恢复核验，不自动刷新绑定。

## 保留差异与首次推出边界

浏览器静态入口在服务停机时仍能由 Nginx 返回页面；Windows 与已经加载的 Flutter 由同一全局宿主显示。旧 v2.5.31 页面或旧 Windows 二进制没有新增轮询代码，必须加载含本功能的新客户端，后续更新才会收到新增居中预告。不能强制刷新仍有输入的旧窗口，也不修改旧签名发布包。

静态资产通过主机安装器从同一受审源码原子安装，独立于 `current/web`，覆盖首次升级前后与失败回到旧代码的情况。源码修改或应用发布本身不等于主机助手、Nginx 与资产已安装；安装顺序及恢复命令见 [服务器运维](../../deploy/simple/SERVER_OPERATIONS.zh-CN.md) 和 [运行手册](../../deploy/simple/RUNBOOK.zh-CN.md)。
