# V895：撤回父批次后保留独立子供给原始责任

本迁移只新增、替换数据库函数和守卫，不改任何既有订单、计划、分摊、原始库存、权益事件或数量，也不恢复已取消父批次的活动别名。源码候选与隔离回归不表示服务器已安装。

## 根因与权威证据

共享父批次撤回后，独立子批次的计划或采购、委外申请仍然有效，但分摊仍指向旧父锚点中的 canonical 物料。取消父行动后，原别名不再承接需求；旧子单的计划量因此保留，原销售树却出现同量待补，后续入库也可能仍归旧路径。

V895 只使用子批次 CREATE / APPEND 中不可变的 `sourcePrivateQtyByTargetMaterialLineId` 证明原始私有来源。每个 target 的已记录私有量必须与 allocation 相等，原 UUID、分析范围、货品、颜色、单位、相对 BOM 路径必须匹配。纯公共制造上下文不会因名称、同 SKU 或旧父关联自动获得销售私有权益。缺少完整证据时明确阻断新增规划及收货归属，不猜测承接。

公开只读接口 `fn_preplan_aggregate_recorded_private_sources(analysis)` 返回历史来源证明，`recorded_qty` 不是当前供给量。单批入口为 `_scoped(analysis, material, batch)`，批量入口为 `_scoped_batches(analysis, material, batch_ids)`；只有后者保存 JSON 解析逻辑，其他入口为兼容包装。备注来源读取使用这个接口，不复制解析器。

## 当前责任与真实收货

`fn_preplan_aggregate_retained_private_sources` 将原始份额与当前有效需求、其他实际供给、已下达责任和当前累计实收共同核对。当前可承接量与累计准入、已实收、未实收分别返回；累计准入不得低于既有实际实收，未实收只扣一次。现有 transfer 算法保存在 `fn_preplan_allocation_base_admitted_qty`；原 public admission 函数保留 OID 并接入已证明的保留责任。

当前准入复用既有刷新权威的「本节点 `required_qty` + 活动别名责任」，校验原来源和仍有效的 BOM、制造路线；不再另写一套源毛需求、祖先扣减或非线性曲线。原有刷新已处理实际合格最终件、外部最终件未来供给、已审委外冻结供料，以及每个实际制造批次的固定批/整包曲线。保留成员只改变本节点的后代需求，不会把自身需求清零；活动别名也保留已实际耗用的累计制造责任，因此不能把父件已完成 40 后的未来需要 60 再减一次子件已收 40。历史 `source_capacity_qty` 的最大值不作为新增准入。

入库在原有履约预锁和事务内先刷新相关分析，再读取新的私有、公共准入。销售修改等待财务复核、来源/BOM/路线暂不可用或旧路径实收待核对时，明确拒绝本次收货并整体回滚；已有私有承诺和 origin 不自动释放成公用。恢复来源有效状态后，可以重新确认原待收入库单。

未收承诺只从旧 canonical 扣一次，并计入原 UUID。再下父批次后，通过新的活动别名承接同一承诺，不同时在旧 canonical、原树及新 canonical 抵三次。共享目标的实收只按该原来源的精确委派切片核对，不能把整个共享目标数量同时扣到每个来源。子供给仅记录 A 来源时，不会要求它同时声称旧父的 B 来源；B 仍可正常另下达。

新的真实 MAKE / IQC 入库先按原始私有权益建 origin，再沿现有 append-only 权益委派流入当前父批次。普通入库保留旧幂等键；只有拆分至 original 的记录添加原 UUID。四位小数按稳定原 UUID 的累计权重边界分摊，分次、拆行不得丢失万分位。按原来源过滤的实收继续使用 V571 净预留、转正式与根履约事件口径，不使用单据表头状态下的历史数量求和替代余额。

候选先按未取消子批与已取消父锚点限定，再按 UUID 数组一次解析；空候选不退回全分析。批量未来供给读取复用同条 SQL 已物化的准入汇总。取消行动的分析范围条件和局部索引一起避免扫描别的分析历史。

## 已执行事实与历史坏状态

旧 canonical 已有合格实收时，新版父撤回在反向计划或执行包之前返回业务冲突。数据库仍保留原委派归还守卫，并补充同一约束。没有自动重写原始库存 origin、beneficiary，也没有将领用、正式占用或已执行事实释放成公用。

对于此前版本已形成的「父已取消、旧 canonical 仍有实收」，GET 详情继续返回 `AnalysisView`，通过现有 `planningBlockedReasons` 展示原因；相关新增规划返回冲突。该状态不自动修库存，不重新采用另一来源，不重放历史命令。发布前必须保留只读核对证据，由明确的可逆业务命令处理实际单据与归属。

## 验证与发布界限

业务回归使用独立 Testcontainers PostgreSQL 和真实 Spring 服务，覆盖撤父保子、再建父、原始 UUID、100 + 200 不等量来源的真实分次报工入库、万分位、祖先最终实收、固定批曲线，以及旧 canonical 先实收后的原子拒绝和历史状态可读。对应类为 `AggregateRetainedResponsibilityEndToEndTest` 与 `AggregateRetainedBatchCurveEndToEndTest`。具体通过数量、日志及最终候选哈希记录在[撤回与调拨验证](../07-业务链路/物料分析撤回与调拨验证.md)。

本迁移没有自动公司数据处置步骤。不得修改已应用迁移、执行 Flyway repair 隐藏漂移，或在原业务库用回归夹具改守卫。隔离夹具中模拟此前守卫语义的测试必须在同一事务恢复函数，且只作用于自建测试库。
