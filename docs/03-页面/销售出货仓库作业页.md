# 销售出货详情 · 仓库作业（V187/V188）

> **页面形态**：复用销售出货详情页，不另造一套库存真相。
> **更新日期**：2026-08-01 · **状态**：订单发运策略、服务端商业事实、单据级仓库作业与 V188 不可变事件账源码已落；V189 销售退货冻结另见业务链文档。目标库迁移、真实岗位权限和实物 UAT 待验收，完整 WMS 仍为 NO-GO。

## 1. 业务定位

销售订单审核只形成订单有效预留，不等于仓库已备货。新流程按以下边界推进：

`订单有效预留 → 出货草稿 PENDING_PICK → PICKING → PICKED → SHIPPED`

- 出货草稿占用订单行可发额度，防止多人重复建立任务；不二次扣 ATP，不扣在手。
- 开始拣货校验指定仓的真实可拣量并进入实物作业保护。
- 交接出库才消费预留、扣库存、回写销售订单并立应收；部分交接只把本次消耗段绑定该仓，未发余量仍可由其他仓履约。
- 无订单的零星出库使用“其它出货”，销售出货不允许手工混入无来源行。
- 客户、币种/汇率、税率、付款方式、销售员和行价格/折扣/原本币金额由服务端从来源订单重建；订单原币额=`qty×price`、本币额=原币额×汇率（4 位），出货按数量比例计额；客户端金额/成本不是商业或会计权威。
- V188 每次状态转换在同事务追加仓库事件；当前状态用于页面，事件账用于追溯，已接受事件不可修改或删除。

## 2. 页面显示

详情表头显示发运/仓库状态、最近作业时间、开始拣货时间、拣货完成时间、物流交接时间和异常原因。状态文案必须来自服务端字段，不从按钮点击或本地缓存推断。

| 状态 | 页面动作 | 服务端约束 |
|---|---|---|
| `PENDING_PICK` | 开始拣货；可登记异常 | 复核订单来源、发运策略、现金客户财务审核和仓库可拣量 |
| `PICKING` | 完成拣货；可登记异常 | 不允许编辑、删除、驳回或财务反审 |
| `PICKED` | 交接出库；可登记异常 | 交接须二次确认；库存、订单、应收同事务 |
| `EXCEPTION` | 填写处理/退拣说明并恢复待拣 | 原因必填；恢复不代表质量问题已自动解决 |
| `SHIPPED` | 只读；从来源关系走销售退货 | 无论是否有 `handedOverAt` 都隐藏并拒绝普通红冲；历史缺时间只表示证据未知，不表示未交接 |
| `LEGACY_PENDING` | 显示历史兼容说明和旧审核入口 | 不补造开始拣货/已拣时间线 |
| `CANCELLED/REVERSED` | 只读 | 保留历史，不提供假动作 |

异步提交期间动作按钮禁用并显示进行中状态；成功后使用服务端返回详情刷新。409/403/400 必须显示具体冲突、无权或校验原因，不能静默返回列表或停留在假成功状态。

## 3. 权限与对象范围

| 能力 | 权限 | 额外范围 |
|---|---|---|
| 查看出货 | `sales_shipment:view` | 销售归属/委派范围；仓库、财务特殊动作权限仅扩大其必要读取范围 |
| 建立/编辑销售出货 | `sales_shipment:edit` | 必须能写来源订单归属；新流程逐行带订单行 |
| 仓库作业 | `sales_shipment:warehouse-work` | 服务端仍校验出货归属对象范围；默认授 PMC 运营部 |
| 仓库驳回并释放订单预留 | `sales_shipment:reject` | 仅待拣或历史待审草稿；开始作业后先异常退拣 |
| 财务审核/反审 | `finance_shipment_audit` | 财务已审单在反审前不可编辑、删除或驳回；仓库开始拣货后反审被拒绝 |
| 客户分批确认 | `sales_order:confirm_partial_shipment` | 同时满足订单正常写范围；特殊动作权限不自动变成全销售跨归属权限 |
| 查看价格/商业条件 | `sales_order:price:view` 或财务授权 | 无权时服务端把表头金额/币税/付款条件及行价格/成本字段置空，不靠页面遮盖 |

页面显隐只改善体验，服务端 `@PreAuthorize`、对象范围和状态机才是权威。无权深链进入统一拒绝页，不得静默跳工作台首页。

## 4. 接口

```text
POST /api/sales/orders/{id}/partial-shipment-confirmation
body: { confirmed: true|false, reason: "联系人/渠道/决定依据" }

POST /api/sales/shipments/{id}/warehouse-work
body: { targetStatus: "PICKING|PICKED|EXCEPTION|PENDING_PICK|SHIPPED", reason: "..." }
```

客户端不能传任意状态。异常和恢复必须有原因；跳级、重复提交、陈旧状态、仓库库存不足、其它任务占用、预留错仓、客户未确认或财务未放行均返回失败且事务不产生部分副作用。

V90 历史 `chain_status=0` 且没有有效预留的旧未结订单，必须在**新建 V187 出货时**提前拒绝，不能拖到开始拣货才报错。业务人员须按订单逐行对账库存、历史已发数量和旧排产后显式激活；当前没有自动批量激活，也不得用迁移脚本伪造历史预留。V187 迁移前已存在的 `LEGACY_PENDING` 出货草稿仍保留旧审核兼容，这是不同边界。

## 5. 明确未覆盖

- 库位、批次/序列号、效期、实拣数量和替代批次；
- 二人复核、装箱、箱码、称重、承运商/运单/多件交接；
- 一张出货单跨多仓与仓间调拨任务；
- V189 已提供销售退货最小冻结与 `GOOD_RELEASE/SCRAP/REWORK`；完整检验项目、批次、特采、召回、返工工单和报废财务仍未覆盖；
- 扫码设备、离线作业和仓库级对象范围。
- 正式价目、折扣/税额最终结算、多次分批舍入尾差归集和开票 condition engine。

这些能力落地前，本页只能称“单据级最小仓库状态”，不能称完整 WMS。

## 6. 人工验收清单

1. 同一订单行两账号并发建任务，总量不超过订单有效预留。
2. 现金客户未财务审核，开始拣货失败；审核后成功；开始后反审失败。
3. 一个现货、一个长周期产品分别验证三种发运策略。
4. 指定仓不足、安全库存保护、其它订单预留和另一在拣任务均能阻断。
5. `PICKING/PICKED/EXCEPTION` 下编辑、删除、驳回、让单、订单改量/取消都失败。
6. 异常无原因、恢复无原因、跳过状态和重复交接均失败。
7. 交接失败时库存、预留、订单已发量、应收全部不变；成功时四者同事务变化。
8. 所有 `SHIPPED`（含历史缺 `handedOverAt`）都没有普通红冲入口且接口拒绝；纠错走 V189 退货冻结。
9. 客户端伪造价格/金额/币税条件不生效；不同商业条件不能错误合单；财务已审单编辑、删除、驳回失败；无价格权账号响应不含商业字段。
10. 仓库异常/恢复/交接事件可按时间线查询，数据库 UPDATE/DELETE V188 事件失败。
11. V90 未激活订单新建出货提前失败；对账显式激活前不能生成作业；既有 `LEGACY_PENDING` 草稿仍按兼容边界验收。
