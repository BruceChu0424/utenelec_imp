# 审计中心

> 目标：获授权的核查人员不用理解数据库字段，也能快速回答：**谁、在什么时间、用哪台设备做了什么、结果如何、是否有风险，以及具体改了什么**。
>
> 页面：`lib/features/admin/pages/admin_audit_log_page.dart`
> 后端：`server/src/main/java/com/uten/imp/audit/`
> 数据库：`V169__audit_center_risk_and_full_operation_coverage.sql`、`V171__audit_export_and_configurable_retention.sql`、`V172__audit_device_evidence_and_local_correlation.sql`、`V173__audit_view_permission.sql`、`V183__professional_asset_and_deferral_subledger.sql`、`V184__refresh_audit_trigger_coverage.sql`、`V185__audit_soft_delete_and_redaction_hardening.sql`

---

## 入口与权限

工作台 → 系统管理 → 审计日志，路由 `/admin/audit-logs`。超级管理员因固有全权限可进入；所有非超管
都必须由超级管理员通过个人覆盖点名授予 `audit_log:view`，该权限不能配置给部门或随部门树继承。
页面、详情和本机回执均为只读，任何账号都没有修改或手工删除审计记录的接口。
导出属于数据外发，除查看权限外还需独立权限 `audit_log:export`；非超管同样只能个人点名授权。
V171/V173 会清理升级前已有的非超管审计导出/查看授权，发布时必须按批准的核查人员名单重新授予，
不能依赖旧部门配置继续生效。

## 页面信息架构

### 1. 总览卡片

| 卡片 | 含义 | 点击行为 |
|---|---|---|
| 全部操作 | 当前日期和搜索条件内的所有用户操作 | 清除风险、结果、分类下钻 |
| 风险行为 | 中、高、严重风险数量 | 仅看风险记录 |
| 严重风险 | 刷新令牌重用等需要立即核查的记录 | 仅看严重风险 |
| 失败操作 | HTTP 失败、认证失败或安全策略拒绝 | 仅看失败记录 |
| 数据变更 | 有数据库 insert/update/delete 快照的记录 | 仅看数据变更 |

卡片是筛选入口而非装饰。当前生效卡片有选中态，再次选择“全部操作”恢复总览。

### 2. 近七天趋势

按天显示操作总量与风险行为量。总量使用主题主色，风险量使用风险色；图形同时提供
`Semantics` 文本，不能只靠颜色理解。

### 3. 搜索与筛选

- 默认最近七天、**用户操作**（`actorScope=user`）与**写操作**（`operationKind=write`），先把货品、分类、
  客户、供应商等日常增删改从批量迁移和普通 GET 噪声中露出来；这只是默认视图，不删除任何系统记录；
- 范围：用户操作、全部、系统操作；查看安全/认证类事件时页面会清除用户范围，避免隐藏匿名失败；
- 操作：全部、写操作、新增、修改、删除、读取；选择登录等原始动作或非数据变更分类时会清除不兼容的
  操作类型，避免互斥条件返回空结果；
- 关键字不区分大小写搜索 action、操作人账号、对象类型、对象 ID、HTTP 路径和 request ID；
- Flutter 对象快捷项当前只有货品 `goods`、货品分类 `material_categories`、客户 `clients`、供应商
  `suppliers`；后端会把这四项同时匹配数据库表类型与对应 `/api/master/**` 请求路由组，因此成功、失败和
  回滚尝试都不会因只有 request 记录而被快捷筛选漏掉。其它对象 ID 可用通用关键字搜索，后端 API 仍支持
  `targetType` + `targetId` 定位任意对象；
- 来源：request、database、business、security；Request ID 独立框只提交完整 UUID，部分值使用关键字；
- 日期范围，默认最近七天；
- 分类：全部、业务操作、数据变更、登录会话、权限变更、安全事件、导出、系统设置；
- 动作、风险级别、成功/失败；
- 一键重置；后端分页，按 `createdAt DESC, id DESC` 稳定倒序。

### 4. 可读事件列表

每条记录优先展示自然语言摘要，而不是原始 action：

- 操作人账号；
- 动作摘要，例如“修改 · 生产执行分段”“调整权限 · 用户账号”；
- 操作对象与对象 ID；
- 精确时间；
- 风险等级和操作结果；
- 设备简称、平台、IP、HTTP 状态码等辅助信息。

解释器为 goods、material_categories、clients、suppliers、资产/待摊分类及 `/api/master/**` 常用路由提供
中文对象标签；未知对象保留可读化 fallback，并在详情中继续显示原始 `targetType`，不能因缺标签隐藏记录。

窄屏采用单列卡片，宽屏把操作人、动作、时间、风险和结果排成易扫描行。点击任意记录打开自适应详情：
桌面端为右侧面板，移动端为底部抽屉。

### 5. 导出当前结果

AppBar 的「导出当前结果」直接复用 `UtenExportButton`。首次列表高水位尚未取得时按钮禁用，不弹密码框、
不发送导出请求；取得 `snapshotId` 后才开放。导出严格沿用页面当前的关键字、对象、来源、
Request ID、用户/系统范围、操作类型、日期、动作、风险、事件类型、成功/失败与当前快照，
不另建一套口径。点击后必须设置 6–128 位 Excel/WPS
文件打开密码；服务端使用 Agile AES-256 加密，受独立权限、每用户频率限制、并发闸门和
`export_max_rows` 行数上限保护。

表格包含可读动作、对象、结果、风险等级与原因、事件类型、来源、设备名称/厂商/型号/平台/系统、
App 版本与构建、设备形态/浏览器/语言/时区/真机声明、本机安装标识、本地操作 ID、本机发起时间、
设备采集状态与摘要、IP、HTTP 上下文、request ID 和审计日志 ID。批量文件刻意不含 before/after JSON、
任何 User-Agent 字段和原始设备 Header；需要核查字段变化时按日志 ID
回到详情，避免把大体积或更敏感的快照批量外发。成功导出另记 `export_audit_log`，限流或失败请求也由
提前进入拦截链的请求审计记录。

## 详情子页

详情必须有以下四个可切换子页；窄屏 TabBar 可横向滚动：

### 概览

回答“谁、何时、做什么、对什么对象、结果如何”。展示风险等级与可解释原因；风险是规则命中结果，
不是机器学习结论。

### 数据变更

将脱敏后的 `before` / `after` JSON 解析为字段级对比，逐项显示变更前和变更后；同时允许展开原始
脱敏 JSON，便于排障。V185 后新生成的通用触发器记录会继续剔除密码、令牌、身份证、手机号、地址、
银行账号、薪资、联系人、迁移列明的原因备注类敏感文本及大型嵌套 JSON 快照。业务名称、编号等调查必需
字段仍按最小必要原则保留。V185 不无界重写旧审计行；历史记录
按原事实保留，只能由受限详情权限、留存策略及经批准的分批调查/治理控制风险。

### 设备证据

展示服务器固化的客户端声明快照：设备名、厂商、型号、平台、系统、App 版本/构建、设备形态、浏览器、
语言、时区、真机/模拟器声明、客户端发起时间、随机本机安装 UUID、设备快照摘要、本地操作 ID 与服务器
Request ID。详情默认只显示服务器快照；核查人员点击“授权并核对本机回执”后，服务端先校验权限并记录本次核查，
成功后才读取当前设备的本机资料与回执。若当前设备恰是原操作设备，会按 Request ID 在多次请求尝试链中定位具体
尝试，并逐字段显示“服务器 / 本机回执 / 一致性”；401 自动刷新、503/504 重试不会因最终 Request ID 不同而误报。
无权限、离线或授权接口失败时不读取本机安装标识、设备资料或回执。

本机回执异步尽力写入，最多 300 条，并按系统公开的审计总留存月数清理；不保存 query、请求正文或令牌。
回执正文以明文 JSON 存在本地偏好存储，HMAC 密钥单独存入平台安全存储：完整性通过只能发现普通编辑、密钥变化或写入损坏，
不是服务器签名或硬件证明。核查人员在另一台设备不能远程读取原设备本地存储；持
`audit_log:view` 的核查人员可在原设备进入“设置 → 本机信息与操作回执”，联网完成后端授权后，按完整
操作 ID 精确查询。普通员工和访客没有入口，深链也会被拦截；查询动作本身另记审计。本机回执没有手工清除
或修改功能，只会按留存策略自动清理；卸载应用或操作系统清理站点/应用数据仍可能使其消失。
系统不采集 IMEI、MAC、硬盘序列号。产品权限只能控制 UI 与 API；已经取得设备管理员/root 权限、
浏览器开发工具权限或用户系统账号的人仍可能直接读取本地偏好数据，因此本机回执不能承载密码、令牌、
请求正文或直接 PII，也不能当成不可抵赖证据。

审计列表、统计、详情和本机核查调用本身会继续产生服务器审计；客户端故意不为 `/admin/audit-logs/**`
写本机回执，避免“观察审计又生成待观察回执”的递归和挤占本机 300 条容量。

### 高水位边界分页

审计查询本身也会新增审计行，若直接用无边界 offset 分页，新高 ID 行会把旧页向后推，造成翻页重复或漏行。
第一次列表请求不传 `snapshotId`，服务端读取当时的最大日志 ID（空表为 0）并在响应顶层返回；随后翻页、
统计和页面导出都复用该值并固定查询 `id <= snapshotId`。直接调用 summary/export API 且未提供快照时，
服务端也会在该请求开始时自行取得最大 ID 并固定边界。刷新、搜索、日期、任一基础筛选、统计卡下钻或
“查看同一操作”会清除旧快照并重新取得一个边界。在普通后续高 ID 写入场景中页集不会被这些新行推移；
边界之后的新操作仍然保留，只是在主动刷新前不混入当前结果。

该边界不是跨 HTTP 请求持有的 PostgreSQL MVCC 快照：ID 已分配但稍后才提交的旧 ID 行仍可能进入结果，
留存任务并发删除在线行也可能移动 offset。因此它保证的是普通“后续分配更高 ID”写入下的确定性分页，
并显著消除审计查询自身造成的漂移；晚提交、03:17 留存窗口及高并发场景仍须实库验证，不能宣称绝对零重复/零遗漏。

### 技术信息

供排障使用：事件来源、request ID、HTTP 方法和路径、状态码、耗时、IP、User-Agent。
同一个 request ID 可关联一次用户请求和它引起的多条数据库变更。

## 风险规则

| 等级 | 当前规则示例 | 页面说明 |
|---|---|---|
| 严重 | 刷新令牌重复使用 | 可能存在会话泄露，需要立即核查 |
| 高 | 删除、权限/数据范围、系统设置、重置密码、库存调整、红冲、离职、黑名单 | 可能产生不可逆或越权影响 |
| 中 | 登录/认证失败、访问拒绝、HTTP 4xx/5xx、改密、数据导出、工资条 PDF 下载、查看敏感审计证据 | 需要确认是否为误操作、异常外发或攻击尝试 |
| 低 | 未命中以上规则的普通查看和业务操作 | 正常留痕，不表示绝对安全 |

风险以数据库生成列为基础；后端读模型会把 V185 前以 `update` 存储的软删除识别为“删除/高风险”，并把
“查看审计详情、核查本机回执、工资条 PDF 下载”等敏感证据访问提升为中风险，
并让列表、筛选、统计、趋势与导出保持同一有效口径。后续新增关键动作时必须同时补生成规则或读模型覆盖、
标签和测试。

## 操作记录覆盖

审计分三层，服务端 request ID 将请求和数据库变化串联；客户端本地操作 ID 串联自动刷新/重试尝试：

1. **请求覆盖层**：`AuditRequestContextFilter` 从安全过滤链前开始计时，MVC 内由
   `UserOperationAuditInterceptor` 落库；没有进入 MVC 或尚未落库时由 Filter 的 `finally` 兜底。这样
   `GET/POST/PUT/PATCH/DELETE/HEAD /api/**` 的正常请求、匿名认证请求、401、CORS 非法来源 403、404/405 与前置异常都有一条
   请求记录；JWT 完整校验成功后会把用户 ID/账号快照绑定到本次 request，因此即使 404/405 返回时安全上下文已清理，
   仍能准确归属操作人，未认证请求则明确为空。记录包含方法、路径、状态码、耗时、IP 与 UA；不保存 query
   值和请求正文，避免复制搜索条件、密码、令牌或 PII。`OPTIONS`、静态资源和健康检查不是用户业务操作。
2. **显式安全/业务事件**：登录成功与失败、限流、账号锁定/停用、员工与访客刷新会话、刷新令牌重用、
   访客验证码、登出、401/安全策略拒绝、导出、工资条 PDF 下载和其它必须单独命名的动作，由
   `AuditService` 显式记录。审计详情、本机回执核查与敏感下载在显式审计失败时不会继续披露内容。
3. **数据库变化层**：V169 为当时所有尚未覆盖的公开业务表补齐 AFTER INSERT/UPDATE/DELETE 触发器；
   V183 最终为其 9 张资产/待摊新表显式创建 `trg_audit_*` 并在迁移尾部做一次只补缺 sweep；V184 再以
   独立后置迁移复核。每张业务表必须恰有一个前缀触发器，且已启用、为 AFTER ROW、覆盖 INSERT/UPDATE/DELETE，并调用
   `fn_audit`/`fn_audit_redacted`，否则迁移 fail closed；完全没有前缀触发器时才补挂 `fn_audit()`。
   V185 将之后的 `is_deleted`/`deleted_at` 软删除转换存为 `delete`，扩充行最小化字段且保留 V172 设备关联列。
   触发器保存脱敏 before/after。凭证、刷新令牌、短信码、Flyway、空间扩展、序号、
   物化视图刷新状态和迁移运行元数据表
   不复制行内容，只保留请求或显式安全事件。

触发器只能记录迁移生效后的变化：V169 之前的历史操作，以及任何表在触发器真正生效前若已发生的操作，
都不能根据当前行反向伪造操作人、时间和原值。当前最终迁移链在 V183 创建新表的同一迁移内先挂触发器，
V184 随后复扫，V185 再加固语义与脱敏；这仍须在目标 PostgreSQL 验证，不能据源码推定已部署。静态迁移测试会扫描后续 `CREATE TABLE`，
新业务表若出现在最新 sweep 之后必须补后续 sweep；技术表只能带书面理由进入白名单。部署验收仍必须在
目标 PostgreSQL 查询 `pg_trigger`，静态测试不能替代运行态证据。

`DeviceAuditInterceptor` 为员工、访客及各自刷新 Dio 注入版本化设备上下文；服务端在 JWT 前的
`AuditRequestContextFilter` 生成权威 Request ID、清洗设备字段并回显关联头。客户端会把编码后设备上下文
控制在 4000 字符内；服务端拒绝整体超过 4096 字符、JSON/版本/枚举/时间非法的上下文并标记 `invalid`，
缺字段标记 `partial/missing`，单字段则按白名单清洗或截断。设备声明异常不能阻断业务；极端或漂移超过
允许窗口的客户端时间不会进入 PostgreSQL。

审计存储正常时，凡进入应用 `/api/**` 的上述方法至少有一条可读请求记录；产生数据变化时还有一条或多条
字段级记录，同一 Request ID 可把两层串联。通用请求审计写入失败会告警，但不会改写已经完成的业务响应；
审计详情、本机回执授权和敏感下载等证据读取则在显式审计失败时 fail closed。数据库触发器与业务写入处于
同一事务。TLS、反向代理拒绝、网关 413 等没有进入应用进程的流量由边缘访问日志负责，不能伪造成数据库内
的用户操作。

## 留存与自动删除

- 在线 `audit_log` 默认保留 **6 个月**，可在系统设置调整为 1–120 个月；到期后先进入冷归档。
- 冷归档默认追加保留 **30 个月**，可调整为 0–240 个月；默认总留存为 36 个月。两个截止点都从记录
  原始 `created_at` 计算，不从归档当天重新计时；长期停机后特别旧的记录可能在同次任务先归档、随后达到永久删除条件。
- 自动任务默认每天北京时间 **03:17** 运行，同一事务内确认归档成功后才删除在线记录；达到总期限后
  才永久删除冷归档。页面和业务 API 都没有编辑、单条删除或批量删除入口。
- 期限只能由有系统设置管理能力的超级管理员修改，并要求二次密码确认和记录设置变更审计。缩短期限前
  必须确认法规、合同、调查冻结与备份要求。当前没有逐条“法律保留/调查冻结”功能；需要冻结时必须走
  审批后的独立备份或后续专门能力，不能只依赖页面提示。
- 本机回执跟随在线期与追加归档期之和自动清理，同时最多 300 条；本机无手工清除入口，但卸载应用或
  操作系统清理应用数据仍可能使其消失。

完整批处理、锁和应急流程见[审计与日志保留策略](../数据迁移/38-运维-审计与日志保留.md)。

## 接口

- `GET /api/admin/audit-logs`：分页列表；保留 action、actorAccount、riskLevel、eventCategory、outcome、
  dateFrom、dateTo，并支持 `keyword`、`targetType`、`targetId`、`eventSource`、`requestId`、
  `operationKind`、`actorScope`、`snapshotId`；`page` 默认 1，`size` 默认 20，服务端会归一到 1–100。响应顶层为
  `items/page/size/total/totalPages/snapshotId`。
- `GET /api/admin/audit-logs/summary`：总量、风险、严重、失败、数据变更与七日趋势；接受 action、
  actorAccount、eventCategory 和全部新增筛选，但不接 riskLevel/outcome，故卡片统计保持在当前基础范围，
  不叠加卡片自身的风险/结果下钻。
- `GET /api/admin/audit-logs/{id}`：概览、字段变化、设备证据、技术上下文完整详情。
- `POST /api/admin/audit-logs/local-receipt-verifications/{clientEventId}`：核查人员在读取原设备本机回执前
  完成服务端授权并记录本次核查；`clientEventId` 必须是规范 UUID，无 `audit_log:view` 或离线时不读取本机数据。
- `POST /api/admin/audit-logs/export`：按列表全部业务筛选与同一 `snapshotId` 导出密码加密 Excel；需
  `audit_log:view` + `audit_log:export`，请求体密码长度 6–128。
- `GET /api/settings/public`：登录后返回会话阈值及审计在线期+追加归档期的总月数，供本机回执自动清理；
  不返回任何审计内容，也不赋予查看权限。

列表不返回 before/after 和 User-Agent，只在按 ID 打开详情时读取，降低普通浏览时的数据暴露和传输量。
`targetId`、`eventSource` 为忽略大小写的精确匹配；四个页面快捷 `targetType` 会额外匹配其 request 路由组，
其它 `targetType` 仍为忽略大小写的精确匹配；`requestId` 必须是规范 UUID；
`snapshotId=0` 合法、负数返回 400。`actorScope=user` 表示 actor ID 非空或账号非空白，`system` 表示两者
都为空；`operationKind` 支持 create/update/delete/write/read，非法枚举返回 400。create 对应
insert/http_post；update 对应 update/http_put/http_patch，但排除 V185 前可识别的软删除 UPDATE；delete 对应
delete/http_delete，并纳入 before/after 显示 `is_deleted false→true` 或 `deleted_at null→非空` 的历史 UPDATE；
write 是增删改并集，read 对应 http_get 与 `view_%` 显式查看事件。

## 验收重点

- 点击每张统计卡片后，列表条件和选中态同步；
- 登录失败、刷新失败、CORS 非法来源 403、无权限访问、普通 GET、写操作、删除、导出均能找到记录；
- 同一次写请求的请求记录与数据变更记录拥有相同 request ID；
- 默认“用户操作 + 写操作”能直接看到货品/分类等真实增删改；切到“全部/系统操作”后迁移记录仍完整存在；
- 翻页、统计和导出复用同一高水位，普通后续高 ID 审计不会推移当前 offset；刷新或改变筛选后取得新边界；
- 首次高水位取得前导出按钮不可用；绕过 UI 直接调用导出且未传边界时，服务端仍自行固定高水位；
- 按对象类型/ID、来源、完整 Request ID、关键字和操作类型的正向/非法参数用例均通过；
- 货品/分类等对象快捷筛选同时返回 database 变化和失败/回滚 request 尝试；历史软删除显示为删除且归入高风险；
- 迁移静态护栏能拒绝最新 sweep 之后未列白名单的新表；目标 PostgreSQL 的公开业务表均有有效
  `trg_audit%`，并验证启用状态、AFTER ROW、I/U/D 事件和函数；V184/V185 不补造任何迁移前历史；
- 详情四个子页在桌面和窄屏可滚动、可关闭，无布局溢出；
- 新版员工/访客请求、刷新请求、401 重放与安全 GET 重试均带同一逻辑操作 ID；本机尝试链可按每个 Request ID 分别匹配；
- 同机回执完整性通过/失败、其他设备、缺失、旧记录、设备上下文无效等状态不混淆；
- 设备详情和导出不包含 IMEI、MAC、硬件序列号、原始设备 Header、query、请求体或令牌；
- V185 后新写 before/after 不含迁移列明的凭证、PII、原因备注类敏感文本和大型嵌套快照字段；对 V185 前历史行执行专项扫描并按批准流程处置，不把“未回写”误报为已清除；
- 导出参数与当前筛选完全一致，超行数会拒绝；Excel 必须输入设置的文件密码才能打开；
- 导出文件不含 before/after 与 User-Agent，导出成功和 429/失败尝试均可在审计中心找到；
- 非超管且未获 `audit_log:view` 的普通员工、访客和管理员无法调用审计查询接口，也看不到本机回执入口；
- 除超管固有全权限外，`audit_log:view` / `audit_log:export` 只能个人点名授权；部门权限保存与数据库直接写入均拒绝这两个权限；
- 只有查看权限时可核查但不能导出；导出还需 `audit_log:export`；审计与本机回执均无编辑/手工删除入口；
- 每次本机回执核查先通过服务器授权，并能按核查人、时间、目标操作 ID 回溯。
