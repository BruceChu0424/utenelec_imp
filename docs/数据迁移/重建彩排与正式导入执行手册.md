## 4. 用业务证据判断历史、进行中、未开始和无效

每张单及每行都要能从判定清单定位源ID、单号、日期、原标志、原数量、最新活动和理由。以源业务截止日为时间锚，不能用脚本执行日期让同批输入产生漂移。

优先顺序：

1. 原已明确关闭/停止/取消的，按各自真实含义归历史；旧Cancel字段若loader没实体化，补正确停止标志，不编造审核。
2. 逐行已完成且不存在另一SKU正剩余的，归完成历史。销售必须逐行计算，不能整单总量互抵；生产分清完工与入库，近期已完工未入库仍是进行中。
   旧生产尤其不能套现代同名字段：源FQTY可在审核时被重置，IQTY才是源视图所称完工/进仓，实际排产显示QTY-LQTY。先读真实O_InItem.PlanID更新链和逐行已审入库，再判历史；不能单因FQTY不足就认定仍在生产，也不能把LQTY直接建立成现代库存预留。
3. 超过365天没有有效活动的旧单，按本轮用户授权默认完成历史；单据超过180天且超过90天没有有效活动的，也关闭剩余并归历史。近期真实下游证据优先于单据年龄。
4. 下游活动只认真实FK，并核货品、颜色、已知单位和正倍率一致。无FK、反审、同名同日或同SKU猜绑均不能刷新活跃期。
5. 近期仍有正逐行剩余且有真实部分执行的保留进行中；近期有有效需求但没有执行的保留未开始。进度、日期和原始备注一起判断，不能只看旧Status。
   本批旧状态仅有1/-1，近期部分-1无审核人、无停止取消、无任何执行/财务事实，实际是未审核；新平台-1却是反审历史。此类逐笔确认后单独恢复为0草稿，销售同时清掉导入器合成且无确认人/时间/case的finance_confirmed位。不能恢复老的反审单或有真实执行/财审的单。
6. 空头、无有效行且无真实下游、明显坏数据按理由软删/排除，原始行和身份留档；老的未审核草稿按是否仍有履约依据单独处置，不能补假审批让它“完成”。

**关闭剩余不等于补足收发。** 本轮优先更新头的 `is_closed/fulfill/is_stopped` 等平台合法字段，使历史退出活跃队列；不将 `shipped/received/fqty/iqty` 硬改等于订量，不制造收货、日报、入库、IQC或财务审核。原始source proof保持原事实，之后独立治理事务记录修正前后投影与理由。

旧已审核手工DRAW尤其要核：loader原来全部is_closed=false且issue_status默认0，`fn_production_draw_requested`对无现代mapping的手工DRAW又默认true，导致真实历史出库进入新待办。本批36368个源已审头按实际排除仓后逐身份关闭；不补issued_qty，不改issue_status或实物流。其他23个单据族同样逐源盘点，不能只修四类订单。

没有原始现代执行链的旧单可查询，但不能直接假造预留、执行段或领料额度来继续操作。无FK委外收发不能证明供应商结存为零。真实继续履约需要相应数量和实物交接证据；页面和报告必须说明待接续项。
