> 迁移文件：`server/src/main/resources/db/migration/V551__sales_order_pending_view_excludes_drafts.sql`
> 日期：2026-09-11 ｜ 关联审计：C13 `G5-reports`

## 一、问题

`sales_order_pending_v`（V52 建）是「待交货订货汇总」视图，取代老库 `View_S_OrderItem`，
按货品 + 颜色 + 客户汇总未发数量，是**生产计划与采购驱动的入口查询**。

它的过滤条件只有：

```sql
WHERE i.is_deleted = false AND o.is_deleted = false
```

没有审核状态过滤。于是**草稿订货单（`status = 0`）的未发数量也进了待交货汇总**——销售刚
录入、还没自审提交的单子，会被生产/采购当成真实交货承诺读走并据此排产、下单。

未审核的单据不构成交货承诺。这是口径错误，不是数据问题。

---

## 二、本迁移做什么

在原定义上**只加一条谓词**：

```sql
WHERE i.is_deleted = false AND o.is_deleted = false AND o.status = 1
```

列名、列序、聚合表达式、`GROUP BY`、`HAVING` 全部保持不变，因此 `CREATE OR REPLACE VIEW`
安全（PostgreSQL 要求 REPLACE 时列名/类型/顺序完全一致），依赖本视图的对象不受影响。

同时更新 `COMMENT ON VIEW`，把「仅已审订单 status=1」写进注释。

迁移自包含：不 DROP、不依赖本轮其它迁移。

---

## 三、口径变化（需要向业务说明）

- **「待交货」数字会变小**：减少的部分正是原先混进来的草稿单。这是修正，不是数据丢失——
  草稿单审核通过后（`status` 0 → 1）会立刻重新出现在待交货里。
- `sales_monthly_mv` 等月度物化视图本来就带 `o.status = 1`（V52:30/40），口径不变，
  刷新后数字不动。
- **报表侧同步调整**（同一轮，代码侧非迁移）：`SalesReportService` /
  `PurchaseReportService` / `SubcontractReportService` / `StockReportService` /
  `FinanceReportService` 的公共过滤新增 `addApprovedByDefault`——调用方**未显式传 status**
  时默认加 `status <> 0`（排除草稿）；显式传 status（含 `status=0` 查草稿、或前端「未审」
  facet）时仍按调用方口径走，查草稿的能力保留。

---

## 四、验证

1. 造 1 张草稿订货单 + 1 张已审订货单（同货品同客户）：
   `SELECT * FROM sales_order_pending_v WHERE goods_id = ...` 只含已审单的量。
2. 把草稿单审核为 `status = 1`：再查，pending_qty 增加对应数量。
3. `REFRESH MATERIALIZED VIEW sales_monthly_mv;` 前后数字一致（本迁移不影响 MV）。
4. 销售明细/汇总报表默认不再出现草稿行；勾「未审」facet 才出现。
