# 通知详情页

> 路由：`/notice/:id` · 实现源：`lib/features/notice/pages/notice_detail_page.dart`

## 一、定位

员工阅读公司通知正文的详情页。

- 解决的问题：展示通知标题、发布人、发布时间、正文（可选中复制）、附件、阅读时间。
- 产品位置：从 [通知列表页](通知列表页.md) 打开的只读详情弹窗；独立路由用于深链。

## 二、入口与导航

- 进入路径：
  - [通知列表页](通知列表页.md) → 点击列表项（同时标记已读并打开弹窗）
  - 推送通知深链（Phase 2+）
- 在导航中的位置：业务详情子页。
- 离开去向：关闭弹窗返回原列表位置；独立路由返回上一页。弹窗态返回键关弹窗（`onBack=Navigator.pop`），独立路由态走默认 go_router 返回（详见 §九 边界）。

## 三、响应式布局

列表内打开时：compact 使用 92% 高底部弹层；medium / expanded 使用最大 760×760dp 的居中对话框。详情内容仍复用同一个 `NoticeDetailPage`，避免弹窗与深链展示不一致。

- compact（手机，< 600dp）：
  ```
  ┌────────────────────────┐
  │ ← 通知详情              │
  ├────────────────────────┤
  │ [📢 公告] [工作] [重要]   │  ← 类型徽章 + 工作标识 + 重要度徽章
  │                        │
  │ 国庆放假通知             │  ← 标题（粗体大字）
  │                        │
  │ 👤 人事部  2026-09-20   │  ← 发布人 + 时间
  │                        │
  │ ┌────────────────────┐ │
  │ │ 各位同事：           │ │  ← UtenCard 正文（SelectableText）
  │ │ 国庆假期为 10.1-10.7 │ │
  │ │ ...                  │ │
  │ └────────────────────┘ │
  │                        │
  │ 附件                    │
  │ ┌────────────────────┐ │
  │ │📄 放假安排.pdf  ⬇    │ │  ← 附件项
  │ └────────────────────┘ │
  │                        │
  │ ✓ 已于 2026-09-20 14:30│  ← 阅读时间提示
  │   阅读                  │
  └────────────────────────┘
  ```
  说明：单列滚动，类型徽章 + 标题 + 发布人 + 正文卡 + 附件 + 阅读信息。

- medium（平板，600-840dp）：内容居中约 600dp 宽。

- expanded（桌面，> 840dp）：内容居中最大 720dp，附件可双列。

## 四、涉及的 Uten 组件

- `UtenAppBar`（带返回按钮）
- `UtenCard`（正文卡）
- `UtenStatusBadge`（类型徽章 + 置顶徽章）
- `UtenEmpty`（数据 null / error）
- `UtenColors`（附件图标 teal 色）
- Flutter 原生：`SelectableText`、`CircleAvatar`

## 五、功能点

1. **顶部徽章行**：
   - `UtenStatusBadge` 显示通知类型（12 种 `NoticeType` 对应 badge type + 类型 icon）。
   - 工作类（`type.isWork`：task/approval/workflow）追加 accent 色「工作」徽章。
   - 若 `priority.showBadge`（important/urgent），追加「重要」（warning 橙）/「紧急」（danger 红）徽章。
   - 若 `topPriority`，追加一个 warning 色"置顶"徽章。
2. **标题**：`headlineSmall` 粗体，与正文明显区分。
3. **发布人信息行**：CircleAvatar（类型色背景 + account_circle 图标）+ 发布人名 + 发布时间（"yyyy-MM-dd HH:mm"）。
4. **主角面板**（V454，多主角聚合卡 `notice.isGroupCelebration` 时）：`CelebrationSubjectsPanel`——类型色浅底圆角容器，头部吉祥物（`CelebrationMascot`）+「今日寿星/周年之星/新婚之喜/喜添新丁 · N 位同事」，下方 `CelebrationSubjectChips` 全员徽章（头像字 + 姓名；周年逐人 `eventLabel` 如「张三 入职5周年」）。单人卡不展示（标题已含主角）。
5. **正文卡** `UtenCard` 内 `SelectableText`，`bodyLarge` + 1.7 行高，便于阅读和复制。
6. **附件区**（若 `attachments.isNotEmpty`）：
   - 标题"附件"。
   - 每个附件一个 `Container`：左侧 teal 色文件图标，中部文件名，右侧下载图标。
7. **阅读信息**（若 `readAt != null`）：底部 surfaceContainerLow 容器 + check_circle 图标 + "已于 yyyy-MM-dd HH:mm 阅读"。
8. `AsyncValue.when` 三态：loading 用 `CircularProgressIndicator`、error 用 `UtenEmpty.error`、null 用 `UtenEmpty`"通知不存在"。
9. **互动区**（V224，ADR-025；正文卡下方，`NoticeInteractionSection` 按 `notice.interactionMode` 分派）：
   - **acknowledge 模式**（公告广播类）：醒目「点击收到」`UtenActionButton`（`POST /{id}/acknowledge`，幂等）→「✓ 你已收到 · 共 N 人收到」+ 近期收到人 chips（`recentAckers`）；已收到则显示确认态。
   - **bless 模式**（庆典类）：`_BlessSection` 祝福墙 + composer——
     - 标题行「祝福墙」+「N 条祝福」计数。
     - 模板 chips：取 `notice.blessingTemplates`（发布者勾选；空则系统默认 `kDefaultBlessingTemplates`），点按把模板填入输入框（单人卡 `{name}` 替换为 `subjectName`；聚合卡服务端模板面向「各位」不含占位符，兜底解析去 `{name}，` 前缀）。
     - 多行输入（≤200）+「发送祝福」`UtenActionButton`（`POST /{id}/blessing`，upsert）。
     - 近期祝福列表（`recentBlessings`，本人那条高亮）+「查看全部 N 条」→ 祝福墙弹层（`noticeBlessingsProvider` 分页）。
   - none 模式（工作类）：无互动区。

## 七、涉及的数据实体

→ 见 [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `Notice`：详情主实体（title / content / type / publisher / publishedAt / topPriority / attachments / readAt）
- `NoticeType`：5 种枚举
- `NoticeReadRecord`：阅读时间 readAt 来自该实体的首次阅读记录
- `Attachment`：通知 Phase 1 仍仅用文件名表示；通用 Attachment 已有源码候选，但通知域 owner policy/UI 和生产附件门禁尚未接入

## 八、权限要求

- **全员可见**。
- 数据范围：员工只能看到发布范围包含自己的通知（按部门/工种/全员）；后端必须校验。
- 关键操作权限点：本页只读 + 触发本人 markRead。

## 九、边界情况

- 无数据时：`notice == null` → `UtenEmpty`"通知不存在"。
- 加载失败时：`UtenEmpty.error` + 重试（`ref.invalidate(noticeDetailProvider(noticeId))`）。
- 性能档 = lite 下：正文区去掉卡阴影，附件图标用纯色矩形代替圆角图标容器。
- 网络断开时（已接真后端 `GET /api/notices/{id}`，2026-07-29）：
  - 当前没有通知正文离线缓存；断网时进入错误态并提供重试。重要公告离线阅读是待实现目标。
  - 附件下载必须在线，断网时点击 Toast 提示"请检查网络后重试"；后台下载队列尚未实现。
  - 长正文应做分页或折叠展开（避免一屏渲染过万字符）。
  - 已被本人删除的通知详情返回 404（`notice_user_states.deleted_at` 非空即视为不存在）。
- **弹窗内嵌返回键**：本页被 `showNoticeDetailDialog`（`showDialog` / `showModalBottomSheet`）包裹时，返回键必须传 `onBack: () => Navigator.of(ctx).pop()`。默认 `UtenBackButton` 走 go_router `context.pop/go`，够不着 Dialog/Sheet 路由（不在 go_router 栈内），表现为「点返回无反应」。`NoticeDetailPage` 用 `onBack` 参数区分：弹窗传 `Navigator.pop`，独立路由 `/notice/:id` 传 null 走默认。同类坑见 memory：go-router-nested-navigator-dialog-pop。
- **弹窗内嵌「查看详情」按钮**：与返回键同类坑——`actionRoute` 跳转若用 `context.go`，同样够不着包裹本页的 Dialog/Sheet 浮层，表现为「点查看详情没反应」（底层页面其实已跳，弹窗仍盖着）。修复：`_Content` 透传 `onBack`，按钮点击时若 `onBack != null`（弹窗态）先 `onBack()` 关弹窗，再用全局 `appRouterProvider`（弹窗内 `GoRouterState.of` 取不到，故用全局 provider 而非 `context`）跳转；独立路由态直接跳。`returnTo` 统一回 `/notice`，目标页返回键回通知列表。后端 `ChainNoticeService` 现已为全部业务通知填充 `actionRoute`（排产/报工/完工/发货/驳回/取消/新订单待排产/财务审核/到货异常/交货预警/预留逾期/库存让单/待料齐套等），仅纯广播（公告/制度/福利）无按钮。
- **通知正文内容约束**：正文必须是对人友好的中文（如「您提交的 1 项个人信息修改（姓名）已批准并生效」），**不得出现字段名 / i18n key / 机器码**（如 `profileChangeFieldFullName`、`emergencyContact.1.phone`）——会暴露系统字段结构。由生成方负责：个人信息审批通知由后端 `ProfileChangeReviewService` 按 `fieldCode`→中文映射拼装，不信任历史可能脏的 `field_label`；前端 `field_policy.dart` 的 `labelOf()` 提交时即解析为中文。
