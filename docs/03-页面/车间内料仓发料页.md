# 车间内料仓发料页 (仓库)

> 2026-10-04 出库仓库只算一次([ADR-147](../99-决策记录-ADR/ADR-147-车间内料仓开通单一真源与发料来源仓.md), [V802](../数据迁移/V802-车间内料仓开通单一真源.md))：每行「出库仓库」的默认值统一由服务端 `fn_workshop_bin_default_source` 给出——这个车间内料仓的发料来源仓有可发量就用它, 否则用货品所属仓库, 再否则用可发量最大的良品子仓 (都不选不良品仓和内料仓; 都没有时留空要人选); 内料仓页、申请候选、申请行建议仓与本页同一口径。「出库仓库」列点开全站仓库滑窗 (先点主仓再点子仓), 每个仓下面显示「可发 N 单位」; 收退回时「退到哪个仓库」同样用滑窗, 只能选启用中的良品子仓。发料来源仓在[车间内料仓页](车间内料仓页.md)的车间总览里设置。

> 2026-09-28 新增, 设计依据 [ADR-131 车间整批领料与盘点计耗](../99-决策记录-ADR/ADR-131-车间整批领料与盘点计耗.md) §5.2、§5.3。

仓库把颗粒这类"整批领料"的料整袋发到车间内料仓 (原名线边仓), 车间也可以先申请, 用不完的料可以退回。发料在系统里是一张调拨 (仓库叶仓到车间内料仓), 只换位置、不算耗用; 用了多少由车间盘点算出来。

## 入口

- [仓库任务中心](仓库任务中心页.md) 大类「车间内料仓」按权限显示待发料、待收退回、盘点审核、周期盘点、记录；有发料权限时显示「直接发料」。新库存盘点申请在「盘点审核」中直接打开审核明细，旧期间计耗在「周期盘点」办理，不混用两种单据。
- 通知"车间要领料""车间要退料", 点开落到仓库任务中心的「车间内料仓」大类。

## 三种办理方式

### 直接发料 (主路径, 车间来人就发)

1. 选发到哪个车间 (只列已开启整批领料的车间)。
2. 选领料人: 车间员工选择器, 默认这个车间上一次的领料人。
3. 逐行填料、袋数 (公斤按每袋净重自动算, 可改)、出库仓库 (默认值见页首: 来源仓有货 -> 货品所属仓库 -> 可发量最大的良品子仓)。同一种料要从两个仓出, 点"从另一个仓库再发一部分"拆成两行; 同一种料同一个仓只能一行。
4. 点「确认发料」: 同一笔里建一张"已完成"的领料单, 按出库仓逐张建并审核调拨单, 料记进车间内料仓。库存不足或别人刚改过时整笔不发, 填写的内容保留。

发完提示单号、调拨单号和"记进第 N 期 (起止日)"。车间内料仓正在盘点时, 发的料自动算到下一期, 页面提示"已开始盘点, 这批料算到下一期"。

### 按申请发 (车间先申请)

「待发料」列出车间提交的领料申请 (单号、车间、料、申请人、申请时间)。打开一张, 默认数量就是申请量, 可按整袋改; 出库仓默认值同直接发料 (申请时已算好的建议仓)。确认后同直接发料。申请只通知这批料所在仓的仓管 (没有仓管时通知全部有发料权限的人)。不发的申请可以取消, 要写原因。

2026-09-30：车间可直接申请使用中的重量原料，无需提前修改发料方式。尚未确认用途的原料在仓库办理页显示首次用途卡，可选主料／辅料／车间费用，预览全部受影响 BOM 与旧需求，确认后随实际发料同一事务提交。仅现有货品编辑与 BOM 编辑权限持有人能确认首次用途；申请和发料权限不会因此升级。没有权限或有冲突时保留申请和输入，不扣库存、不留半次配置；已配置材料仍直接办理。

### 收退回

「待收退回」列出车间提交的退回申请。打开后按实收填公斤数, 选退到哪个仓库 (同一种料可以分到两个仓收); 确认后生成调拨单 (车间内料仓到所选仓库), 记进车间内料仓开着的那一期。不能退到已经截止的上一期。

## 漏录补录

盘点开始前实际已经发了、当时忘了录的料, 直接发料时勾选"这批料是上一期漏录的":

- 出现"补到哪一期"下拉, 只列"盘点中"或"已盘点、还没结算"的那一期; 必须写漏录原因 (至少 2 个字)。
- 补到盘点中的那一期: 随盘点提交一起算。
- 补到已盘点的那一期: 系统在同一笔里自动更正那一期 (领入加上补录量, 期末实盘不变, 实际用量随之增加), 然后立即尝试结算。
- 那一期的盘点里没盘到这种料的, 系统提示"这种料在这一期的盘点里没有盘到, 请先更正盘点补上实盘数", 先更正盘点再补录。
- 已经结算的期间不能补录; 没有可补的期间时提示"不用补录"。

## 规则与提示

- 直接发料仍选已配置的期间材料；按申请发料读取该申请的精确材料与颜色，可在同页处理首次用途。数量一律按所选物料基本单位显示，克、公斤等不混算。申请后单位变化必须重新核对，不能沿用原数值。
- 发料的调出一侧只扣已被别的单子预留的量, 不受货品安全库存限制; 其它普通出库照旧。
- 系统建的这些调拨单不能红冲; 发错了请车间走退回。
- 通用的"仓库调拨 / 其它出库 / 其它入库"页面照旧选不到车间内料仓。
- 水口料不进车间内料仓: 交回仓库走"其它入库", 回收料金额预填 0 (提示"水口料按 0 成本进仓")。

## 给开发看的对照

- 路由 `/workshop-material/issue` (`?mode=direct` 直接发料, `?requisitionId=` 按申请发或收退回), 页面 [workshop_material_issue_page.dart](../../lib/features/warehouse/materialbin/pages/workshop_material_issue_page.dart); 任务中心嵌入 `workshop_material_task_center.dart`。
- 路由守卫 `workshop_material:issue`; 取消申请 `workshop_material:request` 或 `workshop_material:issue`。按钮只看 `allowedActions`。
- 接口: `POST /api/workshop-material/direct-issues`、`GET /api/workshop-material/direct-issues/defaults`、`GET /api/workshop-material/materials` (料与默认出库仓 `defaultLeafWarehouseId`)、`GET /api/workshop-material/settings/source-warehouses` (仓库滑窗的全站仓库树, 发料权限可读)、`GET /api/workshop-material/requisitions`、`GET /api/workshop-material/requisitions/{id}`、`POST /api/workshop-material/requisitions/{id}/fulfil`、`POST /api/workshop-material/requisitions/{id}/cancel`。建单只经 `WorkshopMaterialStockGateway` 到 `StockDocService.createAndApproveWorkshopMaterialDocument`, 单号领料 ZL、退回 ZT。
- 任务中心大类红数合并 `warehouseWorkshopMaterial`（待发＋待收退回）与 `warehouseStockCountReview`（库存盘点待审）两个独立入口，各计一次；黄数仍只来自实际处于 `COUNTING` 的周期。顶部「盘点审核」定位同一子分类，快捷入口和审核子分类共用同一个待审数，0 隐藏。审核列表与其待审数使用相同服务端仓库范围(ADR-149：本人默认范围，主管或多仓负责人选了仓时取带 `scopeWarehouseId` 的汇总，指定主仓包含子仓)，不把页内徽章再次累计进模块。请领/退料任务的所在仓 = 各行预填叶仓；车间成员按本车间看自己的单，不叠加仓库范围。
- 测试: `test/features/warehouse/workshop_material_issue_page_test.dart`; 服务端 `WorkshopMaterialIssuePostgresTest`、`WorkshopMaterialStockAuthorizationPostgresTest`。
