## 数据与闸门

- 报价、订货新增独立负责人阶段、批准/驳回人员和时间、原因、备注及决定认领 ID。状态为 `NOT_REQUIRED / PENDING / APPROVED / REJECTED`。
- 报价修订日志增加 `MANAGER_EDIT / MANAGER_CONFIRM / MANAGER_REJECT / MANAGER_REVERSE`；原日志不改写。负责人直接定价记录独立 `MANAGER` 来源及人员/时间。
- 订货新增不可变负责人审核事件，保存决定、版本、操作人、备注/原因、认领 ID 和原商业快照。
- 事件表按 ADR-105 的 `NONE/ledger` 分类，不重复写通用行审计；legacy 首次导入要求该表 `EMPTY`。反审核的客户端 `decisionId` 是事件主键，重复身份整笔回滚，不能覆盖旧决定。
- 数据库触发器阻止尚未负责人通过的单据被写成财务通过。新提交、完整修订和合法改量由服务端重置负责人阶段；不能靠旧客户端跳过。
- 既有 `status`、财务确认字段、库存预留、履约与资金事实继续保持原职责，不能仅凭订货 `status=1` 或负责人通过推定财务已放行。

## 存量处理

| 升级前记录 | V978 处理 |
|---|---|
| 未删除、未关闭、非迁入历史的待核价报价 | 转负责人待审核 |
| 已销售提交，尚未财务通过、未被财务驳回、未中止、未转重新报价且符合原有效队列条件的非迁入订货 | 转负责人待审核 |
| 已被财务驳回的订货 | 保持销售修订流程；修改重提后才进入新链路 |
| 历史已通过、已办结或迁入只读记录 | 保留原事实，不补造负责人批准人、时间或审批记录 |
| 本次移交的旧财务认领 | 更新释放时间与原因，保留认领记录，不删除历史 |
| 本次移交的旧财务待办通知 | 标记已办结，保留通知及审计；新负责人按实际授权接收或补齐提醒 |

`NOT_REQUIRED` 用于历史兼容。不得用统一改成该值的方式绕过新单审核或处理上线问题。

## 权限与通知

新增 `sales_quote_manager`、`sales_order_manager` 各四项权限：`view / confirm / reject / reverse`，以及 `sales.manager-review` 页面权限面。权限分类沿用平台既有动作分类；新权限遵守 V936 的显式授权规则，不复制到普通销售、财务、旧模板或部门默认包。

首位负责人按用户要求为朱舜炜。执行[只读授权核对](../../server/maintenance/sales_manager_review_authorization_preflight.sql)后，通过已有管理端对唯一启用账号加授“综合营销部 / 订单审核”组；对应请求为 `PUT /api/admin/users/{id}/permission-overrides/grant-all`，请求体 `{"module":"综合营销部","category":"订单审核"}`。仍使用既有超级管理员会话、一次性再认证、账号生命周期锁及授权审计，不直接写权限表。

通知注册 `SALES_QUOTE_PENDING_MANAGER_REVIEW`、`SALES_ORDER_PENDING_MANAGER_REVIEW`，对接居中弹窗、认领心跳、办结撤回、页面已读及个人偏好。补发只给当前实际获授权的审核人，采用有界查询和原单锁，避免重复创建。负责人驳回的修订提醒保留销售对象范围校验。
