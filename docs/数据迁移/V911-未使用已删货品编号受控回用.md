# V911 - 未使用已删货品编号受控回用

该未发布候选从 V909 顺延至 V911，避免与并行 V908 迁移冲突；SQL 内容及其内部候选检查标签保持原样。

`goods.id` 是关联货品的 UUID，`goods.code` 是显示编号。新建或复制到目标分类时继续使用目标分类的有效前缀，显示短序号与全局身份计数分别管理。原货品 UUID 和历史记录完整保留，回用编号产生新的货品 UUID。

只允许有完整生命周期证明、已经软删、从未被业务使用的真实货品回用当前编号。迁移后正常新建货品开始登记生命周期，旧库导入、自动占位货品不登记。所有实际业务 UUID 外键及按规范命名的 UUID/UUID 数组列记录不可删除的首次使用证据，软删、撤回、草稿硬删和清空业务都不会清掉该证据。BOM 父件、组件及学习记录也计算使用。

纯 JSON 的货品身份按明确的业务快照列登记：成本单输入及计算、成本快照、生产物料需求的消耗快照、排产草稿、报价修订快照、BOM 学习材料及代际快照。审计、资料编辑历史、通知、通用发件箱和界面配置不因包含 UUID 而算业务使用。新业务 JSON 身份列必须扩展此目录并通过覆盖测试，不能用当前数量为零作为从未使用的证明。

旧系统曾清空审计并允许按保留期清理，迁移前没有完整生命周期的货品一律按历史不明保留原占号。不会仅凭当前没有订单、库存或 BOM 引用就释放旧号，因此不保证旧截图中的已删号码可以回用。

释放写入 `goods_code_reuse_releases` 不可变账本，原货品和主档、全局两套占号成员均不删除或改写。分配在创建事务中锁定旧货品与两层占号，重新核对唯一归属及使用证据，然后登记释放；新货品正常加入两套占号成员。延迟约束要求事务最终确有新货品及完整双重归属，失败全部回滚。其它业务域、多归属、曾使用、旧历史编号或缺少证明一律保留。预览只读，不推进身份计数或释放号码。

释放后的旧 UUID 永久不能恢复为有效货品，也不能新建业务引用。删除撤回、资料历史恢复及导入恢复都显示明确冲突，数据库触发器独立拒绝旁路。第三代再次回用仍各自保留 UUID，之前两代不能恢复。

货品 Excel 导出保留只读“系统标识”列；这是 UUID，不是可编辑编号。用户修改客户型号等字段再导入时保留此列。曾回用过的编号禁止只按显示编号或名称自动匹配，必须携带匹配的系统标识，防止旧文件给新货品补错字段。基础资料 BOM 导出同时保留“组件系统标识”，导入时与当前编号对应的组件 UUID 逐行核对；旧格式无此列时，只允许从未回用的编号按原规则匹配。本轮未修改销售客户文件识别或其它模块流程。

三个证明与释放表使用 FULL 审计、不可改写守卫和业务清空 PRESERVE。V276/V279 历史 SQL 不改写，没有新增权限码，原对象范围、创建、编辑、售价和状态权限保持原有合同。

验证使用独立 Testcontainers PostgreSQL 与完整前向迁移；覆盖新建、删除、回用、第三代回用、事务回滚、使用证据保留、旧身份恢复拒绝、跨域占号和两向并发引用。测试报告及源码候选不表示公司服务器已应用 V911、发布或完成用户验收。
