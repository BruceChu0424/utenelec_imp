# ADR-036：全局业务标识与单据号命名空间

- 状态：已接受；V279 为共享工作树源码候选，目标库迁移、对账和 UAT 待验收
- 日期：2026-08-14
- 范围：业务单据号、系统号、业务主档/计划行编号、分类显式前缀、旧库迁移与审计
- 局部取代：[ADR-034](ADR-034-分类驱动业务编号与UUID关联.md) 中“主档编号允许跨域重复”以及“单号排除在统一业务标识保留之外”的条款；ADR-034 的 UUID 关联、快照、分类最近前缀和批量改号边界继续有效。

## 一、决策摘要

1. 所有关联、外键、授权、幂等和反写只认系统 UUID；任何可见编号都不是关联键。
2. V279 建立一套全系统命名空间、前缀 token 保留、完整标识保留、历史成员和冲突证据表。前缀和完整标识均按 `upper(btrim(value))` 归一后终身占用，软删、硬删、停用或改号都不释放。
3. 新业务单号格式统一为 `PREFIXYYYYMMDDNNNNNN`，例如采购订单 `CD20260814000001`。日期取 PostgreSQL 的上海业务日，6 位日流水在“不可变命名空间 + 业务日”下原子递增。事务回滚、冲突跳号和运维作废均可产生断号；唯一和可追溯优先于“无缝连号”。
4. 号码不嵌入制单人工号、姓名或秒级时间。制单人可离职、转岗、改工号，且存在定时任务和系统制单；其身份以 `created_by/maker_id -> employees.id` 和审计记录单独保存。如以后引入多公司/多厂区，只能增加另一个稳定、不可复用的组织命名空间，不用人员属性代替。
5. Flutter 不复制 Java/数据库前缀表，也不预取“准确的下一个号”。新建页只显示“保存后由系统生成”，保存成功后展示服务端返回的权威号码。
6. 生产执行分段使用独立系统命名空间 `PRODUCTION_EXECUTION_SEGMENT=ZX`，格式为 `ZX` 加 8 位永久流水；`production_plan_items.product_no` 保留用户业务语义，但按 `plan_id` 作为稳定逻辑所有者进入全局终身占号。用户显式填写的非空编号去除首尾空白后保留；留空时服务端在计划头取得权威 `bill_no` 后生成 `<计划单号>-NNN`（三位起、最多六位），例如 `SJ20260814000001-001`。草稿删除并重建行时，同一计划可恢复原 `product_no`，不同计划不得复用。

## 二、五类字段边界

| 类型 | 例子 | 用途 | 不允许的用法 |
|---|---|---|---|
| 关系身份 | `id`、`goods_id`、`source_order_id`、`maker_id` | UUID 外键、授权、幂等、关联与反写 | 不用编号、姓名、旧整数或前缀反查生成关系 |
| 主档/业务行编号 | `goods.code`、`clients.code`、`production_plan_items.product_no` | 人员识别、搜索、打印；主档可受分类前缀批量改号 | 不做外键；旧号改掉后仍终身保留，不得给其他逻辑所有者复用 |
| 单据/系统号 | `bill_no`、`task_no`、`visitor_no`、`segment_code` | 不可变的展示、搜索、打印、条码和对外沟通标签 | 在线新建不接受客户端自传；不用号码 JOIN 来源 |
| 前缀政策 token | `code_prefix`、固定 `XD/XS/CD/V` | 决定新号的业务语义；全系统精确 token 互斥 | `V` 与 `v` 冲突；`V` 与 `V6` 可并存；不按包含或起始字符误判冲突 |
| 快照、legacy 与备注 | `goods_code_snapshot`、`source_doc_no`、`legacy_id`、`legacy_code_snapshot`、`remark` | 还原审核时事实、迁移对账、人工说明 | 快照不随今日主档改号；legacy/备注不参与运行时关联或取号 |

## 三、命名空间与前缀

V279 登记 37 个文档命名空间，每个固定前缀不重复；另登记 2 个系统命名空间：访客账号 `VISITOR_ACCOUNT=V` 与生产执行分段 `PRODUCTION_EXECUTION_SEGMENT=ZX`。

| 业务族 | 命名空间 = 前缀 |
|---|---|
| 销售 | `SALES_ORDER=XD`、`SALES_SHIPMENT=XC`、`SALES_OTHER_SHIPMENT=OC`、`SALES_RETURN=XT`、`SALES_QUOTE=XB` |
| 采购 | `PURCHASE_REQUEST=CS`、`PURCHASE_ORDER=CD`、`PURCHASE_RECEIPT=CJ`、`PURCHASE_RETURN=CT` |
| 仓库 | `STOCK_TRANSFER=CB`、`STOCK_OTHER_IN=QR`、`STOCK_OTHER_OUT=QC`、`STOCK_DRAW=SL`、`STOCK_WDRAW=ST`、`STOCK_FINISHED_OUT=CC`、`STOCK_FINISHED_IN=CR`、`STOCK_CHECK=PQ`、`STOCK_WASTE=QW` |
| 委外 | `SUB_INQUIRY=EA`、`SUB_APPLICATION=EB`、`SUB_ORDER=EO`、`SUB_MATERIAL_ISSUE=EC`、`SUB_RECEIPT=EJ`、`SUB_RETURN=ET`、`SUB_MATERIAL_RETURN=ER`、`SUB_WASTE=EW` |
| 财务/资产 | `FIN_RECEIPT=XS`、`FIN_PAYMENT=CF`、`FIN_EXPENSE=YF`、`FIN_OTHER_INCOME=QS`、`FIN_BANK_TRANSFER=YC`、`FIXED_ASSET=FA`、`DEFERRED_EXPENSE=DA` |
| 生产/研发 | `PRODUCTION_PLAN=SJ`、`PRODUCTION_SUBPLAN=SZ`、`PRODUCTION_DAILY_REPORT=SR`、`RD_TASK=RD` |
| 系统号 | `VISITOR_ACCOUNT=V`（8 位流水）、`PRODUCTION_EXECUTION_SEGMENT=ZX`（8 位流水） |

销售订单继续使用 `XD`；`XS` 已终身属于财务收款，不能因为“销售”的拼音缩写再分配给销售订单。新业务类型必须先在同一注册表申领未占用 token，再接入取号服务；禁止在 Java、Flutter、SQL 触发器或迁移脚本中各自新建一份孤立前缀表。

固定主档默认前缀与四类分类显式 `code_prefix` 也进入同一 `business_prefix_reservations`。子分类的显式前缀优先，空值继承最近祖先，再回退到该主档域默认前缀。保存分类时服务端在事务中申领 token；409 冲突时 Flutter 保留用户当前输入，由用户改用其他代号。

## 四、数据库权威与并发

- `business_identifier_namespaces`：不可变的命名空间、家族、固定前缀和权威列映射。
- `business_document_sequences`：以 `(namespace_key, sequence_date)` 原子 UPSERT 递增；上限 999999/命名空间/业务日。
- `production_product_no_sequences`：以 `plan_id` 为稳定所有者原子递增计划行后缀；迁移只从符合 `<计划单号>-数字后缀` 的历史编号推进基线，自定义历史编号仍只进入全局保留。编号冲突、事务回滚和显式占号可以跳号。
- `master_code_sequences`：固定主档和系统号按前缀原子递增；位宽是硬上限，访客号和生产执行分段均为 8 位，耗尽时失败关闭，不扩成第 9 位。
- `business_prefix_reservations` / `business_prefix_reservation_members`：固定、分类与历史前缀的全局终身占用及所有者证据。
- `business_identifier_reservations` / `business_identifier_reservation_members`：文档号与主档编号的全局终身占用及当前/历史成员。
- `business_identifier_conflicts`：只追加保存历史完整编号重复、前缀重复和无法安全解析的旧格式；不静默改写证据。

取号与业务头写入在同一事务中完成，最终由数据库触发器保留完整标识。计划行自动编号由 `fn_allocate_production_product_no(plan_id)` 同时推进计数并申领全局保留；Flutter、销售订单导入、物料分析、报工补产和 MRP 自制子计划都不得用销售单号、行号、随机 UUID 或本地字符串拼接自行铸号。同一销售订单行分批进入不同计划时，因为计划 UUID 与权威计划单号不同，会得到不同产品编号。应用程序先检查不能取代唯一约束/数据库守卫。对同一业务日的并发创建只保证唯一和递增，不保证提交顺序与号码顺序完全一致。

## 五、旧库与已有数据迁移

1. **原号原样保留**：不把历史 `bill_no/task_no/visitor_no/code` 批量改成新格式，不伪造历史日期、人员或顺序。新格式只用于 V279 与新应用候选生效后的新建。
2. **先登记、后禁新**：迁移扫描所有权威单据头、访客/生产执行分段系统号、生产计划行 `product_no`、V276 主档编号成员、软删分类前缀，再开启新写守卫。明细拷贝、AR/AP/GL 投影和外部客户订单号不冒充权威编号。
3. **历史冲突不改码**：归一后的重复值保留多个历史成员并写冲突证据；只禁止新身份继续占用。无法识别前缀或不符新格式的旧号记录为格式异常，仍可读可查。
4. **重导依旧可追溯**：受控 legacy import 必须在事务内显式设置 `app.business_identifier_legacy_import=on` 或非空 `uten.legacy_reference_import`，并携带源表、源主键/`legacy_id`、旧号、导入批次和输入哈希。`legacy_id` 非空本身绝不启用放行；只有同一 legacy 身份才能重放为同一成员，不允许用“号码一样”把两个实体合并。
5. **先预演后执行**：在可恢复的生产副本先输出前缀冲突、完整标识冲突、格式异常、分类改号影响量和日序列基线。业务负责人签收报告后才可进入目标库窗口。

## 六、部署、回滚与验收门禁

### 上线前

- 以目标库 `flyway_schema_history` 和已审批源码字节做 `validate`；已应用迁移不修改、不 `repair` 绕过 checksum。
- 先完成库与附件一致备份、PITR 可用性检查和真实恢复演练，再在可丢弃副本执行 V279。
- 核对 37 个文档命名空间和 2 个系统命名空间，确认固定前缀归一后无重复；冲突/异常计数、样本和处置人必须入发布证据包。
- 对销售、采购、仓库、委外、财务、资产、生产、研发、访客、执行分段、计划行 `product_no` 和四类分类前缀做并发、跨日、时区、位宽耗尽、409 保留输入、草稿重建、复制/粘贴/Excel/旧库重导测试。
- 前端确认所有新建页的号码字段只读，没有 peek API，没有 Flutter 前缀镜像表。

### 回滚边界

- **尚未开放新写**：可停止候选应用，还原窗口前备份或切回未改变的旧库副本，然后重做对账。
- **已发出任何新格式号码**：不得用不识别 V279 注册表的旧 JAR 直接回退继续写。保留新号和保留成员，使用更高版本前向修复；必要时只读服务。
- 任何回滚都不释放已发号码/前缀，也不把冲突证据删掉或改写为“无冲突”。

### 当前证据边界

截至 2026-08-14 本次文档冻结，共享工作树迁移目录最高为 V289，共 270 个迁移文件、270 个唯一版本且无重复。V279 才是本 ADR 的全局编号注册迁移；V280/V281 分别处理员工删除/附件授权与附件分类/头像元数据，V282 才是员工 7 项扩展 PII 的局部加密候选，V283 修正生产关联采购/委外订单在财务审批时的一次性货品快照锁定守卫，V284 保护个人信息变更敏感快照及其历史审计副本，V285 收紧客户默认结算方式 UUID，V286 允许 bootstrap/legacy 员工保存无证件号/主手机号的扩展-only 敏感行，V287 禁止主身份密文为空时残留对应 HMAC/last4 派生值，V288/V289 提供现货借用结构、终态守卫、审计与在线源码候选。V280–V289 都不改变 V279 的编号规则，也不能被误写为编号迁移已经部署。

V279、Java/Flutter 改动和本地定向测试只能证明同一冻结字节的源码候选；不代表公司目标库已迁移、历史冲突已签收、并发/跨日压测已通过、备份可恢复或真实岗位 UAT 已放行。迁移目录最高版本和文件总数仍须在最终交付冻结后现场重算，不以“V279 是编号迁移”推断它是整个并发工作树的最新版本。
