## 一、适用范围

本说明只覆盖新数据从“生产计划草稿”进入物料评审、预排草案、审核原子下达、关联单据回查、车间建议学习以及生产执行工卡打印的链路。旧生产计划、旧 BOM、旧库存、旧占用和旧单据不回填、不重算、不补造。

权威流程如下：

```text
生产计划草稿
  → 物料需求评审（当前直接 BOM 层）
  → 可恢复编辑的预排草案（不锁料、不开单）
  → 审核事务内重新校验并原子下达
  → READY / AUTO_WAIT（系统缺料，齐套自动转产）/ DEFERRED（人工暂缓）执行段
  → BUY 采购申请 / MAKE 直接层子计划 / SUBCONTRACT 委外申请 / DRAW
  → 结果回查与只读 A4 生产计划单（流水线执行工卡）
  → FINISHED_IN 精确回供 MAKE 父需求并按策略重新齐套
```

## 二、迁移职责

### V191：不可变预排草案

`production_planning_drafts` 保存目标仓、预览指纹、规范化请求载荷、请求哈希、规划人和规划时间。每张计划最多一个 `ACTIVE` 草案；再次保存将旧草案终结为 `SUPERSEDED`，审核成功终结为 `APPLIED`。载荷和终态不可改写或删除。

草案不是执行事实：不得产生库存占用、生产执行段、采购、委外、领料或子生产计划。

### V192：车间建议学习

`production_goods_workshop_preferences` 只保存“货品未来默认车间建议”。只有正式下达或后续派工成功、同货品本次安排无歧义时才学习；空车间、多车间、失败事务和幂等回放不学习。建议可由用户随时修改，不回写历史执行段。

该表是当前唯一默认建议来源：建议查询只返回有效货品以及 `DEPT_PROD` 直属有效车间；一次安排涉及空车间或多个车间时不学习。后续成功改派可学习本次明确选择，但已确认执行段的历史车间保持不变。

### V193：审计触发器覆盖扫尾

V193 在 V191/V192 之后重新执行审计触发器覆盖检查，只保证迁移后发生的新写入进入审计。它不补历史审计，也不读取或重算业务含义。

### V194：MAKE 直接供给与完工回供

V194 修正旧延迟约束对合法 `MAKE` 需求的误拒绝，并把 `PRODUCTION_PLAN_ITEM` 作为明确供给来源：

- 父计划包只为当前直接 BOM 层的 MAKE 缺口创建子生产计划；A→B→D 时 A 只创建 B，进入 B 后再创建 D；
- 子计划明细通过 `production_material_supply_pegs` 精确挂接父 `production_material_demands`；货品、颜色、单位、供给路线、父计划、计划包和 `EXECUTION_V1` 子计划链均须一致；
- 已审核 `FINISHED_IN` 只能按明确的上游子计划明细回供对应 MAKE peg；
- `production_material_make_receipt_allocations` 记录入库行→peg→父需求→预约→DRAW 的不可变来源链；正常更正只允许追加反向事实；
- 入库行容量、供给 peg 消耗、预约数量和 DRAW 数量必须守恒，并通过一致的行锁/事务锁顺序阻止并发超配；
- 有效分摊只允许属于仍有效的 `CONFIRMED` V1 计划包；子计划、子计划明细或链接在活跃 peg 存在时不得被取消、软删或断链；
- 红冲入库在父段尚未派工/领料时回到 WAITING 并释放本次来源；已派工或已领料时 fail-closed，要求先走业务反向；
- 用户可明确选择“待料 · 齐套自动转产”或“人工暂缓 · 手动恢复”。前者保存 `WAITING + auto_promote_when_ready=true`，后者保存 `WAITING + auto_promote_when_ready=false`（界面处置 `DEFERRED`）；到货回调只提升前者；
- “解除人工暂缓”要求编辑权限、期望版本和幂等键，只允许 `false→true` 一次，并写 `RELEASE_DEFER` 语义事件；同一事务立即重查齐套，已齐套转 READY，仍缺料则保留为可自动提升 WAITING；
- V194 数据库守卫要求新写入车间必须是 `DEPT_PROD` 直属有效车间、班组必须直属该车间；负责人必须是所选组织范围内未删除的 `active/probation` 员工。服务端在草案保存、正式下达、后续改派和派工前重复校验，不能依赖前端下拉框保证完整性。

### V195：审计覆盖再次刷新

V195 在 V194 新增 MAKE 回供分摊业务表之后再次执行 fail-closed 审计覆盖检查，确保包括 `production_material_make_receipt_allocations` 在内的公开业务表都恰有一个启用的 AFTER ROW I/U/D 审计触发器。V195 只保护迁移后的未来写入，不补造历史审计，也不回填或重算任何业务数据。

## 三、无 BOM 与数量门禁

物料评审可列出具体缺 BOM 的成品/自制组件用于治理，但同一生产计划只要存在任一阻断 BOM 缺口，保存草案和正式下达都必须整方案 fail-closed。禁止把“缺 BOM”当作“零物料需求”继续生成半套计划。

对每一条计划明细必须保持：

```text
Σ READY + Σ 系统缺料 WAITING + Σ DEFERRED = 当前未排生产数量
```

READY 必须拥有全套库存预约和对应 DRAW；AUTO_WAIT / DEFERRED 均不得持有零散预约或半套 DRAW。服务端在保存和下达时重新计算并拒绝陈旧指纹、数量不守恒、READY 不齐套或无效车间/班组/负责人的方案。

## 四、打印投影边界

「生产计划单（流水线执行工卡）」是已确认计划包的只读 A4 打印投影，不新增业务实体，也不是工艺路线卡。服务端只从已持久化的计划包、执行段、需求、预约和 DRAW 关系生成结构化视图；每次预览/打印都先按计划制单人对象范围鉴权，并以计划→包顺序锁定当前快照，只有计划已审、未停止/未取消且包为 `CONFIRMED/V1` 才允许，草稿、红冲、停止、取消和失效包禁止打印。

工卡包含计划单号、产品编号、开单日期、交期、分段流水号/条码、货品编号/名称/规格/颜色、实排数量、单位、单支用量、需求/承诺/缺口、车间、班组、负责人、计划开完工、销售订单、领料单、审核人/确认时间、包版本、打印时间/页码和签字栏。名称策略明确为 `CURRENT_MASTER_DATA`；历史数量和关联 ID 仍以持久化事实为准。补打和手写内容不改变系统状态。

纸面尾部的横线区域仅供记录异常、换料、停线和交接，必须打印“手写内容不回写系统”；任何手写内容都不能替代系统中的报工、退料、异常处置或状态变更。

批量打印保持每张计划的精确 plan/package/segment 身份和原始顺序；单次最多 50 张计划、200 张工卡，每 5 张有界读取，任一失败整批终止。单张补打按 segment UUID 重新读取，不按可变分段号猜测。普通领料段的 READY 只表示齐套预留和领料需求已经形成，纸面必须写“已齐套待派工”并提示仓库实发前禁止开工；ZERO_MATERIAL 明说无生产领料需求、仍须车间派工和系统确认。WAITING/人工暂缓、DISPATCHED 和 COMPLETED 也分别显示禁开工或仅存档口径。

## 五、历史数据策略

V191–V195 均不得执行历史业务回填：

- 不为旧草稿或旧已审计划补造草案、计划包、执行段、子计划或供给 peg；
- 不从旧文本、旧报工或仅 4 行历史 `department_id` 推断车间偏好；
- 不重算历史 BOM、库存、占用、READY/WAITING 或下游单据；
- V194 新表初始应为空，历史生产计划、明细、库存和单据计数在迁移前后应保持不变；
- V195 只刷新审计触发器覆盖，不读取业务语义、不补历史审计；
- Flyway 已应用脚本不可改写；如候选脚本已进入任何共享环境，后续修正必须新增更高版本迁移。
