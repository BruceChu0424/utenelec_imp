# 生产物料分析准备

本文是准备页、下达车间、采购和委外三个入口的现行交互合同。历史验收记录只证明当时的代码和环境，不代替当前测试或部署状态。

2026-09-26 本轮业务修复已收尾；极大混合单性能仍有未完成项，当前源码不能视为已经部署。测试批次、规模边界与最后安装核对统一见[修复与验证记录](../99-项目治理/2026-09-26-物料准备统一流程修复.md)，本页只维护现行交互和业务规则。

入口 `/production/material-analysis`，历史记录 `/production/material-analyses`。分析编号来自 `analysis_no`，不以短 UUID 或货品编号代替单号。

## 1. 员工流程

1. 选择已审核销售订单行或合法手工需求，填写本次来源数量，选择主仓库，联合分析。
2. 已有供应方式自动带出并保存。未能确定的行保持空选红框，补选后即保存；没有独立“确认路线”步骤或按钮。自动保存只确认供应方式，不创建采购、委外、车间任务。
3. 在原产品树核对需要数量、可用数量、还缺数量、下单数量和指派。每个真实子件都可以单独下单或追加。
4. 勾选后一次确认下单。相容的同料自动合单，员工无需进入“共享批次”办理页。
5. 回执更新原产品树和三个桶；失败保留未完成的输入与选择，已成功的部分如实保留。

三个桶用于按部门查看待处理、进行中和需处理。桶外层是只读清单，勾选后进入共用“核对并下单”页。核对页复用主表的列、输入控制器、路线、指派、数量预览及提交器，不另维护 notify/issue-plans 的私有编排。

## 2. 来源与树形

- 销售来源以订单行 UUID 为准；手工来源保留真实来源类型、编号、货品、颜色和单位。
- 原产品及 BOM 路径是页面稳定身份。合单后不额外把制造锚点和子件提升为用户产品，也不把原子件变成不可办理的零需求行。
- 系统制造锚点、实际计划和原需求分摊仍在后台保留。读取和命令解析依赖精确 BOM 边、来源分摊及别名证明，禁止按货品名、同货品首行或树中首行猜写入目标。
- 顶层产品保留独立销售/手工来源。组件按货品、颜色、基本单位、供应方式及相容制造参数合单；BOM、车间、负责人或日期等不相容时不能静默采用首个来源设置。
- 汇总视图是同一组事实的可选核对方式，不是追加或继续办理的必经步骤。原行和合计必须去重，不同时累计原需求、制造锚点和其转交份额。

## 3. 数量口径

| 项目 | 含义 |
| --- | --- |
| 需要数量 | 原始来源数量沿保存的 BOM 逐边计算的 `sourceRequiredQty`；下单、超量和追加不改变它。每条边按本节点锁定采用的用量计算：有真实使用数量用真实值，否则用设计使用数量；整包/固定批次、父件单位变了、单一子件委外发料 (按委外合同用量) 用设计值。单元格悬停说明本行按哪个用量算、依据几批、设计值多少；按真实使用数量算且采用时的报工不良率大于 0 时，括号里另列「不良率 X」(百分数，最多 2 位小数，例如「每件按真实使用数量 0.105 计算(12 批累计，设计 0.1，不良率 3.25%)」)，按设计使用数量算时从不列出；不良率只作说明，不参与计算 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.13)；表头仍只留字、不挂说明 |
| 实际备料需求 | 真实计划产出所需的材料；随父件计划量、包装及固定批次规则变化 |
| 下单数量 | 本行实际发出的有效下单量，包含超量；不能只显示分给本需求的数量。多来源合单保留每行输入意图，行合计等于真实单据量 |
| 追加下单 | 已下单行的本次新增量。成功后累计到下单数量，本次输入归零；不能把旧下单输入再加一遍 |
| 还需安排 | 扣除已落实责任后仍须办理的量。可采用供给尚未被占用时仍需办理，不能只因看到候选供给就当作已安排 |
| 还缺数量 | 核对可采用供给后仍需补下单的净缺口；不等于实际领料缺口 |
| 可用数量 | 可安排的仓库现货，加上在途及已下达但尚未办理的供给剩余量；扣除有效占用、认领与已实收部分，按真实供给来源去重 |
| 实物缺口 | 尚未到仓或没有合法精确权益的物料缺口；用于领料/开工门禁，不能由计划可用量替代 |

用量采用与锁定 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.5)：分析在新建和人工「刷新」时才采用最新的设计/真实使用数量 (`design_bom_qty / actual_bom_qty / usage_basis`，采用时的不良率 `usage_defect_rate` 跟真实使用数量一起采用和锁定)；保存路线、下达、审批、唤醒等内部重算沿用快照里的值，只按当前路线重新选用哪一个。例外：BOM 行被原地改了计量规则 (换了组件或单位，改了计量方式、计量基数或是否允许尾包) 时，锁定值只在原规则下有意义，这条边按现时值重新取。人工刷新时，父节点已有下达计划批次的子节点保持原值，与已冻结的车间需求一致；汇总下单的共享制造批次里，锚点与各成员子树在同一相对路径上保持同一个数 (锚点第一次展开时沿用第一个成员子树的锁定值)。同一次重算若改掉了父节点的有效路线 (例如主档建议变了、人工确认被清掉)，会按新路线再选一次用量，需求与分配看同一条路线。预览、下达、汇总下单和审批因此看到同一个数；用量变化不清人工确认的路线，也不让预览报「结构已变化」、下达/审批报「BOM 直接层已变更」，只有组件/颜色/单位/层级路径/控制段/计量规则/第一层单位换算率变了才要求刷新。汇总下单批次的配方键按设计使用数量，学习不会让后续追加找不到原批次。

例如实际下单 10000，本需求安排 1000，页面下单数量显示 10000；剩余 9000 可以成为其它订单的可采用供给。另一订单采用 4000 后，剩余可采用量为 5000。实际到货时，这 4000 按认领来源归接收订单，未认领的部分进入公共库存，不产生第二份库存或销售分摊。

编辑中的共享预算：只有勾选且有效的本次下单量或追加量才预扣可用量，扣至 0；取消选择、清空或减少数量即释放差额。同货品、颜色、基本单位及供给范围使用同一预算，不把每条 BOM 行的重复仓库数据累加，不把历史下单量再次扣除。可用数量列只显示仍可安排的共同余量，本行已经占有的份额不再加回该列；本行私有预留与已领用覆盖仍用于扣减本行缺口。该扣减是页面本轮编辑预算，不写库存或认领；提交后以重新读取的正式供给事实重建预算。还缺数量同时按本行需求与剩余可用量重新计算。

各产品行的首次或追加输入相互独立。修改 A 的输入不会减少或覆盖 B/C 的默认量或手工量，只同步共同可用量和缺口；同一个产品的父件与其子件仍按 BOM 联动。三个产品各需 1000，三行分别输入 10000、1000、1000 时，实际提交总量是 12000，三份占用合计 3000 后共同可用为 9000；实际总下单 10000 且三份需求均已安排时共同可用才是 7000。确认下单显示本次实际合计。

同一合单中 A 填 10000、B 填 1000，应保留 10000/1000 的原行提交意图，不能因需求相同比例回显成 5500/5500。历史记录缺少逐行输入证据时，只能显示有依据的分配与单据总量，不能倒推成“当时输入”。

自制原工单增长按累计产量计算材料差额：`f(原量+追加)-f(原量)`。包装、固定批次按真实执行批次取整，不能对多个来源各取整一次再相加。

## 4. 父子联动与输入保护

- 父件修改首次下单或追加数量后，所有实际受影响的后代重新计算缺口和建议量。折叠、分页、尚未创建输入框的子件同样参与。
- 子件新增缺口默认勾选；不把“保护手工数量”当作跳过勾选同步的理由。用户明确取消的选择保留，显式重新选择父树可以重新选满。
- 手工数量不被后台刷新、迟到预览、系统建议或其它行编辑覆盖。首次下单与追加只读取当前有效的数量列，预览与提交一致。
- 首次和追加都可分批。采购起订量/倍数只作为有权限时的系统建议；没有需求不自动抬量，手工输入仍由用户决定。
- 已下单数量、已有单据的供应方式和生产参数按真实单据锁定；新增量在追加格办理。补充指派在同一核对页完成，不因为缺少车间/负责人把复选框直接隐藏。
- 允许超产比例列 ([ADR-129](../99-决策记录-ADR/ADR-129-BOM设计使用数量与真实使用数量.md) §2.10)：按货品默认预填——有记住的最近一次人确认比例用它，否则结构默认 (货品来源采购/委外 0%；制造底层 10%，上层 0%)。没被人改过的格子下达时提交空值，由服务端按默认填写、标 `DEFAULT`、不记住，新快照带来新默认值时跟着刷新；人改过的按所填值提交 (`EXPLICIT`) 并记成该货品下次默认，文字不再跟着刷新，但判断「是不是还等于默认」改按新默认比 (之后改回旧默认也算人填的)。汇总下单表的比例格在各来源都没人改过时跟着来源一起刷新到新默认；撤销草稿时，当时仍是系统预填的格子回到当前默认值，不把旧默认当成人填的放回去。本页、汇总下单表与计划编辑页判断「人改过没有」用同一个助手 (`SystemPrefilledRates`)。计划单带来的比例 (人改过才会带来) 同等明确提交。已下达的比例随工单锁定显示，修改仍须计划部审批。

## 5. 自动合单、追加和性能

组件共用汇总命令，单来源也经过相同的权限、数量、来源和幂等核对。顶层产品先办理，再按真实父子依赖执行组件；同一依赖层合批，父件落地后按权威快照核对下一层。不得把非重复子件先全部下掉，再提交重复父件。

未提交领料、未发生执行事实且参数相容的自制追加进入原计划及原 ZX 工单，保留 UUID 与单号；已提交领料、发料、开工、报工或拆批时新建任务，旧历史不改。采购/委外未被下游操作的申请追加到原明细，已操作后按现有规则新建责任。

- 同一分析的写入具有共同版本、库存和来源锁，不能用客户端无界并发加速。
- 一次提交最多 500 个物料组、10000 条来源路径；同料不因来源条数被误拆成多张单。
- 上述是请求容量上限，不是已经通过的时延规模。原事务截止时间继续生效；本轮 100 组混合任务、150 个计划仍会超时整批回滚，不能向员工提示整批成功。分轮提交中已经成功的前轮保留真实回执，失败轮输入保留供核对。
- 缓存每份快照的节点索引和行投影；每页按需构建。消除重复全图读取，必要的父子刷新仍按依赖顺序保留。
- 独立制造组可分阶段建立锚点并集中刷新；共享原材料的实际审核仍逐计划读取最新库存。单个计划在完整锁内复用不可变的执行预览，正式库存/执行写入之前立即失效，不跨计划或事务复用。分析内部创建/审核读取轻量命令结果，普通计划详情和追溯接口保持完整。
- 已证明无祖先/输出/供给交叉的制造组，按阶段批量读取来源容量和精确 BOM 责任；每份读取按真实批次及父件分配隔离，不能按同货品推断归属。单计划完成后 flush 并清理 JPA 已完成实体，数据库事务及原锁仍保留。
- 数量预览只读，300ms 去抖、单飞并尾随最新输入。预览不建计划、不写库存、不通过真实下达再回滚模拟。
- 过时的编辑预览取消客户端请求，同签名有效预览继续复用；取消不代表服务端 SQL 一定已停止。一次整树下单完成或部分失败后统一刷新辅助数据及徽章，后继计划必须的指派读取仍先于提交。
- 命令使用版本、指纹和幂等键；网络失败不擅自重放不确定写入。409 更新事实后重新核对，未提交输入保留。
- 后台动态数量变化应刷新可用量、累计、缺口与流程阶段；服务端动态投影变化不以分析头版本未变为由忽略。

## 6. 三个桶与进度

主表、桶清单、核对页共用办理数量和权限。采购与委外用真实申请/订单链的 `flowStage`，车间用真实计划与执行事实；文案来自 `ProductionFlowStage`，颜色统一由 `MaterialPreparationStatusStyle` 按待处理、进行中、待收货、完成、阻塞、取消等语义映射。主表最后的待办列和三个桶使用相同整格背景、文字色，不因采购、委外或车间不同而换色；保留每种业务真实步骤名称。不再加“并入共享批次”等技术前缀。

进度不能把“已经下单”说成“已经入库”，也不能因需求已转交就说“未下达”。已有明确单据阶段时优先显示它，认领数量、缺料解释和来源分摊放在详情，不掩盖真实流程阶段。

桶左上角统一使用 `UtenFilterToolbar` / `UtenFilterSegment`，只保留待处理、进行中、需处理；已下达分类退役。待处理计数为红色，进行中黄色，需处理作为待处理的子集用中性计数，不重复累加。

三个入口继续使用工作台同款黄色进行中、红色未下达徽章，零数隐藏、超过 99 显示 `99+`。徽章与点击后的列表使用同一行投影。完成和取消只保留历史；部分下达可同时有待安排和进行中状态。

## 7. 仓库、执行与反向

所属仓库、归属车间直接来自 `goods` 的归属字段，与货品资料、仓库及车间使用同一事实源。正常业务入库通过 `GoodsOwningWarehouseSyncService` 学习真实仓库；确认生产指派通过 `ProductionGoodsWorkshopPreferenceService` 学习默认车间及负责人。准备页重新读取时同步这些字段，即使分析版本没有变化也要更新。带未提交草稿时保留各行数量文本、选择和路线决定，同时刷新归属、供给数量和真实进度；核对下单页打开时仍沿同一读取通道刷新。结构变化只保留仍有精确原行对应的草稿并提示核对，迟到的旧请求不能覆盖较新的归属修改。

顶层产品已有本产品实际生产计划时，生产车间和负责人显示真实计划/执行任务的指派并锁住；不再显示可修改下拉框，也不由最新货品默认值替换历史指派。只有采用他人供给而没有本产品生产计划的情况不能借用来源计划的指派。货品默认归属更新与已下单任务指派是两种事实。

计划员选择主仓库。服务端展开合法子仓并保存真实库存归属；实际领料、送检与入库由对应仓库办理。公共计划可用量不能转成 READY、正式预留或已发料。

MAKE 缺料允许先下达 WAITING，实际领料和开工仍要求合法到货与本执行批所需材料。`SHIP/REFERENCE` 仅供参考，不生成正式物料需求。委外按是否需要前置自制分流；需要前置自制的行明确要求生产下达权限及指派，不通过通知权限绕过。

自制公共供给以真实计划明细为来源，认领只是供给承诺。实际成品入库才建立原有库存预留、精确归属和权益事件；不能继承原计划的私有销售/用料身份。撤回只释放尚未实收的认领余量；已领用或已下游转移的实收按原反向顺序恢复后才能红冲。目标分析合法释放实收权益后，V723 关闭相应承诺，后续源入库红冲不得复活已取消目标。

取消分析成功后返回来源页并刷新计数。撤回某笔供给仍留在当前分析核对其它任务，不能通过原单一来源撤回入口取消其它来源的份额。

## 8. 接口与验证

接口前缀 `/production/material-analyses`。读写表示协商见[响应协议](../05-架构/物料分析响应协议.md)。

| 动作 | 接口 | 权限/约束 |
| --- | --- | --- |
| 分析/授权刷新 | `POST /preview` | create/refresh，持久化分析，不下达任务 |
| 查看详情 | `GET /{id}` | view 与对象范围 |
| 自动保存供应方式 | `PUT /{id}/routes` | route，已有单据的路线守卫照常执行 |
| 顶层产品下达 | `POST /{id}/issue-plans` | generate，立即审核另需 production_plan:approve |
| 下达数量预览 | `POST /{id}/issue-plans/preview` | 只读投影，同一快照、结构与版本核对 |
| 组件核对/下单 | `POST /{id}/aggregate-orders/preview`、`submit` | 原行来源解析、兼容核对、完整锁内重算、幂等 |
| 公共供给认领、撤回、调拨 | 对应专用命令 | 来源容量、对象范围、独立权限与反向守卫 |

合单预览保留物理执行行 `materialLineId`，同时返回本次原产品树的 `originalMaterialLineIds`，并纳入预览指纹。客户端核对完整原行集合及同份分析的精确别名图；兼容无新字段的响应时只沿该图解析，禁止按同货品猜测。任何丢失或冲突都保留本轮输入并停止后续提交，不能把内部编号变化当作该层已完成。
