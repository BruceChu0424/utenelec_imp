## 一、现行业务链与不变量

两种入口最终进入同一条执行链：

1. 委外人员直接新建委外订货单；
2. 生产物料分析选择 `SUBCONTRACT`，形成只读委外申请，再由委外任务中心分解为订货单。

两者都必须先完成订货财务批准，再按**每条订货明细**的活动 BOM 快照分流：

```text
委外订货财务批准
  ├─ 目标件无活动子层级
  │    DIRECT_OUTBOUND → 目标件进入仓库待出仓
  └─ 目标件有活动子层级
       MAKE_THEN_OUTBOUND
         → 独立 SUBCONTRACT_PREPARATION 物料分析
         → 正常自制整树：备料 / DRAW / 开工 / 装配 / 报工 / FQC
         → 仓库实收入库并转委外行专属预留
         → 整条订货行数量完成后进入仓库待出仓

仓库审核目标件出仓
  → 委外商加工
  → 仓库登记物理回厂
  → IQC 待检隔离
  ├─ PASS：品质合格待仓库入库，不写库存、不推进原物料分析
  │    → 仓库确认实际量与库位：合格入库并推进原物料分析供给
  └─ FAIL：不进可用库存，进入退回/处置
```

必须同时满足以下不变量：

- 新流出仓行的 `goods/color/unit` 与订货目标行一致；`parent_goods_id` 与 `goods_id`
  对新流均指向目标件。BOM 子件只在内部自制分析/生产链中出现。
- 数量按目标件**基本单位 1:1**守恒。订货行存在单位换算时，计划行以
  `planned_qty = order_qty * order_unit_rate` 冻结基本单位量；兼容字段
  `bom_unit_qty` 在新流承载该换算率，不代表子件单耗。
- 有子层级的前置自制可以分批报工、FQC 和实收入库，但 `prepared_qty == planned_qty`
  前不得首次释放仓库委外出仓。
- 前置自制入库不是原分析的委外供给完成。该数量同事务转为
  `SUBCONTRACT_OUTBOUND` 专属预留；委外回厂 IQC PASS 只形成待入库，只有仓库实际确认入库才推进原分析。
- 新流必须先有审核通过的目标件出仓，才能审核物理回厂；回厂基本单位量不得超过
  已审核出仓量，且必须与 V221 供应商处保管台账消费量精确一致。
- 通知只提醒员工打开权威任务。状态、`allowedActions`、库存预留、单据和质检记录才是
  执行依据，通知未读/已读/顶部关闭均不能代替业务动作。

V436 当前只支持同一 SKU 的 1:1 加工前后身份。加工前后不同货号、收得率、一出多进或
多出一进必须另建 SKU 转换模型，不得用备注、改数量或伪造 BOM 绕过。

## 二、V436 表与字段

### 2.1 结构变更总览

| 对象 | 变更 | 权威用途 |
|---|---|---|
| `production_material_analysis_items` | `source_type` 增加 `SUBCONTRACT_PREPARATION` | 标识只为一个委外订货行生产目标件的独立分析；`source_ref` 固定为 `SC-PREP:{orderItemId}` |
| `subcontract_material_plan_items` | 增加流向、准备状态/数量、BOM 快照、冻结仓、分析来源、启动人/时间与 CAS 版本 | 一行一条委外订货明细的目标件准备事实 |
| `subcontract_outbound_preparation_commands` | 新表，当前操作仅 `START_PREPARATION` | 记录可重放、带请求哈希和前后版本的计划员启动命令；禁止 UPDATE/DELETE |
| `stock_reservations` | `owner_type/purpose` 增加 `SUBCONTRACT_OUTBOUND`；供应来源允许 `STOCK_BALANCE`、`PRODUCTION_FINISHED_IN` | 阻止公共库存、其它分析或其它订单再次占用已留给该委外行的目标件 |
| `subcontract_outbound_issue_reservation_allocations` | 新表，`EFFECTIVE/REVERSED` | 精确记录每条 EC 出仓明细消费了哪些本行专属预留切片 |

V436 不新建第二套库存余额、供应商台账、通知表或应付表，也不新增重复的仓库任务视图。
仓库列表、订货进度和生产准备队列都从上述权威事实投影。

### 2.2 `subcontract_material_plan_items` 新字段

| 字段 | 类型/约束 | 说明 |
|---|---|---|
| `flow_mode` | `LEGACY_BOM_COMPONENT / DIRECT_OUTBOUND / MAKE_THEN_OUTBOUND` | 区分历史子件流、直接目标件流和先自制目标件流 |
| `preparation_status` | 见第三节 | 行级准备状态；不能用单头状态替代 |
| `prepared_qty` | `0 <= prepared_qty <= planned_qty` | 已专属于本委外行的目标件基本单位量 |
| `bom_has_children_snapshot` | 新流必填，历史为空 | 财务批准时目标件是否存在活动直接 BOM 边 |
| `preparation_bom_fingerprint` | 新流 64 位小写 SHA-256，历史为空 | 按 BOM 边 UUID、子件/颜色/数量生成；启动准备和保存出仓草稿时复核漂移 |
| `preparation_warehouse_id` | FK `warehouses` | 前置自制冻结实收仓；直接流在仓库保存草稿时确定/更新来源仓 |
| `preparation_analysis_id` + `preparation_analysis_item_id` | 复合 FK 到分析明细 | 精确绑定唯一 `SUBCONTRACT_PREPARATION` 分析行 |
| `preparation_started_by/at` | FK `users` + 时间 | 谁在何时显式启动前置自制 |
| `preparation_version` | 非负整数 | 启动、准备、出仓、反向与关闭的 CAS 版本 |

分析来源由可延迟约束双向校验：分析 id/行 id、`source_type/source_ref`、目标件 UUID、颜色、
单位和需求量任一不一致都在事务提交前失败。只有真实委外任务可以拥有
`SUBCONTRACT_PREPARATION` 分析行，孤立或移花接木的分析来源同样被拒绝。

### 2.3 命令账与出仓分配账

`subcontract_outbound_preparation_commands` 的唯一键为
`(plan_item_id, operation, idempotency_key)`；同一个幂等键只有请求哈希一致时才能重放。
`expected_version -> resulting_version` 必须严格加一，表为 append-only 并挂审计触发器。

`subcontract_outbound_issue_reservation_allocations` 以
`issue_item_id + reservation_id` 唯一，并有全局唯一 `idempotency_key`。可延迟守卫要求：

- 审核出仓行的有效分配量之和等于该行出仓量；
- 预留 `consumed_qty` 等于其有效分配量之和；
- 出仓行、计划行、预留 owner、仓库、货品和颜色完全一致；
- 红冲不删除事实，只把分配改为 `REVERSED` 并记录操作人/时间。

## 三、流向与状态机

### 3.1 流向初始化

| `flow_mode` | 初始准备状态 | 初始 `prepared_qty` | 仓库含义 |
|---|---|---:|---|
| `LEGACY_BOM_COMPONENT` | `LEGACY_READY` | `planned_qty` | 仅兼容 V304 旧 BOM 子件任务 |
| `DIRECT_OUTBOUND` | `READY_OUTBOUND` | `planned_qty` | 无活动子层级，目标件可由仓库选择来源仓并预留 |
| `MAKE_THEN_OUTBOUND` | `ACTION_REQUIRED` | `0` | 有活动子层级，先由计划/生产启动独立自制分析 |

同一订货单允许混合三类行。仓库待执行数量按行投影；尚在前置自制的行不产生“看得见但
无法执行”的假出仓任务。

### 3.2 `preparation_status` 数据库枚举

```text
LEGACY_READY
ACTION_REQUIRED → IN_PREPARATION → WAITING_FQC → WAITING_INBOUND
                                      └───────────────┘
                         prepared_qty == planned_qty → READY_OUTBOUND
READY_OUTBOUND → OUTBOUND_COMPLETE
任一允许边界 → CANCELLED
```

- `WAITING_FQC`、`WAITING_INBOUND` 既是数据库允许值，也是准备任务/订货进度的有效展示态。
  当前读模型还会在落盘仍为 `IN_PREPARATION` 时，依据已报工、FQC 和 FINISHED_IN 草稿动态派生
  这两个状态，不能仅凭列值判断现场阶段。
- ADR-059 文案中的 `WAITING_FINISHED_INBOUND` 对应数据库值 `WAITING_INBOUND`。
- `PARTIALLY_OUTBOUND / PROCESSING / RETURNED_PENDING_IQC / PARTIALLY_QUALIFIED / COMPLETED`
  属于订货全链路投影，不是 V436 的 `preparation_status`，禁止写入该列。
- 审核出仓只在该行 `issued_qty == planned_qty` 时转 `OUTBOUND_COMPLETE`；红冲后仍有余量则
  对称回到 `READY_OUTBOUND`。

## 四、前置自制与仓库执行

### 4.1 启动前置自制

- 列表：`GET /api/production/material-analyses/subcontract-preparations`，要求
  `subcontract_preparation:view`；Flutter 稳定入口为 `/subcontract/preparations`。
- 启动：`POST .../{planItemId}/start`，同时要求 `subcontract_preparation:view + subcontract_preparation:start`，请求包含
  `expectedVersion`、8–128 字符 `idempotencyKey` 和目标仓 UUID。
- 目标仓必须存在、未删除且参与库存核算；冻结后不能静默改仓。
- 服务端在同一事务锁任务、复核 BOM 指纹、创建独立分析及唯一目标行，再写启动命令账。
  页面名称、BOM 展开显示或通知均不参与分流决策。
- 独立分析继续使用正常 MAKE 全树语义，必须完成下层备料、生产计划审批、DRAW 真实发料、
  开工/装配、报工、FQC 和仓库实收，不能为委外跳过其中任一环节。

### 4.2 前置自制成品实收入库

FINISHED_IN 审核事务按分析 id/行 id、计划 link、目标件 UUID、颜色、单位、换算率和冻结仓
逐项核验。每个实收行以 `SC-OUT-MAKE-IN:{stockItemId}` 幂等写一条
`SUBCONTRACT_OUTBOUND / PRODUCTION_FINISHED_IN` 专属预留，并累计 `prepared_qty`。

部分实收只转 `WAITING_INBOUND`；只有整条订货行累计等于 `planned_qty` 才转
`READY_OUTBOUND`、生成 EC 草稿并通知仓库。前置成品因此始终从 `v_stock_available` 的公共可用量
中扣除，不会提前满足原生产需求。

### 4.3 直接目标件与仓库草稿

无子层级行在财务批准后直接生成目标件 EC 草稿。仓库保存/修改草稿时：

1. 按库存维度加锁，选择发出仓和本次数量；
2. 释放该草稿旧的、尚未消费的直接库存预留；
3. 从 `v_stock_available` 校验合格可动用库存；
4. 写 `SUBCONTRACT_OUTBOUND / STOCK_BALANCE` 专属预留；
5. 库存不足、BOM 指纹漂移、跨仓或并发版本变化均 fail-closed。

有前置自制的行只能使用冻结仓内 `PRODUCTION_FINISHED_IN` 专属预留，不能改成公共库存补洞。
同一计划内不同冻结仓的准备行必须拆成不同草稿，禁止静默跨仓扣减。

### 4.4 审核出仓、回厂与反向

- 审核 EC 出仓先精确消费本计划行专属预留并写分配账，再写 `DIR_OUT/type15` 库存流水、
  V221 委外商处保管台账和计划累计；目标件出仓不立采购/加工费应付。
- 新流 `frozen_unit_qty` 只负责把回厂单据单位换成目标件基本单位；不再表达 BOM 子件单耗。
- 可分批出仓、分批物理回厂和分批 IQC；每次回厂都必须满足累计审核回厂基本单位量不超过
  累计审核出仓量，且供应商台账 `consumed_qty` 与审核回厂量精确一致。
- 回厂登记/审核只形成物理回厂与 IQC 隔离事实。IQC PASS 只生成合格待仓库入库切片；
  仓库按 `expectedRemainingBaseQty` 确认实际量与库位后才进合格库存并推进原分析。
  加工费应付继续按收货审核的财务时点处理，不由仓库确认重复立账；FAIL 不进可用库存。
- 出仓红冲先反向分配和预留消费，再回减 `issued_qty`。前置 FINISHED_IN 已被委外出仓消费时，
  必须先红冲委外出仓；存在 EC 草稿时必须先删除草稿，才能红冲成品入库。
- 订货红冲前必须按“委外出仓/草稿 → 成品入库 → FQC → 报工 → DRAW → 生产计划 → 分析”
  自下游向上反向。进行中的前置自制、下游消费或不一致预留一律阻断直接红冲。

## 五、历史回填与非空库对账

### 5.1 V436 自动兼容

V436 新列默认把全部既有 `subcontract_material_plan_items` 归为：

```text
flow_mode = LEGACY_BOM_COMPONENT
preparation_status = LEGACY_READY
prepared_qty = planned_qty
bom_has_children_snapshot = NULL
preparation_bom_fingerprint = NULL
```

迁移不修改既有出仓、回厂、库存流水、供应商结存、BOM 快照或财务事实，也不猜测某个旧子件行
其实是目标件。BOM 快照形状约束以 `NOT VALID` 增加：不全表扫描旧历史，但会约束以后新增/更新
的新流行。应用创建新流时必须显式写 mode、snapshot 和 fingerprint，不能依赖 legacy 默认值。

### 5.2 目标非空库必须对账

迁移前后至少留存以下只读证据：

- V436 前后计划头、计划行、EC 头/行、EJ 头/行、库存余额/流水、供应商保管数量与 AP 金额计数及
  汇总不变；
- 既有计划行全部为 `LEGACY_BOM_COMPONENT/LEGACY_READY`，且
  `prepared_qty = planned_qty`；新流 mode 数量在首次新单前必须为 0；
- 新命令账和新分配账在迁移后初始为空，无孤立 FK、重复幂等键或错误审计触发器；
- `stock_reservations` 既有 owner/purpose/supply 分布不变，不因 CHECK 重建而释放、消费或改写数量；
- 历史 V304 计划行与 EC、V221 supplier ledger 的关联和数量分布逐行可回读；异常进入隔离清单，
  不用 SQL 批量改成新流；
- 全 `public` 审计触发器矩阵、复合来源 FK、可延迟数量守恒和 append-only 命令守卫通过实库探针。

旧库 49,889 条委外发料数量、旧 BOM 版本差异和历史来源缺口仍是独立迁移治理项。V436 的
兼容标记不是这些历史问题的业务认定或修复。

## 六、权限与对象范围

V436 不扩权；V437 只新增页面级权限目录与 surface 精确关联，**零部门/角色/个人默认 grant**。迁移后必须由权限管理员按真实岗位显式授权；不复制旧 receipt price 授权，不恢复已停用复合权限。

| 能力 | 权限与额外门禁 |
|---|---|
| 查看前置自制队列 | `subcontract_preparation:view` |
| 启动前置自制 | `subcontract_preparation:view + subcontract_preparation:start` + 任务实时 `allowedActions=START_PREPARATION` + CAS/幂等/BOM 指纹/目标仓校验 |
| 打开已建分析 | `production_material_analysis:view` + `allowedActions=OPEN_ANALYSIS` |
| 查看仓库委外出仓 | `subcontract_outbound:view` |
| 生成/补齐 EC 草稿 | `subcontract_outbound:execute` |
| 关闭无须继续执行的计划余量 | `subcontract_outbound:close` + 原因 + 无草稿/无进行中前置自制 |
| 编辑/删除/审核/红冲计划生成的 EC | 对应 `subcontract_material_issue:edit/delete/approve/reverse`，并叠加 `subcontract_outbound:execute` |
| 委外商业字段 | 询价/订货/进仓/成品退货/报表分别使用本页 `:price:view`；损耗只有 `subcontract_waste:suggestion:view`；材料出/退无价格权限，历史成本仅 `finance:view:all` |
| IQC 查看/决定、仓库合格入库 | 继续使用既有品质与仓库动作权限及对象池，不由 V436 或通知授予 |

委外制单人只能在订货进度查看事实；仓库页面不显示价格、币种或加工费。计划/生产人员也不能因
收到通知获得委外订单商业字段或仓库出仓权限。服务端返回的 `allowedActions` 是按钮显隐和动作准入
的共同依据；前端只隐藏按钮不构成权限控制。

## 七、Outbox、通知页与顶部非阻塞叠放

V436 不直接写 Flutter 弹层。业务事务向既有 `business_outbox` 发布幂等事件，
`ChainNoticeService` 在 Outbox 投递事务内生成收件人专属通知页记录：

| 事件 | 收件人 | 动作入口 | 明确不代表 |
|---|---|---|---|
| `SUBCONTRACT_PREPARATION_REQUIRED` | SUB_PLAN/DEPT_PROD 中同时有 `notice:read + preparation:view + start` 的活动账号；委外制单人收进度回执 | `/subcontract/preparations` / 委外订货进度 | 已领料、已完工或已入库 |
| `SUBCONTRACT_OUTBOUND_READY` | SUB_WH 中同时有 outbound view+execute 的活动账号；委外制单人收回执 | 仓库委外出仓 / 订货进度 | 已预留、已拣货或已出仓 |
| `SUBCONTRACT_OUTBOUND_COMPLETED` | 委外制单人；存在分析来源时原分析制单人 | 订货进度 / 原分析汇总 | 已回厂或 IQC 结案 |
| 既有 IQC pending/resolved 事件 | 品质、仓库、委外制单人、原分析制单人，按事件权限/归属过滤 | IQC / 进仓 / 订货或分析进度 | 待检等于合格、通知等于入库 |

所有出现在通知页的未读到达提醒都必须同时进入全局顶部通知栈；二者不是可任选其一的通道。
顶部栈遵守以下规则：

- 非阻塞、非模态，不打断仓库拣货、生产填报或品质决定；`important/urgent` 只改变颜色、标题、
  停留时间和栈内优先级，不再自动弹居中确认窗；
- 最新通知叠在最上方，收拢时保留旧层轮廓，可展开最近 3 条并逐条操作；3 条只是同时完整展示
  上限，超过上限仍保留在队列，关闭上层后自动补位；
- 每条真实关闭只记录本设备已展示，不标记通知已读、不写业务完成；点击主动作才按现有协议标记
  已读并跳 `actionRoute`；
- 既有 `popup_acknowledged_at` 和 popup-ack API 只作历史兼容。默认到达链不再写 popup ack，
  也不能把它当作顶部已展示、通知已读或业务完成。

### 7.1 `SUBCONTRACT_RETURN_DUE` 交期提醒边界

当前调度器按上海时区每天 08:49 扫描，窗口为约定回厂日前 3 天至逾期；以
`orderId + businessDate` 幂等发布，Outbox 真正投递前再次读取当前物理事实。它是
`kind=NORMAL` 的交期提醒，带订货进度路由；**不是**可勾完成的 TODO，不设置 `dueAt`，也不产生
`task_completed_at`。业务任务是否完成仍看出仓、回厂、IQC 和订单投影。

只有同时满足以下条件才提醒：

- 订单 `status=1`、未删除、有 `deliver_date`，且日期已进入 3 天窗口；
- 至少存在该订货行的审核出仓；未实际出仓的订单不提醒；
- 新流读取 V221 `supplier_ending > 0`；全部物理回厂、材料退回或批准损耗把净结存降为 0 后
  不再提醒；
- 历史 `LEGACY_BOM_COMPONENT` 因子件与目标件量纲不同，只在该行已有审核出仓后使用订单行
  净未回厂量近似，不能把它冒充新流 1:1 证据；
- `is_closed/fulfill` 可能滞后，不作为屏蔽权威；投递时重新核验，避免延迟事件误报；
- 已物理回厂但 IQC 仍待检时不再报“委外加工逾期”，由品质待检投影继续负责。

收件人只包括活动的委外制单账号和有真实来源关联的原物料分析制单账号，不广播金额，也不通知
无关财务/仓库人员。到期前/当日优先级为 normal，逾期后为 important；无论优先级都进入同一顶部
非阻塞栈。

当前调度器标注 `@Profile("!cloud")`。若目标环境启用 `cloud` profile，必须在发布前证明存在唯一、
可重试且使用同一幂等键的外部调度入口；未证明前交期提醒验收为 **NO-GO**。

## 八、并发、异常和反向顺序

- 锁顺序保持 inventory dimension → analysis/plan/package/segment → subcontract plan/order →
  stock document/item；同一事务不得反向获取。
- 前置启动使用 `preparation_version` CAS、请求哈希和命令账；同键异请求拒绝，同键同请求可重放。
- 保存草稿在库存锁内先释放旧直接预留再建新预留；库存不足、换仓、BOM 漂移或并发改量整体回滚。
- FINISHED_IN 来源、出仓分配、预留消费和回厂消费均有双向可延迟守卫；只改表头、只改一侧数量或
  用通用 SQL 绕过服务都会在提交时失败。
- 已有委外出仓消费时禁止先红冲前置成品入库；有进行中的前置分析时禁止直接红冲订货；同单仍有
  `ACTION_REQUIRED/IN_PREPARATION/WAITING_*` 行时禁止仓库关闭整张计划。
- 关闭、取消和红冲必须释放未消费专属预留并保留原因/反向分配；禁止硬删已审核业务事实。

## 十、发布 NO-GO 门禁

以下任一项未关闭，V436–V447 业务链不得启用或宣称上线：

1. 冻结 V436/V437/V446/V447 和关联应用字节，确认迁移目录版本唯一、checksum 可复现，且未改写已应用迁移；
2. 从目标库当前版本的真实脱敏备份/克隆执行非空升级，完成第五节全部历史对账；
3. 用计划、生产、仓库、委外、品质和财务真实权限账号完成正向、越权、对象范围和深链 UAT；
4. 完成 direct/make/mixed、部分出回、IQC PASS/FAIL、材料退/损耗和反向的实物数量守恒签字；
5. 验证 Outbox 重试、收件人快照、通知页 + 顶部叠放、交期调度单实例和断网/重登恢复；
6. 验证并发保存/审核/红冲、锁顺序、幂等重放和容量，不出现负库存、双占用或跨单泄露；
7. 完成迁移前备份、恢复校验、RPO/RTO 演练、签名构建、部署回读和监控告警。

## 十一、回滚与恢复

- **迁移事务失败**：让 Flyway/PostgreSQL 自己回滚，保留失败证据；禁止 `flyway repair`、删约束或
  手工把 schema history 标成功。
- **V436 已应用但尚无新流业务**：停写后可按经验证的 V436 前完整备份整体恢复，并配套回退到兼容
  应用版本；必须重新核对之后是否存在任何不可丢写入。
- **已有 `DIRECT_OUTBOUND/MAKE_THEN_OUTBOUND` 业务事实**：禁止单独回退旧 JAR、DROP 新列/表或
  把新行批量改成 legacy。旧应用会把目标件计划误当 BOM 子件，可能造成错误出仓。应先冻结订货批准、
  前置启动、EC 保存/审核和回厂写入，按业务反向顺序处置在途事实，再选择经过批准的全库时间点恢复
  或新增 V448+ 前向修复。
- **V446/V447 单版本边界**：必须停止全部旧实例后依次应用 V446、V447，再只启动新应用；任一旧实例、旧 JAR 或旧异步 worker 仍存活都不得迁移或恢复写流量。
- 恢复后必须复核库存余额/流水、专属预留、EC/EJ、supplier ledger、IQC、AP、Outbox/notice 和审计
  指纹；仅“应用能启动”不构成恢复成功。
