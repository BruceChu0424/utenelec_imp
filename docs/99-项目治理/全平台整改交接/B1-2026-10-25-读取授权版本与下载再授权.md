# B1 读取授权版本与下载再授权

日期：2026-10-25。状态：公共 authority、V936 前向候选与定向测试已写，最终组合验证及主树整合由根任务回填。V935 已由根任务冻结；本变更新增 V936，不改旧迁移，不在共享数据库应用。

## 真实缺口

`DataScopeAdminService.setDataScopes` 的差量授权变更不推进角色 `users.auth_version/authorization_state.epoch`。客户 owner/可见人有独立 `clients.access_version`。所以，仅比较角色戳不能防止导出下载或报表元数据复用越过新的数据范围；角色 A→B→A 之外还需保护数据范围的往返变更。

现有角色戳仍负责角色、部门授权和委派配置。不得为补这个缺口随意推进全局角色 epoch：V322 的委派绑定它。委派自然起止不写数据库，仍须读取现有有效权限 authority。

## 现有 authority 与保留差异

| 读取域 | 真实入口 | 必须保留的边界 |
|---|---|---|
| sales | `SalesDocumentAccessPolicy.scope → OwnerVisibility.evaluate(sales,sales:view:all)` | 订单/出货/退货/其它出货 owner 与正式交接、只读数据范围 |
| finance | `FinanceDocumentAccessPolicy.scope`；公司报表另有 `requireCompanyWideReportAccess` | 单据按 maker；完整公司财务、账户流水、预收款仍走原额外权限，不套客户主档 owner |
| purchase/subcontract | 现 ReportService 的公司级报表权限与 `CommercialPriceVisibility` | 当前报表没有文档 owner 裁剪，不能用新增版本服务改变其业务范围 |
| production | 当前计划类 ReportService 的公司级报表权限 | `production_where_used` 是独立权限族，不能强并 `production_report` |
| stock | 公司级 `stock_report` 和 `StockCostMasker`；instant 导出调用原 `instantInventoryRows` | 选仓是原过滤；ADR-149 的 warehouse task keeper 范围不用于这些报表，不强塞 keeper 交集 |
| client | `ClientAccessPolicy` 的 OwnerVisibility、客户可见人 EXISTS 和 assign 权限 | 客户资料与销售订单各有范围，不能把客户 ACL 变更错误解释成销售报表 ACL |
| supplier | 原精简字典的未删除、非内部车间及 `supplier:view` | 已禁用仍可解析名称；采购/委外文档 owner 范围不等于供应商资料字典范围 |

`StaffAuthorityResolver` 对存在启用上下文委派的结果不缓存，包括暂未有效的委派；fresh `SubmitterPrincipalRestorer.restore` 因而能反映自然起止时间。版本服务不复制角色、客户、交接或价格权限算法。

## 公共接口

`security.ReadScopeVersionAuthority.scopeFor(domain, suppliedSubject)` 支持上述六报表域及 client/supplier，返回 opaque 64 位十六进制 SHA-256。必须经 Spring proxy 调用：每次独立只读 REQUIRES_NEW、REPEATABLE_READ，15 秒超时。

它复用 restorer 重新读取当前账号/角色戳，拒绝员工绑定或 superAdmin 形态漂移、以及 supplied 主体仍持有的已失效权限。合法受限主体不偷带后来变宽的权限；临时绑定与真实 reader 相同的 supplied 主体调用 OwnerVisibility，然后恢复原 SecurityContext。OwnerScope 只编码 read 的 seeAll/visibleOwners，不把 writableOwners 当读取范围。

stamp 包含主体、员工、代操作人、当前角色戳、实际 reader 权限集合、现行 OwnerScope 和独立域代次。绑定漂移/读发布失效使用 `READ_SCOPE_CHANGED(403)`；具体功能权限仍由原 Controller/Service 唯一检查，普通无功能权限仍是 FORBIDDEN，版本服务不新增一套 feature 门槛。它不是业务事实内容版本，也不是浏览器 session/MFA 凭据。

持久导出原有禁止模拟导出仍保留。旧文件 scope 不匹配由导出 gate 提示重建，不把用户请求查看旧任务误当全站会话失效。角色戳、范围 stamp、选中扩展定义的当前读取权限与文件 SHA 各有职责，不能彼此代替。

## V936：事务与晚提交

`read_scope_generations` 是八域视图，其 generation 是永久 `read_scope_change_events` 的已提交事件数。每域每事务最多一条；txid 只用于相等去重，事务 local 标记避免逐行批授权反复写全局状态。事件禁止 update/delete/truncate，不使用最大 ID 或 created_at 水位，因此晚提交仍会增加代次。

该结构不在业务锁后争抢一行全局 counter，避免引入交接/并发授权的锁序环。代价是授权事件索引 count；其规模与业务流水单列，最终资源/增长证据不得用小样本冒充。后续若做摘要，仍需独立核验已提交范围与重建，不能改成最大 ID 水位。

| 监测源 | 推进域 | 精确变化 |
|---|---|---|
| user_data_scopes | sales/finance/client 中实际使用者 | user、scope、owner 或就业代次改变；无关 created_by 等不推进 |
| sales 四类头表 | sales | owner_employee_id 真实改变，普通新单、金额/状态更正不触发 |
| finance 收款/付款/费用/其它收入头表 | finance | maker_id 真实改变，普通新单、金额/状态更正不触发 |
| client_visibility_grants / clients | client | 有效共享的真实改变、owner 改变或资料读取资格变化 |
| employee_data_handovers / scopes | 对应 sales/finance/client | 已完成交接及有效 scope；执行中未完成关系不充当已授权事实 |
| employees / employment_history | sales/finance/client | 删除形态或 rehire 身份代次变化，普通人事信息更新不推进 |
| suppliers | supplier | 删除/内部车间读取资格变化；禁用状态或默认结算不取消六域报表 |

V936 为任务新增 access_stamp。原 V935 任务保持 NULL，不能回填今天权限冒充原提交权限；新 INSERT 必须有 64hex stamp。独立触发器禁止修改已有 stamp，不改 V935 的身份守卫函数。

## 发布、缓存与下载

根任务负责将该公共版本接入六域 DTO、元数据请求拦截和发布 advice。`metadataReuse=true` 必须携同一 readScopeVersion，未知或不匹配时保守获取完整元数据。序列化前再次 fresh 校验，不能在新受限 rows 上套旧宽范围 totals。旧客户端和明确 print/rowsOnly 的兼容状态分开记录。

同一长下载每次再授权都需 fresh scope，不能命中初次请求级缓存或一直使用初始宽 principal。持久任务在提交、执行检查点、下载分别比较提交 stamp；任务身份和原请求保留，条件/授权改变时明确新建任务，不暗中换新读取时点继续旧快照。

客户正缓存不能只靠角色 epoch：每次新页/详情引用仍应按批 lookup 取得当前证明，或先取得 fresh client scope 版本再复用；只合并在途请求。当前已核实视图与原始冻结显示可持有自己的名称，cache miss 不清 UUID/原文。供应商不被错误套上客户或采购单据 owner 规则。
