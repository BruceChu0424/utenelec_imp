# 仓库委外出仓工作台页

> **2026-09-14 ADR-085 / V581 单点例外——本页会出现「发子件」的出仓行**：
> 委外订货目标件的活动 BOM 恰好只有一个 PER_UNIT 投入的叶子子件时，公司不先自制目标件，
> 而是把**那颗子件**发给委外商，委外商加工后交回目标件。这类计划行 `flow_mode =
> COMPONENT_OUTBOUND`：货品/颜色/单位是**子件**，父件列仍是订货目标件，`bom_unit_qty`
> 冻结「每 1 个目标件订货单位消耗多少子件基本量」。仓库的操作与 `DIRECT_OUTBOUND`
> 完全同款(选实际叶仓、专属预留、审核出库)，差别只有一句：
> **数量与库存看的都是子件**——2026-09-21 起解锁点按
> [ADR-101](../99-决策记录-ADR/ADR-101-委外单一子层级按到货解锁与容差自动结案.md) 改成「有货才派活」：
> 子件还没到货时，这张单根本不会有可拣的草稿，任务上写的是「等子件到货」，不催仓库、不进红徽章；
> 子件一入库就自动出现一张按当时该仓合格可动用量截断的草稿，并通知仓库现在可发多少。
> 回厂登记、IQC 与实际入库针对的仍是目标件。
> **2026-09-22 起按 [ADR-103](../99-决策记录-ADR/ADR-103-委外两条路线同位锁定与单一子件按到货解锁.md) 补齐仓库侧**：
> 锁前移到委外下单前(任务中心/建单/送审/批准同锁，子件作业叶仓可动用 > 0 才能下单)，所以本页看到的这类计划
> 多数一开始就有货；子件被别人用光时任务列表以状态桶「等子件到货」表达，拣货页预填可发量并显示「建议发料仓」，
> 批量页按行放行；子件到货唤醒从采购 IQC 入库收口到 `StockService` 入库方向，任何入库路径都会补草稿并通知仓库。
> 与 V304 的 `LEGACY_BOM_COMPONENT` 历史行**不是同一回事**：新流向有专属预留与出仓
> 分配断言，历史行没有。见 [ADR-085](../99-决策记录-ADR/ADR-085-委外单一子件直接发料出仓.md)
> 与 [V581](../数据迁移/173-V581委外单一子件直接发料出仓.md)。

> **2026-09-12 加载与完成返回**：只加载需要的仓库字典，并与任务/草稿读取并行；批量读取最多四路，多实际仓草稿由单页转入批量页时复用已读资料，员工姓名后台补充且保留经办人 UUID。当前选中单据全成功后自动回 `/warehouse/tasks/outbound?section=subcontract&view=tasks`；部分失败/结果不明保留核对，确认已成功后同样退出。任务中心真正首次返回即刷新，父层已刷新时避免子页返回再拉一次。后端详情相同草稿量聚合由两次改为一次；权限、库存就绪、提交前指纹校验和访问审计保留。

> **2026-09-12 当前出仓核对规则**：新增 `PREPARED_OUTBOUND` 前端识别；列表支持多选/全选后进入批量详情，单张与批量共用可编辑表格，提交前再次确认。现行数量和交互以[出库任务中心页](出库任务中心页.md#批量办理与数量核对)为准。已有草稿从原 EC 载入数量和真实仓库，`readyOutboundQty=0` 不能解释为该草稿不能出仓；“本次最多”只加回本张草稿原数量。同计划多个实际仓草稿分别显示和执行，不能只取最后一张或合并实际仓身份。

> **2026-08-30 V436 / ADR-059 现行覆盖**：本页新流执行的是委外订货**目标件**出仓，
> 不再把 BOM 子件直接发给委外商。无活动子层级的
> `DIRECT_OUTBOUND` 行直接进入待出仓；有活动子层级的 `MAKE_THEN_OUTBOUND` 行必须先在
> [委外前置自制专页](委外专属工作台与页面权限.md#四前置自制专页)启动独立物料分析，完整完成 DRAW、生产、报工、FQC 和仓库
> 实收入库，且整条订货行数量进入专属预留后，才出现在仓库可执行队列。详见
> [迁移说明 66](../数据迁移/66-委外目标件出仓与前置自制准备.md) 与
> [ADR-059](../99-决策记录-ADR/ADR-059-委外目标件出仓与前置自制准备.md)。
>
> 当前权限已由 V328 拆分：列表/详情用 `subcontract_outbound:view`，生成/补齐草稿用
> `subcontract_outbound:execute`，关闭余量用 `subcontract_outbound:close`；计划生成的 EC
> 草稿在编辑/删除/审核/红冲时还要叠加对应 `subcontract_material_issue:*` 动作权限。
> 下文 V304 的“按 BOM 子件自动生成、冻结子件单耗、供应商处子件台账”只保留为
> `LEGACY_BOM_COMPONENT` 历史页面/旧单解释，不得用于新单验收。

> V304/ADR-042 保留历史迁移解释；新流以 V436/ADR-059 为准。
> 仓库专属的委外**目标件**出仓页面，与委外商业订货、历史执行列表**分立设计**；
> 全页无价格/金额/币种字段。目标件仍是公司自有存货，本次出仓是转为加工商处保管，不立采购或加工费应付。

## 入口与权限

- 仓库 hub → 任务中心「委外出仓」卡（角标 = 待出仓计划数，OPEN 且 计划量>已出仓）；
  **无 `subcontract_outbound:view` 时卡片与角标整组不显**。
  **角标口径(2026-09-22 ADR-103 复述)**：红角标 = `GET /warehouse/subcontract-outbound/tasks/count` 的 `count` =
  `countTasks` **有货口径**——OPEN 且有待出量的计划里，发现货的两种流向(`DIRECT_OUTBOUND` / `COMPONENT_OUTBOUND`)
  要么已挂未审草稿、要么此刻仓里还有合格可动用量才算「轮到仓库动手」；同一响应另带 `waitingComponent` =
  `countWaitingComponentTasks`(全部待出行都在等子件、无草稿的计划数)，两数按同一批行互斥，之和 = 列表里 OPEN 且有待出量的计划数。
  ADR-103 §四明确不给仓库侧登记黄色徽章链(服务端徽章目录不登记该黄数, 只画在出库任务中心分段上)，等料的单子由列表状态桶表达。
- 路由：`/warehouse/subcontract-outbound`（任务中心）、
  `/warehouse/subcontract-outbound/:planId`（拣货出仓页）；静态段先于 `/warehouse/:code`。
- 权限（V328/V437 现行口径）：
  `subcontract_outbound:view` 看任务中心/计划详情；`subcontract_outbound:execute`
  生成/补齐草稿并执行出仓；`subcontract_outbound:close` 关闭余量。计划生成的
  EC 编辑/删除/审核/红冲还叠加对应 `subcontract_material_issue:*` 动作；这些动作已精确列入
  `warehouse.subcontract-outbound` 权限设置 surface。已停用的 `subcontract_outbound:handle`
  不能代替任一现行权限。V437 零默认 grant，须由权限管理员按真实岗位授权；未授权深链同样 403。

## 出仓任务中心页

- 任务卡：委外订货单号、委外商、交货日期、出仓进度（目标量/已出仓/当前可出 + 目标件行数）、
  未审出仓草稿号（有则显示「出仓草稿待拣货」）。
- 搜索：订货单号 / 委外商（防抖，只让最新 GET 回写）；下拉刷新与分页。
- 任务来源：财务批准后服务端逐订货行决定准备路线；`DIRECT_OUTBOUND` 在目标件合格库存可预留时释放，
  `MAKE_THEN_OUTBOUND` 必须整行完成前置自制、FQC 与仓库实收入仓后释放。仓库页面不读 BOM、
  不推断 readiness，也看不到尚未释放的假任务。
- 「发子件」行的释放口径(2026-09-21，ADR-101)：**此刻可发数量大于 0 才算轮到仓库动手**，
  这时才带草稿、才发通知、才进红徽章。子件一件都没到时任务仍然在列表里看得见(计划量、已出、
  待出都照常显示)，但状态是中性的「等子件到货」，不计入红徽章，也不占任何人的待办。
  子件以后每到一批，系统都会再补一次草稿并发一条「现在可发多少」的通知，不需要仓库自己盯着。
- **状态桶三档(2026-09-22 ADR-103，`tasks()` 服务端算，白名单 fail-closed)**：

  | 桶 | 判据 | 列表显示 |
  |---|---|---|
  | `DRAFT_PICKING` | 有未审出仓草稿 | 「出仓草稿待拣货」 |
  | `READY_OUTBOUND` | 无草稿且 `issuableTotal > 0` | 「待出仓」 |
  | `WAITING_COMPONENT` | 无草稿、可发合计为 0 且 `waitingComponentLineCount > 0` | 「等子件到货」 |

  列表项 JSON 新字段 `issuableTotal`(可发合计，数值)与 `waitingComponentLineCount`(等子件到货的行数)；任务卡在出仓进度旁显示
  **可发合计**，此前对没货的计划显示「目标件已备齐，待出仓」而红角标又不数它，两边口径分叉，现已收口。
  列表 `status` 只接受这三个桶，其它值 400「出仓任务状态仅支持 DRAFT_PICKING、READY_OUTBOUND 或 WAITING_COMPONENT」。

## 拣货出仓页

- 表头：订货单号/委外商/计划状态只读；出仓日期（默认今天）、**发出仓（必选）**、
  经办人（默认当前登录人，默认部门 SUB_WH 子树）、交货日期、备注。
- 新流明细行：订货目标件编码/名称、颜色、单位、目标量、前置已完成量、当前可出量、已出仓量、
  本次出仓量和库位号提示；本次量默认取服务端给的草稿量——发现货的行(含「发子件」)这个数
  已经按开草稿那一刻仓里真正拿得出的量截过了，不是整笔计划余量；可改小用于分批出仓。
  2026-09-21 起无「实际重量」录入列(单位已表达重量，与全站口径一致)；原单 `weight` 原样回传。
- 发的是现货的行(含「发子件」行)另有两列，排在「本次最多」**前面**，好让仓库一眼看出上限是
  计划压住的还是仓里没货(ADR-101 §2.3)：
  - **仓内可动用**：这个仓、这个货品和颜色此刻真正拿得出来的合格可动用量，已经扣掉别人未审草稿占住的量；
  - **本次最多**：计划余量与仓内可动用两者取小；这一行已经有草稿时再把本张草稿自己占住的量加回来，
    所以改大本张草稿不会被自己顶回去。
- 分批发料是常态：子件陆续到货时，**直接把同一张草稿的数量改大就行，不必删了重建**。有多少先发多少，
  剩下的等下一批子件入库，系统会再提醒一次；不必等子件凑够整行数量才动手。
- **2026-09-22 ADR-103 §2.4 拣货页四处**：
  - 「本次出库」**预填 = 可发量**(`issuableQty`)，不再预填计划余量再被上限 0 压成红框；可发 0 的行显示
    「等子件到货(仓内可动用 0)」提示，不给填。
  - 明细表新增**「建议发料仓」**列(服务端 `stockWarehouseName`：已定发料仓就是它，未定则是当前可动用量最多的作业叶仓)；
    无草稿时表头「发出仓」下拉**预填** `stockWarehouseId`——ADR-101 §2.3 算了这个字段但界面此前从未显示。
  - **批量出库页按行放行**：从整单阻断改为可发 0 的行自动取消勾选并标「等子件到货」，其余行照常提交。
  - 「补齐出仓单」(`regenerateDraft`) 409 文案分三种原因：无余量「本计划已全部出仓, 没有待出的数量」/ 没货
    「子件还没到货, 仓里一件都没有; 子件入库后系统会自动补草稿并通知仓库」/ 已有草稿「各待出仓仓组均已有未审核草稿，无需补齐」。
    打开拣货页时它仍按此刻库存补草稿，作为唤醒漏网的兜底。
- 「发子件」行与历史 `LEGACY_BOM_COMPONENT` 行都显示父件列。「发子件」行的列名是
  **「回厂交回的委外件」**，带名称与编号——发出去的和收回来的不是同一个货号，拣货、点数、
  核对一律以本行的货品(子件)为准。历史行另显示历史 BOM 子件和冻结单耗；该显示不能用于新单判断。
- 操作：
  - 保存草稿（PUT `/api/subcontract/material-issues/{id}`，planItemId 逐行回传不断链）；
  - 审核出仓（确认弹明示三效果：目标件从专属预留真实出库并转加工商处保管 / 有子层级行已完成
    前置自制且本页不能绕过 / 回厂仍须登记与 IQC 放行）；
  - 「不再出仓」关闭计划余量（必填原因，留痕）；
  - 无草稿且有剩余量时自动经工作台「补齐出仓单」重建（红冲后补发等场景）。
- 出仓记录：该计划全部出仓单（单号/数量/仓库/审核人/状态）。

## 服务端联动（审核同事务）

1. 只消费该计划行、仓库、货品、颜色维度的 `SUBCONTRACT_OUTBOUND` 专属预留，形成真实出库流水；
2. V436 新流按目标件 `1:1` 写加工商处保管台账；`LEGACY_BOM_COMPONENT` 历史行继续按冻结 BOM 单耗解释；
3. 计划行 `issued_qty += 本次`（CAS 防超出 `readyOutboundQty` / 计划余量，并发冲突返回 409）；
4. 计划 OPEN 且剩余量 > 0 且无未审草稿 → 自动续生下一批出仓草稿；发现货的流向(含「发子件」)
   按当时仓里真正拿得出的量截断，一件都没有就这一轮不开草稿、等下一批到货再补(ADR-101 §2.2)。
   续开的草稿不再按整笔余量去占库存，所以不会再出现「刚审核的这一批被自己续开的下一张草稿顶回去」。

红冲：反向入库 + 计划 `issued_qty` 回减；有下游回厂消费/材料退/损耗的出仓单先红冲下游
（既有守卫）。订货红冲：软删未审草稿 + 计划 CANCELED。

## 与其它页面的分工

| 页面 | 归属 | 职责 |
|---|---|---|
| 本页（出仓任务中心 + 拣货） | 仓库 | 已释放目标件的预留、拣货、审核出仓、关闭与反向 |
| 预计到货任务中心 / 独立登记实际到货页 | 仓库 | 委外目标件加工回厂；通用 `/subcontract/receipts/new` 不再受理新回厂 |
| 委外订货单详情「全链路进度」 | 委外 | 只读跟踪出仓/回厂/IQC/应付，单号点进只读详情 |
| `/subcontract/preparations` | 计划/生产 | 有子层级目标件的物料分析、领料、生产、FQC、仓库实收待办 |
| 原物料分析供给进度 | 计划/销售 | 只有委外回厂 IQC PASS 才成为合格供给；前置自制入仓不能提前满足 |

## 页面状态、响应式与并发

- compact：保持可触达的任务表/卡与至少 48dp 操作区；核心数量与阻断原因不依赖悬停。
- expanded：高密度任务表；单击选择、双击打开，右键/长按菜单仍须按权限生成。
- 首次加载显示进度；空态说明“当前没有已释放目标件”，不能把无权限伪装成空数据；错误态提供重试。
- 搜索、筛选、分页使用请求序号，只允许最新响应回写。刷新期间禁止重复生成、保存、审核或关闭。
- 保存草稿、改仓/改量、关闭、审核和红冲均由服务端按版本、幂等键、专属预留与锁顺序重验；
  409 后必须刷新，不静默覆盖他人作业。
- 通知页与顶部通知栈只提醒“可出仓/已出仓”；通知关闭、已读或深链打开都不能替代真实任务状态。

## 发布边界

本页源码、空库迁移和定向测试不等于目标仓库可生产执行。V436/V437 目标非空库迁移、
`LEGACY_BOM_COMPONENT` 对账、真实仓库/计划/委外/品质账号权限 UAT、分批/红冲/并发实物演练、
恢复与发布回读完成前保持 **NO-GO**。用户已授权 V440 IQC 不合格退回/贷项闭环，仓库可从
`/procurement/iqc-rejections` 登记结构化实物退回；但源码候选不等于目标库已迁移或已部署，
V440 多岗位实物/金额脱敏/并发反向 UAT 与恢复发布回读完成前同样 NO-GO。
