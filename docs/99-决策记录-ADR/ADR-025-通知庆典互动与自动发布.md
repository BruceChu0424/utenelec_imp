## 背景

ADR-016 把通知接了真后端，但通知仍是**单向广播**：每用户只有「已读 / 从列表删除」两种状态，`NoticeType` 8 类没有任何按类型的互动。需求方（人事）希望通知按类型产生不同互动：

- **庆典类**（生日 / 入职周年 / 新婚 / 新生儿）：同事可「送上祝福」——点按钮出输入框，系统按类型自动套模板（如「{name}，祝你生日快乐！」），发送后聚合成「祝福墙」，被祝福者本人可见全部祝福。
- **公告广播类**（公告 / 制度 / 系统 / 紧急 / 福利）：阅读人可「点击收到」——回执计数，卡片 / 详情显示「X 人已收到」。
- 类型下拉框重新设计为分组选择器；发布庆典通知选对象后系统自动填充标题 / 事件标签 / 模板；另加每日定时任务自动为当天生日 / 入职周年员工发布全员祝福（可开关）；人事任务中心加快捷入口直达预填的发布页。

已与需求方确认范围：①自动发布 = 手动 + 每日调度器；②庆典类型 = 生日 / 周年（可自动）+ 新婚 / 新生儿（仅手动）。

## 决策

### 1. 互动模式按类型派生（`interaction_mode`）

- `notices.interaction_mode`（V224 新列，CHECK `none/acknowledge/bless`，回填历史）：
  - **bless** = `birthday / anniversary / wedding / newborn`（庆典，新增 4 类）
  - **acknowledge** = `announcement / policy / system / urgent / benefit`
  - **none** = `task / approval / workflow`（保留原 action routing）
- 前后端各有一份等价派生（后端 `NoticeService.interactionModeFor(type)`；前端 `NoticeType.interactionMode` getter），前端 `fromJson` 缺省时按 type 兜底派生。

### 2. 两条新互动记录（每用户、每通知）

- `notice_acknowledgments(notice_id, user_id, acked_at)` 复合主键——幂等 INSERT ON CONFLICT DO NOTHING；驱动「X 人已收到」。
- `notice_blessings(id, notice_id, user_id, sender_name, content, 审计列, UNIQUE(notice_id,user_id))`——一人一祝福，可改不可重复；驱动「祝福墙」。
- 庆典通知加列：`subject_employee_id`（被祝福者，FK employees ON DELETE SET NULL）、`subject_name` / `event_label`（快照，防改名回溯，同 publisher 范式）、`blessing_templates`（JSONB，发布者勾选提供给送祝福者的模板，NULL=系统默认）。
- **祝福模板只用 `{name}` 占位符**（前后端一致），送祝福时统一替换为 `subjectName`。`eventLabel` 单独承载「入职 5 周年」等带年数文案，与模板解耦。

### 3. 接口（`/api/notices`）

`POST /{id}/acknowledge`、`POST|DELETE /{id}/blessing`、`GET /{id}/blessings`、`GET /{id}/acknowledgers`、`GET /celebration/preview?employeeId=&type=`（发布页自动填充，**notice:publish**，birth_date PII 仅此可见）、`GET|PUT /celebration/settings`（超管 + 二次密码）。`NoticeDto` 末尾追加 10 字段（interactionMode / subjectName / eventLabel / ackCount / blessingCount / myAcked / myBlessing / recentAckers / recentBlessings / blessingTemplates）；列表逐条查计数对上限 500 可接受，none 模式短路零查询。

### 4. 自动发布调度器（`CelebrationScheduler`）

镜像 `DeliveryDueWarningScheduler`：`@Scheduled(cron="7 0 8 * * *", zone="Asia/Shanghai")` 每日 08:00:07。读 `system_settings`（`celebration.auto_enabled / auto_types / publisher_name`，V224 种子）。birthday 按 `birth_date` 月日、anniversary 按 `hire_date` 月日且满 1 年匹配在职员工；按 `(subject_employee_id, type, 当年)` 精确去重（用新列，比标题模糊匹配可靠）；命中调系统直发 `publishCelebrationBroadcast`（**旁路 notice:publish**，类比 `publishForUser`）。birth_date 是 PII，仅服务端读，通知只露「生日快乐 + 姓名」不暴露日期；全程 try/catch 静默。

### 5. 前端

- 新模型字段 + `NoticeInteractionMode` 枚举 + `NoticeBlessing` / `NoticeCelebrationPreview` / `NoticeCelebrationSettings`。
- **发布页**：`NoticeTypePicker`（分组：公告广播 / 庆典祝福；瓦片 = 图标 + 色 + 描述；底部抽屉）替换下拉框；选庆典类型 → `UtenEmployeePicker` 选对象 → `previewCelebration` 自动填标题 / 模板策展 chips；`presetType` 经路由 `?type=` 由人事任务中心透传。
- **列表卡片** `NoticeInteractionFooter`：ack「X 人已收到 + 收到 / 已收到」、bless「X 条祝福 + 送上祝福」；庆典卡用类型色强调条。
- **详情页** `NoticeInteractionSection`：ack「点击收到」+ 近期收到人；bless composer（模板 chips + 输入 + 发送）+ 近期祝福 +「查看全部」祝福墙。
- **到达分派**：庆典通知走暖色 `UtenNotify.banner`（节庆图标 + 对象名标题）。
- **人事任务中心** `HrWorkbenchPage._quickNotice`：发通知 / 生日 / 周年 / 新婚 / 新生儿 5 瓦片，`hasPerm(notice:publish)` 显隐（fail-closed，该页仅 employee:view 守卫），`context.push('/notice/publish?type=...')`。
- i18n 三语（zh / en / ko）全覆盖。

## 验证

- 后端 `mvn test-compile` 通过；`NoticeServiceTest` 覆盖 acknowledge 幂等、bless upsert / 撤回、庆典发布（subject 必填 + eventLabel 派生）、错误模式拒绝。
- 前端 `flutter analyze`（notice + hr_task 域）0 新增；`notice_interaction_repository_test.dart` 13 测全过（类型派生 / fromJson / publish 透传 / acknowledge / bless / withdraw / preview / 祝福墙）。
- runtime E2E（须重启后端 + 重建前端）：HR 任务中心点「生日」→ 发布页预填 → 选对象自动出模板 → 发布 → 全员暖色横幅 → 同事「送上祝福」选模板发送 → 详情祝福墙；公告「点击收到」→「N 人已收到」；调度器开关 / 触发验证。

## 影响与后续

- **PII**：birth_date 仅 `notice:publish` / 系统可见；调度器以系统身份读，前端永不接触生日日期。
- **祝福墙可见性**：v1 所有可见该通知者都能看祝福墙 + 送祝福（含被祝福者本人）；如需「仅被祝福者见全部 / 他人只见计数」可后加 `isSubject` 派生（NoticeDto 已可扩展）。
- **推送通道**：庆典通知的接收端到达提醒仍依赖本端动作触发；全员实时推送需 WebSocket/FCM（落点已就绪，同 ADR-016）。
- **curated 模板**：发布者勾选的 `blessingTemplates` 已透传到送祝福者 composer（空则系统默认）。
