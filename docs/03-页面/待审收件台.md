# 待审收件台（我的待审）

> 路由 `/reviews/inbox` · 权限 `review_inbox:view`（人事行政·通知，零默认 grant，按部门矩阵/个人覆盖显式授予）
> 新增于 2026-09-02（V459 / [ADR-063](../99-决策记录-ADR/ADR-063-部门定向审核待办弹窗与通知办结撤回.md)）——独立新页，不与其他页面共用。

## 一、定位

- 解决的问题：跨业务域的待审事项没有统一入口——审核弹卡（顶部非阻塞卡）错过后只能翻通知中心。
  本页是「弹卡的稳定落点」：按职责域汇总我的待审数量，一键直达各域任务中心/审核页。
- 定向口径（与弹卡一致）：**section 可见性 = (主部门 ∈ 部门子树 OR 兼职部门 ∈ 部门子树) AND 持有职责权限码**，
  双条件缺一不可——「只有部门」或「只有权限」都不出现。
- 计数口径：当前用户名下**未办结**的待审通知数（notices 维度）——审核完成的办结撤回
  （`resolved_at`）自动联动归零；只计真实待办（草稿/已办结不计，遵守徽章红线）。
  权威池数据（共享队列全量、认领状态）在各域任务中心，本页不复制业务 count 口径。

## 二、入口与导航

1. 工作台「常用功能」组「待审收件台」卡片（显隐=路由守卫同源 `permission_by_path`）。
2. 居中审核弹窗与顶部条的聚合补充入口（弹窗 20s/关闭后，待办仍在收件台）。
3. 深链/手输 URL 同样受路由守卫拦截（无码 → `/access-denied`）。

> 待办的三个提醒入口（2026-09-02 第二轮口径）：**每次登录**检查未办结待审并弹
> [居中审核弹窗](../02-组件库/ReviewPendingDialog.md)（登录后 3s，`ReviewPendingLoginGate`）；
> 在线新到达弹顶部条+居中弹窗；收件台常驻汇总。

## 三、响应式布局

`UtenContentContainer` + ListView：头部说明卡（职责域口径一句话）+ 分域 section 卡列表。

```
│ ⓘ 汇总你所在职责域（部门主职或兼职 × 职责权限）的待审事项… │  ← IntroCard（浅容器色）
│ [📇] 销售订单待财务确认        [3] › │  ← section 卡：圆底图标+标题+副标题+计数徽章
│ [✅] 采购/委外订货待财务审批   当前无待办 › │  ← count=0：灰图标+「当前无待办」
│ [🧪] 到货 IQC 待检处置          [1] › │
│ [🚚] 订单全部完工可发货         [2] › │  ← 归属人线：有未办结通知才显示
```

- 计数徽章：**固定高度 24、宽度随数字变化**（99+ 封顶），0 不渲染（不挂虚假徽章）。
- 下拉刷新（RefreshIndicator → invalidate summary provider）。

## 四、涉及的 Uten 组件

`UtenAppBar`、`UtenContentContainer`、`UtenCard`、`UtenEmpty`（空态：无职责域时
task_alt 图标提示）。

## 五、功能点

1. **summary 拉取**：`GET /api/reviews/inbox/summary`（后端 `ReviewInboxService`）返回
   `{sections: [{key, title, pendingCount, route}]}`。key = 通知 source_event（与
   `ReviewNoticeCatalog` 注册项一一对应）。
2. **section 资格过滤（服务端）**：
   - 销售订单待财务确认 = `SalesOrderFinanceConfirmerEligibility.isEligible`（DEPT_FIN 子树∪兼职∪点名加授 + `sales_order_finance:confirm`）；
   - 采购/委外订货待财务审批 = `WorkflowReviewerEligibility.findEligible`（同型，`finance_order_approval:review`）；
   - 到货 IQC 待检 = DEPT_QA 子树（主/兼职）AND 有效权限含 `procurement_inspection:handle`；
   - 订单全部完工可发货 = 归属人线（有未办结通知才显示，无资格判定）。
3. **点击直达**：section 卡 `context.go(route)`——财务确认直达任务中心、IQC 直达品质任务中心、
   可发货直达订单详情；各域权威数据与认领状态在目标页。
4. **计数 SQL**：单表（notices LEFT JOIN notice_user_states，audience=me、四事件 IN、
   resolved NULL、snoozed 到期）GROUP BY source_event；`idx_notices_pending_aggregate` 等
   索引保障数据量增长下的响应。

## 六、权限要求

| 项 | 值 |
|---|---|
| 路由守卫 | `review_inbox:view`（`permission_by_path` 注册；工作台卡片显隐同源） |
| 后端 | `GET /api/reviews/inbox/summary` `@PreAuthorize("hasAuthority('review_inbox:view')")` |
| 权限面 | `reviews.inbox`（surface 目录 111 个之一）；按设计无页面内委派入口 |
| 部署注意 | 零默认 grant——上线后需按部门矩阵或个人覆盖显式授予，否则全員不可见（超管除外） |

## 七、边界情况

- 无任何职责域：空态「当前没有指派给你的待审职责域」（不算错误）。
- summary 接口失败：错误态 + 重试。
- 超管：IQC section 恒可见（资格判定对超管直通）；其余按 Eligibility 常规判定。
- snooze 未到期的待审不计入计数（稍后再看期间不重复提醒）。
