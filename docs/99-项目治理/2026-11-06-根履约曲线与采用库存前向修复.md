# 根履约曲线与采用库存前向修复

审查基线 `f52897025d370ef3277aeeed0671eec1421deaff`。V1108 把 `fn_root_fulfilled_source_qty` 单独改为根产出加同销售来源库存采用，覆盖了 V1054/V1056 已有的 BOM 组件交付分支；`fn_root_fulfilled_source_qty_with_delta` 则仍是旧曲线。非空 BOM 履约来源因此被漏算，普通根采用库存后的新产出信用也可能变成负数，直接触发原 `qty_source>=0` 约束。

新增真实前向 V1111，不修改 V1108 或任何已存 SQL、Flyway 历史和来源事实。`fn_root_fulfilled_source_qty_with_delta` 成为唯一曲线，普通读取入口只委托它传入零增量：

- BOM 保留原组件交付事件的订单数量权威；成品根产出、库存采用及其 base 增量不能代替组件交付证明。
- 普通根采用原根产出净 base、同销售来源已采用 base 与本次 delta，保留原单位换算、四位截取和当前剩余数量上限。
- 原 `fn_capture_root_output_source_credit` 和反审预览自动使用同一曲线差额；旧 `qty_source`、原事件、采用账及库存预留不回写，不给旧事实补造信用。

适用调用方均沿公共入口同步：根产出投影及延迟一致性校验、BOM 交付投影、已采用库存来源刷新、产出信用捕获，以及 `MaterialAnalysisRootSupplyService.requireReceiptReversible`。Web、Flutter 和已实现 WPF 调用仍使用同一后端权威；未迁移业务不因此标为完成。

独立真实 PostgreSQL 16 回归 `RootFulfillmentSharedCurvePostgresTest` 加载原 V1056 捕获触发器、V478 投影/延迟约束和 V1108 来源函数，填入非空 BOM、原产出及库存采用账。它验证共享 SQL 曲线和来源生命周期，不代替完整业务环境或公司真实副本升级。
