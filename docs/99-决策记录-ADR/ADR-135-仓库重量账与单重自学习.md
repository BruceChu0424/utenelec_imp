## 一、背景

用户 2026-09-28 原话(整理)：

> 以前仓库按自己的单位和数量执行出库入库，这个继续保留；专门做一个重量的，常用单位放上去、自动换算。仓库说螺丝这类东西计划讲的是个数，但他们习惯称重来算，一个一个点太累。这个值是给仓库自己用的，计划那边之前咋样还是咋样。出库入库在原本基础上，数量列后面加个重量列；即时库存那里也要加上统计；每次自动计算，包括单位统一(库存写的是吨，出库用的千克也能自动换算)；每个物料详情页都要有详细的出入库历史记录。
>
> 这个只是用在仓库。做个自学习，用这个系统时间长了，大概就能估算重量对应的数量；产品 BOM 里一个产品就是固定这么多螺丝(可能有点损耗)，但不同供应商重量会不一样，你多思考、多调查，让系统越来越优秀。
>
> 仓库这边你自己多思考，有什么算法可以用在仓库，让仓库更智能，数据统计啥的，可以多改造。

改造前的事实(2026-09-28 代码与克隆库核对)：

1. 库存流水 `stock_movements.weight`(V435)与余额 `stock_balances.weight`(V80)已存在，但**没有任何单位**：余额把不同单位的数字直接相加；V442 加的 `actual_weight_unit_id` 等四个单位列没有任何写入路径，永远为空。
2. 未称重的出库不减余额重量，余额重量会越来越虚高；数量归零后重量残留；称重出库比账面重一点就被「目标仓库存重量不足」拦住，称重误差会卡住正常出库。
3. 盘点只管数量，重量无法盘点、无法校正；一旦余额重量未知，几乎永远未知。
4. 即时库存与货品详情把未知重量显示成 0。
5. V442 的「计量学习」学的是「这个货品习惯填不填重量」，不是单重；证据记录器没有任何调用方，客户端接口常量无人使用，全平台整改审计已判为死代码。
6. 仓库执行页面里只有其它出入库编辑页有一个无单位的「实际重量」列，到货登记、领料出库、销售出库、委外出库、退料、盘点都不能录重量。

## 二、同行做法(调研)

按「不熟的业务逻辑先查同行」的约定，调研了 SAP、Microsoft Dynamics 365、金蝶云星空、用友 U8/NC、Odoo 的公开资料，以及计数秤厂商(梅特勒-托利多、赛多利斯)和统计方法文献(链接见文末参考)。

| 系统 | 第二计量(重量)怎么存 | 未称重出库 | 尾差 | 单位换算 |
|---|---|---|---|---|
| SAP S/4HANA + EWM(称重物料 CWM) | 数量与平行单位(kg)两套独立库存；不启用全量 CWM 时平行库存只在 EWM(仓库)里 | 取来源库存均重(10 件共 11.4 kg，发 5 件记 5.7 kg) | `/CWM/STOCK_CHECK` 找「一个单位为零另一个不为零」并生成盘点凭证 | 同一维度内固定换算；容差组校验计划换算系数 ± 百分比 |
| Microsoft Dynamics 365 称重物料 | 交易按件，重量是库存单位 | 按实物库存平均重量 | 出入称重差额自动记「称重损失/收益」 | 名义重量 + 每件上下限 × 数量校验 |
| 金蝶云星空 | 辅助单位 + 浮动换算，辅助数量逐单录 | 社区做法按余额比例带出 | 常见「基本数量为零辅助数量不为零」结账报错，靠盘点单消除 | 同组固定换算，跨组浮动 |
| 用友 U8 / NC | 主辅计量，件数与数量两列 | 浮动换算率按余额带出件数(官方补丁修复过此行为) | 知识库多见「主数量为零辅数量还有」 | 固定/浮动换算率 |
| Odoo | 单位类别(重量类以 kg 为参考单位)，产品重量单独精度 | - | - | 类别内固定系数；官方论坛提醒 2 位小数的 kg 会把克舍成 0 |

计数秤与统计：

- 称重计数 = 抽样若干个算平均单重(APW)，再用净重 ÷ APW。误差主要来自抽样数错和单件重量离散(常见 0.5%-1.5%，注塑件更大)；抽样至少 10 个，最好 20-30 个；单重会随供应商、批次、电镀/油污/含水变化而「过时」，要按批复核；毛重 − 皮重 = 净重。
- 从(数量, 重量)观测学单重：比值估计 / 过原点加权最小二乘；中位数与 MAD 的稳健离群剔除；指数衰减应对漂移；供应商级估计向货品级做部分汇聚(经验贝叶斯)；CUSUM 检测换料/换批；对新一批货，批间差异构成下限，历史再多也只能收窄均值，要突破下限只能现场抽样与历史融合。
- 生产领料的数量来自计划(BOM × 产量)，带超领/损耗偏差，是「偏差」而不是「噪声」，不能直接当单重证据；反过来可以用学到的单重测出实发比应发多了多少。

共识(本 ADR 照做的部分)：

1. **数量主导，重量是并行事实**：计划、成本、预留、履约只认数量；重量是仓库自己的第二本账(与 SAP 不启用全量 CWM 时「平行库存只在 EWM」一致)。
2. **重量逐笔记在流水上，并有自己的余额**；不从主档换算系数反推历史。
3. **未称重出库取库存均重**；清空时把剩余重量全部带走；残差由系统自动记一笔有原因的「尾差调整」。
4. **重量永远不拦数量过账**，只提示。
5. **重量类单位用固定系数换到一个参考单位(kg)**；只有「个 ↔ 重量」是浮动的，靠学习。
6. **单重按供应商/批次学习，抽样优先**；领料只用于测偏差。

## 三、决策

### 3.1 业务口径

- 数量(`qty + unit + unit_rate` → 基本数量)仍是唯一的计划/成本/预留事实；采购、销售、委外、生产、财务页面与逻辑不加新的重量输入，已有的隐藏或历史重量字段不动，财务报表不动。
- 仓库执行页面凡是库管录入或确认数量的明细行，都在「数量组」(数量后紧跟单位时即单位)之后加一列重量。
- 重量单位是固定六种：克、千克、吨、斤、磅、盎司；存储一律千克。单据行重量 NUMERIC(18,4) 千克(0.1 克)，流水与余额同为 NUMERIC(18,4)，观测与单重用更高精度。
- 基本单位本身就是重量单位的货品(颗粒按 kg、铜材按吨)：重量 = 数量 × 固定系数(「精确」)，重量格只读显示「= 25 kg」，不学习。
- 估算值一律带「≈」；未知显示「未称」，永远不显示成 0。
- 学到的单重不回写货品主档的「单重」(`goods.m_weight`，设计单重)，避免单一事实源回写环。

### 3.2 重量账规则

每笔流水按以下顺序确定重量(第一条命中即用)：

1. **精确**：货品基本单位(或行单位)是重量单位 → 数量 × 系数。
2. **调拨对应**：调入腿直接取调出腿的重量与来源。
3. **红冲镜像**：同一(来源单类型, 单号, 行, 流水类型, 仓, 货, 色)上已有反方向流水 → 按未冲部分比例镜像原重量(最后一次冲销全部带走)。调用方红冲一律不传重量。
4. **实称 / 分摊**：仓库录入的实称重量，或同一次实称按数量分摊的切片(IQC 分批放行、产成品分批点收)。
5. **出库未称**：库存均重 × 数量(清空时带走全部余额重量)；余额重量未知时用学到的单重估算。
6. **入库未称**：单重可靠(绿/黄)时按单重估算，否则按库存均重，再否则按任意单重估算；都没有则未知。

余额按绝对值写入(与数量同一条语句)：从零起算、未知转已知时写「重量起算」；数量归零而重量不为零、或称重出库后剩余重量 ≤ 0 时写「重量尾差调整」；盘点录了实盘重量时写「盘点定重」；有权限的人可以单独「核重」(只改重量)。所有重量变化都能在流水或调整行上找到前后值，并由对账视图逐维度校验「上一行之后 = 下一行之前、最后一行 = 余额」。

### 3.3 单重自学习

- **观测**只来自「独立数量 + 实称重量」：称样(抽样计数)、盘点、到货登记(供应商来货数)、产成品登记、其它入库为「参考证据」，参与学习；领料、委外发料、销售出库、生产退料、其它出库、调拨为「核对证据」，不参与单重均值，只用来测偏差(领料实发比应发多了多少、退料登记数对不对)。按称重推算出来的数量(称重计数「填入数量」)、重量单位本身就是数量的行、与界面给出的「应重」完全一致的重量(疑似照抄)，都不作为证据。
- **算法**(确定性、纯 Java，与 Python 参考实现逐条对拍)：
  1. 每条观测取对数单重 y = ln(重量 / 数量)，方差 = 单件离散²/数量 + 来源计数误差² + 秤分辨率项。
  2. 按供应商分组，先用截断的 CUSUM 找「换批/换料」切换点(切换前的旧数据不再参与，但保留可查)。
  3. 在当前批次内按组做加权中位数 + MAD 稳健剔除离群(并提示可能的 ×1000 / 斤公斤 / 磅公斤录错)。
  4. 用 DerSimonian-Laird 估计批间差异，加权求货品级与各供应商单重；供应商估计向货品级做部分汇聚(样本少的供应商更多参考总体)。
  5. 学生 t 分位给出 95% 区间：半宽 ≤ 1% 为「可靠」(绿)，≤ 5% 为「可参考」(黄)，否则「未学准」(红)；少于 3 条且没有 ≥10 个的称样一律红。
  6. 只有领料数据的货品：按过往领料推算单重，最多「可参考」且需 ≥10 次领料，界面注明「按过往领料推算」——这是用户提出的「BOM 固定个数」思路的落地，同时承认领料含超领偏差。
  7. 预测：称重计数给出件数与 95% 区间，并可与现场抽样融合(这是突破批间差异下限的唯一办法)；给出「超过 N 个时称重计数只是估算」；入库/出库给出应重与偏差，超过容差且统计显著才提示(黄/红)。
- **人工所有权**：人工设定单重优先于学习值(仍按批间差异算可靠度，并提示与学习值的差异)；可排除/恢复单条观测；可「从今天起重新学习」；批次切换可设为自动或手动。
- **计算时机**：过账事务只追加观测并发出业务事件；事件处理器在提交后按货品加锁重算；每晚再兜底刷新一次。称样接口同步重算，库管立刻看到新单重。

### 3.4 页面

- 到货登记(单张/批量)、产成品登记(单张/批量)、其它出入库/调拨、盘点(账面重量 + 实盘重量)、领料出库(单张/批量/新发现物料)、销售出库、委外出库、生产退料接收：数量组后加「实称重量(kg)」列。表头工具条切换录入单位，单元格可直接输入「850g / 1.2t / 3斤 / 2lb」；空着 = 没称；单重可靠时显示「约 12.5」「应称 12.5」并在偏差时变色提示(按件说：「偏少约 238 个(-4.8%)」)。重量格与数量格永远不做勾选行批量生效。
- 称重计数对话框：毛重(可多次称重累加)− 皮重 × 件数 = 净重；可顺手抽样；显示件数与区间和可靠度；到货登记默认「只记重量」，「按称重改数量」需确认(影响对账)；盘点/其它入库默认填入数量；出库为反向模式(需要 N 个 → 秤上应显示约多少)。
- 称样校准对话框：数个数、称重量，实时对比当前单重，差异大时询问是否作为新批次。
- 即时库存：重量列移到库存数量后面，页面级显示单位(自动/克/千克/吨/斤/磅/盎司)，合计重量由服务端算并注明未称项数；导出固定一个单位并在表头写明。
- 货品详情新增「库存与出入库」页签，与库存详情页共用一个面板：余额(数量 + 重量 + 估算标记 + 核重)、出入库流水(存货明细账式：收入/发出/结存数量与重量、单号可跳转、往来方按单据权限脱敏、期初/本期/期末汇总)、单重学习(当前单重、供应商对比、观测记录、称样与设置)，顶部是该货品的库存分析指标条。
- 新页面「库存分析」(仓库中心 → 库存查询)：呆滞与库龄(FIFO 库龄分段、最后入/出库、呆滞天数、90 天日均消耗、可用天数、ABC)、盘点建议(A/B/C 30/90/180 天周期 + 重量尾差/估算/未知/单重未学准加权，勾选后按仓库打开预填的盘点单)、称重异常(来料少数、领料超发、退料不符、盘点差异、单重可能已变化，可按供应商/车间汇总)、单重学习(上线初期批量称样录入、需称样清单、与主档设计单重不一致清单)。独立的「称重计数」页便于在秤旁用手机操作。

### 3.5 权限

- 新增 `stock:weight:manage`(称重设置与单重学习管理)：设定人工单重、默认皮重、容差、单件离散、学习开关、批次切换方式，排除/恢复观测，重新学习，核重；默认授予持有 `stock_doc:edit` 的部门(仓储部)。
- 称样：`warehouse_inbound:stock_in` / `stock_doc:edit` / `stock:weight:manage` 任一即可。
- 库存分析页与接口：`stock_report:view`(与仓库报表同级；供应商短重排名属于报表级数据)。货品级指标条随 `stock:view`，不显示供应商级数字。
- 出入库流水的往来方名称按来源单据的查看权限脱敏；金额沿用成本脱敏。

### 3.6 2026-09-30 补充：重量预填、表格提示与称重操作

- **按来源预填**：出库优先按所选仓库、货品、颜色的库存基本数量与重量比例预填；例如库存 1,000 个 / 20 kg，本次 500 个预填约 10 kg。入库优先可靠历史/人工单重，其次同维度库存均重。没有有效依据保持空白；不混用不同仓库、颜色或未知单位换算率。库存权威键没有批次/归属维度时，不把仓库均重描述成某一批实称。
- **预填与实称分开**：格内显示 `≈` 和预估说明；未人工接管的值随数量、来源参数变化，人工改过或主动清空后不覆盖。预填不写入单据实称字段、不成为学习样本；真正过账仍由服务端在锁内按最新余额决定估算重量和来源。草稿保存人工输入状态，不固化旧预估值；换仓/颜色后重新取参，旧请求不得覆盖新来源。
- **黄色提醒**：对应库存参考下，实称偏差超过配置容差与 5% 中较大者（库存重量本身为估算时至少 15%），且超过两个秤分辨率，显示黄色边框和“数值可能有问题”，说明预计/实称及核对数量、重量单位、包装。历史学习仍沿用统计显著性门槛。正常偏差不阻止业务，非法格式仍须修正。
- **统一表头说明**：表格固定字段说明/提示图标只在表头；单元格保留行级信息的悬停说明、无障碍描述与必要的警告文字，不重复放说明图标。称重按钮是操作入口，仍可使用。
- **按场景简化弹窗**：出库显示“出库称重核对”，先展示本次数量与预计净重，再填实际秤上读数；不把预计重量预填成实际读数。包装扣重、分次称重、抽样、数量范围按需展开。入库/盘点称重算数量时，抽样用“数了多少 / 这些有多重”，历史不足时展开引导。每批读数有非法内容时不能悄悄忽略该批。

## 五、明确不做

- 不在计划、采购、销售、委外、生产编辑页加重量；销售批量发货面板原有的「实际重量」保持原样但不再进入库存重量账。
- 不自动改数量(按称重改数量必须人点)；不因偏差拦截过账；不给采购推通知(先在库存分析里看)。
- 不把学到的单重写回货品主档；不做按仓库/按货品的显示单位；不接秤硬件(输入统一走一个组件，将来加「读秤」按钮只改一处)。
- 不改财务报表口径(另议)；`stock_monthly_mv` 清理另立任务。
