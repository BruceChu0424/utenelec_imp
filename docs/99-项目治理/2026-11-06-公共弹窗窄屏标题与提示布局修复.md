# 公共弹窗窄屏标题与提示布局修复（2026-11-06）

原 `platform_scale_surfaces_test` 在 320 物理宽度、200% 显示缩放下进入导出密码设置，真实复现 8px RenderFlex 溢出。诊断定位到 `UtenDialogHeader` 将标题与关闭控件固定并排，标题中的 `UtenDialogTitleWithHint` 仅剩 48 逻辑像素，无法同时容纳可访问提示控件、间距及文字。原测试的密码确认、取消与无溢出断言保留，未缩小字体、命中区或放宽画布。

按 frontend-design 继续使用 Uten 组件及主题，唯一修改入口为 `uten_dialog_chrome.dart` 的公共 Header。布局先测量真实操作组，保留一个文字字形及标题实际提示控件需要的最小空间；空间不足时把操作组放到标题上方靠末端的位置，标题与其提示仍在同排。普通无提示标题只保留文字所需空间，避免短高窗口的打印正文被额外挤走。宽窄、LTR/RTL 变化只改变布局，标题、提示和操作的 Element 保持，不重建输入或业务 owner。

公共 Header 的既有调用方自动采用该唯一实现；关闭、防重复、busy 禁止关闭及显式窗口控件替代默认关闭的语义保留。无新增副标题或独立提示句。Web 与 Flutter 桌面共用本入口；WPF 使用独立原生窗口布局，不含本次 Flutter RenderFlex 路径，候选/完整 ERP/Win7 目标机状态不变。

原生两个完整文件及真实 Chrome 相同两个完整文件均 30/30 通过，严格分析 0，Dart format 通过。包含两个新增 LTR/RTL 反复窄宽切换用例，逐次验证同一提示 Element、可点击提示、可达关闭及最终只执行一次关闭；既有测试还覆盖密码不一致不导出、取消、busy、窗口控件、160 画布和 200% 的长文本、打印与短高窗口。日志在 `D:/Projects/uten_imp_worktrees/ci-callers-current-20261106/build/ci-callers-current-20261106/` 的 `header-only-final-{native,chrome}.log` 与 `header-only-final-v2-analysis.log`。

原始渲染诊断、首版 parent-data 编译错误，以及首版过度预留空间造成短高打印回归的失败日志全部保留；最终按实际是否存在标题提示修正空间合同，不改失败预期。本地证据不等于新 Main 远端完整 CI 已绿，也不触发或重建任何冻结版本发布。
