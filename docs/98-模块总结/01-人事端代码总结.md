# 人事端代码总结

> 当前基线：2026-07-30
> 本文描述当前工作树，不保留早期“仅 HR 是真实后端、其余全是 Mock”的历史口径。

## 一、模块边界

人事端已使用 Flutter + Riverpod + Dio 调用 Spring Boot/PostgreSQL 真实后端，覆盖：

- 员工列表、详情、入职、编辑、调岗、转正、离职、复职和删除保护；
- 部门树、岗位模板和岗位联动；
- 员工证书、学历、合同、紧急联系人和任职历史；
- 个人信息修改申请、HR 审批和申请人定向通知；
- 账号状态展示，以及账号锁定、启用、停用和临时密码重置入口；
- 按权限点控制的 PII、银行卡和薪酬脱敏。

员工前端使用 `DioEmployeeRepository`。旧 `MockEmployeeRepository`、旧 employee model 和旧
Provider 已删除，禁止恢复 Mock/真实双轨。工资条与员工报销是独立领域，状态见
[生产就绪审计报告](../99-项目治理/2026-07-30-生产就绪审计报告.md)，不能用人事模块完成来替代其验收。

## 二、入职与账号安全

`POST /api/org/employees` 由 `employee:create` 保护，在同一服务端事务中创建员工资料、任职资料和
登录账号，返回：

```json
{
  "employee": {},
  "temporaryPassword": "仅本次响应可见"
}
```

- 账号默认使用工号；系统不开放自助注册。
- 身份证后六位默认密码已经废止。
- 入职与账号重置复用 `TemporaryPasswordGenerator`：`SecureRandom` 生成 20 位高熵密码，
  至少包含大写、小写、数字和符号。
- 服务端只持久化 Argon2id 哈希，并设置首登强制改密；临时密码不得进入数据库、日志或审计正文。
- Flutter 用不可点遮罩关闭、不可返回键误关的一次性弹窗显示和复制凭据；关闭后不缓存。
- 若交付丢失，只能重新执行受 `account:support` 保护且有审计的密码重置，不能再次读取原密码。

具体交互见[入职流程页](../03-页面/入职流程页.md)。

## 三、认证与权限

- access JWT 源码默认 15 分钟，refresh token 默认 7 天并轮换、哈希入库和检测重用。
- 令牌仅存 `flutter_secure_storage`；认证使用 `Authorization: Bearer`，不是 Cookie 会话。
- `JwtAuthFilter` 每次 staff 请求用一次轻量数据库投影复查账号状态、强制改密状态、超管状态，
  以及 V135 `auth_version`/全局授权 `epoch`。账号停用、锁定或授权版本不匹配立即 401。
- 有效权限以服务端为准：基础权限、员工所在部门及祖先部门配置、个人 grant，再减个人 revoke。
  前端路由和按钮守卫只改善体验，不构成安全边界。
- PII 和薪酬访问分别由 `employee:pii:view`、`employee:compensation:view` 等权限点控制，
  不再按前端角色名猜测。

V135 仍须在真实 PostgreSQL 应用并完成个人覆盖、角色、部门树移动/软删、员工换部门、共享权限及
超管变化的旧 token 失效测试；源码存在不等于生产验收完成。

## 四、敏感数据与一致性

- 身份证、手机、银行卡和薪酬等字段用 pgcrypto 加密；身份证另存 HMAC 以支持唯一性检查。
- 主密钥来自部署环境/Vault，不写源码、SQL 或 Git；缺少关键密钥时应启动失败。
- 工号、证件和账号唯一性必须由数据库约束兜底，不能只靠前端预查。
- 员工写路径使用版本字段防丢更新；调岗、离职、复职和审批必须由服务端状态机执行。
- 离职会停用关联账号、吊销会话并处理在途申请；V135 再保证授权快照变化可拒绝旧 access。
- 请求审计覆盖进入应用的 `GET/POST/PUT/PATCH/DELETE/HEAD /api/**`，包括匿名认证、401、CORS 非法
  来源 403、404/405 与 MVC 前异常，并且不记录 query 值或 body；有效 JWT 的请求级快照保留操作人，
  无效令牌不绑定身份。安全事件另由显式审计补语义，V169 为公开业务表（含关键人事表）补齐脱敏
  before/after 触发器；数据库变化与业务事务共享 TxSessionVars 和 Request ID。仍需持续维护覆盖矩阵与故障演练。

## 五、前端实现约束

- 页面只依赖 Repository 抽象；真实实现通过 `apiClientProvider` 注入。
- 员工、部门、岗位和状态展示复用公共组件与枚举映射，不在页面重复拼权限或状态字符串。
- API 401 由单飞 refresh 处理；refresh 失败或账号/授权版本失效时统一清会话并回登录。
- 临时密码、身份证、银行卡和完整薪酬不得写前端日志、Provider 持久化或
  `shared_preferences`。

6. Flutter 手机/平板/桌面关键流程 E2E。
