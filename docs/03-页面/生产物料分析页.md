## 一、员工看到的主流程

```text
已审核销售订单行 / 合法手工需求
  → 选择本次要分析的产品与数量
  → 选择一个目标仓并点「联合分析所选产品」
  → 完整 BOM 已加载；无直接 BOM 的当前层显示“无下层物料，可直接自制”
  → 有 BOM 时按父件实际短缺与路线激活下一层：BUY 停止、MAKE 展开、供料委外展开
  → 计划员逐路径节点确认 BUY / SUBCONTRACT / MAKE 并处理真实缺口
      ├─ BUY → 提交采购需求
      ├─ SUBCONTRACT → 提交委外需求；有供料 BOM 时继续备齐我方供料
      └─ MAKE → 下层实际齐套后创建 MAKE_COMPONENT 并安排生产
  → MAKE 只检查自己的直接子件；子件齐套后独立建 child 计划，逐级自底向上
  → MAKE child 与根产品在本页填写本批车间、负责人和日期
  → 服务端重新预览并生成计划草稿，提交审批；页面不跳走
  → 计划批准后才形成 READY、正式预留、DRAW 和销售已排量
  → 剩余未排数量继续保留在原物料分析，待物料后续到齐再分批安排
```

销售订单有 10,000 件需求而当前生产硬门槛物料只完整支持 1,000 件时，员工可以先为 1,000 件填写并提交计划单；剩余 9,000 件不复制成一张“待料正式计划”，而是继续留在原分析。采购、委外或 MAKE 合格供给到位后，重新打开同一分析继续安排。

物料分析生成正式计划时不自行写 `MA-UUID` 产品编号。计划服务先持久化带 UUID 的计划头和服务端计划单号，再由数据库为留空的计划行原子分配 `<计划单号>-NNN`；后续分批计划拥有不同计划 UUID/单号，因此不会复用前一批产品编号。来源追溯始终使用分析、需求行、销售订单行和计划行 UUID，不按这些可见编号反查关系。

从“新建生产计划”带入的显式产品编号只作为当前路由内的计划向导初值，不写入物料分析来源表；销售来源按销售订单行 UUID、手工来源按来源类型/来源编号/货品/颜色/单位复合身份匹配回正式分析产品。用户可在计划向导继续修改；非空值同时进入联合预览指纹和生成幂等指纹并原样交给计划服务，留空才由服务端自动分配。

物料分析、MRP 和执行分段使用的 BOM 节点必须已经维护当前 UUID：基本单位来自 `goods.unit_id`，颜色来自 `goods_bom_items.color_id`，未覆盖时才继承 `goods.color_id`。只有 legacy 单位/颜色影子、UUID 悬空或目标已停用时，在线预览、重算和下达均失败关闭，不在运行时按 legacy 整数补造 UUID；应先通过受控迁移完成回填与对账。`SHIP/REFERENCE` 虽不形成正式生产物料需求，也不能借此绕过当前 UUID 完整性门禁。

自制件按自底向上推进。目标合同是：每个 MAKE 节点只以自己的**直接子件**判断本批齐套；父树完整深层路径用于解释下一步，不得扁平为根计划一次领料。MAKE 节点先在父树把本批直接下层实际备齐，再创建系统 `MAKE_COMPONENT` 子分析并把对应路径/数量委派给 child；child 独立经历计划批准、DRAW 实发、开工、报工、FQC 与仓库点收，合格入库后父级可完工量才上调。当前候选通过 child 存在性推导**整节点 ownership** 并让父树后代不再激活，没有显式 `delegated_qty`，不得据此宣称任意分批委派余量已实现。员工仍从同一分析任务流处理下一层。

## 二、历史记录与来源选择

### 2.1 物料分析记录

历史页只读取服务端按负责人、部门和对象范围裁剪的记录，支持：

- 搜索需求编号、销售单号或产品；
- 按 `ACTIVE / PARTIALLY_PLANNED / COMPLETED / CANCELLED` 筛选；
- 按销售、返工、试制、样品、备库、其他或系统自制子需求筛选；
- 查看需求、已提交、已批准、待处理、可立即/按期数量；
- “继续处理”回到原分析 ID，不能用重新创建代替恢复。恢复后点“按最新库存刷新分析”时，前端自动用该分析已持久化的来源重算（从产品行重建销售/手工来源、跳过系统 `MAKE_COMPONENT`，与服务端 `requireSameSources` 排除 MAKE_COMPONENT 一致），无需重新选产品。

历史记录宽屏使用 `MasterDataTableView`，窄屏改为带状态、数量和明确「继续处理/查看」文案的卡片；搜索、筛选、分页和打开记录都是安全读操作，不改变业务状态。新分析候选的移动分页、多选与数量核对属于下一节，不得误写成历史记录列表能力。

### 2.2 新分析来源

- 销售来源只列已审核且仍有可排剩余量的销售订单行；支持勾选多行联合分析，不显示价格。
- 候选接口每页 100 项。桌面候选表使用表头三态复选框：空框=当前可选项全未选，勾选=全选，半选=已选部分；表头动作不改变不可选行或已失效行。手机候选卡固定显示 48dp 的「上一页/下一页」和「第 X / Y 页、共 N 项」，跨页选择保留。
- 单次最多 500 个分析来源，销售订单产品与手工计划合并计数；新增、表头全选和最终提交都执行同一上限，不能选满 500 个销售产品后再绕过前端加入手工来源。
- 手工来源只允许 `REWORK / TRIAL / SAMPLE / STOCK / OTHER`；必须填写稳定需求编号、原因、产品、数量和日期。
- `MAKE_COMPONENT` 只能由系统在 MAKE 节点下层实际齐套并完成幂等委派后创建，员工不能手工伪造。
- 窄屏主页面使用单一滚动区，「其他需求（返工 / 试制 / 样品 / 备库）」默认折叠；已选销售产品只显示数量摘要和「核对数量」，点开独立 90% 高度惰性列表编辑，不在主滚动区嵌套最多 500 个输入框。
- 「加入分析」只把一条手工来源加入当前本地表单；勾选、搜索和本地数量编辑也尚未写业务事实。新建时真正持久化 analysis、来源和 BOM 快照的按钮是「联合分析所选产品」；已有 analysis 的刷新入口是工具提示「按最新库存刷新分析」，文档不得再虚构一个「开始/刷新分析」按钮。
- AppBar 标题是「物料分析准备」，次要入口依次为「计划单预览」「物料分析记录」「生产计划历史」。

### 2.3 下游单据的来源单号可读化（V292/ADR-038，2026-08-16）

- 分析下达生成的采购申请/委外申请：表头与明细的「来源单据」显示 `计划前物料分析 <分析日期>`（上海业务日），备注为「…备料任务自动生成」；不再出现 `物料分析-<UUID>`。销售谱系（「为哪些销售订单备料」）由服务端按分析 id 精确回溯写入 `salesOrderNo`，不靠字符串匹配。
- 生产计划路径生成的申请来源单据仍是计划单号（SJ…）；MRP 明细备注使用执行分段编号（ZX…），不写分段 UUID。
- 系统自制子需求（`MAKE_COMPONENT`）的来源编号为 `自制备料 <创建日> <4位尾码>`（尾码仅去重，满足全局唯一索引），历史记录页「来源/需求编号」列据此可读。
- 「剩余物料已可下达」通知文案只带业务单号（收货 CJ…/进仓 EJ…/成品入库 CR…），分析/单据 UUID 只做内部关联键。
- 历史数据由 V292 一次性清洗；`preplan_supply_actions.external_document_no` 的 MAKE 短码受 append-only 守卫保留原值，但不出现在任何界面。

## 三、分析详情的傻瓜式交互

### 3.1 产品与自制备料项

- 区域表头有三态复选框：空框表示全未选，勾选表示当前可选项全选，半选表示只选了部分；再次点已全选表头即取消当前可选项。
- 每张产品卡也有复选框。未选中时保持紧凑，只显示产品身份、剩余/就绪状态、阻断原因和下一步，不展开阶段参考量或本批输入；选中后整卡使用深绿色底和白色文字，并把本批数量预填为服务端“最多可生产量”，员工只修改例外。表头全选也为未显示产品预填该量，避免第 61 项以后被选中却无法填写；数量仍可编辑且提交时由服务端复核。
- 无直接 BOM 不是异常：当前层按直接自制、无领料明细处理，只要有有效分析事实、正数量和生成权限即可勾选。存在 BOM 但循环/超深、非正用量、失效组件、UUID 颜色/单位、包装计量或指纹异常，以及有生产硬门槛但无可完工量的行仍不能勾选，按钮附近必须显示具体原因；不能给一个看似可点但无响应的按钮。
- “调整物料优先顺序”只改变共享自由库存的分析模拟顺序，不创建正式库存预留；点击“确认优先顺序”才写入服务端并重算。
- 每张卡显示服务端汇总的就绪状态：`可安排生产`、`下层备料中`、`草稿待审`、`待领料`、`生产中` 或 `已完工入库`，并给出下一步提示。状态必须由逐路径任务及真实计划/领料/执行/入库事实投影，不能只在前端统计 depth-1 行。
- 2026-08-14 现场易用性增强：产品卡在「最多可生产 X 个 / 齐套 Y%」标题下新增**齐套进度条**（与服务端 `readinessRatio` 同源），并在有缺口时显示「还缺 N 种料 · 其中 M 条路线待确认」摘要；无缺口时不占行，由标题表达结论。
- 进度展示不得把物料齐套、完工申报、FQC 放行和仓库实收混为一个数：采购/委外只有 IQC `PASS` 数量进入合格库存并刷新齐套；日报审核形成当前有效 `fqty`，FAIL 会通过 adjustment 回退该贡献；FQC PASS 只形成待点收上限；仓库实收才累计 `iqty`。卡片应分别显示「已报工」「待品质/待点收」和「已入库」。
- 产品区按“可排产置顶”做稳定排序（保留分配优先级与父先于子序），让计划员一眼看到现在能做谁；不可排产的卡在其可完工量标题下说明被什么挡住。
- `MAKE_COMPONENT` 卡显示 `自制任务 · 用于组装 {父件}`，并精确回指创建它的父路径节点。前端不得按 goodsId 猜父件；同货多路径时必须使用服务端父节点/委派关系。
- 自制件完工入库后，上级可完工量由服务端 `MaterialAnalysisSupplyWakeupService` 自动 `refreshLocked` 上调，无需人工计算；本页只展示结果。

### 3.2 三个数量不能混用

| 页面名称 | 权威含义 | 能否作为本批计划上限 |
|---|---|---:|
| 可开工（分析参考） | `START` 阶段物料当前可支持的数量，只用于看准备进度 | 否 |
| 可完工入库 | `START + ASSEMBLY + FINISH` 生产硬门槛完整齐套后的数量 | **是** |
| 预计可发货（参考） | 加上 `SHIP` 参考物料后可支持的提示量 | 否 |

`可开工/可完工入库/预计可发货` 的语义和服务端计算始终保留，但产品卡未选中时不展示三阶段明细和批次输入；只有员工选中该产品准备安排计划时才展开。折叠只是减少现场噪音，不能改变 `ready_finish` 的计划上限或隐藏阻断原因。

`readyNowQty` 是兼容 API 字段，服务端与当前页面把它写成、读取为“可完工入库量”。逐张计划单中的最大数量和最终 `plan-preview` 都按该量校验，不按“可开工”或“预计可发货”放大。

`SHIP/REFERENCE` 永远只是参考：不写正式生产物料需求、不占库存、不生成 DRAW，也不阻止生产计划或销售实际发货。生产过程确实消耗的纸箱、胶袋、说明书等必须在 BOM 中配置为 `FINISH`，并按 `PER_UNIT / PER_PACKAGE / FIXED_BATCH` 计算；不能把纸箱放在 `SHIP` 后再假装已经为生产预留。

### 3.3 BOM 父子树与红色缺料

- 2026-08-14 现货层借用（调货，V288/V289 + 源码候选）：计划员可在节点详情点「调给其它产品」，把该直接组件路径已分配的合格现货覆盖量调拨给同一分析内**其它产品**的同物料（货品+颜色+单位）直接组件路径。规则：
  - 只影响分析软分配与齐套投影，不写 `stock_reservations`、不动库存账本；借出方精确减少生效量 m、借入方精确增加 m、第三方路径完全不变（服务端以"基线投影 → cap 封顶 + secured 池外锁定"双趟计算保证，pool 守恒）；
  - 产品级「最多可生产」同步变化：借出方按借用后上限重新判定齐套，借入方把借入量作为池外已锁定覆盖计入齐套；
  - m = min（申请量，借出方基线分配，借入方基线缺口），逐笔按创建顺序扣减两侧容量，多笔不超借；生效量回写 `last_effective_qty` 并在节点行双向显示「已被调走 N 件 · 调给 X」/「已调入 N 件 · 来自 Y」，生效数为 0 显示「暂未生效」；
  - 端点硬门槛：仅直接组件层（depth=1）、跨产品、非 SHIP/REFERENCE 阶段、双方均无未撤销的采购/委外/自制下达任务、未委派 MAKE 子任务；数量不得超过借出方已分配量与借入方当前缺口；原因必填并随 `production_material_analysis_borrows` 留痕（V289 守卫：身份与申请量不可变、禁止物理删除、仅 ACTIVE→REVOKED 单向迁移）；
  - 撤销：`POST /{id}/borrows/{borrowId}/revoke` 填原因后恢复基线投影；两个端点都走版本+指纹 CAS、幂等键与 `production_material_analysis:reallocate` 权限；
  - 当前边界：嵌套深层（depth>1）节点的诊断投影随父件新短缺联动，但借用两端只支持直接组件；借用不改变已 READY 计划的正式预留（那仍须走原计划释放/反向链）。

7. MAKE 行先显示“下层备料中”。只有服务端重算确认**当前 MAKE 层的直接子件**实际齐套后，才启用“安排生产”：当前候选幂等创建 `MAKE_COMPONENT` child item，以 child ownership 让父树后代不再激活，再进入既有计划向导。child 自己重复同一规则，形成逐级自底向上生产；根计划不得同时领取 child 的深层材料。目标合同中的显式分批 `delegated_qty` 尚未落地。
8. 无“标记已领料/生产中/完工”按钮。领料来自仓库实际 `issue`，生产中来自执行段状态，完工申报来自审核日报，质量资格来自 FQC，最终完成来自仓库实收 `iqty`；树通过服务端刷新自动更新。
9. 重新进入仍为活动态且服务端明确允许 `REFRESH` 的旧分析时，前端必须从已持久化 item 重建完整用户来源（排除系统 `MAKE_COMPONENT`），自动执行一次 preview 重算，以便旧的深层零需求快照立即按新规则升级；不得使用路由 seed 中可能残缺的销售选择。`VIEW`-only 记录只读展示，绝不自动写分析版本。

结果区的动态「下一步」引导按服务端事实排序：先提示待确认路线，再提示可下达缺料，再提示可生产产品，最后提示等待已提交任务处理。它只解释下一步，不替代 gate、权限或写按钮。

当路线决定或采购/委外/自制下达项超过单请求 500 条时，客户端先按稳定任务身份排序，再按 500 条安全分批；后一批使用前一批返回的最新 `version + fingerprint`，并显示“已完成 X/Y”。中途失败时刷新到最后成功版本，只恢复仍未提交且仍可执行的选择。幂等键只由该请求发出前的 CAS 事实和排序后的精确任务集合生成，不使用重试后可能重新编号的“第几批”；即使服务端已提交而客户端丢失响应，原 chunk 重试也必须命中同一幂等记录。

服务端不能只分别限制 `actionGroupKeys` 与 `materialLineIds` 各 500。它必须先把物料行映射到 action group、用稳定集合去重，再对**合计任务数**强制 1–500；否则其他客户端可在一个请求塞入 1000 项并同步创建下游申请。超过上限返回可操作的校验错误，要求调用方分批。

这里的「提交需求」不是普通消息：服务端先写幂等 `preplan_supply_actions` 和逐节点 allocations，再创建真实采购/委外下游。消息、角标和岗位队列只是这些事实的提醒投影。重复点击必须按路径任务、代次、当前剩余缺口和请求哈希幂等；不能靠货号级开口供给量替代路径守恒。

### 3.5 按需出现的右下悬浮动作区

底部动作区不常驻，只在至少满足一项时出现：

- 有尚未提交的脏路线；
- 有可直接采纳、尚未确认的服务端路线建议；
- 已选择至少一个可下达的补货节点；
- 已选择至少一个可生成计划的 MAKE/root 产品项。

没有待提交内容时整个动作区隐藏，不显示「提交采购需求（0）」「提交委外需求（0）」「安排自制生产（0）」等零计数按钮，也不常驻计划日期。路线保存、补货下达和计划生成只显示与当前选择相关的动作；计划日期、车间和负责人只在进入既有 `ProductionPlanWizardPage` 后填写。

动作区按需隐藏不改变权限和服务端门禁：按钮仍取“客户端有效权限 ∩ 服务端 `allowedActions`”，提交仍校验对象范围、状态、版本、指纹、数量和幂等键。

## 四、在本页安排 MAKE 与根产品计划

只有两类行显示“安排生产”；当前层没有直接 BOM 的叶子按剩余需求全额可安排，不生成空物料需求、预留或 DRAW：

- 下层实际齐套并已经创建/定位 `MAKE_COMPONENT` child item 的 MAKE 行；
- 本批直接组件实际齐套的根产品行。

BUY 与 SUBCONTRACT 行永远不显示生产计划按钮。点击“安排生产”后，从当前节点进入既有 `ProductionPlanWizardPage` 填写计划；这是同一任务流的继续处理，不要求员工先去计划历史重新找单：

- 显示产品、编码、规格、来源路径和服务端重算的本批可完工上限；
- 必填本批数量、生产车间、负责人、计划开始和结束日期；
- 结束日期不得早于开始日期，数量不得超过该节点尚未安排且实际齐套的数量；
- 多行批量安排可以逐张填写并汇总确认，但每张保持自己的 MAKE/root 身份和路径来源；
- 向导取消时返回原分析，已经幂等创建的 MAKE child 继续留作“待安排生产”任务；A4 版式沿用现有向导/打印能力。

### 4.1 MAKE/root 计划提交向导

底部计划动作会按选择显示「生成总装计划（N）」「安排子件生产（N）」或「生成生产计划（N）」。点击后进入标题为「填写生产计划单」的 `ProductionPlanWizardPage`，只处理 MAKE/root；采购和委外已经由各自「提交…需求」动作独立下达，不进入这个提交向导。

- 一种自制件的一个执行批次对应一张计划单；每张必填数量、生产车间、负责人、开始和结束日期，班组可选。车间必须是有效 `DEPT_PROD` 直属子部门，最终仍由服务端校验。
- 可拖动「调整本次提交顺序」；拖动只改变本次预览顺序，不写 BOM 优先级、计划优先级或 V192。
- 「应用到剩余」弹窗默认只勾选「计划开始/结束日期」，默认不勾选「生产车间、负责人和班组」，并默认勾选「只填写空白字段（推荐）」。组织安排只有员工显式勾选后才按车间+负责人+班组整体复制。
- 汇总弹窗标题为「确认提交 N 张生产计划单 · G 个车间组」，按车间或「未分配车间」分组；操作为「返回修改」和「确认并提交审批」。确认后每个 MAKE/root 仍生成独立草稿、`ACTIVE` planning draft 和 `SUBMITTED` plan link，不默认批准。
- 2026-08-17 审核下达选项：持有 `production_plan:approve` 权限时，汇总弹窗提供「生成后立即审核下达」勾选（无权限者不显示）。勾选后 `generate-plan` 以 `approveNow=true` 提交：服务端同事务审核并确认计划包，原子形成执行段和适用的锁料/DRAW；`ZERO_MATERIAL / DIRECT_MAKE` 没有直接领料物料，不创建空物料提货单。未勾选维持原「提交审批」路径。生成结果对话框只列真实产生的「生产计划单 + 物料提货单」：有 DRAW 时显示单号并可打开，无 DRAW 时说明“无下层领料物料，可直接自制”；待审核的只说明批准后系统按实际需求生成执行事实，不让员工猜下一步去哪。
- 向导当前公司头硬编码为「中山市优腾电器有限公司」。这是单公司源码现状，不是已接组织配置；多公司上线前必须改为权威配置并补打印/UAT。

### 4.2 生成后的计划详情

计划详情不再重复提供旧“物料需求只读估算（MRP）→预排/补建正式计划包”入口。分析生成事务已经保存计划草稿与 ACTIVE planning draft；批准应用该草案并冻结执行段。详情只读展示：

- 当前层直接物料需求、reservation、DRAW 与仓库实际发料进度；
- `ZERO_MATERIAL / DIRECT_MAKE` 的正常无领料状态；
- 真实 MAKE child 计划及其各自的领料、开工、报工、FQC 和仓库点收入库；
- 历史 `PLAN_BOM_OVERRIDE` 冻结证据，只读、不可新建或再次授权。

计划详情物料表为空时，必须先看执行段物料形状：合法 ZERO_MATERIAL 显示正常说明；遗留计划缺分析事实时引导回物料分析准备重新生成。两者都不得显示“该产品要求 BOM，但未维护有效 BOM”。

### 4.3 只读备料汇总预览

AppBar「计划单预览」打开可恢复深链 `/production/material-analyses/{analysisId}/summary`：AppBar 标题「备料计划汇总单」，纸面标题「生产备料计划汇总单」。正常进入时当前 analysis 只作为首帧快照，浏览器硬刷新或直接打开深链时按 analysisId 重读权威详情。它按「一、自制件（按组件安排车间生产）」「二、采购件（通知采购部）」「三、委外件（通知委外商）」汇总当前 analysis，并把「待确认供料路线（确认前不会通知任何部门）」和「缺车间清单（生成计划单前必须指定）」列为阻断。

该页当前也硬编码公司名「中山市优腾电器有限公司」，底部唯一动作是「打印 / 导出 PDF」。默认车间是可取消、单轮 10 秒截止且不自动重放的局部补充查询：汇总正文必须首帧可查看，读取失败只在页内提示并允许重试，不得再用整页转圈阻塞返回；默认车间核验成功前禁止打印，避免把“接口未知”误写成“未维护”。它不调用 generate/notify，不提交计划、采购或委外单；采购/委外“待通知/单号”只反映先前真实 action 的状态。不得把这张只读纸面投影与 4.1 的计划提交汇总合并描述。

### 4.4 默认车间只使用 V192 偏好

- 默认车间的唯一权威来源是 V192 `production_goods_workshop_preferences`，不是 `goods.default_workshop_department_id`。V253 只建立官网询盘表，**不是生产迁移**；当前头 V392 也没有建立第二份默认车间真相。
- 向导打开时按 goodsId 批量读取 V192 偏好并预填；没有可用偏好的组件进入「未分配车间」清单，必须由计划员在本次向导补齐后才能提交。
- 客户端按最多 100 个 goodsId 分块读取偏好，避免 UUID 查询串逼近代理 8KB 请求行；服务端上限不是前端必须用满的分页尺寸。
- 学习发生在生产执行段正式确认，以及后续合法改派车间时；仅保存草稿、打开向导、拖动排序或取消不学习，避免误填污染后续预填。
- 本次手工修改车间必须继续用于本计划的组织、班组和人员校验；只有正式执行确认/改派后，V192 才更新 `selection_count` 与最后选择事实，供后续向导预填。

提交仍固定走普通 generate：创建计划草稿、`ACTIVE` planning draft 和 `SUBMITTED` plan link，不直接批准。生成成功后回到/留在当前分析页，行状态刷新为“计划草稿待审”，显示计划号和“查看计划”；员工可以继续处理其他节点。

具有 `production_plan:approve` 的人员仍从权威审批入口批准。只有批准成功后才原子形成 READY、完整库存预留、DRAW 和销售已排量。多选生成默认整批原子成功或失败；任一库存、版本、指纹、BOM、组织或数量变化都使整批失败并要求刷新，不能静默部分成功。

## 六、岗位交接 SOP

| 交接 | 上一岗位必须完成 | 下一岗位看到的权威任务 | 禁止误解 |
|---|---|---|---|
| 生产 → 采购 | 勾选 BUY 缺口并点击「提交采购需求」 | 计划来源采购申请/分解任务 | 提醒消息不等于已经下采购订单 |
| 采购 → 财务 | 从任务中心选择申请行、填写部分数量，按单供应商/单仓生成订货并提交财务 | 订货审批任务 | 保存草稿不等于正式订单；业务人员不能自批 |
| 财务 → 仓库 | 合格财务审核组成员批准订单 | `inbound_expectations` 预计到货 | 预计到货不是现货、不是 IQC 合格、不能使生产 READY |
| 仓库/质量 → 生产 | 实际收货/回厂并完成 IQC，只有 PASS 数量转入目标仓合格可用库存 | 原分析重算后的可完工量/齐套任务 | 待检、FAIL、未入目标仓和仅有在途不得计入可完工量 |
| 生产 → 委外 | 勾选 SUBCONTRACT 缺口并提交；有供料 BOM 时继续备齐我方供料 | 计划来源委外申请/分解任务及供料节点任务 | 委外申请不等于已经发料或已经回厂 |
| 生产 → 自制子件 | 先把 MAKE 节点下层实际备齐，再点“安排生产” | `MAKE_COMPONENT` 子分析任务；父树投影为 child-owned、后代不再激活 | 子需求不是正式子计划；当前为整节点 ownership，不代表任意分批委派；须从 child item 生成草稿并批准 |
| 生产计划 → 车间 | 本页提交 MAKE/root 计划后由有权人员审核 | READY 执行段、DRAW 和计划详情 | 草稿/SUBMITTED 不得开工；DRAW 已审也不等于仓库已实际发料 |
