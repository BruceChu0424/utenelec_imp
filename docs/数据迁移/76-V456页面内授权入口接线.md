# V456 页面内授权入口接线（5 个业务页改挂专属 surface）

> 2026-09-02 · 平台专业化 Phase 1.5。权威设计：[权限体系总设计](../05-架构/权限体系总设计.md)。
> 迁移文件：`server/src/main/resources/db/migration/V456__page_permission_surface_wiring.sql`

## 一、做了什么

V455 把 10 个守卫页补进 surface 目录（见[迁移说明 75](75-V455权限目录收口.md)），但页面内
授权**入口**由 `lib/shared/auth/page_permission_scope.dart` 的唯一业务映射决定，其中 5 个
业务页当时仍复用既有业务 surface——两处委派面过宽（调度/进度挂全套生产计划面）、一处
FQC 委派真空（`/quality/production-inspections` 无任何映射）。本次按「页面守卫同源」原则
接线，数据库与前端同批提交：

| 页面 | 入口变化 | surface 关联权限（迁移后） |
|---|---|---|
| 品质任务中心 `/quality/task-center` | `quality.inspection` → **`quality.task-center`** | procurement_inspection:view/handle、production_quality_inspection:view/approve（4 码） |
| 生产成品质检 `/quality/production-inspections` | 无映射（真空）→ **`quality.production-fqc`** | production_quality_inspection:view/approve、production_fqc_replenishment:view/confirm（4 码），面更名「生产成品质检与FQC补产」 |
| 仓库质检结果 `/warehouse/quality-results` | `warehouse.iqc-stock-in` → **`warehouse.quality-results`** | warehouse_iqc_stock_in:view/confirm、warehouse_iqc_return:view（3 码） |
| 生产调度 `/production/schedule` | `production.plan` → **`production.schedule`** | production_plan:view（不变，纯前端接线） |
| 生产进度 `/production/progress` | `production.plan` → **`production.progress`** | production_plan:view（不变，纯前端接线） |

### 关键决策

- **退役 `quality.inspection` 旧面**：待检处置合并卡的 IQC/FQC 决定都在品质任务中心页，
  扩码后的 `quality.task-center`（IQC view+handle + FQC view+approve）是旧面
  （IQC view+handle）的严格超集，无能力回退。历史委派行的 `surface_key` 文本列无外键，
  dangling 行属审计证据，保留不动。surface 目录 111 → **110** 个。
- **调度/进度是安全收紧**：看板页此前挂 `production.plan` 面，负责人可从看板委派全套
  生产计划动作（edit/approve/dispatch 等 14 码）；改挂 view-only 专属面后只委派
  `production_plan:view`，完整生产动作仍在 `/production/plans` 的 `production.plan` 面授予。
- **admin×4 与 chain-health 不接线（设计如此）**：授权总控/审计中心/系统设置/本机回执
  按设计永不开放负责人委派入口；生产链路健康在对象范围收口前保持 fail-closed。
  五面维持 V455 的目录登记形态。
- 旧深链 `/warehouse/iqc-stock-ins*`、`/warehouse/iqc-returns*` 重定向进合并页，但
  `page_permission_scope.dart` 的旧映射保留（各挂原面，无害）。

## 二、兼容性

- 零默认 grant，不改变任何现有用户的可见性；不新增业务表，CLEAR 清单维持 220 张。
- 纯目录迁移：surface 扩码/退役/更名 + 前端映射切换，存量数据库直接应用即可。
- `quality.inspection` 面下历史委派行不受影响（无外键），但该面不再出现在
  页面内授权入口；`PermissionDelegationPolicy` 拒绝清单不动。
