## 2026-08-29 当前页面口径（ADR-057 / V423 后）

> 当前入口、交互、接口副作用、岗位交接和 NO_COVERAGE 以[生产物料分析页与逐张计划单向导](生产物料分析页.md)为准。本节优先于下方 2026-08-08 V234 设计快照及 V191–V211 历史兼容说明。源码和隔离克隆验证不等于公司目标库已部署，生产写链路仍为 **NO-GO**。

当前入口是标题为「物料分析准备」的 `/production/material-analysis`。顶部次要入口依次为「备料汇总预览」「物料分析记录」「生产计划历史」，刷新图标提示为「按最新库存刷新分析」。新分析候选的实际写按钮是「联合分析所选产品」：桌面候选表支持表头三态和行多选；手机候选卡按服务端每页 100 项显示 48dp 的「上一页/下一页」，跨页选择保留。销售产品和手工来源合计最多 500 项；手工区的「加入分析」只加入本地来源，不是已经持久化分析。

页面已经从“先建正式计划再看缺料”改为：销售/合法手工需求先做持久化物料分析，完整 BOM 按父子层级进入**同一棵树**，不再按 BUY、SUBCONTRACT、MAKE 分区。结果默认「只看缺料」，可搜索或切换「待确认路线/全部 BOM」；搜索命中子节点时保留祖先并显示「筛选命中 X 条；保留上级后共 Y 条 / 全部 Z 条」。只有路线已确认且当前可执行的节点显示复选框；其余直接显示 48dp 的「先确认路线/先保存路线/下层未齐/仅查看」状态。路线必须显式点「采用采购」「采用委外」「采用自制」，再用「提交采购需求（N）」「提交委外需求（N）」或「安排自制生产（N）」下达。采购/委外会创建计划前动作及真实申请，不是只发消息；MAKE 只检查当前层直接子件，齐套后创建系统 child 需求并由 child 独立生成计划，自底向上推进，不自动递归创建整棵正式计划。

产品卡分别展示“可开工（分析参考）”“可完工入库”“预计可发货（参考）”。兼容字段 `readyNowQty` 当前等于可完工入库量，只有它能作为本批计划上限；`SHIP/REFERENCE` 不得成为生产硬门槛。纸箱、胶袋、说明书等若属于生产实际消耗，必须维护为 `FINISH` 并按件、包装或固定批次计算。

勾选可完工 MAKE/root 后进入标题为「填写生产计划单」的逐张向导，一张对应一种自制件的一个执行批次。员工逐张填写数量、生产车间、负责人和起止日期，可拖动调整本次提交顺序。「应用到剩余」弹窗默认只勾选「计划开始/结束日期」，默认**不**勾选「生产车间、负责人和班组」，并默认「只填写空白字段（推荐）」；组织安排只有员工显式勾选后才整体复制。最后弹窗标题为「确认提交 N 张生产计划单 · G 个车间组」。无审核权限时主按钮为「确认并提交审批」；持 `production_plan:approve` 时「生成后立即审核下达」默认勾选，主按钮为「确认生成并审核下达」，员工可取消勾选且两种路径都必须再次确认。提交后用两阶段加载遮罩显示最新库存/齐套校验及计划生成进度，成功后才展示真实计划与 DRAW 结果。返回结果为 `APPROVED + packageId` 时可立即「打印生产计划单」；以后补打从已审计划详情底部同名按钮进入。草稿、红冲、停止、取消或失效计划包不得打印成流水线有效指令；历史列表不堆打印按钮，先进入详情核对当前状态。未排余量留在同一分析中，支持物料到齐后继续分批生产。

AppBar 的「备料汇总预览」是另一套**只读**页面：页面标题「备料计划汇总单」、纸面标题「生产备料计划汇总单」，分为「一、自制件」「二、采购件」「三、委外件」，并把待确认路线和缺车间列为红色阻断；底部只有「打印 / 导出 PDF」。它不提交计划，也不替代上面的 MAKE/root 计划向导，更不会把采购、委外和生产混成一张权威单据。

向导和只读汇总当前都显示硬编码公司名「中山市优腾电器有限公司」；多公司组织配置尚未接入，文档不得写成已从组织配置读取。默认车间只读取 V192 `production_goods_workshop_preferences`；只有执行段正式确认或后续合法改派才学习，打开/修改/取消向导或生成草稿都不学习。`V253__website_inquiries.sql` 是官网询盘迁移，与生产车间无关，不得作为第二份默认车间来源。

正式流水线工卡当前也使用同一单公司抬头「中山市优腾电器有限公司」。这是诚实的源码现状，不是多公司动态配置；多公司启用前必须接权威组织配置并重新完成打印视觉与岗位 UAT。

计划详情不再提供旧“物料需求只读估算（MRP）→预排并保存草案/补建正式计划包”写入口。新分析来源计划只读展示已冻结执行分段、真实子计划、直接层需求、预留、DRAW/issue、报工、FQC 与仓库点收入库；无下层物料时显示“无下层领料物料，可直接自制”，空表不标红、不要求补 BOM，也不生成空领料单。历史计划原 MRP/计划包结果只读兼容，变更或反向走对应受控链路。

## 2026-08-08 设计快照（V234，历史参考）

> 本节保留 V234 初始页面设计证据；若与上方 2026-08-11 当前页面口径冲突，以上方章节、[ADR-029](../99-决策记录-ADR/ADR-029-生产计划前需求与物料分析重构.md)和当前代码为准。新入口不再要求先创建正式生产计划；目标库未核验、真实 UAT 未完成，页面不得宣称生产可用，写链路仍为 **NO-GO**。

### 入口与导航

- 生产管理 Hub 原“生产计划单”改名为 **“新建生产计划单”**；点击后默认打开新建页，不先展示历史列表。
- 顶部提供与其他部门一致的 **“生产计划历史”** 次要按钮，进入计划历史；另提供文案明确区分的 **“物料分析记录”** 入口，用于恢复尚未生成计划的销售、返工、试制、样品、备库和其他分析任务。返回新建页时保留来源筛选和未提交草稿。
- 每个页面只保留一个主操作：新建页为“开始物料分析”，分析齐套后的主操作才变为“生成生产计划”。历史记录、取消、刷新和打印使用次要样式。
- 当前源码候选路由：`/production/material-analysis` 为新建/分析主入口，`/production/plans/new` 兼容重定向到该入口，历史记录使用 `/production/plans`；分析 item 深链须在路由/查询参数稳定后补契约测试，并提供可预测返回。

### 新建页表单

来源默认留空，使用者必须明确选择：

1. **引用销售订单**：打开已审核且仍有可排剩余量的销售订单行选择器，可多选；展示销售单号、客户、产品、订货量、已下达量、剩余量、交期和销售负责人。保存精确订单行 ID 和数量，不只保存单号文本。
2. **手工生产需求**：只允许选择 `REWORK`、`TRIAL`、`SAMPLE`、`STOCK`、`OTHER`，填写稳定业务需求编号、产品、数量、需求日期、责任人和原因；同类型同编号只能恢复原任务，不能重复创建。不得伪造销售来源，也不得绕过物料齐套。`MAKE_COMPONENT` 是系统由 MAKE action 创建的子件来源，不出现在手工选择器中。

销售行允许拆分数量；同一生产需求也可汇总多个相同产品的销售行，但必须在下达时保留逐行分摊。选择器使用“草稿选择 → 确认写回”协议：取消不改变原表单，确认后才覆盖；失效、被其他计划占用或数量变化的行在提交时由服务端点名返回。

计划行“产品编号”允许填写已有业务编号，也允许留空。销售订单选择器不再用“销售单号-销售行号”预造编号，物料分析也不再生成 `MA-UUID`；正式计划头取得服务端计划单号后，空值统一由数据库按 `<计划单号>-NNN` 原子分配。编号只用于展示、搜索、打印和扫码，销售来源、计划行及分批关系仍分别使用 UUID。同一销售订单行分批建立多个正式计划时，每个计划因此得到独立且全局终身唯一的编号。

### 操作流程

```text
选择销售订单行或手工来源
  → 填写本次生产需求数量/日期/责任人
  → 开始物料分析
  → 跳转生产调度工作台的该计划前需求
  → 备料完成并出现正数可立即生产量
  → 选择一个目标仓并填写本次分批数量
  → 生成计划草稿 + ACTIVE planning draft + SUBMITTED plan link（不预留）
  → 持 production_plan:approve 者批准
  → 原子 READY + 完整预留 + DRAW + 销售分摊（plan link APPROVED）
  → 剩余量继续留在计划前需求，不复制一张 WAITING 正式计划
```

点击“开始物料分析”只创建 `production_material_analyses`、来源 `production_material_analysis_items` 和初始全树节点，不创建 `production_plans`、计划包、执行分段、库存预留、DRAW 或销售已排量。重复命令必须使用幂等键/载荷哈希返回同一结果或明确冲突。

### 生成正式计划面板

- 同时显示“需求剩余量”“目标仓可立即生产量”“预计可生产量”“预计齐套日”和数据更新时间；预计量不能抬高本次可输入上限。分析可以展示其他仓库存分布与调拨候选，但生成时只能选择一个目标仓，其他仓库存不得直接合并进立即量。
- `可立即生产量 = 0` 时主按钮禁用，并在按钮附近列出首要短缺与修复入口，不能只弹一个“失败”。
- 本次数量必须为正且不超过服务端重算后的可立即生产量；数量按产品基本单位精度向下取整。
- 支持从工作台多选产品/需求后批量生成。默认整批原子成功或失败；冲突结果按产品、物料和原因列出，修正后由用户再次确认，不自动重放写操作。
- 路线确认只约束缺料通知。若需求 100、当前已完整齐套 10，剩余 90 的路线尚未确认也允许生成 10；不得把“其余缺口路线未选”作为已齐套批次的禁用原因。
- 普通“生成生产计划”成功后展示计划草稿号、ACTIVE planning draft、本批数量、销售来源和 `SUBMITTED` plan link；此时不得显示 READY、已预留或 DRAW。分析头仍显示 `ACTIVE/PARTIALLY_PLANNED/COMPLETED/CANCELLED` 聚合状态。
- 持 `production_plan:approve` 的用户可在独立确认后“批准”，也可从生成面板显式选择 `approveNow`。批准时服务端按目标仓原子重算并创建 READY、完整预留、DRAW 和销售分摊，将 plan link 转为 `APPROVED`；失败保持草稿/SUBMITTED link 且不留下部分预留。
- 批准成功后才展示正式计划号、READY 执行批次、预留和 DRAW 深链；剩余未排数量继续显示在计划前需求卡。未来采购/委外/MAKE 不得显示为“已预留”。

### 无 BOM 与历史计划

- 2026-08-29 起（ADR-057 / V423）主档「生产 BOM 策略」整体下线：当前 MAKE 层无直接 BOM 时按「直接自制」进入物料分析，剩余需求全额可安排且没有领料明细；有 BOM 时只以当前层直接子件做生产硬门槛齐套，短缺 MAKE 子件再检查自己的直接子层，逐级自底向上。不再存在无 BOM 例外放权流程；历史 `PLAN_BOM_OVERRIDE` 只读留证。循环/超深 BOM、非正用量、非法单位/颜色、失效货品和陈旧指纹仍硬校验。
- 历史记录统一展示物料分析生成的计划、手工计划和旧 V191 计划。历史 `WAITING/AUTO_WAIT/DEFERRED` 标为“历史待料计划”，在新页面只读；完成或反向进入受控兼容入口。

### 权限、反馈与可访问性

- 页面使用实际权限 `production_material_analysis:view`、`production_material_analysis:manage`、`production_material_analysis:route`、`production_material_analysis:notify`、`production_material_analysis:generate`、`production_material_analysis:reallocate` 与 `production_plan:approve`；普通 generate 不预留，只有 approve 可批准，持两者者才可 `approveNow`。前端只根据“本地有效权限 ∩ 服务端 `allowedActions`”显示动作。
- 所有按钮在请求中显示进度并禁用重复点击；失败文案说明原因及下一步，成功后显示真实计划号和可跳转结果。
- 主操作、历史记录和弹层关闭控件触控区域至少 48dp；不能依赖悬停、颜色或拖拽。禁用状态同时提供文本原因，缺料使用深红 + 图标 + “缺料”文本。
- 移动端使用纵向分组和固定底部主动作区，并预留安全区；大屏保持清晰主次层级。动态字体、键盘/读屏顺序、浅色/深色对比度和离页未保存确认必须验收。

## 一、页面职责与审核边界

生产计划详情页是“草稿预排 → 审核下达 → 查看执行单据”的唯一排产入口。“一键生成子计划”沿用现场叫法，但不是盲目复制父计划：

- 草稿阶段先展开完整 BOM、齐套与供给评审，允许调整实排数量、车间、班组、负责人和计划日期；
- 保存的 `production_planning_drafts` 只是不可变预排建议，不是库存、采购、委外、领料或车间执行事实；
- 审核计划时，服务端在同一事务重算并尝试将当前 `ACTIVE` 预排草案正式下达；任一指纹、BOM、库存、数量或权限校验失败，计划审核和全部下游写入一起回滚；
- 父计划内的 `production_execution_segments` 是 READY/WAITING 执行分段；`subplan_links` 指向另一张自制件生产计划。两种“子计划”不得混用。

## 二、按计划状态的按钮语义

| 计划状态 | 主操作 | 结果与限制 |
|---|---|---|
| 草稿 | “物料评审与预排”/“查看已存草案” | 只计算和保存预排草案；可按保存时的精确执行段只读回查。新草案将原 `ACTIVE` 草案转为 `SUPERSEDED`，不修改原载荷 |
| 审核 | “审核并下达” | 若有有效草案，审核和正式计划包必须同事务成功；草案过期则明确失败并要求重新预排 |
| 已审，无有效计划包 | “补建排产包” | 适用于未提前保存草案的新计划；按当前数据重算后一次性正式下达 |
| 已审，已有有效计划包 | “查看已生成单据” | 直接回放已存结果；不再重复生成，不用“生成剩余”绕过变更/取消/反向链路 |
| 红冲、取消、中止 | 只读 | 不允许保存预排或生成新计划包 |

“已审无包可补建，已审有包只查看”是幂等边界。已下达内容要改量、换车间或改日期时，必须走有审计的计划变更、整包取消或反向，不能原地篡改历史。

## 三、物料需求评审

弹窗先按“库存充足、需采购、需自制、需委外、自制无 BOM”展示摘要，每张分类卡都提供“查看详情”。详情面板在紧凑屏使用接近全屏底部面板，大屏使用右侧宽面板，并使用水平可滚动的数据表/编辑网格承载高密度数据。保存后，“查看已存草案”从服务端不可变载荷还原当时的精确执行段、采购申请开关和采购/委外路线，不用当前页面状态猜测。

分类和正式生成只针对本计划包的当前直接 BOM 层。A→B→D 时，A 页只评审并生成 B 子计划；进入 B 计划后再评审 D，禁止在 A 包内递归生成全部层级。

产品和物料字段至少包含：

- 计划流水号/分段编号、货品编码、货品名称、规格、颜色和来源订单行；
- 计划数量、实排数量、单支基本用量、毛需求、自由库存、已分配、缺口和供给路线；
- READY / 系统待料（齐套自动转产）/ 人工暂缓（手动恢复）、推荐车间、班组、负责人、计划开工和计划完工日期。

用户可分拆执行行、调整数量和排程，也可选择“优先生产”“待料 · 齐套自动转产”或“人工暂缓 · 手动恢复”；页面不再用初始建议限制单个产品的 READY 上限，最终由服务端按全计划实时库存做整套齐料校验。车间必须是生产部直属有效车间，班组必须直属该车间，负责人必须属于所选组织范围且状态为在职/试用；前端收窄候选，服务端在草案、下达、改派和派工节点重复校验。提交前必须满足：

```text
对每一条生产计划明细：
Σ READY 实排数量 + Σ 系统待料数量 + Σ 人工暂缓数量 = 该明细计划数量
```

READY 必须能同时占用其全部必需物料；系统待料和人工暂缓都只保留全量需求与供给挂接，不零散锁料。人工暂缓解除时使用期望版本和幂等键，只允许一次性 `false→true`，同一事务立即重新判断齐套。数量改动后必须重算 BOM 需求，不能只改表格显示值。存在无 BOM 产品、循环 BOM、不可换算单位或未知路线时整个方案 fail-closed，页面须点名具体货品和修复入口。

## 四、正式下达与单据结果

审核下达或已审无包补建成功后，页面必须立即展示可回查的结果，而不是只提示“成功”：

| 物料/产品路线 | 正式结果 | 业务边界 |
|---|---|---|
| READY | `production_execution_segments` + 全套 `stock_reservations` + DRAW 领料单 | DRAW 审核只确认需求，实际发料才减在手 |
| WAITING | 执行分段 + 全量物料需求/未来供给挂接 | 不锁零散现货，齐套时重新锁整套 |
| BUY 缺口 | 计划链下达的采购申请 + supply peg | 采购端申请只读；采购在任务中心分解订货并送财务审批，未收货合格不是库存 |
| MAKE 缺口 | 按本包当前直接层货品/颜色聚合的真实子 `production_plans` + `subplan_links(source='EXECUTION_V1')` | 子计划是独立生产计划，进入子计划再逐级下钻；不是父计划执行分段，不在父包递归全展开 |
| SUBCONTRACT 缺口 | 计划链下达的委外申请 + supply peg | 委外端申请只读；委外在任务中心分解订货并送财务审批，发料和回厂质量仍有独立门禁 |

结果对话框按执行分段、真实子计划、采购申请、委外申请和 DRAW 分组；每一行可打开相应的真实单据详情。重放相同幂等请求必须返回同一结果，不重复建单；结果回查对已确认计划包持悲观读锁，避免与并发取消/反向交错后返回过期状态。

## 五、车间建议学习（V192）

`production_goods_workshop_preferences` 按产品货品记住“下次默认建议”，但不替代执行分段上已确认的历史车间。

- 首次计划包整体正式确认成功，或执行段后续成功 assign 车间后才学习；草稿保存、失败请求、取消操作和幂等 replay 都不学习/不重复计数；
- 首次下达时，同一货品在本次包中的全部执行分段都指向同一有效车间时，才更新建议和 `selection_count`；后续 assign 只在真实状态/安排变更成功时学习；
- 未选车间，或同一货品同次被拆到多个车间，视为歧义样本，本次不学习；
- 预览优先带出有效学习建议，用户每次都可修改。修改只影响本次尚未确认的方案和未来建议，不回写历史计划。

## 六、A4/工卡选择

本轮不把一张 A4 文件当作“计划单本体”。权威源是可查询、可关联、可反向的结构化计划包、执行分段和下游单据。已确认计划包可从生成结果或计划详情打开横向 A4「生产计划单（流水线执行工卡）」打印预览；每个执行分段一张，重复页头突出计划单号、分段条码、产品编号/名称、本批数量、车间/班组/负责人、开单/交期和计划开完工，并展示物料承诺/缺口、销售订单、领料单、审核人、包版本及签字栏。打印前重新锁定计划与确认包，复核对象范围、已审、未停止/未取消和 `CONFIRMED/V1`；工卡是只读投影，不是工艺路线卡或第二套事实，补打、丢失和纸面手写不得改变业务状态。

- 批量打印使用生成响应里的精确 packageId；每个任务最多 50 张计划/200 张工卡，5 路有界读取。超过 50 张按原顺序拆成多个编号批次，完成一个预览后仍返回结果清单继续下一批。
- 任一计划/包/分段失效、重复、未知状态或所选 segmentId 缺失时，当前整批失败且不调用打印桥；不得回退为部分打印或“找不到本张就打印全部”。
- 预览中每张工卡可按 segmentId 单独补打；点击「打印本张」或「打印全部」前都再次读取。普通领料段的 READY 显示“已齐套待派工”并提示仓库实发前禁止开工；ZERO_MATERIAL 明说无生产领料需求、仍须车间派工和系统确认。WAITING/人工暂缓与 DISPATCHED 同样给出显著禁开工说明，COMPLETED 明确“仅供存档”。
- 当前只能证明系统打印对话框/下载流程被请求，尚未建立纸张份数、补打原因或物理打印成功账。未来若增加审计，只能诚实记录 `PRINT_REQUESTED`，不能记录无法证明的 `PRINTED`。
- A4 尾部保留带横线的「现场记录（异常/换料/停线/交接）」手写区，并明确“手写内容不回写系统”；它方便纸面交接，但不能代替系统报工、退料、异常或停线事实。

## 七、权限、反馈与历史边界

- 只读账号可查看计划、BOM、执行分段、真实子计划和已生成单据，不能保存预排、审核下达、调整或报工；
- 按钮请求期间显示“正在计算/保存/审核下达”并禁止连点；空仓库、陈旧预览、并发改量、无 BOM、无效路线和无权限必须显示服务端可行动错误；
- V191/V192 业务表对老数据 **零回填**：不重算旧计划、不补造计划包/预排草案、不从历史 `department_id` 猜测学习偏好；V193 只重跑审计触发器覆盖检查，绝不补造历史审计行。历史单据和事实原样保留、只读回查；新规则只由迁移后用户主动预排、正式下达或执行段后续派工产生；
- 页面可用不等于生产放行。真实岗位 UAT、BOM 主数据治理、并发/回滚、仓库与质量门禁验收前仍为 **NO-GO**。

## 七点五、无 BOM 不再阻断排产（2026-08-05 调整）

**原则**：原材料/叶子件（含自制叶子件，原料走车间领料、本就不进 BOM）就是最底层、不能再细分，**没有 BOM 是合法的，不是错误**。无论作为组件还是顶层产品，系统都不再因"无 BOM"拦截排产；货品主档 `source_type` 标了什么就按什么走（自制→生产、采购→采购、委外→委外）。

- **自制叶子件缺料**：不再 fail-closed。后端 `directMakeRequirements` 取 MAKE 缺口，`generateSelfMadeSubplansForPackage` 派生一张「造 N 个」裸子计划（只有 `production_plans`+明细，无 BOM、无执行分段）；该子计划可直接审核→报工→成品入库（报工/入库在 `production_plan_items` 层闭合，不依赖执行分段：`DailyReportExecutionSegmentGuard` 无 confirmed segment 时放行、`ReportablePlanLineQueryService` 的 `OR NOT EXISTS segment` 分支兜底）。
- **顶层产品无 BOM**：分析来源且精确落位的 DIRECT_MAKE 行已经形成合法 ZERO_MATERIAL 执行候选，不进入 `unresolvedZeroMaterialLineageIds`。该字段只列旧/手工计划中“没有直接 BOM 且缺少精确物料分析谱系”的计划行；它不是 BOM 异常桶，正式下达须提示“缺少物料分析事实，请从物料分析准备重新生成”，不得静默放行或要求补 BOM。
- **物料评审对话框**：不再用 `hasBlockingBomGaps` 或 BOM 行数决定按钮是否可用。合法 DIRECT_MAKE 作为“无下层领料物料”的正常执行形状；`unresolvedZeroMaterialLineageIds` 只用于识别旧/手工计划缺谱系并引导返回物料分析。循环、超深、非法用量、UUID 单位颜色或计量错误仍由服务端结构校验失败关闭。
- **仍 fail-closed 的结构错误**（与"无 BOM"不同，不变）：BOM 循环、单位不可换算、关键字段为空、路线未知、版本在计划日期无效等仍整体拒绝。

> **待排产板（`production_board_page`）的「转发研发」暂保留**：V211 的按货品去重 + 多计划员等待名单 + 完成回路（见下）在调度看板仍生效，供计划员主动请研发为某货品补建 BOM。它与"无 BOM 合法"原则略有张力（叶子件本不需要 BOM），是否一并收敛待定；**当前它不阻断任何排产**（阻断只在已移除的校验器里，看板转发仅为可选动作）。

### V211 转发研发实现要点（待排产板仍用，对话框已不用）

- **按货品去重**：`uq_rd_tasks_open_bom (goods_id)` —— 每个组件只建一个未完成 BOM 任务、只通知研发一次（旧 `(order_item_id, goods_id)` 对自制组件 `order_item_id` 为 NULL 完全失效，且同件跨订单重复通知）。
- **多计划员等待**：`rd_task_forwarders` 记录每个转发人；研发维护好 BOM 后**逐个通知所有等待者**（旧版只通知首发人）。待排产板 `_pendingRow` 三态（服务端 `PendingPlanRow.rdForwarded` + `myForward`）：无人转发→「转发研发」；他人已转发→「我也登记」；我已登记→「等待维护」。
- **完成回路**：`GoodsBomService.recalcSourceE` 用 `events.publish(...)`（旧 `publishOnce` 终生键会吞掉同件二次维护）；研发保存有效 BOM 发 `GOODS_BOM_UPDATED`，`ChainNoticeService.notifyBomUpdated` 通知所有 forwarders 并 `resolveOpenBomTasksForGoods` 标 DONE（`hasReadyBom` 校验 `COUNT(goods_bom_items)>0` 防误完成）。任务闭环详见 [工程研发部任务中心.md §六](工程研发部任务中心.md)。

> 顺带修复「详细排产滑窗关闭后表格铺满全屏」bug：内嵌 `MasterDataTableView(embedded:true)` 现默认隐藏工具条「全屏」按钮（新增 `showFullscreenToggle` 开关，默认 `!embedded`），滑窗 `_finish` 关闭改用 `Navigator.of(context, rootNavigator: true).pop()` 对齐 `showGeneralDialog` 的 root navigator。详见 §三详细排产。
