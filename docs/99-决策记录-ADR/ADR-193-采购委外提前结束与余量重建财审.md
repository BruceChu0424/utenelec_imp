# ADR-193 采购委外提前结束与余量重建财审

- 日期：2026-10-24
- 状态：已接受；源码实现与隔离数据库验证，业务库迁移、服务启用和岗位验收分别确认。
- 迁移：V922、V923；第二轮 V924 追加已结清委外损耗的终态基数保护；V929 前向校正只追加来源账的行审计策略。
- 界面按 `frontend-design` 实施，沿用 Uten 悬浮操作组、对话框、表格、主题和权限规则。

采购供应商或委外商停止履约时，原单可以申请提前结束，不必把原数量改小或虚构收货。入口在任务工作台的单行操作和订货详情右下角悬浮操作组，统一叫“直接结束”。申请须核对剩余量、选择处理方式并填写原因。

| 处理方式 | 财务批准后的结果 |
|---|---|
| 直接结束 | 原订单永久停止后续供货，不再催仓库收剩余量，不再继续委外领料、发料。 |
| 结束并重建剩余订单 | 先结束原单，同一事务生成精确剩余数量的新草稿，保留原来源关联，交给提交结束申请的业务人员继续办理；确认新供应商、交期和商业条款后重新提交普通财务审批。 |

财务继续使用采购、委外原审批页，在状态筛选增加“结束待审批”，不另设分类。结束申请使用独立 `request_type=CLOSE/CLOSE_AND_REORDER`，普通商业审批使用 `ORDER`。结束申请不改变原财审、汇率和税率投影；详情通过独立 `closureRequest` 展示申请进度、退回原因和新单链接。

申请待审和被退回时原订单仍正常执行。审批使用原有审核权限、认领、版本检查和事件历史。提交时保存服务端计算的收货、退货、质检、来源和委外材料快照指纹；批准时重新核验，事实变化须退回后重新核对提交，不自动沿用旧余量。并发重复提交只保留一个当前审批，重复批准不会生成第二张订单。

原订货数量、原商业金额和原来源份额不改写。采购收费量和赠品分别核算；委外扣除已经独立接受的结案损耗。已收货未入库不算欠交，已实物退回的数量按原数量口径计算，不把待检量重复重建。计量依据未核验或来源数量不一致时给出明确阻断原因，不默认按 1 换算。

仅对完全没有现代申请来源、来源份额和生产供给挂接的历史导入单，计量未核验时允许财务批准“直接结束”；剩余量显示未知，原始数量和计量事实不改写，禁止按剩余量重建。有现代来源或生产挂接时继续严格核验计量。

`procurement_order_termination_sources` 保存每个原来源释放的收费量、赠品量和保留实物量；`procurement_order_termination_peg_changes` 保存原订单未消费生产供给挂接的释放事实。释放顺序是原来源 FIFO 的逆向尾部，生产供给回到原需求来源，不制造新需求、假库存或假齐套。新草稿逐原明细承接释放的来源；新草稿尚未送审时也占住该份余量，避免需求池重复显示可下单。

两表只由同事务财务批准生成，V923 守卫禁止任何 UPDATE/DELETE，并把插入绑定到父案件的批准状态和 decided_txid。
父案件保留审核人、时间和完整提交快照，APPROVED 语义事件保留操作人与指纹；子账行自身永久保存逐来源与挂接释放量。
因此按[ADR-105](ADR-105-审计白名单行级审计与分区留存.md)的“只追加流水，子行经父行追溯”归 NONE/ledger，
不重复把派生账行复制到行审计。V929 仅经共享 fn_audit_track_table 前向纠正 V923 的 FULL 登记；
V923 原像、既有审计记录、父案件/事件、不可变与数量/延迟约束保持，不能通过改已应用 SQL 或改独立清单凑绿。

直接结束商业订单不等于取消生产需求。真实未满足的来源需求重新显示为缺口；若不再需要，须由原需求业务链处理，不能靠终止采购订单抹去需求。

批准后，订单保存不可清除的 `termination_case_id`，预计到货关闭，旧页面和直接接口均不能继续收货、领料和发料。收货、退货和质检后续重算不能重新打开该订单，原单不能再通过改量或反审恢复执行。

结束前须办清收退货、未决质检和不合格实物处置；已通过品质检验但尚未入库的货可以随后按原流程入库。财务应付和结算继续保留；在外委外材料的真实结存、退料和损耗责任保留，不因结束虚构损耗、转移材料或清零往来。存在未完成草稿、异常或不允许撤回的来源承诺时，按相应实物和来源守卫先处理，不悄悄丢弃待办。

结束申请中的剩余量按当前实收基数冻结。批准后不允许直接新增原单退货、红冲原收退货或登记新的 IQC 实物退回；这些操作会改变冻结基数，必须经过另行核对的后续业务处置，不能通过重新打开原订单或假造补料保持表面一致。本功能没有提供结束后的实收更正审批链，不宣称支持这种逆向更正。服务端及数据库同时拦截实收基数变化，原材料退料不属于成品收退货基数，继续允许。

委外结束批准同时办结原未决短交案件，原因记录为财务批准提前结束，不改记为接受损耗。已到货且品质合格的实物解除短交暂挂，审批首次取锁即覆盖相应收货、品质和库存足迹。后续入库不再因旧订单欠交重新建立短交案件或自动接受虚构损耗；原仓库预计到货提醒同步办结。

本功能不批量清理已导入数据，不补造旧审批历史，不自动核销货款，也不启动正式发布。

- 最终前端 8 个相关测试文件共 129 项通过；17 个相关源文件和 8 个测试文件静态分析通过。验证包含 320px、深浅主题、200% 字号、供应商为空的新草稿实际选商、动作权限刷新及终态打印。
- 14 个真实 PostgreSQL 业务场景全部通过。最终核心版本先通过 11 个场景，修正另 3 个场景的测试准备及原来源分摊预期后仅重跑这 3 个并通过；没有将失败运行描述为单次全绿。
- 40 项终态保护、架构边界和审计独立清单回归通过；采购历史打印另在独立输出目录执行 19 项回归并通过。
- 独立空库完整执行 849 条迁移至 V923；V922/V923 源码、启动时快照与构建资源哈希一致，未修改已应用历史 SQL。
- 本轮未向已导入的业务库应用迁移，未重启现有业务后端，未提交、推送或发布。岗位操作 UAT 和正式启用另行确认。
