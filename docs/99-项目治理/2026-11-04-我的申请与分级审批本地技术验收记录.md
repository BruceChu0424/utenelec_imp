## 已落实的关键业务边界

| 场景 | 当前实现与限制 |
| --- | --- |
| 报销四级审批 | 部门负责人、财务初核、财务复核、总经办串行；财务登记付款另授权。旧待审单迁入部门首审，保留原历史；旧 `expense:approve` 不自动授新节点。已批准/已付款旧单不伪造阶段签字。 |
| 出差申请 | 部门负责人 → 总经办批准 → 财务接收保管；终批不能概括成全部进入付款。 |
| 供应商付款 | 采购意见 → 财务意见 → 副总 → 总经理 → 登记付款；不强套普通部门首审链。 |
| 回避与付款分权 | 本人禁审，同轮不同节点分人；本轮审核参与者不能登记同一申请付款。负责人本人申请由另一配置管理员预配回避人；负责人不得自行更改本部门回避人，配置不自动授审批权限。 |
| 回避配置过期 | 首审中的相关申请标为待重新提交，申请人撤回重提；不伪造驳回、不倒退已进入财务的单据。待处理红数与处理中黄数互斥。 |
| 驳回与修订 | 必填原因，原单修改、保留原号和历史，重提增加轮次并从起点审核。旧轮不能补签新轮。 |
| 报销放弃 | 仅本人 REJECTED 且无资金及付款证明；保留六大 status，记录 ABANDONED 和真实归档事实。本人历史详情及原件只读，不开放其他旧软删或他人访问。DRAFT 沿用原删除入口；APPROVED 未付、PAID 不能普通撤回/放弃。 |
| 通用申请作废 | 仅本人 DRAFT/REJECTED 且未付可 CANCELLED；保留单号、附件和事件，只读查看。 |
| 撤销付款登记 | 通用申请原登记人持当前相应权限时填写原因撤销登记；不退款、不自动红冲既有财务账。不能与申请作废、报销放弃混为同一动作。 |
| 员工报销付款 | 沿用既有财务权威，确认后同步生成关联费用记录，避免另建同笔费用重复记账。`canPay` 为服务端权威，现有权限撤销后不能靠旧 DTO 恢复动作。 |
| 供应商预付实付 | PREPAYMENT 仅供应商，供应商由有效资料选择。获批后登记真实付款日、流水及检查通过的证明，PAID 且 postingStatus=PENDING；不新增扣款、不生成费用、不新增或解禁预付会计算法。 |
| 供应商预付入账关系 | 独立关联权加合法既有已审核 PREPAYMENT 财务付款单，供应商/金额/实付日匹配，才可关联 POSTED。普通费用单、非预付付款单、假来源或重复关联均不能替代；没有候选继续黄跟进，不假称已入账。 |
| 未知结果与身份切换 | 保存付款/关联原动作、版本及原输入，先 GET 核对，不自动重放，不跨动作复用未知命令。账号、权限、服务器、业务读取范围或具体资源变化后旧响应和旧确认失效；A→B→A 的旧回调也不能复活。 |
