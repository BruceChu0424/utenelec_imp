# V614 日报完结数量与物料释放溯源

## 问题与根因

真实 PostgreSQL 对抗用例发现：齐套路线已领10、待退3或另行报损3时，普通报工仍可申报8；原来只有持续生产查询实际净材料能力。现普通路线在来源候选、保存与审核统一复核冻结耗用曲线，审核重新读取退料冻结；FQC恢复仍由它自己的授权与材料来源约束。

齐套是开工门槛。已经合法开工后，真实退料可能把需求状态从FULFILLED恢复为ALLOCATED，不能据此隐藏整张工单或拒绝全部报工：实领10、实退3后仍可报7，报8才应拒绝。报工继续要求已开工、正式需求和拆批来源依据，并以实际净料能力封顶。工作台报工入口表示操作资格，来源页的实际可报额度可能为0；不在列表另造一套FQC额度计算。

从物料分析下达的10件任务，仅领4后提前完结时，V234的分析计划行数量不可变守卫拒绝原来的直接改qty。V524虽已覆盖执行段和销售分摊，却没有为分析计划行提供同等真实日报依据。此外，旧释放逻辑只修改released_qty而没有日报来源，反向无法只恢复原日报的释放。

## 事实与投影

- `production_daily_report_target_events`：CAP/RESTORE，冻结日报、计划行、前后数量和原事件；恢复必须指向同一日报的原CAP。
- `production_daily_report_material_release_events`：RELEASE/RESTORE，冻结日报、物料需求、基本量与原事件；触发器按该事件更新released_qty，恢复只抵销该事件的delta。
- 两表只追加，禁止改删，有UUID外键、重复约束、来源索引和ALWAYS审计触发器。延迟约束要求原日报审核或红冲与事件同一事务提交。
- 事件actor须等于事务审计actor，提交时还须与日报updated_by一致；这是审计归属一致性，不声称抵御拥有超级数据库权限者。
- 分析计划的货品、单位、颜色、源关系和删除保护继续有效。仅由真实当次完结事件证明的数量变更可通过，且`qty+capped_qty`不变。
- 原分析下达量、已批准量与冻结BOM仍是历史事实。例：原批准10、完结4，原计划4+封顶6=10；分析额度仍占10，不重新露出6去重复下达；6由源日报生成的唯一补产草稿承接。红冲时删除尚未批准的该草稿、恢复原目标及其未承诺材料责任；补产已审核则仍须先处理下游。
- 同一计划行已有未反向封顶时，不能再次削减覆盖旧来源，须先反向原完结。一个没有削减目标的后续日报，不能恢复另一个日报拥有的封顶。
- 未兑现的采购、委外或生产供给挂接仍代表真实责任。它们和库存承诺一起计入不可释放量；存在这种开放承诺时，仅阻止提前完结，普通分次报工继续可用。须先沿原供给链取消或改派，再提前完结；日报不会暗中取消订货或建立另一份供给账。
- 内部子件没有销售缺额补产关系，短产时保持原工单和父需求：报4后仍可在同任务续报6。短产`isFinal`在写入前返回409并说明剩余量及处理路径，不创建失去分析/父子来源的独立补产；足量最后报工正常办理。
- 销售短产完结还要求没有未实发预留或有效DRAW剩余：预留10、申请/实发5后，不允许final5成功削减计划却留下可继续错发的5。应普通报5、在同任务续领和续报剩5；没有提供一个虚构的“撤回未发余量”按钮，也不宣称已支持任意部分停产。此旧接口边界不影响新页面默认的普通数量报工。已实际发出再GOOD_RETURN的余料按原ISSUE历史识别，不误算成从未实发。

## 实际耗用、报损与在制

`CONSUMED`表示为本产品发生的实际工艺耗用，包含BOM中已计入的正常工艺损耗；登记后仍支持累计已生产量，不能再扣一次可报能力。

`APPROVED_LOSS`表示另行确认的不可用材料/异常报废，不包括上述正常工艺耗用；`LEGAL_WIP`表示转出或留存于其他在制，不再支持当前任务产出。这两项、实退和待退冻结会减少本任务净可生产材料。数量清账仍是同一份原领料来源账。

既有APPROVED_LOSS不自动猜测为正常损耗；错误分类按原结算反向后重新登记。历史完结已经存在封顶或释放、却没有可证明其原日报归属时，也不按当前余额批量归零或补造事实；正向事实保留，反向明确提示先核对原来源。V614不修改历史业务余额。

## 验证

独立真实服务用例：`ProductionQuantityAdversarialEndToEndTest`。覆盖齐套待退后的新建/审核、另行报损、固定批次边界的可行性与最大性、当前BOM变化不污染冻结曲线、BOM内正常损耗只算一次、提前完结与反向后续领、分析责任不重复、事件改删和直接改计划量被拒。最终执行结果以本次治理验收记录为准。
