# Windows 最大化客户区裁剪根因修复

用户自测报告最大化左右、底边内容被裁。只读当前 LocalTest 进程，不关闭或操作其业务窗口，得到实际物理量：DPI96，监视器1920×1080、work(0,0)-(1920,1032)，顶层 HWND、Flutter 子 HWND 和 client 均为(-8,-8)-(1928,1040)，即 client1936×1048。窗口仍保留 WS_OVERLAPPEDWINDOW 的原生调整大小框，最大化外框含标准不可见 overhang。

根因是公共 Win32Window 在 main 模式无条件对 WM_NCCALCSIZE 返回0，直接把包含 overhang 的 proposed outer rect 全部声明为 Flutter client。现有 WM_GETMINMAXINFO 是请求窗口大小，不能代替该最终客户区计算；实际复现证明 client 仍超出工作区。未通过猜测加 Flutter padding、硬编码8px或关闭DPI处理规避。

修复仍保留原生样式、DWM转换、拖动/贴靠/调整大小及缩放。在 WM_NCCALCSIZE 的 TRUE(NCCALCSIZE_PARAMS.rgrc[0])、FALSE(RECT) 两条路径，只有 main 且实际最大化时，将 proposed client 与目标监视器 rcWork 求交；普通恢复窗口行为不变。使用 MonitorFromRect 选择 proposed 目标监视器，坐标全部是物理屏幕坐标，不按96DPI再换算。

公共入口覆盖当前 Flutter Windows 登录/主窗口的同一 native runner：登录模式不变，所有 ERP 页面和业务浮窗共享主客户区自然受益。Web/Android无此Win32框；WPF候选NativeWindowFrame属于独立实现，未据此标为已验收。本次修复没有扩大支持组合。

Microsoft 原始合同： [WM_NCCALCSIZE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-nccalcsize)、[NCCALCSIZE_PARAMS](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-nccalcsize_params)、[MINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-minmaxinfo)。返回前的目标矩形属于客户区计算，两个参数形式都必须处理。

## 开发回归证据与边界

新增隐藏原生 `uten_native_geometry_regression` 目标，编译真实 win32_window.cpp（MSVC /W4 /WX）。未修实现实际回执 `maximizedBothForms:false`，client[-8,-8,1928,1040]，退出1；修复后同输入 TRUE/FALSE均变为work[0,0,1920,1032]，已经精确的矩形不二次收缩，恢复窗口矩形保持原样。进一步真实 SetWindowPos 后通过 GetClientRect+ClientToScreen 及子 HWND GetWindowRect 验证最终父子客户区全部等于work，回执 `physicalClientAndChild:true`、`visible:false`，退出0。

日志分别保留在独立工作树 `native-geometry-before.json/native-geometry-after.json/native-geometry-physical.json` 及 `build-native-geometry-*.log`。当前开发设备实测DPI96；其他真实DPI/多监视器/任务栏边缘尚未由用户验证，不能据此宣称完整真机覆盖。用户当前运行旧预览未被替换；修复需合入最新审核主链后重建并在用户退出时更新桌面目录。
