# ADR-198 同步导出生成进度协议与 204 语义

- 日期：2026-11-08。
- 状态：已接受；服务端与 Flutter 端实现、真实验收（35,763 行 24.9 秒）随下一版本发布。
- 关联：ADR-199（导出 2 分钟事务时限）、[通用进度弹窗](../02-组件库/通用进度弹窗.md)。

## 问题与核查

2026-11-08 用户反馈货品资料全量导出（约 3.9 万行）「进度直接 0→100，最后显示服务器错误」。

根因：第一版客户端只按**下载字节**算进度，而服务端要整份生成完 Excel 才开始发字节——生成阶段（占
95% 以上耗时）客户端无从得知进展，生成完一下跳满；叠加当时 8080 端口跑的是不含修复的旧进程，
表现成「进度不动 + 服务器错误」。

## 决策

1. **服务端登记生成进度**：`ExportProgress`（ThreadLocal 作用域 + 登记表，键「用户:操作号」，
   上限 256）。读取端（`MasterExportSource`、`ReportQueryKit.paginateAll`、审计导出等）汇报
   `announceTotal` 与 `rows`；`XlsxExportService` 汇报 `PACKAGING`；`WorkbookDownloadService`
   汇报 `ENCRYPTING`。
2. **请求头 `X-Uten-Export-Operation`**（UUID，CORS 已放行）：`ExportRateLimitInterceptor` 见头
   登记、`afterCompletion` 注销。
3. **端点 `GET /api/exports/progress/{operation}`** → `{rows, total, phase}`，只能读本人的。
   **未开始或已结束返回 204 而不是 404**：轮询审计曾把每秒 2 次的 404 记成失败操作。
4. **客户端 `_SyncExportCurve`**：进度只进不退——读取 0–90%（按服务端真实「已读 / 总数」）、
   生成 92%、加密 95%、下载 95–99%、保存 100%；进行中每 0.5 秒轮询，同一时刻只有一个轮询在途，
   收到第一字节即停止轮询；空快照（204）保持当前进度。
5. **后台导出任务百分比**：迁移 V1125 新列 `total_rows`，`ReportExportWorker` 心跳用
   `COALESCE` 只写一次总量；任务弹窗总数已知时显示百分比与「已处理 N / 总 行」。

## 边界保留

- 轮询是读取，不打审计、不挤占远程并发预算（`RemoteRequestBudgetFilter` 是并发信号量，轮询占
  几毫秒；429 时客户端跳过这一次）。
- 未开始/已结束的 204 契约由 `ExportProgressPollAuditTest` 与 `uten_export_sync_progress_test`
  钉死；本地 dev 无后台导出目录时走同步路径（capabilities.available=false）。
