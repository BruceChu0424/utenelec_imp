# V638 委外回厂先出后进守卫计入前置自制出仓行

- 迁移：`V638__subcontract_target_receipt_guard_counts_prepared_outbound.sql`。
- 口径来源：2026-09-21 用户口径「采购允许超量下单，超出部分是公共的；委外只要不超过仓库的存储量(锁定的加公共的)也可以超过需求下单」。
- 决策：[ADR-062 §十](../99-决策记录-ADR/ADR-062-委外先自制后通知与分批通知.md)——前置自制的委外订货以「任务锁定 + 同货色公共可用」为上限，锁定份落 `PREPARED_OUTBOUND`、超出份落 `DIRECT_OUTBOUND`，两条计划行挂在同一条订货明细。
- 依赖：V436 回厂守卫、V581 单一子件流向扩展(同一函数)、V535 直下单现货目标件 PREPARED 切片。
- 编号：V635–V637 留给并行会话(V636 委外允许损耗由并行会话提供)，本迁移 589→590。

## 根因

`fn_assert_subcontract_target_outbound_receipt(order_item_id)` 只在订货明细含 `DIRECT_OUTBOUND / MAKE_THEN_OUTBOUND / COMPONENT_OUTBOUND` 计划行时激活(ADR-085 §四刻意没把 `PREPARED_OUTBOUND` 加进 V507 白名单)，但「已审出仓量 `v_issued`」与「已消费量 `v_consumed`」两个合计共用的 JOIN 也只认这三种流向。前置自制订货超量后同一明细混合出仓 33(30 前置 + 3 公共)，回厂 33 时 `v_issued` 只算到 3，COMMIT 抛 `subcontract target receipt exceeds approved target-item outbound`(`subcontract_target_outbound_first_guard`)。Java 镜像(`SubcontractOutboundFlowSql.ISSUED_TARGET_BASE_SUM`、回厂消费 `consumed_qty` 分摊)一直按全部非 LEGACY 流向合计，所以回厂草稿预检放行、数据库在提交时拒绝。直下单「现货目标件 PREPARED + 余量 MAKE_THEN」(V535 `directPreparedLineage`)的混合明细同受影响。

| 对象 | 变化 |
| --- | --- |
| `fn_assert_subcontract_target_outbound_receipt(uuid)` | 取 `pg_get_functiondef`、行尾归一 LF，把 `v_issued / v_consumed` 合计 JOIN 的流向集合由三种补为四种(加 `'PREPARED_OUTBOUND'`)；锚点恰好一处才替换，且替换后激活条件文本必须原样存在，否则 23514 失败；函数注释同步 |
| 草稿态采购/委外订货行金额 | 同一用户反馈的另一半：客户端曾把「数量×单价」按 double 相乘后原样送来(3×0.10 = 0.30000000000000004)，送审精确比对必拒；服务端自本批起按数量×单价×表头汇率精确重算，迁移把仍在草稿态(`status = 0`)、单价非空且金额与精确乘积不等的采购/委外订货行一次归一(`amount_original = qty × price`、`amount_local = amount_original × 表头汇率`)，表头 `total_original/total_local` 随之按未删明细重算；已审/红冲/取消单一个字节不动 |

不加表、不加列、不动触发器(草稿金额归一是唯一的改行，且只改本就必须与数量×单价相等的草稿字段)；激活条件一个字节不动——纯 `PREPARED_OUTBOUND` 明细(全部历史前置自制订货)仍不受该守卫约束，口径与 ADR-085 §四一致。

## 影响范围

- 只影响「同一订货明细同时有 PREPARED 行与 DIRECT/MAKE_THEN/COMPONENT 行」的混合明细：回厂量按全部已审出仓量(含前置份)比较，消费守恒也按全部出仓明细比较；历史上这类明细只有 V535 直下单切片一种形态，且回厂会被旧守卫拒绝，不存在能通过旧口径落库、按新口径变非法的数据。
- 存量纯 PREPARED / 纯 DIRECT / COMPONENT 明细的判定结果与迁移前完全一致。
- 草稿金额归一只碰 `status = 0` 且金额不等于精确乘积的行(用户实测那张 3 × 0.10 的草稿正是这种)，归一后无需重新编辑即可提交财务审核；金额本来就相等的草稿与所有非草稿单不被触碰。

## 验证

- `SubcontractTargetReceiptGuardPreparedOutboundMigrationContractTest`：锁定只补丁一个函数、锚点/激活条件双重形状断言、新集合含四种流向、不建表不动触发器。
- `FullChainEndToEndTest#subcontractPreparedOverQuantityOrder_isCappedByTaskLockedPlusPublicStock`：台账 30 + 公共 5，订 36 送审可读拒绝、订 33 批准落 PREPARED 30 + DIRECT 3、一张出仓草稿发 33、回厂 33 → IQC 合格 → 批量入库，库存 2 → 35。
- `FullChainEndToEndTest#procurementOrderLineAmounts_areRecomputedByServerFromQuantityTimesPrice`：采购 3 × 0.10 客户端送 0.30000000000000004，落库 0.3000、送审通过、超采 3 回写申请；委外手工行 3 × 0.10、汇率 7 落 0.3 / 2.1 并送审通过。
- `BusinessDataResetSqlContractTest` / `ResetBusinessDataScriptContractTest`：白名单 (638, 590) 与目录对账。
