# V727 已知材料申请与领料单原子批量出库

- 日期：2026-09-26。
- 设计：[ADR-119](../99-决策记录-ADR/ADR-119-底层自制实际领料与BOM累计学习.md)。
- 迁移：`V727__production_draw_discovery_issue_batches.sql`，该迁移引入时源码目录 V727／656；当前头以[迁移索引](README.md)为准。

## 行为

已知材料但数量或实际叶仓待补的申请，可与已有 DRAW 领料单进入同一个批量出库页面。缺失字段在原明细表中标红框，页面加载和编辑不写库存。确认时以一个事务完成材料配置、精确需求及预留、生成领料单、审核和实际出库，任一失败整批回滚。未知材料仍走原选料入口，不混入已知材料批次。

同一材料可以按实际叶仓拆行；每个申请最多 100 行，不跨单位合计。批次最多 50 个来源任务，按实际仓生成的最终 DRAW 也受原批量 50 张上限保护。普通 DRAW 仍按已请求未实发数量办理；父件计划数量不能填进原材料的领料数量。

正式 SL 按每张单自己的真实明细计算有效应领量、累计实发量和申请未发量。跨仓拆单不把整笔需求或申请总量复制到每张单，也不遗漏同一需求的后续正式单据。

混合批次接口为 `POST /api/stock/docs/issue-discovery-batch`，请求包含 `idempotencyKey`、普通单据 `docIds`、申请 `discoveries[{requestId, expectedVersion, items}]` 和选填 `reason`。申请明细填写 `goodsId`、可空 `colorId`、`unitId`、实际叶仓 `warehouseId` 与正数量 `qty`。批量通道须保持申请建议中的材料身份集合；改选材料走原选料详情入口。同料跨仓拆行仍保留同一材料身份。

只选择普通 DRAW 时继续使用原 `issue-batch`。混选未知材料不能静默跳过：先返回原入口确定实际材料，再进入已知材料的批量流程。打开页面仅加载；结果不明时冻结原请求与幂等键重试，不能每次点击另造一个写入意图。

## 新表及完整幂等

新增 `production_draw_issue_batches`，保存操作人/员工、幂等键、规范化请求摘要、请求快照、结果快照、最终领料单 UUID 集合和创建时间。同一操作人与键唯一，成功记录不可更新或删除。

在事务开始固定完整商业来源、库存维度、主仓、物料分析范围，并按统一顺序锁关联生产计划，复核后才调用原材料配置与出库服务。完整范围包含普通 DRAW 所属的旧生产计划，不能假设它一定有物料分析关联。

首次执行由服务端生成批次 UUID，内部实发子命令绑定该 UUID；客户端的幂等键只负责识别外层完整意图，不能提前占用内部出库键。写成功回执前再次校验整批已请求量全部实际发出，任何剩余量都使整个事务回滚，防止旧回执被误计成新实发。相同意图重试返回原结果，不依照重试时的剩余量再次出库；更改批次成员、材料、数量、实际仓或备注后复用旧键直接拒绝。出库取消后重放原成功键也不重新发料。没有用前端多次保存模拟批次原子性。

新表沿已有行审计采用 FULL，业务清空策略为 CLEAR，并同步清空脚本和迁移目录闸门；本次不执行业务清空。实际领料及 BOM 学习仍以原 DRAW、库存流水、生产耗用、确认退料及审核真实产出为准，批次账只是命令与回执证据。

## 升级与回退

后端新接口依赖 V727，按原流程完成备份、前向迁移再激活对应服务。旧迁移保持原字节。回退应用时保留新表及成功回执，不删除已发生的领料、配置或学习事实；业务反向继续走现有取消出库、退料或报工红冲链。

验证范围包括混合批次、多个材料申请、同料跨仓、库存不足整批回滚、过期版本、权限、同键并发/重放/变更拒绝、出库取消后重放、完整预锁覆盖，以及实际生产/退料后的 BOM 学习。申请 LQ 与正式 SL 的编号及跨仓显示见 [V731](250-V731领料申请独立编号与正式单据追溯.md)，验证回执统一见[收尾记录](../99-项目治理/2026-09-26-领料申请批量出库与编号收尾.md)。本文件描述源码变化，不代表业务库已安装或已部署。
