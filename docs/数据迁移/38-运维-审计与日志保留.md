> 时间：2026-07-28 · 依据：用户 YTDQ.txt——「对标大厂 比如有些数据应该保持多久 太久的数据是不是应该清理 比如日志」

## 一、保留策略（对标大厂）

| 数据 | 热保留 | 冷处理 | 理由 |
|---|---|---|---|
| `audit_log`（触发器审计，含 jsonb 前后镜像，膨胀最快） | **180 天** | 归档 `audit_log_archive` 长期留存（合规追溯），磁盘紧张时再导出对象存储后清理 | 等保/大厂常规 6 个月在线 + 归档 1-3 年 |
| 应用日志（server_run.log 等） | 按大小滚动 | 生产用 logback RollingFileAppender（100MB×30 天），避免单文件无限增长 | 防磁盘打满 |
| 业务历史数据 | 不删 | 按年分区（已在 V50-V69 落实）+ 后续冷数据归档机制（预留） | 业务数据是资产，只归档不删除 |
| 迁移 staging CSV | 随正式重迁覆盖 | 正式切换后清理 data/*.csv（含 PII） | 最小留存 |

## 二、执行方式

```bash
# 手动执行（默认 180 天，可 -v retention_days=N 调整）
docker exec -i uten-imp-postgres psql -U uten -d uten_imp -v retention_days=180 \
    -v ON_ERROR_STOP=1 < server/ops/audit_retention.sql
```

脚本行为：建同构归档表（若不存在）→ 超期行 `INSERT ... ON CONFLICT DO NOTHING` 归档 →
热表分批删除（每批 5000，控锁与 WAL）→ ANALYZE → 输出报告。幂等，可反复跑。

> 生产建议挂每周低峰定时任务（如周日 03:17）；正式上线时把 logback 滚动配置一并启用。
