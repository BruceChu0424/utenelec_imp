# V443 销售货款：客户标签、全客户出货财审与铺底口径

## 目标

V443 把销售出货控制固定为：已完成订单财务确认 → 销售创建出货草稿 → 客户已人工归入月结/现金/定金 → 财务逐张放行 → 仓库收到待拣货通知 → 拣货/交接 → `SHIPPED` 同事务扣库存并建立完整 AR。三类标签只帮助人工判断，不自动放行，也不证明定金到账；标签为空时不得完成财审。真实定金仍以已审 `CUSTOMER_PREPAYMENT` 及其转销事实为准。

应收从仓库最终确认的上海业务日起算。出货草稿 `bill_date` 保留单据日期；AR `bill_date`、到期日和账龄使用 `SHIPPED` 业务日。每张来源出货只允许一笔未删除活动 AR：应用层 `ar_posted`/来源锁与数据库 `uq_arap_active_source(source_doc_type,source_doc_id)` 共同防重复立账，不能只靠页面按钮防重。铺底不冲减 AR：发货 100 仍立完整应收 100，报表另列 `铺底额` 和 `超出铺底额 = 应收余额 - 铺底额`，允许负数，未设置铺底按 0。正式 AR 未收不得被尚未转销的客户预收负余额直接净掉；可用预收单列，只有已审预收转销才冲减目标 AR，避免同一到账重复计算。

## 老库只读证据与映射

2026-08-31 对本机只读 SQL Server `YTDQ_2023` 做了结构和聚合核对，未读取客户联系明细、未执行写 SQL：

- `B_Client` 没有独立铺底列；`Credit` 的非零金额分布与用户提供的旧应收汇总截图逐项一致。
- 260 个非删除客户中，旧结账方式可安全归为现金 28、月结 16；其余 216 不能从“提货/代付/支票/垫付/汇款/代收/空值”猜成定金。按旧状态分层：使用中 236（现金 28、月结 15、未决 193），禁用 24（月结 1、未决 23）。禁用客户仍可能保有历史 AR/收款，不能从全量标签对账中豁免。
- 10,653 张旧销售订单中非零 `Deposit` 为 0，不能据此推断定金客户。

因此 bootstrap 将 `B_Client.Credit` 同时作为原始 legacy 快照保留，并在 `credit_floor` 尚未人工维护时回填铺底。对 legacy 客户，原 `credit` 锁定只读并在 UI 明示“旧库 Credit 快照（只读）”（列表总表头为“信用额度 / 旧库 Credit 快照”），不参与订单财审阈值，也不能在当前字段上伪装成后来核准的信用额度；未来若需要真实信用额度，必须新增带审核人/时间/版本的 authority/verified 模型。自动分类只消费已经冻结的机器角色：`CASH` 由 V285 绑定固定 UUID `...0001`，`MONTHLY` 由 V330 在受控维护模式绑定固定 UUID `...0006` 并验证唯一启用；V443 不从中文名或旧整数重新发现角色，只对这两个唯一活动角色做 fail-fast 核验和映射。其它客户进入 `v_client_sales_payment_type_migration_issues`，必须人工选择 `MONTHLY/CASH/DEPOSIT`；全部非删除客户未分类数必须为 0 才能切换，不能以禁用状态豁免历史 AR/收款主体。

## 历史审核真实性

禁止把历史出货批量更新为“已财务审核”。`finance_gate_version=0` 只表示历史审核事实未知；V443 新流和迁移时尚未开始仓库作业的活动 `PENDING_PICK` 草稿必须使用版本 1。已进入 `PICKING/PICKED/SHIPPED` 的历史单保留版本 0，不补造审核人；`LEGACY_PENDING` 是只读迁移异常，不再允许旧 `approve`、财审或仓库推进。业务人员须对账后从当前已财务确认订单逐行重建版本 1 的两审任务，原历史草稿留作证据。数据库触发器对版本 1 强制：

- `finance_audit=1` 必须同时有审核人和审核时间；
- `PICKING/PICKED/SHIPPED` 必须已有财务放行；
- 新出货不能降级为版本 0；
- 旧进行中异常列在 `v_sales_shipment_finance_gate_migration_exceptions`，不得伪造审核人清零；`LEGACY_PENDING` 不得原位升级或出库。

活动历史单若仍为 `PENDING_PICK + finance_gate_version=0`，应在无实物作业证据且锁定该单后升级为版本 1、保持 `finance_audit=0`，再由财务人工审核；不能因为带 `legacy_id` 就继续绕过。无法证明未开始作业的行进入异常清单并阻断切换。

## 权限与页面动作边界

- 精确 surface `finance.sales-shipment-audit` 只关联 `finance_shipment_audit`：财务专页 `/finance/sales-shipment-audits` 只列财审任务并推入受限共享出货详情，读取核对所需商业信息并执行财审/反审；不能新建、编辑、删除、驳回或推进仓库状态。
- 精确 surface `warehouse.sales-outbound` 只关联 `sales_shipment:warehouse-work`：仓库专页 `/warehouse/sales-outbound` 只列已财审可作业及进行中任务，并推入受限共享出货详情；只推进 `PENDING_PICK → PICKING → PICKED → SHIPPED` 及异常/退拣，不能执行财审/反审。开始拣货时仍复核标签、gate 版本和真实财审事实。
- `client:view/client:edit`：客户页面分别控制读取和维护；货款标签与铺底目前属于客户主档维护，不由发货财审权限推导。若财务岗位负责维护，必须在权限设置页显式授权并做真实账号负向 UAT。
- V443 只登记上述精确 surface 与现有权限的关联，不向部门、角色、个人或负责人新增 grant；既有部门基线和管理员配置保持原样。权限设置页须同时列出上述页面/动作关联，且两个专页不再复用宽泛 `sales.shipment` surface；只持财审、只持仓库作业、只持客户查看三类测试账号必须各自只能办理授权范围内动作。

## 当前投影与不可变风险快照

财审页面打开时展示的是**当前投影**：当前客户/币种、当前货款类型、当前 UUID 结算方式、当前正式 AR 未收、当前铺底/超铺底以及同币种当前可用预收。它用于本次人工判断，但会随客户维护、收款和预收转销继续变化，不能冒充历史审批快照。

V443 新增追加式 `sales_shipment_finance_release_events`。每次财务放行与撤回都在修改出货财审状态的同一事务分别追加 `RELEASED` / `REVOKED` 事件，并冻结当时客户 UUID/名称、币种 UUID、本次出货原币合计 `shipment_total_original`、货款类型、结算方式 UUID、正式 AR 未收、铺底额、超铺底额及同币种可用预收。`SHIPPED` 前尚不存在财务开账本币，事件不得伪填本次出货本币。事件只记录审核当时所见风险事实，不生成收款、库存、正式 AR 或总账，也不能取代客户预收转销。

事件表禁止普通 UPDATE/DELETE，并纳入通用审计触发器；反审必须追加 `REVOKED`，不能改写或删除原 `RELEASED`。V443 不为历史财审伪造事件，历史缺失保持未知并进入迁移/UAT说明。当前投影用于“现在怎么看”，追加事件用于“当时为什么放行/撤回”，两层不得混读。本轮不在事件中复制行明细、行 hash 或实体 version；反审后改行的逐项重建仍依赖通用单据/明细审计，这是明确验收边界。

## 迁移前后只读核对

```sql
SELECT count(*) AS non_deleted_unclassified_clients
FROM v_client_sales_payment_type_migration_issues;

SELECT client.status, count(*) AS unclassified_count
FROM v_client_sales_payment_type_migration_issues issue
JOIN clients client ON client.id = issue.client_id
GROUP BY client.status
ORDER BY client.status;

SELECT count(*) AS active_gate_exceptions
FROM v_sales_shipment_finance_gate_migration_exceptions;
SELECT * FROM v_sales_shipment_finance_gate_migration_exceptions
ORDER BY bill_no, shipment_id;

SELECT count(*) AS active_pending_gate_bypass
FROM sales_shipments
WHERE status = 0
  AND COALESCE(is_deleted, FALSE) = FALSE
  AND warehouse_work_status = 'PENDING_PICK'
  AND finance_gate_version <> 1;

SELECT count(*) AS invalid_floor
FROM clients
WHERE credit_floor IS NULL OR credit_floor < 0;

SELECT count(*) AS physical_without_release
FROM sales_shipments
WHERE finance_gate_version = 1
  AND warehouse_work_status IN ('PICKING','PICKED','SHIPPED')
  AND finance_audit <> 1;

SELECT count(*) AS customer_prepayment_open_items_to_exclude_from_formal_ar
FROM ar_ap_ledger
WHERE direction = 'AR'
  AND status = 1
  AND COALESCE(is_deleted, FALSE) = FALSE
  AND open_item_kind = 'CUSTOMER_PREPAYMENT';
```

全部非删除客户未分类、gate 异常、活动 `PENDING_PICK` 版本旁路、非法铺底以及版本 1 实物状态未放行五项都必须为 0，并由客户资料、财务和仓库岗位逐项签收；不能直接 SQL 猜值。按状态分组只用于安排人工工作量，不构成禁用客户豁免。最后一条只统计客户预收开放项供核对，不要求为 0：它们必须从正式 AR 未收查询中排除并由预收报表单列。标签未决不允许正式切换，但不会把“定金”自动当作已到账。

## 风险、恢复与发布边界

先在可恢复的非空副本执行 V443，并保存迁移前后客户数、铺底汇总、标签分布、活动出货状态、财审风险事件数和 AR 数量/金额指纹。失败只能修复前置数据后原样重跑，或恢复已演练备份；不得修改 V443 字节、执行 `flyway repair`、禁用触发器、批量伪造财审或给历史单补造风险快照。

源码、空库回放和聚焦测试不等于公司目标库迁移。目标库备份/恢复、历史客户人工分类、铺底与 AR/预收转销对账、活动 legacy gate 异常清零、财务→仓库多岗位权限负向 UAT、通知积压/重放和签名发布完成前，生产继续 **NO-GO**。
