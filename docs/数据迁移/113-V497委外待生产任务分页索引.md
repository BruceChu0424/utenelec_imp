# V497 委外待生产任务分页与热集合索引

迁移：`V497__subcontract_pending_preparation_index.sql`，只新增
`idx_subcontract_make_pending`，没有新表或业务记录修改。

历史已全通知的任务仍保留status=ACTIVE。V458的旧开放任务索引只按status筛选，无法排除这些历史。
新索引仅覆盖 `status='ACTIVE' AND notified_qty<required_qty`，键为task UUID，并包含
preparation_item_id供前置生产关联使用。工作台按需求日期及task UUID统一排序；索引负责先收窄
待办集合，合并后的排序不再遍历已全通知历史。

委外工作台在服务端将待生产任务与真实申请/订单合并查询。列表、阶段徽章、total和总待办count
采用同一待办条件；前端移除size=200抓取及第一页附加行，只保留现有分页控件。
前置任务仍只读、不可选入订货，双击按task UUID读取单笔TaskView，沿用分析owner或委外共享池范围。
部分通知后原任务只承担未通知余量，已创建的真实申请独立办理；全量通知或取消后退出前置待办。

隔离PostgreSQL验证使用125个待办、20000个已全通知ACTIVE、50个取消任务及3张真实申请：
三页50/50/28覆盖全部128条，计数128，关键字与单笔UUID查询可找到第125个前置任务。
EXPLAIN验证新增索引前COUNT顺序扫描历史，新增后COUNT及真实工作台查询命中新部分索引，
不再顺序扫描preplan_subcontract_make_tasks历史集合。该证据是本地查询测试，不代表目标库已迁移。
