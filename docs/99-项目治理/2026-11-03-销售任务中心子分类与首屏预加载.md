# 销售任务中心子分类与首屏预加载

## 范围与根因

- 基线：`dfe3f3b67`；隔离分支：`uimp/sales-task-prefetch-20261103`。
- 这是客户端读取编排与呈现修复。服务端 API、数据库、业务计算、审批、库存、金额/数量精度及统计口径未变。
- 父「订货进度」徽章已从全站 `/workbench/badges` 汇总取得 `salesStage.*`。子页原先在挂载后重新请求 `/sales/orders/progress/stage-counts`，重复运行阶段聚合；子栏实际只消费 `TASK_*`，与汇总的 `salesStage.*` 完全同口径。
- 原表格缓存归页面实例所有；用户选择子分类后才有第一页请求，任务中心提前取得的父徽章不能使表格提前就绪。

## 公共入口与调用清单

| 能力 | 原实现与边界 | 当前唯一入口及消费者 |
|---|---|---|
| 订货子栏任务计数 | 页面私有阶段请求/缓存；晚于父栏 | `badgeSummaryProvider` 的 `salesStage.*`。任务中心父栏、嵌入和独立 `SalesOrderProgressPage` 共用服务端汇总；不从普通列表行推算任务数 |
| 出货/零星发货/报价/退货计数 | 已有 `documentStatusCountsProvider` 按完整范围共享 | 保留该公共源；任务中心同时预热 `DIRECT_CUSTOMER` 独立切片，不与普通出货合数 |
| 分类首屏交接 | 页面间没有预加载交接 | `PreparedPageRead<T>` 复用 `PagedReadCache` 的完整分页响应和在途合并，仅保存显式准备的第一页，一次消费 |
| 查询构造与解析 | 列表与预加载容易各写一套条件 | `SalesRepository._listQuery/_progressQuery` 与 `_fetchList/_fetchProgress`；可见读取、准备读取使用相同参数构造和响应解析 |
| 有界后台编排 | 无 | `SalesTaskPreloader`。任务中心准备当前或第一个授权大类；两个物理 worker 跨切类、读取身份/范围/写修订和短暂离开保留预算 |
| 前台读取 | `SalesDocListPage`、`SalesOrderProgressPage` 各自持有既有分页窗口 | 只在选择分类时尝试采用准备页；原分页窗口、邻页预取、表头、搜索、历史和刷新继续使用原合同 |

逐入口覆盖：`/sales/tasks` 的订货进度、出货单、客户零星发货、报价单、退货单；`/sales/progress` 的独立进度页与 `/sales/{shipments,customer-shipments,quotes,returns}` 的独立列表也使用同一查询入口。独立列表只消费同一范围已准备的数据，不自行额外启动全中心预加载。`/sales/other-shipments` 是历史读取，不投机预加载。

清理：删除进度页私有 `_stageCounts`、请求版本、加载方法及无有效消费者的 Dart `progressStageCounts()` 包装。后端 `stage-counts` API 保留，未改变其他客户端接口。草稿工作区补齐 repository 的 Riverpod 依赖声明，保持原查询/删除语义。

## 数据与交互保护

- 不改 Uten 组件、主题、布局和既有红数自动选择规则。已加载汇总能直接显示子徽章，并使原有自动选择尽早开始表格读取。汇总未知/缺桶不伪装为零；共享汇总已有的暂时故障保留策略继续适用。
- 进度工作段准备 `DRAFT/IN_PROGRESS/READY_TO_SHIP`，每页 50 行；出货、报价准备当前大类非历史工作段，退货仅准备草稿段，每页 20 行。退货已审属于带时间范围的历史读取，不提前查询。只准备第一页，不取历史、全量或额外邻页。
- 每类 typed lease 最多保留 8 个准备页查询，每查询最多 50 行，完成后 15 秒内可交接。超预算响应不缓存且不截断，所有响应元数据和读取范围证明完整保留。
- 键包含不透明 API 实例、路径及完整查询（来源、阶段/分桶、页大小、零星发货类型、搜索、日期、排序和表头筛选）。本端写、身份、权限、管理员、服务端读范围及 API 更替退休 lease；迟到响应在交回前再次检查所属 lease。
- 显式刷新、写后刷新、搜索和表头变更不采用准备页；已完成和正在进行的准备只可消费一次。若前台先于排队预热开始读取，同查询在途引用计数和完成后短龄标记阻止尾队列重复准备，慢读超过 15 秒也不重复；标记不提供行缓存。
- 切父类清掉旧等待任务；旧在途传输仍占原有两个预算，完成后才放行新任务。隐藏或离开时不发后续准备；同类恢复可以继续队列。准备失败不保留失败快照；采用中的请求走普通表格错误/重试流程，无业务写入重放。
- 全站徽章补齐服务端读取范围与管理员变化的所属代次保护，其他身份/权限/API 保护沿用既有实现。
