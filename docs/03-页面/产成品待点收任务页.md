## 零、V430 两阶段仓库任务

| 阶段 | 权威来源 | 仓库输入 | 提交结果 |
|---|---|---|---|
| 待送检登记 | 已审核、未红冲且仍有未登记日报行 | 一个有效成品仓；本批所选行的 `place` 交易快照 | 同事务冻结本批登记并为所选行创建 FQC PENDING；移出行继续待办，不录实收、不写库存/`iqty` |
| 品质通过·待点收 | PASS release 足额的 FINISHED_IN 草稿 | 每行 `acceptedQty`；短收/拒收原因 | 正数 accepted 才写库存/`iqty`；短收、拒收、重交和红冲沿 V338/V418 |

待送检登记页应沿用仓库独立入库页面的信息架构：来源日报/计划只读，仓库必选，当前收货员工只读展示并由服务端冻结 UUID/姓名快照；固定明细表展示货品、编码、系列、颜色、单位、报工量，并只允许编辑逐行库位或把行移出当前批次。不得新增、换货或删除来源事实，不得复用生产日报编辑页，也不得暴露价格、金额、成本或工资。普通日报草稿保存不出现在任一仓库队列。

### 0.1 V431 按仓库建议与记忆

未选仓库时不解析或应用任何库位建议；`goods.stock_place` 也只能在选定仓库后的完整建议链中作为全局 fallback。选定仓库后，页面必须针对全部固定日报明细一次批量读取 `warehouse + goods + color` 精确偏好，不能逐行发 N 次请求。逐行建议的优先级和来源标签为：

```text
已登记 place_snapshot（只读历史）
  > 该仓已记忆（V431 精确偏好）
  > 最近登记（同仓、同货品 UUID、同颜色）
  > 货品主档建议（goods.stock_place 全局 fallback）
  > 暂无建议
```

- 自动建议始终只是可编辑初值；用户可以直接修改本次库位。页面须跟踪逐行是否已手工修改，异步建议、刷新或同仓重取不得覆盖已修改值。
- 未选择实际成品仓时，逐行库位号输入必须禁用并提示“请先选择成品仓”；选仓完成后才按系统 UUID 批量匹配建议并允许修改。
- 用户切换仓库时，旧仓请求即刻失效，并清除属于原仓上下文的建议和手工库位后重新匹配新仓；即使旧响应最后返回，也不能覆盖新仓建议。建议加载完成前不得把旧仓值当作新仓值提交。同一仓库内的迟到响应仍不得覆盖用户已经手工修改的值。
- 最近登记只按系统 `goods_id` 对齐货品资料，不能按可变货品编码或名称匹配，并同时要求仓库 UUID 和颜色 UUID（NULL 颜色也是确定维度）一致。它只读取其他日报中最近一笔 V430 登记；若那一笔登记的同维度明细存在多个不同库位，则不随机取值、不跳过它采用更老登记，继续回退货品主档或空值。
- 每行显示“该仓已记忆 / 最近登记：同仓同货品 / 货品主档建议 / 本次已修改 / 暂无建议”，让仓库人员知道值从哪里来；已登记任务只显示冻结的 `place_snapshot`，不得再显示当前偏好冒充历史。
- “同时记住为该成品仓默认库位”默认开启，但必须显式可见且可以取消。取消后只提交本次交易快照，不新增或更新偏好；旧客户端没有显式记忆字段时按取消处理。取消不删除本次真实 V430 快照，因此它以后仍可作为可编辑的“最近登记”建议，但不会成为 V431 持久共享偏好。
- 登记与偏好记忆是两个独立结果。登记成功后才执行带稳定幂等身份的偏好动作；偏好失败不得重提登记、回滚或改写已冻结快照。页面应保留成功事实并提示“登记已成功，默认库位保存失败”，提供只重试偏好的动作；重试成功后反馈新增、更新、未变化或因歧义跳过的行数。
- 同一登记若多行落到相同 warehouse/goods/color 且库位相同，只记忆一次；若库位不同，交易行仍按各自输入冻结，但偏好动作必须明确拒绝该键，不能采用最后一行覆盖。

当前库存没有仓库×库位 WMS 维度，任务页面不得把文本偏好展示成货位级可用量、库容、批次或可分配库存。

两阶段均沿用 `stock_doc:view` 读取边界；写动作需 `stock_doc:approve` 并与有效 `SUB_WH` 仓储组织范围求交。计划、生产、品质人员只能在各自对象范围查看进度，不能代仓库登记或点收。

新在线日报审核在同一事务 publishOnce `PRODUCTION_FINISHED_ARRIVAL_PENDING`，aggregate 为日报 UUID，普通任务通知固定进入本路由。收件人只取 `SUB_WH` 子树内同时持 `stock_doc:view/approve` 的未离职、active 账号；delivery 再查日报仍已审、未登记、无 inspection/legacy exemption，过期任务静默跳过。列表和角标始终查询已审核日报、仓库登记与 FINISHED_IN 权威投影，通知未读数不参与计数，通知丢失或清理不隐藏任务。

> **任务路由**：`/warehouse/production-finished-in/tasks`
> **到货登记深链**：`/warehouse/production-finished-in/arrival-registrations/:reportId`
> **多单汇总登记深链（2026-09-03）**：`/warehouse/production-finished-in/arrival-registrations/batch?reportIds=...`
> **页面**：`production_finished_inbound_tasks_page.dart`、`production_finished_arrival_batch_registration_page.dart`
> **后端**：`/api/warehouse/production-finished-in/tasks` 与 `/count`
> **迁移**：V338、V410–V415、V418、V430、V431、V469、V542、V547、V548

### 0.3 撤回登记（2026-09-10，V548）

已登记视图列出同一报工的全部登记批次（仓/行数/检查单号/收货人/备注/撤回态）。批次 `reversible` 由服务端判定：未撤回，且本批每条
FQC 仍 PENDING、合格/不合格为 0、无决定事件/放行命令/恢复授权。点「撤回登记(仅品质未处理)」填原因（2–500 字）后
`POST .../arrival-registrations/{registrationId}/reverse`（`stock_doc:approve` + `SUB_WH` 范围，幂等键随弹窗生成）：服务端追加撤回记录、
标记登记行、逐条追加 `REGISTRATION_REVERSED` 取消事件；数据库 BEFORE 守卫与提交前延迟守卫双重把关。撤回后报工行重新出现在待办，
可再次登记到任意仓（新批次、新 inspection、新检查单）；登记头/行、inspection、检查单明细与库位偏好保留为历史。品质已处理的批次 409。
批量登记页对陈旧已登记（只读）报工同样提供撤回入口。

## 一、职责

本节描述第二阶段：生产 FINISHED_IN 草稿的仓库权威队列，不依赖通知。只有 FQC PASS release 足额的草稿才可进入；V338 residual/reversal replacement 沿原首次 release 谱系继承资格，不重复消费 PASS。

任务页请求与导航必须满足以下运行时契约：

- 首次进入只发起一次任务列表查询；路由落点/page-resume 信号不能与首载叠加成第二次 GET。
- 工具栏刷新与下拉刷新共用单飞门禁；已有任务查询未完成时不能再发同类刷新请求。
- 搜索输入立即使旧请求版本失效，防抖后只提交最新关键词；较早返回的响应不得覆盖当前搜索结果。
- 登记页选仓后的库位建议也使用请求版本门禁；只批量更新仍未手工修改的行，迟到响应不能覆盖当前仓库或用户输入。
- 任务列表和 `/count` 都是纯读投影；列表读取成功不得反向 invalidate 待办 count，只有登记、点收、质检决定等确实改变队列的成功写动作才精准刷新角标。
- 待送检登记必须通过上表正式 `GoRoute` 进入并保留受限 `returnTo`，不得用裸 `MaterialPageRoute` 绕过 URL、深链恢复和路由权限映射。任务页与 arrival UUID 子路径都继承 `stock_doc:view` 路由门禁，写动作继续由页面能力与服务端 `stock_doc:approve`/组织范围共同把关。

## 二、岗位和动作

- 查看队列需要 `stock_doc:view` 及生产库存任务对象范围；只读用户按钮文案为“查看待点收详情”。
- 逐行点收另需 `stock_doc:approve` 与 `SUB_WH` 仓储组织范围；页面不能仅因全局权限显示可点收承诺。
- 队列支持服务端分页、搜索、空态、错误重试和返回刷新；角标来自同一权威 count。

## 三、逐行实收

仓库对每个当前行填写 `acceptedQty`：

```text
0 <= acceptedQty <= reportedQty
residualQty = reportedQty - acceptedQty
```

短收必须填差异原因；当前单只按实收量入账，余量在同一事务生成同来源新草稿。整单所有行均为 0 时原单记录 `REJECTED`，不写库存、不增加 `iqty`；V418 同事务把全部未消费 PASS 额度生成同计划、同日报来源 residual 待点收单，供重新交付，不得要求车间重复报工或重做 FQC。正数实收才写库存、计划 `iqty`、销售预留/进度及不可变 confirmation。

2026-09-12：批量全额确认共用完整预锁，只读取每张已审核单据的结果元数据，不为批量返回重建单张详情。每张单仍依原顺序完成实物库存、成本、生产完成与委外专属转交，最后对整批受影响分析刷新一次。同批实际仓资格只在当前事务内去重核对。单张短收、零实收、余量草稿、重复确认和受控反向仍走同一权威内核；详细验证见[仓库质检入库性能审计](../99-项目治理/2026-09-12-仓库质检入库性能审计.md)。

生产完成率为：

```text
完成率 = production_plan_items.iqty / production_plan_items.qty
```

计划 10,000、仓库累计实收 1,000，显示 10%；日报申报、FQC PASS 或待点收草稿都不能提前显示为入库完成。

## 四、幂等和反向

点收请求使用稳定幂等键并锁定 inventory dimension→plan/package/segment→document/item；重复请求不能重复写库存或 `iqty`。已点收单禁止通用红冲，必须走 `/finished-in/reverse`：按原 accepted slice 反库存/`iqty` 并重建待点收 replacement，append-only 记录保留完整谱系。
