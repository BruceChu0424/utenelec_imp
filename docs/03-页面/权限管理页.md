# 权限管理页

> 路由：`/admin/permissions` · 实现源：`lib/features/admin/pages/admin_permissions_page.dart` + `lib/features/admin/widgets/` + `lib/features/admin/repositories/admin_repository.dart`
> 后端：`server .../features/admin/AdminUserController.java`（`/api/admin`）· 迁移 `V21__admin_perm_assignment.sql`
> 新增：2026-07-23（仅超级管理员）

## 一、定位

超级管理员管理「谁能看啥」的唯一入口：给**员工个人**分配角色与细粒度权限点覆盖，给**部门**配置默认角色（部门直属员工自动继承）。

- 产品位置：[工作台首页](工作台首页.md)「系统管理」分组 → 权限管理（仅超管可见该分组）。
- 权限模型三层（详见 [全局机制.md §一](../05-架构/全局机制.md)）：
  **直接角色 ∪ 直属部门角色 → 权限点并集 → ± 个人覆盖（grant 加授 / revoke 回收）**。

## 二、入口与导航

- 进入路径：工作台 → 系统管理 → 权限管理。
- 路由守卫：`/admin/*` → `Perm.userManage`，无权限访问被重定向到工作台。
- 离开去向：返回工作台；改完权限无需跳转，Toast 反馈结果。

## 三、响应式布局

顶部说明条 + 分段切换「按员工 | 按部门」（`UtenSegmentedFilter`）。

- **按员工（expanded）**：左栏 340px 员工账号列表（搜索 + 状态筛选 + 加载更多），右栏选中员工详情面板。
- **按员工（compact）**：列表 → 点员工进入详情视图（带返回）。
- **按部门**：部门树列表（缩进层级 + 已配角色 chips）→ 选中部门配角色。

## 四、涉及的 Uten 组件

- `UtenCard` · `UtenCollapsibleSection`（权限点分组折叠）· `UtenSegmentedFilter` · `UtenDialog`（二次确认）· Toast 反馈组件

## 五、功能点

1. **员工账号列表**：`GET /admin/users`（分页 + loginAccount 搜索）；状态筛选（全部/正常/锁定/停用，本地过滤）；每项显示姓名/工号/部门/角色 chips/状态。
2. **账号操作**：锁定/解锁/停用/启用/重置密码（已有 `POST /admin/users/{id}/...` 接口），危险操作弹确认框。
3. **角色分配**：全部角色多选（`GET /admin/roles`），保存 → `PUT /admin/users/{id}/roles` 整体替换。
4. **个人权限覆盖**：全部权限点（`GET /admin/permissions`）按 category 分组；每点三态（继承/加授/回收），初始化自 `GET .../permission-overrides`；保存 → `PUT .../permission-overrides`（仅提交加授/回收两集合）。
5. **有效权限预览**：本地计算 effective = rolePerms ∪ grants − revokes（rolePerms = 直接角色 ∪ 部门角色的 permissions 并集）；继承自角色/部门显示来源标签；回收=红、有效=绿、无关=灰。
6. **按部门**（2026-07-23 升级为多选）：`UtenDepartmentPicker` 多选抽屉（公司根不显示、中间层仅作骨架不可选、节点旁已配角色数徽标），选中多个部门统一勾选角色批量保存（逐部门 `PUT /admin/departments/{id}/roles`，Toast 汇总成败）；说明「仅对直属员工生效（不含子部门）」。

## 七、涉及的数据实体

→ 见 [04-数据模型/实体字典.md](../04-数据模型/实体字典.md)
- `UserAccount` / `Role` / `Permission` / `UserRole` / `RolePermission`
- `DepartmentRole`（V21 新增）：部门默认角色
- `UserPermissionOverride`（V21 新增）：个人权限点 grant/revoke

## 八、权限要求

- 仅 `user:manage` 权限点持有者可访问（实际 = admin 角色 + 超管）。
- 后端守卫：不能修改超管账号的角色/覆盖（403）；非管理员不能授 admin 角色（403）；覆盖的权限点必须存在且 grant/revoke 不重叠（400）。
- 全部写操作走后端审计（触发器）。

## 九、边界情况

- 员工无部门：部门角色不参与其权限合成（仅直接角色 ± 覆盖）。
- 决策支持（`analytics:view`，V25 新增权限点）：默认仅 manager/admin 持有；其他人工作台不显示「决策支持」组、直接访问 `/analytics/*` 被守卫弹回，需超管在此页授予。
- 权限变更生效时机：JWT perms 在登录/刷新时生成，变更**下次登录或令牌刷新后生效**（页内已有提示）。
- 列表加载失败：错误态 + 重试（`ref.invalidate`）；保存失败 Toast 提示且不丢本地编辑状态。
- 员工列表状态筛选为本地过滤（后端 status 参数已支持，后续可无缝切换为服务端筛选）。
