# 2026-11-01 Windows 更新提示与页面交互修复

基线 `bd7e8525b`，隔离分支 `uimp/windows-update-interaction-20261101`。用户截图为 Windows Flutter 2.5.38+2538，检测到 2.5.43，页面提示更新已下载。用户随后确认“检查更新”有反应，本次问题范围为启动提示缺失、返回和立即更新的交互。

## 原因与行为

- `ClientUpdateHost._check` 原先等待后台下载完成，并在存在暂存包时直接返回，默认开启的自动更新因此不显示启动提示。现在发现适用版本即展示提示，下载与提示独立运行；同一登录不反复弹同一版本。无人操作时，自己的提示在安全空闲窗口后交还精确路由，再显示原有 10 秒倒计时，不影响空闲安装。
- 设置页不在 `canAutomaticallyUpdateRoute` 的已知安全页面中。更新专页通过根 Navigator 压栈，底层 GoRouter 的路径仍是 `/settings`，所以 `installPrepared` 被错误拦住。新增设置页的安全声明；业务编辑器、在途请求、未知提交及其他弹窗仍由各自登记项独立阻止安装。
- 根、壳导航观察器原先把更新倒计时本身当作 `PopupRoute` 阻挡，真实应用会在安全门前等待。`RouteName` 统一维护更新专页、提示和倒计时的路由标识；只有这三个无业务输入的表面不自行增加阻挡，覆盖的未知页面或其他弹窗仍然阻挡。
- 页面原先把后台准备和主动安装都作为返回锁，并在返回回调中静默返回。现在后台下载可返回；主动更新从下载到安装交接保持锁定并显示禁用态。返回回调使用打开页面时持有的根 Navigator/精确路由，并在执行时重新检查实时导航锁，覆盖点击与重绘之间的竞争。
- 普通嵌套路由的返回在原始回归中正常，不能把它当作已原样复现了截图中每一种返回故障。本轮新增证据覆盖设置入口、根/壳两层导航、后台准备时返回及手动安装锁；现场旧安装程序尚未替换或验收。
- 真正不能安装时，专页及既有顶部通知按未保存、操作进行中或未完成状态说明处理步骤。处理后可用同一暂存包重试，不重下、不重复启动安装器。倒计时动态更新按钮安全态，在 0 处等待业务保护解除。
