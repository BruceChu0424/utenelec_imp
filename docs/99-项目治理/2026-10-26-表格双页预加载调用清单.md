# 表格双页预加载调用清单 (2026-10-26)

## 范围和结论

本次按用户要求使用 `frontend-design`，保留现有 Uten 组件、主题和业务交互。检查目标是货品资料及全项目同类表格的可见页预加载、呈现页窗和读缓存复用，提前加载目标从相邻1页改为前后各2页。

审计采用源码调用链检查。下表是当前源码构造调用及分页接口的逐位置定位，排除了注释、字符串和组件构造器声明。路径和行号是本次审计时的定位线索，后续修改可能使行号移动。静态扫描、调用链核对和本地回归各自记录；本清单不代表真实账号、生产数据、已安装客户端或员工浏览器业务验收。

结论是应修改公共表格与公共读层。普通表、窄屏列表、全屏、主滚动联动表、草稿包装表、报表和分页选择器均经既有公共入口覆盖，不需要每个业务页再复制预取算法。平台扩展列控制器负责列定义/值/布局，不拥有业务列表页码，不应在该控制器另起分页实现。

原呈现窗口默认5页/1000行，读缓存默认12页/5000行。超过呈现窗口后仍需复用读缓存恢复页数据，不能把“呈现行已淘汰”当成必须重新GET。读缓存超过预算、查询/身份/权限/数据修订变化、显式刷新或写后刷新时，仍按现有契约重新读取。两类窗口不能合并为无限增长的Widget树或无限数据缓存。

## 已保留的差异

- 同一业务行的数量、金额、来源、单位、权限和状态仍由服务端决定; 本次只准备GET结果，不发布后台预取结果为当前阅读页，不执行写操作。
- 审计事件/会话为祖先滚动的嵌入表格。`admin_audit_log_page.dart` 已通过 `MasterDataTableRowsController` 报告真实视口及可见页，并保留外层滚动锚点; 原显式 `prepareNext` 也需改为后2页，不将祖先视口换成内部猜测的视口。
- 已有投影入口 `warehouse_draw_task_segment.dart`、`stock_count_session_page.dart`、`warehouse_insight_page.dart`、`subcontract_decomposition_page.dart`、`material_analysis_candidates.dart`、`production_workshop_tasks_page.dart` 使用 `projectReadWindowBinding`。公共回调必须沿该协议传递，不在投影后丢掉读者/查询会话。
- 应收应付引入、供应商贷项应用保留 `canPrefetch: false` 与加载完成后的 `prepareScopedNext`，避免在宿主发布行/输入状态之前启动附加准备。其显式准备复用公共后2页入口。
- 部门员工选择、物料调拨候选及上述金额输入列表由宿主累计保留已加载行，回滚直接显示原行和输入控制器，不按5页呈现窗口淘汰; 公共读层仍可提前准备后续页。
- 修改历史为游标式浏览，已接 `ScopedPagedRead` + 游标适配器，保留自有上一页/下一页按钮与真实游标链。没有公共 `onPageChange` 时，不擅自改成连续滚动表。
- 付款方式工作区、AI统计人员表、品质待处置合并表、物料分析桶明细及备料单在内存对完整快照切片。没有需要额外重复GET的远程页，仍由公共表格管理呈现与滚动。
- `UtenPagedGrid` 是完整数据集的客户端卡片切片; 树、字典、单据明细、历史字段对比和编辑网格没有远程连续分页回调时，保留各自数据来源。权限管理账号列表是独立累计 `ListView`，不将它误计为表格页窗故障。

## 验证记录边界

### 原因与行为合同

1. 原 `MasterDataTableView._scheduleVisiblePage` 仅更新页码，未通知读层继续准备。原追加时机为距已呈现窗口边缘约0.75个视口(200..1200px)，不是进入下一业务页时准备。
2. 默认呈现窗口为5页/1000行，第6页起进入旧行淘汰及行高测量路径。重新挂载呈现行与重新GET是两件事; 货品宿主原已有 `useCache: true`，不能单凭加载提示认定每次回滚均重复GET。
3. 现初始接受第1页后准备第2、3页，可见第2页时继续准备第3、4页，可见第5/6页时继续准备第7/8页。读缓存和呈现页窗仍各自有界，未增加全量加载。
4. 现向后滚动优先准备前2页。呈现窗口外的已缓存数据通过原续页入口恢复，预算内不重复GET。显式刷新、写后刷新、身份/权限/查询及数据修订失效仍重新读取。
5. 修复显式跳页前缓冲覆盖控制器阅读准备回调的问题; 路由覆盖中止预读后，同位置可重新恢复准备; 行高/锚点补偿不改变用户滚动方向。全缓存窗口不再创建无效的零延迟任务。
