# 2026-11-03 人员反馈与默认分批发货

候选分支：`uimp/staff-feedback-20261103`，基线 `c75d6e1e3`。本轮为本地源码修复，不合 main、不推送、不打包、不部署。主工作区现有维护页、依赖锁及临时文件改动保留。

## 反馈原文与实现边界

| 来源 | 原文/事实 | 本轮结果 |
|---|---|---|
| 第一张图 | “增加一列客户名称” | 客户对账单开单日期后增加“客户名称”，出货及退货均读取各自单据关联的客户。 |
| 第二张图 | “排产单据内不能直接修改产品的角色 必须以默认的优先” | 主表、物料汇总及采购/委外/车间桶的供应方式只读；服务端拒绝偏离货品默认来源的人工路线请求，计划确认不回写货品角色。 |
| 第三张图与本轮明确要求 | “发货策略直接不用填写 默认允许分批发货” | 新建订货单移除策略选择与必填校验，客户切换及未落单草稿恢复均采用 `ALLOW_PARTIAL`。服务端普通新建、AI 和报价转单共用缺省规则。 |
| 第三张图顶部报错 | “订单已有发货、退货、核销、排产或完工事实，不能直接修订” | 这是既有业务事实保护，继续保留；本轮没有放宽订单修订、库存锁定或资金校验。 |

历史订单的齐套、客户确认和未指定策略保留原值；编辑请求不回传策略，避免修改其它字段时改写约定。旧客户端显式 `REQUIRE_COMPLETE` 仍兼容。没有批量修改生产订单或货品资料。已下达的生产事实保留原路线，不因当前主档变化追溯改写。

客户主档公共编辑入口的“默认货运策略”改为只读原记录，说明不再参与新单预填；客户分类编辑、详情编辑和内联新建复用该字段定义，不另设可选策略。
