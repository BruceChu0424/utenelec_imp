## 权限和原职责

V981 的三个完整规范码是 `warehouse_task:view:all`、`production_workshop_task:view:all`、`supplier_return_task:view:all`，均为显式授予的 VIEW 范围码，不自动授予部门、个人或模板。目录、525 项 help、V983 及仓库读取由上述并行分支维护。本分支不复制第二份目录或组织算法。

| 入口 | 新增阅读范围 | 仍独立核对的资格 |
| --- | --- | --- |
| 车间任务 | `production_execution:view` + `production_workshop_task:view:all`，真实有效员工可浏览全部车间的当前/历史任务、桶、明细及物料事实 | 原任务负责员工、主/兼职车间关系与每项动作码；count、徽章、催计划及原命令不改为全读 |
| 待退供应商任务 | `supplier_return_task:view` + `supplier_return_task:view:all`，可读已有 return task 的原处理人任务及详情 | `supplier_return_task:complete`、原 user + employee 双重 owner、状态和 expectedVersion；原 owner count 不扩大 |
| 内料及整批状态 | 原 `workshop_material:view`，在原车间范围之外需明确车间全读并与仓库浏览范围相交 | 请求、履行、撤销、开通、启停/撤回等仍用原车间范围和原动作合同 |

车间范围统一入口为 `ProductionWorkshopReadScopePolicy`，复用 `ProductionWorkshopAssignmentScope`。读取 all 不抹掉实际负责员工和车间集合；因此混合操作者的原车间变化也会改变发布证明。任务列表在同一条查询中附带原 assignment 的动作资格，外车间行不返回 start/report/draw/route/batch/urge 等动作，不增加逐行查询。

生产总览的原计划 owner 办理分支仍存在；不能把个人车间任务表的 assignment 限定强套到总览而破坏原合同。`requireVisibleWorkshopTask` 是读取，`requireAssignedWorkshopTask` 供原须 assignment 的催计划命令。其余命令仍保留自身 assignment 或原计划 owner 的既有判定。

待退供应商只扩展 `supplier_return_tasks` 的读取。没有 return task 的其他财务异常不会因此出现；没有基本 VIEW 时也不能借范围码读全局。`COMPLETE_RETURN` 由服务端逐对象给出，外 owner 行即使账号全局持 complete 也没有动作。价格继续按原 mask，原来源金额、附件和其他商业单据权限不被替代。

内料读方法复用原物料数量核算，只将原范围与新的只读投影分开；原 A 车间既有可见行保持，新增部分按车间全读与仓库浏览范围相交。仓库全读不能单独冒充车间全读。原到货登记、内料履行等合法顶班命令没有新增 keeper 限制；task-center 的 history-only 行也不等于删除旧独立命令入口。

这两个 owning 界面没有平台扩展字段读取入口，不新增另一套扩展列 API。仓库现有平台列、物理历史和关联详情按并行分支各自 adapter 的基本 VIEW、原 owner 及 publication guard 核对；不借本次范围码扩大其写入。
