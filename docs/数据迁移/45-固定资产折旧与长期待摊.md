## 一、原型结构与口径（历史快照）

- **V123**：`fixed_assets`（编号/名称/部门/费用科目/原值/残值率默认 5%/年限月/开始期间/状态）+
  `deferred_expenses`（编号/名称/费用科目/总额/摊销月数/开始期间/状态）+
  `fa_depreciation_log`/`da_amortization_log`（asset+period 唯一，防重复计提，回链 voucher）。
- **V140**：为两张管理列表增加 `(code,id) WHERE is_deleted=false` 部分索引，匹配稳定分页排序。
- **科目种子**（auto_created）：`/152/` 累计折旧（ACCOUNT 贷方备抵）、EXPENSE 043 一级子「折旧费」「摊销费」。
- **直线法**：月折旧=原值×(1−残值率)/月数；**末月=剩余应提**（防尾差）；摊销无残值同构。
- **计提过账**：折旧 借 资产费用科目（默认折旧费）/贷 累计折旧；摊销 借 摊销费/贷 /139/ 待摊费用。
  每期间一张凭证（FA-YYYY-MM / DA-YYYY-MM），每资产两条分录。
- **原型当时所谓“幂等”（现已否决）**：先删该期间 FA_DEP/DA_AMT 凭证与日志再重建；该做法会按可变主档改写历史，正式链路已 fail-closed 禁用。

## 二、原型 API（历史快照，非现行操作手册）

| 功能 | 端点 |
|---|---|
| 资产 CRUD | GET `/api/finance/fixed-assets?page=&size=` 返回 `PageResponse`；POST、PUT/DELETE `/{id}`（软删） |
| 待摊 CRUD | GET `/api/finance/deferred-expenses?page=&size=` 返回 `PageResponse`；POST、PUT/DELETE `/{id}` |
| 计提折旧 | ~~POST `/api/finance/fa/depreciate?period=YYYY-MM`~~（已禁用，返回冲突） |
| 计提摊销 | ~~POST `/api/finance/fa/amortize?period=`~~（已禁用，返回冲突） |
| 折旧清单 | GET `/api/finance/reports/fa/depreciation-schedule`（原值/月折旧/已提月数/累计折旧/净值） |
| 摊销清单 | GET `/api/finance/reports/fa/amortization-schedule`（总额/月摊销/累计/余额） |

报表已注册加密导出（fa/depreciation-schedule、fa/amortization-schedule）；
前端在「总账报表」卡尾部 2 chip（折旧清单/摊销清单）；
列表为 1-based 分页，默认 20、最大 100，数据库 count + `LIMIT/OFFSET`，稳定按 `code,id`；
Flutter 双 Tab 各自只保存当前页。**2026-07-29 原型页面当时已落地**：财务 hub「钱流管理 →
资产与待摊」（`/finance/assets`，双 Tab CRUD + 期间计提按钮）；该页面已由四区专业工作台替换，
不再提供旧“一键计提”动作。

四个创建/更新入口使用强类型 Bean Validation DTO，不再接收 raw `Map`：编号/名称/备注有长度
上限，原值/总额必须为正且限制 14+4 精度，残值率为 0..1，使用月份为 1..1200，开始期间必须
`YYYY-MM`，状态只允许固定资产或待摊各自枚举。现阶段 DTO 在 Controller 边界转为内部 Map 以兼容
既有 native-query Service；外部 JSON 字段名不变，后续替换内部 Map 不得放宽校验。
