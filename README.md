## 🛠 技术栈

- **Flutter 3.41+ / Dart 3.x** —— 最新 stable，企业主流
- **Riverpod 2.x** —— 类型安全、可测试的状态管理
- **go_router** —— 官方推荐路由，支持 Web/深链 + 路由守卫
- **Material 3** —— 设计系统底座
- **intl + gen_l10n** —— 官方国际化方案
- **shared_preferences** —— 偏好持久化（主题/语言/字号/性能档）
- **device_info_plus** —— 设备能力检测，喂给性能分级
- **flutter_secure_storage** —— 敏感数据安全存储（账号历史/撤销队列/访客令牌；Web 端员工令牌记录为标签页级 sessionStorage，多标签页多账号并行，见 ADR-061）
- **very_good_analysis** —— 严格 lint 规则

详细选型理由见 [docs/01-规划/技术选型.md](docs/01-规划/技术选型.md) 和 [docs/99-决策记录-ADR/](docs/99-决策记录-ADR/)。

## 🚀 如何运行

> 本节 `flutter run` 仅用于开发调试。公司员工入口必须发布 Web Release 并由受监督的静态站点/后端服务提供；否则调试进程退出后刷新必然出现“localhost 拒绝连接”。稳定运行基线见 [deploy/README.md](deploy/README.md)。

```bash
# 1. 安装依赖
flutter pub get

# 2. 生成国际化文件（修改 arb 后需重新生成）
flutter gen-l10n

# 3. 运行（自动检测平台）
flutter run

# 4. 指定平台
flutter run -d chrome        # Web（推荐：浏览器拉宽即可看到响应式效果）
flutter run -d windows       # Windows 桌面
flutter run -d android       # Android（需模拟器或真机）

# Release：Web 默认同源 /api，并把 CanvasKit 等运行时资源打进同源产物
flutter build web --release --no-web-resources-cdn --dart-define=APP_VERSION=<version>
flutter build windows --release --dart-define=APP_VERSION=<version> \
  --dart-define=API_BASE_URL=https://<lan-host>/api \
  --dart-define=CLOUD_API_BASE_URL=https://<cloud-host>/api

# 代码检查
flutter analyze

# 只格式化本任务的明确文件；共享脏工作区禁止全库格式化
dart format path/to/file1.dart path/to/file2.dart
```

> Flutter SDK 安装见 https://docs.flutter.dev/get-started/install
> 迁移目录当前头与各阶段源码候选/回归证据以 [数据迁移 README](docs/数据迁移/README.md) 顶部为准；
> 六端 Release 签名/安装见 [多端发布与签名](docs/99-项目治理/多端发布与签名.md)。
>
> 本地工具链必须通过 `PATH` 或 `FLUTTER_HOME` 配置满足 Flutter 3.44.2 / Dart 3.12.2；
> Java 通过 `JAVA_HOME` 指向 JDK 21。不要在仓库文档或脚本中写死个人磁盘、用户名或 SDK 安装路径。

### 本地开发验收路径

> 前端使用真实后端认证与业务 API，仓库不提供“任意账号密码”或可提交的演示凭据。开发环境
> 未指定 `API_BASE_URL` 时连接 `http://localhost:8080/api`；Release 规则见
> [多端发布与签名](docs/99-项目治理/多端发布与签名.md)。

1. 启动 App → `/entry` 选择员工入口 → 使用后端有效账号登录。
2. 若账号标记 `mustChangePassword`，必须先完成强制改密，不能绕过进入业务页。
3. 工作台、导航、按钮与路由按服务端权限显示；Dashboard 的通知、生产、仓库/采购/委外履约、访客/档案审核、财务、销售与政策聚合是真实服务端能力。履约分区故障时应局部降级并提示不可用，不能把占位 `count=0` 当成权威零待办。
4. 设置页验证主题、语言、字号、性能档、版本信息、修改密码与二次确认退出。
5. 拉伸 Web/桌面窗口并在手机/平板验证响应式、文本缩放、键盘和滚动边界。
6. 切换 lite/standard/rich，确认动画与特效按性能策略降级且业务功能不受影响。
7. 退出后当前标签页立即 fail-closed（同一浏览器其他标签页的独立会话不受影响，ADR-061）；旧 refresh 在加密队列中最终撤销。普通 logout 不保证已泄露的 access 立即在服务端失效；它最多存活到短 TTL（源码默认 15 分钟），需要立即全局清退时必须另用 `auth_version`/授权 epoch/issuer/签名密钥轮换等受控机制。
8. 验证短时断网、超时、HTML/空体/未知 401 和结构化 503 不清会话；恢复后横幅显示“网络已恢复，可以继续使用”，当前工作台自动重读。
9. 验证只对 GET/HEAD/OPTIONS 最多额外重试两次（400/1200 ms），创建、审批、过账等写请求不自动重放。
10. 用三标签、离线退出后重启、损坏安全记录、真实 12/18 KiB 请求头和严格 JSON health 完成稳定性验收；发布入口不得使用会随调试进程退出的 localhost。

## 🔒 安全声明

- **后端已实现**（Spring Boot 3 + PostgreSQL）：HR 与鉴权为真实安全实现（Argon2id 密码、JWT 轮换、pgcrypto 字段加密、触发器审计、部门权限 + 个人覆盖 + 按权限点脱敏——角色体系已于 2026-07-24 下线，见 [ADR-011](docs/99-决策记录-ADR/ADR-011-工作台部门分区与动态权限配置.md)）
- 令牌记录按标签页存储（Web：sessionStorage，多标签页多账号并行，ADR-061；原生：`flutter_secure_storage`）；开发秘密使用不进 Git 的 `server/.env`，生产秘密由
  `/etc/uten-imp/server.env`、Vault/KMS 或等价密钥管理注入（缺省 fail-fast）
- 销售/采购/委外/仓库/生产/钱流/HR/访客/通知/建议已接真实后端；工资和员工报销活动 Mock 已移除，V133 表、真实 API 与固定状态机已有源码，但业务口径和生产 E2E 仍须验收；实验室和空调设备接入仍待后续
- CI 已加入 Git 历史密钥扫描、后端 Java 21 验证、Flutter 格式/analyze/test/Web 构建、CodeQL Java 安全与质量分析和 OSV 依赖扫描；工作流存在不等于远端已全绿，结果以 Actions 运行记录为准
- 当前私有仓库不接 GitHub Code Scanning：CodeQL 与 OSV 不向 Security 页上传结果，SARIF 均保留为 GitHub Actions artifact；OSV 仍启用 `fail-on-vuln`，发现漏洞时扫描任务必须失败
- 详见 [docs/00-项目准则/10-安全准则.md](docs/00-项目准则/10-安全准则.md) 与 [ADR-006](docs/99-决策记录-ADR/ADR-006-后端栈选型SpringBoot+Postgres.md)
