# 55 - 转正日期回填与员工车辆 / 备用手机号（V210 / V211）

> 时间：2026-08-05 · 决策：[ADR-021](../99-决策记录-ADR/ADR-021-人事域完善-转正车辆多联系方式与任务软认领.md)
> 关联：[53-人事正式名录迁移](53-人事正式名录迁移.md)、[HR任务中心](../03-页面/HR任务中心.md)、[员工详情页](../03-页面/员工详情页.md)

## 一、V210：转正日期老数据回填 + 软认领 + employee:export

### 1.1 老数据适配（confirmed_at 回填）

```sql
UPDATE employees SET confirmed_at = hire_date
WHERE confirmed_at IS NULL AND status <> 'probation';
```

- 口径：**没有登记转正日期的老员工，默认按入职日期视为已转正**（用户钦定 2026-08-05）。
- 试用期（`probation`）员工**不回填**：他们继续出现在 HR 工作台转正提醒里，到期办理。
- 名录迁移脚本 `server/legacy_migration/migrate_hr_roster.sql` 同步改为
  `COALESCE(批注转正日期, hire_date)`——**以后重新迁移正式名录时自带该口径**，幂等。
- 影响：141 人名录从「1 人有转正日期」变为全覆盖；HR 工作台不再刷出上百条「未登记」噪音。

### 1.2 新数据要求

- 入职「用工状态 = 正式」：**转正日期必填**（前端必填 + 后端 fail closed；
  不得晚于今天、早于入职日期）。默认带入入职日期，可按实际修改。
- 「试用」：不填转正日期，由合同试用期月数派生预计转正日，到期在 HR 工作台办理；
  `POST /api/org/employees/{id}/confirm` 支持 `confirmedDate`（默认今天）并写
  `employment_history` 新事件 `confirm`。

### 1.3 hr_task_claims（软认领）

见 [HR任务中心](../03-页面/HR任务中心.md) §五。部分唯一索引
`uq_hr_task_claim_active (task_type, employee_id) WHERE released_at IS NULL`；
24h 租约 `lease_until`，读取时惰性过期，无定时任务。

### 1.4 新权限点

`employee:export`（员工资料打印与导出，预配 DEPT_HR）：花名册打印、架构图打印按钮
按该点显隐（hide，不是 disable）。独立于 `employee:view`，对齐报表 `:export` 五道防线思路的第一道
（本点为客户端 PDF 导出入口门控；服务端加密导出管线复用 ADR-012，后续按需接入）。

## 二、V211：employee_vehicles / employee_phones

| 表 | 关键字段 | 约束 | 权限 |
|---|---|---|---|
| employee_vehicles | plate_no, plate_norm(大写去空白), vehicle_type, brand_model, color, remark | `(employee_id, plate_norm)` 唯一；长度 7–8（含新能源） | 查看 `employee:view`；写 `employee:edit`；自助 `/api/profile/me/vehicles` |
| employee_phones | label, phone_enc(pgcrypto), phone_hash(HMAC) | `(employee_id, phone_hash)` 唯一 | 明文 `employee:pii:view`；写 `employee:pii:edit`；自助 `/api/profile/me/phones` |

- 全部字段**非必填**（除车牌号/号码本身）。
- 员工列表搜索框同时匹配车牌：命中行返回 `matchedPlates`（「、」分隔）——门岗/行政
  「谁的车有问题」按车牌秒查人。
- 更换手机号：`POST /api/org/employees/{id}/change-phone`（`employee:pii:edit`）
  单事务改加密手机 + 同步 `users.login_account` + 吊销全部 refresh（强制重登）；
  HR 编辑改手机与员工申请审批合并走同一 `EmployeeLoginAccountSync` 链路。

## 三、迁移顺序与回滚

- Flyway 顺序：V210 → V211，紧随 V209；均为纯增量 + 一次 UPDATE 回填，无锁表风险（141 行）。
- 回滚：V210 的回填不可逆（无法区分「原本为空」与「回填值」）——这是有意的一次性数据治理，
  如需还原以迁移前备份为准；新表 DROP 即可。
- 生产注意：与其他候选迁移（V196–V202 生产 NO-GO 项）同一 Flyway 链，
  目标库应用前须经 [新库上线与首装操作指引](../99-项目治理/2026-09-01-新库上线与首装操作指引.md) 验收流程。
